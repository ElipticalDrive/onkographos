# Marching Tetrahedra 3 (DLC-Plane)

Also called: 5-Tetrahedron Cell, Diamond Crystal Lattice Tetrahedralization, Diamond Lattice Mesh, Dual Marching Tetrahedra - Diamond Lattice Crystal (DMT-DLC)

## Overview
Marching Tetrahedra 3 (DLC-Plane) is a volume meshing method that generates isosurfaces from voxel data by decomposing the grid into a diamond crystal lattice structure composed of exactly 5 tetrahedra per cell [S1, S2, unofficial]. It differs from standard Marching Cubes or other tetrahedral schemes by eliminating center-point synthesis, which prevents creases and indentations on data boundaries [S1, unofficial]. The "Plane" variant specifically processes the grid plane-by-plane, generating a single calculation for all shared points to reduce total point count and memory overhead compared to the "Volume" variant [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D grid of scalar values representing density [S2, unofficial]. The algorithm assumes scalar values $\le 0$ represent 'outside' and values $> 0$ represent 'inside' [S2, unofficial]. For distance-to-surface point cloud data, density is defined as $-distance$, requiring the 'zero as inside surface' option to be enabled [S1, S2, unofficial].
*   **Output:** A triangle mesh representing the isosurface at threshold $T=0$ [S1, unofficial].

**Data Structures:**
The core data structure is the cell, which uses a 3x3x2 matrix of grid points (indices 0-8) to support the tetrahedron definitions, despite the source's simplification to "5 points" [S1, unofficial]. The vertices are ordered so that every other point is inverted, allowing a modulo 4 operation to wrap point indexing and reduce branching logic [S2, unofficial].

**Cell Geometry and Tetrahedra:**
The cell is decomposed into 5 tetrahedra (indexed 0-4) [S1, unofficial]. The specific connectivity for the tetrahedra, using local vertex indices, is defined as follows [S1, unofficial]:
*   Tetrahedron 0: Vertices 0, 1, 3, 4
*   Tetrahedron 1: Vertices 1, 2, 4, 5
*   Tetrahedron 2: Vertices 3, 4, 6, 7
*   Tetrahedron 3: Vertices 4, 5, 7, 8
*   Tetrahedron 4: Completes the volume, with alternating 90-degree rotations applied to the inner tetrahedron in adjacent cells to ensure edge deltas are computed along the same diagonal in mating cells [S2, unofficial].

**Algorithm Steps:**

1.  **Iteration:** Iterate through the grid planes [S1, unofficial].
2.  **Vertex Ordering:** Order the cell vertices such that every other point is inverted [S2, unofficial].
3.  **Status Determination:** Determine the inside/outside status for each vertex relative to the threshold $T=0$ [S1, unofficial].
    *   If $S_i > 0$, the vertex is Inside.
    *   If $S_i \le 0$, the vertex is Outside.
    *   *Special Case (Zero Handling):* If a vertex value is exactly 0, the state does not transition from Outside to Inside [S1, S2, unofficial]. The origin point is always considered Outside [S2, unofficial]. If points 1, 2, or 3 are 0, the slope delta is forced to 0, keeping the 'inside' point as close to itself as possible [S1, S2, unofficial].
4.  **Intersection Computation:** For each of the 5 tetrahedra, compute edge intersections [S1, unofficial].
    *   For each edge of a tetrahedron, check if it crosses the isosurface (i.e., signs of $(S_i - T)$ differ) [Parent].
    *   Calculate the intersection point $P$ using linear interpolation:
        $$ P = V_1 + \frac{T - S_1}{S_2 - S_1} (V_2 - V_1) $$
    *   *Delta Handling:* If the denominator $(S_2 - S_1)$ is 0 (which occurs if both points are 0 or both are non-zero but one is treated as 0 in the inverted logic), the delta is forced to 0 [S1, S2, unofficial].
5.  **Sidedness and Normal Alignment:** Compute sidedness based on which values are $\le 0$ and $> 0$ [S1, unofficial]. If the value is from -1 to 0, the direction is reversed; if from 0 to 1, the direction is forward [S1, unofficial]. All triangles are emitted with normals trivially aligned with their proper orientation [S1, unofficial].
6.  **Triangle Emission:** Emit triangles for the generated intersection points [S1, unofficial]. Quads are not emitted because they can result in inverted triangles due to boundary conditions [S1, unofficial].

**Pseudocode:**

```python
def march_tetrahedra_dlc_plane(grid, dims, threshold=0.0):
    """
    Marching Tetrahedra 3 (DLC-Plane) implementation.
    grid: 3D array of scalar values (shape: depth, height, width).
    dims: tuple (width, height, depth).
    threshold: Isosurface threshold (default 0.0).
    Returns: List of triangles, each triangle is a list of 3 (x,y,z) tuples.
    """
    triangles = []
    depth, height, width = dims
    
    # Iterate through grid planes (Z-slices)
    for z in range(depth - 1):
        for y in range(height - 1):
            for x in range(width - 1):
                # Extract 3x3x2 cell points (indices 0-8)
                # Mapping: 0=(x,y,z), 1=(x+1,y,z), 2=(x+2,y,z), 3=(x,y+1,z), 
                #          4=(x+1,y+1,z), 5=(x+2,y+1,z), 6=(x,y,z+1), 
                #          7=(x+1,y,z+1), 8=(x+2,y,z+1)
                vals = [
                    grid[z][y][x], grid[z][y][x+1], grid[z][y][x+2],
                    grid[z][y+1][x], grid[z][y+1][x+1], grid[z][y+1][x+2],
                    grid[z+1][y][x], grid[z+1][y][x+1], grid[z+1][y][x+2]
                ]
                # World positions (assuming unit spacing)
                pos = [
                    (x, y, z), (x+1, y, z), (x+2, y, z),
                    (x, y+1, z), (x+1, y+1, z), (x+2, y+1, z),
                    (x, y, z+1), (x+1, y, z+1), (x+2, y, z+1)
                ]
                
                # Tetrahedron definitions from source
                tets = [
                    (0, 1, 3, 4), (1, 2, 4, 5),
                    (3, 4, 6, 7), (4, 5, 7, 8),
                    (0, 3, 4, 6) # 5th tetrahedron to close volume [G]
                ]
                
                for t in tets:
                    emit_tetra(pos, vals, t, threshold, triangles)
                    
    return triangles

def emit_tetra(pos, vals, indices, threshold, triangles):
    """Emits triangles for a single tetrahedron."""
    v0, v1, v2, v3 = [pos[i] for i in indices]
    s0, s1, s2, s3 = [vals[i] for i in indices]
    
    # Determine inside/outside status
    inside = [s > threshold for s in [s0, s1, s2, s3]]
    
    # Skip if all inside or all outside
    if all(inside) or not any(inside):
        return
        
    # Find intersection points on edges
    edges = [(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)]
    intersections = []
    
    for i, j in edges:
        if inside[i] != inside[j]:
            vi, vj = [v0, v1, v2, v3][i], [v0, v1, v2, v3][j]
            si, sj = [s0, s1, s2, s3][i], [s0, s1, s2, s3][j]
            
            # Zero-delta handling per source
            if abs(sj - si) < 1e-9:
                intersections.append(vi)
            else:
                t = (threshold - si) / (sj - si)
                # Linear interpolation
                px = vi[0] + t * (vj[0] - vi[0])
                py = vi[1] + t * (vj[1] - vi[1])
                pz = vi[2] + t * (vj[2] - vi[2])
                intersections.append((px, py, pz))
                
    # Emit triangles (source specifies triangle emission only)
    if len(intersections) >= 3:
        # Fan from first intersection point
        for k in range(1, len(intersections) - 1):
            triangles.append([intersections[0], intersections[k], intersections[k+1]])
```

**Edge Cases and Pitfalls:**
*   **Zero Values:** If a vertex is exactly 0, the slope delta is forced to 0 [S1, S2, unofficial]. This ensures the point remains as close to itself as possible, avoiding division by zero or erratic interpolation [S2, unofficial].
*   **Vertex Ordering:** Incorrect vertex ordering can lead to incorrect 'outside' point detection [S1, unofficial]. The alternating inversion pattern is critical for the modulo 4 optimization [S2, unofficial].
*   **Boundary Conditions:** Quad emission is avoided to prevent inverted triangles at boundaries [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of cells [S2, unofficial]. The "Plane" mode reduces redundant calculations for shared points compared to "Volume" mode [S2, unofficial].
*   **Memory Complexity:** Lower than standard Marching Cubes due to the elimination of fabricated points and the reduced vertex count per cell [S1, unofficial]. The "Plane" mode further reduces working data size by processing plane-by-plane [S2, unofficial].
*   **Performance:** Yields good results for opening spaces without discontinuities [S2, unofficial]. The code simplicity is higher than the 14-tetrahedron skewed-plane approach [S1, unofficial].
*   **Strengths:** No creases or indentations on data boundaries (unlike cuboctohedral approaches that synthesize center points) [S1, unofficial]. Trivial normal alignment [S1, unofficial].
*   **Limitations:** Specific vertex ordering requirements [S2, unofficial]. Limited to the diamond lattice structure [S1, unofficial].

## Background
The method is inspired by the diamond crystal lattice structure [S1, unofficial]. It was developed as an alternative to the cuboctohedral approach and the 14-tetrahedron skewed-plane method, which required synthesizing a center point from 8 surrounding points, causing artifacts [S1, unofficial]. The "DLC-Plane" variant was introduced to optimize point handling by slicing the cloud plane-by-plane [S2, unofficial]. The implementation is associated with the `MarchingTetrahedra` and `DualMarchingTetrahedra` repositories [S1, S2, unofficial].
