# Marching Tetrahedrons Algorithm


## Overview
The Marching Tetrahedrons Algorithm (MTA) is an iso-surface extraction method that resolves the topological ambiguities inherent in the Marching Cubes algorithm by decomposing each cubic grid cell into six tetrahedra [S1, unofficial]. Unlike its sibling [Marching Cubes](link), which can produce ambiguous connections at the cell center, MTA guarantees a unique, unambiguous triangulation for every configuration of vertex values relative to the isovolume [S1, unofficial]. It builds on the shared principles of [Cell projection](26-cell-projection.md) by projecting the implicit field defined on a grid onto a piecewise-linear surface.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $f(x,y,z)$ defined on a regular 3D grid of vertices $V$, and an isovalue $I$.
*   **Output:** A set of triangles representing the iso-surface $f(x,y,z) = I$.

**Data Structures:**
*   **Grid:** A 3D array of scalar values.
*   **Tetrahedra:** Each cubic cell $(i,j,k)$ is decomposed into 6 tetrahedra. The decomposition is fixed and asymmetric. A common decomposition (e.g., [S1, unofficial]) splits the cube along its main diagonal and then subdivides the resulting prisms. The specific connectivity must be consistent across all cells to ensure manifold continuity.
*   **Edge Intersections:** For each edge of a tetrahedron, the intersection point with the isovalue is calculated via linear interpolation.

**Steps:**
1.  **Grid Traversal:** Iterate through every cubic cell in the grid.
2.  **Tetrahedral Decomposition:** Subdivide the current cubic cell into 6 tetrahedra. Let the vertices of the cube be $v_0, \dots, v_7$. The specific assignment of these vertices to the 6 tetrahedra must be fixed (e.g., $T_1=(v_0,v_1,v_2,v_3)$, etc., depending on the chosen diagonal).
3.  **Case Determination:** For each tetrahedron, determine the state of its 4 vertices relative to the isovalue $I$. A vertex $v$ is "inside" if $f(v) < I$ (or $> I$, depending on convention) and "outside" otherwise. This yields $2^4 = 16$ possible cases.
4.  **Intersection Calculation:** For each edge of the tetrahedron connecting vertices $v_a$ and $v_b$ with different states, calculate the intersection point $p$:
    $$ p = v_a + \frac{I - f(v_a)}{f(v_b) - f(v_a)} (v_b - v_a) $$
    If $f(v_a) = f(v_b)$, the edge lies on the isosurface; handle as a degenerate case [G] (typically treat as inside or outside consistently, or skip if exact equality is rare).
5.  **Triangle Generation:** Based on the case (number of inside vertices), select the pre-defined set of triangles connecting the intersection points. The key advantage of MTA is that each of the 16 cases has a unique, unambiguous solution, unlike Marching Cubes which has 4 ambiguous cases.
    *   0 or 4 inside vertices: No triangles.
    *   1 inside vertex: 3 triangles connecting the intersection points on the three edges incident to the inside vertex.
    *   2 inside vertices: 1 or 2 triangles, depending on whether the inside vertices share an edge or are opposite (diagonal). In MTA, the tetrahedral structure resolves the "diagonal" ambiguity present in cubes by forcing a specific split.
    *   3 inside vertices: 3 triangles (complement of the 1-inside case).
6.  **Output:** Collect all generated triangles.

**Parameters:**
*   **Isovalue $I$:** The scalar threshold. Typical values depend on the data range.
*   **Decomposition Scheme:** The specific way a cube is split into 6 tetrahedra. This choice affects the directional bias of the result.

**Edge Cases and Pitfalls:**
*   **Directional Ambiguity:** MTA has directional ambiguities because it subdivides a cube with tetrahedra, which cannot be done symmetrically [S1, unofficial]. The result depends on the orientation of the cube's diagonal used for decomposition. This can cause visible artifacts if the grid alignment is not consistent or if the data has strong directional features [S1, unofficial].
*   **Missing Boundaries:** The algorithm can miss material boundaries in tetrahedra if the isosurface enters a tetrahedron but only intersects one edge, as detection relies on vertex information [S2]. This is a general limitation of vertex-based iso-surface extraction.
*   **Precision:** Linear interpolation assumes the field is linear within the tetrahedron. For highly curved surfaces, higher-order interpolation or denser grids are needed.

**Pseudocode:**
```python
def marching_tetrahedrons(grid, isovalue):
    triangles = []
    # Define the 6 tetrahedra for a unit cube with vertices 0..7
    # This is one common decomposition; others exist.

        (0, 7, 5, 4), (0, 5, 1, 4), (1, 5, 6, 4) # Example set, verify connectivity
    ]
    
    for i in range(grid.width - 1):
        for j in range(grid.height - 1):
            for k in range(grid.depth - 1):
                # Get the 8 vertices of the current cube
                cube_verts = [
                    grid[i, j, k], grid[i+1, j, k], grid[i, j+1, k], grid[i+1, j+1, k],
                    grid[i, j, k+1], grid[i+1, j, k+1], grid[i, j+1, k+1], grid[i+1, j+1, k+1]
                ]
                cube_vals = [v.scalar for v in cube_verts]
                
                for tetra in tetra_defs:
                    v0, v1, v2, v3 = tetra
                    vals = [cube_vals[v0], cube_vals[v1], cube_vals[v2], cube_vals[v3]]
                    verts = [cube_verts[v0], cube_verts[v1], cube_verts[v2], cube_verts[v3]]
                    
                    # Determine case
                    inside = [v < isovalue for v in vals] # Assuming < is inside
                    num_inside = sum(inside)
                    
                    if num_inside == 0 or num_inside == 4:
                        continue

                    edges = [(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)]
                    intersections = []
                    for e in edges:
                        if inside[e[0]] != inside[e[1]]:
                            p = interpolate(verts[e[0]], verts[e[1]], vals[e[0]], vals[e[1]], isovalue)

                    # into the 'intersections' list.
                    case_triangles = get_triangles_for_case(inside, intersections)
                    triangles.extend(case_triangles)
                    
    return triangles
```

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of grid cells. The algorithm runs in effectively the same time as the marching cubes/tetrahedra algorithm [S2].
*   **Memory Complexity:** $O(N)$ for storing the grid and output triangles.
*   **Strengths:** Unambiguous topology resolution for all 16 cases; simpler implementation than Marching Cubes (no complex lookup tables for ambiguous cases).
*   **Limitations:** Directional bias due to asymmetric tetrahedral decomposition; potential for missing boundaries if the isosurface intersects only one edge of a tetrahedron [S2].
*   **When to use:** When topological correctness is critical and the directional bias is acceptable or can be mitigated.
*   **When not to use:** When high symmetry is required or when the data has strong directional features that align with the decomposition bias.

## Background
The Marching Tetrahedrons Algorithm was developed to address the topological ambiguities of the Marching Cubes algorithm. The MTA, unfortunately, has directional ambiguities, because it subdivides a cube with tetrahedrons, which cannot be done symmetrically [S1, unofficial]. The history of iso-surface extraction includes the Marching Cubes algorithm (Lorensen and Cline, 1987), which introduced the concept of case-based surface extraction. MTA was proposed as a refinement to ensure manifold correctness. The "Volume-Enclosing Surface exTraction Algorithm" (VESTA) and other recent methods continue to build upon or critique these foundational techniques [S1, unofficial].
