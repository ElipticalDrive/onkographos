# Subgrid Pipeline

Also called: Subgrid Marching Pipeline

## Overview
The Subgrid Pipeline extracts isosurfaces from tetrahedral grids by resolving topological ambiguities within individual tetrahedra using subgrid-accurate intersection data [S1, unofficial][S2]. It distinguishes itself from standard Marching Tetrahedrons by explicitly handling open, scoop, and normal boundary curves to process complex intersection configurations [S1, unofficial]. It builds on [Marching Tetrahedrons Algorithm](940-marching-tetrahedrons-algorithm.md) by replacing the fixed lookup table with a local reconstruction procedure that processes boundary curves [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
- **Input:** A range of tetrahedra in a grid, a scalar field defined on vertices, an isovalue, and configuration options (`mod2`, `greedy`, `compute_normals`) [S1, unofficial].
- **Output:** A global `TriangleSoup` containing the extracted surface triangles [S1, unofficial].

**Data Structures:**
- `EdgeInts`: A structure storing intersection data for the 6 edges of a tetrahedron.
  - Fields: `ne_01`, `ne_02`, `ne_03`, `ne_12`, `ne_13`, `ne_23` [S1, unofficial].
  - Each `ne_ij` represents the number of intersections on edge $(i,j)$ [G]. In the standard pipeline, these are integers derived from t-values [G]. In the `Mod2 Reduction` variant, they are reduced modulo 2 [S1, unofficial].
- `CombFace`: Represents a boundary curve (open, scoop, or normal). Contains a list of vertices defining the curve [S1, unofficial].
- `TriangleSoup`: A collection of triangles (triplets of vertices) accumulated from all tetrahedra [S1, unofficial].

**Steps:**
1. **Iterate Tetrahedra:** Loop through each tetrahedron in the input range using a `TetRange` iterator [S1, unofficial].
2. **Query Intersections:** For the current tetrahedron, query the edge intersections [S1, unofficial]. Request t-values (positions) and normals for all 6 edges if `compute_normals` is true [S1, unofficial]. Compute the intersection count for each edge based on the scalar field values at the vertices and the isovalue. Let $N_{ij}$ be the number of intersections on edge $(i,j)$ [G].
3. **Mod2 Reduction (Optional):** If the `mod2` option is enabled, apply modulo-2 reduction to the intersection data [S1, unofficial]. If the reduction results in a configuration that implies no surface, skip processing this tetrahedron [S1, unofficial].
4. **Construct Boundary Curves:** Call `boundary_comb_curves` with the tetrahedron indices, intersection counts, and edge occupation flags [S1, unofficial]. This function analyzes the intersection topology to identify three types of curves: `open_curves`, `scoop_curves`, and `normal_curves` [S1, unofficial].
5. **Track Statistics (Optional):** Increment a counter for "non-even" tetrahedra if `open_curves` is not empty [S1, unofficial]. Increment a counter for "non-normal" tetrahedra if `open_curves` is empty AND `scoop_curves` is empty [S1, unofficial].
6. **Construct Local Surface:** Create a local `TriangleSoup` for the current tetrahedron [S1, unofficial]. Use the `subgrid_surface` method for general cases or `subgrid_greedy` for optimized performance, based on the `opts.greedy` flag [S1, unofficial].
7. **Merge:** Append the local `TriangleSoup` to the global result soup [S1, unofficial].

**Pseudocode:**
```python
def subgrid_pipeline(tet_range, scalar_field, isovalue, opts):
    global_soup = []
    non_even_count = 0
    non_normal_count = 0
    
    for tet in tet_range:
        # Step 2: Query edge intersections
        edge_ints = [0] * 6
        normals = [None] * 6
        edge_intersections = [None] * 6
        
        for edge_idx in range(6):
            v0, v1 = tet.edges[edge_idx]
            s0 = scalar_field(v0)
            s1 = scalar_field(v1)
            
            # Compute intersection count and t-value [G]
            if (s0 - isovalue) * (s1 - isovalue) < 0:
                t = (isovalue - s0) / (s1 - s0)
                edge_intersections[edge_idx] = v0 + t * (v1 - v0)
                edge_ints[edge_idx] = 1
                if opts.compute_normals:
                    grad = (scalar_field.gradient(v1) - scalar_field.gradient(v0))
                    normals[edge_idx] = grad / max(norm(grad), 1e-8)
            else:
                edge_ints[edge_idx] = 0
                
        # Step 3: Mod2 Reduction
        if opts.mod2:
            for edge_idx in range(6):
                edge_ints[edge_idx] %= 2
            if sum(edge_ints) == 0:
                continue
                
        # Step 4: Construct boundary curves [G]
        open_curves, scoop_curves, normal_curves = boundary_comb_curves(
            tet.indices, edge_ints, edge_intersections, normals
        )
        
        # Step 5: Track statistics (optional)
        if opts.track_stats:
            if open_curves:
                non_even_count += 1
            if not open_curves and not scoop_curves:
                non_normal_count += 1
                
        # Step 6: Construct local surface [G]
        if opts.greedy:
            local_soup = subgrid_greedy(tet, open_curves, scoop_curves, normal_curves, edge_ints)
        else:
            local_soup = subgrid_surface(tet, open_curves, scoop_curves, normal_curves, edge_ints)
            
        # Step 7: Merge
        global_soup.extend(local_soup)
        
    return global_soup

def compute_edge_intersections(edge, scalar_field, isovalue):
    v0, v1 = edge
    s0 = scalar_field(v0)
    s1 = scalar_field(v1)
    if (s0 - isovalue) * (s1 - isovalue) < 0:
        t = (isovalue - s0) / (s1 - s0)
        return v0 + t * (v1 - v0)
    return None

def compute_normal(edge, scalar_field, isovalue):
    v0, v1 = edge
    grad = scalar_field.gradient(v1) - scalar_field.gradient(v0)
    return grad / max(norm(grad), 1e-8)

def boundary_comb_curves(tet_indices, edge_ints, intersections, normals):
    # Standard Marching Tetrahedrons curve construction [G]
    open_curves = []
    scoop_curves = []
    normal_curves = []
    # Map edge indices to intersection points
    edge_pts = {i: intersections[i] for i in range(6) if intersections[i] is not None}
    # Generate open curves from paired edge intersections [G]
    if len(edge_pts) == 2:
        pts = list(edge_pts.values())
        open_curves.append([pts[0], pts[1]])
    elif len(edge_pts) == 4:
        pts = list(edge_pts.values())
        open_curves.append([pts[0], pts[1]])
        open_curves.append([pts[2], pts[3]])
    return open_curves, scoop_curves, normal_curves

def subgrid_surface(tet, open_curves, scoop_curves, normal_curves, edge_ints):
    # Standard Marching Tetrahedrons triangle generation [G]
    triangles = []
    for curve in open_curves:
        if len(curve) == 2:
            triangles.append(curve)
    return triangles

def subgrid_greedy(tet, open_curves, scoop_curves, normal_curves, edge_ints):
    # Greedy variant fallback [G]
    return subgrid_surface(tet, open_curves, scoop_curves, normal_curves, edge_ints)
```

**Parameters:**
- `mod2`: Boolean. If true, reduces intersection counts modulo 2 [S1, unofficial].
- `greedy`: Boolean. If true, uses the optimized `subgrid_greedy` reconstruction [S1, unofficial].
- `compute_normals`: Boolean. If true, computes normals for intersection points [S1, unofficial].
- `track_stats`: Boolean. If true, collects statistics on curve types [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Subgrid methods require accurate computation of intersection positions; floating-point errors can lead to non-watertight surfaces if not handled carefully [G].
- **Degenerate Input:** Tetrahedra with zero volume or collinear vertices may cause division-by-zero or invalid t-values in intersection computation [G].
- **Complex Topology:** The ability to handle multiple intersections per edge allows for complex topologies, but increases computational cost [S2].

## Subtopics

### [Mod2 Reduction](1665-mod2-reduction.md)
Mod2 Reduction is an ablation of the Subgrid Marching Tetrahedra method that provides exact input intersection locations but limits the output to at most one intersection per edge. It uses the parity of the intersection count to determine connectivity, effectively restoring the single-surface-per-edge constraint of classic Marching Tetrahedra while utilizing subgrid-accurate vertex positions. It is distinguished from its sibling [Subgrid Surface Reconstruction](1666-subgrid-surface-reconstruction.md) by its strict limitation to one output vertex per edge, whereas the full subgrid method allows multiple vertices to represent complex topology.

### [Subgrid Surface Reconstruction](1666-subgrid-surface-reconstruction.md)
Subgrid Surface Reconstruction is a method for extracting a triangle soup from a tetrahedral grid by processing individual tetrahedra to resolve topological ambiguities in isosurface extraction. It distinguishes itself from standard Marching Tetrahedrons by explicitly handling open, scoop, and normal boundary curves to ensure watertightness, offering two variants: `subgrid_surface` for general cases and `subgrid_greedy` for optimized performance.

### Subgrid Marching Triangles
Subgrid Marching Triangles is a 2D contouring algorithm that reconstructs curves within a single triangle using a subgrid procedure, applied to all triangles in a 2D triangular grid given intersection counts on grid edges [S2]. Unlike 3D subgrid marching tets, this 2D variant does not need to worry about compatibility between neighboring cells, allowing for the specific modification in the odd sum case: rather than subtracting 1 from all 3 edge coordinates in a face, subtract 1 from the largest edge coordinate, breaking ties arbitrarily [S2]. For the dual method, it uses the same regularized QEF as in Section 3.3.2 of [S2], but in two dimensions. It can be applied to arbitrary unstructured triangulations, including surface meshes, as it makes no assumptions about the structure of the triangle grid [S2].

## Operating characteristics
- **Time Complexity:** The per-tetrahedron cost is greater than that of marching tets because it may produce more polygons per tet and involves additional logic for local reconstruction [S2]. However, the amortized cost per output triangle is quite comparable [S2].
- **Memory Complexity:** Depends on the number of output triangles and temporary storage for boundary curves and local triangle soups during processing [G].
- **Performance:** Speed improvements can be achieved by precomputing a table of common stencils if speed or thread synchronization is critical [S2].
- **Strengths:** Handles multiple intersections per edge; applicable to arbitrary unstructured grids [S1, unofficial][S2].
- **Limitations:** Higher per-tetrahedron computational cost compared to classic marching tets; potential for increased output polygon count [S2].

## Background
The Subgrid Pipeline originates from the work on Subgrid Marching Tetrahedra, which aims to improve the accuracy of isosurface extraction by considering subgrid details within each tetrahedron [S2]. The 2D variant, Subgrid Marching Triangles, extends these concepts to two-dimensional contouring [S2].
