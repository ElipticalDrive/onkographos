# Grid-based Traversal

Also called: Hierarchical grid traversal for irregular volumes, Parker's brute-force approach, Parker's method

## Overview
Grid-based Traversal is a method for rendering irregular volume data (tetrahedral meshes) at interactive rates by partitioning the volume into a hierarchical rectilinear grid structure to quickly determine candidate tetrahedra [S1][S2, unofficial]. It sets itself apart from sibling methods like [Projected Tetrahedra](877-projected-tetrahedra.md) by avoiding explicit connectivity information and instead relying on spatial hashing via a multilevel grid, allowing for on-the-fly iso-surface computation [S1].

## How it works
**Inputs:** A tetrahedral mesh representing an irregular volume; a hierarchical rectilinear grid structure (multilevel); scalar values associated with tetrahedra vertices [S1].
**Outputs:** Rendered image with iso-surface computed on the fly [S1].

**Data Structures:**
1. **Hierarchical Grid:** A multilevel grid structure covering the volume space [S1][S2, unofficial]. Exact grid dimensions and bit-packing layouts are not given in the sources.
2. **Grid Cell List:** Each leaf cell contains a list of pointers/indices to all tetrahedra that intersect that cell [S1][S2, unofficial].
3. **Cell Bounds:** Each grid cell stores the minimum and maximum scalar values of all tetrahedra attached to it [S1][S2, unofficial].

**Steps:**
1. **Grid Construction:** Partition the volume space into a hierarchical rectilinear grid [S1][S2, unofficial].
2. **Tetrahedron Attachment:** For each tetrahedron in the mesh, determine which grid cells it intersects. Attach the tetrahedron to the list of every intersecting grid cell [S1].
3. **Value Culling:** For each grid cell, compute and store the minimum and maximum scalar values among all attached tetrahedra [S1][S2, unofficial].
4. **Ray Traversal:** For each pixel, cast a ray into the volume. Traverse the hierarchical grid to find leaf cells intersected by the ray [G].
5. **Culling:** Use the stored minimum and maximum values of the traversed grid cells to cull regions that do not contain the current iso-value [S1][S2, unofficial].
6. **Tetrahedron Testing:** For each candidate tetrahedron attached to the intersected grid cells, test for intersection with the ray [S1]. Since no connectivity is used, all attached tetrahedra must be checked sequentially [S1].
7. **Intersection Calculation:** If a tetrahedron face (triangle) is intersected, determine the barycentric coordinates of the intersection point [S1].
8. **Scalar Interpolation:** Interpolate the scalar value at the intersection point using the barycentric coordinates and the vertex scalar values [S1].
9. **Iso-surface Computation:** Compute the precise intersection with the iso-surface using linear interpolation of the scalar values [S1].

**Formulas:**
- Barycentric scalar interpolation at a triangle face intersection: $S = \alpha S_0 + \beta S_1 + \gamma S_2$, where $\alpha, \beta, \gamma$ are the barycentric coordinates of the intersection point and $S_0, S_1, S_2$ are the scalar values at the triangle's vertices [S1].
- Linear iso-surface crossing along a ray segment: $t_{iso} = t_0 + \frac{V_{iso} - S_0}{S_1 - S_0} (t_1 - t_0)$, where $t_0$ and $t_1$ are the ray parameters at the entry and exit points of the tetrahedron, $S_0$ and $S_1$ are the interpolated scalars at those points, and $V_{iso}$ is the target iso-value [S1].

**Parameters:**
* **Grid Levels:** The number of layers in the hierarchical grid. Parker et al. used three layers [S1].
* **Iso-value:** The scalar value defining the surface. It can be changed during rendering as the surface is computed on the fly [S1].

**Edge Cases and Pitfalls:**
* **Curvilinear Volumes:** The method does not natively support curvilinear volumes, although they can be handled by decomposing hexahedra into five tetrahedra [S1].
* **Performance:** Without connectivity, all tetrahedra attached to a cell must be checked, which can be computationally expensive if cells are large or contain many tetrahedra [S1].
* **Precision:** Linear interpolation is used for scalar values and iso-surface intersection, which may introduce artifacts if the scalar field is not piecewise linear [S1].

### Plücker Space Traversal
Plücker Space Traversal is an optimized traversal algorithm for unstructured and curvilinear data sets that uses Plücker coordinates to test line orientations after locating the initial cell via a kd-tree [S1][S2, unofficial]. It sets itself apart by avoiding explicit tetrahedron-face intersection tests and instead relying on algebraic line orientation checks [S2, unofficial]. Choose it when rendering curvilinear volumes or when faster traversal is needed than brute-force cell attachment [S1]. Link: [Plücker Space Traversal](plucker-space-traversal.md).

## Operating characteristics
* **Time Complexity:** Linear with the number of processors for parallel implementation [S1][S2, unofficial]. Sequentially, it depends on the number of tetrahedra per grid cell and the number of cells traversed [S1].
* **Memory Complexity:** Proportional to the number of tetrahedra times the average number of grid cells they intersect, plus the grid structure overhead [S1][S2, unofficial].
* **Measured Performance:** Rendered a bioelectric field with over one million tetrahedra at interactive rates on a 512x512 viewport using 16 processors or more [S1][S2, unofficial].
* **Strengths:** Enables interactive rendering of large irregular volumes on supercomputers; allows dynamic iso-value changes; simple implementation without complex connectivity [S1][S2, unofficial].
* **Limitations:** Does not support curvilinear volumes natively; potentially high computational cost per pixel due to brute-force testing of attached tetrahedra [S1].

## Background
Grid-based Traversal was introduced by Parker et al. [PPL∗ 99] as one of the first methods capable of rendering irregular volume data at interactive rates on a supercomputer [S1][S2, unofficial]. It was demonstrated using a bioelectric field simulation with over one million tetrahedra [S1][S2, unofficial]. The method scales linearly with the number of processors [S1][S2, unofficial].
