# Software Cell-Projection Progressive Rendering

Also called: Software Cell-Projection Rendering, Weber et al. (2001a) software method

## Overview
Software Cell-Projection Progressive Rendering is a software-based method for rendering Adaptive Mesh Refinement (AMR) data sets [S1, unofficial][S2, unofficial]. It solves the problem of visualizing multi-resolution grids by allowing the contribution of coarser cells to be replaced with more accurate representations from finer hierarchy levels [S1, unofficial][S2, unofficial]. Unlike its siblings, it explicitly supports progressive rendering through a pixel-level replacement mechanism, enabling interactive rates by dynamically adjusting traversal depth based on frame time [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**

*   **Output:** Not given in the sources [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **Pixel Metadata:** Additional information stored per pixel during the rendering of each hierarchy level to facilitate replacement by finer levels [S1, unofficial][S2, unofficial].
*   **Dual Mesh/Stitch Cells:** Used in the later variant to define interpolation schemes [S2, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Not given in the sources [S1, unofficial][S2, unofficial].
2.  **Hierarchy Traversal:** Iterate through the AMR hierarchy levels [S1, unofficial][S2, unofficial]. The traversal depth into individual patches is chosen dynamically based on criteria such as the number of pixels covered by a voxel and the measured rendering time for the current frame, aiming to achieve interactive rendering rates [S1, unofficial][S2, unofficial].
3.  **Level Rendering:** For the current level of the AMR hierarchy, project the cells onto the image plane [G]. While rendering, store additional information for each pixel [S1, unofficial][S2, unofficial].
4.  **Replacement/Refinement:** Use the stored pixel information to identify parts of the domain that are refined by a finer hierarchy level [S1, unofficial][S2, unofficial]. Replace the contribution of these refined parts with a more accurate representation from the finer level [S1, unofficial][S2, unofficial]. This replacement mechanism supports the progressive rendering capability [S1, unofficial][S2, unofficial].
5.  **Iteration:** Repeat steps 2-4 for subsequent levels or refinement passes until the desired quality or time budget is met [G].

**Parameters:**
*   **Time Budget:** Measured rendering time for the current frame, used to determine traversal depth [S1, unofficial][S2, unofficial].
*   **Coverage Criteria:** Number of pixels covered by a voxel, used as a criterion for traversal depth [S1, unofficial][S2, unofficial].

## Subtopics

### Progressive Cell-Projection with Dual Mesh
This variant utilizes a $C^0$ continuous interpolation scheme defined using the dual mesh and stitch cells, which were originally introduced for isosurface extraction [S2, unofficial]. This interpolation method is integrated into the progressive cell-projection rendering approach to improve visual continuity [S2, unofficial]. It sets itself apart by providing smoother transitions between refinement levels compared to piecewise-constant cell projection [S2, unofficial].

## Background
The method was described by Weber et al. in 2001a as a software cell-projection-based approach to render AMR data sets in higher quality [S1, unofficial][S2, unofficial]. It builds on [Exact AMR Rendering](4399-exact-amr-rendering.md), which treats cells as piecewise-constant cubic cells [Parent]. In later work, Weber et al. (2001c) extended this approach by incorporating a $C^0$ continuous interpolation scheme using dual mesh and stitch cells from their isosurface extraction work (Weber et al., 2003a) [S2, unofficial]. The method is part of a broader framework for remote, interactive rendering of AMR data, which also includes hardware-accelerated alternatives [S2, unofficial].
