# Spatial Decomposition for Adaptive Projection

Also called: AMRRegion decomposition, Image plane decomposition

## Overview
Spatial Decomposition for Adaptive Projection is a spatially-aware parallelization strategy for inherently spatial tasks, decomposing the domain into subdomains realized as individual data containers for independent processing [S1]. It distributes the image plane equally among processors rather than decomposing the data domain, ensuring that each processor handles a distinct spatial region of the final output [S1]. Communication overhead is negligible because processors only communicate at the end of the projection to share non-overlapping final results, unlike methods requiring frequent synchronization [S1].

## How it works
The method decomposes the computational domain into subdomains realized as individual data containers for independent processing [S1]. The core mechanism involves distributing the image plane equally among processors, with each processor responsible for a specific rectangular prism of the volume along the line of sight [S1].

### Inputs and Outputs
*   **Input:** The computational domain (AMR grids), the projection direction (line of sight), and the total number of processors $P$ [S1].
*   **Output:** A global set of unique points $(x_p, dx_p, y_p, dyp, v)$ representing the adaptive projection, constructed by joining local results from all processors [S1].

### Data Structures
The primary data structure for a processor's workload is the `AMRRegion`, defined as a rectangular prism [S1].
*   **Dimensions:** $(L_i, L_j, L_d)$ [S1].
*   **Coordinate System:** Axes are rotated such that the line of sight corresponds to the third dimension ($L_d$) [S1].
*   **Constraints:**
    *   $L_i \times L_j$ is constant across all processors, representing the fixed area of the image plane assigned to each processor [S1].
    *   $L_d$ spans the entire computational domain along the axis of projection [S1].
*   **Local Result:** Each processor maintains a list of points $(x_p, dx_p, y_p, dyp, v)$ constrained to lie within its assigned `AMRRegion` [S1].

### Steps
1.  **Domain Decomposition:** Divide the computational domain such that the image plane is distributed equally among the $P$ processors [S1].
2.  **Prism Allocation:** For each processor $k$ (where $k \in [0, P-1]$), allocate a rectangular prism `AMRRegion` with dimensions $(L_i, L_j, L_d)$ [S1]. Ensure the axes are rotated so the projection axis aligns with $L_d$ [S1]. The area $L_i \times L_j$ must be identical for all $k$ [S1].
3.  **Local Projection:** Each processor independently executes the Adaptive Projection algorithm on the AMR data [G]. The algorithm computes line integrals along the sight-line [G]. Constraint: Only points $(x_p, dx_p, y_p, dyp, v)$ that fall within the processor's allocated `AMRRegion` are included in the local result set [S1].
4.  **Result Merging:** After all processors complete their local projections, they join their image arrays [S1]. Since the `AMRRegions` are spatially disjoint in the image plane, the resulting sets of points are guaranteed to be unique, requiring no deduplication logic beyond simple concatenation [S1].

    """
    Performs adaptive projection using spatial decomposition.
    
    Args:
        amr_grids: List of AMR grid objects.
        num_processors: Total number of MPI ranks.
        projection_axis: Direction of projection.
        image_plane_width, image_plane_height: Total dimensions of the image plane.
        rank: The MPI process ID.
        
    Returns:
        Global list of unique points (xp, dxp, yp, dyp, v).
    """
    # 1. Determine image plane dimensions per processor
    # Li * Lj is constant across processors. Assume square split for simplicity.
    split = int(num_processors ** 0.5)
    Li = image_plane_width // split
    Lj = image_plane_height // split
    # Ld spans the entire computational domain along the projection axis.
    Ld = max(grid.extent[projection_axis] for grid in amr_grids) # [G] Standard domain extent calculation

    local_results = []
    # 2. Each processor determines its specific region in the image plane
    ox = (rank % split) * Li
    oy = (rank // split) * Lj

    # Define the bounding box for this processor's AMRRegion
    # In the rotated coordinate system where projection axis is z:
    region_min = (ox, oy, 0)
    region_max = (ox + Li, oy + Lj, Ld)

    # 3. Perform local adaptive projection
    for grid in amr_grids:

### Edge Cases and Pitfalls
*   **File Format Compatibility:** Enzo and Orion output formats store one file per processor with unordered grids [S1]. This lack of spatial decomposition in the input files causes poor scaling, as processors must read grid datasets from many files to find relevant data [S1].
*   **Scaling Limit:** Strong scaling holds well between 4 and 64 processors for the Santa Fe Light Cone dataset [S1]. At 128 processors, algorithmic overhead dominates disk I/O cost, causing deviation from ideal scaling [S1].

## Operating characteristics
*   **Communication Overhead:** Negligible because processors only communicate at the end of the projection to share non-overlapping final results, avoiding frequent synchronization [S1].
*   **Scaling:** Strong scaling is effective up to 64 processors for the Santa Fe Light Cone dataset ($512^3$ resolution, 5.5 $\times 10^8$ elements) [S1]. Beyond this, algorithmic overhead becomes the dominant cost, surpassing disk I/O [S1].
*   **Strengths:** Minimal communication and simple merge logic due to spatial disjointness [S1].
*   **Limitations:** Performance degrades significantly if the input data format is not spatially decomposed (e.g., Enzo/Orion formats), leading to excessive I/O [S1].

## Background
This method is implemented within the `yt` analysis toolkit, which provides a `ParallelAnalysisInterface` for spatially-aware decomposition [S1]. It was developed to address the parallelization needs of adaptive projection in astrophysical simulation data, where data is inherently spatial and often stored in formats that do not align with processor boundaries [S1].
