# Adaptive Sampling via Per-Fragment Clipping

Also called: Clipped Cell Projection, Per-fragment clipping for adaptive sampling

## Overview
Adaptive Sampling via Per-Fragment Clipping is a technique to avoid aliasing in volume rendering by clipping tetrahedral cells on the graphics card using up to two parallel planes, rather than geometrically splitting cells or using pre-integration [S1]. It allows for gradient-based opacity and multidimensional transfer functions, solving the aliasing problem where sharp transitions in transfer functions are missed when sampling only at cell vertices [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh where each vertex has a scalar value, and a transfer function (potentially multidimensional or gradient-based) that maps scalars to color and opacity. The method requires passing classified colors and opacities to the GPU, along with distances to cutting planes [S1].
*   **Output:** A rendered image with correct compositing of clipped cell segments in back-to-front order [S1].

**Data Structures:**
*   **Tetrahedron Data:** To support per-fragment clipping, the data transfer to the GPU increases significantly. Each tetrahedron requires 60 floats [S1]. This replaces scalar values with pre-classified colors and adds distances to the cutting planes for each vertex [S1].
*   **Clipping Planes:** Defined by the distance from each vertex along the viewing ray to the plane [S1].

**Steps:**
1.  **Data Preparation:** Replace scalar values at tetrahedron vertices with classified colors and opacities. Calculate and store the distance from each vertex to the near and far clipping planes along the viewing ray [S1].
2.  **Projection:** Project the 3D vertices of each tetrahedron to 2D screen space. The projected edges divide the image plane into polygons [S1].
3.  **Rasterization and Interpolation:** For each fragment within a projected polygon, the rasterizer interpolates the distances to the near and far clipping planes from the vertex values [S1]. The distance between the front and back faces is also known [S1].
4.  **Per-Fragment Clipping Decision:** For each viewing ray segment corresponding to a fragment, determine its position relative to the near and far clipping planes [S1]:
    *   If the entire segment falls between the two planes, do not clip the segment [S1].
    *   If the front part of the ray is behind the far plane or the back part is in front of the near plane, discard the segment [S1].
    *   If the front part of the segment is in front of the near plane, clamp the front scalar value to that of the front plane and shorten the segment length [S1].
    *   If the back part of the segment is behind the far plane, clip the cell at the far plane [S1].
5.  **Rendering:** Render the clipped cells piece-by-piece in back-to-front order [S1].

**Parameters:**
*   **Data Transfer Size:** 60 floats per tetrahedron [S1].
*   **Fragment Program Overhead:** 18 instructions for clipping plus any required for ray integration [S1].
*   **Extra Cells Rendered:** On average about 2.5 percent for a randomly selected control point in a 1D transfer function across three example meshes [S1].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Aliasing occurs if transfer functions are sampled only at cell vertices because sharp transitions within cells are missed, resulting in blocky, blurry images [S1].
*   **Pre-integration Limitations:** Pre-integration limits classification to 1D transfer functions, prevents gradient-based opacity scaling, and cannot support multidimensional transfer functions or global illumination [S1].

## Operating characteristics
*   **Time Complexity:** The method introduces extra load due to extra data transfer, extra fragment program instructions (18 for clipping), and rendering clipped cells multiple times [S1]. The number of extra cells rendered depends on the mesh and classification, averaging about 2.5 percent for a randomly selected control point in a 1D transfer function [S1].
*   **Memory Complexity:** Data transfer increases to 60 floats per tetrahedron [S1].
*   **Strengths:** Allows for gradient-based opacity and multidimensional transfer functions, avoiding the limitations of pre-integration [S1]. It avoids the high overhead of geometric cell splitting when transfer functions change [S1].
*   **Limitations:** Increased data transfer and fragment program overhead [S1].
*   **When to Use:** When using multidimensional or gradient-based transfer functions that cannot be handled by pre-integration, and when geometric cell splitting is too expensive [S1].
*   **When Not to Use:** When simple 1D transfer functions are sufficient and pre-integration is acceptable, or when hardware clipping of polygons is preferred over per-fragment clipping [S1].

## Background
The method was introduced as an alternative to pre-integration and geometric cell splitting (Williams, Max, and Stein) to solve aliasing in volume rendering [S1]. It was developed by the authors of the source paper [S1].
