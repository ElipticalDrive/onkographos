# Visible Faces Driven Ray Casting

Also called: VF-Ray

## Overview
Visible Faces Driven Ray Casting (VF-Ray) is a memory-efficient ray casting algorithm for unstructured tetrahedral and hexahedral grids that exploits ray coherence to minimize memory footprint [S1]. It reduces the storage of expensive face plane parameters by processing pixels in groups defined by visible exterior faces, storing only the face data for the current traversal set in a temporary buffer [S1]. Unlike its parent, Exterior-Face Ray Casting, which casts rays through all visible exterior faces of subvolumes, VF-Ray explicitly manages the lifecycle of face data structures to avoid storing adjacency information for the entire volume, making it suitable for large datasets where memory is constrained [S1].

## How it works
**Inputs:** Unstructured grid (vertices, cells), scalar field values, viewing direction, screen resolution.
**Outputs:** Rendered image (color and opacity per pixel).

**Data Structures:**
1.  **Vertices List:** Array of vertex coordinates.
2.  **Cells List:** Array of cell definitions (e.g., tetrahedra indices).
3.  **Use_set:** For each vertex $v$, a list of all cells incident to $v$. This structure is used to handle degeneracies [S1].
4.  **Face Data:** A structure containing geometry and plane equation constants for a face. This is the most memory-intensive component [S1].
5.  **computedFaces:** A temporary buffer storing face data for internal faces intersected by rays within the current visible set [S1].

**Algorithm Steps:**

1.  **Preprocessing:**
    *   Create the list of vertices and cells.
    *   Build the `Use_set` for each vertex, storing all incident cells [S1].

2.  **Visibility Determination:**
    *   Identify **external faces**: faces belonging to only one cell [S1].
    *   Identify **visible faces**: external faces whose normal vector $\mathbf{n}$ makes an angle greater than $90^\circ$ with the viewing direction $\mathbf{v}$ (i.e., $\mathbf{n} \cdot \mathbf{v} < 0$) [S1].

3.  **Processing Loop (per visible face):**
    *   Project the current visible face onto the screen to determine the **visible set** (the set of pixels covered by the face's projection) [S1].
    *   Initialize the `computedFaces` buffer as empty [S1].
    *   For each pixel $p$ in the visible set:
        1.  Cast a ray from the camera through pixel $p$.
        2.  Perform ray traversal through the volume.
        3.  Compute intersections with cell faces.
        4.  **Degeneracy Handling:**
            *   If the ray hits a vertex $v$, scan the `Use_set` of $v$ to find the next valid intersection [S1].
            *   If the ray hits an edge $v_0v_1$, scan the `Use_set` of $v_0$ and $v_1$ to find the next valid intersection [S1].
        5.  Identify internal faces intersected by the ray.
        6.  **Face Data Caching:**
            *   If an intersected internal face is already in `computedFaces`, read its parameters from the buffer [S1].
            *   Otherwise, compute the face parameters (plane equation constants) and store them in `computedFaces` [S1].
        7.  **Rendering:**
            *   Use the face data to evaluate the traversed distance $d$ within the current cell [S1].
            *   Retrieve entry scalar value $s_0$ and exit scalar value $s_1$ [S1].
            *   Compute the cell contribution to the pixel's color and opacity using $d$, $s_0$, $s_1$, and an illumination integral [S1].
    *   Clear the `computedFaces` buffer [S1].

**Pseudocode:**

```python
def vf_ray_cast(vertices, cells, scalar_field, view_direction, screen_resolution):
    # 1. Preprocessing
    use_set = build_use_set(vertices, cells)
    external_faces = find_external_faces(cells)
    visible_faces = [f for f in external_faces if dot(f.normal, view_direction) < 0]
    
    image = empty_image(screen_resolution)
    
    # 2. Process each visible face
    for face in visible_faces:
        visible_set = project_face_to_pixels(face, screen_resolution)
        computed_faces = {}  # Temporary buffer: face_id -> face_data
        
        # 3. Process pixels in the visible set
        for pixel in visible_set:
            ray = cast_ray_through_pixel(pixel)
            current_pos = ray.origin
            color = (0, 0, 0)
            opacity = 0
            
            # Ray traversal loop
            while not ray_exited_volume(ray, cells):
                # Find intersection with current cell faces
                intersection, hit_face_id = find_intersection(ray, current_pos, cells)
                
                # Handle degeneracies using Use_set
                if is_vertex_hit(intersection):
                    hit_vertex = intersection
                    hit_face_id = find_next_intersection_via_use_set(hit_vertex, use_set, ray)
                elif is_edge_hit(intersection):
                    hit_edge = intersection
                    hit_face_id = find_next_intersection_via_use_set(hit_edge.v0, use_set, ray)
                    if hit_face_id is None:
                        hit_face_id = find_next_intersection_via_use_set(hit_edge.v1, use_set, ray)
                
                # Get or compute face data
                if hit_face_id in computed_faces:
                    face_data = computed_faces[hit_face_id]
                else:
                    face_data = compute_face_data(hit_face_id, vertices, cells)
                    computed_faces[hit_face_id] = face_data
                
                # Evaluate traversal
                d = evaluate_traversed_distance(current_pos, intersection, ray.direction)
                s0 = interpolate_scalar(scalar_field, current_pos, cells)
                s1 = interpolate_scalar(scalar_field, intersection, cells)
                
                # Compute contribution
                cell_color, cell_opacity = compute_cell_contribution(d, s0, s1, face_data)
                color = blend_color(color, cell_color, opacity, cell_opacity)
                opacity = blend_opacity(opacity, cell_opacity)
                
                current_pos = intersection
            
            image[pixel] = color, opacity
        
        # Clear buffer for next visible face
        computed_faces.clear()
        
    return image

def build_use_set(vertices, cells):
    use_set = {v: [] for v in vertices}
    for cell in cells:
        for vertex in cell.vertices:
            use_set[vertex].append(cell)
    return use_set

def find_external_faces(cells):
    face_counts = {}
    for cell in cells:
        for face in cell.faces:
            face_id = get_face_id(face)
            face_counts[face_id] = face_counts.get(face_id, 0) + 1
    return [face for face_id, count in face_counts.items() if count == 1]

def find_next_intersection_via_use_set(vertex_or_edge, use_set, ray):
    # Scan incident cells to find the next valid intersection along the ray
    candidates = []
    if isinstance(vertex_or_edge, Vertex):
        incident_cells = use_set[vertex_or_edge]
    else: # Edge
        incident_cells = set(use_set[vertex_or_edge.v0]) & set(use_set[vertex_or_edge.v1])
        
    for cell in incident_cells:
        dist = ray_intersect_cell(ray, cell)
        if dist > 0:
            candidates.append((dist, cell))
            
    if not candidates:
        return None
    candidates.sort(key=lambda x: x[0])
    return candidates[0][1].face_id # Return the face ID of the next intersection
```

## Subtopics

### [VF-Ray-GPU](15664-vf-ray-gpu.md)
A GPGPU implementation of VF-Ray that parallelizes visibility determination, projection, and ray traversal across CUDA kernels, using a hash-based local memory buffer to minimize global memory bandwidth.

## Operating characteristics
**Time Complexity:** The algorithm's performance depends on the number of visible faces and the coherence of rays within each visible set. Processing each visible face involves projecting it and traversing rays for the covered pixels. The use of `computedFaces` reduces redundant plane equation computations for neighboring rays [S1].

**Memory Complexity:** VF-Ray significantly reduces memory footprint compared to methods storing full adjacency structures. It only stores `Use_set` (incident cells per vertex) and the `computedFaces` buffer, which contains face data only for the current visible set [S1]. The `computedFaces` buffer is cleared after each visible face is processed, keeping memory usage proportional to the maximum number of internal faces intersected by rays in a single visible set [S1].

**Strengths:**
*   Memory efficiency for large unstructured grids [S1].
*   Exploits ray coherence to improve caching performance [S1].
*   Handles degeneracies (vertex/edge hits) correctly using `Use_set` [S1].

**Limitations:**
*   Requires building and storing the `Use_set` structure, which can be memory-intensive for highly connected meshes [S1].
*   Performance may degrade if ray coherence is low (e.g., complex geometry causing many distinct visible faces with small pixel sets) [S1].
*   Not given in the sources: Specific scaling behavior on multi-core CPUs vs. GPUs is not detailed in the base algorithm description, though a GPU variant exists [S1].

## Background
VF-Ray was introduced as a memory-efficient ray casting algorithm for unstructured grids, specifically addressing the high memory cost of storing face plane parameters in traditional ray casting methods [S1]. It builds on the concept of ray coherence, where neighboring rays tend to intersect the same internal faces [S1]. The algorithm was developed to handle the limitations of previous approaches, such as Bunyk's method, which could fail to continue ray traversal when hitting edges or vertices [S1]. The method is cited in the context of volume rendering for unstructured tetrahedral and hexahedral meshes [S1].
