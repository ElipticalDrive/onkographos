# Exterior-Face Ray Casting

Also called: Distributed-memory volume ray-casting, Parallel Volume Ray-Casting on Unstructured Grids, Visible Exterior Face Rendering

## Overview
Exterior-Face Ray Casting is a parallel volume rendering algorithm for unstructured grids (tetrahedral and hexahedral) that restricts ray casting to visible exterior faces of subvolumes, traversing elements until exiting another exterior face [S1, S2, unofficial]. It sets itself apart from its parent, [Projection-Based Ray Casting for Curvilinear Grids](1756-projection-based-ray-casting-for-curvilinear-grids.md), by explicitly identifying and projecting only the *visible* exterior faces of partitioned subdomains to define the exact screen area for ray casting, thereby avoiding redundant traversal of invisible internal boundaries [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Unstructured grid data (elements, connectivity, scalar values), viewing position, transfer function (mapping scalar to color/opacity), image resolution.
- **Outputs:** Final composited image.

**Data Structures:**
- **Exterior Face List:** A list of all faces on the boundary of the local subvolume. Each face stores vertex coordinates, normal vector, and element connectivity [S1, S2, unofficial].
- **Visible Face List:** A subset of the Exterior Face List containing only faces visible from the current viewing position [S1, S2, unofficial].
- **Ray Buffer:** A two-dimensional array of linked lists. Each processor maintains a local buffer corresponding to its assigned image region. Incoming ray segments are sorted into linked lists by pixel address [S2, unofficial].

**Preprocessing:**
1.  **View-Independent (Once):**
    -   Find connectivity between elements.
    -   Identify all exterior faces of the subvolume.
    -   Calculate face normals [S1, S2, unofficial].
2.  **View-Dependent (Per View):**
    -   Extract visible faces from the Exterior Face List by checking face normals against the viewing direction [S1, S2, unofficial].
    -   Orthographically project visible exterior faces onto the screen to produce a set of convex polygons in screen coordinates [S1, S2, unofficial].

**Ray Casting Loop:**
1.  Traverse the Visible Face List in scanline order [S1, S2, unofficial].
2.  For each visible face, cast rays from the eye [S1, S2, unofficial].
3.  A ray enters the data domain through an exterior face and marches element by element using connectivity information until it exits through another exterior face [S1, S2, unofficial].
    -   *Note:* Due to concavity, holes, or saw-toothed partition boundaries, a ray may enter and exit multiple exterior faces [S1, S2, unofficial].
4.  **Segmentation:** Break the ray into segments based on element boundaries. The compositing operation is associative, allowing segments to be processed independently [S1, S2, unofficial].
5.  **Sampling:**
    -   *Adaptive (Expensive):* For a linear element with interpolation function $f(x,y,z)$, ray $P(t) = P(0) + td$, entry $a$, exit $b$, and constant $k$ (sampling rate for unit change in function value), the sample rate $r$ is defined as:
        $$ r = \frac{|f(P(b)) - f(P(a))|}{b - a} \cdot k $$
        This is noted as expensive and often not used in practice [S1, S2, unofficial].
    -   *Fixed (Practical):* Precompute a fixed sampling interval $dt$. A good principle for linear elements is to sample at least one additional point $c$ between entering point $a$ and leaving point $b$ [S1, S2, unofficial].
        -   Estimate $dt$ using:
            $$ dt = 0.5 \times \min\left(\frac{l_x}{n_e}, \frac{l_y}{n_e}, \frac{l_z}{n_e}\right) $$
            where $l_x, l_y, l_z$ are bounding box sizes and $n_e$ is the total number of elements [S1, S2, unofficial].
            *Note:* Source [S1, unofficial] cites an alternative estimation: $dt = \frac{l_x + l_y + l_z}{n_e}$ [S1, unofficial].
        -   Use the Trapezoid rule to calculate the value of the interval between sample points [S1, S2, unofficial].
        -   *Gaussian Quadrature Approximation:* For linear elements, approximate intensity by computing the value at the middle of the segment. For quadratic elements, sample two points; for cubic elements, three points. This approximates a polynomial of degree $2n-1$ using $n$ points [S1, S2, unofficial].
6.  **Color/Opacity Mapping:** At each sample point, use the interpolated function value to obtain color and opacity from a look-up table [S1, S2, unofficial].
7.  **Intensity Calculation:** Compute intensity for a segment from entry $a$ to exit $b$ using:
    $$ I(a, b) = \int_a^b e^{-\int_a^s \alpha(s') ds'} I(t) dt $$
    where $\alpha$ (or $c$) is the attenuation coefficient and $I(t)$ is the intensity at point $t$ [S1, S2, unofficial].
8.  **Compositing:** Form the final image value by compositing front-to-back the intensity values of sample points along the ray [S1, S2, unofficial].
9.  **Early Ray Termination:** Terminate a ray when the accumulated opacity value reaches unity [S2, unofficial].

**Parallel Compositing:**
-   Ray segments contributing to a pixel cannot be combined until all are received and sorted in visibility order by the responsible processor [S2, unofficial].
-   **Approach 1:** Separate local rendering from global compositing. Send all segments after local tracing finishes. Causes large messages and network congestion [S2, unofficial].
-   **Approach 2:** Overlap rendering and compositing. Send segments immediately after generation. Improves overall image compositing performance by as much as 40% [S2, unofficial].
-   **Image Partitioning:** Image space is partitioned evenly into horizontal strips for simplicity [S2, unofficial].

**Pseudocode:**

```python
def exterior_face_ray_casting(grid, view_position, transfer_function, image_width, image_height):
    # 1. View-Independent Preprocessing (Done Once)
    exterior_faces = find_exterior_faces(grid)
    for face in exterior_faces:
        face.normal = calculate_normal(face.vertices)
    
    # 2. View-Dependent Preprocessing (Per View)
    visible_faces = []
    for face in exterior_faces:
        if is_visible(face, view_position):
            visible_faces.append(face)
            
    # Project visible faces to screen to determine ray casting regions
    screen_polygons = project_to_screen(visible_faces, view_position)
    
    # 3. Initialize Ray Buffer for Parallel Compositing
    # Each processor has a local buffer: 2D array of linked lists
    ray_buffer = initialize_ray_buffer(image_width, image_height)
    
    # 4. Ray Casting Loop
    for face in visible_faces:
        # Cast rays through the projected polygon of the face
        for pixel in screen_polygons[face]:
            ray = create_ray_from_eye(pixel, view_position)
            segments = trace_ray_through_elements(ray, grid)
            
            # 5. Process Segments
            segment_results = []
            for segment in segments:
                # Sampling
                samples = sample_segment(segment, transfer_function)
                
                # Intensity Calculation
                intensity = 0.0
                accumulated_opacity = 0.0
                
                # Front-to-back compositing within segment
                for sample in samples:
                    color, opacity = transfer_function(sample.value)
                    # Simple accumulation for demonstration; 
                    # full formula involves attenuation integral
                    intensity += color * opacity * (1 - accumulated_opacity)
                    accumulated_opacity += opacity * (1 - accumulated_opacity)
                    
                    # Early Ray Termination
                    if accumulated_opacity >= 1.0:
                        break
                
                segment_results.append({
                    'pixel': pixel,
                    'intensity': intensity,
                    'opacity': accumulated_opacity,
                    'depth': segment.depth # For sorting
                })
            
            # 6. Send Segments to Ray Buffer (Parallel Step)
            for result in segment_results:
                add_to_ray_buffer(ray_buffer, result)
                
    # 7. Global Compositing
    final_image = composite_ray_buffer(ray_buffer)
    return final_image

def sample_segment(segment, transfer_function):
    # Fixed Sampling Implementation
    a, b = segment.entry, segment.exit
    dt = estimate_dt(segment.grid)
    
    samples = []
    t = a
    while t < b:
        point = segment.start + t * segment.direction
        value = interpolate_grid(segment.grid, point)
        samples.append({'point': point, 'value': value})
        
        # Trapezoid rule approximation between points
        # (Simplified: just storing points for compositing loop)
        
        t += dt
        if t > b:
            t = b # Ensure exit point is sampled
            
    return samples

def estimate_dt(grid):
    lx, ly, lz = grid.bounding_box_size
    ne = grid.num_elements
    # Source [S2, unofficial] formula
    return 0.5 * min(lx/ne, ly/ne, lz/ne)
```

## Subtopics

### [Visible Faces Driven Ray Casting](15651-visible-faces-driven-ray-casting.md)
A memory-efficient variant that reduces memory footprint by storing only the face data of the most recent traversals, exploiting ray coherence among neighboring pixels. It sets itself apart from Exterior-Face Ray Casting by explicitly managing a temporary buffer (`computedFaces`) to cache internal face parameters for the current visible set, thereby avoiding redundant geometric computations for rays traversing the same internal boundaries.

## Operating characteristics
- **Time Complexity:** Dependent on the number of visible exterior faces and the number of elements traversed per ray. Adaptive sampling increases complexity significantly [S1, S2, unofficial].
- **Memory Complexity:** Requires storage for the exterior face list, visible face list, and the Ray Buffer. The Ray Buffer size grows during rendering and depends on viewing position, data shape, and partitioning [S2, unofficial].
- **Measured Performance:** Overlapping ray casting and compositing can improve overall image compositing performance by as much as 40% [S2, unofficial].
- **Scaling:** Load balancing is affected by early ray termination. Subvolumes with larger projected areas of high-density regions (high opacity) cause rays to terminate earlier, traversing fewer elements, leading to uneven load distribution [S2, unofficial].
- **Strengths:** Efficiently handles unstructured grids with concavities and holes; parallelizable via associative compositing [S1, S2, unofficial].
- **Limitations:** Adaptive sampling is expensive; Ray Buffer management can be complex; load balancing issues due to variable ray traversal lengths [S1, S2, unofficial].

## Background
Originated in the mid-1990s for parallel volume rendering on distributed-memory architectures using unstructured grids [S1, S2, unofficial]. The method addresses the challenges of rendering irregular, partitioned data volumes where traditional regular grid ray casting is not applicable [S1, S2, unofficial].
