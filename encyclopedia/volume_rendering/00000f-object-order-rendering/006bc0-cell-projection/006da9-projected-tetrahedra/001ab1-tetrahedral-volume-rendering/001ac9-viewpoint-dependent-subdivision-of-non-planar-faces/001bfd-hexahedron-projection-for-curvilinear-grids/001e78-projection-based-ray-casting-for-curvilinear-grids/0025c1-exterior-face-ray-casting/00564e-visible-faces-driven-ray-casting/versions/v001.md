# Visible Faces Driven Ray Casting

Also called: VF-Ray

## Overview
Visible Faces Driven Ray Casting (VF-Ray) is a memory-efficient ray casting algorithm for unstructured grids (tetrahedral and hexahedral) that reduces memory footprint by storing only the face data of the most recent traversals, exploiting ray coherence among neighboring pixels [S1]. It sets itself apart from its parent, Exterior-Face Ray Casting, by explicitly managing a temporary buffer (`computedFaces`) to cache internal face parameters for the current visible set, thereby avoiding redundant geometric computations for rays traversing the same internal boundaries [S1].

## How it works
**Inputs:** Unstructured grid (vertices, cells, faces), viewing direction, scalar field values.
**Outputs:** Image (color and opacity per pixel).

**Data Structures:**
1.  **Vertices List:** Array of vertex coordinates.
2.  **Cells List:** Array of cell definitions (e.g., tetrahedra defined by 4 vertex indices).
3.  **Use_set:** For each vertex $v$, a list of all cells incident to $v$. This structure is used to handle ray traversal degeneracies at vertices and edges [S1].
4.  **Face Data Structure:** Stores geometry and face parameters, specifically the constants for the plane equation defined by the face. This is identified as the most consuming data structure in ray casting [S1].
5.  **computedFaces:** A temporary buffer storing face data for internal faces intersected by rays within the current visible set. This allows reuse without recomputation [S1].

**Algorithm Steps:**

1.  **Preprocessing:** Create the list of vertices, list of cells, and the `Use_set` for each vertex [S1].
2.  **Identify Visible Faces:** Determine the visible faces from the external faces of the volume.
    *   An **external face** is a face that belongs to only one cell and is not shared by any other cell [S1, BKS97].
    *   A **visible face** is an external face whose normal $\mathbf{n}$ makes an angle greater than $90^\circ$ with the viewing direction $\mathbf{v}$. Mathematically, this is determined by the dot product: $\mathbf{n} \cdot \mathbf{v} < 0$ (assuming $\mathbf{v}$ points from eye to scene) or $\mathbf{n} \cdot \mathbf{v} > 0$ (if $\mathbf{v}$ points from scene to eye). The source states "angle greater than 90 degrees" [S1].
3.  **Process Visible Faces:** Iterate through each visible face.
    *   Project the visible face onto the screen to determine the **visible set** (the set of pixels under the projection of the given visible face) [S1].
4.  **Ray Traversal and Intersection:** For each pixel in the visible set:
    *   Cast a ray.
    *   Perform ray traversal and compute each pair of intersections with the volume elements [S1].
    *   Determine internal faces by the intersections.
    *   Store the face data of these internal faces in the `computedFaces` buffer [S1].
5.  **Face Data Lookup:** Whenever a ray hits an internal face:
    *   Check if the face data is already stored in the `computedFaces` buffer.
    *   If yes, read the face data from the buffer without recomputing the face parameters [S1].
    *   If no, compute the parameters and store them in the buffer [S1].
6.  **Rendering:** Use the face data to evaluate:
    *   Traversed distance $d$.
    *   Entry scalar value $s_0$.
    *   Exit scalar value $s_1$.
    *   Compute the cell contribution for the pixel color and opacity using $d$, $s_0$, $s_1$, and an illumination integral [S1].
7.  **Cleanup:** After all pixels in the visible set are processed, clear the `computedFaces` buffer [S1].

**Handling Degeneracies:**
Degeneracies occur when a ray hits an edge or a vertex. VF-Ray handles this using the `Use_set` data structure [S1]:
*   **Vertex Hit:** When a ray hits a vertex $v$, scan the cells belonging to the `Use_set` of $v$ to find the next intersection [S1].
*   **Edge Hit:** When a ray hits an edge $v_0v_1$, scan the `Use_set` of $v_0$ and $v_1$ to find the next intersection [S1].
This guarantees that the image will be correctly generated, avoiding the incorrect pixel colors that can occur in approaches (like Bunyk's) that only check neighboring cells [S1].

**Pseudocode:**

```python
def vf_ray_casting(vertices, cells, faces, view_direction, scalar_field):
    # 1. Preprocessing
    use_set = build_use_set(vertices, cells)
    computed_faces = {} # Temporary buffer: face_id -> face_data

    # 2. Identify External and Visible Faces
    external_faces = get_external_faces(faces)
    visible_faces = []
    for face in external_faces:
        if is_visible(face.normal, view_direction):
            visible_faces.append(face)

    # 3. Process each visible face
    for face in visible_faces:
        # Project face to screen to get visible set (pixels)
        visible_set = project_to_pixels(face)

        # 4. Ray Traversal for each pixel in visible set
        for pixel in visible_set:
            ray = cast_ray(pixel, view_direction)
            current_cell = find_cell_containing(ray.origin)
            
            # Traverse ray through cells
            while ray_has_intersection(current_cell):
                # Find intersection with current cell faces
                intersection, hit_face = ray_intersect_cell(ray, current_cell)
                
                if hit_face is internal:
                    # Check if face data is in buffer
                    if hit_face.id not in computed_faces:
                        # Compute and store
                        face_data = compute_face_data(hit_face)
                        computed_faces[hit_face.id] = face_data
                    else:
                        # Reuse from buffer
                        face_data = computed_faces[hit_face.id]
                    
                    # Evaluate traversal parameters
                    d = face_data.traversed_distance
                    s0 = scalar_field[hit_face.entry_vertex]
                    s1 = scalar_field[hit_face.exit_vertex]
                    
                    # Compute contribution
                    color, opacity = compute_cell_contribution(d, s0, s1)
                    accumulate_pixel(pixel, color, opacity)
                
                # Handle degeneracies
                if ray_hits_vertex(intersection):
                    next_cell = find_next_cell_via_use_set(intersection.vertex, use_set, ray)
                elif ray_hits_edge(intersection):
                    next_cell = find_next_cell_via_use_set(intersection.edge, use_set, ray)
                else:
                    next_cell = get_neighbor_cell(current_cell, hit_face)
                
                current_cell = next_cell
                ray.origin = intersection.point

        # 7. Cleanup
        computed_faces.clear()

def is_visible(face_normal, view_direction):
    # Angle > 90 degrees means dot product is negative (assuming view dir points into scene)
    # Or positive if view dir points from scene. Source says "angle > 90".
    return dot(face_normal, view_direction) < 0 # Assumption based on standard convention

def build_use_set(vertices, cells):
    use_set = {v: [] for v in vertices}
    for cell in cells:
        for vertex in cell.vertices:
            use_set[vertex].append(cell)
    return use_set

def find_next_cell_via_use_set(vertex_or_edge, use_set, ray):
    # Scan cells in Use_set to find the one the ray enters next
    candidates = []
    if isinstance(vertex_or_edge, Vertex):
        candidates = use_set[vertex_or_edge]
    else: # Edge
        candidates = set(use_set[vertex_or_edge.v0]) & set(use_set[vertex_or_edge.v1])
    
    # Find cell that contains the ray direction from the hit point
    for cell in candidates:
        if ray_enters_cell(cell, ray):
            return cell
    return None # Should not happen if logic is correct
```

## Subtopics

### [VF-Ray-GPU](15664-vf-ray-gpu.md)
A GPGPU implementation of the VF-Ray algorithm using CUDA to parallelize ray casting on unstructured tetrahedral volumes, designed to reduce memory footprint by avoiding explicit adjacency structures like Use_set.

## Operating characteristics
**Time Complexity:** The algorithm exploits ray coherence, reducing redundant face parameter computations. However, the overhead of managing the `computedFaces` buffer and `Use_set` scans for degeneracies adds complexity. The source does not provide a formal Big-O notation.
**Memory Complexity:** The primary advantage is reduced memory footprint. It stores only the face data of the traversals of a set of nearby rays (the visible set) in `computedFaces`, rather than all face data for the entire volume [S1]. The `Use_set` structure is required for degeneracy handling [S1].
**Measured Performance:** The source does not provide specific performance metrics (FPS, memory usage in MB) for the CPU-based VF-Ray. It mentions that the face data structure is the "most consuming data structure in ray casting" [S1], implying that caching it improves performance.
**Strengths:** Memory efficiency; correct handling of degeneracies (vertices/edges); exploitation of ray coherence.
**Limitations:** Requires `Use_set` construction; buffer management overhead; potentially complex logic for degeneracy resolution.
**When to use:** Unstructured grid volume rendering where memory is a constraint and ray coherence is high.
**When not to use:** When hardware acceleration (GPU) is available and can handle the parallelism more efficiently (see VF-Ray-GPU).

## Background
VF-Ray was introduced in the paper "Memory Efficient GPU-Based Ray Casting for Unstructured Volume Rendering" [S1]. It builds on the concept of Exterior-Face Ray Casting [3615-exterior-face-ray-casting.md] but adds explicit memory management for internal faces to improve efficiency. The algorithm references Bunyk's approach [S1] as a predecessor that fails to handle degeneracies correctly. The concept of external faces is attributed to [BKS97] [S1].
