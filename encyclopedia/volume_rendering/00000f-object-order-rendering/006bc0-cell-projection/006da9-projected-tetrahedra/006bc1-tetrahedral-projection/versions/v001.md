# Tetrahedral Projection

Also called: Projected Tetrahedra Rendering Pipeline, Shirley-Tuchman Tetrahedral Projection

## Overview
Tetrahedral Projection is a view-dependent object-order volume rendering technique that projects unstructured tetrahedral meshes into the frame buffer as triangle fans, using barycentric interpolation to approximate ray-integrated optical properties. It differs from standard voxel-based splatting by computing the exact projected extent of each element and from exact ray-casting by avoiding per-pixel ray traversal, instead relying on hardware-accelerated triangle rasterization with Gouraud shading [S2, unofficial].

## How it works
**Inputs:** A tetrahedral mesh where each element $T$ has four vertices with associated scalar field values (e.g., density, emission coefficient $q_0$). A camera model (orthographic or perspective) defined by view and projection matrices.
**Outputs:** A 2D image with color and alpha values.

**Data Structures:**
*   **Tetrahedron:** Defined by 4 vertices $V_0, V_1, V_2, V_3$ in 3D space.
*   **Barycentric Matrix ($M_T$):** A $4 \times 4$ matrix constructed from the homogeneous coordinates of the tetrahedron's vertices. Its inverse $M_T^{-1}$ is precomputed and cached for each tetrahedron.
*   **Attributes:** Each vertex carries a scalar value (e.g., $q_0$) and potentially other attributes for shading.

**Steps:**
1.  **Preprocessing:** For each tetrahedron, compute the inverse of its barycentric matrix $M_T^{-1}$ [S1]. If the mesh undergoes morphing, these matrices must be recomputed using a $4 \times 4$ Gauss-Jordan elimination routine [S1].
2.  **View Vector Transformation:**
    *   Let $\mathbf{g}_2$ be the view direction vector in world space.
    *   Compute the barycentric difference vector $\mathbf{d}$ (for orthographic) or source vector $\mathbf{t}$ (for perspective) by transforming the view direction through the cached inverse matrix: $\mathbf{d} = M_T^{-1}\mathbf{g}_2$ [S1].
3.  **Vertex Identification:**
    *   Identify the **thick vertex** (the vertex corresponding to the maximum depth or integration path length in the projected view). This vertex corresponds to the "thickest point somewhere in the middle of the projected area" [S2, unofficial].
    *   Identify the **boundary vertices** (the remaining vertices of the tetrahedron).
    *   Compute attributes for these vertices. For the thick vertex, perform ray integration to yield optical values (e.g., color $C$ and opacity $\alpha$, or intermediate values $b_k, \theta_k$) [S2, unofficial]. For boundary vertices, set opacity to zero and assign color based on the local emission coefficient or source term $q_0$ (i.e., $C = q(s)$) [S2, unofficial].
4.  **Triangle Fan Construction:**
    *   Construct a triangle fan consisting of 3 or 4 facets [S1].
    *   The fan shares a common vertex: the **thick vertex** [S2, unofficial].
    *   The other vertices are the **boundary vertices** in order.
    *   To close the fan, repeat the first boundary vertex at the end of the sequence.
    *   Total vertices sent to the GPU: 5 (for 3 facets) or 6 (for 4 facets) [S1].
5.  **Rendering:**
    *   Transform the tetrahedron vertices to eye-space and clip-space using a GPU vertex program [S1].
    *   Render the triangle fan using standard hardware rasterization with **Gouraud alpha shading** [S2, unofficial].
    *   The shader interpolates the pre-computed color and opacity attributes across the triangle surface [S2, unofficial].

**Pseudocode:**
```python
def render_tetrahedral_projection(tetrahedra, camera, image_buffer):
    # Precompute inverses if not cached
    for tet in tetrahedra:
        if not tet.has_cached_inverse:
            tet.M_T_inv = invert_matrix(tet.build_barycentric_matrix())
            tet.has_cached_inverse = True

    # Process each tetrahedron
    for tet in tetrahedra:
        # 1. Get view direction in world space
        view_dir = camera.get_view_direction()
        
        # 2. Transform view direction to barycentric space
        # d is the barycentric difference vector
        d = multiply_matrix_vector(tet.M_T_inv, view_dir)
        
        # 3. Identify thick vertex and boundary vertices
        # The thick vertex is the one with the maximum depth in eye-space
        # or determined by the barycentric vector d.
        # For implementation simplicity, we assume the vertex with max Z in eye-space
        # is the thick vertex.
        vertices_eye = [transform_to_eye_space(v, camera) for v in tet.vertices]
        thick_idx = argmax([v.z for v in vertices_eye])
        thick_vertex = tet.vertices[thick_idx]
        boundary_indices = [i for i in range(4) if i != thick_idx]
        
        # 4. Compute attributes
        # Thick vertex: Ray integration
        # Note: Exact ray integration is expensive; Shirley-Tuchman approximates
        # this by using the value at the thick vertex.
        thick_color, thick_alpha = ray_integrate(tet, thick_vertex, camera)
        
        # Boundary vertices: Zero opacity, color from source term
        boundary_colors = []
        boundary_alphas = []
        for idx in boundary_indices:
            v = tet.vertices[idx]
            # q(s) is the emission coefficient or source term at vertex s
            boundary_colors.append(get_emission_coefficient(v))
            boundary_alphas.append(0.0)
            
        # 5. Construct triangle fan vertices
        # Order: Thick, Boundary[0], Boundary[1], ..., Boundary[n-1], Boundary[0]
        fan_vertices = [thick_vertex] + [tet.vertices[i] for i in boundary_indices] + [tet.vertices[boundary_indices[0]]]
        fan_colors = [thick_color] + boundary_colors + [boundary_colors[0]]
        fan_alphas = [thick_alpha] + boundary_alphas + [boundary_alphas[0]]
        
        # 6. Render
        # Transform to clip space and rasterize
        render_triangle_fan(fan_vertices, fan_colors, fan_alphas, camera, image_buffer)

def ray_integrate(tet, thick_vertex, camera):
    # Approximation: Use the value at the thick vertex
    # In the original Shirley-Tuchman method, this is the only point where
    # integration is performed.
    val = get_scalar_value(thick_vertex)
    return val, 1.0 # Simplified return for pseudocode completeness
```

**Parameters:**
*   **Gouraud Shading:** Enabled for interpolation of color and alpha across the triangle fan [S2, unofficial].
*   **Matrix Inversion:** Uses Gauss-Jordan elimination for $4 \times 4$ matrices [S1].

**Edge Cases:**
*   **Degenerate Tetrahedra:** If the tetrahedron has zero volume, $M_T$ is singular and cannot be inverted [S1].
*   **Morphing:** If the mesh deforms, $M_T^{-1}$ must be recomputed [S1].
*   **Approximation Error:** The method is a "crude approximation" because it assumes constant optical properties within the projected triangle, ignoring the variation along the ray path except at the thick vertex [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of tetrahedra, assuming constant-time projection and rasterization. The new algorithm is at least nine times faster than previous PT methods [S1].
*   **Memory Complexity:** $O(N)$ to store the tetrahedral mesh and cached $M_T^{-1}$ matrices [S1].
*   **Strengths:** Fast rendering via hardware acceleration; exact projected extent computation; view-dependent quality [S2, unofficial].
*   **Limitations:** Requires sorting of tetrahedra (implied by parent [Projected Tetrahedra](877-projected-tetrahedra.md)); approximation error due to Gouraud shading; not suitable for highly anisotropic or complex light transport [S2, unofficial].
*   **When to use:** Real-time visualization of unstructured volume data where performance is critical and moderate visual fidelity is acceptable [S2, unofficial].
*   **When not to use:** When high accuracy is required, or when the mesh is highly dynamic and matrix inversion becomes a bottleneck [S1].

## Background
The method was originally suggested by Shirley and Tuchman [S2, unofficial]. It was revisited and optimized by R. H. et al. (2006), who introduced a barycentric formulation to avoid projecting vertices to the image plane for perspective-correct line intersections, resulting in a significant speedup [S1]. It is used in unstructured volume visualization [S2, unofficial].
