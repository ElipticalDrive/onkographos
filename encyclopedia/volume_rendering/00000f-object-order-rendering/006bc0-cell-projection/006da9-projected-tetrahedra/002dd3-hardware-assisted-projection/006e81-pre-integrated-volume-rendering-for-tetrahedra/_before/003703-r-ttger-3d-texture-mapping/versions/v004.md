# Röttger 3D Texture Mapping

Also called: Hardware-Assisted Projected Tetrahedra with 3D Texture Mapping, Pre-integrated Volume Rendering for Tetrahedra, Röttger et al. 3D Texture Mapping

## Overview
Röttger 3D Texture Mapping is an extension of the projected tetrahedra algorithm that enables hardware-accelerated rendering of volumetric data using 3D texture mapping [S1, unofficial]. It solves the problem of accurately applying arbitrary transfer functions to volume integrals within projected cells by pre-integrating the result into a texture map [S2, unofficial][S3, book]. Unlike siblings that handle only linear transfer functions or require software interpolation, this method allows arbitrary transfer functions by leveraging hardware interpolation along the ray [S2, unofficial][S3, book].

## How it works
**Inputs:**
*   A tetrahedral mesh representing the volume.
*   Scalar field values (density/extinction coefficient $\tau$) at mesh vertices.
*   An arbitrary transfer function $f(\tau)$ mapping density to color and opacity.
*   Camera parameters for projection.

**Outputs:**
*   A 2D image with correct opacity and color accumulation.

**Data Structures:**
*   **Pre-integration Texture:** A 3D texture map $T(u, v, w)$ where:
    *   $u$: Value at cell entry point (normalized density or optical thickness).
    *   $v$: Value at cell exit point (normalized density or optical thickness).
    *   $w$: Distance through the cell (normalized segment length).
    *   *Note:* The sources state the 3D texture map is approximated using two-dimensional texture mapping [S1, unofficial][S2, unofficial][S3, book]. The exact layout of the 2D approximation is not specified in the provided notes.

**Steps:**
1.  **Pre-computation (Offline):**
    *   For all possible combinations of entry density $\tau_{in}$, exit density $\tau_{out}$, and segment length $l$, compute the pre-integrated color and opacity.
    *   The volume integral for opacity is $T = \exp(-\int \tau ds)$. For color, it involves integrating the emitted/transmitted light.
    *   Store these results in the 3D texture map $T(u, v, w)$ [S2, unofficial][S3, book].
    *   The sources note that parts of the volume integral depending on segment length are linearly approximated by modulating vertex colors [S1, unofficial]. The remaining parts, depending only on textural coordinates, are tabulated in the texture map [S1, unofficial].

2.  **Projection:**
    *   Project tetrahedron vertices onto the 2D image plane [S1, unofficial].
    *   Decompose the projection into rasterizable primitives (triangles) [S1, unofficial].

3.  **Attribute Computation:**
    *   For each triangle vertex, compute:
        *   Geometric thickness $l$ (length of the viewing ray segment within the cell).
        *   Scalar values $\tau_{in}$ and $\tau_{out}$ at entry and exit points.
    *   These values are passed as vertex attributes [S1, unofficial].

4.  **Hardware Interpolation:**
    *   The rasterizer interpolates $\tau_{in}$, $\tau_{out}$, and $l$ across the screen-space primitive [S1, unofficial].
    *   Use the interpolated values as texture coordinates $(u, v, w)$ to sample the pre-integration texture [S2, unofficial][S3, book].
    *   *Approximation:* The 3D texture map is approximated using 2D texture mapping [S1, unofficial][S2, unofficial][S3, book]. The specific mapping from 3D coordinates to 2D texture coordinates is not detailed in the sources.

5.  **Opacity/Color Evaluation:**
    *   Sample the texture to get the pre-computed color and opacity for the interpolated segment.
    *   Apply linear modulation of vertex colors for parts of the integral depending on segment length [S1, unofficial].

6.  **Compositing:**
    *   Composite fragments in back-to-front order using the Porter-Duff "over" operator [S1, unofficial].

**Parameters:**
*   Texture resolution: Not given in the sources.
*   Transfer function: Arbitrary [S2, unofficial][S3, book].

**Edge Cases and Pitfalls:**
*   **Approximation Error:** The approximation of the 3D texture map using 2D texture mapping may introduce artifacts if the mapping is not carefully designed. The sources do not specify the mapping function [S1, unofficial][S2, unofficial][S3, book].
*   **Precision:** Linear approximation of parts of the volume integral may reduce accuracy for non-linear transfer functions or large segment lengths [S1, unofficial].
*   **Sorting:** Requires a sorted list of cells for correct compositing [S2, unofficial][S3, book].

## Operating characteristics
*   **Time Complexity:** Dominated by rasterization and texture sampling. Pre-computation is offline.
*   **Memory Complexity:** Requires storage for the pre-integration texture. Size depends on the resolution of the 3D texture map. Not given in the sources.
*   **Performance:** Hardware-accelerated. Specific frame rates are not provided for this method in the sources.
*   **Strengths:** Supports arbitrary transfer functions; hardware-accelerated; avoids artifacts from linear interpolation of non-linear opacity.
*   **Limitations:** Requires pre-computation; approximation of 3D texture with 2D texture may introduce errors; requires sorted cells.
*   **When to use:** When arbitrary transfer functions are needed and hardware acceleration is desired.
*   **When not to use:** When memory is limited or pre-computation time is prohibitive.

## Background
*   **Origin:** Introduced by Röttger et al. [RKE00] [S1, unofficial].
*   **History:** It is an extension of the projected tetrahedra algorithm [ST90] [S1, unofficial]. It builds on the concept of pre-integrated volume rendering [S2, unofficial][S3, book].
*   **Usage:** Used for interactive volume rendering of volumetric data [S1, unofficial].
