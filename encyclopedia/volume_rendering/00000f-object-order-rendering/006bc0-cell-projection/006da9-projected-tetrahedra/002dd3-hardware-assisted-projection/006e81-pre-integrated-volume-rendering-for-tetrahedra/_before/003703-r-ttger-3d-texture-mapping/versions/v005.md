# Röttger 3D Texture Mapping

Also called: Hardware-Assisted Projected Tetrahedra with 3D Texture Mapping, Pre-integrated Volume Rendering for Tetrahedra, Röttger et al. 3D Texture Mapping

## Overview
Röttger 3D Texture Mapping is a hardware-accelerated extension of the projected tetrahedra algorithm that enables the rendering of volumetric data with arbitrary transfer functions [S1, unofficial][S2, unofficial][S3, book]. It solves the problem of non-linear opacity artifacts (such as Mach bands) that arise when linearly interpolating transparency across screen-space primitives by pre-integrating the volume rendering integral into a texture map [S2, unofficial][S3, book]. Unlike siblings that rely on linear approximations or unsorted hexahedra, this method uses a 3D texture lookup to accurately compute per-pixel opacity based on entry/exit scalar values and segment length, approximated via 2D hardware texture mapping [S1, unofficial][S2, unofficial][S3, book].

## How it works
**Inputs and Outputs:**
*   **Input:** A tetrahedral mesh representing volumetric data; a scalar field defined at vertices; a user-defined transfer function $f(\tau)$ mapping scalar values $\tau$ to color and opacity.
*   **Output:** A 2D image with correct alpha compositing.

**Data Structures:**
1.  **Pre-integration Texture:** A texture map storing pre-computed color and opacity values.
    *   **Layout:** The sources describe a 3D texture map with three coordinates:
        *   $u$: Scalar value at the cell entry point ($\tau_{in}$).
        *   $v$: Scalar value at the cell exit point ($\tau_{out}$).
        *   $w$: Distance through the cell (segment length $l$) [S2, unofficial][S3, book].
    *   **Approximation:** The 3D texture map is approximated using two-dimensional texture mapping hardware [S2, unofficial][S3, book]. The exact mapping of the third dimension ($w$) into the 2D texture coordinates is not specified in the sources [S1, unofficial].
2.  **Vertex Attributes:** For each projected triangle (tetrahedron face), the following are computed and passed to the rasterizer:
    *   Entry and exit scalar values ($\tau_{in}, \tau_{out}$) at the vertices.
    *   Segment length ($l$) or traversal distance.
    *   Vertex colors modulated by linear parts of the volume integral [S1, unofficial].

**Steps:**
1.  **Sorting:** Sort tetrahedra in back-to-front order relative to the viewpoint [S1, unofficial].
2.  **Projection:** Project 3D tetrahedron vertices to 2D screen space [S1, unofficial].
3.  **Attribute Computation:** Compute $\tau_{in}$, $\tau_{out}$, and segment length $l$ for each triangle. Linearly approximate parts of the volume integral depending on segment length by modulating vertex colors [S1, unofficial].
4.  **Rasterization:** Rasterize the triangles. The hardware interpolates $\tau_{in}$, $\tau_{out}$, and $l$ across the screen-space primitive [S1, unofficial][S2, unofficial].
5.  **Texture Lookup:** For each fragment, sample the pre-integration texture using the interpolated $\tau_{in}$, $\tau_{out}$, and $l$ as texture coordinates [S2, unofficial][S3, book].
6.  **Compositing:** Composite the resulting color and opacity using hardware blending operations [S1, unofficial].

**Formulas:**
The pre-integration texture stores the result of the volume rendering integral:
$$ C = \int_{0}^{l} f(\tau(s)) e^{-\int_{0}^{s} \tau(t) dt} ds $$
$$ T = e^{-\int_{0}^{l} \tau(s) ds} $$
Where $f(\tau)$ is the transfer function, $\tau(s)$ is the scalar value along the ray, and $l$ is the segment length [S2, unofficial][S3, book]. The exact mathematical formulation of the pre-integration is not fully detailed in the provided sources, but it is implied to be the standard pre-integrated volume rendering integral [S2, unofficial][S3, book].

**Parameters:**
*   Texture resolution: Not given in the sources.
*   Transfer function: Arbitrary, defined by the user [S2, unofficial][S3, book].

**Edge Cases and Pitfalls:**
*   **Precision:** Linear interpolation of transparency causes artifacts; this method avoids them by using the texture lookup [S2, unofficial][S3, book].
*   **Approximation Error:** The approximation of the 3D texture map using 2D texture mapping may introduce errors if the mapping is not carefully designed [S2, unofficial][S3, book]. The specific approximation technique is not detailed [S1, unofficial].

## Subtopics

### Pre-integrated Volume Rendering
The core concept introduced by Röttger et al. that allows arbitrary transfer functions by pre-computing the volume integral in a texture map [S2, unofficial][S3, book].

### Hardware-Assisted Projection
The parent method that provides the sorting, projection, and rasterization framework [5625-hardware-assisted-projection.md].

## Operating characteristics
*   **Time Complexity:** Dominated by sorting and rasterization. Texture lookup is constant time per fragment [S1, unofficial].
*   **Memory Complexity:** Requires storage for the pre-integration texture. The size depends on the resolution of the texture map [S2, unofficial][S3, book].
*   **Performance:** Not given in the sources.
*   **Strengths:** Supports arbitrary transfer functions; avoids Mach bands; hardware-accelerated [S2, unofficial][S3, book].
*   **Limitations:** Requires pre-computation of the texture map; approximation of 3D texture with 2D may introduce errors [S2, unofficial][S3, book].

## Background
Röttger et al. introduced the concept of pre-integrated volume rendering to allow for arbitrary transfer functions in hardware-accelerated volume rendering [S2, unofficial][S3, book]. The method extends the projected tetrahedra algorithm [ST90] by using 3D texture mapping to interpolate along the ray between cell entry and exit points [S1, unofficial][S2, unofficial][S3, book].
