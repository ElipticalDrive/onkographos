# Interpolating Fragment Attributes for Perspective Projection

Also called: Back-Side Coordinate Interpolation, Perspective-Correct Interpolation for Projected Tetrahedra (Front/Back Decomposition Variant)

## Overview
This method corrects the interpolation of barycentric coordinates and intersection lengths for facets generated by the Projected Tetrahedra (PT) algorithm under perspective projection. Standard graphics hardware performs linear interpolation of vertex attributes in screen space, which introduces artifacts when attributes vary non-linearly in 3D space relative to the viewer. This technique leverages the linear interpolation of modified vertex attributes on the front side of a facet to recover correct perspective-correct values for the back side, avoiding discontinuities at facet boundaries. It sets itself apart from its predecessor [S1] by using continuous attribute values, allowing the tetrahedron to be rendered as a triangle fan rather than independent triangles, thereby improving vertex-cache coherence.

## How it works
**Inputs and Outputs:**
*   **Input:** Vertices of a facet (generated by projecting a tetrahedron), including eyespace positions and precomputed barycentric coordinates for the front and back sides.
*   **Output:** Correctly interpolated barycentric coordinates ($\mathbf{u}_f, \mathbf{u}_b$) and intersection length for each fragment, enabling accurate density integration.

**Data Structures and Vertex Attributes:**
Each vertex of the facet carries the following attributes:
1.  **Eyespace Position ($\mathbf{p}_0$):** The 3D position of the vertex on the front side in eyespace coordinates. This is required for perspective projection [S1].
2.  **Front-Side Barycentric Coordinates ($\mathbf{u}_f$):** The barycentric coordinates of the vertex on the front side of the facet [S1].
3.  **Modified Back-Side Barycentric Coordinates ($\mathbf{u}'_b$):** A transformed version of the back-side barycentric coordinates, defined as $\mathbf{u}'_b = \alpha^{-1} \mathbf{u}_b$, where $\alpha$ is the scaling factor between the front and back vertices [S1].
4.  **Tetrahedron Index:** Used to retrieve density coefficients (not part of the interpolation geometry but required for the final integral) [S1].
5.  **Front-to-Back Intersection Length:** Used only in orthographic projection; in perspective, this is computed dynamically [S1].

**Parameters:**
*   $\alpha$: The ratio of the distance from the camera to the back vertex relative to the front vertex. At the boundary where front and back sides merge, $\alpha = 1$ [S1].

**Algorithm Steps:**

1.  **Preprocessing (CPU/Geometry Shader):**
    For each vertex of the facet, identify the corresponding "thick" vertex on the front side ($\mathbf{f}$) and its counterpart on the back side ($\mathbf{b}$). The relationship is defined by $\mathbf{b} = \alpha \mathbf{f}$, where $\alpha$ is known from the projection geometry [S1].
    
    Compute the modified back-side barycentric coordinates:
    $$ \mathbf{u}'_b = \alpha^{-1} \mathbf{u}_b $$
    
    Assign $\mathbf{u}'_b$ as a vertex attribute for the front-side vertex $\mathbf{f}$. Note that the magnitude $|\mathbf{u}'_b| = \alpha^{-1}$ [S1].
    
    *Boundary Condition:* At the boundary of the facet, the front and back sides merge, meaning $\alpha = 1$. Consequently, $\mathbf{u}'_b = \mathbf{u}_b$. Equal values are assigned to both front-side and back-side coordinate attributes of the boundary vertices (typically one component is 1 and the others are 0) [S1].

2.  **Rasterization (Hardware):**
    The graphics hardware interpolates the vertex attributes ($\mathbf{p}_0, \mathbf{u}_f, \mathbf{u}'_b$) linearly across the screen-space triangle (the front side of the facet) [S1].

3.  **Fragment Program (GPU):**
    For each fragment, perform the following calculations:
    
    a. **Recover $\alpha$:**
       Compute the scaling factor from the interpolated modified back-side coordinates:
       $$ \alpha = |\mathbf{u}'_b|^{-1} $$
       
    b. **Recover Back-Side Barycentric Coordinates:**
       Compute the correct perspective-correct back-side barycentric coordinates:
       $$ \mathbf{u}_b = \alpha \mathbf{u}'_b $$
       
    c. **Recover Back-Side Position:**
       Let $\mathbf{p}_0$ be the interpolated eyespace position of the front side. Compute the corresponding point on the back side projected onto $\mathbf{p}_0$:
       $$ \mathbf{p}_1 = \alpha \mathbf{p}_0 $$
       
    d. **Compute Intersection Length:**
       The length of the ray segment inside the tetrahedron (or facet) is the Euclidean distance between the front and back points:
       $$ L = \|\mathbf{p}_1 - \mathbf{p}_0\| $$

```python
# Vertex Shader / Preprocessing
def preprocess_vertex(front_pos, back_pos, front_bary, back_bary):
    """
    Computes attributes for the front-side vertex to enable perspective-correct interpolation.
    front_pos: vec3, eyespace position of the front vertex
    back_pos: vec3, eyespace position of the back vertex
    front_bary: vec4, barycentric coords of the front vertex
    back_bary: vec4, barycentric coords of the back vertex
    """
    # Calculate alpha: ratio of distances from camera (assuming camera at origin in eyespace)
    # Note: In eyespace, if camera is at origin, distance is length of position vector.
    # However, the relation b = alpha * f implies alpha is derived from depth or projection.
    # From source: b = alpha * f. Thus alpha = |b| / |f| if collinear with camera, 
    # or more generally derived from the projection matrix inverse.
    # The source states "we know alpha", so we assume it is precomputed.
    alpha = compute_alpha(front_pos, back_pos) 
    
    # Compute modified back-side barycentric coordinates
    # u'_b = alpha^-1 * u_b
    u_prime_b = back_bary / alpha
    
    # Return attributes for the FRONT vertex
    return {
        'p0': front_pos,      # Eyespace position of front side
        'u_f': front_bary,    # Front barycentric coords
        'u_prime_b': u_prime_b # Modified back barycentric coords
    }

def compute_alpha(front_pos, back_pos):
    """
    Computes the scaling factor alpha such that back_pos = alpha * front_pos.
    This assumes the vertices are collinear with the camera center in eyespace.
    """
    # Using the z-component (depth) is standard for perspective division, 
    # but the source defines b = alpha * f.
    # If f and b are 3D vectors, alpha is a scalar.
    # We take the ratio of their lengths or a specific component.
    # Source implies alpha is known from projection geometry (Eq 2 and 8).
    # A robust implementation uses the ratio of depths (z) in eyespace.
    if front_pos.z == 0:
        return 1.0 # Guard against division by zero
    return back_pos.z / front_pos.z

# Fragment Shader
def fragment_shader(p0, u_f, u_prime_b):
    """
    Recovers correct perspective-correct attributes for the fragment.
    p0: interpolated eyespace position of front side
    u_f: interpolated front barycentric coords
    u_prime_b: interpolated modified back barycentric coords
    """
    # 1. Recover alpha from the magnitude of u_prime_b
    # Source: alpha = |u'_b|^-1
    # Note: u_prime_b is a vector. Its magnitude is alpha^-1.
    alpha = 1.0 / length(u_prime_b)
    
    # 2. Recover back-side barycentric coordinates
    u_b = alpha * u_prime_b
    
    # 3. Recover back-side position
    p1 = alpha * p0
    
    # 4. Compute intersection length
    intersection_length = length(p1 - p0)
    
    return {
        'u_f': u_f,
        'u_b': u_b,
        'intersection_length': intersection_length
    }
```

**Edge Cases and Pitfalls:**
*   **Orthographic Projection:** In orthographic projection, barycentric coordinates on the front and back sides and the thickness are interpolated linearly in screen space. The perspective correction algorithm is not required; attributes can be passed directly as computed [S1].
*   **Boundary Continuity:** At the boundary where the front and back sides merge ($\alpha = 1$), the front and back attributes must be equal to ensure continuity. Failure to set $\mathbf{u}'_b = \mathbf{u}_f$ at boundaries will cause visible artifacts [S1].
*   **Precision:** Computing $\alpha$ via division by $|\mathbf{u}'_b|$ can be sensitive to precision errors if $\mathbf{u}'_b$ is very small. However, $\mathbf{u}'_b$ represents $\alpha^{-1}$, so small values correspond to large depths. Standard floating-point precision is generally sufficient for typical volume rendering resolutions [S1].

## Operating characteristics
*   **Time Complexity:** The additional computation per fragment is constant time: one vector magnitude, one division, one vector multiplication, and one distance calculation. This is negligible compared to the density integration step.
*   **Memory Complexity:** Requires storing one additional vector attribute ($\mathbf{u}'_b$) per vertex. This increases vertex buffer size slightly but allows for triangle fan rendering, which reduces the total number of vertices sent to the GPU compared to the independent triangle approach [S1].
*   **Performance:** Improves vertex-cache coherence by enabling triangle fan rendering. Reduces the amount of data sent to the GPU compared to rendering facets as independent triangles [S1].
*   **Strengths:** Correctly handles perspective distortion for barycentric coordinates and intersection lengths. Continuous attributes across facets.
*   **Limitations:** Requires a fragment program to recover the back-side attributes. Not applicable (or unnecessary) for orthographic projections.

## Background
This method was introduced in the paper "Projected Tetrahedra Revisited: A Barycentric Formulation Applied to Volume Rendering" [S1]. It improves upon the predecessor method [1] which used the normal of the back side of the facet to compute the intersection length. Since the normal is not a continuous attribute, the predecessor required rendering facets as independent triangles. The current method uses continuous attribute values, enabling the tetrahedron to be rendered as a triangle fan. This development is part of the broader Projected Tetrahedra (PT) algorithm family for volume rendering, which maps 3D volumetric data to 2D screen space by projecting tetrahedra.
