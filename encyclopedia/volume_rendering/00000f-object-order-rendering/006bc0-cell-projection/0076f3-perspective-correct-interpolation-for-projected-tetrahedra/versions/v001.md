# Perspective-Correct Interpolation for Projected Tetrahedra

Also called: Correct perspective interpolation for PT, Corrected PT interpolation, Front/Back vertex decomposition, Perspective interpolation for PT

## Overview
This method corrects the rendering artifacts caused by standard hardware linear interpolation in screen space when rendering Projected Tetrahedra (PT) [S1]. While the parent [Cell projection](26-cell-projection.md) decomposes the projected tetrahedron into triangles in normalized device coordinates (NDC), this approach decomposes the tetrahedron in object space into smaller sub-tetrahedra, duplicating vertices into "front" and "back" pairs to enable manual perspective correction in the fragment shader [S1]. It is chosen when high-fidelity volume rendering requires accurate interpolation of scalar data, colors, and attenuation coefficients across perspective-projected volumes, avoiding the depth-dependent distortions inherent in standard rasterization [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   A tetrahedron defined by four object-space vertices $\mathbf{v}_o^{(1)}, \mathbf{v}_o^{(2)}, \mathbf{v}_o^{(3)}, \mathbf{v}_o^{(4)}$.
*   Scalar data values $s_i$ associated with each vertex.
*   Model-View Matrix $M$ and Projection Matrix $P$.
*   Constraint: The fourth row of $M$ must be $(0, 0, 0, 1)^T$ to ensure eye-space coordinates are linear functions of object coordinates [S1].
*   Assumption: Object-space homogeneous coordinates $w_o = 1$ for all vertices [S1].

**Outputs:**
*   Correctly interpolated scalar values $s^{(f)}$ (front) and $s^{(b)}$ (back) for each fragment.
*   Eye-space positions $\mathbf{v}_e^{(f)}$ and $\mathbf{v}_e^{(b)}$ for depth/thickness calculation.
*   Fragment thickness $l$ for opacity integration.

### Data Structures
The method requires decomposing the original tetrahedron into three or four smaller tetrahedra in object space [S1]. For each sub-tetrahedron, six vertices are defined:
*   Front vertices: $\mathbf{v}_o^{(1f)}, \mathbf{v}_o^{(2f)}, \mathbf{v}_o^{(3f)}$
*   Back vertices: $\mathbf{v}_o^{(1b)}, \mathbf{v}_o^{(2b)}, \mathbf{v}_o^{(3b)}$

For a given sub-tetrahedron, one pair of vertices (e.g., index 1) is projected to the same 2D screen point. The other two vertices are duplicated to create front/back pairs [S1]. Specifically:
*   $\mathbf{v}_o^{(1f)}$ and $\mathbf{v}_o^{(1b)}$ are distinct object-space points that project to the same screen coordinate.
*   $\mathbf{v}_o^{(2f)}$ and $\mathbf{v}_o^{(2b)}$ are identical copies of the same object-space vertex.
*   $\mathbf{v}_o^{(3f)}$ and $\mathbf{v}_o^{(3b)}$ are identical copies of the same object-space vertex [S1].

Each vertex $i$ carries:
*   Object-space position $\mathbf{v}_o^{(if)}$ (for the rasterized front triangle).
*   Object-space position $\mathbf{v}_o^{(ib)}$ (the corresponding back vertex).
*   Scalar value for front $s^{(if)}$.
*   Scalar value for back $s^{(ib)}$ [S1].

### Numbered Steps

1.  **Decomposition:** Decompose the original tetrahedron into three or four smaller tetrahedra in object coordinates [S1]. For each sub-tetrahedron, identify the front/back vertex pairs as described in Data Structures.

2.  **Vertex Program (Pre-rasterization):** For each vertex $i$ of the front-facing triangle ($\mathbf{v}_o^{(if)}$):
    a. Compute clip coordinates: $\mathbf{v}_c^{(if)} = P M \mathbf{v}_o^{(if)}$.
    b. Extract clip-space $w$: $w_c^{(if)} = \mathbf{v}_c^{(if)}.w$.
    c. Compute eye-space position: $\mathbf{v}_e^{(if)} = M \mathbf{v}_o^{(if)}$ (first 3 components).
    d. Compute eye-space $z$: $z_e^{(if)} = \mathbf{v}_e^{(if)}.z$.
    e. Compute clip coordinates for the back vertex: $\mathbf{v}_c^{(ib)} = P M \mathbf{v}_o^{(ib)}$.
    f. Extract back clip-space $w$: $w_c^{(ib)} = \mathbf{v}_c^{(ib)}.w$.
    g. Compute eye-space position for back: $\mathbf{v}_e^{(ib)} = M \mathbf{v}_o^{(ib)}$.
    h. Compute eye-space $z$ for back: $z_e^{(ib)} = \mathbf{v}_e^{(ib)}.z$.
    i. Output the following attributes for linear interpolation in NDC:
       - Position: $\mathbf{v}_d^{(if)} = \mathbf{v}_c^{(if)} / w_c^{(if)}$ (Normalized Device Coordinates). Setting $w_c=1$ in the pipeline forces linear interpolation [S1].
       - Weight inverse: $1/w_c^{(if)}$.
       - Weighted scalar: $s^{(if)}/w_c^{(if)}$.
       - Weighted eye position: $\mathbf{v}_e^{(if)}/w_c^{(if)}$.
       - Back weight inverse: $1/w_c^{(ib)}$.
       - Back weighted scalar: $s^{(ib)}/w_c^{(ib)}$.
       - Back weighted eye z: $z_e^{(ib)}/w_c^{(ib)}$ [S1].

3.  **Rasterization:** Rasterize the front-facing triangle spanned by $\mathbf{v}_o^{(1f)}, \mathbf{v}_o^{(2f)}, \mathbf{v}_o^{(3f)}$. The back-facing triangle covers the same pixels but is not rasterized [S1].

4.  **Fragment Program (Interpolation and Correction):** For each fragment, linearly interpolate the vertex attributes across the triangle. Let the interpolated values be denoted with superscript $(f)$ for front and $(b)$ for back quantities derived from the back vertex attributes:
    *   $1/w_c^{(f)}$
    *   $s^{(f)}/w_c^{(f)}$
    *   $\mathbf{v}_e^{(f)}/w_c^{(f)}$
    *   $1/w_c^{(b)}$
    *   $s^{(b)}/w_c^{(b)}$
    *   $z_e^{(b)}/w_c^{(b)}$

5.  **Perspective Correction:** Reconstruct the perspective-correct values by dividing the interpolated weighted values by the interpolated weight [S1]:
    $$ s^{(f)} = \frac{s^{(f)}/w_c^{(f)}}{1/w_c^{(f)}} $$
    $$ \mathbf{v}_e^{(f)} = \frac{\mathbf{v}_e^{(f)}/w_c^{(f)}}{1/w_c^{(f)}} $$
    $$ s^{(b)} = \frac{s^{(b)}/w_c^{(b)}}{1/w_c^{(b)}} $$
    $$ z_e^{(b)} = \frac{z_e^{(b)}/w_c^{(b)}}{1/w_c^{(b)}} $$

6.  **Thickness Calculation:** Compute the thickness $l$ of the tetrahedron along the viewing ray for the fragment. Using the corrected eye-space positions:
    $$ l = \left| \mathbf{v}_e^{(b)} - \mathbf{v}_e^{(f)} \right| $$
    Since the points are collinear with the origin and $w_e=1$, this simplifies to [S1]:
    $$ l = \left| \mathbf{v}_e^{(f)} \right| \left| \frac{z_e^{(b)} - z_e^{(f)}}{z_e^{(f)}} \right| $$
    An approximation often used to avoid division is $l \approx |z_e^{(b)} - z_e^{(f)}|$ [S1].

7.  **Compositing:** Use the corrected scalar values $s^{(f)}$ and $s^{(b)}$ and thickness $l$ to compute opacity and color according to the parent [Cell projection](26-cell-projection.md) principles, specifically using the exponential opacity model $\alpha = 1 - \exp(-\tau_{avg} l)$ [S1].

### Pseudocode

```python
def perspective_correct_pt_interpolation(vertex_data):
    """
    vertex_data: List of 3 vertices for the front triangle.
    Each vertex has:
      - v_o_f: Object space position (vec3)
      - v_o_b: Object space position of corresponding back vertex (vec3)
      - s_f: Scalar value at front vertex (float)
      - s_b: Scalar value at back vertex (float)
    Returns:
      - s_f_corrected: Corrected front scalar
      - s_b_corrected: Corrected back scalar
      - l: Thickness
    """
    
    # Pre-compute per-vertex attributes for the vertex shader output
    # Note: In a real implementation, this happens per vertex before rasterization.
    # Here we simulate the fragment shader input after linear interpolation.
    
    # Assume interpolated values from rasterizer (linear in NDC)
    # These are sums of (attribute / w_c) for the 3 vertices, divided by sum(1/w_c)
    # However, the source describes passing 1/w_c, s/w_c, etc., and dividing in fragment shader.
    # So we assume the fragment shader receives the interpolated weighted values.
    
    # Let's define the interpolated values received by fragment shader:
    # inv_w_c_f, s_f_w_c_f, v_e_f_w_c_f, inv_w_c_b, s_b_w_c_b, z_e_b_w_c_b
    
    # Reconstruct perspective-correct values
    s_f_corrected = s_f_w_c_f / inv_w_c_f
    v_e_f_corrected = v_e_f_w_c_f / inv_w_c_f
    
    s_b_corrected = s_b_w_c_b / inv_w_c_b
    z_e_b_corrected = z_e_b_w_c_b / inv_w_c_b
    
    # We also need z_e_f_corrected for thickness calculation if using the simplified formula
    # z_e_f_corrected = z_e_f_w_c_f / inv_w_c_f
    
    # Calculate thickness
    # Using the exact distance formula in eye space
    # l = | v_e_b - v_e_f |
    # But we only have z_e_b and v_e_f. 
    # The source gives: l = | v_e_b - v_e_f | = | v_e_f | * | (z_e_b - z_e_f) / z_e_f |
    
    # We need v_e_b. The source passes z_e_b/w_c_b and s_b/w_c_b. 
    # It does NOT explicitly pass x_e_b/w_c_b or y_e_b/w_c_b in the list of 6 outputs.
    # However, it says "v_e^(b)/w_e^(b) ... can be interpolated ... as described above".
    # And "v_e^(f)/w_c^(f)" is passed.
    # To compute l = |v_e_b - v_e_f|, we need full v_e_b.
    # The source text says: "Apart from these coordinates, each triangle vertex is also provided with 
    # the object coordinates of the corresponding “back” vertex...".
    # And in the vertex program output list: "1/w_c^(ib), s^(ib)/w_c^(ib), and z_e^(ib)/w_c^(ib)".
    # It omits x_e and y_e for the back vertex in the explicit list of 6.
    # However, it says "v_e^(b)/w_e^(b) ... can be interpolated".
    # To be safe and complete, we assume x_e_b and y_e_b are also passed and interpolated similarly.
    
    # Let's assume we also interpolated x_e_b/w_c_b and y_e_b/w_c_b.
    x_e_b_corrected = x_e_b_w_c_b / inv_w_c_b
    y_e_b_corrected = y_e_b_w_c_b / inv_w_c_b
    
    v_e_b_corrected = vec3(x_e_b_corrected, y_e_b_corrected, z_e_b_corrected)
    
    l = length(v_e_b_corrected - v_e_f_corrected)
    
    return s_f_corrected, s_b_corrected, l
```

### Parameters and Edge Cases
*   **Model-View Matrix:** The fourth row must be $(0, 0, 0, 1)^T$. If this is violated, $\mathbf{v}_e/w_e$ is not linear in object coordinates, and the interpolation method fails [S1].
*   **$w_o$:** Assumed to be 1. If not, the term $w_o/w_c$ must be interpolated instead of $1/w_c$ [S1].
*   **Precision:** The method relies on dividing by $1/w_c$. If $w_c$ is very small (near clipping plane), precision issues may arise. Floating-point color buffers and high-resolution textures are recommended to minimize quantization artifacts during compositing [S1].
*   **Degenerate Input:** If the tetrahedron projects to a degenerate triangle (area 0), no fragments are generated, and no artifacts occur. If the decomposition results in zero-volume sub-tetrahedra, they should be skipped [S1].

## Operating characteristics
*   **Time Complexity:** The decomposition adds a constant factor overhead (3-4 sub-tetrahedra per cell). The vertex program performs additional matrix multiplications and divisions per vertex. The fragment program performs a few divisions per fragment. Overall, it is more expensive than standard PT but cheaper than full ray marching.
*   **Memory Complexity:** Requires storing additional vertex attributes (back vertex positions, front/back scalars) in the vertex buffer.
*   **Strengths:** Eliminates perspective interpolation artifacts for scalar data, colors, and attenuation. Enables accurate pre-integrated classification and compositing on GPU hardware [S1].
*   **Limitations:** Requires programmable graphics hardware (vertex/fragment shaders). More complex to implement than standard PT. Sensitive to model-view matrix constraints [S1].
*   **When to use:** High-quality volume rendering where perspective correctness is critical, especially for non-linear scalar fields or when using pre-integrated transfer functions [S1].
*   **When not to use:** Real-time applications with strict performance constraints where artifacts are acceptable, or when using orthographic projection (where perspective correction is unnecessary) [S1].

## Background
The method was introduced by Kraus and Ertl in 2004 in "Projecting Tetrahedra without Rendering Artifacts" [S1]. It addresses the fundamental limitation of the original Projected Tetrahedra algorithm, which decomposes the projection in NDC space, making correct perspective interpolation impossible with standard hardware rasterization [S1]. The technique builds on the mathematical insight by Heckbert and Moreton, and Blinn, that $f(\mathbf{v}_o)w_o/w_c$ is linear in NDC if $f$ is linear in object-space homogeneous coordinates [S1].
