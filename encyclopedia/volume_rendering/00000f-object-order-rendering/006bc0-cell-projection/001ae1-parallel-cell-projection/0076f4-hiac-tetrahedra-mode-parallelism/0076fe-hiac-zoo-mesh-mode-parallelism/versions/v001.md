# HIAC Zoo-Mesh Mode Parallelism

Also called: zoo mode, zoo-mesh mode

## Overview
HIAC Zoo-Mesh Mode Parallelism is a parallel volume rendering method for meshes composed of arbitrary polyhedra ("zoo elements") that uses work quanta for load balancing between sort, projection, and render threads [S1]. It differs from its parent, [HIAC Tetrahedra Mode Parallelism](23614-hiac-tetrahedra-mode-parallelism.md), by supporting general cell geometry rather than requiring tetrahedral decomposition, thereby reducing the total triangle count at the cost of increased per-cell projection complexity [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A mesh of arbitrary polyhedra (zoo elements), camera parameters, and a pool of `workQuantum` structures.
*   **Output:** OpenGL rendering commands and frame buffer updates.

**Data Structures:**
The core synchronization and data unit is the `workQuantum` structure [S1]:

```c
typedef struct {
    char doProjectFlag;
    long startCell, endCell, pcbIndex;
    long ttStart, ttEnd, pcbIndex;
    char doneProjectingFlag,
        inUseFlag, isLastFlag;
    long vvIndex, vvMax,
        polyIndex, polyArraySize;
    GLfloat *mTexArray, *mVertexArray,
        *mColorArray;
    int *polyVertexCounts;
} workQuantum;
```

**Steps:**
1.  **Initialization:** The system initializes a global pool of `workQuantum` structures and two global arrays to track work for projection and rendering threads [S1].
2.  **Sorting and Distribution:** The sort thread sorts cells by visibility. When it has sorted "enough" cells, it obtains a `workQuantum` from the global pool [S1].
3.  **Quantum Setup:** The sort thread fills the `startCell` and `endCell` fields of the `workQuantum` to define the range of cells to be processed [S1].
4.  **Thread Awakening:** The sort thread awakens a single projection thread to process the assigned quantum [S1].
5.  **Projection:** The projection thread performs projection calculations on all cells referenced by the `startCell` to `endCell` range [S1]. It stores the resulting geometric information (vertices, colors, textures) into the arrays within the `workQuantum` (e.g., `mVertexArray`, `mColorArray`) [S1].
6.  **Completion Signal:** Upon completing the projection for the quantum, the projection thread sets `doneProjectingFlag` and goes to sleep, waiting for another `workQuantum` [S1].
7.  **Rendering:** The render thread continually polls the `doneProjectingFlag` of the next `workQuantum` in its work pile [S1]. When the flag is set, the render thread makes the appropriate OpenGL calls to display the image [S1].
8.  **Double Buffering:** The system uses two `projection_render` arrays (or equivalent structures) to allow the projection threads to fill one array while the render thread consumes the other [S1].

**Parameters:**
*   **Work Quantum Size:** A tuning parameter defining the number of cells per quantum. It should be neither very small (causing mutex contention) nor very large (causing projection threads to wait for the sort thread) [S1].

**Pitfalls:**
*   **Non-planar Faces:** Non-planar faces in zoo elements can cause visibility cycles, forcing subdivision even if the general projection method is used. This reduces the triangle count advantage [S1].
*   **Pipeline Saturation:** Neither projection method was able to saturate the graphics hardware pipeline in the tested environment, meaning performance gains from reduced triangle counts may not linearly translate to frame rate improvements [S1].

## Operating characteristics
*   **Complexity:** The method introduces overhead due to the general cell projection algorithm, which is slower per cell than the tetrahedra mode [S1].
*   **Performance:** On SGI hardware, speedup is near-linear up to 10 threads. Beyond 10 threads, returns diminish, and a small slowdown occurs at 18 threads due to NUMA communication costs [S1].
*   **Triangle Count:** Zoo mode generates approximately 2/3 as many triangles as tetrahedra mode (e.g., 12 vs 22 for a hexahedron) [S1].
*   **Processor Requirements:** Zoo mode requires more processors to achieve optimal performance compared to tetrahedra mode due to the higher computational cost of general cell projection [S1].
*   **Strengths:** Reduced triangle count and OpenGL fragment overhead for complex geometries [S1].
*   **Limitations:** Slower per-cell projection; sensitivity to non-planar faces; diminishing parallel scaling on NUMA architectures [S1].

## Background
HIAC (High Accuracy Hardware-Assisted Volume Renderer) was developed to create accurate volume images by performing separate exact analytic or numerical integration for each primary color per pixel [S1]. The zoo-mesh mode was introduced to handle arbitrary polyhedra, such as curvilinear grids wrapped around cylinders, which create non-planar faces [S1]. Tests were conducted on a dataset of 308,190 cells [S1].
