# Pre-integrated classification for cell projection

Also called: Pre-integrated classification

## Overview
Pre-integrated classification for cell projection is a method to determine the color and opacity contribution of a projected tetrahedron by applying pre-integrated classification [S1]. It solves the problem of accurately computing volume ray integrals for linearly varying scalar fields within convex polyhedral cells without performing per-pixel ray marching [S1]. It sets itself apart from standard cell projection by replacing the integration step with a 3D texture lookup, using the scalar values on the front and back faces and the geometric thickness as coordinates [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Scalar values on the front face ($s_f$) and back face ($s_b$) of the tetrahedron, and the thickness ($l$) resulting from scan converting the tetrahedron [S1].
*   **Outputs:** Integrated color and opacity for the ray segment passing through the tetrahedron [S1].

**Data Structures:**
*   **3D Texture Map:** Stores the values of the volume ray integral as a function of $l$, $s_f$, and $s_b$ [S1]. The texture coordinates correspond to these three parameters.

**Steps:**
1.  **Scan Conversion:** Scan convert the projected tetrahedron to determine the thickness $l$ for each pixel [S1].
2.  **Scalar Evaluation:** Determine the scalar values $s_f$ and $s_b$ at the front and back faces of the tetrahedron for the ray segment corresponding to the pixel [S1].
3.  **Texture Lookup:** Perform a 3D dependent texture lookup using $l$, $s_f$, and $s_b$ as texture coordinates to retrieve the pre-computed volume ray integral values [S1].
    *   The lookup is performed based on the result of the lookup in the minimum texture (if applicable) [S1].
    *   The setup involves configuring the texture shader stages to handle the 3D lookup [S1].
4.  **Compositing:** Use the retrieved color and opacity values in the compositing pipeline [S1].

**Formulas:**
*   The pre-integrated classification function maps $(l, s_f, s_b)$ to integrated color and opacity. The specific mathematical definition of the pre-integration is not provided in the sources, but it depends on $l$, $s_f$, and $s_b$ [S1].
*   The opacity calculation for the segment follows the exponential model: $\alpha = 1 - \exp(-\tau_{avg} l)$, where $\tau_{avg}$ is derived from the pre-integrated data [S1, Parent].

**Parameters:**
*   $s_f$: Scalar value on the front face [S1].
*   $s_b$: Scalar value on the back face [S1].
*   $l$: Thickness resulting from scan converting the tetrahedron [S1].

**Edge Cases and Pitfalls:**
*   Precision issues in texture lookup may affect accuracy [S1].
*   The method assumes linear scalar variation within the tetrahedron [S1, Parent].

## Subtopics

### [Logarithmic Thickness Mapping](23633-logarithmic-thickness-mapping.md)
Addresses insufficient lookup table resolution for small geometric features in meshes with high aspect ratios by mapping physical thickness to texture coordinates logarithmically.

### [HILO Texture Lookup for Pre-integrated Cell Projection](23634-hilo-texture-lookup-for-pre-integrated-cell-projection.md)
Improves color accuracy by using 16-bit HILO textures instead of 32-bit floating-point textures, splitting the RGBA lookup into two separate 2-component lookups.

## Operating characteristics
*   **Time Complexity:** The method replaces per-pixel integration with a texture lookup, which is generally faster [S1].
*   **Memory Complexity:** Requires storage for the 3D texture map [S1].
*   **Strengths:** Efficient hardware-based implementation using texture shaders [S1].
*   **Limitations:** Resolution of the texture map may be insufficient for thin structures without techniques like Logarithmic Thickness Mapping [S1].
*   **When to use:** When efficient hardware-based rendering of tetrahedral volumes with linear scalar fields is required [S1].
*   **When not to use:** When high precision is needed for very thin structures without additional mapping techniques [S1].

The method was introduced in the context of hardware-based view-independent cell projection [S1]. It builds on the concept of pre-integrated classification [14, 4] as cited in [S1].
