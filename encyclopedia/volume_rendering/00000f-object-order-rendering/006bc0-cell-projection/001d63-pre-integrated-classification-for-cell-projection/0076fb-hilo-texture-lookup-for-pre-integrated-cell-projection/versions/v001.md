# HILO Texture Lookup for Pre-integrated Cell Projection

Also called: 16-bit HILO texture lookup, Split RGBA lookup

## Overview
This method improves the color accuracy of pre-integrated cell projection by replacing 32-bit floating-point textures with 16-bit HILO textures, which support trilinear interpolation [S1]. It solves the precision loss inherent in nearest-neighbor sampling of floating-point textures by splitting the RGBA lookup into two separate 2-component HILO textures [S1].

## How it works
**Inputs:**
- Scalar data value at the front face, $s^{(f)}$.
- Scalar data value at the back face, $s^{(b)}$.
- Thickness of the cell along the view ray, $l$.
- Maximum thickness in the scene, $l_{\max}$ (length of the longest edge of all cells in eye space) [S1].
- Texture dimensions $n_s, n_s, n_r$ for the $s^{(f)}$, $s^{(b)}$, and $l$ axes respectively [S1].

**Outputs:**
- Four color components (RGBA) and opacity, retrieved via two texture lookups.

**Data Structures:**
- Two 3D HILO textures, each containing 2 color components (e.g., RGBX split into RGB+X or RGBA split into RGB+A). The source specifies splitting the RGBA lookup into two HILO textures [S1].
- Texture coordinates are mapped to the range $[(2n)^{-1}, 1 - (2n)^{-1}]$ for each dimension $n$, corresponding to the centers of the 0-th and $(n-1)$-th texels [S1].

**Steps:**
1. **Compute Texture Coordinates:**
   - Map $s^{(f)}$ and $s^{(b)}$ linearly to their respective texture dimensions $n_s$. The resolution for these dimensions should correspond to the Nyquist sampling rate of the transfer functions to avoid visible artifacts [S1].
   - Map thickness $l \in [0, l_{\max}]$ to the texture coordinate $r$ in dimension $n_r$.
     - For $0 \leq l \leq l_{\max}/64$ (specifically $2^{-(n_r-2)}l_{\max}$ for $n_r=8$), use linear mapping [S1].
     - For $l > l_{\max}/64$, use logarithmic mapping to provide high resolution for small $l$ (where color changes are critical) and coarse resolution for large $l$ (where color dependency is smooth) [S1].
   - The final coordinate $r$ is clamped to $[(2n_r)^{-1}, 1 - (2n_r)^{-1}]$ [S1].

2. **Perform Lookups:**
   - Perform the first texture lookup using the computed coordinates to retrieve the first two color components.
   - Perform the second texture lookup using the same coordinates to retrieve the remaining two color components [S1].

3. **Combine Results:**
   - Combine the results from both lookups to form the complete RGBA color and opacity value for the fragment [S1].

**Pseudocode:**
```python
def compute_hilo_lookup(s_front, s_back, thickness, l_max, n_s, n_r):
    # Map scalar values to texture coordinates
    # Linear mapping for s_front and s_back
    coord_s = map_linear(s_front, s_back, n_s)
    
    # Map thickness to texture coordinate
    # Threshold for switching from linear to logarithmic mapping
    # Based on n_r=8 example: threshold = l_max / 64
    threshold = l_max / (2 ** (n_r - 2))
    
    if thickness <= threshold:
        coord_r = map_linear(thickness, threshold, n_r)
    else:
        # Logarithmic mapping for larger thickness values
        # Map [threshold, l_max] to [(2*n_r)^-1, 1 - (2*n_r)^-1]
        # Using log scale to preserve resolution for small thickness
        coord_r = map_logarithmic(thickness, threshold, l_max, n_r)
        
    # Clamp coordinates to valid texel center range
    min_coord = 1.0 / (2.0 * n_r)
    max_coord = 1.0 - (1.0 / (2.0 * n_r))
    coord_r = clamp(coord_r, min_coord, max_coord)
    
    # Perform two texture lookups
    # Assuming two HILO textures: tex1 (2 components) and tex2 (2 components)
    # Coordinates are (coord_s, coord_s, coord_r) for the 3D texture
    color_part1 = texture_lookup_3d(tex1, coord_s, coord_s, coord_r)
    color_part2 = texture_lookup_3d(tex2, coord_s, coord_s, coord_r)
    
    # Combine parts to get full RGBA
    full_color = combine_components(color_part1, color_part2)
    
    return full_color

def map_linear(value, max_val, n):
    # Map [0, max_val] to [1/(2n), 1 - 1/(2n)]
    min_coord = 1.0 / (2.0 * n)
    max_coord = 1.0 - (1.0 / (2.0 * n))
    if max_val == 0:
        return min_coord
    normalized = value / max_val
    return min_coord + normalized * (max_coord - min_coord)

def map_logarithmic(value, min_val, max_val, n):
    # Map [min_val, max_val] to [1/(2n), 1 - 1/(2n)] using log scale
    # This ensures high resolution for small values near min_val
    min_coord = 1.0 / (2.0 * n)
    max_coord = 1.0 - (1.0 / (2.0 * n))
    
    # Logarithmic normalization
    # log(value) - log(min_val) over log(max_val) - log(min_val)
    if min_val == 0:
        # Handle edge case if min_val is 0, though threshold prevents this in usage
        return min_coord
    log_min = math.log(min_val)
    log_max = math.log(max_val)
    log_val = math.log(value)
    
    normalized = (log_val - log_min) / (log_max - log_min)
    return min_coord + normalized * (max_coord - min_coord)
```

**Parameters:**
- $l_{\max}$: Maximum thickness, defined as the length of the longest edge of all cells in eye space [S1].
- $n_s, n_r$: Texture dimensions. $n_s$ should be chosen based on the Nyquist sampling rate of the transfer functions [S1].

**Edge Cases and Pitfalls:**
- **High Aspect Ratio Meshes:** If the mesh has a very high ratio between the longest and shortest edges, many small tetrahedra have thickness close to zero. Standard linear mapping wastes resolution on large $l$ values. The logarithmic mapping for $l > l_{\max}/64$ addresses this by providing high resolution for small $l$ and coarse resolution for large $l$ [S1].
- **Silhouette Fragments:** Fragments on the silhouette of a tetrahedral cell usually require a thickness very close to zero. The lookup table must cover this range accurately, which is why high resolution for small $l$ is critical [S1].
- **Floating-Point Textures:** Avoid using 32-bit floating-point textures as they only permit nearest-neighbor interpolation, leading to lower accuracy [S1].

## Operating characteristics
- **Accuracy:** Higher color accuracy compared to floating-point textures due to trilinear interpolation support in 16-bit HILO textures [S1].
- **Memory:** Uses 16-bit components, reducing memory usage compared to 32-bit floating-point textures [S1].
- **Performance:** Requires two texture lookups instead of one, which may have a slight performance impact, but avoids the cost of numerical integration [S1].
- **Limitations:** Requires hardware support for 16-bit HILO textures with trilinear interpolation [S1].

## Background
This technique was introduced by Kraus and Ertl in "Projecting Tetrahedra without Rendering Artifacts" (VIS 2004) [S1]. It builds on the pre-integrated cell projection method by improving the precision of the texture lookup step [S1].
