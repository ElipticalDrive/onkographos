# Logarithmic Thickness Mapping

Also called: HILO lookup, Logarithmic lookup

## Overview
Logarithmic Thickness Mapping is a coordinate transformation technique used in pre-integrated classification for cell projection to address insufficient lookup table resolution for small geometric features in meshes with high aspect ratios [S1]. It maps the physical thickness of a tetrahedron to a texture coordinate such that small thicknesses receive linear resolution while large thicknesses receive logarithmic resolution, thereby preventing artifacts caused by undersampling thin structures [S1]. It differs from linear thickness mapping by adapting the sampling density to the sensitivity of the pre-integrated classification function, which varies significantly with thickness [S1].

## How it works
**Inputs and Outputs:**
*   Input: Physical thickness $l$ of the tetrahedron (scalar).
*   Output: Texture coordinate $r$ in the range $[0, 1]$ (scalar).
*   Parameters: $n_r$ (dimension of the texture along the thickness axis), $l_{\max}$ (maximum expected thickness).

**Data Structures:**
*   The lookup table is a 3D texture. The dimension corresponding to thickness is $n_r$. In the reference implementation, $n_r = 16$ [S1]. The total table size is typically $256 \times 256 \times 16$ [S1].

**Formulas:**
The mapping function $r(l)$ is defined piecewise based on a threshold $\Delta l$:

$$ \Delta l = 2^{-(n_r-2)} l_{\max} $$

$$ r = \frac{\max \left( \log_2 \frac{l}{\Delta l}, 0 \right) + \min \left( \frac{l}{\Delta l}, 1 \right)}{n_r} + \frac{1}{2n_r} $$

Where:
*   $l$ is the thickness.
*   $n_r$ is the texture dimension for thickness.
*   $l_{\max}$ is the maximum thickness.
*   $\Delta l$ is the transition point between linear and logarithmic regions.

**Step-by-Step Implementation:**
1.  Calculate the threshold $\Delta l$ using the formula $\Delta l = 2^{-(n_r-2)} l_{\max}$.
2.  Compute the normalized thickness ratio $t = l / \Delta l$.
3.  Compute the logarithmic component: $c_{log} = \max(\log_2(t), 0)$.
4.  Compute the linear component: $c_{lin} = \min(t, 1)$.
5.  Sum the components and normalize by $n_r$: $r_{norm} = (c_{log} + c_{lin}) / n_r$.
6.  Add the offset to center the coordinate within the textel: $r = r_{norm} + \frac{1}{2n_r}$.

**Pseudocode:**
```python
def logarithmic_thickness_mapping(l, n_r, l_max):
    """
    Maps physical thickness l to texture coordinate r.
    
    Args:
        l: Physical thickness of the tetrahedron.
        n_r: Dimension of the texture along the thickness axis (e.g., 16).
        l_max: Maximum expected thickness in the scene.
        
    Returns:
        r: Texture coordinate in [0, 1].
    """
    # Calculate threshold separating linear and logarithmic regions
    delta_l = (2 ** (-(n_r - 2))) * l_max
    
    # Avoid division by zero if l_max is 0, though typically l_max > 0
    if delta_l == 0:
        return 0.5 / n_r # Fallback, though undefined behavior is likely if l_max=0
        
    # Normalized thickness
    t = l / delta_l
    
    # Logarithmic part: max(log2(t), 0)
    # If t <= 1, log2(t) <= 0, so this term becomes 0.
    # If t > 1, this term is log2(t).
    if t <= 0:
        log_part = 0.0
    else:
        log_part = max(math.log2(t), 0.0)
        
    # Linear part: min(t, 1)
    lin_part = min(t, 1.0)
    
    # Combine and normalize
    r = (log_part + lin_part) / n_r
    
    # Add offset to center in the textel
    r += 1.0 / (2.0 * n_r)
    
    return r
```

**Edge Cases and Pitfalls:**
*   **Zero Thickness:** When $l=0$, the formula yields $r = \frac{1}{2n_r}$. This maps to the center of the 0-th textel, avoiding undefined behavior or incorrect sampling at the boundary [S1].
*   **Small Thickness:** For $l < \Delta l$, the mapping is linear. This ensures high resolution for small thicknesses where the pre-integrated classification function changes rapidly [S1].
*   **Large Thickness:** For $l \ge \Delta l$, the mapping is logarithmic. This provides coarser resolution for large thicknesses where the function is smoother, saving texture memory [S1].
*   **Precision:** The implementation requires careful handling of floating-point arithmetic. The reference implementation notes that seven arithmetic instructions are sufficient in OpenGL ARB fragment programs [S1].

**Lookup Table Construction:**
The pre-integrated lookup table is computed using an adapted incremental pre-integration method [S1]. It incrementally computes two-dimensional slices for specific thickness values: $l = 0, \Delta l, 2\Delta l, 4\Delta l, 8\Delta l, \dots, 2^{n_r-2}\Delta l$ [S1]. This corresponds to the logarithmic steps in the mapping.

## Operating characteristics
*   **Time Complexity:** The mapping calculation requires seven arithmetic instructions in OpenGL ARB fragment programs [S1].
*   **Memory Complexity:** The lookup table size is determined by $n_r$. In the reference implementation, $n_r=16$, resulting in a $256 \times 256 \times 16$ texture [S1].
*   **Strengths:** Solves the problem of insufficient resolution for small tetrahedra in high-aspect-ratio meshes [S1]. It allows for accurate compositing without prohibitively large 1D lookup textures [S1].
*   **Limitations:** Requires a 3D texture lookup per fragment, adding to the texture lookup overhead [S1]. The accuracy of compositing may still be limited by hardware floating-point support, potentially requiring additional techniques like alpha dithering [S1].
*   **When to use:** Use when rendering tetrahedral meshes with high aspect ratios where thin structures are critical and linear mapping causes artifacts.
*   **When not to use:** If the mesh has uniform, large thicknesses, linear mapping might be sufficient and simpler. If hardware does not support 3D textures efficiently, this method may be slower.

## Background
Logarithmic Thickness Mapping was introduced in the paper "Projecting Tetrahedra without Rendering Artifacts" by Kraus and Ertl [S1]. The paper was presented at the IEEE Visualization 2004 conference [S1]. The method was developed to address artifacts in volume rendering algorithms caused by insufficient accuracy in compositing colors and the limitations of hardware floating-point color buffers [S1]. It builds on the concept of pre-integrated classification for cell projection, specifically optimizing the thickness coordinate mapping for tetrahedral meshes [S1].
