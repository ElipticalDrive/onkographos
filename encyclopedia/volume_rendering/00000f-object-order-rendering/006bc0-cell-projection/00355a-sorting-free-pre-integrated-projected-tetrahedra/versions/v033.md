# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a volume rendering technique for irregular datasets that eliminates the need for visibility sorting by treating rendering as a stochastic process [S1]. Unlike conventional Projected Tetrahedra which requires back-to-front sorting, and Particle-based Volume Rendering which suffers from visible footprints, PBVR uses pre-integrated projected tetrahedra and controls fragment rendering via opacity-based probability [S1]. It solves the scalability issues of sorting-based methods on large-scale irregular volumes and the quality issues of particle-based methods [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset represented as a tetrahedral mesh; a transfer function mapping scalar values to color and opacity; a viewing ray or rasterization context.
*   **Output:** A rendered image where semi-transparency is achieved through stochastic accumulation rather than alpha blending.

**Data Structures:**
The method operates on projected tetrahedra. Each tetrahedron is projected onto the image plane to form a polygon (triangle or quad). The data structure for a fragment includes its evaluated opacity $\tau$ and luminosity $c$ derived from the density emitter model [S1].

**Core Optical Model:**
The method uses the density emitter model, assuming the number of particles in a unit volume follows a Poisson distribution [S1].
*   Opacity $\tau$ for a ray segment of length $\Delta t$ with particle density $\rho$ is:
    $$ \tau = 1 - e^{-\rho \cdot \pi r^2 \cdot \Delta t} $$
    where $\pi r^2 \rho \Delta t$ expresses the expected number of particles in the segment [S1].
*   Brightness $B_k$ for a segment $k$ with constant particle luminosity $c_k$ and density $\rho_k$ is calculated based on the expected value of luminosity [S1]. The text notes the complexity of direct brightness calculation is $O(n^2)$ if intermediate values are considered [S1].

**Algorithm Steps:**
The rendering is performed by repeating the fragment rendering process $N$ times (repetition level) and averaging the results [S1].

1.  **Subdivision:** Subdivide the viewing ray into segments where particle luminosity $c_k$ and density $\rho_k$ are constant [S1].
2.  **Opacity Calculation:** Calculate the opacity $\tau_k$ for each segment using the Poisson distribution assumption [S1].
3.  **Stochastic Fragment Rendering:** For each repetition $n$ from 1 to $N$:
    a.  Rasterize the projected tetrahedra.
    b.  For each fragment generated by a tetrahedron, evaluate its opacity $\tau$ [S1].
    c.  Generate a random number $r$ uniformly distributed in $[0, 1]$ [G].
    d.  Compare $r$ with $\tau$:
        *   If $r > \tau$, discard the fragment (do not write to the buffer) [S1].
        *   If $r \le \tau$, render the fragment with its luminosity/color [S1].
    e.  Accumulate the rendered pixels into a temporary buffer [S1].
4.  **Averaging:** After $N$ repetitions, calculate the ensemble average of the pixel values across all repetitions to obtain the final brightness [S1].

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated. Higher $N$ reduces error but increases computation time [S1]. Typical values tested include 1, 25, 100, and 144 [S1].
*   **Resolution:** The method's performance is greatly influenced by the number of pixels [S1].

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** If the density function changes drastically, the method may generate an insufficient number of particles (in the stochastic sense) if $N$ is too low, leading to artifacts [S1].
*   **Performance Scaling:** The method is memory-consuming because increasing image resolution affects the number of particles/stochastic samples required [S1].
*   **Concave Sub-volumes:** Unlike sorting-based methods, this approach handles concave sub-volumes correctly without visibility-order compositing failures [S1].

## Operating characteristics
*   **Time Complexity:** The basic brightness calculation has a complexity of $O(n^2)$ if intermediate brightness values are considered [S1]. The overall rendering time is proportional to the number of repetitions $N$ and the number of pixels [S1].
*   **Memory Complexity:** Memory usage is influenced by the image resolution and the number of particles/tetrahedra [S1]. It requires less memory than Hardware-Assisted Visibility Sorting (HAVS), which needs memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, approximately 10 million particles (tetrahedra) can be rendered at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. For 1.4 million tetrahedra, HAVS achieved 1.3 fps, while PBVR's performance scales with pixel count [S1].
*   **Strengths:** No visibility sorting required; handles large-scale irregular volumes distributed across multiple nodes; avoids artifacts from insufficient k-buffer sizes in HAVS; avoids visible footprints of particle-based methods [S1].
*   **Limitations:** Performance is heavily influenced by the number of pixels; requires multiple repetitions for high quality (increasing time); may struggle with precipitous transfer functions if $N$ is insufficient compared to Sorting-free Projected Tetrahedra (SPT) [S1].
*   **When to Use:** Suitable for large-scale irregular volumes where sorting is impractical or impossible (e.g., distributed computing) and where particle-based methods produce visible artifacts [S1].
*   **When Not to Use:** When real-time performance is critical and high repetition counts are prohibitive; when the transfer function has precipitous changes and $N$ cannot be increased sufficiently [S1].

## Background
*   **Origin:** The method was introduced in the paper "Sorting-free pre-integrated projected tetrahedra" [S1].
*   **History:** It was developed to address the limitations of Particle-based Volume Rendering (PBVR) which has low image quality (visible footprints) and conventional Projected Tetrahedra which requires visibility sorting [S1]. It builds on the density emitter model and Poisson distribution assumptions for particle counts [S1].
*   **Usage:** Applied to large-scale irregular volumes from CSM and CFD simulations [S1].
