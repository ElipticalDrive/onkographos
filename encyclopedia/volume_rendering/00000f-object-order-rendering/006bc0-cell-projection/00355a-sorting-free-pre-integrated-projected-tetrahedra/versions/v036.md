# Sorting-free Pre-integrated Projected Tetrahedra

Also called: Pre-integrated Projected Tetrahedra, Sorting-free approach that controls the fragment rendering by using the opacity value, Sorting-free technique for volume rendering of an irregular volume dataset

## Overview
Sorting-free Pre-integrated Projected Tetrahedra (PBVR) is a volume rendering technique for irregular datasets that eliminates the need for explicit visibility sorting of tetrahedral cells [S1]. It solves the scalability bottlenecks of conventional object-order methods and the visibility-sorting requirements of standard Projected Tetrahedra by treating rendering as a stochastic process where sampling points occur along a viewing ray with a probability equal to the local opacity [S1]. Unlike its sibling [Parallelized Accurate Sorting for Projected Tetrahedra](1128-parallelized-accurate-sorting-for-projected-tetrahedra.md) which relies on hardware-assisted sorting, PBVR achieves semi-transparency through multiple stochastic repetitions of fragment rendering, avoiding artifacts associated with limited k-buffer sizes [S1]. This builds on the shared principles of [Cell projection](26-cell-projection.md).

## How it works
**Inputs and Outputs:**
*   **Input:** An irregular volume dataset decomposed into tetrahedral cells, each associated with scalar values at vertices [S1]. A transfer function mapping scalar values to color and extinction (opacity) [S1].
*   **Output:** A 2D image where each pixel's color is the ensemble average of multiple stochastic renderings [S1].

**Data Structures:**
The method operates on the projected tetrahedra primitives [S1]. Each tetrahedron is defined by 4 vertices in 3D space [G]. During rendering, these are projected to 2D screen space [G]. The core data structure for the stochastic process is the opacity value $\alpha$ calculated for each fragment or ray segment, derived from the density emitter model [S1].

**Core Optical Model:**
The method uses a density emitter model where the 3D scalar field is characterized as a varying density emitter with a single level of scattering [S1]. The opacity is derived from the number of particles in a unit volume, assuming the number of particles follows a Poisson distribution [S1].

**Numbered Steps:**

1.  **Projection and Subdivision:** Decompose the volume into tetrahedra [G]. Project the 3D vertices of each tetrahedron to 2D screen space [G]. Subdivide the viewing ray into segments where particle luminosity ($c_k$) and density ($\rho_k$) are constant [S1]. This builds on the cell projection principles of [Projected Tetrahedra Rendering](17711-projected-tetrahedra-rendering.md) [G].
2.  **Opacity Calculation:** For each fragment (or ray segment within the tetrahedron), calculate the opacity $\alpha$ [S1]. In the density emitter model, the opacity for a segment of length $\Delta t$ is given by:
    $$ \alpha = 1 - e^{-\rho \cdot \pi r^2 \cdot \Delta t} $$
    where $\rho$ is the number of particles in a unit volume (derived from the scalar field), and $\pi r^2$ represents the cross-sectional area factor [S1]. Note: In the context of the projected tetrahedra implementation, this opacity is evaluated per fragment based on the interpolated scalar values within the tetrahedron [S1].
3.  **Stochastic Fragment Rendering (Repetition):** To achieve semi-transparency without alpha blending or sorting, the rendering calculation is repeated $N$ times (the repetition level) [S1]. For each repetition:
    a.  Rasterize the projected tetrahedra [G].
    b.  For each fragment, generate a random number $r \in [0, 1]$ [G].
    c.  Compare $r$ with the calculated opacity $\alpha$ of the fragment [S1].
    d.  If $r > \alpha$, discard the fragment (it is treated as transparent/non-existent for this sample) [S1].
    e.  If $r \le \alpha$, render the fragment with its color (opaque emission) [S1].
    
    The possibility that the $k$-th luminosity is equal to the brightness value is defined by the event where there are no particles from the first to the $(k-1)$-th ray-segments and more than one particle in the $k$-th ray segment [S1]. The brightness $B_k$ for a segment is calculated as:
    $$ B_k = c_k \times (1 - e^{-\rho \cdot \text{area} \cdot \text{length}}) $$
    where $c_k$ is particle luminosity [S1].
4.  **Ensemble Averaging:** Accumulate the color values from all $N$ repetitions for each pixel [S1]. The final pixel color is the average of these accumulated values [S1].

**Parameters:**
*   **Repetition Level ($N$):** The number of times the rendering calculation is repeated [S1]. Higher $N$ reduces error but increases computation time [S1]. Typical values tested include 1, 25, 100, and 144 [S1].
*   **Resolution:** The method's performance is heavily influenced by the number of pixels [S1]. Experiments used 1024x1024 resolution [S1].

**Edge Cases and Pitfalls:**
*   **Drastic Density Changes:** If the density function changes drastically, PBVR may generate an insufficient number of particles, leading to visual artifacts compared to methods like SPT which handle precipitous transfer functions better [S1].
*   **Memory Consumption:** The method is memory-consuming because the increase in image resolution affects the number of particles processed [S1].
*   **Computational Complexity:** The basic brightness calculation has a complexity of $O(n^2)$ if intermediate brightness values are considered [S1].
*   **Visibility Sorting Bottlenecks:** Conventional techniques require visibility sorting, which is difficult for large-scale irregular volumes distributed across multiple computing nodes [S1]. Concave sub-volumes also fail visibility-order compositing strategies [S1].

**Pseudocode:**

```python
import math
import random

def render_stochastic_tetrahedra(tetrahedra, transfer_function, resolution, repetition_level):
    """
    Renders an irregular volume using sorting-free pre-integrated projected tetrahedra.
    
    Args:
        tetrahedra: List of tetrahedra, each with 4 vertices and associated scalar values.
        transfer_function: Function mapping scalar value to (color, extinction).
        resolution: Tuple (width, height) of the output image.
        repetition_level: Integer N, number of stochastic repetitions.
        
    Returns:
        Image buffer with accumulated colors.
    """
    width, height = resolution
    # Initialize image buffer for accumulation
    image_buffer = [[0.0, 0.0, 0.0] for _ in range(height * width)]
    
    for rep in range(repetition_level):
        rep_buffer = [[0.0, 0.0, 0.0] for _ in range(height * width)]
        
        for tet in tetrahedra:
            projected_verts = project_to_screen(tet.vertices, width, height)
            # Rasterize the 4 triangular faces of the tetrahedron
            faces = [(0, 1, 2), (0, 1, 3), (0, 2, 3), (1, 2, 3)]
            for f in faces:
                v0, v1, v2 = projected_verts[f[0]], projected_verts[f[1]], projected_verts[f[2]]
                fragments = rasterize_triangle(v0, v1, v2, width, height)
                for frag in fragments:
                    scalar_val = interpolate_scalar(frag.bary, tet.vertex_scalars)
                    color, extinction = transfer_function(scalar_val)
                    alpha = 1.0 - math.exp(-extinction)
                    if random.random() <= alpha:
                        idx = frag.y * width + frag.x
                        rep_buffer[idx] = [color[0], color[1], color[2]]
        
        for i in range(height * width):
            image_buffer[i][0] += rep_buffer[i][0]
            image_buffer[i][1] += rep_buffer[i][1]
            image_buffer[i][2] += rep_buffer[i][2]
            
    final_image = []
    for c in image_buffer:
        final_image.append([c[0] / repetition_level, c[1] / repetition_level, c[2] / repetition_level])
    return final_image

def project_to_screen(vertices, width, height):
    """Projects 3D vertices to 2D screen coordinates using perspective projection."""
    projected = []
    for v in vertices:
        z = -v[2] if v[2] < 0 else 0.001
        x_ndc = v[0] / z
        y_ndc = v[1] / z
        sx = int((x_ndc + 1.0) * 0.5 * width)
        sy = int((y_ndc + 1.0) * 0.5 * height)
        projected.append((sx, sy, z))
    return projected

def rasterize_triangle(v0, v1, v2, width, height):
    """Rasterizes a 2D triangle, returning fragments with barycentric coordinates."""
    fragments = []
    min_x = max(0, min(v0[0], v1[0], v2[0]))
    max_x = min(width - 1, max(v0[0], v1[0], v2[0]))
    min_y = max(0, min(v0[1], v1[1], v2[1]))
    max_y = min(height - 1, max(v0[1], v1[1], v2[1]))
    for y in range(min_y, max_y + 1):
        for x in range(min_x, max_x + 1):
            bary = calculate_barycentric(x, y, v0, v1, v2)
            if bary is not None and all(b >= 0.0 for b in bary):
                fragments.append({'x': x, 'y': y, 'bary': bary})
    return fragments

def calculate_barycentric(x, y, v0, v1, v2):
    """Calculates barycentric coordinates for a point inside a triangle."""
    denom = (v1[1] - v2[1]) * (v0[0] - v2[0]) + (v2[0] - v1[0]) * (v0[1] - v2[1])
    if abs(denom) < 1e-6:
        return None
    b0 = ((v1[1] - v2[1]) * (x - v2[0]) + (v2[0] - v1[0]) * (y - v2[1])) / denom
    b1 = ((v2[1] - v0[1]) * (x - v2[0]) + (v0[0] - v2[0]) * (y - v2[1])) / denom
    b2 = 1.0 - b0 - b1
    return (b0, b1, b2)

def interpolate_scalar(bary, scalars):
    """Interpolates scalar value using barycentric coordinates."""
    return bary[0] * scalars[0] + bary[1] * scalars[1] + bary[2] * scalars[2]
```

## Operating characteristics
*   **Time Complexity:** The computational complexity of the basic brightness calculation is $O(n^2)$ if intermediate brightness values are considered [S1]. The total time is proportional to the number of repetitions $N$ and the number of pixels [S1].
*   **Memory Complexity:** The method is memory-consuming because the increase in image resolution affects the number of particles processed [S1]. It requires less memory than HAVS, which needs memory space for sorting cell faces about twice that for tetrahedral cells [S1].
*   **Measured Performance:** On an NVIDIA GeForce 9600GT, ~10 million particles (tetrahedra) can be rendered at 25.7 milliseconds per repetition with 1024x1024 resolution [S1]. For 1024x1024 resolution, the computing time is estimated at 1.4 seconds per repetition for larger datasets [S1].
*   **Strengths:** No visibility sorting required, making it suitable for large-scale irregular volumes distributed across multiple computing nodes [S1]. Avoids artifacts caused by insufficient k-buffer size associated with HAVS [S1]. Better than particle-based methods (PBVR) in avoiding visible footprints when the viewpoint is inside the volume [S1].
*   **Limitations:** Performance is greatly influenced by the number of pixels [S1]. May generate insufficient particles when the density function changes drastically, leading to lower quality compared to SPT for precipitous transfer functions [S1]. Requires multiple repetitions to achieve high-quality images, increasing computation time [S1].
*   **When to Use:** Suitable for large-scale irregular volume datasets where visibility sorting is a bottleneck or impractical, and when the density function does not change precipitously [S1]. Preferred over HAVS when memory is constrained and over PBVR when viewpoint is inside the volume [S1].

## Background
The Sorting-free Pre-integrated Projected Tetrahedra (PBVR) technique was developed to address the difficulties of rendering large-scale irregular volume datasets [S1]. Conventional techniques require the entire volume dataset to be stored in a single computational node to calculate visibility, which is impractical for multi-node simulations [S1]. The method was introduced in a paper by the authors of [S1], building upon the concept of particle-based volume rendering but replacing particles with projected tetrahedra to improve image quality and eliminate the need for sorting [S1]. It was designed to handle irregular volumes where concave sub-volumes fail visibility-order compositing strategies [S1].
