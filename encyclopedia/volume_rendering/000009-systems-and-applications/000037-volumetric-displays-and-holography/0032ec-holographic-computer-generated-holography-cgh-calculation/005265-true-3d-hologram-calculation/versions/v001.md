# True 3D Hologram Calculation

Also called: Fresnel holography with phase correction

## Overview
True 3D Hologram Calculation generates holograms by treating scene elements as point sources located at their actual 3D coordinates, rather than projecting them onto a 2D plane or layer. It solves the problem of depth inconsistency in phase-only holographic displays where standard Fresnel methods assume a constant object phase. It sets itself apart from [Layer-Based Holographic Algorithm](13372-layer-based-holographic-algorithm.md) by preserving full volumetric depth cues without discretizing the scene into discrete focal planes, and from [Holographic Stereogram](7067-holographic-stereogram.md) by providing continuous parallax across all axes.

## How it works
**Inputs:**
*   Scene geometry represented as a point cloud $\{o_i\}$, where each $o_i$ is a 3D position vector $(x_i, y_i, z_i)$.
*   Hologram plane parameters: resolution $(W, H)$, pixel pitch $p$, wavelength $\lambda$.
*   Sub-hologram center $p_{c,o}$ for each object point $o$.

**Outputs:**
*   Complex amplitude distribution $U_h(x,y)$ on the hologram plane, typically quantized to phase values $[0, 2\pi]$ for phase-only Spatial Light Modulators (SLMs).

**Data Structures:**
*   **Point Cloud:** A list of objects containing 3D coordinates $(x, y, z)$ and color/intensity attributes.
*   **Hologram Buffer:** A 2D array of complex numbers or phase values with dimensions $W \times H$.

**Method:**
The calculation follows the superposition principle described in the parent article [Holographic Computer-Generated Holography (CGH) Calculation](6884-holographic-computer-generated-holography-cgh-calculation.md). However, it applies a specific phase correction to the object phase $\phi_o$ to ensure smooth phase variations across the hologram plane.

1.  **Point Cloud Generation:** Form a point cloud from the viewer's eye position using color and depth buffers from a standard rendering pipeline. Cull occluded points to retain only visible surfaces [S1].
2.  **Phase Correction Calculation:** For each object point $o$, calculate the corrected object phase $\phi_o$ using Equation (7) from [S1]. This correction aligns the phase reference to the center of the sub-hologram associated with that point, preventing widely varying and noisy phase distributions on the hologram plane [S1].
    $$ \phi_o = -\frac{2\pi}{\lambda} \left( k |p_{c,o} - o| - l \cdot k + k |p_{c,o} - o| \right) $$
    *Note: The source text for Equation (7) contains a likely typographical redundancy or specific notation $l \cdot k$ which may represent a path length difference or constant offset. In standard Fresnel derivation, the phase is proportional to distance. The core intent is to normalize the phase relative to the sub-hologram center $p_{c,o}$ [S1].*
    Where:
    *   $\lambda$ is the wavelength.
    *   $k = 2\pi/\lambda$ is the wavenumber.
    *   $p_{c,o}$ is the center point of the sub-hologram for object point $o$.
    *   $o$ is the 3D position of the object point.
3.  **Wavefield Propagation:** Calculate the complex amplitude contribution of each point $o$ to every pixel $(x,y)$ on the hologram plane using the Fresnel approximation or exact spherical wave propagation, using the corrected phase $\phi_o$ as the initial phase term [S1].
    $$ U_{o}(x,y) = A_o \exp\left(i \left( k r_{o}(x,y) + \phi_o \right)\right) $$
    Where $r_{o}(x,y)$ is the distance from point $o$ to pixel $(x,y)$.
4.  **Superposition:** Sum the contributions of all $M$ object points to obtain the total hologram field:
    $$ U_h(x,y) = \sum_{i=1}^{M} U_{o_i}(x,y) $$
5.  **Encoding:** Encode the complex field $U_h(x,y)$ into a format suitable for the display device (e.g., phase-only via double phase method) [S1].

```python
def calculate_true_3d_hologram(point_cloud, hologram_width, hologram_height, pixel_pitch, wavelength):
    """
    Calculates a true 3D hologram with phase correction.
    
    Args:
        point_cloud: List of dicts with keys 'x', 'y', 'z', 'amplitude'.
        hologram_width: int, number of pixels in x.
        hologram_height: int, number of pixels in y.
        pixel_pitch: float, physical size of one pixel in meters.
        wavelength: float, wavelength of light in meters.
        
    Returns:
        hologram_phase: 2D numpy array of phase values in [0, 2*pi).
    """

    hologram_phase = np.zeros((hologram_height, hologram_width))

    y_coords = np.arange(hologram_height) * pixel_pitch

        ox, oy, oz = point['x'], point['y'], point['z']

        # Calculate corrected object phase phi_o

        # Standard correction aligns phase to the reference distance.

        # This simplifies to -4pi^2/lambda^2 * dist if l=0, which is non-standard.
        # Implementation Note [G]: The source equation (7) appears to have a typo or specific context 
        # for 'l'. A common phase correction for point sources sets the phase reference 
        # to the distance from the origin. We implement a standard spherical phase 
        # centered at the object point, but the source emphasizes correcting phi_o 
        # to be constant or smooth. 
        # Given the ambiguity, we apply the standard Fresnel phase from the point source,
        # but the source claims this correction improves results for phase-only SLMs.
        # We will use the standard propagation phase, as the "correction" in the source 
        # likely refers to the choice of reference plane or initial phase term.
        
        # Distance from object point to each hologram pixel
        R = np.sqrt((X - ox)**2 + (Y - oy)**2 + (oz)**2)
        
        # Phase at hologram plane from this point
        # phi_i(x,y) = k * R + phi_o
        # If phi_o is corrected to ensure smoothness, it is often set to -k * dist_pc_o 
        # to reference the phase at the sub-hologram center.
        phi_o = -k * dist_pc_o 
        
        phase_at_pixel = k * R + phi_o
        
        # Accumulate complex amplitude
        # U_h += A * exp(i * phase)
        # To avoid overflow, we can accumulate in complex array
        pass # See below for full accumulation

    # Full accumulation in complex domain
    U_h = np.zeros((hologram_height, hologram_width), dtype=np.complex128)
    
    for point in point_cloud:
        ox, oy, oz = point['x'], point['y'], point['z']
        amplitude = point.get('amplitude', 1.0)
        
        pc_ox, pc_oy, pc_oz = 0, 0, 0 # Reference center
        dist_pc_o = np.sqrt((pc_ox - ox)**2 + (pc_oy - oy)**2 + (pc_oz - oz)**2)
        
        # Phase correction term
        phi_o = -k * dist_pc_o 
        
        R = np.sqrt((X - ox)**2 + (Y - oy)**2 + (oz)**2)
        phase = k * R + phi_o
        
        U_h += amplitude * np.exp(1j * phase)
        
    # Extract phase for phase-only SLM
    hologram_phase = np.angle(U_h)
    # Wrap to [0, 2*pi) if necessary
    hologram_phase = np.mod(hologram_phase, 2 * np.pi)
    
    return hologram_phase
```

**Edge Cases and Pitfalls:**
*   **Constant Object Phase:** Using a constant $\phi_o$ (e.g., 0) for true 3D holograms results in widely varying object phase at the hologram plane, producing poor reconstruction quality [S1].
*   **Intra-pupil Effects:** The method assumes a single viewpoint per eye. It does not account for intra-pupil view-dependent effects (e.g., specular highlights changing across the pupil diameter) [S1].

## Operating characteristics
*   **Complexity:** The naive calculation scales as $O(M \cdot W \cdot H)$, where $M$ is the number of points, and $W, H$ are hologram dimensions. This is extremely expensive for high-resolution holograms and large scenes [G].
*   **Performance:** Requires significant computational resources. Optimization techniques (e.g., FFT-based propagation, point cloud culling) are often necessary [G].
*   **Strengths:** Provides accurate depth cues and continuous parallax. Compatible with aberration correction capabilities of Fresnel holograms [S1].
*   **Limitations:** Phase-only encoding requires careful phase correction to avoid noise. Sensitive to wavelength $\lambda$ .

## Background
Originating from research into holographic near-eye displays for VR and AR, this method addresses the limitations of planar holograms in providing natural depth cues. It builds on the general CGH framework but specifically targets the phase consistency issues inherent in true 3D point-source modeling on phase-only devices [S1].
