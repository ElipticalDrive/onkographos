## Overview
The Diffraction-Specific Approach (also known as the Hogel Vector Approach) is a method for calculating Computer-Generated Holograms (CGH) that avoids the direct simulation of optical interference. Instead of summing complex wavefronts from object points to a hologram plane, it treats the hologram as a subsampled array of functional elements called "hogels," represented spectrally as "hogel vectors" [S1]. It builds on [Holographic Computer-Generated Holography (CGH) Calculation](6884-holographic-computer-generated-holography-cgh-calculation.md) by leveraging standard 3D computer graphics rendering (orthographic projections) to generate these vectors, enabling significant bandwidth compression and faster computation compared to the [Interference-Based Approach](808-volume-rendering-based-cgh-calculation.md) [S1]. Unlike [Volume Rendering based CGH Calculation](808-volume-rendering-based-cgh-calculation.md), which sums point sources, this method decouples the 3D scene generation from the fringe calculation by using precomputed basis fringes [S1].

## How it works
The method consists of two main stages: encoding (generating the hogel-vector array) and decoding (recovering the fringe).

### Inputs and Outputs
*   **Inputs:** A 3D scene description (points, primitives, color, lighting, occlusion data); Hologram parameters (resolution, wavelength $\lambda$, viewing angle); Compression Ratio (CR).
*   **Outputs:** A hogel-vector array (compressed representation); A reconstructed holographic fringe (complex optical field) suitable for SLM modulation.

### Data Structures
1.  **3D Scene List:** A list of 3D points or primitives with attributes: position $(x,y,z)$, color $(R,G,B)$, intensity, and occlusion status [S1].
2.  **Hogel-Vector Array:** A 2D array where each element corresponds to a spatial hogel (a block of hologram pixels). Each hogel is represented by a vector of spectral components (coefficients) [S1].
3.  **Basis Fringes:** A precomputed set of reference fringe patterns corresponding to the spectral samples (viewing directions) of the hogels [S1].

### Steps

#### 1. 3D Scene Preparation
Perform a 3D filling operation to generate a list of 3D points (or other primitives) including information about color, lighting, shading, and occlusion [S1]. This step is identical to standard computer graphics rendering pipelines.

#### 2. Orthographic Projection Rendering
Render a series of orthographic projections of the 3D scene. Each projection corresponds to a specific spectral sample (viewing direction) of the hogels. The number of projections equals the number of spectral components in the hogel vectors [S1].
*   The orthographic projections provide a discrete sampling of space (pixels) and spectrum (projection direction) [S1].
*   These projections are converted into the hogel-vector array. Each hogel in the array contains the pixel values from the corresponding locations in the set of orthographic projections [S1].

#### 3. Hogel-Vector Array Construction
The orthographic projections are mapped into the hogel-vector array. If the hologram is divided into $N_h \times N_v$ hogels, and each hogel has $K$ spectral components, the array has dimensions $N_h \times N_v \times K$ [S1].

#### 4. Decoding (Fringe Recovery)
To reconstruct the holographic fringe from the hogel-vector array, an inner product is performed between the hogel vectors and the precomputed basis fringes [S1].
*   Let $H_{i,j}$ be the hogel vector at spatial position $(i,j)$, with components $h_{i,j,k}$ for $k=1 \dots K$.
*   Let $B_k(x,y)$ be the $k$-th basis fringe pattern, defined over the hologram plane coordinates $(x,y)$ within the hogel's spatial extent.
*   The reconstructed fringe $U(x,y)$ for the hogel at $(i,j)$ is:
    $$ U_{i,j}(x,y) = \sum_{k=1}^{K} h_{i,j,k} \cdot B_k(x,y) $$
*   This operation is repeated for all hogels to form the complete hologram fringe [S1].

```python
def diffraction_specific_cgh(scene_points, hologram_params, compression_ratio):
    """
    Calculate holographic fringe using the Diffraction-Specific Approach.
    
    Args:
        scene_points: List of 3D points with color, intensity, occlusion.
        hologram_params: Dict containing hologram width, height, wavelength, hogel size.
        compression_ratio: Integer, ratio of fringe size to hogel-vector array size.
        
    Returns:
        fringe: 2D array of complex values representing the hologram.
    """
    # Step 1: 3D Filling (Standard Graphics)
    # Generate list of 3D points with color, lighting, shading, occlusion
    # This is handled by the graphics engine.
    points = prepare_3d_scene(scene_points)
    
    # Step 2: Determine Spectral Samples
    # Number of spectral components K is derived from compression ratio
    # CR = Size(Fringe) / Size(HogelVectorArray)
    # HogelVectorArray size is proportional to K * Number_of_Hogels
    # Fringe size is proportional to Hologram_Pixels
    # K is chosen based on CR and spatial subsampling
    num_hogels_x = hologram_params['width'] // hologram_params['hogel_width']
    num_hogels_y = hologram_params['height'] // hologram_params['hogel_height']
    num_spectral_components = determine_K_from_CR(compression_ratio)
    
    # Step 3: Render Orthographic Projections
    # Render 'num_spectral_components' orthographic views of the scene
    # Each view corresponds to a different viewing direction (spectral sample)
    orthographic_projections = []
    for k in range(num_spectral_components):
        view_direction = get_view_direction(k, num_spectral_components)
        projection = render_orthographic_projection(points, view_direction, 
                                                    hologram_params['hogel_width'], 
                                                    hologram_params['hogel_height'])
        orthographic_projections.append(projection)
        
    # Step 4: Construct Hogel-Vector Array
    # Map projections to hogel vectors
    # hogel_vectors[i][j] is a vector of size num_spectral_components
    hogel_vectors = initialize_array(num_hogels_x, num_hogels_y, num_spectral_components)
    
    for k in range(num_spectral_components):
        proj = orthographic_projections[k]
        for i in range(num_hogels_x):
            for j in range(num_hogels_y):
                # Extract pixel block from projection for this hogel
                hogel_block = extract_block(proj, i, j, hologram_params['hogel_width'], 
                                            hologram_params['hogel_height'])
                # Store as component k of the hogel vector
                hogel_vectors[i][j][k] = hogel_block
                
    # Step 5: Decode to Fringe using Basis Fringes
    # Precompute basis fringes B_k(x,y) for each spectral component k
    # Basis fringes are typically plane waves or spherical waves corresponding 
    # to the viewing directions used in Step 3
    basis_fringes = precompute_basis_fringes(num_spectral_components, hologram_params)
    
    fringe = initialize_complex_array(hologram_params['width'], hologram_params['height'])
    
    for i in range(num_hogels_x):
        for j in range(num_hogels_y):
            # Get hogel vector for this spatial location
            hogel_vec = hogel_vectors[i][j]
            
            # Get spatial coordinates of this hogel in the hologram plane
            x_start = i * hologram_params['hogel_width']
            y_start = j * hologram_params['hogel_height']
            
            # Compute inner product: sum over k of (hogel_vec[k] * basis_fringe[k])
            for k in range(num_spectral_components):
                # Basis fringe k is replicated over the hogel's spatial extent
                basis_fringe_k = basis_fringes[k][x_start:x_start+hologram_params['hogel_width'], 
                                                  y_start:y_start+hologram_params['hogel_height']]
                
                # Add contribution to fringe
                fringe[x_start:x_start+hologram_params['hogel_width'], 
                       y_start:y_start+hologram_params['hogel_height']] += \
                    hogel_vec[k] * basis_fringe_k
                    
    return fringe

def determine_K_from_CR(compression_ratio):
    """
    Determine the number of spectral components K based on Compression Ratio.
    CR = (Hologram_Pixels) / (Hogels * K)
    Hogels = (Hologram_Pixels) / (Hogel_Pixels)
    So CR = Hogel_Pixels / K
    Therefore K = Hogel_Pixels / CR
    Note: Hogel_Pixels is the number of pixels in one hogel.
    """
    # This is a simplified model. In practice, K is chosen to balance 
    # image quality and compression.
    # Typical CR values are 8:1, 16:1, 32:1.
    # If Hogel_Pixels = 64 (8x8), and CR=8, K=8.
    # If Hogel_Pixels = 64, and CR=32, K=2.
    # The source does not give the exact formula for K, but implies K is 
    # inversely proportional to CR.
    # We assume Hogel_Pixels is fixed by hogel size.
    hogel_pixels = 64 # Example value, not given in sources. [G]
    K = hogel_pixels / compression_ratio
    return int(K)

def precompute_basis_fringes(num_spectral_components, hologram_params):
    """
    Precompute basis fringes for each spectral component.
    Basis fringes are typically plane waves corresponding to the viewing directions.
    """
    basis_fringes = []
    for k in range(num_spectral_components):
        view_direction = get_view_direction(k, num_spectral_components)
        # Create a plane wave for this direction
        # U(x,y) = exp(i * k_wave * (sin(theta)*x + cos(theta)*y))
        # where theta is the angle of the view direction
        theta = get_angle_from_direction(view_direction)
        k_wave = 2 * pi / hologram_params['wavelength']
        x = np.arange(hologram_params['width'])
        y = np.arange(hologram_params['height'])
        X, Y = np.meshgrid(x, y)
        basis_fringe = np.exp(1j * k_wave * (np.sin(theta) * X + np.cos(theta) * Y))
        basis_fringes.append(basis_fringe)
    return basis_fringes

def get_view_direction(k, num_components):
    """
    Get the viewing direction for spectral component k.
    Assumes uniform sampling over a range of angles.
    """
    # This is a placeholder for the specific sampling scheme.

    angle = 2 * pi * k / num_components
    return (np.cos(angle), np.sin(angle), 0) # Example direction

def get_angle_from_direction(direction):
    """
    Get the angle from a 2D direction vector.
    """
    return np.arctan2(direction[1], direction[0])
```

### Parameters
*   **Compression Ratio (CR):** The ratio between the size of the fringe and the hogel-vector array. Typical values are 8:1, 16:1, and 32:1 [S1].
*   **Hogel Size:** The spatial extent of each hogel in pixels. Not given in the sources. [G]
*   **Number of Spectral Components (K):** Determined by CR and hogel size. Not given in the sources. [G]

### Edge Cases and Pitfalls
*   **Image Sharpness Loss:** Increasing CR (and thus reducing K) leads to a loss in image sharpness (added blur). For CR <= 8:1, the blur is invisible to the Human Visual System (HVS). For CR 16:1 or 32:1, good images are achieved with acceptable degradation [S1].
*   **Basis Fringe Accuracy:** The accuracy of the reconstructed fringe depends on the accuracy of the precomputed basis fringes. If the basis fringes do not match the actual wavefronts from the orthographic projections, artifacts will occur.
*   **Occlusion:** The 3D filling operation must correctly handle occlusion to ensure that only visible points contribute to the orthographic projections. Incorrect occlusion handling will lead to ghosting or incorrect intensity in the hologram.

## Subtopics

### Holographic Bandwidth Compression
Techniques to increase fringe computation speed and reduce data volume, including spatial subsampling, nonuniform sampling, and standard video compression algorithms [S1]. Nonuniformly sampled fringes provide lossless bandwidth compression, whereas standard MPEG algorithms are used for encoding/decoding computed fringes (implying potential loss or different characteristics) [S1]. Holographic bandwidth compression increases fringe computation speed by 3000 times for the same hardware implementation [S1].

### Hogel-Vector Bandwidth Compression
A technique within the diffraction-specific approach where the fringe is subsampled spatially into hogels and spectrally into hogel vectors. It uses standard 3D computer graphics rendering (orthographic projections) to generate the data [S1]. The inner product between an array of hogel vectors and the precomputed basis fringes is performed rapidly by exploiting the texture mapping function and the accumulation buffer. The texture mapping function rapidly multiplies a component from each hogel vector by a replicated array of a single basis fringe. This operation is repeated several times, once for each hogel-vector component, accumulating the result in the accumulation buffer [S1]. Achieved a computation time of 0.9 seconds for fringes of 6-MB with CR=32:1 using Silicon Graphics RealityEngine2 (RE2) for both rendering orthographic projections and decoding [S1].

### Fringelets
Fringelet bandwidth compression further subsamples in the spatial domain. Each hogel is encoded as a spatially smaller "fringelet." Using a simple sample-replication decoding scheme, fringelets provide the fastest method (to date) of fringe computation. Complex images have been generated in under one second for 6 MB fringes [S1]. Furthermore, a "fringelet display" can optically decode fringelets to produce a CR-times greater image volume without increased electronic bandwidth [S1].

## Operating characteristics
*   **Time Complexity:** The encoding step (rendering orthographic projections) is $O(N \cdot K)$, where $N$ is the number of pixels in the projections and $K$ is the number of spectral components. The decoding step is $O(H \cdot K)$, where $H$ is the number of hogels. This is significantly faster than the interference-based approach, which is $O(M \cdot P)$, where $M$ is the number of object points and $P$ is the number of hologram pixels [S1].
*   **Memory Complexity:** The hogel-vector array size is $O(H \cdot K)$, which is smaller than the fringe size $O(P)$ by the compression ratio CR [S1].
*   **Measured Performance:** On a Silicon Graphics RealityEngine2 (RE2), a computation time of 0.9 seconds was achieved for fringes of 6-MB with CR=32:1 [S1]. Holographic bandwidth compression increases fringe computation speed by 3000 times for the same hardware implementation [S1].
*   **Strengths:** Fast computation, bandwidth compression, compatibility with standard 3D graphics hardware (GPUs), ability to match blur to HVS acuity [S1].
*   **Limitations:** Loss of image sharpness (blur) with higher compression ratios, requires precomputed basis fringes, may introduce artifacts if basis fringes are inaccurate [S1].
*   **When to Use:** When interactive or near-interactive holographic display is required, and some loss of image sharpness is acceptable. Particularly suitable for applications where the HVS is the final observer [S1].
*   **When Not to Use:** When high-resolution, artifact-free holograms are required, or when the scene is too complex for efficient orthographic projection rendering [S1].

## Background
The Diffraction-Specific Approach was introduced as an alternative to the conventional Interference-Based Approach for computing holographic fringes. The Interference-Based Approach simulates the physical process of optical interference, summing complex wavefronts from object elements with a reference wavefront. This method requires billions of computational steps for small simple holographic images, involving expensive floating-point calculations with trigonometric functions and square roots, often necessitating supercomputers [S1]. The Diffraction-Specific Approach breaks from this traditional simulation by working backwards from the 3D image, treating the fringe as subsampled spatially into hogels and spectrally into hogel vectors [S1]. This approach was developed to enable interactive holographic displays by leveraging standard 3D computer graphics rendering and specialized hardware for fast decoding [S1]. The concept of hogels and hogel vectors was pioneered by researchers in the field of holovideo and computer-generated holography in the 1990s [S1].
