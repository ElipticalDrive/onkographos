# Point-Cloud Based CGH Calculation

Also called: Object point scattering method, Point-Cloud Approach, Point-based CGH, Point-wise Integration Method, Summation of Point Contributions, conventional hologram, conventional methods, nCGH

## Overview
Point-Cloud Based CGH Calculation is a method for generating computer-generated holograms by discretizing a 3D scene into a finite set of points, treating each as a coherent point light source, and summing their propagated wavefields on the hologram plane [S1, S2]. It is distinguished from sibling methods like [Volume Rendering based CGH Calculation](808-volume-rendering-based-cgh-calculation.md) by its explicit handling of discrete primitives rather than volumetric density, and from [Diffraction-Specific Approach](7015-diffraction-specific-approach.md) by its reliance on direct superposition rather than engineered diffraction kernels [S4]. While computationally simpler to implement than polygon-based or layer-based approaches, it suffers from high computational cost for large scenes and produces artifacts such as vivid boundaries and weak defocus blur compared to modern alternatives [S1, S4].

## How it works
**Inputs:**
*   A set of $N$ object points $P_i = (x_i, y_i, z_i)$ representing the 3D scene [S1, S2].
*   Hologram plane dimensions $W \times H$ (pixels) [S3].
*   Wavelength $\lambda$ of the reconstruction light [S3].
*   Distance $z$ from the object plane to the hologram plane (or individual $z_i$ for each point) [S4].

**Outputs:**
*   A complex amplitude distribution $U_h(x,y)$ on the hologram plane, which is subsequently encoded into a phase-only or amplitude-only hologram pattern [S2].

**Data Structures:**
*   **Point Cloud:** An array of structures or tuples containing coordinates $(x_i, y_i, z_i)$ and optionally amplitude $A_i$ and initial phase $\phi_{0,i}$ for each point $i \in [1, N]$ [S2].
*   **Hologram Buffer:** A 2D complex array of size $W \times H$, initialized to zero, storing the accumulated complex amplitude $U_h(x,y)$ [S2].

**Mathematical Model:**
The complex amplitude contribution of a single point source $i$ at hologram pixel $(x,y)$ is calculated using the angular spectrum method or Fresnel approximation. The phase $\phi_i(x,y)$ depends on the distance $r_i$ from the point to the pixel:
$$ \phi_i(x,y) = k r_i + \phi_{0,i} $$
where $k = 2\pi/\lambda$ is the wavenumber and $r_i = \sqrt{(x-x_i)^2 + (y-y_i)^2 + z_i^2}$ [G, S3, unofficial]. The total hologram is the superposition:
$$ U_h(x,y) = \sum_{i=1}^{N} A_i \exp\left(i \phi_i(x,y)\right) $$
[S2, S3].

**Steps:**
1.  **Discretization:** Represent the 3D object as a finite set of object points $P_i$ [S2].
2.  **Propagation:** For each point $P_i$, calculate its complex amplitude distribution on the hologram plane. This is typically done using the Angular Spectrum Method (ASM) or Fresnel diffraction integral [S2, S4].
    *   If using ASM, the propagation is performed in the frequency domain:
        $$ U_{i,h}(x,y) = \mathcal{F}^{-1} \left\{ \mathcal{F}\{ \delta(x-x_i, y-y_i) \} \cdot H_{prop}(u,v) \right\} $$
        where $H_{prop}$ is the transfer function of free space propagation [S4].
    *   Alternatively, direct calculation of the spherical wave phase term is used for each pixel [S3].
3.  **Superposition:** Sum the complex amplitudes of all $N$ points to obtain the total wave surface information distribution $U_h(x,y)$ [S2].
4.  **Occlusion Handling (Optional):** If occlusion is modeled, ignore the backside wavefront contribution when backside and frontside wavefronts overlap [S4]. This requires depth testing or ray casting to determine visibility [S4].
5.  **Encoding:** Encode the complex distribution $U_h(x,y)$ into a format suitable for the Spatial Light Modulator (SLM), such as phase-only encoding (e.g., double-phase method) or amplitude modulation [S2].

**Pseudocode:**
```python
def calculate_point_cloud_cgh(points, hologram_width, hologram_height, wavelength, distance_z):
    """
    Calculate CGH using direct point-wise integration.
    
    Args:
        points: List of tuples (x, y, z, amplitude, phase) for N points.
        hologram_width: Width of hologram in pixels.
        hologram_height: Height of hologram in pixels.
        wavelength: Wavelength of light in meters.
        distance_z: Distance from object plane to hologram plane in meters.
        
    Returns:
        hologram: 2D complex array of size (hologram_height, hologram_width).
    """
    k = 2 * pi / wavelength
    hologram = zeros((hologram_height, hologram_width), dtype=complex)
    
    # Precompute pixel coordinates
    y_coords, x_coords = meshgrid(range(hologram_height), range(hologram_width))
    
    for point in points:
        px, py, pz, amp, phi0 = point
        
        # Calculate distance from point to each hologram pixel
        # Note: In a full implementation, z_i might vary per point. 
        # Here we assume a common distance z or relative depth.
        # If points have individual z_i, replace distance_z with pz.
        # r = sqrt((x - px)^2 + (y - py)^2 + (z - pz)^2)
        
        # Assuming points are at depth z relative to hologram at z=0
        # Or if distance_z is the plane distance, and points are at z_i:
        # Let's assume points are defined in a coordinate system where 
        # hologram is at z=0 and points are at z_i.
        
        # Vectorized distance calculation for all pixels for this point
        dx = x_coords - px
        dy = y_coords - py
        dz = distance_z - pz # Assuming hologram at z=distance_z, point at pz
        
        r = sqrt(dx**2 + dy**2 + dz**2)
        
        # Calculate phase
        phase = k * r + phi0
        
        # Calculate complex amplitude contribution
        # A_i * exp(i * phi_i)
        contribution = amp * exp(1j * phase)
        
        # Superpose
        hologram += contribution
        
    return hologram
```
*Note: The pseudocode above assumes a simplified direct phase calculation. For higher accuracy, the Angular Spectrum Method (ASM) should be used for propagation [S4]. ASM involves FFTs and is more complex to implement from scratch without libraries, but the core logic remains: propagate each point's field and sum.*

**Parameters:**
*   **Wavelength ($\lambda$):** Typically 400-700 nm for visible light [S3].
*   **Sub-hologram size:** In optimized implementations using Look-Up Tables (LUTs) or Wavefront Recording Planes (WRP), the hologram is divided into sub-holograms. The runtime scales quadratically with the sub-hologram size [S3].
*   **Point Density:** The number of points $N$ directly impacts complexity. 2 million points is a common benchmark for performance measurement [S3].

**Edge Cases and Pitfalls:**
*   **Occlusion:** Naive summation does not account for occlusion, leading to "see-through" artifacts. Explicit occlusion handling increases computational cost [S1, S4].
*   **Depth Errors:** Incorrect depth values in captured depth maps cause interference-induced black lines at object boundaries [S4].
*   **Vivid Boundaries:** Abrupt phase variations at interfaces of objects at different depths cause constructive/destructive interference, creating sharp boundaries instead of natural defocus blur [S4].
*   **Hole Distortion:** Holes in objects are distorted by depth differences between the object and background [S4].
*   **Defocus Blur:** Coherent propagation forms Fresnel diffraction patterns, not natural defocus blur, distorting depth perception [S4].

## Subtopics

### Look-Up-Table (LUT) Acceleration
Pre-calculates point contributions for specific depths and reuses them. Reduces computation time significantly but increases memory usage [S1].

### Wavefront Recording Plane (WRP)
Interposes an intermediate plane between the point cloud and hologram plane to reduce propagation distance and complexity. Speeds up generation but introduces approximation errors [S1].

### Convolution-Based Approximation
Approximates point-wise integration as a convolution with a spatially invariant kernel (if lens phase is fixed). Reduces runtime from seconds to milliseconds but sacrifices spatial variance accuracy [S3].

## Operating characteristics
**Time Complexity:**
*   The naive point-wise integration method scales quadratically with the sub-hologram size and linearly with the number of points $N$ [S3].
*   Total complexity is $O(N \cdot W \cdot H)$ for direct calculation [G].
*   With LUTs or WRP, complexity is reduced but depends on the number of pre-calculated entries [S1].

**Memory Complexity:**
*   $O(W \cdot H)$ for the hologram buffer [G].
*   LUT methods require $O(D \cdot W_{sub} \cdot H_{sub})$ memory for pre-calculated tables, where $D$ is the number of depth levels [S1].

**Measured Performance:**
*   **Hardware:** NVIDIA GTX 980 Ti [S3], NVIDIA V100 [S4].
*   **Runtime:** 1 to tens of seconds for 2 million points on GTX 980 Ti, depending on sub-hologram size [S3]. Convolution methods can achieve milliseconds [S3].
*   **Image Quality (nCGH vs DEH):**
    *   512x512 dataset: PSNR 22.5 dB, SSIM 0.756 [S4].
    *   FHD dataset: PSNR 27.1 dB, SSIM 0.889 [S4].
    *   Significantly lower PSNR/SSIM compared to Diffraction-Engineered Holography (DEH) [S4].

**Strengths:**
*   Relatively simple calculations [S1].
*   Can handle real scenes acquired as point clouds [S1].
*   No need for complex polygon mesh processing [S1].

**Limitations:**
*   High computational cost for large scenes [S1].
*   Weak defocus blur and vivid boundaries distort depth perception [S4].
*   Sensitive to depth map errors [S4].
*   Slower than convolution-based methods [S3].

**When to Use:**
*   Small to medium-sized scenes where simplicity is prioritized over speed.
*   Synthetic scenes with known point coordinates.
*   When hardware acceleration (GPU) is available and real-time is not critical.

**When Not to Use:**
*   Real-time applications requiring high resolution and large point counts.
*   Scenes requiring accurate depth cues and natural defocus blur.
*   Applications with noisy or incomplete depth data.

## Background
The point-cloud approach, also known as the object point scattering method, is one of the conventional methods for CGH generation [S1, S2]. It was among the earliest techniques developed for computer-generated holography [S1]. In 2002, T. Shimobab et al. employed this method to construct a 3D diagram using a reflective LCD panel and LED reference light source [S2]. The method is based on the principle of superposition of spherical waves from point sources [S2]. It has been widely studied as a baseline for comparison with more advanced methods like layer-based, polygon-based, and diffraction-engineered holography [S1, S4]. Despite its simplicity, its computational inefficiency and optical artifacts have led to the development of faster and higher-quality alternatives [S1, S4].
