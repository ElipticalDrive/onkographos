# Volumetric Display using Rotating Mirror (VRDM)
Also called: Rotating Mirror Volumetric Display, vdrm optical simulation & encoding

## Overview
VRDM is a volumetric display system that projects 3D voxel data onto a rotating mirror surface, illuminated by surrounding LED screens, to create a stationary 3D image visible to the human eye. It solves the problem of generating a continuous volumetric display without mechanical scanning of the light source itself by using analytical mirror reflection matrices to map 3D coordinates directly to 2D screen pixels per rotation angle. It differs from standard ray marching by avoiding per-pixel ray tracing loops, instead computing pixel overlaps via depth sorting and mirror geometry [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D voxel grid (implicitly defined by the pyramid surface generation or external model), rotation angle $\theta$, and screen configuration.
- Output: A sequence of 2D images (frames) for the surrounding LED screens, encoded as `AngleImage` structs.

**Data Structures:**
- `AngleImage`: A contiguous memory block of 772 bytes.
  - Bytes 0-3: `u32` angle (in degrees or normalized units, mapped to rotation).
  - Bytes 4-771: 192 rows of `RGBH` arrays. Each row is 4 bytes: `R` (u8), `G` (u8), `B` (u8), `H` (u8, representing depth/address).
- `ScreenLinePixels`: An array of `W_PIXELS` (64) optional pixel colors for a single screen line.
- `Screen`: Defined by two 3D points (start and end of the screen edge) and a Z-offset.

**Parameters:**
- `W_PIXELS`: 64 (width of the pyramid surface in pixels).
- `H_PIXELS`: 40 (height of the pyramid surface in pixels).
- `TOTAL_ANGLES`: `W_PIXELS * 8` (256 total angles for a full rotation).
- `MIRROR_OFFSET`: `sqrt(2)` (distance from origin to mirror plane in simulation units).
- `SCREEN_OFFSET`: 0.05 (vertical screen placement offset).
- `SCREEN_Z_OFFSET`: `-1.0 + SCREEN_OFFSET` (horizontal screen placement offset).
- `NUM_SCREENS`: 3 (number of surrounding LED screens).
- `SCREEN_ZOOM`: 1.0 (scaling factor for screen size).

**Steps:**

1. **Generate Pyramid Surface:**
   For each pixel $(x, y)$ in a `W_PIXELS` x `W_PIXELS` grid:
   - Compute center $r = W\_PIXELS / 2$.
   - Compute height metric $h = |x - r| + |y - r|$.
   - If $h \ge H\_PIXELS$, skip.
   - Compute $z = H\_PIXELS - 1 - h$.
   - Assign color based on quadrant relative to center $(r, r)$:
     - $x \ge r, y \ge r$: Gray
     - $x < r, y \ge r$: Red
     - $x < r, y < r$: Green
     - $x \ge r, y < r$: Magenta
   - Store as initial voxel candidates.

2. **Encode Pixels per Angle:**
   Iterate over the angle map generated by `codec.encode()`. For each angle $\theta$:
   - Initialize `pixels` array of size `IMG_HEIGHT` (192 rows).
   - For each screen line, iterate through pixels.
   - Unpack RGBA from the source voxel data.
   - If the alpha channel is zero (`rgba & 0xFFFF_FF00 == 0`), force the computed z-depth to 0 to prevent rendering artifacts from transparent voxels [S1, unofficial].
   - Apply mirror reflection transformation (see Formulas) to map 3D point to 2D screen coordinates.
   - If a pixel position on the screen is already occupied, keep the one with the smaller `p.addr` (closest depth).
   - Store `[r, g, b, p.addr as u8]` in the `RGBH` array.

3. **Mirror 3D Point Transformation:**
   - Apply a 2D rotation matrix to $(x, y)$ coordinates based on the current rotation angle.
   - Apply a fixed 45-degree rotation matrix to $(y, z)$ coordinates to align the point with the mirror plane.
   - Use the mirror reflection matrix $M$ to project the point to the screen coordinates.

**Formulas:**

Mirror reflection matrix in homogeneous coordinates:
$$
M = \begin{bmatrix} \sin^2\theta - \cos^2\theta & -2\sin\theta\cos\theta & 0 \\ -2\sin\theta\cos\theta & \cos^2\theta - \sin^2\theta & 0 \\ 2d\cos\theta & 2d\sin\theta & 1 \end{bmatrix}
$$
where $\theta$ is the mirror angle in radians and $d$ is the mirror offset distance (`MIRROR_OFFSET`).

Rotation matrices for alignment:
$$
MAT\_ROTATE\_X = \begin{bmatrix} \frac{1}{\sqrt{2}} & -\frac{1}{\sqrt{2}} \\ \frac{1}{\sqrt{2}} & \frac{1}{\sqrt{2}} \end{bmatrix}, \quad
MAT\_ROTATE\_X\_REV = \begin{bmatrix} \frac{1}{\sqrt{2}} & \frac{1}{\sqrt{2}} \\ -\frac{1}{\sqrt{2}} & \frac{1}{\sqrt{2}} \end{bmatrix}
$$

    """Compute the 4x4 mirror reflection matrix."""

## Subtopics

### [Helical Display Surface Geometry & Balancing](8512-helical-display-surface-geometry-balancing.md)
Defines the mechanical geometry, structural assembly, and dynamic balancing of a rotating double-helix reflector used in laser-based volumetric displays. It solves the problem of maintaining structural integrity and optical precision at high rotational speeds by minimizing vibration and aerodynamic drag while maximizing stiffness. It sets itself apart from standard rotating mirror systems by using a continuous, axisymmetric double-helix contour that inherently balances centrifugal forces, rather than relying solely on counterweights or rigid flat mirrors.

## Operating characteristics
- **Time Complexity:** $O(N \cdot A \cdot P)$, where $N$ is the number of voxels, $A$ is the number of angles (`TOTAL_ANGLES`), and $P$ is the number of pixels per screen. The depth sorting and mirror transformation are linear with respect to these factors.
- **Memory Complexity:** $O(A \cdot H \cdot W)$ for storing the encoded frames, where $H$ is the number of screen lines (192) and $W$ is the width (64). Each frame is 772 bytes.
- **Measured Performance:** The simulation uses 256 angles and 64x64 pixel resolution. The exact frame rate depends on the hardware, but the analytical approach avoids the overhead of ray marching.
- **Strengths:** Fast rendering due to analytical projection; no per-pixel ray tracing; simple hardware setup with surrounding LEDs.
- **Limitations:** Limited to specific geometries (pyramid/helix); requires precise mechanical alignment; resolution is limited by the number of screens and pixels.
- **When to use:** For educational demonstrations or low-resolution volumetric displays where simplicity and speed are prioritized over high fidelity.
- **When not to use:** For high-resolution, large-scale volumetric displays requiring complex lighting or occlusion handling.

## Background
VRDM was developed by hikaricai as an early-stage volumetric display concept. It was first presented on Hackaday and GitHub in 2024. The project explores the use of rotating mirrors and surrounding LED screens to create a 3D image. It is an unofficial, open-source implementation aimed at hobbyists and researchers interested in volumetric display technologies.
