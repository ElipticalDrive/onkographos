# Volumetric Display using Rotating Mirror (VRDM)

Also called: Rotating Mirror Volumetric Display, Volumetric Display using Rotating Mirror (vdrm) optical simulation & encoding, vdrm optical simulation & encoding

## Overview
Volumetric Display using Rotating Mirror (VRDM) is a simulation and encoding pipeline for a hardware system that projects 3D voxel data onto surrounding LED screens via a rotating mirror to create a stationary volumetric image. It solves the problem of mapping 3D spatial coordinates to 2D screen pixels for multiple angled displays by applying analytical mirror reflection matrices, avoiding the computational cost of per-pixel ray tracing loops [S1, unofficial]. Unlike standard ray marching, VRDM uses direct geometric projection per rotation angle, handling pixel overlaps via depth sorting to ensure correct occlusion [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** 3D voxel data (implicit or explicit), mirror rotation angle $\theta$, mirror offset $d$, screen geometry parameters.
- **Output:** A sequence of 2D images (frames) for each rotation angle, formatted as `AngleImage` structs, ready for display on surrounding LED screens.

**Data Structures:**
1.  **AngleImage:** A contiguous memory block of 772 bytes.
    -   Bytes 0-3: `u32` angle (in degrees or normalized units, mapped from rotation).
    -   Bytes 4-771: 192 rows of `RGBH` arrays. Each row is 4 bytes: `R` (u8), `G` (u8), `B` (u8), `H` (u8, representing depth/address).
    -   Layout: `[angle(4), R, G, B, H, R, G, B, H, ...]` repeated 192 times.
2.  **ScreenLinePixels:** An array of `W_PIXELS` (default 64) optional pixel colors, used during encoding to resolve depth conflicts.
3.  **Screen:** Defined by four corner points in 3D space, derived from `SCREEN_OFFSET`, `SCREEN_Z_OFFSET`, and `SCREEN_Y_OFFSET`.

**Parameters:**
-   `W_PIXELS`: 64 (width of screen resolution).
-   `H_PIXELS`: 40 (height of screen resolution).
-   `MIRROR_OFFSET`: `SQRT(2)` ≈ 1.4142 (distance from origin to mirror plane in simulation units) [S1, unofficial].
-   `SCREEN_OFFSET`: 0.05 (vertical screen placement offset) [S1, unofficial].
-   `SCREEN_Z_OFFSET`: -0.95 (calculated as -1.0 + SCREEN_OFFSET) [S1, unofficial].
-   `SCREEN_Y_OFFSET`: -0.95 (calculated as -1.0 + SCREEN_OFFSET) [S1, unofficial].
-   `NUM_SCREENS`: 3 (number of surrounding LED screens) [S1, unofficial].
-   `TOTAL_ANGLES`: `W_PIXELS * 8` = 512 (total number of rotation steps per revolution) [S1, unofficial].

**Step-by-Step Method:**

1.  **Generate Pyramid Surface (Coordinate Mapping):**
    For each pixel coordinate $(x, y)$ in the screen grid (where $x, y \in [-r, r]$ and $r = W\_PIXELS / 2$):
    -   Compute Manhattan distance from center: $h = |x - r| + |y - r|$.
    -   If $h \ge H\_PIXELS$, skip this pixel (it is outside the pyramid shape).
    -   Compute depth index: $z = H\_PIXELS - 1 - h$.
    -   Assign color based on quadrant relative to center $(r, r)$:
        -   $x \ge r, y \ge r$: Gray.
        -   $x < r, y \ge r$: Red.
        -   $x < r, y < r$: Green.
        -   $x \ge r, y < r$: Magenta.
    -   This creates a base mapping of 3D-like depth $z$ to 2D screen positions.

2.  **Mirror Reflection Transformation:**
    To map a 3D point $(x, y, z)$ to the 2D screen coordinates for a given mirror angle $\theta$:
    -   Apply a 2D rotation matrix to the $(x, y)$ coordinates to align with the mirror's rotational symmetry.
    -   Apply a fixed 45-degree rotation matrix to the $(y, z)$ coordinates to align the depth axis with the mirror plane.
    -   Use the homogeneous mirror reflection matrix $M$ to project the point:
        $$
        M = \begin{bmatrix} \sin^2\theta - \cos^2\theta & -2\sin\theta\cos\theta & 0 \\ -2\sin\theta\cos\theta & \cos^2\theta - \sin^2\theta & 0 \\ 2d\cos\theta & 2d\sin\theta & 1 \end{bmatrix}
        $$
        where $\theta$ is the mirror angle in radians and $d$ is `MIRROR_OFFSET` [S1, unofficial].
    -   The resulting 2D coordinates $(x', y')$ are mapped to screen pixel indices.

3.  **Encode Pixels per Angle:**
    For each angle in the rotation map (from $0$ to `TOTAL_ANGLES`):
    -   Initialize an empty `pixels` array of size `IMG_HEIGHT` (or `W_PIXELS` depending on orientation, typically 192 rows in output).
    -   For each 3D voxel or surface point projected to this angle:
        -   Unpack RGBA color.
        -   Compute the screen address (pixel index) $p.addr$.
        -   If the pixel at $p.addr$ is empty, store `[r, g, b, p.addr as u8]`.
        -   If the pixel already exists, compare depths. Keep the pixel with the smaller $p.addr$ (closest depth to the viewer/mirror) [S1, unofficial].
    -   **Pitfall - Z-depth Zeroing:** If the alpha channel of a pixel is zero (transparent), force the computed $z$-depth to 0 to prevent rendering artifacts from transparent voxels [S1, unofficial].

4.  **Output Assembly:**
    -   Pack the resulting pixels into the `AngleImage` structure.
    -   Repeat for all angles to generate the full volumetric sequence.

**Pseudocode:**

W_PIXELS = 64
H_PIXELS = 40
MIRROR_OFFSET = math.sqrt(2)
SCREEN_OFFSET = 0.05
SCREEN_Z_OFFSET = -1.0 + SCREEN_OFFSET
SCREEN_Y_OFFSET = -1.0 + SCREEN_OFFSET
NUM_SCREENS = 3
TOTAL_ANGLES = W_PIXELS * 8

def mirror_reflection_matrix(theta, d):
    """
    Computes the 3x3 mirror reflection matrix M.
    theta: mirror angle in radians
    d: mirror offset distance (MIRROR_OFFSET)
    """
    sin_t = math.sin(theta)
    cos_t = math.cos(theta)
    sin2 = sin_t * sin_t
    cos2 = cos_t * cos_t
    sin_cos = sin_t * cos_t

    # Note: The source code uses a 4x4 matrix with specific column ordering.
    # Here we implement the 3x3 form for coordinate transformation logic.
    return [
        [sin2 - cos2, -2 * sin_cos, 0],
        [-2 * sin_cos, cos2 - sin2, 0],
        [2 * d * cos_t, 2 * d * sin_t, 1]
    ]

def generate_pyramid_surface():
    """
    Generates the base pyramid surface mapping for a single screen.
    Returns a list of (x, y, z, color) tuples.
    """
    r = W_PIXELS / 2.0
    surface = []
    for x in range(W_PIXELS):

            # Adjust coordinates to be centered around 0 for calculation
            # The source uses |x - r| + |y - r|, implying x,y are 0-indexed pixel coords
            h = abs(x - r) + abs(y - r)
            if h >= H_PIXELS:
                continue
            
            z = H_PIXELS - 1 - h
            
            # Quadrant color assignment
            # Note: Source uses x>=0, y>=0 relative to center? 
            # Source says: (x>=0, y>=0) -> gray. Assuming x,y are shifted to center.
            # Let's use 0-indexed pixel coords relative to center (r,r)
            dx = x - r
            dy = y - r
            
            if dx >= 0 and dy >= 0:
                color = (128, 128, 128) # Gray
            elif dx < 0 and dy >= 0:
                color = (255, 0, 0)     # Red
            elif dx < 0 and dy < 0:
                color = (0, 255, 0)     # Green
            else: # dx >= 0 and dy < 0
                color = (255, 0, 255)   # Magenta
                
            surface.append((x, y, z, color))
    return surface

def encode_vdrm(voxels, mirror_angle):
    """
    Encodes voxels for a specific mirror angle.
    Returns a list of pixel data [r, g, b, addr].
    """
    theta = mirror_angle
    d = MIRROR_OFFSET
    M = mirror_reflection_matrix(theta, d)
    
    # Initialize pixel buffer: 192 rows (H_PIXELS * 3? or fixed 192 as per layout)
    # The layout says 192 rows. Let's assume 192 rows of W_PIXELS width.
    # However, the source code uses ScreenLinePixels with W_PIXELS.
    # We will use a dictionary to handle overlaps by depth.
    pixel_buffer = {} 
    
    for voxel in voxels:
        x, y, z, rgba = voxel
        
        # 1. Apply 2D rotation to (x, y)
        # 2. Apply 45-degree rotation to (y, z)
        # 3. Apply Mirror Matrix M
        
        # Simplified transformation based on source logic:
        # The source applies rotations to align with mirror plane.
        # Let's assume standard 3D point (x,y,z)
        
        # Rotate (x,y) by theta? Or is theta the mirror angle?
        # Source: "Apply 2D rotation matrix to (x, y) coordinates"
        # Then "fixed 45-degree rotation matrix to (y, z)"
        
        # For implementation, we project the 3D point to 2D screen coords.
        # The mirror matrix M transforms (x,y,1) to (x',y',1) in homogeneous coords?
        # The source code uses a 4x4 matrix.
        
        # Let's use the 4x4 matrix from source for accuracy.
        sin_t = -math.sin(theta)
        cos_t = -math.cos(theta)
        sin2 = sin_t * sin_t
        cos2 = cos_t * cos_t
        sin_cos = sin_t * cos_t
        
        # 4x4 Matrix from source [S1, unofficial]
        # Columns:
        # Col 0: (sin2-cos2, -2sin_cos, 0, 2d*cos)
        # Col 1: (-2sin_cos, cos2-sin2, 0, 2d*sin)
        # Col 2: (0, 0, 1, 0)
        # Col 3: (0, 0, 0, 1)
        
        mat_mir = [
            [sin2 - cos2, -2 * sin_cos, 0, 2 * d * cos_t],
            [-2 * sin_cos, cos2 - sin2, 0, 2 * d * sin_t],
            [0, 0, 1, 0],
            [0, 0, 0, 1]

        px = x * mat_mir[0][0] + y * mat_mir[1][0] + z * mat_mir[2][0] + 1 * mat_mir[3][0]

        # Normalize
        if pw == 0:
            continue
        px /= pw
        py /= pw
        pz /= pw
        
        # Map to screen pixel coordinates

        # Assuming linear mapping from simulation units to pixel indices.
        # This part is implementation-specific and not fully detailed in sources.

        screen_x = int(px * W_PIXELS / 2 + W_PIXELS / 2)

        # Check bounds
        if not (0 <= screen_x < W_PIXELS and 0 <= screen_y < H_PIXELS):
            continue
            
        # Depth sorting: use pz as depth. Smaller pz is closer?
        # Source says: "keep the one with smaller p.addr (closest depth)"
        # p.addr is likely the pixel index or a depth value.
        # We use pz as the depth metric.
        
        addr = screen_y * W_PIXELS + screen_x
        
        # Pitfall: Z-depth zeroing
        alpha = rgba & 0xFFFF_FF00
        if alpha == 0:
            depth = 0
        else:
            depth = pz
            
        # Store in buffer, keeping closest depth
        if addr not in pixel_buffer or depth < pixel_buffer[addr][1]:
            pixel_buffer[addr] = (rgba, depth)
            
    # Convert buffer to list of [r, g, b, addr_as_u8]
    # Note: addr_as_u8 is a simplification; source stores p.addr as u8.
    # This implies addr is small or truncated.
    result = []
    for addr, (rgba, depth) in sorted(pixel_buffer.items()):
        r = (rgba >> 16) & 0xFF
        g = (rgba >> 8) & 0xFF
        b = rgba & 0xFF
        # Truncate addr to u8 if necessary, or use depth as addr
        # Source: "store [r, g, b, p.addr as u8]"
        addr_u8 = addr & 0xFF
        result.append([r, g, b, addr_u8])
        
    return result

    # Encode for each angle

        theta = (i / TOTAL_ANGLES) * 2 * math.pi
        pixels = encode_vdrm(pyramid, theta)
        # Pack into AngleImage structure
        # [angle(4), R, G, B, H, ...]

## Operating characteristics
-   **Time Complexity:** $O(N \cdot A)$, where $N$ is the number of voxels and $A$ is the number of angles (`TOTAL_ANGLES`). Each voxel is transformed and projected for each angle.
-   **Memory Complexity:** $O(A \cdot S)$, where $S$ is the screen resolution (192 rows $\times$ 4 bytes). The output is a sequence of frames.
-   **Performance:** The analytical matrix approach avoids per-pixel ray tracing, making it faster than brute-force ray marching for dense volumes. However, it requires pre-computing the mirror transformation for each angle.
-   **Strengths:** Simple hardware implementation (rotating mirror + LEDs), real-time capable with optimized encoding, no need for complex holographic calculations.
-   **Limitations:** Resolution is limited by screen pixel density and mirror rotation speed. Occlusion handling is simplified (depth sorting per pixel), which may cause artifacts in complex scenes.
-   **When to use:** For educational or low-cost volumetric displays where hardware simplicity is prioritized over high-fidelity holography.
-   **When not to use:** For high-resolution, full-color, or viewer-independent holographic displays.

## Background
The VRDM method originates from an open-source project by hikaricai, described as an "early stage" idea for volumetric display using two spinning mirrors, later evolving to version 2.0 with one mirror and three surrounding LED screens [S1, unofficial]. The project includes an emulator and hardware demos, demonstrating the feasibility of using analytical mirror reflection matrices for volumetric projection. It is not a peer-reviewed academic method but a practical engineering implementation [S1, unofficial].
