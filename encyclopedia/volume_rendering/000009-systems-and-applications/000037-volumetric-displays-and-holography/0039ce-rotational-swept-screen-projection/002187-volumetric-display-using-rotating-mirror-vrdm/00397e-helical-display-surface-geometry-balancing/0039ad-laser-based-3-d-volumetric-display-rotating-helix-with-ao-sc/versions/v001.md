# Laser-based 3-D Volumetric Display (Rotating Helix with AO Scanner)

Also called: AO Random-Access Scanner Volumetric Display, Helix-based 3-D Volumetric Display

## Overview
This method projects a laser beam onto a rotating reflective double-helix surface to form discrete 3D volume points (voxels) visible to the naked eye [S1, unofficial]. It solves the limitation of 2D displays by creating physical voxels in real space, providing physiological depth cues (motion parallax, accommodation, convergence) rather than relying on psychological depth cues [S1, unofficial]. Unlike its parent method which focuses on the mechanical geometry and balancing of the helix, this method defines the optical scanning, synchronization, and data addressing required to render the image [S1, unofficial].

## How it works
**Inputs:** Raw 3D coordinates $(x, y, z)$ of the desired voxels; synchronization pulse from a sensor on the helix hub.
**Outputs:** Reflected laser light forming a volumetric image in real space.

**Data Structures:**
*   **Frame Buffer / Memory:** A linear memory array where the $z$-axis (height) is mapped to the memory address (temporal domain). The $x$ and $y$ coordinates are stored as data values at the corresponding memory location [S1, unofficial].
*   **Voxel Address:** Defined by $(x, y, z)$. The system supports an addressability of $4095 \times 4095$ per voxel, with an effective X-Y resolution of $256 \times 256$ [S1, unofficial].

**Parameters (Second Generation):**
*   Helix Diameter: 36 inches [S1, unofficial].
*   Helix Height: 18 inches [S1, unofficial].
*   Rotation Speed: ~10 revolutions per second [S1, unofficial].
*   Refresh Rate: 20 Hz per color [S1, unofficial].
*   Max Voxels per Color: 40,000 [S1, unofficial].
*   Control Card Memory Capacity: 65,000 voxels per color [S1, unofficial].

**Steps:**
1.  **Data Mapping:** Translate raw $(x, y, z)$ coordinates into computer memory such that the $z$-axis is mapped from the spatial domain to a temporal domain. The height of a point determines its location in memory [S1, unofficial].
2.  **Synchronization:** Wait for a synchronization pulse from a sensor located on the hub of the rotating helix [S1, unofficial].
3.  **Addressing:** Upon receiving the pulse, send $x$-$y$ coordinate pairs to the Acousto-Optic (AO) scanner in sequence. The sequence addresses the correct radial position corresponding to the current angular position of the helix [S1, unofficial].
4.  **Scanning:** The AO scanner deflects the laser beam to the specific $(x, y)$ position on the rotating helix surface [S1, unofficial].
5.  **Illumination:** The laser beam illuminates the corresponding discrete points on the reflective helix surface [S1, unofficial].
6.  **Rendering:** Light scatters from the helix surface. To the observer, each voxel appears to emanate from a specific point in real space, forming a true volumetric image [S1, unofficial].

**Pseudocode:**
```python
# Constants
HELIUX_ROTATION_SPEED = 10.0  # revolutions per second
REFRESH_RATE = 20.0           # Hz per color
MAX_VOXELS_PER_COLOR = 40000
MEMORY_SIZE = 65000           # voxels per color

# Data Structure: Frame Buffer
# Memory is indexed by Z-height (temporal domain).
# Each entry contains X and Y coordinates.
class VoxelBuffer:
    def __init__(self, max_voxels):
        self.max_voxels = max_voxels
        self.data = [None] * max_voxels

    def set_voxel(self, z_index, x, y):
        """Map spatial Z to temporal memory index."""
        if 0 <= z_index < self.max_voxels:
            self.data[z_index] = (x, y)

    def get_voxel(self, z_index):
        return self.data[z_index]

def render_volumetric_image(voxel_buffer, sync_pulse_sensor, ao_scanner, laser):
    """
    Main rendering loop for the rotating helix display.
    """
    while True:
        # Step 2: Wait for synchronization
        if not sync_pulse_sensor.wait_for_pulse():
            continue
        
        # The pulse indicates the start of a rotation cycle or a specific angular phase.
        # The system must address voxels based on the current angular position.
        
        # Step 3 & 4: Address and Scan
        # Iterate through the memory mapped by Z (height)
        for z_index in range(voxel_buffer.max_voxels):
            voxel = voxel_buffer.get_voxel(z_index)
            
            if voxel is not None:
                x, y = voxel
                
                # Send X-Y coordinates to the AO scanner
                # The AO scanner deflects the laser beam to the radial position (x,y)
                ao_scanner.set_deflection(x, y)
                
                # Step 5: Illuminate
                # The laser beam hits the helix surface at the correct height (z)
                # and radial position (x,y) determined by the scanner and rotation
                laser.enable()
                
                # Brief pause to allow light scattering/retinal persistence
                # The duration depends on the rotation speed and resolution
                # Not explicitly defined in sources, but implied by refresh rate
                pass 
                
                laser.disable()
        
        # Note: The sources describe the mapping of Z to memory and X/Y to the scanner.
        # The exact timing of the laser pulse relative to the helix rotation angle
        # is handled by the synchronization and the AO scanner's random-access capability.
```

**Edge Cases and Pitfalls:**
*   **Occlusion:** The reflective double-helix structure causes occlusions, constraining the addressable volume to $10" \times 10" \times 15"$ despite the larger physical helix size [S1, unofficial].
*   **Scanner Limits:** The effective volume is constrained by scanner optics limitations [S1, unofficial].
*   **Viewability:** First-generation systems suffered from viewability restrictions due to front projection onto a reflective, opaque helix surface [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The rendering time is dominated by the rotation speed and the number of voxels. With a rotation speed of 10 rev/s and a refresh rate of 20 Hz per color, the system must address up to 40,000 voxels per color within the rotation cycle [S1, unofficial].
*   **Memory Complexity:** Requires a frame buffer capable of storing at least 65,000 voxels per color to support the addressable volume and potential overdraw [S1, unofficial].
*   **Performance:** Second-generation systems achieve 40,000 voxels per color at 20 Hz refresh rate [S1, unofficial].
*   **Strengths:** Provides true 3D physical voxels, allowing group viewing with unrestricted head movement and physiological depth cues (motion parallax, accommodation, convergence, binocular disparity) [S1, unofficial].
*   **Limitations:** Small addressable volume ($10" \times 10" \times 15"$) due to scanner optics and helix occlusion; front projection onto a reflective surface can cause viewability issues; limited to discrete voxels rather than continuous surfaces [S1, unofficial].
*   **When to use:** Military, medical, and commercial applications requiring naked-eye 3D visualization with group viewing capabilities [S1, unofficial].
*   **When not to use:** Applications requiring high-resolution continuous surfaces or large unobstructed viewing volumes [S1, unofficial].

## Background
The concept of laser-generated 3-D volumetric displays was suggested by Rüdiger Hartwig of the University of Stuttgart in the early 1980s [S1, unofficial]. Feasibility was demonstrated by Don Williams of Texas Instruments at the 1988 Society for Information Display (SID) International Symposium in Anaheim, California, showing a laser beam generating simple 3-D geometric figures in a volume defined by a rotating disk [S1, unofficial]. The first-generation prototype was built by the Naval Command, Control and Ocean Surveillance Center (NCCOSC) RDT&E Division in early 1990, with results reported in 1992 [S1, unofficial]. Second-generation development objectives were established in mid-1992, leading to a report published in April 1995 [S1, unofficial]. The system was controlled via PC 386/486 systems with dedicated Volumetric #2 Electronic cards [S1, unofficial].
