# Multi-View and Parallax-Based Rendering
## Overview
Multi-View and Parallax-Based Rendering generates volumetric or holographic imagery by computing multiple distinct perspective views of a scene and displaying them on hardware that separates these views spatially or angularly to create a 3D effect [G]. It differs from single-view volume rendering by explicitly managing view-dependent parallax, and from full wave-optics holographic CGH calculation by typically relying on rasterized or pre-computed view extraction [S1], setting it apart from sibling methods like [Galvanometer Scanner Volume Rendering](5277-galvanometer-scanner-volume-rendering.md) and [Drawing Space Separation (DSS)](5290-drawing-space-separation-dss.md) which use physical scanning or spatial separation.

## Subtopics

### [Multi-view Lenticular Volume Rendering](6636-multi-view-lenticular-volume-rendering.md)
A hardware-accelerated method for generating stereoscopic images of volumetric datasets for display on multi-view lenticular screens without glasses. It computes $N$ distinct perspective views from offset focal spots and composites them into a single interlaced bitmap where each sub-pixel (R, G, B) samples from a different view. Choose this when rendering scalar volumetric data on lenticular displays.

### [Four-View Hologram Compositor](15796-four-view-hologram-compositor.md)
A rendering technique that projects four synchronized views of a 3D scene onto a four-sided acrylic pyramid to create a floating volumetric image visible from all sides. It differs from multi-view lenticular rendering by using physical reflection parity via a pyramid rather than optical lenses, requiring independent rotation and mirroring of each view to correct for the acrylic's reflection properties. Choose this for 360-degree holographic displays using acrylic pyramids.

### Rendering Framework for Autostereoscopic Displays
A pre-processing framework for rendering Computer-Generated Holograms (CGH) on autostereoscopic light-field displays [S1]. It consists of four sequential steps applied to the hologram to acquire reconstruction images corresponding to views from a camera rotating around the scene [S1]. The resolution of these images equals the 2D resolution of the screen [S1]. The steps are: view extraction, where a window with the resolution of the vertical axis of the hologram moves along the horizontal axis to acquire sub-holograms that simulate a pinhole camera view [S1]; suppression of aperture diffraction (apodization) [S1]; back propagation, which numerically reconstructs the view [S1] using only 1D FFTs with a pre-computed kernel due to the same distance [S1]; and colour balancing [S1]. The computational complexity is $O(NM)$ for $V$ views and a hologram with $M \times N$ resolution [S1]. Performance tests on a 3.3 GHz Intel Core i7-5820 CPU with Windows 8 (x64) recorded processing times per view for the 'Dice' dataset (142,903 points) as: View extraction 0.04s, Apodization 0.38s, Back propagation 16.33s, Colour balancing 1.19s [S1]. The system renders on an Holografika HoloVizio 722RC light field display (72 projectors, 70° viewing angle), extracting 70 views with an angular resolution of 1° and a 2D resolution of 1280x768 pixels [S1].

## Background
The concept of multi-view rendering for volumetric displays has evolved alongside autostereoscopic and light-field display technologies [G]. The specific framework for rendering CGHs on autostereoscopic displays was proposed to address the need for high-end 3D visualization of holograms [S1]. The method leverages parallel computing and raster OpenGL graphics to manage the computational load of view extraction and back propagation [S1].
