# Parallel streaming model with GPU-CPU matching


## Overview
This method defines a hardware mapping and concurrency model for multi-GPU rendering systems, ensuring that communication, CPU/GPU data transfers, disk access, and GPU kernel execution occur concurrently [S1, unofficial]. It matches each GPU to a CPU core as part of a parallel streaming model to support multiple GPUs per node [S1, unofficial].

```python
def parallel_streaming_model(gpu_list, cpu_core_list, task_list):
    """
    Implements the parallel streaming model with GPU-CPU matching.
    Matches each GPU to a CPU core and runs concurrent I/O, transfer, and compute.
    """
    pairs = list(zip(gpu_list, cpu_core_list))
    threads = []
    for (gpu, cpu_core), task in zip(pairs, task_list):
        def worker(g, c, t):
            # 1. Disk access and data preparation
            data = read_from_disk(t.path)
            # 2. Data transfer
            gpu_mem = allocate_gpu_memory(g, len(data))
            copy_to_device(g, gpu_mem, data)
            # 3. Kernel execution
            launch_kernel(g, t.config, gpu_mem)
            synchronize(g)
            return copy_to_host(g, gpu_mem)
        # Bind thread to specific CPU core [G]
        t_obj = threading.Thread(target=worker, args=(gpu, cpu_core, task))
        threads.append(t_obj)
        t_obj.start()
    for t_obj in threads:
        t_obj.join()
```

### [Single-User Multi-Object Scheduling](11517-single-user-multi-object-scheduling.md)
This method is a scheduling policy for distributing rendering jobs for a single user viewing multiple objects in a large scene. It solves the problem of unbalanced GPU workload and I/O bandwidth bottlenecks by separating objects into "Heavy" (larger-sized) and "Light" (smaller-sized) tasks. It distinguishes itself from uniform resource assignment by dynamically allocating dedicated GPUs to heavy tasks and shared GPUs to light tasks, thereby reducing long tail latency for large objects and preventing I/O saturation.
