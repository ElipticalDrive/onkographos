# Voxel Space
Also called: 2.5D voxel engine, color map and depth map 3D

## Overview
Voxel Space is a 2.5D rendering technique that generates a pseudo-3D environment by plotting vertical lines whose colors are sampled from a 2D color map and whose initial vertical positions are determined by a 2D depth map [S1, unofficial]. It avoids full 3D volumetric ray-casting or polygon rasterization, instead relying on pre-computed height and color data to simulate perspective [S1, unofficial].

## How it works
**Inputs:**
- A 2D color map storing surface colors.
- A 2D depth map storing vertical height offsets for each column.
- Camera parameters: horizontal position, vertical angle, and altitude.

**Outputs:**
- A 2D frame buffer containing the rendered image.

**Data Structures:**
- `color_map`: 2D array of color values.
- `depth_map`: 2D array of height offsets.
- `math_tables`: Pre-computed tables for rotation and trigonometric values to avoid runtime calculation [S1, unofficial].
- `frame_buffers`: Two frame buffers for double buffering [S1, unofficial].

**Steps:**
1. **Initialize:** Allocate two frame buffers for double buffering [S1, unofficial].
2. **Copy Code to RAM:** Transfer the ARM engine code to RAM for faster execution than cartridge ROM [S1, unofficial].
3. **Calculate Camera State:** Determine camera position and orientation, restricting heights and vertical angles to values stored in `math_tables` [S1, unofficial].
4. **Iterate Columns:** For each column $x$ in the output image:
    a. **Sample Depth:** Read the height offset $h$ from the `depth_map` at the corresponding map coordinate.
    b. **Determine Y-Start:** Calculate the initial y-coordinate for the vertical line based on $h$ and the camera's vertical angle [S1, unofficial].
    c. **Plot Vertical Line:** Iterate through the vertical pixels of the column. For each pixel, sample the color from the `color_map` and plot it at the calculated position [S1, unofficial].
5. **Optimize Horizontal Frequency:** Reduce the frequency of horizontal plane rendering for distant columns to save processing time [S1, unofficial].
6. **Optimize Math Tables:** Use pre-computed values from `math_tables` for rotation and trigonometric calculations instead of computing them at runtime [S1, unofficial].
7. **Optimize Shift Operations:** Use bitwise shift operations (`<<`, `>>`) instead of multiplication or division where possible to speed up calculations [S1, unofficial].
8. **Optimize Inlining:** Replicate and modify the main render routine for each angle rendering to avoid function call overhead [S1, unofficial].
9. **Optimize Background Mode:** Use GBA Background Mode 5 to decrease resolution and facilitate frame buffer switching [S1, unofficial].
10. **Optimize Scrolling:** Use GBA background scaling and scrolling features to render "intra-frames" between full frame renders to improve perceived fluidity [S1, unofficial].

```python
    # Optimization: Code is assumed to be in RAM
    # Optimization: Use GBA Background Mode 5
    
    # Pre-calculate camera constants from math_tables
    # Limits camera height and angle to stored values
    cam_cos = math_tables[camera_angle]
    cam_sin = math_tables[camera_angle + 1]
    
    # Double buffering setup
    active_buffer = 0
    inactive_buffer = 1
    
    # Map dimensions from source code snippet
    map_width = 1024
    map_height = 1024
    
    for x in range(frame_width):
        # Optimization: Horizontal plane render frequency decreases with distance
        # Skip or simplify calculations for far columns
        distance = abs(x - frame_width // 2)
        if distance > 200:  # Threshold for far columns
            continue
            
        # Sample depth map
        # Map coordinate calculation depends on camera position and rotation
        map_x = (x + camera_angle) % map_width
        height_offset = depth_map[map_x]
        
        # Calculate initial y-coordinate
        # y_start is derived from height_offset and camera vertical angle
        y_start = height_offset + camera_altitude
        
        # Plot vertical line
        for y in range(height_offset):
            # Sample color from color map
            color = color_map[map_x, y]
            
            # Plot pixel
            frame_buffer[x][y_start + y] = color
            
    # Optimization: Use scrolling for intra-frames
    # This is handled by hardware features, not explicit code steps
    
    # Swap buffers
    active_buffer = inactive_buffer
    inactive_buffer = active_buffer
```

**Parameters:**
- `math_tables`: Size and content depend on the required precision and range of camera angles. Specific sizes are not given [S1, unofficial].

**Edge Cases and Pitfalls:**
- Simple calculations are excessive for the GBA ARM CPU, requiring significant optimization for a good frame rate [S1, unofficial].
- Camera heights and vertical angles are limited to those stored in the `math_tables` [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not explicitly defined, but heavily optimized for constant-time lookups using pre-computed tables and bitwise operations [S1, unofficial].
- **Memory Complexity:** Requires storage for color map, depth map, and math tables. Specific memory usage is not given [S1, unofficial].
- **Measured Performance:** Designed for the GameBoy Advance ARM CPU. Without optimizations, frame rates are poor. With optimizations (RAM code, math tables, shift operations), a "decent frame rate" is achieved [S1, unofficial].
- **Scaling:** Performance degrades if camera angles or heights exceed the pre-computed `math_tables` range [S1, unofficial].
- **Strengths:** Fast rendering on limited hardware; simple implementation; good visual result for 2.5D games.
- **Limitations:** Limited to 2.5D perspective; camera movement restricted to pre-computed angles/heights; not suitable for full 3D navigation.
- **When to use:** When targeting hardware with limited processing power (e.g., GBA) and a 2.5D perspective is acceptable.
- **When not to use:** When full 3D navigation or dynamic lighting is required.

## Background
Voxel Space was originally developed by NovaLogic for the game *Comanche* [S1, unofficial]. The technique was later reverse-engineered and implemented for the GameBoy Advance [S1, unofficial]. The technology may still be patented in some countries [S1, unofficial].
