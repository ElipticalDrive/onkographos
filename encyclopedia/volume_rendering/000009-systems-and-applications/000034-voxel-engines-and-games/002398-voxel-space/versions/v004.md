# Voxel Space
Also called: 2.5D voxel engine, color map and depth map 3D

## Overview
Voxel Space is a 2.5D rendering technique that generates a pseudo-3D environment by plotting vertical lines whose colors are sampled from a 2D color map and whose vertical positions are determined by a 2D depth map [S1, unofficial]. It differs from full 3D voxel engines by avoiding volumetric ray-casting or polygon rasterization, instead relying on pre-computed height and color data to simulate perspective [S1, unofficial].

## How it works
**Inputs:**
- A 2D color map (texture) storing surface colors.
- A 2D depth map (height map) storing vertical offsets for each column.
- Camera parameters: horizontal position, vertical angle, and altitude.

**Outputs:**
- A 2D frame buffer containing the rendered image.

**Data Structures:**
- `color_map`: 2D array of color values. Dimensions are not explicitly defined in the source but implied to match the map resolution [S1, unofficial].
- `depth_map`: 2D array of integer or fixed-point values representing height offsets.
- `math_tables`: Pre-computed tables for rotation and trigonometric functions to avoid runtime calculation [S1, unofficial].

**Steps:**
1. **Initialize Frame Buffer:** Allocate two frame buffers to allow double buffering [S1, unofficial].
2. **Calculate Camera State:** Determine the current camera position and orientation. Limit camera heights and vertical angles to values present in the pre-computed `math_tables` [S1, unofficial].
3. **Iterate Columns:** For each column $x$ in the output image:
    a. **Sample Depth:** Read the height offset $h$ from the `depth_map` at the corresponding map coordinate.
    b. **Determine Y-Start:** Calculate the initial y-coordinate for the vertical line based on $h$ and the camera's vertical angle [S1, unofficial].
    c. **Plot Vertical Line:** Iterate through the vertical pixels of the column. For each pixel, sample the color from the `color_map` and plot it at the calculated position [S1, unofficial].
4. **Optimization - Horizontal Plane Frequency:** Reduce the frequency of horizontal plane rendering for distant columns to save processing time [S1, unofficial].
5. **Optimization - Code Placement:** Copy the ARM engine code to RAM for faster execution compared to running from cartridge ROM [S1, unofficial].
6. **Optimization - Math Tables:** Use pre-computed values from `math_tables` for rotation and trigonometric calculations instead of computing them at runtime [S1, unofficial].
7. **Optimization - Shift Operations:** Use bitwise shift operations (`<<`, `>>`) instead of multiplication or division where possible to speed up calculations [S1, unofficial].
8. **Optimization - Inlining:** Replicate and modify the main render routine for each angle rendering to avoid function call overhead [S1, unofficial].
9. **Optimization - Background Mode:** Use GBA Background Mode 5 to decrease resolution and facilitate frame buffer switching [S1, unofficial].
10. **Optimization - Scrolling:** Use GBA background scaling and scrolling features to render "intra-frames" between full frame renders to improve perceived fluidity [S1, unofficial].

## Subtopics

### Cascaded Voxel Volumes
A method that divides the voxel space into cascaded volumes to handle large scenes. It differs from Voxel Space by supporting full 3D navigation and larger scales, whereas Voxel Space is a 2.5D technique limited by its reliance on pre-computed maps [4637-cascaded-voxel-volumes.md]. Choose Cascaded Voxel Volumes for large-scale 3D environments; choose Voxel Space for constrained 2.5D perspectives with limited hardware resources.

## Operating characteristics
- **Time Complexity:** Not explicitly defined, but heavily optimized for constant-time lookups using pre-computed tables and bitwise operations [S1, unofficial].
- **Memory Complexity:** Requires storage for color map, depth map, and math tables. Specific memory usage is not given [S1, unofficial].
- **Measured Performance:** Designed for the GameBoy Advance ARM CPU. Without optimizations, frame rates are poor. With optimizations (RAM code, math tables, shift operations), a "decent frame rate" is achieved [S1, unofficial].
- **Scaling:** Performance degrades if camera angles or heights exceed the pre-computed `math_tables` range [S1, unofficial].
- **Strengths:** Fast rendering on limited hardware; simple implementation; good visual result for 2.5D games.
- **Limitations:** Limited to 2.5D perspective; camera movement restricted to pre-computed angles/heights; not suitable for full 3D navigation.
- **When to use:** When targeting hardware with limited processing power (e.g., GBA) and a 2.5D perspective is acceptable.
- **When not to use:** When full 3D navigation or dynamic lighting is required.

## Background
Voxel Space was originally developed by NovaLogic for the game *Comanche* [S1, unofficial]. The technique was later reverse-engineered and implemented for the GameBoy Advance by Juan Manuel Vázquez [S1, unofficial]. The technology may still be patented in some countries [S1, unofficial].
