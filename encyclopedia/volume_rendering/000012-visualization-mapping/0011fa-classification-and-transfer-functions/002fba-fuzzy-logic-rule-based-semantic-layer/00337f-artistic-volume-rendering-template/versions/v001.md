# Artistic Volume Rendering Template

Also called: Artistic Style Rendering

## Overview
A direct volume rendering technique that maps volumetric data attributes to visual artistic styles using fuzzy-logic rules, allowing for selective and gradual application of rendering effects [S1]. It differs from standard volume rendering by decoupling color evaluation into prioritized "styles" that are composited like layers in image editing software, and from sibling semantic methods by relying on shader templates parameterized by shaded sphere images rather than complex semantic models or analogies [S1].

## How it works
**Inputs:** Volumetric dataset, fuzzy logic rule outputs (defuzzified floating-point values for each style), style transfer functions (sets of images of shaded spheres), and a priority list for styles.
**Outputs:** Final pixel color for each viewing ray.

**Data Structures:**
*   **Style Transfer Function:** A collection of images representing shaded spheres. Each image is indexed by the surface normal of the current sample in eye-space.
*   **Defuzzified Values:** A set of floating-point numbers, one per style, representing the degree to which the current sample belongs to that style.

**Steps:**
1.  Cast viewing rays through the volume at equidistant sample positions.
2.  For each sample position, evaluate the opacity transfer function to determine visibility.
3.  If opacity is greater than zero, evaluate the fuzzy logic rules to obtain a defuzzified floating-point value for each artistic style.
4.  Determine the normal of the current sample in eye-space.
5.  Use this normal to index the corresponding image in the style transfer function for each active style.
6.  Retrieve the color for each style from the indexed sphere image.
7.  Composite the colors of all active styles from bottom to top based on their assigned priority, following standard image manipulation compositing schemes (e.g., "over" operator) [S1].

**Formulas:**
*   **Color Retrieval:** $C_{style} = \text{Lookup}(\text{StyleImage}, \mathbf{n}_{eye})$, where $\mathbf{n}_{eye}$ is the sample normal in eye-space.
*   **Compositing:** Styles are composited sequentially. If style $A$ has higher priority than style $B$, $A$ is composited over $B$. The final color depends on this priority order [S1].

**Parameters:**
*   **Style Transfer Function Images:** Not given in the sources.
*   **Priority List:** Defined by the user or fuzzy rules.

**Edge Cases and Pitfalls:**
*   **Compositing Order:** The final color is highly sensitive to the priority order of styles. If style $A$ is prioritized over style $B$, $A$'s color dominates; if $B$ is prioritized over $A$, $B$'s color dominates [S1].
*   **Normal Indexing:** The normal must be correctly transformed to eye-space to index the sphere images accurately [S1].

**Pseudocode:**
```python
def artistic_volume_rendering(ray, volume, styles, priorities):
    # ray: object with origin, direction, and length
    # volume: volumetric dataset
    # styles: list of style objects, each containing a sphere_image and defuzzified_value
    # priorities: list of style indices sorted by priority (highest first)
    
    final_color = (0, 0, 0, 0)
    
    # Cast ray through volume
    for t in range(0, ray.length, step_size):
        sample_pos = ray.origin + ray.direction * t
        sample_value = volume.sample(sample_pos)
        
        # Evaluate opacity
        opacity = opacity_transfer_function(sample_value)
        
        if opacity > 0:
            # Get normal in eye-space
            normal_eye = get_normal_in_eye_space(sample_pos)
            
            # Collect colors for all styles
            style_colors = []
            for style in styles:
                # Index sphere image by normal
                color = style.sphere_image.lookup(normal_eye)
                # Apply defuzzified value (weight)
                weighted_color = color * style.defuzzified_value
                style_colors.append(weighted_color)
            
            # Composite styles based on priority
            # Priorities is a list of indices, highest priority first
            for idx in priorities:
                style_color = style_colors[idx]
                # Simple alpha compositing: result = src + dst * (1 - src_alpha)
                # Assuming style_color is RGBA
                final_color = composite_over(style_color, final_color)
                
    return final_color
```

## Subtopics

### Flat Rendering Mode Template
Extends the artistic volume rendering template to emphasize spatial relations or hide structures by ignoring lower-priority regions [S1]. Each style has a priority, and higher-priority regions overdraw lower-priority ones [S1]. Along a viewing ray, common compositing is performed until a region of higher priority is reached. When entering a higher-priority region at position $x_i$, the ray color $c_r(x_i)$ is updated using the formula $c_r(x_i) = c_r(x_{i-1}) \times (1 - p_f)$, where $x_{i-1}$ is the previous sample position and $p_f$ is the flatness parameter [S1]. The flatness parameter $p_f$ controls the trade-off between showing spatial relationships and showing important regions: $p_f=0$ results in common volume rendering, while $p_f=1$ always shows regions with the highest priority [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples along each ray, plus the cost of fuzzy rule evaluation and style compositing per sample.
*   **Memory Complexity:** Depends on the number of styles and the size of the sphere images used in style transfer functions.
*   **Strengths:** Allows for intuitive, linguistically defined visual styles; supports gradual and selective application of effects; leverages hardware acceleration for fuzzy logic arithmetic [S1].
*   **Limitations:** Compositing order significantly affects the result; requires careful tuning of style priorities and flatness parameters [S1].
*   **When to use:** When illustrative quality and semantic control over visual styles are more important than photorealism.
*   **When not to use:** When precise quantitative analysis of data values is required, or when performance is critical and fuzzy logic overhead is prohibitive.

## Background
Introduced by Rautek et al. in 2008 as part of their work on interaction-dependent semantics for illustrative volume rendering [S1]. It builds on the concept of fuzzy-logic rule-based semantic layers to provide a flexible framework for artistic volume rendering [S1].
