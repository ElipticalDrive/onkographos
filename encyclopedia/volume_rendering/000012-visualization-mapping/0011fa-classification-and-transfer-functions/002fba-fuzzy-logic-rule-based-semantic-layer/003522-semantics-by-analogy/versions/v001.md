# Semantics by Analogy

Also called: brushing-based membership function specification

## Overview
Semantics by Analogy is a method for specifying semantic mappings in volume rendering where the interpretation of data values (fuzzy membership functions) is defined through analogy, i.e., by brushing on renderings of the properties of interest [S1]. Unlike systems that specify mapping in an abstract data space (e.g., via brushing in linked abstract representations) or dual-domain interaction which links spatial domain with transfer function domain, this method allows mapping specification with brushing on a more direct data representation by visualizing attributes of interest in an intermediate domain (semantic-property image) [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A raycasting shader program containing semantic data properties (e.g., volume z-coordinate, normal, sparseness) tagged for dynamic mapping [S1].
*   **Output:** A visualization where data values are mapped to visual attributes (color, opacity, sparseness parameters) via fuzzy visualization rules [S1].

**Data Structures:**
*   **Semantic-Property Image:** A rendered image where pixels represent the values of specific semantic data properties (e.g., a 2D projection or slice of the volume's z-coordinate) [S1].
*   **Membership-Function Texture:** A 1D texture (or histogram) representing the fuzzy membership function for a semantic property. The domain corresponds to the range of the semantic property's visualized values (e.g., color space or normalized coordinate), and the codomain is the membership value in $[0, 1]$ [S1].

**Steps:**
1.  **Render Semantic-Property Image:** The system renders images of the data properties (semantic data properties) so that users can define semantics by analogy [S1]. This involves generating a visual representation of the property (e.g., mapping the z-coordinate to a grayscale or color gradient) [S1].
2.  **Brushing Interaction:** The user brushes values of interest in the rendered visualization [S1].
3.  **Sampling:** Sample the color value $C_{sample}$ at the cursor location in the source semantic-property image [S1].
4.  **Mapping:** Map the sampled color value $C_{sample}$ to the domain of the membership function. This involves determining the index or position in the membership-function texture corresponding to the visualized value of $C_{sample}$ [S1].
5.  **Increment/Decrement:**
    *   If the brushing mode is **additive**, increment the membership-function value at the corresponding location in the membership-function texture by a fixed amount (e.g., 1) [S1].
    *   If the brushing mode is **subtractive**, decrement the membership-function value at the corresponding location [S1].
6.  **Adaptive Normalization (Optional):** If adaptive mode is enabled, normalize the membership function so that the area below the function equals one. This ensures the function represents a normalized probability distribution of brushed color values, causing the function to shift to the recently marked data range [S1].
    *   Let $M[i]$ be the membership value at index $i$.
    *   Calculate the total area $A = \sum M[i]$.
    *   Update $M[i] \leftarrow M[i] / A$ for all $i$ [S1].
7.  **Visual Feedback:** Generate a membership-function image by mapping the color values of the semantic-property image to the corresponding membership-function values. This creates a gray-value mask that provides visual feedback about the current membership function [S1].

**Parameters:**
*   **Brushing Mode:** Can be additive (adaptive or non-adaptive) or subtractive [S1].
*   **Adaptive Mode:** If true, normalization is applied after each brush stroke. If false, normalization is skipped, affecting only the brushed range [S1].

**Pseudocode:**
```python
def brush_on_semantic_property(semantic_property_image, membership_function_texture, cursor_pos, mode, adaptive):
    """
    Update the membership function based on user brushing on a semantic property image.
    
    Args:
        semantic_property_image: 2D array of color values representing the semantic property.
        membership_function_texture: 1D array representing the membership function values.
        cursor_pos: (x, y) tuple indicating the cursor location in the semantic_property_image.
        mode: 'add' or 'sub' indicating the brushing operation.
        adaptive: boolean indicating whether to normalize the membership function.
        
    Returns:
        Updated membership_function_texture.
    """
    # Step 3: Sample the color value at the cursor location
    color_value = semantic_property_image[cursor_pos.y][cursor_pos.x]
    
    # Step 4: Map the sampled color value to the domain of the membership function
    # Assuming the semantic property image is a direct visualization of the property domain
    # and the membership function texture is indexed by the same domain.
    # For example, if the property is normalized to [0,1] and mapped to color,
    # we need to reverse-map the color to the domain index.
    # This step depends on the specific visualization mapping used in Step 1.
    domain_index = map_color_to_domain_index(color_value)
    
    # Step 5: Increment or Decrement the membership function value
    if mode == 'add':
        membership_function_texture[domain_index] += 1.0
    elif mode == 'sub':
        membership_function_texture[domain_index] -= 1.0
        
    # Step 6: Adaptive Normalization
    if adaptive:
        total_area = sum(membership_function_texture)
        if total_area > 0:
            for i in range(len(membership_function_texture)):
                membership_function_texture[i] /= total_area
                
    return membership_function_texture

def generate_visual_feedback(semantic_property_image, membership_function_texture):
    """
    Generate a visual feedback mask based on the current membership function.
    
    Args:
        semantic_property_image: 2D array of color values.
        membership_function_texture: 1D array representing the membership function values.
        
    Returns:
        2D array of grayscale values representing the visual feedback mask.
    """
    feedback_mask = np.zeros_like(semantic_property_image)
    for y in range(semantic_property_image.shape[0]):
        for x in range(semantic_property_image.shape[1]):
            color_value = semantic_property_image[y][x]
            domain_index = map_color_to_domain_index(color_value)
            membership_value = membership_function_texture[domain_index]
            feedback_mask[y][x] = membership_value
    return feedback_mask
```

**Edge Cases and Pitfalls:**
*   **Precision:** The mapping from color value to domain index must be consistent between the rendering of the semantic-property image and the membership-function texture lookup [S1].
*   **Boundaries:** The domain of the membership function must cover the full range of values visualized in the semantic-property image [S1].
*   **Degenerate Input:** If the semantic-property image has uniform color, brushing will affect only one index in the membership function [S1].

*   **Strengths:** Allows domain experts to create interactive illustrations on an abstract level; direct visual assignment of meaning to data ranges; adaptive brushing permits rapid exploration of different data ranges [S1].
*   **Limitations:** Relies on the user's ability to interpret the semantic-property image; requires dynamic shader generation for rule evaluation [S1].
*   **When to use:** When a domain expert needs to define semantic mappings intuitively through visual analogy.
*   **When not to use:** When precise, programmatic control over the mapping is required without user interaction.

## Background
Semantics by Analogy was introduced by Zachow et al. in 2011 [S1]. It is part of a framework for semantics-driven visualizations that uses fuzzy-logic rule-based semantic layers [S1]. The method was developed to allow domain experts to define data semantics by brushing on visualizations of data properties, rather than in abstract data spaces [S1].
