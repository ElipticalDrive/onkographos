# Linear Look-up Table Classification

Also called: Histogram-based classification, Nearest neighbor classification, VolPack Lookup Table Classification, vpRamp, vpSetClassifierTable

## Overview
Linear look-up table classification maps voxel intensity values to material composition percentages using a pre-calculated linear table [S1, unofficial]. It solves the problem of assigning physical properties to discrete voxel data by treating classification as a nearest-neighbor decision based on density peaks [S1, unofficial]. Unlike [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md) or [Piecewise Linear Interpolation (Lookup Table)](2643-piecewise-linear-interpolation-lookup-table.md) which allow arbitrary opacity curves, this method enforces a strict linear ordering of materials, making it computationally simple but restricted to scenarios where materials are distinct and adjacent in density space [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset where each voxel has one or more scalar fields (e.g., density, T1/T2 MRI values) [S1, unofficial][S2].
*   **Output:** For each voxel, material percentage values mapped through the look-up table [S1, unofficial]. If multiple fields are used, the final opacity is the product of the values retrieved from their respective tables [S2].

**Data Structures:**
The core data structure is a linear look-up table (LUT) [S1, unofficial].
*   **VolPack Implementation:** The table is a contiguous array of floats [S2].
*   **Indexing:** The voxel field value (e.g., intensity) serves as the index into the table [S2].
*   **Table Size:** Defined in bytes, not number of entries [S2].
*   **Association:** Tables are associated with specific voxel fields via a parameter number and field index [S2].

**Prerequisites (Conditions for Correctness):**
1.  Each material corresponds to a known, distinct density value [S1, unofficial].
2.  Each voxel contains no more than two materials [S1, unofficial].
3.  If a voxel contains two materials, their densities must follow each other in the specific order defined by the linear table [S1, unofficial].

**Algorithm Steps:**

1.  **Histogram Analysis:** Analyze the image histogram to identify peaks, which represent the centers of the density regions for the materials [S1, unofficial].
2.  **Table Initialization:** Create a piecewise linear ramp to define the table values [S2]. Define `ramp_x` coordinates (table indices) corresponding to the density boundaries or centers [S2]. Define `ramp_y` coordinates (values) representing the desired material percentage or opacity at those indices [S2]. Linearly interpolate values between the `ramp_x` points [S2].
3.  **Table Association:** Associate the initialized table with the specific voxel field used for classification using `vpSetClassifierTable` [S2].
4.  **Classification (Runtime):** For each voxel, retrieve the value from the designated field [G]. Use this value to index into the look-up table [G]. Retrieve the material percentage value from the table [G]. If multiple fields are used, multiply the retrieved values from their respective tables to determine the final opacity [S2].
5.  **Thresholding:** Apply a minimum opacity threshold using `vpSeti` with `VP_MIN_VOXEL_OPACITY` to discard transparent voxels [S2].

**Pseudocode:**

```python
def vp_ramp(array, num_points, ramp_x, ramp_y):
    """Initializes a lookup table with piecewise linear ramps [S2].
    Note: VolPack's vpRamp accepts a stride parameter for non-contiguous layouts."""
    for i in range(num_points - 1):
        x0, x1 = ramp_x[i], ramp_x[i + 1]
        y0, y1 = ramp_y[i], ramp_y[i + 1]
        # Fill indices from x0 up to (but not including) x1
        for idx in range(x0, x1):
            if x1 == x0:
                array[idx] = y0
            else:
                t = (idx - x0) / (x1 - x0)
                array[idx] = y0 + t * (y1 - y0)
        # Explicitly set the endpoint to avoid off-by-one errors
        array[x1] = y1

def classify_voxel(voxel_intensity, lookup_table, min_opacity=0.0):
    """Classifies a single voxel using the lookup table [S2]."""
    idx = int(voxel_intensity)
    if idx < 0:
        idx = 0
    elif idx >= len(lookup_table):
        idx = len(lookup_table) - 1
    material_percentage = lookup_table[idx]
    if material_percentage < min_opacity:
        return 0.0
    return material_percentage

# Example usage matching VolPack documentation
scalar_table = [0.0] * 256
scalar_ramp_x = [0, 24, 255]
scalar_ramp_y = [0.0, 1.0, 1.0]
vp_ramp(scalar_table, len(scalar_ramp_x), scalar_ramp_x, scalar_ramp_y)
```

**Edge Cases and Pitfalls:**
*   **Ordering Violation:** The method fails if materials do not follow the linear ordering in density [S1, unofficial]. For example, at an air-bone interface, soft tissue may appear between air and bone in density, violating the adjacency criteria required for the linear table [S1, unofficial].
*   **Multi-Material Voxels:** The method assumes voxels contain no more than two materials [S1, unofficial]. Voxels with three or more materials will be misclassified [S1, unofficial].
*   **Memory Management:** In VolPack, the lookup table memory is never deallocated by the library, even if the rendering context is destroyed [S2].

## Subtopics

### Multi-variable Scatter-plot Classification
This variant extends linear look-up table classification to multiple image parameters (e.g., T1 and T2 weighted MRI densities) [S1, unofficial]. Instead of a 1D histogram, it uses a 2D scatter-plot (histogram of two inputs) to locate clusters representing materials in a 2D space [S1, unofficial]. Classification is performed using a nearest-neighbor decision function where the distance is the length of the chord joining the center of each 2D region with the 2D point corresponding to the voxel's parameters [S1, unofficial]. This allows for better separation of materials that overlap in a single density dimension but are distinct in multi-parametric space [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:** Not given in the sources.
**Measured Performance:** Not given in the sources.
**Scaling:** Not given in the sources.
**Strengths and Limitations:** Simple to implement and computationally efficient for data with distinct, non-overlapping density peaks (e.g., neurological CT) [S1, unofficial]. Cannot handle materials with overlapping density distributions or complex interfaces (e.g., air-bone-soft tissue) without manual intervention or carving [S1, unofficial]. Requires strict ordering of materials [S1, unofficial].
**When to Use:** Use for datasets where materials have distinct, known density values and voxels contain at most two materials [S1, unofficial].
**When Not to Use:** Do not use for datasets with significant partial volume effects involving three or more materials [S1, unofficial]. Do not use when materials have overlapping density ranges that cannot be resolved by a simple linear ordering [S1, unofficial].

## Background
**Origin:**
The method was described in the context of volumetric rendering of medical data, specifically for stereotactic neurosurgery planning [S1, unofficial]. It is also implemented in the VolPack library, a standard tool for volume rendering [S2].

**History and Development:**
The technique is based on the principle of nearest-neighbor classification using histogram analysis [S1, unofficial]. Direct volume rendering techniques are not as sensitive to errors in classification as polygonal surface rendering methods [S1, unofficial]. The VolPack implementation provides utility functions like `vpRamp` to facilitate the creation of these tables [S2].

**Where it is Used:**
*   Neurological CT data visualization [S1, unofficial].
*   Applications requiring fast, simple classification of scalar fields [S2].
