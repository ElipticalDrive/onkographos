# Post-classification Transfer Function Sampling

Also called: 1D/2D Transfer Function, Post-classification, TF Lookup, Transfer Function Mapping

## Overview
Post-classification Transfer Function Sampling is a volume rendering technique where scalar values are first interpolated from the volume texture during ray casting, and then mapped to colors and opacity through transfer functions (TFs) [S3]. Unlike pre-classification, which applies the TF to grid points before interpolation, post-classification maintains high-frequency details and produces sharp edges by applying the nonlinear classification function to continuous sample values [S2, unofficial][S3][S8]. It is distinct from pre-classification in its handling of high-frequency artifacts: while pre-classification suppresses high-frequency information (resulting in blurred images), post-classification maintains all high frequencies but is prone to aliasing and striping artifacts if the sampling rate is insufficient [S3].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume texture containing scalar values (e.g., density/intensity) and optionally pre-computed gradient magnitudes.
*   **Output:** A final image with color and opacity determined by the transfer function lookup.

**Data Structures:**
The transfer function is implemented as a pre-sampled texture (LUT) [S2, unofficial].
*   **1D TF Texture:** Dimensions $256 \times 1 \times 1$, format `R8G8B8A8Unorm` [S2, unofficial]. Maps scalar density to RGBA.
*   **2D TF Texture:** Dimensions $256 \times 64 \times 1$, format `R8G8B8A8Unorm` [S2, unofficial]. Maps (density, gradient magnitude) to RGBA.

**Steps:**
1.  **Ray Casting:** Cast a ray through the volume.
2.  **Interpolation:** Sample the volume texture at the current ray position to obtain the scalar value $v$ (density) and, if using 2D TF, the gradient magnitude $g = \|\nabla f(\mathbf{x})\|$ [S1, unofficial].
3.  **TF Lookup:**
    *   For 1D TF: Sample the 1D texture at coordinate $v$ to retrieve base color $C_{base}$ and opacity $\alpha$ [S2, unofficial].
    *   For 2D TF: Use the pair $(v, g)$ as coordinates to sample the 2D texture, returning a `vec4` containing color and opacity [S1, unofficial].
4.  **Accumulation:** Use the retrieved optical properties in the standard volume rendering integral (e.g., front-to-back compositing).

**Pseudocode:**
```python
# Assuming standard front-to-back volume rendering loop
# volume_texture: 3D texture holding scalar values and pre-computed gradients
# tf_1d: 1D texture (256x1x1, R8G8B8A8)
# tf_2d: 2D texture (256x64x1, R8G8B8A8)
# use_2d_tf: boolean flag

for sample in ray_samples:
    # Step 1 & 2: Interpolate volume data
    # v is the scalar density, g is the gradient magnitude
    v = sample_volume_scalar(volume_texture, sample.position)
    g = sample_volume_gradient_magnitude(volume_texture, sample.position)
    
    # Step 3: Post-classification lookup
    if use_2d_tf:
        # Map (density, gradient) to RGBA
        # Coordinates are normalized to [0,1] based on texture dimensions
        # Density range typically [0, 1], Gradient range [0, 1] (normalized)
        color_rgba = texture(tf_2d, vec2(v, g))
    else:
        # Map density to RGBA
        color_rgba = texture(tf_1d, vec2(v, 0.5)) # 0.5 is dummy Y coord for 1D texture
    
    alpha = color_rgba.a
    color = color_rgba.rgb
    
    # Step 4: Accumulation (standard front-to-back)
    # c_out = c_in + alpha * color * (1 - c_alpha)
    # a_out = a_in + alpha * (1 - a_in)
    pass
```

**Parameters:**
*   **TF Texture Size:** 1D: $256 \times 1 \times 1$; 2D: $256 \times 64 \times 1$ [S2, unofficial].
*   **Format:** `R8G8B8A8Unorm` [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Striping Artifacts:** Post-classification maintains all high frequencies but introduces "striping" artifacts in the final images if the sampling rate is insufficient [S3].
*   **Aliasing:** Prone to aliasing due to the nonlinear TF applied after interpolation [S2, unofficial][S3][S8].

## Subtopics

### 3D Pre-integrated Transfer Function
A variant where a 3D texture-based transfer function is used during optical property accumulation [S4, unofficial]. It stores the function in a 3D texture and accesses it using floating-point coordinates (interpolated values) [S4, unofficial]. It minimizes the 3D texture size to fit as much data as possible in the texture cache, balancing rendering quality and cache efficiency [S4, unofficial]. It allows maintaining constant brightness and provides better rendering quality compared to standard transfer functions when using adaptive sampling steps [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by texture lookups (1 or 2) per sample point. Faster than analytical TF evaluation but requires memory bandwidth for texture sampling.
*   **Memory Complexity:** Requires storage for the TF texture(s). 1D TF: $256 \times 4$ bytes. 2D TF: $256 \times 64 \times 4$ bytes [S2, unofficial].
*   **Strengths:** Maintains high-frequency details and sharp edges [S2, unofficial][S3][S8]. Boundary emphasis via gradient magnitude is possible with 2D TF [S2, unofficial].
*   **Limitations:** Prone to aliasing and striping artifacts if sampling rate is insufficient [S3].
*   **When to use:** When sharp edges and high-frequency detail preservation are critical, and sufficient sampling rates can be maintained.
*   **When not to use:** When memory bandwidth is limited and aliasing artifacts are unacceptable without sufficient sampling.

## Background
Post-classification is a fundamental approach in volume rendering classification, contrasting with pre-classification [S3]. It is widely used in real-time volume rendering implementations [S1, unofficial][S2, unofficial]. The technique is discussed in the context of hardware-accelerated volume visualization [S3].
