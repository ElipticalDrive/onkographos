# 1D Lookup Table with Interpolation

Also called: HU -> mu mapping, Piecewise Linear HU to Attenuation Transfer Function, Piecewise Linear Transfer Function

## Overview
This method maps raw scalar voxel values (typically Hounsfield Units in medical imaging) to optical properties, specifically attenuation coefficients ($\mu$), using a piecewise linear function defined by user-specified keypoints [S1, unofficial]. It solves the problem of converting discrete density measurements into continuous visual parameters for volume rendering, allowing specific tissue types to be highlighted or suppressed [S1, unofficial]. Unlike multi-dimensional transfer functions that incorporate gradient magnitude or other derivatives to highlight boundaries [S2, unofficial], this method relies solely on the scalar intensity value, making it the simplest classification tool where mapping is a direct 1-to-1 or many-to-1 function [S8, unofficial]. It differs from [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md) by providing linear segments between control points rather than $C^1$ continuous derivatives, and from [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) by allowing arbitrary opacity curves rather than enforcing a strict linear ordering of materials [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume tensor `vol` of scalar values (e.g., HU), and a set of keypoints defining the transfer function.
*   **Output:** A 3D volume tensor `mu_tf` containing the mapped attenuation coefficients.

**Data Structures:**
*   **Keypoints:** A tensor of shape $(K, 2)$, where $K$ is the number of keypoints. The first column represents the input scalar values (HU), and the second column represents the output values (attenuation coefficients) [S1, unofficial].

**Steps:**
1.  **Define Keypoints:** Create a tensor `kp` of shape $(K, 2)$. Each row $i$ contains $(hu_i, \mu_i)$, representing a control point in the transfer function [S1, unofficial].
2.  **Normalize Input Domain:** Normalize the HU values to the range $[0, 1]$ to facilitate interpolation. The standard normalization formula uses an offset of 3500 and a scale of 7000 [S1, unofficial]:
    $$
    hu_{norm} = \frac{HU + 3500}{7000}
    $$
    This maps the typical HU range of $[-3500, 3500]$ to $[0, 1]$. Note that the source example cites an upper bound of 3071, but the normalization scale is fixed at 7000 [S1, unofficial].
3.  **Extract Normalized Coordinates:** Extract the normalized input values $x_p$ and output values $y_p$ as 1D tensors of shape $(1, K)$ [S1, unofficial].
    $$
    x_p = \frac{kp[:, 0] + 3500}{7000}
    $$
    $$
    y_p = kp[:, 1]
    $$
4.  **Interpolate:** Apply piecewise linear interpolation to the volume. For each voxel value $v$ in `vol`, compute the normalized value $v_{norm}$, find the interval $[x_p[i], x_p[i+1]]$ containing $v_{norm}$, and linearly interpolate the corresponding attenuation value [S1, unofficial].

**Pseudocode:**
```python
import torch

def piecewise_linear_hu_to_mu(vol: torch.Tensor, keypoints: torch.Tensor) -> torch.Tensor:
    """
    Maps Hounsfield Unit (HU) values in a volume to attenuation coefficients (mu)
    using piecewise linear interpolation defined by keypoints.
    
    Args:
        vol: 3D tensor of shape (D, H, W) containing HU values.
        keypoints: 2D tensor of shape (K, 2). Column 0 is HU, Column 1 is mu.
        
    Returns:
        mu_tf: 3D tensor of shape (D, H, W) containing mapped attenuation values.
    """
    # Step 1: Normalize HU values to [0, 1]
    # Offset: 3500, Scale: 7000
    # Clamp to ensure values stay within valid interpolation range if necessary
    vol_norm = torch.clamp((vol + 3500.0) / 7000.0, min=0.0, max=1.0)
    
    # Step 2: Extract normalized x and y coordinates from keypoints
    # keypoints shape: (K, 2)
    kp_hu = keypoints[:, 0]
    kp_mu = keypoints[:, 1]
    
    # Normalize keypoint HU values
    kp_hu_norm = (kp_hu + 3500.0) / 7000.0
    
    # Sort keypoints by HU value to ensure correct interpolation order
    # [G] Sorting is required for standard piecewise linear interpolation logic
    sorted_indices = torch.argsort(kp_hu_norm)
    xp = kp_hu_norm[sorted_indices]
    yp = kp_mu[sorted_indices]
    
    # Step 3: Perform piecewise linear interpolation
    # We use torch.nn.functional.grid_sample or a custom interpolation loop.
    # Here we implement a vectorized piecewise linear interpolation.
    
    # Expand vol_norm to match keypoint dimensions for broadcasting
    # vol_norm shape: (D, H, W) -> (1, 1, 1, D, H, W) for comparison
    # xp shape: (K,) -> (K, 1, 1, 1, 1, 1)
    
    xp_expanded = xp.unsqueeze(-1).unsqueeze(-1).unsqueeze(-1).unsqueeze(-1).unsqueeze(-1)
    yp_expanded = yp.unsqueeze(-1).unsqueeze(-1).unsqueeze(-1).unsqueeze(-1).unsqueeze(-1)
    
    # Find the index of the right endpoint of the interval for each voxel
    # (xp[i] <= vol_norm < xp[i+1])
    # We use searchsorted to find the insertion point
    # searchsorted returns the index i such that xp[i-1] <= vol_norm < xp[i]
    # We need to adjust for 0-based indexing and boundary conditions
    
    # Flatten vol for easier processing, then reshape back
    vol_flat = vol_norm.view(-1)
    
    # Find indices where xp[i] <= vol_flat < xp[i+1]
    # searchsorted('right') gives the first index i where xp[i] > vol_flat
    # So the interval is [i-1, i]
    indices = torch.searchsorted(xp, vol_flat, side='right')
    
    # Handle boundary cases: values below min HU or above max HU
    # Clamp indices to [1, K-1] to ensure valid intervals
    indices = torch.clamp(indices, min=1, max=len(xp) - 1)
    
    # Get the x and y values for the lower and upper bounds of the interval
    x0 = xp[indices - 1]
    x1 = xp[indices]
    y0 = yp[indices - 1]
    y1 = yp[indices]
    
    # Compute the interpolation factor t
    # t = (vol_norm - x0) / (x1 - x0)
    # Avoid division by zero if x0 == x1
    denom = x1 - x0
    denom = torch.where(denom == 0, torch.ones_like(denom), denom)
    t = (vol_flat - x0) / denom
    
    # Compute the interpolated y value
    y_interp = y0 + t * (y1 - y0)
    
    # Reshape back to original volume dimensions
    mu_tf = y_interp.view(vol_norm.shape)
    
    return mu_tf
```

**Parameters:**
*   **Keypoints:** User-defined. Typical keypoints include air, lung/soft-tissue, soft tissue, cortical bone, and dense bone/metal [S1, unofficial].
*   **Normalization Offset:** 3500 [S1, unofficial].
*   **Normalization Scale:** 7000 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Out-of-Bounds Values:** HU values outside the range $[-3500, 3500]$ will be clamped to $[0, 1]$ in the normalized domain. If the keypoints do not cover the full $[0, 1]$ range, extrapolation behavior depends on the implementation. The pseudocode clamps indices to ensure valid intervals [G].
*   **Duplicate Keypoints:** If multiple keypoints have the same HU value, the denominator in the interpolation step becomes zero. The pseudocode handles this by setting the denominator to 1 and the interpolation factor to 0, effectively selecting the lower bound's value [G].
*   **Unsorted Keypoints:** The interpolation logic assumes keypoints are sorted by HU value. The pseudocode explicitly sorts them [G].

## Subtopics

### Label-aware Interpolation Switching
Switches volume interpolation type to nearest-neighbor when labels are present to prevent band-crossing artifacts, otherwise uses linear interpolation [S2, unofficial]. It solves the problem of linear interpolation across label band boundaries producing values that fall into incorrect anatomical classes, breaking label-scoped transfer functions [S2, unofficial]. When labels are present, `volume.getProperty().setInterpolationTypeToNearest()` is called; otherwise, `volume.getProperty().setInterpolationTypeToLinear()` is called [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for $N$ voxels, as each voxel requires a constant-time lookup and interpolation [S1, unofficial].
*   **Memory Complexity:** $O(K)$ for storing $K$ keypoints [S1, unofficial].
*   **Strengths:** Simple to implement and edit; computationally efficient; intuitive for users familiar with HU values [S1, unofficial].
*   **Limitations:** Cannot distinguish between materials with similar HU values but different boundary characteristics; prone to aliasing if post-classification is used without sufficient sampling [S2, unofficial].
*   **When to Use:** When the volume data is primarily distinguished by scalar intensity (e.g., CT scans) and boundary information is not critical for classification [S1, unofficial].
*   **When Not to Use:** When materials have overlapping HU ranges but different textures or boundaries, requiring a 2D or 3D transfer function [S2, unofficial].

## Background
This method originates from the need to visualize medical imaging data, particularly CT scans, where Hounsfield Units provide a standardized measure of radiodensity [S1, unofficial]. It is widely used in clinical visualization tools and research prototypes for rapid volume rendering [S1, unofficial]. The specific implementation using PyTorch and CUDA acceleration (e.g., Triton) allows for real-time performance on modern GPUs [S1, unofficial].
