# 1D Lookup Table with Interpolation

Also called: HU -> mu mapping, Piecewise Linear HU to Attenuation Transfer Function, Piecewise Linear Transfer Function

## Overview
This method maps scalar volume data values (typically Hounsfield Units) to optical properties (attenuation coefficients, color, and opacity) using a piecewise linear function defined by user-specified keypoints [S1, unofficial]. It solves the problem of converting discrete voxel intensities into continuous physical or visual properties for volume rendering [S4, unofficial]. Unlike binary classification which uses hard thresholds, this soft classification method allows for semi-transparent visualization of overlapping structures by assigning intermediate opacity values based on linear interpolation between control points [6229-binary-and-soft-classification.md]. It differs from [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md) by using linear segments rather than $C^1$ continuous cubic splines, and from [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) by allowing arbitrary control point placement rather than strict nearest-neighbor density peak assignment [S1, unofficial][S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume tensor `vol` of scalar values (e.g., HU), and a set of keypoints defining the transfer function.
*   **Output:** A transformed volume tensor `mu_tf` (or RGBA texture) where each voxel's value is mapped to an attenuation coefficient or optical property.

**Data Structures:**
*   **Keypoints:** A tensor of shape $(K, 2)$ where $K$ is the number of keypoints. The first column represents the input domain values (e.g., HU), and the second column represents the output range values (e.g., attenuation $\mu$ or opacity $\alpha$) [S1, unofficial].
*   **Normalized Coordinates:** Input values are often normalized to $[0, 1]$ for consistent interpolation [S1, unofficial].

**Parameters:**
*   **Normalization Offset and Scale:** For HU values, the range $[-3500, 3500]$ is typical. The offset is $3500$ and the scale is $7000$ [S1, unofficial].
*   **Keypoints:** Specific $(x, y)$ pairs. Example keypoints for medical imaging include air, lung/soft-tissue, soft tissue, cortical bone, and dense bone/metal [S1, unofficial].

**Steps:**
1.  **Define Keypoints:** Create a tensor `kp` of shape $(K, 2)$ containing the control points $(x_i, y_i)$ [S1, unofficial].
2.  **Normalize Input Domain:** If the input domain is HU, normalize the voxel values $v$ to $v' \in [0, 1]$ using:
    $$ v' = \frac{v + 3500}{7000} $$
    Clamp $v'$ to $[0, 1]$ to handle out-of-bounds values [S1, unofficial].
3.  **Extract Control Point Coordinates:** Extract the normalized input coordinates $x_p$ and output values $y_p$ from the keypoints tensor. If keypoints are not pre-normalized, normalize $x_p$ using the same offset/scale as the input [S1, unofficial].
4.  **Interpolate:** For each voxel value $v'$, find the interval $[x_{p,i}, x_{p,i+1}]$ such that $x_{p,i} \le v' \le x_{p,i+1}$. Compute the interpolated output value $y$ using linear interpolation:
    $$ y = y_{p,i} + \frac{(v' - x_{p,i})}{(x_{p,i+1} - x_{p,i})} (y_{p,i+1} - y_{p,i}) $$
    This can be implemented efficiently using vectorized piecewise linear interpolation functions [S1, unofficial].
5.  **Assign Output:** Assign the interpolated value $y$ to the corresponding voxel in the output tensor `mu_tf` [S1, unofficial].

**Pseudocode:**
```python
import torch
import math

def normalize_hu(hu_values, offset=3500.0, scale=7000.0):
    """Normalize HU values to [0, 1]."""
    normalized = (hu_values + offset) / scale
    return torch.clamp(normalized, 0.0, 1.0)

def piecewise_linear_interpolation(x, xp, yp):
    """
    Perform piecewise linear interpolation.
    x: tensor of query points, shape (N,)
    xp: tensor of x-coordinates of keypoints, shape (K,), sorted
    yp: tensor of y-coordinates of keypoints, shape (K,)
    Returns: tensor of interpolated values, shape (N,)
    """
    # Find indices of the rightmost keypoint <= x
    # torch.searchsorted returns indices where x should be inserted to maintain order
    # side='right' gives the index of the first element > x, so we subtract 1 to get the left interval
    indices = torch.searchsorted(xp, x, side='right') - 1
    
    # Clamp indices to valid range [0, K-2]
    indices = torch.clamp(indices, 0, len(xp) - 2)
    
    x0 = xp[indices]
    x1 = xp[indices + 1]
    y0 = yp[indices]
    y1 = yp[indices + 1]
    
    # Avoid division by zero if duplicate x values exist
    denom = x1 - x0
    denom = torch.where(denom == 0, torch.ones_like(denom), denom)
    
    # Linear interpolation formula
    t = (x - x0) / denom
    y = y0 + t * (y1 - y0)
    
    return y

def apply_hu_to_mu_transfer_function(vol, keypoints_hu, keypoints_mu):
    """
    Map HU volume to attenuation map using piecewise linear interpolation.
    
    Args:
        vol: Input volume tensor, shape (D, H, W) or (B, 1, D, H, W)
        keypoints_hu: Tensor of HU values for keypoints, shape (K,)
        keypoints_mu: Tensor of attenuation values for keypoints, shape (K,)
        
    Returns:
        mu_tf: Output attenuation tensor, same shape as vol
    """
    # Flatten volume for processing
    original_shape = vol.shape
    vol_flat = vol.view(-1)
    
    # Normalize HU values
    vol_norm = normalize_hu(vol_flat)
    
    # Normalize keypoints HU values if necessary (assuming they are in HU range)
    kp_hu_norm = normalize_hu(keypoints_hu)
    
    # Sort keypoints by HU value to ensure searchsorted works correctly
    sorted_indices = torch.argsort(kp_hu_norm)
    kp_hu_sorted = kp_hu_norm[sorted_indices]
    kp_mu_sorted = keypoints_mu[sorted_indices]
    
    # Perform interpolation
    mu_flat = piecewise_linear_interpolation(vol_norm, kp_hu_sorted, kp_mu_sorted)
    
    # Reshape back to original volume shape
    mu_tf = mu_flat.view(original_shape)
    
    return mu_tf
```

**Edge Cases and Pitfalls:**
*   **Out-of-Bounds Values:** Values outside the range of the keypoints must be clamped or extrapolated. Clamping to the nearest endpoint is standard [S1, unofficial].
*   **Duplicate Keypoints:** If multiple keypoints have the same x-value, the denominator in the interpolation formula becomes zero. The pseudocode handles this by replacing zero denominators with ones, effectively copying the y-value [S1, unofficial].
*   **Unsorted Keypoints:** The interpolation function assumes keypoints are sorted by x-value. Unsorted keypoints will produce incorrect results [S1, unofficial].

## Subtopics

### [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md)
A 1D transfer function that maps a scalar field value in $[0, 1]$ to density and attenuation color using cubic spline interpolation of control points. It builds on [1D Lookup Table with Interpolation](2528-1d-lookup-table-with-interpolation.md) by providing $C^1$ continuous derivatives for smoother visual transitions compared to linear methods.

### [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md)
Linear look-up table classification is a volume rendering method that maps voxel intensity values to material composition percentages using a pre-calculated linear table. It solves the problem of assigning physical properties to discrete voxel data by treating classification as a nearest-neighbor decision based on density peaks. Unlike cubic spline or piecewise linear interpolation methods which allow arbitrary opacity curves, this method enforces a strict linear ordering of materials, making it computationally simple but restricted to scenarios where materials are distinct and adjacent in density space.

### [Piecewise Linear Interpolation (Lookup Table)](2643-piecewise-linear-interpolation-lookup-table.md)
Piecewise Linear Interpolation (Lookup Table) evaluates scalar-to-color and scalar-to-opacity transfer functions by linearly interpolating between adjacent control points. It solves the problem of mapping discrete scalar values from a volume dataset to continuous RGBA output values for volume rendering. It differs from [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) by explicitly supporting arbitrary control point placement and binary search for interval identification rather than fixed uniform grid indexing.

### [Smoothstep Interpolation](3287-smoothstep-interpolation.md)
Smoothstep interpolation provides a smooth, continuous transition between two values by applying a cubic Hermite spline to a normalized input. It is used in volume rendering classification to map scalar values to transfer function properties (such as opacity or color) with $C^1$ continuity, avoiding the discontinuities inherent in linear interpolation. It differs from [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) by eliminating sharp corners in the transfer function, and from [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md) by being a fixed, parameter-free kernel rather than a piecewise function defined by control points.

### [Shading Lookup Table Computation](3589-shading-lookup-table-computation.md)
Shading Lookup Table Computation is the process of generating or updating a color lookup table (LUT) that maps scalar data values to RGB colors and opacity, incorporating current lighting, material, and view transformation parameters. It solves the problem of efficiently applying complex shading models to volume data during rendering by pre-computing these effects into a 1D texture, allowing the renderer to fetch shaded colors via simple texture lookups. It is distinguished from its siblings by its reliance on **color index mode** (storing indices and transforming them at render time) rather than pre-shaded color values, which enables interactive manipulation of visual quantities like lighting and material properties.

### [Lookup Table Implementation](5347-lookup-table-implementation.md)
Lookup Table Implementation is the mechanism that materializes a 1D transfer function into a hardware-accessible data structure, typically a 1D texture or Shader Storage Buffer Object (SSBO), for use during volume rendering. It solves the problem of efficiently mapping scalar volume data values to RGBA optical properties by converting user-defined control points or parametric definitions into a dense, sampled array. It differs from [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by focusing on the data upload and GPU state management rather than the mathematical generation of the LUT values, and from [Hardcoded Transfer Function](1098-hardcoded-transfer-function.md) by supporting dynamic updates and complex data structures.

### Cosine Ramp Table Generation
A helper procedure that generates a cosine-shaped ramp table for smoothly attenuating density values [S2, unofficial]. It is used to fade out density at the boundaries of a volume slab. The table is generated by looping from $i = 0$ to $RAMP\_SIZE-1$, computing the normalized distance $dist = i / (RAMP\_SIZE - 1.0)$, and setting $ramp[i] = (\cos(dist \cdot \pi) + 1.0) / 2.0$ [S2, unofficial].

### Target Value Configuration
User configuration of up to five target data values, their associated RGB colors, allowable value deviation windows, and maximum opacity [S3, unofficial]. The number of targets is limited to five [S3, unofficial]. RGB triplets are expressed as three real numbers ranging from $0.0$ to $1.0$ [S3, unofficial]. A key pitfall is using identical RGB triplets for different target values, which causes surfaces to appear with the same color, leading to ambiguity. RGB triplets must be distinct enough to prevent color crossover caused by surface highlighting variations [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for $N$ voxels, assuming $O(1)$ or $O(\log K)$ lookup for the interpolation interval, where $K$ is the number of keypoints. Vectorized implementations on GPU can achieve near-linear scaling with batch size [S1, unofficial].
*   **Memory Complexity:** $O(K)$ for storing keypoints, plus $O(N)$ for the output volume. The LUT size is proportional to the number of samples taken from the transfer function, typically much smaller than the volume size if the LUT is used for caching [S1, unofficial].
*   **Strengths:** Simple to implement and understand. Allows for intuitive control over material appearance via keypoints. Efficient on modern GPUs using texture lookups or vectorized operations [S1, unofficial].
*   **Limitations:** Linear interpolation can produce sharp corners in the transfer function if keypoints are not carefully placed, leading to visual artifacts. Less smooth than cubic spline methods [S1, unofficial].
*   **When to Use:** Suitable for real-time volume rendering where performance is critical and smoothness requirements are moderate. Ideal for medical imaging where HU values have well-defined physical meanings [S1, unofficial].
*   **When Not to Use:** When high visual smoothness is required (use [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md)) or when materials are not distinct in density space (use [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) with caution).

## Background
The method originates from early volume rendering techniques that mapped scalar data to optical properties for visualization [S1, unofficial]. It is widely used in medical imaging, particularly in CT scans, where Hounsfield Units provide a standardized scale for tissue density [S1, unofficial]. The use of lookup tables for transfer function evaluation was popularized in the 1990s to accelerate rendering on hardware that lacked programmable shaders [S1, unofficial]. The specific normalization of HU values to $[0, 1]$ is a common practice in medical imaging pipelines to simplify transfer function definition [S1, unofficial].
