# Palette-based Color Mapping

Also called: Color index UV mapping, Texture palette atlas

## Overview
Palette-based color mapping maps discrete color indices to UV coordinates on a square texture atlas to avoid storing per-voxel color data in vertex buffers [S1, unofficial]. It differs from [Scalar/Component to Color Mapping](6697-scalar-component-to-color-mapping.md) by using a pre-computed lookup table rather than procedural functions, and from [Voxel Color Mapping](2970-voxel-color-mapping.md) by decoupling color definition from vertex geometry via a shared texture resource [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of unique color indices and their corresponding RGB values extracted from a model file [S1, unofficial].
*   **Output:** A square texture atlas (`paletteBitmap`) containing the colors, and a mapping structure (`colorIndexToUV`) associating each color index with its UV coordinates for sampling [S1, unofficial].

**Data Structures:**
1.  `colorIndexToUV`: A map where keys are integer color indices and values are 2D float arrays `[u, v]` [S1, unofficial].
2.  `paletteBitmap`: A square bitmap of size `side x side` with `ARGB_8888` configuration (8 bits per channel: Alpha, Red, Green, Blue) [S1, unofficial].

**Steps:**
1.  Count the total number of unique color indices ($N$) from the source data [S1, unofficial].
2.  Calculate the palette side length ($S$) using $S = \max(8, \lceil \sqrt{N} \rceil)$ to enforce a minimum 8x8 size for GPU sampling stability [S1, unofficial].
3.  Sort the color indices deterministically and assign each to a grid position $(p_x, p_y)$ where $p_x = i \pmod S$ and $p_y = \lfloor i / S \rfloor$ for the $i$-th index [S1, unofficial].
4.  Convert the RGB values to an ARGB integer with Alpha=255, and store the color in the bitmap at $(p_x, p_y)$ [S1, unofficial].
5.  Compute UVs as $u = \frac{p_x + 0.5}{S}$ and $v = \frac{p_y + 0.5}{S}$ to sample the center of each texel, storing the pair in `colorIndexToUV` [S1, unofficial].
6.  Erase any unused cells in the $S \times S$ grid to black (RGB=0,0,0, Alpha=255) [S1, unofficial].
7.  Do not invert the V coordinate; the texture loading function loads rows top-to-bottom, matching the bitmap layout [S1, unofficial].

**Pseudocode:**
```python
import math

def build_palette(color_map):
    """
    color_map: dict mapping integer color_index -> [r, g, b] (values 0-255)
    Returns:
        side: int
        palette_uv_map: dict mapping color_index -> [u, v]
        palette_data: list of [r, g, b, a] tuples in row-major order
    """
    # 1. Count and sort unique color indices deterministically
    keys = sorted(color_map.keys())
    num_colors = len(keys)
    
    # 2. Calculate palette side length (minimum 8x8 for GPU sampling stability)
    side = max(8, math.ceil(math.sqrt(num_colors)))
    
    # Initialize palette data with black (0,0,0) and alpha 255
    palette_data = [(0, 0, 0, 255)] * (side * side)
    palette_uv_map = {}
    
    # 3. Assign colors and compute UVs
    for i, color_index in enumerate(keys):
        r, g, b = color_map[color_index]
        a = 255
        
        # Grid position
        px = i % side
        py = i // side
        
        # Store color in palette data (row-major: py * side + px)
        idx = py * side + px
        palette_data[idx] = (r, g, b, a)
        
        # Compute UV for center of texel
        u = (px + 0.5) / side
        v = (py + 0.5) / side
        
        palette_uv_map[color_index] = [u, v]
        
    return side, palette_uv_map, palette_data
```

**Parameters:**
*   `side`: Must be $\ge 8$. Typical values depend on $N$. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Small Palettes:** Using a palette smaller than 8x8 (e.g., 3x3) causes sampling errors with `GL_NEAREST` on some mobile GPUs; enforcing a minimum side of 8 eliminates border bleeding [S1, unofficial].
*   **V Coordinate Inversion:** Inverting V breaks sampling if the texture loader assumes top-to-bottom row order, which matches standard bitmap layouts [S1, unofficial].
*   **Unused Cells:** Must be explicitly filled with black to prevent undefined sampling behavior if an index is missed or if the GPU samples outside the valid range [S1, unofficial].

## Background
This method is documented in the VoxelRenderer project, an unofficial Android OpenGL ES 3.0 voxel renderer [S1, unofficial]. It is used to efficiently render voxel models by mapping color indices to a shared texture atlas, avoiding the overhead of storing color data in vertex buffers for each voxel face [S1, unofficial].
