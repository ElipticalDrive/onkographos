# Voxel Color Mapping

Also called: Color Index Mapping, Deterministic Voxel Material Assignment, Height-based Voxel Coloring

## Overview
Voxel Color Mapping is a method for assigning discrete or continuous colors to volumetric data by mapping scalar values to integer indices for lookup in a color table [S1, unofficial]. It solves the problem of quantitative visualization by converting raw data values into RGBA representations suitable for rendering [S1, unofficial]. It differs from its parent [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by focusing on the specific implementation of the index calculation and table lookup, often using deterministic rules (such as height-based assignment) rather than parametric functions [S2, unofficial]. It is distinct from [Color Specification](3969-color-specification.md) which defines color spaces, and [Parametric Function Generation](5349-parametric-function-generation.md) which generates transfer functions via mathematical functions rather than direct value-to-index mapping [S1, unofficial].

## How it works
**Inputs:**
- Scalar voxel value $v$.
- Data bounds $v_{min}$ and $v_{max}$ [S1, unofficial].
- Color table of size 256 entries [S1, unofficial].

**Outputs:**
- RGBA color value for the voxel.

**Data Structures:**
- **Color Table:** An array of 256 entries. Each entry contains 4 components: Red, Green, Blue, and Opacity. Each component is scaled from 0.0 to 1.0 [S1, unofficial].

**Steps:**
1. **Determine Data Bounds:** Establish $v_{min}$ and $v_{max}$. These can be specified by the user, calculated as global min/max, or determined via percentile bounds (e.g., 1st and 99th percentiles) using a histogram scan [S1, unofficial].
2. **Compute Color Index:** Map the scalar value $v$ to an integer index $i$ between 0 and 255 using the following formula [S1, unofficial]:
   $$
   i = \begin{cases} 
   0 & v < v_{min} \\
   1 + 253 \frac{v - v_{min}}{v_{max} - v_{min}} & v_{min} \leq v \leq v_{max} \\
   255 & v > v_{max}
   \end{cases}
   $$
   The index is typically truncated or rounded to the nearest integer for table access.
3. **Lookup Color:** Retrieve the RGBA components from the color table at index $i$.
4. **Display:** Render the color using 1D texture maps or direct color commands [S1, unofficial].

**Height-Based Variant (Deterministic Assignment):**
In specific applications like voxel terrain, color is determined by geometric height rather than scalar data bounds [S2, unofficial].
1. **Normalize Height:** Calculate normalized height $h = y / 64.0$, where $y$ is the voxel's vertical coordinate [S2, unofficial].
2. **Assign Material Color:**
   - If $h > 0.70$: Color is Grass $(0x4D, 0x9E, 0x2E)$.
   - If $h > 0.40$: Color is Dirt $(0x85, 0x61, 0x38)$.
   - Otherwise: Color is Stone $(0x85, 0x85, 0x85)$.
3. **Pack Color:** Combine components into a single integer: `(r << 16) | (g << 8) | b` [S2, unofficial].

**Pseudocode:**
```python
def voxel_color_mapping(value, v_min, v_max, color_table):
    """
    Maps a scalar value to a color using a 256-entry lookup table.
    
    Args:
        value (float): The scalar voxel value.
        v_min (float): Minimum data bound.
        v_max (float): Maximum data bound.
        color_table (list): List of 256 tuples, each containing (r, g, b, a) floats in [0.0, 1.0].
        
    Returns:
        tuple: (r, g, b, a) color components.
    """
    # Step 1: Compute color index
    if value < v_min:
        index = 0
    elif value > v_max:
        index = 255
    else:
        # Formula: 1 + 253 * (v - v_min) / (v_max - v_min)
        # Using integer arithmetic for index, clamping to 0-255
        index = int(1 + 253 * (value - v_min) / (v_max - v_min))
        # Guard against floating point errors pushing index to 256
        if index > 255:
            index = 255
            
    # Step 2: Lookup color
    # color_table is assumed to be pre-populated with 256 entries
    return color_table[index]

def height_based_voxel_coloring(y_coordinate):
    """
    Deterministic voxel material assignment based on height.
    
    Args:
        y_coordinate (float): The vertical position of the voxel.
        
    Returns:
        int: Packed RGB color (0xRRGGBB).
    """
    # Normalize height
    h = y_coordinate / 64.0
    
    if h > 0.70:
        r, g, b = 0x4D, 0x9E, 0x2E
    elif h > 0.40:
        r, g, b = 0x85, 0x61, 0x38
    else:
        r, g, b = 0x85, 0x85, 0x85
        
    # Pack as (r << 16) | (g << 8) | b
    return (r << 16) | (g << 8) | b
```

## Subtopics

### Scalar/Component to Color Mapping
Maps a scalar value or a specific normal component (X, Y, Z) to a color using a colormap, clamping the input to the range [0, 1] [S3, unofficial]. It is chosen when visualizing vector field components or normalized scalar data. The input is processed based on a `visualize_target` enum: if `NORMAL_X`, `NORMAL_Y`, or `NORMAL_Z`, the component is mapped via `(component + 1.0) / 2.0` and clamped; if `VALUE`, the value is clamped directly to [0, 1] [S3, unofficial]. The specific colormap is selected via a `cm_type` parameter [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for index calculation and table lookup [S1, unofficial].
- **Memory Complexity:** $O(1)$ for the color table (fixed at 256 entries) [S1, unofficial].
- **Performance:** Fast and deterministic. The use of 1D texture maps allows hardware interpolation between grid points, providing smoother visual transitions than discrete table lookups alone [S1, unofficial].
- **Strengths:** Simple implementation; efficient for real-time visualization; supports user-defined bounds for dynamic data [S1, unofficial].
- **Limitations:** Discrete index mapping can introduce banding if not interpolated; dependent on accurate $v_{min}$ and $v_{max}$ selection [S1, unofficial].
- **When to use:** When quantitative visualization of scalar data is required and a fixed color mapping is sufficient.
- **When not to use:** When complex, non-linear transfer functions or multi-dimensional data mapping is needed.

## Background
Voxel Color Mapping is a fundamental technique in volume visualization, prominently used in tools like Smokeview for visualizing Fire Dynamics Simulation data [S1, unofficial]. The method was formalized in the context of converting quantitative data to color for display, utilizing 1D texture maps for interpolation [S1, unofficial]. It is also applied in voxel-based games and simulations for deterministic terrain coloring based on height [S2, unofficial].
