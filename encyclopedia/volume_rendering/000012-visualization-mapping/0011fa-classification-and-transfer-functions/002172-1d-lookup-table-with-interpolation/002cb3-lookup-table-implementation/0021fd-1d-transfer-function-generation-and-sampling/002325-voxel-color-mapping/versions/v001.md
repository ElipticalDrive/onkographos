# Voxel Color Mapping

Also called: Color Index Mapping, Deterministic Voxel Material Assignment, Height-based Voxel Coloring

## Overview
Voxel Color Mapping is a technique for visualizing scalar volumetric data by converting raw data values into integer indices that address a pre-defined color table [S1, unofficial]. It solves the problem of quantitative data visualization by providing a deterministic, discrete mapping from continuous or discrete scalar fields to RGBA colors [S1, unofficial]. Unlike [Parametric Function Generation](5349-parametric-function-generation.md), which computes color based on the derivative and value of the transfer function, this method relies on a fixed lookup table indexed by normalized data bounds [S1, unofficial]. It differs from [Color Specification](3969-color-specification.md) by explicitly handling the index calculation and clamping logic required for texture map or buffer access [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scalar voxel value $v$; minimum data bound $v_{min}$; maximum data bound $v_{max}$.
*   **Output:** An integer color index $i$ in the range $[0, 255]$.
*   **Data Structure:** A color table of 256 entries. Each entry contains four components: Red, Green, Blue, and Opacity, each scaled from 0.0 to 1.0 [S1, unofficial].

**Steps:**
1.  Determine the data bounds $v_{min}$ and $v_{max}$. These may be specified by the user, calculated via global min/max, or derived from percentile bounds (e.g., 1st and 99th percentiles) using a histogram scan [S1, unofficial].
2.  Compute the color index $i$ using the formula below.
3.  Use $i$ to retrieve the RGBA color from the color table.
4.  Apply the color to the voxel or interpolated geometry (e.g., via 1D texture maps) [S1, unofficial].

**Formula:**
The color index is computed as [S1, unofficial]:

$$
i = \begin{cases} 
0 & v < v_{min} \\
1 + 253 \frac{v - v_{min}}{v_{max} - v_{min}} & v_{min} \leq v \leq v_{max} \\
255 & v > v_{max}
\end{cases}
$$

Where:
*   $v$ is the scalar data value.
*   $v_{min}$ is the lower bound of the data range.
*   $v_{max}$ is the upper bound of the data range.
*   The result is an integer index. Note that the range $[v_{min}, v_{max}]$ maps to indices $[1, 254]$, leaving 0 and 255 for out-of-bounds clamping [S1, unofficial].

**Parameters:**
*   **Color Table Size:** 256 entries [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The formula uses linear interpolation. If $v_{min} = v_{max}$, division by zero occurs. Implementers must guard against this case, typically by defaulting to index 0 or a neutral color [G].
*   **Clamping:** Values outside $[v_{min}, v_{max}]$ are clamped to 0 or 255. This ensures no out-of-bounds memory access when indexing the color table.
*   **Index Range:** The formula explicitly maps the valid range to $1 \dots 254$. Index 0 is reserved for $v < v_{min}$ and 255 for $v > v_{max}$. This leaves a gap in the mapping density compared to a $0 \dots 255$ linear map, but ensures strict clamping behavior [S1, unofficial].

**Pseudocode:**
```python
def compute_color_index(v: float, v_min: float, v_max: float) -> int:
    """
    Computes the integer color index for a scalar value v.
    Based on the formula from Smokeview technical reference [S1, unofficial].
    """
    if v_min == v_max:
        # Guard against division by zero [G]
        return 0
    
    if v < v_min:
        return 0
    elif v > v_max:
        return 255
    else:
        # Linear interpolation mapped to 1..254
        # Formula: 1 + 253 * (v - v_min) / (v_max - v_min)
        index_float = 1.0 + 253.0 * (v - v_min) / (v_max - v_min)
        return int(index_float)

def get_voxel_color(v: float, v_min: float, v_max: float, color_table: list) -> tuple:
    """
    Retrieves the RGBA color for a voxel value.
    color_table: List of 256 tuples, each (r, g, b, a) with components in [0.0, 1.0].
    """
    idx = compute_color_index(v, v_min, v_max)
    return color_table[idx]
```

**Height-based Variant:**
Some implementations, such as those in voxel comparison tools, bypass data bounds entirely and map color directly to geometric height (y-coordinate) [S2, unofficial].
*   Normalize height: $h = y / 64.0$.
*   If $h > 0.70$: Grass $(0x4D, 0x9E, 0x2E)$.
*   If $h > 0.40$: Dirt $(0x85, 0x61, 0x38)$.
*   Otherwise: Stone $(0x85, 0x85, 0x85)$.
*   Pack as $(r \ll 16) | (g \ll 8) | b$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel for index computation and table lookup.
*   **Memory Complexity:** $O(1)$ for the color table (fixed 256 entries).
*   **Strengths:** Simple to implement; deterministic; fast execution; suitable for real-time visualization when combined with 1D texture maps for interpolation [S1, unofficial].
*   **Limitations:** Discrete mapping can introduce banding if the color table is not dense or if interpolation is not used during rendering [S1, unofficial]. Percentile-based bounds require a pre-scan of the data, adding $O(N)$ overhead before rendering [S1, unofficial].
*   **When to use:** Quantitative visualization where data bounds are known or can be pre-computed; simple categorical mapping based on value ranges.
*   **When not to use:** When smooth, derivative-based classification is required (use [Parametric Function Generation](5349-parametric-function-generation.md)); when the data distribution is highly non-uniform and global bounds obscure details (use percentile bounds or adaptive mapping).

## Background
Voxel Color Mapping is described in the technical reference guide for Smokeview, a tool for visualizing Fire Dynamics Simulation (FDS) data [S1, unofficial]. The method is part of Smokeview's quantitative visualization pipeline, which converts data values to color using 1D texture maps to enable interpolation between grid points [S1, unofficial]. The height-based variant is observed in voxel comparison tools like `voxel-compare` [S2, unofficial].
