# Scalar/Component to Color Mapping

Also called: Target Value Visualization, Visualization Target Mapping, 颜色映射

## Overview
Scalar/Component to Color Mapping is a visualization method that maps a single scalar volume value or a specific vector component (such as a normal direction) to an RGB color using a 1D colormap texture [S1, S2, unofficial]. It solves the problem of visualizing scalar fields by converting numerical data into perceptible color information, serving as the fundamental color assignment step in direct volume rendering pipelines [S3, unofficial]. Unlike Palette-based Color Mapping, which assigns colors from a discrete set of predefined palettes often for categorical data, this method uses continuous interpolation within a colormap texture to provide smooth gradients for continuous scalar data [S3, unofficial]. It builds on [Voxel Color Mapping](2970-voxel-color-mapping.md) by defining the specific mechanism for translating the voxel's scalar or component value into a texture coordinate.

## How it works
The method takes a scalar value or a vector component as input and outputs an RGBA color. The core data structure is a 2D colormap texture (`u_colormap`) which stores the color gradient. The input value is normalized to the range $[0, 1]$ and used as the x-coordinate to sample this texture.

### Inputs and Outputs
*   **Input Value**: A scalar value from the volume data, or a component of a vector (e.g., normal vector).
*   **Clim Range (`u_clim`)**: A pair of floats $(min, max)$ defining the data range for normalization [S1, unofficial].
*   **Colormap Texture (`u_colormap`)**: A 2D texture containing the color gradient [S1, unofficial].
*   **Visualize Target (`visualize_target`)**: An enum specifying whether to map the scalar `VALUE` or a specific normal component (`NORMAL_X`, `NORMAL_Y`, `NORMAL_Z`) [S2, unofficial].
*   **Output**: An RGBA color vector.

### Data Structures
*   **Colormap Texture**: A 2D texture sampled at $y=0.5$ (center) to retrieve the color corresponding to the normalized x-coordinate. The texture format is typically RGB or RGBA [S1, unofficial].

### Steps
1.  **Select Source Value**:
    *   If `visualize_target` is `VALUE`, use the scalar volume value $v$ [S2, unofficial].
    *   If `visualize_target` is `NORMAL_X`, `NORMAL_Y`, or `NORMAL_Z`, extract the corresponding component $c$ from the normal vector $\mathbf{n}$ [S2, unofficial].

2.  **Normalize to [0, 1]**:
    *   **For Scalar Value**: Normalize $v$ using the clim range $[u_{clim}[0], u_{clim}[1]]$ [S1, unofficial]:
        $$
        v_{norm} = \frac{v - u_{clim}[0]}{u_{clim}[1] - u_{clim}[0]}
        $$
    *   **For Normal Component**: Map the component $c \in [-1, 1]$ to $[0, 1]$ [S2, unofficial]:
        $$
        c_{norm} = \frac{c + 1.0}{2.0}
        $$

3.  **Clamp**: Clamp the normalized value $v_{norm}$ or $c_{norm}$ to the range $[0, 1]$ to handle out-of-bounds values [S1, S2, unofficial].

4.  **Sample Colormap**: Sample the 2D colormap texture `u_colormap` at the normalized x-coordinate with a fixed y-coordinate of $0.5$ [S1, unofficial]:
    $$
    \text{color} = \text{texture2D}(u_{colormap}, (v_{norm} \text{ or } c_{norm}, 0.5))
    $$
    The returned color has alpha set to $1.0$ [S1, unofficial].

### Pseudocode
```python
def scalar_to_color(value, normal, visualize_target, u_clim, u_colormap):
    """
    Maps a scalar value or normal component to a color using a 2D colormap.
    
    Args:
        value: The scalar volume value.
        normal: A vector (x, y, z) representing the surface normal.
        visualize_target: Enum indicating which value to visualize ('VALUE', 'NORMAL_X', 'NORMAL_Y', 'NORMAL_Z').
        u_clim: A tuple (min, max) defining the normalization range for scalar values.
        u_colormap: A 2D texture object supporting sampling.
        
    Returns:
        A tuple (r, g, b, a) representing the color.
    """
    normalized_val = 0.0
    
    if visualize_target == 'VALUE':
        # Normalize scalar value using clim range [S1, unofficial]
        min_val, max_val = u_clim
        if max_val == min_val:
            normalized_val = 0.5 # Guard against division by zero [G]
        else:
            normalized_val = (value - min_val) / (max_val - min_val)
            
    elif visualize_target == 'NORMAL_X':
        # Map normal.x from [-1, 1] to [0, 1] [S2, unofficial]
        normalized_val = (normal.x + 1.0) / 2.0
    elif visualize_target == 'NORMAL_Y':
        # Map normal.y from [-1, 1] to [0, 1] [S2, unofficial]
        normalized_val = (normal.y + 1.0) / 2.0
    elif visualize_target == 'NORMAL_Z':
        # Map normal.z from [-1, 1] to [0, 1] [S2, unofficial]
        normalized_val = (normal.z + 1.0) / 2.0
    else:
        normalized_val = 0.0 # Default fallback [G]

    # Clamp to [0, 1] [S1, S2, unofficial]
    normalized_val = max(0.0, min(1.0, normalized_val))

    # Sample 2D colormap at y=0.5 [S1, unofficial]
    # Assuming u_colormap is a texture sampler
    color_sample = u_colormap.sample(normalized_val, 0.5)
    
    # Return RGB with alpha 1.0 [S1, unofficial]
    return (color_sample.r, color_sample.g, color_sample.b, 1.0)
```

### Parameters
*   **`u_clim`**: A `vec2` containing the lower and upper bounds of the value range for normalization [S1, unofficial].
*   **`visualize_target`**: An enum determining whether to visualize `NORMAL_X`, `NORMAL_Y`, `NORMAL_Z`, or `VALUE` [S2, unofficial].
*   **`u_colormap`**: A 2D sampler texture containing the color map [S1, unofficial].
*   **`cm_type`**: Colormap type identifier (e.g., from `tinycolormap::ColormapType`) used to generate or select the texture [S2, unofficial].

### Edge Cases and Pitfalls
*   **Division by Zero**: If `u_clim[0]` equals `u_clim[1]`, normalization fails. A guard clause should return a default color or handle the degenerate range [G].
*   **Logarithmic Scale Zero**: If a logarithmic scale is used for the colormap generation (see Subtopics), and the scalar range contains zero, the mapping defaults to linear to avoid undefined behavior ($\log(0)$) [S5].
*   **Perceptual Artifacts**: Using non-uniform colormaps like Rainbow can introduce "false boundary" artifacts due to non-uniform human perception of hue intervals [S3, unofficial].

## Subtopics

### Colormap Conversion
Maps a scalar tensor to RGB colors using a matplotlib colormap (default 'turbo') [S4, unofficial]. It normalizes input to $[0, 1]$, scales to $[0, 255]$, and indexes into pre-loaded colormap colors [S4, unofficial].
*   **Steps**: 1. Load colormap colors from matplotlib and move to tensor device. 2. Normalize input map: $(map - min) / (max - min)$. 3. Scale to 0-255: $map * 255$. 4. Round and convert to long integers. 5. Squeeze dimensions. 6. Index into colors tensor. 7. Permute dimensions to $(2, 0, 1)$ (RGB, H, W) [S4, unofficial].
*   **Parameters**: `cmap`: Colormap name string. Default: 'turbo' [S4, unofficial].
*   **When to choose**: Useful for post-processing or generating static visualizations in Python/tensor environments where matplotlib colormaps are preferred over GPU textures [S4, unofficial].

### Scalar to Color Mapping Scale
Defines the type of scale used to map scalar values to the transfer function range [S5]. Options are linear or logarithmic (base 10) [S5].
*   **Parameters**: Default scale type is linear [S5].
*   **Pitfalls**: If the scale is set to logarithmic but the scalar range contains zero, the color mapping defaults to linear to avoid undefined behavior [S5].
*   **When to choose**: Use logarithmic scale for data with large dynamic ranges where low-intensity details are important [S5].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per voxel/pixel. The operation involves basic arithmetic, clamping, and a single texture lookup [S1, S2, unofficial].
*   **Memory Complexity**: $O(1)$ additional memory per voxel, plus the fixed size of the colormap texture [S1, unofficial].
*   **Strengths**: Simple to implement; efficient on GPU via texture sampling; provides smooth color transitions for continuous data [S3, unofficial].
*   **Limitations**: Single-dimensional mapping cannot encode multiple attributes simultaneously (unlike 2D transfer functions) [S3, unofficial]. Choice of colormap significantly impacts perceptual accuracy [S3, unofficial].
*   **When to use**: When visualizing a single scalar field or a specific vector component is sufficient [S3, unofficial].
*   **When not to use**: When multiple attributes need to be encoded simultaneously or when categorical data requires discrete palette mapping [S3, unofficial].

## Background
Scalar/Component to Color Mapping is the most common scalar field visualization method, mapping scalar values to a color space [S3, unofficial]. It originated from the need to visualize continuous data in scientific computing and computer graphics [S3, unofficial]. Common schemes include Rainbow, Viridis, Diverging, Grayscale, and Hot [S3, unofficial]. Perceptually uniform colormaps like Viridis are preferred over Rainbow colormaps because Rainbow colormaps suffer from 'false boundary' artifacts due to non-uniform human perception of hue intervals [S3, unofficial]. For data with positive/negative distinctions, a diverging colormap should be used [S3, unofficial].
