# Voxel Color Mapping

Also called: Color Index Mapping

## Overview
Voxel Color Mapping is the fundamental technique for visualizing scalar fields by mapping a single scalar value or a specific vector component to an RGB color using a 1D colormap [S1, S2, S3, unofficial]. It solves the problem of translating abstract numerical data into perceptible visual information, serving as the core color assignment step in direct volume rendering and surface visualization [S3, unofficial]. Unlike Palette-based Color Mapping, which assigns colors from a discrete set of predefined palettes often for categorical data, this method uses a continuous 2D texture (colormap) to provide smooth gradients, allowing for the representation of continuous magnitude or directional components [S1, S2, unofficial]. It builds on [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by implementing the actual lookup and sampling of the generated transfer function.

## How it works
**Inputs:**
- Scalar voxel data $V$ (density, pressure, etc.) with minimum value $v_{min}$ and maximum value $v_{max}$ [S1, S4, unofficial].
- A 1D Transfer Function (colormap) $T$ of size $N=256$ entries [S1, S2, S4, unofficial]. Each entry $T[i]$ contains 4 components: Red, Green, Blue, and Opacity, scaled from 0.0 to 1.0 [S1, unofficial].
- Voxel coordinates $(i, j, k)$ [S4, unofficial].

**Outputs:**
- RGBA color value for each voxel, used for rendering [S4, unofficial].

**Data Structures:**
- **Color Table (LUT):** An array of 256 entries. Each entry is a struct or packed value containing 4 normalized floats (or 8-bit integers mapped to 0.0–1.0) representing $(R, G, B, \alpha)$ [S1, unofficial].
- **Volume Texture:** A 3D texture (e.g., `GL_TEXTURE_3D`) storing the scalar data, typically in a single-channel format like `GL_R8` (unsigned byte) [S2, unofficial].
- **Colormap Texture:** A 1D texture (e.g., `GL_TEXTURE_1D`) storing the color table, typically in `GL_RGBA8` format [S2, unofficial].

**Steps:**

1.  **Determine Data Bounds:** Identify $v_{min}$ and $v_{max}$ for the dataset. This can be done by user specification, global min/max, or percentile-based histogram analysis (e.g., 1st and 99th percentiles) [S1, unofficial].
2.  **Scale Data to Index:** Convert the raw scalar value $v$ of a voxel to an integer color index $c$ between 0 and 255 using linear scaling and clamping [S1, S4, unofficial]:
    $$
    c = \begin{cases} 
    0 & v < v_{min} \\
    1 + 253 \frac{v - v_{min}}{v_{max} - v_{min}} & v_{min} \leq v \leq v_{max} \\
    255 & v > v_{max}
    \end{cases}
    $$
    [S1, unofficial]
3.  **Compute Opacity (Optional/Implicit):** Normalize the scaled value to lie between 0 (transparent) and 1 (opaque) if opacity is not directly stored in the LUT or if a separate opacity function is used. Straightforward value-to-opacity mapping may fail to display surfaces accurately; gradient-based opacity is often needed for interfaces [S4, unofficial].
4.  **Lookup Color:** Use the index $c$ to retrieve the RGBA color from the 1D colormap texture $T[c]$ [S1, S4, unofficial].
5.  **Render:** Combine the retrieved color and opacity with other voxels during volume rendering (e.g., front-to-back or back-to-front compositing) [S4, unofficial].

**Pseudocode:**

```python
def voxel_color_mapping(voxel_value: float, v_min: float, v_max: float, colormap: list) -> tuple:
    """
    Maps a scalar voxel value to an RGBA color using a 1D lookup table.
    
    Args:
        voxel_value: The scalar data value of the voxel.
        v_min: The minimum data bound for scaling.
        v_max: The maximum data bound for scaling.
        colormap: A list of 256 tuples, each containing (r, g, b, a) floats in [0.0, 1.0].
        
    Returns:
        A tuple (r, g, b, a) representing the mapped color.
    """
    # Step 2: Scale data to index (0-255)
    if voxel_value < v_min:
        index = 0
    elif voxel_value > v_max:
        index = 255
    else:
        # Linear interpolation formula from [S1, unofficial]
        # Note: 1 + 253 * ... maps [v_min, v_max] to [1, 254], leaving 0 and 255 for clamps
        # This ensures full utilization of the 256-entry table for the range
        index = 1 + 253 * (voxel_value - v_min) / (v_max - v_min)
    
    # Clamp index to integer range [0, 255]
    index = int(round(index))
    index = max(0, min(255, index))
    
    # Step 4: Lookup color from colormap
    # Colormap is assumed to be pre-populated with 256 RGBA entries
    color_rgba = colormap[index]
    
    return color_rgba

def render_volume_shader(volume_texture_3d, colormap_texture_1d, voxel_coords):
    """
    GLSL-like pseudocode for fragment shader implementation [S2, unofficial].
    """
    # Step 1: Get voxel coordinates in texture space
    # Assuming aPosition is the voxel center or corner
    tex_coords = voxel_coords + vec3(0.5) 
    
    # Sample the 3D volume texture to get the scalar data value (e.g., from Red channel)
    # The volume texture is typically GL_R8, so .r gives the normalized scalar value [0.0, 1.0]
    # Note: The raw data must be scaled to [0.0, 1.0] before uploading to the texture
    raw_value = texture(volume_texture_3d, tex_coords).r
    
    # If the volume texture stores raw bytes (0-255), normalize it first
    # normalized_value = raw_value # if already normalized
    
    # Step 2 & 4: Use the scalar value as a coordinate to sample the 1D colormap
    # The 1D colormap texture stores the RGBA color table
    # Linear filtering on the 1D texture provides interpolation between color table entries
    frag_color = texture(colormap_texture_1d, vec2(raw_value, 0.5)).rgba
    
    return frag_color
```

**Edge Cases and Pitfalls:**
- **Precision:** Linear scaling may lose precision if the data range is large and the number of bits is small (e.g., 8-bit) [S4, unofficial].
- **Boundary Conditions:** Values outside $[v_{min}, v_{max}]$ are clamped to the first or last entry of the colormap, which may hide outliers or create artifacts if bounds are not chosen carefully (e.g., using percentiles instead of global min/max) [S1, unofficial].
- **Surface Display:** Straightforward value-to-opacity mapping may not accurately display surfaces; gradient-based opacity is needed for interfaces like air/skin or skin/muscle [S4, unofficial].

## Subtopics

### [Scalar/Component to Color Mapping](6697-scalar-component-to-color-mapping.md)
Scalar/Component to Color Mapping is the fundamental technique for visualizing scalar fields by mapping a single scalar value or a specific vector component to an RGB color using a 1D colormap. It solves the problem of translating abstract numerical data into perceptible visual information, serving as the core color assignment step in direct volume rendering and surface visualization. Unlike Palette-based Color Mapping, which assigns colors from a discrete set of predefined palettes often for categorical data, this method uses a continuous 2D texture (colormap) to provide smooth gradients, allowing for the representation of continuous magnitude or directional components.

### [Palette-based Color Mapping](7283-palette-based-color-mapping.md)
Palette-based color mapping maps discrete color indices to UV coordinates on a square texture atlas to avoid storing per-voxel color data in vertex buffers. It differs from [Scalar/Component to Color Mapping](6697-scalar-component-to-color-mapping.md) by using a pre-computed lookup table rather than procedural functions, and from [Voxel Color Mapping](2970-voxel-color-mapping.md) by decoupling color definition from vertex geometry via a shared texture resource.

### Multi-hypothesis Voxel Coloring
Multi-hypothesis Voxel Coloring is an extension where a set of hypotheses (possible colorings) is identified for each voxel [S5, unofficial]. The algorithm narrows down these hypotheses during a hypothesis removal step, carving inconsistent voxels [S5, unofficial]. This approach is used in volumetric reconstruction to handle ambiguity in voxel coloring from multiple views [S5, unofficial].

### Manual Coloring
Manual Coloring is a straightforward approach where the user manually colors voxels, typically assigning a single uniform color to the object and floor from a palette [S6]. The user selects colors from a palette and assigns them to the objects in the scene, similar to a bucket fill tool [S6]. The network then shades the scene based on light position and generates global illumination effects [S6].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel for lookup, assuming a fixed-size LUT (256 entries) [S1, unofficial]. The overall complexity is $O(N)$ where $N$ is the number of voxels.
- **Memory Complexity:** $O(N)$ for the volume data and $O(1)$ for the colormap (256 entries) [S1, S4, unofficial].
- **Performance:** Fast due to simple table lookup and interpolation [S1, unofficial]. Using 1D texture maps enables more detail to be obtained from the visualization due to hardware-accelerated color interpolations between grid points [S1, unofficial].
- **Strengths:** Simple to implement, efficient, supports smooth gradients [S1, unofficial].
- **Limitations:** Straightforward value-to-opacity mapping may not accurately display surfaces; gradient-based opacity is needed for interfaces [S4, unofficial]. May lose precision with large data ranges and small bit depths [S4, unofficial].

## Background
Voxel Color Mapping originated as a basic technique for visualizing quantitative data in fire dynamics simulation tools like Smokeview [S1, unofficial]. It has been widely adopted in direct volume rendering and medical imaging, where classification processes convert original data values into opacity and color values indicating voxel importance [S4, unofficial]. The use of 1D texture maps for color lookup became standard in OpenGL-based renderers to leverage hardware interpolation [S1, S2, unofficial].
