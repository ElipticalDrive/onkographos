# Scalar/Component to Color Mapping

Also called: Target Value Visualization, Visualization Target Mapping, 颜色映射

## Overview
Scalar/Component to Color Mapping is the fundamental technique for visualizing scalar fields by mapping a single scalar value or a specific vector component to an RGB color using a 1D colormap [S1, S2, S3, unofficial]. It solves the problem of translating abstract numerical data into perceptible visual information, serving as the core color assignment step in direct volume rendering and surface visualization [S3, unofficial]. Unlike Palette-based Color Mapping, which assigns colors from a discrete set of predefined palettes often for categorical data, this method uses a continuous 2D texture (colormap) to provide smooth gradients, allowing for the representation of continuous magnitude or directional components [S1, S2, unofficial].

## How it works
The method maps a scalar input to a color by normalizing the input to a $[0, 1]$ range and sampling a 2D colormap texture. The implementation depends on whether the input is a raw scalar value or a specific component of a vector (normal).

### Inputs and Outputs
*   **Input**: A scalar value $v$ or a normal vector $\mathbf{n} = (n_x, n_y, n_z)$.
*   **Input**: A 2D colormap texture `u_colormap` (typically $N \times 1$ or $N \times M$ pixels, sampled at $y=0.5$) [S1, unofficial].
*   **Input**: A clim range `u_clim` = $[c_{min}, c_{max}]$ for scalar normalization [S1, unofficial].
*   **Input**: An enum `visualize_target` specifying the target: `VALUE`, `NORMAL_X`, `NORMAL_Y`, or `NORMAL_Z` [S2, unofficial].
*   **Output**: An RGBA color value.

### Data Structures
*   **Colormap Texture**: A 2D sampler texture `u_colormap`. In GLSL, this is typically `sampler2D`. The color is retrieved by sampling the x-coordinate corresponding to the normalized value and a fixed y-coordinate (usually 0.5 for horizontal colormaps) [S1, unofficial].
*   **Clim Range**: A `vec2` containing the lower and upper bounds of the value range for normalization [S1, unofficial].

### Steps
1.  **Determine Input Value**:
    *   If `visualize_target` is `VALUE`: The input is the scalar value $v$ [S2, unofficial].
    *   If `visualize_target` is `NORMAL_X`: The input is $n_x$ [S2, unofficial].
    *   If `visualize_target` is `NORMAL_Y`: The input is $n_y$ [S2, unofficial].
    *   If `visualize_target` is `NORMAL_Z`: The input is $n_z$ [S2, unofficial].

2.  **Normalize to [0, 1]**:
    *   For scalar values (`VALUE`):
        $$ t = \frac{v - c_{min}}{c_{max} - c_{min}} $$
        Clamp $t$ to $[0, 1]$ [S1, unofficial].
    *   For normal components (`NORMAL_X`, `NORMAL_Y`, `NORMAL_Z`):
        Normal components are in the range $[-1, 1]$. Map to $[0, 1]$ using:
        $$ t = \frac{n_{comp} + 1.0}{2.0} $$
        Clamp $t$ to $[0, 1]$ [S2, unofficial].

3.  **Sample Colormap**:
    *   Sample the 2D colormap texture at coordinate $(t, 0.5)$ [S1, unofficial].
    *   Return the RGB color with alpha 1.0 [S1, unofficial].

### Pseudocode
```python
def scalar_to_color(value, normal, visualize_target, u_clim, u_colormap):
    """
    Maps a scalar or normal component to a color using a 2D colormap.
    
    Args:
        value (float): The scalar value (used if visualize_target is VALUE).
        normal (Vec3): The normal vector (used if visualize_target is NORMAL_*).
        visualize_target (Enum): VALUE, NORMAL_X, NORMAL_Y, or NORMAL_Z.
        u_clim (Vec2): [c_min, c_max] for scalar normalization.
        u_colormap (Texture2D): The 2D colormap texture.
        
    Returns:
        Vec4: RGBA color.
    """
    t = 0.0
    
    if visualize_target == VALUE:
        # Normalize scalar value to [0, 1]
        c_min = u_clim[0]
        c_max = u_clim[1]
        # Guard against division by zero
        if c_max == c_min:
            t = 0.0
        else:
            t = (value - c_min) / (c_max - c_min)
        # Clamp to [0, 1]
        t = clamp(t, 0.0, 1.0)
        
    elif visualize_target == NORMAL_X:
        # Map normal.x from [-1, 1] to [0, 1]
        t = (normal.x + 1.0) / 2.0
        t = clamp(t, 0.0, 1.0)
        
    elif visualize_target == NORMAL_Y:
        # Map normal.y from [-1, 1] to [0, 1]
        t = (normal.y + 1.0) / 2.0
        t = clamp(t, 0.0, 1.0)
        
    elif visualize_target == NORMAL_Z:
        # Map normal.z from [-1, 1] to [0, 1]
        t = (normal.z + 1.0) / 2.0
        t = clamp(t, 0.0, 1.0)
        
    # Sample the 2D colormap texture at (t, 0.5)
    # Assuming standard texture sampling where x is the color dimension
    color = sample_2d_texture(u_colormap, vec2(t, 0.5))
    
    # Return RGB with alpha 1.0
    return vec4(color.rgb, 1.0)
```

### Parameters
*   **u_clim**: A `vec2` containing the lower and upper bounds of the value range for normalization [S1, unofficial].
*   **visualize_target**: Enum determining whether to visualize `NORMAL_X`, `NORMAL_Y`, `NORMAL_Z`, or `VALUE` [S2, unofficial].
*   **u_colormap**: A 2D sampler texture containing the color map [S1, unofficial].
*   **cm_type**: Colormap type (e.g., from `tinycolormap::ColormapType`) [S2, unofficial].

### Edge Cases and Pitfalls
*   **Division by Zero**: If `u_clim[1] == u_clim[0]`, the normalization step results in division by zero. The implementation must handle this, typically by defaulting to a neutral color or clamping the result to 0 [G].
*   **Logarithmic Scale**: If a logarithmic scale is used for the colormap (see *Scalar to Color Mapping Scale*), and the scalar range contains zero, the mapping defaults to linear to avoid undefined behavior (log(0)) [S5].
*   **Colormap Choice**: Rainbow colormaps suffer from "false boundary" artifacts due to non-uniform human perception of hue intervals. Perceptually uniform colormaps (e.g., Viridis) are preferred [S3, unofficial]. For data with positive/negative distinctions, a diverging colormap should be used [S3, unofficial].

### Scalar to Color Mapping Scale
Defines the type of scale used to map scalar values to the transfer function range [S5]. Options are linear or logarithmic (base 10) [S5]. Default scale type is linear [S5]. If the scale is set to logarithmic but the scalar range contains zero, the color mapping defaults to linear to avoid undefined behavior [S5].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per pixel/voxel. The operation involves a few arithmetic operations and a single texture lookup [S1, S2, unofficial].
*   **Memory Complexity**: $O(N)$ for the colormap texture, where $N$ is the number of colors in the colormap (typically small, e.g., 256 or 1024 entries) [S1, unofficial].
*   **Strengths**: Simple to implement, computationally inexpensive, provides smooth color transitions [S3, unofficial].
*   **Limitations**: Single-dimensional mapping loses information about other attributes (e.g., gradient magnitude) unless combined with other transfer function dimensions [S3, unofficial]. Rainbow colormaps can mislead perception [S3, unofficial].
*   **When to Use**: When visualizing a single scalar field or a specific vector component is sufficient. Ideal for direct volume rendering where color encodes density or material type [S1, S3, unofficial].
*   **When Not to Use**: When multiple attributes need to be encoded simultaneously (use 2D transfer functions) or when categorical data requires discrete palettes (use Palette-based Color Mapping) [S3, unofficial].

## Background
Scalar/Component to Color Mapping is the most common scalar field visualization method, mapping scalar values to a color space [S3, unofficial]. It originated with the development of scientific visualization techniques in the 1980s and 1990s, becoming a standard component of volume rendering pipelines [S3, unofficial]. Common schemes include Rainbow, Viridis, Diverging, Grayscale, and Hot [S3, unofficial]. The method is widely used in direct volume rendering, where it serves as the color assignment stage of the transfer function [S1, S3, unofficial].
