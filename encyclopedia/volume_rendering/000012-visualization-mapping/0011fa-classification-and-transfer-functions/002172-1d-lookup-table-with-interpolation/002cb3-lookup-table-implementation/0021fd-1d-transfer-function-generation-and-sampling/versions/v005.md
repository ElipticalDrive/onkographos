# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function, TF1D

## Overview
1D Transfer Function Generation and Sampling maps scalar voxel data values to color and opacity using a 1D lookup table (LUT) implemented as a texture [S1, book][S9]. It solves the problem of defining visual appearance for volume rendering by interpolating between user-defined control points to create a smooth mapping [S4, S7, unofficial]. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by relying on discrete interpolation between control points rather than analytic functions, and from [Voxel Color Mapping](2970-voxel-color-mapping.md) by explicitly managing opacity and color channels separately before sampling [S1, book][S2, unofficial].

## How it works
**Inputs:**
*   Scalar volume data (normalized to $[0, 1]$ or mapped via data bounds) [S3, S4, S6, unofficial].
*   Control points defining the transfer function. Each point consists of a scalar position (value) and associated color ($R, G, B$) and opacity ($\alpha$) [S4, S7, unofficial].
*   LUT resolution ($N$), typically 256, 1024, or 8192 [S4, S6, S7, unofficial].

**Outputs:**
*   A 1D texture (or array) of size $N$ containing 4-component vectors $(R, G, B, \alpha)$ [S1, book][S4, S7, unofficial].
*   Sampled color and opacity values for each voxel during rendering [S1, book].

**Data Structures:**
*   **Control Point:** A structure holding `value` (float/int) and `color` (TFColor) [S4, unofficial]. `TFColor` contains `r`, `g`, `b`, `a` (floats in $[0, 1]$) [S4, unofficial].
*   **LUT Array:** A 1D array of size $N$ (resolution) storing `vec4f` (RGBA) values [S7, unofficial].
*   **Alpha Array:** (Optional) Separate 1D array of size $N$ for alpha control, often combined with color into the LUT [S7, unofficial].

**Steps:**

1.  **Initialize Control Points:**
    *   Collect user-defined control points. Each point $i$ has a position $p_i$ and color $c_i = (r_i, g_i, b_i, a_i)$ [S4, S7, unofficial].
    *   Sort control points by position $p_i$ in ascending order [S7, unofficial].
    *   If no control points are defined, insert a default point (e.g., position 0, color black/transparent) [S7, unofficial].

2.  **Generate LUT Entries:**
    *   Iterate through each index $k$ from $0$ to $N-1$ [S7, unofficial].
    *   Compute the normalized scalar value $v$ corresponding to index $k$. Two common binning strategies exist:
        *   **Center-aligned:** $v = \frac{k + 0.5}{N}$ [S7, unofficial].
        *   **Edge-aligned:** $v = \frac{k}{N - 1}$ [S7, unofficial].
        *   *Note:* Inconsistent binning between color and alpha generation can cause misalignment [S7, unofficial].
    *   Find the interval $[p_L, p_R]$ in the sorted control points such that $p_L \le v < p_R$ [S7, unofficial].
    *   **Boundary Handling:**
        *   If $v < p_0$ (first control point), use $c_0$ [S7, unofficial].
        *   If $v \ge p_{last}$ (last control point), use $c_{last}$ [S7, unofficial].
    *   **Interpolation:**
        *   Calculate interpolation weight $w$:
            $$ w = \frac{|v - p_L|}{|p_R - p_L|} $$
            [S7, unofficial]
        *   Interpolate color components:
            $$ c = \text{mix}(c_L, c_R, w) $$
            where $\text{mix}(a, b, w) = a(1-w) + bw$ [S7, unofficial].
        *   Interpolate alpha similarly if alpha is controlled separately, or use the alpha from the color control point [S7, unofficial].
    *   **Gaussian Opacity (Optional):**
        *   If Gaussian objects are defined, compute their contribution to alpha at index $k$ and update the LUT alpha:
            $$ \alpha_{final}[k] = \max(\alpha_{LUT}[k], \alpha_{Gaussian}[k]) $$
            [S7, unofficial]
    *   Store the resulting RGBA vector in `LUT[k]` [S7, unofficial].

3.  **Upload to GPU:**
    *   Create a 1D texture object (e.g., `GL_TEXTURE_1D` or CUDA 1D texture) with format RGBA [S1, book][S3, S7, unofficial].
    *   Set texture parameters:
        *   Wrap mode: `Clamp` or `Clamp-to-Edge` to handle out-of-bounds coordinates [S3, S7, unofficial].
        *   Filter mode: `Linear` or `Bilinear` for smooth interpolation [S3, S7, unofficial].
    *   Upload the LUT array data to the texture [S7, unofficial].

4.  **Sampling (Rendering):**
    *   For each voxel, read its scalar value $x$ [S1, book].
    *   Normalize $x$ to $[0, 1]$ using volume bounds $x_{min}, x_{max}$:
        $$ x_{norm} = \frac{x - x_{min}}{x_{max} - x_{min}} $$
        [S3, S4, S6, unofficial]
    *   Clamp $x_{norm}$ to $[0, 1]$ [S3, S4, S6, unofficial].
    *   Sample the 1D texture at coordinate $x_{norm}$ to retrieve color $C$ and opacity $\alpha$ [S1, book].
    *   **Opacity-Weighted Color:** Multiply color components by opacity for correct compositing:
        $$ C_{final} = C \cdot \alpha $$
        [S1, book][S9]

**Pseudocode:**

```python
import math

def generate_1d_tf(control_points, resolution=1024):
    """
    Generates a 1D transfer function LUT from control points.
    
    Args:
        control_points: List of dicts with keys 'pos' (float), 'color' (list of 4 floats [r,g,b,a]).
        resolution: Integer size of the LUT.
        
    Returns:
        List of vec4f (tuples of 4 floats) representing the LUT.
    """
    if not control_points:
        # Default control point if none provided
        control_points = [{'pos': 0.0, 'color': [0.0, 0.0, 0.0, 0.0]}]
    
    # Sort control points by position
    control_points.sort(key=lambda p: p['pos'])
    
    n_controls = len(control_points)
    lut = [None] * resolution
    
    # Use center-aligned binning as per [S7, unofficial]
    for i in range(resolution):
        # Compute normalized value for this bin
        value = (i + 0.5) / resolution
        
        # Find interval
        # upper_bound returns the first control point with pos > value
        # We need to find the index of this upper bound
        ub_index = 0
        for idx, cp in enumerate(control_points):
            if cp['pos'] > value:
                ub_index = idx
                break
        else:
            ub_index = n_controls # Value is beyond last control point
        
        # Determine left and right control points
        if ub_index <= 0:
            # Value is before or at the first control point
            left_cp = control_points[0]
            right_cp = control_points[0]
            w = 0.0
        elif ub_index >= n_controls:
            # Value is after or at the last control point
            left_cp = control_points[-1]
            right_cp = control_points[-1]
            w = 0.0
        else:
            # Interpolate between left_cp (ub_index - 1) and right_cp (ub_index)
            left_cp = control_points[ub_index - 1]
            right_cp = control_points[ub_index]
            
            # Calculate interpolation weight
            pos_left = left_cp['pos']
            pos_right = right_cp['pos']
            
            # Avoid division by zero if duplicate positions exist
            if pos_right == pos_left:
                w = 0.0
            else:
                w = abs(value - pos_left) / abs(pos_right - pos_left)
        
        # Interpolate color
        c_left = left_cp['color']
        c_right = right_cp['color']
        
        r = c_left[0] * (1 - w) + c_right[0] * w
        g = c_left[1] * (1 - w) + c_right[1] * w
        b = c_left[2] * (1 - w) + c_right[2] * w
        a = c_left[3] * (1 - w) + c_right[3] * w
        
        lut[i] = (r, g, b, a)
        
    return lut

def sample_tf(lut, value, vmin, vmax):
    """
    Samples the 1D TF for a given scalar value.
    
    Args:
        lut: List of vec4f from generate_1d_tf.
        value: Scalar voxel value.
        vmin: Minimum scalar value of the volume.
        vmax: Maximum scalar value of the volume.
        
    Returns:
        Tuple (color, opacity) where color is (r,g,b) and opacity is float.
    """
    if vmax == vmin:
        return (0.0, 0.0, 0.0), 0.0
        
    # Normalize value to [0, 1]
    norm_val = (value - vmin) / (vmax - vmin)
    
    # Clamp to [0, 1]
    norm_val = max(0.0, min(1.0, norm_val))
    
    # Map to LUT index
    # Using edge-aligned mapping for sampling to match generation if generation used edge-aligned
    # However, generation used center-aligned. For consistency with hardware texture sampling,
    # we typically map [0,1] directly to texture coordinates.
    # If LUT was generated with center-aligned bins, the texture coordinate should align with bin centers.
    # Standard GPU texture sampling maps [0,1] to the full texture range.
    
    # Calculate index based on normalized value
    # Note: Hardware linear interpolation handles the fractional part.
    # We need to map norm_val to a float index in [0, resolution-1]
    resolution = len(lut)
    index_float = norm_val * (resolution - 1)
    
    index = int(index_float)
    frac = index_float - index
    
    # Clamp index
    index = max(0, min(resolution - 1, index))
    
    # Get left and right colors
    c_left = lut[index]
    if index < resolution - 1:
        c_right = lut[index + 1]
    else:
        c_right = c_left
        
    # Interpolate
    r = c_left[0] * (1 - frac) + c_right[0] * frac
    g = c_left[1] * (1 - frac) + c_right[1] * frac
    b = c_left[2] * (1 - frac) + c_right[2] * frac
    a = c_left[3] * (1 - frac) + c_right[3] * frac
    
    # Opacity-weighted color
    color = (r * a, g * a, b * a)
    
    return color, a
```

## Subtopics

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S10, unofficial]. It implements the LUT by mapping HU values to colors, where water is 0 HU, air is -1000 HU, and bone is 500–1500 HU [S10, unofficial]. The HU value is calculated as $HU = \frac{\mu_{tissue} - \mu_{water}}{\mu_{water}} \times 1000$ [S10, unofficial].

### Magnitude Color Gradient
A linear blue-green-red gradient stored in a 1D CUDA texture to visualize vector magnitude (velocity), where blue is lowest and red is highest [S11, unofficial]. It queries the interpolated color using `tex1D` on the GPU [S11, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S2, unofficial]. The interpolated color is calculated as the average of two colors: $interpolated\ color = (f(c_1) + f(c_2))/2$, where $c_1$ and $c_2$ are integer indices [S2, unofficial]. This causes artifacts (e.g., purple between red and blue) because the result may not lie on the defined colorbar [S2, unofficial].

### Gradient/Color Ramp Sampling
Reads luminance in float and truncates each channel for the color ramp, as implemented in Godot [S12, unofficial]. It runs the Gradient sampler and channel-to-byte conversion in float [S12, unofficial]. A pitfall is that `GradientTexture2D` with `use_hdr` keeps a channel above 1 [S12, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates using `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S13, unofficial]. This ensures corner pixels align with grid boundaries [S13, unofficial].

### Color Blending
Linearly interpolates between two colors based on a ratio, handling alpha, red, green, and blue channels separately [S14, unofficial]. The formula for each channel is $result = round(c1.ch \cdot (1 - ratio) + c2.ch \cdot ratio)$, with alpha taken from $c1$ [S14, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two 1D LUT textures (soft and hard) for labelmap transfer functions [S3, unofficial]. The soft LUT uses float precision and bilinear filtering; the hard LUT uses byte precision and point filtering [S3, unofficial]. It initializes arrays, maps label indices to LUT entries, converts float colors to byte, and uploads to GPU textures [S3, unofficial]. The LUT size is constant 256 [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** LUT generation is $O(N \cdot C)$, where $N$ is the LUT resolution and $C$ is the number of control points (for linear search) or $O(N \log C)$ if binary search is used [S7, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
*   **Memory Complexity:** $O(N)$ for the LUT storage [S7, unofficial].
*   **Performance:** Linear interpolation is fast and hardware-accelerated [S4, S6, unofficial].
*   **Strengths:** Simple to implement, smooth transitions, widely supported by GPU hardware [S1, book][S4, unofficial].
*   **Limitations:** Limited to scalar data; cannot capture complex multi-dimensional relationships without extension (e.g., 2D TFs) [S1, book]. Linear interpolation may not capture sharp features as well as higher-order methods [S4, unofficial].
*   **When to Use:** Standard volume rendering with scalar data [S1, book].
*   **When Not to Use:** When multi-dimensional data (e.g., gradient magnitude) is needed for classification [S1, book].

## Background
1D transfer functions were introduced as a simple and widely used method for volume rendering, mapping data values to color and opacity [S1, book]. They are typically implemented with 1D texture lookup tables [S1, book][S9]. The concept of interpolating color indices rather than colors to stay within a defined colorbar was highlighted in Smokeview documentation [S2, unofficial]. The opacity-weighted color multiplication was established by Wittenbrink et al. (1998) [S1, book][S9].
