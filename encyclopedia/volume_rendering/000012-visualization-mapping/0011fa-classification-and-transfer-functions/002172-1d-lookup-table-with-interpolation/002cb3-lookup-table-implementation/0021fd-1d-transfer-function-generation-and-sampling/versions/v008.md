# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function, TF1D

## Overview
1D Transfer Function Generation and Sampling maps scalar volume data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) [S1, book][S9]. It solves the problem of classifying volumetric features by translating numerical intensity into visual appearance, serving as the core classification step in ray-casting pipelines [S1, book][S5, unofficial]. Unlike [Parametric Function Generation](5349-parametric-function-generation.md), which uses continuous analytic expressions, this method relies on discrete control points and explicit interpolation [S1, book][S4, unofficial]. It differs from [3D Color Cube Interpolation](5349-parametric-function-generation.md#3d-color-cube-interpolation) by interpolating indices within a 1D colorbar rather than colors in 3D RGB space, thereby preventing artifacts like unintended purple hues when blending red and blue regions [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A set of control points defining the transfer function, where each point consists of a scalar position $p$ and a color $\mathbf{c} = (r, g, b)$ and opacity $\alpha$. The scalar domain is typically normalized to $[0, 1]$ using the volume's minimum ($x_{min}$) and range ($x_{max} - x_{min}$) [S3, S4, unofficial].
*   **Output**: A 1D texture (LUT) of size $N$ (typically a power of two, e.g., 256, 1024) containing RGBA values, ready for GPU sampling [S6, S7, S8, unofficial].

**Data Structures**
*   **ControlPoint**: A structure containing `value` (float/int, the scalar position) and `color` (TFColor).
*   **TFColor**: A structure containing `r`, `g`, `b`, `a` (all floats in $[0, 1]$) [S4, unofficial].
*   **LUT Array**: A 1D array of size $N$ (resolution) storing `vec4f` (RGBA) values. In OpenGL, this is often a `Texture2D` of size $N \times 1$ with format `RGBAFloat` or `RGBA8` [S3, S7, unofficial].

**Algorithm Steps**
1.  **Initialization**: Create an empty list of control points. If no points are defined, insert a default point (e.g., position 0.0, color (0,0,0,0)) [S7, unofficial].
2.  **Sorting**: Sort the control points by their scalar `value` in ascending order [S4, S7, unofficial].
3.  **LUT Construction**: Iterate through each index $i$ of the LUT from $0$ to $N-1$:
    a.  **Normalize Index**: Compute the normalized scalar value $v$ corresponding to index $i$. Two common binning strategies exist:
        *   Center-aligned: $v = \frac{i + 0.5}{N}$ [S7, unofficial].
        *   Edge-aligned: $v = \frac{i}{N - 1}$ [S7, S3, unofficial].
        *   *Note*: Inconsistent binning between color and alpha generation can cause misalignment [S7, unofficial].
    b.  **Find Interval**: Locate the two adjacent control points, `left` and `right`, such that `left.value` $\le v \le$ `right.value`. Use binary search (e.g., `std::upper_bound`) to find the first control point with position $> v$; the previous point is `left` [S7, unofficial].
    c.  **Boundary Handling**:
        *   If $v \le$ `left.value` (or `left` is the first point), set color = `left.color` and alpha = `left.alpha` [S7, unofficial].
        *   If $v \ge$ `right.value` (or `right` is the last point), set color = `right.color` and alpha = `right.alpha` [S7, unofficial].
    d.  **Interpolation**: If strictly between points, compute the interpolation weight $w$:
        $$ w = \frac{|v - \text{left.value}|}{|\text{right.value} - \text{left.value}|} $$
        Interpolate color and alpha:
        $$ \mathbf{c}_{new} = \text{mix}(\mathbf{c}_{left}, \mathbf{c}_{right}, w) $$
        $$ \alpha_{new} = \text{mix}(\alpha_{left}, \alpha_{right}, w) $$
        where $\text{mix}(a, b, w) = a(1-w) + b \cdot w$ [S7, unofficial].
    e.  **Combine with Gaussian Objects**: If Gaussian opacity objects are present, compute their contribution at $v$ and update the alpha channel:
        $$ \alpha_{final} = \max(\alpha_{new}, \alpha_{gaussian}(v)) $$
        This uses maximum compositing for opacity, allowing Gaussians to override but not attenuate base opacity [S7, unofficial].
    f.  **Store**: Set `LUT[i] = vec4f(c_new.r, c_new.g, c_new.b, alpha_final)` [S7, unofficial].
4.  **Upload**: Upload the LUT array to GPU memory as a 1D texture with `GL_LINEAR` (bilinear) filtering and `GL_CLAMP_TO_EDGE` wrapping [S3, S7, unofficial].

**Pseudocode**
```python
def generate_1d_lut(control_points, resolution=1024):
    """
    Generates a 1D LUT from sorted control points.
    control_points: list of dicts {'value': float, 'color': [r,g,b], 'alpha': float}
    resolution: int, size of the LUT
    returns: list of [r, g, b, a] tuples
    """
    if not control_points:
        control_points = [{'value': 0.0, 'color': [0.0, 0.0, 0.0], 'alpha': 0.0}]
    
    # Sort by value
    control_points.sort(key=lambda p: p['value'])
    n = len(control_points)
    lut = [None] * resolution
    
    for i in range(resolution):
        # Center-aligned binning
        v = (i + 0.5) / resolution
        
        # Find interval
        # upper_bound returns first element > v
        upper_idx = 0
        for k in range(n):
            if control_points[k]['value'] > v:
                upper_idx = k
                break
        else:
            upper_idx = n
            
        if upper_idx == 0:
            # Below all points
            cp = control_points[0]
            r, g, b, a = cp['color'][0], cp['color'][1], cp['color'][2], cp['alpha']
        elif upper_idx >= n:
            # Above all points
            cp = control_points[-1]
            r, g, b, a = cp['color'][0], cp['color'][1], cp['color'][2], cp['alpha']
        else:
            # Between upper_idx-1 and upper_idx
            left = control_points[upper_idx - 1]
            right = control_points[upper_idx]
            
            denom = right['value'] - left['value']
            if denom == 0:
                w = 0.0
            else:
                w = abs(v - left['value']) / denom
            
            r = left['color'][0] + w * (right['color'][0] - left['color'][0])
            g = left['color'][1] + w * (right['color'][1] - left['color'][1])
            b = left['color'][2] + w * (right['color'][2] - left['color'][2])
            a = left['alpha'] + w * (right['alpha'] - left['alpha'])
            
        # Optional: Combine with Gaussian alpha (max)
        # a = max(a, gaussian_alpha(v))
        
        # Alpha normalization (optional, per source)
        # a = floor(a * 100) / 100.0
        
        lut[i] = [r, g, b, a]
        
    return lut

def sample_lut(lut, value, s_min, s_range):
    """
    Samples the LUT for a given scalar value.
    value: raw scalar from volume
    s_min: minimum scalar value of volume
    s_range: max - min of volume
    """
    # Normalize to [0, 1]
    norm_v = (value - s_min) / s_range
    # Clamp to [0, 1]
    norm_v = max(0.0, min(1.0, norm_v))
    
    # Map to index
    # Using center-aligned logic for consistency with generation
    index = int((len(lut) - 1) * norm_v)
    
    return lut[index]
```

**Parameters**
*   `resolution`: Size of the LUT. Default 1024, commonly 256 or 8192 [S7, S8, unofficial].
*   `s_min`, `s_range`: Volume data range for normalization [S3, S4, unofficial].

**Edge Cases and Pitfalls**
*   **Color Artifacts**: Interpolating RGB values directly (3D color cube) can produce colors outside the defined colorbar (e.g., purple between red and blue). Interpolating indices or using 1D texture maps prevents this [S2, unofficial].
*   **Opacity-Weighted Color**: For correct rendering, the sampled color components must be multiplied by the opacity (emission/absorption approximation) [S1, book][S9].
*   **Alpha Combination**: Using `max` for Gaussian alpha overrides base opacity but does not attenuate it. Multiplicative blending is an alternative not described in the primary sources [S7, unofficial].
*   **Binning Misalignment**: Using different binning formulas (center vs. edge) for color and alpha generation causes slight misalignment at boundaries [S7, unofficial].

## Subtopics

### [Voxel Color Mapping](2970-voxel-color-mapping.md)
Voxel Color Mapping maps scalar data values to integer indices for direct lookup in a color table, translating numerical volume data into visual appearance. It serves as the final step in the classification pipeline, distinct from complex transfer functions that map multiple attributes to opacity and color; instead, it performs a direct lookup based on a normalized input, often used for maximum intensity projection or surface visualization where opacity is fixed or handled separately. Unlike [Parametric Function Generation](5349-parametric-function-generation.md) which computes colors via continuous functions, this method relies on discrete table indexing.

### [Color Specification](3969-color-specification.md)
Color Specification defines the RGBA (Red, Green, Blue, Alpha) representation used to map scalar voxel values to visual colors in volume rendering. It solves the problem of translating abstract data values into perceptible color and opacity for display. It differs from [Voxel Color Mapping](2970-voxel-color-mapping.md) by focusing on the fundamental component definition rather than the spatial mapping strategy, and from [Parametric Function Generation](5349-parametric-function-generation.md) by specifying discrete values rather than continuous functions. It builds on [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by providing the atomic color units sampled from the transfer function.

### [Color Blending](5150-color-blending.md)
Color Blending is the final compositing step in volume rendering that combines the color and opacity contributions of multiple samples along a ray into a single pixel color. It solves the problem of accumulating translucent volume data into a coherent 2D image by applying alpha compositing rules. It is distinguished from [Voxel Color Mapping](2970-voxel-color-mapping.md) (which maps scalar values to colors) and [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) (which generates the color map) by operating on the accumulated RGBA values rather than individual voxel properties.

### [Parametric Function Generation](5349-parametric-function-generation.md)
Parametric Function Generation defines transfer functions (TFs) using closed-form mathematical expressions rather than discrete control points or piecewise linear segments. It solves the problem of defining smooth, continuous, and differentiable color/opacity mappings with a small set of global parameters, enabling automatic generation, optimization, and smooth interpolation. It differs from [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md), which relies on explicit key-value pairs and interpolation, by providing a compact, analytic representation that is inherently smooth and often differentiable, facilitating gradient-based tuning.

### [Transfer Function Editor (Alpha Pins)](6772-transfer-function-editor-alpha-pins.md)
The Transfer Function Editor (Alpha Pins) is an interactive visualization tool that maps scalar voxel values $S(x,y,z)$ to color vectors $F(x,y,z)$ and opacity $\alpha_F(x,y,z)$. It distinguishes itself from other classification methods by using a pin-based interface where users manipulate specific geometric primitives (ramps, hats, blanks) to define opacity and vertical color markers to define gradients, rather than editing a continuous curve or parametric function directly.

### [Colormap LUT Generation](7229-colormap-lut-generation.md)
Colormap LUT Generation constructs a fixed-size lookup table (LUT) that maps scalar values to RGBA colors using a predefined named colormap (e.g., Viridis, Jet, Inferno). It differs from manual transfer function definition by abstracting the color gradient into a standard library type, ensuring perceptual uniformity or specific visual properties defined by the colormap standard.

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S10, unofficial]. It implements the formula $\text{HU} = \frac{\mu_{\text{tissue}} - \mu_{\text{water}}}{\mu_{\text{water}}} \times 1000$ [S10, unofficial]. Water has a HU value of 0, air -1000, and bone 500–1500 [S10, unofficial]. Implemented as a LUT where a color value is read out for a given HU value [S10, unofficial].

### Magnitude Color Gradient
A linear blue-green-red gradient stored in a 1D CUDA texture to visualize vector magnitude (velocity), where blue is lowest and red is highest [S11, unofficial]. Gradient values are stored in a 1D texture on GPU and queried using `tex1D` for interpolated color [S11, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S2, unofficial]. The interpolated color is calculated as the average: $\text{interpolated color} = (f(c_1) + f(c_2))/2$, where $c_1$ and $c_2$ are integer indices [S2, unofficial]. Pitfall: Interpolating colors directly causes artifacts near large gradients (e.g., fire); for example, interpolating between red (1,0,0) and blue (0,0,1) yields purple (0.5,0.0,0.5), which is not in the colorbar and has no physical meaning [S2, unofficial].

### Gradient/Color Ramp Sampling
Reads luminance in float and truncates each channel for the colour ramp shared with NoiseTexture2D, as Godot does [S12, unofficial]. Runs Gradient sampler and channelToByte in float [S12, unofficial]. Pitfall: A GradientTexture2D with use_hdr keeps a channel above 1 [S12, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates. Takes `images` tensor of shape `[batch_size, H, W, C]` and `xy_grid` of shape `[N, 2]`. Flips `xy_grid` sign, reshapes to `[batch_size, N, 1, 2]`. Permutes images to `[batch_size, C, H, W]`. Uses `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S13, unofficial]. Parameter `align_corners=True` ensures corner pixels align with grid boundaries during interpolation, preventing coordinate scaling artifacts at image edges [S13, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two 1D LUT textures (soft and hard) for labelmap transfer functions. The soft LUT uses float precision and bilinear filtering; the hard LUT uses byte precision and point filtering [S3, unofficial]. LUT size is constant 256 [S3, unofficial]. Steps: Initialize float/byte arrays; iterate entries, clamp label to index, extract RGBA; convert float [0,1] to byte [0,255]; create `Texture2D` with appropriate formats and filters; upload [S3, unofficial].

### 2D Transfer Function
A volume rendering technique that maps two separate scalar fields to color and opacity using a 2D lookup table (image), extending the 1D transfer function approach [S14]. Parameters: `value` (primary scalar field), `valueRange` (default [0,1]), `lookupTable` (2D array of Colors) [S14]. Pitfall: Ambiguity in mapping scalar fields to the 2D lookup table axes; prescriptive interpretation is X-axis = `value`, Y-axis = `grad(value)` [S14]. Comparison: Unlike separable 1D transfer functions, 2D TFN allows non-separable, arbitrary 2D mappings [S14].

## Operating characteristics
*   **Time Complexity**: LUT construction is $O(N \cdot K)$ or $O(N \log K)$ depending on whether linear scan or binary search is used for interval finding, where $N$ is LUT resolution and $K$ is the number of control points [S7, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
*   **Memory Complexity**: $O(N)$ for the LUT storage [S7, unofficial].
*   **Performance**: Hardware-accelerated 1D texture sampling is extremely fast, making this the standard method for real-time volume rendering [S1, book][S2, unofficial].
*   **Strengths**: Simple to implement, efficient, supports smooth interpolation via hardware filters [S4, S7, unofficial].
*   **Limitations**: Limited to single-scalar input; cannot capture correlations between multiple attributes (e.g., gradient magnitude) without extending to 2D TFs [S1, book][S14]. Linear interpolation may not capture complex feature boundaries as well as higher-order methods [S4, unofficial].

## Background
The 1D transfer function is the simplest and most widely used transfer function in volume rendering, mapping the range of data values to color and opacity [S1, book][S9]. It is typically implemented with 1D texture lookup tables [S1, book][S9]. The concept of using 1D texture maps to interpolate color indices (rather than colors) to avoid artifacts was highlighted in the Smokeview technical reference [S2, unofficial]. The method is foundational in GPU Gems and other graphics literature [S1, book][S9].
