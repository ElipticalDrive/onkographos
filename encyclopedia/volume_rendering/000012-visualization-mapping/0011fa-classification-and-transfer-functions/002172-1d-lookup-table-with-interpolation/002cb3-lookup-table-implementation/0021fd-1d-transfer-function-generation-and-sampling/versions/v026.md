# 1D Transfer Function Generation and Sampling

Also called: 1-D colour LUT, 1D Transfer Function (LUT), TF1D, Opacity Points, RGBPoints, Transfer Function Interpolation

## Overview
1D Transfer Function Generation and Sampling maps scalar voxel data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) or texture [S1, book]. It solves the problem of translating abstract numerical intensity data into perceptible visual information, serving as the core classification step in direct volume rendering [G]. Unlike [2D Transfer Function](7592-2d-transfer-function.md) which maps two scalar fields, this method relies on a single scalar measure, typically voxel intensity, to determine optical properties [S1, book]. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by using piecewise linear interpolation between discrete control points rather than continuous analytical functions, and from [Hardcoded Transfer Function](1098-hardcoded-transfer-function.md) by allowing dynamic, user-defined mapping [S5, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of control points defining the mapping, where each point consists of a scalar value (position) and an RGBA color/opacity tuple [S6, unofficial][S9, unofficial]. Optional inputs include Gaussian objects for opacity shaping and a target LUT resolution (typically 256, 1024, or 65536 entries) [S9, unofficial].
*   **Output:** A 1D texture (or contiguous array) of size $N$ containing interpolated RGBA values, ready for GPU sampling [S2, unofficial][S9, unofficial].

**Data Structures**
*   **Control Point:** A structure containing `value` (float/int, normalized or raw) and `color` (vec4: r, g, b, a floats in [0,1]) [S5, unofficial][S9, unofficial].
*   **LUT Array:** A contiguous array of size $N$ (power of two) storing `vec4` entries. Common formats are `float32` (RGBA32F) or `uint8` (RGBA8) [S2, unofficial][S9, unofficial].
*   **Gaussian Object (Optional):** Defined by `mean`, `sigma`, and `heightFactor`, generating an `alphaArray` of size $N$ [S9, unofficial].

**Steps**

1.  **Initialization:** Create an empty list of control points. If no points are provided, insert a default point (e.g., value 0.0, color 0,0,0,0) [S9, unofficial].
2.  **Sorting:** Sort control points by their scalar `value` in ascending order [S9, unofficial].
3.  **LUT Construction:** Iterate through each index $i$ from $0$ to $N-1$ to fill the LUT:
    a.  **Normalization:** Compute the normalized scalar value $v$ corresponding to index $i$. Two binning schemes exist:
        *   Center-aligned: $v = \frac{i + 0.5}{N}$ [S9, unofficial].
        *   Edge-aligned: $v = \frac{i}{N-1}$ [S9, unofficial].
        *   *Note:* Inconsistent binning between color and alpha generation can cause boundary misalignment [S9, unofficial].
    b.  **Interval Search:** Find the two adjacent control points, `left` and `right`, such that `left.value` $\le v \le$ `right.value`. Use `upper_bound` to find the first control point with value $> v$; `right` is this point, `left` is the previous one [S9, unofficial].
    c.  **Clamping:** If $v$ is below the first control point, use the first point. If above the last, use the last point [S9, unofficial].
    d.  **Interpolation Weight:** Calculate the interpolation weight $w$:
        $$ w = \frac{|v - \text{left.value}|}{|\text{right.value} - \text{left.value}|} $$
        *Pitfall:* Division by zero occurs if `left.value` equals `right.value` (duplicate control points) [S8, unofficial].
    e.  **Color Interpolation:** Interpolate RGB components:
        $$ \text{color} = \text{mix}(\text{left.color}, \text{right.color}, w) $$
        *Pitfall:* Do not interpolate colors directly in 3D RGB space if the goal is to stay within a specific colorbar; instead, interpolate indices or use 1D texture mapping to ensure colors remain valid [S3, unofficial].
    f.  **Alpha Handling:**
        *   Interpolate alpha from color control points if separate alpha controls are not used [S9, unofficial].
        *   If Gaussian objects are present, compute their contribution at index $i$ and combine with the control point alpha using maximum: $\alpha_{final} = \max(\alpha_{control}, \alpha_{gaussian})$ [S9, unofficial].
        *   *Pitfall:* Using `max` overrides opacity rather than blending it [S9, unofficial].
    g.  **Storage:** Store the resulting RGBA vector in `LUT[i]` [S9, unofficial].
4.  **Post-Processing (Optional):** Apply brightness scaling to RGB channels: $\text{color.rgb} \times \text{brightness}$ [S12, unofficial].
5.  **Upload:** Upload the LUT array to GPU memory as a 1D texture (`GL_TEXTURE_1D`) or a 2D texture with height 1 (`GL_TEXTURE_2D`) [S2, unofficial][S9, unofficial]. Set wrap mode to `CLAMP_TO_EDGE` and filter mode to `LINEAR` (bilinear) for hardware interpolation [S2, unofficial][S9, unofficial].

**Pseudocode**

```python
from typing import List

class ControlPoint:
    def __init__(self, value: float, color: List[float]):
        self.value = value
        self.color = color  # [r, g, b, a]

def generate_1d_lut(control_points: List[ControlPoint], resolution: int = 256) -> List[List[float]]:
    """
    Generates a 1D LUT from control points.
    Returns: list of [r, g, b, a]
    """
    if not control_points:
        control_points = [ControlPoint(value=0.0, color=[0.0, 0.0, 0.0, 0.0])]
    
    control_points.sort(key=lambda cp: cp.value)
    n = len(control_points)
    lut = []
    
    for i in range(resolution):
        v = (i + 0.5) / resolution  # Center-aligned binning [S9, unofficial]
        
        # Find interval using upper_bound logic
        idx = 0
        for k in range(n):
            if control_points[k].value > v:
                idx = k
                break
        else:
            idx = n
            
        if idx == 0:
            left = control_points[0]
            right = control_points[0]
        elif idx == n:
            left = control_points[n-1]
            right = control_points[n-1]
        else:
            left = control_points[idx-1]
            right = control_points[idx]
            
        denom = right.value - left.value
        w = 0.0 if denom == 0 else (v - left.value) / denom
            
        r = left.color[0] + w * (right.color[0] - left.color[0])
        g = left.color[1] + w * (right.color[1] - left.color[1])
        b = left.color[2] + w * (right.color[2] - left.color[2])
        a = left.color[3] + w * (right.color[3] - left.color[3])
        
        lut.append([r, g, b, a])
        
    return lut
```

**Parameters**
*   **Resolution ($N$):** Size of the LUT. Must be a power of two for hardware texture support [G]. Common values: 256 (8-bit data), 1024, 65536 (16-bit data) [S2, unofficial][S8, unofficial][S9, unofficial].
*   **Brightness Factor:** Multiplier for RGB channels, default 1.0 [S12, unofficial].

### [Parametric Function Generation](5349-parametric-function-generation.md)
Constructs transfer functions by evaluating mathematical functions of a normalized scalar input. Sets itself apart by defining the mapping through continuous analytical formulas rather than piecewise linear interpolation. Choose when high-order smoothness is required.

Procedural creation of a 1D LUT from a named colormap definition. Sets itself apart by generating the table procedurally rather than from user control points. Choose when applying standard named colormaps.

### [2D Transfer Function](7592-2d-transfer-function.md)
Maps two separate scalar fields to color and opacity using a 2D LUT. Sets itself apart by enabling non-separable, arbitrary 2D mappings. Choose when comparing and contrasting spatial features of two fields.

### [Bipolar Scalar-to-Color Mapping with Level Set Support](13036-bipolar-scalar-to-color-mapping-with-level-set-support.md)
Maps scalar voxel values to RGB using a bipolar LUT treating positive and negative values independently. Sets itself apart by maintaining separate color ranges for opposing scalar signs. Choose when distinct visual encoding for opposing signs is needed.

### [Color Table Filtering](16454-color-table-filtering.md)
Anti-aliasing technique filtering the color table itself rather than the noise function. Sets itself apart by relying on MIP-mapping the color table to approximate the integral. Choose when anti-aliasing procedural textures.

### [Discrete Terrain Color Mapping](17937-discrete-terrain-color-mapping.md)
Assigns specific terrain types and palette indices based on discrete height levels. Sets itself apart by using strict range checks rather than blending. Choose when mapping scalar elevation data to categorical visual classes.

### [1D Texture Color Mapping](18347-1d-texture-color-mapping.md)
Visualizes scalar fields on surfaces by mapping values to texture coordinates in a 1D color ramp. Sets itself apart by operating on surface geometry rather than volumetric voxels. Choose when avoiding interpolation artifacts on sparsely tessellated geometry.

### [Discrete Color Table Lookup](22230-discrete-color-table-lookup.md)
Maps volumetric scalar data to RGBA using a user-defined LUT with linear interpolation. Sets itself apart by relying on a fixed-size discrete array rather than continuous functions. Choose when a fixed discrete mapping is preferred.

## Operating characteristics
*   **Time Complexity:** LUT generation is $O(N \cdot C)$, where $N$ is resolution and $C$ is the number of control points (using binary search, $O(N \log C)$) [S9, unofficial]. Rendering lookup is $O(1)$ per sample via texture fetch [S1, book].
*   **Memory Complexity:** $O(N)$ for the LUT storage [G]. For $N=256$ and `float32`, this is 4 KB [S2, unofficial].
*   **Performance:** Hardware interpolation (LINEAR filter) is efficient on GPUs. Direct lookup (nearest neighbor) is faster but less smooth [S2, unofficial][S3, unofficial].
*   **Strengths:** Supports smooth transitions via linear interpolation between control points [S5, unofficial].
*   **Limitations:** Limited to single-scalar data. Cannot capture correlations between multiple properties (requires 2D TF) [S1, book]. Interpolation artifacts if colorbar is not linear in perceptual space [S3, unofficial].
*   **When to use:** Standard volume rendering of scalar fields (CT, MRI, simulations) [S1, book][S3, unofficial].
*   **When not to use:** When visualizing relationships between two variables (use 2D TF) [S1, book].

## Background
The 1D transfer function is the most widely used classification method in volume rendering, introduced in early GPU Gems chapters and standard graphics pipelines [S1, book]. It maps data values to optical properties (color and opacity) to emphasize features [S1, book]. The use of 1D texture maps for interpolation ensures colors remain within the defined colorbar, avoiding artifacts associated with 3D color cube interpolation [S3, unofficial]. It is implemented in various tools like ClearVolume, Smokeview, and VTK [S2, unofficial][S3, unofficial][S17].
