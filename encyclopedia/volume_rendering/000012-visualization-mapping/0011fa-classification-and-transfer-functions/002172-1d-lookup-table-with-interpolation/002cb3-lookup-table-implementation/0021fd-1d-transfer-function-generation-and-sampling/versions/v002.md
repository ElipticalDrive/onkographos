# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function, 1D Transfer Function Texture Generation, TF1D, TFN Sampling to Texture, TFN Texture Upload, Transfer Function Specification

## Overview
1D Transfer Function Generation and Sampling maps scalar data values to color and opacity using a 1D lookup table (LUT) implemented as a 1D texture [S1, book][S7, unofficial]. It solves the problem of visualizing scalar fields by assigning optical properties based on a single data measure, typically the voxel value [S1, book]. Unlike 3D color cube interpolation, which interpolates RGB vectors directly and can produce colors outside the defined colorbar (e.g., purple between red and blue), this method interpolates color indices or positions within a 1D colorbar, ensuring all displayed colors remain physically meaningful and contained within the defined spectrum [S2, unofficial]. It builds on [Lookup Table Implementation](5347-lookup-table-implementation.md) by defining how the LUT content is generated from control points and uploaded for GPU sampling.

## How it works
**Inputs:**
- Scalar data values with range $[s_{min}, s_{max}]$.
- Control points defining the transfer function: pairs of (scalar value, RGBA color) or separate color and alpha control points [S3, unofficial][S6, unofficial].
- Optional Gaussian opacity objects [S6, unofficial].
- LUT resolution (size) [S6, unofficial].

**Outputs:**
- A 1D RGBA texture (LUT) where each entry maps a normalized scalar value to an RGBA color [S1, book][S6, unofficial].
- Sampled RGBA values for each voxel during rendering [S1, book].

**Data Structures:**
- **ControlPoint:** Contains `value` (scalar) and `color` (TFColor) [S3, unofficial].
- **TFColor:** Contains `r`, `g`, `b`, `a` (floats in $[0.0, 1.0]$) [S3, unofficial].
- **ColorControl:** Contains `position` (float) and `color` (vec3f) [S6, unofficial].
- **AlphaControl:** Contains `pos` (vec2f) where `pos.x` is value and `pos.y` is alpha [S6, unofficial].
- **GaussianObject:** Contains `mean`, `sigma`, `heightFactor`, and `alphaArray` (vector<float>) [S6, unofficial].
- **m_rgbaTable:** Vector of `vec4f` of size `resolution` [S6, unofficial].
- **m_alphaArray:** Vector of `float` of size `resolution` [S6, unofficial].
- **palette:** `std::vector<uint8_t>` of size `tfn_w * tfn_h * 4` for OpenGL upload, layout row-major RGBA [S6, unofficial].

**Steps:**
1. **Initialize Control Points:**
   - Define control points with scalar values and RGBA colors.
   - Normalize RGB components from input (0-255) to $[0.0, 1.0]$ by dividing by 255.0 [S3, unofficial].
   - Normalize alpha values to two decimal places: `alpha = floor(alpha * 100) / 100.0` [S3, unofficial].
   - Sort control points by scalar value [S6, unofficial].
   - If no control points exist, add a default point (e.g., 0.0, 0.0, 0.0, 0.0) [S6, unofficial].

2. **Build LUT (Color):**
   - Iterate $i$ from $0$ to `resolution` - 1 [S6, unofficial].
   - Compute normalized value: $v = \frac{i + 0.5}{\text{resolution}}$ (center-aligned bin) [S6, unofficial].
   - Find the interval $[p_L, p_R]$ in sorted color controls such that $p_L \le v < p_R$ using `upper_bound` [S6, unofficial].
   - Determine interpolation weight: $w = \frac{|v - p_L|}{|p_R - p_L|}$ [S6, unofficial].
   - Interpolate color: $c = \text{mix}(c_L, c_R, w)$ where $c_L$ and $c_R$ are colors of left and right control points [S6, unofficial].
   - Store in `m_rgbaTable[i]`: `m_rgbaTable[i].rgb = c` [S6, unofficial].

3. **Build LUT (Alpha):**
   - Initialize `m_alphaArray` with zeros [S6, unofficial].
   - If alpha controls exist:
     - Sort alpha controls by position [S6, unofficial].
     - Iterate $i$ from $0$ to `resolution` - 1 [S6, unofficial].
     - Compute normalized value: $v = \frac{i}{\text{resolution} - 1}$ (edge-aligned) [S6, unofficial].
     - Find interval and interpolate alpha: $\alpha = \text{mix}(\alpha_L, \alpha_R, w)$ [S6, unofficial].
     - Update `m_rgbaTable[i].a = max(m_rgbaTable[i].a, alpha)` [S6, unofficial].
   - If Gaussian objects exist:
     - For each Gaussian, compute its alpha contribution at each LUT index and update `m_rgbaTable[i].a = max(m_rgbaTable[i].a, gaussian_alpha[i])` [S6, unofficial].

4. **Upload to GPU:**
   - Convert `m_rgbaTable` to `palette` vector of `uint8_t` by multiplying RGB components by 255 and clamping to $[0, 255]$ [S6, unofficial].
   - Upload using `glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA8, tfn_w, tfn_h, 0, GL_RGBA, GL_UNSIGNED_BYTE, palette.data())` [S6, unofficial].

5. **Sampling during Rendering:**
   - Read scalar value $v$ from 3D data texture [S1, book].
   - Normalize $v$ to $[0, 1]$: $v_{norm} = \frac{v - s_{min}}{s_{max} - s_{min}}$, clamping out-of-bounds values to $[0, 1]$ [Parent].
   - Use $v_{norm}$ as texture coordinate to sample 1D transfer function texture: `color = tex1d(v, tfTex)` [S1, book].
   - Multiply color components by opacity for correct rendering: `final_color = color.rgb * color.a` (opacity-weighted color) [S1, book][S8].

**Formulas:**
- Normalization: $x_{norm} = \frac{x - x_{min}}{x_{max} - x_{min}}$ [Parent].
- Interpolation weight: $w = \frac{|v - p_L|}{|p_R - p_L|}$ [S6, unofficial].
- Color/Alpha mix: $c = \text{mix}(c_L, c_R, w)$ or $\alpha = \text{mix}(\alpha_L, \alpha_R, w)$ [S6, unofficial].
- Linear interpolation: $colours[idx] = start\_colour \times (1-t) + end\_colour \times t$, where $t = \frac{idx - start\_idx}{end\_idx - start\_idx}$ [S5, unofficial].

**Parameters:**
- `resolution`: Size of the 1D lookup table. Default value in loader is 1024 [S6, unofficial].
- `tfn_w`, `tfn_h`: Width and height of the output texture in pixels [S6, unofficial].
- `step`: Sampling interval, calculated as $1.0f / (tfn\_w - 1)$ [S6, unofficial].
- `n_colours`: Number of colour entries, e.g., 8192 [S5, unofficial].

**Edge Cases and Pitfalls:**
- **Binning Misalignment:** `updateColorMap` uses center-aligned bins $(i+0.5)/resolution$, while `updateFromAlphaControls` uses edge-aligned values $i/(resolution-1)$. This causes a slight misalignment between color and alpha sampling at boundaries [S6, unofficial].
- **Alpha Combination:** Alpha combination uses maximum (`max`) rather than multiplication or blending. This means Gaussian opacity overrides control opacity if higher, but does not attenuate it [S6, unofficial].
- **Precision:** Alpha values are rounded to two decimal places before storage [S3, unofficial]. Color components may exceed 1.0 for HDR palettes, requiring clamping or HDR framebuffer support [Parent].
- **Degenerate Input:** If only one control point exists, interpolation defaults to that point's color/alpha [S6, unofficial].

**Pseudocode:**
```python
import math

def build_lut(color_controls, alpha_controls, gaussian_objects, resolution):
    """
    Builds a 1D LUT from control points.
    color_controls: list of (position, r, g, b)
    alpha_controls: list of (position, alpha)
    gaussian_objects: list of objects with compute_alpha_array(resolution) -> list[float]
    resolution: int, size of LUT
    Returns: list of (r, g, b, a) tuples
    """
    if not color_controls:
        color_controls = [(0.0, 0.0, 0.0, 0.0)]
    color_controls.sort(key=lambda x: x[0])
    control_count = len(color_controls)
    lut = [None] * resolution

    # 1. Build Color LUT (center-aligned bins)
    for i in range(resolution):
        v = (i + 0.5) / resolution
        # Find upper bound index
        ub_idx = 0
        for j in range(control_count):
            if color_controls[j][0] > v:
                ub_idx = j
                break
        else:
            ub_idx = control_count

        if ub_idx <= 0:
            r, g, b = color_controls[0][1], color_controls[0][2], color_controls[0][3]
        elif ub_idx >= control_count:
            r, g, b = color_controls[-1][1], color_controls[-1][2], color_controls[-1][3]
        else:
            left = color_controls[ub_idx - 1]
            right = color_controls[ub_idx]
            w = abs(v - left[0]) / abs(right[0] - left[0])
            r = left[1] + w * (right[1] - left[1])
            g = left[2] + w * (right[2] - left[2])
            b = left[3] + w * (right[3] - left[3])
        lut[i] = [r, g, b, 0.0]

    # 2. Build Alpha LUT (edge-aligned bins)
    if alpha_controls:
        alpha_controls.sort(key=lambda x: x[0])
        alpha_count = len(alpha_controls)
        for i in range(resolution):
            v = i / (resolution - 1)
            ub_idx = 0
            for j in range(alpha_count):
                if alpha_controls[j][0] > v:
                    ub_idx = j
                    break
            else:
                ub_idx = alpha_count

            if ub_idx <= 0:
                alpha = alpha_controls[0][1]
            elif ub_idx >= alpha_count:
                alpha = alpha_controls[-1][1]
            else:
                left = alpha_controls[ub_idx - 1]
                right = alpha_controls[ub_idx]
                w = abs(v - left[0]) / abs(right[0] - left[0])
                alpha = left[1] + w * (right[1] - left[1])
            lut[i][3] = max(lut[i][3], alpha)

    # 3. Combine Gaussian Opacity
    for gauss in gaussian_objects:
        gauss_alpha = gauss.compute_alpha_array(resolution)
        for i in range(resolution):
            lut[i][3] = max(lut[i][3], gauss_alpha[i])

    return lut

def sample_tf(v, lut, s_min, s_range):
    """
    Samples the LUT for a given scalar value v.
    v: scalar value
    lut: list of (r, g, b, a)
    s_min: minimum scalar value in data
    s_range: range of scalar values (s_max - s_min)
    Returns: (r, g, b, a)
    """
    # Normalize and clamp to [0, 1]
    v_norm = max(0.0, min(1.0, (v - s_min) / s_range))
    # Map to LUT index
    index = int(v_norm * (len(lut) - 1))
    return lut[index]

def render_voxel(v, tf_tex):
    """
    Fragment shader equivalent.
    v: scalar value from data
    tf_tex: 1D transfer function texture
    Returns: final color
    """
    # Sample TF
    color_rgba = sample_tf(v, tf_tex, s_min=0.0, s_range=255.0)
    r, g, b, a = color_rgba
    # Opacity-weighted color
    final_r = r * a
    final_g = g * a
    final_b = b * a
    return (final_r, final_g, final_b, a)
```

## Subtopics

### [Voxel Color Mapping](2970-voxel-color-mapping.md)
Voxel Color Mapping is a technique for visualizing scalar volumetric data by converting raw data values into integer indices that address a pre-defined color table. It solves the problem of quantitative data visualization by providing a deterministic, discrete mapping from continuous or discrete scalar fields to RGBA colors. Unlike [Parametric Function Generation](5349-parametric-function-generation.md), which computes color based on the derivative and value of the transfer function, this method relies on a fixed lookup table indexed by normalized data bounds. It differs from [Color Specification](3969-color-specification.md) by explicitly handling the index calculation and clamping logic required for texture map or buffer access.

### [Color Specification](3969-color-specification.md)
Color Specification defines the RGBA (Red, Green, Blue, Alpha) representation used to map scalar voxel values to visual colors in volume rendering. It establishes the four-component structure where each component ranges from 0.0 to 1.0, enabling semi-transparent rendering through blending. It differs from [Voxel Color Mapping](2970-voxel-color-mapping.md) by focusing on the atomic definition of a single color value rather than the mapping strategy, and from [Parametric Function Generation](5349-parametric-function-generation.md) by being a static value definition rather than a functional generation method.

### [Parametric Function Generation](5349-parametric-function-generation.md)
Parametric Function Generation constructs transfer functions (TFs) by evaluating analytic mathematical functions rather than interpolating discrete control points. It solves the problem of creating smooth, continuous, and often perceptually uniform color gradients or localized highlights without the manual tuning required by piecewise linear or Gaussian bump methods. It is distinguished from its parent [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by replacing the key-value pair interpolation with closed-form expressions, and from siblings like [Voxel Color Mapping](2970-voxel-color-mapping.md) by its reliance on global parametric definitions rather than local voxel properties.

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S9, unofficial]. It solves the problem of mapping physical X-ray attenuation to perceptually distinct colors for medical tissue classification [S9, unofficial]. The formula is $HU = \frac{\mu_{\text{Gewebe}} - \mu_{\text{Wasser}}}{\mu_{\text{Wasser}}} \times 1000$ [S9, unofficial]. Water has a HU value of 0, while bone ranges between 500 and 1500 HU [S9, unofficial]. It is implemented as a Lookup Table (LUT) where a color value is read out for a given HU value [S9, unofficial].

### Magnitude Color Gradient
A linear blue-green-red gradient stored in a 1D CUDA texture to visualize vector magnitude (velocity), where blue is lowest and red is highest [S10, unofficial]. It solves the problem of encoding scalar magnitude derived from vector fields into a perceptually uniform color ramp [S10, unofficial]. The gradient values are stored in a 1D texture on GPU and queried via `tex1D(vectorMangitudeCtfTex, vector.w)` [S10, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S2, unofficial]. It solves the problem of generating intermediate colors between two control points but fails to maintain colors within the defined colorbar [S2, unofficial]. The interpolated color is calculated as $interpolated\ color = (f(c_1) + f(c_2))/2$, where $c_1$ and $c_2$ are integer indices between 0 and 255, and $f(c_{ij})$ is the $c_{ij}$'th color in the colorbar [S2, unofficial]. Interpolating colors directly causes artifacts near large gradients (e.g., fire); for example, interpolating between red (1,0,0) and blue (0,0,1) yields purple (0.5,0.0,0.5), which is not in the colorbar and has no physical meaning [S2, unofficial].

### Gradient/Color Ramp Sampling
Samples colors from a gradient texture, often with truncation or HDR handling [S11, unofficial]. It solves the problem of mapping continuous offsets to discrete color channels in engine-specific pipelines [S11, unofficial]. Implementation reads luminance in float and truncates each channel for the colour ramp shared with NoiseTexture2D, as Godot does [S11, unofficial]. It runs Gradient sampler and channelToByte in float, as Gradient::get_color_at_offset and Color::get_r8 do [S11, unofficial]. A GradientTexture2D with use_hdr keeps a channel above 1 [S11, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates [S12, unofficial]. It solves the problem of texture coordinate mapping for image-based transfer functions [S12, unofficial]. It takes `images` tensor of shape `[batch_size, H, W, C]` and `xy_grid` of shape `[N, 2]`, flips `xy_grid` sign, reshapes to `[batch_size, N, 1, 2]`, permutes images to `[batch_size, C, H, W]`, and uses `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S12, unofficial]. The `align_corners=True` parameter ensures corner pixels align with grid boundaries during interpolation, preventing coordinate scaling artifacts at image edges [S12, unofficial].

### Color Blending
Linearly interpolates between two colors based on a ratio, handling alpha, red, green, and blue channels separately [S13, unofficial]. It solves the problem of combining two RGBA values for compositing or transfer function transitions [S13, unofficial]. For each channel (r, g, b): $result = round(c1.ch.channel \times (1 - ratio) + c2.ch.channel \times ratio)$ [S13, unofficial]. Alpha is taken from c1 [S13, unofficial].

## Operating characteristics
- **Time Complexity:** LUT construction is $O(N \cdot C)$ where $N$ is resolution and $C$ is number of control points (or $O(N \log C)$ with binary search) [S6, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
- **Memory Complexity:** $O(N)$ for LUT storage, where $N$ is resolution (e.g., 1024 entries) [S6, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** LUT size can be increased for higher precision, but memory usage grows linearly [S6, unofficial].
- **Strengths:** Simple, efficient, ensures colors stay within the defined colorbar [S2, unofficial].
- **Limitations:** Only uses scalar value; cannot incorporate gradient or other measures without 2D TF [S1, book]. Misalignment between color and alpha binning can cause boundary issues [S6, unofficial].
- **When to use:** When scalar values are sufficient for classification and performance is critical [S1, book].
- **When not to use:** When gradient information is needed for better feature separation [S1, book].

## Background
The technique of mapping scalar data to optical properties via 1D texture lookup tables was established in early volume rendering literature, with detailed implementation guidance provided in NVIDIA's GPU Gems [S1, book][S8]. Subsequent work, such as Smokeview's technical reference, formalized the interpolation of color indices to prevent out-of-spectrum artifacts [S2, unofficial]. Gaussian opacity profiles were later integrated into control-point-based systems [S6, unofficial]. It is widely used in medical imaging (e.g., Hounsfield scale mapping) [S9, unofficial] and vector field visualization [S10, unofficial].
