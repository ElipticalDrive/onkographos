# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function (LUT), TF1D, 1-D colour LUT, TransferFunction1D

## Overview
1D Transfer Function Generation and Sampling maps scalar volume data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) [S1, book]. It solves the problem of visualizing quantitative scalar data by converting numerical intensity values into optical properties for ray casting [S4, unofficial]. Unlike [Parametric Function Generation](5349-parametric-function-generation.md) which computes values via analytical formulas, or [2D Transfer Function](13036-bipolar-scalar-to-color-mapping-with-level-set-support.md) which uses two scalar fields, this method relies on piecewise linear interpolation between user-defined control points [S5, unofficial]. It differs from [3D Color Cube Interpolation](13036-bipolar-scalar-to-color-mapping-with-level-set-support.md) by interpolating color *indices* within a 1D texture rather than RGB vectors directly, ensuring all resulting colors remain within the defined colorbar and avoiding artifacts like purple hues between red and blue regions [S3, unofficial].

## How it works
**Inputs:**
*   A set of control points $C = \{c_0, c_1, \dots, c_{n-1}\}$, where each $c_i$ contains a scalar position $p_i \in [x_{min}, x_{max}]$, a color vector $\mathbf{col}_i = (r_i, g_i, b_i)$, and an opacity value $\alpha_i$.
*   Optional Gaussian objects for additional opacity modulation.
*   Target LUT resolution $N$ (typically a power of two, e.g., 256, 1024) [S2, unofficial][S9, unofficial].
*   Data value range $[x_{min}, x_{max}]$ [S5, unofficial].

**Outputs:**
*   A 1D texture (or contiguous array) of size $N$ containing RGBA values, uploaded to GPU memory [S2, unofficial][S9, unofficial].

**Data Structures:**
*   **ControlPoint**: Fields `value` (float/int), `color` (struct with `r`, `g`, `b`, `a` floats) [S5, unofficial].
*   **LUT Array**: Contiguous array of $N$ vectors, typically `float4` (RGBA) or `uint8` (RGBA) [S1, book][S2, unofficial].
*   **GaussianObject** (optional): Fields `mean` (float), `sigma` (float), `heightFactor` (float), `alphaArray` (vector<float> of size $N$) [S9, unofficial].

**Steps:**

1.  **Initialization**: If the control point list is empty, insert a default control point (e.g., at $x_{min}$ with black/transparent color) [S9, unofficial]. Sort control points by their scalar position $p_i$ in ascending order [S9, unofficial].
2.  **Normalization Setup**: Calculate the step size for the LUT. If using edge-aligned sampling, step $s = \frac{1}{N-1}$. If using center-aligned sampling (common for avoiding boundary bias), the center of bin $i$ is $v_i = \frac{i + 0.5}{N}$ [S9, unofficial].
3.  **Color Table Construction**: Iterate through each LUT index $i$ from $0$ to $N-1$:
    *   Compute the normalized scalar value $v$ corresponding to index $i$.
        *   Edge-aligned: $v = \frac{i}{N-1}$ [S9, unofficial].
        *   Center-aligned: $v = \frac{i + 0.5}{N}$ [S9, unofficial].
    *   Find the interval $[p_L, p_R]$ in the sorted control points such that $p_L \le v < p_R$. Use `upper_bound` to find the first control point with position $> v$; let this be index $k$. Then $p_L = c_{k-1}.p$ and $p_R = c_k.p$ [S9, unofficial].
    *   **Boundary Clamping**: If $v \le p_0$, set color to $c_0.color$. If $v \ge p_{n-1}$, set color to $c_{n-1}.color$ [S9, unofficial].
    *   **Interpolation**: Calculate the interpolation weight $w$:
        $$ w = \frac{|v - p_L|}{|p_R - p_L|} $$
        Interpolate color components:
        $$ \mathbf{col} = \text{mix}(\mathbf{col}_L, \mathbf{col}_R, w) $$
        where $\text{mix}(a, b, w) = a(1-w) + b w$ [S9, unofficial].
    *   Store $\mathbf{col}$ in the LUT at index $i$.
4.  **Alpha Table Construction**:
    *   Initialize an alpha array of size $N$ [S9, unofficial].
    *   If separate alpha control points exist, interpolate them similarly to colors using their positions and alpha values [S9, unofficial]. Note: Some implementations use edge-aligned bins for alpha while using center-aligned for color, causing slight misalignment [S9, unofficial].
    *   If Gaussian objects are present, compute their contribution. For each Gaussian $j$, calculate its alpha contribution at each LUT index $i$ using the Gaussian function:
        $$ \alpha_j(v_i) = \frac{h_j}{\sigma_j \sqrt{2\pi}} e^{-\frac{(v_i - \mu_j)^2}{2\sigma_j^2}} $$
        where $h_j$ is the height factor, $\sigma_j$ is sigma, and $\mu_j$ is the mean [S9, unofficial].
    *   Combine alphas. The standard approach in some implementations is to take the maximum of the interpolated control-point alpha and the Gaussian alpha:
        $$ \alpha_{final}[i] = \max(\alpha_{control}[i], \max_j(\alpha_j(v_i))) $$
        This allows Gaussians to override but not attenuate existing opacity [S9, unofficial].
5.  **Normalization and Formatting**:
    *   If the LUT is stored as 8-bit integers, normalize RGB components from $[0, 1]$ to $[0, 255]$ by multiplying by 255 and clamping [S8, unofficial].
    *   Alpha values may be rounded to two decimal places before storage in some UI-driven implementations [S5, unofficial].
6.  **GPU Upload**:
    *   Create a 1D texture (or 2D texture with height 1) with format `RGBA32F` (for float) or `RGBA8` (for byte) [S2, unofficial][S4, unofficial].
    *   Set wrap mode to `CLAMP_TO_EDGE` and filter mode to `LINEAR` (for hardware interpolation) or `NEAREST` (for direct lookup) [S2, unofficial][S4, unofficial].
    *   Upload the data using `glTexImage1D` or `glTexImage2D` [S2, unofficial][S9, unofficial].
    *   Mark the LUT as "clean" to avoid redundant uploads [S2, unofficial].

**Pseudocode:**

```python
def generate_1d_lut(control_points, resolution=256, gaussians=None):
    """
    Generates a 1D transfer function LUT from control points.
    
    Args:
        control_points: List of dicts/tuples with keys 'pos' (float), 'color' (vec3), 'alpha' (float).
        resolution: Integer, size of the LUT (must be power of 2 for GPU, but logic works for any N).
        gaussians: Optional list of dicts with 'mean', 'sigma', 'height'.
        
    Returns:
        LUT: List of vec4 (RGBA) values of length resolution.
    """
    if not control_points:
        # Default fallback if no points defined
        control_points = [{'pos': 0.0, 'color': [0.0, 0.0, 0.0], 'alpha': 0.0}]
    
    # Sort control points by position
    control_points.sort(key=lambda cp: cp['pos'])
    n_controls = len(control_points)
    
    # Initialize LUT arrays
    lut_rgba = [None] * resolution
    
    # Precompute Gaussian alpha arrays if present
    gaussian_alphas = []
    if gaussians:
        for g in gaussians:
            g_alpha = []
            for i in range(resolution):
                # Center-aligned bin value
                v = (i + 0.5) / resolution
                diff = v - g['mean']
                # Gaussian PDF scaled by height
                # Note: Standard Gaussian normalization factor is 1/(sigma*sqrt(2*pi))
                # Implementation in [S9, unofficial] uses heightFactor directly in the formula
                val = g['height'] / (g['sigma'] * (2.0 * 3.14159265359) ** 0.5) * \
                      math.exp(-(diff * diff) / (2.0 * g['sigma'] * g['sigma']))
                g_alpha.append(max(0.0, min(1.0, val)))
            gaussian_alphas.append(g_alpha)

    for i in range(resolution):
        # Determine normalized value v for this bin
        # Using center-aligned bins as per [S9, unofficial] updateColorMap
        v = (i + 0.5) / resolution
        
        # Find interval [left, right]
        # upper_bound returns first element > v
        upper_idx = 0
        for k in range(n_controls):
            if control_points[k]['pos'] > v:
                upper_idx = k
                break
        else:
            upper_idx = n_controls # v is greater than all control points
            
        if upper_idx == 0:
            # v <= first control point position
            left = control_points[0]
            right = control_points[0]
            w = 0.0
        elif upper_idx >= n_controls:
            # v >= last control point position
            left = control_points[-1]
            right = control_points[-1]
            w = 0.0
        else:
            left = control_points[upper_idx - 1]
            right = control_points[upper_idx]
            # Calculate interpolation weight
            denom = right['pos'] - left['pos']
            if denom == 0:
                w = 0.0
            else:
                w = abs(v - left['pos']) / denom
                
        # Interpolate Color
        r = left['color'][0] * (1 - w) + right['color'][0] * w
        g = left['color'][1] * (1 - w) + right['color'][1] * w
        b = left['color'][2] * (1 - w) + right['color'][2] * w
        
        # Interpolate Alpha from controls
        alpha_ctrl = left['alpha'] * (1 - w) + right['alpha'] * w
        
        # Combine with Gaussians
        alpha_final = alpha_ctrl
        if gaussian_alphas:
            for g_alpha in gaussian_alphas:
                alpha_final = max(alpha_final, g_alpha[i])
                
        lut_rgba[i] = [r, g, b, alpha_final]
        
    return lut_rgba
```

**Edge Cases and Pitfalls:**
*   **Division by Zero**: If adjacent control points have identical positions ($p_R = p_L$), the interpolation weight calculation divides by zero. The code must guard against this or ensure unique positions [S8, unofficial].
*   **Alpha Combination**: Using `max` for Gaussian alpha combination means Gaussians can only increase opacity, not blend with it multiplicatively [S9, unofficial].
*   **Binning Misalignment**: Mixing center-aligned bins for color and edge-aligned bins for alpha can cause slight visual misalignment at boundaries [S9, unofficial].
*   **Dirty Flag**: The LUT must be marked "dirty" when control points change and re-uploaded to the GPU only when necessary to avoid performance hits [S2, unofficial].

## Subtopics

### [Voxel Color Mapping](2970-voxel-color-mapping.md)
Voxel Color Mapping converts scalar volume data values into integer indices for a color table lookup, assigning RGB colors and opacity to each voxel. It solves the problem of quantitative data visualization by mapping numerical values to visual appearance. Unlike [Parametric Function Generation](5349-parametric-function-generation.md) which computes values analytically, or [Color Blending](5150-color-blending.md) which composites final pixels, this method performs a deterministic, per-voxel assignment based on a 1D Lookup Table (LUT). It builds on [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by utilizing the generated LUT to index colors.

### [Color Specification](3969-color-specification.md)
Color Specification defines the RGBA (Red, Green, Blue, Alpha) representation used to specify color and opacity in rendering pipelines. It solves the problem of defining discrete color values with explicit transparency control, allowing background objects to be seen through semi-transparent foreground objects. It differs from [Voxel Color Mapping](2970-voxel-color-mapping.md) and [Color Blending](5150-color-blending.md) by strictly defining the color state itself rather than combining or mapping it.

### [Color Blending](5150-color-blending.md)
Color Blending is the fundamental operation of interpolating between two RGBA color values based on a scalar ratio, typically derived from the distance between sample points or the fractional position within a voxel. It serves as the atomic step for mapping scalar voxel data to visible colors in volume rendering, ensuring smooth transitions between material properties defined by transfer functions. Unlike advanced techniques that account for opacity weighting or physical density, this method treats color channels independently and linearly, often ignoring the alpha channel's influence on the resulting color mixture.

### [Parametric Function Generation](5349-parametric-function-generation.md)
Parametric Function Generation constructs transfer functions by evaluating mathematical functions of a normalized scalar input to determine color and opacity values, rather than relying on piecewise linear interpolation between user-defined control points. It differs from sibling methods like [Voxel Color Mapping](2970-voxel-color-mapping.md) and [Color Specification](3969-color-specification.md) by defining the mapping through continuous analytical formulas (e.g., Gaussians, sigmoids, or trigonometric functions) rather than explicit lookup table entries or discrete color specifications.

### [Transfer Function Editor (Alpha Pins)](6772-transfer-function-editor-alpha-pins.md)
The Transfer Function Editor (Alpha Pins) is an interactive visualization tool that maps scalar voxel values $S(x,y,z)$ to color vectors $F(x,y,z)$ and opacity $\alpha_F(x,y,z)$. It distinguishes itself from other classification methods by using a pin-based interface where users manipulate specific geometric primitives (ramps, hats, blanks) to define opacity and vertical color markers to define gradients, rather than editing a continuous curve or parametric function directly.

### [Colormap LUT Generation](7229-colormap-lut-generation.md)
Colormap LUT Generation is the procedural creation of a 1D lookup table (typically 256 entries of RGBA) from a named colormap definition, serving as the color mapping stage in volume rendering classification.

### [Bipolar Scalar-to-Color Mapping with Level Set Support](13036-bipolar-scalar-to-color-mapping-with-level-set-support.md)
This method maps scalar voxel values to RGB colors using a bipolar lookup table that treats positive and negative values independently, supporting both continuous interpolation and discrete level-set selection. It differs from standard unipolar transfer functions by maintaining separate color ranges for positive and negative domains, allowing distinct visual encoding for opposing scalar signs.

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S14, unofficial]. The Hounsfield Unit (HU) is calculated as $HU = \frac{\mu_{tissue} - \mu_{water}}{\mu_{water}} \times 1000$, where water has a HU value of 0 and bone ranges from 500 to 1500 [S14, unofficial]. It is implemented as a Lookup Table (LUT) where a color value is read out for a given HU value [S14, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S3, unofficial]. The interpolated color between two colors $f(c_1)$ and $f(c_2)$ is calculated as the average: $interpolated color = (f(c_1) + f(c_2))/2$, where $c_1$ and $c_2$ are integer indices between 0 and 255 [S3, unofficial]. A pitfall is that interpolating colors directly causes artifacts near large gradients (e.g., fire); for example, interpolating between red (1,0,0) and blue (0,0,1) yields purple (0.5,0.0,0.5), which is not in the colorbar and has no physical meaning [S3, unofficial].

### Gradient/Color Ramp Sampling
Involves reading luminance in float and truncating each channel for the colour ramp shared with NoiseTexture2D, as Godot does [S15, unofficial]. A pitfall is that a GradientTexture2D with `use_hdr` keeps a channel above 1 [S15, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates. Takes `images` tensor of shape `[batch_size, H, W, C]` and `xy_grid` of shape `[N, 2]`. Flips `xy_grid` sign, reshapes to `[batch_size, N, 1, 2]`. Permutes images to `[batch_size, C, H, W]`. Uses `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S16, unofficial]. The parameter `align_corners=True` ensures corner pixels align with grid boundaries during interpolation, preventing coordinate scaling artifacts at image edges [S16, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two 1D LUT textures (soft and hard) for labelmap transfer functions. The soft LUT uses float precision and bilinear filtering; the hard LUT uses byte precision and point filtering [S4, unofficial]. It initializes float and byte pixel arrays of size 256, maps label indices to colors, converts float RGBA to byte, and uploads them as `Texture2D` with appropriate wrap/filter modes (`Clamp`/`Bilinear` for soft, `Clamp`/`Point` for hard) [S4, unofficial].

### 2D Transfer Function
A volume rendering technique that maps two separate scalar fields to color and opacity using a 2D lookup table (image), extending the 1D transfer function approach [S17]. It uses a `lookupTable` which is an `ARRAY2D` of Color objects, where width and height represent two separate scalar fields. A pitfall is the ambiguity in mapping scalar fields to the 2D lookup table axes; a prescriptive interpretation is that the X-axis represents the scalar `value` and the Y-axis represents the gradient of the value, `grad(value)` [S17]. Unlike separable 1D transfer functions, the 2D TFN allows for non-separable, arbitrary 2D mappings [S17].

### Material Synchronization LUT Adjustment
An algorithm to adjust a 1D Look-Up Table (LUT) mapping sample values to material indices, ensuring that the distribution of sample values across materials is synchronized with the frame number and material centers [S18, unofficial]. It calculates a common base allocation range `d` as `frameNumber / colorKind` and initializes material center positions `indexM[i]` to `d*i + d / 2` [S18, unofficial].

### BuildFunctionFromTable
Constructs a color transfer function from a pre-existing table of colors [S19]. The function range will be $[x_1, x_2]$, the function will have size `nodes`, and function values will be regularly spaced between $x_1$ and $x_2$ [S19]. The table parameter's layout is assumed to be $[R_1, G_1, B_1, R_2, G_2, B_2, \dots, R_n, G_n, B_n]$, a block of memory of size $[3 \times size]$ [S19].

### Scalar Mapping Output Formats
The output format for mapped scalars can be set to specific component counts. The default output format is RGBA if not supplied [S19].

## Operating characteristics
*   **Time Complexity**: LUT generation is $O(N \cdot K)$ where $N$ is the LUT resolution and $K$ is the number of control points (due to sorting and interval search). Sampling during rendering is $O(1)$ per sample using hardware texture lookup [S1, book].
*   **Memory Complexity**: $O(N)$ for the LUT storage, where $N$ is typically 256 to 65536 entries of 4 floats (1KB to 1MB) [S2, unofficial][S8, unofficial].
*   **Performance**: Hardware interpolation via 1D textures is extremely fast and parallelizable on the GPU [S1, book]. Direct lookup is also fast but lacks smoothness unless $N$ is very large.
*   **Strengths**: Simple to implement, intuitive user interface (control points), efficient GPU support, smooth color transitions [S1, book][S5, unofficial].
*   **Limitations**: Cannot easily model complex dependencies between multiple scalar fields (requires 2D TF) [S1, book]. Linear interpolation may not capture sharp features as well as higher-order methods [S5, unofficial].
*   **When to use**: Standard volume rendering of single-scalar data (CT, MRI, scalar fields).
*   **When not to use**: When material classification depends on multiple properties (e.g., density and gradient) requiring 2D TF [S1, book], or when precise analytical control is needed without discretization errors [S5, unofficial].

## Background
The 1D transfer function is the simplest and most widely used type of transfer function in volume rendering, mapping the range of data values to color and opacity [S1, book]. It was popularized in early GPU-based volume rendering techniques, such as those described in the NVIDIA GPU Gems Chapter 39 [S1, book]. The use of 1D texture maps for interpolation was notably discussed in the context of Smokeview, where it was shown to prevent color artifacts compared to 3D color cube interpolation [S3, unofficial]. The method has been implemented in various visualization toolkits, including VTK's `vtkColorTransferFunction` [S19] and custom raycasting renderers [S5, unofficial][S8, unofficial].
