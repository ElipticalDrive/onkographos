# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function (LUT), TF1D, 1-D colour LUT, TransferFunction1D

## Overview
1D Transfer Function Generation and Sampling maps scalar volume data values to RGBA color and opacity properties using a 1D lookup table (LUT) or texture [S1, book][S2, unofficial]. It solves the problem of visualizing quantitative scalar data by assigning optical properties based on intensity, typically implemented as a 1D texture sampled during ray casting [S1, book]. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by relying on piecewise linear interpolation between discrete control points rather than analytical functions, and from [Gradient/Color Ramp Sampling](4337-gradient-color-ramp-sampling.md) by constructing a dense 1D array rather than a procedural 2D gradient map [S1, book].

## How it works
**Inputs and Outputs**
*   **Input:** A set of control points defining the transfer function. Each control point consists of a scalar position (normalized to $[0, 1]$ or mapped to data range) and an RGBA color value [S5, unofficial][S9, unofficial]. Optional Gaussian objects may be added to modulate opacity [S9, unofficial].
*   **Output:** A 1D texture (or contiguous array) of size $N$ (typically 256, 1024, or 65536) containing interpolated RGBA values [S2, unofficial][S9, unofficial].

**Data Structures**
*   **Control Point:** A structure containing `value` (float, scalar position) and `color` (vec4f, RGBA) [S5, unofficial].
*   **LUT Array:** A contiguous array of size $N$ where each entry is a 4-component vector (R, G, B, A) [S1, book][S2, unofficial]. Common formats are `float32` (32-bit per component) or `uint8` (8-bit per component) [S2, unofficial][S9, unofficial].
*   **Texture:** The LUT is uploaded as a 1D texture (`GL_TEXTURE_1D`) or a 2D texture with height 1 (`GL_TEXTURE_2D`, width $N$, height 1) [S2, unofficial][S9, unofficial].

**Steps**
1.  **Normalization:** Map input scalar values $v$ from the data domain $[x_{min}, x_{max}]$ to the normalized domain $[0, 1]$ using:
    $$ x = \frac{v - x_{min}}{x_{max} - x_{min}} $$
    Values outside this range are clamped to $[0, 1]$ [S2, unofficial][S3, unofficial].
2.  **Control Point Sorting:** Sort control points by their scalar position in ascending order [S9, unofficial].
3.  **LUT Construction:** Iterate through each index $i$ of the LUT (from $0$ to $N-1$):
    a. Compute the normalized position $p$ for index $i$. Sources vary on binning:
       *   Center-aligned: $p = \frac{i + 0.5}{N}$ [S9, unofficial].
       *   Edge-aligned: $p = \frac{i}{N - 1}$ [S9, unofficial][S2, unofficial].
    b. Find the two adjacent control points, $C_L$ (left) and $C_R$ (right), such that $p_L \le p \le p_R$ [S9, unofficial].
    c. Calculate the interpolation weight $w$:
       $$ w = \frac{|p - p_L|}{|p_R - p_L|} $$
       If $p \le p_L$, $w=0$; if $p \ge p_R$, $w=1$ [S9, unofficial].
    d. Interpolate color and alpha:
       $$ C_{rgb} = \text{mix}(C_{L,rgb}, C_{R,rgb}, w) $$
       $$ \alpha = \text{mix}(\alpha_L, \alpha_R, w) $$
    e. Store the result in the LUT at index $i$ [S9, unofficial].
4.  **Gaussian Modulation (Optional):** If Gaussian opacity objects are defined, for each LUT entry $i$, update the alpha channel:
    $$ \alpha_i = \max(\alpha_i, \alpha_{Gaussian, i}) $$
    This uses maximum compositing rather than multiplication [S9, unofficial].
5.  **Upload:** Upload the LUT array to GPU memory as a texture with `LINEAR` filtering and `CLAMP_TO_EDGE` wrapping [S2, unofficial][S9, unofficial].

**Pseudocode**
```python
def generate_1d_lut(control_points, resolution=256):
    """
    Generates a 1D LUT from control points.
    control_points: list of dicts with 'pos' (float 0-1) and 'color' (vec4f).
    resolution: int, size of the LUT.
    Returns: list of vec4f of length resolution.
    """
    if not control_points:
        # Default to transparent black if no points defined
        control_points = [{'pos': 0.0, 'color': [0.0, 0.0, 0.0, 0.0]}]
    
    # Sort control points by position
    sorted_points = sorted(control_points, key=lambda p: p['pos'])
    n_points = len(sorted_points)
    
    lut = [None] * resolution
    
    for i in range(resolution):
        # Center-aligned binning: (i + 0.5) / resolution
        p = (i + 0.5) / resolution
        
        # Find interval
        # upper_bound finds first point with pos > p
        upper_idx = 0
        for idx, pt in enumerate(sorted_points):
            if pt['pos'] > p:
                upper_idx = idx
                break
        else:
            upper_idx = n_points
            
        if upper_idx == 0:
            # p is before or at the first point
            left = sorted_points[0]
            right = sorted_points[0]
            w = 0.0
        elif upper_idx >= n_points:
            # p is after or at the last point
            left = sorted_points[-1]
            right = sorted_points[-1]
            w = 1.0
        else:
            # p is between upper_idx-1 and upper_idx
            left = sorted_points[upper_idx - 1]
            right = sorted_points[upper_idx]
            
            # Calculate weight
            pos_diff = right['pos'] - left['pos']
            if pos_diff == 0:
                w = 0.0
            else:
                w = (p - left['pos']) / pos_diff
                
        # Interpolate color
        r = left['color'][0] + w * (right['color'][0] - left['color'][0])
        g = left['color'][1] + w * (right['color'][1] - left['color'][1])
        b = left['color'][2] + w * (right['color'][2] - left['color'][2])
        a = left['color'][3] + w * (right['color'][3] - left['color'][3])
        
        lut[i] = [r, g, b, a]
        
    return lut

def sample_lut(lut, normalized_value):
    """
    Samples the LUT using hardware-like linear interpolation.
    normalized_value: float in [0, 1].
    """
    # Clamp to valid range
    p = max(0.0, min(1.0, normalized_value))
    
    # Map to index
    # Using edge-aligned mapping for sampling consistency with generation if resolution-1 is used
    # However, hardware linear sampling on a texture of size N with CLAMP_TO_EDGE 
    # typically maps coordinate x to index floor(x * (N-1)) for nearest, 
    # or interpolates between floor(x*(N-1)) and ceil(x*(N-1)).
    # Standard linear texture sampling:
    idx_float = p * (len(lut) - 1)
    idx_low = int(idx_float)
    idx_high = min(idx_low + 1, len(lut) - 1)
    w = idx_float - idx_low
    
    r = lut[idx_low][0] + w * (lut[idx_high][0] - lut[idx_low][0])
    g = lut[idx_low][1] + w * (lut[idx_high][1] - lut[idx_low][1])
    b = lut[idx_low][2] + w * (lut[idx_high][2] - lut[idx_low][2])
    a = lut[idx_low][3] + w * (lut[idx_high][3] - lut[idx_low][3])
    
    return [r, g, b, a]
```

**Parameters**
*   **Resolution ($N$):** Size of the LUT. Common values are 256, 1024, 4096, 65536 [S2, unofficial][S9, unofficial]. Must be a power of two for optimal hardware texture support [S2, unofficial].
*   **Data Range ($x_{min}, x_{max}$):** Defines the window/level for normalizing input data [S2, unofficial].
*   **Brightness Factor:** Optional multiplier applied to RGB channels after lookup [S12, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero:** If two adjacent control points have the same position, the interpolation weight calculation divides by zero [S8, unofficial].
*   **Binning Misalignment:** Inconsistent binning schemes (e.g., center-aligned for generation vs. edge-aligned for sampling) can cause slight misalignments at boundaries [S9, unofficial].
*   **Alpha Combination:** Using maximum (`max`) for Gaussian opacity overrides control opacity but does not attenuate it, which may lead to unintended opacity levels [S9, unofficial].
*   **Dirty Flag:** The LUT must be marked "dirty" when control points change and re-uploaded to the GPU only when necessary to avoid performance penalties [S2, unofficial].

## Subtopics

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S14, unofficial]. It implements the standard HU formula $HU = \frac{\mu_{tissue} - \mu_{water}}{\mu_{water}} \times 1000$ to map physical density to LUT indices [S14, unofficial]. Water is 0 HU, bone is 500–1500 HU [S14, unofficial].

### 3D Color Cube Interpolation
An older method (e.g., Smokeview v4) where colors are interpolated directly in RGB space: $C_{interp} = \frac{C_1 + C_2}{2}$ [S3, unofficial]. This causes artifacts (e.g., purple between red and blue) because the interpolated color may not exist in the defined colorbar [S3, unofficial]. The 1D LUT method avoids this by interpolating indices, not colors [S3, unofficial].

### Bilinear Image Sampling
Samples colors from 2D image tensors using `grid_sample` with bilinear interpolation and `align_corners=True` [S15, unofficial]. While not a volume LUT, it demonstrates the coordinate transformation and interpolation logic used in texture sampling [S15, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two LUTs: a soft (float, bilinear) and hard (byte, point) texture for labelmap data [S4, unofficial]. The soft LUT allows smooth transitions, while the hard LUT ensures discrete label colors [S4, unofficial].

### Material Synchronization LUT Adjustment
Adjusts a 1D LUT mapping sample values to material indices to synchronize material distribution with frame numbers [S16, unofficial]. It calculates material centers based on `frameNumber / colorKind` [S16, unofficial].

### BuildFunctionFromTable
Constructs a transfer function from a pre-existing flat table of RGB values [S17]. The table is assumed to be a block of memory `[R1, G1, B1, ...]` and the function range is set to `[x1, x2]` [S17].

### Scalar Mapping Output Formats
Specifies the output component count for mapped scalars, defaulting to RGBA if not supplied [S17].

## Operating characteristics
*   **Time Complexity:** LUT generation is $O(N \cdot K)$ where $N$ is LUT size and $K$ is the number of control points (or $O(N \log K)$ if binary search is used) [S9, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
*   **Memory Complexity:** $O(N)$ for the LUT storage [S2, unofficial].
*   **Performance:** Hardware texture sampling is extremely fast, making 1D TFs the standard for real-time volume rendering [S1, book].
*   **Strengths:** Simple to implement, efficient, supports smooth interpolation [S1, book].
*   **Limitations:** Cannot handle multivariate data (e.g., gradient magnitude) without extension to 2D TFs [S1, book]. Linear interpolation may not capture complex feature boundaries as well as higher-order methods [S5, unofficial].

## Background
The 1D transfer function is the simplest and most widely used classification method in volume rendering, introduced in early ray casting techniques [S1, book]. It maps scalar data values to optical properties, typically implemented using 1D texture lookup tables [S1, book]. The method evolved to use hardware-accelerated 1D textures to ensure interpolated colors remain within the defined colorbar, avoiding artifacts associated with 3D color cube interpolation [S3, unofficial].
