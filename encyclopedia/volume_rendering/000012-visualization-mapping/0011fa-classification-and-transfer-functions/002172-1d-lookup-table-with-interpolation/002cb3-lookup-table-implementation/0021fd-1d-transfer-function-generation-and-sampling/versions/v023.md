# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function (LUT), TF1D, 1-D colour LUT, TransferFunction1D

## Overview
1D Transfer Function Generation and Sampling maps scalar volume data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) [S1, book]. It solves the problem of quantitative data visualization by assigning visual appearance to numerical voxel intensities [S4, unofficial]. Unlike [Parametric Function Generation](5349-parametric-function-generation.md) which computes values analytically, or [Color Blending](5150-color-blending.md) which composites final pixels, this method performs a deterministic, per-voxel assignment based on a 1D Lookup Table (LUT) [S1, book]. It builds on [Lookup Table Implementation](5347-lookup-table-implementation.md) by defining how the LUT entries are populated from control points and uploaded for sampling [S1, book].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of control points defining scalar positions and RGBA values; optional Gaussian opacity objects; optional alpha control points; input volume bit depth (determines LUT size).
*   **Outputs:** A 1D texture (or 2D texture with height 1) containing the RGBA LUT ready for GPU sampling.

**Data Structures**
*   **Control Point:** A structure containing `value` (scalar position, normalized or raw) and `color` (TFColor with fields `r`, `g`, `b`, `a` as floats) [S5, unofficial].
*   **Alpha Control:** A structure with `pos` (vec2f, where `x` is scalar position and `y` is opacity) [S9, unofficial].
*   **Gaussian Object:** A structure with `mean`, `sigma`, `heightFactor`, and an `alphaArray` (vector of floats) [S9, unofficial].
*   **LUT Table:** A contiguous array of 4-component vectors (e.g., `vec4f` or `uint8_t[4]`) of size $N$ (typically 256, 1024, or 65536) [S1, book][S9, unofficial].

**Steps**
1.  **Initialization:** If no control points are defined, insert a default point (e.g., at position 0 with black/transparent color) [S9, unofficial].
2.  **Sorting:** Sort the control points by their scalar position in ascending order [S9, unofficial].
3.  **LUT Population:** Iterate through each index $i$ of the LUT (from $0$ to $N-1$):
    *   Compute the normalized scalar value $v$ corresponding to index $i$. Sources vary on binning: some use center-aligned bins $v = (i + 0.5) / N$ [S9, unofficial], while others use edge-aligned $v = i / (N-1)$ [S9, unofficial].
    *   Find the interval $[p_L, p_R]$ in the sorted control points such that $p_L \le v < p_R$ using an upper-bound search [S9, unofficial].
    *   **Color Interpolation:** If $v$ is outside the control point range, clamp to the nearest endpoint color. Otherwise, calculate the interpolation weight $w = \frac{|v - p_L|}{|p_R - p_L|}$ and interpolate the color: $c = \text{mix}(c_L, c_R, w)$ [S9, unofficial].
    *   **Alpha Handling:**
        *   If separate alpha controls exist, interpolate alpha similarly using the alpha control points [S9, unofficial].
        *   If Gaussian objects are present, compute their contribution to opacity at index $i$ and combine it with the interpolated alpha using the maximum operator: $\alpha_{final} = \max(\alpha_{interpolated}, \alpha_{gaussian})$ [S9, unofficial].
    *   Store the resulting RGBA vector in the LUT at index $i$.
4.  **Boundary Filling:** Ensure indices after the last control point are filled with the last control point's color [S10, unofficial].
5.  **Upload:** Convert the LUT data to the target format (e.g., float32 or uint8) and upload to GPU memory as a 1D or 2D texture with `LINEAR` filtering and `CLAMP_TO_EDGE` wrapping [S2, unofficial][S9, unofficial].

**Formulas**
*   **Interpolation Weight:**
    $$ w = \frac{|v - p_L|}{|p_R - p_L|} $$
    where $v$ is the current LUT index value, and $p_L, p_R$ are the positions of the left and right control points [S9, unofficial].
*   **Color Mix:**
    $$ c = \text{mix}(c_L, c_R, w) $$
    where $c_L$ and $c_R$ are the colors of the left and right control points [S9, unofficial].
*   **Gaussian Alpha:**
    $$ \alpha_{gauss}(x) = \frac{h}{\sigma \sqrt{2\pi}} e^{-\frac{(x-\mu)^2}{2\sigma^2}} $$
    where $h$ is height factor, $\sigma$ is sigma, $\mu$ is mean [S9, unofficial].

**Parameters**
*   **Resolution ($N$):** Size of the LUT. Common values are 256 for 8-bit data, 65536 for 16-bit data [S8, unofficial][S9, unofficial].
*   **Brightness Factor:** A multiplier applied to RGB channels after lookup (optional) [S12, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero:** If adjacent control points have identical scalar positions, the denominator in the weight calculation becomes zero [S8, unofficial].
*   **Binning Misalignment:** Inconsistent binning schemes (center-aligned vs. edge-aligned) between color and alpha generation can cause slight misalignments at boundaries [S9, unofficial].
*   **Alpha Combination:** Using `max` for Gaussian alpha overrides lower opacity values rather than blending them, which may not be physically accurate for all materials [S9, unofficial].
*   **Dirty Flag:** The LUT must be marked "dirty" when control points change and cleared after GPU upload to avoid redundant transfers [S2, unofficial].

**Pseudocode**
```python
def generate_1d_tf(control_points, resolution=256):
    """
    Generates a 1D transfer function LUT from control points.
    control_points: list of dicts with 'pos' (float) and 'color' (vec4).
    resolution: int, size of the LUT.
    Returns: list of vec4 (RGBA) of length resolution.
    """
    if not control_points:
        control_points = [{'pos': 0.0, 'color': [0.0, 0.0, 0.0, 0.0]}]
    
    # Sort by position
    control_points.sort(key=lambda p: p['pos'])
    
    n = len(control_points)
    lut = [None] * resolution
    
    for i in range(resolution):
        # Center-aligned binning
        v = (i + 0.5) / resolution
        
        # Find interval
        # upper_bound finds first point with pos > v
        ub_idx = 0
        for k in range(n):
            if control_points[k]['pos'] > v:
                ub_idx = k
                break
        else:
            ub_idx = n
            
        if ub_idx == 0:
            # Clamp to first point
            color = control_points[0]['color']
        elif ub_idx >= n:
            # Clamp to last point
            color = control_points[-1]['color']
        else:
            # Interpolate
            left = control_points[ub_idx - 1]
            right = control_points[ub_idx]
            dist = right['pos'] - left['pos']
            if dist == 0:
                color = left['color'] # Guard against div by zero
            else:
                w = (v - left['pos']) / dist
                color = [
                    left['color'][0] + w * (right['color'][0] - left['color'][0]),
                    left['color'][1] + w * (right['color'][1] - left['color'][1]),
                    left['color'][2] + w * (right['color'][2] - left['color'][2]),
                    left['color'][3] + w * (right['color'][3] - left['color'][3])
                ]
        
        # Apply Gaussian alpha if present (simplified)
        # In full implementation, max(alpha_interp, alpha_gauss)
        
        lut[i] = color
        
    return lut
```

## Subtopics

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S14, unofficial]. It implements the LUT mapping specifically for HU values, where Water is 0 HU and Bone is 500–1500 HU [S14, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S3, unofficial]. It calculates the average of two colors $f(c_1)$ and $f(c_2)$ as $(f(c_1) + f(c_2))/2$ [S3, unofficial]. This causes artifacts near large gradients (e.g., fire) because interpolated colors like purple (from red and blue) are not in the defined colorbar [S3, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates using `torch.nn.functional.grid_sample` with `align_corners=True` [S15, unofficial]. It flips the `xy_grid` sign and permutes images to `[batch_size, C, H, W]` before sampling [S15, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two 1D LUT textures (soft and hard) for labelmap transfer functions [S4, unofficial]. The soft LUT uses float precision and bilinear filtering; the hard LUT uses byte precision and point filtering [S4, unofficial]. It maps discrete label indices to RGBA values, clamping labels to the LUT size [S4, unofficial].

### Material Synchronization LUT Adjustment
An algorithm to adjust a 1D LUT mapping sample values to material indices, ensuring synchronization with frame number and material centers [S16, unofficial]. It calculates base allocation ranges and updates material center positions based on the frame number [S16, unofficial].

### BuildFunctionFromTable
Constructs a color transfer function from a pre-existing table of colors [S17]. The function range becomes $[x_1, x_2]$ with size `nodes`, and values are regularly spaced [S17]. The input table layout is assumed to be block-interleaved `[R1, G1, B1, R2, G2, B2, ...]` [S17].

### Scalar Mapping Output Formats
Defines the output format for mapped scalars, defaulting to RGBA if not supplied [S17].

### Color Table Filtering
Filters procedural textures by filtering the 1D color table $C$ rather than the noise function, returning the average color over a small interval [S18]. It uses MIP-mapping on the 1D color table and computes interval size $\delta$ from the filter size and maximum gradient [S18].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$ where $N$ is LUT resolution and $K$ is the number of control points (for naive search) or $O(N \log K)$ with binary search [S9, unofficial].
*   **Memory Complexity:** $O(N)$ for the LUT storage [S1, book].
*   **Performance:** Hardware interpolation is efficient, but frequent LUT updates (due to control point changes) can cause GPU bandwidth bottlenecks if not managed with dirty flags [S2, unofficial].
*   **Strengths:** Simple to implement; supports smooth transitions via linear interpolation; compatible with standard GPU texture units [S1, book].
*   **Limitations:** Linear interpolation may not capture complex non-linear mappings; 3D color cube interpolation causes visual artifacts [S3, unofficial].

## Background
The method originated as a standard technique in volume rendering to map scalar data to optical properties [S1, book]. It was widely adopted in early GPU-based volume rendering pipelines, such as those described in the NVIDIA GPU Gems series [S1, book]. Variants like 3D color cube interpolation were used in tools like Smokeview but were later superseded by 1D texture-based index interpolation to preserve colorbar integrity [S3, unofficial].
