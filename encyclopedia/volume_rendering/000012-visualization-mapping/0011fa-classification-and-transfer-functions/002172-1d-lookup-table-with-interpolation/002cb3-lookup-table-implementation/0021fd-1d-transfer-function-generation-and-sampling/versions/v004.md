# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function, 1D Transfer Function Texture Generation, TF1D, TFN Sampling to Texture, TFN Texture Upload, Transfer Function Specification

## Overview
1D Transfer Function Generation and Sampling maps scalar voxel values to RGBA optical properties (color and opacity) using a 1D lookup table (LUT) implemented as a 1D texture [S1, book][S8]. It solves the problem of visualizing scalar volumetric data by converting raw intensity values into perceptible color and opacity for rendering [S1, book]. It differs from [3D Color Cube Interpolation](2970-voxel-color-mapping.md) by interpolating color indices (texture coordinates) rather than RGB values directly, ensuring all displayed colors remain within the defined colorbar and avoiding artifacts like purple hues between red and blue regions [S2, unofficial]. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by using discrete control points and linear interpolation rather than analytic mathematical functions [S1, book].

## How it works
**Inputs:**
- Scalar volume data range $[x_{min}, x_{max}]$ [S3, unofficial][S4, unofficial].
- A set of control points defining color and opacity. Each color control point $C_i$ has a position $p_i \in [0, 1]$ (normalized scalar value) and a color $c_i \in [0, 1]^3$ [S6, unofficial]. Each alpha control point $A_j$ has a position $p_j \in [0, 1]$ and an opacity $\alpha_j \in [0, 1]$ [S6, unofficial].
- Optional Gaussian opacity objects defined by mean $\mu$, sigma $\sigma$, and height factor [S6, unofficial].
- LUT resolution $R$ (default 1024) [S6, unofficial].

**Outputs:**
- A 1D texture (or array) of size $R$ containing `vec4` (RGBA) values [S6, unofficial].

**Data Structures:**
- `ControlPoint`: Fields `value` (float, normalized), `color` (vec3f), `alpha` (float) [S3, unofficial][S6, unofficial].
- `m_rgbaTable`: `vector<vec4f>` of size $R$ [S6, unofficial].
- `m_alphaArray`: `vector<float>` of size $R$ [S6, unofficial].
- `palette`: `vector<uint8_t>` of size $R \times 4$ for GPU upload [S6, unofficial].

**Steps:**

1. **Normalize Control Points:**
   Convert raw scalar values to normalized domain $[0, 1]$ using:
   $$ p = \frac{x - x_{min}}{x_{max} - x_{min}} $$
   Clamp $p$ to $[0, 1]$ [S3, unofficial][S4, unofficial].

2. **Sort Control Points:**
   Sort color control points by position $p$ in ascending order [S6, unofficial].

3. **Initialize LUT:**
   Create `m_rgbaTable` of size $R$ and `m_alphaArray` of size $R$, initialized to zero [S6, unofficial].

4. **Interpolate Color:**
   For each index $i$ from $0$ to $R-1$:
   a. Compute normalized value $v$. Sources differ on binning:
      - Center-aligned: $v = \frac{i + 0.5}{R}$ [S6, unofficial].
      - Edge-aligned: $v = \frac{i}{R-1}$ [S6, unofficial].
      *Note: Inconsistent binning between color and alpha generation can cause boundary misalignment [S6, unofficial].*
   b. Find the interval $[p_L, p_R]$ containing $v$ in the sorted color control points. Let $c_L$ and $c_R$ be the colors at these points.
   c. Compute interpolation weight:
      $$ w = \frac{|v - p_L|}{|p_R - p_L|} $$
   d. Interpolate color:
      $$ c = \text{mix}(c_L, c_R, w) $$
   e. If $v < p_0$ (first control point), $c = c_0$. If $v > p_{last}$, $c = c_{last}$ [S6, unofficial].
   f. Store $c$ in a temporary buffer or directly into `m_rgbaTable[i].rgb` [S6, unofficial].

5. **Interpolate Alpha:**
   For each index $i$ from $0$ to $R-1$:
   a. Compute normalized value $v$ (using the same binning as color to avoid misalignment, though sources note discrepancies [S6, unofficial]).
   b. Find interval $[p_L, p_R]$ in sorted alpha control points. Let $\alpha_L$ and $\alpha_R$ be the opacities.
   c. Compute weight $w$ as above.
   d. Interpolate alpha:
      $$ \alpha = \text{mix}(\alpha_L, \alpha_R, w) $$
   e. Clamp $\alpha$ to $[0, 1]$ [S6, unofficial].
   f. Store $\alpha$ in `m_alphaArray[i]` [S6, unofficial].

6. **Apply Gaussian Opacity (Optional):**
   For each Gaussian object $G_j$ with mean $\mu_j$, sigma $\sigma_j$, and height factor $H_j$:
   a. For each index $i$, compute value $v$ (center-aligned: $v = \frac{i + 0.5}{R}$) [S6, unofficial].
   b. Compute Gaussian value:
      $$ g(v) = \frac{H_j}{\sigma_j \sqrt{2\pi}} e^{-\frac{(v - \mu_j)^2}{2\sigma_j^2}} $$
   c. Update alpha in `m_rgbaTable[i].a` using maximum:
      $$ \text{m\_rgbaTable}[i].a = \max(\text{m\_rgbaTable}[i].a, \text{clamp}(g(v), 0.0, 1.0)) $$
   *Note: Maximum is used instead of multiplication, meaning Gaussian opacity overrides control opacity if higher [S6, unofficial].*

7. **Finalize and Upload:**
   a. Combine interpolated color and final alpha into `m_rgbaTable[i]` [S6, unofficial].
   b. Convert `m_rgbaTable` to `palette` (uint8, 0-255) [S6, unofficial].
   c. Upload to GPU as `GL_TEXTURE_1D` or `GL_TEXTURE_2D` (with height 1) using `glTexImage2D` or equivalent [S6, unofficial].

**Pseudocode:**

```python
def generate_1d_tf(color_controls, alpha_controls, gaussian_objects, resolution=1024):
    """
    color_controls: list of (position: float, color: vec3f)
    alpha_controls: list of (position: float, alpha: float)
    gaussian_objects: list of (mean: float, sigma: float, height_factor: float)
    resolution: int
    """
    # 1. Sort controls
    color_controls.sort(key=lambda x: x[0])
    alpha_controls.sort(key=lambda x: x[0])
    
    # 2. Initialize tables
    rgba_table = [vec4f(0,0,0,0) for _ in range(resolution)]
    
    # 3. Interpolate Color and Alpha
    for i in range(resolution):
        # Use center-aligned binning for consistency with Gaussian update
        v = (i + 0.5) / resolution
        
        # Interpolate Color
        c = interpolate_color(color_controls, v)
        
        # Interpolate Alpha
        alpha = interpolate_alpha(alpha_controls, v)
        
        rgba_table[i] = vec4f(c.r, c.g, c.b, alpha)
        
    # 4. Apply Gaussian Opacity
    for gauss in gaussian_objects:
        mu, sigma, h = gauss
        for i in range(resolution):
            v = (i + 0.5) / resolution
            diff = v - mu
            g_val = (h / (sigma * sqrt(2 * PI))) * exp(-(diff * diff) / (2 * sigma * sigma))
            g_val = clamp(g_val, 0.0, 1.0)
            # Max combination
            rgba_table[i].a = max(rgba_table[i].a, g_val)
            
    return rgba_table

def interpolate_color(controls, v):
    if not controls:
        return vec3f(0,0,0)
    if v <= controls[0][0]:
        return controls[0][1]
    if v >= controls[-1][0]:
        return controls[-1][1]
    
    # Find interval
    for j in range(len(controls) - 1):
        p_l, c_l = controls[j]
        p_r, c_r = controls[j+1]
        if p_l <= v <= p_r:
            w = abs(v - p_l) / abs(p_r - p_l)
            return mix(c_l, c_r, w)
    return controls[-1][1] # Fallback

def interpolate_alpha(controls, v):
    if not controls:
        return 0.0
    if v <= controls[0][0]:
        return controls[0][1]
    if v >= controls[-1][0]:
        return controls[-1][1]
        
    for j in range(len(controls) - 1):
        p_l, a_l = controls[j]
        p_r, a_r = controls[j+1]
        if p_l <= v <= p_r:
            w = abs(v - p_l) / abs(p_r - p_l)
            return mix(a_l, a_r, w)
    return controls[-1][1]
```

## Subtopics

### [Voxel Color Mapping](2970-voxel-color-mapping.md)
Voxel Color Mapping assigns discrete or continuous colors to volumetric data by mapping scalar values to integer indices for lookup in a color table. It differs from the parent method by focusing on deterministic index calculation (e.g., height-based) rather than parametric interpolation. It is distinct from [Color Specification](3969-color-specification.md) which defines color spaces, and [Parametric Function Generation](5349-parametric-function-generation.md) which generates transfer functions via mathematical functions.

### [Color Specification](3969-color-specification.md)
Color Specification defines the RGBA representation used to map scalar voxel values to visual colors. It differs from [Voxel Color Mapping](2970-voxel-color-mapping.md) by focusing on component definition rather than spatial mapping strategy, and from [Parametric Function Generation](5349-parametric-function-generation.md) by specifying discrete values rather than continuous functions. It builds on [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md) by providing the atomic color units sampled from the transfer function.

### [Parametric Function Generation](5349-parametric-function-generation.md)
Parametric Function Generation constructs transfer functions by evaluating analytic mathematical functions rather than interpolating discrete control points. It solves the problem of creating smooth, continuous gradients without manual tuning of piecewise linear methods. It is distinguished from the parent method by replacing key-value pair interpolation with closed-form expressions, and from [Voxel Color Mapping](2970-voxel-color-mapping.md) by its reliance on global parametric definitions.

### [Transfer Function Editor (Alpha Pins)](6772-transfer-function-editor-alpha-pins.md)
The Transfer Function Editor (Alpha Pins) is an interactive visualization tool that maps scalar voxel values to color and opacity using a pin-based interface. It distinguishes itself by using geometric primitives (ramps, hats) for opacity and vertical markers for color gradients, rather than editing a continuous curve or parametric function directly.

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (CT scans) using the Hounsfield scale [S9, unofficial]. The Hounsfield value is calculated as $HU = \frac{\mu_{tissue} - \mu_{water}}{\mu_{water}} \times 1000$ [S9, unofficial]. Water has a HU value of 0, air -1000, and bone 500-1500 [S9, unofficial]. It is implemented as a LUT where a color value is read out for a given HU value [S9, unofficial].

### Magnitude Color Gradient
A linear blue-green-red gradient stored in a 1D CUDA texture to visualize vector magnitude (velocity), where blue is lowest and red is highest [S10, unofficial]. The gradient is queried using `tex1D` on the GPU [S10, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S2, unofficial]. The interpolated color is calculated as $interpolated color = (f(c_1) + f(c_2))/2$, where $c_1$ and $c_2$ are integer indices [S2, unofficial]. This causes artifacts near large gradients (e.g., fire) because interpolating between red (1,0,0) and blue (0,0,1) yields purple (0.5,0.0,0.5), which is not in the colorbar [S2, unofficial].

### Gradient/Color Ramp Sampling
Reads luminance in float and truncates each channel for the color ramp, as done in Godot [S11, unofficial]. A `GradientTexture2D` with `use_hdr` keeps a channel above 1 [S11, unofficial]. Measured ramp bytes off by one drop from 1212 to 0 of 2244 [S11, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates using `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S12, unofficial]. `align_corners=True` ensures corner pixels align with grid boundaries [S12, unofficial].

### Color Blending
Linearly interpolates between two colors based on a ratio, handling alpha, red, green, and blue channels separately [S13, unofficial]. For each channel: $result = round(c1.ch.channel * (1 - ratio) + c2.ch.channel * ratio)$. Alpha is taken from c1 [S13, unofficial].

## Operating characteristics
- **Time Complexity:** $O(R)$ to generate the LUT, where $R$ is the resolution [S6, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
- **Memory Complexity:** $O(R)$ for the LUT storage [S6, unofficial].
- **Performance:** Linear interpolation is hardware-accelerated on GPUs [S4, unofficial].
- **Strengths:** Simple to implement, fast sampling, ensures colors remain within the defined colorbar [S2, unofficial].
- **Limitations:** Linear interpolation may not capture complex features; higher-order interpolation (e.g., cubic splines) is not supported by default [S3, unofficial]. Inconsistent binning between color and alpha can cause boundary misalignment [S6, unofficial].

## Background
The method was introduced in early volume rendering techniques, with 1D transfer functions being the simplest and most widely used [S1, book]. The concept of using 1D texture lookup tables for transfer functions is detailed in NVIDIA's GPU Gems [S1, book][S8]. The critique of 3D color cube interpolation versus 1D texture map interpolation was highlighted in the Smokeview technical reference [S2, unofficial].
