# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function (LUT), TF1D, 1-D colour LUT, TransferFunction1D

## Overview
1D Transfer Function Generation and Sampling maps scalar voxel data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) or texture [S1, book][S3, unofficial]. It solves the problem of translating abstract numerical intensity data into perceptible visual information, serving as the core classification step in direct volume rendering [S3, unofficial]. Unlike [2D Transfer Function](7592-2d-transfer-function.md) which maps two scalar fields, this method relies on a single scalar measure, typically voxel intensity, to determine optical properties [S1, book]. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by using piecewise linear interpolation between discrete control points rather than continuous analytical functions, and from [Hardcoded Transfer Function](1098-hardcoded-transfer-function.md) by allowing dynamic, user-defined mapping [S5, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of control points defining the mapping, where each point consists of a scalar value (position) and an RGBA color/opacity tuple. Optional inputs include Gaussian objects for opacity shaping and a target LUT resolution (typically 256, 1024, or 65536 entries) [S9, S12, unofficial].
*   **Output:** A 1D texture (or contiguous array) of size $N$ containing interpolated RGBA values, ready for GPU sampling [S2, S9, unofficial].

**Data Structures**
*   **Control Point:** A structure containing `value` (float/int, normalized or raw) and `color` (vec4: r, g, b, a floats in [0,1]) [S5, S9, unofficial].
*   **LUT Array:** A contiguous array of size $N$ (power of two) storing `vec4` entries. Common formats are `float32` (RGBA32F) or `uint8` (RGBA8) [S2, S9, unofficial].
*   **Gaussian Object (Optional):** Defined by `mean`, `sigma`, and `heightFactor`, generating an `alphaArray` of size $N$ [S9, unofficial].

**Steps**

1.  **Initialization:** Create an empty list of control points. If no points are provided, insert a default point (e.g., value 0.0, color 0,0,0,0) [S9, unofficial].
2.  **Sorting:** Sort control points by their scalar `value` in ascending order [S9, unofficial].
3.  **LUT Construction:** Iterate through each index $i$ from $0$ to $N-1$ to fill the LUT:
    a.  **Normalization:** Compute the normalized scalar value $v$ corresponding to index $i$. Two binning schemes exist:
        *   Center-aligned: $v = \frac{i + 0.5}{N}$ [S9, unofficial].
        *   Edge-aligned: $v = \frac{i}{N-1}$ [S9, unofficial].
        *   *Note:* Inconsistent binning between color and alpha generation can cause boundary misalignment [S9, unofficial].
    b.  **Interval Search:** Find the two adjacent control points, `left` and `right`, such that `left.value` $\le v \le$ `right.value`. Use `upper_bound` to find the first control point with value $> v$; `right` is this point, `left` is the previous one [S9, unofficial].
    c.  **Clamping:** If $v$ is below the first control point, use the first point. If above the last, use the last point [S9, unofficial].
    d.  **Interpolation Weight:** Calculate the interpolation weight $w$:
        $$ w = \frac{|v - \text{left.value}|}{|\text{right.value} - \text{left.value}|} $$
        *Pitfall:* Division by zero occurs if `left.value` equals `right.value` (duplicate control points) [S8, unofficial].
    e.  **Color Interpolation:** Interpolate RGB components:
        $$ \text{color} = \text{mix}(\text{left.color}, \text{right.color}, w) $$
        *Pitfall:* Do not interpolate colors directly in 3D RGB space if the goal is to stay within a specific colorbar; instead, interpolate indices or use 1D texture mapping to ensure colors remain valid [S3, unofficial].
    f.  **Alpha Handling:**
        *   Interpolate alpha from color control points if separate alpha controls are not used.
        *   If Gaussian objects are present, compute their contribution at index $i$ and combine with the control point alpha using maximum: $\alpha_{final} = \max(\alpha_{control}, \alpha_{gaussian})$ [S9, unofficial].
        *   *Pitfall:* Using `max` overrides opacity rather than blending it [S9, unofficial].
    g.  **Storage:** Store the resulting RGBA vector in `LUT[i]` [S9, unofficial].
4.  **Post-Processing (Optional):** Apply brightness scaling to RGB channels: $\text{color.rgb} \times \text{brightness}$ [S2, unofficial].
5.  **Upload:** Upload the LUT array to GPU memory as a 1D texture (`GL_TEXTURE_1D`) or a 2D texture with height 1 (`GL_TEXTURE_2D`) [S2, S9, unofficial]. Set wrap mode to `CLAMP_TO_EDGE` and filter mode to `LINEAR` (bilinear) for hardware interpolation [S2, S9, unofficial].

**Pseudocode**

```python
def generate_1d_lut(control_points: list[ControlPoint], resolution: int = 256) -> list[vec4]:
    """
    Generates a 1D LUT from control points.
    ControlPoint: {value: float, color: vec4}
    Returns: list of vec4 (RGBA)
    """
    if not control_points:
        control_points = [ControlPoint(value=0.0, color=vec4(0, 0, 0, 0))]
    
    # Sort by value
    control_points.sort(key=lambda cp: cp.value)
    
    n = len(control_points)
    lut = [vec4(0, 0, 0, 0)] * resolution
    
    # Pre-calculate step for center-aligned binning
    # v = (i + 0.5) / resolution
    for i in range(resolution):
        # Normalized value in [0, 1] assuming control points are normalized
        # If control points are raw, map them to [0,1] first
        v = (i + 0.5) / resolution
        
        # Find interval
        # upper_bound returns first element > v
        idx = 0
        for k in range(n):
            if control_points[k].value > v:
                idx = k
                break
        else:
            idx = n # v is greater than all points
        
        if idx == 0:
            # Below first point
            left = control_points[0]
            right = control_points[0]
        elif idx == n:
            # Above last point
            left = control_points[n-1]
            right = control_points[n-1]
        else:
            left = control_points[idx-1]
            right = control_points[idx]
            
        # Interpolation
        denom = right.value - left.value
        if denom == 0:
            w = 0.0
        else:
            w = (v - left.value) / denom
            
        # Linear interpolation of RGBA
        r = left.color.r + w * (right.color.r - left.color.r)
        g = left.color.g + w * (right.color.g - left.color.g)
        b = left.color.b + w * (right.color.b - left.color.b)
        a = left.color.a + w * (right.color.a - left.color.a)
        
        lut[i] = vec4(r, g, b, a)
        
    return lut
```

**Parameters**
*   **Resolution ($N$):** Size of the LUT. Must be a power of two for hardware texture support. Common values: 256 (8-bit data), 1024, 65536 (16-bit data) [S2, S8, S9, unofficial].
*   **Brightness Factor:** Multiplier for RGB channels, default 1.0 [S12, unofficial].

### Hounsfield Scale Color Mapping
A method to assign colors to voxels based on CT attenuation coefficients using the Hounsfield Unit (HU) scale [S14, unofficial]. The HU value is calculated as $\text{HU} = \frac{\mu_{\text{tissue}} - \mu_{\text{water}}}{\mu_{\text{water}}} \times 1000$, where water is 0 HU and bone ranges from 500 to 1500 HU [S14, unofficial]. Implemented as a LUT where the HU value indexes the color table [S14, unofficial].

### 3D Color Cube Interpolation
An older method (Smokeview v4) interpolating colors directly in 3D RGB space: $\text{color} = \frac{f(c_1) + f(c_2)}{2}$ [S3, unofficial]. This causes artifacts (e.g., purple between red and blue) because the interpolated color may not exist in the defined colorbar [S3, unofficial]. The 1D LUT method avoids this by interpolating indices or using 1D texture mapping [S3, unofficial].

### Bilinear Image Sampling
Samples colors from 2D images at specified coordinates using `grid_sample` with `align_corners=True` to prevent edge scaling artifacts [S15, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two LUTs for labelmaps: a soft LUT (float, bilinear) and a hard LUT (byte, point filtering) [S4, unofficial]. Labels are clamped to [0, 255] and mapped to RGBA [S4, unofficial].

### Material Synchronization LUT Adjustment
Adjusts a 1D LUT mapping sample values to material indices, synchronizing value distribution with frame numbers and material centers [S16, unofficial].

### BuildFunctionFromTable
Constructs a transfer function from a pre-existing table of colors, assuming a block memory layout of [R1, G1, B1, ...] and regular spacing between nodes [S17].

### Scalar Mapping Output Formats
Allows setting the output component count for mapped scalars, defaulting to RGBA [S17].

## Operating characteristics
*   **Time Complexity:** LUT generation is $O(N \cdot C)$, where $N$ is resolution and $C$ is the number of control points (using binary search, $O(N \log C)$) [S9, unofficial]. Rendering lookup is $O(1)$ per sample via texture fetch [S1, book].
*   **Memory Complexity:** $O(N)$ for the LUT storage. For $N=256$ and `float32`, this is 4 KB [S2, unofficial].
*   **Performance:** Hardware interpolation (LINEAR filter) is efficient on GPUs. Direct lookup (nearest neighbor) is faster but less smooth [S2, S3, unofficial].
*   **Strengths:** Simple to implement, efficient, supports smooth transitions via interpolation [S5, unofficial].
*   **Limitations:** Limited to single-scalar data. Cannot capture correlations between multiple properties (requires 2D TF) [S1, book]. Interpolation artifacts if colorbar is not linear in perceptual space [S3, unofficial].
*   **When to use:** Standard volume rendering of scalar fields (CT, MRI, simulations) [S1, book][S3, unofficial].
*   **When not to use:** When visualizing relationships between two variables (use 2D TF) or when high-order smoothness is required (use Parametric Generation) [S1, book][S5, unofficial].

## Background
The 1D transfer function is the most widely used classification method in volume rendering, introduced in early GPU Gems chapters and standard graphics pipelines [S1, book]. It maps data values to optical properties (color and opacity) to emphasize features [S1, book]. The use of 1D texture maps for interpolation ensures colors remain within the defined colorbar, avoiding artifacts associated with 3D color cube interpolation [S3, unofficial]. It is implemented in various tools like ClearVolume, Smokeview, and VTK [S2, S3, unofficial][S17].
