# 1D Transfer Function Generation and Sampling

Also called: 1D Transfer Function (LUT), TF1D, 1-D colour LUT, TransferFunction1D

## Overview
1D Transfer Function Generation and Sampling maps scalar volume data values to RGBA color and opacity properties using a one-dimensional lookup table (LUT) [S1, book]. It solves the problem of quantitative data visualization by assigning visual appearance to numerical voxel intensities [S4, unofficial]. Unlike [Parametric Function Generation](5349-parametric-function-generation.md) which computes values analytically, or [Color Blending](5150-color-blending.md) which composites final pixels, this method performs a deterministic, per-voxel assignment based on a pre-computed 1D LUT [S1, book]. It builds on [Lookup Table Implementation](5347-lookup-table-implementation.md) by defining the specific algorithm for constructing the LUT from user-defined control points and sampling it during rendering.

## How it works
**Inputs and Outputs**
*   **Input:** A set of control points defining the transfer function. Each control point consists of a scalar value (position) and an RGBA color vector [S5, unofficial][S9, unofficial]. Optional inputs include Gaussian opacity objects [S9, unofficial] or separate alpha control points [S9, unofficial].
*   **Output:** A contiguous array of 4-component vectors (RGBA) of size $N$ (typically a power of two, e.g., 256, 1024, 65536) [S1, book][S2, unofficial][S9, unofficial]. This array is uploaded to the GPU as a 1D texture (or 2D texture with height 1) for sampling [S2, unofficial][S9, unofficial].

**Data Structures**
*   **Control Point:** A structure containing `value` (float/int, representing the scalar domain position) and `color` (struct with `r`, `g`, `b`, `a` floats) [S5, unofficial].
*   **LUT Array:** A 1D array `m_rgbaTable` of size `resolution` (e.g., 256) where each element is a `vec4f` (RGBA) [S9, unofficial].
*   **Texture:** A GPU texture object (e.g., `GL_TEXTURE_1D` or `GL_TEXTURE_2D` with height 1) with format `RGBA32F` (float) or `RGBA8` (byte), wrap mode `CLAMP_TO_EDGE`, and filter mode `LINEAR` (bilinear) or `NEAREST` [S2, unofficial][S4, unofficial][S9, unofficial].

**Steps**
1.  **Initialization:** Create an empty list of control points. If no control points are provided, insert a default point (e.g., at position 0 with black/transparent color) [S9, unofficial].
2.  **Sorting:** Sort the control points by their scalar value (position) in ascending order [S9, unofficial].
3.  **LUT Construction (CPU-side):**
    *   Determine the resolution $N$ of the LUT (e.g., 256) [S2, unofficial][S9, unofficial].
    *   For each index $i$ from $0$ to $N-1$:
        *   Compute the normalized scalar value $v$. Sources vary on binning:
            *   Center-aligned: $v = \frac{i + 0.5}{N}$ [S9, unofficial].
            *   Edge-aligned: $v = \frac{i}{N-1}$ [S9, unofficial][S2, unofficial].
        *   Find the interval $[p_L, p_R]$ in the sorted control points such that $p_L \le v \le p_R$ [S9, unofficial].
        *   If $v < p_0$ (first control point), clamp to $p_0$ [S9, unofficial].
        *   If $v > p_{last}$ (last control point), clamp to $p_{last}$ [S9, unofficial].
        *   Calculate interpolation weight $w$:
            $$ w = \frac{|v - p_L|}{|p_R - p_L|} $$
            [S9, unofficial]
        *   Interpolate color $c$ and alpha $\alpha$:
            $$ c = \text{mix}(c_L, c_R, w) $$
            $$ \alpha = \text{mix}(\alpha_L, \alpha_R, w) $$
            [S9, unofficial]
        *   Store the interpolated color in the LUT: `m_rgbaTable[i] = vec4f(c, alpha)` [S9, unofficial].
4.  **Alpha Combination (Optional):** If Gaussian opacity objects or separate alpha controls are present, compute their contribution at each index $i$ and update the alpha channel. The sources indicate using the maximum (`std::max`) of the control-point alpha and the Gaussian alpha [S9, unofficial].
5.  **Normalization:** Ensure RGB components are in $[0, 1]$ and alpha in $[0, 1]$. Some implementations round alpha to two decimal places [S5, unofficial].
6.  **GPU Upload:**
    *   Convert the LUT array to a contiguous buffer (float or byte) [S2, unofficial].
    *   Bind a 1D or 2D texture.
    *   Set parameters: `GL_TEXTURE_WRAP_S = GL_CLAMP_TO_EDGE`, `GL_TEXTURE_MIN_FILTER = GL_LINEAR`, `GL_TEXTURE_MAG_FILTER = GL_LINEAR` [S2, unofficial][S4, unofficial].
    *   Upload data using `glTexImage1D` or `glTexImage2D` [S2, unofficial][S9, unofficial].
7.  **Sampling (Shader-side):**
    *   Read the scalar voxel value $v$ from the volume texture [S1, book].
    *   Normalize $v$ to the domain $[0, 1]$ using window/level parameters ($x_{min}, x_{max}$) [S2, unofficial].
    *   Sample the transfer function texture: `color = texture(tfTex, vec2(normalized_v, 0.5))` [S2, unofficial].
    *   Apply brightness scaling if defined: `color.rgb *= brightness` [S2, unofficial].
    *   **Opacity Correction:** Multiply color components by opacity for correct compositing (opacity-weighted color) [S1, book].

**Pseudocode**
```python
def generate_1d_lut(control_points, resolution=256):
    """
    Generates a 1D LUT from control points.
    control_points: list of dicts {'value': float, 'color': [r,g,b,a]}
    resolution: int, size of the LUT
    returns: list of [r,g,b,a] tuples
    """
    if not control_points:
        control_points = [{'value': 0.0, 'color': [0.0, 0.0, 0.0, 0.0]}]
    
    # Sort by value
    control_points.sort(key=lambda p: p['value'])
    
    # Normalize control point values to [0, 1] if they are not already
    # Assuming control point values are in the domain [0, 1]
    # If they are in raw data units, they must be normalized first
    
    lut = []
    
    for i in range(resolution):
        # Center-aligned binning [S9, unofficial]
        v = (i + 0.5) / resolution
        
        # Find interval
        # Find the first control point with value >= v
        left_idx = 0
        for idx, cp in enumerate(control_points):
            if cp['value'] >= v:
                left_idx = idx
                break
        else:
            left_idx = len(control_points) - 1
            
        # Determine left and right control points
        if left_idx == 0:
            left_cp = control_points[0]
            right_cp = control_points[0]
            w = 0.0
        elif left_idx >= len(control_points):
            left_cp = control_points[-1]
            right_cp = control_points[-1]
            w = 0.0
        else:
            left_cp = control_points[left_idx - 1]
            right_cp = control_points[left_idx]
            
            # Calculate weight [S9, unofficial]
            denom = right_cp['value'] - left_cp['value']
            if denom == 0:
                w = 0.0
            else:
                w = abs(v - left_cp['value']) / denom
                
        # Interpolate color [S9, unofficial]
        r = left_cp['color'][0] + w * (right_cp['color'][0] - left_cp['color'][0])
        g = left_cp['color'][1] + w * (right_cp['color'][1] - left_cp['color'][1])
        b = left_cp['color'][2] + w * (right_cp['color'][2] - left_cp['color'][2])
        a = left_cp['color'][3] + w * (right_cp['color'][3] - left_cp['color'][3])
        
        # Optional: Combine with Gaussian alpha using max [S9, unofficial]
        # a = max(a, gaussian_alpha[i])
        
        # Clamp to [0, 1]
        r = max(0.0, min(1.0, r))
        g = max(0.0, min(1.0, g))
        b = max(0.0, min(1.0, b))
        a = max(0.0, min(1.0, a))
        
        lut.append([r, g, b, a])
        
    return lut

def sample_lut(lut, scalar_value, domain_min=0.0, domain_max=1.0):
    """
    Samples the LUT for a given scalar value.
    """
    # Normalize scalar value to [0, 1]
    if domain_max == domain_min:
        normalized_v = 0.0
    else:
        normalized_v = (scalar_value - domain_min) / (domain_max - domain_min)
        
    # Clamp to [0, 1]
    normalized_v = max(0.0, min(1.0, normalized_v))
    
    # Map to LUT index
    # Using edge-aligned mapping for sampling to match generation if edge-aligned
    # Or center-aligned if generation used center-aligned. 
    # Hardware linear sampling handles this automatically if texture is set up correctly.
    # For direct lookup:
    idx = int(normalized_v * (len(lut) - 1))
    idx = max(0, min(len(lut) - 1, idx))
    
    return lut[idx]
```

**Parameters**
*   `resolution`: Size of the LUT. Common values: 256, 1024, 65536 [S2, unofficial][S9, unofficial].
*   `brightness_factor`: Multiplier for RGB channels, default 1.0 [S12, unofficial].
*   `domain_min`, `domain_max`: The range of scalar values mapped to [0, 1] [S2, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero:** If adjacent control points have the same value, the interpolation weight calculation divides by zero [S8, unofficial]. Guard against this by checking `denom == 0` [G].
*   **Inconsistent Binning:** If color and alpha are generated using different binning schemes (e.g., center-aligned vs edge-aligned), they may misalign at boundaries [S9, unofficial]. Use a consistent scheme [G].
*   **Alpha Combination:** Using `max` for alpha combination means Gaussian opacity overrides control opacity if higher, but does not attenuate it [S9, unofficial].
*   **Dirty Flag:** The LUT must be marked "dirty" when control points change and uploaded to the GPU only when dirty to avoid redundant uploads [S2, unofficial].

## Subtopics

### Hounsfield Scale Color Mapping
A method to assign color values to voxels based on attenuation coefficients (e.g., from CT scans) using the Hounsfield scale [S14, unofficial]. It is implemented as a LUT where a color value is read out for a given HU value [S14, unofficial]. The Hounsfield unit is calculated as $HU = \frac{\mu_{tissue} - \mu_{water}}{\mu_{water}} \times 1000$ [S14, unofficial]. Water has a HU value of 0, and bone ranges from 500 to 1500 HU [S14, unofficial].

### 3D Color Cube Interpolation
An interpolation method used in Smokeview version 4 and earlier where colors are interpolated directly within the 3D RGB color space [S3, unofficial]. The interpolated color is calculated as the average of two colors: $interpolated\ color = \frac{f(c_1) + f(c_2)}{2}$, where $c_1$ and $c_2$ are integer indices [S3, unofficial]. This causes artifacts near large gradients (e.g., fire) because interpolating between red (1,0,0) and blue (0,0,1) yields purple (0.5,0.0,0.5), which is not in the colorbar and has no physical meaning [S3, unofficial]. The 1D LUT method avoids this by interpolating indices, not colors [S3, unofficial].

### Bilinear Image Sampling
Samples colors from a batch of images at specified 2D pixel coordinates using bilinear interpolation [S15, unofficial]. It takes an `images` tensor of shape `[batch_size, H, W, C]` and an `xy_grid` of shape `[N, 2]` [S15, unofficial]. The grid coordinates are flipped, reshaped, and permuted, then passed to `torch.nn.functional.grid_sample` with `align_corners=True` and `mode="bilinear"` [S15, unofficial]. `align_corners=True` ensures corner pixels align with grid boundaries, preventing coordinate scaling artifacts at image edges [S15, unofficial].

### Labelmap Transfer Function LUT Construction
Constructs two 1D LUT textures (soft and hard) for labelmap transfer functions [S4, unofficial]. The soft LUT uses float precision and bilinear filtering; the hard LUT uses byte precision and point filtering [S4, unofficial]. It initializes float and byte pixel arrays of size 256 [S4, unofficial]. For each label entry, it calculates the index, extracts RGBA, and stores it in the respective arrays [S4, unofficial]. The float array is uploaded to a `RGBAFloat` texture with `Bilinear` filtering, and the byte array to a `RGBA32` texture with `Point` filtering [S4, unofficial].

### Material Synchronization LUT Adjustment
An algorithm to adjust a 1D LUT mapping sample values to material indices, ensuring synchronization with the frame number and material centers [S16, unofficial]. It calculates a common base allocation range $d = \frac{frameNumber}{colorKind}$ and initializes material center positions $indexM[i] = d \cdot i + \frac{d}{2}$ for each material $i$ [S16, unofficial]. It then decrements the count for the selected material and stores the index [S16, unofficial].

### BuildFunctionFromTable
Constructs a color transfer function from a pre-existing table of colors [S17]. The function range becomes $[x_1, x_2]$, the size is `nodes`, and function values are regularly spaced between $x_1$ and $x_2$ [S17]. The table layout is assumed to be `[R1, G1, B1, R2, G2, B2, ..., Rn, Gn, Bn]` in a block of memory of size `[3*size]` [S17].

### Scalar Mapping Output Formats
The output format for mapped scalars can be set to specific component counts [S17]. The default output format is RGBA if not supplied [S17].

### Color Table Filtering
A method to filter procedural textures by filtering the 1D color table $C$ rather than the noise function, returning the average color over a small interval [S18]. It evaluates the average color using MIP-mapping on the 1D color table [S18]. The interval size $\delta$ is computed from the filter size and the maximum gradient of $C$ with respect to $u$ [S18].

## Operating characteristics
*   **Time Complexity:** LUT generation is $O(N \cdot K)$ where $N$ is the LUT resolution and $K$ is the number of control points (or $O(N \log K)$ if binary search is used for interval finding) [S9, unofficial]. Sampling is $O(1)$ per voxel [S1, book].
*   **Memory Complexity:** $O(N)$ for the LUT array, where $N$ is the resolution (e.g., 256 entries $\times$ 16 bytes = 4 KB for float32) [S2, unofficial].
*   **Performance:** Hardware interpolation using 1D textures is very fast and efficient on GPUs [S1, book][S3, unofficial].
*   **Strengths:** Simple to implement, efficient, allows smooth transitions between colors via interpolation [S1, book][S5, unofficial].
*   **Limitations:** Limited to scalar data; cannot capture correlations between multiple data fields (requires 2D TF) [S1, book]. Linear interpolation may not capture complex non-linear mappings [S5, unofficial].
*   **When to Use:** When the volume data is scalar and the visual properties depend primarily on the intensity value [S1, book].
*   **When Not to Use:** When the data is multi-dimensional or requires complex correlations between different data measures (e.g., gradient magnitude) [S1, book].

## Background
1D transfer functions are the simplest and most widely used transfer functions in volume rendering [S1, book]. They map the range of data values to color and opacity [S1, book]. The method is typically implemented with 1D texture lookup tables [S1, book]. The concept of using 1D texture maps to interpolate color indices (rather than colors directly) to avoid artifacts in the color cube was highlighted in Smokeview [S3, unofficial]. The opacity-weighted color multiplication was established by Wittenbrink et al. (1998) [S1, book].
