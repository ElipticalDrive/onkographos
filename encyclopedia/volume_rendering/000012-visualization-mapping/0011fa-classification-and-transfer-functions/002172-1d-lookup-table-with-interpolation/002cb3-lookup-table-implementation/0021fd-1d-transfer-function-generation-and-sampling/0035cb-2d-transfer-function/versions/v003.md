# 2D Transfer Function

Also called: 2D Transfer Function for Volumes, tf2d

## Overview
A 2D transfer function maps two separate scalar fields to color and opacity using a 2D lookup table (image), enabling the visualization to compare and contrast spatial features of the two fields [S1, unofficial][S2]. Unlike separable 1D transfer functions which combine two 1D lookups, the 2D transfer function allows for non-separable, arbitrary 2D mappings without implementation constraints on combination [S2].

## How it works
**Inputs and Outputs**
*   **Input 1 (X-axis):** A `SPATIAL_FIELD` object providing the primary scalar values for the volume [S2].
*   **Input 2 (Y-axis):** Either a second scalar field (via `SetColorArray`/`SetColorArray2Component`) or the gradient magnitude of the primary scalar field (`grad(value)`) [S1, unofficial][S2].
*   **Input 3 (Range):** A `FLOAT32_BOX1` or `FLOAT64_BOX1` specifying the range of sampled values from the primary field [S2]. Default is `[0, 1]`. Sampled values are clamped to this range [S2].
*   **Output:** An `ARRAY2D` of `Color` objects (RGBA), where the image width represents the X-axis field and the image height represents the Y-axis field [S2].

**Data Structures**
The transfer function is composed of rectangular regions of interest (boxes) [S1, unofficial].
*   `vtkPVTransferFunction2DBox`: Represents a single box. Exposes API for bounds (min/max X, min/max Y), color, and opacity [S1, unofficial].
*   `vtkPVTransferFunction2D`: Manages a vector of `vtkPVTransferFunction2DBox` objects. Provides utility API for adding, removing, and editing control boxes [S1, unofficial]. Uses a `Build` method to compose the final image data [S1, unofficial].
*   `vtkSMTransferFunction2DProxy`: Proxy class managing the server-side `vtkPVTransferFunction2D` object [S1, unofficial].

**Algorithm Steps**
1.  **Compute Histogram (Optional but Recommended):** Compute a 2D histogram over the two chosen scalar fields to highlight areas where interesting relationships exist [S1, unofficial]. The output is a one-component `vtkImageData` of type `double`, visualized as a grayscale image slice where white indicates highest density and black indicates lowest [S1, unofficial].
2.  **Initialize Transfer Function:** Create an empty `vtkPVTransferFunction2D` instance [S1, unofficial].
3.  **Define Regions:** For each region of interest, create a `vtkPVTransferFunction2DBox` [S1, unofficial].
    *   Set the box bounds within the histogram bounds or data ranges [S1, unofficial].
    *   Set the user-specifiable color and opacity for the box [S1, unofficial].
4.  **Generate Lookup Table:** Call `vtkPVTransferFunction2D::Build()` [S1, unofficial].
    *   Initialize the output `ARRAY2D` of `Color` objects to transparent black [G].
    *   For each pixel $(u, v)$ in the `ARRAY2D`:
        *   Map $u$ to X-axis value $x$ and $v$ to Y-axis value $y$ based on the image dimensions and the defined value ranges [G].
        *   Check if $(x, y)$ falls within the bounds of any defined box [S1, unofficial].
        *   If $(x, y)$ is inside a box, determine the contribution [S1, unofficial]. The sources state that color and opacity are "distributed in the box area as a 2D Gaussian distribution" [S1, unofficial].
        *   Calculate the Gaussian weight $w$ for the pixel based on its distance from the box center $(c_x, c_y)$ and the box dimensions (acting as standard deviations $\sigma_x, \sigma_y$) [G].
        *   $w = \exp\left(-\frac{(x-c_x)^2}{2\sigma_x^2} - \frac{(y-c_y)^2}{2\sigma_y^2}\right)$ [G].
        *   Set the output color at $(u, v)$ to the box's color weighted by $w$ [S1, unofficial].
5.  **Apply:** Set the resulting `ARRAY2D` as the `lookupTable` for the volume rendering object [S2].

**Pseudocode**
```python
from math import exp

class Color:
    def __init__(self, r=0.0, g=0.0, b=0.0, a=0.0):
        self.r, self.g, self.b, self.a = r, g, b, a
    def __add__(self, other):
        return Color(self.r + other.r, self.g + other.g, self.b + other.b, self.a + other.a)
    def __mul__(self, scalar):
        return Color(self.r * scalar, self.g * scalar, self.b * scalar, self.a * scalar)

def build_2d_transfer_function(boxes, width, height, x_range, y_range):
    if width < 2 or height < 2:
        return [[Color(0, 0, 0, 0) for _ in range(width)] for _ in range(height)]
    lut = [[Color(0, 0, 0, 0) for _ in range(width)] for _ in range(height)]
    for v in range(height):
        for u in range(width):
            x = x_range[0] + (u / (width - 1)) * (x_range[1] - x_range[0])
            y = y_range[0] + (v / (height - 1)) * (y_range[1] - y_range[0])
            acc_color = Color(0, 0, 0, 0)
            acc_opacity = 0.0
            for box in boxes:
                if box.x_min <= x <= box.x_max and box.y_min <= y <= box.y_max:
                    cx, cy = (box.x_min + box.x_max) / 2, (box.y_min + box.y_max) / 2
                    sx, sy = (box.x_max - box.x_min) / 2, (box.y_max - box.y_min) / 2
                    w = exp(-((x - cx)**2 / (2 * sx**2)) - ((y - cy)**2 / (2 * sy**2)))
                    acc_color = acc_color + box.color * w
                    acc_opacity += box.opacity * w
            lut[v][u] = Color(acc_color.r, acc_color.g, acc_color.b, acc_opacity)
    return lut
```

**Parameters**
*   `SetUseTransfer2D`: Boolean property to enable the use of 2D transfer functions [S1, unofficial].
*   `SetUseGradientForTransfer2D`: Boolean property. If true, Y-axis is `grad(value)`. If false, Y-axis is a second scalar array [S1, unofficial].
*   `Number of histogram bins`: Defines the resolution of the displayed 2D histogram. Changing this triggers an update if Automatic histogram is enabled [S1, unofficial].
*   `valueRange`: `FLOAT32_BOX1` or `FLOAT64_BOX1`. Default `[0, 1]` [S2].

**Edge Cases and Pitfalls**
*   **Axis Ambiguity:** A prescriptive interpretation is that the X-axis represents the scalar `value` and the Y-axis represents `grad(value)` [S2]. However, the UI allows selecting a second array if gradient is disabled [S1, unofficial].
*   **UI Constraint:** The widget for selecting the Y-axis array is only shown if the option to use gradient is disabled [S1, unofficial].
*   **Overlap:** The sources do not specify how overlapping boxes are handled in the final LUT. Standard practice is additive blending or last-wins [G].
*   **Normalization:** The mapping from pixel coordinates to scalar values requires normalization based on `valueRange` and the range of the second field. The sources do not specify if the second field's range is auto-computed or user-defined [G].

## Operating characteristics
*   **Memory:** The lookup table is an `ARRAY2D` of `Color` objects. Memory usage scales with the product of the X and Y axis resolutions (image width $\times$ height) [G]. This is generally larger than two separate 1D LUTs if the 2D function is separable, but necessary for non-separable mappings [S2].
*   **Performance:** Rendering requires a 2D texture lookup per sample [G].
*   **Strengths:** Enables visualization of relationships between two scalar fields (e.g., density and temperature) [S1, unofficial]. Supports non-separable mappings [S2].
*   **Limitations:** More complex to define and edit than 1D transfer functions. Requires careful selection of the two scalar fields [S1, unofficial].

## Background
*   **Origin:** Implemented in ParaView 5.11 for GPU-based raycaster volume rendering algorithms [S1, unofficial].
*   **Standardization:** Defined in the `KHR_VOLUME_TRANSFER_FUNCTION2D` extension for ANARI [S2].
*   **History:** The feature was added to ParaView to allow users to define and edit 2-dimensional transfer functions for volume visualization of structured data, enhancing "edges" in scalar values when coupled with gradient magnitude [S1, unofficial].
