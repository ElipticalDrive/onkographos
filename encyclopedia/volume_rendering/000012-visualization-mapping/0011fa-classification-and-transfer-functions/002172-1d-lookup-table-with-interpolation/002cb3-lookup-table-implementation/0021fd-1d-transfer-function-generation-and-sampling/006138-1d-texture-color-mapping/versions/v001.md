# 1D Texture Color Mapping

Also called: Color coding via 1D texture mapping, Colorbar Texture Interpolation, Scalar field visualization on surfaces, Slice Color Mapping, Texture-based color interpolation

## Overview
1D Texture Color Mapping is a technique for visualizing scalar fields on surfaces by mapping scalar values to texture coordinates in a 1D color ramp (texture map) and sampling the resulting color at the pixel level [S1, S2]. It solves the problem of color interpolation artifacts that occur when standard hardware linearly interpolates RGB vertex colors across sparsely tessellated geometry, which causes high-contrast or non-linear color transitions to appear blurred or incorrect [S2]. It is distinguished from sibling methods like [Voxel Color Mapping](2970-voxel-color-mapping.md) by operating on surface geometry rather than volumetric voxels, and from [Gradient/Color Ramp Sampling](4337-gradient-color-ramp-sampling.md) by explicitly leveraging the graphics pipeline's texture sampling hardware for per-pixel accuracy [S1, S2].

## How it works
**Inputs:**
- A 3D surface mesh (set of vertices and polygons, typically triangles) [S2].
- A scalar property value $s$ associated with each vertex $v_i$ [S2].
- A 1D color map (texture) $T$ of width $W$, where each texel $T[u]$ stores an RGBA color [S1, S2].

**Outputs:**
- A rendered image where each pixel is colored according to the scalar value at that point on the surface, sampled from $T$ [S1, S2].

**Data Structures:**
- **Texture Map $T$**: A 1D array of size $W$. Each entry $T[u]$ is a 4-component vector $(R, G, B, A)$ with components in $[0, 1]$. The index $u$ corresponds to the normalized texture coordinate $t \in [0, 1]$.
- **Vertex Data**: Each vertex $v_i$ stores a scalar value $s_i$.
- **Texture Coordinates**: Each vertex $v_i$ is assigned a texture coordinate $t_i$ derived from $s_i$.

**Steps:**

1. **Generate the 1D Texture Map**: Create a 1D texture $T$ of width $W$ representing the color bar. The texture is filled such that $T[u]$ contains the color corresponding to the normalized value $u$. For a transfer function defined by key-value pairs $(p_j, c_j)$ where $p_j \in [0, 1]$ are positions and $c_j$ are colors, linear interpolation is used to fill $T$ [S1, S2].
   $$ T[u] = \text{InterpolateColor}(p_j, c_j, u) $$
   where $p_j \le u < p_{j+1}$.

2. **Assign Texture Coordinates**: For each vertex $v_i$ with scalar value $s_i$, compute the normalized texture coordinate $t_i$. This requires mapping the scalar range $[s_{min}, s_{max}]$ to $[0, 1]$:
   $$ t_i = \frac{s_i - s_{min}}{s_{max} - s_{min}} $$
   If $s_i$ is outside $[s_{min}, s_{max}]$, clamp $t_i$ to $[0, 1]$ [S2].

3. **Rasterize and Interpolate**: During rendering, for each pixel covered by a polygon, interpolate the texture coordinate $t$ across the surface using barycentric interpolation of the vertex coordinates $t_i$ [S2].
   $$ t_{pixel} = \alpha t_1 + \beta t_2 + \gamma t_3 $$
   where $\alpha, \beta, \gamma$ are the barycentric coordinates of the pixel within the triangle.

4. **Sample the Texture**: Sample the 1D texture $T$ at the interpolated coordinate $t_{pixel}$. The hardware texture sampler performs linear interpolation between texels if $t_{pixel}$ is not an integer index, retrieving the final RGBA color $C_{pixel}$ [S1, S2].
   $$ C_{pixel} = T[t_{pixel} \cdot (W - 1)] $$

**Parameters:**
- **Texture Width $W$**: Not given in the sources. Typical values for high-precision color mapping are 256 or 512, matching the resolution of the transfer function generation step [S2, Parent].
- **Scalar Range**: $[s_{min}, s_{max}]$. Must be determined from the data or user input [S2].

**Edge Cases and Pitfalls:**
- **Non-linear Color Ramps**: Standard hardware RGB interpolation fails to capture non-linear color transitions because it interpolates R, G, and B channels independently. Texture mapping avoids this by interpolating the texture coordinate $t$ and then sampling the full color from $T$, ensuring sharp transitions are preserved [S2].
- **Multi-dimensional Overload**: Extending the texture to 2D or 3D to visualize multiple properties can overload the surface with information. Care must be taken to ensure the additional dimensions provide meaningful insight [S2].
- **Precision**: The method provides pixel-accurate coloring, meaning the color is accurate to the pixel, unlike the former color cube interpolation method which was less precise [S1].

## Operating characteristics
- **Time Complexity**: $O(N)$ for assigning texture coordinates, where $N$ is the number of vertices. Rendering time is dominated by rasterization and texture sampling, which is hardware-accelerated and effectively $O(P)$ where $P$ is the number of pixels [S2].
- **Memory Complexity**: $O(W)$ for the 1D texture map, where $W$ is the texture width. Vertex data requires $O(N)$ storage [S2].
- **Performance**: Hardware-accelerated texture sampling is efficient. The method allows for real-time changes to the color mapping by updating the texture or texture coordinates [S2].
- **Strengths**: Provides crisp, sharp, and accurate coloring, especially for high-contrast or non-linear color ramps on sparsely tessellated surfaces. It avoids the blurring artifacts of linear RGB interpolation [S1, S2].
- **Limitations**: Requires the surface to be tessellated. For very coarse meshes, the interpolation of $t$ across large triangles may still smooth out sharp scalar changes, though less severely than RGB interpolation [S2].
- **When to Use**: When visualizing scalar fields on surfaces (e.g., molecular surfaces, slice plots) where color accuracy and sharp transitions are critical, and the geometry may be sparsely tessellated [S1, S2].
- **When Not to Use**: When visualizing volumetric data directly without surface extraction, or when multiple independent properties need to be visualized simultaneously without risking information overload [S2].

## Background
The method was introduced as an improvement over color cube interpolation for visualizing data in slice, boundary, and PLOT3D files in Fire Dynamics Simulation (FDS) data visualization tools like Smokeview [S1]. It was also independently developed for molecular graphics to address the problem of high-contrast color variation on sparsely tessellated molecular surfaces, such as the solvent-accessible surface of Gramicidine A and ethanol [S2]. The technique leverages the independence of texture space and object space to allow real-time modifications to the color mapping [S2].
