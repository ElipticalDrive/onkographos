# Fire Color and Opacity Curves

Also called: Color Gradient, Intensity/Opacity Curve

## Overview
Fire Color and Opacity Curves remap grid simulation data channels (such as Temperature or Fuel) into render-ready color and opacity values for fire visualization. It distinguishes itself from generic transfer functions by explicitly separating the color mapping (via a gradient) from the intensity/opacity mapping (via a curve), with specific modes for handling opacity relative to smoke.

## How it works
**Inputs and Outputs:**
*   **Input:** A grid simulation data channel (e.g., Temperature, Fuel) laid out horizontally along the X-axis.
*   **Output:** Final fire color (RGB) and opacity (alpha) or intensity values used in rendering.

**Data Structures:**
The method uses two primary visual controls, both defined by a set of points $(x_i, y_i)$:
1.  **Color Gradient:** Maps simulation value ($x$) to color ($y$). The $x$-axis represents the selected source channel value. The $y$-axis represents the color component.
2.  **Intensity/Opacity Curve:** Maps simulation value ($x$) to a scalar value ($y$). The $x$-axis represents the selected source channel value. The $y$-axis represents either luminance (intensity) or opacity, depending on the mode.

**Parameters:**
*   `emRampColor_t`, `emRampColor_s`, `emRampColor_v`, `emRampColor_f`: Control the color of the light as a function of the selected channel's value. These correspond to the color gradient points.
*   `epower_t`, `epower_s`, `epower_v`, `epower_f`: Control the scalar value of the curve.
    *   If Opacity Mode is **Use Smoke Opacity** or **Fully Visible**, these determine the **luminance** (intensity) of the emitted light.
    *   If Opacity Mode is **Use Own Opacity**, these determine the **opacity** of the emitted light.
*   `emMult`: General multiplier for the fire color's intensity.
*   `emAlphaMult`: Multiplier for the fire's own opacity. Used **only** when Opacity Mode is **Use Own Opacity**.

**Algorithm:**
1.  **Select Source Channel:** Identify the grid simulation channel (e.g., Temperature) to base the mapping on.
2.  **Sample Gradient:** For a given simulation value $v$, sample the Color Gradient to get a base color $C_{base}$. The gradient points define the mapping from $v$ to RGB.
3.  **Sample Curve:** For the same value $v$, sample the Intensity/Opacity Curve to get a scalar factor $S$.
    *   If Opacity Mode is **Use Smoke Opacity** or **Fully Visible**: $S$ is the intensity multiplier.
    *   If Opacity Mode is **Use Own Opacity**: $S$ is the base opacity.
4.  **Apply Color Multiplier:** Calculate the final fire color $C_{final}$:
    $$ C_{final} = C_{base} \times emMult $$
5.  **Apply Opacity/Intensity:**
    *   **Case A: Use Smoke Opacity or Fully Visible**
        The fire's opacity is determined by the smoke (external). The fire contributes color with intensity $S$.
        $$ Color_{render} = C_{final} \times S $$
        $$ Alpha_{render} = Alpha_{smoke} $$
    *   **Case B: Use Own Opacity**
        The fire's opacity is determined by the curve $S$.
        $$ Alpha_{final} = S \times emAlphaMult $$
        $$ Color_{render} = C_{final} $$
        (Note: The final alpha is clamped to [0, 1]).

**Edge Cases and Pitfalls:**
*   **Data Range Highlight:** The selected channel's data range is highlighted in light blue on the curve controls. Values outside this range may behave unpredictably if extrapolation is not defined.
*   **Mode Dependency:** The interpretation of `epower` points changes based on the Opacity Mode. Using `epower` for intensity when "Use Own Opacity" is selected will incorrectly set opacity instead of brightness.
*   **Multiplier Interaction:** `emMult` affects color intensity, while `emAlphaMult` affects opacity only in "Use Own Opacity" mode.

## Subtopics

### Color Gradient
A control that maps simulation values to RGB colors. It sets apart from the curve by outputting a vector (color) rather than a scalar. Choose it when you need to define the visual hue and brightness distribution of the fire based on simulation data. [Gradient/Color Ramp Sampling](4337-gradient-color-ramp-sampling.md)

### Intensity/Opacity Curve
A control that maps simulation values to a scalar. It differs from the gradient by outputting a single value used for either luminance or alpha. Choose it to control how "bright" or "transparent" the fire appears at different simulation densities. [Gradient/Color Ramp Sampling](4337-gradient-color-ramp-sampling.md)

## Operating characteristics
*   **Time Complexity:** $O(1)$ per pixel/voxel, assuming linear interpolation between curve points.
*   **Memory Complexity:** $O(N)$ where $N$ is the number of control points in the gradient and curve.
*   **Strengths:** Intuitive visual editing; separates color logic from opacity logic; flexible handling of smoke interaction.
*   **Limitations:** Dependent on the specific UI implementation (Phoenix for Maya); limited to 1D mapping; no spatial variation beyond the simulation channel.
*   **When to use:** When rendering fire from grid-based simulations (like Phoenix) and needing precise control over how temperature/fuel maps to visual appearance.
*   **When not to use:** For non-grid data, or when complex 3D transfer functions are required.

## Background
This method originates from the Phoenix for Maya plugin by Chaos Group. It is part of the Voxel Shader system, specifically designed to bridge the gap between fluid/grid simulation data and the final rendered image. The terminology (`emRampColor`, `epower`) reflects the internal API of the Phoenix software.
