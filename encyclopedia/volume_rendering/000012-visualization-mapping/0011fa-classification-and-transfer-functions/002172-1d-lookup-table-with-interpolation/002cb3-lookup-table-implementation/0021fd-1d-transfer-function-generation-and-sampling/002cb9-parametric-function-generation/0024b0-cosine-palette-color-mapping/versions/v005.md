# Cosine Palette Color Mapping
Also called: Inigo Quilez Palette
## Overview
Cosine Palette Color Mapping generates smooth, perceptually distinct color gradients from a scalar input using a parametric cosine function with specific vector parameters [S1, unofficial]. It solves the problem of creating visually rich transfer functions for volume rendering without the complexity of multi-component basis functions, offering a compact alternative to piecewise linear or Gaussian methods [S1, unofficial]. Unlike [Gaussian Transfer Function](4408-gaussian-transfer-function.md) which uses bell curves for localized highlighting, this method uses a single cosine wave per channel to create global, oscillating color transitions [S1, unofficial].
## How it works
**Inputs and Outputs**:
- Input: A normalized scalar parameter $t \in [0, 1]$ derived from volume data [S1, unofficial].
- Output: An RGBA color vector $\mathbf{C} = (R, G, B, A)$. The alpha channel is typically handled separately or set to a constant; this method primarily defines the RGB components [S1, unofficial].

**Data Structures**:
- Parameters are stored as three 3D vectors $\mathbf{a}, \mathbf{b}, \mathbf{c}, \mathbf{d}$ where each component corresponds to the Red, Green, and Blue channels respectively.
- $\mathbf{a} = (0.5, 0.5, 0.5)$
- $\mathbf{b} = (0.5, 0.5, 0.5)$
- $\mathbf{c} = (1.0, 1.0, 1.0)$
- $\mathbf{d} = (0.00, 0.33, 0.67)$

**Steps**:
1. Normalize the input scalar value $v$ to $t \in [0, 1]$ using the parent's domain normalization formula [S1, unofficial].
2. Compute the RGB color components using the parametric equation:
   $$ \mathbf{C}_{rgb} = \mathbf{a} + \mathbf{b} \cdot \cos(2\pi (\mathbf{c} \cdot t + \mathbf{d})) $$
   where the operations are performed component-wise.
3. Clamp the resulting RGB values to the range $[0, 1]$ to handle any numerical precision issues or out-of-bounds results [G].
4. Assign the alpha channel $A$ based on the specific transfer function requirements (e.g., constant opacity or a separate alpha function) [G].

**Pseudocode**:
```python
def cosine_palette(t: float) -> tuple:
    """
    Generates an RGB color using the Inigo Quilez Cosine Palette.
    
    Args:
        t: Normalized scalar input in [0, 1].
        
    Returns:
        A tuple (R, G, B) with values in [0, 1].
    """
    # Define palette parameters as vectors
    a = (0.5, 0.5, 0.5)
    b = (0.5, 0.5, 0.5)
    c = (1.0, 1.0, 1.0)
    d = (0.00, 0.33, 0.67)
    
    # Compute the argument for the cosine function
    # arg = c * t + d
    arg_r = c[0] * t + d[0]
    arg_g = c[1] * t + d[1]
    arg_b = c[2] * t + d[2]
    
    # Apply cosine and scale by 2*pi
    cos_r = math.cos(2 * math.pi * arg_r)
    cos_g = math.cos(2 * math.pi * arg_g)
    cos_b = math.cos(2 * math.pi * arg_b)
    
    # Calculate final color components: a + b * cos(...)
    r = a[0] + b[0] * cos_r
    g = a[1] + b[1] * cos_g
    b_val = a[2] + b[2] * cos_b
    
    # Clamp to [0, 1]
    r = max(0.0, min(1.0, r))
    g = max(0.0, min(1.0, g))
    b_val = max(0.0, min(1.0, b_val))
    
    return (r, g, b_val)
```

**Parameters**:
- $\mathbf{a}$: Offset vector. Default: $(0.5, 0.5, 0.5)$.
- $\mathbf{b}$: Amplitude vector. Default: $(0.5, 0.5, 0.5)$.
- $\mathbf{c}$: Frequency vector. Default: $(1.0, 1.0, 1.0)$.
- $\mathbf{d}$: Phase shift vector. Default: $(0.00, 0.33, 0.67)$.

**Edge Cases**:
- If $t$ is outside $[0, 1]$, the color may wrap around or produce unexpected hues. Clamping $t$ is recommended [G].
- The phase shifts $(0.00, 0.33, 0.67)$ ensure that the three color channels are offset by $1/3$ of a cycle, creating a balanced, non-monochromatic gradient [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per voxel, involving a few trigonometric evaluations and arithmetic operations.
- **Memory Complexity**: $O(1)$, storing only four constant vectors.
- **Strengths**: Extremely compact definition; produces smooth, visually pleasing gradients with minimal parameters; easy to implement in shaders [S1, unofficial].
- **Limitations**: Limited control over specific color transitions compared to multi-component basis functions; may not highlight specific data ranges as effectively as Gaussian methods [S1, unofficial].
- **When to use**: General-purpose volume rendering where aesthetic appeal and simplicity are prioritized over precise data-driven color mapping.

## Background
The method was popularized by Inigo Quilez in the context of procedural shading and raymarching, where it is used to generate aesthetically pleasing color palettes from simple scalar inputs [S1, unofficial]. It has been adapted for volume rendering as a parametric transfer function generation technique.
