# Cosine Palette Color Mapping

Also called: Inigo Quilez Palette

## Overview
Cosine Palette Color Mapping generates smooth, perceptually distinct color gradients from a scalar input $t \in [0, 1]$ using a vectorized cosine function with per-channel phase offsets [S1, unofficial]. It solves the problem of creating visually rich, continuous transfer functions for volume rendering without the discontinuities of piecewise linear maps or the complexity of multi-basis splines. Unlike [Gaussian Transfer Function](4408-gaussian-transfer-function.md), which relies on additive bell curves to highlight specific density ranges, this method uses a single periodic wave structure to create a repeating spectral palette, offering a simpler, differentiable alternative for general data visualization [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: A scalar value $t$, normalized to the range $[0, 1]$.
- Output: A color vector $\mathbf{c} = (r, g, b)$, where each component is in $[0, 1]$.

**Data Structures**
The method relies on four constant vectors $\mathbf{a}, \mathbf{b}, \mathbf{c}, \mathbf{d} \in \mathbb{R}^3$. These are typically hardcoded as uniform variables in a shader or constants in a CPU implementation.

**Parameters**
The standard parameters defined by Inigo Quilez are:
- $\mathbf{a} = (0.5, 0.5, 0.5)$
- $\mathbf{b} = (0.5, 0.5, 0.5)$
- $\mathbf{c} = (1.0, 1.0, 1.0)$
- $\mathbf{d} = (0.00, 0.33, 0.67)$

**Formula**
The color $\mathbf{c}(t)$ is computed component-wise as:
$$ \mathbf{c}(t) = \mathbf{a} + \mathbf{b} \cdot \cos\left(2\pi \cdot (\mathbf{c} \cdot t + \mathbf{d})\right) $$
where $\cdot$ denotes element-wise multiplication and addition. The cosine function returns values in $[-1, 1]$, which are scaled by $\mathbf{b}$ and shifted by $\mathbf{a}$ to fit the $[0, 1]$ range.

**Pseudocode**
```python
import math

def cosine_palette(t: float) -> tuple[float, float, float]:
    """
    Computes the Inigo Quilez Cosine Palette color for scalar t in [0, 1].
    
    Args:
        t: Normalized scalar input value.
        
    Returns:
        A tuple (r, g, b) with values in [0, 1].
    """
    # Constants as defined by Inigo Quilez
    a = (0.5, 0.5, 0.5)
    b = (0.5, 0.5, 0.5)
    c = (1.0, 1.0, 1.0)
    d = (0.00, 0.33, 0.67)
    
    # Compute the argument for the cosine function for each channel
    # arg = 2 * pi * (c_i * t + d_i)
    # cos_val = cos(arg)
    # result_i = a_i + b_i * cos_val
    
    r = a[0] + b[0] * math.cos(2 * math.pi * (c[0] * t + d[0]))
    g = a[1] + b[1] * math.cos(2 * math.pi * (c[1] * t + d[1]))
    b_val = a[2] + b[2] * math.cos(2 * math.pi * (c[2] * t + d[2]))
    
    return (r, g, b_val)
```

**Edge Cases and Pitfalls**
- **Input Range**: The formula assumes $t \in [0, 1]$. Values outside this range will produce colors outside the intended palette range, potentially causing overflow or unexpected hues. Clamping $t$ to $[0, 1]$ is recommended [G].
- **Precision**: Floating-point precision errors are negligible for this simple trigonometric evaluation.
- **Degenerate Input**: If $\mathbf{b}$ is zero, the output is constant $\mathbf{a}$. This is not a degenerate case in terms of validity but results in a grayscale output.

## Subtopics

### [Blue-Red Colormap](3921-blue-red-colormap.md)
The Blue-Red Colormap is a visualization mapping technique that converts scalar depth values into a perceptually distinct color gradient ranging from blue (near) to red (far). It solves the problem of interpreting 3D spatial structure from rendered depth buffers by providing a high-contrast, continuous color representation. Unlike the parent Cosine Palette Color Mapping which generates smooth gradients via trigonometric functions, this method uses a piecewise linear "jet-like" function specifically optimized for depth visualization, where blue represents minimum depth and red represents maximum depth.

### [Hue Transfer Function](4574-hue-transfer-function.md)
A procedural transfer function that maps a scalar input value to an RGB color based on hue cycles, using smoothstep functions to create continuous color bands. It generates a repeating spectral palette where the input value determines the position within a 6-segment hue cycle. Unlike [Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md), which uses a single cosine wave for smooth gradients, this method constructs distinct color bands using piecewise linear interpolation (smoothstep) to ensure sharp transitions between primary and secondary hues while maintaining continuity.

## Operating characteristics
- **Time Complexity**: $O(1)$ per sample. The computation involves a fixed number of arithmetic operations and one trigonometric function evaluation per channel.
- **Memory Complexity**: $O(1)$. Only four constant vectors are stored.
- **Performance**: Extremely fast, suitable for real-time volume rendering on GPUs. The cosine function is hardware-accelerated in most graphics APIs.
- **Strengths**: Smooth, continuous gradients; no discontinuities; simple parameterization; visually appealing spectral colors.
- **Limitations**: The palette is fixed; custom color ranges require modifying the constants $\mathbf{a}, \mathbf{b}, \mathbf{c}, \mathbf{d}$, which may not yield intuitive results. The repeating nature may not be suitable for data where monotonicity is required.
- **When to use**: General-purpose volume rendering where smooth, colorful gradients are desired without specific color mapping requirements.
- **When not to use**: When specific color semantics (e.g., blue for low, red for high) are critical, or when monotonic color mapping is required.

## Background
The Cosine Palette Color Mapping technique was popularized by Inigo Quilez in the context of ray marching and procedural graphics [S1, unofficial]. It has been adopted in volume rendering as a simple, effective way to generate transfer functions that provide good visual contrast and smooth transitions. The method is part of the broader family of parametric transfer functions, which define color mappings using analytic functions rather than discrete lookup tables.
