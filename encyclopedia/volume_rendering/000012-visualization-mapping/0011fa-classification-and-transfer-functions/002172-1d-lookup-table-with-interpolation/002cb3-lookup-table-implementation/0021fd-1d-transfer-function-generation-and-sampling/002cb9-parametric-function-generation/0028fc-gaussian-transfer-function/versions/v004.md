# Gaussian Transfer Function

Also called: 3-Gaussian Transfer Function, TransferFunctionWidget3

## Overview
The Gaussian Transfer Function constructs a 4-channel RGBA transfer function texture using three Gaussian bumps to control opacity and color contribution based on scalar value position [S1, unofficial]. It differs from its siblings by explicitly normalizing RGB channels by their maximum sum to prevent overflow and ensuring smooth, differentiable transitions via Gaussian basis functions, unlike the piecewise or sigmoidal approaches of [Sigmoid Function with Jacobian](6497-sigmoid-function-with-jacobian.md) or the palette-based mapping of [Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** Three sets of parameters for the Gaussian bumps: `levels` (centers), `opacities` (max contributions), and `widths` (standard deviations). Each set contains 3 floats in the range $[0, 1]$ for levels and $[0, \infty)$ for widths/opacities.
*   **Outputs:** A 1D lookup table (texture) of shape $(1024, 4)$, where index $i$ corresponds to normalized scalar position $t = i / 1023.0$. Channels 0-2 are RGB color, channel 3 is opacity.

**Data Structures:**
*   `rgba`: A numpy array of shape `(1024, 4)` initialized to zeros.
*   `colors`: A list of 3 RGB vectors, hardcoded to `red`, `green`, and `blue` from matplotlib's color converter [S1, unofficial].
*   `levels`, `opacities`, `widths`: Lists of 3 floats each.

**Parameters:**
*   `levels`: `[0.1, 0.5, 0.8]` (Default)
*   `opacities`: `[0.4, 0.1, 0.1]` (Default)
*   `widths`: `[0.1, 0.1, 0.1]` (Default)

**Steps:**
1.  Initialize `rgba` array of shape $(1024, 4)$ with zeros.
2.  Define color vectors $\mathbf{c}_j$ for $j \in \{0, 1, 2\}$ as Red, Green, and Blue respectively.
3.  For each texel index $i$ from 0 to 1023:
    a. Calculate normalized position: $t = i / 1023.0$.
    b. Initialize `intensity_sum` = 0.0.
    c. For each Gaussian bump $j$ from 0 to 2:
        i. Calculate Gaussian intensity: $I_j = \exp\left(-\left(\frac{t - \text{levels}[j]}{\text{widths}[j]}\right)^2\right)$.
        ii. Add color contribution: `rgba[i, 0:3]` += $\mathbf{c}_j \times \text{opacities}[j] \times I_j$.
        iii. Add opacity contribution: `rgba[i, 3]` += $\text{opacities}[j] \times I_j$.
    d. Normalize RGB channels: Let $M = \max(\text{rgba}[i, 0], \text{rgba}[i, 1], \text{rgba}[i, 2])$. If $M > 0$, `rgba[i, 0:3]` /= $M$. If $M = 0$, leave RGB as 0 to avoid NaN [S1, unofficial].
    e. Clamp all values: `rgba[i]` = $\text{clip}(\text{rgba}[i], 0, 1)$.

**Pseudocode:**
```python
import numpy as np

def generate_gaussian_transfer_function(levels, opacities, widths):
    """
    Generate a 1024x4 RGBA transfer function using 3 Gaussian bumps.
    
    Args:
        levels: List of 3 floats [l1, l2, l3] in [0, 1].
        opacities: List of 3 floats [o1, o2, o3] >= 0.
        widths: List of 3 floats [w1, w2, w3] > 0.
        
    Returns:
        numpy array of shape (1024, 4) with RGBA values in [0, 1].
    """
    N = 1024
    rgba = np.zeros((N, 4))
    
    # Hardcoded colors: Red, Green, Blue
    colors = [
        np.array([1.0, 0.0, 0.0]),
        np.array([0.0, 1.0, 0.0]),
        np.array([0.0, 0.0, 1.0])
    ]
    
    for i in range(N):
        t = i / 1023.0
        intensity_sum = 0.0
        
        for j in range(3):
            # Gaussian intensity calculation
            # Note: widths[j] must be > 0 to avoid division by zero. 
            # If widths[j] is 0, intensity is 0 unless t == levels[j], 
            # but standard Gaussian implementation assumes width > 0.
            if widths[j] == 0:
                intensity = 0.0
            else:
                intensity = np.exp(-((t - levels[j]) / widths[j]) ** 2)
            
            # Add color contribution
            rgba[i, 0:3] += colors[j] * opacities[j] * intensity
            
            # Add opacity contribution
            rgba[i, 3] += opacities[j] * intensity
            
        # Normalize RGB channels by their maximum to prevent overflow
        max_rgb = np.max(rgba[i, 0:3])
        if max_rgb > 0:
            rgba[i, 0:3] /= max_rgb
        # If max_rgb is 0, RGB remains 0, avoiding NaN
        
        # Clamp values to [0, 1]
        rgba[i] = np.clip(rgba[i], 0, 1)
        
    return rgba
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If no Gaussian contributes to the RGB channels (i.e., all `opacities` are 0 or `widths` are effectively 0 at the current $t$), `max_rgb` is 0. The code must check for this to avoid NaN values, which `np.clip` might not handle predictably across all implementations [S1, unofficial].
*   **Width Zero:** If `widths[j]` is 0, division by zero occurs in the Gaussian formula. The implementation should handle this by setting intensity to 0 (or 1 if $t == \text{levels}[j]$ for a Dirac delta, but the source uses standard Gaussian with division, implying width > 0) [S1, unofficial].
*   **Opacity Range:** Opacities are not clamped to [0, 1] in the source, but the final `clip` ensures output is valid. However, high opacity values can lead to very bright colors before normalization if not managed [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$ where $N=1024$ is the texture size and $K=3$ is the number of Gaussians. This is constant time relative to scene complexity, making it very fast for texture generation.
*   **Memory Complexity:** $O(N)$ for the 1D texture, specifically $1024 \times 4$ floats (or bytes if quantized).
*   **Performance:** The generation is performed in Python using numpy loops in the reference implementation, which is slower than vectorized operations but sufficient for interactive tuning in a Jupyter environment [S1, unofficial].
*   **Strengths:** Simple parameterization, smooth transitions, explicit control over color mixing via RGB normalization.
*   **Limitations:** Fixed 3-bump structure limits complexity. Hardcoded colors (Red, Green, Blue) restrict artistic control compared to methods allowing arbitrary color selection. The normalization step can alter perceived color intensity if not understood.
*   **When to Use:** When a simple, smooth, multi-component transfer function is needed with explicit control over opacity peaks and color mixing, particularly in interactive visualization tools like ipyvolume.
*   **When Not to Use:** When complex, non-Gaussian shapes are required, or when arbitrary color palettes are needed beyond the primary RGB mix.

## Background
The Gaussian Transfer Function is implemented in the `ipyvolume` library's `transferfunction` module, specifically as `TransferFunctionWidget3` [S1, unofficial]. It was developed by Maarten Breddels as part of the ipyvolume project for interactive 3D visualization in Jupyter notebooks. It differs from `TransferFunctionJsBumps` by computing the RGBA texture in Python using matplotlib colors and explicit normalization, whereas the JS-based version handles computation in the browser [S1, unofficial].
