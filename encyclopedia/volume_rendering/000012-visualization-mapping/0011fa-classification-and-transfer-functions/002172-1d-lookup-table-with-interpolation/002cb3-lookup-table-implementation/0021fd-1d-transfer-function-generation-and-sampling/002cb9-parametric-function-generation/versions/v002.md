# Parametric Function Generation

Also called: Parametric Transfer Functions, Analytic Transfer Functions

## Overview
Parametric Function Generation defines transfer functions (TFs) using closed-form mathematical expressions rather than discrete control points or piecewise linear segments. It solves the problem of defining smooth, continuous, and differentiable color/opacity mappings with a small set of global parameters, enabling automatic generation, optimization, and smooth interpolation. It differs from [1D Transfer Function Generation and Sampling](2689-1d-transfer-function-generation-and-sampling.md), which relies on explicit key-value pairs and interpolation, by providing a compact, analytic representation that is inherently smooth and often differentiable, facilitating gradient-based tuning.

## Shared principles
All methods in this family map a normalized scalar input $t \in [0, 1]$ (representing the normalized data value) to an RGBA output vector. The core mechanism involves evaluating a parametric function $f(t; \theta)$, where $\theta$ represents a set of tunable parameters (e.g., centers, widths, phases, amplitudes).

Key shared characteristics:
1.  **Continuity**: The resulting transfer function is continuous (and often infinitely differentiable) over the domain $[0, 1]$, avoiding the visual artifacts associated with piecewise linear interpolation.
2.  **Parameterization**: The shape of the TF is controlled by a small number of parameters rather than a large lookup table. This allows for compact storage and easy manipulation.
3.  **Basis Functions**: Most methods use basis functions (Gaussian, Sigmoid, Cosine) that can be combined linearly or non-linearly to construct complex multi-component mappings.
4.  **Normalization**: Since parametric functions may produce values outside the $[0, 1]$ range or unbounded outputs, post-processing steps such as clamping, normalization, or saturation are often required to ensure valid color/opacity values.

## Subtopics

### [Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md)
[Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md) generates smooth, perceptually distinct color gradients from a scalar input $t \in [0, 1]$ using a vectorized cosine function with per-channel phase offsets. It solves the problem of creating visually rich, continuous transfer functions for volume rendering without the discontinuities of piecewise linear maps or the complexity of multi-basis splines. Unlike [Gaussian Transfer Function](4408-gaussian-transfer-function.md), which relies on additive bell curves to highlight specific density ranges, this method uses a single periodic wave structure to create a repeating spectral palette, offering a simpler, differentiable alternative for general data visualization.

### [Gaussian Transfer Function](4408-gaussian-transfer-function.md)
[Gaussian Transfer Function](4408-gaussian-transfer-function.md) is a parametric method for generating a 4-channel RGBA transfer function texture using three Gaussian basis functions to map scalar data values to color and opacity. It solves the problem of defining smooth, multi-component visualization mappings by combining independent color contributions from red, green, and blue channels with a shared opacity field. It differs from its sibling [Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md) by using localized Gaussian bumps rather than global periodic functions, allowing for precise control over specific data ranges.

### [Sigmoid Function with Jacobian](6497-sigmoid-function-with-jacobian.md)
[Sigmoid Function with Jacobian](6497-sigmoid-function-with-jacobian.md) computes the sigmoid activation $\sigma(x)$ and its analytical derivative $\sigma'(x)$ for scalar inputs. It serves as a differentiable mapping component in transfer function generation, providing smooth, bounded output $[0, 1]$ with known gradient properties essential for optimization-based parameter tuning. It differs from [Cosine Palette Color Mapping](3359-cosine-palette-color-mapping.md) by providing monotonic, non-periodic mapping, and from [Gaussian Transfer Function](4408-gaussian-transfer-function.md) by lacking localized peak control, instead offering global asymptotic behavior.

### Rainbow Transfer Function Preset
**Definition**: Generates a transfer function initialized with a 7-segment rainbow color map spanning $[0, 1]$, with no Gaussian objects [S1, unofficial].
**Steps**:
1. Create TF with given resolution.
2. Clear existing controls.
3. Add 7 ColorControls at positions $0/6, 1/6, 2/6, 3/6, 4/6, 5/6, 6/6$.
4. Assign RGB values: $(0, 0.364706, 1)$, $(0, 1, 0.976471)$, $(0, 1, 0.105882)$, $(0.968627, 1, 0)$, $(1, 0.490196, 0)$, $(1, 0, 0)$, $(0.662745, 0, 1)$.
5. Clear Gaussian objects.
6. Call `updateColorMap()` [S1, unofficial].

### Style Function Animation
**Definition**: A time-varying coefficient function $S(t)$ used to modify rendering style, providing smooth transitions based on user interaction start/stop events [S2, unofficial].
**Steps**:
- For rotation, the style function value is the same for the whole object [S2, unofficial].
- For zooming, a spatially-dependent factor is transferred: style parameters are adjusted so that the closer a voxel's projection is to the interaction point, the higher the style-function value is [S2, unofficial].
**Formula**:
$$ S(t_{current}) = S(t_{start}) \cdot e^{-(t_{current} - t_{start})} + S(t_{dest}) \cdot (1 - e^{-(t_{current} - t_{start})}) $$
where $S(t_{current})$ is the current style function value, $S(t_{start})$ is the value before interaction start/end, $S(t_{dest})$ is 0 if interaction stopped and 1 if started, $t_{current}$ is current time, and $t_{start}$ is start time [S2, unofficial].
**Parameter**: Output range is a floating point value in interval $[0, 1]$. 0 corresponds to no interaction, 1 to very long interaction [S2, unofficial].

### Random Transfer Function Generation
**Definition**: Generates a random transfer function LUT [S3, unofficial].
**Steps**:
1. Clear the LUT [S3, unofficial].
2. Iterate `i` from 0 to `n_bins - 1`. If `i == 0`, push `glm::vec4(0)`. Otherwise, push `glm::vec4(randf(), randf(), randf(), randf())` [S3, unofficial].
3. Call `upload_gpu()` [S3, unofficial].
**Parameter**: `n_bins`: Number of bins. Default value is 8 [S3, unofficial].

## Background
Parametric transfer functions originated in the early days of volume rendering as a way to simplify the user interface for defining visualization mappings. Instead of manipulating numerous control points, users could adjust a few parameters to define the overall "shape" of the transfer function. The Gaussian Transfer Function, in particular, has been widely adopted in scientific visualization for its ability to isolate specific data ranges with smooth, bell-shaped curves. The Cosine Palette, popularized by Inigo Quilez in the context of procedural shading, has been adapted for volume rendering to provide perceptually uniform color ramps. The use of sigmoid functions with Jacobians has gained traction in recent years due to the rise of differentiable rendering and optimization-based parameter tuning, where gradients are required for backpropagation.
