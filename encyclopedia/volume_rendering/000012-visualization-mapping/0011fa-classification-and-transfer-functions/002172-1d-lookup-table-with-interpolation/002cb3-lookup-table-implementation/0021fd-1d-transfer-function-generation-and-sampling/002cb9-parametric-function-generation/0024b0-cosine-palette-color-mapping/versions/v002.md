# Cosine Palette Color Mapping

Also called: Inigo Quilez Palette

## Overview
Cosine Palette Color Mapping generates smooth, perceptually distinct color gradients from a scalar input by evaluating a cosine function with channel-specific phase offsets [S1, unofficial]. It solves the problem of creating visually rich, continuous transfer functions for volume rendering without the discontinuities of piecewise linear maps or the complexity of multi-parameter splines [S1, unofficial]. Unlike the [Gaussian Transfer Function](4408-gaussian-transfer-function.md), which relies on additive basis functions to create localized peaks, this method uses global periodic interference to create complex, non-repeating patterns from simple trigonometric components [S1, unofficial].

## How it works
**Inputs and Outputs**
*   Input: A scalar value $t \in [0, 1]$ representing normalized data (e.g., density, temperature).
*   Output: A color vector $\mathbf{c} = (r, g, b) \in [0, 1]^3$.

**Data Structures**
The method relies on four constant vectors of size 3 (floats):
*   $\mathbf{a}$: Base color offset.
*   $\mathbf{b}$: Amplitude scaling.
*   $\mathbf{c}$: Frequency scaling.
*   $\mathbf{d}$: Phase shift.

**Parameters**
The standard "Inigo Quilez" palette uses the following values [S1, unofficial]:
*   $\mathbf{a} = (0.5, 0.5, 0.5)$
*   $\mathbf{b} = (0.5, 0.5, 0.5)$
*   $\mathbf{c} = (1.0, 1.0, 1.0)$
*   $\mathbf{d} = (0.00, 0.33, 0.67)$

**Formula**
The color for each channel $i \in \{R, G, B\}$ is computed as:
$$ c_i = a_i + b_i \cos(2\pi (c_i t + d_i)) $$

**Pseudocode**
```python
def cosine_palette(t: float) -> tuple[float, float, float]:
    """
    Computes the Inigo Quilez cosine palette color for scalar t.
    t: float in [0, 1]
    Returns: (r, g, b) tuple in [0, 1]
    """
    # Constants from [S1, unofficial]
    a = (0.5, 0.5, 0.5)
    b = (0.5, 0.5, 0.5)
    c = (1.0, 1.0, 1.0)
    d = (0.0, 0.33, 0.67)
    
    r = a[0] + b[0] * cos(2 * PI * (c[0] * t + d[0]))
    g = a[1] + b[1] * cos(2 * PI * (c[1] * t + d[1]))
    b_val = a[2] + b[2] * cos(2 * PI * (c[2] * t + d[2]))
    
    # Clamp to [0, 1] to handle potential precision errors or out-of-range inputs [G]
    r = max(0.0, min(1.0, r))
    g = max(0.0, min(1.0, g))
    b_val = max(0.0, min(1.0, b_val))
    
    return (r, g, b_val)
```

**Edge Cases and Pitfalls**
*   **Precision**: Floating-point errors in the cosine evaluation may result in values slightly outside $[0, 1]$. Clamping is required [G].
*   **Boundary Conditions**: The function is periodic. If $t$ is not normalized to $[0, 1]$, the color pattern will repeat. The specific phase offsets ensure that the full range $[0, 1]$ covers a significant portion of the color cycle without immediate repetition at the boundaries.

## Subtopics

### [Blue-Red Colormap](3921-blue-red-colormap.md)
The Blue-Red Colormap is a visualization mapping technique that converts scalar depth values into a perceptually distinct color gradient ranging from blue (near) to red (far). It solves the problem of interpreting 3D spatial structure from rendered depth buffers by providing a high-contrast, continuous color representation. Unlike the parent Cosine Palette Color Mapping which generates smooth gradients via trigonometric functions, this method uses a piecewise linear "jet-like" function specifically optimized for depth visualization, where blue represents minimum depth and red represents maximum depth.

### Hue Transfer Function
A procedural transfer function that maps a scalar input value to an RGB color based on hue cycles, using smoothstep functions to create continuous color bands [S2, unofficial]. It calculates Red, Green, and Blue channels using specific `smoothstep` intervals defined by a `HUE_PART` constant ($1/6 \approx 0.16666666666666$) [S2, unofficial]. The formula for the channels is:
*   $r = \text{smoothstep}(HUE, 2HUE, x) - \text{smoothstep}(4HUE, 5HUE, x)$
*   $g = \text{smoothstep}(0, HUE, x) - \text{smoothstep}(3HUE, 4HUE, x)$
*   $b = \text{smoothstep}(2HUE, 3HUE, x) - \text{smoothstep}(5HUE, 6HUE, x)$
The final color is returned as $(1-r, g, b)$ with alpha 1.0 [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per pixel/voxel. Requires 3 cosine evaluations and basic arithmetic.
*   **Memory Complexity**: $O(1)$. Only constant vectors are stored.
*   **Performance**: Extremely fast, suitable for real-time ray marching in fragment shaders [S1, unofficial].
*   **Strengths**: Produces visually pleasing, high-contrast gradients with minimal parameters. No lookup table memory overhead.
*   **Limitations**: The color distribution is fixed by the constants; customizing the gradient requires changing the vectors $\mathbf{a}, \mathbf{b}, \mathbf{c}, \mathbf{d}$. It does not naturally support opacity mapping unless combined with a separate function.
*   **When to use**: When a rich, continuous color gradient is needed for scalar data visualization without the overhead of a large LUT.
*   **When not to use**: When specific, localized color bands are required (use [Gaussian Transfer Function](4408-gaussian-transfer-function.md) or [Hue Transfer Function](3921-hue-transfer-function.md)).

## Background
The method was popularized by Inigo Quilez in the context of procedural shading and ray marching [S1, unofficial]. It is widely used in real-time graphics and volume rendering demos to provide aesthetically pleasing color maps with minimal code [S1, unofficial].
