# Blue-Red Colormap

Also called: Depth Normalization & Blue-Red Colormap, Depth Visualization, Depth Visualization via Min-Max Normalization, Jet-like Colormap

## Overview
The Blue-Red Colormap is a visualization mapping technique that converts scalar depth values into a perceptually distinct color gradient ranging from blue (near) to red (far) [S1, S2, unofficial]. It solves the problem of interpreting 3D spatial structure from rendered depth buffers by providing a high-contrast, continuous color representation [S1, S2, unofficial]. Unlike the parent Cosine Palette Color Mapping which generates smooth gradients via trigonometric functions, this method uses a piecewise linear "jet-like" function specifically optimized for depth visualization, where blue represents minimum depth and red represents maximum depth [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A depth buffer containing raw depth values $d_{i,j}$ for each pixel $(i,j)$, and the global minimum ($d_{min}$) and maximum ($d_{max}$) depth values across the entire image [S1, S2, unofficial].
*   **Output:** An RGB image where each pixel is colored according to its normalized depth value [S1, S2, unofficial].

**Data Structures:**
*   `depth`: A 2D array or flattened vector of shape $(H, W)$ or $(H \times W)$ containing raw depth values [S2, unofficial].
*   `render_buffer`: A 2D array of shape $(H, W, 3)$ storing the final RGB output [S2, unofficial].
*   `min_v`, `max_v`: Scalar values representing the global minimum and maximum depth [S2, unofficial].

**Steps:**

1.  **Compute Global Extents:** Determine the minimum and maximum depth values across all rays/pixels. This is typically done using atomic operations in parallel implementations to ensure consistency across all threads [S2, unofficial].
    $$ d_{min} = \min_{i,j} (d_{i,j}) $$
    $$ d_{max} = \max_{i,j} (d_{i,j}) $$
    [S2, unofficial]

2.  **Normalize Depth:** For each pixel, normalize the raw depth value to the range $[0, 1]$ using min-max normalization. A small epsilon ($\epsilon = 10^{-8}$) is added to the denominator to prevent division by zero in degenerate cases where $d_{max} = d_{min}$ [S1, unofficial].
    $$ x = \frac{d_{i,j} - d_{min}}{d_{max} - d_{min} + \epsilon} $$
    [S1, S2, unofficial]

3.  **Compute Color Channels:** Calculate the Red ($R$), Green ($G$), and Blue ($B$) channels using piecewise linear functions of the normalized depth $x$ [S1, unofficial]:
    $$ R = \text{clip}(2x - 1, 0, 1) $$
    $$ G = \text{clip}(1 - |2x - 1|, 0, 1) $$
    $$ B = \text{clip}(1 - 2x, 0, 1) $$
    [S1, unofficial]
    *   When $x=0$ (near), $R=0, G=0, B=1$ (Blue).
    *   When $x=0.5$ (mid), $R=0, G=1, B=0$ (Green).
    *   When $x=1$ (far), $R=1, G=0, B=0$ (Red).

4.  **Finalize Output:** Stack the channels into an RGB vector, scale to $[0, 255]$, and cast to `uint8` for storage or display [S1, unofficial].
    $$ \text{Color}_{i,j} = \text{uint8}([R, G, B] \times 255) $$
    [S1, unofficial]

**Pseudocode:**

```python
def blue_red_colormap(depth_buffer, height, width):
    """
    Applies Blue-Red colormap to a depth buffer.
    
    Args:
        depth_buffer: 2D array of shape (height, width) with raw depth values.
        height: Integer, height of the image.
        width: Integer, width of the image.
        
    Returns:
        rgb_image: 2D array of shape (height, width, 3) with uint8 RGB values.
    """
    # Step 1: Compute global min and max
    # In a parallel implementation (e.g., Taichi), this uses atomic_min/max.
    # Here, we compute it sequentially for clarity.
    min_v = np.min(depth_buffer)
    max_v = np.max(depth_buffer)
    
    # Step 2: Normalize depth to [0, 1]
    epsilon = 1e-8
    normalized_depth = (depth_buffer - min_v) / (max_v - min_v + epsilon)
    
    # Clip to ensure values are strictly within [0, 1] despite floating point errors
    normalized_depth = np.clip(normalized_depth, 0.0, 1.0)
    
    # Step 3: Compute RGB channels
    # x is the normalized depth
    x = normalized_depth
    
    # Red channel: increases linearly from 0.5 to 1.0
    r = np.clip(x * 2 - 1, 0, 1)
    
    # Green channel: triangular shape, peak at 0.5
    g = np.clip(1 - np.abs(x * 2 - 1), 0, 1)
    
    # Blue channel: decreases linearly from 1.0 to 0.0
    b = np.clip(1 - x * 2, 0, 1)
    
    # Step 4: Stack and convert to uint8
    rgb_image = np.stack((r, g, b), axis=-1) * 255
    rgb_image = rgb_image.astype(np.uint8)
    
    return rgb_image
```

**Parameters:**
*   `epsilon`: Small constant for numerical stability, typically $10^{-8}$ [S1, unofficial].
*   `T_threshold`: Transparency threshold for ray marching termination, default $10^{-2}$ [S2, unofficial]. (Note: This parameter is used in the rendering pipeline that *produces* the depth buffer, not in the colormap function itself, but is part of the context in [S2, unofficial]).
*   `max_samples_for_rendering`: Maximum samples per ray, default 100 [S2, unofficial].
*   `dist_to_focus`: Distance to focus for Depth of Field, default 1.2 [S2, unofficial].
*   `len_dis`: Lens size for Depth of Field, default 0.04 [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Variance:** If $d_{max} = d_{min}$, the denominator becomes zero. The epsilon term prevents NaNs, resulting in a uniform color (typically blue if $x=0$ is forced, or undefined if not clipped). Clipping the normalized depth to $[0,1]$ after division handles this [S1, S2, unofficial].
*   **Out-of-Bounds Depth:** Depth values outside the $[d_{min}, d_{max}]$ range calculated from the buffer will be clipped to 0 or 1 by the `clip` function in the channel calculations, ensuring valid RGB output [S1, unofficial].
*   **Precision:** Using `float32` for intermediate calculations is recommended to avoid quantization artifacts in the gradient [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, as it requires a single pass for min/max and a single pass for color mapping [S1, S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the depth buffer and the output RGB image [S1, S2, unofficial].
*   **Performance:** Highly efficient and suitable for real-time visualization. The linear operations are computationally inexpensive [S1, S2, unofficial].
*   **Strengths:** High contrast between near and far objects; simple to implement; perceptually distinct colors for different depth ranges [S1, S2, unofficial].
*   **Limitations:** Not perceptually uniform; the green band in the middle may obscure subtle depth variations in the mid-range [S1, unofficial]. It is specifically designed for depth visualization and may not be suitable for other scalar fields [S1, S2, unofficial].
*   **When to use:** Visualizing depth maps from NeRF or other volumetric renderers where spatial structure needs to be quickly assessed [S1, S2, unofficial].
*   **When not to use:** When perceptual uniformity is required (e.g., scientific data visualization) or when the depth range is not the primary variable of interest [S1, unofficial].

## Background
The Blue-Red Colormap is commonly used in the context of Neural Radiance Fields (NeRF) and other 3D vision tasks to visualize depth outputs [S1, S2, unofficial]. It is often referred to as a "jet-like" colormap due to its similarity to the classic Jet colormap, but simplified to a blue-green-red gradient [S1, S2, unofficial]. The method is implemented in various open-source repositories for NeRF visualization, such as `nerf-3d-vision` and `taichi-ngp-renderer` [S1, S2, unofficial].
