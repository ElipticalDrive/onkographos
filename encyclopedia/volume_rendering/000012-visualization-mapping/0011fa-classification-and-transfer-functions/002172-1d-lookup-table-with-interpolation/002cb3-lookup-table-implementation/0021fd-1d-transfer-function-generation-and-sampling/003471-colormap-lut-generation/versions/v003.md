# Colormap LUT Generation

Also called: Named Colormap LUT Generation, TransferFunction Colormap Generation

## Overview
Colormap LUT Generation is the procedural creation of a 1D lookup table (typically 256 entries of RGBA) from a named colormap definition, serving as the color mapping stage in volume rendering classification [S1, unofficial][S2, unofficial][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A colormap identifier (e.g., 'viridis', 'hot', 'gray') [S2, unofficial][S3, unofficial].
*   **Output:** A 1D texture or array of 256 (or $N$) RGBA values, where each component is typically an 8-bit unsigned integer (uint8) [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **LUT Array:** A contiguous array of size $N$ (default 256) [S3, unofficial]. Each element is a 4-component vector (R, G, B, A) [S1, unofficial][S3, unofficial].
*   **Texture Structure:** In GPU implementations, this is wrapped in a structure containing dimensions (`size.x`, `size.y`) and a `Uint8Array` of RGBA data [S1, unofficial].

**Steps:**
1.  **Initialize LUT:** Create an empty array of size $N$ (default 256) [S3, unofficial].
2.  **Select Colormap:** Identify the target colormap by name (e.g., 'inferno', 'jet', 'viridis') [S2, unofficial][S3, unofficial].
3.  **Generate Colors:** For each index $i$ from 0 to $N-1$:
    *   Calculate normalized position $t = i / N$ [S1, unofficial][S3, unofficial].
    *   Compute RGB values based on the colormap algorithm:
        *   **Gray:** $R=G=B = i$, $A=255$ [S1, unofficial].
        *   **Hot:** $R = \min(255, i \times 3)$, $G = \min(255, \max(0, (i - 85) \times 3))$, $B = \min(255, \max(0, (i - 170) \times 3))$, $A=255$ [S1, unofficial].
        *   **Viridis:** $t = i / 255$, $R = \lfloor 68 + 187t \rfloor$, $G = \lfloor 1 + 231t \rfloor$, $B = \lfloor 84 - 82t \rfloor$, $A=255$ [S1, unofficial].
        *   **Red:** $R=255, G=0, B=0, A=255$ for all entries [S1, unofficial].
        *   **Generic/Named:** Use a library function (e.g., `cmap.Colormap(name).lut()`) [S2, unofficial] or `tinycolormap::GetColor(f, type)` [S3, unofficial] to retrieve RGB, then scale to uint8 [S2, unofficial].
    *   Store the resulting RGBA vector in the LUT at index $i$ [S3, unofficial].
4.  **Apply Opacity Modifiers (Optional):**
    *   **Fading:** Clone the LUT. For each $i$, set $A_i = \lfloor (i / (N - 1)) \times 255 \rfloor$ [S1, unofficial].
    *   **Clamping:** Clone the LUT. For each $i$, if $minAlpha < i < maxAlpha$, keep original $A$; otherwise set $A=0$ [S1, unofficial].
5.  **Upload/Export:** Convert the array to `Uint8Array` [S1, unofficial]. Reshape to $(1, N, 3)$ for image export [S2, unofficial]. Upload to GPU memory [S3, unofficial].

**Pseudocode:**
```python
def generate_colormap_lut(name: str, n_bins: int = 256) -> list:
    """
    Generate a 1D LUT for a named colormap.
    Returns a list of 4-tuples (R, G, B, A) as integers 0-255.
    """
    lut = []
    
    def get_color_from_name(name, i, n):
        t = i / n
        if name == 'gray':
            return (i, i, i, 255)
        elif name == 'hot':
            r = min(255, i * 3)
            g = min(255, max(0, (i - 85) * 3))
            b = min(255, max(0, (i - 170) * 3))
            return (r, g, b, 255)
        elif name == 'viridis':
            t = i / 255
            r = int(68 + 187 * t)
            g = int(1 + 231 * t)
            b = int(84 - 82 * t)
            return (r, g, b, 255)
        elif name == 'red':
            return (255, 0, 0, 255)
        else:
            # [G] Other colormaps require external libraries like cmap or tinycolormap [S2, unofficial][S3, unofficial]
            return (0, 0, 0, 255)

    for i in range(n_bins):
        r, g, b, a = get_color_from_name(name, i, n_bins)
        lut.append((r, g, b, a))
        
    return lut

def apply_opacity_fade(lut: list) -> list:
    """
    Apply opacity fading to an existing LUT.
    Alpha becomes proportional to the index.
    """
    n = len(lut)
    new_lut = []
    for i, (r, g, b, a) in enumerate(lut):
        new_a = int((i / (n - 1)) * 255)
        new_lut.append((r, g, b, new_a))
    return new_lut

def apply_opacity_clamp(lut: list, min_alpha_idx: int, max_alpha_idx: int) -> list:
    """
    Apply opacity clamping.
    Alpha is 0 outside the range (min_alpha_idx, max_alpha_idx).
    """
    new_lut = []
    for i, (r, g, b, a) in enumerate(lut):
        if min_alpha_idx < i < max_alpha_idx:
            new_lut.append((r, g, b, a))
        else:
            new_lut.append((r, g, b, 0))
    return new_lut
```

**Parameters:**
*   `name`: String identifier for the colormap (e.g., 'inferno', 'jet', 'viridis', 'hot', 'gray', 'red') [S2, unofficial][S3, unofficial]. Default is 'inferno' [S2, unofficial].
*   `n_bins`: Number of entries in the LUT. Default is 256 [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Precision:** Sources use $i / (N - 1)$ [S1, unofficial] or $i / N$ [S3, unofficial] for normalization.
*   **Alpha Interpretation:** Standard colormaps like 'hot' have constant alpha [S1, unofficial], while fading or clamping can modify it [S1, unofficial].
*   **Library Dependency:** Generating non-standard colormaps requires external libraries like `cmap` [S2, unofficial] or `tinycolormap` [S3, unofficial].

## Subtopics

### Colormap Gaussian Addition
Adds a Gaussian based on an existing colormap, calculating height for each color from the colormap [S4]. The value is calculated as $f(x) = h \exp{-(x-x_0)^2 / w}$, where $h$ is calculated from the colormap [S4]. Parameters: $v$ (float) is the value at which the Gaussian is added, $w$ (float) is the relative width, $\alpha$ (float, optional) is the alpha value height, `colormap` (string, optional) specifies the colormap name, and `col_bounds` (array_like, optional) sets limits [min, max] for the colormap span [S4]. Usage example: `tf.sample_colormap(-7.0, 0.01, colormap="cmyt.arbre")` [S4].

## Background
Early implementations used simple procedural gradients such as 'gray' and 'hot' [S1, unofficial]. Modern implementations leverage libraries like `cmap` [S2, unofficial] and `tinycolormap` [S3, unofficial] to support perceptually uniform colormaps.
