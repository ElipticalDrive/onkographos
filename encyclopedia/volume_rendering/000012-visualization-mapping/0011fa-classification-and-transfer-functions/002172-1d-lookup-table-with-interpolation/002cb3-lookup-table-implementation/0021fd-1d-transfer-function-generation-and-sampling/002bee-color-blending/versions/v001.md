# Color Blending

Also called: Linear Color Interpolation, Linear RGB Blending

## Overview
Color Blending is the final step in the 1D Transfer Function pipeline where two discrete color samples from a lookup table are combined to produce a continuous RGBA output for a specific scalar value. It solves the problem of discrete quantization in transfer functions by providing smooth transitions between defined key colors. Unlike [Voxel Color Mapping](2970-voxel-color-mapping.md) which may involve complex multi-view averaging, this method strictly interpolates between two adjacent entries in a 1D map. It differs from [Parametric Function Generation](5349-parametric-function-generation.md) by using piecewise linear segments rather than continuous mathematical functions.

## How it works
**Inputs and Outputs:**
- Input: Two source colors $C_1$ and $C_2$ (RGBA), and a blending ratio $t \in [0, 1]$.
- Output: A single blended color $C_{out}$ (RGBA).

**Data Structures:**
Colors are represented as 4-channel vectors. In standard 8-bit integer implementations, each channel is an unsigned 8-bit integer ($0-255$).

**Steps:**
1. Calculate the blending ratio $t$ based on the scalar value's position relative to the two nearest transfer function key points.
2. For each color channel $c \in \{R, G, B\}$, compute the linear interpolation:
   $$ c_{out} = \text{round}(c_1 \cdot (1 - t) + c_2 \cdot t) $$
   where $c_1$ and $c_2$ are the integer values of the channel in $C_1$ and $C_2$ respectively.
3. Set the alpha channel of the output to the alpha channel of the first color $C_1$:
   $$ \alpha_{out} = \alpha_1 $$
   Note: Some implementations may interpolate alpha as well, but the primary definition cited here fixes alpha to $C_1$ [S1, unofficial].

**Pseudocode:**
```python
def color_blend(c1: Color, c2: Color, t: float) -> Color:
    """
    Blends two colors using linear interpolation for RGB and fixed alpha from c1.
    
    Args:
        c1: First color (RGBA), values 0-255.
        c2: Second color (RGBA), values 0-255.
        t: Blending ratio, 0.0 <= t <= 1.0.
        
    Returns:
        Blended Color (RGBA), values 0-255.
    """
    # Interpolate RGB channels
    r_out = round(c1.r * (1.0 - t) + c2.r * t)
    g_out = round(c1.g * (1.0 - t) + c2.g * t)
    b_out = round(c1.b * (1.0 - t) + c2.b * t)
    
    # Alpha is taken from c1
    a_out = c1.a
    
    return Color(r_out, g_out, b_out, a_out)
```

**Parameters:**
- $t$: The interpolation factor. Typically derived from the normalized distance between the scalar value and the lower bound of the transfer function interval.

**Edge Cases:**
- If $t=0$, the result is $C_1$.
- If $t=1$, the result is $C_2$.
- Precision: Rounding errors can accumulate if this operation is part of a larger iterative refinement, though for single-step lookup it is negligible.

## Subtopics

### Blur Group Colour Replacement
A post-processing variant used when linear blending causes unwanted blur due to large color differences between $C_1$ and $C_2$ [S2]. It preserves sharpness by replacing the blended color of a "blur group" voxel with a color from a neighboring "clear group" voxel [S2].
- **Definition:** A mechanism to handle cases where the average method causes object blur [S2].
- **Steps:**
  1. Define a threshold for color difference.
  2. If the difference between $C_1$ and $C_2$ exceeds the threshold, place the voxel in a "blur group" [S2].
  3. If the difference is less than or equal to the threshold, place the voxel in a "clear group" [S2].
  4. For voxels in the blur group, replace the computed color $C_{old}$ with the color of a neighboring voxel that belongs to the clear group and has the closest color value to $C_{old}$ [S2].
- **When to choose:** Use when visual sharpness is critical and standard linear blending introduces artifacts due to high contrast between adjacent transfer function keys [S2].

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel. Requires 3 multiplications, 3 additions, and 1 rounding operation per color.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple to implement; provides smooth gradients; computationally inexpensive.
- **Limitations:** Can cause blurring if the color difference between adjacent transfer function keys is large [S2]. Alpha handling is fixed in the primary definition, which may not be suitable for all transparency requirements.
- **When to use:** Standard volume rendering with smooth transfer functions.
- **When not to use:** When sharp edges are required between distinct material classes and the color jump is significant [S2].

## Background
The method originates from standard computer graphics techniques for texture and color interpolation. In the context of volume rendering, it is a fundamental component of 1D lookup table implementations. The specific alpha-handling variant (taking alpha from $C_1$) is documented in the [Musta-Kissa/quadtree-raycast](https://github.com/Musta-Kissa/quadtree-raycast) repository [S1, unofficial]. The concept of replacing blurred colors with clear neighbors to preserve sharpness was introduced in the context of sparse multi-view volumetric representation [S2].
