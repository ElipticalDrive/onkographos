# Hardcoded Transfer Function

Also called: Fixed RGBA Array, Static 1D Lookup Table, 1D Transfer Function, 1D data-based TF, 1D data-based transfer function, 1dTF

## Overview
The Hardcoded Transfer Function (HTF) is a volume rendering classification method that maps a single scalar input value directly to a fixed color and opacity tuple using a pre-defined, static lookup table [S2][S4]. It solves the problem of visualizing scalar field data by assigning RGBA properties based solely on intensity, without considering local geometric context or multi-channel correlations [S2][S4]. Unlike gradient-based or texture-based transfer functions, the HTF relies exclusively on the scalar value itself, making it the simplest and most computationally efficient classification approach, though it cannot distinguish between visually distinct features that share the same intensity [S2][S4].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar data value $v$ (e.g., voxel intensity) and a defined domain $[x_{min}, x_{max}]$.
*   **Output:** A 4-component vector $(R, G, B, \alpha)$ representing the color and opacity for the sample point.

**Data Structures:**
The transfer function is stored as a contiguous array of 4-component vectors.
*   **Format:** Typically `float4` (32-bit floats per component) or 8-bit integers [S1, unofficial][S2][S3, unofficial].
*   **Size:** The number of entries $N$ must be a power of two (e.g., 256, 4096, 65536) to support hardware texture sampling [S1, unofficial][S2][S3, unofficial].
*   **Layout:** A 1D array where index $i$ corresponds to the normalized value mapping to entry $i$. In some hardware implementations (e.g., VolumePro), the LUT may be 4096 entries deep with 36-bit entries (8-bit RGB, 12-bit alpha) [S3, unofficial].

**Steps:**
1.  **Normalization:** Normalize the input scalar $v$ to a coordinate $x \in [0, 1]$ using the defined domain:
    $$ x = \frac{v - x_{min}}{x_{max} - x_{min}} $$
    Values outside $[x_{min}, x_{max}]$ are clamped to $[0, 1]$ [S2][S3, unofficial].
2.  **Lookup:** Retrieve the RGBA value from the table. Two methods are common:
    *   **Hardware Interpolation:** Use texture units with `LINEAR` filter mode to interpolate between adjacent entries based on $x$ [S1, unofficial].
    *   **Direct Lookup:** Compute the integer index for nearest-neighbor sampling:
        $$ idx = \text{clamp}(\lfloor x \cdot (N-1) \rfloor, 0, N-1) $$
        Return the value at `table[idx]` [S3, unofficial].
3.  **Output:** Return the resulting $(R, G, B, \alpha)$ tuple.

**Pseudocode (CUDA Implementation):**
The following implements the class structure and sampling logic described in [S5, unofficial].

```python
import math

class HardcodedTransferFunction:
    def __init__(self, host_table, domain_min, domain_max):
        """
        Initialize the HTF.
        host_table: list of float4 tuples (R, G, B, A) on host memory.
        domain_min, domain_max: float, the scalar range [x_min, x_max].
        """
        self.count = len(host_table)
        self.domain = (domain_min, domain_max)
        
        # 1. Allocate device memory for raw table (direct lookup)
        self.device_table = cuda_malloc(self.count * 16) # 16 bytes per float4
        cuda_memcpy(self.device_table, host_table, self.count * 16, cudaMemcpyHostToDevice)
        
        # 2. Create 1D CUDA array for texture binding
        ch = cuda_channel_format_kind_float # Assuming float4
        self.array = cuda_malloc_1d_array(self.count, 1, ch)
        cuda_memcpy_2d_to_array(self.array, host_table, self.count * 16, 1)
        
        # 3. Create texture object for hardware sampling
        tex_desc = cuda_texture_descriptor()
        tex_desc.filter_mode = cuda_filter_mode_linear
        tex_desc.address_mode[0] = cuda_address_mode_clamp
        tex_desc.normalized_coords = 1
        self.texture_object = cuda_create_texture_object(self.array, tex_desc)

    def sample(self, x):
        """
        Hardware interpolated sampling.
        x: scalar input value.
        Returns: float4 (R, G, B, A).
        """
        # Normalize
        normalized_x = (x - self.domain[0]) / (self.domain[1] - self.domain[0])
        # Clamp is handled by texture address mode
        return tex1D<float4>(self.texture_object, normalized_x)

    def lookup(self, x):
        """
        Direct nearest-neighbor lookup.
        x: scalar input value.
        Returns: float4 (R, G, B, A).
        """
        # Normalize
        normalized_x = (x - self.domain[0]) / (self.domain[1] - self.domain[0])
        # Compute index
        idx = int(normalized_x * (self.count - 1))
        # Clamp index
        idx = max(0, min(idx, self.count - 1))
        return self.device_table[idx]

    def cleanup(self):
        if self.texture_object:
            cuda_destroy_texture_object(self.texture_object)
        if self.array:
            cuda_free_array(self.array)
        if self.device_table:
            cuda_free(self.device_table)
```

**Parameters:**
*   $x_{min}, x_{max}$: The scalar range mapped to the table. Typical values depend on the dataset (e.g., 0-255 for 8-bit images, or Hounsfield units for CT).
*   $N$: Table size. Must be a power of two. Common sizes are 256 or 4096 [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Identical Values:** The method cannot distinguish between samples with the same scalar value but different visual contexts (e.g., boundaries vs. homogeneous regions) [S2][S4].
*   **Opacity Correction:** In some hardware pipelines, opacities may require software correction to account for non-unit sample spacing [S3, unofficial].
*   **Precision:** Opacity values in hardcoded tables are often sparse (e.g., mostly 0.0 or 0.1) [S1, unofficial].

## Subtopics

### [2D Transfer Function Volume Rendering](1295-2d-transfer-function-volume-rendering.md)
Extends the 1D Lookup Table with Interpolation method by mapping both the scalar data value $f$ and the local gradient magnitude $|\nabla f|$ to color and opacity. It solves the problem of overlapping data-value intervals in 1D transfer functions, where different materials or boundaries share similar scalar values but differ in their local structure. By using gradient magnitude as a second dimension, it uniquely isolates material boundaries and homogeneous regions, providing superior tissue differentiation and boundary visualization compared to the Hardcoded Transfer Function.

### [Tent Alpha Transfer Function](3031-tent-alpha-transfer-function.md)
A hardcoded 1D RGBA transfer texture generation method for fluorescence microscopy data that maps 8-bit scalar values to color and opacity using a tent-shaped alpha curve and gamma corrections. It provides a parametric opacity profile centered on a user-defined peak value. It builds on the Hardcoded Transfer Function by defining the color and opacity as a static float array generated from a closed-form mathematical profile rather than a manually edited lookup table.

### Fire Color Palette
A piecewise linear color mapping function that maps a value in $[0,1]$ to a gradient from gray to dark gray to red to orange to yellow [S7, unofficial]. It is implemented by clamping the input $d$ to $[0.0, 1.0]$ and interpolating between specific color stops based on intervals: $[0, 0.25)$ (gray to darkgray), $[0.25, 0.5)$ (darkgray to red), $[0.5, 0.75)$ (red to orange), and $[0.75, 1.0]$ (orange to yellow) [S7, unofficial]. The color stops are: `gray` (0.4, 0.4, 0.4), `darkgray` (0.2, 0.2, 0.2), `red` (1.0, 0.0, 0.0), `orange` (1.0, 0.6, 0.0), and `yellow` (1.7, 1.3, 1.0) [S7, unofficial]. Note that the yellow components can exceed 1.0 [S7, unofficial].

### Exponential Color Transfer Function
Maps volume intensity to color and alpha using an exponential function for alpha and linear interpolation for color [S8, unofficial]. It defines high color as white (1.0, 1.0, 1.0) and low color as black (0.0, 0.0, 0.0) [S8, unofficial]. The color is computed as `intensity * high + (1.0 - intensity) * low` [S8, unofficial]. The alpha is computed as $\alpha = \frac{e^{intensity} - 1}{e^1 - 1}$ [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The lookup is a constant-time operation involving normalization and array access or texture sampling [S2].
*   **Memory Complexity:** $O(N)$, where $N$ is the table size. Typically small (e.g., 256-4096 entries), consuming minimal GPU memory compared to multi-dimensional TFs [S2][S3, unofficial].
*   **Performance:** Lowest computation power and memory usage among transfer function types [S2]. Enables real-time rendering on modest hardware [S2].
*   **Strengths:** High safety against misinterpretation errors due to simplicity; little user interaction required; fast execution [S2].
*   **Limitations:** Cannot differentiate between samples with identical data values but different visual characteristics (e.g., boundaries vs. interiors); fails to capture correlations in multi-channel data [S2][S4].
*   **When to Use:** Simple scalar data visualization where intensity is the primary distinguishing feature; real-time applications with strict performance constraints.
*   **When Not to Use:** Data with overlapping intensity ranges for distinct features; multi-channel data; need for boundary emphasis.

## Background
The Hardcoded Transfer Function is the foundational method for volume rendering classification, originating from early ray-casting and texture-based volume rendering systems. It is described in foundational surveys of transfer functions as the "1D data-based TF" (1dTF) [S2]. The method was implemented in early real-time hardware systems like VolumePro, which used pre-computed 4096-entry LUTs for classification [S3, unofficial]. It serves as a reference point for more complex transfer functions, such as 2D gradient-based or texture-based TFs, which were developed to address its limitations in distinguishing features with similar intensities [S2].
