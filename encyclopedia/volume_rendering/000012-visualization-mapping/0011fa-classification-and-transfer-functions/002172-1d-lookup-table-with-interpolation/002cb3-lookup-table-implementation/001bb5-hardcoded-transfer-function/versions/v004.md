# Hardcoded Transfer Function

Also called: Fixed RGBA Array, Static 1D Lookup Table, 1D Transfer Function, 1D data-based TF, 1dTF, 1D data-based transfer function

## Overview
The Hardcoded Transfer Function (HTF) is a classification method that maps a single scalar input value directly to a fixed RGBA color and opacity tuple using a static lookup table or closed-form function [S1, unofficial][S2][S4]. It solves the problem of visualizing scalar volume data by assigning appearance properties based solely on intensity, ignoring spatial context or multi-channel correlations [S2][S4]. Unlike [2D Transfer Function Volume Rendering](1295-2d-transfer-function-volume-rendering.md), which uses gradient magnitude to disambiguate overlapping intensities, the HTF cannot distinguish between samples with identical scalar values but different structural contexts [S2][S4]. It is chosen when computational efficiency is paramount and the data exhibits distinct intensity ranges for different materials [S2].

## How it works
**Inputs and Outputs:**
- Input: A scalar value $x$ from the volume dataset, typically normalized to $[0, 1]$ via $x_{norm} = \frac{x - x_{min}}{x_{max} - x_{min}}$ [S3, unofficial][S4].
- Output: A 4-component vector $(R, G, B, \alpha)$ where components are in $[0, 1]$ (or HDR if supported) [S4][S5, unofficial].

**Data Structures:**
The transfer function is stored as a static array of 4-component vectors. Common layouts include:
1.  **Fixed-Size Array:** 256 entries mapping implicit scalar indices 0–255 to RGBA, where each entry is 4 floats (16 bytes) [S1, unofficial].
2.  **Configurable LUT:** 4096 entries, 36 bits per entry (8-bit RGB repeating-fraction + 12-bit alpha repeating-fraction) [S3, unofficial].
3.  **GPU Texture:** A 1D CUDA array (`cudaArray_t`) or texture object (`cudaTextureObject_t`) bound to device memory for hardware-accelerated linear interpolation [S5, unofficial].

**Steps:**
1.  **Normalization:** Normalize the input scalar $x$ to the domain $[0, 1]$ using the volume's min/max bounds [S3, unofficial][S4].
2.  **Boundary Handling:** Clamp the normalized coordinate to $[0, 1]$ to prevent out-of-bounds sampling [S3, unofficial][S4].
3.  **Lookup/Interpolation:**
    -   *Table Lookup:* Retrieve the RGBA value from the static array at the index corresponding to the normalized coordinate. Linear interpolation is often applied via hardware filters (e.g., `cudaFilterModeLinear`) to smooth transitions [S4][S2].
    -   *Direct Indexing:* Compute integer index $idx = \text{clamp}(\lfloor x_{norm} \cdot (N-1) \rfloor, 0, N-1)$ and return `table[idx]` for nearest-neighbor sampling [S5, unofficial].
    -   *Parametric Function:* Evaluate a closed-form function (e.g., exponential decay for opacity) if no table is used [S6, S8, unofficial].
4.  **Output:** Return the resulting $(R, G, B, \alpha)$ tuple [S4].

**Formulas:**
-   **Linear Interpolation (Hardware):** $\text{tex1D}(x_{norm})$ performs linear interpolation between adjacent LUT entries [S5, unofficial].
-   **Exponential Opacity (Parametric Variant):** $\alpha = \frac{e^{k_i \cdot x} - 1}{e^{k_i} - 1}$, where $k_i$ controls opacity decay [S6, S8, unofficial].
-   **Gradient Attenuation (Variant):** $\alpha_{final} = \alpha \cdot \left(1 - \frac{1}{1 + k_g \cdot |\nabla f|}\right)$, where $k_g$ is a gradient constant [S6, unofficial]. Note: This variant uses gradient, technically moving towards 2D TF, but is often implemented as a hardcoded parametric function in simple shaders [S6, unofficial].

**Parameters:**
-   $k_i$: Exponential decay constant for opacity (typical values not specified, depends on data range) [S6, S8, unofficial].
-   $k_g$: Gradient attenuation constant (typical values not specified) [S6, unofficial].
-   Color stops: Defined by the static array or function (e.g., Black to White) [S6, S8, unofficial].

**Edge Cases and Pitfalls:**
-   **Indistinguishable Features:** If multiple distinct features share the same scalar value, they will be rendered identically, leading to visual ambiguity [S2][S4].
-   **Precision:** Components stored as floats in $[0, 1]$. HDR palettes may exceed 1.0, requiring HDR framebuffer support or clamping to avoid overflow [S5, S6, unofficial].
-   **Opacity Values:** In some hardcoded implementations (e.g., [S1, unofficial]), opacity values are sparse (mostly 0.0 or 0.1), which may result in transparent rendering if not carefully tuned.
-   **Non-Unit Spacing:** Software correction may be required to adjust opacities for non-uniform sample spacing along the ray [S3, unofficial].

**Pseudocode:**
```python
def hardcoded_transfer_function(x: float, x_min: float, x_max: float, lut: list, count: int) -> tuple:
    """
    x: scalar input value
    x_min, x_max: volume data range
    lut: list of float4 (R, G, B, A) tuples, length 'count'
    count: number of entries in LUT
    """
    # 1. Normalize
    if x_max == x_min:
        x_norm = 0.0
    else:
        x_norm = (x - x_min) / (x_max - x_min)
    
    # 2. Clamp
    x_norm = max(0.0, min(1.0, x_norm))
    
    # 3. Lookup (Linear Interpolation)
    # Map normalized [0,1] to LUT indices [0, count-1]
    idx_float = x_norm * (count - 1)
    idx_low = int(idx_float)
    idx_high = min(idx_low + 1, count - 1)
    t = idx_float - idx_low
    
    # Get RGBA values
    rgba_low = lut[idx_low]
    rgba_high = lut[idx_high]
    
    # 4. Interpolate
    r = rgba_low[0] + t * (rgba_high[0] - rgba_low[0])
    g = rgba_low[1] + t * (rgba_high[1] - rgba_low[1])
    b = rgba_low[2] + t * (rgba_high[2] - rgba_low[2])
    a = rgba_low[3] + t * (rgba_high[3] - rgba_low[3])
    
    return (r, g, b, a)
```

## Subtopics

### [2D Transfer Function Volume Rendering](1295-2d-transfer-function-volume-rendering.md)
Extends the 1D LUT by mapping both scalar value $f$ and gradient magnitude $|\nabla f|$ to RGBA. It solves the ambiguity of overlapping scalar values by using gradient to distinguish boundaries from homogeneous regions. Choose this when material differentiation is critical and scalar values overlap. See [2D Transfer Function Volume Rendering](1295-2d-transfer-function-volume-rendering.md).

### [Tent Alpha Transfer Function](3031-tent-alpha-transfer-function.md)
A parametric hardcoded method for fluorescence microscopy that maps 8-bit scalars to RGBA using a tent-shaped alpha curve and gamma correction. It provides a parametric opacity profile centered on a peak value, avoiding manual LUT editing. Choose this for microscopy data with a specific peak intensity range. See [Tent Alpha Transfer Function](3031-tent-alpha-transfer-function.md).

### Fire Color Palette
A piecewise linear color mapping function for the [Hardcoded Transfer Function](1098-hardcoded-transfer-function.md) that maps $[0, 1]$ to a gradient: Gray $\to$ Dark Gray $\to$ Red $\to$ Orange $\to$ Yellow [S7, unofficial]. It is used for thermal or fire-like visualizations [S7, unofficial].

### Exponential Color Transfer Function
A parametric variant of the HTF that uses linear interpolation for color (Black to White) and an exponential function for opacity: $\alpha = \frac{e^{intensity} - 1}{e^1 - 1}$ [S8, unofficial]. It provides smooth opacity transitions without a large LUT [S8, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(1)$ per sample. Lookup or function evaluation is constant time [S2].
-   **Memory Complexity:** $O(N)$ for LUT storage, where $N$ is the number of entries (e.g., 256 or 4096) [S1, S3, unofficial]. Minimal compared to multi-dimensional TFs.
-   **Performance:** Lowest computation power and memory usage among TF types [S2]. Suitable for real-time rendering on low-end hardware [S2].
-   **Strengths:** High safety against misinterpretation (simple mapping), low user interaction, fast [S2].
-   **Limitations:** Cannot distinguish features with identical scalar values but different contexts (e.g., boundaries vs. interiors) [S2][S4].
-   **When to Use:** Scalar data with distinct, non-overlapping intensity ranges for different materials [S2][S4].
-   **When Not to Use:** Multi-channel data or data where boundaries/homogeneity are more important than intensity [S2][S4].

## Background
The 1D transfer function is the foundational method for volume classification, originating from early ray-casting systems like VolumePro [S3, unofficial]. It was formalized in surveys of volume rendering techniques as the "1D data-based TF" (1dTF) [S2]. It remains a baseline for comparison against more complex gradient-based or texture-based TFs [S2].
