# Hardcoded Transfer Function

Also called: Fixed RGBA Array, Static 1D Lookup Table, 1D Transfer Function, 1D data-based TF, 1D data-based transfer function, 1dTF

## Overview
The Hardcoded Transfer Function (HTF) is a volume rendering classification method that maps a single scalar data value directly to a color and opacity tuple $(R, G, B, \alpha)$ using a static, pre-defined 1D lookup table (LUT) [S2, S4]. It solves the problem of visualizing scalar field data by assigning appearance properties based solely on intensity, requiring minimal user interaction and computational resources [S2]. Unlike gradient-based or texture-based transfer functions, the HTF cannot differentiate between samples that share the same scalar value but differ in local structure or context, making it suitable for homogeneous data or as a baseline reference [S2, S4].

## How it works
**Inputs and Outputs**
*   **Input:** A scalar data value $v$ (e.g., voxel intensity) and a defined domain $[x_{min}, x_{max}]$.
*   **Output:** A 4-component vector $(R, G, B, \alpha)$ where components are in $[0, 1]$ [S4].

**Data Structures**
The transfer function is stored as a contiguous array of 4-component vectors.
*   **Format:** Typically `float4` (32-bit floats per component) or 8-bit integers (`uint8_t[4]`) [S1, unofficial][S2][S3, unofficial]. In hardware implementations like VolumePro, entries may be 36-bit (8-bit RGB, 12-bit alpha) [S3, unofficial].
*   **Size:** The number of entries $N$ is typically a power of two (e.g., 256, 4096) to support hardware texture sampling [S1, unofficial][S2][S3, unofficial].
*   **Layout:** A 1D array where index $i$ corresponds to the normalized value mapping to entry $i$ [S1, unofficial][S2].

**Normalization**
The input scalar $v$ is mapped to a normalized coordinate $x \in [0, 1]$ using the domain parameters:
$$ x = \frac{v - x_{min}}{x_{max} - x_{min}} $$
Values outside $[x_{min}, x_{max}]$ are clamped to $[0, 1]$ [S2][S3, unofficial].

**Sampling Methods**
Two primary methods retrieve RGBA values from the LUT:

1.  **Hardware Interpolation:** The LUT is uploaded as a texture with `LINEAR` filter mode and `CLAMP_TO_EDGE` wrap mode. The hardware interpolates between adjacent entries based on $x$ [S1, unofficial].
2.  **Direct Lookup:** The integer index is computed for nearest-neighbor sampling:
    $$ idx = \text{clamp}(\lfloor x \cdot (N-1) \rfloor, 0, N-1) $$
    The value at `table[idx]` is returned [S3, unofficial].

**Opacity Correction**
In some hardware pipelines, opacities require software correction to account for non-unit sample spacing $\Delta$ [S3, unofficial]. The opacity entry $\alpha_0$ is computed as:
$$ \alpha_0 = 1 - e^{-map[C_i] \Delta_0} $$
If the distance changes to $\Delta_k$, opacity values must be corrected accordingly [S1, unofficial].

**Pseudocode**
The following Python-like pseudocode demonstrates the CUDA-based implementation structure and sampling logic [S5, unofficial].

```python
import math

class HardcodedTransferFunction:
    def __init__(self, host_table, domain_min, domain_max):
        """
        Initialize the transfer function.
        :param host_table: List of float4 tuples [(R,G,B,A), ...]
        :param domain_min: float, x_min
        :param domain_max: float, x_max
        """
        self.count = len(host_table)
        self.domain = (domain_min, domain_max)
        
        # [G] In a real implementation, allocate device memory and copy data.
        # 1. Allocate device memory for m_device_table of size count * sizeof(float4).
        # 2. Copy host_table to m_device_table via cudaMemcpyHostToDevice.
        # 3. Create channel format descriptor ch for float4.
        # 4. Allocate 1D CUDA array m_array with width count, height 1.
        # 5. Copy host_table to m_array using cudaMemcpy2DToArray.
        # 6. Create texture object m_tex from m_array with linear filtering and clamp address mode.
        self.device_table = host_table # Placeholder for device pointer
        self.texture_object = None     # Placeholder for texture object

    def sample(self, x):
        """
        Sample the transfer function using hardware interpolation.
        :param x: float, scalar value
        :return: tuple (R, G, B, A)
        """
        # 1. Normalize x
        x_min, x_max = self.domain
        if x_max == x_min:
            normalized_x = 0.0
        else:
            normalized_x = (x - x_min) / (x_max - x_min)
        
        # 2. Clamp to [0, 1]
        normalized_x = max(0.0, min(1.0, normalized_x))
        
        # [G] tex1D<float4>(m_tex, normalized_x) performs linear interpolation
        # and clamping based on texture settings defined in constructor.
        # Return the interpolated float4.
        return self._hardware_sample(normalized_x)

    def lookup(self, x):
        """
        Sample the transfer function using direct nearest-neighbor lookup.
        :param x: float, scalar value
        :return: tuple (R, G, B, A)
        """
        # 1. Normalize x
        x_min, x_max = self.domain
        if x_max == x_min:
            normalized_x = 0.0
        else:
            normalized_x = (x - x_min) / (x_max - x_min)
        
        # 2. Clamp to [0, 1]
        normalized_x = max(0.0, min(1.0, normalized_x))
        
        # 3. Compute integer index
        idx = int(math.floor(normalized_x * (self.count - 1)))
        idx = max(0, min(idx, self.count - 1))
        
        # 4. Return value from device table
        return self.device_table[idx]

    def _hardware_sample(self, normalized_x):
        """
        Simulates hardware texture sampling.
        """
        # [G] This function represents the result of tex1D<float4>(m_tex, normalized_x).
        # It performs linear interpolation between adjacent entries in the LUT.
        idx_float = normalized_x * (self.count - 1)
        idx_low = int(math.floor(idx_float))
        idx_high = min(idx_low + 1, self.count - 1)
        t = idx_float - idx_low
        
        r = self.device_table[idx_low][0] * (1 - t) + self.device_table[idx_high][0] * t
        g = self.device_table[idx_low][1] * (1 - t) + self.device_table[idx_high][1] * t
        b = self.device_table[idx_low][2] * (1 - t) + self.device_table[idx_high][2] * t
        a = self.device_table[idx_low][3] * (1 - t) + self.device_table[idx_high][3] * t
        
        return (r, g, b, a)

    def cleanup(self):
        """
        Destructor cleanup.
        """
        # [G] cudaDestroyTextureObject, cudaFreeArray, cudaFree
        pass
```

## Subtopics

### [2D Transfer Function Volume Rendering](1295-2d-transfer-function-volume-rendering.md)
2D Transfer Function Volume Rendering extends the 1D Lookup Table with Interpolation method by mapping both the scalar data value $f$ and the local gradient magnitude $|\nabla f|$ to color and opacity. It solves the problem of overlapping data-value intervals in 1D transfer functions, where different materials or boundaries share similar scalar values but differ in their local structure. By using gradient magnitude as a second dimension, it uniquely isolates material boundaries and homogeneous regions, providing superior tissue differentiation and boundary visualization compared to the Hardcoded Transfer Function.

### [Tent Alpha Transfer Function](3031-tent-alpha-transfer-function.md)
The Tent Alpha Transfer Function is a hardcoded 1D RGBA transfer texture generation method for fluorescence microscopy data that maps 8-bit scalar values to color and opacity using a tent-shaped alpha curve and gamma corrections. It provides a parametric opacity profile centered on a user-defined peak value. It builds on the Hardcoded Transfer Function by defining the color and opacity as a static float array generated from a closed-form mathematical profile rather than a manually edited lookup table.

### Fire Color Palette
A piecewise linear color mapping function that maps a value in $[0,1]$ to a gradient from gray to dark gray to red to orange to yellow [S7, unofficial].
*   **Steps:** Clamp input $d$ to $[0.0, 1.0]$. If $x < 0.25$, interpolate between `gray` and `darkgray` using $x \cdot 4.0$. If $0.25 \le x < 0.5$, interpolate between `darkgray` and `red` using $x \cdot 4.0 - 1.0$. If $0.5 \le x < 0.75$, interpolate between `red` and `orange` using $x \cdot 4.0 - 2.0$. If $x \ge 0.75$, interpolate between `orange` and `yellow` using $x \cdot 4.0 - 3.0$ [S7, unofficial].
*   **Parameters:** `gray`: (0.4, 0.4, 0.4); `darkgray`: (0.2, 0.2, 0.2); `red`: (1.0, 0.0, 0.0); `orange`: (1.0, 0.6, 0.0); `yellow`: (1.7, 1.3, 1.0) [S7, unofficial]. Note: components can exceed 1.0.

### Exponential Color Transfer Function
Maps volume intensity to color and alpha using an exponential function for alpha and linear interpolation for color [S8, unofficial].
*   **Steps:** Define high color as white `vec3(1.0, 1.0, 1.0)` and low color as black `vec3(0.0, 0.0, 0.0)`. Compute color as linear interpolation between low and high weighted by intensity: `vec4(intensity * high + (1.0 - intensity) * low, alpha)` [S8, unofficial].
*   **Formula:** Alpha is computed as $\alpha = \frac{e^{intensity} - 1}{e^1 - 1}$ [S8, unofficial].

## Operating characteristics
*   **Time and Memory Complexity:** Lowest among compared transfer functions in terms of computation power and memory usage [S2]. The LUT size is fixed and small (e.g., 256–4096 entries) [S1, S3, unofficial].
*   **Measured Performance:** Hardware implementations (e.g., VolumePro) perform classification at the rate of one sample per clock cycle using a 4096-entry LUT [S3, unofficial].
*   **Strengths:** Requires little user interaction, provides high safety against errors leading to misinterpretation, and is computationally efficient [S2].
*   **Limitations:** Cannot distinguish features with identical scalar values (grey levels) regardless of their visual context or boundaries [S2, S4]. It fails to capture correlations in multi-channel data or distinguish features with similar intensities but different contexts [S4].
*   **When to use:** Suitable for homogeneous data, quick visualization, or as a baseline reference [S2].
*   **When not to use:** When differentiating between materials with similar intensities but different structures (e.g., tissue boundaries) is required [S2, S4].

## Background
The 1D transfer function is a foundational technique in volume rendering, mapping intensity values directly to color and opacity [S4]. It serves as a reference point for more complex transfer functions like gradient-based or texture-based TFs [S2]. The method is widely used in scientific visualization for its simplicity and efficiency [S2]. Hardware implementations, such as the VolumePro system, have historically utilized pre-computed 1D LUTs for real-time ray-casting [S3, unofficial].
