# Hardcoded Transfer Function

Also called: Fixed RGBA Array, Static 1D Lookup Table, 1D Transfer Function, 1D data-based TF, 1dTF, 1D data-based transfer function

## Overview
The Hardcoded Transfer Function is a classification method that maps a single scalar data value directly to a color and opacity tuple using a static, pre-defined lookup table [S2, S4]. It solves the problem of visualizing volume data by assigning RGBA properties based solely on intensity, without considering local geometric context or multi-channel correlations [S2, S4]. It is distinguished from its siblings by its minimal computational footprint and lack of user interaction, but it cannot differentiate between samples with identical scalar values that may represent distinct physical features [S2, S4].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar volume dataset with values in range $[x_{min}, x_{max}]$.
*   **Output:** A 4-component vector $(R, G, B, \alpha)$ for each sample point, where components are typically in $[0, 1]$.

**Data Structures:**
The transfer function is stored as a contiguous array of 4-component vectors.
*   **Format:** `float4` (R, G, B, A), where each component is a 32-bit float [S5, unofficial].
*   **Size:** Commonly 256 entries for 8-bit data [S1, unofficial] or 4096 entries for higher precision [S3, unofficial].
*   **GPU Storage:** Uploaded to GPU memory as a 1D CUDA array bound to a texture object (for hardware interpolation) and/or a raw device pointer (for direct lookup) [S5, unofficial].

**Parameters:**
*   `tf_size` ($N$): Number of entries in the lookup table [S2].
*   `tf_window_left` ($x_{min}$): Minimum scalar value of the domain [S2].
*   `tf_window_width` ($W$): Range of the domain ($x_{max} - x_{min}$) [S2].

**Steps:**
1.  **Normalization:** Map the input scalar $v$ to a normalized coordinate $x \in [0, 1]$:
    $$ x = \frac{v - x_{min}}{x_{max} - x_{min}} $$
    [S2][S3, unofficial][S4][S5, S6, S8, unofficial]
2.  **Lookup:** Retrieve the RGBA value from the table.
    *   *Hardware Interpolation:* Use a texture sampler with linear filtering and clamp addressing. The sampler automatically computes the index and interpolates between adjacent entries [S5, unofficial].
    *   *Direct Lookup:* Compute the integer index and perform nearest-neighbor access:
        $$ idx = \text{clamp}(\lfloor x \cdot (N-1) \rfloor, 0, N-1) $$
        [S3, S5, S8, unofficial]
3.  **Output:** Return the fetched $(R, G, B, \alpha)$ tuple.

**Pseudocode:**
```python
# Host-side initialization (CUDA example)
def init_hardcoded_tf(host_table: List[float4], x_min: float, x_max: float):
    """
    Allocates GPU memory and uploads the hardcoded transfer function.
    host_table: List of float4 tuples (R, G, B, A) in [0, 1].
    """
    N = len(host_table)
    
    # 1. Allocate raw device memory for direct lookup
    m_device_table = cuda_malloc(N * sizeof(float4))
    cuda_memcpy(m_device_table, host_table, N * sizeof(float4), cudaMemcpyHostToDevice)
    
    # 2. Allocate 1D CUDA array for texture binding
    channel_desc = make_cuda_channel_format_type(cuda_channel_format_kind_float, 32, 0, 0, 0)
    m_array = cuda_malloc_1d_array(N, 1, channel_desc)
    cuda_memcpy_2d_to_array(m_array, 0, 0, host_table, N * sizeof(float4), N * sizeof(float4), 1)
    
    # 3. Create texture object for hardware interpolation
    tex_desc = cuda_texture_descriptor()
    tex_desc.filter_mode = cudaFilterModeLinear
    tex_desc.address_mode[0] = cudaAddressModeClamp
    tex_desc.normalized_coords = 1
    
    res = cuda_resource_descriptor()
    res.res_type = cudaResourceTypeArray
    res.res.array = m_array
    
    m_tex = cuda_create_texture_object(res, tex_desc)
    
    return {
        'm_device_table': m_device_table,
        'm_array': m_array,
        'm_tex': m_tex,
        'm_count': N,
        'm_domain': (x_min, x_max)
    }

# Device-side sampling
def sample_hardcoded_tf(x: float, tf_data: dict) -> float4:
    """
    Samples the transfer function for a scalar value x.
    """
    x_min, x_max = tf_data['m_domain']
    N = tf_data['m_count']
    
    # Normalize input
    normalized_x = (x - x_min) / (x_max - x_min)
    
    # Option A: Hardware Interpolation (Linear)
    # tex1D performs clamping and linear interpolation automatically
    rgba = tex1D<float4>(tf_data['m_tex'], normalized_x)
    
    # Option B: Direct Lookup (Nearest Neighbor)
    # idx = min(max(0, (int)(normalized_x * (N - 1))), N - 1)
    # rgba = tf_data['m_device_table'][idx]
    
    return rgba
```

**Edge Cases and Pitfalls:**
*   **Precision:** Opacity values in hardcoded tables are often sparse (e.g., mostly 0.0 or 0.1), which can lead to aliasing or banding if not handled with appropriate interpolation [S1, unofficial].
*   **Ambiguity:** The method cannot distinguish between different materials or structures that share the same scalar intensity (e.g., bone and dense tissue in CT) [S2, S4].
*   **Boundary Conditions:** Input values outside $[x_{min}, x_{max}]$ must be clamped to prevent out-of-bounds memory access [S5, unofficial].

## Subtopics

### Fire Color Palette
A piecewise linear color mapping variant that maps a value in $[0, 1]$ to a gradient from gray to dark gray to red to orange to yellow [S7, unofficial]. It is chosen for visual effects or thermal visualization where a specific aesthetic gradient is required [S7, unofficial].
*   **Clamp** input $d$ to $[0.0, 1.0]$.
*   If $x < 0.25$, interpolate between `gray` (0.4, 0.4, 0.4) and `darkgray` (0.2, 0.2, 0.2) using $t = x \cdot 4.0$.
*   If $0.25 \le x < 0.5$, interpolate between `darkgray` and `red` (1.0, 0.0, 0.0) using $t = x \cdot 4.0 - 1.0$.
*   If $0.5 \le x < 0.75$, interpolate between `red` and `orange` (1.0, 0.6, 0.0) using $t = x \cdot 4.0 - 2.0$.
*   If $x \ge 0.75$, interpolate between `orange` and `yellow` (1.7, 1.3, 1.0) using $t = x \cdot 4.0 - 3.0$. Note that yellow components may exceed 1.0 [S7, unofficial].

### Exponential Color Transfer Function
A variant that uses an exponential function for opacity and linear interpolation for color [S8, unofficial]. It is chosen when a smooth, non-linear fade-in of opacity is desired relative to intensity [S8, unofficial].
*   Define `high` = (1.0, 1.0, 1.0) and `low` = (0.0, 0.0, 0.0).
*   Compute color: `vec3 color = intensity * high + (1.0 - intensity) * low`.
*   Compute alpha: $\alpha = \frac{e^{intensity} - 1}{e^1 - 1}$ [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The lookup is a single memory access or texture fetch [S2][S5, unofficial].
*   **Memory Complexity:** $O(N)$, where $N$ is the table size (e.g., 256 or 4096 entries). This is the lowest among transfer function types [S2].
*   **Performance:** Extremely fast, suitable for real-time rendering on low-end hardware [S2][S3, unofficial].
*   **Strengths:** Minimal user interaction, high safety against misinterpretation errors, and lowest computational cost [S2].
*   **Limitations:** Cannot resolve ambiguities where different features share the same scalar value (e.g., different tissues with similar Hounsfield units) [S2, S4]. It fails to capture multi-channel correlations [S4].

## Background
The 1D data-based transfer function (1dTF) is the foundational classification method in volume rendering, serving as a reference point for more complex techniques like 2D gradient-based or texture-based TFs [S2]. It was formalized in early volume rendering literature and is implemented in systems like VolumePro, which used pre-computed 4096-entry LUTs for real-time ray-casting [S3, unofficial]. It remains the standard for simple scalar visualization where geometric context is not required [S2].
