# Preintegration LUT Generation

Also called: 2D Preintegration LUT, Pre-integration of transfer functions, Preintegration Table Generation, pre-integrated TF

## Overview
Preintegration LUT Generation is a technique to improve the quality of post-interpolative classification by pre-computing the integral of the transfer function over all possible pairs of scalar values ($S_f, S_b$) across a slab [S3, unofficial]. It reduces the number of samples needed during rendering by storing the accumulated color and opacity for a given path length, thereby mitigating artifacts caused by small transfer function windows and high-frequency scalar fields [S1, S3, unofficial]. It differs from standard ray casting by moving the integration of the volume rendering equation from runtime sampling to a pre-computed 2D lookup table indexed by boundary scalar values [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Transfer functions (color and opacity curves), scalar field resolution (implicit via LUT size), step length (slab thickness), and integration mode (particle or medium).
*   **Outputs:** A 2D Lookup Table (LUT) of size $size \times size$, where each entry stores a pre-integrated color (vec3) and opacity (float).

**Data Structures:**
*   **1D Transfer Function Tables:**
    *   `tf_colors`: Array of `size` entries, each a `vec4` (RGBA).
    *   `tf_opacities`: Array of `size` entries, each a `float`.
*   **2D Preintegration LUT:**
    *   `data`: Array of `size * size` entries.
    *   Layout: Row-major, indexed by `y * size + x`.
    *   Entry: `vec4` containing `{final_color.r, final_color.g, final_color.b, final_alpha}`.

**Parameters:**
*   `size`: Integer dimension of the 2D LUT. The LUT stores `size * size` entries. Typical values are $512^2$ for high accuracy [S7, unofficial], or smaller for performance [S1, unofficial].
*   `step_length`: Float representing the total path length integrated over in the LUT generation (slab thickness) [S1, unofficial].
*   `is_medium_table`: Boolean flag. If `true`, uses medium rendering mode (Beer-Lambert approximation with average color). If `false`, uses particle rendering mode (standard front-to-back accumulation) [S1, unofficial].
*   `d`: Sampling distance used during pre-integration. In the discrete implementation, this is derived from `step_length` and the number of integration steps [S3, unofficial].

**Algorithm Steps:**

1.  **Initialize 1D Lookup Tables:**
    Create `tf_colors` and `tf_opacities` with `size` entries. Populate them by sampling the user-defined transfer function curves.

2.  **Generate 2D LUT:**
    Iterate over all pairs of scalar values $S_f$ (front) and $S_b$ (back). The LUT is indexed such that $y$ corresponds to $S_f$ and $x$ corresponds to $S_b$.
    *   Normalize scalar values to $[0, 1]$:
        $$s_{front} = \frac{y}{size - 1}$$
        $$s_{back} = \frac{x}{size - 1}$$
    *   Initialize accumulators: `accum_color` (vec3, 0.0), `accum_alpha` (float, 0.0), `accum_density` (float, 0.0).
    *   Perform numerical integration along the path between $s_{front}$ and $s_{back}$.

3.  **Numerical Integration (Inner Loop):**
    Use a fixed number of steps (e.g., 32) to approximate the integral [S1, unofficial].
    *   Calculate step size: $ds = \frac{step\_length}{steps}$.
    *   For $k$ from $0$ to $steps - 1$:
        *   Compute interpolation weight: $w = \frac{k + 0.5}{steps}$.
        *   Interpolate scalar value: $d = s_{front}(1 - w) + s_{back}w$.
        *   Map to 1D table index: $idx = \lfloor d \cdot (size - 1) \rfloor$.
        *   Retrieve pre-sampled values: $color = tf\_colors[idx]$, $opacity = tf\_opacities[idx]$.
        *   Accumulate based on mode:
            *   **Particle Mode** (standard accumulation):
                *   Calculate sample alpha using Beer-Lambert law:
                    $$\alpha_{sample} = 1 - e^{-\text{opacity} \cdot 100.0 \cdot ds}$$
                *   Update color and alpha:
                    $$transmittance = 1.0 - accum\_alpha$$
                    $$accum\_color += color \cdot transmittance \cdot \alpha_{sample}$$
                    $$accum\_alpha += (1.0 - accum\_alpha) \cdot \alpha_{sample}$$
            *   **Medium Mode** (Beer-Lambert with average color):
                *   Accumulate density and color contribution:
                    $$accum\_color += color \cdot opacity$$
                    $$accum\_density += opacity$$

4.  **Finalize LUT Entry:**
    *   **Particle Mode:**
        *   Store: `data[y * size + x] = {accum_color.r, accum_color.g, accum_color.b, accum_alpha}`.
    *   **Medium Mode:**
        *   Calculate final average color:
            $$final\_color = \begin{cases} \frac{accum\_color}{accum\_density} & \text{if } accum\_density > 0.0001 \\ (1.0, 1.0, 1.0) & \text{otherwise} \end{cases}$$
        *   Calculate final alpha:
            $$total\_extinction = accum\_density \cdot ds \cdot 100.0$$
            $$final\_alpha = 1.0 - e^{-total\_extinction}$$
        *   Store: `data[y * size + x] = {final_color.r, final_color.g, final_color.b, final_alpha}`.

**Pseudocode:**

```python
def generate_preintegration_lut(tf_colors_curve, tf_opacities_curve, size, step_length, is_medium_table):
    # Step 1: Initialize 1D LUTs
    tf_colors = [vec4(0.0) for _ in range(size)]
    tf_opacities = [0.0 for _ in range(size)]
    
    for i in range(size):
        t = i / float(size - 1)
        if is_medium_table:
            tf_colors[i] = sample_curve(t, tf_colors_curve.medium_colors)
        else:
            tf_colors[i] = sample_curve(t, tf_colors_curve.particle_colors)
        tf_opacities[i] = sample_curve(t, tf_opacities_curve.opacities)

    # Step 2: Generate 2D LUT
    lut_data = [vec4(0.0) for _ in range(size * size)]
    steps = 32
    ds = step_length / steps

    for y in range(size):
        for x in range(size):
            s_front = y / float(size - 1)
            s_back = x / float(size - 1)
            
            accum_color = vec3(0.0)
            accum_alpha = 0.0
            accum_density = 0.0

            # Step 3: Inner integration loop
            for k in range(steps):
                w = (k + 0.5) / steps
                d = s_front * (1.0 - w) + s_back * w
                idx = int(d * (size - 1))
                
                color = tf_colors[idx]
                opacity = tf_opacities[idx]

                if is_medium_table:
                    accum_color += color * opacity
                    accum_density += opacity
                else:
                    extinction = opacity * 100.0
                    sample_alpha = 1.0 - math.exp(-extinction * ds)
                    transmittance = 1.0 - accum_alpha
                    accum_color += color * transmittance * sample_alpha
                    accum_alpha += (1.0 - accum_alpha) * sample_alpha

            # Step 4: Finalize
            if is_medium_table:
                if accum_density > 0.0001:
                    final_color = accum_color / accum_density
                else:
                    final_color = vec3(1.0)
                total_extinction = accum_density * ds * 100.0
                final_alpha = 1.0 - math.exp(-total_extinction)
                lut_data[y * size + x] = vec4(final_color.r, final_color.g, final_color.b, final_alpha)
            else:
                lut_data[y * size + x] = vec4(accum_color.r, accum_color.g, accum_color.b, accum_alpha)

    return lut_data
```

## Subtopics

### LUT Cache Hashing Fix for In-Place Edits
A fix for stale transmittance and multiscattering LUT caches after in-place medium edits. Previously, the cache hashed the medium's handle, which remains constant during in-place asset edits, causing LUTs to go stale until a periodic rebuild (e.g., every 240 frames) [S4, unofficial]. This caused visual artifacts like washed-out skies because sky-view and aerial LUTs read the new medium while the cached LUTs did not [S4, unofficial]. The fix hashes the prepared GPU medium's textures instead of the handle, ensuring the cache is invalidated when textures are replaced [S4, unofficial]. Parameters such as `ATMOSPHERE_SECOND_SUN`, `ATMOSPHERE_SUN_AZ_DEG`, `ATMOSPHERE_SUN_SCALE`, `ATMOSPHERE_AEROSOL`, and `ATMOSPHERE_AEROSOL_EDIT_SECS` define the atmospheric state being cached [S4, unofficial].

### 1D Pre-integration Table Approximation
An approximation technique to reduce the dimensionality of the pre-integration lookup table from two dimensions to one, reducing texture memory size and update time [S5]. It modifies the geometric average of transparency into an arithmetic average [S5]. The method relies on the quantization of scalar values $s$ and rewrites the transparency integral as an arithmetic mean of exponential terms, allowing the storage of only a 1D texture $S(x)$ to retrieve pre-integrated values [S5]. This reduces memory requirements significantly (e.g., from $4096^2$ entries to 4096 entries) at the cost of some accuracy [S5].

### Arithmetic Mean Opacity Approximation
An optimization to improve lookup table generation speed by using the arithmetic mean instead of the geometric mean in the integral computation [S6]. This simplifies the calculation of opacity attenuation, trading off some physical accuracy for faster pre-computation [S6].

### Adaptive Preintegration Table Generation
A scheme that computes preintegration tables for opacity, shading, and material properties using an incremental subrange algorithm [S7, unofficial]. It only computes tables for specific lengths $l_{max}, l_{max}/2, ..., l_{min}$, bounding the interval length with parameters $l_{max}$ and $l_{min}$ [S7, unofficial]. To control accuracy, it supersedamples intervals if necessary to limit the maximal step size of numerical integration [S7, unofficial]. If an interval is clipped against bounding geometry, the integral for a non-table length is computed by combining values from different tables [S7, unofficial]. Direct computation with controlled step size is preferred over incremental computation from $l_k/2$ to avoid error accumulation [S7, unofficial]. Typical table resolution is $512^2$, requiring approximately 72MB of memory and up to 10 seconds of CPU time for generation [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** Pre-computation is $O(size^2 \cdot steps)$, where $steps$ is the number of integration steps per slab. Generation can take up to 10 seconds on CPU for high-resolution tables ($512^2$) [S7, unofficial].
*   **Memory Complexity:** $O(size^2)$ for the 2D LUT. For $size=512$, this requires approximately 72MB [S7, unofficial]. 1D approximations reduce this to $O(size)$ [S5].
*   **Performance:** Pre-integration allows rendering with significantly fewer samples. For example, 128 slabs with pre-integration achieve quality comparable to 284 slices without it [S3, unofficial].
*   **Strengths:** Eliminates artifacts from small transfer function windows and high-frequency scalar fields when using post-interpolative classification [S3, unofficial]. Accelerates rendering by replacing runtime integration with texture lookups [S2, unofficial].
*   **Limitations:** Artifacts may still occur from high frequencies and non-linear effects of tri-linear interpolation and shading, requiring over-sampling (decreased sample distance) [S2, unofficial]. The discrete approximation converges to correct results only for high volume sampling rates [S2, unofficial]. Non-linear transfer functions require very high sampling rates to avoid errors [S2, unofficial].
*   **When to use:** When using post-interpolative classification and constant sampling distances (e.g., orthographic projections) [S2, unofficial].
*   **When not to use:** When variable sampling distances are required (e.g., perspective projections with spherical shells) without modification, or when memory bandwidth is severely constrained and 1D approximations are insufficient [S2, unofficial].

## Background
Pre-integration was introduced by Roettger and Ertl [S2, unofficial]. It addresses the problem that the discrete approximation of the volume rendering integral converges to correct results only for high sampling rates [S2, unofficial]. The technique pre-computes the integral of the opacity and color transfer functions for all possible pairs of scalar values at the boundaries of a slab [S2, unofficial]. It is often applied in conjunction with shading models, such as the Phong model, to pre-integrate ambient, diffuse, and specular lighting parameters [S2, unofficial].
