# Piecewise Linear Interpolation (Lookup Table)

Also called: Linear Spline, Piecewise Linear Transfer Function, Linear Interpolation between Control Points, Piecewise Linear Transfer Function Evaluation, 1D Transfer Function Control Point Interpolation

## Overview
Piecewise Linear Interpolation (Lookup Table) is the most disseminated approach for implementing specified Transfer Functions (TFs) in volume rendering, mapping scalar data values to visual properties (color and opacity) via a discretized indexed table [S1, S4, unofficial]. It solves the problem of efficiently evaluating continuous visual parameter curves defined by user-specified control points during ray casting [S2, S8, unofficial]. Unlike [Cubic Spline Transfer Function](1811-cubic-spline-transfer-function.md), which ensures $C^1$ continuity, this method provides only $C^0$ continuity, resulting in simpler computation but potential visual discontinuities in derivatives at control points [S9]. It differs from [Linear Look-up Table Classification](2636-linear-look-up-table-classification.md) by explicitly defining the interpolation logic between arbitrary control points rather than relying solely on pre-binned discrete bins [S2, S8, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ control points $P = \{p_0, p_1, \dots, p_{N-1}\}$, where each point $p_i$ has a scalar position $pos_i$ and a visual value $val_i$ (e.g., color vector $\mathbf{c}_i$ and opacity $\alpha_i$). The positions must be sorted in ascending order [S2, S6, S8, unofficial].
*   **Input:** A query scalar value $t$ (or $P$ in formulas) from the volume data [S2, S8, unofficial].
*   **Output:** The interpolated visual value $v$ (or $\mathbf{c}, \alpha$) at $t$ [S2, S8, unofficial].

**Data Structures:**
The control points are typically stored in two parallel arrays or a struct array:
1.  `positions`: Array of floats $[pos_0, pos_1, \dots, pos_{N-1}]$, sorted ascending [S8, unofficial].
2.  `values`: Array of visual parameters. For color, this is often 4 arrays (R, G, B, A) or a struct array of vectors [S2, S7, S8, unofficial].

**Algorithm Steps:**
1.  **Boundary Clamping:** If the input set is empty, return default values (e.g., 0.0 for scalar, $\{0,0,0,0\}$ for color) [S2, unofficial]. If $t \le pos_0$, return $val_0$ [S2, S8, unofficial]. If $t \ge pos_{N-1}$, return $val_{N-1}$ [S2, S8, unofficial].
2.  **Interval Search:** Find the index $i$ such that $pos_i \le t < pos_{i+1}$ [S2, S8, unofficial]. This is typically done using binary search (e.g., `std::lower_bound` or custom `nearestn`) [S8, unofficial]. Note: Some implementations use nearest-neighbor lookup which may skip the exact interval if $t$ equals a control point exactly, risking index errors if not handled [S8, unofficial][S9].
3.  **Weight Calculation:** Compute the interpolation weight $w$ (or $\alpha$) within the segment [S2, S8, unofficial]:
    $$ w = \frac{t - pos_i}{pos_{i+1} - pos_i} $$
    Alternatively, using the formula from [S7, unofficial]:
    $$ w = \frac{t - pl}{pr - pl} $$
    where $pl = pos_i$ and $pr = pos_{i+1}$ [S7, unofficial].
4.  **Interpolation:** Compute the result $v$ by linearly interpolating between $val_i$ and $val_{i+1}$ [S2, S8, unofficial]:
    $$ v = (1 - w) \cdot val_i + w \cdot val_{i+1} $$
    For color, this is applied independently to each channel (R, G, B) and opacity (A) [S2, S7, S8, unofficial].

**Pseudocode:**
```python
def piecewise_linear_interpolate(positions, values, t):
    """
    Interpolate visual value at scalar t given sorted control points.
    positions: List[float], sorted ascending.
    values: List[float] or List[Vector4], corresponding to positions.
    t: float, query scalar value.
    Returns: float or Vector4.
    """
    n = len(positions)
    if n == 0:
        return 0.0 # Default for empty
    
    # Boundary clamping
    if t <= positions[0]:
        return values[0]
    if t >= positions[n - 1]:
        return values[n - 1]
    
    # Binary search for interval index i such that positions[i] <= t < positions[i+1]
    # Using a standard lower_bound logic
    left = 0
    right = n - 1
    i = 0
    while left <= right:
        mid = (left + right) // 2
        if positions[mid] <= t:
            i = mid
            left = mid + 1
        else:
            right = mid - 1
            
    # Ensure we are in the correct segment [i, i+1]
    # If t is exactly at a point, i might be that point. 
    # We need the segment starting at i.
    # If t >= positions[i+1], we should have moved i further, 
    # but the binary search above finds the largest index <= t.
    # So positions[i] <= t. We must check if t < positions[i+1].
    # If t >= positions[i+1], the search should have returned i+1 or higher.
    # Standard lower_bound returns first element >= t. 
    # Let's use the logic from [S8, unofficial] nearestn which finds largest index with value < t?
    # [S8, unofficial] nearestn returns result_index where array[mid] < value. 
    # So if array[mid] < t, it goes right. 
    # Let's stick to the formula definition [S2, S8, unofficial].
    
    # Re-implementing interval search to match [S2, unofficial] and [S8, unofficial] intent:
    # Find i such that positions[i] <= t <= positions[i+1]
    # If t equals a control point exactly, any adjacent segment works, 
    # but typically we pick the one where t is the left bound or right bound.
    
    # Using the logic from [S2, unofficial]:
    # Find i such that points[i].pos <= t <= points[i+1].pos
    
    # Robust search:
    idx = 0
    for k in range(n - 1):
        if positions[k] <= t <= positions[k+1]:
            idx = k
            break
    else:
        # Fallback if loop finishes without break (should be covered by clamping)
        idx = n - 2
        
    pos_left = positions[idx]
    pos_right = positions[idx + 1]
    val_left = values[idx]
    val_right = values[idx + 1]
    
    # Handle division by zero if duplicate positions exist
    if pos_right == pos_left:
        return val_left
        
    # Calculate weight
    w = (t - pos_left) / (pos_right - pos_left)
    
    # Interpolate
    # Assuming values are floats or vectors supporting linear interpolation
    result = val_left * (1.0 - w) + val_right * w
    
    return result
```

**Parameters:**
*   **STEP:** In some precomputed LUT implementations, a constant resolution step (e.g., 0.1f) is used to index into a precomputed spline array [S5, unofficial]. However, direct control point interpolation does not require a fixed STEP [S2, S8, unofficial].

**Edge Cases and Pitfalls:**
*   **Duplicate Positions:** If $pos_i = pos_{i+1}$, division by zero occurs in weight calculation. Sources do not explicitly define the guard, but implementation requires checking for zero denominator [G].
*   **Unsorted Input:** The algorithm assumes sorted positions. Unsorted input leads to incorrect interval selection [S6, unofficial].
*   **Out-of-Bounds:** Binary search may return -1 or invalid indices if $t$ is outside the range and clamping is not applied [S8, unofficial].
*   **Ringing Artifacts:** Linear interpolation lacks derivative continuity, which can lead to ringing artifacts and larger errors on non-linear implicit functions compared to higher-order methods [S9].

## Subtopics

### [Transfer Function Control Point Management](2718-transfer-function-control-point-management.md)
Handles insertion, deletion, modification, and sorting of control points. It ensures topological correctness (no crossing points) and maintains a valid, sorted domain during interactive manipulation, operating on parametric control points rather than the discrete LUT.

### [Blurring a Step Function](4383-blurring-a-step-function.md)
Convolution of a step function with a rectangular pulse to yield a piecewise linear spline. It operates directly on input arrays $x$ and $y$ representing the domain and range values of the step function.

### [Step Function Resampling](7924-step-function-resampling.md)
Constructs inner and outer measures on a step function to resample values defined by endpoints into new intervals. It provides exact bounds (sum and contained mass) rather than smoothed approximations, preserving discontinuous nature unlike piecewise linear interpolation.

### [Piecewise Linear Interpolation](16011-piecewise-linear-interpolation.md)
A general technique to evaluate a continuous curve defined by an AnimationCurve at arbitrary points using precomputed discrete values and linear interpolation.

### Piecewise Hermite Transfer Function
A variant allowing independent control of color and opacity mappings with fewer control points. It uses a sharpness coefficient (0.0 to 1.0) to interpolate between linear mapping and piecewise constant solutions, and supports interactive adjustment of the segment midpoint [S10].

### Similarity-Based Isovalue Remapping
A nonlinear mapping function $MSV(x)$ that maps UI input to isovalues based on isosurface similarity, ensuring uniform visual progression. It is piecewise constant but can be interpolated for continuous values [S11].

## Operating characteristics
**Time Complexity:** $O(\log N)$ for binary search interval lookup, $O(1)$ for interpolation [S8, unofficial]. Linear scan is $O(N)$ [S2, unofficial].
**Memory Complexity:** $O(N)$ to store control points [S1, unofficial].
**Performance:** Fast and simple to implement. Suitable for interactive applications where control point updates are frequent [S10].
**Strengths:** Simple, computationally inexpensive, easy to understand and modify [S2, S8, unofficial].
**Limitations:** Discontinuous derivatives at control points can cause visual artifacts (ringing) on complex data [S9]. Not suitable for applications requiring smooth gradients in the transfer function itself without post-processing [S9].

## Background
Originated as the standard method for implementing Transfer Functions in volume rendering, popularized by early works in the field [S1, unofficial]. The approach is mathematically defined as an indexed table of discretizations of visual properties and scalar data values [S1, unofficial]. It is widely used in tools like ParaView and various custom volume renderers [S10][S7, unofficial].
