# Transfer Function Control Point Management

Also called: Automatic TF Control Point Handling, TF Control Point Management, TF Point Reordering, Transfer Function Control Point Sorting

## Overview
This method manages the lifecycle of control points in a piecewise linear transfer function (TF), ensuring data integrity during user interaction (dragging, deleting, adding) and maintaining the sorted order required for linear interpolation. It distinguishes itself from [Blurring a Step Function](4383-blurring-a-step-function.md) and [Step Function Resampling](7924-step-function-resampling.md) by operating on the parametric definition of the TF (control points) rather than the sampled LUT values, preserving exact geometric constraints before reconstruction.

## How it works
**Inputs and Outputs:**
- Input: A list of existing control points, user interaction events (add, delete, move), and the scalar domain range $[s_{min}, s_{max}]$.
- Output: A sorted list of control points and an updated Lookup Table (LUT).

**Data Structures:**
The implementation uses two parallel arrays for the active TF state:
1. `pointList`: Array of `glm::ivec2` (or equivalent 2D integer vector). Each element stores $(x, y)$ coordinates. $x$ is the scalar value (domain), $y$ is the opacity/alpha value (range).
2. `colorList`: Array of `glm::vec4` (or equivalent 4D float vector). Each element stores $(r, g, b, a)$ color values corresponding to the control point.

Auxiliary structures for interaction state:
- `specialPoint` struct:
  - `point`: `glm::ivec2` (coordinates).
  - `color`: `glm::vec4` (RGBA).
  - `pickerPos`: `glm::ivec2` (UI picker position).
  - `selectedColorPos`: `int` (index reference).
  - `drag`: `bool` (indicates if the point is currently being dragged).
  - `selected`: `bool` (indicates if the point is selected).

**Numbered Steps:**

1. **Initialization:**
   - Determine scalar range: $s_{range} = s_{max} - s_{min}$.
   - Initialize LUT size to $s_{range}$.
   - Create default control points at boundaries:
     - Min point: $(s_{min}, 0)$ with color $(0, 0, 0, 0)$ (black, transparent).
     - Max point: $(s_{max}, 1)$ with color $(1, 1, 1, 1)$ (white, opaque).
   - Set `ptsCounter` to the number of active points.

2. **Interaction Handling (Add/Delete/Move):**
   - **Add Point:**
     - Clamp alpha to 2 decimal places: $a_{clamped} = \lfloor a \times 100 \rfloor / 100.0$.
     - Validate input: If the new scalar value $s$ is outside $[s_{min}, s_{max}]$, reject the point (return error).
     - Find insertion index by comparing scalar values with existing points.
     - If a point with the same scalar value exists, replace it. Otherwise, insert the new point at the correct index to maintain order.
   - **Delete Point:**
     - Identify the point to delete (`jumpPoint`).
     - Decrement `ptsCounter`.

3. **Reordering (SortPoints):**
   - Use a priority queue (`pilaState`) to temporarily store points and their selection states.
   - Calculate `less`: `less = 1` if a point was deleted (`jumpPoint != -1`), else `0`.
   - Iterate through the original `pointList` from $0$ to `ptsCounter - 1`.
   - Skip the `jumpPoint` if it was deleted.
   - Identify selection flags:
     - `selectPicking`: True if `dragDrop` is active and the current index matches `lastPicking - 1`.
     - `selectPoint`: True if the current index matches `pointSelected - 1`.
   - Push a `specialPoint` object containing the point's coordinates, color, picker position, and flags into `pilaState`.
   - **Note on Sorting:** The priority queue defaults to a max-heap. The sort order relies on the default struct comparison, which compares `point.x` (scalar) first, then `point.y` (alpha). This assumes unique scalar values. If $x$-coordinates are not unique, the sort order is undefined by the default comparator [S2, unofficial].

4. **Reconstruction:**
   - Iterate from $0$ to `ptsCounter - less - 1`.
   - Pop the top element from `pilaState`.
   - Assign the popped element's data back to `pointList` and `colorList`.
   - Update `lastPicking` and `pointSelected` if the popped element's `drag` or `selected` flags are true.
   - Rebuild the LUT based on the sorted control points.

**Pseudocode:**

```python
import math
import heapq

class ControlPoint:
    def __init__(self, scalar: int, alpha: float, color: tuple):
        self.scalar = scalar
        self.alpha = alpha
        self.color = color

class TransferFunctionManager:
    def __init__(self, s_min: int, s_max: int):
        self.s_min = s_min
        self.s_max = s_max
        self.s_range = s_max - s_min
        self.points = []
        self.colors = []
        self._init_defaults()

    def _init_defaults(self):
        # Initialize with min (black, transparent) and max (white, opaque)
        self.points.append(self.s_min)
        self.colors.append((0, 0, 0, 0))
        self.points.append(self.s_max)
        self.colors.append((1, 1, 1, 1))

    def add_point(self, scalar: int, alpha: float, color: tuple) -> bool:
        # Clamp alpha to 2 decimal places
        alpha = math.floor(alpha * 100) / 100.0
        
        # Validate range
        if scalar < self.s_min or scalar > self.s_max:
            return False
        
        # Find insertion index
        idx = 0
        while idx < len(self.points) and self.points[idx] < scalar:
            idx += 1
            
        # Check for duplicate scalar
        if idx < len(self.points) and self.points[idx] == scalar:
            self.colors[idx] = color
        else:
            self.points.insert(idx, scalar)
            self.colors.insert(idx, color)
            
        return True

    def delete_point(self, index: int) -> bool:
        if 0 <= index < len(self.points):
            self.points.pop(index)
            self.colors.pop(index)
            return True
        return False

    def sort_points(self, jump_point: int = -1, last_picking: int = 0, point_selected: int = 0, drag_drop: bool = False):
        """
        Reorders points using a priority queue to maintain selection state.
        jump_point: index of the point to skip (deleted).
        """
        less = 1 if jump_point != -1 else 0
        
        # Priority queue stores tuples: (scalar, alpha, point_index, color, picker_pos, selected_color_pos, is_drag, is_selected)
        # Note: Python's heapq is a min-heap. We want ascending scalar order.
        # We push (scalar, alpha, original_index, ...) to ensure stable sorting by scalar then alpha.
        
        pq = []
        
        for i in range(len(self.points)):
            if i == jump_point:
                continue
                
            # Determine selection flags
            # Note: Indices in UI are often 1-based, so we subtract 1 for 0-based array access
            select_picking = (drag_drop and (i == last_picking - 1))
            select_point = (i == point_selected - 1)
            
            # Push to heap. Tuple comparison in Python is lexicographical.
            # (scalar, alpha, i, ...) ensures sorting by scalar first, then alpha, then index.
            item = (
                self.points[i],
                self.colors[i][3], # alpha for secondary sort
                i,
                self.points[i],
                self.colors[i],
                0, # placeholder for picker_pos
                0, # placeholder for selected_color_pos
                select_picking,
                select_point
            )
            heapq.heappush(pq, item)
            
        new_points = []
        new_colors = []
        new_last_picking = last_picking
        new_point_selected = point_selected
        
        for _ in range(len(self.points) - less):
            if not pq:
                break
                
            top = heapq.heappop(pq)
            
            # top[3] is scalar, top[4] is color
            new_points.append(top[3])
            new_colors.append(top[4])
            
            # Update selection indices if the popped item was the selected one
            # Note: The indices in the UI are 1-based. The new index is the loop counter + 1.
            if top[7]: # is_drag
                new_last_picking = len(new_points)
            if top[8]: # is_selected
                new_point_selected = len(new_points)
                
        self.points = new_points
        self.colors = new_colors
        return new_last_picking, new_point_selected
```

**Parameters:**
- `LUTsize`: Number of entries in the transfer function lookup table, equal to $s_{range}$ ($s_{max} - s_{min}$) [S1, unofficial].
- `alpha precision`: Clamped to 2 decimal places via `math.floor(a * 100) / 100.0` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Alpha values must be clamped to 2 decimal places to avoid floating-point drift during repeated interactions [S1, unofficial].
- **Boundary Rejection:** Control points with scalar values outside $[s_{min}, s_{max}]$ are rejected [S1, unofficial].
- **Sorting Stability:** The default struct comparison in C++ `std::priority_queue` (used in the reference implementation) relies on lexicographical comparison of `point.x` then `point.y`. If multiple points have the same scalar value ($x$), the sort order depends on the alpha ($y$) value. This assumes unique scalar values for primary sorting [S2, unofficial].
- **Index Off-by-One:** UI indices are often 1-based, while internal arrays are 0-based. Care must be taken when mapping `lastPicking` and `pointSelected` to array indices (subtract 1) [S2, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** Sorting takes $O(N \log N)$ where $N$ is the number of control points. LUT reconstruction takes $O(S)$ where $S$ is the scalar range (LUT size).
- **Memory Complexity:** $O(N)$ for storing control points and $O(S)$ for the LUT.
- **Strengths:** Maintains exact geometric constraints of the TF. Efficient for interactive editing.
- **Limitations:** Sorting relies on unique scalar values for deterministic ordering. Precision issues may arise if alpha is not clamped.
- **When to use:** Interactive TF editing in volume rendering applications.
- **When not to use:** When the TF is static and pre-computed, or when the number of control points is extremely large (consider [TF Simplification](3947-tf-simplification.md)).

## Background
This method is derived from implementations in interactive volume rendering tools, specifically those using OpenGL and GLFW for UI interaction. It addresses the need to maintain a valid piecewise linear function after user modifications, ensuring that the LUT can be correctly reconstructed from the sorted control points. The approach is documented in unofficial GitHub repositories for transfer function editors [S1, unofficial][S2, unofficial].
