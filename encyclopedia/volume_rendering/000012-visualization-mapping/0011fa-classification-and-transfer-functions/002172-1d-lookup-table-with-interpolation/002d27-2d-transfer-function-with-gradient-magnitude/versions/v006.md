# 2D Transfer Function with Gradient Magnitude

Also called: Gradient-based TF, Scalar and Gradient TF, Gradient-Aware Transfer Function, 2D Histogram TF (Scalar-Gradient), Joint histogram transfer function, Intensity-Gradient Transfer Function, scalar value vs. gradient magnitude transfer function

## Overview
The 2D Transfer Function with Gradient Magnitude extends the domain of volume classification from a single scalar value to a two-dimensional space comprising the scalar value and its gradient magnitude [S1, book][S2, unofficial][S3]. This method solves the ambiguity inherent in 1D transfer functions, where distinct materials with similar intensity values but different boundary characteristics (e.g., sharp vs. soft edges) cannot be distinguished [S3][S4, unofficial]. Unlike its parent [1D Lookup Table with Interpolation](2528-1d-lookup-table-with-interpolation.md), which maps a single scalar to color and opacity independently, this method uses a single 2D mapping to simultaneously disambiguate regions based on both intensity and edge strength [S4, unofficial]. It is distinguished from [3D Transfer Function](5777-3d-transfer-function.md) by restricting the second dimension to the L2-norm of the gradient, rather than incorporating additional derivatives or vector components [S2, unofficial][S3].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D volumetric dataset $V$ of scalar values, and a 2D transfer function texture $T$.
*   **Output:** A 2D image where each pixel's color and opacity are determined by the scalar value and gradient magnitude of the corresponding voxel.

**Data Structures**
The transfer function is stored as a 2D texture (or `vtkImageData` object) with 4 components per pixel, typically floating-point values in the range $[0, 1]$ [S1, book][S4, unofficial].
*   **Texture Dimensions:** $W \times H$.
*   **Axes:**
    *   Horizontal axis ($x$): Scalar data values (intensity).
    *   Vertical axis ($y$): Gradient magnitude (L2-norm of the gradient vector) [S1, book][S3].
*   **Components:** $(R, G, B, \alpha)$ representing color and opacity [S4, unofficial].

**Algorithm Steps**
1.  **Gradient Computation:** For each voxel in the volumetric dataset, compute the first derivative (gradient vector $\nabla V$) [S2, unofficial]. The gradient represents the direction of the most prominent change in values at that point [S2, unofficial].
2.  **Gradient Magnitude Calculation:** Compute the gradient magnitude $g$ for each voxel using the L2-norm:
    $$ g = \|\nabla V\|_2 = \sqrt{\left(\frac{\partial V}{\partial x}\right)^2 + \left(\frac{\partial V}{\partial y}\right)^2 + \left(\frac{\partial V}{\partial z}\right)^2} $$
    [S3].
3.  **Histogram Generation (Optional/Visual Aid):** Generate a 2D histogram with scalar values on the horizontal axis and gradient magnitudes on the vertical axis [S2, unofficial]. Material boundaries appear as arches in this histogram: the ends of the arch correspond to homogeneous regions (gradient magnitude $\approx 0$), and the top of the arch corresponds to the border between materials (maximum gradient magnitude) [S2, unofficial].
4.  **Transfer Function Definition:** Define the mapping function $tf$:
    $$ tf: (x, y) \in \mathbb{R}^2 \rightarrow (R, G, B, \alpha) \in [0, 1]^4 $$
    where $x$ is the scalar intensity and $y$ is the gradient magnitude [S3].
5.  **User Interaction (Painting):** Users paint directly into the 2D transfer function texture using graphical widgets [S1, book]. Brushes assign color and opacity to specific ranges of data values and gradient magnitudes [S1, book].
6.  **Rendering Lookup:** During volume rendering, for each sample point along the ray:
    *   Retrieve the scalar value $s$ and gradient magnitude $g$.
    *   Sample the 2D texture $T$ at coordinates $(s, g)$ to obtain $(R, G, B, \alpha)$.
    *   Use these values for compositing.

**Pseudocode**
```python
# Assume:
# volume_data: 3D array of scalar values
# tf_texture: 2D array of 4 floats (R, G, B, A) normalized to [0,1]
# tf_width: width of tf_texture (maps to scalar range)
# tf_height: height of tf_texture (maps to gradient range)
# scalar_min, scalar_max: min/max scalar values in volume_data
# grad_min, grad_max: min/max gradient magnitudes in volume_data

def compute_gradient_magnitude(volume_data):
    """
    Computes the gradient magnitude for each voxel.
    Uses central differences for interior points and forward/backward for boundaries.
    """
    dims = volume_data.shape
    grad_mag = np.zeros(dims)
    
    # Compute gradients in x, y, z directions
    # Using numpy gradient or manual central differences
    gx, gy, gz = np.gradient(volume_data)
    
    # L2 norm
    grad_mag = np.sqrt(gx**2 + gy**2 + gz**2)
    return grad_mag

def sample_tf_texture(tf_texture, scalar_val, grad_val, tf_width, tf_height, 
                      scalar_min, scalar_max, grad_min, grad_max):
    """
    Samples the 2D transfer function texture.
    """
    # Normalize inputs to [0, 1]
    u = (scalar_val - scalar_min) / (scalar_max - scalar_min)
    v = (grad_val - grad_min) / (grad_max - grad_min)
    
    # Clamp to [0, 1] to handle out-of-bounds
    u = np.clip(u, 0.0, 1.0)
    v = np.clip(v, 0.0, 1.0)
    
    # Map to texture coordinates
    tex_x = int(u * (tf_width - 1))
    tex_y = int(v * (tf_height - 1))
    
    # Bilinear interpolation could be applied here for smoothness
    # For simplicity, assuming nearest neighbor or pre-interpolated texture
    return tf_texture[tex_y, tex_x]

def render_volume(volume_data, tf_texture):
    """
    Simplified volume rendering loop.
    """
    grad_mag_data = compute_gradient_magnitude(volume_data)
    
    # Determine ranges
    scalar_min = volume_data.min()
    scalar_max = volume_data.max()
    grad_min = grad_mag_data.min()
    grad_max = grad_mag_data.max()
    
    # Initialize output image
    output_image = np.zeros((height, width, 4))
    
    # Ray casting loop (simplified)
    for ray in rays:
        color = np.array([0.0, 0.0, 0.0, 0.0])
        alpha = 0.0
        
        for sample in ray.samples:
            s = sample.value
            g = sample.gradient_magnitude
            
            # Sample TF
            tf_color = sample_tf_texture(tf_texture, s, g, 
                                         tf_texture.shape[1], tf_texture.shape[0],
                                         scalar_min, scalar_max, grad_min, grad_max)
            
            # Composite (front-to-back)
            # C_out = C_in + (1 - alpha_in) * C_tf * alpha_tf
            # alpha_out = alpha_in + (1 - alpha_in) * alpha_tf
            
            c_tf = tf_color[:3]
            a_tf = tf_color[3]
            
            color = color + (1 - alpha) * c_tf * a_tf
            alpha = alpha + (1 - alpha) * a_tf
            
        output_image[ray.screen_pos] = color

# Implementation Note: In practice, this is executed on the GPU using fragment shaders.
# The fragment shader receives interpolated scalar and gradient values and samples the 2D texture.
```

**Parameters**
*   **Sampling Rate:** The opacity assigned by the transfer function may need scaling based on the sampling rate $s$ relative to a reference rate $s_0$ to maintain consistent visual intensity [S1, book].
*   **Texture Resolution:** Higher resolution allows finer control over material boundaries but increases memory usage [S1, book][S4, unofficial].

**Edge Cases and Pitfalls**
*   **Noise:** Gradient magnitude is sensitive to noise, which can create false material borders [S2, unofficial].
*   **Partial Volume Effects:** These can blur boundaries, affecting gradient accuracy [S2, unofficial].
*   **Intensity Biasing:** Non-uniformities in intensity values (e.g., from high-field MRI scanners) can cause false material border detection [S2, unofficial].
*   **Overlap:** Material density values and gradient magnitudes can overlap in the 2D histogram, causing ambiguity in selection [S2, unofficial].
*   **Hardware Support:** Only specific mappers (e.g., `vtkGPUVolumeRayCastMapper` with OpenGL2 backend) support 2D transfer functions [S4, unofficial].

## Subtopics

### [Rectangular Classification Widget](5634-rectangular-classification-widget.md)
The Rectangular Classification Widget is an interactive tool for defining general transfer functions for scalar data that lacks clear material boundaries. It operates in the 2D domain of data value and gradient magnitude, allowing users to define regions of interest via a resizable rectangle. Unlike triangular widgets which emphasize surfaces, this widget supports flexible opacity falloffs (ellipsoidal, linear ramps, tents, or pyramids) while maintaining constant color within the defined region.

### [Multivariate Gradient Magnitude](5652-multivariate-gradient-magnitude.md)
Multivariate Gradient Magnitude provides a scalar measure of local change in multidimensional volume data (e.g., RGB color, meteorological fields) by computing the L2 norm of the structure tensor $G$. It solves the problem that gradient estimation for multivalued fields is not well-defined in the same way as for scalar datasets, where a single gradient vector exists. Unlike scalar volume rendering which relies on a single intensity axis, this method generalizes gradient-based edge detection by incorporating a first-derivative measure of total local change across all data components as an additional axis in multidimensional transfer functions. It is distinguished from its siblings by its use of the rotationally invariant L2 norm of the tensor, rather than the principal eigenvalue or non-rotationally invariant measures.

### [Local Histogram-based Transfer Function](9491-local-histogram-based-transfer-function.md)
The Local Histogram-based Transfer Function (LH TF) is a 2D visualization mapping technique that utilizes local intensity distributions to define material boundaries, addressing the noise and partial volume effect limitations inherent in standard gradient magnitude-based transfer functions. Unlike its parent method, which relies on global gradient magnitude, the LH TF represents data using diagonals or local intensity pairs, allowing for superior discrimination of tissues in medical datasets by explicitly modeling the lower and higher intensities of materials forming boundaries.

### [Gradient-Based Transfer Functions with Shading](12103-gradient-based-transfer-functions-with-shading.md)
This method enhances volume visualization by precomputing surface normals and shaded intensity values to drive a 2D opacity transfer function based on gradient magnitude, while using a 1D transfer function for color/intensity. It solves the problem of flat, featureless volume rendering by providing shading cues that reveal internal structure and boundaries, distinguishing it from simple 1D transfer functions. It builds on [2D Transfer Function with Gradient Magnitude](5491-2d-transfer-function-with-gradient-magnitude.md) by explicitly incorporating diffuse lighting calculations into the data preparation phase.

### 2D Patch Sketching
2D Patch Sketching is a proposed technique to map opacity values to each intensity-gradient pair using a sketchpad with an underlying 2D histogram [S5, unofficial]. It places 1D transfer functions at the bottom and left side of the 2D domain so the user can better draw or delete the patch of interest [S5, unofficial]. Over the sketchpad, users draw arbitrary patches or closed curves to define or delete specific segments within the 2D domain [S5, unofficial]. Points outside the selection patch are set to have zero opacity [S5, unofficial]. When opacity values need to be settled, the flat 2D histogram view converts to a 3D plot where users can rotate the plot, select the 2D patch, and raise/lower the transparency height [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** The primary computational cost is the gradient calculation, which is $O(N)$ where $N$ is the number of voxels. The lookup during rendering is $O(1)$ per sample point, assuming texture sampling is constant time.
*   **Memory Complexity:** Requires storage for the gradient magnitude volume ($O(N)$) and the 2D transfer function texture ($O(W \times H)$).
*   **Performance:** Rendering performance depends on the resolution of the 2D texture and the number of samples per ray. The method is supported only by specific GPU mappers (e.g., `vtkGPUVolumeRayCastMapper` with OpenGL2 backend) [S4, unofficial].
*   **Strengths:** Allows finer control and sophisticated visualization of material boundaries [S1, book]. It can visually distinguish data points that have the same intensity but different gradient magnitudes, allowing for feature isolation [S3].
*   **Limitations:** Does not address noise, partial volume effects, or false material border detection due to biasing [S2, unofficial]. Material density values and gradient magnitudes can overlap, causing ambiguity [S2, unofficial].
*   **When to Use:** When 1D transfer functions fail to distinguish materials with similar intensities but different edge characteristics.
*   **When Not to Use:** When the data is noisy or has significant partial volume effects without pre-processing, or when hardware does not support 2D transfer functions [S4, unofficial].

## Background
The concept of incorporating gradient magnitude into transfer functions was introduced by Kindlmann and Durkin (1998) and Kindlmann (1999) to allow for finer control and more sophisticated visualization [S1, book]. The specific implementation of 2D transfer functions as a single 2D texture mapping scalar value and gradient magnitude to color and opacity was added to VTK thanks to developments in tomviz under DOE Office of Science contract DE-SC0011385, announced on September 1, 2017 [S4, unofficial]. The feature enables users to switch between legacy 1D transfer functions (which use three independent 1D functions) and the single 2D transfer function mode [S4, unofficial].
