# 2D Transfer Function with Gradient Magnitude

Also called: 2D Transfer Function Support in GPUVolumeMapper, 2D Transfer Function in GPUVolumeMapper, Gradient-Aware Transfer Function, Intensity-Gradient Transfer Function, Joint histogram transfer function, scalar value vs. gradient magnitude transfer function

## Overview
This method extends the classification domain from a single scalar value to a joint space of scalar value and gradient magnitude, allowing the isolation of features that share intensity but differ in boundary characteristics [S2][S3, unofficial]. Unlike independent 1D functions which map scalar-to-color and scalar-to-opacity separately, this approach uses a single 2D mapping to disambiguate regions simultaneously based on both parameters, improving discrimination between overlapping structures [S3, unofficial]. It sets itself apart from [Style Transfer Function (1D)](777-style-transfer-function-1d.md) by utilizing the second dimension (gradient magnitude) to identify material boundaries, and from [Boundary-Enhanced Opacity](795-boundary-enhanced-opacity.md) by treating gradient magnitude as a primary axis of the transfer function domain rather than just an opacity modifier [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume $V$ and a 2D transfer function texture $T$.
*   **Output:** A 2D image where each pixel's color $(R, G, B)$ and opacity $\alpha$ are determined by the scalar value $v$ and gradient magnitude $g$ of the corresponding sample point.

**Data Structures:**
The transfer function is stored as a 2D texture (e.g., `vtkImageData` with 4 components per pixel) [S3, unofficial].
*   **Horizontal Axis ($x$):** Represents the scalar data value $v$.
*   **Vertical Axis ($y$):** Represents the gradient magnitude $g = \|\nabla f(\mathbf{x})\|$ [S2].
*   **Texture Content:** Each texel stores a 4-component float vector $(R, G, B, \alpha)$ [S3, unofficial].

**Gradient Calculation:**
The gradient magnitude is computed for each sample point $\mathbf{x}$ during ray casting. For a scalar field $f(\mathbf{x})$, the gradient vector $\nabla f(\mathbf{x})$ is typically estimated using central differences or trilinear interpolation derivatives. The gradient magnitude is the L2-norm:
$$ g = \|\nabla f(\mathbf{x})\| = \sqrt{\left(\frac{\partial f}{\partial x}\right)^2 + \left(\frac{\partial f}{\partial y}\right)^2 + \left(\frac{\partial f}{\partial z}\right)^2} $$
[S2]

**Classification Function:**
The transfer function is defined as a mapping from the 2D input space to the 4D output space:
$$ tf: (x, y) \in \mathbb{R}^2 \rightarrow (R, G, B, \alpha) \in [0, 1]^4 $$
where $x$ is the intensity and $y$ is the gradient magnitude [S2].

**Rendering Steps:**
1.  **Ray Casting:** For each pixel, cast a ray through the volume.
2.  **Sampling:** Interpolate the scalar value $v$ from the volume data at the current sample position $\mathbf{x}$ [S2].
3.  **Gradient Estimation:** Compute the gradient magnitude $g$ at $\mathbf{x}$ [S2].
4.  **TF Lookup:** Sample the 2D transfer function texture $T$ at coordinates $(v, g)$. This yields the color $\mathbf{c} = (R, G, B)$ and opacity $\alpha$ [S3, unofficial].
5.  **Accumulation:** Composite the sample using standard volume rendering accumulation (e.g., front-to-back):
    $$ C_{out} = C_{in} + \mathbf{c} \cdot \alpha \cdot (1 - \alpha_{in}) $$
    $$ \alpha_{out} = \alpha_{in} + \alpha \cdot (1 - \alpha_{in}) $$
6.  **Opacity Correction:** If the sampling rate $s$ differs from the reference sampling rate $s_0$, the opacity $\alpha$ retrieved from the transfer function must be scaled to maintain consistent visual intensity [S1, book]. The correction factor is derived from Equation 3 in [S1, book]:
    $$ \alpha_{corrected} = 1 - (1 - \alpha)^{\frac{s_0}{s}} $$
    [S1, book]

**Pseudocode:**
```python
def render_2d_tf_volume(volume_data, tf_texture, ray_origin, ray_direction, resolution):
    """
    Renders a volume using a 2D transfer function mapping scalar value and gradient magnitude.
    
    Args:
        volume_data: 3D array of scalar values.
        tf_texture: 2D texture mapping (scalar, gradient) -> (R, G, B, alpha).
        ray_origin: 3D vector, start of the ray.
        ray_direction: 3D vector, direction of the ray.
        resolution: Tuple (width, height) of the output image.
        
    Returns:
        2D image array (width, height, 4).
    """
    image = np.zeros((resolution[1], resolution[0], 4))
    
    # Precompute ray step size and bounds
    step_size = 1.0 / resolution[0] # Simplified; actual step depends on volume bounds
    # In practice, step_size is determined by the volume's physical dimensions and desired sample count
    
    for y in range(resolution[1]):
        for x in range(resolution[0]):
            # 1. Cast ray
            ray = Ray(ray_origin + x * ray_direction, ray_direction)
            
            color_accum = np.array([0.0, 0.0, 0.0, 0.0])
            alpha_accum = 0.0
            
            # 2. Sample along ray
            sample_pos = ray.origin
            while alpha_accum < 1.0 and sample_pos inside volume:
                # 3. Get scalar value
                v = interpolate_volume(volume_data, sample_pos)
                
                # 4. Compute gradient magnitude
                # Gradient is computed using central differences or texture derivatives
                grad = compute_gradient(volume_data, sample_pos)
                g = np.linalg.norm(grad)
                
                # 5. Lookup TF
                # Clamp v and g to texture bounds [0, 1] or [min, max]
                tf_color, tf_alpha = sample_tf_texture(tf_texture, v, g)
                
                # 6. Apply opacity correction if sampling rate differs from reference
                # s is current samples per unit length, s0 is reference
                # alpha_corrected = 1 - (1 - tf_alpha)^(s0/s)
                tf_alpha = apply_opacity_correction(tf_alpha, s, s0)
                
                # 7. Composite
                weight = tf_alpha * (1.0 - alpha_accum)
                color_accum += tf_color * weight
                alpha_accum += weight
                
                sample_pos += ray_direction * step_size
            
            image[y, x] = color_accum
            
    return image

def compute_gradient(volume_data, pos):
    """
    Computes the gradient vector at a position using central differences.
    """
    # Implementation depends on volume grid spacing
    # dx, dy, dz are grid spacings
    grad_x = (volume_data[pos + (1,0,0)] - volume_data[pos - (1,0,0)]) / (2 * dx)
    grad_y = (volume_data[pos + (0,1,0)] - volume_data[pos - (0,1,0)]) / (2 * dy)
    grad_z = (volume_data[pos + (0,0,1)] - volume_data[pos - (0,0,1)]) / (2 * dz)
    return np.array([grad_x, grad_y, grad_z])
```
[S1, book][S2][S3, unofficial]

**Parameters:**
*   **Sampling Rate ($s$):** The number of samples per unit length. Affects the opacity correction factor [S1, book].
*   **Reference Sampling Rate ($s_0$):** The sampling rate for which the transfer function was originally designed [S1, book].
*   **Transfer Mode:** A flag to switch between legacy 1D mode (`TF_1D`) and 2D mode (`TF_2D`) [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Hardware Support:** Only `vtkGPUVolumeRayCastMapper` with the OpenGL2 backend supports 2D transfer functions [S3, unofficial].
*   **Precision:** Gradient magnitude calculation can be sensitive to noise in the volume data, potentially creating false boundaries. Smoothing may be required [S1, book][S2].
*   **Boundary Conditions:** Gradient estimation at volume boundaries requires careful handling of missing neighbors [G].
*   **Opacity Scaling:** Failure to correct opacity for sampling rate changes results in inconsistent visual intensity across different rendering settings [S1, book].

## Subtopics

### [Rectangular Classification Widget](5634-rectangular-classification-widget.md)
A classification widget for creating more general transfer functions for data without clear boundaries. It allows users to define rectangular regions in the 2D domain to assign specific color and opacity values, suitable for data where features do not form distinct arches or clusters [5634-rectangular-classification-widget.md].

### [Multivariate Gradient Magnitude](5652-multivariate-gradient-magnitude.md)
Multivariate Gradient Magnitude is a first-derivative measure for multivariate data (e.g., RGB color) that captures the total amount of local change across all data components, used as an axis in multidimensional transfer functions. It sets itself apart from scalar gradient magnitude by operating on a tensor derived from the Jacobian of the multivariate field, providing a rotationally invariant measure of local contrast. Unlike non-rotationally invariant measures of the gradient tensor used in other work, this method uses the L2 norm of the resulting tensor $G$ to ensure directional independence.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the number of samples per ray. The gradient computation adds a constant factor per sample.
*   **Memory Complexity:** $O(V + T)$, where $V$ is the volume data size and $T$ is the size of the 2D transfer function texture.
*   **Performance:** Rendering performance depends on the cost of gradient estimation. Computing gradients on-the-fly during ray casting can be expensive; precomputing gradient magnitude volumes can improve performance but increases memory usage [S1, book][S2].
*   **Strengths:** Superior feature isolation compared to 1D TFs, especially for distinguishing materials with similar intensities but different boundary sharpness [S2][S3, unofficial].
*   **Limitations:** Requires gradient computation, which can be noisy. Limited to scalar volumes in the basic implementation; multivariate extensions require more complex gradient tensors [S1, book].
*   **When to Use:** When 1D transfer functions fail to separate overlapping structures with similar intensity ranges but different edge characteristics [S2].
*   **When Not to Use:** For very noisy data where gradient estimation is unreliable, or when hardware does not support the required mapper/backend [S3, unofficial].

## Background
The concept of using gradient magnitude to enhance transfer functions was introduced by Kindlmann and Durkin (1998) and further developed by Kindlmann (1999) [S1, book]. The specific implementation as a 2D texture mapping in VTK's GPU volume mapper was added in 2017, thanks to developments in tomviz under DOE Office of Science contract DE-SC0011385 [S3, unofficial]. This feature allows users to switch between legacy 1D transfer functions and the more expressive 2D mode [S3, unofficial].
