# 2D Transfer Function with Gradient Magnitude

Also called: Gradient-based TF, Scalar and Gradient TF, Gradient-Aware Transfer Function, 2D Histogram TF (Scalar-Gradient), Joint histogram transfer function, Intensity-Gradient Transfer Function, scalar value vs. gradient magnitude transfer function

## Overview
This method extends the 1D lookup table by adding gradient magnitude as a second dimension, mapping a voxel's scalar value and its local gradient magnitude simultaneously to color and opacity [S1, book][S2, unofficial][S3]. It solves the ambiguity of 1D transfer functions where different materials share similar intensity values but differ in boundary sharpness, allowing for finer control and sophisticated visualization of material boundaries [S1, book][S2, unofficial]. Unlike independent 1D functions that map scalar-to-color and scalar/gradient-to-opacity separately, this approach uses a single 2D domain to disambiguate regions that fall within similar ranges for both parameters simultaneously [S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$ and a 2D transfer function texture $TF$.
*   **Output:** A 2D image where each pixel's color and opacity are determined by the voxel's scalar value and gradient magnitude.

**Data Structures:**
The transfer function is stored as a 2D texture (or `vtkImageData` object) with 4 components per pixel (float) [S4, unofficial].
*   **Horizontal Axis ($x$):** Scalar data values (intensity).
*   **Vertical Axis ($y$):** Gradient magnitude (L2-norm of the gradient vector) [S3][S4, unofficial].
*   **Pixel Value:** A 4-component vector $(R, G, B, \alpha) \in [0, 1]^4$ representing the mapped color and opacity [S3][S4, unofficial].

**Gradient Computation:**
For each voxel in the volumetric dataset, the first derivative (gradient) is computed, representing the direction of the most prominent change in values at that point [S2, unofficial]. The gradient magnitude $g$ is defined as the L2-norm of the gradient vector $\nabla V$ [S3]:
$$ g = \|\nabla V\|_2 = \sqrt{\left(\frac{\partial V}{\partial x}\right)^2 + \left(\frac{\partial V}{\partial y}\right)^2 + \left(\frac{\partial V}{\partial z}\right)^2} $$
This magnitude is effective in visualizing object boundaries [S3].

**Transfer Function Mapping:**
The transfer function is defined as a mapping from the 2D domain of scalar value and gradient magnitude to the 4D output space of color and opacity [S3]:
$$ tf: (x, y) \in \mathbb{R}^2 \rightarrow (R, G, B, \alpha) \in [0, 1]^4 $$
where $x$ is the intensity and $y$ is the gradient magnitude [S3].

**Interaction and Design:**
1.  **Histogram Visualization:** A 2D histogram is generated with scalar values on the horizontal axis and gradient magnitudes on the vertical axis [S2, unofficial].
2.  **Feature Identification:** Material boundaries appear as arches in this histogram. The two ends of an arch correspond to homogeneous regions of two different materials (where gradient value is 0), while the top of the arch corresponds to the border between materials (where gradient magnitude is maximum) [S2, unofficial].
3.  **Direct Manipulation:** Users paint directly into the 2D transfer function texture using graphical widgets or brushes to assign color and opacity to specific ranges of data values and gradient magnitudes [S1, book][S2, unofficial].
4.  **Opacity Correction:** If the sampling rate $s$ changes from a reference sampling rate $s_0$, the opacity must be scaled to maintain consistent image intensity [S1, book]. The correction formula is:
    $$ \alpha_{corrected} = \alpha_{original} \times \frac{s}{s_0} $$
    [S1, book]

## Subtopics

### [Rectangular Classification Widget](5634-rectangular-classification-widget.md)
The Rectangular Classification Widget is an interactive tool for defining general transfer functions for scalar data that lacks clear material boundaries. It operates in the 2D domain of data value and gradient magnitude, allowing users to define regions of interest via a resizable rectangle. Unlike triangular widgets which emphasize surfaces, this widget supports flexible opacity falloffs (ellipsoidal, linear ramps, tents, or pyramids) while maintaining constant color within the defined region.

### [Multivariate Gradient Magnitude](5652-multivariate-gradient-magnitude.md)
Multivariate Gradient Magnitude provides a scalar measure of local change in multidimensional volume data (e.g., RGB color, meteorological fields) by computing the L2 norm of the structure tensor $G$. It solves the problem that gradient estimation for multivalued fields is not well-defined in the same way as for scalar datasets, where a single gradient vector exists. Unlike scalar volume rendering which relies on a single intensity axis, this method generalizes gradient-based edge detection by incorporating a first-derivative measure of total local change across all data components as an additional axis in multidimensional transfer functions. It is distinguished from its siblings by its use of the rotationally invariant L2 norm of the tensor, rather than the principal eigenvalue or non-rotationally invariant measures.

### [Local Histogram-based Transfer Function](9491-local-histogram-based-transfer-function.md)
The Local Histogram-based Transfer Function (LH TF) is a 2D visualization mapping technique that utilizes local intensity distributions to define material boundaries, addressing the noise and partial volume effect limitations inherent in standard gradient magnitude-based transfer functions. Unlike its parent method, which relies on global gradient magnitude, the LH TF represents data using diagonals or local intensity pairs, allowing for superior discrimination of tissues in medical datasets by explicitly modeling the lower and higher intensities of materials forming boundaries.

### 2D Patch Sketching
A proposed technique to map opacity values to each intensity-gradient pair using a sketchpad with an underlying 2D histogram [S5, unofficial]. It places 1D transfer functions at the bottom and left side of the 2D domain so the user can better draw or delete the patch of interest [S5, unofficial]. Over the sketchpad, users draw arbitrary patches or closed curves to define or delete specific segments within the 2D domain, setting points outside the selection patch to have zero opacity [S5, unofficial]. When opacity values need to be settled, the flat 2D histogram view converts to a 3D plot where users can rotate the plot, select the 2D patch, and raise/lower the transparency height [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time depends on the ray casting algorithm and the number of samples per ray. The lookup into the 2D transfer function is $O(1)$ per sample. Gradient computation is $O(N)$ for the volume, where $N$ is the number of voxels.
*   **Memory Complexity:** Requires storage for the 3D volume data, the 3D gradient magnitude data, and the 2D transfer function texture. The 2D TF texture size depends on the resolution of the scalar and gradient axes.
*   **Strengths:** Allows for finer control and sophisticated visualization of material boundaries compared to 1D TFs [S1, book]. Can visually distinguish data points that have the same intensity but different gradient magnitudes, allowing for feature isolation [S3].
*   **Limitations:** Does not address noise, partial volume effects, or biasing artifacts [S2, unofficial]. Material density values and gradient magnitudes can overlap, causing ambiguity [S2, unofficial]. Implementation support is limited in some libraries (e.g., VTK requires specific mapper and backend) [S4, unofficial].
*   **When to Use:** When materials have similar intensity values but distinct boundary characteristics (sharp vs. soft edges).
*   **When Not to Use:** When the data is noisy or has significant partial volume effects without preprocessing, or when hardware/software does not support 2D TF lookups efficiently.

## Background
The concept of incorporating gradient magnitude into transfer functions was introduced by Kindlmann and Durkin (1998) and Kindlmann (1999) to allow for finer control and more sophisticated visualization [S1, book]. The feature was added to VTK's `vtkGPUVolumeRayCastMapper` thanks to developments in tomviz under DOE Office of Science contract DE-SC0011385, with the announcement made on September 1, 2017 [S4, unofficial].
