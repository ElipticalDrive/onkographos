# Sequential 2D/1D Transfer Function Combination

Also called: Sequential 2D-then-1D TF, Sequential TF Application

## Overview
A method that sequentially applies a 2D transfer function and a 1D transfer function to all voxels of a multivariate volume dataset to improve feature classification specificity [S1, unofficial]. It addresses the difficulty of robustly separating features using only single 1D or 2D transfer functions by combining different transfer function spaces [S1, unofficial]. Unlike analytical multidimensional transfer functions that rely on multiplication in high dimensions, this approach avoids misclassification pitfalls associated with high-dimensional products [S1, unofficial]. It builds on [Separable Transfer Function](9014-separable-transfer-function.md) and differs from [Multivariate Transfer Function Combination Selection](9482-multivariate-transfer-function-combination-selection.md) and [Separable 3D Transfer Function Editor](9507-separable-3d-transfer-function-editor.md).

## How it works
**Inputs and Outputs**
*   **Input:** A volume dataset $V$ containing $l$ properties (attributes) $Y_1, Y_2, \dots, Y_l$ [S1, unofficial]. Each voxel $v_X$ is identified by its 3D position $X$ [S1, unofficial].
*   **Parameters:**
    *   $k$: The number of 2D transfer function widgets applied. This is user-defined; no fixed value is specified [S1, unofficial].
    *   $r$: The number of 1D transfer functions applied to the classified regions. Typically 1 or 2 [S1, unofficial].
*   **Output:** A final classified volume consisting of regions $W_i$ [S1, unofficial].

**Data Structures**
The method operates on logical sets of voxels [S1, unofficial].
*   $C_j$: The $j$-th classified voxel set generated by the $j$-th 2D transfer function widget [S1, unofficial].
*   $W_i$: The final classified volume region [S1, unofficial].

**Steps**
1.  **2D Classification:** For each of the $k$ 2D transfer function widgets $w_j$ (where $j \in [1, k]$), evaluate the widget on two specific properties $Y_p$ and $Y_q$ (where $p, q \in [1, l]$) for every voxel $v_X$ in the dataset $V$ [S1, unofficial].
2.  **Generate Intermediate Sets:** Create the set $C_j$ containing all voxels $v_X$ where the 2D transfer function value is positive:
    $$C_j := \{v_X \mid \text{TF}_{w_j}(Y_p(X), Y_q(X)) > 0, \ p,q \in [1,l]\}$$
    This results in $k$ distinct sets of classified voxels $\{C_1, C_2, \dots, C_k\}$ [S1, unofficial].
3.  **1D Refinement:** For each intermediate set $C_j$, apply one of the $r$ available 1D transfer functions $\text{TF}_r$ to a third property $Y_r$ [S1, unofficial]. The property $Y_r$ must be distinct from the properties $Y_p$ and $Y_q$ used in the 2D step (i.e., $r \in \{1, \dots, l\} \setminus \{p, q\}$) [S1, unofficial].
4.  **Final Classification:** Define the final classified region $W_i$ as the subset of $C_j$ that satisfies the 1D transfer function condition:
    $$\{W_i \subset C_j\} = \text{TF}_r(Y_r(X)) \quad \text{where} \quad X \in C_j$$
    Each 2D transfer function widget is associated with one 1D transfer function [S1, unofficial].

**Pseudocode**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def sequential_2d_1d_tf_combination(properties, tf_2d_widgets, tf_1d_functions, widget_configs):
    """
    properties: list of l 3D arrays (lists of lists of lists) of shape (D, H, W)
    tf_2d_widgets: list of k callables, each taking two scalars and returning a float
    tf_1d_functions: list of r callables, each taking one scalar and returning a float
    widget_configs: list of k tuples (p, q, r) where p, q, r are property indices (0-based)
    Returns: list of k boolean 3D arrays representing final regions W_i
    """
    D, H, W = len(properties[0]), len(properties[0][0]), len(properties[0][0][0])
    final_regions = []

    for j in range(len(tf_2d_widgets)):
        p, q, r = widget_configs[j]
        prop_p = properties[p]
        prop_q = properties[q]
        prop_r = properties[r]

        # Step 1: Generate intermediate set C_j
        mask_C_j = [[[False for _ in range(W)] for _ in range(H)] for _ in range(D)]
        for x in range(D):
            for y in range(H):
                for z in range(W):
                    if tf_2d_widgets[j](prop_p[x][y][z], prop_q[x][y][z]) > 0:
                        mask_C_j[x][y][z] = True

        # Step 2: Apply 1D TF to refine C_j into W_i
        mask_W_i = [[[False for _ in range(W)] for _ in range(H)] for _ in range(D)]
        for x in range(D):
            for y in range(H):
                for z in range(W):
                    if mask_C_j[x][y][z] and tf_1d_functions[j](prop_r[x][y][z]) > 0:
                        mask_W_i[x][y][z] = True

        final_regions.append(mask_W_i)

    return final_regions
```

**Edge Cases and Pitfalls**
*   **Classification Inconsistency:** The sequential dimension reduction can cause classification inconsistencies compared to a true $n$-dimensional transfer function [S1, unofficial]. However, the precision loss is typically minor and considered a reasonable trade-off for usability [S1, unofficial].
*   **Property Selection:** The method requires $l \ge 3$ to allow for distinct $p, q, r$ indices [S1, unofficial]. If $l < 3$, the 1D refinement step cannot use a property distinct from the 2D inputs [S1, unofficial].
*   **Misclassification Avoidance:** Unlike methods that multiply transfer function values in high dimensions (which can lead to misclassification as shown by Kniss et al.), this sequential approach avoids such pitfalls by filtering voxels in stages [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Provides more specificity for data classification than traditional 1D or 2D transfer functions alone [S1, unofficial]. It is more flexible than local transfer functions (which require pre-classified/tagged volumes) because it allows interactive labeling via 2D widgets followed by 1D refinement [S1, unofficial].
*   **Limitations:** Not as expressive as a true $n$-dimensional transfer function due to the sequential reduction [S1, unofficial].
*   **When to Use:** Suitable for multivariate volume visualization systems, particularly for time-varying and complex simulation datasets where high-dimensional transfer functions are needed but interactive design is required [S1, unofficial].

## Background
This method was proposed by Zhou et al. in their dissertation on multivariate transfer function design [S1, unofficial]. It was developed to address the limitations of existing transfer function spaces, such as traditional 1D and 2D methods, which are not always effective for all datasets [S1, unofficial]. The work contrasts with Kniss et al.'s analytical multidimensional transfer functions, which suffer from misclassification when extending to 3D via multiplication, and Rezk-Salama's local transfer functions, which rely on pre-classified tagged volumes [S1, unofficial]. The method prioritizes classification specificity over illustrative rendering, distinguishing it from style indexing approaches like those of Bruckner and Groller [S1, unofficial].
