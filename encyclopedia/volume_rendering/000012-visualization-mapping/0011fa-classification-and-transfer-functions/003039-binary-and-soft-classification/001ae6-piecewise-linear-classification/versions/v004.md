# Piecewise-Linear Classification

Also called: Local Classification, Piecewise Linear Channelwise Transfer Function, RGBA classification functions, Ramps, Syntactic Control

## Overview
Piecewise-Linear Classification is a local classification technique that maps voxel intensity and derived features (such as gradient magnitude) to RGBA optical properties using piecewise-linear functions, commonly called ramps [S2, unofficial][S3, unofficial]. It solves the problem of emphasizing specific data features by allowing users to define smooth transitions between material classes, distinguishing it from the hard thresholds of [Binary Classification](931-binary-classification.md) and enabling multi-channel control unlike basic single-channel methods [S1, unofficial]. It is a specific instance of [Binary and Soft Classification](6229-binary-and-soft-classification.md) that relies on linear interpolation between user-defined keypoints.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar value $v$ representing voxel intensity, and optionally a derived feature $g$ such as gradient magnitude $\|\nabla f(\mathbf{x})\|$ [S2, unofficial]. The input domain is typically 1D per channel [S3, unofficial].
*   **Output:** A set of optical properties: Opacity $\alpha \in [0, 1]$ and Color $C = (r, g, b)$ [S2, unofficial].

**Data Structures:**
The transfer function is defined by keypoints. For each output channel (Red, Green, Blue, Alpha), a pair of sorted 1D arrays is stored:
*   $x_p$: Tensor of shape $(K,)$ containing sorted x-coordinates (input values) of the keypoints.
*   $y_p$: Tensor of shape $(K,)$ containing y-coordinates (output values) at those keypoints.
*   $K$: The number of keypoints. The system supports any number of segments, though UIs may limit this (e.g., to three segments) [S2, unofficial].

**Numbered Steps:**
1.  **Define Keypoints:** The user specifies keypoints $(x_{p,i}, y_{p,i})$ for $i=0 \dots K-1$. By default, these are linear ramps representing 1:1 mappings, where high intensity maps to high opacity and white color [S1, unofficial].
2.  **Compute Opacity:** Opacity is computed by passing the intensity $v$ through an intensity ramp and the gradient magnitude $g$ through a gradient ramp, then multiplying the results [S2, unofficial].
    $$ \alpha = \text{Ramp}_{\alpha}(v) \times \text{Ramp}_{\alpha}(g) $$
3.  **Compute Color:** Color components are computed by passing the intensity $v$ through separate red, green, and blue ramp functions [S2, unofficial].
    $$ r = \text{Ramp}_{r}(v), \quad g = \text{Ramp}_{g}(v), \quad b = \text{Ramp}_{b}(v) $$
4.  **Evaluate Ramp Function:** For a given input $x$ and keypoints $x_p, y_p$, the output $y$ is determined by finding the segment containing $x$ and linearly interpolating [S3, unofficial].
    *   Extrapolation beyond the first and last keypoints is handled by extending the first and last segments, respectively [S3, unofficial].

**Pseudocode:**
The following Python-like pseudocode implements the evaluation of a piecewise-linear channelwise transfer function for a batch of inputs [S3, unofficial].

```python
import torch

def piecewise_linear_channelwise(x: torch.Tensor, xp: torch.Tensor, yp: torch.Tensor) -> torch.Tensor:
    """
    Evaluate piecewise linear transfer functions channel-wise.
    
    Args:
        x: Input tensor of shape (B, C, H, W) or (B, C, D, H, W).
        xp: Tensor of shape (C, K) containing sorted x keypoints per channel.
        yp: Tensor of shape (C, K) containing y values per channel at keypoints.
        
    Returns:
        Output tensor of shape (B, C, H, W) or (B, C, D, H, W).
    """
    # 1. Reshape input to (B, C, N) where N is the product of spatial dimensions
    B, C, *spatial_dims = x.shape
    x_flat = x.view(B, C, -1)  # Shape: (B, C, N)
    
    # 2. Expand keypoints to match batch and spatial dimensions for broadcasting
    # xp, yp shape: (C, K) -> (B, C, K)
    xp = xp.unsqueeze(0).expand(B, -1, -1)
    yp = yp.unsqueeze(0).expand(B, -1, -1)
    
    # 3. Prepare x for segment comparison
    # x_unsq shape: (B, C, N, 1)
    x_unsq = x_flat.unsqueeze(-1)
    
    # 4. Create segment boundaries
    # xp_left shape: (B, C, 1, K-1)
    xp_left = xp.unsqueeze(2)[:, :, :, :-1]
    # xp_right shape: (B, C, 1, K-1)
    xp_right = xp.unsqueeze(2)[:, :, :, 1:]
    
    # 5. Create mask for segments where x_left <= x < x_right
    # mask shape: (B, C, N, K-1)
    mask = (x_unsq >= xp_left) & (x_unsq < xp_right)
    
    # 6. Handle cases where no segment is selected (x >= last keypoint)
    # none_selected shape: (B, C, N)
    none_selected = ~mask.any(dim=-1)
    
    # 7. Find segment index
    # idx shape: (B, C, N)
    idx = mask.float().argmax(dim=-1)
    
    # 8. Assign last segment index to unselected points
    if none_selected.any():
        idx[none_selected] = xp.shape[-1] - 2  # K - 2
        
    # 9. Gather left and right x and y values for interpolation
    # gather_idx shape: (B, C, N, 1)
    gather_idx = idx.unsqueeze(-1)
    
    # xp_l, xp_r shape: (B, C, N, 1)
    xp_l = torch.gather(xp, 2, gather_idx)
    xp_r = torch.gather(xp_right, 2, gather_idx) # Note: xp_right is already shifted, but gather needs correct indexing relative to xp
    # Correction: xp_right in step 4 was sliced. We need to gather from the original xp array using idx+1 for right side
    xp_r = torch.gather(xp, 2, gather_idx + 1)
    
    # yp_l, yp_r shape: (B, C, N, 1)
    yp_l = torch.gather(yp, 2, gather_idx)
    yp_r = torch.gather(yp, 2, gather_idx + 1)
    
    # 10. Linear interpolation
    # Avoid division by zero if xp_l == xp_r
    denom = xp_r - xp_l
    denom = torch.where(denom == 0, torch.ones_like(denom), denom)
    
    # t is the normalized position within the segment
    t = (x_unsq.squeeze(-1) - xp_l.squeeze(-1)) / denom
    
    # 11. Compute output
    y = yp_l.squeeze(-1) + t * (yp_r.squeeze(-1) - yp_l.squeeze(-1))
    
    # 12. Reshape back to original spatial dimensions
    y = y.view(B, C, *spatial_dims)
    
    return y
```

**Parameters:**
*   **Keypoints ($x_p, y_p$):** User-defined. The UI typically allows interactive control over the center, width, and height of each ramp segment [S2, unofficial].
*   **Default Classification:** Linear ramps representing 1:1 mappings. High intensity objects appear white and nearly opaque [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Shape Validation:** If $x_p$ and $y_p$ do not have shape $(C, K)$, a `ValueError` is raised [S3, unofficial].
*   **Local Ambiguity:** Local classification fails when the region of interest has similar intensity and gradient to its background. For example, in MRI data, anatomically distinct regions of the same organ may be indistinguishable using only local classification [S2, unofficial].
*   **Extrapolation:** Values outside the range of $x_p$ are extrapolated using the first or last segment [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot C \cdot K)$ per voxel, where $N$ is the number of samples, $C$ is the number of channels, and $K$ is the number of keypoints. In practice, $K$ is small, making it $O(N \cdot C)$.
*   **Memory Complexity:** $O(C \cdot K)$ to store the keypoints.
*   **Strengths:** Intuitive user interface; allows rapid switching between classifiers with a single keystroke to compare views [S2, unofficial]; computationally efficient for GPU implementation via texture lookup or simple interpolation [S1, unofficial].
*   **Limitations:** Cannot distinguish regions with similar local features (intensity/gradient) but different global context [S2, unofficial].
*   **When to use:** When the user needs to quickly visualize specific intensity ranges or gradients and the data has distinct local feature distributions.
*   **When not to use:** When the data contains regions with ambiguous local features that require global context or multi-dimensional classification beyond intensity and gradient [S2, unofficial].

## Background
Piecewise-linear classification was introduced as a standard method for volume visualization to allow users to define transfer functions interactively. It is often associated with early volume rendering systems that utilized 3D texture mapping for hardware acceleration [S1, unofficial]. The technique was formalized in systems like the one described in *Achieving Direct Volume Visualization with Interactive Semantic Region Selection* (1990), which highlighted the use of ramps for opacity and color mapping [S2, unofficial]. It remains a foundational technique in volume rendering, often implemented as a default or starting point for more complex classification methods.
