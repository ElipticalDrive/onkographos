# Semantic Rendering

Also called: Semantic Ray Compositing, Weighted Semantic Compositing

## Overview
Semantic Rendering maps discrete integer identifiers or semantic class labels to deterministic color vectors and opacity masks for volume visualization [G]. It solves the problem of visualizing categorical data by avoiding the "color bleeding" inherent in continuous transfer functions, ensuring that distinct semantic regions remain visually distinct [G]. Unlike [Semantic Transfer Function Design](9493-semantic-transfer-function-design.md) which operates on continuous scalar intensities, this method relies on exact matching against defined keys and nearest-neighbor interpolation to maintain label integrity [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume or scene representation containing discrete integer class labels (or logits/probabilities for probabilistic variants) at sample points $\mathbf{x}$.
*   **Output:** A 2D image where each pixel contains an RGB color tuple and an opacity value derived from the aggregated semantic information along the viewing ray.

**Data Structures:**
*   **Label Volume:** A 3D grid of integers or floats representing class IDs or probabilities.
*   **Lookup Table (LUT):** A mapping from integer class IDs to deterministic RGB tuples. If a class ID is unseen, a fallback NaN or transparent color is used [G].

**Steps:**
1.  **Ray Casting:** Cast a ray through the volume. Sample points $\mathbf{x}_i$ along the ray.
2.  **Interpolation:** Use nearest-neighbor interpolation to retrieve the label or probability value at each sample point $\mathbf{x}_i$ to prevent mixing distinct semantic classes [G].
3.  **Weight Calculation:** Compute transmittance weights $w_i$ for each sample based on opacity and depth, following standard volume rendering compositing rules.
4.  **Aggregation:**
    *   *Deterministic Variant:* Identify the dominant class label among samples with significant weight. Map this label to an RGB color via the LUT.
    *   *Probabilistic Variant (SDFStudio):* Compute semantic class probabilities by weighting per-sample class logits by transmittance weights.
5.  **Color Mapping:** Assign the final pixel color based on the aggregated semantic result.

**Formulas:**
For the probabilistic aggregation method described in [S1, unofficial]:
$$ \text{sem} = \sum_{i} w_i \cdot \text{logits}_i $$
Where $w_i$ are the transmittance weights and $\text{logits}_i$ are the class logits at sample $i$. The final color is derived from the resulting semantic vector.

**Pseudocode:**
```python
def semantic_render(ray_origin, ray_direction, volume_grid, lut, num_samples):
    """
    Renders a single ray using semantic classification.
    :param ray_origin: 3D vector, start of the ray
    :param ray_direction: 3D vector, direction of the ray
    :param volume_grid: 3D array of class labels or logits
    :param lut: Dictionary mapping class_id -> (r, g, b)
    :param num_samples: Integer, number of samples along the ray
    :return: (r, g, b, opacity) tuple
    """
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    transmittance = 1.0
    
    # Semantic aggregation buffer (for probabilistic variant)
    semantic_scores = {} # Map class_id -> score

    for i in range(num_samples):
        # Calculate sample position
        t = i / num_samples
        pos = ray_origin + t * ray_direction
        
        # Nearest-neighbor lookup to preserve label integrity [G]
        label = volume_grid.get_nearest_neighbor(pos)
        
        # Get color from LUT, fallback to transparent if unknown [G]
        if label in lut:
            color = lut[label]
            opacity = 1.0 # Deterministic: valid labels are opaque
        else:
            color = [0.0, 0.0, 0.0]
            opacity = 0.0
            
        # Standard volume rendering compositing
        weight = transmittance * opacity
        accumulated_color = [
            accumulated_color[j] + weight * color[j] for j in range(3)
        ]
        accumulated_opacity += weight
        transmittance *= (1.0 - opacity)
        
        # Early termination if fully opaque
        if accumulated_opacity > 0.99:
            break
            
    return accumulated_color, accumulated_opacity
```

**Parameters:**
*   **LUT:** Must be pre-computed. Hash-based HSV mapping is a common method for generating colors for arbitrary unseen IDs [G].
*   **Interpolation Mode:** Must be `nearest` for label volumes. `linear` or `trilinear` causes color bleeding [G].

**Edge Cases:**
*   **Unseen Labels:** If a label exists in the volume but not in the LUT, it must map to a transparent color or a specific "unknown" color to avoid rendering artifacts [G].
*   **Degenerate Input:** Empty volumes or rays that do not intersect the volume bounds should return transparent black.

## Subtopics

### Semantic-aware Weight Network
A network component that learns a view reweighting vector $w$ to rescore the significance of each source view for constructing the final semantic ray, ensuring semantic consistency [S2]. Unlike mean aggregation which ignores different significance of source views, this method uses learned weights $w$ to distinguish view importance, improving mIoU and total accuracy [S2].

*   **Definition:** Learns view importance weights $w_i$ for $m$ source views [S2].
*   **Formula:** The weights are constrained by:
    $$ w \in C(\tau) := \left\{ w : 0 < \frac{1}{m} - \frac{\tau}{m} < w_i < \frac{1}{m} + \frac{\tau}{m}, \sum_{i=1}^m w_i = 1 \right\} $$
    where $w$ is the view reweighting vector of length $m$, and $\tau$ is a hyperparameter controlling semantic awareness [S2].
*   **Parameters:** Hyperparameter $\tau$ controls semantic awareness. Typical values tested: 1, 0.8, 0.7, 0.5, 0.2. Best mIoU (57.15%) observed at $\tau=0.7$ [S2].
*   **Architecture:**
    *   Input 1: Initial 3D contextual space (dim 37, 16, 8, 1).
    *   Input 2: View direction differences.
    *   L1: Concat(Input 1, Input 2).
    *   L2: MLP(L1) with ELU activation.
    *   L3: Sigmoid(L2) [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of classes (for probabilistic aggregation). Lookup table access is $O(1)$.
*   **Memory Complexity:** Proportional to the volume size and the size of the LUT.
*   **Strengths:** Eliminates color bleeding between distinct categories; deterministic output for identical inputs; efficient for categorical data.
*   **Limitations:** Cannot represent gradual transitions between semantic classes; sensitive to label noise; requires accurate label segmentation or classification prior to rendering.
*   **When to use:** Visualization of segmented medical data, semantic maps in robotics, or any categorical volume data where class boundaries are sharp.
*   **When not to use:** Continuous scalar fields (e.g., temperature, density) where transfer functions are more appropriate.

## Background
Semantic rendering is a specialized form of volume rendering tailored for categorical data. It builds on [Semantic and Label-Based Classification](10722-semantic-and-label-based-classification.md) principles. The probabilistic aggregation variant was introduced in SDFStudio [S1, unofficial]. The Semantic-aware Weight Network variant was introduced in "Semantic Ray: Learning a Generalizable Semantic Field with Cross-Reprojection Attention" [S2].
