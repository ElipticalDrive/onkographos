# Label-Scoped Volume Rendering

Also called: Label-aware banding, bandLabeledHuValues, label-scoped volume

## Overview
Label-Scoped Volume Rendering is a technique for rendering labeled volumes using a single 1D VTK transfer function by packing label rows into distinct scalar bands, allowing per-class opacity scaling without multi-dimensional transfer functions [S1, unofficial]. It transforms raw Hounsfield Unit (HU) values into label-specific bands so that a single transfer function table can be partitioned per anatomical class [S1, unofficial]. Unlike general semantic classification which may use multi-dimensional functions or hash-based color generation for arbitrary IDs, this method relies on a fixed, large scalar offset (`LABEL_BAND`) to isolate classes within a 1D lookup, ensuring that the transfer function's opacity and color ramps apply strictly to their designated semantic region [S1, unofficial].

## How it works
The method operates in two phases: scalar banding (preprocessing the volume data) and transfer function application (configuring the renderer) [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   `values`: Array of raw HU values (float32) [S1, unofficial].
    *   `labels`: Array of integer class labels (int32), aligned with `values` [S1, unofficial].
    *   `CENTER_RANGE`: Array `[lo, hi]` defining the HU clamp bounds [S1, unofficial].
    *   `LABEL_BAND`: Constant scalar offset width (default 4096.0) [S1, unofficial].
    *   `tfTable`: Transfer function table containing opacity and RGB parameters per label row [S1, unofficial].
*   **Outputs:**
    *   `banded_array`: Float32 array where each voxel's value is shifted into its label's scalar band [S1, unofficial].
    *   VTK `ColorTransferFunction` and `PiecewiseFunction` instances configured with points mapped to the banded scalar space [S1, unofficial].

### Data Structures
*   **Masked Volume Cache:** An `OrderedDict` mapping the tuple `(id(volume), id(labels))` to a tuple `(volume_ref, labels_ref, banded_array)` [S1, unofficial]. This cache stores pre-computed banded volumes to avoid redundant computation [S1, unofficial]. It evicts the oldest entry when the cache size exceeds `MASKED_VOLUME_CACHE_SIZE` (default 8) [S1, unofficial].
*   **Transfer Function Parameters:** A structured array or object containing rows of opacity and RGB values for each label [S1, unofficial]. The length of the parameter array is expected to equal `TOTAL_PARAMS` [S1, unofficial].

### Algorithm Steps

#### Phase 1: Scalar Banding
1.  **Smoothing:** Apply Gaussian smoothing to the raw HU values before banding [S1, unofficial]. Use standard deviation $\sigma=1.0$ and radius $r=2.0$ [S1, unofficial]. This step is critical to prevent blending of label rows during subsequent rendering [S1, unofficial].
2.  **Clamping:** For each voxel index $i$, clamp the smoothed HU value $v_i$ to the `CENTER_RANGE` $[lo, hi]$:
    $$ v'_i = \max(lo, \min(hi, v_i)) $$
3.  **Banding:** Compute the banded scalar value $b_i$ by subtracting the lower bound and adding the label-specific offset:
    $$ b_i = v'_i - lo + (labels[i] \times LABEL\_BAND) $$
4.  **Storage:** Store $b_i$ in a `Float32Array` output [S1, unofficial]. The result is cast to float32 [S1, unofficial].

#### Phase 2: Transfer Function Application
1.  **Initialization:** Create instances of VTK `ColorTransferFunction` (`ctf`) and `PiecewiseFunction` (`otf`) [S1, unofficial].
2.  **Iteration:** Iterate over each label row $k$ in the transfer function table (where $k=0$ is unlabelled, $k \ge 1$ are canonical classes) [S1, unofficial].
3.  **Scale and Offset Calculation:**
    *   Calculate the scale factor $s_k$: $1.0$ if $k=0$ (unlabelled), otherwise the normalized opacity for class $k$ [S1, unofficial].
    *   Calculate the offset $o_k$: $k \times LABEL\_BAND - lo$ [S1, unofficial].
4.  **Point Addition:** For each HU sample $j$ in the `CENTER_RANGE`:
    *   Compute the banded scalar coordinate $x_{j,k}$:
        $$ x_{j,k} = hu[j] + o_k $$
    *   Add RGB point to `ctf`:
        $$ ctf.AddRGBPoint(x_{j,k}, r_{j,k}, g_{j,k}, b_{j,k}) $$
    *   Add opacity point to `otf`:
        $$ otf.AddPoint(x_{j,k}, \alpha_{j,k} \times s_k) $$
    *   Where $(r_{j,k}, g_{j,k}, b_{j,k})$ and $\alpha_{j,k}$ are the color and opacity parameters for sample $j$ of class $k$ [S1, unofficial].
5.  **Assignment:** Set the configured `ctf` and `otf` on the volume property [S1, unofficial].
6.  **Notification:** Notify transfer function listeners and trigger a render window update (unless in XR mode) [S1, unofficial].

### Pseudocode

```python
class ColorTransferFunction:
    """Mimics VTK ColorTransferFunction for self-contained implementation."""
    def __init__(self):
        self.points = []
    def addRGBPoint(self, x, r, g, b):
        self.points.append((x, r, g, b))

class PiecewiseFunction:
    """Mimics VTK PiecewiseFunction for self-contained implementation."""
    def __init__(self):
        self.points = []
    def addPoint(self, x, y):
        self.points.append((x, y))

def band_volume(values, labels, center_range, label_band):
    """
    Transforms raw HU values into label-specific scalar bands.
    
    Args:
        values: List[float] - Raw HU values (pre-smoothed).
        labels: List[int] - Integer class labels.
        center_range: List[float] - [lo, hi] clamp bounds.
        label_band: float - Width of the scalar band per label (e.g., 4096.0).
        
    Returns:
        List[float] - Banded scalar values.
    """
    lo, hi = center_range
    banded = [0.0] * len(values)
    
    for index in range(len(values)):
        # Clamp HU value to center range
        hu_clamped = max(lo, min(hi, values[index]))
        
        # Compute banded value: clamped_hu - lo + label * LABEL_BAND
        banded[index] = float(hu_clamped - lo + labels[index] * label_band)
        
    return banded

def configure_transfer_function(tf_table, center_range, label_band, has_labels):
    """
    Configures VTK ColorTransferFunction and PiecewiseFunction based on label bands.
    
    Args:
        tf_table: Object - Transfer function table with a `.rows` iterable.
                  Each row object has `.normalized_opacity` and `.samples`.
                  Each sample has `.hu`, `.rgb` (tuple/list), and `.alpha`.
        center_range: List[float] - [lo, hi].
        label_band: float - LABEL_BAND constant.
        has_labels: bool - Whether the volume contains label data.
        
    Returns:
        tuple: (ctf, otf) - Configured transfer function objects.
    """
    lo, hi = center_range
    
    ctf = ColorTransferFunction()
    otf = PiecewiseFunction()
    
    # Iterate over rows from tfTable.tfRows(params, activeLayers, hasLabels())
    for row_index, params in enumerate(tf_table.rows):
        # Calculate scale: 1.0 for row 0, otherwise normalized opacity for that class
        scale = 1.0 if row_index == 0 else params.normalized_opacity
        
        # Calculate offset: row * LABEL_BAND - lo
        offset = (row_index * label_band) - lo
        
        # Iterate over HU samples
        for sample in params.samples:
            hu_val = sample.hu
            rgb = sample.rgb
            alpha = sample.alpha
            
            # Compute banded scalar coordinate
            if has_labels:
                x = (row_index * label_band) + hu_val - lo
            else:
                x = hu_val
                
            # Add points to VTK functions
            ctf.addRGBPoint(x, rgb[0], rgb[1], rgb[2])
            otf.addPoint(x, alpha * scale)
            
    return ctf, otf
```

### Parameters
*   **LABEL_BAND:** The width of the scalar band assigned to each label row [S1, unofficial]. Must exceed the span of `CENTER_RANGE` (3050 HU) to prevent overlap between label rows [S1, unofficial]. Default value: 4096.0 [S1, unofficial].
*   **CENTER_RANGE:** The HU range $[lo, hi]$ used for clamping and defining the span within each label band [S1, unofficial]. Default span: 3050 HU (implied from source comments) [S1, unofficial].
*   **MASKED_VOLUME_CACHE_SIZE:** Maximum number of cached banded volumes [S1, unofficial]. Default: 8 [S1, unofficial].
*   **TOTAL_PARAMS:** Expected length of the transfer function parameter array [S1, unofficial].

### Edge Cases and Pitfalls
*   **Smoothing Order:** Smoothing must occur on raw HU values *before* banding [S1, unofficial]. Smoothing the banded scalar values would blend label rows into each other, causing semantic corruption [S1, unofficial].
*   **Interpolation:** Labelled volumes must use nearest-neighbor interpolation during ray casting [S1, unofficial]. Linear interpolation between two label bands lands in a third class's band, corrupting label semantics [S1, unofficial].
*   **XR Rendering:** In XR mode, calling `render()` immediately after setting transfer functions would ray-march into the bound XR framebuffer unnecessarily [S1, unofficial]. Rendering is deferred to the next frame loop [S1, unofficial].
*   **Band Overlap:** If `LABEL_BAND` is not sufficiently large (specifically, if it is less than the `CENTER_RANGE` span), label rows will overlap in the scalar space, causing incorrect color/opacity mapping [S1, unofficial].

## Subtopics

### Label-aware Transfer Function Application
This variant specifically refers to the configuration step where banded scalar values are mapped to VTK color and opacity transfer functions [S1, unofficial]. It partitions the transfer function table per label band, ensuring that the 1D lookup table correctly addresses the shifted scalar coordinates [S1, unofficial]. It is chosen when using VTK-based renderers with label-aware volumes [S1, unofficial]. It differs from general transfer function design by enforcing the `LABEL_BAND` offset logic during point addition [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Banding is $O(N)$ where $N$ is the number of voxels [S1, unofficial]. Transfer function configuration is $O(M \times S)$ where $M$ is the number of labels and $S$ is the number of samples per label [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for the banded volume array [S1, unofficial]. The cache adds $O(K \times N)$ where $K$ is the cache size (8) [S1, unofficial].
*   **Performance:** The method allows efficient 1D lookup during rendering, avoiding the overhead of multi-dimensional transfer functions [S1, unofficial]. However, it requires storing a separate banded volume if labels change [S1, unofficial].
*   **Strengths:** Simple implementation using standard 1D VTK transfer functions [S1, unofficial]. Avoids color bleeding between semantic regions if nearest-neighbor interpolation is used [S1, unofficial]. Supports per-class opacity scaling [S1, unofficial].
*   **Limitations:** Requires fixed `LABEL_BAND` size [S1, unofficial]. Not suitable for continuous scalar fields without labels [S1, unofficial]. Interpolation artifacts if nearest-neighbor is not enforced [S1, unofficial].
*   **When to use:** When rendering CT volumes with discrete semantic labels (e.g., TotalSegmentator) and using VTK-based rendering pipelines [S1, unofficial].
*   **When not to use:** When continuous scalar interpolation is required for semantic boundaries, or when labels are not available [S1, unofficial].

## Background
Developed within the `reinforcement-learning-volume-rendering-transfer-function` repository [S1, unofficial]. It was created to enable efficient policy evaluation and planning in VR/AR environments where rapid re-rendering of labeled anatomical structures was required [S1, unofficial]. The method leverages VTK's transfer function capabilities to map discrete labels to visual properties without the complexity of multi-dimensional transfer functions, facilitating the use of automated policy-based transfer function adjustment [S1, unofficial].
