# Self-Organizing Map Dimensional Reduction for Transfer Functions

Also called: Dimensional reduction for TF design, Kohonen's maps, Multi-dimensional Transfer Function Design using Self-Organizing Maps, SOM-based TF design, Self-Organizing Maps (SOM) for Transfer Function Design, Voxel Signature Mapping

## Overview
This method simplifies the design of multi-dimensional (nD) transfer functions by reducing the dimensionality of voxel signatures using Self-Organizing Maps (SOMs) [S1][S2, unofficial]. It maps nD voxel signatures to a 2D map space, allowing the user to define optical properties in the 2D space, which is then composed with the dimensional reduction function to form the actual nD transfer function [S1][S2, unofficial]. Unlike explicit nD TF definition, this method uses a simplified 2D interaction space via SOMs, making exploration and visualization of the TF domain easier as dimensionality increases [S1]. Compared to discrete classification schemes, this method is a non-discrete classification scheme (dimensional reduction) combined with TF design in an easily manageable 2D space [S2, unofficial].

## How it works
**Inputs:**
*   Volume data $V$ with dimensions $D_x \times D_y \times D_z$.
*   Voxel signature attributes: A set of $n$ attributes per voxel, such as scalar value, gradient magnitude, directional second derivative, or statistical measures (mean, standard deviation, cubic root of third-order moment) from a subvolume centered at the voxel [S1][S2, unofficial].
*   Attribute weights: Weights defining the importance of each vector element in the distance metric [S1].
*   SOM parameters: Map topology (Kohonen grid or Spherical), map size (e.g., $32 \times 32$ cells), learning rate $\eta$, and number of training steps [S1].

**Outputs:**
*   A 2D map of coordinates for each voxel.
*   A transfer function defined in the 2D map space (opacity and color functions).
*   Rendered volume visualization [S1].

**Data Structures:**
*   **Voxel Signature Vector ($\vec{T}$):** An $n$-dimensional vector representing the attributes of a voxel. Elements are normalized [S1][S2, unofficial].
*   **SOM Grid:** A 2D grid of cells $C_i$. Each cell $C_i$ contains an $n$-dimensional weight vector $\vec{W}(C_i)$ [S2, unofficial].
*   **Topological Distance ($td$):** For Kohonen maps, the Euclidean distance between integer 2D coordinates of two cells. For spherical maps, the number of edges in the shortest path connecting two cells [S1].

**Steps:**

1.  **Preprocessing and Signature Extraction:**
    *   Extract complex voxel signatures from volume data. For noisy scalar data, use statistical measures from a small subvolume centered at the voxel [S1].
    *   Normalize the signature vectors [S1].
    *   Define weights for each attribute. Suggested weights: 1.3 for mean, 1.0 for standard deviation, 0.7 for cubic root of third-order moment; 1.0 for scalar, 1.0 for first derivative, 0.7 for second derivative [S1].

2.  **Background Removal (Optional):**
    *   Identify background voxels (e.g., air in CT/MRI) in the most exterior regions [S1][S2, unofficial].
    *   Use a simple region growing technique with these exterior voxels as seeds to remove them from the training set to prevent them from dominating the map due to high occurrence [S1][S2, unofficial].

3.  **SOM Initialization:**
    *   Initialize the SOM weight vectors $\vec{W}(C_i)$ with random values between zero and one. The weight vectors must have the same dimension as the input data [S1][S2, unofficial].
    *   Set map size: At least $20 \times 20$ cells for Kohonen maps; typical implementation uses $32 \times 32$ cells [S1]. For spherical maps, at least seven subdivisions by icosahedron edge; typical implementation uses ten subdivisions [S1].

4.  **SOM Training Stage 1 (Global Structure):**
    *   Set learning rate $\eta = 0.3$ [S1].
    *   Present non-background voxel signatures as training cases in random order until convergence. Each training case is often presented more than once [S1][S2, unofficial].
    *   For each training case $\vec{T}$:
        *   Find the Best Matching Unit (BMU), which is the cell $C_i$ with the minimum weighted Euclidean distance to $\vec{T}$ [S1][S2, unofficial].
        *   Update weight $\vec{W}_{t+1}(C_i)$ for the BMU and its neighborhood using the Gaussian neighborhood function $nf1$ [S1][S2, unofficial]:
            $$nf1(td) = \exp\left(-\frac{td^2}{3}\right)$$
        *   Calculate interpolation coefficient $a = \eta \times nf1(td(BMU, C_i))$ [S1][S2, unofficial].
        *   Update weights:
            $$\vec{W}_{t+1}(C_i) = (1-a) \times \vec{W}_t(C_i) + a \times \vec{T}$$
        *   [S1] Typical steps: 3,000,000 steps for $32 \times 32$ map [S1].

5.  **SOM Training Stage 2 (Refinement):**
    *   Set learning rate $\eta = 0.5$ [S1].
    *   Continue training with the same random order of signatures [S1][S2, unofficial].
    *   For each training case $\vec{T}$:
        *   Find the BMU [S1][S2, unofficial].
        *   Update weights using the modified neighborhood function $nf2$ [S1][S2, unofficial]:
            $$nf2(td, d) = \min(d, 1) \times \exp\left(-\frac{td^2}{3}\right)$$
            where $d$ is the distance between the training case and the winner cell's weight vector [S1][S2, unofficial].
        *   Calculate $a = \eta \times nf2(td(BMU, C_i), d)$ [S1][S2, unofficial].
        *   Update weights:
            $$\vec{W}_{t+1}(C_i) = (1-a) \times \vec{W}_t(C_i) + a \times \vec{T}$$
        *   This modified function allows signatures far from their winner cell to have more influence, preventing large homogeneous regions from dominating the map [S1][S2, unofficial].
        *   [S1] Typical steps: 4,500,000 steps for $32 \times 32$ map [S1].

6.  **Dimensional Reduction:**
    *   Map all voxels (including background) to the 2D map space [S1].
    *   For each voxel, find its BMU in the trained SOM.
    *   Assign the coordinates of the BMU in the SOM grid to the voxel. This replaces the nD signature with 2D map coordinates [S1][S2, unofficial].
    *   [S1] Time for this step is proportional to the number of non-background voxels, map size, and weight vector size [S1].

7.  **Transfer Function Design in 2D Space:**
    *   The user specifies the transfer function (optical properties like color and opacity) by interacting in the 2D map space [S1].
    *   This is described as using dual domain interaction [S1].
    *   Automatic color transfer functions can be generated by assigning different colors to different regions of the SOM map, which correspond to voxels with considerably different attribute values [S1].
    *   Allow user interaction by moving Gaussian opacity functions on the map space to tune parameters and build meaningful visualizations [S1].

8.  **Rendering:**
    *   The actual multidimensional transfer function is the composition of the dimensional reduction function (mapping nD signature to 2D map coordinates) and the 2D transfer function (mapping 2D map coordinates to optical properties) [S1].
    *   Evaluate Radial Basis Functions (RBF) for each non-background voxel to determine the transfer function response. This is solved using the Lapack library [S1].
    *   Render the volume using OpenGL and Cg. Use hardware interpolation for map coordinates and precomputed normals by default. Allow user selection of color/opacity interpolation and on-the-fly normal computation for high-quality rendering [S1].
    *   [G] Precomputed normals cannot be used for multivariate data sets (e.g., Hurricane) because the attributes lack a clear physical meaning for normal orientation [S1].

**Pseudocode:**

```python
import math
import random

def weighted_euclidean_distance(vec1, vec2, weights):
    """Calculate weighted Euclidean distance between two vectors."""
    dist_sq = 0.0
    for i in range(len(vec1)):
        diff = (vec1[i] - vec2[i]) * weights[i]
        dist_sq += diff * diff
    return math.sqrt(dist_sq)

def gaussian_neighborhood(topological_dist):
    """Gaussian neighborhood function nf1."""
    return math.exp(-(topological_dist ** 2) / 3.0)

def modified_neighborhood(topological_dist, data_dist):
    """Modified neighborhood function nf2."""
    return min(data_dist, 1.0) * math.exp(-(topological_dist ** 2) / 3.0)

def train_som(signatures, map_width, map_height, weights, steps_stage1, steps_stage2):
    """
    Train SOM using two stages.
    signatures: list of nD vectors (non-background voxels)
    map_width, map_height: dimensions of the 2D grid
    weights: list of weights for each dimension of the signature
    steps_stage1: number of steps for stage 1
    steps_stage2: number of steps for stage 2
    """
    n_dims = len(signatures[0])
    num_cells = map_width * map_height
    
    # Initialize weight vectors with random values between 0 and 1
    weights_map = [[random.random() for _ in range(n_dims)] for _ in range(num_cells)]
    
    # Stage 1: Global Structure
    eta = 0.3
    for _ in range(steps_stage1):
        # Present training cases in random order
        random.shuffle(signatures)
        for sig in signatures:
            # Find BMU
            min_dist = float('inf')
            bmu_idx = -1
            for i in range(num_cells):
                # Calculate topological distance (Euclidean distance in 2D grid)
                row_i, col_i = divmod(i, map_width)
                # We need the row/col of the BMU, but we don't know it yet.
                # First, find BMU based on data distance only for selection?
                # No, BMU is based on data distance. Topological distance is for update.
                
                # Calculate data distance
                dist = weighted_euclidean_distance(weights_map[i], sig, weights)
                if dist < min_dist:
                    min_dist = dist
                    bmu_idx = i
            
            bmu_row, bmu_col = divmod(bmu_idx, map_width)
            
            # Update weights for BMU and neighborhood
            for i in range(num_cells):
                row_i, col_i = divmod(i, map_width)
                td = math.sqrt((row_i - bmu_row)**2 + (col_i - bmu_col)**2)
                
                nf = gaussian_neighborhood(td)
                a = eta * nf
                
                # Interpolate
                for d in range(n_dims):
                    weights_map[i][d] = (1 - a) * weights_map[i][d] + a * sig[d]

    # Stage 2: Refinement
    eta = 0.5
    for _ in range(steps_stage2):
        random.shuffle(signatures)
        for sig in signatures:
            # Find BMU
            min_dist = float('inf')
            bmu_idx = -1
            for i in range(num_cells):
                dist = weighted_euclidean_distance(weights_map[i], sig, weights)
                if dist < min_dist:
                    min_dist = dist
                    bmu_idx = i
            
            bmu_row, bmu_col = divmod(bmu_idx, map_width)
            
            # Update weights for BMU and neighborhood
            for i in range(num_cells):
                row_i, col_i = divmod(i, map_width)
                td = math.sqrt((row_i - bmu_row)**2 + (col_i - bmu_col)**2)
                
                nf = modified_neighborhood(td, min_dist)
                a = eta * nf
                
                # Interpolate
                for d in range(n_dims):
                    weights_map[i][d] = (1 - a) * weights_map[i][d] + a * sig[d]
                    
    return weights_map, map_width, map_height

def dimensional_reduction(signatures, weights_map, map_width, map_height, weights):
    """
    Map all voxels to 2D map space.
    signatures: list of nD vectors (all voxels)
    weights_map: trained weight vectors
    map_width, map_height: dimensions of the 2D grid
    weights: list of weights for each dimension of the signature
    """
    n_dims = len(signatures[0])
    num_cells = map_width * map_height
    map_coords = []
    
    for sig in signatures:
        # Find BMU
        min_dist = float('inf')
        bmu_idx = -1
        for i in range(num_cells):
            dist = weighted_euclidean_distance(weights_map[i], sig, weights)
            if dist < min_dist:
                min_dist = dist
                bmu_idx = i
        
        # Assign 2D coordinates
        row, col = divmod(bmu_idx, map_width)
        map_coords.append((row, col))
        
    return map_coords
```

## Subtopics

### Multi-dimensional Transfer Function Design using Dimensional Reduction
A method for specifying multi-dimensional (nD) transfer functions by reducing the dimensionality of nD voxel signatures into a 2D map using Self-Organizing Maps (SOMs) and Radial Basis Functions (RBFs), allowing TF design in a simplified 2D space [S2, unofficial]. It explores two types of SOMs: Kohonen maps and spherical self-organizing maps [S2, unofficial]. Unlike 1D TFs which only use scalar values, this nD TF approach uses multi-dimensional voxel signatures (including gradient, curvature, etc.) to distinguish volume regions that have the same scalar value range [S2, unofficial].

## Operating characteristics
**Time Complexity:**
*   Training time is quadratically related to map size (number of cells) and proportional to weight vector size [S1].
*   Winner search is linear in number of cells [S1].
*   Weight vector size has linear influence on winner search and update time [S1].
*   Dimensional reduction time is proportional to the number of non-background voxels, map size, and size of weight vectors [S1].
*   RBF evaluation time is proportional to the number of cells and the size of weight vectors [S1].

**Measured Performance:**
*   Training time for $32 \times 32$ Kohonen map: 57 seconds for 3,000,000 steps (Neigh. func 1) and 87 seconds for 4,500,000 steps (Neigh. func 2) [S1].
*   Training time for Spherical map (10 subdivisions): 151 seconds for 3,000,000 steps (Neigh. func 1) and 264 seconds for 5,250,000 steps (Neigh. func 2) [S1].
*   Dimensional reduction time for Engine dataset ($256 \times 2 \times 128$, 5,297,265 non-bg voxels): 140 seconds [S1].
*   Dimensional reduction time for Tooth dataset ($128 \times 2 \times 256$, 4,193,888 non-bg voxels): 110 seconds [S1].
*   Dimensional reduction time for Foot dataset ($256^3$, 4,890,753 non-bg voxels): 133 seconds [S1].
*   Dimensional reduction time for Carp dataset ($256 \times 2 \times 512$, 32,806,605 non-bg voxels): 845 seconds [S1].
*   Dimensional reduction time for Hurricane dataset ($256 \times 2 \times 128$, 8,388,608 non-bg voxels): 220 seconds [S1].
*   Dimensional reduction time for Sheep heart dataset ($256^3$, 16,776,721 non-bg voxels): 375 seconds [S1].
*   Spherical map dimensional reduction time is approximately 13% greater than Kohonen map time [S1].
*   Hardware: AMD Athlon 64 3700+, 2.21GHz CPU and 2GB of RAM [S1].

**Strengths and Limitations:**
*   **Strengths:** Simplicity and flexibility. Allows building multidimensional transfer functions through the exploration of a simplified (reduced) space where traditional interaction techniques can be employed. Self-organizing maps group similar voxel signatures, helping to understand data distribution. Automatically generated color TFs can emphasize details hard to visualize with other approaches. Exploring 2D maps is easier and faster than navigating a class hierarchy [S1].
*   **Limitations:** Dimensional reduction causes loss and distortion of information, making accurate quantitative analysis impossible. The method is suitable only for qualitative aspects like shape and dissimilarity [S1]. Precomputed normals cannot be used for multivariate data sets because the attributes lack a clear physical meaning for normal orientation [S1].

**When to Use:**
*   When designing multi-dimensional transfer functions is difficult due to high dimensionality.
*   When qualitative visualization of shape and dissimilarity is more important than quantitative accuracy.
*   When automatic color generation is desired to emphasize details.

**When Not to Use:**
*   When accurate quantitative analysis of the volume data is required during TF specification.
*   When multivariate data sets require precomputed normals for shading.

## Background
This method was proposed in a paper by [S1] and further detailed in a thesis by [S2, unofficial]. It builds on the concept of Self-Organizing Maps (SOMs) introduced by Kohonen [KOH 97] and spherical self-organizing maps [SAN 2002]. The method addresses the challenge of designing multi-dimensional transfer functions, which is difficult due to the high dimensionality of the interaction space. It uses unsupervised learning to group similar voxel signatures and reduce them to a 2D space for easier user interaction [S1][S2, unofficial].
