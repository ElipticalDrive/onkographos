# Self-Organizing Map Dimensional Reduction for Transfer Functions

Also called: Dimensional reduction for TF design, Kohonen's maps, Multi-dimensional Transfer Function Design using Self-Organizing Maps, SOM-based TF design, Self-Organizing Maps (SOM) for Transfer Function Design, Voxel Signature Mapping

## Overview
This method simplifies the design of multi-dimensional (nD) transfer functions by reducing the dimensionality of voxel signatures using Self-Organizing Maps (SOMs) [S1][S2, unofficial]. It maps nD voxel signatures to a 2D map space, allowing the user to define optical properties in the 2D space, which is then composed with the dimensional reduction function to form the actual nD transfer function [S1]. Unlike explicit nD TF definition, this method uses a simplified 2D interaction space via SOMs, making exploration and visualization of the TF domain easier as dimensionality increases [S1]. It performs non-discrete classification, which can represent uncertainty, unlike volume segmentation techniques [S1].

## How it works
**Inputs:** Volume data (scalar or multivariate); optional user-defined weights for signature attributes.
**Outputs:** A multidimensional transfer function defined by the composition of a dimensional reduction function (mapping nD signatures to 2D map coordinates) and a 2D transfer function (mapping 2D map coordinates to optical properties) [S1].

**Data Structures:**
*   **Voxel Signature:** An nD vector $\vec{T}$ containing normalized attributes (e.g., scalar value, gradient magnitude, directional second derivative, statistical measures like mean, standard deviation, cubic root of third-order moment) [S1][S2, unofficial].
*   **SOM Grid:** A 2D grid of cells $C_i$. Each cell $C_i$ contains an nD weight vector $\vec{W}(C_i)$ [S2, unofficial].
*   **Topological Distance ($td$):** For Kohonen maps, the Euclidean distance between integer 2D coordinates of two cells. For spherical maps, the number of edges in the shortest path connecting two cells [S1].

**Parameters:**
*   **Learning Rate ($\eta$):** Constant between 0 and 1. Typical values: $\eta=0.3$ for Stage 1, $\eta=0.5$ for Stage 2 [S1].
*   **Map Size:** Kohonen maps: at least $20 \times 20$ cells (typical $32 \times 32$). Spherical maps: at least 7 subdivisions by icosahedron edge (typical 10) [S1].
*   **Attribute Weights:** Define importance of vector elements. Typical weights for statistical variables (mean, std dev, cubic root 3rd moment): 1.3, 1.0, 0.7. For scalar and first/second derivatives: 1.0, 1.0, 0.7. For Hurricane dataset (wind speed, pressure, temperature): 1.0, 1.0, 0.5 [S1].

**Algorithm Steps:**

1.  **Preprocessing:** Extract complex voxel signatures from volume data and normalize them. Each voxel becomes an nD signature vector $\vec{T}$ [S1][S2, unofficial].
2.  **Background Removal (Optional):** Identify background voxels (e.g., air in CT/MRI) in the most exterior regions. Use a simple region growing technique with these exterior voxels as seeds to remove them from the training set to prevent them from dominating the map due to high occurrence [S1][S2, unofficial].
3.  **SOM Initialization:** Initialize the weight vectors $\vec{W}(C_i)$ of the SOM cells with random values between zero and one. The weight vectors must have the same dimension as the input data [S1][S2, unofficial].
4.  **SOM Training Stage 1 (Global Structure):** Present non-background voxel signatures as training cases in random order. Use a Gaussian neighborhood function $nf1$ to update weights. This stage defines the overall aspect of the map [S1].
    *   **Winner Selection:** For each training case $\vec{T}$, find the Best Matching Unit (BMU), which is the cell $C_i$ with the minimum weighted Euclidean distance to $\vec{T}$ [S1][S2, unofficial].
    *   **Weight Update:** Update weight $\vec{W}_{t+1}(C_i)$ for the BMU and its neighborhood.
        $$ \vec{W}_{t+1}(C_i) = (1-a) \times \vec{W}_t(C_i) + a \times \vec{T} $$
        $$ a = \eta \times nf1(td) $$
        $$ nf1(td) = \exp\left(-\frac{td^2}{3}\right) $$
        where $td$ is the topological distance between the winner cell and the cell in focus [S1][S2, unofficial].
5.  **SOM Training Stage 2 (Refinement):** Continue training with the same random order of signatures. Use a modified neighborhood function $nf2$ that depends on both topological distance ($td$) and the data distance ($d$) between the training case and the winner cell's weight vector. This allows signatures far from their winner cell to have more influence, preventing large homogeneous regions from dominating the map [S1][S2, unofficial].
    *   **Weight Update:**
        $$ nf2(td, d) = \min(d, 1) \times \exp\left(-\frac{td^2}{3}\right) $$
        where $d$ is the distance between the training case and the winner cell's weight vector [S1][S2, unofficial].
6.  **Dimensional Reduction:** After training, map all voxels (including background) to the 2D map space. Each voxel is assigned the coordinates of its Best Matching Unit (BMU) in the SOM grid. This replaces the nD signature with 2D map coordinates [S1].
7.  **TF Design in 2D Space:** The user specifies the transfer function (optical properties like color and opacity) by interacting in the 2D map space. This is described as using dual domain interaction [S1].
8.  **Rendering:** The actual multidimensional transfer function is the composition of the dimensional reduction function (mapping nD signature to 2D map coordinates) and the 2D transfer function (mapping 2D map coordinates to optical properties) [S1].

**Pseudocode:**

```python
import math
import random

def weighted_euclidean_distance(v1, v2, weights):
    """Calculate weighted Euclidean distance between two vectors."""
    dist_sq = 0.0
    for i in range(len(v1)):
        diff = (v1[i] - v2[i]) * weights[i]
        dist_sq += diff * diff
    return math.sqrt(dist_sq)

def topological_distance_kohonen(pos1, pos2):
    """Calculate topological distance for Kohonen map (2D grid)."""
    return math.sqrt((pos1[0] - pos2[0])**2 + (pos1[1] - pos2[1])**2)

def train_som(signatures, map_width, map_height, eta_stage1, eta_stage2, steps_stage1, steps_stage2, attr_weights):
    """
    Train SOM on signatures.
    signatures: list of nD vectors (training cases)
    map_width, map_height: dimensions of the 2D grid
    eta_stage1, eta_stage2: learning rates for stage 1 and 2
    steps_stage1, steps_stage2: number of training steps for each stage
    attr_weights: weights for each dimension of the signature
    """
    # Initialize weights
    num_cells = map_width * map_height
    dim = len(signatures[0])
    weights = [[random.random() for _ in range(dim)] for _ in range(num_cells)]
    cell_positions = [(x, y) for y in range(map_height) for x in range(map_width)]

    # Stage 1: Global Structure
    for _ in range(steps_stage1):
        t = random.choice(signatures)
        # Find BMU
        min_dist = float('inf')
        bmu_idx = 0
        for i in range(num_cells):
            d = weighted_euclidean_distance(t, weights[i], attr_weights)
            if d < min_dist:
                min_dist = d
                bmu_idx = i
        
        bmu_pos = cell_positions[bmu_idx]
        
        # Update weights
        for i in range(num_cells):
            td = topological_distance_kohonen(bmu_pos, cell_positions[i])
            nf = math.exp(-(td**2) / 3.0)
            a = eta_stage1 * nf
            for j in range(dim):
                weights[i][j] = (1 - a) * weights[i][j] + a * t[j]

    # Stage 2: Refinement
    for _ in range(steps_stage2):
        t = random.choice(signatures)
        # Find BMU
        min_dist = float('inf')
        bmu_idx = 0
        for i in range(num_cells):
            d = weighted_euclidean_distance(t, weights[i], attr_weights)
            if d < min_dist:
                min_dist = d
                bmu_idx = i
        
        bmu_pos = cell_positions[bmu_idx]
        
        # Update weights
        for i in range(num_cells):
            td = topological_distance_kohonen(bmu_pos, cell_positions[i])
            nf = min(min_dist, 1.0) * math.exp(-(td**2) / 3.0)
            a = eta_stage2 * nf
            for j in range(dim):
                weights[i][j] = (1 - a) * weights[i][j] + a * t[j]

    return weights, cell_positions

def dimensional_reduction(signatures, weights, cell_positions, attr_weights):
    """
    Map signatures to 2D map coordinates.
    Returns list of 2D coordinates for each signature.
    """
    num_cells = len(weights)
    map_coords = []
    
    for t in signatures:
        min_dist = float('inf')
        bmu_idx = 0
        for i in range(num_cells):
            d = weighted_euclidean_distance(t, weights[i], attr_weights)
            if d < min_dist:
                min_dist = d
                bmu_idx = i
        map_coords.append(cell_positions[bmu_idx])
        
    return map_coords
```

## Subtopics

### Multi-dimensional Transfer Function Design using Dimensional Reduction
A method for specifying multi-dimensional (nD) transfer functions by reducing the dimensionality of nD voxel signatures into a 2D map using Self-Organizing Maps (SOMs) and Radial Basis Functions (RBFs), allowing TF design in a simplified 2D space [S2, unofficial]. It explores two types of SOMs: Kohonen maps and spherical self-organizing maps [S2, unofficial]. Unlike 1D TFs which only use scalar values, this nD TF approach uses multi-dimensional voxel signatures (including gradient, curvature, etc.) to distinguish volume regions that have the same scalar value range [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   Training time is quadratically related to map size (number of cells) and proportional to weight vector size [S1].
*   Winner search is linear in the number of cells [S1].
*   Weight vector size has linear influence on winner search and update time [S1].
*   Dimensional reduction time is proportional to the number of non-background voxels, map size, and weight vector size [S1].
*   RBF evaluation time is proportional to the number of cells and the size of weight vectors [S1].

**Measured Performance:**
*   Training time for $32 \times 32$ Kohonen map: 57 seconds for 3,000,000 steps (Neigh. func 1) and 87 seconds for 4,500,000 steps (Neigh. func 2) [S1].
*   Training time for Spherical map (10 subdivisions): 151 seconds for 3,000,000 steps (Neigh. func 1) and 264 seconds for 5,250,000 steps (Neigh. func 2) [S1].
*   Dimensional reduction time for Engine dataset (256x2x128, 5,297,265 non-bg voxels): 140 seconds [S1].
*   Dimensional reduction time for Tooth dataset (128x2x256, 4,193,888 non-bg voxels): 110 seconds [S1].
*   Dimensional reduction time for Foot dataset (256^3, 4,890,753 non-bg voxels): 133 seconds [S1].
*   Dimensional reduction time for Carp dataset (256x2x512, 32,806,605 non-bg voxels): 845 seconds [S1].
*   Dimensional reduction time for Hurricane dataset (256x2x128, 8,388,608 non-bg voxels): 220 seconds [S1].
*   Dimensional reduction time for Sheep heart dataset (256^3, 16,776,721 non-bg voxels): 375 seconds [S1].
*   Spherical map dimensional reduction time is approximately 13% greater than Kohonen map time [S1].

**Strengths and Limitations:**
*   **Strengths:** Simplifies nD TF design by reducing it to a 2D interaction space. Allows uniform treatment of volume data with arbitrary dimension signatures. Non-discrete classification represents uncertainty. Automatic color TFs can emphasize details hard to visualize with other approaches [S1].
*   **Limitations:** Dimensional reduction causes loss and distortion of information, making accurate quantitative analysis impossible. Suitable only for qualitative aspects like shape and dissimilarity [S1]. Precomputed normals cannot be used for multivariate data sets (e.g., Hurricane) because attributes lack clear physical meaning for normal orientation [S1].

**When to use:**
*   When designing multi-dimensional transfer functions is too difficult due to high dimensionality.
*   When qualitative visualization of structures and dissimilarity is the goal.
*   When non-discrete classification is preferred over segmentation [S1].

**When not to use:**
*   When accurate quantitative analysis is required [S1].
*   When precomputed normals are essential and data is multivariate [S1].

## Background
This method was proposed to address the difficulty of designing multi-dimensional transfer functions, which becomes unintuitive as the domain increases [S1]. It builds on the concept of Self-Organizing Maps (SOMs) for dimensional reduction [S1][S2, unofficial]. The approach was implemented using OpenGL, Cg, GLUT, GLUI, and Lapack library [S1]. It is used in a visualization framework that uses graphics hardware to provide interactive volume rendering, with a user interface based on dual domain interaction [S1].
