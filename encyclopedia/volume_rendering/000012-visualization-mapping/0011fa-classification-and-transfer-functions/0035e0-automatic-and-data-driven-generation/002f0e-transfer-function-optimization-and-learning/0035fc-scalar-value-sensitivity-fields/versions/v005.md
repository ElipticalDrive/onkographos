# Scalar Value Sensitivity Fields

Also called: SVSF

## Overview
Scalar Value Sensitivity Fields (SVSF) are visualization techniques that represent the sensitivity of a volume-rendered image to modifications in the opacity transfer function (TF) at specific scalar values [S1]. They solve the problem of understanding how local edits to the TF domain impact specific regions of the resulting image, allowing users to predict which volume parts will change density or appearance before applying an edit [S1]. Unlike Region Sensitivity Plots, which show TF sensitivity conditioned on image regions, SVSF shows image sensitivity conditioned on scalar values in the TF domain [S1].

## How it works
**Inputs:**
*   A volume rendering pipeline capable of differentiable rendering (typically via backpropagation) [S1].
*   An opacity transfer function $T(v)$ mapping scalar values $v \in [0, 255]$ to opacity $\alpha$ [S1].
*   A grid resolution parameter $r$ [S1].

**Outputs:**
*   A 3-tensor $\Sigma \in \mathbb{R}^{256 \times r \times r}$, where $\Sigma(i, \cdot, \cdot)$ is the sensitivity field for the scalar value at index $i$ [S1].

**Data Structures:**
*   $\Sigma$: A 3-dimensional tensor. The first dimension corresponds to the 256 discrete scalar values of the TF. The last two dimensions correspond to the $r \times r$ grid blocks of the image domain [S1].

**Steps:**
1.  **Grid Definition:** Define a grid resolution $r$ and divide the rendered image into $r \times r$ non-overlapping blocks [S1].
2.  **Sensitivity Computation:** For each scalar value index $i \in [0, 255]$ and each block $(u, v)$ in the grid, compute the TF sensitivity using Equation 11 from the source [S1]. This involves calculating the gradient of the rendered image intensity with respect to the opacity value at index $i$ [S1].
3.  **Tensor Assembly:** Store the computed sensitivity for block $(u, v)$ and scalar value $i$ into $\Sigma(i, u, v)$ [S1].
4.  **Acceleration:** Perform the backpropagation required for sensitivity calculation in parallel on the GPU using minibatches of size 64 to reduce latency [S1].
5.  **Visualization (Filtering):** To visualize the impact of a user-selected scalar value $v_{sel}$, apply a Gaussian filter to the sequence of fields $\Sigma$ centered at $v_{sel}$ with a specified bandwidth [S1]. The filter weight for each field is superimposed on the sensitivity plot [S1].
6.  **Visualization (Coloring):** Color-map the sensitivity based on the global range of the field to provide context, and encode the range specific to the user's selection via opacity mapping [S1].

**Formulas:**
*   Sensitivity for block $(u,v)$ at scalar index $i$:
    $$ \Sigma(i, u, v) = \text{Sensitivity}_{\text{Eq.11}}(\text{Block}_{u,v}, i) $$
    Where $\text{Sensitivity}_{\text{Eq.11}}$ refers to the gradient-based sensitivity metric defined in the source paper [S1]. The exact mathematical form of Equation 11 is not provided in the notes, but it represents the derivative of the image pixel values with respect to the opacity TF value at index $i$ [S1].

**Parameters:**
*   $r$: Grid resolution. Typical values are 8 or 16 to balance latency and detail [S1].
*   Minibatch size: 64 for GPU parallelization [S1].
*   Gaussian bandwidth: Not specified in the notes [S1].

**Edge Cases and Pitfalls:**
*   Setting $r=256$ (pixel-level sensitivity) is prohibitively costly because it requires performing backpropagation $256^2$ times [S1].
*   The sensitivity field is relative; small absolute changes in the TF may result in small sensitivity values relative to the global sensitivity, requiring careful opacity encoding for visibility [S1].

**Pseudocode:**

def compute_scalar_value_sensitivity_fields(render_pipeline, tf_opacity, grid_resolution_r):
    """
    Computes the Scalar Value Sensitivity Field tensor.
    
    Args:
        render_pipeline: A differentiable volume rendering function.
        tf_opacity: Array of 256 opacity values.
        grid_resolution_r: Integer, the resolution of the output grid (e.g., 8 or 16).
        
    Returns:
        sigma: Tensor of shape (256, r, r).
    """
    # Get image dimensions
    img_h, img_w = render_pipeline.get_image_dimensions()
    
    # Initialize the 3-tensor Sigma: (256 scalar values, r x r blocks)
    sigma = zeros((256, grid_resolution_r, grid_resolution_r))
    
    # Calculate block dimensions
    block_h = img_h // grid_resolution_r
    block_w = img_w // grid_resolution_r
    
    # Pre-calculate block indices for efficiency
    # Map each pixel (y, x) to its block (u, v)
    # This is done implicitly by averaging gradients over blocks
    
    # Parallel backpropagation over scalar values
    # The source specifies using minibatches of size 64 on GPU
    batch_size = 64
    num_scalar_values = 256
    
    for batch_start in range(0, num_scalar_values, batch_size):
        batch_end = min(batch_start + batch_size, num_scalar_values)
        current_batch_indices = range(batch_start, batch_end)
        
        # For each scalar value in the batch, compute sensitivity
        for i in current_batch_indices:
            # Create a modified TF with a perturbation at index i
            # The exact perturbation magnitude is not specified in notes [G]
            # Typically, sensitivity is d(Image) / d(TF[i])
            
            # Compute gradient of rendered image w.r.t opacity at index i
            # This requires backpropagation through the render pipeline
            # Assuming render_pipeline returns image and allows gradient computation
            gradients = render_pipeline.compute_gradient(tf_opacity, target_scalar_index=i)
            
            # gradients is an image-sized array (H, W)
            # Aggregate gradients into r x r blocks
            for u in range(grid_resolution_r):
                for v in range(grid_resolution_r):
                    y_start = u * block_h
                    y_end = (u + 1) * block_h
                    x_start = v * block_w
                    x_end = (v + 1) * block_w
                    
                    # Extract block gradients
                    block_grads = gradients[y_start:y_end, x_start:x_end]
                    
                    # Compute sensitivity metric for the block
                    # Equation 11 is referenced but not defined in notes [G]
                    # Common metric is mean or L2 norm of gradients in the block
                    sensitivity_value = mean(block_grads) 
                    
                    sigma[i, u, v] = sensitivity_value

    return sigma

## Operating characteristics
*   **Time Complexity:** Proportional to $256 \times r^2$ sensitivity computations, where each computation requires a backpropagation pass through the volume renderer [S1].
*   **Memory Complexity:** $O(256 \times r^2)$ to store the tensor $\Sigma$ [S1].
*   **Performance:** Setting $r=256$ is prohibitively costly due to the $256^2$ backpropagation passes required [S1]. Using $r=8$ or $16$ significantly reduces latency [S1].
*   **Strengths:** Allows users to understand the impact of TF edits on specific image regions before applying them; complements Region Sensitivity Plots [S1].
*   **Limitations:** Computationally expensive for high-resolution grids; sensitivity values are relative and may require careful opacity encoding to be visible [S1].

## Background
Scalar Value Sensitivity Fields were introduced in the paper "A Generative Model for Volume Rendering" [S1]. The method is part of a broader framework for exploring opacity transfer function latent spaces using generative models (specifically GANs) [S1]. It is used in conjunction with Region Sensitivity Plots to provide a comprehensive interface for TF editing and exploration [S1].
