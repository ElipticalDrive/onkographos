# Two-stage CBR Method for Transfer Function Design

Also called: CBR-TF, Case-Based Reasoning Transfer Function, Content-Based Retrieval for Transfer Function Design, Retrieval based Transfer Function Design, Two-stage CBR-TF approach, two-stage CBR method, two-stage method

## Overview
The Two-stage CBR Method automatically generates intensity-based 1D transfer functions (TFs) for volume rendering by retrieving relevant anatomical structures of interest (SOIs) from a knowledge database of labeled volumes [S1, unofficial][S2]. It solves the problem of manual TF navigation and fine-tuning by using a "triplet input query" (TIQ) to match spatial semantics and intensity profiles, then composing a TF from the retrieved labels [S2]. It is distinguished from single-stage retrieval methods by its complementary two-stage ranking: first using CNN-based image matching to narrow candidates, then using Dynamic Time Warping (DTW) on intensity profiles to refine the selection, which prevents the misclassification errors common in Euclidean Distance (ED) baselines [S1, unofficial][S2].

## How it works
### Inputs and Outputs
**Inputs:**
1.  **Knowledge Database:** A collection of $N$ volumes where each voxel has an intensity value and an SOI label. Each volume is pre-processed into ray elements [S1, unofficial][S2].
2.  **Input Volume:** The target volume for which the TF is designed [S1, unofficial][S2].
3.  **User Interaction:** A user selects a ray $q$ by drawing a line on a 2D cross-sectional view (axial, coronal, or sagittal) or clicking a point on an initial 3D DVR visualization [S1, unofficial][S2].

**Outputs:**
1.  **Transfer Function:** A 1D intensity-based TF composed of tent-shaped components for each identified SOI [S1, unofficial][S2].
2.  **Optimized Parameters:** (Optional) Opacity parameters optimized for visibility [S1, unofficial][S2].

### Data Structures
**Ray Element (Database Entry):**
Each entry in the knowledge database represents a ray extracted from a labeled volume. It contains:
*   **Image Pair ($c_i$):** Two co-planar 2D images aligned with the primary axes, perpendicular to the ray direction.
*   **Intensity Profile ($c_p$):** A 1D array of intensity values along the ray.
*   **SOI Labels:** A list of SOI names intersected by the ray.
*   **Coordinates:** Entry and exit points of the ray [S1, unofficial].

**Target Image Query (TIQ):**
The query generated from the user's input ray $q$. It consists of:
*   **Image Pair ($q_i$):** Two co-planar images from the input volume corresponding to the ray.
*   **Intensity Profile ($q_p$):** The intensity values along the ray $q$ [S1, unofficial][S2].

**CNN Feature Vector:**
A 4096-dimensional vector extracted from the fully connected layer (FC7) of the AlexNet architecture [S1, unofficial].

### Numbered Steps

#### 1. Offline Knowledge Database Construction
1.  Select a set of labeled volumes (e.g., from the 3D-IRCADb-01 dataset) [S2].
2.  For each volume, extract rays uniformly along the three primary axes (x, y, z).
    *   Use 64 rays per axis, totaling 192 rays per volume [S1, unofficial].
    *   Exclude empty background regions [S1, unofficial].
3.  For each ray, extract the image pair and intensity profile.
4.  Store the ray elements in the knowledge database along with their SOI labels [S1, unofficial][S2].

#### 2. User Interaction and TIQ Generation
1.  Display the input volume in a quarter-view visualization (2D cross-sectional views + 3D DVR) [S1, unofficial][S2].
2.  User draws a line (ray $q$) on a 2D view or clicks a point on the 3D DVR [S1, unofficial][S2].
    *   *If point click:* Construct a viewing ray perpendicular to the camera origin passing through the point [S2].
3.  Extract the two co-planar images ($q_i$) and the intensity profile ($q_p$) for ray $q$ from the input volume [S1, unofficial][S2].
4.  Form the TIQ: $TIQ = (q_i, q_p)$ [S2].

#### 3. Stage 1: Image Matching (CNN Retrieval)
1.  Pre-process the images in $q_i$ to match the input format of the pre-trained CNN (AlexNet) [S1, unofficial].
2.  Pass each image in $q_i$ through the CNN to extract feature vectors.
    *   Use the output of the FC7 layer (4096 dimensions) [S1, unofficial].
3.  For each candidate $c$ in the knowledge database:
    *   Extract its image pair $c_i$.
    *   Compute the Image Similarity Distance $D_{img}(q_i, c_i)$ using Euclidean Distance (ED) between the feature vectors:
        $$ D_{img}(q_i, c_i) = \sum_{j=1}^{2} \sum_{b=1}^{4096} (F^b_{qij} - F^b_{cij})^2 $$
        where $F^b_{qij}$ is the $b$-th feature of the $j$-th image in $q_i$, and $F^b_{cij}$ is the $b$-th feature of the $j$-th image in $c_i$ [S1, unofficial].
4.  Rank all database candidates by $D_{img}$ in ascending order.
5.  Select the top $N$ candidates (default $N=40$) [S2].

#### 4. Stage 2: Intensity Profile Matching (DTW Refinement)
1.  For each of the top $N$ candidates from Stage 1:
    *   Retrieve its intensity profile $c_p$ [S1, unofficial][S2].
    *   Compute the Intensity Profile Similarity Distance $D_{prof}(q_p, c_p)$ using Dynamic Time Warping (DTW) [S1, unofficial][S2].
    *   **DTW Calculation:**
        1.  Create a distance matrix $M$ of size $L_{q_p} \times L_{c_p}$, where $L$ is the length of the profile. $M[k, l] = |q_p[k] - c_p[l]|$ [S1, unofficial].
        2.  Find the optimal warping path $P^*$ that minimizes the cumulative cost, subject to:
            *   **Boundary:** Path starts at $(1,1)$ and ends at $(L_{q_p}, L_{c_p})$ [S1, unofficial].
            *   **Continuity:** Steps are to adjacent cells (horizontal, vertical, diagonal) [S1, unofficial].
            *   **Monotonicity:** Path does not move backwards [S1, unofficial].
        3.  Calculate the distance:
            $$ D_{prof}(q_p, c_p) = \min \sqrt{\sum_{k=1}^{K} p_k / K} $$
            where $K$ is the length of the warping path $P^*$ and $p_k$ is the cost of the $k$-th step in the path [S1, unofficial].
2.  Re-rank the $N$ candidates based on $D_{prof}$ in ascending order [S1, unofficial][S2].
3.  Combine the rankings from Stage 1 and Stage 2 using a rank-based sequential combination method to determine the final best match [S2].
    *   *Note:* The sources describe combining the results to find the "overall best matching" result, often implying a weighted sum or rank aggregation, though the exact mathematical combination formula is not explicitly detailed beyond "rank-based sequential combination" [S2]. The implementation should prioritize the final rank order derived from the DTW refinement of the CNN top-N [S1, unofficial][S2].

#### 5. TF Generation
1.  Identify the SOI labels associated with the best-matching candidate(s) [S1, unofficial][S2].
2.  For each unique SOI $S_m$ (where $m=1..M$):
    *   Determine the intensity range from the retrieved case:
        *   $I_{l,m}$: Lowest intensity in $S_m$.
        *   $I_{h,m}$: Highest intensity in $S_m$.
        *   $I_{m}$: Average intensity in $S_m$ [S1, unofficial].
    *   Define a tent-shaped component $T_m$ for the TF:
        $$ T_m = \{(I_{l,m}, 0), (I_{m}, \sigma_m), (I_{h,m}, 0)\} $$
        where $\sigma_m$ is the initial opacity of the tent peak, typically set to 0.3 [S1, unofficial].
    *   Assign a unique color to the apex $(I_m, \sigma_m)$ using a color scheme (e.g., ColorBrewer) and black to the endpoints $(I_{l,m}, 0)$ and $(I_{h,m}, 0)$ to improve depth perception [S1, unofficial][S2].
3.  The initial TF is the union of all tent components:
    $$ TF_{initial} = \bigcup_{m=1}^{M} T_m $$
    [S1, unofficial]

#### 6. TF Optimization (Optional)
1.  Define target visibility $V^T_m$ for each SOI $m$. $V^T_m$ can be uniform or user-defined (e.g., 0.7 for bones, 0.3 for lungs) [S1, unofficial][S2].
2.  Define the energy function $E(\theta)$ based on visibility tolerance:
    $$ E(\theta) = \sum_{m=1}^{M} (V^T_m - V^R_m)^2 $$
    where $\theta$ are the opacity parameters of the tent peaks, and $V^R_m$ is the resultant visibility [S1, unofficial].
3.  Calculate resultant visibility $V_{SOI}$ for a voxel $p$ in an SOI:
    *   Compute front-to-back opacity composition $F(p)$:
        $$ F(p) = e^{-\int_{h}^{p} A(g) dg} $$
        where $h$ is the viewpoint [S1, unofficial].
    *   Update composited opacity $A(p)$:
        $$ A(p) = A(p - \Delta p) + (1.0 - A(p - \Delta p))O(p) $$
        where $O(p)$ is the opacity defined by the TF at $p$, and $\Delta p$ is the sampling step size [S1, unofficial].
    *   Compute visibility:
        $$ V_{SOI} = \sum_{p \in SOI} O(p)F(p) $$
        [S1, unofficial]
4.  Minimize $E(\theta)$ using the Downhill Simplex method [S1, unofficial].
5.  Generate the final DVR visualization using the optimized TF [S2].

### Parameters and Typical Values
*   **CNN Architecture:** AlexNet, pre-trained on ImageNet (1.2 million images) [S1, unofficial].
*   **Feature Dimension:** 4096 (from FC7 layer) [S1, unofficial].
*   **Rays per Volume:** 192 (64 per axis) [S1, unofficial].
*   **Top N Candidates:** 40 [S2].
*   **Initial Opacity ($\sigma_m$):** 0.3 [S1, unofficial].
*   **Visibility Tolerance ($V^T_m$):** User-defined or uniform (e.g., 0.7 for bones, 0.3 for lungs) [S1, unofficial][S2].
*   **Optimization Method:** Downhill Simplex [S1, unofficial].

### Edge Cases and Pitfalls
*   **False Positives:** If the system incorrectly identifies an SOI, the user must manually eliminate the corresponding tent-shape TF component [S2].
*   **False Negatives:** Missing structures are harder to correct manually, but the system avoids starting from scratch [S2].
*   **ED Baseline Failure:** Euclidean Distance baseline incorrectly labels arteries and kidneys; the two-stage method corrects this by combining CNN and DTW [S1, unofficial].
*   **Fine-tuning:** Fine-tuning AlexNet did not consistently improve recall compared to pre-trained AlexNet, except for spleen [S1, unofficial].

## Operating characteristics
*   **Time Complexity:**
    *   **Retrieval:** Dominated by CNN feature extraction. AlexNet compartment takes ~15.70s, DTW compartment ~1.14s, ED baseline ~0.84s. Two-stage method takes ~15.93s [S1, unofficial].
    *   **TF Generation:** < 1 second [S1, unofficial].
*   **Memory Complexity:** Depends on the size of the knowledge database (3840 ray elements from 20 volumes in the study) [S1, unofficial].
*   **Performance:**
    *   **Recall:** Two-stage method achieved 0.719 recall for "All" SOIs, compared to 0.518 for ED baseline [S1, unofficial].
    *   **Improvement:** Average recall improvement of 0.201 over ED baseline; largest improvement for kidney (0.304) [S1, unofficial].
    *   **CNN Comparison:** Pre-trained AlexNet (0.719) outperformed GoogleNet (0.707) and ResNet (0.620) [S1, unofficial].
*   **Strengths:**
    *   Handles subtle alignment differences in intensity profiles via DTW [S2].
    *   Uses high-level spatial semantics via CNN, improving retrieval of complex SOIs like arteries and kidneys [S1, unofficial].
    *   Reduces manual navigation and fine-tuning [S2].
*   **Limitations:**
    *   Computationally expensive due to CNN inference (~15s) [S1, unofficial].
    *   Fine-tuning CNNs is not necessarily beneficial [S1, unofficial].
    *   Requires a labeled knowledge database [S2].

## Background
*   **Origin:** The method was proposed by Jung, Kong, and Kim [S1, unofficial][S2].
*   **Paper:** "A Transfer Function Design Using A Knowledge Database based on Deep Image and Primitive Intensity Profile Features Retrieval" (2022) [S1, unofficial][S2].
*   **Dataset:** Evaluated on the 3D Image Reconstruction for Comparison of Algorithm Database (3D-IRCADb-01), consisting of 20 CT volumes of the upper abdomen [S1, unofficial][S2].
*   **Implementation:** Implemented in the Voreen volume rendering engine [S1, unofficial].
*   **Context:** Builds on Case-Based Reasoning (CBR) in visualization, addressing limitations of previous CBR approaches that relied solely on intensity profiles or 2D slice linking [S2].
