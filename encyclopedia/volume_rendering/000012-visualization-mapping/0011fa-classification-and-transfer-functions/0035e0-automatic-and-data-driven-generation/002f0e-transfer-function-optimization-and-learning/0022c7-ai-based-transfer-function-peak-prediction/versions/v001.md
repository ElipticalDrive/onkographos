# AI-Based Transfer Function Peak Prediction

Also called: AI-Assisted Transfer Function Selection, ONNX Transfer Function Picker, Peak Predictor, usePeakPredictor, usePeakPredictor hook

## Overview
This method automates the selection of the `peak` parameter for a volume rendering transfer function by analyzing rendered frames using a neural network [S1, unofficial]. It solves the tedious manual tuning required when browsing many volume/surface pairs [S1, unofficial]. It is distinguished from other optimization methods by its reliance on a pre-trained MobileNetV3 model running in WebAssembly to predict a single scalar parameter from image space, rather than optimizing the entire transfer function via gradient descent or reconstruction loss [S1, unofficial].

## How it works
The method is implemented as a React hook (`usePeakPredictor`) that controls the renderer to capture frames, construct a tensor, and query an ONNX model.

**Inputs and Outputs:**
*   **Input:** Rendered pixel buffers from the volume renderer.
*   **Output:** A predicted `peak` value (integer 0-255) applied to the transfer function.

**Data Structures:**
*   **Transfer Function Texture:** A `THREE.DataTexture` with width 256, height 1, and format `THREE.RGBAFormat`. Each 8-bit data value maps to a 4-byte RGBA value [S1, unofficial].
*   **Input Tensor:** A multi-channel tensor of size 192x192 pixels. It consists of:
    1.  Binary mask: Dilation of the green surface.
    2.  Binary mask: Crop region.
    3.  Red channel: Combined render from the first transfer function sample.
    4.  Red channel: Combined render from the second transfer function sample.
    *(Note: The specific combination of channels and samples is derived from the capture process described below)* [S1, unofficial].

**Steps:**
1.  **Initialization:** The hook invokes control over the renderer. It initializes the ONNX Runtime Web environment. If the CDN hosting the WASM code does not respond within 10 seconds, an exception is thrown [S1, unofficial].
2.  **Sampling:** The system cycles through several transfer functions, varying the `peak` parameter from high to low. For each iteration:
    a.  Render the volume.
    b.  Capture a "surface-only" frame to help the model locate the green surface [S1, unofficial].
    c.  Capture the resulting pixel buffer using `gl.readPixels` [S1, unofficial].
3.  **Verification:** To ensure frame integrity, the fragment shader writes a one-byte watermark into the blue channel of the image center pixel. The predictor reads this byte back and compares it against the expected value. Frames failing this check are discarded [S1, unofficial].
4.  **Tensor Construction:**
    a.  Extract the relevant channels from the captured buffers.
    b.  Create binary masks for the green surface (dilated) and the crop region.
    c.  Combine these masks and the red channels of the renders into a single multi-channel tensor.
    d.  Crop and resize the tensor to 192x192 pixels [S1, unofficial].
5.  **Prediction:** Feed the 192x192 tensor into the MobileNetV3-Small ONNX model. The model returns the predicted optimal `peak` value [S1, unofficial].
6.  **Application:** Apply the predicted `peak` value to the transfer function's `alpha` calculation. The alpha follows a tent shape: rising from `alpha0` at data value 0 to 255 at `peak`, then falling to `alpha1` at data value 255. The rise/fall is controlled by `dataGamma` using $y^{(1.0 / \text{dataGamma})}$, where $y$ is the normalized data value [S1, unofficial].

**Pseudocode:**

```python
import onnxruntime_web as ort # Pseudocode for ONNX Runtime Web
import gl_utils

def use_peak_predictor(renderer, model_path):
    # Initialize ONNX model
    session = ort.InferenceSession(model_path)
    
    # Define transfer function parameters
    alpha0 = 0
    alpha1 = 255
    data_gamma = 0.5
    final_gamma = 4.5
    color_str = '#ff00ff'
    
    # Helper to create transfer function texture
    def make_tf_texture(peak):
        # Creates DataTexture with width 256, height 1, RGBAFormat
        # Alpha is tent-shaped: rises to 255 at 'peak', falls to alpha1
        # Rise/Fall uses power function: y ** (1.0 / data_gamma)
        return renderer.create_data_texture(peak, alpha0, alpha1, data_gamma, color_str)

    # Helper to verify frame integrity
    def verify_frame(frame_buffer):
        center_pixel = frame_buffer[center_x, center_y]
        watermark = center_pixel.blue_channel
        expected_watermark = 0xAA # Example expected value
        return watermark == expected_watermark

    # Capture and process frames
    samples = []
    for peak_val in range(255, 0, -10): # Cycle high to low
        tf_texture = make_tf_texture(peak_val)
        renderer.set_transfer_function(tf_texture)
        renderer.render()
        
        # Capture pixel buffer
        buffer = gl_utils.read_pixels()
        
        # Verify watermark
        if not verify_frame(buffer):
            continue
            
        # Capture surface-only frame for mask generation
        surface_buffer = gl_utils.read_surface_only()
        
        samples.append({
            'buffer': buffer,
            'surface': surface_buffer,
            'peak': peak_val
        })
        
        # Limit samples to reduce computation time
        if len(samples) >= 5:
            break

    # Construct tensor
    # 1. Create binary mask for green surface (dilated)
    surface_mask = create_dilated_green_mask(samples[0]['surface'])
    
    # 2. Create crop region mask
    crop_mask = create_crop_mask()
    
    # 3. Extract red channels from combined renders
    red_ch_1 = samples[0]['buffer'].red_channel
    red_ch_2 = samples[1]['buffer'].red_channel if len(samples) > 1 else red_ch_1
    
    # 4. Combine into multi-channel tensor
    # Channels: [surface_mask, crop_mask, red_ch_1, red_ch_2]
    tensor = combine_channels(surface_mask, crop_mask, red_ch_1, red_ch_2)
    
    # 5. Resize to 192x192
    tensor = resize_tensor(tensor, 192, 192)
    
    # 6. Run inference
    input_tensor = prepare_onnx_input(tensor)
    prediction = session.run(None, {session.get_inputs()[0].name: input_tensor})
    predicted_peak = prediction[0][0] # Extract scalar value
    
    # 7. Apply result
    final_tf = make_tf_texture(predicted_peak)
    renderer.set_transfer_function(final_tf)
    
    return predicted_peak
```

**Parameters:**
*   **Model:** MobileNetV3-Small [S1, unofficial].
*   **Input Tensor Size:** 192x192 [S1, unofficial].
*   **ONNX Runtime Web Version:** ^1.24.3 [S1, unofficial].
*   **Typical `dataGamma`:** 0.5 (de-emphasizes low values) [S1, unofficial].
*   **Typical `finalGamma`:** 4.5 (prevents loss of low-value context) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Dependency Failure:** If `onnxruntime-web` is not installed as a peer dependency, the build fails with a Webpack error: 'Module not found: Error: Can't resolve 'onnxruntime-web'...' [S1, unofficial].
*   **Network Timeout:** The WASM code is fetched from a CDN. If the CDN does not respond within 10 seconds, an exception is thrown [S1, unofficial].
*   **Precision:** The `peak` parameter is an integer in the range 0-255, corresponding to the 8-bit data values [S1, unofficial].

## Subtopics

### [Transfer Function Reconstruction Loss](1199-transfer-function-reconstruction-loss.md)
Optimizes the transfer function by minimizing the difference between rendered and target images using gradient descent. Choose when pixel-perfect reconstruction is required.

### [Voxel-based Transfer Function Optimization](3259-voxel-based-transfer-function-optimization.md)
Optimizes transfer function values directly in voxel space. Choose when spatial coherence of the transfer function is critical.

### [Self-Organizing Map Dimensional Reduction for Transfer Functions](6242-self-organizing-map-dimensional-reduction-for-transfer-funct.md)
Uses SOMs to reduce the dimensionality of the transfer function parameter space. Choose when exploring the parameter space for complex transfer functions.

## Operating characteristics
*   **Time Complexity:** Depends on the number of samples taken during the search cycle and the inference time of the MobileNetV3-Small model. The model runs in WebAssembly, which may be slower than native CPU/GPU execution [S1, unofficial].
*   **Memory Complexity:** Low. Requires storing a few frame buffers and the ONNX model weights. The input tensor is small (192x192x4) [S1, unofficial].
*   **Strengths:** Automates tedious manual tuning; works well for fluorescence microscopy data; lightweight deployment in web browsers via WebAssembly [S1, unofficial].
*   **Limitations:** Requires a pre-trained model specific to the data type (fluorescence microscopy); dependent on external CDN for WASM runtime; verification step adds overhead [S1, unofficial].
*   **When to use:** When browsing many volume/surface pairs and manual tuning is impractical.
*   **When not to use:** When high precision in transfer function shape is required beyond the `peak` parameter, or when network access is unavailable.

## Background
This method is implemented in the `web-vol-viewer` project by JaneliaSciComp [S1, unofficial]. It is designed for visualizing 3D and 4D confocal microscopy data, building on the FluoRender application described by Wan et al. in "FluoRender: An Application of 2D Image Space Methods for 3D and 4D Confocal Microscopy Data Visualization in Neurobiology Research" (2012 IEEE Pacific Visualization Symposium) [S1, unofficial]. The desktop application VVD Viewer also uses the underlying transfer function logic [S1, unofficial].
