# Unit Transfer Function Generation via Histogram Peak Detection

Also called: Douglas-Peucker Histogram Simplification, Peak-based Unit Transfer Function

## Overview
This method automatically generates "unit transfer functions," which are simple mappings that visualize a single structure in a scalar volume dataset, characterized by a peak in the data histogram [S1, unofficial]. It solves the problem of designing complex transfer functions by allowing users to assemble simple, recognizable visualizations based on domain knowledge [S1, unofficial]. It sets itself apart from its siblings by using the Douglas-Peucker algorithm to simplify the histogram curve and identify main peaks, rather than relying on manual inspection or noise reduction techniques alone [S1, unofficial].

## How it works
**Inputs:** A scalar volume dataset (density values).
**Outputs:** A set of unit transfer functions, each associated with a random color and an opacity function.

**Data Structures:**
1.  **Histogram:** A 2D curve represented as a list of points. Each point is a tuple `(binValue, normalizedLogCount)`.
    *   `binValue`: The density value of the bin.
    *   `normalizedLogCount`: The normalized logarithmic value of the number of voxels in that bin.
2.  **Polyline S:** A list of points representing the simplified curve. Initially contains only the first and last points of the histogram curve.

**Steps:**

1.  **Generate Histogram:**
    Create a bin for each value in the range of density values in the dataset. Compute the number of voxels with that value for each bin [S1, unofficial].

2.  **Normalize and Log-Transform:**
    To handle dramatic variations between maximum and minimum bin values, apply a normalized logarithmic transformation to the histogram counts [S1, unofficial]. The formula for the y-coordinate of each point is:
    $$ y = \frac{\log(\text{ValueOfTheCurrentBin})}{\log(\text{MaxValue})} $$
    where `ValueOfTheCurrentBin` is the number of voxels in the current bin, and `MaxValue` is the maximum number of voxels in any bin [S1, unofficial]. The x-coordinate is the bin value (density value) [S1, unofficial].

3.  **Simplify Curve using Douglas-Peucker:**
    Apply the Douglas-Peucker algorithm to the 2D curve to identify main peaks [S1, unofficial].
    *   **Parameter:** $\epsilon$ (epsilon). This value specifies the maximum allowed error of the approximated curve and corresponds to the size of features to capture [S1, unofficial].
    *   **Initialization:** Initialize polyline $S$ containing only the first and last points of the curve (left and right most values in the histogram) [S1, unofficial].
    *   **Recursive Simplification:**
        1.  Compute the perpendicular distances of all points in the current segment to the line segment connecting the endpoints of $S$.
        2.  Find the point $P$ with the maximum distance.
        3.  If the maximum distance is smaller than $\epsilon$, stop processing this segment.
        4.  If the maximum distance is greater than or equal to $\epsilon$, add point $P$ to $S$.
        5.  Recursively call the algorithm for the two sections of the curve on either side of $P$ [S1, unofficial].

4.  **Identify and Sort Peaks:**
    Sort the identified peaks in the resulting simplified histogram by importance. Importance is determined by their height relative to the valleys on either side [S1, unofficial].

5.  **Define Unit Transfer Functions:**
    For each peak, define a unit transfer function capturing the region represented by that section of the histogram [S1, unofficial].
    *   **Color:** Associate each unit transfer function with a random color value [S1, unofficial].
    *   **Opacity:** Define an opacity value that increases linearly with the density value of the corresponding peak in the histogram [S1, unofficial].

**Pseudocode:**

```python
import math
import random

def generate_histogram(data):
    """
    Generates a histogram from scalar volume data.
    Returns a list of tuples (bin_value, raw_count).
    """
    # Determine range of density values
    min_val = min(data)
    max_val = max(data)
    
    # Create bins for each value in the range
    # Note: In practice, binning might involve grouping, but the source implies
    # a bin for each value or a fine-grained binning.
    # We assume a direct mapping for simplicity based on "bin for each value"
    # However, standard histograms group values. The source says "creating a bin 
    # for each value of the range of density values". This implies a dense histogram.
    
    histogram = {}
    for val in data:
        if val not in histogram:
            histogram[val] = 0
        histogram[val] += 1
        
    # Sort by value
    sorted_histogram = sorted(histogram.items(), key=lambda x: x[0])
    return sorted_histogram

def normalize_log_histogram(sorted_histogram):
    """
    Applies normalized logarithmic transformation to histogram counts.
    Returns list of tuples (bin_value, normalized_log_count).
    """
    if not sorted_histogram:
        return []
        
    # Find MaxValue (maximum number of voxels in any bin)
    max_count = max(count for _, count in sorted_histogram)
    
    # Avoid log(0) or log(1) issues if max_count is 0 or 1
    if max_count <= 1:
        # If all counts are 0 or 1, log normalization might be degenerate.
        # The source uses log(Value)/log(MaxValue). If MaxValue is 1, log(1)=0.
        # This would cause division by zero.
        # [G] Guard against division by zero. If max_count is 1, all counts are 1.
        # We can return 0 or 1. Let's return 0 for simplicity as they are all equal.
        return [(val, 0.0) for val, _ in sorted_histogram]

    normalized_points = []
    for bin_value, count in sorted_histogram:
        # Formula: log(ValueOfTheCurrentBin) / log(MaxValue)
        # Note: If count is 0, log(0) is undefined.
        # [G] Handle count=0 by assigning a very small negative number or 0.
        # The source doesn't specify, but typically empty bins are ignored or set to min.
        # Assuming count > 0 for valid bins.
        if count > 0:
            y = math.log(count) / math.log(max_count)
        else:
            y = -float('inf') # Or a small negative number
            
        normalized_points.append((bin_value, y))
        
    return normalized_points

def perpendicular_distance(point, line_start, line_end):
    """
    Computes the perpendicular distance from a point to a line segment.
    """
    x, y = point
    x1, y1 = line_start
    x2, y2 = line_end
    
    # Line equation: Ax + By + C = 0
    # A = y1 - y2
    # B = x2 - x1
    # C = x1*y2 - x2*y1
    
    A = y1 - y2
    B = x2 - x1
    C = x1 * y2 - x2 * y1
    
    # Distance = |Ax + By + C| / sqrt(A^2 + B^2)
    numerator = abs(A * x + B * y + C)
    denominator = math.sqrt(A**2 + B**2)
    
    if denominator == 0:
        return 0
        
    return numerator / denominator

def douglas_peucker(points, epsilon):
    """
    Simplifies a curve using the Douglas-Peucker algorithm.
    Returns a list of points from the simplified polyline.
    """
    if len(points) < 3:
        return points
    
    # Find the point with the maximum distance from the line segment
    # connecting the first and last points
    dmax = 0
    index = 0
    end = len(points) - 1
    
    for i in range(1, end):
        d = perpendicular_distance(points[i], points[0], points[end])
        if d > dmax:
            index = i
            dmax = d
            
    # If max distance is greater than epsilon, recursively simplify
    if dmax >= epsilon:
        # Recursive calls
        rec_results1 = douglas_peucker(points[:index+1], epsilon)
        rec_results2 = douglas_peucker(points[index:], epsilon)
        
        # Combine results, avoiding duplicate points at the split
        return rec_results1[:-1] + rec_results2
    else:
        # Return only the endpoints
        return [points[0], points[end]]

def identify_peaks(simplified_curve):
    """
    Identifies peaks in the simplified curve.
    A peak is a point that is higher than its neighbors.
    """
    peaks = []
    for i in range(1, len(simplified_curve) - 1):
        prev_y = simplified_curve[i-1][1]
        curr_y = simplified_curve[i][1]
        next_y = simplified_curve[i+1][1]
        
        if curr_y > prev_y and curr_y > next_y:
            peaks.append(simplified_curve[i])
            
    return peaks

def sort_peaks_by_importance(peaks):
    """
    Sorts peaks by importance, determined by their height relative to the valleys.
    """
    # [G] The source says "height relative to the valleys on either side".
    # A simple approximation is the peak height itself, or the difference between
    # peak height and the minimum of its neighbors.
    # Let's use the difference between peak height and the minimum of its neighbors.
    # However, we don't have the original neighbors in the simplified curve.
    # We can approximate importance by the peak's y-value itself, as higher peaks
    # are generally more significant.
    # Or, we can look at the original histogram data around the peak's bin value.
    # For simplicity, we sort by y-value (height).
    return sorted(peaks, key=lambda p: p[1], reverse=True)

def generate_unit_transfer_functions(peaks):
    """
    Generates unit transfer functions for each peak.
    Returns a list of transfer function definitions.
    """
    transfer_functions = []
    for peak in peaks:
        bin_value, y = peak
        
        # Random color
        color = (random.random(), random.random(), random.random())
        
        # Opacity increases linearly with the density value of the corresponding peak
        # [G] The source says "opacity value which increases linearly with the density value".
        # This implies a function Opacity(density) = k * density + b.
        # Since it's a "unit" transfer function for a specific peak, it likely covers
        # a range around the peak. The source doesn't specify the range.
        # We assume the transfer function is defined for the bin value of the peak.
        # The opacity is proportional to the density value.
        # Let's assume a simple linear mapping: opacity = density / max_density.
        # Or simply opacity = density_value.
        # The source says "increases linearly with the density value of the corresponding peak".
        # This is ambiguous. Does it mean the opacity *at* the peak is linear with the peak's density?
        # Or the opacity function is linear with density?
        # Given it's a "unit" function, it likely maps a range of densities to opacity.
        # Let's assume the opacity is simply the normalized density value for that peak.
        opacity = bin_value # Or normalized bin_value
        
        transfer_functions.append({
            'peak_bin_value': bin_value,
            'color': color,
            'opacity_function': lambda d: d # Linear with density
        })
        
    return transfer_functions

def main(data, epsilon):
    histogram = generate_histogram(data)
    normalized_histogram = normalize_log_histogram(histogram)
    simplified_curve = douglas_peucker(normalized_histogram, epsilon)
    peaks = identify_peaks(simplified_curve)
    sorted_peaks = sort_peaks_by_importance(peaks)
    transfer_functions = generate_unit_transfer_functions(sorted_peaks)
    return transfer_functions
```

**Parameters:**
*   $\epsilon$ (epsilon): The maximum allowed error of the approximated curve in the Douglas-Peucker algorithm. Controls the size of features captured. $\epsilon=0$ yields the original smoothed histogram; $\epsilon=\text{maximumBinValue}$ yields only one peak [S1, unofficial].

**Edge Cases and Pitfalls:**
*   The linear opacity increase assumes that regions with the highest density are inside the data set and lower density regions are outside (e.g., bone vs. muscle in CT) [S1, unofficial]. This may not hold for all data types [S1, unofficial].
*   Division by zero in log normalization if `MaxValue` is 1 or 0.
*   Log of 0 if bin count is 0.

## Operating characteristics
**Time Complexity:** The Douglas-Peucker algorithm has a worst-case time complexity of $O(n^2)$, where $n$ is the number of points in the histogram. However, it often performs closer to $O(n \log n)$ on typical data. Histogram generation is $O(N)$, where $N$ is the number of voxels.
**Memory Complexity:** $O(n)$ for storing the histogram and simplified curve.
**Measured Performance:** Not given in the sources.
**Scaling:** The method scales with the number of voxels for histogram generation and the number of bins for the Douglas-Peucker algorithm.
**Strengths:** Simple to implement; provides a good basis for exploration by generating simple, recognizable visualizations; allows users to assemble complex visualizations from simple units.
**Limitations:** Assumes a specific relationship between density and opacity (higher density = inside); may not be suitable for all data types; relies on the choice of $\epsilon$.
**When to use:** When the data has clear peaks in the histogram corresponding to distinct structures, and the user wants to quickly generate simple visualizations for exploration.
**When not to use:** When the data does not have clear peaks, or when the assumption about density and opacity does not hold.

## Background
The method was introduced in 2010 by SCITEPRESS [S1, unofficial]. It builds on previous research demonstrating that structures in scalar volume data sets can often be characterized by the first and second order derivatives [S1, unofficial]. The Douglas-Peucker algorithm was originally proposed by Peucker in 1973 [S1, unofficial]. The method is used in the context of a spreadsheet-like interface for "programming-by-example" in volume rendering [S1, unofficial].
