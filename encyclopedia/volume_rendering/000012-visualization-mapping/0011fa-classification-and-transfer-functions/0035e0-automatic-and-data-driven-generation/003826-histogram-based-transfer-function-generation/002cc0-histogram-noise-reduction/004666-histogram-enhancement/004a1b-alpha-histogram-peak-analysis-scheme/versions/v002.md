# Alpha-histogram Peak Analysis Scheme

Also called: Automatic Peak Detection in Alpha-histogram, Peak Detection Scheme, Peak analysis scheme

## Overview
The Alpha-histogram Peak Analysis Scheme is an automatic method for detecting significant peaks in an $\alpha$-histogram to facilitate Transfer Function (TF) design. It solves the problem of noise-induced spurious peaks in $\alpha$-histograms by combining selective smoothing with area-based importance assessment. It differs from its parent, [α-histogram Enhancement](11753-histogram-enhancement.md), by providing the specific algorithmic steps to reduce the enhanced histogram's peak count to a manageable, significant set. It differs from [TF adaptation peak selection](12678-tf-adaptation-peak-selection.md) by focusing on the raw detection and simplification of peaks rather than the final selection based on valid ranges and confidence metrics.

## How it works
**Inputs:** An $\alpha$-histogram represented as an array of bin heights.
**Outputs:** A list of simplified peaks, where each peak is defined by its apex position, width (valleys), and area.

**Data Structures:**
*   **Histogram:** Array $H$ of size $N$, where $H[i]$ is the count for intensity bin $i$.
*   **Peak:** A tuple $(v_{left}, a, v_{right})$ where $v_{left}$ and $v_{right}$ are the indices of the surrounding valleys and $a$ is the index of the apex.
*   **Area:** A scalar value associated with each peak.

**Parameters:**
*   $np1$: Maximum number of remaining peaks after global smoothing. Typical value: 20 [S1].
*   $np2$: Predefined number of peaks to retain after simplification. Typical values: 1, 2, 3, 4 [S1].
*   Kernel: Binomial smoothing kernel $K = [0.25, 0.5, 0.25]$ (represented as $0.25 \cdot [1, 2, 1]$) [S1].

**Steps:**

1.  **Selective Smoothing:**
    Identify "minimal peaks" or "creases". A minimal peak is an apex surrounded by two valleys (valley-apex-valley). A crease is an apex surrounded by two other apices (apex-valley-apex is not a crease; the text specifies "middle of three directly adjacent valley-apex-valley or apex-valley-apex points"). Specifically, a point is a minimal peak/crease if it is the local extremum in a triplet of adjacent points where the neighbors are of the opposite type (valley or apex).
    Apply the smoothing kernel $K$ to the histogram bin corresponding to each identified minimal peak or crease.
    Repeat this process iteratively until no minimal peaks or creases remain in the histogram. This step removes small, noise-induced irregularities without affecting larger, subtle peaks [S1].

2.  **Global Smoothing:**
    Apply the smoothing kernel $K$ to the entire histogram array.
    After each application, count the number of remaining peaks (local maxima).
    Repeat the global smoothing until the number of remaining peaks equals $np1$ (typically 20) [S1].

3.  **Peak Listing and Simplification:**
    Identify all remaining peaks in the smoothed histogram.
    Calculate the area for each peak (see Formula below).
    If the number of peaks exceeds $np2$, iteratively remove the peak with the smallest area.
    When a peak is removed, extend one of its immediate neighbors to cover the removed peak's range if doing so increases the neighbor's area.
    If both neighbors would gain from an extension, select the neighbor with the largest peak height (apex value) [S1].
    Repeat until exactly $np2$ peaks remain.

**Formulas:**

*   **Smoothing Operator:**
    For a bin $i$, the new value $H'[i]$ is:
    $$ H'[i] = 0.25 \cdot H[i-1] + 0.5 \cdot H[i] + 0.25 \cdot H[i+1] $$
    Boundary conditions: Not given in the sources. [G] (Assume zero-padding or replication).

*   **Peak Definition:**
    A point $a$ is an apex if $H[a] > H[a-1]$ and $H[a] > H[a+1]$.
    A point $v$ is a valley if $H[v] < H[v-1]$ and $H[v] < H[v+1]$.

*   **Base Line Construction:**
    For a peak with apex $a$ and left valley $v_{left}$:
    Start at the highest valley with a downward slope relative to the peak.
    Extend a straight line from this valley touching exactly one other point on the histogram curve within the peak range (the right boundary of the peak segment).
    *Note:* The text states "starting at the highest valley with a downward slope". In the context of a single peak segment bounded by two valleys, this likely refers to the valley that defines the base of the peak. The base line connects the left valley to a specific point on the right side of the peak curve.

*   **Peak Area:**
    $$ \text{Area} = \sum_{i=v_{left}}^{v_{right}} |H[i] - L[i]| $$
    Where $L[i]$ is the height of the base line at bin $i$, and $v_{left}, v_{right}$ are the start and end points of the peak segment defined by the base line touching points [S1].

**Pseudocode:**

```python
def alpha_histogram_peak_analysis(histogram, np1=20, np2=4):
    """
    Detects and simplifies peaks in an alpha-histogram.
    
    Args:
        histogram: List of float/int, the bin counts.
        np1: Max peaks after global smoothing.
        np2: Final number of peaks to retain.
        
    Returns:
        List of Peak objects.
    """
    H = list(histogram) # Copy
    N = len(H)
    
    # Helper to find local extrema
    def find_extrema(arr):
        apices = []
        valleys = []
        for i in range(1, N - 1):
            if arr[i] > arr[i-1] and arr[i] > arr[i+1]:
                apices.append(i)
            elif arr[i] < arr[i-1] and arr[i] < arr[i+1]:
                valleys.append(i)
        return apices, valleys

    # Step 1: Selective Smoothing
    while True:
        apices, valleys = find_extrema(H)
        minimal_peaks_or_creases = []
        
        # Identify minimal peaks (valley-apex-valley) and creases (apex-valley-apex is NOT a crease per text "apex-valley-apex points" middle? 
        # Text: "middle of three directly adjacent valley-apex-valley or apex-valley-apex points"
        # This implies we look at triplets.
        # Let's iterate through all points and check their local context.
        
        for i in range(1, N - 1):
            is_apex = H[i] > H[i-1] and H[i] > H[i+1]
            is_valley = H[i] < H[i-1] and H[i] < H[i+1]
            
            # Check for valley-apex-valley
            if is_apex:
                # Check if neighbors are valleys
                left_is_valley = (i-1 == 0 or H[i-1] < H[i-2]) and (i-1 < N-1 and H[i-1] < H[i]) # Simplified check
                # Actually, simpler: check if i-1 is a valley and i+1 is a valley
                # We need to know if i-1 is a valley.
                left_is_valley = (i-1 > 0 and i-1 < N-1 and H[i-1] < H[i-2] and H[i-1] < H[i])
                right_is_valley = (i+1 > 0 and i+1 < N-1 and H[i+1] < H[i] and H[i+1] < H[i+2])
                
                if left_is_valley and right_is_valley:
                    minimal_peaks_or_creases.append(i)
            
            # Check for apex-valley-apex (Crease)
            elif is_valley:
                left_is_apex = (i-1 > 0 and i-1 < N-1 and H[i-1] > H[i-2] and H[i-1] > H[i])
                right_is_apex = (i+1 > 0 and i+1 < N-1 and H[i+1] > H[i] and H[i+1] > H[i+2])
                
                if left_is_apex and right_is_apex:
                    minimal_peaks_or_creases.append(i)
        
        if not minimal_peaks_or_creases:
            break
            
        # Apply smoothing to these points
        for i in minimal_peaks_or_creases:
            H[i] = 0.25 * H[i-1] + 0.5 * H[i] + 0.25 * H[i+1]

    # Step 2: Global Smoothing
    while True:
        apices, _ = find_extrema(H)
        if len(apices) <= np1:
            break
        # Apply smoothing to whole histogram
        new_H = [0] * N
        for i in range(1, N - 1):
            new_H[i] = 0.25 * H[i-1] + 0.5 * H[i] + 0.25 * H[i+1]
        # Boundary handling [G]
        new_H[0] = H[0]
        new_H[N-1] = H[N-1]
        H = new_H

    # Step 3: Peak Listing and Simplification
    apices, valleys = find_extrema(H)
    peaks = []
    
    # Construct peaks from apices and valleys
    # A peak is defined by an apex and its surrounding valleys.
    # We need to assign the correct valleys to each apex.
    sorted_valleys = sorted(valleys)
    sorted_apices = sorted(apices)
    
    for apex_idx in sorted_apices:
        # Find left valley: largest valley index < apex_idx
        left_valley = None
        for v in reversed(sorted_valleys):
            if v < apex_idx:
                left_valley = v
                break
        if left_valley is None:
            left_valley = 0 # [G] Default boundary
            
        # Find right valley: smallest valley index > apex_idx
        right_valley = None
        for v in sorted_valleys:
            if v > apex_idx:
                right_valley = v
                break
        if right_valley is None:
            right_valley = N - 1 # [G] Default boundary
            
        # Calculate Area
        # Base line: Start at highest valley with downward slope?
        # Text: "Start at the highest valley with a downward slope. Extend a straight line touching exactly one more point..."
        # This description is ambiguous for a single peak. Usually, base line connects the two bounding valleys.
        # However, the text specifies a specific construction.
        # "Start at the highest valley with a downward slope" -> This likely refers to the left valley if it slopes down from the apex?
        # Or it refers to the global minimum in the range?
        # Given the ambiguity and lack of explicit formula for the "touching point", we assume the standard base line between valleys for implementation simplicity, 
        # noting the source's specific geometric constraint might require iterative search.
        # For the purpose of this article, we define the base line as the linear interpolation between the left and right valleys.
        # Note: The source says "touching exactly one more point". If the histogram is convex/concave, the line between valleys might intersect the curve.
        # We will implement the standard area between curve and chord.
        
        area = 0.0
        # Linear interpolation between left_valley and right_valley
        x1, y1 = left_valley, H[left_valley]
        x2, y2 = right_valley, H[right_valley]
        
        for i in range(left_valley, right_valley + 1):
            # Line height at i
            if x2 == x1:
                line_y = y1
            else:
                line_y = y1 + (y2 - y1) * (i - x1) / (x2 - x1)
            
            area += abs(H[i] - line_y)
            
        peaks.append({
            'apex': apex_idx,
            'left_valley': left_valley,
            'right_valley': right_valley,
            'area': area,
            'height': H[apex_idx]
        })
        
    # Simplification
    while len(peaks) > np2:
        # Find peak with least area
        min_peak_idx = min(range(len(peaks)), key=lambda k: peaks[k]['area'])
        removed_peak = peaks.pop(min_peak_idx)
        
        # Extend neighbors
        # Find neighbors in the current list
        # Since we popped, indices shifted. We need to find which peaks were adjacent to the removed one.
        # We can't easily track adjacency in a list without a graph. 
        # Alternative: Re-evaluate adjacency based on position.
        
        # Let's assume we keep the list sorted by apex position.
        # Find the peak that was to the left of the removed peak
        left_neighbor = None
        right_neighbor = None
        
        # Re-scan to find neighbors of the removed peak's range
        # Actually, the text says "A peak neighboring the removed one".
        # We need to identify which peaks in the *current* list are spatially adjacent to the removed peak's location.
        
        # Since we removed it, we look at the peaks that are now adjacent in the sorted list?
        # No, the removal might have been from the middle.
        
        # Let's find the peak with the largest apex < removed_peak.apex
        # And the peak with the smallest apex > removed_peak.apex
        
        candidates_left = [p for p in peaks if p['apex'] < removed_peak['apex']]
        candidates_right = [p for p in peaks if p['apex'] > removed_peak['apex']]
        
        if candidates_left:
            left_neighbor = max(candidates_left, key=lambda p: p['apex'])
        if candidates_right:
            right_neighbor = min(candidates_right, key=lambda p: p['apex'])
            
        # Check if extending increases area
        # Extend left neighbor to cover removed peak
        # New right valley for left neighbor becomes left valley of removed peak? 
        # Or does it extend to the right valley of the removed peak?
        # Text: "extend a neighboring peak to cover the removed peak"
        # This implies the neighbor's range expands.
        
        best_neighbor = None
        max_area_gain = -1
        
        # Try extending left neighbor
        if left_neighbor:
            # New range: left_neighbor.left_valley to removed_peak.left_valley? 
            # Or to removed_peak.right_valley?
            # "Cover the removed peak" usually means absorbing its range.
            # If we extend left neighbor, its new right boundary becomes the left boundary of the removed peak?
            # Or does it merge?
            # Let's assume it extends to the *start* of the removed peak (left valley).
            # But the removed peak is gone.
            # Let's assume the neighbor expands to include the removed peak's apex and valleys.
            
            # Calculate new area for left neighbor if it extends to removed_peak.left_valley
            # Wait, if left neighbor is to the left, its right valley is currently < removed_peak.left_valley.
            # If it extends, its new right valley becomes removed_peak.left_valley?
            # This seems small.
            # Maybe it extends to removed_peak.right_valley?
            
            # Let's stick to the most logical interpretation: The neighbor absorbs the gap.
            # Left neighbor's new right valley = removed_peak.left_valley.
            
            old_right_valley = left_neighbor['right_valley']
            new_right_valley = removed_peak['left_valley']
            
            # Recalculate area
            new_area = 0.0
            x1, y1 = left_neighbor['left_valley'], H[left_neighbor['left_valley']]
            x2, y2 = new_right_valley, H[new_right_valley]
            
            for i in range(left_neighbor['left_valley'], new_right_valley + 1):
                if x2 == x1:
                    line_y = y1
                else:
                    line_y = y1 + (y2 - y1) * (i - x1) / (x2 - x1)
                new_area += abs(H[i] - line_y)
                
            gain = new_area - left_neighbor['area']
            if gain > max_area_gain:
                max_area_gain = gain
                best_neighbor = left_neighbor
                best_extension = 'right'
                best_new_right = new_right_valley

        # Try extending right neighbor
        if right_neighbor:
            # New left valley = removed_peak.right_valley
            new_left_valley = removed_peak['right_valley']
            
            old_left_valley = right_neighbor['left_valley']
            
            new_area = 0.0
            x1, y1 = new_left_valley, H[new_left_valley]
            x2, y2 = right_neighbor['right_valley'], H[right_neighbor['right_valley']]
            
            for i in range(new_left_valley, right_neighbor['right_valley'] + 1):
                if x2 == x1:
                    line_y = y1
                else:
                    line_y = y1 + (y2 - y1) * (i - x1) / (x2 - x1)
                new_area += abs(H[i] - line_y)
                
            gain = new_area - right_neighbor['area']
            if gain > max_area_gain:
                max_area_gain = gain
                best_neighbor = right_neighbor
                best_extension = 'left'
                best_new_left = new_left_valley
            elif gain == max_area_gain and best_neighbor:
                # Tie-breaker: largest peak height
                if right_neighbor['height'] > best_neighbor['height']:
                    best_neighbor = right_neighbor
                    best_extension = 'left'
                    best_new_left = new_left_valley

        # Apply extension
        if best_neighbor:
            if best_extension == 'right':
                best_neighbor['right_valley'] = best_new_right
                # Recalculate area for the updated neighbor
                new_area = 0.0
                x1, y1 = best_neighbor['left_valley'], H[best_neighbor['left_valley']]
                x2, y2 = best_neighbor['right_valley'], H[best_neighbor['right_valley']]
                for i in range(best_neighbor['left_valley'], best_neighbor['right_valley'] + 1):
                    if x2 == x1:
                        line_y = y1
                    else:
                        line_y = y1 + (y2 - y1) * (i - x1) / (x2 - x1)
                    new_area += abs(H[i] - line_y)
                best_neighbor['area'] = new_area
                
            elif best_extension == 'left':
                best_neighbor['left_valley'] = best_new_left
                new_area = 0.0
                x1, y1 = best_neighbor['left_valley'], H[best_neighbor['left_valley']]
                x2, y2 = best_neighbor['right_valley'], H[best_neighbor['right_valley']]
                for i in range(best_neighbor['left_valley'], best_neighbor['right_valley'] + 1):
                    if x2 == x1:
                        line_y = y1
                    else:
                        line_y = y1 + (y2 - y1) * (i - x1) / (x2 - x1)
                    new_area += abs(H[i] - line_y)
                best_neighbor['area'] = new_area

    return peaks
```

## Subtopics

### [TF adaptation peak selection](12678-tf-adaptation-peak-selection.md)
This method selects a single transfer function peak from the candidates detected by the Alpha-histogram Peak Analysis Scheme. It solves the problem of choosing the most relevant feature when multiple peaks exist. It differs from the parent scheme by enforcing a "valid range" constraint on the peak apex and using a confidence metric to break ties, ensuring the selected peak corresponds to a significant, spatially coherent structure rather than noise.

### Partial Range Histogram (PRH)
A variant histogram construction method where a separate histogram is created for each tissue, contrasting with the $\alpha$-histogram which highlights tissues at the global level. It is well-suited for detecting highly overlapping peaks. The main parameter is the range weight limit $\varepsilon$ (typical values: 0.6, 0.7, 0.8). A pitfall is that peak confidence is always very large and thus less useful, and the method is sensitive to $\varepsilon$, which can cause differing median errors.

## Operating characteristics
*   **Time Complexity:** The smoothing steps are $O(N \cdot K)$ where $N$ is the number of bins and $K$ is the number of smoothing iterations. The number of iterations depends on the noise level and $np1$. The simplification step is $O(P^2)$ where $P$ is the number of peaks after global smoothing.
*   **Memory Complexity:** $O(N)$ for the histogram and $O(P)$ for the peak list.
*   **Performance:** The scheme reduces the need for general smoothing, preserving subtle peaks. It is effective for MR angiography data sets.
*   **Strengths:** Automatic, robust against noise, preserves subtle peaks.
*   **Limitations:** Requires tuning of $np1$ and $np2$. The base line construction is geometrically complex to implement precisely as described.

## Background
The method was introduced by Ljung et al. in 2006 in the paper "The alpha-histogram: Using Spatial Coherence to Enhance Histograms and Transfer Function Design". It was developed to address the challenge of automatic Transfer Function design in volume rendering, specifically the noise in $\alpha$-histograms.
