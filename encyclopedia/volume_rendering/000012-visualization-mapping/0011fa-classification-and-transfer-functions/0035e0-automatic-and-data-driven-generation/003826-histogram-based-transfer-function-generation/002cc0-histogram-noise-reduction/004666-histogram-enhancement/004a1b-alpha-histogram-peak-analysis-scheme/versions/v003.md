# Alpha-histogram Peak Analysis Scheme

Also called: Automatic Peak Detection in Alpha-histogram, Peak Detection Scheme, Peak analysis scheme

## Overview
The Alpha-histogram Peak Analysis Scheme is an automatic algorithm for detecting significant tissue peaks in an $\alpha$-histogram to facilitate transfer function (TF) design in volume rendering [S1]. It solves the problem of noise-induced spurious peaks in the $\alpha$-histogram by combining selective smoothing with area-based importance assessment [S1]. It sets itself apart from its siblings by providing the specific iterative smoothing and simplification logic that reduces a noisy histogram to a manageable set of candidate peaks, which are then passed to [TF adaptation peak selection](12678-tf-adaptation-peak-selection.md) for final TF construction [S1, S2].

## How it works
**Inputs:** An $\alpha$-histogram (array of bin counts), parameters $np_1$ (max peaks after global smoothing) and $np_2$ (final number of peaks to retain).
**Outputs:** A list of detected peaks, where each peak is defined by its apex position, width (valleys), and area.

**Data Structures:**
*   `histogram`: Array of floats representing bin heights. Index $i$ corresponds to intensity value $i$.
*   `peak`: Object or tuple containing:
    *   `apex`: Index of the local maximum.
    *   `left_valley`: Index of the valley to the left.
    *   `right_valley`: Index of the valley to the right.
    *   `area`: Calculated importance metric.

**Definitions:**
*   **Apex:** An index $i$ such that $H[i] > H[i-1]$ and $H[i] > H[i+1]$.
*   **Valley:** An index $i$ such that $H[i] < H[i-1]$ and $H[i] < H[i+1]$.
*   **Minimal Peak/Crest:** A peak or valley surrounded by opposite extrema (e.g., Valley-Apex-Valley or Apex-Valley-Apex) where the middle element is a local extremum of lower significance than its neighbors in a way that suggests noise [S1].
*   **Smoothing Kernel:** $K = [0.25, 0.5, 0.25]$ (represented as `0.25 * [1 2 1]`) [S1].

**Algorithm Steps:**

1.  **Selective Smoothing:**
    Identify all "minimal peaks" or "creases". A minimal peak is an apex surrounded by two valleys (Valley-Apex-Valley). A crease is a valley surrounded by two apexes (Apex-Valley-Apex) [S1].
    Apply the smoothing kernel to the histogram bin corresponding to the middle element of these triplets.
    Repeat this process iteratively until no minimal peaks or creases remain in the histogram [S1].

2.  **Global Smoothing:**
    Apply the same smoothing kernel to the entire histogram array repeatedly.
    After each pass, count the number of remaining peaks (local maxima).
    Stop when the number of peaks equals or drops below $np_1$ (typically 20) [S1].

3.  **Peak Extraction and Simplification:**
    Extract all remaining peaks from the smoothed histogram. For each peak, identify its left and right valleys to define its range.
    Calculate the **Peak Area** for each peak:
    *   Find the "base line". Start at the highest valley with a downward slope relative to the peak apex.
    *   Extend a straight line from this valley touching exactly one other point on the histogram curve within the peak's range (the second touching point) [S1].
    *   Calculate the area as the sum of the height differences between the histogram curve and this base line between the two touching points (the start valley and the second touching point) [S1].
    *   Sort peaks by area in ascending order.
    *   Iteratively remove the peak with the smallest area until only $np_2$ peaks remain.
    *   When a peak is removed, extend the boundary of a neighboring peak to cover the removed peak's range if doing so increases the neighbor's area. If both neighbors would gain from an extension, select the neighbor with the largest peak height (apex value) [S1].

**Pseudocode:**

```python
def alpha_histogram_peak_analysis(histogram, np1=20, np2=4):
    """
    Detects significant peaks in an alpha-histogram.
    
    Args:
        histogram: List[float], bin counts of the alpha-histogram.
        np1: int, max peaks allowed after global smoothing.
        np2: int, final number of peaks to retain.
        
    Returns:
        List[Peak], where Peak is a dict with 'apex', 'left_valley', 'right_valley', 'area'.
    """
    
    # Helper: Apply binomial smoothing
    def smooth(hist):
        new_hist = list(hist)
        for i in range(1, len(hist) - 1):
            new_hist[i] = 0.25 * hist[i-1] + 0.5 * hist[i] + 0.25 * hist[i+1]
        return new_hist

    # Helper: Find all local maxima (peaks) and minima (valleys)
    def find_extrema(hist):
        peaks = []
        valleys = []
        for i in range(1, len(hist) - 1):
            if hist[i] > hist[i-1] and hist[i] > hist[i+1]:
                peaks.append(i)
            elif hist[i] < hist[i-1] and hist[i] < hist[i+1]:
                valleys.append(i)
        return peaks, valleys

    # Helper: Find valleys adjacent to a peak
    def find_peak_boundaries(peak_idx, valleys):
        # Find the closest valley to the left
        left_v = None
        for v in valleys:
            if v < peak_idx:
                left_v = v
            else:
                break
        
        # Find the closest valley to the right
        right_v = None
        for v in valleys:
            if v > peak_idx:
                right_v = v
                break
        return left_v, right_v

    # Step 1: Selective Smoothing
    # Repeat until no minimal peaks/creases remain
    changed = True
    while changed:
        changed = False
        peaks, valleys = find_extrema(histogram)
        
        # Identify minimal peaks (Valley-Apex-Valley) and creases (Apex-Valley-Apex)
        # A minimal peak is an apex where the adjacent valleys are "higher" in significance?
        # The source defines it as the middle of three directly adjacent valley-apex-valley or apex-valley-apex points.
        # We iterate through peaks and valleys to find these triplets.
        
        # Check for Valley-Apex-Valley triplets
        for i in range(len(valleys) - 1):
            v_left = valleys[i]
            v_right = valleys[i+1]
            # Find apex between them
            # Since peaks and valleys alternate, there should be one peak between two valleys
            # Find peak index between v_left and v_right
            p_idx = None
            for p in peaks:
                if v_left < p < v_right:
                    p_idx = p
                    break
            
            if p_idx is not None:
                # This is a minimal peak. Smooth it.
                histogram[p_idx] = 0.25 * histogram[p_idx-1] + 0.5 * histogram[p_idx] + 0.25 * histogram[p_idx+1]
                changed = True
        
        # Check for Apex-Valley-Apex triplets (Creases)
        for i in range(len(peaks) - 1):
            p_left = peaks[i]
            p_right = peaks[i+1]
            # Find valley between them
            v_idx = None
            for v in valleys:
                if p_left < v < p_right:
                    v_idx = v
                    break
            
            if v_idx is not None:
                # This is a crease. Smooth it.
                histogram[v_idx] = 0.25 * histogram[v_idx-1] + 0.5 * histogram[v_idx] + 0.25 * histogram[v_idx+1]
                changed = True

    # Step 2: Global Smoothing
    while True:
        peaks, _ = find_extrema(histogram)
        if len(peaks) <= np1:
            break
        histogram = smooth(histogram)

    # Step 3: Peak Extraction and Simplification
    peaks, valleys = find_extrema(histogram)
    peak_list = []
    
    for p_idx in peaks:
        left_v, right_v = find_peak_boundaries(p_idx, valleys)
        
        # Calculate Base Line and Area
        # Base line starts at the highest valley with a downward slope.
        # "Downward slope" implies the valley is lower than the peak.
        # We need to find the base line touching exactly one more point.
        
        # Identify the start valley: The highest valley with a downward slope.
        # In the context of a single peak, this is usually the left valley if it's lower than the right,
        # or the one that provides the "base". The source says "highest valley with a downward slope".
        # Let's assume we look at the valleys bounding the peak.
        
        # Simplification: The source figure 3 shows the base line connecting the left valley to a point on the right side.
        # Let's implement the area calculation as described:
        # 1. Start at the highest valley with a downward slope.
        # 2. Extend a straight line touching exactly one more point on the histogram curve within the peak range.
        
        # Determine start valley
        # If left_v and right_v exist:
        # "Highest valley with a downward slope" -> likely the valley from which the peak rises.
        # If left_v < right_v, left_v is the start. If right_v < left_v, right_v is the start?
        # Actually, "downward slope" from the valley perspective means going up to the peak.
        # Let's pick the valley that is lower, as it forms the base.
        
        start_v = None
        end_v = None
        
        if left_v is not None and right_v is not None:
            if histogram[left_v] <= histogram[right_v]:
                start_v = left_v
                end_v = right_v # The "second touching point" is the other valley
            else:
                start_v = right_v
                end_v = left_v
        elif left_v is not None:
            start_v = left_v
            end_v = len(histogram) - 1 # Fallback
        elif right_v is not None:
            start_v = right_v
            end_v = 0 # Fallback
        else:
            # No valleys found, peak is at boundary or flat
            continue

        # Calculate Area
        # Sum of height difference between histogram and base line between start_v and end_v
        area = 0.0
        # Base line equation: y = m*x + c
        # Points: (start_v, histogram[start_v]) and (end_v, histogram[end_v])
        # Note: The source says "touching exactly one more point". In a simple peak, the other valley is the natural touch point.
        
        x1, y1 = start_v, histogram[start_v]
        x2, y2 = end_v, histogram[end_v]
        
        if x2 == x1:
            continue
            
        m = (y2 - y1) / (x2 - x1)
        c = y1 - m * x1
        
        for x in range(start_v, end_v + 1):
            y_hist = histogram[x]
            y_base = m * x + c
            area += max(0, y_hist - y_base)
            
        peak_list.append({
            'apex': p_idx,
            'left_valley': left_v,
            'right_valley': right_v,
            'area': area
        })

    # Simplification: Reduce to np2 peaks
    while len(peak_list) > np2:
        # Find peak with least area
        min_peak_idx = 0
        min_area = peak_list[0]['area']
        for i in range(1, len(peak_list)):
            if peak_list[i]['area'] < min_area:
                min_area = peak_list[i]['area']
                min_peak_idx = i
        
        removed_peak = peak_list.pop(min_peak_idx)
        
        # Extend neighboring peak
        # Find neighbors in the original list (before pop, indices might shift)
        # We need to find the peaks adjacent to the removed peak in the sorted order of positions?
        # Or adjacent in the list? The source says "neighboring peak". Usually implies spatial adjacency.
        
        removed_apex = removed_peak['apex']
        
        # Find candidates for extension
        candidates = []
        for p in peak_list:
            p_apex = p['apex']
            # Check if p is spatially adjacent to removed_peak
            # Define adjacency: no other peak apex lies between them
            is_adjacent = True
            for other in peak_list:
                if other is p: continue
                other_apex = other['apex']
                # Check if other_apex is between removed_apex and p_apex
                if (removed_apex < other_apex < p_apex) or (p_apex < other_apex < removed_apex):
                    is_adjacent = False
                    break
            if is_adjacent:
                candidates.append(p)
        
        if not candidates:
            continue
            
        # Calculate potential new area for each candidate if it extends to cover removed_peak
        best_candidate = None
        best_gain = -1
        
        for c in candidates:
            # Extend c's range to include removed_peak's range
            # New left valley: min(c.left_valley, removed_peak.left_valley) if c is left of removed
            # New right valley: max(c.right_valley, removed_peak.right_valley) if c is right of removed
            
            # Determine direction
            if c['apex'] < removed_apex:
                # c is to the left
                new_left = c['left_valley']
                new_right = removed_peak['right_valley'] # Extend to removed's right valley?
                # Or just cover the removed peak's apex?
                # Source: "extend a neighboring peak to cover the removed peak"
                # This implies merging the ranges.
                new_left = min(c['left_valley'] if c['left_valley'] is not None else 0, 
                               removed_peak['left_valley'] if removed_peak['left_valley'] is not None else 0)
                new_right = max(c['right_valley'] if c['right_valley'] is not None else len(histogram)-1,
                                removed_peak['right_valley'] if removed_peak['right_valley'] is not None else len(histogram)-1)
            else:
                # c is to the right
                new_left = min(c['left_valley'] if c['left_valley'] is not None else 0,
                               removed_peak['left_valley'] if removed_peak['left_valley'] is not None else 0)
                new_right = max(c['right_valley'] if c['right_valley'] is not None else len(histogram)-1,
                                removed_peak['right_valley'] if removed_peak['right_valley'] is not None else len(histogram)-1)
            
            # Recalculate area for c with new boundaries
            # Note: This is a simplification. The source implies the area *would* increase.
            # We calculate the area of c over the new range [new_left, new_right]
            
            # Base line for the extended peak
            # Start at highest valley with downward slope in the NEW range?
            # This is complex. The source says "if its area would increase".
            # We approximate by checking if the new range includes the removed peak's mass.
            
            # Simplified check: Does the new range encompass the removed peak's apex?
            # If yes, the area likely increases.
            
            # Let's calculate the exact area for the candidate with the new boundaries
            # Find valleys for the candidate in the new range?
            # The candidate's valleys might change if the range expands.
            # For implementation simplicity, we assume the candidate's existing valleys are the bounds,
            # but we extend them to the removed peak's valleys.
            
            # Re-calculate area for candidate c with new_left and new_right
            # We need to find the "base line" for this new extended peak.
            # Start at highest valley with downward slope in [new_left, new_right].
            
            # Find valleys in the new range
            local_valleys = [v for v in valleys if new_left <= v <= new_right]
            if not local_valleys:
                continue
                
            # Find start valley: highest valley with downward slope
            # Downward slope from valley means going up to the peak.
            # So we look for a valley v such that histogram[v] < histogram[v+1] (going right)
            # or histogram[v] < histogram[v-1] (going left).
            # "Highest valley with a downward slope" -> The valley that is the base.
            
            start_v_ext = None
            for v in local_valleys:
                # Check if it has a downward slope towards the peak
                # If v < c['apex'], check right neighbor
                # If v > c['apex'], check left neighbor
                if v < c['apex']:
                    if v + 1 < len(histogram) and histogram[v] < histogram[v+1]:
                        if start_v_ext is None or histogram[v] > histogram[start_v_ext]:
                            start_v_ext = v
                elif v > c['apex']:
                    if v - 1 >= 0 and histogram[v] < histogram[v-1]:
                        if start_v_ext is None or histogram[v] > histogram[start_v_ext]:
                            start_v_ext = v
            
            if start_v_ext is None:
                continue
                
            # Find second touching point
            # Extend line from start_v_ext touching one more point in [new_left, new_right]
            # The second point is usually the other boundary valley or the peak itself?
            # Source: "touching exactly one more point on the histogram curve within the peak range"
            # Let's assume the other end of the range (new_right or new_left) is the touch point if it's a valley.
            
            end_v_ext = None
            if new_right <= c['apex']:
                end_v_ext = new_right
            elif new_left >= c['apex']:
                end_v_ext = new_left
            else:
                # The peak is inside. The other valley in the range is the touch point.
                # Find the valley on the other side of the peak
                if c['apex'] > start_v_ext:
                    # Look for valley to the right
                    right_valls = [v for v in local_valleys if v > c['apex']]
                    if right_valls:
                        end_v_ext = min(right_valls) # Closest to peak?
                    else:
                        end_v_ext = new_right
                else:
                    left_valls = [v for v in local_valleys if v < c['apex']]
                    if left_valls:
                        end_v_ext = max(left_valls)
                    else:
                        end_v_ext = new_left
                        
            if end_v_ext is None or end_v_ext == start_v_ext:
                continue
                
            # Calculate area
            x1, y1 = start_v_ext, histogram[start_v_ext]
            x2, y2 = end_v_ext, histogram[end_v_ext]
            
            if x2 == x1:
                continue
                
            m = (y2 - y1) / (x2 - x1)
            c_val = y1 - m * x1
            
            new_area = 0.0
            for x in range(start_v_ext, end_v_ext + 1):
                y_hist = histogram[x]
                y_base = m * x + c_val
                new_area += max(0, y_hist - y_base)
                
            gain = new_area - c['area']
            if gain > best_gain:
                best_gain = gain
                best_candidate = c
                best_candidate['new_area'] = new_area
                best_candidate['new_left'] = new_left
                best_candidate['new_right'] = new_right

        if best_candidate and best_gain > 0:
            # Update best_candidate
            best_candidate['area'] = best_candidate['new_area']
            best_candidate['left_valley'] = best_candidate['new_left']
            best_candidate['right_valley'] = best_candidate['new_right']
        else:
            # If no neighbor gains, just remove the peak
            pass

    return peak_list
```

**Parameters:**
*   $np_1$: Maximum number of remaining peaks after global smoothing. Typical value: 20 [S1].
*   $np_2$: Predefined number of peaks to retain after simplification. Typical values tested: 1, 2, 3, 4 [S1].

**Edge Cases and Pitfalls:**
*   **Intensity 0:** Intensity value 0 is often orders of magnitude more frequent and should be discarded from the histogram before processing [S1].
*   **Precision:** The smoothing operation uses floating-point arithmetic. Accumulated error over many iterations may require normalization or careful handling, though the binomial kernel is stable [S1].
*   **Boundary Conditions:** Peaks at the edges of the histogram (0 or max intensity) may not have both left and right valleys. The algorithm must handle these by extending to the histogram boundary or ignoring them if they are not "true" peaks [S1].
*   **Flat Regions:** If the histogram has flat regions (plateaus), the definition of apex/valley may fail. The source assumes distinct local extrema [S1].

## Subtopics

### [Partial Range Histogram (PRH)](12656-partial-range-histogram-prh.md)
The Partial Range Histogram (PRH) method creates separate histograms for individual tissues by analyzing local voxel neighborhoods, contrasting with the $\alpha$-histogram which enhances tissues at the global histogram level. It is specifically designed to detect highly overlapping peaks and expose minor tissue peaks that are obscured in the global histogram.

### [TF adaptation peak selection](12678-tf-adaptation-peak-selection.md)
This method selects a single transfer function (TF) peak from a set of candidate peaks detected in an $\alpha$-histogram or probability range histogram (PRH). It solves the problem of automatically choosing the most relevant feature density for volume rendering exploration when multiple local maxima exist. It differs from sibling methods by enforcing a "valid range" constraint on the peak apex and using a confidence metric to break ties, ensuring the selected peak corresponds to a significant, spatially coherent structure rather than noise or background.

### [Exhaustive Multiple-Peak Search](14136-exhaustive-multiple-peak-search.md)
Exhaustive Multiple-Peak Search is an automatic algorithm for detecting all tissue peaks in a global intensity histogram by iteratively identifying the highest peak, fitting a Gaussian, creating a Partial Range Histogram (PRH) for that peak's range, removing the PRH's contribution from the global histogram, and repeating until the histogram is empty. It sets itself apart from its sibling [Partial Range Histogram (PRH)](12656-partial-range-histogram-prh.md) by providing the iterative search strategy that utilizes PRHs as the core component for isolating distinct materials, and from [TF adaptation peak selection](12678-tf-adaptation-peak-selection.md) by focusing on the detection phase rather than the transfer function construction phase.

## Operating characteristics
*   **Time Complexity:** The algorithm involves iterative smoothing and peak extraction. The number of smoothing passes is bounded by $np_1$. Each pass is $O(N)$ where $N$ is the number of histogram bins. Peak extraction and simplification are $O(P \log P)$ or $O(P^2)$ where $P$ is the number of peaks. Overall complexity is dominated by smoothing, roughly $O(N \cdot K)$ where $K$ is the number of smoothing iterations.
*   **Memory Complexity:** $O(N)$ for storing the histogram and peak list.
*   **Measured Performance:** Evaluated on 20 MR AAA angiographies with a block size of $8^3$ [S1]. The method effectively reduces noise while preserving subtle peaks [S1].
*   **Strengths:** Automatically handles noise in $\alpha$-histograms; distinguishes significant peaks from noise using area-based importance; reduces the number of candidate peaks to a manageable set for TF design [S1].
*   **Limitations:** Requires tuning of $np_1$ and $np_2$; may merge closely spaced peaks if smoothing is too aggressive; assumes the $\alpha$-histogram is a good representation of tissue coherence [S1].
*   **When to use:** When automatic transfer function generation is needed for $\alpha$-histograms with significant noise [S1].
*   **When not to use:** When manual TF design is preferred; when the histogram is already clean and simple [S1].

## Background
The Alpha-histogram Peak Analysis Scheme was introduced by [S1] in the paper "The alpha-histogram: Using Spatial Coherence to Enhance Histograms and Transfer Function Design" (EuroVis 2006). It was developed to address the challenge of automatic transfer function design in volume rendering, specifically leveraging the spatial coherence information captured by the $\alpha$-histogram [S1]. The method builds on the $\alpha$-histogram Enhancement technique [Parent] to provide a robust peak detection mechanism [S1].
