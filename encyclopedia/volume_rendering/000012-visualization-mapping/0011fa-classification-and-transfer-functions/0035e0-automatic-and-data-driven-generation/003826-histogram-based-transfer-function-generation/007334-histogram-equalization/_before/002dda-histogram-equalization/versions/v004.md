# Histogram Equalization

Also called: Automatic Range Mapping, CDF-based Normalization

## Overview
Histogram Equalization is an automatic technique that redistributes scalar values by spreading out clustered regions of the data distribution to achieve a uniform output distribution [S1, unofficial]. It solves the problem of visualizing high dynamic range (HDR) data where features are hidden in dense spikes of the scalar histogram, by mapping input values to a normalized range where every intensity level is equally probable [S1, unofficial]. Unlike its sibling method, [Range Mapping](5650-range-mapping.md), which uses piecewise linear functions to provide user control and maintain continuity, Histogram Equalization is fully automatic and tends to break the continuity of the scalar range [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: A normalized scalar value $x$ from the volume data, typically in the range $[0, 1]$.
*   Output: A new normalized scalar value $y$ in the range $[0, 1]$, representing the cumulative probability of the input.

**Data Structures:**
*   **Histogram:** A discrete array representing the Probability Density Function (PDF). Let $N$ be the number of bins. The histogram $H$ stores the count of voxels falling into each bin.
*   **CDF Array:** An array of size $N$ storing the cumulative sums of the histogram bins.

**Steps:**
1.  **Compute PDF:** Count the occurrences of each scalar value (or binned value) in the dataset to form the Probability Density Function. If $n_i$ is the number of voxels in bin $i$ and $N_{total}$ is the total number of voxels, the probability $p_i$ for bin $i$ is:
    $$ p_i = \frac{n_i}{N_{total}} $$
2.  **Compute CDF:** Calculate the Cumulative Distribution Function by summing the probabilities. For a normalized scalar input $x_i$ corresponding to bin $i$, the CDF value is:
    $$ CDF(x_i) = \sum_{x_j < x_i} PDF(x_j) $$
    In discrete terms, if $CDF[i]$ is the value for bin $i$:
    $$ CDF[i] = \sum_{k=0}^{i} p_k $$
    Note: The source formula $\sum_{x_j < x_i}$ implies a strict inequality, but in standard discrete histogram equalization implementations, the CDF at index $i$ usually includes the probability of bin $i$ itself to map the bin's range to the upper end of the output interval. However, adhering strictly to the source notation [S1, unofficial], the sum is over $x_j < x_i$. To ensure the full range $[0,1]$ is covered, the final output is typically normalized by the maximum CDF value.
3.  **Map Input to Output:** Perform the mapping on the normalized scalar input $x$ to yield the uniformly distributed output $y$:
    $$ y = CDF(x) $$
    If using a discrete lookup table (LUT) for performance, the value $y$ is retrieved directly from the precomputed CDF array corresponding to the bin of $x$.

**Parameters:**
*   Number of bins $N$: Not given in the sources. Typically determined by the bit depth of the scalar data or chosen to balance resolution and noise.

**Edge Cases and Pitfalls:**
*   **Loss of Continuity:** The method tends to break the continuities of the scalar range, potentially introducing visual artifacts where smooth gradients in the data become discontinuous in the visualization [S1, unofficial].
*   **Lack of Control:** It provides the user with very little control over the redistribution process, as the mapping is entirely data-driven [S1, unofficial].
*   **Noise Amplification:** In regions with sparse data (low PDF), small variations can lead to large jumps in the CDF, amplifying noise. This is not explicitly detailed in the notes but is a known consequence of the "spreading out" mechanism described in [S1, unofficial].

**Pseudocode:**
```python
def histogram_equalization(scalar_data, num_bins):
    """
    Performs histogram equalization on scalar data.
    
    Args:
        scalar_data: 1D array of normalized scalar values in [0, 1].
        num_bins: Integer, number of bins for the histogram.
        
    Returns:
        equalized_data: 1D array of equalized values in [0, 1].
        cdf: 1D array of size num_bins, the cumulative distribution function.
    """
    # Step 1: Compute Histogram (PDF)
    # Initialize histogram bins
    histogram = [0] * num_bins
    
    # Count occurrences
    for value in scalar_data:
        # Map value [0, 1] to bin index [0, num_bins - 1]
        # Clamp to ensure valid index
        bin_index = int(value * num_bins)
        if bin_index >= num_bins:
            bin_index = num_bins - 1
        histogram[bin_index] += 1
        
    # Normalize to get PDF
    total_voxels = len(scalar_data)
    pdf = [count / total_voxels for count in histogram]
    
    # Step 2: Compute CDF
    # Source formula: CDF(xi) = sum(PDF(xj) for xj < xi)
    # We implement this as a cumulative sum. 
    # Note: Standard practice often includes the current bin in the sum for the upper bound.
    # To strictly follow the source's "xj < xi" notation, we might exclude the current bin,
    # but this would map the lowest bin to 0 and potentially leave gaps.
    # A common interpretation for equalization is CDF[i] = sum(pdf[0]...pdf[i]).
    # We will use the standard cumulative sum including the current bin to ensure full range coverage,
    # as implied by the goal of "uniformly distributed normalized output".
    cdf = [0] * num_bins
    cumulative_sum = 0.0
    for i in range(num_bins):
        cumulative_sum += pdf[i]
        cdf[i] = cumulative_sum
        
    # Normalize CDF to [0, 1] if the sum is not exactly 1.0 due to floating point
    max_cdf = cdf[-1]
    if max_cdf > 0:
        cdf = [val / max_cdf for val in cdf]
        
    # Step 3: Map Input to Output
    equalized_data = [0.0] * len(scalar_data)
    for i, value in enumerate(scalar_data):
        bin_index = int(value * num_bins)
        if bin_index >= num_bins:
            bin_index = num_bins - 1
        equalized_data[i] = cdf[bin_index]
        
    return equalized_data, cdf
```

## Subtopics

### [Range Mapping](5650-range-mapping.md)
Range mapping is a technique that redistributes scalar values non-linearly to spread regions of interest evenly across a fixed-size lookup table, addressing the resolution limitations of hardware lookup tables for high dynamic range (HDR) data. Unlike its sibling method, [Histogram Equalization](5642-histogram-equalization.md), which automatically redistributes values and breaks continuity, range mapping uses piecewise linear functions to provide user control while maintaining the continuity and order of the scalar range. It exploits the non-linear shape of the histogram to magnify specific data clusters, allowing users to focus on narrow clusters of scalar values without the resolution artifacts inherent in fixed-size textures.

### [Histogram Population (Normal & Equalized)](15394-histogram-population-normal-equalized.md)
Histogram Population generates the underlying intensity distribution data structures required for transfer function generation in volume rendering. It solves the problem of converting raw scalar voxel values into a normalized, visualizable format (line segments) that represents either the raw frequency of intensities (Normal) or their cumulative distribution (Equalized). It differs from its parent [Histogram Equalization](5642-histogram-equalization.md) by focusing on the construction of the histogram geometry itself rather than just the remapping logic, and from [Range Mapping](5650-range-mapping.md) by providing the binned density data necessary for automatic transfer function design.

### Histogram Stretching with Percentile Clipping
Histogram Stretching with Percentile Clipping is a post-processing step to create a balanced RGB image by suppressing high intensity outliers caused by constructive interference phenomena inherent to diffraction [S2]. Percentile clipping is applied to suppress high intensity outliers. The maximum intensity $I_{max}$ per color channel is determined by the maximum intensity value after clipping the higher values belonging to the high 0.15 percentile [S2]. Histogram stretching modifies the intensity range using the formula: $I(x, y) = \frac{I(x, y) - I_{min}}{I_{max} - I_{min}}$, where $I_{min}$ and $I_{max}$ are the minimum and maximum values of the intensity respectively [S2].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for computing the histogram and CDF, where $N$ is the number of voxels. The mapping step is also $O(N)$ or $O(1)$ per voxel if using a lookup table.
*   **Memory Complexity:** $O(N)$ for storing the input and output data. $O(B)$ for the histogram and CDF, where $B$ is the number of bins.
*   **Strengths:** Simple, fast, and automatic. Effective at enhancing features hidden in clustered data regions [S1, unofficial].
*   **Limitations:** Breaks continuity of the scalar range, leading to potential visual artifacts. Provides no user control over the specific redistribution [S1, unofficial].
*   **When to use:** When automatic enhancement of HDR data is needed and user control is not required.
*   **When not to use:** When maintaining the continuity of the scalar range is critical, or when user control over the transfer function is desired (use [Range Mapping](5650-range-mapping.md) instead).

## Background
Histogram Equalization was introduced as an automatic approach to redistribute scalar values by spreading out clustered regions, used as a basis for range mapping but providing less user control [S1, unofficial]. It is commonly used in volume rendering to handle high dynamic range (HDR) data, where the non-uniform distribution of scalar values makes feature visualization difficult [S1, unofficial]. The method is described in the context of earthquake simulation and other scientific simulations [S1, unofficial].
