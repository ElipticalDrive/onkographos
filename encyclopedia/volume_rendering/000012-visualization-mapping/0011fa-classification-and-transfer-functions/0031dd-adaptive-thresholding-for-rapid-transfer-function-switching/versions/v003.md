# Adaptive Thresholding for Rapid Transfer Function Switching

Also called: Density encoding scheme, Two-bit cell coding

## Overview
Adaptive Thresholding for Rapid Transfer Function Switching is a classification optimization that enables instant switching between a fixed set of predefined transfer functions without re-evaluating voxel data or re-classifying the volume [S1, unofficial]. Unlike standard pre-classification which requires re-computation when opacity thresholds change, this method pre-computes a two-bit code per voxel cell based on density intervals, allowing the renderer to skip transparent cells by simply changing a lookup table pointer [S1, unofficial].

## How it works
**Inputs:**
*   A scalar volume dataset $V$ with density values [S1, unofficial].
*   A set of $N$ predefined transfer functions, each defined by a lower density threshold [S1, unofficial].
*   A rendering ray traversal routine (e.g., Depth routine) [S1, unofficial].

**Outputs:**
*   A pre-computed two-bit code array $C$ of size $D_x \times D_y \times D_z$ [S1, unofficial].
*   A set of Lookup Tables (LUTs) for rapid cell skipping [S1, unofficial].

**Data Structures:**
1.  **Code Array ($C$):** An integer array where each element stores a 2-bit code for a corresponding voxel cell [S1, unofficial]. The array is packed such that codes are contiguous but must be treated as atomic 2-bit units during memory operations [S1, unofficial].
2.  **Lookup Table (LUT):** A small table mapping byte patterns to bit offsets [S1, unofficial]. For a specific transfer function, the LUT contains the offset of the first occurrence of the required non-transparent bit pattern (e.g., '10' or '11') within a byte [S1, unofficial].

**Numbered Steps:**
1.  **Define Intervals:** Define $N$ transfer functions, each with a lower density threshold [S1, unofficial]. These thresholds divide the density domain into intervals $I_0, I_1, \dots, I_N$ sorted in ascending order [S1, unofficial].
2.  **Assign Codes:** Assign a unique two-bit binary code to each interval, corresponding to the binary format of the interval index [S1, unofficial].
3.  **Compute Cell Codes:** For each cell, determine the code based on the interval containing the highest corner voxel density [S1, unofficial].
4.  **Store and Shear:** Store these two-bit codes in an integer array and shear this array during transformation [S1, unofficial]. When applying shear transformations, the two bits of a code must be moved together as a unit to avoid the cutting of the codes [S1, unofficial].
5.  **Rendering (LUT Selection):** During rendering, the Depth routine uses a lookup table determined by the current transfer function's bit pattern to search for the first non-transparent cell [S1, unofficial]. When the user changes the transfer function, update the LUT pointer to the address of the corresponding lookup table [S1, unofficial].

**Formulas:**
Let $v_{\max}(\mathbf{c})$ be the maximum density value among the corner voxels of cell $\mathbf{c}$. The cell code $C(\mathbf{c})$ is assigned as:
$$C(\mathbf{c}) = k \quad \text{if} \quad v_{\max}(\mathbf{c}) \in I_k$$
where $k \in \{0, 1, \dots, N\}$ is the interval index [S1, unofficial].

**Parameters:**
*   **Number of Transfer Functions ($N$):** The source example uses $N=3$, creating 4 intervals ($I_0$ to $I_3$) and 2-bit codes [S1, unofficial].
*   **LUT Configuration:** Contains bit offsets of the first matching bit pattern (e.g., '10' or '11') inside a given byte for the selected transfer function [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Bit Alignment:** When shearing the code array, the two bits of a code must be moved together to avoid cutting the codes [S1, unofficial].
*   **Interval Limit:** The 2-bit encoding restricts the number of transfer functions to 4 (indices 0-3) [S1, unofficial].
*   **Threshold Sorting:** Thresholds must be strictly sorted in ascending order to ensure correct interval assignment [S1, unofficial].

**Pseudocode:**
```python
def precompute_codes(volume, thresholds):
    """Pre-compute two-bit codes per cell based on highest corner voxel density."""
    # volume: 3D array of densities
    # thresholds: sorted list of lower density thresholds [T0, T1, ...]
    codes = [[[0] * volume.shape[2] for _ in range(volume.shape[1])] for _ in range(volume.shape[0])]
    for x in range(volume.shape[0]):
        for y in range(volume.shape[1]):
            for z in range(volume.shape[2]):
                v = volume[x][y][z]  # Highest corner voxel density for the cell
                k = 0
                for i, t in enumerate(thresholds):
                    if v >= t:
                        k = i + 1
                    else:
                        break
                codes[x][y][z] = k
    return codes

def apply_shear(codes, shear_matrix):
    """Shear the code array. Two bits of each code must be moved together as a unit."""
    # Standard geometric shear applied to cell coordinates [G]
    # Implementation must ensure the two bits of a code are moved together to avoid cutting [S1, unofficial]
    sheared = [[[0] * codes[0][0].__len__() for _ in range(codes[0].__len__())] for _ in range(codes.__len__())]
    for x in range(codes.__len__()):
        for y in range(codes[0].__len__()):
            for z in range(codes[0][0].__len__()):
                sx, sy, sz = x + shear_matrix[0]*y, y + shear_matrix[1]*z, z
                if 0 <= sx < codes.__len__() and 0 <= sy < codes[0].__len__() and 0 <= sz < codes[0][0].__len__():
                    sheared[sx][sy][sz] = codes[x][y][z]
    return sheared

def build_lut(non_transparent_codes):
    """Build LUT containing bit offsets of first matching bit pattern inside a byte."""
    # LUT maps byte values to the offset of the first matching 2-bit pattern [S1, unofficial]
    lut = [0] * 256
    for byte_val in range(256):
        for offset in range(4): # 4 codes per byte (2 bits each)
            pattern = (byte_val >> (offset * 2)) & 0x03
            if pattern in non_transparent_codes:
                lut[byte_val] = offset
                break
    return lut

def depth_routine(codes, ray_origin, ray_direction, tf_index, lut):
    """Find first non-transparent cell along ray using LUT."""
    # Determine which codes are non-transparent for the selected TF
    non_transparent_codes = [tf_index, tf_index + 1] # Example pattern mapping [G]
    # Traverse cells along ray direction
    for cell in ray.traverse_cells(codes.shape):
        code = codes[cell.x][cell.y][cell.z]
        if code in non_transparent_codes:
            return cell
    return None
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   For a $128 \times 128 \times 113$ volume with low opacity TFs:
        *   Cell size 1: TF A takes 0.36s, TF B 0.19s, TF C 0.18s [S1, unofficial].
        *   Cell size 2: TF A 0.39s, TF B 0.21s, TF C 0.21s [S1, unofficial].
        *   Cell size 4: TF A 0.51s, TF B 0.32s, TF C 0.31s [S1, unofficial].
    *   For a $256 \times 256 \times 225$ volume with low opacity TFs:
        *   Cell size 1: TF A 1.97s, TF B 1.02s, TF C 0.99s [S1, unofficial].
        *   Cell size 2: TF A 1.93s, TF B 1.01s, TF C 0.96s [S1, unofficial].
        *   Cell size 4: TF A 2.44s, TF B 1.45s, TF C 1.46s [S1, unofficial].
    *   Performance is largely independent of the selected transfer function for skipping, as the LUT pointer change is $O(1)$ [S1, unofficial].
*   **Strengths:** Rapid switching between predefined TFs; no re-classification needed; efficient skipping of transparent cells [S1, unofficial].
*   **Limitations:** Limited to 4 intervals (3 thresholds); requires pre-computation; less flexible than dynamic TF evaluation for arbitrary thresholds [S1, unofficial].
*   **When to Use:** When a small, fixed set of transfer functions is used frequently (e.g., medical imaging with standard tissue types like air, fat, soft tissue, bone) and rapid switching is required [S1, unofficial].
*   **When Not to Use:** When the number of transfer functions exceeds 4, or when thresholds are dynamic/user-defined in real-time [S1, unofficial].

## Subtopics
*   **Binary Classification [6229-binary-and-soft-classification.md]:** Uses hard thresholds for inclusion/exclusion. Adaptive Thresholding extends this by pre-computing interval codes to support multiple binary-like switches without re-classification [S1, unofficial].
*   **Pre-classification [6103-pre-classification.md]:** Applies transfer functions before sampling. Adaptive Thresholding is a form of pre-classification that optimizes the lookup process for multiple TFs [S1, unofficial].
*   **1D Lookup Table with Interpolation [2528-1d-lookup-table-with-interpolation.md]:** Standard method for evaluating TFs. Adaptive Thresholding replaces the per-sample TF evaluation with a code-based skip mechanism [S1, unofficial].

## Background
The method was proposed in the context of fast volume rotation and rendering techniques for medical data visualization [S1, unofficial]. It addresses the limitation of pre-classified binary volumes where the opacity function cannot be modified flexibly [S1, unofficial]. The technique is particularly relevant in medical imaging where densities can be separated into a few distinct materials (e.g., air, fat, soft tissue, bone) based on Hounsfield units [S1, unofficial]. It was implemented in C++ and tested on an SGI Indy workstation [S1, unofficial].
