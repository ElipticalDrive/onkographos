# Transparency Compositing Formula

Also called: Alpha Blending Formula, Alpha Compositing (1-A)*B, Blend1 Compositing, C_out = C_in * (1 - α) + C * α, Over-Under Blend

## Overview
The Transparency Compositing Formula computes the resulting color and opacity when a foreground voxel blends with a background accumulation, typically used for over-compositing in volume rendering where the foreground alpha represents opacity. It sets itself apart from sibling methods like [CTF Color Blending](14808-ctf-color-blending.md) by strictly following the standard Porter-Duff "over" operator logic rather than perceptual or harmonization models.

## How it works
**Inputs and Outputs:**
*   $C_{in}$: Incoming intensity/color from previous voxels along the ray.
*   $C(X_i)$: Shading/color calculated for the current voxel $X_i$, typically derived from the local gradient and lighting [S1, unofficial].
*   $\alpha(X_i)$: Opacity (light impermeability) of the current voxel, calculated from the underlying data value (e.g., CT value) [S1, unofficial].
*   $C_{out}$: Outgoing intensity/color after compositing the current voxel.

**Data Structures:**
The method operates on scalar or vector values representing color and opacity. In grid-based implementations (e.g., OpenVDB), values may be multiplied by a grid-specific multiplier `aMult` and combined with a constant `ONE` of the grid's `ValueT` type [S2, unofficial].

**Formula:**
The standard compositing equation is:
$$ C_{out} = C_{in} \cdot (1 - \alpha(X_i)) + C(X_i) \cdot \alpha(X_i) $$

In grid-based implementations using multipliers:
$$ \text{out} = (\text{ONE} - \text{aMult} \cdot \alpha) \cdot \text{bMult} \cdot C + C \cdot (\text{aMult} \cdot \alpha) $$
Where `aMult` is a multiplier for the alpha value (default 1.0) and `bMult` is a multiplier for the color [S2, unofficial].

**Steps:**
1.  Sample the voxel at position $X_i$ along the ray to obtain its color $C(X_i)$ and opacity $\alpha(X_i)$.
2.  Compute the contribution of the current voxel: $C_{contrib} = C(X_i) \cdot \alpha(X_i)$.
3.  Compute the transmission of the incoming color: $C_{trans} = C_{in} \cdot (1 - \alpha(X_i))$.
4.  Sum the contributions: $C_{out} = C_{trans} + C_{contrib}$.
5.  Update the accumulated opacity if tracking it: $\alpha_{out} = \alpha_{in} + \alpha(X_i) \cdot (1 - \alpha_{in})$ [G].
6.  Recursively apply this formula along the ray until an alpha value of 0 is hit (e.g., hitting light-impermeable tissue like bone) or the ray exits the volume [S1, unofficial].

**Parameters:**
*   `aMult`: Multiplier for grid A value. Default 1.0 [S2, unofficial].
*   `ONE`: Constant value 1.0 of the grid's ValueT type [S2, unofficial].

**Edge Cases and Pitfalls:**
*   Precision: Floating-point precision errors can accumulate during recursive application along long rays [G].
*   Boundaries: The formula assumes the ray enters the volume with $C_{in}=0$ and $\alpha_{in}=0$ [G].
*   Implementation Gap: Some raycasters do not implement this transparency formula, offering only images without transparency [S1, unofficial].

## Subtopics

### Additive Color Blending
A simple additive blending mode for combining brush color and canvas color, primarily used in 3D painting applications rather than volume rendering compositing. It differs from the standard over-operator by defining output opacity as the sum of opacities and modulating color mixing based on relative alpha weights.
**Formula:**
Output Color: $C_{out} = B_{rgb} \cdot m + (1 - m) \cdot C_{rgb}$
Output Opacity: $C_{out, \alpha} = B_{\alpha} + C_{\alpha}$
Where $m = B_{\alpha} / (B_{\alpha} + C_{\alpha})$, $B_{rgb}, B_{\alpha}$ are brush RGB and alpha, and $C_{rgb}, C_{\alpha}$ are canvas RGB and alpha [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel sample.
*   **Memory Complexity:** $O(1)$ auxiliary memory per ray.
*   **Strengths:** Physically plausible for translucent media; standard in volume rendering pipelines.
*   **Limitations:** Does not account for subsurface scattering or complex light transport; requires accurate opacity estimation.
*   **When to use:** Standard volume visualization where translucency is desired.
*   **When not to use:** When additive mixing is preferred (e.g., certain painting tools) or when performance constraints prevent recursive accumulation.

## Background
The formula is a direct application of the Porter-Duff "over" compositing operator, widely adopted in computer graphics for alpha blending. In the context of volume rendering, it is used to accumulate color and opacity along rays cast through volumetric data. The specific implementation details involving grid multipliers (`aMult`, `bMult`) appear in grid manipulation libraries like OpenVDB [S2, unofficial]. The recursive application along rays until opacity 0 is hit is a common optimization in raycasting, though not all implementations support it [S1, unofficial].
