# Gradient-Based Color Table Filtering


## Overview
Gradient-Based Color Table Filtering addresses the aliasing artifacts that occur when sampling a 1D color table for procedural noise functions. It refines the basic interval-based filtering by incorporating the local gradient of the noise function to determine the appropriate sampling interval, thereby reducing high-frequency noise in the final image [S1]. It distinguishes itself from simpler methods like [Windowing](6611-windowing.md) by dynamically adjusting the filter width based on the local rate of change of the noise, rather than using a fixed spatial or value-based window.

## How it works
The method computes a filtered color by evaluating the color table over a value interval centered on the noise value. The width of this interval is determined by the filter size and the local gradient of the noise function.

**Inputs:**
*   $u$: The procedural noise value at the current sample point.
*   $C(v)$: The 1D color table function, mapping value $v$ to a color.
*   $\nabla N(u)$: The local gradient (derivative) of the noise function $N$ with respect to its input.
*   $h$: The filter size (or step size) used in the rendering process.

**Outputs:**
*   $C_{filtered}$: The anti-aliased color value.

**Data Structures:**
*   The color table is typically stored as a 1D texture or array to allow for efficient interpolation (e.g., via MIP-mapping) [S1].

**Steps:**
1.  Compute the local gradient $\nabla N(u)$ of the noise function. This can be done analytically if the noise function is differentiable, or via finite differencing [S1].
2.  Calculate the value interval width $\delta$. The interval is defined as $[u - \delta, u + \delta]$. The value of $\delta$ is computed based on the filter size $h$ and the magnitude of the gradient $|\nabla N(u)|$. Specifically, $\delta$ scales with the gradient to ensure that the interval covers the range of noise values that will be sampled by the filter kernel [S1].
3.  Evaluate the color table $C(v)$ over the interval $[u - \delta, u + \delta]$. This is conveniently implemented using MIP-mapping on the 1D color table, where the MIP level corresponds to the interval width $\delta$ [S1].
4.  Return the color sampled from the MIP-mapped color table at the center value $u$ [S1].

**Pitfalls:**
*   A significant source of error is that the noise value $u$ and its gradient $\nabla N(u)$ are evaluated on the *unfiltered* noise. This can lead to inaccuracies if the filtering process significantly alters the effective noise distribution [S1].

**Pseudocode:**
```python
def gradient_based_color_table_filtering(u, noise_gradient, color_table_mipmap, filter_size):
    """
    u: float, the noise value at the current point
    noise_gradient: float, the magnitude of the gradient of the noise function at u
    color_table_mipmap: object, 1D color table with MIP levels
    filter_size: float, the spatial filter size h
    """
    # Step 1: Compute delta based on filter size and gradient
    # The interval width delta must cover the range of values
    # affected by the filter. The source implies delta is derived
    # from the filter size and the maximum gradient.
    # A common formulation for the value domain interval width
    # given a spatial step h and gradient g is delta = h * |g|.
    delta = filter_size * abs(noise_gradient)
    
    # Step 2: Evaluate color table over [u - delta, u + delta]
    # Using MIP-mapping: the MIP level is chosen such that the
    # texel width corresponds to delta.
    # The color is sampled at the center u.
    filtered_color = color_table_mipmap.sample_level(u, delta)
    
    return filtered_color
```

## Subtopics

### Variance-Based Color Table Filtering
This variant achieves accurate filtering by estimating the noise value range $\delta$ from the loss in noise variance due to filtering, rather than using the gradient directly. This approach relies on the availability of an analytical expression for the noise variance [S1]. It is chosen when the noise function's variance is known analytically and provides a more robust estimate of the filtering interval in cases where gradient computation is difficult or inaccurate.

## Operating characteristics
*   **Time Complexity:** The method requires computing the noise gradient, which adds computational cost compared to simple lookup. However, the color table evaluation remains efficient via MIP-mapping.
*   **Memory Complexity:** Requires storage for the 1D color table and its MIP levels.
*   **Strengths:** Reduces aliasing artifacts more effectively than fixed-interval filtering by adapting to local noise frequency.
*   **Limitations:** The error introduced by evaluating the gradient on unfiltered noise can affect accuracy. Requires differentiable noise functions or finite differencing, which may be noisy.
*   **When to use:** When rendering procedural noise textures with color tables and aliasing is visible.
*   **When not to use:** When the noise function is not differentiable and finite differencing is too expensive or unstable.

## Background
The method was introduced by Hart et al. [HCK99] as a refinement to earlier color table filtering approaches. It builds on the idea of evaluating the color table over an interval to anti-alias the transfer function. The approach was later analyzed and compared with other methods, such as those by Lagae et al. [LLDD09a], in the context of procedural noise function filtering [S1].
