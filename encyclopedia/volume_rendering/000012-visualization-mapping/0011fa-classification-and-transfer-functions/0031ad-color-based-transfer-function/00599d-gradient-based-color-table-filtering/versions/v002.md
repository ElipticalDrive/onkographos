# Gradient-Based Color Table Filtering


## Overview
Gradient-Based Color Table Filtering is a technique for accurately filtering color table-based textures by using the local noise gradient to determine the appropriate filtering interval [S2]. It addresses the error introduced when noise values and gradients are evaluated on unfiltered noise, which is a common source of inaccuracy in procedural noise rendering [S1]. Unlike methods that rely on affine arithmetic or shader simplification, this approach leverages the differentiability of noise functions to compute a precise range of color table indices [S2].

## How it works
**Inputs:**
1.  A procedural noise function $N(u)$, where $u$ is the input coordinate [S2].
2.  A 1D color table $C$, mapping noise values to colors [S2].
3.  The filter size (or footprint) over which the color table is sampled [S2].

**Outputs:**
1.  A filtered color value for the given pixel/voxel [S2].

**Data Structures:**
*   **Color Table ($C$):** A 1D texture or array mapping scalar noise values to RGB(A) colors.
*   **Noise Function ($N$):** A differentiable function returning a scalar value [S2].

**Steps:**
1.  **Evaluate Noise:** Compute the noise value $N(u)$ at the current coordinate $u$ [S2].
2.  **Compute Gradient:** Compute the local gradient of the noise function, $\nabla N(u)$, at $u$ [S2]. This can be done via finite differencing or analytically, as most procedural noises are differentiable [S1, S2].
3.  **Determine Interval Size ($\delta$):** Calculate the size of the interval $[N(u) - \delta, N(u) + \delta]$ based on the filter size and the magnitude of the local noise gradient [S2]. The gradient determines how much the noise value varies across the filter footprint, thus defining the range of color table indices that must be sampled [S2].
4.  **Sample Color Table:** Evaluate the color table $C$ over the interval $[N(u) - \delta, N(u) + \delta]$ [S2]. This is conveniently implemented using MIP-mapping on the 1D color table, where the MIP level corresponds to the interval size $\delta$ [S2].
5.  **Return Color:** Return the filtered color result [S2].

**Formulas:**
*   Interval: $[N(u) - \delta, N(u) + \delta]$ [S2].
*   $\delta$ computation: $\delta$ is computed from the filter size and the maximum gradient of $C$ with respect to $u$ [S2]. Specifically, it scales with the local noise gradient magnitude $|\nabla N(u)|$ [S2].

**Parameters:**
*   Filter size: Determines the base resolution of the MIP level [S2].
*   Gradient computation method: Finite differencing or analytical derivative [S1, S2].

**Edge Cases and Pitfalls:**
*   **Unfiltered Noise Evaluation:** A source of error is that the noise value $N(u)$ and gradient $\nabla N(u)$ are evaluated on the unfiltered noise [S1, S2]. This can lead to inaccuracies if the noise function varies significantly within the filter footprint [S1, S2].
*   **Non-differentiable Noise:** If the noise function is not differentiable, analytical gradients cannot be used, and finite differencing must be employed, which may introduce numerical instability [S2].

## Subtopics

### Gradient-Aware Color Table Filtering
An refinement by Hart et al. of color table filtering that uses the local noise gradient to improve accuracy [S2]. A source of error is that the noise value and gradient are evaluated on the unfiltered noise [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   Time complexity depends on the cost of evaluating the noise function and its gradient, plus the cost of sampling the MIP-mapped color table [S2].
*   Memory complexity is dominated by the storage of the color table and its MIP levels [S2].

**Measured Performance:**
*   Not given in the sources.

**Scaling:**
*   Not given in the sources.

**Strengths and Limitations:**
*   **Strengths:** Provides accurate filtering by adapting to the local variation of the noise function [S2].
*   **Limitations:** Error arises from evaluating noise and gradient on unfiltered noise [S1, S2]. Requires differentiable noise functions [S2].

**When to use it and when not:**
*   Use when accurate filtering of procedural noise textures is required and the noise function is differentiable [S2].
*   Do not use when the noise function is not differentiable and finite differencing is insufficient, or when high performance is critical and gradient computation is too expensive [S2].

## Background
Origin: Hart et al. [HCK99] [S2]. History and development: This method refines earlier color table filtering approaches by incorporating the local noise gradient [S2]. It is used in procedural noise rendering to reduce aliasing and improve visual quality [S1, S2].
