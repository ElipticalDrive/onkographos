# Trained Exposure Application
Also called: Learned per-image color transform, Per-image color correction

## Overview
Trained Exposure Application is a post-processing step applied to rendered RGB images to normalize their appearance to match the exposure conditions present in the training dataset. It solves the problem of domain shift where test-time rendering conditions (e.g., camera exposure, white balance) differ from the conditions the model was trained on. It differs from its sibling [Reference Based Color Transfer for Medical Volume Rendering](11552-reference-based-color-transfer-for-medical-volume-rendering.md) by using a fixed, data-driven affine transform rather than a learned style transfer, and from [Color Transfer](13520-color-transfer.md) by operating on a per-image basis using stored metadata rather than global histogram matching.

## How it works
**Inputs and Outputs:**
*   Input: A rendered RGB image tensor $I_{in}$ of shape $(H, W, 3)$ or $(3, H, W)$, and an image identifier (filename/name).
*   Output: A color-adjusted RGB image tensor $I_{out}$ of the same spatial dimensions as $I_{in}$.

**Data Structures:**
The method retrieves a pre-computed exposure tensor $E$ associated with the input image. The tensor $E$ has shape $(4, 4)$ or a compatible structure where:
*   $E_{3\times3}$ corresponds to $E[0:3, 0:3]$, a $3 \times 3$ matrix representing the linear color transform.
*   $E_{3}$ corresponds to $E[0:3, 3]$, a 3D bias vector representing the additive offset.

**Formulas:**
The transformation is an affine color correction defined as:
$$ I_{out} = (I_{in} \cdot E_{3\times3})^T + E_{3} $$
Where $I_{in}$ is treated as a column vector for the multiplication step if using standard matrix notation, or handled via batched matrix multiplication in tensor libraries. In the implementation, this is computed as:
$$ I_{out} = \text{permute}( \text{matmul}( \text{permute}(I_{in}), E_{3\times3} ) ) + E_{3} $$
*Note: The source code [S1, unofficial] implements this by permuting to $(H, W, 3)$, multiplying by the $3 \times 3$ matrix, permuting back to $(3, H, W)$, and adding the bias.*

**Steps:**
1.  Retrieve the exposure tensor $E$ for the current image using its unique name/identifier. If not found, the method cannot proceed without fallback logic (not specified in source) [S1, unofficial].
2.  Extract the $3 \times 3$ color transform matrix $M = E[0:3, 0:3]$ and the bias vector $b = E[0:3, 3]$ [S1, unofficial].
3.  Ensure the input image $I_{in}$ is in the format $(H, W, 3)$ [G].
4.  Compute the intermediate product $P = I_{in} \times M$ using matrix multiplication, resulting in a tensor of shape $(H, W, 3)$ [S1, unofficial].
5.  Add the bias vector $b$ to $P$. The bias is broadcasted across the height and width dimensions [S1, unofficial].
6.  Permute the result back to the target layout $(3, H, W)$ [S1, unofficial].

**Pseudocode:**
```python
import torch

def trained_exposure_application(rendered_image: torch.Tensor, exposure_tensor: torch.Tensor) -> torch.Tensor:
    """
    Applies a learned per-image 3x3 color transform and 3D bias vector to the rendered RGB image.
    
    Args:
        rendered_image: Input tensor of shape (3, H, W) or (H, W, 3). 
                        The source code assumes (3, H, W) input which is permuted.
        exposure_tensor: Tensor of shape (4, 4) containing the color transform and bias.
        
    Returns:
        Output tensor of shape (3, H, W).
    """
    # Extract components from the exposure tensor
    # E_3x3 is the 3x3 color transform matrix
    E_3x3 = exposure_tensor[0:3, 0:3]
    # E_3 is the 3D bias vector
    E_3 = exposure_tensor[0:3, 3]
    
    # Permute input from (3, H, W) to (H, W, 3) to allow matrix multiplication
    # with the 3x3 transform on the last dimension
    img_permuted = rendered_image.permute(1, 2, 0)
    
    # Multiply by the 3x3 matrix
    # matmul handles the batch dimensions if any, but here we apply to the spatial dims
    # Result shape: (H, W, 3)
    transformed = torch.matmul(img_permuted, E_3x3)
    
    # Permute back to (3, H, W)
    transformed_permuted = transformed.permute(2, 0, 1)
    
    # Add the bias vector. E_3 has shape (3,), need to add to each spatial location.
    # None, None broadcasts the 3 values across H and W dimensions.
    output = transformed_permuted + E_3[None, None, :]
    
    return output
```

**Parameters:**
*   `exposure_tensor`: Must be retrieved from storage using the specific image name. Typical values are learned during the training phase [S1, unofficial].
*   No other tunable parameters are mentioned [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Missing Data:** The method requires exposure data to be stored and retrievable by image name. If the lookup fails, the method is undefined [S1, unofficial].
*   **Shape Mismatch:** Permutation operations must match tensor dimensions exactly. Failing to permute before or after multiplication results in shape errors or incorrect mathematical operations [S1, unofficial].
*   **Precision:** The operation is linear. Numerical stability is generally high, but input values should be normalized appropriately for the learned matrix coefficients [G].

## Subtopics

### [ExpModel](14212-expmodel.md)
ExpModel is a learned colorization module that applies a per-image 3x3 color transform and 3D bias vector to a rendered RGB image to match training-time exposure conditions. It operates as a conditional neural network that maps a scalar condition (temperature for white balance, exposure for log-scale adjustment) to a color correction factor. It builds on Trained Exposure Application by providing the specific parameterized functions for white balance and exposure adjustments within that framework.

### [Reinhard Tonemapping for Training](14950-reinhard-tonemapping-for-training.md)
This method converts unbounded high-dynamic-range (HDR) linear radiance from a differentiable renderer into display-referred sRGB images suitable for neural network training. It prevents numerical instabilities and out-of-distribution inputs by compressing the dynamic range into a bounded, perceptually plausible interval. It differs from ExpModel by using a fixed, non-learnable luminance normalization rather than a learned per-image transform.

### Image-dependent affine color transformation
A baseline variant where an MLP predicts an affine color transformation (shift + scale) to each Gaussian to inject appearance variance like exposure [S2]. On the Brandenburg Gate scene, this method achieves PSNR 18.34, SSIM 0.777, LPIPS 0.313. On the Trevi Fountain scene, this method achieves PSNR 19.01, SSIM 0.761, LPIPS 0.246 [S2].

## Operating characteristics
**Time and Memory Complexity:**
The operation is a single matrix multiplication and vector addition per pixel. Time complexity is $O(H \cdot W)$ where $H$ and $W$ are image dimensions. Memory complexity is $O(H \cdot W)$ for the output tensor. The lookup of the exposure tensor is $O(1)$ assuming hash-based storage [G].

**Measured Performance:**
Not given in the sources.

**Scaling:**
The method scales linearly with image resolution. It is independent of volume resolution as it operates on the final rendered image [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Simple to implement, computationally inexpensive, effectively corrects global exposure and white balance shifts if the training data included such variations [S1, unofficial].
*   **Limitations:** Limited to affine color corrections; cannot model complex non-linear color shifts or texture changes [S2]. Requires pre-computed exposure metadata for every image [S1, unofficial].

**When to use it and when not:**
Use when test-time camera parameters (exposure, white balance) are known or can be mapped to training conditions via stored metadata [S1, unofficial]. Do not use when complex appearance variations (e.g., lighting direction changes, material changes) are present, as affine transforms are insufficient [S2].

## Background
The method originates from the Improved-GS project, which applies deep image analogy principles to volume rendering [S1, unofficial]. It is part of a family of techniques that use learned per-image transforms to handle appearance variance in 3D Gaussian Splatting and similar rendering frameworks.
