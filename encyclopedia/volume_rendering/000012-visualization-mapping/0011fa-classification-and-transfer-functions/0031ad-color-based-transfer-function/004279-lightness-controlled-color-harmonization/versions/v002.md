# Lightness-Controlled Color Harmonization

Also called: Lightness-Preserving Harmonic Colorization, Lightness-preserving color harmonization

## Overview
Lightness-Controlled Color Harmonization is a technique for volume visualization that transforms a transfer function’s color distribution to fit a specific harmonic template while strictly preserving the original lightness values [S1]. It solves the problem that standard hue-based harmonization (e.g., Cohen et al.) alters lightness, thereby destroying the perceptual contrast and "pop-out" effects critical for highlighting density intervals [S1]. It sets itself apart from [Windowing](6611-windowing.md) and [Colormap Application for Visualization](7714-colormap-application-for-visualization.md) by operating in the perceptually uniform CIE LAB space to decouple hue shifts from lightness changes, ensuring that visual salience is maintained during colorization [S1].

## How it works
The method maps RGB transfer function values through HSV to CIE LAB space to find a target hue that matches a harmonic template while retaining the source lightness [S1].

**Inputs and Outputs:**
*   **Input:** An RGB transfer function (TF) defined over scalar density values; a target harmonic hue template (e.g., from the 8 Itten/Matsuda types) [S1].
*   **Output:** A harmonized RGB transfer function where hues follow the template but lightness $L^*$ is preserved from the input [S1].

**Data Structures:**
*   **Transfer Function:** A set of $N$ triples $(r_i, g_i, b_i)$ representing color at specific density intervals [S1].
*   **Harmonic Template:** One of 8 predefined hue distributions (I, V, L, I, T, Y, X, N) [S1]. The N-type consists only of grey hues [S1]. Templates can be rotated by an arbitrary angle $\theta$ but cannot be resized [S1].

**Steps:**
1.  **Convert to HSV:** Transform each RGB triple $(r_i, g_i, b_i)$ of the transfer function into HSV coordinates $(H_i, S_i, V_i)$ [S1].
2.  **Map to CIE LAB:** Map each HSV triple to CIE LAB space $(L^*_i, a^*_i, b^*_i)$ [S1].
3.  **Locate Harmonized LAB Value:** For each TF entry, locate the LAB triple $(L^*_{new}, a^*_{new}, b^*_{new})$ such that it has the target hue (from the harmonic template), the source saturation, and the source lightness [S1].
4.  **Convert to RGB:** Convert the resulting LAB triple back to RGB to obtain the harmonized transfer function [S1].

**Formulas and Definitions:**
*   **Iso-lightness Mapping:** Iso-lightness curves derived from CIE LAB are mapped onto HSV hue slices to determine the correct saturation/lightness trade-off when shifting hues [S1]. These curves are monitor-specific and require a prior sRGB conversion step using the monitor’s white point, followed by a mapping to CIE XYZ and then CIE LAB [S1].
*   **Saturation Priority:** When the target hue requires a lightness $L^*_{req} > L^*_i$ (which is often the case for vivid colors), the algorithm does not force $L^*$ up [S1]. Instead, it prefers to reduce saturation over lightness to maintain the target lightness value [S1].

**Parameters:**
*   **Color Space:** CIE LAB (CIE L*a*b*) is the mandatory perceptual space for lightness preservation [S1].
*   **Harmonic Templates:** 8 types (I, V, L, I, T, Y, X, N) based on Itten/Matsuda schemes [S1].
*   **Rotation:** Arbitrary angle $\theta$ for template alignment [S1].

**Pitfalls:**
*   **Lightness-Saturation Trade-off:** It is not always possible to increase lightness without sacrificing saturation [S1]. The algorithm must prioritize lightness preservation, potentially resulting in less saturated colors if the target hue demands higher lightness than the source [S1].
*   **Monitor Dependency:** The mapping from HSV to LAB iso-lightness curves is monitor-specific and requires accurate sRGB conversion using the monitor’s white point [S1].
*   **Grey Hues:** The N-type template contains only grey hues; applying this may result in desaturated outputs if the source has high chroma [S1].

**Pseudocode:**
```python
def lightness_controlled_harmonization(tf_rgb, target_hue_deg):
    """
    Harmonizes the RGB transfer function to match a target hue template
    while preserving lightness in CIE LAB space.
    
    Args:
        tf_rgb: List of (r, g, b) tuples for the transfer function.
        target_hue_deg: Target hue in degrees [0, 360) from the harmonic template.
        
    Returns:
        List of (r, g, b) tuples for the harmonized transfer function.
    """
    harmonized_tf = []
    for r, g, b in tf_rgb:
        # Step 1: Convert RGB to HSV
        h, s, v = rgb_to_hsv(r, g, b)
        # Step 2: Map HSV to CIE LAB
        l, a, b_val = hsv_to_lab(h, s, v)
        # Step 3: Locate LAB triple with target hue, source saturation, source lightness
        l_new, a_new, b_new = locate_lab_for_target_hue(l, s, h, target_hue_deg)
        # Step 4: Convert LAB back to RGB
        r_new, g_new, b_new = lab_to_rgb(l_new, a_new, b_new)
        harmonized_tf.append((r_new, g_new, b_new))
    return harmonized_tf

def rgb_to_hsv(r, g, b):
    c_max = max(r, g, b)
    c_min = min(r, g, b)
    delta = c_max - c_min
    if delta == 0:
        h = 0
    elif c_max == r:
        h = 60 * (((g - b) / delta) % 6)
    elif c_max == g:
        h = 60 * (((b - r) / delta) + 2)
    else:
        h = 60 * (((r - g) / delta) + 4)
    v = c_max
    s = 0 if c_max == 0 else delta / c_max
    return h, s, v

def hsv_to_srgb(h, s, v):
    h = h / 60.0
    i = int(h)
    f = h - i
    p = v * (1 - s)
    q = v * (1 - s * f)
    t = v * (1 - s * (1 - f))
    if i == 0: r, g, b = v, t, p
    elif i == 1: r, g, b = q, v, p
    elif i == 2: r, g, b = p, v, t
    elif i == 3: r, g, b = p, q, v
    elif i == 4: r, g, b = t, p, v
    else: r, g, b = v, p, q
    return r, g, b

def srgb_to_xyz(r, g, b):
    r, g, b = r / 255.0, g / 255.0, b / 255.0
    r = ((r + 0.055) / 1.055) ** 2.4 if r > 0.04045 else r / 12.92
    g = ((g + 0.055) / 1.055) ** 2.4 if g > 0.04045 else g / 12.92
    b = ((b + 0.055) / 1.055) ** 2.4 if b > 0.04045 else b / 12.92
    r, g, b = r * 100, g * 100, b * 100
    x = r * 0.4124564 + g * 0.3575761 + b * 0.1804375
    y = r * 0.2126729 + g * 0.7151522 + b * 0.0721750
    z = r * 0.0193339 + g * 0.1191920 + b * 0.9503041
    return x, y, z

def xyz_to_lab(x, y, z):
    x, y, z = x / 95.047, y / 100.0, z / 108.883
    x = x ** (1/3) if x > 0.008856 else (7.787 * x) + (16/116)
    y = y ** (1/3) if y > 0.008856 else (7.787 * y) + (16/116)
    z = z ** (1/3) if z > 0.008856 else (7.787 * z) + (16/116)
    l = (116 * y) - 16
    a = 500 * (x - y)
    b_val = 200 * (y - z)
    return l, a, b_val

def lab_to_xyz(l, a, b):
    y = (l + 16) / 116
    x = a / 500 + y
    z = y - b / 200
    y = y ** 3 if y ** 3 > 0.008856 else (y - 16/116) / 7.787
    x = x ** 3 if x ** 3 > 0.008856 else (x - 16/116) / 7.787
    z = z ** 3 if z ** 3 > 0.008856 else (z - 16/116) / 7.787
    x, y, z = x * 95.047, y * 100.0, z * 108.883
    return x, y, z

def xyz_to_srgb(x, y, z):
    x, y, z = x / 100, y / 100, z / 100
    r = x * 3.2404542 + y * -1.5371385 + z * -0.4985314
    g = x * -0.9692660 + y * 1.8760108 + z * 0.0415560
    b = x * 0.0556434 + y * -0.2040259 + z * 1.0572252
    r = r / 100; g = g / 100; b = b / 100
    r = 12.92 * r if r <= 0.0031308 else 1.055 * (r ** (1/2.4)) - 0.055
    g = 12.92 * g if g <= 0.0031308 else 1.055 * (g ** (1/2.4)) - 0.055
    b = 12.92 * b if b <= 0.0031308 else 1.055 * (b ** (1/2.4)) - 0.055
    return max(0, min(255, int(round(r * 255)))), max(0, min(255, int(round(g * 255)))), max(0, min(255, int(round(b * 255))))

def hsv_to_lab(h, s, v):
    r, g, b = hsv_to_srgb(h, s, v)
    x, y, z = srgb_to_xyz(r, g, b)
    return xyz_to_lab(x, y, z)

def lab_to_rgb(l, a, b):
    x, y, z = lab_to_xyz(l, a, b)
    return xyz_to_srgb(x, y, z)

def locate_lab_for_target_hue(l_src, s_src, h_src, h_target):
    # Locate LAB triple with target hue, source saturation, source lightness
    # If increasing lightness to match target hue is impossible without sacrificing saturation,
    # prefer reducing saturation over lightness to maintain the target lightness value.
    # We compute the LAB coordinates for (h_target, s_src, l_src).
    # If the resulting chroma exceeds the gamut boundary for l_src at h_target,
    # we reduce s_src until the point lies on the iso-lightness curve for l_src.
    # Convert target hue and source saturation/lightness to LAB
    l_new, a_new, b_new = hsv_to_lab(h_target, s_src, 1.0) # Normalize v for hue/sat lookup
    # Adjust saturation to match source lightness constraint
    # In practice, iterate s from s_src down to 0 until lab_to_rgb(l_new, a_new, b_new) 
    # yields a lightness matching l_src within tolerance, or use precomputed iso-lightness curves [G]
    return l_new, a_new, b_new
```

## Subtopics

### [Iso-lightness Curve Mapping](10797-iso-lightness-curve-mapping.md)
Iso-lightness curve mapping is a technique that uses iso-lightness curves derived from the CIE LAB color space, mapped onto HSV hue slices, to determine the correct saturation/lightness trade-off when shifting hues in volume visualization. It addresses the limitation of hue-only harmonization by preserving existing lightness contrasts and salience, which are critical for highlighting and contrast enhancement. Unlike standard HSV manipulation, this method accounts for the non-perceptual nature of HSV by grounding color adjustments in the perceptually uniform CIE LAB space.

### Harmonic Color Harmonization
Harmonic Color Harmonization is a method that transforms a given image with a non-harmonic hue distribution into one that fits a specific harmonic hue template, using optimization to re-colorize the image while preserving lightness [S1]. It accepts an image with a possibly non-harmonic hue distribution, finds the closest (rotated) harmonic hue template, and uses an optimization algorithm to re-colorize the image to have a hue distribution that fits the nearest harmonic template [S1]. Pixels with higher saturation receive more weight in the template matching procedure because their hue is perceptually more salient [S1]. The eight harmonic hue wheel templates (I, V, L, I, T, Y, X, N) define grey sectors where the hue histogram must occupy; the N-type is composed only of grey hues [S1]. Templates can be rotated by an arbitrary angle but cannot be resized [S1]. A limitation is that the base algorithm only considers hue, not saturation or lightness, which is a drawback for volume visualization where lightness preservation is critical [S1].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of transfer function entries, as each entry undergoes a fixed sequence of color space conversions [S1].
*   **Memory Complexity:** Constant per entry, requiring storage for intermediate HSV and LAB values [S1].
*   **Performance:** The method preserves contrast and details significantly better than Cohen et al.'s method, as observed in volume renderings of the Buckyball and human silhouettes [S1].
*   **Strengths:** Maintains lightness channel to support the pop-out effect; preserves contrast relationships between density intervals; perceptually uniform adjustments via CIE LAB [S1].
*   **Limitations:** Monitor-specific mapping requires accurate sRGB conversion and white point adaptation; cannot always increase lightness without sacrificing saturation; N-type templates may result in desaturated outputs [S1].
*   **When to use:** When harmonic color schemes are desired but visual salience and density contrast must be preserved [S1].
*   **When not to use:** When monitor-independent color reproduction is critical without calibration; when the N-type (grey) template is used and chroma is needed [S1].

## Background
The method originates from the work of Wang and Mueller (2008) on "Harmonic Colormaps for Volume Visualization" [S1]. It builds upon Itten’s color wheel and Matsuda’s 80 harmonic color schemes, which were the basis for Cohen et al.'s automated image color harmonization system [S1]. Cohen et al.'s method allowed users to transform ill-chosen scene colorizations into harmonious ones but only shifted hue in HSV space, changing lightness and destroying visual salience [S1]. Wang and Mueller extended this by introducing CIE LAB-based iso-lightness curves to preserve lightness during hue harmonization, addressing the specific needs of volume visualization where lightness contrasts guide the viewer [S1].
