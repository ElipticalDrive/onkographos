# Color-Based Transfer Function

Also called: Color Transfer Function Mapping, Grayscale Color Mapping, Non-linear Color Mapping with K-Means Splitting

## Overview
The Color-Based Transfer Function maps scalar volume data values directly to RGB color vectors, allowing the user to define visual appearance based on intensity ranges rather than relying solely on grayscale or fixed colormaps [S2, book][S3, unofficial]. It solves the problem of distinguishing specific material properties or density clusters that are difficult to separate using opacity alone, by assigning distinct hues to different value intervals [S2, book]. Unlike [1D Transfer Function](11719-1d-transfer-function.md) which typically maps scalar values to a single opacity channel (with color often derived from lighting or fixed attributes), this method explicitly defines the color output for each scalar value, enabling non-linear perceptual scaling and multi-range color assignment [S2, book][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar value $v$ representing voxel intensity or density.
*   **Output:** A color vector $\mathbf{c}_{rgb} = (r, g, b)$ and optionally an opacity $\alpha$.

**Data Structures:**
The transfer function is typically implemented as a set of control points (keypoints) defining a piecewise linear interpolation curve, or as a 1D Lookup Table (LUT) [S3, unofficial].
*   **Control Point Structure:** Each point consists of a scalar threshold $t_i$ and an associated RGB color $\mathbf{c}_i = (r_i, g_i, b_i)$ [S3, unofficial].
*   **LUT Layout:** A 1D texture or array where index $i$ corresponds to normalized intensity $i/255$ (for 8-bit data) or scaled intensity, storing the resulting RGBA values [S4, unofficial].

**Steps:**
1.  **Normalization:** If using a grayscale baseline, normalize the scalar value $v$ to the range $[0, 1]$ [S2, book].
    $$ c = \frac{v - v_{min}}{v_{max} - v_{min}} $$
    where $v_{min}$ and $v_{max}$ are the minimum and maximum values in the dataset or the window of interest [S2, book].
2.  **Grayscale Mapping (Baseline):** For a simple grayscale color mapping, the RGB components are set equal to the normalized value $c$ [S2, book]:
    $$ \mathbf{c}_{rgb} = (c, c, c) $$
3.  **Color Point Definition:** Define specific RGB triples at scaled scalar thresholds to create a non-linear color mapping [S3, unofficial]. For example, assign specific colors to specific intensity ranges to highlight clusters [S2, book].
4.  **Interpolation:** For a query value $v$, find the two nearest control points $(t_i, \mathbf{c}_i)$ and $(t_{i+1}, \mathbf{c}_{i+1})$ such that $t_i \le v \le t_{i+1}$. Interpolate the color linearly:
    $$ \mathbf{c}_{rgb}(v) = \mathbf{c}_i + \frac{v - t_i}{t_{i+1} - t_i} (\mathbf{c}_{i+1} - \mathbf{c}_i) $$
5.  **Opacity Combination (Optional):** The color-based transfer function can be combined with other transfer functions, such as a gradient-magnitude-based function, by multiplying the resulting opacity with the gradient-based opacity to suppress high-gradient areas (e.g., skin) [S1].

**Parameters:**
*   **Color Mapping Points:** Specific RGB triples assigned at scalar thresholds. Example from VTK implementation:
    *   Threshold ~1105 (scaled): RGB (0.8, 0.0, 0.0)
    *   Threshold ~1626 (scaled): RGB (1.0, 0.5, 0.5)
    *   Threshold ~22102 (scaled): RGB (0.0, 0.0, 0.0) [S3, unofficial].
*   **Stretch Factor:** A scalar multiplier applied to raw intensity values before mapping to handle large dynamic ranges (e.g., `stretch = 0.05` in VTK example) [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Clipping:** If a value falls outside the defined control points, it is typically clamped to the nearest endpoint color [S3, unofficial].
*   **Perceptual Uniformity:** Linear RGB interpolation may not be perceptually uniform. Non-linear scaling is recommended to match human perception [S2, book].
*   **Color Bleeding:** When using pre-classification, color interpolation between voxels can cause color bleeding if not handled with opacity-weighted colors [S2, book].

**Pseudocode:**
```python
def color_based_transfer_function(value, control_points, min_val, max_val):
    """
    Maps a scalar value to an RGB color using piecewise linear interpolation.
    
    Args:
        value (float): The scalar input value.
        control_points (list of tuples): List of (threshold, (r, g, b)) tuples.
                                         Thresholds should be sorted.
        min_val (float): Minimum value for normalization (if using normalized mode).
        max_val (float): Maximum value for normalization (if using normalized mode).
    
    Returns:
        tuple: (r, g, b) color values in [0, 1].
    """
    # Normalize value if control points are defined in [0, 1]
    # Note: Some implementations use raw intensity, others normalized.
    # This example assumes control points are defined in the same domain as 'value'.
    
    if not control_points:
        return (0.0, 0.0, 0.0)
    
    # Clamp value to the range of control points
    t_min = control_points[0][0]
    t_max = control_points[-1][0]
    
    if value <= t_min:
        return control_points[0][1]
    if value >= t_max:
        return control_points[-1][1]
    
    # Find the interval
    for i in range(len(control_points) - 1):
        t_i, c_i = control_points[i]
        t_next, c_next = control_points[i+1]
        
        if t_i <= value <= t_next:
            # Linear interpolation
            if t_next == t_i:
                return c_i
            
            ratio = (value - t_i) / (t_next - t_i)
            r = c_i[0] + ratio * (c_next[0] - c_i[0])
            g = c_i[1] + ratio * (c_next[1] - c_i[1])
            b = c_i[2] + ratio * (c_next[2] - c_i[2])
            return (r, g, b)
    
    return (0.0, 0.0, 0.0)

# Example usage based on [S3, unofficial] VTK-like setup:
# control_points = [
#     (0, (0.0, 0.0, 0.0)),
#     (stretch * 22102, (0.0, 0.0, 0.0)),
#     (stretch * 22103, (0.8, 0.0, 0.0)),
#     (stretch * 32532, (1.0, 0.5, 0.5)),
#     (stretch * 42532, (1.0, 0.9, 0.9)),
#     (stretch * 65535, (1.0, 1.0, 1.0))
# ]
```

## Subtopics

### Default Spine-Focused Transfer Function
A specific preset for medical spine imaging that maps intensity indices 0-255 to specific colors and opacities to highlight bone and soft tissue [S4, unofficial]. It uses a 2D numpy array of shape (256, 4) [dtype float32] where each row is [R, G, B, Alpha] [S4, unofficial].
*   **Intensity < 0.2:** RGB [0.0, 0.0, 0.0], Alpha 0.0 (Transparent) [S4, unofficial].
*   **0.2 <= Intensity < 0.5:** RGB [0.6, 0.8, 0.9], Alpha max(0.5, (intensity - 0.2) * 2.0) [S4, unofficial].
*   **0.5 <= Intensity < 0.8:** RGB [0.9 + t*0.1, 0.9 + t*0.1, 0.9 + t*0.1] where $t = (intensity - 0.5) / 0.3$, Alpha 0.3 + t*0.3 [S4, unofficial].
*   **Intensity >= 0.8:** RGB [1.0, 1.0, 1.0], Alpha 1.0 [S4, unofficial].

### Multi-Range Color Mapping
A technique that divides the volume into distinct color ranges based on density values to improve perception of details, especially for non-evenly distributed values or clusters [S2, book]. It assigns different colors to different salinity/density levels (e.g., high salinity green, medium blue, low red) [S2, book]. The UI displays gray lines showing value distribution, with color line height indicating brightness [S2, book].

### Color Affine Transform
Applies a per-pixel affine color transformation to RGB values, allowing for dynamic color adjustment during rendering [S5, unofficial].
*   **Formula:** $\text{out} = \text{affine\_mats}[\dots, :3] \times \text{rgb} + \text{affine\_mats}[\dots, 3]$ [S5, unofficial].
*   **Layout:** `affine_mats` is a tensor of shape (..., 3, 4) containing 3x4 affine matrices; `rgb` is a tensor of shape (..., 3) [S5, unofficial].

### Guided Image Filter Colorization
A colorization technique applied after gamma encoding to transfer color from a reference image to a target image [S6, unofficial].
*   **Parameters:** Radius $r = 16$, Regularization term $\epsilon = 2$ [S6, unofficial].

### Fast Global Smoother Filter Colorization
A colorization technique applied after gamma encoding to transfer color from a reference image to a target image [S6, unofficial].
*   **Parameters:** Lambda $\lambda = 0.2$, Alpha $\alpha = 1.8$; or $\lambda = 32$, sigma range $\sigma_r = 200$ [S6, unofficial].

### Palette Remapping
A method to remap voxel colors to a target palette, often used in schematic or voxel-based rendering [S7, unofficial].
*   **Steps:** Collect unique colors from the input schematic, find their indices in the target palette using `ColorComparison.CompareColorRGB`, and replace voxel colors via dictionary lookup [S7, unofficial].
*   **Pitfall:** If a color is not found in the palette, `KeyNotFoundException` or invalid index may occur if `CompareColorRGB` fails [S7, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample point for lookup table access or piecewise linear interpolation [S3, unofficial].
*   **Memory Complexity:** $O(N)$ for the LUT size, where $N$ is the number of bins (e.g., 256 for 8-bit) or number of control points [S3, unofficial].
*   **Strengths:** Intuitive user interaction via color bars; effective for highlighting specific material clusters; supports non-linear perceptual scaling [S1][S2, book].
*   **Limitations:** Requires manual tuning of color points for optimal results; color bleeding can occur with pre-classification if not handled correctly [S2, book]; may not preserve perceptual uniformity if linear RGB interpolation is used [S2, book].
*   **When to use:** When specific density ranges need distinct visual identification (e.g., medical tissue types, environmental salinity gradients) [S1][S2, book].
*   **When not to use:** When automatic data-driven colorization is preferred (see [Automatic and Data-Driven Generation](7609-automatic-and-data-driven-generation.md)) or when perceptual uniformity is critical without manual adjustment (see [Lightness-Controlled Color Harmonization](10770-lightness-controlled-color-harmonization.md)).

## Background
The color-based transfer function is a fundamental technique in volume visualization, evolving from simple grayscale mapping to complex multi-range color assignments. Early implementations used linear grayscale mapping where $c_{rgb} = (c, c, c)$ for normalized values $c$ [S2, book]. Later developments introduced non-linear scaling and multi-color ranges to better match human perception and highlight data clusters [S2, book]. Modern implementations often integrate with interactive widgets that display color bars corresponding to the transfer function's horizontal axis, improving user intuition [S1]. Recent variants include automatic color transfer from reference images [S6, unofficial] and perceptual harmonization techniques [S1].
