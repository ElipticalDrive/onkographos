# Palette Remapping

Also called: Color Palette Remapping, Schematic Color Remapping

## Overview
Palette Remapping is a technique that replaces the colors of a source volume or image with colors from a target palette, ensuring the output strictly adheres to a limited set of allowed colors. It solves the problem of color quantization and style transfer in schematic or voxel-based visualization where a fixed color set is required for consistency or performance. It differs from [Windowing](6611-windowing.md) and [Colormap Application for Visualization](7714-colormap-application-for-visualization.md) by mapping discrete source colors to discrete target palette entries rather than interpolating continuous scalar values into a gradient, and from [Lightness-Controlled Color Harmonization](10770-lightness-controlled-color-harmonization.md) by prioritizing exact palette membership over perceptual lightness preservation.

## How it works
**Inputs:** A source schematic or volume containing a set of unique colors (the source palette) and a target palette (a list of allowed colors).
**Outputs:** A remapped schematic or volume where each voxel's color is replaced by the closest match in the target palette.

**Data Structures:**
1.  **Source Colors List:** A collection of unique colors found in the input.
2.  **Target Palette:** An ordered list of colors (e.g., 256 entries max for 8-bit indexing).
3.  **Palette Dictionary:** A hash map or lookup table mapping source color identifiers (RGB tuples) to their corresponding index in the target palette.

**Steps:**
1.  **Collect Source Colors:** Identify all unique colors present in the input schematic. This can be done by iterating through all voxels and storing distinct RGB values in a set, or by using a dedicated method like `schematic.UsedColors` if available [S1, unofficial].
2.  **Build Mapping:** For each unique color $C_{src}$ in the source:
    *   Find the index $i$ in the target palette such that $C_{target}[i]$ is the best match for $C_{src}$.
    *   The matching criterion is typically defined by a comparison function, such as `ColorComparison.CompareColorRGB` [S1, unofficial].
    *   Store the mapping $C_{src} \rightarrow i$ in the `paletteDictionary`.
3.  **Remap Voxels:** Iterate through every voxel in the source schematic.
    *   Retrieve the voxel's current color $C_{voxel}$.
    *   Look up the index $i$ in `paletteDictionary` using $C_{voxel}$ as the key.
    *   Replace $C_{voxel}$ with $C_{target}[i]$.

**Pitfalls:**
*   **Missing Colors:** If a color in the source schematic is not found in the target palette, the dictionary lookup may fail. The implementation must handle cases where `CompareColorRGB` does not return a valid match, potentially throwing a `KeyNotFoundException` or returning an invalid index [S1, unofficial]. A fallback strategy (e.g., default color or nearest neighbor with tolerance) is required [G].

**Pseudocode:**
```python
def remap_palette(source_schematic, target_palette):
    """
    Remaps colors in a source schematic to a target palette.
    
    Args:
        source_schematic: Object containing voxels and a method to get used colors.
        target_palette: List of Color objects representing the allowed output colors.
        
    Returns:
        Remapped schematic with colors replaced by target palette indices.
    """
    # Step 1: Collect unique colors from source
    # Using a set to ensure uniqueness
    source_colors = set()
    for voxel in source_schematic.voxels:
        source_colors.add(voxel.color)
        
    # Alternatively, if the source provides a direct method:
    # source_colors = source_schematic.used_colors()

    # Step 2: Build the mapping dictionary
    palette_dictionary = {}
    
    for src_color in source_colors:
        best_index = -1
        min_distance = float('inf')
        
        # Find the closest color in the target palette
        for idx, tgt_color in enumerate(target_palette):
            # CompareColorRGB computes distance/metric between two RGB colors
            distance = compare_color_rgb(src_color, tgt_color)
            
            if distance < min_distance:
                min_distance = distance
                best_index = idx
        
        # Pitfall handling: If no valid match is found (distance too high or comparison fails)
        if best_index == -1:
            # [G] Fallback to the first palette color or a default transparent color
            best_index = 0 
            
        palette_dictionary[src_color] = best_index

    # Step 3: Remap all voxels
    for voxel in source_schematic.voxels:
        if voxel.color in palette_dictionary:
            mapped_index = palette_dictionary[voxel.color]
            voxel.color = target_palette[mapped_index]
        else:
            # [G] This case should be covered by the dictionary build step if all source colors are processed
            # but acts as a safety guard
            voxel.color = target_palette[0]

    return source_schematic

def compare_color_rgb(color_a, color_b):
    """
    Computes the squared Euclidean distance between two RGB colors.
    """
    r_diff = color_a.r - color_b.r
    g_diff = color_a.g - color_b.g
    b_diff = color_a.b - color_b.b
    return r_diff**2 + g_diff**2 + b_diff**2
```

## Subtopics

### Nearest Color Lookup with Gamma Correction
A variant that computes the color matching error in gamma-corrected space rather than linear RGB space to better approximate human perception. It uses a precomputed 16x16x16 lookup table (4096 entries) for performance, where each entry stores a packed unsigned int containing foreground (5 bits) and background (5 bits) indices as `(bg << 5) | fg` [S2, unofficial]. The error metric is the squared Euclidean distance in gamma space ($\gamma(x) = x^{2.2}$), with an additional weight of 0.04 on the difference between foreground and background gamma values [S2, unofficial]. The formula for error $E$ between a target color $C$ and a palette entry with foreground $P_{fg}$ and background $P_{bg}$ is:
$$ E = \sum_{c \in \{r,g,b\}} (\gamma(P_{bg,c}) - \gamma(C_c))^2 + 0.04 \sum_{c \in \{r,g,b\}} (\gamma(P_{bg,c}) - \gamma(P_{fg,c}))^2 $$
Parameters include a gamma exponent of 2.2 and an error weight of 0.04 [S2, unofficial]. This method is chosen when perceptual accuracy is more important than raw RGB distance, and performance constraints allow for a 4096-entry LUT [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ where $N$ is the number of unique source colors and $M$ is the size of the target palette. The remapping step is $O(V)$ where $V$ is the number of voxels, assuming $O(1)$ dictionary lookup.
*   **Memory Complexity:** $O(N)$ to store the source colors and the dictionary. The LUT variant uses a fixed 4096-entry table [S2, unofficial].
*   **Strengths:** Guarantees output colors are strictly from the target palette; fast lookup after initial mapping; simple to implement.
*   **Limitations:** Discontinuous color transitions if source colors are not well-represented in the target palette; sensitive to the definition of "closest" color; potential for `KeyNotFoundException` if source colors are not found [S1, unofficial].
*   **When to use:** Schematic visualization, voxel art conversion, or any scenario requiring a strict, limited color set.
*   **When not to use:** When smooth gradients or continuous color mapping are required (use [Colormap Application for Visualization](7714-colormap-application-for-visualization.md) instead).

## Background
Palette Remapping is commonly used in voxel-based game engines and schematic tools to convert high-color-depth models into formats that support limited palettes, such as the Minecraft .schematic format or legacy 8-bit display modes. The technique is implemented in tools like FileToVox for converting .vox files to schematics [S1, unofficial] and in rendering demos like asciitracing for optimized color lookup [S2, unofficial].
