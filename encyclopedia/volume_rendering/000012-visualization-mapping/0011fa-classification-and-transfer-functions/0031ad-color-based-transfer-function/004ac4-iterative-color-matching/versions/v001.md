# Iterative Color Matching


## Overview
Iterative Color Matching warps the colors of an input image to match a reference image by solving for a per-channel quadratic transformation using iterative least squares [S1, unofficial]. It distinguishes itself from static color mapping methods by handling non-linear transformations and explicitly managing pixel clipping through iterative refinement, ensuring the output remains within valid bounds [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: `img` (input image tensor, shape $H \times W \times C$), `ref` (reference image tensor, shape $H \times W \times C$), `num_iters` (integer), `eps` (float).
- Output: `img_warped` (warped image tensor, shape $H \times W \times C$).

**Data Structures**
- `img_mat`: Reshaped input image of size $N \times C$, where $N = H \times W$.
- `ref_mat`: Reshaped reference image of size $N \times C$.
- `a_mat`: Design matrix of size $N \times K$, where $K$ is the number of quadratic expansion terms.
- `b`: Target vector of size $N$ for a single channel.
- `w`: Weight vector of size $K$ for a single channel.
- `mask`: Boolean array of size $N$ indicating valid (unclipped) pixels.

**Parameters**
- `num_iters`: Number of iterations for color matching. Default: 5 [S1, unofficial].
- `eps`: Clipping threshold for unclipped pixels. Default: $0.5 / 255$ [S1, unofficial].

**Steps**
1. Reshape `img` and `ref` into matrices `img_mat` and `ref_mat` of shape $N \times C$, where $N$ is the total number of pixels.
2. Define a helper function `is_unclipped(z)` which returns `True` if $z \ge \text{eps}$ and $z \le 1 - \text{eps}$, and `False` otherwise. This identifies pixels not saturated at the boundaries [S1, unofficial].
3. Initialize `mask0` as a boolean array of size $N$ where `True` indicates pixels in `img_mat` that are unclipped according to `is_unclipped`.
4. Loop `num_iters` times:
    a. Construct `a_mat` of size $N \times K$. The columns correspond to the quadratic expansion terms:
       - Products of input channels: $\text{img}_c \cdot \text{img}_{c'}$ for all pairs $(c, c')$ including $c=c'$.
       - Linear terms: $\text{img}_c$ for each channel $c$.
       - Bias term: a column of ones $\mathbf{1}$.
       These terms are concatenated along the channel dimension [S1, unofficial].
    b. For each output channel $c$ from $0$ to $C-1$:
       i. Set target vector $b = \text{ref\_mat}[:, c]$.
       ii. Compute a new mask for unclipped pixels based on the current `img_mat`, $b$, and the original `img_mat`. Specifically, a pixel is valid if it is unclipped in the current `img_mat`, the target $b$, and the original input.
       iii. Zero out rows in `a_mat` and $b$ corresponding to saturated (masked out) pixels. This prevents distortion from clipped values [S1, unofficial].
       iv. Solve the least squares problem $w = \text{lstsq}(a\_mat, b)$ to find the weights $w$ for channel $c$.
       v. Stack the weights $w$ into a warp structure for channel $c$.
       vi. Update `img_mat` for the next iteration by applying the warp: $\text{img\_mat} = \text{clip}(\text{matmul}(a\_mat, \text{warp}), 0, 1)$.
5. Reshape the final `img_mat` back to the original image shape $H \times W \times C$ to produce `img_warped`.

            mask_c = is_unclipped(img_mat[:, c]) & is_unclipped(b) & is_unclipped(img[:, c].reshape(N))

            a_mat_masked = a_mat.copy()
            b_masked = b.copy()

**Edge Cases and Pitfalls**
- Saturated pixels (clipped at 0 or 1) are masked out during least squares solving to prevent distortion [S1, unofficial].
- The mask is updated iteratively based on the current corrected estimate, which helps handle non-linear transformations [S1, unofficial].
- Precision issues may arise if the design matrix `a_mat` is ill-conditioned. Using `rcond` in least squares helps [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(\text{num\_iters} \cdot N \cdot K^2)$ or $O(\text{num\_iters} \cdot N \cdot C^3)$ depending on implementation, where $K \approx C^2/2$. Solving least squares for each channel per iteration dominates.
- **Memory Complexity**: $O(N \cdot K)$ for storing the design matrix.
- **Strengths**: Handles non-linear color mappings; robust to clipping by masking saturated pixels; iterative refinement improves accuracy.
- **Limitations**: Computationally expensive for large images or high channel counts; requires a reference image; sensitive to the choice of `eps` and `num_iters`.
- **When to use**: When precise color matching between two images is required, especially if the transformation is non-linear or involves clipping.
- **When not to use**: For real-time applications with limited computational resources; when no reference image is available.
