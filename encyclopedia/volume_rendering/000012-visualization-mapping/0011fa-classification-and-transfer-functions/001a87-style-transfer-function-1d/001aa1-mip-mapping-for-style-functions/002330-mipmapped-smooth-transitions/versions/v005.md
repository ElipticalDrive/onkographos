# Mipmapped Smooth Transitions
## Overview
Mipmapped Smooth Transitions introduces smooth transitions based on mipmapping to allow temporal coherence and anti-aliasing in volume rendering [S1, unofficial]. It addresses visual artifacts caused by abrupt changes in sampling rates or data resolution during camera or volume movement [S1, unofficial].
## How it works
The method integrates mipmapping into the rendering pipeline to smooth out variations in sampling quality over time [S1, unofficial].

**Inputs:** Volume data, camera parameters, streaming parameters $N$ and $M$.
**Data Structures:** Precomputed mipmaps analyzed for constant density [S1, unofficial]. A streaming grid defined by parameters $N$ and $M$ [S1, unofficial].
**Steps:**
1. Precompute mipmaps for the volume, analyzing them for constant density [S1, unofficial].
2. Cast rays through the volume for each pixel [G].
3. Select the mipmap level based on ray intersection density and camera view, smoothing the selection over time to avoid popping artifacts [S1, unofficial].
4. Sample volume data from the selected mipmap level, adjusting the sampling rate to maintain visual consistency [G].
5. Stream necessary volume chunks based on the ray path and selected level [S1, unofficial].

**Parameters:** $N=2$ and $M=16$ in the documented example [S1, unofficial].
**Edge Cases:** Rapid camera movement may cause temporary visual artifacts if the mipmap transition is not smooth enough; the method relies on temporal coherence to mitigate this [S1, unofficial]. High resolution data requires significant precomputation time and CPU memory [S1, unofficial].

**Pseudocode:**
```python
def render_frame(volume, camera, N, M):
    mipmaps = [downsample(volume, 2**i) for i in range(10)]
    output = [[0.0, 0.0, 0.0, 0.0] for _ in range(camera.height)]
    prev_level = 0.0
    for y in range(camera.height):
        for x in range(camera.width):
            ray_o, ray_d = camera.get_ray(x, y)
            t = 0.0
            acc_color = [0.0, 0.0, 0.0, 0.0]
            acc_alpha = 0.0
            while t < camera.far_plane:
                pos = ray_o + ray_d * t
                if not (0 <= pos[0] < volume.size[0] and 0 <= pos[1] < volume.size[1] and 0 <= pos[2] < volume.size[2]):
                    break
                target_level = max(0, min(9, int((pos[0] + pos[1] + pos[2]) / (N * M))))
                level = prev_level + 0.5 * (target_level - prev_level)
                prev_level = level
                density = sample_mipmap(mipmaps, level, pos)
                color, alpha = transfer_function(density)
                acc_color = [c + col * alpha * (1.0 - acc_alpha) for c, col in zip(acc_color, color)]
                acc_alpha = acc_alpha + alpha * (1.0 - acc_alpha)
                if acc_alpha > 0.99:
                    break
                t += step_size(ray_d, volume.resolution, level)
            output[y][x] = acc_color
    return output

def downsample(vol, factor):
    return [[sum(vol[i][j] for i in range(factor) for j in range(factor)) / (factor*factor) for j in range(0, len(vol[0]), factor)] for i in range(0, len(vol), factor)]

def sample_mipmap(mipmaps, level, pos):
    idx = int(level)
    frac = level - idx
    v0 = mipmaps[idx][int(pos[0])][int(pos[1])][int(pos[2])]
    v1 = mipmaps[min(idx+1, 9)][int(pos[0])][int(pos[1])][int(pos[2])]
    return v0 * (1.0 - frac) + v1 * frac

def transfer_function(density):
    return [density, density, density, density * 0.5]

def step_size(ray_d, resolution, level):
    return 1.0 / (resolution[0] * (2**level))
```
## Subtopics
## Operating characteristics
- **Performance:** Achieves 2040 Hz with smooth mipmapping on a simulated $8192^3$ volume ($1024^3$ copied 8 times per axis), compared to 60 fps without it [S1, unofficial].
- **Memory:** Minimizes GPU memory usage via a compact data structure [S1, unofficial]. Precomputing mipmaps requires significant CPU memory and time [S1, unofficial].
- **Quality:** Provides temporal coherence and anti-aliasing [S1, unofficial].
- **Limitations:** Rapid camera movement may cause temporary artifacts if transitions are insufficiently smooth [S1, unofficial]. High-resolution data increases precomputation overhead [S1, unofficial].
## Background
Demonstrated on a detailed trabecular bone scan [S1, unofficial]. Showed real-time performance with high-quality volume rendering is possible, avoiding most CPU interaction and minimizing GPU memory usage [S1, unofficial]. Smooth transitions based on mipmapping were a key contribution to achieving temporal coherence [S1, unofficial].
