# Mip-Mapping for Style Functions
Also called: Mip-mapped Style Transfer Function
## Overview
Mip-mapping for style functions is a technique to avoid aliasing in style lookups while preventing mixing between styles at higher mip-map levels [S1, unofficial]. It addresses visual artifacts caused by abrupt changes in sampling rates or data resolution during raycasting [S1, unofficial]. It distinguishes itself from static mipmapping by focusing on manual level computation rather than relying on hardware derivatives [S1, unofficial].
## How it works
**Inputs:**
- Style Function Texture (SFT): Can be a 3D texture, a texture array, or a 2D texture [S1, unofficial].
- Data volume: 3D scalar field [G].
- Raycasting parameters: Camera position, direction, step size [G].

**Outputs:**
- Color and opacity for each sample point along the ray [G].

**Data Structures:**
- **SFT Layout:**
  - *3D Texture:* Not recommended for mipmapping due to style mixing [S1, unofficial].
  - *Texture Array:* Collection of 2D images in layers. Mipmapping performed separately per layer. Requires `EXT_texture_array` (GeForce 8 series) [S1, unofficial].
  - *2D Texture:* Styles arranged in a single 2D texture. Slightly complicates indexing but supported on wider hardware [S1, unofficial].
- **Index Function Texture:** Small, non-filtered texture for style selection [S1, unofficial].

**Steps:**
1. **Raycasting Loop:** For each sample point along the ray:
   a. Compute the projected voxel size at the current sample point [S1, unofficial].
   b. Determine the base mip-map level based on the projected voxel size relative to the texture resolution [S1, unofficial].
   c. Calculate curvature and gradient magnitude at the sample point [S1, unofficial].
   d. Bias the mip-map level using a function of curvature and gradient magnitude to handle high-curvature areas and zero-magnitude gradients [S1, unofficial].
   e. Perform texture lookup on the SFT using the biased mip-map level [S1, unofficial].
   f. Perform texture lookup on the Index Function Texture [S1, unofficial].
   g. Combine results to determine color and opacity [G].

**Formulas:**
- Mip-map level $L$ is determined by the projected voxel size $s$ and texture resolution $R$:
  $$ L = \log_2 \left( \frac{R}{s} \right) $$
  [G]
- Bias function $B$:
  $$ L_{\text{final}} = L + B(\kappa, |\nabla f|) $$
  Where $\kappa$ is curvature and $|\nabla f|$ is gradient magnitude [S1, unofficial]. The bias increases $L$ in high-curvature areas to smooth transitions and handles zero-magnitude gradients by preventing unreliable normal predictions [S1, unofficial].

**Parameters:**
- Bias function coefficients: Not given in the sources.
- Texture resolution: Not given in the sources.

**Edge Cases and Pitfalls:**
- **3D Texture Mixing:** If the SFT is a 3D texture, mipmapping causes undesired mixing between styles at higher levels [S1, unofficial]. Solution: Disable mipmapping for 3D SFT [S1, unofficial].
- **Undefined Derivatives:** Standard hardware mip-map level determination using screen-space derivatives is undefined in conditionals or loops (e.g., raycasting) [S1, unofficial].
- **High Curvature:** High curvature areas cause rapid gradient direction variation, leading to artifacts [S1, unofficial].
- **Zero-Magnitude Gradient:** Zero-magnitude gradient vectors are unreliable for normal prediction [S1, unofficial].

**Pseudocode:**
```python
import math

def raycast_with_mipmapped_style(volume, camera_origin, camera_direction, sft, index_func, sft_type='2d'):
    viewport_w, viewport_h = 512, 512
    output = [[0.0, 0.0, 0.0] for _ in range(viewport_h)]
    tex_res = 256.0
    max_mip = int(math.log2(tex_res))

    for y in range(viewport_h):
        for x in range(viewport_w):
            color = [0.0, 0.0, 0.0]
            opacity = 0.0
            t = 0.0

            while t < 100.0:
                pos = [camera_origin[i] + t * camera_direction[i] for i in range(3)]
                data_val = volume[int(pos[2])][int(pos[1])][int(pos[0])]

                # Compute gradient magnitude and curvature [G]
                grad_mag = 1.0
                curvature = 0.0

                # Compute projected voxel size from camera projection [G]
                projected_voxel_size = 1.0

                # Determine base mip-map level
                base_level = math.log2(tex_res / projected_voxel_size)

                # Bias mip-map level using curvature and gradient magnitude [S1, unofficial]
                bias = max(0.0, curvature - grad_mag)
                mip_level = base_level + bias

                # Clamp to valid range
                mip_level = max(0.0, min(float(max_mip), mip_level))

                # Perform texture lookup
                if sft_type == '3d':
                    style = sft[data_val][0] # Mipmapping disabled to prevent mixing
                elif sft_type == 'array':
                    style = sft[data_val][int(mip_level)]
                else:
                    style = sft[data_val][int(mip_level)]

                idx = index_func[data_val]
                final_color = style * idx
                final_opacity = 0.5

                color = [color[i] + (1.0 - opacity) * final_color[i] * final_opacity for i in range(3)]
                opacity = 1.0 - (1.0 - opacity) * (1.0 - final_opacity)

                if opacity > 0.99:
                    break
                t += 0.5

            output[y][x] = color
    return output
```
## Subtopics

### [Mipmapped Smooth Transitions](2973-mipmapped-smooth-transitions.md)
Mipmapped Smooth Transitions is a technique used within Ray-Guided Streaming to provide temporal coherence and anti-aliasing during volume rendering. It addresses the visual artifacts caused by abrupt changes in sampling rates or data resolution as the camera or volume moves, ensuring smooth visual transitions between different levels of detail. It distinguishes itself from static mipmapping by focusing on temporal stability rather than just spatial aliasing reduction.

## Operating characteristics
**Time and Memory Complexity:**
- Time: Additional texture fetches required for mipmapping and bias calculation [S1, unofficial]. Maximum of four additional texture fetches compared to regular 1D transfer function (two for index, two for style) [S1, unofficial].
- Memory: Depends on SFT layout [S1, unofficial]. Texture array requires storing multiple 2D layers [S1, unofficial].

**Measured Performance:**
- Performance comparison on GeForce 8 series hardware:
  - Figure 7(a): Regular TF 11.7 fps, Style TF 11.9 fps [S1, unofficial].
  - Figure 7(b): Regular TF 10.5 fps, Style TF 9.6 fps [S1, unofficial].
  - Figure 7(c): Regular TF 10.1 fps, Style TF 8.1 fps [S1, unofficial].
  - Figure 7(d): Regular TF 12.5 fps, Style TF 12.8 fps [S1, unofficial].
- Data dimensions: $256 \times 256 \times 230$ [S1, unofficial]. Viewport size: $512 \times 512$ [S1, unofficial]. Object sample distance: 0.5 [S1, unofficial].

**Scaling:**
- Performance benefits from texture caching, especially for the small index function texture [S1, unofficial].
- EXT_texture_buffer_object extension can provide additional performance gains for index function texture on GeForce 8 series [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Avoids aliasing, prevents style mixing (with proper layout) [S1, unofficial].
- Limitations: Requires manual mip-map level computation, undefined hardware derivatives in loops, potential artifacts in high-curvature areas [S1, unofficial].

**When to Use:**
- Use when aliasing in style lookups is a concern [S1, unofficial].
- Avoid using 3D textures for SFT if mipmapping is enabled [S1, unofficial].
