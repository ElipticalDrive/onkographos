# Position-dependent Transfer Function Customization

Also called: Interactive Position-dependent Customization via Primitives, Seed Customization Points

## Overview
This method allows users to interactively modify transfer function classification parameters (such as opacity and color) at specific 3D locations within a volume dataset using configurable geometric primitives [S1]. It solves the problem of highlighting regions of interest (e.g., medical stenosis) without losing surrounding spatial context, which is often lost when using simple clipping approaches [S1]. Unlike its siblings, it does not define the base color mapping itself but acts as a spatial override layer that blends with or modifies the base transfer function output [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A base transfer function $f(t)$ mapping normalized scalar data $t \in [0, 1]$ to color $\mathbf{c}$ and opacity $\alpha$; a set of user-defined geometric primitives $\mathcal{P} = \{p_1, \dots, p_n\}$; and the volume dataset $V$.
*   **Output:** A modified classification volume where opacity is lowered outside regions of interest and colors are modified inside them, providing direct visual feedback [S1].

**Data Structures:**
*   **Primitive ($p_i$):** Defined by:
    *   `position`: A 3D vector $(x, y, z)$ representing the geometric center of the primitive. Can be specified in voxel coordinates or set interactively via mouse in 2D views [S1].
    *   `extent`: A 3D vector $(e_x, e_y, e_z)$ defining the spatial size along each axis [S1].
    *   `parameters`: User-defined visualization parameters associated with the primitive (e.g., target color or opacity values) [S1].
    *   `id`: A unique integer identifier corresponding to the creation order of the seed point [S1].
    *   `enabled`: A boolean flag. Disabled primitives are ignored during customization volume computation [S1].
*   **Customization Volume:** A 3D grid (resolution configurable) storing the influence of all active primitives. The memory requirements are configurable [S1].

**Steps:**
1.  **Primitive Definition:** The user adds, disables, or adjusts primitives via a property list or 2D view interaction. The position is the center, and the extent defines the shape:
    *   Extent $(0,0,0)$ defines a point [S1].
    *   Non-zero extent in exactly one direction defines a line [S1].
    *   Non-zero extents in two or three directions define a rectangle or cuboid, respectively [S1].
2.  **Customization Volume Computation:** Upon any position update, the system immediately recalculates the customization volume. This volume represents the spatial influence of the primitives [S1].
3.  **Classification Modification:** The updated customization volume is used in an additional classification step. This step lowers opacity values outside the region of interest and modifies color values inside it [S1].
4.  **Rendering and Feedback:** The updated customization volume and seed points are rendered across all views.
    *   **Seed Point Visualization:** Two color schemes are available:
        1.  **Heat Map:** Maps a user-defined visualization parameter value to color [S1].
        2.  **Unique ID:** Colors points based on creation order; all points belonging to the same primitive share the same color [S1].
    *   **Occlusion Handling:** Seed points can be forced into the foreground to bypass 3D occlusion [S1].
    *   **Orientation Lines:** Axis-aligned orientation lines from each seed point to the bounding box borders can be toggled [S1].

    """
    Computes a 3D grid representing the influence of geometric primitives.
    primitives: List of Primitive objects.
    volume_shape: Tuple (D, H, W) defining the resolution of the output volume.
    """
    # Initialize customization volume with zeros or base values
    # Note: Exact blending formula for overlapping primitives is not given in sources [G]
    customization_vol = zeros(volume_shape)
    
    for p in primitives:
        if not p.enabled:
            continue
            
        # Determine the voxel indices covered by the primitive
        # Primitive is defined by center (p.position) and extent (p.extent)
        # Calculate bounds based on center and half-extents
        center = p.position
        half_ext = p.extent / 2.0
        
        min_idx = floor(center - half_ext)
        max_idx = ceil(center + half_ext)
        
        # Clip to volume bounds
        min_idx = clamp(min_idx, 0, volume_shape - 1)
        max_idx = clamp(max_idx, 0, volume_shape - 1)
        
        # For each voxel in the bounding box, update the customization volume
        # The specific influence function (e.g., Gaussian falloff, box filter) 
        # is not detailed in the sources [G]
        for x in range(min_idx[0], max_idx[0] + 1):
            for y in range(min_idx[1], max_idx[1] + 1):
                for z in range(min_idx[2], max_idx[2] + 1):
                    # Update customization_vol[x, y, z] based on p.parameters
                    # This step integrates the primitive's influence into the volume
                    update_customization_volume_entry(customization_vol, x, y, z, p)
                    
    return customization_vol

**Parameters:**
*   **Spatial Extent:** Scalar values per dimension. Zero in all directions = point; non-zero in one = line; non-zero in two/three = rectangle/cuboid [S1].
*   **Position:** Geometric center. Specified in voxel coordinates or via 2D mouse interaction [S1].
*   **Customization Volume Resolution:** Configurable. Higher resolution increases accuracy but also memory usage [S1].

**Edge Cases and Pitfalls:**
*   **3D Mouse Placement:** Exact placement of points in 3D views using a mouse is difficult; the method focuses configuration input on 2D views and uses 3D rendering only for feedback [S1].
*   **Cognitive Load:** Large numbers of seed points can make matching 2D and 3D representations difficult; the Unique ID coloring scheme alleviates this [S1].
*   **Performance:** The additional classification step reduces overall rendering performance, but the effect is negligible compared to memory transfer bandwidth for large datasets [S1].

## Operating characteristics
*   **Time Complexity:** The additional classification step adds overhead, but it is negligible compared to the memory transfer bandwidth required for rendering large volume datasets [S1].
*   **Memory Complexity:** Memory requirements for the customization volume are configurable [S1].
*   **Strengths:** Highlights features (e.g., stenosis) without losing surrounding volume structure, which would be lost with simple clipping [S1]. Provides direct visual feedback during interaction [S1].
*   **Limitations:** Currently limited to axis-aligned primitives (non-axis-aligned primitives are planned for future work) [S1]. Configuration is primarily done in 2D views due to 3D mouse placement difficulties [S1].
*   **When to use:** Interactive region-of-interest highlighting and parameter tuning in direct volume rendering of large datasets, particularly in medical and biological research (e.g., CT scans of human hearts) [S1].

## Background
The method was proposed in a paper titled "Interactive Position-dependent Customization of Transfer Function Classification Parameters in Volume Rendering" [S1]. It is applied to direct volume rendering of large datasets, particularly in medical and biological research [S1]. Future work includes refining the user interface for non-axis-aligned primitives and extending the implementation to include more sophisticated parameters such as color maps for classification [S1].
