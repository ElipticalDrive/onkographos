# Position-dependent Transfer Function Customization

Also called: Customization volume method, Interactive Position-dependent Customization of Transfer Function Classification Parameters, Interactive Position-dependent Customization via Primitives, Position-dependent customization, Seed Customization Points

## Overview
This method enables interactive, position-dependent modification of transfer function classification parameters in volume rendering by defining user-specified seed points and interpolating their effects across the volume via a lightweight "customization volume" [S1]. Unlike global transfer functions that apply uniform classification rules, this approach allows local adaptations of visualization parameters (e.g., intensity correction, color maps) based on voxel position without requiring preprocessing steps like segmentation or distance field computation [S1]. It addresses the limitation of standard transfer functions, which assume constant feature characteristics, by allowing users to highlight specific regions (e.g., stenosis in medical scans) while preserving spatial context, a capability lost in simple clipping approaches [S1].

## How it works
The method operates in three primary phases: defining seed customization points, calculating the customization volume, and integrating the result into the rendering pipeline [S1].

### Inputs and Outputs
*   **Input:**
    *   Volume dataset $V$ with dimensions $D_x \times D_y \times D_z$.
    *   Set of seed customization points $S = \{p_1, p_2, ..., p_n\}$, where each $p_i$ consists of a voxel position $\mathbf{x}_i$ and a parameter vector $\mathbf{v}_i$ [S1].
    *   Geometric primitives defining the spatial extent of each seed point (points, lines, rectangles, cuboids) [S1].
*   **Output:**
    *   A customized classification result where optical properties (opacity, color) are modified based on the spatial location of the sample point relative to the seed points [S1].

### Data Structures

**1. Seed Customization Point ($p$)**
*   **Position ($\mathbf{x}$):** 3D voxel coordinates $(x, y, z)$ [S1].
*   **Parameter Vector ($\mathbf{v}$):** Contains all customizations for visualization parameters. Types include:
    *   Scalar floats (e.g., intensity correction factor) [S1].
    *   Complex structures (e.g., entire color map or transfer function segment) [S1].
*   **Primitive Extent:** Defined by scalar values for each dimension $(e_x, e_y, e_z)$ [S1].
    *   $e_x=e_y=e_z=0$: Point.
    *   One non-zero extent: Line.
    *   Two non-zero extents: Rectangle.
    *   Three non-zero extents: Cuboid [S1].
*   **Primitive Position:** Geometric center of the primitive, specified in voxel coordinates or via 2D view interaction [S1].

**2. Customization Volume ($C$)**
*   **Resolution:** Configurable grid size $R_x \times R_y \times R_z$, typically between $32^3$ and $512^3$ voxels, depending on GPU memory and parameter complexity [S1].
*   **Data Layout:** For each voxel in $C$, store the interpolated parameter vector $\mathbf{v}_{interp}$ corresponding to that spatial location [S1].
*   **Memory:** Size is independent of the input volume size $V$, making it suitable for large datasets ($>1000^3$ voxels) [S1].

### Algorithm Steps

**Step 1: Define Seed Customization Points**
The user defines a set of seed points $S$. Individual specification for every voxel in large volumes is infeasible; thus, customization is limited to these sparse seeds [S1].
*   User creates primitives (points, lines, etc.) via a property list or 2D view interaction [S1].
*   Each primitive is associated with a parameter vector $\mathbf{v}$ [S1].
*   Disabled points are ignored during subsequent calculations [S1].

**Step 2: Calculate Customization Volume**
The system interpolates the parameter vectors from the seed points $S$ to fill the customization volume $C$ [S1]. This is performed on the GPU using OpenGL compute shaders to achieve interactive frame rates [S1].

*Interpolation Requirements:*
1.  **Exactness:** The interpolation must not change the value at the user-defined seed points [S1].
2.  **Continuity and Monotonicity:** Interpolation between neighboring seed points must be continuous and monotonic [S1].
3.  **Locality:** Each seed point should only have local influence [S1].

**Step 3: Integration into Volume Rendering Pipeline**
The customization volume is integrated into the classification step of the ray casting pipeline [S1].

1.  **Sampling:** For each ray sample at position $\mathbf{x}_{sample}$ in the volume $V$, gather input parameters (e.g., intensity $I$, gradient $\nabla I$) [S1].
2.  **Fetch Customization:** Map $\mathbf{x}_{sample}$ to the corresponding voxel in the customization volume $C$ and fetch the interpolated parameter vector $\mathbf{v}_{custom}$ [S1].
3.  **Apply Modification:** Apply $\mathbf{v}_{custom}$ to the input parameters or the transfer function itself, depending on the parameter type [S1].
    *   *Example:* If $\mathbf{v}_{custom}$ contains an intensity correction factor, modify the input intensity $I$ before passing it to the transfer function.
    *   *Example:* If $\mathbf{v}_{custom}$ contains a color map, use it to override the color output of the transfer function [S1].
4.  **Classification:** Compute opacity $\alpha$ and color $C$ using the modified parameters and the base transfer function [S1].
5.  **Accumulation:** Perform standard volume rendering accumulation (e.g., front-to-back compositing) [S1].

### Parameters and Typical Values
*   **Customization Volume Resolution:** $32^3$ to $512^3$ voxels [S1].
*   **Primitive Types:** Axis-aligned points, lines, rectangles, cuboids [S1].
*   **Visualization Feedback:**
    *   Seed points can be forced to foreground to bypass 3D occlusion [S1].
    *   Axis-aligned orientation lines from seed points to bounding box borders can be toggled [S1].
    *   Color schemes: Heat map (parameter value to color) or Unique ID (creation order) [S1].

### Edge Cases and Pitfalls
*   **Large Data Sets:** Individual specification for each voxel is not feasible for volumes $>1000^3$ voxels; seed points are necessary [S1].
*   **Performance Overhead:** The additional classification step adds negligible overhead compared to the memory transfer bandwidth required for rendering large volume datasets [S1].
*   **Precision:** Interpolation must preserve exact values at seed points to ensure user intent is met [S1].

## Subtopics

### [Dual-Domain Interaction](5633-dual-domain-interaction.md)
An interaction paradigm where transfer function specification is driven by direct interaction in the spatial domain (volume) with feedback in the transfer function domain, reversing the traditional workflow. It solves the conceptual gap between 3D geometry and abstract TF space, particularly for multi-dimensional TFs.

## Operating characteristics
*   **Time Complexity:** The interpolation step is performed on the GPU using compute shaders. The overhead of the extra classification step is negligible compared to the memory transfer bandwidth for large datasets [S1].
*   **Memory Complexity:** Memory requirements for the customization volume are configurable and independent of the input volume size, scaling with the chosen resolution ($32^3$ to $512^3$) [S1].
*   **Strengths:**
    *   No preprocessing required (unlike distance fields or segmentation-based methods) [S1].
    *   Preserves spatial context (unlike simple clipping) by lowering opacity outside regions of interest while modifying colors inside [S1].
    *   Applicable to large datasets (e.g., 9.5 GB mouse embryo data) [S1].
*   **Limitations:**
    *   Limited to axis-aligned primitives in the current implementation (non-axis-aligned primitives are future work) [S1].
    *   Relies on user-defined seed points; poor seed placement may lead to unintuitive interpolation results [S1].
*   **When to Use:** Interactive region-of-interest highlighting and parameter tuning in direct volume rendering of large datasets, particularly in medical and biological research (e.g., CT scans of human hearts) [S1].
*   **When Not to Use:** When global, uniform classification is sufficient, or when preprocessing capabilities (segmentation) are available and preferred for defining regions of interest [S1].

## Background
The method was proposed in 2015 by researchers in the field of computer graphics and visualization [S1]. It addresses the limitation of standard transfer functions, which assume constant feature characteristics across the volume, by introducing a position-dependent extension. The approach builds on existing transfer function concepts (e.g., [BKW08], [GY13]) but extends them to allow user-defined, position-dependent customizations without preprocessing [S1]. It is particularly relevant for medical imaging, where scanner technology restrictions can cause intensity homogeneities, necessitating local adjustments [S1].
