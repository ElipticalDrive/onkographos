# 2D Transfer Function Widget

Also called: 2D TF Display, TF Widget, Transfer Function Widget, Transfer Function Widget Implementation

## Overview
The 2D Transfer Function Widget is an interactive visualization interface that presents a 2D slice of a multi-dimensional transfer function (TF) domain, allowing users to manually define and edit classification parameters while receiving real-time feedback from volume queries [S2]. It solves the problem of mapping spatial volume characteristics to optical properties by "re-projecting" local voxel data (values and derivatives) into the TF domain as graphical markers [S2]. Unlike standard point probes, it visualizes the local gradient and curvature structure by connecting corner points with edges reflecting spatial connectivity, enabling users to distinguish between homogeneous regions and boundaries [S2]. It builds on [Interaction and Editing Interfaces](6592-interaction-and-editing-interfaces.md) by providing a direct-manipulation canvas for the TF definition [G].

## How it works
**Inputs and Outputs:**
*   **Input:** User mouse interactions (drag, right-click) within the widget canvas; volume data queries (probe position or clipping plane location) [S1, unofficial][S2].
*   **Output:** An updated piecewise linear transfer function defined by control points (handles) in the 2D domain, typically exported as a lookup table (LUT) or used directly by a renderer [S1, unofficial][S2].

**Data Structures:**
The core implementation uses a class `TransferFunctionWidget` with the following fields [S1, unofficial]:
*   `domain_` (int): Size of the transfer function lookup table (number of entries per channel).
*   `width_`, `height_` (float): Physical dimensions of the widget canvas [S1, unofficial].
*   `scaling_` (float): Scaling factor for the canvas.
*   `handleRadius_`, `handleBorder_` (float): Visual properties of control points [S1, unofficial].
*   `isHandleCaptured_`, `isFocusMode_` (bool): State flags for interaction [S1, unofficial].
*   `groupActive_`, `handleActive_` (std::size_t): Indices of the currently active channel group and handle [S1, unofficial].
*   `handleCountMax_` (std::size_t): Maximum number of handles allowed per group.
*   `margins_`, `origin_` (ImVec2): Canvas layout parameters [S1, unofficial].
*   `label_` (std::string): Widget label.
*   `groups_` (std::array<std::vector<ImVec2>, 4>): Array of 4 vectors storing control points (handles) for R, G, B, A channels respectively. Indexed by `GROUP_R=0`, `GROUP_G=1`, `GROUP_B=2`, `GROUP_A=3` [S1, unofficial].

**Coordinate Systems:**
The widget maintains two coordinate systems: Screen coordinates (pixel positions) and Canvas coordinates (normalized 0.0 to 1.0) [S1, unofficial].
*   **Screen to Canvas:**
    $$
    \begin{aligned}
    height &= height_ \times scaling_ \\
    px &= (pos.x - origin_.x) / scaling_ \\
    py &= -((pos.y - origin_.y - height) / scaling_) \\
    canvas.x &= px / width_ \\
    canvas.y &= py / height_
    \end{aligned}
    $$
*   **Canvas to Screen:**
    $$
    \begin{aligned}
    height &= height_ \times scaling_ \\
    screen.x &= (pos.x \times width_) \times scaling_ + origin_.x \\
    screen.y &= (height - (pos.y \times height_) \times scaling_) + origin_.y
    \end{aligned}
    $$

**Interaction Steps:**
1.  **Volume Query & Re-projection:** When a user queries the volume (via a probe or clipping plane), the system identifies the voxel containing the query point [S2]. It calculates the data value and derivatives (gradient magnitude, second derivative) for the query point and the eight corners of that voxel [S2].
2.  **Feedback Rendering:** The system renders 9 balls in the TF widget: one for the query point and eight for the voxel corners [S2]. Edges connect the corner balls to reflect spatial voxel connectivity [S2]. The second derivative values are indicated by colormapping the balls: negative, zero, and positive second derivatives are represented by blue, white, and yellow balls, respectively [S2].
3.  **Handle Creation:** If the user right-clicks within the canvas (normalized coordinates $0.0 < x < 1.0$ and $0.0 < y < 1.0$) and no handle is selected, and the number of active handles is less than `handleCountMax_`, a new handle is appended to the active group at the click position [S1, unofficial]. The handles are then sorted by x-coordinate ascending [S1, unofficial].
4.  **Handle Manipulation:** If a handle is active, the user can drag it [S1, unofficial]. The new position `posNext` is clamped: `posNext.x` is clamped to `[xMin, xMax]` (where `xMin` is the x-coordinate of the previous handle or 0, and `xMax` is the x-coordinate of the next handle or 1), and `posNext.y` is clamped to `[0.0f, 1.0f]` [S1, unofficial]. The active handle's position is updated, and a `changed` flag is set to true [S1, unofficial].
5.  **Transfer Function Generation:** The piecewise linear TF is generated from the handles [S1, unofficial]. For each channel group:
    *   Initialize a vector `function` of size `domain_ * groupCount` with 0.0f [S1, unofficial].
    *   Scale handle positions by `scaleToDomain = (domain_, 1.0f)` to get `a` and `b` for consecutive handles [S1, unofficial].
    *   Compute `interval = round(b.x) - round(a.x)` and `slope = (b.y - a.y) / interval` [S1, unofficial].
    *   For each `handleId` from 0 to `interval - 1`:
        $$ x = groupId + groupCount \times (handleId + round(a.x)) $$
        $$ function[x] = handleId \times slope + a.y $$
6.  **Export:** The TF can be exported to a file with header `# Transfer Function` and `# Value    R    G    B    A`, writing the row index and channel values with precision 4 [S1, unofficial].

**Pseudocode:**
```python
class TransferFunctionWidget:
    def __init__(self, domain_size, width, height, scaling, handle_count_max):
        self.domain_ = domain_size
        self.width_ = width
        self.height_ = height
        self.scaling_ = scaling
        self.handle_count_max_ = handle_count_max
        # groups_ is an array of 4 vectors (R, G, B, A), each storing ImVec2 (x, y)
        self.groups_ = [[], [], [], []]
        self.group_active_ = 0
        self.handle_active_ = 0
        self.is_handle_captured_ = False
        self.origin_ = (0.0, 0.0)
        self.changed = False

    def canvas_coord(self, screen_pos):
        height = self.height_ * self.scaling_
        px = (screen_pos.x - self.origin_.x) / self.scaling_
        py = -((screen_pos.y - self.origin_.y - height) / self.scaling_)
        return (px / self.width_, py / self.height_)

    def screen_coord(self, canvas_pos):
        height = self.height_ * self.scaling_
        x = (canvas_pos.x * self.width_) * self.scaling_ + self.origin_.x
        y = (height - (canvas_pos.y * self.height_) * self.scaling_) + self.origin_.y
        return (x, y)

    def handle_mouse(self, mouse_pos, is_right_clicked, is_dragging):
        canvas_pos = self.canvas_coord(mouse_pos)
        active_group = self.groups_[self.group_active_]

        if is_dragging and self.handle_active_ < len(active_group):
            # Determine bounds for x-clamping
            idx = self.handle_active_
            x_min = 0.0
            x_max = 1.0
            if idx > 0:
                x_min = active_group[idx - 1].x
            if idx < len(active_group) - 1:
                x_max = active_group[idx + 1].x

            # Clamp position
            pos_next_x = max(x_min, min(x_max, canvas_pos.x))
            pos_next_y = max(0.0, min(1.0, canvas_pos.y))
            
            active_group[idx] = (pos_next_x, pos_next_y)
            self.changed = True

        elif is_right_clicked and not is_dragging:
            if (0.0 < canvas_pos.x < 1.0) and (0.0 < canvas_pos.y < 1.0):
                if len(active_group) < self.handle_count_max_:
                    active_group.append(canvas_pos)
                    # Sort handles by x-coordinate
                    active_group.sort(key=lambda p: p.x)
                    self.changed = True

    def generate_transfer_function(self):
        group_count = len(self.groups_)
        function = [0.0] * (self.domain_ * group_count)
        scale_to_domain = (self.domain_, 1.0)

        for group_id in range(group_count):
            group = self.groups_[group_id]
            for idx in range(1, len(group)):
                b = (group[idx].x * scale_to_domain[0], group[idx].y * scale_to_domain[1])
                a = (group[idx-1].x * scale_to_domain[0], group[idx-1].y * scale_to_domain[1])
                
                interval = round(b.x) - round(a.x)
                if interval <= 0:
                    continue
                    
                slope = (b.y - a.y) / interval
                
                for handle_id in range(interval):
                    x = group_id + group_count * (handle_id + round(a.x))
                    function[x] = handle_id * slope + a.y
        return function

    def export_to_file(self, filename):
        function = self.generate_transfer_function()
        col_size = len(self.groups_)
        with open(filename, 'w') as f:
            f.write("# Transfer Function\n")
            f.write("# Value    R    G    B    A\n")
            for row in range(self.domain_):
                f.write(f"{row}")
                for col in range(col_size):
                    f.write(f"    {function[row * col_size + col]:.4f}")
                f.write("\n")
```

## Subtopics

### [Re-projected Voxel Visualization](6550-re-projected-voxel-visualization.md)
Re-projected Voxel Visualization is an interaction technique that maps a spatial voxel to the transfer function (TF) domain to help users interpret local volume characteristics. It represents the data value and derivatives at a query position and the eight corner samples of the containing voxel as points in the TF domain. Unlike standard point probes, it visualizes the local gradient and curvature structure by connecting corner points with edges reflecting spatial connectivity. This allows users to distinguish between homogeneous regions and boundaries based on the geometric configuration of the projected points.

### [Gaussian Widget for Transfer Function Design](6568-gaussian-widget-for-transfer-function-design.md)
The Gaussian Widget is an interactive interface component that defines transfer functions in a reduced-dimensional domain (e.g., 3D) by mapping input feature vectors to colors using a Gaussian distribution centered at a user-selected location. It solves the problem of manually tuning volumetric appearance by providing a visual, direct-manipulation interface where Gaussian parameters (position and spread) map directly to transfer function properties. It differs from its sibling [Piecewise Gaussian Transfer Function Widget](7724-piecewise-gaussian-transfer-function-widget.md) by mapping feature vectors to colors via a single distribution rather than composing multiple piecewise Gaussian functions.

## Operating characteristics
*   **Time Complexity:** Generating the transfer function from handles is $O(D \times C)$, where $D$ is the domain size and $C$ is the number of channels (typically 4) [S1, unofficial]. Interaction handling is $O(1)$ per event, except for handle sorting which is $O(H \log H)$ where $H$ is the number of handles [S1, unofficial].
*   **Memory Complexity:** $O(H \times C)$ to store the handles, plus $O(D \times C)$ for the generated LUT [S1, unofficial].
*   **Strengths:** Provides intuitive direct manipulation of the TF; visual feedback from volume queries helps users understand the relationship between spatial data and TF parameters; supports multi-dimensional TFs by displaying slices [S2].
*   **Limitations:** Limited to 2D slices of the TF domain; may not fully represent complex multi-dimensional relationships; performance depends on the number of handles and domain size [S1, unofficial][S2].
*   **When to use:** When users need precise, manual control over the TF and benefit from visual feedback about local volume characteristics [S2].
*   **When not to use:** For fully automated TF design or when the TF domain is too high-dimensional to be effectively represented by 2D slices [S2].

## Background
The 2D Transfer Function Widget was introduced in the context of interactive volume rendering using multi-dimensional transfer functions [S2]. It is part of a system that allows users to query the volume and see the corresponding representation in the TF domain, facilitating the design of complex transfer functions [S2]. The implementation described in [S1, unofficial] is a modern C++/ImGui-based version of such a widget, demonstrating the practical application of these concepts in a graphical user interface [S1, unofficial].
