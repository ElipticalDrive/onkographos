# 2D Transfer Function Widget

Also called: 2D TF Display, TF Widget, Transfer Function Widget

## Overview
The 2D Transfer Function Widget is a graphical interface that presents a 2D slice of the 3D transfer function domain, allowing users to manually set and alter the transfer function while receiving visual feedback from volume queries [S1]. It distinguishes itself from other interaction methods by explicitly "re-projecting" spatial voxel information (data value and derivatives) into the transfer function domain, enabling users to understand how classification variables change near a specific probe location [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point in the spatial volume domain, obtained via a Data Probe or Clipping Plane widget [S1].
*   **Output:** A 2D graphical representation where the horizontal axis represents Data Value and the vertical axis represents Gradient Magnitude [S1].

**Data Structures:**
The widget is implemented as a basic frame widget [S1].
*   **Axes:**
    *   Horizontal axis: Data value ($v$).
    *   Vertical axis: Gradient magnitude ($\|\nabla f\|$).
    *   Note: The third axis (Second Derivative) is not explicitly represented on the 2D plane but is controlled by other sub-widgets [S1].
*   **Inner Plane:** A polygon texture-mapped with a slice through the 3D Lookup Table (LUT) containing the full 3D transfer function [S1].
*   **Interactive Elements:**
    *   **Balls:** Represent queried data points.
    *   **Edges:** Connect corner balls to reflect spatial voxel connectivity [S1].
    *   **Corner Controls:** Balls at the corners of the widget frame are used to resize the widget [S1].
    *   **Edge Controls:** Bars on the edges of the widget frame are used to translate the widget's position [S1].

**Numbered Steps:**
1.  **Query:** The user performs a query in the volume using a Data Probe or Clipping Plane widget [S1].
2.  **Voxel Identification:** The system identifies the voxel containing the query point [S1].
3.  **Feature Calculation:** The system calculates the data value ($v$) and derivatives for:
    *   The query point itself.
    *   The 8 corners of the identified voxel [S1].
4.  **Re-projection:** The system maps these 9 points (1 query + 8 corners) into the 2D Transfer Function domain:
    *   $x_{TF} = v$
    *   $y_{TF} = \|\nabla f\|$
5.  **Rendering Feedback:**
    *   Render 9 balls in the TF widget: one for the query point, eight for the voxel corners [S1].
    *   Color-code the balls based on the second derivative ($\nabla^2 f$) of the data value:
        *   Negative second derivative: Blue [S1].
        *   Zero second derivative: White [S1].
        *   Positive second derivative: Yellow [S1].
    *   Draw edges connecting the corner balls to reflect the connectivity of the voxel corners in the spatial domain [S1].
6.  **User Interaction:** The user observes the distribution of balls to understand how TF variables change near the probe. The user can then adjust the transfer function (via the LUT slice or other controls) [S1].

**Parameters and Edge Cases:**
*   **Second Derivative Visualization:** The color mapping for the second derivative is a critical visual cue. If the second derivative is not available or calculated, the balls may default to a neutral color or omit this specific feedback [G].
*   **Widget Bounds:** The resize and translate controls allow the user to adjust the visible range of data values and gradient magnitudes. If the query point falls outside the current widget bounds, the widget may need to auto-scale or the user must manually translate/resize to view the feedback [G].

## Subtopics

### [Re-projected Voxel Visualization](6550-re-projected-voxel-visualization.md)
A visualization technique where a voxel from the spatial domain is mapped to the 3D transfer function domain to help the user understand how transfer function variables (data value and derivatives) change near a probe location.

### [Gaussian Widget for Transfer Function Design](6568-gaussian-widget-for-transfer-function-design.md)
A method for defining transfer functions in a reduced-dimensional domain (e.g., 3D) by mapping input feature vectors to colors using a Gaussian distribution centered at a user-selected location.

## Operating characteristics
*   **Time Complexity:** The computational cost per query is constant, involving the calculation of derivatives for 9 points (1 query + 8 corners) and their mapping to 2D coordinates [S1].
*   **Memory Complexity:** The widget requires storage for the 3D LUT slice and the interactive elements (balls, edges) [S1].
*   **Strengths:** Provides immediate visual feedback on the local behavior of the transfer function variables, aiding in the tuning of classification parameters for specific structures [S1].
*   **Limitations:** Only displays a 2D slice of the 3D domain; the third dimension (second derivative) is not directly visible on the plane but is indicated by color [S1].

## Background
The 2D Transfer Function Widget was introduced in the context of interactive volume rendering using multi-dimensional transfer functions, specifically demonstrated with CT tooth datasets [S1]. It is part of a suite of widgets designed to facilitate dual-domain interaction, bridging the spatial domain (volume) and the transfer function domain [S1].
