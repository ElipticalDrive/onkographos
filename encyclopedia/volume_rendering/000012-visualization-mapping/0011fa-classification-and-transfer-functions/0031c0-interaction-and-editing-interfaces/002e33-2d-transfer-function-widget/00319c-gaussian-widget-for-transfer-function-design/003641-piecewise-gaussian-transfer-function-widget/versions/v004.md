# Piecewise Gaussian Transfer Function Widget

Also called: Dynamic Transfer Function Widget, Gaussian Widget, Interactive Transfer Function Editor, Piecewise Gaussian Transfer Function Configuration, vtkPiecewiseGaussianWidget

## Overview
The Piecewise Gaussian Transfer Function Widget is an interactive user interface component that allows users to define and edit color and opacity transfer functions by placing Gaussian curves over a data histogram [S1, S2, S3, unofficial]. It solves the problem of manually specifying visibility and color mappings in volume rendering by providing a visual, histogram-based editor where users can add, move, and resize Gaussian distributions to shape the transfer function [S1, S3, unofficial]. Unlike static parameter tuning or basic handle-based editors, this method uses Gaussian functions as the fundamental building blocks of the transfer function, allowing for smooth, continuous transitions and intuitive control over the contribution of specific data ranges [S1, S3, unofficial]. It builds on [Gaussian Widget for Transfer Function Design](6568-gaussian-widget-for-transfer-function-design.md) by implementing the Gaussian mapping in a 2D widget context (value vs. opacity/color) with histogram integration.

## How it works
The widget operates by displaying a histogram of the scalar data and allowing the user to overlay Gaussian curves that define the opacity and color contributions. The final transfer function is the superposition of these Gaussian components.

### Inputs and Outputs
*   **Input:** A scalar data array (e.g., from a volume dataset) and its range.
*   **Output:** A modified opacity piecewise function and a color lookup table (or transfer function) that are applied to the volume mapper.

### Data Structures
The widget maintains an internal list of Gaussian curves. Each Gaussian is defined by five parameters:
1.  $x$: The center position on the data value axis (normalized or absolute).
2.  $y$: The peak height (opacity or color intensity).
3.  $\sigma_x$: The width (standard deviation) along the data value axis.
4.  $\sigma_y$: The height spread (standard deviation) along the opacity/color axis.
5.  $\alpha$: The opacity spread (specifically for opacity Gaussians).

The histogram is stored as an array of bin counts, with a resolution defined by `numberOfBins`.

### Parameters
*   `numberOfBins`: The number of bins in the displayed histogram. Typical value: 256 [S1, S2, S3, unofficial].
*   `size`: The dimensions of the widget in pixels, specified as `[width, height]`. Typical value: `[400, 150]` [S2, S3, unofficial].
*   `addGaussian(x, y, sigmaX, sigmaY, alpha)`: Method to add a new Gaussian curve.
    *   $x$: Position (0.0 to 1.0 normalized, or data range). Example: 0.425 [S3, unofficial].
    *   $y$: Height. Example: 0.5 [S3, unofficial].
    *   $\sigma_x$: Width. Example: 0.2 [S3, unofficial].
    *   $\sigma_y$: Height spread. Example: 0.3 [S3, unofficial].
    *   $\alpha$: Opacity spread. Example: 0.2 [S3, unofficial].

### Steps
1.  **Instantiate Widget:** Create the widget instance with `numberOfBins` and `size` [S1, S2, S3, unofficial].
    *   Example: `vtkPiecewiseGaussianWidget.newInstance({ numberOfBins: 256, size: [400, 150] })` [S3, unofficial].
2.  **Create Container:** Create a DOM container element with specific styling (e.g., absolute position, background transparency) and set it as the widget's container [S2, unofficial].
3.  **Bind Data:** Bind the scalar data array to the widget so it can compute and display the histogram [S3, unofficial].
    *   Example: `widget.setDataArray(dataArray.getData())` [S3, unofficial].
4.  **Style Configuration:** Apply visual style properties including background, histogram color, stroke, active state, handle, and button colors, as well as stroke widths and padding [S2, unofficial].
5.  **Bind Transfer Functions:**
    *   Apply the opacity transfer function: `widget.applyOpacity(piecewiseFunction)` [S3, unofficial].
    *   Bind the color transfer function: `widget.setColorTransferFunction(lookupTable)` [S3, unofficial].
6.  **Add Gaussians:** Add Gaussian curves to the widget using the `addGaussian` method with specific parameters [S3, unofficial].
    *   Example: `gaussWidget.addGaussian(0.425, 0.5, 0.2, 0.3, 0.2)` [S3, unofficial].
    *   Example: `gaussWidget.addGaussian(0.75, 1, 0.3, 0, 0)` [S3, unofficial].
7.  **Bind Listeners:**
    *   Register a modification listener on the lookup table to trigger re-rendering of the widget and scene when changes occur [S3, unofficial].
    *   Register an opacity change listener on the widget to apply the updated opacity function to the piecewise function and trigger a render [S1, S3, unofficial].
        *   Example: `adjustableTransferFunctionWidget.onOpacityChange(() => { adjustableTransferFunctionWidget.applyOpacity(piecewiseFun); renderWindow.render(); })` [S1, unofficial].

### Pseudocode
```python
# Initialization
widget = vtkPiecewiseGaussianWidget.newInstance(numberOfBins=256, size=[400, 150])

# Container Setup
container = document.querySelector('#container')
widget.setContainer(container)

# Data Binding
data_array = get_scalar_data_array()
widget.setDataArray(data_array)

# Style Configuration
widget.setStyle({
    background: 'rgba(255, 255, 255, 0.3)',
    histogram: 'gray',
    stroke: 'black',
    active: 'blue',
    handle: 'red',
    button: 'green',
    strokeWidth: 1,
    handleWidth: 5,
    iconSize: 10,
    padding: 5
})

# Transfer Function Binding
piecewise_fun = vtkPiecewiseFunction.newInstance()
lookup_table = vtkColorTransferFunction.newInstance()

widget.applyOpacity(piecewise_fun)
widget.setColorTransferFunction(lookup_table)

# Adding Gaussians
widget.addGaussian(x=0.425, y=0.5, sigmaX=0.2, sigmaY=0.3, alpha=0.2)
widget.addGaussian(x=0.75, y=1.0, sigmaX=0.3, sigmaY=0.0, alpha=0.0)

# Event Listeners
lookup_table.onModified(lambda: (widget.render(), render_window.render()))

widget.onOpacityChange(lambda: (widget.applyOpacity(piecewise_fun), render_window.render()))
```

### Edge Cases and Pitfalls
*   **Surface Rendering Mode:** The widget may not appear or function correctly if the rendering mode is set to surface rendering rather than volume rendering [S2, unofficial].
*   **Data Range:** The widget expects the data range to be properly mapped. If the data range is not updated or is incorrect, the Gaussian positions (normalized 0-1) may not align with the actual data values [S3, unofficial].
*   **Precision:** The histogram binning resolution (`numberOfBins`) affects the smoothness of the visual feedback. Low resolution may lead to jagged histograms and imprecise Gaussian placement [S1, S2, unofficial].

## Subtopics

### [Interactive Transfer Function Editing](11521-interactive-transfer-function-editing.md)
Interactive Transfer Function (TF) Editing provides a graphical user interface for defining, modifying, and managing the color and opacity mappings used in volume rendering. It solves the problem of manually specifying which data values are visible and how they are colored, allowing users to iteratively refine visualizations through direct manipulation. Unlike static parameter tuning, this method integrates real-time feedback, history management, and structural context (such as cut-away views) into the editing workflow. It distinguishes itself from basic widget-based editing by offering persistent state management (history trees) and structural classification integration (focus+context).

### Programmable Transfer Function GUI Interaction
A GUI implementation (using IMGUI) that allows users to dynamically modify variables in Programmable Transfer Functions, such as isovalue, shading color, volume step size, silhouette terms, silhouette coefficients, specular highlight augmentation coefficient, and intersection shading toggle, without recomputing and storing new transfer function textures [S4]. Parameters like isovalue, volume step size, silhouette term, silhouette coefficients, and the coefficient of specular highlight augmentation are modifiable via the GUI [S4].

### Transfer Function Editor
A UI component for defining multi-isosurface transfer functions, allowing users to add, drag, and adjust color/opacity handles along a gradient bar [S5, unofficial]. It initializes a picker by querying DOM elements for the slider container and background gradient [S5, unofficial]. Handles are added on double-click by cloning a color handle template and computing the color via linear interpolation [S5, unofficial]. The handle position percentage is calculated as $pct = \max(0, \min(bw - hw, clientX - box.left - hw/2) / bw)$, where $bw$ is the bar width and $hw$ is the handle width [S5, unofficial]. Pointer events are attached for dragging: `pointerdown` captures the pointer, `pointermove` updates the left position, and `pointerup` releases the capture [S5, unofficial]. Handles are removed on double-click (`e.detail === 2`) and the gradient is updated [S5, unofficial]. A `hard` boolean toggle controls gradient interpolation mode [S5, unofficial].

### Opacity Widgets
Opacity function is composed of opacity widgets [S6, unofficial]. Three opacity widgets are available: pyramid, Gaussian, and control point based [S6, unofficial]. Opacity widgets can be modified in linear and Iso-Dist mode as needed [S6, unofficial]. In Iso-Dist mode, the opacity function is warped into non-uniform data space, similar to the color function [S6, unofficial].

## Background
The Piecewise Gaussian Transfer Function Widget is part of the VTK (Visualization Toolkit) ecosystem, specifically implemented as `vtkPiecewiseGaussianWidget` [S1, S3, unofficial]. It is used in web-based volume rendering applications to provide an interactive interface for transfer function design [S2, S3, unofficial]. The method builds on the concept of Gaussian widgets for transfer function design, extending it to a 2D widget context with histogram integration [S1, S3, unofficial]. It is commonly used in medical imaging and scientific visualization applications where intuitive control over volume rendering appearance is critical [S1, S3, unofficial].
