# Real-time transfer function evaluation

Also called: Engel, Kraus & Ertl Technique, Texture-based volume rendering with GPU illumination

## Overview
This method enables real-time modification of volume classification by mapping the transfer function (TF) to a 2D texture, allowing the GPU to evaluate color and opacity values during ray casting without CPU intervention [S1, unofficial]. It distinguishes itself from CPU-based illumination approaches (e.g., Westermann & Sevenich) by performing dynamic lighting calculations on the GPU using fragment programs, thereby supporting interactive parameter adjustment [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume data (scalar values), pre-computed gradient data, and a 2D texture representing the transfer function.
*   **Output:** Rendered image with dynamic color and opacity based on interactive parameters.

**Data Structures:**
1.  **Transfer Function Texture:** A 2D texture where the input value range is mapped to the texture coordinates (typically the x-axis or a specific channel). The texture stores the pre-evaluated primary color (RGB) and opacity (A or a separate channel) for each input value [S1, unofficial].
2.  **Gradient Texture:** A compressed RGB texture storing the pre-calculated gradient vector for each volume element [S1, unofficial].

**Steps:**
1.  **Pre-compute Gradients:** Calculate the gradient for each volume element on the CPU or during initialization. Compress these gradients into an RGB texture format [S1, unofficial].
2.  **Build TF Texture:** Evaluate the transfer function for the desired range of input values. Store the resulting color and opacity values in a 2D texture [S1, unofficial].
3.  **Ray Casting with Fragment Program:** Execute a fragment program (e.g., using Cg) for each volume sample along the ray [S1, unofficial].
4.  **Classification:** Sample the TF texture using the current voxel's scalar value to retrieve the primary color and opacity [S1, unofficial].
5.  **Illumination:** Calculate the final color by combining the retrieved primary color with lighting contributions. The fragment program computes diffuse and specular lighting terms using the gradient from the gradient texture and uniform parameters passed from the application [S1, unofficial].

**Formulas:**
*   **Gradient Storage:** Gradients $\nabla V$ are stored in an RGB texture. The exact compression scheme is not specified in the sources [S1, unofficial].
*   **Final Color:** $C_{final} = C_{primary} \cdot (L_{diffuse} + L_{specular})$, where $L_{diffuse}$ and $L_{specular}$ are calculated in the fragment program using uniform parameters and the gradient vector [S1, unofficial].

**Parameters:**
*   **Uniform Parameters:** Lighting parameters (e.g., light position, view direction, material properties) are passed as uniforms to the fragment program, allowing interactive modification from the C application [S1, unofficial].
*   **Texture Resolution:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Reproducibility:** The original results could not be reproduced due to the complexity of the plane reduction optimization and its approximation towards two-texture interpolation [S1, unofficial].
*   **Performance:** Achieved 4 to 6 frames per second with GPU-based illumination [S1, unofficial].

**Pseudocode:**
```python
# Fragment Program Logic (Cg-like pseudocode)
uniform float4 lightPos;
uniform float4 viewDir;
uniform float4 materialDiffuse;
uniform float4 materialSpecular;

void main(float4 voxelValue : TEXCOORD0,
          float3 gradient : TEXCOORD1,
          out float4 color : COLOR) {
    // 1. Classification: Sample TF texture
    // Assuming TF texture maps input value to color/opacity
    float4 tfResult = tex2D(tfTexture, voxelValue.x);
    float3 primaryColor = tfResult.rgb;
    float opacity = tfResult.a;

    // 2. Illumination: Calculate lighting
    // Normalize gradient for normal vector
    float3 normal = normalize(gradient);
    
    // Calculate diffuse and specular contributions
    // Note: Exact lighting model (e.g., Phong) is not specified in sources
    float3 lightDir = normalize(lightPos.xyz - voxelPosition);
    float3 halfVec = normalize(lightDir + viewDir);
    
    float diff = max(dot(normal, lightDir), 0.0);
    float spec = pow(max(dot(normal, halfVec), 0.0), materialSpecular.w);
    
    float3 diffuseContrib = diff * materialDiffuse.rgb;
    float3 specularContrib = spec * materialSpecular.rgb;
    
    // 3. Combine
    color.rgb = primaryColor * (diffuseContrib + specularContrib);
    color.a = opacity;
}
```

## Subtopics

### [List-based Pre-classification](1930-list-based-pre-classification.md)
An optimization for interactive transfer function changes that avoids rebuilding index buffers by pre-sorting voxel indices into iso-value buckets. It builds on Real-time transfer function evaluation by providing a mechanism to efficiently select which pre-classified voxels are visible based on the current transfer function configuration.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Requires storage for the volume data, gradient texture, and TF texture [S1, unofficial].
*   **Measured Performance:** 4 to 6 frames per second achieved with GPU-based illumination and shading [S1, unofficial].
*   **Strengths:** Enables dynamic lighting and interactive transfer function modification on the GPU, avoiding CPU bottlenecks associated with per-voxel calculations [S1, unofficial].
*   **Limitations:** The original plane reduction optimization was not implemented due to complexity, potentially impacting performance on large volumes [S1, unofficial]. Reproducibility of original results was not achieved [S1, unofficial].
*   **When to use:** When interactive lighting and transfer function adjustment are required, and GPU fragment programs are available.
*   **When not to use:** When high frame rates are critical and the complexity of implementing the lighting model in the fragment program is prohibitive, or when CPU-based pre-computed lighting is sufficient.

## Background
The technique was proposed by Engel, Kraus, and Ertl. It is discussed in the context of texture mapping-based volume rendering [S1, unofficial]. The work highlights the potential of GPU fragment programs (Cg) for dynamic illumination, contrasting with CPU-based approaches like Westermann & Sevenich [S1, unofficial].
