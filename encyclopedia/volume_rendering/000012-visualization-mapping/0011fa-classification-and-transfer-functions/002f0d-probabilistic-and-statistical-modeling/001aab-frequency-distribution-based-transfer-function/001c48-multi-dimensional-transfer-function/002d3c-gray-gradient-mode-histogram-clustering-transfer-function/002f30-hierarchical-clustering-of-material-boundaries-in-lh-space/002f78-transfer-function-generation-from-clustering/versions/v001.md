# Transfer Function Generation from Clustering
Also called: TF from Labels
## Overview
This method generates a transfer function (TF) by mapping cluster labels derived from hierarchical clustering in the Local Intensity-Histogram (LH) space to color and opacity values. It solves the problem of automatic or semi-automatic TF design by converting discrete cluster groupings into a visual mapping. It differs from its parent method by explicitly defining the final rendering mapping via labels, which restricts the output to hard boundaries in the specific implementation described, whereas the parent focuses on the interactive hierarchy exploration.
## How it works
**Inputs and Outputs:**
- Input: A set of clusters resulting from the hierarchical clustering of material boundaries in the LH space. Each cluster contains a set of LH coordinates (bins).
- Output: A 2D transfer function defined by assigning color and opacity to each unique cluster label.

**Data Structures:**
- **Cluster Label Map:** A mapping from each unique cluster identifier (integer) to a color tuple $(R, G, B)$ and an opacity value $\alpha \in [0, 1]$.
- **Volume Label Volume:** A 3D volume of the same dimensions as the input scalar volume, where each voxel is assigned an integer label corresponding to its cluster membership. This is used for hardware renderers that only support 1D TFs.

**Steps:**
1. **Assign Default Properties:** For each unique cluster label generated by the clustering algorithm, assign a random color $(R, G, B)$ and full opacity $\alpha = 1.0$ [S1].
2. **Handle Cluster Merging (Hierarchy Navigation):** When the user navigates the hierarchy and two clusters merge into a single parent cluster:
   - Identify the "dominant" cluster (the one with the larger number of voxels or LH histogram bins) and the "subordinate" cluster (the smaller one) [S1].
   - The subordinate cluster inherits the color and opacity of the dominant cluster [S1].
   - Update the cluster label map so that both the dominant and subordinate labels map to the same color and opacity [S1].
3. **User Modification:** Allow the user to manually override the color and opacity for any specific cluster label [S1].
4. **Rendering Preparation (for 1D TF Hardware):** If the rendering hardware (e.g., VolumePro1000) supports only 1D transfer functions:
   - Perform a one-time labeling of the input volume. Each voxel is assigned the label of the cluster to which its LH coordinate belongs [S1].
   - Generate a 1D transfer function that maps these integer labels to colors and opacities [S1].
   - Note: This labeling step is performed only once for the initial cluster configuration to maintain interaction speed [S1].

**Edge Cases and Pitfalls:**
- **Hard Boundaries:** Using labels restricts the method to hard boundaries between clusters. Fuzzy borders between clusters are not possible with this specific implementation [S1].
- **Hardware Limitations:** The method must account for hardware that only supports 1D TFs by pre-computing a label volume [S1].
- **Merge Ambiguity:** When clusters join, the definition of "dominant" (larger cluster) determines inheritance. The sources specify the smaller cluster inherits from the bigger one [S1].

## Operating characteristics
- **Time Complexity:** The labeling of the volume is performed once for the initial clusters, so the initial setup cost is proportional to the number of voxels $N$ [S1]. Subsequent interactions with the hierarchy (merging clusters) are fast as they only involve updating the TF map, not re-labeling the volume [S1].
- **Memory Complexity:** Requires storing the label volume ($O(N)$) if using 1D TF hardware, plus the TF map ($O(C)$ where $C$ is the number of clusters) [S1].
- **Strengths:** Allows combining TF design with segmentation [S1]. Fast interaction with the hierarchy because labeling is done only once [S1].
- **Limitations:** Cannot represent fuzzy borders between clusters in the specific implementation described [S1].
- **When to use:** When using hardware that only supports 1D TFs (e.g., VolumePro1000) or when hard boundaries are acceptable [S1].
- **When not to use:** When fuzzy borders are required and the renderer does not support them natively [S1].

## Background
This method was introduced in the paper "Automating Transfer Function Design for Volume Rendering Using Hierarchical Clustering of Material Boundaries" by P. K. et al. (EuroVis 2006) [S1]. It builds on the hierarchical clustering of material boundaries in LH space. The method was demonstrated on CT datasets of an engine and a carp [S1]. The specific implementation using labels was driven by the limitations of the VolumePro1000 rendering board, which only allows 1D TFs [S1].
