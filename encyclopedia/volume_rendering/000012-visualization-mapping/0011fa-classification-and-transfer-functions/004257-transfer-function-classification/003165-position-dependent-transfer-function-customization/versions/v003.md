# Position-dependent Transfer Function Customization

Also called: Customization volume method, Interactive Position-dependent Customization via Primitives, Position-dependent customization, Seed Customization Points

## Overview
A method for the interactive, position-dependent customization of arbitrary transfer function classification parameters in volume rendering, allowing local adaptations of visualization parameters based on voxel position without preprocessing [S1]. It solves the problem of spatial inhomogeneities in volume data (e.g., scanner artifacts) or the need to highlight specific regions of interest (ROI) by overriding or blending base transfer function parameters locally [S1]. Unlike [Automated Classification Widget Placement](5645-automated-classification-widget-placement.md) which focuses on widget placement, or [Sketch-based Transfer Function Editing](5943-sketch-based-transfer-function-editing.md) which operates in 2D TF space, this method operates directly in the 3D spatial domain using geometric primitives to define a "customization volume" that modulates the classification step [S1]. It differs from simple clipping by lowering opacity outside an ROI while modifying colors inside, preserving spatial context [S1].

## How it works
The method integrates into the volume rendering pipeline via three main steps: defining seed points, calculating a customization volume, and integrating this volume into the classification step [S1].

### Inputs and Outputs
*   **Input:**
    *   Volume dataset $D$ with resolution $R_D$.
    *   Base transfer function $T$.
    *   User-defined set of seed customization points $S = \{p_1, p_2, ..., p_n\}$.
    *   Each seed point $p_i$ consists of a voxel position $pos_i$ and a parameter vector $v_i$ containing reference values for visualization parameters (e.g., intensity correction factors, color map entries) [S1].
    *   Geometric primitives defining the spatial extent of each seed point (points, lines, rectangles, cuboids) [S1].
*   **Output:**
    *   A rendered volume image where classification parameters are modified based on the spatial position relative to the seed points [S1].

### Data Structures

**1. Seed Customization Point**
*   `position`: 3D vector (voxel coordinates).
*   `parameter_vector`: Array of floats or complex structures (e.g., color maps).
*   `primitive_type`: Enum (Point, Line, Rectangle, Cuboid).
*   `extent`: 3D vector (scalar values defining size along each axis). An extent of 0 in all directions defines a point; non-zero in one direction defines a line; two or three directions define a rectangle or cuboid [S1].
*   `enabled`: Boolean flag. Disabled points are ignored during customization volume computation [S1].

**2. Customization Volume**
*   A 3D texture/volume $C$ with resolution $R_C$ (configurable between $32^3$ and $512^3$ voxels) [S1].
*   Each voxel in $C$ stores a parameter vector $v_{custom}$ corresponding to the interpolated customization values for that spatial location [S1].
*   The resolution $R_C$ is chosen based on available GPU memory and parameter complexity [S1].

### Numbered Steps

1.  **Define Seed Customization Points:**
    The user defines seed points $p_i$ within the volume. Due to the infeasibility of specifying parameters for each voxel in large volumes ($>1000^3$), customization is limited to these user-defined seeds [S1]. The user specifies the position (via 2D view interaction or voxel coordinates) and the parameter vector $v_i$ [S1].

2.  **Calculate Customization Volume:**
    Map the seed customization points into the smaller customization volume $C$. Interpolate parameter customizations for all voxels in $C$ using OpenGL compute shaders on the GPU [S1].
    *   **Interpolation Requirements:**
        1.  The interpolation must not change the value at the user-defined seed points [S1].
        2.  The interpolation between neighboring seed points must be continuous and monotonic [S1].
        3.  Each seed point should only have local influence [S1].
    *   Upon any position update or primitive adjustment, the customization volume is immediately recalculated [S1].

3.  **Integration into Volume Rendering Pipeline:**
    During the classification step of the rendering pipeline:
    *   Gather input parameters (e.g., intensity, gradient) from the volume data $D$ at the current sampling position $x$ [S1].
    *   Fetch the parameter modification vector $v_{mod}$ from the customization volume $C$ at the normalized position corresponding to $x$ [S1].
    *   Apply $v_{mod}$ to the input parameters or the transfer function $T$ itself, depending on the parameter type [S1]. For example, an intensity correction factor might multiply the input intensity, while a color map modification might shift the color lookup [S1].

### Pseudocode

```python
# Data Structures
class SeedPoint:
    position: Vec3  # Voxel coordinates
    parameter_vector: List[float]  # e.g., [gamma_correction, color_shift]
    extent: Vec3  # Size along x, y, z. 0 means no extent in that axis.
    enabled: bool

class CustomizationVolume:
    resolution: int  # e.g., 256
    data: Tensor3D  # Shape (resolution, resolution, resolution, param_count)

# Step 1: User Interaction (Conceptual)
def add_seed_point(position, parameter_vector, extent):
    seed = SeedPoint(position, parameter_vector, extent, enabled=True)
    global_seeds.append(seed)
    update_customization_volume()

# Step 2: Calculate Customization Volume
def update_customization_volume():
    # Filter enabled seeds
    active_seeds = [s for s in global_seeds if s.enabled]
    
    # Initialize customization volume with base values (e.g., identity or 0)
    # The exact interpolation logic is performed on GPU via OpenGL compute shaders [S1]
    # Here we describe the logical requirement
    
    for each voxel v in CustomizationVolume:
        # Interpolate values from active_seeds based on spatial distance
        # and primitive extents.
        # Requirement 1: Value at seed position must equal seed's parameter_vector [S1]
        # Requirement 2: Continuous and monotonic interpolation [S1]
        # Requirement 3: Local influence only [S1]
        v.data = interpolate(active_seeds, v.position)
        
    return CustomizationVolume

# Step 3: Integration into Rendering Pipeline
def classify_voxel(volume_data, sampling_position, customization_volume):
    # 1. Gather input parameters from volume data
    intensity = volume_data[sampling_position]
    gradient = compute_gradient(volume_data, sampling_position)
    input_params = [intensity, gradient]
    
    # 2. Fetch modification from customization volume
    # Normalize sampling_position to [0, 1] range for texture lookup
    normalized_pos = normalize(sampling_position, volume_data.resolution)
    mod_params = customization_volume.lookup(normalized_pos)
    
    # 3. Apply modifications
    # Example: If mod_params[0] is a gamma correction
    modified_intensity = input_params[0] ** mod_params[0]
    
    # 4. Apply base transfer function with modified parameters
    color = apply_transfer_function(modified_intensity, input_params[1])
    
    return color
```

### Parameters
*   **Customization Volume Resolution:** $32^3$ to $512^3$ voxels [S1].
*   **Primitive Extent:** Scalar values per dimension. 0 in all directions = Point. Non-zero in 1 direction = Line. Non-zero in 2 or 3 directions = Rectangle or Cuboid [S1].
*   **Primitive Position:** Geometric center of the primitive [S1].

### Edge Cases and Pitfalls
*   **Large Data Sets:** Individual specification for each voxel in volumes $>1000^3$ is not feasible; seed points are required [S1].
*   **Precision:** Interpolation must preserve seed values exactly (Requirement 1) [S1].
*   **Occlusion:** Seed points can be forced into the foreground to bypass 3D occlusion during visualization [S1].
*   **Axis-Aligned:** Current implementation supports axis-aligned primitives only; non-axis-aligned primitives are future work [S1].

## Subtopics

### [Dual-Domain Interaction](5633-dual-domain-interaction.md)
An interaction paradigm where transfer function specification is driven by direct interaction in the spatial domain with visual feedback in the TF domain, and vice versa. It solves the conceptual gap between 3D spatial geometry and abstract TF space.

## Operating characteristics
*   **Time Complexity:** The interpolation is performed on the GPU using OpenGL compute shaders to achieve interactive frame rates [S1]. Updates are immediate upon position changes [S1].
*   **Memory Complexity:** Memory requirements for the customization volume are configurable and do not depend on the size of the visualized data, making it applicable to large datasets [S1].
*   **Performance Overhead:** The additional classification step has negligible performance overhead compared to the memory transfer bandwidth required for rendering large volume datasets [S1].
*   **Strengths:** No preprocessing required; preserves spatial context unlike clipping; interactive feedback [S1].
*   **Limitations:** Limited to axis-aligned primitives in current implementation; requires GPU compute shader support [S1].
*   **When to Use:** Direct volume rendering of large datasets, particularly in medical/biological research (e.g., CT scans), for interactive ROI highlighting and parameter tuning [S1].
*   **When Not to Use:** When non-axis-aligned customization regions are needed (current limitation) [S1].

## Background
The method was proposed in 2015 by [S1]. It addresses issues like intensity homogeneities in volume data due to scanner technology restrictions [S1]. It extends traditional transfer function concepts by allowing position-dependent customization without preprocessing, unlike distance fields or segmentation-based structures [S1]. It is applicable to multi-dimensional mappings using multiple intensity channels and additional input parameters like local image gradient [S1]. Example applications include maximum intensity projection of large datasets (e.g., 9.5 GB 3-channel mouse embryo data) and CT scans of human hearts [S1].
