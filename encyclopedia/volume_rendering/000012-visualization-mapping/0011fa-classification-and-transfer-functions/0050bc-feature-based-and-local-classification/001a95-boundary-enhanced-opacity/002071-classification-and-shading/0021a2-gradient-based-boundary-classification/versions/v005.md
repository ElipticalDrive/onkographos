# Gradient-Based Boundary Classification

Also called: Cell-Diagonal Data Shift, Reflecting Material Classification, Gradient-based surface classification, Reflecting Surface Classification, Surface Classification

## Overview
Gradient-Based Boundary Classification is a method to classify voxels as either 'reflecting' (surface) or 'ambient' (volume) based on the voxel's data value, the gradient magnitude, and the range of field values for the material [S1, S2, S3, unofficial]. It solves the problem of accurately identifying surface boundaries for shading by interpreting the gradient magnitude in the context of the data value and classification parameters, rather than using gradient magnitude in isolation [S1, S3, unofficial]. This departs from earlier work [Lev90a, LL94] which relied on gradient magnitude alone, preventing misclassification of voxels with high gradients that are far from the actual material boundary [S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Voxel data value $d$, gradient vector $\vec{\gamma} = (\gamma_x, \gamma_y, \gamma_z)$, inter-voxel spacing $\bar{\Delta}$ (assumed uniform $\bar{\Delta}_x = \bar{\Delta}_y = \bar{\Delta}_z = \bar{\Delta}$ unless specified), material lower limit $b$, material upper limit $a$, and a client-tunable scaling factor $k$ [S1, S2, S3, unofficial].
*   **Output:** A boundary probability $P \in [0, 1]$ indicating the likelihood that the voxel lies on a material boundary, which blends ambient and reflecting shading components [S1, S2, S3, unofficial].

**Formulas:**
1.  **Linear Field Approximation:** The field function $\tilde{f}(\bar{q})$ in the neighborhood of a voxel at location $\bar{q}_0$ with data value $d$ and gradient vector $\vec{\gamma}$ is approximated as [S1, S2, S3, unofficial]:
    $$ \tilde{f}(\bar{q}) = d + \vec{\gamma} \cdot (\bar{q} - \bar{q}_0) $$
2.  **Cell-Diagonal Data Shift ($s$):** This quantity estimates the maximum change in data value across the diagonal of a voxel cell [S1, S2, S3, unofficial]:
    $$ s = \bar{\Delta}_x |\gamma_x| + \bar{\Delta}_y |\gamma_y| + \bar{\Delta}_z |\gamma_z| $$
    If inter-voxel spacing is uniform ($\bar{\Delta}$), this simplifies to $s = \bar{\Delta} (|\gamma_x| + |\gamma_y| + |\gamma_z|)$ [S3, unofficial].
3.  **Boundary Proximity Tests:**
    *   **Lower Boundary ($b$):** A voxel is considered near the lower boundary if one of the 26 neighboring voxels has data below $b$ [S1, S2, S3, unofficial]. Based on the linear approximation, this occurs if and only if [S1, S2, S3, unofficial]:
        $$ (d - b) < s $$
    *   **Upper Boundary ($a$):** A similar test applies for the upper boundary [S1, S2, S3, unofficial]:
        $$ (a - d) < s $$
4.  **Probability Calculation:** To handle noise and nonlinearity, a binary decision is replaced by a probability $P$ when $s$ is near the threshold values $(d-b)$ or $(a-d)$ [S1, S2, S3, unofficial]. The implementation uses a linear ramp [S1, S2, S3, unofficial]:
    *   For the lower boundary, let $D_{lower} = d - b$ [S1, S2, S3, unofficial]. If $D_{lower} \le 0$, $P_{lower} = 0$ [S1, S2, S3, unofficial]. Otherwise:
        $$ P_{lower} = \begin{cases} 0 & \text{if } s < 0.5 D_{lower} \\ \frac{s - 0.5 D_{lower}}{D_{lower}} & \text{if } 0.5 D_{lower} \le s \le 1.5 D_{lower} \\ 1 & \text{if } s > 1.5 D_{lower} \end{cases} $$
    *   For the upper boundary, let $D_{upper} = a - d$ [S1, S2, S3, unofficial]. The logic is symmetric [S1, S2, S3, unofficial].
    *   The source does not specify how to combine $P_{lower}$ and $P_{upper}$ into a final probability [G]. Implementers typically use the maximum or compute $P$ for the closer boundary [G].
    *   A scaling factor $k$ can be applied to the probability function to fine-tune classification [S1, S2, S3, unofficial]. The exact mathematical application of $k$ is not specified in the sources [G]. A common implementation scales the probability directly: $P_{final} = \min(1.0, P \cdot k)$ [G].

**Pseudocode:**
```python
def gradient_based_boundary_classification(d, gamma_x, gamma_y, gamma_z, delta_x, delta_y, delta_z, b, a, k=1.0):
    """
    Computes the boundary probability for a voxel.
    
    Args:
        d: Voxel data value.
        gamma_x, gamma_y, gamma_z: Gradient components.
        delta_x, delta_y, delta_z: Inter-voxel spacing.
        b: Lower limit of the material range.
        a: Upper limit of the material range.
        k: Scaling factor for fine-tuning (default 1.0).
        
    Returns:
        P: Boundary probability in [0, 1].
    """
    # Calculate cell-diagonal data shift
    s = delta_x * abs(gamma_x) + delta_y * abs(gamma_y) + delta_z * abs(gamma_z)
    
    # Calculate probability for lower boundary
    diff_lower = d - b
    if diff_lower <= 0:
        P_lower = 0.0
    else:
        t_start = 0.5 * diff_lower
        t_end = 1.5 * diff_lower
        if s < t_start:
            P_lower = 0.0
        elif s > t_end:
            P_lower = 1.0
        else:
            P_lower = (s - t_start) / (t_end - t_start)
            
    # Calculate probability for upper boundary
    diff_upper = a - d
    if diff_upper <= 0:
        P_upper = 0.0
    else:
        t_start = 0.5 * diff_upper
        t_end = 1.5 * diff_upper
        if s < t_start:
            P_upper = 0.0
        elif s > t_end:
            P_upper = 1.0
        else:
            P_upper = (s - t_start) / (t_end - t_start)
            
    # Combine probabilities: source does not specify combination rule [G]
    P = max(P_lower, P_upper)
    
    # Apply scaling factor: exact application of k is not specified in sources [G]
    P = min(1.0, P * k)
    
    return P
```

**Edge Cases and Pitfalls:**
*   **High Gradient, Far from Boundary:** A voxel with a high data value (e.g., 130 in a bone example where $b=110$) may have a high gradient magnitude but be far from the boundary [S2, S3, unofficial]. The method correctly classifies this as ambient because $(d-b)$ is large, making $s < (d-b)$ likely false for the boundary test, or the probability ramp requires a much larger $s$ to reach 1 [S2, S3, unofficial].
*   **Noise and Nonlinearity:** The linear probability ramp handles gradient noise and field nonlinearity better than a binary threshold [S1, S2, S3, unofficial].
*   **Scaling Factor:** The exact mathematical application of the scaling factor $k$ is not explicitly defined in the sources beyond "applied to this probability function" [S1, S2, S3, unofficial]. Implementers must determine if $k$ scales the probability value or the transition thresholds [G].
