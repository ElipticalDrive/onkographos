# Reflected Light Component Lookup

Also called: Gradient-based shading lookup, Lookup Table Shading, Lookup Table for Shading, Material-Gradient Lookup Table, Shading via lookup tables

## Overview
Reflected Light Component Lookup is a shading method that pre-calculates surface responses to directional lighting for combinations of material types and quantized gradient directions, storing the results in a lookup table [S1, S2, unofficial]. It solves the problem of efficiently rendering multiple-material volumes with specular highlights and directional lighting by decoupling the expensive lighting calculations from the per-voxel rendering loop [S2, unofficial]. Unlike sibling methods that rely solely on ambient lighting or simple gradient magnitude, this approach encodes the full reflected light component (diffuse and specular) based on the voxel's orientation relative to light sources, allowing for realistic surface appearance in volume rendering [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   $m$: Number of material types specified by the client [S1, S2, unofficial].
    *   $k$ (or $A$): Number of refinement levels for gradient quantization [S1, S2, unofficial].
    *   Lighting parameters: Light colors, directions, and enabled states [S3].
    *   Material parameters: Shading properties (e.g., shininess) for each material [S3].
    *   Voxel data: Scalar field values and gradients [S1, S2, unofficial].
*   **Outputs:**
    *   A pre-computed color lookup table (LUT) mapping indices to RGB(A) intensities [S1, S2, unofficial].
    *   Two auxiliary fields stored per voxel: an encoded surface normal index and a weight index [S3].
    *   Rendered image with directional lighting effects [S2, unofficial].

**Data Structures:**
1.  **Color Table:** A 3D array `float color_table[n][num_materials][color_channels]` [S3].
    *   $n$: Number of possible values for the color field (lookup index size) [S3].
    *   `num_materials`: $m$ [S3].
    *   `color_channels`: 1 for grayscale, 3 for RGB [S3].
    *   Values are floating-point intensities in $[0.0, 1.0]$ [S1, unofficial][S3].
2.  **Weight Table:** A 2D array `float weight_table[m_w][num_materials]` [S3].
    *   $m_w$: Number of possible values for the weight field [S3].
    *   Values are fractional occupancies in $[0.0, 1.0]$ [S3].
    *   If `num_materials` is 1, this table is unused [S3].
3.  **Voxel Fields:**
    *   **Color Field:** Stores an index into the Color Table. This index encodes both the material type and the quantized gradient direction [S1, S2, unofficial][S3].
    *   **Weight Field:** Stores an index into the Weight Table, representing the mixture of materials in the voxel [S3].

**Gradient Quantization:**
The gradient direction space is quantized into a finite set of unit vectors distributed evenly on a unit sphere [S1, S2, unofficial]. The number of quantized gradients $g$ is determined by the refinement level $k$ (or $A$) [S1, S2, unofficial]:
$$ g = 30 \cdot 4^k + 2 $$
[S1, S2, unofficial]

**Lookup Index Calculation:**
For each voxel, a final lookup index $I$ is computed for the Color Table [S1, S2, unofficial]:
*   If the voxel has reflection properties (classified as a surface):
    $$ I = M \cdot g + G $$
    Where:
    *   $M$: The material index of the voxel [S1, S2, unofficial].
    *   $g$: The total number of quantized gradients [S1, S2, unofficial].
    *   $G$: The quantized gradient index, found by mapping the voxel's actual gradient direction to the closest pre-computed quantized gradient vector [S1, S2, unofficial].
*   If the voxel has no reflection properties (ambient/volume):
    $$ I = M $$
    [S1, S2, unofficial]
    *   Note: Material 0 is the "null" material. Its entries in the lookup table store colors for ambient materials, which do not require a gradient index [S1, S2, unofficial].

**Shading Model:**
The color values in the lookup table are calculated using a "half-way vector" specularity model [TM67, CT82] combined with Lambertian diffuse shading [S1, S2, unofficial]. The surface response to directional lights is computed for each combination of material and quantized gradient, added to the ambient component, and stored [S1, S2, unofficial].

**Pseudocode:**

```python
# 1. Setup Lighting and Material Parameters
# Define light properties (color and direction)
# Direction vectors are transformed by the current modeling matrix
def setup_lighting(context, light_num, color_rgb, direction_xyz):
    set_light_property(context, light_num, VP_COLOR, color_rgb)
    set_light_property(context, light_num, VP_DIRECTION, direction_xyz)
    enable_light(context, light_num, enabled=True)

# 2. Initialize Lookup Tables
# Color Table Dimensions: [n][num_materials][color_channels]
# Weight Table Dimensions: [m_w][num_materials]
def initialize_tables(context, num_materials, color_channels, n, m_w):
    color_table = zeros((n, num_materials, color_channels))
    weight_table = zeros((m_w, num_materials))
    
    # Set lighting parameters before shading table generation
    # vpSetLight and vpEnable calls would occur here
    
    # Generate the color table based on current lighting and material properties
    # This calculates the reflected light component for all gradient/material combos
    generate_shading_table(context, color_table, num_materials, color_channels)
    
    return color_table, weight_table

# 3. Process Voxels (Setup Procedure)
def process_voxel(voxel_gradient, voxel_material_index, has_reflection):
    # Calculate quantized gradient index G
    # Find the closest vector in the pre-defined set of g quantized gradients
    G = find_closest_quantized_gradient(voxel_gradient)
    
    M = voxel_material_index
    
    if has_reflection:
        # Index = M * g + G
        lookup_index = M * g + G
    else:
        # Index = M
        lookup_index = M
        
    return lookup_index, G

# 4. Rendering
def render_voxel(voxel_color_index, voxel_weight_index, color_table, weight_table):
    # Retrieve base colors for all materials based on the encoded normal/material index
    base_colors = color_table[voxel_color_index] # Shape: [num_materials][color_channels]
    
    # Retrieve material weights (fractional occupancy)
    weights = weight_table[voxel_weight_index] # Shape: [num_materials]
    
    # Combine colors weighted by material occupancy
    final_color = zeros(3) # Assuming RGB
    for i in range(num_materials):
        final_color += base_colors[i] * weights[i]
        
    return final_color
```

**Edge Cases and Pitfalls:**
*   **Recalculation Requirement:** The lookup table must be recalculated whenever any lighting factor changes, including volume rotation or light source movement [S1, S2, unofficial]. This is a significant computational overhead compared to ambient-only methods [S2, unofficial].
*   **Gradient Quantization Error:** The accuracy of the shading depends on the density of the quantized gradient set. Low $k$ values result in visible quantization artifacts in specular highlights [S1, S2, unofficial].
*   **Material 0 Handling:** Material 0 (null material) uses a simplified index $M$ without gradient combination, as it represents ambient materials that do not reflect light directionally [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:**
    *   **Setup:** $O(g \cdot m \cdot L)$, where $g$ is the number of quantized gradients, $m$ is the number of materials, and $L$ is the number of lights. This involves computing the shading model for every entry in the color table [S1, S2, unofficial].
    *   **Rendering:** $O(1)$ per voxel for lookup and weighted combination, assuming the tables fit in cache [S3].
*   **Memory Complexity:**
    *   **Lookup Table:** $O(n \cdot m \cdot c)$, where $n$ is the number of color field values (indices), $m$ is materials, and $c$ is color channels [S3].
    *   **Weight Table:** $O(m_w \cdot m)$ [S3].
    *   **Voxel Storage:** Requires storing two additional fields per voxel (color index and weight index) [S3].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Performance degrades linearly with the number of materials and refinement levels $k$. The need to recalculate the table on rotation prevents efficient caching of the LUT during interactive rotation [S2, unofficial].
*   **Strengths:** Supports multiple materials with distinct shading properties; enables realistic specular highlights and directional lighting in volume rendering; efficient per-voxel rendering cost [S1, S2, unofficial][S3].
*   **Limitations:** Requires significant memory for the lookup tables; computationally expensive setup phase; requires table recalculation for any change in lighting or view orientation, unlike ambient-only methods [S1, S2, unofficial].
*   **When to use:** When realistic surface shading with specular highlights is required for multi-material volumes and interactive rotation is not the primary concern, or when pre-computed frames are acceptable [S2, unofficial][S3].
*   **When not to use:** When real-time interactive rotation with dynamic lighting is critical and the cost of table recalculation is prohibitive [S2, unofficial].

## Background
*   **Origin:** The method is described in the context of "Direct Volume Rendering with Shading via Three-Dimensional Textures" [S1, S2, unofficial] and implemented in the VolPack library [S3].
*   **History:** It departs from earlier work that used gradient magnitude in isolation for classification [S1, S2, unofficial]. It builds on the multiple-material voxel model introduced by Drebin, Carpenter, and Hanrahan (SIGGRAPH 88) [S3].
*   **Usage:** Implemented in the VolPack software library for volume rendering [S3].
