# Gradient-Based Boundary Classification

Also called: Cell-Diagonal Data Shift, Reflecting Material Classification, Gradient-based surface classification, Reflecting Surface Classification, Surface Classification

## Overview
Gradient-Based Boundary Classification is a method to classify voxels as either 'reflecting' (surface) or 'ambient' (volume) based on the voxel's data value, the gradient magnitude, and the range of field values for the material [S1, S2, S3, unofficial]. It solves the problem of accurately identifying surface boundaries for shading by interpreting the gradient magnitude in the context of the data value and classification parameters, rather than using gradient magnitude in isolation [S1, S3, unofficial]. This departs from earlier work [Lev90a, LL94] which relied on gradient magnitude alone, preventing misclassification of voxels with high gradients that are far from the actual material boundary [S2, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Voxel data value $d$, gradient vector $\vec{\gamma} = (\gamma_x, \gamma_y, \gamma_z)$, inter-voxel spacing $\bar{\Delta}$ (assumed uniform $\bar{\Delta}_x = \bar{\Delta}_y = \bar{\Delta}_z = \bar{\Delta}$ unless specified), material lower limit $b$, material upper limit $a$, and a client-tunable scaling factor $k$ [S1, S2, S3, unofficial].
*   **Output:** A boundary probability $P \in [0, 1]$ indicating the likelihood that the voxel lies on a material boundary. This probability is used to blend ambient and reflecting shading components [S1, S2, S3, unofficial].

**Data Structures:**
No specific complex data structures are required beyond standard voxel access. The method computes scalar values per voxel.

**Formulas:**
1.  **Linear Field Approximation:** The field function $\tilde{f}(\bar{q})$ in the neighborhood of a voxel at location $\bar{q}_0$ with data value $d$ and gradient vector $\vec{\gamma}$ is approximated as [S1, S2, S3, unofficial]:
    $$ \tilde{f}(\bar{q}) = d + \vec{\gamma} \cdot (\bar{q} - \bar{q}_0) $$
2.  **Cell-Diagonal Data Shift ($s$):** This quantity estimates the maximum change in data value across the diagonal of a voxel cell [S1, S2, S3, unofficial]:
    $$ s = \bar{\Delta}_x |\gamma_x| + \bar{\Delta}_y |\gamma_y| + \bar{\Delta}_z |\gamma_z| $$
    If inter-voxel spacing is uniform ($\bar{\Delta}$), this simplifies to $s = \bar{\Delta} (|\gamma_x| + |\gamma_y| + |\gamma_z|)$ [S3, unofficial].
3.  **Boundary Proximity Tests:**
    *   **Lower Boundary ($b$):** A voxel is considered near the lower boundary if one of the 26 neighboring voxels has data below $b$. Based on the linear approximation, this occurs if and only if [S1, S2, S3, unofficial]:
        $$ (d - b) < s $$
    *   **Upper Boundary ($a$):** A similar test applies for the upper boundary [S1, S2, S3, unofficial]:
        $$ (a - d) < s $$
4.  **Probability Calculation:** To handle noise and nonlinearity, a binary decision is replaced by a probability $P$ when $s$ is near the threshold values $(d-b)$ or $(a-d)$ [S1, S2, S3, unofficial]. The implementation uses a linear ramp [S1, S2, S3, unofficial]:
    *   For the lower boundary:
        $$ P_{lower} = \begin{cases} 0 & \text{if } s < 0.5(d - b) \\ \frac{s - 0.5(d - b)}{(d - b)} & \text{if } 0.5(d - b) \le s \le 1.5(d - b) \\ 1 & \text{if } s > 1.5(d - b) \end{cases} $$
        *Note: The source states "increases linearly to become 1 when $s = 1.5(d - b)$". The slope is calculated as $\frac{1 - 0}{1.5(d-b) - 0.5(d-b)} = \frac{1}{d-b}$ [S1, S2, S3, unofficial].*
    *   For the upper boundary, the logic is symmetric using $(a-d)$ [S1, S2, S3, unofficial].
    *   The final probability $P$ is the maximum of the lower and upper boundary probabilities (or combined as per specific implementation, but typically max for "near either boundary") [S1, S2, S3, unofficial].
    *   A scaling factor $k$ can be applied to the probability function to fine-tune classification [S1, S2, S3, unofficial]. The exact application of $k$ is described as being "applied to this probability function," causing more or fewer voxels to have nonzero probability [S1, S2, S3, unofficial]. A common interpretation is scaling the threshold range or the probability value itself. The source does not specify the exact mathematical placement of $k$ (e.g., $P \cdot k$ or scaling the thresholds). [G: Assuming $k$ scales the probability value directly, i.e., $P_{final} = \min(1, P \cdot k)$, or scales the transition width. Given the ambiguity, the base probability $P$ is computed as above, and $k$ is a post-processing multiplier or threshold scaler applied by the client.]

**Pseudocode:**
```python
def gradient_based_boundary_classification(d, gamma_x, gamma_y, gamma_z, delta_x, delta_y, delta_z, b, a, k=1.0):
    """
    Computes the boundary probability for a voxel.
    
    Args:
        d: Voxel data value.
        gamma_x, gamma_y, gamma_z: Gradient components.
        delta_x, delta_y, delta_z: Inter-voxel spacing.
        b: Lower limit of the material range.
        a: Upper limit of the material range.
        k: Scaling factor for fine-tuning (default 1.0).
        
    Returns:
        P: Boundary probability in [0, 1].
    """
    # Calculate cell-diagonal data shift
    s = delta_x * abs(gamma_x) + delta_y * abs(gamma_y) + delta_z * abs(gamma_z)
    
    # Calculate probability for lower boundary
    diff_lower = d - b
    if diff_lower <= 0:
        # Voxel is already below or at the lower limit, so it's deep inside or below the material
        # The condition (d-b) < s is trivially true if d < b, but physically 
        # if d < b, it's not "near" the boundary from the inside in the same way.
        # However, the source implies the test is for neighbors having data < b.
        # If d < b, the voxel itself is below the range. 
        # The source example focuses on d >= b.
        # If d < b, the voxel is likely ambient or below the material.
        # We assume the method applies when d is within or near [b, a].
        P_lower = 0.0
    else:
        # Thresholds for the linear ramp
        t_start = 0.5 * diff_lower
        t_end = 1.5 * diff_lower
        
        if s < t_start:
            P_lower = 0.0
        elif s > t_end:
            P_lower = 1.0
        else:
            # Linear interpolation
            P_lower = (s - t_start) / (t_end - t_start)
            
    # Calculate probability for upper boundary
    diff_upper = a - d
    if diff_upper <= 0:
        P_upper = 0.0
    else:
        t_start = 0.5 * diff_upper
        t_end = 1.5 * diff_upper
        
        if s < t_start:
            P_upper = 0.0
        elif s > t_end:
            P_upper = 1.0
        else:
            P_upper = (s - t_start) / (t_end - t_start)
            
    # Combine probabilities (voxel is near boundary if near either)
    P = max(P_lower, P_upper)
    
    # Apply scaling factor
    # Source says "scaling factor ... applied to this probability function"
    # Assuming multiplicative scaling on the result, clamped to 1
    P = min(1.0, P * k)
    
    return P
```

**Edge Cases and Pitfalls:**
*   **High Gradient, Far from Boundary:** A voxel with a high data value (e.g., 130 in a bone example where $b=110$) may have a high gradient magnitude but be far from the boundary. The method correctly classifies this as ambient because $(d-b)$ is large, making $s < (d-b)$ likely false for the boundary test, or the probability ramp requires a much larger $s$ to reach 1 [S2, S3, unofficial].
*   **Noise and Nonlinearity:** The linear probability ramp handles gradient noise and field nonlinearity better than a binary threshold [S1, S2, S3, unofficial].
*   **Scaling Factor:** The exact mathematical application of the scaling factor $k$ is not explicitly defined in the sources beyond "applied to this probability function" [S1, S2, S3, unofficial]. Implementers must determine if $k$ scales the probability value or the transition thresholds.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel for the classification step. The calculation involves basic arithmetic operations (absolute values, multiplications, additions, comparisons).
*   **Memory Complexity:** $O(1)$ per voxel for the classification step. No additional storage is required beyond the input data and gradient.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Accurately identifies surface boundaries by considering the data value range, avoiding false positives from high gradients in the volume interior. Handles noise and nonlinearity via probability ramps.
*   **Limitations:** Requires accurate gradient computation. Relies on linear approximation of the field function, which may be inaccurate for highly nonlinear fields. The scaling factor $k$ requires tuning.
*   **When to Use:** When accurate surface shading is required for specific materials in volume rendering, especially when gradient magnitude alone leads to noisy or incorrect surface detection.
*   **When Not to Use:** When computational resources are extremely limited and simple thresholding is sufficient, or when the field function is highly nonlinear and the linear approximation is invalid.

## Background
The method was introduced in the context of Direct Volume Rendering with Shading via Three-Dimensional Textures [S1, S2, S3, unofficial]. It departs from earlier work [Lev90a, LL94] that used gradient magnitude in isolation for surface detection [S1, S3, unofficial]. The method is part of a pipeline that includes Reflected Light Component Lookup and Gradient Quantization to achieve interactive rendering with directional lighting [S1, S2, S3, unofficial].
