# Feature Graph

Also called: Feature Graph Construction, Feature Graph building

## Overview
The Feature Graph is a hierarchical data structure for volume rendering that represents classified voxel models as a directed acyclic graph (DAG) [S1, unofficial]. It solves the problem of visualizing complex semantic hierarchies where a single voxel belongs to multiple non-exclusive classes simultaneously, enabling focus+context rendering through multiresolution support [S1, unofficial]. It differs from standard single-criterion classification by explicitly modeling the subset relationships between disjoint classes of different criteria, creating a graph where nodes are features (clusters of voxels with identical labels) and edges represent inclusion [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A labeled voxel model where each voxel $v$ has a set of $n_c$ boolean labels $r_i(v)$ for $i \in [1, n_c]$, indicating fulfillment of $n_c$ non-exclusive classification criteria [S1, unofficial].
*   **Output:** A Feature Graph DAG where nodes represent features and arcs represent inclusion of voxel sets, along with a Feature Hash Table for direct node access [S1, unofficial].

**Data Structures:**
1.  **Feature Hash Table:** A hash table providing direct index access to feature nodes. The hash code for a voxel is derived from its set of labels [S1, unofficial].
2.  **Feature Node:** Represents a feature $f$. Contains:
    *   Label signature (subset of boolean expressions).
    *   Reference to a Set of Voxels (SOV).
    *   Parent pointers (for traversal to ancestors).
    *   Child pointers (for traversal to descendants).
3.  **Set of Voxels (SOV):** The spatial representation of a feature. Stored only in leaf nodes to avoid redundancy [S1, unofficial].
    *   **Representation:** Can be a list of voxels or a voxel submodel (octree) [S1, unofficial].
    *   **List-based:** Stores voxel coordinates. No spatial ordering. Convenient for non-compact distributions [S1, unofficial].
    *   **Submodel-based:** Octree representation. Voxels not belonging to the feature are assigned zero value, ensuring a voxel has a non-zero value in only one unique leaf SOV. Preserves spatial ordering [S1, unofficial].
    *   **Compaction:** Homogeneous regions within an SOV are compacted using different voxel sizes. For submodels, an octree is used. For lists, only black nodes of the octree with their associated size are stored [S1, unofficial].

**Algorithm Steps:**

1.  **Clustering (High Resolution):**
    *   Traverse the labeled voxel model.
    *   For each voxel $v$, compute its label set $\{r_1(v), ..., r_{n_c}(v)\}$.
    *   Use this label set as a hash code to index into the Feature Hash Table.
    *   Add $v$ to the SOV list indexed by this hash code.
    *   After traversal, for each non-empty SOV:
        *   Compute the bounding box.
        *   Create a voxel submodel (octree) for the SOV.
        *   Compress the submodel. Optionally, traverse the octree to create a list-based representation with variable-sized voxels [S1, unofficial].
    *   Create leaf nodes in the graph for each non-empty SOV and associate them with the computed SOVs [S1, unofficial].

2.  **Hierarchy Creation:**
    *   Derive the graph hierarchy iteratively using boolean operations on feature labels.
    *   Recursively create common ancestor nodes for all nodes sharing a bit in their hash code (i.e., features that are supersets of other features) [S1, unofficial].
    *   Update the Feature Hash Table to reference the newly created ancestor nodes [S1, unofficial].
    *   If the graph consists of multiple disconnected hierarchies, create a common root node called `fall` (feature all) that includes all features without an ancestor [S1, unofficial].
    *   **Storage Policy:** Store SOVs only in leaf nodes. Ancestor SOVs are obtained by recursively traversing descendant nodes down to the leaves [S1, unofficial].

3.  **Multiresolution Handling:**
    *   Compute label sets at coarser resolution levels of the voxel model [S1, unofficial].
    *   Repeat the clustering process for larger voxels at each coarser level.
    *   Distribute the SOVs computed from these coarser clusters through the graph hierarchy, attaching them to corresponding nodes.
    *   Each node can contain SOVs from different resolution levels. Note that some clusters non-empty at high resolution may become empty at lower resolution, so not all features exist at all levels. A feature can be a leaf at one resolution and an intermediate node at another [S1, unofficial].

    def _create_fall_node(self):

        # If so, create a root node that points to all roots of components

                    self.hash_table[sig] = new_node
                    self.nodes.append(new_node)
        
        # Link nodes
        for sig in all_signatures:
            if sig in self.hash_table:
                node = self.hash_table[sig]
                # Find parents: supersets of sig that are in all_signatures
                # Find children: subsets of sig that are in all_signatures
                for other_sig in all_signatures:
                    if other_sig == sig:
                        continue
                    if is_subset(sig, other_sig):
                        # sig is a subset of other_sig, so other_sig is an ancestor
                        if other_sig in self.hash_table:
                            parent = self.hash_table[other_sig]
                            if node not in parent.children:
                                parent.children.append(node)
                                node.parent = parent
                    elif is_subset(other_sig, sig):
                        # other_sig is a subset of sig, so other_sig is a descendant
                        if other_sig in self.hash_table:
                            child = self.hash_table[other_sig]
                            if child not in node.children:
                                node.children.append(child)
                                child.parent = node

def is_subset(sub, super_set):
    # sub is a subset of super_set if every True in sub is True in super_set
    for s, sup in zip(sub, super_set):
        if s and not sup:
            return False
    return True

**Parameters:**
*   $n_c$: The number of non-exclusive classification criteria (boolean conditions) [S1, unofficial].
*   `fall`: The entry point node of the graph, representing a feature that includes all features that do not have an ancestor [S1, unofficial].
*   Leaf nodes: Nodes in the graph that do not include any other feature [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Clusters:** Many theoretical clusters ($2^{n_c}$) may be empty. The algorithm only creates nodes for non-empty clusters [S1, unofficial].
*   **Multiresolution Disappearance:** Clusters non-empty at high resolution may become empty at lower resolution. Not all features exist at all levels [S1, unofficial].
*   **Redundancy:** SOVs are stored only in leaf nodes to avoid redundancy. Ancestor SOVs are derived by traversal [S1, unofficial].
*   **Spatial Ordering:** List-based SOVs do not preserve spatial ordering, requiring view-aligned splatting for rendering [S1, unofficial]. Submodel-based SOVs preserve ordering but may have overlapping bounding boxes [S1, unofficial].

## Subtopics

### [Multiclassified Structure Graph Construction](14781-multiclassified-structure-graph-construction.md)
Builds a directed acyclic graph representing inclusion relationships between isoclasses in a voxel model classified by multiple independent criteria. It differs from standard single-criterion classification by explicitly modeling subset relationships between disjoint classes of different criteria, creating a graph where nodes are class identifiers and edges represent inclusion.

## Operating characteristics
*   **Time Complexity:** Construction involves clustering ($O(V)$ where $V$ is number of voxels) and hierarchy creation. Hierarchy creation depends on $n_c$. The number of possible features is $2^{n_c}$, but only non-empty ones are created.
*   **Memory Complexity:** Depends on the SOV representation. List-based SOVs store only voxel coordinates. Submodel-based SOVs store octrees. SOVs are stored only in leaves, reducing redundancy [S1, unofficial].
*   **Performance:** View-aligned splatting is used for list-based SOVs to handle lack of spatial ordering [S1, unofficial]. Multiresolution support reduces aliasing and provides focus+context visualizations [S1, unofficial].
*   **Strengths:** Handles non-exclusive classification, supports multiresolution, allows focus+context rendering.
*   **Limitations:** List-based SOVs require view-aligned splatting. Submodel-based SOVs may have overlapping bounding boxes.
