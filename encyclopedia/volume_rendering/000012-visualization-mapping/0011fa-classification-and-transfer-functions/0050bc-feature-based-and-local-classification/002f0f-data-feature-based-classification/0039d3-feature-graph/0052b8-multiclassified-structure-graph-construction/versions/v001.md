# Multiclassified Structure Graph Construction

Also called: Isoclass Graph, Structure Graph

## Overview
Multiclassified Structure Graph Construction builds a directed acyclic graph representing the inclusion relationships between isoclasses in a voxel model classified by multiple independent criteria. It solves the problem of visualizing complex semantic hierarchies where a single voxel can belong to multiple classes simultaneously, enabling users to explore structural semantics through focus+context rendering. It differs from standard single-criterion classification by explicitly modeling the subset relationships between disjoint classes of different criteria, creating a graph where nodes are class identifiers and edges represent inclusion.

## How it works
The method constructs the graph in two main phases: building the isoclass hierarchy and constructing the labelled voxel model with cluster relationships.

**Inputs and Outputs**
*   **Input:** A voxel model $V$ and $n_c$ independent classification criteria. Each criterion $i$ defines a set of disjoint class identifiers $\tilde{c}_i = \{c_{i1}, \dots, c_{i n_{ci}}\}$ and a classification function $C_i: V \to \tilde{c}_i$ [S1, unofficial].
*   **Output:** A directed graph $G = (I, E)$ where $I$ is the set of all isoclass identifiers and $E$ represents inclusion relationships; a labelled voxel model $LV$; and a cluster list $R$ with a binary relation $F$ [S1, unofficial].

**Data Structures**
1.  **Graph Nodes ($I$):** Each node represents an isoclass identifier $c_{ij}$.
2.  **Adjacency Table:** A matrix storing the number of voxels for each pair of isoclasses. Rows correspond to potential included isoclasses; columns to potential includers. Non-zero entries indicate voxel overlap [S1, unofficial].
3.  **Labelled Voxel Model ($LV$):** A voxel model aligned with $V$, where each voxel value is a cluster identifier $r \in R$ [S1, unofficial].
4.  **Cluster List ($R$):** A list of unique cluster identifiers, each associated with a tuple of isoclass identifiers $CR$ [S1, unofficial].

**Parameters**
*   $n_c$: Number of independent classification criteria [S1, unofficial].
*   $MAX$: Maximum intensity value used in color arithmetic operations (e.g., for Stone’s coloring model) [S1, unofficial].
*   $\beta$: User-specified blending factor, $0 \le \beta \le 1$ [S1, unofficial].

**Steps**

1.  **Construct Isoclasses:**
    Separate the classified voxels into sets based on each criterion. For each isoclass, compute:
    *   The number of voxels.
    *   The bounding box.
    *   Opacity: Set as a factor of the bounding sphere radius and voxel count [S1, unofficial].
    *   Color: Compute using Stone’s coloring model [25] (see formula below) [S1, unofficial].
    *   Create one graph node per isoclass [S1, unofficial].

2.  **Compute Inclusion Hierarchy:**
    *   Process input voxels slice by slice to manage memory for large models [S1, unofficial].
    *   Construct an adjacency table storing the count of voxels belonging to both an included isoclass and an includer isoclass. If no voxels are shared, store zero [S1, unofficial].
    *   Sort the rows of the adjacency table by increasing number of voxels [S1, unofficial].
    *   Derive the inclusion hierarchy through a simple matrix traversal of the sorted table. An edge exists from $c_{li}$ to $c_{kj}$ if $c_{kj}$ is included in $c_{li}$ [S1, unofficial].

3.  **Construct Labelled Voxel Model and Clusters:**
    *   For each voxel $v$, identify the set of isoclasses it belongs to (an $n_c$-tuple) [S1, unofficial].
    *   Compute a cluster identifier $r$ as a hash code of the isoclass identifiers in the tuple [S1, unofficial].
    *   Label voxel $v$ in $LV$ with $r$. If $r$ is new, insert it into the cluster list $R$ [S1, unofficial].
    *   Codify the relationship $F$ between graph nodes and clusters in the hash code [S1, unofficial].

**Formulas**

*   **Implication/Inclusion:**
    $$c_{kj} \Rightarrow c_{li} \iff \text{isoclas}(c_{kj}) \subset \text{isoclas}(c_{li})$$
    Where $c_{kj}$ implies $c_{li}$ if the isoclass of $c_{li}$ includes all voxels of $c_{kj}$. Edges in $G$ go from includer to included [S1, unofficial].

*   **Cluster-Node Relationship ($F$):**
    $$\forall i \in I \land \forall r \in R, i F r \iff \exists c_i \in CR \mid i = c_i \land \neg(\exists c_j \in CR, c_j \neq c_i \mid c_j \Rightarrow c_i)$$
    Node $i$ is related to cluster $r$ if $i$ is in the cluster's isoclass tuple $CR$ and no descendant of $i$ in $G$ has an identifier in $CR$ [S1, unofficial].

*   **Stone’s Coloring Model Arithmetic:**
    Let $c_1 = (r_1, g_1, b_1)$ and $c_2 = (r_2, g_2, b_2)$.
    *   Negation: $\bar{c}_1 = (MAX - r_1, MAX - g_1, MAX - b_1)$ [S1, unofficial].
    *   Union: $c_1 \cup c_2 = (\max(r_1, r_2), \max(g_1, g_2), \max(b_1, b_2))$ [S1, unofficial].
    *   Intersection: $c_1 \cap c_2 = (\min(r_1, r_2), \min(g_1, g_2), \min(b_1, b_2))$ [S1, unofficial].

**Pseudocode**

def construct_multiclassified_structure_graph(V, classification_functions):
    """
    V: voxel model
    classification_functions: list of functions C_i mapping voxel -> class_id
    """
    nc = len(classification_functions)
    I = [] # List of all isoclass identifiers
    E = [] # List of edges
    adjacency_table = {} # Key: (included_id, includer_id), Value: voxel_count
    
    # Step 1: Construct Isoclasses
    for i in range(nc):
        C_i = classification_functions[i]
        # Group voxels by class identifier
        isoclass_sets = {}
        for v in V.voxels:
            cid = C_i(v)
            if cid not in isoclass_sets:
                isoclass_sets[cid] = []
            isoclass_sets[cid].append(v)
            
            # Add to global identifier set
            if cid not in I:
                I.append(cid)
        
        # Compute properties for each isoclass
        for cid, voxels in isoclass_sets.items():
            voxel_count = len(voxels)
            bounding_box = compute_bounding_box(voxels)
            bounding_sphere_radius = compute_radius(bounding_box)
            opacity = compute_opacity(bounding_sphere_radius, voxel_count)
            color = stone_coloring_model(cid, MAX) # [S1, unofficial]
            # Store isoclass properties...
            
    # Step 2: Compute Inclusion Hierarchy
    # Process slice by slice to manage memory
    for slice in V.slices:
        for v in slice.voxels:
            # Get all isoclass identifiers for this voxel
            voxel_isoclasses = [C_i(v) for C_i in classification_functions]
            
            # Check all pairs for inclusion
            for inc_id in voxel_isoclasses:
                for incl_id in voxel_isoclasses:
                    if inc_id != incl_id:
                        # Increment count if both present
                        key = (inc_id, incl_id)
                        adjacency_table[key] = adjacency_table.get(key, 0) + 1
                        
    # Sort rows by increasing voxel count to derive hierarchy
    sorted_edges = sorted(adjacency_table.items(), key=lambda x: x[1])
    
    # Simple matrix traversal to define edges
    # Note: The source describes sorting rows and traversing. 
    # Implementation detail: If count > 0, inc_id is included in incl_id.
    # Direction: incl_id -> inc_id
    for (inc_id, incl_id), count in sorted_edges:
        if count > 0:
            E.append((incl_id, inc_id))
            
    # Step 3: Construct Labelled Voxel Model and Clusters
    LV = create_voxel_model_aligned_with(V)
    R = [] # Cluster list
    cluster_map = {} # hash_code -> cluster_id
    
    for v in V.voxels:
        voxel_isoclasses = tuple(C_i(v) for C_i in classification_functions)
        hash_code = compute_hash(voxel_isoclasses)
        
        if hash_code not in cluster_map:
            new_cluster_id = len(R)
            R.append({'id': new_cluster_id, 'isoclass_tuple': voxel_isoclasses})
            cluster_map[hash_code] = new_cluster_id
            
        cluster_id = cluster_map[hash_code]
        LV.set_value(v, cluster_id)
        
    # Define relationship F
    # F associates node i to cluster r if i in r.isoclass_tuple and no descendant of i is in r.isoclass_tuple
    F = {}
    for r in R:
        for node_id in r['isoclass_tuple']:
            # Check if any descendant of node_id is also in the tuple
            has_descendant_in_tuple = False
            for other_id in r['isoclass_tuple']:
                if other_id != node_id and is_descendant(other_id, node_id, E):
                    has_descendant_in_tuple = True
                    break
            if not has_descendant_in_tuple:
                F[node_id] = r['id']

def is_descendant(desc_id, anc_id, E):
    """Check if desc_id is a descendant of anc_id in the graph."""
    # Simple BFS/DFS from anc_id
    visited = set()
    queue = [anc_id]
    while queue:
        current = queue.pop(0)
        if current == desc_id:
            return True
        if current in visited:
            continue
        visited.add(current)
        # Find neighbors (children)
        for parent, child in E:
            if parent == current and child not in visited:
                queue.append(child)
    return False

**Edge Cases and Pitfalls**
*   **Memory Load:** Processing all voxels at once for huge models with many criteria can exceed memory. The method specifies slice-by-slice processing for the adjacency table construction [S1, unofficial].
*   **Empty Classes:** The source notes that "empty" classes across different criteria are equivalent and should be handled (remapped) to avoid spurious inclusion relationships [S1, unofficial].
*   **Precision:** Opacity and color computations depend on bounding box accuracy and $MAX$ value consistency [S1, unofficial].

## Subtopics

### Cluster Definition and Labelled Voxel Model
This subtopic defines the binary relation $F$ that links graph nodes to clusters in the labelled voxel model $LV$. A node $i$ is related to a cluster $r$ if $i$ is present in the cluster's isoclass tuple $CR$ and no descendant of $i$ in the graph $G$ is also present in $CR$. This ensures that each cluster is associated with the most specific (highest) isoclass in the hierarchy that contains it, allowing efficient access to voxels during graph traversal queries [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The inclusion hierarchy construction involves processing voxels slice by slice and sorting an adjacency table. The complexity depends on the number of voxels, the number of classification criteria $n_c$, and the number of classes per criterion. Sorting the adjacency table adds a logarithmic factor relative to the number of isoclass pairs [S1, unofficial].
*   **Memory Complexity:** The method uses an adjacency table and a labelled voxel model $LV$. Slice-by-slice processing of the input voxels reduces peak memory usage during hierarchy construction [S1, unofficial].
*   **Strengths:** Enables structural focus+context rendering by providing a clear hierarchy of semantic relationships. Allows users to explore complex multiclassified data through boolean queries on isoclasses [S1, unofficial].
*   **Limitations:** The construction process can be memory-intensive for very large models if not processed carefully (hence the slice-by-slice approach). The reliance on Stone’s coloring model may not suit all visual preferences, though it is interactive [S1, unofficial].
*   **When to use:** When visualizing volume data classified by multiple independent criteria where the inclusion relationships between classes are semantically important and need to be explored interactively [S1, unofficial].

## Background
The Multiclassified Structure Graph Construction method was introduced in the paper "Structural focus+context rendering of multiclassified volume data" [S1, unofficial]. It builds on the concept of Feature Graphs, extending them to handle multiple classification criteria simultaneously. The method uses Stone’s coloring model for initial color assignment [25] and employs multimodal 3D texture-mapping for rendering, composing proxy polygons parallel to the viewing plane [S1, unofficial].
