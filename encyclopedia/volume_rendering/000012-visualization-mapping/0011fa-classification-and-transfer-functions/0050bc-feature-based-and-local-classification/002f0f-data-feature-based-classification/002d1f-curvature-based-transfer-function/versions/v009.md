# Curvature-based Transfer Function

Also called: Curvature Based TF, Non-photorealistic Curvature TF, Shape Based TF (Curvature), cbTF

## Overview
The Curvature-based Transfer Function (cbTF) is a feature-based classification method that maps scalar data values and local surface curvature to optical properties (color and opacity) to highlight structural contours, ridges, and valleys in volume data [S1][S3, unofficial]. It distinguishes itself from intensity- or gradient-based methods by utilizing second-order derivative information, allowing it to differentiate between features of similar intensity but different geometric shapes (e.g., small vs. large spheres) [S1]. Unlike [Shape-based Transfer Function Generation](5941-shape-based-transfer-function-generation.md) which may rely on skeletonization or pre-segmentation, cbTF operates directly on the continuous field's differential invariants [S2, unofficial].

## How it works
The method evaluates a classification function $C(\mathbf{x})$ for each sample point $\mathbf{x}$, where the feature vector $\mathbf{f}(\mathbf{x})$ consists of the scalar data value $v(\mathbf{x})$ and the curvature $\kappa(\mathbf{x})$ [S1][S3, unofficial].

**Inputs:**
*   Scalar volume data $V$.
*   Camera position $\mathbf{c}$ (optional, for view-dependent contouring) [S1].

**Outputs:**
*   Opacity $\alpha \in [0, 1]$.
*   Color $\mathbf{C} = (r, g, b)$ [S1].

**Data Structures:**
*   **Transfer Function Domain:** A 2D lookup table (LUT) or texture where one axis represents the data value $v$ and the other represents the curvature $\kappa$ [S1][S3, unofficial].
*   **Curvature Field:** A pre-computed 3D volume storing the curvature value at each voxel [S1].

**Algorithm Steps:**

1.  **Preprocessing (Smoothing):**
    To mitigate spurious curvature variations caused by noise, the input volume $V$ is smoothed [S2, unofficial]. This is typically achieved via Gaussian smoothing, though it sacrifices resolution and accuracy [S2, unofficial].
    $$ V_{smooth} = V * G_\sigma $$
    Where $G_\sigma$ is a Gaussian kernel with standard deviation $\sigma$ [S2, unofficial].

2.  **Curvature Computation:**
    Compute the curvature $\kappa(\mathbf{x})$ for each voxel. The curvature is derived from the second-order derivatives of the scalar field, often using the Hessian matrix or Laplacian [S1].
    *   Compute the Hessian matrix $H(\mathbf{x})$ at each voxel.
    *   Calculate the curvature metric from the eigenvalues of $H(\mathbf{x})$ or the Laplacian $\nabla^2 V(\mathbf{x})$ [S1].
    *   **Constraint:** The computation requires a neighborhood of at least 26 points (the 3x3x3 cube excluding the center) to estimate the second derivatives accurately [S1].

3.  **Transfer Function Evaluation:**
    For each sample point $\mathbf{x}$ along a ray:
    *   Retrieve the scalar value $v = V(\mathbf{x})$ and curvature $\kappa = \kappa(\mathbf{x})$.
    *   If view-dependent contouring is enabled, compute the view vector $\mathbf{v}$ from $\mathbf{x}$ to camera $\mathbf{c}$ and the surface normal $\mathbf{n}$ (derived from the gradient $\nabla V$) [S1].
    *   Sample the 2D TF LUT at coordinates $(v, \kappa)$ to obtain $\alpha$ and $\mathbf{C}$ [S1][S3, unofficial].
    *   *Note:* The specific mapping of curvature to opacity/color is user-defined via keypoints in the 2D domain [S3, unofficial].

4.  **Accumulation:**
    Perform standard volume rendering accumulation (e.g., front-to-back compositing) using the computed $\alpha$ and $\mathbf{C}$ [S1].

**Pseudocode:**

```python
def compute_curvature_field(volume: Volume3D, sigma: float) -> Volume3D:
    """
    Computes the curvature field for a volume.
    Requires a 26-point neighborhood (3x3x3 stencil).
    """
    # Step 1: Smooth the volume to reduce noise-induced curvature artifacts
    smoothed_volume = gaussian_smooth(volume, sigma)
    
    # Step 2: Compute second-order derivatives (Hessian or Laplacian)
    # Using central differences for Laplacian as a proxy for curvature magnitude
    # Laplacian = d2V/dx2 + d2V/dy2 + d2V/dz2
    curvature_field = Volume3D(volume.dimensions)
    
    for x in range(1, volume.width - 1):
        for y in range(1, volume.height - 1):
            for z in range(1, volume.depth - 1):
                # Central difference approximation of Laplacian
                laplacian = (
                    smoothed_volume[x+1, y, z] + smoothed_volume[x-1, y, z] +
                    smoothed_volume[x, y+1, z] + smoothed_volume[x, y-1, z] +
                    smoothed_volume[x, y, z+1] + smoothed_volume[x, y, z-1] -
                    6 * smoothed_volume[x, y, z]
                )
                curvature_field[x, y, z] = laplacian
                
    return curvature_field
```

**Parameters:**
*   **Smoothing Kernel ($\sigma$):** Controls the trade-off between noise reduction and feature preservation. Higher $\sigma$ reduces spurious curvature but blurs fine details [S2, unofficial].
*   **TF Domain Dimensions:** The resolution of the 2D LUT. Typical values are not specified in sources, but real-time implementations require efficient texture sampling [S1].

**Edge Cases and Pitfalls:**
*   **Noise Sensitivity:** Curvature is highly sensitive to noise, leading to spurious surface variations. Smoothing is mandatory but degrades accuracy [S2, unofficial].
*   **Ambiguity:** Many distinct features share the same curvature value, making it difficult to isolate a specific target feature without unintended emphasis on other structures with similar geometry [S1].
*   **Computational Cost:** Requires at least 27 3D texture lookups per sample in real-time GPU implementations (1 for data, 6 for gradient if needed for normals, and additional lookups for curvature or the TF itself) [S1].

## Subtopics

### [Curvature](11695-curvature.md)
Defines the specific metric for curvature (e.g., mean curvature, Gaussian curvature) and its computation via the Hessian matrix. It is the foundational feature used by cbTF to measure local shape deviation.

## Operating characteristics
*   **Time Complexity:** Real-time capable on modern GPUs. Requires a minimum of 27 3D texture lookups per sample in the implementation described in [S1].
*   **Memory Complexity:** Requires storage for the original volume, the smoothed volume (optional), and the pre-computed curvature field [S1].
*   **Strengths:** Effective for non-photorealistic rendering (NPR) to highlight contours and distinguish features by shape rather than intensity [S1][S3, unofficial]. Can differentiate between objects of the same intensity but different sizes/curvatures [S1].
*   **Limitations:** Highly susceptible to noise; requires smoothing which reduces resolution. Struggles to uniquely identify specific features if they share similar curvature properties [S1].
*   **When to Use:** When the goal is to visualize surface contours, ridges, or valleys, or when intensity-based classification fails to separate structurally distinct objects [S1][S3, unofficial].
*   **When Not to Use:** In noisy datasets where smoothing destroys critical detail, or when precise isolation of a specific feature is required without affecting others with similar curvature [S1].

## Background
The Curvature-based Transfer Function was introduced by Kindlmann et al. [KWTM03] as a method to use the curvature of structures within a volume to aid classification and produce non-photorealistic images by highlighting contours [S2, S3, unofficial]. It was further popularized in real-time GPU implementations described in *GPU Gems 2* [PF05] and [HSS∗05] for iso-surface rendering [S1]. The approach is part of the broader family of feature-based classification methods that extend the transfer function domain beyond simple scalar values [S1].
