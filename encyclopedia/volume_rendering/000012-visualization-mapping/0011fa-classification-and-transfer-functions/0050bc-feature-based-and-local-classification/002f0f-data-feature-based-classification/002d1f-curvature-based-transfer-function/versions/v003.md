# Curvature-based Transfer Function

Also called: Curvature Based TF, Non-photorealistic Curvature TF, Shape Based TF (Curvature), cbTF

## Overview
The Curvature-based Transfer Function (cbTF) maps scalar data values and local surface curvature to opacity and color, primarily to distinguish feature boundaries and produce non-photorealistic contouring effects [S1][S2, S3, unofficial]. Unlike gradient-based methods that highlight edge intensity, cbTF distinguishes features based on their geometric shape (e.g., distinguishing the border of a small feature from a large one) [S1]. It is particularly effective for ridge/valley visualization and emphasizing bumpiness, though it struggles to isolate specific features without unintended emphasis on other structures sharing similar curvature [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Scalar volume data $V$, camera position $\mathbf{p}_{cam}$ (optional, for view-dependent contouring).
*   **Output:** Opacity $\alpha \in [0, 1]$ and color $\mathbf{c}$ for each sample point.

**Data Structures:**
*   **Curvature Volume:** A 3D volume storing curvature values, computed from the input scalar volume.
*   **Transfer Function LUT:** A 2D lookup table indexed by $(v, k)$, where $v$ is the data value and $k$ is the curvature. The table stores $(\alpha, \mathbf{c})$ pairs [S1].

**Feature Extraction (Curvature Computation):**
Curvature is computed using a 26-point neighborhood (the 3x3x3 cube centered on the voxel) [S1]. The curvature metric describes local shape contours and measures deviation from a straight aspect [S4, unofficial]. It is derived from the eigenvalues of the Hessian matrix or approximated via the Laplacian [S4, unofficial].
Two main magnitudes are defined: maximum curvature $k_1$ and minimum curvature $k_2$ [S4, unofficial]. Common derived metrics include:
*   Mean Curvature: $H = \frac{k_1 + k_2}{2}$
*   Gaussian Curvature: $K = k_1 k_2$ [S4, unofficial]

**Classification Steps:**
1.  **Smoothing (Optional):** To combat spurious curvature variations in noisy data (e.g., MRI), the input volume is smoothed [S2, unofficial]. This sacrifices accuracy and resolution [S2, unofficial].
2.  **Curvature Calculation:** For each voxel, compute the curvature metric $k$ using the 26-point neighborhood [S1].
3.  **Lookup:** Query the 2D LUT using the pair $(v, k)$ to retrieve opacity $\alpha$ and color $\mathbf{c}$ [S1].
4.  **Rendering:** Perform volume rendering (e.g., ray casting) using the retrieved optical properties [S1].

**Pseudocode:**
```python
def compute_curvature(volume, voxel):
    """
    Computes curvature for a voxel using a 26-point neighborhood.
    Returns a scalar curvature value k.
    Note: Exact formula (Hessian eigenvalues vs Laplacian) depends on implementation [S4, unofficial].
    """
    # Extract 3x3x3 neighborhood centered at voxel
    neighborhood = volume[voxel.x-1:voxel.x+2, 
                          voxel.y-1:voxel.y+2, 
                          voxel.z-1:voxel.z+2]
    
    # Compute Hessian matrix or Laplacian from neighborhood
    # H = Hessian(neighborhood)
    # k1, k2 = eigenvalues(H)
    # k = (k1 + k2) / 2  # Mean curvature example
    k = compute_curvature_metric(neighborhood)
    return k

def cbtf_render(ray, volume, tf_lut, curvature_volume):
    """
    Single ray sample for curvature-based transfer function.
    """
    t = ray.origin
    alpha_accum = 0.0
    color_accum = [0.0, 0.0, 0.0]
    
    while t inside volume:
        v = volume.sample(t)
        k = curvature_volume.sample(t)
        
        # Query 2D LUT with data value and curvature
        alpha, color = tf_lut.lookup(v, k)
        
        # Standard volume rendering compositing
        weight = alpha * (1.0 - alpha_accum)
        color_accum += weight * color
        alpha_accum += weight
        
        t += ray.direction * step_size
        
    return color_accum, alpha_accum
```

**Parameters:**
*   **Smoothing Kernel:** Size and sigma for pre-smoothing to reduce noise-induced curvature artifacts [S2, unofficial].
*   **Curvature Metric:** Choice between Mean, Gaussian, or Principal curvatures [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Noise Amplification:** Noise causes spurious surface curvature variations, leading to incorrect classification [S2, unofficial]. Smoothing is required but reduces resolution [S2, unofficial].
*   **Ambiguity:** Many distinct features share the same curvature value, making it difficult to emphasize a targeted feature without unintended emphasis on others [S1].
*   **Computational Cost:** Requires at least a 26-point neighborhood for accurate curvature, increasing memory access patterns [S1].

## Subtopics

### Curvature
A specific metric computed by signal convolution that describes local shape contours [S4, unofficial]. It is derived from maximum ($k_1$) and minimum ($k_2$) curvatures, allowing for Mean or Gaussian curvature variants [S4, unofficial]. Used primarily for non-photorealistic visualizations [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Real-time capable with GPU implementations [S1]. Requires a minimum of 27 3D texture lookups per sample (1 for data, 26 for neighborhood/curvature context) [S1].
*   **Memory Complexity:** Requires storage for the curvature volume and a 2D LUT [S1].
*   **Strengths:** Effective for non-photorealistic contouring and distinguishing feature sizes based on geometry [S1][S2, unofficial].
*   **Limitations:** Sensitive to noise; difficult to isolate specific features due to curvature ambiguity across different shapes [S1][S2, unofficial].
*   **When to Use:** When visual emphasis on contours, ridges, or valleys is desired, or when distinguishing features by shape rather than intensity [S1][S2, unofficial].
*   **When Not to Use:** In noisy datasets without sufficient smoothing, or when precise isolation of specific internal structures is required [S1][S2, unofficial].

## Background
The curvature-based transfer function was introduced by Kindlmann et al. [KWTM03] as a second dimension in the transfer function domain [S3, unofficial]. It builds on the concept of using geometric features for classification [S2, unofficial]. Real-time GPU variants were later detailed in GPU Gems 2 [PF05] and [HSS*05] for iso-surfaces [S1]. It is part of the broader family of data feature-based classification methods [S1][S2, S3, unofficial].
