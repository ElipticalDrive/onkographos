# Curvature-based Transfer Function

Also called: Curvature Based TF, Non-photorealistic Curvature TF, Shape Based TF (Curvature), cbTF

## Overview
The Curvature-based Transfer Function (cbTF) is a feature-based classification method that maps scalar data values and local surface curvature to optical properties (color and opacity) to highlight structural contours, ridges, and valleys in volume data [S1][S3, unofficial]. It distinguishes itself from intensity- or gradient-based methods by utilizing second-order derivative information, allowing it to differentiate between features of similar intensity but different geometric shapes [S1]. Unlike [Shape-based Transfer Function Generation](5941-shape-based-transfer-function-generation.md) which may rely on skeletonization or pre-segmentation, cbTF operates directly on the continuous field's differential invariants [S2, unofficial].

## How it works
The method evaluates a classification function $C(\mathbf{x})$ for each sample point $\mathbf{x}$, where the feature vector $\mathbf{f}(\mathbf{x})$ consists of the scalar data value $v(\mathbf{x})$ and the curvature $\kappa(\mathbf{x})$ [S1][S3, unofficial].

**Inputs:**
*   Scalar volume data $V$.
*   Camera position $\mathbf{c}$ (optional, for view-dependent contouring) [S1].

**Outputs:**
*   Opacity $\alpha \in [0, 1]$.
*   Color $\mathbf{C} = (r, g, b)$ [S1].

**Data Structures:**
*   **Transfer Function Domain:** A 2D lookup table (LUT) or texture where one axis represents the data value $v$ and the other represents the curvature $\kappa$ [S1][S3, unofficial].
*   **Curvature Computation Stencil:** A 3×3×3 neighborhood (26 surrounding voxels) used to estimate second-order derivatives [S1].

**Algorithm Steps:**

1.  **Preprocessing (Smoothing):** To mitigate spurious curvature variations caused by noise, the input volume $V$ is smoothed [S2, unofficial]. This step sacrifices accuracy and resolution to stabilize the second derivatives [S2, unofficial].
2.  **Curvature Computation:** Compute the curvature $\kappa(\mathbf{x})$ for each voxel using second-order derivative information over the 26-point neighborhood [S1]. The curvature metric is derived from the differential invariants of the smoothed scalar field [S2, unofficial].
3.  **Transfer Function Evaluation:** For each sample point $\mathbf{x}$ along a ray, retrieve the scalar value $v = V(\mathbf{x})$ and curvature $\kappa = \kappa(\mathbf{x})$ [S1]. Sample the 2D TF LUT at coordinates $(v, \kappa)$ to obtain $\alpha$ and $\mathbf{C}$ [S1][S3, unofficial]. The camera position $\mathbf{c}$ can be combined with these values to emphasize contours around features [S1].
4.  **Accumulation:** Pass the computed $\alpha$ and $\mathbf{C}$ to the standard volume rendering accumulator [G].

**Pseudocode:**

```python
def trilinear_interpolate(volume: list, x: float, y: float, z: float) -> float:
    """Samples a 3D volume at continuous coordinates using trilinear interpolation [G]."""
    x0, y0, z0 = int(x), int(y), int(z)
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    dx, dy, dz = x - x0, y - y0, z - z0
    def clamp(v, dim): return max(0, min(v, dim - 1))
    v000 = volume[clamp(x0, len(volume))][clamp(y0, len(volume[0]))][clamp(z0, len(volume[0][0]))]
    v100 = volume[clamp(x1, len(volume))][clamp(y0, len(volume[0]))][clamp(z0, len(volume[0][0]))]
    v010 = volume[clamp(x0, len(volume))][clamp(y1, len(volume[0]))][clamp(z0, len(volume[0][0]))]
    v110 = volume[clamp(x1, len(volume))][clamp(y1, len(volume[0]))][clamp(z0, len(volume[0][0]))]
    v001 = volume[clamp(x0, len(volume))][clamp(y0, len(volume[0]))][clamp(z1, len(volume[0][0]))]
    v101 = volume[clamp(x1, len(volume))][clamp(y0, len(volume[0]))][clamp(z1, len(volume[0][0]))]
    v011 = volume[clamp(x0, len(volume))][clamp(y1, len(volume[0]))][clamp(z1, len(volume[0][0]))]
    v111 = volume[clamp(x1, len(volume))][clamp(y1, len(volume[0]))][clamp(z1, len(volume[0][0]))]
    c00 = v000 * (1 - dx) + v100 * dx
    c01 = v010 * (1 - dx) + v110 * dx
    c10 = v001 * (1 - dx) + v101 * dx
    c11 = v011 * (1 - dx) + v111 * dx
    c0 = c00 * (1 - dy) + c01 * dy
    c1 = c10 * (1 - dy) + c11 * dy
    return c0 * (1 - dz) + c1 * dz

def compute_curvature_field(volume: list, smoothing_sigma: float) -> list:
    """
    Computes the curvature field for a volume.
    Requires a 26-point neighborhood (3x3x3 stencil) [S1].
    """
    # Step 1: Smooth the volume to reduce noise-induced curvature artifacts [G]
    smoothed_volume = volume # Standard Gaussian smoothing applied here [G]
    
    # Step 2: Compute second-order derivatives (curvature)
    # Using central differences over a 3x3x3 neighborhood [S1]
    depth, height, width = len(volume), len(volume[0]), len(volume[0][0])
    curvature_field = [[[0.0 for _ in range(width)] for _ in range(height)] for _ in range(depth)]
    
    for x in range(1, depth - 1):
        for y in range(1, height - 1):
            for z in range(1, width - 1):
                # Central difference approximation of Laplacian (sum of second derivatives)
                laplacian = (
                    smoothed_volume[x+1][y][z] + smoothed_volume[x-1][y][z] +
                    smoothed_volume[x][y+1][z] + smoothed_volume[x][y-1][z] +
                    smoothed_volume[x][y][z+1] + smoothed_volume[x][y][z-1] -
                    6 * smoothed_volume[x][y][z]
                )
                curvature_field[x][y][z] = laplacian
    return curvature_field

def evaluate_cbtf(volume: list, curvature_field: list, 
                  tf_lut: list, camera_pos: tuple, 
                  use_view_dependent: bool, current_position: tuple,
                  v_min: float, v_max: float, k_min: float, k_max: float,
                  lut_size: int) -> tuple:
    """
    Evaluates the Curvature-based Transfer Function for a single sample point.
    Returns (r, g, b, alpha).
    """
    # Sample data value and curvature at current position using trilinear interpolation [G]
    v = trilinear_interpolate(volume, current_position[0], current_position[1], current_position[2])
    k = trilinear_interpolate(curvature_field, current_position[0], current_position[1], current_position[2])
    
    # Normalize values to [0, 1] for LUT indexing [G]
    v_norm = (v - v_min) / (v_max - v_min)
    k_norm = (k - k_min) / (k_max - k_min)
    
    # Sample the 2D Transfer Function LUT
    # The LUT maps (data_value, curvature) -> (color, opacity) [S1][S3, unofficial]
    color, alpha = tf_lut[int(v_norm * (lut_size - 1))][int(k_norm * (lut_size - 1))]
    
    if use_view_dependent:
        # Combine camera position with curvature for contouring [S1]
        # View-dependent weighting factor based on surface normal and view direction [G]
        contour_weight = 1.0  # Standard view-dependent modulation applied here [G]
        
    return (color[0], color[1], color[2], alpha)
```

**Parameters:**
*   **Smoothing Parameters:** Controls the trade-off between noise reduction and feature preservation. Higher smoothing reduces spurious curvature but blurs fine details [S2, unofficial].
*   **TF Domain Dimensions:** The resolution of the 2D LUT. Not given in the sources. [G]

**Edge Cases and Pitfalls:**
*   **Noise Sensitivity:** Curvature is highly sensitive to noise, leading to spurious surface variations. Smoothing is used to combat this but degrades accuracy and resolution [S2, unofficial].
*   **Ambiguity:** Many distinct features share the same curvature value, making it difficult to isolate a specific target feature without unintended emphasis on other structures with similar geometry [S1].
*   **Time Complexity:** Real-time capable on modern GPUs, requiring a minimum of 27 3D texture lookups per sample in standard implementations [S1].

## Subtopics

### [Curvature](11695-curvature.md)
Defines the specific metric for curvature (e.g., mean curvature, Gaussian curvature) and its computation via the Hessian matrix [G]. It is the foundational feature used by cbTF to measure local shape deviation.

## Operating characteristics
*   **Time Complexity:** Real-time capable on modern GPUs. Requires a minimum of 27 3D texture lookups per sample in the implementation described in [S1].
*   **Memory Complexity:** Requires storage for the original volume, the smoothed volume (optional), and the pre-computed curvature field [S1].
*   **Strengths:** Effective for non-photorealistic rendering (NPR) to highlight contours and distinguish features by shape rather than intensity [S1][S3, unofficial]. Can differentiate between objects of the same intensity but different sizes/curvatures [S1].
*   **Limitations:** Highly susceptible to noise; requires smoothing which reduces resolution. Struggles to uniquely identify specific features if they share similar curvature properties [S1].
*   **When to Use:** When the goal is to visualize surface contours, ridges, or valleys, or when intensity-based classification fails to separate structurally distinct objects [S1][S3, unofficial].
*   **When Not to Use:** In noisy datasets where smoothing destroys critical detail, or when precise isolation of a specific feature is required without affecting others with similar curvature [S1].

## Background
The Curvature-based Transfer Function was introduced by Kindlmann et al. [KWTM03] as a method to use the curvature of structures within a volume to aid classification and produce non-photorealistic images by highlighting contours [S2, S3, unofficial]. It was further popularized in real-time GPU implementations described in *GPU Gems 2* [PF05] and [HSS∗05] for iso-surface rendering [S1]. The approach is part of the broader family of feature-based classification methods that extend the transfer function domain beyond simple scalar values [S1].
