# Barycentric Mapping for Tensor Shape Exploration

Also called: Barycentric Shape Mapping, Tensor Anisotropy Barycentric Mapping

## Overview
Barycentric Mapping is a feature-based classification technique that projects tensor anisotropy indices onto a 2D hyper-plane to control opacity and color transfer functions in volume rendering [S1]. It distinguishes itself from scalar transfer functions by mapping the geometric shape of diffusion tensors directly to a triangular domain, allowing distinct visual separation of isotropic, linear, and planar diffusion regimes . This method emphasizes important structural features (linear and planar anisotropy) while rendering unimportant regions (isotropic diffusion) transparent [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A symmetric tensor field where each tensor has eigenvalues $\lambda_1, \lambda_2, \lambda_3$ sorted such that $\lambda_1 > \lambda_2 > \lambda_3$ [S1].
*   **Output:** A 2D coordinate vector $\mathbf{v}$ used to index a 2D opacity transfer function $\alpha_b(\mathbf{v})$ and/or a color lookup table [S1].

**Data Structures:**
The method relies on three anisotropy indices $(c_l, c_p, c_s)$ which form a barycentric coordinate system. These indices satisfy the constraint $c_p + c_l + c_s = 1$ [S1].

**Steps:**

1.  **Compute Anisotropy Indices:**
    Calculate the three shape indices from the sorted eigenvalues $\lambda_1 > \lambda_2 > \lambda_3$ using the following formulas [S1]:
    $$
    c_p = \frac{\lambda_2 - \lambda_3}{\lambda_3}
    $$
    $$
    c_l = \frac{\lambda_1 - \lambda_2}{\lambda_3}
    $$
    $$
    c_s = \frac{\lambda_1}{\lambda_3}
    $$
    Note: While the source states $c_p + c_l + c_s = 1$, the provided formulas for $c_p, c_l, c_s$ do not mathematically sum to 1 for arbitrary eigenvalues. For example, if $\lambda_1=3, \lambda_2=2, \lambda_3=1$, then $c_p=1, c_l=1, c_s=3$, summing to 5. The source text explicitly claims the sum is 1 [S1]. Implementers should verify if the indices are normalized differently in practice or if the formula definitions in the source contain a typo (e.g., division by $\lambda_1$ or normalization by the sum). However, the mapping step below uses $c_s$ directly.

2.  **Normalize Indices (Optional but Recommended):**
    To utilize the full range of the transfer function, normalize the indices across the dataset or a local neighborhood [S1]:
    $$
    c_i' = \frac{c_i - \min(c_i)}{\max(c_i) - \min(c_i)}
    $$
    where $c_i \in \{c_l, c_p, c_s\}$ [S1].

3.  **Map to 2D Barycentric Space:**
    Construct the 2D vector $\mathbf{v}$ from the indices. The source defines this as [S1]:
    $$
    \mathbf{v} = \begin{pmatrix} 1 - c_l - 0.5c_s \\ c_s \end{pmatrix}
    $$
    This vector $\mathbf{v}$ serves as the coordinate for the 2D transfer function [S1].

4.  **Lookup Transfer Function:**
    Use $\mathbf{v}$ to sample the opacity transfer function $\alpha_b(\mathbf{v})$ and/or color lookup table [S1].

**Pseudocode:**
```python
def barycentric_mapping(eigenvalues):
    """
    Computes the 2D barycentric coordinate vector v from tensor eigenvalues.
    
    Args:
        eigenvalues: Tuple or list of three floats (lambda1, lambda2, lambda3)
                     sorted such that lambda1 > lambda2 > lambda3.
                     
    Returns:
        v: Tuple (v_x, v_y) representing the 2D coordinate for transfer function lookup.
    """
    lambda1, lambda2, lambda3 = eigenvalues
    
    # Guard against division by zero or invalid eigenvalue ordering
    if lambda3 == 0:
        # Handle degenerate case: Not given in the sources.
        # Typically, clamp lambda3 to a small epsilon or handle isotropic case separately.
        lambda3 = 1e-9 
        
    # 1. Compute anisotropy indices as defined in source [S1]
    # Note: Source claims cp + cl + cs = 1, but formulas provided do not satisfy this.
    # Implementation follows source formulas exactly.
    cp = (lambda2 - lambda3) / lambda3
    cl = (lambda1 - lambda2) / lambda3
    cs = lambda1 / lambda3
    
    # 2. Map to 2D vector v
    # v = (1 - cl - 0.5*cs, cs)
    v_x = 1.0 - cl - 0.5 * cs
    v_y = cs
    
    return (v_x, v_y)
```

**Parameters:**
*   **Normalization:** The normalization step $c_i \rightarrow (c_i - \min(c_i)) / (\max(c_i) - \min(c_i))$ is optional but used to stretch the map to utilize the entire range of anisotropy indices [S1].

**Edge Cases and Pitfalls:**
*   **Eigenvalue Ordering:** The formulas require $\lambda_1 > \lambda_2 > \lambda_3$. If eigenvalues are equal (isotropic tensor), the indices may become undefined or zero depending on implementation [S1].
*   **Zero Eigenvalues:** Division by $\lambda_3$ requires $\lambda_3 \neq 0$. If $\lambda_3 = 0$, the indices are undefined. A guard is required [G].
*   **Sum Constraint Contradiction:** The source states $c_p + c_l + c_s = 1$ but provides formulas that do not sum to 1. This is a significant inconsistency in the source material [S1].

## Subtopics

### [Barycentric Opacity Mapping](22236-barycentric-opacity-mapping.md)
Uses the barycentric coordinates to control opacity, emphasizing structural features and making isotropic regions transparent. Choose this when visual separation of diffusion regimes is the primary goal.

## Operating characteristics
*   **Time Complexity:** The computation per tensor is $O(1)$, involving a few arithmetic operations (subtractions, divisions, multiplications) [S1].
*   **Memory Complexity:** $O(1)$ auxiliary memory per tensor for storing indices and the 2D vector [S1].
*   **Performance:** The method allows hardware-accelerated lookup at framebuffer rates, as demonstrated with 1.8M texture pixels on a $94 \times 128 \times 32$ DWI dataset [S1].
*   **Strengths:** Interactive exploration of tensor anisotropies; distinct visual separation of isotropic, linear, and planar regimes; supports both opacity and color mapping [S1].
*   **Limitations:** The mathematical inconsistency in the source regarding the sum of indices may lead to implementation confusion; requires sorted eigenvalues [S1].
*   **When to use:** When exploring the shape characteristics of tensor fields (e.g., diffusion MRI) and needing to highlight specific anisotropy types (linear, planar, spherical) [S1].
*   **When not to use:** When the tensor field is not symmetric or when eigenvalue sorting is not feasible [G].

## Background
The method was introduced in the paper "Tensor Splats: Visualising Tensor Fields by Texture Mapped Volume Rendering" [S1]. It was used to visualize synthetic data (cube, sphere, radiating spikes) and Diffusion Weighted Imaging (DWI) data, specifically highlighting white-matter fiber tracks [S1]. The technique is part of a broader family of feature-based classification methods for tensor visualization [S1].
