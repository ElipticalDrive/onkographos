# Shape-based Transfer Function Generation

Also called: Shape classification, Shape-based TF (Skeleton), Shape-based Transfer Functions, Curve-Skeleton Shape Classification TF, Shape classification for volume visualization, Skeleton-based shape descriptor classification

## Overview
Shape-based Transfer Function Generation is a classification method that assigns optical properties to volumetric features based on their 3D shape rather than solely on intensity or gradient magnitude [S3]. It solves the problem of distinguishing features with overlapping intensity ranges (e.g., contrast-filled vessels vs. bones) by using a shape descriptor derived from curve-skeletons [S3]. Unlike per-voxel classification methods such as [Curvature-based Transfer Function](5452-curvature-based-transfer-function.md) which rely on local eigenvalue analysis, this method classifies complete volumetric features using curve-skeletons, allowing for a more intuitive user interface where optical properties are assigned to shape classes rather than individual voxels [S3].

## How it works
**Inputs:**
*   Scalar volume data $V$.
*   Pre-segmentation mask $M$ (binary volume specifying surface voxels of objects of interest) [S3].

**Outputs:**
*   Shape descriptor triple $(\tau, \sigma, \beta)$ for each voxel, where $\tau$ is tubiness, $\sigma$ is surfaceness, and $\beta$ is blobbiness [S3].
*   Optical properties (color, opacity) assigned by the user based on these descriptors [S3].

**Data Structures:**
*   **Pre-segmentation Mask:** Binary volume $M(\mathbf{x}) \in \{0, 1\}$. 1 indicates surface voxels of the object; 0 indicates background [S3].
*   **Curve-Skeleton:** A set of polygonal chains (segments). Each segment is a list of 3D points $(x, y, z)$ [S3].
*   **Skeleton Regions:** A partition of the pre-segmented volume. Each region $R$ corresponds to one curve-skeleton segment [S3].
*   **Distance Map:** $D(\mathbf{v})$ stores the minimal distance from a surface voxel $\mathbf{v}$ to the skeleton [S3].

**Parameters:**
*   **Field Strength:** Low value of 4 chosen to get minimal complexity skeleton [S3].
*   **High Divergence Points:** Default 20% used for skeleton computation [S3].
*   **Segment Length Threshold:** 5 to 10 voxels for data sets of size $256^3$ to $512^3$ [S3].

**Steps:**

1.  **Pre-segmentation:** Perform a rough, threshold-based pre-segmentation (windowing) of the volume data to obtain surface information about objects of interest. This can be automatic if intensity ranges are known (e.g., Hounsfield scale for CT) [S3].
2.  **Skeleton Computation:** Compute the curve-skeletons for each resulting volumetric structure using the potential field method (e.g., Cornea’s pfSkel) [S3]. Input is the binary volume $M$. Output is multiple skeleton segments (polygonal chains of seed points) [S3].
3.  **Skeleton Normalization:**
    *   **Gap Closing:** Connect each end node of the skeleton graph with its next neighboring skeleton point outside the end node's segment, if the connecting line lies completely within the pre-segmented object [S3].
    *   **Segmentation:** Split the curve-skeleton into segments not exceeding the length threshold (5-10 voxels) [S3].
    *   **Pruning:** Discard degenerated skeleton branches shorter than the length threshold [S3].
4.  **Decomposition:** Decompose the pre-segmented volume based on the curve-skeleton segments. Divide the volume into 'skeleton regions' $R$, where each region corresponds to one segment of the curve-skeleton [S3].
5.  **Merging:** Merge adjacent skeleton regions based on criteria to improve classifiability, as individual skeleton regions from ad-hoc decomposition may not have a meaningful shape [S3].
6.  **Shape Analysis:** Compute shape scores (membership values) for each merged skeleton region $R$ [S3].
    *   **Tubiness $\tau(R)$:**
        $$ \tau(R) := \frac{1}{\max\left(\sqrt{\frac{1}{|\partial R|} \sum_{\vec{v} \in \partial R} (D(\vec{v}) - \bar{d})^2}, 1\right)} \in [0; 1] $$
        where $\partial R$ is the set of surface voxels of $R$, $D$ is the distance map from skeleton region growing, and $\bar{d}$ is the mean skeleton distance of all $\vec{v} \in \partial R$ [S3].
    *   **Planarity $plan(R)$:**
        $$ plan(R) := \text{clamp}\left(\frac{1}{5} \frac{b_m(R)}{b_s(R)} - 1, 0, 1\right) \in [0; 1] $$
        where $b_m(R)$ is the second shortest side and $b_s(R)$ is the shortest side of the minimal oriented bounding box of $R$ [S3].
    *   **Convexity $conv(R)$:** Select an arbitrary set of pairs of surface points. For each line segment formed by a point pair, determine the fraction that runs inside the shape. $conv(R)$ is the average of these fractions [S3].
    *   **Surfaceness $surf(R)$:**
        $$ surf(R) := (plan(R) + conv(R)) \cdot (1 - \tau(R)) \in [0; 2] $$
        [S3].
    *   **Blobbiness $blob(R)$:**
        $$ blob(R) := \frac{\sigma^2_{sph}(vol)}{\sigma^2(R)} \in [0; 1] $$
        where $\sigma^2(R)$ is the variance of the region and $\sigma^2_{sph}(vol)$ is the variance of a sphere with the same volume [S3].
        *   Variance $\sigma^2(R)$:
            $$ \sigma^2(R) := \sum_{\vec{r} \in R} |\vec{r} - m|^2 $$
            where $\vec{r}$ are voxel coordinates and $m$ is the center of mass: $m = \frac{1}{|R|} \sum_{\vec{r} \in R} \vec{r}$ [S3].
        *   Sphere Variance $\sigma^2_{sph}(vol)$:
            $$ \sigma^2_{sph}(vol) = \frac{4}{5} \pi \left(\frac{3}{4\pi} vol\right)^{5/3} $$
            where $vol = |R|$ [S3].
7.  **Transfer Function Specification:** Assign optical properties to the shape classes via a continuous triangle-shaped plot showing the occurrence of detected shape classes [S3].

## Subtopics

### [Barycentric Shape Selection Widget](5970-barycentric-shape-selection-widget.md)
The Barycentric Shape Selection Widget is a user interface component that maps 4D transfer function space (tubiness, surfaceness, blobbiness, and intensity) onto a 2D equilateral triangle using barycentric coordinates, allowing users to intuitively select shape classes for volume rendering. It distinguishes itself from scalar-only transfer functions by enabling direct manipulation of geometric shape memberships (tubiness, surfaceness, blobbiness) derived from curve skeletons, serving as the first stage of classification before intensity-based optical property assignment.

## Operating characteristics
**Time and Memory Complexity:**
*   Skeleton computation using the potential field method is the slowest of examined techniques, but preprocessing time is not a main issue for the use case [S3].
*   Memory usage depends on storing the distance map and skeleton segments [S3].

**Measured Performance:**
*   Tested on data sets of sizes $256^3$ to $512^3$ [S3].
*   Successfully distinguishes blobby heart structures filled with contrast agents from occluding vessels and rib bones [S3].

**Strengths and Limitations:**
*   **Strengths:** Allows visual separation of objects with similar intensity but different shapes; more intuitive user interface than per-voxel methods; robust to moderate within-class deformation [S3].
*   **Limitations:** Requires proper masking/pre-segmentation, which can be challenging; imperfect pre-segmentations cause instabilities in shape-skeletons; tubiness classifier reliability depends on skeleton quality (incomplete segments boost standard deviation); cavities inside pre-segmentation disturb skeleton computation [S3].

**When to Use:**
*   When features have overlapping intensity ranges but distinct shapes (e.g., medical imaging with contrast agents) [S3].
*   When an intuitive, feature-based classification is preferred over per-voxel histogram interpretation [S3].

**When Not to Use:**
*   When high-quality manual segmentation is not feasible and windowing is insufficient [S3].
*   When real-time performance is critical and potential field skeletonization is too slow [S3].

## Background
The concept of axial description of shape (skeleton) was proposed in 2D by Blum [2]. Binford [1] proposed generalized cylinders in 3D. Cornea et al. [4, 5] introduced hierarchical curve-skeletons using repulsive force fields. The specific method of Shape-based Transfer Functions was proposed by Praßni et al. [S3]. It is described in reference [17] [S1, unofficial].
