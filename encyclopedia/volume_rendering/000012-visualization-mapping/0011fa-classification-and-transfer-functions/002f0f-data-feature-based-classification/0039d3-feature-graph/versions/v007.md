# Feature Graph

Also called: Feature Graph Construction, Feature Graph building

## Overview
The Feature Graph is a hierarchical data structure that represents classified voxel models as a directed acyclic graph (DAG), where nodes correspond to non-empty clusters of voxels (features) sharing specific label values, and arcs represent the inclusion relationship of these voxel sets [S1, unofficial]. It solves the problem of efficiently managing and rendering multiresolution volume data by organizing voxels into disjoint sets at leaf nodes, allowing ancestor features to be reconstructed via traversal, thereby avoiding redundancy [S1, unofficial]. Unlike flat transfer functions, it explicitly models the topological inclusion of material regions, enabling focused visualization and efficient out-of-core traversal [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A labeled voxel model where each voxel $v$ has a set of $n_c$ boolean labels $r_i(v)$ for $i \in [1, n_c]$, indicating fulfillment of $n_c$ non-exclusive classification criteria [S1, unofficial].
*   **Output:** A Feature Graph (DAG) with nodes representing features, arcs representing inclusion, and leaf nodes storing Sets of Voxels (SOVs). A Feature Hash Table provides direct index access to nodes [S1, unofficial].

**Data Structures:**
1.  **Feature Hash Table:** Maps a hash code (derived from the boolean label vector of a voxel) to a graph node.
2.  **Node:** Represents a feature. Contains:
    *   Label signature (subset of boolean expressions).
    *   Reference to SOV (if leaf) or list of children.
    *   Optional optical properties.
3.  **Set of Voxels (SOV):** The set of voxels belonging to feature $f_i$.
    *   **Storage Policy:** SOVs are stored **only** in leaf nodes to avoid redundancy. Ancestor SOVs are virtual, computed by recursively traversing descendant nodes [S1, unofficial].
    *   **Representation:**
        *   *List-based:* List of voxels with various sizes (from octree compression). Does not preserve spatial ordering.
        *   *Submodel:* Octree or voxel grid. Voxels not belonging to the feature are assigned zero value. Preserves spatial ordering. A voxel has a non-zero value in only one unique leaf SOV [S1, unofficial].
4.  **Feature (fall):** A special root node representing the union of all features that do not have an ancestor.

**Algorithm Steps:**

1.  **Clustering (High Resolution):**
    *   Traverse the labeled voxel model.
    *   For each voxel $v$, compute its label vector $\mathbf{r}(v) = [r_1(v), \dots, r_{n_c}(v)]$.
    *   Compute hash code $h = \text{Hash}(\mathbf{r}(v))$.
    *   Add $v$ to the SOV indexed by $h$ in the Feature Hash Table.
    *   Initially, SOVs are represented as lists of voxels [S1, unofficial].

2.  **Compression (Optional but recommended):**
    *   Compute the bounding box for each filled SOV.
    *   Create a voxel submodel (e.g., octree) for each SOV.
    *   Compress submodels as octrees.
    *   *Alternative:* Traverse octrees to create a list-based representation of SOVs with voxels of various sizes (storing only black nodes of the octree with associated size) [S1, unofficial].

3.  **Hierarchy Creation:**
    *   Create leaf nodes in the graph for each non-empty SOV computed in Step 1. Associate them with the SOVs.
    *   Derive the hierarchy iteratively:
        *   Identify common ancestors for nodes sharing bits in their hash codes.
        *   Create intermediate nodes for these common ancestors.
        *   Update the Feature Hash Table to reference new nodes [S1, unofficial].
    *   If the graph consists of multiple disconnected hierarchies, create the `fall` node as the common root, linking to the roots of each hierarchy [S1, unofficial].

4.  **Multiresolution Handling:**
    *   Compute label sets at coarser resolution levels (larger voxels).
    *   Repeat the clustering process (Step 1) for larger voxels.
    *   Distribute the SOVs computed from coarser clusters through the existing graph hierarchy, attaching them to corresponding nodes.
    *   Note: Some features non-empty at high resolution may become empty at lower resolution. Features can be leaves at one resolution and intermediate nodes at another.
    *   Store SOVs only at the leaves of *each* resolution level [S1, unofficial].

**Pseudocode:**

class Node:
    def __init__(self, label_signature):
        self.label_signature = label_signature
        self.children = []
        self.sov = None  # Only for leaf nodes
        self.is_leaf = True

class FeatureGraph:
    def __init__(self, num_criteria):
        self.num_criteria = num_criteria
        self.hash_table = {}  # Maps hash_code -> Node
        self.fall_node = None

    def build(self, voxels, labels):
        """
        voxels: list of voxel objects with position and value
        labels: list of boolean vectors, labels[i] is the label vector for voxels[i]
        """
        # Step 1: Clustering
        # Group voxels by their label signature
        clusters = {}
        for i, voxel in enumerate(voxels):
            label_vec = labels[i]
            # Convert boolean vector to a hashable key (e.g., tuple or integer bitmask)
            hash_code = self._compute_hash(label_vec)
            
            if hash_code not in clusters:
                clusters[hash_code] = []
            clusters[hash_code].append(voxel)

        # Step 2: Create Leaf Nodes and SOVs
        leaf_nodes = []
        for hash_code, voxel_list in clusters.items():
            if not voxel_list:
                continue
            
            # Determine label signature from hash_code (inverse of hash or stored in node)
            label_sig = self._decode_hash(hash_code)
            node = Node(label_sig)
            node.sov = voxel_list  # Store as list initially
            node.is_leaf = True
            
            self.hash_table[hash_code] = node
            leaf_nodes.append(node)

        # Step 3: Hierarchy Creation
        # Create ancestors based on shared bits in hash codes
        # This is an iterative process: for each pair of nodes, find common ancestors
        # A simplified approach: group nodes by prefix of their label signature
        self._build_hierarchy(leaf_nodes)

        # Step 4: Create 'fall' node if needed
        # Check if there are disconnected components or nodes without parents
        roots = self._find_roots()
        if len(roots) > 1:
            self.fall_node = Node(None) # Special root

                self.fall_node.children.append(root)
        elif len(roots) == 1:
            self.fall_node = roots[0]
        else:
            self.fall_node = None

        # Step 5: Multiresolution (Simplified)

        # and merging results into the existing graph structure.
        # Not fully implemented here as it requires access to coarser voxel data.

    def _compute_hash(self, label_vec):
        # Example: convert boolean list to integer
        return int("".join(map(str, label_vec)), 2)

    def _decode_hash(self, hash_code):
        # Inverse operation to retrieve label signature
        # This assumes a fixed number of criteria
        return [(hash_code >> i) & 1 for i in range(self.num_criteria)]

    def _build_hierarchy(self, leaf_nodes):
        # Group nodes by their label signature prefixes
        # For each bit position, if two nodes differ, they may share an ancestor
        # This is a simplified recursive grouping
        if not leaf_nodes:
            return
        
        # Group by first bit
        groups = {}
        for node in leaf_nodes:
            # Assuming label_signature is a list of booleans
            key = node.label_signature[0] if node.label_signature else None
            if key not in groups:
                groups[key] = []
            groups[key].append(node)
        
        # Create intermediate nodes if there are multiple groups
        if len(groups) > 1:
            parent = Node(None) # Intermediate node
            for key, child_nodes in groups.items():
                parent.children.extend(child_nodes)
                for child in child_nodes:
                    child.is_leaf = False
            # Recursively build hierarchy for children
            for key, child_nodes in groups.items():
                self._build_hierarchy(child_nodes)
            # Add parent to hash table if it represents a valid feature
            # (i.e., if it covers a non-empty set of voxels)
            # This requires checking if the union of children's SOVs is non-empty
            # For simplicity, we assume all intermediate nodes are valid features
            # In reality, we must check if the feature is non-empty
            pass
        else:
            # All nodes share the same first bit, recurse
            for key, child_nodes in groups.items():
                self._build_hierarchy(child_nodes)

    def _find_roots(self):
        # Find nodes that are not children of any other node
        all_nodes = set(self.hash_table.values())
        children_set = set()
        for node in self.hash_table.values():
            for child in node.children:
                children_set.add(child)
        
        roots = all_nodes - children_set
        return list(roots)

**Parameters:**
*   $n_c$: The number of non-exclusive classification criteria (boolean conditions) [S1, unofficial].
*   `fall`: The entry point node of the graph, representing a feature that includes all features that do not have an ancestor [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Clusters:** The theoretical number of clusters is $2^{n_c}$, but many are empty. The algorithm must handle empty clusters by not creating nodes for them [S1, unofficial].
*   **Multiresolution Consistency:** A feature may be a leaf at one resolution and an intermediate node at another. The storage policy (SOVs only at leaves) must be applied per resolution level [S1, unofficial].
*   **Spatial Ordering:** List-based SOVs do not preserve spatial ordering, making them unsuitable for methods requiring spatial locality (e.g., ray casting with interpolation). Submodel representations (octrees) preserve ordering but may have overlapping bounding boxes [S1, unofficial].

## Subtopics

### View-Aligned Splatting
A rendering technique for Feature Graphs using list-based SOVs. It transforms and inserts voxels in view order to handle the lack of spatial ordering [S1, unofficial].

### Octree Compression
A method to compact homogeneous regions within an SOV using different voxel sizes, represented as octrees. This reduces memory usage for sparse data [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Construction is $O(N)$ for clustering, where $N$ is the number of voxels, assuming hash table operations are $O(1)$. Hierarchy creation depends on the number of features and criteria. Rendering complexity depends on the number of features and the traversal depth.
*   **Memory Complexity:** Proportional to the number of non-empty features and the size of their SOVs. Storing SOVs only at leaves reduces redundancy. Octree compression further reduces memory for homogeneous regions [S1, unofficial].
*   **Performance:** Efficient for focused visualization and multiresolution rendering. Out-of-core traversal is supported due to the hierarchical structure and file-based storage of SOVs [S1, unofficial].
*   **Strengths:** Explicit modeling of feature inclusion; efficient multiresolution support; direct access via hash table; compact storage for sparse data.
*   **Limitations:** Construction can be complex; list-based SOVs lack spatial ordering; requires careful handling of empty clusters and multiresolution consistency [S1, unofficial].
*   **When to Use:** When visualizing complex, multi-label volume data with hierarchical relationships; when multiresolution rendering is required; when memory efficiency for sparse data is critical.
*   **When Not to Use:** When spatial locality is crucial for rendering performance (e.g., standard ray casting); when the number of criteria is very large (leading to many potential features).

## Background
The Feature Graph was introduced in the paper "Splatting multiresolution volume data using the feature graph" [S1, unofficial]. It is designed to address the limitations of flat classification methods by providing a structured representation of voxel data that supports multiresolution and focused visualization. The method is particularly relevant in medical imaging and scientific visualization, where data often has multiple overlapping labels and varying levels of detail [S1, unofficial].
