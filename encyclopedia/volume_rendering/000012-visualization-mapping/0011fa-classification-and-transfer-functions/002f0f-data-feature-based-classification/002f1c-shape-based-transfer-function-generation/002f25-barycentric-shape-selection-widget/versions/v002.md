# Barycentric Shape Selection Widget

Also called: Barycentric Shape Selection, Shape-Selection Widget

## Overview
The Barycentric Shape Selection Widget is a user interface component for shape-based transfer function generation that maps three normalized shape attributes (tubiness, surfaceness, blobbiness) into a 2D equilateral triangle using barycentric coordinates [S1]. It allows users to visually select specific shape classes by placing markers on the triangle, serving as the first stage of classification before intensity-based optical property assignment [S1]. It differs from intensity-only transfer functions by decoupling morphological selection from density selection, and from other shape methods by providing an interactive, geometric selection interface rather than a purely mathematical thresholding approach [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of computed shape segments from a pre-segmented volume. Each segment has three normalized shape classifier values: $T$ (tubiness), $S$ (surfaceness), and $B$ (blobbiness) [S1].
*   **Output:** A set of selected markers on the widget, representing the shape classes chosen for visualization [S1].

**Data Structures:**
*   **Shape Segment:** A data structure containing the normalized scalar values $T, S, B \in [0, 1]$ [S1].
*   **Widget Geometry:** An equilateral triangle defined by three corners representing the pure shape classes: Corner 1 (Tubiness), Corner 2 (Surfaceness), Corner 3 (Blobbiness) [S1].

**Steps:**
1.  **Normalization:** Ensure the shape classifiers $T, S, B$ are normalized to be comparable [S1]. The source implies these are derived from the shape attributes defined in [Shape Attribute](11699-shape-attribute.md).
2.  **Marker Placement:** For each computed shape segment, calculate its position in the triangle using barycentric coordinates defined by $T, S, B$ [S1].
    *   Let the triangle corners be $C_T, C_S, C_B$.
    *   The marker position $P$ is calculated as:
        $$ P = T \cdot C_T + S \cdot C_S + B \cdot C_B $$
    *   The marker is placed closer to the corners corresponding to the shape classes the segment is best classified as [S1].
3.  **User Selection:** The user selects an arbitrary number of markers on the triangle to constrain the shape classes to be visualized [S1]. This constitutes the first stage of classification.
4.  **Intensity Mapping:** For the selected shape classes, use a conventional 1D transfer function to assign optical properties based on intensity values [S1]. This constitutes the second stage.

**Parameters:**
*   **Tubiness Threshold:** Default value 0.8 [S1].
*   **Maximum Inner-Surface-to-Outer-Surface Ratio:** Default value 0.1 [S1].
*   **Maximum Skeleton:** Parameter adjusted during testing, but specific value not given in the sources [S1].

**Edge Cases and Pitfalls:**
*   **Omission of Surfaceness:** If the data set has no planar structures, the surfaceness class can be omitted, collapsing the triangle to a line [S1].

**Pseudocode:**

def place_markers(shape_segments, triangle_corners):
    """
    shape_segments: List of objects with attributes .tubiness, .surfaceness, .blobbiness
    triangle_corners: Tuple of (C_T, C_S, C_B) representing the 2D/3D coordinates of the triangle vertices
    Returns: List of marker positions
    """
    markers = []
    for segment in shape_segments:
        # Barycentric combination
        # Note: The source states markers are placed based on normalized classifiers.
        # Assuming T, S, B are already normalized and sum to 1 or are treated as weights.
        # If they do not sum to 1, normalization step is required.
        # The source says "barycentric coordinates defined by the three normalized shape classifiers"
        # implying T+S+B=1 or they are used as direct weights in a convex combination.
        
        # Calculate position P
        P = (segment.tubiness * triangle_corners[0] +
             segment.surfaceness * triangle_corners[1] +
             segment.blobbiness * triangle_corners[2])
        
        markers.append(P)
    return markers

def select_shape_classes(markers, user_selection_indices):

    markers: List of marker positions
    user_selection_indices: Indices of markers selected by the user
    Returns: Set of selected shape classes (represented by the markers)
    """
    selected = [markers[i] for i in user_selection_indices]
    return selected

## Subtopics

### [Shape Attribute](11699-shape-attribute.md)
Shape Attribute is a data feature-based classification operator that discriminates volumetric objects by analyzing their local geometric structure through three shape aspects: tubiness (cylindrical), surfaceness (planar), and blobbiness (spherical). It is prepared on segmented volumes to enable intuitive transfer function design based on object morphology rather than intensity alone. It differs from intensity-based or size-based transfer functions by focusing on the topological shape of the underlying data features.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** The technique was integrated into the Voreen volume rendering engine [S1]. Pre-segmentation and classification computation took seconds [S1].
*   **Strengths:** Intuitive selection of shape classes; decouples shape from intensity; allows arbitrary number of markers to be selected [S1].
*   **Limitations:** Requires pre-segmentation; relies on normalized shape classifiers; triangle collapses if surfaceness is omitted [S1].
*   **When to Use:** When visualizing data with distinct morphological features (tubular, planar, blob-like) and the user wants to select classes based on shape first, then intensity [S1].
*   **When Not to Use:** When the data lacks planar structures and the triangle collapse is undesirable, or when pre-segmentation is not feasible [S1].

## Background
The method was proposed in the paper "Shape-based Transfer Functions for Volume Visualization" [S1]. It was integrated into the Voreen volume rendering engine [S1]. The widget is similar to the one proposed by Kindlmann and Weinstein [13] for DTI data [S1]. The technique was tested with several synthetic as well as real-world data sets, mostly from the medical domain [S1].
