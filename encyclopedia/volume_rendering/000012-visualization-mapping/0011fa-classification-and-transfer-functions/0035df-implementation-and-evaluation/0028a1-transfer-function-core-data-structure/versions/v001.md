# Transfer Function Core Data Structure

Also called: TransferFunctionCore

## Overview
The Transfer Function Core Data Structure is a concrete implementation of the classification and transfer function mechanism that manages the mapping from scalar volume data to optical properties (color and opacity) [S1, unofficial]. It solves the problem of efficiently storing, updating, and serializing transfer function definitions by maintaining a pre-computed RGBA lookup table and a separate alpha array, driven by control points and Gaussian objects [S1, unofficial]. It sets itself apart from generic shader-based evaluation by using a fixed-resolution table for fast GPU sampling, while allowing dynamic updates via control point manipulation [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scalar data values (implicitly mapped to $[0, 1]$ via normalization), control points for color and opacity, and Gaussian objects for opacity modulation.
*   **Output:** A pre-computed `m_rgbaTable` of size `resolution` containing RGBA values, and an `m_alphaArray` of size `resolution` containing opacity values [S1, unofficial].

**Data Structures:**
The core class maintains the following internal state [S1, unofficial]:
*   `m_rgbaTable`: `std::vector<vec4f>` of size `resolution`. Stores the final RGBA output for each bin.
*   `m_alphaArray`: `std::vector<float>` of size `resolution`. Stores the opacity component, potentially modified by Gaussian objects.
*   `m_colorControls`: `std::vector<ColorControl>`. Sorted by `position`.
*   `m_alphaControls`: `std::vector<AlphaControl>`.
*   `m_gaussianObjects`: `std::vector<GaussianObject>`.

**Struct Layouts:**
*   `vec2f`: `x` (float), `y` (float). Size: `sizeof(vec2f)` [S1, unofficial].
*   `vec3f`: `x` (float), `y` (float), `z` (float). Size: `sizeof(vec3f)` [S1, unofficial].
*   `vec4f`: `x` (float), `y` (float), `z` (float), `w` (float). Size: `sizeof(vec4f)` [S1, unofficial].
*   `ColorControl`: `position` (float), `color` (vec3f). Size must equal `sizeof(vec4f)` [S1, unofficial].
*   `AlphaControl`: `pos` (vec2f). Size must equal `sizeof(vec2f)` [S1, unofficial].
*   `GaussianObject`: `mean` (float), `sigma` (float), `heightFactor` (float), `alphaArray` (std::vector<float>) [S1, unofficial].

**Parameters:**
*   `resolution`: Integer, default 1024. Determines the size of `m_rgbaTable` and `m_alphaArray` [S1, unofficial]. Must be greater than 0 [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Allocate `m_rgbaTable` and `m_alphaArray` of size `resolution` [S1, unofficial].
    *   Clear all control vectors and Gaussian objects [S1, unofficial].
    *   Clear `m_alphaArray` by setting all entries to 0.0f [S1, unofficial].

2.  **Adding Color Control Points:**
    *   When adding a color control point at `pos` with `color` (vec3f):
        *   Create a `ColorControl` with `position = pos` and `color`.
        *   Insert into `m_colorControls` maintaining sorted order by `position` [S1, unofficial].
        *   Call `updateColorMap()` [S1, unofficial].

3.  **Updating Color Map:**
    *   Iterate through each bin index $i$ from 0 to `resolution - 1`.
    *   Calculate normalized position $x = i / (\text{resolution} - 1)$ [S1, unofficial].
    *   Find the two surrounding color controls: `left` (largest position $\le x$) and `right` (smallest position $> x$) [S1, unofficial].
    *   If $x$ is outside the range of controls, clamp to the nearest control's color [S1, unofficial].
    *   Calculate interpolation weight $w = \frac{x - \text{left.position}}{\text{right.position} - \text{left.position}}$ [S1, unofficial].
    *   Interpolate color: $\text{result.color} = \text{mix}(\text{left.color}, \text{right.color}, w)$ [S1, unofficial].
    *   Set `m_rgbaTable[i].rgb` to `result.color` [S1, unofficial].

4.  **Updating Alpha Array:**
    *   Call `updateFromAlphaControls()` [S1, unofficial].
    *   Initialize `m_alphaArray` based on `m_alphaControls` (linear interpolation between control points) [S1, unofficial].
    *   For each `GaussianObject` in `m_gaussianObjects`:
        *   Compute Gaussian contribution for each bin $i$: $G_i = \text{heightFactor} \cdot e^{-\frac{(x - \text{mean})^2}{2 \cdot \text{sigma}^2}}$ where $x = i / (\text{resolution} - 1)$ [S1, unofficial].
        *   Add $G_i$ to `m_alphaArray[i]` [S1, unofficial].
    *   Update `m_rgbaTable[i].a` with the final `m_alphaArray[i]` [S1, unofficial].

5.  **Removal and Clearing:**
    *   Removing a control point or Gaussian object requires removing it from the respective vector and calling `updateColorMap()` [S1, unofficial].
    *   `clear()` resets all internal structures [S1, unofficial].

**Pseudocode:**

```python
class TransferFunctionCore:
    def __init__(self, resolution=1024):
        if resolution <= 0:
            raise ValueError("Resolution must be greater than 0")
        self.resolution = resolution
        self.m_rgba_table = [Vec4f(0, 0, 0, 0) for _ in range(resolution)]
        self.m_alpha_array = [0.0] * resolution
        self.m_color_controls = []  # List of ColorControl
        self.m_alpha_controls = []  # List of AlphaControl
        self.m_gaussian_objects = []  # List of GaussianObject

    def add_color_control(self, position, color):
        control = ColorControl(position, color)
        # Insert maintaining sorted order by position
        self.m_color_controls.append(control)
        self.m_color_controls.sort(key=lambda c: c.position)
        self.update_color_map()

    def update_color_map(self):
        self.update_from_alpha_controls()
        for i in range(self.resolution):
            x = i / (self.resolution - 1)
            color = self._interpolate_color(x)
            self.m_rgba_table[i].r = color.x
            self.m_rgba_table[i].g = color.y
            self.m_rgba_table[i].b = color.z
            self.m_rgba_table[i].a = self.m_alpha_array[i]

    def _interpolate_color(self, x):
        controls = self.m_color_controls
        if not controls:
            return Vec3f(0, 0, 0)
        
        # Find surrounding controls
        left = None
        right = None
        for i in range(len(controls)):
            if controls[i].position <= x:
                left = controls[i]
            else:
                right = controls[i]
                break
        
        if left is None:
            return right.color
        if right is None:
            return left.color
        
        # Linear interpolation
        w = (x - left.position) / (right.position - left.position)
        return mix(left.color, right.color, w)

    def update_from_alpha_controls(self):
        # Initialize alpha array from alpha controls (linear interpolation)
        # [G] Implementation details for alpha control interpolation are not fully specified in sources
        # Assuming linear interpolation between AlphaControl.pos.x (value) and AlphaControl.pos.y (opacity)
        # If no controls, default to 0
        if not self.m_alpha_controls:
            self.m_alpha_array = [0.0] * self.resolution
            return
        
        # Sort controls by position
        sorted_controls = sorted(self.m_alpha_controls, key=lambda c: c.pos.x)
        
        for i in range(self.resolution):
            x = i / (self.resolution - 1)
            alpha = self._interpolate_alpha(x, sorted_controls)
            self.m_alpha_array[i] = alpha
        
        # Apply Gaussian objects
        for gauss in self.m_gaussian_objects:
            for i in range(self.resolution):
                x = i / (self.resolution - 1)
                exponent = -((x - gauss.mean) ** 2) / (2 * gauss.sigma ** 2)
                gaussian_val = gauss.height_factor * math.exp(exponent)
                self.m_alpha_array[i] += gaussian_val

    def _interpolate_alpha(self, x, controls):
        if not controls:
            return 0.0
        left = None
        right = None
        for i in range(len(controls)):
            if controls[i].pos.x <= x:
                left = controls[i]
            else:
                right = controls[i]
                break
        
        if left is None:
            return right.pos.y
        if right is None:
            return left.pos.y
        
        w = (x - left.pos.x) / (right.pos.x - left.pos.x)
        return mix(left.pos.y, right.pos.y, w)

class Vec2f:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class Vec3f:
    def __init__(self, x, y, z):
        self.x = x
        self.y = y
        self.z = z

class Vec4f:
    def __init__(self, r, g, b, a):
        self.r = r
        self.g = g
        self.b = b
        self.a = a

class ColorControl:
    def __init__(self, position, color):
        self.position = position
        self.color = color

class AlphaControl:
    def __init__(self, pos):
        self.pos = pos

class GaussianObject:
    def __init__(self, mean, sigma, height_factor):
        self.mean = mean
        self.sigma = sigma
        self.height_factor = height_factor
        self.alpha_array = [] # Populated during update

def mix(a, b, w):
    return a + (b - a) * w
```

## Subtopics

### Transfer Function Serialization
Serializes and deserializes a transfer function to/from JSON format [S1, unofficial]. It stores the resolution, base64-encoded alpha array, color controls, opacity controls, and Gaussian objects [S1, unofficial]. The JSON structure is: `{"resolution": int, "alphaArray": {"encoding": "BASE64", "data": string}, "colorControls": [{"position": float, "color": vec3f}], "opacityControl": [{"position": vec2f}], "gaussianObjects": [{"mean": float, "sigma": float, "heightFactor": float}]}` [S1, unofficial]. Pitfall: Missing JSON keys are silently skipped. If 'position' or 'color' is missing in colorControls, the control is skipped. If 'mean', 'sigma', or 'heightFactor' is missing in gaussianObjects, it is skipped [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Initialization is $O(\text{resolution})$. Adding/removing control points is $O(N \log N)$ for sorting and $O(\text{resolution})$ for updating the map, where $N$ is the number of controls. Serialization is $O(\text{resolution})$ due to base64 encoding.
*   **Memory Complexity:** $O(\text{resolution})$ for the RGBA table and alpha array. Additional $O(N)$ for control points and Gaussian objects.
*   **Performance:** Fast GPU sampling due to pre-computed LUT. Dynamic updates require CPU-side recomputation of the table.
*   **Strengths:** Efficient for real-time rendering; supports complex opacity modulation via Gaussians; easy serialization.
*   **Limitations:** Fixed resolution limits precision; CPU-side update cost for frequent changes; no support for multi-dimensional transfer functions directly in the core structure.
*   **When to use:** When a fixed-resolution LUT is acceptable and dynamic control point manipulation is needed.
*   **When not to use:** When high-precision, resolution-independent evaluation is required, or for multi-dimensional transfer functions.

## Background
The Transfer Function Core Data Structure is part of the OSPRay sample applications and related modules, specifically designed to convert and manage ParaView transfer function formats [S1, unofficial]. It provides a standardized way to handle color and opacity control points and Gaussian objects for volume rendering [S1, unofficial].
