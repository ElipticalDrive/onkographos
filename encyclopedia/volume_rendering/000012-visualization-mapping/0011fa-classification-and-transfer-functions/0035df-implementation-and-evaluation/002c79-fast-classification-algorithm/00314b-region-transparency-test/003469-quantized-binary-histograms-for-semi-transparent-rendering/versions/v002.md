# Quantized Binary Histograms for Semi-Transparent Rendering

Also called: Brick Histogram Transparency Check, Histogram-based Space Leaping, Quantized Binary Histograms

## Overview
Quantized Binary Histograms is a pre-processing technique used to determine if a spatial region (brick) in a volume dataset is fully transparent, enabling space leaping to skip rendering of empty regions [S1][S2, unofficial]. It builds on [Region Transparency Test](6496-region-transparency-test.md) by using conservative quantized binary histograms of voxel and opacity values, ensuring that a transparent region is never falsely classified as opaque, although an opaque region may be conservatively classified as transparent [S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A volume brick, a transfer function mapping voxel values to opacity, and the bit-depth of the voxel data [S1].
*   **Output:** A boolean flag indicating if the brick is fully transparent [S1].

**Data Structures**
Two histograms are built per brick:
1.  **Voxel Value Histogram:** A binary list of size $s$, where $s$ is the range of possible voxel values (e.g., $s=255$ for 8-bit data) [S1][S2, unofficial].
2.  **Opacity Histogram:** A binary list of size $s$, corresponding to the opacity values derived from the transfer function for each possible voxel value [S1].

Both histograms are quantized into buckets of size $B=32$ to save memory and increase lookup efficiency [S1][S2, unofficial].

**Steps**
1.  **Pre-processing (Histogram Construction):**
    For each brick in the volume:
    a. Initialize two binary arrays, $H_{\text{voxel}}$ and $H_{\text{opacity}}$, of size $s$, with all elements set to 0 [S1].
    b. Iterate over every voxel $v$ in the brick [S1].
    c. Set $H_{\text{voxel}}[v] = 1$ [S1].
    d. Compute the opacity $o$ for voxel value $v$ using the transfer function [S1].
    e. Set $H_{\text{opacity}}[o] = 1$ [S1].
    f. Quantize both histograms into buckets of size $B=32$ [S1]. For each array $H$, create a bucketed array $H_{\text{bucket}}$ where $H_{\text{bucket}}[i] = 1$ if any element in the range $[i \cdot B, (i+1) \cdot B - 1]$ is 1, otherwise 0 [G].

2.  **Transparency Test:**
    To determine if a brick is fully transparent:
    a. Iterate over all buckets in $H_{\text{voxel\_bucket}}$ [S1].
    b. For each bucket index $i$ where $H_{\text{voxel\_bucket}}[i] == 1$:
        i. Check the corresponding range in $H_{\text{opacity\_bucket}}$ [S1].
        ii. If any opacity value in the range is non-zero (i.e., $H_{\text{opacity\_bucket}}[i] == 1$), the brick contains potentially opaque data [S1].
    c. If all buckets in $H_{\text{voxel\_bucket}}$ that have active voxel values correspond to zero opacity in $H_{\text{opacity\_bucket}}$, the brick is fully transparent [S1]. Otherwise, it is not fully transparent [S1].

**Pseudocode**
```python
def build_histograms(brick_voxels, transfer_function, s=255, bucket_size=32):
    """
    Builds quantized binary histograms for a brick.
    :param brick_voxels: List of voxel values in the brick.
    :param transfer_function: Function mapping voxel value to opacity.
    :param s: Range of voxel values (e.g., 255 for 8-bit).
    :param bucket_size: Size of quantization buckets.
    :return: Tuple of (voxel_bucket, opacity_bucket)
    """
    h_voxel = [0] * s
    h_opacity = [0] * s
    for v in brick_voxels:
        h_voxel[v] = 1
        opacity = transfer_function(v)
        opacity_idx = int(opacity * (s - 1))  # [G]
        if 0 <= opacity_idx < s:
            h_opacity[opacity_idx] = 1
    num_buckets = (s + bucket_size - 1) // bucket_size
    voxel_bucket = [0] * num_buckets
    opacity_bucket = [0] * num_buckets
    for i in range(num_buckets):
        start = i * bucket_size
        end = min(start + bucket_size, s)
        for j in range(start, end):
            if h_voxel[j] == 1:
                voxel_bucket[i] = 1
                break
        for j in range(start, end):
            if h_opacity[j] == 1:
                opacity_bucket[i] = 1
                break
    return voxel_bucket, opacity_bucket

def is_brick_transparent(voxel_bucket, opacity_bucket):
    """
    Determines if a brick is fully transparent based on histograms.
    Conservative: Transparent region can be classified as opaque, but not vice versa.
    """
    for i in range(len(voxel_bucket)):
        if voxel_bucket[i] == 1 and opacity_bucket[i] == 1:
            return False
    return True
```

**Parameters**
*   $s$: Range of voxel values. Typical value: 255 for 8-bit data [S1][S2, unofficial].
*   Bucket size: Typical value: 32 [S1][S2, unofficial].

**Edge Cases and Pitfalls**
*   **Conservatism:** The method is conservative. A transparent region might be classified as opaque due to bucket quantization (if a bucket contains both transparent and opaque voxel values, the whole bucket is marked opaque). However, an opaque region is never falsely classified as transparent [S2, unofficial].
*   **Quantization Error:** Larger bucket sizes reduce memory but increase false positives (classifying opaque bricks as transparent is impossible, but transparent bricks might be classified as opaque if the bucket mixes values) [S1][S2, unofficial].
*   **Transfer Function Mapping:** The opacity histogram must correctly map the transfer function's output to the histogram indices [S1].

## Operating characteristics
*   **Time Complexity:** Pre-processing requires iterating over all voxels in the brick, yielding $O(N)$ per brick [G]. The transparency test iterates over all buckets, yielding $O(s/B)$ per brick [G].
*   **Memory Complexity:** $O(s)$ per brick for the histograms, reduced by a factor of $B$ due to quantization [S1].
*   **Strengths:** Simple to implement, low memory overhead compared to full spatial hierarchies, conservative (no false negatives for opacity) [S1][S2, unofficial].
*   **Limitations:** Conservative nature may lead to skipping fewer regions than min-max approaches if quantization is coarse [S2, unofficial].
*   **When to use:** Pre-classification volume rendering where space leaping is beneficial and memory is constrained [S1][S2, unofficial].
*   **When not to use:** Not given in the sources.

## Background
Quantized Binary Histograms were proposed by Grimm et al. in 2004 [S2, unofficial] as a solution to false transparent/opaque classification errors in pre-classification volume rendering. The technique exploits coherence in brute-force ray casting applications, similar to space leaping techniques proposed by Sarang et al. [S1][S2, unofficial]. It is used in interactive volume rendering to accelerate ray casting by skipping empty regions [S1].
