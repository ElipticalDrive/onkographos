# Real-time transfer function evaluation

Also called: Engel, Kraus & Ertl Technique, Post-classification approach, Pre-computed Transfer Function (Post-classification), Texture-based volume rendering with GPU illumination

## Overview
This method enables real-time modification of volume classification by pre-computing transfer function results and storing them in 2D textures, allowing the GPU to classify voxels and compute primary color and opacity instantly [S1]. It distinguishes itself from CPU-based illumination approaches by performing dynamic lighting calculations on the GPU using fragment programs, thereby supporting interactive lighting changes [S2, unofficial].

## How it works
**Inputs:**
*   Volume dataset containing scalar values [S1].
*   Transfer function definition mapping scalar values to color and opacity [S1].
*   Lighting parameters including view vector, light positions, and material properties [S2, unofficial].

**Outputs:**
*   Rendered image with dynamic illumination [S2, unofficial].

**Data Structures:**
1.  **2D Texture (Transfer Function Lookup):** Stores the result of the transfer function evaluated for a range of input scalar values [S2, unofficial]. Each texel contains the pre-computed primary color (RGB) and opacity (A) [S1].
2.  **Compressed RGB Texture (Gradients):** Stores the pre-calculated gradient vectors for each volume element, compressed into an RGB texture format [S2, unofficial].
3.  **3D Texture (Classification - Variant Specific):** In the PCbTF variant, the classification of each voxel is stored as a 3D texture in the frame buffer [S3].
4.  **3D RGB Texture (User Picked Colors - Variant Specific):** Stores colors and opacities picked by the user in the PCbTF variant [S3].

**Steps:**
1.  **Pre-calculate Gradients:** Compute the gradient vector for every voxel in the volume dataset and compress these gradients into a compressed RGB texture format [S2, unofficial].
2.  **Evaluate Transfer Function:** Evaluate the transfer function for the entire range of possible input scalar values and store these results in a 2D texture [S2, unofficial].
3.  **Initialize Rendering:** Load the volume data, the 2D transfer function texture, and the compressed gradient texture into GPU memory [S2, unofficial].
4.  **Fragment Program Execution:** For each pixel or sample in the ray casting process: sample the volume data to get the scalar value $v$, use $v$ to index into the 2D transfer function texture to retrieve the primary color $C_{prim}$ and opacity $\alpha$, sample the compressed gradient texture to retrieve the gradient vector $\mathbf{g}$, and calculate the final color value using a fragment program [S2, unofficial].
5.  **Composite:** Accumulate the final color and opacity along the ray using standard volume rendering integration [S1].

**Pseudocode:**
```python
# Standard math helpers
def dot(v1, v2): return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]
def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/mag, v[1]/mag, v[2]/mag) if mag > 0 else (0, 0, 0)

# Pre-processing
def precompute_gradients(volume_data):
    width, height, depth = len(volume_data), len(volume_data[0]), len(volume_data[0][0])
    gradient_texture = [[[None]*depth for _ in range(height)] for _ in range(width)]
    for x in range(width):
        for y in range(height):
            for z in range(depth):
                gx = (volume_data[x+1][y][z] - volume_data[x-1][y][z]) / 2.0 if 0 < x < width-1 else 0.0
                gy = (volume_data[x][y+1][z] - volume_data[x][y-1][z]) / 2.0 if 0 < y < height-1 else 0.0
                gz = (volume_data[x][y][z+1] - volume_data[x][y][z-1]) / 2.0 if 0 < z < depth-1 else 0.0
                gradient_texture[x][y][z] = (gx, gy, gz)
    return gradient_texture

def precompute_transfer_function(tf_function, min_val, max_val):
    width = int(max_val - min_val)
    height = 1
    tf_texture = [[None]*width for _ in range(height)]
    for i in range(width):
        value = min_val + i
        color, opacity = tf_function(value)
        tf_texture[0][i] = (color.r, color.g, color.b, opacity)
    return tf_texture, min_val, max_val

# Rendering
def render_fragment(scalar_value, gradient, view_vector, light_positions, material, tf_texture, min_val, max_val):
    tf_x = int((scalar_value - min_val) / (max_val - min_val) * (len(tf_texture[0]) - 1))
    primary_color, opacity = tf_texture[0][tf_x]
    normal = normalize(gradient)
    total_diffuse = 0.0
    total_specular = 0.0
    for light in light_positions:
        light_direction = normalize(light.position - sample_position)
        diffuse_factor = max(dot(normal, light_direction), 0.0)
        total_diffuse += diffuse_factor * material.diffuse
        reflection = 2.0 * dot(normal, light_direction) * normal - light_direction
        specular_factor = pow(max(dot(reflection, view_vector), 0.0), material.shininess)
        total_specular += specular_factor * material.specular
    final_color = primary_color * (material.ambient + total_diffuse) + total_specular * material.specular_color
    return final_color, opacity
```

**Parameters:**
*   **Gradient Storage:** Compressed into an RGB texture format [S2, unofficial].
*   **Illumination:** Dynamic, performed on the GPU using Cg [S2, unofficial].
*   **Hardware (PCbTF Variant):** Intel Xeon CPU 3.60GHz, 3GB memory, Nvidia GeForce GTX 285 graphic card [S3].
*   **Software Libraries (PCbTF Variant):** OpenGL and FLTK for interface, Cg for rendering [S3].

**Edge Cases and Pitfalls:**
*   **Reproducibility:** The original work's results could not be reproduced because the plane reduction optimization was not implemented due to the complexity of their approximation towards two-texture interpolation [S2, unofficial].
*   **Precision:** Compressing gradients into RGB textures may introduce quantization errors, affecting lighting accuracy [G].
*   **Boundary Conditions:** Gradient calculation at volume boundaries requires careful handling (e.g., clamping, mirroring) to avoid artifacts [G].

## Subtopics

### [List-based Pre-classification](1930-list-based-pre-classification.md)
List-based pre-classification is an optimization for interactive transfer function changes in volume rendering that avoids rebuilding index buffers on the CPU by pre-sorting voxel indices into iso-value buckets, allowing fast pointer merging. Unlike naive pre-classification which requires rebuilding and reloading the index buffer on every transfer function change (causing CPU-GPU bandwidth bottlenecks), this method uses pre-sorted buffers and pointer merging for interactive rates.

### GPU-Accelerated Volume Rendering with PCbTF
A rendering implementation that accelerates volume rendering and transfer function specification using graphics hardware, treating TF design as a mapping from nD vectors to color and opacity values [S3]. It stores the classification of each voxel as a 3D texture in the frame buffer and recomputes/redraws the new texture on the screen via the GPU whenever the Transfer Function changes [S3]. It calculates a separate 3D RGB texture to store the colors and opacities picked by the user [S3].

## Operating characteristics
*   **Performance:** Achieves 4 to 6 frames per second with GPU-based illumination and shading [S2, unofficial].
*   **Complexity:** Time complexity is dominated by the ray casting and fragment program execution per frame [S2, unofficial]. Pre-computation of gradients and TF evaluation is done once or when parameters change significantly [G].
*   **Memory:** Requires storage for the volume data, 2D TF texture, compressed gradient texture, and potentially 3D classification/color textures in variants [G].
*   **Strengths:** Enables dynamic lighting and real-time TF modification, which is not possible with pre-computed CPU illumination [S2, unofficial].
*   **Limitations:** Performance is limited by GPU fill rate and fragment program complexity [G]. The original plane reduction optimization was not implemented, potentially impacting performance on large volumes [S2, unofficial].
*   **When to Use:** When interactive lighting changes and real-time TF adjustment are required [G].
*   **When Not to Use:** When maximum image quality is prioritized over speed, or when hardware does not support the required GPU features (e.g., Cg, 3D textures) [G].

## Background
The technique was proposed by Engel, Kraus, and Ertl [S2, unofficial]. It is discussed in the context of texture mapping-based volume rendering [S2, unofficial]. The approach leverages the computational power of modern graphics cards to perform illumination and shading on the GPU, contrasting with earlier methods that calculated illumination on the CPU [S2, unofficial]. The PCbTF variant was implemented to accelerate volume rendering and TF specification using graphics hardware [S3].
