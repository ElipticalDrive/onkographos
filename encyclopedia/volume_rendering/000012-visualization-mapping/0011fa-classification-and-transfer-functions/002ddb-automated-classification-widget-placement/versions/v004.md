# Automated Classification Widget Placement

Also called: Automated Widget Placement

## Overview
Automated Classification Widget Placement is an interaction technique that positions and sizes classification widgets in the transfer-function domain based on data probe feedback and reprojected voxel distributions [S1, book][S2]. It solves the difficulty of manually creating effective higher-dimensional transfer functions by tying widget geometry to the statistical distribution of data at a specific probe location [S1, book][S2]. Unlike manual placement methods, it reduces user effort by automatically determining widget bounds from local data variance [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A data probe location in the volume, defined by a tip position $\mathbf{p}$ and a slider value $s$. The probe queries the volume to obtain scalar values and gradient information.
*   **Output:** The position $(x_w, y_w)$ and dimensions $(w_w, h_w)$ of a classification widget (rectangular or triangular) in the transfer-function domain.

**Data Structures:**
The method relies on the **Data Probe** structure, which contains:
*   `tip`: 3D position $\mathbf{p}$ in the volume.
*   `slider`: Scalar value $s$ representing the current probe setting.
*   `reprojected_voxels`: A set of voxel locations $\{\mathbf{v}_i\}$ that map to the probe's current query state.

**Steps:**
1.  **Query Probe:** Determine the transfer function values at the probe's tip. Let $v_{tip}$ be the scalar value and $\mathbf{g}_{tip}$ be the gradient magnitude or other derived feature at $\mathbf{p}$ [S1, book][S2].
2.  **Reproject Voxels:** Identify the set of voxels $\{\mathbf{v}_i\}$ that are "reprojected" to the current probe state. This involves mapping volume data to the multi-dimensional transfer function domain based on the probe's location [S1, book][S2].
3.  **Calculate Variance:** Compute the horizontal variance $\sigma_h^2$ and vertical variance $\sigma_v^2$ of the reprojected voxel locations in the transfer-function domain [S1, book][S2].
    *   Horizontal variance $\sigma_h^2$ corresponds to the variance in the primary data dimension (e.g., scalar value).
    *   Vertical variance $\sigma_v^2$ corresponds to the variance in the secondary dimension (e.g., gradient magnitude) [S1, book][S2].
4.  **Place Widget:**
    *   **Rectangular Widget:**
        *   Center: $(x_c, y_c) = (v_{tip}, g_{tip})$ [S1, book][S2].
        *   Size: The width and height are controlled by the data probe's slider $s$. The sources do not specify the exact formula linking $s$ to dimensions, stating only that the size is "controlled by" the slider [S1, book][S2].
    *   **Triangular Widget:**
        *   Horizontal Position: $x_w = v_{tip}$ [S1, book][S2].
        *   Width: $w_w = k_h \cdot \sigma_h$, where $k_h$ is a scaling factor (Not given in the sources).
        *   Height: $h_w = k_v \cdot \sigma_v$, where $k_v$ is a scaling factor (Not given in the sources).
        *   The width and height are determined by the horizontal and vertical variance in the reprojected voxel locations [S1, book][S2].

**Pseudocode:**
```python
def place_widget(probe, widget_type):
    # Query the volume at the probe tip
    v_tip = probe.query_scalar(probe.tip)
    g_tip = probe.query_gradient_magnitude(probe.tip)
    
    # Get reprojected voxels based on probe location
    voxels = probe.get_reprojected_voxels()
    
    if widget_type == "rectangular":
        # Center at interpolated transfer function values
        center_x = v_tip
        center_y = g_tip
        
        # Size controlled by slider (exact mapping not specified)
        width = probe.slider * scale_factor_horizontal
        height = probe.slider * scale_factor_vertical
        
        return {
            "type": "rectangular",
            "center": (center_x, center_y),
            "size": (width, height)
        }
        
    elif widget_type == "triangular":
        # Horizontal position at data value queried by probe
        x_pos = v_tip
        
        # Calculate variance of reprojected voxels
        # Horizontal variance (scalar dimension)
        scalar_values = [v.scalar for v in voxels]
        mean_scalar = sum(scalar_values) / len(scalar_values)
        var_h = sum((s - mean_scalar)**2 for s in scalar_values) / len(scalar_values)
        
        # Vertical variance (gradient/feature dimension)
        grad_values = [v.gradient for v in voxels]
        mean_grad = sum(grad_values) / len(grad_values)
        var_v = sum((g - mean_grad)**2 for g in grad_values) / len(grad_values)
        
        # Width and height determined by variance
        # Scaling factors k_h and k_v are not specified in sources
        width = math.sqrt(var_h) * k_h
        height = math.sqrt(var_v) * k_v
        
        return {
            "type": "triangular",
            "position": (x_pos, 0), # Vertical position not specified
            "dimensions": (width, height)
        }
```

**Edge Cases:**
*   **Zero Variance:** If all reprojected voxels have identical values, variance is zero, resulting in a degenerate widget. A minimum size guard is required [G].
*   **Empty Probe:** If no voxels are reprojected, variance cannot be computed. The widget should default to a standard size or remain hidden [G].

## Subtopics

### Position-dependent Transfer Function Customization
Allows widgets to change based on spatial location, whereas automated placement focuses on statistical distribution [5287-position-dependent-transfer-function-customization.md].

Uses freehand drawing for placement, contrasting with the algorithmic placement of this method [5943-sketch-based-transfer-function-editing.md].

### Image-based TF Design
Derives transfer functions from reference images, whereas automated placement uses internal volume statistics [7807-image-based-tf-design.md].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of reprojected voxels, as variance calculation requires a single pass over the voxel set [S1, book][S2].
*   **Memory Complexity:** $O(N)$ to store the reprojected voxel data [S1, book][S2].
*   **Strengths:** Reduces manual effort in creating multi-dimensional transfer functions; adapts to local data characteristics [S1, book][S2].
*   **Limitations:** Relies on the accuracy of the data probe and reprojected voxel set; may produce overly broad or narrow widgets if variance is high or low [S1, book][S2].
*   **When to Use:** When exploring complex multi-dimensional transfer functions and manual tuning is tedious [S1, book].
*   **When Not to Use:** When precise, artist-driven control is required over widget boundaries [S1, book].

## Background
The method was introduced in the context of multi-dimensional transfer functions for volume rendering [S1, book]. It addresses the complexity of higher-dimensional transfer functions by automating widget placement based on probe feedback [S1, book][S2]. The technique is part of a broader set of interaction widgets including shading and color-picker widgets [S1, book][S2].
