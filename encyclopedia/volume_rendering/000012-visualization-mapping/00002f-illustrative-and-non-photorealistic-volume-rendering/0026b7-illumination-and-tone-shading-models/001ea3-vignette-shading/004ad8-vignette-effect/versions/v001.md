# Vignette Effect
Also called: Post-processing Vignette, Vignetting Post-Processing

## Overview
The Vignette Effect darkens the corners and edges of a rendered image relative to the center, simulating optical lens falloff or drawing attention to the focal point [S1, unofficial]. It is applied as a post-processing step to the final color buffer, distinct from volumetric illumination models like [Vignette Shading](1830-vignette-shading.md) which modulate lighting based on ray alignment within the volume.

## How it works
**Inputs and Outputs**
- Input: Final rendered color buffer (RGB or RGBA), image dimensions ($W \times H$).
- Output: Vignette-modified color buffer.

**Data Structures**
- UV Coordinates: Normalized coordinates $(u, v)$ where $u \in [0, 1]$ and $v \in [0, 1]$, representing the pixel's position in the image plane.

**Steps**
1. For each pixel, calculate normalized UV coordinates:
   $$ u = \frac{x}{W}, \quad v = \frac{y}{H} $$
   where $x$ and $y$ are pixel coordinates.
2. Compute the vignette factor. Two common formulations exist in the sources:

   *Formulation A (Polynomial/Root-based) [S1, unofficial]:*
   $$ \text{vignette\_factor} = 0.5 + 0.5 \cdot \left( 16 \cdot u \cdot v \cdot (1-u) \cdot (1-v) \right)^{0.25} $$
   The final color is multiplied by this factor.

   *Formulation B (Power-based with Fringe) [S2, unofficial]:*
   Let $pos_{2d}$ be the 2D position vector from the image center, and $fr$ be a fringe radius parameter.
   $$ \text{vignetting} = \min\left(\frac{\|pos_{2d}\|}{fr}, 1.0\right) $$
   $$ \text{vignetting} = \left( 1.0 - \text{vignetting}^2 \right)^{20.0} $$
   The color is mixed with a background color weighted by this factor:
   $$ \text{color}_{out} = \text{mix}(\text{vignetting\_background} \cdot \text{color}_w, \text{color}_{xyz}, \text{vignetting}) $$
   where $\text{color}_w$ is the alpha channel and $\text{color}_{xyz}$ is the RGB channels.

**Parameters**
- $fr$: Fringe radius. Not given in the sources for Formulation A. For Formulation B, typical values are not specified, but it controls the onset of the darkening.
- Exponent (20.0 in Formulation B): Controls the steepness of the vignette. Not given in the sources for Formulation A.

**Edge Cases and Pitfalls**
- Precision: The term $u \cdot v \cdot (1-u) \cdot (1-v)$ in Formulation A is zero at the edges and center, potentially causing floating-point underflow or exact zero results if not handled, though the root operation is stable.
- Boundaries: Formulation A naturally goes to 0.5 at the corners (since $u,v \to 0$ or $1$), while Formulation B can go to 0 depending on the exponent and $fr$.
- Degenerate Input: If $W$ or $H$ is 0, UV calculation fails. [G] Ensure $W, H > 0$.

**Pseudocode**
```python
def apply_vignette_uv(color_buffer, width, height, vignette_background=(0,0,0)):
    """
    Applies vignette effect using Formulation A [S1, unofficial] and Formulation B [S2, unofficial].
    color_buffer: Nx3 or Nx4 array of floats [0,1].
    Returns: Modified color buffer.
    """
    h, w, c = color_buffer.shape
    # Generate UV coordinates
    u = np.arange(w) / width
    v = np.arange(h) / height
    U, V = np.meshgrid(u, v)
    
    # Formulation A [S1, unofficial]
    # Term inside root: 16 * u * v * (1-u) * (1-v)
    term_a = 16.0 * U * V * (1.0 - U) * (1.0 - V)
    # Clamp to avoid negative due to precision
    term_a = np.maximum(term_a, 0.0)
    vignette_factor_a = 0.5 + 0.5 * np.power(term_a, 0.25)
    
    # Apply Formulation A
    result_a = color_buffer * vignette_factor_a[:, :, np.newaxis]
    
    # Formulation B [S2, unofficial]
    # Center coordinates
    cx, cy = width / 2.0, height / 2.0
    # 2D position from center
    pos_x = (np.arange(w) - cx) / width  # Normalize by width for consistency? Source uses image_coords directly.
    pos_y = (np.arange(h) - cy) / height
    PX, PY = np.meshgrid(pos_x, pos_y)
    pos_2d = np.sqrt(PX**2 + PY**2)
    
    # Fringe radius. Not given in sources. Using 1.0 as normalized max distance approx.
    fr = 1.0 
    vignetting = np.minimum(pos_2d / fr, 1.0)
    vignetting = np.power(1.0 - np.power(vignetting, 2.0), 20.0)
    
    # Mix with background
    # Assuming RGBA input for alpha handling
    if c == 4:
        alpha = color_buffer[:, :, 3]
        rgb = color_buffer[:, :, :3]
        bg_rgb = vignette_background
        # mix(bg * alpha, rgb, vignetting)
        # Note: Source mixes vignetting_background * color.w with color.xyz
        mixed_rgb = np.where(
            vignetting[:, :, np.newaxis] > 0.5, # Simple threshold for mix? No, mix is linear.
            bg_rgb * alpha[:, :, np.newaxis],
            rgb
        )
        # Correct linear mix:
        vignetting_expanded = vignetting[:, :, np.newaxis]
        result_b_rgb = vignetting_expanded * (vignette_background * alpha[:, :, np.newaxis]) + (1.0 - vignetting_expanded) * rgb
        result_b = np.concatenate([result_b_rgb, alpha[:, :, np.newaxis]], axis=2)
    else:
        # If no alpha, just multiply? Source implies alpha usage.
        # Fallback to simple multiplication if alpha not present, though source specifies mix.
        result_b = color_buffer * vignetting[:, :, np.newaxis]
        
    return result_a, result_b

def apply_vignette_simple(color_buffer, width, height):
    """
    Simplified implementation of Formulation A [S1, unofficial].
    """
    h, w, c = color_buffer.shape
    u = np.arange(w) / width
    v = np.arange(h) / height
    U, V = np.meshgrid(u, v)
    
    term = 16.0 * U * V * (1.0 - U) * (1.0 - V)
    term = np.maximum(term, 0.0)
    factor = 0.5 + 0.5 * np.power(term, 0.25)
    
    return color_buffer * factor[:, :, np.newaxis]
```

## Operating characteristics
- Time Complexity: $O(W \cdot H)$ per frame, as it requires a single pass over all pixels.
- Memory Complexity: $O(W \cdot H)$ for the output buffer.
- Strengths: Computationally inexpensive; easily implemented as a post-process; effective for artistic stylization.
- Limitations: Does not account for 3D scene geometry or depth; purely 2D effect.
- When to use: When a quick artistic darkening of edges is desired without modifying the rendering pipeline or lighting models.
- When not to use: When physically accurate lens simulation is required (requires more complex optical models) or when the effect needs to interact with volumetric density.

## Background
The vignette effect is a common post-processing technique in computer graphics and photography. The specific polynomial formulation using $16 \cdot u \cdot v \cdot (1-u) \cdot (1-v)$ is cited from [S1, unofficial]. The power-based formulation with a fringe radius is cited from [S2, unofficial].
