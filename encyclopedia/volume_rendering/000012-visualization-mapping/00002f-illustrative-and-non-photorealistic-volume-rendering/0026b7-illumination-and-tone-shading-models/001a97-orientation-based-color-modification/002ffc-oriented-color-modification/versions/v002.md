# Oriented Color Modification


## Overview
Oriented Color Modification is a technique that adjusts the color value (brightness) of volume samples based on the orientation of the surface gradient relative to the viewer, simulating illustrative "oriented fading" [S1]. It sets itself apart from general illumination models by operating directly in the HSV color space to decouple brightness from hue and saturation, allowing for painterly effects where facing surfaces remain bright and edge-on surfaces fade [S1].

## How it works
**Inputs:**
*   Volume sample color $C$ in RGB [S1].
*   Volume sample opacity $\alpha$ [S1].
*   Gradient vector $\mathbf{g}$ at the sample point [S1].
*   View direction vector $\mathbf{v}$ (typically from sample to camera) [G].

**Outputs:**
*   Modified color $C'$ and opacity $\alpha'$ [S1].

**Data Structures:**
*   Vectors $\mathbf{g}$ and $\mathbf{v}$ are 3D floating-point vectors [G].
*   Color is converted to HSV space for modification [S1].

**Steps:**
1.  Compute the angle $\theta$ between the gradient $\mathbf{g}$ and the view direction $\mathbf{v}$ [S1].
    $$ \cos \theta = \frac{\mathbf{g} \cdot \mathbf{v}}{\|\mathbf{g}\| \|\mathbf{v}\|} $$
2.  Convert the sample color from RGB to HSV [S1]. Let the value component be $V$ [S1].
3.  Decrease $V$ as $\theta$ increases (i.e., as the surface becomes more edge-on to the viewer) [S1]. The exact mapping function is not specified in the primary source, but the trend is monotonic decrease with increasing angle [S1].
4.  Convert the modified HSV color back to RGB to obtain $C'$ [S1].
5.  (Optional/Variant) Modulate opacity $\alpha$ based on the same or similar orientation metrics [S2, unofficial].

**Pseudocode:**
```python
def oriented_color_modification(rgb_color, gradient, view_direction):
    # Normalize vectors
    g_len = (gradient[0]**2 + gradient[1]**2 + gradient[2]**2)**0.5
    v_len = (view_direction[0]**2 + view_direction[1]**2 + view_direction[2]**2)**0.5
    g_norm = (gradient[0]/g_len, gradient[1]/g_len, gradient[2]/g_len)
    v_norm = (view_direction[0]/v_len, view_direction[1]/v_len, view_direction[2]/v_len)
    
    # Calculate cosine of the angle between gradient and view
    cos_theta = g_norm[0]*v_norm[0] + g_norm[1]*v_norm[1] + g_norm[2]*v_norm[2]
    
    # Convert RGB to HSV [G]
    hsv_color = rgb_to_hsv(rgb_color)
    h, s, v = hsv_color
    
    # Decrease value V as angle increases (cos_theta decreases)
    # Note: Exact formula for V' vs theta is not provided in [S1]
    # [G] Assuming a linear fade for implementation completeness:
    v_modified = v * (0.5 + 0.5 * cos_theta) 
    
    # Clamp value to [0, 1]
    v_modified = max(0.0, min(1.0, v_modified))
    
    # Convert back to RGB [G]
    new_rgb = hsv_to_rgb((h, s, v_modified))
    
    return new_rgb

def rgb_to_hsv(rgb):
    # [G] Standard RGB to HSV conversion
    r, g, b = rgb[0]/255.0, rgb[1]/255.0, rgb[2]/255.0
    cmax = max(r, g, b)
    cmin = min(r, g, b)
    delta = cmax - cmin
    if delta == 0: h = 0
    elif cmax == r: h = 60 * (((g - b) / delta) % 6)
    elif cmax == g: h = 60 * (((b - r) / delta) + 2)
    else: h = 60 * (((r - g) / delta) + 4)
    s = 0 if cmax == 0 else delta / cmax
    v = cmax
    return (h, s, v)

def hsv_to_rgb(hsv):
    # [G] Standard HSV to RGB conversion
    h, s, v = hsv
    c = v * s
    x = c * (1 - abs((h / 60) % 2 - 1))
    m = v - c
    if h < 60: r1, g1, b1 = c, x, 0
    elif h < 120: r1, g1, b1 = x, c, 0
    elif h < 180: r1, g1, b1 = 0, c, x
    elif h < 240: r1, g1, b1 = 0, x, c
    elif h < 300: r1, g1, b1 = x, 0, c
    else: r1, g1, b1 = c, 0, x
    return ((r1 + m) * 255, (g1 + m) * 255, (b1 + m) * 255)
```

**Edge Cases:**
*   **Zero Gradient:** If $\|\mathbf{g}\| = 0$, the direction is undefined [G]. Handle by preserving original color or using a default view-aligned value [G].
*   **Precision:** Floating-point errors in dot product near boundaries [G].

## Subtopics

### IDVR ColAndOpModulator
A specific implementation of oriented color modification within the Importance-Driven Volume Rendering (IDVR) framework [S2, unofficial]. It modulates color by calculating a new specular intensity based on modified gradients along cut-away borders and modulates the opacity of the current sample point prior to adapted compositing [S2, unofficial]. It is integrated into the `IDVRMImPCompositingModelSW` class [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample, as it involves basic vector operations and color space conversion [G].
*   **Memory Complexity:** $O(1)$ additional memory per sample [G].
*   **Strengths:** Provides intuitive, painterly control over visual emphasis; decouples brightness from color identity [S1].
*   **Limitations:** Not given in the sources.
*   **When to use:** Illustrative volume rendering, medical visualization where edge-on structures need to be deemphasized [S1].

## Background
Introduced within volume illustration for non-photorealistic rendering [S1]. It adapts traditional illustration techniques of oriented fading to 3D volume data, leveraging the HSV color space for intuitive control [S1].
