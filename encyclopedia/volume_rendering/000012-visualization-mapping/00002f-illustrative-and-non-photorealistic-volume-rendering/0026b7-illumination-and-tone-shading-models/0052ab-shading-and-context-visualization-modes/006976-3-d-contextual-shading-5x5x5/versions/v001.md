# 3-D Contextual Shading (5x5x5)
Also called: 5x5x5 Contextual Shading Method
## Overview
3-D Contextual Shading (5x5x5) is an illumination model for volume rendering that computes surface normals from a 5x5x5 voxel neighborhood to generate non-photorealistic shading. It improves upon the 3x3x3 contextual shading method by using a larger neighborhood to capture smoother surface inclinations, while employing systematic elimination of interior and redundant entries to keep the lookup table size manageable (reducing effective combinations to fewer than 1,000). It is distinct from gradient-based methods by relying on topological border detection rather than intensity derivatives, and from the 3x3x3 method by its larger context and optimized pattern reduction.
## How it works
### Inputs and outputs
- **Input**: A 3D voxel grid $V$ where each voxel is either occupied (surface) or unoccupied (background). The method operates on a central voxel $C$ assumed to lie on the surface.
- **Output**: A surface normal vector $\mathbf{n}$ for voxel $C$, used for shading calculations.

### Data structures
- **Voxel Grid**: Binary occupancy grid.
- **Lookup Table (LUT)**: Maps a reduced set of pattern indices to precomputed normal vectors. The LUT size is less than 1,000 entries.

### Steps
1. **Define Neighborhood**: Consider the 5x5x5 neighborhood centered at voxel $C$. Divide this cube into three orthogonal planes: XY, YZ, and XZ.
2. **Identify Open Directions**: Determine the "open direction(s)" of $C$ by checking if $C$ is a border point in the global grid.
    - A voxel is an **X-border point** if it has an unoccupied neighbor in the $\pm X$ direction.
    - A direction (e.g., North/South, East/West, Front/Back) is an **open direction** if $C$ is a border point in that direction but *not* in the opposite direction.
    - If $C$ is a border point in both opposite directions (e.g., both North and South), neither is an open direction.
    - [G] If no open directions are found (e.g., $C$ is surrounded in all 6 cardinal directions), the normal cannot be determined by this method; use a fallback (e.g., gradient or default).
3. **Plane Contribution Check**: For each of the three orthogonal planes:
    - Check the 4 direct neighbors of $C$ in that plane.
    - If all 4 direct neighbors are occupied, check the 4 indirect neighbors (diagonal neighbors in the plane, sharing only a corner with $C$).
    - If all 4 indirect neighbors are also occupied, the plane contributes nothing to the normal. Skip this plane.
4. **Column Traversal for Open Directions**: For each identified open direction:
    - Divide the 5x5 plane of that direction into five 5x1 columns parallel to the open direction.
    - Traverse each column starting from the open direction towards the center.
    - Identify the **first surface voxel** encountered in each column.
    - If no surface voxel is found in a column, record a null value.
    - There are 5 columns, each having 6 possible states (5 positions for the first surface voxel, or 1 state for "no surface"). This yields $6^5 = 7,776$ raw patterns.
5. **Pattern Reduction**:
    - **Center Constraint**: Since $C$ is on the surface, the first surface voxel in the center column cannot be beyond $C$ (i.e., it must be at or before $C$). This halves the possibilities for the center column, reducing the total patterns by half.
    - **Parallel Surface Elimination**: If there are no surface voxels in the second column (adjacent to center) or the fourth column, the surface is effectively parallel to the column length. In such cases, any surface voxels in the first or fifth column (farthest from center) have negligible influence on the normal and are neglected.
    - The effective number of combinations is reduced to fewer than 1,000.
6. **Normal Computation**:
    - Map the reduced pattern to an entry in the LUT to retrieve a precomputed normal vector $\mathbf{n}_{plane}$ for that plane.
    - [G] The final normal $\mathbf{n}$ is typically the normalized sum of the contributions from the three orthogonal planes: $\mathbf{n} = \frac{\mathbf{n}_{XY} + \mathbf{n}_{YZ} + \mathbf{n}_{XZ}}{\|\mathbf{n}_{XY} + \mathbf{n}_{YZ} + \mathbf{n}_{XZ}\|}$. If a plane contributed nothing, its vector is zero.

### Pseudocode

```python
def compute_normal_5x5x5(voxel_grid, center_coords):
    """
    Computes the surface normal for a surface voxel using the 5x5x5 contextual shading method.
    
    Args:
        voxel_grid: 3D array of booleans (True for occupied, False for unoccupied).
        center_coords: Tuple (x, y, z) of the center voxel index.
        
    Returns:
        Normal vector (nx, ny, nz).
    """
    x, y, z = center_coords
    # Define 5x5x5 neighborhood bounds
    # Note: Boundary checks should be added in practice [G]
    neighborhood = get_5x5x5_neighbors(voxel_grid, x, y, z)
    
    # Step 1 & 2: Identify open directions
    # Check if center is a border point in each axis
    # A voxel is a border point if at least one neighbor in that axis is unoccupied
    is_north_border = not all(neighborhood[x, y, z+1], ...) # Simplified logic
    # More precisely:
    # North/South (Z), East/West (X), Front/Back (Y) - assuming standard axes
    # Let's define directions:
    # Z+: North, Z-: South
    # X+: East, X-: West
    # Y+: Front, Y-: Back
    
    open_dirs = []
    
    # Check Z (North/South)
    has_unocc_z_pos = any(not voxel_grid[x, y, z+1+i] for i in range(1, 3)) # Simplified
    has_unocc_z_neg = any(not voxel_grid[x, y, z-1-i] for i in range(1, 3))
    
    # A direction is open if it is a border point but not the converse
    # Border point means unoccupied neighbor exists
    is_north_border = has_unocc_z_pos
    is_south_border = has_unocc_z_neg
    
    if is_north_border and not is_south_border:
        open_dirs.append('Z+')
    elif is_south_border and not is_north_border:
        open_dirs.append('Z-')
        
    # Repeat for X and Y axes...
    # ...
    
    normals = []
    
    # Step 3 & 4: Process each open direction
    for direction in open_dirs:
        # Determine the plane and columns
        if direction == 'Z+':
            plane = 'XY'
            # Columns are parallel to Z
            # Traverse from Z+ towards Z-
            # ...
        elif direction == 'Z-':
            plane = 'XY'
            # Traverse from Z- towards Z+
            # ...
        # ...
        
        # For the plane, check if it contributes
        # Check 4 direct neighbors in the plane
        direct_neighbors_occupied = check_direct_neighbors(voxel_grid, x, y, z, plane)
        
        if not direct_neighbors_occupied:
            # Plane contributes
            # Divide 5x5 plane into 5 columns
            # Traverse each column from the open direction
            # Find first surface voxel
            pattern = get_pattern_from_columns(voxel_grid, x, y, z, direction)
            
            # Reduce pattern
            reduced_pattern = reduce_pattern(pattern, direction)
            
            # Lookup normal
            n_plane = lookup_normal(reduced_pattern)
            normals.append(n_plane)
            
    # Step 6: Combine normals
    if not normals:
        return [0, 0, 0] # Fallback
        
    final_normal = sum(normals)
    return normalize(final_normal)
```

### Parameters
- **Neighborhood Size**: 5x5x5.
- **Effective LUT Size**: < 1,000 entries.

### Edge cases and pitfalls
- **No Open Directions**: If the central voxel is surrounded by occupied voxels in all 6 cardinal directions, no open direction is found. The method fails to determine a normal from context alone. A fallback strategy is required [G].
- **Boundary Conditions**: Voxels near the edge of the volume grid do not have a full 5x5x5 neighborhood. Boundary handling (e.g., padding, clamping) must be defined [G].
- **Precision**: The method relies on binary occupancy. Noise in the voxelization process can lead to incorrect border detection. The source notes that fuzzy objects were generated using Gaussian filtering before voxelization to mitigate this [S1, unofficial].
- **Degenerate Input**: If the surface is extremely thin (1 voxel thick) or has complex topology, the "first surface voxel" logic may need careful definition to ensure consistency.

## Operating characteristics
- **Time Complexity**: The method involves checking neighbors and traversing columns. The lookup table access is O(1). The preprocessing (LUT construction) is done once. Per-voxel cost is constant but higher than 3x3x3 due to the larger neighborhood.
- **Memory Complexity**: The LUT size is < 1,000 entries, which is small. The 5x5x5 neighborhood requires accessing 125 voxels per query.
- **Measured Performance**: Compared to a polygon model, the 5x5x5 contextual shading method has a mean error of 0.0376 and a standard deviation of 0.0573 [S1, unofficial]. This is slightly higher error than the 3x3x3 method (mean 0.0295, std 0.0460) but provides smoother shading due to the larger context.
- **Strengths**: Captures smoother surface inclinations than 3x3x3; lookup table size is manageable due to pattern reduction.
- **Limitations**: Higher computational cost than 3x3x3; sensitive to voxelization quality; requires handling of edge cases where no open direction exists.
- **When to use**: When smoother shading is desired and the voxel grid is clean (or pre-filtered). When the 3x3x3 method produces too much noise or jagged shading.
- **When not to use**: When computational resources are very limited (use 3x3x3 or gradient methods); when the voxel grid is noisy without pre-filtering.

## Background
The 3-D Contextual Shading (5x5x5) method was developed as an improvement over the 3x3x3 contextual shading method. It was presented in a final report on visualization techniques for die casting part and die design [S1, unofficial]. The report dates from July 1, 1995, to September 30, 1997. The method was compared against polygon models and grayscale gradient shading methods applied with Gaussian filters.
