# Volumetric Toon Shading

Also called: Fragment Shader Toon-Shading for Volumes, Interactive volume cartoon shading, Toon-Shading for Volumes, Toon-shading via 3D normal map

## Overview
Volumetric Toon Shading is a non-photorealistic rendering technique that simulates cel shading for volumetric datasets without requiring explicit surface vertices or mesh extraction [S1, unofficial]. It differs from surface-based NPR methods by operating directly on fragment-level data using a 3D normal map, allowing for interactive rendering of stylized volumes where features are defined by local gradient properties rather than discrete geometry [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar field (volume data), a parallel light direction vector $L$, and a 1D toon-shading texture (lookup table).
*   **Output:** A 2D image with discrete tonal shading.

**Data Structures:**
1.  **3D Normal Map:** A 3D texture storing the gray-scale gradients of the volume data in its RGB components. Each texel $(x, y, z)$ contains the normalized gradient vector $\nabla f_n$ at that location [S1, unofficial].
2.  **Toon-Shading Texture:** A 1D texture (or lookup table) containing user-specified color values corresponding to different illumination levels [S1, unofficial].

**Steps:**
1.  **Generate Normal Map:** Compute the gradient $\nabla f$ for the volume data and normalize it to obtain $\nabla f_n$. Store these vectors in the RGB components of a 3D texture [S1, unofficial].
2.  **Render Normal Map:** Render the 3D normal map using direct volume rendering or a similar technique to generate a depth buffer or fragment positions, ensuring per-fragment access to the gradient data [S1, unofficial].
3.  **Compute Dot Product:** For each fragment, retrieve the normal vector $N$ from the 3D normal map. Compute the dot product between the light direction $L$ and the normal $N$:
    $$ D = L \cdot N $$
    where $L$ is issued as a constant color in the texture combiner stage [S1, unofficial].
4.  **Apply Threshold/Multiplexer:** Use the dot product $D$ as a control value for a multiplexer. The standard threshold is $0.5$. If $D > 0.5$, select register A; otherwise, select register B [S1, unofficial].
5.  **Lookup Color:** Use the selected register's output to index into the 1D toon-shading texture. To achieve the characteristic "toon" discontinuity, use **nearest neighbor** texture interpolation [S1, unofficial].
6.  **Output Color:** The sampled color from the toon-shading texture is the final fragment color [S1, unofficial].

**Parameters:**
*   **Threshold:** The value separating illuminated and shadowed regions. Default is $0.5$ [S1, unofficial].
*   **Offset:** An additive offset applied to the dot product before the threshold comparison, allowing arbitrary mapping of shades to tones [S1, unofficial].

**Pseudocode:**
```python
# Constants
LIGHT_DIRECTION = normalize(vec3(0.0, 1.0, 0.0)) # Example light vector
THRESHOLD = 0.5
OFFSET = 0.0

# Textures
normal_map_3d: Texture3D # Stores normalized gradients
toon_lut_1d: Texture1D   # Stores discrete color values

# Fragment Shader Logic
def fragment_shader(fragment_position):
    # 1. Retrieve normal from 3D normal map
    # Note: In a real implementation, this requires rendering the volume 
    # to access the gradient at the fragment's depth.
    N = normal_map_3d.sample(fragment_position).rgb
    
    # 2. Compute dot product with light direction
    # L is treated as a constant color vector
    D = dot(N, LIGHT_DIRECTION)
    
    # 3. Apply offset
    D_adjusted = D + OFFSET
    
    # 4. Determine illumination state based on threshold
    # This mimics the hardware multiplexer described in [S1, unofficial]
    if D_adjusted > THRESHOLD:
        # Illuminated register
        tone_index = 1.0
    else:
        # Shadowed register
        tone_index = 0.0
        
    # 5. Lookup color in 1D toon-shading texture
    # Use nearest neighbor interpolation for discontinuity
    color = toon_lut_1d.sample(tone_index, filter=NEAREST)
    
    return color
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of fragments rendered. The per-fragment cost is constant (dot product, comparison, texture lookup).
*   **Memory Complexity:** Requires storage for the 3D normal map (same resolution as volume data) and the 1D toon-shading texture.
*   **Strengths:** Interactive performance due to hardware-accelerated fragment shading and texture combiners; no need for explicit mesh generation or silhouette extraction [S1, unofficial].
*   **Limitations:** Relies on the assumption that volume gradients approximate surface normals, which may be ambiguous in homogeneous regions; discrete shading may appear aliased without proper filtering strategies [S1, unofficial].

## Background
The method was introduced in "Interactive volume illustration" [S1, unofficial]. It adapts the polygonal toon-shading technique described in [22, 23] (referenced in [S1, unofficial]) to volumetric data by replacing vertex-based normal interpolation with per-fragment gradient lookup via a 3D normal map. This approach avoids the computational overhead of surface extraction and allows for seamless integration with other volume rendering techniques like hatch-based approaches [S1, unofficial].
