# Hatching and Stroke-based Rendering


## Overview
Hatching and Stroke-based Rendering is a family of non-photorealistic volume rendering techniques that simulate hand-drawn line art, such as hatching, stippling, or paint strokes, to convey shape, spatial relationships, and aesthetic qualities of 3D volumetric data [G]. It solves the problem of abstracting continuous volumetric features into discrete, interpretable graphical elements that mimic traditional artistic media [G]. It sets itself apart from its siblings by explicitly combining line-strip primitives or textured quads with direct volume rendering (DVR) or particle systems, using data-driven seed point selection and curvature-guided tracing to minimize memory and generation time while maintaining interactivity [S2, unofficial].

## Shared principles
This family builds on the shared principles of [Stylization and Pattern Generation](7612-stylization-and-pattern-generation.md) [G]. Volumetric illustration differs from surface-based NPR in several important ways [G]. In surface NPR, surfaces (features) are well-defined, whereas with volumes, feature areas within the volume must be determined through analysis of local volumetric properties because volumetric features vary continuously throughout three-dimensional space [G].

## Subtopics

### [Interactive Volume Illustration (Hatching)](5272-interactive-volume-illustration-hatching.md)
[Interactive Volume Illustration (Hatching)](5272-interactive-volume-illustration-hatching.md) is an object-space technique for illustrating volumetric data by simulating free-hand line art (hatching) using hardware-assisted volume and line rendering. It solves the problem of conveying shape and spatial relationships in 3D volumes by tracing hatches as polylines over implicit surfaces along either a fixed direction or a smoothed principal curvature direction. It sets itself apart from its siblings by explicitly combining line-strip primitives with direct volume rendering (DVR) in a two-pass pipeline, using data-driven seed point selection to minimize memory and generation time. Choose it when interactivity and explicit curvature-guided hatching are required.

### [Fast Paint Texture](14343-fast-paint-texture.md)
[Fast Paint Texture](14343-fast-paint-texture.md) is a stylization technique that simulates 3D paint undulations and overlap shadows on 2D strokes by generating a height field from stroke height maps and overlap counts, rendered via Phong shading, thereby avoiding the computational cost of 3D mesh generation. It sets itself apart from sibling methods like [Interactive Volume Illustration (Hatching)](5272-interactive-volume-illustration-hatching.md) by explicitly modeling paint layer accumulation through a 2D height field rather than relying solely on surface normals or simple shading. Choose it when simulating physical paint properties like overlap and shadow without 3D mesh generation is needed.

### [Visual Complexity (VC) Algorithm](14351-visual-complexity-vc-algorithm.md)
[Visual Complexity (VC) Algorithm](14351-visual-complexity-vc-algorithm.md) is a non-photorealistic volume rendering technique that simulates the local visual variations found in hand-painted artworks to enhance aesthetic judgment and detail perception. Unlike Interpretational Complexity (IC), which establishes global trends across the volume, VC focuses on local variations in stroke properties such as color, thickness, and contour to create a dense, textured appearance. It differs from [Interactive Volume Illustration (Hatching)](5272-interactive-volume-illustration-hatching.md) by employing a single-region, full-coverage painting strategy with varied stroke geometries rather than structured hatching lines, and from [Fast Paint Texture](14343-fast-paint-texture.md) by integrating embossing as a post-processing lighting effect on 2D stroke textures rather than a primary geometric modeling step. Choose it when simulating local hand-painted aesthetic variations is the goal.

### VolFliesGPU Framework
#### definition
- [S1] An interactive illustrative visualization framework for real-time pen-and-ink style rendering of volume data, based on a particle system.
#### layout
- [S1] Input: Volume data stored in a 3D texture; Proxy geometry comprising a 3D grid of equally spaced vertices.
#### usage
- [S1] Uses the VolumeFlies hidden surface removal filter: iso-surface is splatted with uniquely colored cones generated by the geometry shader; particle visibility is determined by an off-screen framebuffer.

### Non-photorealistic Volume Rendering via Point Sampling
#### definition
- [S2, unofficial] A methodology for sampling and rendering 3D volume data to simulate classical ink-and-paint non-photorealistic styles, addressing the lack of artist-friendly NPR volume rendering tools.
#### step
- [S2, unofficial] Scatter point data within the 3D volume data based on density values, or create a custom point cloud.
- [S2, unofficial] Ray cast from the camera to the hit position of the volume.
- [S2, unofficial] From the ray's hit position, cast a secondary ray towards a direction, either towards a light source for shading or continuing in the same direction for a headlamp effect.
- [S2, unofficial] Tally and normalize the number of scattered points found within a radius of the direction of the secondary ray.
- [S2, unofficial] Interpolate between the lit color of the volume and the background color using the normalized value from the previous step.

### Curved Strokes
#### definition
- [S3] A method to render strokes as Bézier curves with control points positioned based on data attribute orientations.
#### step
- [S3] Query data attribute values at three sample points s0, s1, s2. Compute associated orientations θ0, θ1, θ2 to position control points A, B, C, D.
- [S3] Place control points so that segment BC has orientation θ0, AB has orientation θ1, and CD has orientation θ2.
- [S3] If max(d1, d2) is large, draw the stroke as a curve; otherwise, likely draw as linear segments (implied by contrast with 'draw stroke as a curve').

### Variegation
#### definition
- [S3] A technique to simulate paint variation by drawing strokes as three quadrilaterals with varying colors and widths.
#### step
- [S3] Sample center color C=(R,G,B) and length l, width w. Vary C to C1, C2 in small interval. Vary w to w1, w2 such that 0 <= w1, w2 < w/8.
- [S3] Draw q centered on sample with length l, width w-(w1+w2), color C. Draw q1 next to q with length l, width w1, color C1. Draw q2 opposite q1 with length l, width w2, color C2.

### HatchForge Rendering Pipeline
#### definition
- [S4, unofficial] A raymarching renderer that produces SVG files with hatching lines, where strokes follow surface tangent directions and density is controlled by lighting to produce an engraving or etching aesthetic.
#### step
- [S4, unofficial] Pass 1: A Rust backend raymarches the SDF scene per-pixel using rayon parallelism, producing hit, brightness, and hatch angle buffers.
- [S4, unofficial] Pass 2: A flow field line tracer connects polylines through the 2D angle field, enforcing minimum spacing that varies with brightness to create light and shadow.
- [S4, unofficial] Pass 3: The polylines are written out as SVG.
#### parameter
- [S4, unofficial] RenderConfig parameters: width (int), height (int), buf_scale (int, default 18 in example), light_dir (tuple of 3 floats, e.g., (0.7, 1.0, 0.4)), shadows (bool, default True).
- [S4, unofficial] TraceConfig parameters: step_size (float, e.g., 0.04), min_space (float, e.g., 0.06), max_space (float, e.g., 0.7).
- [S4, unofficial] stroke_width (float, e.g., 0.04) is passed to render_scene to define the width of the output strokes.
#### layout
- [S4, unofficial] Scene definition uses a tree of SDF nodes (spheres, boxes, tori, boolean operations, transforms) evaluated natively in Rust via PyO3.
#### comparison
- [S4, unofficial] Native Rust evaluation via PyO3 provides roughly 150x speedup over pure Python execution of the scene graph.

## Background
The VolFliesGPU framework, introduced by Busking et al. in 2008, pioneered the use of GPU-based particle systems for interactive illustrative volume rendering, leveraging GPGPU paradigms for real-time performance [S1]. The Visual Complexity algorithm, developed by Liao et al., introduced sophisticated stroke placement, variegation, and flank texturing to simulate hand-painted aesthetics [S3]. Fast Paint Texture provided a method for simulating physical paint properties like overlap and shadow without 3D mesh generation [S1]. More recent methodologies, such as those by [S2, unofficial], have explored point-sampling techniques to generalize ink-and-paint styles for volume data. Halftones and hatching were proposed to help distinguish faces of wound stream surfaces [S5, unofficial]. Brush stamping methods support multiple shapes including sphere, cylinder, box, cone, and procedural Perlin noise, with sweeping to create tapered capsules [S6, unofficial]. HatchForge provides a raymarching renderer that produces SVG files with hatching lines following surface tangent directions, controlled by lighting to produce an engraving aesthetic [S4, unofficial].
