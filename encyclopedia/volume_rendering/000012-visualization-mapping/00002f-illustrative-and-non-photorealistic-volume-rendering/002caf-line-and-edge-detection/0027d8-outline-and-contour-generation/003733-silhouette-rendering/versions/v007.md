# Silhouette Rendering

Also called: Object-space line rendering, Silhouette Rendering Pipeline, Stroke Pipeline

## Overview
Silhouette rendering is a non-photorealistic technique that extracts and stylizes object boundaries to enhance perceptual clarity, distinguish object classes, and indicate contextual relationships [S1, book][S2]. It sets itself apart from image-space alternatives by operating in object space, allowing for precise geometric edge extraction and independent stroke stylization before compositing [S2]. Unlike [Image Space Outline Generation](788-image-space-outline-generation.md), which relies on post-processing rendered images, this method constructs explicit line primitives from mesh data [S2].

## How it works
The method follows a pipeline: geometry preparation, line extraction, stroke generation, hidden line removal (HLR), and stylization [S2].

**Inputs and Outputs:**
*   **Input:** Segmented 3D mesh geometry (vertices, edges, faces) [S2].
*   **Output:** Stylized line primitives (strokes) composited over the scene [S2].

**Data Structures:**
1.  **Adjacency Structure:** A graph representation of the mesh providing connectivity information (vertex-to-edge, edge-to-face) to facilitate edge traversal [S2].
2.  **Stroke Data:** A list of line segments or polylines, each containing vertex coordinates and associated stylization parameters (width, color, saturation, texture) [S2].
3.  **Z-Buffer:** A depth buffer storing the minimum depth value for each pixel, generated from the surface geometry [S2].

**Steps:**

1.  **Geometry Data Preparation:**
    Construct the adjacency structure from the input mesh to enable efficient traversal of edges and vertices [S2].

2.  **Line Extraction:**
    Identify significant edges from the mesh. These include:
    *   **Silhouettes:** Edges separating front-facing and back-facing polygons relative to the view vector.
    *   **Feature Lines:** Edges defined by specific geometric properties or segmentation criteria [S2].

3.  **Stroke Generation:**
    Assemble the extracted edges into continuous strokes (polylines). This step is independent of the final rendering pipeline, allowing the stroke data to be reused or modified without altering the source geometry [S2].

4.  **Hidden Line Removal (HLR):**
    Determine which strokes are visible from the current camera viewpoint using a z-buffer test [S2].
    *   **Step 4a:** Render the surface geometry of the objects into the z-buffer. The frame buffer is **not** updated; only depth values are written [S2].
    *   **Step 4b:** For each stroke, scan-convert the line segment into pixel coordinates [S2].
    *   **Step 4c:** For each pixel along the stroke, compare the stroke's depth ($z_{stroke}$) with the depth value in the z-buffer ($z_{buffer}$) at that pixel location [S2].
    *   **Step 4d:** Classify the pixel (and potentially the entire stroke segment) as visible if $z_{stroke} \le z_{buffer}$ (assuming standard depth testing where smaller values are closer) and hidden otherwise [S2]. Note: The source describes "locally comparing z-depths" [S2].

5.  **Stroke Stylization:**
    Apply visual modifications to the visible strokes. Parameters include:
    *   Width
    *   Saturation
    *   Color
    *   Texture [S2]
    *   Additional effects such as cut-away views or lighted regions may also be applied [S2].

6.  **Compositing:**
    Render the stylized strokes onto the final image. If surface rendering is used, the surface objects must be rendered into the final image **prior** to the lines to ensure correct occlusion of the strokes by the surface [S2].

**Pseudocode:**

```python
def silhouette_rendering_pipeline(mesh, camera):
    # 1. Geometry Data Preparation
    adjacency = build_adjacency_structure(mesh)
    
    # 2. Line Extraction
    # Extract silhouettes and feature lines based on mesh topology and view direction
    significant_edges = extract_edges(mesh, adjacency, camera.view_vector)
    
    # 3. Stroke Generation
    # Assemble edges into continuous polylines
    strokes = assemble_strokes(significant_edges)
    
    # 4. Hidden Line Removal
    # 4a. Render objects into z-buffer only
    z_buffer = render_z_buffer(mesh, camera)
    
    visible_strokes = []
    for stroke in strokes:
        is_visible = True
        for point in stroke.points:
            # Project point to screen space to get pixel coordinates (x, y)
            screen_pos = project_to_screen(point, camera)
            x, y = screen_pos.x, screen_pos.y
            
            # Get depth from z-buffer
            z_buffer_val = z_buffer[y][x]
            
            # Compare stroke depth with buffer depth
            # Assuming standard OpenGL-like depth test: visible if stroke is closer or equal
            if point.z > z_buffer_val:
                is_visible = False
                break
        
        if is_visible:
            visible_strokes.append(stroke)
            
    # 5. Stroke Stylization
    stylized_strokes = []
    for stroke in visible_strokes:
        # Apply stylization parameters
        stroke.width = calculate_width(stroke)
        stroke.color = calculate_color(stroke)
        stroke.saturation = 1.0 # Example default
        stylized_strokes.append(stroke)
        
    # 6. Compositing
    # Render surface first
    render_surface(mesh, camera)
    # Then render stylized strokes
    render_strokes(stylized_strokes, camera)
```

**Parameters:**
*   **Edge Selection Criteria:** Not given in the sources.
*   **Stylization Parameters:** Width, saturation, color, texture [S2].

**Edge Cases and Pitfalls:**
*   **Z-Fighting:** Silhouettes located exactly at discontinuities of the z-buffer of the surface objects may cause visual artifacts if depth precision is insufficient [S2].
*   **Performance:** HLR requires individual scan-conversion of lines, which can be computationally expensive for complex meshes with many edges [S2].

## Subtopics

### Image-space silhouette extraction with perturbation
A technique that extracts surface silhouettes in image space using edge detection filters, optionally modified by a procedural perturbation function for artistic variation, and combines them with Direct Volume Rendering (DVR) for depth perception [S3, unofficial]. Unlike the object-space approach, it operates on the rendered image rather than mesh geometry [S3, unofficial].

**Steps:**
1.  Render the volume using DVR [S3, unofficial].
2.  Apply image processing filters (e.g., edge detectors) to the rendered image to extract feature lines, hatching strokes, ridges, and valley lines [S3, unofficial].
3.  Optionally apply a procedural perturbation function to the edge detector output to achieve different artistic results [S3, unofficial].
4.  Composite the extracted silhouettes/feature lines over the DVR result to enhance main features while preserving contextual information [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of edges and strokes. HLR requires $O(E \cdot L)$ where $E$ is the number of edges and $L$ is the average length of strokes in pixels, plus the cost of rendering the z-buffer [S2].
*   **Memory Complexity:** Requires storage for the adjacency structure, stroke data, and the z-buffer [S2].
*   **Strengths:** Precise control over edge geometry; independent stylization pipeline; effective for discriminating object classes and highlighting critical features (e.g., lymph nodes touching critical structures) [S1, book][S2].
*   **Limitations:** Requires pre-segmented geometry; HLR can be slow for dense edge sets; potential z-fighting artifacts at surface discontinuities [S2].
*   **When to use:** When precise geometric edge representation is required, such as in medical visualization for surgery planning where distinguishing touching structures is critical [S1, book].
*   **When not to use:** When performance is critical and the scene has extremely high polygon counts, or when the geometry is not available (only volume data).

## Background
Silhouette rendering was developed as part of illustrative volume visualization techniques to enhance the perception of salient features in complex scenes [S1, book][S3, unofficial]. It is particularly used in medical visualization, such as neck surgery planning, to help users identify critical structures like lymph nodes and bones [S1, book]. The object-space line rendering approach was detailed by Tietjen et al. in 2005 for combining silhouettes, surface, and volume rendering [S2].
