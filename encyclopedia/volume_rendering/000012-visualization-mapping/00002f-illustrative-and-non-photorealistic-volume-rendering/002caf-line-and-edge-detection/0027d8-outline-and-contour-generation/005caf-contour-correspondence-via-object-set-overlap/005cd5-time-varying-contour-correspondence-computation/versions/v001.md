# Time-Varying Contour Correspondence Computation

Also called: Correspondence Computation Algorithm, Five-Step Correspondence

## Overview
This method computes the correspondence between time-varying contours across two consecutive time steps, $t$ and $t+1$, by labeling edges in the contour tree of $t+1$ with sets of edges from the contour tree of $t$. It solves the problem of tracking how individual contour components evolve, merge, or split as the scalar field changes over time. Unlike direct geometric comparison, it leverages the topological structure of Join Trees (JT) and Split Trees (ST) to efficiently determine overlaps between upper and lower objects, ensuring that a contour at $t+1$ is linked to the specific contours at $t$ that generated it.

## How it works
The algorithm operates on the contour trees $CT_t$ and $CT_{t+1}$ derived from scalar fields $f_t$ and $f_{t+1}$ on domains $M_t$ and $M_{t+1}$. The core insight is that upper objects (regions where $f > w$) and lower objects (regions where $f < w$) grow as the isovalue $w$ decreases. When an upper object from $t$ and an upper object from $t+1$ collide at a point $x_c$ and isovalue $w_0$, they overlap for all $w < w_0$. The algorithm computes this overlap implicitly using JT and ST structures.

### Inputs and Outputs
*   **Inputs:**
    *   Contour tree $CT_t$ of the scalar field at time $t$.
    *   Scalar field $f_{t+1}$ on domain $M_{t+1}$.
    *   Join Tree $JT_{t+1}$ and Split Tree $ST_{t+1}$ constructed from $f_{t+1}$.
*   **Outputs:**
    *   $CT_{t+1}$ where every edge $e_k^{t+1}$ is labeled with a set of edges $E_t \subset CT_t$.
    *   Labeling satisfies: A contour on $e_k^{t+1}$ at isovalue $w_0 \in [f_a, f_b]$ evolves from contours on edges $e_k'^t \in E_t$ at time $t$.

### Data Structures
*   **Contour Tree Edge Label:** A set of integer IDs, where each ID uniquely identifies an edge in $CT_t$.
*   **Join Tree Node Label:** A set of integer IDs, representing the set of $CT_t$ edges whose contours are contained within the upper object represented by the node.
*   **Split Tree Node Label:** A set of integer IDs, representing the set of $CT_t$ edges whose contours are contained within the lower object represented by the node.

### Steps

1.  **Assign IDs to $CT_t$ Edges:**
    Assign a unique integer ID to each edge in $CT_t$. Let $E_{CT_t}$ be the set of these IDs.

2.  **Label $JT_t$ and $ST_t$:**
    Label each edge in $JT_t$ and $ST_t$ with a set of edges from $CT_t$.
    *   **Logic:** An upper object with isovalue $w$ on an edge $e \in JT_t$ must contain contours with isovalue $w$ on borders $e' \in E$ from $CT_t$.
    *   **Implementation:** Process vertices $v$ of the domain mesh $M_t$ in decreasing order of function value $f_t(v)$. Traverse $JT_t$ from upper leaves toward the global minimum.
        *   If $v$ is a critical point, a node in $JT_t$ is created and connected to parent nodes belonging to the same objects.
        *   Update the label in the parent vertex of $v$ incrementally: delete edge IDs corresponding to destroyed contour classes and insert edge IDs corresponding to newly created contour classes.
    *   *Note:* The process for $ST_t$ is symmetric, processing vertices in increasing order of function value.

3.  **Core Matching (Label $JT_{t+1}$ and $ST_{t+1}$):**
    Label each edge $e$ in $JT_{t+1}$ and $ST_{t+1}$ with a set of edges $E$ from $CT_t$.
    *   **Logic:** An upper/lower object with isovalue $w$ on edge $e$ in time $t+1$ must overlap upper/lower objects in time $t$ that contain contours with isovalue $w$ on borders $e' \in E$.
    *   **Implementation:** This step determines the correspondence by checking overlaps. Since upper objects grow as $w$ decreases, the overlap condition is monotonic. The labels in $JT_{t+1}$ and $ST_{t+1}$ are populated based on the topological relationships established in Step 2. Specifically, the label of a node in $JT_{t+1}$ represents the set of $CT_t$ edges whose upper objects overlap with the upper object represented by the $JT_{t+1}$ node.

4.  **Convert to Contour Tree Form:**
    Convert the labeled $JT_{t+1}$ and $ST_{t+1}$ into contour tree forms $CT_{t+1}(JT)$ and $CT_{t+1}(ST)$.
    *   **Logic:** The label at a point $p$ in the contour tree must match the label at the corresponding point $p'$ in the join/split tree.
    *   **Implementation:** Map the node labels from $JT_{t+1}$ to the edges of $CT_{t+1}(JT)$ and from $ST_{t+1}$ to the edges of $CT_{t+1}(ST)$. The label at a point $p$ on an edge in $CT_{t+1}$ is derived from the label of the node in $JT_{t+1}$ or $ST_{t+1}$ that represents the upper/lower object containing the contour at $p$.

5.  **Compute Final Labels for $CT_{t+1}$:**
    Label each edge $e$ in $CT_{t+1}$ with a set of edges $E$ from $CT_t$.
    *   **Formula:** $Label(e) = Label_{JT}(e) \cap Label_{ST}(e)$
    *   **Logic:** $E$ is computed as the intersection of the labels (edge sets) from $CT_{t+1}(JT)$ and $CT_{t+1}(ST)$. This ensures that the contour represented by $e$ at time $t+1$ overlaps with the contours represented by $E$ at time $t$ in both upper and lower object spaces, satisfying the correspondence definition.

### Parameters and Edge Cases
*   **Function Range:** The labeling is computed for the entire function range $[f_a, f_b]$.
*   **Critical Points:** Labels change only at critical points. Non-critical vertices simply propagate labels.
*   **Collision Property:** The algorithm relies on the property that once upper/lower objects from $t$ and $t+1$ collide, they always overlap thereafter as the isovalue decreases. This ensures that the overlap information computed at the collision point is valid for the entire range below it.
*   **Precision:** Numerical precision in determining critical points and collision points can affect the accuracy of the labels. Robust geometric predicates are recommended.

## Operating characteristics
*   **Time Complexity:** The complexity is dominated by the construction of the Join and Split trees and the overlap computation. The overlap computation in Step 3 is the most expensive, potentially requiring pairwise comparisons or spatial indexing if the number of contours is large. The sources do not provide a precise asymptotic complexity.
*   **Memory Complexity:** Requires storing the contour trees, join/split trees, and the labels for each edge/node. The labels are sets of integers, so memory usage scales with the number of edges and the average size of the correspondence sets.
*   **Strengths:** Provides a complete topological correspondence for all isovalues. Efficiently uses the monotonic growth property of upper/lower objects to avoid redundant checks.
*   **Limitations:** Requires the construction of JT and ST for both time steps. The overlap computation can be computationally intensive for complex scalar fields with many topological changes.

## Background
The method was introduced in the paper "Time-varying contour topology" [S1]. It builds upon the concept of contour trees and join/split trees to provide a robust way to track topological changes in time-varying scalar fields. The key innovation is the use of JT and ST to implicitly compute the overlap of upper and lower objects, which is necessary for defining contour correspondence.
