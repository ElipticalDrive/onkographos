# Object Contour NPR

Also called: Csébfalvi's contour method, GPU-based contour tracing, Geometry shader contour rendering, Gradient-based contour visualization, View-Dependent Contour Generation

## Overview
Object Contour NPR generates view-dependent lines that demarcate areas where an object's surface turns away from the viewer, effectively emphasizing physical boundaries without relying on predefined classification functions or voxel intensity values [S2, unofficial]. Unlike hatch-based techniques which are often pre-rendered to texture buffers, this method produces line-strips rendered directly to the screen, allowing for interactive, view-dependent illustration [S1].

## How it works
**Inputs:** A 3D scalar volume dataset; viewing direction; user-defined contour distance threshold.
**Outputs:** A set of line primitives rendered to the screen.

**Data Structures:**
1.  **Particle Set:** A collection of points sampled within the volume. Each particle stores its 3D position $(x, y, z)$ and potentially its gradient vector.
2.  **Geometry Shader State:** Configured to accept point primitives and output line strips.

**Gradient Estimation:**
Due to the method's heavy reliance on gradient accuracy, conventional central difference estimation is insufficient as it only considers a narrow voxel neighborhood [S2, unofficial]. Instead, a 4D linear regression method is used to estimate the gradient vector $\nabla f$ at each particle position [S2, unofficial].

**Algorithm Steps:**
1.  **Particle Selection:** Identify particles located within a user-defined distance $d_{thresh}$ from the implicit object contours. The contour condition is typically defined by the angle between the viewing direction $\vec{v}$ and the gradient vector $\nabla f$, or by a curvature-dependent measure $\tau$ [S1].
2.  **Primitive Conversion:** Treat the selected particles as point primitives.
3.  **Contour Tracing (Geometry Shader):** For each point primitive, trace along the contour direction. The geometry shader transforms the single point into a line-strip segment that approximates the local contour path. The trace direction and constant-width measure are adopted from the VolumeFlies framework [S1].
4.  **Rendering:** Render the generated line-strips directly to the screen framebuffer. Do not accumulate them into a texture buffer [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of particles and the cost of gradient estimation. Tracing is performed per-particle in the geometry shader. [S1]
*   **Memory Complexity:** Requires storage for particles and gradients. No large texture buffers are needed for contour accumulation. [S1]
*   **Strengths:** Fast parameter tuning due to independence from voxel intensity values; view-dependent nature ensures contours always reflect the current viewpoint. [S2, unofficial]
*   **Limitations:** High sensitivity to gradient reconstruction errors; performance degrades with multiple particle sets. [S1][S2, unofficial]
*   **When to use:** When interactive, view-dependent boundary emphasis is required without the overhead of classification-based volume rendering. [S2, unofficial]
*   **When not to use:** When voxel intensity-based features are more important than boundary orientation, or when pre-rendered static contours are sufficient. [S1]

## Background
Object contour NPR was introduced by Csébfalvi et al. in 2001 as a fast non-photorealistic volume visualization technique [S2, unofficial]. It was adopted from the VolumeFlies framework [BVvW07], which presented constant-width contours using a threshold on a curvature-dependent measure $\tau$ [S1]. The method distinguishes itself from direct volume rendering by ignoring voxel intensity values in favor of gradient magnitude and viewing angle. [S2, unofficial]
