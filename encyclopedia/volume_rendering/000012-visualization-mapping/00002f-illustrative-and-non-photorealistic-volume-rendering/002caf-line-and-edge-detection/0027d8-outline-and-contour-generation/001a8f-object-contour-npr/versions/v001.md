# Object Contour NPR

Also called: Csébfalvi's contour method, Gradient-based contour visualization

## Overview
Object Contour NPR generates view-dependent lines that demarcate areas where an object's surface turns away from the viewer, emphasizing physical boundaries without relying on predefined classification functions or voxel intensity values [S1][S2, unofficial]. Unlike sibling methods such as Lasso Contour Rendering or Curvature-Controlled Style Contours, this technique relies exclusively on gradient magnitude and the angle between the viewing direction and the gradient vector to determine color and opacity, making parameter tuning significantly faster [S2, unofficial].

## How it works
**Inputs:** Volume dataset, viewing direction, user-defined contour distance threshold.
**Outputs:** Rendered image with contour lines.

**Data Structures:**
*   **Particle Set:** A collection of points sampled within the volume. Each particle stores position $(x, y, z)$ and potentially normal/gradient information.
*   **Gradient Field:** Estimated using 4D linear regression (see Pitfalls).

**Steps:**
1.  **Gradient Estimation:** Compute the gradient vector $\nabla V$ at each particle position using 4D linear regression to ensure accuracy [S2, unofficial].
2.  **Contour Selection:** Select particles that satisfy the contour condition. A particle is considered part of a contour if it is within a user-defined distance from the theoretical contour line. The contour is defined as the set of lines where the surface turns away from the viewer [S1].
3.  **Primitive Transformation:** Treat selected particles as point primitives. Pass them to a geometry shader [S1].
4.  **Line-Strip Generation:** The geometry shader traces along the contour direction and transforms the point primitives into line-strips that resemble parts of the contour [S1].
5.  **Rendering:** Render the line-strips directly to the screen framebuffer. Do not record them to a texture buffer [S1].
6.  **Color/Opacity Calculation:** For each voxel/pixel, determine color and opacity based on:
    *   Gradient magnitude $|\nabla V|$
    *   Angle $\theta$ between the viewing direction $\vec{v}$ and the gradient vector $\nabla V$ [S2, unofficial].

**Formulas:**
The contour condition is implicitly defined by the geometry where the surface normal is perpendicular to the view direction, or more generally, where the gradient indicates a boundary turning away from the viewer [S1]. The specific mapping function for color/opacity $C$ is not explicitly defined in the sources, but depends on $|\nabla V|$ and $\cos(\theta) = \frac{\nabla V \cdot \vec{v}}{|\nabla V| |\vec{v}|}$ [S2, unofficial].

**Parameters:**
*   **User-defined distance:** Threshold distance from the contour for selecting particles [S1].
*   **Gradient estimation method:** Must use 4D linear regression [S2, unofficial].

**Pitfalls:**
*   **Gradient Accuracy:** Conventional central difference estimation is insufficient because it only takes a narrow voxel neighborhood into account, leading to inaccurate contours due to the method's enormous reliance on gradient reconstruction [S2, unofficial].
*   **View Dependency:** Contours cannot be generated prior to rendering as they are view-dependent [S1].

## Subtopics

### Lasso Contour Rendering
Uses lasso-like selections to define contour regions, differing from the global gradient-based selection of Object Contour NPR. [Lasso Contour Rendering](1855-lasso-contour-rendering.md)

### Curvature-Controlled Style Contours
Controls contour style based on surface curvature, whereas Object Contour NPR relies on gradient magnitude and view angle. [Curvature-Controlled Style Contours](5350-curvature-controlled-style-contours.md)

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** The method is described as "fast" and allows for interactive framerates when combined with other styles, though adding multiple particle sets leads to performance costs and loss of interactivity [S1][S2, unofficial].
*   **Strengths:** No direct dependence on voxel intensity values makes tuning parameters faster than traditional direct volume rendering [S2, unofficial].
*   **Limitations:** Enormous reliance on accurate gradient reconstruction; conventional central difference is inaccurate [S2, unofficial]. Cannot be pre-computed due to view dependency [S1].
*   **When to use:** When rapid parameter tuning is desired and physical boundaries need to be emphasized without classification functions [S2, unofficial].
*   **When not to use:** When high accuracy in gradient estimation is not feasible or when pre-rendered contours are required [S1][S2, unofficial].

## Background
Object Contour NPR was presented by Csébfalvi et al. in 2001 [S2, unofficial]. It was adopted from the VolumeFlies framework [BVvW07], which presented constant-width contours using a threshold on a curvature-dependent measure $\tau$ [S1]. The method is part of the broader field of illustrative and non-photorealistic volume rendering, specifically within line and edge detection techniques [S1][S2, unofficial].
