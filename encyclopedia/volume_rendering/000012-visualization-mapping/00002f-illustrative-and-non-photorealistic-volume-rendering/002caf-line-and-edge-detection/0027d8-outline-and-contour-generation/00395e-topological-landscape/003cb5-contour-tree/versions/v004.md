# Contour Tree

Also called: Join Tree, Merge Tree, Split Tree

## Overview
The contour tree is a topological data structure that captures the changes in the topology of a scalar field as the isovalue is swept across the scalar range [S1, unofficial]. It tracks the creation, splitting, and merging of connected components (level sets) by identifying critical points such as local extrema and saddle points [S1, unofficial]. It sets itself apart from the [Reeb Graph](9315-reeb-graph.md) by requiring a simply connected domain without loops, and from the [Topological Zone Transfer Function Application](11654-topological-zone-transfer-function-application.md) by providing the underlying structural hierarchy rather than a direct visualization mapping.

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field defined on a simply connected domain (e.g., a 3D volume or 2D image) [S1, unofficial]. The domain must be free of loops [S1, unofficial].
*   **Output:** A tree structure consisting of vertices (supernodes) and edges (superarcs) [S1, unofficial].

**Data Structures:**
The contour tree is a graph $T = (V, E)$ where:
*   **Vertices ($V$):**
    *   **Leaf Nodes:** Represent local extrema.
        *   Local maxima: Where a contour is created [S1, unofficial].
        *   Local minima: Where a contour is destroyed [S1, unofficial].
    *   **Interior Nodes:** Represent saddle points.
        *   Type 1 (Split): One contour splits into two or more disjoint contours [S1, unofficial].
        *   Type 2 (Merge): Two or more disjoint contours merge into one [S1, unofficial].
*   **Edges ($E$):**
    *   Represent a single contour segment between the supernode where it is created and the supernode where it is destroyed [S1, unofficial].
    *   There is a one-to-one correspondence between individual contours in the data and edges in the tree [S1, unofficial].

**Construction Steps (Join Tree Variant):**
A Join Tree captures connected sub-level sets (regions below a specific isovalue) [S1, unofficial]. The construction follows these steps [S1, unofficial]:

1.  **Initialize:** Set the current isovalue $v$ to the global maximum of the scalar field.
2.  **Identify Maxima:** As $v$ decreases, identify local maxima. Mark each as a red critical point (leaf node in the tree) [S1, unofficial].
3.  **Track Merges:** Continue decreasing $v$. When two distinct connected regions merge, create a new interior node (merge saddle) in the tree to represent this event [S1, unofficial].
4.  **Connect:** Link the regions to the new merge node.
5.  **Terminate:** Continue until $v$ reaches the global minimum, represented by a blue graph node (leaf node) [S1, unofficial].

**Optimizations:**
*   **Sorting:** Chiang et al. improve processing time by only sorting critical vertices during the merge tree construction stage, rather than sorting all elements [S1, unofficial].
*   **Seeds:** To avoid re-extracting surfaces, "seeds" can be used. Seeds are vertices where contours can be built from. An entire contour for a specified isovalue is computed from the seed bounded by the two supernodes representing the critical points of the contour [S1, unofficial]. Using seeds significantly reduces the number of seeds required for representation but often increases the overall storage size of the contour tree [S1, unofficial].
*   **Augmented Trees:** Carr et al. introduced augmented contour trees, which add non-branching vertices at non-critical points to provide additional values for isosurfaces to be seeded [S1, unofficial].
*   **Parallelism:** Gueunet et al. present a multithreaded "contour forest" algorithm using a shared memory approach to compute the augmented contour tree [S1, unofficial].

            # Mark as red critical point [S1, unofficial]
            
        elif cp.type == 'local_min':
            # Create leaf node for local minimum
            node = tree.add_leaf_node(cp.position, cp.value)
            # Mark as blue critical point [S1, unofficial]
            
        elif cp.type == 'saddle':
            # Determine if this is a split or merge event
            # based on the connectivity of level sets below the isovalue
            connected_components = get_connected_components_below(scalar_field, cp.value)
            
            if cp.event_type == 'merge':
                # Two or more contours merge into one
                # Create interior node
                merge_node = tree.add_interior_node(cp.position, cp.value, type='merge')
                # Connect the merging components to this node
                for comp in connected_components:
                    tree.add_edge(comp.root_node, merge_node)

                # One contour splits into two or more
                # Create interior node

                # Connect the resulting components to this node
                for comp in connected_components:
                    tree.add_edge(split_node, comp.root_node)
                    
    return tree

**Parameters and Edge Cases:**
*   **Neighborhood Definition:** Changing the method of defining neighbors during split/merge tree computations can slightly alter the location of critical points, though the underlying structure (number of supernodes and superarcs) remains fixed for a given input [S1, unofficial].
*   **Genus:** The contour tree does not typically contain information regarding changes in topological genus (loops) [S1, unofficial]. This information must be added to the output separately if required [S1, unofficial].
*   **Domain Constraints:** The input domain must be simply connected and free of loops. The merge tree computation phase cannot correctly handle data without a boundary or with loops [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the algorithm. Chiang et al. improve processing time by sorting only critical vertices [S1, unofficial]. Gueunet et al.'s multithreaded "contour forest" algorithm offers quicker computations but is limited by load imbalance and redundant computations [S1, unofficial].
*   **Memory Complexity:** Using seeds reduces the number of seeds required for representation but often increases the overall storage size of the contour tree [S1, unofficial].
*   **Strengths:** Simple method for capturing topological information; used for zero-dimensional persistence measures; can be used directly for analysis and feature extraction [S1, unofficial].
*   **Limitations:** Cannot handle domains with loops or without boundaries; critical vertices are difficult to identify in 4D+ data [S1, unofficial].
*   **When to use:** For analyzing scalar fields on simply connected domains, computing persistence, or as a step in constructing more complex topological structures [S1, unofficial].
*   **When not to use:** When the domain has genus (loops) or is not simply connected; use the [Reeb Graph](9315-reeb-graph.md) instead [S1, unofficial].

## Background
The contour tree was introduced by Boyell and Ruston [S1, unofficial]. It uses concepts from Morse theory to capture changes in the topology of scalar fields at critical points [S1, unofficial]. Carr et al. investigated its use in higher-dimensional data sets and introduced augmented contour trees [S1, unofficial]. Merge trees are fundamental data structures in computational topology, often used as a computation step in constructing the contour tree [S1, unofficial].
