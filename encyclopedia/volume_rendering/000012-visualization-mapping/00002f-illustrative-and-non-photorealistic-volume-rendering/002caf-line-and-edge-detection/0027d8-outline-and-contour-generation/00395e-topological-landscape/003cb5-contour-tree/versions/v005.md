# Contour Tree

Also called: Join Tree, Merge Tree, Split Tree

## Overview
The contour tree is a topological data structure that captures the evolution of connected components (level sets) of a scalar field as the isovalue sweeps across the scalar range [S1, unofficial]. It solves the problem of representing the global connectivity of scalar data by tracking where contours are created, split, or merged [S1, unofficial]. It sets itself apart from the [Reeb Graph](9315-reeb-graph.md) by requiring a simply connected domain without loops, and from the [Topological Landscape](8481-topological-landscape.md) by providing the underlying hierarchical graph structure rather than just a terrain metaphor [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field defined on a domain (typically a regular grid or simplicial mesh) [S1, unofficial]. The domain must be simply connected and free of loops [S1, unofficial].
*   **Output:** A tree structure consisting of vertices (supernodes) and edges (superarcs) [S1, unofficial].

**Data Structures:**
The contour tree is a graph $T = (V, E)$ where:
*   **Vertices ($V$):**
    *   **Leaf Nodes:** Correspond to local extrema.
        *   Local maxima: Where a contour is created [S1, unofficial].
        *   Local minima: Where a contour is destroyed [S1, unofficial].
    *   **Interior Nodes:** Correspond to saddle points.
        *   Type 1: A saddle where one more contour is created as a contour splits into two or more disjoint contours [S1, unofficial].
        *   Type 2: A saddle where one or more contours are destroyed as two or more disjoint contours merge into one [S1, unofficial].
*   **Edges ($E$):**
    *   Represent a single contour between the supernode where it is created and the supernode where it is destroyed [S1, unofficial].
    *   There is a one-to-one correspondence between individual contours in the data and edges in the tree [S1, unofficial].

**Construction Algorithm (Join Tree Variant):**
A Join Tree captures connected sub-level sets (regions below a specific isovalue) [S1, unofficial]. The construction proceeds as follows [S1, unofficial]:

1.  **Identify Critical Points:** Find all local maxima and minima in the scalar field. Mark local maxima as critical points [S1, unofficial].
2.  **Sort Critical Vertices:** Sort the critical vertices by scalar value. Optimizations exist to sort only critical vertices rather than all elements to improve processing time [S1, unofficial].
3.  **Sweep Isovalue:** Gradually decrease the isovalue from the global maximum towards the global minimum [S1, unofficial].
4.  **Track Connectivity:**
    *   When a local maximum is encountered, a new connected component (contour) is created [S1, unofficial].
    *   When two distinct regions merge as the isovalue decreases, mark the merge event by creating a node in the graph [S1, unofficial].
    *   Continue until reaching the global minimum, which is represented by a final graph node [S1, unofficial].
5.  **Augmentation (Optional):** Non-branching vertices can be added at non-critical points to provide additional values for isosurfaces to be seeded [S1, unofficial].

**Pseudocode:**
```python
def construct_join_tree(scalar_field):
    # 1. Identify critical points
    critical_points = find_local_extrema(scalar_field)
    
    # 2. Sort critical points by value (descending for Join Tree)
    sorted_points = sort_by_value(critical_points, descending=True)
    
    # 3. Initialize tree structure
    tree = EmptyTree()
    
    # 4. Sweep isovalue
    current_isovalue = sorted_points[0].value
    components = {} # Map from component_id to list of points
    
    for point in sorted_points:
        if point.is_maximum():
            # New component created
            new_id = generate_new_id()
            components[new_id] = [point]
            tree.add_leaf_node(point, new_id)
        elif point.is_saddle():
            # Determine if split or merge based on neighborhood connectivity
            neighbors = get_neighbors(point, scalar_field)
            active_components = [c for c in components if any(n in c for n in neighbors)]
            
            if len(active_components) > 1:
                # Merge event: multiple components become one
                merged_id = active_components[0]
                for cid in active_components[1:]:
                    merge_components(components, merged_id, cid)
                tree.add_merge_node(point, active_components)
            else:
                # Split event: one component becomes multiple
                # Note: In Join Tree (sub-level sets), splits are implicit 
                # as components grow. Explicit split nodes are typically 
                # handled in Split Trees or general Contour Trees.
                pass
                
        elif point.is_minimum():
            # Component destroyed
            destroy_component(components, point)
            tree.add_leaf_node(point)
            
    return tree
```

**Parameters:**
*   **Neighborhood Definition:** The method of defining neighbors during split/merge tree computations can slightly alter the location of critical points, though the underlying structure (number of supernodes and superarcs) remains fixed for a given input [S1, unofficial].
*   **Seeds:** Vertices where contours can be built from. An entire contour for a specified isovalue is computed from the seed bounded by the two supernodes representing the critical points of the contour [S1, unofficial]. Using seeds reduces the number of seeds required for representation significantly compared to other methods, but often increases the overall storage size of the contour tree [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Genus:** The contour tree does not typically contain information regarding changes in topological genus (loops) [S1, unofficial]. This information must be added to the output separately [S1, unofficial].
*   **Domain Constraints:** The input domain must be simply connected and free of loops. The merge tree computation phase cannot correctly handle data without a boundary or with loops [S1, unofficial].
*   **High Dimensions:** Critical vertices are difficult to identify in data with dimensionality of four or more [S1, unofficial].
*   **Multithreading:** The speedup of multithreaded approaches (e.g., contour forest) is limited by load imbalance and redundant computations [S1, unofficial].

## Subtopics

### [Reeb Graph](9315-reeb-graph.md)
The Reeb graph is a topological data structure that generalizes the contour tree to handle scalar fields defined on domains that are not simply connected (i.e., domains containing loops or lacking a boundary). While the contour tree tracks the evolution of connected components of level sets, the Reeb graph tracks the evolution of connected components of level sets modulo homotopy, effectively identifying points in the domain that can be connected by a path of constant scalar value. It solves the problem of capturing the global topology of scalar data in complex geometries, such as toroidal volumes or data with internal voids, where standard contour trees fail or produce ambiguous results. It sets itself apart from the [Contour Tree](9312-contour-tree.md) by explicitly handling genus (loops) in the input domain, and from the [Joint Contour Net](9316-joint-contour-net.md) by operating on single-variable scalar fields rather than multivariate data.

### [Topological Zone Transfer Function Application](11654-topological-zone-transfer-function-application.md)
This method applies distinct transfer functions to different topological zones of a scalar field, determined by mapping sample points to arcs in a contour tree via monotone paths. It sets itself apart from global transfer functions by allowing topology-aware color and opacity mapping, and from simple gradient reversal or flattening by using dynamic tube sweeping to broaden connections between components, providing a smoother approximation of the scalar field.

### [Contour-Tree-Defined Segmentation](11672-contour-tree-defined-segmentation.md)
Contour-Tree-Defined Segmentation partitions a scalar volume into topologically distinct regions, called "topological zones," based on the arcs of the contour tree of the underlying trilinear interpolant. It solves the problem of assigning transfer functions to specific structural components of a volume by allowing independent transfer functions for individual zones, thereby isolating features for visualization. It sets itself apart from [Reeb Graph](9315-reeb-graph.md) by focusing on the full topological hierarchy of the scalar field for segmentation, and from [Topological Zone Transfer Function Application](11654-topological-zone-transfer-function-application.md) by providing the foundational segmentation mechanism that defines these zones prior to application.

### [Stratified Morse Theory for Euler Characteristic](11757-stratified-morse-theory-for-euler-characteristic.md)
Stratified Morse Theory (SMT) for Euler Characteristic is a method to compute the Euler characteristic $\chi$ of isosurfaces defined by piecewise trilinear interpolants on regular grids, specifically handling the non-smoothness at cell boundaries. It serves two primary purposes: verifying the topological correctness of isosurface extraction algorithms via a Manufactured Solutions pipeline, and estimating noise levels in direct volume rendering transfer function design. Unlike smooth Morse theory, which fails on discontinuous derivatives, SMT stratifies the grid into vertices, edges, faces, and cells to apply local topological analysis. It is distinct from the [Contour Tree](9312-contour-tree.md) in that it provides a scalar topological invariant ($\chi$) for verification or noise estimation rather than a hierarchical graph of critical points, and differs from [Reeb Graph](9315-reeb-graph.md) by focusing on the Euler characteristic specifically rather than component merging/splitting paths.

### Contour Tree Branch Navigation
After determining high and low vertices, look up their corresponding high and low arcs in the contour tree [S2, unofficial]. Walk from the high arc towards the low arc to find the arc containing the sampled value $f$ [S2, unofficial]. Use the branch decomposition (a rooted tree) instead of the contour tree (a free tree) to find the path between branches $b$ and $c$ [S2, unofficial]. Walk up the parent link of the deeper of the two branches $b$ and $c$ simultaneously [S2, unofficial]. If neither stopping condition is met, the walk terminates when both paths reach the common ancestor $a$, which is the desired branch [S2, unofficial]. When walking towards increasing function value, stop if the next step goes past a saddle with a higher value than the sampled point [S2, unofficial]. When walking towards decreasing function value, stop if the next step goes past a saddle with a lower value than the sample [S2, unofficial].

## Operating characteristics
*   **Complexity:** Not given in the sources.
*   **Performance:** Chiang et al. improve processing time by only sorting critical vertices in the merge tree construction stage, which vastly increases processing speeds in very large data sets [S1, unofficial]. Gueunet et al. present a multithreaded approach ("contour forest") that achieves quicker computations, though speedup is limited by load imbalance and redundant computations [S1, unofficial].
*   **Storage:** Using seeds reduces the number of seeds required for representation significantly compared to other methods, but often increases the overall storage size of the contour tree [S1, unofficial].
*   **Limitations:** The contour tree cannot handle domains with loops or without boundaries [S1, unofficial]. Critical vertices are difficult to identify in 4D or higher data [S1, unofficial].
*   **Usage:** Merge trees are often used as a computation step in the construction of more complex topological data structures such as the contour tree. Alternatively, they can be used directly for analysis and feature extraction in complex data sets [S1, unofficial].

## Background
The contour tree was introduced by Boyell and Ruston [S1, unofficial]. It uses concepts from Morse theory to capture changes in the topology of a scalar field at critical points [S1, unofficial]. Merge trees are fundamental data structures in computational topology that track connected level sets within data as the isovalue is swept across the scalar range [S1, unofficial].
