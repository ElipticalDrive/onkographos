# Contour-Tree-Defined Segmentation
Also called: Topological Zone Segmentation

## Overview
Contour-Tree-Defined Segmentation partitions a scalar volume into topologically distinct regions, called "topological zones," based on the arcs of the contour tree of the underlying trilinear interpolant. It solves the problem of assigning transfer functions to specific structural components of a volume by allowing independent transfer functions for individual zones, thereby isolating features for visualization [S1]. It sets itself apart from [Reeb Graph](9315-reeb-graph.md) by focusing on the full topological hierarchy of the scalar field for segmentation, and from [Topological Zone Transfer Function Application](11654-topological-zone-transfer-function-application.md) by providing the foundational segmentation mechanism that defines these zones prior to application [S1].

## How it works
**Inputs:** A scalar field defined on a hexahedral grid.
**Outputs:** A segmentation of the volume into topological zones, each associated with a specific transfer function, and a hierarchical representation of the contour tree.

**Data Structures:**
1.  **Contour Tree:** A graph where nodes represent critical points (minima, maxima, saddles) and arcs represent intervals between critical values. Each arc corresponds to a topological zone.
2.  **Widget:** A local graph structure within each hexahedral cell. It consists of the cell's edges augmented by edges connecting body saddles, face saddles, and vertices. This widget represents the topology of the trilinear interpolant within that cell [S1].
3.  **Branch Decomposition:** A hierarchical structure used to store the simplified contour tree, grouping arcs into units to avoid oversegmentation [S1].

**Steps:**
1.  **Compute the Contour Tree:** Calculate the contour tree of the trilinear interpolant. This is done using a variation of the method by Pascucci and Cole-McLaughlin [S1, S19], applied to the union of cellwise join and split trees constructed from the widgets [S1]. Any graph accurately representing the trilinear interpolant's topology may be used [S1].
2.  **Simplify the Tree:** Apply topological simplification to the computed contour tree to remove symbolic perturbation artifacts [S1, S41]. This step reduces noise and complexity.
3.  **Assign Transfer Functions:** Assign a specific transfer function to each topological zone (arc) in the simplified contour tree. This allows independent control over the visualization of each zone [S1].
4.  **Store Hierarchy:** Use branch decomposition to store the hierarchy of the simplified contour tree. This concatenates sequences of arcs into single units, unifying their topological zones and preventing oversegmentation when regions do not overlap in value range [S1, S35].
5.  **Render Opacity:** For each hexahedral cell, determine the opacity by applying the trilinear interpolant. If a cell spans multiple topological zones, look up the opacity directly in the transfer function associated with the specific zone, rather than interpolating over tetrahedra [S1].

**Pseudocode:**
```python
def contour_tree_segmentation(volume_data, grid):
    # Step 1: Construct widgets and compute contour tree
    # Each hexahedral cell gets a widget with augmented edges
    widgets = []
    for cell in grid.hexahedra:
        widget = construct_widget(cell) # Augments cell edges with saddle-vertex connections
        widgets.append(widget)
    
    # Compute contour tree using union of cellwise join/split trees
    contour_tree = compute_contour_tree_from_widgets(widgets)
    
    # Step 2: Simplify to remove symbolic perturbation
    simplified_tree = simplify_contour_tree(contour_tree)
    
    # Step 3: Store hierarchy using branch decomposition
    branch_decomposition = build_branch_decomposition(simplified_tree)
    
    # Step 4: Assign transfer functions to zones
    # Note: In practice, user interaction or algorithmic selection assigns TFs
    zone_transfer_functions = assign_transfer_functions(branch_decomposition)
    
    # Step 5: Render
    rendered_volume = []
    for cell in grid.hexahedra:
        # Determine which topological zones this cell intersects
        intersecting_zones = find_intersecting_zones(cell, branch_decomposition)
        
        # Calculate opacity for each sample point in the cell
        for sample_point in cell.samples:
            value = trilinear_interpolate(volume_data, sample_point)
            # Find the zone corresponding to the value's arc in the tree
            zone = find_zone_for_value(value, branch_decomposition)
            # Look up opacity directly in the zone's transfer function
            opacity = zone_transfer_functions[zone].evaluate(value)
            rendered_volume.append((sample_point, opacity))
            
    return rendered_volume

def construct_widget(cell):
    """
    Creates a graph widget for a hexahedral cell.
    Augments standard cell edges with edges between:
    - Body saddles
    - Face saddles
    - Vertices
    """
    graph = Graph()
    # Add vertices and standard edges
    for vertex in cell.vertices:
        graph.add_node(vertex)
    for edge in cell.edges:
        graph.add_edge(edge)
        
    # Identify saddles within the cell based on trilinear interpolant critical points
    body_saddles = find_body_saddles(cell)
    face_saddles = find_face_saddles(cell)
    
    # Augment graph with edges between saddles and vertices
    for saddle in body_saddles + face_saddles:
        for vertex in cell.vertices:
            graph.add_edge(saddle, vertex)
            
    return graph
```

**Parameters and Edge Cases:**
*   **Symbolic Perturbation:** Must be handled during simplification to ensure topological correctness [S1, S41].
*   **Oversegmentation:** Branch decomposition mitigates this by unifying zones that do not overlap in value range [S1].
*   **Tetrahedral Artifacts:** The method explicitly avoids tetrahedral interpolation artifacts by using trilinear interpolation over hexahedral cells and direct transfer function lookups [S1].

## Subtopics

### [Contour-Based Segmentation for FT Specification](11723-contour-based-segmentation-for-ft-specification.md)
A technique using contours to separate portions of a volume before transfer function specification. It sets itself apart by using explicit geometric boundaries (contours) to define regions of interest, whereas sketch-based methods rely on neural networks to interpret freehand strokes.

## Operating characteristics
*   **Complexity:** The complexity is dominated by the computation of the contour tree and the branch decomposition. For medium to large datasets, the hierarchical representation is necessary [S1].
*   **Performance:** The method avoids the artifacts associated with tetrahedral interpolation, potentially improving visual quality in cells spanning multiple zones [S1].
*   **Strengths:** Allows independent transfer functions for individual topological zones; handles trilinear interpolation correctly; avoids tetrahedral artifacts; hierarchical representation aids user interaction [S1].
*   **Limitations:** Topological complexity can be high, requiring simplification; depends on the accuracy of the trilinear interpolant representation [S1].
*   **When to use:** When fine-grained control over specific topological features is required, and when avoiding interpolation artifacts in hexahedral grids is critical [S1].
*   **When not to use:** When real-time performance is critical and the overhead of contour tree computation is prohibitive; when the scalar field does not have well-defined topological features [S1].

## Background
The method was introduced in "Topology-Controlled Volume Rendering" (2007) [S1]. It extends previous work by Takeshima et al. [S10] by allowing independent transfer functions for individual topological zones and using trilinear interpolation over hexahedral cells. It builds on the contour tree computation methods of Pascucci and Cole-McLaughlin [S19] and the branch decomposition technique of Pascucci et al. [S35]. The concept of "topological zones" follows Cox et al. [S25].
