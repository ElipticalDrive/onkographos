# Multi-Dimensional Reeb Graph

Also called: Hierarchical Reeb graph

## Overview
The Multi-Dimensional Reeb Graph (MDRG) is a hierarchical data structure used to represent the topology of multivariate scalar fields by recursively storing joint contours. It solves the problem of capturing complex topological relationships in domains with multiple independent functions (e.g., pressure, temperature) where standard univariate methods fail. It sets itself apart from the [Joint Contour Net](9316-joint-contour-net.md) by providing a recursive, tiered representation of the Reeb space, which serves as an intermediate structure for extracting the Jacobi structure and the Reeb skeleton [S1, unofficial].

## How it works
The MDRG constructs a hierarchy of Reeb graphs, where each level restricts the topology of a new function to the contours established by previous functions.

**Inputs and Outputs**
*   **Input:** A set of $n$ scalar functions $F = \{f_1, f_2, \dots, f_n\}$ defined on a common domain (e.g., a volume grid). The functions may represent independent physical quantities or temporal snapshots.
*   **Output:** A hierarchical structure where Level $k$ is the Reeb graph of $f_k$ restricted to the contours of $f_1, \dots, f_{k-1}$.

**Data Structures**
The structure is a list of Reeb graphs, indexed by level $k \in \{1, \dots, n\}$.
*   **Level 1:** The standard Reeb graph of $f_1$.
*   **Level $k$ ($k > 1$):** A Reeb graph representing the topology of $f_k$, but computed only on the connected components (contours) defined by the previous levels $f_1, \dots, f_{k-1}$.

**Algorithm Steps**
1.  **Initialize Level 1:** Compute the standard Reeb graph for the first function $f_1$. This forms the base of the hierarchy.
2.  **Iterate for $k = 2$ to $n$:**
    a.  Identify the joint contours of $f_1, \dots, f_{k-1}$. These contours define the sub-domains or "sheets" in the Reeb space.
    b.  Restrict the domain of $f_k$ to these joint contours.
    c.  Compute the Reeb graph for $f_k$ within these restricted domains. This captures how the topology of $f_k$ changes relative to the fixed topology of the preceding functions.
    d.  Store this Reeb graph as Level $k$ of the MDRG.
3.  **Completion:** The full MDRG consists of the sequence of Reeb graphs from Level 1 to Level $n$.

**Parameters**
*   **Function Order:** The order of functions $f_1, \dots, f_n$ affects the hierarchy. The sources do not specify a default ordering rule, but note that the structure allows extracting the Reeb graph of any individual function $f_i$ from the hierarchy [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Degenerate Inputs:** If functions are identical or linearly dependent, the joint contours may collapse, leading to degenerate Reeb graphs.
*   **Complexity:** The recursive restriction can lead to a large number of components if the joint contours are highly fragmented.

## Subtopics

### Reeb Skeleton
The Reeb skeleton is a simplified graph structure derived from the MDRG and the Jacobi structure. It takes into account the size of connected components, allowing measures of persistence to be assigned to its arcs. It is generated as the dual graph of the singular and regular components captured in the Jacobi structure. Unlike the Layered Reeb graph, which works directly with Jacobi sets, the Reeb skeleton uses the Jacobi structure to aid multivariate simplification. Unlike the MDRG, which stores Reeb space criticalities, the Reeb skeleton provides a simplified graph for assigning persistence measures. It is used for multivariate simplification, allowing noisy features to be removed via lip pruning techniques. Persistence measures can be applied, such as the accumulated volume of joint contour slabs in a connected region [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The complexity depends on the computation of the Reeb graphs at each level and the extraction of joint contours.
*   **Memory Complexity:** Not given in the sources. The structure stores a Reeb graph for each function, restricted by previous functions, which can be memory-intensive for high-dimensional data.
*   **Strengths:** It provides a convenient structure for extracting the Reeb graphs of each individual function making up the Reeb space. It serves as a foundation for extracting the Jacobi structure and Reeb skeleton, which are crucial for multivariate simplification and persistence analysis [S1, unofficial].
*   **Limitations:** The recursive nature can be complex to implement. It is an intermediate structure, not a final visualization tool in itself, but rather a basis for further topological analysis [S1, unofficial].

## Background
The MDRG was introduced by Carr et al. as an extension of the Joint Contour Net (JCN) [53]. It was designed to extract further topological structure from the Reeb space by evaluating an intermediate structure, the MDRG [62]. The MDRG is part of a broader effort in topological visualization techniques for volume multifield data, aiming to handle multiple independent functions such as pressure, temperature, or wind speed [S1, unofficial]. The related Jacobi structure and Reeb skeleton were further developed by Chattopadhyay et al. [62, 63] to address the need for multivariate simplification and persistence measures.
