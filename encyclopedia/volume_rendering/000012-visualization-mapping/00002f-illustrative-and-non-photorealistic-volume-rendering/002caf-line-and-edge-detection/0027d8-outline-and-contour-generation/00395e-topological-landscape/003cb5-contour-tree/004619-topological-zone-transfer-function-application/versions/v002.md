# Topological Zone Transfer Function Application

Also called: Contour Tree Mapping, Contour tree-based volume rendering, GPU-based Topological Zone Look-up, Topological Zone-Based Volume Rendering, Topology-Controlled Volume Rendering, Zone-based Rendering, Zone-specific transfer functions

## Overview
This method applies distinct transfer functions to different topological zones of a scalar field, determined by mapping sample points to arcs in a contour tree via monotone paths [S1][S2, unofficial]. It sets itself apart from global transfer functions by allowing topology-aware color and opacity mapping, and from simple gradient reversal or flattening by using dynamic tube sweeping to broaden connections between components, providing a smoother approximation of the scalar field [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field defined on a grid (voxels) or mesh (tetrahedra/hexahedra), a precomputed contour tree, and a set of transfer functions associated with contour tree branches [S1][S2, unofficial].
*   **Output:** A rendered image where each sample point is colored and opaqued based on its topological zone [S1][S2, unofficial].

**Data Structures:**
1.  **Branch Records:** Stored logically in a 1D array but physically wrapped in a 2D texture due to dimension limits [S1]. Each record contains: Reference to parent branch, Value at its saddle, Depth in the rooted branch decomposition, Reference to its transfer function, and Scale-and-bias pair for simplification scaling [S1].
2.  **Transfer Functions:** Stored in a logically 1D, physically 2D array [S1]. References are texture coordinates; a function value is added to the coordinate to offset and select the proper color [S1].
3.  **Voxel-to-Branch Map:** Stored as a 3D texture with nearest-neighbor interpolation [S1]. Output is references (texture coordinates) to the branch array [S1].
4.  **Tube Lookup Table:** Stores three values for each function value $v$: Position $p_t(v)$, Tube radius $r_t(v)$, Replacement function value $f_t(v)$ [S1].
5.  **Tube Reference Map:** A 3D texture storing references to the closest tube in each voxel's topological zone, determined in preprocessing [S1].

**Algorithm Steps:**

1.  **Determine Monotone Path Endpoints:** For a sample point $p$ in a cell, identify the local maximum vertex ($v_{high}$) and local minimum vertex ($v_{low}$) of the monotone path passing through $p$ [S1][S2, unofficial].
    *   **Tetrahedral Meshes (Linear Interpolation):** The path is implicit [S1][S2, unofficial]. Use the path from the highest-valued vertex to the lowest-valued vertex of the tetrahedron [S1][S2, unofficial].
    *   **Hexahedral Meshes (Trilinear Interpolation):** Construct an explicit monotone path using axis-parallel segments because saddles may occur inside cells [S1][S2, unofficial]. Use Algorithm 1 below to find $v_{high}$ and $v_{low}$ [S1][S2, unofficial].

2.  **Map to Contour Tree Branch:** Look up the high arc (corresponding to $v_{high}$) and low arc (corresponding to $v_{low}$) in the contour tree [S1]. Identify the common ancestor $a$ of the branches $b$ (high) and $c$ (low) in the rooted branch decomposition [S1]. Walk up the parent links of the deeper of branches $b$ and $c$ simultaneously [S1].
    *   **Stopping Condition:** If walking towards increasing value, stop if the next step goes past a saddle with a higher value than the sample [S1]. If walking towards decreasing value, stop if the next step goes past a saddle with a lower value than the sample [S1]. If neither condition is met, terminate when both paths reach the common ancestor $a$ [S1]. The branch containing the sample is the one where the walk stopped [S1].

3.  **Apply Transfer Function:** Trace the monotone path $Q$ in the contour tree corresponding to the field path [S2, unofficial]. Find the unique point $q$ on $Q$ with the same isovalue as $p$ [S2, unofficial]. Apply the transfer function associated with the branch on which $q$ lies [S1][S2, unofficial].

4.  **Tube Sweeping (Simplification/Gradient Reversal):** For each voxel, retrieve the reference to the closest tube in its topological zone from the Tube Reference Map [S1]. During rendering, look up tube parameters ($p_t(v), r_t(v), f_t(v)$) from the Tube Lookup Table indexed by the sample's function value $v$ [S1]. Compute the blending function $b$ based on the distance from the sample location $p_s$ to the tube axis $p_t(v)$ [S1]:
    $$ b = \frac{r_t(v) - \|p_s - p_t(v)\|}{r_t(v)} $$
    Clamp $b$ to $[0, 1]$ [S1]. The parameter $\beta$ controls the width of the tube's influence, and $\beta > 1$ ensures the interior volume of the tube is visible during rendering [S1]. Compute the final output value $v_{out}$ by linearly interpolating between the original value $v_{in}$ and the replacement value $f_t(v_{in})$, weighted by $b$:
    $$ v_{out} = \text{clamp}(1 - b) v_{in} + \text{clamp}(b) f_t(v_{in}) $$
    where $\text{clamp}(x) = 0$ if $x \le 0$, $x$ if $0 < x < 1$, and $1$ if $x \ge 1$ [S1].

5.  **Simplification Scaling:** If a branch is pruned, a scaling transformation $s$ is applied to all children by multiplying each child's scale-and-bias pair by $s [S1]. If pruning is reversed, apply $s^{-1}$ [S1]. Scaling is performed on interpolated fragments during rendering before tube blending [S1]. The replacement function value $f_t$ must reflect this scale and bias transformation [S1].

**Pseudocode for Hexahedral Monotone Path (Algorithm 1):**

```python
def find_monotone_path_endpoints(trilinear_interpolant, p):
    """
    Input:
      trilinear_interpolant: Function t(x,y,z) returning scalar value.
      p: Sample position (x, y, z) inside the cell [0,1]^3.
    Output:
      plo: Position of the local minimum vertex.
      phi: Position of the local maximum vertex.
    """
    # Initialize path to boundary faces
    plo = round_down('x', p)
    phi = round_up('x', p)
    
    if trilinear_interpolant(plo) > trilinear_interpolant(phi):
        plo, phi = phi, plo
        
    # Complete descending path to mesh vertex (from plo)
    temp = round_up('y', plo)
    plo = round_down('y', plo)
    if trilinear_interpolant(plo) > trilinear_interpolant(temp):
        plo, temp = temp, plo
        
    temp = round_up('z', plo)
    plo = round_down('z', plo)
    if trilinear_interpolant(plo) > trilinear_interpolant(temp):
        plo, temp = temp, plo
        
    # Complete ascending path to mesh vertex (from phi)
    temp = round_up('y', phi)
    phi = round_down('y', phi)
    if trilinear_interpolant(phi) < trilinear_interpolant(temp):
        phi, temp = temp, phi
        
    temp = round_up('z', phi)
    phi = round_down('z', phi)
    if trilinear_interpolant(phi) < trilinear_interpolant(temp):
        phi, temp = temp, phi
        
    return plo, phi

def round_down(axis, p):
    """Replaces the component corresponding to axis with 0."""
    if axis == 'x':
        return (0, p[1], p[2])
    elif axis == 'y':
        return (p[0], 0, p[2])
    elif axis == 'z':
        return (p[0], p[1], 0)

def round_up(axis, p):
    """Replaces the component corresponding to axis with 1."""
    if axis == 'x':
        return (1, p[1], p[2])
    elif axis == 'y':
        return (p[0], 1, p[2])
    elif axis == 'z':
        return (p[0], p[1], 1)
```

**Edge Cases and Pitfalls:**
*   **Hexahedral Saddles:** Trilinear interpolation allows saddles inside cells, requiring explicit path construction (Algorithm 1) rather than using vertex extrema directly [S1][S2, unofficial].
*   **Scaling Composition:** When multiple simplifications are applied, scaling transformations must be composed into a single scale-and-bias pair per zone to ensure correct rendering [S1].

## Operating characteristics
*   **Time Complexity:** The branch lookup involves walking up the branch decomposition tree, which is logarithmic in the number of branches in the worst case, but typically small [S1]. The tube lookup is $O(1)$ via texture access [S1].
*   **Memory Complexity:** Requires storing the contour tree, branch decomposition, voxel-to-branch map (32 bits/voxel), tube reference map, and transfer functions [S1]. Texture usage depends on the number of branches and transfer functions [S1].
*   **Performance:** Measured on an NVIDIA 7800 GPU [S1]. Frame rates for 512x512 images with approx. one sample per voxel per ray [S1]. The Fuel dataset (64x64x64) and Nucleon dataset (41x41x41) were used for testing [S1]. The Chest CT dataset (384x384x240) was also rendered [S1].
*   **Strengths:** Provides topology-aware visualization, allowing users to highlight specific structures (e.g., ribs in CT) while maintaining context [S1]. Tube sweeping offers a smoother approximation of the scalar field than gradient reversal or flattening, with gradual growth of simplified components [S1].
*   **Limitations:** Requires preprocessing to build the contour tree and branch decomposition [S1]. The method is complex to implement due to the need for GPU-based branch lookup and tube sweeping [S1].

## Background
This method was introduced by J. Weber, J. Tierny, H. Hagen, J. P. Burgess, and C. Gold in their paper "Topology-Controlled Volume Rendering" [S1]. It builds on the concepts of the contour tree [Contour Tree](9312-contour-tree.md) and extends them to volume rendering by mapping topological zones to transfer functions [S1]. The method addresses the limitation of global transfer functions by allowing distinct visualizations for different topological features [S1].
