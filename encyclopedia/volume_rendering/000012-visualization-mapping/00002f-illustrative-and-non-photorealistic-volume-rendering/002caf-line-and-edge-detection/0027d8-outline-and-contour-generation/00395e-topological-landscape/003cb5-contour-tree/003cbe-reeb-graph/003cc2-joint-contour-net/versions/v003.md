# Joint Contour Net

Also called: Discrete Reeb space

## Overview
The Joint Contour Net (JCN) is a discrete graph-based representation of the Reeb space for multivariate scalar data, approximating the topology of $n$ variables defined over an $m$-dimensional domain [S1, unofficial]. It solves the problem of visualizing and analyzing the topological relationships between multiple scalar fields by partitioning the domain into connected regions called joint contour slabs [S1, unofficial]. Unlike the [Reeb Graph](9315-reeb-graph.md), which handles single-variable topology, the JCN extends this to multivariate inputs; it differs from the [Multi-Dimensional Reeb Graph](9382-multi-dimensional-reeb-graph.md) by using a quantization-based slab construction rather than critical node extraction [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** $n$ scalar functions $f_1, \dots, f_n$ defined on an $m$-dimensional domain $\mathbb{R}^m$ [S1, unofficial].
*   **Output:** An undirected graph $G = (V, E)$ [S1, unofficial].
    *   If $n < m$, the output is an approximation of the Reeb space [S1, unofficial].
    *   If $n \ge m$, the output is a subdivision of the input geometry over the $n$ variables [S1, unofficial].

**Data Structures:**
*   **Graph:** Undirected graph [S1, unofficial].
*   **Vertices ($V$):** Represent joint contour slabs. Each vertex stores the barycentric spatial coordinates of the slab [S1, unofficial].
*   **Edges ($E$):** Represent adjacency between joint contour slabs [S1, unofficial].

**Algorithm Steps:**
1.  **Quantization:** Define quantization intervals for each of the $n$ input scalar functions [S1, unofficial].
2.  **Overlay:** Overlay the quantization intervals to construct the bivariate/multivariate field [S1, unofficial]. This partitions the domain into regions where the isovalue tuples of all $n$ functions remain constant within their respective intervals [S1, unofficial].
3.  **Slab Identification:** Identify connected regions formed by the overlay [S1, unofficial]. These regions are the joint contour slabs [S1, unofficial]. Each slab is a connected component of the domain where the quantized values of all input functions are identical [S1, unofficial].
4.  **Vertex Placement:** For each identified joint contour slab, compute its barycenter (centroid) in the spatial domain [S1, unofficial]. Place a vertex in the graph at this coordinate [S1, unofficial].
5.  **Edge Construction:** Mark adjacency between regions [S1, unofficial]. If two joint contour slabs share a boundary in the domain, add an undirected edge between their corresponding vertices in the graph [S1, unofficial].

**Pseudocode:**
```python
def compute_joint_contour_net(scalar_fields, quantization_intervals):
    """
    scalar_fields: List of n scalar function arrays on a regular grid.
    quantization_intervals: List of n tuples (min, max, step) for each field.
    Returns: vertices list of dicts, edges list of tuples.
    """
    n = len(scalar_fields)
    grid_shape = scalar_fields[0].shape
    num_voxels = 1
    for dim in grid_shape: num_voxels *= dim

    # Step 1 & 2: Quantize and Overlay
    quantized_fields = []
    for i, field in enumerate(scalar_fields):
        min_val, max_val, step = quantization_intervals[i]
        num_bins = int((max_val - min_val) / step) + 1
        quantized = []
        for val in field.flat:
            idx = int((val - min_val) / step)
            idx = max(0, min(idx, num_bins - 2))
            quantized.append(idx)
        quantized_fields.append(quantized)

    combined_keys = [tuple(q[idx] for q in quantized_fields) for idx in range(num_voxels)]

    # Step 3: Identify connected slabs (connected components of identical keys)
    visited = set()
    slabs = []
    for idx in range(num_voxels):
        if idx not in visited:
            key = combined_keys[idx]
            component = []
            queue = [idx]
            visited.add(idx)
            while queue:
                curr = queue.pop(0)
                component.append(curr)
                c = []
                rem = curr
                for dim in reversed(grid_shape):
                    c.append(rem % dim); rem //= dim
                for d in range(len(grid_shape)):
                    for delta in [-1, 1]:
                        nc = c[:]; nc[d] += delta
                        if all(0 <= nc[d] < grid_shape[d] for d in range(len(grid_shape))):
                            n_idx = 0
                            for dim, val in zip(grid_shape, nc): n_idx = n_idx * dim + val
                            if combined_keys[n_idx] == key and n_idx not in visited:
                                visited.add(n_idx)
                                queue.append(n_idx)
            slabs.append((key, component))

    vertices = []
    edges = []
    vertex_map = {}

    # Step 4: Vertex Placement
    for slab_key, voxel_indices in slabs:
        coords = []
        for v_idx in voxel_indices:
            c = []
            rem = v_idx
            for dim in reversed(grid_shape):
                c.append(rem % dim); rem //= dim
            coords.append(c)
        barycenter = [sum(c) / len(coords) for c in zip(*coords)]
        vertex_index = len(vertices)
        vertices.append({'barycenter': barycenter, 'slab_key': slab_key})
        vertex_map[slab_key] = vertex_index

    # Step 5: Edge Construction
    edge_set = set()
    for slab_key, voxel_indices in slabs:
        current_v = vertex_map[slab_key]
        for v_idx in voxel_indices:
            c = []
            rem = v_idx
            for dim in reversed(grid_shape):
                c.append(rem % dim); rem //= dim
            for d in range(len(grid_shape)):
                for delta in [-1, 1]:
                    nc = c[:]; nc[d] += delta
                    if all(0 <= nc[d] < grid_shape[d] for d in range(len(grid_shape))):
                        n_idx = 0
                        for dim, val in zip(grid_shape, nc): n_idx = n_idx * dim + val
                        n_key = combined_keys[n_idx]
                        if n_key != slab_key:
                            n_v = vertex_map[n_key]
                            edge = (min(current_v, n_v), max(current_v, n_v))
                            if edge not in edge_set:
                                edge_set.add(edge)
                                edges.append(edge)
    return vertices, edges
```

**Parameters:**
*   **Quantization Intervals:** The choice of intervals affects the resolution of the JCN [G]. Finer intervals yield more slabs and a more detailed graph, but increase computational cost [G].

**Edge Cases and Pitfalls:**
*   **Parallelization Merge:** In distributed memory implementations, multiple sub-JCNs are constructed in parallel [S1, unofficial]. The merge step, which combines these sub-JCNs into a single output, is the limiting factor for speedup [S1, unofficial].
*   **High Dimensionality:** When $n \ge m$, the output is not a Reeb space approximation but a geometric subdivision [S1, unofficial]. The algorithm still computes, but the topological interpretation changes [S1, unofficial].

## Subtopics

### Jacobi Structure
An improvement over the Jacobi set that relates the Jacobi set directly to the Reeb space by capturing the exact location of topological change [S1, unofficial]. It includes 'regular sheets' connecting critical nodes, allowing it to capture topological elements (e.g., forking in multi-field topology) that the standard Jacobi set cannot represent [S1, unofficial]. It is extracted as the set of critical nodes in the [Multi-Dimensional Reeb Graph](9382-multi-dimensional-reeb-graph.md) (MDRG) [S1, unofficial].

### Layered Reeb Graph
An alternative approach for presenting the Reeb space of multiple scalar functions [S1, unofficial]. It differs from the MDRG by working directly with Jacobi sets rather than the Jacobi structure (which includes regular sheets) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Performance:** The JCN is better suited to parallelization than contour tree algorithms because each joint contour slab is constructed from smaller independent regions called fragments [S1, unofficial].
*   **Limitations:** The merge step in parallel implementations is the limiting factor for speedup [S1, unofficial].
*   **When to Use:** Suitable for visualizing and analyzing multivariate data where topological relationships between multiple scalar fields are of interest, such as in nuclear physics (scission datasets) or meteorology (hurricane data) [S1, unofficial].
*   **When Not to Use:** When a single-variable topological summary is sufficient (use [Reeb Graph](9315-reeb-graph.md) or [Contour Tree](9315-reeb-graph.md)) [S1, unofficial].

## Background
The Joint Contour Net was first presented as a discrete representation of the Reeb space by Carr et al. [53] [S1, unofficial]. It has been used in nuclear physics to visualize and analyze scission datasets, identifying the splitting of atomic nuclei into multiple parts using proton and neutron density fields [S1, unofficial]. It was also used to visually analyze data from Hurricane Isabel, mapping vertices to barycentric spatial coordinates to capture topological changes [S1, unofficial].
