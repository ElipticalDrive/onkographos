# Handle Size Measurement via Nonseparating Cuts

Also called: Reeb loop and cross loop measurement

## Overview
This method measures the geometric size of topological handles in a scalar field by computing two specific nonseparating loops: the Reeb loop and the cross loop [S1]. It solves the problem of quantifying handle prominence to guide topology simplification, ensuring that geometric changes to the volume are minimized [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A scalar field $F(x)$, its isosurface mesh $M$ at level set $F(x)=c$, and a Reeb cycle $C_R$ in the Reeb graph $R$ corresponding to a handle [S1].
*   **Output:** A handle size metric (scalar value) and the geometric definitions of the Reeb loop and cross loop [S1].

**Data Structures:**
*   **Isosurface Mesh $M$:** A weighted graph of vertices and edges representing the level set, with geometric coordinates for edge lengths [G].
*   **Reeb Cycle $C_R$:** A sequence of contours on $M$ that form a cycle in $R$ corresponding to the handle [S1].
*   **Shortest-Path State:** Distance maps and predecessor pointers initialized for Dijkstra's algorithm on the mesh graph [G].

**Steps:**

1.  **Identify the Reeb Cycle:** Locate the cycle $C_R$ in the Reeb graph $R$ corresponding to the handle to be measured [S1].
2.  **Construct the Reeb Loop ($L_{Reeb}$):**
    *   Select a contour $\gamma$ within the Reeb cycle $C_R$ [S1]. This contour is a nonseparating curve on the isosurface [S1].
    *   Cut the isosurface along $\gamma$, topologically transforming the handle region into a cylinder open at both ends with two boundary sets $A$ and $B$ [S1].
    *   Compute the shortest path on the isosurface mesh $M$ between any point in $A$ and any point in $B$ [S1].
    *   **Constraint:** The search for the shortest path must be strictly restricted to the region of the isolated handle associated with the Reeb cycle [S1]. This guarantees the loop matches the specific Reeb cycle [S1].
    *   Combine the computed shortest path with the segment of $\gamma$ it connects to form the Reeb loop $L_{Reeb}$ [S1]. This loop is locally nearly minimal because it closes by traversing along the contour [S1].
3.  **Construct the Cross Loop ($L_{Cross}$):**
    *   Identify the two sides $S_1$ and $S_2$ of the Reeb loop $L_{Reeb}$ on the isosurface [S1].
    *   Compute shortest paths from all points in $S_1$ to all points in $S_2$ on the isosurface mesh $M$ [S1].
    *   Among all shortest paths that form cycles when combined with $L_{Reeb}$, select the one with the minimum length as the cross loop $L_{Cross}$ [S1].
4.  **Calculate Handle Size:**
    *   Calculate the length of the Reeb loop, $|L_{Reeb}|$, and the cross loop, $|L_{Cross}|$ [S1]. The length corresponds to the extent of the cut along the surface necessary for loop closure [S1].
    *   The handle size $H$ is defined as:
        $$ H = \min(|L_{Reeb}|, |L_{Cross}|) $$
    *   **Alternative Metric:** The area of the spanning minimal surface bounded by the loop can be used instead of length if deemed more appropriate for the application [S1].
5.  **User Control and Filtering (Optional):**
    *   **Ratio Preservation:** To avoid removing long, skinny handles, preserve handles where the ratio $|L_{Reeb}| / |L_{Cross}|$ is large [S1].
    *   **Material Orientation:** Determine the orientation of any contour in the Reeb graph cycle to check if the ribbon cycle encloses a void ($F(x) \ge 0$) or encloses material ($F(x) < 0$) [S1]. This allows users to specify material addition or subtraction only by changing nodes with $F(x) < 0$ or $F(x) \ge 0$ [S1].

def dijkstra(adj, sources, targets, mask):
    """Standard Dijkstra's algorithm on a mesh graph."""
    dist = {v: float('inf') for v in adj}
    prev = {v: None for v in adj}
    dist.update({v: 0 for v in sources})
    pq = [(0, v) for v in sources]
    while pq:
        d, u = pq.pop(0)
        if u in targets:
            path = []
            curr = u
            while curr is not None:
                path.append(curr)
                curr = prev[curr]
            return path[::-1]
        if d > dist[u]: continue
        for v, w in adj[u]:
            if mask[v] and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                prev[v] = u
                pq.append((dist[v], v))
    return []

## Operating characteristics
*   **Time Complexity:** Dominated by the shortest path computations (Dijkstra's algorithm) on the isosurface mesh [G]. For a mesh with $V$ vertices and $E$ edges, each shortest path computation is $O(E + V \log V)$ using a binary heap [G]. Two such computations are performed per handle [S1].
*   **Memory Complexity:** $O(V + E)$ to store the mesh and distance maps [G].
*   **Strengths:** Provides a tight geometric measure of handle size [S1]. The use of shortest paths ensures the loops are locally minimal [S1]. The method allows for user control over topology simplification based on geometric properties (length vs. area) and material orientation [S1].
*   **Limitations:** Computationally expensive for large meshes due to multiple shortest path computations [G]. The quality of the measure depends on the resolution of the isosurface mesh [G]. The method assumes the Reeb graph is already computed [S1].
*   **When to use:** When simplifying isosurfaces while preserving significant topological features (handles) and minimizing geometric distortion [S1]. Particularly useful when distinguishing between "long skinny" handles and "short fat" handles is important [S1].
*   **When not to use:** For real-time applications where performance is critical and approximate topology simplification is acceptable [G]. If the scalar field is noisy, the Reeb graph may contain spurious cycles, leading to incorrect handle measurements [G].

## Background
The method was introduced by [S1] in the context of removing excess topology from isosurfaces. It builds on the concept of Reeb graphs for non-simply connected domains. The key insight is that a handle can be characterized by two nonseparating loops: one that follows the cycle of the handle (Reeb loop) and one that crosses it (cross loop) [S1]. The minimum of their lengths serves as a robust measure of the handle's "size" or "thickness" [S1]. This approach allows for more informed decisions about which handles to remove during topology simplification, compared to methods that rely solely on topological persistence or arbitrary geometric thresholds [S1].
