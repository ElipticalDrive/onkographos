# Total Euler Characteristic (TEC)

Also called: Total Euler Characteristic as a Noise Measure

## Overview
Total Euler Characteristic (TEC) is a noise level estimation metric for direct volume rendering transfer function design, defined as the L1-norm of the evolution curve of the Euler Characteristic across all possible isovalues [S1, unofficial]. It solves the problem of distinguishing true topological structures (islands and holes) from noise-induced speckles in rendered images, offering a more accurate noise assessment than gradient-based measures like Total Variation (TV) or Total Second Derivatives (TSD) [S1, unofficial]. Unlike its siblings, TEC approximates zero for vanishing noise even in scenes with significant true gradients and curvatures, making it superior for automated transfer function optimization [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An integer-valued image (2D) or volume (3D), typically 8-bit or 16-bit [S1, unofficial].
*   **Output:** A scalar value $TEC$ representing the total topological complexity across all isovalues [S1, unofficial].

**Data Structures:**
*   **Histogram $H$:** An array indexed by intensity value $I$. For integer data, the bin width is 1, covering the range $[0, I_{max}]$ [S1, unofficial].
*   **Accumulated Histogram $H_{acc}$:** Stores the cumulative Euler characteristic for each isovalue [S1, unofficial].

**Method:**
The method computes the Euler Characteristic $\chi(T)$ for every possible isovalue $T$ simultaneously using a single raster scan and a histogram-based accumulation strategy. The Euler Characteristic is defined as $\chi = \#vertices - \#edges + \#faces$ (in 2D) or extended to include cells in 3D, based on the Euler-Poincaré formula [S1, unofficial].

1.  **Initialize Histogram:** Create histogram $H$ with bins for all possible intensity values $I \in [0, I_{max}]$, initialized to zero [S1, unofficial].
2.  **Raster Scan:** Iterate over the image/volume using a sliding window.
    *   For 2D: Use a $2 \times 2$ neighborhood of pixels.
    *   For 3D: Use a $2 \times 2 \times 2$ neighborhood of voxels [S1, unofficial].
3.  **Update Histogram (Local Euler Contributions):** For each neighborhood, update the histogram bins corresponding to the topological elements becoming part of the super level set as the isovalue $T$ decreases from $I_{max}$ to $0$:
    *   **Vertices:** For each vertex (pixel/voxel) in the neighborhood with intensity $I_v$, increment $H[I_v]$ by 1. This represents the vertex entering the super level set when $T \le I_v$ [S1, unofficial].
    *   **Edges (2D) / Faces (3D):** For each edge (pair of pixels) or face (quad of voxels) in the neighborhood, let $I_{min}$ be the minimum intensity of its constituent vertices. Decrement $H[I_{min}]$ by 1. This represents the edge/face entering the super level set when $T \le I_{min}$ [S1, unofficial].
    *   **Faces (2D) / Cells (3D):** For each face (quad of pixels) or cell (hexahedron of voxels) in the neighborhood, let $I_{min}$ be the minimum intensity of its constituent vertices. Increment $H[I_{min}]$ by 1. This represents the face/cell entering the super level set when $T \le I_{min}$ [S1, unofficial].
    *   *Note:* In 3D, the pattern continues with alternating signs for higher-dimensional cells (edges decrement, faces increment, cells decrement, etc.) to maintain the Euler-Poincaré formula $\chi = \sum (-1)^k N_k$ [S1, unofficial].
4.  **Accumulate:** After the raster scan, compute the accumulated histogram $H_{acc}$ by summing $H$ from the highest bin downwards:
    $$ H_{acc}[T] = \sum_{i=T}^{I_{max}} H[i] $$
    $H_{acc}[T]$ now contains the Euler Characteristic $\chi(T)$ of the super level set at isovalue $T$ [S1, unofficial].
5.  **Compute TEC:** Sum the absolute values of the accumulated histogram bins:
    $$ TEC = \sum_{T=0}^{I_{max}} |H_{acc}[T]| $$
    This is the L1-norm of the Euler Characteristic evolution curve [S1, unofficial].

**Pseudocode:**
```python
def compute_tec(image):
    """
    Computes the Total Euler Characteristic for an integer-valued image or volume.
    image: 2D numpy array (H, W) or 3D numpy array (D, H, W) with integer dtype.
    Returns: float, the TEC value.
    """
    # Determine dimensions
    if image.ndim == 2:
        is_3d = False
        dims = image.shape
    elif image.ndim == 3:
        is_3d = True
        dims = image.shape
    else:
        raise ValueError("Image must be 2D or 3D")

    # Get intensity range
    min_val = image.min()
    max_val = image.max()
    
    # Initialize histogram. Size covers all possible integer values in the image.
    # Using a dictionary or offset array to handle arbitrary integer ranges if needed.
    # For standard 8/16-bit, a fixed size array is efficient.
    hist_size = max_val - min_val + 1
    H = [0] * hist_size
    
    # Helper to map intensity to histogram index
    def get_idx(val):
        return val - min_val

    # Define neighborhood structures
    # 2D: 2x2 window. Elements: 4 vertices, 4 edges, 1 face.
    # 3D: 2x2x2 window. Elements: 8 vertices, 12 edges, 6 faces, 1 cell.
    
    if is_3d:
        # 3D Implementation
        D, H_dim, W = dims
        # Iterate over 2x2x2 windows
        for d in range(D - 1):
            for h in range(H_dim - 1):
                for w in range(W - 1):
                    # Extract 2x2x2 block
                    block = image[d:d+2, h:h+2, w:w+2]
                    
                    # Vertices (8)
                    for val in block.flatten():
                        H[get_idx(val)] += 1
                    
                    # Edges (12)
                    # Edges are pairs of vertices. Min intensity determines entry.
                    # Horizontal edges in z-slice
                    for z in range(2):
                        for y in range(2):
                            edge_vals = [block[z, y, 0], block[z, y, 1]]
                            H[get_idx(min(edge_vals))] -= 1
                    # Vertical edges in y-direction
                    for z in range(2):
                        for x in range(2):
                            edge_vals = [block[z, 0, x], block[z, 1, x]]
                            H[get_idx(min(edge_vals))] -= 1
                    # Vertical edges in x-direction
                    for y in range(2):
                        for x in range(2):
                            edge_vals = [block[0, y, x], block[1, y, x]]
                            H[get_idx(min(edge_vals))] -= 1

                    # Faces (6)
                    # Faces are quads. Min intensity determines entry.
                    # XY faces (z=0, z=1)
                    for z in range(2):
                        face_vals = block[z, :, :].flatten()
                        H[get_idx(min(face_vals))] += 1
                    # XZ faces (y=0, y=1)
                    for y in range(2):
                        face_vals = block[:, y, :].flatten()
                        H[get_idx(min(face_vals))] += 1
                    # YZ faces (x=0, x=1)
                    for x in range(2):
                        face_vals = block[:, :, x].flatten()
                        H[get_idx(min(face_vals))] += 1

                    # Cell (1)
                    # The entire 2x2x2 block
                    cell_vals = block.flatten()
                    H[get_idx(min(cell_vals))] -= 1

    else:
        # 2D Implementation
        H_dim, W = dims
        for h in range(H_dim - 1):
            for w in range(W - 1):
                # Extract 2x2 block
                block = image[h:h+2, w:w+2]
                
                # Vertices (4)
                for val in block.flatten():
                    H[get_idx(val)] += 1
                
                # Edges (4)
                # Top and Bottom horizontal edges
                H[get_idx(min(block[0, 0], block[0, 1]))] -= 1
                H[get_idx(min(block[1, 0], block[1, 1]))] -= 1
                # Left and Right vertical edges
                H[get_idx(min(block[0, 0], block[1, 0]))] -= 1
                H[get_idx(min(block[0, 1], block[1, 1]))] -= 1
                
                # Face (1)
                H[get_idx(min(block.flatten()))] += 1

    # Accumulate histogram from highest bin downwards
    # H_acc[T] = sum(H[i] for i in T..max)
    # Note: H is indexed by intensity offset. 
    # We need to accumulate such that H_acc[i] contains the Euler char for isovalue = i + min_val
    
    # Reverse cumulative sum
    current_sum = 0
    H_acc = [0] * hist_size
    for i in range(hist_size - 1, -1, -1):
        current_sum += H[i]
        H_acc[i] = current_sum

    # Compute TEC: Sum of absolute values of accumulated histogram
    tec = sum(abs(val) for val in H_acc)
    
    return tec
```

**Parameters:**
*   **Data Type:** Integer-valued images (e.g., 8-bit or 16-bit) [S1, unofficial].
*   **Bin Width:** 1 for integer data [S1, unofficial].
*   **Dimensionality:** Can be computed in 2D (image-centric) or 3D (data-centric) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Numerical Inaccuracies:** At thin crests of phantoms (e.g., Marschner-Lobb), numerical inaccuracies can produce speckles, causing TEC to not respond with zero even in the absence of added noise [S1, unofficial].
*   **Floating Point Data:** Extending the algorithm to floating-point data is straightforward, but the approximation error must be analyzed with respect to the histogram bin width [S1, unofficial].
*   **View Dependency:** Image-centric (2D) TEC is dependent on the view angle, whereas data-centric (3D) TEC is not [S1, unofficial].

## Subtopics

### Image-Centric TEC
Computed on the 2D rendered image. Suitable for view-dependent transfer function design but suffers from view angle dependency [S1, unofficial].

### Data-Centric TEC
Computed on the 3D data volume. Avoids view angle dependency, providing a more robust noise measure for volume data [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Comparable to Total Variation (TV). In 2D, it samples four intensity points per pixel; in 3D, eight points per voxel. This is slightly higher than TV (3 samples) and TSD (5 samples) but remains linear with respect to the number of pixels/voxels [S1, unofficial].
*   **Memory Complexity:** Requires a histogram of size proportional to the intensity range ($I_{max} - I_{min}$). This is independent of the image/volume size [S1, unofficial].
*   **Strengths:** Superior to TV and TSD for scenes with many true gradients and curvatures because it better approximates zero for vanishing noise. It is more reflective of true noise levels and human perception of noise [S1, unofficial].
*   **Limitations:** Not perfectly zero for noise-free data due to numerical inaccuracies at thin crests. Requires integer data for exact computation; floating-point extension requires bin width analysis [S1, unofficial].
*   **When to Use:** Automated evaluation of direct volume renderings, controlling transfer function parameters, or smoothing operations, especially when true gradients are present [S1, unofficial].
*   **When Not to Use:** When view-independence is not required and computational resources are extremely limited (though TEC is still efficient), or when the data is floating-point and bin-width approximation errors are unacceptable without further analysis [S1, unofficial].

## Background
The Total Euler Characteristic method was presented by R. Wiemker in 2013, copyrighted by The Eurographics Association [S1, unofficial]. It builds on the Euler-Poincaré formula and the additivity of the Euler Characteristic, allowing for efficient computation via sliding windows [S1, unofficial]. The method is used for automated evaluation of direct volume renderings and may be added to the Contour Spectrum [S1, unofficial]. It addresses limitations of Total Variation (TV) and Total Second Derivatives (TSD), which over-estimate noise by interpreting true object gradients as noise [S1, unofficial].
