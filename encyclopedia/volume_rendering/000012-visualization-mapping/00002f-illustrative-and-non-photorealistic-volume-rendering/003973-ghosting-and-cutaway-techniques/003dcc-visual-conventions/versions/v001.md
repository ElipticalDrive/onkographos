# Visual Conventions

Also called: Boxes, Arrows, Fans

## Overview
Visual Conventions are auxiliary geometric overlays used in illustrative volume rendering to clarify the spatial relationship between a **Selection** (the object of interest) and its **Ghost** (the original position) [S1]. Unlike photorealistic rendering, these conventions explicitly depict transformations such as translation, orientation, or alternative states, enhancing the communicative power of the visualization [S1]. They are distinct from siblings like [Feature Halos](799-feature-halos.md) which emphasize boundaries, or [Context-Preserving Volume Rendering](801-context-preserving-volume-rendering.md) which focuses on background opacity; Visual Conventions add explicit semantic geometry [S1].

## How it works
Visual Conventions operate on the logical model defined in [Ghosting and Cutaway Techniques](8497-ghosting-and-cutaway-techniques.md), where the volume is decomposed into Selection, Ghost, and Background [S1]. The conventions are rendered as static geometric primitives overlaid on the volume data, avoiding costly per-voxel importance compositing [S1].

### Inputs and Outputs
*   **Inputs**: 3D coordinates of the Selection object, 3D coordinates of the Ghost object (original position), camera view matrix, and projection matrix.
*   **Outputs**: Screen-space 2D coordinates for rendering auxiliary geometry (boxes, arrows, fans).

### Data Structures
The method requires storing the bounding volumes of the Selection and Ghost.
*   **Selection Bounding Box**: Axis-aligned or oriented bounding box defined by min/max corners in world space.
*   **Ghost Bounding Box**: Axis-aligned or oriented bounding box defined by min/max corners in world space.
*   **Screen-Space Bounding Rectangle**: Projected 2D rectangle for each object, used for Fan construction.

### Steps
1.  **Compute Screen-Space Projections**: Project the 3D bounding boxes of the Selection and Ghost onto the image plane using the current camera view and projection matrices.
2.  **Render Boxes**: If the user chooses the Box convention, render the 3D bounding box of the Selection.
    *   *Note*: Boxes provide orientation cues but can be distracting during presentation [S1].
3.  **Render Arrows**: If the user chooses the Arrow convention, draw a curve from the Ghost position to the Selection position.
    *   Calculate the screen-space depth difference ($\Delta z_{screen}$) between the Ghost and Selection.
    *   Use $\Delta z_{screen}$ to control the curvature of the arrow. A larger depth difference allows for a straighter arrow; a smaller difference results in a bent arrow to avoid visual ambiguity when projections are nearby [S1].
4.  **Render Fans**: If the user chooses the Fan convention, construct a shape connecting the screen-space bounding rectangles of the Ghost and Selection.
    *   Identify the screen-space bounding rectangle for the Ghost ($R_{ghost}$) and the Selection ($R_{selection}$).
    *   Connect the corresponding corners or edges of $R_{ghost}$ and $R_{selection}$ to form a connected pair of shapes (e.g., rectangles or circles) [S1].
    *   This indicates an alternative or detailed depiction of the structure [S1].

### Parameters
*   **Arrow Curvature Factor**: A scalar controlling the bend of the arrow based on screen-space depth difference [S1].
*   **Box Opacity**: Controls visibility of bounding boxes to prevent occlusion of details [S1].

### Edge Cases and Pitfalls
*   **Short Arrows**: If the Selection and Ghost project to nearly identical positions in screen space, standard linear arrows become too short to perceive. The method uses screen-space depth difference to bend the arrow, creating the "bent arrow" convention common in illustrations [S1].
*   **Occlusion**: Bounding boxes can occlude important details of the Selection. They are most useful during design/interaction and less so during final presentation [S1].

### Pseudocode

```python
def render_visual_conventions(selection_bbox, ghost_bbox, view_matrix, proj_matrix):
    """
    Renders Boxes, Arrows, or Fans based on user selection.
    selection_bbox: 3D bounding box of the current object position.
    ghost_bbox: 3D bounding box of the original object position.
    view_matrix: Camera view matrix.
    proj_matrix: Camera projection matrix.
    """
    # Project 3D bounding boxes to screen space
    screen_rect_selection = project_bbox_to_screen(selection_bbox, view_matrix, proj_matrix)
    screen_rect_ghost = project_bbox_to_screen(ghost_bbox, view_matrix, proj_matrix)
    
    # Calculate screen-space depth difference for arrow curvature
    # Depth is typically the Z-component in clip space or normalized device coordinates
    depth_selection = get_screen_depth(selection_bbox, view_matrix, proj_matrix)
    depth_ghost = get_screen_depth(ghost_bbox, view_matrix, proj_matrix)
    depth_diff = abs(depth_selection - depth_ghost)
    
    if user_prefers("Boxes"):
        render_3d_box(selection_bbox, view_matrix, proj_matrix)
        
    elif user_prefers("Arrows"):
        # Draw arrow from ghost center to selection center
        start_point = get_center(ghost_bbox)
        end_point = get_center(selection_bbox)
        
        # Control curvature based on depth difference
        # If depth_diff is small, increase curvature to avoid short/flat arrows
        curvature = map_depth_diff_to_curvature(depth_diff)
        draw_bent_arrow(start_point, end_point, curvature, view_matrix, proj_matrix)
        
    elif user_prefers("Fans"):
        # Connect screen-space bounding rectangles
        # Construct a shape connecting screen_rect_ghost and screen_rect_selection
        draw_fan(screen_rect_ghost, screen_rect_selection)

def project_bbox_to_screen(bbox, view_matrix, proj_matrix):
    """Projects the 8 corners of a 3D bounding box to 2D screen space and returns the bounding rectangle."""
    corners = get_bbox_corners(bbox)
    projected_corners = []
    for corner in corners:
        # Transform to clip space
        clip_pos = proj_matrix @ view_matrix @ corner
        # Perspective divide
        ndc_pos = clip_pos / clip_pos.w
        # Map to screen coordinates
        screen_pos = ndc_to_screen(ndc_pos)
        projected_corners.append(screen_pos)
    
    min_x = min(c.x for c in projected_corners)
    min_y = min(c.y for c in projected_corners)
    max_x = max(c.x for c in projected_corners)
    max_y = max(c.y for c in projected_corners)
    
    return Rectangle(min_x, min_y, max_x, max_y)

def map_depth_diff_to_curvature(depth_diff):
    """
    Maps screen-space depth difference to an arrow curvature factor.
    Smaller depth difference -> Higher curvature (bent arrow).
    Larger depth difference -> Lower curvature (straighter arrow).
    """
    # Implementation detail: [G]
    # A simple inverse mapping or sigmoid function can be used.
    # Example: curvature = 1.0 / (1.0 + depth_diff)
    return 1.0 / (1.0 + depth_diff)
```

## Subtopics

### Marker Placement
Marker Placement is a variant where cone-shaped markers are placed within the data set to aid in discussions or to locate features after parameter changes [S2, unofficial]. Unlike Boxes, Arrows, and Fans which relate Selection and Ghost, Markers are static or interactive anchors within the volume. They can be moved and oriented arbitrarily using a pointer, allowing users to highlight specific regions of interest without altering the volume rendering itself [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per convention type per object, as it involves projecting bounding boxes and drawing simple geometric primitives. It does not depend on voxel count.
*   **Memory Complexity**: $O(1)$ auxiliary memory for storing bounding box coordinates and screen-space rectangles.
*   **Strengths**: Computationally inexpensive; enhances interpretability of complex transformations; supports interactive design workflows.
*   **Limitations**: Can be distracting during final presentation (especially Boxes); relies on correct occlusion handling to be effective [S1].
*   **When to use**: When illustrating movement, insertion, or alternative states of objects within a volume.
*   **When not to use**: When photorealism is required or when the conventions would occlude critical data details.

## Background
Visual Conventions originate from the field of volume illustration, where the goal is to create expressive, communicative visualizations rather than strictly photorealistic ones. The specific techniques of Boxes, Arrows, and Fans were introduced in the VolumeShop system [S1]. The system was designed to provide users with interactive tools to create illustrative volumes, leveraging these conventions to clarify the role and transformation of objects within the data set [S1]. Marker Placement was also explored in the context of user-friendly volume data set exploration, particularly in immersive environments like the Cave [S2, unofficial].
