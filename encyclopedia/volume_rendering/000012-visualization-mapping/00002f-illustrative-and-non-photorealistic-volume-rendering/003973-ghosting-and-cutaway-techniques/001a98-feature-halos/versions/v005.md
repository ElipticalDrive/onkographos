# Feature Halos

Also called: Auxiliary volume halos, Feature Halos Effect, Halo Effects, Null Halos

## Overview
Feature Halos is an illustrative volume rendering technique that enhances depth perception by generating dark, opaque regions around structures of interest, thereby obscuring background elements that would otherwise cause visual clutter [S2][S3, unofficial]. Unlike standard photorealistic rendering, this method uses view-dependent darkening and opacity increases in planes orthogonal to the viewing direction to create a visual separation around features, making foreground structures stand out more clearly [S2][S3, unofficial].

## How it works
The method operates during the illumination/compositing pass of volume rendering [G]. It computes a halo intensity value for each voxel based on the spatial relationship between that voxel and its neighbors, specifically targeting empty regions adjacent to strong features [S2][S3, unofficial].

### Inputs and Outputs
*   **Input:**
    *   Volume data $V$ (scalar field) [G].
    *   View direction vector $V$ (normalized) [S2][S3, unofficial].
    *   Parameters: $k_{hpe}$ (halo potential exponent, typically 1.0), $k_{hse}$ (halo separation exponent, typically 2.0) [S2][S3, unofficial].
*   **Output:**
    *   Modified color $C'$ and opacity $\alpha'$ for each voxel, where halos are darker and more opaque than the base volume rendering [S2][S3, unofficial].

### Data Structures
*   **Volume Grid:** Standard 3D array of scalar values [G].
*   **Gradient Field:** 3D array of 3D vectors, computed via finite differences [G].
*   **Halo Field:** 3D array of floats, storing the computed halo influence $h(i)$ for each voxel [G].

### Algorithm Steps

1.  **Compute Gradient Field:**
    Calculate the gradient $\nabla_f(P)$ at every voxel $P$ in the volume [G].

2.  **Initialize Halo Field:**
    Create a halo field $H$ of the same dimensions as the volume, initialized to zero [G].

3.  **Compute Halo Influence:**
    For each voxel $i$ at position $P_i$:
    a. Initialize $h(i) = 0$ [G].
    b. Iterate over a specified neighborhood of voxels $n$ at positions $P_n$ [S2][S3, unofficial].
    c. For each neighbor $n$:
        i. Calculate the displacement vector $D = P_i - P_n$ and distance $d = \|D\|$ [S2][S3, unofficial].
        ii. Calculate the normalized direction $u = D / d$ [S2][S3, unofficial].
        iii. Compute the halo potential $h_n$ for the neighbor:
        $$ h_n = \left( \nabla_f(P_n) \cdot u \right)^{k_{hpe}} (1 - \nabla_f(P_n) \cdot V)^{k_{hse}} $$
        [S3, unofficial]
        iv. Add the distance-weighted influence to the current voxel's halo field:
        $$ h(i) \leftarrow h(i) + \frac{h_n}{d^2} $$
        [S2][S3, unofficial]
    d. Weight the accumulated halo influence by the complement of the current voxel's gradient magnitude to restrict halos to less interesting (low-gradient) regions:
    $$ h(i) \leftarrow h(i) \cdot (1 - \|\nabla_f(P_i)\|) $$
    [S2][S3, unofficial]

4.  **Apply Visual Appearance:**
    For each voxel $i$, adjust the base color $C$ and opacity $\alpha$ computed from the volume transfer function:
    a. Decrease brightness: $C' = C \cdot (1 - k_{dark} \cdot h(i))$, where $k_{dark}$ is a scalar controlling the darkness of the halo [S2][S3, unofficial].
    b. Increase opacity: $\alpha' = \min(1.0, \alpha + k_{opaque} \cdot h(i))$, where $k_{opaque}$ is a scalar controlling the opacity increase [S2][S3, unofficial].

5.  **Composite:**
    Perform standard volume compositing (e.g., front-to-back or back-to-front) using the modified $C'$ and $\alpha'$ values [G].

### Pseudocode

```python
import numpy as np

def compute_feature_halos(volume, view_direction, k_hpe=1.0, k_hse=2.0):
    """
    Compute feature halos for volume rendering.
    
    Args:
        volume: 3D numpy array of scalar values.
        view_direction: 3D numpy array, normalized view vector.
        k_hpe: Halo potential exponent.
        k_hse: Halo separation exponent.
        
    Returns:
        halo_field: 3D numpy array of halo intensities.
    """
    # Step 1: Compute gradient field
    grad = np.gradient(volume) # Returns tuple of 3 arrays (dz, dy, dx)
    gradient_magnitude = np.sqrt(sum(g**2 for g in grad))
    max_grad = np.max(gradient_magnitude)
    normalized_grad_mag = gradient_magnitude / max_grad if max_grad > 0 else gradient_magnitude
    
    # Step 2: Initialize halo field
    halo_field = np.zeros_like(volume)
    
    # Neighborhood radius (specified neighborhood) [G]
    radius = 1
    neighborhood_indices = np.arange(-radius, radius + 1)
    
    vx, vy, vz = view_direction
    
    # Step 3: Compute halo influence
    for z in range(volume.shape[0]):
        for y in range(volume.shape[1]):
            for x in range(volume.shape[2]):
                h_i = 0.0
                current_grad_mag = normalized_grad_mag[z, y, x]
                
                for dz_off in neighborhood_indices:
                    for dy_off in neighborhood_indices:
                        for dx_off in neighborhood_indices:
                            if dz_off == 0 and dy_off == 0 and dx_off == 0:
                                continue
                                
                            nz, ny, nx = z + dz_off, y + dy_off, x + dx_off
                            
                            if not (0 <= nz < volume.shape[0] and 
                                    0 <= ny < volume.shape[1] and 
                                    0 <= nx < volume.shape[2]):
                                continue
                                
                            dx_vec, dy_vec, dz_vec = dx_off, dy_off, dz_off
                            dist_sq = dx_vec**2 + dy_vec**2 + dz_vec**2
                            dist = np.sqrt(dist_sq)
                            
                            ux, uy, uz = dx_vec / dist, dy_vec / dist, dz_vec / dist
                            
                            grad_nz, grad_ny, grad_nx = grad[0][nz, ny, nx], grad[1][nz, ny, nx], grad[2][nz, ny, nx]
                            
                            dot_product = grad_nz * ux + grad_ny * uy + grad_nx * uz
                            cos_theta = grad_nz * vx + grad_ny * vy + grad_nx * vz
                            
                            # Halo potential formula from [S3, unofficial]
                            potential = max(0.0, dot_product) ** k_hpe
                            view_factor = (1.0 - cos_theta) ** k_hse
                            h_n = potential * view_factor
                            
                            h_i += h_n / dist_sq
                            
                halo_field[z, y, x] = h_i * (1.0 - current_grad_mag)
                
    return halo_field

def apply_halos(base_color, base_opacity, halo_field, k_dark=0.5, k_opaque=0.5):
    """
    Apply halo effects to color and opacity.
    
    Args:
        base_color: RGB array.
        base_opacity: Float.
        halo_field: Float halo intensity.
        k_dark: Scalar for brightness reduction.
        k_opaque: Scalar for opacity increase.
        
    Returns:
        modified_color, modified_opacity
    """
    modified_color = base_color * (1.0 - k_dark * halo_field)
    modified_opacity = np.minimum(1.0, base_opacity + k_opaque * halo_field)
    return modified_color, modified_opacity
```

### Parameters
*   $k_{hpe}$: Controls how directly the neighbor's gradient must be oriented toward the current location. Typical value: 1.0 [S2][S3, unofficial].
*   $k_{hse}$: Controls how tightly halos are kept in the plane orthogonal to the view direction. Typical value: 2.0 [S2][S3, unofficial].
*   $k_{dark}$: Scalar controlling the amount of brightness reduction in halo regions. Not given in the sources.
*   $k_{opaque}$: Scalar controlling the amount of opacity increase in halo regions. Not given in the sources.

### Edge Cases and Pitfalls
*   **Self-Obscuration:** Since halos are view-dependent and computed based on the relationship between neighbors and the current voxel, features do not cast halos on themselves. This avoids the self-obscuration issues present in other methods like Line Integral Convolution (LIC) [S2][S3, unofficial].
*   **Gradient Normalization:** The gradient magnitude must be normalized to [0,1] before being used in the weighting term $(1 - \|\nabla_f(P_i)\|)$ to ensure consistent behavior across different datasets [G].
*   **Boundary Conditions:** Neighbors outside the volume bounds must be handled, typically by ignoring them or padding with zeros [G].
*   **Performance:** The naive implementation is $O(N \cdot R^3)$ where $N$ is the number of voxels and $R$ is the neighborhood radius. Optimization via separable filters or GPU parallelization is recommended for large volumes [G].

## Subtopics

### Dual-layer Halo Splatting
A variant that uses a dual-layer splat presentation: an inner core for the primary structure and an outer halo for softer support [S6, unofficial]. The inner core is rendered as the primary measured structure, while the outer halo is rendered as a softer support shell [S6, unofficial]. The intensity of the halo can be tuned using a "Halo Strength" slider, which can be reduced to zero [S6, unofficial].

### Volumetric Halos
A technique that enhances depth perception by processing the volume model in view-aligned slices to generate halos around structures of interest, using hue changes rather than just brightening/darkening [S1, unofficial]. The steps are: 1) Classify structures to highlight based on density, direction, and position, and place seeds around them; 2) Generate the halo region of influence by filtering the seeds; 3) Assign colors and opacities to the halo regions and composite them with the volume rendering [S1, unofficial]. Unlike previous techniques that only brighten or darken color, this approach considers hue changes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot R^3)$ for a naive implementation, where $N$ is the number of voxels and $R$ is the neighborhood radius. Can be optimized to $O(N)$ with separable filters or GPU acceleration [G].
*   **Memory Complexity:** $O(N)$ for storing the gradient field and halo field [G].
*   **Measured Performance:** In medical volume rendering (e.g., liver and kidneys), halos make foreground structures stand out more clearly [S2][S3, unofficial].
*   **Strengths:** Enhances depth perception, reduces visual clutter from background elements, view-dependent (no self-obscuration), applicable to any type of data [S2][S3, unofficial].
*   **Limitations:** View-dependent (halos change with camera angle), requires gradient computation, may obscure fine details if parameters are not tuned correctly [G].
*   **When to Use:** When depth perception is critical and background clutter is a problem, especially in medical or scientific visualization [G].
*   **When Not to Use:** When photorealism is required, or when performance is extremely constrained and gradient computation is prohibitive [G].

## Background
Feature Halos were introduced in non-photorealistic rendering literature [S2][S3, unofficial]. The technique builds on earlier work by Interrante and Grosch who applied halos to flow visualization [S1, unofficial]. It is part of the broader family of Ghosting and Cutaway Techniques [8497-ghosting-and-cutaway-techniques.md].
