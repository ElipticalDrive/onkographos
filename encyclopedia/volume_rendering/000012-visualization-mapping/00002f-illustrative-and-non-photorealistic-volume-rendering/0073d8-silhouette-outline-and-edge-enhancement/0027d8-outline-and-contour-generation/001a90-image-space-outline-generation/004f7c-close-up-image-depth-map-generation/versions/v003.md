# Close-Up Image Depth Map Generation

Also called: Local Edge Histogram CGDM, Occlusion-based CGDM

## Overview
A method to generate a Cumulative Gradient Depth Map (CGDM) for close-up images (defined as scenes with no or multiple vanishing points) by leveraging occlusion cues and local edge histograms [S1]. It determines spatial relationships by counting edge amounts, where regions with fewer edges are considered farther away [S1].

## How it works
**Inputs:** A 2D image $I$ [S1].
**Outputs:** An 8-bit CGDM $D_f$ of the same dimensions as $I$ [S1].

**Data Structures:**
- $E$: Binary edge map (same size as $I$), where 1 indicates an edge, 0 otherwise [S1].
- $B_{ij}$: A grid of 5×5 pixel blocks covering $I$ [S1].
- $N_{ij}$: Integer count of edge pixels in block $B_{ij}$ [S1].
- $N_{av}$: Average edge count per block across the grid [S1].
- $M$: Total number of "main blocks" identified [S1].
- $D_i$: Circular depth gradient map for the $i$-th main block [S1].
- $N_{i0}$: Edge count of the $i$-th main block [S1].

**Steps:**
1. Extract edges from $I$ using the Canny algorithm to produce binary map $E$ [S1].
2. Divide $E$ into a grid of 5×5 pixel blocks [S1].
3. Count the number of edge pixels $N_{ij}$ in each block $B_{ij}$ [S1].
4. Compute the average edge count $N_{av}$ across all blocks [S1].
5. Identify blocks where $N_{ij} > N_{av}$ as "main blocks" [S1]. Let the set of main blocks be indexed $i=1 \dots M$, with edge counts $N_{10}, N_{20}, \dots, N_{M0}$ [S1].
6. For each main block $i$:
   - Define a circular depth gradient map $D_i$ centered at the center of block $B_{ij}$ [S1].
   - Assign pixel value 255 at the center [S1].
   - Assign pixel value 0 at the circumference [S1].
   - Decrease pixel values evenly (linearly) from the center to the circumference [S1].
   - Determine the radius $R$. The source states an optimized radius is half the length (or width) of the image [S1].
7. Fuse all $D_i$ maps into the final CGDM $D_f$ using the weighted sum formula [S1]:
   $$ D_f = \sum_{i=1}^{M} \left( D_i \times \frac{N_{i0}}{\sum_{j=1}^{M} N_{j0}} \right) $$

**Pseudocode:**
```python
def generate_close_up_cgdm(image: list[list[int]]) -> list[list[int]]:
    # 1. Edge Extraction
    # Apply standard Canny edge detection to produce binary edge map E [G]
    edges = compute_canny_edges(image)
    H, W = len(edges), len(edges[0])
    
    # 2. Block Division and Counting
    BLOCK_H, BLOCK_W = 5, 5
    grid_h = H // BLOCK_H
    grid_w = W // BLOCK_W
    
    # Handle non-divisible dimensions by truncating to full blocks [G]
    valid_h = grid_h * BLOCK_H
    valid_w = grid_w * BLOCK_W
    
    block_counts = [[0] * grid_w for _ in range(grid_h)]
    for i in range(grid_h):
        for j in range(grid_w):
            count = 0
            for y in range(i * BLOCK_H, (i + 1) * BLOCK_H):
                for x in range(j * BLOCK_W, (j + 1) * BLOCK_W):
                    count += edges[y][x]
            block_counts[i][j] = count
            
    # 3. Average and Main Block Identification
    total_blocks = grid_h * grid_w
    N_av = sum(sum(row) for row in block_counts) / total_blocks if total_blocks > 0 else 0
    
    main_blocks = []
    for i in range(grid_h):
        for j in range(grid_w):
            if block_counts[i][j] > N_av:
                main_blocks.append((i, j, block_counts[i][j]))
                
    M = len(main_blocks)
    if M == 0:
        return [[0] * W for _ in range(H)] # Fallback for no main blocks [G]
        
    # 4. Generate Individual CGDMs and Sum
    R = min(H, W) / 2.0
    total_main_edges = sum(nb[2] for nb in main_blocks)
    
    fused_d = [[0.0] * W for _ in range(H)]
    
    for i, j, n_k0 in main_blocks:
        cy = (i + 0.5) * BLOCK_H
        cx = (j + 0.5) * BLOCK_W
        
        weight = n_k0 / total_main_edges
        
        for y in range(H):
            for x in range(W):
                dist = ((y - cy)**2 + (x - cx)**2)**0.5
                if dist <= R:
                    # Linear decrease from 255 at center to 0 at circumference
                    val = 255.0 * (1.0 - dist / R)
                    fused_d[y][x] += val * weight
                    
    # Convert to 8-bit
    return [[int(min(max(val, 0), 255)) for val in row] for row in fused_d]
```

**Parameters:**
- Block size: 5×5 pixels [S1].
- Radius $R$: Half the length or width of the image [S1].
- Center value: 255 [S1].
- Circumference value: 0 [S1].
- Gradient type: Linear/even decrease [S1].

**Edge Cases and Pitfalls:**
- **Image Dimensions:** If image dimensions are not divisible by 5, block boundaries are ambiguous. The source does not specify padding or cropping [S1]. Implementation must handle this by truncating or padding [G].
- **No Main Blocks:** If no block has edge count $> N_{av}$, $M=0$. The formula is undefined. A fallback returning a zero map is required [G].
- **Circle Boundary:** The circular gradient extends beyond the block. The source states the CGDM is fused from these circles. It does not specify if values outside the circle radius $R$ from the block center are zero. The pseudocode assumes zero outside $R$ [G].
- **Precision:** The source uses 8-bit values (0–255). Intermediate calculations should use float to prevent quantization errors during fusion [G].

## Subtopics

### [Perspective View Depth Map Generation](14031-perspective-view-depth-map-generation.md)
Generates a CGDM for perspective view images by calculating separate horizontal and vertical depth gradients based on distance from a detected vanishing point. It is chosen when the scene exhibits a single clear convergence point, distinguishing it from this method which relies on local occlusion cues rather than global geometric convergence.

### [Distant View Depth Map Generation](#distant-view-depth-map-generation)
Generates a CGDM for distant views with infinite-distance horizons [S1]. It is chosen when the scene represents a sky/land horizon at extreme distance, distinguishing it from this method which handles moderate-distance close-up scenes without global perspective distortion [S1].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Simple, fast, relies on local occlusion cues which are robust for close-up scenes without global perspective [S1].
- **Limitations:** Discrete block structure may cause artifacts at block boundaries. Radius is fixed relative to image size, not object size. Does not handle perspective distortion explicitly [S1].
- **When to Use:** Close-up images with no or multiple vanishing points [S1].
- **When Not to Use:** Perspective views with a single vanishing point or distant views with infinite-distance horizons [S1].

## Background
Originated in the context of holographic 3D display using depth maps generated by 2D-to-3D rendering [S1]. It builds on the observation that regions with fewer edges are generally farther away in close-up scenes [S1].
