# Tube Outline Effect

Also called: Tube Outline

## Overview
The Tube Outline Effect is a boundary enhancement technique that constructs a tubular contour around volumetric features to clarify borders and assist in feature identification relative to the view direction [S1, unofficial]. Unlike image-space outline methods that operate on prerendered images, this method operates directly on 3-D field data and meshes within a visualization pipeline [S1, unofficial]. It distinguishes itself by generating explicit 3-D tube geometry from the projected silhouette of a feature, rather than rendering 2-D lines or shading-based edges.

## How it works
**Inputs and Outputs**
*   **Input:** A selected feature (defined by its exterior face-points and edges) on an unstructured mesh; camera projection plane vector from the visualization environment (e.g., ParaView) [S1, unofficial].
*   **Output:** A set of cylindrical tube segments added to the unstructured mesh, colored by a user-defined intensity value [S1, unofficial].

**Data Structures**
Three uniform square grids are constructed for the projection plane. In the reference implementation, these are $100 \times 100$ [S1, unofficial].
1.  `CoveredCells`: Boolean grid. Marks cells intersected by exterior feature edges.
2.  `HeightMap`: Integer/Float grid. Stores the highest z-value (closest to view plane) of intersecting edges for each cell.
3.  `VisitedCells`: Boolean grid. Marks cells traversed during contour extraction.

**Parameters**
*   Grid resolution: $100 \times 100$ (reference implementation) [S1, unofficial].
*   Tube thickness: User-defined [S1, unofficial].
*   Color value/intensity: User-defined [S1, unofficial].
*   Number of sides per cylinder segment: User-defined [S1, unofficial].
*   DCT smoothing parameters: User-defined [S1, unofficial].

**Algorithm Steps**

1.  **Coordinate Transformation:** Retrieve the camera projection plane normal vector $\mathbf{n}$ from the visualization environment. Apply a homogeneous transform to all exterior face-points of the selected feature such that $\mathbf{n}$ aligns with the local z-axis [S1, unofficial].
2.  **Grid Initialization:** Construct `CoveredCells`, `VisitedCells`, and `HeightMap` grids of specified resolution, initialized to false/zero [S1, unofficial].
3.  **Projection and Marking:** Iterate through all exterior feature edges. For each edge:
    *   Mark all grid cells intersected by the edge in `CoveredCells` [S1, unofficial].
    *   In `HeightMap`, assign the maximum z-value of the intersecting edge to the corresponding cells [S1, unofficial].
4.  **Connectivity Cleanup:** Remove weakly connected cells from `CoveredCells`. A cell is weakly connected if it is marked but has fewer than two marked face-neighbors. Repeat this removal until all remaining marked cells in `CoveredCells` are strongly connected (forming a single closed loop or component) [S1, unofficial].
5.  **Contour Traversal:**
    *   Select an exterior marked cell in `CoveredCells` as the seed point [S1, unofficial].
    *   Traverse the grid in a counter-clockwise fashion between face-neighboring marked cells in `CoveredCells`.
    *   Mark each newly visited cell in `VisitedCells` [S1, unofficial].
    *   Terminate when a previously visited cell is reached (typically the seed point) [S1, unofficial].
6.  **Contour Extraction:** Obtain the closed contour from the coordinates of marked cells in `VisitedCells` and their corresponding z-values from `HeightMap` [S1, unofficial].
7.  **Inverse Transformation:** Transform the extracted bounding contour points back into the global coordinate system [S1, unofficial].
8.  **Smoothing:** Apply a Discrete Cosine Transform (DCT) filter to the contour to remove high-frequency components resulting from the rectilinear grid mapping [S1, unofficial].
9.  **Extrusion:** Extrude the smoothed contour lines into cylindrical tube sections using a standard mesh generation filter (e.g., VTK) [S1, unofficial].
10. **Rendering:** Add the tube contour to the unstructured mesh and apply the user-defined color/intensity [S1, unofficial].

**Pseudocode**

```python
def tube_outline_effect(feature, camera_normal, grid_size=100, tube_radius=1.0, tube_sides=12, smoothing_cutoff=0.5):
    """
    Generates a tube outline for a feature based on its projection onto the view plane.
    
    Args:
        feature: Object containing exterior_face_points and exterior_face_edges.
        camera_normal: 3D vector representing the camera projection plane normal.
        grid_size: Resolution of the uniform square grids.
        tube_radius: Thickness of the resulting tube.
        tube_sides: Number of sides for the cylindrical segments.
        smoothing_cutoff: Cutoff for DCT smoothing (0.0 to 1.0).
        
    Returns:
        List of tube mesh segments to be added to the scene.
    """
    
    # 1. Coordinate Transformation
    # Construct rotation matrix R to align camera_normal with local Z axis (0,0,1)
    R = rotation_matrix_to_align(camera_normal, [0, 0, 1])
    
    # Transform exterior face points to local coordinates
    local_points = [apply_transform(R, p) for p in feature.exterior_face_points]
    
    # 2. Grid Initialization
    covered_cells = [[False for _ in range(grid_size)] for _ in range(grid_size)]
    height_map = [[0.0 for _ in range(grid_size)] for _ in range(grid_size)]
    visited_cells = [[False for _ in range(grid_size)] for _ in range(grid_size)]
    
    # 3. Projection and Marking
    for edge in feature.exterior_face_edges:
        # Determine the segment of the edge in local coordinates
        p1_local = apply_transform(R, edge.start_point)
        p2_local = apply_transform(R, edge.end_point)
        
        # Intersect edge with grid cells
        intersected_cells = get_intersected_cells(p1_local, p2_local, grid_size)
        
        for (x, y) in intersected_cells:
            covered_cells[x][y] = True
            # Assign greatest z-value of overlapping cells
            z_max = max(p1_local.z, p2_local.z)
            if z_max > height_map[x][y]:
                height_map[x][y] = z_max
                
    # 4. Connectivity Cleanup
    # Remove weakly connected cells (marked cells with only one marked face-neighbor)
    changed = True
    while changed:
        changed = False
        weakly_connected = []
        for x in range(grid_size):
            for y in range(grid_size):
                if covered_cells[x][y]:
                    neighbors = get_face_neighbors(x, y, grid_size)
                    marked_neighbors = sum(1 for nx, ny in neighbors if covered_cells[nx][ny])
                    if marked_neighbors < 2:
                        weakly_connected.append((x, y))
        
        for (x, y) in weakly_connected:
            covered_cells[x][y] = False
            changed = True
            
    # 5. Contour Traversal
    # Find an exterior marked cell as seed
    seed = find_exterior_marked_cell(covered_cells, grid_size)
    if not seed:
        return [] # No contour found
        
    start_x, start_y = seed
    path = []
    current_x, current_y = start_x, start_y
    visited_cells[start_x][start_y] = True
    path.append((start_x, start_y))
    
    # Traverse counter-clockwise
    # Note: Direction logic depends on grid orientation; standard CCW traversal
    # checks neighbors in order: Right, Up, Left, Down (or similar relative to current direction)
    direction = [0, -1] # Initial direction, e.g., moving "up" in grid indices
    steps = 0
    max_steps = grid_size * grid_size # Safety break
    
    while steps < max_steps:
        # Move to next neighbor in CCW order
        next_x, next_y, new_direction = get_next_ccw_neighbor(current_x, current_y, direction, covered_cells, grid_size)
        
        if next_x == start_x and next_y == start_y:
            # Completed loop
            break
            
        if covered_cells[next_x][next_y]:
            visited_cells[next_x][next_y] = True
            path.append((next_x, next_y))
            current_x, current_y = next_x, next_y
            direction = new_direction
            steps += 1
        else:
            # Should not happen if contour is closed and valid
            break
            
    # 6. Contour Extraction
    # Get 3D points from grid indices and height map
    contour_points_2d = []
    for (x, y) in path:
        z = height_map[x][y]
        # Convert grid index to continuous coordinate
        coord_x = x / grid_size
        coord_y = y / grid_size
        contour_points_2d.append([coord_x, coord_y, z])
        
    # 7. Inverse Transformation
    R_inv = inverse_matrix(R)
    global_contour_points = [apply_transform(R_inv, p) for p in contour_points_2d]
    
    # 8. Smoothing
    smoothed_points = dct_smooth(global_contour_points, cutoff=smoothing_cutoff)
    
    # 9. Extrusion
    # Create tube mesh from smoothed points
    tubes = create_tube_mesh(smoothed_points, radius=tube_radius, sides=tube_sides)
    
    # 10. Rendering
    # Apply color/intensity (handled by renderer)
    return tubes
```

**Edge Cases and Pitfalls**
*   **Degenerate Features:** If the feature has no exterior edges or is fully enclosed, no contour is generated [S1, unofficial].
*   **Weak Connectivity:** The cleanup step may remove valid parts of the contour if the feature's projection is fragmented. The algorithm assumes the feature projects to a single connected component [S1, unofficial].
*   **Grid Resolution:** Low grid resolution may result in jagged contours or loss of detail. The reference uses $100 \times 100$, but higher resolutions may be needed for complex features [S1, unofficial].
*   **Z-Value Ambiguity:** The `HeightMap` stores the highest z-value. If an edge is nearly parallel to the view plane, the z-value may be unstable. The DCT smoothing helps mitigate this [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by grid iteration and contour traversal. $O(N \cdot R^2)$ where $N$ is the number of exterior edges and $R$ is the grid resolution [S1, unofficial].
*   **Memory Complexity:** $O(R^2)$ for the three grids [S1, unofficial].
*   **Strengths:** Provides explicit 3-D geometry that can be interacted with in the scene; effective for clarifying boundaries in complex unstructured meshes [S1, unofficial].
*   **Limitations:** Dependent on grid resolution; may introduce artifacts if the feature projection is complex or fragmented; requires access to 3-D mesh data, not suitable for pure image-space post-processing [S1, unofficial].
*   **When to Use:** When explicit 3-D outlines are needed for feature identification in unstructured mesh visualization [S1, unofficial].
*   **When Not to Use:** When performance is critical and grid-based processing is too slow; when the feature is not well-defined or has no clear exterior boundary [S1, unofficial].

## Background
The Tube Outline Effect was developed as part of a generalized framework for illustrative visualization of time-varying data on unstructured meshes [S1, unofficial]. It was implemented within the ParaView visualization pipeline to address the limitations of 2-D image-space boundary enhancement techniques, which cannot operate directly on 3-D field data [S1, unofficial]. The method leverages existing VTK filters for tube extrusion and DCT smoothing [S1, unofficial].
