# Suggestive Contour Extraction

Also called: Suggestive contours

## Overview
Suggestive contour extraction identifies surface locations where radial curvature is zero but increasing towards the viewer, complementing standard object contours to enhance shape perception in non-photorealistic volume rendering [S1]. Unlike standard contours which mark visible boundaries, suggestive contours reveal hidden or occluded geometry, such as the rims of indentations, by detecting where the surface is about to curve towards the camera [S1].

## How it works
**Inputs:** A scalar volume field $\phi$, an isovalue $\tau$ defining the isosurface $\phi - \tau = 0$, and a view vector $\mathbf{v}$ for each sample point [S1].
**Outputs:** A set of line segments representing the suggestive contours [S1].

**Data Structures:**
The method operates on a 3D grid of voxels indexed by $(i, j, k)$ [S1]. For each voxel, the following values are required or computed:
*   $\phi(i, j, k)$: Scalar field value [S1].
*   $\mathbf{n}(i, j, k)$: Unit-length surface normal, computed as $\mathbf{n} = -\nabla \phi / \|\nabla \phi\|$ [S1].
*   $\mathbf{v}(i, j, k)$: View vector pointing from the surface point to the camera [S1].
*   $s(i, j, k)$: Radial curvature proxy, defined below [S1].

**Formulas:**
The radial curvature function $s$ is defined as:
$$ s(i, j, k) = \nabla \hat{\mathbf{n}}(i, j, k) \cdot \mathbf{v}(i, j, k) \cdot \mathbf{v}(i, j, k) $$
where $\hat{\mathbf{n}}$ is the unit-length normal and $\mathbf{v}$ is the view vector [S1]. The sign of $s$ corresponds to the sign of the radial curvature [S1].

The directional derivative of $s$ towards the viewer, denoted $D_s$, is computed numerically via finite differences [S1].

**Algorithm Steps:**
1.  **Sample Selection:** Identify candidate points on the isosurface via random probing or gradient descent from previous-frame seeds [S1].
2.  **Zero-Crossing Detection:** Locate points where $s(i, j, k) \approx 0$, indicating zero radial curvature [S1].
3.  **Derivative Test (Frontfaces):** For frontfacing points (normal points toward camera), check if the directional derivative of $s$ towards the viewer is positive [S1]. In practice, compare $D_s$ to a small positive threshold $\epsilon$: $D_s > \epsilon$ [S1]. This filters out spurious zero crossings caused by noise [S1].
4.  **Derivative Test (Backfaces):** For backfacing points, negate the sign of the derivative test to $D_s < -\epsilon$ to maintain analogous lines to frontfacing contours [S1]. Previous work assumed opaque surfaces and did not address backfacing suggestive contours [S1].
5.  **Interior Contour Filtering (Optional):** To omit contours never visible from outside the surface (e.g., bottom of an indentation), test if $s < 0$ for extracted segments [S1].
6.  **Line Generation:** Connect valid points into line segments or strips [S1].

**Pseudocode:**
```python
def extract_suggestive_contours(volume, isovalue, camera_pos, epsilon=1e-6, voxel_size=1.0):
    segments = []
    # 1. Identify candidate points on the isosurface phi - tau = 0
    # Sources describe random probing or gradient descent from previous-frame seeds [S1].
    surface_points = [] # Implementation detail not specified in sources.

    for p in surface_points:
        # 2. Compute normal n_hat = -grad(phi) / ||grad(phi)|| via finite differences [S1]
        grad_phi = central_gradient(volume, p, voxel_size)
        n_hat = normalize(-grad_phi)

        # 3. Compute view vector v from surface point to camera
        v = normalize(camera_pos - p)

        # 4. Compute radial curvature proxy s = (grad(n_hat) . v) . v [S1]
        delta = voxel_size
        n_plus = normalize(-central_gradient(volume, p + delta * v, voxel_size))
        n_minus = normalize(-central_gradient(volume, p - delta * v, voxel_size))
        D_v_n_hat = (n_plus - n_minus) / (2.0 * delta)
        s = dot(D_v_n_hat, v)

        # 5. Check for zero crossing (radial curvature ~ 0)
        if abs(s) < epsilon:
            # 6. Compute directional derivative of s towards viewer (Ds)
            n_pp = normalize(-central_gradient(volume, p + 2*delta*v, voxel_size))
            n_mm = normalize(-central_gradient(volume, p - 2*delta*v, voxel_size))
            D_v_n_hat_plus = (n_pp - n_hat) / (2.0 * delta)
            D_v_n_hat_minus = (n_hat - n_mm) / (2.0 * delta)
            s_plus = dot(D_v_n_hat_plus, v)
            s_minus = dot(D_v_n_hat_minus, v)
            Ds = (s_plus - s_minus) / (2.0 * delta)

            # 7. Apply derivative test based on facing
            if dot(n_hat, v) > 0:
                # Frontfacing: Ds > epsilon [S1]
                if Ds > epsilon:
                    segments.append(p)
            else:
                # Backfacing: Ds < -epsilon [S1]
                if Ds < -epsilon:
                    segments.append(p)

    # 8. Connect valid points into line segments or strips [S1]
    # Implementation detail not specified in sources.
    return segments

def central_gradient(volume, p, voxel_size):
    ix, iy, iz = int(p[0]), int(p[1]), int(p[2])
    return (
        (volume[ix+1, iy, iz] - volume[ix-1, iy, iz]) / (2.0 * voxel_size),
        (volume[ix, iy+1, iz] - volume[ix, iy-1, iz]) / (2.0 * voxel_size),
        (volume[ix, iy, iz+1] - volume[ix, iy, iz-1]) / (2.0 * voxel_size)
    )

def normalize(v):
    mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/mag, v[1]/mag, v[2]/mag)

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
```

**Parameters:**
*   $\epsilon$: Small positive threshold for derivative test [S1].
*   Tolerance: For zero-crossing detection of $s$. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Noise:** Spurious zero crossings in $s$ due to noise are filtered by the $D_s > \epsilon$ test [S1].
*   **Backfaces:** Standard contour methods often ignore backfaces, but suggestive contours require explicit handling by negating the derivative test [S1].
*   **Interior Contours:** Contours at the bottom of indentations have negative radial curvature ($s < 0$) and are never visible from outside; these can be detected and omitted if desired [S1].
*   **Performance:** Computing normals and gradients via finite differences on demand is less efficient than precomputing, which would increase memory usage by 4× [S1].

## Subtopics

### Interior Contour Detection
A method to detect and omit 'interior' contours (those never visible from outside the surface, e.g., bottom of an indentation) by testing for negative radial curvature [S1]. The test involves checking if $s < 0$ for an extracted segment [S1]. A pitfall is that normals and gradients are computed numerically on demand using finite differences, which is less efficient than precomputing (which would cost 4× memory) [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the sampling strategy; random probing and gradient descent are used to locate seeds [S1].
*   **Memory Complexity:** If normals are computed on demand, memory usage is low; precomputing normals increases memory usage by 4× [S1].
*   **Performance:** In tests on a skull dataset, checking $64n$ points took 416 msec/frame, while checking $n$ points took 110 msec/frame, showing that fewer probes reduce cost but may miss contours [S1]. Temporal coherence (retaining previous frame contours) accelerates detection [S1].
*   **Strengths:** Complements standard contours by revealing hidden shape features, improving perceptual clarity of complex shapes [S1].
*   **Limitations:** Requires careful handling of backfaces and noise filtering; numerical computation of derivatives can be noisy and expensive [S1].

## Background
Suggestive contours were introduced by DeCarlo et al. [2003] to complement standard contours in line drawings, producing more effective renderings of shape [S1]. The original work assumed opaque surfaces and did not address backfacing suggestive contours [S1]. The method is based on the observation that radial curvature is zero at the boundary between convex and concave regions, and a positive derivative towards the viewer indicates a region curving towards the camera [S1]. Interior contours, which have negative radial curvature, were later discussed as a refinement to omit hidden details [S1].
