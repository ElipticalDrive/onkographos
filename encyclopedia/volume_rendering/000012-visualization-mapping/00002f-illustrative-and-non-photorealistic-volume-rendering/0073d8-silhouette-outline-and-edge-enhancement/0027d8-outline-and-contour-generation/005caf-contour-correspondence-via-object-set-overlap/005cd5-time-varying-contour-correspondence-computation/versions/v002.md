# Time-Varying Contour Correspondence Computation

Also called: Correspondence Computation Algorithm, Five-Step Correspondence

## Overview
This method computes the correspondence between time-varying contours across two consecutive time steps, $t$ and $t+1$, by labeling edges in the contour tree of $t+1$ with sets of edges from the contour tree of $t$ [S1]. It is a preprocessing algorithm to compute correspondence information of time-varying contours over all isovalues [S1]. Unlike direct geometric comparison, it leverages the topological structure of Join Trees (JT) and Split Trees (ST) to efficiently determine overlaps between upper and lower objects [S1]. The algorithm operates on the contour trees $CT_t$ and $CT_{t+1}$ derived from scalar fields $f_t$ and $f_{t+1}$ on domains $M_t$ and $M_{t+1}$ [S1]. The core insight is that upper objects (regions where $f > w$) and lower objects (regions where $f < w$) grow as the isovalue $w$ decreases [S1]. When an upper object from $t$ and an upper object from $t+1$ collide at a point $x_c$ and isovalue $w_0$, they overlap for all $w < w_0$ [S1]. The algorithm computes this overlap implicitly using JT and ST structures [S1].

## How it works
### Inputs and Outputs
*   **Inputs:**
    *   Contour tree $CT_t$ of the scalar field at time $t$ [S1].
    *   Scalar field $f_{t+1}$ on domain $M_{t+1}$ [S1].
    *   Join Tree $JT_{t+1}$ and Split Tree $ST_{t+1}$ constructed from $f_{t+1}$ [S1].
*   **Outputs:**
    *   $CT_{t+1}$ where every edge $e_k^{t+1}$ is labeled with a set of edges $E_t \subset CT_t$ [S1].
    *   Labeling satisfies: A contour on $e_k^{t+1}$ at isovalue $w_0 \in [f_a, f_b]$ evolves from contours on edges $e_k'^t \in E_t$ at time $t$ [S1].

### Data Structures
*   **Contour Tree Edge Label:** A set of integer IDs, where each ID uniquely identifies an edge in $CT_t$ [S1].
*   **Join Tree Node Label:** A set of integer IDs, representing the set of $CT_t$ edges whose contours are contained within the upper object represented by the node [S1].
*   **Split Tree Node Label:** A set of integer IDs, representing the set of $CT_t$ edges whose contours are contained within the lower object represented by the node [S1].

### Steps
1.  **Assign IDs to $CT_t$ Edges:** Assign a unique integer ID to each edge in $CT_t$ [S1].
2.  **Label $JT_t$ and $ST_t$:** Label each edge in $JT_t$ and $ST_t$ with a set of edges from $CT_t$ [S1].
    *   **Logic:** An upper object with isovalue $w$ on an edge $e \in JT_t$ must contain contours with isovalue $w$ on borders $e' \in E$ from $CT_t$ [S1].
    *   **Implementation:** Process vertices $v$ of the domain mesh $M_t$ in decreasing order of function value $f_t(v)$ [S1].
        *   If $v$ is a critical point, a node in $JT_t$ is created and connected to parent nodes belonging to the same objects [S1].
        *   Update the label in the parent vertex of $v$ incrementally: delete edge IDs corresponding to destroyed contour classes and insert edge IDs corresponding to newly created contour classes [S1].
    *   *Note:* The process for $ST_t$ is symmetric, processing vertices in increasing order of function value [S1].
3.  **Core Matching (Label $JT_{t+1}$ and $ST_{t+1}$):** Label each edge $e$ in $JT_{t+1}$ and $ST_{t+1}$ with a set of edges $E$ from $CT_t$ [S1].
    *   **Logic:** An upper/lower object with isovalue $w$ on edge $e$ in time $t+1$ must overlap upper/lower objects in time $t$ that contain contours with isovalue $w$ on borders $e' \in E$ [S1].
    *   **Implementation:** This step determines the correspondence by checking overlaps. Since upper objects grow as $w$ decreases, the overlap condition is monotonic [S1].
4.  **Convert to Contour Tree Form:** Convert the labeled $JT_{t+1}$ and $ST_{t+1}$ into contour tree forms $CT_{t+1}(JT)$ and $CT_{t+1}(ST)$ [S1].
    *   **Logic:** The label at a point $p$ in the contour tree must match the label at the corresponding point $p'$ in the join/split tree [S1].
5.  **Compute Final Labels for $CT_{t+1}$:** Label each edge $e$ in $CT_{t+1}$ with a set of edges $E$ from $CT_t$ [S1].
    *   **Formula:** $Label(e) = Label_{JT}(e) \cap Label_{ST}(e)$ [S1].
    *   **Logic:** $E$ is computed as the intersection of the labels (edge sets) from $CT_{t+1}(JT)$ and $CT_{t+1}(ST)$ [S1].

### Parameters and Edge Cases
*   **Function Range:** The labeling is computed for the entire function range $[f_a, f_b]$ [S1].
*   **Critical Points:** Labels change only at critical points [S1].
*   **Collision Property:** The algorithm relies on the property that once upper/lower objects from $t$ and $t+1$ collide, they always overlap thereafter as the isovalue decreases [S1].

## Operating characteristics
*   **Time Complexity:** The complexity is dominated by the construction of the Join and Split trees and the overlap computation. The overlap computation in Step 3 is the most expensive. The sources do not provide a precise asymptotic complexity [S1].
*   **Memory Complexity:** Requires storing the contour trees, join/split trees, and the labels for each edge/node. The labels are sets of integers, so memory usage scales with the number of edges and the average size of the correspondence sets [S1].
*   **Strengths:** Provides a complete topological correspondence for all isovalues. Efficiently uses the monotonic growth property of upper/lower objects to avoid redundant checks [S1].
*   **Limitations:** Requires the construction of JT and ST for both time steps. The overlap computation can be computationally intensive for complex scalar fields with many topological changes [S1].

## Background
The method was introduced in the paper "Time-varying contour topology" [S1]. It builds upon the concept of contour trees and join/split trees to provide a robust way to track topological changes in time-varying scalar fields [S1]. The key innovation is the use of JT and ST to implicitly compute the overlap of upper and lower objects, which is necessary for defining contour correspondence [S1].
