# Contour Correspondence via Object Set Overlap

Also called: Contour Correspondence Test, Definition 1

## Overview
This method determines if a contour $C_k^t$ at time $t$ corresponds to a contour $C_{k'}^{t+1}$ at time $t+1$ by verifying that their associated upper and lower object sets overlap. It solves the problem of tracking isosurface features across time steps without constructing higher-dimensional interpolated functions, which can cause undesirable matchings when contours are far apart. It differs from [Image Space Outline Generation](788-image-space-outline-generation.md) by operating in volume space using topological object sets rather than image-space depth/normal discontinuities, and from [Time-Varying Contour Correspondence Computation](17255-time-varying-contour-correspondence-computation.md) by defining the core matching logic rather than the preprocessing labeling algorithm.

## How it works
**Inputs:**
- Scalar field $f_t(x)$ at time $t$ and $f_{t+1}(x)$ at time $t+1$.
- A contour $C_k^t$ at time $t$, defined by the isovalue $w$.
- A contour $C_{k'}^{t+1}$ at time $t+1$, defined by the isovalue $w$.
- Threshold $\epsilon$ for significant overlap.

**Outputs:**
- Boolean result: $C_k^t$ corresponds to $C_{k'}^{t+1}$ or not.

**Data Structures:**
- **Object Set:** A set of 3D grid points (or voxels) satisfying the scalar field inequality.
  - Upper Object Set $X_t(w) = \{x \mid f_t(x) \ge w\}$.
  - Lower Object Set $Y_t(w) = \{x \mid f_t(x) \le w\}$.
- **Connected Components:** The object sets are decomposed into connected components (objects).
  - $X_t(w) = \{X_1^t, \dots, X_n^t\}$ where each $X_i^t$ is an upper object.
  - $Y_t(w) = \{Y_1^t, \dots, Y_m^t\}$ where each $Y_i^t$ is a lower object.
- **Contour-Object Mapping:** Each contour $C$ is associated with exactly one upper object $X_a$ and one lower object $Y_b$ such that the contour lies on the border of both.

**Steps:**
1. **Identify Associated Objects:** For contour $C_k^t$, identify its associated upper object $X_{at}$ and lower object $Y_{bt}$. For contour $C_{k'}^{t+1}$, identify its associated upper object $X_{a't+1}$ and lower object $Y_{b't+1}$. [G] This requires determining which connected component of $X_t(w)$ and $Y_t(w)$ the contour vertices belong to.
2. **Compute Overlap Volumes:** Calculate the volume of the intersection between the upper objects and between the lower objects.
   - $V_{upper\_intersect} = V(X_{at} \cap X_{a't+1})$
   - $V_{lower\_intersect} = V(Y_{bt} \cap Y_{b't+1})$
   - $V_{upper\_t} = V(X_{at})$, $V_{upper\_t+1} = V(X_{a't+1})$
   - $V_{lower\_t} = V(Y_{bt})$, $V_{lower\_t+1} = V(Y_{b't+1})$
3. **Check Basic Correspondence:** Verify if there is any overlap.
   - Condition: $(X_{at} \cap X_{a't+1} \neq \emptyset) \land (Y_{bt} \cap Y_{b't+1} \neq \emptyset)$.
4. **Check Significant Overlap (Optional but Recommended):** To avoid matching contours with negligible overlap, apply the threshold $\epsilon$.
   - Condition: $\frac{V_{upper\_intersect}}{\min(V_{upper\_t}, V_{upper\_t+1})} > \epsilon$ AND $\frac{V_{lower\_intersect}}{\min(V_{lower\_t}, V_{lower\_t+1})} > \epsilon$.
5. **Return Result:** If the significant overlap condition is met, $C_k^t$ corresponds to $C_{k'}^{t+1}$.

**Parameters:**
- $\epsilon$: Threshold for significant overlap. Typical value: 0.3 [S1].

**Edge Cases and Pitfalls:**
- **Degenerate Objects:** If an object has zero volume (e.g., empty space or a single point), the denominator in the overlap ratio becomes zero. Handle by checking if volumes are non-zero before division.
- **Precision:** Volume calculations depend on the discretization of the scalar field. Ensure consistent voxel counting or integration methods for $V(O)$.
- **Boundary Conditions:** Ensure object sets are correctly computed at domain boundaries.

**Pseudocode:**
```python
def check_contour_correspondence(contour_t, contour_t_plus_1, field_t, field_t_plus_1, isovalue, epsilon):
    """
    Determines if contour_t at time t corresponds to contour_t_plus_1 at time t+1.
    
    Args:
        contour_t: List of 3D points defining the contour at time t.
        contour_t_plus_1: List of 3D points defining the contour at time t+1.
        field_t: 3D array of scalar values at time t.
        field_t_plus_1: 3D array of scalar values at time t+1.
        isovalue: The scalar value defining the contour.
        epsilon: Threshold for significant overlap (e.g., 0.3).
        
    Returns:
        bool: True if contours correspond, False otherwise.
    """
    # Step 1: Identify associated upper and lower objects for contour_t
    # An upper object is a connected component of {x | field_t(x) >= isovalue}
    # A lower object is a connected component of {x | field_t(x) <= isovalue}
    # We need to find which connected component contains the contour vertices.
    
    # Create binary masks for upper and lower objects at time t
    mask_upper_t = field_t >= isovalue
    mask_lower_t = field_t <= isovalue
    
    # Label connected components for upper and lower objects at time t
    # Note: Connected components must be computed on the binary masks.
    # We assume a function label_connected_components exists.
    labels_upper_t = label_connected_components(mask_upper_t)
    labels_lower_t = label_connected_components(mask_lower_t)
    
    # Find the label of the upper object containing contour_t
    # We sample the contour points and find the dominant label in their vicinity
    # or simply check the label of the grid points closest to the contour.
    # For simplicity, we assume contour_t provides access to the grid indices or we find the closest grid point.
    # Let's assume we can get the label for a point p.
    
    def get_label_at_point(p, labels):
        # Find the closest grid point to p and return its label
        # This is a placeholder for the actual nearest-neighbor lookup
        idx = find_closest_grid_index(p)
        return labels[idx]
        
    label_X_at = get_label_at_point(contour_t[0], labels_upper_t) # Assume contour_t[0] is representative
    label_Y_bt = get_label_at_point(contour_t[0], labels_lower_t)
    
    # Step 2: Identify associated upper and lower objects for contour_t_plus_1
    mask_upper_t1 = field_t_plus_1 >= isovalue
    mask_lower_t1 = field_t_plus_1 <= isovalue
    
    labels_upper_t1 = label_connected_components(mask_upper_t1)
    labels_lower_t1 = label_connected_components(mask_lower_t1)
    
    label_X_a_t1 = get_label_at_point(contour_t_plus_1[0], labels_upper_t1)
    label_Y_b_t1 = get_label_at_point(contour_t_plus_1[0], labels_lower_t1)
    
    # Step 3: Compute Overlap Volumes
    # Create masks for the specific objects
    mask_X_at = (labels_upper_t == label_X_at)
    mask_Y_bt = (labels_lower_t == label_Y_bt)
    mask_X_a_t1 = (labels_upper_t1 == label_X_a_t1)
    mask_Y_b_t1 = (labels_lower_t1 == label_Y_b_t1)
    
    # Calculate volumes (number of voxels)
    V_X_at = count_voxels(mask_X_at)
    V_Y_bt = count_voxels(mask_Y_bt)
    V_X_a_t1 = count_voxels(mask_X_a_t1)
    V_Y_b_t1 = count_voxels(mask_Y_b_t1)
    
    # Calculate intersection volumes
    # Note: mask_X_at and mask_X_a_t1 are from different time steps, so they are on different grids.
    # We must map one grid to the other or use a common coordinate system.
    # Assuming the grids are aligned and have the same resolution/spacing.
    # If not, interpolation or resampling is needed.
    
    # For this pseudocode, we assume aligned grids.
    mask_X_intersect = mask_X_at & mask_X_a_t1
    mask_Y_intersect = mask_Y_bt & mask_Y_b_t1
    
    V_X_intersect = count_voxels(mask_X_intersect)
    V_Y_intersect = count_voxels(mask_Y_intersect)
    
    # Step 4: Check Significant Overlap
    # Avoid division by zero
    if V_X_at == 0 or V_X_a_t1 == 0:
        return False
    if V_Y_bt == 0 or V_Y_b_t1 == 0:
        return False
        
    overlap_upper = V_X_intersect / min(V_X_at, V_X_a_t1)
    overlap_lower = V_Y_intersect / min(V_Y_bt, V_Y_b_t1)
    
    if overlap_upper > epsilon and overlap_lower > epsilon:
        return True
    else:
        return False
```

## Subtopics

### [Time-Varying Contour Correspondence Computation](17255-time-varying-contour-correspondence-computation.md)
A preprocessing algorithm to compute correspondence information of time-varying contours over all isovalues. It labels edges in $CT_{t+1}$ with sets of edges from $CT_t$.

## Operating characteristics
- **Time Complexity:** Dominated by connected component labeling and volume calculation. For a grid of size $N$, connected component labeling is $O(N)$. Volume calculation is $O(N)$. Comparing all pairs of contours is $O(K_t \times K_{t+1})$ where $K$ is the number of contours.
- **Memory Complexity:** $O(N)$ to store the scalar fields and binary masks.
- **Strengths:** Avoids the complexity and potential artifacts of higher-dimensional interpolation. Provides flexibility via the threshold $\epsilon$ to control matching strictness.
- **Limitations:** Requires connected component labeling, which can be computationally expensive for large datasets. Sensitive to the choice of $\epsilon$.
- **When to Use:** When tracking isosurface contours across time steps is required, and interpolation-based methods are too costly or produce incorrect matches.
- **When Not to Use:** When real-time performance is critical and the dataset is very large, or when contours are not well-defined by a single isovalue.

## Background
The method was introduced in the paper "Time-varying contour topology" [S1]. It is based on the observation that corresponding objects in successive timesteps have significant overlap. It extends feature correspondence  to contour correspondence.
