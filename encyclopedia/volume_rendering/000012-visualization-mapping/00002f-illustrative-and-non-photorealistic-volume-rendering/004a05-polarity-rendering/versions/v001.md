# Polarity Rendering

Also called: Polarity-based volume rendering, Sign-based field visualization

## Overview
Polarity rendering visualizes volumetric data by coloring voxels based on the sign (positive or negative) of a selected vector field component basis ($B_x, B_y,$ or $B_z$) [S1, unofficial]. It solves the problem of distinguishing directional orientation in vector fields, such as magnetic fields, where magnitude alone is insufficient [S1, unofficial]. Unlike [Geometric Buffers (G-buffers)](781-geometric-buffers-g-buffers.md) which rely on surface normals, or [Volume Illustration](810-volume-illustration.md) which uses gradient magnitude for edge enhancement, polarity rendering explicitly maps the algebraic sign of a specific axis component to distinct colors [S1, unofficial].

## How it works
**Inputs:**
1.  A volumetric vector field dataset $V$, where each voxel contains a vector $\mathbf{B} = (B_x, B_y, B_z)$ [S1, unofficial].
2.  A selected component basis $C \in \{B_x, B_y, B_z\}$ [S1, unofficial].
3.  Two distinct colors: $c_{pos}$ for positive values and $c_{neg}$ for negative values [S1, unofficial].

**Outputs:**
*   A rendered image where each pixel color is determined by the sign of the selected component at the corresponding sample location [S1, unofficial].

**Data Structures:**
*   The input data is typically stored as a 3D array of vectors. For implementation, the scalar component $C$ is extracted into a 3D scalar field $S$ where $S(x,y,z) = C(x,y,z)$ [S1, unofficial].

**Steps:**
1.  **Preprocessing:** Replace any `NaN` or `Inf` values in the input vector field with zero to prevent rendering artifacts, particularly at array boundaries [S1, unofficial].
2.  **Component Selection:** Extract the scalar field $S$ corresponding to the chosen basis component $C$ [S1, unofficial].
3.  **Sign Evaluation:** For each sample point $p$ in the volume, evaluate the sign of $S(p)$:
    $$
    \text{sign}(S(p)) = \begin{cases} 
    +1 & \text{if } S(p) > 0 \\
    -1 & \text{if } S(p) < 0 \\
    0 & \text{if } S(p) = 0 
    \end{cases}
    $$
4.  **Color Mapping:** Assign the output color $c_{out}$ based on the sign:
    $$
    c_{out} = \begin{cases} 
    c_{pos} & \text{if } \text{sign}(S(p)) > 0 \\
    c_{neg} & \text{if } \text{sign}(S(p)) < 0 \\
    c_{zero} & \text{if } \text{sign}(S(p)) = 0 
    \end{cases}
    $$
    Where $c_{zero}$ is typically a neutral color (e.g., black or gray) or transparent, though specific handling of zero-crossings is not detailed in the primary source [S1, unofficial].

**Parameters:**
*   **Component Basis:** The specific axis ($B_x, B_y,$ or $B_z$) to evaluate [S1, unofficial].
*   **Colors:** $c_{pos}$ and $c_{neg}$ are user-defined to maximize contrast [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Crossings:** The behavior at exactly zero is not explicitly defined in the primary source [S1, unofficial]. Implementers should define a default color or transparency for $S(p)=0$ [G].
*   **Incomplete Topology:** Polarity rendering does not represent full magnetic topology, connectivity classes, or radial polarity unless additional modes are implemented [S1, unofficial]. It only indicates the sign of the chosen component, not the full vector direction [S1, unofficial].

**Pseudocode:**
```python
def polarity_render(vector_field, component_index, color_pos, color_neg, color_zero):
    """
    Renders a volume based on the sign of a specific vector component.
    
    Args:
        vector_field: 3D numpy array of shape (D, H, W, 3) containing vector components.
        component_index: Integer 0, 1, or 2 corresponding to x, y, or z.
        color_pos: RGB tuple for positive values.
        color_neg: RGB tuple for negative values.
        color_zero: RGB tuple for zero values.
        
    Returns:
        3D numpy array of shape (D, H, W, 3) with colored voxels.
    """
    # Extract the scalar field for the chosen component
    scalar_field = vector_field[:, :, :, component_index]
    
    # Initialize output buffer
    output = np.zeros_like(scalar_field)
    output = np.stack([output, output, output], axis=-1)
    
    # Create masks for positive, negative, and zero values
    mask_pos = scalar_field > 0
    mask_neg = scalar_field < 0
    mask_zero = ~mask_pos & ~mask_neg
    
    # Assign colors based on sign
    output[mask_pos] = color_pos
    output[mask_neg] = color_neg
    output[mask_zero] = color_zero
    
    return output
```

## Subtopics

### Scalar Value Assignment for Polarity
This variant is used when the input data is not a native vector field but rather scalar data representing different polarities (e.g., Radar Cross Section data with Vertical, Horizontal, and Cross-pole polarities) [S2, unofficial]. Instead of evaluating the sign of a vector component, distinct scalar values are assigned to each polarity type [S2, unofficial]. Vertical polarity (W) and Horizontal polarities (HH) are given unique values, while Cross-pole polarities (HV and VH) are assigned the same scalar weight [S2, unofficial]. A spacing of 50 units between scalar values is recommended to ensure accurate representation and avoid bias [S2, unofficial]. A key pitfall is that closely spaced scalar values or values close to zero significantly bias the final results, leading to inaccurate visualizations [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels, as it involves a single pass to evaluate the sign of the selected component.
*   **Memory Complexity:** $O(N)$ to store the scalar field and output buffer.
*   **Strengths:** Simple to implement; effectively highlights directional asymmetry in vector fields; computationally inexpensive.
*   **Limitations:** Does not convey full vector direction or topology; sensitive to the choice of component basis; zero-crossings require explicit handling [S1, unofficial].
*   **When to use:** When the primary interest is distinguishing regions of positive vs. negative orientation along a specific axis (e.g., magnetic polarity).
*   **When not to use:** When full vector direction, magnitude, or topological connectivity is required [S1, unofficial].

## Background
Polarity rendering was introduced in the context of astrophysical vector field visualization, specifically for magnetograms [S1, unofficial]. It was developed to provide a native volumetric visualization method that could quickly indicate magnetic polarity in solar physics data. The method is also applied in radar cross-section (RCS) data visualization, where distinct scalar values are assigned to different polarization states to facilitate 3D interpretation [S2, unofficial].
