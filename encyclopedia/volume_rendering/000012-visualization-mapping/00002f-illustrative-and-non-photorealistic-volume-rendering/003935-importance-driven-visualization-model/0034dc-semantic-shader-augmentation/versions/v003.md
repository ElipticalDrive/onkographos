# Semantic Shader Augmentation

Also called: dynamic shader generation for semantic mapping

## Overview
Semantic Shader Augmentation is a technique that automatically extends an input GPU shader program with rule-based rendering functionality, replacing static visualization mappings (such as fixed transfer functions) with dynamic mappings defined by semantic rules and fuzzy membership functions [S1]. It solves the problem of rigid, hard-coded visualization pipelines by allowing domain experts to interactively explore and specify multi-dimensional mappings without programming skills [S1]. Unlike the original semantic-layers approach where rule-based functionality is hard-coded a priori, or UberShader/SuperShader which combine pre-coded fragments, this method generates code fragments entirely on the fly, allowing the augmentation of any existing shader with minimal overhead [S1].

## How it works
### Inputs and Outputs
*   **Input Shader Program:** An initial shader program (e.g., GLSL) selected by the user, which may contain special tags surrounding variables of potential interest [S1].
*   **Semantic Tags:** Dedicated tags in the shader code containing three pieces of information: a specifier, the name, and the type of the associated variable. These tags identify variables as either semantic data properties (inputs) or visual attributes (outputs) [S1].
*   **Compositing Method:** Selectable by the user from averaging, maximum, or slicing [S1].
*   **Mapping Factor:** A user-adjustable scalar factor multiplied with the composite value to map it to a visible data range [S1].
*   **Membership Functions:** Defined via a graphical user interface using analogy. Implemented as single-channel textures where the dimensionality matches the number of dimensions of the represented data properties (e.g., 1D texture for 1D attribute) [S1].

### Data Structures
*   **Semantic Property Texture:** An output texture used to visualize semantic data properties. The mapping of semantic data dimensions to texture color channels is as follows: for one-dimensional variables, use the blue color channel; for three-dimensional variables, use all three color channels [S1].
*   **Membership Function Texture:** A single-channel texture representing the fuzzy membership function. The domain represents the scalar values of a semantic property (given by color values in the semantic-property image), and the co-domain represents the corresponding membership values [S1].

### Numbered Steps
1.  **Tagging:** The visualization expert identifies suitable semantic variables in the input shader and marks them with dedicated tags containing the specifier, name, and type [S1]. This process is performed once [S1].
2.  **Parsing:** A pre-compiler parses the input shader source file to detect the tags that define variables as semantic entities [S1].
3.  **Augmentation (Code Generation):** A copy of the shader file is created in main memory [S1]. Required functionality is generated on the fly (not pre-coded fragments) and inserted at the locations indicated by the detected tags [S1].
    *   **Step 1 Functionality:** Inserts code to generate visualizations of semantic data properties and render the result to a texture. This involves performing raycasting, compositing values assigned to semantic variables during input shader execution, and mapping the composite value to a visible color range using the selected compositing method (averaging, maximum, or slicing) and mapping factor [S1].
    *   **Step 2 Functionality:** Enhances the shader with the capability to evaluate a semantic rule base using fuzzy-logic arithmetics [S1].
4.  **Dynamic Loading:** The resulting augmented code is used as a dynamically loaded shader program. This allows the input-shader code to be edited during runtime [S1].
5.  **Rule Specification (GUI):** The domain expert uses a graphical user interface to specify illustration rules. Attributes of interest are interpreted as fuzzy sets, where membership functions describe the attributes' contributions to the mapping. Fuzzy-logic arithmetics are applied to evaluate the illustration rules [S1].
6.  **Rendering:** The augmented shader executes, evaluating the fuzzy rules to map semantic data properties to visual attributes (color, opacity, sparseness parameters) [S1].

### Formulas
*   **Composite Value Mapping:** $V_{visible} = V_{composite} \times F_{mapping}$, where $V_{visible}$ is the final mapped value, $V_{composite}$ is the result of the selected compositing method (averaging, maximum, or slicing) applied to semantic variable values during raycasting, and $F_{mapping}$ is the user-adjustable mapping factor [S1].
*   **Membership Function Evaluation:** $M(v) = \text{TextureLookup}(T_{membership}, v)$, where $M(v)$ is the membership value, $v$ is the scalar value of a semantic property (derived from the semantic-property texture), and $T_{membership}$ is the single-channel membership function texture [S1].

### Parameters
*   **Compositing Method:** 'averaging', 'maximum', or 'slicing' [S1].
*   **Mapping Factor:** User-adjustable, no specific typical value given [S1].
*   **Membership Functions:** Defined via GUI, no specific typical values given [S1].

### Edge Cases and Pitfalls
*   **Tagging Time:** Identifying and tagging suitable semantic variables can be time-consuming, but this is performed only once by a visualization expert before the domain expert uses the abstract control [S1].

## Subtopics

### Graphically Specified Visualization Rules
A method for determining the mapping from semantic data properties to visual attributes using rules that are graphically specified and evaluated using fuzzy-logic arithmetics [S1]. It adds functionality to evaluate fuzzy visualization rules to the augmented shader, interpreting attributes of interest as fuzzy sets where membership functions describe the attributes' contributions to the mapping [S1]. Visual attributes include color, opacity, or parameters of sparseness or stylized shading [S1]. Unlike formal and textual rule formulations which are considered rigid and non-exploratory, this method combines rule-based rendering with graphical user interfaces for defining multi-dimensional mappings [S1].

## Background
The method was proposed by the authors of the current work, extending the flexibility and exploration capabilities offered by Rautek et al.'s original semantic-layers system, which used textual rules and fuzzy logic [S1]. The approach builds on the principle that rule-based visualization bears great potential, but formal and textual rule formulations are rigid and non-exploratory [S1]. It differs from UberShader and SuperShader by generating code fragments entirely on the fly rather than combining pre-coded fragments [S1].
