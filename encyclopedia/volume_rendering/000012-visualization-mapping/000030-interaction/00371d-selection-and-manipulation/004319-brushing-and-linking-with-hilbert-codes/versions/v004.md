# Brushing and Linking with Hilbert Codes

Also called: Brushing and Linking for DVL and 3D Views, Hilbert code selection

## Overview
This method connects 1D visualization views with 3D volume rendering by using Hilbert space-filling curve codes to define selection ranges [S1]. When a user selects a Region of Interest (ROI) in the 1D plot, the corresponding cells in the 3D view are highlighted [S1]. It differs from standard spatial selection by mapping the selection criterion to a 1D range of Hilbert codes rather than a 3D bounding box, allowing for a compact representation of non-contiguous spatial regions [S1].

## How it works
**Inputs:**
- A set of ROIs defined in the 1D view, each specified by a start and end Hilbert code ($H_{start}, H_{end}$) [S1].
- A 3D volume dataset (structured-regular or AMR) [S1].
- A transfer function $T$ mapping scalar values to color and opacity [S1].

**Outputs:**
- Highlighted cells in the 3D view corresponding to the selected ROIs [S1].

**Data Structures:**
- **ROI Range:** A pair of integers $(H_{start}, H_{end})$ defining the selection interval [S1].

**Steps:**
1. **User Selection:** The user selects one or more ROIs in the 1D view, and the system records the first and last Hilbert codes of each selected ROI [S1].
2. **Shader Initialization:** The 3D rendering shader receives the list of ROI ranges $(H_{start}, H_{end})$ as uniform variables [S1].
3. **Ray Casting:** For each pixel, a ray is cast through the volume [G]. At each sample point $p$ along the ray:
    a. **Coordinate to Hilbert Conversion:** The 3D coordinates of the sample point $p$ are transformed into its corresponding Hilbert code $H(p)$ [S1].
    b. **Containment Test:** The shader checks if $p$ falls within any active ROI range [S1]. For structured-regular volumes, this is a direct integer comparison $H_{start} \le H(p) \le H_{end}$ [S1]. For AMR data, the cell centroid's Hilbert code is insufficient; the shader must explicitly locate the cell to verify that $p$ lies within the ROI's exact bounds [S1].
    c. **Value Lookup:** If contained, the scalar value at $p$ is retrieved and passed to the transfer function $T$ to determine color and opacity [S1].
4. **Compositing:** Standard front-to-back compositing accumulates the sampled color and opacity values along the ray [G].

**Formulas:**
- **ROI Containment (Structured):** A sample at position $p$ is part of ROI $k$ if:
  $$ H_{start}^{(k)} \le H(p) \le H_{end}^{(k)} $$
  where $H(p)$ is the Hilbert code of the cell containing $p$ [S1].
- **Alpha Approximation (1D View):** For the 1D plot, the alpha value for a ROI is approximated by:
  $$ V_\alpha = \max_{m \in M} \left( \max_{a \in [i, j]} A(m, a) - \min_{a \in [i, j]} A(m, a) \right) $$
  where $A$ denotes a lookup to the transfer function to retrieve the alpha value, $[i, j]$ is the Hilbert code range, and $M$ is the set of fields [S1].

**Parameters:**
- **Hilbert Order:** Not given in the sources.

**Edge Cases and Pitfalls:**
- **Structured-Regular Volumes:** Cell bounds can be derived implicitly from the Hilbert code because cells are uniform in size [S1].
- **AMR Data:** For AMR data, the cell centroid’s Hilbert code is not sufficient; instead, when we check if a sample falls inside an ROI, we must explicitly locate cells to know the ROI’s exact size [S1].

**Pseudocode:**
```python
def ray_cast_pixel(ray_origin, ray_direction, roi_ranges, volume_bounds, is_amr, transfer_function):
    color = (0.0, 0.0, 0.0, 0.0)
    alpha = 0.0
    t = 0.0
    step = 0.5  # [G] Typical step size
    max_t = compute_max_t(ray_origin, ray_direction, volume_bounds)  # [G] Standard ray-volume intersection (not given in the sources)
    
    while t <= max_t:
        p = ray_origin + t * ray_direction
        h_code = compute_hilbert_code(p)  # [G] Standard 3D Hilbert code conversion (not given in the sources)
        
        inside_roi = False
        for h_start, h_end in roi_ranges:
            if h_start <= h_code <= h_end:
                if is_amr:
                    # [G] Standard AMR cell boundary check (not given in the sources)
                    if point_in_cell_bounds(p, h_code):
                        inside_roi = True
                        break
                else:
                    inside_roi = True
                    break
        
        if inside_roi:
            scalar = volume_data.sample(p)
            rgba = transfer_function(scalar)
            color = (
                color[0] + rgba[0] * rgba[3] * (1.0 - alpha),
                color[1] + rgba[1] * rgba[3] * (1.0 - alpha),
                color[2] + rgba[2] * rgba[3] * (1.0 - alpha),
                alpha + rgba[3] * (1.0 - alpha)
            )
            if alpha >= 1.0:
                break
        t += step
    return color
```

## Operating characteristics
- **Time Complexity:** The containment test uses direct integer comparisons on Hilbert codes [S1].
- **Memory Complexity:** The compact representation of ROIs as Hilbert codes reduces memory bandwidth usage compared to storing lists of cell indices [S1].
- **Performance:** The method is efficient for GPU implementation using CUDA, as the compact representation of ROIs as Hilbert codes reduces memory bandwidth usage compared to storing lists of cell indices [S1].
- **Strengths:** Compact representation of complex, non-contiguous ROIs; efficient GPU implementation; seamless integration between 1D and 3D views [S1].
- **Limitations:** Requires pre-computation of Hilbert codes; AMR data requires explicit cell location for accurate containment testing, which may be more expensive than structured grids [S1].

## Background
This method was introduced in the context of visual analysis of large multi-field AMR data on GPUs using Interactive Volume Lines [S1]. It was presented at IEEE VIS 2023 [S1]. The technique builds on the concept of Dynamic Volume Lines (DVL) and extends it to support 3D view interaction through Hilbert space-filling curves [S1].
