# 3D Widget Interaction Model

Also called: VTK 3D Widget Model

## Overview
The 3D Widget Interaction Model provides a framework for creating interactive graphical objects (widgets) that exist within a 3D scene and can be directly manipulated by the user. It solves the problem of coupling user input events (mouse, keyboard) to specific geometric representations in the rendering window, allowing for immediate visual feedback and data modification. Unlike standard interactor styles which manipulate the camera or view, this model associates observers with a `vtkRenderWindow` that maintain a scene representation, enabling direct manipulation of data structures such as streamlines or clipping volumes [S1, book].

## How it works
The model relies on the Command/Observer design pattern to decouple the widget's internal state from the application logic.

**Inputs and Outputs:**
*   **Input:** User interaction events (mouse down, move, up) generated by the `vtkRenderWindowInteractor`.
*   **Output:** Modified scene geometry (e.g., new polyline points, updated clipping planes) and triggered pipeline updates.

**Data Structures:**
The core class hierarchy is based on `vtkInteractorObserver`.
*   `vtkInteractorObserver`: Base class. Associates with a `vtkRenderWindow` and observes events. Does not have a scene representation [S1, book].
*   `vtk3DWidget`: Subclass of `vtkInteractorObserver`. Has a representation in the scene that can be directly manipulated [S1, book].
*   `vtkWidgetRepresentation`: Defines the visual geometry of the widget.
*   `vtkWidgetCallback`: Handles specific interaction states.

**Numbered Steps:**
1.  **Instantiation:** Create the specific widget instance (e.g., `vtkLineWidget`, `vtkBoxWidget2`) [S1, book][S2, unofficial].
2.  **Placement:** Position, scale, and orient the widget consistent with the target object or data domain [S1, book].
3.  **Event Binding:** Register application callbacks using `AddObserver()` for key events:
    *   `StartInteractionEvent`: Triggered on mouse down [S1, book].
    *   `InteractionEvent`: Triggered on mouse move [S1, book].
    *   `EndInteractionEvent`: Triggered on mouse up [S1, book].
4.  **Interaction Handling:**
    *   On `InteractionEvent`, retrieve the current widget geometry via `GetPolyData()` (for line/point widgets) or `GetPlanes()` (for box widgets) [S1, book][S2, unofficial].
    *   Feed this geometry into the rendering or analysis pipeline (e.g., streamline seeding, volume clipping) [S1, book].
5.  **Pipeline Update:** The pipeline automatically executes on the next render cycle because the input data source has been modified [S1, book].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Initialization
widget = vtkLineWidget()
widget.SetInteractor(interactor)
widget.SetRepresentation(representation)

# Placement
widget.PlaceWidget(bounds) # Position, scale, orient consistent with target

# Event Binding
def on_start_interaction(obj, event):
    # Handle mouse down
    pass

def on_interaction(obj, event):
    # Retrieve current geometry
    poly_data = obj.GetPolyData()
    
    # Update pipeline (e.g., seed streamlines with new points)
    streamline_filter.SetInputData(poly_data)
    streamline_filter.Update()

def on_end_interaction(obj, event):
    # Handle mouse up
    pass

widget.AddObserver("StartInteractionEvent", on_start_interaction)
widget.AddObserver("InteractionEvent", on_interaction)
widget.AddObserver("EndInteractionEvent", on_end_interaction)

# Enable widget
widget.On() # Default enabled via 'keypress-i' event, but can be manually toggled
```

**Parameters:**
*   **Enable Event:** By default, widgets are enabled via a `keypress-i` event. This can be modified to any key or mouse button [S1, book].

**Edge Cases and Pitfalls:**
*   **Multiple Observers:** More than one `vtkInteractorObserver` can watch a `vtkRenderWindow` simultaneously. Event handling order depends on the registration order [S1, book].
*   **Pipeline Latency:** Changes to widget geometry do not immediately render; they trigger an update on the next render call [S1, book].

## Subtopics

### Interactive Box Clipping
A variant using `vtkBoxWidget2` to define a 3D bounding box for volume clipping. It sets apart from line widgets by manipulating six clipping planes rather than a polyline. Choose this when volumetric data needs to be sliced or masked based on a user-defined rectangular region.
*   **Steps:**
    1.  Attach a callback to `vtkBoxWidget2` listening for `vtkCommand::InteractionEvent` [S2, unofficial].
    2.  Cast the caller to `vtkBoxWidget2` and retrieve its representation as `vtkBoxRepresentation` [S2, unofficial].
    3.  Enable inside-out clipping mode by calling `boxRepresentation->SetInsideOut(1)` [S2, unofficial].
    4.  Extract the six clipping planes defining the box via `boxRepresentation->GetPlanes(planes_)` [S2, unofficial].
    5.  Apply the extracted planes to the volume mapper using `volume_->GetMapper()->SetClippingPlanes(planes_)` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Interaction event handling is $O(1)$ for geometry retrieval, but pipeline updates (e.g., streamline generation, volume rendering) depend on the complexity of the downstream filter and data size.
*   **Memory Complexity:** Proportional to the size of the widget's representation and the data structures it influences (e.g., the number of points in a streamline or the number of voxels in a clipped volume).
*   **Strengths:** Direct manipulation provides intuitive user feedback; decoupled via observer pattern allowing flexible application logic.
*   **Limitations:** Tightly coupled to VTK's event system; requires careful management of multiple observers to avoid event conflicts.
*   **When to use:** When direct, real-time manipulation of 3D geometric primitives (lines, boxes, planes) is required for data exploration or parameter adjustment.
*   **When not to use:** For simple camera navigation (use `vtkInteractorStyle`) or for selection tasks better suited to brushing/linking or ray-casting based selection.

## Background
The 3D Widget Interaction Model is a core component of the Visualization Toolkit (VTK). It was developed to provide a standardized way to handle interactive graphical objects in scientific visualization applications. The model is detailed in "Chapter 7 - Advanced Computer Graphics" of the VTK Book [S1, book]. It builds upon the `vtkInteractorObserver` base class, distinguishing itself from `vtkInteractorStyle` by maintaining a persistent scene representation [S1, book].
