# 3D Cursor

Also called: Cross-hair Cursor, Cross-plane Cursor, virtual cursor

## Overview
The 3D Cursor is a direct interaction method that specifies X, Y, and Z coordinates to select or explore features within a volume dataset [S1, S2, unofficial]. It serves as a spatial probe, allowing users to identify internal structures without altering the geometry, distinct from clipping or deformation methods [S1, S2, unofficial]. Unlike 2D cursors, it operates in three dimensions, often visualized as intersecting planes or lines, and can be used for both local selection and action-at-a-distance targeting [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** User position/orientation data (from mouse, tracker, or haptic device) and rendering parameters (volume data, transfer function).
*   **Output:** A visual representation of the cursor overlaid on the volume, and optionally, data values (intensity, gradient) at the cursor's tip [S1, S2, unofficial][S3].

**Data Structures:**
The cursor is defined by its position $(x, y, z)$ in volume space and its geometric properties.
*   **Position:** A 3D vector $P = (x, y, z)$ representing the tip or center of the cursor [S3].
*   **Geometry:** Defined by width and length parameters for each axis (X, Y, Z) [S2, unofficial].
*   **Appearance:** Color and thickness for each axis component [S2, unofficial].
*   **State:** Boolean flags indicating which axes (X, Y, Z) are enabled [S2, unofficial].

**Steps:**
1.  **Initialization:** Define the cursor's initial position and enable specific axes (e.g., X, Y, Z) [S2, unofficial].
2.  **Position Update:** Map user input to the 3D cursor position.
    *   For **local interaction**, map the user's hand or pointer directly to the cursor position [S1, unofficial].
    *   For **action-at-a-distance**, move a "virtual cursor" or "drone" through the environment until it reaches the target distance [S1, unofficial].
3.  **Rendering:**
    *   Generate the cursor geometry (lines or planes) based on the current position and enabled axes [S2, unofficial].
    *   Blend the cursor into the volume data using alpha-blending to ensure visibility against varying densities [S2, unofficial].
4.  **Data Query (Optional, e.g., Data Probe):**
    *   Query the volume data value and derivatives at the cursor tip position [S3].
    *   Display these values in a linked Transfer Function Widget [S3].
    *   Represent the eight corners of the voxel containing the query location as visual markers (e.g., balls) connected by edges [S3].

**Pseudocode:**
```python

    """
    Renders the 3D cursor and queries data if configured.
    
    Args:
        volume_data: 3D array of voxel values.
        cursor_state: Object containing:
            - position: (x, y, z) float tuple
            - enabled_axes: list of strings ('x', 'y', 'z')
            - width: float, width of cursor lines/planes
            - color: tuple (r, g, b, a)
            - thickness: float
        camera_view: Camera projection and model matrices.
        
    Returns:
        Rendered image with cursor overlay.
    """
    # Step 1: Define cursor geometry based on enabled axes
    cursor_geometry = []
    if 'x' in cursor_state.enabled_axes:
        # Create line/plane along X axis at cursor position
        cursor_geometry.append(create_axis_geometry('x', cursor_state.position, cursor_state.width))
    if 'y' in cursor_state.enabled_axes:
        cursor_geometry.append(create_axis_geometry('y', cursor_state.position, cursor_state.width))
    if 'z' in cursor_state.enabled_axes:
        cursor_geometry.append(create_axis_geometry('z', cursor_state.position, cursor_state.width))
        
    # Step 2: Render volume
    volume_image = ray_cast_volume(volume_data, camera_view)
    
    # Step 3: Blend cursor into volume
    # Alpha blending is used to integrate cursor with volume density
    final_image = alpha_blend(volume_image, cursor_geometry, cursor_state.color)
    
    # Step 4: Query data at tip (if using Data Probe variant)
    if cursor_state.query_data:
        tip_position = cursor_state.position
        voxel_value = interpolate_volume(volume_data, tip_position)
        gradient = compute_gradient(volume_data, tip_position)
        # Update linked UI elements with voxel_value and gradient
        update_transfer_function_widget(voxel_value, gradient)
        
    return final_image
```

*   **Occlusion:** In dense volumes, the cursor may be obscured. Alpha blending helps but may reduce precision [S2, unofficial].

## Subtopics

### Data Probe Widget
A specialized 3D cursor shaped like a pencil, designed to point at features in the volume [S3]. It links spatial interaction to transfer function feedback by reporting its tip's position and a slider sub-widget's value [S3]. When the volume widget's position or orientation is modified, the data probe widget's tip tracks its point in volume space [S3]. It can be linked to a haptic device (e.g., SensAble PHANTOM) for direct 3D location and orientation input [S3]. The system queries data value and derivatives at the tip, displaying them in the Transfer Function Widget as a ball, with the eight corners of the containing voxel represented as balls connected by edges [S3].

## Operating characteristics
*   **Time Complexity:** Rendering is $O(1)$ per frame for the cursor overlay, assuming fixed geometry. Data querying is $O(1)$ with trilinear interpolation.
*   **Memory Complexity:** $O(1)$ for cursor state.
*   **Performance:** On hardware like VolumePro vg500, the cursor is hardware-generated, allowing real-time performance without CPU overhead [S2, unofficial].
*   **Strengths:** Direct, intuitive selection; works in both local and action-at-a-distance modes [S1, unofficial].
*   **Limitations:** Limited to point/line/plane selection; does not support complex shape selection [S1, unofficial].
*   **When to use:** For precise spatial exploration and selection within volumes, especially when combined with transfer function editing [S3].

## Background
The 3D Cursor was introduced as a direct interaction method for volumetric displays and ray-casting systems [S1, S2, unofficial]. Mine distinguished between local and action-at-a-distance interactions in virtual worlds, suggesting the use of a "virtual cursor or drone" for distant targets [S1, unofficial]. The Silk Cursor, an extension of 2D area cursors, was also proposed to increase activation area [S1, unofficial]. The VolumePro system implemented a hardware-generated, software-controlled 3D cursor for real-time ray-casting [S2, unofficial]. The Data Probe Widget was developed as part of a multi-dimensional transfer function interaction system, linking spatial widgets to transfer function domains [S3].
