# Pre-integrated Clipping Boundary Handling


## Overview
Pre-integrated Clipping Boundary Handling eliminates visual artifacts at clip boundaries in pre-integrated volume rendering, particularly when using low sampling rates [S1, unofficial]. It differs from surface-shading alternatives by mapping an opaque texture onto the clip geometry to hide artifacts, while specifically preserving the visibility of relationships between internal features, such as distances between isosurfaces, which opaque textures might otherwise obscure [S1, unofficial].

## How it works
**Inputs:**
*   Clipping geometry defined as proxy polygons representing the clipping boundary [S1, unofficial].
*   Viewing ray parameters and volume data values [S1, unofficial].

**Outputs:**
*   Correctly shaded pixel color at the clip boundary, including the contribution of the ray segment between the clip surface and the first volume sample [S1, unofficial].

**Data Structures:**
*   **Clip Geometry:** A set of proxy polygons defining the clipping boundary [S1, unofficial].
*   **Volume Data:** Scalar field or texture values accessed at spatial points $P$ and $Q$ [S1, unofficial].

**Steps:**
1.  Render the clipping surface (proxy polygon) before rendering the clipped volume behind it [S1, unofficial].
2.  For a point $P$ on the rendered clip surface, find the intersection $Q$ of the viewing ray with the first proxy polygon behind $P$ [S1, unofficial].
3.  Look up data values $v_P$ at $P$ and $v_Q$ at $Q$ from the underlying scalar field or texture [S1, unofficial].
4.  Compute the corresponding sampling distance $d$ for the segment between $P$ and $Q$ [S1, unofficial]. For consistency with pre-integration, the actual geometric length of the ray segment is not computed [S1, unofficial].
5.  Compute the contribution of the ray segment between the surface $P$ and the first slice in the clipped volume (point $Q$) using a fragment program [S1, unofficial].
6.  Render the clipped volume behind the boundary [S1, unofficial].

**Pseudocode:**
```python
def render_clip_boundary(ray_origin, ray_direction, clip_polygons, volume_lookup):
    # Step 1: Render clipping surface first
    clip_surface = find_frontmost_intersection(ray_origin, ray_direction, clip_polygons)
    P = clip_surface.intersection_point
    
    # Step 2: Find intersection Q with first proxy polygon behind P
    Q = find_next_intersection(ray_origin, ray_direction, clip_polygons, behind=P)
    
    # Step 3: Lookup data values
    v_P = volume_lookup(P)
    v_Q = volume_lookup(Q)
    
    # Step 4: Compute sampling distance d (not geometric length)
    d = compute_sampling_distance(v_P, v_Q)
    
    # Step 5: Compute segment contribution in fragment program
    segment_contribution = fragment_program_compute(P, Q, d, v_P, v_Q)
    
    # Step 6: Render clipped volume behind Q
    volume_color = render_volume_behind(Q, ray_direction, volume_lookup)
    
    return blend(segment_contribution, volume_color)
```

**Pitfalls:**
*   Opaque textures may obscure internal feature relationships if not handled carefully [S1, unofficial].
*   An alternative optical model using a boundary layer of finite thickness requires interleaved rendering of volume and clip surface, increasing complexity [S1, unofficial].

## Subtopics

### Volume Clipping (Texture Slicing)
Volume clipping in 2D and 3D texture slicing allows arbitrary clip geometry defined by polygons, voxelized geometry, or the iso-surface of another volume. It sets itself apart from slab-based cropping by supporting non-planar and complex clip boundaries through a high-quality shading technique that combines surface-based and volumetric shading. Choose this approach when precise boundary shading is required for complex clip shapes rather than simple axis-aligned slabs. See [Volume Clipping (Texture Slicing)](887-volume-clipping-texture-slicing.md).

## Operating characteristics
*   **Performance:** Minimal overhead on current GPUs due to efficient depth buffer usage [S1, unofficial].
*   **Quality:** Eliminates artifacts at clip boundaries for low sampling rates [S1, unofficial].
*   **Limitations:** Opaque textures may obscure internal feature relationships [S1, unofficial].
*   **Use Case:** Suitable for interactive volume rendering where clip boundaries need to be clean and artifacts minimized, especially with pre-integrated techniques [S1, unofficial].

## Background
Originated in the context of pre-integrated volume rendering to address boundary artifacts [S1, unofficial]. Developed as an alternative to complex interleaved rendering approaches for boundary layers [S1, unofficial]. Used in interactive volume rendering interfaces [S1, unofficial].
