# Volume Clipping (Texture Slicing)

Also called: Clipping Node, Clipping in Texture Slicing, FSClipper, Volume Clipping Node, Volumetric Clipping

## Overview
Volume clipping is a technique to reveal internal structures of a volume model by setting unwanted parts to transparent, complementing transfer function specifications [S1, S4, unofficial]. It sets apart from sibling methods by allowing arbitrary clip geometry (polygons, voxelized geometry, or iso-surfaces) to define the visible region, often implemented via fragment shaders that modify alpha based on geometric distance [S3][S4, unofficial]. Unlike stencil-based approaches which decouple geometry from volume data, this method integrates clipping logic directly into the rendering pipeline of texture slicing [S1, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume texture (3D), `SculptMap` texture (3D, stores clipping state), `PolygonCoord` texture (2D, stores projection coordinates), `clipPlane` (4D vector), `ProjPlane` (4x4 projection matrix), and tool point `P` (4D vector) [S3].
*   **Output:** Rendered color/alpha buffer with clipped regions [S3].

**Data Structures:**
*   `SculptMap`: A 3D texture where each voxel stores a mask value, with voxels inside the clip geometry initialized to 0 (transparent) and remaining voxels set to 1 (opaque) [S1, unofficial].
*   `PolygonCoord`: A 2D texture mapping fragment coordinates to 3D projection space [S3].
*   `ProjPlane`: A uniform 4x4 matrix representing the projection transformation required to map texture coordinates to clip space [S3].
*   `clipPlane`: A uniform `float4` defining the clipping plane equation [S3].
*   `P`: A uniform `float4` where $P_{xyz}$ represents a 3D point and $P_a$ represents the tool radius [S3].

**Steps:**
1.  **Coordinate Projection:** Sample the `PolygonCoord` texture at the input fragment coordinates to obtain 3D texture coordinates [S3].
2.  **Mask Sampling:** Sample the `SculptMap` texture at the obtained 3D coordinates to retrieve the current alpha mask value [S3].
3.  **Coordinate Transformation:** Subtract 0.5 from the 3D coordinate components, append 1.0, and multiply by the `ProjPlane` matrix [S3].
4.  **Perspective Division:** Divide the transformed vector's $x$, $y$, and $z$ components by its $w$ component [S3].
5.  **Distance Calculation:** Compute the 2D Euclidean distance $D = \frac{\| \text{PlaneCoordinates}_{xy} - P_{xy} \|}{P_z}$, where $P_{xy}$ and $P_z$ are components of the tool point vector [S3].
6.  **Alpha Update:** If $D$ is less than the current alpha value, update the alpha value to $D$ [S3].

**Pseudocode:**
```python
import math

def mul_row_vec_mat(vec, mat):
    """Multiplies a row vector by a 4x4 matrix."""
    return [sum(vec[i] * mat[i][j] for i in range(4)) for j in range(4)]

def FSClipper(v2f_Tex0, SculptMap, PolygonCoord, ProjPlane, P):
    # 1. Coordinate Projection
    texCoord = PolygonCoord.sample(v2f_Tex0)
    
    # 2. Mask Sampling
    Col = SculptMap.sample(texCoord[:3])
    
    # 3. Coordinate Transformation
    centered = [texCoord[0] - 0.5, texCoord[1] - 0.5, texCoord[2] - 0.5, 1.0]
    PlaneCoordinates = mul_row_vec_mat(centered, ProjPlane)
    
    # 4. Perspective Division
    PlaneCoordinates[0] /= PlaneCoordinates[3]
    PlaneCoordinates[1] /= PlaneCoordinates[3]
    PlaneCoordinates[2] /= PlaneCoordinates[3]
    
    # 5. Distance Calculation
    D = math.sqrt((PlaneCoordinates[0] - P[0])**2 + (PlaneCoordinates[1] - P[1])**2) / P[2]
    
    # 6. Alpha Update
    if D < Col[3]:
        Col[3] = D
        
    return Col
```

**Parameters:**
*   **Clipping Mode 1:** The part inside the clipping geometry is the clipped object (removed) [S1, unofficial].
*   **Clipping Mode 2:** The part outside the clipping geometry is the clipped object (removed) [S1, unofficial].
*   **Clipping Mode 3:** Initializes the clipped volume model and attaches it to the clipping geometry [S1, unofficial].
*   **Tool Radius:** Stored in $P_a$, defines the effective radius of the clipping tool [S3].

**Edge Cases and Pitfalls:**
*   **Multi-volume Clipping:** Issuing the same clipping operation twice does not realize multi-volume clipping directly; a clipping-geometry-list must be created to arrange different clipping geometries [S1, unofficial].
*   **Performance:** Multi-model clipping can seriously affect the interactive rate at runtime if not optimized [S1, unofficial].
*   **Occlusion:** There is unavailability of volume-based depth buffering, meaning the final rendered frame with multiple volume models cannot always show correct occlusions like wireframe ones [S1, unofficial].

## Subtopics

### [Stencil-based Clipping Geometries](14493-stencil-based-clipping-geometries.md)
Uses the OpenGL stencil buffer to restrict rendering to pixels inside or outside an arbitrary closed surface geometry. Sets apart by decoupling clipping boundary definition from volume data, allowing any triangle mesh to act as a clipper without voxelization overhead. Choose when hardware stencil support is available and arbitrary mesh clippers are needed.

## Operating characteristics
*   **Time Complexity:** Depends on the number of slices and the cost of texture sampling and distance calculation per fragment [S4, unofficial].
*   **Memory Complexity:** Requires storage for the `SculptMap` texture, which scales with the volume resolution [S3].
*   **Performance:** Multi-step slicing with oversampling (e.g., four-times) yields the best quality-performance tradeoff due to increased cache coherency [S4, unofficial].
*   **Strengths:** Allows arbitrary clip geometry (polygons, voxelized, iso-surface) and provides high-quality shading for clip boundaries [S4, unofficial].
*   **Limitations:** Multi-model clipping impacts interactive rate and lack of volume-based depth buffering leads to incorrect occlusions in multi-volume scenes [S1, unofficial].

## Background
Volume clipping was introduced as part of hybrid rendering frameworks for real-time manipulation of volume and surface models [S1, unofficial]. It complements transfer function specifications by providing geometric control over visibility [S1, S4, unofficial]. Techniques for volume clipping in 2D and 3D texture slicing methods were proposed by Weiskopf et al., who also presented high-quality shading techniques for clip boundaries [S4, unofficial]. The method is used in medical visualization (e.g., anatomical atlases) and engineering visualization (e.g., engine box clipping) [S1, S2, unofficial].
