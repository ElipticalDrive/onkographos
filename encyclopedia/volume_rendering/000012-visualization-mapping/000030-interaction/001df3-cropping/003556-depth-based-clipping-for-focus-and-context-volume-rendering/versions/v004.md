# Depth-based Clipping for Focus and Context Volume Rendering

Also called: Four-Pass Depth Clipping, Interactive Lens via Depth Clipping

## Overview
This method decomposes a volume rendering into a high-quality 'focus' region and a lower-quality 'context' region using depth-based clipping and early-z rejection [S1, unofficial]. It is implemented in four rendering passes to maximize fragment shader discard efficiency [S1, unofficial]. It is chosen over tessellating proxy geometry or tagging volume regions because it supports arbitrary convex clip objects and large bricked volumes without performance-complicating side effects [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volume dataset (potentially bricked), a clip object (representing the focus region boundary) defined by front-facing and back-facing polygons, and a depth buffer.
*   **Output:** A rendered image where the focus region is rendered with full sampling/quality and the context region is rendered with reduced sampling/quality (implied by the decomposition goal).

**Data Structures:**
*   **Clip Texture:** A high-resolution depth component texture storing back-face depth values of the clip object [S1, unofficial].
*   **Depth Buffer:** Standard framebuffer depth buffer [S1, unofficial].
*   **Opaque Depth Texture (Optional):** If opaque geometry is present, a texture storing depths of opaque objects [S1, unofficial].

**Parameters:**
*   **Depth Test Modes:** `GL_LESS` (used in Pass 1) and `GL_GREATER` (used in Passes 3 and 4) [S1, unofficial].
*   **Clip Texture Resolution:** High-resolution, matching the screen resolution [S1, unofficial].

**Steps:**
1.  **Pass 1: Initialize Depth Buffer for Front Region.**
    *   Render the front-facing polygons of the clip object into the depth buffer.
    *   Set the depth test to `GL_LESS`.
    *   Draw all volume slices in front-to-back order. This establishes the depth bounds for the front portion of the focus region [S1, unofficial].

2.  **Pass 2: Capture Back-Face Depth.**
    *   Render the back-facing polygons of the clip object.
    *   Copy the resulting depth values into the high-resolution depth component clip texture [S1, unofficial].

3.  **Pass 3: Render Front Half of Focus Region.**
    *   Change the depth test to `GL_GREATER`.
    *   Draw volume slices from the front of the volume until the center of the clip object.
    *   **Fragment Shader Logic:** At the beginning of the fragment shader, read the corresponding back-face depth value from the clip texture. If the fragment's depth is greater than the fetched clip texture value, terminate shader execution (discard fragment) [S1, unofficial]. This ensures early discard of fragments outside the focus region's depth bounds [S1, unofficial].

4.  **Pass 4: Render Back Half of Focus Region and Context.**
    *   Repeat the process for slices from the center of the clip object to the back of the volume, with roles reversed:
        *   Use the back faces of the clip object to initialize the depth buffer.
        *   Use the front faces to set the clip texture (store their depth values).
        *   Set the depth test to `GL_GREATER`.
        *   Render slices from the front of the clip object to the back of the volume.
    *   **Fragment Shader Logic:** Same as Pass 3: read front-face depth from the clip texture and discard if fragment depth > fetched value [S1, unofficial].

**Pseudocode:**
```python
# Pass 1: Initialize depth for front region
set_depth_test(GL_LESS)
render_clip_object_front_faces_into_depth_buffer()
draw_volume_slices_front_to_back()

# Pass 2: Capture back-face depth for clipping
render_clip_object_back_faces()
copy_depth_buffer_to_clip_texture()

# Pass 3: Render front half of focus region
set_depth_test(GL_GREATER)
draw_volume_slices_from_front_to_clip_center()
# In fragment shader:
#   clip_depth = texture(clip_texture, tex_coord).r
#   if fragment_depth > clip_depth: discard

# Pass 4: Render back half of focus region and context
# Re-initialize depth buffer with back faces
set_depth_test(GL_LESS) # Implicitly needed to write depth, though not explicitly stated as GL_LESS, GL_LESS is standard for writing
render_clip_object_back_faces_into_depth_buffer()
# Re-capture front-face depth into clip texture
render_clip_object_front_faces()
copy_depth_buffer_to_clip_texture()

# Render back half
set_depth_test(GL_GREATER)
draw_volume_slices_from_clip_center_to_back()
# In fragment shader:
#   clip_depth = texture(clip_texture, tex_coord).r
#   if fragment_depth > clip_depth: discard
```

**Edge Cases and Pitfalls:**
*   **Screen Space Lenses:** If the lens is screen-space based, the focus does not need to be divided, and a clip texture is not required [S1, unofficial]. However, opaque geometry and acceleration techniques (early ray termination/empty space skipping) require two additional depth textures: one for opaque object depths, one for the current pass's depth buffer [S1, unofficial].
*   **Opaque Geometry:** To incorporate opaque geometry, the opaque depth texture is used to initialize the depth texture at the beginning of the passes, and the current pass's depth buffer is used to initialize the depth buffer for intermediate steps of the acceleration technique [S1, unofficial].
*   **Transition Region:** Additional passes are needed for adding a transition region for blending the results [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Four rendering passes are required, increasing the overhead compared to single-pass methods [S1, unofficial].
*   **Memory Complexity:** Requires a high-resolution depth component clip texture [S1, unofficial]. For screen-space lenses with opaque geometry, two additional depth textures are needed [S1, unofficial].
*   **Strengths:** Supports arbitrary convex clip objects and large bricked volumes without performance-complicating side effects [S1, unofficial]. Maximizes early-z rejection efficiency [S1, unofficial].
*   **Limitations:** Requires multiple passes, which can be costly on hardware with limited render target flexibility. Complexity increases with opaque geometry and acceleration techniques [S1, unofficial].
*   **When to Use:** When interactive focus and context rendering is required with arbitrary convex clip regions and large volumes [S1, unofficial].
*   **When Not to Use:** When screen-space lenses are sufficient and opaque geometry/acceleration techniques are not needed, as the clip texture and multiple passes are unnecessary [S1, unofficial].

## Background
This method was developed by I. K. et al. and presented in the unpublished paper "A Focus and Context Interface for Interactive Volume Rendering" [S1, unofficial]. It was chosen over alternative approaches like tessellating proxy geometry or tagging volume regions due to its ability to handle arbitrary convex clip objects and large bricked volumes efficiently [S1, unofficial].
