# Shader Clip Plane Setup

Also called: Clip Plane Uniform Setup, Custom Clip Plane Uniform, Exclusion Plane Clipping

## Overview
A clipping technique using user-defined planes to cut away parts of a volume, enabling the visualization of interior structures by excluding points on the positive side of the plane [S1, unofficial]. It differs from fixed hardware clipping by passing a 4D homogeneous plane equation to a shader as a uniform, allowing dynamic, per-frame updates of the clipping boundary without rebuilding geometry [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of active exclusion planes, each defined by a normal vector and a distance/offset. In the shader, these are accessed via a uniform array or single uniform depending on the variant.
*   **Output:** A rendered volume where fragments/voxels satisfying the clipping condition are discarded (not colored), effectively "cutting" the volume.

**Data Structures:**
The plane is represented as a 4-component vector (often `vec4` in GLSL/HLSL).
*   **Format A (Homogeneous/Standard):** `(A, B, C, D)` representing the plane equation $Ax + By + Cz + D = 0$. The normal is $(A, B, C)$ and $D = -\text{dot}(\text{normal}, \text{point})$ [S1, unofficial].
*   **Format B (Normal/Distance):** `(nx, ny, nz, w)` where $(nx, ny, nz)$ is the unit normal and $w$ is the signed distance from the origin to the plane along the normal [S3, unofficial].

**Numbered Steps:**
1.  **Bind Shader:** Retrieve the uniform location for the clip plane equation (e.g., `clip_eqn`) from the target shader program [S2, unofficial].
2.  **Upload Data:** Pass the 4 components of the plane equation as floats to the uniform. Unbind the shader program if necessary for other operations [S2, unofficial].
3.  **Shader Evaluation (Per Point/Voxel):**
    *   For each intersection point $p$ (or voxel center) in world space:
    *   Iterate through all active exclusion planes.
    *   **Check Condition:**
        *   If using **Format A**: Calculate $d = \text{dot}(p, \text{vec3}(A,B,C)) + D$. If $d > 0$, the point is on the "cut" side (positive side). Mark `plane_test_passed = false` and break [S1, unofficial].
        *   If using **Format B**: Calculate $d = \text{dot}(p, \text{vec3}(nx,ny,nz))$. If $d \ge w$ (or $> w$ depending on strictness), the point is outside the valid region. Mark `plane_test_passed = false` and break [S3, unofficial].
    *   If `plane_test_passed` is false, discard the fragment/voxel (continue to next iteration or return) [S1, unofficial].
    *   If all planes pass, color the point using the volume transfer function [S1, unofficial].

**Formulas:**
*   **Format A (Homogeneous):**
    $$ \text{clip\_test} = \text{dot}(p_{xyz}, \text{plane}_{xyz}) + \text{plane}_w $$
    Discard if $\text{clip\_test} > 0$ [S1, unofficial].
    *Note: Some implementations use $w=-1$ for homogeneous coordinates in specific contexts, but standard plane equation evaluation uses the 4th component as the offset $D$ [S1, unofficial].*

*   **Format B (Normal/Distance):**
    $$ \text{clip\_test} = \text{dot}(p, \text{clippingPlane}_{xyz}) $$
    Discard if $\text{clip\_test} \ge \text{clippingPlane}_w$ [S3, unofficial].

**Parameters:**
*   `clip_eqn`: 4-component float uniform.
    *   Format A: `[A, B, C, D]` [S2, unofficial].
    *   Format B: `[nx, ny, nz, w]` [S3, unofficial].
*   `MAX_EXCLUSION_PLANES`: Maximum number of planes supported in the shader loop. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors near the plane boundary may cause flickering or artifacts. [G] It is common practice to add a small epsilon bias to the comparison or the plane distance to stabilize the boundary.
*   **Normal Direction:** The "positive" side definition depends on the normal direction. Ensure the normal points *away* from the volume interior if the condition is `dot > 0` (Format A) or `dot >= w` (Format B) [S1, unofficial][S3, unofficial].
*   **Multiple Planes:** The order of plane checks does not matter for correctness, but early-out optimization (breaking on first failure) is critical for performance [S1, unofficial].

**Pseudocode:**
```python
# Shader-side evaluation for a single point p (vec3)
# Assumes uniform vec4 clip_plane represents [A, B, C, D]
# where D = -dot(normal, point_on_plane)

def is_inside_volume(p, clip_plane):
    # Calculate signed distance from point to plane
    # Plane equation: Ax + By + Cz + D = 0
    # dot(p, normal) + D
    normal = vec3(clip_plane.x, clip_plane.y, clip_plane.z)
    d = clip_plane.w
    
    # Evaluate plane equation
    # If result > 0, point is on the positive side (excluded)
    distance = dot(p, normal) + d
    
    if distance > 0.0:
        return False  # Point is clipped
    
    return True     # Point is inside
```

## Subtopics

### Vector4 Plane Representation
A method to represent a clipping plane using a 4D vector where the first three components (xyz) define the plane's normal vector and the fourth component (w) defines the signed distance from the origin to the plane along that normal [S3, unofficial]. It is simpler than managing three separate planes or using sine/cosine rotations for X and Y axes, allowing rotation in all directions (X, Y, and Z) through a single plane definition [S3, unofficial]. The core check is `dot(point, clippingPlane.xyz) < clippingPlane.w` [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of fragments/voxels processed and $P$ is the number of active exclusion planes. The check is a simple dot product per plane.
*   **Memory Complexity:** $O(1)$ additional memory on the GPU for the uniform storage.
*   **Performance:** Very fast as it avoids geometry reconstruction. Performance depends on the number of active planes and the cost of the volume ray-marching loop. [G] Early-out in the plane loop helps if many points are clipped.
*   **Strengths:** Dynamic, per-frame updates; no geometry rebuild; works with any volume rendering technique (ray marching, splatting) that supports fragment/voxel discard.
*   **Limitations:** Requires shader modification or specific uniform support; not all volume rendering engines expose a generic clip plane uniform.
*   **When to use:** When interactive, dynamic cropping is needed without the overhead of modifying the underlying volume data structure or geometry.

## Background
Originating from general graphics clipping techniques, this specific implementation for volume rendering leverages the flexibility of fragment shaders to apply custom clipping logic [S2, unofficial]. It is commonly used in medical imaging and scientific visualization tools (e.g., Godot volume layers, Three.js extensions) to allow users to "slice" through volumes to see internal structures [S1, unofficial][S3, unofficial].
