# Clipping plane for volume suppression

Also called: Clip Plane, Clipping Planes, Cropping Widget Planes, Cut Planes, Volume Cropping via Clipping Planes

## Overview
Clipping plane for volume suppression is a technique that removes specific regions of a volume dataset to reveal interior structures or resolve occlusion, typically by defining one or more arbitrary planes [S1, S2, unofficial]. Unlike [Cropping](1648-cropping.md), which restricts visibility to a rectilinear slab using axis-aligned planes, clipping planes allow for arbitrary orientation and can define complex cutaway views or smooth transitions [S5, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Volume dataset $V$ (scalar or vector field), clipping plane definition (normal vector $\mathbf{n} = (A, B, C)$ and distance parameter $D$ from the origin, or two parallel planes for thickness), and optionally a falloff parameter $D_{\text{fallo}}$ [S4][S5, unofficial].
- **Output:** Rendered image where voxels on the suppressed side of the plane have zero opacity, and voxels in the transition region have modified opacity [S5, unofficial].

**Data Structures:**
- **Clipping Plane:** Defined by a normal vector $\mathbf{n} = (A, B, C)$ and a distance parameter $D$ from the origin [S4][S5, unofficial]. For a single plane, the implicit equation is $Ax + By + Cz - D = 0$ [S4][S5, unofficial]. For a thick cut plane, two parallel planes are defined: $Ax + By + Cz - D_{\min} = 0$ and $Ax + By + Cz - D_{\max} = 0$, where $D_{\min} \neq D_{\max}$ [S5, unofficial]. The thickness is $D_{\max} - D_{\min}$ [S5, unofficial].
- **Widget State:** In interactive systems, a frame-type widget reports the plane's orientation and position to the volume renderer [S9]. The widget can also query positions via mouse clicks on its surface [S9].

**Steps:**
1. **Define Plane Geometry:**
   - For a 2D screen-based clipper, the plane is defined by the point of view (POV) and two user-selected screen points [S4].
   - Calculate the plane coefficients $(A, B, C, D)$ from these three points [S4].
   - Alternatively, for a 3D widget, extract the normal and position from the widget's transformation matrix [S9].
2. **Calculate Signed Distance:**
   - For each voxel center $\mathbf{v} = (x, y, z)$, calculate the signed distance $D_{\text{voxel}}$ to the plane:
     $$ D_{\text{voxel}} = \text{dot}(\mathbf{v}, \mathbf{n}) - D $$
     where $\mathbf{n} = (A, B, C)$ and $D$ is the plane offset [S4][S5, unofficial].
   - For a thick cut plane, calculate distances to both $D_{\min}$ and $D_{\max}$ [S5, unofficial].
3. **Determine Visibility and Opacity:**
   - **Binary Suppression:** If $D_{\text{voxel}} < 0$ (or outside the slab defined by $D_{\min}$ and $D_{\max}$), set opacity $\alpha = 0$ [S4][S5, unofficial].
   - **Smooth Transition:** If a falloff parameter $D_{\text{fallo}}$ is specified:
     - Outside the cut plane (suppressed side): $\alpha = 0$ [S5, unofficial].
     - In the transition region (width $D_{\text{fallo}}$): Multiply the shading-stage opacity $\alpha_{\text{shade}}$ by a correction factor $f$ that increases linearly from $0$ to $1$ [S5, unofficial].
     - In the interior (visible side): $\alpha = \alpha_{\text{shade}}$ [S5, unofficial].
4. **Render:**
   - Render the clipped volume using a standard volume rendering algorithm (e.g., ray casting) [S10].
   - Render the 3D plane widget in a second pass to visualize the clipping boundary [S10].

**Pseudocode:**
```python
def clip_volume(volume, plane_normal, plane_offset, falloff_width=0.0):
    # plane_normal: (A, B, C), plane_offset: D
    clipped_volume = empty_like(volume)
    for voxel in volume:
        dist = dot(voxel.coords, plane_normal) - plane_offset
        if dist < 0:
            clipped_volume[voxel] = 0.0
        elif falloff_width > 0 and dist < falloff_width:
            factor = dist / falloff_width
            clipped_volume[voxel] = voxel.opacity * factor
        else:
            clipped_volume[voxel] = voxel.opacity
    return clipped_volume
```

**Parameters:**
- **$D_{\text{fallo}}$:** Width of the transition region from full opacity to none. Typical value: 5 voxels [S5, unofficial].
- **Single vs. Multiple Planes:** Most systems support a single clipping plane as a compromise between flexibility and usability [S2, unofficial]. VolumePro supports a single cut plane [S5, unofficial]. SFP renderer supports up to 6 cutting planes simultaneously [S17].

**Edge Cases and Pitfalls:**
- **Capping Geometry:** In complex scenarios involving both polygonal geometry and volume data, clipped volume data always contains data inside the clipped region, whereas clipped polygonal objects may be empty. Medical applications often expect intersected 3D geometry to be capped [S3].
- **Orientation Perception:** Users may find it confusing to perceive volume orientation and clipping plane location without additional cues like bounding boxes or stippled lines [S2, unofficial].
- **Coordinate Systems:** Some implementations use normalized coordinates $(0,0,0)$ to $(1,1,1)$ with the volume box center at $(0.5, 0.5, 0.5)$ rather than world-space coordinates [S12].

## Subtopics

### [Clipping Cube and Cutting Plane Interaction](7062-clipping-cube-and-cutting-plane-interaction.md)
This method enables interactive, selective suppression of volume datasets using an axis-aligned Clipping Cube and an arbitrary Cutting Plane, implemented via client-side widgets controlling server-side RTVR clipping capabilities. It distinguishes itself from standard polygon clipping by supporting non-uniform cube resizing via corner spheres and rendering the context region outside the cube as non-photorealistic contours rather than transparent geometry.

### [Virtual Resection](14289-virtual-resection.md)
Virtual Resection is a technique for selectively suppressing portions of a volume dataset to resolve occlusion problems, particularly in medical imaging where internal structures (e.g., pulmonary nodules) are hidden by surrounding tissue (e.g., lung parenchyma). It generates a deformable clipping plane or mask from user-defined resection lines on the organ's surface, allowing the user to cut away specific regions while preserving the texture of the remaining surface. Unlike standard clipping planes that cut the entire volume uniformly, this method enables complex, arbitrary-shaped cutaways centered on regions of interest.

### Note Cut
Cuts the sample after it has been played for x ticks [S13, unofficial].

### Spatial Domain Interaction
An interaction mode where a clipping plane slice is textured with map coordinates to help users understand the relationship between spatial and TF domains [S14]. The user rotates and translates the volume and places a clipping plane [S14]. Voxels on the clipping plane are sampled, and their map coordinates are mapped to color channels (e.g., x,y to Red,Green for Kohonen maps; x,y,z to RGB for Spherical maps) [S14]. The textured slice is blended with the rendered volume using user-controlled opacity [S14]. The user can click on the clipping plane to set the Gaussian TF peak to the map coordinates of the pointed voxel, with a white cross displayed in the map representation corresponding to the mouse position [S14].

### Superimposed Data Visualization with Cutting Planes
A visualization technique for superimposed anatomical and physiological data, displaying physiological data only within a known region of interest (e.g., inside the lung) and on a user-controlled cutting plane surface [S15, unofficial]. The steps are: 1. Identify the region of interest. 2. Display physiological data only within this region. 3. Render the data as grey-scale on the surface exposed by the user-controlled cutting plane [S15, unofficial].

### Clipping Planes for MIP
Applying clipping planes to Maximum Intensity Projection of a Head CT dataset to extract interesting features by slicing the volume [S16, unofficial]. The volume is clipped in half by removing half the face with a vertical plane [S16, unofficial]. This highlights regions of interest unable to be captured in the original visualization without clipping [S16, unofficial].

### Depth-based Clipping
A depth-based clipping approach analyzing depth information of the cutting geometry to decide which part of the volume to clip [S1, unofficial].

### Rigging System for Cutaways
A method allowing the user to modify the appearance of elements in the clipped region via a rigging system defining how the cutaway affects each structure [S1, unofficial].

### Selective Cutting
A feature allowing the user to cut the volume layer by layer, excluding internal parts from being cut [S1, unofficial].

### SFP Cutting Planes
Virtual planes that cut away parts of the image to allow viewing inside the object [S17]. Up to 6 cutting planes can be added simultaneously, and each cutting plane can be placed in an arbitrary position and orientation [S17].

### Local Slicer
A visualization method for scalar fields that renders a 2D slice of the data at a user-specified position, represented by a mesh in a symbolic box [S18]. A visualization method where the user holds and moves a small rectangle plane in the CAVE room. The plane color shows the distribution of a selected scalar field on the slice. It follows wand motion [S18]. Steps: 1. User selects 'Orthoslicer' and presses wand button, causing a box-shaped object symbolizing the data space to appear. 2. A mesh inside the box designates the current slice position. 3. User moves the wand in the desired direction while pressing the button; the mesh moves in accord with the wand motion. 4. When the button is released, render the scalar data distribution at the specified slice position [S18]. Mode 1: The normal vector of the plane is always perpendicular to the wand direction. Mode 2: The normal vector of the plane is always perpendicular to a specified vector field [S18]. Pitfall: Near a 'hot spot' where vector and scalar fields change sharply, the plane exhibits dynamic motion as the user slowly moves the wand around it [S18].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels or samples, as each sample must be tested against the plane equation [S4][S5, unofficial].
- **Memory Complexity:** $O(1)$ additional memory for plane coefficients, plus storage for the volume dataset [S5, unofficial].
- **Performance:** Real-time performance is achievable on modern GPUs using fragment shaders for distance calculation and opacity masking [S4, S12]. VolumePro supports real-time ray-casting with a single cut plane [S5, unofficial].
- **Strengths:** Supports smooth transitions for better visual integration [S5, unofficial].
- **Limitations:** Single plane limits complex cutaway shapes unless combined with other techniques [S2, unofficial]; binary suppression can create harsh edges without falloff [S5, unofficial].
- **When to Use:** When the user needs to remove bulk tissue or outer structures to see embedded details (e.g., chest wall removal for injection site visualization) [S8, unofficial].
- **When Not to Use:** Not given in the sources.

## Background
The VolumePro system, developed in the late 1990s, introduced a single cut plane with smooth falloff capabilities [S5, unofficial]. The X3D standard has supported clipping planes for volumetric data since version 3.2, though it notes ambiguities in capping intersected geometry [S3]. Interactive systems like Simian introduced frame-type widgets for clipping plane manipulation, allowing users to query positions and blend slices [S9]. More recent approaches include depth-based clipping for cutaway views [S1, unofficial] and spatial domain interactions for transfer function design [S14].
