# Clipping plane for volume suppression

Also called: Clip Plane, Clipping Plane Widget, Clipping plane, Cut Planes, Cutaway view generation, Frame type widget

## Overview
A clipping plane is an interaction technique that suppresses portions of a volume dataset by defining a planar slice of arbitrary angle and thickness, generating cutaway views [S1, S2, unofficial][S3]. Unlike [Cropping](1648-cropping.md), which uses axis-aligned slabs, or [Clipping](1444-clipping.md), which typically refers to hardware frustum culling, this method allows independent movement of a single plane to truncate region-growing operations or hide background structures [S1, unofficial][S3]. It serves as a bridge between spatial exploration and transfer function tuning by allowing users to inspect internal structures directly [S5].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume dataset $V$, clipping plane definition (normal vector $\mathbf{n} = (A, B, C)$ and distances $D_{\min}, D_{\max}$), falloff parameter $D_{\text{fallo}}$, and current sample position $\mathbf{p} = (x, y, z)$ [S2, unofficial].
*   **Output:** Modified opacity $\alpha'$ for each sample, where samples outside the plane are suppressed [S2, unofficial].

**Data Structures:**
The clipping plane is defined by two parallel planes:
1.  $Ax + By + Cz - D_{\min} = 0$
2.  $Ax + By + Cz - D_{\max} = 0$
where $D_{\min} \neq D_{\max}$ [S2, unofficial]. The thickness is $D_{\max} - D_{\min}$ [S2, unofficial].

**Steps:**
1.  **Define Plane:** The user manipulates a widget (e.g., frame-type with corner balls and edge bars) to set orientation and position [S3]. The widget reports $\mathbf{n}$ and $D_{\min}, D_{\max}$ to the volume renderer [S3].
2.  **Evaluate Distance:** For each sample at $\mathbf{p}$, compute the signed distance to the plane origin: $d = Ax + By + Cz$ [S2, unofficial].
3.  **Determine Region:**
    *   If $d < D_{\min}$ or $d > D_{\max}$, the sample is outside the cut plane.
    *   If $D_{\min} \le d \le D_{\max}$, the sample is inside.
    *   Transition regions exist within distance $D_{\text{fallo}}$ from $D_{\min}$ and $D_{\max}$ [S2, unofficial].
4.  **Compute Correction Factor:** Calculate a linear correction factor $f$ based on the distance to the nearest boundary [S2, unofficial]:
    *   If $d < D_{\min}$: $f = \max(0, \frac{d - (D_{\min} - D_{\text{fallo}})}{D_{\text{fallo}}})$
    *   If $d > D_{\max}$: $f = \max(0, \frac{(D_{\max} + D_{\text{fallo}}) - d}{D_{\text{fallo}}})$
    *   Otherwise: $f = 1.0$
5.  **Apply Opacity:** Multiply the original opacity $\alpha$ from the shading stage by $f$: $\alpha' = \alpha \cdot f$ [S2, unofficial].
6.  **Optional Slice Mapping:** The volume widget may map a slice of data to the clipping plane and blend it with the volume using a constant opacity determined by the widget’s slider [S3].

**Pseudocode:**
```python
def apply_clipping_plane(opacity: float, position: Vector3, normal: Vector3, 
                         d_min: float, d_max: float, d_fallo: float) -> float:
    """
    Applies clipping plane suppression to a sample's opacity.
    
    Args:
        opacity: Original opacity from shading stage.
        position: Sample position (x, y, z).
        normal: Plane normal (A, B, C).
        d_min: Distance from origin to inner face.
        d_max: Distance from origin to outer face.
        d_fallo: Width of the transition region.
        
    Returns:
        Modified opacity.
    """
    # Calculate signed distance from origin to the point along the normal
    # Note: The source defines plane equations as Ax + By + Cz - D = 0.
    # Thus, the value Ax + By + Cz represents the distance scaled by normal magnitude.
    # Assuming normalized normal, this is the geometric distance.
    distance = dot(position, normal)
    
    # Determine correction factor f
    f = 1.0
    
    if distance < d_min:
        # Outside the inner boundary
        # Linear falloff from 0 to 1 over distance d_fallo
        # At distance = d_min - d_fallo, f = 0
        # At distance = d_min, f = 1
        if distance < (d_min - d_fallo):
            f = 0.0
        else:
            f = (distance - (d_min - d_fallo)) / d_fallo
            
    elif distance > d_max:
        # Outside the outer boundary
        # Linear falloff from 1 to 0 over distance d_fallo
        # At distance = d_max, f = 1
        # At distance = d_max + d_fallo, f = 0
        if distance > (d_max + d_fallo):
            f = 0.0
        else:
            f = ((d_max + d_fallo) - distance) / d_fallo
            
    # Apply correction
    return opacity * f
```

**Parameters:**
*   $D_{\text{fallo}}$: Falloff parameter specifying the width of the transition from full opacity to none. Typical value: 5 voxels [S2, unofficial].
*   Single clipping plane: VolumePro supports only one cut plane [S2, unofficial]. This is considered a reasonable compromise between flexibility and usability [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Ensure $D_{\min} \neq D_{\max}$ to avoid degenerate planes [S2, unofficial].
*   **Boundary Conditions:** Samples exactly on the boundary should be handled consistently with the linear interpolation logic [S2, unofficial].
*   **Visibility Logic:** The method can be inverted to make samples visible *only* if they are outside the cut plane, though the standard implementation suppresses the outside [S2, unofficial].

## Subtopics

### Note Cut
A variant where the clipping plane is triggered temporally rather than spatially, cutting the sample after it has been played for $x$ ticks [S4, unofficial].

### Spatial Domain Interaction
An interaction mode where a clipping plane slice is textured with map coordinates (e.g., from Kohonen or Spherical maps) to help users understand the relationship between spatial and transfer function domains [S5].
*   **Steps:**
    1.  Rotate and translate the volume and place a clipping plane [S5].
    2.  Sample voxels on the clipping plane and retrieve their map coordinates [S5].
    3.  Map map coordinates to color channels: For Kohonen maps, $x$ and $y$ to Red and Green. For Spherical maps, $x, y, z$ to Red, Green, and Blue [S5].
    4.  Blend the textured slice with the rendered volume using a user-controlled opacity [S5].
    5.  Allow the user to click on the clipping plane to set the Gaussian transfer function peak to the map coordinates of the pointed voxel [S5].
    6.  Display a white cross in the map representation corresponding to the mouse position on the clipping plane [S5].

### Clipping Cube and Cutting Plane Interaction
Interaction techniques for selective clipping using a Clipping Cube (axis-aligned, resizable via corner spheres) and a Cutting Plane (arbitrary alignment), implemented via client-side widgets controlling server-side RTVR clipping capabilities [S6, unofficial].
*   **Clipping Cube:** Represented as a wireframe cube with spheres at the corners. Spheres light up when the pen enters them and can be moved to resize the cube non-uniformly while keeping it axis-aligned [S6, unofficial].
*   **Cutting Plane:** Acts like a single face of the clipping cube with arbitrary alignment. Placed by using the PIP pad as the plane in 'cutting' mode, then clicking the second pen button to freeze it [S6, unofficial].
*   **Interaction:** Uses the second pen button for cutting mode because the primary button is used for moving the volume object, enabling two-handed interaction (one hand moves plane via pad, other moves object via pen) [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per frame, where $N$ is the number of samples, as each sample requires a dot product and conditional logic [S2, unofficial].
*   **Memory Complexity:** $O(1)$ for plane parameters, plus storage for the widget state [S3].
*   **Performance:** Hardware-accelerated clipping is possible for polygonal objects, but for volume rendering, it is typically implemented in the ray-casting shader or CPU loop [S6, unofficial]. VolumePro supports this in real-time [S2, unofficial].
*   **Strengths:** Provides an additional means of querying positions distinct from the 3D Data Probe, allowing users to inspect slices and click on boundaries within those slices [S3]. Helps generate cutaway views and truncate region-growing operations [S1, unofficial].
*   **Limitations:** Supports only a single clipping plane in some implementations (e.g., VolumePro) [S2, unofficial]. Perceiving volume orientation and clipping plane location can be confusing without additional cues like bounding boxes [S1, unofficial].
*   **When to Use:** When examining cross-sections of segmented objects or exploring internal structures without removing data from the dataset [S1, unofficial][S5].
*   **When Not to Use:** When multiple independent clipping regions are required (use Cropping or multiple Clipping planes if supported) [S1, unofficial].

## Background
The concept of an independently movable clipping plane for suppressing portions of a volume dataset was originally mentioned in [GK96] and implemented in systems like SIV [S1, unofficial]. It was further detailed in the VolumePro real-time ray-casting system, which supported a single cut plane with smooth falloff [S2, unofficial]. The clipping plane widget was also described as a frame-type widget in interactive volume rendering systems using multi-dimensional transfer functions [S3]. Variants include temporal cutting (Note Cut) [S4, unofficial], spatial domain interaction with map coordinates [S5], and distributed virtual environment interactions with Clipping Cubes [S6, unofficial].
