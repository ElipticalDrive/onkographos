# History Rectification

Also called: AABB Clipping

## Overview
History rectification is a class of Temporal Anti-Aliasing (TAA) techniques that correct historical color values before blending by restricting the reprojected history to a region defined by current-frame neighborhood samples [S1, unofficial]. It solves the problem of temporal lag and ghosting during abrupt scene changes (such as light introduction or sudden movement) where a baseline Exponential Moving Average (EMA) fails to react quickly enough [S1, unofficial]. What sets it apart from its siblings and nearest alternatives is the use of a spatial neighborhood of current-frame samples to define a "color extent" or bound; if the historical value falls outside this extent, it is considered stale and is corrected (clamped or clipped) prior to blending [S1, unofficial]. This approach builds on [AABB Clamping](2019-aabb-clamping.md), which uses a simpler Axis-Aligned Bounding Box approximation, whereas History Rectification encompasses more sophisticated variants like Variance Clipping and AABB Clipping that better handle color information and statistical distributions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The reprojected history buffer value $H$ for the current pixel, and a neighborhood of current-frame color samples $C_{neighbor}$ (typically a 3x3 grid of pixels surrounding the current pixel) [S1, unofficial].
*   **Output:** A rectified history value $H_{rect}$ ready for blending with the current frame [S1, unofficial].

**Data Structures:**
*   **Neighborhood Samples:** A set of color vectors $\{c_1, c_2, ..., c_n\}$ representing the RGB(A) values of the neighboring pixels in the current frame [S1, unofficial].
*   **Bounds:** A minimum vector $min$ and a maximum vector $max$ defining the rectification region. For AABB-based methods, these are component-wise min/max [S1, unofficial]. For Variance Clipping, these are derived from statistical moments [S1, unofficial].

**Steps:**
1.  **Sample Neighborhood:** Gather the color values of the neighboring pixels in the current frame [S1, unofficial]. The standard evaluation uses a 3x3 neighborhood to avoid averaging across depth slices, which would act as a spatial stabilizer and hide flicker artifacts [S1, unofficial]. Alternatives like 3x3x3 or 6-tap neighborhoods smooth across depth but are not used in the primary evaluation context [S1, unofficial].
2.  **Define Bounds:** Calculate the bounding region based on the chosen variant (see Subtopics) [S1, unofficial].
    *   For AABB variants: $min = \min(c_i)$, $max = \max(c_i)$ for each color channel independently [S1, unofficial].
    *   For Variance Clipping: Bounds are expanded beyond min/max using the standard deviation of the neighborhood values to account for statistical distribution [S1, unofficial].
3.  **Rectify History:** Compare the reprojected history value $H$ against the defined bounds [S1, unofficial].
    *   If $H$ is within the bounds, $H_{rect} = H$ [S1, unofficial].
    *   If $H$ is outside the bounds, $H_{rect}$ is adjusted to the nearest boundary value (clamping) or projected onto the boundary (clipping) [S1, unofficial].
4.  **Blend:** Blend $H_{rect}$ with the current frame color $C_{current}$ using the temporal blend factor $\alpha$ (typically $\alpha = 0.05$ for evaluation comparability) [S1, unofficial].

**Formulas:**
For AABB Clamping/Clipping, the rectified value for a single channel is:
$$ H_{rect} = \text{clamp}(H, min, max) $$
Where $\text{clamp}(v, a, b)$ returns $a$ if $v < a$, $b$ if $v > b$, and $v$ otherwise [G].

For Variance Clipping, the bounds are extended by a factor of the standard deviation $\sigma$:
$$ min_{var} = \mu - k \cdot \sigma $$
$$ max_{var} = \mu + k \cdot \sigma $$
Where $\mu$ is the mean of the neighborhood, $\sigma$ is the standard deviation, and $k$ is a scaling factor [G]. The first and second sample moments used for variance clipping are defined as $m_1 = \sum_{i=1}^N c_i$ and $m_2 = \sum_{i=1}^N c_i^2$, from which $\mu = m_1/N$ and $\sigma^2 = m_2/N - \mu^2$ are derived [S1, unofficial].

**Parameters:**
*   **Neighborhood Size:** 3x3 is the standard for evaluation to preserve depth separation [S1, unofficial].
*   **Blend Factor ($\alpha$):** 0.05 is used in the cited evaluations to match baseline EMA conditions [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Static Extent:** When the light turns off, the neighborhood extent becomes 0 (a single point) [S1, unofficial]. The history is clamped to this point, eliminating temporal lag instantly [S1, unofficial].
*   **Gradual Color Change:** AABB clamping struggles with gradual color transitions (e.g., red to blue fade) [S1, unofficial]. It exhibits an especially big RMSE spike at frame 500 and takes around 50 frames for the error to converge back down to the level of AABB clipping [S1, unofficial].
*   **Temporal Instability (TI):** Tighter bounds allow faster adaptation but increase TI, perceived as visual flicker [S1, unofficial]. The distance between highest error peaks is exactly 16 frames, corresponding to the jitter sequence length [S1, unofficial].
*   **Grayscale Scenes:** AABB clipping and clamping produce identical results in grayscale scenes because color rectification is irrelevant [S1, unofficial].

**Pseudocode:**
```python
def history_rectification(history_value, current_frame_color, neighborhood_colors, method='aabb_clamp'):
    """
    Rectifies the history value based on the current frame neighborhood.
    
    Args:
        history_value: list of 3 floats, the reprojected history color [R, G, B].
        current_frame_color: list of 3 floats, the current frame's color.
        neighborhood_colors: list of lists of 3 floats, colors of neighboring pixels.
        method: str, one of 'aabb_clamp', 'aabb_clip', 'variance_clip'.
        
    Returns:
        list of 3 floats, the rectified history value.
    """
    # Step 1: Calculate bounds from neighborhood
    if method in ('aabb_clamp', 'aabb_clip'):
        # Component-wise min and max across the neighborhood
        min_val = [min(c[i] for c in neighborhood_colors) for i in range(3)]
        max_val = [max(c[i] for c in neighborhood_colors) for i in range(3)]
        
        if method == 'aabb_clamp':
            # Clamp history to AABB bounds per channel
            rectified = [max(min_val[i], min(history_value[i], max_val[i])) for i in range(3)]
        else: # aabb_clip
            # Project history onto AABB towards the current frame sample
            # The current frame sample is guaranteed to be inside the AABB
            dir_vec = [current_frame_color[i] - history_value[i] for i in range(3)]
            t_min = 1.0
            for i in range(3):
                if abs(dir_vec[i]) > 1e-6:
                    t1 = (min_val[i] - history_value[i]) / dir_vec[i]
                    t2 = (max_val[i] - history_value[i]) / dir_vec[i]
                    t_lo = min(t1, t2)
                    t_hi = max(t1, t2)
                    t_min = max(t_min, t_lo)
            # Clamp t to [0, 1] to stay within the segment between history and target
            t = max(0.0, min(1.0, t_min))
            rectified = [history_value[i] + t * dir_vec[i] for i in range(3)]
            
    elif method == 'variance_clip':
        # Calculate first and second sample moments per channel
        n = len(neighborhood_colors)
        m1 = [sum(c[i] for c in neighborhood_colors) for i in range(3)]
        m2 = [sum(c[i]**2 for c in neighborhood_colors) for i in range(3)]
        mean_val = [m1[i] / n for i in range(3)]
        variance = [m2[i] / n - mean_val[i]**2 for i in range(3)]
        std_dev = [max(0.0, v)**0.5 for v in variance] # Guard against negative variance due to precision
        k = 1.0 # [G] Scaling factor not specified in sources
        min_val = [mean_val[i] - k * std_dev[i] for i in range(3)]
        max_val = [mean_val[i] + k * std_dev[i] for i in range(3)]
        
        rectified = [max(min_val[i], min(history_value[i], max_val[i])) for i in range(3)]
        
    else:
        rectified = list(history_value) # Fallback to no rectification
        
    return rectified
```

## Subtopics

### Variance Clipping History Rectification
A history rectification method that uses the statistical distribution of values in the current frame neighborhood to create the bounds of the AABB used for clipping [S1, unofficial]. It calculates the mean and standard deviation of the neighborhood colors to define a range that is typically tighter than the raw min/max but accounts for variance [S1, unofficial]. It consistently introduces less bias than AABB-based methods during movement, reducing ghosting artifacts more effectively, but exhibits higher Temporal Instability (flicker) [S1, unofficial]. In step response scenarios, it achieves the lowest RMSE (0.002977) but the highest TI P (0.004217, +190.23% increase over baseline) [S1, unofficial].

### AABB Clipping History Rectification
A history rectification method that projects the history onto the AABB defined by the minimum and maximum values in each color channel of the current frame neighborhood [S1, unofficial]. In grayscale scenes, it produces identical results to AABB Clamping because color rectification is not relevant [S1, unofficial]. It performs better than EMA in abrupt change scenarios and has lower TI than Variance Clipping (TI P of 0.002373, +63.32% over baseline) [S1, unofficial]. However, it struggles with gradual color changes, showing a large RMSE spike when a light fades from red to blue [S1, unofficial].

### Convex Hull Clipping
Clipping the historical value against the convex hull formed by neighboring color samples, representing the smallest convex region containing all neighboring colors [S1, unofficial]. Constructing and projecting history onto the convex hull is too computationally expensive for real-time rendering performance constraints [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(N)$ where $N$ is the number of neighbors in the sampling kernel (e.g., 9 for 3x3) [G]. The operations are simple min/max or mean/std calculations per pixel [G].
*   **Memory:** $O(1)$ auxiliary memory per pixel for storing neighborhood samples during the rectification pass [G].

**Measured Performance:**
*   **Hardware/Resolution:** Not given in the sources.
*   **Scene:** Evaluated in step response (abrupt light on/off) and gradual change (moving/rotating light) scenarios [S1, unofficial].
*   **Metrics:**
    *   **Baseline EMA:** RMSE 0.009724, TI P 0.001453 [S1, unofficial].
    *   **AABB Clamp/Clip:** RMSE 0.003136, TI P 0.002373 (+63.32% TI) [S1, unofficial].
    *   **Variance Clip:** RMSE 0.002977, TI P 0.004217 (+190.23% TI) [S1, unofficial].

**Scaling:**
*   Performance scales with neighborhood size [S1, unofficial]. Larger neighborhoods (3x3x3, 6-tap) smooth the signal across depth, reducing visible flicker but potentially blurring details [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Superior to EMA in abrupt change scenarios; immediately drops error to zero when intensity drops, eliminating temporal lag [S1, unofficial]. Variance clipping produces the lowest error spike when reconstructing the signal during quick illumination introduction [S1, unofficial].
*   **Limitations:** Higher Temporal Instability (flicker) compared to EMA, especially with Variance Clipping [S1, unofficial]. AABB Clamping struggles with gradual color changes, taking ~50 frames to converge after a color fade [S1, unofficial]. Jittering causes periodic error patterns (16-frame cycle) perceived as flicker [S1, unofficial].

**When to use/not use:**
*   **Use:** When rapid reaction to scene changes (light on/off, fast motion) is prioritized over absolute temporal stability, and ghosting must be minimized [S1, unofficial].
*   **Not Use:** In scenes with gradual color transitions where AABB clamping is used, or when visual flicker is unacceptable and higher TI is a dealbreaker [S1, unofficial].

## Background
History rectification techniques were developed as part of the broader effort to improve Temporal Anti-Aliasing (TAA) for real-time rendering, specifically in the context of froxel-based volumetric rendering [S1, unofficial]. The specific evaluation of these methods (Variance Clipping, AABB Clamping, AABB Clipping) is detailed in the work on "Advances in volumetric temporal anti-aliasing for real-time rendering of participating media" [S1, unofficial]. The mathematical definition for each method remains unchanged from their original pixel-space TAA counterparts [S1, unofficial].
