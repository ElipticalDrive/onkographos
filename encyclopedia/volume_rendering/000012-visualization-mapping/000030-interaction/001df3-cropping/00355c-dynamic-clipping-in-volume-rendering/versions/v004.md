# Dynamic Clipping in Volume Rendering

Also called: Clipping in Volume Rendering, Dynamic Clipping Planes Setup, Interactive Volume Cropping, VTK Volume Clipping, Volume Cropping with Clipping Planes, Volume Rendering with Dynamic Clipping, vtk.js Volume Rendering Pipeline

## Overview
Dynamic Clipping in Volume Rendering restricts the visualization to a specific region of interest (ROI) by applying six axis-aligned clipping planes (X min/max, Y min/max, Z min/max) that are updated in response to user interaction [S2, S3, unofficial]. Unlike static cropping masks which are pre-defined, this method allows the clipping boundaries to be adjusted interactively via a widget, converting index-space constraints into world-space planes for the renderer [S2, unofficial]. It sets itself apart from sibling methods like [Clipping plane for volume suppression](887-clipping-plane-for-volume-suppression.md) by explicitly managing the geometric transformation of clipping boundaries relative to the volume's coordinate system, and from [Variance Clipping](1970-variance-clipping.md) by operating on spatial extent rather than statistical data properties.

## How it works
The method involves initializing a volume rendering pipeline, configuring transfer functions, and establishing a mechanism to translate user-defined index-space bounds into world-space clipping planes that are applied to the volume mapper [S1, S2, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   Volume data (e.g., DICOM series, VTI files) with an associated index-to-world transformation matrix [S2, S3, unofficial].
    *   User interaction coordinates defining the cropping region in index (IJK) space [S2, unofficial].
*   **Outputs**:
    *   A rendered volume image where voxels outside the defined clipping box are excluded from the ray-casting integration [S2, unofficial].
    *   Updated clipping plane objects in world space [S2, unofficial].

### Data Structures
1.  **Clipping Planes**: Defined by a normal vector $\mathbf{n}$ and an origin point $\mathbf{o}$. In VTK, this is represented as a plane object. Six planes are required for a box:
    *   X-min: Normal $[-1, 0, 0]$, Origin at $(i_{min}, j_{min}, k_{min})$
    *   X-max: Normal $[1, 0, 0]$, Origin at $(i_{max}, j_{max}, k_{max})$
    *   Y-min: Normal $[0, -1, 0]$, Origin at $(i_{min}, j_{min}, k_{min})$
    *   Y-max: Normal $[0, 1, 0]$, Origin at $(i_{max}, j_{max}, k_{max})$
    *   Z-min: Normal $[0, 0, -1]$, Origin at $(i_{min}, j_{min}, k_{min})$
    *   Z-max: Normal $[0, 0, 1]$, Origin at $(i_{max}, j_{max}, k_{max})$
    *   *Note*: The specific origin assignment for min/max planes in the source code [S2, unofficial] uses the min-corner for negative normals and max-corner for positive normals to ensure the half-space points inward.
2.  **Transformation Matrix**: A $4 \times 4$ matrix (or quaternion for rotation) derived from the volume's index-to-world transform to map axis-aligned normals to world space [S2, unofficial].
3.  **Transfer Functions**:
    *   Color Transfer Function (CTF): Maps scalar values to RGBA. Example points: $(0, 0.333, 0, 0)$, $(95, 0.9765, 0.9647, 0.9333)$, $(225, 0, 0.6, 0.2)$, $(255, 1, 0, 0)$ [S1, unofficial].
    *   Scalar Opacity Function (SOF): Maps scalar values to opacity. Example points: $(0.0, 0.0)$, $(255.0, 1.0)$ [S1, unofficial].

### Parameters
*   `clip_min`: Numpy array `[0.0, 0.0, 0.0]` representing the minimum corner of the clipping box in normalized or index space [S3, unofficial].
*   `clip_max`: Numpy array `[1.0, 1.0, 1.0]` representing the maximum corner [S3, unofficial].
*   `sample_distance`: Controls the step size along the ray. Default/Example: `1.0` [S1, unofficial].
*   `scalar_opacity_unit_distance`: Scaling factor for opacity. Example: `3.0` [S1, unofficial].
*   `gradient_opacity`: Boolean flag to use gradient magnitude for opacity. Example: `true` [S1, unofficial].
*   `gradient_opacity_minimum_value`: Example: `2` [S1, unofficial].
*   `gradient_opacity_minimum_opacity`: Example: `0.0` [S1, unofficial].
*   `gradient_opacity_maximum_value`: Example: `30` [S1, unofficial].
*   `gradient_opacity_maximum_opacity`: Example: `1.0` [S1, unofficial].
*   Shading parameters: `shading=true`, `ambient=0.2`, `diffuse=0.7`, `specular=0.3`, `specular_power=8.0` [S1, unofficial].

### Steps
1.  **Initialize Pipeline**: Create `vtkVolumeMapper` and `vtkVolume`. Set sample distance [S1, unofficial].
2.  **Configure Transfer Functions**:
    *   Create `vtkColorTransferFunction` and add RGB points [S1, unofficial].
    *   Create `vtkPiecewiseFunction` for scalar opacity and add points [S1, unofficial].
    *   Assign these to the volume actor's property [S1, unofficial].
3.  **Setup Interaction Widget**:
    *   Instantiate `vtkImageCroppingWidget` [S2, unofficial].
    *   Register the widget with a `vtkWidgetManager` [S2, unofficial].
    *   Set a display callback to update UI overlays based on widget coordinates [S2, unofficial].
4.  **Handle Cropping State Change**:
    *   Listen for modifications in the widget's cropping state [S2, unofficial].
    *   Retrieve the current cropping planes in index (IJK) space: `[iMin, iMax, jMin, jMax, kMin, kMax]` [S2, unofficial].
5.  **Transform to World Space**:
    *   Extract the rotation component from the volume's index-to-world transformation matrix [S2, unofficial].
    *   Define axis-aligned normals for the six faces of the box [S2, unofficial].
    *   Transform these normals to world space using the extracted rotation [S2, unofficial].
    *   Calculate the world-space origins for the planes using the index-to-world transformation applied to the min and max corners of the IJK bounds [S2, unofficial].
6.  **Apply Clipping Planes**:
    *   Remove any existing clipping planes from the volume mapper [S2, unofficial].
    *   Add the six new world-space planes to the mapper [S2, unofficial].
    *   Mark the mapper as modified to trigger a pipeline update [S2, unofficial].

### Pseudocode

```python
def setup_volume_clipping(volume_data, widget):
    """
    Sets up dynamic clipping for a volume using VTK-like logic.
    volume_data: Object with indexToWorld() method and getRotation() capability.
    widget: Object with getWidgetState().getCroppingPlanes() and onModified().
    """
    # 1. Initialize Mapper and Volume
    mapper = vtkVolumeMapper()
    mapper.set_sample_distance(1.0)
    mapper.set_input_connection(volume_data.get_output_port())
    
    actor = vtkVolume()
    actor.set_mapper(mapper)
    
    # 2. Configure Transfer Functions
    ctfun = vtkColorTransferFunction()
    ctfun.add_rgb_point(0, 85/255.0, 0, 0)
    ctfun.add_rgb_point(95, 0.9765, 0.9647, 0.9333)
    ctfun.add_rgb_point(225, 0, 0.6, 0.2)
    ctfun.add_rgb_point(255, 1, 0, 0)
    
    ofun = vtkPiecewiseFunction()
    ofun.add_point(0.0, 0.0)
    ofun.add_point(255.0, 1.0)
    
    prop = actor.get_property()
    prop.set_rgb_transfer_function(0, ctfun)
    prop.set_scalar_opacity(0, ofun)
    prop.set_scalar_opacity_unit_distance(0, 3.0)
    prop.set_interpolation_type_to_linear()
    prop.set_use_gradient_opacity(0, True)
    prop.set_gradient_opacity_minimum_value(0, 2)
    prop.set_gradient_opacity_minimum_opacity(0, 0.0)
    prop.set_gradient_opacity_maximum_value(0, 30)
    prop.set_gradient_opacity_maximum_opacity(0, 1.0)
    prop.set_shade(True)
    prop.set_ambient(0.2)
    prop.set_diffuse(0.7)
    prop.set_specular(0.3)
    prop.set_specular_power(8.0)
    
    # 3. Get Rotation from Index-to-World Transform
    # Assuming volume_data has a method to get the 4x4 matrix
    index_to_world_matrix = volume_data.get_index_to_world_matrix()
    rotation_quat = get_rotation_quaternion_from_matrix(index_to_world_matrix)
    
    def rotate_vector(vec):
        """Transform a 3D vector by the rotation quaternion."""
        out = [0, 0, 0]
        vec3_transform_quat(out, vec, rotation_quat)
        return out

    def get_world_planes(ijk_bounds):
        """
        Convert IJK bounds to world-space VTK planes.
        ijk_bounds: [iMin, iMax, jMin, jMax, kMin, kMax]
        """
        i_min, i_max, j_min, j_max, k_min, k_max = ijk_bounds
        
        # Origins in world space
        origin_min = volume_data.index_to_world([i_min, j_min, k_min])
        origin_max = volume_data.index_to_world([i_max, j_max, k_max])
        
        # Normals in world space
        n_x_pos = rotate_vector([1, 0, 0])
        n_x_neg = rotate_vector([-1, 0, 0])
        n_y_pos = rotate_vector([0, 1, 0])
        n_y_neg = rotate_vector([0, -1, 0])
        n_z_pos = rotate_vector([0, 0, 1])
        n_z_neg = rotate_vector([0, 0, -1])
        
        planes = []
        # X min/max
        planes.append(vtk_plane(normal=n_x_pos, origin=origin_min)) # Note: Source uses origin for min with normal [1,0,0]? 
        # Correction based on S2 code:
        # X min: normal rotateVec([1,0,0]), origin origin_min
        # X max: normal rotateVec([-1,0,0]), origin origin_max
        # Wait, S2 code says:
        # vtkPlane.newInstance({ normal: rotateVec([1, 0, 0]), origin }) -> X min?
        # vtkPlane.newInstance({ normal: rotateVec([-1, 0, 0]), origin: corner }) -> X max?
        # Usually, normal points OUT of the volume. 
        # If normal is [1,0,0], the plane equation is x = x0. Points with x < x0 are on the negative side.
        # VTK clipping keeps the side where dot(p - origin, normal) >= 0? Or <= 0?
        # Standard VTK: Keeps the side where dot(p - origin, normal) >= 0.
        # So for X-min plane at iMin, we want to keep x >= iMin. Normal should be [1,0,0]. Origin at iMin.
        # For X-max plane at iMax, we want to keep x <= iMax. Normal should be [-1,0,0]. Origin at iMax.
        # This matches S2 code structure.
        
        planes.append(vtk_plane(normal=n_x_pos, origin=origin_min))
        planes.append(vtk_plane(normal=n_x_neg, origin=origin_max))
        
        # Y min/max
        planes.append(vtk_plane(normal=n_y_pos, origin=origin_min))
        planes.append(vtk_plane(normal=n_y_neg, origin=origin_max))
        
        # Z min/max
        planes.append(vtk_plane(normal=n_z_pos, origin=origin_min))
        planes.append(vtk_plane(normal=n_z_neg, origin=origin_max))
        
        return planes

    # 4. Register Callback for Widget State Change
    crop_state = widget.get_widget_state().get_cropping_planes()
    
    def on_crop_modified():
        ijk_bounds = crop_state.get_planes() # Returns [iMin, iMax, jMin, jMax, kMin, kMax]
        
        # Remove old planes
        mapper.remove_all_clipping_planes()
        
        # Get new world planes
        world_planes = get_world_planes(ijk_bounds)
        
        # Add new planes
        for plane in world_planes:
            mapper.add_clipping_plane(plane)
            
        # Trigger update
        mapper.modified()
        
    crop_state.on_modified(on_crop_modified)
    
    return actor, mapper

def vec3_transform_quat(out, vec, quat):
    """Standard quaternion-vector rotation."""
    x, y, z = vec
    qx, qy, qz, qw = quat
    
    # t = 2 * cross(quat.xyz, vec)
    tx = 2 * (qy * z - qz * y)
    ty = 2 * (qz * x - qx * z)
    tz = 2 * (qx * y - qy * x)
    
    # out = vec + quat.w * t + cross(quat.xyz, t)
    out[0] = x + qw * tx + (qy * tz - qz * ty)
    out[1] = y + qw * ty + (qz * tx - qx * tz)
    out[2] = z + qw * tz + (qx * ty - qy * tx)
    return out
```

### Edge Cases and Pitfalls
*   **Coordinate System Mismatch**: Failing to transform index-space normals to world space results in incorrect clipping if the volume is rotated relative to the world axes [S2, unofficial].
*   **Plane Orientation**: The normal vector direction determines which side of the plane is kept. Incorrect assignment of min/max origins to normals will clip the wrong side of the volume [S2, unofficial].
*   **Hardware Clipping Artifacts**: When using hardware clip planes in image-space ray casting for particle volumes, simply discarding particles outside the plane leads to no sharp cuts because the kernel is evaluated for the complete particle footprint. This results in wrong density values at the boundary [S4, unofficial]. To achieve correct volumetric clipping in such cases, the density must be explicitly set to zero in the fragment program if the sampling position is outside the cut planes [S4, unofficial].

## Subtopics

### [Axis Threshold Clipping](11577-axis-threshold-clipping.md)
Axis Threshold Clipping is a dynamic clipping method for 3D Gaussian Splatting that discards Gaussians whose projected screen-space bounding quad exceeds a maximum axis length threshold $\tau_\lambda$. It solves the performance bottleneck of processing large, distant Gaussians that fall outside the view frustum but have significant screen-space extent, specifically targeting mobile hardware constraints. It differs from general volume clipping methods by operating on the projected 2D geometry of splats rather than 3D voxel data, and from sibling dynamic clipping techniques by using a simple axis-aligned bound check rather than complex frustum intersection tests.

### [Clipping Volumes](13345-clipping-volumes.md)
Clipping volumes restrict rendering to a specific region of space defined by a set of planar half-spaces, allowing internal structures to be revealed by discarding geometry outside the defined volume. Unlike static cropping masks, this method constructs a dynamic, convex polyhedral volume (up to 6 planes) that can be combined via intersection or union logic, functioning as a simple Constructive Solid Geometry (CSG) expression. It is distinct from simple view-frustum culling as it allows arbitrary plane orientations and offsets independent of the camera, and from surface-level clipping as it operates on the volumetric data itself.

### Hardware-Accelerated Volumetric Clipping in Image-Space Ray Casting
This variant uses hardware clip planes to discard non-contributing particles in a rasterizer but requires manual density correction in the fragment program to avoid artifacts. Positioning hardware clip planes ensures only non-contributing particles are discarded by the rasterizer [S4, unofficial]. In the fragment program, during density computation, the method checks if the sampling position $p$ is outside the cut planes. If $p$ is outside, the computed density is set to zero to achieve correct volumetric clipping [S4, unofficial]. A key pitfall is that using hardware clip planes alone results in no sharp cuts because the kernel is evaluated for the complete particle footprints, and the missing contribution of clipped particles leads to wrong density results [S4, unofficial].

## Operating characteristics
*   **Time Complexity**: The cost of computing the world-space planes is $O(1)$ per frame (constant number of planes and transformations). The rendering cost depends on the volume rendering algorithm (e.g., ray casting) but is reduced by the clipping as fewer voxels/particles are processed [S2, S4, unofficial].
*   **Memory Complexity**: $O(1)$ for storing the six clipping plane definitions [S2, unofficial].
*   **Performance**: In VTK-based implementations, the update is triggered by `mapper.modified()`, which is efficient for interactive rates [S2, unofficial]. For particle volumes, hardware clipping combined with fragment program checks maintains frame rates even with high particle counts (e.g., 250,000 particles), though isosurface rendering may suffer from memory bandwidth issues due to gradient computation [S4, unofficial].
*   **Strengths**: Interactive exploration of internal structures; simple geometric definition; compatible with standard graphics APIs (OpenGL/Vulkan) via clipping planes [S2, S4, unofficial].
*   **Limitations**: Hardware clipping alone causes artifacts in particle-based volume rendering if not supplemented by shader logic [S4, unofficial]. Requires careful handling of coordinate transformations [S2, unofficial].

## Background
Dynamic clipping in volume rendering is widely implemented in visualization toolkits like VTK (Visualization Toolkit) and its JavaScript port, VTK.js, to support interactive medical imaging applications [S2, unofficial]. The technique allows users to "slice" through volumes to inspect internal anatomy, such as the human chest or skull, by adjusting clipping planes via widgets [S2, unofficial]. The approach of using six axis-aligned planes to define a cropping region is a standard method in 3D visualization for defining a Region of Interest (ROI) [S2, S3, unofficial]. The specific handling of clipping artifacts in particle-based volumes was detailed in research on interactive image-space volume visualization for dynamic particle simulations [S4, unofficial].
