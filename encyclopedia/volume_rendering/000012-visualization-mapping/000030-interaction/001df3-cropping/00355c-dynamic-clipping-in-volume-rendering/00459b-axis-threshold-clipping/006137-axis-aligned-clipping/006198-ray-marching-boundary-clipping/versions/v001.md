# Ray-marching boundary clipping

Also called: Clipping box coordinates within [0, 1] space, Ray-marching volume clipping via boundary check

## Overview
Ray-marching boundary clipping prevents ray-marching from accumulating color and alpha when the ray position is outside a defined clipping box, thereby avoiding the black artifacts caused by discarding fragments in the fragment shader [S1, S2, unofficial]. It differs from fragment-shader discarding by allowing the ray to continue marching through empty space or other volumes without contributing to the final pixel color, preserving the visibility of interior structures [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `currentPosition`: The 3D position of the ray at the current marching step.
    *   `xClippingPlaneMin`, `yClippingPlaneMin`, `zClippingPlaneMin`: Minimum coordinates of the clipping box.
    *   `xClippingPlaneMax`, `yClippingPlaneMax`, `zClippingPlaneMax`: Maximum coordinates of the clipping box.
    *   `colorSample`: The color sampled from the volume at `currentPosition`.
    *   `alphaSample`: The alpha (opacity) sampled from the volume at `currentPosition`.
    *   `accumulatedColor`: The running sum of accumulated color.
    *   `accumulatedAlpha`: The running sum of accumulated alpha.
*   **Outputs:**
    *   Updated `accumulatedColor` and `accumulatedAlpha` if the position is within boundaries; otherwise, they remain unchanged for this step.

**Data Structures:**
*   Clipping box coordinates are defined as six scalar values representing the min/max extents along the X, Y, and Z axes.
*   Clipping box coordinates must be within the [0, 1] space [S1, S2, unofficial].

**Boundary Check Function:**
The method relies on a function `withinBoundaries` that returns `true` if the position is inside the clipping box and `false` otherwise.

$$
\text{withinBoundaries}(pos) = \begin{cases} 
\text{false} & \text{if } pos.x < xClippingPlaneMin \lor pos.y < yClippingPlaneMin \lor pos.z < zClippingPlaneMin \\
\text{false} & \text{if } pos.x > xClippingPlaneMax \lor pos.y > yClippingPlaneMax \lor pos.z > zClippingPlaneMax \\
\text{true} & \text{otherwise}
\end{cases}
$$

**Algorithm Steps:**
1.  Initialize `accumulatedColor` to $(0, 0, 0)$ and `accumulatedAlpha` to $0$ [S1, S2, unofficial].
2.  For each ray-marching iteration $i$ from $0$ to $MAX\_STEPS - 1$:
    a. Calculate `currentPosition` based on the ray origin, direction, and step size [S1, S2, unofficial].
    b. Evaluate `withinBoundaries(currentPosition)` [S1, S2, unofficial].
    c. If `withinBoundaries(currentPosition)` is `true`:
        i. Sample `colorSample` and `alphaSample` from the volume texture at `currentPosition` [S1, S2, unofficial].
        ii. Update `accumulatedColor`:
        $$ accumulatedColor = accumulatedColor + colorSample \times alphaSample $$
        iii. Update `accumulatedAlpha`:
        $$ accumulatedAlpha = accumulatedAlpha + alphaSample \times (1 - accumulatedAlpha) $$
        [S1, S2, unofficial]
    d. If `withinBoundaries(currentPosition)` is `false`:
        i. Skip the composition step for this iteration; do not update `accumulatedColor` or `accumulatedAlpha` [S1, S2, unofficial].
3.  After the loop, apply the final accumulated color and alpha to the pixel [S1, S2, unofficial].

**Pseudocode:**
```python
# Initialize accumulation variables
accumulated_color = (0.0, 0.0, 0.0)
accumulated_alpha = 0.0

# Define clipping boundaries (must be in [0, 1] space)
x_min = xClippingPlaneMin
y_min = yClippingPlaneMin
z_min = zClippingPlaneMin
x_max = xClippingPlaneMax
y_max = yClippingPlaneMax
z_max = zClippingPlaneMax

# Boundary check function
def within_boundaries(pos):
    if pos.x < x_min or pos.y < y_min or pos.z < z_min:
        return False
    if pos.x > x_max or pos.y > y_max or pos.z > z_max:
        return False
    return True

# Ray marching loop
for i in range(MAX_STEPS):
    # Calculate current position along the ray [S1, S2, unofficial]
    # currentPosition = ray_origin + ray_direction * step_size * i
    # (Exact position calculation depends on the specific ray-marching implementation)
    
    if within_boundaries(current_position):
        # Sample volume data at current position [S1, S2, unofficial]
        color_sample = sample_volume(current_position)
        alpha_sample = sample_alpha(current_position)
        
        # Accumulate color and alpha [S1, S2, unofficial]
        accumulated_color = accumulated_color + color_sample * alpha_sample
        accumulated_alpha = accumulated_alpha + alpha_sample * (1.0 - accumulated_alpha)
    else:
        # Skip composition if outside clipping box [S1, S2, unofficial]
        pass
```

**Parameters:**
*   `xClippingPlaneMin`, `yClippingPlaneMin`, `zClippingPlaneMin`: Minimum clipping plane coordinates. Must be in [0, 1] space [S1, S2, unofficial].
*   `xClippingPlaneMax`, `yClippingPlaneMax`, `zClippingPlaneMax`: Maximum clipping plane coordinates. Must be in [0, 1] space [S1, S2, unofficial].
*   `MAX_STEPS`: The maximum number of ray-marching iterations. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Black Artifacts:** Discarding the pixel in the fragment shader prevents it from being rendered at all, causing black areas instead of showing the inner structure or surface [S1, S2, unofficial]. This method avoids that pitfall by skipping accumulation rather than discarding the fragment.
*   **Coordinate Space:** Clipping box coordinates must be within [0, 1] space [S1, S2, unofficial]. Using coordinates outside this range may lead to incorrect clipping behavior.

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of ray-marching steps. The boundary check is $O(1)$ per step.
*   **Memory Complexity:** $O(1)$ additional memory for the clipping boundaries and accumulation variables.
*   **Strengths:** Prevents black artifacts associated with fragment discarding; allows viewing interior structures by effectively "slicing" the volume [S1, unofficial].
*   **Limitations:** Requires the clipping box coordinates to be normalized to [0, 1] space [S1, S2, unofficial]. Performance is not significantly impacted compared to standard ray-marching, as the boundary check is inexpensive.
*   **When to use:** When visualizing interior structures of a volume by clipping away outer layers, and avoiding black artifacts is critical [S1, unofficial].
*   **When not to use:** When the clipping boundaries are not aligned with the axis or when the coordinate space is not normalized to [0, 1] [S1, S2, unofficial].

## Background
This technique was discussed in the context of Three.js volume rendering to address issues with black areas appearing when clipping volumes [S1, S2, unofficial]. It was proposed as an alternative to discarding fragments in the fragment shader, which was found to prevent pixels from being rendered at all [S1, S2, unofficial].
