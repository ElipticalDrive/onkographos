# Clipped Cropping Region Planes

Also called: ClipCroppingRegionPlanes, Cropping Region Plane Clipping, Volume Bounding Box Clipping

## Overview
Clipped Cropping Region Planes is a preprocessing step for volume rendering that ensures user-defined cropping planes remain within the physical bounds of the input volume data [S1, S2, unofficial]. It solves the problem of invalid clipping regions that would otherwise cause rendering artifacts or errors by computing the intersection of arbitrary user-defined planes with the volume's bounding box [S1, unofficial]. Unlike its parent method, Cropping, which defines the logical clipping region, this method enforces geometric validity by clamping the planes to the data extents [S1, S2, unofficial]. It differs from sibling methods like [Pre-integrated Clipping Boundary Handling](7867-pre-integrated-clipping-boundary-handling.md) by operating on the plane coordinates directly rather than modifying the transfer function or integration process [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The input volume dataset (accessed via `this->GetInput(0)`), the user-defined cropping planes array `CroppingRegionPlanes[6]`, and a boolean flag `Cropping` indicating if clipping is active.
*   **Output:** The array `ClippedCroppingRegionPlanes[6]`, which contains the valid, bounded plane coordinates.

**Data Structures:**
*   `volBounds[6]`: An array of 6 doubles representing the volume bounding box in the format `[xmin, xmax, ymin, ymax, zmin, zmax]`.
*   `CroppingRegionPlanes[6]`: An array of 6 doubles representing the user-defined planes. The indices correspond to:
    *   `0, 1`: Min and Max X planes.
    *   `2, 3`: Min and Max Y planes.
    *   `4, 5`: Min and Max Z planes.
*   `ClippedCroppingRegionPlanes[6]`: An array of 6 doubles storing the result.

**Numbered Steps:**
1.  **Validation:** Assert that the input volume exists (`this->GetInput(0) != 0`) [S1, unofficial]. Assert that cropping is enabled (`this->Cropping` is true) and that the planes are ordered correctly: `CroppingRegionPlanes[0] < CroppingRegionPlanes[1]`, `CroppingRegionPlanes[2] < CroppingRegionPlanes[3]`, and `CroppingRegionPlanes[4] < CroppingRegionPlanes[5]` [S1, S2, unofficial]. If these preconditions are not met, the parent render method may silently stop [S2, unofficial].
2.  **Retrieve Bounds:** Get the volume's bounding box into `volBounds[6]` using the dataset's `GetBounds` method: `this->GetInput(0)->GetBounds(volBounds)` [S1, S2, unofficial].
3.  **Clamp Min Planes:** For each axis $i \in \{0, 2, 4\}$ (representing X, Y, Z minimums):
    *   If `CroppingRegionPlanes[i] < volBounds[i]`, set `ClippedCroppingRegionPlanes[i] = volBounds[i]`.
    *   Otherwise, set `ClippedCroppingRegionPlanes[i] = CroppingRegionPlanes[i]` [S1, S2, unofficial].
4.  **Clamp Max Planes:** For each axis $i \in \{1, 3, 5\}$ (representing X, Y, Z maximums):
    *   If `CroppingRegionPlanes[i] > volBounds[i]`, set `ClippedCroppingRegionPlanes[i] = volBounds[i]`.
    *   Otherwise, set `ClippedCroppingRegionPlanes[i] = CroppingRegionPlanes[i]` [S1, S2, unofficial].

**Pseudocode:**
```python
def clip_cropping_region_planes(input_volume, cropping_region_planes, cropping_enabled):
    """
    Clamps user-defined cropping planes to the volume's bounding box.
    
    Args:
        input_volume: Object with GetBounds() method returning [xmin, xmax, ymin, ymax, zmin, zmax].
        cropping_region_planes: List of 6 floats [min_x, max_x, min_y, max_y, min_z, max_z].
        cropping_enabled: Boolean indicating if cropping is active.
        
    Returns:
        List of 6 floats representing the clipped planes.
        
    Raises:
        ValueError: If preconditions are not met.
    """
    # Step 1: Validation
    if input_volume is None:
        raise ValueError("Precondition failed: volume_exists")
    
    if not cropping_enabled:
        raise ValueError("Precondition failed: cropping must be enabled")
        
    # Check ordering: min < max for each axis
    if not (cropping_region_planes[0] < cropping_region_planes[1] and
            cropping_region_planes[2] < cropping_region_planes[3] and
            cropping_region_planes[4] < cropping_region_planes[5]):
        raise ValueError("Precondition failed: planes must be ordered (0<1, 2<3, 4<5)")

    # Step 2: Retrieve Bounds
    vol_bounds = input_volume.GetBounds() # Returns [xmin, xmax, ymin, ymax, zmin, zmax]
    
    # Step 3 & 4: Clamp Planes
    clipped_planes = [0.0] * 6
    
    # Clamp Min Planes (indices 0, 2, 4)
    # Index 0: Min X, Index 2: Min Y, Index 4: Min Z
    # Corresponding bounds indices: 0, 2, 4
    for i in [0, 2, 4]:
        user_plane = cropping_region_planes[i]
        bound_min = vol_bounds[i]
        if user_plane < bound_min:
            clipped_planes[i] = bound_min
        else:
            clipped_planes[i] = user_plane
            
    # Clamp Max Planes (indices 1, 3, 5)
    # Index 1: Max X, Index 3: Max Y, Index 5: Max Z
    # Corresponding bounds indices: 1, 3, 5
    for i in [1, 3, 5]:
        user_plane = cropping_region_planes[i]
        bound_max = vol_bounds[i]
        if user_plane > bound_max:
            clipped_planes[i] = bound_max
        else:
            clipped_planes[i] = user_plane
            
    return clipped_planes
```

**Parameters:**
*   `CroppingRegionPlanes`: User-defined. No typical values given.
*   `volBounds`: Derived from input data.

**Edge Cases and Pitfalls:**
*   **Invalid Ordering:** If `CroppingRegionPlanes` are not ordered (e.g., min > max), the method fails its precondition check [S1, S2, unofficial]. The parent renderer may silently stop without error if this check is bypassed or handled upstream [S2, unofficial].
*   **Empty Volume:** If the volume has zero extent in any dimension, `volBounds` min and max will be equal. The clamping logic still applies, potentially resulting in a zero-thickness clipping region [G].
*   **Precision:** Floating-point comparisons (`<`, `>`) are used. Edge cases where `CroppingRegionPlanes[i]` is extremely close to `volBounds[i]` are handled by the strict inequality checks [S1, S2, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(1)$, as it performs a fixed number of comparisons and assignments (6 planes, 2 bounds checks per plane).
*   **Memory Complexity:** $O(1)$, requiring storage for 6 doubles for the output array.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Ensures geometric validity of clipping regions, preventing rendering errors. Simple and fast.
*   **Limitations:** Only handles axis-aligned bounding box constraints. Does not handle non-planar or polygonal clipping (see [Polygon-based Cropping](11787-polygon-based-cropping.md)).
*   **When to Use:** When using axis-aligned cropping planes and ensuring they stay within data bounds is required.
*   **When Not to Use:** When non-planar clipping is needed or when the cropping region is guaranteed to be within bounds by other means.

## Background
This method is part of the Visualization Toolkit (VTK) volume rendering infrastructure, specifically used in mappers like `vtkGPUMultiVolumeRayCastMapper` [S1, S2, unofficial]. It was developed to handle the robustness of cropping operations in GPU-accelerated volume rendering, ensuring that user interactions with cropping planes do not result in invalid memory access or rendering artifacts [S1, S2, unofficial]. The implementation is found in VTK source code repositories [S1, S2, unofficial].
