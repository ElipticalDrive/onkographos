# Convex VOI Clipping via Weighted Sweep Graph

Also called: Clipper, WSG-based clipping

## Overview
This method is a CPU-based clipping algorithm that intersects a sequence of parallel sampling planes against a user-defined convex Volume of Interest (VOI) to reduce the computational load on the GPU [S1]. It differs from single-plane intersection algorithms by exploiting the coherence between parallel planes, using a Weighted Sweep Graph (WSG) to maintain topological edge order and efficiently handle vertex events during the sweep [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A convex VOI defined by a set of cutting planes (each specified by a normal vector $\mathbf{n}$ and a point $\mathbf{p}$ on the plane), and a sequence of parallel sampling planes defined by their distance from the VOI center along a viewing direction.
*   **Output:** A sequence of convex polygons, each representing the intersection of a sampling plane with the VOI. Each polygon is defined by an ordered list of vertices.

**Data Structures:**
1.  **VOI Representation:** The VOI is implicitly defined by the intersection of half-spaces created by cutting planes. The initial shape is a cube, and each cutting plane slices the current convex volume, adding one face [S1].
2.  **Weighted Sweep Graph (WSG):** A graph structure that encodes the topology of the convex volume. It maintains a list of current edges in polygon order. The WSG allows for:
    *   Maintenance of the edge list in correct polygon order.
    *   Easy detection of vertex events (when a VOI vertex lies between two consecutive sampling planes).
    *   Efficient processing of edge list updates (deleting/inserting edges incident to the vertex generating the event) [S1].
    *   In a planar representation, vertices are connected as needed to maintain the topological structure (e.g., if $v_3$ and $v_2$ are connected, this relationship is preserved in the graph) [S1].

**Algorithm Steps:**
1.  **VOI Definition:** The user defines the convex VOI by starting with a basic convex shape (e.g., a cube) and iteratively adding cutting planes. Each cutting plane is defined by:
    *   A normal vector $\mathbf{n}$, controlled by dragging a line endpoint from the VOI center.
    *   A reference point on the plane, controlled by a slider specifying the distance from the VOI center [S1].
2.  **Initialization:** Construct the WSG for the initial convex VOI. The WSG encodes the topological structure, including vertices and edges, and initializes the edge list for the first sampling plane [S1].
3.  **Sweeping:** Sweep a plane through the volume along the viewing direction. For each sampling plane:
    a.  **Check for Vertex Events:** Determine if any VOI vertex lies between the current sampling plane and the previous one. This is detected by comparing the signed distance of each vertex to the two planes.
    b.  **Update Edge List (if vertex event):** If a vertex event occurs, update the WSG's edge list by removing edges incident to the vertex and adding new edges that become part of the boundary. The WSG structure facilitates this by maintaining the topological relationships [S1].
    c.  **Compute Polygon Vertices:** Compute the intersection of the current sampling plane with the current list of edges (from the WSG). Since the edges are ordered, the resulting intersection points form the vertices of the convex polygon in order [S1].
    d.  **Output Polygon:** Return the ordered list of vertices defining the convex polygon intersection [S1].
4.  **Transmission:** Send the resulting clipped planes (polygons) to the GPU for volume rendering [S1].

**Pseudocode:**
```python
def convex_voi_clipping_via_wsg(voi_cutting_planes, sampling_planes):
    """
    voi_cutting_planes: List of tuples (normal, point) defining the convex VOI.
    sampling_planes: List of distances from VOI center along viewing direction.
    Returns: List of polygons, where each polygon is a list of vertices.
    """
    # Initialize VOI as a cube, then apply cutting planes to define the convex region
    # This step implicitly defines the vertices and edges of the convex VOI
    voi_vertices, voi_edges = initialize_convoi_voi(voi_cutting_planes)
    
    # Initialize WSG with the topological structure of the VOI
    wsg = WeightedSweepGraph(voi_vertices, voi_edges)
    
    polygons = []
    prev_plane_dist = sampling_planes[0]
    
    # Compute initial polygon for the first plane
    # The WSG provides the initial list of edges in polygon order
    current_edges = wsg.get_current_edges()
    initial_polygon = compute_polygon_intersection(current_edges, sampling_planes[0])
    polygons.append(initial_polygon)
    
    for i in range(1, len(sampling_planes)):
        curr_plane_dist = sampling_planes[i]
        
        # Check for vertex events: vertices between prev_plane_dist and curr_plane_dist
        vertices_between = []
        for v in voi_vertices:
            dist_v = project_vertex_to_view_direction(v)
            if is_between(dist_v, prev_plane_dist, curr_plane_dist):
                vertices_between.append(v)
        
        # Update WSG if vertex events occur
        if vertices_between:
            for v in vertices_between:
                wsg.process_vertex_event(v)
        
        # Get updated edge list from WSG
        current_edges = wsg.get_current_edges()
        
        # Compute new polygon by intersecting current edges with the new plane
        new_polygon = compute_polygon_intersection(current_edges, curr_plane_dist)
        polygons.append(new_polygon)
        
        prev_plane_dist = curr_plane_dist
        
    return polygons

def compute_polygon_intersection(edges, plane_dist):
    """
    Intersects a list of edges with a plane at a given distance.
    Returns an ordered list of vertices.
    """
    vertices = []
    for edge in edges:
        # Intersect edge with plane
        intersection_point = intersect_edge_with_plane(edge, plane_dist)
        if intersection_point is not None:
            vertices.append(intersection_point)
    # Vertices are already ordered due to the edge list order from WSG
    return vertices

def is_between(value, min_val, max_val):
    """Check if value is strictly between min_val and max_val."""
    return min_val < value < max_val or max_val < value < min_val

def project_vertex_to_view_direction(vertex):
    """Project vertex onto the viewing direction axis."""
    # Assuming viewing direction is along Z-axis for simplicity, or normalized vector
    return vertex.z # [G] Simplified projection; actual implementation depends on view matrix

def intersect_edge_with_plane(edge, plane_dist):
    """
    Intersect an edge (defined by two vertices) with a plane at plane_dist.
    Returns the intersection point or None if no intersection.
    """
    v1, v2 = edge
    d1 = project_vertex_to_view_direction(v1)
    d2 = project_vertex_to_view_direction(v2)
    
    # Check if edge straddles the plane
    if (d1 - plane_dist) * (d2 - plane_dist) > 0:
        return None
    
    # Linear interpolation to find intersection
    t = (plane_dist - d1) / (d2 - d1)
    intersection = v1 + t * (v2 - v1)
    return intersection
```

**Parameters:**
*   **Cutting Planes:** Defined by normal vector and distance from VOI center. No specific typical values are given, as they are user-defined [S1].
*   **Sampling Planes:** Defined by their distance from the VOI center. The number of planes depends on the desired resolution and VOI size [S1].

**Edge Cases and Pitfalls:**
*   **Vertex Events:** If a VOI vertex lies exactly on a sampling plane, special handling may be required to avoid degenerate polygons. The algorithm assumes vertices between planes trigger updates [S1].
*   **Precision:** Floating-point precision issues may arise when checking if a vertex is between two planes or when computing intersections. [G] Robust geometric predicates should be used.
*   **Degenerate Input:** If the VOI becomes non-convex or invalid due to user input, the algorithm may fail. The method assumes a valid convex VOI [S1].

## Subtopics

## Operating characteristics
*   **Time Complexity:** The complexity depends on the number of edges in the WSG and the number of sampling planes. For each plane, the algorithm iterates through the current edge list. Vertex events require updating the WSG, which is efficient due to its topological structure [S1].
*   **Memory Complexity:** The WSG stores the topological structure of the VOI, which is proportional to the number of vertices and edges of the convex shape [S1].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Reduces GPU computation by clipping the VOI on the CPU. Exploits coherence between parallel planes. Efficiently handles topological changes via the WSG [S1].
*   **Limitations:** Requires CPU processing for clipping. The WSG structure may be complex to implement [S1].
*   **When to use:** When the VOI is significantly smaller than the full volume, and the GPU is the bottleneck. Suitable for interactive visualization where the VOI can be defined by the user [S1].
*   **When not to use:** If the VOI is large or complex, the CPU overhead may negate the benefits. If real-time performance is critical and the GPU can handle the full volume, this method may not be necessary [S1].

## Background
This method was proposed in the context of real-time interactive visualization and manipulation of volumetric data using GPU-based methods [S1]. The goal was to free up GPU resources by reducing the amount of data processed, allowing for more sampling planes or elaborate classification functions [S1]. The WSG structure was introduced to efficiently manage the topological changes during the sweep of parallel planes through a convex VOI [S1].
