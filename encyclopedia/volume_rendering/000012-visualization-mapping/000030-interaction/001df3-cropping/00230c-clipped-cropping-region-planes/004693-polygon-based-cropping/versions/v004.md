# Polygon-based Cropping
Also called: CutLineInside, CutLineOutside, CutingImagedata, Voxel-wise 2D Polygon Clipping

## Overview
Polygon-based cropping is a voxel-wise volume rendering technique that masks voxels based on a user-defined 2D polygon drawn in the display (screen) coordinate space [S1, unofficial]. It solves the problem of interactive, free-form region-of-interest selection by converting screen-space constraints into volume-space visibility masks [S1, unofficial]. It differs from planar clipping methods by supporting arbitrary convex or non-convex polygonal shapes rather than just axis-aligned or arbitrary planar cuts, and it operates by explicitly iterating over voxels to test their projected positions against the polygon boundary [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A `vtkImageData` object containing the volume scalar data, a `vtkRenderer` for coordinate transformation, a `QPolygonF` defining the 2D clipping boundary in screen coordinates, and an integer `type` flag determining the clipping mode [S1, unofficial].
- Output: The modified `vtkImageData` where voxels outside the valid region are set to zero (transparent), effectively cropping the volume [S1, unofficial].

**Data Structures:**
- `vtkImageData`: Stores voxel data. The implementation assumes the scalar type is `unsigned char` [S1, unofficial]. If the type differs, pointer casting must be adjusted [S1, unofficial].
- `QPolygonF`: A 2D polygon defined by a sequence of `QPointF` vertices [S1, unofficial].
- `vtkCoordinate`: Used to transform world coordinates to display coordinates [G].

**Steps:**
1. Retrieve volume metadata: dimensions, spacing, and origin [S1, unofficial].
2. Iterate over all voxel coordinates $(i, j, k)$ within the volume bounds [S1, unofficial].
3. Compute the world position of the current voxel [S1, unofficial].
4. Transform the world position to display coordinates using a coordinate mapper [G].
5. Check if the display position lies inside the user-drawn polygon using the `Qt::OddEvenFill` rule [S1, unofficial].
6. Apply clipping based on `type`: if `type == CutLineInside` and the point is inside the polygon, set the voxel value to 0; if `type == CutLineOutside` and the point is outside the polygon, set the voxel value to 0 [S1, unofficial].
7. After modification, update the volume and re-add it to the renderer [S1, unofficial].

**Pseudocode:**
```python
def polygon_based_cropping(image_data, volume, renderer, polygon, clip_type):
    # Retrieve metadata [S1, unofficial]
    img_dims = image_data.GetDimensions()
    img_spacing = image_data.GetSpacing()
    img_origian = image_data.GetOrigin()
    
    # Standard coordinate transformation helper [G]
    def transform_world_to_display(world_pos, renderer):
        # VTK coordinate system conversion to screen space
        return renderer.GetActors()[0].GetMapper().GetInput().GetCoordinate().GetComputedDoubleDisplayValue(renderer)

    # Iterate over all voxels [S1, unofficial]
    for k in range(img_dims[2]):
        for j in range(img_dims[1]):
            for i in range(img_dims[0]):
                # Compute world position [S1, unofficial]
                world_pos = [
                    i * img_spacing[0] + img_origian[0],
                    j * img_spacing[1] + img_origian[1],
                    k * img_spacing[2] + img_origian[2]
                ]
                
                # Transform to display coordinates [G]
                display_pos = transform_world_to_display(world_pos, renderer)
                
                # Check if point is inside polygon using OddEvenFill rule [S1, unofficial]
                contains_point = point_in_polygon(display_pos, polygon, fill_rule="odd_even")
                
                # Get pointer to voxel data (assumes unsigned char) [S1, unofficial]
                voxel_ptr = image_data.GetScalarPointer(i, j, k)
                
                # Apply clipping logic [S1, unofficial]
                if clip_type == CLIP_INSIDE:
                    if contains_point:
                        voxel_ptr[0] = 0
                elif clip_type == CLIP_OUTSIDE:
                    if not contains_point:
                        voxel_ptr[0] = 0
                        
    # Update volume and renderer [S1, unofficial]
    volume.Update()
    renderer.RemoveVolume(volume)
    renderer.AddVolume(volume)
```

**Parameters:**
- `clip_type`: Enum or integer flag. `CutLineInside` (remove inside polygon), `CutLineOutside` (remove outside polygon) [S1, unofficial].
- `fill_rule`: `Qt::OddEvenFill` is used for point-in-polygon testing [S1, unofficial].

**Edge Cases and Pitfalls:**
- The implementation assumes the bounding box origin starts at `(0,0,0)` [S1, unofficial]. Production code must validate actual bounds [S1, unofficial].
- Do not use `vtkImageIterator` as it cannot retrieve spatial positions; direct indexing is required [S1, unofficial].
- The scalar type is assumed to be `unsigned char` [S1, unofficial]. If the scalar type differs, the pointer cast and assignment must be adjusted [S1, unofficial].

## Subtopics

### [Convex VOI Clipping via Weighted Sweep Graph](15939-convex-voi-clipping-via-weighted-sweep-graph.md)
A CPU-based clipping algorithm that intersects a sequence of parallel sampling planes against a user-defined convex Volume of Interest (VOI) to reduce the computational load on the GPU. It solves the problem of unnecessary volume rendering computation in empty or irrelevant regions by transmitting only the clipped, valid portions of sampling planes to the GPU. It sets itself apart from general convex clipping algorithms by exploiting the coherence between parallel planes and using a Weighted Sweep Graph (WSG) to efficiently manage topological changes (vertex events) during the sweep, avoiding the recomputation of edge lists from scratch for every plane.

### Camera Cropping
A variant that calculates crop offsets from screen coordinates, computes a new image resolution, updates the principal point to preserve the original principal axis, validates dimensions, and updates the camera's image size and principal point [S2, unofficial]. It is chosen when precise camera parameter adjustment is required after defining a rectangular crop region [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the total number of voxels in the volume, as every voxel is visited and transformed [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space, as it modifies the volume in place [S1, unofficial].
- **Performance:** The method is CPU-bound due to the per-voxel coordinate transformation and polygon containment test [S1, unofficial]. It is suitable for interactive editing but may be slow for very large volumes compared to GPU-based clipping [S1, unofficial].
- **Strengths:** Supports arbitrary 2D polygonal shapes in screen space, allowing for intuitive free-form cropping [S1, unofficial].
- **Limitations:** Requires full volume iteration; not suitable for real-time rendering of large datasets without optimization [S1, unofficial]. Assumes specific data types and coordinate systems [S1, unofficial].
- **When to use:** Interactive volume editing where the user draws a custom 2D shape to define the region of interest [S1, unofficial].
- **When not to use:** Real-time rendering of large volumes where performance is critical; use GPU-based clipping or the Convex VOI Clipping method instead [S1, unofficial].

## Background
The method is described in the open-source project `kpengk/VolumeClipping` [S1, unofficial]. It is part of a larger system for interactive volume visualization using VTK and Qt [S1, unofficial]. The approach leverages VTK's coordinate transformation capabilities and Qt's polygon geometry classes to implement a simple, voxel-wise clipping mechanism [S1, unofficial].
