# Polygon-based Cropping
Also called: CutLineInside, CutLineOutside, CutingImagedata, Voxel-wise 2D Polygon Clipping

## Overview
Polygon-based cropping is a voxel-wise volume rendering technique that masks voxels based on a user-defined 2D polygon drawn in the display (screen) coordinate space. It solves the problem of interactive, free-form region-of-interest selection by converting screen-space constraints into volume-space visibility masks. It differs from its parent, [Clipped Cropping Region Planes](2931-clipped-cropping-region-planes.md), which uses axis-aligned or planar boundaries, by allowing arbitrary convex or non-convex polygonal shapes projected onto the view.

## How it works
**Inputs:**
- `image_data`: A `vtkImageData` object containing the volume scalar data, dimensions, spacing, and origin.
- `volume`: A `vtkVolume` object associated with the renderer.
- `renderer`: The `vtkRenderer` instance managing the scene.
- `polygon`: A `QPolygonF` representing the user-drawn 2D polygon in display coordinates.
- `type`: An integer flag indicating the clipping mode: `RenderWidget::CutLineInside` (keep inside) or `RenderWidget::CutLineOutside` (keep outside).

**Outputs:**
- Modified `image_data` where voxels outside the desired region are set to 0 (transparent).
- Updated `volume` and `renderer` state reflecting the new cropping.

**Data Structures:**
- `image_data`: Standard VTK image data structure. The scalar data is assumed to be stored as `unsigned char` (8-bit unsigned integer) [S1, unofficial]. If the scalar type differs, pointer casting must be adjusted [S1, unofficial].
- `polygon`: A list of 2D points `(x, y)` in display coordinates.

**Steps:**
1. **Retrieve Volume Metadata:**
   Get the dimensions, spacing, and origin of the volume data:
   ```python
   img_dims = image_data.GetDimensions()
   img_spacing = image_data.GetSpacing()
   img_origin = image_data.GetOrigin()
   ```
   Note: The implementation assumes the bounding box origin starts at `(0,0,0)` in world space if not explicitly retrieved, but production code must validate actual bounds [S1, unofficial].

2. **Iterate Over Voxels:**
   Loop through all voxel coordinates `(i, j, k)` within the volume bounds:
   ```python
   for i in range(img_dims[0]):
       for j in range(img_dims[1]):
           for k in range(img_dims[2]):
   ```

3. **Compute World Position:**
   Convert voxel indices to world coordinates:
   $$
   \text{world\_pos} = [i \cdot \text{img\_spacing}[0] + \text{img\_origin}[0], \quad j \cdot \text{img\_spacing}[1] + \text{img\_origin}[1], \quad k \cdot \text{img\_spacing}[2] + \text{img\_origin}[2]]
   $$

4. **Compute Display Position:**
   Transform the world position to display (screen) coordinates using the renderer's coordinate transformation:
   ```python
   display_pos = coordinate.GetComputedDoubleDisplayValue(renderer)
   ```
   This step maps the 3D world point to the 2D screen plane corresponding to the current view.

5. **Point-in-Polygon Test:**
   Check if the `display_pos` lies inside the user-defined polygon using the Odd-Even Fill rule:
   ```python
   contains_point = polygon.containsPoint(QPointF(display_pos[0], display_pos[1]), Qt::OddEvenFill)
   ```

6. **Apply Cropping Mask:**
   Modify the voxel value based on the `type` flag:
   - If `type == RenderWidget::CutLineInside` and `contains_point` is `true`, set the voxel value to 0:
     ```python
     *pPixel = 0
     ```
   - If `type == RenderWidget::CutLineOutside` and `contains_point` is `false`, set the voxel value to 0:
     ```python
     *pPixel = 0
     ```
   - Otherwise, leave the voxel value unchanged.

7. **Update Renderer:**
   After modifying the image data, update the volume and re-add it to the renderer to reflect changes:
   ```python
   volume.Update()
   renderer.RemoveVolume(volume)
   renderer.AddVolume(volume)
   ```

**Parameters:**
- `type`: `RenderWidget::CutLineInside` or `RenderWidget::CutLineOutside`.
- `polygon`: User-defined 2D polygon.

**Edge Cases and Pitfalls:**
- **Voxel Data Type:** The implementation assumes `unsigned char` scalar data. If the data type is different, the pointer cast and assignment must be adjusted [S1, unofficial].
- **Bounding Box Origin:** The code assumes the bounding box origin starts at `(0,0,0)`. Production code must validate actual bounds [S1, unofficial].
- **Iterator Limitation:** Do not use `vtkImageIterator` as it cannot retrieve spatial positions; direct indexing is required [S1, unofficial].

## Subtopics

### [Convex VOI Clipping via Weighted Sweep Graph](15939-convex-voi-clipping-via-weighted-sweep-graph.md)
This method is a CPU-based clipping algorithm that intersects a sequence of parallel sampling planes against a user-defined convex Volume of Interest (VOI) to reduce the computational load on the GPU. It solves the problem of unnecessary volume rendering computation in empty or irrelevant regions by transmitting only the clipped, valid portions of sampling planes to the GPU. It sets itself apart from general convex clipping algorithms by exploiting the coherence between parallel planes and using a Weighted Sweep Graph (WSG) to efficiently manage topological changes (vertex events) during the sweep, avoiding the recomputation of edge lists from scratch for every plane.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the total number of voxels in the volume, as each voxel is processed once.
- **Memory Complexity:** $O(1)$ additional memory, as the operation modifies the volume data in place.
- **Performance:** The method is CPU-bound due to the per-voxel transformation and point-in-polygon test. It is suitable for interactive editing but may be slow for large volumes.
- **Strengths:** Allows arbitrary 2D polygonal cropping shapes. Simple to implement.
- **Limitations:** Requires full volume iteration. Not suitable for real-time rendering without optimization. Assumes specific data types and bounding box origins.
