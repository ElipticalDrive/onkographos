# Cropping
Also called: Axis-Aligned Bounding Box Cropping, Axis-Aligned Cropping, SetCroppingRegionPlanes, Slab Cropping, Slab-based cropping

## Overview
Cropping is an interaction technique that restricts volume rendering to a specific region of interest (ROI) by defining axis-aligned cut-planes along the volume's spatial dimensions [S1][S3, S4, unofficial]. It solves the problem of visual clutter and computational waste by allowing users to "slice away" outer layers of a volume to reveal internal structures or focus on specific features [S1][S3, unofficial]. Unlike [Clipping plane for volume suppression](887-clipping-plane-for-volume-suppression.md), which uses arbitrarily oriented planes, cropping is strictly axis-aligned relative to the volume's object coordinates [S3, S4, unofficial]. It differs from [Clipping](1444-clipping.md) in that it defines a rectilinear slab (or union/intersection of slabs) rather than just a near/far camera boundary, and from [Dynamic Clipping in Volume Rendering](7498-dynamic-clipping-in-volume-rendering.md), which supports arbitrary plane orientations [S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The volume dataset $D$ with dimensions $(N_x, N_y, N_z)$, and six scalar parameters defining the cropping region: $(x_{min}, x_{max}, y_{min}, y_{max}, z_{min}, z_{max})$ [S3, S4, unofficial].
*   **Output:** A rendered image where voxels outside the defined region are excluded from the rendering pipeline (opacity set to 0 or skipped) [S3, S4, unofficial].

**Data Structures:**
The cropping region is typically stored as six floating-point or integer values representing the bounds in the volume's local coordinate system [S3, S4, unofficial]. In implementations like VTK, this is managed via a `vtkVolume` mapper with a specific flag [S2, unofficial]:
*   `CroppingEnabled`: Boolean flag (e.g., `mapper->SetCropping(1)`) [S2, unofficial].
*   `CroppingRegionPlanes`: Array of 6 floats `[xmin, xmax, ymin, ymax, zmin, zmax]` [S2, unofficial].
*   `CroppingMode`: Enum specifying the logic, e.g., `VTK_CROP_SUBVOLUME` to restrict rendering to the defined region [S2, unofficial].

**Steps:**
1.  **Define Region:** The user or application sets the six plane coordinates. These coordinates are relative to the volume's object coordinates [S4, unofficial].
2.  **Validate/Clamp:** Ensure the planes are within the volume bounds. If a plane falls outside, it may be clamped or ignored depending on implementation [S3, S4, unofficial]. Note: [Clipped Cropping Region Planes](2931-clipped-cropping-region-planes.md) is a preprocessing step that enforces this validity [S3, S4, unofficial].
3.  **Ray Casting / Slicing:** For each pixel, cast a ray through the volume.
4.  **Visibility Check:** A sample at position $(x, y, z)$ is visible if and only if it falls within the defined region of visibility [S3, unofficial].
    *   The region is typically the intersection of three slabs:
        $$ S_x = \{ (x,y,z) \mid x_{min} \le x \le x_{max} \} $$
        $$ S_y = \{ (x,y,z) \mid y_{min} \le y \le y_{max} \} $$
        $$ S_z = \{ (x,y,z) \mid z_{min} \le z \le z_{max} \} $$
    *   The visible region $V$ is usually $S_x \cap S_y \cap S_z$ [S3, unofficial].
    *   Alternatively, unions or inverses can be used to define more complex visibility masks (e.g., showing only the outer shell) [S3, unofficial].
5.  **Rendering:** Render only the samples that pass the visibility check. If using pre-integration, handle boundary artifacts using [Pre-integrated Clipping Boundary Handling](7867-pre-integrated-clipping-boundary-handling.md) [S3, S4, unofficial].
6.  **Depth Management:** If using depth-based techniques (like DVR prepass), ensure the depth texture maintains correct order when cutting planes are active [S1].

**Pseudocode:**
```python
def render_cropped_volume(volume_data, camera, planes):
    """
    volume_data: 3D array of shape (Nx, Ny, Nz)
    camera: object with get_ray(origin, screen_coord) method
    planes: tuple (xmin, xmax, ymin, ymax, zmin, zmax)
    """
    xmin, xmax, ymin, ymax, zmin, zmax = planes
    
    # Initialize output image
    image = empty_image(camera.width, camera.height)
    
    for y in range(camera.height):
        for x in range(camera.width):
            ray_origin, ray_direction = camera.get_ray((x, y))
            
            # Calculate intersection of ray with the cropping box
            # This is a standard AABB intersection test
            t_min, t_max = intersect_aabb(ray_origin, ray_direction, 
                                          (xmin, ymin, zmin), 
                                          (xmax, ymax, zmax))
            
            if t_max < 0 or t_min > t_max:
                # Ray does not intersect the cropped region
                image[x, y] = background_color
                continue
            
            # Determine start and end points in volume coordinates
            # Note: Ray parameters must be mapped to volume indices
            t_start = max(t_min, 0)
            t_end = t_max
            
            # Perform ray marching only within [t_start, t_end]
            color = accumulate_color(ray_origin, ray_direction, t_start, t_end, volume_data)
            image[x, y] = color
            
    return image

def accumulate_color(origin, direction, t_start, t_end, volume_data):
    """
    Standard ray marching loop restricted to t_start and t_end.
    """
    total_color = (0, 0, 0, 0)
    t = t_start
    step_size = 1.0 / max(volume_data.Nx, volume_data.Ny, volume_data.Nz) # Example step
    
    while t < t_end:
        # Convert ray position to volume index
        pos = origin + direction * t
        idx = pos_to_volume_index(pos, volume_data.origin, volume_data.spacing)
        
        # Check bounds (should be guaranteed by AABB intersection, but good for safety)
        if is_inside_volume(idx, volume_data):
            sample = volume_data[idx]
            alpha, color = transfer_function(sample)
            
            # Front-to-back compositing
            total_color = composite(total_color, color, alpha)
            
            if total_color.a >= 1.0: # Early termination
                break
        
        t += step_size
        
    return total_color
```

**Parameters:**
*   **Plane Coordinates:** Arbitrary voxel positions are allowed [S3, unofficial].
*   **Logic:** Intersection (default), Union, or Inverse [S3, unofficial].
*   **Overlap:** In partitioned volume rendering, subvolume indices $(i, j, k)$ and dimensions $(N_x, N_y, N_z)$ with overlap are used to transform the slab location [S4, unofficial]:
    $$ D_{subj} = (D - Origin_{Sub}) \cdot N $$
    $$ Origin_{Sub} = (i(N_x - overlap), j(N_y - overlap), k(N_z - overlap)) $$
    [S4, unofficial]

**Edge Cases and Pitfalls:**
*   **Depth Order:** When using depth textures (e.g., in DVR prepass), ensure the depth texture correctly maintains order when cutting planes are active [S1].
*   **Boundary Artifacts:** Low sampling rates can cause visual artifacts at clip boundaries. Use [Pre-integrated Clipping Boundary Handling](7867-pre-integrated-clipping-boundary-handling.md) to mitigate this [S3, S4, unofficial].
*   **Invalid Regions:** If $x_{min} > x_{max}$, the region is empty. Implementations should handle or clamp these cases [S3, S4, unofficial].

## Subtopics

### [Clipping plane for volume suppression](887-clipping-plane-for-volume-suppression.md)
A clipping plane for volume suppression uses one or more arbitrarily oriented planes to cut away selected portions of a volume dataset, uncovering internal details. Unlike [Cropping](1648-cropping.md), which restricts visibility to a rectilinear slab defined by planes parallel to the volume axes, clipping planes operate at arbitrary angles and can define a planar slice of finite thickness. It is distinct from [Clipping](1444-clipping.md) in its specific application to volumetric data nodes where the interior of the clipped region retains data, often requiring capping of intersected geometry in medical contexts.

### [Clipping](1444-clipping.md)
Clipping is a technique to enable correct perspective projection in sliced-based volume rendering by defining a near clipping boundary relative to the viewpoint. It solves the problem of incorrect depth impression in inside views, where parallel projection fails to provide accurate spatial cues. Unlike general cropping [Cropping](1648-cropping.md) which cuts along volume faces, this method clips against the camera's near/far planes and active clipping planes to ensure only relevant slabs are processed.

### [Variance Clipping](1970-variance-clipping.md)
Variance clipping is a history rectification technique used in Temporal Anti-Aliasing (TAA) for volumetric rendering that constructs a tight bounding box for valid color values based on the statistical mean and variance of a neighborhood of samples. It solves the problem of ghosting artifacts during rapid illumination changes by adapting the clipping region to the local signal distribution, allowing it to reconstruct signals faster than fixed-bound methods. It sets itself apart from [AABB Clamping](2019-aabb-clamping.md) and [AABB Clipping](1444-clipping.md) by using a statistically derived, typically smaller, clipping region that reacts more precisely to changes, though at the cost of higher temporal instability.

### [Clipped Cropping Region Planes](2931-clipped-cropping-region-planes.md)
Clipped Cropping Region Planes is a preprocessing step that clamps user-defined axis-aligned cropping planes to the volume's bounding box, ensuring the resulting clipping region is valid and contained within the data bounds. It sets apart from its parent method, [Cropping](1648-cropping.md), by enforcing geometric validity before rendering, preventing undefined behavior when planes fall outside the dataset.

### [Dynamic Clipping in Volume Rendering](7498-dynamic-clipping-in-volume-rendering.md)
Dynamic clipping restricts volume rendering to a specific region of interest (ROI) using six user-defined clipping planes, typically derived from an interactive cropping widget. Unlike static cropping masks that cut along axes parallel to the volume faces, this method constructs a dynamic, convex polyhedral volume (up to 6 planes) that can be combined via intersection logic, functioning as a simple Constructive Solid Geometry (CSG) expression. It is distinct from simple view-frustum culling as it allows arbitrary plane orientations and offsets independent of the camera, and from surface-level clipping as it operates on the volumetric data itself.

### [Pre-integrated Clipping Boundary Handling](7867-pre-integrated-clipping-boundary-handling.md)
Pre-integrated Clipping Boundary Handling is a technique to eliminate visual artifacts at clip boundaries in pre-integrated volume rendering, particularly when using low sampling rates. It differs from surface-shading alternatives by mapping an opaque texture onto the clip geometry to hide artifacts, while specifically addressing the need to show relationships between internal features (e.g., distances between isosurfaces) that opaque textures might otherwise obscure.

### Clipping Geometry Illumination
Clipping geometry makes parts of the volume transparent. At the boundary of this geometry, the surface normal of the clipping geometry is used for illumination instead of the volume's gradient [S5, unofficial]. This technique, described in Weiskopf et al., TVCG 2003, enhances the visual clarity of cutaway views by providing consistent lighting cues at the artificial boundaries created by cropping or clipping [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, but the constant factor is reduced by the fraction of the volume rendered. If the cropped region is small, the number of samples per ray decreases significantly.
*   **Memory Complexity:** $O(1)$ additional memory for the plane parameters. No significant storage overhead compared to the base volume data.
*   **Performance:** Significantly improves rendering speed when the ROI is small compared to the full volume. However, if the ROI is large, the overhead of plane checks is negligible.
*   **Strengths:** Simple to implement, intuitive for users (sliders), effective for isolating internal structures.
*   **Limitations:** Cannot handle non-axis-aligned features efficiently. May introduce artifacts at boundaries if not handled properly (e.g., [Pre-integrated Clipping Boundary Handling](7867-pre-integrated-clipping-boundary-handling.md)).
*   **When to Use:** When the user needs to inspect internal structures or focus on a specific part of the volume.
*   **When Not to Use:** When the ROI is arbitrary or non-axis-aligned; use [Clipping plane for volume suppression](887-clipping-plane-for-volume-suppression.md) or [Dynamic Clipping in Volume Rendering](7498-dynamic-clipping-in-volume-rendering.md) instead.

## Background
Cropping is a fundamental interaction technique in volume visualization, widely supported in libraries like VTK (via `SetCroppingRegionPlanes`) and systems like VolumePro [S2, S3, unofficial]. It originated as a method to provide "slices" or "slabs" of data for interactive exploration [S3, unofficial]. The technique is often synchronized with other visualization panels (e.g., DVR and IR panels) to maintain consistency [S1]. It is a key component of the feedback loop in volume visualization interaction, where user input (sliders) modifies the rendering parameters [G].
