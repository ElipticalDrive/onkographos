# Structural Focus+Context Rendering

Also called: SFC rendering, structural F+C volume rendering

## Overview
Structural Focus+Context (SFC) rendering is a volume visualization method that outlines structural relationships between different classification criteria of a multiclassified voxel model [S1, unofficial]. It solves the problem of exploring complex, multiclassified datasets (e.g., multimodal medical images like MR/SPECT) by explicitly modeling the logical inclusion relationships between classification classes [S1, unofficial]. Unlike prior systems that treat classification criteria independently, this method clusters voxels based on combined criteria, constructs a directed graph of these relationships, and applies structural focus+context shading via multimodal 3D texture mapping [S1, unofficial].

## How it works
The method operates in two main phases: a preprocessing phase that builds the structural data model, and a rendering phase that applies user-defined queries to generate the visual output.

### Inputs and Outputs
**Inputs:**
1.  **Original Voxel Model ($V$):** A 3D volume dataset. This may be multimodal (e.g., combining MR and SPECT data) [S1, unofficial].
2.  **Classification Criteria:** A set of independent criteria used to classify the voxels in $V$ [S1, unofficial].
3.  **User Query:** A boolean expression defined over the initial classification criteria [S1, unofficial].

**Outputs:**
1.  **Directed Graph ($G$):** A graph where nodes represent classification classes and edges represent logical implications (inclusion relationships) between classes [S1, unofficial].
2.  **Labelled Voxel Model ($LV$):** An auxiliary 3D volume where each voxel stores a unique integer identifier representing the cluster to which it belongs [S1, unofficial].
3.  **Rendering Parameters:** Transfer functions (CTF and GMTF) computed based on the user query and graph structure [S1, unofficial].

### Data Structures

**1. Directed Graph Model ($G$)**
*   **Nodes:** Represent individual classification criteria (classes).
*   **Edges:** Represent logical implications. An edge from node $A$ to node $B$ indicates that class $A$ is a subset of or implies class $B$ [S1, unofficial].
*   **Purpose:** Defines the "grammar" for boolean arithmetic on classes [S1, unofficial].

**2. Labelled Voxel Model ($LV$)**
*   **Layout:** A 3D array with the same spatial dimensions as the original voxel model $V$.
*   **Content:** Each voxel location $(x, y, z)$ stores a unique integer identifier $L_{x,y,z}$.
*   **Meaning:** $L_{x,y,z}$ identifies the specific cluster (combination of classification criteria) that the voxel at $(x, y, z)$ belongs to [S1, unofficial].

**3. Transfer Functions**
*   **CTF (Color/Visibility Transfer Function):** Defined on the domain of cluster labels (integers from $LV$). It maps each label to:
    *   Visibility (boolean or scalar)
    *   Color (RGB)
    *   Opacity (scalar)
*   **GMTF (Gradient Modulation Transfer Function):** Defined on the domain of cluster labels. It maps each label to a gradient modulation factor, used to adjust shading based on local gradients [S1, unofficial].

### Preprocessing Steps

1.  **Classification:** Classify the initial voxel model $V$ according to various independent criteria. If the data is multimodal, handle each modality's contribution to the classification [S1, unofficial].
2.  **Clustering:** Clusterize the voxel model into subsets of voxels that share the exact same combination of classification criteria.
3.  **Label Assignment:** Construct the auxiliary voxel model $LV$. For each voxel, assign a unique integer identifier corresponding to its cluster [S1, unofficial].
4.  **Graph Construction:**
    *   Identify dependencies between the clusters.
    *   Construct the directed graph $G$ where nodes are the classification criteria and edges represent the logical inclusion relationships derived from the cluster dependencies [S1, unofficial].
5.  **Output Generation:** Output the directed graph $G$ and the labelled voxel model $LV$ [S1, unofficial].

### Rendering Steps

**Step 1: Query Parsing and Transfer Function Computation**
1.  **Input:** User provides a rendering query as a boolean expression of the initial classification criteria (e.g., $A \land B$) [S1, unofficial].
2.  **Parsing:** A parser takes the boolean query and the graph structure $G$ as input.
3.  **Computation:** Using the graph structure as a grammar and applying boolean arithmetic on the classes, the parser computes the CTF and GMTF on the cluster label domain.
    *   The parser determines which clusters (labels in $LV$) satisfy the boolean query.
    *   It assigns visibility, color, opacity, and gradient modulation values to these clusters based on the query and the structural relationships defined in $G$ [S1, unofficial].

**Step 2: Multimodal 3D Texture Mapping Rendering**
1.  **Input:** Original voxel model $V$, labelled voxel model $LV$, computed CTF, and computed GMTF [S1, unofficial].
2.  **Texture Mapping:** Apply a multimodal 3D texture-mapping strategy. This involves binding both $V$ and $LV$ as 3D textures to the graphics hardware [S1, unofficial].
3.  **Fragment Shader Execution:** For each fragment (pixel) in the rendered image:
    a.  **Fetch Values:**
        *   Fetch the voxel value $v$ from the original model $V$ at the current ray/sample position.
        *   Fetch the cluster label $l$ from the auxiliary model $LV$ at the same position.
    b.  **Lookup Parameters:**
        *   Use $l$ to look up rendering parameters from the CTF: $color = CTF_{color}(l)$, $opacity = CTF_{opacity}(l)$, $visible = CTF_{visible}(l)$.
        *   Use $l$ to look up the gradient modulation factor from the GMTF: $mod = GMTF(l)$.
    c.  **Shading:** Apply structural focus+context shading. This typically involves using the fetched $v$ and its gradient, modulated by $mod$, and colored/opacity-adjusted by the CTF parameters [S1, unofficial].
    d.  **Compositing:** Composite the fragment color and opacity into the final image buffer using standard volume rendering compositing (e.g., front-to-back or back-to-front) [S1, unofficial].

### Pseudocode

```python
# Preprocessing Phase
def preprocess(V, criteria_list):
    """
    V: 3D array of voxel values (may be multimodal)
    criteria_list: List of classification criteria functions or thresholds
    Returns: LV (labelled voxel model), G (directed graph)
    """
    # Step 1: Classify voxels
    # Each voxel gets a set of boolean flags indicating which criteria it satisfies
    voxel_flags = {} # Map from (x,y,z) to set of satisfied criteria indices
    
    for each voxel (x, y, z) in V:
        satisfied = set()
        for i, criterion in enumerate(criteria_list):
            if criterion(V[x, y, z]):
                satisfied.add(i)
        voxel_flags[(x, y, z)] = satisfied

    # Step 2: Clusterize and assign unique labels
    # Map each unique combination of criteria to a unique integer label
    label_map = {} # Map from frozenset(criteria) to int label
    next_label = 0
    LV = empty_3d_array_of_integers(same_shape_as(V)
    
    for each voxel (x, y, z) in V:
        criteria_set = frozenset(voxel_flags[(x, y, z)])
        if criteria_set not in label_map:
            label_map[criteria_set] = next_label
            next_label += 1
        LV[x, y, z] = label_map[criteria_set]

    # Step 3: Construct Directed Graph G
    # Nodes are criteria indices. Edges represent inclusion.
    # An edge from A to B exists if all voxels satisfying A also satisfy B?
    # Or based on cluster dependencies? The source says "identifying dependencies between clusters"
    # and "edges represent logical implications between the corresponding classifiers".
    # We assume a standard subset relationship on the criteria sets.
    G = DirectedGraph()
    num_criteria = len(criteria_list)
    
    # Add nodes
    for i in range(num_criteria):
        G.add_node(i)
        
    # Add edges based on inclusion
    # If criterion A implies criterion B, then any voxel satisfying A must satisfy B.
    # This can be checked by verifying if the set of voxels for A is a subset of B.
    # Alternatively, if the criteria are hierarchical, this might be given.
    # Here we infer from data:
    for i in range(num_criteria):
        for j in range(num_criteria):
            if i != j:
                # Check if satisfying i implies satisfying j
                # i.e., for all voxels, if i is satisfied, j is also satisfied
                implies = True
                for each voxel (x, y, z) in V:
                    if i in voxel_flags[(x, y, z)] and j not in voxel_flags[(x, y, z)]:
                        implies = False
                        break
                if implies:
                    G.add_edge(i, j)
                    
    return LV, G

def render(V, LV, G, user_query):
    """
    V: Original voxel model
    LV: Labelled voxel model
    G: Directed graph of criteria relationships
    user_query: Boolean expression string over criteria indices (e.g., "0 & 1")
    Returns: Rendered image
    """
    # Step 1: Parse Query and Compute Transfer Functions
    
    # Parse the boolean expression to determine which clusters are visible
    # The parser uses G as a grammar.
    # Let's assume a simple evaluator that maps criteria indices to boolean values
    # and computes the result for each cluster label.
    
    # Get all unique labels present in LV
    unique_labels = set(LV.flatten())
    
    # Define CTF and GMTF as dictionaries mapping label -> parameters
    CTF = {}
    GMTF = {}
    
    # For each label, determine if it satisfies the user_query
    # We need to know which criteria each label corresponds to.
    # Reconstruct label-to-criteria mapping from preprocessing or store it.
    # Let's assume we have a map: label -> frozenset of criteria indices
    label_to_criteria = reconstruct_label_to_criteria(LV, unique_labels)
    
    for label in unique_labels:
        criteria = label_to_criteria[label]
        
        # Evaluate user_query on the criteria
        # user_query is a boolean expression over criteria indices.
        # We create a context where each criterion index is True if it is in 'criteria'
        query_context = {i: (i in criteria) for i in range(len(G.nodes))}
        
        # Evaluate the boolean expression
        is_visible = evaluate_boolean_expression(user_query, query_context)
        
        if is_visible:
            # Compute rendering parameters
            # Color, opacity, visibility are set based on the query result and potentially the graph structure
            # For simplicity, assume full visibility and default color if visible
            # In a real system, these might be modulated by the graph structure (F+C)
            CTF[label] = {
                'visible': True,
                'color': compute_color(label), # Placeholder for specific color mapping
                'opacity': compute_opacity(label) # Placeholder for specific opacity mapping
            }
            
            # Gradient modulation factor
            # This might depend on the structural role of the cluster
            GMTF[label] = compute_gradient_modulation(label, G)
        else:
            # If not visible, set opacity to 0
            CTF[label] = {
                'visible': False,
                'color': (0, 0, 0),
                'opacity': 0.0
            }
            GMTF[label] = 1.0 # Default modulation
            
    # Step 2: Multimodal 3D Texture Mapping Rendering
    
    # Bind V and LV as 3D textures
    bind_3d_texture(V, texture_unit_0)
    bind_3d_texture(LV, texture_unit_1)
    
    # Bind CTF and GMTF as 1D lookup textures (indexed by label)
    # Since labels are integers, we can map them to texture coordinates
    # Or use a 3D texture for CTF/GMTF if dimensions allow, but 1D is simpler for labels
    bind_1d_texture(CTF_values, texture_unit_2) # Stores color/opacity per label
    bind_1d_texture(GMTF_values, texture_unit_3) # Stores modulation per label
    
    # Execute fragment shader for each pixel
    image = empty_image(same_resolution_as_view)
    
    for each pixel (u, v) in image:
        # Cast ray through volume
        ray = cast_ray(u, v)
        
        color_accum = (0, 0, 0, 0)
        alpha_accum = 0.0
        
        # Sample along ray
        for t in range(num_samples):
            pos = ray.origin + t * ray.direction
            x, y, z = floor(pos)
            
            if not inside_volume(x, y, z):
                break
                
            # Fetch values
            v_val = V[x, y, z]
            label = LV[x, y, z]
            
            # Lookup parameters
            params = CTF[label]
            mod = GMTF[label]
            
            if not params['visible']:
                continue
                
            # Compute gradient at pos (using V)
            grad = compute_gradient(V, pos)
            
            # Apply gradient modulation
            mod_grad = grad * mod
            
            # Compute shading (e.g., Phong)
            shaded_color = compute_shading(v_val, mod_grad, params['color'])
            
            # Composite
            alpha = params['opacity']
            color_accum = blend(color_accum, shaded_color, alpha)
            alpha_accum += alpha * (1 - alpha_accum)
            
            if alpha_accum >= 1.0:
                break
                
        image[u, v] = color_accum
        
    return image
```

### Parameters
*   **CTF:** Defined on the cluster label domain. Determines visibility, color, and opacity for each cluster [S1, unofficial].
*   **GMTF:** Defined on the cluster label domain. Determines the gradient modulation factor for each cluster [S1, unofficial].
*   **User Query:** A boolean expression of the initial classification criteria. Typical values depend on the user's exploration goals [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** Not given in the sources.
*   **Boundaries:** Not given in the sources.
*   **Degenerate Input:** If the classification criteria are contradictory or if the graph contains cycles that violate logical implications, the parser may fail or produce unexpected results. The source assumes a valid directed graph of inclusion relationships [S1, unofficial].
*   **Multimodal Data:** Handling multimodal datasets (e.g., MR/SPECT) requires careful integration of different data modalities during the classification step [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing involves classifying all voxels ($O(N)$ where $N$ is the number of voxels) and constructing the graph ($O(C^2)$ where $C$ is the number of criteria, or $O(N \cdot C)$ if checking all voxels for implications). Rendering is standard volume rendering complexity, but with additional texture lookups for the label and transfer functions.
*   **Memory Complexity:** Requires storing the original voxel model $V$, the labelled voxel model $LV$ (same size as $V$), and the graph $G$ (small compared to $V$). The transfer functions are small (size equal to the number of unique clusters).
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with the resolution of the voxel model due to the need to store and process $LV$. The graph size depends on the number of classification criteria, which is typically small.
*   **Strengths:** Explicitly represents the structure of multiclassified datasets, allowing users to explore logical relationships between classification criteria. Supports interactive querying via boolean expressions.
*   **Limitations:** Requires a preprocessing step to build the graph and labelled model. The complexity of the boolean query evaluation depends on the graph structure.
*   **When to Use:** When exploring multiclassified volume data where the logical relationships between classification criteria are important. Particularly useful for multimodal medical imaging.
*   **When Not to Use:** When the data is not multiclassified or when the classification criteria do not have clear logical inclusion relationships.

## Background
Structural Focus+Context rendering was proposed by P. Abellán, A. Puig, and D. Tost. The paper "Structural focus+context rendering of multiclassified volume data" was received on 31 March 2007, accepted on 1 August 2007, and posted online on 27 October 2007 [S1, unofficial]. It addresses the limitations of existing illustrative visualization systems that do not explicitly represent the structure of multiclassified datasets [S1, unofficial]. The method is used in the context of volume rendering and visualization mapping, specifically for structural and glyph-based visualization [S1, unofficial].
