# Hybrid Rendering for Stress Tensor Fields

Also called: Focus and context visualization

## Overview
Hybrid rendering for stress tensor fields is a visualization approach that combines volume rendering with explicit geometric representations (glyphs and tensorlines) to separate focus and context regions in stress tensor datasets [S1, book]. It solves the problem of visual clutter and occlusion in dense tensor fields by allowing users to interactively select specific regions of interest (focus) for detailed geometric analysis while maintaining a global context view via volume rendering [S1, book]. Unlike pure volume rendering, which obscures internal structures, or pure glyph-based rendering, which lacks global continuity, this method dynamically adjusts opacity and geometry based on user-defined masks [S1, book].

## How it works

### Inputs and Outputs
**Inputs:**
1.  A 3D stress tensor field $\mathbf{T}(\mathbf{x})$.
2.  A scalar invariant field $S(\mathbf{x})$ (e.g., von Mises stress) for volume rendering [S1, book].
3.  User selections from diagram views (e.g., scatterplots, Mohr diagrams) defining the focus regions [S1, book].

**Outputs:**
1.  A rendered image combining volume-rendered context and geometric focus elements [S1, book].

### Data Structures
1.  **Mask Volume:** A 3D volume $M(\mathbf{x})$ where $M(\mathbf{x}) = 1$ if the tensor at $\mathbf{x}$ belongs to the focus region, and $0$ otherwise. This volume is created and updated based on user selections [S1, book].
2.  **Depth Image:** A buffer storing the depth values of the opaque geometric elements (glyphs/tensorlines) to handle intersection with volume rays [S1, book].

### Parameters
*   **$c$:** Determines the slope of the antisymmetric mapping function at the origin. Not given in the sources.
*   **$\alpha$:** Scaling parameter for the antisymmetric mapping function. Not given in the sources.
*   **Global Scale:** A parameter to adapt the size of tensor glyphs. Not given in the sources.
*   **Integration Step Size:** For the Runge-Kutta scheme. Not given in the sources.

### Steps

1.  **Mask Evaluation:** Evaluate the mask volume $M(\mathbf{x})$ to determine which features belong to focus regions based on user selections in diagram views [S1, book].
2.  **Volume Rendering (Context):**
    *   Perform standard GPU ray-casting for the scalar invariant $S(\mathbf{x})$ (e.g., von Mises stress) [S1, book].
    *   Decrease opacity in focus regions ($M(\mathbf{x}) = 1$) to allow analysis of glyphs and tensorlines [S1, book].
    *   Use a depth image of the geometry to account for correct intersections. During volume traversal, stop rays as soon as they hit geometry positions [S1, book].
3.  **Focus Region Rendering:** Map selected features (where $M(\mathbf{x}) = 1$) to geometrical tensor representations. Two options are provided:
    *   **Tensorlines:**
        *   Randomly place seeds inside the masked volume [S1, book].
        *   Integrate the line starting at seed points using a fourth-order Runge-Kutta scheme [S1, book].
        *   Stop integration when the line enters an isotropic region [S1, book].
    *   **Tensor Glyphs:**
        *   Draw ellipsoids in focus regions [S1, book].
        *   Map the tensor to a positive-definite metric using an antisymmetric mapping to distinguish between positive and negative eigenvalues [S1, book].
        *   The mapping function is:
            $$ f(\sigma_i, c, \alpha) = \exp(\alpha \arctan(c \cdot \sigma_i)) $$
            where $\sigma_i$ are the eigenvalues of the tensor [S1, book].
        *   Adapt the glyph’s size using a global scale parameter [S1, book].

### Pseudocode

```python
def render_hybrid_stress_field(tensor_field, scalar_invariant, mask_volume, depth_buffer):
    """
    Renders a hybrid visualization of a stress tensor field.
    
    Args:
        tensor_field: 3D array of stress tensors T(x).
        scalar_invariant: 3D array of scalar values S(x) for volume rendering.
        mask_volume: 3D array M(x) where 1 indicates focus region, 0 indicates context.
        depth_buffer: Buffer storing depth of rendered geometry.
        
    Returns:
        Rendered image.
    """
    # Step 1: Volume Rendering (Context)
    # Initialize image buffer
    image = zeros_like(scalar_invariant.shape[:2])
    
    # Ray casting loop
    for each ray in image:
        t = 0.0
        accumulated_color = 0.0
        accumulated_opacity = 0.0
        
        while t < max_depth:
            x = ray.origin + t * ray.direction
            if not in_bounds(x):
                break
                
            # Get scalar invariant and mask value
            s_val = scalar_invariant[x]
            m_val = mask_volume[x]
            
            # Determine opacity: decrease in focus regions
            # Note: Exact opacity function not specified, assume linear decrease
            base_opacity = compute_opacity(s_val)
            if m_val == 1:
                opacity = base_opacity * 0.5  # Example: 50% opacity in focus
            else:
                opacity = base_opacity
            
            # Check depth buffer for intersection with geometry
            if depth_buffer[x] < t:
                # Ray hits geometry, stop volume traversal
                break
                
            # Composite color
            alpha_term = opacity * (1.0 - accumulated_opacity)
            accumulated_color += alpha_term * s_val
            accumulated_opacity += alpha_term
            
            if accumulated_opacity >= 1.0:
                break
                
            t += step_size
            
        image[ray.xy] = accumulated_color

    # Step 2: Render Focus Region Geometry
    # Option A: Tensorlines
    seeds = random_seeds_inside_mask(mask_volume)
    for seed in seeds:
        line = integrate_tensorline(seed, tensor_field, is_isotropic_check)
        render_line(line, depth_buffer)
        
    # Option B: Tensor Glyphs
    focus_points = get_points_where(mask_volume == 1)
    for point in focus_points:
        tensor = tensor_field[point]
        eigenvalues = compute_eigenvalues(tensor)
        
        # Apply antisymmetric mapping to distinguish positive/negative eigenvalues
        mapped_eigenvalues = []
        for sigma_i in eigenvalues:
            f_val = exp(alpha * arctan(c * sigma_i))
            mapped_eigenvalues.append(f_val)
            
        glyph = create_ellipsoid(mapped_eigenvalues, global_scale)
        render_glyph(glyph, depth_buffer)

    return image

def integrate_tensorline(seed, tensor_field, is_isotropic_check):
    """
    Integrates a tensorline using fourth-order Runge-Kutta.
    """
    points = [seed]
    current_pos = seed
    step_size = 0.1  # Not given in sources
    
    while not is_isotropic_check(tensor_field[current_pos]):
        # Fourth-order Runge-Kutta integration
        k1 = tensor_field[current_pos]
        k2 = tensor_field[current_pos + 0.5 * step_size * k1]
        k3 = tensor_field[current_pos + 0.5 * step_size * k2]
        k4 = tensor_field[current_pos + step_size * k3]
        
        next_pos = current_pos + (step_size / 6.0) * (k1 + 2*k2 + 2*k3 + k4)
        points.append(next_pos)
        current_pos = next_pos
        
    return points

def is_isotropic_check(tensor):
    """
    Checks if a tensor is isotropic.
    """
    # Not given in sources. Typically checks if eigenvalues are equal.
    eigenvalues = compute_eigenvalues(tensor)
    return isclose(eigenvalues[0], eigenvalues[1]) and isclose(eigenvalues[1], eigenvalues[2])
```

### Edge Cases and Pitfalls
*   **Isotropic Regions:** Integration of tensorlines must stop when entering isotropic regions to avoid undefined directions [S1, book].
*   **Occlusion:** Correct intersection handling between volume rendering and opaque geometry is critical. Failure to use a depth buffer can result in incorrect blending [S1, book].
*   **Eigenvalue Sign:** The antisymmetric mapping is required to distinguish between positive and negative eigenvalues, which standard ellipsoid glyphs might not handle correctly if not mapped to a positive-definite metric [S1, book].

## Operating characteristics
*   **Time Complexity:** Depends on the number of rays for volume rendering and the number of seeds for tensorlines/glyphs. Not given in the sources.
*   **Memory Complexity:** Requires storage for the tensor field, scalar invariant, mask volume, and depth buffer. Not given in the sources.
*   **Strengths:** Allows detailed analysis of specific regions (focus) while maintaining global context. Interactive selection via diagram views enables flexible exploration [S1, book].
*   **Limitations:** Requires user interaction to define focus regions. Performance may degrade with high-resolution datasets and dense glyph/tensorline placement. Not given in the sources.
*   **When to Use:** When analyzing stress tensor fields where specific regions of interest need detailed geometric inspection while maintaining awareness of the overall field structure [S1, book].
*   **When Not to Use:** When automatic, non-interactive visualization is required, or when the dataset is too large for real-time interaction [S1, book].

## Background
This method was introduced in the book "A Visual Approach to Analysis of Stress Tensor Fields" [S1, book]. It builds on the idea of using various visualization methods to separate focus and context regions in the dataset [S1, book]. The approach is particularly useful for domain experts who need to analyze specific features in complex simulations, such as slit cube simulations [S1, book].
