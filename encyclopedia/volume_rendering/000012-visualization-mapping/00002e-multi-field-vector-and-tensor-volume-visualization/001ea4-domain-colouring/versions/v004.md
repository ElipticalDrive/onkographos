# Domain Colouring

## Overview
Domain Colouring maps complex numbers defined by real and imaginary parts to colors using a cyclic colormap, scaled by a degree parameter and brightness derived from the magnitude [S1, unofficial]. It differs from sibling methods like [Multi-field Visualization](6557-multi-field-visualization.md) by treating paired scalar fields as a single complex field, directly encoding phase and magnitude into color and brightness [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `real_part` (scalar field), `imag_part` (scalar field), `degree` (integer, typically 1), `cyclic_colourmap` (array of $N$ RGB colors) [S1, unofficial].
- Output: `color` (RGB vector), `brightness` (scalar) [S1, unofficial].

**Data Structures:**
- `cyclic_colourmap`: An array of $N$ colors, where each color is a 3-component vector (R, G, B) [S1, unofficial].

**Steps:**
1. Compute the complex value $z = \text{real\_part} + i \cdot \text{imag\_part}$ [S1, unofficial].
2. Calculate the phase $\theta = \operatorname{atan2}(\text{imag\_part}, \text{real\_part})$ [S1, unofficial].
3. Normalize the phase to $[0, 1)$ via $u = \frac{\theta}{2\pi} + 0.5$ [S1, unofficial].
4. Compute the colormap index $idx = \lfloor u \cdot \text{degree} \cdot N \rfloor \bmod N$ [S1, unofficial].
5. Retrieve the base color $c = \text{cyclic\_colourmap}[idx]$ [S1, unofficial].
6. Calculate the brightness $b = |z|$ [S1, unofficial].
7. Return the final color $b \cdot c$ [S1, unofficial].

**Formulas:**
$$ c = \text{cyclic\_colourmap}\left[ \left\lfloor \left( \frac{\arg(z)}{2\pi} + 0.5 \right) \cdot \text{degree} \cdot N \right\rfloor \bmod N \right] $$
$$ b = |z| $$
$$ \text{output} = b \cdot c $$
where $z = \text{real\_part} + i \cdot \text{imag\_part}$ and $N$ is the length of `cyclic_colourmap` [S1, unofficial].

**Pseudocode:**
```python
import math
import torch

def rotate_quaternion(v, q):
    # Rotate vector v by unit quaternion q (w, x, y, z)
    # Assumes q is normalized [G]
    q_w, q_vec = q[..., 0], q[..., 1:]
    cross1 = torch.cross(q_vec, v)
    cross2 = torch.cross(q_vec, cross1)
    return v + 2.0 * (q_w * cross1 + cross2)

def domain_colouring(real_part, imag_part, cyclic_colourmap, degree=1):
    theta = torch.atan2(imag_part, real_part)
    normalized_phase = (theta / (2 * math.pi)) + 0.5
    index = (normalized_phase * degree * cyclic_colourmap.shape[0]).floor().long().remainder(cyclic_colourmap.shape[0])
    colours = cyclic_colourmap[index]
    brightness = torch.norm(torch.stack([real_part, imag_part], dim=-1), dim=-1, keepdim=True)
    return colours * brightness

def tangent_shading(surface_normals, ray_directions, camera_orientation_conj, cyclic_colourmap, degree=1):
    dot = (surface_normals * ray_directions).sum(dim=-1, keepdim=True)
    projected = surface_normals - dot * ray_directions
    rotated = rotate_quaternion(projected, camera_orientation_conj)
    return domain_colouring(rotated[..., 0], rotated[..., 1], cyclic_colourmap, degree)
```

**Edge Cases and Pitfalls:**
- **Zero Magnitude:** If $z=0$, $\arg(z)$ is undefined, but `atan2(0, 0)` returns 0, yielding a black output (brightness 0) [G].
- **Precision:** Floating-point precision in `atan2` and normalization can cause slight discontinuities at the branch cut (negative real axis) [G].
- **Degree Parameter:** A degree $>1$ creates multiple color cycles around the origin, scaling the phase mapping [S1, unofficial].

## Subtopics

### Tangent Shading
Tangent Shading applies Domain Colouring to surface normals projected onto the tangent plane of a ray [S1, unofficial]. It projects the surface normal $\mathbf{n}$ onto the plane perpendicular to the ray direction $\mathbf{r}$, rotates the result to camera space, and applies Domain Colouring to the resulting 2D tangent vector components [S1, unofficial]. This highlights the spin orientation of objects relative to the camera [S1, unofficial].

**Formula:**
$$ \mathbf{t} = \mathbf{n} - (\mathbf{n} \cdot \mathbf{r})\mathbf{r} $$
The vector $\mathbf{t}$ is rotated by the camera orientation conjugate, and Domain Colouring is applied to $t_x$ and $t_y$ [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample point, dominated by `atan2`, norm, and array lookup [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the colormap, where $N$ is the number of colors [S1, unofficial].
- **Strengths:** Efficiently visualizes complex phase information; simple to implement in shaders [S1, unofficial].
- **Limitations:** Only applicable to data that can be naturally represented as complex numbers or 2D vectors; magnitude scaling can obscure phase details if not normalized [S1, unofficial].
- **When to Use:** When visualizing fields with inherent rotational or phase characteristics, such as spin orientation in ray-marched scenes [S1, unofficial].
- **When Not to Use:** For general scalar or vector fields without complex structure [S1, unofficial].

## Background
Domain Colouring is adapted from complex analysis visualization for use in ray marching and constructive geometry [S1, unofficial]. It is used to render objects based on their spin orientation relative to the camera, providing a visual cue for rotational symmetry in SDF-based scenes [S1, unofficial].
