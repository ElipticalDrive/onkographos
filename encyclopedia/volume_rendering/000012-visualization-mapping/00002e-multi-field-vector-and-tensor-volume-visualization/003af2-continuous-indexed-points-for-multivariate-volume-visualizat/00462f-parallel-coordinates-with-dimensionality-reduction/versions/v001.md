# Parallel Coordinates with Dimensionality Reduction

Also called: Pradhan et al. interface, Zhao and Kaufman system

## Overview
A user interface technique for multivariate volume visualization that maps volumetric attributes to axes in Parallel Coordinates (PCs), where user-specified values act as control points [S1, unofficial]. It addresses the difficulty of interpreting PCs with a large number of attributes by incorporating dimensionality reduction methods, such as Locally Linear Embedding (LLE), to project arbitrary dimensions into a 2D space for global data investigation and manipulation [S1, unofficial]. It builds on [Continuous Indexed Points for Multivariate Volume Visualization](8878-continuous-indexed-points-for-multivariate-volume-visualizat.md) by providing a global exploration mechanism for the local correlations encoded therein.

## How it works
**Inputs and Outputs:**
*   **Input:** Multivariate volume data attributes; user-defined control points for specific attribute values.
*   **Output:** A 2D projection of the high-dimensional attribute space allowing for global data investigation.

**Data Structures:**
*   **Parallel Coordinates Plot:** A set of parallel axes, one for each volumetric attribute.
*   **Control Points:** User-defined values on specific axes.
*   **Dimensionality Reduction Projection:** A 2D coordinate space derived from the high-dimensional data using algorithms like LLE or Multidimensional Scaling (MDS).

**Steps:**
1.  **Map Attributes:** Map each volumetric attribute of the dataset to a distinct axis in the Parallel Coordinates plot [S1, unofficial].
2.  **Set Control Points:** The user specifies values for the attributes by placing control points on the corresponding axes [S1, unofficial].
3.  **Global Investigation (Zhao and Kaufman):** Incorporate global data investigation by applying a dimensionality reduction method, specifically Locally Linear Embedding (LLE), to project the arbitrary dimensions of the data into a 2D space [S1, unofficial]. This allows the user to manipulate widgets in the 2D space to explore global correlations [S1, unofficial].
4.  **Alternative Global Investigation (Guo, Xiao, and Yuan):** Use Multidimensional Scaling (MDS) to generate scatter plots for global data investigation [S1, unofficial].

**Formulas:**
*   **LLE (Locally Linear Embedding):** The sources cite Roweis and Saul (2000) for LLE but do not provide the mathematical formulation. [S1, unofficial]
*   **MDS (Multidimensional Scaling):** The sources cite Kruskal (1964) for MDS but do not provide the mathematical formulation. [S1, unofficial]

**Parameters:**
*   **Dimensionality Reduction Method:** LLE [S1, unofficial] or MDS [S1, unofficial].
*   **Number of Dimensions:** Arbitrary, but PCs are noted as difficult to interpret when a large number of attributes are involved [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Interpretability:** PCs are difficult to interpret when a large number of attributes are involved [S1, unofficial].
*   **Precision:** Not given in the sources.

**Pseudocode:**
```python
# Pseudocode for Parallel Coordinates with Dimensionality Reduction
# Based on [S1, unofficial]

def initialize_parallel_coordinates(attributes):
    """
    Map each volumetric attribute to an axis in the Parallel Coordinates plot.
    """
    axes = []
    for attr in attributes:
        axes.append(Axis(attr))
    return axes

def set_control_points(axes, user_values):
    """
    User specifies values for attributes by placing control points on axes.
    user_values: dict mapping attribute name to value
    """
    for attr_name, value in user_values.items():
        for axis in axes:
            if axis.name == attr_name:
                axis.add_control_point(value)
                break

def apply_dimensionality_reduction(data, method='LLE'):
    """
    Project high-dimensional data into 2D space for global investigation.
    method: 'LLE' for Locally Linear Embedding [S1, unofficial], 'MDS' for Multidimensional Scaling [S1, unofficial]
    """
    if method == 'LLE':
        # LLE algorithm as described by Roweis and Saul (2000) [S1, unofficial]
        # 1. Find k-nearest neighbors for each data point.
        # 2. Compute reconstruction weights that best reconstruct each point from its neighbors.
        # 3. Find low-dimensional embedding that preserves these reconstruction weights.
        projection = lle_algorithm(data)
    elif method == 'MDS':
        # MDS algorithm as described by Kruskal (1964) [S1, unofficial]
        # 1. Compute distance matrix between all data points.
        # 2. Find coordinates in lower-dimensional space that preserve these distances.
        projection = mds_algorithm(data)
    else:
        raise ValueError("Unsupported dimensionality reduction method")
    return projection

def visualize(axes, projection):
    """
    Render the Parallel Coordinates plot and the 2D projection.
    """
    render_parallel_coordinates(axes)
    render_2d_projection(projection)
```

## Subtopics

### Parallel Coordinates for Performance Visualization
A visualization technique used to present many metrics simultaneously, allowing quick comparison between nodes and outlier spotting, chosen over scatter plots or bar charts to minimize occlusion [S2]. Users can interact by rearranging and scaling the axes and brushing the poly-lines for selection [S2]. Each poly-line in the plot represents the metrics for one frame [S2]. The history of frames kept in the plot is 20 to reduce clutter and overdraw [S2]. Collecting metrics and rendering the plot on one node takes approximately 10 ms for the sort-first approach on five display nodes [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** Collecting metrics and rendering the parallel coordinates plot on one node takes approximately 10 ms for the sort-first approach on five display nodes [S2].
*   **Memory:** Not given in the sources.

**Measured Performance:**
*   On five display nodes using a sort-first approach, metric collection and rendering take ~10 ms per node [S2].
*   With sort-last volume rendering, metric collection is negligible (4 bytes per metric per frame per node) relative to image data, but the resulting plot may become unreadable due to the increased number of nodes [S2].

**Scaling:**
*   The approach scales to multiple display nodes, but advanced techniques (density-based approaches, clustering, bundling) are required when the number of nodes providing metrics is large to maintain readability [S2].

**Strengths and Limitations:**
*   **Strengths:** Minimizes occlusion of the application; allows quick comparison of metrics between nodes and outlier spotting; distinct patterns between dimension axes help identify relations between metrics [S2].
*   **Limitations:** Can become unreadable with a large number of nodes providing metrics; requires advanced techniques for large-scale distributed systems [S2].

**When to Use:**
*   Use for exploratory performance analysis and tuning of parallel interactive volume visualization on large displays [S2].
*   Use when minimizing occlusion of the application is critical [S2].

**When Not to Use:**
*   Not suitable for post-mortem analysis if real-time collection overhead is a concern, although post-mortem approaches can offload metrics [S2].
*   Not suitable for large-scale distributed systems without advanced techniques like clustering or bundling [S2].

## Background
The concept was introduced by Pradhan, Bartz, and Mueller (2005) as a user interface of Parallel Coordinates where each volumetric attribute is an axis and the specified value is a control point [S1, unofficial]. Zhao and Kaufman (2010) developed a complementary system that incorporates global data investigation using Locally Linear Embedding (LLE) [S1, unofficial]. Guo, Xiao, and Yuan (2011) utilized scatter plots generated by Multidimensional Scaling (MDS) for a similar purpose [S1, unofficial]. The technique is used in the context of multivariate volume visualization to support the definition of multidimensional transfer functions [S1, unofficial].
