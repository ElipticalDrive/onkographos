# Multivariate Indexed Points Transfer Function

Also called: Volume rendering with indexed points TF

## Overview
This method defines the transfer function lookup mechanism for continuous indexed points, mapping multivariate volume data samples to color and opacity values via precomputed indexed point locations in image space [S1]. It solves the problem of efficiently applying multivariate transfer functions by avoiding costly on-the-fly local fitting transformations during rendering, instead relying on precomputed volumes that map spatial positions directly to indexed point coordinates [S1]. It differs from general multivariate transfer functions by utilizing a subspace-aware ID map to handle overlapping indexed points from different subspaces, distinguishing it from its sibling [Rendering Continuous Indexed Points](14769-rendering-continuous-indexed-points.md) which focuses on the rasterization of the points themselves rather than the transfer function logic.

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric sample value at spatial location $\mathbf{x}$; precomputed indexed point volume; ID map; color and opacity maps; subspace ID ($sID$); transfer function ID ($tID$).
*   **Output:** Final color and opacity for the fragment.

**Data Structures:**
1.  **Indexed Point Volume:** A 3D volume where each voxel stores the 2D indexed point location $\eta$ corresponding to the spatial location $\mathbf{x}$. This volume is precomputed for a fixed axis order of the parallel coordinates [S1].
2.  **ID Map:** A 3D volume storing two identifiers for each indexed point $\eta$:
    *   Subspace ID ($sID$): Distinguishes subspaces in overlapping regions.
    *   Transfer Function ID ($tID$): Identifies and links specific transfer functions.
3.  **Color and Opacity Maps:** 2D lookup tables indexed by $\eta$, $sID$, and $tID$ [S1].

**Steps:**
1.  **Sample:** Sample the multivariate data at spatial location $\mathbf{x}$ [S1].
2.  **Retrieve Indexed Point:** Look up the precomputed indexed point location $\eta$ from the Indexed Point Volume at $\mathbf{x}$. This avoids computing the local fitting information $(\xi, \mathbf{X})$ transformation for every fragment, which is computationally expensive [S1].
3.  **Retrieve IDs:** Look up the Subspace ID ($sID$) and Transfer Function ID ($tID$) from the ID Map at $\mathbf{x}$ [S1].
4.  **Lookup Transfer Function:** Use $\eta$, $sID$, and $tID$ to index into the color and opacity maps [S1].
    *   If $sID = -1$ (default), the widget applies across all subspaces [S1].
    *   If multiple transfer functions are active, they are combined:
        *   Default: OR-operation of brushes [S1].
        *   Linked: If $tID$ is used, transfer functions with the same $tID$ are joined using an AND operation [S1].
5.  **Output:** Return the resulting color and opacity [S1].

**Pseudocode:**
```python
def lookup_multivariate_tf(x, indexed_point_vol, id_map, color_map, opacity_map):
    """
    x: 3D spatial coordinate
    indexed_point_vol: 3D volume mapping x -> 2D indexed point eta
    id_map: 3D volume mapping x -> (sID, tID)
    color_map: 3D lookup table indexed by (eta_x, eta_y, sID, tID)
    opacity_map: 3D lookup table indexed by (eta_x, eta_y, sID, tID)
    """
    # Step 1 & 2: Retrieve precomputed indexed point location
    eta = indexed_point_vol[x]
    
    # Step 3: Retrieve IDs from ID map
    sID, tID = id_map[x]
    
    # Step 4: Lookup color and opacity
    # Note: In practice, color_map and opacity_map might be separate or combined.
    # The lookup uses eta, sID, and tID.
    color = color_map[eta.x, eta.y, sID, tID]
    opacity = opacity_map[eta.x, eta.y, sID, tID]
    
    # Step 5: Combine if necessary (handled by the renderer's accumulation logic
    # based on the OR/AND operation defined by the user's brush selection)
    return color, opacity
```

**Parameters:**
*   $sID$ (Subspace ID): Default value is $-1$, indicating the widget lives in the image plane across all subspaces [S1].
*   $tID$ (Transfer Function ID): Used to link transfer functions for AND operations [S1].

**Edge Cases and Pitfalls:**
*   **Performance:** Computing the transformation from local fitting information $(\xi, \mathbf{X})$ to $\eta$ for every fragment is costly. The method mitigates this by precomputing indexed points for a given axis order [S1].
*   **Overlapping Subspaces:** Indexed points of positive correlations may overlap with neighboring subspaces. The ID map is required to distinguish these using $sID$ [S1].

## Subtopics

### Multivariate Indexed Point Transfer Function Lookup
This is the specific lookup process that realizes the multivariate transfer functions using a lookup table [S1]. It requires color/opacity maps and an ID map to handle overlapping indexed points from different subspaces [S1]. Transfer functions are constructed using the OR-operation of brushes by default, or linked via $tID$ for AND operations [S1]. The ID map stores both $sID$ and $tID$ for each indexed point $\eta$ [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Precomputation:** The time to compute indexed points volumes depends on the subdivision threshold ($t_s$), eigenvector interpolation threshold ($t_e$), and dataset noise. Octrees are effective in reducing computation time for certain datasets [S1].
*   **Rendering:** The lookup is $O(1)$ per fragment, assuming precomputed volumes are available.

**Measured Performance:**
*   Measured on a machine with 3.5 GHz Intel i7 CPU, 32 GB main memory, and NVIDIA Quadro P6000 graphics card [S1].
*   Data processed with a neighborhood size of $7 \times 7 \times 7$ voxels after normalization [S1].
*   Specific timing values are reported in Table 2 of the source, varying with thresholds and noise [S1].

**Strengths and Limitations:**
*   **Strengths:** Enables flexible parallel coordinates manipulations (e.g., changing axis order) without per-fragment fitting costs [S1]. Handles overlapping subspaces effectively [S1].
*   **Limitations:** Precomputation is required for a fixed axis order; changing axis order may require recomputation [S1].

**When to Use:**
*   Use when visualizing multivariate volume data with linear structures and local correlations, especially when interactive manipulation of parallel coordinates is desired [S1].

## Background
This method is part of the "Continuous Indexed Points for Multivariate Volume Visualization" technique, which represents linear structures in parallel coordinates to encode local correlation of multivariate volume data [S1]. It addresses the limitation of traditional gradient-based shading in multivariate volumes by providing a shading model that does not rely on gradients, which are undefined for general multivariate attributes [S1].
