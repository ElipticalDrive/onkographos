# LIC on Stream Surfaces
Also called: Line Integral Convolution on Stream Surfaces

## Overview
LIC on Stream Surfaces is a visualization method that superimposes a texture generated by the Line Integral Convolution (LIC) algorithm onto stream surfaces to resolve the lack of directional information inherent in the base geometry [S1, unofficial]. While stream surfaces effectively show the topology of steady-state flows by stitching adjacent streamlines, they appear as blank, directionless sheets; this method solves that ambiguity by encoding local flow direction into a continuous noise texture mapped to the surface [S1, unofficial]. It distinguishes itself from standard stream surfaces by providing dense, global flow pattern visibility, though it is computationally more expensive than optimized variants like Fast LIC [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A steady-state 3D vector field $\mathbf{V}(x,y,z)$, a seed curve or set of points defining the stream surface, and a scalar noise texture $N$.
*   **Output:** A rendered image of the stream surface where the surface color/intensity is modulated by the LIC convolution result, revealing flow direction.

**Data Structures:**
*   **Stream Surface:** A polygonal mesh (typically triangles) constructed by integrating streamlines from a seed curve. The surface geometry is defined by vertices $\mathbf{P}_i$ and connectivity.
*   **LIC Texture:** A 2D or 3D scalar field representing the convolution result. For surface mapping, this is often computed per-pixel or per-vertex during rendering.

**Steps:**
1.  **Construct Stream Surface:** Generate the stream surface geometry by integrating streamlines from a seed curve in the vector field $\mathbf{V}$ [S1, unofficial]. This builds on [Stream Surfaces](7696-stream-surfaces.md).
2.  **Rasterize Surface:** Project the 3D stream surface onto the 2D image plane. Identify the set of pixels covered by the surface.
3.  **Compute LIC for Surface Pixels:** For each pixel $(u,v)$ on the surface:
    a.  Determine the 3D position $\mathbf{P}$ on the surface corresponding to $(u,v)$.
    b.  Trace the streamline passing through $\mathbf{P}$ in the vector field $\mathbf{V}$ to define the integration path $L$.
    c.  Sample the noise field $N$ along $L$.
    d.  Compute the convolution integral:
        $$ I(u,v) = \int_{L} N(\mathbf{P}(t)) \, dt $$
        where $N$ is typically a high-frequency white noise texture [S1, unofficial].
    e.  Normalize or scale $I(u,v)$ to the desired intensity range.
4.  **Render:** Color the surface pixels using the computed LIC values $I(u,v)$, often combined with lighting models or transparency to handle occlusion [S1, unofficial].

**Parameters:**
*   **Noise Texture Frequency:** Controls the granularity of the flow pattern. Not given in the sources.
*   **Integration Step Size:** Affects accuracy of streamline tracing. Not given in the sources.
*   **Surface Opacity:** Used to handle occlusion between multiple surfaces. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Occlusion:** Single surfaces can have substantial occlusion, requiring careful examination from many viewpoints. Semi-transparent rendering restricts the use of standard hardware to slow ray-tracing programs for correct sorting [S1, unofficial].
*   **Boundary Conditions:** The flow must enter or exit the volume boundaries for the stream surface technique to work. Artificial boundaries may need to be placed to rectify this [S1, unofficial].
*   **Direction Ambiguity:** Without LIC, the surface has no inherent direction. LIC resolves this by correlating noise with flow direction [S1, unofficial].

**Pseudocode:**
```python
def render_lic_on_stream_surface(surface_mesh, vector_field, noise_texture):
    """
    Renders a stream surface with LIC texture.
    
    Args:
        surface_mesh: List of triangles defining the stream surface.
        vector_field: Function V(x, y, z) returning velocity vector.
        noise_texture: Function N(x, y, z) returning noise value.
        
    Returns:
        Image buffer with LIC values.
    """
    image = create_empty_image()
    
    for triangle in surface_mesh:
        # Rasterize triangle to get covered pixels
        pixels = rasterize_triangle(triangle)
        
        for pixel in pixels:
            # Get 3D point on surface for this pixel
            p_3d = get_surface_point(triangle, pixel.u, pixel.v)
            
            # Trace streamline through p_3d
            streamline_path = trace_streamline(p_3d, vector_field)
            
            # Compute LIC integral along streamline
            lic_value = 0.0
            for point_on_streamline in streamline_path:
                # Sample noise at current point on streamline
                noise_val = noise_texture(point_on_streamline.x, 
                                          point_on_streamline.y, 
                                          point_on_streamline.z)
                lic_value += noise_val * step_size
            
            # Store LIC value in image
            image.set_color(pixel.u, pixel.v, lic_value)
            
    return image

def trace_streamline(start_point, vector_field):
    """
    Integrates the vector field to generate a streamline path.
    """
    path = [start_point]
    current_point = start_point
    step_size = 0.1 # Example step size
    
    while not out_of_bounds(current_point):
        velocity = vector_field(current_point.x, current_point.y, current_point.z)
        current_point = current_point + velocity * step_size
        path.append(current_point)
        
    return path
```

## Subtopics

### Optimized LIC
An extension to LIC that speeds up computation by avoiding redundant integrations and reusing LIC values for adjacent pixels on the same streamline [S1, unofficial]. It is based on two key observations: first, a streamline passes through many pixels, so only one rasterized streamline is sufficient for convolution results for those pixels, avoiding redundant numerical integrations; second, adjacent pixels along the same streamline use very similar sets of pixel values for convolution, allowing the LIC value computed for one pixel to be reused by its neighbors with small modifications [S1, unofficial]. This method gains significant savings in computing the LIC by reducing the number of streamlines computed and accelerating the convolution [S1, unofficial].

### Dye-Advection LIC
A 3D extension of LIC that introduces dye advection into the computation, using the 'smearing' nature of LIC to simulate dye advection [S1, unofficial]. It allows the visualization to include both regular LIC textures and 3D particle traces. To improve interactivity, it proposes an efficient algorithm to locate "dyed" regions so that a fast update of the LIC result is possible, allowing the user to dynamically inject dye at different locations [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Computationally expensive due to the need to trace streamlines and perform convolution integrals for each pixel on the surface [S1, unofficial]. Optimized variants reduce this by reusing computations [S1, unofficial].
*   **Memory Complexity:** Requires storage for the stream surface geometry, the noise texture, and the LIC result buffer [S1, unofficial].
*   **Strengths:** Provides dense, continuous visualization of flow direction and structure on complex surfaces; reveals global flow patterns [S1, unofficial].
*   **Limitations:** Computationally intensive; single surfaces can suffer from occlusion; requires careful handling of boundaries [S1, unofficial].
*   **When to Use:** When directional information on stream surfaces is critical and computational resources allow for intensive rendering [S1, unofficial].
*   **When Not to Use:** When real-time performance is required and optimized variants are not available, or when the flow field is too complex to trace accurately [S1, unofficial].

## Background
The method was proposed by Interrante and others, who suggested using the Line Integral Convolution (LIC) algorithm to solve the problem of lack of direction on stream surfaces [S1, unofficial]. This builds on the work of Van Wijk, who constructed stream surfaces using iso-contour surfaces of a function derived from the vector field [S1, unofficial]. The approach addresses the limitations of single stream surfaces, which can have substantial occlusion and require careful examination from multiple viewpoints [S1, unofficial].
