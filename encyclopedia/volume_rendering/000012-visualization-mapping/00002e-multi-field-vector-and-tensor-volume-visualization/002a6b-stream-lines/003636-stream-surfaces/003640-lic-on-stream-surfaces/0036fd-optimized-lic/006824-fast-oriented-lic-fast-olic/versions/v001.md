# Fast-Oriented LIC (Fast-OLIC)

Also called: Asymmetric Fast-LIC, Exponential Fast-LIC

## Overview
Fast-Oriented LIC (Fast-OLIC) is a volume rendering technique that generates line integral convolution textures with directional orientation by combining the computational efficiency of fast-LIC with an asymmetric exponential filter. It solves the problem of conveying flow direction (forward and backward) in 3D vector fields, which standard fast-LIC cannot do because it relies on a symmetric box filter. Unlike its sibling [Optimized LIC](7862-optimized-lic.md), which optimizes for speed by reusing adjacent pixel calculations, Fast-OLIC specifically modifies the filtering kernel to encode orientation while maintaining incremental update efficiency.

## How it works
Fast-OLIC modifies the texture generation pass of fast-LIC. Instead of averaging a fixed number of samples (box filter), it applies a weighted sum where the weight decreases exponentially for samples further along the streamline. This asymmetry allows the resulting texture intensity to vary based on the direction of flow relative to the viewer or a reference frame, effectively conveying orientation.

### Inputs and Outputs
*   **Input:** A 3D texture containing the scalar field values to be convolved (e.g., density or velocity magnitude) and a 3D texture defining the streamline paths (or a vector field from which streamlines are traced).
*   **Output:** A 3D texture containing the integrated intensity values for the LIC visualization.

### Data Structures
The method operates on a sliding window of sample values along a streamline.
*   **Window Array $v$:** An array of fixed size `flength + 1` storing the input texture values $v_i$ at the $i$-th sample point along the streamline.
*   **Current Intensity $I'$:** A scalar value representing the current integrated intensity at the current voxel.

### Parameters
*   **$c$:** A constant controlling the rate of decrease in contribution for samples farther along the streamline. Must satisfy $c < 1$ [S1, unofficial].
*   **$flength$:** The length of the filter kernel, defined as the number of weighted samples in the forward direction along the streamline from each point that combine to determine the value at the corresponding point in the output texture [S1, unofficial].

### Formulas
The core of Fast-OLIC is the exponential filter kernel and its incremental update rules.

**Initial Filter Kernel:**
The integrated intensity $I_0'$ at the current position is calculated as:
$$ I_0' = \frac{1}{c^{flength+1}} \sum_{i=0}^{flength} v_i c^i $$
where:
*   $v_i$ is the input texture value at the $i$-th sample point.
*   $c$ is the exponential decay constant ($c < 1$).
*   $flength$ is the kernel length.

**Incremental Update (Forward):**
When moving to the next voxel along the streamline (forward direction), the new intensity $I_1'$ is computed from the previous intensity $I_0'$ without re-summing the entire window:
$$ I_1' = \frac{I_0' - v_0}{c} + v_{flength+1} c^{flength} $$
where:
*   $v_0$ is the value leaving the window (the oldest sample).
*   $v_{flength+1}$ is the new value entering the window (the newest sample).

**Incremental Update (Backward):**
When moving to the previous voxel (backward direction), the new intensity $I_{-1}'$ is computed as:
$$ I_{-1}' = (I_0' - v_{flength} c^{flength}) c + v_{-1} $$
where:
*   $v_{flength}$ is the value leaving the window.
*   $v_{-1}$ is the new value entering the window.

### Pseudocode
The following Python-like pseudocode demonstrates the forward incremental update logic. It assumes a function `trace_streamline` yields sample values $v$ sequentially.

```python
def fast_olic_forward(v_stream, flength, c):
    """
    Computes Fast-OLIC texture values using incremental updates.
    
    Args:
        v_stream: Iterator yielding input texture values v_i along the streamline.
        flength: Integer, length of the filter kernel.
        c: Float, exponential decay constant (0 < c < 1).
        
    Returns:
        List of integrated intensity values I'.
    """
    # Initialize the window with the first flength + 1 samples
    window = []
    for i in range(flength + 1):
        window.append(next(v_stream))
        
    # Calculate initial intensity I_0'
    # Formula: I_0' = (1 / c^(flength+1)) * sum(v_i * c^i) for i=0 to flength
    sum_val = 0.0
    for i in range(flength + 1):
        sum_val += window[i] * (c ** i)
        
    current_intensity = sum_val / (c ** (flength + 1))
    results = [current_intensity]
    
    # Incremental updates for subsequent samples
    while True:
        try:
            new_val = next(v_stream)
        except StopIteration:
            break
            
        # The value leaving the window is the oldest one (index 0)
        v_out = window[0]
        
        # Shift window: remove oldest, append new
        window.pop(0)
        window.append(new_val)
        
        # Incremental update formula:
        # I_1' = (I_0' - v_0) / c + v_{flength+1} * c^{flength}
        # Note: v_{flength+1} in the formula corresponds to the new_val just entered.
        # In the shifted window, new_val is at index flength.
        
        current_intensity = (current_intensity - v_out) / c + new_val * (c ** flength)
        results.append(current_intensity)
        
    return results
```

### Edge Cases and Pitfalls
*   **Precision:** Division by $c$ in the forward update can amplify numerical errors if $c$ is very small. [G] Ensure $c$ is not too close to 0 to maintain stability.
*   **Boundary Conditions:** The initial calculation requires `flength + 1` samples. At the start or end of a streamline segment, padding or clamping may be required if the source does not provide sufficient samples. [G]
*   **Degenerate Input:** If the streamline length is less than `flength + 1`, the filter cannot be applied as defined. [Not given in the sources.]

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels along the streamline, due to the incremental update which is $O(1)$ per step. This matches the efficiency of standard fast-LIC.
*   **Memory Complexity:** $O(1)$ auxiliary memory per streamline (storing only the window of size `flength + 1` and current intensity), plus storage for the output texture.
*   **Strengths:** Conveys flow direction (orientation) similar to OLIC while retaining the high performance of fast-LIC. It avoids the "halo" artifacts mentioned in some OLIC implementations by using a decaying weight.
*   **Limitations:** The orientation is implicit in the intensity gradient; it may be less intuitive than explicit arrow-based methods. The choice of $c$ affects the visual balance between forward and backward contributions.
*   **When to use:** When visualizing 3D flow fields where directionality is critical and performance is a constraint, and when a volumetric representation is preferred over line-based methods.

## Background
Fast-Oriented LIC was introduced in 1998 by Interran et al. in the paper "Visualizing 3D Flow" published in *IEEE Computer Graphics and Applications*. The method was developed to address the limitation of the fast-LIC algorithm, which used a symmetric box filter and thus could not distinguish flow direction. By adapting the filter to an asymmetric exponential function, the authors achieved the orientation capabilities of OLIC (Oriented LIC) by Wegenkittl et al. while preserving the incremental calculation efficiency of fast-LIC.
