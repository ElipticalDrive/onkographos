# Optimized LIC

Also called: Fast LIC, LIC with Streamline Reuse, Stalling and Hege LIC

## Overview
Optimized LIC (also known as Fast LIC) is a method to accelerate the Line Integral Convolution algorithm by eliminating redundant numerical integrations and reusing convolution results for adjacent pixels along the same streamline [S1, unofficial][S2]. It differs from standard [Line Integral Convolution (LIC)](7940-line-integral-convolution-lic.md) by computing long field line segments once and incrementally updating the convolution integral for all pixels covered by that segment, rather than recomputing the integral independently for each pixel [S2]. This approach significantly reduces computational cost [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D vector field $\mathbf{v}(x,y)$, a random noise texture $T$, and parameters for integration step size $h_t$, convolution half-length $n$, maximum traversal steps $M$, and minimum hit count $minNumHits$ [S2].
*   **Output:** An image where each pixel $p$ contains the accumulated and normalized LIC intensity [S2].

**Data Structures:**
*   **Hit Counter Array:** An integer array `numHits` matching the output image dimensions, initialized to zero, to track how many field lines pass through each pixel for normalization [S2].
*   **Accumulator Array:** A floating-point array `accumulatedIntensity` matching the output image dimensions, initialized to zero, to store the sum of convolution values for each pixel [S2].

**Parameters:**
*   $h_t$: Distance between sample points along the field line. Typically $h_t = 0.5 \times \text{width of a texture cell}$ [S2].
*   $n$: Half-length of the convolution kernel in terms of sample steps.
*   $k$: Normalization constant for the kernel, set to $k = 1/(2n + 1)$ [S2].
*   $M$: Maximum number of steps to traverse along a field line from the starting point. The field line length is typically larger than the convolution length [S2].
*   $minNumHits$: Threshold to determine if a new field line needs to be computed for a pixel [S2].

**Formulas:**
*   Initial convolution at starting point $x_0 = \sigma(s_0)$:
    $$ I(x_0) = k \sum_{i=-n}^{n} T(x_i), \quad \text{where } x_i = \sigma(s_0 + i h_t) $$
*   Forward incremental update for $m = 0, 1, \dots, M$:
    $$ I(x_{m+1}) = I(x_m) + k [T(x_{m+1+n}) - T(x_{m-n})] $$
*   Backward incremental update for $m = 0, -1, \dots, -M$:
    $$ I(x_{m-1}) = I(x_m) + k [T(x_{m-1-n}) - T(x_{m+n})] $$

**Algorithm Steps:**
1.  Initialize `numHits` and `accumulatedIntensity` to zero for all pixels [S2].
2.  Iterate through each pixel $p$ in the output image [S2].
3.  If `numHits(p)` < $minNumHits$:
    *   Initiate field line computation with $x_0$ at the center of pixel $p$ [S2].
    *   Compute the initial convolution $I(x_0)$ using the initial formula [S2].
    *   Add $I(x_0)$ to `accumulatedIntensity(p)` and increment `numHits(p)` [S2].
    *   Set $m = 1$ [S2].
    *   While $m \le M$:
        *   Update convolution $I(x_m)$ and $I(x_{-m})$ using the forward and backward formulas [S2].
        *   Add $I(x_m)$ to `accumulatedIntensity` of the pixel containing $x_m$ [S2].
        *   Add $I(x_{-m})$ to `accumulatedIntensity` of the pixel containing $x_{-m}$ [S2].
        *   Increment `numHits` for the pixels containing $x_m$ and $x_{-m}$ [S2].
        *   Set $m = m + 1$ [S2].
4.  After processing all pixels, normalize the intensity of each pixel by dividing `accumulatedIntensity(p)` by `numHits(p)` [S2].

**Pseudocode:**
```python
def optimized_lic(vector_field, texture, width, height, h_t, n, M, min_num_hits):
    k = 1.0 / (2 * n + 1)
    num_hits = [[0] * width for _ in range(height)]
    acc_intensity = [[0.0] * width for _ in range(height)]

    def rk4_step(x, y, dt):
        k1 = vector_field(x, y)
        k2 = vector_field(x + 0.5 * dt * k1[0], y + 0.5 * dt * k1[1])
        k3 = vector_field(x + 0.5 * dt * k2[0], y + 0.5 * dt * k2[1])
        k4 = vector_field(x + dt * k3[0], y + dt * k3[1])
        return x + (dt / 6.0) * (k1[0] + 2*k2[0] + 2*k3[0] + k4[0]), \
               y + (dt / 6.0) * (k1[1] + 2*k2[1] + 2*k3[1] + k4[1])

    def get_pixel_coords(x, y):
        return int(round(x)), int(round(y))

    for py in range(height):
        for px in range(width):
            if num_hits[py][px] < min_num_hits:
                cx, cy = px + 0.5, py + 0.5
                total_points = 2 * M + 2 * n + 1
                center_idx = M + n
                points = [(cx, cy)]
                for _ in range(total_points - 1):
                    cx, cy = rk4_step(cx, cy, h_t)
                    points.append((cx, cy))

                current_I = 0.0
                for i in range(-n, n + 1):
                    current_I += texture(*points[center_idx + i])
                current_I *= k

                acc_intensity[py][px] += current_I
                num_hits[py][px] += 1

                for m in range(M):
                    idx_m = center_idx + m
                    idx_m1 = idx_m + 1
                    current_I += k * (texture(*points[idx_m1 + n]) - texture(*points[idx_m - n]))
                    px_m1, py_m1 = get_pixel_coords(*points[idx_m1])
                    if 0 <= px_m1 < width and 0 <= py_m1 < height:
                        acc_intensity[py_m1][px_m1] += current_I
                        num_hits[py_m1][px_m1] += 1

                current_I_back = current_I
                for j in range(1, M + 1):
                    idx_prev = center_idx - (j - 1)
                    idx_curr = idx_prev - 1
                    current_I_back += k * (texture(*points[idx_curr - n]) - texture(*points[idx_prev + n]))
                    px_curr, py_curr = get_pixel_coords(*points[idx_curr])
                    if 0 <= px_curr < width and 0 <= py_curr < height:
                        acc_intensity[py_curr][px_curr] += current_I_back
                        num_hits[py_curr][px_curr] += 1

    output = [[0.0] * width for _ in range(height)]
    for py in range(height):
        for px in range(width):
            if num_hits[py][px] > 0:
                output[py][px] = acc_intensity[py][px] / num_hits[py][px]
    return output
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** If the step size $h_t$ is too large, pixels along the field line may be missed, causing aliasing artifacts [S2].
*   **Accuracy:** Accuracy is critical near vortex centers; incorrect field lines disturb the LIC pattern [S2]. The method uses fourth-order Runge-Kutta to ensure this accuracy, unlike the variable step Euler's method used in CL-LIC [S2].
*   **Boundary Conditions:** Field lines may exit the domain. The algorithm must handle indices out of bounds when accessing the texture or updating pixel accumulators [G].

## Operating characteristics
*   **Time Complexity:** Significantly faster than standard LIC. By reusing field lines and updating integrals incrementally, it avoids redundant numerical integrations for pixels on the same streamline [S1, unofficial]. The cost is proportional to the number of unique field lines generated (determined by $minNumHits$) rather than the total number of pixels [S2].
*   **Memory Complexity:** Requires storage for `numHits` and `accumulatedIntensity` arrays proportional to the image dimensions [S2].
*   **Strengths:** Great saving in computing time compared to standard LIC; maintains visual quality by using accurate integration [S1, unofficial][S2].
*   **Limitations:** Requires careful tuning of $h_t$ to avoid aliasing; accuracy depends heavily on the integration method (RK4) [S2].

## Background
Optimized LIC was proposed by Stalling and Hege in 1995 [S2]. It was introduced as an improvement over the original Line Integral Convolution algorithm by Cabral and Leedom (CL-LIC) [S2]. The method addresses the computational expense of LIC by exploiting the redundancy in field line coverage and convolution integrals [S1, unofficial].
