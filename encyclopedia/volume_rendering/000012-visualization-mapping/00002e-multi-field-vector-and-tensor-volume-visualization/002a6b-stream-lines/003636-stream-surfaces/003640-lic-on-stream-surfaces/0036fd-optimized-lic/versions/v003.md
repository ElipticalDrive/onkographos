# Optimized LIC

Also called: Fast LIC, LIC with Streamline Reuse, Stalling and Hege LIC

## Overview
Optimized LIC (also known as Fast LIC) accelerates the Line Integral Convolution algorithm by eliminating redundant numerical integrations and reusing convolution results for adjacent pixels along the same streamline [S1, unofficial][S2]. It differs from standard [Line Integral Convolution (LIC)](7940-line-integral-convolution-lic.md) by computing long field line segments once and incrementally updating the convolution integral for all pixels covered by that segment, rather than recomputing the integral independently for each pixel [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D vector field, a random noise texture $T$, and parameters for integration step size $h_t$, convolution half-length $n$, and minimum hit count $minNumHits$ [S2].
*   **Output:** An image where each pixel $p$ contains the accumulated and normalized LIC intensity [S2].

**Data Structures:**
*   **Hit Counter Array:** An integer array `numHits` of the same dimensions as the output image, initialized to zero. It tracks how many field lines have passed through each pixel to enable normalization [S2].
*   **Accumulator Array:** A floating-point array `accumulatedIntensity` of the same dimensions as the output image, initialized to zero. It stores the sum of convolution values for each pixel [S2].

**Parameters:**
*   $h_t$: Distance between sample points along the field line. Typically $h_t = 0.5 \times \text{width of a texture cell}$ [S2].
*   $n$: Half-length of the convolution kernel in terms of sample steps [S2].
*   $k$: Normalization constant for the kernel, set to $k = 1/(2n + 1)$ [S2].
*   $M$: Maximum number of steps to traverse along a field line from the starting point. The field line length is typically larger than the convolution length [S2].
*   $minNumHits$: Threshold to determine if a new field line needs to be computed for a pixel [S2].

**Algorithm Steps:**

1.  **Initialization:** Initialize `numHits` and `accumulatedIntensity` to zero for all pixels [S2].
2.  **Field Line Generation and Convolution:** Iterate through each pixel $p$ in the output image [S2].
    *   If `numHits(p)` < $minNumHits$:
        *   Set the starting point $x_0$ to the center of pixel $p$ [S2].
        *   Compute the field line segment $\sigma(s)$ starting at $x_0$ using a fourth-order Runge-Kutta method [S2].
        *   Sample the texture $T$ at evenly spaced locations $x_i = \sigma(s_0 + i \cdot h_t)$ for $i = -n, \dots, n$ [S2].
        *   Compute the initial convolution integral $I(x_0)$:
            $$ I(x_0) = k \sum_{i=-n}^{n} T(x_i) $$
        *   Add $I(x_0)$ to `accumulatedIntensity(p)` [S2].
        *   Increment `numHits(p)` [S2].
        *   Set $m = 1$ [S2].
        *   **Incremental Update Loop:** While $m \le M$:
            *   Update the convolution integral for the forward point $x_m$:
                $$ I(x_{m+1}) = I(x_m) + k [T(x_{m+1+n}) - T(x_{m-n})] $$
            *   Update the convolution integral for the backward point $x_{-m}$:
                $$ I(x_{m-1}) = I(x_m) + k [T(x_{m-1-n}) - T(x_{m+n})] $$
            *   Determine the pixels containing $x_{m+1}$ and $x_{m-1}$ [S2].
            *   Add $I(x_{m+1})$ to `accumulatedIntensity` of the pixel containing $x_{m+1}$ [S2].
            *   Add $I(x_{m-1})$ to `accumulatedIntensity` of the pixel containing $x_{m-1}$ [S2].
            *   Increment `numHits` for the pixels containing $x_{m+1}$ and $x_{m-1}$ [S2].
            *   Increment $m$ [S2].
3.  **Normalization:** Iterate through each pixel $p$ [S2].
    *   Normalize intensity according to `numHits(p)` [S2].

**Pseudocode:**

```python
def optimized_lic(vector_field, texture, width, height, h_t, n, M, min_num_hits):
    k = 1.0 / (2 * n + 1)
    num_hits = [[0] * width for _ in range(height)]
    accumulated = [[0.0] * width for _ in range(height)]

    def sample_field_line(x0, y0, steps, step_size):
        pts = [(x0, y0)]
        x, y = x0, y0
        for _ in range(steps):
            k1 = vector_field(x, y)
            k2 = vector_field(x + 0.5 * step_size * k1[0], y + 0.5 * step_size * k1[1])
            k3 = vector_field(x + 0.5 * step_size * k2[0], y + 0.5 * step_size * k2[1])
            k4 = vector_field(x + step_size * k3[0], y + step_size * k3[1])
            x += (step_size / 6.0) * (k1[0] + 2*k2[0] + 2*k3[0] + k4[0])
            y += (step_size / 6.0) * (k1[1] + 2*k2[1] + 2*k3[1] + k4[1])
            pts.append((x, y))
        return pts

    for py in range(height):
        for px in range(width):
            if num_hits[py][px] < min_num_hits:
                total_pts = 2 * (M + n) + 1
                line = sample_field_line(px + 0.5, py + 0.5, total_pts - 1, h_t)
                center = M + n

                I_curr = 0.0
                for i in range(-n, n + 1):
                    I_curr += texture(line[center + i][0], line[center + i][1])
                I_curr *= k

                accumulated[py][px] += I_curr
                num_hits[py][px] += 1

                idx = center
                for m in range(M):
                    I_curr += k * (texture(line[idx + 1 + n][0], line[idx + 1 + n][1]) -
                                   texture(line[idx - n][0], line[idx - n][1]))
                    px_next, py_next = line[idx + 1]
                    if 0 <= px_next < width and 0 <= py_next < height:
                        accumulated[py_next][px_next] += I_curr
                        num_hits[py_next][px_next] += 1
                    idx += 1

                idx = center
                I_curr_back = 0.0
                for i in range(-n, n + 1):
                    I_curr_back += texture(line[center + i][0], line[center + i][1])
                I_curr_back *= k

                for j in range(1, M + 1):
                    I_curr_back += k * (texture(line[idx - 1 - n][0], line[idx - 1 - n][1]) -
                                        texture(line[idx + n][0], line[idx + n][1]))
                    px_prev, py_prev = line[idx - 1]
                    if 0 <= px_prev < width and 0 <= py_prev < height:
                        accumulated[py_prev][px_prev] += I_curr_back
                        num_hits[py_prev][px_prev] += 1
                    idx -= 1

    output = [[0.0] * width for _ in range(height)]
    for py in range(height):
        for px in range(width):
            if num_hits[py][px] > 0:
                output[py][px] = accumulated[py][px] / num_hits[py][px]
    return output
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** If the step size $h_t$ is too large, pixels along the field line may be missed, causing aliasing artifacts [S2].
*   **Accuracy:** Accuracy is critical near vortex centers; incorrect field lines disturb the LIC pattern [S2]. The method uses fourth-order Runge-Kutta to ensure this accuracy, unlike the variable step Euler's method used in CL-LIC [S2].
*   **Boundary Conditions:** Field lines may exit the domain. The algorithm must handle indices out of bounds when accessing the texture or updating pixel accumulators [G].

## Operating characteristics
*   **Time Complexity:** Significantly faster than standard LIC. By reusing field lines and updating integrals incrementally, it avoids redundant numerical integrations for pixels on the same streamline [S1, unofficial][S2]. The cost is proportional to the number of unique field lines generated (determined by $minNumHits$) rather than the total number of pixels [S2].
*   **Strengths:** Great saving in computing time compared to standard LIC; maintains accuracy by using fourth-order Runge-Kutta integration [S1, unofficial][S2].
*   **Limitations:** Requires careful tuning of $h_t$ to avoid aliasing; accuracy depends heavily on the integration method [S2].

## Background
Optimized LIC was proposed by Stalling and Hege in 1995 [S2]. It was introduced as an improvement over the original Line Integral Convolution algorithm by Cabral and Leedom (CL-LIC) [S2]. The method addresses the computational expense of LIC by exploiting the redundancy in field line coverage and convolution integrals [S1, unofficial].
