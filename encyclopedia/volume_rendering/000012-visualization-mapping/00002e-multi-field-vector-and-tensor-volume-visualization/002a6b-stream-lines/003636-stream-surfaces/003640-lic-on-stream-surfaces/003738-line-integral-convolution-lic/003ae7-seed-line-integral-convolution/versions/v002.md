# Seed Line Integral Convolution

Also called: Seed LIC

## Overview
Seed Line Integral Convolution (Seed LIC) is a volume rendering technique for visualizing 3D vector fields that computes Line Integral Convolution textures only along field lines originating from a sparse set of seed points, rather than covering every voxel in the output volume [S1]. It solves the problem of excessive computational cost in standard Fast LIC when applied to sparse or ROI-masked input textures by avoiding unnecessary calculations in regions where field lines do not coincide with cells containing seed points [S1]. Unlike Fast LIC, which assigns values to neighboring voxels causing smearing, Seed LIC produces sparser textures with significantly reduced computational cost for sparse inputs, though it is more susceptible to aliasing [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D vector field $\mathbf{V}$, a scalar quantity defining a Region of Interest (ROI) (e.g., vorticity magnitude), and a density factor controlling seed point distribution [S1].
*   **Output:** A 3D scalar texture representing the LIC result, with voxel intensities normalized to the range $[0, 255]$ [S1].

**Data Structures:**
*   **Input Texture ($T$):** A 3D grid of the same resolution as the vector field (or a specified multiple) [S1]. Voxels are initialized to 0, and selected seed voxels are set to 255 [S1].
*   **Output Texture:** A 3D grid of the same resolution as the input texture, initialized to 0 [S1].
*   **Seed Points:** A list of 3D coordinates $(x, y, z)$ representing the centers of voxels set to 255 in the input texture [S1].

**Parameters:**
*   **Filter Kernel Length ($2L$):** The length of the convolution kernel, set to 21 times the grid cell size in reported experiments [S1].
*   **Field Line Length:** The integration length for tracing field lines, set to 51 times the grid cell size in reported experiments [S1].
*   **Minimum Seed Distance:** Points within three voxels of an existing seed are discarded to prevent line merging [S1].
*   **Integration Method:** Fifth-order adaptive Runge-Kutta with a fixed sample interval [S1].

**Algorithm Steps:**
1.  **Generate Input Texture:** Define the ROI based on the scalar quantity [S1]. Determine the number of seed points using the density factor [S1]. Distribute points randomly within the ROI [S1]. Discard any point that falls within three voxels of a previously accepted seed point [S1]. Set the voxels corresponding to the accepted seed points to 255; set all other voxels to 0 [S1].
2.  **Initialize Output:** Set all voxels in the output texture to 0 [S1].
3.  **Trace Field Lines and Compute Convolution:** For each seed point $x_0$, trace a field line $\alpha(s)$ starting at $x_0$ using the fifth-order adaptive Runge-Kutta method with a fixed sample interval [S1]. The curve $\alpha(s)$ is parameterized by arc-length $s$ [S1]. Compute the convolution integral for the voxel at $x_0$:
    $$ I(x_0) = \int_{s_0-L}^{s_0+L} k(s-s_0) T(\alpha(s)) ds $$
    where $k$ is the filter kernel of length $2L$, $T$ is the input texture, and $s_0$ is the arc-length parameter corresponding to $x_0$ [S1]. Assign the result $I(x_0)$ to the corresponding voxel in the output texture [S1].
4.  **Normalize:** Normalize the intensity of the voxels in the output texture so that values vary from 0 to 255 [S1].

**Pseudocode:**
```python
def seed_lic(vector_field, scalar_roi, density_factor, cell_size, grid_dims):
    # 1. Generate Input Texture
    input_texture = zeros(grid_dims)
    seed_points = []
    min_dist = 3 * cell_size

    # Generate candidate points based on density factor within ROI
    num_candidates = int(density_factor * grid_dims[0] * grid_dims[1] * grid_dims[2])
    candidates = []
    for _ in range(num_candidates):
        x, y, z = random.uniform(0, grid_dims[0]), random.uniform(0, grid_dims[1]), random.uniform(0, grid_dims[2])
        if scalar_roi[int(x)][int(y)][int(z)] > 0: # Threshold not specified in sources [G]
            candidates.append((x, y, z))

    # Filter by minimum distance (3 voxels)
    for pt in candidates:
        too_close = False
        for sp in seed_points:
            if (pt[0]-sp[0])**2 + (pt[1]-sp[1])**2 + (pt[2]-sp[2])**2 < min_dist**2:
                too_close = True
                break
        if not too_close:
            seed_points.append(pt)
            ix, iy, iz = int(pt[0]), int(pt[1]), int(pt[2])
            input_texture[ix][iy][iz] = 255.0

    # 2. Initialize Output Texture
    output_texture = zeros(grid_dims)

    # 3. Trace Field Lines and Compute Convolution
    kernel_length = 21 * cell_size
    field_line_length = 51 * cell_size
    sample_interval = cell_size # Fixed sample interval [S1]
    num_samples = int(field_line_length / sample_interval)

    for seed in seed_points:
        # Trace field line using 5th order adaptive Runge-Kutta with fixed sample interval [S1]
        field_line = trace_field_line_rk45(vector_field, seed, field_line_length, sample_interval)

        # Compute convolution integral: I(x0) = integral_{s0-L}^{s0+L} k(s-s0) * T(alpha(s)) ds
        intensity = 0.0
        for i, pt in enumerate(field_line):
            t_val = interpolate_trilinear(input_texture, pt) # Trilinear interpolation [G]
            # Kernel weight k(s-s0). Exact kernel function not specified in sources [G]
            weight = 1.0 / len(field_line) # Uniform weighting approximation [G]
            intensity += weight * t_val

        ix, iy, iz = int(seed[0]), int(seed[1]), int(seed[2])
        output_texture[ix][iy][iz] = intensity

    # 4. Normalize
    max_val = max(max(max(row) for row in plane) for plane in output_texture)
    if max_val > 0:
        for i in range(grid_dims[0]):
            for j in range(grid_dims[1]):
                for k in range(grid_dims[2]):
                    output_texture[i][j][k] = (output_texture[i][j][k] / max_val) * 255.0

    return output_texture

def zeros(dims):
    return [[[0.0 for _ in range(dims[2])] for _ in range(dims[1])] for _ in range(dims[0])]

def trace_field_line_rk45(vector_field, start_pt, total_length, step_size):
    pts = [start_pt]
    current = list(start_pt)
    steps = int(total_length / step_size)
    for _ in range(steps):
        # Standard 5th-order adaptive Runge-Kutta step [G]
        k1 = vector_field_at(current)
        k2 = vector_field_at([current[c] + 0.5*step_size*k1[c] for c in range(3)])
        k3 = vector_field_at([current[c] + 0.5*step_size*k2[c] for c in range(3)])
        k4 = vector_field_at([current[c] + step_size*k3[c] for c in range(3)])
        next_pt = [current[c] + step_size * (k1[c] + 2*k2[c] + 2*k3[c] + k4[c]) / 6 for c in range(3)]
        pts.append(next_pt)
        current = next_pt
    return pts

def vector_field_at(pt):
    return interpolate_trilinear(vector_field, pt)

def interpolate_trilinear(texture, pt):
    ix, iy, iz = pt
    x0, y0, z0 = int(ix), int(iy), int(iz)
    x1, y1, z1 = min(x0+1, len(texture)-1), min(y0+1, len(texture[0])-1), min(z0+1, len(texture[0][0])-1)
    fx, fy, fz = ix-x0, iy-y0, iz-z0
    v000 = texture[x0][y0][z0]
    v100 = texture[x1][y0][z0]
    v010 = texture[x0][y1][z0]
    v110 = texture[x1][y1][z0]
    v001 = texture[x0][y0][z1]
    v101 = texture[x1][y0][z1]
    v011 = texture[x0][y1][z1]
    v111 = texture[x1][y1][z1]
    return (1-fx)*(1-fy)*(1-fz)*v000 + fx*(1-fy)*(1-fz)*v100 + (1-fx)*fy*(1-fz)*v010 + fx*fy*(1-fz)*v110 + \
           (1-fx)*(1-fy)*fz*v001 + fx*(1-fy)*fz*v101 + (1-fx)*fy*fz*v011 + fx*fy*fz*v111
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** Seed LIC is more affected by aliasing than Fast LIC due to the fewer number of calculated voxels, resulting in a less smooth appearance [S1].
*   **Line Merging:** If seed points are too close, convolution can cause field lines to merge into bundles [S1].
*   **Resolution:** To preserve the thinness of individual field lines and avoid merging, the resolution of the input texture can be increased by a factor of three prior to computation [S1].
*   **Smearing:** Unlike Fast LIC, Seed LIC does not assign values to neighboring voxels, which avoids smearing but results in sparser textures [S1].

## Operating characteristics
*   **Time Complexity:** Significantly reduced compared to Fast LIC for sparse input textures [S1].
*   **Memory Complexity:** Requires storage for the input texture (sparse), output texture, and seed points [S1].
*   **Performance:** On an SGI ONYX 3800 (500 MHz R14000 processor), Seed LIC on a 398x298x798 texture took 26.86 seconds, while Fast LIC took 25 hours [S1]. An additional isotropic 3x3x3 convolution to reduce aliasing took 206.19 seconds [S1].
*   **Strengths:** Drastically reduces computational cost for sparse or ROI-masked vector fields by avoiding unnecessary computations in areas where field lines do not coincide with seed points [S1].
*   **Limitations:** More susceptible to aliasing than Fast LIC and produces sparser textures that may require post-processing [S1]. Higher computational cost for dense fields compared to Fast LIC if the ROI is large [S1].
*   **When to Use:** When visualizing vector fields with sparse features or when a Region of Interest (ROI) is defined, and computational efficiency is critical [S1].
*   **When Not to Use:** When a smooth, dense texture is required without post-processing, or when the vector field is dense and uniform, making Fast LIC more efficient [S1].

## Background
Seed LIC was proposed by Helgeland and Andreassen in 2004 as a method for effective volume visualization of three-dimensional vector fields [S1]. It addresses the limitations of traditional LIC, which is commonly used for 2D or surface-based visualization, by extending it to 3D volumes while managing the perceptual difficulties of dense 3D displays [S1]. The method exploits the sparsity of input textures masked by a Region of Interest (ROI) function, such as vorticity magnitude or temperature, to highlight important features [S1]. It was implemented and tested on synthetic vector fields and real-world data, such as shock wave simulations, using volume rendering techniques like VoluViz [S1]. The technique is often combined with limb darkening shading to reveal depth relations among field lines [S1].
