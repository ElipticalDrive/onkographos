# Three-Dimensional LIC

Also called: 3D LIC, Volume Line Integral Convolution, Volumetric LIC

## Overview
Three-Dimensional Line Integral Convolution (3D LIC) generalizes the 2D LIC algorithm to three dimensions, applying a noise texture along streamlines within a 3D vector field to produce a 3D scalar output texture where voxel values are locally correlated with the flow direction [S1][S2, unofficial]. It differs from its siblings by operating on volumetric data rather than surfaces or 2D slices, allowing for the visualization of internal flow structures, though it suffers from higher computational cost and perceptual difficulties in conveying directionality from 2D projections [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input Vector Field:** A 3D vector field $\mathbf{V}(x,y,z)$ [S1].
*   **Input Texture:** A 3D scalar noise texture $T(x,y,z)$ [S1].
*   **Output:** A 3D scalar field $O(x,y,z)$ [S1].

**Data Structures:**
The algorithm processes the volume on a per-cell basis, where each cell corresponds to a voxel in the 3D grid [S1].

**Steps:**
1.  **Initialize Output:** Create a 3D output scalar field $O$ of the same dimensions as the input vector field and texture [S1].
2.  **Iterate Cells:** For each cell $(i,j,k)$ in the 3D grid:
    a.  **Sample Vector:** Retrieve the vector $\mathbf{v} = \mathbf{V}(i,j,k)$ [S1].
    b.  **Check Magnitude Threshold:** If $|\mathbf{v}|$ is outside the volume renderer's min/max threshold window, set $O(i,j,k)$ to transparent/zero and skip further processing for this cell [S1].
    c.  **Integrate Streamline:** Compute the streamline passing through the center of the cell $(i,j,k)$ by integrating the vector field $\mathbf{V}$ (e.g., using Euler or Runge-Kutta methods) to generate a path [S1].
    d.  **Convolve Noise:** Sample the input noise texture $T$ along the streamline and convolve these samples with a kernel to compute the output value $O(i,j,k)$ [S1].
3.  **Render:** Render the resulting 3D scalar field $O$ using volume rendering techniques, such as ray casting with opacity transfer functions [S1].

**Formulas:**
The sources state that the 1D LIC equations trivially extend to three dimensions, but do not provide the explicit mathematical formulation [S1].

**Parameters:**
*   **Convolution Length:** Not given in the sources.
*   **Integration Step Size:** Not given in the sources.
*   **Boundary Conditions:** Not given in the sources.
*   **Threshold Window:** Defined by the volume renderer's min/max magnitude thresholds [S1].

**Edge Cases and Pitfalls:**
*   **Perceptual Difficulty:** Dense 3D displays suffer from difficulties in clearly conveying directional information and mental reconstruction of 3D flow from 2D slices [S2, unofficial].
*   **Performance:** The algorithm is computationally expensive, and performance drops significantly without thresholding [S1].

**Pseudocode:**
```python
def three_d_lic(vector_field, noise_texture, output_volume, threshold_min, threshold_max, num_steps, step_size):
    # Iterate over all cells in the 3D grid
    for i in range(vector_field.shape[0]):
        for j in range(vector_field.shape[1]):
            for k in range(vector_field.shape[2]):
                v = vector_field[i, j, k]
                magnitude = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
                if magnitude < threshold_min or magnitude > threshold_max:
                    output_volume[i, j, k] = 0.0
                    continue
                # Integrate streamline using Euler method [G]
                x, y, z = float(i), float(j), float(k)
                samples = []
                for _ in range(num_steps):
                    # Boundary handling not specified in sources [G]
                    ix, iy, iz = int(x), int(y), int(z)
                    samples.append(noise_texture[ix, iy, iz])
                    v = vector_field[ix, iy, iz]
                    x += v[0] * step_size
                    y += v[1] * step_size
                    z += v[2] * step_size
                # Convolve samples with a box filter [G]
                output_volume[i, j, k] = sum(samples) / len(samples)
    return output_volume
```

## Operating characteristics
*   **Time Complexity:** The algorithm remains one-dimensional in nature, so the cost per cell increases by a factor of three due to dimensionality [S1].
*   **Memory Complexity:** Requires storage for the input vector field, input noise texture, and output scalar field [S1][S2, unofficial].
*   **Performance:** On an IBM 550 RISC 6000, 3D LIC processes approximately 1,200 cells per second (CPS) [S1]. Using magnitude thresholding to skip cells outside the volume renderer's min/max window, performance exceeds 30,000 CPS [S1]. In 2D, the DDA method averages about 30,000 CPS while LIC averages about 3,000 CPS [S1].
*   **Strengths:** Allows visualization of internal flow structures within a volume [S2, unofficial].
*   **Limitations:** High computational cost; perceptual difficulties in conveying directionality from 2D slices; dense 3D displays are hard to interpret [S2, unofficial].
*   **When to use:** When internal flow structures need to be visualized and computational resources allow for volume rendering [S2, unofficial].
*   **When not to use:** Not given in the sources.

## Background
3D LIC was introduced as a generalization of the 2D LIC algorithm [S1]. It was developed to address the need for visualizing 3D flow fields within volumes, extending the concept of texture correlation along streamlines to three dimensions [S1][S2, unofficial]. The method has been used in applications such as rendering electrostatic fields [S1].
