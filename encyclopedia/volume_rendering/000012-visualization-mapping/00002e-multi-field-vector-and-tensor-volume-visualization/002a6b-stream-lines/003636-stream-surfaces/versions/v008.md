# Stream Surfaces

Also called: Stream Surface as Isosurface, Streamsheet, Van Wijk Stream Surface Method, Van Wijk's method, van Wijk's Stream Surface Method

## Overview
Stream surfaces visualize steady-state vector fields by stitching together adjacent streamlines to form a continuous geometric sheet, solving the problem of ascertaining overall flow direction in areas of substantial directional change where individual streamlines curl around each other [S1, unofficial]. Unlike its parent [Stream Lines](4796-stream-lines.md), which represents flow as discrete trajectories, stream surfaces provide a coherent topological separation of the flow volume [S1, unofficial]. The method is distinct from [Stream-Balls](7700-stream-balls.md) in that it relies on explicit geometric stitching of trajectories rather than implicit scalar field extraction, and from [Streak Surface](10437-streak-surface.md) as it assumes steady-state flow rather than tracking particle history [S1, unofficial].

## How it works
The method constructs a surface defined as the infinite set of streamlines emanating from a starting line segment or curve [S1, unofficial]. Two primary algorithmic approaches exist: the advancing front method (Hultquist) and the isosurface reformulation (van Wijk) [S1, unofficial][S2].

### Inputs and Outputs
*   **Input:** A steady-state vector field $\mathbf{v}(\mathbf{x})$ defined on a domain; a seeding curve $\mathcal{C}$ (line segment or closed loop); optionally, a discretized grid for the isosurface method [S1, unofficial].
*   **Output:** A mesh representing the stream surface [G].

### Data Structures
1.  **Vector Field:** Stored as a grid or unstructured mesh [G].
2.  **Surface Mesh:** A list of vertices and connectivity [G].
3.  **Scalar Field (Isosurface Method):** A regular grid where each cell stores a scalar value representing the boundary intersection identifier [S1, unofficial].

### Algorithm 1: Advancing Front (Hultquist)
This method explicitly integrates streamlines to build the surface geometry [S1, unofficial].

1.  **Initialization:** Define the seeding curve $\mathcal{C}$ [S1, unofficial]. Discretize $\mathcal{C}$ into a set of seed points $\{\mathbf{p}_0, \mathbf{p}_1, \dots, \mathbf{p}_n\}$ [G].
2.  **Integration:** For each seed point $\mathbf{p}_i$, integrate the streamline forward using a numerical integrator (e.g., Runge-Kutta) to generate a trajectory $\mathbf{s}_i(t)$ [S1, unofficial].
3.  **Stitching:** Connect adjacent streamlines $\mathbf{s}_i(t)$ and $\mathbf{s}_{i+1}(t)$ at corresponding parameter values $t$ to form quadrilateral strips [S1, unofficial].
4.  **Adaptive Refinement:** Monitor the divergence of adjacent streamlines. If the distance between $\mathbf{s}_i(t)$ and $\mathbf{s}_{i+1}(t)$ exceeds a threshold or if the surface mesh distorts significantly (e.g., around obstacles), insert new seed points between $\mathbf{p}_i$ and $\mathbf{p}_{i+1}$ on the curve $\mathcal{C}$ and integrate new streamlines [S1, unofficial].
5.  **Handling Tears:** If the flow divergence causes the surface to tear (adjacent streamlines separate beyond connectivity), allow the mesh to split or handle the boundary explicitly [S1, unofficial].

### Algorithm 2: Isosurface Reformulation (van Wijk)
This method reformulates the stream surface construction as an isosurface extraction problem [S2].

1.  **Grid Precomputation:** Precompute a discretized volume on a regular grid covering the flow domain [S1, unofficial].
2.  **Backward Integration:** For every interior grid point $\mathbf{x}_k$, compute a backward streamline by integrating $-\mathbf{v}(\mathbf{x})$ until the trajectory intersects the boundary of the domain $\partial \Omega$ [S1, unofficial].
3.  **Boundary Labeling:** Store the position or unique identifier $\mathbf{b}_k$ of the boundary intersection point for each interior grid point $\mathbf{x}_k$ [S1, unofficial].
4.  **Scalar Field Definition:** Assign scalar function values to the boundary points. The scalar value at an interior grid point $\mathbf{x}_k$ is defined by the scalar value of its boundary intersection $\mathbf{b}_k$ [S1, unofficial]. This results in a scalar function $f(\mathbf{x})$ defined over the regular grid [S1, unofficial].
5.  **Iso-Contour Extraction:** Extract the iso-contour surface of $f(\mathbf{x})$ using a standard algorithm to construct the stream surface [S1, unofficial].

### Parameters and Edge Cases
*   **Steady-State Assumption:** The method assumes the flow is steady. The utility is lost for unsteady flows [S1, unofficial].
*   **Boundary Conditions:** The flow must enter or exit the volume boundaries for the isosurface method to work. Artificial boundaries can be placed to rectify this if the flow is confined [S1, unofficial].
*   **Directional Ambiguity:** The flow direction tangential to the surface is lost because merging many streamlines prevents determining if the flow went straight or weaved [S1, unofficial]. This is often mitigated by superimposing textures like LIC [S1, unofficial].

### Pseudocode (Isosurface Method)
```python
def compute_stream_surface_isosurface(vector_field, grid_points, boundary_points, step_size=0.1, max_steps=1000):
    """
    Constructs a stream surface by reformulating it as an isosurface of a 
    scalar field derived from backward integration to the boundary.
    
    Args:
        vector_field: Function v(x) returning velocity at x.
        grid_points: List of 3D points on the regular grid.
        boundary_points: Set of 3D points defining the domain boundary.
        step_size: Integration step length.
        max_steps: Maximum integration steps to prevent infinite loops.
        
    Returns:
        scalar_field: Dictionary mapping grid points to boundary identifiers.
    """
    scalar_field = {}
    
    # Step 1 & 2: Backward integration for interior points
    for x in grid_points:
        if x in boundary_points:
            continue
            
        current_pos = x
        reached_boundary = False
        for _ in range(max_steps):
            v = vector_field(current_pos)
            v_norm = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
            if v_norm == 0:
                break
            # Euler integration backward along -v(x)
            current_pos = (current_pos[0] - step_size * v[0]/v_norm,
                           current_pos[1] - step_size * v[1]/v_norm,
                           current_pos[2] - step_size * v[2]/v_norm)
            
        if current_pos in boundary_points:
            # Step 3: Store boundary identifier
            boundary_id = boundary_points.index(current_pos)
            # Step 4: Assign scalar value based on boundary
            scalar_field[x] = boundary_id
            reached_boundary = True
        else:
            scalar_field[x] = None
            
    # Step 5: Extract iso-contour
    # The stream surface corresponds to the iso-surface separating 
    # regions tracing back to different parts of the seeding curve.
    # [G] Standard marching cubes or similar grid-based iso-surface extraction 
    # is applied to scalar_field to generate the final mesh.
    return scalar_field
```

## Subtopics

### [Stream-Balls](7700-stream-balls.md)
Replaces explicit geometric stitching with an implicit scalar field using blobby functions, allowing the surface to gracefully split in high divergence areas.

### [LIC on Stream Surfaces](7721-lic-on-stream-surfaces.md)
Superimposes Line Integral Convolution texture onto stream surfaces to resolve the lack of directional information inherent in standard surface rendering.

### [Streak Surface](10437-streak-surface.md)
Visualizes time-dependent flows by tracking particles from a seeding curve at different ages, capturing flow history unlike steady-state stream surfaces.

### [Hairs](12773-hairs.md)
Grows tiny, segmented hairs from contour surfaces that bend with the flow, offering a discrete alternative when surface continuity fails.

### [Streamtape Rendering](14472-streamtape-rendering.md)
Represents individual streamlines as twisted surfaces (streamtapes) using local torsion to manage visual complexity, rather than stitching adjacent lines into a continuous sheet.

### [Stream Arrows](15478-stream-arrows.md)
Texture maps arrows onto stream surface geometry to convey local flow direction, solving orientation ambiguity in curling flows.

### Hyperstreamlines
A continuous representation of a tensor field constructed by sweeping a geometric primitive along a streamline of one of the eigenfields [S3, unofficial]. It selects one of the three eigenfields (major, medium, or minor) to define the longitudinal direction, constructs a streamline through it, and sweeps a geometric primitive (ellipse or cross) along the trajectory [S3, unofficial]. For an ellipse primitive, the other two eigenvectors define the major and minor axes of the cross-section; for a cross primitive, they control the length and orientation of the arms [S3, unofficial]. Color and trajectory represent the longitudinal eigenvector, while the cross-section encodes the two transverse eigenvectors [S3, unofficial]. When using a cross primitive, the arms may rotate in some tensor fields, resulting in a helical shape [S3, unofficial]. Critical points occur where the longitudinal eigenvector vanishes (locus) or where the cross-section becomes singular (surface) [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The advancing front method is expensive due to the need for adaptive refinement and handling severe mesh distortion as flow diverges around obstacles [S1, unofficial]. The isosurface method requires increased computational effort to advect a boundary-defined scalar field throughout the entire volume domain [S2].
*   **Memory Complexity:** Requires storage for the vector field, the surface mesh (or scalar grid), and integration history [G]. The isosurface method requires a full scalar grid representation [S1, unofficial][S2].
*   **Strengths:** A single surface can be rendered efficiently using standard graphics hardware [S1, unofficial]. It provides a clear topological separation of the flow, especially for closed curves where it divides the volume into bounded and unbounded regions [S1, unofficial].
*   **Limitations:** The method is limited to steady-state flows [S1, unofficial]. The tangential flow direction is lost on the surface [S1, unofficial]. Multiple surfaces may occlude each other, requiring careful examination from multiple viewpoints [S1, unofficial]. The advancing front method suffers from severe distortion and requires complex tear handling [S1, unofficial].
*   **When to Use:** When visualizing steady-state flows where the overall topology and separation of flow regions are critical, and individual streamline curling makes discrete lines hard to interpret [S1, unofficial].
*   **When Not to Use:** For unsteady flows, or when precise tangential flow direction on the surface is required without additional texturing [S1, unofficial].

## Background
Stream surfaces were introduced as an extension of streamlines to address the difficulty of ascertaining overall flow in 3D vector fields where streamlines curl around each other [S1, unofficial]. Hultquist [1] proposed the original method of stitching adjacent streamlines to build a stream surface, including adaptive refinement to handle mesh distortion [S1, unofficial]. Van Wijk [2] later proposed a simpler scheme for closed environments by reformulating stream surfaces as isosurfaces, which avoids explicit mesh stitching but requires global integration to the boundary [S1, unofficial][S2]. The method is widely used in computational fluid dynamics visualization for steady-state flows [S1, unofficial][S2].
