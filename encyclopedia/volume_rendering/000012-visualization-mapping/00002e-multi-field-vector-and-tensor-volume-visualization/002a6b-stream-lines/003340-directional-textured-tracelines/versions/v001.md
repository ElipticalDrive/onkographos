# Directional Textured Tracelines

Also called: Animated Line Tracelines, Texture Map Animation for Vector Magnitude, Textured Streamlines

## Overview
Directional Textured Tracelines is a flow visualization technique that enhances standard 1D line primitives (streamlines) by overlaying an animated 1D texture to explicitly convey flow direction and magnitude [S1, unofficial][S2, book]. While standard lines indicate orientation and extent, they fail to show the direction of the underlying vector field; this method solves that ambiguity by moving a structured texture (e.g., a zebra-like pattern) along the line in the direction of the flow [S1, unofficial]. It builds on [Stream Lines](4796-stream-lines.md) by adding temporal visual cues to static geometric trajectories.

## How it works
**Inputs:**
- A set of streamlines, defined as sequences of vertices $V = \{v_0, v_1, \dots, v_n\}$.
- A 1D texture map $T$, computed on the CPU, containing a visual structure (e.g., alternating dark/light bands) that varies monotonically in intensity [S1, unofficial][S2, book].
- A global time parameter $\Delta t$ [S1, unofficial].

**Outputs:**
- Rendered streamlines with apparent motion indicating flow direction [S1, unofficial].

**Data Structures:**
- **Vertices:** Each vertex $v_i$ of a line is assigned a local texture coordinate $u_i$.
- **Texture Coordinate Range:** The coordinates are normalized such that $u_0 = 0$ at the first vertex and $u_n = 1$ at the last vertex [S1, unofficial].
- **Texture Map:** A static 1D image downloaded to GPU memory once. It does not change during animation [S1, unofficial].

**Steps:**
1. **Assign Texture Coordinates:** For each vertex $v_i$ in a streamline, compute the local texture coordinate $u_i$ based on its position along the line segment. The range is $[0, 1]$ from start to end [S1, unofficial].
2. **Select Texture:** Choose a 1D texture map where intensity varies monotonically (e.g., dark to light) to ensure perceived motion direction is unambiguous [S2, book].
3. **Shift Coordinates:** For each frame, update the effective texture coordinate $u'_i$ for every vertex by adding the global shift parameter $\Delta t$:
   $$ u'_i = (u_i + \Delta t) \mod 1 $$
   This shifts the texture along the line in the direction of the underlying flow field [S1, unofficial].
4. **Render:** Render the lines using the shifted texture coordinates. The animation creates the illusion of the line crawling in the direction of the vector field [S2, book].

**Pseudocode:**
```python
def render_directional_tracelines(streamlines, texture_map, delta_t):
    """
    streamlines: List of lists of vertices. Each vertex is a 3D point.
    texture_map: 1D array of color/intensity values.
    delta_t: Global float parameter for animation time shift.
    """
    for line in streamlines:
        n = len(line)
        if n < 2:
            continue
        
        # Step 1: Assign base texture coordinates [0, 1]
        # Assuming linear distribution along the line for simplicity
        # In practice, this might be based on arc length
        base_u = [i / (n - 1) for i in range(n)]
        
        # Step 3: Shift texture coordinates
        # The texture moves in the direction of the flow
        # Modulo 1 ensures wrapping within the texture domain
        shifted_u = [(u + delta_t) % 1.0 for u in base_u]
        
        # Step 4: Render line with texture
        # The GPU interpolates texture values between vertices
        # based on shifted_u and samples texture_map
        draw_line_with_texture(line, shifted_u, texture_map)
```

**Edge Cases and Pitfalls:**
- **Direction Ambiguity:** Standard lines alone fail to indicate flow direction; the animated texture is required to resolve this [S1, unofficial].
- **Texture Selection:** The texture must have visual structure (e.g., zebra-like pattern) for motion to be perceivable [S1, unofficial].
- **Monotonicity:** The texture intensity should vary monotonically to avoid ambiguous motion perception [S2, book].

## Operating characteristics
- **Time Complexity:** $O(N)$ per frame, where $N$ is the total number of vertices across all streamlines. Texture coordinate calculation is linear.
- **Memory Complexity:** $O(N)$ for storing vertex positions and texture coordinates. The texture map is constant size.
- **Performance:** Real-time visualization is possible, especially with GPU acceleration, as the texture map is static and downloaded once [S1, unofficial].
- **Strengths:** Clearly indicates flow direction; computationally inexpensive; works well with semi-transparent volume rendering via depth testing [S1, unofficial].
- **Limitations:** Only conveys direction along the line; does not show cross-flow components; requires careful texture selection for clarity [S1, unofficial][S2, book].

## Background
Originated in GPU-assisted multi-field video volume visualization [S1, unofficial]. The technique leverages texture coordinate animation to add apparent motion to 1D primitives, a concept also applied to hedgehogs for vector magnitude visualization [S2, book]. It is used in scientific visualization to enhance the readability of vector fields in dynamic environments.
