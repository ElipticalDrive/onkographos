# Feature Streamlines
Also called: Automatic Streamline Placement, DOI-based Streamline Seeding

## Overview
Feature Streamlines is a method for visualizing vector fields by automatically placing streamlines near significant flow features using a user-defined Degree of Interest (DOI) function [S1, S2, unofficial]. It extends Jobard et al.'s evenly-spaced placement by applying a smooth DOI function to control both seeding locations and the termination of streamline computation [S1, unofficial]. Unlike sibling methods that rely on entropy or multi-seed strategies, this approach allows explicit, brush-based definition of focal interest regions, reducing occlusion by suppressing streamlines in low-interest areas [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D vector field $\mathbf{V}(x,y,z)$; a scalar Degree of Interest (DOI) function $D(x,y,z)$ mapping spatial locations to $[0, 1]$; a rendering style (color/opacity mapping or shading).
*   **Output:** A set of 3D streamlines, each associated with a unique feature color and intensity derived from the DOI.

**Data Structures**
*   **DOI Field:** A 3D grid or texture storing scalar values $D \in [0, 1]$. $D=1$ indicates "focal interest"; $D=0$ indicates "context" or "ignore".
*   **Streamline:** A sequence of points $\mathbf{p}_0, \mathbf{p}_1, \dots, \mathbf{p}_n$ where $\mathbf{p}_0$ is the seed. Each streamline has an associated `feature_id` and `color_intensity`.

**Algorithm Steps**
The method supports two seeding modes. Non-random seeding is preferred for deterministic results and explicit control [S1, unofficial].

1.  **Feature Identification:** Identify significant features (e.g., object surfaces, high velocity regions, vortices) to define the DOI function $D(x,y,z)$ [S2, unofficial].
2.  **Seeding:**
    *   *Mode 1 (Focal Interest):* Allow seeding only at locations where $D(x,y,z) = 1$ [S1, unofficial].
    *   *Mode 2 (Probability):* Randomly sample a spatial location $\mathbf{p}$. Generate a random float $n \in (0, 1)$. If $n < D(\mathbf{p})$, use $\mathbf{p}$ as a seed [S1, unofficial].
3.  **Integration:** Compute the streamline starting from the seed $\mathbf{p}_0$ by integrating the vector field $\mathbf{V}$ (e.g., using RK4) to generate points $\mathbf{p}_i$.
4.  **Termination Condition:** Stop integration if:
    *   The endpoint leaves the scene boundary.
    *   The endpoint enters a region where $D(\mathbf{p}) = 0$ (for Mode 1, integration continues while $D > 0$; for Mode 2, similar logic applies to break computation in non-interest areas) [S1, unofficial].
5.  **Rendering Mapping:**
    *   Assign a unique color to the streamline based on its `feature_id`.
    *   Map the color intensity or opacity of each point on the streamline proportional to the DOI value $D(\mathbf{p}_i)$ at that point. Alternatively, apply the Zöckler shading model [S1, unofficial].

**Pseudocode**
```python
def compute_feature_streamlines(vector_field, doi_field, seeding_mode='focal', max_steps=1000):
    """
    vector_field: function V(x,y,z) -> (vx, vy, vz)
    doi_field: function D(x,y,z) -> float in [0,1]
    seeding_mode: 'focal' or 'probability'
    """
    streamlines = []
    
    # Step 2: Seeding
    seeds = []
    if seeding_mode == 'focal':
        # Non-random seeding for deterministic results and highest density
        # Evaluate condition in every point to ensure equal positions after update
        for point in grid_points:
            if doi_field(point) == 1.0:
                seeds.append(point)
    elif seeding_mode == 'probability':
        # Random sampling
        for _ in range(num_samples):
            point = random_sample_spatial_location()
            n = random_float(0, 1)
            if n < doi_field(point):
                seeds.append(point)
                
    # Step 3 & 4: Integration and Termination
    for seed in seeds:
        streamline = [seed]
        current_pos = seed
        feature_id = assign_unique_color_id()
        
        for step in range(max_steps):
            # Integrate one step
            velocity = vector_field(current_pos)
            next_pos = integrate_step(current_pos, velocity)
            streamline.append(next_pos)
            
            # Check termination
            if not is_inside_scene(next_pos):
                break
            if doi_field(next_pos) == 0.0:
                # Break computation in non-interest regions
                break
                
            current_pos = next_pos
            
        # Step 5: Rendering Mapping
        color_intensity_map = []
        for point in streamline:
            doi_val = doi_field(point)
            # Map intensity proportional to DOI
            intensity = doi_val 
            # Or apply Zöckler shading model here
            color_intensity_map.append((intensity, feature_id))
            
        streamlines.append({
            'points': streamline,
            'colors': color_intensity_map
        })
        
    return streamlines
```

**Parameters and Edge Cases**
*   **DOI Threshold:** $D=1$ is the strict focal interest. $D=0$ terminates or hides. Values in $(0,1)$ provide context [S1, unofficial].
*   **Precision:** Non-random seeding ensures deterministic results, avoiding the influence of random entities during focus variation [S1, unofficial].
*   **Pitfall:** Random seeding speeds up computation but lacks explicit control over placement [S1, unofficial].

## Operating characteristics
*   **Complexity:** Depends on the number of seeds and streamline length. Non-random seeding requires evaluating the DOI function at every grid point, which is $O(N)$ where $N$ is the number of grid cells. Random seeding is $O(M)$ where $M$ is the number of samples.
*   **Strengths:** Reduces visual clutter by suppressing streamlines in low-interest areas; allows intuitive, brush-based definition of focus [S1, unofficial]. Deterministic with non-random seeding [S1, unofficial].
*   **Limitations:** Requires a user-defined DOI function, which can be difficult to construct for complex flows [S1, unofficial]. Random seeding lacks explicit control [S1, unofficial].
*   **When to use:** When the user wants to focus on specific features (e.g., vortices, surfaces) and reduce occlusion from background flow [S1, S2, unofficial].

## Background
Feature Streamlines was introduced by Mlejnek et al. in 2003 as an extension of Jobard et al.'s evenly-spaced streamline placement [S1, unofficial]. It was developed to address occlusion problems in volume rendering of simulation data by using a focus-and-context approach [S1, unofficial]. The method integrates concepts from Löffelman et al. for probability-based seeding and Zöckler for shading [S1, unofficial]. It is used in interactive frameworks for visualizing computational simulation data, particularly in aerodynamic and fluid dynamics contexts [S1, S2, unofficial].
