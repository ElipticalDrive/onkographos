# Particle Traces on 2D Surfaces

Also called: Particle traces on surfaces, Surface particle traces, Trace lines on surfaces

## Overview
Particle Traces on 2D Surfaces is a flow visualization technique that represents the magnitude and direction of a 3D vector field on arbitrary 2D surfaces (not necessarily contour surfaces) using long, evenly spaced particle trace lines composed of contrasting color segments [S1][S2, unofficial]. It solves the problem of visualizing flow near surfaces without the density issues inherent in dense line fields, ensuring nearly constant line density across the entire surface regardless of local vector magnitude [S1][S2, unofficial]. Unlike [Integral Surface](11268-integral-surface.md), which generates a continuous surface, this method produces discrete, segmented lines that begin and end arbitrarily to maintain uniform spacing, avoiding the clustering or sparseness that occurs with random seeding [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D vector field $\mathbf{V}(x,y,z)$ and a set of arbitrary 2D surfaces defined piecewise linearly.
*   **Output:** A set of particle trace lines rendered on the surfaces, where each line consists of segments with length proportional to vector magnitude and color indicating direction.

**Data Structures:**
*   **Octree:** The surfaces are scan-converted into an octree to allow fast access to adjacent cells and memory efficiency compared to a full 3D grid [S1][S2, unofficial].
    *   **Cell Layout:** Each cell stores a plane equation consisting of four numbers (e.g., $Ax + By + Cz + D = 0$) representing the piecewise linear surface approximation [S1][S2, unofficial].
    *   **Constraint:** The surface must not pass through any cell twice [S1].
    *   **Subdivision:** Surfaces are subdivided down to a constant cell size [S1][S2, unofficial].
    *   **Presence:** Only cells intersecting the surfaces are present in the octree [S1][S2, unofficial].
*   **Trace Storage:** Each trace is a sequence of points. The length of erased traces is preserved in the cells they passed through to prevent extensive recalculation during backtracking [S1][S2, unofficial].

**Algorithm Steps:**

1.  **Surface Representation:** Scan-convert the input surfaces into the octree structure described above [S1][S2, unofficial].

2.  **Seed Selection:**
    *   Choose seed points on an integer lattice in a spatially hierarchical manner [S1][S2, unofficial].
    *   This guarantees that some seed point is near every point on the surface, unlike random placement which does not guarantee coverage [S1][S2, unofficial].
    *   The hierarchy ensures the first particle traces start well away from each other [S1][S2, unofficial].
    *   Define a `length_threshold` initialized to a large value [S1][S2, unofficial].

3.  **Advection Loop:**
    *   For each seed point at the current resolution:
        a.  Initialize a particle at the seed point [S1][S2, unofficial].
        b.  Advect the particle along the surface in both forward and backward directions using variable step size Euler's method [S1][S2, unofficial].
        c.  **Projection:** At each step, project the 3D vector field $\mathbf{V}$ onto the 2D surface tangent plane to determine the advection direction [S1][S2, unofficial]. (See [Vector Field Projection onto Surface](13034-vector-field-projection-onto-surface.md) for projection details).
        d.  **Termination Conditions:** Stop advection if:
            i.  The particle reaches a stagnation zone (velocity approaches zero) [S1][S2, unofficial].
            ii. The particle reaches an edge of the surface [S1][S2, unofficial].
            iii. The particle becomes too close to its own trace or another particle's trace [S1][S2, unofficial].
        e.  **Stagnation Handling:** If velocity approaches zero, the particle shrinks to a small round dot of radius $r$ [S1].

4.  **Validation and Thresholding:**
    *   Calculate the total length $L$ of the generated trace [S1][S2, unofficial].
    *   If $L > \text{length\_threshold}$:
        *   Accept the trace [S1][S2, unofficial].
    *   If $L \le \text{length\_threshold}$:
        *   Erase the trace [S1][S2, unofficial].
        *   Preserve the length of the erased trace in the cells it passed through to prevent extensive recalculation while backtracking for new seeds [S1][S2, unofficial].
        *   Select a new seed point [S1][S2, unofficial].

5.  **Threshold Reduction:**
    *   After all seed points at the current resolution are tried, reduce the `length_threshold` [S1][S2, unofficial].
    *   Repeat the process (Steps 3-4) with the new threshold [S1][S2, unofficial].
    *   Gradually reduce the threshold from maximum to minimum to produce an aesthetically pleasing distribution, though this takes longer than using a single threshold value [S1][S2, unofficial].

6.  **Rendering:**
    *   Break accepted particle trace lines into small segments [S1][S2, unofficial].
    *   **Segment Length:** The length of each segment represents the magnitude of the vector field, calculated as a constant time interval $\Delta t$ multiplied by the magnitude $|\mathbf{V}|$ [S1][S2, unofficial].
        $$ \text{Segment Length} = \Delta t \cdot |\mathbf{V}| $$
    *   **Segment Direction:** The direction of the segment is the vector field direction at that point projected onto the 2D surface [S1][S2, unofficial].
    *   **Color Mapping:** Use contrasting colors for adjacent segments [S1][S2, unofficial].
    *   **Directional Ambiguity:** In still pictures, use a sawtooth-shaped color map across each segment to resolve the directional ambiguity of the lines [S1][S2, unofficial].
    *   **Animation (Optional):** Use color table animation to add motion, making lines "flow" in the direction of the vector field with velocity proportional to $|\mathbf{V}|$ [S1].

**Pseudocode:**

```python
def particle_traces_on_2d_surfaces(vector_field, surfaces, octree, max_threshold, min_threshold, threshold_step):
    """
    Generates particle traces on 2D surfaces using hierarchical seeding and variable step advection.
    """
    # 1. Surface Representation (Assumed pre-computed into octree)
    # octree contains cells with plane equations (4 numbers)
    
    # 2. Seed Selection Setup
    seeds = generate_hierarchical_integer_lattice(surfaces, octree)
    current_threshold = max_threshold
    
    traces = []
    
    while current_threshold >= min_threshold:
        new_traces = []
        
        for seed in seeds:
            # 3. Advection
            trace_points = []
            current_pos = seed
            
            # Forward advection
            forward_trace = advect_along_surface(vector_field, octree, current_pos, direction=1, threshold_check=False)
            # Backward advection
            backward_trace = advect_along_surface(vector_field, octree, current_pos, direction=-1, threshold_check=False)
            
            # Combine traces (backward reversed, then forward)
            full_trace = reverse(backward_trace) + [current_pos] + forward_trace
            
            # 4. Validation
            trace_length = calculate_length(full_trace)
            
            # Preserve length in cells for backtracking optimization [S1][S2, unofficial]
            store_trace_length_in_cells(full_trace, trace_length)
            
            if trace_length > current_threshold:
                new_traces.append(full_trace)
            else:
                # Erase trace, try new seed (handled by loop iteration)
                pass
        
        traces.extend(new_traces)
        
        # 5. Threshold Reduction
        current_threshold -= threshold_step
        
    # 6. Rendering
    rendered_lines = []
    for trace in traces:
        segments = break_into_segments(trace, vector_field, delta_t=CONSTANT_TIME_INTERVAL)
        rendered_line = render_segments_with_sawtooth_color(segments)
        rendered_lines.append(rendered_line)
        
    return rendered_lines

def advect_along_surface(vector_field, octree, start_pos, direction, threshold_check):
    """
    Advects a particle using variable step size Euler's method.
    """
    points = [start_pos]
    current_pos = start_pos
    step_size = INITIAL_STEP_SIZE
    
    while True:
        # Get vector at current position
        v = vector_field(current_pos)
        
        # Check for stagnation
        if magnitude(v) < STAGNATION_THRESHOLD:
            points.append(current_pos) # Shrink to dot
            break
            
        # Project vector onto surface tangent plane
        surface_normal = get_surface_normal(octree, current_pos)
        v_projected = project_vector_onto_plane(v, surface_normal)
        
        # Check termination conditions
        if is_at_edge(octree, current_pos):
            points.append(current_pos)
            break
        if is_too_close_to_other_traces(current_pos):
            points.append(current_pos)
            break
            
        # Euler step
        next_pos = current_pos + direction * step_size * normalize(v_projected)
        
        # Update step size (variable step size Euler's method)
        step_size = update_step_size(v, step_size)
        
        points.append(next_pos)
        current_pos = next_pos
        
        # Optional: Check threshold during advection if needed for early exit
        if threshold_check and calculate_length(points) > MAX_TRACE_LENGTH:
            break
            
    return points
```

**Parameters:**
*   **Length Threshold:** A minimum acceptable length for a particle trace. Initially set to a large value, then gradually reduced to minimum [S1][S2, unofficial].
*   **Constant Time Interval:** Used to determine segment length based on vector magnitude [S1][S2, unofficial].
*   **Stagnation Radius ($r$):** The radius of the dot when velocity approaches zero [S1].

**Pitfalls:**
*   **Directional Ambiguity:** In still images, lines may appear bidirectional. This is resolved by using a sawtooth-shaped color map across each segment [S1][S2, unofficial].
*   **Recalculation Cost:** Erasing short traces can be expensive if not optimized. Preserving the length of erased traces in the cells they passed through prevents extensive recalculation during backtracking [S1][S2, unofficial].
*   **Viewpoint Dependence:** Viewpoint-dependent projection techniques require particle traces to be recalculated when the viewpoint changes, whereas viewpoint-independent techniques (normal, xy normal, cylinder) do not [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of seed points, the length of traces, and the threshold reduction strategy. Gradually reducing the threshold from maximum to minimum produces the most aesthetically pleasing distribution but takes longer to calculate than using a single length threshold value [S1][S2, unofficial].
*   **Memory Complexity:** The octree structure is much more memory efficient than a full 3D grid, storing only cells that intersect the surfaces [S1][S2, unofficial].
*   **Performance:** On an SGI Onyx workstation, real-time rotation and particle motion can be achieved on small data sets, and interactive performance on large data sets, using hardware texture mapping [S2, unofficial].
*   **Strengths:** Guarantees coverage near every point on the surface (unlike random seeding); keeps line density nearly constant; allows long towlines to be easily understood; avoids density issues [S1][S2, unofficial].
*   **Limitations:** Viewpoint-dependent projections require recalculation; gradual threshold reduction is computationally expensive; surfaces must not pass through any cell twice [S1].

## Background
The technique was developed to visualize 3D velocity fields near contour surfaces, allowing long flowlines to be easily understood without becoming too dense or sparse [S1][S2, unofficial]. It builds on the concept of color table animation for flow visualization, an old technique [Shoup79] applied to flow visualization by Van Gelder and Wilhelms [VanGelder92] [S1]. The method was implemented and tested on an SGI Onyx workstation [S2, unofficial].
