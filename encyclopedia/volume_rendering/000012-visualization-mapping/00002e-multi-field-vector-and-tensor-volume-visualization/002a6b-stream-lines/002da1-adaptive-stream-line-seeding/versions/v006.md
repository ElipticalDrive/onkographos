# Adaptive Stream Line Seeding

Also called: Adaptive Line Extension, Adaptive seeding of stream lines, Streamline Subdivision

## Overview
Adaptive Stream Line Seeding is a method for visualizing vector fields by dynamically increasing the density of streamlines in regions where the flow diverges, such as turbulent areas or vortices, while maintaining sparse sampling in laminar regions [S1, unofficial]. It differs from sibling methods like [Directional Textured Tracelines](6965-directional-textured-tracelines.md) and [Stream Surfaces](7696-stream-surfaces.md) by explicitly using geometric divergence between neighboring line segments to trigger the insertion of new seed points, thereby creating a denser surface representation of the flow structure [S2, unofficial].

## How it works
The algorithm operates iteratively on the GPU, typically alternating between a control kernel that identifies diverging line pairs and an evaluation kernel that integrates the new streamlines [S1, unofficial]. The core mechanism involves analyzing pairs of existing streamlines (or line segments) and inserting new seed points between them if the distance between corresponding points exceeds a defined threshold [S2, unofficial].

### Inputs and Outputs
**Inputs:**
*   `linePairs`: Array of `uint2` structures, where each element contains the indices of two neighboring streamlines to be compared.
*   `lineVertices`: Array of `float3` structures containing the vertex positions of all current streamlines.
*   `lineLengths`: Array of `uint` values, storing the number of vertices for each streamline.
*   `seeds`: Array of `float3` structures, storing the initial seed position for each streamline.
*   `maxAllowedLineDist`: Scalar threshold for the maximum distance between corresponding points of two lines before subdivision is triggered.
*   `verticesPerLine`: Integer stride representing the number of vertices allocated per streamline in the `lineVertices` buffer.
*   `verticesPerSample`: Integer stride representing the step size between sampled points within a streamline for divergence testing.
*   `linesMaxCount`: Integer, the maximum capacity of the streamline buffer.

**Outputs:**
*   `outLinePairs`: Array of `uint2` structures, updated to include new pairs formed by the subdivided lines.
*   `outPairsIndex`: Atomic counter tracking the number of pairs written to `outLinePairs`.
*   `outLinesIndex`: Atomic counter tracking the number of new lines/seeds written to the output buffers.
*   `seeds` (updated): New seed positions are written into the existing `seeds` array at indices determined by `outLinesIndex`.

### Data Structures
The implementation relies on static arrays allocated to maximum capacity to avoid dynamic memory allocation overhead during the kernel execution. Atomic operations are used to manage these static arrays as dynamic structures.

*   `linePairs`: `uint2*`
*   `lineVertices`: `float3*`
*   `lineLengths`: `uint*`
*   `seeds`: `float3*`
*   `outLinePairs`: `uint2*`
*   `outPairsIndex`: `uint*` (device pointer, atomic)
*   `outLinesIndex`: `uint*` (device pointer, atomic)

### Steps
1.  **Thread Initialization**: Each thread processes one pair of streamlines. Calculate the global thread ID `id`. If `id >= linePairsCount`, terminate.
2.  **Pair Retrieval**: Retrieve the current pair indices `currPair = linePairs[id]`.
3.  **Length Check**: Determine the minimum length of the two lines: `count = min(lineLengths[currPair.x], lineLengths[currPair.y])`. If `count < 2`, terminate (lines are too short to sample).
4.  **Divergence Sampling**: Sample 32 points along the two lines to find the maximum distance between them.
    *   Initialize `maxDist = 0`.
    *   Iterate `i` from `0` to `count` with a step of `count / 32`.
    *   Retrieve vertices: `v1 = lineVertices[currPair.x * verticesPerLine + i * verticesPerSample]` and `v2 = lineVertices[currPair.y * verticesPerLine + i * verticesPerSample]`.
    *   Update `maxDist = max(maxDist, length(v1 - v2))`.
5.  **Threshold Test**: If `maxDist < maxAllowedLineDist`, terminate (lines are sufficiently close).
6.  **Calculate New Lines**: Compute the number of new lines to insert using the formula:
    $$ newLines = \lfloor \sqrt{\frac{maxDist}{maxAllowedLineDist}} \rfloor $$
7.  **Allocate Output Space**: Atomically allocate space for the new lines in the output buffer:
    *   `outLineIndex = atomicAdd(outLinesIndex, newLines)`
    *   If `outLineIndex + newLines >= linesMaxCount`, rollback the allocation (`atomicAdd(outLinesIndex, -newLines)`) and terminate (buffer full).
8.  **Generate Seeds**: Calculate the step vector between the seeds of the diverging pair:
    $$ seedStep = \frac{seeds[currPair.y] - seeds[currPair.x]}{newLines + 1} $$
    Loop `i` from `0` to `newLines - 1`:
    *   Set new seed: `seeds[outLineIndex + i] = seeds[currPair.x] + (i + 1) * seedStep`.
9.  **Link Pairs**: Update the neighbor list to include the new lines.
    *   `lastOutPairIndex` is the index where the original pair was stored (or the previous new pair in the chain).
    *   For each new line `i`:
        *   Atomically allocate a pair index: `outPairIndex = atomicAdd(outPairsIndex, 1)`.
        *   Link the previous end to the new seed: `outLinePairs[lastOutPairIndex].y = outLineIndex + i`.
        *   Link the new seed to the current pair's other line: `outLinePairs[outPairIndex].x = outLineIndex + i`, `outLinePairs[outPairIndex].y = currPair.y`.
        *   Update `lastOutPairIndex = outPairIndex`.

### Pseudocode
```python
# CUDA Kernel: computeLineAdaptiveExtensionKernel
# Inputs:
#   maxAllowedLineDist: float
#   linePairs: uint2*
#   linePairsCount: uint
#   lineVertices: float3*
#   verticesPerLine: uint
#   verticesPerSample: uint
#   lineLengths: uint*
#   seeds: float3*
#   outLinePairs: uint2*
#   outPairsIndex: uint* (atomic)
#   outLinesIndex: uint* (atomic)
#   linesMaxCount: uint

def computeLineAdaptiveExtensionKernel(maxAllowedLineDist, linePairs, linePairsCount,
                                       lineVertices, verticesPerLine, verticesPerSample,
                                       lineLengths, seeds, outLinePairs, outPairsIndex,
                                       outLinesIndex, linesMaxCount):
    
    # Calculate global thread ID
    id = blockIdx.x * blockDim.x + threadIdx.x
    
    if id >= linePairsCount:
        return

    # Get current pair indices
    currPair = linePairs[id]
    
    # Atomically allocate space for the output pair (preserving the original pair link)
    outPairIndex = atomicAdd(outPairsIndex, 1)
    outLinePairs[outPairIndex].x = currPair.x
    outLinePairs[outPairIndex].y = currPair.y
    
    # Calculate minimum length of the two lines
    count = min(lineLengths[currPair.x], lineLengths[currPair.y])
    
    if count < 2:
        return  # One of the lines is too short

    # Test 32 samples for divergence
    maxDist = 0.0
    step = count / 32
    if step == 0:
        step = 1
        
    for i in range(0, count, step):
        v1 = lineVertices[currPair.x * verticesPerLine + i * verticesPerSample]
        v2 = lineVertices[currPair.y * verticesPerLine + i * verticesPerSample]
        dist = length(v1 - v2)
        if dist > maxDist:
            maxDist = dist

    if maxDist < maxAllowedLineDist:
        return  # Lines do not diverge enough

    # Calculate number of new lines to add
    newLines = floor(sqrt(maxDist / maxAllowedLineDist))

    # Atomically allocate output line indices
    outLineIndex = atomicAdd(outLinesIndex, newLines)
    
    if (outLineIndex + newLines) >= linesMaxCount:
        # Rollback if not enough space
        atomicAdd(outLinesIndex, -newLines)
        return  # Not enough space for new seeds

    # Calculate seed step
    seedStep = (seeds[currPair.y] - seeds[currPair.x]) / (newLines + 1)

    lastOutPairIndex = outPairIndex
    
    for i in range(0, newLines):
        # Set new seed
        seeds[outLineIndex + i] = seeds[currPair.x] + (i + 1) * seedStep
        
        # Insert new pair (like in linked-list)
        outPairIndex = atomicAdd(outPairsIndex, 1)
        
        # Link previous pair end to new seed
        outLinePairs[lastOutPairIndex].y = outLineIndex + i
        
        # Link new seed to current pair end
        outLinePairs[outPairIndex].x = outLineIndex + i
        outLinePairs[outPairIndex].y = currPair.y
        
        lastOutPairIndex = outPairIndex
```

### Parameters
*   `maxAllowedLineDist`: The maximum distance between corresponding points of two lines before subdivision is triggered. Typical values depend on the scale of the vector field.
*   `verticesPerSample`: Stride between sampled points in the `lineVertices` buffer. The algorithm samples 32 points evenly spaced along the shorter of the two lines.

### Edge Cases and Pitfalls
*   **Buffer Overflow**: If the pre-allocated buffer for lines (`linesMaxCount`) is insufficient, the atomic allocation fails. The code handles this by rolling back the `outLinesIndex` and skipping the subdivision for that pair [S1, unofficial].
*   **Short Lines**: If either line in a pair has fewer than 2 vertices, the divergence test is skipped to prevent out-of-bounds access or invalid sampling [S2, unofficial].
*   **Performance**: The algorithm is computationally expensive because it requires alternating CPU-GPU invocations and atomic operations for memory management. The number of new lines grows exponentially in early iterations ($2^n$), which can cause initial slowdowns [S1, unofficial].
*   **Precision**: The divergence test uses only 32 samples. If the lines oscillate rapidly between close and far distances, the maximum distance might be underestimated or overestimated depending on the sampling alignment.

## Subtopics

### [Adaptive Streamline Generation](7692-adaptive-streamline-generation.md)
An iterative algorithm to generate streamlines by starting with a fixed number of seeds, extending them via CUDA kernels, and recursively adding new seeds based on the endpoints of previously generated lines until a maximum number of adaptive steps is reached or no new lines are generated. It differs from the basic subdivision method by focusing on endpoint-based recursion rather than pairwise geometric divergence along the entire line length.

### [Entropy-based Seeding](14471-entropy-based-seeding.md)
Entropy-based Seeding is a method for selecting streamline seed locations in 3D vector fields by using Shannon’s entropy to measure local information content. It places seeds proportionally to entropy values to quantitatively capture critical flow features, such as turbulent cores, ensuring important regions are densely sampled. It differs from sibling methods like [Adaptive Stream Line Seeding](5604-adaptive-stream-line-seeding.md) by deriving seed density directly from an information-theoretic scalar field rather than geometric divergence or control kernels.

## Operating characteristics
*   **Time Complexity**: The algorithm is iterative. In each step, the number of lines can double, leading to exponential growth in the number of pairs to process in subsequent iterations. The divergence test is $O(N)$ where $N$ is the number of vertices, but fixed to 32 samples.
*   **Memory Complexity**: Requires pre-allocation of buffers for the maximum possible number of streamlines and pairs. This can lead to significant memory overhead if the field is highly turbulent.
*   **Performance**: The use of atomic operations for dynamic array management on GPU is a bottleneck. The alternation between CPU and GPU kernels adds synchronization overhead. However, the results are visually superior to regular seeding, and the overall slowdown is considered "not very significant" in the source [S1, unofficial].
*   **Strengths**: Effectively highlights complex flow features like vortices and turbulence by concentrating lines where they are needed.
*   **Limitations**: Computationally intensive; requires careful tuning of `maxAllowedLineDist`; memory management is complex due to the need for static pre-allocation.

## Background
The method was developed for real-time visualization of 3D vector fields using CUDA. The primary challenge addressed was the difficulty of implementing adaptive algorithms on GPU due to the cost of thread communication and dynamic memory management [S1, unofficial]. The solution uses a clever combination of static arrays, atomic operations, and alternating CPU-GPU kernel invocations to achieve adaptive subdivision without dynamic allocation.
