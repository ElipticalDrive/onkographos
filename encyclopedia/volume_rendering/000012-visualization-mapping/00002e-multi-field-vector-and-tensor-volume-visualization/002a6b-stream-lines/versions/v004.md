# Stream Lines

Also called: Integral Curve, Particle Tracing

## Overview
Stream lines visualize 3D vector fields by tracing the trajectories of massless particles through the flow, solving the initial value problem defined by the velocity field [S1, S3, S4, unofficial]. Unlike static glyphs that show direction at discrete points, stream lines reveal the continuous connectivity and topology of the flow, such as vortices and separation zones [S4, unofficial]. They are distinguished from path lines (which track particles in time-varying fields) by being tangential to the stationary flow field and generally not self-intersecting, except at cycles [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D vector field $\mathbf{V}(x,y,z)$, a set of seed points $\mathbf{x}_0$, an integration step size $\Delta t$, and a maximum number of integration steps $N_{max}$ [S3, S4, S5, unofficial].
*   **Output:** A sequence of 3D points (vertices) forming line strips or tubes, optionally colored by vector magnitude [S4, S5, unofficial].

**Data Structures:**
*   **Vector Field:** Stored as a 3D texture array (e.g., `cudaArray` with `float4` channels) to enable hardware-accelerated trilinear interpolation [S5, unofficial]. The texture is bound with linear filtering and clamp addressing [S5, unofficial].
*   **Seeds:** An array of 3D coordinates (float3) defining the starting positions of the stream lines [S4, S5, unofficial].
*   **Output Buffers:**
    *   `outVertices`: Array of `float3` storing the geometric positions. Each stream line occupies $N_{max} / \text{geometrySampling} + 1$ vertices [S4, S5, unofficial].
    *   `outVertexColors`: Array of `float3` storing the color for each vertex, derived from vector magnitude [S4, S5, unofficial].
    *   `outComputedSteps`: Array of `uint` storing the number of valid steps computed per seed [S5, unofficial].

**Parameters:**
*   $\Delta t$: Integration step size. Smaller values increase accuracy but require more steps [S4, unofficial].
*   $N_{max}$: Maximum number of integration steps [S4, S5, unofficial].
*   `geometrySampling`: Integer specifying how many integration steps are skipped between emitted geometry vertices. If 1, every step is emitted; if 2, every second point is emitted. This allows high-precision integration (small $\Delta t$) while reducing memory usage [S4, S5, unofficial].
*   `volumeSize`: Dimensions of the vector field domain $(W, H, D)$ [S4, S5, unofficial].
*   `volumeCoordSpaceMult`: A scaling factor converting world coordinates to texture coordinates for lookup [S5, unofficial].

**Algorithm Steps:**
1.  **Initialization:** For each seed point $i$, initialize the current position $\mathbf{p}$ in double precision to prevent accumulation error, though output is stored in single precision [S4, S5, unofficial]. Write $\mathbf{p}$ to the first vertex slot in `outVertices` [S5, unofficial].
2.  **Integration Loop:** Iterate from step $k=1$ to $N_{max}$:
    a.  **Boundary Check:** If $\mathbf{p}$ is outside the volume bounds ($x<0, y<0, z<0$ or $x>W, y>H, z>D$), terminate the stream line [S4, S5, unofficial].
    b.  **Vector Lookup:** Sample the vector field $\mathbf{v} = \mathbf{V}(\mathbf{p})$ using trilinear interpolation [S3, S5, unofficial].
    c.  **Termination Check:** If $|\mathbf{v}| < v_{min}$ (threshold) or the particle intersects itself (enters a previously visited cell), terminate [S3, unofficial].
    d.  **Integration:** Compute the next position $\mathbf{p}_{new}$ using an integrator (Euler or RK4) [S4, S5, unofficial].
    e.  **Update:** Set $\mathbf{p} = \mathbf{p}_{new}$ [S5, unofficial].
    f.  **Geometry Emission:** Decrement a counter. If the counter reaches zero, reset it to `geometrySampling` and write $\mathbf{p}$ to `outVertices` and its magnitude-based color to `outVertexColors` [S5, unofficial].
3.  **Finalization:** Record the number of computed steps for the seed [S5, unofficial].

**Formulas:**
*   **ODE Definition:** The streamline is the solution to $\frac{d\mathbf{x}}{dt} = \mathbf{V}(\mathbf{x})$ with $\mathbf{x}(t_0) = \mathbf{x}_0$ [S1, S3, unofficial].
*   **Euler Integration:** $\mathbf{p}_{i+1} = \mathbf{p}_i + \Delta t \cdot \mathbf{V}(\mathbf{p}_i)$ [S2, S4, unofficial].
*   **RK4 Integration:** Uses four slope estimates ($k_1, k_2, k_3, k_4$) for higher accuracy:
    $$ \mathbf{p}_{i+1} = \mathbf{p}_i + \frac{\Delta t}{6} (k_1 + 2k_2 + 2k_3 + k_4) $$
    where $k_1 = \mathbf{V}(\mathbf{p}_i)$, $k_2 = \mathbf{V}(\mathbf{p}_i + \frac{\Delta t}{2}k_1)$, etc. [S5, unofficial].
*   **Trilinear Interpolation:** For a cell defined by corners $(x_i, y_i, z_i)$ to $(x_i+dx, y_i+dy, z_i+dz)$, the weight $b_j$ for corner $j$ is calculated based on the distance of the query point $(x,y,z)$ from the corner. For example:
    $$ b_1 = \frac{(x_i+dx-x)(y_i+dy-y)(z_i+dz-z)}{dx \cdot dy \cdot dz} $$
    The interpolated vector is the weighted sum of the corner vectors [S3, unofficial].

**Pseudocode:**
```python
def compute_streamlines(seeds, vector_field_tex, volume_size, dt, max_steps, geometry_sampling, use_rk4):
    """
    Computes streamlines for a set of seed points.
    :param seeds: List of (x, y, z) tuples.
    :param vector_field_tex: 3D texture object supporting trilinear lookup.
    :param volume_size: Tuple (width, height, depth).
    :param dt: Integration step size.
    :param max_steps: Maximum integration steps per seed.
    :param geometry_sampling: Steps between emitted vertices.
    :param use_rk4: Boolean flag for integrator choice.
    :return: out_vertices (list of lists of (x,y,z)), out_colors (list of lists of (r,g,b))
    """
    out_vertices = []
    out_colors = []
    
    for seed in seeds:
        # Initialize position in double precision for accuracy
        pos_x, pos_y, pos_z = float(seed[0]), float(seed[1]), float(seed[2])
        
        line_vertices = []
        line_colors = []
        
        # Emit initial vertex
        line_vertices.append((pos_x, pos_y, pos_z))
        # Color lookup for initial position
        mag = get_magnitude(vector_field_tex, pos_x, pos_y, pos_z)
        line_colors.append(magnitude_to_color(mag))
        
        geometry_step = geometry_sampling
        step_count = 0
        
        for step in range(1, max_steps + 1):
            # Boundary check
            if (pos_x < 0 or pos_y < 0 or pos_z < 0 or 
                pos_x > volume_size[0] or pos_y > volume_size[1] or pos_z > volume_size[2]):
                break
            
            # Get vector at current position
            vec = vector_field_tex.lookup(pos_x, pos_y, pos_z)
            vx, vy, vz = vec.x, vec.y, vec.z
            
            # Termination check: magnitude threshold
            if sqrt(vx**2 + vy**2 + vz**2) < 1e-6:
                break
                
            # Integration step
            if use_rk4:
                # RK4 Implementation
                k1 = vec
                k2 = vector_field_tex.lookup(pos_x + 0.5*dt*k1.x, pos_y + 0.5*dt*k1.y, pos_z + 0.5*dt*k1.z)
                k3 = vector_field_tex.lookup(pos_x + 0.5*dt*k2.x, pos_y + 0.5*dt*k2.y, pos_z + 0.5*dt*k2.z)
                k4 = vector_field_tex.lookup(pos_x + dt*k3.x, pos_y + dt*k3.y, pos_z + dt*k3.z)
                
                dx = (dt/6.0) * (k1.x + 2*k2.x + 2*k3.x + k4.x)
                dy = (dt/6.0) * (k1.y + 2*k2.y + 2*k3.y + k4.y)
                dz = (dt/6.0) * (k1.z + 2*k2.z + 2*k3.z + k4.z)
            else:
                # Euler Implementation
                dx = dt * vx
                dy = dt * vy
                dz = dt * vz
            
            # Update position
            pos_x += dx
            pos_y += dy
            pos_z += dz
            
            # Geometry sampling
            geometry_step -= 1
            if geometry_step == 0:
                geometry_step = geometry_sampling
                line_vertices.append((pos_x, pos_y, pos_z))
                mag = get_magnitude(vector_field_tex, pos_x, pos_y, pos_z)
                line_colors.append(magnitude_to_color(mag))
                
            step_count += 1
            
        out_vertices.append(line_vertices)
        out_colors.append(line_colors)
        
    return out_vertices, out_colors

def get_magnitude(tex, x, y, z):
    vec = tex.lookup(x, y, z)
    return sqrt(vec.x**2 + vec.y**2 + vec.z**2)

def magnitude_to_color(mag):
    # Placeholder for transfer function logic
    return (mag, mag, mag) # Grayscale for simplicity
```

## Subtopics

### [Adaptive Stream Line Seeding](5604-adaptive-stream-line-seeding.md)
Adaptive Stream Line Seeding dynamically refines the density of stream lines in regions of high flow divergence, such as turbulence or vortices, while keeping sampling sparse in laminar areas. It iteratively subdivides pairs of neighboring stream lines when the distance between them exceeds a threshold, creating denser representations where flow complexity is highest. This contrasts with static seeding strategies and focuses on individual trajectory density rather than constructing continuous surfaces like [Stream Surfaces](7696-stream-surfaces.md).

### [Directional Textured Tracelines](6965-directional-textured-tracelines.md)
Directional Textured Tracelines enhance standard 1D line primitives by overlaying an animated 1D texture (e.g., a zebra pattern) that moves along the line in the direction of the flow. This solves the ambiguity of standard lines, which indicate orientation and extent but not flow direction. It builds on [Stream Lines](4796-stream-lines.md) by adding temporal visual cues to static geometric trajectories.

### [Stream Surfaces](7696-stream-surfaces.md)
Stream surfaces visualize steady-state vector fields by stitching together adjacent streamlines to form a continuous geometric surface. This helps ascertain overall flow direction in areas where streamlines curl around each other, providing a unified geometric entity efficient for standard graphics hardware. However, they may suffer from a loss of tangential flow direction information compared to discrete lines.

### Flow Geometry Bricks Rendering
Flow Geometry Bricks Rendering is a technique for rendering flow visualization (arrows and streamlines) using geometry bricks that hold range information of the visible region [S2, unofficial]. It constructs render geometry for the whole visible region (e.g., a distorted horseshoe shape) only when needed, mapping directly from computation space to physical space [S2, unofficial]. Streamlines are stored in a single vertex buffer as a line strip, while arrows use an indexed vertex buffer [S2, unofficial]. All geometry is rendered as opaque before the semi-transparent volume to allow accurate depth testing and occlusion culling [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of seeds and $M$ is the number of integration steps per seed. RK4 integration is approximately 4 times more expensive per step than Euler due to multiple texture lookups [S5, unofficial].
*   **Memory Complexity:** $O(N \cdot M / \text{geometrySampling})$ for the output vertex buffers. Using double precision for integration positions increases register pressure but prevents error accumulation, while single precision is used for storage [S4, unofficial].
*   **Performance:** Real-time performance is achievable on GPUs using CUDA, leveraging hardware-accelerated trilinear interpolation from 3D textures [S5, unofficial].
*   **Strengths:** Provides clear visualization of flow topology, vortices, and connectivity. GPU implementation allows interactive rates for large datasets [S4, S5, unofficial].
*   **Limitations:** Requires careful selection of seed points to avoid clutter or missing features. Integration errors can accumulate if step size is too large or precision is insufficient [S4, unofficial]. Self-intersection detection adds computational overhead [S3, unofficial].

## Background
Stream lines are a fundamental technique in flow visualization, rooted in the mathematical definition of integral curves of vector fields [S1, unofficial]. The method was adapted for volume rendering and GPU acceleration in the mid-2000s, with notable implementations using CUDA for real-time visualization of 3D vector fields [S4, S5, unofficial]. Early work included interactive visualization of magnetic fields and current using Euler integration [S3, unofficial], and later extensions included handling distorted volumes (e.g., horseshoe shapes) and optical flow in video volumes [S2, unofficial].
