# Uncertainty Visualization Using Glyphs

Also called: Error Glyph Mapping, Glyph-based Uncertainty Visualization

## Overview
This method visualizes data uncertainty by mapping error values to visual properties of triangular facets generated during surface extraction (typically via Marching Cubes). It solves the problem of conveying reliability information alongside geometry, allowing users to distinguish authentic data from noisy or interpolated regions. It differs from sibling methods like [Line Glyphs](2569-line-glyphs-for-vector-field-visualization.md) or [Arrow Glyphs](2663-arrow-glyphs-for-vector-field-visualization.md), which encode vector direction and magnitude, by focusing exclusively on scalar error metrics. It differs from [Uncertainty Visualization Using Blurring Texture](#uncertainty-visualization-using-blurring-texture) and [Uncertainty Visualization Using Transparency](#uncertainty-visualization-using-transparency) by using distinct geometric shapes or sizes rather than texture distortion or alpha blending, providing categorical or magnitude-based visual cues that are distinct from the underlying surface color.

## How it works
The core technique iterates over every triangular facet of the iso-surface. For each facet, an error value is computed, and this value determines the visual representation of the facet.

### Inputs and Outputs
*   **Inputs**:
    *   Triangular mesh (list of vertices and faces).
    *   Per-vertex error values (scalar fields).
    *   Base texture or glyph set.
*   **Outputs**:
    *   Rendered image where each triangular facet displays a visual cue corresponding to its error level.

### Data Structures
*   **Vertex**: Contains position $(x, y, z)$ and error value $e_v$.
*   **Face**: Contains indices to three vertices $v_1, v_2, v_3$.
*   **Glyph Set**: A collection of textures or geometric primitives. In the primary implementation, this includes:
    *   Set 1: Distinct shapes (triangle, diamond, rectangular, trapezoidal, crescent, round, heart, pentagram).
    *   Set 2: Shapes with varying sizes (e.g., gradient shapes of the moon).
    *   Base state: Solid color texture for error-free or low-error data.

### Steps
1.  **Iterate** over every triangular facet in the mesh.
2.  **Calculate Error**: Compute the error value for the facet. The sources specify using a weighted average of the errors from the three vertices of the triangular facet [S1].
    *   Let $e_1, e_2, e_3$ be the error values of the three vertices.
    *   The facet error $E_f$ is calculated as:
        $$ E_f = \frac{w_1 e_1 + w_2 e_2 + w_3 e_3}{w_1 + w_2 + w_3} $$
        Where $w_i$ are weights. The sources do not specify the exact weighting formula (e.g., area-based or uniform), only that it is a "weighted average" [S1]. [G] In the absence of specific weighting instructions, a uniform average ($w_1=w_2=w_3=1$) is the standard implementation assumption for vertex-based interpolation on triangles.
3.  **Map Error to Visual**: Map the calculated error $E_f$ to a specific visual property based on the chosen variant (Glyphs, Blurring, or Transparency).
    *   For **Glyphs**: Select a glyph texture or shape from the predefined set based on the magnitude of $E_f$.
    *   For **Blurring**: Determine the blurring level corresponding to $E_f$.
    *   For **Transparency**: Normalize $E_f$ to the range $[0, 1]$ and assign it to the alpha component.
4.  **Render**: Map the selected visual property (glyph texture, blurred texture, or alpha value) to the triangular facet during rendering.

### Parameters
*   **Glyph Set 1**: Uses distinct shapes to distinguish error levels apparently. Shapes include: triangle, diamond, rectangular, trapezoidal, crescent, round, heart, pentagram [S1].
*   **Glyph Set 2**: Uses shapes with different sizes (gradient shapes of the moon) to allow easier perception of error levels [S1].
*   **Low Error Representation**: Error-free or low-error data is represented by a solid color texture [S1].
*   **Blurring Scales**: 11 scales mapping error ranges.
    *   Clearest texture: Error range $0.0$ to $18.18$ [S1].
    *   Most blurring texture: Error range $> 181.81$ [S1].
    *   Intermediate scales are gradient from top to bottom (most blurring to clearest) [S1].
*   **Texture Pre-processing**: Blurring effects can be pre-processed using tools like Photoshop or generated by a user-defined program [S1].

### Edge Cases and Pitfalls
*   **Graphical Overload**: Using too many tiny triangular facets can cause graphical overload, making it difficult to get a fast overview of error patterns compared to blurring techniques [S1].
*   **Interaction Requirement**: Due to the potential for overload, interaction techniques (rotation, translation, zooming) are recommended to inspect individual facet errors [S1].
*   **Vertex Error Source**: The method relies on pre-existing vertex errors (e.g., from multi-resolution decomposition or measurement noise). The method itself does not compute the error but maps it [S1].

def render_uncertainty_blurring(mesh, vertex_errors, blur_scales):
    """
    Renders a mesh with uncertainty visualization using blurring textures.
    
    Args:
        mesh: List of faces.
        vertex_errors: Dictionary mapping vertex index to error value.
        blur_scales: List of tuples (min_error, max_error, blur_texture).
                     Sorted by error magnitude.
    """
    for face in mesh.faces:
        v1, v2, v3 = face.vertices
        
        e1 = vertex_errors[v1.index]
        e2 = vertex_errors[v2.index]
        e3 = vertex_errors[v3.index]
        
        # Weighted average
        facet_error = (e1 + e2 + e3) / 3.0
        
        # Map error to blur level
        # Sources specify 11 scales: 0.0-18.18 (clearest) to >181.81 (most blurring)
        blur_texture = None
        for min_e, max_e, tex in blur_scales:
            if min_e <= facet_error <= max_e:
                blur_texture = tex
                break
        
        if blur_texture is None:
            # Default to most blurred if error exceeds defined range
            blur_texture = blur_scales[-1][2]
            
        render_facet(face, texture=blur_texture)

def render_uncertainty_transparency(mesh, vertex_errors, min_error=0.0, max_error=1.0):
    """
    Renders a mesh with uncertainty visualization using transparency.
    
    Args:
        mesh: List of faces.
        vertex_errors: Dictionary mapping vertex index to error value.
        min_error: Minimum error value for normalization.
        max_error: Maximum error value for normalization.
    """
    for face in mesh.faces:
        v1, v2, v3 = face.vertices
        
        # Step 1: Obtain error for every vertex
        e1 = vertex_errors[v1.index]
        e2 = vertex_errors[v2.index]
        e3 = vertex_errors[v3.index]
        
        # Step 2: Normalize error to [0, 1]
        # [G] Clamping to handle values outside range
        n1 = clamp((e1 - min_error) / (max_error - min_error), 0.0, 1.0)
        n2 = clamp((e2 - min_error) / (max_error - min_error), 0.0, 1.0)
        n3 = clamp((e3 - min_error) / (max_error - min_error), 0.0, 1.0)
        
        # Step 3: Map to alpha component
        # Higher error -> Lower opacity (more transparent)
        # Source: "The more opaque the triangular facet is, the more reliable the data is"
        # So Alpha = 1 - Normalized_Error
        a1 = 1.0 - n1
        a2 = 1.0 - n2
        a3 = 1.0 - n3
        
        render_facet_rgba(face, alpha=(a1, a2, a3))

## Subtopics

### Uncertainty Visualization Using Blurring Texture
Maps error information to blurring levels of a texture applied to triangular facets; higher error results in more blurring. It uses 11 scales mapping error ranges from 0.0-18.18 (clearest) to >181.81 (most blurring). Textures can be pre-processed using Photoshop or generated by a user-defined blurring program. It is advantageous over glyphs for avoiding graphical overload when dealing with many tiny facets [S1].

### Uncertainty Visualization Using Transparency
Maps error values to the transparency (alpha component) of triangular facets; higher error results in lower opacity. It normalizes vertex errors to $[0, 1]$ and maps them to the alpha component of RGBA. More opaque facets indicate more reliable data [S1].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of triangular facets $N$, $O(N)$, as it iterates once over the mesh to compute errors and assign visual properties.
*   **Memory Complexity**: Linear, $O(N)$, to store the mesh and error values. Additional memory is required for the glyph/texture sets, which is constant relative to $N$.
*   **Performance**: Implemented in C++ using OpenGL and GLUT on a dual processor 2.4GHz laptop with an ATI 3450 graphics card (256MB memory) [S1].
*   **Strengths**: Provides immediate visual feedback on data reliability. Glyphs with distinct shapes allow categorical distinction of error levels.
*   **Limitations**: Can cause graphical overload if the mesh has too many tiny triangular facets, obscuring the overall error pattern. Requires interaction (zoom/rotate) for detailed inspection [S1].
*   **When to use**: When categorical distinction of error levels is preferred over continuous gradients, or when texture distortion (blurring) is undesirable.
*   **When not to use**: When the mesh is extremely dense and performance or visual clarity of the overall structure is prioritized over per-facet error inspection.

## Background
Originated in research on visualizing uncertainty in multi-resolution volumetric data using the Marching Cubes algorithm. The work was presented in a paper discussing the application of blurring textures and glyph-based mappings to MRI human brain data sets. The implementation was based on low-level APIs (OpenGL/ GLUT) to allow control over the Marching Cubes algorithm and rendering [S1].
