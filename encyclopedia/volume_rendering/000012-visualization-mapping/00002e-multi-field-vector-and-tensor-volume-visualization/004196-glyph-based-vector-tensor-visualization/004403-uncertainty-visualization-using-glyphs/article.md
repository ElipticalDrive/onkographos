# Uncertainty Visualization Using Glyphs

Also called: Error Glyph Mapping, Glyph-based Uncertainty Visualization

## Overview
This method visualizes data uncertainty by mapping error values to visual properties of triangular facets generated during surface extraction [S1]. It solves the problem of conveying reliability information alongside geometry, allowing users to distinguish authentic data from noisy or interpolated regions [S1]. It differs from sibling methods like [Line Glyphs](2569-line-glyphs-for-vector-field-visualization.md) or [Arrow Glyphs](2663-arrow-glyphs-for-vector-field-visualization.md), which encode vector direction and magnitude, by focusing exclusively on scalar error metrics [S1]. It differs from [Uncertainty Visualization Using Blurring Texture](#uncertainty-visualization-using-blurring-texture) and [Uncertainty Visualization Using Transparency](#uncertainty-visualization-using-transparency) by using distinct geometric shapes or sizes rather than texture distortion or alpha blending, providing categorical or magnitude-based visual cues that are distinct from the underlying surface color [S1].

## How it works
The core technique iterates over every triangular facet of the iso-surface [S1]. For each facet, an error value is computed, and this value determines the visual representation of the facet [S1].

### Inputs and Outputs
*   **Inputs**: Triangular mesh (list of vertices and faces) [S1]. Per-vertex error values (scalar fields) [S1]. Base texture or glyph set [S1].
*   **Outputs**: Rendered image where each triangular facet displays a visual cue corresponding to its error level [S1].

### Data Structures
*   **Vertex**: Contains position $(x, y, z)$ and error value $e_v$ [S1].
*   **Face**: Contains indices to three vertices $v_1, v_2, v_3$ [S1].
*   **Glyph Set**: A collection of textures or geometric primitives [S1]. In the primary implementation, this includes:
    *   Set 1: Distinct shapes (triangle, diamond, rectangular, trapezoidal, crescent, round, heart, pentagram) [S1].
    *   Set 2: Shapes with varying sizes (e.g., gradient shapes of the moon) [S1].
    *   Base state: Solid color texture for error-free or low-error data [S1].

### Steps
1.  **Iterate** over every triangular facet in the mesh [S1].
2.  **Calculate Error**: Compute the error value for the facet using a weighted average of the errors from the three vertices [S1].
    *   Let $e_1, e_2, e_3$ be the error values of the three vertices.
    *   The facet error $E_f$ is calculated as:
        $$ E_f = \frac{w_1 e_1 + w_2 e_2 + w_3 e_3}{w_1 + w_2 + w_3} $$
        Where $w_i$ are weights [S1]. The exact weighting formula is not specified in the sources [S1].
3.  **Map Error to Visual**: Map the calculated error $E_f$ to a specific visual property based on the chosen variant (Glyphs, Blurring, or Transparency) [S1].
    *   For **Glyphs**: Select a glyph texture or shape from the predefined set based on the magnitude of $E_f$ [S1].
    *   For **Blurring**: Determine the blurring level corresponding to $E_f$ [S1].
    *   For **Transparency**: Normalize $E_f$ to the range $[0, 1]$ and assign it to the alpha component [S1].
4.  **Render**: Map the selected visual property (glyph texture, blurred texture, or alpha value) to the triangular facet during rendering [S1].

### Parameters
*   **Glyph Set 1**: Uses distinct shapes to distinguish error levels apparently [S1]. Shapes include: triangle, diamond, rectangular, trapezoidal, crescent, round, heart, pentagram [S1].
*   **Glyph Set 2**: Uses shapes with different sizes (gradient shapes of the moon) to allow easier perception of error levels [S1].
*   **Low Error Representation**: Error-free or low-error data is represented by a solid color texture [S1].
*   **Blurring Scales**: 11 scales mapping error ranges [S1].
    *   Clearest texture: Error range $0.0$ to $18.18$ [S1].
    *   Most blurring texture: Error range $> 181.81$ [S1].
    *   Intermediate scales are gradient from top to bottom (most blurring to clearest) [S1].
*   **Texture Pre-processing**: Blurring effects can be pre-processed using tools like Photoshop or generated by a user-defined program [S1].

### Edge Cases and Pitfalls
*   **Graphical Overload**: Using too many tiny triangular facets can cause graphical overload, making it difficult to get a fast overview of error patterns compared to blurring techniques [S1].
*   **Interaction Requirement**: Due to the potential for overload, interaction techniques (rotation, translation, zooming) are recommended to inspect individual facet errors [S1].
*   **Vertex Error Source**: The method relies on pre-existing vertex errors (e.g., from multi-resolution decomposition or measurement noise) [S1]. The method itself does not compute the error but maps it [S1].

```python
def clamp(value, min_val, max_val):
    return max(min_val, min(value, max_val))

def set_face_texture(face_idx, texture):

def set_face_rgba(face_idx, r, g, b, a):

def render_uncertainty_glyphs(mesh, vertex_errors, glyph_set, error_thresholds):
    """Renders a mesh with uncertainty visualization using glyphs."""
    for face in mesh:
        v1, v2, v3 = face
        e1 = vertex_errors[v1]
        e2 = vertex_errors[v2]
        e3 = vertex_errors[v3]
        # Weighted average (uniform weights assumed when unspecified)
        facet_error = (e1 + e2 + e3) / 3.0
        
        glyph_index = 0
        for i, threshold in enumerate(error_thresholds):
            if facet_error < threshold:
                glyph_index = i
                break
        else:
            glyph_index = len(error_thresholds)
            
        set_face_texture(face, glyph_set[glyph_index])

def render_uncertainty_blurring(mesh, vertex_errors, blur_scales):
    """Renders a mesh with uncertainty visualization using blurring textures."""
    for face in mesh:
        v1, v2, v3 = face
        e1 = vertex_errors[v1]
        e2 = vertex_errors[v2]
        e3 = vertex_errors[v3]
        facet_error = (e1 + e2 + e3) / 3.0
        
        blur_texture = blur_scales[-1][2]
        for min_e, max_e, tex in blur_scales:
            if min_e <= facet_error <= max_e:
                blur_texture = tex
                break
                
        set_face_texture(face, blur_texture)

def render_uncertainty_transparency(mesh, vertex_errors, min_error=0.0, max_error=1.0):
    """Renders a mesh with uncertainty visualization using transparency."""
    for face in mesh:
        v1, v2, v3 = face
        e1 = vertex_errors[v1]
        e2 = vertex_errors[v2]
        e3 = vertex_errors[v3]
        
        # Normalize error to [0, 1]
        n1 = clamp((e1 - min_error) / (max_error - min_error), 0.0, 1.0)
        n2 = clamp((e2 - min_error) / (max_error - min_error), 0.0, 1.0)
        n3 = clamp((e3 - min_error) / (max_error - min_error), 0.0, 1.0)
        
        # Map normalized error to alpha component
        # The more opaque the facet is, the more reliable the data is [S1]
        a1 = 1.0 - n1
        a2 = 1.0 - n2
        a3 = 1.0 - n3
        
        set_face_rgba(face, 0.0, 0.0, 0.0, a1)
```

## Subtopics

### Uncertainty Visualization Using Blurring Texture
Maps error information to blurring levels of a texture applied to triangular facets; higher error results in more blurring [S1]. It uses 11 scales mapping error ranges from 0.0-18.18 (clearest) to >181.81 (most blurring) [S1]. Textures can be pre-processed using Photoshop or generated by a user-defined blurring program [S1]. It is advantageous over glyphs for avoiding graphical overload when dealing with many tiny facets [S1].

### Uncertainty Visualization Using Transparency
Maps error values to the transparency (alpha component) of triangular facets; higher error results in lower opacity [S1]. It normalizes vertex errors to $[0, 1]$ and maps them to the alpha component of RGBA [S1]. The more opaque the triangular facet is, the more reliable the data is and vice versa [S1].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of triangular facets $N$, $O(N)$, as it iterates once over the mesh to compute errors and assign visual properties [S1].
*   **Memory Complexity**: Linear, $O(N)$, to store the mesh and error values [S1]. Additional memory is required for the glyph/texture sets, which is constant relative to $N$ [S1].
*   **Performance**: Implemented in C++ using OpenGL and GLUT on a dual processor 2.4GHz laptop with an ATI 3450 graphics card (256MB memory) [S1].
*   **Strengths**: Provides immediate visual feedback on data reliability [S1]. Glyphs with distinct shapes allow categorical distinction of error levels [S1].
*   **Limitations**: Can cause graphical overload if the mesh has too many tiny triangular facets, obscuring the overall error pattern [S1]. Requires interaction (zoom/rotate) for detailed inspection [S1].
*   **When to use**: When categorical distinction of error levels is preferred over continuous gradients, or when texture distortion (blurring) is undesirable [S1].
*   **When not to use**: When the mesh is extremely dense and performance or visual clarity of the overall structure is prioritized over per-facet error inspection [S1].

## Background
Originated in research on visualizing uncertainty in multi-resolution volumetric data using the Marching Cubes algorithm [S1]. The work was presented in a paper discussing the application of blurring textures and glyph-based mappings to MRI human brain data sets [S1]. The implementation was based on low-level APIs (OpenGL/ GLUT) to allow control over the Marching Cubes algorithm and rendering [S1].
