# Tensor Glyphs

Also called: DT-MRI Glyphs, Eigenvalue-based Glyphs, Ellipsoid Glyphs, Superquadric Glyphs, Tensor Axes Glyphs

## Overview
Tensor Glyphs are point-icon visualization techniques that represent scalar, vectorial, or tensorial information (specifically eigenvalues and eigenvectors) at every data point in space, overcoming the limitation of colormaps which can display only three distinct metrics or one direction per point [S1, unofficial]. Unlike [Ellipsoid Glyphs](10535-glyph-based-vector-tensor-visualization.md) which suffer from ambiguity in projection, or [Tensor Axes Glyphs](10535-glyph-based-vector-tensor-visualization.md) which may be hard to distinguish, Tensor Glyphs map the tensor shape space (linear, planar, spherical) to geometric primitives that satisfy continuity, uniqueness, and unambiguity criteria [S1, unofficial]. They are primarily used in Diffusion Tensor Imaging (DTI) to visualize the orientation and anisotropy of diffusion [S1, unofficial][S2, unofficial].

## How it works
**Inputs:** A 3×3 symmetric diffusion tensor $D$ at each voxel [S2, unofficial].
**Outputs:** Geometric glyphs (ellipsoids, superquadrics, cylinders, boxes, or spheres) positioned at voxel centers [S2, unofficial].

**Data Structures:**
*   **Tensor Field:** Array of 3×3 symmetric matrices. Stored as 6 floats per voxel (diagonal $D_{xx}, D_{yy}, D_{zz}$ and off-diagonals $D_{xy}, D_{xz}, D_{yz}$) [G].
*   **Eigen Decomposition:** For each tensor, compute eigenvalues $\lambda_1, \lambda_2, \lambda_3$ and eigenvectors $\mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3$ [S2, unofficial].
    *   Constraint: $\lambda_1 \ge \lambda_2 \ge \lambda_3 \ge 0$.
    *   $\mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3$ are the major, medium, and minor eigenvectors, respectively [S2, unofficial].

**Numbered Steps:**
1.  **Eigen Decomposition:** For each tensor $D$, compute eigenvalues $\lambda_i$ and normalized eigenvectors $\mathbf{v}_i$, ordered $\lambda_1 \ge \lambda_2 \ge \lambda_3 \ge 0$ [S2, unofficial].
2.  **Metric Calculation:** Compute scalar anisotropy metrics $C_L, C_P, C_S$ using the formulas below [S2, unofficial].
3.  **Glyph Selection:** Determine the glyph type based on the dominant metric: if $C_L$ is high (linear diffusion), render a cylinder oriented along $\mathbf{v}_1$; if $C_S$ is high (isotropic diffusion), render a sphere; if $C_P$ is high (planar diffusion), render a box [S2, unofficial]. Alternatively, use a single superquadric surface parameterized by $C_L, C_P, C_S$ to smoothly interpolate between these shapes [S1, unofficial].
4.  **Transformation:** Transform a base glyph geometry $G$ to the tensor glyph geometry $G_T$ using the rotation matrix $R$ (formed by eigenvectors) and scaling by eigenvalues: $G_T = R^{-1} \begin{pmatrix} \lambda_1 & 0 & 0 \\ 0 & \lambda_2 & 0 \\ 0 & 0 & \lambda_3 \end{pmatrix} R G$ [S1, unofficial].
5.  **Rendering:** Render the transformed glyphs. For superquadrics, use GPU-based raytracing for efficiency [S1, unofficial].

**Formulas:**
*   Linear Anisotropy ($C_L$): $C_L = \frac{\lambda_1 - \lambda_2}{\lambda_1 + \lambda_2 + \lambda_3}$ [S2, unofficial]
*   Planar Anisotropy ($C_P$): $C_P = \frac{2(\lambda_2 - \lambda_3)}{\lambda_1 + \lambda_2 + \lambda_3}$ [S2, unofficial]
*   Spherical Anisotropy ($C_S$): $C_S = \frac{3\lambda_3}{\lambda_1 + \lambda_2 + \lambda_3}$ [S2, unofficial]
*   Note: $C_L + C_P + C_S = 1$ [S2, unofficial]
*   Rotation Matrix: $R = [\mathbf{v}_1 | \mathbf{v}_2 | \mathbf{v}_3]$ [S1, unofficial]
*   Transformation: $G_T = R^{-1} S R G$, where $S = \text{diag}(\lambda_1, \lambda_2, \lambda_3)$ [S1, unofficial]

**Parameters:**
*   Thresholds for glyph selection are not explicitly defined in the sources; typical implementations use values around $0.6$ for dominance [G].
*   Display density must be kept low to avoid visual clutter [S2, unofficial].

**Pseudocode:**
```python
def compute_tensor_glyph(tensor_D):
    # 1. Eigen Decomposition (standard 3x3 symmetric solver [G])
    eigenvalues, eigenvectors = solve_eigen_3x3_symmetric(tensor_D)
    # Sort descending: lambda1 >= lambda2 >= lambda3
    idx = argsort_descending(eigenvalues)
    lambda1, lambda2, lambda3 = eigenvalues[idx]
    v1, v2, v3 = eigenvectors[:, idx]

    # 2. Calculate Scalar Metrics [S2, unofficial]
    trace = lambda1 + lambda2 + lambda3
    if trace == 0:
        return None, (0.0, 0.0, 0.0)

    CL = (lambda1 - lambda2) / trace
    CP = 2.0 * (lambda2 - lambda3) / trace
    CS = 3.0 * lambda3 / trace

    # 3. Construct Rotation Matrix R [S1, unofficial]
    R = column_stack((v1, v2, v3))

    # 4. Construct Scaling Matrix S
    S = diag([lambda1, lambda2, lambda3])

    # 5. Transformation Matrix T = R^-1 S R. Since R is orthogonal, R^-1 = R^T [S1, unofficial]
    T = transpose(R) @ S @ R

    return T, (CL, CP, CS)

def render_glyphs(tensor_field):
    for voxel_tensor in tensor_field:
        T, metrics = compute_tensor_glyph(voxel_tensor)
        if T is None:
            continue
        CL, CP, CS = metrics
        # Glyph selection based on dominant metric [S2, unofficial]
        if CL > 0.6:
            shape = 'cylinder'
        elif CS > 0.6:
            shape = 'sphere'
        elif CP > 0.6:
            shape = 'box'
        else:
            shape = 'superquadric'
        # Render primitive at voxel center with transformation T [G]
        rasterize_or_raytrace(shape, T)
```

**Edge Cases and Pitfalls:**
*   **Unambiguity:** Boxes/cuboids fail criterion (g3) because they are not distinguishable from every view direction [S1, unofficial]. Ellipsoids also suffer from this ambiguity [S1, unofficial]. Superquadrics are preferred as they meet all criteria (g1-g3) [S1, unofficial].
*   **Visual Clutter:** Display density must be kept low to avoid visual clutter when rendering many icons [S2, unofficial].
*   **Continuity:** Minimal changes in neighboring tensors must not cause discontinuities in glyph geometry [S1, unofficial].
*   **Uniqueness:** The mapping from tensor shape to glyph geometry must be unique [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels, for eigen decomposition and glyph placement [G]. Rendering complexity depends on the glyph type; superquadrics require raytracing, which is more expensive than simple ellipsoids but manageable with GPU acceleration [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store the tensor field and glyph parameters [G].
*   **Performance:** Hlawitschka et al. [S1, unofficial] introduced a fast, GPU-based raytracing method for superquadrics, allowing real-time rendering of thousands of glyphs.
*   **Strengths:** Can display multiple metrics (direction, anisotropy type) simultaneously; unambiguous shape representation with superquadrics [S1, unofficial].
*   **Limitations:** Visual clutter at high densities [S2, unofficial]; computationally expensive for raytraced superquadrics compared to simple colormaps [S1, unofficial]; ellipsoids are ambiguous [S1, unofficial].
*   **When to use:** When understanding the local tensor shape (linear vs. planar vs. spherical) is critical, such as in DTI fiber tractography analysis [S1, unofficial][S2, unofficial].
*   **When not to use:** When performance is critical and only dominant direction is needed (use [Arrow Glyphs](2663-arrow-glyphs-for-vector-field-visualization.md) or [Line Glyphs](2569-line-glyphs-for-vector-field-visualization.md)); when data density is very high [S2, unofficial].

## Background
Tensor Glyphs were introduced to overcome the limitations of colormaps in displaying tensor information [S1, unofficial]. Superquadrics, a specific type of tensor glyph, were introduced by A. H. Barr in 1981 [S1, unofficial] and suggested for DTI visualization by Kindlmann in 2004 [S1, unofficial]. Hlawitschka et al. [S1, unofficial] later optimized their rendering for GPUs.
