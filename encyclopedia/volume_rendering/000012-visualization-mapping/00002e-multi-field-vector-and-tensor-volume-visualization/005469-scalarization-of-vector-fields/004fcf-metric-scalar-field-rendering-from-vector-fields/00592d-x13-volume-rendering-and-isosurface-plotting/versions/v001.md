# X13 Volume Rendering and Isosurface Plotting

Also called: 3D isosurface figures, GLMakie volume render

## Overview
X13 is a post-processing method for generating 3D visualizations of turbulent flow simulations by rendering scalar fields derived from vector velocity data. It solves the problem of visualizing 3D coherent structures (such as streamwise vortices) that are lost when reducing 3D data to 2D slices. It is distinguished from its sibling [X12](14065-x12-volume-rendering-and-isosurface-plotting.md) by using GPU-accelerated raymarching (GLMakie) to look *through* the volume, whereas X12 uses CPU-based orthogonal cutting planes.

## How it works
**Inputs:**
- NetCDF or HDF5 simulation snapshot files containing velocity components ($u, v, w$) and optional scalar fields.
- Command-line arguments specifying fields, rendering mode, and cropping limits.

**Outputs:**
- 3D figures (PNG/PDF) containing volume renders and/or isosurfaces of derived scalar metrics.

**Data Structures:**
- The method operates on a 3D grid where $u, v, w$ are stored at cell centers.
- Derived fields (Q, enstrophy, speed) are computed on the same grid.
- No staggered interpolation is used; gradients are computed directly on the collocated grid.

**Numbered Steps:**

1.  **Input Handling and Virtual Dataset Registration:**
    If the input file is an HDF5 virtual dataset (common in multi-GPU merged outputs), call `allow_virtual_storage!()` on the dataset object before reading. This prevents `KeyError` exceptions in `NCDatasets` [S1, unofficial].

2.  **Z-Cropping:**
    Crop the z-dimension to an active layer defined by `--zlim`.
    -   Default `--zlim` is 5.
    -   Keep a margin of one cell on each side of the cropped slab. This margin is required for the accuracy of centered differences in the next step.
    -   *Note:* Cropping must occur *before* differentiation. Cropping after differentiation causes memory peaks of 15–25 GB at $N_z=1024$ [S1, unofficial].

3.  **Field Extraction and Derivation:**
    -   Read the specified fields from the file.
    -   If the requested field is not present, derive it from velocity components $u, v, w$.
    -   The file's native vorticity ($\omega$) is often only the spanwise component, which is insufficient for 3D structure visualization.
    -   Compute the gradient tensor $\nabla \mathbf{u}$ using centered differences on the cropped grid.
    -   Derive scalar metrics such as:
        -   **Q-criterion:** $Q = \frac{1}{2}(\|\Omega\|^2 - \|S\|^2)$, where $\Omega$ is the rotation tensor and $S$ is the strain tensor.
        -   **Enstrophy:** $\Omega^2 = \|\nabla \times \mathbf{u}\|^2$.
        -   **Speed:** $|\mathbf{u}| = \sqrt{u^2 + v^2 + w^2}$.
    -   Boundary conditions: Periodic in x and y; one-sided differences at z-walls [S1, unofficial].

4.  **Isosurface Level Calculation:**
    -   Set isosurface levels symmetrically around zero (e.g., $-L, -l, l, L$).
    -   For positive-definite fields, clamp levels into the color range.
    -   The top level is set to the 0.995 quantile of the data.
    -   The color range upper bound is determined by `--clim-percentile` (default 99).
    -   *Pitfall:* If a level exceeds the color range upper bound, it renders saturated and indistinguishable from the next level in [S1, unofficial].

5.  **Figure Layout and Rendering:**
    -   **Panel Arrangement:**
        -   Single field: Layout by mode (volume and isosurface panels).
        -   Multiple fields: Layout by field, one panel each, wrapped at `--cols` (default 3).
    -   **Camera Orientation:** Set camera azimuth to $1.30\pi$. This orients the streamwise direction (x) across the frame width while keeping the spanwise direction (y) readable [S1, unofficial].
    -   **Panel Resolution:** Set panel size to 820x560 pixels to match the cropped domain aspect ratio (roughly 14:4.7:8) [S1, unofficial].
    -   **Color Scaling:**
        -   Use fixed fraction levels (0.18, 0.515, 0.85) of each panel's own range to ensure consistent surface meaning across panels.
        -   Use a symmetric `:balance` color scale for all panels, even positive-definite ones. The unused lower half indicates the quantity never changes sign [S1, unofficial].
    -   **Overlay Contours:**
        -   Draw contours of a reference field (e.g., buoyancy $b$) on the two vertical bounding walls using `--overlay`.
        -   *Pitfall:* Do not use isosurfaces for overlays. GLMakie ignores alpha transparency on volume contours, making interpenetrating isosurfaces indistinguishable. Wall contours provide clear spatial reference [S1, unofficial].

**Pseudocode:**

```python
function render_x13(file_path, args):
    # 1. Load Dataset
    ds = load_dataset(file_path)
    
    # Handle HDF5 virtual datasets from multi-GPU merges
    if is_virtual_dataset(ds):
        allow_virtual_storage!(ds)
    
    # 2. Crop Z-dimension
    # Default zlim is 5, but plotting scripts may use 4.
    # Must crop BEFORE differentiation to save memory and maintain centered diff accuracy.
    z_margin = 1
    z_max = args.zlim + z_margin
    z_min = -z_max
    ds_cropped = crop_z(ds, z_min, z_max)
    
    # 3. Derive Fields
    u = ds_cropped.u
    v = ds_cropped.v
    w = ds_cropped.w
    
    # Compute gradient tensor using centered differences
    # Periodic in x, y; one-sided at z boundaries
    du_dx, du_dy, du_dz = centered_gradient(u, ds_cropped.grid)
    dv_dx, dv_dy, dv_dz = centered_gradient(v, ds_cropped.grid)
    dw_dx, dw_dy, dw_dz = centered_gradient(w, ds_cropped.grid)
    
    # Compute Q-criterion (example derivation)
    # Q = 0.5 * (norm(omega_tensor)^2 - norm(strain_tensor)^2)
    # omega_tensor components from velocity gradients
    # strain_tensor components from velocity gradients
    Q = compute_q_criterion(du_dx, du_dy, du_dz, dv_dx, dv_dy, dv_dz, dw_dx, dw_dy, dw_dz)
    
    # 4. Calculate Isosurface Levels
    levels = compute_symmetric_levels(Q, args.clim_percentile)
    # levels = [-L, -l, l, L]
    # Top level is 0.995 quantile, range ends at clim_percentile
    
    # 5. Render
    fig = Figure(resolution=(820 * cols, 560 * rows))
    
    for field in args.fields:
        ax = Axis3(fig, aspect=(14, 4.7, 8))
        
        # Set camera azimuth
        set_camera!(ax, azimuth=1.30 * pi)
        
        # Render Volume or Isosurface
        if args.mode == "volume":
            volume_render(ax, field, levels=levels, color_range=get_panel_range(field))
        else:
            isosurface_render(ax, field, levels=levels, color_range=get_panel_range(field))
            
        # Add Overlay Contours on vertical walls
        if args.overlay:
            overlay_field = ds_cropped[args.overlay]
            draw_contours_on_walls(ax, overlay_field, color=:gray)
            
        # Set Color Scale
        set_colorscale!(ax, :balance)
        # Use fixed fractions for consistent meaning
        set_levels_fraction!(ax, [0.18, 0.515, 0.85])
        
    save("output.png", fig)
```

## Operating characteristics
-   **Time Complexity:** Rendering time is dominated by GPU raymarching. On a Casper compute node at $N_z=1024$, a six-panel figure takes ~90 seconds. A full 101-record set takes ~2.5 hours [S1, unofficial].
-   **Memory Complexity:** Significant memory savings are achieved by cropping the z-dimension before differentiation. A subsetter script can reduce file size from 2.15 GiB to 0.006 GiB (336x compression) for $N_z=128$ [S1, unofficial]. Without cropping, memory peaks can reach 15–25 GB at $N_z=1024$ [S1, unofficial].
-   **Hardware Requirements:** Requires an OpenGL context. Can run on CPU-only nodes using Mesa software rasterizer and Xvfb for off-screen rendering. Does not require a dedicated GPU or display [S1, unofficial].
-   **Strengths:** Provides true 3D visualization of internal structures; efficient batch rendering via software rasterization; handles large multi-GPU merged files.
-   **Limitations:** Transparency does not work for separating interpenetrating isosurfaces; requires careful tuning of isosurface levels and color ranges for multi-field comparisons; dependent on specific Julia packages (GLMakie, NCDatasets) [S1, unofficial].

## Background
X13 was developed as part of the `tomchor/CoarseGrainedKHAPE` repository for rendering 3D isosurfaces of turbulent flow simulations, specifically Kelvin-Helmholtz (KH) runs. It was introduced in October 2026 as a companion to X12, which used orthogonal cutting planes. X13 was designed to visualize 3D coherent structures (streamwise vortices) that are critical to the physics of the flow but invisible in 2D slices. It runs on the Casper compute cluster using Xvfb and Mesa for off-screen rendering [S1, unofficial].
