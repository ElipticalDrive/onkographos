# Object Space Ray Setup — Camera Space Transformation for Ray Origin, Local Space Ray Setup, Object Space Ray Casting

Also called: Ray Origin Calculation for Near Plane Quad, RayCasterShaderCodeTester::NearPlaneVertexShader

## Overview
This method constructs the ray origin in volume texture space by transforming a vertex from the near plane quad through inverse view and model transformations, followed by scaling and translation to align with the volume grid [S1, unofficial]. It differs from world-space ray generation by embedding the object's transform directly into the ray origin calculation, allowing the raytraced object to move, scale, and rotate with the mesh transform [1642-object-space-ray-setup.md].

## How it works
**Inputs:**
- `glVertex`: The vertex position of the near plane quad in view space (typically a 2D quad at $z=0$ or similar, centered on origin).
- `InverseModelViewMatrix`: The inverse of the combined Model-View matrix.
- `VolTranslation`: The translation vector of the volume in world space.
- `VolScale`: The scale factor of the volume in world space.
- `ProjectionMatrix`: The projection matrix for clipping.

**Outputs:**
- `RayPosition`: The ray origin in volume texture space (normalized 0..1).
- `gl_Position`: The clip-space position for rendering the quad.

**Data Structures:**
- The near plane quad is defined by four vertices in view space:
  - $(-0.5, -0.5, 0.0)$
  - $(0.5, -0.5, 0.0)$
  - $(0.5, 0.5, 0.0)$
  - $(-0.5, 0.5, 0.0)$
- Indices: $(0,1,2), (2,3,0)$ forming two triangles [S1, unofficial].

**Steps:**
1. Compute clip-space position: $gl\_Position = ProjectionMatrix \times glVertex$.
2. Transform vertex from view space to world space: $rayPosition = (InverseModelViewMatrix \times glVertex).xyz$.
3. Translate to volume local space: $rayPosition = rayPosition - VolTranslation$.
4. Scale to volume texture space: $rayPosition = rayPosition / VolScale$.
5. Offset to center in texture coordinates: $rayPosition = rayPosition + 0.5$.
6. Set output: $RayPosition = vec4(rayPosition, 1.0)$.

**Pseudocode:**
```python
def NearPlaneVertexShader(glVertex: vec4, InverseModelViewMatrix: mat4, VolTranslation: vec3, VolScale: float, ProjectionMatrix: mat4) -> tuple[vec4, vec4]:
    # Step 1: Clip space position
    gl_Position = ProjectionMatrix * glVertex
    
    # Step 2: View to World space
    rayPosition = (InverseModelViewMatrix * glVertex).xyz
    
    # Step 3: Translate to volume local space
    rayPosition = rayPosition - VolTranslation
    
    # Step 4: Scale to volume texture space
    rayPosition = rayPosition / VolScale
    
    # Step 5: Offset to center in texture coordinates
    rayPosition = rayPosition + 0.5
    
    # Step 6: Output
    RayPosition = vec4(rayPosition, 1.0)
    
    return gl_Position, RayPosition
```

**Parameters:**
- `VolScale`: Typically the physical size of the volume grid in world units.
- `VolTranslation`: The world position of the volume's origin.

**Edge Cases:**
- If `VolScale` is zero, division by zero occurs. Guard against this.
- If the volume is not axis-aligned, the simple scaling/translation may not correctly map to texture coordinates. This method assumes axis-aligned bounding box (AABB) alignment with the grid.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(1)$ per vertex.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple, efficient, directly maps to texture coordinates.
- **Limitations:** Assumes axis-aligned volumes. Does not handle complex object transforms (rotation) correctly if the volume is rotated relative to the grid.
- **When to use:** When the volume is axis-aligned and static or only translating/scaling.
- **When not to use:** When the volume is rotated or has complex non-uniform scaling that does not align with the grid axes.

## Background
This method originates from the VoxVizThesis project, which implements a debug renderer for volumetric data [S1, unofficial]. It is used in the context of raycasting shaders for volume visualization, specifically for setting up the ray origin in texture space for testing purposes.
