# Epipolar Ray Intersection

Also called: Lift 2D Points to 3D via Epipolar Lines, depth from 2D points, lift_to_3d / get_depth

## Overview
Epipolar Ray Intersection calculates the 3D positions corresponding to specified 2D points on epipolar lines by intersecting rays generated from those 2D points with given world-space rays. It solves the problem of lifting 2D image coordinates to 3D space in a multi-view geometry context, specifically when the 3D point must lie on the intersection of a ray from a target camera and a ray from a source camera (the epipolar constraint). It differs from [Orthographic (Parallel) Camera Ray Generation](1319-orthographic-parallel-camera-ray-generation.md) by using perspective projection and epipolar geometry rather than parallel projection, and from [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md) by computing the intersection of two specific rays rather than backprojecting a depth map value.

## How it works
**Inputs:**
1.  `xy`: Tensor of 2D points with shape `(N, 2)` representing pixel coordinates in the target camera frame.
2.  `extrinsics`: Tensor of shape `(N, 3, 4)` or `(N, 4, 4)` containing the world-to-camera transformation matrices for the source cameras.
3.  `intrinsics`: Tensor of shape `(N, 3, 3)` containing the camera intrinsic matrices for the source cameras.
4.  `origins`: Tensor of shape `(N, 3)` containing the origins of the world-space rays (typically from the target camera or a reference frame).
5.  `directions`: Tensor of shape `(N, 3)` containing the directions of the world-space rays.

**Outputs:**
1.  `xyz`: Tensor of shape `(N, 3)` containing the 3D intersection points.
2.  `depth` (optional): Tensor of shape `(N,)` containing the Euclidean distance from the ray origin to the intersection point.

**Data Structures:**
*   Points are represented as 3D vectors $(x, y, z)$.
*   Camera matrices are standard $3 \times 4$ projection matrices $P = K [R | t]$ or $4 \times 4$ transformation matrices.

**Steps:**

1.  **Generate Target Rays:** Convert the 2D points `xy` and the source camera parameters (`extrinsics`, `intrinsics`) into world-space ray origins and directions. This is typically done using a helper function `get_world_rays`.
    *   The ray origin for the target camera is the camera center derived from `extrinsics`.
    *   The ray direction is computed by unprojecting the 2D point `xy` using `intrinsics` and transforming it to world space using `extrinsics`.
    *   Let the resulting target ray origins be $O_{target}$ and directions be $D_{target}$.

2.  **Intersect Rays:** Intersect the input world-space rays (defined by `origins` $O_{src}$ and `directions` $D_{src}$) with the newly created target rays ($O_{target}, D_{target}$).
    *   The intersection is found by solving for the closest points between two skew lines in 3D space.
    *   Let the intersection point be $P$.

3.  **Compute Depth (Optional):** Calculate the depth as the L2 norm of the difference between the 3D intersection point $P$ and the ray origin $O_{src}$ along the last dimension.
    $$ \text{depth} = \| P - O_{src} \|_2 $$

**Pseudocode:**

```python
import torch
import torch.linalg

def get_world_rays(xy, extrinsics, intrinsics):
    """
    Converts 2D pixel coordinates to world-space rays.
    xy: (N, 2)
    extrinsics: (N, 3, 4) or (N, 4, 4)
    intrinsics: (N, 3, 3)
    Returns: origins (N, 3), directions (N, 3)
    """
    # Extract camera centers from extrinsics
    # Assuming extrinsics is 3x4 [R|t], center is -R^T * t
    if extrinsics.shape[-2] == 4:
        R = extrinsics[:, :3, :3]
        t = extrinsics[:, :3, 3]
    else:
        R = extrinsics[:, :3, :3]
        t = extrinsics[:, :3, 3]
        
    # Camera center in world space: C = -R^T * t
    origins = -torch.bmm(R.transpose(1, 2), t.unsqueeze(2)).squeeze(2)
    
    # Unproject 2D points to camera space
    # xy is (N, 2), pad to (N, 3) with 1
    xy_hom = torch.cat([xy, torch.ones_like(xy[:, :1])], dim=1) # (N, 3)
    
    # Invert intrinsics
    K_inv = torch.inverse(intrinsics) # (N, 3, 3)
    
    # Direction in camera space
    dir_cam = torch.bmm(K_inv, xy_hom.unsqueeze(2)).squeeze(2) # (N, 3)
    
    # Transform direction to world space
    directions = torch.bmm(R, dir_cam.unsqueeze(2)).squeeze(2) # (N, 3)
    
    return origins, directions

def intersect_rays(origins1, directions1, origins2, directions2):
    """
    Finds the midpoint of the common perpendicular between two rays.
    origins1, directions1: (N, 3)
    origins2, directions2: (N, 3)
    Returns: intersection points (N, 3)
    """
    # Vector between origins
    d_o = origins2 - origins1 # (N, 3)
    
    # Cross product of directions
    cross_d = torch.cross(directions1, directions2, dim=1) # (N, 3)
    cross_d_norm_sq = torch.sum(cross_d ** 2, dim=1, keepdim=True) # (N, 1)
    
    # Avoid division by zero for parallel rays
    cross_d_norm_sq = torch.clamp(cross_d_norm_sq, min=1e-8)
    
    # Project d_o onto the normal of the plane defined by the two directions
    # t1 = dot(d_o, cross(d2, n)) / |cross(d1, d2)|^2 ? 
    # Standard formula for closest points:
    # t1 = dot(d_o, cross(d2, cross(d1, d2))) / |cross(d1, d2)|^2
    # t2 = dot(d_o, cross(d1, cross(d1, d2))) / |cross(d1, d2)|^2
    
    # Let n = cross(d1, d2)
    # t1 = dot(d_o, cross(d2, n)) / dot(n, n)
    # t2 = dot(d_o, cross(d1, n)) / dot(n, n)
    
    n = cross_d
    n_sq = cross_d_norm_sq.squeeze(1)
    
    # cross(d2, n)
    cross_d2_n = torch.cross(directions2, n, dim=1)
    # cross(d1, n)
    cross_d1_n = torch.cross(directions1, n, dim=1)
    
    # Dot products
    dot1 = torch.sum(d_o * cross_d2_n, dim=1) # (N,)
    dot2 = torch.sum(d_o * cross_d1_n, dim=1) # (N,)
    
    t1 = dot1 / n_sq
    t2 = dot2 / n_sq
    
    # Closest points
    p1 = origins1 + directions1 * t1.unsqueeze(1)
    p2 = origins2 + directions2 * t2.unsqueeze(1)
    
    # Midpoint
    intersection = (p1 + p2) / 2.0
    
    return intersection

def epipolar_ray_intersection(xy, extrinsics, intrinsics, origins, directions):
    """
    Main function for Epipolar Ray Intersection.
    """
    # Step 1: Generate rays from 2D points
    xy_origins, xy_directions = get_world_rays(xy, extrinsics, intrinsics)
    
    # Step 2: Intersect with input world-space rays
    xyz = intersect_rays(origins, directions, xy_origins, xy_directions)
    
    # Step 3: Compute depth
    depth = torch.linalg.norm(xyz - origins, dim=1)
    
    return xyz, depth
```

**Parameters:**
*   `xy`: Pixel coordinates. Precision depends on input image resolution.
*   `extrinsics`, `intrinsics`: Camera parameters. Must be consistent with the coordinate system of `origins` and `directions`.

**Edge Cases and Pitfalls:**
*   **Parallel Rays:** If the two rays are parallel, the cross product of their directions is zero, leading to division by zero in the intersection formula. The implementation must clamp the denominator or handle parallel rays separately (e.g., by projecting one origin onto the other ray).
*   **Precision:** Floating-point errors in ray intersection can lead to small offsets. Using double precision for the intersection calculation may be necessary for high-accuracy applications.
*   **Boundary Conditions:** Points `xy` outside the image bounds will still generate rays, but the resulting 3D points may be irrelevant or cause artifacts if not filtered.

## Subtopics

### Depth Labeling on Epipolar Lines
This variant focuses on rendering depth labels along the epipolar line for visualization or debugging. It interpolates epipolar line endpoints in pixel space: $pt = \text{projection}["xy_{min}"] \cdot t + (1 - t) \cdot \text{projection}["xy_{max}"]$ for $t \in [0, 1]$. The depth is computed as the Euclidean distance from the camera center to the 3D point: $\text{depth} = \| xyz - \text{extrinsics}[0, :3, 3] \|$. The depth labels are then rendered along the epipolar line with white backer rectangles and rotated text [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of points, as the operations are vectorized per point.
*   **Memory Complexity:** $O(N)$ for storing the intermediate ray origins, directions, and intersection points.
*   **Strengths:** Provides geometrically consistent 3D points for multi-view stereo and volume rendering by enforcing epipolar constraints. Efficient on GPU due to vectorized operations.
*   **Limitations:** Sensitive to noise in camera parameters and 2D point detection. Fails or produces inaccurate results for parallel rays.
*   **When to use:** When lifting 2D points to 3D in a multi-view setting where the point must lie on the intersection of rays from different views.
*   **When not to use:** For single-view depth estimation (use [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md)) or when rays are known to be parallel.

## Background
Epipolar Ray Intersection is a fundamental technique in multi-view geometry, used in projects like VolSplat and PixelSplat for lifting 2D features to 3D space [S1, unofficial][S2, unofficial]. It builds on the principles of epipolar geometry, where corresponding points in two images lie on corresponding epipolar lines.
