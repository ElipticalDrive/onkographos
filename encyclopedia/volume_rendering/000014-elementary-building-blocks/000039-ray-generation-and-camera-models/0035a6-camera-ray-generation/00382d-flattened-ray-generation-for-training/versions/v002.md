# Flattened Ray Generation for Training

Also called: Ray Generation for Training Views

## Overview
Flattened Ray Generation for Training converts a set of 2D training images into a single, contiguous 1D tensor of 3D rays and corresponding color values [S1, unofficial]. It differs from [Camera Ray Generation](7456-camera-ray-generation.md) by aggregating all views into a unified flat structure suitable for stochastic gradient descent, and from [Sample Streaming Payload Ray Computation](1509-sample-streaming-payload-ray-computation.md) by pre-computing all rays in memory rather than computing them on-the-fly per batch [S1, S2, unofficial].

## How it works
**Inputs:**
- `rgb_tr`: List of training images with shape `[H, W, 3]` or `[3, H, W]` [S1, unofficial].
- `train_poses`: List of camera-to-world transformation matrices ($c2w$), shape `[N, 4, 4]` [S1, unofficial].
- `K`: Intrinsic camera matrix, shape `[3, 3]` [S1, unofficial].
- `H, W`: Height and width of the images [S1, unofficial].
- `ndc`: Boolean flag for Normalized Device Coordinates conversion [S1, unofficial].
- `inverse_y`, `flip_x`, `flip_y`: Boolean flags for coordinate system adjustments [S1, unofficial].
- `DEVICE`: Target device (e.g., `torch.device('cuda')`) [S1, unofficial].

**Outputs:**
- `rgb_tr`, `rays_o_tr`, `rays_d_tr`, `viewdirs_tr`: Flattened tensors of shape `[N, 3]` on `DEVICE` [S1, unofficial].

**Data Structures:**
- `N`: Total pixel count across all training images [S1, unofficial].
- Output tensors are 2D arrays of dtype `float32` [S1, unofficial].

**Steps:**
1. Calculate total pixels $N = \sum_{i=0}^{M-1} (H_i \times W_i)$, where $M$ is the number of training images [S1, unofficial].
2. Initialize output tensors `rgb_tr`, `rays_o_tr`, `rays_d_tr`, `viewdirs_tr` on `DEVICE` with shape `[N, 3]` [S1, unofficial].
3. Initialize `top = 0` and `imsz = []` [S1, unofficial]. Iterate over each training image $i$ from $0$ to $M-1$:
   a. Let $img$ be the $i$-th image and $c2w$ be the $i$-th pose [S1, unofficial].
   b. Compute `rays_o`, `rays_d`, `viewdirs` using camera parameters $H, W, K, c2w, ndc, inverse_y, flip_x, flip_y$ [S1, unofficial].
   c. Calculate $n = H \times W$ [S1, unofficial].
   d. Flatten $img$, `rays_o`, `rays_d`, `viewdirs` to shape `[n, 3]` and copy into the output tensors starting at `top`: `rgb_tr[top:top+n] = img.flatten(0,1)`, `rays_o_tr[top:top+n] = rays_o.flatten(0,1).to(DEVICE)`, `rays_d_tr[top:top+n] = rays_d.flatten(0,1).to(DEVICE)`, `viewdirs_tr[top:top+n] = viewdirs.flatten(0,1).to(DEVICE)` [S1, unofficial].
   e. Update `top += n` and append $n$ to `imsz` [S1, unofficial].

**Pseudocode:**
```python
import torch

def get_rays_of_a_view(H, W, K, c2w, ndc=False, inverse_y=False, flip_x=False, flip_y=False):
    """Standard camera ray generation helper [G].
    Computes ray origins, directions, and view directions for a single view."""
    i, j = torch.meshgrid(torch.arange(W, dtype=torch.float32), torch.arange(H, dtype=torch.float32), indexing='xy')
    if inverse_y:
        j = H - 1 - j
    if flip_x:
        i = W - 1 - i
    if flip_y:
        j = H - 1 - j
    dirs = torch.stack([(i - K[0, 2]) / K[0, 0], (j - K[1, 2]) / K[1, 1], torch.ones_like(i)], dim=-1)
    rays_d = torch.sum(dirs[..., None, :] * c2w[:3, :3], dim=-1)
    rays_o = c2w[:3, 3].expand_as(rays_d)
    viewdirs = rays_d / torch.norm(rays_d, dim=-1, keepdim=True)
    if ndc:
        # NDC coordinate conversion [G]
        pass
    return rays_o, rays_d, viewdirs

def get_training_rays_flatten(rgb_tr, train_poses, K, H, W, ndc=False, 
                              inverse_y=False, flip_x=False, flip_y=False, 
                              DEVICE='cuda'):
    """Flattens ray generation for all training views into single tensors [S1, unofficial]."""
    N = 0
    for img in rgb_tr:
        h, w = img.shape[0], img.shape[1] if img.shape[0] != 3 else img.shape[1], img.shape[2]
        N += h * w
        
    rgb_tr = torch.zeros((N, 3), dtype=torch.float32, device=DEVICE)
    rays_o_tr = torch.zeros((N, 3), dtype=torch.float32, device=DEVICE)
    rays_d_tr = torch.zeros((N, 3), dtype=torch.float32, device=DEVICE)
    viewdirs_tr = torch.zeros((N, 3), dtype=torch.float32, device=DEVICE)
    
    top = 0
    imsz = []
    
    for img, c2w in zip(rgb_tr, train_poses):
        rays_o, rays_d, viewdirs = get_rays_of_a_view(H, W, K, c2w, ndc, inverse_y, flip_x, flip_y)
        
        if img.shape[0] == 3:
            img_flat = img.permute(1, 2, 0).flatten(0, 1)
        else:
            img_flat = img.flatten(0, 1)
            
        n = H * W
        
        rgb_tr[top:top+n] = img_flat.to(DEVICE)
        rays_o_tr[top:top+n] = rays_o.flatten(0, 1).to(DEVICE)
        rays_d_tr[top:top+n] = rays_d.flatten(0, 1).to(DEVICE)
        viewdirs_tr[top:top+n] = viewdirs.flatten(0, 1).to(DEVICE)
        
        imsz.append(n)
        top += n
        
    return rgb_tr, rays_o_tr, rays_d_tr, viewdirs_tr
```

**Edge Cases and Pitfalls:**
- **Memory Exhaustion:** Precomputing all rays for high-resolution datasets can exhaust CPU RAM [S2, unofficial]. The code assumes `img_wh` is manageable (default 800x800) [S2, unofficial].
- **Coordinate System Mismatches:** Incorrect application of `inverse_y`, `flip_x`, or `flip_y` can lead to inverted or rotated rays, causing rendering artifacts [G].
- **Device Consistency:** Ensure all tensors are on the same device before training; mismatched devices will cause runtime errors [G].

## Subtopics

### Precomputed Ray Buffering
A variant that stores rays along with near/far plane distances and RGB values in a single concatenated tensor per image before final aggregation [S2, unofficial]. It computes rays via `get_rays(directions, c2w)` and concatenates `rays_o`, `rays_d`, `near`, and `far` into a tensor of shape `(h*w, 8)` [S2, unofficial]. This is appended to `self.all_rays` and `self.all_rgbs` [S2, unofficial]. After processing all images, these lists are concatenated into final tensors of shape `((N_images-1)*h*w, 8)` and `((N_images-1)*h*w, 3)` [S2, unofficial]. The layout of `self.all_rays` is `(B, 8)` with dtype `torch.float32`: columns 0-2 are ray origin, 3-5 are ray direction, 6 is near plane distance, and 7 is far plane distance [S2, unofficial]. `self.all_rgbs` is `(B, 3)` with normalized RGB values in `[0, 1]` [S2, unofficial]. A key pitfall is that precomputing all rays for high-resolution datasets can exhaust CPU RAM [S2, unofficial]. The code assumes `img_wh` is manageable (default 800x800) [S2, unofficial]. Validation and test splits bypass this buffer, computing rays on-the-fly per image to save memory [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the total number of pixels across all training images [G]. The cost is dominated by the per-pixel ray computation and flattening operations [S1, unofficial].
- **Memory Complexity:** $O(N \times D)$, where $D$ is the number of attributes per pixel (e.g., 3 for RGB, 3 for origin, 3 for direction, 3 for view direction = 12 floats per pixel) [G]. For high-resolution images, this can be substantial [S2, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of training images and resolution [G]. Memory usage is the primary bottleneck [S2, unofficial].
- **Strengths:** Enables efficient random sampling during training without repeated ray computation [S1, unofficial]. Simplifies batch handling in the training loop [S1, unofficial].
- **Limitations:** High memory consumption for large datasets [S2, unofficial]. Not suitable for very high-resolution images without chunking or on-the-fly computation [S2, unofficial].
- **When to use:** When training on a fixed set of moderate-resolution images and memory is sufficient [S2, unofficial].
- **When not to use:** When dealing with very high-resolution images or limited memory; consider on-the-fly ray generation instead [S2, unofficial].

## Background
Flattened Ray Generation for Training is a common practice in neural radiance field (NeRF) implementations, particularly in PyTorch-based frameworks [S1, unofficial]. It originates from the need to efficiently sample rays for stochastic gradient descent in volume rendering [S1, unofficial]. The method is widely used in projects like [UnboundedNeRFPytorch](https://github.com/sjtuytc/UnboundedNeRFPytorch) and [nerf_pl](https://github.com/kwea123/nerf_pl) [S1, S2, unofficial].
