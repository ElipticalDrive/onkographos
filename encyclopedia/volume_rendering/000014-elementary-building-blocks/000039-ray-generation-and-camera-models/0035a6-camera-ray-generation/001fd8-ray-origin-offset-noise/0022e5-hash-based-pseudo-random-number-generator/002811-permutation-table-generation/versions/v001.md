# Permutation Table Generation

Also called: perm table

## Overview
Generates a shuffled permutation table of size 512 using a seeded random shuffle, then duplicates the first 256 entries to avoid modulo operations during hash-based pseudo-random number generation. It serves as the foundational data structure for [Hash-based Pseudo-Random Number Generator](2896-hash-based-pseudo-random-number-generator.md), ensuring deterministic yet uniformly distributed indices for noise functions. Unlike [Deterministic Integer Hashing](4149-deterministic-integer-hashing.md) which computes hashes on the fly, this method pre-computes a lookup table, trading memory for computational speed and avoiding expensive bitwise operations or trigonometric functions during ray generation.

## How it works
**Inputs:**
- `seed`: Integer random seed passed to the constructor.

**Outputs:**
- `m_perm`: An integer array of size 512 containing a shuffled permutation of integers $0 \dots 255$, with the first half duplicated.

**Data Structures:**
- `m_perm`: `int[512]`. The array stores indices. The first 256 entries are a permutation of $0 \dots 255$. The next 256 entries are identical to the first 256.

**Parameters:**
- `SIZE`: Constant integer 256.

**Steps:**
1. Initialize the first `SIZE` entries of `m_perm` with the identity permutation:
   $$ m\_perm[i] = i \quad \text{for } i \in [0, SIZE-1] $$
2. Perform a Fisher-Yates shuffle on the first `SIZE` entries using the provided `seed` to generate pseudo-random numbers. Iterate `i` from `SIZE - 1` down to `1`:
   a. Generate a pseudo-random integer `j` in the range $[0, i]$ using the seeded RNG.
   b. Swap `m_perm[i]` and `m_perm[j]`.
3. Duplicate the shuffled first half to the second half to facilitate modulo-free indexing:
   $$ m\_perm[SIZE + i] = m\_perm[i] \quad \text{for } i \in [0, SIZE-1] $$

**Pseudocode:**
```python
def generate_permutation_table(seed, size=256):
    # Step 1: Initialize identity permutation
    perm = [i for i in range(size)]
    
    # Step 2: Fisher-Yates shuffle
    # Note: The specific PRNG implementation for Random.Range is assumed 
    # to be provided by the context of the Hash-based PRNG.
    # Here we assume a standard linear congruential generator or similar 
    # seeded RNG for the sake of completeness, though the source 
    # references a specific 'Random.Range' helper.
    rng = SeededRNG(seed)
    
    for i in range(size - 1, 0, -1):
        # Generate random index j in [0, i]
        j = rng.next_int(i + 1)
        
        # Swap elements
        perm[i], perm[j] = perm[j], perm[i]
        
    # Step 3: Duplicate first half to second half
    full_perm = perm + perm
    
    return full_perm
```

**Edge Cases and Pitfalls:**
- **Seed Collision:** Different seeds produce different permutations, but if the seed is not properly initialized, the table may be non-deterministic across runs.
- **Modulo Avoidance:** The duplication step is critical. When accessing the table with an index $k$, the code typically uses `perm[k & 255]` (bitwise AND) instead of `perm[k % 256]`. This requires the table to have at least 256 valid entries starting from index 0, which the duplication ensures. If the table were not duplicated, indices $256 \dots 511$ would be out of bounds or require modulo.
- **Precision:** The values in `m_perm` are integers. No floating-point precision issues arise during generation.

## Subtopics

### Permutation Table Texture Loading
Converts the CPU-side permutation array into GPU-readable textures for 1D and 2D noise lookups. The 1D permutation table is stored in a `Texture2D` of dimensions `(SIZE, 1)` with `Alpha8` format. The pixel at coordinate $(x, 1)$ is set to `Color(0, 0, 0, m_perm[x] / (SIZE - 1))`. This normalization maps the integer indices $0 \dots 255$ to the floating-point range $[0, 1]$ suitable for GPU texture sampling. This allows the noise function to be evaluated entirely on the GPU using texture lookups, which can be faster than computing hashes in shader code on some hardware architectures.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N=256$. The Fisher-Yates shuffle is linear. This is a one-time cost per seed.
- **Memory Complexity:** $O(N)$ integers. 512 integers = 2 KB. Negligible compared to volume data.
- **Performance:** Lookup is $O(1)$ with bitwise AND. Faster than computing sine/dot product hashes per sample.
- **Strengths:** Deterministic, fast lookup, avoids modulo operations.
- **Limitations:** Requires memory allocation for the table. Less flexible than on-the-fly hashing if the hash function needs to change dynamically.

## Background
Originated in the context of GPU-based marching cubes and noise generation, specifically in the [Scrawk/Marching-Cubes-On-The-GPU](https://github.com/Scrawk/Marching-Cubes-On-The-GPU) repository. It is a standard technique in procedural noise generation to provide a fast, deterministic way to map integer coordinates to pseudo-random values.
