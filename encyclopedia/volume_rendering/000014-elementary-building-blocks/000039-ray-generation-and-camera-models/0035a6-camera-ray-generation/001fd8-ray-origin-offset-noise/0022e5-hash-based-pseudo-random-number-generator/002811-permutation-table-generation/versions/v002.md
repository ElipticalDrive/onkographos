# Permutation Table Generation

Also called: perm table

## Overview
Generates a shuffled permutation table of size 512 using a seeded random shuffle, then duplicates the first 256 entries to avoid modulo operations [S1, unofficial]. It provides the lookup structure for [Hash-based Pseudo-Random Number Generator](2896-hash-based-pseudo-random-number-generator.md) [S1, unofficial].

## How it works
**Inputs:**
- `seed`: Integer random seed passed to the constructor [S1, unofficial].

**Outputs:**
- `m_perm`: Integer array of size 512 [S1, unofficial].

**Data Structures:**
- `m_perm`: `int[512]` [S1, unofficial].

**Parameters:**
- `SIZE`: Constant integer 256 [S1, unofficial].

**Steps:**
1. Initialize `m_perm[0..255]` with identity: `m_perm[i] = i` for `i` in `[0, SIZE-1]` [S1, unofficial].
2. Fisher-Yates shuffle: iterate `i` from `SIZE - 1` down to `1`, swap `m_perm[i]` with `m_perm[Random.Range(0, SIZE)]` [S1, unofficial].
3. Duplicate first 256 entries to indices 256-511: `m_perm[SIZE + i] = m_perm[i]` for `i` in `[0, SIZE-1]` [S1, unofficial].

**Pseudocode:**
```python
import random

def generate_permutation_table(seed, size=256):
    # Step 1: Initialize identity permutation
    perm = list(range(size))
    
    # Step 2: Fisher-Yates shuffle
    random.seed(seed)
    for i in range(size - 1, 0, -1):
        j = random.randint(0, size - 1)
        perm[i], perm[j] = perm[j], perm[i]
        
    # Step 3: Duplicate first half to second half
    return perm + perm
```

**Edge Cases and Pitfalls:**
The duplication step enables modulo-free indexing (e.g., `k & 255`) [S1, unofficial]. Not given in the sources for other pitfalls.

## Subtopics

### Permutation Table Texture Loading
Converts the CPU-side permutation array into GPU-readable textures for 1D and 2D noise lookups [S1, unofficial]. The 1D permutation table is stored in a `Texture2D` of dimensions `(SIZE, 1)` with `Alpha8` format [S1, unofficial]. The pixel at coordinate $(x, 1)$ is set to `Color(0, 0, 0, m_perm[x] / (SIZE - 1))` [S1, unofficial].

## Operating characteristics
Memory: 512 integers (2 KB) [S1, unofficial]. Generation time is $O(\text{SIZE})$ [G]. Lookup time is $O(1)$ [G]. Strengths include deterministic output and fast indexing [G]. Limitations include fixed table size [G].
