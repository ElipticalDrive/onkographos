# Ray Origin Offset Noise

Also called: Noise Generation for Ray Offset, Ray Offset Noise

## Overview
Ray Origin Offset Noise is a technique that perturbs the starting position of a ray march to avoid banding artifacts [S1, unofficial]. It differs from its sibling [Orthographic (Parallel) Camera Ray Generation](1319-orthographic-parallel-camera-ray-generation.md) by adding stochastic variation to the ray origin rather than strictly adhering to pixel centers, and from [Sample Streaming Payload Ray Computation](1509-sample-streaming-payload-ray-computation.md) by focusing on initialization jitter rather than payload management during traversal [G].

## How it works
**Inputs:**
- `uv`: A 2D vector representing the normalized screen or grid coordinates of the current sample [G].
- `unitVector`: A constant 2D vector used to break spatial correlation [G].

**Outputs:**
- `r`: A pseudo-random floating-point value in the range $[0, 1)$ [S1, unofficial].

**Data Structures:**
- No persistent data structures are required; the function is stateless and computes the random value on demand based on input coordinates [G].

**Steps:**
1. Scale `unitVector` by the constant `79.30408` [S1, unofficial].
2. Compute the dot product of `uv` and the scaled vector [S1, unofficial].
3. Apply the sine function to the dot product result [S1, unofficial].
4. Multiply the sine output by `43758.5453` [S1, unofficial].
5. Extract the fractional part of the product to yield `r` [S1, unofficial].

**Formula:**
$$ r = \text{fract}(\sin(\text{dot}(uv, \text{unitVector} \times 79.30408)) \times 43758.5453) $$

Where:
- $\text{dot}(a, b)$ is the dot product of vectors $a$ and $b$ [G].
- $\text{fract}(x) = x - \lfloor x \rfloor$ [G].
- $\text{unitVector}$ is a constant 2D vector; its specific components are not detailed in the source [G].

**Parameters:**
- `unitVector`: A constant 2D vector [G].
- `79.30408`: A constant scaling factor applied to `unitVector` [S1, unofficial].
- `43758.5453`: A constant multiplier [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** The use of sine and large constants can lead to precision issues on some hardware; intermediate calculations should maintain sufficient precision to avoid pattern repetition [G].
- **Correlation:** The choice of `unitVector` and the scaling factor is critical to minimize spatial correlation between adjacent samples [G].

**Pseudocode:**
```python
import math

def ray_origin_offset_noise(uv: tuple, unit_vector: tuple) -> float:
    """Generates a pseudo-random value to offset the ray origin."""
    scale = 79.30408
    dot_product = uv[0] * (unit_vector[0] * scale) + uv[1] * (unit_vector[1] * scale)
    sin_val = math.sin(dot_product)
    multiplied = sin_val * 43758.5453
    fractional_part = multiplied - math.floor(multiplied)
    return fractional_part
```

## Subtopics

### [Hash-based Pseudo-Random Number Generator](2896-hash-based-pseudo-random-number-generator.md)
A hash-based pseudo-random number generator maps integer or floating-point coordinates to a deterministic pseudo-random value in the range $[0, 1)$ or $[-1, 1]$ using transcendental functions (typically sine) or multiplicative mixing. It generates independent values based on spatial coordinates, ensuring that the same coordinate always yields the same random value across different frames and devices. Unlike [Incremental Random Number Generation](4898-incremental-random-number-generation.md), which generates a sequence of correlated random numbers for a single ray, this method computes values on demand from input coordinates.

### [Incremental Random Number Generation](4898-incremental-random-number-generation.md)
Incremental Random Number Generation is a method for producing pseudo-random numbers with low discrepancy properties, suitable for sampling in ray tracing and volume rendering. It differs from its parent [Ray Origin Offset Noise](2118-ray-origin-offset-noise.md) by using a deterministic additive sequence based on irrational constants rather than a hash function, and from its sibling [Hash-based Pseudo-Random Number Generator](2896-hash-based-pseudo-random-number-generator.md) by avoiding bitwise operations in favor of floating-point arithmetic. This approach ensures uniform distribution over iterations while maintaining statelessness across samples if the initial seed is managed externally.

### Deterministic LCG Noise Generation
A Linear Congruential Generator (LCG) producing deterministic pseudo-random floats in the range $[-1, 1)$ using Numerical Recipes constants, used for procedural sound synthesis [S2, unofficial].
**Steps:**
1. Update state: Multiply current state by 6,364,136,223,846,793,005 and add 1,442,695,040,888,963,407 using wrapping arithmetic (mod $2^{64}$) [S2, unofficial].
2. Extract top 24 bits: Shift state right by 40 bits and cast to f32 [S2, unofficial].
**Formula:**
$$ x_{n+1} = (x_n \times 6364136223846793005 + 1442695040888963407) \mod 2^{64} $$
$$ v = \left(\frac{x_n \gg 40}{8388608.0}\right) - 1.0 $$

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample; the computation involves a few arithmetic operations and a sine function [G].
- **Memory Complexity:** $O(1)$; no additional memory is required beyond the input coordinates [G].
- **Performance:** The method is efficient and suitable for real-time applications; the sine function is the most expensive operation, but modern GPUs optimize this well [G].
- **Strengths:** Simple to implement, deterministic, and effective at reducing banding artifacts [G].
- **Limitations:** The quality of the random numbers depends on the choice of constants; poorly chosen constants can lead to visible patterns [G].
- **When to use:** When banding artifacts are visible in volumetric rendering due to regular sampling patterns [G].
- **When not to use:** When high-quality, statistically independent random numbers are required for Monte Carlo integration, as this method is not designed for such purposes [G].

## Background
The technique is used to offset the starting position of the ray march to avoid banding artifacts [S1, unofficial]. It is a simple yet effective method for reducing aliasing and banding artifacts [G].
