# Ray Origin Offset Noise

Also called: Noise Generation for Ray Offset, Ray Offset Noise

## Overview
Ray Origin Offset Noise is a technique used in volume rendering to perturb the starting position of a ray march, thereby avoiding banding artifacts caused by the regular sampling grid [S1, unofficial]. It differs from sibling methods like [Orthographic (Parallel) Camera Ray Generation](1319-orthographic-parallel-camera-ray-generation.md) or [Camera Matrix Ray Generation](2172-camera-matrix-ray-generation.md), which define the geometric ray path, by adding a stochastic perturbation to the ray's origin or initial step [S1, unofficial]. This method is distinct from [Incremental Random Number Generation](4898-incremental-random-number-generation.md) because it typically relies on spatial hashing to ensure deterministic, uncorrelated values for each pixel or sample, rather than maintaining a continuous state [S1, S2, unofficial][S4].

## How it works
**Inputs:**
- `uv`: A 2D vector representing the normalized screen coordinates or spatial position of the sample/pixel.
- `unitVector`: A constant 2D vector used to break symmetry in the hash function.

**Outputs:**
- `r`: A pseudo-random floating-point value in the range $[0, 1)$.

**Data Structures:**
- No persistent data structures are required. The method is stateless and computes the random value on the fly from the input coordinates.

**Steps:**
1. Compute the dot product of the input coordinates `uv` and the scaled `unitVector`.
2. Apply the sine function to the result.
3. Multiply by the constant `43758.5453`.
4. Extract the fractional part of the result to obtain the random value.

**Formula:**
$$ r = \text{fract}(\sin(\text{dot}(uv, \text{unitVector} \times 79.30408)) \times 43758.5453) $$

Where:
- $\text{fract}(x) = x - \lfloor x \rfloor$
- $\text{dot}(a, b) = a_x b_x + a_y b_y$
- $\text{unitVector}$ is a constant 2D vector, typically chosen to be irrational or non-integer to minimize correlation (e.g., $(7.31, 2.13)$ or similar, though the specific vector is not defined in the source, only the scaling factor is provided) [S1, unofficial].
- The constant $79.30408$ scales the input vector.
- The constant $43758.5453$ is a multiplier that exploits the chaotic nature of the sine function's tail to produce a uniform distribution.

**Pseudocode:**
```python
def ray_origin_offset_noise(uv: Vector2, unit_vector: Vector2) -> float:
    """
    Generates a pseudo-random value in [0, 1) for ray origin offsetting.
    
    Args:
        uv: 2D coordinates (e.g., normalized pixel coordinates).
        unit_vector: 2D constant vector for hashing.
        
    Returns:
        A float in [0, 1).
    """
    # Scale the unit vector by the constant factor
    scaled_vector = unit_vector * 79.30408
    
    # Compute dot product
    dot_product = uv.x * scaled_vector.x + uv.y * scaled_vector.y
    
    # Apply sine
    sine_val = math.sin(dot_product)
    
    # Multiply by constant
    multiplied = sine_val * 43758.5453
    
    # Extract fractional part
    random_value = multiplied - math.floor(multiplied)
    
    return random_value
```

**Parameters:**
- `unitVector`: Not given in the sources. Typically a constant 2D vector.
- `79.30408`: Scaling factor for the dot product.
- `43758.5453`: Multiplier for the sine output.

**Edge Cases and Pitfalls:**
- **Precision:** The method relies on the precision of the sine function and floating-point arithmetic. In low-precision environments, the output may exhibit patterns or reduced randomness.
- **Boundary Conditions:** The method is stateless, so boundary conditions are handled by the input `uv`. However, if `uv` is not normalized or scaled appropriately, the randomness may not be uniform across the screen.
- **Correlation:** If `unitVector` is not chosen carefully (e.g., if it has integer components), the output may exhibit banding or correlation artifacts. The source implies the use of a specific constant scaling factor to mitigate this, but the vector itself is not specified [S1, unofficial].

## Subtopics

### [Hash-based Pseudo-Random Number Generator](2896-hash-based-pseudo-random-number-generator.md)
A hash-based pseudo-random number generator (PRNG) maps integer or floating-point coordinates to a deterministic pseudo-random value in the range $[0, 1)$ or $[-1, 1]$ using transcendental functions (typically sine) or bitwise/multiplicative mixing. It solves the problem of generating unique, seemingly random offsets for ray origins or noise sampling without storing large lookup tables, thereby avoiding banding artifacts in volume rendering. Unlike [Incremental Random Number Generation](4898-incremental-random-number-generation.md), which generates a sequence of correlated random numbers for a single ray, this method generates independent values based on spatial coordinates, ensuring that the same coordinate always yields the same random value across different frames and devices.

### [Incremental Random Number Generation](4898-incremental-random-number-generation.md)
Incremental Random Number Generation is a method for producing low-discrepancy pseudo-random sequences by iteratively adding an irrational constant to a state variable and taking the fractional part. It solves the problem of generating uniformly distributed samples with minimal correlation between consecutive iterations, which is critical for avoiding banding artifacts in ray marching. It differs from hash-based generators by maintaining a continuous state that evolves deterministically, ensuring that the sequence covers the sampling space more evenly (quasi-Monte Carlo properties) than standard linear congruential generators, while being computationally cheaper than complex hash functions.

### Deterministic LCG Noise Generation
A Linear Congruential Generator (LCG) producing deterministic pseudo-random floats in the range [-1, 1) using Numerical Recipes constants. Used for procedural sound synthesis [S2, unofficial].

**Steps:**
1. Update state: Multiply current state by 6,364,136,223,846,793,005 and add 1,442,695,040,888,963,407 using wrapping arithmetic (mod 2^64) [S2, unofficial].
2. Extract top 24 bits: Shift state right by 40 bits and cast to f32 [S2, unofficial].

**Formula:**
$$ x_{n+1} = (x_n \times 6364136223846793005 + 1442695040888963407) \mod 2^{64} $$
$$ v = \left(\frac{x_n \gg 40}{8388608.0}\right) - 1.0 $$

**Parameters:**
- Multiplier: 6,364,136,223,846,793,005 (u64) [S2, unofficial].
- Increment: 1,442,695,040,888,963,407 (u64) [S2, unofficial].
- State type: u64 [S2, unofficial].
- Output range: [-1.0, 1.0) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample. The computation involves a dot product, sine, multiplication, and fractional part extraction, all of which are constant-time operations.
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the input coordinates and constant values.
- **Performance:** The method is computationally inexpensive and suitable for real-time applications. The use of transcendental functions (sine) may be slightly more expensive than bitwise operations, but modern GPUs optimize these well.
- **Strengths:** Deterministic, stateless, easy to implement, avoids banding artifacts.
- **Limitations:** The quality of randomness depends on the choice of constants and input coordinates. May not provide high-quality randomness for applications requiring statistical rigor.
- **When to use:** When avoiding banding artifacts in volume rendering is critical and computational resources are limited.
- **When not to use:** When high-quality statistical randomness is required, or when the input coordinates are not available or meaningful.

## Background
The method originates from the need to improve the visual quality of volume rendering by reducing artifacts caused by regular sampling patterns. The specific formula using sine and fractional part extraction is a common technique in computer graphics for generating pseudo-random numbers from spatial coordinates [S1, unofficial]. It is widely used in real-time rendering engines and shaders.
