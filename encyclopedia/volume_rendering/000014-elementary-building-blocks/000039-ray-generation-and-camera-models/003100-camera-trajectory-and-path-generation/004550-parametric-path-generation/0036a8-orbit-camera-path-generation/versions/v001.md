# Orbit Camera Path Generation
Also called: Cyclic rotation rendering, Orbit rendering, Rotation Rendering
## Overview
Orbit Camera Path Generation creates a sequence of rendered images by rotating the camera around a specified axis to capture frames for video export [S1, unofficial]. It differs from [Spiral Camera Path Generation](1635-spiral-camera-path-generation.md) by maintaining a constant radius and elevation, providing a pure rotational view rather than a helical trajectory. It serves as a foundational method for generating turn-table videos used in downstream 3D reconstruction tasks [S2].
## How it works
**Inputs and Outputs**
- Input: A list of rotation angles `rotate_angles` (floats in degrees) and an axis identifier `rotate_axis` (integer 0, 1, or 2) [S1, unofficial].
- Output: A sequence of rendered images (video frames) [S1, unofficial].

**Data Structures**
- `rotate_angles`: A list of floats representing the cumulative or incremental rotation angles for each frame step [S1, unofficial].
- `rotate_axis`: An integer specifying the rotation axis: 0 for Elevation, 1 for Roll, 2 for Azimuth [S1, unofficial].

**Steps**
1. Initialize the rendering window and camera object [S1, unofficial].
2. Create a `vtkWindowToImageFilter` instance to convert the render window output to an image format [S1, unofficial].
3. Allocate a buffer `rendered_image` with shape `(len(rotate_angles), height, width, 3)` and type `uint8` [S1, unofficial].
4. For each angle `angle` in `rotate_angles` at index `i`:
    a. Apply the rotation to the camera using the method corresponding to `rotate_axis` (e.g., `Azimuth` for axis 2) [S1, unofficial].
    b. Mark the filter as modified and update it [S1, unofficial].
    c. Render the scene [S1, unofficial].
    d. Extract the image data from the filter output and convert it to a NumPy array [S1, unofficial].
    e. Store the array in `rendered_image[i]` [S1, unofficial].
    f. Reset the camera rotation by applying the inverse angle to return to the baseline orientation for the next step [S1, unofficial].

**Pseudocode**
```python
import numpy as np
import vtk

def generate_orbit_path(camera, window, rotate_angles, rotate_axis, width, height):
    """
    Generates an orbit camera path.
    
    Args:
        camera: VTK camera object.
        window: VTK render window object.
        rotate_angles: List of float angles in degrees.
        rotate_axis: Integer 0 (Elevation), 1 (Roll), 2 (Azimuth).
        width: Image width.
        height: Image height.
        
    Returns:
        rendered_image: NumPy array of shape (N, height, width, 3).
    """
    # Initialize filter
    image_filter = vtk.vtkWindowToImageFilter()
    image_filter.SetInput(window)
    image_filter.Update()
    
    # Allocate output buffer
    rendered_image = np.zeros((len(rotate_angles), height, width, 3), dtype=np.uint8)
    
    for i, angle in enumerate(rotate_angles):
        # Apply rotation based on axis
        if rotate_axis == 0:
            camera.Elevation(angle)
        elif rotate_axis == 1:
            camera.Roll(angle)
        elif rotate_axis == 2:
            camera.Azimuth(angle)
        else:
            raise ValueError("rotate_axis must be 0, 1, or 2")
            
        # Update and render
        image_filter.Modified()
        image_filter.Update()
        window.Render()
        
        # Extract image
        # Note: VTK output extraction details depend on specific window backend.
        # Assuming a helper function exists to convert VTK image to numpy array.
        rendered_image[i, :, :, :] = _image_to_numpy(image_filter.GetOutput())
        
        # Reset camera to baseline for next iteration
        if rotate_axis == 0:
            camera.Elevation(-angle)
        elif rotate_axis == 1:
            camera.Roll(-angle)
        elif rotate_axis == 2:
            camera.Azimuth(-angle)
            
    return rendered_image
```

**Parameters and Edge Cases**
- `rotate_axis`: Must be 0, 1, or 2. Values outside this range are invalid [S1, unofficial].
- Precision: Floating point angles are used. Accumulated errors are mitigated by resetting the camera rotation after each frame rather than accumulating rotations [S1, unofficial].
- Degenerate Input: Empty `rotate_angles` list results in an empty output array [S1, unofficial].

## Subtopics

### IM-3D
A method that finetunes an image-to-video model based on Emu to generate turn-table like videos rotating around an object [S2]. These generated videos are subsequently used as input for 3D Gaussian Splatting (3DGS) reconstruction [S2]. It differs from the standard VTK-based orbit rendering by being a generative AI approach rather than a geometric ray-casting one [S2].

## Operating characteristics
**Time and Memory Complexity**
- Time: Linear with respect to the number of frames $N$, i.e., $O(N)$, where each frame requires a full render pass [S1, unofficial].
- Memory: $O(N \cdot H \cdot W \cdot C)$ for storing the output video frames, where $H, W$ are dimensions and $C=3$ is channels [S1, unofficial].

**Strengths and Limitations**
- Strengths: Simple to implement using standard visualization toolkits like VTK; provides consistent, high-quality geometric views for 3D reconstruction [S1, unofficial][S2].
- Limitations: Requires explicit 3D scene data and rendering pipeline; not applicable for novel view synthesis from single images without underlying geometry [S1, unofficial].

**When to Use**
- Use when explicit 3D geometry is available and a turn-table video is needed for downstream tasks like 3DGS reconstruction [S2].
- Do not use when only a single image is available and no 3D model exists; use [Novel View Synthesis Rendering](6402-novel-view-synthesis-rendering.md) instead [S2].

## Background
Originated from standard computer graphics visualization techniques using VTK [S1, unofficial]. It has been adopted in recent 3D generative pipelines, such as IM-3D, to create training data for 3D Gaussian Splatting from single images via video generation [S2].
