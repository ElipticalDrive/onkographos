# Sparse Trajectory Generation
Also called: Mapping-based Trajectory Selection

## Overview
Sparse Trajectory Generation reduces a dense camera path to a subset of frames by filtering based on a predefined mapping file [S1, unofficial]. It differs from [Parametric Path Generation](11476-parametric-path-generation.md) by relying on discrete frame indices rather than continuous mathematical functions, and from [Synthetic Camera Trajectory Generation](7942-synthetic-camera-trajectory-generation.md) by acting as a post-processing filter rather than a generative model. This method is primarily used to select representative views for training or rendering, balancing computational cost against coverage [S1, unofficial].

## How it works
**Inputs and Outputs**
- Input: `f_trajectory`, a list of camera frames (e.g., poses, intrinsics); `mapping`, a list of entries where each entry contains a frame index.
- Output: `sparse_traj`, a list of camera frames corresponding to the selected indices.

**Data Structures**
- `f_trajectory`: A sequence of frame objects.
- `mapping`: A sequence of entries. Each entry `m` is structured such that `m[1]` holds the 1-based frame index.
- `sparse_traj`: A dynamic list of frame objects.

**Steps**
1. Initialize an empty list `sparse_traj`.
2. Iterate through each entry `m` in the `mapping` list.
3. Extract the frame index from `m[1]`. Convert this value to an integer.
4. Adjust for 0-based indexing by subtracting 1 from the extracted integer. Let this be `index`.
5. Retrieve the frame `f_trajectory[index]`.
6. Append the retrieved frame to `sparse_traj`.
7. Return `sparse_traj`.

**Pseudocode**
```python
def generate_sparse_trajectory(f_trajectory, mapping):
    sparse_traj = []
    for m in mapping:
        # m[1] contains the 1-based frame index
        frame_index_1_based = int(m[1])
        # Convert to 0-based index
        index = frame_index_1_based - 1
        # Append the corresponding frame
        sparse_traj.append(f_trajectory[index])
    return sparse_traj
```

**Parameters and Edge Cases**
- The mapping file format is assumed to be consistent with the source implementation [S1, unofficial].
- If `mapping` is empty, the result is an empty list.
- If `index` is out of bounds for `f_trajectory`, the behavior is undefined in the source; a robust implementation should check bounds [G].
- The source notes that for trajectory alignment tasks, if the trajectory length exceeds 1600 frames and a mapping file is provided, the input may be sparsified [S1, unofficial]. This specific threshold applies to the alignment variant, not necessarily the general generation method.

## Subtopics

### [Trajectory Alignment (RANSAC)](7876-trajectory-alignment-ransac.md)
Aligns a sparse camera trajectory to a ground truth trajectory using RANSAC-based point cloud registration. It handles sparse, potentially noisy inputs through iterative sampling and optionally sparsifies the input trajectory if a mapping file is provided and the trajectory length exceeds 1600 frames.

## Operating characteristics
- **Time Complexity**: Linear with respect to the size of the `mapping` list, $O(N)$, where $N$ is the number of entries in the mapping. List access is $O(1)$.
- **Memory Complexity**: Linear with respect to the number of selected frames, $O(K)$, where $K$ is the length of `sparse_traj`.
- **Strengths**: Simple to implement; computationally inexpensive; deterministic based on the mapping file.
- **Limitations**: Does not optimize for view coverage or redundancy; relies entirely on the quality of the provided mapping file.
- **When to use**: When a specific subset of frames is known a priori to be sufficient or required (e.g., from a previous analysis or manual selection).

## Background
The method originates from the implementation details of 2D Gaussian Splatting pipelines, specifically within the `hbb1/2d-gaussian-splatting` repository [S1, unofficial]. It is used in conjunction with training and rendering processes where managing the number of views is necessary for efficiency or specific regularization criteria.
