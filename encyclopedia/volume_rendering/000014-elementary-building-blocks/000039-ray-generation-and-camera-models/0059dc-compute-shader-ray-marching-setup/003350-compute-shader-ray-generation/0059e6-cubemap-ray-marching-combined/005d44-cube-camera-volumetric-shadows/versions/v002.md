# Cube Camera Volumetric Shadows


## Overview
A method to cast volumetric shadows in all directions from a single light source by using a CubeCamera to capture depth from six directions, overcoming the limitation of a single directional light camera [S1, unofficial]. Unlike the single-direction light camera approach which requires the light camera to point at the viewer to maximize shadow map coverage, the cube camera captures shadows in all directions but is considered a 'hack' with lower quality than other examples [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Scene geometry, light position, light far plane distance (`shadowFar`), cube render target dimensions (`SHADOW_MAP_SIZE`) [S1, unofficial].
*   **Output:** A cube texture containing normalized depth values in the red channel, used by the volumetric lighting effect's fragment shader [S1, unofficial].

**Data Structures:**
1.  **Cube Render Target:** Stores the depth data as a floating-point RGBA texture.
    *   Format: RGBA [S1, unofficial]
    *   Type: 32-bit float [S1, unofficial]
    *   Mipmaps: Disabled [S1, unofficial]
    *   Filtering: Linear [S1, unofficial]
    *   Depth Buffer: Enabled [S1, unofficial]
2.  **Cube Camera:** Captures the scene from six orthogonal directions.
    *   Near plane: `CUBE_CAMERA_NEAR` [S1, unofficial]
    *   Far plane: `CUBE_CAMERA_FAR` [S1, unofficial]
    *   Target: The cube render target [S1, unofficial]
3.  **Shadow Material:** A custom shader material used to render depth.
    *   Vertex Shader: Outputs `vWorldPosition` (world space position of the vertex) [S1, unofficial]
    *   Fragment Shader: Computes normalized distance to the light [S1, unofficial]
    *   Uniforms: `lightPosition` (vec3), `shadowFar` (float) [S1, unofficial]

**Steps:**
1.  Create a cube render target with the specified size, RGBA format, float type, no mipmaps, linear filtering, and depth buffer enabled [S1, unofficial].
2.  Initialize a cube camera with near and far clipping planes, targeting the created cube render target [S1, unofficial].
3.  Create a custom shadow material that calculates the linear distance from the vertex's world position to the light position [S1, unofficial].
4.  Normalize the distance to the range $[0, 1]$ by dividing by the shadow far plane and clamping the result [S1, unofficial].
5.  Output the normalized distance to the red channel of the fragment color, leaving other channels zero [S1, unofficial].
6.  Replace all scene object materials with the shadow material before rendering the cube camera snapshot [S1, unofficial].
7.  Render the scene using the cube camera to capture the depth texture [S1, unofficial].
8.  Restore the original scene materials after capturing the depth texture [S1, unofficial].
9.  Pass the resulting cube shadow map to the volumetric lighting effect's fragment shader to calculate shadows in all directions [S1, unofficial].

**Formulas:**
The normalized distance $d_{\text{norm}}$ for a fragment at world position $\mathbf{p}$ relative to light position $\mathbf{l}$ and far plane $F$ is:
$$ d_{\text{norm}} = \text{clamp}\left( \frac{\|\mathbf{p} - \mathbf{l}\|}{F}, 0.0, 1.0 \right) $$
In the provided implementation, the light position is assumed to be the origin or handled such that `length(vWorldPosition)` represents the distance [S1, unofficial].

**Pseudocode:**
```python
# Step 1: Setup Render Target
# Create a 6-face floating-point RGBA texture with specified dimensions, no mipmaps, linear filtering, and depth buffer
shadow_cube_render_target = allocate_cube_texture(
    size=SHADOW_MAP_SIZE,
    format=RGBA_FLOAT32,
    generate_mipmaps=False,
    min_filter=LINEAR,
    mag_filter=LINEAR,
    depth_buffer=True
)

# Step 2: Setup Cube Camera
# Create a camera that renders to all 6 faces of the target texture
shadow_cube_camera = create_cube_camera(
    near=CUBE_CAMERA_NEAR,
    far=CUBE_CAMERA_FAR,
    target=shadow_cube_render_target
)

# Step 3: Define Shadow Material
# Custom shader material that outputs normalized depth to the red channel
shadow_material = create_shader_material(
    vertex_shader="""
        varying vec3 vWorldPosition;
        void main() {
            vec4 worldPosition = modelMatrix * vec4(position, 1.0);
            vWorldPosition = worldPosition.xyz;
            gl_Position = projectionMatrix * viewMatrix * worldPosition;
        }
    """,
    fragment_shader="""
        uniform vec3 lightPosition;
        uniform float shadowFar;
        varying vec3 vWorldPosition;
        void main() {
            float distance = length(vWorldPosition - lightPosition);
            float normalizedDistance = clamp(distance / shadowFar, 0.0, 1.0);
            gl_FragColor = vec4(normalizedDistance, 0.0, 0.0, 1.0);
        }
    """,
    side=DUAL_SIDED,
    uniforms={
        "lightPosition": light_position_vector,
        "shadowFar": CUBE_CAMERA_FAR
    }
)

# Step 4: Render Depth
original_materials = []
for object in scene.objects:
    original_materials.append(object.material)
    object.material = shadow_material

# Render the scene from the cube camera's perspective
for face_index in range(6):
    shadow_cube_camera.set_active_face(face_index)
    renderer.render(scene, shadow_cube_camera)

# Step 5: Restore Scene
for i, object in enumerate(scene.objects):
    object.material = original_materials[i]
```

**Edge Cases and Pitfalls:**
*   **No Native Cube Depth Texture:** Three.js does not provide a native `CubeDepthTexture`, requiring a custom depth extraction method using a color buffer [S1, unofficial].
*   **Flickering Artifacts:** Shadow beams may flicker due to shadow map resolution. This is a side-effect of the resolution and tends to happen in scenes with a large number of objects occluding the light, even with simple geometries. Increasing the resolution stabilizes the effect [S1, unofficial].
*   **Performance:** Scaling to multiple light sources requires extra code for each new source (new light camera, new shadow FBO, passing textures/matrices, calculating shadows/scattering/accumulation) [S1, unofficial].
