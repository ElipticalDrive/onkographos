# Cubemap Ray Marching (Combined)
## Overview
Cubemap Ray Marching (Combined) is a compute shader dispatch setup method for rendering volumetric effects across a cube map environment [S1, unofficial]. It configures the required shader resources and dispatches the `CS_RAY_MARCH` kernel to process multiple cube map faces in parallel [S1, unofficial].
## How it works
**Inputs and Outputs:**
- **Inputs:** Per-object constant buffer, per-frame constant buffer, sample resolution constant buffer (`CB_SAMPLE_RES`), grid dimensions (`m_gridSize`), cube map LOD (`m_cubeMapLOD`), cube face count (`m_cubeFaceCount`), color shader resource view (SRV), optional spherical harmonic coefficient SRV (`m_coeffSH`), and optional cube face culling constant buffer view (CBV) controlled by `_CPU_CUBE_FACE_CULL_` [S1, unofficial].
- **Outputs:** Unordered Access View (UAV) for the cube map at the specified LOD [S1, unofficial].

**Data Structures:**
- `m_gridSize`: 3D vector containing the simulation grid dimensions [S1, unofficial].
- `m_cubeMapLOD`: Integer specifying the mip level for the cube map [S1, unofficial].
- `m_cubeFaceCount`: Integer specifying the number of cube map faces to process [S1, unofficial].
- `CB_SAMPLE_RES`: Constant buffer holding sample resolution parameters [S1, unofficial].

**Steps:**
1. Set the compute shader to `CS_RAY_MARCH` [S1, unofficial].
2. Bind the UAV for the cube map at LOD `m_cubeMapLOD` [S1, unofficial].
3. Bind CBVs for per-object, per-frame, and sample resolution (`CB_SAMPLE_RES`) [S1, unofficial].
4. Conditionally bind a CBV for cube face culling or a list if the `_CPU_CUBE_FACE_CULL_` macro is set to 1 or 2 [S1, unofficial].
5. Bind the SRV for colors at descriptor index 0 [S1, unofficial].
6. If `m_coeffSH` is present, bind the SRV for spherical harmonic coefficients at descriptor index 1 [S1, unofficial].
7. Bind a `LINEAR_CLAMP` sampler [S1, unofficial].
8. Calculate the compute shader dispatch group counts by shifting `m_gridSize.x` and `m_gridSize.y` right by `m_cubeMapLOD`, then dividing by 8 for the x and y group counts, while the z group count equals `m_cubeFaceCount` [S1, unofficial].
9. Dispatch the compute shader with the calculated group counts [S1, unofficial].

**Formulas:**
- $x_{\text{groups}} = \lfloor (m\_gridSize.x \gg m\_cubeMapLOD) / 8 \rfloor$
- $y_{\text{groups}} = \lfloor (m\_gridSize.y \gg m\_cubeMapLOD) / 8 \rfloor$
- $z_{\text{groups}} = m\_cubeFaceCount$
Where $\gg$ denotes a bitwise right shift [S1, unofficial].

**Parameters:**
- `m_gridSize.x`, `m_gridSize.y`: Grid dimensions [S1, unofficial].
- `m_cubeMapLOD`: Cube map LOD level [S1, unofficial].
- `m_cubeFaceCount`: Number of cube faces [S1, unofficial].
- `_CPU_CUBE_FACE_CULL_`: Macro controlling face culling behavior (1 or 2) [S1, unofficial].
- Typical values: Not given in the sources.

**Edge Cases:**
- If `m_coeffSH` is not present, the SRV for spherical harmonic coefficients is skipped [S1, unofficial].
- The face culling CBV is only bound when `_CPU_CUBE_FACE_CULL_` equals 1 or 2 [S1, unofficial].
- Division by 8 assumes a thread group width of 8; if the hardware group size differs, the divisor must match the actual thread group dimensions [G].

**Pseudocode:**
```python
def setup_cubemap_ray_marching(m_gridSize, m_cubeMapLOD, m_cubeFaceCount, _CPU_CUBE_FACE_CULL_, m_coeffSH_present):
    # 1. Set compute shader to CS_RAY_MARCH
    active_shader = "CS_RAY_MARCH"

    # 2. Bind UAV for cube map at specific LOD
    uav_state = {"resource": "cube_map", "lod": m_cubeMapLOD}

    # 3. Bind CBVs for per-object, per-frame, and sample resolution
    cbv_state = [
        {"type": "per_object"},
        {"type": "per_frame"},
        {"type": "sample_resolution", "name": "CB_SAMPLE_RES"}
    ]

    # 4. Conditionally bind CBV for cube face culling
    if _CPU_CUBE_FACE_CULL_ in (1, 2):
        cbv_state.append({"type": "cube_face_culling"})

    # 5. Bind SRV for colors at index 0
    srv_state = [{"index": 0, "type": "colors"}]

    # 6. Bind SRV for spherical harmonic coefficients at index 1 if present
    if m_coeffSH_present:
        srv_state.append({"index": 1, "type": "sh_coefficients"})

    # 7. Bind LINEAR_CLAMP sampler
    sampler_state = {"filter": "LINEAR_CLAMP"}

    # 8. Calculate dispatch group counts
    x_raw = m_gridSize.x >> m_cubeMapLOD
    y_raw = m_gridSize.y >> m_cubeMapLOD
    x_groups = x_raw // 8
    y_groups = y_raw // 8
    z_groups = m_cubeFaceCount

    # 9. Dispatch compute shader
    dispatch_groups = (x_groups, y_groups, z_groups)
```

### [Cube Camera Volumetric Shadows](17333-cube-camera-volumetric-shadows.md)
A method to cast volumetric shadows in all directions from a single light source by using a CubeCamera to capture depth from six directions, overcoming the limitation of a single directional light camera. Unlike the single-direction light camera approach which requires the light camera to point at the viewer to maximize shadow map coverage, the cube camera captures shadows in all directions but is considered a 'hack' with lower quality than other examples.
