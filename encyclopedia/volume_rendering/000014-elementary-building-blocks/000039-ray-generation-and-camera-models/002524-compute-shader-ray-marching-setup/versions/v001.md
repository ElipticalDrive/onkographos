# Compute Shader Ray Marching Setup

Also called: Ray Marching Setup

## Overview
This method initializes the compute shader pipeline for volumetric ray marching, specifically handling camera ray reconstruction from screen coordinates to world space and setting up the data structures for density accumulation [S1, unofficial]. It differs from generic ray generation by tightly coupling the ray setup with the specific requirements of a two-stage marching algorithm (empty-space skipping followed by density accumulation) and procedural noise integration [S1, unofficial]. It serves as the foundation for evaluating volumetric effects like smoke over a camera feed [S1, unofficial].

## How it works
**Inputs:**
- Screen resolution (`Screen.width`, `Screen.height`) [S1, unofficial].
- Camera matrices: `_CamToWorldMatrix` (world space transform) and `_invProjectionMatrix` (inverse projection) [S1, unofficial].
- Camera position: `camPosWS` (world space eye position) [S1, unofficial].
- Volume parameters: `_RayMaxLength` (default 50.0), density smoothing, and density multiplier [S1, unofficial].
- Noise texture: `RWTexture2D` containing Worley noise [S1, unofficial].
- Voxel grid: `ComputeBuffer` representing the occupancy grid [S1, unofficial].

**Outputs:**
- `RWTexture2D<float4> _ResultTexture`: ARGB64 format, linear color space, random write enabled, storing the accumulated smoke color [S1, unofficial].

**Data Structures:**
1. **Voxel Grid:** Flattened 3D array stored in a `ComputeBuffer`. Indexing formula: `index = z * (X * Y) + y * X + x`, where $X, Y, Z$ are grid dimensions [S1, unofficial]. Out-of-bounds access returns `-1` to distinguish empty space from volume boundaries [S1, unofficial].
2. **Noise Texture:** `RWTexture2D` storing Worley noise values, sampled per pixel [S1, unofficial].
3. **Result Texture:** `RWTexture2D<float4>` for final compositing [S1, unofficial].

**Steps:**
1. **Resolution Calculation:** Compute render resolution by dividing screen dimensions by 8 and rounding up:
   $$ width = \lceil \frac{\text{Screen.width}}{8} \rceil, \quad height = \lceil \frac{\text{Screen.height}}{8} \rceil $$
   [S1, unofficial].
2. **Texture Initialization:** Create `_ResultTexture` with dimensions `width` $\times$ `height`, format `ARGB64`, and linear color space [S1, unofficial].
3. **Matrix Setup:** Pass `_CamToWorldMatrix` and `_invProjectionMatrix` to the compute shader [S1, unofficial].
4. **Camera Position:** Set `camPosWS` to the camera's transform position [S1, unofficial].
5. **Dispatch:** Launch the compute shader kernel with thread groups:
   $$ \text{groups}_x = \frac{\text{smokeTexture.width}}{8}, \quad \text{groups}_y = \frac{\text{smokeTexture.height}}{8}, \quad \text{groups}_z = 1 $$
   [S1, unofficial].

**Per-Pixel Ray Reconstruction (Compute Shader Kernel):**
Each thread processes one pixel (or sub-pixel block).
1. **UV to NDC:** Convert thread ID `id.xy` to normalized device coordinates (NDC):
   $$ uv = \frac{id.xy}{(\text{_TextureWidth}, \text{_TextureHeight})} $$
   $$ ndcCS = (uv.x \cdot 2 - 1, \quad uv.y \cdot 2 - 1, \quad 0, \quad 1) $$
   [S1, unofficial].
2. **View Space Direction:** Transform NDC to view space direction using the inverse projection matrix:
   $$ \mathbf{viewDir} = \text{normalize}(\text{mul}(\text{_invProjectionMatrix}, ndcCS).xyz) $$
   [S1, unofficial].
3. **World Space Direction:** Transform view direction to world space:
   $$ \mathbf{rayVector} = \text{normalize}(\text{mul}(\text{_CamToWorldMatrix}, (0, 0, 0, 0) + \mathbf{viewDir}).xyz) $$
   Note: The source code uses `mul(_CamToWorldMatrix, float4(viewDir, 0))` which treats `viewDir` as a vector (w=0) [S1, unofficial].
4. **Ray Origin:** Set $\mathbf{o} = \text{camPosWS}$ [S1, unofficial].

**Two-Stage Marching:**
1. **Stage 1 (Empty-Space Skipping):**
   - Initialize `length = 0`, `stepSize` (not explicitly defined, assumed small constant), `smokeValue = 0`.
   - Loop while `smokeValue <= 0` and `length < _RayMaxLength`:
     $$ \text{length} += \text{stepSize} $$
     $$ \mathbf{positionWS} = \mathbf{o} + \text{length} \cdot \mathbf{rayVector} $$
     $$ \text{smokeValue} = \text{getSmokeVoxel}(\mathbf{positionWS}) $$
   - `getSmokeVoxel` performs the voxel lookup using the flattening formula and returns `-1` if out of bounds [S1, unofficial].
2. **Stage 2 (Density Accumulation):**
   - Begins only if Stage 1 found a non-empty voxel.
   - Accumulates density over a fixed number of steps (e.g., 40 steps) [S1, unofficial].
   - **Pitfall:** Stage 2 ignores volume bounds, potentially bleeding smoke past the grid [S1, unofficial].
   - **Pitfall:** Noise is sampled using screen-space UVs (`uv`) instead of world-space position, causing the noise pattern to swim across the smoke as the camera moves [S1, unofficial]. The correct approach is 3D world-space noise sampling [S1, unofficial].

**Pseudocode:**
```python
# Compute Shader Kernel
kernel void RayMarchingSetup(uint3 id : SV_DispatchThreadID) {
    // 1. UV to NDC
    float2 uv = id.xy / float2(_TextureWidth, _TextureHeight);
    float4 ndcCS = float4(uv.x * 2 - 1, uv.y * 2 - 1, 0, 1);
    
    // 2. View Space Direction
    float3 viewDir = mul(_invProjectionMatrix, ndcCS).xyz;
    
    // 3. World Space Direction
    float3 rayVector = normalize(mul(_CamToWorldMatrix, float4(viewDir, 0)).xyz);
    
    // 4. Ray Origin
    float3 origin = camPosWS;
    
    // 5. Stage 1: Empty-Space Skipping
    float length = 0.0;
    float stepSize = 0.1; // Assumed constant, not given in sources
    float smokeValue = 0.0;
    
    while (smokeValue <= 0 && length < _RayMaxLength) {
        length += stepSize;
        float3 positionWS = origin + length * rayVector;
        smokeValue = getSmokeVoxel(positionWS);
    }
    
    // 6. Stage 2: Density Accumulation (if inside volume)
    float4 result = float4(0, 0, 0, 0);
    if (smokeValue > 0) {
        float density = 0.0;
        for (int i = 0; i < 40; i++) { // Fixed steps, ignores bounds [S1, unofficial]
            float3 samplePoint = origin + length * rayVector;
            // Bug: Using screen UV for noise instead of world position
            float noiseValue = _NoiseTexture[uint2(uv.x * _NoiseResolution.x, uv.y * _NoiseResolution.y)].r;
            // Correct approach would be: sampleNoise3D(samplePoint)
            
            float voxelDensity = getSmokeVoxel(samplePoint);
            density += voxelDensity * noiseValue;
            length += stepSize;
        }
        result = float4(density, density, density, 1.0);
    }
    
    _ResultTexture[id.xy] = result;
}
```

## Operating characteristics
- **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of pixels (screen resolution / 64 due to 8x8 dispatch) and $M$ is the maximum ray length steps. Stage 1 is $O(M)$ worst-case, Stage 2 is $O(40)$ fixed.
- **Memory Complexity:** $O(V)$ for the voxel grid and $O(P)$ for the noise and result textures, where $V$ is voxel count and $P$ is pixel count.
- **Performance:** The two-stage approach optimizes performance by skipping empty space, paying only for cheap occupancy tests until the volume is entered [S1, unofficial].
- **Strengths:** Efficient for sparse volumes; integrates procedural noise directly on GPU [S1, unofficial].
- **Limitations:** Screen-space noise sampling causes visual artifacts (swimming noise) [S1, unofficial]. Stage 2 ignores volume bounds, leading to bleeding [S1, unofficial]. Fixed step count in Stage 2 may not adapt to varying density [S1, unofficial].

## Background
This method originates from a GitHub repository by Schokolasbotter, demonstrating a volumetric smoke raymarching technique using Unity Compute Shaders [S1, unofficial]. It combines voxel occupancy grids with procedural Worley noise to create animated smoke effects composited over a camera feed [S1, unofficial].
