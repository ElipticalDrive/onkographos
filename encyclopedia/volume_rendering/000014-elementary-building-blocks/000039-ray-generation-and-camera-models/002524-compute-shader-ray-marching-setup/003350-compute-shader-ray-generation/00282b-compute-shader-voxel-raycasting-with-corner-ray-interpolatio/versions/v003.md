# Compute Shader Voxel Raycasting with Corner Ray Interpolation

Also called: Corner Ray Interpolation Raycasting

## Overview
This method generates view rays for each framebuffer pixel by bilinearly interpolating four pre-computed world-space corner rays of the camera's view frustum, then traces them through a 3D voxel or Sparse Voxel Octree (SVO) texture to produce a color image [S1, unofficial]. It differs from standard perspective projection by avoiding per-pixel matrix-vector multiplication for ray direction generation, instead relying on spatial interpolation of boundary vectors [S1, unofficial].

## How it works
**Inputs and Outputs:**
* **Inputs:** Integer pixel coordinates `px` (from `gl_GlobalInvocationID.xy`), camera eye position `eye`, four world-space corner direction vectors (`ray00`, `ray01`, `ray10`, `ray11`) defining the frustum corners, framebuffer dimensions `size`, and a 3D voxel texture containing the scene data [S1, unofficial].
* **Outputs:** An RGB color with alpha 1.0 stored in the framebuffer image at `px` [S1, unofficial].

**Data Structures:**
* **Voxel Texture:** A 3D OpenGL texture (`GL_TEXTURE_3D`) storing the SVO or volume data, uploaded via `SVO.uploadTexture(textureSize, svo.getTextureData())` [S1, unofficial].
* **Framebuffer:** An OpenGL image (`framebufferImage`) bound at a specific binding point for write access via `imageStore` [S1, unofficial].
* **Uniforms:** `textureSize` is a `vec3` uniform set to `(texSize, 1.0/texSize, 1.0/(2.0*texSize))`, providing the texture resolution and its reciprocals for coordinate normalization [S1, unofficial]. `invNumberOfIndGrids` is a float uniform set to `2.0 / texSize`, used to scale indirection grid lookups [S1, unofficial].

**Algorithm Steps:**
1. **Boundary Check:** Determine the framebuffer `size` using the built-in `imageSize` function [S1, unofficial]. If the current global invocation ID `px` exceeds `size` in any dimension, terminate the shader execution to prevent out-of-bounds memory access [S1, unofficial].
2. **Normalize Pixel Coordinate:** Calculate the normalized pixel coordinate `p` in the interval $(0, 1)$ by adding $0.5$ to the integer pixel index `px`, casting to `vec2`, and dividing by the framebuffer `size` [S1, unofficial]:
   $$ p = \frac{\text{vec2}(px) + \text{vec2}(0.5)}{\text{vec2}(size)} $$
3. **Interpolate Ray Direction:** Compute the world-space ray direction `dir` by bilinearly interpolating the four corner rays using `p.x` and `p.y` [S1, unofficial]:
   $$ \text{dir} = \text{mix}(\text{mix}(\text{ray00}, \text{ray01}, p.y), \text{mix}(\text{ray10}, \text{ray11}, p.y), p.x) $$
   Here, `ray00`, `ray01`, `ray10`, and `ray11` represent the world-space direction vectors from the eye to the four corners of the view frustum [S1, unofficial].
4. **Normalize Direction:** Normalize the interpolated `dir` vector to ensure it is a unit vector [S1, unofficial]. This is critical because the bilinearly interpolated direction is not guaranteed to be of unit length, and normalization ensures consistent step sizes or intersection calculations during tracing [S1, unofficial].
5. **Trace Ray:** Trace the ray starting at the `eye` position along the normalized `dir` through the voxel texture [S1, unofficial]. The traversal samples the 3D texture and accumulates color until an opaque voxel is found or the maximum depth is reached [S1, unofficial].
6. **Store Result:** Store the resulting RGB color with an alpha of 1.0 into the framebuffer image at the current pixel index `px` [S1, unofficial].

**Pseudocode:**
```python
def main():
    px = gl_GlobalInvocationID.xy
    size = framebuffer_image.shape  # [S1, unofficial]
    if px[0] >= size[0] or px[1] >= size[1]:
        return  # [S1, unofficial]

    p = (np.array(px, dtype=float) + 0.5) / size  # [S1, unofficial]
    dir = mix(mix(ray00, ray01, p[1]), mix(ray10, ray11, p[1]), p[0])  # [S1, unofficial]
    dir = normalize(dir)  # [S1, unofficial]

    color = trace(eye, dir)  # [S1, unofficial]
    # The internal ray traversal and texture sampling logic is not given in the sources. [G]

    framebuffer_image[px[0], px[1]] = np.array([color[0], color[1], color[2], 1.0])  # [S1, unofficial]
```
*Note:* `mix`, `normalize`, and vector arithmetic are standard math/vector operations [G]. `gl_GlobalInvocationID.xy` provides the pixel coordinates [S1, unofficial].

**Edge Cases and Pitfalls:**
* **Non-Unit Direction:** The interpolated `dir` vector is not guaranteed to be unit length [S1, unofficial]. Failing to normalize it before tracing can lead to incorrect step sizes in the ray marching algorithm or inaccurate intersection calculations [S1, unofficial].
* **Out-of-Bounds Execution:** Compute shaders often require work group sizes that are powers of two [S1, unofficial]. If the framebuffer dimensions are not powers of two, extra work items may be launched [S1, unofficial]. A boundary check against `imageSize` is required to prevent writing to unallocated memory [S1, unofficial].
