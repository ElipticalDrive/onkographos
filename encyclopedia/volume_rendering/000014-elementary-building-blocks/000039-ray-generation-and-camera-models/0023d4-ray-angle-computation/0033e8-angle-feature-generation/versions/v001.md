# Angle Feature Generation
## Overview
Angle Feature Generation creates geometric features based on the angular relationship between rays and camera positions for multi-view stereo rendering [S1, unofficial]. It builds on [Ray Angle Computation](3156-ray-angle-computation.md) by converting angular differences into explicit feature vectors that encode viewing geometry. Unlike Direction Feature Generation, which relies on coordinate transformation, this method explicitly computes the dot product between ray directions to capture angular similarity [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: Ray directions from the reference camera ($\mathbf{d}_{ref}$), ray directions from source/training cameras ($\mathbf{d}_{src}$), and camera positions if required for direction normalization [S1, unofficial].
- Output: A feature vector containing the computed angle features (dot products) [S1, unofficial].

**Data Structures:**
- Feature vector: A 1D array or tensor where each element corresponds to a computed angular metric (e.g., dot product) for a specific source view [S1, unofficial].
- Ray directions: 3D unit vectors representing the direction of the ray in world or camera space [S1, unofficial].

**Steps:**
1. **Compute Directions:** Determine the direction vectors from the camera centers to the ray points. For a ray originating at camera center $\mathbf{C}$ and passing through point $\mathbf{P}$, the direction is $\mathbf{d} = \frac{\mathbf{P} - \mathbf{C}}{\|\mathbf{P} - \mathbf{C}\|}$ [S1, unofficial].
2. **Compute Dot Products:** Calculate the dot product between the reference ray direction $\mathbf{d}_{ref}$ and each source ray direction $\mathbf{d}_{src}$. The angle feature $f$ is given by:
   $$ f = \mathbf{d}_{ref} \cdot \mathbf{d}_{src} $$
   This value represents the cosine of the angle between the two rays [S1, unofficial].
3. **Aggregate Features:** Collect these dot products for all source views to form the final angle feature vector [S1, unofficial].

**Parameters:**
- Number of source views: Determines the length of the output feature vector [S1, unofficial].
- Normalization: Directions are typically normalized to unit length before dot product computation [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Zero-length rays:** If the point coincides with the camera center, the direction is undefined. Guard against division by zero [G].
- **Precision:** Dot products are sensitive to floating-point precision; ensure directions are normalized [G].
- **Boundary conditions:** Ensure consistent coordinate system conventions between reference and source cameras [S1, unofficial].

**Pseudocode:**
```python
import torch
import math

def compute_angle_features(ref_cam_pos, ref_cam_rot, src_cam_pos, src_cam_rot, point):
    """
    Compute angle features based on dot products between ray directions.
    
    Args:
        ref_cam_pos: (3,) tensor, reference camera position in world space
        ref_cam_rot: (3, 3) tensor, reference camera rotation matrix (world to camera)
        src_cam_pos: (N, 3) tensor, source camera positions in world space
        src_cam_rot: (N, 3, 3) tensor, source camera rotation matrices
        point: (3,) tensor, 3D point in world space
        
    Returns:
        features: (N,) tensor, angle features (dot products)
    """
    # Step 1: Compute reference ray direction in world space
    # Direction from ref camera to point
    ref_dir_world = point - ref_cam_pos
    ref_dir_world = ref_dir_world / torch.norm(ref_dir_world)
    
    # Transform to reference camera coordinate system
    ref_dir_cam = torch.matmul(ref_cam_rot, ref_dir_world)
    
    features = []
    for i in range(len(src_cam_pos)):
        # Step 1: Compute source ray direction in world space
        src_dir_world = point - src_cam_pos[i]
        src_dir_world = src_dir_world / torch.norm(src_dir_world)
        
        # Transform to reference camera coordinate system for consistent comparison
        # Note: The source method description implies computing directions from camera centers to ray points.
        # To compute the angle between rays, we need them in the same coordinate system.
        # The reference method computes dot product between directions.
        # We transform source direction to reference camera frame.
        src_dir_cam = torch.matmul(ref_cam_rot, src_dir_world)
        
        # Step 2: Compute dot product
        dot_product = torch.dot(ref_dir_cam, src_dir_cam)
        features.append(dot_product)
        
    return torch.stack(features)
```
## Subtopics

### Direction Feature Generation
Generates features based on the direction of rays in the reference camera coordinate system [S1, unofficial]. It sets itself apart by transforming ray directions using the world-to-camera rotation matrix rather than computing dot products between multiple rays [S1, unofficial]. Choose this method when explicit angular similarity metrics are less important than absolute directional encoding in the reference frame [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(N)$ where $N$ is the number of source views, due to the loop over source cameras [S1, unofficial].
- Memory: $O(N)$ for storing the feature vector [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Linear scaling with the number of source views [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Simple to implement; provides explicit angular information [S1, unofficial].
- Limitations: Sensitive to noise in point positions; requires accurate camera poses [S1, unofficial].

**When to Use:**
- Use when angular relationships between views are critical for feature matching [S1, unofficial].
- Avoid when computational efficiency is paramount and directional encoding suffices [S1, unofficial].
## Background
Originated in the context of multi-view stereo rendering, specifically in implementations like PointNeRF [S1, unofficial]. It is used to enhance geometric understanding in neural rendering by providing explicit angular features [S1, unofficial].
