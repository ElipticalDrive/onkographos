# Epipolar Ray Intersection

Also called: Epipolar 3D Lifting and Depth Computation, Get Depth, Lift 2D Points to 3D via Epipolar Lines, Lift to 3D, depth from 2D points, lift_to_3d / get_depth

## Overview
Epipolar Ray Intersection lifts 2D image points to 3D space by intersecting rays projected from those points with a set of input world-space rays, computing the resulting 3D positions and depths [S1, unofficial][S2, unofficial][S3, unofficial]. It differs from [Camera Ray Generation](7456-camera-ray-generation.md) by specifically solving for the intersection between a user-defined set of rays and rays derived from 2D pixel coordinates, rather than generating primary camera rays from scratch. It is distinct from [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md) because it relies on ray-ray intersection geometry rather than explicit backprojection of a depth map, and from [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing on the geometric lifting step without implicit field refinement [S1, unofficial][S2, unofficial][S3, unofficial].

## How it works
**Inputs:**
- `origins`: Float tensor of shape `(*#batch, 3)`, representing ray origins in world space [S1, unofficial].
- `directions`: Float tensor of shape `(*#batch, 3)`, representing ray directions in world space [S1, unofficial].
- `xy`: Float tensor of shape `(*#batch, 2)`, representing 2D image coordinates [S1, unofficial].
- `extrinsics`: Float tensor of shape `(*#batch, 4, 4)`, camera extrinsic matrices [S2, unofficial][S3, unofficial].
- `intrinsics`: Float tensor of shape `(*#batch, 3, 3)`, camera intrinsic matrices [S2, unofficial][S3, unofficial].

**Outputs:**
- `xyz`: Float tensor of shape `(*#batch, 3)`, the 3D intersection points [S2, unofficial][S3, unofficial].
- `depth`: Float tensor of shape `(*#batch)`, the distance from the ray origin to the intersection point [S1, unofficial][S3, unofficial].

**Data Structures:**
- `xy_origins`: Float tensor of shape `(*#batch, 3)`, computed ray origins for the 2D points in world space.
- `xy_directions`: Float tensor of shape `(*#batch, 3)`, computed ray directions for the 2D points in world space.

**Steps:**
1. **Compute World Rays from 2D Points:** Convert the 2D image coordinates `xy` and camera parameters (`extrinsics`, `intrinsics`) into world-space ray origins and directions. This is typically done using a helper function `get_world_rays` [S1, unofficial][S2, unofficial][S3, unofficial].
   - Let `xy_origins, xy_directions = get_world_rays(xy, extrinsics, intrinsics)` [S1, unofficial][S2, unofficial].
   - *Note:* Before intersection, it is common to validate that `xy` is within bounds (e.g., `xy >= -epsilon` and `xy <= 1 + epsilon`) and that the resulting Z-coordinate in camera space is positive (in front of the camera) [S3, unofficial].

2. **Intersect Rays:** Intersect the input world-space rays (`origins`, `directions`) with the newly created rays from the 2D points (`xy_origins`, `xy_directions`) [S1, unofficial][S2, unofficial][S3, unofficial].
   - Let `xyz = intersect_rays(origins, directions, xy_origins, xy_directions)` [S1, unofficial][S2, unofficial].
   - The intersection of two rays in 3D space is generally found by minimizing the distance between them. If the rays are skew, the intersection point is the midpoint of the shortest segment connecting them. If they intersect exactly, the distance is zero.
   - *Validation:* Ensure the intersection parameter `t` is positive (ray direction) [S3, unofficial].

3. **Compute Depth:** Calculate the depth as the L2 norm (Euclidean distance) between the computed 3D point `xyz` and the original ray `origins` [S1, unofficial][S2, unofficial][S3, unofficial].
   - Formula: $$depth = \|xyz - origins\|$$ [S3, unofficial].
   - In code: `depth = (xyz - origins).norm(dim=-1)` [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def get_world_rays(xy: torch.Tensor, extrinsics: torch.Tensor, intrinsics: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
    """
    Converts 2D image coordinates to world-space ray origins and directions.
    xy: (*batch, 2)
    extrinsics: (*batch, 4, 4)
    intrinsics: (*batch, 3, 3)
    Returns:
        origins: (*batch, 3)
        directions: (*batch, 3)
    """
    # Normalize xy to [-1, 1] if they are in [0, 1] or pixel coordinates, 
    # depending on the specific convention of the intrinsic matrix. 
    # Assuming xy is in pixel coordinates or normalized device coordinates as per the specific implementation.
    # Standard backprojection:
    # 1. Unproject xy to camera space.
    # 2. Transform to world space using extrinsics.
    
    # Reshape for matrix multiplication
    # Assuming xy is (N, 2) and needs to be homogeneous (N, 3)
    xy_homo = torch.cat([xy, torch.ones_like(xy[..., :1])], dim=-1) # (N, 3)
    
    # Invert intrinsics to go from pixel to camera coordinates
    # K_inv @ [u, v, 1]^T
    K_inv = torch.inverse(intrinsics) # (N, 3, 3)
    cam_coords = torch.bmm(K_inv, xy_homo.unsqueeze(-1)).squeeze(-1) # (N, 3)
    
    # Transform to world space
    # R @ cam_coords + t
    R = extrinsics[..., :3, :3] # (N, 3, 3)
    t = extrinsics[..., :3, 3] # (N, 3)
    
    origins = t # The camera center is the origin of the ray in world space
    directions = torch.bmm(R, cam_coords.unsqueeze(-1)).squeeze(-1) # (N, 3)
    
    # Normalize directions
    directions = F.normalize(directions, dim=-1)
    
    return origins, directions

def intersect_rays(origins1: torch.Tensor, directions1: torch.Tensor, 
                   origins2: torch.Tensor, directions2: torch.Tensor) -> torch.Tensor:
    """
    Computes the midpoint of the shortest segment between two rays.
    origins1, directions1: (*batch, 3)
    origins2, directions2: (*batch, 3)
    Returns:
        xyz: (*batch, 3)
    """
    # Vector between origins
    d_o = origins2 - origins1 # (N, 3)
    
    # Cross product of directions
    n1 = torch.cross(directions1, directions2, dim=-1) # (N, 3)
    n2 = torch.cross(directions2, directions1, dim=-1) # (N, 3)
    
    # Denominator
    denom = torch.sum(n1 * n1, dim=-1) # (N,)
    
    # Avoid division by zero
    denom = torch.clamp(denom, min=1e-8)
    
    # Project d_o onto the normal plane
    # t1 = dot(d_o, n2) / dot(n1, n1)
    # t2 = dot(d_o, n1) / dot(n1, n1)
    
    t1 = torch.sum(d_o * n2, dim=-1) / denom # (N,)
    t2 = torch.sum(d_o * n1, dim=-1) / denom # (N,)
    
    # Points on each ray
    p1 = origins1 + directions1 * t1.unsqueeze(-1) # (N, 3)
    p2 = origins2 + directions2 * t2.unsqueeze(-1) # (N, 3)
    
    # Midpoint
    xyz = (p1 + p2) / 2.0
    
    return xyz

def epipolar_ray_intersection(origins: torch.Tensor, directions: torch.Tensor, 
                              xy: torch.Tensor, extrinsics: torch.Tensor, 
                              intrinsics: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
    """
    Lifts 2D points to 3D via epipolar ray intersection.
    """
    # Step 1: Get world rays from 2D points
    xy_origins, xy_directions = get_world_rays(xy, extrinsics, intrinsics)
    
    # Step 2: Intersect rays
    xyz = intersect_rays(origins, directions, xy_origins, xy_directions)
    
    # Step 3: Compute depth
    depth = torch.norm(xyz - origins, dim=-1)
    
    return xyz, depth
```

**Parameters:**
- `origins`: Ray origins in world space. Shape: `Float[Tensor, "*#batch 3"]` [S1, unofficial].
- `directions`: Ray directions in world space. Shape: `Float[Tensor, "*#batch 3"]` [S1, unofficial].
- `xy`: 2D image coordinates. Shape: `Float[Tensor, "*#batch 2"]` [S1, unofficial].
- `extrinsics`: Camera extrinsic matrices. Shape: `Float[Tensor, "batch _ 4 4"]` [S1, unofficial].
- `intrinsics`: Camera intrinsic matrices. Shape: `Float[Tensor, "batch _ 3 3"]` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Parallel/Skew Rays:** If the two rays are parallel or nearly parallel, the cross product of their directions will be near zero, leading to numerical instability in the intersection calculation. A small epsilon should be used to clamp the denominator [S3, unofficial].
- **Out of Bounds:** 2D coordinates `xy` should be validated to ensure they are within the image bounds (e.g., normalized 0 to 1 with some epsilon tolerance) [S3, unofficial].
- **Behind Camera:** Points must be in front of the camera. The Z-coordinate in camera space should be greater than `-epsilon` [S3, unofficial].
- **Negative t:** The intersection parameter `t` should be positive to ensure the intersection lies in the direction of the ray [S3, unofficial].

## Subtopics

### [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md)
This method converts 2D depth maps and camera parameters into a 3D point cloud, serving as the geometric foundation for initializing point clouds in neural rendering pipelines. It differs from its sibling [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by relying on explicit geometric backprojection rather than implicit field refinement, and from [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md) by focusing on the core coordinate transformation without necessarily incorporating color or specific downsampling strategies in the base definition. It solves the problem of lifting 2D image data into 3D space for subsequent volume rendering or Gaussian splatting operations.

### Depth Labeling on Epipolar Lines
This variant involves interpolating epipolar line endpoints in pixel space and rendering depth labels along the epipolar line.
- **Steps:**
  1. Interpolate epipolar line endpoints in pixel space: `pt = projection["xy_min"] * t + (1 - t) * projection["xy_max"]` for `t` in `[0, 1]` [S4, unofficial].
  2. Compute depth as Euclidean distance from camera center to 3D point: `depth = (xyz - extrinsics[0, :3, 3]).norm(dim=-1)` [S4, unofficial].
  3. Render depth labels along the epipolar line with white backer rectangles and rotated text [S4, unofficial].

### Epipolar Line Projection
This variant focuses on validating the projection of points onto epipolar lines.
- **Steps:**
  1. Check if XY coordinates are in bounds (normalized 0 to 1) by verifying `xy >= -epsilon` and `xy <= 1 + epsilon` for all dimensions [S3, unofficial].
  2. Check if points are in front of the camera by verifying the Z coordinate is greater than `-epsilon` [S3, unofficial].
  3. Check if ray parameter `t` is positive by verifying `t > -epsilon` [S3, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- The complexity is dominated by the matrix inversions and multiplications in `get_world_rays` and the vector operations in `intersect_rays`. For `N` points, the time complexity is $O(N)$ with a small constant factor due to fixed-size matrix operations. Memory complexity is also $O(N)$ to store the intermediate tensors.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The method scales linearly with the number of points. It is suitable for GPU acceleration due to the tensor operations involved.

**Strengths and Limitations:**
- **Strengths:** Provides a geometrically consistent way to lift 2D points to 3D using epipolar geometry. It is robust to noise if the rays are well-conditioned.
- **Limitations:** Sensitive to the accuracy of the camera parameters (intrinsics and extrinsics). If the rays are nearly parallel, the intersection becomes unstable.

**When to Use:**
- Use when you need to lift 2D points to 3D space using known camera parameters and a set of reference rays. It is particularly useful in multi-view stereo and neural rendering pipelines.

**When Not to Use:**
- Avoid if the camera parameters are inaccurate or if the rays are nearly parallel, leading to numerical instability.

## Background
Epipolar Ray Intersection is a fundamental technique in computer vision and graphics for relating 2D image points to 3D space. It is commonly used in multi-view stereo, structure from motion, and neural rendering pipelines. The method leverages the epipolar geometry between two or more views to constrain the possible 3D locations of a point.
