# Depth-aware Feature Warping

## Overview
Depth-aware Feature Warping projects 2D features from a source view to a target view using estimated depth and camera poses, enabling multi-view consistency checks or feature aggregation for depth estimation [S1, unofficial].

## How it works
**Inputs:**
- Source feature map $F_s \in \mathbb{R}^{B \times C \times H \times W}$ [S1, unofficial].
- Source camera intrinsics $K \in \mathbb{R}^{B \times 3 \times 3}$ [S1, unofficial].
- Relative pose from source to target view $P \in \mathbb{R}^{B \times 4 \times 4}$, composed of rotation $R \in \mathbb{R}^{B \times 3 \times 3}$ and translation $t \in \mathbb{R}^{B \times 3 \times 1}$ [S1, unofficial].
- Depth volume $D \in \mathbb{R}^{B \times D \times H \times W}$, where $D$ is the number of depth candidates [S1, unofficial].

**Outputs:**
- Warped feature map $F_w \in \mathbb{R}^{B \times C \times D \times H \times W}$ [S1, unofficial].

**Data Structures:**
- Homogeneous pixel coordinate grid: Shape $[B, 3, H, W]$ [S1, unofficial].
- 3D points in camera space: Shape $[B, 3, H \times W]$ [S1, unofficial].
- Transformed 3D points: Shape $[B, 3, D, H \times W]$ [S1, unofficial].
- Sampling grid: Shape $[B, D, H \times W, 2]$ [S1, unofficial].

**Parameters:**
- `clamp_min_depth`: Minimum depth value for clamping $z$ during reprojection to prevent division by zero. Default is $10^{-3}$ [S1, unofficial].

**Steps:**
1. Generate a homogeneous pixel coordinate grid of shape $[B, 3, H, W]$ by appending a ones channel to pixel coordinates [S1, unofficial].
2. Back-project pixels to 3D camera space by multiplying the inverse intrinsics with the flattened grid, resulting in shape $[B, 3, H \times W]$ [S1, unofficial].
3. Transform 3D points to the target view's coordinate system using the rotation component of the pose matrix, repeat across depth channels, and scale by depth values, resulting in shape $[B, 3, D, H \times W]$ [S1, unofficial].
4. Translate the points by the translation component of the pose, maintaining shape $[B, 3, D, H \times W]$ [S1, unofficial].
5. Reproject the 3D points to the target 2D image plane by multiplying with intrinsics and reshaping, resulting in shape $[B, 3, D, H \times W]$ [S1, unofficial].
6. Compute normalized pixel coordinates by dividing $x$ and $y$ by $z$ (depth), clamping $z$ to `clamp_min_depth` to avoid division by zero, resulting in shape $[B, 2, D, H \times W]$ [S1, unofficial].
7. Normalize pixel coordinates to the range $[-1, 1]$ required by `grid_sample`, resulting in shape $[B, D, H \times W]$ for each coordinate [S1, unofficial].
8. Stack $x$ and $y$ grids into a sampling grid of shape $[B, D, H \times W, 2]$ [S1, unofficial].
9. Sample features from the source feature map using bilinear interpolation and zero padding on out-of-bounds pixels, resulting in shape $[B, C, D, H, W]$ [S1, unofficial].

**Pseudocode:**
```python
def warp_with_pose_depth_candidates(feature1, intrinsics, pose, depth, clamp_min_depth=1e-3):
    B, C, H, W = feature1.shape
    D = depth.shape[1]

    # 1. Generate homogeneous pixel coordinate grid [B, 3, H, W]
    u = torch.arange(W, device=feature1.device).float().view(1, 1, 1, W)
    v = torch.arange(H, device=feature1.device).float().view(1, 1, H, 1)
    ones = torch.ones_like(u)
    grid = torch.cat([u, v, ones], dim=1).expand(B, -1, -1, -1)

    # 2. Back-project to 3D camera space [B, 3, H*W]
    points = torch.inverse(intrinsics).bmm(grid.view(B, 3, -1))

    # 3. Transform to target coordinate system [B, 3, D, H*W]
    R = pose[:, :3, :3]
    points = torch.bmm(R, points).unsqueeze(2).repeat(1, 1, D, 1) * depth.view(B, 1, D, H * W)

    # 4. Translate by pose translation [B, 3, D, H*W]
    t = pose[:, :3, -1:].unsqueeze(-1)
    points = points + t

    # 5. Reproject to target image plane [B, 3, D, H*W]
    points = torch.bmm(intrinsics, points.view(B, 3, -1)).view(B, 3, D, H * W)

    # 6. Compute normalized pixel coordinates [B, 2, D, H*W]
    pixel_coords = points[:, :2] / points[:, -1:].clamp(min=clamp_min_depth)

    # 7. Normalize to [-1, 1] range [B, D, H*W]
    x_grid = 2 * pixel_coords[:, 0] / (W - 1) - 1
    y_grid = 2 * pixel_coords[:, 1] / (H - 1) - 1

    # 8. Stack into sampling grid [B, D, H*W, 2]
    grid_sample = torch.stack([x_grid, y_grid], dim=-1)

    # 9. Sample features [B, C, D, H, W]
    warped_feature = F.grid_sample(
        feature1,
        grid_sample.view(B, D * H, W, 2),
        mode="bilinear",
        padding_mode="zeros",
        align_corners=True
    )
    return warped_feature
```

**Pitfalls:**
- Large feature maps (>1,000,000 elements) cause CUDNN errors in `grid_sample`; the code disables CUDNN for `grid_sample` in this case [S1, unofficial].
- Division by zero must be handled via clamping $z$ to `clamp_min_depth` [S1, unofficial].
- Coordinate system conventions (e.g., origin at center vs. corner, axis directions) must be consistent between back-projection and reprojection [G].

## Operating characteristics
- Time complexity: Not given in the sources.
- Memory complexity: Not given in the sources.
- Measured performance: Not given in the sources.
- Strengths: Enables multi-view consistency checks and feature aggregation across multiple depth hypotheses rather than a single depth plane [S1, unofficial].
- Limitations: Computationally expensive for high-resolution images and large depth volumes; sensitive to errors in depth estimation and camera pose accuracy [G].
- When to use: Multi-view stereo depth estimation and feature alignment tasks requiring cross-view aggregation [S1, unofficial].
- When not to use: Real-time applications with strict latency constraints and limited depth uncertainty [G].

## Background
Depth-aware Feature Warping is a technique in deep learning-based multi-view stereo (MVS) and novel view synthesis that aligns features from multiple viewpoints into a common coordinate system [G]. It is implemented in frameworks such as DepthSplat for efficient depth estimation and feature aggregation [S1, unofficial].
