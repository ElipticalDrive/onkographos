# Point Cloud Construction

Also called: Depth and Feature Unprojection, Multi-view Point Cloud Generation

## Overview
Point Cloud Construction converts 2D image features and estimated depth into a 3D point cloud representation, enabling multi-view consistency checks and feature aggregation for tasks like novel view synthesis [S1, unofficial][S2]. Unlike sibling methods that may rely on virtual laser scans or direct geometric projection without semantic features, this method explicitly constructs a structured point cloud where each point carries both 3D geometry and high-dimensional view-dependent semantics (e.g., RGB and learned feature vectors) [S2]. It serves as the bridge between 2D image-based depth estimation and 3D-aware rendering or fusion [S2].

## How it works
**Inputs:**
- Input view $I_i$ (image).
- Estimated depth map $D_i$ for view $I_i$.
- Feature vectors $F_i^0$ (per-pixel features) for view $I_i$.
- Camera intrinsics $K$ (3x3 matrix).
- Camera pose $P$ (4x4 matrix, containing rotation $R$ and translation $t$).
- Image dimensions $H \times W$.

**Outputs:**
- Point cloud $P_i$: A set of 3D points with associated feature vectors. Each point has 3D coordinates and a 64-dimensional feature vector (61-dim semantic features + 3 RGB channels) [S2].

**Data Structures:**
- **Grid:** Homogeneous pixel coordinate grid of shape $[B, 3, H, W]$, where the third channel is all ones [S1, unofficial].
- **Points (Camera Space):** Shape $[B, 3, H \times W]$ after back-projection [S1, unofficial].
- **Points (World Space):** Shape $[B, 3, D, H \times W]$ where $D$ is the number of depth samples or channels if discretized, or simply $[B, 3, H \times W]$ if continuous [S1, unofficial].
- **Feature Vector:** 64 dimensions per point (61 from encoder + 3 RGB) [S2].

**Steps:**

1.  **Generate Pixel Grid:** Create a homogeneous coordinate grid for the image dimensions. For each pixel $(u, v)$, the grid contains $[u, v, 1]$ [S1, unofficial].
    $$ \text{grid}_{u,v} = [u, v, 1]^T $$
    The grid has shape $[B, 3, H, W]$ [S1, unofficial].

2.  **Back-project to Camera Space:** Flatten the grid to $[B, 3, H \times W]$. Multiply by the inverse of the camera intrinsics $K^{-1}$ to obtain 3D points in the camera coordinate system.
    $$ \mathbf{X}_{cam} = K^{-1} \cdot \text{grid}_{flat} $$
    Resulting shape: $[B, 3, H \times W]$ [S1, unofficial].

3.  **Scale by Depth:** Multiply the camera-space points by the estimated depth values $D_i$. If depth is represented as a tensor $D$ of shape $[B, 1, H \times W]$, the operation is:
    $$ \mathbf{X}_{cam\_scaled} = \mathbf{X}_{cam} \cdot D $$
    Note: In some implementations, depth might be discretized into $D$ channels, resulting in shape $[B, 3, D, H \times W]$ [S1, unofficial].

4.  **Transform to Target/World Coordinate System:** Apply the camera pose transformation.
    -   **Rotation:** Multiply by the rotation matrix $R$ (top-left 3x3 of pose $P$).
        $$ \mathbf{X}_{rot} = R \cdot \mathbf{X}_{cam\_scaled} $$
    -   **Translation:** Add the translation vector $t$ (top-right 3x1 of pose $P$).
        $$ \mathbf{X}_{world} = \mathbf{X}_{rot} + t $$
    In batched tensor operations, this is often implemented as:
    $$ \mathbf{X}_{world} = \text{bmm}(P[:, :3, :3], \mathbf{X}_{cam\_scaled}) + P[:, :3, -1:] $$
    [S1, unofficial].

5.  **Construct Point Cloud:** Combine the 3D coordinates $\mathbf{X}_{world}$ with the feature vectors. The feature vector for each point is the concatenation of the 61-dimensional semantic features $F_i^0$ and the 3 RGB channels from the input image $I_i$ [S2].
    $$ \text{Feature}_p = [F_i^0, \text{RGB}] \in \mathbb{R}^{64} $$
    The point cloud $P_i$ consists of points $(\mathbf{X}_{world}, \text{Feature}_p)$ [S2].

**Parameters:**
-   **clamp_min_depth:** Minimum depth value for clamping $z$ during reprojection to prevent division by zero. Default is $10^{-3}$ [S1, unofficial].
-   **Feature Dimension:** 64 dimensions per point (61 semantic + 3 RGB) [S2].

**Pitfalls:**
-   **CUDNN Errors:** Large feature maps (>1,000,000 elements) can cause CUDNN errors during grid sampling. The code should disable CUDNN for `grid_sample` in such cases [S1, unofficial].
-   **Division by Zero:** When reprojecting points to 2D (if required for consistency checks), clamp $z$ to `clamp_min_depth` [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def point_cloud_construction(
    image: torch.Tensor,       # [B, 3, H, W]
    depth: torch.Tensor,       # [B, 1, H, W]
    intrinsics: torch.Tensor,  # [B, 3, 3]
    pose: torch.Tensor,        # [B, 4, 4]
    semantic_features: torch.Tensor, # [B, 61, H, W]
    clamp_min_depth: float = 1e-3
) -> torch.Tensor:
    """
    Constructs a 3D point cloud from 2D image, depth, and features.
    Returns point cloud with 3D coordinates and 64-dim features.
    """
    B, C, H, W = image.shape
    
    # Step 1: Generate homogeneous pixel coordinate grid [B, 3, H, W]
    # u: 0..W-1, v: 0..H-1
    u = torch.arange(W, device=image.device).float().view(1, 1, 1, W)
    v = torch.arange(H, device=image.device).float().view(1, 1, H, 1)
    ones = torch.ones_like(u)
    grid = torch.cat([u, v, ones], dim=1)  # [B, 3, H, W]
    
    # Step 2: Back-project to camera space
    # Flatten grid to [B, 3, H*W]
    grid_flat = grid.view(B, 3, -1)
    # Multiply by inverse intrinsics [B, 3, 3] @ [B, 3, H*W] -> [B, 3, H*W]
    inv_intrinsics = torch.inverse(intrinsics)
    points_cam = torch.bmm(inv_intrinsics, grid_flat)
    
    # Step 3: Scale by depth
    # depth shape [B, 1, H, W] -> [B, 1, H*W]
    depth_flat = depth.view(B, 1, -1)
    points_cam_scaled = points_cam * depth_flat  # [B, 3, H*W]
    
    # Step 4: Transform to world coordinates
    # Rotation [B, 3, 3] @ [B, 3, H*W] -> [B, 3, H*W]
    R = pose[:, :3, :3]
    points_rot = torch.bmm(R, points_cam_scaled)
    # Translation [B, 3, 1]
    t = pose[:, :3, 3:].unsqueeze(-1)  # [B, 3, 1]
    points_world = points_rot + t  # [B, 3, H*W]
    
    # Step 5: Construct feature vectors
    # Semantic features [B, 61, H, W] -> [B, 61, H*W]
    feat_flat = semantic_features.view(B, 61, -1)
    # RGB channels [B, 3, H, W] -> [B, 3, H*W]
    rgb_flat = image.view(B, 3, -1)
    # Concatenate: [B, 64, H*W]
    features_flat = torch.cat([feat_flat, rgb_flat], dim=1)
    
    # Reshape to [B, H*W, 64] for easier handling if needed, 
    # but typically point cloud is stored as [B, 64, H*W] or list of points.
    # Here we return the combined tensor [B, 67, H*W] (3 coords + 64 features)
    point_cloud = torch.cat([points_world, features_flat], dim=1)
    
    return point_cloud
```

## Subtopics

### [Virtual Laser Scan for Point Cloud Generation](16278-virtual-laser-scan-for-point-cloud-generation.md)
Generates point clouds by simulating laser scans from camera poses, focusing on geometric accuracy rather than rich feature aggregation. Choose when memory efficiency and simple geometric representation are prioritized over semantic richness.

### [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md)
Converts depth maps to 3D points in world coordinates. This is a prerequisite step for Point Cloud Construction, providing the geometric foundation.

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of pixels $N = H \times W$ and batch size $B$. The dominant operations are matrix multiplications for back-projection and pose transformation, which are $O(B \cdot N)$.
-   **Memory Complexity:** $O(B \cdot N \cdot D_{feat})$, where $D_{feat}$ is the feature dimension (64). For high-resolution images, this can be significant.
-   **Measured Performance:** Not given in the sources.
-   **Scaling:** Scales well with batch size due to tensor operations. However, large feature maps (>1,000,000 elements) may require disabling CUDNN optimizations, potentially impacting performance [S1, unofficial].
-   **Strengths:** Compact memory usage compared to dense volumetric representations; scalability to complex scenes; enables view-dependent semantics [S2].
-   **Limitations:** Relies on accurate depth estimation; sparse in regions with no depth; may suffer from noise in depth estimates [S2].
-   **When to use:** When multi-view consistency and feature aggregation are required for novel view synthesis or depth estimation [S1, unofficial][S2].
-   **When not to use:** When dense volumetric representation is needed or when depth estimation is unreliable.

## Background
Point Cloud Construction is a key component in differentiable rendering and multi-view stereo pipelines. It was prominently used in the FWD (Forward Warping and Depth) model for real-time novel view synthesis [S2]. The method leverages the efficiency of point clouds for representing scenes with complex geometry and view-dependent appearance [S2]. It builds on the concept of unprojecting 2D pixels to 3D space using camera parameters, a technique common in computer vision [S1, unofficial][S2].
