# LiDAR Ray Simulation

Also called: NeRF-LiDAR Ray Simulation

## Overview
Simulates real LiDAR sensor rays by defining ray origin and direction based on sensor parameters and ego-vehicle motion to generate 3D points [S1]. It differs from standard ray casting by explicitly modeling the temporal evolution of the sensor origin due to vehicle velocity and incorporating a learned "raydrop" probability to mimic real-world signal loss, rather than assuming perfect reflection [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Implicit NeRF representation (for distance $\hat{D}$), LiDAR sensor parameters (channels, field of view, spin rate), ego-vehicle velocity $v$, and time interval $\Delta t$ [S1].
*   **Outputs:** A set of 3D points $p$ and their associated semantic/depth labels, forming a simulated LiDAR frame $\hat{P}$ [S1].

**Data Structures**
*   **Ray Parameters:** Defined by azimuth $\theta$ and vertical angle $\phi$ [S1].
*   **Equirectangular Grid:** A 2D image grid of resolution $H \times W$ used for point-wise alignment [S1]. For a 32-channel LiDAR (e.g., nuScenes), this is $32 \times 1024$ [S1].

**Numbered Steps**
1.  **Determine Ray Direction:** For each laser channel, calculate the azimuth $\theta$ and vertical angle $\phi$ based on the LiDAR's mechanical settings and the time interval $\Delta t$ within the scan cycle [S1]. Compute the direction vector $d$ using:
    $$d = (\cos \theta \cos \phi, \sin \theta \sin \phi, \cos \phi)^T$$
    [S1]
2.  **Update Ray Origin:** Calculate the current sensor origin $o$ by updating the previous origin $o_0$ with the ego-vehicle's velocity $v$ over the time interval $\Delta t$:
    $$o = o_0 + \Delta t \cdot v$$
    [S1]
3.  **Query NeRF for Distance:** Cast the ray defined by $o$ and $d$ into the NeRF to render the distance $\hat{D}$ from the sensor to the nearest surface [S1].
4.  **Compute 3D Point:** Calculate the simulated point $p$ in 3D space:
    $$p = o + \hat{D}d$$
    [S1]
5.  **Apply Raydrop (Optional/Learned):** To match real-world sensor behavior where points are dropped due to low reflectance or incidence angle, apply a learned probability mask [S1]. This is achieved by projecting both the real point cloud $P$ and simulated point cloud $\hat{P}$ into 2D equirectangular grids to establish point-wise correspondence $P \simeq \hat{P}$ [S1].

**Parameters**
*   LiDAR spinning speed: 20 Hz (e.g., Velodyne HDL32E in nuScenes) [S1].
*   Field of view: -30.67° to 10.67° across 32 channels [S1].
*   Time interval $\Delta t$: Determined by the LiDAR frame rate (e.g., 20 Hz for nuScenes) [S1].
*   Points per frame: 20,000 to 40,000 for a standard 32-channel LiDAR [S1].

**Pseudocode**
```python
def simulate_lidar_ray(o0, v, dt, theta, phi, nerf_query):
    # Step 1: Ray direction
    d = np.array([np.cos(theta) * np.cos(phi),
                  np.sin(theta) * np.sin(phi),
                  np.cos(phi)])
    d = d / np.linalg.norm(d)  # Normalize direction [G]
    # Step 2: Update origin
    o = o0 + dt * v
    # Step 3: Query NeRF for Distance
    # Cast the ray defined by o and d into the NeRF to find distance D_hat [G]
    D_hat = nerf_query(o, d)
    # Step 4: Compute 3D Point
    p = o + D_hat * d
    return p, d, o
```

**Edge Cases and Pitfalls**
*   Precision: Spherical projection to equirectangular grids requires careful handling of azimuth wrapping at $\pm 180^\circ$ [G].
*   Degenerate input: Zero velocity $v$ or zero time interval $\Delta t$ freezes the origin $o$, requiring fallback to static calibration [G].

## Subtopics

### Raydrop Learning via Equirectangular Projection
Learns a raydrop processing (probability of points being dropped due to reflectance/angle) by projecting irregular 3D point clouds into 2D equirectangular images to establish point-wise correspondence with real LiDAR frames [S1]. It projects irregular LiDAR points into 2D equirectangular image grids using spherical projection to create point-wise correspondence between simulated and real LiDAR frames [S1]. The point-wise alignment target is $P \simeq \hat{P}$, where $P$ is the ground-truth LiDAR frame and $\hat{P}$ is the simulated LiDAR frame [S1]. The equirectangular image resolution is set to $32 \times 1024$ for a 32-channel LiDAR (e.g., nuScenes) [S1]. A standard U-Net encodes depth ranges, semantic labels, RGB textures, and depth variances between neighborhoods into a feature representation, outputting a 2D probability map (binary mask) to represent drop probabilities for each grid location [S1].

## Background
Originated in the NeRF-LiDAR paper presented at the Thirty-Eighth AAAI Conference on Artificial Intelligence (AAAI-24) [S1]. It is used to generate realistic LiDAR point clouds for autonomous driving simulation and semantic label generation, leveraging hash-encoding NeRF to accelerate the simulation process [S1]. The method is applied to datasets like nuScenes to align sparse 3D point labels with weak 2D image labels for robust semantic radiance field learning [S1].
