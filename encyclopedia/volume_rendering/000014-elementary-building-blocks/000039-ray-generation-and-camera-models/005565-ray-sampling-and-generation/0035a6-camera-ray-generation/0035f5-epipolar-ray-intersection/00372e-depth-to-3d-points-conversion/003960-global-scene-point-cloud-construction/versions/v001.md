# Global Scene Point Cloud Construction

Also called: Global Point Cloud Construction, Multi-view Point Cloud Generation

## Overview
Global Scene Point Cloud Construction aggregates depth maps from multiple calibrated views into a single, unified 3D point cloud in world coordinates. It solves the problem of redundant and inconsistent primitives that arise when unprojecting overlapping depth maps independently. It differs from [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md) by handling the accumulation and cleaning of multiple views rather than processing a single depth map, and from [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing specifically on the initial global assembly and noise removal steps.

## How it works
**Inputs:**
- $N$ RGB images $\{I_n\}_{n=1}^N$.
- $N$ corresponding metric depth maps $\{D_n\}_{n=1}^N$.
- Intrinsic matrices $\{K_n\}_{n=1}^N$.
- Extrinsics matrices $\{T_n = [R_n | t_n]\}_{n=1}^N$, where $R_n$ is rotation and $t_n$ is translation.
- Ego-vehicle poses for registration (if LiDAR is used for bounds, see [S1]).

**Outputs:**
- A global scene point cloud $\mathcal{P} \in \mathbb{R}^{N_p \times 3}$ in world coordinates.

**Data Structures:**
- Raw point cloud $P_{raw}$: List or array of 3D points.
- Filtered point cloud $P_{final}$: List or array of 3D points.

**Steps:**
1. **Unprojection:** For each view $n \in \{1, \dots, N\}$, unproject the depth map $D_n$ using $I_n, D_n, T_n, K_n$ to obtain local 3D points.
   $$ P_n = \pi^{-1}(I_n, D_n, T_n, K_n) $$
   Where $\pi^{-1}$ denotes the pixel unprojection operation, mapping each pixel $(u, v)$ with depth $d$ to world coordinates via $K_n^{-1}$ and $T_n^{-1}$.

2. **Accumulation:** Union all local point clouds:
   $$ P_{raw} = \bigcup_{n=1}^N P_n $$

3. **Uniform Filtering:** Apply a uniform filter in 3D space to $P_{raw}$ to delete duplicate primitives while keeping the scene structure. This addresses redundancy in overlapping regions [S2].

4. **Statistical Filtering:** Apply a statistical filter to $P_{final}$ (output of step 3) to remove floaters (noise) [S2].

5. **LiDAR Integration (Optional/Contextual):** If using LiDAR for scene bounds:
   - Filter LiDAR points to keep only those within 80 meters from the ego-vehicle [S1].
   - Register filtered LiDAR points in the global world frame using ego-vehicle poses [S1].
   - Compute scene bounds from the resulting global point cloud [S1].

**Pseudocode:**
```python

    """
    images: List of N RGB images
    depths: List of N depth maps
    intrinsics: List of N intrinsic matrices K_n
    extrinsics: List of N extrinsic matrices T_n = [R_n | t_n]
    """
    raw_points = []
    
    # Step 1 & 2: Unproject and Accumulate
    for n in range(len(images)):
        # Unproject depth map to 3D points in world coordinates
        # pi_inv handles: pixel -> normalized camera coords -> world coords
        local_points = unproject_depth_map(images[n], depths[n], intrinsics[n], extrinsics[n])
        raw_points.extend(local_points)
    
    # Step 3: Uniform Filter
    # Removes duplicates in overlapping regions
    filtered_points = uniform_filter_3d(raw_points)
    
    # Step 4: Statistical Filter
    # Removes noise/floaters
    final_cloud = statistical_filter_3d(filtered_points)
    
    return final_cloud

def unproject_depth_map(image, depth_map, K, T):
    """
    Unprojects a depth map to 3D points in world coordinates.
    K: 3x3 intrinsic matrix
    T: 4x4 extrinsic matrix [R|t]
    """
    h, w = depth_map.shape
    points = []
    
    # Precompute inverse intrinsic
    K_inv = np.linalg.inv(K)
    
    # Precompute inverse extrinsic (world to camera)
    # T maps world to camera: P_cam = T * P_world
    # So P_world = T_inv * P_cam
    T_inv = np.linalg.inv(T)
    
    for y in range(h):
        for x in range(w):
            d = depth_map[y, x]
            if d <= 0:  # Skip invalid depth
                continue
            
            # Pixel to normalized camera coordinates
            # Assuming pixel center at (x+0.5, y+0.5)
            u, v = x + 0.5, y + 0.5
            
            # Back-project to camera frame
            # [u, v, 1] are homogeneous coordinates in image plane
            cam_coords = K_inv @ np.array([u, v, 1])
            
            # Scale by depth
            cam_coords = cam_coords * d
            
            # Transform to world coordinates
            # cam_coords is 3D, so we use homogeneous 4D for T_inv
            world_coords = T_inv @ np.append(cam_coords, 1)
            
            # Extract 3D point
            point = world_coords[:3]
            points.append(point)
            
    return points
```

**Edge Cases and Pitfalls:**
- Overlapping regions generate redundant primitives; uniform filtering is required [S2].

- Dynamic objects may receive invalid depth supervision if not handled; LiDAR measurements are used as ground truth only at the time of camera sensor recording [S1].

## Operating characteristics
- **Time Complexity:** $O(N \cdot H \cdot W)$ for unprojection, where $N$ is number of views, $H, W$ are image dimensions. Filtering complexity depends on implementation (e.g., $O(N_p \log N_p)$ for KDTree-based filtering).
- **Memory Complexity:** $O(N \cdot H \cdot W)$ for raw points, reduced after filtering.
- **Strengths:** Handles overlapping views efficiently; removes redundancy and noise.
- **Limitations:** Requires accurate calibration; sensitive to depth errors.
- **When to use:** When constructing a global scene representation from multiple calibrated views.
- **When not to use:** When real-time single-view reconstruction is required.
