# Virtual Laser Scan for Point Cloud Generation

Also called: Scan class, get_surface_point_cloud via scan

## Overview
A method to generate a point cloud with normals from a mesh by rendering normal and depth buffers from a specific camera viewpoint and reprojecting the buffer data into world space [S1, unofficial]. It differs from direct mesh sampling by relying on rasterization to handle visibility and occlusion, effectively acting as a "virtual laser scan" from a single viewpoint. It builds on [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md) by providing the specific reprojection logic and visibility handling required to convert rendered buffers into a coherent 3D surface representation.

## How it works
**Inputs:**
- `mesh`: A triangular mesh object.
- `camera_transform`: A $4 \times 4$ transformation matrix representing the camera's pose in world coordinates.
- `resolution`: Integer, the width and height of the rendered buffers (square aspect ratio assumed). Default: 400.
- `calculate_normals`: Boolean. If true, render and process normal buffers. Default: True.
- `fov`: Vertical field of view in radians. Default: 1.
- `z_near`: Near clipping plane distance. Default: 0.1.
- `z_far`: Far clipping plane distance. Default: 10.

**Outputs:**
- `self.points`: Array of shape $(N, 3)$ containing 3D coordinates in world space.
- `self.normals`: Array of shape $(N, 3)$ containing unit normals in world space (if `calculate_normals` is True).

**Data Structures:**
- `depth_buffer`: Rendered depth values from the graphics API (typically normalized or linearized depending on the renderer).
- `normal_buffer`: RGB color buffer where each channel is an 8-bit integer (0-255) representing the normal vector components.
- `projection_matrix`: $4 \times 4$ matrix derived from `fov`, `aspectRatio` (1.0), `z_near`, and `z_far`.

**Steps:**

1.  **Initialize Camera:**
    Compute `camera_position` from `camera_transform`:
    $$ \text{camera\_position} = (\text{camera\_transform} \times [0, 0, 0, 1]^T)[:3] $$
    Create a perspective camera with `yfov=fov`, `aspectRatio=1.0`, `znear=z_near`, `zfar=z_far`. Retrieve the `projection_matrix`.

2.  **Render Buffers:**
    Render the `mesh` using the camera. Obtain `depth_buffer` and `normal_buffer` (if `calculate_normals` is True).

3.  **Process Depth:**
    Find indices where depth is valid (non-zero):
    $$ \text{indices} = \text{argwhere}(\text{depth\_buffer} \neq 0) $$
    Set invalid depth values to infinity to exclude them:
    $$ \text{depth\_buffer}[\text{depth\_buffer} == 0] = \infty $$
    Revert the renderer's depth processing to calculate the original depth in clipping space ($z_{clip}$). The formula depends on the renderer's depth encoding. For the source implementation (pyrender), the formula is [S1, unofficial]:
    $$ z_{clip} = \frac{z_{far} + z_{near} - \frac{2 z_{near} z_{far}}{depth_{buffer}}}{z_{far} - z_{near}} $$
    Store this as `self.depth`.

4.  **Map to Clip Space:**
    Create a points array of shape $(N, 4)$ initialized with ones in the w-component.
    Map pixel indices to normalized device coordinates (NDC) clip space:
    $$ x_{clip} = \frac{\text{indices}_y}{\text{resolution} - 1} \times 2 - 1 $$
    $$ y_{clip} = -\left( \frac{\text{indices}_x}{\text{resolution} - 1} \times 2 - 1 \right) $$
    $$ z_{clip} = \text{self.depth}[\text{indices}_x, \text{indices}_y] $$
    $$ w_{clip} = 1.0 $$
    Note: The y-coordinate is negated to account for coordinate system differences between screen space and clip space.

5.  **Transform to World Space:**
    Compute the clipping-to-world transformation matrix:
    $$ M_{clip \to world} = \text{camera\_transform} \times \text{projection\_matrix}^{-1} $$
    Transform points:
    $$ \mathbf{p}_{homogeneous} = \mathbf{p}_{clip} \times M_{clip \to world}^T $$
    Perform perspective divide:
    $$ \mathbf{p}_{world} = \frac{\mathbf{p}_{homogeneous}}{\mathbf{p}_{homogeneous}[3]} $$
    Store the first three components as `self.points`.

6.  **Process Normals (Optional):**
    If `calculate_normals` is True:
    Decode normals from the color buffer (assuming 8-bit RGB):
    $$ \mathbf{n}_{view} = \frac{\text{normal\_buffer}[\text{indices}_x, \text{indices}_y]}{255} \times 2 - 1 $$
    Compute the vector from the camera to the points:
    $$ \mathbf{v}_{cam \to pt} = \text{camera\_position} - \text{self.points} $$
    Determine orientation using the dot product:
    $$ \text{orientation}_i = \mathbf{v}_{cam \to pt, i} \cdot \mathbf{n}_{view, i} $$
    Flip normals pointing away from the camera:
    $$ \mathbf{n}_{view}[\text{orientation} < 0] = -\mathbf{n}_{view}[\text{orientation} < 0] $$
    Transform normals to world space (rotation only, no translation) if the `camera_transform` includes rotation. The source code implies storing them directly, but standard practice requires rotating by the upper-left $3 \times 3$ of `camera_transform`. The source notes do not explicitly detail the rotation step for normals, only the orientation flip [S1, unofficial]. Store as `self.normals`.

**Pseudocode:**

```python
import numpy as np

def generate_point_cloud(mesh, camera_transform, resolution=400, calculate_normals=True, 
                         fov=1.0, z_near=0.1, z_far=10.0, projection_matrix=None):
    """
    Generates a point cloud from a mesh using virtual laser scan principles.
    Assumes a helper function `render_buffers` exists that returns depth and normal buffers.
    """
    # 1. Compute camera position
    camera_position = np.matmul(camera_transform, np.array([0, 0, 0, 1]))[:3]
    
    # 2. Render buffers
    # Note: In a real implementation, this calls the graphics API (e.g., pyrender)
    depth_buffer, normal_buffer = render_buffers(mesh, camera_transform, resolution, fov, z_near, z_far)
    
    # 3. Process Depth
    indices = np.argwhere(depth_buffer != 0)
    if len(indices) == 0:
        return np.empty((0, 3)), None
        
    depth_buffer_copy = depth_buffer.copy()
    depth_buffer_copy[depth_buffer_copy == 0] = float('inf')
    
    # Revert pyrender's depth processing to get clip-space depth
    # Formula: z_clip = (z_far + z_near - (2 * z_near * z_far) / depth_buffer) / (z_far - z_near)
    z_clip = (z_far + z_near - (2.0 * z_near * z_far) / depth_buffer_copy) / (z_far - z_near)
    
    # 4. Map to Clip Space
    # indices shape: (N, 2) -> (row, col) -> (y, x) in image coords
    # We need x_clip, y_clip, z_clip, w_clip
    n_points = indices.shape[0]
    points_clip = np.ones((n_points, 4))
    
    # Map pixel coordinates to NDC [-1, 1]
    # x corresponds to column index (indices[:, 1])
    # y corresponds to row index (indices[:, 0])
    points_clip[:, 0] = (indices[:, 1].astype(float) / (resolution - 1)) * 2 - 1
    # Negate y for clip space convention
    points_clip[:, 1] = -((indices[:, 0].astype(float) / (resolution - 1)) * 2 - 1)
    points_clip[:, 2] = z_clip[indices[:, 0], indices[:, 1]]
    
    # 5. Transform to World Space
    # clipping_to_world = camera_transform @ inv(projection_matrix)
    if projection_matrix is None:
        # Placeholder for projection matrix generation if not provided
        # Typically calculated from fov, aspect, z_near, z_far
        raise ValueError("projection_matrix must be provided or generated")
        
    inv_proj = np.linalg.inv(projection_matrix)
    clipping_to_world = np.matmul(camera_transform, inv_proj)
    
    # Transform points: p_world_hom = p_clip @ M^T
    points_hom = np.matmul(points_clip, clipping_to_world.T)
    
    # Perspective divide
    w = points_hom[:, 3, np.newaxis]
    # Avoid division by zero
    w[w == 0] = 1.0
    points_world = points_hom / w
    
    self_points = points_world[:, :3]
    
    # 6. Process Normals
    self_normals = None
    if calculate_normals:
        # Decode normals from 8-bit color buffer
        # normal_buffer shape: (H, W, 3)
        # indices: (N, 2)
        normals_view = normal_buffer[indices[:, 0], indices[:, 1]]
        normals_view = (normals_view / 255.0) * 2.0 - 1.0
        
        # Vector from camera to point
        camera_to_points = camera_position - self_points
        
        # Determine orientation
        # Dot product of camera-to-point vector and normal
        normal_orientation = np.einsum('ij,ij->i', camera_to_points, normals_view)
        
        # Flip normals pointing away from camera
        normals_view[normal_orientation < 0] *= -1
        
        # Transform normals to world space (rotation only)
        # Assuming camera_transform includes rotation in the upper 3x3
        rotation_matrix = camera_transform[:3, :3]
        normals_world = np.matmul(normals_view, rotation_matrix.T)
        
        self_normals = normals_world
        
    return self_points, self_normals
```

## Subtopics

### Surface Point Cloud Generation via Scans
A variant that aggregates multiple virtual laser scans to cover the entire mesh surface. It generates camera angles using a Fibonacci sphere distribution to ensure equidistant sampling on the unit sphere. For each angle, a `Scan` object is created with specific parameters: `fov=1.0472` (approx 60 degrees), `z_near=bounding_radius`, and `z_far=3*bounding_radius`. The camera distance is set to `2*bounding_radius`. The final point cloud is formed by concatenating points and normals from all scans. This approach mitigates occlusion issues inherent in single-view scans [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of pixels in the resolution ($O(R^2)$) for rendering and reprojection. Aggregating multiple scans scales linearly with the number of scans.
- **Memory Complexity:** Proportional to the number of visible pixels. Storing normals doubles the memory requirement for the point cloud data.
- **Strengths:** Handles visibility and occlusion naturally via the depth buffer. Provides normals without requiring explicit mesh normal lookups. Simple to implement using standard graphics APIs.
- **Limitations:** Resolution-dependent; high resolution is needed for dense, accurate point clouds. Single-view scans suffer from occlusion. Rendering overhead can be significant for high-resolution meshes.
- **When to use:** When a quick, visibility-aware point cloud is needed from a mesh, or when normals are required and mesh normals are not available or reliable.
- **When not to use:** When exact mesh sampling is required (e.g., for SDF computation where uniform distribution is critical), or when performance is critical and mesh normals are already available.

## Background
The method originates from the `mesh_to_sdf` library, which uses virtual laser scans to generate point clouds for Signed Distance Field (SDF) computation [S1, unofficial]. It leverages the `pyrender` library for rendering and `numpy` for data processing. The approach is commonly used in 3D reconstruction and deep learning pipelines where mesh data needs to be converted into point cloud format for further processing or training.
