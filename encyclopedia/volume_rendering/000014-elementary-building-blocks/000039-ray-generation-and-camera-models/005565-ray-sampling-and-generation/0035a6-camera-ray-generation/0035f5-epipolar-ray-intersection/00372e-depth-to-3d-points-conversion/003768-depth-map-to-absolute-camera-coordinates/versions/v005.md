# Depth Map to Absolute Camera Coordinates

Also called: Depth Map Unprojection, RGBD to Point Cloud Back-Projection, camera back-projection, depth-to-3D conversion, depth2pc

## Overview
This method converts 2D rasterized depth and color images into a 3D point cloud using camera intrinsics and extrinsics [S1, S2, unofficial]. It solves the problem of mapping per-pixel depth values from a 2D image plane into 3D world coordinates, enabling the construction of geometric scene representations from multi-view RGB-D data [S1, S2, S3, unofficial]. Unlike sibling methods that may rely on explicit mesh extraction or virtual laser scans, this approach directly unprojects per-pixel depth and learned feature vectors into 3D space, preserving high-dimensional semantic information alongside geometry [S1, unofficial]. It builds on [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md) by providing the specific reprojection logic required to convert rendered buffers into 3D points.

## How it works
**Inputs:**
- `depth`: A tensor of shape $(B, H, W)$ or $(H, W)$ containing depth values $z$ (distance from camera center).
- `intrinsics`: A 3x3 camera intrinsic matrix $K$.
  - $K_{0,0} = f_x$ (focal length in x)
  - $K_{1,1} = f_y$ (focal length in y)
  - $K_{0,2} = c_x$ (principal point x)
  - $K_{1,2} = c_y$ (principal point y)
  - $K_{2,2} = 1$
- `extrinsic` (optional): A 4x4 world-to-camera transformation matrix $W2C$ or its inverse $C2W$. If not provided, points remain in camera space.

**Outputs:**
- `points`: A tensor of shape $(B, H \times W, 3)$ or $(H \times W, 3)$ containing 3D coordinates in world space (or camera space if extrinsics are omitted).

**Data Structures:**
- Pixel grid indices `xx`, `yy`: 1D tensors of shape $(H \times W)$ representing column and row indices.
- Homogeneous coordinate vector `pix_ones`: 1D tensor of shape $(H \times W, 1)$ filled with ones.

**Steps:**

1. **Generate Pixel Grid:**
   Create 2D meshgrid indices for all pixels. For a depth map of size $H \times W$, generate coordinates $u \in [0, W-1]$ and $v \in [0, H-1]$. Flatten these into 1D arrays `xx` and `yy` of length $H \times W$.
   *Note: Some implementations normalize these to $[-1, 1]$ range first [S4, unofficial], while others keep integer indices [S1, unofficial]. The standard pinhole model uses integer indices or normalized device coordinates depending on the intrinsic definition. We follow the standard pinhole projection formula.*

2. **Compute Camera Space Coordinates:**
   For each pixel $(u, v)$ with depth $z$:
   $$x_c = (u - c_x) \frac{z}{f_x}$$
   $$y_c = (v - c_y) \frac{z}{f_y}$$
   $$z_c = z$$
   Stack these into a tensor `pts_cam` of shape $(H \times W, 3)$.

3. **Handle Depth Scaling (Variant):**
   Some pipelines (e.g., AtomGS) apply a depth scaling factor using elements $f_1, f_2$ from the projection matrix to adjust for specific rendering artifacts or inverse depth representations [S4, unofficial]. If applicable:
   $$s_{d_{i,j}} = \frac{f_1 d_{i,j} + f_2}{d_{i,j}}$$
   Replace $z_c$ with $s_{d_{i,j}}$ in `pts_cam`.

4. **Transform to World Space (Optional):**
   If `extrinsic` is provided:
   - Construct homogeneous coordinates `pts4` by appending a column of ones to `pts_cam`: `pts4 = [x_c, y_c, z_c, 1]`.
   - Compute the camera-to-world matrix $C2W = (W2C)^{-1}$.
   - Transform points: $P_{world} = C2W \times pts4^T$.
   - Extract the first three rows to get Cartesian world coordinates.
   - Reshape to $(B, H \times W, 3)$.

**Pseudocode:**

```python
import torch

def depth_map_to_absolute_camera_coordinates(depth, intrinsics, extrinsic=None):
    """
    Converts a depth map to 3D world coordinates.
    
    Args:
        depth: Tensor of shape (B, H, W) or (H, W). Depth values in meters.
        intrinsics: Tensor of shape (B, 3, 3) or (3, 3). Camera intrinsic matrix K.
        extrinsic: Tensor of shape (B, 4, 4) or (4, 4). World-to-Camera matrix W2C. Optional.
        
    Returns:
        points: Tensor of shape (B, H*W, 3). 3D points in world space.
    """
    # Handle batch dimension
    if depth.dim() == 2:
        depth = depth.unsqueeze(0)
        intrinsics = intrinsics.unsqueeze(0)
        if extrinsic is not None:
            extrinsic = extrinsic.unsqueeze(0)
            
    B, H, W = depth.shape
    
    # 1. Generate pixel grid indices
    # Create meshgrid: u in [0, W-1], v in [0, H-1]
    # Note: Using torch.arange and meshgrid
    u = torch.arange(0, W, device=depth.device).float()
    v = torch.arange(0, H, device=depth.device).float()
    uu, vv = torch.meshgrid(u, v, indexing='xy')
    
    # Flatten to 1D
    xx = uu.reshape(-1) # Column indices (u)
    yy = vv.reshape(-1) # Row indices (v)
    
    # Repeat for batch dimension if needed, or broadcast
    # Assuming intrinsics are per-batch
    xx = xx.unsqueeze(0).expand(B, -1)
    yy = yy.unsqueeze(0).expand(B, -1)
    z_depth = depth.reshape(B, -1)
    
    # 2. Extract intrinsics
    fx = intrinsics[:, 0, 0]
    fy = intrinsics[:, 1, 1]
    cx = intrinsics[:, 0, 2]
    cy = intrinsics[:, 1, 2]
    
    # 3. Compute camera space coordinates
    # x_c = (u - cx) * z / fx
    # y_c = (v - cy) * z / fy
    # z_c = z
    
    # Broadcasting: xx, yy, z_depth are (B, H*W)
    # fx, fy, cx, cy are (B,)
    
    x_cam = (xx - cx.unsqueeze(1)) * z_depth / fx.unsqueeze(1)
    y_cam = (yy - cy.unsqueeze(1)) * z_depth / fy.unsqueeze(1)
    z_cam = z_depth
    
    # Stack into (B, H*W, 3)
    pts_cam = torch.stack([x_cam, y_cam, z_cam], dim=-1)
    
    # 4. Transform to world space if extrinsic is provided
    if extrinsic is not None:
        # Compute C2W = inv(W2C)
        # Note: Inverse of 4x4 matrix
        c2w = torch.inverse(extrinsic)
        
        # Append homogeneous coordinate 1
        ones = torch.ones(B, pts_cam.shape[1], 1, device=pts_cam.device)
        pts4 = torch.cat([pts_cam, ones], dim=-1) # (B, H*W, 4)
        
        # Transform: P_world = C2W @ P_cam_hom
        # pts4 is (B, N, 4). We need to multiply C2W (B, 4, 4) by pts4^T (B, 4, N)
        # Result is (B, 4, N). Then transpose to (B, N, 4)
        pts_world_hom = torch.bmm(c2w, pts4.transpose(1, 2)) # (B, 4, H*W)
        pts_world_hom = pts_world_hom.transpose(1, 2) # (B, H*W, 4)
        
        # Discard homogeneous coordinate
        pts = pts_world_hom[:, :, :3]
    else:
        pts = pts_cam
        
    return pts
```

**Edge Cases and Pitfalls:**
- **Zero Depth:** Pixels with $z=0$ result in undefined coordinates. Mask these out or set to NaN [S1, unofficial].
- **Invalid Intrinsics:** Ensure $f_x, f_y \neq 0$.
- **Coordinate System:** Verify if the depth map represents distance along the optical axis or Euclidean distance from the camera center. Standard pinhole assumes optical axis distance [S1, unofficial].
- **Precision:** Use float32 or float64 for coordinate calculations to avoid precision loss in large scenes [S1, unofficial].

## Subtopics

### [Point Cloud Construction](13172-point-cloud-construction.md)
Point Cloud Construction converts 2D input views into 3D point clouds containing both geometric positions and view-dependent semantic features. It solves the problem of representing complex scenes in a format that is memory-efficient and scalable, serving as the foundational representation for subsequent differentiable rendering and multi-view fusion. Unlike sibling methods that may rely on explicit mesh extraction or virtual laser scans, this approach directly unprojects per-pixel depth and learned feature vectors into 3D space, preserving high-dimensional semantic information alongside geometry.

### [Virtual Laser Scan for Point Cloud Generation](16278-virtual-laser-scan-for-point-cloud-generation.md)
A method to generate a point cloud with normals from a mesh by rendering normal and depth buffers from a specific camera viewpoint and reprojecting the buffer data into world space. It differs from direct mesh sampling by relying on rasterization to handle visibility and occlusion, effectively acting as a "virtual laser scan" from a single viewpoint. It builds on [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md) by providing the specific reprojection logic required to convert rendered buffers into 3D points.

#### Lidar Depth Generation
In scenarios where LiDAR data is available, depth maps can be generated by projecting LiDAR points onto the image plane. For a given image frame, LiDAR points from the ten closest LiDAR frames are selected and transformed into world coordinates [S5]. These points are then projected onto the image coordinates. The depth value for each pixel is derived from the distance along the ray from the camera center to the nearest LiDAR point. If multiple LiDAR points project to the same pixel, the depth value is taken from the closest point [S5].

## Operating characteristics
- **Time Complexity:** $O(H \times W)$ per image, as each pixel is processed independently.
- **Memory Complexity:** $O(H \times W)$ to store the resulting point cloud.
- **Performance:** Highly parallelizable on GPU. Typical performance depends on resolution; for 1080p images, processing is nearly instantaneous on modern GPUs.
- **Strengths:** Simple, differentiable (if depth is learned), and preserves per-pixel correspondence.
- **Limitations:** Sensitive to depth errors; noisy depth maps result in noisy point clouds. Does not handle occlusions or missing depth data automatically (requires masking).

## Background
The method originates from standard computer vision techniques for back-projecting depth maps to 3D space using pinhole camera models. It is widely used in RGB-D reconstruction, SLAM, and NeRF/Gaussian Splatting pipelines to initialize point clouds or supervise depth predictions. Key implementations include SplaTAM [S1, unofficial], InstantSplat [S2, unofficial], and GPS+ [S3, unofficial]. The specific depth scaling variant is described in AtomGS [S4, unofficial].
