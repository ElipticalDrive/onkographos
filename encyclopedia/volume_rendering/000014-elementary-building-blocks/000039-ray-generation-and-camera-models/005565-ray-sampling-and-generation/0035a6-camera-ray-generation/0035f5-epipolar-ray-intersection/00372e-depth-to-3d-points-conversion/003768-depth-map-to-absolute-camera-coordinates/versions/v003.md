# Depth Map to Absolute Camera Coordinates

Also called: Depth Map Unprojection, depth2pc

## Overview
Converts a 2D depth map, camera intrinsics, and camera pose into 3D points in world coordinates [S1, S2, S3, unofficial]. It solves the problem of backprojecting pixel-space depth measurements into a global 3D reference frame, enabling the construction of point clouds from single or multi-view depth estimates. It differs from [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing strictly on the geometric reprojection step rather than feature fusion or refinement, and from [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md) by handling arbitrary depth maps and explicit pose transformations rather than fixed-size buffers [S1, S2, S3, unofficial][S4].

## How it works
**Inputs:**
- Depth map $D'$ of size $H \times W$ (or batch $B \times H \times W$), where $d_{i,j}$ is the depth at pixel $(i, j)$ [S3, unofficial].
- Camera intrinsics matrix $K$ (or focal lengths $f_x, f_y$ and principal point $c_x, c_y$) [S2, S3, unofficial].
- Camera pose (extrinsics) $T_{cam2world}$, comprising rotation $R_{cam2world}$ and translation $t_{cam2world}$ [S1, S3, unofficial]. If only relative coordinates are needed, this may be omitted [S1, unofficial].

**Outputs:**
- 3D point cloud $D \in \mathbb{R}^{H \times W \times 3}$ (or $B \times H \times W \times 3$) representing world coordinates [S3, unofficial].

**Data Structures:**
- Homogeneous coordinates: 4D vectors $[x, y, z, 1]^T$.
- Camera space points: 3D vectors $[x_{cam}, y_{cam}, z_{cam}]^T$.
- World space points: 3D vectors $[x_{world}, y_{world}, z_{world}]^T$.

**Steps:**

1. **Pixel Coordinate Generation**: Create a meshgrid of pixel coordinates $(i, j)$ for $i \in [0, H-1]$ and $j \in [0, W-1]$ [S2, S3, unofficial].

2. **Normalization**: Normalize pixel coordinates to the range $[-1, 1]$ [S3, unofficial]:
   $$ x_{norm} = \frac{2j}{W-1} - 1 $$
   $$ y_{norm} = \frac{2i}{H-1} - 1 $$
   *Note: Some implementations use inverse depth scaling directly on raw pixel coordinates offset by principal point [S2, unofficial].*

3. **Camera Space Construction**: Form homogeneous camera space coordinates $p_{camera}$ [S3, unofficial]:
   $$ p_{camera} = [x_{norm}, y_{norm}, d_{i,j}]^T $$
   *Alternative (S2):* Extract rotation `rot` and translation `trans` from extrinsics. Stack `x, y, 1` into `pts_2d`. Set z-component to `1.0 / (depth + 1e-8)` to handle inverse depth representations common in neural rendering [S2, unofficial]. Subtract principal point offsets: $x' = x - c_x$, $y' = y - c_y$. Divide by focal lengths: $x_{norm} = x' / f_x$, $y_{norm} = y' / f_y$ [S2, unofficial].

4. **Depth Scaling (Optional/Variant)**: If using a specific projection matrix formulation involving $f_1, f_2$ (e.g., for normalized device coordinate adjustments), scale depth values [S3, unofficial]:
   $$ s_{d_{i,j}} = \frac{f_1 d_{i,j} + f_2}{d_{i,j}} $$
   Adjusted camera coordinates: $p'_{camera} = [x_{norm}, y_{norm}, s_{d_{i,j}}]^T$ [S3, unofficial].

5. **World Space Transformation**:
   - **Method A (Explicit Rotation/Translation) [S1, S2, unofficial]:**
     If camera pose is provided, transform camera space points to world space:
     $$ X_{world} = R_{cam2world} \cdot X_{cam} + t_{cam2world} $$
     In batched form (S2): `pts = rot^T * pts_2d - rot^T * trans` (assuming `pts_2d` contains normalized coordinates and inverse depth handling) [S2, unofficial].
   - **Method B (Projection Matrix Inverse) [S3, unofficial]:**
     Multiply by the inverse of the full projection transform matrix $T$ (where $T$ combines intrinsics and extrinsics):
     $$ p_{world} = T^{-1} \times [x_{norm}, y_{norm}, s_{d_{i,j}}, 1]^T $$
     Discard homogeneous coordinate to get Cartesian coordinates:
     $$ D = p'_{world} = \frac{p_{world}[0:3]}{p_{world}[3]} $$
     [S3, unofficial].

**Parameters:**
- Epsilon for numerical stability: $1e-8$ (used in inverse depth calculation) [S2, unofficial].
- Typical values for $f_1, f_2$ depend on the specific camera calibration and normalization scheme [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Depth:** Depth values of zero cause division by zero in inverse depth or normalization. Use epsilon addition [S2, unofficial].
- **Invalid Pixels:** Mask out pixels with invalid depth (e.g., 0 or NaN) before transformation [S1, unofficial].
- **Coordinate System Convention:** Ensure consistency between the depth map's coordinate system (e.g., Z-forward vs Z-backward) and the camera model [S2, S3, unofficial].
- **Principal Point Offset:** Failure to subtract $(c_x, c_y)$ leads to skewed point clouds if raw pixel coordinates are used instead of normalized ones [S2, unofficial].

**Pseudocode:**

```python
import torch
import numpy as np

def depth_map_to_absolute_camera_coordinates(
    depth_map: torch.Tensor,
    intrinsics: torch.Tensor,
    extrinsics: torch.Tensor = None,
    use_inverse_depth: bool = False
) -> torch.Tensor:
    """
    Converts depth map to 3D world coordinates.
    
    Args:
        depth_map: Tensor of shape (B, H, W) or (H, W). Depth values.
        intrinsics: Tensor of shape (B, 3, 3) or (3, 3). Camera intrinsic matrix K.
        extrinsics: Tensor of shape (B, 4, 4) or (4, 4). Camera-to-world transformation matrix.
        use_inverse_depth: If True, treats depth_map as inverse depth (1/d).
        
    Returns:
        Points in world coordinates of shape (B, H, W, 3).
    """
    # Handle batch dimension
    if depth_map.dim() == 2:
        depth_map = depth_map.unsqueeze(0)
        intrinsics = intrinsics.unsqueeze(0)
        if extrinsics is not None:
            extrinsics = extrinsics.unsqueeze(0)
            
    B, H, W = depth_map.shape
    
    # 1. Generate pixel coordinates
    # Create meshgrid: j in [0, W-1], i in [0, H-1]
    j_coords, i_coords = torch.meshgrid(
        torch.arange(W, device=depth_map.device, dtype=torch.float32),
        torch.arange(H, device=depth_map.device, dtype=torch.float32),
        indexing='ij'
    )
    
    # 2. Normalize to [-1, 1]
    x_norm = (2.0 * j_coords) / (W - 1) - 1.0
    y_norm = (2.0 * i_coords) / (H - 1) - 1.0
    
    # 3. Handle Depth and Inverse Depth
    depth = depth_map
    if use_inverse_depth:
        # Add epsilon to avoid division by zero
        depth = 1.0 / (depth + 1e-8)
        
    # 4. Construct Camera Space Points
    # Option A: Using normalized coordinates and depth directly (S3)
    # p_camera = [x_norm, y_norm, depth]
    # However, standard pinhole projection requires scaling by focal length
    # Extract intrinsics
    fx = intrinsics[:, 0, 0] # (B,)
    fy = intrinsics[:, 1, 1] # (B,)
    cx = intrinsics[:, 0, 2] # (B,)
    cy = intrinsics[:, 1, 2] # (B,)
    
    # Adjust for principal point if using raw pixel coordinates, 
    # but here we use normalized coordinates which implicitly handle aspect ratio 
    # if the image is square or if we assume standard NDC. 
    # For general case, we map normalized coords back to metric camera space.
    # x_metric = x_norm * (W-1)/2 * (1/fx) ? No, standard unprojection:
    # x_cam = (x_pixel - cx) / fx
    # y_cam = (y_pixel - cy) / fy
    # z_cam = depth
    
    # Re-calculate using pixel coordinates for robustness with arbitrary intrinsics
    x_pixel = j_coords.float()
    y_pixel = i_coords.float()
    
    x_cam = (x_pixel - cx.view(-1, 1, 1)) / fx.view(-1, 1, 1)
    y_cam = (y_pixel - cy.view(-1, 1, 1)) / fy.view(-1, 1, 1)
    z_cam = depth
    
    # Stack to (B, H, W, 3)
    points_camera = torch.stack([x_cam, y_cam, z_cam], dim=-1)
    
    # 5. Transform to World Space
    if extrinsics is not None:
        # Extrinsics is 4x4 matrix [R | t; 0 0 0 1]
        # R is 3x3, t is 3x1
        R = extrinsics[:, :3, :3] # (B, 3, 3)
        t = extrinsics[:, :3, 3] # (B, 3)
        
        # Reshape points_camera to (B, H*W, 3)
        points_camera_flat = points_camera.view(B, -1, 3)
        
        # Apply rotation: (B, 3, 3) @ (B, 3, N)^T -> (B, 3, N)
        # Or use matmul: (B, N, 3) @ (B, 3, 3)^T
        points_world_flat = torch.matmul(points_camera_flat, R.transpose(1, 2)) + t.view(-1, 1, 3)
        
        # Reshape back to (B, H, W, 3)
        points_world = points_world_flat.view(B, H, W, 3)
    else:
        points_world = points_camera
        
    return points_world
```

## Subtopics

### [Virtual Laser Scan for Point Cloud Generation](16278-virtual-laser-scan-for-point-cloud-generation.md)
A method to generate a point cloud with normals from a mesh by rendering normal and depth buffers from a specific camera viewpoint and reprojecting the buffer data into world space. It differs from direct mesh sampling by relying on rasterization to handle visibility and occlusion, effectively acting as a "virtual laser scan" from a single viewpoint. It builds on [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md) by providing the specific reprojection logic required to convert rendered buffers into 3D points.

## Operating characteristics
- **Time Complexity:** $O(H \times W)$ per view, as it involves a single pass over the depth map pixels [S3, unofficial].
- **Memory Complexity:** $O(H \times W)$ to store the output point cloud [S3, unofficial].
- **Performance:** Highly efficient on GPU due to parallelizable pixel-wise operations [S2, unofficial][S4].
- **Strengths:** Simple, differentiable (if depth is differentiable), and compatible with standard neural rendering pipelines [S4].
- **Limitations:** Sensitive to depth errors; noisy depth maps result in noisy point clouds [S4]. Requires accurate camera calibration [S2, unofficial].
- **When to use:** When constructing initial point clouds from estimated depth maps for novel view synthesis or 3D reconstruction [S4].
- **When not to use:** When high-precision geometric normals are required without post-processing (use [Virtual Laser Scan](16278-virtual-laser-scan-for-point-cloud-generation.md) for normals) or when dealing with non-planar projections without adjustment [S3, unofficial].

## Background
Originated from standard computer vision techniques for backprojecting depth maps to 3D space [S3, unofficial]. It is widely used in neural radiance fields (NeRF) and 3D Gaussian Splatting pipelines for initializing point clouds or converting rendered depth buffers to world coordinates [S1, S3, unofficial][S4]. The method is foundational in multi-view stereo and depth estimation evaluation [S1, unofficial].
