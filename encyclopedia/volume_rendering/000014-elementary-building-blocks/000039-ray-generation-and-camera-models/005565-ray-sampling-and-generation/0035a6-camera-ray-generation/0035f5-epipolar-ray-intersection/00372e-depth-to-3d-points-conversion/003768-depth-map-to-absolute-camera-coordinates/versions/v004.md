# Depth Map to Absolute Camera Coordinates
Also called: Depth Map Unprojection, depth2pc

## Overview
This method converts a 2D depth map, camera intrinsic parameters, and an optional camera pose (extrinsic parameters) into a 3D point cloud in absolute world coordinates [S1, S3, unofficial]. It solves the problem of backprojecting per-pixel depth measurements from image space into a global 3D reference frame [S2, unofficial]. It differs from sibling methods like [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing strictly on the geometric reprojection step, whereas the sibling also includes feature estimation and semantic fusion [S4]. It differs from [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md) by typically operating on variable-resolution depth maps without enforcing a fixed grid size during the initial unprojection [S3, unofficial].

## How it works
**Inputs:**
- Depth map $D'$ of size $H \times W$ (or batch $B \times H \times W$), where $d_{i,j}$ is the depth value at pixel $(i, j)$ [S3, unofficial].
- Camera intrinsic matrix $K$ (or focal lengths $f_x, f_y$ and principal point $c_x, c_y$) [S2, S3, unofficial].
- Camera extrinsic matrix $T_{cam2world}$ (rotation $R$ and translation $t$) [S1, S3, unofficial]. Optional; if absent, output is in camera space [S1, unofficial].

**Outputs:**
- 3D point cloud $D \in \mathbb{R}^{H \times W \times 3}$ (or $B \times H \times W \times 3$) representing world coordinates [S3, unofficial].

**Data Structures:**
- Pixel coordinates: 2D grid $(i, j)$ where $i \in [0, H-1]$ and $j \in [0, W-1]$ [S3, unofficial].
- Homogeneous coordinates: 4D vectors $[x, y, z, 1]^T$ [S3, unofficial].

**Steps:**

1. **Coordinate Normalization:**
   Normalize pixel indices to the range $[-1, 1]$ [S3, unofficial]:
   $$ x_{norm} = \frac{2j}{W-1} - 1 $$
   $$ y_{norm} = \frac{2i}{H-1} - 1 $$
   *Note:* Some implementations use a meshgrid from $0.5$ to $S-0.5$ to center coordinates on pixel centers before normalization [S2, unofficial].

2. **Camera Space Construction:**
   Form homogeneous coordinates in camera space $p_{camera}$ [S3, unofficial]:
   $$ p_{camera} = [x_{norm}, y_{norm}, d_{i,j}]^T $$
   Alternatively, using inverse depth for numerical stability in some pipelines:
   $$ z_{inv} = \frac{1}{d_{i,j} + \epsilon} $$
   where $\epsilon$ is a small constant (e.g., $10^{-8}$) to avoid division by zero [S2, unofficial].

3. **Depth Scaling (Optional/Variant):**
   If the depth map requires scaling based on the projection matrix elements $f_1, f_2$ (often corresponding to $f_x, f_y$ or specific calibration offsets), adjust the depth value $s_{d_{i,j}}$ [S3, unofficial]:
   $$ s_{d_{i,j}} = \frac{f_1 d_{i,j} + f_2}{d_{i,j}} $$
   The adjusted camera space coordinate becomes $p'_{camera} = [x_{norm}, y_{norm}, s_{d_{i,j}}]^T$ [S3, unofficial].
   *Note:* In standard pinhole models, this step is often implicit or handled by the intrinsic matrix inversion. If principal point offsets are used directly, subtract $c_x, c_y$ from $x, y$ and divide by $f_x, f_y$ [S2, unofficial].

4. **World Space Transformation:**
   If camera pose $T_{cam2world}$ is provided:
   - Extract rotation $R_{cam2world}$ and translation $t_{cam2world}$ [S1, unofficial].
   - Transform camera space points to world space [S1, unofficial]:
     $$ X_{world} = R_{cam2world} X_{cam} + t_{cam2world} $$
   - Alternatively, using the full inverse projection transform matrix $T$ (where $T$ is the inverse of the combined projection matrix):
     $$ p_{world} = T \times [x_{norm}, y_{norm}, s_{d_{i,j}}, 1]^T $$
     Then discard the homogeneous coordinate to get Cartesian coordinates [S3, unofficial]:
     $$ D = p'_{world} = \frac{p_{world}[0:3]}{p_{world}[3]} $$

5. **Reshaping:**
   Reshape the resulting points from the grid structure to a point cloud format (e.g., $B \times N \times 3$) [S2, unofficial].

**Pseudocode:**
```python
import numpy as np

def depth_map_to_absolute_camera_coordinates(depth_map, intrinsics, extrinsics=None):
    """
    Convert depth map to 3D world coordinates.
    
    Args:
        depth_map: np.ndarray of shape (H, W) or (B, H, W). Depth values.
        intrinsics: np.ndarray of shape (3, 3) or (B, 3, 3). Camera intrinsic matrix K.
        extrinsics: np.ndarray of shape (3, 4) or (B, 3, 4). Camera extrinsic matrix [R|t].
    
    Returns:
        points_world: np.ndarray of shape (H, W, 3) or (B, H, W, 3).
    """
    # Handle batch dimension
    if depth_map.ndim == 2:
        depth_map = depth_map[np.newaxis, ...]
        intrinsics = intrinsics[np.newaxis, ...]
        if extrinsics is not None:
            extrinsics = extrinsics[np.newaxis, ...]
    
    B, H, W = depth_map.shape
    
    # Create pixel coordinate grid
    # Using 0.5 offset to center on pixel
    j, i = np.meshgrid(np.arange(W) + 0.5, np.arange(H) + 0.5)
    
    # Normalize to [-1, 1] as per AtomGS [S3, unofficial]
    # Note: Some implementations skip this and use pixel coordinates directly with intrinsics [S2, unofficial]
    # Here we follow the explicit normalization step from [S3, unofficial]
    x_norm = (2 * j / (W - 1)) - 1
    y_norm = (2 * i / (H - 1)) - 1
    
    # Stack normalized coordinates
    # Shape: (B, H, W, 3)
    pts_camera_norm = np.stack([x_norm, y_norm, depth_map], axis=-1)
    
    # Apply depth scaling if required by specific intrinsic formulation [S3, unofficial]
    # Assuming intrinsics[0,0] is f_x and intrinsics[1,1] is f_y
    # This step is specific to the AtomGS formulation [S3, unofficial]
    f1 = intrinsics[:, 0, 0] # f_x
    f2 = intrinsics[:, 1, 1] # f_y
    # Avoid division by zero
    depth_safe = depth_map + 1e-8
    
    # Scale depth
    s_d = (f1[:, np.newaxis, np.newaxis] * depth_map + f2[:, np.newaxis, np.newaxis]) / depth_safe
    
    # Update z-component
    pts_camera_scaled = pts_camera_norm.copy()
    pts_camera_scaled[:, :, :, 2] = s_d
    
    # Transform to world coordinates
    if extrinsics is not None:
        # Extrinsics is [R|t] shape (3, 4)
        R = extrinsics[:, :3, :3] # (B, 3, 3)
        t = extrinsics[:, :3, 3] # (B, 3)
        
        # Convert to homogeneous (B, H, W, 4)
        pts_hom = np.concatenate([pts_camera_scaled, np.ones_like(pts_camera_scaled[..., :1])], axis=-1)
        
        # Matrix multiplication: R * X_cam + t
        # pts_camera_scaled is (B, H, W, 3)
        # R is (B, 3, 3)
        # Result: (B, H, W, 3)
        pts_world = np.einsum('bij,bhwj->bhiw', R, pts_camera_scaled) + t[:, np.newaxis, np.newaxis, :]
        
        return pts_world
    else:
        # Return camera space coordinates
        return pts_camera_scaled[..., :3]
```

**Edge Cases and Pitfalls:**
- **Zero Depth:** Division by zero occurs if $d_{i,j} = 0$. Use a small epsilon ($10^{-8}$) [S2, unofficial].
- **Invalid Pixels:** Depth maps often contain invalid values (e.g., 0, NaN, or max depth). These should be masked out or handled separately [S1, unofficial].
- **Coordinate System:** Ensure consistency between the depth map's coordinate system (e.g., Z-forward vs Z-backward) and the camera model [S2, unofficial].
- **Principal Point:** If using pixel coordinates directly, subtracting the principal point $(c_x, c_y)$ is required before dividing by focal lengths [S2, unofficial].

## Subtopics

### [Virtual Laser Scan for Point Cloud Generation](16278-virtual-laser-scan-for-point-cloud-generation.md)
A method to generate a point cloud with normals from a mesh by rendering normal and depth buffers from a specific camera viewpoint and reprojecting the buffer data into world space. It differs from direct mesh sampling by relying on rasterization to handle visibility and occlusion, effectively acting as a "virtual laser scan" from a single viewpoint. It builds on [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md) by providing the specific reprojection logic required to convert rendered buffers into 3D points.

## Operating characteristics
- **Time Complexity:** $O(H \times W)$ per image, as each pixel is processed independently [S3, unofficial].
- **Memory Complexity:** $O(H \times W \times 3)$ to store the resulting 3D points [S3, unofficial].
- **Performance:** Highly parallelizable on GPUs. Performance scales linearly with resolution [S3, unofficial].
- **Strengths:** Simple, deterministic, and efficient for converting dense depth maps to 3D [S3, unofficial].
- **Limitations:** Sensitive to noise in depth maps; invalid depth values lead to outliers in the point cloud [S1, unofficial]. Requires accurate intrinsics and extrinsics [S2, unofficial].

## Background
The method originates from the need to convert 2D sensor data (depth maps) into 3D representations for tasks like novel view synthesis and 3D reconstruction [S3, unofficial]. It is a fundamental building block in neural rendering pipelines, such as those using Gaussian Splatting [S3, unofficial] and neural point clouds [S4]. The specific normalization and scaling steps described in [S3, unofficial] are part of the AtomGS pipeline, while the inverse depth and meshgrid approaches are common in other frameworks like GPS_plus [S2, unofficial] and InstantSplat [S1, unofficial].
