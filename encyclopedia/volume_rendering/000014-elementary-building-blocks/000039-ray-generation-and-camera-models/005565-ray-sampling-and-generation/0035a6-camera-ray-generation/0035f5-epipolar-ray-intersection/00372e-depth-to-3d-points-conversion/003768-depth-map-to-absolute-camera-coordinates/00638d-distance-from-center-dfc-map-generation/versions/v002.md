# Distance-from-Center (DFC) Map Generation

Also called: DFC maps

## Overview
Distance-from-Center (DFC) map generation converts per-view depth maps into a global radial distance representation relative to a scene center [S1]. It solves the problem of separating foreground and background elements in outdoor scenes by providing a unified metric that is invariant to camera position [S1]. Unlike sibling methods that operate in local camera coordinates or raw point clouds, DFC maps express depth in a common global reference frame, enabling a single distance threshold to segment foreground and background regions across all views [S1].

## How it works
**Inputs:**
- Camera poses (extrinsics) for $N$ views [S1].
- Depth maps $D_v$ for each view $v$ [S1].
- Camera intrinsics (standard pinhole model) [G].

**Outputs:**
- A set of DFC maps, one per view, where each pixel stores the Euclidean distance from the unprojected 3D point to $O$ [S1].

**Data Structures:**
- **Scene Center $O$**: A 3D vector $(O_x, O_y, O_z)$ [G].
- **DFC Map $M_v$**: A 2D array of floats, same dimensions as $D_v$. $M_v(u, v)$ stores the distance [S1].

**Steps:**
1. For each view $v$ and each pixel $(u, v)$ in $D_v$:
   - Retrieve depth $d = D_v(u, v)$. If $d \le 0$ or invalid, mark $M_v(u, v)$ as invalid and continue [G].
   - Unproject $(u, v)$ and $d$ using intrinsics and the camera pose to obtain the 3D point $P$ in world coordinates [G].
2. Compute the Euclidean distance from $P$ to $O$:
   $$ \text{dist} = \| P - O \|_2 = \sqrt{(P_x - O_x)^2 + (P_y - O_y)^2 + (P_z - O_z)^2} $$
   [S1].
3. Store $\text{dist}$ in $M_v(u, v)$ [S1].

**Parameters:**
- **Scene Center $O$**: Not given in the sources.

**Edge Cases and Pitfalls:**
- **Invalid Depth**: Pixels with missing or non-positive depth must be excluded to prevent invalid distances [G].
- **Coordinate System Alignment**: Camera poses and depth maps must share the same world coordinate frame for $O$ to be valid [G].

**Pseudocode:**
```python
import numpy as np

def generate_dfc_maps(depth_maps, poses, intrinsics, scene_center):
    """
    depth_maps: list of 2D arrays, shape (H, W), depth in meters.
    poses: list of 4x4 arrays, camera-to-world transformation matrices.
    intrinsics: 3x3 array, camera intrinsic matrix K.
    scene_center: 1D array, shape (3,), coordinates of O.
    Returns: list of 2D arrays, DFC maps.
    """
    dfc_maps = []
    for depth_map, T_cam2world in zip(depth_maps, poses):
        H, W = depth_map.shape
        dfc_map = np.full((H, W), np.nan)
        u, v = np.meshgrid(np.arange(W), np.arange(H))
        # Unproject to camera space rays
        x_cam = (u - intrinsics[0, 2]) / intrinsics[0, 0]
        y_cam = (v - intrinsics[1, 2]) / intrinsics[1, 1]
        rays_cam = np.stack([x_cam, y_cam, np.ones_like(u)], axis=-1)
        # Transform to world space
        R = T_cam2world[:3, :3]
        rays_world = np.einsum('ijk,ljk->ijl', rays_cam, R)
        C_world = T_cam2world[:3, 3]
        # Filter valid depth
        valid = (depth_map > 0)
        P_world = np.zeros((H, W, 3))
        P_world[valid] = C_world + depth_map[valid, :, np.newaxis] * rays_world[valid]
        # Compute distance to scene center
        diff = P_world - scene_center[np.newaxis, np.newaxis, :]
        dists = np.sqrt(np.sum(diff**2, axis=-1))
        dfc_map[valid] = dists[valid]
        dfc_maps.append(dfc_map)
    return dfc_maps
```

## Subtopics

### Foreground-Background Segmentation via DFC Histogram
This variant uses the DFC maps to automatically determine a threshold for separating foreground and background [S1]. It estimates the histogram of DFC values from the original point cloud with a binning interval of 10 meters [S1]. The threshold $R_i$ is set at the first bin interval where the point count is less than 2.5% of the total reconstructed points [S1]. This threshold is then used to generate masked background images (removing foreground pixels) and filtered foreground points (keeping points within distance $R_i$ from the center) [S1]. The parameter $R_i$ is scene-dependent but the heuristic is robust; manual override is possible [S1]. Changing $R_i$ within reasonable ranges has minimal impact on novel view synthesis metrics but may affect reconstruction detail in moved regions [S1].

## Operating characteristics
- **Time Complexity**: $O(N \cdot H \cdot W)$, where $N$ is the number of views, and $H, W$ are image dimensions. Each pixel is processed once for unprojection and distance calculation [G].
- **Memory Complexity**: $O(N \cdot H \cdot W)$ to store the DFC maps [G].
- **Strengths**: Provides a global, view-invariant metric for depth, simplifying foreground/background segmentation in outdoor scenes [S1].
- **Limitations**: Relies on accurate depth maps and camera poses [G]. The heuristic for $R_i$ may fail in scenes with unusual depth distributions [G].
- **When to use**: Outdoor scene reconstruction where background separation is critical, such as in Gaussian Splatting with environment map baking [S1].
- **When not to use**: Indoor scenes with complex lighting or where global center is ambiguous [G].

## Background
The DFC map generation method was introduced in the context of EnvMap-GS, a two-stage outdoor Gaussian reconstruction method that bakes background into an environment map [S1]. It was proposed by D. Pintani et al. to address the challenge of separating foreground and background in outdoor scenes for 3D Gaussian Splatting [S1].
