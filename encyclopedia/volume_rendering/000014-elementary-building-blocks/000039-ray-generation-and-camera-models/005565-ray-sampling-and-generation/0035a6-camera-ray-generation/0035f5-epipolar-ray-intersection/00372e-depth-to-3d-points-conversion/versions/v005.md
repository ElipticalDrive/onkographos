# Depth to 3D Points Conversion

Also called: 3D Point Cloud Generation from Depth

## Overview
This method converts a 2D depth map and camera intrinsic parameters (specifically pseudo-focal lengths) into a 3D point cloud in absolute coordinates [S1, unofficial][S3]. It solves the problem of backprojecting per-pixel depth measurements from image space into a global 3D reference frame [S2]. It differs from sibling methods like [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing strictly on the geometric reprojection step, whereas the sibling also includes feature estimation and semantic fusion . It differs from [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md) by typically operating on variable-resolution depth maps without enforcing a fixed grid size during the initial unprojection [S3].

## How it works
**Inputs:**
*   `depth`: A depth map tensor of shape $(B, H, W)$ or $(B, H, W, n)$ [S1, unofficial].
*   `pseudo_focal`: Pseudo-focal length parameters of shape $[B, H, W]$, $[B, 2, H, W]$, or $[B, 1, H, W]$ [S1, unofficial].
*   `pp` (optional): Principal point coordinates. If `None`, defaults are used [S1, unofficial].

**Outputs:**
*   A 3D point cloud tensor where each point $(x, y, z)$ corresponds to a pixel in the input depth map [S1, unofficial].

**Data Structures:**
*   The output is a dense tensor of shape $(B, H, W, 3)$ containing the $(x, y, z)$ coordinates for every pixel [S1, unofficial].

**Steps:**
1.  **Extract Focal Lengths:** Parse `pseudo_focal` to extract horizontal ($f_x$) and vertical ($f_y$) focal lengths. If `pseudo_focal` has shape $[B, 2, H, W]$, split the second dimension into $f_x$ and $f_y$. If shape is $[B, 1, H, W]$ or $[B, H, W]$, assume $f_x = f_y = \text{pseudo\_focal}$ [S1, unofficial].
2.  **Generate Grid Coordinates:** Create a coordinate grid $(grid\_x, grid\_y)$ for the image dimensions $H \times W$. The coordinates typically range from $0$ to $W-1$ for $x$ and $0$ to $H-1$ for $y$ [S1, unofficial].
3.  **Adjust for Principal Point:** Calculate the principal point $(c_x, c_y)$. If `pp` is provided, use it. Otherwise, calculate the center of the image:
    $$c_x = \frac{W - 1}{2}, \quad c_y = \frac{H - 1}{2}$$
    Subtract these values from the grid coordinates:
    $$grid\_x' = grid\_x - c_x$$
    $$grid\_y' = grid\_y - c_y$$
    [S1, unofficial]
4.  **Compute 3D Coordinates:** For each pixel with depth $d$, compute the 3D coordinates $(x, y, z)$ in the camera coordinate system:
    $$x = d \cdot \frac{grid\_x'}{f_x}$$
    $$y = d \cdot \frac{grid\_y'}{f_y}$$
    $$z = d$$
    [S1, unofficial]

**Pseudocode:**
```python
import torch

def depth_to_3d_points(depth: torch.Tensor, pseudo_focal: torch.Tensor, pp: tuple = None) -> torch.Tensor:
    """
    Converts a depth map to 3D points in camera coordinates.
    
    Args:
        depth: Tensor of shape (B, H, W) or (B, H, W, n).
        pseudo_focal: Tensor of shape [B, H, W], [B, 2, H, W], or [B, 1, H, W].
        pp: Optional tuple (cx, cy) for principal point.
        
    Returns:
        Points tensor of shape (B, H, W, 3).
    """
    # 1. Extract focal lengths
    if pseudo_focal.dim() == 4:
        if pseudo_focal.shape[1] == 2:
            fx = pseudo_focal[:, 0, :, :]
            fy = pseudo_focal[:, 1, :, :]
        else:
            # Assume single focal length or broadcastable
            fx = pseudo_focal[:, 0, :, :]
            fy = fx
    else:
        fx = pseudo_focal
        fy = fx

    B, H, W = depth.shape[:3]
    
    # 2. Generate grid coordinates
    # Create meshgrid: x ranges 0..W-1, y ranges 0..H-1
    y_coords, x_coords = torch.meshgrid(
        torch.arange(H, device=depth.device),
        torch.arange(W, device=depth.device),
        indexing='ij'
    )
    
    # 3. Adjust for principal point
    if pp is not None:
        cx, cy = pp
    else:
        cx = (W - 1) / 2.0
        cy = (H - 1) / 2.0
        
    x_coords = x_coords - cx
    y_coords = y_coords - cy
    
    # Expand dimensions to match depth for broadcasting
    # depth shape: (B, H, W)
    # x_coords, y_coords shape: (H, W)
    # We need to broadcast them to (B, H, W)
    
    # 4. Compute 3D coordinates
    # x = depth * grid_x / fx
    # y = depth * grid_y / fy
    # z = depth
    
    # Ensure depth is float32 for precision
    depth_f = depth.float()
    
    # Broadcast x_coords and y_coords to (B, H, W)
    # x_coords is (H, W), expand to (1, H, W) then to (B, H, W)
    x_coords_exp = x_coords.unsqueeze(0).expand(B, -1, -1)
    y_coords_exp = y_coords.unsqueeze(0).expand(B, -1, -1)
    
    # Handle fx, fy broadcasting if they are (B, H, W)
    # If pseudo_focal was (B, H, W), fx/fy are already (B, H, W)
    
    x = depth_f * x_coords_exp / fx
    y = depth_f * y_coords_exp / fy
    z = depth_f
    
    # Stack into (B, H, W, 3)
    points = torch.stack([x, y, z], dim=-1)
    
    return points
```

**Parameters:**
*   `pseudo_focal`: Represents the focal length. In some implementations, this is derived from image dimensions assuming a square pixel aspect ratio and center principal point, hence "pseudo" [S1, unofficial].
*   `depth`: The input depth values. Must be metric depth (e.g., meters) if the output is to be in metric units [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Depth:** Pixels with $depth=0$ will result in $(0,0,0)$, which may be invalid if the camera origin is not at $(0,0,0)$ in the final world frame.
*   **Principal Point:** If the camera's principal point is not at the image center, failing to provide `pp` will introduce geometric distortion [S1, unofficial].
*   **Coordinate System:** This method outputs points in the **camera coordinate system**. To get world coordinates, an extrinsic transformation (rotation and translation) must be applied to the resulting points [S3].

## Subtopics

### [Depth Map to Absolute Camera Coordinates](7984-depth-map-to-absolute-camera-coordinates.md)
This method converts a 2D depth map, camera intrinsic parameters, and an optional camera pose (extrinsic parameters) into a 3D point cloud in absolute world coordinates. It solves the problem of backprojecting per-pixel depth measurements from image space into a global 3D reference frame. It differs from sibling methods like [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by focusing strictly on the geometric reprojection step, whereas the sibling also includes feature estimation and semantic fusion. It differs from [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md) by typically operating on variable-resolution depth maps without enforcing a fixed grid size during the initial unprojection.

### [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md)
An offline process that generates and refines a 3D point cloud from a subset of training images to improve depth estimation accuracy for novel views in neural rendering. It differs from standard Multi-View Stereo (MVS) by iteratively validating points against ground-truth depth from adjacent views, allowing it to generate a denser, more accurate point cloud for similar computational time, which leads to higher rendering quality (PSNR).

### [Fixed-size initialization from RGB-D backprojection](10155-fixed-size-initialization-from-rgb-d-backprojection.md)
This method generates a fixed-size, colored 3D point cloud initialization for volume rendering primitives by backprojecting RGB-D data. It differs from its parent [Depth to 3D Points Conversion](7929-depth-to-3d-points-conversion.md) by applying explicit downsampling factors and stride ratios to control point density, and from its sibling [Point Cloud Generation and Refinement](8042-point-cloud-generation-and-refinement.md) by relying on direct geometric backprojection rather than implicit field refinement.

### Global Scene Point Cloud Construction
This variant constructs a global scene point cloud $P \in \mathbb{R}^{N_p \times 3}$ in world coordinates by unprojecting pixels from $N$ calibrated images using intrinsic matrices $\{K_n\}_{n=1}^N$ and extrinsic matrices $\{T_n = R_n | t_n\}_{n=1}^N$ [S3]. It solves the problem of accumulating sparse, noisy depth estimates from multiple views into a single coherent 3D structure [S3]. It differs from single-view conversion by handling multi-view consistency and redundancy [S3].
**Steps:**
1.  **Unprojection:** For each image $n$, unproject pixels using the formula:
    $$\mathcal {P}=\bigcup ^N \mathbf {\pi }^{-1}\left (I_n, D_n, \mathbf {T}_n, \mathbf {K}_n\right )$$
    where $\pi^{-1}$ denotes pixel unprojection, $I_n$ is the image, $D_n$ is the depth, $T_n$ is the extrinsic matrix, and $K_n$ is the intrinsic matrix [S3].
2.  **Uniform Filtering:** Apply a uniform filter in 3D space to the raw points $P$ to delete duplicate primitives while keeping the scene structure [S3].
3.  **Statistical Filtering:** Apply a statistical filter to remove floaters (noise) from the processed primitives [S3].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels in the depth map, as the operation is a per-pixel arithmetic calculation [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store the resulting 3D point cloud tensor [S1, unofficial].
*   **Strengths:** Simple, differentiable (if implemented with floating-point arithmetic), and efficient for generating initial point clouds for neural rendering or Gaussian Splatting [S1, unofficial][S3].
*   **Limitations:** Produces noisy points directly from depth maps; requires post-processing (filtering) for clean geometry [S3]. Does not handle occlusions or multi-view consistency inherently [S3].
*   **When to use:** When initializing point-based representations (like 3D Gaussian Splatting) from monocular or stereo depth estimates [S1, unofficial][S3].
*   **When not to use:** When high-precision geometric reconstruction is required without additional filtering or refinement steps [S3].

## Background
The method originates from the need to initialize 3D representations for neural rendering and Gaussian Splatting from 2D depth predictions [S1, unofficial][S3]. It was popularized in frameworks like InstantSplat, which uses pseudo-focal lengths to backproject depth maps into 3D space for training generalizable models [S1, unofficial]. The concept of unprojecting depth maps into point clouds is fundamental to Multi-View Stereo (MVS) and has been adapted for neural rendering pipelines to provide explicit geometric priors [S2, S3].
