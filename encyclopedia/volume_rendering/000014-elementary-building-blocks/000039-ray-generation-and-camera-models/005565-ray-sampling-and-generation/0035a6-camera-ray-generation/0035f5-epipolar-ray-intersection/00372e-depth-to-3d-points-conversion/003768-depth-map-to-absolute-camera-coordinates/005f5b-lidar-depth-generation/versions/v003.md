# Lidar Depth Generation

## Overview
Lidar Depth Generation converts accumulated 3D LiDAR points into pixel-aligned depth maps for synchronized RGB images [S1]. It projects LiDAR points from multiple time steps onto the 2D image plane, selecting the nearest point per pixel to handle sparsity [S1].

## How it works
**Inputs:**
- Target image frame timestamp [S1].
- Camera intrinsics $K$ (3×3 matrix) [G].
- Camera-to-world pose $T_{cam}^{world}$ (4×4 matrix) [G].
- Set of LiDAR frames, each containing a timestamp, 3D points in sensor coordinates, and LiDAR-to-world pose $T_{lidar}^{world}$ (4×4 matrix) [G].
- Image dimensions $H \times W$ [G].

**Outputs:**
- Depth map $D$ of size $H \times W$, where $D_{u,v}$ is the depth value for pixel $(u, v)$ [G].

**Data Structures:**
- Depth map: 2D array initialized to infinity to indicate no depth [G].

**Steps:**
1. Select the 10 closest LiDAR frames to the target image frame [S1].
2. Transform the selected LiDAR points into world coordinates [S1].
3. Project the world-coordinate LiDAR points onto the image coordinates [S1].
4. Compute the depth value as the distance along the ray from the camera center to each LiDAR point [S1].
5. When multiple LiDAR points project to the same pixel, derive the depth value from the nearest LiDAR point [S1].

**Formulas:**
- Camera-relative point: $p_{cam} = T_{cam}^{world^{-1}} p_{world}$ [G].
- Pixel coordinates: $u = \frac{K_{00} p_{cam,x} + K_{02}}{p_{cam,z}}$, $v = \frac{K_{11} p_{cam,y} + K_{12}}{p_{cam,z}}$ [G].
- Depth: $d = \|p_{cam}\|_2 = \sqrt{p_{cam,x}^2 + p_{cam,y}^2 + p_{cam,z}^2}$ [G].
- Aggregation: $D_{u,v} = \min(D_{u,v}, d)$ [G].

**Pseudocode:**
```python
def generate_lidar_depth(image_timestamp, K, cam_pose, lidar_frames, image_height, image_width, num_frames=10):
    # 1. Select closest frames
    time_diffs = [(abs(frame[0] - image_timestamp), i) for i, frame in enumerate(lidar_frames)]
    time_diffs.sort(key=lambda x: x[0])
    selected_frames = [lidar_frames[idx] for _, idx in time_diffs[:num_frames]]
    
    # Initialize depth map with infinity
    depth_map = [[float('inf')] * image_width for _ in range(image_height)]
    
    # Inverse camera pose
    cam_inv = invert_4x4(cam_pose)  # Standard linear algebra [G]
    
    for frame in selected_frames:
        _, points, lidar_pose = frame
        for p in points:
            # 2. Transform to world coordinates
            p_homo = [p[0], p[1], p[2], 1.0]
            w_p = [sum(lidar_pose[i][j] * p_homo[j] for j in range(4)) for i in range(4)]
            p_world = w_p[:3]
            
            # 3. Project to image coordinates
            w_p_homo = [p_world[0], p_world[1], p_world[2], 1.0]
            c_p_homo = [sum(cam_inv[i][j] * w_p_homo[j] for j in range(4)) for i in range(4)]
            p_cam = c_p_homo[:3]
            
            if p_cam[2] <= 0:
                continue
            
            u = (K[0][0] * p_cam[0] + K[0][2]) / p_cam[2]
            v = (K[1][1] * p_cam[1] + K[1][2]) / p_cam[2]
            
            if 0 <= u < image_width and 0 <= v < image_height:
                # 4. Compute depth
                d = (p_cam[0]**2 + p_cam[1]**2 + p_cam[2]**2)**0.5
                
                # 5. Update depth map with minimum depth
                ui, vi = int(u), int(v)
                if d < depth_map[vi][ui]:
                    depth_map[vi][ui] = d
    return depth_map
```

**Edge Cases:**
- **No LiDAR points:** If no points project to a pixel, the depth remains infinity [S1].
- **Multiple points:** The nearest point (smallest depth) is chosen, handling occlusions [S1].
- **Precision:** Floating-point precision in depth calculation should be sufficient to distinguish close points [G].

## Subtopics

### [LiDAR Ray Simulation](18371-lidar-ray-simulation.md)
Simulates real LiDAR sensor rays by defining ray origin and direction based on sensor parameters and ego-vehicle motion to generate 3D points. It differs from standard ray casting by explicitly modeling the temporal evolution of the sensor origin due to vehicle velocity and incorporating a learned "raydrop" probability to mimic real-world signal loss, rather than assuming perfect reflection.

## Operating characteristics
- **Time Complexity:** $O(N \cdot W)$, where $N$ is the number of LiDAR points in the selected frames and $W$ is the number of frames [G]. Projection and aggregation are linear in the number of points [G].
- **Memory Complexity:** $O(H \cdot W)$ for the depth map, plus storage for the selected LiDAR points [G].
- **Strengths:** Provides accurate depth supervision by leveraging LiDAR's direct range measurement [G]. Handles sparse LiDAR data by accumulating points over time [S1].
- **Limitations:** Requires synchronized LiDAR and camera data [G]. Performance depends on the density of LiDAR points and the number of frames used [G]. Occlusions may still result in missing depth if the nearest point is not captured [G].
- **When to use:** When generating depth maps for neural rendering or vision tasks where LiDAR data is available but sparse [G].
- **When not to use:** When real-time performance is critical and LiDAR data is not available or too sparse [G].

## Background
Lidar Depth Generation is a technique used in datasets like PandaSet to provide depth supervision for neural radiance fields and vision tasks [S1]. It addresses unbounded scenes by normalizing the scene based on the camera trajectory radius [S1].
