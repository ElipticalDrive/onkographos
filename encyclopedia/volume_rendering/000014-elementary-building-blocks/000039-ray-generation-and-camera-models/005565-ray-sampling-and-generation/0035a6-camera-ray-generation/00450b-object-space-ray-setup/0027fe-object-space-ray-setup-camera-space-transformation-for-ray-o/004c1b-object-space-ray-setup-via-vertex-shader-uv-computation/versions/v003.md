# Object Space Ray Setup via Vertex Shader UV Computation

Also called: GPU Raycasting (Vertex Shader UV Computation), Raycasting Bounding Box & Sample Position Setup, Vertex Shader UV Computation

## Overview
This method establishes the geometric foundation for GPU-based volume raycasting by mapping a 3D bounding box to screen space while simultaneously computing normalized 3D texture coordinates for each fragment [S1, unofficial]. It solves the problem of translating object-space vertex positions into both clip-space positions for rasterization and valid texture lookup coordinates for the fragment shader [S2, unofficial]. It differs from camera-space ray setup [4179-object-space-ray-setup-camera-space-transformation-for-ray-o.md] by operating directly on object-space vertices and using hardware interpolation of 3D UVs, rather than computing ray origins and directions in camera space [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Object-space vertex positions (`vVertex`), Model-View-Projection matrix (`MVP`) [S2, unofficial].
*   **Output:** Clip-space position (`gl_Position`), 3D texture coordinates (`vUV`) [S2, unofficial].

**Data Structures:**
*   **Vertex Buffer Object (VBO):** Stores vertex positions with layout `totalVertices * sizeof(glm::vec3)` [S2, unofficial].
*   **Index Buffer Object (IBO):** Stores triangle indices with layout `totalIndices * sizeof(GLuint)` [S2, unofficial].
*   **Vertex Array Object (VAO):** Binds the VBO and IBO, enabling the vertex attribute array for `vVertex` at location 0 with 3 components, `GL_FLOAT`, normalized false, stride 0, offset 0 [S2, unofficial].

**Steps:**
1.  **Buffer Initialization:** Generate and bind a VAO [S2, unofficial]. Allocate memory for vertices and indices [S2, unofficial]. Fill the vertex buffer with the bounding box geometry (e.g., a cube centered at the origin with bounds $[-0.5, 0.5]$) [S2, unofficial]. Fill the index buffer with triangle indices [S2, unofficial]. Enable the vertex attribute array for `vVertex` and bind the index buffer [S2, unofficial].
2.  **Vertex Shader Execution:** For each vertex, compute the clip-space position by multiplying the MVP matrix with the homogeneous vertex position:
    $$ \text{gl\_Position} = \text{MVP} \times \begin{bmatrix} \text{vVertex}.xyz \\ 1.0 \end{bmatrix} $$
    [S2, unofficial]. Compute the 3D texture coordinates by adding $0.5$ to each component of the object-space vertex position, shifting the range from $[-0.5, 0.5]$ to $[0.0, 1.0]$ for normalized texture lookups:
    $$ \text{vUV} = \text{vVertex}.xyz + 0.5 $$
    [S2, unofficial]. Declare `vUV` as `smooth out vec3` to enable hardware interpolation across the primitive [S2, unofficial].
3.  **Fragment Shader Input:** The fragment shader receives the interpolated `vUV` values, which represent the position within the volume texture space for direct sampling [S2, unofficial].

**Pseudocode:**
```python
def compute_vertex_setup(vVertex: tuple[float, float, float], MVP: list[list[float]]) -> tuple[tuple[float, float, float, float], tuple[float, float, float]]:
    """
    Computes clip-space position and 3D texture coordinates for a single vertex.
    
    Args:
        vVertex: Object-space vertex position (x, y, z).
        MVP: Combined Model-View-Projection matrix (4x4 list of lists).
        
    Returns:
        gl_Position: Clip-space position (x, y, z, w).
        vUV: 3D texture coordinates (u, v, w).
    """
    # Homogeneous vertex position
    vertex_h = (vVertex[0], vVertex[1], vVertex[2], 1.0)
    
    # Matrix-vector multiplication for clip space
    gl_Position = tuple(
        sum(MVP[row][col] * vertex_h[col] for col in range(4))
        for row in range(4)
    )
    
    # Shift unit cube coordinates from [-0.5, 0.5] to [0, 1]
    vUV = (vVertex[0] + 0.5, vVertex[1] + 0.5, vVertex[2] + 0.5)
    
    return gl_Position, vUV
```

**Parameters:**
*   `MVP`: Combined Model-View-Projection matrix, passed as a `uniform mat4` [S2, unofficial].
*   `vVertex`: Object-space vertex position, declared as `layout(location = 0) in vec3` [S2, unofficial].
*   `vUV`: 3D texture coordinates, declared as `smooth out vec3` in the vertex shader and `smooth in vec3` in the fragment shader [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Coordinate Range:** The unit cube is typically centered at the origin with bounds $[-0.5, -0.5, -0.5]$ to $[0.5, 0.5, 0.5]$ [S2, unofficial]. Failing to add $0.5$ to the vertex coordinates will result in texture coordinates outside the $[0, 1]$ range, causing incorrect sampling or clamping artifacts [S2, unofficial].

## Background
This method is used in GPU-based volume raycasting implementations, particularly in educational and open-source projects [S1, unofficial][S2, unofficial]. It relies on standard OpenGL features such as vertex shaders, fragment shaders, and texture sampling [S2, unofficial]. The approach of using a unit cube and shifting coordinates is a common technique in computer graphics for simplifying texture coordinate generation [G].
