# Deterministic LCG Noise Generation

Also called: LCG, Linear Congruential Generator, Rng

## Overview
Deterministic LCG Noise Generation is a pseudo-random number generator that produces normalized floating-point values in the range $[-1, 1]$ using linear congruential recurrence and bit-shifting normalization [S1, S2, unofficial]. It is used in volume rendering to provide deterministic noise for ray origin offsetting, thereby avoiding banding artifacts during ray marching [Parent]. It differs from hash-based pseudo-random number generators by relying on sequential state updates rather than spatial hashing, and from incremental random number generation methods by its fixed modular arithmetic structure [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A seed value representing the initial state [S1, S2, unofficial].
*   **Output:** A normalized float $v$ in the range $[-1, 1)$ or $[-1, 1]$ depending on the variant [S1, S2, unofficial].

**Data Structures:**
The generator maintains a single state variable [S1, S2, unofficial]. Two variants are documented:
1.  **32-bit variant:** A single 32-bit unsigned integer (`u32`) state field [S1, unofficial].
2.  **64-bit variant:** A single 64-bit unsigned integer (`u64`) state field [S2, unofficial].

**Parameters:**
*   **32-bit constants:** Multiplier $a = 1664525$, Increment $c = 1013904223$ [S1, unofficial].
*   **64-bit constants:** Multiplier $a = 6364136223846793005$, Increment $c = 1442695040888963407$ [S2, unofficial]. These are the Numerical Recipes constants [S2, unofficial].
*   **Modulus:** Implicitly $2^{32}$ for the 32-bit variant and $2^{64}$ for the 64-bit variant, implemented via wrapping arithmetic [S1, S2, unofficial].

**Steps:**
1.  **Update State:** Compute the next state using the linear congruential formula:
    $$x_{n+1} = (x_n \cdot a + c) \pmod M$$
    where $M = 2^{32}$ or $2^{64}$, and arithmetic is performed with wrapping (modulo $2^k$) [S1, S2, unofficial].
2.  **Extract Bits:**
    *   For the 32-bit variant: Shift the state right by 8 bits (`state >> 8`) to extract the top 24 bits [S1, unofficial].
    *   For the 64-bit variant: Shift the state right by 40 bits (`state >> 40`) to extract the top 24 bits [S2, unofficial].
3.  **Normalize:** Convert the extracted integer bits to a float in $[-1, 1)$ [S1, S2, unofficial].
    *   For the 32-bit variant: Scale the 24-bit integer to $[0, 1)$ and then to $[-1, 1]$ via $v = (\text{bits} / 2^{24}) \cdot 2.0 - 1.0$ [S1, unofficial].
    *   For the 64-bit variant: Cast the shifted value to `f32` and divide by $8388608.0$ ($2^{23}$), then subtract 1.0: $v = (\text{bits} / 8388608.0) - 1.0$ [S2, unofficial].

**Pseudocode:**
```python
def lcg_noise_32(seed: int) -> float:
    """
    32-bit LCG noise generation as described in [S1, unofficial].
    Produces values in [-1, 1].
    """
    state = seed & 0xFFFFFFFF
    # Step 1: Update state with wrapping arithmetic
    state = (state * 1664525 + 1013904223) & 0xFFFFFFFF
    # Step 2: Extract top 24 bits
    bits = state >> 8
    # Step 3: Normalize to [-1, 1]
    val = (bits / 16777216.0) * 2.0 - 1.0
    return val

def lcg_noise_64(seed: int) -> float:
    """
    64-bit LCG noise generation as described in [S2, unofficial].
    Produces values in [-1, 1).
    Uses Numerical Recipes constants.
    """
    state = seed & 0xFFFFFFFFFFFFFFFF
    # Step 1: Update state with wrapping arithmetic
    state = (state * 6364136223846793005 + 1442695040888963407) & 0xFFFFFFFFFFFFFFFF
    # Step 2: Extract top 24 bits
    bits = state >> 40
    # Step 3: Normalize to [-1, 1)
    val = (bits / 8388608.0) - 1.0
    return val
```

**Edge Cases and Pitfalls:**
*   **Precision:** The 64-bit variant casts to `f32` after shifting, which preserves the top 24 bits but discards lower precision [S2, unofficial].
*   **Range:** The 32-bit variant is described as producing values in $[-1, 1]$ [S1, unofficial], while the 64-bit variant produces $[-1, 1)$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample [G].
*   **Memory Complexity:** $O(1)$ state storage (32 or 64 bits) [S1, S2, unofficial].
*   **Strengths:** Deterministic state progression and minimal state storage [S1, S2, unofficial].
*   **Limitations:** Not given in the sources.
*   **When to use:** Suitable for simple noise generation where high statistical quality is not critical, or for ray origin offsetting where speed is paramount [Parent, S1, S2, unofficial].
*   **When not to use:** Not given in the sources.

## Background
The 32-bit variant is used in a voxel game engine for procedural generation tasks [S1, unofficial]. The 64-bit variant uses constants from Numerical Recipes and is used in a portable reimplementation of Ken Silverman's engine for procedural sound synthesis [S2, unofficial]. The method is a standard technique in computer graphics for generating pseudo-random numbers [G].
