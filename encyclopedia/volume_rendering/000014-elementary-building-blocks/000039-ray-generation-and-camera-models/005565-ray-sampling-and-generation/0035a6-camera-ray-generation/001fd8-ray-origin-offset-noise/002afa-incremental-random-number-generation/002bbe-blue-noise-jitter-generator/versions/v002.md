# Blue Noise Jitter Generator
Also called: Void-and-Cluster Blue Noise

## Overview
The Blue Noise Jitter Generator produces offsets for ray sampling by combining a precomputed low-discrepancy lookup table, a golden-ratio-based temporal shift, and a Halton sequence for subpixel jitter [S1, unofficial].

## How it works
**Inputs:**
- Pixel coordinates $(x, y)$ (floats) [S1, unofficial].
- Frame index $f$ (integer, $\ge 0$) [S1, unofficial].
- Table size $N$ (default 64) [S1, unofficial].

**Outputs:**
- A single jitter value $j \in [0, 1)$ [S1, unofficial].

**Data Structures:**
- `table`: A 1D array of size $N \times N$ (default $64 \times 64 = 4096$) [S1, unofficial].
- Each entry `table[i]` stores a float in $[0, 1)$ [S1, unofficial].

**Initialization:**
The table is initialized using a low-discrepancy sequence based on the golden ratio [S1, unofficial]:
$$ \phi = 0.618033988749895 $$
$$ \text{table}[i] = (i \times \phi) \pmod{1.0}, \quad \text{for } i = 0, \dots, N^2-1 $$
[S1, unofficial] In floating-point arithmetic, this is typically implemented as `i * phi - floor(i * phi)` [G].

**Step 1: Spatial Base Offset**
Determine the spatial index within the table based on pixel coordinates [S1, unofficial]:
$$ p_x = |\lfloor x \rfloor| \pmod N $$
$$ p_y = |\lfloor y \rfloor| \pmod N $$
$$ \text{baseOffset} = \text{table}[p_y \times N + p_x] $$
[S1, unofficial] Absolute value is used to handle negative pixel coordinates gracefully, mapping them to valid table indices [G].

**Step 2: Temporal Shift**
Compute a temporal shift that evolves over frames to ensure temporal coherence [S1, unofficial]:
$$ \text{temporalShift} = ((f \pmod{16}) \times \phi) \pmod{1.0} $$
[S1, unofficial] The modulo 16 ensures the temporal sequence repeats every 16 frames, providing a balance between coherence and variation [G].

**Step 3: Subpixel Jitter (Halton Sequence)**
Generate subpixel jitter using the Halton sequence with bases 2 and 3 [S1, unofficial]:
$$ h_2 = \text{Halton}(f + 1, 2) - 0.5 $$
$$ h_3 = \text{Halton}(f + 1, 3) - 0.5 $$
[S1, unofficial] The Halton sequence is defined as:
$$ \text{Halton}(index, base) = \sum_{k=1}^{\infty} \frac{d_k}{base^k} $$
where $d_k$ are the digits of $index$ in base $base$ [G].

**Step 4: Final Jitter**
Combine the components [S1, unofficial]:
$$ j = (\text{baseOffset} + \text{temporalShift}) \pmod{1.0} $$
[S1, unofficial] The sources do not specify how $h_2$ and $h_3$ are combined into the final output $j$ [S1, unofficial]. If a single scalar jitter is required, it may be derived from $h_2$ or $h_3$ alone, or combined via a hash [G].

**Pseudocode:**
```python
import math

def blue_noise_jitter(x: float, y: float, frame_index: int, table_size: int = 64) -> float:
    phi = 0.618033988749895
    # Module-level table initialization (assumed persistent)
    if not hasattr(blue_noise_jitter, 'table'):
        blue_noise_jitter.table = [0.0] * (table_size * table_size)
        for i in range(table_size * table_size):
            blue_noise_jitter.table[i] = (i * phi) % 1.0
    table = blue_noise_jitter.table
    px = abs(math.floor(x)) % table_size
    py = abs(math.floor(y)) % table_size
    base_offset = table[py * table_size + px]
    temporal_shift = ((frame_index % 16) * phi) % 1.0
    return (base_offset + temporal_shift) % 1.0

def halton(index: int, base: int) -> float:
    result = 0.0
    f = 1.0 / base
    i = index
    while i > 0:
        result += f * (i % base)
        i = i // base
        f = f / base
    return result
```

## Subtopics

### Blue Noise Sampling
A technique for sampling pre-generated 3D blue noise textures using integer indexing and normalization [S2, unofficial].
- **Steps:**
  1. Scale the input position by the resolution: $pos \times res$ [S2, unofficial].
  2. Cast components to unsigned integers: $index.x = \lfloor pos.x \rfloor$, $index.y = \lfloor pos.y \rfloor$, $index.z = \lfloor pos.z \rfloor$ [S2, unofficial].
  3. Set $index.w$ to the channel number [S2, unofficial].
  4. Retrieve the value from the texture cache and normalize: $value / 256.0$ [S2, unofficial].
- **Parameters:**
  - $res$: Resolution of the blue noise texture (16, 32, or 64) [S2, unofficial].
  - $channel$: Channel index (0-3 for RGBA) [S2, unofficial].
- **Pitfalls:** The resolution must match the loaded texture exactly [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for the main lookup and arithmetic, with $O(\log_{base}(index))$ for the Halton sequence [G].
- **Memory Complexity:** $O(N^2)$ for the lookup table, defaulting to 4096 floats for $N=64$ [S1, unofficial].
- **Performance:** The method avoids transcendental functions in the main path, making it suitable for real-time rendering [G].
- **Limitations:** The temporal sequence repeats every 16 frames, which may cause visible patterns in long animations [S1, unofficial].

## Background
The method is implemented in real-time volumetric cloud rendering code [S1, unofficial]. It leverages the golden ratio for low-discrepancy sequences, a technique common in quasi-Monte Carlo methods [G]. The blue noise sampling variant is described in a volume noise generator repository [S2, unofficial].
