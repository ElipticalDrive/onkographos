# Viewing Plane Ray Generation
Also called: Projection Plane Raycasting

## Overview
Viewing Plane Ray Generation constructs the initial rays for volume rendering by defining a projection plane parallel to the scanline and casting rays in the viewing direction within that plane [S1]. It serves as the geometric foundation for orthographic ray casting, where ray origins are distributed across a 2D grid and all rays share a single normalized direction [S1][S2, unofficial]. This method generates parallel rays, contrasting with perspective ray generation which supports non-parallel viewing [S4, unofficial].

## How it works
**Inputs:**
- Image resolution: $W \times H$ (width, height) [G].
- Viewing direction vector: $\mathbf{d}_{view}$ (normalized) [G].
- Transformation matrix: $\mathbf{M}$ (combined translation, rotation, and scaling) [S2, unofficial].
- Camera scale factor: $S_{cam}$ (typically 0.25) [S2, unofficial].
- Sample period: $P_{sample}$ (typically 2.0) [S2, unofficial].

**Outputs:**
- A set of rays, each defined by an origin $\mathbf{o}_{i,j}$ and direction $\mathbf{d}_{ray}$ [G].

**Data Structures:**
- `ViewingPlane`: A 2D grid of size $W \times H$ [S2, unofficial].
- `m_data`: A `std::vector<vec3>` of size $W \times H$. Each element at index $k = i + j \cdot W$ stores a 2D screen coordinate normalized to $[-1, 1]$ for $x$ and $y$, with $z=0$ [S2, unofficial].
- `m_mat`: The combined transformation matrix $\mathbf{M}$ [S2, unofficial].

**Steps:**

1. **Initialize Normalized Grid Points:**
   For each pixel $(i, j)$ where $0 \le i < W$ and $0 \le j < H$:
   $$ x_{norm} = \frac{2(i + 0.5)}{W} - 1 $$
   $$ y_{norm} = \frac{2(j + 0.5)}{H} - 1 $$
   Store $\mathbf{p}_{norm} = [x_{norm}, y_{norm}, 0]^T$ in `m_data` at index $k$ [S2, unofficial].

2. **Compute Ray Direction:**
   Define three reference points in local space:
   - Origin $\mathbf{a} = [0, 0, 0]^T$
   - Rightmost $\mathbf{b} = [1, 0, 0]^T$
   - Upmost $\mathbf{c} = [0, 1, 0]^T$
   
   Transform these points using $\mathbf{M}$:
   $$ \mathbf{a}' = \mathbf{M} \mathbf{a} $$
   $$ \mathbf{b}' = \mathbf{M} \mathbf{b} $$
   $$ \mathbf{c}' = \mathbf{M} \mathbf{c} $$
   
   Compute the ray direction as the normalized cross product of the transformed right and up vectors:
   $$ \mathbf{d}_{ray} = \text{normalize}(\text{cross}(\mathbf{b}' - \mathbf{a}', \mathbf{c}' - \mathbf{a}')) $$
   [S2, unofficial]

3. **Compute Ray Origins:**
   For each pixel $(i, j)$ with normalized coordinate $\mathbf{p}_{norm} = [x_{norm}, y_{norm}, 0]^T$:
   - Scale the coordinate by $S_{cam}$:
     $$ \mathbf{p}_{scaled} = [x_{norm} \cdot S_{cam}, y_{norm} \cdot S_{cam}, 0]^T $$
   - Transform $\mathbf{p}_{scaled}$ by $\mathbf{M}$ to get the world-space origin:
     $$ \mathbf{o}_{i,j} = \mathbf{M} \mathbf{p}_{scaled} $$
   [G]

4. **Cast Rays:**
   For each pixel $(i, j)$, cast a ray $\mathbf{r}(t) = \mathbf{o}_{i,j} + t \cdot \mathbf{d}_{ray}$ into the volume data [G]. Resample volume data planes in top-to-bottom order and cast rays in the viewing direction inside the projection planes to produce the image [S1].

**Pseudocode:**

```python
def generate_viewing_plane_rays(W, H, M, S_cam=0.25, P_sample=2.0):
    """
    Generate rays for an orthographic viewing plane.
    
    Args:
        W: Image width
        H: Image height
        M: 4x4 transformation matrix (translation * rotation * scaling)
        S_cam: Camera scale factor
        P_sample: Sample period (used in ray marching, not generation)
        
    Returns:
        origins: List of vec3, size W*H
        directions: List of vec3, size W*H (all identical)
    """
    def cross(u, v):
        return (u[1]*v[2] - u[2]*v[1], u[2]*v[0] - u[0]*v[2], u[0]*v[1] - u[1]*v[0])

    def normalize(v):
        mag = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
        if mag == 0: return (0.0, 0.0, 0.0)
        return (v[0]/mag, v[1]/mag, v[2]/mag)

    def mat_vec_mul(M, v):
        return (
            M[0][0]*v[0] + M[0][1]*v[1] + M[0][2]*v[2] + M[0][3],
            M[1][0]*v[0] + M[1][1]*v[1] + M[1][2]*v[2] + M[1][3],
            M[2][0]*v[0] + M[2][1]*v[1] + M[2][2]*v[2] + M[2][3]
        )

    origins = []
    directions = []
    
    # Step 2: Compute ray direction from transformation matrix
    a = (0.0, 0.0, 0.0)
    b = (1.0, 0.0, 0.0)
    c = (0.0, 1.0, 0.0)
    
    a_prime = mat_vec_mul(M, a)
    b_prime = mat_vec_mul(M, b)
    c_prime = mat_vec_mul(M, c)
    
    right_vec = (b_prime[0]-a_prime[0], b_prime[1]-a_prime[1], b_prime[2]-a_prime[2])
    up_vec = (c_prime[0]-a_prime[0], c_prime[1]-a_prime[1], c_prime[2]-a_prime[2])
    ray_dir = normalize(right_vec)
    
    # Step 1 & 3: Generate origins for each pixel
    for j in range(H):
        for i in range(W):
            x_norm = 2.0 * (i + 0.5) / W - 1.0
            y_norm = 2.0 * (j + 0.5) / H - 1.0
            
            x_scaled = x_norm * S_cam
            y_scaled = y_norm * S_cam
            
            p_scaled = (x_scaled, y_scaled, 0.0)
            origin = mat_vec_mul(M, p_scaled)
            
            origins.append(origin)
            directions.append(ray_dir)
            
    # Ray marching and volume accumulation are not specified in the sources [G].
    return origins, directions
```

**Edge Cases and Pitfalls:**
- If $\mathbf{M}$ is singular or degenerate, the cross product may yield a zero vector. Guard against this by checking the magnitude of the cross product before normalization [G].
- The normalization to $[-1, 1]$ assumes a centered projection plane. Off-center cameras require an offset in the transformation matrix [G].
- Precision issues may arise if $S_{cam}$ is very small or very large, affecting the spatial distribution of origins [G].

## Subtopics

### Orthographic Camera Ray Generation
A specific instance of viewing plane ray generation for isometric views, defined by a height parameter [S3, unofficial]. It generates parallel rays where the viewing direction is determined by the height setting, typically used for voxel-based rendering [S3, unofficial]. Choose this when an isometric perspective is required without perspective distortion [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \cdot H)$ to generate all ray origins and directions [G].
- **Memory Complexity:** $O(W \cdot H)$ to store the origins and directions [G].
- **Performance:** Linear scaling with image resolution. The direction computation is constant time per ray (all rays share the same direction in orthographic mode) [G].
- **Strengths:** Simple, deterministic, no perspective distortion, efficient for parallel processing [G].
- **Limitations:** No depth cueing from perspective, limited to orthographic views [G].
- **When to use:** Isometric views, technical visualizations, voxel rendering where perspective is not desired [G].
- **When not to use:** Perspective views, scenes requiring depth-based field of view [G].

## Background
The concept of projection plane raycasting originates from early volume rendering architectures, such as the VIRIM system, which used hardware-accelerated resampling and ray casting [S1]. The method was formalized in architectures for real-time volume rendering, emphasizing the separation of geometry resampling and ray casting [S1]. The specific implementation details, including the transformation matrix approach and normalization, are derived from modern implementations in procedural noise and voxel rendering libraries [S2, unofficial].
