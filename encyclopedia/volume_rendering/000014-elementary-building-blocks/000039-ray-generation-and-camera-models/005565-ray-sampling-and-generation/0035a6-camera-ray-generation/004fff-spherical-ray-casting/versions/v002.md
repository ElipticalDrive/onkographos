# Spherical Ray Casting
## Overview
Spherical Ray Casting generates camera rays by mapping a 2D pixel grid to spherical angles ($\theta, \phi$), creating a cylindrical-spherical projection suitable for omnidirectional rendering [S1, unofficial]. It differs from perspective and orthographic models by sampling directions uniformly in spherical angle space rather than screen-space or world-space linear coordinates [G].

## How it works
**Inputs:**
- `width`, `height`: Integer resolution of the output image [S1, unofficial].
- `camtoworld`: $4 \times 4$ extrinsic camera pose matrix containing rotation and translation [S1, unofficial].
- `xnp`: Numerical array library (e.g., NumPy) [S1, unofficial].

**Outputs:**
- `Rays` object containing:
  - `origins`: Array of shape $(H, W, 3)$, camera positions [S1, unofficial].
  - `directions`: Array of shape $(H, W, 3)$, normalized ray directions in world space [S1, unofficial].
  - `radii`: Array of shape $(H, W, 1)$, pixel radii for sampling [S1, unofficial].
  - `imageplane`: Array of shape $(H, W, 2)$, initialized to zeros [S1, unofficial].
  - `lossmult`: Scalar $1$ [S1, unofficial].
  - `near`, `far`: Not given in the sources.
  - `cam_idx`: Scalar $0$ [S1, unofficial].

**Data Structures:**
- `theta`, `phi`: 2D arrays of shape $(H+1, W+1)$ representing angular coordinates [S1, unofficial].
- `directions_cam`: 3D array of shape $(H+1, W+1, 3)$ representing untransformed directions in the camera frame [S1, unofficial].
- `dx`, `dy`: 2D arrays of shapes $(H+1, W, 3)$ and $(H, W+1, 3)$ representing finite differences [S1, unofficial].

**Steps:**
1. **Generate Angular Grids:** Create linearly spaced values for azimuth $\theta$ and elevation $\phi$:
   $$ \theta_{\text{vals}} = \text{linspace}(0, 2\pi, W + 1) $$
   $$ \phi_{\text{vals}} = \text{linspace}(0, \pi, H + 1) $$
   Create a meshgrid using `xy` indexing:
   $$ \theta, \phi = \text{meshgrid}(\theta_{\text{vals}}, \phi_{\text{vals}}, \text{indexing}='xy') $$
2. **Compute Camera-Frame Directions:** Calculate unit vectors in the camera reference frame where $y$ is up:
   $$ \mathbf{D}_{\text{cam}} = [-\sin(\phi)\sin(\theta), \cos(\phi), \sin(\phi)\cos(\theta)] $$
   Shape: $(H+1, W+1, 3)$ [S1, unofficial].
3. **Transform to World Space:** Apply the camera rotation matrix $R_{\text{cam}}$ (top-left $3 \times 3$ of `camtoworld`) to each direction vector:
   $$ \mathbf{D}_{\text{world}} = R_{\text{cam}} \cdot \mathbf{D}_{\text{cam}}^T $$
   Reshape to $(H+1, W+1, 3)$ [S1, unofficial].
4. **Compute Finite Differences:** Calculate differences along axes to estimate pixel extent:
   $$ \Delta_y = \text{diff}(\mathbf{D}_{\text{world}}[:, :-1], \text{axis}=0) $$
   $$ \Delta_x = \text{diff}(\mathbf{D}_{\text{world}}[:-1, :], \text{axis}=1) $$
   Shapes: $\Delta_y$ is $(H, W+1, 3)$, $\Delta_x$ is $(H+1, W, 3)$ [S1, unofficial].
5. **Crop Directions:** Remove the extra row and column introduced by the meshgrid and diff operations to align with pixel centers:
   $$ \mathbf{D}_{\text{final}} = \mathbf{D}_{\text{world}}[:-1, :-1] $$
   Shape: $(H, W, 3)$ [S1, unofficial].
6. **Compute Origins:** Broadcast the camera translation vector $\mathbf{t}$ (last column of `camtoworld`) to match the shape of $\mathbf{D}_{\text{final}}$:
   $$ \mathbf{O} = \text{broadcast\_to}(\mathbf{t}, (H, W, 3)) $$
   [S1, unofficial].
7. **Compute Radii:** Calculate norms of difference vectors and compute average radius scaled by a geometric factor:
   $$ r = 0.5 \cdot (\|\Delta_y\| + \|\Delta_x\|) \cdot \frac{2}{\sqrt{12}} $$
   Reshape to $(H, W, 1)$ [S1, unofficial].
8. **Initialize Image Plane:** Set image plane coordinates to zeros:
   $$ \text{imageplane} = \text{zeros}(\text{shape}(\mathbf{D}_{\text{final}}[..., :2])) $$
   [S1, unofficial].

**Pseudocode:**
```python
class Rays:
    origins: object
    directions: object
    radii: object
    imageplane: object
    lossmult: float
    near: object
    far: object
    cam_idx: int

def spherical_ray_casting(width: int, height: int, camtoworld: object, xnp: type) -> Rays:
    # 1. Generate Angular Grids
    theta_vals = xnp.linspace(0, 2 * xnp.pi, width + 1)
    phi_vals = xnp.linspace(0, xnp.pi, height + 1)
    theta, phi = xnp.meshgrid(theta_vals, phi_vals, indexing='xy')

    # 2. Compute Camera-Frame Directions (y is up)
    sin_phi = xnp.sin(phi)
    cos_phi = xnp.cos(phi)
    sin_theta = xnp.sin(theta)
    cos_theta = xnp.cos(theta)
    directions_cam = xnp.stack([-sin_phi * sin_theta, cos_phi, sin_phi * cos_theta], axis=-1)

    # 3. Transform to World Space
    R_cam = camtoworld[:3, :3]
    directions_world = xnp.matmul(R_cam, directions_cam[..., None])[..., 0]

    # 4. Compute Finite Differences
    dy_diff = xnp.diff(directions_world[:, :-1], axis=0)
    dx_diff = xnp.diff(directions_world[:-1, :], axis=1)

    # 5. Crop Directions
    directions = directions_world[:-1, :-1]

    # 6. Compute Origins
    cam_translation = camtoworld[:3, -1]
    origins = xnp.broadcast_to(cam_translation, directions.shape)

    # 7. Compute Radii
    dy_norm = xnp.linalg.norm(dy_diff, axis=-1)
    dx_norm = xnp.linalg.norm(dx_diff, axis=-1)
    radii = (0.5 * (dy_norm + dx_norm))[..., None] * 2 / xnp.sqrt(12)

    # 8. Initialize Image Plane
    imageplane = xnp.zeros_like(directions[..., :2])

    # Return Rays object
    return Rays(
        origins=origins,
        directions=directions,
        radii=radii,
        imageplane=imageplane,
        lossmult=1.0,
        near=None,
        far=None,
        cam_idx=0
    )
```

**Edge Cases and Pitfalls:**
- **Coordinate System:** The method assumes a camera frame where $y$ is up [S1, unofficial].
- **Boundary Precision:** The meshgrid includes boundaries $0$ and $2\pi$ for $\theta$ and $0$ and $\pi$ for $\phi$ [G].
- **Singularity at Poles:** At $\phi=0$ and $\phi=\pi$, the $\theta$ variation collapses to a point, which the finite difference radius calculation handles by reducing the effective pixel width [G].

## Subtopics

### [Spherical Lens Projection](18274-spherical-lens-projection.md)
Spherical Lens Projection generates a cylindrical-spherical projection of a volume dataset, mapping 3D spatial data onto a 2D flat image plane suitable for equirectangular display. It solves the problem of visualizing omnidirectional or spherical data by projecting rays from a central viewpoint through a spherical lens model onto a rectangular pixel grid. Unlike standard perspective cameras, this method wraps the horizontal angle around the full 360 degrees and the vertical angle across the full 180 degrees, creating an equirectangular map. It is distinct from its siblings, [Spherical Coordinate GPU Ray Casting with 3D Textures](19744-spherical-coordinate-gpu-ray-casting-with-3d-textures.md) which focuses on texture sampling efficiency in spherical coordinates, and [Spherical Light Grid for Shadows](19872-spherical-light-grid-for-shadows.md) which focuses on shadow computation rather than image projection.

### [Spherical Coordinate GPU Ray Casting with 3D Textures](19744-spherical-coordinate-gpu-ray-casting-with-3d-textures.md)
This method renders volumetric data distributed in spherical coordinates by stepping along decreasing spherical shells (constant radius intervals) rather than fixed Cartesian increments. It solves the problem of rendering spherical volumes, such as atmospheric scattering or celestial bodies, by converting Cartesian ray-sphere intersection points directly into texture coordinates for a 3D texture. Unlike Cartesian ray casting, this approach avoids interpolation artifacts in spherical domains but requires a ray-sphere intersection test per shell.

### [Spherical Light Grid for Shadows](19872-spherical-light-grid-for-shadows.md)
The Spherical Light Grid for Shadows is a ray generation and reordering technique that treats shadow rays with the same coherence as primary rays by mapping the light source’s environment into a perspective grid. It solves the problem of poor spatial locality in shadow ray tracing, where rays originating from scattered primary intersections lack the tile-based coherence found in primary ray generation. Unlike sibling methods that handle frustums separately or use cumbersome cubemap clamping, this method uses a unified spherical mapping in azimuthal-elevation space to enable efficient parallel sorting and load balancing on the GPU.

### Nonplanar 2D to 3D Input Mapping via Ray Casting
A method for mapping a nonplanar 2D input surface (such as a dome, sphere, or cylinder enclosure) to 3D volumetric data by casting a ray from the input point into the scene [S2]. It solves the problem of mapping nonplanar 2D inputs to underlying 3D data by identifying the point of contact on the enclosure surface and casting a ray from that point into the 3D scene to determine interaction [S2].

### VisC3D Cutaway View
Technique to gain cutaway views of a 3D field, allowing arbitrary sections to be seen and converting 3D information into 2D information for analysis [S3, unofficial]. It solves the problem of 3D field visualization by obtaining images of the 2D slice in the right window of ViSC3D, saving 2D data as text files in an appointed folder, and providing an interactive tool where users can see the value of an arbitrary point on the 2D slice by moving the mouse [S3, unofficial].
