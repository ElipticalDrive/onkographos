# Spherical Ray Casting

## Overview
Spherical Ray Casting generates camera rays by mapping a 2D grid of pixel coordinates to spherical angles ($\theta, \phi$), creating a cylindrical-spherical projection suitable for 360-degree video and dome-based presentations [S2]. It differs from standard pinhole models by using angular spacing rather than linear perspective projection, and from orthographic models by maintaining a central viewpoint with varying ray density [S1, unofficial][S2].

## How it works
**Inputs:**
- `width`, `height`: Integer resolution of the output image.
- `camtoworld`: $4 \times 4$ extrinsic camera pose matrix (rotation and translation).
- `xnp`: Numerical array library (e.g., NumPy).

**Outputs:**
- `utils.Rays` object containing:
  - `origins`: Array of shape $(H, W, 3)$, camera positions.
  - `directions`: Array of shape $(H, W, 3)$, normalized ray directions in world space.
  - `lossmult`: Scalar $1$.
  - `near`, `far`: Not given in the sources.
  - `cam_idx`: Scalar $0$.

**Data Structures:**
- `theta`, `phi`: 2D arrays of shape $(H+1, W+1)$ representing angular coordinates.
- `directions`: 3D array of shape $(H+1, W+1, 3)$ representing untransformed directions in the camera frame.
- `dx`, `dy`: 2D arrays of shape $(H, W+1, 3)$ and $(H+1, W, 3)$ representing finite differences.
- `radii`: 2D array of shape $(H, W, 1)$ representing pixel radii for sampling.

**Steps:**
1. **Generate Angular Grids:**
   Create linearly spaced values for azimuth $\theta$ and elevation $\phi$:
   $$ \theta_{\text{vals}} = \text{linspace}(0, 2\pi, W + 1) $$
   $$ \phi_{\text{vals}} = \text{linspace}(0, \pi, H + 1) $$
   Create a meshgrid using 'xy' indexing:
   $$ \theta, \phi = \text{meshgrid}(\theta_{\text{vals}}, \phi_{\text{vals}}, \text{indexing}='xy') $$

2. **Compute Camera-Frame Directions:**
   Calculate unit vectors in the camera reference frame where $y$ is up:
   $$ d_x = -\sin(\phi) \sin(\theta) $$
   $$ d_y = \cos(\phi) $$
   $$ d_z = \sin(\phi) \cos(\theta) $$
   Stack into directions array:
   $$ \mathbf{D}_{\text{cam}} = [\dots, d_x, d_y, d_z] $$
   Shape: $(H+1, W+1, 3)$.

3. **Transform to World Space:**
   Apply the camera rotation matrix $R_{\text{cam}}$ (top-left $3 \times 3$ of `camtoworld`) to each direction vector:
   $$ \mathbf{D}_{\text{world}} = R_{\text{cam}} \cdot \mathbf{D}_{\text{cam}}^T $$
   Reshape to $(H+1, W+1, 3)$.

4. **Compute Finite Differences:**
   Calculate differences along axes to estimate pixel extent:
   $$ \Delta_y = \text{diff}(\mathbf{D}_{\text{world}}[:, :-1], \text{axis}=0) $$
   $$ \Delta_x = \text{diff}(\mathbf{D}_{\text{world}}[:-1, :], \text{axis}=1) $$
   Shapes: $\Delta_y$ is $(H, W+1, 3)$, $\Delta_x$ is $(H+1, W, 3)$.

5. **Crop Directions:**
   Remove the extra row and column introduced by the meshgrid and diff operations to align with pixel centers:
   $$ \mathbf{D}_{\text{final}} = \mathbf{D}_{\text{world}}[:-1, :-1] $$
   Shape: $(H, W, 3)$.

6. **Compute Origins:**
   Broadcast the camera translation vector $\mathbf{t}$ (last column of `camtoworld`) to match the shape of $\mathbf{D}_{\text{final}}$:
   $$ \mathbf{O} = \text{broadcast\_to}(\mathbf{t}, (H, W, 3)) $$

7. **Compute Radii:**
   Calculate norms of difference vectors:
   $$ \|\Delta_y\| = \text{norm}(\Delta_y, \text{axis}=-1) $$
   $$ \|\Delta_x\| = \text{norm}(\Delta_x, \text{axis}=-1) $$
   Compute average radius scaled by geometric factor:
   $$ r = 0.5 \cdot (\|\Delta_y\| + \|\Delta_x\|) \cdot \frac{2}{\sqrt{12}} $$
   Reshape to $(H, W, 1)$.

8. **Initialize Image Plane:**
   Set placeholder image plane coordinates to zeros:
   $$ \text{imageplane} = \text{zeros}(\text{shape}(\mathbf{D}_{\text{final}}[..., :2])) $$

**Pseudocode:**
```python
def spherical_ray_casting(width, height, camtoworld, xnp):
    # 1. Generate Angular Grids
    theta_vals = xnp.linspace(0, 2 * xnp.pi, width + 1)
    phi_vals = xnp.linspace(0, xnp.pi, height + 1)
    theta, phi = xnp.meshgrid(theta_vals, phi_vals, indexing='xy')

    # 2. Compute Camera-Frame Directions (y is up)
    sin_phi = xnp.sin(phi)
    cos_phi = xnp.cos(phi)
    sin_theta = xnp.sin(theta)
    cos_theta = xnp.cos(theta)

    dx_cam = -sin_phi * sin_theta
    dy_cam = cos_phi
    dz_cam = sin_phi * cos_theta

    directions_cam = xnp.stack([dx_cam, dy_cam, dz_cam], axis=-1)

    # 3. Transform to World Space
    R_cam = camtoworld[:3, :3]
    # Matmul expects last dim to be vector; R_cam is (3,3), directions_cam is (H+1, W+1, 3)
    directions_world = xnp.matmul(R_cam, directions_cam[..., None])[..., 0]

    # 4. Compute Finite Differences
    # diff along axis 0 (rows) for dy, axis 1 (cols) for dx
    dy_diff = xnp.diff(directions_world[:, :-1], axis=0)
    dx_diff = xnp.diff(directions_world[:-1, :], axis=1)

    # 5. Crop Directions
    directions = directions_world[:-1, :-1]

    # 6. Compute Origins
    cam_translation = camtoworld[:3, -1]
    origins = xnp.broadcast_to(cam_translation, directions.shape)

    # 7. Compute Radii
    dy_norm = xnp.linalg.norm(dy_diff, axis=-1)
    dx_norm = xnp.linalg.norm(dx_diff, axis=-1)
    radii = (0.5 * (dy_norm + dx_norm))[..., None] * 2 / xnp.sqrt(12)

    # 8. Image Plane Placeholder
    imageplane = xnp.zeros_like(directions[..., :2])

    # Return Rays object structure
    return utils.Rays(
        origins=origins,
        directions=directions,
        radii=radii,
        imageplane=imageplane,
        lossmult=1,
        near=None,
        far=None,
        cam_idx=0
    )
```

**Edge Cases and Pitfalls:**
- **Boundary Precision:** The meshgrid includes boundaries $0$ and $2\pi$ for $\theta$ and $0$ and $\pi$ for $\phi$. The cropping step `[:-1, :-1]` is critical to align rays with pixel centers; failing to crop results in shape mismatch with the image buffer [S1, unofficial].
- **Singularity at Poles:** At $\phi=0$ and $\phi=\pi$, the $\theta$ variation collapses to a point. The finite difference method naturally handles this by reducing the effective pixel width, but numerical stability should be monitored [S1, unofficial].
- **Coordinate System:** The method assumes a camera frame where $y$ is up. If the downstream renderer expects $z$-forward or $y$-down, the direction computation must be adjusted [S1, unofficial].

## Subtopics

### Spherical Lens Projection
Produces a cylindrical-spherical projection specifically designed for 360-degree video content [S2]. Unlike the basic spherical ray casting which maps pixels to angles linearly, this variant is optimized for playback on platforms like YouTube 360 [S2]. It supports stereo rendering via `StereoSphericalLens`, which generates two images from nearby camera positions for VR headsets (e.g., Oculus Rift, Google Cardboard) [S2].

## Operating characteristics
- **Time Complexity:** $O(H \cdot W)$ for grid generation and vector transformations.
- **Memory Complexity:** $O(H \cdot W)$ for storing origins, directions, and auxiliary difference arrays.
- **Performance:** Efficient on GPU due to vectorized operations (meshgrid, matmul, diff). No iterative ray marching is performed here; this is purely ray generation.
- **Strengths:** Naturally handles full 360-degree fields of view; uniform angular sampling simplifies spherical harmonics integration if used later.
- **Limitations:** Pixel density is not uniform in world space (higher density near poles if $\phi$ is linear, though the diff-based radius calculation attempts to account for this); not suitable for perspective-correct rendering of flat scenes without distortion correction.
- **When to use:** 360-degree video rendering, planetarium dome presentations, spherical environment mapping.
- **When not to use:** Standard perspective camera rendering, orthographic projections, or when linear pixel spacing is required.

## Background
Originated in the context of spherical video rendering and 360-degree media pipelines [S2]. The specific implementation details (angular grid generation, finite difference radius calculation) are documented in the `multinerf` repository by Google Research, which adapts spherical sampling for neural radiance field rendering [S1, unofficial][S2]. The concept of spherical lenses for dome-based presentations (e.g., Hayden Planetarium) dates back to early virtual reality and planetarium software [S2].
