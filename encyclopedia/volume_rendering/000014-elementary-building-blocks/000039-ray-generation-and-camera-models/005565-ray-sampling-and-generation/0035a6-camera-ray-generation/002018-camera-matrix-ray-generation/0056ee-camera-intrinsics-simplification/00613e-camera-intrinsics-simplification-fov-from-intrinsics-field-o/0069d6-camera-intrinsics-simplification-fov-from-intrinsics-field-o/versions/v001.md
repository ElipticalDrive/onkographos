# Camera Intrinsics Simplification — FOV from Intrinsics, Field of View Calculation, Simplified Camera Intrinsics, Square Pixel Camera Model, get_fov

Also called: Camera Zoom Methods

## Overview
This method provides utilities to manipulate the field of view (FOV) width of a volume rendering camera without altering its position or orientation. It solves the problem of adjusting the visible scene extent by narrowing or widening the viewing frustum. Unlike translation methods that move the camera closer to the focus, these methods only reduce the width of the field of view [S1].

## How it works
The implementation relies on a simplified camera model where the camera does not physically move during zoom operations. The core logic involves modifying the intrinsic parameters that define the angular extent of the view.

**Inputs and Outputs:**
- Input: Current camera state (position, orientation, intrinsic matrix).
- Output: Updated camera state with modified FOV width.

**Data Structures:**
- Camera Object: Contains `position`, `orientation`, and `lens` (or intrinsic matrix).
- Lens/Intrinsics: Contains focal lengths ($f_x, f_y$) and principal point ($c_x, c_y$).

**Steps:**
1. Retrieve current intrinsic parameters ($f_x, f_y$).
2. Calculate the new focal length required to achieve the target FOV width. For a horizontal FOV $\theta_h$ and image width $w$, the relationship is $f_x = \frac{w}{2 \tan(\theta_h / 2)}$.
3. Update the intrinsic matrix with the new focal length.
4. Apply the change to the camera's lens object.

**Formulas:**
- Horizontal FOV: $\theta_h = 2 \arctan\left(\frac{w}{2 f_x}\right)$
- Vertical FOV: $\theta_v = 2 \arctan\left(\frac{h}{2 f_y}\right)$

**Parameters:**
- Target FOV width: Specified in degrees or radians.
- Image dimensions ($w, h$): Pixel width and height.

**Edge Cases and Pitfalls:**
- **Zoom Misconception:** A common pitfall is assuming zooming moves the camera closer to the focus. It does not; it only reduces the width of the field of view [S1].
- **Aspect Ratio:** If $f_x \neq f_y$, the FOV calculation must account for different focal lengths for the x and y axes.

**Pseudocode:**
```python

    """
    Changes the width of the FOV for the given camera.
```

## Subtopics

### DSAC Modification
A modification to the DSAC (Direct Search and Alignment Clustering) algorithm to support different focal lengths for the image x-axis and y-axis, as the original DSAC supports only a single focal length [S2, unofficial]. This is necessary for accurate camera pose computation in scenarios with non-square pixels or anamorphic lenses. The reprojection error threshold in DSAC is set to be within 6 pixels [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for simple `set_width` operations. Iterative methods scale with the number of steps.
- **Memory Complexity:** $O(1)$ as it modifies existing camera parameters.
- **Strengths:** Simple to implement; does not require recalculation of camera position.
- **Limitations:** Does not simulate optical zoom effects like depth of field changes.
- **When to use:** When adjusting the visible scene extent without moving the camera.
- **When not to use:** When simulating physical camera movement or optical zoom effects.
