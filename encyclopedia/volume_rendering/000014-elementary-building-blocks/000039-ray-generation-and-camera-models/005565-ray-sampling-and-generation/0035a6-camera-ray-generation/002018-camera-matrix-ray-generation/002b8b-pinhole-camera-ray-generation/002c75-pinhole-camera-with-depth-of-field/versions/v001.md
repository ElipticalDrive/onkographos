# Pinhole Camera with Depth of Field

Also called: Aperture Sampling, Camera Ray Generation with Depth of Field

## Overview
This method extends the pinhole camera model by generating rays from random points on a lens disk rather than a single focal point, simulating defocus blur (depth of field) [S1, S2, unofficial]. It differs from the standard pinhole model by introducing an aperture radius parameter that controls the spread of ray origins, allowing for realistic focus falloff based on scene depth [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Pixel coordinates $(s, t)$ in $[0, 1] \times [0, 1]$, camera position (Origin), camera orientation basis vectors ($U, V, W$), vertical field of view ($vfov$), aspect ratio, focus distance ($focus\_dist$), and aperture diameter ($aperture$).
- **Output:** A `Ray` struct containing an origin point and a direction vector.

**Data Structures:**
The `Camera` object stores precomputed geometric constants to accelerate ray generation:
- `Origin`: `vec3` (camera position).
- `U`, `V`, `W`: `vec3` (orthonormal basis vectors; $W$ is the view direction, $U$ is right, $V$ is up).
- `Horizontal`: `vec3` (viewport width vector).
- `Vertical`: `vec3` (viewport height vector).
- `LowerLeftCorner`: `vec3` (bottom-left corner of the viewport plane).
- `LensRadius`: `float` (radius of the aperture disk, $aperture / 2$).
- `AspectRatio`: `float`.
- `ViewportHeight`: `float`.
- `ViewportWidth`: `float`.
- `FocalLength`: `float` (often equivalent to $focus\_dist$).

**Precomputation (Constructor):**
1. Convert vertical field of view to radians: $\theta = \text{degrees\_to\_radians}(vfov)$ [S1, S2, unofficial].
2. Calculate half-height of the viewport at distance 1: $h = \tan(\theta / 2)$ [S1, S2, unofficial].
3. Calculate viewport dimensions:
   - $viewport\_height = 2.0 \times h$ [S1, S2, unofficial].
   - $viewport\_width = aspect\_ratio \times viewport\_height$ [S1, S2, unofficial].
4. Calculate lens radius: $lens\_radius = aperture / 2$ [S1, S2, unofficial].
5. Compute viewport vectors scaled by focus distance:
   - $Horizontal = U \times viewport\_width \times focus\_dist$ [S1, S2, unofficial].
   - $Vertical = V \times viewport\_height \times focus\_dist$ [S1, S2, unofficial].
6. Compute the lower-left corner of the viewport plane:
   - $LowerLeftCorner = Origin - Horizontal / 2 - Vertical / 2 - W \times focus\_dist$ [S1, S2, unofficial].

**Ray Generation Steps:**
For a given pixel $(s, t)$:
1. Sample a random point on the lens disk:
   - Generate a random 2D vector $rd$ inside the unit disk (e.g., using rejection sampling or polar coordinates) [S1, S2, unofficial].
   - Scale by lens radius: $rd = rd \times lens\_radius$ [S1, S2, unofficial].
2. Compute the offset from the optical axis:
   - $offset = U \times rd.x + V \times rd.y$ [S1, S2, unofficial].
3. Determine the ray origin:
   - $ray\_origin = Origin + offset$ [S1, S2, unofficial].
4. Determine the ray direction:
   - Calculate the target point on the viewport plane corresponding to pixel $(s, t)$: $target = LowerLeftCorner + Horizontal \times s + Vertical \times t$ [S1, S2, unofficial].
   - $direction = target - ray\_origin$ [S1, S2, unofficial].
   - Normalize the direction: $direction = unit\_vector(direction)$ [S1, S2, unofficial].
5. Return `Ray{ray_origin, direction}` [S1, S2, unofficial].

**Pseudocode:**

```python
import math
import random

def degrees_to_radians(degrees):
    return degrees * math.pi / 180.0

def random_in_unit_disk():
    """Generates a random point inside the unit disk using rejection sampling."""
    while True:
        p = vec3(2.0 * random.random() - 1.0, 2.0 * random.random() - 1.0, 0.0)
        if p.length_squared() < 1.0:
            return p

class Camera:
    def __init__(self, origin, u, v, w, vfov, aspect_ratio, aperture, focus_dist):
        self.origin = origin
        self.u = u
        self.v = v
        self.w = w
        self.aspect_ratio = aspect_ratio
        self.lens_radius = aperture / 2.0
        self.focus_dist = focus_dist
        
        # Precompute viewport geometry
        theta = degrees_to_radians(vfov)
        h = math.tan(theta / 2.0)
        viewport_height = 2.0 * h
        viewport_width = aspect_ratio * viewport_height
        
        self.horizontal = u * (viewport_width * focus_dist)
        self.vertical = v * (viewport_height * focus_dist)
        self.lower_left_corner = origin - (self.horizontal / 2.0) - (self.vertical / 2.0) - (w * focus_dist)

    def get_ray(self, s, t):
        # Sample random point on lens disk
        rd = random_in_unit_disk()
        offset = self.u * rd.x + self.v * rd.y
        
        # Ray origin is shifted by offset from center
        ray_origin = self.origin + offset
        
        # Target is on the focal plane
        target = self.lower_left_corner + (self.horizontal * s) + (self.vertical * t)
        
        # Direction points from lens origin to focal plane target
        direction = target - ray_origin
        direction = direction / direction.length()
        
        return Ray(ray_origin, direction)

class Ray:
    def __init__(self, origin, direction):
        self.origin = origin
        self.direction = direction
```

**Edge Cases and Pitfalls:**
- **Zero Aperture:** If $aperture = 0$, $lens\_radius = 0$, and the method degenerates to a standard pinhole camera [S1, S2, unofficial].
- **Focus Distance:** The blur effect is centered around $focus\_dist$. Objects significantly closer or farther will exhibit blur proportional to their distance from the focal plane [S1, S2, unofficial].
- **Precision:** Ensure $focus\_dist$ is positive. Negative distances may invert the view direction depending on the coordinate system [G].

## Subtopics

### Pinhole Camera Ray Generation
The base model with no aperture sampling, producing sharp images for all depths. Choose when depth of field is not required or for performance-critical applications. [Pinhole Camera Ray Generation](5058-pinhole-camera-ray-generation.md)

## Operating characteristics
- **Time Complexity:** $O(1)$ per ray, assuming constant-time random number generation.
- **Memory Complexity:** $O(1)$ additional memory per camera instance for precomputed vectors.
- **Performance:** Adds negligible overhead compared to pinhole ray generation. The primary cost is the random number generation for the lens offset.
- **Strengths:** Provides realistic photographic effects (bokeh, focus pull) with minimal computational cost per sample.
- **Limitations:** Requires multiple samples per pixel (anti-aliasing + DOF) to reduce noise, increasing total render time. The blur is purely geometric and does not account for lens aberrations or diffraction [S1, S2, unofficial].
- **When to use:** When realistic depth of field is desired.
- **When not to use:** When real-time performance is critical and DOF is not visually necessary, or when using a fixed-focus optical model.

## Background
This method is a standard extension in physically based rendering, widely popularized by the "Ray Tracing in One Weekend" series and subsequent educational ray tracers [S1, S2, unofficial]. It models the thin lens approximation, where the lens is treated as a plane with a circular aperture, and all rays passing through the aperture are focused to a single point on the focal plane [S1, S2, unofficial].
