# World Space Position Reconstruction

Also called: Camera Space to World Space Reconstruction, Coordinate system transformations, Deferred Lighting Data Reconstruction, Depth to World Position, G-Buffer Reconstruction, LightingData Construction, Screen-to-World Ray Reconstruction, World position reconstruction

## Overview
World Space Position Reconstruction is a method to reconstruct 3D world-space positions from 2D screen-space UV coordinates and depth values, enabling raymarching in post-processing by converting screen space to world space [S2, unofficial]. It differs from direct ray generation by first establishing the precise 3D location of the current fragment in the world, which serves as the origin for subsequent raymarching steps [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `uv`: UV coordinate of the current fragment in the post-processing pass [S2, unofficial].
    *   `depth`: Depth value of the underlying scene sampled at `uv` [S2, unofficial].
    *   `projectionMatrixInverse`: Inverse of the camera projection matrix [S2, unofficial].
    *   `viewMatrixInverse`: Inverse of the view matrix (equivalent to `camera.matrixWorld`) [S2, unofficial].
    *   `CameraPosition`: The 3D position of the camera [S3, unofficial].
    *   `ViewDir`: The view direction vector for the current pixel [S3, unofficial].
*   **Outputs:**
    *   `worldSpace`: The reconstructed 3D position in world coordinates [S2, unofficial].

**Data Structures:**
*   **Clip Space Vector:** A 4D vector `{xNDC, yNDC, zNDC, 1.0}` [S2, unofficial].
*   **View Space Vector:** A 4D vector resulting from matrix multiplication [S2, unofficial].
*   **World Space Vector:** A 4D vector resulting from matrix multiplication, requiring perspective division [S2, unofficial].
*   **Depth Texture Index:** An integer 3-vector (`int3`) constructed from the pixel's screen-space `x` and `y` coordinates and a `z` of 0, used for direct texture loading [S3, unofficial].

**Steps:**
1.  **Convert UV to NDC:** Calculate Normalized Device Coordinates (NDC) for x and y [S2, unofficial].
2.  **Convert Depth to NDC Z:** Transform the linear or depth-buffer value to NDC Z [S2, unofficial].
3.  **Construct Clip Space Vector:** Assemble the 4D clip-space vector [S2, unofficial].
4.  **Transform to View Space:** Multiply the clip-space vector by the inverse projection matrix [S2, unofficial].
5.  **Transform to World Space:** Multiply the view-space vector by the inverse view matrix [S2, unofficial].
6.  **Perspective Divide:** Divide the x, y, and z components by the w component to obtain the final world position [S2, unofficial].

**Formulas:**
Matrix-based reconstruction pipeline [S2, unofficial]:
$$x_{NDC} = uv.x \times 2.0 - 1.0$$
$$y_{NDC} = uv.y \times 2.0 - 1.0$$
$$z_{NDC} = depth \times 2.0 - 1.0$$
$$clipSpace = \{x_{NDC}, y_{NDC}, z_{NDC}, 1.0\}$$ [S2, unofficial]
$$view = projectionMatrixInverse \times clipSpace$$ [S2, unofficial]
$$world = viewMatrixInverse \times view$$ [S2, unofficial]
$$worldSpace = \frac{world.xyz}{world.w}$$ [S2, unofficial]
Linear depth reconstruction alternative [S3, unofficial]:
$$Position_{WS} = Depth_{linear} \times ViewDir + CameraPosition$$ [S3, unofficial]

**Parameters:**
*   `uv`: UV coordinate of the current fragment in the post-processing pass [S2, unofficial].
*   `depth`: Depth texture of the underlying scene sampled at the same UV [S2, unofficial].
*   `projectionMatrixInverse`: Inverse of the camera projection matrix, used to convert clip-space to view-space [S2, unofficial].
*   `viewMatrixInverse`: Inverse of the view matrix (camera.matrixWorld), transforms view space to world space [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Texture Filtering:** Hardware texture filtering must not be used for depth sampling in this context because it interpolates across edges of different blocks, leading to incorrect depth values. Point filtering (e.g., `Texture.Load`) must be used instead [S3, unofficial].
*   **Precision:** Standard floating-point precision is assumed for matrix operations. Degenerate inputs (e.g., `world.w` being zero) should be handled, though not explicitly detailed in sources [G].

**Pseudocode:**
```python
def get_world_position(uv: vec2, depth: float, projection_matrix_inverse: mat4, view_matrix_inverse: mat4) -> vec3:
    # Step 1 & 2: Convert to NDC
    clip_z = depth * 2.0 - 1.0
    ndc = uv * 2.0 - 1.0
    
    # Step 3: Construct clip space vector
    clip = vec4(ndc.x, ndc.y, clip_z, 1.0)
    
    # Step 4: Transform to view space
    view = projection_matrix_inverse * clip
    
    # Step 5: Transform to world space
    world = view_matrix_inverse * view
    
    # Step 6: Perspective divide
    return world.xyz / world.w
```

## Background
The method originates from real-time volumetric lighting implementations that rely on post-processing passes to reconstruct 3D rays from the camera through each pixel [S2, unofficial]. It is also applied in signed distance field rendering to convert screen-space coordinates into world-space coordinates for texture sampling and interpolation [S3, unofficial].
