# Ray Position Calculation

Also called: Query Point Sampling

## Overview
Ray Position Calculation computes the 3D spatial coordinates of sample points (query points) along a bundle of rays defined by their origins and directions, constrained within a specific depth range. It solves the problem of mapping 1D depth samples to 3D Euclidean space for volume rendering or neural rendering pipelines. It differs from [Camera Ray Generation](7456-camera-ray-generation.md) by assuming the ray origins and directions are already computed; it focuses solely on the linear interpolation along the ray vector to determine sample locations.

## How it works
**Inputs:**
- `ray_origins`: Tensor of shape `(width, height, 3)` containing the 3D starting position of each ray [S1, unofficial].
- `ray_directions`: Tensor of shape `(width, height, 3)` containing the normalized direction vector for each ray [S1, unofficial].
- `near_thresh`: Float, the minimum depth distance from the origin to sample [S1, unofficial].
- `far_thresh`: Float, the maximum depth distance from the origin to sample [S1, unofficial].
- `num_samples`: Integer, the number of discrete points to generate along each ray [S1, unofficial].
- `randomize`: Boolean, default `True`. If true, adds uniform random noise to the depth values to reduce aliasing (jittering) [S1, unofficial].

**Outputs:**
- `query_points`: Tensor of shape `(width, height, num_samples, 3)` containing the 3D coordinates of all sample points [S1, unofficial].

**Data Structures:**
- `depth_values`: A 1D tensor of shape `(num_samples,)` representing the scalar distances along the ray [S1, unofficial].

**Steps:**
1. Generate a linearly spaced array of depth values between `near_thresh` and `far_thresh` with `num_samples` entries.
   $$ depth\_values = \text{linspace}(near\_thresh, far\_thresh, num\_samples) $$
   [S1, unofficial]
2. If `randomize` is true, add uniform random noise $\epsilon \in [0, 1)$ scaled by the step size to each depth value to jitter the samples [S1, unofficial].
   $$ depth\_values_{jittered} = depth\_values + \text{random}(num\_samples) \times \frac{far\_thresh - near\_thresh}{num\_samples} $$
   [G] (Standard jittering technique implied by "adds random noise" [S1, unofficial])
3. Compute the 3D position for each sample by scaling the ray direction by the depth value and adding the ray origin.
   $$ query\_points = ray\_origins[..., \text{None}, :] + ray\_directions[..., \text{None}, :] \times depth\_values[..., :, \text{None}] $$
   [S1, unofficial]
   The broadcasting expands `depth_values` from shape `(num_samples,)` to `(1, 1, num_samples, 1)` to match the dimensions of `ray_origins` and `ray_directions` `(width, height, 1, 3)` and `(width, height, 1, 3)` respectively, resulting in output shape `(width, height, num_samples, 3)` [S1, unofficial].

**Pseudocode:**
```python
import torch
import numpy as np

def calculate_ray_positions(ray_origins, ray_directions, near_thresh, far_thresh, num_samples, randomize=True):
    """
    Computes 3D query points along rays within near_thresh and far_thresh bounds.
    
    Args:
        ray_origins (torch.Tensor): Shape (width, height, 3).
        ray_directions (torch.Tensor): Shape (width, height, 3).
        near_thresh (float): Nearest depth coordinate.
        far_thresh (float): Farthest depth coordinate.
        num_samples (int): Number of samples per ray.
        randomize (bool): Whether to add jitter noise.
        
    Returns:
        torch.Tensor: Shape (width, height, num_samples, 3).
    """
    # Step 1: Create linear depth values
    depth_values = torch.linspace(near_thresh, far_thresh, num_samples, device=ray_origins.device)
    
    # Step 2: Add random noise if requested
    if randomize:
        # Generate uniform noise in [0, 1)
        noise = torch.rand(num_samples, device=ray_origins.device)
        # Scale noise by the step size between samples
        step_size = (far_thresh - near_thresh) / num_samples
        depth_values = depth_values + noise * step_size
        
    # Step 3: Compute 3D positions
    # Expand dimensions for broadcasting:
    # ray_origins: (W, H, 3) -> (W, H, 1, 3)
    # ray_directions: (W, H, 3) -> (W, H, 1, 3)
    # depth_values: (N,) -> (1, 1, N, 1)
    
    query_points = ray_origins.unsqueeze(2) + ray_directions.unsqueeze(2) * depth_values.unsqueeze(0).unsqueeze(0).unsqueeze(3)
    
    return query_points
```

## Subtopics

### World Space Position Reconstruction
This variant reconstructs 3D world-space positions from a 2D depth map (e.g., from a previous render pass) rather than generating them from camera rays. It calculates the linear depth from a depth texture using the pixel's screen-space coordinates and a z-coordinate of 0, then computes the world space position by multiplying the linear depth by the view direction vector and adding the camera position [S4, unofficial].
- **Formula:** $Position_{WS} = Depth_{linear} \times ViewDir + CameraPosition$ [S4, unofficial]
- **Parameters:** `texCoordInt`: An integer 3-vector `(int3)` constructed from the pixel's screen-space x and y coordinates and a z of 0, used as the index for the depth texture load [S4, unofficial].
- **Pitfall:** Hardware texture filtering must not be used because it interpolates across edges of different blocks; point filtering (e.g., `Texture.Load`) must be used instead to avoid incorrect depth values at block boundaries [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \times H \times N)$, where $W$ is width, $H$ is height, and $N$ is `num_samples`. The operation is highly parallelizable and typically executed on the GPU [S1, unofficial].
- **Memory Complexity:** $O(W \times H \times N \times 3)$ for the output `query_points` tensor [S1, unofficial].
- **Strengths:** Simple, differentiable, and efficient for uniform sampling strategies in NeRF and volume rendering [S1, unofficial].
- **Limitations:** Uniform sampling may be inefficient for scenes with large empty spaces or complex geometry, requiring adaptive sampling strategies (not covered here) [G]. Precision issues may arise if `near_thresh` and `far_thresh` are very large relative to the scene scale, affecting floating-point accuracy in the depth calculation [G].

## Background
This method is a fundamental building block in neural radiance fields (NeRF) and volume rendering pipelines. It is commonly found in PyTorch-based NeRF implementations where ray bundles are generated for each pixel and sampled at discrete intervals along the ray [S1, unofficial]. The specific implementation details (tensor shapes, jittering) are characteristic of modern deep learning-based 3D reconstruction tools [S1, unofficial].
