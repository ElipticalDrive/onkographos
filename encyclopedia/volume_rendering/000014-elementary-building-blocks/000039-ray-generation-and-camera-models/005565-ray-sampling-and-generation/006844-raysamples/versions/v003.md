# RaySamples

Also called: ColorSamples, ColorSamplesVec, DepthSamples, DepthSamplesVec, Pixel Rendering, Ray/Depth/Color Sample Data Structures, RaySamples Data Structure, RaySamplesVec

## Overview
RaySamples is a data structure used in volume rendering and neural rendering pipelines to store geometric and radiometric attributes for a batch of ray samples [S1, unofficial]. It serves as the primary container for intermediate results during ray marching, holding origins, directions, and predicted scene properties such as signed distance fields, density, or color for each sample point along the ray [S1, unofficial]. Unlike sibling methods that focus on generation or specific sampling patterns, RaySamples focuses on the storage and manipulation of these samples, enabling efficient batched operations for integration and gradient computation [S1, unofficial].

## How it works
The RaySamples structure aggregates tensors representing the state of rays sampled through a scene [S1, unofficial]. It is typically populated by a ray sampler and consumed by an integrator [G].

### Inputs and Outputs
*   **Input:** A set of rays defined by origins and directions, often generated from camera parameters and lens models [S2, unofficial].
*   **Output:** A structured batch of samples containing geometric positions, surface normals, and predicted neural network outputs such as SDF, density, and color [S1, unofficial].

### Data Structures
The core implementation is a C++ struct wrapping seven PyTorch tensors [S1, unofficial]. All fields are `torch::Tensor` objects, and operations include a `numel() > 0` guard to prevent processing empty tensors [S1, unofficial].

**RaySamples Layout:**
*   `origin`: `[N, 3]` — World-space origin of each ray sample.
*   `direction`: `[N, 3]` — Normalized direction vector of each ray sample.
*   `zdir_norm`: `[N, 1]` — Cosine of the angle between the ray direction and a reference normal, used for importance sampling or shading [S1, unofficial].
*   `pred_xyz`: `[N, 3]` — Predicted 3D coordinates from a neural network prior or refinement [S1, unofficial].
*   `pred_sdf`: `[N, 1]` — Predicted Signed Distance Field value [S1, unofficial].
*   `pred_isigma`: `[N, 1]` — Predicted inverse density or opacity parameter [S1, unofficial].
*   `ridx`: `[N]` — Ray indices mapping each sample back to its originating pixel or ray [S1, unofficial].

**Variants:**
*   **DepthSamples:** Extends RaySamples with `xyz` `[N, 3]`, `depth` `[N, 1]`, and `ray_sdf` `[N, 1]` [S1, unofficial].
*   **ColorSamples:** Extends RaySamples with `rgb` `[N, 3]` [S1, unofficial].
*   **Vec Variants:** `RaySamplesVec`, `DepthSamplesVec`, and `ColorSamplesVec` store the same fields as vectors of tensors, supporting variable-length batches or specific memory layouts [S1, unofficial].

### Steps for Ray Sampling and Intensity Computation
The following steps describe the generation of rays and computation of intensities as detailed in [S2, unofficial]. This process involves sensor sampling, lens modeling, and optical corrections [S2, unofficial].

1.  **Sample Ray Origins on Sensor:**
    Generate origins on the sensor plane for each pixel $(px_i, px_j)$ and sample count [S2, unofficial].
    ```python
    ray_origins, p_a1 = sensor.sample_on_pixels(samples_per_pixel, px_i, px_j, device=device)
    ray_origins = ray_origins.reshape(-1, 3)
    ray_origins = ray_origins.unsqueeze(0).expand([directions_per_sample] + list(ray_origins.shape)).transpose(0, 1).reshape(-1, 3)
    ```

2.  **Sample Points on Lens:**
    Generate points on the lens aperture to simulate depth of field or aperture effects [S2, unofficial].
    ```python
    p_prime, p_a2 = lens.sample_points_on_lens(ray_origins.shape[0], device=device)
    ```

3.  **Compute Ray Directions:**
    Calculate the direction from the sensor origin to the lens point [S2, unofficial].
    ```python
    ray_directions = optics.batch_vector(
        p_prime[:, 0] - ray_origins[:, 0],
        p_prime[:, 1] - ray_origins[:, 1],
        p_prime[:, 2] - ray_origins[:, 2]
    )
    ```

4.  **Compute Cosine Theta:**
    Calculate the cosine of the angle between the sensor normal and the ray direction for vignetting/falloff correction [S2, unofficial].
    ```python
    sensor_normal = (lens.transform.transform[:-1, -1] - torch.tensor(sensor.position)).to(device)
    sensor_normal *= 1. / torch.norm(sensor_normal)
    cos_theta = optics.optics.vector.cos_theta(sensor_normal[None, ...], ray_directions)
    ```

5.  **Create Rays Object:**
    Assemble the rays with metadata [S2, unofficial].
    ```python
    rays = Rays(origin=ray_origins, direction=ray_directions, meta={'cos_theta': cos_theta})
    ```

6.  **Backward Ray Tracing:**
    Trace rays through the scene using an integrator [S2, unofficial].
    ```python
    intensities, variances = backward_ray_tracing(rays, scene, light_source, integrator, max_iterations=max_iterations)
    if not integrator.with_var:
        intensities = backward_ray_tracing(rays, scene, light_source, integrator, max_iterations=max_iterations)
    ```

7.  **Compute Final Intensities and Variances:**
    Apply optical corrections and average over samples [S2, unofficial].
    Let $z$ be the distance from the lens center to the sensor center:
    $$ z = \sqrt{\sum((lens.transform.transform[:3, -1] - sensor.c2w.transform[:3, -1])^2)} $$
    
    The final intensity for each pixel is:
    $$ I = \frac{\text{mean}_{samples}(\text{mean}_{dirs}(\cos\_theta^4 \cdot I_{raw}))}{z^2 \cdot p_{a1} \cdot p_{a2}} $$
    
    The final variance is:
    $$ V = \frac{\text{mean}_{samples}(\text{mean}_{dirs}(\cos\_theta^8 \cdot V_{raw}))}{z^4 \cdot p_{a1}^2 \cdot p_{a2}^2} $$
    
    If the integrator does not compute variance, return only intensities [S2, unofficial].

### Parameters
*   `samples_per_pixel`: Number of samples per pixel [S2, unofficial].
*   `directions_per_sample`: Number of directions sampled per pixel location for lens effects [S2, unofficial].
*   `max_iterations`: Maximum number of bounces or ray marching steps (default: 3) [S2, unofficial].

### Edge Cases and Pitfalls
*   **Empty Tensors:** The `numel() > 0` guard is critical to avoid runtime errors in PyTorch/C++ when a pixel or batch dimension is empty [S1, unofficial].
*   **Precision:** Optical calculations involving $z^2$ and $z^4$ in denominators can lead to numerical instability if $z$ is very small, requiring consistent coordinate systems for `sensor.position` and `lens.transform` [S2, unofficial].

## Subtopics

### ColorSamples Data Structure
*   **What it is:** A variant of `RaySamples` that includes an `rgb` tensor `[N, 3]` representing the color contribution of each sample [S1, unofficial].
*   **What sets it apart:** It adds radiometric data to the geometric base without altering the underlying tensor manipulation methods [S1, unofficial].
*   **When to choose it:** Use it when the rendering pipeline outputs color directly per sample, such as in path tracing or neural radiance field rendering, and needs to accumulate color [S1, unofficial].
*   **Link:** Inherits all methods from `RaySamples`, including `index`, `slice`, and `cat`, with safety checks applied to the `rgb` field [S1, unofficial].

### ImgToPatch
*   **What it is:** A utility for extracting pixel values from an input image corresponding to sampled rays [S3, unofficial].
*   **What sets it apart:** It focuses on image-space retrieval rather than world-space ray storage [S3, unofficial].
*   **When to choose it:** Use it in supervised training where rendered rays need to be compared against ground-truth image patches [S3, unofficial].
*   **Link:** Uses a ray sampler to get indices or coordinates, applying direct indexing or bilinear grid sampling to extract RGB values [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear in the number of samples $N$ for storage and basic operations such as indexing and slicing [S1, unofficial]. The ray tracing step depends on the scene complexity and integrator [S2, unofficial].
*   **Memory Complexity:** $O(N)$, where $N$ is the total number of samples, requiring $7 \times N \times \text{dtype\_size}$ bytes for the base structure plus variants [S1, unofficial].
*   **Performance:** Efficient on GPU due to the PyTorch tensor backend, allowing high throughput through batched operations [S1, unofficial].
*   **Strengths:** Provides a unified data structure for geometric and neural predictions [S1, unofficial].
*   **Limitations:** Memory overhead for storing all intermediate predictions for every sample [S1, unofficial].
*   **When to use:** Neural rendering pipelines that require joint optimization of geometry and appearance [S1, unofficial].

## Background
The RaySamples structure enables the integration of LiDAR data with visual rendering by providing a common data format for ray-sample interactions [S1, unofficial]. The specific implementation with `pred_xyz`, `pred_sdf`, and `pred_isigma` fields is characteristic of systems like GS-SDF, which unify Gaussian Splatting and SDF-based reconstruction [S1, unofficial]. The optical sampling model originates from computational photography and gradient optics, applying physical lens models to neural rendering [S2, unofficial].
