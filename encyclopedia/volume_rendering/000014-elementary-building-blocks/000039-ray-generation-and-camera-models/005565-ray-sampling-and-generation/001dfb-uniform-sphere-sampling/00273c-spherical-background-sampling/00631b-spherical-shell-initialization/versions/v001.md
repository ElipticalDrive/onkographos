# Spherical Shell Initialization

Also called: Outer Spherical Shell Initialization

## Overview
Spherical Shell Initialization represents the scene background as a volumetric shell between two concentric spheres, addressing the unreliability of sparse point clouds in distant regions [S1]. Unlike [Spherical Background Sampling](3991-spherical-background-sampling.md), which generates rays from an internal origin against a single background sphere, this method explicitly constructs a 3D geometric boundary (the shell) to constrain background point placement and prevent artifacts from incomplete masks or erroneous point growth [S2].

## How it works
**Inputs:**
*   $O$: Center of the spherical shell (typically the scene centroid).
*   $R_i$: Inner radius, representing the foreground-background separation threshold.
*   $R_o$: Outer radius, denoting the maximum scene limit.
*   Metric distance maps: Depth information for the scene.
*   Input images: RGB values for color initialization.
*   Tessellation grid: Vertices of a finely tessellated geodesic dome.

**Outputs:**
*   A set of background points positioned within the shell $[R_i, R_o]$.
*   Initial view-independent color components for each point.

**Data Structures:**
*   **Point Cloud:** A list of points $P = \{p_1, ..., p_N\}$. Each point $p_i$ has a position vector $\mathbf{p}_i$ and a color vector $\mathbf{c}_i$.
*   **Distance Map:** A spatial field providing the metric distance from the center $O$ to the nearest surface for any given direction.

**Parameters:**
*   $R_i$: Threshold for foreground separation. [S1]
*   $R_o$: Empirically set to 10 times the diameter of the navigation area, approximated by the maximum distance between estimated camera positions. [S1]

**Algorithm Steps:**
1.  **Generate Base Geometry:** Place initial points at the vertices of a finely tessellated geodesic dome centered at $O$. This provides a uniform angular distribution. [S1]
2.  **Determine Radial Distance:** For each point, calculate its distance from the center $O$ using the metric distance maps. Let this measured distance be $d$. [S1]
3.  **Clamp or Randomize Radius:**
    *   If $d > R_o$, set the radial coordinate of the point precisely to $R_o$. These points represent features at infinity (e.g., sky, distant mountains). [S1]
    *   If $d \le R_o$, set the radial coordinate to a random value sampled uniformly from the range $[R_i, R_o]$. [S1]
    *   *Note:* Using the radial depth information directly for positioning was tested but found not to improve convergence in the outer shell. [S1]
4.  **Initialize Color:** Assign each point an initial view-independent color equal to the average of the RGB values found in the intersection of the corresponding ray (from $O$ through the point's angular position) and the input images. [S1]

**Pseudocode:**
```python
def initialize_spherical_shell(O, R_i, R_o, distance_map, images, dome_vertices):
    """
    Initialize background points in a spherical shell.
    
    Args:
        O: Center of the shell (vector).
        R_i: Inner radius (scalar).
        R_o: Outer radius (scalar).
        distance_map: Function or grid providing metric distance from O for a given direction.
        images: List of input RGB images.
        dome_vertices: Array of unit vectors representing the geodesic dome tessellation.
        
    Returns:
        points: List of initialized background points with position and color.
    """
    points = []
    
    for vertex in dome_vertices:
        # 1. Calculate direction from center
        direction = vertex - O
        direction_norm = normalize(direction)
        
        # 2. Get metric distance from map
        # distance_map returns the distance to the nearest surface along direction_norm
        d = distance_map(O, direction_norm)
        
        # 3. Determine radial coordinate r
        if d > R_o:
            r = R_o
        else:
            # Random value in [R_i, R_o]
            r = random_uniform(R_i, R_o)
            
        # 4. Set position
        position = O + direction_norm * r
        
        # 5. Initialize color
        # Average RGB values from input images intersected by the ray
        # Ray: origin=O, direction=direction_norm
        color = compute_average_color_from_images(O, direction_norm, images)
        
        points.append({
            'position': position,
            'color': color
        })
        
    return points

def compute_average_color_from_images(origin, direction, images):
    """
    [G] Placeholder for ray-image intersection logic.
    In practice, this involves projecting the ray onto each image plane,
    sampling the RGB value at the intersection, and averaging across all valid views.
    """
    # Implementation depends on camera intrinsics/extrinsics not provided in source.
    # We assume a standard ray-marching or projection approach.
    colors = []
    for img in images:
        # Project ray to image coordinates
        u, v = project_ray_to_image(origin, direction, img.camera_intrinsics, img.camera_extrinsics)
        if is_valid_pixel(u, v, img.width, img.height):
            colors.append(img.get_rgb(u, v))
    
    if not colors:
        return [0.0, 0.0, 0.0] # Default black if no intersection
        
    avg_r = sum(c[0] for c in colors) / len(colors)
    avg_g = sum(c[1] for c in colors) / len(colors)
    avg_b = sum(c[2] for c in colors) / len(colors)
    return [avg_r, avg_g, avg_b]
```

**Edge Cases and Pitfalls:**
*   **Precision:** The random sampling in $[R_i, R_o]$ for $d \le R_o$ introduces stochasticity. While tested, using the exact depth $d$ did not improve convergence, suggesting the shell acts as a soft constraint rather than a hard surface. [S1]
*   **Boundary Conditions:** Points with $d > R_o$ are clamped to $R_o$. This creates a dense layer at the outer boundary for distant features. [S1]
*   **Navigation Area Approximation:** $R_o$ relies on the maximum distance between estimated camera positions. If camera poses are inaccurate or sparse, $R_o$ may be incorrectly sized, leading to either truncated backgrounds or excessive empty space. [S1]

## Subtopics

### Background Sphere Modeling
A technique to model the background using a single sphere covering the entire scene, primarily used in point cloud-guided NeRF models like NeuralEditor to prevent the growth of erroneous points in incomplete background masks [S2]. Unlike the shell which has thickness $[R_i, R_o]$, this method uses the sphere as a direct representation of the background, avoiding the need to grow new points for background regions [S2]. It is chosen when the primary issue is "growing wrong points" due to mask inaccuracies rather than initializing a volumetric background shell [S2].

## Operating characteristics
*   **Complexity:** Initialization is $O(N)$ where $N$ is the number of dome vertices. Color averaging requires ray-image intersections, scaling with the number of input images.
*   **Performance:** The method replaces unreliable sparse COLMAP points in distant regions, improving reconstruction stability for outdoor scenes [S1].
*   **Strengths:** Prevents artifacts from incomplete background masks; provides a bounded parallax limit via $R_o$ [S1].
*   **Limitations:** $R_o$ is empirical and scene-dependent; random radial placement may not perfectly align with actual geometry, though convergence is not significantly harmed [S1].
*   **Use Case:** Outdoor Gaussian reconstruction where background points are sparse or noisy [S1].

## Background
Originated in "EnvMap-GS: two-stage outdoor Gaussian reconstruction with background-to-environment map baking" (Pintani et al., 2026) [S1]. The method was developed to address the limitations of sparse point clouds (e.g., from COLMAP) in distant regions of outdoor scenes. It builds on the concept of spherical background sampling but extends it to a volumetric shell initialization for 3D Gaussian Splatting optimization [S1]. A related concept, "Background Sphere Modeling," was introduced in "NeuralEditor" (2023) to solve similar issues in NeRFs by preventing erroneous point growth [S2].
