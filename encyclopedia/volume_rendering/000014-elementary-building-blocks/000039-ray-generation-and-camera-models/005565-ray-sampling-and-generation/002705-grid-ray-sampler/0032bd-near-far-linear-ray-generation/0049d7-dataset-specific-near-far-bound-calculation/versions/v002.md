# Dataset-Specific Near/Far Bound Calculation

Also called: Dataset-dependent Near/Far Clipping, Near/Far Bound Calculation per Dataset, Scene Normalization, Scene contraction strategy

## Overview
Computes the near and far clipping planes for ray sampling based on the dataset type and Normalized Device Coordinates (NDC) configuration [S2, unofficial].

## How it works
**Inputs:**
- `dataset_type`: String identifier for the dataset ('llff', 'blender', 'deepvoxels') [S2, unofficial].
- `no_ndc`: Boolean flag to disable NDC projection for non-forward-facing scenes [S2, unofficial].
- `bds`: Array of bounding box min/max extents, typically pre-scaled during data loading [S2, unofficial].
- `poses`: Array of camera transformation matrices [S2, unofficial].

**Outputs:**
- `near`: Float, the near clipping plane distance.
- `far`: Float, the far clipping plane distance.

**Data Structures:**
- `bds`: Contains bounding box extents [S2, unofficial].
- `poses`: Contains camera extrinsics [S2, unofficial].

**Steps:**
1. **LLFF Dataset (`dataset_type == 'llff'`):**
   - If `no_ndc` is `True`: compute `near = min(bds) * 0.9` and `far = max(bds) * 1.0` [S2, unofficial].
   - If `no_ndc` is `False`: set `near = 0.0` and `far = 1.0` [S2, unofficial].
2. **Blender Dataset (`dataset_type == 'blender'`):**
   - Set `near = 2.0` and `far = 6.0` [S2, unofficial].
3. **DeepVoxels Dataset (`dataset_type == 'deepvoxels'`):**
   - Compute the mean trajectory radius: `hemi_R = mean(norm(poses[:, :3, -1]))` [S2, unofficial].
   - Set `near = hemi_R - 1.0` and `far = hemi_R + 1.0` [S2, unofficial].
4. **Scene Normalization (Unbounded Scenes):**
   - Calculate the maximum distance $D_{max}$ between any two camera positions in the training log [S1].
   - Determine sphere diameter $D_{sphere} = D_{max} + 50$ meters [S1].
   - This diameter defines the contraction sphere used to map unbounded space into a bounded domain [S1].

**Pitfalls:**
- LLFF requires explicit bounding box scaling (`* 0.9`, `* 1.0`) when NDC is disabled, whereas NDC scenes use fixed [0, 1] bounds [S2, unofficial].
- Ensure translation extraction uses the correct matrix column (`poses[:, :3, -1]`) [S2, unofficial].

**Pseudocode:**
```python
import math

def compute_near_far(dataset_type, no_ndc, bds, poses):
    if dataset_type == 'llff':
        if no_ndc:
            near = min(bds) * 0.9
            far = max(bds) * 1.0
        else:
            near = 0.0
            far = 1.0
    elif dataset_type == 'blender':
        near = 2.0
        far = 6.0
    elif dataset_type == 'deepvoxels':
        translations = []
        for pose in poses:
            translations.append(pose[:3, -1])
        norms = []
        for t in translations:
            norms.append(math.sqrt(sum(x * x for x in t)))
        hemi_R = sum(norms) / len(norms)
        near = hemi_R - 1.0
        far = hemi_R + 1.0
    else:
        raise ValueError("Unsupported dataset_type")
    return near, far
```

## Operating characteristics
Time complexity is $O(1)$ for Blender and LLFF, and $O(N)$ for DeepVoxels where $N$ is the number of poses [G]. Memory complexity is $O(1)$ auxiliary space [G].

## Background
The dataset-specific bounds originate from early NeRF implementations and repositories [S2, unofficial]. The scene normalization strategy using a sphere diameter of maximum camera distance plus 50 meters was introduced in LidaRF to handle unbounded street scenes via scene contraction [S1].
