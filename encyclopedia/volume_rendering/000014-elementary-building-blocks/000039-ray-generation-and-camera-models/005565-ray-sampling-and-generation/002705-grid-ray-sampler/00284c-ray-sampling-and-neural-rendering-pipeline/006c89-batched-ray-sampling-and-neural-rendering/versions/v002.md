# Batched Ray Sampling and Neural Rendering

Also called: Create Samples, Inference Rendering, NeRF inference loop, Volume Rendering Sample Generation

## Overview
A procedure to render RGB, Depth, and Accumulation maps for a set of latent codes and camera poses using a pre-trained NeRF generator [S1, unofficial]. It handles batching and post-processing of outputs, reshaping them into image tensors [S1, unofficial]. It differs from standard ray marching by operating on a batch of latent vectors and camera poses simultaneously, optimizing throughput for inference [S1, unofficial].

## How it works
**Inputs:**
- Latent codes $z$: Tensor of shape $(N, D_z)$, where $N$ is the number of samples and $D_z$ is the latent dimension [S1, unofficial].
- Camera poses: Optional tensor or list of camera extrinsics [S1, unofficial]. If not provided, rays are set to `None` [S1, unofficial].
- Generator: A pre-trained neural network capable of querying color and density given a latent code and ray [S1, unofficial].
- `batch_size`: Integer controlling the chunking of latent codes and rays [S1, unofficial].
- `img_size`: Spatial dimensions $(H, W)$ of the output image [S1, unofficial].

**Outputs:**
- RGB: Tensor of shape $(N, 3, H, W)$ [S1, unofficial].
- Depth: Tensor of shape $(N, 1, H, W)$ [S1, unofficial].
- Accumulation: Tensor of shape $(N, 1, H, W)$ [S1, unofficial].

**Data Structures:**
- Rays: Input rays are structured as $(B, 2, H \times W, C)$ where $B$ is the batch size, $2$ represents the ray origin and direction, $H \times W$ is the number of pixels, and $C=3$ is the dimensionality of origin/direction vectors [S1, unofficial].
- Intermediate Query Output: The generator returns tensors of shape $(N \times H \times W, C_{out})$ where $C_{out}$ includes RGB, Disparity, Accumulation, and other outputs [S1, unofficial].

**Steps:**
1. **Initialization**: Set the generator to evaluation mode to disable training-specific updates [S1, unofficial]. Determine the computation device [S1, unofficial].
2. **Batch Splitting**: Split the latent codes $z$ into batches of size `batch_size` [S1, unofficial].
3. **Ray Generation**: If camera poses are provided, generate rays for each pose using a ray sampler (e.g., `val_ray_sampler`), stack them, and split into batches matching the latent code batches [S1, unofficial]. If no poses are provided, the rays list is `None` [S1, unofficial].
4. **Iteration**: Iterate through each batch of latent codes $z_i$ and rays $rays_i$ [S1, unofficial].
5. **Gradient Disabling**: Disable gradient computation for the forward pass [S1, unofficial].
6. **Ray Preprocessing**: Permute and flatten the rays tensor from shape $(B, 2, H, W, C)$ to $(2, B \times H \times W, 3)$ [S1, unofficial]. This flattens the spatial dimensions to query the network pixel-by-pixel within the batch [S1, unofficial].
7. **Network Query**: Pass the latent code $z_i$ and preprocessed rays $rays_i$ to the generator [S1, unofficial]. Retrieve RGB, Disparity, Accumulation, and other outputs [S1, unofficial].
8. **Reshaping**: Reshape the outputs from $(N \times H \times W, C)$ to $(N, C, H, W)$ [S1, unofficial].
9. **Collection**: Append the reshaped tensors to lists for RGB, Disparity, and Accumulation [S1, unofficial].
10. **Concatenation**: Concatenate all batch results along the first dimension to form the final tensors [S1, unofficial].
11. **Depth Conversion**: Convert disparity maps to depth maps [S1, unofficial].
12. **Return**: Return the final RGB, Depth, and Accumulation tensors [S1, unofficial].

**Formulas:**
- **Disparity to Depth Conversion**:
  $$ depth = \frac{1}{\max(10^{-10}, disparity)} $$
  Undefined values (where disparity equals $10^{10}$) are set to the far plane value [S1, unofficial].
- **Depth Normalization** (for visualization):
  $$ depth_{norm} = \frac{depth - near}{far - near} $$
  Where $near$ and $far$ are the near and far plane distances retrieved from `generator.render_kwargs_test` [S1, unofficial].

**Parameters:**
- `near`: Near plane distance, retrieved from `generator.render_kwargs_test['near']` [S1, unofficial].
- `far`: Far plane distance, retrieved from `generator.render_kwargs_test['far']` [S1, unofficial].
- `batch_size`: Controls chunking [S1, unofficial].
- `img_size`: Spatial dimensions, e.g., 64 [S1, unofficial].

**Pseudocode:**
```python
def batched_ray_sampling_and_neural_rendering(generator, latent_codes, poses, batch_size, img_size, near, far):
    """
    Renders RGB, Depth, and Accumulation for a batch of latent codes and poses.
    Args:
        generator: Pre-trained NeRF generator model.
        latent_codes: List of latent vectors of shape (N, D_z).
        poses: List of camera pose matrices or None.
        batch_size: Integer for batching.
        img_size: Integer, spatial dimension (H=W).
        near: Near plane distance.
        far: Far plane distance.
    Returns:
        rgb: Array (N, 3, H, W)
        depth: Array (N, 1, H, W)
        acc: Array (N, 1, H, W)
    """
    generator.eval()
    N = len(latent_codes)
    
    # Split latent codes into batches
    z_batches = [latent_codes[i:i+batch_size] for i in range(0, N, batch_size)]
    
    # Generate rays if poses are provided
    rays_batches = None
    if poses is not None:
        all_rays = []
        for pose in poses:
            # val_ray_sampler returns rays for a single pose
            rays = generator.val_ray_sampler(img_size, img_size, generator.focal, pose)[0]
            all_rays.append(rays)
        all_rays = stack(all_rays, axis=0) # Shape: (N, 2, H, W, C)
        rays_batches = [all_rays[i:i+batch_size] for i in range(0, N, batch_size)]
        
    rgb_list = []
    disp_list = []
    acc_list = []
    
    for i, z_i in enumerate(z_batches):
        rays_i = rays_batches[i] if rays_batches is not None else None
        bs = len(z_i)
        
        # Disable gradients
        with no_grad():
            # Preprocess rays: Bx2x(HxW)xC -> 2x(BxHxW)x3
            if rays_i is not None:
                # Permute to (B, H, W, 2, C) then flatten spatial and view dims
                rays_i = permute(rays_i, axes=(0, 2, 3, 1, 4))
                rays_i = reshape(rays_i, (bs * img_size * img_size, 2, 3))
                rays_i = permute(rays_i, axes=(1, 0, 2))
            
            # Query generator
            rgb_i, disp_i, acc_i, _ = generator(z_i, rays=rays_i)
            
            # Reshape outputs from (N*H*W, C) to (N, C, H, W)
            reshape_fn = lambda x: permute(reshape(x, (bs, img_size, img_size, x.shape[1])), axes=(0, 3, 1, 2))
            
            rgb_list.append(reshape_fn(rgb_i))
            disp_list.append(reshape_fn(disp_i))
            acc_list.append(reshape_fn(acc_i))
            
    # Concatenate results
    rgb = concatenate(rgb_list, axis=0)
    disp = concatenate(disp_list, axis=0)
    acc = concatenate(acc_list, axis=0)
    
    # Handle undefined disparity values (10^10)
    disp = where(disp == 1e10, far, disp)
    
    # Depth = 1 / max(1e-10, disp)
    depth = 1.0 / clamp(disp, min=1e-10)
    
    return rgb, depth, acc
```

**Edge Cases and Pitfalls:**
- **Undefined Disparity**: Disparity values equal to $10^{10}$ indicate undefined depth (e.g., background) and must be explicitly handled by setting them to the far plane value before the inverse operation [S1, unofficial].
- **Precision**: Use $\max(10^{-10}, disparity)$ to avoid division by zero or numerical instability with very small disparity values [S1, unofficial].
- **Missing Poses**: If poses are not provided, rays must be handled correctly as `None` to avoid errors in the generator query [S1, unofficial].

## Operating characteristics
- **Performance**: Measured performance depends on the generator's complexity and hardware [S1, unofficial]. For example, on a GPU with $\le$10GB memory, an image size of 64x64 is recommended [S1, unofficial].
- **Strengths**: Efficient for generating multiple views or latent samples and handles batching automatically [S1, unofficial].
- **Limitations**: Requires a pre-trained generator [S1, unofficial].
- **When to Use**: When rendering multiple images from a NeRF model, especially for evaluation metrics like FID/KID or video generation [S1, unofficial].
- **When Not to Use**: Not given in the sources.
