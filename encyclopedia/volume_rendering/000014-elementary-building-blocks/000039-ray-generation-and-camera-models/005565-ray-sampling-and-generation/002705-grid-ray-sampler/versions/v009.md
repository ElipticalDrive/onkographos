# Grid Ray Sampler

Also called: Primary Ray Sampling with Reparameterization, Reparameterized Primary Ray Sampling

## Overview
The Grid Ray Sampler generates a set of 3D camera rays by mapping pixel coordinates from an image grid to world space using camera intrinsics and extrinsics [S1, S2, unofficial]. It solves the problem of sampling primary rays for a sensor, optionally applying a reparameterization function to the image-space positions to enable differentiable rendering with respect to camera or scene parameters [S1, unofficial]. It differs from its siblings by focusing on the geometric transformation from 2D pixel indices to 3D ray vectors, whereas methods like [Near-Far Linear Ray Generation](6841-near-far-linear-ray-generation.md) focus on depth discretization along those rays, and [Refined Ray Generation via PDF Sampling](6837-refined-ray-generation-via-pdf-sampling.md) focuses on adaptive depth sampling based on prior weights [S2, unofficial][S3, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** `intrinsic` (camera intrinsic matrix), `pose` (world-to-object or camera-to-world transformation matrix), `resolution` (image dimensions $H \times W$), `num_rays` (target ray count), `full_grid` (boolean flag for uniform vs random sampling), `framerate.count()` (accumulated sample count per pixel for coherence handling) [S2, unofficial].
*   **Outputs:** `rays_o` (ray origins tensor), `rays_d` (ray directions tensor) [S2, unofficial].

**Data Structures**
*   **Ray Buffer:** A contiguous memory block storing origins and directions [G].
*   **Pixel Coordinates:** Integer tensors $i, j$ representing row and column indices, generated via meshgrid [S2, unofficial].

**Steps**
1.  **Determine Ray Count:** $N = \text{num\_rays}$ if `full_grid` is false, otherwise $N = H \times W$ [S2, unofficial].
2.  **Generate Pixel Indices:** Create 2D grids of pixel coordinates $i \in [0, H-1]$ and $j \in [0, W-1]$ using `torch.meshgrid` with `indexing="ij"` [S2, unofficial].
3.  **Select Indices:** If `full_grid` is false, generate random indices `select_inds` of size $N$ from the range $[0, H \times W - 1]$ [S2, unofficial]. Gather the corresponding $i$ and $j$ values using `select_inds` [S2, unofficial]. Reshape and expand $i$ and $j$ to match batch dimensions [S2, unofficial].
4.  **Lift to Camera Space:** Convert 2D pixel coordinates to 3D points in the camera coordinate system using a lift function with intrinsics: `pixel_points_cam = lift(i, j, torch.ones_like(i), intrinsics=intrinsic)` [S2, unofficial].
5.  **Transform to World Space:** Apply the pose transformation to get world coordinates: `world_coords = torch.bmm(pose, pixel_points_cam).transpose(-1, -2)[..., :3]` [S2, unofficial].
6.  **Compute Ray Origins:** Extract ray origins from the pose matrix: `rays_o = pose[..., :3, 3]` [S2, unofficial].
7.  **Compute Ray Directions:** Calculate raw directions by subtracting origins from world coordinates: `rays_d = world_coords - rays_o[..., None, :]` [S2, unofficial].
8.  **Normalize Directions:** Normalize the direction vectors: `rays_d = F.normalize(rays_d, dim=-1)` [S2, unofficial].
9.  **Expand Origins:** Expand ray origins to match ray directions shape: `rays_o = rays_o[..., None, :].expand_as(rays_d)` [S2, unofficial].

**Formulas**
*   Ray origin: $\mathbf{o} = \text{pose}[:, :, :3, 3]$ [S2, unofficial].
*   Ray direction: $\mathbf{d} = \frac{\mathbf{p}_{\text{world}} - \mathbf{o}}{\|\mathbf{p}_{\text{world}} - \mathbf{o}\|_2}$ [S2, unofficial].

**Parameters**
*   `resolution`: Integer defining image dimensions. Typical value: 512 [S2, unofficial].
*   `framerate.count()`: `uint32_t` representing accumulated samples per pixel, passed to ray generator for coherence handling [S2, unofficial].

**Edge Cases and Pitfalls**
*   Reparameterization requires the film to sample borders and the filter to not be a box filter [S1, unofficial].
*   Precision handling for matrix operations and coordinate transformations is required to avoid artifacts [G].
*   Boundary conditions for pixel coordinates must be handled to prevent out-of-bounds access [G].

**Pseudocode**
```python
import torch
import torch.nn.functional as F

def grid_ray_sampler(intrinsic, pose, resolution, num_rays, full_grid=False, batch_size=1):
    """
    Generate camera rays from pixel grid.
    
    Args:
        intrinsic: (3, 3) Camera intrinsic matrix K.
        pose: (4, 4) Camera-to-world transformation matrix.
        resolution: (H, W) Image dimensions.
        num_rays: int Number of rays if full_grid is False.
        full_grid: bool If True, generate H*W rays.
        batch_size: int Number of camera views.
        
    Returns:
        rays_o: (batch_size, N, 3) Ray origins.
        rays_d: (batch_size, N, 3) Ray directions.
    """
    H, W = resolution
    N = H * W if full_grid else num_rays
    
    # 1. Generate pixel coordinates
    i, j = torch.meshgrid(torch.arange(H), torch.arange(W), indexing='ij')
    
    # 2. Reshape and expand to match batch dimensions
    i = i.reshape(-1).unsqueeze(0).expand(batch_size, -1)
    j = j.reshape(-1).unsqueeze(0).expand(batch_size, -1)
    
    # 3. Select indices if not full grid
    if not full_grid:
        select_inds = torch.randint(0, H * W, size=(N,), device=i.device)
        i = i[:, select_inds]
        j = j[:, select_inds]
        
    # 4. Lift to camera space
    ones = torch.ones_like(i)
    pixel_points_cam = torch.stack([j.float(), i.float(), ones], dim=-1)
    # Apply inverse intrinsic to lift to camera space
    K_inv = torch.inverse(intrinsic)
    pixel_points_cam = torch.bmm(pixel_points_cam, K_inv.T)
    
    # 5. Transform to world coordinates
    pixel_points_cam_hom = torch.cat([pixel_points_cam, torch.ones(batch_size, N, 1, device=i.device)], dim=-1)
    world_coords_hom = torch.bmm(pose, pixel_points_cam_hom.transpose(-1, -2))
    world_coords = world_coords_hom[..., :3, :].transpose(-1, -2)
    
    # 6. Compute ray origins
    rays_o = pose[..., :3, 3]
    rays_o = rays_o.unsqueeze(1).expand_as(world_coords)
    
    # 7. Compute ray directions
    rays_d = world_coords - rays_o
    
    # 8. Normalize directions
    rays_d = F.normalize(rays_d, dim=-1)
    
    return rays_o, rays_d
```

## Subtopics

### [Ray Sampling and Neural Rendering Pipeline](4255-ray-sampling-and-neural-rendering-pipeline.md)
This method generates camera rays from pixel coordinates, passes them through an implicit neural renderer, and extracts rendered features (such as color or geometry) into image tensors. It differs from the parent [Grid Ray Sampler](3930-grid-ray-sampler.md) by handling the complete inference pipeline—transforming pixel grids into ray bundles, executing the neural network forward pass, and reshaping the output—rather than just sampling ray origins and directions. Choose it when building a full differentiable neural rendering pipeline rather than a standalone ray generator.

### [Near-Middle-Far Ray Generation](6817-near-middle-far-ray-generation.md)
Near-Middle-Far Ray Generation divides a camera ray into two distinct segments: a linear interpolation from the near plane to a middle point, and a disparity (inverse-linear) interpolation from the middle point to the far plane. It allocates a configurable fraction of samples to the near-middle segment and the remainder to the middle-far segment. Choose it when depth resolution needs to be non-uniformly distributed across the viewing frustum.

### [Refined Ray Generation via PDF Sampling](6837-refined-ray-generation-via-pdf-sampling.md)
Refined Ray Generation via PDF Sampling generates refined ray samples for volume rendering by sampling new depth positions based on previous iteration's weights, then computing segment lengths and midpoints for rendering. It builds on the coarse sampling provided by the [Grid Ray Sampler](3930-grid-ray-sampler.md) by adaptively drawing new samples from the distribution defined by prior weights. Choose it when variance reduction is needed by concentrating samples on high-contribution regions.

### [Near-Far Linear Ray Generation](6841-near-far-linear-ray-generation.md)
Near-Far Linear Ray Generation generates a list of 3D sampling points along a camera ray segment defined by near ($t_{min}$) and far ($t_{max}$) distances for a specified number of samples. It solves the problem of discretizing the continuous ray domain into a finite set of query points for volume rendering or neural radiance field evaluation. It sets itself apart from its siblings by providing the foundational uniform or disparity-based spacing logic upon which stratified, probabilistic, or depth-guided variants build. Unlike [Inverse CDF Ray Sampling](11412-inverse-cdf-ray-sampling.md) which adapts density to learned probabilities, or [Depth-Guided Supersampling](12190-depth-guided-supersampling.md) which uses external depth priors, this method relies on fixed geometric intervals. Choose it for standard uniform discretization along a ray segment.

### [Batch Stratified Pixel Sampling](9144-batch-stratified-pixel-sampling.md)
Batch Stratified Pixel Sampling is a ray generation method used in neural reconstruction pipelines to select a subset of pixels for optimization at each training iteration. It solves the problem of efficiently computing gradients by avoiding the memory overhead of processing the entire image grid while ensuring uniform coverage through stratification. It differs from its sibling [Grid-based Stratified Camera Sampling](11819-grid-based-stratified-camera-sampling.md) by focusing on batched pixel selection for ground-truth retrieval via bilinear interpolation, rather than generating continuous camera rays for volumetric traversal. Choose it when training memory is constrained and pixel-level gradient updates are required.

### [Grid-based Stratified Camera Sampling](11819-grid-based-stratified-camera-sampling.md)
Grid-based Stratified Camera Sampling generates camera rays by uniformly covering the scene volume using a 3D stratified grid for camera positions, combined with random selection of training view orientations. It differs from the parent [Grid Ray Sampler](3930-grid-ray-sampler.md) by explicitly stratifying the camera position space across the scene bounds rather than just the pixel grid, and from siblings like [Near-Middle-Far Ray Generation](6817-near-middle-far-ray-generation.md) by decoupling position stratification from view orientation selection. Choose it when novel view synthesis requires diverse camera poses rather than fixed viewpoints.

### [Stratified Cosine-Weighted Diffuse Ray Generation](12304-stratified-cosine-weighted-diffuse-ray-generation.md)
This method generates stratified cosine-weighted diffuse rays for bounded one-bounce voxel global illumination, sampling from primary hit positions. It differs from its siblings by specifically targeting the second bounce (GI) in a voxel-based pipeline, using stratified sampling to reduce variance compared to pure random generation, while restricting rays to a fixed maximum distance for performance. Choose it for efficient first-bounce global illumination in voxel-based rendering.

## Background
The Grid Ray Sampler is a fundamental component in computer graphics and neural rendering pipelines for generating camera rays from pixel coordinates [S1, S2, unofficial]. It is widely used in NeRF-based methods and differentiable rendering frameworks [S1, S2, unofficial][S3, unofficial][S4]. The method relies on standard pinhole camera models and homogeneous coordinate transformations [S2, unofficial].
