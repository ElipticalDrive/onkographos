# Grid Ray Sampler


## Overview
The Grid Ray Sampler generates camera rays by sampling pixel coordinates from a 2D image grid, lifting them to 3D space using intrinsic parameters, and transforming them into world coordinates via a camera pose matrix [S1, unofficial]. It differs from its siblings by explicitly handling the geometric transformation from discrete pixel indices to continuous world-space ray origins and directions, supporting both uniform full-grid sampling and random subsampling [S1, unofficial]. Unlike [Sky Gradient](1262-sky-gradient.md) which models environmental lighting, or [Arcball Camera](1639-arcball-camera.md) which defines interactive control, this method focuses on the deterministic or stochastic generation of ray bundles for rendering pipelines [S1, unofficial].

## How it works
**Inputs:**
- `pose`: Camera-to-world transformation matrix of shape $[B, 4, 4]$ (Batch, 4x4).
- `intrinsic`: Camera intrinsic matrix of shape $[B, 3, 3]$.
- `H`, `W`: Image height and width.
- `num_rays`: Number of rays to sample (used when `full_grid` is False).
- `full_grid`: Boolean flag; if True, sample all $H \times W$ pixels; if False, sample `num_rays` randomly.
- `prefix`: List of dimensions to prepend to the output tensor shape (e.g., batch dimensions).

**Outputs:**
- `rays_o`: Ray origins of shape $[B, N, 3]$.
- `rays_d`: Ray directions of shape $[B, N, 3]$.

**Data Structures:**
- Pixel coordinates `i`, `j`: Integer grids representing row and column indices.
- `pixel_points_cam`: Homogeneous 3D points in camera space, shape $[B, 3, N]$.
- `world_coords`: Transformed 3D points in world space, shape $[B, 3, N]$.

**Steps:**
1. **Determine Ray Count:**
   If `full_grid` is True, $N = H \times W$. Otherwise, $N = \text{num\_rays}$.

2. **Generate Pixel Grid:**
   Create 2D grids for pixel indices $i$ (rows) and $j$ (columns) using `torch.meshgrid` with `indexing="ij"`.
   $$ i, j = \text{meshgrid}(\text{range}(H), \text{range}(W), \text{indexing}="ij") $$

3. **Reshape and Expand Indices:**
   Reshape $i$ and $j$ to match the batch and prefix dimensions, then flatten the spatial dimensions to size $H \times W$.
   $$ i_{flat} = i.t().\text{reshape}([*[1] * \text{len(prefix)}, H \times W]) $$
   $$ i_{expanded} = i_{flat}.\text{expand}([*\text{prefix}, H \times W]) $$
   Repeat for $j$.

4. **Select Indices (Optional):**
   If `full_grid` is False, select $N$ random indices from the flattened grid.
   $$ \text{select\_inds} = \text{randint}(0, H \times W, \text{size}=[N], \text{device}=\text{device}) $$
   Gather the corresponding $i$ and $j$ values using `select_inds`.

5. **Lift to Camera Space:**
   Convert pixel coordinates $(i, j)$ to 3D points in the camera coordinate system using the intrinsic matrix.
   $$ \mathbf{p}_{cam} = \text{lift}(i, j, \mathbf{1}, \text{intrinsic}) $$
   Where $\mathbf{1}$ is a vector of ones matching the size of $i$ and $j$. The `lift` function typically computes:
   $$ x_{cam} = (i - c_x) / f_x $$
   $$ y_{cam} = (j - c_y) / f_y $$
   $$ z_{cam} = 1 $$
   Resulting in points of shape $[B, 3, N]$.

6. **Transform to World Space:**
   Apply the camera pose transformation to convert points from camera space to world space.
   $$ \mathbf{p}_{world} = \text{bmm}(\text{pose}, \mathbf{p}_{cam}).\text{transpose}(-1, -2)[..., :3] $$
   This yields world coordinates of shape $[B, N, 3]$.

7. **Compute Ray Directions:**
   Calculate the direction vector from the ray origin to the world coordinate point.
   $$ \mathbf{d}_{raw} = \mathbf{p}_{world} - \mathbf{o}_{world} $$
   Where $\mathbf{o}_{world}$ is the camera origin extracted from the pose matrix ($\text{pose}[..., :3, 3]$).

8. **Normalize Directions:**
   Normalize the direction vectors to unit length.
   $$ \mathbf{d} = \text{normalize}(\mathbf{d}_{raw}) $$

9. **Expand Ray Origins:**
   Expand the ray origin $\mathbf{o}_{world}$ to match the shape of the directions $[B, N, 3]$.

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def grid_ray_sampler(pose, intrinsic, H, W, num_rays, full_grid, prefix, device):
    """
    Generate rays from a grid of pixel coordinates.
    
    Args:
        pose: [B, 4, 4] Camera-to-world matrix.
        intrinsic: [B, 3, 3] Camera intrinsic matrix.
        H: int, Height.
        W: int, Width.
        num_rays: int, Number of rays if full_grid is False.
        full_grid: bool, If True, sample all pixels.
        prefix: list, Batch/prefix dimensions.
        device: torch.device.
        
    Returns:
        rays_o: [B, N, 3] Ray origins.
        rays_d: [B, N, 3] Ray directions.
    """
    B = pose.shape[0]
    
    # 1. Determine number of rays
    if full_grid:
        N = H * W
    else:
        N = num_rays
        
    # 2. Generate pixel coordinates
    i, j = torch.meshgrid(torch.arange(H, device=device), torch.arange(W, device=device), indexing="ij")
    
    # 3. Reshape and expand
    # i, j are [H, W]. Transpose to [W, H] then reshape.
    # Note: The source uses i.t().reshape(...).expand(...)
    # We assume prefix is handled by expanding dimensions.
    # For simplicity, we assume prefix is empty or handled by batch dim B.
    # The source code shows: i = i.t().reshape([*[1] * len(prefix), H * W]).expand([*prefix, H * W])
    # Here we handle B as part of the batch, so prefix might be [] or [B].
    # Let's assume the function is called per batch or B is in prefix.
    # To match source exactly:
    prefix_dims = [1] * len(prefix)
    i_flat = i.t().reshape(prefix_dims + [H * W])
    j_flat = j.t().reshape(prefix_dims + [H * W])
    
    # Expand to include batch dimension B if not already in prefix
    # The source code implies prefix is separate from B in some contexts, 
    # but here pose is [B, 4, 4]. Let's assume B is the first dim.
    # We will expand to [B, H*W]
    i_flat = i_flat.expand([B] + prefix_dims + [H * W]) # Adjust based on actual prefix usage
    j_flat = j_flat.expand([B] + prefix_dims + [H * W])
    
    # If prefix is not empty, the reshape logic in source is specific.
    # Simplified for standard [B, H, W] input:
    i_flat = i.t().reshape(B, H * W)
    j_flat = j.t().reshape(B, H * W)
    
    # 4. Select indices if not full grid
    if not full_grid:
        # Flatten to select random indices
        i_flat = i_flat.view(B, -1)
        j_flat = j_flat.view(B, -1)
        
        # Select random indices for each batch item? 
        # Source: select_inds = torch.randint(0, len(i.view(-1)), size=[N_rays], device=device)
        # This selects N_rays globally or per batch? 
        # "len(i.view(-1))" suggests total elements. 
        # However, pose is [B, ...]. 
        # Usually, random sampling is done per batch or globally.
        # Source code: 
        # select_inds = torch.randint(0, len(i.view(-1)), size=[N_rays], device=device)
        # This implies global random selection if i is not batched in the view.
        # But i was expanded. 
        # Let's assume standard random sampling per batch or global.
        # Given the source snippet:
        # i = i.t().reshape(...).expand(...)
        # select_inds = torch.randint(0, len(i.view(-1)), ...)
        # This suggests selecting N_rays from the total flattened grid.
        
        # To be safe and implementable:
        # We will select N_rays indices from the total H*W pixels.
        # If B > 1, this might need adjustment, but source implies a single selection logic.
        # Let's assume B=1 for the random case or that N_rays is total.
        
        total_pixels = H * W
        select_inds = torch.randint(0, total_pixels, size=[N], device=device)
        
        # Gather
        # i_flat is [B, H*W]. We need to gather for each batch?
        # Source doesn't show batched gathering explicitly for random case, 
        # but pose is [B, 4, 4].
        # If B > 1, we likely need to select N_rays/B per batch or N_rays total.
        # Given the ambiguity, we stick to the source's global selection if B=1,
        # or assume the method handles B internally.
        # For a general implementation:
        rays_o_indices = select_inds # Global indices
        # Reshape to [B, N] if needed? Source doesn't show this.
        # We will assume B=1 for the random sampling logic in the source snippet 
        # or that the method is called per batch.
        
        i_selected = i_flat[0, select_inds] # Assuming B=1 for random
        j_selected = j_flat[0, select_inds]
    else:
        i_selected = i_flat
        j_selected = j_flat
        
    # 5. Lift to camera space
    # intrinsic is [B, 3, 3] or [3, 3]. Source: intrinsic=intrinsic
    # lift function:
    # x = (i - cx) / fx
    # y = (j - cy) / fy
    # z = 1
    
    # Extract intrinsics
    fx = intrinsic[..., 0, 0]
    fy = intrinsic[..., 1, 1]
    cx = intrinsic[..., 0, 2]
    cy = intrinsic[..., 1, 2]
    
    # Normalize coordinates
    # i_selected, j_selected are [N] or [B, N]
    # We need to handle broadcasting.
    
    # If B > 1 and full_grid, i_selected is [B, H*W]
    # If B=1 and random, i_selected is [N]
    
    # Let's assume i_selected, j_selected are [B, N] or [N]
    # If [N], expand to [B, N]
    if i_selected.dim() == 1:
        i_selected = i_selected.unsqueeze(0).expand(B, N)
        j_selected = j_selected.unsqueeze(0).expand(B, N)
        
    # Compute camera space points
    # x_cam = (i - cx) / fx
    # y_cam = (j - cy) / fy
    # z_cam = 1
    
    # fx, fy, cx, cy are [B] or [B, 1] or scalars
    # i_selected is [B, N]
    
    x_cam = (i_selected - cx.unsqueeze(-1)) / fx.unsqueeze(-1)
    y_cam = (j_selected - cy.unsqueeze(-1)) / fy.unsqueeze(-1)
    z_cam = torch.ones_like(x_cam)
    
    pixel_points_cam = torch.stack([x_cam, y_cam, z_cam], dim=-1) # [B, N, 3]
    
    # 6. Transform to world coordinates
    # pose is [B, 4, 4]
    # Homogeneous coordinates for pixel_points_cam
    pixel_points_cam_homo = torch.cat([pixel_points_cam, torch.ones_like(pixel_points_cam[..., :1])], dim=-1) # [B, N, 4]
    
    # Transform: world = pose * cam
    # pose is [B, 4, 4], points are [B, N, 4]
    # We need to multiply pose by points.
    # world_coords_homo = bmm(pose, points^T) -> [B, 4, N]
    # Then transpose to [B, N, 4]
    
    # Note: Source uses torch.bmm(pose, pixel_points_cam).transpose(-1, -2)
    # pixel_points_cam in source is [B, 3, N] (homogeneous z=1 included?)
    # Source: pixel_points_cam = lift(..., intrinsic)
    # If lift returns [B, 3, N], then bmm(pose [B,4,4], [B,3,N]) fails.
    # It must be [B, 4, N] or pose is [B, 4, 4] and points are [B, 4, N].
    # Source: pixel_points_cam = lift(i, j, torch.ones_like(i), intrinsic=intrinsic)
    # If lift returns [B, 3, N], then bmm won't work directly with [B, 4, 4].
    # However, source says: world_coords = torch.bmm(pose, pixel_points_cam).transpose(-1, -2)[..., :3]
    # This implies pixel_points_cam is [B, 4, N] or pose is [B, 4, 4] and it handles the 4th dim.
    # Actually, bmm(A [B,M,N], B [B,N,P]) -> [B,M,P].
    # If pose is [B, 4, 4] and points are [B, 4, N], result is [B, 4, N].
    # So lift must return [B, 4, N] or we append 1s.
    
    # Let's assume pixel_points_cam is [B, 4, N]
    pixel_points_cam_homo_t = torch.cat([pixel_points_cam, torch.ones_like(pixel_points_cam[..., :1])], dim=-1).permute(0, 2, 1) # [B, N, 4] -> [B, 4, N]
    
    world_coords_homo = torch.bmm(pose, pixel_points_cam_homo_t) # [B, 4, N]
    world_coords = world_coords_homo.transpose(-1, -2)[..., :3] # [B, N, 3]
    
    # 7. Compute ray origins
    rays_o = pose[..., :3, 3] # [B, 3]
    rays_o = rays_o.unsqueeze(1).expand(-1, N, -1) # [B, N, 3]
    
    # 8. Compute ray directions
    rays_d = world_coords - rays_o # [B, N, 3]
    
    # 9. Normalize directions
    rays_d = F.normalize(rays_d, dim=-1)
    
    return rays_o, rays_d
```

## Subtopics

### Ray Unification
Ray Unification maps every ray starting location onto a sphere circumscribed around the view cell (or around the object for 360-degree captures) [S2]. This ensures that identical rays have identical depth values regardless of the camera position, easing the task for the oracle network [S2]. Without this technique, the same ray is encoded differently depending on the starting location, requiring different depth values [S2]. It adds about 0.6 dB in PSNR compared to no unification [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of rays. The dominant operations are meshgrid generation, matrix multiplication, and normalization, all linear in the number of sampled pixels.
- **Memory Complexity:** $O(N)$ to store the ray origins and directions.
- **Performance:** Efficient on GPU due to vectorized tensor operations. Random sampling reduces $N$ significantly for large images, speeding up training/inference.
- **Strengths:** Simple, deterministic (for full grid), and flexible (supports random subsampling).
- **Limitations:** Does not handle depth sampling along the ray; that is handled by a separate volume rendering or marching step. Random sampling may introduce noise if not averaged over multiple passes.

## Background
The Grid Ray Sampler is a fundamental component in neural rendering pipelines, particularly in methods like NeRF and its variants [S1, unofficial]. It bridges the gap between 2D image space and 3D world space, providing the necessary ray data for subsequent volume rendering or neural network inference [S1, unofficial]. The specific implementation details, including the use of `torch.meshgrid` and `bmm` for batched matrix multiplication, are derived from common practices in PyTorch-based neural rendering frameworks [S1, unofficial].
