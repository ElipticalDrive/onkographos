# Near-Far Clipping

Also called: NearFar Collider

## Overview
Near-Far Clipping is a post-processing step applied to ray samples generated by a [Near-Far Linear Ray Sampler](6841-near-far-linear-ray-generation.md). Its purpose is to restrict the valid sampling interval to a specified viewing volume defined by a near plane and a far plane, ensuring that no samples are processed outside these bounds [S1, unofficial]. It differs from culling techniques (such as those used in splatting) by operating on the ray parameter space rather than the primitive space, making it applicable to both ray tracing and rasterization-based volume rendering pipelines [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of ray samples $\{s_i\}$, where each sample $s_i$ represents a distance $t$ from the camera origin along the ray direction.
*   **Input:** `near_plane` ($t_{\text{near}}$): The minimum valid distance from the camera origin [S1, unofficial].
*   **Input:** `far_plane` ($t_{\text{far}}$): The maximum valid distance from the camera origin [S1, unofficial].
*   **Output:** A filtered sequence of ray samples $\{s'_j\}$ such that $t_{\text{near}} \le s'_j \le t_{\text{far}}$ for all $j$.

**Data Structures:**
The method operates on a 1D array or list of floating-point values representing distances. No complex data structures are required beyond the input sample array.

**Steps:**
1.  Initialize an empty output list `valid_samples`.
2.  For each sample $s$ in the input ray samples:
    a. Let $t$ be the distance value of sample $s$.
    b. If $t < t_{\text{near}}$, discard $s$.
    c. If $t > t_{\text{far}}$, discard $s$.
    d. Otherwise, append $s$ to `valid_samples`.
3.  Return `valid_samples`.

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def near_far_clip(samples, near_plane, far_plane):
    """
    Clips ray samples to the range [near_plane, far_plane].
    
    Args:
        samples: List or array of float distances from camera origin.
        near_plane: Minimum valid distance (float).
        far_plane: Maximum valid distance (float).
        
    Returns:
        List of samples within the valid range.
    """
    valid_samples = []
    for s in samples:
        if s >= near_plane and s <= far_plane:
            valid_samples.append(s)
    return valid_samples
```

**Parameters:**
*   `near_plane`: The minimum distance from the camera origin for valid ray samples [S1, unofficial].
*   `far_plane`: The maximum distance from the camera origin for valid ray samples [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Invalid Ranges:** If `near_plane` > `far_plane`, the output will always be empty. Implementers should validate this condition [G].
*   **Precision:** Floating-point comparisons should account for epsilon errors if samples lie exactly on the boundary, though standard `>=` and `<=` operators are typically sufficient for standard rendering distances [G].
*   **Empty Input:** If no samples fall within the range, the method returns an empty list, which downstream rendering steps must handle gracefully (e.g., skipping shading) [G].

## Subtopics

### Near Clipping Plane Floater Masking
A specific application of near clipping used in 3D Gaussian Splatting to reduce the visual impact of "floaters" (noisy Gaussians near the camera) [S2]. For ray tracers, this is implemented by starting the trace further along the initial ray (effectively setting a higher `near_plane`) [S2]. For splatting, it involves culling Gaussians whose centroids are closer than $d_{\text{near}}$ to the camera [S2]. The parameter $d_{\text{near}}$ varies by scene; typical values include 1.00 for `counter`, `flowers`, and `room`; 2.00 for `bicycle`, `drjohnson`, and `garden`; 3.00 for `bonsai`; 5.00 for `playroom`; 2.50 for `stump`; 0.65 for `train`; 3.25 for `treehill`; and 1.45 for `truck` [S2]. A key pitfall is that quality metrics (PSNR, SSIM, LPIPS) are typically measured *without* clipping planes to ensure fair comparison, as the clipping offers negligible improvements to these metrics (e.g., TreeHill PSNR changes from 26.91 to 26.93 at $d_{\text{near}}=1.0$; Garden PSNR changes from 21.89 to 21.94 at $d_{\text{near}}=2.0$) [S2].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(N)$, where $N$ is the number of ray samples. Each sample is checked once against two constants.
*   **Memory:** $O(K)$, where $K$ is the number of valid samples retained ($K \le N$). In the worst case (all samples valid), memory usage is proportional to the input size.

**Measured Performance:**
Not given in the sources. The method is a simple filter and is generally considered computationally negligible compared to ray marching or shading [S1, unofficial][S2].

**Strengths and Limitations:**
*   **Strengths:** Simple to implement; effective at removing artifacts from invalid viewing volumes; applicable to both ray tracing and splatting pipelines [S1, unofficial][S2].
*   **Limitations:** Does not improve perceptual quality metrics significantly in some cases (e.g., 3DGS floaters) [S2]. Requires careful tuning of `near_plane` to avoid clipping valid geometry [S2].

**When to Use:**
Use when the rendering pipeline requires restricting the sampling domain to a specific depth range, such as avoiding near-plane artifacts or limiting the far clipping distance for performance [S1, unofficial][S2].

**When Not to Use:**
Do not use if the goal is to optimize quality metrics where clipping provides negligible benefit, as it may complicate the pipeline without measurable gain [S2].

## Background
The concept of near-far clipping is fundamental in computer graphics for defining the viewing frustum. In the context of volume rendering and neural rendering, it is used to manage the sampling density and avoid artifacts from invalid regions [S1, unofficial]. The specific application to 3D Gaussian Splatting for floater reduction was documented in the GRay paper, which highlighted the negligible impact on standard metrics despite visual improvements [S2].
