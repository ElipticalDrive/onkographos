# Depth Network

Also called: Depth Network d

## Overview
The Depth Network is a hybrid module for estimating and refining per-pixel depth maps from image inputs, designed to resolve the scaling and shifting ambiguities inherent in single-image depth estimation while mitigating the inaccuracies of applying Multi-View Stereo (MVS) to sparse views [S1]. It combines an initial MVS estimation with a U-Net refinement stage that leverages both multi-view stereo cues and image features to produce consistent depth maps suitable for point cloud construction [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Image $I_i$ and initial depth estimates. The initial depth estimates are either generated by an MVS module (e.g., PatchmatchNet) or provided directly as sensor depths $D^{sen}$ [S1].
*   **Output:** Refined depth map $D_i$ [S1].

**Data Structures:**
*   **Image $I_i$:** Standard RGB image.
*   **Initial Depth:** A depth map of the same spatial resolution as $I_i$. If from MVS, it is a probabilistic or confidence-weighted estimate; if from sensor, it may contain noise and holes [S1].
*   **Binary Mask $M_i$:** A mask of the same spatial resolution as the depth map, where $M_i = 1$ indicates valid sensor depth pixels and $M_i = 0$ indicates invalid/missing data [S1].

**Method Steps:**
1.  **Initial Estimation:** If sensor depths are not available, run an MVS module (specifically PatchmatchNet [S1]) on the input image $I_i$ (and potentially neighboring views if available) to generate an initial depth estimation. This step addresses the challenge of limited overlap and huge baselines in sparse inputs [S1].
2.  **U-Net Input Preparation:** Construct the input tensor for the U-Net. The U-Net takes the image $I_i$ and the initial depth estimation (from MVS or sensor) as inputs [S1].
3.  **Refinement:** Pass the inputs through the U-Net. The network refines the depth by integrating multi-view stereo cues (if available from the MVS stage) and image cues (texture/appearance from $I_i$) to output the refined depth $D_i$ [S1].
4.  **Point Cloud Construction:** Use the refined depth $D_i$ to back-project pixels into 3D space to build the point cloud for the view [S1].

**Training and Loss:**
When sensor depths $D^{sen}$ are available, they serve as the ground truth target for refinement. The U-Net acts as a completion and refinement module, handling the noise and incompleteness typical of sensor data [S1]. The training loss $L_s$ is defined as:

$$
L_s = \| M_i D_i - M_i D^{sen} \|
$$

where:
*   $D_i$ is the U-Net output (refined depth).
*   $D^{sen}$ is the sensor depth.
*   $M_i$ is the binary mask indicating valid sensor depths [S1].

```python
def depth_network(image_i, sensor_depth=None, mvs_module=None, unet=None):
    """
    Estimates and refines depth for a single view.
    
    Args:
        image_i: Input RGB image.
        sensor_depth: Optional sensor depth map. If None, MVS is used.
        mvs_module: Instance of PatchmatchNet or similar MVS module.
        unet: Instance of the refinement U-Net.
        
    Returns:
        refined_depth: Refined depth map D_i.
    """
    # Step 1: Generate initial depth estimation
    if sensor_depth is not None:
        # Use sensor depth directly as initial estimate
        initial_depth = sensor_depth
        # Note: Sensor depths are often noisy/incomplete, handled by U-Net
    else:
        # Use MVS module to estimate depth
        # PatchmatchNet is cited as the specific implementation [S1]
        if mvs_module is None:
            raise ValueError("MVS module required when sensor_depth is not provided")
        initial_depth = mvs_module.estimate(image_i)
        
    # Step 2: Refine using U-Net
    # The U-Net takes image I_i and initial_depth as inputs [S1]
    refined_depth = unet(image_i, initial_depth)
    
    return refined_depth

def compute_sensor_loss(refined_depth, sensor_depth, mask):
    """
    Computes the sensor depth loss L_s.
    
    Args:
        refined_depth: U-Net output D_i.
        sensor_depth: Ground truth sensor depth D^sen.
        mask: Binary mask M_i for valid sensor depths.
        
    Returns:
        loss: Scalar loss value.
    """
    # Apply mask to both depth maps
    masked_refined = refined_depth * mask
    masked_sensor = sensor_depth * mask
    
    # Compute L2 norm (Euclidean distance)
    # The source uses || ... || which implies L2 norm [S1]
    loss = torch.norm(masked_refined - masked_sensor)
    
    return loss
```

**Parameters and Edge Cases:**
*   **MVS Module:** PatchmatchNet is specified as the MVS module due to its speed and lightweight nature [S1].
*   **Sensor Depth Availability:** If $D^{sen}$ is available, it bypasses the MVS step and is fed directly to the U-Net [S1].
*   **Sparse Inputs:** The hybrid design is specifically chosen because applying MVS solely on sparse inputs is challenging due to limited overlap and huge baselines, leading to inaccurate/low-confidence estimations [S1].
*   **Single-Image Ambiguity:** Pure single-image estimation suffers from scaling/shifting ambiguity and loses multi-view cues [S1].

## Operating characteristics
*   **Complexity:** The MVS module (PatchmatchNet) is described as "fast and lightweight" [S1]. The U-Net refinement adds computational cost but is necessary for consistency.
*   **Strengths:** Resolves scaling/shifting ambiguity of single-image methods; handles sparse input limitations of standard MVS; integrates sensor data for completion [S1].
*   **Limitations:** Relies on the quality of the initial MVS estimate or sensor data; performance depends on the U-Net's ability to generalize across views [S1].
*   **Use Cases:** Novel view synthesis from sparse inputs; scenarios where sensor data is available but noisy/incomplete [S1].

## Background
The Depth Network is part of the FWD (Forward Warping and Depth) framework for real-time novel view synthesis [S1]. It was introduced to address the limitations of existing depth estimation methods when applied to sparse view sets, where traditional MVS fails due to large baselines and single-image methods fail due to ambiguity [S1]. The method builds on PatchmatchNet [77] for initial estimation and uses a U-Net architecture for refinement [S1].
