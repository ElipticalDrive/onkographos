# Stereo Pseudo 3D Rendering via Image Stacks

Also called: Pseudo Stereo Pair Generation, Stereo Pseudo 3D, Web-based Stereo Pseudo 3D

## Overview
This method generates a stereo pair of images from a pre-existing 2D image stack to simulate binocular parallax and volumetric depth perception using standard web technologies [S1]. It solves the problem of visualizing scientific volumetric data in a browser without specialized hardware or client-side rendering engines [S1]. It is distinguished from full ray-casting volume rendering by relying on image overlay and CSS positioning rather than per-pixel shading, and from single-slice viewers like BrainMaps.org by allowing simultaneous visibility of multiple depth layers [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A stack of $N$ 2D images (e.g., PNG slices) representing cross-sections of a volume [S1].
*   **Output:** Two HTML DOM trees (stacks) containing positioned `<img>` elements that produce a 3D effect when viewed with stereo merging [S1].

**Data Structures**
The implementation relies on the HTML Document Object Model (DOM) [S1].
*   **Containers:** Two `<div>` elements with `position: absolute` CSS styling [S1]. One serves as the base stack (`imgstacks`), the other as the offset stack (`imgoffsets`) [S1].
*   **Image Elements:** `<img>` nodes created dynamically [S1]. Each has `position: absolute`, and explicit `top`, `left`, `width`, and `height` style properties [S1].
*   **Preprocessing:** Input images must have alpha channels added, with background pixels set to transparent to allow proper overlay blending [S1].

**Numbered Steps**
1.  **Preprocess Images:** Convert input slices to PNG format with transparent backgrounds [S1]. Generate a single semi-opaque white image (e.g., 180x180 pixels, 10% opacity) to be reused for distance attenuation [S1].
2.  **Initialize DOM:** Create two absolute-positioned `<div>` containers in the HTML structure: one for the base stack and one for the offset stack [S1].
3.  **Generate Base Stack:** Iterate through the image stack from $i = 0$ to $N-1$ [S1]. For each data slice $i$: create an `<img>` element, set `src` to the data slice, set `position` to `absolute`, and set `top` and `left` to the base coordinates (e.g., 0,0 relative to container) [S1]. Append to the base stack container [S1]. Insert the semi-opaque white image between every pair of data slices to simulate distance attenuation (aerial perspective) [S1].
4.  **Generate Offset Stack:** Iterate through the image stack from $i = 0$ to $N-1$ [S1]. For each data slice $i$: create an `<img>` element, set `src` to the data slice, set `position` to `absolute`, calculate horizontal position: $x_i = x_{i-1} + \Delta x$, where for the first slice $x_0$ is the base left position, set `left` to $x_i$, keep `top` identical to the base stack, and append to the offset stack container [S1]. Insert the semi-opaque white image between every pair of data slices in the offset stack as well [S1].
5.  **Display:** Load both stacks into the browser [S1]. The combined result is viewed with stereo merging to perceive the 3D effect [S1].

**Formulas**
*   Horizontal offset accumulation: $x_i = x_{i-1} + \Delta x$ for $i > 0$, with $x_0 = x_{\text{base}}$ [S1].
*   Distance attenuation: achieved by interleaving a semi-opaque layer with opacity $\alpha$ between data slices [S1].

**Parameters**
*   **Opacity of interleaving layer ($\alpha$):** Typically 10% (0.1) for the semi-opaque white image [S1].
*   **Horizontal offset per slice ($\Delta x$):** Typically 1 pixel relative to the previous slice's position [S1].
*   **Eye separation:** Approximately 6 cm, used to calculate horizontal disparities for stereoscopic depth perception [S1].
*   **Image Resolution:** Example usage subsampled to 180x180 pixels from 512x512 source [S1].

**Edge Cases and Pitfalls**
*   **Pseudo-Accuracy:** Fixed linear offsetting produces "pseudo" accurate stereo pairs, not fully accurate geometric projections [S1]. Nonlinear offsetting based on a depth function can improve accuracy but is not implemented in the basic method [S1].
*   **Viewpoint Rigidity:** The viewpoint is predetermined by the image stack organization [S1]. Interactive viewpoint changes (rotation, zoom) are not supported on the fly [S1].
*   **Viewer Strain:** Stereo merging requires the user to perform cross-viewing or parallel viewing, which can cause eye strain [S1]. Optical aids (mirrors/prisms) may be required [S1].
*   **Performance Scaling:** Memory and load time scale linearly with the number of images [S1].

**Pseudocode**
```python
class DOMElement:
    def __init__(self, tag, attrs=None):
        self.tag = tag
        self.attrs = attrs or {}
        self.children = []
    def append(self, child):
        self.children.append(child)

def generate_stereo_pseudo_3d(image_stack, num_slices, offset_per_slice=1, opacity=0.1):
    """
    Generates DOM structures for stereo pseudo 3D rendering.
    image_stack: List of image data/paths.
    num_slices: Number of data slices N.
    offset_per_slice: Horizontal pixel shift per slice depth.
    opacity: Opacity of the interleaving attenuation layer.
    """
    # 1. Preprocessing assumed done: images are transparent PNGs.
    # Generate a single semi-opaque white image for attenuation.
    attenuation_image = {"src": "attenuation_10pct.png", "opacity": opacity}

    # 2. Initialize DOM containers
    base_container = DOMElement("div", {"id": "imgstacks", "position": "absolute"})
    offset_container = DOMElement("div", {"id": "imgoffsets", "position": "absolute"})
    content_container = DOMElement("div", {"id": "imgcontent", "position": "absolute"})
    content_container.append(base_container)
    content_container.append(offset_container)

    # 3. Build Base Stack
    current_top = 0
    current_left = 0

    for i in range(num_slices):
        # Add data slice
        img_elem = DOMElement("img", {"src": image_stack[i], "position": "absolute",
                                      "top": str(current_top) + "px", "left": str(current_left) + "px"})
        base_container.append(img_elem)

        # Add attenuation layer between slices (except after the last one)
        if i < num_slices - 1:
            att_img = DOMElement("img", {"src": attenuation_image["src"], "position": "absolute",
                                         "top": str(current_top) + "px", "left": str(current_left) + "px"})
            base_container.append(att_img)

    # 4. Build Offset Stack
    offset_top = 0
    offset_left = 0

    for i in range(num_slices):
        # Add data slice with cumulative horizontal offset
        current_offset_x = offset_left + i * offset_per_slice
        img_elem = DOMElement("img", {"src": image_stack[i], "position": "absolute",
                                      "top": str(offset_top) + "px", "left": str(current_offset_x) + "px"})
        offset_container.append(img_elem)

        # Add attenuation layer
        if i < num_slices - 1:
            att_img = DOMElement("img", {"src": attenuation_image["src"], "position": "absolute",
                                         "top": str(offset_top) + "px", "left": str(current_offset_x) + "px"})
            offset_container.append(att_img)

    return content_container
```

## Operating characteristics
*   **Time Complexity:** Linear $O(N)$ with respect to the number of images $N$ for loading and DOM construction [S1].
*   **Memory Complexity:** Linear $O(N)$, as each image is stored in the browser cache and DOM [S1].
*   **Measured Performance:** On a 1.7 GHz PC with 1GB RAM, displaying 50 overlayed images took approximately 3 seconds after download [S1]. Load time and memory usage scaled linearly for 15, 30, and 50 images (95kB–126kB each) on Firefox 2.0 and IE 7.0 [S1].
*   **Strengths:** Requires no specialized software, hardware, or client-side computation; works in standard web browsers with CSS/JS support [S1]. Allows viewing multiple stacked images simultaneously to perceive volumetric structures [S1].
*   **Limitations:** No interactive viewpoint changes; stereo accuracy is approximate; requires user ability to merge stereo images; potential eye strain [S1].
*   **When to Use:** Web-based display of static scientific volumetric data where interactive 3D rendering is not feasible or necessary [S1].
*   **When Not to Use:** When interactive viewpoint changes or high-precision geometric stereo are required [S1].

## Background
The method was developed by D. C.-Y. Eng and Y. Choe and presented at the Pacific Graphics 2008 conference [S1]. It was applied to visualize 50 slices of mouse spinal cord scans from the KESM dataset, where blood vessels were stained with India ink [S1]. The approach contrasts with BrainMaps.org, which displays one slide at a time, and other web-based 3D approaches that require specialized software or hardware [S1].
