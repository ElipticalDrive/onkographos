# Sky Gradient

Also called: Aurora Rendering, Aurora curtains, Horizon-Zenith Gradient, Neon Sky, Sky gradient texture, Synthwave Sky Gradient, getSky

## Overview
Sky Gradient generates a background color for rays that do not intersect the primary volume, interpolating between a horizon color and a zenith color based on the ray's vertical direction component [S1, S3, S4, unofficial]. It differs from [SkyboxRendering](2619-skyboxrendering.md) by lacking time-dependent sun/moon arcs or procedural starfields in its core definition [S1, S2, S3, unofficial].

## How it works
**Inputs and Outputs**
- Input: Ray direction vector $\mathbf{d}$ (typically normalized) [G].
- Input: Horizon color $\mathbf{C}_{horizon}$ (RGB) [S1, S3, S4, unofficial].
- Input: Zenith color $\mathbf{C}_{zenith}$ (RGB) [S1, S3, S4, unofficial].
- Input: Optional transition parameters (bounds, power, glow intensity) [S1, S4, unofficial].
- Output: Background color $\mathbf{C}_{sky}$ (RGB) [S1, S3, S4, unofficial].

**Data Structures**
No persistent data structures are required. The method is a pure function of the ray direction and uniform color parameters [G].

**Steps**
1.  **Normalize Direction**: Ensure the ray direction $\mathbf{d}$ is normalized. If the input is a point $\mathbf{p}$ relative to the camera, compute $\mathbf{d} = \text{normalize}(\mathbf{p})$ [S1, S3, unofficial].
2.  **Compute Vertical Component**: Extract the vertical component $y = \mathbf{d}_y$ (the y-component of the normalized direction vector) [S1, S3, S4, unofficial].
3.  **Compute Interpolation Factor**: Calculate a factor $t$ that maps the vertical range to $[0, 1]$ [G]. Two common variations exist:
    -   *Linear Mapping*: $t = 0.5 \times (y + 1.0)$ [S3, unofficial]. This maps $y=-1$ (nadir) to $t=0$ and $y=1$ (zenith) to $t=1$ [G].
    -   *Smoothstep Mapping*: $t = \text{smoothstep}(0.0, 0.7, y)$ [S1, unofficial]. This creates a smooth transition starting at $y=0$ and completing at $y=0.7$ [S1, unofficial].
    -   *Clamped Linear*: $h = \text{clamp}(0.5 \times y + 0.5, 0.0, 1.0)$ [S4, unofficial].
4.  **Apply Power (Optional)**: Some implementations apply a power function to the factor to adjust the gradient curve. For example, use $h^{0.55}$ instead of $h$ [S4, unofficial].
5.  **Interpolate Colors**: Compute the base sky color using linear interpolation (mix):
    $$ \mathbf{C}_{base} = (1 - t) \mathbf{C}_{horizon} + t \mathbf{C}_{zenith} $$
    Or using the power-adjusted factor $h$:
    $$ \mathbf{C}_{base} = (1 - h^p) \mathbf{C}_{horizon} + h^p \mathbf{C}_{zenith} $$
    where $p$ is the mix power (e.g., 0.55) [S4, unofficial].
6.  **Add Ground Glow (Optional)**: Enhance the horizon with a glow effect [S4, unofficial]. Compute the glow intensity based on the distance from the horizon:
    $$ \mathbf{C}_{glow} = \mathbf{C}_{horizon} \times I \times (1.0 - |y|)^g $$
    where $I$ is intensity (e.g., 0.4) and $g$ is the glow power (e.g., 6.0) [S4, unofficial].
7.  **Combine**: Add the glow to the base color:
    $$ \mathbf{C}_{sky} = \mathbf{C}_{base} + \mathbf{C}_{glow} $$
    [S4, unofficial].

**Pseudocode**
```python
import math

def normalize(v):
    length = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    if length == 0.0:
        return (0.0, 0.0, 0.0)
    return (v[0]/length, v[1]/length, v[2]/length)

def smoothstep(edge0, edge1, x):
    t = max(0.0, min(1.0, (x - edge0) / (edge1 - edge0)))
    return t * t * (3.0 - 2.0 * t)

def mix(a, b, t):
    return (a[0]*(1.0-t) + b[0]*t, a[1]*(1.0-t) + b[1]*t, a[2]*(1.0-t) + b[2]*t)

def clamp(x, min_val, max_val):
    return max(min_val, min(max_val, x))

def sky_gradient(direction, horizon, zenith, use_smoothstep=False, smoothstep_max=0.7, mix_power=1.0, glow_intensity=0.0, glow_power=6.0):
    d = normalize(direction)
    y = d[1]
    
    if use_smoothstep:
        t = smoothstep(0.0, smoothstep_max, y)
    else:
        t = 0.5 * (y + 1.0)
        t = clamp(t, 0.0, 1.0)
        
    t_pow = t ** mix_power
    base_color = mix(horizon, zenith, t_pow)
    
    if glow_intensity > 0.0:
        glow_factor = (1.0 - abs(y)) ** glow_power
        glow_color = (horizon[0]*glow_intensity*glow_factor, horizon[1]*glow_intensity*glow_factor, horizon[2]*glow_intensity*glow_factor)
        base_color = (base_color[0]+glow_color[0], base_color[1]+glow_color[1], base_color[2]+glow_color[2])
        
    return base_color
```

**Parameters**
-   **Horizon Color**: RGB vector. Example: `(0.80, 0.90, 1.0)` [S1, unofficial], `(0.55, 0.06, 0.32)` [S4, unofficial], `(255, 100, 80)` [S3, unofficial].
-   **Zenith Color**: RGB vector. Example: `(0.35, 0.60, 0.95)` [S1, unofficial], `(0.02, 0.01, 0.05)` [S4, unofficial], `(10, 20, 60)` [S3, unofficial].
-   **Smoothstep Bounds**: Transition range for $d.y$. Example: `(0.0, 0.7)` [S1, unofficial].
-   **Mix Power**: Exponent for interpolation factor. Example: `0.55` [S4, unofficial]. Default: `1.0`.
-   **Glow Intensity**: Multiplier for ground glow. Example: `0.4` [S4, unofficial]. Default: `0.0`.
-   **Glow Power**: Exponent for glow falloff. Example: `6.0` [S4, unofficial]. Default: `1.0`.

**Edge Cases and Pitfalls**
-   **Non-normalized Input**: If the direction vector is not normalized, the $y$-component will not accurately represent the vertical angle, leading to incorrect gradient placement. Always normalize [G].
-   **Precision**: When $y$ is close to 0 or 1, floating-point precision errors might cause slight color shifts. Clamping $t$ to $[0, 1]$ mitigates this [G].
-   **Degenerate Input**: If horizon and zenith colors are identical, the result is constant regardless of direction [G].

## Subtopics

### [SkyboxRendering](2619-skyboxrendering.md)
Generates a dynamic sky color with time-dependent sun/moon arcs, day/night palettes, and a hashed starfield. Choose when you need a realistic day/night cycle or starfield.

### [Background Rendering](5042-background-rendering.md)
Uses a learnable/procedural 3D grid sampled on spherical shells with volumetric attenuation. Choose when you need density-based background sampling or volumetric fog effects in the background.

## Operating characteristics
-   **Time Complexity**: $O(1)$ per ray. The computation involves a few arithmetic operations and trigonometric functions (if normalization is required) [G].
-   **Memory Complexity**: $O(1)$. No additional memory is required beyond the input parameters [G].
-   **Performance**: Extremely fast. Suitable for real-time rendering on any hardware [G].
-   **Strengths**: Simple to implement, computationally inexpensive, easy to tune visually [G].
-   **Limitations**: Lacks physical accuracy (no scattering, no sun position), no temporal variation (static unless manually animated), no starfields or complex atmospheric effects [G].
-   **When to Use**: Simple backgrounds, stylized rendering, performance-critical applications, or as a base for more complex sky models [G].
-   **When Not to Use**: When physical accuracy is required, when dynamic sun/moon positions are needed, or when volumetric background effects are desired [G].

## Background
Variations include "Aurora Rendering" which adds sine-wave based aurora effects [S2, unofficial], and implementations featuring ground glow and specific color palettes [S4, unofficial].
