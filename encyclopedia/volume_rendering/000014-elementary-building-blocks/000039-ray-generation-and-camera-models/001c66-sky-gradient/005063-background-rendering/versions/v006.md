# Background Rendering

## Overview
Background Rendering renders the environment behind a volume by sampling a 3D grid representing the background field along concentric spheres [S4, unofficial]. It handles infinite distance or skybox-like backgrounds by mapping spherical coordinates to a 2D equirectangular texture [S2, unofficial]. Unlike standard equirectangular sampling which may alias distant features, this method uses a structured traversal of background layers to mitigate aliasing [S1, unofficial]. It serves as the final compositing stage, accumulating color from background layers and adding a constant ambient term based on remaining transmission [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin `ray.origin`, ray direction `ray.dir`, background grid resolution `grid.background_reso`, number of background layers `grid.background_nlayers`, background data grid `grid.background_data` (density and color), log-transmittance `log_transmit` from the volume pass, optimization options `opt` (including `step_size`, `stop_thresh`, `background_brightness`), and ray world step size `ray.world_step` [S4, unofficial].
*   **Outputs:** Background color `out` (RGB) and updated log-transmittance [S4, unofficial].

**Data Structures:**
*   `grid.background_data`: A 3D grid of size `background_reso` x `background_reso` x `background_nlayers`. Each voxel stores 4 channels: 3 for color (RGB) and 1 for density ($\sigma$) [S4, unofficial].
*   `ray.l`: Integer lattice indices for trilinear interpolation [S4, unofficial].
*   `ray.pos`: Fractional offsets for trilinear interpolation [S4, unofficial].

**Parameters:**
*   `inner_radius`: Minimum sampling radius, calculated as $\max(\text{dist}(\text{ray.origin}, \text{ray.dir}) + 10^{-3}, 1.0)$ [S4, unofficial].
*   `n_steps`: Number of sampling steps, calculated as $\lfloor \text{grid.background\_nlayers} / \text{opt.step\_size} \rfloor + 2$ [S4, unofficial].
*   `C0`: Spherical Harmonic DC factor, typically $\frac{1}{\sqrt{4\pi}}$ [S4, unofficial].

**Steps:**
1.  **Early Termination Check:** If `log_transmit < -25.0`, return early to avoid numerical instability for fully opaque rays [S4, unofficial].
2.  **Initialization:** Compute `inner_radius` and `n_steps` [S4, unofficial]. Initialize output color `outv[3]` to zeros [S4, unofficial]. Set `invr_last` and `invr_mid` to track inverse radii across steps [S4, unofficial].
3.  **Sampling Loop:** Iterate `i` from `0` to `n_steps - 1`:
    a.  **Radius Calculation:** Compute sampling radius $r = \frac{n\_steps}{n\_steps - i - 0.5}$ [S4, unofficial]. This creates non-linear spacing, denser near the origin and sparser at infinity [S4, unofficial].
    b.  **Intersection:** Intersect the ray with a sphere of radius `r` centered at the origin [S4, unofficial]. If intersection fails or $r < \text{inner\_radius}$, skip to next step [S4, unofficial].
    c.  **Position Calculation:** Calculate ray position `ray.pos` at intersection $t$: `ray.pos[j] = ray.origin[j] + t * ray.dir[j]` [S4, unofficial].
    d.  **Normalization:** Normalize `ray.pos` and compute `invr_mid = 1.0 / \|ray.pos\|` [S4, unofficial].
    e.  **Depth Coordinate:** Set the z-coordinate (layer index) based on inverse radius: `ray.pos[2] = \text{clamp}((1.0 - \text{invr\_mid}) \times \text{grid.background\_nlayers} - 0.5, 0.0, \text{grid.background\_nlayers} - 1)` [S4, unofficial].
    f.  **Grid Indices:** Compute integer grid indices `ray.l` from `ray.pos` and clamp them to valid bounds: `ray.l[0]` to `2 \times \text{background\_reso} - 1`, `ray.l[1]` to `background\_reso - 1`, `ray.l[2]` to `background\_nlayers - 2` [S4, unofficial].
    g.  **Fractional Offsets:** Compute fractional offsets `ray.pos` by subtracting integer indices: `ray.pos[j] -= ray.l[j]` [S4, unofficial].
    h.  **Trilinear Interpolation:** Sample density $\sigma$ and color from `grid.background_data` using trilinear interpolation with `ray.l` and `ray.pos` [S4, unofficial].
    i.  **Optical Depth:** If $\sigma > 0$, calculate optical depth $pcnt = (\text{invr\_last} - \text{invr\_mid}) \times \text{ray.world\_step} \times \sigma$ [S4, unofficial].
    j.  **Weight Calculation:** Calculate weight $weight = e^{\text{log\_transmit}} \times (1 - e^{-pcnt})$ [S4, unofficial]. Update `log_transmit -= pcnt` [S4, unofficial].
    k.  **Color Accumulation:** For each color channel $i$ (0-2), interpolate color, scale by $C0$, add 0.5, clamp to $[0, \infty)$, and accumulate: `outv[i] += weight \times \max(\text{color} \times C0 + 0.5, 0.0)` [S4, unofficial].
    l.  **Update Inverse Radius:** Set `invr_last = invr_mid` [S4, unofficial].
    m.  **Termination Check:** If $e^{\text{log\_transmit}} < \text{opt.stop\_thresh}$, break loop [S4, unofficial].
4.  **Final Output:** For each channel $i$, add ambient term: `out[i] = outv[i] + e^{\text{log\_transmit}} \times \text{opt.background\_brightness}` [S4, unofficial].

**Pseudocode:**

```python
import math

def render_background_forward(grid, ray_spec, opt, log_transmit, out):
    """
    Renders the background color for a single ray using concentric sphere sampling.
    
    Args:
        grid: Background grid data structure containing background_reso, background_nlayers, background_data.
        ray_spec: Ray specification containing origin, dir, world_step.
        opt: Optimization options containing step_size, stop_thresh, background_brightness.
        log_transmit: Current log-transmittance of the ray.
        out: Output array for background color (size 3).
        
    Returns:
        Updated log_transmit.
    """
    # Early termination for fully opaque rays
    if log_transmit < -25.0:
        return log_transmit

    outv = [0.0, 0.0, 0.0]
    dist_to_origin = math.sqrt(sum(ray_spec.origin[j]**2 for j in range(3)))
    inner_radius = max(dist_to_origin + 1e-3, 1.0)
    n_steps = int(grid.background_nlayers / opt.step_size) + 2
    C0 = 1.0 / math.sqrt(4.0 * math.pi)

    invr_last = 0.0
    invr_mid = 0.0

    for i in range(n_steps):
        # Calculate sampling radius
        r = n_steps / (n_steps - i - 0.5)
        
        # Check if radius is valid
        if r < inner_radius:
            continue
            
        # Ray-sphere intersection for sphere centered at origin with radius r
        ox, oy, oz = ray_spec.origin
        dx, dy, dz = ray_spec.dir
        a = dx*dx + dy*dy + dz*dz
        b = 2.0 * (ox*dx + oy*dy + oz*dz)
        c = ox*ox + oy*oy + oz*oz - r*r
        disc = b*b - 4.0*a*c
        if disc < 0.0:
            continue
        sqrt_disc = math.sqrt(disc)
        t = (-b - sqrt_disc) / (2.0 * a)
        if t < 0.0:
            t = (-b + sqrt_disc) / (2.0 * a)
        if t < 0.0:
            continue
            
        # Calculate ray position at intersection
        ray_pos = [ox + t*dx, oy + t*dy, oz + t*dz]
        
        # Normalize position and compute inverse radius
        norm = math.sqrt(sum(v**2 for v in ray_pos))
        invr_mid = 1.0 / norm
        ray_pos = [v * invr_mid for v in ray_pos]
        
        # Calculate depth coordinate (layer index)
        depth_coord = (1.0 - invr_mid) * grid.background_nlayers - 0.5
        ray_pos[2] = max(min(depth_coord, grid.background_nlayers - 1), 0.0)
        
        # Compute integer grid indices
        ray_l = [int(ray_pos[j]) for j in range(3)]
        
        # Clamp indices to valid bounds
        ray_l[0] = max(min(ray_l[0], 2 * grid.background_reso - 1), 0)
        ray_l[1] = max(min(ray_l[1], grid.background_reso - 1), 0)
        ray_l[2] = max(min(ray_l[2], grid.background_nlayers - 2), 0)
        
        # Compute fractional offsets
        ray_frac = [ray_pos[j] - ray_l[j] for j in range(3)]
        
        # Sample density
        sigma = trilinear_interpolate(grid.background_data, ray_l, ray_frac, channel=3)
        
        if sigma > 0.0:
            # Calculate optical depth
            pcnt = (invr_last - invr_mid) * ray_spec.world_step * sigma
            
            # Calculate weight
            weight = math.exp(log_transmit) * (1.0 - math.exp(-pcnt))
            
            # Update log-transmittance
            log_transmit -= pcnt
            
            # Accumulate color
            for i_ch in range(3):
                color = trilinear_interpolate(grid.background_data, ray_l, ray_frac, channel=i_ch)
                # Scale by SH DC factor and add bias
                color_val = color * C0 + 0.5
                # Clamp and accumulate
                outv[i_ch] += weight * max(color_val, 0.0)
        
        # Update inverse radius for next step
        invr_last = invr_mid
        
        # Termination check
        if math.exp(log_transmit) < opt.stop_thresh:
            break
            
    # Final output with ambient term
    for i_ch in range(3):
        out[i_ch] = outv[i_ch] + math.exp(log_transmit) * opt.background_brightness
        
    return log_transmit

def trilinear_interpolate(grid, l, frac, channel):
    """Standard 3D trilinear interpolation over a 4D grid (depth, height, width, channels)."""
    x0, y0, z0 = l
    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
    fx, fy, fz = frac

    def fetch(x, y, z):
        x = max(0, min(x, grid.width - 1))
        y = max(0, min(y, grid.height - 1))
        z = max(0, min(z, grid.depth - 1))
        return grid.data[z, y, x, channel]

    c00 = fetch(x0, y0, z0)
    c10 = fetch(x1, y0, z0)
    c01 = fetch(x0, y1, z0)
    c11 = fetch(x1, y1, z0)
    c00z = fetch(x0, y0, z1)
    c10z = fetch(x1, y0, z1)
    c01z = fetch(x0, y1, z1)
    c11z = fetch(x1, y1, z1)

    ix = c00 * (1 - fx) + c10 * fx
    iy = c01 * (1 - fx) + c11 * fx
    iz0 = ix * (1 - fy) + iy * fy
    ix = c00z * (1 - fx) + c10z * fx
    iy = c01z * (1 - fx) + c11z * fx
    iz1 = ix * (1 - fy) + iy * fy
    return iz0 * (1 - fz) + iz1 * fz
```

## Subtopics

### [Background Rendering Kernel (Forward)](14913-background-rendering-kernel-forward.md)
A CUDA kernel that renders the background color for rays that have transmitted through the volume. It serves as the final compositing stage in the background rendering kernel, accumulating color from the background layers and adding a constant ambient term based on remaining transmission. It differs from standard equirectangular sampling by using concentric spheres to distribute samples, which helps mitigate aliasing and provides a structured traversal of the background layers.

### [Skybox Rendering with Procedural Shading](16291-skybox-rendering-with-procedural-shading.md)
A procedural sky rendered on a back-face culled sphere using a custom shader material, combining horizon/zenith gradients, ground reflection, tiling noise clouds, and a sun disk with glow. It differs from kernel-based forward rendering by computing the background color per-fragment via analytical functions and noise sampling rather than precomputing or accumulating contributions in a separate pass.

## Operating characteristics
*   **Time Complexity:** $O(n\_steps)$ per ray, where $n\_steps$ is proportional to the number of background layers [S4, unofficial].
*   **Memory Complexity:** $O(\text{background\_reso}^2 \times \text{background\_nlayers})$ for the background grid [S4, unofficial].
*   **Performance:** The method is efficient for infinite backgrounds as it avoids explicit skybox geometry intersection [S4, unofficial]. The concentric sphere sampling reduces aliasing compared to uniform angular sampling [S1, unofficial].
*   **Strengths:** Handles infinite distance backgrounds naturally; mitigates aliasing; integrates seamlessly with volume rendering pipelines [S1, unofficial].
*   **When to use:** When rendering scenes with infinite or skybox-like backgrounds that need to be integrated with volumetric effects [S4, unofficial].
*   **When not to use:** For simple static skyboxes where procedural shading is sufficient and more efficient [S1, unofficial].

## Background
Background Rendering using concentric spheres was introduced in the context of voxel-based neural rendering, specifically in the Svox2 framework [S4, unofficial]. It addresses the challenge of rendering infinite backgrounds in a way that is consistent with the volume rendering pipeline. The method has been adopted in various implementations, including Plenoxel [S2, unofficial] and SDFStudio [S1, unofficial], often as part of a larger rendering system that includes volume rendering and mesh extraction. The approach is particularly useful for novel view synthesis and 3D reconstruction tasks where the background needs to be rendered consistently with the foreground geometry [S1, unofficial].
