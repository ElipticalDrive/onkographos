# Spiral Camera Path Generation

Also called: Novel View Synthesis Path, load_tankstemple_data spiral generation

## Overview
Spiral Camera Path Generation creates a sequence of camera poses along a helical trajectory around a scene centroid for novel view synthesis [S1, S3, S4, unofficial]. It solves the problem of generating smooth, continuous fly-through viewpoints that cover the scene volume more comprehensively than static or planar orbits [S3, unofficial]. It differs from [Orbit Camera Path Generation](7811-orbit-camera-path-generation.md) by introducing vertical oscillation (z-axis variation) via a sine wave, creating a 3D spiral rather than a 2D circle [S1, S3, unofficial]. It is a generalization of [Circular Camera Path Generation](2734-circular-camera-path-generation.md), which is the degenerate case where the vertical rate is zero [S1, unofficial].

## How it works
**Inputs:**
- `poses`: Array of training camera poses, shape $(N, 4, 4)$, where each pose is a camera-to-world matrix $c2w$.
- `n_poses` (or `N`): Number of output poses to generate.
- `n_rots` (or `rots`): Number of full rotations ($2\pi$) around the scene.
- `z_rate` (or `zrate`): Vertical oscillation rate.
- `rads` (or `radii`): Radii for the spiral along x, y, z axes. If not provided, computed from input poses.
- `focal`: Focal length. If not provided, computed from input poses.
- `focus_depth`: Depth of the focal plane. If not provided, defaults to 0 or computed.
- `rads_scale`: Scale factor for computed radii. Default 1.0 [S3, unofficial].
- `shift`: Optional centroid shift $(dx, dy, dz)$. Default $(0,0,0)$ [S6, unofficial].
- `pitch_deg`: Optional pitch angle in degrees. Default 0 [S6, unofficial].
- `flip_up_vec`: Boolean to flip the up vector. Default False [S6, unofficial].

**Outputs:**
- `render_poses`: Array of generated camera poses, shape $(n\_poses, 4, 4)$.

**Data Structures:**
- `c2w`: $4 \times 4$ matrix. Columns 0-2 are basis vectors (x, y, z), column 3 is translation (origin). Row 3 is $[0, 0, 0, 1]$.
- `centroid`: 3D vector, mean of all training camera positions.
- `up`: 3D vector, mean of all training camera up vectors (column 1 of $c2w$).

**Steps:**

1. **Compute Scene Statistics:**
   - Calculate `centroid` as the mean of all camera positions:
     $$ \text{centroid} = \frac{1}{N} \sum_{i=0}^{N-1} \text{poses}_i[:3, 3] $$
   - Calculate `up` as the mean of all camera up vectors:
     $$ \text{up} = \frac{1}{N} \sum_{i=0}^{N-1} \text{poses}_i[:3, 1] $$
   - Calculate `focal` if not provided. Sources vary:
     - Mean norm of camera positions: $\text{focal} = \frac{1}{N} \sum_{i=0}^{N-1} \|\text{poses}_i[:3, 3]\|$ [S3, unofficial].
     - Or extracted from intrinsic scaling in $c2w$ [S1, S4, unofficial].
   - Calculate `rads` if not provided:
     - 90th percentile of absolute camera positions along each axis, scaled by `rads_scale` [S3, unofficial].
     - Or `radcircle` = `scale_r` * mean distance from cameras to centroid [S6, unofficial].

2. **Apply Centroid Shift (Optional):**
   - If `shift` is provided:
     $$ \text{centroid} \leftarrow \text{centroid} + \text{shift} $$

3. **Iterate to Generate Poses:**
   - Initialize empty list `render_poses`.
   - For $i$ from 0 to $n\_poses - 1$:
     - Compute normalized time $t = i / n\_poses$.
     - Compute angle $\theta = 2 \pi \cdot n\_rots \cdot t$.
     - Compute vertical offset $z_{offset}$ using sine wave:
       $$ z_{offset} = \sin(2 \pi \cdot n\_rots \cdot t) \cdot \text{height\_range} $$
       *Note: `height_range` is often implicit in `rads[2]` or `z_rate`.*
     - Compute spiral offset vector `c_offset`:
       $$ \text{c\_offset} = [\cos(\theta) \cdot r_x, -\sin(\theta) \cdot r_y, -\sin(\theta \cdot z\_rate) \cdot r_z] $$
       *Note: Signs and scaling may vary by implementation. Some use `rads` directly, others scale by `radcircle` [S1, S4, S6, unofficial].*
     - Compute camera center `c`:
       $$ \mathbf{c} = \text{centroid} + \mathbf{R}_{avg} \cdot \text{c\_offset} $$
       Where $\mathbf{R}_{avg}$ is the rotation part of the average pose `c2w` [S1, S4, unofficial].
       *Alternative: Some implementations compute `c` directly in world space using the spiral formula relative to centroid [S6, unofficial].*
     - Compute viewing direction `z` (forward):
       - Define focal point. Often the origin of the average pose projected along its z-axis, or a fixed depth plane.
       - $$ \mathbf{z} = \text{normalize}(\text{focal\_point} - \mathbf{c}) $$
       - If `pitch_deg` is non-zero, adjust the target y-coordinate:
         $$ \text{target\_y} = \text{radcircle} \cdot \tan(\text{pitch\_deg} \cdot \pi / 180) $$
         And modify the look-at target accordingly [S6, unofficial].
     - Compute camera basis vectors:
       - $$ \mathbf{x} = \text{normalize}(\text{up} \times \mathbf{z}) $$
       - $$ \mathbf{y} = \mathbf{z} \times \mathbf{x} $$
       - *Note: If `flip_up_vec` is True, negate `up` before cross product [S6, unofficial].*
     - Construct pose matrix:
       $$ \text{pose} = [\mathbf{x}, \mathbf{y}, \mathbf{z}, \mathbf{c}] $$
       Shape $(4, 4)$, with row 3 as $[0, 0, 0, 1]$.
     - Append `pose` to `render_poses`.

4. **Return:**
   - Stack `render_poses` into array of shape $(n\_poses, 4, 4)$.

**Pseudocode:**

```python
import numpy as np

def generate_spiral_path(poses, n_poses, n_rots=2, z_rate=0.5, rads=None, focal=None, rads_scale=1.0, shift=(0,0,0), pitch_deg=0):
    """
    Generate a spiral camera path.
    
    Args:
        poses: (N, 4, 4) array of training camera poses.
        n_poses: int, number of poses to generate.
        n_rots: int, number of rotations.
        z_rate: float, vertical oscillation rate.
        rads: (3,) array of radii. If None, computed.
        focal: float, focal length. If None, computed.
        rads_scale: float, scale for computed radii.
        shift: (3,) tuple, centroid shift.
        pitch_deg: float, pitch angle.
        
    Returns:
        render_poses: (n_poses, 4, 4) array.
    """
    # 1. Compute Scene Statistics
    centroid = np.mean(poses[:, :3, 3], axis=0)
    up = np.mean(poses[:, :3, 1], axis=0)
    
    # Apply shift
    centroid = centroid + np.array(shift)
    
    # Compute focal if not provided
    if focal is None:
        focal = np.mean(np.linalg.norm(poses[:, :3, 3], axis=-1))
        
    # Compute rads if not provided
    if rads is None:
        # 90th percentile of absolute camera positions, scaled
        rads = np.percentile(np.abs(poses[:, :3, 3]), 90, axis=0) * rads_scale
        
    # Ensure rads has 3 elements
    if len(rads) < 3:
        rads = np.append(rads, 1.0)
        
    # Average rotation matrix from training poses
    avg_c2w = np.mean(poses, axis=0)
    R_avg = avg_c2w[:3, :3]
    
    render_poses = []
    
    # 3. Iterate to Generate Poses
    for i in range(n_poses):
        t = i / n_poses
        theta = 2 * np.pi * n_rots * t
        
        # Compute spiral offset
        # Note: The sign of sin terms and scaling may vary. 
        # Using the formula from S1/S4: center = [cos(t), -sin(t), -sin(0.5*t)] * radii
        # Here t is theta, and z_rate affects the z-component frequency.
        c_offset_local = np.array([
            np.cos(theta) * rads[0],
            -np.sin(theta) * rads[1],
            -np.sin(theta * z_rate) * rads[2]
        ])
        
        # Transform offset to world space using average rotation
        c_offset_world = R_avg @ c_offset_local
        
        # Camera center
        c = centroid + c_offset_world
        
        # Compute viewing direction z
        # Focal point is often defined relative to the average pose's focal length
        # S1/S4: z = normalize(c - [0,0,-focus_depth]) in local space? 
        # S6: z = normalize(camorigin) then adjust lookat.
        # Standard approach: look at centroid or focal point.
        # Let's use the average pose's focal direction.
        # Focal point in world space: avg_c2w[:3, 3] + avg_c2w[:3, 2] * focal
        focal_point = avg_c2w[:3, 3] + avg_c2w[:3, 2] * focal
        
        # Adjust for pitch
        if pitch_deg != 0:
            # S6: target_y = radcircle * tan(pitch)
            # This modifies the look-at target's y component relative to centroid
            radcircle = np.linalg.norm(c_offset_world[:2]) # Approximation
            target_y = radcircle * np.tan(np.radians(pitch_deg))
            focal_point[1] = centroid[1] + target_y
            
        z = c - focal_point
        z = z / np.linalg.norm(z)
        
        # Compute basis vectors
        # S1/S4: x = normalize(cross(up, z))
        # S6: x = normalize(cross([0,1,0], z)) if up is fixed, or mean up.
        # Using mean up from training data is more robust.
        x = np.cross(up, z)
        x = x / np.linalg.norm(x)
        y = np.cross(z, x)
        
        # Construct pose matrix
        pose = np.eye(4)
        pose[:3, 0] = x
        pose[:3, 1] = y
        pose[:3, 2] = z
        pose[:3, 3] = c
        
        render_poses.append(pose)
        
    return np.array(render_poses)
```

**Edge Cases and Pitfalls:**
- **Precision:** Use float32 or float64 consistently. Small errors in `centroid` or `focal` can cause drift in long spirals.
- **Boundaries:** If `n_rots` is large, ensure `theta` does not overflow.
- **Degenerate Input:** If training poses are collinear or have zero variance, `centroid` and `up` may be undefined. Guard against zero-length vectors in normalization.
- **Focal Length:** Incorrect focal length estimation leads to incorrect viewing directions, causing the spiral to look at the wrong part of the scene.

## Subtopics

### Spiral Camera Pose Generation
A variant that generates poses in a circular path with optional vertical offset, often used in PyTorch3D-based pipelines [S7, unofficial]. It differs from the standard spiral by using `look_at_view_transform` and `PerspectiveCameras` objects, integrating directly with differentiable renderers [S7, unofficial]. It is chosen when using PyTorch3D for differentiable rendering. It computes eye position based on `up` vector orientation and applies pitch via `target_y` [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(n\_poses)$, as each pose is computed in constant time.
- **Memory Complexity:** $O(n\_poses)$ to store the output poses.
- **Performance:** Very fast, typically milliseconds for hundreds of poses.
- **Strengths:** Smooth, continuous path; covers 3D volume; easy to tune with `n_rots` and `z_rate`.
- **Limitations:** Assumes a roughly spherical or ellipsoidal scene distribution; may not fit elongated or planar scenes well without adjustment [S3, S6, unofficial].
- **When to Use:** Novel view synthesis for general 3D scenes, fly-through videos.
- **When Not to Use:** Forward-facing scenes with strict planar constraints (use [Elongated Structure Camera Trajectory Generation](4666-elongated-structure-camera-trajectory-generation.md) or [Orbit Camera Path Generation](7811-orbit-camera-path-generation.md)).

## Background
Originated in the NeRF (Neural Radiance Fields) community for generating novel views from sparse input images [S1, S3, unofficial]. Popularized by the original NeRF implementation [S1, unofficial] and subsequent variants like NeRF-Pl [S2, unofficial] and Tank/Temples dataset loaders [S1, unofficial]. It is widely used in 360° novel view synthesis and video rendering [S3, unofficial].
