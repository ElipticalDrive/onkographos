# Orbit Camera Path Generation

Also called: Camera Orbit Animation, Circular Camera Path, Cyclic rotation rendering, Orbit rendering, Orbiting Render, Rotation Rendering

## Overview
Orbit Camera Path Generation creates a sequence of rendered frames by incrementally rotating the camera around a focal point or specified axis, producing a smooth circular trajectory [S1, S2, unofficial]. It is primarily used for turn-table visualization, video export, and generating training data for 3D reconstruction pipelines [S1, unofficial][S3].

## How it works
This method builds on [Parametric Path Generation](11476-parametric-path-generation.md).

**Inputs:**
*   `center`: 3D vector representing the focal point [G].
*   `num_frames`: Integer $N$, total number of output poses [S1, unofficial].
*   `azimuth_increment`: Degrees to rotate the camera per frame, typically $10^\circ$ [S1, unofficial].
*   `rotate_axis`: Integer 0, 1, or 2 indicating the rotation axis (0=Elevation, 1=Roll, 2=Azimuth) [S2, unofficial].
*   `resolution`: Output image dimensions, typically $[1000, 800]$ [S1, unofficial].

**Outputs:**
*   List of $N$ camera poses or rendered frames [S1, S2, unofficial].

**Data Structures:**
*   Pose $\mathbf{P}$: $4 \times 4$ transformation matrix mapping camera space to world space [G].
    $$
    \mathbf{P} = \begin{bmatrix}
    r_{11} & r_{12} & r_{13} & t_x \\
    r_{21} & r_{22} & r_{23} & t_y \\
    r_{31} & r_{32} & r_{33} & t_z \\
    0 & 0 & 0 & 1
    \end{bmatrix}
    $$
    Where $\mathbf{R}$ is the $3 \times 3$ rotation basis and $\mathbf{t}$ is the translation vector [G].

**Steps:**
1.  **Scene Analysis**: Compute the focal point `center` from scene statistics or user input [G].
2.  **Parameterization**: Define the rotation angles. S1 uses a fixed azimuth increment per frame [S1, unofficial]. S2 uses a list of angles `rotate_angles` and an axis index `rotate_axis` [S2, unofficial].
3.  **Pose Construction**: Assemble $\mathbf{P}$ from the camera's position, view direction, and up vector [G]. The view direction points from the camera position to `center` [G]. The up vector is aligned with the rotation axis or a world up vector [G].
4.  **Sampling**: Evaluate the pose at $N$ evenly spaced intervals. S1 specifies a typical frame count of 36 for a full orbit [S1, unofficial]. Render and save each frame at the specified resolution [S1, unofficial].

**Formulas:**
Camera position on a circular orbit around axis $\mathbf{a}$:
$$
\mathbf{c}(\theta) = \mathbf{center} + \cos(\theta)\mathbf{v}_0 + \sin(\theta)\mathbf{v}_1
$$
where $\mathbf{v}_0$ and $\mathbf{v}_1$ are orthogonal unit vectors in the rotation plane perpendicular to $\mathbf{a}$ [G].
View direction: $\mathbf{z}_{view} = \text{normalize}(\mathbf{center} - \mathbf{c}(\theta))$ [G].
Rotation basis: $\mathbf{x}_{right} = \text{normalize}(\mathbf{u} \times \mathbf{z}_{view})$, $\mathbf{y}_{up} = \mathbf{z}_{view} \times \mathbf{x}_{right}$ [G].

**Parameters:**
*   `Azimuth Increment`: $10^\circ$ per frame [S1, unofficial].
*   `Frame Count`: 36 frames [S1, unofficial].
*   `Resolution`: $[1000, 800]$ [S1, unofficial].

**Edge Cases:**
*   S2 undoes the rotation after each frame (`Azimuth(-angle)`) to prevent cumulative floating-point drift [S2, unofficial].
*   If the rotation axis is parallel to the view direction, the cross product for the right vector becomes zero; a guard must select an alternative up vector [G].

**Pseudocode:**
```python
import numpy as np

def generate_orbit_path(center, num_frames, azimuth_increment_deg=10.0, rotate_axis=2, resolution=(1000, 800)):
    """
    Generates a sequence of camera poses for an orbit path.
    Follows the parent's parameterization and pose construction steps.
    """
    center = np.asarray(center, dtype=float)
    axis = np.array([0.0, 0.0, 0.0])
    axis[rotate_axis] = 1.0
    axis = axis / np.linalg.norm(axis)

    # Initial offset vector perpendicular to axis
    arbitrary = np.array([1.0, 0.0, 0.0])
    if np.abs(np.dot(axis, arbitrary)) > 0.9:
        arbitrary = np.array([0.0, 1.0, 0.0])
    v0 = arbitrary - np.dot(arbitrary, axis) * axis
    v0 = v0 / np.linalg.norm(v0)
    # Radius is not specified in sources; set to 1.0 or compute from scene [G]
    radius = 1.0
    v0 = v0 * radius
    v1 = np.cross(axis, v0)

    poses = []
    delta_theta = np.deg2rad(azimuth_increment_deg)

    for i in range(num_frames):
        theta = i * delta_theta
        camera_pos = center + np.cos(theta) * v0 + np.sin(theta) * v1

        # View direction points to center
        z_view = center - camera_pos
        z_view = z_view / np.linalg.norm(z_view)

        # Up vector alignment with rotation axis
        world_up = axis
        x_right = np.cross(world_up, z_view)
        if np.linalg.norm(x_right) < 1e-6:
            x_right = np.cross(np.array([1.0, 0.0, 0.0]), z_view)
            if np.linalg.norm(x_right) < 1e-6:
                x_right = np.cross(np.array([0.0, 1.0, 0.0]), z_view)
        x_right = x_right / np.linalg.norm(x_right)

        y_up = np.cross(z_view, x_right)

        R = np.column_stack((x_right, y_up, z_view))
        P = np.eye(4)
        P[:3, :3] = R
        P[:3, 3] = camera_pos
        poses.append(P)

    return poses
```

## Subtopics

### IM-3D
A method that finetunes an image-to-video model based on Emu to generate a turn-table like video rotating around an object, which are then taken as input for 3D Gaussian Splatting (3DGS) reconstruction [S3]. Unlike standard geometric path generation, this variant generates the visual content of the orbit frames using a learned model rather than a static scene [S3].

## Operating characteristics
*   **Time Complexity**: $O(N)$, where $N$ is the number of frames [G].
*   **Memory Complexity**: $O(N)$ to store the sequence of poses [G].
*   **Performance**: Rendering time depends on the downstream renderer (e.g., VTK, OpenGL) [G].
*   **Strengths**: Simple to implement; produces smooth, continuous rotation; ideal for objects with rotational symmetry [G].
*   **Limitations**: Cannot capture depth variations in elevation; radius is fixed, so occlusion handling is static [G].
*   **When to use**: Turn-table visualization, generating training data for 3D models [S1, unofficial][S3].
*   **When not to use**: When elevation changes are needed or the path must follow complex scene geometry [G].

## Background
The technique is widely used in scientific visualization and computer graphics for creating animation sequences [G]. It is implemented in tools like ParaView via `paraview.simple` [S1, unofficial] and VTK-based renderers [S2, unofficial]. In the context of modern 3D generation, it serves as a data generation step for 3D Gaussian Splatting pipelines, such as in the IM-3D method [S3].
