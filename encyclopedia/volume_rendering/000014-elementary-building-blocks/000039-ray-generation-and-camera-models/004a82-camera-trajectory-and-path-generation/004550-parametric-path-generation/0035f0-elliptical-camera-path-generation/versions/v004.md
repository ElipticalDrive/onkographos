# Elliptical Camera Path Generation

Also called: Elliptical Camera Path with Y Variation, Elliptical Path Generation, Elliptical Render Path (Y Variation), Elliptical Render Path Generation, elliptical camera trajectory

## Overview
Generates a closed-loop elliptical camera trajectory centered on a focal point derived from input training poses, with optional asymmetric height variation along the vertical axis [S1, S2, S3, unofficial]. It differs from [Orbit Camera Path Generation](7811-orbit-camera-path-generation.md) by allowing independent scaling of the ellipse axes and non-circular vertical oscillation, and from [Spiral Camera Path Generation](1635-spiral-camera-path-generation.md) by maintaining a constant radius (or bounded height range) rather than a continuously expanding or contracting radius [S1, S2, S3, unofficial].

## How it works
**Inputs:**
- `poses`: Array of shape $(N, 4, 4)$ containing $N$ input camera poses in column-major or row-major format (implementation dependent, but typically $4 \times 4$ matrices where the upper $3 \times 3$ is rotation and the last column is translation) [S1, S2, S3, unofficial].
- `n_frames`: Integer, number of output frames [S1, S2, S3, unofficial].
- `z_variation` (or `variation`): Float, amplitude of height variation. Default $0$ [S1, S2, unofficial].
- `z_phase` (or `phase`): Float, phase shift for height variation. Default $0$ [S1, S2, unofficial].
- `const_speed`: Boolean, whether to resample for constant angular velocity. Default `False` [S1, unofficial].

**Outputs:**
- `path`: Array of shape $(n\_frames, 4, 4)$ containing the generated camera poses [S1, S2, S3, unofficial].

**Data Structures:**
- `center`: Vector of shape $(3,)$ representing the focal point [S1, S2, S3, unofficial].
- `offset`: Vector of shape $(3,)$ defining the center of the ellipse bounds [S1, S2, S3, unofficial].
- `sc`: Vector of shape $(3,)$ representing the semi-axis lengths (scaling factors) [S1, S2, S3, unofficial].
- `low`, `high`: Vectors of shape $(3,)$ defining the bounding box of the ellipse [S1, S2, S3, unofficial].
- `z_low`, `z_high`: Scalars or vectors defining the vertical bounds [S1, S2, S3, unofficial].
- `up`: Vector of shape $(3,)$ defining the camera up direction [S1, S2, S3, unofficial].
- `positions`: Array of shape $(n\_frames + 1, 3)$ for intermediate position calculation [S1, S2, S3, unofficial].

**Steps:**

1.  **Scene Analysis**: Compute the focal point `center` using a function `focus_point_fn(poses)`. This function typically calculates the mean or median of the camera positions or the intersection of optical axes [S1, S2, S3, unofficial].
2.  **Offset and Scaling**:
    -   Determine the `offset` vector. For X-Y plane paths, `offset = [center[0], center[1], 0]` [S1, S3, unofficial]. For X-Z plane paths, `offset = [center[0], height, center[2]]` where `height` is a specific Z-coordinate or `center[1]` depending on the variant [S2, unofficial].
    -   Compute scaling factors `sc` using the 90th percentile of the absolute distances of camera positions from `offset`:
        $$ \text{sc} = \text{percentile}(|\text{poses}[:, :3, 3] - \text{offset}|, 90, \text{axis}=0) $$
        [S1, S2, S3, unofficial].
    -   Define ellipse bounds:
        $$ \text{low} = -\text{sc} + \text{offset} $$
        $$ \text{high} = \text{sc} + \text{offset} $$
        [S1, S2, S3, unofficial].
3.  **Vertical Bounds (if variation > 0)**:
    -   Compute `z_low` and `z_high` using the 10th and 90th percentiles of the relevant coordinate (Z for X-Y paths, Y for X-Z paths) of the camera positions [S1, S2, S3, unofficial].
    -   Example for X-Y path:
        $$ \text{z\_low} = \text{percentile}(\text{poses}[:, :3, 3][:, 2], 10, \text{axis}=0) $$
        $$ \text{z\_high} = \text{percentile}(\text{poses}[:, :3, 3][:, 2], 90, \text{axis}=0) $$
        [S1, S2, unofficial].
4.  **Position Parameterization**: Define a function `get_positions(theta)` that returns the 3D position for a given angle $\theta \in [0, 2\pi]$.
    -   For X-Y plane with Z variation [S1, S2, unofficial]:
        $$ x(\theta) = \text{low}[0] + (\text{high}[0] - \text{low}[0]) \cdot \left(\frac{\cos(\theta) + 1}{2}\right) $$
        $$ y(\theta) = \text{low}[1] + (\text{high}[1] - \text{low}[1]) \cdot \left(\frac{\sin(\theta) + 1}{2}\right) $$
        $$ z(\theta) = \text{offset}[2] + \text{variation} \cdot \left( \text{z\_low}[2] + (\text{z\_high}[2] - \text{z\_low}[2]) \cdot \left(\frac{\cos(\theta + 2\pi \cdot \text{phase}) + 1}{2}\right) \right) $$
        [S1, S2, unofficial].
    -   For X-Z plane with Y variation [S2, unofficial]:
        $$ x(\theta) = \text{low}[0] + (\text{high}[0] - \text{low}[0]) \cdot \left(\frac{\cos(\theta) + 1}{2}\right) $$
        $$ y(\theta) = \text{offset}[1] + \text{variation} \cdot \left( \text{y\_low}[1] + (\text{y\_high}[1] - \text{y\_low}[1]) \cdot \left(\frac{\cos(\theta + 2\pi \cdot \text{phase}) + 1}{2}\right) \right) $$
        $$ z(\theta) = \text{low}[2] + (\text{high}[2] - \text{low}[2]) \cdot \left(\frac{\sin(\theta) + 1}{2}\right) $$
        [S2, unofficial].
5.  **Sampling**:
    -   Generate $\theta$ values:
        $$ \theta_i = \frac{2\pi i}{n\_frames}, \quad i = 0, \dots, n\_frames $$
        [S1, S2, S3, unofficial].
    -   Evaluate `get_positions(theta)` for all $\theta_i$ to get `positions` of shape $(n\_frames + 1, 3)$ [S1, S2, S3, unofficial].
    -   Remove the last duplicate point (where $\theta = 2\pi$) to close the loop without redundancy:
        $$ \text{positions} = \text{positions}[0:n\_frames] $$
        [S1, S2, S3, unofficial].
6.  **Constant Speed Resampling (Optional)**: If `const_speed` is true, calculate the arc lengths between consecutive positions and resample $\theta$ to ensure uniform spacing [S1, unofficial].
    -   Calculate lengths:
        $$ \text{lengths}_i = \| \text{positions}_{i+1} - \text{positions}_i \|_2 $$
        [S1, unofficial].
    -   Resample $\theta$ using a step function sampler based on the log of lengths to maintain constant velocity [S1, unofficial].
7.  **Up Vector Determination**:
    -   Compute the average up vector from input poses:
        $$ \text{avg\_up} = \text{mean}(\text{poses}[:, :3, 1], \text{axis}=0) $$
        [S1, S2, S3, unofficial].
    -   Normalize `avg_up` [S1, S2, S3, unofficial].
    -   Find the index `ind_up` of the maximum absolute component of `avg_up` [S1, S2, S3, unofficial].
    -   Set the up vector:
        $$ \text{up} = \mathbf{e}_{\text{ind\_up}} \cdot \text{sign}(\text{avg\_up}[\text{ind\_up}]) $$
        where $\mathbf{e}_{\text{ind\_up}}$ is the basis vector with 1 at `ind_up` and 0 elsewhere [S1, S2, S3, unofficial].
8.  **Pose Construction**:
    -   For each position `p` in `positions`, construct a view matrix. The camera looks from `p` towards `center` [S1, S2, S3, unofficial].
    -   The forward vector is $\mathbf{z} = \text{normalize}(\text{center} - \text{p})$ [S1, S3, unofficial].
    -   The right vector is $\mathbf{x} = \text{normalize}(\text{up} \times \mathbf{z})$ [G].
    -   The new up vector is $\mathbf{y} = \mathbf{z} \times \mathbf{x}$ [G].
    -   Assemble the rotation matrix $\mathbf{R} = [\mathbf{x}, \mathbf{y}, \mathbf{z}]$ (columns) [S1, S3, unofficial].
    -   The translation vector is $\mathbf{t} = -\mathbf{R}^T \mathbf{p}$ [G].
    -   The pose matrix is $\mathbf{P} = [\mathbf{R} | \mathbf{t}]$ [S1, S3, unofficial].
    -   Stack all poses into the output `path` [S1, S2, S3, unofficial].

**Pseudocode:**

```python
import numpy as np

def focus_point_fn(poses):
    """Calculate the focal point (center) of the camera poses.
    Typically the mean of the camera positions."""
    return np.mean(poses[:, :3, 3], axis=0)

def viewmatrix(look_at, up, position):
    """Construct a view matrix from look-at direction, up vector, and position.
    look_at: direction the camera looks towards (from position).
    up: up vector.
    position: camera position.
    Returns a 4x4 matrix."""
    # Normalize inputs
    z = look_at / np.linalg.norm(look_at)
    x = np.cross(up, z)
    x = x / np.linalg.norm(x)
    y = np.cross(z, x)
    
    # Rotation matrix (columns are x, y, z)
    R = np.column_stack((x, y, z))
    
    # Translation: t = -R^T * p
    t = -R.T @ position
    
    # Construct 4x4 matrix
    P = np.eye(4)
    P[:3, :3] = R
    P[:3, 3] = t
    return P

def generate_ellipse_path(poses, n_frames, z_variation=0.0, z_phase=0.0, const_speed=False):
    """Generate an elliptical camera path."""
    
    # 1. Scene Analysis
    center = focus_point_fn(poses)
    
    # 2. Offset and Scaling
    # Determine offset based on plane. Assuming X-Y plane with Z variation as default variant [S1, S3, unofficial]
    # If X-Z plane, offset would be [center[0], height, center[2]] [S2, unofficial]
    offset = np.array([center[0], center[1], 0.0])
    
    # Compute scaling factors using 90th percentile
    sc = np.percentile(np.abs(poses[:, :3, 3] - offset), 90, axis=0)
    
    # Define bounds
    low = -sc + offset
    high = sc + offset
    
    # 3. Vertical Bounds
    z_low = np.percentile(poses[:, :3, 3][:, 2], 10, axis=0)
    z_high = np.percentile(poses[:, :3, 3][:, 2], 90, axis=0)
    
    # 4. Position Parameterization
    def get_positions(theta):
        # X and Y are mapped from [-1, 1] to [0, 1] then to [low, high]
        # cos(theta) * 0.5 + 0.5 maps [-1, 1] to [0, 1]
        x = low[0] + (high[0] - low[0]) * (np.cos(theta) * 0.5 + 0.5)
        y = low[1] + (high[1] - low[1]) * (np.sin(theta) * 0.5 + 0.5)
        
        # Z variation
        if z_variation != 0:
            z = offset[2] + z_variation * (z_low[2] + (z_high[2] - z_low[2]) * (np.cos(theta + 2 * np.pi * z_phase) * 0.5 + 0.5))
        else:
            z = offset[2]
            
        return np.array([x, y, z])
    
    # 5. Sampling
    theta = np.linspace(0, 2 * np.pi, n_frames + 1, endpoint=True)
    positions = np.array([get_positions(t) for t in theta])
    
    # Remove duplicate last point
    positions = positions[:-1]
    
    # 6. Constant Speed Resampling (Optional)
    if const_speed:
        lengths = np.linalg.norm(positions[1:] - positions[:-1], axis=-1)
        # Resample theta to maintain constant velocity
        # This step requires a stepfun.sample implementation or equivalent interpolation
        # For simplicity, we assume a placeholder for resampling logic if not provided
        # In practice, this involves cumulative sum of lengths and inverse interpolation
        pass # Implementation detail omitted as per source [S1, unofficial]
        
    # 7. Up Vector Determination
    avg_up = np.mean(poses[:, :3, 1], axis=0)
    avg_up = avg_up / np.linalg.norm(avg_up)
    
    ind_up = np.argmax(np.abs(avg_up))
    up = np.eye(3)[ind_up] * np.sign(avg_up[ind_up])
    
    # 8. Pose Construction
    path = []
    for p in positions:
        # Camera looks from p towards center
        look_at = center - p
        P = viewmatrix(look_at, up, p)
        path.append(P)
        
    return np.stack(path)
```

**Edge Cases and Pitfalls:**
-   **Degenerate Input**: If all input poses are collinear or identical, `sc` may be zero or `avg_up` may be undefined. Guard against division by zero in normalization [G].
-   **Precision**: Using `np.percentile` with small $N$ can lead to unstable bounds. Ensure $N$ is sufficient [S1, S2, S3, unofficial].
-   **Boundary Conditions**: The mapping from $\theta$ to position uses a shifted cosine/sine, ensuring the path starts and ends at the same point without discontinuity [S1, S2, S3, unofficial].

## Subtopics

### [Spiral Camera Path Generation](1635-spiral-camera-path-generation.md)
Generates a path with a continuously changing radius, suitable for capturing scenes with depth variation. Choose when the scene has significant depth and a circular orbit is insufficient.

### [Orbit Camera Path Generation](7811-orbit-camera-path-generation.md)
Generates a circular path around a center point. Choose when the scene is roughly spherical and a constant radius is appropriate.

## Operating characteristics
-   **Time Complexity**: $O(N + M)$, where $N$ is the number of input poses and $M$ is the number of output frames. The percentile calculation and position generation are linear in their respective inputs [S1, S2, S3, unofficial].
-   **Memory Complexity**: $O(N + M)$ for storing input poses and output path [S1, S2, S3, unofficial].
-   **Strengths**: Simple to implement, provides smooth and symmetric paths, allows for controlled height variation [S1, S2, S3, unofficial].
-   **Limitations**: Assumes the scene is roughly centered and bounded by the input poses. May not capture complex scene geometries well if the input poses are sparse or biased [S1, S2, S3, unofficial].
-   **When to Use**: When a smooth, closed-loop camera path is needed for novel view synthesis or visualization, and the scene is well-contained within the input poses [S1, S2, S3, unofficial].
-   **When Not to Use**: When the scene is very large or unbounded, or when the camera needs to follow a specific non-elliptical trajectory [S1, S2, S3, unofficial].

## Background
The method originates from the NeRF and multi-NeRF literature, specifically implemented in the `multinerf` repository by Google Research [S1, unofficial]. It has been adopted and adapted in various other neural rendering frameworks such as `mrGSplat` and `VolSplat` for generating training or evaluation camera paths [S2, S3, unofficial]. The approach leverages basic statistical properties of input poses to define a robust and adaptive camera trajectory.
