# Random Camera Sampling

Also called: Camera Sampling

## Overview
Random Camera Sampling is a method for selecting a fixed subset of cameras from a predefined viewpoint stack by uniformly sampling indices without replacement. It solves the problem of generating a diverse, non-sequential set of viewing angles for volume rendering or 3D reconstruction tasks where exhaustive sampling is computationally prohibitive. It differs from [Random Pose Selection](8187-random-pose-selection.md) by operating on a discrete, pre-computed list of existing camera poses rather than generating continuous pose parameters, and it differs from [Active Learning Scene Sampling](15489-active-learning-scene-sampling.md) by using a purely stochastic selection criterion rather than optimizing for information gain or rendering time budgets.

## How it works
**Inputs and Outputs:**
- Input: `my_viewpoint_stack`, a list of camera objects representing available viewpoints.
- Input: `num_cams`, an integer specifying the number of cameras to select.
- Output: `camlist`, a list of `num_cams` camera objects selected from the stack.

**Data Structures:**
- `my_viewpoint_stack`: A dynamic list (array) of camera objects. The implementation modifies this list in-place by removing selected elements.
- `camlist`: A dynamic list (array) of camera objects to be returned.

**Parameters:**
- `num_cams`: The fixed number of cameras to sample. The source specifies a typical value of 10 [S1, unofficial].

**Steps:**
1. Initialize an empty list `camlist`.
2. Set a counter or loop limit to `num_cams`.
3. For each iteration from 1 to `num_cams`:
   a. Calculate the valid index range: `0` to `len(my_viewpoint_stack) - 1`.
   b. Generate a random integer `loc` uniformly distributed within this range.
   c. Retrieve the camera at index `loc` from `my_viewpoint_stack`.
   d. Remove the camera at index `loc` from `my_viewpoint_stack` (pop operation).
   e. Append the retrieved camera to `camlist`.
4. Return `camlist`.

**Edge Cases and Pitfalls:**
- If `num_cams` exceeds `len(my_viewpoint_stack)`, the algorithm will fail or return fewer cameras than requested. The source does not specify error handling for this case [S1, unofficial].
- The method assumes `my_viewpoint_stack` is mutable. If the original stack must be preserved, a copy must be made before sampling.
- Random number generation must be uniform to ensure unbiased sampling.

**Pseudocode:**
```python
import random

def random_camera_sampling(my_viewpoint_stack, num_cams):
    """
    Selects num_cams cameras from my_viewpoint_stack by random sampling without replacement.
    
    Args:
        my_viewpoint_stack (list): List of camera objects.
        num_cams (int): Number of cameras to sample.
        
    Returns:
        list: List of selected camera objects.
    """
    camlist = []
    
    # Create a local copy to avoid modifying the original stack if needed,
    # though the source implies in-place modification.
    # [G] Standard practice suggests copying, but source logic pops directly.
    # We follow the source logic: pop from the provided list.
    stack = my_viewpoint_stack
    
    for _ in range(num_cams):
        if not stack:
            break # Stop if stack is empty
        
        # Generate random index
        loc = random.randint(0, len(stack) - 1)
        
        # Pop camera at loc and append to camlist
        camera = stack.pop(loc)
        camlist.append(camera)
        
    return camlist
```

## Operating characteristics
**Time Complexity:** $O(N \cdot K)$ or $O(K)$ depending on implementation, where $N$ is the stack size and $K$ is `num_cams`. The `pop` operation on a list is $O(N)$ in the worst case (shifting elements), making the total complexity $O(K \cdot N)$. If a linked list or swap-and-pop technique were used, it could be $O(K)$. The source does not specify the underlying data structure's pop complexity [S1, unofficial].
**Memory Complexity:** $O(K)$ for the output list. The input stack is modified in-place, so no additional memory for the stack is required beyond the output.
**Strengths:** Simple to implement; ensures no duplicate cameras are selected (sampling without replacement); fast for small `num_cams`.
**Limitations:** Does not guarantee spatial diversity (randomly selected cameras might cluster in one region); performance degrades if `num_cams` is large relative to stack size due to list shifting.
**When to use:** When a quick, unbiased subset of existing viewpoints is needed for training or rendering, and spatial distribution is not critical.
**When not to use:** When spatial coverage is important (use [Random Pose Selection](8187-random-pose-selection.md) or active learning); when the stack is very large and performance is critical (consider swap-and-pop or reservoir sampling).

## Background
The method is documented in the context of Gaussian Splatting implementations, specifically within the FastGS repository. It is used to select a subset of cameras for rendering or training steps. The approach is a standard technique in computer graphics for dataset subsampling.
