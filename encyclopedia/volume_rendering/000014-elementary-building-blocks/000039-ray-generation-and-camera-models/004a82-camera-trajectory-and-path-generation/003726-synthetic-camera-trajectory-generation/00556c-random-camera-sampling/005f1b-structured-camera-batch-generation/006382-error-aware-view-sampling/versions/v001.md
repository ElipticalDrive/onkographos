# Error-aware View Sampling

Also called: error-guided camera refinement

## Overview
Error-aware view sampling is a dynamic camera trajectory generation method that refines camera positions based on the current rendering error, ensuring focused coverage of complex or poorly reconstructed regions. Unlike static structured batches, it adapts to the optimization state by targeting areas of high discrepancy between rendered and reference images.

## How it works
The method operates in two phases: initial global coverage and iterative local refinement.

**Inputs:**
- Reference images (ground truth).
- Current rendered images.
- A set of 3D points (e.g., from a point cloud or mesh).
- Hyperparameters: $K$ (number of points to consider for focal center), $V$ (number of views per step, if applicable), sampling radius for refinement.

**Outputs:**
- A new set of camera poses (position and orientation).

**Data Structures:**
- **Reference Image:** 2D array of pixel values.
- **Rendered Image:** 2D array of pixel values.
- **3D Points:** List of $(x, y, z)$ coordinates.
- **Camera Pose:** Position $\mathbf{c}$ and look-at target $\mathbf{t}$.

**Steps:**

1. **Initial Sampling (Global Coverage):**
   - Sample camera positions on a hulling sphere surrounding the object using Farthest Point Sampling (FPS) to ensure uniform initial distribution [S1].
   - Randomly perturb these sampled positions to break symmetry [S1].
   - Set the camera look-at target to the center of the object (centroid of the 3D points) [S1].
   - Repeat this process periodically during optimization to maintain global coverage [S1].

2. **Error-Aware Refinement (Local Focus):**
   - **Compute Error:** Downsample the reference image and the current rendered image to a manageable resolution. Compute the pixel-wise error (e.g., L2 norm or L1 norm) between the downsampled reference and rendered images [S1].
   - **Identify Max Error:** Find the pixel coordinates $(u_{max}, v_{max})$ with the largest error value [S1].
   - **Back-Project to 3D:** Identify $K$ 3D points whose projection onto the image plane is closest to $(u_{max}, v_{max})$. This requires knowing the current camera projection matrix or ray directions [S1].
   - **Determine Focal Center:** Calculate the mean 3D position $\mathbf{c}_{focus}$ of these $K$ points:
     $$ \mathbf{c}_{focus} = \frac{1}{K} \sum_{i=1}^{K} \mathbf{p}_i $$
     where $\mathbf{p}_i$ are the selected 3D points [S1].
   - **Sample New Poses:** Sample new camera positions on a sphere centered at $\mathbf{c}_{focus}$ with a relatively small radius (distance) [S1].
   - **Set Orientation:** Set the new camera look-at target to $\mathbf{c}_{focus}$ [S1].

**Pseudocode:**

```python
def error_aware_view_sampling(points, ref_img, render_img, K, radius, fps_count):
    # Phase 1: Initial Global Sampling (performed periodically)
    # 1. Sample fps_count positions on a hulling sphere using Farthest Point Sampling
    global_positions = farthest_point_sampling_on_sphere(fps_count)
    
    # 2. Randomly perturb positions
    global_positions += random_perturbation(global_positions)
    
    # 3. Set look-at to object center
    object_center = mean(points)
    global_cameras = [Camera(pos, object_center) for pos in global_positions]
    
    # Phase 2: Error-Aware Refinement (performed every step or frequently)
    # 1. Downsample images
    ref_down = downsample(ref_img, factor=4)
    render_down = downsample(render_img, factor=4)
    
    # 2. Compute pixel-wise error
    error_map = abs(ref_down - render_down)
    
    # 3. Find pixel with largest error
    max_error_pixel = argmax(error_map)
    
    # 4. Find K points closest to this pixel's projection
    # Assuming we have a function to project 3D points to 2D for the current camera
    projected_points = project_points_to_image(points, current_camera)
    distances = compute_distance_to_pixel(projected_points, max_error_pixel)
    k_indices = argsort(distances)[:K]
    k_points = [points[i] for i in k_indices]
    
    # 5. Compute focal center
    focal_center = mean(k_points)
    
    # 6. Sample new camera positions on a sphere around focal center
    local_positions = sample_on_sphere(focal_center, radius, count=V)
    
    # 7. Set look-at to focal center
    local_cameras = [Camera(pos, focal_center) for pos in local_positions]
    
    return global_cameras, local_cameras
```

**Parameters:**
- $K$: Number of points to average for the focal center. Not given in the sources.
- Radius: Distance from the focal center for sampling new cameras. Described as "relatively small" [S1].
- FPS Count: Number of initial global samples. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Downsampling images may smooth out high-frequency errors, leading to suboptimal focal points. The sources do not specify the downsampling factor.
- **Boundaries:** If the object has complex topology, the initial uniform sampling may be insufficient, necessitating the error-aware step [S1].
- **Degenerate Input:** If $K$ points are not available (e.g., too few points), the method fails. Not given in the sources.

## Subtopics

### Mesh-Guided Multi-View Sampling
This variant uses a target mesh and camera poses to sample views. At each training step, $V$ camera views are sampled. All rays hitting the mesh across these views are identified. A random subset of these rays is selected to provide uniform coverage around the object. The rendering error against ground-truth pixels at the ray intersections is minimized to drive optimization (e.g., HKTex optimization) [S2]. This approach is suitable when a mesh is available and the goal is to optimize texture or material properties rather than geometry from scratch.

## Operating characteristics
- **Time Complexity:** The initial FPS sampling is $O(N \log N)$ or $O(N^2)$ depending on implementation, where $N$ is the number of points. The error-aware step involves image downsampling ($O(W \times H)$), error computation ($O(W \times H)$), and finding $K$ closest points ($O(M)$ where $M$ is the number of points). Overall, it is efficient per step but requires rendering at each step to compute error.
- **Memory Complexity:** Requires storing reference and rendered images, and the 3D points. Not given in the sources.
- **Strengths:** Quickly converges on complex shapes by focusing on high-error regions. Improves point positions in small holes during large shape deformation [S1].
- **Limitations:** Requires rendering at each step to compute error, which can be computationally expensive. Performance depends on the quality of the initial sampling.
- **When to use:** When optimizing geometry or texture for complex shapes where uniform sampling is insufficient.
- **When not to use:** When computational resources are limited and rendering is too slow.

## Background
The method was introduced in "Differentiable surface splatting for point-based geometry processing" by [S1]. It addresses the challenge of quick convergence in differentiable rendering for point-based geometry editing. The authors found that simple uniform sampling on a hulling sphere was insufficient for shapes with complex topology, leading to the development of the error-aware refinement strategy.
