# Synthetic Camera Trajectory Generation

Also called: Colmap Dataset Generation, Sobol Camera Sampling

## Overview
Synthetic Camera Trajectory Generation creates a sequence of camera poses for volume rendering or novel view synthesis when real-world capture data is unavailable or insufficient [S1, unofficial]. It solves the problem of defining valid viewing geometries by sampling positions and orientations from a structured distribution, typically using low-discrepancy sequences like Sobol samplers to ensure uniform coverage of the scene volume [S1, unofficial]. It differs from spiral or orbit generation by decoupling position and direction sampling to allow arbitrary spherical coverage, and from random pose selection by providing deterministic, space-filling trajectories rather than stochastic samples [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Volume bounding box (AABB), target number of views ($N_{VIEWS}$), renderer resolution, focal length calculation method [G].
- **Output**: A list of camera poses (position, orientation quaternion, translation) and metadata compatible with standard photogrammetry formats (e.g., COLMAP) [G].

**Data Structures**
1. **Volume AABB**: Represented as a bounding box defining the scene extent [G].
2. **Camera Definition**: A single camera object with a pinhole model [G]. The focal length is computed based on the renderer resolution [G].
3. **Pose List**: A sequence of entries, each containing image metadata, rotation quaternion, and translation vector [G].

**Steps**
1. **Initialize Volume Metadata**: Write the world-space AABB of the volume [S1, unofficial].
2. **Initialize Camera Model**: Write a single camera with a pinhole model [S1, unofficial]. Set the resolution to the renderer's output dimensions [S1, unofficial]. Calculate the focal length [S1, unofficial].
3. **Sample Positions**: For each view index $i$ from $0$ to $N_{VIEWS}-1$, sample a camera position on a sphere centered at the volume center using a Sobol sequence sampler [S1, unofficial].
4. **Sample Directions**: Sample a camera direction towards the center with a small random offset using a Sobol sequence sampler [S1, unofficial].
5. **Compute Orientation**: Construct a rotation matrix or quaternion that aligns the camera's local forward vector with the sampled direction [G].
6. **Store Pose**: Store the image metadata, quaternion, and translation vector for view $i$ [S1, unofficial].

        direction_to_center = direction_to_center / np.linalg.norm(direction_to_center)
        
        raw_offset = sampler_in.next()  # Returns 3D vector in [0, 1]^3
        offset = (raw_offset - 0.5) * 0.1
        final_direction = direction_to_center + offset
        final_direction = final_direction / np.linalg.norm(final_direction)
        
        # Step 5: Compute quaternion
        forward = final_direction
        world_up = np.array([0, 1, 0])
        if np.abs(np.dot(forward, world_up)) > 0.999:
            world_up = np.array([1, 0, 0])
        right = np.cross(forward, world_up)
        right = right / np.linalg.norm(right)
        up = np.cross(right, forward)
        R = np.column_stack((right, up, -forward))
        trace = np.trace(R)
        if trace > 0:
            S = np.sqrt(trace + 1.0) * 2
            w = 0.25 * S
            x = (R[2, 1] - R[1, 2]) / S
            y = (R[0, 2] - R[2, 0]) / S
            z = (R[1, 0] - R[0, 1]) / S
        elif (R[0, 0] > R[1, 1]) and (R[0, 0] > R[2, 2]):
            S = np.sqrt(1.0 + R[0, 0] - R[1, 1] - R[2, 2]) * 2
            w = (R[2, 1] - R[1, 2]) / S
            x = 0.25 * S
            y = (R[0, 1] + R[1, 0]) / S
            z = (R[0, 2] + R[2, 0]) / S
        elif R[1, 1] > R[2, 2]:
            S = np.sqrt(1.0 + R[1, 1] - R[0, 0] - R[2, 2]) * 2
            w = (R[0, 2] - R[2, 0]) / S
            x = (R[0, 1] + R[1, 0]) / S
            y = 0.25 * S
            z = (R[1, 2] + R[2, 1]) / S
        else:
            S = np.sqrt(1.0 + R[2, 2] - R[0, 0] - R[1, 1]) * 2
            w = (R[1, 0] - R[0, 1]) / S
            x = (R[0, 2] + R[2, 0]) / S
            y = (R[1, 2] + R[2, 1]) / S
            z = 0.25 * S
        quat = np.array([w, x, y, z])
        
        # Step 6: Store Pose
        poses.append({
            'id': i,
            'position': position,
            'quaternion': quat,
            'camera_id': 0
        })
    return poses

**Parameters**
- $N_{VIEWS}$: Number of views. Not given in the sources.
- Radius of sampling sphere: Not given in the sources. The source implies "around the volume center" but does not specify the radius relative to the AABB.
- Offset magnitude for direction: Not given in the sources. The source mentions "small random offset" but does not quantify it.

**Edge Cases and Pitfalls**
- **Precision**: Sobol sequence generators must be initialized with the correct dimension and seed to avoid repetition [G]. Ensure the Sobol sampler handles the mapping to the sphere correctly to avoid clustering at poles if using simple normalization of uniform samples [G].
- **Boundaries**: The camera position must be outside the volume AABB to avoid occlusion issues, unless the volume is transparent and the renderer supports interior views. The source does not specify a minimum distance.
- **Degenerate Input**: If the volume center is not well-defined (e.g., empty AABB), the trajectory generation fails [G]. Check for valid AABB bounds before sampling [G].

## Subtopics

### [Random Pose Selection](8187-random-pose-selection.md)
Random Pose Selection generates intermediate camera poses by interpolating between two randomly chosen training poses, ensuring that rendered views remain within the observed regions of the training data. This approach prevents rendering failures on unobserved parts of the scene that occur when attempting to render frames significantly outside the training view coverage. It differs from deterministic trajectory generation by relying on stochastic sampling constrained by proximity thresholds, and from simple linear interpolation by using rotation-aware interpolation for the orientation component. See [Random Pose Selection](8187-random-pose-selection.md).

### Inpainting Trajectory Sampling
Inpainting Trajectory Sampling generates camera positions for inpainting tasks by defining a closed curve on the horizontal plane based on depth values at zero elevation angle from a single panoramic depth map [S2]. It applies 1D Gaussian filtering to smooth the distance values, creating a closed curve $C$ that defines the maximum movement space [S2]. It then progressively samples on shrunk curves $\{C_i\}$ scaled by factors $\{s_i\}$ [S2]. Specifically, it uses 4 shrunk curves with scale factors 0.15, 0.3, 0.45, and 0.6, uniformly sampling 8 positions on each, resulting in 32 total positions [S2].

## Operating characteristics
- **Time Complexity**: $O(N_{VIEWS})$ for sampling and pose generation, assuming constant-time Sobol sampling and quaternion conversion.
- **Memory Complexity**: $O(N_{VIEWS})$ to store the pose list.
- **Performance**: The method is computationally lightweight compared to optimization-based trajectory planning. It relies on fast low-discrepancy sequence generation.
- **Strengths**: Provides uniform coverage of the spherical viewing space. Deterministic and reproducible. Simple to implement.
- **Limitations**: Does not account for scene-specific occlusions or lighting conditions. The fixed radius and offset parameters may not be optimal for all scene scales.
- **When to use**: When generating synthetic datasets for training neural radiance fields or volume renderers where uniform sampling is desired.
- **When not to use**: When specific viewpoints are required (e.g., looking at a specific object) or when the scene geometry is highly irregular and requires adaptive sampling.

## Background
The method originates from the need to generate training data for volume rendering and neural radiance fields when real-world captures are unavailable. The specific implementation using Sobol sequences and COLMAP format is documented in the `volren` repository [S1, unofficial]. The inpainting variant is described in the context of panoramic neural radiance fields from single panoramas [S2].
