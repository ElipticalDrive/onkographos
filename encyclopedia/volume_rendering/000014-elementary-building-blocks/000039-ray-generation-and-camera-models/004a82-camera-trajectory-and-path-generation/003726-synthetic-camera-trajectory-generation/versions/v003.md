# Synthetic Camera Trajectory Generation

Also called: Colmap Dataset Generation, Sobol Camera Sampling

## Overview
Synthetic Camera Trajectory Generation creates a sequence of camera poses for volume rendering or novel view synthesis when real-world capture data is unavailable or insufficient [S1, unofficial]. It solves the problem of defining valid viewing geometries by sampling positions and orientations from a structured distribution, typically using low-discrepancy sequences like Sobol samplers to ensure uniform coverage of the scene volume [S1, unofficial]. It differs from sibling methods by decoupling position and direction sampling to allow arbitrary spherical coverage [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Volume bounding box (AABB), target number of views ($N_{VIEWS}$), renderer resolution, and focal length calculation method [S1, unofficial].
- **Output**: A list of camera poses (position, orientation quaternion, translation) and metadata compatible with standard photogrammetry formats [S1, unofficial].

**Data Structures**
1. **Volume AABB**: Represented as a bounding box defining the scene extent [S1, unofficial].
2. **Camera Definition**: A single camera object with a SIMPLE_PINHOLE model [S1, unofficial]. The focal length is computed based on the renderer resolution [S1, unofficial].
3. **Pose List**: A sequence of entries, each containing image metadata, rotation quaternion, and translation vector [S1, unofficial].

**Steps**
1. **Initialize Volume Metadata**: Write the world-space AABB of the volume as a single Point3D (id=0) with position and RGB values from the AABB bounds [S1, unofficial].
2. **Initialize Camera Model**: Write a single camera (id=0) with model SIMPLE_PINHOLE, using renderer resolution and focal length calculated by `renderer.colmap_focal_length()` [S1, unofficial].
3. **Sample Positions**: For each view $i$ from $0$ to $N_{VIEWS}-1$, sample a camera position on a sphere around the volume center using a Sobol sequence samplerOut [S1, unofficial].
4. **Sample Directions**: Sample a camera direction towards the center with a small random offset using a Sobol sequence samplerIn [S1, unofficial].
5. **Compute Orientation**: Construct a rotation matrix or quaternion that aligns the camera's local forward vector with the sampled direction [G].
6. **Store Pose**: Store the image metadata including quaternion rotation (reordered from [3,0,1,2]) and translation vector for view $i$ [S1, unofficial].

**Pseudocode**
```python
import numpy as np

def generate_synthetic_trajectory(aabb_center, n_views):
    """
    Generates synthetic camera trajectories using Sobol sampling.
    """
    poses = []
    # Standard Sobol sequence generation is used here [G]
    # sampler_out and sampler_in are assumed to be initialized low-discrepancy generators
    
    for i in range(n_views):
        # Step 3: Sample position on sphere around volume center
        raw_pos = sampler_out.next()  # Returns 3D vector in [0, 1]^3
        raw_pos = raw_pos * 2 - 1     # Map to [-1, 1]^3
        norm = np.linalg.norm(raw_pos)
        if norm == 0: norm = 1e-6
        offset_from_center = raw_pos / norm
        # Radius relative to AABB is not specified in the sources [S1, unofficial]
        radius = 1.0 
        position = aabb_center + offset_from_center * radius
        
        # Step 4: Sample direction towards center with small random offset
        direction_to_center = aabb_center - position
        direction_to_center = direction_to_center / np.linalg.norm(direction_to_center)
        
        raw_offset = sampler_in.next()  # Returns 3D vector in [0, 1]^3
        offset = (raw_offset - 0.5) * 0.1
        final_direction = direction_to_center + offset
        final_direction = final_direction / np.linalg.norm(final_direction)
        
        # Step 5: Compute quaternion from direction [G]
        forward = final_direction
        world_up = np.array([0, 1, 0])
        if np.abs(np.dot(forward, world_up)) > 0.999:
            world_up = np.array([1, 0, 0])
        right = np.cross(forward, world_up)
        right = right / np.linalg.norm(right)
        up = np.cross(right, forward)
        R = np.column_stack((right, up, -forward))
        trace = np.trace(R)
        if trace > 0:
            S = np.sqrt(trace + 1.0) * 2
            w = 0.25 * S
            x = (R[2, 1] - R[1, 2]) / S
            y = (R[0, 2] - R[2, 0]) / S
            z = (R[1, 0] - R[0, 1]) / S
        elif (R[0, 0] > R[1, 1]) and (R[0, 0] > R[2, 2]):
            S = np.sqrt(1.0 + R[0, 0] - R[1, 1] - R[2, 2]) * 2
            w = (R[2, 1] - R[1, 2]) / S
            x = 0.25 * S
            y = (R[0, 1] + R[1, 0]) / S
            z = (R[0, 2] + R[2, 0]) / S
        elif R[1, 1] > R[2, 2]:
            S = np.sqrt(1.0 + R[1, 1] - R[0, 0] - R[2, 2]) * 2
            w = (R[0, 2] - R[2, 0]) / S
            x = (R[0, 1] + R[1, 0]) / S
            y = 0.25 * S
            z = (R[1, 2] + R[2, 1]) / S
        else:
            S = np.sqrt(1.0 + R[2, 2] - R[0, 0] - R[1, 1]) * 2
            w = (R[1, 0] - R[0, 1]) / S
            x = (R[0, 2] + R[2, 0]) / S
            y = (R[1, 2] + R[2, 1]) / S
            z = 0.25 * S
        quat = np.array([w, x, y, z])
        
        # Step 6: Store Pose with quaternion reordered from [3,0,1,2] as specified [S1, unofficial]
        reordered_quat = quat[[3, 0, 1, 2]]
        poses.append({
            'id': i,
            'position': position,
            'quaternion': reordered_quat,
            'camera_id': 0
        })
    return poses
```

**Edge Cases and Pitfalls**
- **Precision**: Sobol sequence generators must be initialized with the correct dimension and seed to avoid repetition [G].
- **Boundaries**: The source does not specify a minimum distance from the volume center [S1, unofficial].
- **Degenerate Input**: If the volume center is not well-defined, the trajectory generation fails [G].

## Subtopics

### [Random Pose Selection](8187-random-pose-selection.md)
Random Pose Selection generates intermediate camera poses by interpolating between two randomly chosen training poses, ensuring that rendered views remain within the observed regions of the training data. It differs from nearest camera pose selection by synthesizing new poses that lie between existing training views to guarantee visibility.

### Inpainting Trajectory Sampling
Inpainting Trajectory Sampling generates camera positions for inpainting tasks by defining a closed curve on the horizontal plane based on depth values at zero elevation angle from a single panoramic depth map [S2]. It applies 1D Gaussian filtering to smooth the distance values, creating a closed curve $C$ that defines the maximum movement space [S2]. It then progressively samples on shrunk curves $\{C_i\}$ scaled by factors $\{s_i\}$ [S2]. Specifically, it uses 4 shrunk curves with scale factors 0.15, 0.3, 0.45, and 0.6, uniformly sampling 8 positions on each, resulting in 32 total positions [S2].

## Background
The method originates from the need to generate training data for volume rendering and neural radiance fields when real-world captures are unavailable [S1, unofficial]. The specific implementation using Sobol sequences and COLMAP format is documented in the `volren` repository [S1, unofficial]. The inpainting variant is described in the context of panoramic neural radiance fields from single panoramas [S2].
