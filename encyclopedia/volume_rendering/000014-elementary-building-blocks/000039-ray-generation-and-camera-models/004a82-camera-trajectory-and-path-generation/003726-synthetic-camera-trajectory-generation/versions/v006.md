# Synthetic Camera Trajectory Generation

Also called: Colmap Dataset Generation, Sobol Camera Sampling

## Overview
Synthetic Camera Trajectory Generation creates a structured set of camera poses for volume rendering by sampling positions on a sphere surrounding the scene center [S1, unofficial].

## How it works
**Inputs:**
- Volume bounding box (AABB) defined by minimum and maximum coordinates [G].
- Renderer resolution (width $W$, height $H$) [G].
- Number of views $N_{VIEWS}$ [S1, unofficial].
- Sampling radius $R$ for the sphere [G].
- Focal length calculation function (e.g., based on sensor size or field of view) [S1, unofficial].

**Outputs:**
- A list of camera poses, each containing a position $\mathbf{p}$, orientation (quaternion $\mathbf{q}$), and translation vector $\mathbf{t}$ [G].
- Metadata compatible with COLMAP format (camera model, intrinsic parameters) [G].

**Data Structures:**
1.  **Volume AABB:** Stored as a single `Point3D` (id=0) with position and RGB values representing bounds [S1, unofficial].
2.  **Camera Record:**
    -   `id`: Integer identifier.
    -   `model`: String, e.g., "SIMPLE_PINHOLE".
    -   `width`, `height`: Integer resolution.
    -   `focal_length`: Float.
    -   `qvec`: Quaternion components.
    -   `tvec`: Translation vector.

**Steps:**
1.  **Initialize Volume Metadata:** Write the world-space AABB of the volume as a single `Point3D` (id=0) with position and RGB values derived from the AABB bounds [S1, unofficial].
2.  **Initialize Camera Intrinsics:** Write a single camera definition (id=0) with model `SIMPLE_PINHOLE`. Set resolution to the renderer's output dimensions. Calculate the focal length $f$ using the renderer's focal length function [S1, unofficial].
3.  **Sample Camera Positions (Sphere Sampling):** For each view index $i$ from $0$ to $N_{VIEWS}-1$: use a Sobol sequence sampler (`samplerOut`) to generate a 3D point on the unit sphere, then scale by radius $R$ and translate by the volume center to get the camera position $\mathbf{p}_i$ [S1, unofficial].
4.  **Sample Camera Orientation:** Define the target direction $\mathbf{d}_{target} = \mathbf{c} - \mathbf{p}_i$. Use a Sobol sequence sampler (`samplerIn`) to generate a small random offset vector $\mathbf{o}_i$. Compute the final viewing direction $\mathbf{d}_i = \text{normalize}(\mathbf{d}_{target} + \mathbf{o}_i)$ [S1, unofficial].
5.  **Store Pose Metadata:** Compute the translation vector $\mathbf{t}_i = -\mathbf{R}_i \mathbf{p}_i$, where $\mathbf{R}_i$ is the rotation matrix derived from $\mathbf{q}_i$. Store the quaternion reordered from indices $[3, 0, 1, 2]$ and the translation vector [S1, unofficial].

**Pseudocode:**
```python
import math

class SobolSequence:
    def __init__(self, dim):
        self.dim = dim
        self.count = 0
        self.direction_numbers = [
            [1], [1, 1], [3, 1], [1, 3], [5, 1, 1], [3, 5, 1], [1, 7, 3], [7, 1, 5, 1]
        ]

    def next(self):
        out = []
        for d in range(self.dim):
            val = 0
            bits = self.count
            idx = 0
            while bits > 0:
                if bits & 1:
                    val ^= self.direction_numbers[d][idx]
                bits >>= 1
                idx += 1
            out.append(val / (1 << 32))
        self.count += 1
        return out

def generate_trajectory(n_views, volume_center, volume_bounds, resolution, focal_length_func, radius):
    # 1. Write AABB
    aabb = {'id': 0, 'position': volume_center, 'rgb': volume_bounds}

    # 2. Write camera
    width, height = resolution
    focal_length = focal_length_func(width, height)
    camera = {'id': 0, 'model': 'SIMPLE_PINHOLE', 'width': width, 'height': height, 'focal_length': focal_length}

    poses = []
    sampler_out = SobolSequence(dim=3)
    sampler_in = SobolSequence(dim=3)

    for i in range(n_views):
        # 3. Sample position on sphere
        u = sampler_out.next()
        theta = 2.0 * math.pi * u[0]
        phi = math.acos(2.0 * u[1] - 1.0)
        pos = (
            volume_center[0] + radius * math.sin(phi) * math.cos(theta),
            volume_center[1] + radius * math.sin(phi) * math.sin(theta),
            volume_center[2] + radius * math.cos(phi)
        )

        # 4. Sample orientation
        target_dir = (
            volume_center[0] - pos[0],
            volume_center[1] - pos[1],
            volume_center[2] - pos[2]
        )
        norm = math.sqrt(target_dir[0]**2 + target_dir[1]**2 + target_dir[2]**2)
        target_dir = (target_dir[0]/norm, target_dir[1]/norm, target_dir[2]/norm)

        v = sampler_in.next()
        offset = ((v[0] - 0.5) * 0.1, (v[1] - 0.5) * 0.1, (v[2] - 0.5) * 0.1)
        final_dir = (target_dir[0] + offset[0], target_dir[1] + offset[1], target_dir[2] + offset[2])
        norm_dir = math.sqrt(final_dir[0]**2 + final_dir[1]**2 + final_dir[2]**2)
        final_dir = (final_dir[0]/norm_dir, final_dir[1]/norm_dir, final_dir[2]/norm_dir)

        # Construct rotation matrix aligning local Z with final_dir
        z = final_dir
        up = (0.0, 1.0, 0.0)
        if abs(z[1]) > 0.99:
            up = (1.0, 0.0, 0.0)
        x = (up[1]*z[2] - up[2]*z[1], up[2]*z[0] - up[0]*z[2], up[0]*z[1] - up[1]*z[0])
        x_norm = math.sqrt(x[0]**2 + x[1]**2 + x[2]**2)
        x = (x[0]/x_norm, x[1]/x_norm, x[2]/x_norm)
        y = (z[1]*x[2] - z[2]*x[1], z[2]*x[0] - z[0]*x[2], z[0]*x[1] - z[1]*x[0])

        m00, m01, m02 = x[0], x[1], x[2]
        m10, m11, m12 = y[0], y[1], y[2]
        m20, m21, m22 = z[0], z[1], z[2]

        # Rotation matrix to quaternion [w, x, y, z]
        trace = m00 + m11 + m22
        if trace > 0:
            s = 0.5 / math.sqrt(trace + 1.0)
            q = (0.25/s, (m21-m12)*s, (m02-m20)*s, (m10-m01)*s)
        else:
            if m00 > m11 and m00 > m22:
                s = 2.0 * math.sqrt(1.0 + m00 - m11 - m22)
                q = ((m21-m12)/s, 0.25*s, (m01+m10)/s, (m02+m20)/s)
            elif m11 > m22:
                s = 2.0 * math.sqrt(1.0 + m11 - m00 - m22)
                q = ((m21-m12)/s, (m01+m10)/s, 0.25*s, (m12+m21)/s)
            else:
                s = 2.0 * math.sqrt(1.0 + m22 - m00 - m11)
                q = ((m21-m12)/s, (m02+m20)/s, (m12+m21)/s, 0.25*s)

        # Reorder from [3,0,1,2] -> [w,x,y,z]
        q_reordered = [q[3], q[0], q[1], q[2]]

        # Translation
        t = (-m00*pos[0] - m10*pos[1] - m20*pos[2],
             -m01*pos[0] - m11*pos[1] - m21*pos[2],
             -m02*pos[0] - m12*pos[1] - m22*pos[2])

        poses.append({'id': i, 'position': pos, 'quaternion': q_reordered, 'translation': t})

    return aabb, camera, poses
```

**Parameters:**
-   $N_{VIEWS}$: Number of views. Not given in the sources.
-   Radius: Distance from center. Not given in the sources.
-   Offset Scale: Magnitude of the random orientation offset. Small values (e.g., 0.1 radians) prevent gimbal lock and ensure stable viewing [G].

**Edge Cases:**
-   **Degenerate Up Vector:** If the viewing direction is parallel to the up vector, the cross product for the X-axis becomes zero. A fallback up vector must be selected [G].
-   **Sobol Sequence Dimension:** Sobol sequences are sensitive to dimension. Ensure the sampler is initialized with the correct dimension (3 for position, 3 for offset) [G].
-   **Quaternion Ordering:** COLMAP uses $[w, x, y, z]$. Many libraries return $[x, y, z, w]$. The source specifies reordering from $[3, 0, 1, 2]$ to map internal layouts to the target format [S1, unofficial].

## Subtopics

### Inpainting Trajectory Sampling
Inpainting Trajectory Sampling generates camera poses for RGBD inpainting by defining a closed curve on the horizontal plane based on depth values at zero elevation angle from a single panoramic depth map [S2]. It differs from standard spherical sampling by constraining the camera to a 2D curve that adapts to the scene's geometry, ensuring the camera stays within observable regions [S2].
-   **Definition:** Samples camera positions on shrunk curves derived from a smoothed depth-based curve [S2].
-   **Steps:**
    1.  Extract distance values of all pixels at zero elevation angle from the panoramic depth map [S2].
    2.  Apply 1D Gaussian filtering to these distances to obtain a smoothed closed curve $C$ [S2].
    3.  Define shrunk curves $\{C_i\}$ scaled by factors $\{s_i\}$ relative to $C$ [S2].
    4.  Uniformly sample 8 camera positions on each shrunk curve [S2].
-   **Parameters:**
    -   Number of shrunk curves: 4 [S2].
    -   Scale factors $\{s_i\}$: 0.15, 0.3, 0.45, 0.6 [S2].
    -   Positions per curve: 8 [S2].
    -   Total positions: 32 [S2].

### [Random Pose Selection](8187-random-pose-selection.md)
Random Pose Selection generates intermediate camera poses by interpolating between two randomly chosen training poses to ensure rendering occurs within observed regions, avoiding failures on unobserved parts of the scene. It differs from [Nearest Camera Pose Selection](12726-nearest-camera-pose-selection.md), which explicitly ranks existing training data by geometric proximity to a query pose, by instead synthesizing new poses that lie between existing training views to guarantee visibility.

### [Random Camera Sampling](15470-random-camera-sampling.md)
Random Camera Sampling selects a fixed number of cameras from a predefined viewpoint stack by uniformly sampling indices without replacement. It solves the problem of generating a diverse set of training views for 3D reconstruction or novel view synthesis when a limited pool of existing captures is available. It differs from its sibling [Random Pose Selection](8187-random-pose-selection.md) by drawing exclusively from a discrete, existing list of poses rather than generating continuous pose parameters from a distribution.

## Operating characteristics
-   **Time Complexity:** $O(N_{VIEWS})$ for generating poses, assuming constant-time Sobol sequence generation [G].
-   **Memory Complexity:** $O(N_{VIEWS})$ to store the pose list [G].
-   **Strengths:** Uniform coverage of the viewing sphere; deterministic and reproducible; simple to implement [G].
-   **Limitations:** Assumes a central volume; not suitable for scenes with significant depth variation where a fixed radius is inappropriate; does not account for occlusions or visibility constraints [G].
-   **When to Use:** When a uniform set of views around a central object is required for volume rendering or NeRF training [G].
-   **When Not to Use:** For scenes with large depth variations, indoor environments with complex geometry, or when specific viewpoints are required [S2].

## Background
Synthetic Camera Trajectory Generation using Sobol sequences for volume rendering was described in the context of the `volren` project [S1, unofficial]. The method leverages low-discrepancy sequences to ensure efficient sampling of the camera sphere.
