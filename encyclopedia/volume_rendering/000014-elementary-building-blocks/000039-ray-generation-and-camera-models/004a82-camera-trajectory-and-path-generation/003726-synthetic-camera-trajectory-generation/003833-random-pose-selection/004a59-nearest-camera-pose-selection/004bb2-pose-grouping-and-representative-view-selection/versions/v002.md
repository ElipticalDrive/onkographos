# Pose Grouping and Representative View Selection

Also called: AABB Expansion, Block Splitting, Clustering-based View Selection, KMeans Block Splitting, Representative View Selection

## Overview
Pose Grouping and Representative View Selection is a method to select representative viewpoints from rendered images for subsequent training rounds by clustering camera poses and selecting the sharpest image within each cluster [S1]. It also serves as a strategy to divide training images into overlapping blocks using KMeans clustering on camera centers and expanding bounding boxes to enable distributed or scalable training [S2, unofficial]. It differs from its parent [Nearest Camera Pose Selection](12726-nearest-camera-pose-selection.md) by grouping multiple views into clusters or blocks rather than selecting a single nearest neighbor, and it differs from [K-Means Spatial Partitioning for Camera Clustering](16768-k-means-spatial-partitioning-for-camera-clustering.md) by explicitly selecting representative views based on image quality metrics (Laplacian variance) rather than just partitioning the dataset for parallel training [S1][S2, unofficial].

## How it works
**Inputs:**
- Set of $N$ camera poses $P = \{P_1, \dots, P_N\}$, where each $P_i$ consists of rotation matrix $R_i$ and translation vector $t_i$ [S1][S2, unofficial].
- Rendered images $I$ corresponding to each pose (for representative selection) [S1].
- Number of clusters/blocks $K$ [S1][S2, unofficial].
- Scale factor vector $s_{AABB} = [s_x, s_y, s_z]^T$ for bounding box expansion [S2, unofficial].

**Outputs:**
- A set of representative viewpoints (one per cluster) [S1].
- Or, a set of intersected blocks $B = \{B_k\}$ containing images [S2, unofficial].

**Data Structures:**
- Camera Center $c_n = -R_n^T t_n$ [S1].
- Forward Direction $z_n = R_n^T [0,0,1]^T$ [S1].
- 6D Feature Vector $v_n = [c_n, z_n]$ [S1].
- Axis-Aligned Bounding Box (AABB) defined by min corner $A$ and max corner $B$ [S2, unofficial].

**Steps:**

1. **Extract Geometric Features:**
   For each camera pose $P_n$ with extrinsics $(R_n, t_n)$:
   - Compute camera center: $c_n = -R_n^T t_n$ [S1].
   - Compute forward direction: $z_n = R_n^T [0,0,1]^T$ [S1].
   - Form 6D feature vector: $v_n = [c_n, z_n]$ [S1].

2. **Initial Clustering (K-Means):**
   Perform K-Means clustering on the feature vectors (or camera centers $t_i$) to assign each image to an initial block/cluster $k \in [1, K]$ [S1][S2, unofficial].
   - Input: $\{v_n\}$ or $\{t_i\}$ [S1][S2, unofficial].
   - Output: Cluster assignment $L_i$ for each image $i$ [S2, unofficial].
   - Note: [S1] fixes $K=12$ for representative selection; [S2, unofficial] uses $K$ as a parameter [S2, unofficial].

3. **Bounding Box Computation (AABB):**
   For each cluster $k$:
   - Let $P_k$ be the set of camera poses in cluster $k$ [S2, unofficial].
   - Compute the axis-aligned bounding box: $AABB_k = [A_k, B_k] = [\min(P_k), \max(P_k)]$ [S2, unofficial].
   - Compute diagonal midpoint: $C_k = (A_k + B_k) / 2$ [S2, unofficial].
   - Compute diagonal direction: $r_k = (A_k - B_k) / \|A_k - B_k\|$ [S2, unofficial].
   - Compute half-length of diagonal: $len_k = \|A_k - B_k\| / 2$ [S2, unofficial].

4. **AABB Expansion:**
   Recompute the expanded bounds $A'_k$ and $B'_k$ using the scale factor $s_{AABB}$ [S2, unofficial]:
   $$ A'_k = C_k + s_{AABB} \cdot r_k \cdot len_k $$
   $$ B'_k = C_k - s_{AABB} \cdot r_k \cdot len_k $$
   - If $s_{AABB} = 1.0$, there is no overlap [S2, unofficial].
   - If $s_{AABB} > 1.0$, blocks overlap [S2, unofficial].

5. **Regrouping (Optional, for Block Splitting):**
   For each image $i$ with pose $P_i$:
   - If $P_i$ lies within the expanded bounds $[A'_k, B'_k]$ for any block $k$, add image $i$ to block $B_k$ [S2, unofficial].
   - This creates intersecting blocks [S2, unofficial].

6. **Representative View Selection (For Representative Selection):**
   For each cluster $k$:
   - Calculate the Laplacian variance for each image $I_i$ in the cluster:
     $$ Var_{Lap}(I_i) = Var(\nabla^2 I_i) $$
     where $\nabla^2 I_i$ is the Laplacian gradient of image $I_i$ [S1].
   - Select the image with the highest $Var_{Lap}(I_i)$ as the representative viewpoint for cluster $k$ [S1].

**Parameters:**
- $K$: Number of clusters/blocks. Default $K=12$ in [S1] [S1].
- $s_{AABB}$: Scale factor vector $[s_x, s_y, s_z]^T$. Default $s_x=s_y=s_z$ [S2, unofficial]. Controls overlap ratio [S2, unofficial].

**Edge Cases and Pitfalls:**
- Texture-less regions: SfM-based splitting may fail here, but this method uses camera pose priors, avoiding such issues [S2, unofficial].
- Overlap management: If $s_{AABB}$ is too large, blocks may encompass all training images; if too small, no overlap exists [S2, unofficial].
- Blurriness in blending: If using Inverse Distance Weighting (IDW) to blend images from intersected blocks, blurriness may occur if blocks are close [S2, unofficial].

## Subtopics

### [K-Means Spatial Partitioning for Camera Clustering](16768-k-means-spatial-partitioning-for-camera-clustering.md)
A data-driven spatial decomposition strategy that uses K-Means clustering on 3D camera center positions to partition large-scale scenes into sub-scenes for parallel training. It adapts to the actual distribution of viewpoints rather than using heuristic grids. Unlike [Pose Grouping and Representative View Selection](13042-pose-grouping-and-representative-view-selection.md), which selects representative views for training rounds, this method partitions the dataset itself to enable multi-block rendering.

## Operating characteristics
- **Time Complexity:** K-Means clustering is generally $O(N \cdot K \cdot D \cdot I)$, where $N$ is the number of views, $K$ is the number of clusters, $D$ is the dimensionality (6 or 3), and $I$ is the number of iterations [S1][S2, unofficial]. Laplacian variance calculation is $O(M)$ per image, where $M$ is the number of pixels [S1].
- **Memory Complexity:** Requires storing camera poses, feature vectors, and images [S1][S2, unofficial].
- **Strengths:** Does not require manually setting distance thresholds [S1]. Leverages known camera pose priors, avoiding issues in texture-less regions common in SfM-based splitting [S2, unofficial]. Ensures geometric consistency within clusters [S1].
- **Limitations:** Requires rendered images for Laplacian variance calculation (for representative selection) [S1]. Overlap management requires tuning $s_{AABB}$ [S2, unofficial].
- **When to use:** When a structured selection of viewpoints is needed for fine-grained denoising or reconstruction [S1]. When scalable training of large scenes is required with overlapping blocks [S2, unofficial].

## Background
Originated in the context of 3D Gaussian Splatting and NeRF training. [S1] introduced Pose Grouping and Representative View Selection for denoising sparse-view 3D Gaussian Splatting, selecting representative viewpoints for a second training round to ensure geometric coverage and noise characteristics [S1]. [S2, unofficial] introduced Block Splitting (AABB Expansion) for scalable NeRF training, using KMeans on camera centers and AABB expansion to create overlapping blocks for distributed training [S2, unofficial].
