# Nearest Camera Pose Selection

Also called: Pose Selection by Distance

## Overview
Nearest Camera Pose Selection identifies the most relevant training images for a novel view by finding camera poses with minimal positional and angular distance [S1]. It addresses the problem of selecting appropriate context for feature reprojection or rendering enhancement by ensuring the selected neighbors share significant image content overlap with the target view [S1]. It differs from [Pose Grouping and Representative View Selection](13042-pose-grouping-and-representative-view-selection.md) by selecting the closest subset based on minimal distance rather than partitioning the dataset into clusters to ensure geometric coverage [S1].

## How it works
**Inputs:**
- A novel camera pose $C_k$, defined by a rotation matrix $R_k$ and a translation vector $\bm{t}_k$ [S1].
- A set of $M$ training camera poses $\{C_j\}_{j=1}^M$, where each $C_j$ consists of rotation matrix $R_j$ and translation vector $\bm{t}_j$ [S1].

**Outputs:**
- A subset of $n$ training poses $\{C_i\}_{i=1}^n$ considered the closest neighbors to $C_k$ [S1].

**Data Structures:**
- Camera Pose: A tuple or object containing $R \in \mathbb{R}^{3 \times 3}$ and $\bm{t} \in \mathbb{R}^3$ [S1].
- Distance Metrics: Scalar values computed per training pose [G].

**Formulas:**
1.  **Angular Distance:**
    $$dist^{i}_{ang}(R_{k}, R_{i}) = \frac {1}{3} \lvert \pi (R_{k}) - \pi (R_{i}) \rvert _{1}$$
    where $\pi(R_i)$ returns the three Euler angles of the rotation matrix $R_i$, and $\lvert \cdot \rvert_1$ is the L1 norm (sum of absolute differences) [S1].

2.  **Positional Distance:**
    $$dist^{i}_{pos}(\bm {t}_{k}, \bm {t}_{i}) = \frac {1}{3} \lvert \bm {t}_{k} - \bm {t}_{i} \rvert _{1}$$
    where $\bm{t}_k$ and $\bm{t}_i$ are the translation vectors of the novel and training cameras, respectively [S1].

3.  **Selection Logic:**
    Empirically, positional distance is the strongest indicator for image content overlap, followed by angular distance [S1].
    -   First, select the 5 poses $\{C_p\}_{p=1}^5$ with the smallest positional distances:
        $$\{C_{p}\}_{p=1}^{5} = \{C_{j}\} \mid \ j \in \text{min}_{5}\{dist^{j}_{pos}(\bm {t}_{k}, \{\bm {t}_j\}_{j=1}^M)\}$$
    -   Second, from these 5 candidates, select the $n$ poses $\{C_i\}_{i=1}^n$ with the smallest angular distances:
        $$\{C_{i}\}_{i=1}^{n} = \{C_{p}\} \mid \ p \in \text{min}_{n}\{dist^{p}_{ang}(R_{k},\{R_p\}_{p=1}^5)\}$$

**Parameters:**
-   Number of initial positional candidates: 5 (used for LLFF and 360v2 datasets) [S1].
-   Number of final angular neighbors $n$: 2 (used for DTU dataset) [S1].

**Pseudocode:**
```python
import numpy as np

def euler_angles_from_rotation_matrix(R):
    """Extracts ZYX Euler angles from a 3x3 rotation matrix [G]."""
    sy = np.sqrt(R[0, 0]**2 + R[1, 0]**2)
    if sy > 1e-6:
        x = np.arctan2(R[2, 1], R[2, 2])
        y = np.arctan2(-R[2, 0], sy)
        z = np.arctan2(R[1, 0], R[0, 0])
    else:
        x = np.arctan2(-R[1, 2], R[1, 1])
        y = np.arctan2(-R[2, 0], sy)
        z = 0
    return np.array([x, y, z])

def nearest_camera_pose_selection(novel_pose, training_poses, k_pos=5, n_ang=2):
    """Selects the nearest training camera poses to a novel view [S1]."""
    R_k, t_k = novel_pose
    pi_R_k = euler_angles_from_rotation_matrix(R_k)
    
    # Step 1: Compute positional distances for all M training poses
    pos_distances = []
    for i, (R_j, t_j) in enumerate(training_poses):
        dist_pos = np.sum(np.abs(t_k - t_j)) / 3.0
        pos_distances.append((dist_pos, i))
        
    # Sort by positional distance and pick top k_pos candidates
    pos_distances.sort(key=lambda x: x[0])
    top_k_indices = [idx for _, idx in pos_distances[:k_pos]]
    
    # Step 2: Compute angular distances for the top k_pos candidates
    ang_distances = []
    for idx in top_k_indices:
        R_j, t_j = training_poses[idx]
        pi_R_j = euler_angles_from_rotation_matrix(R_j)
        dist_ang = np.sum(np.abs(pi_R_k - pi_R_j)) / 3.0
        ang_distances.append((dist_ang, idx))
        
    # Sort by angular distance and pick top n_ang final neighbors
    ang_distances.sort(key=lambda x: x[0])
    final_indices = [idx for _, idx in ang_distances[:n_ang]]
    
    return [training_poses[idx] for idx in final_indices]
```

## Subtopics

### [Pose Grouping and Representative View Selection](13042-pose-grouping-and-representative-view-selection.md)
Selects a subset of representative training viewpoints by clustering camera poses and filtering for image quality. It partitions the dataset to ensure geometric coverage, whereas Nearest Camera Pose Selection selects the closest subset based on minimal distance.

### Nearest Neighbor Pose Selection
A variant that distributes scene representation factors across 3D space using camera pose priors [S2]. It uses Farthest Point Sampling (FPS) to select $L$ positions for basis factors from input cameras, and K-means to select $C$ positions for core factors, sharing the core factor across basis factors ($C \ll L$) [S2]. For rendering, it selects the $\hat{C}$ nearest core factors and $\hat{L}$ basis factors based on the distance between the probe position and the target camera position [S2]. Parameters vary by scene scale: $L \in \{64, 100, 256\}$ and $C \in \{3, 5, 16\}$ for small, medium, and large scenes respectively [S2]. The number of neighboring basis factors $\hat{L}$ is fixed at 16, while $\hat{C}$ is 3 for centralized camera trajectories (mip-NeRF360, 56Leonard) and 2 for others [S2].

## Background
The method is used in RoGUENeRF, a geometry-consistent universal enhancer for NeRF, to leverage relevant information from neighboring training images for feature reprojection and enhancement [S1]. It was evaluated on the LLFF, 360v2, and DTU datasets [S1].
