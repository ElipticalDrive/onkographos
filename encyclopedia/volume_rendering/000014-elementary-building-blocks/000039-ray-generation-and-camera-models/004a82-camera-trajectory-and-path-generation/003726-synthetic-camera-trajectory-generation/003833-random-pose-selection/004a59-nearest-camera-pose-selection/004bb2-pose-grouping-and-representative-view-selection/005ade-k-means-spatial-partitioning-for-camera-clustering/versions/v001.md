# K-Means Spatial Partitioning for Camera Clustering
Also called: Camera Center Clustering, Initial spatial partitioning, K-Means Spatial Partitioning

## Overview
A data-driven spatial decomposition strategy that uses K-Means clustering on 3D camera center positions to partition large-scale scenes into sub-scenes for parallel training [S1]. It adapts to the actual distribution of viewpoints rather than using heuristic grids [S1]. Unlike [Pose Grouping and Representative View Selection](13042-pose-grouping-and-representative-view-selection.md), which selects representative views for training rounds, this method partitions the dataset itself to enable multi-block rendering [S1].

## How it works
**Inputs:** Intrinsic and extrinsic camera parameters, and a sparse point cloud [S1].
**Outputs:** A set of camera clusters, where each cluster contains a subset of cameras and their corresponding images/parameters [S1].

**Data Structures:**
*   **Camera Positions:** A list of 3D vectors $X \in \mathbb{R}^3$ representing the optical centers of all input cameras.
*   **Centroids:** A list of $K$ 3D vectors $O_i \in \mathbb{R}^3$ representing the center of each cluster.
*   **Clusters:** A list of $K$ sets $C_i$, where each $C_i$ contains the indices or objects of cameras assigned to cluster $i$.

**Parameters:**
*   $K$: The number of clusters. Determined by available GPU memory during training [S1].
*   $\sigma$: Expansion threshold for sub-scene extension [S1].
*   $\text{MaxNum}$: Initial maximum number of cameras per cluster (typically 80% of hardware limit) [S1].
*   $\text{TopNum}$: Hard upper bound on cluster size after expansion (typically 10% higher than $\text{MaxNum}$) [S1].
*   $\epsilon$: Preset threshold for convergence of error change [S1].
*   $I_{max}$: Maximum number of iterations [S1].

**Steps:**

1.  **Initialization:** Choose $K$ camera positions from the input set as the initial centroids $(\mathbf{O_1}, \mathbf{O_2}, ..., \mathbf{O_K})$ [S1]. Let the initial clustering be denoted as $(\mathbf{C_1}, \mathbf{C_2}, ..., \mathbf{C_K})$ [S1].
2.  **Assignment:** For each camera position $X$, assign it to the cluster $C_i$ whose centroid $O_i$ is closest.
3.  **Update:** Recalculate the centroid for each cluster $i$ as the mean of all positions $X$ in $C_i$:
    $$O_j = \frac{1}{|C_j|} \sum_{X \in C_j} X$$
    [S1]
4.  **Convergence Check:** Calculate the total within-cluster squared error $E$:
    $$E = \sum_{i=1}^{K} \sum_{X \in C_i} ||X - O_i||^2_2$$
    [S1]
    Repeat steps 2–3 until the change in error $E$ falls below a preset threshold $\epsilon$ or the maximum number of iterations $I_{max}$ is reached [S1].

**Sub-scene Extension (Post-processing):**
To ensure sufficient overlap between neighboring sub-scenes for robust image registration, the initial clusters are expanded [S1].
1.  For each cluster $i$, calculate the maximum intra-cluster radius $R_i$ (distance from centroid $O_i$ to the furthest camera in $C_i$) [S1].
2.  Define an expanded radius $R'_i = R_i \times (1 + \sigma)$ [S1].
3.  Identify all cameras not currently in $C_i$ that lie within distance $R'_i$ from $O_i$ [S1].
4.  Add these nearby cameras to $C_i$ [S1].
5.  Enforce the hard upper bound: if $|C_i| > \text{TopNum}$, cap the cluster size to $\text{TopNum}$ cameras [S1].
6.  Repeat for all initial clusters [S1].

**Pseudocode:**

    for iteration in range(max_iter):

        for idx, pos in enumerate(camera_positions):
            # Find closest centroid
            min_dist = float('inf')
            closest_cluster = -1
            for c_idx, centroid in enumerate(centroids):
                dist = sum((p - c)**2 for p, c in zip(pos, centroid))
                if dist < min_dist:
                    min_dist = dist
                    closest_cluster = c_idx
            clusters[closest_cluster].append(idx)
            
        # Step 3: Update
        for c_idx in range(K):
            if not clusters[c_idx]:
                continue # [G] Handle empty cluster by reinitializing to a random point
            cluster_points = [camera_positions[i] for i in clusters[c_idx]]
            centroids[c_idx] = [sum(p) / len(cluster_points) for p in zip(*cluster_points)]
            
        # Step 4: Convergence Check
        error = 0.0
        for c_idx, cluster_indices in enumerate(clusters):
            centroid = centroids[c_idx]
            for idx in cluster_indices:
                pos = camera_positions[idx]
                dist_sq = sum((p - c)**2 for p, c in zip(pos, centroid))
                error += dist_sq
                
        if abs(prev_error - error) < epsilon:
            break
        prev_error = error
        
    return clusters

    for c_idx in range(len(clusters)):

        cluster_indices = clusters[c_idx]
        
        # Calculate max intra-cluster radius
        max_radius_sq = 0.0
        for idx in cluster_indices:
            pos = camera_positions[idx]
            dist_sq = sum((p - c)**2 for p, c in zip(pos, centroid))
            if dist_sq > max_radius_sq:
                max_radius_sq = dist_sq
        max_radius = max_radius_sq ** 0.5
        
        # Expanded radius
        expanded_radius = max_radius * (1 + sigma)
        expanded_radius_sq = expanded_radius ** 2
        
        # Find nearby cameras
        nearby_indices = []
        for i in range(n_cameras):
            if i in cluster_indices:
                continue
            pos = camera_positions[i]
            dist_sq = sum((p - c)**2 for p, c in zip(pos, centroid))
            if dist_sq <= expanded_radius_sq:
                nearby_indices.append(i)
                
        # Add nearby cameras
        current_count = len(cluster_indices)
        available_slots = top_num - current_count

## Subtopics

### Sub-scene Extension
A post-processing step applied to initial K-Means clusters to ensure sufficient overlap between neighboring sub-scenes for robust image registration and multi-block rendering, by expanding cluster radii and adding nearby cameras [S1]. It is chosen when the initial clustering does not guarantee sufficient camera overlap, which could cause image registration failure when combining rendered outputs [S1]. The expansion uses a threshold $\sigma$ to guide augmentation [S1]. A key pitfall is that cluster expansion may cause the number of cameras to exceed the initial MaxNum limit, risking GPU memory overflow; this is handled by enforcing a hard upper bound TopNum on the cluster size after expansion [S1]. The method typically sets MaxNum to 80% of the hardware limit and expands by 10% to reserve a 10% safety margin [S1].

## Operating characteristics
*   **Time Complexity:** K-Means is generally $O(I \cdot N \cdot K \cdot D)$ where $I$ is iterations, $N$ is cameras, $K$ is clusters, $D$ is dimension (3) [S1]. Sub-scene extension is $O(K \cdot N)$ for radius calculation and neighbor search [S1].
*   **Memory Complexity:** Stores camera positions, centroids, and cluster assignments. The expansion step may temporarily increase memory usage if not capped [S1].
*   **Performance:** Enables parallel training of large-scale scenes by decomposing them into sub-scenes [S1].
*   **Strengths:** Adapts to actual spatial distribution of viewpoints; principled solution for large-scale 3D reconstruction; ensures overlap for better registration [S1].
*   **Limitations:** Requires careful tuning of $K$, $\sigma$, and memory bounds to avoid GPU overflow [S1].
*   **When to use:** Large-scale scene reconstruction from aerial imagery where heuristic grids are insufficient [S1].
*   **When not to use:** Small scenes where a single block fits in memory; scenes with highly non-uniform camera distribution where $K$ is hard to determine [S1].

## Background
Originated in the BirdNeRF paper, which introduced the use of K-Means clustering for initial spatial partitioning in 3D reconstruction tasks for the first time [S1]. It is used in fast neural reconstruction of large-scale scenes from aerial imagery [S1].
