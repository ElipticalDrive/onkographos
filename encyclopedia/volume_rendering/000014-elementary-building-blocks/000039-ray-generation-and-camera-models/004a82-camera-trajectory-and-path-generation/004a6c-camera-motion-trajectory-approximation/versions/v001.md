# Camera Motion Trajectory Approximation
Also called: Lie Algebra SE(3) Interpolation, SE(3) Camera Trajectory Approximation

## Overview
This method approximates the continuous camera trajectory during a finite shutter exposure time by interpolating between known discrete poses within the Lie algebra of the special Euclidean group SE(3) [S1]. It solves the problem of modeling motion blur in differentiable rendering by providing a smooth, differentiable parameterization of camera motion that respects the non-commutative nature of 3D rigid body transformations [S1]. It distinguishes itself from linear interpolation in Euclidean space by ensuring the interpolated poses remain valid rigid transformations, and from B-spline methods by offering explicit control over the interpolation order via Bézier curves [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** Start pose $T_0 \in SE(3)$, end pose $T_1 \in SE(3)$, shutter duration $\tau$, and current time $t \in [0, \tau]$. For higher-order methods, additional control points $T_j$ and interpolation order $K$ are required.
*   **Outputs:** Interpolated camera pose $T_t \in SE(3)$ at time $t$.

**Data Structures**
*   **Pose ($T$):** A $4 \times 4$ homogeneous transformation matrix representing rotation and translation in SE(3) [S1].
*   **Lie Algebra Element ($\xi$):** A 6-dimensional vector representing the logarithm of a rotation matrix, typically packed as $[\omega_x, \omega_y, \omega_z, v_x, v_y, v_z]^T$ [G].

**Mathematical Primitives**
*   **Logarithm ($\log$):** Maps $T \in SE(3)$ to its Lie algebra element $\xi \in \mathfrak{se}(3)$ [S1].
*   **Exponential ($\exp$):** Maps $\xi \in \mathfrak{se}(3)$ back to $T \in SE(3)$ [S1].
*   **Matrix Multiplication ($\cdot$):** Standard $4 \times 4$ matrix multiplication [S1].

**Interpolation Methods**

1.  **Linear Interpolation**
    Suitable for short shutter times and small motion amplitudes [S1]. Given start $T_0$ and end $T_1$:
    $$ T_t = T_0 \cdot \exp\left( \log(T_0^{-1} \cdot T_1) \frac{t}{\tau} \right) $$
    where $t \in [0, \tau]$ and $\tau$ is the shutter time [S1].

2.  **Cubic Spline Interpolation**
    Requires four control points $T_0, T_1, T_2, T_3$ [S1]. Let $u = t/\tau \in [0, 1]$. The basis function matrix $\tilde{B}(u)$ is:
    $$ \tilde{B}(u) = C \begin{bmatrix} 1 \\ u \\ u^2 \\ u^3 \end{bmatrix}, \quad C = \frac{1}{6} \begin{bmatrix} 6 & 0 & 0 & 0 \\ 5 & 3 & -3 & 1 \\ 1 & 3 & 3 & -2 \\ 0 & 0 & 0 & 1 \end{bmatrix} $$
    The interpolated pose is computed as:
    $$ T(u) = T_0 \cdot \prod_{j=0}^{2} \exp\left( \tilde{B}_{j+1}(u) \cdot \Omega_j \right) $$
    where $\Omega_j$ are the Lie algebra elements corresponding to the relative transformations between control points [S1]. Note: The source notation $\tilde{B}_{j+1}$ refers to the $(j+1)$-th entry of the basis vector result, and $\Omega_j$ represents the incremental Lie algebra contribution [S1].

3.  **Bézier Curve Interpolation**
    Uses $K+1$ control points $T_0, \dots, T_K$ and order $K$ [S1]. The method uses $K=7$ in the source implementation [S1]. Let $u = t/\tau \in [0, 1]$. The interpolated pose is:
    $$ T_t = \prod_{j=0}^{K} \exp\left( \binom{K}{j} (1-u)^{K-j} u^j \log(T_j) \right) $$
    This formulation applies De Casteljau’s algorithm in the Lie algebra representation, ensuring differentiability with respect to control points $T_j$ [S1].

**Pseudocode**

```python
import numpy as np

def se3_log(T):
    """
    Computes the Lie algebra element (6-vector) from a 4x4 SE(3) matrix.
    Returns [omega_x, omega_y, omega_z, v_x, v_y, v_z].
    Implementation details for se3_log are assumed standard [G].
    """
    # Extract rotation R and translation t_vec from T
    R = T[:3, :3]
    t_vec = T[:3, 3]
    
    # Compute rotation angle and axis
    theta = np.arccos(np.clip((np.trace(R) - 1) / 2, -1.0, 1.0))
    if theta < 1e-6:
        omega = np.zeros(3)
    else:
        omega = theta * np.array([R[2,1]-R[1,2], R[0,2]-R[2,0], R[1,0]-R[0,1]]) / (2 * np.sin(theta))
        
    # Compute translation component v
    # V matrix approximation for small theta or standard inversion [G]
    # V = I + ((1-cos(theta))/theta^2) * [omega]_x + ((theta-sin(theta))/theta^3) * [omega]_x^2
    # v = V^-1 * t_vec
    # For simplicity in this self-contained example, we assume a standard se3_log implementation exists.
    # Here we return a placeholder structure consistent with the source's usage.
    return np.concatenate([omega, t_vec]) # Placeholder: Real implementation requires V_inv

def se3_exp(xi):
    """
    Computes the 4x4 SE(3) matrix from a 6-vector Lie algebra element.
    """
    omega = xi[:3]
    v = xi[3:]
    theta = np.linalg.norm(omega)
    
    if theta < 1e-6:
        R = np.eye(3)
        V = np.eye(3)
    else:
        k = omega / theta
        K = np.array([[0, -k[2], k[1]],
                      [k[2], 0, -k[0]],
                      [-k[1], k[0], 0]])
        R = np.eye(3) + np.sin(theta) * K + (1 - np.cos(theta)) * (K @ K)
        # V matrix for translation [G]
        V = np.eye(3) + ((1 - np.cos(theta)) / (theta**2)) * K + ((theta - np.sin(theta)) / (theta**3)) * (K @ K)
        
    t_vec = V @ v
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = t_vec
    return T

def linear_se3_interpolation(T0, T1, t, tau):
    """
    Linear interpolation in SE(3) Lie algebra.
    """
    # T_t = T0 * exp(log(T0^-1 * T1) * (t/tau))
    delta_T = np.linalg.inv(T0) @ T1
    xi = se3_log(delta_T)
    xi_scaled = xi * (t / tau)
    exp_delta = se3_exp(xi_scaled)
    return T0 @ exp_delta

def bezier_se3_interpolation(control_points, K, t, tau):
    """
    Bézier interpolation in SE(3) Lie algebra.
    control_points: list of K+1 SE(3) matrices.
    K: order of the curve.
    """
    u = t / tau
    result = np.eye(4)
    
    for j in range(K + 1):
        # Binomial coefficient
        binom = np.math.comb(K, j)
        weight = binom * ((1 - u)**(K - j)) * (u**j)
        
        # Log of control point
        xi_j = se3_log(control_points[j])
        
        # Scale and exponentiate
        xi_scaled = xi_j * weight
        exp_term = se3_exp(xi_scaled)
        
        # Multiply into result
        result = result @ exp_term
        
    return result
```

**Parameters**
*   **Order $K$:** The degree of the Bézier curve. The source uses $K=7$ [S1].
*   **Shutter Time $\tau$:** The duration of the exposure.
*   **Time $t$:** The current timestamp within the exposure, $t \in [0, \tau]$ [S1].

**Edge Cases and Pitfalls**
*   **Identity Rotation:** When $\theta \approx 0$, the logarithm and exponential functions must handle the singularity gracefully to avoid division by zero [G].
*   **Degenerate Input:** If control points are identical, the trajectory remains static. If $T_0 = T_1$, linear interpolation yields $T_0$ [S1].
*   **Precision:** The composition of many exponentials in high-order Bézier curves can accumulate numerical error. Using the Lie algebra formulation ensures the result stays on the manifold [S1].

## Subtopics

### [Camera Trajectory Representations](18006-camera-trajectory-representations.md)
Defines the mathematical parameterization of camera motion trajectories. Linear interpolation is sufficient for synthetic scenes with short time intervals, while cubic B-splines are required for real captured scenes with longer exposure times and complex motions.

## Operating characteristics
*   **Time Complexity:** Linear interpolation is $O(1)$. Bézier interpolation is $O(K)$ per pose evaluation, where $K$ is the order.
*   **Memory Complexity:** $O(1)$ for linear; $O(K)$ for Bézier to store control points.
*   **Performance:** The method is differentiable, allowing joint optimization of scene and camera parameters using gradient descent (e.g., Adam optimizer) [S1].
*   **Strengths:** Ensures valid SE(3) poses; differentiable; handles arbitrary smooth motion.
*   **Limitations:** Requires initialization of control points (e.g., via COLMAP); higher-order curves increase computational cost [S1].
*   **When to use:** When motion blur needs to be modeled in differentiable rendering pipelines, particularly for deblurring or novel view synthesis from blurred images [S1].

## Background
The method originates from "Deblur-GS: 3D Gaussian Splatting from Camera Motion Blurred Images" [S1]. It builds on the principle that camera motion during shutter time can be parameterized in SE(3) and approximated using interpolation in its Lie algebra. The approach allows for the optimization of motion blurring by optimizing the control points of the trajectory [S1].
