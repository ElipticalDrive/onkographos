# B-Spline Camera Path Interpolation

Also called: B-Spline Camera Path, Multidimensional B-Spline Interpolation for Camera Poses, Spline Interpolated Camera Path

## Overview
Creates a smooth, continuous camera trajectory between discrete input keyframe poses using multidimensional B-spline interpolation [S1, S2, unofficial]. It solves the problem of generating high-quality intermediate views for novel view synthesis or volume rendering when only sparse camera positions are available [S1, unofficial]. Unlike linear interpolation or simple quaternion slerp, this method ensures $C^2$ continuity (smooth acceleration) across the entire path by treating position, look-at direction, and up vector as coupled spline components [S1, S2, unofficial]. It is distinct from [Parametric Path Generation](11476-parametric-path-generation.md) which uses explicit geometric primitives (spirals, ellipses), and from [Sparse Trajectory Generation](7215-sparse-trajectory-generation.md) which focuses on selecting keyframes rather than interpolating between them.

## How it works
**Inputs:**
- `poses`: Array of shape $(N, 3, 4)$ or $(N, 4, 4)$ representing $N$ input camera poses. If $(N, 3, 4)$, it is padded to homogeneous coordinates.
- `n_interp`: Integer, number of interpolated poses to generate between each pair of consecutive keyframes.
- `spline_degree`: Integer, polynomial degree of the B-spline. Default: 5 [S1, S2, unofficial].
- `smoothness`: Float, smoothing factor for the spline fit. Default: 0.03 [S1, S2, unofficial].
- `rot_weight`: Float, relative weighting of rotation vs. translation in the pose decomposition. Default: 0.1 [S1, S2, unofficial].

**Outputs:**
- `new_poses`: Array of shape $(M, 3, 4)$ or $(M, 4, 4)$, where $M = n\_interp \times (N - 1)$, containing the interpolated camera poses.

**Data Structures:**
- **Pose Matrix**: $4 \times 4$ homogeneous transformation matrix $\mathbf{P} = [\mathbf{R} | \mathbf{t}; \mathbf{0}^T | 1]$, where $\mathbf{R}$ is $3 \times 3$ rotation and $\mathbf{t}$ is $3 \times 1$ translation [S1, unofficial].
- **Points Tuple**: A tuple of three arrays `(pos, lookat, up)`, each of shape $(N, 3)$, representing the spatial coordinates for position, look-at target, and up vector respectively [S1, S2, unofficial].
- **Spline Tuple (tck)**: Returned by `splprep`, containing knots `t`, coefficients `c`, and degree `k` [S1, unofficial].

**Steps:**

1.  **Preprocessing**: Ensure input poses are in $(N, 3, 4)$ format. If input is $(N, 4, 4)$, remove the homogeneous row [S1, unofficial].
2.  **Decomposition**: Convert each pose matrix into $(pos, lookat, up)$ points using `poses_to_points`:
    $$
    \begin{aligned}
    \mathbf{pos}_i &= \mathbf{P}_i[:, 3] \\
    \mathbf{lookat}_i &= \mathbf{P}_i[:, 3] - \text{rot\_weight} \cdot \mathbf{P}_i[:, 2] \\
    \mathbf{up}_i &= \mathbf{P}_i[:, 3] + \text{rot\_weight} \cdot \mathbf{P}_i[:, 1]
    \end{aligned}
    $$
    where $\mathbf{P}_i[:, 1]$ is the up vector column and $\mathbf{P}_i[:, 2]$ is the forward/look-at direction column in the local frame [S1, S2, unofficial].
3.  **Spline Fitting**: Fit a multidimensional B-spline to the points using `splprep`. The points are transposed to shape $(3, N)$ for the function [S1, unofficial]:
    $$
    \text{tck} = \text{splprep}([\mathbf{pos}^T, \mathbf{lookat}^T, \mathbf{up}^T], k=\min(\text{spline\_degree}, N-1), s=\text{smoothness})
    $$
    Here, $k$ is the degree, and $s$ is the smoothing factor. If $s=0$, the spline interpolates exactly through the points [S1, S2, unofficial].
4.  **Evaluation**: Generate parameter values $u$ uniformly spaced between 0 and 1. The total number of output poses is $M = n\_interp \times (N - 1)$. The parameter array is:
    $$
    u = \text{linspace}(0, 1, M, \text{endpoint}=\text{False})
    $$
    Evaluate the spline at these parameters using `splev` [S1, unofficial]:
    $$
    [\mathbf{pos}_{new}, \mathbf{lookat}_{new}, \mathbf{up}_{new}] = \text{splev}(u, \text{tck})
    $$
    The result arrays are of shape $(M, 3)$ [S1, unofficial].
5.  **Recomposition**: Convert the interpolated points back to pose matrices using `points_to_poses`. This involves constructing the rotation matrix from the `lookat` and `up` vectors and setting the translation to `pos` [S1, S2, unofficial].
6.  **Padding**: Pad the resulting $(M, 3, 4)$ poses to $(M, 4, 4)$ if required by the downstream renderer [S1, unofficial].

**Pseudocode:**

```python
import numpy as np
from scipy.interpolate import splprep, splev

def poses_to_points(poses, rot_weight=0.1):
    """
    Convert pose matrices to (pos, lookat, up) points.
    Args:
        poses: np.ndarray, shape (N, 3, 4) or (N, 4, 4)
        rot_weight: float, weight for rotation component
    Returns:
        pos, lookat, up: np.ndarray, shape (N, 3)
    """
    # Handle 4x4 input
    if poses.shape[-2] == 4:
        poses = poses[:, :3, :]
    
    pos = poses[:, :3, 3]
    # Column 2 is the z-axis (forward/look-at direction in camera frame)
    # Column 1 is the y-axis (up vector in camera frame)
    lookat = pos - rot_weight * poses[:, :3, 2]
    up = pos + rot_weight * poses[:, :3, 1]
    return pos, lookat, up

def points_to_poses(pos, lookat, up):
    """
    Convert points back to pose matrices.
    Args:
        pos, lookat, up: np.ndarray, shape (N, 3)
    Returns:
        poses: np.ndarray, shape (N, 3, 4)
    """
    N = pos.shape[0]
    poses = np.zeros((N, 3, 4))
    
    # Reconstruct camera basis
    # Forward vector (z-axis)
    z = lookat - pos
    z = z / np.linalg.norm(z, axis=1, keepdims=True)
    
    # Right vector (x-axis) from cross product of up and forward
    # Note: Standard camera convention often uses up x forward or similar.
    # Based on multinerf source, we reconstruct R from lookat and up.
    # A robust reconstruction:
    # x = normalize(up x z)
    # y = z x x
    # However, the source simply uses the provided up vector to define the orientation.
    # We approximate the standard view matrix construction.
    
    # Let's assume the standard OpenGL/Blender convention where:
    # z = normalize(lookat - pos)
    # x = normalize(cross(up, z))
    # y = cross(z, x)
    
    # Handle degenerate cases where up is parallel to z
    cross = np.cross(up, z)
    norms = np.linalg.norm(cross, axis=1, keepdims=True)
    # Avoid division by zero
    norms = np.where(norms < 1e-6, 1.0, norms)
    x = cross / norms
    
    y = np.cross(z, x)
    
    R = np.stack([x, y, z], axis=1) # Shape (N, 3, 3)
    poses[:, :3, :3] = R
    poses[:, :3, 3] = pos
    return poses

def generate_interpolated_path(poses, n_interp=10, spline_degree=5, smoothness=0.03, rot_weight=0.1):
    """
    Generate interpolated camera path using B-splines.
    """
    # 1. Decompose
    pos, lookat, up = poses_to_points(poses, rot_weight)
    
    # 2. Prepare points for splprep (transpose to (3, N))
    pts = np.array([pos, lookat, up]).T # Shape (N, 3) -> splprep expects list of arrays or (3, N)
    # splprep expects a list of 1D arrays or a 2D array where rows are dimensions.
    # scipy.interpolate.splprep expects x, y, z as separate arrays or a list.
    # The source uses pts.T which is (N, 3). splprep takes [x, y, z].
    # So we pass [pos, lookat, up]
    
    # 3. Fit Spline
    # k is degree. Must be <= N-1.
    k = min(spline_degree, pos.shape[0] - 1)
    tck, _ = splprep([pos, lookat, up], k=k, s=smoothness)
    
    # 4. Evaluate
    n_total = n_interp * (pos.shape[0] - 1)
    u = np.linspace(0, 1, n_total, endpoint=False)
    
    new_pos, new_lookat, new_up = splev(u, tck)
    
    # 5. Recompose
    new_poses = points_to_poses(new_pos, new_lookat, new_up)
    
    return new_poses
```

**Parameters:**
- `n_interp`: Number of interpolated poses per segment. Total output poses $M = n\_interp \times (N - 1)$ [S1, S2, unofficial].
- `spline_degree`: Polynomial degree. Default 5 [S1, S2, unofficial].
- `smoothness`: Smoothing factor. $0$ forces exact interpolation through keyframes. Default 0.03 [S1, S2, unofficial].
- `rot_weight`: Weight for rotation/translation coupling. Default 0.1 [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- If `smoothness` is set to 0, the spline will interpolate exactly through the keyframes, which may result in oscillations if the keyframes are noisy [S1, S2, unofficial].
- If `rot_weight` is too high, the look-at direction may swing excessively; if too low, the camera may not rotate enough [S1, S2, unofficial].
- The number of keyframes $N$ must be at least 2. If $N < 2$, `splprep` will fail [S1, unofficial].
- The degree $k$ is capped at $N-1$ to ensure a valid spline [S1, unofficial].

## Subtopics

### Spline Render Path Creation with Exposure Interpolation
Creates a spline interpolation render path from a subset of dataset poses, optionally interpolating per-frame exposure values to avoid flickering [S1, unofficial]. It identifies keyframe indices by matching image names from a config file against the dataset [S1, unofficial]. It generates render poses using the standard B-spline interpolation method [S1, unofficial]. If exposure interpolation is enabled, it logs the exposure values, fits a 1D B-spline (degree 5, smoothness 20) to the log-exposures, and exponentiates the result to get render exposures [S1, unofficial]. If exposures are None but interpolation is enabled, it raises a ValueError [S1, unofficial]. The smoothness value for exposure interpolation (20) is significantly higher than for geometry (0.03) to ensure smooth lighting transitions [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N \cdot M)$ where $N$ is the number of keyframes and $M$ is the number of interpolated poses. The spline fitting is $O(N)$ and evaluation is $O(M)$ [S1, S2, unofficial].
- **Memory Complexity**: $O(N)$ for storing the spline coefficients and $O(M)$ for the output poses [S1, S2, unofficial].
- **Performance**: Efficient for real-time path generation. The use of `scipy` makes it fast for typical dataset sizes ($N < 1000$) [S1, S2, unofficial].
- **Strengths**: Produces smooth, continuous camera motion with $C^2$ continuity. Handles both position and orientation smoothly. Simple to implement using standard libraries [S1, S2, unofficial].
- **Limitations**: Requires a set of keyframes. Does not handle occlusions or scene geometry. The choice of `smoothness` and `rot_weight` can significantly affect the visual quality [S1, S2, unofficial].
- **When to use**: When generating novel views from sparse keyframes for volume rendering or NeRF training [S1, S2, unofficial].
- **When not to use**: When exact camera poses are required (use raw poses) or when the camera path needs to follow specific scene geometry (use [Elongated Structure Camera Trajectory Generation](4666-elongated-structure-camera-trajectory-generation.md)) [S1, S2, unofficial].

## Background
Originated in the context of NeRF and multi-view stereo reconstruction, specifically popularized by the Google Research MultiNeRF project [S1, unofficial]. It is used to generate smooth camera trajectories for rendering novel views from sparse input images, which is crucial for training and evaluating neural radiance fields [S1, S2, unofficial]. The method leverages standard B-spline interpolation techniques adapted for 3D pose data [S1, S2, unofficial].
