# Trajectory Alignment (RANSAC)

Also called: RANSAC Trajectory Alignment, Trajectory Alignment via RANSAC

## Overview
Aligns a sparse camera trajectory to a ground truth trajectory using RANSAC-based point cloud registration [S1, unofficial]. It differs from standard global alignment by handling sparse, potentially noisy inputs through iterative sampling, and optionally sparsifies the input trajectory when a mapping file is provided and the trajectory length exceeds 1600 frames [S1, unofficial].

## How it works
**Inputs:**
- `gt_traj_col`: Ground truth trajectory in column-major format [S1, unofficial].
- `map_file`: Optional mapping file containing `n_sampled_frames`, `n_total_frames`, and a mapping array where each row is `[frame_index, total_frame_index]` [S1, unofficial].
- `gt_trans`: Optional transformation matrix to apply to the ground truth point cloud [S1, unofficial].
- `randomvar`: Noise magnitude multiplier. Default: 0.0. If `< 1e-5`, no noise is added [S1, unofficial].

**Outputs:**
- Aligned trajectory poses [S1, unofficial].

**Data Structures:**
- Point Cloud: A set of 3D points derived from trajectory camera positions [S1, unofficial].
- Correspondence Vector: A list of index pairs `[i, i]` indicating self-correspondence between the source and target point clouds [S1, unofficial].

**Parameters:**
- `max_iteration`: 100,000 [S1, unofficial].
- `max_validation`: 100,000 [S1, unofficial].

**Steps:**
1. Parse `map_file` to extract `n_sampled_frames`, `n_total_frames`, and the mapping array [S1, unofficial].
2. If `map_file` is provided and trajectory length > 1600, sparsify the trajectory using the mapping; otherwise, use the full trajectory [S1, unofficial].
3. Convert the selected ground truth trajectory `gt_traj_col` into a point cloud `traj_pcd_col` [S1, unofficial].
4. If `gt_trans` is provided, apply it to `traj_pcd_col` [S1, unofficial].
5. Create a correspondence vector `corres` where each point index `i` maps to itself: `corres = [[0,0], [1,1], ..., [N-1, N-1]]` [S1, unofficial].
6. Run RANSAC registration with `max_iteration=100000` and `max_validation=100000` [S1, unofficial]. If `randomvar >= 1e-5`, add noise scaled by `randomvar` to the source points before registration [S1, unofficial].
7. Apply the best-fit transformation found by RANSAC to the source trajectory [S1, unofficial].

**Pseudocode:**
```python
import numpy as np
import open3d as o3d

def trajectory_alignment_ransac(source_traj_col, gt_traj_col, map_file=None, gt_trans=None, randomvar=0.0):
    # Step 1 & 2: Parse mapping and sparsify if necessary
    # [G] File parsing logic not detailed in source. Assumes returns list of frame indices.
    if map_file is not None and len(gt_traj_col) > 1600:
        indices = parse_mapping_file(map_file)
        selected_traj = gt_traj_col[indices]
    else:
        selected_traj = gt_traj_col

    # Step 3: Convert to point cloud
    # [G] Extracts 3D positions from trajectory data structure
    traj_pcd_col = convert_trajectory_to_pointcloud(selected_traj)

    # Step 4: Transform ground truth if provided
    if gt_trans is not None:
        traj_pcd_col.transform(gt_trans)

    # Step 5: Create correspondence vector
    n_points = len(selected_traj)
    corres_indices = np.asarray([[i, i] for i in range(n_points)])
    corres = o3d.utility.Vector2iVector(corres_indices)

    # Step 6: RANSAC Alignment
    # [G] Assumes source_traj_pcd is the trajectory to be aligned
    source_traj_pcd = convert_trajectory_to_pointcloud(source_traj_col)

    # Add noise if randomvar >= 1e-5
    if randomvar >= 1e-5:
        noise = np.random.randn(len(source_traj_pcd.points), 3) * randomvar
        source_traj_pcd.points = o3d.utility.Vector3dVector(
            np.asarray(source_traj_pcd.points) + noise
        )

    # Perform RANSAC registration
    # [G] open3d.registration.registration_ransac_based_on_correspondence is used
    # max_correspondence_distance and ransac_n are not specified in sources
    result = o3d.registration.registration_ransac_based_on_correspondence(
        source_traj_pcd,
        traj_pcd_col,
        corres,
        max_correspondence_distance=0.1, # [G] Not given in sources. Typical value.
        estimation_method=o3d.pipelines.registration.TransformationEstimationPointToPoint(),
        ransac_n=3, # [G] Not given. Typical for point-to-point.
        checks=100000,
        criteria=o3d.pipelines.registration.RANSACConvergenceCriteria(100000, 100000)
    )

    # Step 7: Apply transformation
    source_traj_pcd.transform(result.transformation)
    return source_traj_pcd

def convert_trajectory_to_pointcloud(traj):
    # [G] Extracts 3D positions from trajectory
    pcd = o3d.geometry.PointCloud()
    pcd.points = o3d.utility.Vector3dVector(traj[:, :3])
    return pcd

def parse_mapping_file(path):
    # [G] Reads mapping file and returns list of frame indices
    # Format: n_sampled_frames, n_total_frames, then rows of [frame_index, total_frame_index]
    data = np.loadtxt(path)
    return data[:, 0].astype(int)
```

**Edge cases and pitfalls:**
- If trajectory length is `<= 1600` or `map_file` is absent, sparsification is skipped and the full trajectory is used [S1, unofficial].
- If `randomvar < 1e-5`, noise injection is disabled to prevent unnecessary perturbation [S1, unofficial].

## Subtopics

### Pose Alignment (RANSAC-inspired)
For fewer than 9 input views, alignment samples every possible pair of cameras in one set and computes the Sim(3) transformation relating it to the same camera pair in the other trajectory [S2]. The global Sim(3) transformation yielding the lowest average camera alignment error is selected [S2]. For 9 or more views, it uses the standard Umeyama algorithm [S2].

## Operating characteristics
- **Time Complexity:** High for the RANSAC variant due to 100,000 iterations and validation steps [S1, unofficial]. The RANSAC-inspired variant for <9 views involves checking all camera pairs, which is $O(N^2)$ for $N$ views [S2].
- **Memory Complexity:** Linear with respect to the number of trajectory points for point cloud storage [S1, unofficial].
- **Strengths:** Handles very few views (<9) where standard algorithms fail [S2].
- **Limitations:** Sparsification is only applied if trajectory length > 1600 and a mapping file is provided [S1, unofficial].
- **When to use:** When aligning sparse trajectories where standard global alignment is unstable due to insufficient views [S2].

## Background
Originated in the context of sparse pose alignment for NeRF reconstruction [S2]. The RANSAC-based approach was adopted to handle the instability of standard alignment methods when dealing with very few input views (<9) [S2]. The conditional sparsification logic is part of the trajectory processing pipeline [S1, unofficial].
