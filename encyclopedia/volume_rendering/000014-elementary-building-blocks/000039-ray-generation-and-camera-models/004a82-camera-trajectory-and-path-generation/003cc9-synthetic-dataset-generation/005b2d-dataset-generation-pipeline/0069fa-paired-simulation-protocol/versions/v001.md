# Paired Simulation Protocol


## Overview
The Paired Simulation Protocol is a standardized evaluation framework for comparing volume rendering and neural scene reconstruction methods under controlled, degraded conditions, specifically targeting underwater rendering scenarios [S1, unofficial]. It solves the problem of inconsistent benchmarking by freezing all input data, camera poses, and evaluation metrics before training begins, ensuring that performance differences arise solely from the algorithmic approach rather than data leakage or hyperparameter tuning on test sets [S1, unofficial]. It sets itself apart from sibling pipelines like the [Difix3D Pipeline](20628-difix3d-pipeline.md) by enforcing a strict "blind" evaluation where clean ground-truth images are inaccessible during the training and checkpoint selection phases, and by mandating that all final metrics be computed on a single, frozen export format to eliminate environment-specific variance [S1, unofficial].

## How it works
The protocol operates on synthetic datasets generated by Plenodium, providing paired inputs of degraded (underwater) and clean (original) imagery [S1, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Synthetic subsets from Plenodium Beach and Street simulations at easy, medium, and hard water levels [S1, unofficial].
    *   Each subset contains 100 posed $512 \times 512$ images and a pose-matched clean counterpart [S1, unofficial].
    *   A subset-specific sparse point cloud [S1, unofficial].
    *   Frozen camera poses for testing [S1, unofficial].
*   **Outputs:**
    *   Rendered images from the evaluated method.
    *   Quantitative metrics: PSNR, SSIM, and AlexNet-LPIPS [S1, unofficial].

### Data Structures and Layout
The dataset is structured into two disjoint sets of 50 images each, derived from the 100 available poses per subset:
1.  **Training Set:** 50 degraded views. These are used for optimization.
2.  **Held-out Set:** 50 degraded views. These are used for final evaluation.
*   **Clean Images:** The pose-matched clean counterparts are stored but are explicitly inaccessible to the training loop [S1, unofficial]. They are read only by the final evaluator [S1, unofficial].

### Numbered Steps
1.  **Dataset Freezing:** Explicit filenames are assigned to freeze the 50 degraded training views and 50 held-out views before any full run begins [S1, unofficial].
2.  **Environment Setup:** All methods receive the same degraded images, cameras, subset-specific sparse point cloud, and frozen test poses [S1, unofficial].
3.  **Training:** Methods are trained using only the degraded training views. No clean target, test image, or test metric is used to select a checkpoint or tune hyperparameters [S1, unofficial].
    *   *Note:* For methods with a medium-separation branch (e.g., WaterSplatting, Ours), the clean data is not used for supervision. For methods without such a branch (e.g., Ordinary 3DGS), the underwater RGB is retained as a no-separation reference [S1, unofficial].
4.  **Export:** All methods export lossless 8-bit RGB PNGs [S1, unofficial].
5.  **Evaluation:**
    *   The frozen metric environment rescoring is applied to the exported PNGs [S1, unofficial].
    *   Metrics are computed for two comparisons:
        1.  Rendered underwater image vs. its degraded target (from the held-out set).
        2.  Raw medium-disabled branch (or full output if no branch exists) vs. the clean target [S1, unofficial].
    *   Ordinary 3DGS results are labeled as "no-separation reference" in the second test [S1, unofficial].

### Formulas and Parameters
*   **Image Resolution:** $512 \times 512$ pixels [S1, unofficial].
*   **Subset Size:** 100 posed images per subset [S1, unofficial].
*   **Training Iterations:**
    *   Nerfstudio 3DGS: 30,000 iterations [S1, unofficial].
    *   WaterSplatting and Ours: 15,000 iterations [S1, unofficial].
    *   Depth-assisted Plenodium: 15,001 iterations [S1, unofficial].
*   **Metrics:** PSNR, SSIM, AlexNet-LPIPS [S1, unofficial].

### Pseudocode
```python
def run_paired_simulation_protocol():
    # 1. Load Frozen Dataset
    # Load Plenodium Beach and Street simulations (easy, medium, hard levels)
    # Each subset has 100 poses. Split into 50 training, 50 held-out.
    # Clean counterparts exist but are marked inaccessible for training.
    dataset = load_plenodium_subsets()
    train_views = dataset.frozen_training_views() # 50 degraded images
    test_views = dataset.frozen_held_out_views()  # 50 degraded images
    clean_targets = dataset.clean_counterparts()    # Inaccessible during training
    
    # 2. Initialize Methods
    methods = [
        Nerfstudio3DGS(iterations=30000),
        WaterSplatting(iterations=15000),
        Ours(iterations=15000),
        DepthAssistedPlenodium(iterations=15001, depth_priors="DepthAnythingV2")
    ]
    
    results = {}
    
    for method in methods:
        # 3. Train
        # Input: train_views, cameras, sparse_point_cloud
        # Constraint: No access to clean_targets or test_views for checkpoint selection
        method.train(inputs=train_views, 
                     cameras=dataset.cameras, 
                     point_cloud=dataset.sparse_point_cloud)
        
        # 4. Export
        # Export lossless 8-bit RGB PNGs
        exported_pngs = method.export_pngs(test_views)
        
        # 5. Evaluate
        # Metric environment is frozen
        metrics = {}
        
        # Comparison 1: Rendered vs Degraded Target
        for i, (rendered, degraded_target) in enumerate(zip(exported_pngs, test_views)):
            psnr_1 = compute_psnr(rendered, degraded_target)
            ssim_1 = compute_ssim(rendered, degraded_target)
            lpips_1 = compute_lpips(rendered, degraded_target)
            metrics[f"vs_degraded_{i}"] = (psnr_1, ssim_1, lpips_1)
            
        # Comparison 2: Output vs Clean Target
        # Note: For methods with medium-separation branch, use raw branch output
        # For Ordinary 3DGS, use full underwater RGB as no-separation reference
        for i, (rendered, clean_target) in enumerate(zip(exported_pngs, clean_targets)):
            psnr_2 = compute_psnr(rendered, clean_target)
            ssim_2 = compute_ssim(rendered, clean_target)
            lpips_2 = compute_lpips(rendered, clean_target)
            metrics[f"vs_clean_{i}"] = (psnr_2, ssim_2, lpips_2)
            
        results[method.name] = metrics
        
    return results
```

### Edge Cases and Pitfalls
*   **No Separation Branch:** Ordinary 3DGS lacks a medium-separation branch. Its output must be clearly labeled as a "no-separation reference" in the second test (vs. clean target) to distinguish it from methods that explicitly model and remove the medium [S1, unofficial].
*   **Metric Environment:** Method-native float metrics are retained only as a render audit. All table results must be rescored from the lossless 8-bit PNG exports to remove training-environment differences [S1, unofficial].
*   **Data Leakage:** The clean images must never influence checkpoint selection or hyperparameter tuning. Violating this invalidates the protocol [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Determined by the number of training iterations (15k–30k) and the number of views (100 per subset).
*   **Memory Complexity:** Depends on the scene representation (e.g., 3DGS primitives) and the resolution ($512 \times 512$).
*   **Strengths:** Eliminates variability from data splits, hyperparameter tuning, and metric computation environments. Allows direct comparison of algorithmic improvements in handling degraded media.
*   **Limitations:** Restricted to synthetic datasets (Plenodium). Does not evaluate generalization to real-world unseen scenes outside the provided subsets.
*   **When to Use:** When comparing multiple methods on the same underwater rendering task under identical conditions.
*   **When Not to Use:** When evaluating real-world robustness or generalization to unseen environments.

## Background
The Paired Simulation Protocol was introduced in the context of evaluating "Optical-Mass Water Gaussians for Per-Scene Underwater Rendering" [S1, unofficial]. It builds upon the need for rigorous comparison in neural rendering, specifically addressing the challenges of underwater imaging where media scattering and absorption degrade input images. The protocol leverages the official Plenodium Beach and Street simulations [S1, unofficial] and compares against baselines including Nerfstudio 3DGS [S1, unofficial], WaterSplatting [S1, unofficial], and depth-assisted Plenodium [S1, unofficial].
