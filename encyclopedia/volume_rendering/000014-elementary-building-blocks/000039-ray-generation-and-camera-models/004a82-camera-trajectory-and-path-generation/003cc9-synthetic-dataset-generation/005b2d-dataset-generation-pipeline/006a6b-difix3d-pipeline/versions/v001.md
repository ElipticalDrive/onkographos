# Difix3D Pipeline

Also called: DifixPipeline

## Overview
The Difix3D Pipeline is a training data generation method that periodically synthesizes novel camera views, renders them via a 3D model, and uses a pretrained diffusion model to remove degradation (such as blur or artifacts) from the rendered images before retraining the model on these "fixed" images [S1, unofficial]. It distinguishes itself from standard novel view synthesis pipelines by integrating a 1-step diffusion refinement step (using SD-Turbo) to enhance image quality, specifically targeting high-dynamic-range (HDR) deblurring and novel view synthesis tasks [S1, unofficial]. It builds on [Dataset Generation Pipeline](16831-dataset-generation-pipeline.md) by providing training data with extreme lighting conditions and high-quality fixed views.

## How it works

### Inputs and Outputs
**Inputs:**
- Pretrained 3D model (e.g., NeRF or Gaussian Splatting implementation) capable of rendering images from camera poses.
- Pretrained diffusion model (`DifixPipeline`) based on `stabilityai/sd-turbo` [S1, unofficial].
- Original training datamanager containing initial camera poses and images.
- Configuration parameters controlling fix frequency, interpolation distance, and diffusion settings [S1, unofficial].

**Outputs:**
- A sequence of "fixed" novel view images saved to disk.
- Updated datamanagers containing novel camera poses and fixed images, used for subsequent training steps.

### Data Structures

**Cameras Object**
Represents camera intrinsics and extrinsics for a batch of poses. Fields include:
- `fx`, `fy`: Focal lengths.
- `cx`, `cy`: Principal point coordinates.
- `distortion_params`: Lens distortion coefficients.
- `height`, `width`: Image dimensions.
- `camera_to_worlds`: Array of shape $[N, 3, 4]$ containing the rotation and translation for each of the $N$ cameras [S1, unofficial].
- `camera_type`, `metadata`: Additional metadata fields.

**DataparserOutputs**
Container for dataset parsing results. Fields include:
- `image_filenames`: List of paths to image files.
- `cameras`: The `Cameras` object described above.
- `scene_box`: Bounding box of the scene.
- `mask_filenames`: Optional list of mask paths (default `None`).
- `dataparser_scale`, `dataparser_transform`: Scaling and transformation matrices.
- `metadata`: Additional metadata [S1, unofficial].

**Difix3DDataManagerConfig**
Configuration for the data manager. Inherits from `VanillaDataManagerConfig` and adds:
- `_target`: Type identifier.
- `patch_size`: Integer, default 32 [S1, unofficial].

### Parameters
- `steps_per_val`: Integer, default 5000. Frequency of validation steps [S1, unofficial].
- `steps_per_fix`: Integer. Frequency of diffusion fix steps.
- `distance`: Float, default 0.5. Interpolation distance for generating novel poses [S1, unofficial].
- `timesteps`: List of integers, default `[199]`. Diffusion timestep for 1-step inference [S1, unofficial].
- `guidance_scale`: Float, default 0.0. Classifier-free guidance scale for diffusion [S1, unofficial].
- `prompt`: String, default `"remove degradation"`. Text prompt for the diffusion model [S1, unofficial].
- `train_num_rays_per_batch`: Integer, default 16384. Rays per batch for new datamanager training [S1, unofficial].
- `eval_num_rays_per_batch`: Integer, default 4096. Rays per batch for evaluation [S1, unofficial].

### Algorithm Steps

1. **Initialization**: Load the pretrained diffusion model `DifixPipeline` from `nvidia/difix_ref` and move it to CUDA. Initialize `CameraPoseInterpolator` with rotation and translation weights of 1.0. Cache training and testing camera poses by appending homogeneous coordinates `[0, 0, 0, 1]` [S1, unofficial].

2. **Training Loop Sampling**: In each training step, randomly sample from the original datamanager with 40% probability or from the latest novel datamanager with 60% probability to fetch `ray_bundle` and `batch` [S1, unofficial].

3. **Forward Pass**: Perform a forward pass through the 3D model using `self.model(ray_bundle)`. Compute metrics via `self.model.get_metrics_dict` and loss via `self.model.get_loss_dict` [S1, unofficial].

4. **Fix Trigger**: If `step % steps_per_fix == 0`, trigger the `fix(step)` routine. If `step % steps_per_val == 0`, trigger validation `val(step)` [S1, unofficial].

5. **Pose Interpolation (inside `fix`)**: Interpolate novel poses from `current_novel_poses` to `testing_poses` using `shift_poses` with `distance=0.5` [S1, unofficial].

6. **Reference Image Mapping**: Find the nearest training poses to the generated novel poses using `find_nearest_assignments` and map them to `ref_image_filenames` [S1, unofficial].

7. **Camera Construction**: Construct a `Cameras` object for the novel poses. Repeat intrinsics (`fx`, `fy`, `cx`, `cy`), distortion, and dimensions. Set `camera_to_worlds` to `novel_poses[:, :3, :4]`. **Pitfall**: Ensure `novel_poses` are 4x4 matrices before slicing to drop the homogeneous row [S1, unofficial].

8. **Rendering**: Render the novel poses to `render_dir/novel/step/Pred/` using `get_outputs_for_camera` [S1, unofficial].

9. **Diffusion Fix**: For each rendered image:
   - Run the diffusion model: `self.difix(prompt="remove degradation", image=image, ref_image=ref_image, num_inference_steps=1, timesteps=[199], guidance_scale=0.0)` [S1, unofficial].
   - Resize the output using `Image.LANCZOS` to match the original image size.
   - Save the fixed image to `Fixed/` [S1, unofficial].

10. **Datamanager Update**: Create new `DataparserOutputs` with the fixed image filenames and novel cameras. Initialize a new `Difix3DDataManager` with `train_num_rays_per_batch=16384` and `eval_num_rays_per_batch=4096`. Append this new datamanager to `self.novel_datamanagers`. Update `self.current_novel_poses` and `self.current_novel_cameras` [S1, unofficial].

        self.difix.set_eval()
        
        # Initialize camera pose interpolator
        self.camera_pose_interpolator = CameraPoseInterpolator(rotation_weight=1.0, translation_weight=1.0)
        
        # Cache poses with homogeneous coordinates
        self.training_poses = self._add_homogeneous_coordinates(self.training_poses)
        self.testing_poses = self._add_homogeneous_coordinates(self.testing_poses)
        
        self.novel_datamanagers = []
        self.current_novel_poses = None
        self.current_novel_cameras = None

    def _add_homogeneous_coordinates(self, poses):
        """Append [0, 0, 0, 1] to 3x4 pose matrices to make them 4x4."""
        # Assuming poses are [N, 3, 4]
        homogeneous_row = torch.tensor([[0, 0, 0, 1]], device=poses.device).unsqueeze(0).expand(poses.shape[0], -1, -1)
        return torch.cat([poses, homogeneous_row], dim=1)

    def get_train_loss_dict(self, step):
        # Sample from original or novel datamanager
        if torch.rand(1).item() < 0.4:
            ray_bundle, batch = self.original_datamanager.sample()
        else:
            if self.novel_datamanagers:
                ray_bundle, batch = self.novel_datamanagers[-1].sample()
            else:
                ray_bundle, batch = self.original_datamanager.sample()

        # Forward pass
        model_outputs = self.model(ray_bundle)
        metrics = self.model.get_metrics_dict(model_outputs, batch)
        loss = self.model.get_loss_dict(model_outputs, batch)

        # Check for fix or validation steps
        if step % self.config.steps_per_fix == 0:
            self.fix(step)
        if step % self.config.steps_per_val == 0:
            self.val(step)

        return loss, metrics

    def fix(self, step):
        # Interpolate novel poses
        novel_poses = self.camera_pose_interpolator.shift_poses(
            self.current_novel_poses, 
            self.testing_poses, 
            distance=0.5
        )
        
        # Find nearest training poses for reference images
        nearest_indices = self.find_nearest_assignments(novel_poses, self.training_poses)
        ref_image_filenames = [self.training_image_filenames[i] for i in nearest_indices]
        
        # Construct Cameras object
        # Repeat intrinsics
        fx = self.original_cameras.fx
        fy = self.original_cameras.fy
        cx = self.original_cameras.cx
        cy = self.original_cameras.cy
        distortion = self.original_cameras.distortion_params
        height = self.original_cameras.height
        width = self.original_cameras.width
        
        # camera_to_worlds is [N, 3, 4]
        camera_to_worlds = novel_poses[:, :3, :4]
        
        cameras = Cameras(
            fx=fx, fy=fy, cx=cx, cy=cy,
            distortion_params=distortion,
            height=height, width=width,
            camera_to_worlds=camera_to_worlds
        )
        
        # Render novel poses
        render_dir = f"render_dir/novel/step/{step}/Pred/"
        os.makedirs(render_dir, exist_ok=True)
        
        rendered_images = self.get_outputs_for_camera(cameras)
        
        # Diffusion fix
        fixed_images = []
        for i, (image, ref_filename) in enumerate(zip(rendered_images, ref_image_filenames)):
            # Convert tensor to PIL Image if necessary
            pil_image = self.tensor_to_pil(image)
            pil_ref = Image.open(ref_filename).convert("RGB")
            
            # Run diffusion fix
            # Note: The actual DifixPipeline call handles the VAE encode/decode and UNet inference
            fixed_image = self.difix(
                prompt="remove degradation",
                image=pil_image,
                ref_image=pil_ref,

                timesteps=[199],
                guidance_scale=0.0
            )
            
            # Resize to original size
            fixed_image = fixed_image.resize((width, height), Image.LANCZOS)
            
            # Save
            save_path = f"render_dir/novel/step/{step}/Fixed/fixed_{i}.png"
            fixed_image.save(save_path)
            fixed_images.append(save_path)
        
        # Create new DataparserOutputs
        dataparser_outputs = DataparserOutputs(

            mask_filenames=None,

        )
        
        # Setup new Datamanager
        new_datamanager = Difix3DDataManager(
            dataparser_outputs=dataparser_outputs,

                patch_size=32,

### Edge Cases and Pitfalls
- **Camera Pose Slicing**: `camera_to_worlds` is constructed by slicing `novel_poses[:, :3, :4]`. If `novel_poses` are not 4x4 matrices, this slice will fail or produce incorrect extrinsics [S1, unofficial].
- **Diffusion Input Format**: The diffusion model expects PIL Images. Ensure rendered tensors are correctly converted to PIL format before inference [S1, unofficial].
- **Resolution Mismatch**: The diffusion output must be resized to match the original image size using `Image.LANCZOS` interpolation to maintain consistency with the datamanager's expected input dimensions [S1, unofficial].
- **Memory Usage**: The diffusion model (SD-Turbo) and VAE require significant VRAM. Ensure sufficient GPU memory is available during the `fix` step [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
- **Time Complexity**: The pipeline adds a periodic overhead of diffusion inference. Each fix step involves rendering novel views and running 1-step diffusion inference for each view. The diffusion step is constant time per image but computationally expensive due to the UNet and VAE passes [S1, unofficial].
- **Memory Complexity**: Requires storing multiple datamanagers (original and novel) and the diffusion model in VRAM. The VAE and UNet parameters are loaded into memory [S1, unofficial].

### Measured Performance
- **Hardware**: Tested on CUDA-enabled GPUs [S1, unofficial].
- **Resolution**: Depends on the original image resolution; diffusion output is resized to match [S1, unofficial].
- **Scene**: General 3D scenes; effectiveness depends on the quality of the initial 3D model and the diffusion model's ability to remove specific degradations [S1, unofficial].

### Scaling
- Scales with the number of novel views generated per fix step.
- The 40/60 sampling ratio balances original data and fixed novel views, potentially improving generalization [S1, unofficial].

### Strengths and Limitations
- **Strengths**: Improves image quality of novel views by removing degradation; integrates seamlessly with existing 3D training pipelines; uses efficient 1-step diffusion [S1, unofficial].
- **Limitations**: Requires significant VRAM for diffusion model; periodic fix steps interrupt training flow; quality depends on the reference images and diffusion prompt [S1, unofficial].

### When to Use
- Use when training HDR deblurring or novel view synthesis models that require high-quality training data with extreme lighting conditions [S1, unofficial].
- Use when the initial 3D model produces degraded or blurry novel views that can be corrected by diffusion [S1, unofficial].

### When Not to Use
- Avoid when VRAM is limited and diffusion model cannot be loaded [S1, unofficial].
- Avoid when real-time training is required and periodic fix steps introduce unacceptable latency [S1, unofficial].

## Background

### Origin
The Difix3D Pipeline was introduced by NVIDIA Research (nv-tlabs) as part of the Difix3D project [S1, unofficial]. It leverages the SD-Turbo diffusion model for 1-step image refinement [S1, unofficial].

### History and Development
The pipeline was developed to address the challenge of generating high-quality training data for 3D models, particularly in scenarios with challenging lighting and degradation. It builds on the concept of using diffusion models for image restoration and enhancement [S1, unofficial].

### Usage
Used in research for HDR deblurring and novel view synthesis, providing training data that enhances model performance on degraded inputs [S1, unofficial].
