# Random Multi-view Sampling for Training

Also called: Fitting Multi-view Images Baselines, Random View Subsetting

## Overview
Random multi-view sampling for training is a data selection strategy used in inverse rendering and novel view synthesis to construct minibatches from a sparse set of input images. It addresses the problem of efficiently training neural representations (such as MLPs or Gaussian splats) when the available training views are limited or computationally expensive to process. Unlike deterministic selection methods, this approach selects a random subset of views at each epoch to form the training batch, ensuring that the model is exposed to diverse view combinations over time. It is distinguished from sibling methods like [Light Cone Construction](19580-light-cone-construction.md) by its lack of geometric constraints on view adjacency, relying instead on stochastic diversity.

## How it works
The method operates by dynamically selecting training views during the optimization process rather than fixing a static subset.

**Inputs:**
- A set of $N$ training images $\mathcal{I} = \{I_1, I_2, \dots, I_N\}$ with associated camera poses.
- A target batch size $B$ (number of views per minibatch).
- A neural network architecture (e.g., MLP for texture fitting or Gaussian Splatting parameters).

**Outputs:**
- A minibatch of $B$ views and their corresponding rays/points for a single training iteration.

**Data Structures:**
- **View Index List:** An array of integers $[0, \dots, N-1]$ representing the available training images.
- **Minibatch Indices:** A list of $B$ unique integers sampled from the View Index List.

**Steps:**
1. **Initialization:** Store the total number of training views $N$.
2. **Epoch Loop:** For each training epoch:
   a. **Random Subset Selection:** Sample $B$ distinct indices from the range $[0, N-1]$ without replacement. Let this set be $\mathcal{B}$.
   b. **Ray Generation:** For each view $i \in \mathcal{B}$, generate rays according to the camera model (see [Ray generation and camera models](link)).
   c. **Forward Pass:** Render the scene using the current neural representation for all rays in $\mathcal{B}$.
   d. **Loss Computation:** Compute the reconstruction loss (e.g., MSE, LPIPS) between rendered pixels and ground truth pixels for all views in $\mathcal{B}$.
   e. **Backward Pass:** Update network parameters using automatic differentiation.

**Parameters:**
- **Batch Size ($B$):** The number of views sampled per iteration. Typical values depend on memory constraints; in texture fitting baselines, this is often small (e.g., 1-4 views) to allow for high-resolution rendering [S1].
- **Epochs:** The number of full passes over the dataset.

**Pseudocode:**
```python
def train_random_multi_view(model, images, poses, batch_size, num_epochs):
    """
    Train a model using random multi-view sampling.
    
    Args:
        model: Neural network model (e.g., MLP or Gaussian Splatting renderer).
        images: List of N training images.
        poses: List of N camera pose matrices.
        batch_size: Number of views to sample per minibatch (B).
        num_epochs: Number of training epochs.
    """
    n_views = len(images)
    
    for epoch in range(num_epochs):
        # Step 2a: Random subset selection
        # Sample B unique indices from 0 to N-1
        batch_indices = sample_without_replacement(n_views, batch_size)
        
        current_batch_loss = 0.0
        
        for idx in batch_indices:
            # Step 2b: Ray generation for view idx
            rays = generate_rays(poses[idx], images[idx].shape)
            
            # Step 2c: Forward pass
            rendered_colors = model(rays)
            ground_truth = images[idx]
            
            # Step 2d: Loss computation
            # Example: Mean Squared Error
            loss = mean_squared_error(rendered_colors, ground_truth)
            
            # Accumulate loss for logging (optional)
            current_batch_loss += loss
            
            # Step 2e: Backward pass
            # Note: In practice, gradients are accumulated or the loss is averaged
            # before calling backward() to handle the batch structure.
            loss.backward()
            
        # Update weights (e.g., using Adam optimizer)
        optimizer.step()
        optimizer.zero_grad()

def sample_without_replacement(n, k):
    """
    Sample k unique integers from 0 to n-1.
    Implemented using Fisher-Yates shuffle for the first k elements.
    """
    indices = list(range(n))
    # Shuffle only the first k elements to save time if n is large
    for i in range(k):
        j = random.randint(i, n - 1)
        indices[i], indices[j] = indices[j], indices[i]
    return indices[:k]
```

**Edge Cases and Pitfalls:**
- **Small $N$:** If the number of training views $N$ is smaller than the batch size $B$, sampling without replacement is impossible. The method must fall back to sampling with replacement or reduce $B$ [S1].
- **View Correlation:** Random sampling may occasionally select highly correlated views (e.g., adjacent frames), leading to redundant gradients. However, over many epochs, this averages out [S1].
- **Precision:** When using hash encodings for positional encoding, ensure the hash grid size is tuned to match the storage cost of the baseline models to ensure fair comparison [S1].

## Subtopics

### Farthest-Point Sampling for View Selection
A deterministic variant used in sparse-view reconstruction (e.g., CADSplat) to select training views. It selects the first training image randomly, then iteratively selects remaining images by finding the camera center farthest from the already selected set in the SfM frame [S2, unofficial]. This ensures maximal geometric diversity. It is chosen when geometric coverage is more critical than stochastic diversity, such as in CAD-assisted reconstruction. A key pitfall is that reduced-view conditions often reuse the relative calibration of the full capture, modeling a pre-calibrated-rig regime rather than a genuine sparse capture which would require wide-baseline SfM calibration [S2, unofficial].

### Patch Sampling with Shift
A strategy to obtain a patch set $S_p$ from an image $I$ to ensure all areas are trained and enhance synthetic quality from different views [S3]. It involves shifting the patch center $(\Delta x, \Delta y)$ and adjusting the focal lengths by a zoom ratio $\alpha$. The patch size $w \times h$ is kept less than 15% of the total image resolution $W \times H$ [S3]. This method is used to manage GPU memory constraints while training on high-resolution images (e.g., KITTI, Brno Urban) [S3].

### Quality-based Training Data Sampling
A strategy to sample driving scene data based on synthetic quality, strengthening the model to learn sparse regions and reducing training time [S3]. It calculates a synthetic quality metric $Q(I_e)$ for each image $I_e$ in the set $S_e$ using perceptual loss. The top $n$ samples with the worst performance are selected as training data for the next phase [S3]. The sampling ratio is typically set to 80% [S3]. This method is chosen when the input point cloud has significant holes or outliers, and the goal is to focus training on difficult-to-render regions.

## Operating characteristics
- **Time Complexity:** $O(B \cdot R \cdot D)$ per iteration, where $B$ is batch size, $R$ is rays per view, and $D$ is decoding depth. Since $B \ll N$ (total views), it is significantly faster than full-view training per iteration.
- **Memory Complexity:** $O(B \cdot R \cdot C)$, where $C$ is channel size. Allows training on high-resolution images by limiting the number of views processed simultaneously [S1].
- **Performance:** In texture fitting baselines, random multi-view sampling allows for fair comparison with high-resolution vertex colors and neural baselines while requiring substantially less storage [S1]. It consistently outperforms high-resolution vertex colors in LPIPS and SSIM metrics [S1].
- **Strengths:** Simple to implement; does not require complex geometric analysis for view selection; robust to noise in view selection.
- **Limitations:** May select redundant views in early epochs; does not guarantee coverage of specific geometric features unless combined with other strategies (e.g., quality-based sampling) [S3].
- **When to use:** When training data is abundant but computationally expensive to process; when comparing against baselines that use random subsets [S1].
- **When not to use:** When geometric coverage is critical and views are extremely sparse (e.g., <5 views), where deterministic farthest-point sampling might be superior [S2, unofficial].

## Background
The method originates from inverse rendering and neural texture fitting literature. It was used as a baseline in "Heat Kernel Textures the Geodesic Gaussians That Do Not Splat" to compare against the proposed HKTex model, demonstrating that constraining representation to the surface manifold provides a strong inductive bias [S1]. It is also referenced in the context of sparse-view 3D Gaussian Splatting (CADSplat) and large-scale neural scene rendering for autonomous driving (READ) [S2, unofficial][S3].
