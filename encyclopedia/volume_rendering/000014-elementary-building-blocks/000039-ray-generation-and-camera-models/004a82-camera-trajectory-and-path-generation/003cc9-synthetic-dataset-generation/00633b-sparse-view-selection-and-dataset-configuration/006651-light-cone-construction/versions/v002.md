# Light Cone Construction

Also called: Light cone projection, Light rays

## Overview
Light Cone Construction is a method for generating synthetic astronomical observations (imaging or spectroscopy) from cosmological simulation data by stacking discrete redshift slices into a continuous line-of-sight volume [S1]. It solves the problem of creating realistic light cones from periodic simulation boxes that do not natively span the required redshift range, while minimizing redundant sampling of the same physical structures [S1]. It is distinguished from standard volume rendering by its specific handling of cosmological distance metrics, periodic domain wrapping, and the statistical generation of unique, non-overlapping sightlines [S1].

## How it works

### Inputs and Outputs
**Inputs:**
*   Observer redshift ($z_{obs}$) and redshift interval $[z_{min}, z_{max}]$ [S1].
*   Simulation datasets at various redshifts [S1].
*   Cosmological parameters: $\Omega_M$ (matter density), $\Omega_k$ (curvature density), $\Omega_\Lambda$ (cosmological constant density) [S1].
*   For Light Cone Projections: angular field of view ($\theta$) and image resolution [S1].
*   For Light Rays: arbitrary-angle rays [S1].

**Outputs:**
*   A stack of datasets ordered by redshift [S1].
*   For Projections: a 2D image or data cube representing the integrated signal along the line of sight [S1].
*   For Rays: a list of ray segments, each containing intersected pixels, path lengths ($dl$), and assigned redshifts [S1].

### Data Structures

**Dataset Stack:**
A list of simulation data objects ordered from highest redshift ($z_{max}$) to lowest ($z_{min}$) [S1].

**Ray Segment (for Light Rays):**
An array containing indices of all pixels intersected by the ray within the dataset and the path length $dl$ through each intersected pixel [S1].

**Projection Object (for Light Cone Projections):**
A pre-computed projection of the entire lateral domain of a dataset, enabling multiple light cone projections to sample different regions without re-projecting the full volume [S1].

### Formulas

**Expansion Factor $E(z)$:**
$$ E(z) \equiv \sqrt{\Omega_M (1 + z)^3 + \Omega_k (1 + z)^2 + \Omega_\Lambda} $$
where $\Omega_M, \Omega_k, \Omega_\Lambda$ are the energy density contributions of matter, curvature, and the cosmological constant, respectively [S1].

**Angular Size Distance $D_A$:**
The width of the sampled region in the image plane for a field of view $\theta$ is $(1+z) D_A \theta$ [S1]. $D_A$ is defined as:
$$
D_A = \begin{cases} 
\frac{D_H}{\sqrt{|\Omega_k|}} \frac{\sinh(\sqrt{|\Omega_k|} D_C)}{1+z} & \text{for } \Omega_k > 0 \\
\frac{D_C}{1+z} & \text{for } \Omega_k = 0 \\
\frac{D_H}{\sqrt{|\Omega_k|}} \frac{\sin(\sqrt{|\Omega_k|} D_C)}{1+z} & \text{for } \Omega_k < 0
\end{cases}
$$
where $D_C$ is the comoving distance and $D_H$ is the Hubble distance [S1].

**Column Density:**
For a ray segment, the column density $N$ contributed by a physical density $\rho$ over a path length element $dl$ is:
$$ N = \rho \times dl $$
[S1].

### Parameters
*   **Fraction of Box Length:** The user may specify a fraction of the total simulation box length to calculate the maximum allowable redshift step $\delta z$ between datasets, rather than using the full box length [S1].
*   **Maximum Common Volume:** A user-specified limit on the volume overlap between different light cone projections to ensure statistical independence [S1].

### Steps

1.  **Select Datasets:** Use time series machinery to select simulation datasets appropriate for the requested redshift interval $[z_{min}, z_{max}]$ [S1].
2.  **Build Stack:** Initialize an empty stack and add the dataset with the redshift closest to $z_{max}$ as the first element [S1].
3.  **Iterate Downward:**
    a. Calculate $\delta z$, the redshift interval corresponding to the length of the simulation box, noting that $\delta z$ is not constant with redshift [S1].
    b. Determine the target redshift for the next dataset: $z_{target} = z_{current} - \delta z$ [S1].
    c. Select the dataset whose redshift is closest to, but no less than, $z_{target}$ [S1].
    d. Add this dataset to the stack and repeat until the lower limit $z_{min}$ is reached [S1].
    *Note:* The user may constrain the maximum $\delta z$ to be a fraction of the full box length to ensure smoother transitions [S1].
4.  **Generate Sightlines (Randomization):** For each dataset in the stack, choose a random projection axis and center for the projected region to minimize sampling the same structures multiple times, exploiting the periodicity of the computational domain [S1]. For Light Rays, assign a random orientation to each ray segment [S1].
5.  **Compute Projections/Rays:** Project the full lateral domain of each dataset; the comoving radial distance determines the fraction of the box used in the line of sight, and the image width is determined by $(1+z) D_A \theta$ [S1]. For rays, identify all intersected pixels and calculate the path length $dl$ through each [S1].
6.  **Assign Redshifts:** For each length element in a ray, assign a unique redshift based on the dataset's redshift and the point's position along the ray, assuming a smooth Hubble flow [S1].
7.  **Ensure Uniqueness (Optional):** Use a unique solution generator to find realizations with a user-specified maximum common volume [S1]. The generator first attempts to vary only the lateral randomization, allowing a single set of projection objects to be reused, before attempting fully unique randomization [S1].

    relevant.sort(key=lambda d: d.redshift, reverse=True)
    if not relevant:

    stack = []
    current_z = z_max
    
    # Step 2: Add dataset closest to upper limit [S1]
    current_dataset = min(relevant, key=lambda d: abs(d.redshift - current_z))
    stack.append(current_dataset)
    current_z = current_dataset.redshift

    # Step 3: Iterate downward until lower limit [S1]
    while current_z > z_min:
        # Calculate delta_z for box length (not constant with redshift) [S1]
        delta_z = compute_comoving_redshift_step(box_length, current_z, cosmology)
        # User may specify smaller fraction of box length [S1]
        delta_z = min(delta_z, max_delta_z_fraction * compute_comoving_redshift_step(box_length, current_z, cosmology))

        target_z = current_z - delta_z
        # Select next dataset closest to, but no less than, target_z [S1]
        candidates = [d for d in relevant if d.redshift >= target_z]
        if not candidates:
            break

        next_dataset = min(candidates, key=lambda d: abs(d.redshift - target_z))
        if next_dataset not in stack:
            stack.append(next_dataset)
            current_z = next_dataset.redshift
        else:
            remaining = [d for d in candidates if d not in stack]
            if remaining:
                next_dataset = min(remaining, key=lambda d: abs(d.redshift - target_z))
                stack.append(next_dataset)
                current_z = next_dataset.redshift
            else:
                break
    return stack

### Edge Cases and Pitfalls
*   **Non-constant $\delta z$:** The redshift interval corresponding to the simulation box length changes with redshift, requiring recalculation at each stacking step [S1].
*   **Periodicity:** The method relies on the periodicity of the computational domain to randomize projection axes and centers without introducing boundary artifacts [S1].
*   **Sampling Redundancy:** Without randomizing the projection axis and center for each dataset, the same large-scale structures may be sampled multiple times, biasing statistical analyses [S1].
*   **Common Volume:** If the maximum common volume is not specified or set too high, multiple light cone projections may sample the same volume, violating the assumption of independent realizations [S1].

## Operating characteristics

*   **Time Complexity:** The initial dataset stacking is linear with respect to the number of datasets in the stack [S1]. Projection of the full lateral domain is performed once per dataset, making subsequent light cone projections computationally cheap as they only sample different regions [S1].
*   **Memory Complexity:** Requires storing the full lateral projection for each dataset in the stack if multiple light cone projections are to be generated efficiently [S1].
*   **Strengths:** Efficiently generates multiple independent sightlines from a limited set of simulation boxes, and the pre-computation of full lateral projections allows for rapid generation of statistical samples [S1].
*   **Limitations:** Relies on the assumption of a smooth Hubble flow for redshift assignment along rays, which may not capture local velocity distortions unless explicitly modeled [S1].
*   **When to Use:** When generating synthetic observations (imaging or spectroscopy) from cosmological simulations that do not span the full redshift range of interest, or when statistical independence of multiple sightlines is required [S1].
*   **When Not to Use:** When high-fidelity modeling of local velocity fields or non-periodic boundary conditions is critical, or when computational resources are insufficient to store full lateral projections for all datasets [S1].

## Background

Light Cone Construction was implemented in the `yt` analysis toolkit, building on earlier work by Hallman et al. (2007, 2009) [S1]. The method leverages `yt`'s projection machinery to handle the complexities of projecting data from periodic simulation boxes onto a light cone [S1]. It is primarily used in astrophysics for creating synthetic surveys of the universe, such as quasar absorption line studies or galaxy distribution maps, allowing researchers to compare simulation predictions directly with observational data [S1].
