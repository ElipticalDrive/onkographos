# Replica Dataset Preparation

Also called: Replica Data Processing

## Overview
Replica Dataset Preparation filters and corrects the raw Replica synthetic indoor scan data to remove unrealistic camera poses and fix label ambiguities for neural rendering evaluation [S1]. It is distinct from general synthetic generation by focusing on post-processing and filtering of existing scans rather than procedural generation [G], and builds on [Synthetic Dataset Generation](9337-synthetic-dataset-generation.md).

## How it works
**Inputs:** Replica scene data including posed images, semantic labels, and point clouds [S1].
**Outputs:** Filtered image sets, corrected semantic labels, normalized camera poses, and valid near/far clipping parameters [S1].

### Data Structures
The input data consists of:
- `Images`: RGB arrays with semantic segmentation labels [S1].
- `Poses`: Camera poses for the rendered images [S1].
- `Point Clouds`: 3D coordinates associated with the scene [S1].

### Steps
1. **Scene Selection:** Select specific scenes from the Replica dataset. Standard preparation uses `room_0`, `room_1`, `office_3`, and `office_4` [S1]. For sparse-view variants, use `room0`, `room1`, `room2`, `office0`, `office1`, `office2`, and `office3` [S2].
2. **Geometric Filtering:** Render images from the provided camera poses and filter out any images where the camera position is inside furniture or other geometry, as these are unrealistically rendered [S1].
3. **Coordinate Normalization:** Adjust the camera poses so that the 3D points visible in the selected training images are centered around the world origin $(0,0,0)$ [S2]. This is critical for pose refinement stability [S2].
4. **Clipping Plane Setup:** Set NeRF near/far clipping planes. Default is $(0.1, 10.0)$ [S1]. For `office_3`, use $(0.1, 15.0)$ [S1].
5. **Semantic Label Correction (Semi-Automatic):** Apply LSeg to predict semantic label maps for each RGB image [S1]. Evaluate the accuracy of LSeg predictions against the original Replica label map [S1]. Ignore points with labels having accuracy $\approx 0$ or exactly $0$ from evaluation [S1]. Manually fix label ambiguities by ignoring specific labels or merging them (e.g., merge 'rug' and 'floor') [S1].
6. **Sparse-View Sub-sampling (Variant):** Sub-sample every $k$-th frame from the video sequence [S2]. Adapt $k$ per scene to ensure a minimum of 20% covisible regions between any selected view and its neighbors [S2]. Randomly select a triplet of consecutive training images from the sub-sampled set [S2].

### Parameters
- **Image Resolution:** $340 \times 600$ pixels [S2].
- **Near/Far Clipping:** $(0.1, 10.0)$ generally; $(0.1, 15.0)$ for `office_3` [S1].
- **Covisibility Threshold:** Minimum 20% overlap between selected views [S2].

### Edge Cases
- **Collapsed Geometry:** Replica data suffers from collapsed geometry and less photo-realistic appearances compared to real scans [S1].
- **Label Ambiguity:** Objects may have bad appearance or intrinsic indistinguishability (e.g., rug vs. floor) [S1].
- **Unobserved Regions:** Training images may not cover all scene regions; evaluation must account for generalization to unobserved areas via propagation [S1].

## Subtopics

### Replica Dataset Sparse-View Preparation
Replica Dataset Sparse-View Preparation is a variant designed for sparse-view reconstruction tasks [S2]. It uses 7 scenes (`room0`, `room1`, `room2`, `office0`, `office1`, `office2`, `office3`) and adapts the sampling rate per scene to ensure wide-baseline coverage [S2]. It is chosen when evaluating methods under realistic sparse-input conditions [S2].

- **Strengths:** Provides a moderate-quality dataset with semantic labels and controlled geometry for neural rendering evaluation [S1]. Centering poses improves optimization stability [S2].
- **Limitations:** Data artifacts (collapsed geometry, bad appearance) persist from the source [S1]. Label quality requires manual intervention [S1].

## Background
The Replica dataset is a moderate-quality indoor reconstruction dataset with semantic segmentation labels, originally created for proof-of-concept work in neural rendering [S1]. It is based on synthetic scans with randomly generated pose trajectories [S1]. The preparation method was introduced to address issues like camera-in-geometry poses and label inaccuracies [S1]. The sparse-view variant was developed to evaluate methods under realistic sparse-input conditions [S2].
