# Data Augmentation

Also called: Random Rotation Augmentation

## Overview
Data augmentation generates diverse training samples from synthetic sensor data to improve the robustness and generalization of neural scene representations. It addresses the problem of limited or biased training distributions by applying geometric transformations and inserting synthetic objects. Unlike [Novel View Synthesis Rendering](6402-novel-view-synthesis-rendering.md), which synthesizes new views of existing geometry, or [Sparse View Selection and Dataset Configuration](18846-sparse-view-selection-and-dataset-configuration.md), which selects existing captures, data augmentation actively modifies the input data distribution. It builds on [Synthetic Dataset Generation](9337-synthetic-dataset-generation.md) by adding stochastic variation to poses, signs, and scene content.

## How it works
The method consists of two primary strategies: random rotation of existing data and dataset-specific sign balancing.

### Inputs and Outputs
*   **Inputs:**
    *   Point cloud data $P$.
    *   Camera poses $T$ (position and orientation).
    *   Sensor measurements $Z_t = \{v_i, r_{t,i}\}$, where $v_i$ is the ray direction and $r_{t,i}$ is the range measurement at sensor position $p_t$ and orientation $R_t$.
    *   CAD models (optional, for object insertion).
*   **Outputs:**
    *   Augmented dataset $D$ containing samples $(p_j, v_j, f^*_j, i^*_j, s^*_j)$.

### Data Structures
The dataset sample structure is defined as:
*   $p_j \in \mathbb{R}^3$: Ray origin.
*   $v_j \in S^2$: Ray direction.
*   $f^*_j \in \mathbb{R}$: SDF/signed distance measurement.
*   $i^*_j \in \{-1, 1\}$: Intersection indicator.
*   $s^*_j \in \{-1, 1\}$: Sign indicator.

### Steps

#### 1. Random Rotation Augmentation
To obtain diverse training samples, random rotations are applied to both point cloud data and camera poses [S1, unofficial].

1.  Generate random rotation angles $\theta_x, \theta_y, \theta_z$.
2.  Construct rotation matrices $R_x(\theta_x)$, $R_y(\theta_y)$, $R_z(\theta_z)$.
3.  Compute total rotation $R_{total} = R_z(\theta_z) R_y(\theta_y) R_x(\theta_x)$.
4.  Apply $R_{total}$ to all points in the point cloud.
5.  Apply $R_{total}$ to the rotation component of all camera poses.

**Parameters:**
*   $\theta_x \in [-\pi/64, \pi/64]$ [S1, unofficial].
*   $\theta_y \in [-\pi/64, \pi/64]$ [S1, unofficial].
*   $\theta_z \in [-\pi, \pi]$ [S1, unofficial].

#### 2. Dataset Generation and Sign Balancing (SDDF)
For Signed Directional Distance Function (SDDF) models, the initial dataset is unbalanced in sign indicators [S2].

1.  **Generate Positive Samples:**
    For each ray measurement $(v_i, r_{t,i})$ from sensor position $p_t$ and orientation $R_t$:
    *   $p_j = p_t$
    *   $v_j = R_t v_i$
    *   $f^*_j = r_{t,i}$
    *   $i^*_j = 1$
    *   $s^*_j = 1$
2.  **Generate Negative Samples:**
    For each positive sample $(p_j, v_j, f^*_j, i^*_j, s^*_j)$, generate a corresponding negative sample:
    *   $p' = p_j + (f^*_j + \epsilon) v_j$
    *   $v'_j = v_j$
    *   $f'^*_j = -\epsilon$
    *   $i'^*_j = 1$
    *   $s'^*_j = -1$
    *   Where $\epsilon > 0$ is a small offset [S2].

**Pitfalls:**
*   The initial dataset has all $s^*_j = 1$ and $f^*_j \ge 0$, causing sign imbalance [S2].
*   Intersection indicator augmentation ($i^*_j = -1$) is not performed because generating non-intersecting rays is inefficient and does not improve reconstruction results [S2].

#### 3. Object Insertion Augmentation
For downstream tasks, synthetic objects are inserted into scenes to enhance diversity [S3].

1.  Select a CAD model (e.g., from a library of 283 car models and 30 construction vehicles) [S3].
2.  Randomize the object's appearance (e.g., paint color from 60 diverse options) [S3].
3.  Apply Gaussian perturbation to the object's orientation with $\sigma = 15^\circ$ [S3].
4.  Insert the object into the scene.
5.  Handle occlusion naively by comparing the depth map of the scene with the depth map of the inserted object, removing the previous occlusion check [S3].

    theta_y = np.random.uniform(-np.pi / 64, np.pi / 64)
    theta_z = np.random.uniform(-np.pi, np.pi)
    
    # Rotation matrices
    Rx = np.array([
        [1, 0, 0],
        [0, np.cos(theta_x), -np.sin(theta_x)],
        [0, np.sin(theta_x), np.cos(theta_x)]
    ])
    Ry = np.array([
        [np.cos(theta_y), 0, np.sin(theta_y)],
        [0, 1, 0],
        [-np.sin(theta_y), 0, np.cos(theta_y)]
    ])
    Rz = np.array([
        [np.cos(theta_z), -np.sin(theta_z), 0],
        [np.sin(theta_z), np.cos(theta_z), 0],
        [0, 0, 1]
    ])
    
    R_total = Rz @ Ry @ Rx
    
    # Apply to point cloud
    augmented_pc = (R_total @ point_cloud.T).T
    
    # Apply to camera poses (assuming poses are 4x4 matrices)
    augmented_poses = []

## Subtopics

### Dataset Generation and Augmentation
A procedure to convert sensor poses and range measurements into a dataset $D$ suitable for training the SDDF model, specifically addressing sign imbalance [S2]. It is chosen when training implicit signed distance functions that require balanced positive and negative samples. It differs from general rotation augmentation by explicitly generating negative samples via ray extension [S2].

### Object Insertion Data Augmentation
An approach that inserts synthetic CAD models (cars, construction vehicles) into scenes with randomized colors and high orientation perturbation ($\sigma = 15^\circ$) to enhance diversity for downstream tasks [S3]. It is chosen when the training data lacks sufficient variety in object types or appearances. It differs from rotation augmentation by adding new semantic content rather than transforming existing geometry [S3].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples for rotation and sign balancing. Object insertion adds rendering overhead proportional to the number of inserted objects.
*   **Memory Complexity:** Increases the dataset size by a factor of 2 due to negative sample generation in SDDF augmentation [S2].
*   **Strengths:** Improves model robustness to pose variations and sign ambiguities. Object insertion enhances generalization to unseen objects [S3].
*   **Limitations:** Intersection indicator augmentation is omitted due to inefficiency and lack of benefit [S2]. Naive occlusion handling may produce artifacts compared to physically accurate occlusion checks [S3].
*   **When to use:** When training data is limited or biased towards specific poses/signs. When the target application involves diverse object appearances or poses [S1, unofficial][S3].

## Background
Data augmentation in this context originated from the need to train robust neural scene representations from synthetic data. Random rotation augmentation was introduced in the context of point cloud unsupervised pre-training using 3D Gaussian Splatting [S1, unofficial]. Sign balancing for SDDF models was developed to address the inherent bias in range sensor data where all samples initially have positive signs [S2]. Object insertion augmentation was proposed for neural light field estimation to enhance diversity in street scene reconstruction [S3].
