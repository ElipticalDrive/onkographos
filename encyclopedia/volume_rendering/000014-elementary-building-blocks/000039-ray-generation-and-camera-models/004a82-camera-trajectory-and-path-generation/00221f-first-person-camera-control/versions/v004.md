# First-Person Camera Control

Also called: Camera Control, Camera Controller, Camera State & GPU Data Packing, Input Handler, Mouse and Keyboard Input Controller

## Overview
First-Person Camera Control manages the position, orientation (yaw/pitch), and projection parameters of a virtual camera, mapping user input (mouse/keyboard) to transformations for 3D rendering [S1, unofficial][S2, unofficial][S3, unofficial]. It differs from spherical or arcball models by maintaining a fixed "up" vector and allowing free translation along the camera's local axes, which is essential for immersive exploration or precise volumetric inspection [S1, unofficial][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Mouse movement deltas ($\Delta x, \Delta y$), keyboard state (active keys), time delta ($\Delta t$), and initial camera state (position, yaw, pitch) [S2, unofficial][S3, unofficial].
*   **Outputs:** Updated camera position, orientation vectors (front, right, up), and a packed GPU buffer containing these parameters for rendering passes [S1, unofficial].

**Data Structures:**
*   **CPU State (S3, unofficial):**
    *   `_position`: `vec3`
    *   `_front`, `_right`, `_up`: `vec3`
    *   `_worldUp`: `vec3` (default $(0, 1, 0)$)
    *   `_yaw`, `_pitch`: `float`
    *   `_speed`, `_sensitivity`, `_zoom`, `_aspectRatio`, `_nearPlane`, `_farPlane`: `float`
*   **GPU Struct (S1, unofficial):**
    *   `position`: `array<f32, 4>`
    *   `rot`: `array<array<f32, 4>, 3>`
    *   `sin_half_vfov`: `f32`
    *   `frame_count`: `u32`
    *   `width`, `height`: `f32`
    *   `prev_position`: `array<f32, 4>`

**Parameters (Typical Values):**
*   `vfov`: $\pi/2$ radians [S1, unofficial].
*   `moving_speed`: $1.0$ [S1, unofficial].
*   `mouse_speed` / `ROTATION_FACTOR`: $0.01$ or $0.0025$ [S1, unofficial][S2, unofficial].
*   `PAN_FACTOR`: $1$ [S2, unofficial].
*   `ZOOM_FACTOR`: $0.0025$ [S2, unofficial].

**Algorithm Steps:**

1.  **Process Input:** Read mouse deltas ($\Delta x, \Delta y$) and active keyboard keys [S2, unofficial][S3, unofficial]. If left mouse button is active and Control key is held, update lighting parameters [S2, unofficial]. Otherwise, update rotation: $\Delta \text{yaw} = \Delta x \times \text{ROTATION\_FACTOR}$, $\Delta \text{pitch} = \Delta y \times \text{ROTATION\_FACTOR}$ [S2, unofficial]. If right mouse button is active, update pan: $\Delta \text{pan}_x = \Delta x \times \text{PAN\_FACTOR}$, $\Delta \text{pan}_y = \Delta y \times \text{PAN\_FACTOR}$ [S2, unofficial]. Store active keys on key-down; clear on key-up [S2, unofficial].

2.  **Update Orientation:** Apply rotation deltas to `_yaw` and `_pitch` [S3, unofficial]. Clamp `_pitch` to $[-\pi/2 + \epsilon, \pi/2 - \epsilon]$ to prevent flipping [G]. Recalculate basis vectors: $\text{front}_x = \cos(\text{pitch}) \sin(\text{yaw})$, $\text{front}_y = -\sin(\text{pitch})$, $\text{front}_z = \cos(\text{pitch}) \cos(\text{yaw})$ [S1, unofficial]. $\text{right} = \text{normalize}(\text{cross}(\text{front}, \text{worldUp}))$ [S3, unofficial]. $\text{up} = \text{cross}(\text{right}, \text{front})$ [S1, unofficial].

3.  **Update Position:** Determine movement direction based on active keys [S3, unofficial]. Calculate displacement: $\mathbf{v} = (\text{forward} \times \text{front} + \text{right} \times \text{right} + \text{up} \times \text{up}) \times \text{speed} \times \Delta t$ [S3, unofficial]. Update position: $\text{position} = \text{position} + \mathbf{v}$ [S3, unofficial]. Apply pan offsets to position if right mouse was used [S2, unofficial].

4.  **Pack GPU Data:** Compute `sin_half_vfov = sin(0.5 * vfov)` [S1, unofficial]. Construct rotation matrix rows from `front`, `right`, `up` [S1, unofficial]. Fill `CameraGpuData` struct with `position`, `rot`, `sin_half_vfov`, `frame_count`, `width`, `height`, and `prev_position` [S1, unofficial].

**Pseudocode:**

```python
import math

class FirstPersonCamera:
    def __init__(self, position=[0.0, 0.0, 0.0], yaw=math.pi / 2, pitch=0.0):
        self.position = list(position)
        self.yaw = yaw
        self.pitch = pitch
        self.world_up = [0.0, 1.0, 0.0]
        self.front = [0.0, 0.0, 0.0]
        self.right = [0.0, 0.0, 0.0]
        self.up = [0.0, 0.0, 0.0]
        self.speed = 1.0
        self.sensitivity = 0.01
        self.vfov = math.pi / 2
        self._update_vectors()

    def _update_vectors(self):
        x = math.cos(self.pitch) * math.sin(self.yaw)
        y = -math.sin(self.pitch)
        z = math.cos(self.pitch) * math.cos(self.yaw)
        self.front = self._normalize([x, y, z])
        self.right = self._normalize(self._cross(self.front, self.world_up))
        self.up = self._normalize(self._cross(self.right, self.front))

    def _normalize(self, v):
        length = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
        if length == 0: return [0.0, 0.0, 0.0]
        return [v[0]/length, v[1]/length, v[2]/length]

    def _cross(self, a, b):
        return [
            a[1]*b[2] - a[2]*b[1],
            a[2]*b[0] - a[0]*b[2],
            a[0]*b[1] - a[1]*b[0]
        ]

    def process_mouse(self, dx, dy, active_button=0, active_key=None):
        if active_button == 0:
            if active_key == 'Control':
                # Update lighting parameters per S2
                pass
            else:
                self.yaw += dx * 0.0025
                self.pitch += dy * 0.0025
                if self.pitch > 89.0 * math.pi / 180.0: self.pitch = 89.0 * math.pi / 180.0
                if self.pitch < -89.0 * math.pi / 180.0: self.pitch = -89.0 * math.pi / 180.0
        elif active_button == 2:
            # Update pan per S2
            pass
        self._update_vectors()

    def process_keyboard(self, direction, delta_time):
        velocity = self.speed * delta_time
        if direction == 'FORWARD':
            self.position[0] += self.front[0] * velocity
            self.position[1] += self.front[1] * velocity
            self.position[2] += self.front[2] * velocity
        elif direction == 'BACKWARD':
            self.position[0] -= self.front[0] * velocity
            self.position[1] -= self.front[1] * velocity
            self.position[2] -= self.front[2] * velocity
        elif direction == 'RIGHT':
            self.position[0] += self.right[0] * velocity
            self.position[1] += self.right[1] * velocity
            self.position[2] += self.right[2] * velocity
        elif direction == 'LEFT':
            self.position[0] -= self.right[0] * velocity
            self.position[1] -= self.right[1] * velocity
            self.position[2] -= self.right[2] * velocity

    def get_gpu_data(self, width, height, frame_count):
        sin_half_vfov = math.sin(self.vfov / 2.0)
        rot_packed = [
            self.front + [0.0],
            self.right + [0.0],
            self.up + [0.0]
        ]
        return {
            "position": self.position + [0.0],
            "rot": rot_packed,
            "sin_half_vfov": sin_half_vfov,
            "frame_count": frame_count,
            "width": float(width),
            "height": float(height),
            "prev_position": self.position + [0.0]
        }
```

## Subtopics

### [Cinematic Camera Metaphor](7134-cinematic-camera-metaphor.md)
The Cinematic Camera Metaphor is a navigation technique for non-immersive 3D environments where user input manipulates the position and orientation of a virtual camera to control the viewpoint. It enables users to "tumble, track, and dolly" the view, allowing for precise framing of the scene. It is distinguished from direct manipulation metaphors (like Scene-in-Hand) by treating the camera as an independent entity controlled via standard input devices, often requiring modifier keys or specific gestures to invoke different camera motions.

### setCamera
A programmatic interface for setting camera state, often used in scientific visualization toolkits (e.g., VTK.js) [S4, unofficial]. It handles synchronization between requested state and applied state, ensuring that changes are only applied if they differ from the last request [S4, unofficial]. It supports setting position, focal point, view up, and zoom (parallel scale) [S4, unofficial]. A key pitfall is handling XR mode, where headset pose should override programmatic control, and ensuring that unchanged camera steps do not reset the view unexpectedly [S4, unofficial].
