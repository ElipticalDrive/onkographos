# Arbitrary Source-Detector Geometry Projector

Also called: Arbitrary Source-Detector Geometry, Axial cone-beam, Cone-Beam Geometry Projector, Flexible cone-beam, Parallel-Beam Geometry Projector

## Overview
The Arbitrary Source-Detector Geometry Projector is a volume rendering and forward projection method that supports flexible specification of CT imaging systems, including arbitrary 3D detector shifts, non-equispaced projection angles, and planar or curved detectors [S1, unofficial]. It solves the problem of generating accurate line integrals through a voxelized volume for complex, non-standard X-ray geometries where standard parallel or simple cone-beam assumptions fail [S1, unofficial]. Unlike fixed-geometry projectors, it allows the user to define the 3D location and orientation of every individual source-detector pair, overriding standard geometric assumptions [S1, unofficial]. It builds on [Ray generation and camera models](770-ray-generation-and-camera-models.md) by generalizing ray assembly to arbitrary source positions and detector orientations.

## How it works
**Inputs:**
- Volume data: 3D array of voxel values (units $\text{mm}^{-1}$) [S1, unofficial].
- Geometry configuration: Source position $\mathbf{s}$, detector plane parameters (origin, normal, pixel grid), and projection angles [S1, unofficial].
- For TIGRE-style setups: Scanner mode ("parallel" or "cone"), voxel dimensions ($nVoxel, sVoxel, dVoxel$), detector dimensions ($nDetector, sDetector, dDetector$), and distances ($DSD, DSO$) [S3, unofficial].

**Outputs:**
- Projection image: 2D array of line integrals (attenuation values) corresponding to detector pixels [S1, unofficial].

**Data Structures:**
- **Detector Grid:** A 2D mesh of pixel centers in world coordinates. For a planar detector, pixels are arranged in a grid with spacing defined by `pixel_size`. Coordinates are generated using `linspace` and `meshgrid` with 'ij' indexing [S2, unofficial].
- **Ray Representation:** Each ray is defined by an origin $\mathbf{o}$ (source position) and a direction $\mathbf{d}$ (normalized vector from source to detector pixel) [S2, unofficial].

**Steps:**
1. **Initialize Geometry:**
   - If using TIGRE-style configuration, set parameters from config dictionary: `geo.DSD` (Source-Detector Distance), `geo.DSO` (Source-Origin Distance), `nDetector`, `sDetector`, `dDetector`, `nVoxel`, `sVoxel`, `dVoxel`, and offsets [S3, unofficial].
   - Determine scanner mode: "parallel" or "cone" [S3, unofficial].

2. **Compute Detector Pixel Positions in World Coordinates:**
   - Calculate $y\_coords$ and $x\_coords$ using `linspace` based on `detector_size` and `pixel_size` [S2, unofficial].
   - Create a meshgrid with 'ij' indexing to form 2D arrays $X$ and $Y$ [S2, unofficial].
   - Set the $Z$ coordinate to `center_offset_z` (SID, Source-Image Distance) [S2, unofficial].
   - Stack into a 3D array of shape $(H, W, 3)$ with order $[Z, Y, X]$ [S2, unofficial]. Let this array be $\mathbf{P}_{det}$.

3. **Compute Ray Directions:**
   - For each pixel $(i, j)$, let $\mathbf{p}_{ij}$ be the world coordinate of the detector pixel from $\mathbf{P}_{det}$ [S2, unofficial].
   - Let $\mathbf{s}$ be the source position [S2, unofficial].
   - Compute the raw direction vector: $\mathbf{v}_{ij} = \mathbf{p}_{ij} - \mathbf{s}$ [S2, unofficial].
   - Normalize the direction: $\mathbf{d}_{ij} = \frac{\mathbf{v}_{ij}}{\|\mathbf{v}_{ij}\|}$ [S2, unofficial].

4. **Forward Projection (Line Integral):**
   - For each ray $(\mathbf{o}=\mathbf{s}, \mathbf{d}=\mathbf{d}_{ij})$, compute the line integral through the volume.
   - Common methods include Siddon’s method, Joseph’s method, Distance Driven (DD), or SF method [S1, unofficial].
   - The result for pixel $(i, j)$ is $I_{ij} = \int_{ray} \mu(\mathbf{x}) \, d\mathbf{x}$, where $\mu$ is the voxel attenuation coefficient [S1, unofficial].

5. **Assemble Output:**
   - Collect all $I_{ij}$ into a 2D array of shape $(H, W)$ [S2, unofficial].

**Pseudocode:**
```python
import numpy as np

def arbitrary_source_detector_projector(volume, source_pos, detector_origin, detector_normal, 
                                        detector_width, detector_height, pixel_size, 
                                        num_angles=None, angles=None):
    """
    Performs forward projection for arbitrary source-detector geometry.
    
    Args:
        volume: 3D numpy array of voxel values (mm^-1).
        source_pos: 3D array-like, source position [x, y, z].
        detector_origin: 3D array-like, origin of the detector plane [x, y, z].
        detector_normal: 3D array-like, normal vector of the detector plane [nx, ny, nz].
        detector_width: float, total width of the detector in mm.
        detector_height: float, total height of the detector in mm.
        pixel_size: float, size of each pixel in mm.
        num_angles: int, number of projection angles (optional).
        angles: array-like, specific angles in radians (optional).
        
    Returns:
        projections: 2D numpy array of line integrals for a single view.
    """
    # 1. Compute detector pixel positions in world coordinates
    # Calculate coordinates
    x_coords = np.linspace(-detector_width / 2, detector_width / 2, int(detector_width / pixel_size))
    y_coords = np.linspace(-detector_height / 2, detector_height / 2, int(detector_height / pixel_size))
    
    # Create meshgrid with 'ij' indexing
    X, Y = np.meshgrid(x_coords, y_coords, indexing='ij')
    
    # Determine Z coordinate (SID)
    # SID is the distance from source to detector origin along the normal
    # Assuming detector_origin is at distance SID from source along the normal direction
    # For simplicity, if detector_origin is given, we use it directly.
    # If we need to compute SID, it would be |source_pos - detector_origin| projected on normal.
    # Here, we assume detector_origin is the center of the detector plane.
    
    # Stack into (H, W, 3) array with order [Z, Y, X]
    # We need to express detector pixels in world coordinates.
    # First, define local detector basis.
    # Normal is Z_local. We need Right and Up vectors.
    # Let's assume a standard orientation where detector plane is perpendicular to normal.
    # We need two orthogonal vectors in the plane.
    
    # Simple approach: if normal is [0,0,1], then X and Y are world X and Y.
    # General case: construct basis.
    normal = np.array(detector_normal) / np.linalg.norm(detector_normal)
    
    # Choose a reference vector to compute 'right'
    if np.abs(normal[2]) < 0.9:
        ref = np.array([0, 0, 1])
    else:
        ref = np.array([1, 0, 0])
        
    right = np.cross(normal, ref)
    right = right / np.linalg.norm(right)
    up = np.cross(right, normal)
    
    # World coordinates of detector pixels
    # Pixel centers relative to detector origin
    # X and Y are in local detector coordinates (width and height directions)
    # But our meshgrid X is along width, Y is along height.
    # So, world_pos = detector_origin + X * right + Y * up
    
    # Note: X and Y from meshgrid are 2D arrays.
    # We need to scale them by pixel_size? No, linspace already gives coordinates.
    # But linspace range is -width/2 to width/2.
    # So X and Y are already in mm.
    
    # Compute world coordinates
    # X is shape (H, W), Y is shape (H, W)
    # right and up are 3D vectors
    
    # Expand dimensions for broadcasting
    X_exp = X[:, :, np.newaxis] # (H, W, 1)
    Y_exp = Y[:, :, np.newaxis] # (H, W, 1)
    
    # World positions
    # detector_origin is (3,)
    # right is (3,)
    # up is (3,)
    
    world_positions = (np.array(detector_origin) + 
                       X_exp * right[np.newaxis, np.newaxis, :] + 
                       Y_exp * up[np.newaxis, np.newaxis, :])
    
    # world_positions shape: (H, W, 3)
    
    # 2. Compute ray directions
    source_pos = np.array(source_pos)
    
    # Vector from source to detector pixel
    ray_dirs_raw = world_positions - source_pos[np.newaxis, np.newaxis, :] # (H, W, 3)
    
    # Normalize
    norms = np.linalg.norm(ray_dirs_raw, axis=2, keepdims=True)
    # Avoid division by zero
    norms = np.maximum(norms, 1e-8)
    ray_dirs = ray_dirs_raw / norms
    
    # 3. Forward Projection
    # This step requires a specific projector implementation (Siddon, Joseph, etc.)
    # Here we simulate the integration step.
    # In practice, this would call a CUDA kernel or optimized C++ function.
    # For this pseudocode, we assume a function `integrate_ray` exists.

    projections = np.zeros((H, W))
```

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision issues may arise when computing ray directions for very distant sources or small pixel sizes [G].
- **Boundaries:** Rays may miss the volume entirely. These should be handled by returning 0 or skipping [G].
- **Degenerate Input:** If the source lies on the detector plane, the ray direction is undefined. Check for zero-length vectors [G].
- **Non-equispaced Angles:** The method supports arbitrary angles, but interpolation may be needed if angles are not uniform [S1, unofficial].

## Subtopics

### [t-beam projectors](3067-t-beam-projectors.md)
Integrates the source-to-pixel segment along a ray for volume rendering or projection. It is a specific implementation of the forward/back projection step within the arbitrary geometry framework. Choose it when efficient integration along the ray segment is required. See [t-beam projectors](3067-t-beam-projectors.md).

### DRR Geometry and Coordinate Transformation
A variant focused on generating Digitally Reconstructed Radiographs (DRR) from 3D CT/MRI data. It emphasizes the coordinate transformation from world space to detector space for clinical comparison with 2D X-rays. Choose it for medical imaging applications requiring virtual X-ray generation. See [DRR Geometry and Coordinate Transformation](3067-t-beam-projectors.md) (Note: No separate article exists, so it is described here).

## Operating characteristics
- **Time Complexity:** Depends on the projector method (Siddon, Joseph, DD, SF) and the number of rays (pixels) and samples per ray. Generally $O(N_{pixels} \times N_{samples})$ [S1, unofficial].
- **Memory Complexity:** $O(N_{voxels})$ for the volume data. Additional memory for ray data structures [S1, unofficial].
- **Measured Performance:** Implemented on CPU (C/C++) and NVIDIA GPUs (CUDA) for parallelization over samples [S1, unofficial].
- **Scaling:** Scales well with GPU parallelization. Performance depends on volume size and detector resolution [S1, unofficial].
- **Strengths:** Flexibility in geometry specification, support for arbitrary source-detector pairs, non-equispaced angles, and curved detectors [S1, unofficial].
- **Limitations:** More complex setup than standard parallel or cone-beam geometries. Performance may be lower than optimized fixed-geometry projectors due to lack of specialized optimizations [S1, unofficial].
- **When to Use:** Complex CT geometries, non-standard imaging systems, research applications requiring flexible geometry [S1, unofficial].
- **When Not to Use:** Standard parallel or simple cone-beam CT where fixed-geometry projectors are sufficient and faster [S1, unofficial].

## Background
The Arbitrary Source-Detector Geometry Projector is part of a software package for X-ray Computed Tomography (XCT) forward models [S1, unofficial]. It was developed to support flexible specification of CT geometries, including arbitrary 3D detector shifts and non-equispaced projection angles [S1, unofficial]. The implementation includes forward and back projector pairs for objects with cylindrical symmetry, such as the Abel Transform for parallel-beam geometries [S1, unofficial]. The core algorithms (Siddon, Joseph, DD, SF) are based on established mathematical models for XCT line integrals [S1, unofficial].
