# Spherical Background Sampling

Also called: Spherical Map Sampling

## Overview
Spherical Background Sampling converts a 3D ray direction vector into 2D UV coordinates suitable for sampling a background environment map [S1, unofficial]. It assumes the ray origin lies inside the background sphere, mapping the direction directly to spherical coordinates [S2, unofficial].

## How it works
**Inputs:**
- `v`: A 3D direction vector [S1, unofficial].
- `rays_o`, `rays_d`: Ray origins and directions, batched inputs for GPU implementations [S2, unofficial].
- `radius`: Radius of the background sphere [S2, unofficial].

**Outputs:**
- `coords`: 2D UV coordinates [S1, S2, unofficial]. The single-vector implementation returns values in `[0, 1]` [S1, unofficial], while the batched implementation returns values in `[-1, 1]` [S2, unofficial].

**Data Structures:**
- Input vectors are standard 3D floats.
- Output coordinates are 2D floats.

**Steps:**
1. Calculate intermediate UV components using spherical coordinate conversion:
   $$ u_{\text{raw}} = \operatorname{atan2}(v_z, -v_x) $$
   $$ v_{\text{raw}} = \operatorname{asin}(v_y) $$
   [S1, unofficial]
2. Scale the coordinates to map the range of `atan2` and `asin` to `[0, 1]`:
   $$ u = u_{\text{raw}} \times 0.1591 $$
   $$ v = v_{\text{raw}} \times 0.3183 $$
   [S1, unofficial]
   Note: $0.1591 \approx \frac{1}{2\pi}$ and $0.3183 \approx \frac{1}{\pi}$.
3. Offset the coordinates to center them:
   $$ u = u + 0.5 $$
   $$ v = v + 0.5 $$
   [S1, unofficial]
4. Flip the coordinates to match standard texture coordinate systems (where Y is often inverted):
   $$ u_{\text{final}} = 1 - u $$
   $$ v_{\text{final}} = 1 - v $$
   [S1, unofficial]

**Pseudocode:**
```python
import math

def spherical_background_sampling(v):
    """
    Converts a 3D direction vector to 2D UV coordinates for environment map sampling.
    
    Args:
        v: tuple or list of 3 floats (x, y, z) representing the direction vector.
        
    Returns:
        tuple: (u, v) coordinates in range [0, 1].
    """
    x, y, z = v
    
    # Step 1: Calculate raw UV components
    u_raw = math.atan2(z, -x)
    v_raw = math.asin(y)
    
    # Step 2: Scale
    u = u_raw * 0.1591
    v = v_raw * 0.3183
    
    # Step 3: Offset
    u = u + 0.5
    v = v + 0.5
    
    # Step 4: Flip
    u_final = 1.0 - u
    v_final = 1.0 - v
    
    return (u_final, v_final)
```

**Edge Cases and Pitfalls:**
- The input vector `v` must be normalized to ensure `|v_y| \le 1` for the `asin` function [G].
- The method assumes the ray origin is inside the background sphere [S2, unofficial].

## Subtopics

### Random Hemisphere Sampling
- **What it is:** Generates random directions within a hemisphere.
- **Difference:** Produces stochastic directions, whereas Spherical Background Sampling is deterministic.
- **When to choose:** When sampling light sources or reflections within a hemisphere.
- **Link:** [Random Hemisphere Sampling](2034-random-hemisphere-sampling.md)

### Rejection Sampling for Uniform Sphere Sampling
- **What it is:** A method to generate uniform random directions on a sphere using rejection sampling.
- **Difference:** Stochastic generation vs. deterministic mapping.
- **When to choose:** When random directions are needed, not mapping existing ones.
- **Link:** [Rejection Sampling for Uniform Sphere Sampling](3286-rejection-sampling-for-uniform-sphere-sampling.md)

## Operating characteristics
- **Time Complexity:** $O(1)$ per ray [S1, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Performance:** Very fast, suitable for real-time rendering [S1, unofficial].
- **Strengths:** Simple, deterministic, easy to implement [S1, unofficial].
- **Limitations:** Only works for background sampling assuming inside-sphere origins [S2, unofficial]. Not suitable for generating random directions [G].
