# Thin Lens Depth of Field

Also called: Concentric Disk Sampling for DOF, Depth of Field, Thin Lens Camera

## Overview
A camera model implementing depth of field (DOF) using a thin lens approximation with concentric disk sampling for the aperture [S1, S2, unofficial]. Unlike a pinhole camera where all rays originate from a single point, this model uses a finite aperture lens where objects at the focal distance are sharp and others are blurry (bokeh) [S2, unofficial]. It sets itself apart from sibling effects like [Lens Shift](1851-lens-shift.md) by simulating optical blur rather than geometric perspective distortion.

## How it works
**Inputs:**
- `position`: Camera position (pinhole location).
- `ray_dir`: The base ray direction from the pinhole camera model.
- `aperture`: Lens diameter (float). Larger values produce more blur [S2, unofficial].
- `focus_distance`: Distance to the focal plane (float) [S2, unofficial].
- `right`, `up`: Orthogonal basis vectors defining the lens plane orientation.
- `random_in_unit_disk()`: A function returning a uniformly distributed 2D vector inside the unit circle [S1, S2, unofficial].

**Outputs:**
- `Ray`: A new ray with modified origin and direction.

**Data Structures:**
- `vec2`: 2D vector for disk coordinates.
- `vec3`: 3D vector for positions and directions.

**Steps:**
1. Sample a random point on the lens disk using concentric disk sampling [S1, S2, unofficial].
   $$ \text{disk} = \text{aperture} \times 0.5 \times \text{random\_in\_unit\_disk}() $$
2. Compute the new lens origin by offsetting the camera position along the lens plane [S2, unofficial]:
   $$ \text{lens\_origin} = \text{position} + \text{disk}.x \times \text{right} + \text{disk}.y \times \text{up} $$
3. Compute the focus point on the focal plane [S2, unofficial]:
   $$ \text{focus\_point} = \text{position} + \text{focus\_distance} \times \text{normalize}(\text{ray\_dir}) $$
4. Compute the new ray direction pointing from the lens origin to the focus point [S2, unofficial]:
   $$ \text{direction} = \text{normalize}(\text{focus\_point} - \text{lens\_origin}) $$
5. Return the ray:
   $$ \text{Ray}(\text{lens\_origin}, \text{direction}) $$

**Pseudocode:**
```python
def thin_lens_dof_ray(position, ray_dir, aperture, focus_distance, right, up):
    # Step 1: Sample aperture using concentric disk sampling
    # random_in_unit_disk() returns a vec2 (u, v) such that u^2 + v^2 <= 1
    disk_uv = random_in_unit_disk()
    disk = vec2(aperture * 0.5 * disk_uv.x, aperture * 0.5 * disk_uv.y)
    
    # Step 2: Compute new lens origin
    lens_origin = position + vec3(disk.x, 0, 0) * right + vec3(0, disk.y, 0) * up
    
    # Step 3: Compute focus point
    # Note: ray_dir should be normalized before this step if not already
    normalized_ray_dir = normalize(ray_dir)
    focus_point = position + focus_distance * normalized_ray_dir
    
    # Step 4: Compute new direction
    direction = normalize(focus_point - lens_origin)
    
    # Step 5: Return ray
    return Ray(lens_origin, direction)
```

**Parameters:**
- `aperture`: Lens diameter. Typical values depend on the desired depth of field intensity. Not given in the sources.
- `focus_distance`: Distance to the focal plane. Must be positive.

**Edge Cases and Pitfalls:**
- If `aperture` is 0, the model degenerates to a pinhole camera.
- If `focus_distance` is 0 or negative, the focus point is invalid or behind the camera.
- Precision issues may arise if `aperture` is very large relative to `focus_distance`, causing extreme blur or numerical instability in normalization.
- The `right` and `up` vectors must be orthogonal to each other and to the view direction for correct lens plane alignment.

## Operating characteristics
- **Time Complexity:** $O(1)$ per ray, assuming `random_in_unit_disk()` is $O(1)$.
- **Memory Complexity:** $O(1)$ additional memory per ray.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Performance scales linearly with the number of rays. Blur intensity is controlled by `aperture`, not by resolution.
- **Strengths:** Simple to implement; produces realistic depth of field blur; works with any scene geometry.
- **Limitations:** Requires additional samples per pixel for noise reduction; does not simulate lens aberrations or vignetting.
- **When to use:** When realistic depth of field is desired in a path tracer or ray tracer.
- **When not to use:** When performance is critical and DOF is not needed; when specific lens artifacts (like anamorphic streaks) are required.

## Background
The thin lens model is a standard approximation in computer graphics for simulating depth of field [S1, S2, unofficial]. It originates from optical physics, where a thin lens focuses light from a plane at the focal distance to a point on the image plane. The use of concentric disk sampling for aperture sampling is a common technique to ensure uniform distribution of samples within the circular aperture, reducing variance in the rendered image [S1, S2, unofficial]. This method is widely used in path tracers and ray tracers for realistic image synthesis.
