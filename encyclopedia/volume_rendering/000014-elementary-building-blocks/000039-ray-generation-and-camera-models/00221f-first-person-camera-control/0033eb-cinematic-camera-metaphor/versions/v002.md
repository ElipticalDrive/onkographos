# Cinematic Camera Metaphor

Also called: Eyeball-in-Hand Metaphor, Flying Vehicle Metaphor, StyleCam, Unicam, cinematic camera

## Overview
The Cinematic Camera Metaphor is a navigation technique for non-immersive 3D environments where user input manipulates the position and orientation of a virtual camera to control the viewpoint [S1, unofficial]. It enables users to "tumble, track, and dolly" the view, allowing for precise framing of the scene [S1, unofficial]. It is distinguished from direct manipulation metaphors (like Scene-in-Hand) by treating the camera as an independent entity controlled via standard input devices, often requiring modifier keys or specific gestures to invoke different camera motions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Mouse movements, modifier keys, or 6DoF input device position/orientation.
*   **Output:** Updated virtual camera position and orientation (view matrix) applied to the rendering pipeline.

**Data Structures:**
*   `CameraState`: Struct containing `position` (vec3), `orientation` (quat or euler angles), and `projection_params` (fov, aspect ratio).
*   `InputEvent`: Struct containing `delta_position` (vec2 or vec3), `button_state` (bool), and `modifier_keys` (bitmask).

**Steps:**
1.  **Initialize:** Set `CameraState` to initial view.
2.  **Read Input:** Capture `InputEvent` from mouse or 6DoF device.
3.  **Map Input to Motion:**
    *   If using mouse + keys: Map specific key combinations to tumble (rotation), track (pan), or dolly (zoom) operations [S1, unofficial].
    *   If using 6DoF device:
        *   *Eyeball-in-Hand:* Map device position directly to camera position. Use absolute mapping for continuous control or relative mapping where movement only occurs when a button is depressed [S1, unofficial].
        *   *Flying Vehicle:* Map device input to spatial and angular velocity of the camera vehicle [S1, unofficial].
4.  **Update Camera:** Apply the calculated transformation to `CameraState`.
5.  **Render:** Use updated `CameraState` to generate the view matrix for ray generation.

**Parameters:**
*   **Mapping Mode:** Absolute or Relative. Relative mapping requires a button press to activate movement [S1, unofficial].
*   **Gestures:** Specific mouse movements or button sequences can invoke predefined camera paths or positions (e.g., StyleCam) [S1, unofficial].

**Pitfalls:**
*   **Relative Mapping Confusion:** Using relative mapping for eyeball-in-hand navigation can destroy the user's mental model of a fixed, invisible scene, leading to confusion [S1, unofficial].
*   **Complexity:** Managing multiple modifier keys and gestures can have a steep learning curve [S1, unofficial].

**Pseudocode:**
```python
def update_cinematic_camera(camera: CameraState, input: InputEvent) -> CameraState:
    """
    Updates the camera state based on input using the Cinematic Camera Metaphor.
    """
    if input.device_type == "MOUSE":
        # Mouse + Modifier Keys
        if input.modifier_keys & KEY_TUMBLE:
            camera.orientation.rotate_yaw_pitch(input.delta_position.x, input.delta_position.y)
        elif input.modifier_keys & KEY_TRACK:
            camera.position.pan(input.delta_position.x, input.delta_position.y)
        elif input.modifier_keys & KEY_DOLLY:
            camera.position.move_along_view_axis(input.delta_position.y)
        # Unicam: Single button + gestures logic would be implemented here
        # e.g., if input.button_pressed:
        #     camera.position = apply_gesture(input.gesture, camera.position)
            
    elif input.device_type == "6DOF":
        # Eyeball-in-Hand or Flying Vehicle
        if input.relative_mode:
            # Relative mapping: only move when button is depressed
            if input.button_pressed:
                camera.position += input.delta_position
                camera.orientation.rotate(input.delta_orientation)
        else:
            # Absolute mapping: direct position mapping
            camera.position = input.device_position
            camera.orientation = input.device_orientation
            
        # Flying Vehicle: Control velocity
        # camera.position += input.velocity * dt
        # camera.orientation.rotate(input.angular_velocity * dt)
        
    return camera
```

## Subtopics

### Eyeball-in-Hand Metaphor
A variant where the input device's position is directly mapped to the virtual camera's position. It supports absolute mapping (continuous control) or relative mapping (movement only when a button is depressed). Absolute mapping is preferred to maintain the user's mental model of a fixed scene; relative mapping can cause confusion [S1, unofficial]. Example: Chameleon display device [S1, unofficial].

### Flying Vehicle Metaphor
The scene is perceived from the position and orientation of a virtual vehicle. The input device controls the spatial and angular velocity of this vehicle, allowing it to move through the scene. Commonly used in 3D games where the "player position" is the vehicle. Enhancements include rapid and controlled movement techniques [S1, unofficial].

### Scene-in-Hand Metaphor
The 3D world moves in correspondence with the 6DoF input device. Rotating the device clockwise rotates the scene clockwise. Large movements can be achieved by ratcheting using a button as a clutch. Useful for hierarchical scenes. An extension, "World-in-Miniature," involves manipulating a hand-held miniature copy of the virtual environment [S1, unofficial].

## Operating characteristics
*   **Strengths:** Intuitive for users familiar with standard 2D mouse interactions; allows for precise control over framing and composition (tumble, track, dolly) [S1, unofficial].
*   **Limitations:** Can be less applicable for immersive 3D environments compared to other navigation tasks; relative mapping can break spatial awareness [S1, unofficial].
*   **Performance:** Low computational overhead; primarily involves updating camera matrices based on input [S1, unofficial].
*   **Usage:** Implemented in Unicam (mouse + single button + gestures) and StyleCam (tailored camera positions/paths) [S1, unofficial].

## Background
The Cinematic Camera Metaphor was introduced in the context of non-immersive 3D environments, such as 3D graphics and animation programs [S1, unofficial]. It is based on the concept of tumbling, tracking, and dollying a viewpoint, as described by Burtnyk et al. [S1, unofficial]. Variations using 6DoF input devices were explored by Ware and Osborne [S1, unofficial]. Specific implementations include Unicam by Zeleznik and Forsberg [S1, unofficial] and StyleCam by Burtnyk et al. [S1, unofficial]. The Eyeball-in-Hand and Scene-in-Hand metaphors were also discussed by Ware and Osborne [S1, unofficial], with the Chameleon device by Fitzmaurice [S1, unofficial] and World-in-Miniature by Stoakley et al. [S1, unofficial] serving as examples.
