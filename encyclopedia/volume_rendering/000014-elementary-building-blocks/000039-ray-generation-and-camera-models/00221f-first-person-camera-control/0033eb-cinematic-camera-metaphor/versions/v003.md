# Cinematic Camera Metaphor

Also called: Eyeball-in-Hand Metaphor, Flying Vehicle Metaphor, StyleCam, Unicam, cinematic camera

## Overview
The Cinematic Camera Metaphor is a navigation technique for non-immersive 3D environments where user input manipulates the position and orientation of a virtual camera to control the user's viewpoint [S1, unofficial]. It enables users to tumble, track, and dolly the view for precise scene framing [S1, unofficial]. It is distinguished from direct manipulation metaphors by treating the camera as an independent entity controlled via standard input devices, often requiring modifier keys or specific gestures to invoke different camera motions [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Mouse movements with modifier keys, or 6DoF input device position/orientation [S1, unofficial].
*   **Output:** Updated virtual camera position and orientation applied to the rendering pipeline [S1, unofficial].

**Data Structures:**
*   `CameraState`: Holds `position` (vec3), `orientation` (quat or euler angles), and `projection_params` (fov, aspect ratio) [G].
*   `InputEvent`: Holds `delta_position` (vec2/vec3), `button_state` (bool), `modifier_keys` (bitmask), and device pose data [G].

**Steps:**
1.  **Initialize:** Set `CameraState` to an initial view [G].
2.  **Read Input:** Capture `InputEvent` from mouse or 6DoF device [G].
3.  **Map Input to Motion:**
    *   If using mouse + keys: Map specific key combinations to tumble (rotation), track (pan), or dolly (zoom) operations [S1, unofficial].
    *   If using 6DoF device: Map device position directly to camera position for Eyeball-in-Hand, or map input to spatial/angular velocity for Flying Vehicle [S1, unofficial].
4.  **Update Camera:** Apply the calculated transformation to `CameraState` [G].
5.  **Render:** Use updated `CameraState` to generate the view matrix for ray generation [G].

**Parameters:**
*   **Mapping Mode:** Absolute or Relative. Relative mapping requires a button press to activate movement [S1, unofficial].
*   **Gestures:** Specific mouse movements or button sequences can invoke predefined camera paths or positions (e.g., StyleCam) [S1, unofficial].

**Pitfalls:**
*   **Relative Mapping Confusion:** Using relative mapping for eyeball-in-hand navigation can destroy the user's mental model of a fixed, invisible scene, leading to confusion [S1, unofficial].

**Pseudocode:**
```python
KEY_TUMBLE = 0x01
KEY_TRACK = 0x02
KEY_DOLLY = 0x04

def update_cinematic_camera(camera: dict, input_event: dict) -> dict:
    """
    Updates the camera state based on input using the Cinematic Camera Metaphor.
    camera: dict with 'position' (list[float]), 'orientation' (list[float]), 'projection_params' (dict)
    input_event: dict with 'device_type' (str), 'delta_position' (list[float]), 'button_pressed' (bool),
                 'modifier_keys' (int), 'device_position' (list[float]), 'device_orientation' (list[float])
    """
    if input_event["device_type"] == "MOUSE":
        if input_event["modifier_keys"] & KEY_TUMBLE:
            camera["orientation"][0] += input_event["delta_position"][0]
            camera["orientation"][1] += input_event["delta_position"][1]
        elif input_event["modifier_keys"] & KEY_TRACK:
            camera["position"][0] += input_event["delta_position"][0]
            camera["position"][1] += input_event["delta_position"][1]
        elif input_event["modifier_keys"] & KEY_DOLLY:
            camera["position"][2] += input_event["delta_position"][1]
    elif input_event["device_type"] == "6DOF":
        if input_event.get("relative_mode", False):
            if input_event["button_pressed"]:
                camera["position"] = [camera["position"][i] + input_event["delta_position"][i] for i in range(3)]
                camera["orientation"] = [camera["orientation"][i] + input_event.get("delta_orientation", [0,0,0])[i] for i in range(3)]
        else:
            camera["position"] = input_event["device_position"]
            camera["orientation"] = input_event["device_orientation"]
    return camera
```

## Subtopics

### Eyeball-in-Hand Metaphor
A variant where the input device's position is directly mapped to the virtual camera's position [S1, unofficial]. It supports absolute mapping (continuous control) or relative mapping (movement only when a button is depressed) [S1, unofficial]. Absolute mapping is preferred to maintain the user's mental model of a fixed scene; relative mapping can cause confusion [S1, unofficial]. Example: Chameleon display device [S1, unofficial].

### Flying Vehicle Metaphor
The scene is perceived from the position and orientation of a virtual vehicle [S1, unofficial]. The input device controls the spatial and angular velocity of this vehicle, allowing it to move through the scene [S1, unofficial]. Commonly used in 3D games where the "player position" is the vehicle [S1, unofficial]. Enhancements include rapid and controlled movement techniques [S1, unofficial].

### Scene-in-Hand Metaphor
The 3D world moves in correspondence with the 6DoF input device [S1, unofficial]. Rotating the device clockwise rotates the scene clockwise [S1, unofficial]. Large movements can be achieved by ratcheting using a button as a clutch [S1, unofficial]. Useful for hierarchical scenes [S1, unofficial]. An extension, "World-in-Miniature," involves manipulating a hand-held miniature copy of the virtual environment [S1, unofficial].

## Operating characteristics
*   **Strengths:** Intuitive for users familiar with standard 2D mouse interactions; allows for precise control over framing and composition (tumble, track, dolly) [S1, unofficial].
*   **Limitations:** Can be less applicable for immersive 3D environments compared to other navigation tasks; relative mapping can break spatial awareness [S1, unofficial].
*   **Usage:** Implemented in Unicam (mouse + single button + gestures) and StyleCam (tailored camera positions/paths) [S1, unofficial].

## Background
The Cinematic Camera Metaphor was introduced in the context of non-immersive 3D environments, such as 3D graphics and animation programs [S1, unofficial]. It is based on the concept of tumbling, tracking, and dollying a viewpoint, as described by Burtnyk et al. [S1, unofficial]. Variations using 6DoF input devices were explored by Ware and Osborne [S1, unofficial]. Specific implementations include Unicam by Zeleznik and Forsberg [S1, unofficial] and StyleCam by Burtnyk et al. [S1, unofficial]. The Eyeball-in-Hand and Scene-in-Hand metaphors were also discussed by Ware and Osborne [S1, unofficial], with the Chameleon device by Fitzmaurice [S1, unofficial] and World-in-Miniature by Stoakley et al. [S1, unofficial] serving as examples.
