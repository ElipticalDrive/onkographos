# Depth Estimation from Point Cloud
Also called: Closest Point Depth Estimation
## Overview
This method generates a depth map for a novel viewpoint by projecting a pre-existing 3D point cloud onto the 2D image plane. It solves the problem of converting sparse or generated geometric data into a dense per-pixel depth representation. It differs from [Perspective Projection of Points](4037-perspective-projection-of-points.md) by explicitly resolving occlusion via a "closest point" selection rule to handle multiple points projecting to the same pixel, and from [Triangulation for Closest Point](9933-triangulation-for-closest-point.md) by operating on a static point cloud rather than optimizing for 3D positions from multi-view rays.
## How it works
**Inputs:**
- A 3D point cloud $P = \{p_1, p_2, \dots, p_N\}$, where each $p_i \in \mathbb{R}^3$ represents a point in world or camera coordinates.
- A camera model for the novel viewpoint, defined by intrinsic matrix $K$ and extrinsic matrix $[R|t]$ (rotation and translation), mapping world coordinates to camera coordinates.
- Image dimensions $W \times H$.

**Outputs:**
- A depth image $D \in \mathbb{R}^{H \times W}$, where $D(u, v)$ is the distance from the camera center to the closest surface point at pixel $(u, v)$.

**Data Structures:**
- Depth image $D$: Initialized to zero or a maximum depth value (indicating no data).
- Point cloud $P$: List or array of 3D coordinates.

**Steps:**
1. **Coordinate Transformation:** For each point $p_i \in P$, transform it into the camera coordinate system of the novel viewpoint:
   $$
   p'_i = R p_i + t
   $$
   where $p'_i = [X'_i, Y'_i, Z'_i]^T$.

2. **Projection:** Project the transformed point $p'_i$ onto the 2D image plane using the intrinsic matrix $K$:
   $$
   \begin{bmatrix} u_i \\ v_i \\ w_i \end{bmatrix} = K p'_i
   $$
   The normalized image coordinates are $x_i = u_i / w_i$ and $y_i = v_i / w_i$. The pixel coordinates are:
   $$
   u = \text{round}(x_i), \quad v = \text{round}(y_i)
   $$
   Only points with $w_i > 0$ (in front of the camera) and $0 \le u < W, 0 \le v < H$ are considered valid.

3. **Closest Point Selection:** For each pixel $(u, v)$, if multiple points project to it, select the point with the smallest depth value $Z'_i$ (distance from the camera center along the optical axis).
   $$
   D(u, v) = \min \{ Z'_i \mid p_i \text{ projects to } (u, v) \}
   $$
   If no points project to $(u, v)$, $D(u, v)$ remains undefined (e.g., zero or background marker).

**Pseudocode:**
```python
def estimate_depth_from_point_cloud(point_cloud, K, R, t, width, height):
    """
    point_cloud: list of (x, y, z) tuples
    K: 3x3 intrinsic matrix
    R: 3x3 rotation matrix
    t: 3x1 translation vector
    width, height: image dimensions
    """
    # Initialize depth map with zeros (indicating no data)
    depth_map = [[0.0 for _ in range(width)] for _ in range(height)]
    
    # Pre-allocate for efficiency if needed, but here we iterate points
    # To handle "closest point", we can store current min depth per pixel
    # Initialize with infinity
    min_depth_map = [[float('inf') for _ in range(width)] for _ in range(height)]
    
    for p in point_cloud:
        # 1. Transform to camera coordinates
        # p is (x, y, z)
        # p_cam = R * p + t
        p_cam_x = R[0][0]*p[0] + R[0][1]*p[1] + R[0][2]*p[2] + t[0]
        p_cam_y = R[1][0]*p[0] + R[1][1]*p[1] + R[1][2]*p[2] + t[1]
        p_cam_z = R[2][0]*p[0] + R[2][1]*p[1] + R[2][2]*p[2] + t[2]
        
        # Check if in front of camera
        if p_cam_z <= 0:
            continue
            
        # 2. Project to 2D
        # [u, v, w] = K * p_cam
        u_float = K[0][0]*p_cam_x + K[0][1]*p_cam_y + K[0][2]*p_cam_z
        v_float = K[1][0]*p_cam_x + K[1][1]*p_cam_y + K[1][2]*p_cam_z
        w = K[2][0]*p_cam_x + K[2][1]*p_cam_y + K[2][2]*p_cam_z
        
        if w == 0:
            continue
            
        u_norm = u_float / w
        v_norm = v_float / w
        
        u = int(round(u_norm))
        v = int(round(v_norm))
        
        # Check bounds
        if 0 <= u < width and 0 <= v < height:
            # 3. Closest point selection
            if p_cam_z < min_depth_map[v][u]:
                min_depth_map[v][u] = p_cam_z
                
    # Convert infinity to 0 or keep as is depending on convention
    for v in range(height):
        for u in range(width):
            if min_depth_map[v][u] == float('inf'):
                depth_map[v][u] = 0.0
            else:
                depth_map[v][u] = min_depth_map[v][u]
                
    return depth_map
```

**Edge Cases and Pitfalls:**
- **Holes:** Pixels with no corresponding 3D points result in zero or undefined values. The source notes that these holes may represent background or missing surface data, requiring post-processing (e.g., inpainting) if a complete depth map is needed [S1].
- **Precision:** Rounding pixel coordinates may cause jitter if points are very close to pixel boundaries.
- **Occlusion:** The "closest point" rule assumes the closest point is visible. In complex scenes with self-occlusion not resolved by the point cloud generation, this may produce incorrect depth values.

## Subtopics

### [Triangulation for Closest Point](9933-triangulation-for-closest-point.md)
Computes 3D positions from multi-view rays using least-squares optimization with visibility masks. Choose when point cloud is not available but multi-view 2D tracks are.

### [Dense Depth Estimation via Plane Sweep](10850-dense-depth-estimation-via-plane-sweep.md)
Sweeps virtual planes to evaluate photometric consistency. Choose for uncalibrated views or when dense photometric consistency is preferred over geometric point projection.

## Operating characteristics
- **Time Complexity:** $O(N)$ for projecting $N$ points, plus $O(W \times H)$ for initializing and finalizing the depth map.
- **Memory Complexity:** $O(W \times H)$ for the depth map.
- **Performance:** Fast and simple, suitable for real-time applications if the point cloud is pre-computed.
- **Limitations:** Produces sparse depth maps if the point cloud is sparse. Cannot infer depth in regions without points without additional processing.

## Background
This method is used in neural radiance field (NeRF) improvements and multi-view stereo (MVS) pipelines. It is cited in [S1] as a step in generating depth images from point clouds for novel viewpoints, comparing its PSNR performance against standard MVS methods.
