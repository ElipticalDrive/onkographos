# Binocular Depth Estimation (Stereo Matching)
Also called: Disparity computation, Stereo depth

## Overview
Binocular depth estimation estimates the depth of a scene by analyzing the geometric correspondence between a pair of images (typically left and right) captured from slightly different viewpoints. It solves the problem of recovering 3D structure from 2D imagery by computing a disparity map, which is then converted to depth. Unlike monocular depth estimation, which relies on learned priors from a single image, this method leverages explicit geometric constraints (epipolar geometry) to provide metrically consistent depth estimates [S1]. It serves as a foundational step for dense depth estimation and 3D reconstruction, often feeding into subsequent volume rendering or plane-sweep algorithms.

## How it works
The modern deep learning-based pipeline for binocular depth estimation consists of four sequential stages: feature extraction, cost volume construction, cost aggregation, and disparity computation [S1].

**Inputs and Outputs:**
*   **Inputs:** A pair of rectified images, $I_l$ (left) and $I_r$ (right), of size $H \times W \times 3$.
*   **Outputs:** A disparity map $d$ of size $H \times W$, where each pixel value represents the horizontal shift between corresponding points in the left and right images.

**Data Structures:**
1.  **Feature Maps:** Intermediate representations extracted from input images.
2.  **Cost Volume:** A 4D tensor storing matching costs. For a given pixel $(u, v)$ in the left image and a candidate disparity $k$, the cost is stored at $C(u, v, k)$. The dimensions are typically $H \times W \times D_{max} \times C_{feat}$, where $D_{max}$ is the maximum disparity and $C_{feat}$ is the feature dimension.
3.  **Disparity Map:** A 2D tensor $d \in \mathbb{R}^{H \times W}$.

**Steps:**

1.  **Feature Extraction ($f_\theta$):**
    A shared-weight convolutional neural network extracts features from both input images.
    $$ F_l = f_\theta(I_l) $$
    $$ F_r = f_\theta(I_r) $$
    Here, $f_\theta$ is a feature extraction network parameterized by $\theta$. The output features $F_l, F_r$ are typically multi-scale feature maps.

2.  **Cost Volume Construction ($\partial$):**
    Matching costs are computed between features from the left and right images across a range of possible disparities.
    $$ C = \partial(F_l, F_r) $$
    The cost volume $C$ aggregates similarity metrics (e.g., correlation, absolute difference) for all pixels and all candidate disparities. This results in a 4D tensor.

3.  **Cost Aggregation ($\delta$):**
    The raw cost volume is often noisy. A cost aggregation network refines the costs by incorporating contextual information from neighboring pixels and disparities.
    $$ C' = \delta(C) $$
    This step typically uses 3D convolutions or recurrent neural networks to propagate reliable matching cues while suppressing outliers.

4.  **Disparity Computation ($\eta$):**
    The final disparity map is estimated from the aggregated cost volume. This is often done via a differentiable soft-argmin operation or a regression head.
    $$ d = \eta(C') $$
    The disparity $d(u,v)$ corresponds to the disparity index with the lowest cost (or highest similarity) in the cost volume.

**Formula:**
The entire process can be represented as a composition of these functions [S1]:
$$ d = \eta(\delta(\partial(f_\theta(I_l), f_\theta(I_r)))) $$

**Parameters:**
*   **Maximum Disparity ($D_{max}$):** Determines the range of depths covered. Typical values depend on the baseline and scene depth; e.g., 192 or 384 pixels in standard datasets.
*   **Network Weights ($\theta$):** Learned parameters of the feature extraction and aggregation networks. Representative architectures include CFNet [47] and PCWNet [48] [S1].

**Edge Cases and Pitfalls:**
*   **Occlusions:** Regions visible in one image but not the other lead to ambiguous matches. Standard stereo matching may produce incorrect disparities in occluded areas.
*   **Textureless Regions:** Areas with uniform color or lack of high-frequency features provide weak matching cues, leading to noisy cost volumes.
*   **Rectification Errors:** The method assumes images are rectified (epipolar lines are horizontal). Misalignment causes significant errors.
*   **Precision:** Disparity is often computed at sub-pixel precision using soft-argmin, but quantization errors can occur if the disparity range is coarse.

## Subtopics

### MASt3R Feature Integration
MASt3R is a state-of-the-art 3D foundation model that learns to establish correspondences in feature space between pairs of images of the same scene [S2, unofficial]. It takes two input images $I_i, I_j$ and predicts a dense pointmap and stereo feature image for each:
$$ F_{ij}, F_{ji} = F_{MASt3R}(I_i, I_j) $$
where $F \in \mathbb{R}^{H \times W \times 24}$ [S2, unofficial]. These features enrich the cost volume (4D tensors storing matching costs) used in subsequent depth estimation, making the predicted depth and mesh reconstruction more accurate compared to using only monocular features like DINOv2 [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the convolutional operations in the feature extraction and cost aggregation stages. With modern GPU acceleration, inference can be real-time for moderate resolutions.
*   **Memory Complexity:** The cost volume is the primary memory consumer, scaling as $O(H \times W \times D_{max})$. For high-resolution images and large disparity ranges, this can be substantial.
*   **Strengths:** Provides metrically consistent depth; robust to lighting changes compared to photometric methods; leverages geometric constraints.
*   **Limitations:** Requires rectified stereo pairs; struggles with textureless regions and occlusions; performance degrades with large baselines due to occlusion and resolution loss.
*   **When to use:** When metric depth accuracy is required and stereo pairs are available.
*   **When not to use:** For monocular video streams without stereo pairs; in scenes with significant occlusions where ground truth is unavailable for training.

## Background
Binocular depth estimation has been a core problem in computer vision for decades. Traditional methods relied on hand-crafted features and optimization techniques (e.g., semi-global matching). Recent advances have shifted towards deep learning, where end-to-end networks learn to extract features and aggregate costs. The pipeline described above, involving feature extraction, cost volume construction, aggregation, and disparity computation, is the standard architecture for current deep stereo matching methods [S1]. Representative networks include CFNet and PCWNet [S1]. The integration of foundation models like MASt3R represents a recent development in enhancing feature quality for 3D reconstruction tasks [S2, unofficial].
