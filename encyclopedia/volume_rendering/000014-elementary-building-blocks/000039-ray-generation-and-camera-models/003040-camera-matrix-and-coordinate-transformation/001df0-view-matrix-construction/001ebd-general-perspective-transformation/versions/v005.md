# General Perspective Transformation

Also called: Eye-to-screen transformation, Perspective Transformation with Eye and Projection Plane Off-Origin

## Overview
A perspective transformation where both the eye and the projection plane may be positioned away from the world origin [S1]. It solves the problem of maintaining numerical stability in screen-z values by ensuring the Jacobian is the identity at the center of the visibility bounding box (Vbb) [S1]. Unlike standard perspective projections that fix the eye at the origin, this method allows arbitrary translation along the viewing axis, which is critical for preventing floating-point errors when compositing thousands of closely spaced triangles far from the origin [S1].

## How it works
**Inputs:**
- Eye offset parameter $e_o$: The distance from the projection plane to the eye along the viewing axis [S1].
- Translation parameter $z_t$: The user-specified translation in the z-direction [S1].
- Visibility Bounding Box (Vbb): The 3D region containing the geometry to be rendered [S1].

**Outputs:**
- Transformed coordinates in screen space.
- A projection matrix or transformation logic that maps 3D view-space to 2D screen space with correct depth buffering [S1][S2, unofficial].

**Data Structures:**
- Standard 4x4 homogeneous transformation matrix or equivalent projection logic. The specific matrix elements are derived from the geometric setup described below.

**Steps:**
1. **Define the Geometric Basis:** Establish a coordinate system where the eye is not at the origin. The eye point is located at $(0, 0, e_o - z_t)$ and the projection plane is defined by $z = -z_t$ [S1].
2. **Apply Translation:** The user-specified translation $z_t$ effectively moves both the eye and the projection plane relative to the world origin [S1]. This translation ensures that the center of the Vbb is appropriately positioned relative to the projection plane.
3. **Compute Projection:** Project 3D points onto the plane $z = -z_t$ using the eye at $(0, 0, e_o - z_t)$. The projection preserves the property that objects in the background take up less screen space than foreground objects of the same size [S2, unofficial].
4. **Handle Clipping:** Define the view frustum using six clipping planes: $fleft, fright, fdown, fup, fnear, ffar$ [S2, unofficial]. Geometry outside this truncated pyramid is discarded [S2, unofficial].

**Formulas:**
- Eye Position: $E = (0, 0, e_o - z_t)$ [S1].
- Projection Plane: $z = -z_t$ [S1].
- Jacobian Identity: The Jacobian of the transformation is the identity at the center of the Vbb, minimizing relative errors in screen-z [S1].

**Parameters:**
- $e_o$: Eye offset. Not given in the sources.
- $z_t$: Translation parameter. Not given in the sources.
- $fleft, fright, fdown, fup, fnear, ffar$: Clipping plane boundaries. Typical values depend on the scene scale and required depth precision [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Numerical Precision:** Standard perspective transformations with the eye at the origin can cause floating-point errors in screen-z values when vertices are far from the origin, leading to z-fighting or ordering inconsistencies during compositing [S1]. This method mitigates that by shifting the eye and plane.
- **Degenerate Input:** If the eye and projection plane are coincident ($e_o - z_t = -z_t \implies e_o = 0$), the projection is undefined.

**Pseudocode:**
```python
def general_perspective_transform(point, e_o, z_t):
    """
    Projects a 3D point using a general perspective transformation
    where the eye and projection plane are offset from the origin.
    
    Args:
        point: (x, y, z) tuple representing the 3D vertex.
        e_o: Eye offset parameter.
        z_t: Translation parameter.
        
    Returns:
        (x_screen, y_screen, z_depth) tuple.
    """
    # Eye position
    eye_z = e_o - z_t
    # Projection plane z-coordinate
    plane_z = -z_t
    
    # Vector from eye to point
    dx = point[0] - 0
    dy = point[1] - 0
    dz = point[2] - eye_z
    
    # Check for division by zero (point at eye)
    if dz == 0:
        return None
        
    # Project onto the plane z = plane_z
    # The projection factor is determined by the ratio of distances
    # Distance from eye to plane: plane_z - eye_z
    # Distance from eye to point: dz
    # Note: In standard perspective, screen coords are proportional to 
    # (point - eye) / (depth). Here, we map to the specific plane.
    
    # Calculate the scaling factor to project onto plane_z
    # Using similar triangles: scale = (plane_z - eye_z) / dz
    scale = (plane_z - eye_z) / dz
    
    x_screen = dx * scale
    y_screen = dy * scale
    
    # Depth for z-buffering (normalized or raw, depending on pipeline)
    # Raw depth relative to eye
    z_depth = dz
    
    return (x_screen, y_screen, z_depth)

def apply_clipping(point, fleft, fright, fdown, fup, fnear, ffar):
    """
    Checks if a point is within the view frustum defined by clipping planes.
    """
    if point[0] < fleft or point[0] > fright:
        return False
    if point[1] < fdown or point[1] > fup:
        return False
    if point[2] < fnear or point[2] > ffar:
        return False
    return True
```

## Subtopics

### [Numerically Stable Perspective Transformation](2008-numerically-stable-perspective-transformation.md)
This method prevents floating-point errors in screen-z values that occur when translating vertices far from the origin in standard perspective projections, which otherwise cause ordering inconsistencies during the compositing of thousands of closely spaced triangles. It differs from standard perspective transformations by positioning the eye away from the world origin, thereby establishing a geometric basis where relative errors are minimized without requiring double-precision arithmetic. See [Numerically Stable Perspective Transformation](2008-numerically-stable-perspective-transformation.md).

It solves the problem of mapping 3D view-space coordinates to 2D screen space by combining field-of-view (FOV) parameters with viewport dimensions, differing from fixed-function pipeline setups by allowing tangent-based FOV parameter management and explicit coordinate system conversions. It builds on [General Perspective Transformation](1845-general-perspective-transformation.md) by providing the specific matrix assembly logic used in modern splat renderers. ## Operating characteristics
- **Time Complexity:** $O(1)$ per vertex for the transformation.
- **Memory Complexity:** $O(1)$ auxiliary memory for the transformation parameters.
- **Performance:** Improves rendering stability for large scenes by reducing z-fighting caused by precision loss [S1].
- **Strengths:** Eliminates the need for double-precision arithmetic in scenarios where geometry is far from the origin [S1].
- **Limitations:** Requires careful calculation of $e_o$ and $z_t$ to ensure the Vbb is properly centered relative to the projection plane [S1].
- **When to Use:** When rendering large-scale scenes with geometry far from the world origin, or when compositing many thin triangles where z-ordering is critical [S1].
- **When Not to Use:** For simple, small-scale scenes where standard perspective projection suffices and precision is not an issue.

## Background
The concept of moving the eye and projection plane away from the origin was introduced to address numerical stability issues in direct volume rendering for irregular and multiple grids [S1]. The method was developed in the context of hierarchical and parallelizable rendering techniques [S1]. The use of `glFrustum` for defining the view frustum is a standard OpenGL technique adopted in tools like Smokeview for visualizing fire dynamics simulation data [S2, unofficial].
