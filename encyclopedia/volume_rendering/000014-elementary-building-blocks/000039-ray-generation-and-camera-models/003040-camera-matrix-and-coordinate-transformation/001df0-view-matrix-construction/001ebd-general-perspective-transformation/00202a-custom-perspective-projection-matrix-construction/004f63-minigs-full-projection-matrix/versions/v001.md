# MiniGS Full Projection Matrix

Also called: MiniGS Projection Matrix

## Overview
The MiniGS Full Projection Matrix constructs a combined view-projection matrix that adheres to the specific rendering conventions of the MiniGS reference kernel. It solves the problem of transforming 3D camera-space coordinates into clip space for perspective projection, explicitly handling the frustum geometry and depth mapping. It differs from standard textbook projections by using an explicit frustum plane calculation followed by a matrix transpose before batched multiplication with the view matrix, ensuring compatibility with the specific memory layout and shader expectations of the MiniGS implementation [S1, unofficial].

## How it works
**Inputs:**
- `znear`: Float, camera near clipping plane distance.
- `zfar`: Float, camera far clipping plane distance.
- `FoVx`: Float, horizontal field of view in radians.
- `FoVy`: Float, vertical field of view in radians.
- `world_view_transform`: 4x4 matrix (or batch of matrices) representing the world-to-view transformation.

**Outputs:**
- `full_projection_matrix`: 4x4 float32 matrix (row-major), representing the combined view-projection transformation.

**Data Structures:**
- The projection matrix is a 4x4 array of 32-bit floats. The source code initializes it as a standard 4x4 tensor/matrix and applies a transpose operation at the end. The final matrix is row-major in memory after the transpose, consistent with the `bmm` (batched matrix multiply) operation used in the reference implementation [S1, unofficial].

**Steps:**
1.  Calculate the tangent of half the horizontal and vertical fields of view:
    $$ t_x = \tan\left(\frac{FoV_x}{2}\right) $$
    $$ t_y = \tan\left(\frac{FoV_y}{2}\right) $$
2.  Compute the frustum boundaries at the near plane:
    $$ right = znear \cdot t_x $$
    $$ left = -right $$
    $$ top = znear \cdot t_y $$
    $$ bottom = -top $$
3.  Initialize a 4x4 matrix $M$ with zeros.
4.  Set the specific elements of $M$ according to the MiniGS convention:
    $$ M_{0,0} = \frac{2 \cdot znear}{right - left} $$
    $$ M_{1,1} = \frac{2 \cdot znear}{top - bottom} $$
    $$ M_{0,2} = \frac{right + left}{right - left} $$
    $$ M_{1,2} = \frac{top + bottom}{top - bottom} $$
    $$ M_{3,2} = 1.0 $$
    $$ M_{2,2} = \frac{zfar + znear}{zfar - znear} $$
    $$ M_{2,3} = -\frac{zfar \cdot znear}{zfar - znear} $$
    *Note: All other elements remain 0.*
5.  Transpose the matrix $M$ to obtain the row-major layout required for the subsequent multiplication.
6.  Multiply the transposed projection matrix with the `world_view_transform` using batched matrix multiplication (`bmm`) to produce the final `full_projection_matrix`.

**Pseudocode:**
```python
import math
import numpy as np

def mini_gs_full_projection_matrix(znear, zfar, fov_x, fov_y, world_view_transform):
    """
    Constructs the MiniGS full projection matrix.
    
    Args:
        znear (float): Near clipping plane.
        zfar (float): Far clipping plane.
        fov_x (float): Horizontal field of view in radians.
        fov_y (float): Vertical field of view in radians.
        world_view_transform (np.ndarray): 4x4 matrix (or batch of 4x4 matrices).
        
    Returns:
        np.ndarray: The combined view-projection matrix.
    """
    # 1. Calculate tangents
    tan_half_fov_x = math.tan(fov_x * 0.5)
    tan_half_fov_y = math.tan(fov_y * 0.5)
    
    # 2. Calculate frustum boundaries
    right = znear * tan_half_fov_x
    left = -right
    top = znear * tan_half_fov_y
    bottom = -top
    
    # 3. Initialize 4x4 matrix
    # Using float32 as per source convention
    M = np.zeros((4, 4), dtype=np.float32)
    
    # 4. Set matrix elements
    # M[0,0]
    M[0, 0] = 2.0 * znear / (right - left)
    
    # M[1,1]
    M[1, 1] = 2.0 * znear / (top - bottom)
    
    # M[0,2]
    M[0, 2] = (right + left) / (right - left)
    
    # M[1,2]
    M[1, 2] = (top + bottom) / (top - bottom)
    
    # M[3,2]
    M[3, 2] = 1.0
    
    # M[2,2]
    M[2, 2] = (zfar + znear) / (zfar - znear)
    
    # M[2,3]
    M[2, 3] = -(zfar * znear) / (zfar - znear)
    
    # 5. Transpose the matrix
    # The source explicitly transposes the matrix before multiplication.
    # This converts it from the initialized layout to the expected row-major layout
    # for the subsequent bmm operation.
    M = M.T
    
    # 6. Multiply with world_view_transform
    # Assuming world_view_transform is 4x4 or (N, 4, 4)
    # numpy.matmul or @ operator handles broadcasting for batches
    full_projection_matrix = M @ world_view_transform
    
    return full_projection_matrix
```

**Parameters:**
- `znear`: Positive float. Typical values depend on scene scale, often $10^{-3}$ to $10^{-1}$ for normalized coordinates or larger for world units.
- `zfar`: Positive float, must be greater than `znear`.
- `FoVx`, `FoVy`: Floats in radians. Typical values range from $\pi/4$ to $\pi/2$ depending on the desired view angle.

**Edge Cases and Pitfalls:**
- **Radians vs Degrees:** The source code uses `math.tan` directly on the input angles. The documentation explicitly states that FoV values must be in radians. Passing degrees will result in incorrect projection geometry [S1, unofficial].
- **Matrix Transpose:** The matrix is explicitly transposed before multiplication. This is a critical implementation detail. Standard OpenGL/DirectX conventions often assume column-major storage or specific row/column interpretations. The MiniGS implementation requires this transpose to align with its internal `bmm` expectations [S1, unofficial].
- **Division by Zero:** If `right == left` or `top == bottom` (i.e., zero field of view), division by zero occurs. If `zfar == znear`, the depth mapping terms also divide by zero. These should be guarded against in production code [G].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ for matrix construction. The batched matrix multiplication is $O(N \cdot 4^3)$ for $N$ matrices, which is constant for a single view.
- Memory: $O(1)$ for the projection matrix (16 floats).

**Strengths and Limitations:**
- **Strengths:** Explicitly matches the MiniGS reference kernel, ensuring correct depth buffering and frustum culling in that specific pipeline.
- **Limitations:** The explicit transpose and specific element placement make it non-standard compared to generic graphics APIs (OpenGL/Vulkan/Metal). It is tightly coupled to the MiniGS architecture.

**When to use:**
- Use this method when implementing or debugging the MiniGS reference kernel or when interoperating with codebases that rely on the `XiaoBin2001/Improved-GS` implementation [S1, unofficial].
- Do not use for general-purpose rendering engines unless they explicitly require this matrix layout.

## Background
The MiniGS Full Projection Matrix originates from the "Improved-GS" project by XiaoBin2001, an unofficial implementation related to Gaussian Splatting rendering. It is designed to replace or augment standard projection matrices to fit the specific coordinate transformation and depth handling requirements of the MiniGS kernel [S1, unofficial].
