# Custom Perspective Projection Matrix Construction

Also called: 3D Projection Matrix Construction, Camera projection matrix setup, Canvas projection setup, Custom Perspective Projection Matrix, View matrix assembly, View matrix setup

## Overview
This method constructs the perspective projection matrix for 3D rendering, explicitly managing focal lengths and aspect ratios rather than relying on fixed-function pipeline defaults [S2, S3, unofficial]. It builds on [General Perspective Transformation](1845-general-perspective-transformation.md) by providing the specific matrix assembly logic for custom camera setups [G].

## How it works
**Inputs and Outputs:**
- Inputs: Horizontal and vertical focal lengths ($f_x, f_y$), viewport dimensions ($width, height$), and near/far clipping plane distances ($near, far$) [S2, S3, unofficial].
- Output: A $4 \times 4$ projection matrix $P$ [S2, unofficial].

**Data Structures:**
- The projection matrix is a $4 \times 4$ matrix of floating-point values [G].
- Standard element indexing $P_{i,j}$ corresponds to row $i$, column $j$ [G].

**Steps:**
1. **Calculate Matrix Elements:** Populate the projection matrix $P$ using the specified non-zero elements [S2, unofficial].
2. **Combine with View and Model Matrices:** Multiply the projection matrix $P$ by the view matrix $V$ and the model matrix $M$ to form the final transformation matrix: $MVP = P \times V \times M$ [S3, unofficial].
3. **Handle Resizing:** On viewport resize, update the aspect ratio and recalculate the projection matrix to maintain correct perspective [S2, unofficial].
4. **Apply Rotations and Scaling:** Apply yaw rotation around the Z-axis and pitch rotation around the X-axis if the absolute angle values exceed $10^{-20}$ to prevent numerical instability [S1, unofficial]. Apply uniform scaling with factor 0.7 and handle coordinate shifts if non-zero shift vectors are provided [S1, unofficial].

**Formulas:**
The core projection matrix elements are defined as [S2, unofficial]:
$$ P_{0,0} = \frac{2 f_x}{width} $$
$$ P_{1,1} = \frac{2 f_y}{height} $$
$$ P_{2,2} = -\frac{far + near}{far - near} $$
$$ P_{2,3} = -1 $$
$$ P_{3,2} = -\frac{2 \cdot far \cdot near}{far - near} $$
All other elements are $0$.

Where:
- $f_x, f_y$: Horizontal and vertical focal lengths in pixels.
- $width, height$: Viewport dimensions in pixels.
- $near, far$: Distances to the near and far clipping planes.

**Parameters:**
- Typical default camera specs: $f_x = 1159.5880733038064$, $f_y = 1164.6601287484507$, $near = 0.1$, $far = 500.0$ [S2, unofficial].
- Typical aspect ratio: $SCR\_WIDTH / SCR\_HEIGHT$ (e.g., $1280/720$) [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Numerical Instability:** Rotations should be skipped if angles are near zero (threshold $10^{-20}$) to prevent numerical instability and unnecessary matrix multiplications [S1, unofficial].
- **Aspect Ratio Changes:** Failing to update the projection matrix on viewport resize leads to distorted rendering [S2, unofficial].
- **Precision:** The near and far plane distances must be positive and $far > near$ to avoid division by zero or invalid depth ranges [G].

**Pseudocode:**
```python
def construct_projection_matrix(fx, fy, width, height, near, far):
    """Constructs a perspective projection matrix."""
    P = [[0.0] * 4 for _ in range(4)]
    P[0][0] = (2.0 * fx) / width
    P[1][1] = (2.0 * fy) / height
    P[2][2] = -(far + near) / (far - near)
    P[2][3] = -1.0
    P[3][2] = -(2.0 * far * near) / (far - near)
    return P

def combine_matrices(projection, view, model):
    """Combines projection, view, and model matrices: MVP = P * V * M."""
    temp = multiply_matrices(view, model)
    return multiply_matrices(projection, temp)

def multiply_matrices(A, B):
    """Multiplies two 4x4 matrices."""
    C = [[0.0] * 4 for _ in range(4)]
    for i in range(4):
        for j in range(4):
            for k in range(4):
                C[i][j] += A[i][k] * B[k][j]
    return C
```

## Subtopics

### [View and Projection Matrix Construction](2432-view-and-projection-matrix-construction.md)
This method computes the view and projection matrices for camera rendering, specifically handling focal length calculation from field of view (FOV) for use in splat shaders. It differs from fixed-function pipeline setups by explicitly managing tangent-based FOV parameters, coordinate system conversions (e.g., OpenGL to WGPU), and uniform buffer population.

### [Reverse Z Perspective Projection with Infinite Far Plane](7544-reverse-z-perspective-projection-with-infinite-far-plane.md)
This method constructs a perspective projection matrix that maps view space coordinates to clip space while utilizing a reversed depth buffer (Reverse Z) and an effectively infinite far plane. It solves the problem of depth precision loss at large distances inherent in standard finite-far-plane projections, thereby avoiding far-plane clipping artifacts and maintaining high precision near the camera. It differs from standard perspective projections by inverting the depth range and removing the far-plane dependency from the matrix structure.

### [MiniGS Full Projection Matrix](13954-minigs-full-projection-matrix.md)
Constructs a combined view-projection matrix matching the MiniGS reference kernel convention, using explicit frustum plane calculations and a specific z-near/z-far mapping.

### Object Space Projection
A projection technique where a second-order tensor $T$ is projected onto object space using a symmetric projection matrix $P$ [S4, unofficial]. It projects $T$ from world space to object space (surface space) by rendering the surface using the default OpenGL rendering pipeline to provide depth and surface normal information, then transforming the tensor field [S4, unofficial]. The tensor is projected to object space by $T' = P \cdot T \cdot P^T$, where $P = \begin{pmatrix} 1 - n_x^2 & -n_y n_x & -n_z n_x \\ -n_x n_y & 1 - n_y^2 & -n_z n_y \\ -n_x n_z & -n_y n_z & 1 - n_z^2 \end{pmatrix}$ and $n_x, n_y, n_z$ are the components of the surface normal $n$ [S4, unofficial].
