# Custom Perspective Projection Matrix Construction

Also called: 3D Projection Matrix Construction, Camera projection matrix setup, Canvas projection setup, Custom Perspective Projection Matrix, View matrix assembly, View matrix setup

## Overview
This method constructs the perspective projection matrix for 3D rendering, specifically tailored for splat-based rendering pipelines where explicit control over focal lengths and aspect ratios is required [S2, S3, unofficial]. It solves the problem of mapping 3D view-space coordinates to 2D screen space by combining field-of-view (FOV) parameters with viewport dimensions, differing from fixed-function pipeline setups by allowing tangent-based FOV parameter management and explicit coordinate system conversions [S1, S2, S3, unofficial]. It builds on [General Perspective Transformation](1845-general-perspective-transformation.md) by providing the specific matrix assembly logic used in modern splat renderers.

## How it works
**Inputs and Outputs:**
- Inputs: Field of view angle (in radians), aspect ratio ($w/h$), near plane distance ($near$), far plane distance ($far$), and optionally viewport dimensions ($width, height$) if constructing from focal lengths directly [S2, S3, unofficial].
- Output: A $4 \times 4$ projection matrix $P$ in column-major or row-major format depending on the graphics API [S2, S3, unofficial].

**Data Structures:**
- The projection matrix is a $4 \times 4$ matrix of floating-point values.
- Standard OpenGL-style column-major layout is implied by the source formulas [S2, unofficial].

**Steps:**
1. **Calculate Focal Lengths (if not provided):** If the input is FOV and aspect ratio, calculate horizontal and vertical focal lengths ($f_x, f_y$) based on the sensor width and FOV. If the input is direct focal lengths, use them [S2, unofficial].
2. **Compute Matrix Elements:** Populate the projection matrix $P$ using the following non-zero elements [S2, unofficial]:
   - $P_{0,0} = \frac{2 f_x}{width}$
   - $P_{1,1} = \frac{2 f_y}{height}$
   - $P_{2,2} = -\frac{far + near}{far - near}$
   - $P_{2,3} = -1$
   - $P_{3,2} = -\frac{2 \cdot far \cdot near}{far - near}$
   - All other elements are $0$.
3. **Combine with View and Model Matrices:** Multiply the projection matrix $P$ by the view matrix $V$ and the model matrix $M$ to form the final model-view-projection (MVP) matrix: $MVP = P \times V \times M$ [S3, unofficial].
4. **Handle Resizing:** On viewport resize, update the aspect ratio and recalculate the projection matrix to maintain correct perspective [S2, unofficial].

**Formulas:**
The core projection matrix elements are defined as:
$$ P_{0,0} = \frac{2 f_x}{width} $$
$$ P_{1,1} = \frac{2 f_y}{height} $$
$$ P_{2,2} = -\frac{far + near}{far - near} $$
$$ P_{2,3} = -1 $$
$$ P_{3,2} = -\frac{2 \cdot far \cdot near}{far - near} $$

Where:
- $f_x, f_y$: Horizontal and vertical focal lengths in pixels.
- $width, height$: Viewport dimensions in pixels.
- $near, far$: Distances to the near and far clipping planes.

**Parameters:**
- Typical default camera specs: $f_x = 1159.5880733038064$, $f_y = 1164.6601287484507$, $near = 0.1$, $far = 500.0$ [S2, unofficial].
- Typical aspect ratio: $SCR\_WIDTH / SCR\_HEIGHT$ (e.g., $1280/720$) [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Numerical Instability:** Rotations should be skipped if angles are near zero (threshold $10^{-20}$) to prevent numerical instability and unnecessary matrix multiplications [S1, unofficial].
- **Aspect Ratio Changes:** Failing to update the projection matrix on viewport resize leads to distorted rendering [S2, unofficial].
- **Coordinate System Conversions:** Explicit handling is required when converting between different coordinate systems (e.g., OpenGL to WGPU) [S1, S3, unofficial].

**Pseudocode:**
```python
def construct_projection_matrix(fx, fy, width, height, near, far):
    """
    Constructs a perspective projection matrix.
    
    Args:
        fx: Horizontal focal length in pixels.
        fy: Vertical focal length in pixels.
        width: Viewport width in pixels.
        height: Viewport height in pixels.
        near: Near clipping plane distance.
        far: Far clipping plane distance.
        
    Returns:
        A 4x4 matrix (list of lists) representing the projection matrix.
    """
    # Initialize 4x4 matrix with zeros
    P = [[0.0 for _ in range(4)] for _ in range(4)]
    
    # Calculate non-zero elements
    P[0][0] = (2.0 * fx) / width
    P[1][1] = (2.0 * fy) / height
    P[2][2] = -(far + near) / (far - near)
    P[2][3] = -1.0
    P[3][2] = -(2.0 * far * near) / (far - near)
    
    return P

def combine_matrices(projection, view, model):
    """
    Combines projection, view, and model matrices.
    
    Args:
        projection: 4x4 projection matrix.
        view: 4x4 view matrix.
        model: 4x4 model matrix.
        
    Returns:
        The combined MVP matrix.
    """
    # Matrix multiplication: MVP = Projection * View * Model
    # Assuming column-major order and standard matrix multiplication
    temp = multiply_matrices(view, model)
    mvp = multiply_matrices(projection, temp)
    return mvp

def multiply_matrices(A, B):
    """
    Multiplies two 4x4 matrices.
    
    Args:
        A: 4x4 matrix.
        B: 4x4 matrix.
        
    Returns:
        The product A * B.
    """
    C = [[0.0 for _ in range(4)] for _ in range(4)]
    for i in range(4):
        for j in range(4):
            for k in range(4):
                C[i][j] += A[i][k] * B[k][j]
    return C
```

It solves the problem of depth precision loss at large distances inherent in standard finite-far-plane projections, thereby avoiding far-plane clipping artifacts and maintaining high precision near the camera. It differs from standard perspective projections by inverting the depth range and removing the far-plane dependency from the matrix structure.

## Operating characteristics
- **Time Complexity:** $O(1)$ for matrix construction, as it involves a fixed number of arithmetic operations.
- **Memory Complexity:** $O(1)$ for storing the $4 \times 4$ matrix.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Linear with respect to the number of vertices processed by the shader, but the matrix construction itself is constant time.
- **Strengths:** Explicit control over focal lengths and aspect ratio, suitable for splat rendering where precise control over projection is needed.
- **Limitations:** Requires manual updates on viewport resize; not directly compatible with fixed-function pipeline without modification.
- **When to use:** When using splat-based rendering or when explicit control over projection parameters is required.
- **When not to use:** When using standard fixed-function pipelines that handle projection automatically.

## Background
This method is commonly used in modern splat-based rendering engines, such as those for 3D Gaussian Splatting, where explicit control over the projection matrix is necessary for accurate rendering [S2, S3, unofficial]. It differs from traditional OpenGL/DirectX fixed-function pipelines by allowing developers to manually construct the projection matrix based on specific camera parameters [S1, S2, S3, unofficial].
