# MiniGS Full Projection Matrix

Also called: MiniGS Projection Matrix

## Overview
The MiniGS Full Projection Matrix constructs a combined view-projection matrix matching the MiniGS reference kernel convention using explicit frustum plane calculations and a specific z-near/z-far mapping [S1, unofficial]. It differs from standard column-major projection matrices by explicitly transposing the computed matrix before batched multiplication with the view transform [S1, unofficial].

## How it works
**Inputs:**
- `znear`: Float, camera near clipping plane distance [S1, unofficial].
- `zfar`: Float, camera far clipping plane distance [S1, unofficial].
- `FoVx`: Float, horizontal field of view in radians [S1, unofficial].
- `FoVy`: Float, vertical field of view in radians [S1, unofficial].
- `world_view_transform`: 4x4 matrix (or batch of matrices) representing the world-to-view transformation [S1, unofficial].

**Outputs:**
- `full_projection_matrix`: 4x4 float32 matrix (row-major), representing the combined view-projection transformation [S1, unofficial].

**Data Structures:**
The projection matrix is a 4x4 array of 32-bit floats [S1, unofficial]. The source code initializes it as a standard 4x4 tensor/matrix and applies a transpose operation at the end [S1, unofficial]. The final matrix is row-major in memory after the transpose, consistent with the batched matrix multiplication (`bmm`) operation used in the reference implementation [S1, unofficial].

**Steps:**
1. Calculate the tangent of half the horizontal and vertical fields of view:
   $$ t_x = \tan\left(\frac{FoV_x}{2}\right) $$
   $$ t_y = \tan\left(\frac{FoV_y}{2}\right) $$
2. Compute the frustum boundaries at the near plane:
   $$ right = znear \cdot t_x $$
   $$ left = -right $$
   $$ top = znear \cdot t_y $$
   $$ bottom = -top $$
3. Initialize a 4x4 matrix $M$ with zeros.
4. Set the specific elements of $M$ according to the MiniGS convention:
   $$ M_{0,0} = \frac{2 \cdot znear}{right - left} $$
   $$ M_{1,1} = \frac{2 \cdot znear}{top - bottom} $$
   $$ M_{0,2} = \frac{right + left}{right - left} $$
   $$ M_{1,2} = \frac{top + bottom}{top - bottom} $$
   $$ M_{3,2} = 1.0 $$
   $$ M_{2,2} = \frac{zfar + znear}{zfar - znear} $$
   $$ M_{2,3} = -\frac{zfar \cdot znear}{zfar - znear} $$
   All other elements remain 0 [S1, unofficial].
5. Transpose the matrix $M$ to obtain the row-major layout required for the subsequent multiplication [S1, unofficial].
6. Multiply the transposed projection matrix with the `world_view_transform` using batched matrix multiplication (`bmm`) to produce the final `full_projection_matrix` [S1, unofficial].

**Formulas:**
- $right = znear \cdot \tan(FoV_x / 2)$
- $top = znear \cdot \tan(FoV_y / 2)$
- $left = -right$
- $bottom = -top$
- $M_{0,0} = \frac{2 \cdot znear}{right - left}$
- $M_{1,1} = \frac{2 \cdot znear}{top - bottom}$
- $M_{0,2} = \frac{right + left}{right - left}$
- $M_{1,2} = \frac{top + bottom}{top - bottom}$
- $M_{3,2} = 1.0$
- $M_{2,2} = \frac{zfar + znear}{zfar - znear}$
- $M_{2,3} = -\frac{zfar \cdot znear}{zfar - znear}$

**Pseudocode:**
```python
import math
import numpy as np

def mini_gs_full_projection_matrix(znear, zfar, fov_x, fov_y, world_view_transform):
    """
    Constructs the MiniGS full projection matrix.
    
    Args:
        znear (float): Near clipping plane.
        zfar (float): Far clipping plane.
        fov_x (float): Horizontal field of view in radians.
        fov_y (float): Vertical field of view in radians.
        world_view_transform (np.ndarray): 4x4 matrix (or batch of 4x4 matrices).
        
    Returns:
        np.ndarray: The combined view-projection matrix.
    """
    # 1. Calculate tangents
    tan_half_fov_x = math.tan(fov_x * 0.5)
    tan_half_fov_y = math.tan(fov_y * 0.5)
    
    # 2. Calculate frustum boundaries
    right = znear * tan_half_fov_x
    left = -right
    top = znear * tan_half_fov_y
    bottom = -top
    
    # 3. Initialize 4x4 matrix
    M = np.zeros((4, 4), dtype=np.float32)
    
    # 4. Set matrix elements
    M[0, 0] = 2.0 * znear / (right - left)
    M[1, 1] = 2.0 * znear / (top - bottom)
    M[0, 2] = (right + left) / (right - left)
    M[1, 2] = (top + bottom) / (top - bottom)
    M[3, 2] = 1.0
    M[2, 2] = (zfar + znear) / (zfar - znear)
    M[2, 3] = -(zfar * znear) / (zfar - znear)
    
    # 5. Transpose the matrix
    M = M.T
    
    # 6. Multiply with world_view_transform via batched matrix multiplication
    # np.matmul handles broadcasting for batches, equivalent to bmm
    full_projection_matrix = np.matmul(M, world_view_transform)
    
    return full_projection_matrix
```

**Parameters:**
- `znear`: Positive float, camera near clipping plane distance [S1, unofficial].
- `zfar`: Positive float, camera far clipping plane distance [S1, unofficial].
- `FoVx`, `FoVy`: Floats in radians, horizontal and vertical field of view [S1, unofficial].
Typical values are Not given in the sources [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Radians vs Degrees:** The source code uses `math.tan` directly on the input angles, and the documentation explicitly states that FoV values must be in radians [S1, unofficial].
- **Matrix Transpose:** The matrix is explicitly transposed before multiplication, which differs from standard column-major conventions if not accounted for [S1, unofficial].
- **Division by Zero:** If `right == left` or `top == bottom` (i.e., zero field of view), division by zero occurs [G]. If `zfar == znear`, the depth mapping terms also divide by zero [G]. These should be guarded against in production code [G].
