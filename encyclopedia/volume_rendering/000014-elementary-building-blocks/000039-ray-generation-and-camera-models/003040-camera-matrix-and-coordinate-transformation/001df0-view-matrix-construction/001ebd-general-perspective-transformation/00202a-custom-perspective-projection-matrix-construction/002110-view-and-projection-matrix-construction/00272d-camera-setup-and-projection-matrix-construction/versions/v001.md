# Camera Setup and Projection Matrix Construction

Also called: CamSetup

## Overview
Prepares camera parameters for rendering and training, handling downscaling, view matrix construction, and projection matrix calculation [S1, unofficial]. It differs from standard graphics pipelines by deriving a custom projection matrix tailored for the specific near/far plane constraints of 3D Gaussian Splatting training, rather than using a standard OpenGL/DirectX default projection [S1, unofficial].

## How it works
**Inputs:**
- Camera intrinsics: $f_x, f_y, c_x, c_y$ (focal lengths and principal point).
- Camera extrinsics: $4 \times 4$ row-major matrix $\mathbf{C}_{world}$ (camera-to-world transform).
- Image dimensions: $W, H$ (original width and height).
- Downscale step: $step$ (integer level of the image pyramid).
- Constants: $BLOCK\_X, BLOCK\_Y$ (tile block sizes), $SH\_DegreeInterval$ (Spherical Harmonics degree interval), $shDegree$ (maximum SH degree), $featuresRest$ (size of feature vector).
- Planes: Near $n = 0.001$, Far $f = 1000.0$.

**Outputs:**
- Downscaled intrinsics: $f'_x, f'_y, c'_x, c'_y$.
- Downscaled dimensions: $W', H'$.
- Field of View: $fovX, fovY$.
- View Matrix: $\mathbf{V}$ ($4 \times 4$).
- Projection Matrix: $\mathbf{P}$ ($4 \times 4$).
- Proj-View Matrix: $\mathbf{PV} = \mathbf{P} \times \mathbf{V}$.
- Camera Position: $\mathbf{cam\_pos}$ in world space.
- Tile Bounds: derived from $W', H'$.
- SH Degree: $degreesToUse$.

**Data Structures:**
- `Camera`: Contains `width`, `height`, `fx`, `fy`, `cx`, `cy`, `camToWorld[16]` (row-major), `cachedViewMat`, `cachedProjViewMat`, `cachedCamPos[3]`, `cachedFovX`, `cachedFovY`.
- `Image`: Contains `data` (float array, size $W \times H \times 3$), `width`, `height`.

**Steps:**

1.  **Calculate Downscale Factor:**
    Determine the downscale factor $sf$ based on the current $step$. Typically $sf = 2^{step}$ or similar power-of-two scaling depending on the pyramid structure [S1, unofficial].

2.  **Update Intrinsics and Dimensions:**
    Divide original intrinsics by $sf$:
    $$f'_x = f_x / sf, \quad f'_y = f_y / sf$$
    $$c'_x = c_x / sf, \quad c'_y = c_y / sf$$
    Divide original dimensions by $sf$:
    $$W' = W / sf, \quad H' = H / sf$$

3.  **Calculate Field of View (FOV):**
    Compute horizontal and vertical FOV in radians using the new dimensions and focal lengths:
    $$fovX = 2.0 \cdot \arctan\left(\frac{W'}{2.0 \cdot f'_x}\right)$$
    $$fovY = 2.0 \cdot \arctan\left(\frac{H'}{2.0 \cdot f'_y}\right)$$
    [S1, unofficial]

4.  **Check Cache:**
    If the view matrix is not cached or the FOV has changed since the last calculation, proceed to construct matrices. Otherwise, retrieve cached $\mathbf{V}$, $\mathbf{PV}$, $\mathbf{cam\_pos}$, $fovX$, and $fovY$ [S1, unofficial].

5.  **Construct View Matrix ($\mathbf{V}$):**
    Extract rotation $\mathbf{R}$ and translation $\mathbf{T}$ from the camera-to-world matrix $\mathbf{C}_{world}$ (indices $i \cdot 4 + j$ for row $i$, column $j$).
    Compute the inverse rotation $\mathbf{R}^{-1}$ as the transpose of $\mathbf{R}$ ($\mathbf{R}^T$).
    Compute the inverse translation $\mathbf{T}^{-1} = -\mathbf{R}^T \mathbf{T}$.
    Construct $\mathbf{V}$ ($4 \times 4$) using $\mathbf{R}^T$ and $\mathbf{T}^{-1}$:
    $$\mathbf{V} = \begin{bmatrix} \mathbf{R}^T & \mathbf{T}^{-1} \\ \mathbf{0}^T & 1 \end{bmatrix}$$
    [S1, unofficial]

    Store $\mathbf{V}$, $\mathbf{PV}$, $\mathbf{cam\_pos}$, $fovX$, and $fovY$ in the camera object's cache fields [S1, unofficial].

    $$degreesToUse = \min\left(\frac{step}{SH\_DegreeInterval}, shDegree\right)$$

    Calculate the degree based on the size of `featuresRest` [S1, unofficial].

    Derive tile bounds from $W'$, $H'$, $BLOCK\_X$, and $BLOCK\_Y$ [S1, unofficial].

    Set `cam_pos` from the cached values (extracted from $\mathbf{V}$ or $\mathbf{C}_{world}$) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Using `float` (32-bit) for matrix calculations may lead to precision issues for very large or very small scenes. The source uses `0.001f` and `1000.0f`, suggesting a specific scale.
- **Boundaries:** Ensure $f_x, f_y$ are not zero to avoid division by zero in FOV calculation.
- **Degenerate Input:** If $step$ is negative or $sf$ calculation is invalid, the method fails.
- **Source Discrepancy:** The source's projection matrix $P_{3,2}$ value ($-fn/(f-n)$) differs from the standard OpenGL value ($2fn/(f-n)$). This must be implemented as per the source [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per camera setup, as it involves a fixed number of matrix multiplications and trigonometric operations.
- **Memory Complexity:** $O(1)$ additional memory for caching matrices and parameters.
- **Performance:** Optimized for Metal GPU rendering, minimizing CPU-GPU synchronization by caching matrices [S1, unofficial].
- **Strengths:** Handles downscaling automatically, integrates SH degree calculation, and uses a custom projection matrix suitable for the specific training pipeline.
- **Limitations:** Tied to specific near/far plane values ($0.001, 1000.0$) which may not be suitable for all scenes. The non-standard projection matrix element requires careful verification.
