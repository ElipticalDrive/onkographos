# Camera Setup and Projection Matrix Construction

Also called: CamSetup

## Overview
Prepares camera parameters for rendering and training, handling downscaling, view matrix construction, and projection matrix calculation [S1, unofficial].

## How it works
**Inputs:**
- Camera intrinsics: $f_x, f_y, c_x, c_y$ (focal lengths and principal point) [S1, unofficial].
- Camera extrinsics: $4 \times 4$ row-major matrix $\mathbf{C}_{world}$ (camera-to-world transform) [S1, unofficial].
- Image dimensions: $W, H$ (original width and height) [S1, unofficial].
- Downscale step: $step$ (integer level of the image pyramid) [S1, unofficial].
- Constants: $BLOCK\_X, BLOCK\_Y$ (tile block sizes), $SH\_DegreeInterval$ (Spherical Harmonics degree interval), $shDegree$ (maximum SH degree), $featuresRest$ (size of feature vector) [S1, unofficial].
- Planes: Near $n = 0.001$, Far $f = 1000.0$ [S1, unofficial].

**Outputs:**
- Downscaled intrinsics: $f'_x, f'_y, c'_x, c'_y$ [S1, unofficial].
- Downscaled dimensions: $W', H'$ [S1, unofficial].
- Field of View: $fovX, fovY$ [S1, unofficial].
- View Matrix: $\mathbf{V}$ ($4 \times 4$) [S1, unofficial].
- Projection Matrix: $\mathbf{P}$ ($4 \times 4$) [S1, unofficial].
- Proj-View Matrix: $\mathbf{PV} = \mathbf{P} \times \mathbf{V}$ [S1, unofficial].
- Camera Position: $\mathbf{cam\_pos}$ in world space [S1, unofficial].
- Tile Bounds: derived from $W', H'$ [S1, unofficial].
- SH Degree: $degreesToUse$ [S1, unofficial].

**Data Structures:**
- `Camera`: Contains `width`, `height`, `fx`, `fy`, `cx`, `cy`, `camToWorld[16]` (row-major), `cachedViewMat`, `cachedProjViewMat`, `cachedCamPos[3]`, `cachedFovX`, `cachedFovY` [S1, unofficial].
- `Image`: Contains `data` (float array, size $W \times H \times 3$), `width`, `height` [S1, unofficial].

**Steps:**
1. Calculate downscale factor $sf$ from $step$ [S1, unofficial].
2. Divide camera intrinsics by $sf$: $f'_x = f_x / sf$, $f'_y = f_y / sf$, $c'_x = c_x / sf$, $c'_y = c_y / sf$ [S1, unofficial].
3. Calculate new height/width by dividing original by $sf$: $W' = W / sf$, $H' = H / sf$ [S1, unofficial].
4. Calculate $fovX$ and $fovY$ from new width/height and $f'_x/f'_y$: $fovX = 2.0 \cdot \arctan(W' / (2.0 \cdot f'_x))$, $fovY = 2.0 \cdot \arctan(H' / (2.0 \cdot f'_y))$ [S1, unofficial].
5. If view matrix is not cached or FOV changed:
   a. Extract rotation $\mathbf{R}$ and translation $\mathbf{T}$ from $\mathbf{C}_{world}$ (indices $i \cdot 4 + j$ for row $i$, column $j$) [S1, unofficial].
   b. Compute $\mathbf{R}^{-1}$ as the transpose of $\mathbf{R}$ ($\mathbf{R}^T$) [S1, unofficial].
   c. Compute inverse translation $\mathbf{T}^{-1} = -\mathbf{R}^T \mathbf{T}$ [S1, unofficial].
   d. Construct view matrix $\mathbf{V}$ ($4 \times 4$) using $\mathbf{R}^T$ and $\mathbf{T}^{-1}$ [S1, unofficial].
   e. Calculate $r_p = n \cdot \tan(fovX / 2)$ and $t_p = n \cdot \tan(fovY / 2)$, where $n = 0.001$ [S1, unofficial].
   f. Construct projection matrix $\mathbf{P}$ ($4 \times 4$) with elements: $P_{0,0} = n / r_p$, $P_{1,1} = n / t_p$, $P_{2,2} = (f + n) / (f - n)$, $P_{3,2} = -f \cdot n / (f - n)$, where $f = 1000.0$ [S1, unofficial].
   g. Compute $\mathbf{PV} = \mathbf{P} \times \mathbf{V}$ [S1, unofficial].
   h. Cache $\mathbf{V}$, $\mathbf{PV}$, $\mathbf{cam\_pos}$, $fovX$, and $fovY$ [S1, unofficial].
6. Set $degreesToUse = \min(step / SH\_DegreeInterval, shDegree)$ [S1, unofficial].
7. Determine degree from `featuresRest` size [S1, unofficial].
8. Calculate `tileBounds` from $W'$, $H'$, $BLOCK\_X$, and $BLOCK\_Y$ [S1, unofficial].
9. Set `cam_pos` from cached values [S1, unofficial].

**Pseudocode:**
```python
import math

def setup_camera(camera, step, sh_degree_interval, sh_degree, features_rest_size, block_x, block_y):
    # 1. Calculate downscale factor from step
    sf = 2 ** step  # [G] Standard power-of-two pyramid scaling
    
    # 2. Update intrinsics and dimensions
    fx_new = camera.fx / sf
    fy_new = camera.fy / sf
    cx_new = camera.cx / sf
    cy_new = camera.cy / sf
    
    width_new = camera.width / sf
    height_new = camera.height / sf
    
    # 3. Calculate FOV
    fov_x = 2.0 * math.atan(width_new / (2.0 * fx_new))
    fov_y = 2.0 * math.atan(height_new / (2.0 * fy_new))
    
    # 4. Check Cache
    if camera.cached_view_mat is None or camera.cached_fov_x != fov_x or camera.cached_fov_y != fov_y:
        
        # 5. Construct View Matrix
        # Extract R and T from camera.camToWorld (4x4 row-major)
        R = [
            [camera.camToWorld[0], camera.camToWorld[1], camera.camToWorld[2]],
            [camera.camToWorld[4], camera.camToWorld[5], camera.camToWorld[6]],
            [camera.camToWorld[8], camera.camToWorld[9], camera.camToWorld[10]]
        ]
        T = [camera.camToWorld[3], camera.camToWorld[7], camera.camToWorld[11]]
        
        # Rinv is transpose of R
        R_inv = [
            [R[0][0], R[1][0], R[2][0]],
            [R[0][1], R[1][1], R[2][1]],
            [R[0][2], R[1][2], R[2][2]]
        ]
        
        # Tinv = -Rinv * T
        T_inv = [
            -(R_inv[0][0]*T[0] + R_inv[0][1]*T[1] + R_inv[0][2]*T[2]),
            -(R_inv[1][0]*T[0] + R_inv[1][1]*T[1] + R_inv[1][2]*T[2]),
            -(R_inv[2][0]*T[0] + R_inv[2][1]*T[1] + R_inv[2][2]*T[2])
        ]
        
        # Construct View Matrix V (4x4)
        V = [
            [R_inv[0][0], R_inv[0][1], R_inv[0][2], T_inv[0]],
            [R_inv[1][0], R_inv[1][1], R_inv[1][2], T_inv[1]],
            [R_inv[2][0], R_inv[2][1], R_inv[2][2], T_inv[2]],
            [0.0, 0.0, 0.0, 1.0]
        ]
        
        # 6. Construct Projection Matrix P
        n = 0.001
        f = 1000.0
        r_p = n * math.tan(0.5 * fov_x)
        t_p = n * math.tan(0.5 * fov_y)
        
        # P elements as per source
        P = [
            [n/r_p, 0.0, 0.0, 0.0],
            [0.0, n/t_p, 0.0, 0.0],
            [0.0, 0.0, (f+n)/(f-n), -1.0], # [G] Standard P[2][3]
            [0.0, 0.0, -f*n/(f-n), 0.0]    # [S1, unofficial] pm[14]
        ]
        
        # 7. Compute PV = P * V
        PV = [[0.0]*4 for _ in range(4)]
        for i in range(4):
            for j in range(4):
                for k in range(4):
                    PV[i][j] += P[i][k] * V[k][j]
        
        # 8. Cache Results
        camera.cached_view_mat = V
        camera.cached_proj_view_mat = PV
        
        # Extract cam_pos from V or C_world. 
        # Cam pos in world is the position of the camera origin.
        # In C_world, the camera origin is -R^T * T.
        cam_pos = [
            -(R_inv[0][0]*T[0] + R_inv[0][1]*T[1] + R_inv[0][2]*T[2]),
            -(R_inv[1][0]*T[0] + R_inv[1][1]*T[1] + R_inv[1][2]*T[2]),
            -(R_inv[2][0]*T[0] + R_inv[2][1]*T[1] + R_inv[2][2]*T[2])
        ]
        camera.cached_cam_pos = cam_pos
        camera.cached_fov_x = fov_x
        camera.cached_fov_y = fov_y
    else:
        V = camera.cached_view_mat
        PV = camera.cached_proj_view_mat
        cam_pos = camera.cached_cam_pos
        fov_x = camera.cached_fov_x
        fov_y = camera.cached_fov_y

    # 9. Determine SH Degree
    degrees_to_use = min(step / sh_degree_interval, sh_degree)

    # [G] Specific mapping not given in sources.
    
    # 11. Calculate Tile Bounds
    # [G] Specific calculation not given in sources.
    
    # 12. Set cam_pos
    # Already set in cache
    
    return {
        "fov_x": fov_x,
        "fov_y": fov_y,
        "view_mat": V,
        "proj_view_mat": PV,
        "cam_pos": cam_pos,
        "degrees_to_use": degrees_to_use
    }
```

**Edge Cases and Pitfalls:**
- **Precision:** Using `float` (32-bit) for matrix calculations may lead to precision issues for very large or very small scenes. The source uses `0.001f` and `1000.0f`, suggesting a specific scale [S1, unofficial].
- **Boundaries:** Ensure $f_x, f_y$ are not zero to avoid division by zero in FOV calculation [S1, unofficial].
- **Degenerate Input:** If $step$ is negative or $sf$ calculation is invalid, the method fails [S1, unofficial].
- **Source Discrepancy:** The source's projection matrix $P_{3,2}$ value ($-fn/(f-n)$) differs from the standard OpenGL value ($2fn/(f-n)$) [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per camera setup, as it involves a fixed number of matrix multiplications and trigonometric operations [S1, unofficial].
- **Memory Complexity:** $O(1)$ additional memory for caching matrices and parameters [S1, unofficial].
- **Performance:** Optimized for Metal GPU rendering, minimizing CPU-GPU synchronization by caching matrices [S1, unofficial].
- **Strengths:** Handles downscaling automatically, integrates SH degree calculation, and uses a custom projection matrix suitable for the specific training pipeline [S1, unofficial].
- **Limitations:** Tied to specific near/far plane values ($0.001, 1000.0$) which may not be suitable for all scenes [S1, unofficial].
