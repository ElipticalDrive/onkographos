# Pivot-based Geometry Transformation

Also called: Pivot Transformation, Transform Relative to Pivot

## Overview
Pivot-based Geometry Transformation applies a homogeneous transformation matrix to geometric primitives relative to a specific pivot point rather than the world origin, ensuring that rotation and scaling occur around the object's local center or a designated anchor [S1, unofficial]. It distinguishes itself from standard matrix multiplication by explicitly subtracting the pivot vector before transformation and adding it back afterward, while also scaling geometric radii and thicknesses by the maximum scale factor to preserve visual proportions [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A `Geometry` struct instance (containing position, vertices, radius, or thickness), a 4x4 transformation matrix $M$ (derived from translation, rotation, and scale), and a pivot point $P_{pivot}$ (3D vector).
- **Output**: A transformed `Geometry` instance with updated vertices/positions and scaled radii/thicknesses.

**Data Structures**
The method operates on specific geometry types defined in the source library:
- `ParticleGeometry`: Fields `pos` (3D vector), `radius` (float).
- `CapsuleGeometry`: Fields `start` (3D vector), `end` (3D vector), `radius` (float).
- `TriangleGeometry`: Fields `v1`, `v2`, `v3` (3D vectors), `thickness` (float).
- `MeshGeometry`: Handled by storing the transformation directly (implementation detail not fully specified, assumed to apply matrix to mesh vertices) [S1, unofficial].
- `TextGeometry`: 3D text defined by string, position, size, and orientation [S1, unofficial].

**Formulas**
For a point $P$ in the geometry:
$$ P' = P_{pivot} + M \cdot (P - P_{pivot}) $$
For a radius $r$ or thickness $t$:
$$ r' = r \cdot \max(s_x, s_y, s_z) $$
$$ t' = t \cdot \max(s_x, s_y, s_z) $$
Where $s_x, s_y, s_z$ are the scale components of the transformation matrix [S1, unofficial].

**Steps**
1. Extract the scale components $(s_x, s_y, s_z)$ from the transformation matrix $M$.
2. Compute the maximum scale factor: $maxScale = \max(s_x, s_y, s_z)$.
3. For each vertex or position point $P$ in the geometry:
   a. Translate the point relative to the pivot: $P_{local} = P - P_{pivot}$.
   b. Apply the transformation matrix: $P_{transformed} = M \cdot P_{local}$.
   c. Translate back: $P' = P_{pivot} + P_{transformed}$.
4. Scale the geometric radius or thickness: $r' = r \cdot maxScale$.
5. Return the new geometry with updated points and scaled dimensions.

**Pseudocode**
```python
def pivot_transform(geometry, t_matrix, pivot):
    # Extract scale factors from the transformation matrix
    # Assuming t_matrix is a 4x4 matrix stored as list of lists or similar
    # Scale factors are typically in the diagonal elements for uniform/non-uniform scaling
    sx = t_matrix[0][0]
    sy = t_matrix[1][1]
    sz = t_matrix[2][2]
    
    max_scale = max(sx, sy, sz)
    
    if isinstance(geometry, ParticleGeometry):
        # Transform position
        pos_local = geometry.pos - pivot
        pos_transformed = mat_col_mul(t_matrix, pos_local)
        new_pos = pivot + pos_transformed
        return ParticleGeometry(
            pos=new_pos,
            radius=geometry.radius * max_scale
        )
        
    elif isinstance(geometry, CapsuleGeometry):
        # Transform start and end points
        start_local = geometry.start - pivot
        start_transformed = mat_col_mul(t_matrix, start_local)
        new_start = pivot + start_transformed
        
        end_local = geometry.end - pivot
        end_transformed = mat_col_mul(t_matrix, end_local)
        new_end = pivot + end_transformed
        
        return CapsuleGeometry(
            start=new_start,
            end=new_end,
            radius=geometry.radius * max_scale
        )
        
    elif isinstance(geometry, TriangleGeometry):
        # Transform vertices
        v1_local = geometry.v1 - pivot
        v1_transformed = mat_col_mul(t_matrix, v1_local)
        new_v1 = pivot + v1_transformed
        
        v2_local = geometry.v2 - pivot
        v2_transformed = mat_col_mul(t_matrix, v2_local)
        new_v2 = pivot + v2_transformed
        
        v3_local = geometry.v3 - pivot
        v3_transformed = mat_col_mul(t_matrix, v3_local)
        new_v3 = pivot + v3_transformed
        
        return TriangleGeometry(
            v1=new_v1,
            v2=new_v2,
            v3=new_v3,
            thickness=geometry.thickness * max_scale
        )
        
    elif isinstance(geometry, MeshGeometry):
        # Store transformation directly (implementation specific)
        # [G] Assuming this applies the matrix to all mesh vertices internally
        geometry.apply_transformation(t_matrix)
        return geometry
        
    elif isinstance(geometry, TextGeometry):
        # TextGeometry does not support transformation logic
        # [S1, unofficial]
        raise Warning("TextGeometry does not support transformation; geometry unchanged.")
        return geometry
        
    else:
        raise ValueError("Unsupported geometry type")

def mat_col_mul(matrix, vector):
    # Multiply 4x4 matrix by 3D vector (assuming homogeneous coordinate w=1 for translation)
    # Vector is treated as [x, y, z, 1]
    x = matrix[0][0]*vector[0] + matrix[0][1]*vector[1] + matrix[0][2]*vector[2] + matrix[0][3]
    y = matrix[1][0]*vector[0] + matrix[1][1]*vector[1] + matrix[1][2]*vector[2] + matrix[1][3]
    z = matrix[2][0]*vector[0] + matrix[2][1]*vector[1] + matrix[2][2]*vector[2] + matrix[2][3]
    return [x, y, z]
```

**Parameters**
- `pivot`: The 3D point around which transformation occurs. Not given in the sources if it defaults to origin or must be explicitly set via `scene.setObjectIntrinsicPivot`.
- `t_matrix`: The 4x4 transformation matrix.

**Edge Cases and Pitfalls**
- `TextGeometry` does not support transformation logic. Applying a non-identity matrix triggers a runtime warning and leaves the geometry unchanged [S1, unofficial].
- Precision issues may arise if the pivot point is very large or the scale factors are extreme, but no specific numerical limits are given in the sources.

## Operating characteristics
**Time and Memory Complexity**
- Time complexity is linear with respect to the number of vertices in the geometry, as each vertex is transformed individually.
- Memory complexity is constant, as the transformation is applied in-place or creates a new geometry object with the same number of vertices.

**Measured Performance**
- Not given in the sources.

**Scaling**
- Not given in the sources.

**Strengths and Limitations**
- **Strengths**: Allows for intuitive local transformations (rotation/scaling around a specific point) without manual vertex manipulation.
- **Limitations**: `TextGeometry` is not supported. Requires explicit pivot definition.

**When to Use**
- Use when objects need to rotate or scale around their own center or a specific anchor point.
- Do not use for `TextGeometry`.
