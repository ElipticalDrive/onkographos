# Scaling and Rotation Matrix Construction
## Overview
Constructs a 3x3 transformation matrix by combining anisotropic scaling and rotation. It sets apart from [Scaling Matrix Construction](4126-scaling-matrix-construction.md) by explicitly integrating a rotation component, producing a composite linear transformation $M = L R$ where $L$ is the scaling matrix and $R$ is the rotation matrix. This method is a core building block for [Transformation Matrix Construction](12879-transformation-matrix-construction.md), which extends this logic to include translation for full model matrix generation.
## How it works
**Inputs:**
- `s`: A tensor of shape `(N, 3)` containing scaling factors for $N$ instances. Each row represents $(s_x, s_y, s_z)$.
- `r`: A tensor of shape `(N, 3)` containing rotation parameters (typically Euler angles) for $N$ instances.

**Outputs:**
- `M`: A tensor of shape `(N, 3, 3)` containing the resulting transformation matrices.

**Data Structures:**
- `L`: A 3x3 diagonal scaling matrix per instance.
- `R`: A 3x3 rotation matrix per instance, computed via `build_rotation(r)`.

**Steps:**
1. Initialize a zero tensor `L` of shape `(N, 3, 3)` on the target device (e.g., CUDA).
2. Compute the rotation matrix `R` by calling `build_rotation(r)`. This helper function converts the rotation parameters `r` into a proper 3x3 orthogonal rotation matrix for each instance.
3. Assign the scaling factors to the diagonal elements of `L`:
   - $L_{i,0,0} = s_{i,0}$
   - $L_{i,1,1} = s_{i,1}$
   - $L_{i,2,2} = s_{i,2}$
   for each instance $i \in [0, N-1]$.
4. Compute the final transformation matrix $M$ by multiplying the scaling matrix $L$ by the rotation matrix $R$:
   $$ M = L R $$
   Note: The multiplication order is critical. The scaling is applied after rotation in the matrix multiplication sense ($L$ on the left, $R$ on the right), meaning the vector is first rotated, then scaled.

**Pseudocode:**
```python
def build_scaling_rotation(s, r):
    """
    Constructs a 3x3 transformation matrix combining scaling and rotation.
    
    Args:
        s: Tensor of shape (N, 3) with scaling factors.
        r: Tensor of shape (N, 3) with rotation parameters.
        
    Returns:
        M: Tensor of shape (N, 3, 3) with transformation matrices.
    """
    # Initialize zero matrix L of shape (N, 3, 3)
    N = s.shape[0]
    L = torch.zeros((N, 3, 3), device=s.device)
    
    # Set diagonal elements of L
    L[:, 0, 0] = s[:, 0]
    L[:, 1, 1] = s[:, 1]
    L[:, 2, 2] = s[:, 2]
    
    # Compute rotation matrix R using build_rotation(r)
    # build_rotation is assumed to be defined elsewhere in the library
    R = build_rotation(r)
    
    # Multiply L by R
    # Matrix multiplication: (N, 3, 3) @ (N, 3, 3) -> (N, 3, 3)
    M = torch.bmm(L, R)
    
    return M
```

**Edge Cases and Pitfalls:**
- **Precision:** Ensure `build_rotation` handles degenerate rotation angles correctly to avoid non-orthogonal matrices.
- **Device Consistency:** `s`, `r`, and the resulting tensors must reside on the same device (e.g., CUDA) to avoid runtime errors during tensor operations.
- **Order of Operations:** The order $L R$ implies rotation is applied first, then scaling. Reversing the order ($R L$) would scale the axes before rotating them, which is a different transformation.

## Subtopics

### [Transformation Matrix Construction](12879-transformation-matrix-construction.md)
Computes a 4x4 homogeneous transformation matrix from translation, rotation (Euler angles), and scale factors for 3D geometry. It combines the scaling and rotation logic of [Scaling and Rotation Matrix Construction](7986-scaling-and-rotation-matrix-construction.md) with translation to produce a complete model matrix. It is distinguished by its explicit construction of individual axis rotation matrices and their specific multiplication order ($R_z R_y R_x$) before applying scale.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of instances. The operations are element-wise assignments and a batched matrix multiplication.
- **Memory Complexity:** $O(N)$ for storing the input tensors and the output matrix.
- **Performance:** Efficient on GPU due to batched operations. The use of CUDA tensors allows for parallel processing of all $N$ instances.
- **Strengths:** Simple, efficient, and modular. It separates scaling and rotation logic, making it easy to debug and extend.
- **Limitations:** Only produces a 3x3 matrix. For full 3D transformations including translation, it must be combined with other methods.
- **When to Use:** When you need to apply anisotropic scaling and rotation to a set of 3D vectors or points in a batched manner.
- **When Not to Use:** When translation is also required (use [Transformation Matrix Construction](12879-transformation-matrix-construction.md)) or when a 4x4 homogeneous matrix is needed directly.

## Background
This method is part of the InstantSplat framework [S1, unofficial], which is used for 3D Gaussian Splatting training. It provides a low-level building block for constructing transformation matrices from scaling and rotation parameters. The approach is typical in differentiable rendering pipelines where transformations need to be computed efficiently for large numbers of primitives.
