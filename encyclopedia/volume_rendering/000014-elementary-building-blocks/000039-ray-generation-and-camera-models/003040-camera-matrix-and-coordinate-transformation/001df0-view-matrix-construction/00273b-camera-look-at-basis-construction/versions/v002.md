# Camera Look-at Basis Construction
Also called: Camera Coordinate System Construction, Camera Matrix Generation, LookAt Basis Construction
## Overview
Constructs a 3x3 rotation matrix that transforms world-space vectors into camera-local space, given a camera origin and look-at target [S1, unofficial]. It builds an orthogonal camera coordinate system (basis) from a camera center and a look-at point by deriving an up vector orthogonal to the viewing direction, then computing the right vector via cross product [S2, unofficial].
## How it works
**Inputs:**
- `ro`: Camera origin position (world space, vec3) [S1, unofficial].
- `lookAt`: Target point in world space (vec3) [S1, unofficial].
- `up`: Fixed world up vector (vec3, hardcoded as `(0, 1, 0)` in [S1, unofficial] or derived via projection in [S2, unofficial]).

**Outputs:**
- `M`: A 3x3 rotation matrix where columns are the camera's local right, up, and depth vectors [S1, unofficial].
- `basis`: A 4x4 homogeneous matrix if the full extrinsic transform is required, constructed by embedding the 3x3 basis and adding a homogeneous row `[0, 0, 0, 1]` [S2, unofficial].

**Data Structures:**
- Vectors are 3-component floating-point arrays [G].
- The basis matrix is 3x3 (rotation only) or 4x4 (extrinsic transform) [S1, S2, unofficial].

**Steps:**
1. Calculate the viewing direction (depth vector) $d = \text{normalize}(lookAt - ro)$ [S1, unofficial].
2. Define the world up vector $w = (0, 1, 0)$ [S1, unofficial].
3. Compute the camera right vector $r = \text{normalize}(d \times w)$ [S1, unofficial].
4. Compute the camera up vector $u = \text{normalize}(r \times d)$ [S1, unofficial].
5. Construct the 3x3 rotation matrix $M$ with columns $r, u, d$: $M = [r, u, d]$ [S1, unofficial].
Alternative projection method [S2, unofficial]:
1. Calculate depth vector $d = lookAt - ro$ [S2, unofficial].
2. Define world Z-axis $z_{world} = (0, 0, 1)$ [S2, unofficial].
3. Compute projection scalar $\lambda = \frac{z_{world} \cdot d}{d \cdot d}$ [S2, unofficial].
4. Compute orthogonal up vector $u = z_{world} - \lambda d$ [S2, unofficial].
5. Compute right vector $r = \text{cross}(d, u)$ [S2, unofficial].
6. Normalize $r, u, d$ and stack into a 4x4 homogeneous matrix [S2, unofficial].

**Pseudocode:**
```python
import math

def cross(v1, v2):
    return [
        v1[1]*v2[2] - v1[2]*v2[1],
        v1[2]*v2[0] - v1[0]*v2[2],
        v1[0]*v2[1] - v1[1]*v2[0]
    ]

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def normalize(v):
    length = math.sqrt(dot(v, v))
    if length == 0:
        return [0, 0, 0] # [G] Guard against zero vector
    return [v[0]/length, v[1]/length, v[2]/length]

def camera_look_at_basis(lookAt, ro, up_world=None):
    """
    Constructs a 3x3 rotation matrix transforming world vectors to camera space.
    Implements the standard cross-product approach from [S1, unofficial].
    """
    if up_world is None:
        up_world = [0, 1, 0] # Default up vector [S1, unofficial]

    # 1. Calculate depth vector (viewing direction)
    depth_vector = [lookAt[0] - ro[0], lookAt[1] - ro[1], lookAt[2] - ro[2]]
    cd = normalize(depth_vector)

    # 2. Calculate right vector
    cr = normalize(cross(cd, up_world))

    # 3. Calculate true up vector
    cu = normalize(cross(cr, cd))

    # 4. Construct 3x3 matrix
    # [S1, unofficial] returns mat3(cx, cy, cz), meaning columns are right, up, depth.
    M = [
        [cr[0], cu[0], cd[0]],
        [cr[1], cu[1], cd[1]],
        [cr[2], cu[2], cd[2]]
    ]
    return M

def camera_basis_from_depth(camera_depth_z_vector, up_world=None):
    """
    Alternative construction based on [S2, unofficial].
    Projects world Z-axis onto plane orthogonal to depth vector.
    """
    if up_world is None:
        up_world = [0, 0, 1] # [S2, unofficial] uses world Z-axis as reference

    depth_vector = camera_depth_z_vector[:3]

    # Calculate projection lambda
    dot_dd = dot(depth_vector, depth_vector)
    if dot_dd == 0:
        return None # [G] Guard against zero depth vector

    cartesian_z_projection_lambda = dot(depth_vector, up_world) / dot_dd

    # Calculate camera up vector (orthogonal to depth)
    camera_up_vector = [
        up_world[0] - cartesian_z_projection_lambda * depth_vector[0],
        up_world[1] - cartesian_z_projection_lambda * depth_vector[1],
        up_world[2] - cartesian_z_projection_lambda * depth_vector[2]
    ]

    # Calculate camera x vector (right)
    camera_x_vector = cross(depth_vector, camera_up_vector)

    # Normalize
    camera_x_vector = normalize(camera_x_vector)
    camera_up_vector = normalize(camera_up_vector)
    depth_vector = normalize(depth_vector)

    # Stack into 4x4 homogeneous basis
    # [S2, unofficial] stacks [x, up, depth] as rows and adds homogeneous row.
    homogeneous_basis = [
        [camera_x_vector[0], camera_x_vector[1], camera_x_vector[2], 0],
        [camera_up_vector[0], camera_up_vector[1], camera_up_vector[2], 0],
        [depth_vector[0], depth_vector[1], depth_vector[2], 0],
        [0, 0, 0, 1]
    ]
    return homogeneous_basis
```

**Parameters:**
- `lookAt`: Target point in world space [S1, unofficial].
- `ro`: Camera origin position [S1, unofficial].
- `up`: Fixed up vector, hardcoded as `(0, 1, 0)` in [S1, unofficial] or derived via projection in [S2, unofficial].

**Edge Cases:**
- If `ro` equals `lookAt`, the depth vector is zero, leading to division by zero or undefined normalization [G].
- If the viewing direction is parallel to the world up vector, the cross product for the right vector will be zero, leading to an undefined basis [G].
- Precision issues may arise if the depth vector is very small [G].

## Operating characteristics
- **Time Complexity:** $O(1)$, involving a constant number of vector operations (subtraction, dot product, cross product, normalization) [G].
- **Memory Complexity:** $O(1)$, storing a few 3D vectors and a 3x3 or 4x4 matrix [G].
- **Strengths:** Simple to implement and provides a direct way to orient a camera towards a specific point [S1, S2, unofficial].
- **Limitations:** Fails if the viewing direction aligns with the up vector, causing the cross product to yield a zero vector [G]. The choice of up vector directly controls the camera's roll [G].
- **When to use:** When the camera position and target are known, and a specific orientation is required [G].
- **When not to use:** When the camera orientation is defined by spherical angles (use [Orbit Camera Basis Computation](1749-orbit-camera-basis-computation.md)) or when a full projection matrix is needed directly (use [General Perspective Transformation](1845-general-perspective-transformation.md)) [G].

## Background
The look-at function is a standard technique in computer graphics for defining camera orientation [G]. It is widely used in ray tracing, rendering, and 3D modeling [G]. The specific implementation in [S1, unofficial] originates from a signed distance field (SDF) ray marching example. The implementation in [S2, unofficial] originates from a PyTorch guide for Plenoxels/NeRF, focusing on constructing camera matrices for neural rendering [S1, S2, unofficial].
