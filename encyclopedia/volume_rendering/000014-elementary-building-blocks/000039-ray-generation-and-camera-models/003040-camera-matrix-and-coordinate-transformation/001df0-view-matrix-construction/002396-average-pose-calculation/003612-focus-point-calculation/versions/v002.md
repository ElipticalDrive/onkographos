# Focus Point Calculation
Also called: focal axis nearest point
## Overview
Focus Point Calculation finds the 3D point that minimizes the distance to all camera focal axes in a set of poses [S1, S2, unofficial]. It serves as a geometric center for a camera rig, often used to define the center of rotation or the origin for subsequent coordinate transformations [G]. It differs from [Average Pose Calculation](1645-average-pose-calculation.md) by minimizing perpendicular distance to viewing rays rather than averaging origins and directions, and from [Bounding Sphere Estimation](7056-bounding-sphere-estimation.md) by providing a single point rather than a volume [G].
## How it works
### Inputs and Outputs
- **Input**: An array of camera poses. Each pose is a $4 \times 4$ transformation matrix [G]. The array shape is $[N, 4, 4]$, where $N$ is the number of cameras [G].
- **Output**: A 3D vector $\mathbf{p} \in \mathbb{R}^3$ representing the focus point [G].

### Data Structures
- **Poses Array**: A contiguous block of memory or tensor of shape $[N, 4, 4]$ [G].
- **Directions Array**: Extracted from column index 2 of the poses array, shape $[N, 3, 1]$ (or $[N, 3]$ if flattened) [S2, unofficial]. Let this be $\mathbf{D}$.
- **Origins Array**: Extracted from column index 3 of the poses array, shape $[N, 3, 1]$ (or $[N, 3]$ if flattened) [S2, unofficial]. Let this be $\mathbf{O}$.

### Steps
1. **Extract Directions and Origins**: For each camera $i \in \{0, \dots, N-1\}$, extract the viewing direction $\mathbf{d}_i$ from the third column (index 2) and the origin $\mathbf{o}_i$ from the fourth column (index 3) of the pose matrix $P_i$ [S2, unofficial]. Normalize $\mathbf{d}_i$ if not already unit length [G].
2. **Compute Projection Matrices**: For each camera $i$, compute the projection matrix $M_i$ that projects onto the plane perpendicular to the viewing direction $\mathbf{d}_i$ [S2, unofficial]. The formula is:
   $$ M_i = I - \mathbf{d}_i \mathbf{d}_i^T $$
   where $I$ is the $3 \times 3$ identity matrix [G].
3. **Accumulate Sum of Outer Products**: Compute the sum of the outer products of the projection matrices:
   $$ A = \sum_{i=0}^{N-1} M_i^T M_i $$
   Since $M_i$ is symmetric and idempotent ($M_i^T = M_i$ and $M_i^2 = M_i$), this simplifies to $A = \sum_{i=0}^{N-1} M_i$, but the explicit $M_i^T M_i$ form is used to maintain numerical stability [G].
4. **Accumulate Weighted Origins**: Compute the sum of the projection matrices applied to the origins:
   $$ b = \sum_{i=0}^{N-1} M_i \mathbf{o}_i $$
5. **Solve for Focus Point**: Solve the linear system $A \mathbf{p} = b$ for $\mathbf{p}$ [G]. This is done by inverting $A$ (or using a pseudo-inverse if $A$ is singular) and multiplying by $b$:
   $$ \mathbf{p} = A^{-1} b $$
   The mean formulation $\mathbf{p} = (\frac{1}{N}\sum M_i^T M_i)^{-1} (\frac{1}{N}\sum M_i \mathbf{o}_i)$ is mathematically equivalent because the $1/N$ scaling factors cancel during inversion and multiplication [G]. The method is deterministic given the input poses [G].

### Pseudocode
```python
import numpy as np

def calculate_focus_point(poses: np.ndarray) -> np.ndarray:
    """
    Calculate the focus point that minimizes distance to all camera focal axes.
    
    Args:
        poses: Array of shape (N, 4, 4) containing camera transformation matrices.
        
    Returns:
        A 3D vector (np.ndarray of shape (3,)) representing the focus point.
    """
    N = poses.shape[0]
    
    # Extract directions from column 2 (index 2) and origins from column 3 (index 3)
    # Shape: (N, 3)
    directions = poses[:, 2, :3]
    origins = poses[:, 3, :3]
    
    # Normalize directions to ensure they are unit vectors
    norms = np.linalg.norm(directions, axis=1, keepdims=True)
    # Handle potential zero-length directions (degenerate input)
    norms = np.where(norms == 0, 1.0, norms)
    directions = directions / norms
    
    # Initialize accumulators
    # A will be 3x3, b will be 3x1 (or 3,)
    A = np.zeros((3, 3))
    b = np.zeros(3)
    
    for i in range(N):
        d = directions[i]  # Shape (3,)
        o = origins[i]     # Shape (3,)
        
        # Compute projection matrix M = I - d * d^T
        # d is column vector for outer product
        d_col = d.reshape(3, 1)
        d_row = d.reshape(1, 3)
        I_3 = np.eye(3)
        M = I_3 - d_col @ d_row
        
        # Accumulate A = sum(M^T @ M)
        A += M.T @ M
        
        # Accumulate b = sum(M @ o)
        b += M @ o
        
    # Solve for p: A @ p = b
    # Use numpy's linear algebra solver for stability
    try:
        focus_point = np.linalg.solve(A, b)
    except np.linalg.LinAlgError:
        # Fallback to pseudo-inverse if singular
        focus_point = np.linalg.lstsq(A, b, rcond=None)[0]
        
    return focus_point
```

### Parameters
- No explicit hyperparameters. The method is deterministic given the input poses [G].

### Edge Cases and Pitfalls
- **Collinear Cameras**: If all camera centers lie on a single line and all viewing directions are parallel to that line, the matrix $A$ will be singular [G]. The pseudo-inverse should be used [G].
- **Zero-Length Directions**: If a pose matrix has a zero vector in the direction column, normalization must handle division by zero [G].
- **Numerical Precision**: The matrix $A$ should be symmetric positive semi-definite [G].

## Operating characteristics
- **Time Complexity**: $O(N)$, where $N$ is the number of cameras [G]. Each camera requires a constant number of matrix operations ($3 \times 3$) [G].
- **Memory Complexity**: $O(1)$ auxiliary space, excluding the input poses [G].
- **Strengths**: Provides a geometrically meaningful center for camera rigs [G]. Robust to camera translation along the viewing axis [G].
- **Limitations**: Sensitive to outliers in camera positions if the distribution is highly skewed [G]. Not suitable for defining a bounding volume [G].
- **When to use**: When a single reference point is needed for ray generation or coordinate transformation in multi-view reconstruction [G].
- **When not to use**: When a bounding volume is required ([Bounding Sphere Estimation](7056-bounding-sphere-estimation.md)) or when an average pose including orientation is needed ([Average Pose Calculation](1645-average-pose-calculation.md)) [G].

## Background
The method is derived from the least-squares minimization of distances from a point to a set of lines in 3D space [G]. It is commonly used in structure-from-motion and multi-view stereo pipelines to define the origin of the reconstruction coordinate system [G]. The specific implementation details, including the extraction of directions from column 2 and origins from column 3, are documented in the source code of [mrGSplat](https://github.com/meshroomHub/mrGSplat) [S1, unofficial] and [VolSplat](https://github.com/ziplab/VolSplat) [S2, unofficial].
