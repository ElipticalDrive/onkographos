# Average Pose Calculation
Also called: Average Pose Computation, mean pose via SVD
## Overview
Computes an average camera pose from a set of input poses by aggregating their translations and rotations [S1, S2, unofficial]. Implementations differ in how they handle rotation: some sum viewing and up vectors directly, while others use Singular Value Decomposition (SVD) on a mean rotation matrix to enforce orthogonality [S1, S2, unofficial].
## How it works
**Inputs:**
- `poses`: An array of $N$ camera poses, shaped as $[N, 3, 4]$ or $[N, 4, 4]$ [S2, unofficial].
**Outputs:**
- `avg_pose`: A single $3 \times 4$ or $4 \times 4$ matrix representing the average pose [S2, unofficial].
**Data Structures:**
- `poses`: Shape $(N, 3, 4)$ or $(N, 4, 4)$.
- `center`: Shape $(3,)$, the averaged translation vector [S2, unofficial].
- `mean_rot`: Shape $(3, 3)$, the element-wise mean of the rotation sub-matrices [S2, unofficial].
- `avg_rot`: Shape $(3, 3)$, the orthogonalized average rotation matrix [S2, unofficial].
**Steps:**
1. **Compute Average Translation:** Calculate `center` by taking the mean of the translation columns (index 3) of all poses along axis 0 [S2, unofficial].
   $$ \text{center} = \frac{1}{N} \sum_{i=0}^{N-1} \text{poses}_i[:, 3] $$
2. **Compute Rotation or Direction:** Two approaches exist in the literature. The SVD method computes `mean_rot` as the element-wise mean of the rotation sub-matrices (indices 0-2) along axis 0, then applies SVD to obtain $U$ and $V^T$, yielding `avg_rot` $= U V^T$ [S2, unofficial]. The vector method computes `vec2` as the normalized sum of pose viewing directions (column 2) and `up` as the sum of pose up vectors (column 1) [S1, unofficial].
   $$ \text{mean\_rot} = \frac{1}{N} \sum_{i=0}^{N-1} \text{poses}_i[:, :3, :3] $$
   $$ U, \Sigma, V^T = \text{SVD}(\text{mean\_rot}) $$
   $$ \text{avg\_rot} = U V^T $$
3. **Construct Average Pose:** The SVD variant concatenates `avg_rot` and `center` (reshaped to a column vector) along axis 1 to form `avg_pose` [S2, unofficial]. The vector variant extracts `hwf` from the first pose, constructs a camera-to-world matrix using `viewmatrix(vec2, up, center)`, and concatenates `hwf` [S1, unofficial].
**Pseudocode:**
```python
import numpy as np

def average_pose_calculation(poses):
    """
    Compute the average camera pose from a set of poses using SVD for rotation averaging.
    
    Args:
        poses: numpy array of shape (N, 3, 4) or (N, 4, 4) containing camera-to-world matrices.
        
    Returns:
        avg_pose: numpy array of shape (3, 4) representing the average pose.
    """
    # Ensure poses are 3x4 for consistency
    if poses.shape[-2] == 4:
        poses = poses[:, :3, :]
        
    N = poses.shape[0]
    
    # Step 1: Calculate average translation (center)
    center = np.mean(poses[:, :3, 3], axis=0)
    
    # Step 2: Calculate mean rotation and orthogonalize via SVD
    mean_rot = np.mean(poses[:, :3, :3], axis=0)
    U, _, Vt = np.linalg.svd(mean_rot)
    avg_rot = U @ Vt
    
    # Step 3: Construct the average pose matrix
    avg_pose = np.hstack((avg_rot, center.reshape(-1, 1)))
    
    return avg_pose
```
**Parameters:**
- `poses`: Input poses, either $[N, 3, 4]$ or $[N, 4, 4]$ [S2, unofficial].
**Edge Cases and Pitfalls:**
- **Reflection Handling:** If $\det(U V^T) = -1$, the result represents a reflection rather than a proper rotation. Standard implementations often correct this by flipping the sign of the last column of $U$ or $V^T$, but this correction is not detailed in the provided sources [S2, unofficial].
- **Degenerate Input:** If all poses are identical or collinear in rotation space, the mean rotation may be singular, leading to unstable SVD results [G].

## Background
The method originates from implementations in NeRF (Neural Radiance Fields) pipelines for computing a canonical camera pose from a dataset of images [S1, S2, unofficial]. It is commonly referred to as `poses_avg` in codebases such as `bmild/nerf` and `nerf-from-scratch` [S1, S2, unofficial].
