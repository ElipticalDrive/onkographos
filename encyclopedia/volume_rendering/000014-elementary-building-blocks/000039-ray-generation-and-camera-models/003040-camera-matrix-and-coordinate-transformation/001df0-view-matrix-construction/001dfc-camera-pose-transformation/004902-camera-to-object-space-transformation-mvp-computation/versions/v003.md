# Camera-to-Object Space Transformation & MVP Computation

Also called: Box/mesh overlay rendering with MVP matrix, prerender matrix setup, view direction transform

## Overview
This method precomputes the Model-View-Projection (MVP) matrix and transforms camera direction and position into object space for use in shaders, supporting both perspective and orthographic projections [S2, unofficial]. It distinguishes itself by explicitly synchronizing projection types via shader defines and providing inverse-transformed camera parameters for local-space calculations [S2, unofficial]. It builds on [Camera Pose Transformation](1672-camera-pose-transformation.md) by consuming pose data to construct the final transformation chain [G].

## How it works
**Inputs:**
- Camera object with properties: `isPerspectiveCamera` (boolean), viewport dimensions (`viewport_w`, `viewport_h`), field of view (`_fov_deg`), and methods `getWorldDirection()`, `getWorldPosition()` [S2, unofficial].
- Scene configuration: near plane (`0.01`), far plane (`100.0`) [S1, unofficial].
- Model and view matrix construction logic via helper functions [S1, unofficial].

**Outputs:**
- `mvp`: 4x4 matrix (float32) representing the combined transformation [S1, unofficial].
- `local_view_direction`: 3D vector in object space [S2, unofficial].
- `local_camera_position`: 3D vector in object space [S2, unofficial].
- Shader state updates: `material.defines['ENABLE_PERSPECTIVE_PROJECTION']` and `material.needsUpdate` [S2, unofficial].

**Data Structures:**
- `mvp`: `np.float32` array of shape (4, 4) [S1, unofficial].
- `local_view_direction`, `local_camera_position`: 3D vectors (x, y, z) [S2, unofficial].
- `ENABLE_PERSPECTIVE_PROJECTION`: Shader define flag, present (value `1`) or absent (deleted) [S2, unofficial].

**Steps:**
1. **Compute Aspect Ratio:**
   Calculate the aspect ratio to prevent division by zero or distortion:
   $$ \text{aspect\_ratio} = \frac{\text{viewport\_w}}{\max(\text{viewport\_h}, 1)} $$
   [S1, unofficial]

2. **Check Projection Type:**
   Determine if the camera is perspective:
   $$ \text{isPerspective} = \text{camera.isPerspectiveCamera} $$
   [S2, unofficial]
   If `isPerspective` differs from the current state, update the shader material:
   - If perspective: set `material.defines['ENABLE_PERSPECTIVE_PROJECTION'] = 1` [S2, unofficial].
   - If orthographic: delete `material.defines['ENABLE_PERSPECTIVE_PROJECTION']` [S2, unofficial].
   - Set `material.needsUpdate = true` [S2, unofficial].

3. **Compute Projection Matrix:**
   Generate the projection matrix using the field of view, aspect ratio, and clipping planes:
   $$ \text{proj} = \text{perspective\_matrix}(\text{fov\_deg}, \text{aspect\_ratio}, 0.01, 100.0) $$
   [S1, unofficial]

4. **Compute View and Model Matrices:**
   $$ \text{view} = \text{self.\_build\_view\_matrix()} $$
   $$ \text{model} = \text{self.\_build\_model\_matrix()} $$
   [S1, unofficial]

5. **Compute MVP Matrix:**
   Multiply the matrices in the order: Projection, then View, then Model:
   $$ \text{mvp} = (\text{proj} \otimes \text{view} \otimes \text{model}).\text{astype}(\text{np.float32}) $$
   [S1, unofficial]
   Where $\otimes$ denotes matrix multiplication [G].

6. **Transform Camera Direction to Object Space:**
   - Get the world-space direction:
     $$ \text{world\_view\_direction} = \text{camera.getWorldDirection()} $$
   - Apply the inverse of the combined model-view matrix ($M^{-1}$) to get the local direction:
     $$ \text{local\_view\_direction} = \text{world\_view\_direction} \cdot M^{-1} $$
   [S2, unofficial]

7. **Transform Camera Position to Object Space:**
   - Get the world-space position:
     $$ \text{world\_camera\_position} = \text{camera.getWorldPosition()} $$
   - Apply the inverse matrix:
     $$ \text{local\_camera\_position} = \text{world\_camera\_position} \cdot M^{-1} $$
   [S2, unofficial]

8. **Render Overlay:**
   Pass the computed `mvp` to the box/mesh overlay renderer:
   $$ \text{self.\_box\_overlay.render}(\text{mvp}, \text{self.show\_box}, \text{self.show\_mesh}) $$
   [S1, unofficial]

**Pseudocode:**
```python
import numpy as np

def compute_mvp_and_transform(camera, viewport_w, viewport_h, fov_deg, show_box, show_mesh):
    """
    Computes MVP matrix and transforms camera pose to object space.
    """
    # 1. Compute Aspect Ratio
    aspect_ratio = viewport_w / max(viewport_h, 1)
    
    # 2. Check Projection Type and Update Shader Defines
    is_perspective = camera.isPerspectiveCamera
    # Shader state updates are handled externally in the source framework [S2, unofficial]
    
    # 3. Compute Projection Matrix (Standard OpenGL-style perspective [G])
    fov_rad = np.radians(fov_deg)
    f = 1.0 / np.tan(fov_rad / 2.0)
    near = 0.01
    far = 100.0
    proj = np.array([
        [f / aspect_ratio, 0, 0, 0],
        [0, f, 0, 0],
        [0, 0, (far + near) / (near - far), -1],
        [0, 0, (2 * far * near) / (near - far), 0]
    ], dtype=np.float32)
    
    # 4. Compute View and Model Matrices
    # View and model matrix construction logic is not provided in the sources [S1, unofficial]
    view = np.eye(4, dtype=np.float32)  # Not provided in sources [S1, unofficial]
    model = np.eye(4, dtype=np.float32) # Not provided in sources [S1, unofficial]
    
    # 5. Compute MVP Matrix
    mvp = (proj @ view @ model).astype(np.float32)
    
    # 6. Transform Camera Direction to Object Space
    world_view_direction = np.array(camera.getWorldDirection(), dtype=np.float32)
    # Compute inverse of combined model-view matrix
    mv = view @ model
    mv_inv = np.linalg.inv(mv)
    # Direction vectors use only the rotation part (upper 3x3) to ignore translation [G]
    local_view_direction = (mv_inv[:3, :3] @ world_view_direction)
    
    # 7. Transform Camera Position to Object Space
    world_camera_position = np.array(camera.getWorldPosition(), dtype=np.float32)
    # Position vectors use the full 4x4 inverse with homogeneous coordinate w=1 [G]
    pos_homogeneous = np.append(world_camera_position, 1.0)
    local_pos_homogeneous = mv_inv @ pos_homogeneous
    local_camera_position = local_pos_homogeneous[:3]
    
    # 8. Render Overlay
    # self._box_overlay.render(mvp, show_box, show_mesh) [S1, unofficial]
    
    return mvp, local_view_direction, local_camera_position
```

**Parameters:**
- `ENABLE_PERSPECTIVE_PROJECTION`: Shader define flag. If present, the fragment shader uses perspective projection logic; if deleted, it uses orthographic logic [S2, unofficial].
- `u_time`: Uniform set to `0.0` (hardcoded, noted as FIXME) [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Division by Zero:** Aspect ratio calculation uses `max(viewport_h, 1)` to prevent division by zero if height is zero [S1, unofficial].
- **Shader Synchronization:** Failure to update `material.needsUpdate` when projection type changes will result in incorrect rendering [S2, unofficial].
- **Vector vs. Point Transformation:** Direction vectors should not be translated; using the full 4x4 matrix inverse on a direction vector without isolating the rotation submatrix introduces translation errors [G]. The sources imply `applyMatrix4` handles this correctly for directions [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources [G].
- **Memory Complexity:** Not given in the sources [G].
- **Strengths:** Centralizes transformation logic for overlays and handles both perspective and orthographic projections seamlessly via shader defines [S2, unofficial].
- **Limitations:** The `u_time` uniform is hardcoded to `0.0`, limiting dynamic time-based effects in overlays [S2, unofficial]. The method relies on specific helper functions (`_build_view_matrix`, `_build_model_matrix`) whose implementation details are not provided [S1, unofficial].
- **When to Use:** When rendering 3D overlays aligned with the camera view in a volume rendering pipeline [S1, S2, unofficial].
- **When Not to Use:** Not given in the sources [G].

## Background
This method is derived from the `unray` and `clearvolume-plus` projects, which are unofficial implementations of volume rendering tools [S1, S2, unofficial]. It addresses the need for consistent coordinate transformation between camera space and object space for overlay rendering in web-based or Python-based frameworks [G]. The approach of using shader defines to toggle projection types is a common pattern in WebGL-based renderers [S2, unofficial].
