# Camera Pose Transformation

Also called: Camera Offset and Rotation, Pose Transformation, RotateX

## Overview
Camera Pose Transformation applies translation and rotation to points or coordinate systems to position cameras or deform scenes [S2, unofficial]. It maps local scene coordinates to world space or adjusts camera extrinsics relative to a reference frame [S3, unofficial]. It operates directly on points or pose structures rather than constructing a full view matrix from basis vectors [S2, unofficial][S3, unofficial].

## How it works
**Inputs:**
- A point $p = (x, y, z)$ or a set of points in 3D space [S2, unofficial].
- A rotation angle $\theta$ (float) [S1, unofficial].
- A translation vector $t$ (optional, e.g., $[0, -1, -2.2]$) [S2, unofficial].
- A cell scale factor `cell_size_m` (optional, for RigidXform contexts) [S3, unofficial].

**Outputs:**
- The transformed point $p'$ or the adjusted camera pose [S2, unofficial][S3, unofficial].

**Data Structures:**
- Points are represented as 3D vectors $(x, y, z)$ [S2, unofficial].
- Poses may be stored as quaternions combined with translation vectors [S3, unofficial].
- Rigid transformations map local cell space to world metres via scaling, rotation, and translation [S3, unofficial].

**Steps:**

1. **Translation (Offset):** If a translation vector $t = (t_x, t_y, t_z)$ is provided, add it to the point $p$:
   $$
   p_{offset} = p + t
   $$
   Example: Offset by $[0, -1, -2.2]$ [S2, unofficial].

2. **Rotation:** Apply rotation around a specified axis by angle $\theta$.
   - **RotateY:** Rotate around the Y-axis. The $x$ component remains unchanged. The $y$ and $z$ components are transformed using a 2D rotation matrix:
     $$
     \begin{aligned}
     y' &= y \cos(\theta) + z \sin(\theta) \\
     z' &= -y \sin(\theta) + z \cos(\theta)
     \end{aligned}
     $$
     [S2, unofficial]
   - **RotateX:** Rotate around the X-axis. The $y$ and $z$ components are transformed:
     $$
     \begin{aligned}
     y' &= y \cos(\theta) - z \sin(\theta) \\
     z' &= y \sin(\theta) + z \cos(\theta)
     \end{aligned}
     $$
     [S1, unofficial]
   - **RotateZ:** Rotate around the Z-axis. The $x$ and $y$ components are transformed:
     $$
     \begin{aligned}
     x' &= x \cos(\theta) - y \sin(\theta) \\
     y' &= x \sin(\theta) + y \cos(\theta)
     \end{aligned}
     $$
     [S1, unofficial]

3. **RigidXform Construction:** To map local cell space to world metres, construct a transformation from a pose:
   - Dequantise and renormalise the quaternion from the pose [S3, unofficial].
   - Reject if the orientation is zero [S3, unofficial].
   - Apply uniform cell scale, rotation, and translation: $p_{world} = (p_{local} \times \text{cell\_size\_m}) \times R + t$ [S3, unofficial].

**Pseudocode:**

```python
import math

def rotate_y(p, angle):
    """Rotates point p around the Y-axis by angle (radians). Based on [S2, unofficial]."""
    x, y, z = p
    cos_a = math.cos(angle)
    sin_a = math.sin(angle)
    # Use temporary variables to avoid cascading errors from intermediate updates [G]
    new_y = cos_a * y + sin_a * z
    new_z = -sin_a * y + cos_a * z
    return (x, new_y, new_z)

def rotate_x(p, angle):
    """Rotates point p around the X-axis by angle (radians). Based on [S1, unofficial]."""
    x, y, z = p
    cos_a = math.cos(angle)
    sin_a = math.sin(angle)
    new_y = y * cos_a - z * sin_a
    new_z = y * sin_a + z * cos_a
    return (x, new_y, new_z)

def rotate_z(p, angle):
    """Rotates point p around the Z-axis by angle (radians). Based on [S1, unofficial]."""
    x, y, z = p
    cos_a = math.cos(angle)
    sin_a = math.sin(angle)
    new_x = x * cos_a - y * sin_a
    new_y = x * sin_a + y * cos_a
    return (new_x, new_y, z)

def transform_point(p, translation=None, rotation_axis='y', rotation_angle=0.0):
    """Applies translation and rotation to point p."""
    if translation:
        p = (p[0] + translation[0], p[1] + translation[1], p[2] + translation[2])
    if rotation_angle != 0.0:
        if rotation_axis == 'x':
            p = rotate_x(p, rotation_angle)
        elif rotation_axis == 'y':
            p = rotate_y(p, rotation_angle)
        elif rotation_axis == 'z':
            p = rotate_z(p, rotation_angle)
        else:
            raise ValueError("Unsupported rotation axis")
    return p

def quaternion_rotate(q, v):
    """Standard quaternion-vector rotation [G]."""
    # q = (w, x, y, z), v = (vx, vy, vz)
    t = 2.0 * (q[1]*v[0] + q[2]*v[1] + q[3]*v[2])
    return (
        v[0] + q[0]*t + 2.0*(q[2]*(q[3]*v[0] - q[1]*v[2]) - q[1]*(q[0]*v[0] + q[3]*v[1] - q[2]*v[2])),
        v[1] + q[1]*t + 2.0*(q[3]*(q[3]*v[0] - q[1]*v[2]) - q[2]*(q[0]*v[0] + q[3]*v[1] - q[2]*v[2])),
        v[2] + q[2]*t + 2.0*(q[1]*(q[3]*v[0] - q[1]*v[2]) - q[3]*(q[0]*v[0] + q[3]*v[1] - q[2]*v[2]))
    )

def build_rigid_xform(pose, cell_size_m):
    """Constructs RigidXform from a Pose by dequantising and normalising the quaternion. Based on [S3, unofficial]."""
    q = (pose.qw, pose.qx, pose.qy, pose.qz)
    mag = math.sqrt(q[0]**2 + q[1]**2 + q[2]**2 + q[3]**2)
    if mag == 0:
        raise ValueError("Zero orientation rejected")
    q = (q[0]/mag, q[1]/mag, q[2]/mag, q[3]/mag)
    
    def transform(p_local):
        p_scaled = (p_local[0] * cell_size_m, p_local[1] * cell_size_m, p_local[2] * cell_size_m)
        p_rotated = quaternion_rotate(q, p_scaled)
        return (p_rotated[0] + pose.tx, p_rotated[1] + pose.ty, p_rotated[2] + pose.tz)
    return transform
```

**Parameters:**
- `angle`: Float representing the rotation angle [S1, unofficial].
- `translation`: Vector $(t_x, t_y, t_z)$ for offsetting the origin [S2, unofficial].
- `cell_size_m`: Uniform scale factor converting local cells to world metres [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Normalising quaternions ensures the conjugate is the exact inverse of the rotation [S3, unofficial].
- **Zero Orientation:** Reject poses with zero orientation to avoid undefined rotation [S3, unofficial].
- **Boundary Conditions:** In ray traversal, origins exactly on a boundary belong to the cell defined by the floor function [S3, unofficial].
- **Zero Direction:** Zero or non-finite ray directions must return an error [S3, unofficial].
- **Variable Reuse:** Rotation formulas must use temporary variables for updated components to avoid cascading errors from intermediate updates [G].

## Subtopics

### RotateY
RotateY is a geometric transformation primitive that rotates a point or shape around the Y-axis in 3D space [S2, unofficial]. It serves as a fundamental building block for constructing camera poses and deforming Signed Distance Fields (SDFs) [G]. Unlike [Rotation Transformation](2279-rotation-transformation.md), which may imply a general rotation matrix, RotateY specifically isolates the Y-axis component, and unlike [Twist](1722-twist.md), it applies a uniform rotation angle to the entire object rather than a spatially varying one [G]. It is a sibling to [RotateX](2278-rotatex.md) and [RotateZ](2280-rotatez.md) [S1, unofficial].

### RotateZ
Similar to RotateX, but rotates around the z-axis instead [S1, unofficial]. It takes a float input representing the angle of rotation [S1, unofficial].

### [Pose Recentering](1786-pose-recentering.md)
Recenters a set of poses such that their average pose becomes the identity transformation (origin at center, aligned axes) [G]. It involves computing the average pose, constructing a transformation matrix, and left-multiplying all poses by the inverse of the average pose [G].

### [Rotation Transformation](2279-rotation-transformation.md)
Rotation Transformation constructs a 4×4 homogeneous rotation matrix to rotate a shape or vector around a specified axis by a given angle. It sets itself apart from [Quaternion Rotation](2302-quaternion-rotation.md) by yielding an explicit matrix representation rather than using quaternion algebra, and from [SE2 Lie Group Implementation](3144-se2-lie-group-implementation.md) by operating in 3D space rather than 2D [G].

### [Rotation Matrix Computation](2280-rotation-matrix-computation.md)
Computes a 3x3 rotation matrix given a rotation axis and an angle using Rodrigues' rotation formula components. It differs from [RotateY](1720-rotatey.md) and [Rotation Transformation](2279-rotation-transformation.md) by accepting an arbitrary axis vector rather than fixed coordinate axes, and from [Camera Matrix Decomposition](3164-camera-matrix-decomposition.md) by constructing the matrix directly from geometric parameters rather than decomposing an existing matrix [G].

### [Translation Transformation](2281-translation-transformation.md)
A geometric transformation that moves a shape by a given vector. It adjusts positional offsets without altering orientation, distinguishing it from rotation transformations [G].

### [C-Arm to Camera Parameters Conversion](2589-c-arm-to-camera-parameters-conversion.md)
This method converts C-arm geometric parameters (Source-to-Image Distance, AP angle, lateral angle, center, table translation) into camera position, look-at point, and up vector in RAS coordinates. It explicitly models the C-arm's mechanical degrees of freedom (AP and lateral tilts) relative to a patient-centered coordinate system to generate synthetic Digital Radiography (DRR) views.

### [Camera Matrix Decomposition](3164-camera-matrix-decomposition.md)
Decomposes a 3x4 projection matrix into intrinsic matrix $K$, rotation matrix $R$, and translation vector $t$. It extracts the camera's internal parameters and external pose from a combined projection matrix, enabling the separation of optical properties from physical camera position and orientation.

### [Camera Coordinate Homogenization and Rigid Transformation](4005-camera-coordinate-homogenization-and-rigid-transformation.md)
A method to apply rigid transformations to camera coordinates by first homogenizing points (appending 1) and vectors (appending 0), then applying the transformation via matrix multiplication [G].

The specific implementations cited here are from a COS 426 final project on raymarching with SDFs [S1, unofficial], an Observable notebook on raymarching distance functions [S2, unofficial], and a fixture world implementation in the spall repository [S3, unofficial].
