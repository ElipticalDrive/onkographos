# RotateY
Also called: Y-axis rotation, Rotate around Y
## Overview
RotateY is a geometric transformation primitive that rotates a point or shape around the Y-axis in 3D space [S1, unofficial]. It serves as a fundamental building block for constructing camera poses and deforming Signed Distance Fields (SDFs) [G]. Unlike [Rotation Transformation](2279-rotation-transformation.md), which may imply a general rotation matrix, RotateY specifically isolates the Y-axis component [G]. Unlike [Twist](1722-twist.md), it applies a uniform rotation angle to the entire object rather than a spatially varying one [G]. It is a sibling to [RotateX](2278-rotatex.md) and [RotateZ](2280-rotatez.md) [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A 3D point $P = (x, y, z)$ and a rotation angle $\theta$ [S1, unofficial].
- Output: A transformed 3D point $P' = (x', y', z')$ [G].
**Data Structures:**
The input point is typically represented as a 3-component vector [G]. The angle is a scalar float [G].
**Method:**
The rotation occurs in the XZ plane, leaving the Y-coordinate invariant [G]. The transformation is defined by the following equations:
$$x' = x \cos(\theta) - z \sin(\theta)$$
$$y' = y$$
$$z' = x \sin(\theta) + z \cos(\theta)$$
**Parameters:**
- $\theta$: The angle of rotation [S1, unofficial].
**Pseudocode:**
```python
from math import cos, sin

def rotate_y(point, angle):
    x, y, z = point
    cos_a = cos(angle)
    sin_a = sin(angle)
    x_prime = x * cos_a - z * sin_a
    y_prime = y
    z_prime = x * sin_a + z * cos_a
    return (x_prime, y_prime, z_prime)
```
**Edge Cases and Pitfalls:**
- **Angle Units:** Ensure consistency between the angle input and the trigonometric functions' expected units (radians vs. degrees) [G]. Standard mathematical libraries expect radians [G].
- **Precision:** For very small angles, standard floating-point precision is sufficient [G]. For large numbers of cumulative rotations, consider normalizing the angle to $[0, 2\pi)$ to avoid precision loss [G].
## Subtopics

### [Twist](1722-twist.md)
A geometric deformation that twists a shape around the Y-axis proportional to its height [G]. It sets itself apart from RotateY by applying a spatially varying rotation angle that depends on the Y-coordinate, creating a gradient along the vertical axis [G]. Choose it when creating helical or spiral variations of rigid primitives, such as twisting a cylinder into a corkscrew [G].

## Operating characteristics
- **Time Complexity:** $O(1)$ per point transformation [G]. Requires two multiplications, two additions/subtractions, and two trigonometric evaluations per point [G].
- **Memory Complexity:** $O(1)$ auxiliary space [G].
- **Strengths:** Simple, computationally inexpensive, and numerically stable for standard ranges [G].
- **Limitations:** Only rotates around a single axis and cannot represent combined rotations without composition [G].
## Background
RotateY is a standard elementary transformation in computer graphics, derived from the fundamental rotation matrices in linear algebra [G]. It is widely used in raymarching shaders for SDF deformation and in camera pose construction to orient the view direction [G]. Its implementation in educational raymarching contexts, such as the COS 426 Final Project Writeup, follows the same pattern as RotateX and RotateZ, taking a single float input for the rotation degree [S1, unofficial].
