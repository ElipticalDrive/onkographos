# Twist
Also called: Twist Transformation

## Overview
Twist is a geometric deformation operation for Signed Distance Fields (SDFs) that twists a shape around the Y-axis proportional to its height [S1, S2, S3, unofficial]. It solves the problem of creating helical or spiral variations of rigid primitives, such as twisting a cylinder into a corkscrew [S1, S3, unofficial]. Unlike [RotateY](1720-rotatey.md), which applies a uniform rotation to the entire object, Twist applies a spatially varying rotation where the angle depends on the Y-coordinate, creating a gradient of rotation along the vertical axis [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A point $p = (p_x, p_y, p_z)$ in local space, and a twist factor $k$ (float) [S1, S2, S3, unofficial].
- Output: A transformed point $p'$ in local space [S1, S2, unofficial].

**Data Structures:**
- No persistent data structures. The transformation is computed per-point during SDF evaluation [S1, S2, unofficial].

**Steps:**
1. Calculate the twist angle $\theta$ based on the Y-coordinate and the twist factor:
   $$ \theta = k \cdot p_y $$
   [S1, S2, unofficial]
2. Compute the sine and cosine of the angle:
   $$ c = \cos(\theta) $$
   $$ s = \sin(\theta) $$
   [S1, S2, unofficial]
3. Apply a 2D rotation matrix to the X and Z components of the point, leaving the Y component unchanged:
   $$ p'_x = c \cdot p_x - s \cdot p_z $$
   $$ p'_y = p_y $$
   $$ p'_z = s \cdot p_x + c \cdot p_z $$
   [S1, S2, unofficial]

**Pseudocode:**
```python
def twist(p: Vec3, k: float) -> Vec3:
    """
    Twists space around the Y-axis proportional to height.
    
    Args:
        p: Input point (x, y, z).
        k: Twist factor controlling the rate of twist.
        
    Returns:
        Transformed point.
    """
    angle = k * p.y
    cos_a = cos(angle)
    sin_a = sin(angle)
    
    # Rotate XZ plane
    new_x = cos_a * p.x - sin_a * p.z
    new_y = p.y
    new_z = sin_a * p.x + cos_a * p.z
    
    return Vec3(new_x, new_y, new_z)
```

**Parameters:**
- $k$: The twist factor. A value of 0 results in no twist. Positive values create a right-handed twist, negative values create a left-handed twist [S1, S3, unofficial]. Typical values depend on the desired visual effect; [S1, unofficial] uses 0.5 as an example.

**Edge Cases and Pitfalls:**
- **Precision:** For very large values of $k \cdot p_y$, the sine and cosine calculations may suffer from precision loss if not handled carefully, though standard floating-point arithmetic is usually sufficient for typical SDF scenes [G].
- **Boundaries:** The twist is continuous across the entire space. However, if the SDF is evaluated at discrete steps during raymarching, the discontinuity between steps might become visible if the twist rate is extremely high relative to the step size [G].

## Subtopics

### Bend Transformation
Bend is a geometric deformation operation for SDFs that curves a shape around the X-axis [S1, S3, unofficial]. It solves the problem of creating organic, curved variations of rigid primitives, such as bending a cylinder into an arc [S3, unofficial]. Unlike [Twist](1722-twist.md), which rotates geometry around the Y-axis with a linear or angular progression, Bend applies a spatially varying rotation around the X-axis, creating a smooth arc [S1, S3, unofficial].

**Definition:** Bends space along the X-axis around the Y-axis [S2, unofficial].

**Steps:**
1. Calculate the bend angle $\theta$ based on the X-coordinate and a bend factor $k$:
   $$ \theta = k \cdot p_x $$
   [S2, unofficial]
2. Compute the sine and cosine of the angle:
   $$ c = \cos(\theta) $$
   $$ s = \sin(\theta) $$
   [S2, unofficial]
3. Apply a 2D rotation matrix to the X and Y components of the point, leaving the Z component unchanged:
   $$ p'_x = c \cdot p_x - s \cdot p_y $$
   $$ p'_y = s \cdot p_x + c \cdot p_y $$
   $$ p'_z = p_z $$
   [S2, unofficial]

**Pseudocode:**
```python
def bend(p: Vec3, k: float) -> Vec3:
    """
    Bends space along the X-axis around the Y-axis.
    
    Args:
        p: Input point (x, y, z).
        k: Bend factor controlling the degree of bending.
        
    Returns:
        Transformed point.
    """
    angle = k * p.x
    cos_a = cos(angle)
    sin_a = sin(angle)
    
    # Rotate XY plane
    new_x = cos_a * p.x - sin_a * p.y
    new_y = sin_a * p.x + cos_a * p.y
    new_z = p.z
    
    return Vec3(new_x, new_y, new_z)
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per point evaluation. The transformation involves a constant number of arithmetic operations (multiplications, additions, trigonometric functions) [S1, S2, unofficial].
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the input point and temporary variables [S1, S2, unofficial].
- **Strengths:** Simple to implement and computationally inexpensive. Allows for the creation of complex, organic shapes from simple primitives [S1, S3, unofficial].
- **Limitations:** The transformation is non-linear, which can complicate analytical normal calculation if not derived carefully. The normal must be transformed using the inverse transpose of the Jacobian of the transformation to remain perpendicular to the deformed surface [G].
- **When to use:** When a helical or spiral deformation is desired for a primitive [S1, S3, unofficial].
- **When not to use:** When a uniform rotation is sufficient (use [RotateY](1720-rotatey.md)) or when a simple arc is desired (use [Bend](2044-bend.md)) [S1, S3, unofficial].

## Background
Twist is a standard geometric transformation used in Signed Distance Field (SDF) raymarching, popularized by Inigo Quilez's articles on SDFs [S1, S3, unofficial]. It is often used in conjunction with other transformations like translation, rotation, and scaling to create complex scenes [S1, unofficial]. The method is implemented in various educational and hobbyist raymarching projects, such as the Torch-Sphere-Tracer and sdf-math-rs repositories [S1, S2, unofficial].
