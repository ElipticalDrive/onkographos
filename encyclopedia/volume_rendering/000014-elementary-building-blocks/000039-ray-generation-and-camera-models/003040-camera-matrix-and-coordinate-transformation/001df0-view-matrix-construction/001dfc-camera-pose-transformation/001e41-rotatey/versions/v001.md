# RotateY

Also called: Y-axis rotation, Rotate around Y

## Overview
RotateY is a geometric transformation primitive that rotates a point or shape around the Y-axis in 3D space. It serves as a fundamental building block for constructing camera poses and deforming Signed Distance Fields (SDFs). Unlike [Rotation Transformation](2279-rotation-transformation.md), which may imply a general rotation matrix, RotateY specifically isolates the Y-axis component, and unlike [Twist](1722-twist.md), it applies a uniform rotation angle to the entire object rather than a spatially varying one. It is a sibling to [RotateX](2278-rotatex.md) and [RotateZ](2280-rotatez.md).

## How it works
**Inputs and Outputs:**
- Input: A 3D point $P = (x, y, z)$ and a rotation angle $\theta$ (in radians or degrees, depending on implementation convention).
- Output: A transformed 3D point $P' = (x', y', z')$.

**Data Structures:**
The input point is typically represented as a 3-component vector. The angle is a scalar float.

**Method:**
The rotation occurs in the XZ plane, leaving the Y-coordinate invariant. The transformation is defined by the following equations:

$$
x' = x \cos(\theta) - z \sin(\theta)
$$
$$
y' = y
$$
$$
z' = x \sin(\theta) + z \cos(\theta)
$$

**Parameters:**
- $\theta$: The angle of rotation. Typical values range from $0$ to $2\pi$.

**Pseudocode:**
```python
def rotate_y(point, angle):
    """
    Rotates a 3D point around the Y-axis by a given angle.
    
    Args:
        point: A tuple or list of three floats (x, y, z).
        angle: A float representing the rotation angle in radians.
        
    Returns:
        A tuple or list of three floats (x', y', z').
    """
    x, y, z = point
    cos_a = cos(angle)
    sin_a = sin(angle)
    
    x_prime = x * cos_a - z * sin_a
    y_prime = y
    z_prime = x * sin_a + z * cos_a
    
    return (x_prime, y_prime, z_prime)
```

**Edge Cases and Pitfalls:**
- **Angle Units:** Ensure consistency between the angle input and the trigonometric functions' expected units (radians vs. degrees). [G] Standard mathematical libraries (e.g., Python's `math`) expect radians.
- **Precision:** For very small angles, standard floating-point precision is sufficient. For large numbers of cumulative rotations, consider normalizing the angle to $[0, 2\pi)$ to avoid precision loss.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(1)$ per point transformation. Requires two multiplications, two additions/subtractions, and two trigonometric evaluations per point.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Strengths:** Simple, computationally inexpensive, and numerically stable for standard ranges.
- **Limitations:** Only rotates around a single axis. Cannot represent combined rotations without composition.

## Background
RotateY is a standard elementary transformation in computer graphics, derived from the fundamental rotation matrices in linear algebra. It is widely used in raymarching shaders for SDF deformation and in camera pose construction to orient the view direction. The specific implementation details are consistent across various graphics programming contexts, including the COS 426 Final Project Writeup which documents its use in raymarching with SDFs [S1, unofficial].
