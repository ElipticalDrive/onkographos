# Coarse Camera Pose Estimation

Also called: DSAC-based PnP registration, 2D-3D pose initialization

## Overview
Coarse Camera Pose Estimation initializes the camera pose for a target image by establishing 2D-3D correspondences between the target image and a registered reference image using a scene regressor, then solving for the pose via Direct Linear Transform (DSAC) and Perspective-n-Point (PnP) with RANSAC. It differs from [Iterative Closest Point (ICP)](10563-iterative-closest-point-icp.md) by relying on learned semantic or geometric features from a neural scene regressor rather than iterative point-cloud alignment, and from [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md) by providing the initial seed for incremental training rather than refining an existing estimate via closed-form SVD.

## How it works
**Inputs:**
- Registered reference image $I_{ref}$ (or $I_i$).
- Target image $I_k$ to be registered.
- Camera intrinsic matrix $K$ (potentially with distinct focal lengths $f_x, f_y$).
- Inlier threshold $s_{inlier} = 5,000$ [S1, unofficial].
- Reprojection error threshold $\epsilon_{reproj} = 6$ pixels [S1, unofficial].

**Outputs:**
- Coarse camera pose $T_{coarse}$ for $I_k$.
- Inlier count $S_k$.
- Boolean flag indicating whether $I_k$ is added to the training buffer.

**Data Structures:**
- Scene Regressor $f_{SCR}$: A neural network (e.g., transformer-based) mapping $(I_{ref}, I_k)$ to a set of 3D points $\{X_k\}$ in the global coordinate frame.
- Pixel coordinates $\{u_k\}$: 2D image coordinates for each pixel in $I_k$.
- 2D-3D Correspondences: Set $\{(u_k, X_k)\}$.

**Steps:**
1. **Scene Regression:** Pass $I_{ref}$ and $I_k$ to the scene regressor $f_{SCR}$ to obtain 3D points $\{X_k\}$ in the global coordinate frame [S1, unofficial].
   $$ \{X_k\} = f_{SCR}(I_{ref}, I_k) $$
2. **Correspondence Generation:** For each pixel $u_k$ in $I_k$, pair it with its corresponding 3D point $X_k$ from the regressor output to form 2D-3D correspondences $\{(u_k, X_k)\}$ [S1, unofficial].
3. **Pose Estimation (DSAC + PnP):** Use Direct Space Alignment of Correspondences (DSAC) with RANSAC to estimate the pose, followed by Perspective-n-Point (PnP) refinement [S1, unofficial].
   $$ T_{coarse}, S_k = \text{PnP}(K, \{(u_k, X_k)\}) $$
   Note: DSAC is modified to support different focal lengths for the x-axis and y-axis [S1, unofficial].
4. **Inlier Validation:** Count the number of inliers $S_k$ based on the reprojection error threshold (6 pixels) [S1, unofficial].
5. **Buffer Update:** If $S_k > s_{inlier}$ (where $s_{inlier} = 5,000$), add $I_k$ to the training buffer [S1, unofficial].

**Pseudocode:**
```python
def coarse_camera_pose_estimation(I_ref, I_k, K, s_inlier=5000, epsilon_reproj=6.0):
    # Step 1: Get 3D points from scene regressor
    # f_scr is the pre-trained scene regressor (e.g., transformer)
    X_k = f_scr(I_ref, I_k)
    
    # Step 2: Generate 2D-3D correspondences
    # u_k are pixel coordinates for all pixels in I_k
    # Correspondences is a list of tuples (u_k, X_k)
    correspondences = []
    for u_k in get_pixel_coordinates(I_k):
        X_k_point = get_corresponding_3d_point(u_k, X_k)
        correspondences.append((u_k, X_k_point))
        
    # Step 3: Estimate pose using DSAC with RANSAC and PnP
    # DSAC is modified to handle distinct fx and fy in K
    T_coarse, inlier_indices = dsac_ransac_pnp(K, correspondences, epsilon_reproj)
    
    # Step 4: Count inliers
    S_k = len(inlier_indices)
    
    # Step 5: Validate and return
    is_valid = S_k > s_inlier
    return T_coarse, S_k, is_valid
```

**Edge Cases and Pitfalls:**
- **Gauge Ambiguity:** The camera pose of the seed image is fixed during optimization to resolve gauge ambiguity [S1, unofficial].
- **Scale Ambiguity:** The scaling factor between the seed image and its most similar adjacent image is fixed to resolve scale ambiguity [S1, unofficial].
- **Regressor Accuracy:** If the scene regressor has not seen the target image type, the initial pose may be inaccurate. However, experiments show that a separate MLP pose refiner does not improve accuracy with transformer-based regressors [S1, unofficial].
- **Focal Lengths:** Standard DSAC assumes equal focal lengths; the method requires modification to support distinct $f_x$ and $f_y$ [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** Dominated by the inference of the scene regressor $f_{SCR}$ and the RANSAC iterations in DSAC/PnP. The regressor is typically a transformer, which is computationally heavy.
- **Memory Complexity:** Requires storing the 3D points $\{X_k\}$ for the target image and the training buffer of registered images.
- **Performance:** Effective for initializing unposed images in incremental NeRF/3DGS training. The high inlier threshold (5,000) ensures robust registration but may exclude images with sparse or noisy regressor outputs.
- **Strengths:** Provides a robust initial pose for incremental training without requiring iterative refinement during the initialization phase.
- **Limitations:** Relies heavily on the accuracy of the scene regressor. Inaccurate regressor outputs lead to poor correspondences and failed registration.

## Background
Coarse Camera Pose Estimation is a key component in incremental training pipelines for Neural Radiance Fields (NeRF) and 3D Gaussian Splatting (3DGS) from unposed images. It was introduced in the context of ZeroGS [S1, unofficial], which aims to train these models without pre-computed camera poses. The method builds on [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md) by providing the initial seed poses that are subsequently refined during the training process.
