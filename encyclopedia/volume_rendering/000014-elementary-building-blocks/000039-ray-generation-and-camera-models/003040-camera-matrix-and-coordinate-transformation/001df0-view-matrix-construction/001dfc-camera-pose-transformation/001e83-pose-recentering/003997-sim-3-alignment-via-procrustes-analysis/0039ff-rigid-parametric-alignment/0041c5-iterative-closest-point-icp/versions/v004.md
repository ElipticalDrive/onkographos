# Iterative Closest Point (ICP)

Also called: ICP Alignment, Iterative Closest Point (ICP) Alignment, Point-to-Point ICP Alignment

## Overview
Iterative Closest Point (ICP) is a registration algorithm that computes an optimal rigid transformation to align two point sets, typically a reconstructed point cloud and a ground truth mesh or another point cloud [S2, S3]. It solves the problem of spatial alignment by iteratively minimizing the distance between corresponding points in the two sets. Unlike [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md), which requires explicit correspondences and uses a closed-form SVD solution, ICP automatically establishes correspondences by finding the nearest neighbors in each iteration [S2]. It is primarily used to align reconstructed meshes or point clouds to a ground truth metric space for geometric evaluation [S1, unofficial][S3].

## How it works
**Inputs:**
1.  `source_cloud`: A set of points (e.g., vertices from a reconstructed mesh or point cloud) to be aligned.
2.  `target_cloud`: A set of points (e.g., vertices from a ground truth mesh or reference point cloud).
3.  `threshold`: Maximum correspondence distance for point matching. Default value is 0.1 [S1, unofficial].

**Outputs:**
1.  `T`: A 4x4 rigid transformation matrix (rotation and translation) that aligns `source_cloud` to `target_cloud`.

**Data Structures:**
*   `source_cloud`: List or array of 3D points $(x, y, z)$.
*   `target_cloud`: List or array of 3D points $(x, y, z)$.
*   `T`: 4x4 matrix, initialized as identity.

**Steps:**
1.  **Preprocessing:** Convert input triangle meshes into point clouds using their vertex coordinates [S1, unofficial].
2.  **Initialization:** Initialize the transformation matrix $T$ to a 4x4 identity matrix $I$ [S1, unofficial].
3.  **Iteration:** Repeat the following steps until convergence or a maximum number of iterations is reached:
    a.  **Correspondence:** For each point $p_i$ in `source_cloud`, find the closest point $q_i$ in `target_cloud` based on Euclidean distance. If the distance exceeds `threshold`, the correspondence is ignored or the point is discarded [S1, unofficial].
    b.  **Transformation Estimation:** Compute the optimal rigid transformation (rotation $R$ and translation $t$) that minimizes the sum of squared distances between the corresponding points $(p_i, q_i)$. This is typically done using Singular Value Decomposition (SVD) or similar closed-form solvers for the Procrustes problem [S2, S3].
    c.  **Update:** Update $T$ by composing the newly computed transformation with the current $T$.
    d.  **Apply:** Apply $T$ to `source_cloud`.
4.  **Return:** Extract and return the resulting transformation matrix $T$ [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def icp(source_cloud, target_cloud, threshold=0.1, max_iterations=100):
    """
    Perform Iterative Closest Point registration.
    
    Args:
        source_cloud: np.ndarray of shape (N, 3), points to align.
        target_cloud: np.ndarray of shape (M, 3), reference points.
        threshold: float, maximum distance for valid correspondence.
        max_iterations: int, maximum number of iterations.
        
    Returns:
        T: np.ndarray of shape (4, 4), rigid transformation matrix.
    """
    # Initialize transformation matrix as identity
    T = np.eye(4)
    
    # Convert to homogeneous coordinates for matrix multiplication if needed, 
    # but here we work with 3D points and separate R, t
    current_source = source_cloud.copy()
    
    for i in range(max_iterations):
        # Step 1: Find closest points (Correspondence)
        # Compute distances between all pairs (N, M)
        # Using broadcasting: current_source[:, None, :] - target_cloud[None, :, :]
        diff = current_source[:, np.newaxis, :] - target_cloud[np.newaxis, :, :]
        dists = np.linalg.norm(diff, axis=2)
        
        # Find index of minimum distance for each source point
        closest_indices = np.argmin(dists, axis=1)
        closest_points = target_cloud[closest_indices]
        
        # Filter correspondences based on threshold
        distances = np.min(dists, axis=1)
        valid_mask = distances <= threshold
        valid_source = current_source[valid_mask]
        valid_target = closest_points[valid_mask]
        
        # If no valid correspondences, stop
        if len(valid_source) == 0:
            break
            
        # Step 2: Compute optimal rigid transformation
        # Center the points
        mean_source = np.mean(valid_source, axis=0)
        mean_target = np.mean(valid_target, axis=0)
        
        centered_source = valid_source - mean_source
        centered_target = valid_target - mean_target
        
        # Compute covariance matrix
        H = centered_source.T @ centered_target
        
        # SVD to find rotation
        U, S, Vt = np.linalg.svd(H)
        R = Vt.T @ U.T
        
        # Check for reflection (determinant -1) and correct if necessary
        if np.linalg.det(R) < 0:
            Vt[-1, :] *= -1
            R = Vt.T @ U.T
            
        # Compute translation
        t = mean_target - R @ mean_source
        
        # Step 3: Update transformation
        # Create 4x4 rotation matrix
        R_4x4 = np.eye(4)
        R_4x4[:3, :3] = R
        R_4x4[:3, 3] = t
        
        # Compose transformations: T_new = T_old @ R_4x4
        # Note: Depending on convention, this might be R_4x4 @ T_old.
        # Standard ICP applies the new transform to the points, so we accumulate.
        # If T transforms source to target, and we have a new delta transform D,
        # the new total transform is D @ T.
        T = R_4x4 @ T
        
        # Apply transformation to source cloud for next iteration
        # current_source = R @ current_source + t
        current_source = (R @ current_source.T).T + t
        
        # Check convergence (e.g., change in T or error)
        # Not given in the sources. [G]
        
    return T
```

**Edge Cases and Pitfalls:**
*   **Singularities and Bad Correspondences:** ICP methods can exhibit singularities and establish bad correspondences in noise-free dense point clouds [S4].
*   **Local Minima:** ICP may find poor local minima, leading to suboptimal alignment on average [S4].
*   **Noise Sensitivity:** Under synthetic depth noise, Point-to-Plane ICP degrades significantly [S4]. Adding noise can break symmetry and improve lower-quartile performance by helping avoid singularities [S4].

## Subtopics

### Point-to-Point ICP
Matches each point in the source cloud to the nearest point in the target cloud based on Euclidean distance. It is the standard variant described in the main method. In noise-free conditions, it outperforms Point-to-Plane ICP and differentiable renderers, achieving errors to fractions of a degree [S4]. However, it suffers from poor local minima on average [S4].

### Point-to-Plane ICP
Matches each point in the source cloud to the nearest point in the target cloud, but uses the surface normal of the target point to define the error metric (distance to the tangent plane). It performs better than Point-to-Point ICP when noise is present, but degrades significantly under synthetic depth noise compared to differentiable renderers [S4].

### Pose Estimation with ICP and Differentiable Renderers
This variant integrates ICP with differentiable rendering pipelines for pose estimation. While ICP provides high accuracy in noise-free scenarios, differentiable renderers are more robust to noise. Fuzzy Metaballs, a low-fidelity model using algebraic surfaces, show higher robustness under noise, achieving lower mean and percentile errors than ICP in noisy conditions [S4].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** Each iteration requires finding nearest neighbors, which is $O(N \log M)$ with efficient spatial indexing (e.g., KD-tree) or $O(NM)$ with brute force, where $N$ and $M$ are the number of points in source and target clouds. The transformation estimation is $O(N)$ or $O(1)$ depending on implementation. Total time is $O(K \cdot N \log M)$, where $K$ is the number of iterations.
*   **Memory:** $O(N + M)$ to store the point clouds and intermediate correspondence arrays.

**Measured Performance:**
*   **Noise-Free:** Point-to-Point ICP achieves errors to fractions of a degree, outperforming differentiable renderers by an order of magnitude [S4]. However, Fuzzy Metaballs have a median error 8x higher and 25th percentile error 10x higher than ICP in these cases [S4].
*   **Noisy:** Under synthetic depth noise, ICP results see a large degradation in peak performance. Fuzzy Metaballs achieve the lowest mean, median, 25th, and 75th percentile errors, typically 2x better than ICP [S4].

**Strengths and Limitations:**
*   **Strengths:** High accuracy in noise-free, dense point cloud scenarios; simple to implement; widely used for geometric evaluation [S2, S3, S4].
*   **Limitations:** Prone to local minima; sensitive to noise; requires good initialization; performance degrades significantly with noisy input data [S4].

**When to Use:**
*   Use when high accuracy is required in noise-free or low-noise environments and the point clouds are dense [S4].
*   Use for aligning reconstructed point clouds to ground truth meshes for geometric evaluation [S1, unofficial][S3].

**When Not to Use:**
*   Use when the input data contains significant noise, as differentiable renderers or Fuzzy Metaballs may be more robust [S4].
*   Use when the point clouds are sparse or have poor overlap, as ICP may fail to find valid correspondences [S4].

## Background
ICP was introduced by Besl and McKay in 1992 [S2]. It is a fundamental algorithm in computer vision and robotics for 3D registration. It is commonly used to align reconstructed meshes or point clouds to a ground truth metric space for evaluation purposes [S1, unofficial][S2, S3]. The method is often employed in the context of evaluating Neural Radiance Fields (NeRFs) and other 3D reconstruction techniques against terrestrial laser scanning (TLS) data [S2, S3].
