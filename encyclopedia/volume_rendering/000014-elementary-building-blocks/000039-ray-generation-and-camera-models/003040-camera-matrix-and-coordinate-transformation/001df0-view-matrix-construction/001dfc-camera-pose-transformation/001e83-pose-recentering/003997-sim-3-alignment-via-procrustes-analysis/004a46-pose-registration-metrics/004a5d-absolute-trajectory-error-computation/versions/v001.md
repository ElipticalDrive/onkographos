# Absolute Trajectory Error Computation

Also called: ATE, Absolute Trajectory Error Measurement, Ego-Motion Estimation Evaluation

## Overview
Absolute Trajectory Error (ATE) computes the integrated distance between all estimated pose positions relative to a ground truth trajectory after alignment [S1]. It serves as the primary metric for evaluating the global consistency of ego-motion estimation and SLAM systems [S1]. Unlike local metrics, ATE measures the cumulative drift of the estimated path against the reference path [S1].

## How it works
**Inputs:**
1.  Ground truth trajectory: A sequence of poses $P_{gt} = \{T_{gt, i}, R_{gt, i}\}$ for $i=1 \dots N$, where $T$ is translation and $R$ is rotation [S1][S2, unofficial].
2.  Estimated trajectory: A sequence of poses $P_{es} = \{T_{es, i}, R_{es, i}\}$ for $i=1 \dots N$ [S1][S2, unofficial].
3.  Alignment parameters: Scale $s$, rotation $R_{align}$, and translation $t_{align}$ obtained from Sim(3) Procrustes analysis [S1][S2, unofficial].

**Outputs:**
1.  Translation error vector $e_{trans\_vec}$ and magnitude $e_{trans}$ [S2, unofficial].
2.  Rotation error magnitude $e_{rot}$ [S2, unofficial].
3.  Euler angle errors $e_{ypr}$ [S2, unofficial].
4.  Scale drift percentage $e_{scale\_perc}$ [S2, unofficial].

**Data Structures:**
*   $T_{gt}, T_{es}$: Arrays of shape $(N, 3)$ containing 3D coordinates.
*   $R_{gt}, R_{es}$: Arrays of shape $(N, 3, 3)$ containing rotation matrices, or quaternions $q_{gt}, q_{es}$ of shape $(N, 4)$.
*   $e_{trans}$: Array of shape $(N,)$ containing scalar translation errors.
*   $e_{rot}$: Array of shape $(N,)$ containing scalar rotation errors in degrees.

**Steps:**

1.  **Alignment:** Apply the Sim(3) alignment to the estimated trajectory.
    *   Scale the estimated positions: $T'_{es, i} = s \cdot T_{es, i}$.
    *   Rotate the scaled positions: $T''_{es, i} = R_{align} \cdot T'_{es, i}$.
    *   Translate the rotated positions: $T_{aligned, i} = T''_{es, i} + t_{align}$.
    *   Rotate the estimated rotations: $R_{aligned, i} = R_{align} \cdot R_{es, i}$.
    *   [G] Ensure $R_{align}$ is a proper rotation matrix (determinant +1). If derived from Procrustes, it may require correction if determinant is -1.

2.  **Translation Error:**
    *   Compute the difference vector for each frame $i$:
        $$ e_{trans\_vec, i} = T_{gt, i} - T_{aligned, i} $$
    *   Compute the magnitude:
        $$ e_{trans, i} = \| e_{trans\_vec, i} \|_2 = \sqrt{\sum_{j=1}^{3} (e_{trans\_vec, i, j})^2} $$

3.  **Rotation Error:**
    *   Compute the error rotation matrix $e_{R, i}$:
        $$ e_{R, i} = R_{aligned, i} \cdot R_{gt, i}^{-1} = R_{aligned, i} \cdot R_{gt, i}^T $$
    *   Compute the rotation error magnitude in radians using the logarithmic map of the special orthogonal group $so(3)$:
        $$ \theta_i = \| \log(e_{R, i}) \|_2 $$
        Where $\log(\cdot)$ extracts the axis-angle vector from the rotation matrix.
    *   Convert to degrees:
        $$ e_{rot, i} = \theta_i \cdot \frac{180}{\pi} $$
    *   [G] The norm of the logmap vector corresponds to the angle of rotation.

4.  **Euler Angle Errors (Optional):**
    *   Extract Euler angles $e_{ypr, i}$ from $e_{R, i}$ using a specific convention (e.g., 'rzyx') [S2, unofficial].
    *   This provides component-wise error but is less robust than the axis-angle magnitude due to gimbal lock [S2, unofficial].

5.  **Scale Drift (Optional):**
    *   Compute motion vectors for ground truth and aligned estimated trajectories:
        $$ motion_{gt, i} = T_{gt, i} - T_{gt, i-1} $$
        $$ motion_{aligned, i} = T_{aligned, i} - T_{aligned, i-1} $$
    *   Compute distances:
        $$ dist_{gt, i} = \| motion_{gt, i} \|_2 $$
        $$ dist_{aligned, i} = \| motion_{aligned, i} \|_2 $$
    *   Calculate percentage error:
        $$ e_{scale\_perc, i} = \left| \frac{dist_{aligned, i}}{dist_{gt, i}} - 1 \right| \cdot 100 $$

**Pseudocode:**

```python
import numpy as np
from scipy.spatial.transform import Rotation

def compute_ate(T_gt, R_gt, T_es, R_es, s, R_align, t_align):
    """
    Compute Absolute Trajectory Error.
    
    Args:
        T_gt: (N, 3) ground truth translations.
        R_gt: (N, 3, 3) ground truth rotation matrices.
        T_es: (N, 3) estimated translations.
        R_es: (N, 3, 3) estimated rotation matrices.
        s: Scale factor from alignment.
        R_align: (3, 3) Rotation matrix from alignment.
        t_align: (3,) Translation vector from alignment.
        
    Returns:
        e_trans: (N,) translation errors in meters.
        e_rot: (N,) rotation errors in degrees.
    """
    N = T_gt.shape[0]
    e_trans = np.zeros(N)
    e_rot = np.zeros(N)
    
    # Step 1: Align estimated trajectory
    # Scale
    T_scaled = T_es * s
    # Rotate
    T_rotated = (R_align @ T_scaled.T).T
    # Translate
    T_aligned = T_rotated + t_align
    
    # Rotate rotations
    R_aligned = (R_align @ R_es.transpose(0, 2, 1)).transpose(0, 2, 1)
    
    # Step 2: Translation Error
    diff = T_gt - T_aligned
    e_trans = np.linalg.norm(diff, axis=1)
    
    # Step 3: Rotation Error
    # Compute relative rotation: R_aligned * R_gt^T
    # R_gt is (N, 3, 3), transpose last two dims
    R_gt_T = R_gt.transpose(0, 2, 1)
    e_R = np.zeros((N, 3, 3))
    for i in range(N):
        e_R[i] = R_aligned[i] @ R_gt_T[i]
        
    # Convert rotation matrices to axis-angle
    # scipy Rotation.from_matrix returns a Rotation object
    # .as_rotvec() returns the axis-angle vector (axis * angle)
    # The norm of this vector is the angle in radians
    rot_vecs = np.zeros((N, 3))
    for i in range(N):
        r = Rotation.from_matrix(e_R[i])
        rot_vecs[i] = r.as_rotvec()
        
    e_rot_rad = np.linalg.norm(rot_vecs, axis=1)
    e_rot = np.degrees(e_rot_rad)
    
    return e_trans, e_rot
```

**Parameters:**
*   **Baseline Processing:** In some evaluations, the ground truth map is processed with a Gaussian blur kernel of size $9 \times 9 \times 9$ voxels and $\sigma = 4/3$ to simulate sensor noise or reconstruction smoothing [S1].
*   **Alignment:** The alignment parameters ($s, R_{align}, t_{align}$) are typically derived from a Procrustes analysis minimizing the sum of squared distances between corresponding points [S1][S2, unofficial].

**Edge Cases:**
*   **Degenerate Input:** If $dist_{gt, i} = 0$ in scale drift calculation, division by zero occurs. Handle by skipping or setting error to 0 [S2, unofficial].
*   **Precision:** Use double precision for alignment to avoid numerical instability in rotation matrix multiplication [S2, unofficial].
*   **Boundary:** The first frame has no previous motion for scale drift calculation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for error computation after alignment, where $N$ is the number of frames. Alignment is typically $O(N)$ or $O(N \log N)$ depending on the solver.
*   **Memory Complexity:** $O(N)$ to store error arrays.
*   **Measured Performance:** On the "Original data" baseline (Gaussian blur $9 \times 9 \times 9$, $\sigma=4/3$), the Mean ATE was $0.10 \pm 0.17$ m and Median ATE was $0.038$ m [S1].
*   **Strengths:** Provides a single scalar metric for global trajectory consistency [S1].
*   **Limitations:** Sensitive to alignment quality; does not distinguish between rotational and translational errors without separate metrics [S1][S2, unofficial].

## Background
ATE was introduced as a standard metric for evaluating the accuracy of ego-motion estimation and SLAM systems [S1]. It is widely used in RGB-D SLAM evaluation, such as in the evaluation of the freiburg-1 dataset [S1]. The metric relies on the availability of ground truth poses from an external tracking system [S1].
