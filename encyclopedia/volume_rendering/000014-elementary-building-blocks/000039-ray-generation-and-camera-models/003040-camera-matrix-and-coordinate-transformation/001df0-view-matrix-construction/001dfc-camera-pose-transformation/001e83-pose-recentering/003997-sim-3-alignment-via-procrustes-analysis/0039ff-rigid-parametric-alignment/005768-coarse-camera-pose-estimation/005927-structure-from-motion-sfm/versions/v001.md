# Structure-from-Motion (SfM)

Also called: COLMAP SfM, Camera Pose Estimation using SfM, HLOC SfM, LocalRF SfM

## Overview
Structure-from-Motion (SfM) estimates the 3D camera poses for a set of extracted video frames to provide the geometric input required for training Neural Radiance Fields (NeRFs) [S1]. It differs from its sibling methods in [Coarse Camera Pose Estimation](15954-coarse-camera-pose-estimation.md) by explicitly reconstructing the sparse point cloud and camera trajectory from image correspondences, rather than relying on pre-existing coarse estimates or purely learned priors.

## How it works
**Inputs:** A dataset of $n_{\text{frame}}$ extracted video frames.
**Outputs:** A set of $n_{\text{pose}}$ estimated camera poses (extrinsics) corresponding to the input frames.

**Data Structures:**
The implementation relies on the internal data structures of the chosen SfM engine (e.g., COLMAP, HLOC, or LocalRF). These typically include:
- **Features:** Keypoints and descriptors extracted from each image.
- **Matches:** Correspondences between keypoints across image pairs.
- **Sparse Reconstruction:** A set of 3D points and their associated 2D projections.
- **Camera Poses:** Rotation matrices and translation vectors for each image.

**Steps:**
1. **Feature Extraction:** Extract local features from each of the $n_{\text{frame}}$ images.
2. **Image Matching:** Match features between image pairs to establish correspondences.
3. **Pose Estimation:** Solve for camera poses and 3D structure using the matches.
4. **Bundle Adjustment:** Refine the poses and 3D points to minimize reprojection error.

**Parameters and Methods:**
Three primary implementations are cited in the sources, each with distinct feature extractors and matchers:

1.  **COLMAP SfM:**
    -   Uses Scale-Invariant Feature Transform (SIFT) features [S1].
    -   Standard SfM pipeline.
2.  **HLOC SfM:**
    -   Uses SuperPoint for feature extraction [S1].
    -   Uses SuperGlue for image matching [S1].
    -   Built upon the COLMAP framework [S1].
3.  **LocalRF SfM:**
    -   Designed for long-range camera trajectories and large unbounded scenes [S1].
    -   Capable of estimating poses for all $n_{\text{frame}}$ images ($n_{\text{pose}} = n_{\text{frame}}$) [S1].
    -   Implementation requires modifying the ray sampling to restrict it solely to valid color pixels during internal processing [S1].

**Edge Cases and Pitfalls:**
-   **Sparsity:** COLMAP performs well only with dense views (e.g., 2784 frames) but struggles with sparse views (310 or 1392 frames) [S1]. HLOC demonstrates better effectiveness in sparse scenarios [S1].
-   **Runtime:** LocalRF has extensive running times, making it unsuitable for large frame counts in the tested context [S1]. HLOC also suffers from long running times compared to COLMAP [S1].
-   **Incomplete Poses:** Standard COLMAP may not estimate poses for all frames if the reconstruction is incomplete ($n_{\text{pose}} < n_{\text{frame}}$), whereas LocalRF aims to estimate all [S1].

## Operating characteristics
**Time Complexity and Performance:**
Performance was measured on a machine with a single RTX A6000 GPU and 128 GB RAM [S1].

| Frames ($n_{\text{frame}}$) | Method | Time | Poses ($n_{\text{pose}}$) |
| :--- | :--- | :--- | :--- |
| 310 | COLMAP | 00:08:26 | 62 |
| 310 | HLOC | 01:08:39 | 43 |
| 310 | LocalRF | 23:20:52 | 310 |
| 1392 | COLMAP | 00:49:29 | 376 |
| 1392 | HLOC | 21:51:34 | 647 |
| 1392 | LocalRF | 75:10:54 | 1392 |
| 2784 | COLMAP | 04:32:53 | 2667 |

-   COLMAP is significantly faster than HLOC, with speedup factors of 8x for 310 frames and 26.5x for 1392 frames [S1].
-   LocalRF is the slowest method, taking over 23 hours for 310 frames and over 75 hours for 1392 frames [S1].
-   HLOC and LocalRF were not used for the 2784-frame dataset due to excessive runtime [S1].

**Strengths and Limitations:**
-   **COLMAP:** Fast and effective for dense views; poor performance on sparse views [S1].
-   **HLOC:** More effective than COLMAP on sparse views; slower than COLMAP [S1].
-   **LocalRF:** Handles long-range trajectories and unbounded scenes; estimates all poses; extremely slow [S1].

**When to Use:**
-   Use **COLMAP** for dense image sets where speed is critical.
-   Use **HLOC** for sparse image sets where COLMAP fails to reconstruct sufficient poses.
-   Use **LocalRF** for sparse views requiring full pose coverage and long-range trajectory handling, provided computational time is not a constraint.

## Background
Structure-from-Motion is a standard technique in computer vision for estimating camera parameters and 3D structure from uncalibrated image sequences. In the context of NeRF training, it serves as the preprocessing step to determine the camera poses for extracted video frames [S1]. The specific implementations discussed (COLMAP, HLOC, LocalRF) represent the evolution from classical SIFT-based pipelines to learned feature matching (SuperPoint/SuperGlue) and specialized methods for unbounded scenes [S1].
