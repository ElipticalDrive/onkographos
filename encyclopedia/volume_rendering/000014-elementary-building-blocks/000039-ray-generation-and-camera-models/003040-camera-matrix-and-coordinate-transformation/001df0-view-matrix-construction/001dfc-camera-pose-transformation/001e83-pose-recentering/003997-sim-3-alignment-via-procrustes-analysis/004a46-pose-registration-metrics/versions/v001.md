# Pose Registration Metrics

Also called: Pose Error Metrics, Rotation Error, Translation Error

## Overview
Pose Registration Metrics quantify the geometric discrepancy between estimated camera poses and ground-truth poses after alignment. They solve the problem of evaluating the accuracy of Structure-from-Motion (SfM) or Sim(3) alignment methods by providing scalar measures of rotational and translational deviation. Unlike sibling methods that focus on alignment computation or optimization, these metrics serve as the evaluation standard for registration quality [S1].

## How it works
The method computes two primary scalar errors: rotation error and translation error. These are calculated per pose or averaged over a trajectory.

**Inputs:**
- $R$: Ground-truth rotation matrix ($3 \times 3$).
- $\hat{R}$: Estimated rotation matrix ($3 \times 3$).
- $T$: Ground-truth translation vector ($3 \times 1$).
- $\hat{T}$: Estimated translation vector ($3 \times 1$).

**Outputs:**
- $|R_{err}|$: Rotation error in radians.
- $T_{err}$: Translation error magnitude.

**Data Structures:**
- Rotation matrices are $3 \times 3$ orthogonal matrices with determinant 1.
- Translation vectors are 3-dimensional Euclidean vectors.

**Formulas:**

1. **Rotation Error:**
   The rotation error is the absolute value of the rotation angle required to align the ground-truth rotation $R$ with the estimated rotation $\hat{R}$ [S1]. It is computed using the trace of the relative rotation matrix $R^{-1}\hat{R}$:

   $$
   |R_{err}| = \cos^{-1}\left( \frac{\text{Tr}(R^{-1}\hat{R}) - 1}{2} \right)
   $$

   where $\text{Tr}(\cdot)$ denotes the trace of a matrix [S1].

2. **Translation Error:**
   The translation error is the Euclidean distance between the estimated position $\hat{T}$ and the ground-truth position $T$ [S1]:

   $$
   T_{err} = \|\hat{T} - T\|_2
   $$

   Note that on datasets where poses are not in metric space, $T_{err}$ has no physical units [S1].

**Pseudocode:**

```python
import numpy as np

def compute_rotation_error(R_gt, R_est):
    """
    Computes the rotation error in radians between ground-truth and estimated rotation matrices.
    
    Args:
        R_gt: numpy array, shape (3, 3), ground-truth rotation matrix.
        R_est: numpy array, shape (3, 3), estimated rotation matrix.
        
    Returns:
        float: Rotation error in radians.
    """
    # Compute relative rotation matrix R_rel = R_gt^(-1) @ R_est
    # Since R_gt is orthogonal, R_gt^(-1) is R_gt.T
    R_rel = R_gt.T @ R_est
    
    # Compute the trace of the relative rotation matrix
    trace_val = np.trace(R_rel)
    
    # Clamp the argument to acos to handle numerical precision issues
    # The theoretical range is [-1, 1], but floating point errors may push it slightly outside
    cos_angle = (trace_val - 1.0) / 2.0
    cos_angle = np.clip(cos_angle, -1.0, 1.0)
    
    # Compute the angle
    angle = np.arccos(cos_angle)
    
    return angle

def compute_translation_error(T_gt, T_est):
    """
    Computes the Euclidean distance between ground-truth and estimated translation vectors.
    
    Args:
        T_gt: numpy array, shape (3,), ground-truth translation vector.
        T_est: numpy array, shape (3,), estimated translation vector.
        
    Returns:
        float: Translation error magnitude.
    """
    diff = T_est - T_gt
    error = np.linalg.norm(diff)
    return error
```

**Parameters:**
- No tunable parameters. The metrics are deterministic functions of the input poses.

**Edge Cases:**
- **Numerical Precision:** The argument to $\cos^{-1}$ must be clamped to $[-1, 1]$ to avoid NaNs due to floating-point inaccuracies in the trace calculation [G].
- **Non-Metric Space:** If the input poses are not in metric space, the translation error is unitless and should not be interpreted as physical distance [S1].

## Subtopics

### Absolute Trajectory Error Computation
Computes absolute pose errors between aligned estimated and ground truth trajectories [S2, unofficial]. It calculates a translation error vector $e_{trans\_vec} = p_{gt} - p_{es\_aligned}$ and its magnitude $e_{trans} = \sqrt{\sum e_{trans\_vec}^2}$ [S2, unofficial]. For rotation, it computes error rotation $e_R = R_{we} R_{wg}^{-1}$ from quaternions, extracts Euler angles $e_{ypr}$ using 'rzyx' convention, and computes rotation error magnitude $e_{rot}$ using the norm of the logarithmic map of the rotation matrix $e_{rot} = \|\log_{so3}(e_R)\|$ converted to degrees [S2, unofficial]. It also computes scale drift by comparing motion vectors and distances between ground truth and estimated trajectories, reporting percentage error $e_{scale\_perc} = |\frac{dist_{es}}{dist_{gt}} - 1| \times 100$ [S2, unofficial]. Inputs are aligned estimated positions $p_{es\_aligned}$ and quaternions $q_{es\_aligned}$ [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per pose for rotation and translation error. $O(N)$ for trajectory-level metrics where $N$ is the number of frames.
- **Memory Complexity:** $O(1)$ per pose. $O(N)$ for storing trajectory errors.
- **Strengths:** Simple, differentiable (rotation error is smooth except at identity), and standard for evaluating SfM and SLAM systems.
- **Limitations:** Does not account for temporal consistency or drift directly (unless computed as trajectory error). Translation error is sensitive to scale if not properly aligned [S1].
- **When to use:** Evaluating the accuracy of camera pose estimation after Sim(3) alignment.
- **When not to use:** When metric accuracy is not required or when scale is ambiguous and not resolved by alignment.

## Background
Pose registration metrics originated in the evaluation of visual odometry and SLAM systems. The rotation error formula using the trace of the relative rotation matrix is a standard result in rigid body kinematics. The translation error is a standard Euclidean distance metric. These metrics are widely used in NeRF and 3D reconstruction papers to report the quality of pose estimation, particularly when poses are noisy or sparse [S1]. The absolute trajectory error variant, including scale drift, is common in SLAM evaluation benchmarks [S2, unofficial].
