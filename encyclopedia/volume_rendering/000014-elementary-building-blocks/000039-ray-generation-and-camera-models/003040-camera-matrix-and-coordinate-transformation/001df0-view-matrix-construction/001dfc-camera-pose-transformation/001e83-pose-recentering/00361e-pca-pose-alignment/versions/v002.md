# PCA Pose Alignment
Also called: principal component pose transform

## Overview
PCA Pose Alignment recenters and rotates a set of camera poses so that the principal components of the camera position distribution align with the global XYZ axes [S1, unofficial]. It solves the problem of arbitrary coordinate system orientation in multi-view datasets by enforcing a canonical frame derived from the data geometry. Unlike [Sim(3) Alignment via Procrustes Analysis](8526-sim-3-alignment-via-procrustes-analysis.md), which minimizes rigid-body transformation errors to match a target configuration, PCA Pose Alignment relies solely on the statistical variance of camera centers, ignoring orientation constraints during the rotation estimation [S1, unofficial].

## How it works
**Inputs:** A set of $N$ camera poses, represented as $4 \times 4$ matrices $P_i$ (camera-to-world, c2w).
**Outputs:** A $4 \times 4$ transformation matrix $T$ and the transformed poses $P'_i = T P_i$.

**Data Structures:**
- $P$: Array of shape $(N, 4, 4)$ containing the input poses.
- $t$: Array of shape $(N, 3)$ containing the translation vectors (camera positions).
- $T_{3 \times 4}$: Intermediate $3 \times 4$ matrix.
- $T_{4 \times 4}$: Final $4 \times 4$ transformation matrix.

**Steps:**
1. **Extract Positions:** Extract the translation components from the poses. For each pose $P_i$, let $t_i$ be the first three elements of the fourth column:
   $$ t_i = P_i[:3, 3] $$
   Stack these into a matrix $t \in \mathbb{R}^{N \times 3}$.

2. **Recenter:** Compute the mean position $\bar{t}$:
   $$ \bar{t} = \frac{1}{N} \sum_{i=1}^{N} t_i $$
   Subtract the mean from all positions:
   $$ t_{centered} = t - \bar{t} $$

3. **Covariance and Eigendecomposition:** Compute the covariance matrix $C$ of the centered positions:
   $$ C = t_{centered}^T t_{centered} $$
   Perform eigendecomposition on $C$ to obtain eigenvalues $\lambda$ and eigenvectors $v$.

4. **Construct Rotation:** Sort the eigenvectors in descending order of their corresponding eigenvalues. Let the sorted eigenvectors be $v_1, v_2, v_3$. Construct the rotation matrix $R \in \mathbb{R}^{3 \times 3}$ by stacking these vectors as columns:
   $$ R = [v_1 | v_2 | v_3] $$
   **Determinant Check:** If $\det(R) < 0$, the transformation includes a reflection. Flip the third column (associated with the smallest eigenvalue) to ensure a proper rotation:
   $$ R[:, 2] = -R[:, 2] $$

5. **Construct Transform Matrix:** Form the $3 \times 4$ matrix $M$ by concatenating $R$ and the rotated translation offset:
   $$ M = [R \quad | \quad R(-\bar{t})] $$
   Append a homogeneous row $[0, 0, 0, 1]$ to $M$ to create the $4 \times 4$ transformation matrix $T$.

6. **Apply Transform:** Transform the poses by multiplying $T$ with each $P_i$. Note that since $P_i$ are $4 \times 4$ and $T$ is $4 \times 4$, the operation is standard matrix multiplication. The result is the set of aligned poses.

7. **Axis Flipping (Y/Z Check):** After alignment, inspect the y-axis vectors (second row of the rotation part) of the recentered poses. Calculate the mean z-component of these y-axes. If this mean is negative, flip the y and z axes in both the poses and the transformation matrix $T$ to ensure consistent orientation [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def pca_pose_alignment(poses):
    """
    Aligns camera poses using PCA on camera positions.
    Args:
        poses: np.array of shape (N, 4, 4), camera-to-world matrices.
    Returns:
        T: np.array of shape (4, 4), the transformation matrix.
        aligned_poses: np.array of shape (N, 4, 4), transformed poses.
    """
    # 1. Extract positions
    t = poses[:, :3, 3]  # Shape (N, 3)
    
    # 2. Center positions
    t_mean = np.mean(t, axis=0)
    t_centered = t - t_mean
    
    # 3. Covariance and Eigendecomposition
    # Covariance matrix C = t_centered.T @ t_centered
    C = t_centered.T @ t_centered
    eigenvalues, eigenvectors = np.linalg.eigh(C)
    
    # 4. Sort eigenvectors by descending eigenvalues
    # eigh returns sorted ascending, so reverse
    idx = np.argsort(eigenvalues)[::-1]
    R = eigenvectors[:, idx]  # Shape (3, 3)
    
    # Ensure proper rotation (det = 1)
    if np.linalg.det(R) < 0:
        R[:, 2] = -R[:, 2]
        
    # 5. Construct 3x4 transform matrix
    # Translation part: R @ (-t_mean)
    t_offset = R @ (-t_mean)
    M_3x4 = np.hstack([R, t_offset.reshape(3, 1)])
    
    # 6. Construct 4x4 transform matrix T
    T = np.eye(4)
    T[:3, :] = M_3x4
    
    # 7. Apply transform to poses
    # P' = T @ P
    aligned_poses = T @ poses
    
    # 8. Check Y/Z axis flip
    # Get y-axis of recentered poses (second row of rotation part)
    # The rotation part of aligned_poses is aligned_poses[:, :3, :3]
    y_axes = aligned_poses[:, :3, 1]
    mean_z_y = np.mean(y_axes[:, 2])
    
    if mean_z_y < 0:
        # Flip Y and Z axes in poses and T
        # Flip Y and Z in poses
        aligned_poses[:, :3, 1] *= -1
        aligned_poses[:, :3, 2] *= -1
        
        # Flip Y and Z in T
        T[:3, 1] *= -1
        T[:3, 2] *= -1
        
    return T, aligned_poses
```

**Edge Cases and Pitfalls:**
- **Degenerate Data:** If all camera positions are collinear or coincident, the covariance matrix will be singular or near-singular, leading to undefined eigenvectors. [G] Implementers should check the condition number of $C$ and fallback to a default identity transform or raise an error.
- **Determinant Sign:** Failure to check $\det(R)$ results in a reflection, which reverses depth ordering and breaks rendering.
- **Homogeneous Coordinates:** Ensure poses are strictly $4 \times 4$ with the last row $[0,0,0,1]$.

## Subtopics

### [Camera Space Normalization via Similarity Transform](11417-camera-space-normalization-via-similarity-transform.md)
Computes a 4x4 similarity transform matrix $T$ and a scalar scale to normalize camera poses (c2w) and optionally point clouds, aligning the world up axis to the camera's negative Y axis and centering the scene. It sets the coordinate system such that the average camera orientation defines the vertical axis, distinct from [PCA Pose Alignment](7626-pca-pose-alignment.md) which aligns principal components of the data distribution.

## Operating characteristics
- **Time Complexity:** $O(N)$ to extract positions and compute the mean. $O(N)$ to compute the covariance matrix (assuming fixed dimension 3). Eigendecomposition of a $3 \times 3$ matrix is $O(1)$. Total time is dominated by $O(N)$ for data extraction and transformation application.
- **Memory Complexity:** $O(N)$ to store the positions and centered positions.
- **Strengths:** Fast, deterministic, and requires no iterative optimization. It effectively handles large datasets by reducing them to a simple covariance calculation.
- **Limitations:** It only considers camera positions, ignoring camera orientations. If the camera orientations are highly correlated with positions in a non-principal way, the resulting alignment might not be optimal for rendering tasks that depend on view consistency. It does not scale the scene, unlike similarity transforms.
- **When to Use:** When a quick, position-based canonicalization is needed and orientation constraints are secondary or handled separately.
- **When Not to Use:** When the scene has a known global up vector that must be preserved, or when camera orientations are critical for the alignment metric.

## Background
PCA Pose Alignment is a heuristic method commonly used in neural radiance field (NeRF) and multi-view stereo pipelines to standardize input data. It originates from the need to handle datasets with arbitrary coordinate systems. The specific implementation details, including the Y/Z axis flipping heuristic, are documented in the VolSplat repository [S1, unofficial]. It is a simpler alternative to Procrustes analysis, which requires a target configuration or iterative alignment.
