# Structure-from-Motion (SfM)

Also called: COLMAP SfM, Camera Pose Estimation using SfM, HLOC SfM, LocalRF SfM

## Overview
Structure-from-Motion (SfM) is a photogrammetric technique that recovers camera poses (extrinsics), camera calibration parameters (intrinsics), and a sparse 3D point cloud from a set of uncalibrated photographs [S2, unofficial]. It serves as the foundational preprocessing step for modern implicit and explicit radiance field methods, such as NeRF and Gaussian Splatting, by providing the necessary geometric constraints (camera positions) required to optimize scene representations against source images [S1][S2, unofficial]. Unlike its siblings in the camera pose estimation hierarchy, SfM operates globally on a set of images to establish a consistent coordinate system, whereas methods like [Coarse Camera Pose Estimation](15954-coarse-camera-pose-estimation.md) may rely on sequential or local assumptions.

## How it works
**Inputs:** A set of $N$ unordered images $\{I_1, \dots, I_N\}$, optionally with EXIF metadata.
**Outputs:** Camera poses $P_i \in \mathbb{R}^{3 \times 4}$ (rotation $R_i$ and translation $t_i$), intrinsic parameters $K$ (focal length, principal point, distortion), and a sparse 3D point cloud $\{X_j\}$.

**Data Structures:**
1.  **Keypoints:** For each image $i$, a list of detected features. Each feature $k$ contains:
    *   `x, y`: 2D coordinates in pixels.
    *   `scale`: Detection scale.
    *   `orientation`: Angle in radians.
    *   `descriptor`: A vector (e.g., 128-dim for SIFT) summarizing local texture.
2.  **Matches:** A list of correspondences between image $i$ and image $j$. Each match contains indices into the keypoint lists of both images.
3.  **Reconstruction:**
    *   `cameras`: List of camera objects with pose $P_i$ and intrinsics $K_i$.
    *   `points3D`: List of 3D points with position $X_j$, color, and a list of `observations` (image_id, keypoint_id, reprojection_error).

**Algorithm Steps:**

1.  **Feature Detection:** For each image $I_i$, detect distinctive keypoints (corners, spots) and compute descriptors.
    *   *Note:* SIFT is monochrome, discarding hue and saturation [S2, unofficial].
    *   *Pseudocode:*
        ```python
        keypoints = []
        for image in images:
            # Detect keypoints and compute descriptors
            # SIFT is the classic detector; SuperPoint is a learned alternative [S1, S4]
            kp, desc = detect_features(image) 
            keypoints.append({'image_id': image.id, 'keypoints': kp, 'descriptors': desc})
        ```

2.  **Pairwise Matching:** Compare descriptors between image pairs to find candidate matches.
    *   For large $N$, use a vocabulary tree to avoid $O(N^2)$ comparisons [S2, unofficial].
    *   Match descriptors using nearest neighbor distance ratio (e.g., Lowe's ratio test).
    *   *Pseudocode:*
        ```python
        matches = []
        for i in range(len(keypoints)):
            for j in range(i + 1, len(keypoints)):
                # Compute descriptor distances
                dists = compute_descriptor_distances(keypoints[i]['descriptors'], keypoints[j]['descriptors'])
                # Select best matches
                pair_matches = select_best_matches(dists)
                if len(pair_matches) > threshold:
                    matches.append({'img_a': i, 'img_b': j, 'matches': pair_matches})
        ```

3.  **Geometric Verification:** Discard incorrect matches using RANSAC and epipolar geometry.
    *   True matches must satisfy the epipolar constraint: $x_j^T F x_i = 0$ (fundamental matrix $F$ for uncalibrated) or $x_j^T E x_i = 0$ (essential matrix $E$ for calibrated) [S2, unofficial].
    *   RANSAC iteratively selects a minimal subset of matches (e.g., 5 points for $E$, 7 or 8 for $F$), computes the matrix, and counts inliers (matches satisfying the constraint within a threshold) [S2, unofficial].
    *   *Pseudocode:*
        ```python
        verified_matches = []
        for match_pair in matches:
            # RANSAC loop
            best_inliers = []
            for _ in range(max_iterations):
                subset = random_sample(match_pair['matches'], k=5) # k depends on matrix type
                matrix = compute_epipolar_matrix(subset)
                inliers = [m for m in match_pair['matches'] if reprojection_error(m, matrix) < threshold]
                if len(inliers) > len(best_inliers):
                    best_inliers = inliers
            if len(best_inliers) > min_inliers:
                verified_matches.append({'img_a': match_pair['img_a'], 'img_b': match_pair['img_b'], 'matches': best_inliers})
        ```

4.  **Incremental Reconstruction:**
    *   **Initialization:** Select a pair of images with a wide baseline and many verified matches. Reconstruct the two camera poses and triangulate the 3D points from these matches [S2, unofficial].
    *   **Registration:** For each remaining image, find images that share enough 3D points. Solve for the new camera pose using Perspective-n-Point (PnP) given the known 3D points and their 2D projections [S2, unofficial].
    *   **Triangulation:** Triangulate new 3D points from the newly registered camera and previously registered cameras. Triangulation finds the point $X$ that minimizes the distance to the rays from camera centers through the feature locations [S2, unofficial].
    *   *Pseudocode:*
        ```python
        # Initialize with best pair
        reg_cameras = [cam_a, cam_b]
        points3D = triangulate_points(reg_cameras, verified_matches[best_pair])
        
        # Register remaining images
        unregistered = set(all_image_ids) - {cam_a.id, cam_b.id}
        while unregistered:
            # Find image with most matches to registered cameras
            next_img = find_best_candidate(unregistered, reg_cameras, points3D)
            
            # Solve PnP
            pose = solve_pnp(next_img, points3D, verified_matches)
            reg_cameras.append(Camera(id=next_img.id, pose=pose))
            unregistered.remove(next_img.id)
            
            # Triangulate new points
            new_points = triangulate_new_points(reg_cameras, next_img, verified_matches)
            points3D.extend(new_points)
            
            # Periodic Bundle Adjustment
            if len(reg_cameras) % ba_interval == 0:
                bundle_adjustment(reg_cameras, points3D)
        ```

5.  **Bundle Adjustment (BA):** Minimize the total reprojection error by optimizing all camera poses and 3D points simultaneously.
    *   **Objective:** Minimize $\sum_{i,j} \| x_{ij} - \pi(P_i, X_j) \|^2$, where $x_{ij}$ is the observed 2D point, $P_i$ is the camera pose, $X_j$ is the 3D point, and $\pi$ is the projection function including distortion [S2, unofficial].
    *   **Self-Calibration:** Intrinsics (focal length, principal point, distortion) are treated as unknowns and optimized alongside poses and points, rather than relying solely on EXIF metadata [S2, unofficial]. If images come from the same fixed-lens camera, intrinsics are shared to constrain the solution [S2, unofficial].

**Parameters:**
*   **Feature Detector:** SIFT (monochrome, scale-invariant) [S2, unofficial] or SuperPoint (learned) [S1, S4].
*   **Matcher:** SuperGlue (learned) [S1] or LightGlue (learned) [S4].
*   **Intrinsics:** Treated as unknowns in BA [S2, unofficial]. Shared across images if from the same camera [S2, unofficial].
*   **RANSAC Inlier Threshold:** Typically a few pixels [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Zooming:** If photos are taken with zooming, intrinsics change, violating the shared-intrinsics assumption [S2, unofficial].
*   **Rolling Shutter:** Fast motion with rolling-shutter sensors smears geometry, violating the pinhole model assumption [S2, unofficial].
*   **Cropping/Resizing:** Invalidates principal point and focal length relative to the original sensor [S2, unofficial].
*   **Motion Blur:** Smears feature points, causing bad matches. Mitigation: drop blurriest frames or shoot at high shutter speeds [S2, unofficial].
*   **Tiny Baselines:** Processing too many nearly-identical video frames wastes compute and provides little triangulation information [S2, unofficial].

## Subtopics

### Canonical Frame Estimation via Facial Landmarks
A method to estimate a canonical frame of reference for selfie and full-body captures using facial landmarks, enabling automatic generation of novel view trajectories [S3]. It computes 2D facial landmarks using MediaPipe’s face mesh, triangulates them in 3D using SfM camera poses, sets a canonical coordinate frame centered at the facemesh (+y up, +x right, -z into the face), and scales the scene so that the interpupillary distance matches 6 cm [S3]. The 3D triangulation is only strictly correct if the subject is static, but is observed to be sufficiently good even with head rotation [S3].

### Deep Image Matching Initialization
An initialization pipeline that replaces traditional sparse SfM methods (like SIFT/SuperGlue) with a deep learning framework to construct a robust initial point cloud [S4]. It uses SuperPoint for feature extraction and LightGlue for feature matching [S4]. This approach is cited as offering better robustness, efficiency, and scalability compared to traditional SfM/MVS methods [S4].

## Operating characteristics
*   **Time Complexity:** SfM is computationally intensive, particularly the pairwise matching ($O(N^2)$ without vocabulary trees) and bundle adjustment (non-linear least squares).
*   **Performance:** COLMAP is significantly faster than HLOC and LocalRF. For 310 frames, COLMAP takes ~8 minutes, HLOC ~68 minutes, and LocalRF ~23 hours [S1]. For 1392 frames, COLMAP takes ~49 minutes, HLOC ~21 hours, and LocalRF ~75 hours [S1].
*   **Scalability:** COLMAP performs well with dense views (e.g., 2784 frames) but may struggle with sparse views where HLOC is more effective [S1]. LocalRF is unsuitable for large frame counts due to extensive running time [S1]. GLOMAP offers a global solution that is dramatically quicker on large sets than COLMAP [S2, unofficial].
*   **Strengths:** Robust to viewpoint changes; provides metric scale if calibrated; standard output format (COLMAP) is widely supported.
*   **Limitations:** Sensitive to textureless regions, repetitive patterns, and motion blur; requires sufficient overlap and baseline between images; incremental approach can suffer from error drift without periodic BA [S2, unofficial].

## Background
Structure-from-Motion is a classic computer vision technique predating Gaussian Splatting by decades [S2, unofficial]. It is the same math that builds sparse point clouds in classic photogrammetry [S2, unofficial]. The de facto standard tool for SfM is COLMAP, an open-source package developed by Schönberger and Frahm (CVPR 2016) [S2, unofficial]. It is used to generate the camera poses and sparse point cloud that serve as the seed for Gaussian Splatting training [S2, unofficial].
