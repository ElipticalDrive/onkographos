# Rigid Parametric Alignment

Also called: Closed-form Rigid Alignment, Horn's Method, Horn's Method for Trajectory Alignment, Rigid Alignment via SVD

## Overview
Rigid Parametric Alignment computes the optimal 3D rigid transformation (rotation and translation) that aligns a set of model points to a set of data points by minimizing the sum of squared Euclidean distances between corresponding points [S1, unofficial][S2]. It solves the absolute orientation problem in a single closed-form step using Singular Value Decomposition (SVD) [S1, unofficial][S2]. Unlike [Iterative Closest Point (ICP)](10563-iterative-closest-point-icp.md), which iteratively refines correspondences and transformation estimates, this method assumes pre-established point-to-point correspondences and yields a direct solution [G]. It differs from [Test-time Optimization with Sim(3) Initialization](8565-test-time-optimization-with-sim-3-initialization.md) by providing an analytical solution rather than relying on gradient-based optimization [G].

## How it works
**Inputs:**
- `model`: A $3 \times N$ matrix representing $N$ 3D points in the model coordinate system.
- `data`: A $3 \times N$ matrix representing $N$ corresponding 3D points in the data (target) coordinate system.

**Outputs:**
- `R`: A $3 \times 3$ rotation matrix.
- `t`: A $3 \times 1$ translation vector.
- The transformation $T = [R|t] \in SE(3)$ [S2].

**Data Structures:**
- Points are stored as column vectors in matrices.
- Covariance matrix $H$ is $3 \times 3$.
- SVD components $U, S, V^T$ are $3 \times 3$ matrices.

**Steps:**

1.  **Center the Data:**
    Compute the centroid of the model points $\bar{x}$ and the data points $\bar{y}$ (denoted as $T\bar{x}$ in [S2] for the target mean, but logically $\bar{y}$). Subtract the centroids from the respective point sets to obtain zero-centered coordinates.
    $$ \bar{x} = \frac{1}{N} \sum_{j=1}^{N} x_j $$
    $$ \bar{y} = \frac{1}{N} \sum_{j=1}^{N} y_j $$
    $$ x'_j = x_j - \bar{x} $$
    $$ y'_j = y_j - \bar{y} $$
    [S1, unofficial][S2]

2.  **Compute Covariance Matrix:**
    Calculate the $3 \times 3$ covariance matrix $H$ (denoted as $W$ in [S1, unofficial] and $H$ in [S2]) by summing the outer products of the centered corresponding points.
    $$ H = \sum_{j=1}^{N} x'_j (y'_j)^T $$
    [S1, unofficial][S2]

3.  **Singular Value Decomposition (SVD):**
    Perform SVD on the covariance matrix $H$.
    $$ H = U S V^T $$
    [S1, unofficial][S2]
    Note: [S1, unofficial] computes SVD on $W^T$ and defines $R = U S V^T$, which is mathematically equivalent to the standard formulation $R = V U^T$ when applied to $H$ directly, provided the SVD definition is consistent. We follow the standard derivation in [S2] for clarity: $R = V U^T$.

4.  **Handle Reflection:**
    Compute the rotation matrix $R$. To ensure a proper rotation (determinant +1) and avoid reflection (determinant -1), check the determinant of $U V^T$.
    $$ R = V U^T $$
    If $\det(R) < 0$, a reflection is present. Correct this by flipping the sign of the last column of $V$ (or the last row of $U^T$) before recomputing $R$. Specifically, let $S = \text{diag}(1, 1, \det(V U^T))$. Then $R = V S U^T$.
    [S1, unofficial][S2]
    [S1, unofficial] implements this by initializing a diagonal matrix $S$ with identity and setting $S_{2,2} = -1$ if $\det(U)\det(V^T) < 0$.

5.  **Compute Translation:**
    Calculate the translation vector $t$ using the centroids and the computed rotation.
    $$ t = \bar{y} - R \bar{x} $$
    [S1, unofficial][S2]

6.  **Apply Transformation:**
    The aligned model points are given by:
    $$ x_{aligned} = R x + t $$
    [S1, unofficial]

**Pseudocode:**

```python
import numpy as np

def rigid_parametric_alignment(model, data):
    """
    Computes the optimal rigid transformation (R, t) aligning model to data.
    
    Args:
        model: numpy array of shape (3, N), model points.
        data: numpy array of shape (3, N), corresponding data points.
        
    Returns:
        R: numpy array of shape (3, 3), rotation matrix.
        t: numpy array of shape (3, 1), translation vector.
    """
    # Step 1: Center the data
    model_mean = np.mean(model, axis=1, keepdims=True)
    data_mean = np.mean(data, axis=1, keepdims=True)
    
    model_centered = model - model_mean
    data_centered = data - data_mean
    
    # Step 2: Compute covariance matrix H
    # H = sum(x' * y'^T)
    H = model_centered @ data_centered.T
    
    # Step 3: SVD of H
    U, S_vals, Vt = np.linalg.svd(H)
    
    # Step 4: Compute Rotation R
    # Standard formula: R = V * U^T
    # Note: np.linalg.svd returns Vt, so V = Vt.T
    V = Vt.T
    R = V @ U.T
    
    # Check for reflection (det(R) == -1)
    if np.linalg.det(R) < 0:
        # Flip the sign of the last column of V
        V[:, -1] *= -1
        R = V @ U.T
        
    # Step 5: Compute Translation t
    # t = y_mean - R * x_mean
    t = data_mean - R @ model_mean
    
    return R, t
```

**Parameters:**
- Not given in the sources. The method is purely geometric and does not require tunable hyperparameters like learning rates or regularization weights.

**Edge Cases and Pitfalls:**
- **Reflection:** If the point sets are mirrored, the SVD solution may yield a rotation with determinant -1. The correction step (flipping the sign of the smallest singular value's corresponding vector) is required to ensure a proper rigid body transformation [S1, unofficial][S2].
- **Degenerate Input:** If all points are collinear or coplanar, the covariance matrix $H$ may be rank-deficient, leading to ambiguous rotation solutions. The SVD will still produce a result, but it may not be unique or physically meaningful.
- **Precision:** Using double-precision floating-point arithmetic is recommended for the SVD computation to maintain numerical stability, especially when point coordinates vary significantly in magnitude.

## Subtopics

### [Iterative Closest Point (ICP)](10563-iterative-closest-point-icp.md)
Iterative Closest Point (ICP) is a registration algorithm used to align two point sets, typically a reconstructed point cloud and a ground truth mesh, by finding an optimal rigid transformation. It builds on [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md) by iteratively refining the transformation estimate through correspondence matching, rather than solving for a transformation from pre-established correspondences in a single step [G]. Unlike differentiable renderers which optimize pose via gradient descent on pixel errors, ICP operates directly in geometric space.

### [Coarse Camera Pose Estimation](15954-coarse-camera-pose-estimation.md)
Coarse Camera Pose Estimation is an incremental registration method that estimates the initial extrinsic parameters (camera pose) for unposed target images relative to a registered reference image using a learned scene regressor. It solves the problem of initializing camera poses in neural radiance field training by converting predicted 3D points into 2D-3D correspondences and solving for the pose via Perspective-n-Point (PnP). It differs from [Iterative Closest Point (ICP)](10563-iterative-closest-point-icp.md) by relying on a neural scene representation to provide dense 3D structure rather than iterative point-to-point alignment, and from [Structure-from-Motion (SfM)](16341-structure-from-motion-sfm.md) by operating incrementally on a learned regressor rather than globally on feature matches.

### Homography Parametric Alignment
A differentiable solver that estimates a 2D homography transformation $T \in SL(3)$ from point correspondences by solving a homogeneous linear least squares problem via SVD [S2]. The homography constraint in homogeneous coordinates is:
$$ \begin{bmatrix} 0 & x^j_1 & x^j_2 & 1 \end{bmatrix} = T \begin{bmatrix} x^j_1 \\ x^j_2 \\ 1 \end{bmatrix} $$
which is rearranged into the linear system $A_j h = 0$ [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ to compute centroids and covariance matrix, where $N$ is the number of points. The SVD of a $3 \times 3$ matrix is $O(1)$ (constant time relative to $N$, though dependent on dimension). Thus, the overall complexity is linear in the number of points $O(N)$.
- **Memory Complexity:** $O(N)$ to store the point sets. The auxiliary matrices ($H, U, S, V$) are fixed size ($3 \times 3$).
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of correspondences. Suitable for real-time applications given the small fixed size of the linear algebra operations.
- **Strengths:** Closed-form solution ensures deterministic results and fast computation. No initialization required.
- **Limitations:** Requires known point-to-point correspondences. Sensitive to outliers in correspondences. Cannot handle partial overlaps or missing data without robust estimation techniques (e.g., RANSAC) [G].
- **When to use:** When accurate 3D point correspondences are available and a fast, exact alignment is needed.
- **When not to use:** When correspondences are unknown, noisy, or partial, or when the transformation is not rigid (e.g., affine or projective).

## Background
Rigid Parametric Alignment, often referred to as Horn's Method, originates from the work of Berthold K.P. Horn in 1987, "Closed-form solution of absolute orientation using unit quaternions" [S2, implied by name]. It is a fundamental algorithm in computer vision and robotics for pose estimation and registration. It is widely used in [Sim(3) Alignment via Procrustes Analysis](8526-sim-3-alignment-via-procrustes-analysis.md) as a sub-step for computing the rotational component of the similarity transformation. Recent applications include differentiable rendering pipelines such as L2G-NeRF, where it is used for local-to-global registration of neural radiance fields [S2].
