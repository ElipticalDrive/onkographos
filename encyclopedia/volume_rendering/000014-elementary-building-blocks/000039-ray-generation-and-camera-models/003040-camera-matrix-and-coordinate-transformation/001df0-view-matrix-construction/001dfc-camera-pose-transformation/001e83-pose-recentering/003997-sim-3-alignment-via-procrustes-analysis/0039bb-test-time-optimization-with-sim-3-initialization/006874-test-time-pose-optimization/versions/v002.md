# Test-time Pose Optimization

Also called: Freezing 3DGS for Pose Optimization, Test View Pose Estimation, Test-time Pose Optimization for 3DGS, Test-time camera optimization, Test-time optimization for view synthesis

## Overview
Test-time Pose Optimization is a procedure to obtain accurate camera poses for testing views by freezing a pre-trained 3D Gaussian Splatting (3DGS) model and optimizing only the test view poses via photometric error minimization [S2]. It sets itself apart from sibling methods by decoupling the scene representation (frozen) from the camera parameters (optimized), specifically addressing pose errors that degrade novel view synthesis quality [S2].

## How it works
**Inputs:**
- Pre-trained 3DGS model with fixed Gaussian attributes and covariance [S2].
- Test view images [S2].
- Initial test view poses, initialized via Procrustes alignment on training cameras and nearest-neighbor lookup among learned training poses [S1, S2].

**Outputs:**
- Optimized camera poses for the test views [S1, S2].

**Data Structures:**
- Camera Pose: A $4 \times 4$ transformation matrix $P \in \mathbb{R}^{4 \times 4}$ representing the world-to-camera transformation [G].
- Photometric Loss: Mean Squared Error (MSE) or L1 loss between rendered pixels and ground truth pixels [G].

**Steps:**
1. **Procrustes Alignment:** Register the cameras of the test images using the transformation matrix obtained via Procrustes analysis on the predicted and ground truth cameras of the training images [S1]. This provides a global alignment baseline [S1].
2. **Initialization:** Initialize the camera pose of each test view using the closest camera position from the learned poses of all training frames [S2].
3. **Optimization:** Optimize the camera poses of the test images by minimizing the photometric loss between the synthesized images and the test view images [S1, S2]. This factors out the effect of pose error on view synthesis quality [S1].
4. **Interleaving:** In some pipelines (e.g., GNeRF), the test-time optimization is interleaved with the training process, so the total number of iterations depends on the number of training steps seen for the best checkpoint [S1].

**Pseudocode:**
```python
def test_time_pose_optimization(frozen_model, test_images, initial_poses, num_iterations, lr):
    # Initialize trainable parameters: list of 4x4 pose matrices
    poses = [pose.clone().detach().requires_grad_(True) for pose in initial_poses]
    # Standard optimizer state (e.g., Adam moments) initialized to zero [G]
    optimizer_state = {p: {'m': 0.0, 'v': 0.0} for p in poses}
    
    for step in range(num_iterations):
        total_loss = 0.0
        for pose, gt_image in zip(poses, test_images):
            rendered_image = frozen_model.render(pose)
            loss = sum((rendered_image - gt_image) ** 2) / rendered_image.numel() # MSE [G]
            total_loss += loss
        
        # Backpropagation and parameter update [G]
        gradients = compute_gradients(total_loss, poses)
        update_parameters(poses, gradients, optimizer_state, lr)
        
    return [pose.detach() for pose in poses]
```

**Parameters:**
- Number of test-time optimization iterations: Typically ~4230 for the GNeRF pipeline [S1]. For scenes with pose outliers, increasing iterations (e.g., from 100 to 1000) dramatically improves convergence and rendering metrics [S1].

**Edge Cases and Pitfalls:**
- **Outlier Sensitivity:** Procrustes alignment is severely affected by outlier images, which can cause exaggerated misalignment and prevent test-time optimization from converging accurately [S1].
- **Convergence:** If Procrustes alignment is poor due to outliers, increasing the number of optimization iterations is necessary to converge to a more accurate viewpoint [S1].

## Operating characteristics
- **Time Complexity:** The optimization is iterative, and the total time depends on the number of iterations and the cost of rendering each test view [S1]. For the GNeRF pipeline, it runs approximately 4230 iterations [S1].
- **Memory Complexity:** Low, as the 3DGS model is frozen and only camera poses are stored as trainable parameters [G].
- **Performance:** On a single RTX 3090 GPU, the method takes approximately 2 hours, significantly faster than methods like Nope-NeRF which take ~30 hours [S2].
- **Strengths:** Factors out pose error effects on view synthesis quality [S1].
- **Limitations:** Sensitive to initial alignment quality; may not converge accurately if initial poses are severely misaligned due to outliers [S1].
- **When to use:** When test view poses are unknown or inaccurate, and high-quality novel view synthesis is required [S1, S2].
- **When not to use:** When the scene has severe outliers that break Procrustes alignment and increasing iterations is computationally prohibitive [S1].

## Background
The method is inspired by NeRFmm [S2] and is used in the context of COLMAP-free 3D Gaussian Splatting [S2]. It is also employed in the GNeRF pipeline for evaluating novel view synthesis [S1]. The procedure follows established practices for evaluating novel view synthesis where test poses are not given [S1].
