# Sim(3) Alignment via Procrustes Analysis

Also called: Pose Accuracy Measurement, Procrustes alignment, Sim(3) BARF

## Overview
Sim(3) Alignment via Procrustes Analysis is a method to align estimated camera poses to ground truth by computing a 3D similarity transformation (Sim(3)) using Procrustes analysis on camera pose locations [S1, unofficial][S3]. It solves the problem of evaluating pose accuracy or initializing test-time optimization by finding the optimal scale, rotation, and translation that minimizes the distance between predicted and reference camera centers [S1, unofficial][S3]. It sets itself apart from [PCA Pose Alignment](7626-pca-pose-alignment.md) by explicitly solving for a global scale factor in addition to rotation and translation, whereas PCA typically only aligns axes without scaling [S1, S2, unofficial].

## How it works
**Inputs:**
- `camtoworlds`: A set of $N$ camera poses, where each pose is a $4 \times 4$ matrix representing the transformation from camera coordinates to world coordinates.
- `points` (optional): A set of 3D points in world coordinates, used for principal axes alignment.

**Outputs:**
- `aligned_camtoworlds`: The transformed camera poses.
- `aligned_points` (optional): The transformed points.
- `T_combined`: The cumulative transformation matrix applied to the inputs.

**Data Structures:**
- Camera poses are represented as $4 \times 4$ homogeneous transformation matrices:
  $$
  T = \begin{bmatrix} R & t \\ 0 & 1 \end{bmatrix}
  $$
  where $R \in \mathbb{R}^{3 \times 3}$ is a rotation matrix and $t \in \mathbb{R}^3$ is the translation vector (camera center).

**Steps:**
1. **Compute Initial Similarity Transform ($T_1$):**
   Extract the camera centers (translation vectors $t_i$) from all `camtoworlds` matrices. Compute the Sim(3) transformation $T_1$ that aligns these centers to the ground truth centers using Procrustes analysis. This involves:
   - Centering the source and target points by subtracting their centroids.
   - Computing the covariance matrix between centered source and target points.
   - Using Singular Value Decomposition (SVD) to find the optimal rotation.
   - Computing the optimal scale factor $s$ and translation $t$.
   [S2, unofficial]

2. **Transform Cameras:**
   Apply $T_1$ to all camera poses:
   $$
   \text{camtoworlds} = T_1 \times \text{camtoworlds}
   $$
   If `points` are provided, transform them as well:
   $$
   \text{points} = T_1 \times \text{points}
   $$
   [S2, unofficial]

3. **Compute Principal Axes Transform ($T_2$):**
   If `points` are provided, compute the principal axes transform $T_2$ from the transformed points. This aligns the coordinate system with the principal components of the point cloud distribution.
   [S2, unofficial]

4. **Transform Cameras and Points Again:**
   Apply $T_2$ to the cameras and points:
   $$
   \text{camtoworlds} = T_2 \times \text{camtoworlds}
   $$
   $$
   \text{points} = T_2 \times \text{points}
   $$
   [S2, unofficial]

5. **Return Results:**
   Return the aligned cameras, aligned points, and the combined transform $T_{combined} = T_2 \times T_1$.
   [S2, unofficial]

import numpy as np

def procrustes_analysis(source, target):
    """
    Computes the Sim(3) transformation (scale, rotation, translation)
    that aligns source points to target points.
    """
    # Center points
    source_mean = np.mean(source, axis=0)
    target_mean = np.mean(target, axis=0)
    source_centered = source - source_mean
    target_centered = target - target_mean
    
    # Compute scale
    # s = sum(||target_centered||^2) / sum(||source_centered||^2) ? 
    # Standard Procrustes for Sim(3) usually involves SVD for rotation and scale calculation.
    # Here we assume a standard implementation that returns s, R, t.
    # Note: Exact SVD-based Sim(3) derivation is complex; this is a placeholder for the logic.
    # In practice, this often uses the Kabsch algorithm extended for scale.
    
    # Covariance matrix
    H = source_centered.T @ target_centered
    U, S, Vt = np.linalg.svd(H)
    
    # Rotation
    d = np.sign(np.linalg.det(Vt.T @ U.T))
    D = np.diag([1, 1, d])
    R = Vt.T @ D @ U.T
    
    # Scale
    # s = trace(S * D) / sum(||source_centered||^2)
    scale = np.trace(np.diag(S) @ D) / np.sum(source_centered**2)
    
    # Translation
    t = target_mean - scale * (R @ source_mean.T).T
    
    return scale, R, t

**Edge Cases and Pitfalls:**
- Procrustes analysis is unreliable when all cameras lie in a line or camera translation contains noise [S1, unofficial].
- Incorrect pose estimations can affect the Sim(3) alignment, causing the initialization to fail [S1, unofficial].

## Subtopics

### [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md)
A differentiable solver that estimates a 3D rigid transformation $T \in SE(3)$ from correspondences by minimizing the reprojection error in a closed form using Singular Value Decomposition (SVD). It differs from Sim(3) by not estimating a scale factor, assuming the scale is known or fixed. Choose this when the scale is accurate and only rotation/translation need adjustment. [Link: [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md)]

### Sim(3) with Rotation Alignment
A variant of Sim(3) alignment that adds a virtual point to mitigate Procrustes analysis failures in degenerate cases, using camera rotation during alignment. It is chosen when cameras lie in a line or translation is noisy. However, it causes more translation errors compared to standard Sim(3). [Link: [Sim(3) with Rotation Alignment](8609-sim3-with-rotation-alignment.md)]

### Test-time Optimization with Sim(3) Initialization
A testing procedure involving Sim(3) alignment initialization followed by additional test-time optimization to adjust test poses for view synthesis. It is used when estimated poses can be aligned precisely to COLMAP poses. Incorrect pose estimations can affect the Sim(3) alignment, causing the initialization to fail. [Link: [Test-time Optimization with Sim(3) Initialization](8609-test-time-optimization.md)]

## Operating characteristics
- **Time Complexity:** Procrustes analysis is $O(N)$ for centering and $O(1)$ for SVD on $3 \times 3$ matrices, making it very fast.
- **Memory Complexity:** $O(N)$ to store camera centers and points.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales linearly with the number of cameras.
- **Strengths:** Provides a robust global alignment for pose evaluation and initialization.
- **Limitations:** Unreliable in degenerate cases (collinear cameras, noisy translations).
- **When to use:** For pose accuracy measurement and test-time optimization initialization in NeRF pipelines.
- **When not to use:** When cameras are collinear or translation noise is high; consider [Sim(3) with Rotation Alignment](8609-sim3-with-rotation-alignment.md) instead, accepting higher translation errors.

## Background
Originated from the BARF [20] and L2G-NeRF [6] papers, this method is used for pose quality assessment alignment. It was derived from the official open-source version of BARF [S1, unofficial]. It is also used in CF-NeRF [41] and DBARF [S3] for evaluating pose accuracy.
