# Structure-from-Motion (SfM)

Also called: COLMAP SfM, Camera Pose Estimation using SfM, HLOC SfM, LocalRF SfM

## Overview
Structure-from-Motion (SfM) estimates the 3D structure of a scene and the camera poses for a set of extracted video frames, providing the necessary geometric input for NeRF training [S1]. It differs from its sibling [Coarse Camera Pose Estimation](15954-coarse-camera-pose-estimation.md) by explicitly reconstructing the sparse point cloud and refining camera parameters through bundle adjustment, whereas the parent method may rely on simpler or hierarchical approximations.

## How it works
**Inputs:** A dataset of $n_{\text{frame}}$ extracted video frames.
**Outputs:** A set of $n_{\text{pose}}$ estimated camera poses (extrinsics) corresponding to the input frames, and optionally a sparse 3D point cloud.

**Data Structures:**
The implementation typically relies on one of three specific pipelines, each with distinct internal data structures for feature matching and optimization:
1.  **COLMAP:** Uses Scale-Invariant Feature Transform (SIFT) features for extraction and matching [S1].
2.  **HLOC:** Utilizes the Hierarchical Localization toolbox, which employs SuperPoint for feature extraction and SuperGlue for image matching, built upon the COLMAP framework [S1].
3.  **LocalRF:** A method capable of handling long-range trajectories and large unbounded scenes [S1].

**Steps:**
1.  **Feature Extraction:** Detect and describe keypoints in each input frame.
    *   For COLMAP: Use SIFT [S1].
    *   For HLOC: Use SuperPoint [S1].
2.  **Image Matching:** Match features between image pairs.
    *   For COLMAP: Use standard geometric verification [S1].
    *   For HLOC: Use SuperGlue [S1].
3.  **Pose Estimation:** Estimate initial camera poses and 3D points.
    *   Standard SfM pipelines (COLMAP, HLOC) may result in $n_{\text{pose}} < n_{\text{frame}}$ if some frames cannot be successfully registered [S1].
    *   LocalRF is designed to estimate poses for all frames ($n_{\text{pose}} = n_{\text{frame}}$) [S1].
4.  **Refinement (Bundle Adjustment):** Optimize camera poses and 3D points to minimize reprojection error [S1].
5.  **Ray Sampling Constraint (LocalRF Specific):** If using LocalRF, modify the internal processing to restrict ray sampling solely to valid color pixels [S1].

**Parameters:**
*   **Feature Detector:** SIFT (COLMAP) or SuperPoint (HLOC) [S1].
*   **Matcher:** SuperGlue (HLOC) [S1].
*   **Frame Count ($n_{\text{frame}}$):** Varies by dataset sparsity (e.g., 310, 1392, 2784) [S1].

**Edge Cases and Pitfalls:**
*   **Sparse Views:** COLMAP performs poorly on sparse views (e.g., 310 or 1392 frames) but performs well on dense views (2784 frames) [S1].
*   **Runtime Limits:** HLOC and LocalRF have extensive running times, making them unsuitable for large frame counts (e.g., 2784 frames) in resource-constrained contexts [S1].
*   **Missing Poses:** Standard COLMAP/HLOC pipelines may fail to estimate poses for all frames in sparse scenarios, resulting in $n_{\text{pose}} < n_{\text{frame}}$ [S1].

## Subtopics

### COLMAP SfM
Uses SIFT features. Best for dense views. [Link](15954-coarse-camera-pose-estimation.md#colmap)

### HLOC SfM
Uses SuperPoint/SuperGlue. Better effectiveness for sparse views than COLMAP. [Link](15954-coarse-camera-pose-estimation.md#hloc)

### LocalRF SfM
Handles long-range trajectories and unbounded scenes. Estimates all poses but is slow. [Link](15954-coarse-camera-pose-estimation.md#localrf)

## Operating characteristics
**Time Complexity and Performance:**
Performance was measured on a machine with a single RTX A6000 GPU and 128 GB RAM [S1].

| $n_{\text{frame}}$ | Method | $n_{\text{pose}}$ | Time (hh:mm:ss) |
| :--- | :--- | :--- | :--- |
| 310 | COLMAP | 62 | 00:08:26 |
| 310 | HLOC | 43 | 01:08:39 |
| 310 | LocalRF | 310 | 23:20:52 |
| 1392 | COLMAP | 376 | 00:49:29 |
| 1392 | HLOC | 647 | 21:51:34 |
| 1392 | LocalRF | 1392 | 75:10:54 |
| 2784 | COLMAP | 2667 | 04:32:53 |

*   COLMAP is significantly faster than HLOC, with speedup factors of 8x (310 frames) and 26.5x (1392 frames) [S1].
*   LocalRF is the slowest method, taking 23+ hours for 310 frames and 75+ hours for 1392 frames [S1].
*   HLOC and LocalRF were not used for 2784 frames due to excessive runtime [S1].

**Strengths and Limitations:**
*   **COLMAP:** Fast and effective for dense views (2784 frames). Struggles with sparse views (310, 1392 frames) [S1].
*   **HLOC:** More effective than COLMAP for sparse views (310, 1392 frames). Slower than COLMAP [S1].
*   **LocalRF:** Capable of estimating all camera poses ($n_{\text{pose}} = n_{\text{frame}}$) and handling large unbounded scenes. Unsuitable for large frame counts due to extensive running time [S1].

## Background
Structure-from-Motion is employed in workflows for rendering 3D scenes from video, such as abdominal 3-D scene rendering from laparoscopic surgical videos using NeRFs [S1]. The method is a critical pre-processing step that converts extracted video frames into geometric data (camera poses) required for training NeRF-based models [S1].
