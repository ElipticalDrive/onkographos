# Pose Registration Metrics

Also called: Pose Error Metrics, Rotation Error, Translation Error

## Overview
Pose Registration Metrics quantify the discrepancy between estimated camera poses and ground-truth poses after alignment, typically following a Sim(3) alignment step. They serve as the primary evaluation tools for assessing the global consistency of ego-motion estimation and SLAM systems [S1]. Unlike local trajectory metrics that measure cumulative drift, these metrics provide scalar summaries of rotational and translational deviations [S1].

## How it works
The method computes two distinct error components: rotation error and translation error. These are calculated on a per-pose basis and then averaged across the dataset.

**Inputs:**
- $R$: Ground-truth rotation matrix ($3 \times 3$).
- $\hat{R}$: Estimated rotation matrix ($3 \times 3$).
- $T$: Ground-truth position vector ($3 \times 1$).
- $\hat{T}$: Estimated position vector ($3 \times 1$).

**Outputs:**
- $|R_{err}|$: Rotation error in radians.
- $T_{err}$: Translation error in dataset units.

**Data Structures:**
- Rotation matrices are standard $3 \times 3$ orthogonal matrices with determinant +1.
- Position vectors are 3D coordinates. Note that positions are often not in metric space (e.g., normalized coordinates), meaning the translation error has no physical units [S1].

**Steps:**

1. **Compute Rotation Error:**
   Calculate the angle required to align the estimated rotation $\hat{R}$ with the ground-truth rotation $R$. The formula is derived from the trace of the relative rotation matrix $R^{-1}\hat{R}$:
   $$
   |R_{err}| = \cos^{-1}\left( \frac{\text{Tr}(R^{-1} \hat{R}) - 1}{2} \right)
   $$
   where $\text{Tr}(\cdot)$ denotes the trace of a matrix [S1].

2. **Compute Translation Error:**
   Calculate the Euclidean distance between the estimated position $\hat{T}$ and the ground-truth position $T$:
   $$
   T_{err} = \| \hat{T} - T \|_2
   $$
   This value represents the distance in the coordinate system's native units [S1].

3. **Aggregate:**
   Report the average rotation and translation errors across all poses in the sequence [S1].

**Pseudocode:**
```python
import numpy as np

def compute_rotation_error(R_gt, R_est):
    """
    Computes the rotation error in radians between ground-truth and estimated rotation matrices.
    """
    # Compute relative rotation matrix
    # Note: R_gt is orthogonal, so R_gt^-1 is R_gt.T
    R_rel = R_gt.T @ R_est
    
    # Compute trace
    trace_val = np.trace(R_rel)
    
    # Clamp value to [-1, 1] to handle numerical precision issues in acos
    cos_angle = (trace_val - 1.0) / 2.0
    cos_angle = np.clip(cos_angle, -1.0, 1.0)
    
    # Compute angle in radians
    angle = np.arccos(cos_angle)
    return angle

def compute_translation_error(T_gt, T_est):
    """
    Computes the Euclidean translation error between ground-truth and estimated positions.
    """
    diff = T_est - T_gt
    return np.linalg.norm(diff)

def evaluate_pose_registration(poses_gt, poses_est):
    """
    Evaluates pose registration metrics for a sequence of poses.
    
    Args:
        poses_gt: List of tuples (R_gt, T_gt)
        poses_est: List of tuples (R_est, T_est)
        
    Returns:
        avg_rot_error: Average rotation error in radians
        avg_trans_error: Average translation error in dataset units
    """
    if len(poses_gt) != len(poses_est):
        raise ValueError("Ground truth and estimated pose lists must have the same length.")
        
    rot_errors = []
    trans_errors = []
    
    for (R_gt, T_gt), (R_est, T_est) in zip(poses_gt, poses_est):
        rot_err = compute_rotation_error(R_gt, R_est)
        trans_err = compute_translation_error(T_gt, T_est)
        
        rot_errors.append(rot_err)
        trans_errors.append(trans_err)
        
    return np.mean(rot_errors), np.mean(trans_errors)
```

**Edge Cases and Pitfalls:**
- **Numerical Stability:** The argument to $\cos^{-1}$ must be clamped to $[-1, 1]$ to prevent NaNs due to floating-point inaccuracies when the rotation matrices are nearly identical [G].
- **Non-Metric Space:** Translation error units depend on the dataset's coordinate system. If poses are not in metric space, the translation error has no physical units [S1].

## Subtopics

### [Absolute Trajectory Error Computation](12727-absolute-trajectory-error-computation.md)
Absolute Trajectory Error (ATE) computes the integrated distance between all estimated pose positions relative to a ground truth trajectory after alignment. It serves as the primary metric for evaluating the global consistency of ego-motion estimation and SLAM systems. Unlike local metrics, ATE measures the cumulative drift of the estimated path against the reference path.

### Viewpoint Accuracy Evaluation
An evaluation metric based on geodesic distance tolerance between estimated and ground-truth viewpoints [S2]. The estimated viewpoint $v_\mu$ is defined as the label with the maximum probability: $v_\mu = \arg \max_{v \in V} P_v(s)$, where the distribution is modeled as $P_v(s) \sim \mathcal{N}(v_\mu, v_\sigma^2)$ [S2]. Accuracy is measured by checking if the geodesic distance between $v_\mu$ and the ground-truth viewpoint $v_s$ falls within specific tolerances: $2^\circ, 5^\circ, 8^\circ, 11^\circ, 15^\circ$ [S2]. A prediction is correct if the distance is within the chosen tolerance [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of poses, as each pose requires a constant number of matrix operations and norm calculations.
- **Memory Complexity:** $O(1)$ auxiliary space if computed incrementally, or $O(N)$ if storing per-pose errors.
- **Strengths:** Provides a simple, interpretable scalar summary of alignment quality [S1]. Rotation error is invariant to scale and translation, isolating rotational accuracy [S1].
- **Limitations:** Translation error lacks physical meaning if the coordinate system is not metric [S1]. It does not capture temporal consistency or drift over time, which is why ATE is often used in conjunction with these per-pose metrics [S1].

## Background
These metrics are standard in the evaluation of neural radiance fields (NeRF) and SLAM systems, particularly when dealing with sparse or noisy pose inputs. The rotation error formula is derived from the properties of SO(3) rotation matrices [S1]. The viewpoint accuracy metric originates from CNN-based viewpoint estimation for volume visualization [S2].
