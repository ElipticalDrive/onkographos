# Sim(3) Alignment via Procrustes Analysis

Also called: Pose Accuracy Measurement, Procrustes alignment, Sim(3) BARF

## Overview
Sim(3) Alignment via Procrustes Analysis computes a 3D similarity transformation (rotation, translation, and uniform scale) to align estimated camera poses to ground truth by applying Procrustes analysis on camera pose locations [S1, unofficial]. It is primarily used for pose quality assessment and as an initialization step for test-time optimization in neural radiance field (NeRF) reconstruction [S1, unofficial]. Unlike [PCA Pose Alignment](7626-pca-pose-alignment.md), which aligns poses based on principal component analysis of their spatial distribution, this method explicitly minimizes the geometric error between corresponding camera centers under a similarity transform [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of estimated camera poses $P_{est} = \{T_1, \dots, T_N\}$ and a set of ground truth camera poses $P_{gt} = \{T'_1, \dots, T'_N\}$, where each $T_i$ is a $4 \times 4$ transformation matrix representing the camera-to-world transformation.
*   **Output:** A $4 \times 4$ similarity transformation matrix $S \in Sim(3)$ that best aligns $P_{est}$ to $P_{gt}$ [S1, unofficial].

**Data Structures**
The method extracts the translation vectors (camera centers) from the pose matrices. For a pose $T$, the camera center $C$ is the upper-right $3 \times 1$ column of the matrix:
$$ C = \begin{bmatrix} T_{0,3} \\ T_{1,3} \\ T_{2,3} \end{bmatrix} $$
Let $C_{est} = \{c_1, \dots, c_N\}$ be the set of estimated camera centers and $C_{gt} = \{c'_1, \dots, c'_N\}$ be the set of ground truth camera centers [S1, unofficial].

**Algorithm Steps**
1.  **Centering:** Compute the centroid of the estimated centers $\bar{c}_{est} = \frac{1}{N} \sum_{i=1}^N c_i$ and the centroid of the ground truth centers $\bar{c}_{gt} = \frac{1}{N} \sum_{i=1}^N c'_i$.
2.  **Demean:** Subtract the centroids from each point to obtain centered sets:
    $$ \tilde{c}_i = c_i - \bar{c}_{est} $$
    $$ \tilde{c}'_i = c'_i - \bar{c}_{gt} $$
3.  **Covariance Matrix:** Compute the $3 \times 3$ covariance matrix $H$ between the centered estimated and ground truth points:
    $$ H = \sum_{i=1}^N \tilde{c}_i \tilde{c}'_i^T $$
4.  **Singular Value Decomposition (SVD):** Perform SVD on $H$:
    $$ H = U \Sigma V^T $$
5.  **Rotation Calculation:** Compute the rotation matrix $R$. To ensure a proper rotation (determinant +1) and handle reflections, calculate:
    $$ d = \text{sign}(\det(V U^T)) $$
    $$ R = V \begin{bmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & d \end{bmatrix} U^T $$
    [G: This is the standard Kabsch algorithm step for Procrustes analysis, necessary to ensure $R$ is a valid rotation matrix.]
6.  **Scale Calculation:** Compute the uniform scale factor $s$:
    $$ s = \frac{\sum_{i=1}^N \tilde{c}'_i \cdot (R \tilde{c}_i)}{\sum_{i=1}^N \| \tilde{c}_i \|^2} $$
    [G: This formula minimizes the least-squares error for the scale component in similarity Procrustes analysis.]
7.  **Translation Calculation:** Compute the translation vector $t$:
    $$ t = \bar{c}_{gt} - s R \bar{c}_{est} $$
8.  **Construct Sim(3) Matrix:** Assemble the final $4 \times 4$ transformation matrix $S$:
    $$ S = \begin{bmatrix} sR & t \\ 0 & 1 \end{bmatrix} $$

**Parameters**
*   $N$: Number of camera poses.
*   Typical values: None specific; depends on the dataset size.

**Edge Cases and Pitfalls**
*   **Degenerate Configurations:** Procrustes analysis is unreliable when all cameras lie in a line or when the camera translation contains significant noise [S1, unofficial]. In such cases, the covariance matrix may be ill-conditioned, leading to unstable rotation estimates.
*   **Precision:** Numerical stability depends on the conditioning of the covariance matrix $H$.

**Pseudocode**
```python
import numpy as np

def sim3_procrustes(poses_est, poses_gt):
    """
    Aligns estimated poses to ground truth using Sim(3) Procrustes analysis.
    
    Args:
        poses_est: List of N 4x4 numpy arrays (camera-to-world matrices).
        poses_gt: List of N 4x4 numpy arrays (camera-to-world matrices).
        
    Returns:
        S: 4x4 numpy array representing the Sim(3) transformation.
    """
    N = len(poses_est)
    
    # Extract camera centers (translation components)
    centers_est = np.array([T[:3, 3] for T in poses_est])
    centers_gt = np.array([T[:3, 3] for T in poses_gt])
    
    # Step 1: Compute centroids
    centroid_est = np.mean(centers_est, axis=0)
    centroid_gt = np.mean(centers_gt, axis=0)
    
    # Step 2: Demean
    centered_est = centers_est - centroid_est
    centered_gt = centers_gt - centroid_gt
    
    # Step 3: Covariance matrix
    H = centered_est.T @ centered_gt
    
    # Step 4: SVD
    U, S_vals, Vt = np.linalg.svd(H)
    V = Vt.T
    
    # Step 5: Rotation
    d = np.sign(np.linalg.det(V @ U.T))
    D = np.diag([1, 1, d])
    R = V @ D @ U.T
    
    # Step 6: Scale
    numerator = np.sum(centered_gt * (R @ centered_est.T).T, axis=1).sum()
    denominator = np.sum(centered_est ** 2)
    s = numerator / denominator
    
    # Step 7: Translation
    t = centroid_gt - s * R @ centroid_est
    
    # Step 8: Construct Sim(3) matrix
    S = np.eye(4)
    S[:3, :3] = s * R
    S[:3, 3] = t
    
    return S
```

## Subtopics

### [Test-time Optimization with Sim(3) Initialization](8565-test-time-optimization-with-sim-3-initialization.md)
A testing procedure involving Sim(3) alignment initialization followed by additional test-time optimization to adjust test poses for view synthesis. It sets itself apart from sibling methods like [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md) by explicitly decoupling the coarse alignment (via Procrustes analysis on locations) from the fine-grained pose refinement (via gradient-based optimization).

### [Rigid Parametric Alignment](8609-rigid-parametric-alignment.md)
Rigid Parametric Alignment is a differentiable solver that estimates a 3D rigid transformation $T \in SE(3)$ from point correspondences by minimizing the reprojection error in a closed form using Singular Value Decomposition (SVD). It builds on [Sim(3) Alignment via Procrustes Analysis](8526-sim-3-alignment-via-procrustes-analysis.md) by restricting the transformation group to rigid motions (rotation and translation only), thereby removing the scale component. Unlike [Test-time Optimization with Sim(3) Initialization](8565-test-time-optimization-with-sim-3-initialization.md), which uses optimization-based approaches, this method provides an analytical solution.

### Sim(3) with Rotation Alignment
A variant of Sim(3) alignment that adds a virtual point to mitigate Procrustes analysis failures in degenerate cases, using camera rotation during alignment [S1, unofficial].
**Steps:**
1.  Add a virtual point at coordinates $(0, 0, 1)$ in the camera coordinate system of each image.
2.  Use the camera parameter to transform this virtual point to the world coordinate.
3.  Use the camera rotation during the alignment process [S1, unofficial].
**Pitfalls:** This approach causes more translation errors compared to standard Sim(3) [S1, unofficial].
**Comparison:** Reduces rotation errors ($\Delta R$) but harms translation accuracy ($\Delta T$) when pose accuracy is high [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity**
The complexity is dominated by the SVD of a $3 \times 3$ matrix, which is $O(1)$ per dataset alignment. Memory usage is $O(N)$ to store the camera centers.

**Measured Performance**
Standard Sim(3) causes fewer translation errors, especially when pose accuracy is high, whereas Sim(3) with rotation reduces rotation errors but increases translation errors [S1, unofficial].

**Strengths and Limitations**
*   **Strengths:** Provides a robust, closed-form solution for aligning camera trajectories. Effective for pose quality assessment [S1, unofficial].
*   **Limitations:** Unreliable for degenerate camera configurations (e.g., collinear cameras) or noisy translations [S1, unofficial]. Does not account for rotation alignment in the standard Procrustes formulation, focusing only on translation centers.

**When to Use**
Use for initial alignment of estimated poses to ground truth for error measurement or as a coarse initialization for test-time optimization in NeRF methods like BARF and L2G-NeRF [S1, unofficial].

**When Not to Use**
Avoid when cameras are collinear or translation noise is high; consider [Sim(3) with Rotation Alignment](8526-sim-3-alignment-via-procrustes-analysis.md#sim3-with-rotation-alignment) or other variants [S1, unofficial].

## Background
The method originates from the use of Procrustes analysis in computer vision for pose alignment. It was notably employed in the BARF (Bundle-Adjusting NeRF) paper [20] and L2G-NeRF [6] for pose quality assessment and test-time optimization [S1, unofficial]. The specific variant "Sim(3) with Rotation" was introduced in CF-NeRF [41] to address degeneracies in standard Procrustes analysis [S1, unofficial].
