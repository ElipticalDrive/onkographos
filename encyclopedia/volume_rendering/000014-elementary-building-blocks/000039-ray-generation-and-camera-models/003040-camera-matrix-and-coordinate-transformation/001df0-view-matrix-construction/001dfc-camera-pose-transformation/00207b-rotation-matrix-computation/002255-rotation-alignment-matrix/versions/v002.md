# Rotation Alignment Matrix
## Overview
Computes a 3x3 rotation matrix that rotates a source vector to align with a target vector using Rodrigues' rotation formula components [S1, unofficial].
## How it works
**Inputs:**
- `from_vec`: 3D vector to rotate from.
- `to_vec`: 3D vector to align with.

**Outputs:**
- `M`: 3x3 rotation matrix.

**Data Structures:**
- `v`: 3D vector representing the cross product of `from_vec` and `to_vec`.
- `c`: Scalar representing the dot product of `from_vec` and `to_vec`.
- `k`: Scalar helper value.

**Steps:**
1. Compute `v = from_vec × to_vec` and `c = from_vec · to_vec` [S1, unofficial].
2. Handle parallel vectors: if `v` is zero and `c > 0`, return identity matrix; if `v` is zero and `c < 0`, return negative identity matrix [S1, unofficial].
3. Compute scalar `k = 1 / (1 + c)` [S1, unofficial].
4. Construct rotation matrix `M` using components of `v` and `k` [S1, unofficial]:
   - `M[0,0] = v[0]^2 * k + c`
   - `M[0,1] = v[0]*v[1]*k - v[2]`
   - `M[0,2] = v[0]*v[2]*k + v[1]`
   - `M[1,0] = v[0]*v[1]*k + v[2]`
   - `M[1,1] = v[1]^2 * k + c`
   - `M[1,2] = v[1]*v[2]*k - v[0]`
   - `M[2,0] = v[0]*v[2]*k - v[1]`
   - `M[2,1] = v[1]*v[2]*k + v[0]`
   - `M[2,2] = v[2]^2 * k + c`

**Pseudocode:**
```python
def rotation_alignment_matrix(from_vec, to_vec):
    # Compute cross product v and dot product c
    v = [
        from_vec[1] * to_vec[2] - from_vec[2] * to_vec[1],
        from_vec[2] * to_vec[0] - from_vec[0] * to_vec[2],
        from_vec[0] * to_vec[1] - from_vec[1] * to_vec[0]
    ]
    c = (from_vec[0] * to_vec[0] +
         from_vec[1] * to_vec[1] +
         from_vec[2] * to_vec[2])

    # Handle parallel vectors
    if v[0] == 0 and v[1] == 0 and v[2] == 0:
        if c > 0:
            return [[1, 0, 0], [0, 1, 0], [0, 0, 1]]
        else:
            return [[-1, 0, 0], [0, -1, 0], [0, 0, -1]]

    # Compute helper scalar
    k = 1.0 / (1.0 + c)

    # Construct rotation matrix
    v0, v1, v2 = v[0], v[1], v[2]
    M = [
        [v0 * v0 * k + c, v0 * v1 * k - v2, v0 * v2 * k + v1],
        [v0 * v1 * k + v2, v1 * v1 * k + c, v1 * v2 * k - v0],
        [v0 * v2 * k - v1, v1 * v2 * k + v0, v2 * v2 * k + c]
    ]
    return M
```

**Edge Cases and Pitfalls:**
- **Parallel Vectors:** If `from_vec` and `to_vec` are parallel, the cross product `v` is zero [S1, unofficial]. The algorithm explicitly handles this by returning the identity matrix (if `c > 0`) or negative identity matrix (if `c < 0`), which prevents division by zero when `c = -1` [S1, unofficial].
- **Normalization:** The sources do not specify if `from_vec` and `to_vec` must be normalized [S1, unofficial]. The formula assumes unit vectors for numerical stability, and precision may degrade if vectors are not normalized [G].
