# Quaternion Rotation

Also called: Quaternion Rotation of Vector, Quaternion-based vector rotation, Ray Rotation via Quaternion

## Overview
Quaternion Rotation applies a 3D rotation defined by a unit quaternion $q$ to a 3D vector $v$. It solves the problem of efficiently rotating rays or points in volume rendering pipelines without the singularities of Euler angles or the computational overhead of $4 \times 4$ matrices. It sets itself apart from [Rotation Matrix Computation](2280-rotation-matrix-computation.md) by operating directly in quaternion space, avoiding the explicit construction of a $3 \times 3$ matrix, and from [Quaternion to SO3 Conversion](2305-quaternion-to-so3-conversion.md) by returning a rotated vector rather than a rotation matrix.

## How it works
**Inputs:**
- $q$: A quaternion $(w, x, y, z)$ representing the rotation. It must be a unit quaternion ($||q||=1$).
- $v$: A 3D vector $(v_x, v_y, v_z)$ to be rotated.

**Outputs:**
- $v'$: The rotated 3D vector.

**Data Structures:**
- Quaternion $q$: 4 floating-point values $(w, x, y, z)$.
- Vector $v$: 3 floating-point values $(v_x, v_y, v_z)$.

**Steps:**
1. **Normalize** $q$ to ensure it is a unit quaternion. If $q$ is not guaranteed to be normalized, compute $q_{norm} = q / ||q||$.
2. **Extract** the scalar part $s = w$ and the vector part $u = (x, y, z)$ from the normalized quaternion.
3. **Compute** the rotated vector $v'$ using the following formula derived from quaternion algebra:
   $$ v' = 2 \cdot (u \cdot v) \cdot u + (s^2 - u \cdot u) \cdot v + 2 \cdot s \cdot (u \times v) $$
   Where:
   - $u \cdot v$ is the dot product of $u$ and $v$.
   - $u \times v$ is the cross product of $u$ and $v$.
   - $s^2 - u \cdot u$ simplifies to $2s^2 - 1$ if $q$ is normalized, but the general form is used for robustness [S2, unofficial].

**Pseudocode:**
```python
def quaternion_rotate_vector(q: list[float], v: list[float]) -> list[float]:
    """
    Rotates vector v by quaternion q.
    q: [w, x, y, z]
    v: [vx, vy, vz]
    Returns: [vx', vy', vz']
    """
    # 1. Normalize q
    w, x, y, z = q
    norm_sq = w*w + x*x + y*y + z*z
    if norm_sq != 1.0:
        inv_norm = 1.0 / (norm_sq ** 0.5)
        w *= inv_norm
        x *= inv_norm
        y *= inv_norm
        z *= inv_norm

    # 2. Extract scalar s and vector u
    s = w
    u = (x, y, z)
    
    # 3. Compute terms
    # Dot product u . v
    dot_uv = u[0]*v[0] + u[1]*v[1] + u[2]*v[2]
    
    # Term a: u * (dot(u, v) * 2.0)
    a = (u[0] * dot_uv * 2.0, u[1] * dot_uv * 2.0, u[2] * dot_uv * 2.0)
    
    # Term b: v * ((s * s) - dot(u, u))
    # Note: dot(u, u) = x*x + y*y + z*z
    dot_uu = u[0]*u[0] + u[1]*u[1] + u[2]*u[2]
    scalar_b = (s * s) - dot_uu
    b = (v[0] * scalar_b, v[1] * scalar_b, v[2] * scalar_b)
    
    # Term c: cross(u, v) * (2.0 * s)
    cross_uv = (
        u[1]*v[2] - u[2]*v[1],
        u[2]*v[0] - u[0]*v[2],
        u[0]*v[1] - u[1]*v[0]
    )
    c = (cross_uv[0] * 2.0 * s, cross_uv[1] * 2.0 * s, cross_uv[2] * 2.0 * s)
    
    # 4. Return a + b + c
    return (a[0] + b[0] + c[0], a[1] + b[1] + c[1], a[2] + b[2] + c[2])
```

**Edge Cases and Pitfalls:**
- **Non-unit quaternion:** If $q$ is not normalized, the rotation will include scaling. Always normalize $q$ first [S3, unofficial].
- **Precision:** For very small rotations, standard floating-point arithmetic is stable. However, repeated multiplications (if composing rotations) should be re-normalized to prevent drift.
- **Input Validation:** Ensure $v$ is a 3D vector and $q$ has 4 components.

## Subtopics

### Axis Extraction from Quaternion
This variant extracts the local coordinate axes of a rotated object (e.g., a Gaussian Splat) by applying the quaternion rotation to the standard basis vectors. It is used to determine the orientation of anisotropic primitives in volume rendering [S4, unofficial].
- **X-axis:** Apply `quaternion_rotate_vector` to $(1, 0, 0)$.
- **Y-axis:** Apply `quaternion_rotate_vector` to $(0, 1, 0)$.
- **Z-axis:** Apply `quaternion_rotate_vector` to $(0, 0, 1)$.

## Operating characteristics
- **Time Complexity:** $O(1)$ per vector. It involves a constant number of multiplications and additions (approx. 15-20 FLOPs).
- **Memory Complexity:** $O(1)$. No additional data structures are required beyond the input and output vectors.
- **Performance:** Faster than converting to a rotation matrix and multiplying, as it avoids the 9 multiplications and 6 additions required for matrix-vector multiplication, plus the overhead of matrix construction.
- **Strengths:** Numerically stable (if normalized), efficient, no gimbal lock.
- **Limitations:** Requires normalization of the quaternion. Not directly compatible with linear algebra libraries expecting matrices without conversion.

## Background
Quaternion rotation of vectors is a fundamental technique in 3D computer graphics and robotics, originating from the work of William Rowan Hamilton in the 19th century. In modern volume rendering and Gaussian Splatting, it is used to rotate 3D Gaussians or rays efficiently [S3, S4, unofficial]. The method is widely implemented in graphics engines and libraries due to its computational efficiency and numerical stability compared to Euler angles or rotation matrices [S1, S2, unofficial].
