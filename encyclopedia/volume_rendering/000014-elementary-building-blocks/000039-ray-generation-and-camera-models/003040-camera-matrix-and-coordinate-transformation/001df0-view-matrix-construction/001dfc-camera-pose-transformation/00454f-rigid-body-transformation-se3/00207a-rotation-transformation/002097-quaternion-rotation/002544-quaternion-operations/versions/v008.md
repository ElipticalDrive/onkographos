# Quaternion Operations

Also called: Quaternion Conjugate, Quaternion Multiplication, Rotate vector by quaternion

## Overview
This method implements the quaternion conjugate, quaternion multiplication, and vector rotation operations used to transform coordinates in volume rendering pipelines [S1, unofficial]. It exposes the underlying algebraic steps rather than abstracting them into a single rotation call.

## How it works
**Inputs:**
- Two quaternions $q_0 = (x_0, y_0, z_0, w_0)$ and $q_1 = (x_1, y_1, z_1, w_1)$, typically represented as 4-element vectors [S1, unofficial].
- A 3D vector $v = (v_x, v_y, v_z)$ to be rotated [S1, unofficial].

**Outputs:**
- Conjugate $q^* = (-x, -y, -z, w)$ [S1, unofficial].
- Product $q = q_0 \otimes q_1$ [S1, unofficial].
- Rotated vector $v'$ [S1, unofficial].

**Data Structures:**
Quaternions are stored as 4-component vectors [S1, unofficial]. The layout is $(x, y, z, w)$, where $x, y, z$ are the imaginary components and $w$ is the scalar component [S1, unofficial].

**Steps:**

1.  **Quaternion Conjugate:**
    Compute the conjugate of a quaternion $q = (x, y, z, w)$ by negating the vector part while keeping the scalar part unchanged:
    $$q^* = (-x, -y, -z, w)$$ [S1, unofficial].

2.  **Quaternion Multiplication:**
    Compute the product $q = q_0 \otimes q_1$ component-wise [S1, unofficial]. The scalar component $w$ and vector components $x, y, z$ of the result are calculated as follows:
    $$
    \begin{aligned}
    w &= w_0 w_1 - x_0 x_1 - y_0 y_1 - z_0 z_1 \\
    x &= w_0 x_1 + x_0 w_1 + y_0 z_1 - z_0 y_1 \\
    y &= w_0 y_1 - x_0 z_1 + y_0 w_1 + z_0 x_1 \\
    z &= w_0 z_1 + x_0 y_1 - y_0 x_1 + z_0 w_1
    \end{aligned}
    $$ [S1, unofficial].

3.  **Rotate Vector by Quaternion:**
    To rotate a 3D vector $v$ by a unit quaternion $q$:
    a. Treat $v$ as a pure quaternion $q_v = (v_x, v_y, v_z, 0.0)$ [S1, unofficial].
    b. Compute the conjugate $q^*$ [S1, unofficial].
    c. Compute the intermediate product $q_{temp} = q_v \otimes q^*$ [S1, unofficial].
    d. Compute the final result $q_{ret} = q \otimes q_{temp}$ [S1, unofficial].
    e. Extract the vector part $(x, y, z)$ of $q_{ret}$ as the rotated vector [S1, unofficial].

**Pseudocode:**

```python
def quaternion_conjugate(q):
    """
    Computes the conjugate of a quaternion q = (x, y, z, w).
    Returns (-x, -y, -z, w).
    """
    x, y, z, w = q
    return (-x, -y, -z, w)

def quaternion_multiply(q0, q1):
    """
    Multiplies two quaternions q0 and q1.
    q0 = (x0, y0, z0, w0), q1 = (x1, y1, z1, w1)
    Returns q0 * q1.
    """
    x0, y0, z0, w0 = q0
    x1, y1, z1, w1 = q1
    
    x = w0 * x1 + x0 * w1 + y0 * z1 - z0 * y1
    y = w0 * y1 - x0 * z1 + y0 * w1 + z0 * x1
    z = w0 * z1 + x0 * y1 - y0 * x1 + z0 * w1
    w = w0 * w1 - x0 * x1 - y0 * y1 - z0 * z1
    
    return (x, y, z, w)

def rotate_vector_by_quaternion(v, q):
    """
    Rotates a 3D vector v by a unit quaternion q.
    v = (vx, vy, vz)
    q = (qx, qy, qz, qw)
    Returns the rotated vector.
    """
    # Treat v as a pure quaternion
    qv = (v[0], v[1], v[2], 0.0)
    
    # Compute conjugate of q
    q_conj = quaternion_conjugate(q)
    
    # Compute qv * q_conj
    q_temp = quaternion_multiply(qv, q_conj)
    
    # Compute q * (qv * q_conj)
    q_ret = quaternion_multiply(q, q_temp)
    
    # Return the vector part (x, y, z)
    return (q_ret[0], q_ret[1], q_ret[2])
```

**Parameters:**
- Quaternions should be normalized (unit length) for correct rotation behavior [G]. If $q$ is not normalized, the resulting rotation will be scaled [G]. Normalization is typically performed by dividing each component by the magnitude $\sqrt{x^2+y^2+z^2+w^2}$ [G].

**Edge Cases and Pitfalls:**
- **Non-unit quaternions:** If $q$ is not normalized, the resulting rotation will be scaled [G].
- **Precision errors:** Floating-point arithmetic may introduce small errors in the scalar part of the rotated quaternion [G]. It is recommended to re-normalize the result if the quaternion is to be used in subsequent operations [G].
- **Pure quaternion assumption:** The vector rotation method assumes $v$ is treated as a pure quaternion (scalar part 0) [S1, unofficial].

## Subtopics

### [Inverse SE3 Transformation](3476-inverse-se3-transformation.md)
Computes the inverse of a rigid body transformation (Special Euclidean group SE3) defined by a rotation and a translation. It solves the problem of mapping coordinates from a transformed frame back to the original frame, which is essential for coordinate system conversions in ray generation and camera models. It sets itself apart by providing explicit implementations for both matrix and quaternion representations, ensuring numerical stability through the use of quaternion conjugates for rotation inversion.

### [Index-to-World Clipping Plane Generation](13249-index-to-world-clipping-plane-generation.md)
This method converts voxel-space index bounds (defined by minimum and maximum coordinates along the $i$, $j$, and $k$ axes) into world-space clipping planes compatible with volume rendering pipelines. It solves the problem of aligning rectangular crop regions with the physical orientation of the volume data, ensuring that clipping boundaries respect the image's spatial transformation. It differs from inverse transformation methods by explicitly constructing plane primitives from index bounds rather than transforming existing world-space geometry.

### Quaternion Möbius Transformations
Conformal transformations of 3D space formalized as quaternion Möbius transformations generated by translations, rotations, dilations, reflections, and geometric inversions [S2]. The transformation is defined as $L_H(q) = (aq+b)(cq+d)^{-1}$, where $q, a, b, c, d \in \mathbb{H}$ (quaternions) [S2]. Elementary transformations are represented by $2 \times 2$ quaternionic matrices [S2]. Types include: Identity $L(q)=q$, Dilation $L(q)=sq$ ($s \in \mathbb{R}$), Translation $L(q)=q+v$ ($v \in \mathbb{H}_0$), Inversion $L(q)=rq^{-1}$, Reflection $L(q)=-iq$, and Inversion $L(q)=q^{-1}$ [S2]. The composition of two Möbius transformations is also a Möbius transformation, with coefficients obtainable as a matrix product [S2].

### Rotation Matrix to Quaternion Conversion
Converts a 3x3 rotation matrix to a unit quaternion $[w, x, y, z]$ using eigenvalue decomposition of a specific matrix derived from the rotation matrix [S3, unofficial]. Construct matrix $K$ from rotation matrix elements $R_{xx}, R_{yx}, R_{zx}, R_{xy}, R_{yy}, R_{zy}, R_{xz}, R_{yz}, R_{zz}$: $K = \begin{bmatrix} R_{xx}-R_{yy}-R_{zz} & 0 & 0 & 0 \\ R_{yx}+R_{xy} & R_{yy}-R_{xx}-R_{zz} & 0 & 0 \\ R_{zx}+R_{xz} & R_{zy}+R_{yz} & R_{zz}-R_{xx}-R_{yy} & 0 \\ R_{yz}-R_{zy} & R_{zx}-R_{xz} & R_{xy}-R_{yx} & R_{xx}+R_{yy}+R_{zz} \end{bmatrix} / 3.0$ [S3, unofficial]. Compute eigenvalues and eigenvectors of $K$, select the eigenvector corresponding to the largest eigenvalue, and map indices to $[w, x, y, z]$ as $[3, 0, 1, 2]$ [S3, unofficial]. Ensure the $w$ component is non-negative; if negative, negate the entire quaternion vector [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for all operations (conjugate, multiplication, rotation) as they involve a fixed number of arithmetic operations [G].
- **Memory Complexity:** $O(1)$ per quaternion/vector [G].
- **Strengths:** Efficient, numerically stable for unit quaternions, avoids gimbal lock, compact representation [G].
- **Limitations:** Requires normalization to maintain unit length; interpolation (slerp) is more complex than with matrices [G].
- **When to use:** When performing multiple rotations or composing rotations in 3D space [G].
- **When not to use:** When interfacing with APIs that require rotation matrices without conversion overhead [G].

## Background
Quaternion operations are fundamental in computer graphics and robotics for representing 3D rotations [G]. The conjugate and multiplication operations are derived from Hamilton's quaternion algebra [G]. The use of quaternions for rotation avoids the gimbal lock problem associated with Euler angles and is more compact than rotation matrices [G]. The specific implementation details for conjugate and multiplication are provided in [S1, unofficial]. Quaternion Möbius transformations extend this algebra to conformal geometry, allowing for more complex spatial transformations [S2]. Rotation matrix to quaternion conversion can be performed using eigenvalue decomposition of a derived matrix [S3, unofficial].
