# Quaternion to SO3 Conversion

Also called: Hamilton quaternion rotation matrix, Quaternion to Rotation Matrix, Quaternion to Rotation Matrix Conversion, qvec2rotmat

## Overview
This method converts a 4D unit quaternion $q = (w, x, y, z)$ into a $3 \times 3$ rotation matrix $R \in SO(3)$ [S1, S2, S3, S4, S5, S6, S8, S9, unofficial]. It solves the problem of representing a 3D rotation in a format compatible with standard linear algebra operations, such as transforming camera poses or rotating 3D points in volume rendering pipelines [S7, S8, unofficial]. Unlike sibling methods like [Quaternion Operations](3474-quaternion-operations.md) which may handle general quaternion arithmetic, this method specifically targets the efficient and numerically stable generation of the orthogonal rotation matrix required for coordinate transformations [S1, S2, unofficial]. It is distinct from the inverse conversion (Matrix to Quaternion) which requires handling multiple cases based on the matrix trace to avoid singularities [S6, S7, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A quaternion $q$ represented as a 4D vector. The sources use two common orderings: $(w, x, y, z)$ [S1, S2, S3, S4, S5, S6, S8, S9, unofficial] or $(x, y, z, w)$ [S6, S7, unofficial]. The method assumes the Hamilton convention [S8, unofficial]. The input quaternion must be normalized to unit length; if not, it is normalized first [S2, S3, S4, S5, S6, S9, unofficial].
- Output: A $3 \times 3$ rotation matrix $R$ with shape $(3, 3)$ for a single quaternion, or $(N, 3, 3)$ for a batch of $N$ quaternions [S2, S3, S4, S5, S9, unofficial].

**Data Structures:**
- Quaternion $q$: A tensor of shape $(N, 4)$ or $(4,)$. Elements are floating-point numbers.
- Rotation Matrix $R$: A tensor of shape $(N, 3, 3)$ or $(3, 3)$. Elements are floating-point numbers.

**Steps:**
1. **Normalization:** If the input quaternion $q$ is not guaranteed to be a unit vector, compute its L2 norm and divide $q$ by this norm.
   $$ \text{norm} = \sqrt{q_w^2 + q_x^2 + q_y^2 + q_z^2} $$
   $$ q \leftarrow q / \text{norm} $$
   [S2, S3, S4, S5, S6, S9, unofficial]

2. **Unpacking:** Extract the scalar and vector components. Let $w$ be the scalar part and $(x, y, z)$ be the vector part.
   - If input is $(w, x, y, z)$: $w = q[0], x = q[1], y = q[2], z = q[3]$ [S2, S3, S4, S5, S8, S9, unofficial].
   - If input is $(x, y, z, w)$: $x = q[0], y = q[1], z = q[2], w = q[3]$ [S6, S7, unofficial].
   *Note: The formulas below assume the $(w, x, y, z)$ ordering as per the majority of sources [S2, S3, S4, S5, S8, S9, unofficial]. If using $(x, y, z, w)$, map indices accordingly.*

3. **Matrix Construction:** Compute the elements of $R$ using the following formulas. The matrix is symmetric in its off-diagonal terms' magnitudes but antisymmetric in sign for specific pairs, ensuring orthogonality.
   $$
   R = \begin{bmatrix}
   1 - 2(y^2 + z^2) & 2(xy - wz) & 2(xz + wy) \\
   2(xy + wz) & 1 - 2(x^2 + z^2) & 2(yz - wx) \\
   2(xz - wy) & 2(yz + wx) & 1 - 2(x^2 + y^2)
   \end{bmatrix}
   $$
   [S2, S3, S4, S5, S6, S8, S9, unofficial]

   Explicitly:
   - $R_{0,0} = 1 - 2(y^2 + z^2)$
   - $R_{0,1} = 2(xy - wz)$
   - $R_{0,2} = 2(xz + wy)$
   - $R_{1,0} = 2(xy + wz)$
   - $R_{1,1} = 1 - 2(x^2 + z^2)$
   - $R_{1,2} = 2(yz - wx)$
   - $R_{2,0} = 2(xz - wy)$
   - $R_{2,1} = 2(yz + wx)$
   - $R_{2,2} = 1 - 2(x^2 + y^2)$

   [S2, S3, S4, S5, S6, S8, S9, unofficial]

4. **Batching:** If processing a batch, stack the computed elements along the batch dimension and reshape to $(N, 3, 3)$ [S2, S3, S9, unofficial].

**Pseudocode:**
```python
import torch
import math

def quaternion_to_rotation_matrix(q):
    """
    Converts a quaternion q to a 3x3 rotation matrix R.
    Input q shape: (..., 4) with order (w, x, y, z).
    Output R shape: (..., 3, 3).
    """
    # 1. Normalize
    # q_norm = torch.norm(q, dim=-1, keepdim=True)
    # q = q / q_norm
    # [G] Normalization is often handled by the optimizer or input guarantee, 
    # but included here for completeness as per [S2, S3, S4, S5, S6, S9, unofficial].
    
    # 2. Unpack components (w, x, y, z)
    w = q[..., 0]
    x = q[..., 1]
    y = q[..., 2]
    z = q[..., 3]
    
    # 3. Compute matrix elements
    # Using the formula from [S2, S3, S4, S5, S6, S8, S9, unofficial]
    R = torch.empty((*q.shape[:-1], 3, 3), dtype=q.dtype, device=q.device)
    
    R[..., 0, 0] = 1 - 2 * (y**2 + z**2)
    R[..., 0, 1] = 2 * (x*y - w*z)
    R[..., 0, 2] = 2 * (x*z + w*y)
    
    R[..., 1, 0] = 2 * (x*y + w*z)
    R[..., 1, 1] = 1 - 2 * (x**2 + z**2)
    R[..., 1, 2] = 2 * (y*z - w*x)
    
    R[..., 2, 0] = 2 * (x*z - w*y)
    R[..., 2, 1] = 2 * (y*z + w*x)
    R[..., 2, 2] = 1 - 2 * (x**2 + y**2)
    
    return R
```

**Parameters:**
- None. The method is deterministic based on the input quaternion.

**Edge Cases and Pitfalls:**
- **Non-unit Quaternion:** If the input quaternion is not normalized, the resulting matrix will not be a pure rotation (it will include scaling). Normalization is required [S2, S3, S4, S5, S6, S9, unofficial].
- **Sign Ambiguity:** Quaternions $q$ and $-q$ represent the same rotation. The conversion produces the same matrix for both [S7, unofficial].
- **Numerical Stability:** The direct formula is numerically stable for all unit quaternions. Unlike the inverse conversion (Matrix to Quaternion), no case splitting based on trace is needed for stability [S6, S7, unofficial].

## Subtopics

### SE3 to Quaternion and Translation
This variant extracts the quaternion and translation vector from a $4 \times 4$ SE3 transformation matrix. It first extracts the top-left $3 \times 3$ submatrix as $R$ and the top-right $3 \times 1$ column as translation $t$. It then applies the standard Quaternion to SO3 Conversion (inverse direction) to convert $R$ to a quaternion $q$. The result is the pair $(q, t)$ [S6, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ for a single quaternion, $O(N)$ for a batch of $N$ quaternions. The computation involves a fixed number of multiplications and additions (approx. 20-30 FLOPs per matrix).
- Memory: $O(1)$ auxiliary memory for a single quaternion, $O(N)$ for batch processing to store the output matrix.

**Measured Performance:**
- Performance depends on the hardware and batch size. GPU implementations using tensor cores (e.g., PyTorch) can process millions of quaternions per second due to parallelization [S2, S3, S4, S5, S6, S9, unofficial].

**Strengths and Limitations:**
- Strengths: Simple, fast, and numerically stable for unit quaternions. No branching required.
- Limitations: Requires normalized input. Does not handle non-unit quaternions gracefully without pre-normalization.

**When to Use:**
- Use when a rotation matrix is needed for linear algebra operations, such as transforming camera poses in volume rendering or Gaussian Splatting [S7, S8, unofficial].

**When Not to Use:**
- Do not use if memory is extremely constrained and only the quaternion representation is needed for subsequent rotations (use [Quaternion Rotation](2302-quaternion-rotation.md) instead).
- Do not use if the input quaternion is not normalized and normalization is not feasible.

## Background
The conversion from quaternion to rotation matrix is a fundamental operation in 3D computer graphics and robotics. The Hamilton convention for quaternions is widely used in computer graphics [S8, unofficial]. The specific formula provided is standard and appears in many graphics libraries and research papers related to 3D reconstruction and Gaussian Splatting [S2, S3, S4, S5, S6, S7, S8, S9, unofficial]. The method is attributed to the general mathematical properties of quaternions representing rotations in 3D space [S1, S2, S3, S4, S5, S6, S7, S8, S9, unofficial].
