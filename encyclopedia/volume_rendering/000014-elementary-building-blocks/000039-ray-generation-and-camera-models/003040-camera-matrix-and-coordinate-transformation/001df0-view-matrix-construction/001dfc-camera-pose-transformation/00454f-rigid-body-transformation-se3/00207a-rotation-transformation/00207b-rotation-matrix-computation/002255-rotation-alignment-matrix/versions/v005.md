# Rotation Alignment Matrix

Also called: Differentiable Rotation Matrices

## Overview
The Rotation Alignment Matrix computes a $3 \times 3$ rotation matrix $R$ that rotates a source direction $v_1$ to align with a target direction $v_2$ such that $R v_1 = v_2$ [S1]. It solves the singularity in standard Rodrigues' rotation formula when $v_1 = v_2$ by providing a closed-form expression that remains differentiable in the limit [S1]. Unlike [Rotation Matrix Computation](2280-rotation-matrix-computation.md), which requires an explicit axis-angle pair, this method derives the rotation directly from two vectors and avoids normalization of the rotation axis [S1].

## How it works
**Inputs:** Two 3D vectors $v_1$ (from) and $v_2$ (to) [S1].
**Output:** A $3 \times 3$ rotation matrix $R$ [S1].
**Data Structures:**
- $v_1, v_2$: 3-element vectors (float32 or float64) [S1].
- $R$: $3 \times 3$ matrix (float32 or float64) [S1].
- Intermediate scalars $\alpha$ (dot product) and vector $\beta$ (cross product) [S1].

**Steps:**
1. Compute the dot product $\alpha = v_1 \cdot v_2$ [S1].
2. Compute the cross product $\beta = v_1 \times v_2$ [S1].
3. Handle degenerate cases:
   - If $\beta$ is zero (vectors are parallel), check $\alpha$ [S2, unofficial]. If $\alpha > 0$, return the identity matrix $I$ [S2, unofficial]. If $\alpha < 0$, return the negative identity matrix $-I$ [S2, unofficial].
   - If $\alpha = -1$ (anti-parallel vectors), the denominator $1+\alpha$ becomes zero and the rotation axis is undefined [S1]. A fallback branch is required [S1, G].
4. Compute the scalar $k = \frac{1}{1 + \alpha}$ [S1].
5. Construct the skew-symmetric matrix $[\beta]_x$ from $\beta$ [S1]:
   $$ [\beta]_x = \begin{bmatrix} 0 & -\beta_x & \beta_y \\ \beta_x & 0 & -\beta_z \\ -\beta_y & \beta_z & 0 \end{bmatrix} $$
6. Compute the outer product matrix $\beta \beta^T$ [S1].
7. Assemble $R$ using the formula:
   $$ R = \alpha I + [\beta]_x + k \beta \beta^T $$
   [S1]

**Pseudocode:**
```python
import numpy as np

def rotation_alignment_matrix(v1: np.ndarray, v2: np.ndarray) -> np.ndarray:
    """
    Computes a rotation matrix R such that R @ v1 = v2.
    Handles the case where v1 == v2 (identity) and v1 == -v2 (180 deg rotation).
    Differentiable with respect to v1 and v2.
    
    Args:
        v1: (3,) array-like, source vector.
        v2: (3,) array-like, target vector.
        
    Returns:
        (3, 3) ndarray, rotation matrix.
    """
    v1 = np.asarray(v1, dtype=np.float64)
    v2 = np.asarray(v2, dtype=np.float64)
    
    # Dot product alpha
    alpha = np.dot(v1, v2)
    
    # Cross product beta
    beta = np.cross(v1, v2)
    
    # Handle parallel/anti-parallel cases
    if np.linalg.norm(beta) < 1e-8:
        if alpha > 0:
            return np.eye(3)
        elif alpha < 0:
            return -np.eye(3)
        else:
            return np.eye(3)
            
    # General case
    k = 1.0 / (1.0 + alpha)
    
    # Skew-symmetric matrix of beta
    beta_x = np.array([
        [0.0, -beta[2], beta[1]],
        [beta[2], 0.0, -beta[0]],
        [-beta[1], beta[0], 0.0]
    ])
    
    # Outer product beta beta^T
    beta_outer = np.outer(beta, beta)
    
    # R = alpha * I + [beta]_x + k * (beta beta^T)
    R = alpha * np.eye(3) + beta_x + k * beta_outer
    
    return R
```

**Parameters:**
- None. The method is fully determined by inputs $v_1, v_2$ [S1].

**Edge Cases and Pitfalls:**
- **Parallel Vectors:** When $v_1 = v_2$, $\beta = 0$ and $\alpha = 1$, yielding $R = I$ [S1]. The formula avoids the division by zero in Rodrigues' formula [S1].
- **Anti-Parallel Vectors:** When $v_1 = -v_2$, $\alpha = -1$ and $\beta = 0$, causing division by zero in $k$ [S1]. The rotation axis is undefined [S1]. Implementation must branch to a 180-degree rotation around an arbitrary orthogonal axis [S1, G].
- **Zero Vectors:** If $v_1$ or $v_2$ is zero, the direction is undefined [S2, unofficial]. The method assumes non-zero input directions for valid alignment [S1].

## Subtopics

### [PCA Rotation](4256-pca-rotation.md)
Aligns a mesh so its first principal axis aligns with the positive X-axis and its second with the positive Y-axis. It orients geometry relative to its intrinsic shape distribution, a prerequisite for consistent voxelization or spatial hashing in volume rendering pipelines [G]. It differs from this method by deriving the rotation from the data's statistical covariance rather than rotating between two arbitrary vectors [G].

## Operating characteristics
- **Time Complexity:** $O(1)$, requiring a constant number of dot products, cross products, outer products, and matrix additions [S1].
- **Memory Complexity:** $O(1)$, storing only a few 3D vectors and a $3 \times 3$ matrix [S1].
- **Strengths:** Differentiable everywhere except the anti-parallel singularity, enabling gradient-based optimization in differentiable rendering pipelines [S1]. It avoids the normalization step that causes singularities in Rodrigues' formula at $v_1 = v_2$ [S1].
- **Limitations:** The anti-parallel case ($v_1 = -v_2$) remains a singularity where the gradient is discontinuous without explicit branching or smoothing [S1].
- **When to use:** When differentiable alignment between two vectors is required, particularly in neural rendering or optimization loops [S1].
- **When not to use:** When $v_1$ and $v_2$ are anti-parallel and a smooth, branch-free gradient is strictly required [S1].

## Background
The method was introduced by Felix Petersen, Amit Bermano, Oliver Deussen, and Daniel Cohen-Or in 2019 as part of "Pix2Vex: Image-to-Geometry Reconstruction using a Smooth Differentiable Renderer" [S1]. It was designed to enable differentiable rendering by providing a differentiable way to align normals or directions, overcoming the non-differentiability of standard Rodrigues' rotation formula at the identity rotation [S1].
