# Quaternion Rotation

Also called: Quaternion Rotation of Vector, Quaternion-based vector rotation, Ray Rotation via Quaternion

## Overview
Quaternion Rotation computes the rotated position of a 3D vector $v$ given a unit quaternion $q$ representing the rotation [S1, S2, S3, unofficial]. It solves the problem of applying 3D rotations efficiently and without the gimbal lock singularities associated with Euler angles [S3474-quaternion-operations.md]. It sets itself apart from [Rotation Matrix Computation](2280-rotation-matrix-computation.md) by avoiding the intermediate construction of a $3 \times 3$ matrix, thereby reducing memory bandwidth and arithmetic operations for single-vector rotations [S1, S2, unofficial]. It differs from [Quaternion to SO3 Conversion](2305-quaternion-to-so3-conversion.md) by operating directly on vectors rather than converting the rotation representation to a matrix format [S3474-quaternion-operations.md].

## How it works
**Inputs:**
- $q$: A quaternion $(w, x, y, z)$ representing the rotation. Must be a unit quaternion ($|q|=1$) [S3, unofficial].
- $v$: A 3D vector $(v_x, v_y, v_z)$ to be rotated [S1, S3, unofficial].

**Outputs:**
- $v'$: The rotated 3D vector $(v'_x, v'_y, v'_z)$ [S1, S3, unofficial].

**Data Structures:**
- Quaternion $q$: Stored as a 4-element structure or array. Convention: $w$ is the scalar part, $(x, y, z)$ is the vector part [S2, S3, unofficial].
- Vector $v$: Stored as a 3-element structure or array [S1, S3, unofficial].

**Steps:**
1. **Normalization**: If $q$ is not guaranteed to be a unit quaternion, normalize it:
   $$ q_{norm} = \frac{q}{\sqrt{w^2 + x^2 + y^2 + z^2}} $$
   Let the normalized components be $w, x, y, z$ [S3, unofficial].

2. **Decomposition**: Extract the scalar part $s = w$ and the vector part $\mathbf{u} = (x, y, z)$ from $q$ [S2, unofficial].

3. **Computation**: Compute the rotated vector $v'$ using the following vector algebra formula [S2, unofficial]:
   $$ v' = \mathbf{u} \cdot (2 \cdot (\mathbf{u} \cdot v)) + v \cdot (s^2 - \mathbf{u} \cdot \mathbf{u}) + (\mathbf{u} \times v) \cdot (2s) $$
   Where:
   - $\cdot$ denotes the dot product.
   - $\times$ denotes the cross product.
   - $s^2 - \mathbf{u} \cdot \mathbf{u}$ is equivalent to $w^2 - (x^2 + y^2 + z^2)$ [S2, unofficial].

   *Alternative Derivation (Hamilton Product)*:
   Treat $v$ as a pure quaternion $v_q = (0, v_x, v_y, v_z)$ [S3, unofficial].
   Compute the conjugate $q^* = (w, -x, -y, -z)$ [S3, unofficial].
   Compute $v'_{q} = q \otimes v_q \otimes q^*$, where $\otimes$ is the quaternion multiplication [S3, unofficial].
   Extract the vector part $(v'_x, v'_y, v'_z)$ from $v'_q$ [S3, unofficial].

**Parameters:**
- No additional parameters. The rotation is fully defined by $q$ and $v$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Non-unit Quaternion**: If $q$ is not normalized, the result will be scaled incorrectly. Normalization is required [S3, unofficial].
- **Precision**: For very small rotations or near-zero vectors, standard floating-point arithmetic may introduce minor errors. However, the vector algebra method [S2, unofficial] is generally numerically stable for unit quaternions.
- **Input Format**: Ensure the quaternion convention (scalar-first vs. vector-first) matches the implementation. The sources assume scalar-first $(w, x, y, z)$ [S2, S3, unofficial].

**Pseudocode:**
```python
def quaternion_rotate_vector(q: list[float], v: list[float]) -> list[float]:
    """
    Rotates vector v by quaternion q.
    q: [w, x, y, z]
    v: [vx, vy, vz]
    Returns: [vx', vy', vz']
    """
    # 1. Normalize q if necessary [S3, unofficial]
    w, x, y, z = q
    norm_sq = w*w + x*x + y*y + z*z
    if norm_sq != 1.0:
        inv_norm = 1.0 / (norm_sq ** 0.5)
        w *= inv_norm
        x *= inv_norm
        y *= inv_norm
        z *= inv_norm

    # 2. Decompose [S2, unofficial]
    s = w
    u_x, u_y, u_z = x, y, z
    v_x, v_y, v_z = v

    # 3. Compute terms [S2, unofficial]
    # term_a = u * (dot(u, v) * 2.0)
    dot_uv = u_x*v_x + u_y*v_y + u_z*v_z
    term_a_x = u_x * (dot_uv * 2.0)
    term_a_y = u_y * (dot_uv * 2.0)
    term_a_z = u_z * (dot_uv * 2.0)

    # term_b = v * ((s * s) - dot(u, u))
    dot_uu = u_x*u_x + u_y*u_y + u_z*u_z
    scalar_b = (s * s) - dot_uu
    term_b_x = v_x * scalar_b
    term_b_y = v_y * scalar_b
    term_b_z = v_z * scalar_b

    # term_c = cross(u, v) * (2.0 * s)
    cross_x = u_y*v_z - u_z*v_y
    cross_y = u_z*v_x - u_x*v_z
    cross_z = u_x*v_y - u_y*v_x
    scalar_c = 2.0 * s
    term_c_x = cross_x * scalar_c
    term_c_y = cross_y * scalar_c
    term_c_z = cross_z * scalar_c

    # 4. Return sum [S2, unofficial]
    return [term_a_x + term_b_x + term_c_x,
            term_a_y + term_b_y + term_c_y,
            term_a_z + term_b_z + term_c_z]
```

## Subtopics

### Axis Extraction from Quaternion
Extracting the basis axes of a rotated frame (e.g., for Gaussian Splatting) is a direct application of Quaternion Rotation [S4, unofficial]. To extract the local X-axis, apply the rotation to the vector $(1, 0, 0)$ [S4, unofficial]. To extract the local Y-axis, apply the rotation to $(0, 1, 0)$ [S4, unofficial]. To extract the local Z-axis, apply the rotation to $(0, 0, 1)$ [S4, unofficial]. This avoids constructing the full rotation matrix when only specific basis vectors are needed [S4, unofficial].

## Operating characteristics
**Time Complexity:** $O(1)$ per vector rotation. The vector algebra method [S2, unofficial] requires approximately 15-20 floating-point operations (dot products, cross products, multiplications, additions). The Hamilton product method [S3, unofficial] requires more operations (quaternion multiplication is ~34-44 FLOPs depending on optimization) but is algebraically equivalent.
**Memory Complexity:** $O(1)$ auxiliary space.
**Performance:** Generally faster than matrix-vector multiplication for single vectors because it avoids the overhead of constructing and storing a $3 \times 3$ matrix [S1, S2, unofficial].
**Strengths:** No gimbal lock; computationally efficient for single rotations; smooth interpolation capabilities (SLERP) are inherent to the representation [S3474-quaternion-operations.md].
**Limitations:** Requires normalization to maintain unit length; less intuitive for visualizing rotations compared to matrices; composing multiple rotations requires quaternion multiplication, not addition [S3474-quaternion-operations.md].
**When to use:** When rotating individual vectors (e.g., normals, rays, points) by a known quaternion orientation.
**When not to use:** When transforming entire coordinate systems or when matrix operations are already dominant in the pipeline (in which case [Rotation Matrix Computation](2280-rotation-matrix-computation.md) might be more cache-friendly for batched operations).

## Background
Quaternion rotation was introduced by William Rowan Hamilton in 1843 [unofficial]. In computer graphics and volume rendering, it has become a standard method for representing 3D orientations due to its compactness (4 numbers vs 9 for a matrix) and numerical stability [S3474-quaternion-operations.md]. It is widely used in camera pose transformations, skeletal animation, and 3D Gaussian Splatting [S3, S4, unofficial].
