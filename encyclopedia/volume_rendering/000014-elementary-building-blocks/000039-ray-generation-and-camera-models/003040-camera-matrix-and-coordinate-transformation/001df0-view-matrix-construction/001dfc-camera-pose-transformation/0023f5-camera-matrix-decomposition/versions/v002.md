# Camera Matrix Decomposition
Also called: Decompose Projection Matrix, Intrinsic/Extrinsic Decomposition, PnP Decomposition
## Overview
This method extracts the physical camera configuration from a projective transformation matrix by decomposing a $3 \times 4$ projection matrix into intrinsic parameters, extrinsic rotation, and translation [S1, unofficial]. It provides a direct linear decomposition to initialize metric reconstruction pipelines, differing from iterative non-linear optimization methods [G].
## How it works
**Inputs:** A $3 \times 4$ projection matrix $P$ (float32) [S1, unofficial].
**Outputs:** Intrinsic matrix $K$ ($3 \times 3$), Rotation matrix $R$ ($3 \times 3$), Translation vector $t$ ($3 \times 1$) [S1, unofficial].

**Data Structures:**
- $P$: $3 \times 4$ matrix representing the camera projection.
- $K$: $3 \times 3$ upper triangular intrinsic matrix.
- $R$: $3 \times 3$ orthogonal rotation matrix.
- $t$: $3 \times 1$ translation vector.

**Steps:**
1. **Decomposition:** Compute the decomposition of $P$ into $K$, $R$, and a homogeneous translation vector $T_h$ [S1, unofficial]. The standard relation satisfies $P = K [R | t]$ [G].
2. **Intrinsic Normalization:** Normalize the extracted intrinsic matrix $K_{raw}$ by dividing by its element $K_{raw}[2,2]$ to ensure the bottom-right element is $1.0$ [S1, unofficial].
   $$ K = \frac{K_{raw}}{K_{raw}[2,2]} $$
3. **Translation Normalization:** Normalize the translation vector by dividing by its homogeneous component $T_h[3]$ to obtain Euclidean translation $t$ [S1, unofficial].
   $$ t = \frac{T_h[0:3]}{T_h[3]} $$
4. **Pose Matrix Construction:** Construct the $4 \times 4$ pose matrix by transposing $R$ and using the normalized $t$, while padding the intrinsic matrix to a $4 \times 4$ identity structure [S1, unofficial].

**Pseudocode:**
```python
import numpy as np

def decompose_camera_matrix(P):
    """
    Decomposes a 3x4 projection matrix P into K, R, t.
    P: numpy array, shape (3, 4), dtype float32.
    Returns: K (3x3), R (3x3), t (3x1), pose_matrix (4x4), K_padded (4x4)
    """
    # Step 1: Decompose P into K, R, and homogeneous translation T_h
    # Sources mention OpenCV's cv2.decomposeProjectionMatrix [S1, unofficial]
    # Implementation uses standard QR decomposition for self-containment [G]
    K_raw, R, T_h = _standard_decomposition(P)

    # Step 2: Normalize intrinsics by dividing by K[2,2]
    K = K_raw / K_raw[2, 2]

    # Step 3: Normalize translation by dividing by T_h[3]
    t = T_h[:3] / T_h[3]

    # Step 4: Construct pose matrix with transposed R and normalized t
    pose_matrix = np.eye(4)
    pose_matrix[:3, :3] = R.T
    pose_matrix[:3, 3] = t

    # Pad K to 4x4 identity matrix as specified in sources [S1, unofficial]
    K_padded = np.eye(4)
    K_padded[:3, :3] = K

    return K, R, t, pose_matrix, K_padded

def _standard_decomposition(P):
    """
    Extracts K, R, T_h from P = K[R|t] using QR decomposition on P[:, :3] [G].
    """
    Q, R_mat = np.linalg.qr(P[:, :3])
    # Adjust signs to ensure proper rotation and upper triangular K [G]
    signs = np.sign(np.diag(R_mat))
    R_mat = R_mat * signs[np.newaxis, :]
    Q = Q * signs[:, np.newaxis]
    K = np.triu(R_mat)
    R = Q
    # Solve for homogeneous translation: K @ t_h = P[:, 3]
    T_h = np.linalg.solve(K, P[:, 3])
    T_h = np.append(T_h, 1.0)
    return K, R, T_h
```

**Parameters:**
- Precision: float32 is used for the projection matrix input [S1, unofficial].

**Edge Cases:**
- **Scale Ambiguity:** The projection matrix is scale-invariant, so the decomposition returns $t$ up to a scale factor [G].
- **Degenerate Input:** If $P$ is not a valid projection matrix (rank < 3), decomposition may produce invalid $R$ or $K$ [G].
- **Singular K:** If $K$ is singular (e.g., zero focal length), normalization by $K[2,2]$ fails [G].

## Subtopics          

### [Self-Calibration via Absolute Dual Quadric](4732-self-calibration-via-absolute-dual-quadric.md)
Recovers metric reconstruction from projective reconstruction by imposing constraints on the absolute dual quadric $\Omega^*$. Sets itself apart by formulating calibration as a linear system solvable via SVD, providing an initial estimate for refinement.

## Operating characteristics
- **Time Complexity:** $O(1)$ for fixed-size $3 \times 4$ matrix decomposition, dominated by linear algebra operations [G].
- **Memory Complexity:** $O(1)$, storing only $3 \times 4$ and $3 \times 3$ matrices [G].
- **Strengths:** Fast, deterministic, provides a direct linear estimate [G].
- **Limitations:** Sensitive to noise in $P$; assumes a valid pinhole camera model; scale ambiguity in translation [G].
- **When to Use:** Initializing camera parameters for volume rendering or 3D reconstruction from known projection matrices [G].
- **When Not to Use:** When the camera model is complex or when high precision is required without subsequent refinement [G].

## Background
This method originates from computer vision literature as a standard step in camera calibration and structure-from-motion pipelines [G]. In volume rendering, it converts camera poses from tracking systems or reconstruction algorithms into renderable camera matrices [G].
