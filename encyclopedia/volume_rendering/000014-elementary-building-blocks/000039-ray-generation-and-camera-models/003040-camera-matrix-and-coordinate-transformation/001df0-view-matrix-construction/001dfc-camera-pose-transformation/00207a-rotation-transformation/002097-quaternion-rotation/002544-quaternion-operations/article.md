# Quaternion Operations

Also called: Quaternion Conjugate, Quaternion Multiplication, Rotate vector by quaternion

## Overview
Quaternion operations provide the fundamental arithmetic for representing and composing 3D rotations without the singularities of Euler angles. This method implements the core algebraic primitives: conjugation, multiplication, and vector rotation. It is distinguished from [Quaternion Rotation](2302-quaternion-rotation.md) by explicitly defining the underlying component-wise arithmetic and data layouts required to implement the higher-level rotation logic, and from [Quaternion to SO3 Conversion](2305-quaternion-to-so3-conversion.md) by operating directly on quaternion fields rather than converting to rotation matrices.

## How it works
**Inputs and Outputs:**
- Input: Two unit quaternions $q_0 = (x_0, y_0, z_0, w_0)$ and $q_1 = (x_1, y_1, z_1, w_1)$, or a single quaternion $q$ and a 3D vector $v$.
- Output: A resulting quaternion $q_{res}$ from multiplication, or a rotated 3D vector $v'$.

**Data Structures:**
Quaternions are stored as 4-component vectors with layout $(x, y, z, w)$, where $x, y, z$ are the imaginary components and $w$ is the scalar component [S1, unofficial].

**Formulas:**
1.  **Conjugate:** The conjugate $q^*$ of $q = (x, y, z, w)$ is defined as [S1, unofficial]:
    $$q^* = (-x, -y, -z, w)$$
2.  **Multiplication:** The product $q = q_0 \otimes q_1$ is computed component-wise [S1, unofficial]:
    $$
    \begin{aligned}
    x &= w_0 x_1 + x_0 w_1 + y_0 z_1 - z_0 y_1 \\
    y &= w_0 y_1 - x_0 z_1 + y_0 w_1 + z_0 x_1 \\
    z &= w_0 z_1 + x_0 y_1 - y_0 x_1 + z_0 w_1 \\
    w &= w_0 w_1 - x_0 x_1 - y_0 y_1 - z_0 z_1
    \end{aligned}
    $$
3.  **Vector Rotation:** To rotate vector $v$ by unit quaternion $q$, treat $v$ as a pure quaternion $q_v = (v_x, v_y, v_z, 0)$ [S1, unofficial]. Compute:
    $$q_{rot} = q \otimes q_v \otimes q^*$$
    The rotated vector is the imaginary part $(x, y, z)$ of $q_{rot}$ [S1, unofficial].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def quaternion_conjugate(q):
    """
    Computes the conjugate of a quaternion q = (x, y, z, w).
    Returns (-x, -y, -z, w).
    """
    x, y, z, w = q
    return (-x, -y, -z, w)

def quaternion_multiply(q0, q1):
    """
    Multiplies two quaternions q0 and q1 in (x, y, z, w) format.
    Returns q0 * q1.
    """
    x0, y0, z0, w0 = q0
    x1, y1, z1, w1 = q1
    
    x = w0 * x1 + x0 * w1 + y0 * z1 - z0 * y1
    y = w0 * y1 - x0 * z1 + y0 * w1 + z0 * x1
    z = w0 * z1 + x0 * y1 - y0 * x1 + z0 * w1
    w = w0 * w1 - x0 * x1 - y0 * y1 - z0 * z1
    
    return (x, y, z, w)

def rotate_vector_by_quaternion(v, q):
    """
    Rotates vector v by unit quaternion q.
    v is a 3-tuple (vx, vy, vz).
    q is a 4-tuple (x, y, z, w).
    """
    # Treat v as pure quaternion
    q_v = (v[0], v[1], v[2], 0.0)
    
    # Compute q * q_v
    q_temp = quaternion_multiply(q, q_v)
    
    # Compute conjugate of q
    q_conj = quaternion_conjugate(q)
    
    # Compute (q * q_v) * q_conj
    q_rot = quaternion_multiply(q_temp, q_conj)
    
    # Return vector part
    return (q_rot[0], q_rot[1], q_rot[2])
```

**Parameters and Edge Cases:**
- Quaternions must be normalized (unit length) for valid rotation representation. Non-unit quaternions result in scaled/rotated outputs [G].
- The order of multiplication matters: $q_0 \otimes q_1 \neq q_1 \otimes q_0$.
- Precision issues may arise if $q$ is not strictly unit length; normalization is recommended before rotation [G].

## Subtopics

### [Inverse SE3 Transformation](3476-inverse-se3-transformation.md)
Computes the inverse of an SE3 transformation represented by a unit quaternion $q$ and translation $t$. The inverse rotation is the conjugate $q^*$, and the inverse translation is $-q^* \otimes t$.

### Quaternion Möbius Transformations
Conformal transformations of 3D space formalized as quaternion Möbius transformations generated by translations, rotations, dilations, reflections, and geometric inversions [S2]. The transformation is $L_H(q) = (aq+b)(cq+d)^{-1}$ where $q, a, b, c, d \in \mathbb{H}$ [S2]. Composition is achieved via matrix product of $2 \times 2$ quaternionic matrices [S2].

### Index-to-World Clipping Plane Generation
Extracts rotation quaternion from an index-to-world transformation matrix to define clipping planes for volume rendering. The rotation is applied to unit vectors to generate normals for min/max planes, which are then added to a volume mapper [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ for conjugate and multiplication (fixed number of arithmetic operations). Vector rotation involves 3 multiplications and 2 conjugates, still $O(1)$.
- **Memory Complexity:** $O(1)$ for scalar/quaternion storage.
- **Strengths:** Numerically stable for composing rotations; avoids gimbal lock; efficient for GPU parallelization.
- **Limitations:** Requires normalization to maintain unit length; interpolation (slerp) requires additional steps not covered here.
- **When to use:** When composing multiple rotations or rotating vectors in 3D space within a rendering pipeline.

## Background
Quaternion algebra was introduced by William Rowan Hamilton in 1843. In computer graphics, quaternions became standard for representing rotations due to their compactness and avoidance of singularities. The specific component-wise multiplication formula and conjugate definition are standard in graphics literature [S1, unofficial]. Quaternion Möbius transformations extend this algebra to conformal geometry [S2].
