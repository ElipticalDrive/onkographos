# 2D Rotation

Also called: Planar rotation, 2D rotation matrix application

## Overview
2D Rotation rotates a 2D vector by a specified angle within a plane perpendicular to a defined axis. It serves as the fundamental building block for constructing more complex transformations, such as those required in camera pose adjustments or matrix factorization. Unlike general 3D rotation which requires a full 3x3 matrix or quaternion, this method operates directly on the 2D components, offering a computationally lighter alternative when the rotation axis is fixed and known.

## How it works
**Inputs:**
- `p`: A 2D vector $(p_x, p_y)$ to be rotated.
- `a`: The rotation angle in radians.

**Outputs:**
- `p'`: The rotated 2D vector $(p'_x, p'_y)$.

**Data Structures:**
- The input and output are standard 2D floating-point vectors. No complex data structures are required.

**Steps:**
1. Compute the cosine and sine of the angle `a`.
2. Apply the rotation formula to update the vector components.

**Formula:**
The rotated vector $p'$ is calculated as:
$$
p' = \cos(a)p + \sin(a)(p_y, -p_x)
$$
Expanding this into components:
$$
p'_x = p_x \cos(a) + p_y \sin(a)
$$
$$
p'_y = -p_x \sin(a) + p_y \cos(a)
$$
Note: The source formula $p' = \cos(a)p + \sin(a)(p_y, -p_x)$ implies a specific orientation. The term $(p_y, -p_x)$ represents a 90-degree clockwise rotation of $p$. Standard counter-clockwise rotation usually uses $(-p_y, p_x)$. The source explicitly defines the operation as `cos(a)*p + sin(a)*vec2(p.y, -p.x)` [S1, unofficial].

**Pseudocode:**
```python
def rotate_2d(p_x, p_y, angle):
    """
    Rotates a 2D vector (p_x, p_y) by angle (in radians).
    Uses the specific convention from the source: 
    p' = cos(a)*p + sin(a)*(p_y, -p_x).
    """
    c = cos(angle)
    s = sin(angle)
    
    # Calculate new x and y based on source formula
    # p' = c * (p_x, p_y) + s * (p_y, -p_x)
    new_x = c * p_x + s * p_y
    new_y = c * p_y - s * p_x
    
    return new_x, new_y
```

**Edge Cases and Pitfalls:**
- **Angle Normalization:** While trigonometric functions handle large angles, normalizing `a` to $[-\pi, \pi]$ can improve precision for very large angles.
- **Precision:** For small angles, direct computation is stable. However, if `a` is close to 0, $\cos(a) \approx 1$ and $\sin(a) \approx 0$, which is numerically safe.
- **Axis Definition:** This method assumes rotation in the XY plane. If rotation around a different axis is needed, the vector components must be mapped appropriately before application [S1, unofficial].

## Subtopics

### [Givens Rotation](3986-givens-rotation.md)
A Givens rotation is a 2D rotation applied to a 3x3 matrix to zero out or transform specific elements, used here for QR decomposition or SVD-like iterative solving. It sets apart from general 3D rotation by operating on a single plane (defined by two axes) while leaving the third axis invariant, allowing for targeted element elimination in matrix factorization.

## Operating characteristics
- **Time Complexity:** $O(1)$ per vector rotation. Requires two trigonometric evaluations (cos, sin) and four multiplications/additions.
- **Memory Complexity:** $O(1)$. No additional memory allocation is required beyond temporary variables for the result.
- **Strengths:** Extremely fast for individual vector rotations; minimal memory footprint; simple implementation.
- **Limitations:** Only applicable to 2D planes; not suitable for arbitrary 3D rotations without decomposition; precision depends on the accuracy of the trigonometric library.
- **When to use:** When rotating individual 2D vectors in a fixed plane (e.g., XY plane) is required, such as in certain camera model adjustments or 2D texture coordinate transformations.
- **When not to use:** For rotating entire 3D objects or when the rotation axis is arbitrary and not aligned with a coordinate plane.

## Background
The concept of 2D rotation is a fundamental geometric operation in linear algebra and computer graphics. The specific implementation detail of using `vec2(p.y, -p.x)` as the orthogonal component is documented in the context of GLSL marching cubes implementations [S1, unofficial]. This approach is often used in shader programming for its simplicity and direct mapping to hardware vector operations.
