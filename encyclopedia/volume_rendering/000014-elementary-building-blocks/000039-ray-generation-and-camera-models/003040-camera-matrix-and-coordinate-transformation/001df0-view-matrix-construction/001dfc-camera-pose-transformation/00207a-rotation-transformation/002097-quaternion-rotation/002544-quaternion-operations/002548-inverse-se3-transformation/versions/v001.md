# Inverse SE3 Transformation
Also called: Inverse Rigid Body Transformation, SE3 Inverse, Taichi Inverse SE3

## Overview
Computes the inverse of a rigid body transformation (Special Euclidean group SE3) defined by a rotation quaternion $q$ and a translation vector $t$, or equivalently by a $4 \times 4$ homogeneous transformation matrix. This operation is essential for converting camera poses from world-to-camera coordinates to camera-to-world coordinates, or vice versa, during ray generation and view matrix construction in volume rendering and 3D Gaussian Splatting. It is distinguished from general matrix inversion by exploiting the orthogonality of the rotation component, reducing computational cost from $O(n^3)$ to $O(1)$ with simple vector operations.

## How it works
The method supports two input representations: quaternion-translation pairs and $4 \times 4$ matrices. Both yield the same geometric inverse.

### Inputs and Outputs
- **Input (Quaternion form):** A unit quaternion $q = [w, x, y, z]$ representing rotation, and a 3D translation vector $t = [t_x, t_y, t_z]$.
- **Input (Matrix form):** A $4 \times 4$ homogeneous transformation matrix $T$ in column-major or row-major layout (implementation dependent, see code).
- **Output (Quaternion form):** Inverse quaternion $q_{inv}$ and inverse translation $t_{inv}$.
- **Output (Matrix form):** Inverse $4 \times 4$ matrix $T^{-1}$.

### Data Structures
- **Quaternion:** 4 floating-point values $[w, x, y, z]$. Assumed to be normalized ($\|q\|=1$).
- **Vector:** 3 floating-point values $[x, y, z]$.
- **Matrix:** $4 \times 4$ grid of floating-point values.

### Formulas
For quaternion representation:
1.  **Inverse Rotation:** The inverse of a rotation represented by unit quaternion $q$ is its conjugate $q^*$.
    $$ q_{inv} = q^* = [w, -x, -y, -z] $$
2.  **Inverse Translation:** The inverse translation is the negative of the original translation vector rotated by the inverse rotation.
    $$ t_{inv} = -\text{rotate}(q^*, t) $$
    Where $\text{rotate}(q, v)$ applies the rotation $q$ to vector $v$. In component form, if $q^* = [w, \mathbf{v}]$ with $\mathbf{v} = [-x, -y, -z]$, the rotation of $t$ is:
    $$ \text{rotate}(q^*, t) = t + 2\mathbf{v} \times (\mathbf{v} \times t + w t) $$
    Or using the standard quaternion-vector multiplication formula.

For matrix representation:
Given $T = \begin{bmatrix} R & t \\ 0 & 1 \end{bmatrix}$, where $R$ is the $3 \times 3$ rotation submatrix and $t$ is the $3 \times 1$ translation column:
1.  **Inverse Rotation:** $R^T$ (transpose of $R$).
2.  **Inverse Translation:** $-R^T t$.
    $$ T^{-1} = \begin{bmatrix} R^T & -R^T t \\ 0 & 1 \end{bmatrix} $$

### Pseudocode (Quaternion Form)
```python
def inverse_se3_quaternion(q: Quaternion, t: Vector3) -> tuple[Quaternion, Vector3]:
    """
    Computes the inverse SE3 transformation from quaternion q and translation t.
    q = [w, x, y, z]
    t = [tx, ty, tz]
    """
    # Step 1: Compute conjugate quaternion
    # q* = [w, -x, -y, -z]
    q_inv = Quaternion(w=q.w, x=-q.x, y=-q.y, z=-q.z)
    
    # Step 2: Rotate the original translation vector by the inverse rotation
    # rotate(q_inv, t) applies the rotation q_inv to vector t
    t_rotated = quaternion_rotate_vector(q_inv, t)
    
    # Step 3: Negate the rotated translation
    t_inv = Vector3(x=-t_rotated.x, y=-t_rotated.y, z=-t_rotated.z)
    
    return q_inv, t_inv

def quaternion_rotate_vector(q: Quaternion, v: Vector3) -> Vector3:
    """
    Rotates vector v by quaternion q.
    Assumes q is normalized.
    Formula: v' = v + 2 * cross(q.xyz, cross(q.xyz, v) + q.w * v)
    """
    # Extract vector part of quaternion
    qx, qy, qz = q.x, q.y, q.z
    qw = q.w
    
    # Cross product of q.xyz and v
    # cross(q_vec, v) = [qy*vz - qz*vy, qz*vx - qx*vz, qx*vy - qy*vx]
    cx = qy * v.z - qz * v.y
    cy = qz * v.x - qx * v.z
    cz = qx * v.y - qy * v.x
    
    # Cross product of q.xyz and the result above
    # cross(q_vec, cross_result)
    # Let u = cross_result
    # cross(q_vec, u) = [qy*uz - qz*uy, qz*ux - qx*uz, qx*uy - qy*ux]
    ux = qy * cz - qz * cy
    uy = qz * cx - qx * cz
    uz = qx * cy - qy * cx
    
    # Final rotation: v + 2 * (cross(q_vec, cross(q_vec, v)) + qw * v)
    # Note: The standard formula is often written as:
    # v' = v + 2 * cross(q.xyz, cross(q.xyz, v) + qw * v)
    # Let's compute inner term: cross(q.xyz, v) + qw * v
    inner_x = cx + qw * v.x
    inner_y = cy + qw * v.y
    inner_z = cz + qw * v.z
    
    # Now cross q.xyz with inner
    final_x = qy * inner_z - qz * inner_y
    final_y = qz * inner_x - qx * inner_z
    final_z = qx * inner_y - qy * inner_x
    
    # v' = v + 2 * final
    return Vector3(
        x=v.x + 2 * final_x,
        y=v.y + 2 * final_y,
        z=v.z + 2 * final_z
    )
```

### Pseudocode (Matrix Form)
```python
def inverse_se3_matrix(T: Matrix4x4) -> Matrix4x4:
    """
    Computes the inverse of a 4x4 SE3 transformation matrix.
    T is assumed to be in the form:
    [ R00 R01 R02 Tx ]
    [ R10 R11 R12 Ty ]
    [ R20 R21 R22 Tz ]
    [  0   0   0   1 ]
    Note: Source [S1, unofficial] uses row-major indexing for extraction but constructs the result
    such that R_T is the transpose of the upper-left 3x3 block of T.
    """
    # Extract the 3x3 rotation matrix R from T
    # Source [S1, unofficial] extracts R_T directly as the transpose of the upper-left 3x3 of T
    # R_T[i, j] = T[j, i] for i,j in 0..2
    
    # Extract translation vector t from T (first 3 elements of 4th column)
    # Source [S1, unofficial] uses T[0,3], T[1,3], T[2,3]
    t_x = T[0, 3]
    t_y = T[1, 3]
    t_z = T[2, 3]
    
    # Compute inverse translation: -R_T * t
    # R_T is 3x3, t is 3x1
    # inv_t_x = -(R_T[0,0]*t_x + R_T[0,1]*t_y + R_T[0,2]*t_z)
    # inv_t_y = -(R_T[1,0]*t_x + R_T[1,1]*t_y + R_T[1,2]*t_z)
    # inv_t_z = -(R_T[2,0]*t_x + R_T[2,1]*t_y + R_T[2,2]*t_z)
    
    # Since R_T[i, j] = T[j, i]:
    # inv_t_x = -(T[0,0]*t_x + T[1,0]*t_y + T[2,0]*t_z)
    # inv_t_y = -(T[0,1]*t_x + T[1,1]*t_y + T[2,1]*t_z)
    # inv_t_z = -(T[0,2]*t_x + T[1,2]*t_y + T[2,2]*t_z)
    
    inv_t_x = -(T[0, 0] * t_x + T[1, 0] * t_y + T[2, 0] * t_z)
    inv_t_y = -(T[0, 1] * t_x + T[1, 1] * t_y + T[2, 1] * t_z)
    inv_t_z = -(T[0, 2] * t_x + T[1, 2] * t_y + T[2, 2] * t_z)
    
    # Construct the inverse matrix
    # T_inv = [ R_T  inv_t ]
    #         [  0     1   ]
    # R_T[i, j] = T[j, i]
    
    return Matrix4x4(
        row0=[T[0, 0], T[1, 0], T[2, 0], inv_t_x],
        row1=[T[0, 1], T[1, 1], T[2, 1], inv_t_y],
        row2=[T[0, 2], T[1, 2], T[2, 2], inv_t_z],
        row3=[0.0, 0.0, 0.0, 1.0]
    )
```

### Parameters and Edge Cases
- **Normalization:** The input quaternion $q$ must be normalized. If not, the rotation is incorrect. [G] It is recommended to normalize $q$ before computing the conjugate if the source is not guaranteed to be unit length.
- **Precision:** Floating-point errors can accumulate. For repeated inversions, re-normalizing the quaternion is advised.
- **Degenerate Input:** If $T$ is not a valid rigid body transformation (e.g., rotation submatrix is not orthogonal), the result will be geometrically incorrect.

## Operating characteristics
- **Time Complexity:** $O(1)$ for both quaternion and matrix forms. The quaternion form involves a few multiplications and additions. The matrix form involves 9 multiplications and 6 additions for the translation part, plus copying the rotation.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** Significantly faster than general matrix inversion ($O(n^3)$). In GPU kernels (e.g., Taichi, CUDA), this operation is highly parallelizable and has low latency.
- **Strengths:** Numerically stable for rigid bodies; computationally cheap; easy to implement.
- **Limitations:** Only applicable to rigid transformations (SE3). Does not handle scaling or shearing. If the input is not a valid SE3 matrix, the result is undefined.

## Background
The SE3 group represents rigid body motions in 3D space. The inverse operation is a fundamental concept in robotics, computer graphics, and computer vision. In the context of 3D Gaussian Splatting and volume rendering, it is used to transform points between world and camera coordinate systems. The specific implementation details provided in the sources are from the Taichi 3D Gaussian Splatting project [S1, unofficial], which uses this transformation for camera pose management.
