# Quaternion Rotation
Also called: Quaternion Rotation of Vector, Quaternion-based vector rotation
## Overview
Quaternion Rotation applies a 3D rotation to a vector using quaternion algebra, avoiding the gimbal lock issues of Euler angles and the computational overhead of full $3 \times 3$ matrix multiplication [S1, S2, unofficial]. It sets itself apart from [SE2 Lie Group Implementation](3144-se2-lie-group-implementation.md) and [2D Rotation](3357-2d-rotation.md) by operating in 3D space with unit quaternions, and from [Quaternion to SO3 Conversion](2305-quaternion-to-so3-conversion.md) by directly yielding a rotated vector rather than an intermediate rotation matrix [G].
## How it works
**Inputs:**
- $q$: A quaternion $(w, x, y, z)$ representing the rotation. Must be a unit quaternion.
- $v$: A 3D vector $(v_x, v_y, v_z)$ to be rotated.

**Outputs:**
- $v'$: The rotated 3D vector.

**Data Structures:**
- Quaternions are stored as 4-element vectors/tensors.
- Vectors are stored as 3-element vectors/tensors.

**Steps:**
1. **Normalize $q$**: Ensure $q$ is a unit quaternion. If $q$ is not guaranteed to be normalized, compute $q_{norm} = q / \|q\|$.
2. **Extract Vector Part**: Let $q_v = (x, y, z)$ be the vector part of $q$.
3. **Compute Intermediate Vector $t$**: Calculate the cross product of the vector part of the quaternion and the input vector, then scale by 2:
   $$ t = 2 (q_v \times v) $$
4. **Compute Second Cross Product**: Calculate the cross product of $q_v$ and $t$:
   $$ u = q_v \times t $$
5. **Combine Terms**: The rotated vector is the sum of $u$, the scaled scalar part of $q$ times $t$, and the original vector $v$:
   $$ v' = u + (w \cdot t) + v $$
   Where $w$ is the scalar part of $q$.

**Alternative Formulation (Hamilton Product):**
1. Normalize $q$.
2. Treat $v$ as a pure quaternion $v_q = (0, v_x, v_y, v_z)$.
3. Compute the conjugate $q^* = (w, -x, -y, -z)$.
4. Compute the Hamilton product $p = q \otimes v_q$.
5. Compute the Hamilton product $result = p \otimes q^*$.
6. Return the vector part $(result_x, result_y, result_z)$ of $result$.

**Pseudocode (Optimized Cross-Product Form):**
```python
def quaternion_rotate_vector(q, v):
    """
    Rotates vector v by quaternion q.
    q: [w, x, y, z]
    v: [vx, vy, vz]
    """
    # 1. Normalize q if necessary [G]
    # norm_q = sqrt(q[0]^2 + q[1]^2 + q[2]^2 + q[3]^2)
    # if norm_q != 1.0:
    #     q = q / norm_q
    
    w, x, y, z = q[0], q[1], q[2], q[3]
    vx, vy, vz = v[0], v[1], v[2]
    
    # 2. Extract vector part of q
    qv = [x, y, z]
    
    # 3. Compute t = 2 * cross(qv, v)
    # cross(qv, v) = [y*vz - z*vy, z*vx - x*vz, x*vy - y*vx]
    tx = 2 * (y * vz - z * vy)
    ty = 2 * (z * vx - x * vz)
    tz = 2 * (x * vy - y * vx)
    
    # 4. Compute u = cross(qv, t)
    ux = y * tz - z * ty
    uy = z * tx - x * tz
    uz = x * ty - y * tx
    
    # 5. v' = u + w*t + v
    rx = ux + w * tx + vx
    ry = uy + w * ty + vy
    rz = uz + w * tz + vz
    
    return [rx, ry, rz]
```

**Edge Cases and Pitfalls:**
- **Non-unit Quaternion**: If $q$ is not normalized, the rotation will include scaling. Normalization is required [S2, unofficial].
- **Zero Vector**: Rotating a zero vector yields a zero vector.
- **Precision**: Floating-point errors can accumulate if quaternions are not re-normalized periodically in iterative applications [G].

## Operating characteristics
- **Time Complexity**: $O(1)$ per vector. The optimized cross-product method requires ~15 multiplications and ~12 additions, which is generally faster than the 27 multiplications and 18 additions required for full matrix-vector multiplication [S1, S2, unofficial].
- **Memory Complexity**: $O(1)$ auxiliary space.
- **Strengths**: Numerically stable, avoids gimbal lock, compact storage (4 floats vs 9 for a matrix), efficient for composition [S2, unofficial].
- **Limitations**: Less intuitive for visualization than matrices; interpolation requires spherical linear interpolation (slerp) which is more complex than linear interpolation of matrices [G].
- **When to use**: Preferred for rotating many vectors, composing rotations, or storing camera orientations in memory-constrained environments.
- **When not to use**: When interfacing with APIs that strictly require $3 \times 3$ or $4 \times 4$ matrices, or when debugging rotation logic where matrix visualization is helpful.

## Background
Quaternions were introduced by William Rowan Hamilton in 1843. In computer graphics and volume rendering, they became popular for camera pose representation and interpolation due to their ability to avoid gimbal lock and provide smooth interpolation [S1, S2, unofficial]. The optimized cross-product formulation is widely used in GPU shaders and deep learning frameworks for its efficiency [S1, unofficial].
