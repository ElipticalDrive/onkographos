# Quaternion Operations

Also called: Quaternion Conjugate, Quaternion Multiplication, Rotate vector by quaternion

## Overview
This article defines the fundamental arithmetic operations for unit quaternions: conjugation, multiplication, and vector rotation. These operations serve as the computational core for [Quaternion Rotation](2302-quaternion-rotation.md), enabling the transformation of 3D vectors and the composition of rotations in volume rendering pipelines. Unlike direct matrix multiplication, quaternion operations maintain numerical stability and avoid gimbal lock, while offering lower computational overhead for rotation composition.

## How it works

### Inputs and Outputs
*   **Input**: Two quaternions $q_0 = (x_0, y_0, z_0, w_0)$ and $q_1 = (x_1, y_1, z_1, w_1)$, typically represented as 4-element vectors. A 3D vector $v = (v_x, v_y, v_z)$ may also be provided for rotation.
*   **Output**: A resulting quaternion $q_{res}$ or a rotated 3D vector $v'$.

### Data Structures
Quaternions are stored as 4-component vectors. The standard layout used in the source is $(x, y, z, w)$, where $x, y, z$ form the vector part and $w$ is the scalar part [S1, unofficial].

### Formulas

**1. Quaternion Conjugate**
The conjugate of a quaternion $q = (x, y, z, w)$ is defined as [S1, unofficial]:
$$q^* = (-x, -y, -z, w)$$

**2. Quaternion Multiplication**
The product $q = q_0 \otimes q_1$ is computed component-wise [S1, unofficial]:
$$
\begin{aligned}
x &= w_0 x_1 + x_0 w_1 + y_0 z_1 - z_0 y_1 \\
y &= w_0 y_1 - x_0 z_1 + y_0 w_1 + z_0 x_1 \\
z &= w_0 z_1 + x_0 y_1 - y_0 x_1 + z_0 w_1 \\
w &= w_0 w_1 - x_0 x_1 - y_0 y_1 - z_0 z_1
\end{aligned}
$$

**3. Rotate Vector by Quaternion**
To rotate a 3D vector $v$ by a unit quaternion $q$:
1.  Treat $v$ as a pure quaternion $q_v = (v_x, v_y, v_z, 0.0)$ [S1, unofficial].
2.  Compute the intermediate quaternion: $q_{temp} = q \otimes q_v \otimes q^*$ [S1, unofficial].
3.  Extract the vector part $(x, y, z)$ of $q_{temp}$ as the result $v'$ [S1, unofficial].

### Pseudocode

```python
def quaternion_conjugate(q):
    """
    Computes the conjugate of a quaternion q = (x, y, z, w).
    Returns (-x, -y, -z, w).
    """
    x, y, z, w = q
    return (-x, -y, -z, w)

def quaternion_multiply(q0, q1):
    """
    Multiplies two quaternions q0 and q1.
    q0 = (x0, y0, z0, w0), q1 = (x1, y1, z1, w1)
    Returns q0 * q1.
    """
    x0, y0, z0, w0 = q0
    x1, y1, z1, w1 = q1
    
    x = w0 * x1 + x0 * w1 + y0 * z1 - z0 * y1
    y = w0 * y1 - x0 * z1 + y0 * w1 + z0 * x1
    z = w0 * z1 + x0 * y1 - y0 * x1 + z0 * w1
    w = w0 * w1 - x0 * x1 - y0 * y1 - z0 * z1
    
    return (x, y, z, w)

def rotate_vector_by_quaternion(v, q):
    """
    Rotates vector v by quaternion q.
    v = (vx, vy, vz)
    q = (qx, qy, qz, qw)
    Returns rotated vector v'.
    """
    # Treat v as pure quaternion
    qv = (v[0], v[1], v[2], 0.0)
    
    # Compute q * qv
    temp1 = quaternion_multiply(q, qv)
    
    # Compute conjugate of q
    q_conj = quaternion_conjugate(q)
    
    # Compute (q * qv) * q_conj
    q_result = quaternion_multiply(temp1, q_conj)
    
    # Return vector part
    return (q_result[0], q_result[1], q_result[2])
```

### Parameters and Edge Cases
*   **Normalization**: The rotation formula assumes $q$ is a unit quaternion ($|q|=1$). If $q$ is not normalized, the result will be scaled incorrectly. Normalization is not part of the basic operation but is a prerequisite for correct rotation [G].
*   **Precision**: Floating-point errors can accumulate during repeated multiplications. Re-normalization may be required in iterative applications [G].
*   **Order of Multiplication**: Quaternion multiplication is non-commutative ($q_0 \otimes q_1 \neq q_1 \otimes q_0$). The order specified in the formula must be preserved [S1, unofficial].

## Subtopics

### [Inverse SE3 Transformation](3476-inverse-se3-transformation.md)
Computes the inverse of a rigid body transformation (Special Euclidean group SE3) defined by a rotation quaternion $q$ and a translation vector $t$, or equivalently by a $4 \times 4$ homogeneous transformation matrix. This operation is essential for converting camera poses from world-to-camera coordinates to camera-to-world coordinates, or vice versa, during ray generation and view matrix construction in volume rendering and 3D Gaussian Splatting. It is distinguished from general matrix inversion by exploiting the orthogonality of the rotation component, reducing computational cost from $O(n^3)$ to $O(1)$ with simple vector operations.

## Operating characteristics

*   **Time Complexity**: Quaternion multiplication and conjugation are $O(1)$ operations, involving a fixed number of arithmetic operations (16 multiplications and 12 additions for multiplication [S1, unofficial]). Vector rotation involves two multiplications and one conjugation, also $O(1)$.
*   **Memory Complexity**: $O(1)$ for storing the quaternion and intermediate results.
*   **Strengths**: Computationally efficient compared to $3 \times 3$ or $4 \times 4$ matrix operations. Avoids gimbal lock. Compact representation (4 floats vs 9 or 16).
*   **Limitations**: Interpolation (slerp) requires additional logic. Non-commutativity requires careful ordering. Not as intuitive for visualizing rotation axes as Euler angles [G].
*   **When to Use**: When composing multiple rotations or rotating many vectors efficiently. Essential for [Quaternion Rotation](2302-quaternion-rotation.md).
*   **When Not to Use**: When explicit rotation matrices are required for compatibility with other graphics APIs or when interpolating between rotations (use Slerp instead).

## Background
Quaternion operations are fundamental in computer graphics and robotics for representing 3D rotations. The specific formulas and implementation details cited here are derived from implementations in 3D Gaussian Splatting pipelines, where efficient rotation of points and normals is critical for rendering performance [S1, unofficial]. The use of the $(x, y, z, w)$ layout is common in modern GPU-based rendering engines.
