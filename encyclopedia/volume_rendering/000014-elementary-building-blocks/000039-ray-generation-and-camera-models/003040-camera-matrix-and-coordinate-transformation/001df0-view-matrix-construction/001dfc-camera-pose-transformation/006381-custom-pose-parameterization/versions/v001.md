# Custom Pose Parameterization

Also called: augmented weak-perspective model, world-to-camera parameterization

## Overview
Custom Pose Parameterization is a differentiable representation for camera pose optimization that avoids orthogonality constraints, rotation-translation dependency, and translation-focal length entanglement [S1]. It parameterizes a world-to-camera transformation using a quaternion, scale, 2D translation, and a perspective distortion factor [S1]. Unlike standard camera-to-world matrices which require enforcing orthogonality on the rotation matrix and suffer from entanglement between translation and focal length, this method provides more "linear" optimization dynamics while remaining fully differentiable and convertible to standard view matrices [S1].

## How it works
**Inputs:**
- Rotation parameter $q \in \mathbb{R}^4$: a unit quaternion representing the world-to-camera rotation [S1].
- Screen-space scale $s \in \mathbb{R}$: a scalar parameter for scaling in screen space [S1].
- Screen-space translation $t_2 \in \mathbb{R}^2$: a 2D vector for translation in screen space [S1].
- Perspective distortion factor $z_0 \in \mathbb{R}$: a scalar used to derive the focal length [S1].

**Outputs:**
- Focal length $f \in \mathbb{R}$ [S1].
- 3D translation vector $t_3 \in \mathbb{R}^3$ [S1].
- Rotation matrix $R \in \mathbb{R}^{3 \times 3}$ derived from $q$ [S1].

**Data Structures:**
The parameters are stored as independent floating-point values. $q$ is normalized to unit length. $z_0$ is unconstrained. $s$ is typically positive. $t_2$ is a 2D vector.

**Steps:**
1. Compute the focal length $f$ from the perspective distortion factor $z_0$:
   $$f = 1 + \exp(z_0)$$
   [S1]
2. Compute the 3D translation vector $t_3$ from the screen-space translation $t_2$, scale $s$, and focal length $f$:
   $$t_3 = \begin{bmatrix} t_2 / s \\ f / s \end{bmatrix}$$
   [S1]
   Here, $t_2/s$ forms the first two components (x, y) and $f/s$ forms the third component (z) of $t_3$.
3. Convert the unit quaternion $q$ to a $3 \times 3$ rotation matrix $R$ [S1].
4. Construct the world-to-camera view matrix $V$ using $R$ and $t_3$:
   $$V = \begin{bmatrix} R & -R t_3 \\ 0 & 1 \end{bmatrix}$$
   [G] (Standard construction from rotation and translation for world-to-camera transform).

**Pseudocode:**
```python
import numpy as np

def quaternion_to_rotation_matrix(q):
    """Convert a unit quaternion [w, x, y, z] to a 3x3 rotation matrix."""
    w, x, y, z = q
    # Standard quaternion to rotation matrix conversion
    R = np.array([
        [1 - 2*y*y - 2*z*z, 2*x*y - 2*w*z, 2*x*z + 2*w*y],
        [2*x*y + 2*w*z, 1 - 2*x*x - 2*z*z, 2*y*z - 2*w*x],
        [2*x*z - 2*w*y, 2*y*z + 2*w*x, 1 - 2*x*x - 2*y*y]
    ])
    return R

def compute_pose_parameters(q, s, t2, z0):
    """
    Compute focal length and 3D translation from custom pose parameters.
    
    Args:
        q: numpy array of shape (4,), unit quaternion [w, x, y, z]
        s: float, screen-space scale
        t2: numpy array of shape (2,), screen-space translation [tx, ty]
        z0: float, perspective distortion factor
        
    Returns:
        f: float, focal length
        t3: numpy array of shape (3,), 3D translation
        R: numpy array of shape (3, 3), rotation matrix
    """
    # Step 1: Compute focal length
    f = 1.0 + np.exp(z0)
    
    # Step 2: Compute 3D translation
    # t3 = [t2 / s; f / s]
    t3 = np.zeros(3)
    t3[0] = t2[0] / s
    t3[1] = t2[1] / s
    t3[2] = f / s
    
    # Step 3: Compute rotation matrix from quaternion
    R = quaternion_to_rotation_matrix(q)
    
    return f, t3, R

def build_view_matrix(R, t3):
    """
    Build world-to-camera view matrix from rotation and translation.
    
    Args:
        R: numpy array of shape (3, 3), rotation matrix
        t3: numpy array of shape (3,), 3D translation
        
    Returns:
        V: numpy array of shape (4, 4), view matrix
    """
    V = np.eye(4)
    V[:3, :3] = R
    V[:3, 3] = -R @ t3
    return V
```

**Parameters:**
- $z_0$: Typical values are not specified, but it is optimized directly. The exponential ensures $f > 1$. [S1]
- $s$: Screen-space scale. [S1]
- $t_2$: Screen-space translation. [S1]
- $q$: Unit quaternion. [S1]

**Edge Cases and Pitfalls:**
- Standard camera-to-world view matrices require enforcing orthogonality constraints on the rotation matrix, which complicates optimization [S1]. This method avoids that by using a quaternion.
- Standard representations suffer from entanglement between translation and focal length, requiring amplified learning rates for translation as depth increases to maintain linear behavior in projective space [S1]. This parameterization decouples them.
- Existing neural renderer implementations may present gradient detachments when coarse-fine importance sampling is used and view-dependent effects are enabled [S1]. This method ensures full differentiability w.r.t. the pose even in these scenarios [S1].

## Subtopics

### Camera Pose Parameterization
A parameterization of camera poses $T_i = [R_i | t_i] \notin SE(3)$ for optimization, representing position as a 3D vector and rotation as a 6D vector to avoid expensive exponential map conversions during training [S2]. It represents the position component $t$ as a 3D vector and the rotation $R$ as a 6D vector $R = [v_a | v_b]$ where $v_a, v_b \in \mathbb{R}^3$ [S2]. The third basis vector is computed as $v_c = v_a \times v_b$ [S2]. Gram-Schmidt orthonormalization is performed on $v_a, v_b, v_c$ to obtain orthonormal bases $\bar{v}_a, \bar{v}_b, \bar{v}_c$ [S2]. The rotation matrix is constructed as $R = [\bar{v}_a^T | \bar{v}_b^T | \bar{v}_c^T]$ [S2]. This method is chosen for its simplicity and efficiency in high-frequency operations during training [S2].

## Operating characteristics
**Time and Memory Complexity:**
The conversion from parameters to view matrix involves basic arithmetic operations and a quaternion-to-matrix conversion, which is constant time $O(1)$ and memory $O(1)$ [S1, S2].

**Strengths and Limitations:**
Strengths: Avoids orthogonality constraints, reduces rotation-translation dependency, and decouples translation from focal length for more linear optimization dynamics [S1]. Fully differentiable even with coarse-fine sampling and view-dependent effects [S1]. Efficient for high-frequency operations [S2].
Limitations: Requires conversion to standard view matrices for use in neural renderers [S1]. The 6D vector parameterization requires Gram-Schmidt orthonormalization which can be numerically unstable if not implemented carefully [S2].

**When to use it and when not:**
Use when optimizing camera poses in neural rendering pipelines where differentiability and optimization stability are critical [S1]. Use when avoiding orthogonality constraints is beneficial [S1]. Use when computational efficiency in pose conversion is needed [S2]. Not given in the sources for when not to use.

## Background
**Origin:**
The custom pose parameterization was introduced in "Shape, Pose, and Appearance from a Single Image via Bootstrapped Radiance Field Inversion" [S1]. The 6D vector parameterization was introduced in "CRAYM: Neural Field Optimization via Camera RAY Matching" [S2].

**History and Development:**
The custom pose parameterization was developed to address issues in pose estimation and parameterization for neural renderers, specifically the need for orthogonality constraints, rotation-translation dependency, and translation-focal length entanglement [S1]. It is used in the initial data preparation and hybrid inversion steps for pose optimization [S1]. The 6D vector parameterization was developed to simplify and speed up the high-frequency operation of pose parameterization during training [S2].

**Where it is used:**
Used in neural rendering pipelines for pose optimization [S1]. Used in aerial path planning for efficient urban scene reconstruction [S2].
