# View Transformations

Also called: Modeling and Viewing Matrix Setup, VolPack View Transformations

## Overview
View Transformations define the pipeline for mapping volume data from its native object coordinate system to the final image plane. This method manages four distinct transformation matrices (modeling, viewing, projection, and viewport) that collectively handle the geometric positioning of the volume, the camera orientation, and the final clipping and mapping to screen coordinates. It is distinct from sibling methods like [Camera Look-at Basis Construction](3990-camera-look-at-basis-construction.md) by managing the entire state stack of transformations rather than computing a single basis, and differs from [View Matrix Construction](1644-view-matrix-construction.md) by handling the full pipeline including projection and viewport stages.

## How it works
**Inputs and Outputs:**
The method operates on a rendering context (`vpContext`) and modifies internal state matrices. It does not produce a single output matrix but establishes the state for subsequent rendering calls. The primary inputs are transformation parameters (rotation angles, translation vectors, scaling factors, or projection bounds).

**Data Structures:**
VolPack maintains four transformation matrices internally:
1.  **Modeling Matrix:** Transforms object coordinates to world coordinates.
2.  **Viewing Matrix:** Transforms world coordinates to eye coordinates.
3.  **Projection Matrix:** Transforms eye coordinates to clip coordinates.
4.  **Viewport Matrix:** Transforms clip coordinates to image coordinates.

The coordinate systems implied are:
*   **Object:** Volume data resides in a unit cube centered at the origin.
*   **World:** The global coordinate space.
*   **Eye:** Camera-centered space, looking down the -Z axis.
*   **Clip:** Homogeneous clip space.
*   **Image:** Final 2D screen coordinates.

**Parameters and Defaults:**
*   **Multiplication Mode:** Default is post-multiplication ($M_{new} = M_{old} \times R$). Pre-multiplication can be enabled via `vpSeti` with `CONCAT_MODE`.
*   **Vector Multiplication:** Vectors are always post-multiplied regardless of the matrix concatenation mode.
*   **Projection Type:** `VP_PARALLEL` for parallel projection. Perspective projection is noted as a future release feature.

**Numbered Steps:**
1.  **Select Target Matrix:** Call `vpCurrentMatrix(vpc, VP_MODEL)`, `VP_VIEW`, `VP_PROJECT`, or `VP_VIEWPORT` to set the active matrix stack.
2.  **Initialize:** Call `vpIdentityMatrix(vpc)` to reset the active matrix to the identity.
3.  **Apply Transformations:** Use `vpTranslate`, `vpRotate`, `vpScale`, or `vpMultMatrix` to modify the active matrix.
    *   `vpRotate(vpc, axis, angle)`: Rotates by `angle` degrees around `axis` (`VP_X_AXIS`, `VP_Y_AXIS`, `VP_Z_AXIS`).
    *   `vpTranslate(vpc, x, y, z)`: Translates by `(x, y, z)`.
    *   `vpScale(vpc, sx, sy, sz)`: Scales by `(sx, sy, sz)`.
    *   `vpMultMatrix(vpc, m)`: Multiplies the current matrix by matrix `m`.
    *   `vpSetMatrix(vpc, m)`: Replaces the current matrix with `m`.
4.  **Configure Projection:** Switch to `VP_PROJECT` and call `vpWindow` or `vpWindowPHIGS`.
    *   `vpWindow`: Defines a parallel projection box using `left`, `right`, `bottom`, `top`, `near`, `far` in eye coordinates.
    *   `vpWindowPHIGS`: Uses the PHIGS viewing model with View Reference Point (`vrp`), View Plane Normal (`vpn`), View Up Vector (`vup`), and Projection Reference Point (`prp`).
5.  **Lighting Setup:** Call `vpSetLight`. The light direction vector is transformed by the **modeling matrix** active at the time of this call.
6.  **Rendering:** When rendering, the volume is transformed by the current modeling matrix, and the viewing/projection/viewport matrices are applied.

**Pseudocode:**
```python
def setup_view_transformation(vpc):
    # 1. Setup Modeling Matrix
    vpCurrentMatrix(vpc, VP_MODEL)
    vpIdentityMatrix(vpc)
    # Rotate 90 degrees around X axis
    vpRotate(vpc, VP_X_AXIS, 90.0)
    # Rotate 23 degrees around Y axis
    vpRotate(vpc, VP_Y_AXIS, 23.0)
    
    # 2. Setup Viewing Matrix
    vpCurrentMatrix(vpc, VP_VIEW)
    vpIdentityMatrix(vpc)
    # Translate 0.1 along X axis
    vpTranslate(vpc, 0.1, 0.0, 0.0)
    
    # 3. Setup Projection Matrix
    vpCurrentMatrix(vpc, VP_PROJECT)
    # Define parallel projection volume in eye coordinates
    # left=-0.5, right=0.5, bottom=-0.5, top=0.5, near=-0.5, far=0.5
    vpWindow(vpc, VP_PARALLEL, -0.5, 0.5, -0.5, 0.5, -0.5, 0.5)
    
    # 4. Setup Lighting
    # Note: Light direction is transformed by the MODELING matrix 
    # active at the time of this call.
    vpSetLight(vpc, light_direction_vector)
    
    # 5. Viewport is set automatically based on image size.
```

**Edge Cases and Pitfalls:**
*   **Light Direction Timing:** Light direction vectors are transformed by the modeling matrix *in effect at the time of the call to `vpSetLight`*, not at render time. Changing the modeling matrix after setting the light will not update the light's direction in world space.
*   **Volume Transformation Timing:** Volumes are transformed according to the modeling matrix *in effect at the time of rendering*.
*   **Data Consistency:** If the underlying volume data array is modified, `vpCreateMinMaxOctree` must be called to recompute the octree, or renderings will be incorrect.
*   **Multiplication Order:** By default, transformations are post-multiplied. If pre-multiplication is required, `vpSeti` with `CONCAT_MODE` must be called.

## Operating characteristics
*   **Time Complexity:** Matrix operations are $O(1)$ for standard 4x4 matrix multiplications and updates.
*   **Memory Complexity:** Maintains four 4x4 matrices in the context.
*   **Strengths:** Provides a complete, state-based pipeline similar to OpenGL's fixed-function pipeline. Handles the full chain from object to image coordinates.
*   **Limitations:** Limited to parallel projection in current implementations (perspective is noted as future). The separation of light direction transformation (at set time) vs volume transformation (at render time) can be confusing.
*   **When to use:** When using the VolPack library and needing to define the complete geometric transformation pipeline.
*   **When not to use:** When custom projection matrices or non-standard coordinate systems are required outside the VolPack context.

## Background
VolPack is a library for volume rendering. The transformation system is based on the PHIGS (Programmer's Hierarchical Interactive Graphics System) viewing model concepts, specifically referencing *Computer Graphics: Principles and Practice* by Foley, van Dam, Feiner, and Hughes. The system implies five coordinate systems: object, world, eye, clip, and image. The object coordinate system contains the volume in a unit cube centered at the origin.
