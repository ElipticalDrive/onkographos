# Arcball Camera View & Projection Matrix Computation
Also called: Arcball Camera Matrices, Camera View & Projection Matrix Computation, Perspective View Setup

## Overview
Computes the view and perspective projection matrices for an arcball-style camera, handling rotation around a pivot point and avoiding pitch flip artifacts. It differs from standard look-at methods by explicitly managing the camera position via sequential yaw and pitch rotations around a fixed target, ensuring the view direction remains well-defined even at extreme angles.

## How it works
**Inputs:**
- Camera position ($P$), target ($T$), and up vector ($U$).
- Yaw angle ($\theta_{yaw}$) and pitch angle ($\theta_{pitch}$).
- Pivot point ($C$), typically the target $T$.
- Screen aspect ratio ($w/h$), vertical field of view ($\phi$), near plane ($z_{near}$), and far plane ($z_{far}$).

**Outputs:**
- View matrix ($M_{view}$).
- Projection matrix ($M_{proj}$).

**Data Structures:**
- Vectors are 3D ($x, y, z$).
- Matrices are 4x4 column-major.
- Rotation matrices are constructed from axis-angle representation.

**Parameters:**
- $z_{near} = 0.01$ [S1, unofficial].
- $z_{far} = 100.0$ [S1, unofficial].
- $\phi = \pi / 2.0$ (90 degrees) [S1, unofficial].

**Steps:**
1. **Compute View Direction:** Calculate the normalized vector from the target to the current position: $V = \text{normalize}(P - T)$.
2. **Gimbal Lock Check:** Compute the dot product $d = V \cdot U$. If $d \cdot \text{sign}(\theta_{pitch}) > 0.99$, set $\theta_{pitch} = 0.0$ to prevent pitch flip [S1, unofficial].
3. **Yaw Rotation:** Rotate the position $P$ around the pivot $C$ by $\theta_{yaw}$ using $U$ as the rotation axis. Let the result be $P_{yaw}$:
   $$ P_{yaw} = R(U, \theta_{yaw})(P - C) + C $$
4. **Right Vector:** Compute the right vector $R_{vec}$ from the rotated position:
   $$ R_{vec} = \text{normalize}(U \times P_{yaw}) $$
   *Note: The source code computes `glm::cross(&self.up, &self.position)` which implies $U \times P_{yaw}$ before normalization or use in rotation [S1, unofficial].*
5. **Pitch Rotation:** Rotate $P_{yaw}$ around the pivot $C$ by $\theta_{pitch}$ using $R_{vec}$ as the rotation axis. Let the result be $P_{final}$:
   $$ P_{final} = R(R_{vec}, \theta_{pitch})(P_{yaw} - C) + C $$
6. **View Matrix:** Construct $M_{view}$ using a look-at function with eye position $P_{final}$, target $T$, and up vector $U$ [S1, unofficial].
7. **Projection Matrix:** Construct $M_{proj}$ using perspective projection with aspect ratio $w/h$, vertical FOV $\phi$, $z_{near}$, and $z_{far}$ [S1, unofficial].

**Pseudocode:**
```python
import math
import numpy as np

def arcball_camera_matrices(position, target, up, yaw, pitch, pivot, width, height, znear=0.01, zfar=100.0, fovy=math.pi/2.0):
    """
    Computes view and projection matrices for an arcball camera.
    
    Args:
        position: np.array([x, y, z]), current camera position
        target: np.array([x, y, z]), look-at target
        up: np.array([x, y, z]), world up vector
        yaw: float, yaw angle in radians
        pitch: float, pitch angle in radians
        pivot: np.array([x, y, z]), center of rotation (usually target)
        width: int, viewport width
        height: int, viewport height
        znear: float, near clipping plane
        zfar: float, far clipping plane
        fovy: float, vertical field of view in radians
        
    Returns:
        view_matrix: 4x4 numpy array
        proj_matrix: 4x4 numpy array
    """
    # Step 1: Compute view direction
    view_dir = position - target
    view_dir_norm = view_dir / np.linalg.norm(view_dir)
    
    # Step 2: Gimbal lock check
    cos_angle = np.dot(view_dir_norm, up)
    pitch_sign = 1.0 if pitch >= 0 else -1.0
    if cos_angle * pitch_sign > 0.99:
        pitch = 0.0
        
    # Step 3: Yaw rotation around up vector
    # Rotate position around pivot using yaw and up axis
    position_rel = position - pivot
    rotation_x = rotation_matrix(up, yaw)
    position_rotated = np.dot(rotation_x, position_rel) + pivot
    
    # Step 4: Compute right vector
    # Note: Source uses cross(up, position). We use the rotated position.
    right_vec = np.cross(up, position_rotated)
    right_vec_norm = right_vec / np.linalg.norm(right_vec)
    
    # Step 5: Pitch rotation around right vector
    position_rel_rotated = position_rotated - pivot
    rotation_y = rotation_matrix(right_vec_norm, pitch)
    final_position = np.dot(rotation_y, position_rel_rotated) + pivot
    
    # Step 6: View matrix (LookAt)
    view_matrix = look_at(final_position, target, up)
    
    # Step 7: Projection matrix (Perspective)
    aspect = width / height
    proj_matrix = perspective(fovy, aspect, znear, zfar)
    
    return view_matrix, proj_matrix

def rotation_matrix(axis, angle):
    """
    Computes a 4x4 rotation matrix for rotating around a given axis by a given angle.
    Axis is assumed to be normalized.
    """
    axis = axis / np.linalg.norm(axis)
    x, y, z = axis
    c = math.cos(angle)
    s = math.sin(angle)
    t = 1 - c
    
    # Rotation matrix components
    # R = [ t*x^2+c   t*x*y-s*z   t*x*z+s*y   0 ]
    #     [ t*x*y+s*z  t*y^2+c    t*y*z-s*x   0 ]
    #     [ t*x*z-s*y  t*y*z+s*x  t*z^2+c     0 ]
    #     [ 0          0          0           1 ]
    
    mat = np.eye(4)
    mat[0, 0] = t * x * x + c
    mat[0, 1] = t * x * y - s * z
    mat[0, 2] = t * x * z + s * y
    
    mat[1, 0] = t * x * y + s * z
    mat[1, 1] = t * y * y + c
    mat[1, 2] = t * y * z - s * x
    
    mat[2, 0] = t * x * z - s * y
    mat[2, 1] = t * y * z + s * x
    mat[2, 2] = t * z * z + c
    
    return mat

def look_at(eye, target, up):
    """
    Computes a 4x4 view matrix (LookAt).
    """
    z_axis = eye - target
    z_axis = z_axis / np.linalg.norm(z_axis)
    
    x_axis = np.cross(up, z_axis)
    x_axis = x_axis / np.linalg.norm(x_axis)
    
    y_axis = np.cross(z_axis, x_axis)
    
    # View matrix is the inverse of the camera-to-world transform
    # Camera-to-world is [R | T] where R is [x; y; z] and T is eye
    # Inverse is [R^T | -R^T * T]
    
    view = np.eye(4)
    view[0, 0] = x_axis[0]
    view[0, 1] = x_axis[1]
    view[0, 2] = x_axis[2]
    view[0, 3] = -np.dot(x_axis, eye)
    
    view[1, 0] = y_axis[0]
    view[1, 1] = y_axis[1]
    view[1, 2] = y_axis[2]
    view[1, 3] = -np.dot(y_axis, eye)
    
    view[2, 0] = z_axis[0]
    view[2, 1] = z_axis[1]
    view[2, 2] = z_axis[2]
    view[2, 3] = -np.dot(z_axis, eye)
    
    return view

def perspective(fovy, aspect, znear, zfar):
    """
    Computes a 4x4 perspective projection matrix.
    """
    f = 1.0 / math.tan(fovy / 2.0)
    
    proj = np.zeros((4, 4))
    proj[0, 0] = f / aspect
    proj[1, 1] = f
    proj[2, 2] = (zfar + znear) / (znear - zfar)
    proj[2, 3] = -1.0
    proj[3, 2] = (2 * zfar * znear) / (znear - zfar)
    proj[3, 3] = 0.0
    
    return proj
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per frame. Matrix multiplications and vector operations are constant time for fixed-size matrices.
- **Memory Complexity:** $O(1)$. Stores only the camera state and two 4x4 matrices.
- **Strengths:** Robust against gimbal lock at extreme pitch angles. Simple to implement. Provides intuitive control for orbiting around a target.
- **Limitations:** Not suitable for first-person cameras where the up vector should remain fixed relative to the world or camera. The pitch flip check is a heuristic (0.99 threshold) and may not cover all edge cases.
- **When to use:** Interactive 3D viewers, orbit cameras, and applications where the camera rotates around a central object.
- **When not to use:** First-person shooters, flight simulators, or any application requiring continuous pitch rotation without limits.

## Background
The arcball camera technique was popularized by Ken Shoemake in "Arcball Control of 2D Objects" (1992) [S1, unofficial]. It allows users to rotate objects by dragging on a virtual sphere. The specific implementation described here, including the pitch flip prevention, is found in the 3D Gaussian Splatting reference implementation by Thomas Antony [S1, unofficial].
