# Orbit Camera Controls

Also called: Orbit Camera Controller, Spherical Orbit Camera

## Overview
An interactive camera controller that manipulates a camera's pose using spherical coordinates (distance, theta, phi) relative to a target center, enabling orbiting, panning, and zooming operations [S2, unofficial]. It differs from [Arcball Camera View & Projection Matrix Computation](2210-arcball-camera-view-projection-matrix-computation.md) by using explicit spherical angles rather than quaternion-based rotation from mouse vectors, and from [Camera Look-at Computation via Rotation](2696-camera-look-at-computation-via-rotation.md) by maintaining a persistent target center that can be panned independently of the orbit angles [G]. It builds on [Orbit Camera Basis Computation](1749-orbit-camera-basis-computation.md) to derive the final view matrix from the computed pose [G].

## How it works
### Inputs and Outputs
- **Inputs**: Mouse delta $(dx, dy)$ for orbit/pan, scroll wheel delta $\delta$ (or $yoffset$) for zoom, and optional explicit parameter updates [S1, unofficial][S2, unofficial].
- **Outputs**: A $4 \times 4$ view matrix representing the camera's current pose [S1, unofficial].

### Data Structures
The controller maintains the following state variables:
- `center`: A 3D vector $(c_x, c_y, c_z)$ representing the target point. Default: $(0, 0, 0)$ [S2, unofficial].
- `radius` (or `distance`): A scalar representing the distance from `center` to the camera position. Default: $5.0$ [S2, unofficial].
- `theta`: A scalar representing the yaw angle. Default: $0.0$ [S2, unofficial].
- `phi`: A scalar representing the pitch angle from the Y-axis. Default: $\pi/4$ [S2, unofficial].
- `rot`: A $3 \times 3$ orthonormal rotation matrix representing the camera's orientation. Initialized to the identity matrix [S1, unofficial].
- `rotate_speed`: A scalar controlling orbit rotation sensitivity. Default: $0.8$ [S1, unofficial].
- `pan_speed`: A scalar controlling panning sensitivity. Not given in the sources.
- `zoom_speed`: A scalar controlling zoom sensitivity. Not given in the sources.

### Steps
1. **Initialization**: Set `center` to $(0, 0, 0)$, `radius` to $5.0$, `theta` to $0.0$, `phi` to $\pi/4$, `rot` to the $3 \times 3$ identity matrix, and `rotate_speed` to $0.8$ [S1, unofficial][S2, unofficial].
2. **Orbit Update**: On mouse drag $(dx, dy)$, compute rotation vectors in radians:
   $$\text{rotvec}_x = \text{rot}[:, 1] \times \text{np.radians}(100 \times \text{rotate\_speed} \times dx)$$
   $$\text{rotvec}_y = \text{rot}[:, 0] \times \text{np.radians}(-100 \times \text{rotate\_speed} \times dy)$$
   where $\text{rot}[:, 0]$ is the first column (right vector) and $\text{rot}[:, 1]$ is the second column (up vector) [S1, unofficial].
   Compose rotations: $\text{rot} \leftarrow R_y \times R_x \times \text{rot}$, where $R_x = \text{R.from\_rotvec}(\text{rotvec}_x).\text{as\_matrix}()$ and $R_y = \text{R.from\_rotvec}(\text{rotvec}_y).\text{as\_matrix}()$ [S1, unofficial].
   Alternatively, update spherical angles directly: $\theta \leftarrow \theta - dx \times \text{rotationSpeed}$, $\phi \leftarrow \phi - dy \times \text{rotationSpeed}$ [S2, unofficial]. Clamp $\phi$ to $[0.01, \pi - 0.01]$ to avoid gimbal lock at the poles [S2, unofficial].
3. **Zoom Update**: On scroll delta $\delta$ (or $yoffset$), update radius: $\text{radius} \leftarrow \text{radius} \times 1.1^{-\delta}$ [S1, unofficial]. Alternatively, $\text{distance} \leftarrow \text{distance} - yoffset \times \text{zoomSpeed} \times \text{distance}$ [S2, unofficial]. Clamp to $[0.1, 100.0]$ [S2, unofficial].
4. **Pan Update**: On mouse drag $(dx, dy, dz)$, update center using the rotation matrix: $\text{center} \leftarrow \text{center} + 10^{-4} \times \text{rot} \times [dx, dy, dz]^T$ [S1, unofficial]. Alternatively, compute camera-space basis vectors: $\text{forward} = \text{normalize}(\text{targetPos} - \text{camPos})$, $\text{right} = \text{normalize}(\text{cross}(\text{forward}, \text{up}))$, $\text{up} = \text{normalize}(\text{cross}(\text{right}, \text{forward}))$, then update target: $\text{targetPos} \leftarrow \text{targetPos} + \text{right} \times (-dx \times \text{panSpeed} \times \text{distance}) + \text{up} \times (dy \times \text{panSpeed} \times \text{distance})$ [S2, unofficial].
5. **View Matrix Construction**: Compute camera position from spherical coordinates: $x = \text{distance} \times \sin(\phi) \times \cos(\theta)$, $y = \text{distance} \times \cos(\phi)$, $z = \text{distance} \times \sin(\phi) \times \sin(\theta)$ [S2, unofficial]. Set camera position: $\text{camPos} = \text{targetPos} + [x, y, z]^T$ [S2, unofficial]. Construct the $4 \times 4$ view matrix $V$: initialize as identity, apply rotation $V[0:3, 0:3] = \text{rot}$, apply translation $V[2, 3] -= \text{radius}$, then apply center offset $V[0:3, 3] -= \text{center}$ [S1, unofficial].

### Pseudocode
```python
import numpy as np
from scipy.spatial.transform import Rotation as R

class OrbitCameraController:
    def __init__(self):
        self.center = np.array([0.0, 0.0, 0.0])
        self.radius = 5.0
        self.theta = 0.0
        self.phi = np.pi / 4.0
        self.rot = np.eye(3)
        self.rotate_speed = 0.8
        self.pan_speed = 1.0
        self.zoom_speed = 1.0
        self.min_radius = 0.1
        self.max_radius = 100.0

    def update_orbit(self, dx, dy):
        rotvec_x = self.rot[:, 1] * np.radians(100 * self.rotate_speed * dx)
        rotvec_y = self.rot[:, 0] * np.radians(-100 * self.rotate_speed * dy)
        R_x = R.from_rotvec(rotvec_x).as_matrix()
        R_y = R.from_rotvec(rotvec_y).as_matrix()
        self.rot = R_y @ R_x @ self.rot

    def update_zoom(self, delta):
        self.radius *= 1.1 ** (-delta)
        self.radius = np.clip(self.radius, self.min_radius, self.max_radius)

    def update_pan(self, dx, dy, dz=0.0):
        delta_vec = np.array([dx, dy, dz])
        self.center += 1e-4 * (self.rot @ delta_vec)

    def get_view_matrix(self):
        x = self.radius * np.sin(self.phi) * np.cos(self.theta)
        y = self.radius * np.cos(self.phi)
        z = self.radius * np.sin(self.phi) * np.sin(self.theta)
        cam_pos = self.center + np.array([x, y, z])
        view = np.eye(4)
        view[:3, :3] = self.rot
        view[2, 3] -= self.radius
        view[:3, 3] -= self.center
        return view
```

## Subtopics

### [Arcball Camera View & Projection Matrix Computation](2210-arcball-camera-view-projection-matrix-computation.md)
Uses quaternion-based rotation from mouse vectors, offering smoother rotation without gimbal lock but requiring more complex state management. Choose when smooth, continuous rotation is prioritized over explicit spherical coordinates.

### [Camera Look-at Computation via Rotation](2696-camera-look-at-computation-via-rotation.md)
Focuses on computing the view matrix from a target and up vector, without maintaining orbit state. Choose when the camera pose is determined by external logic rather than interactive controls.

### [Spherical Camera Path Generation](3934-spherical-camera-path-generation.md)
Generates smooth camera paths along spherical coordinates for animation. Choose when automated camera movement is needed rather than interactive control.

### [Volume Visualization Camera](4116-volume-visualization-camera.md)
Specialized camera controls for volume rendering, often including clipping planes and transfer function adjustments. Choose when specific volume rendering features are required.

## Operating characteristics
- **Time Complexity**: $O(1)$ per frame for updates and view matrix construction [G].
- **Memory Complexity**: $O(1)$, storing only a few scalars and a $3 \times 3$ matrix [G].
- **Measured Performance**: Not given in the sources.
- **Scaling**: Linear with respect to input delta magnitude; performance remains constant regardless of scene resolution or object count [G].
- **Strengths**: Simple to implement, intuitive for users, computationally efficient [G].
- **Limitations**: Gimbal lock at poles if using spherical angles directly; requires careful handling of coordinate systems [S2, unofficial][G].
- **When to use**: Interactive 3D viewers, volume rendering applications, general-purpose camera controls [G].
- **When not to use**: When smooth, continuous rotation is critical (use Arcball), or when camera path is pre-defined (use Spherical Camera Path Generation) [G].

## Background
Orbit camera controls are a standard technique in 3D graphics for interactive visualization [G]. The method described here is implemented in open-source rendering projects such as those using Taichi and OpenGL for volume rendering or splatting [S1, unofficial][S2, unofficial].
