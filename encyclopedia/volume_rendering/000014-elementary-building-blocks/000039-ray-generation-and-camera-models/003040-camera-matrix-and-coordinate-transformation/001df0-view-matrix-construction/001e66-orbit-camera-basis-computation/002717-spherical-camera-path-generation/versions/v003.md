# Spherical Camera Path Generation
Also called: 360° Orbit Path, Circular Orbit Camera

## Overview
Generates a smooth circular camera path looking at a target for 360° orbit video rendering [S1, unofficial]. It differs from [Arcball Camera View & Projection Matrix Computation](2210-arcball-camera-view-projection-matrix-computation.md) by producing a continuous temporal sequence of poses rather than a single interactive view, and from [Orbit Camera Controls](3262-orbit-camera-controls.md) by automating the trajectory generation for offline video export rather than providing user input handling [G].

## How it works
**Inputs:**
- `n_frames`: Integer number of frames in the path (default 120) [S1, unofficial].
- `radius`: Float distance from the target (default 4.0) [S1, unofficial].
- `target`: 3D vector defining the look-at point (default `[0, 0, 0]`) [S1, unofficial].

**Outputs:**
- `poses`: `torch.Tensor` of shape `[n_frames, 4, 4]` containing camera-to-world matrices [S1, unofficial].

**Data Structures:**
- The output is a contiguous tensor where each `4x4` slice represents a homogeneous transformation matrix [S1, unofficial].
- Matrix layout follows OpenGL convention: `+z` is backward [S1, unofficial].
- Columns 0, 1, 2 are the Right, Up, and -Forward vectors respectively. Column 3 is the translation (camera position) [S1, unofficial].

**Steps:**
1. For each frame index $i$ from $0$ to $n\_frames - 1$:
   a. Compute the orbital angle:
      $$ \theta_i = \frac{2\pi i}{n\_frames} $$ [S1, unofficial].
   b. Compute the camera position $\mathbf{p} = (x, y, z)$:
      $$ x = \text{radius} \cdot \cos(\theta_i) $$
      $$ y = \text{radius} \cdot 0.3 $$
      $$ z = \text{radius} \cdot \sin(\theta_i) $$ [S1, unofficial].
   c. Compute the forward vector $\mathbf{f}$ pointing from the camera to the target:
      $$ \mathbf{f} = \text{normalize}(-\text{target}) $$ [S1, unofficial]. (The source uses `origin` to denote the target point; numerically this computes the direction from $\mathbf{p}$ to `target`.)
   d. Compute the right vector $\mathbf{r}$:
      $$ \mathbf{r} = \text{normalize}(\mathbf{f} \times [0, 1, 0]) $$ [S1, unofficial].
   e. Compute the up vector $\mathbf{u}$:
      $$ \mathbf{u} = \mathbf{r} \times \mathbf{f} $$ [S1, unofficial].
   f. Construct the $4 \times 4$ camera-to-world matrix $C$:
      $$ C_{:3,0} = \mathbf{r}, \quad C_{:3,1} = \mathbf{u}, \quad C_{:3,2} = -\mathbf{f}, \quad C_{:3,3} = \mathbf{p} $$ [S1, unofficial].

**Pseudocode:**
```python
import torch
import math

def generate_spherical_camera_path(n_frames=120, radius=4.0, target=None):
    """
    Generate a spherical camera path looking at a target.
    
    Args:
        n_frames (int): Number of frames.
        radius (float): Distance from target.
        target (torch.Tensor): Look-at target, shape (3,). Default [0,0,0].
        
    Returns:
        torch.Tensor: Camera-to-world matrices, shape (n_frames, 4, 4).
    """
    if target is None:
        target = torch.tensor([0.0, 0.0, 0.0])
        
    poses = []
    
    for i in range(n_frames):
        # 1. Compute angle
        angle = 2.0 * math.pi * i / n_frames
        
        # 2. Compute position
        cam_x = radius * math.cos(angle)
        cam_y = radius * 0.3
        cam_z = radius * math.sin(angle)
        position = torch.tensor([cam_x, cam_y, cam_z])
        
        # 3. Compute forward vector (direction from camera to target)
        forward = target - position
        forward = forward / torch.norm(forward)
        
        # 4. Compute right vector
        world_up = torch.tensor([0.0, 1.0, 0.0])
        right = torch.cross(forward, world_up)
        right = right / torch.norm(right)
        
        # 5. Compute up vector
        up = torch.cross(right, forward)
        
        # 6. Construct 4x4 matrix (OpenGL convention: +z backward)
        mat = torch.eye(4)
        mat[:3, 0] = right
        mat[:3, 1] = up
        mat[:3, 2] = -forward
        mat[:3, 3] = position
        
        poses.append(mat)
        
    return torch.stack(poses)
```

## Subtopics

### Circular Sensor Array Initialization
Programmatically generates a set of perspective camera sensors arranged uniformly in a circle around a central point, configured for Mitsuba 3 rendering [S2, unofficial]. It differs from the main method by instantiating specific renderer sensor objects with film properties rather than returning raw pose matrices, and by supporting arbitrary numbers of discrete sensors rather than a continuous video frame sequence [G]. It is chosen when rendering a static multi-view dataset or a light field using a specific path tracer [G]. Parameters include `num_sensors` (count), `render_res` (film resolution, default 256), `fov` (field of view in degrees, default 45.0), `center` (circle center, default `[0,0,0]`), and `radius` (distance, default 1.3) [S2, unofficial]. The transform for each sensor $i$ is constructed by translating to `center`, rotating around the Y-axis by $\theta_i = \frac{360.0}{num\_sensors} \cdot i$, and looking at the target `[0,0,0]` from `[0,0,radius]` with up `[0,1,0]` [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(n\_frames)$ to generate the poses, as each frame requires constant-time trigonometric and vector operations [G].
- **Memory Complexity:** $O(n\_frames \times 16)$ for the output tensor storage [G].
- **Performance:** Generation is instantaneous on modern hardware; rendering time depends on the downstream ray tracer and scene complexity [G].
- **Strengths:** Simple, deterministic, and produces smooth 360° orbits suitable for visualizing 3D reconstructions [G].
- **Limitations:** The fixed Y-offset (`radius * 0.3`) may not be suitable for all scenes (e.g., if the object is tall or flat) [G].
- **When to use:** When a smooth, automated 360-degree fly-around is needed for visualization or dataset creation [G].
- **When not to use:** When interactive control is required (use [Orbit Camera Controls](3262-orbit-camera-controls.md)) or when a single specific view is needed (use [Camera Look-at Computation via Rotation](2696-camera-look-at-computation-via-rotation.md)) [G].
