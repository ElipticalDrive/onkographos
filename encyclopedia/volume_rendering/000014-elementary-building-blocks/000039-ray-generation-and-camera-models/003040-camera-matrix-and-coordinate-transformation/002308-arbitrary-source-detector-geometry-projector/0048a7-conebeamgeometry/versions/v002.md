# ConeBeamGeometry

Also called: C-arm CBCT Geometry & Sampling Setup, CBCT Geometry, Cone Beam CT Acquisition

## Overview
ConeBeamGeometry defines the physical and geometric parameters for a cone-beam CT acquisition, including projection angles and fixed distances [S2, unofficial]. It provides the source-to-detector and source-to-isocenter distances, along with detector dimensions, required to map 3D coordinates to 2D detector pixels in divergent beam systems [S1][S2, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs:** Physical scanner specifications (distances, pixel size), acquisition trajectory (angles), and detector array dimensions [S1][S2, unofficial].
*   **Outputs:** A geometry object containing attributes used to compute projection rays and backprojector weights [S2, unofficial].

### Data Structures
The geometry is represented as a class or struct with the following attributes [S2, unofficial]:

| Attribute | Type | Description | Default Value |
| :--- | :--- | :--- | :--- |
| `DSO` | float | Source-to-Isocenter Distance (SID) | 500 (mm) |
| `DSD` | float | Source-to-Detector Distance (SDD) | 800 (mm) |
| `det_pixels` | int | Number of detector pixels per side (assumed square) | 256 |
| `pixel_size` | float | Physical size of a single detector pixel (mm) | 1.0 |
| `angles` | array | Array of rotation angles (radians) from 0 to $2\pi$ | 180 angles |

### Formulas and Parameters
The geometry defines projection and isosampling magnification factors to relate physical distances to digital sampling grids [S1]:

1.  **Projection Magnification ($\alpha$):** Relates the source-detector distance to the detector bin size.
    $$ \alpha = \frac{\text{DSD}}{\text{pixel\_size}} $$
2.  **Isosampling Magnification ($t_z$):** Relates the source-isocenter distance to the voxel size at the isocenter.
    $$ t_z = \frac{\text{DSO}}{\text{voxel\_size}} $$
    Where $\text{voxel\_size}$ is the physical voxel size at the center of rotation [S1].

**Example Parameters (C-arm System) [S1]:**
*   Focal spot to detector distance (DSD): 1295 mm
*   Detector bin size: 0.2 mm
*   $\alpha = 1295 / 0.2 = 6475$
*   Focal spot to rotation center (DSO): 820 mm
*   Iso-sampling voxel size: 0.127 mm
*   $t_z = 820 / 0.127 = 6456$
*   Field of View (FOV): 65 mm (for a $512 \times 512$ detector)

### Pseudocode
The following Python-like pseudocode initializes the geometry object and computes the necessary magnification factors. It assumes standard vector operations are available.

```python
import numpy as np

class ConeBeamGeometry:
    def __init__(self, DSO=500.0, DSD=800.0, det_pixels=256, pixel_size=1.0, n_angles=180):
        """
        Initialize Cone Beam CT Geometry.
        
        Args:
            DSO: Source-to-Isocenter Distance in mm.
            DSD: Source-to-Detector Distance in mm.
            det_pixels: Number of pixels per side of the square detector.
            pixel_size: Physical size of one detector pixel in mm.
            n_angles: Number of projection angles.
        """
        self.DSO = DSO
        self.DSD = DSD
        self.det_pixels = det_pixels
        self.pixel_size = pixel_size
        self.n_angles = n_angles
        
        # Compute projection magnification factor
        self.alpha = DSD / pixel_size
        
        # Generate angles from 0 to 2*pi
        self.angles = np.linspace(0, 2 * np.pi, n_angles, endpoint=False)

    def get_isosampling_magnification(self, voxel_size):
        """
        Calculate the isosampling magnification factor tz.
        
        Args:
            voxel_size: Physical voxel size at the center of rotation in mm.
            
        Returns:
            tz: Magnification factor relating DSO to voxel size.
        """
        if voxel_size <= 0:
            raise ValueError("Voxel size must be positive.")
        return self.DSO / voxel_size
```

### Edge Cases and Pitfalls
*   **Sampling Condition Violation:** In real-data conditions, the ideal sampling condition (often referred to as Equation 6 in literature [S1]) is not rigorously satisfied. This occurs when the voxel size does not perfectly align with the system's magnification, requiring fallback to interpolation handling during backprojection [S1].
*   **Voxel Size Mismatch:** Using a larger voxel size (e.g., 0.508 mm vs 0.127 mm) to increase FOV degrades resolution. The degradation is induced by the interpolation required to map the large voxels to the detector geometry, not by the physical system itself [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Accurately models divergent beam geometry, essential for CBCT reconstruction [S1][S2, unofficial]. Supports variable FOV by adjusting voxel size relative to magnification factors [S1].
*   **Limitations:** Requires careful interpolation when voxel sizes do not match the ideal sampling condition [S1].
*   **When to use:** When reconstructing data from a CBCT scanner (e.g., C-arm systems) where the source and detector move in a circular or helical trajectory [G].
*   **When not to use:** For parallel-beam CT or when using simplified fan-beam approximations where cone-beam artifacts are negligible [G].

## Background
Cone-beam CT geometry originated with the development of C-arm X-ray systems for interventional radiology and dental imaging [S1]. The specific parameters cited (1295 mm SDD, 820 mm SID) are derived from experimental setups on GE Healthcare C-arm systems [S1]. The geometry is implemented as a class defining geometric parameters for a cone-beam CT scanner setup [S2, unofficial]. The distinction between projection magnification ($\alpha$) and isosampling magnification ($t_z$) highlights the challenge of balancing field of view and resolution in digital radiography [S1].
