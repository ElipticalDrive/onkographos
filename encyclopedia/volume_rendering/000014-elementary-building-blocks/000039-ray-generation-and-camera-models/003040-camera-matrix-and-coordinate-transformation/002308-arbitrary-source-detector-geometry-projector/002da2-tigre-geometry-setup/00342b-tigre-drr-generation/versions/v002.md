# TIGRE DRR Generation

Also called: CT to X-ray Projection, DRR Generation from CT Volumes, Digital Reconstruction Radiography, Digitally Reconstructed Radiography (DRR), Digitally Reconstructed Radiograph Pipeline, TIGRE X-ray Projection

## Overview
TIGRE DRR Generation converts 3D Computed Tomography (CT) volumes into 2D Digitally Reconstructed Radiographs (DRR) by simulating X-ray projection through the volume [S1, unofficial][S2]. This method addresses the scarcity of paired clinical datasets (2D X-ray and 3D CT acquired simultaneously) by synthetically generating 2D projections from existing 3D volumes, enabling the training of neural networks for tasks such as single-X-ray-to-3D-CT reconstruction [S1, unofficial][S2]. It differs from standard volume rendering by explicitly targeting the physics of X-ray attenuation for medical imaging applications and relying on external projection tools for geometric consistency [S1, unofficial][S2].

## How it works
**Inputs:**
- A 3D CT volume stored as a DICOM series or MHA file [S1, unofficial].
- A configuration dictionary specifying projection parameters (e.g., number of views, resolution) [S1, unofficial][S2].
- External tools: SimpleITK (for I/O), plastimatch (for projection, version 1.9.3) [S1, unofficial].

**Outputs:**
- A set of 2D DRR images in `.png` format corresponding to specified angular views [S1, unofficial][S2].

**Data Structures:**
- **CT Volume:** Loaded as a 3D array with associated metadata: `origin` (3D vector), `size` (3D integer vector), and `spacing` (3D vector) [S1, unofficial].
- **Geometry:** Defined by the parent [TIGRE Geometry Setup](5605-tigre-geometry-setup.md), which configures detector, voxel, and offset parameters for cone or parallel beam modes [G].

**Steps:**
1. **Load Volume:** Read the DICOM series using SimpleITK. It is critical to read the series in order using `GetGDCMSeriesFileNames` to preserve anatomical orientation [S1, unofficial]. Extract the image origin, size, and spacing [S1, unofficial].
2. **Compute Center:** Calculate the volume center in world coordinates using the formula:
   $$ \text{center} = \text{origin} + \frac{\text{size} - 1}{2} \times \text{spacing} $$
3. **Configure Geometry:** Use the TIGRE geometry setup to define the projection geometry (source-to-detector distance, detector dimensions, voxel size) consistent with the loaded volume [G].
4. **Project:** Execute the projection using the external command-line tool `plastimatch` (version 1.9.3) [S1, unofficial]. The tool takes the CT volume and the defined geometry as input [G].
5. **Post-process:** Read the header of the generated `.pfm` file to determine color format, width, height, scale, and endianess [S1, unofficial]. Convert the `.pfm` output to `.png` format [S1, unofficial].

**Parameters:**
- **Number of Views:** Typically 50 views covering 360° for training dataset generation [S2].
- **Resolution:** Consistently scaled to 512 × 512 pixels to eliminate bias in model comparisons [S2].
- **Plastimatch Version:** 1.9.3 [S1, unofficial].

**Pitfalls:**
- **Orientation:** DICOM series must be read in strict order; incorrect ordering leads to anatomical misalignment [S1, unofficial].
- **External Dependency:** The method relies on `plastimatch`, requiring it to be installed and accessible in the system path [S1, unofficial].

**Pseudocode:**
```python
import SimpleITK as sitk
import subprocess
import os

def generate_drr(ct_path, output_dir, num_views=50, resolution=(512, 512)):
    # 1. Load CT volume
    file_names = sitk.GetGDCMSeriesFileNames(ct_path)
    if not file_names:
        raise ValueError("No DICOM files found")
    
    img_itk = sitk.ReadImage(file_names)
    origin = list(img_itk.GetOrigin())
    size = list(img_itk.GetSize())
    spacing = list(img_itk.GetSpacing())
    
    # 2. Compute volume center in world coordinates
    center = [origin[i] + (size[i] - 1) * spacing[i] / 2.0 for i in range(3)]
    
    # 3. Configure Geometry (via TIGRE Geometry Setup)
    # Geometry parameters are configured by the parent module [TIGRE Geometry Setup](5605-tigre-geometry-setup.md)
    geometry_params = {
        "voxel_size": spacing,
        "detector_size": resolution,
        "source_to_detector_distance": 1000.0,
        "source_to_origin_distance": 1500.0
    }
    
    # 4. Project using plastimatch
    for i in range(num_views):
        angle = i * (360.0 / num_views)
        pfm_path = os.path.join(output_dir, f"drr_{i:04d}.pfm")
        
        cmd = [
            "plastimatch", "drr",
            "-i", ct_path,
            "-o", pfm_path,
            "--angle", str(angle),
            "--geometry", str(geometry_params)
        ]
        subprocess.run(cmd, check=True)
        
    # 5. Post-process: Convert .pfm to .png
    for i in range(num_views):
        pfm_path = os.path.join(output_dir, f"drr_{i:04d}.pfm")
        png_path = os.path.join(output_dir, f"drr_{i:04d}.png")
        
        if os.path.exists(pfm_path):
            # Read .pfm header to determine color, width, height, scale, endian and convert to .png [G]
            os.remove(pfm_path)
```

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of views and the volume size, as each view requires a full projection through the 3D volume [S2].
- **Memory Complexity:** Proportional to the size of the CT volume and the number of generated DRR images [S1, unofficial][S2].
- **Performance:** Generating 50 views per volume is computationally feasible for training dataset creation [S2].
- **Strengths:** Provides a scalable way to generate large paired datasets for supervised learning [S2]. Ensures geometric consistency via TIGRE [S2].
- **Limitations:** Relies on external tools (`plastimatch`) which may introduce variability or compatibility issues [S1, unofficial].
- **When to use:** When paired clinical X-ray/CT data is unavailable and synthetic projections are needed for neural network training [S2].
- **When not to use:** When high-fidelity physical X-ray effects (scatter, beam hardening) are required without external configuration [S1, unofficial].

## Background
The technique was introduced to overcome the impracticality of collecting paired clinical data (2D X-ray and 3D CT) in medical settings [S2]. It leverages the TIGRE tomography toolbox for generating X-ray images [S2] and SimpleITK for loading medical image volumes [S1, unofficial]. The method is commonly used in research involving Neural Radiance Fields (NeRF) and other deep learning models for medical image reconstruction [S1, unofficial][S2].
