# Arbitrary Source-Detector Geometry Projector

Also called: Arbitrary Source-Detector Geometry, Axial cone-beam, Cone-Beam Geometry Projector, Flexible cone-beam, Parallel-Beam Geometry Projector

## Overview
The Arbitrary Source-Detector Geometry Projector is a CT forward/backward projection method that supports flexible specification of the imaging geometry, including arbitrary 3D detector shifts, non-equispaced projection angles, and arbitrary source/detector placement and orientation [S1, unofficial]. It solves the problem of modeling X-ray line integrals through a voxelized volume for complex scanner configurations that deviate from standard fixed-camera assumptions [S1, unofficial]. It sets itself apart from siblings like [Parallel-Beam Geometry Projector](52-parallel-beam-projector.md) or [Cone-Beam Geometry Projector](53-cone-beam-projector.md) by allowing the user to explicitly define the 3D location and orientation of every individual source-detector pair, supporting complex trajectories (circular, spiral, saddle) and parameterized detector surfaces [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D volume $V$ (voxel values in $\text{mm}^{-1}$), a list of projection angles $\Theta$, and a geometry specification defining source positions $\mathbf{s}_i$ and detector planes for each angle $i$.
- Output: A set of 2D projection images (sinograms) $P_i$ for each angle $i$.

**Data Structures:**
- `volume`: 3D array of shape $(H, W, D)$, representing the attenuation coefficient map.
- `geometry`: Dictionary or object containing:
  - `DSO`: Source-to-Isocenter Distance (default 500 mm) [S3, unofficial].
  - `DSD`: Source-to-Detector Distance (default 800 mm) [S3, unofficial].
  - `det_pixels`: Number of pixels per side of the square detector (default 256) [S3, unofficial].
  - `pixel_size`: Physical size of a single detector pixel (default 1.0 mm) [S3, unofficial].
  - `angles`: Array of rotation angles from $0$ to $2\pi$ (default 180 angles) [S3, unofficial].
  - `source_positions`: Array of 3D coordinates for each source position.
  - `detector_orientations`: Array of rotation matrices or quaternions defining detector plane orientation for each angle.

**Steps:**
1. **Compute Detector Pixel Positions in World Coordinates:**
   a. Calculate $y\_coords$ and $x\_coords$ using `linspace` based on `detector_size` and `pixel_size`. The range is typically $[-\frac{N}{2} \cdot \text{pixel\_size}, \frac{N}{2} \cdot \text{pixel\_size}]$.
   b. Create a meshgrid with 'ij' indexing to form 2D arrays $X$ and $Y$ of shape $(H_{det}, W_{det})$.
   c. Set the $z$ coordinate to `center_offset_z` (equal to `DSD` or `DSO` depending on origin definition, typically `DSD` from source).
   d. Stack into a 3D array `detector_grid` of shape $(H_{det}, W_{det}, 3)$ with order $[Z, Y, X]$.
   e. Apply the rotation and translation defined by the source-detector pair's orientation to transform these local detector coordinates to world coordinates.

2. **Compute Ray Directions:**
   For each pixel $p$ in the detector array at world position $\mathbf{d}_p$:
   a. Get the source position $\mathbf{s}$ for the current projection angle.
   b. Compute the ray direction vector: $\mathbf{r} = \mathbf{d}_p - \mathbf{s}$.
   c. Normalize the ray direction: $\mathbf{d} = \frac{\mathbf{r}}{\|\mathbf{r}\|}$.

3. **Forward Projection (Ray Marching):**
   For each ray $(\mathbf{o}, \mathbf{d})$:
   a. Determine the entry and exit points of the ray with the volume bounding box.
   b. Sample the volume along the ray using a method such as Siddon’s method or Distance Driven (DD) [S1, unofficial].
   c. Integrate the attenuation coefficients along the ray path to compute the projection value: $P = \int_{\text{entry}}^{\text{exit}} \mu(\mathbf{o} + t\mathbf{d}) \, dt$.
   d. Store $P$ in the corresponding pixel of the projection image.

4. **Backward Projection:**
   For each pixel in the projection image with value $P$:
   a. Trace the ray back through the volume.
   b. Distribute the value $P$ to the voxels intersected by the ray, weighted by the intersection length or a smoothing kernel (e.g., Joseph method) [S1, unofficial].

**Parameters:**
- `DSO`: Source-to-Isocenter Distance. Default: 500 [S3, unofficial].
- `DSD`: Source-to-Detector Distance. Default: 800 [S3, unofficial].
- `det_pixels`: Detector pixel count per side. Default: 256 [S3, unofficial].
- `pixel_size`: Physical size of a detector pixel. Default: 1.0 [S3, unofficial].
- `angles`: Array of rotation angles. Default: 180 angles from $0$ to $2\pi$ [S3, unofficial].

**Edge Cases and Pitfalls:**
- Precision: Floating-point errors in ray-volume intersection calculations can lead to artifacts. Use robust intersection algorithms [S1, unofficial].
- Boundaries: Rays missing the volume should be handled gracefully (e.g., set projection value to 0).
- Degenerate Input: Ensure source and detector positions are not coincident, which would result in undefined ray directions.

    """
    Perform forward projection for arbitrary source-detector geometry.
    
    Args:
        volume: 3D numpy array of shape (H, W, D)
        geometry: Dictionary containing geometry parameters
        
    Returns:
        projections: List of 2D numpy arrays, one for each angle
    """
    DSO = geometry.get('DSO', 500)
    DSD = geometry.get('DSD', 800)
    det_pixels = geometry.get('det_pixels', 256)
    pixel_size = geometry.get('pixel_size', 1.0)
    angles = geometry.get('angles', np.linspace(0, 2 * np.pi, 180))
    
    # Precompute detector grid in local coordinates
    half_det = det_pixels * pixel_size / 2
    x_coords = np.linspace(-half_det, half_det, det_pixels)
    y_coords = np.linspace(-half_det, half_det, det_pixels)
    X, Y = np.meshgrid(x_coords, y_coords, indexing='ij')
    Z = np.full_like(X, DSD)
    detector_local = np.stack([Z, Y, X], axis=-1) # Shape (H, W, 3)
    
    projections = []
    
    for angle in angles:
        # Compute source position (assuming circular trajectory around z-axis)
        # Source is at distance DSO from isocenter (0,0,0)
        source_x = DSO * np.cos(angle)
        source_y = DSO * np.sin(angle)
        source_z = 0
        source_pos = np.array([source_x, source_y, source_z])
        
        # Compute detector orientation (assuming detector faces the source)
        # Normal vector from source to isocenter
        normal = -source_pos / np.linalg.norm(source_pos)
        
        # Transform detector grid to world coordinates
        # For simplicity, assume detector plane is perpendicular to the normal
        # and centered at (DSD * normal) from the source
        detector_center = source_pos + DSD * normal
        detector_world = detector_local + detector_center

        ray_dirs = ray_dirs / np.linalg.norm(ray_dirs, axis=-1, keepdims=True)

## Subtopics

### [t-beam projectors](3067-t-beam-projectors.md)
t-beam projectors integrate the source-to-pixel segment along a ray for volume rendering or projection in arbitrary source-detector geometries. They differ from standard fixed-camera models by allowing explicit definition of every source-detector pair, supporting complex trajectories (circular, spiral, saddle) and parameterized detector surfaces while maintaining exact cell-constant integration.

### [TIGRE Geometry Setup](5605-tigre-geometry-setup.md)
Configures a TIGRE geometry object from a configuration dictionary, setting detector, voxel, and offset parameters for cone or parallel beam modes. It serves as the foundational step for defining the arbitrary source-detector geometry required by the parent projector, ensuring that ray origins and detector coordinates are mathematically consistent with the chosen scanner mode.

### [Projection Geometry to Vector Conversion](13361-projection-geometry-to-vector-conversion.md)
This method converts a dictionary-based projection geometry specification into a flat 12-element vector array for each projection angle, supporting both cone and parallel3D beam geometries. It serves as the bridge between high-level geometric parameters and the low-level vector representations required by downstream differentiable ray-casting kernels, distinguishing itself from higher-level setup utilities by producing the exact numerical arrays expected by the projection engine.

### DRR Geometry and Coordinate Transformation
DRR (Digitally Reconstructed Radiograph) geometry involves transforming 3D volume data into 2D X-ray images by simulating the X-ray projection process [S2, unofficial]. It requires precise coordinate transformations between the volume space, the source space, and the detector space to accurately model the attenuation of X-rays through the volume [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N_{rays} \cdot N_{samples})$, where $N_{rays}$ is the number of detector pixels and $N_{samples}$ is the number of samples per ray.
- **Memory Complexity:** $O(V)$ for the volume and $O(P)$ for the projections, where $V$ is the volume size and $P$ is the projection size.
- **Measured Performance:** Performance depends on the hardware and resolution. GPU implementations using CUDA can achieve real-time or near-real-time performance for moderate resolutions [S1, unofficial].
- **Scaling:** Scales well with the number of rays due to parallel execution [S1, unofficial].
- **Strengths:** Flexibility in geometry definition, support for complex trajectories, and compatibility with various projection algorithms (Siddon, SF, DD) [S1, unofficial].
- **Limitations:** Computational cost for high-resolution volumes and complex geometries, potential for artifacts if intersection algorithms are not robust [S1, unofficial].
- **When to Use:** When the scanner geometry is non-standard, or when simulating complex trajectories is required [S1, unofficial].
- **When Not to Use:** For standard parallel or cone-beam geometries where simpler, optimized projectors are available [S1, unofficial].

## Background
The Arbitrary Source-Detector Geometry Projector is part of a software package that implements three different 3D XCT geometry types: parallel-beam, axial cone-beam, and flexible cone-beam [S1, unofficial]. The flexible cone-beam geometry allows users to place X-ray sources and detectors at any position and orientation in space, covering most XCT applications [S1, unofficial]. The implementation uses both CPU (C/C++) and GPU (CUDA) for forward and back projection, utilizing algorithms like Siddon’s method and the Distance Driven (DD) method [S1, unofficial]. The concept of DRR (Digitally Reconstructed Radiograph) is closely related, as it involves generating 2D X-ray images from 3D volume data, which is a key application of this projector [S2, unofficial].
