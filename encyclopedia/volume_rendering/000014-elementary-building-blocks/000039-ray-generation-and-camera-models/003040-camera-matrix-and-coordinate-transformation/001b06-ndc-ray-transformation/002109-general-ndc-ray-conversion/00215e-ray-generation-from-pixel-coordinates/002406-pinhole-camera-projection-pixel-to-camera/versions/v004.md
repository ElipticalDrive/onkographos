# Pinhole Camera Projection (Pixel to Camera)

Also called: Camera Projection and Backprojection, Camera Ray Lifting, Depth Map to Camera Coordinates, Inverse Projection, Pixel to Camera, Ray Generation from Pixel Coordinates using Intrinsics

## Overview
This method converts 2D pixel coordinates $(u, v)$ and a depth value $z$ into 3D homogeneous coordinates in the camera coordinate frame using the camera intrinsic matrix [S1, S4, unofficial]. It solves the problem of "lifting" a depth map into 3D space, which is a prerequisite for ray generation in volume rendering and point cloud reconstruction [S3, unofficial]. It is the inverse of the camera projection operator $\pi$ [S2]. Unlike variants that assume zero skew or specific pixel centering conventions, this method provides the general algebraic backprojection formula, though implementations often simplify based on sensor assumptions [S3, S5, unofficial].

## How it works
**Inputs:**
- `intrinsics`: A $3 \times 3$ matrix $K$ containing focal lengths and principal point offsets [S1, S4, unofficial].
- `pixel_coords`: 2D coordinates $(u, v)$ or $(x, y)$ representing pixel locations [S4, unofficial].
- `depth`: Depth value $z$ (distance from the camera center along the optical axis) [S4, unofficial].

**Outputs:**
- `camera_coords`: A tensor of shape $(..., 4)$ containing homogeneous 3D coordinates $[X_c, Y_c, Z_c, 1]^T$ in the camera frame [S1, S4, unofficial].

**Data Structures:**
- The intrinsic matrix $K$ is typically stored as:
  $$
  K = \begin{bmatrix}
  f_x & s & c_x \\
  0 & f_y & c_y \\
  0 & 0 & 1
  \end{bmatrix}
  $$
  where $f_x, f_y$ are focal lengths in pixels, $(c_x, c_y)$ is the principal point, and $s$ is the skew coefficient [S1, S4, unofficial].

**Steps:**
1. Extract intrinsic parameters from the matrix $K$:
   - $f_x = K[0, 0]$
   - $f_y = K[1, 1]$
   - $c_x = K[0, 2]$
   - $c_y = K[1, 2]$
   - $s = K[0, 1]$ (skew) [S1, S4, unofficial].
2. Compute the unnormalized camera space coordinates $X_{lift}$ and $Y_{lift}$ using the backprojection formula [S1, S4, unofficial]:
   $$
   X_{lift} = \frac{u - c_x + \frac{c_y \cdot s}{f_y} - \frac{s \cdot v}{f_y}}{f_x} \cdot z
   $$
   $$
   Y_{lift} = \frac{v - c_y}{f_y} \cdot z
   $$
   Note: Some sources define the input pixel coordinates as $(x, y)$ instead of $(u, v)$ [S4, unofficial]. The formula for $X_{lift}$ accounts for non-zero skew $s$ [S1, S4, unofficial]. If skew is assumed to be zero (common in modern sensors), the term involving $s$ vanishes [S3, unofficial].
3. Set $Z_{lift} = z$ [S4, unofficial].
4. Construct the homogeneous coordinate vector by stacking $[X_{lift}, Y_{lift}, Z_{lift}, 1]$ along the last dimension [S1, S4, unofficial].
5. (Optional) Generate a validity mask where depth $z > 0$ to filter out invalid points [S3, unofficial].

**Pseudocode:**
```python
def pixel_to_camera(intrinsics: Tensor, u: Tensor, v: Tensor, z: Tensor) -> Tensor:
    """
    Lifts pixel coordinates and depth to camera space homogeneous coordinates.
    
    Args:
        intrinsics: Tensor of shape (..., 3, 3) containing the camera intrinsic matrix K.
        u: Tensor of shape (...,) containing x-pixel coordinates.
        v: Tensor of shape (...,) containing y-pixel coordinates.
        z: Tensor of shape (...,) containing depth values.
        
    Returns:
        Tensor of shape (..., 4) containing homogeneous camera coordinates [X, Y, Z, 1].
    """
    # Extract intrinsics
    fx = intrinsics[..., 0, 0]
    fy = intrinsics[..., 1, 1]
    cx = intrinsics[..., 0, 2]
    cy = intrinsics[..., 1, 2]
    skew = intrinsics[..., 0, 1]
    
    # Compute X coordinate in camera space
    # Formula: x = ((u - cx + cy * skew / fy - skew * v / fy) / fx) * z
    x_lift = ((u - cx + cy * skew / fy - skew * v / fy) / fx) * z
    
    # Compute Y coordinate in camera space
    # Formula: y = ((v - cy) / fy) * z
    y_lift = ((v - cy) / fy) * z
    
    # Z is simply the depth
    z_lift = z
    
    # Stack into homogeneous coordinates [x, y, z, 1]
    ones = torch.ones_like(z_lift)
    camera_coords = torch.stack([x_lift, y_lift, z_lift, ones], dim=-1)
    
    return camera_coords
```

**Parameters:**
- `intrinsics`: $3 \times 3$ matrix. Typical values depend on resolution and lens, e.g., $f_x \approx 500-1000$ for standard lenses [S1, S4, unofficial].
- `depth`: Positive float. Must be $>0$ for valid backprojection [S3, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Depth:** Division by zero or invalid geometry if $z=0$. A validity mask ($z>0$) should be applied [S3, unofficial].
- **Skew:** If the source assumes zero skew but the matrix contains non-zero skew, the $X_{lift}$ calculation will be incorrect if the skew term is omitted [S1, S3, unofficial].
- **Pixel Centering:** The formula assumes pixel coordinates refer to the top-left corner or center depending on convention. The "Continuous-to-Discrete" variant explicitly assumes pixel centers are at integer + 0.5 [S5, unofficial]. If using integer pixel indices directly, ensure consistency with the intrinsic definition [S5, unofficial].
- **Coordinate System:** The output is in the camera frame. To get world coordinates, it must be multiplied by the extrinsic matrix $[R|t]$ [S2].

## Subtopics

### Continuous-to-Discrete Pixel Coordinate Conversion
A method to convert continuous image coordinates $(\mu'_x, \mu'_y)$ to discrete pixel coordinates $(p_i, p_j)$ [S5, unofficial]. It assumes the pixel center is at the center of a unit area box, leading to the relation $p_i + 0.5 = f_x \cdot t_x / t_z + c_x$ and $p_j + 0.5 = f_y \cdot t_y / t_z + c_y$ [S5, unofficial]. This is the forward projection step often used to map 3D points to 2D pixels, whereas the main method performs the inverse [S5, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of pixels/points, as it involves only element-wise arithmetic operations [S1, S4, unofficial].
- **Memory Complexity:** $O(N)$ to store the output homogeneous coordinates [S4, unofficial].
- **Strengths:** Simple, differentiable, and efficient. It directly maps depth maps to 3D points without iterative solvers [S3, unofficial].
- **Limitations:** Requires accurate depth and intrinsics. Errors in intrinsics (especially principal point or focal length) propagate linearly to 3D errors [S2]. Does not handle occlusions or missing depth values inherently (requires masking) [S3, unofficial].
- **When to use:** When generating rays for volume rendering from a known depth map and camera pose [S3, S4, unofficial].
- **When not to use:** When depth is unknown or unreliable, or when working in world coordinates without extrinsics [S2].

## Background
The pinhole camera model is a fundamental concept in computer vision and graphics [S2]. The projection operator $\pi(x_c) \approx K x_c$ and its inverse $\pi^{-1}(p, z) = z K^{-1} \bar{p}$ are standard formulations [S2]. The method is widely used in NeRF-based approaches, Structure-from-Motion (SfM), and Gaussian Splatting pipelines to initialize 3D points from 2D observations [S2][S5, unofficial]. The specific handling of skew and pixel centering conventions varies between libraries, with some assuming zero skew for simplicity [S3, S5, unofficial].
