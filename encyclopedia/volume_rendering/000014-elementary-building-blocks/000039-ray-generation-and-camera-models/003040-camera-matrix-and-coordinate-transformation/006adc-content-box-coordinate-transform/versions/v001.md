# Content Box Coordinate Transform

Also called: applyContentBoxTransform

## Overview
The Content Box Coordinate Transform maps a 3D bounding box defined in a source coordinate system into the canonical Z-up tile coordinate system used by 3D Tiles. It solves the problem of spatial consistency in hierarchical tilesets by ensuring that oriented bounding boxes (OBBs) are correctly aligned with the tile's local frame before serialization. It differs from [NDC Ray Transformation](905-ndc-ray-transformation.md) by operating on static geometric bounds rather than ray parameters, and from [View Matrix Construction](1644-view-matrix-construction.md) by targeting the specific 3D Tiles tile-space convention rather than a general camera view.

## How it works
**Inputs and Outputs:**
*   **Input:** `box`, an array of 12 floating-point numbers representing an OBB in the source coordinate system. The layout is four 3D basis vectors: $[\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2, \mathbf{v}_3]$, where $\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$ define the orientation (columns of the rotation matrix) and $\mathbf{v}_3$ defines the translation (center).
*   **Input:** `sourceCoordinateSystem`, an object providing the transformation matrix `sourceToTileZUp`.
*   **Output:** The transformed box array in the tile's Z-up coordinate system.

**Data Structures:**
The box is stored as a flat array of 12 floats.
*   Indices 0, 1, 2: $x, y, z$ of the first basis vector.
*   Indices 3, 4, 5: $x, y, z$ of the second basis vector.
*   Indices 6, 7, 8: $x, y, z$ of the third basis vector.
*   Indices 9, 10, 11: $x, y, z$ of the translation vector.

**Steps:**
1.  **Validation:** Verify `box` is an array of length 12. If not, return the input unchanged or raise an error [S1, unofficial].
2.  **Retrieve Transform:** Obtain the source-to-tile Z-up transformation matrix $M_{s2t}$ from `sourceCoordinateSystemInfo(sourceCoordinateSystem).sourceToTileZUp` [S1, unofficial]. This is a $4 \times 4$ affine matrix.
3.  **Transform Basis Vectors:** Extract the 3x3 rotation submatrix $R$ from $M_{s2t}$. Apply $R$ to the first three basis vectors ($\mathbf{v}_0, \mathbf{v}_1, \mathbf{v}_2$) located at indices 0, 3, and 6 of the box array.
    *   For each basis vector $\mathbf{v}_i$ (where $i \in \{0, 1, 2\}$), compute:
        $$ \mathbf{v}'_i = R \cdot \mathbf{v}_i $$
    *   Update the box array with $\mathbf{v}'_i$ at the corresponding indices.
4.  **Transform Translation:** The translation vector $\mathbf{v}_3$ (indices 9, 10, 11) is a point. It must be transformed using the full $4 \times 4$ matrix $M_{s2t}$ with homogeneous coordinate $w=1$.
    *   Let $\mathbf{p} = [x, y, z, 1]^T$ be the translation vector padded with 1.
    *   Compute $\mathbf{p}' = M_{s2t} \cdot \mathbf{p}$.
    *   Update the box array with $[p'_x, p'_y, p'_z]$ at indices 9, 10, 11.

**Pseudocode:**
```python
def apply_content_box_transform(box, source_coordinate_system):
    # box is a list/array of 12 floats
    if len(box) != 12:
        return box  # Validation [S1, unofficial]

    # Retrieve the 4x4 transformation matrix
    # sourceToTileZUp is assumed to be a 4x4 matrix represented as a flat list or 2D array
    m = source_coordinate_system.source_to_tile_z_up

    # Extract 3x3 rotation matrix R from the first 3 rows and columns of m
    # m layout: [m00, m01, m02, m03, m10, m11, m12, m13, m20, m21, m22, m23, m30, m31, m32, m33]
    r = [
        [m[0], m[1], m[2]],
        [m[4], m[5], m[6]],
        [m[8], m[9], m[10]]
    ]

    # Transform the three orientation basis vectors (indices 0, 3, 6)
    # These are treated as vectors (w=0), so only rotation applies
    for i in range(3):
        idx = i * 3
        v = [box[idx], box[idx+1], box[idx+2]]
        # Matrix-vector multiplication: v' = R * v
        v_prime = [
            r[0][0]*v[0] + r[0][1]*v[1] + r[0][2]*v[2],
            r[1][0]*v[0] + r[1][1]*v[1] + r[1][2]*v[2],
            r[2][0]*v[0] + r[2][1]*v[1] + r[2][2]*v[2]
        ]
        box[idx] = v_prime[0]
        box[idx+1] = v_prime[1]
        box[idx+2] = v_prime[2]

    # Transform the translation vector (indices 9, 10, 11)
    # This is a point, so use the full 4x4 matrix with w=1
    p = [box[9], box[10], box[11], 1.0]
    
    # Matrix-vector multiplication: p' = M * p
    p_prime = [
        m[0]*p[0] + m[1]*p[1] + m[2]*p[2] + m[3]*p[3],
        m[4]*p[0] + m[5]*p[1] + m[6]*p[2] + m[7]*p[3],
        m[8]*p[0] + m[9]*p[1] + m[10]*p[2] + m[11]*p[3],
        m[12]*p[0] + m[13]*p[1] + m[14]*p[2] + m[15]*p[3]
    ]
    
    box[9] = p_prime[0]
    box[10] = p_prime[1]
    box[11] = p_prime[2]

    return box
```

## Subtopics

### 3D Tiles JSON Serialization
This variant integrates the transform into the recursive serialization of a 3D Tiles node hierarchy. It selects the bounding box using `node.orientedBox || node.bounds.toBoxArray()` and applies `applyContentBoxTransform` to it. If the node has children, the process is mapped recursively to each child [S1, unofficial]. This ensures that the entire tile tree maintains consistent spatial alignment with the tile's local Z-up frame.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per box, as it involves a fixed number of matrix-vector multiplications (12 floats transformed).
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Strengths:** Ensures strict compliance with 3D Tiles spatial indexing requirements.
*   **Limitations:** Dependent on the correctness of the `sourceToTileZUp` matrix. If the source coordinate system is ill-defined, the transform produces invalid geometry.
*   **When to use:** When converting 3D Gaussian Splatting or other point cloud data into 3D Tiles format where oriented bounding boxes must be aligned to the tile's local frame.

## Background
The method originates from the implementation of 3D Gaussian Splatting to 3D Tiles converters, specifically the `lzy-0618/3DGS-PLY-3DTiles-Converter` repository [S1, unofficial]. It addresses the need to align arbitrary source coordinate systems (e.g., from LiDAR or photogrammetry) with the canonical Z-up coordinate system required by the 3D Tiles specification for efficient spatial indexing and rendering.
