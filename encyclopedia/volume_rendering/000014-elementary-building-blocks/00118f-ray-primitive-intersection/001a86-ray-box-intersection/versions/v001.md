# Ray-box intersection
Also called: Axis-aligned bounding box intersection, Kay and Kajiya slab test, Kay and Kay's Ray-Box Intersection Method, Ray-AABB intersection, Ray-Box intersection using slabs, Slab method, Slabs Test, slabsBoxTest

## Overview
The ray-box intersection method determines whether a ray intersects an axis-aligned bounding box (AABB) by treating the box as the intersection of three pairs of parallel planes, known as slabs [S1, S3]. It computes the entry ($t_{near}$) and exit ($t_{far}$) distances for each slab pair and checks for overlap across all three axes [S1, S3]. Unlike general primitive intersection methods, this approach exploits the axis-aligned nature of the box to reduce the problem to simple scalar comparisons and vector operations, making it the dominant technique for bounding volume hierarchy traversal in ray tracing [S2, S3].

## How it works
### Inputs and Outputs
**Inputs:**
*   **Ray:** Defined by origin $\mathbf{o} = (o_x, o_y, o_z)$ and direction $\mathbf{v} = (v_x, v_y, v_z)$. The ray is parameterized as $\mathbf{p}(t) = \mathbf{o} + t\mathbf{v}$ for $t \ge 0$ [S1, S3].
*   **AABB:** Defined by minimum corner $\mathbf{p}_0 = (x_0, y_0, z_0)$ and maximum corner $\mathbf{p}_1 = (x_1, y_1, z_1)$, where $x_0 \le x_1$, $y_0 \le y_1$, and $z_0 \le z_1$ [S1, S2, S3].
*   **Ray Interval (Optional):** A valid hit distance interval $[t_{min}, t_{max}]$ [S2, S3].

**Outputs:**
*   Boolean indicating intersection.
*   If intersecting, the entry distance $t_{entry}$ and exit distance $t_{exit}$ [S1].

### Data Structures
No complex data structures are required. The method operates on scalar values or 3D/4D vectors.
*   **Inverse Ray Direction:** $\mathbf{invV} = (1/v_x, 1/v_y, 1/v_z)$ [S2, S3].
*   **Interval Vectors:** Vectors storing the computed intersection parameters for each axis [S2, S3].

### Algorithm Steps
The method can be implemented in two primary styles: the iterative scalar approach (Kay and Kajiya original) and the compact vector approach (widely used in modern kernels).

#### 1. Iterative Scalar Approach
This approach processes each axis (X, Y, Z) sequentially, updating global $t_{near}$ and $t_{far}$ values [S1].

1.  Initialize $t_{near} = -\infty$ and $t_{far} = \infty$ [S1].
2.  For each axis $i \in \{x, y, z\}$:
    a.  Let $o_i$ be the ray origin component, $v_i$ be the ray direction component, $min_i$ be the box minimum coordinate, and $max_i$ be the box maximum coordinate [S1, S3].
    b.  Check for parallelism: If $v_i = 0$:
        i.  If $o_i < min_i$ or $o_i > max_i$, the ray is outside the slab. Return `false` (miss) [S1].
        ii. Otherwise, the ray is inside the slab along this axis; continue to the next axis [S1].
    c.  Compute intersection distances with the near and far planes of the slab:
        $$t_1 = \frac{min_i - o_i}{v_i}$$
        $$t_2 = \frac{max_i - o_i}{v_i}$$
    d.  Ensure $t_1$ is the smaller value (entry) and $t_2$ is the larger value (exit). If $t_1 > t_2$, swap $t_1$ and $t_2$ [S1].
    e.  Update the global intersection interval:
        $$t_{near} = \max(t_{near}, t_1)$$
        $$t_{far} = \min(t_{far}, t_2)$$
    f.  Check for miss: If $t_{near} > t_{far}$, the intervals do not overlap. Return `false` [S1].
    g.  Check if the box is behind the ray: If $t_{far} < 0$, the entire box is behind the ray origin. Return `false` [S1].
3.  If the loop completes without returning `false`, the ray intersects the box. Return `true` [S1].

#### 2. Compact Vector Approach
This approach computes all intersections in parallel using vector operations, often branchless [S2, S3].

1.  Compute the inverse ray direction: $\mathbf{invV} = (1/v_x, 1/v_y, 1/v_z)$ [S2, S3].
2.  Compute the t-values for the lower and upper bounds of the box:
    $$\mathbf{t}_{lower} = (\mathbf{p}_0 - \mathbf{o}) \odot \mathbf{invV}$$
    $$\mathbf{t}_{upper} = (\mathbf{p}_1 - \mathbf{o}) \odot \mathbf{invV}$$
    where $\odot$ denotes component-wise multiplication [S2, S3].
3.  Determine the entry and exit t-values for each slab by taking the component-wise minimum and maximum of $\mathbf{t}_{lower}$ and $\mathbf{t}_{upper}$:
    $$\mathbf{t}_{min\_slabs} = \min(\mathbf{t}_{lower}, \mathbf{t}_{upper})$$
    $$\mathbf{t}_{max\_slabs} = \max(\mathbf{t}_{lower}, \mathbf{t}_{upper})$$
4.  Incorporate the ray's valid hit interval $[t_{min}, t_{max}]$ as a fourth dimension (or separate scalar check) [S2, S3].
    $$t_{box\_min} = \max(\mathbf{t}_{min\_slabs}.x, \mathbf{t}_{min\_slabs}.y, \mathbf{t}_{min\_slabs}.z, t_{min})$$
    $$t_{box\_max} = \min(\mathbf{t}_{max\_slabs}.x, \mathbf{t}_{max\_slabs}.y, \mathbf{t}_{max\_slabs}.z, t_{max})$$
5.  The ray intersects the box if $t_{box\_min} \le t_{box\_max}$ [S2, S3].

### Pseudocode (Compact Vector Style)
The following Python-like pseudocode implements the compact vector approach, which is widely cited as the standard modern implementation [S2, S3]. It assumes the existence of vector operations `min`, `max`, and `max_component`/`min_component`.

```python
def slabs_box_test(p0, p1, ray_origin, inv_ray_dir, ray_t_min, ray_t_max):
    """
    Determines if a ray intersects an AABB.
    
    Args:
        p0: vec3, minimum corner of the AABB
        p1: vec3, maximum corner of the AABB
        ray_origin: vec3, origin of the ray
        inv_ray_dir: vec3, (1/vx, 1/vy, 1/vz)
        ray_t_min: real, minimum valid t value for the ray
        ray_t_max: real, maximum valid t value for the ray
        
    Returns:
        bool, True if the ray intersects the box within [ray_t_min, ray_t_max]
    """
    # Compute t-values for intersections with lower and upper bounds
    # Component-wise subtraction and multiplication
    t_lower = (p0 - ray_origin) * inv_ray_dir
    t_upper = (p1 - ray_origin) * inv_ray_dir
    
    # Determine the entry (min) and exit (max) t-values for each slab
    # min and max are component-wise operations
    t_min_slabs = min(t_lower, t_upper)
    t_max_slabs = max(t_lower, t_upper)
    
    # Combine with the ray's valid interval [ray_t_min, ray_t_max]
    # max_component returns the maximum value among all components of the vector
    # min_component returns the minimum value among all components of the vector
    t_box_min = max_component(t_min_slabs, ray_t_min)
    t_box_max = min_component(t_max_slabs, ray_t_max)
    
    # Check for overlap
    return t_box_min <= t_box_max
```

### Parameters and Typical Values
*   **Ray Direction:** Must be normalized in many applications, but the algorithm works with unnormalized directions as long as `inv_ray_dir` is computed correctly [S2, S3].
*   **Box Corners:** $\mathbf{p}_0$ and $\mathbf{p}_1$ must satisfy $p_{0,i} \le p_{1,i}$ for all $i \in \{x,y,z\}$ [S1, S2].
*   **Ray Interval:** $t_{min}$ is typically $0$ or a small epsilon to avoid self-intersection; $t_{max}$ is often the current traversal depth limit [S2, S3].

### Edge Cases and Pitfalls
*   **Zero Direction Components:** The algorithm produces correct results for rays with zero direction components (parallel to axes) provided the hardware is IEEE floating-point compliant [S2, S3]. The division by zero in `inv_ray_dir` results in infinity, which is handled correctly by the min/max logic [S2, S3].
*   **Ray Origin on Box Face:** If the ray origin lies exactly on the box surface and the direction points along the face, the computation may result in `NaN` (Not a Number), causing the test to return `false` [S2, S3]. This behavior can be modified if specific handling is required [S2, S3].
*   **Branchless Optimization:** Removing early exit checks (like `if t_near > t_far`) creates a branchless implementation. While this performs more arithmetic operations, it significantly increases performance on modern hardware by avoiding branch mispredictions [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ constant time. The algorithm performs a fixed number of arithmetic operations (subtractions, multiplications, comparisons) regardless of scene complexity [S2, S3].
*   **Memory Complexity:** $O(1)$ auxiliary space. Only a few scalar or vector variables are needed [S2, S3].
*   **Performance:** The slabs test is the dominant method for AABB intersection due to its simplicity and efficiency [S2, S3]. Branchless implementations are preferred in high-performance ray tracing kernels (e.g., Embree) to maximize throughput on SIMD units and GPUs [S2].
*   **Strengths:** Fast, robust, easy to implement, works well with SIMD/vectorization [S2, S3].
*   **Limitations:** Only applicable to axis-aligned boxes. For oriented bounding boxes (OBBs), a transformation to local space is required, which adds computational cost [S2].

## Background
*   **Origin:** The method was introduced by T. L. Kay and J. T. Kajiya in their 1986 paper "Ray tracing complex scenes" presented at SIGGRAPH [S2, S3].
*   **Development:** The algorithm has become the standard for AABB intersection in ray tracing. It is widely used in modern ray tracing kernels such as Embree and in astronomical simulation tools like raytheia [S2, S3].
*   **Usage:** It is a fundamental building block in volume rendering and ray tracing, used for bounding volume hierarchy (BVH) traversal and primitive intersection tests [S2, S3].
