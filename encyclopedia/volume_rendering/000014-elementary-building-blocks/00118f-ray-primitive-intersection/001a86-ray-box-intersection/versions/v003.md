# Ray-box intersection
Also called: AABB Ray Intersection, Kay and Kajiya slab test, Ray-AABB intersection, Ray-AABB intersection using slabs, Slab Method, Slab Method for Ray-AABB Intersection, Slab intersection, Slabs Test

## Overview
The ray-box intersection method determines whether a ray intersects an axis-aligned bounding box (AABB) by treating the box as the intersection of three pairs of parallel planes, known as slabs [S1, unofficial, S3, unofficial]. It computes the entry ($t_{near}$) and exit ($t_{far}$) distances for each slab pair and checks for overlap across all three axes [S1, unofficial, S3, unofficial]. Unlike general primitive intersection methods, this approach exploits the axis-aligned nature of the box to reduce the problem to simple scalar comparisons and vector operations, making it the dominant technique for bounding volume hierarchy traversal in ray tracing [S2, S3, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   **Ray:** Defined by origin $\mathbf{o} = (o_x, o_y, o_z)$ and direction $\mathbf{v} = (v_x, v_y, v_z)$, parameterized as $\mathbf{p}(t) = \mathbf{o} + t\mathbf{v}$ [S1, unofficial, S3, unofficial].
*   **AABB:** Defined by minimum corner $\mathbf{p}_0 = (x_0, y_0, z_0)$ and maximum corner $\mathbf{p}_1 = (x_1, y_1, z_1)$ [S1, unofficial, S2, S3, unofficial].
*   **Ray Interval (Optional):** A valid hit distance interval $[t_{min}, t_{max}]$ representing the range of $t$-values on the ray that count as a hit [S3, unofficial, S4].

**Outputs:**
*   Boolean indicating intersection.
*   If intersecting, the entry distance $t_{near}$ and exit distance $t_{far}$ [S1, unofficial, S4].

### Data Structures
No complex data structures are required; the method operates on scalar values or 3D/4D vectors [S2, S3, unofficial].
*   **Inverse Ray Direction:** $\mathbf{invV} = (1/v_x, 1/v_y, 1/v_z)$ [S3, unofficial, S4].
*   **Interval Vectors:** Vectors storing the computed $t$-values for the lower and upper bounds of each axis [S3, unofficial, S4].

### Algorithm Steps
The method can be implemented in two primary styles: the iterative scalar approach (Kay and Kajiya original) and the compact vector approach (widely used in modern kernels) [S2, S3, unofficial].

#### 1. Iterative Scalar Approach
This approach processes each axis (X, Y, Z) sequentially, updating global $t_{near}$ and $t_{far}$ values [S1, unofficial].

1.  Initialize $t_{near} = -\infty$ and $t_{far} = \infty$ [S1, unofficial].
2.  For each axis $i \in \{x, y, z\}$:
    a.  Let $o_i$ be the ray origin component, $v_i$ be the ray direction component, $min_i$ be the box minimum coordinate, and $max_i$ be the box maximum coordinate [S1, unofficial, S3, unofficial].
    b.  Check for parallelism: If $v_i = 0$:
        i.  If $o_i < min_i$ or $o_i > max_i$, the ray is outside the slab. Return `false` (miss) [S1, unofficial].
        ii. Otherwise, the ray is inside the slab along this axis; continue to the next axis [S1, unofficial].
    c.  Compute intersection distances with the near and far planes of the slab:
        $$t_1 = \frac{min_i - o_i}{v_i}$$
        $$t_2 = \frac{max_i - o_i}{v_i}$$
    d.  Ensure $t_1$ is the smaller value (entry) and $t_2$ is the larger value (exit). If $t_1 > t_2$, swap $t_1$ and $t_2$ [S1, unofficial].
    e.  Update the global intersection interval:
        $$t_{near} = \max(t_{near}, t_1)$$
        $$t_{far} = \min(t_{far}, t_2)$$
    f.  Check for miss: If $t_{near} > t_{far}$, the intervals do not overlap. Return `false` [S1, unofficial].
    g.  Check if the box is behind the ray: If $t_{far} < 0$, the entire box is behind the ray origin. Return `false` [S1, unofficial].
3.  If the loop completes without returning `false`, the ray intersects the box. Return `true` [S1, unofficial].

#### 2. Compact Vector Approach
This approach computes all intersections in parallel using vector operations, often branchless [S2, S3, unofficial].

1.  Compute the inverse ray direction: $\mathbf{invV} = (1/v_x, 1/v_y, 1/v_z)$ [S3, unofficial, S4].
2.  Compute the $t$-values for the lower and upper bounds of the box:
    $$\mathbf{t}_{lower} = (\mathbf{p}_0 - \mathbf{o}) \odot \mathbf{invV}$$
    $$\mathbf{t}_{upper} = (\mathbf{p}_1 - \mathbf{o}) \odot \mathbf{invV}$$
    where $\odot$ denotes component-wise multiplication [S3, unofficial, S4].
3.  Determine the entry and exit $t$-values for each slab by taking the component-wise minimum and maximum of $\mathbf{t}_{lower}$ and $\mathbf{t}_{upper}$:
    $$\mathbf{t}_{min\_slabs} = \min(\mathbf{t}_{lower}, \mathbf{t}_{upper})$$
    $$\mathbf{t}_{max\_slabs} = \max(\mathbf{t}_{lower}, \mathbf{t}_{upper})$$
4.  Incorporate the ray's valid hit interval $[t_{min}, t_{max}]$ as a fourth dimension (or separate scalar check) [S3, unofficial, S4].
    $$t_{box\_min} = \max(\mathbf{t}_{min\_slabs}.x, \mathbf{t}_{min\_slabs}.y, \mathbf{t}_{min\_slabs}.z, t_{min})$$
    $$t_{box\_max} = \min(\mathbf{t}_{max\_slabs}.x, \mathbf{t}_{max\_slabs}.y, \mathbf{t}_{max\_slabs}.z, t_{max})$$
5.  The ray intersects the box if $t_{box\_min} \le t_{box\_max}$ [S3, unofficial, S4].

### Pseudocode (Compact Vector Style)
The following Python-like pseudocode implements the compact vector approach, which is widely cited as the standard modern implementation [S3, unofficial, S4].

```python
def slabs_box_test(p0, p1, ray_origin, inv_ray_dir, ray_t_min, ray_t_max):
    """
    Determines if a ray intersects an AABB.
    
    Args:
        p0: list of 3 floats, minimum corner of the AABB
        p1: list of 3 floats, maximum corner of the AABB
        ray_origin: list of 3 floats, origin of the ray
        inv_ray_dir: list of 3 floats, (1/vx, 1/vy, 1/vz)
        ray_t_min: float, minimum valid t value for the ray
        ray_t_max: float, maximum valid t value for the ray
        
    Returns:
        bool, True if the ray intersects the box within [ray_t_min, ray_t_max]
    """
    # Compute t-values for intersections with lower and upper bounds
    t_lower = [(p0[i] - ray_origin[i]) * inv_ray_dir[i] for i in range(3)]
    t_upper = [(p1[i] - ray_origin[i]) * inv_ray_dir[i] for i in range(3)]
    
    # Determine the entry (min) and exit (max) t-values for each slab
    t_min_slabs = [min(t_lower[i], t_upper[i]) for i in range(3)]
    t_max_slabs = [max(t_lower[i], t_upper[i]) for i in range(3)]
    
    # Combine with the ray's valid interval [ray_t_min, ray_t_max]
    t_box_min = max(t_min_slabs[0], t_min_slabs[1], t_min_slabs[2], ray_t_min)
    t_box_max = min(t_max_slabs[0], t_max_slabs[1], t_max_slabs[2], ray_t_max)
    
    # Check for overlap
    return t_box_min <= t_box_max
```

### Parameters and Typical Values
*   **Ray Direction:** Must be normalized in many applications, but the algorithm works with unnormalized directions as long as `inv_ray_dir` is computed correctly [S3, unofficial, S4].
*   **Box Corners:** $\mathbf{p}_0$ and $\mathbf{p}_1$ must satisfy $p_{0,i} \le p_{1,i}$ for all $i \in \{x,y,z\}$ [S1, unofficial, S2].
*   **Ray Interval:** The interval $[t_{min}, t_{max}]$ represents the valid hit distances on the ray [S3, unofficial, S4]. Typical values are not given in the sources [G].

### Edge Cases and Pitfalls
*   **Zero Direction Components:** The algorithm produces correct results for rays with zero direction components (parallel to axes) provided the hardware is IEEE floating-point compliant [S3, unofficial, S4]. The division by zero in `inv_ray_dir` results in infinity, which is handled correctly by the min/max logic [S3, unofficial, S4].
*   **Ray Origin on Box Face:** If the ray origin lies exactly on the box surface and the direction points along the face, the computation may result in `NaN` (Not a Number), causing the test to return `false` [S3, unofficial, S4]. This behavior can be modified if specific handling is required [S3, unofficial, S4].
*   **Branchless Optimization:** Removing early exit checks (like `if t_near > t_far`) creates a branchless implementation. While this performs more arithmetic operations, it significantly increases performance on modern hardware by avoiding branch mispredictions [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** The algorithm performs a fixed number of arithmetic operations and comparisons regardless of scene complexity [S3, unofficial, S4].
*   **Memory Complexity:** Only a few scalar or vector variables are needed [S3, unofficial, S4].
*   **Performance:** The slabs test is the dominant method for AABB intersection due to its simplicity and efficiency [S3, unofficial, S4]. Branchless implementations are preferred in high-performance ray tracing kernels (e.g., Embree) to maximize throughput on SIMD units and GPUs [S3, unofficial].
*   **Strengths:** Fast, robust, easy to implement, works well with SIMD/vectorization [S3, unofficial, S4].
*   **Limitations:** Only applicable to axis-aligned boxes [S3, unofficial, S4].

## Background
*   **Origin:** The method was introduced by T. L. Kay and J. T. Kajiya in their 1986 paper "Ray tracing complex scenes" presented at SIGGRAPH [S2, S3, unofficial].
*   **Development:** The algorithm has become the standard for AABB intersection in ray tracing. It is widely used in modern ray tracing kernels such as Embree and in astronomical simulation tools like raytheia [S3, unofficial, S4].
*   **Usage:** It is used for primary ray-scene intersection testing, shadow ray occlusion testing, frustum culling, and spatial traversal of octree and grid acceleration structures [S5].
