# Ray-Sphere Intersection

Also called: Analytical ray-sphere intersection, Quadratic Ray-Sphere Intersection, Sphere Hit Test, Sphere Ray Intersection, Sphere-Ray Intersection Check

## Overview
Computes the intersection of a ray with a sphere defined by center and radius, returning the entry/exit distances, hit position, and surface normal [S1, S3, S5, S6, unofficial]. It solves the quadratic equation derived from substituting the ray parametric form into the sphere implicit equation, filtering roots against the ray segment bounds [S2, S5, unofficial]. Unlike [Ray-box intersection](776-ray-box-intersection.md) which uses slab tests, or [Ray-triangle intersection](909-general-ray-triangle-intersection-pl-cker-coordinates.md) which uses barycentric coordinates, this method relies on algebraic root finding [S1, S6, unofficial]. It is the fundamental primitive for [Sphere Intersection](1620-sphere-intersection.md) and serves as the entry/exit bound calculator for volume marching [S5, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (normalized), sphere center $\mathbf{c}$, sphere radius $r$, and optional ray segment bounds $[t_{min}, t_{max}]$ [S1, S5, S6, unofficial].
**Outputs:** Boolean hit status, intersection distance $t$, hit point $\mathbf{p}$, and surface normal $\mathbf{n}$ [S6, unofficial]. If entry/exit bounds are required, outputs $t_{entry}$ and $t_{exit}$ [S5, unofficial].

**Data Structures:**
*   `Ray`: `origin` (vec3), `direction` (vec3).
*   `Sphere`: `center` (vec3), `radius` (float) [S5, S6, unofficial].
*   `HitRecord`: `hit` (bool), `t` (float), `point` (vec3), `normal` (vec3) [S6, unofficial].

**Steps:**
1.  **Transform to Local Space (Optional):** If the sphere has a transformation matrix $M$, transform the ray origin and direction to the sphere's local space: $\mathbf{o}_{loc} = M^{-1}\mathbf{o}$, $\mathbf{d}_{loc} = M^{-1}\mathbf{d}$ (direction transformation requires no translation) [S1, unofficial]. The sphere center becomes $\mathbf{0}$ in local space. If no transformation is used, $\mathbf{o}_{loc} = \mathbf{o} - \mathbf{c}$ and $\mathbf{d}_{loc} = \mathbf{d}$ [S2, S5, unofficial].
2.  **Compute Quadratic Coefficients:**
    Define vector $\mathbf{oc} = \mathbf{o}_{loc} - \mathbf{c}_{loc}$ (or simply $\mathbf{o}_{loc}$ if centered at origin) [S2, S5, unofficial].
    Calculate coefficients for $A t^2 + B t + C = 0$:
    $$ A = \mathbf{d}_{loc} \cdot \mathbf{d}_{loc} $$
    $$ B = 2 (\mathbf{oc} \cdot \mathbf{d}_{loc}) $$
    $$ C = (\mathbf{oc} \cdot \mathbf{oc}) - r^2 $$
    [S1, S5, unofficial]. Note: Some implementations use half-B ($b = \mathbf{oc} \cdot \mathbf{d}_{loc}$) to simplify the quadratic formula to $t = \frac{-b \pm \sqrt{b^2 - AC}}{A}$ [S2, unofficial].
3.  **Compute Discriminant:**
    $$ \Delta = B^2 - 4AC $$
    [S5, unofficial]. Alternatively, using the half-B formulation: $\Delta = b^2 - AC$ [S2, unofficial].
4.  **Check for Intersection:**
    If $\Delta < 0$, the ray misses the sphere. Return miss [S5, unofficial].
    If $\Delta = 0$, the ray is tangent. Return hit at $t = -B / (2A)$ [S2, unofficial].
    If $\Delta > 0$, there are two roots:
    $$ t_1 = \frac{-B - \sqrt{\Delta}}{2A} $$
    $$ t_2 = \frac{-B + \sqrt{\Delta}}{2A} $$
    [S5, unofficial]. Ensure $t_1 \le t_2$ [S5, unofficial].
5.  **Filter Roots:**
    Select the smallest positive $t$ within $[t_{min}, t_{max}]$ [S2, S6, unofficial].
    *   If $t_2 < t_{min}$ or $t_2 > t_{max}$, check $t_1$.
    *   If $t_1 < t_{min}$ or $t_1 > t_{max}$, return miss [S2, unofficial].
    *   If $t_1 \ge t_{min}$ and $t_1 \le t_{max}$, use $t = t_1$ [S2, unofficial].
    *   If $t_1 < t_{min}$ but $t_2 \in [t_{min}, t_{max}]$, use $t = t_2$ [S2, unofficial].
    *   Note: Some implementations clamp negative $t$ to 0.0, effectively treating the ray origin as inside the sphere if it starts there, but standard ray tracing rejects $t < t_{min}$ (usually $t_{min} > 0$) [S5, S6, unofficial].
6.  **Compute Hit Point and Normal:**
    $$ \mathbf{p} = \mathbf{o} + t \mathbf{d} $$
    [S5, S6, unofficial].
    $$ \mathbf{n} = \text{normalize}(\mathbf{p} - \mathbf{c}) $$
    [S6, unofficial]. If the sphere is opaque and the ray originates inside, the normal should be negated ($\mathbf{n} = -\mathbf{n}$) to point against the ray direction, though this is often handled by the shading stage [S6, G, unofficial].
7.  **Transform Back (Optional):** If local space was used, transform $\mathbf{p}$ and $\mathbf{n}$ back to world space using $M$ [S1, unofficial].

**Pseudocode:**
```python
def ray_sphere_intersect(ray_origin, ray_dir, sphere_center, sphere_radius, t_min=0.0, t_max=float('inf')):
    # Vector from ray origin to sphere center
    oc = ray_origin - sphere_center
    
    # Quadratic coefficients
    a = dot(ray_dir, ray_dir)
    b = 2.0 * dot(oc, ray_dir)
    c = dot(oc, oc) - sphere_radius * sphere_radius
    
    # Discriminant
    discriminant = b * b - 4 * a * c
    
    # No intersection
    if discriminant < 0:
        return None
        
    sqrt_disc = sqrt(discriminant)
    
    # Calculate potential t values
    t1 = (-b - sqrt_disc) / (2.0 * a)
    t2 = (-b + sqrt_disc) / (2.0 * a)
    
    # Select the smallest valid t
    if t1 < t2:
        t = t1
        t_other = t2
    else:
        t = t2
        t_other = t1
        
    # Check bounds
    if t < t_min or t > t_max:
        # Try the other root if the first was out of bounds
        if t_other < t_min or t_other > t_max:
            return None
        t = t_other
        
    # Compute hit point and normal
    hit_point = ray_origin + t * ray_dir
    normal = normalize(hit_point - sphere_center)
    
    # Optional: Handle inside-outside normal orientation
    # if dot(ray_dir, normal) > 0:
    #     normal = -normal
     
    return {
        'hit': True,
        't': t,
        'point': hit_point,
        'normal': normal
    }
```

**Edge Cases and Pitfalls:**
*   **Ray Origin Inside Sphere:** If $\mathbf{o}$ is inside the sphere, $C < 0$, resulting in one negative and one positive root. The positive root is the exit point. If the caller expects an entry point, this must be handled explicitly [S5, S6, unofficial].
*   **Precision Errors:** When the ray is tangent ($\Delta \approx 0$), floating-point errors can cause $\Delta$ to be slightly negative, missing the hit. A small epsilon tolerance may be applied to $\Delta$ [S6, G, unofficial].
*   **Uninitialized Variables:** Incorrect implementation may reference uninitialized $t$ when computing the normal before assigning it [S6, unofficial].
*   **Self-Intersection:** A threshold (e.g., $0.0001$) is often added to $t_{min}$ to prevent the ray from intersecting the same object it just hit (z-fighting) [S6, unofficial].

## Subtopics

### 3-Sphere Intersection (Trilateration)
Finds the intersection points of the surfaces of three spheres, used to generate new sample points on the boundary of a carved volume [S9]. It computes $T(\mathcal{S}_k) = \{\partial \mathcal{S}_a \cap \partial \mathcal{S}_b \cap \partial \mathcal{S}_c, (\mathcal{S}_a, \mathcal{S}_b, \mathcal{S}_c) \in \mathcal{S}_k^3\}$, representing the intersection of boundaries of three distinct spheres [S9]. This is used in sphere carving algorithms to ensure convergence by placing new spheres on existing surface intersections [S9].

## Operating characteristics
*   **Time Complexity:** $O(1)$ constant time. Requires a few dot products, a square root, and basic arithmetic [S5, S8, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space [S5, unofficial].
*   **Performance:** Extremely fast; often the fastest primitive intersection test [S8, unofficial]. The square root is the most expensive operation, but unavoidable for exact analytical solutions [S8, unofficial].
*   **Strengths:** Exact solution, no iterative approximation, robust for convex shapes [S5, S8, unofficial].
*   **Limitations:** Only applies to spheres. Does not handle non-uniform scaling or rotation without transformation overhead [S1, unofficial]. Precision issues near tangency [S6, unofficial].
*   **When to use:** When the scene contains spherical objects or bounding volumes [S5, unofficial]. When exact intersection is required [S8, unofficial].
*   **When not to use:** For complex meshes or non-spherical primitives [S8, unofficial].

## Background
The analytical ray-sphere intersection is a fundamental technique in ray tracing, dating back to the early days of computer graphics [S1, S8, unofficial]. It is derived from the parametric equation of a line and the implicit equation of a sphere [S5, unofficial]. It is widely used in volume rendering to determine entry and exit points for marching algorithms [S5, unofficial], and in general ray tracing for sphere primitives [S6, S8, unofficial]. Variants exist for transformed spheres [S1, unofficial] and for use in signed distance field (SDF) ray marching [S8, unofficial].
