# 3-Sphere Intersection (Trilateration)
Also called: Sphere Trilateration, Trilateration

## Overview
The 3-Sphere Intersection method computes the geometric points where the surfaces of three distinct spheres intersect [S1]. In sphere carving algorithms, this operation generates new sample points on the boundary of a carved volume by finding the intersection of the boundaries of three existing empty spheres [S1]. It differs from standard ray-sphere intersection [Ray-Sphere Intersection] by solving a system of three quadratic equations to find a point defined by three spherical constraints, rather than intersecting a line with a single surface [G].

## How it works
**Inputs and Outputs:**
**Inputs:** Three spheres $S_0, S_1, S_2$, defined by their centers $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ and radii $r_0, r_1, r_2$ [S1].
**Outputs:** A set of intersection points $\mathbf{p}$ [S1]. Typically, there are zero, one, or two solutions [G].

**Data Structures:**
The algorithm operates on 3D vectors. Exact data structure layouts, fields, sizes, and bit packing are Not given in the sources [G]. No persistent data structures are required beyond the input sphere parameters [G].

**Steps:**
1. **Construct Local Frame:** Define an orthonormal basis $(\mathbf{e}_x, \mathbf{e}_y, \mathbf{e}_z)$ aligned with the plane passing through the sphere centers [S1].
   * Compute the normal to the plane: $\mathbf{n} = (\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)$ [S1].
   * Set $\mathbf{e}_z = \frac{\mathbf{n}}{\|\mathbf{n}\|}$ [S1].
   * Set $\mathbf{e}_x = \frac{\mathbf{p}_1 - \mathbf{p}_0}{\|\mathbf{p}_1 - \mathbf{p}_0\|}$ [S1].
   * Set $\mathbf{e}_y$ to complete the right-handed orthonormal basis [S1]. The source text contains a typo ($e_y = e_x \times e_x$); geometrically, this must be $\mathbf{e}_y = \mathbf{e}_z \times \mathbf{e}_x$ to ensure orthogonality [S1, G].
2. **Compute Local Coordinates of Centers:** Project the relative positions of the centers onto the local frame to determine parameters $a, b, c$ [S1].
   * $a = \|\mathbf{p}_1 - \mathbf{p}_0\|$ [S1].
   * $\mathbf{v}_{20} = \mathbf{p}_2 - \mathbf{p}_0$ [S1].
   * $b = \mathbf{v}_{20} \cdot \mathbf{e}_x$ [S1].
   * $c = \mathbf{v}_{20} \cdot \mathbf{e}_y$ [S1].
3. **Solve for Local Coordinates $(x, y, z)$:** The intersection point $\mathbf{p}$ in the local frame is $(x, y, z)$ [S1]. The system of equations is:
   $$x^2 + y^2 + z^2 = r_0^2$$
   $$(x - a)^2 + y^2 + z^2 = r_1^2$$
   $$(x - b)^2 + (y - c)^2 + z^2 = r_2^2$$
   * Solve for $x$: $x = \frac{r_0^2 - r_1^2 + a^2}{2a}$ [S1].
   * Solve for $y$: $y = \frac{r_1^2 - r_2^2 - (x - a)^2 + (x - b)^2 + c^2}{2c}$ [S1].
   * Solve for $z$: $z = \sqrt{r_0^2 - x^2 - y^2}$ [S1]. The term under the radical must be non-negative for an intersection to exist [S1].
4. **Transform to Global Frame:** Return to the original frame: $\mathbf{p} = \mathbf{p}_0 + x \cdot \mathbf{e}_x + y \cdot \mathbf{e}_y \pm z \cdot \mathbf{e}_z$ [S1]. This yields up to two points, symmetric with respect to the plane defined by the three sphere centers [G].

**Pseudocode:**
```python
import math
from typing import List, Tuple

def vec_sub(v1, v2):
    return (v1[0] - v2[0], v1[1] - v2[1], v1[2] - v2[2])

def vec_add(v1, v2):
    return (v1[0] + v2[0], v1[1] + v2[1], v1[2] + v2[2])

def vec_scale(v, s):
    return (v[0] * s, v[1] * s, v[2] * s)

def vec_dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def vec_cross(v1, v2):
    return (
        v1[1]*v2[2] - v1[2]*v2[1],
        v1[2]*v2[0] - v1[0]*v2[2],
        v1[0]*v2[1] - v1[1]*v2[0]
    )

def vec_len(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def sphere_trilateration(p0, r0, p1, r1, p2, r2):
    """
    Computes intersection points of three spheres.
    Returns a list of 3D points (tuples).
    """
    # 1. Local Frame Construction
    v10 = vec_sub(p1, p0)
    v20 = vec_sub(p2, p0)
    
    n = vec_cross(v10, v20)
    n_len = vec_len(n)
    
    if n_len < 1e-9:
        return [] # Degenerate: centers are collinear
    
    e_z = vec_scale(n, 1.0 / n_len)
    
    v10_len = vec_len(v10)
    if v10_len < 1e-9:
        return [] # Degenerate: p0 and p1 are coincident
    
    e_x = vec_scale(v10, 1.0 / v10_len)
    
    # Corrected from source typo: e_y = e_z x e_x
    e_y = vec_cross(e_z, e_x)
    
    # 2. Local Coordinates
    a = v10_len
    b = vec_dot(v20, e_x)
    c = vec_dot(v20, e_y)
    
    # 3. Solve for x, y, z
    x = (r0**2 - r1**2 + a**2) / (2.0 * a)
    
    if abs(c) < 1e-9:
        return [] # Degenerate: c=0 makes y calculation singular
    
    y = (r1**2 - r2**2 - (x - a)**2 + (x - b)**2 + c**2) / (2.0 * c)
    
    rad = r0**2 - x**2 - y**2
    
    if rad < 0:
        return [] # No intersection
    
    z = math.sqrt(rad)
    
    # 4. Transform to Global Frame
    pt1 = vec_add(p0, vec_add(vec_scale(e_x, x), vec_add(vec_scale(e_y, y), vec_scale(e_z, z))))
    pt2 = vec_add(p0, vec_add(vec_scale(e_x, x), vec_add(vec_scale(e_y, y), vec_scale(e_z, -z))))
    
    if rad <= 1e-9:
        return [pt1]
    else:
        return [pt1, pt2]
```

**Parameters:**
*   $a = \|\mathbf{p}_1 - \mathbf{p}_0\|$ [S1].
*   $b = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_x$ [S1].
*   $c = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_y$ [S1].
*   Typical values: Not given in the sources [S1].

**Edge Cases and Pitfalls:**
*   **Collinear Centers:** If $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ are collinear, $\mathbf{n}$ is zero and $\mathbf{e}_z$ is undefined [S1].
*   **Coincident Centers:** If $\mathbf{p}_0 = \mathbf{p}_1$, $a=0$ causes division by zero [S1].
*   **No Intersection:** If $r_0^2 - x^2 - y^2 < 0$, the spheres do not intersect at a common point [S1].
*   **Precision:** Floating-point errors in the calculation of $x$ and $y$ can lead to a slightly negative value under the square root for $z$ when the spheres theoretically intersect at a single point; a small epsilon guard is recommended [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per triplet of spheres [G].
*   **Memory Complexity:** $O(1)$ auxiliary space [G].
*   **Measured Performance:** Not given in the sources [S1].
*   **Scaling:** Not given in the sources [S1].
*   **Strengths:** Deterministic analytical solution; no iterative convergence required; efficient for generating dense point clouds on implicit surfaces [S1, G].
*   **Limitations:** Only works for exactly three spheres. Requires the spheres to actually intersect [S1]. Degenerate configurations (collinear centers) must be handled [S1].
*   **When to Use:** Sphere carving algorithms for generating signed distance fields from point clouds or meshes [S1].
*   **When Not to Use:** When fewer than three spheres are available, when sphere centers are collinear, or when an approximate/iterative solution is preferred over an exact analytical one [G].

## Background
The method is described in the context of "Sphere Carving," a technique for bounding volumes for signed distance fields [S1]. It was introduced by Cédric Zanni in 2024 [S1]. The algorithm relies on the property that sampling the initial volume densely enough creates sphere intersections, which are then used to place new spheres on the surface of the carved volume [S1]. This process ensures convergence of the carved volume to the target shape [S1]. The specific trilateration formulas are detailed in Appendix A.2 of the source paper [S1].
