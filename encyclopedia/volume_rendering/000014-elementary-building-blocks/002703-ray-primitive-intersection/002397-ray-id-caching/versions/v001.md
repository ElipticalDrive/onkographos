# Ray ID Caching

Also called: RayID Culling, RayID Technique for Avoiding Multiple Intersections

## Overview
Ray ID Caching is an optimization technique used during ray-primitive intersection testing to eliminate redundant intersection calculations when a single ray intersects the same object multiple times across different voxels in a grid [S1, unofficial]. It solves the "multiple intersection problem" by maintaining a unique identifier for each ray and storing the last ray ID that tested each object, allowing the renderer to skip intersection tests that have already been performed for that specific ray-object pair [S1, unofficial]. Unlike methods that require precise voxel-object containment checks (such as Glassner's method), this technique allows for looser voxel lists because redundant intersections are filtered by the ID check rather than geometric precision [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A ray with a unique identifier (`rayID`), a list of candidate objects (primitives) potentially intersecting the current voxel, and the current intersection state.
- **Output**: A set of valid intersection tests, skipping those already performed by the current ray.

**Data Structures**
1.  **Ray Structure**: Contains an integer field `rayID`.
    -   `rayID`: A unique integer value assigned to each ray shot through the grid. It must be distinct for every ray [S1, unofficial].
2.  **Object Structure**: Contains an integer field `last_rayID`.
    -   `last_rayID`: An integer variable stored with each object, initialized to `0`. It holds the `rayID` of the ray that most recently performed an intersection test with this object [S1, unofficial].
    -   Constraint: `0` is a reserved value that no valid ray is ever allowed to have [S1, unofficial].

**Algorithm Steps**
1.  For each candidate object in the current voxel's list:
    a.  Retrieve the current ray's `rayID` and the object's `last_rayID`.
    b.  Compare `rayID` with `last_rayID`.
    c.  If `rayID == last_rayID`:
        -   The object has already been intersected by this specific ray.
        -   Skip the intersection test for this object [S1, unofficial].
    d.  If `rayID != last_rayID`:
        -   Perform the full geometric intersection test between the ray and the object.
        -   If an intersection occurs (or regardless of outcome, depending on implementation strictness, but typically only on test completion to ensure state consistency for future rays), update the object's `last_rayID` to the current ray's `rayID` [S1, unofficial].

**Pseudocode**
```python
def process_candidate_objects(ray, candidate_objects):
    """
    ray: object with attribute rayID (int)
    candidate_objects: list of objects, each with attribute last_rayID (int)
    """
    current_ray_id = ray.rayID
    
    for obj in candidate_objects:
        # Check if this object has already been tested by this specific ray
        if obj.last_rayID == current_ray_id:
            # Redundant intersection test; skip it
            continue
        
        # Perform the actual intersection test
        # Note: The source implies the update happens if the test is performed.
        # To ensure correctness for subsequent rays, we update last_rayID 
        # after the test, regardless of hit/miss, or specifically on hit.
        # The text says: "Otherwise, the intersection test is performed and 
        # the object’s rayID is set to that of the ray’s."
        
        intersection = perform_intersection_test(ray, obj)
        
        # Update the object's cached rayID to the current ray's ID
        obj.last_rayID = current_ray_id
        
        if intersection:
            process_intersection(intersection)
```

**Parameters and Initialization**
-   **Initialization**: All object `last_rayID` fields must be initialized to `0` before rendering begins [S1, unofficial].
-   **Ray ID Assignment**: Each ray must be assigned a unique integer `rayID` before traversal begins. The value `0` is prohibited for valid rays [S1, unofficial].

**Edge Cases and Pitfalls**
-   **Initialization**: If `last_rayID` is not initialized to `0`, a ray with `rayID == 0` (if allowed) or a mismatched initial state could cause incorrect skipping or redundant tests. The sources explicitly state `0` is reserved and no ray has this ID [S1, unofficial].
-   **Precision**: The comparison is integer-based, avoiding floating-point precision issues associated with geometric checks for redundancy [S1, unofficial].
-   **State Consistency**: The `last_rayID` must be updated after the intersection test is performed, not just when a hit occurs, to ensure that if the same ray hits the same object again in a different voxel (due to loose voxel lists), it is skipped [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: Adds one integer comparison per potential intersection. This is negligible compared to the cost of a full geometric intersection test, which is typically several orders of magnitude more expensive [S1, unofficial].
-   **Memory Complexity**: Requires storing one additional integer (`last_rayID`) per object in the scene [S1, unofficial].
-   **Performance**: Significantly reduces the number of objects that must be intersected, especially as the level of grid subdivision increases and objects cover more voxels [S1, unofficial].
-   **Strengths**: Allows for looser, faster-to-compute voxel-object lists (avoiding the non-trivial computation of exact voxel occupancy required by Glassner's method) [S1, unofficial].
-   **Limitations**: Does not reduce the memory overhead of voxel initialization or traversal time itself, which can become significant with high subdivision rates [S1, unofficial].

## Background
The technique was described in the context of fast voxel traversal for ray tracing, specifically addressing the multiple intersection problem where a single ray intersects the same object across multiple voxels [S1, unofficial]. It is contrasted with Glassner's method, which requires determining the minimal number of voxels an object occupies, a process that is non-trivial for complicated objects [S1, unofficial]. The implementation described was in C on a Sun 3/75 running Unix, testing scenes with resolutions up to 512x512 [S1, unofficial].
