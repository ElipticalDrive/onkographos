# Ray Tracing Implicit Surfaces

Also called: Isosurface Ray Tracing, Ray Tracing General-Form Implicits, Ray Tracing Implicits, Ray casting isosurfaces

## Overview
Ray tracing implicit surfaces renders a surface defined by a function $f(\mathbf{x}) = 0$ (or $f(\mathbf{x}) - v = 0$ for an isovalue $v$) by directly solving for the intersection of a viewing ray with the surface, without extracting a proxy triangle mesh. It solves the root-finding problem $f_t(t) = 0$ for the smallest $t > 0$ along the ray $\vec{p}(t) = \vec{o} + t\vec{d}$. Unlike rasterization of proxy geometry (e.g., marching cubes), it avoids mesh extraction costs and Nyquist sampling artifacts, guaranteeing correct rendering regardless of camera position. It is distinguished from simple ray casting by its native support for secondary rays (shadows, refractions) and traversal of spatial acceleration structures [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $\vec{o} = (o_x, o_y, o_z)$.
- Ray direction $\vec{d} = (d_x, d_y, d_z)$, typically normalized.
- Implicit function $f: \mathbb{R}^3 \to \mathbb{R}$ defining the surface $f(\mathbf{x}) = 0$.
- Search interval $[t_{min}, t_{max}]$ (often derived from an acceleration structure or bounding box).
- Precision tolerance $\epsilon$.

**Outputs:**
- Intersection distance $t^*$ such that $f(\vec{o} + t^*\vec{d}) \approx 0$ and $t^*$ is the smallest positive root.
- Intersection point $\mathbf{p}^* = \vec{o} + t^*\vec{d}$.

**Data Structures:**
- **Acceleration Structure:** Spatial hierarchy (grid, octree, kd-tree, BVH) specialized for the implicit data. For structured volume data, a hierarchical min-max grid is common, storing bounds of $f$ values in each node to prune empty space [S1, unofficial].
- **Implicit Function:** Stored as procedural code, voxel grid, or hierarchical tree.

**Steps:**
1. **Ray Parameterization:** Construct the unidimensional function $f_t(t)$ by substituting the ray equation into the implicit function:
   $$f_t(t) = f(o_x + td_x, o_y + td_y, o_z + td_z)$$
2. **Root Isolation:** Use the acceleration structure or interval arithmetic to find an interval $[t_a, t_b] \subseteq [t_{min}, t_{max}]$ containing a root.
   - For algebraic surfaces, methods like Sturm sequences or Descartes' rule of signs can isolate roots [S1, unofficial].
   - For general forms, interval arithmetic or Lipschitz bounds can verify sign changes or bound the function to ensure a root exists [S1, unofficial].
   - If the acceleration structure (e.g., min-max grid) indicates $f$ does not change sign or stays above/below zero in a voxel, skip that voxel.
3. **Refinement:** Solve $f_t(t) = 0$ within the isolated interval $[t_a, t_b]$ using a numerical method to achieve precision $\epsilon$.
   - **Newton-Raphson:** Fast but requires $f_t'(t)$ and may fail for non-monotonic functions or poor initial guesses.
   - **Bisection/Regula Falsi:** Globally convergent but slower.
   - **Bounded Newton-Raphson:** Combines speed of Newton with safety of bracketing [S1, unofficial].
   - **Affine Arithmetic:** An extension of interval arithmetic for tighter bounds and better convergence [S1, unofficial].
4. **Termination:** Return the smallest $t > 0$ found. If no root is found in $[t_{min}, t_{max}]$, the ray misses the surface.

**Pseudocode:**
```python
def ray_trace_implicit_surface(o, d, f, t_min, t_max, epsilon):
    """
    Ray trace an implicit surface f(x) = 0.
    
    Args:
        o: Ray origin (vec3)
        d: Ray direction (vec3)
        f: Implicit function f(x: vec3) -> float
        t_min: Minimum search distance
        t_max: Maximum search distance
        epsilon: Convergence tolerance
        
    Returns:
        t: Intersection distance, or infinity if no intersection.
    """
    
    # Helper: Evaluate implicit function along ray
    def f_t(t):
        p = o + d * t
        return f(p)
    
    # Helper: Evaluate derivative along ray (for Newton methods)
    # Requires gradient of f. If not available, use finite differences or fallback to bisection.
    def df_t(t):
        h = epsilon * 10
        return (f_t(t + h) - f_t(t - h)) / (2 * h)

    # Step 1: Root Isolation
    # In practice, this involves traversing an acceleration structure.
    # Here we assume a robust bracketing interval [t_a, t_b] is found.
    # For simple cases without acceleration, we might sample or use interval arithmetic.
    
    # Example: Simple bracketing using interval arithmetic logic (conceptual)
    # Real implementations use specific structures (e.g., Sturm sequences for algebraics, 
    # or min-max grids for volumes).
    
    t_a = t_min
    t_b = t_max
    
    # Check if root exists in interval
    # If f_t(t_a) and f_t(t_b) have same sign, root might not exist or be even number of roots.
    # Robust methods (interval arithmetic) handle this.
    # For this pseudocode, we assume a valid bracket [t_a, t_b] is provided by the accelerator.
    
    # Step 2: Refinement
    # Use Bounded Newton-Raphson for robustness and speed
    
    t_current = (t_a + t_b) / 2.0
    
    for i in range(100): # Max iterations
        val = f_t(t_current)
        
        if abs(val) < epsilon:
            return t_current
            
        # Check for derivative zero to avoid division by zero
        deriv = df_t(t_current)
        if abs(deriv) < 1e-10:
            # Fallback to bisection if derivative is too small
            if val > 0:
                t_b = t_current
            else:
                t_a = t_current
            t_current = (t_a + t_b) / 2.0
            continue
            
        # Newton step
        t_next = t_current - val / deriv
        
        # Bounding: ensure t_next stays within [t_a, t_b]
        if t_next < t_a or t_next > t_b:
            # If Newton step goes out of bounds, use bisection
            t_next = (t_a + t_b) / 2.0
            
        # Update bracket
        if f_t(t_next) * val < 0:
            # Root is between t_current and t_next
            if val > 0:
                t_b = t_next
            else:
                t_a = t_next
        else:
            # Root is between t_next and the other bound
            if val > 0:
                t_a = t_next
            else:
                t_b = t_next
                
        t_current = t_next
        
    return t_current
```

**Parameters:**
- $\epsilon$: Typical value $10^{-4}$ to $10^{-6}$ for visual quality.
- Max iterations: 100 is sufficient for most convergent methods.

**Edge Cases and Pitfalls:**
- **Multiple Roots:** Simple Newton-Raphson may converge to a local root or diverge. Robust methods (bracketing, interval arithmetic) are required for general forms [S1, unofficial].
- **Non-monotonic Behavior:** If $f_t(t)$ is not monotonic, sign changes may not indicate a single root. Interval arithmetic or Lipschitz bounds help isolate roots [S1, unofficial].
- **Derivative Zero:** Newton-Raphson fails if $f_t'(t) \approx 0$. Fallback to bisection is necessary [G].
- **Precision:** Floating-point errors can cause false positives/negatives in root isolation. Interval arithmetic mitigates this [S1, unofficial].

## Subtopics

### Isosurface Ray Tracing
Renders $f(\mathbf{x}) - v = 0$. Sets apart by allowing dynamic isovalue changes without re-meshing. Choose when isovalue varies or is user-defined. [Isosurface Ray Tracing](52-isosurface-ray-tracing.md)

### Ray Tracing General-Form Implicits
Handles arbitrary $f(\mathbf{x}) = 0$, including non-algebraic functions. Sets apart by using interval/affine arithmetic for robustness. Choose for complex procedural implicits. [Ray Tracing General-Form Implicits](53-ray-tracing-general-form-implicits.md)

### GPU Ray Casting of Implicits
Uses fragment shaders to cast rays through bounding proxies. Sets apart by leveraging GPU parallelism for primary rays. Choose for interactive applications with limited secondary rays. [GPU Ray Casting of Implicits](54-gpu-ray-casting-of-implicits.md)

## Operating characteristics
- **Time Complexity:** $O(\log N)$ per pixel with acceleration structures (e.g., hierarchical grids, BVHs), where $N$ is the number of geometric primitives or voxels. Without acceleration, $O(N)$ [S1, unofficial].
- **Memory Complexity:** Depends on the acceleration structure. Hierarchical grids for volumes can be large but allow efficient traversal.
- **Measured Performance:** Interactive rendering of large (1 GB) structured volumes achieved on 128-CPU workstations using tile-based parallel ray tracing [S1, unofficial]. GPU implementations enable interactive ray casting of cubics and quartics [S1, unofficial].
- **Scaling:** Scales well with parallelization (CPU/GPU). Acceleration structures reduce cost significantly for complex scenes.
- **Strengths:** No mesh extraction overhead; correct rendering at any resolution/camera position; supports dynamic isovalue; handles complex geometry naturally.
- **Limitations:** Slower than rasterization of simple proxy geometry; requires robust numerical methods for general forms; acceleration structure construction can be costly for dynamic data.
- **When to Use:** Visualization of large structured data (e.g., medical volumes); dynamic isosurface exploration; complex procedural implicits where mesh extraction is impractical.
- **When Not to Use:** Simple static geometry where mesh extraction is cheap; real-time applications with strict latency constraints and simple scenes.

## Background
Ray tracing implicit surfaces was first explored by Hanrahan [39] using Descartes' rule of signs. Van Wijk [122] implemented a recursive root bracketing algorithm using Sturm sequences, employed in POV-Ray [96]. Mitchell [82] suggested interval arithmetic for root isolation. De Cusatis Junior et al. [16] extended this to affine arithmetic. Loop and Blinn [72] implemented a GPU ray caster using Bernstein polynomials. Fryazinov and Pasko [27] used rule-of-signs interval methods for FRep surfaces on GPU. Parker et al. [90, 89] achieved interactive rendering of large structured volumes using hierarchical grids.
