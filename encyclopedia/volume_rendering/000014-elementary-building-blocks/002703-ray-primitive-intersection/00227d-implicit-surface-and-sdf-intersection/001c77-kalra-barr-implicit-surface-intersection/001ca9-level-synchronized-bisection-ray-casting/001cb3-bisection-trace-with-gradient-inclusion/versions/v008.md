# Bisection Trace with Gradient Inclusion

Also called: Level-Synchronized Interval Bisection

## Overview
Bisection Trace with Gradient Inclusion is a robust ray casting algorithm that renders the zero-level-set of an implicit function $f: \mathbb{R}^3 \to \mathbb{R}$ by combining level-synchronized bisection with gradient-based inclusion functions. It solves the problem of missing surface features during ray traversal by using interval arithmetic to guarantee that no zero-crossings are pruned. It differs from standard bisection by using gradient information to tighten bounds on the function's range over axis-aligned boxes, and from pure interval arithmetic by potentially offering tighter bounds with less dependency on symbolic expansion, directly impacting convergence speed [S1, unofficial].

## How it works
**Inputs:** Ray origins $\mathbf{o}$, directions $\mathbf{d}$, near/far clip planes $t_{min}, t_{max}$, implicit function $f$, Lipschitz constant $L$ (or 'auto'), maximum bisection depth $D_{max}$, convergence threshold $\epsilon$, Newton iteration count $N_{newton}$, and batch size $B$.
**Outputs:** Hit distances $t$, hit masks, and optionally surface normals.

**Data Structures:**
*   **Affine Form (AA):** Represents an interval $[f]$ as a tuple $(x_0, \xi, \delta)$ where $f \in [x_0 - \delta, x_0 + \delta]$ and $\xi$ is the slope vector for dependency tracking.
*   **Inclusion Function:** An object implementing `evaluate(lo, hi)` that returns $(f_{min}, f_{max})$ for boxes defined by lower bounds `lo` and upper bounds `hi`.

**Steps:**
1.  **Initialize Inclusion Function:** Create an instance of `GradientInclusion` using $f$ and $L$. If $L$ is 'auto', estimate it by sampling gradient norms $\|\nabla f\|$ over the bounding box using automatic differentiation [S1, unofficial].
2.  **Batch Processing:** Divide rays into batches of size $B$. If $B$ is None, process all rays.
3.  **Level-Synchronized Bisection Loop:**
    a.  For each active ray $i$ (where hit mask is true):
    b.  Define current interval $[t_{curr}] = [t_{min}, t_{max}]$.
    c.  For $d = 1$ to $D_{max}$:
        i.  Evaluate inclusion function: $(f_{min}, f_{max}) = \text{Inclusion.evaluate}(f(\mathbf{o}_i + t_{curr} \cdot \mathbf{d}_i))$.
        ii. If $0 \notin [f_{min}, f_{max}]$, prune ray $i$ (no hit in this interval).
        iii. If $f_{max} - f_{min} < \epsilon$, convergence reached. Refine using Newton's method for $N_{newton}$ iterations to find precise $t^*$. Mark ray as hit.
        iv. Bisect $[t_{curr}]$ into two sub-intervals. Select the sub-interval containing zero (if both, keep both or use heuristic). Update $[t_{curr}]$.
4.  **Return Results:** Collect hit distances and masks for all rays.

**Parameters:**
*   $D_{max}$: Maximum bisection depth. Typical value: 10-20.
*   $\epsilon$: Convergence threshold. Typical value: $10^{-6}$ to $10^{-8}$.
*   $L$: Lipschitz constant. If 'auto', estimated via sampling.
*   $N_{newton}$: Newton iterations. Typical value: 3-5.
*   $B$: Batch size. None for all.

**Edge Cases:**
*   **Wide Intervals:** For large intervals, gradient-based bounds may be loose. Use dense sampling or analytical critical point detection for specific functions (e.g., sin/cos) to tighten bounds [S1, unofficial].
*   **Straddle Zero:** When interval contains zero, ensure conservative bounds are used to avoid false negatives.
*   **Precision:** Use double precision for interval arithmetic to avoid accumulation errors.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot D \cdot C)$, where $N$ is number of rays, $D$ is max depth, $C$ is cost of inclusion evaluation.
*   **Memory Complexity:** $O(N)$ for ray state.
*   **Strengths:** Robustness against missed surfaces; gradient-based bounds can be tighter than pure interval arithmetic for smooth functions.
*   **Limitations:** Requires gradient computation; may be slower per step than simple bisection due to inclusion evaluation overhead.
*   **When to Use:** High-quality rendering where missing surface features is unacceptable; smooth implicit surfaces.
*   **When Not to Use:** Real-time applications with strict latency constraints; non-smooth functions where gradient is undefined.

## Background
Originated from the need for robust iso-surface rendering in implicit modeling. The method builds on level-synchronized bisection ray casting [1313-level-synchronized-bisection-ray-casting.md] and incorporates gradient-based inclusion functions to improve convergence. Implemented in the `iso-surface-rendering` library [S1, unofficial].
