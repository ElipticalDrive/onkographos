# Bisection Trace with Gradient Inclusion

Also called: Level-Synchronized Interval Bisection

## Overview
Bisection Trace with Gradient Inclusion is a robust ray casting algorithm that renders the zero-level-set of an implicit function $f: \mathbb{R}^3 \to \mathbb{R}$ by combining level-synchronized bisection with gradient-based Lipschitz estimation. It solves the problem of missing surface features during ray traversal by using interval arithmetic to guarantee that no zero-crossings are pruned. It differs from its parent, [Level-synchronized bisection ray casting](1313-level-synchronized-bisection-ray-casting.md), by automating the computation of the Lipschitz constant required for the inclusion function via gradient sampling, rather than requiring a user-provided global bound.

## How it works
The method traces rays in lockstep (level-synchronized) using interval arithmetic to bound the implicit function $f$ over axis-aligned boxes. Intervals that cannot contain a zero crossing are pruned, and the remaining intervals are bisected to refine the hit location.

**Inputs:**
- Ray origins $\mathbf{o}$ and directions $\mathbf{d}$.
- Ray segment bounds $t_{min}, t_{max}$.
- Implicit function $f(\mathbf{x})$ and its gradient $\nabla f(\mathbf{x})$.
- Parameters: `max_depth` (maximum bisection iterations), `threshold` (convergence tolerance), `lipschitz` (Lipschitz constant $L$, or 'auto'), `batch_size` (rays per batch), `newton_iter` (Newton refinement steps).

**Outputs:**
- Hit positions $\mathbf{x}$ for each ray.
- Hit mask indicating successful intersections.

**Data Structures:**
- **Affine Arithmetic Form (AA):** Used for tighter bounds than standard Interval Arithmetic. Defined as $a = x_0 + \sum_{i=1}^n \xi_i \delta_i + \delta_{new} \delta_{new}$, where $x_0$ is the center, $\xi_i$ are coefficients, and $\delta$ are uncertainty bounds.
- **Inclusion Function:** A protocol implementing `evaluate(lo, hi)` that returns conservative lower and upper bounds $[f_{min}, f_{max}]$ for $f$ over the box $[\mathbf{lo}, \mathbf{hi}]$.

**Steps:**

1. **Initialize Inclusion Function:**
   If `lipschitz` is 'auto', estimate $L$ by sampling gradient norms $\|\nabla f(\mathbf{x})\|$ over the bounding box using automatic differentiation. Initialize the inclusion function (e.g., `GradientInclusion`) with $L$.

2. **Batch Processing:**
   Divide rays into batches of size `batch_size`. If `batch_size` is None, process all rays.

3. **Level-Synchronized Bisection Loop:**
   For each depth level $d$ from 1 to `max_depth`:
   a. **Evaluate Bounds:** For each active ray, define the current interval $[t_{curr\_min}, t_{curr\_max}]$. Map this to 3D axis-aligned box bounds. Call `inclusion.evaluate(lo, hi)` to get $[f_{min}, f_{max}]$.
   b. **Pruning:** If $f_{max} < 0$ or $f_{min} > 0$, the interval cannot contain a zero crossing. Mark the ray as "empty" or "missed" and remove it from active processing.
   c. **Bisection:** For remaining active rays, compute the midpoint $t_{mid} = (t_{min} + t_{max}) / 2$. Update the interval to $[t_{min}, t_{mid}]$ or $[t_{mid}, t_{max}]$ based on the sign of $f$ at the endpoints or interval bounds.
   d. **Convergence Check:** If $t_{max} - t_{min} < \text{threshold}$, mark the ray as "hit" with position $\mathbf{o} + t_{mid}\mathbf{d}$ and remove from active processing.

4. **Newton Refinement:**
   For rays marked as "hit", perform `newton_iter` steps of Newton's method to refine the hit position:
   $$ \mathbf{x}_{new} = \mathbf{x} - \frac{f(\mathbf{x})}{\nabla f(\mathbf{x}) \cdot \mathbf{d}} $$
   Ensure the refined point remains within the original $[t_{min}, t_{max}]$ bounds.

5. **Output:**
   Return hit positions and masks for all rays.

            batch_end = min(batch_start + (batch_size if batch_size else len(active_indices)), len(active_indices))
            batch_indices = active_indices[batch_start:batch_end]
            
            # Get current ray parameters
            batch_origins = origins[batch_indices]
            batch_dirs = directions[batch_indices]
            batch_t_min = current_t_min[batch_indices]
            batch_t_max = current_t_max[batch_indices]
            
            # Compute box bounds in 3D
            # Box min: origin + t_min * dir, Box max: origin + t_max * dir
            box_lo = batch_origins + batch_t_min[:, None] * batch_dirs
            box_hi = batch_origins + batch_t_max[:, None] * batch_dirs
            
            # Evaluate inclusion function
            f_min, f_max = inclusion.evaluate(box_lo, box_hi)
            
            # Pruning: if interval does not contain zero, remove ray
            # Condition: f_max < 0 OR f_min > 0
            prune_mask = (f_max < 0) | (f_min > 0)
            
            # Convergence check: if interval is small enough, mark as hit
            interval_width = batch_t_max - batch_t_min
            converge_mask = interval_width < threshold
            
            # Update active indices
            # Keep rays that are not pruned AND not converged
            keep_mask = ~prune_mask & ~converge_mask
            active_indices = active_indices[batch_start:batch_end][keep_mask]
            
            # Update t_min/t_max for active rays
            # Simple bisection: update based on sign of f at midpoint or interval bounds
            # For robustness, use the inclusion bounds to decide which half to keep
            # If f_min > 0, keep upper half; if f_max < 0, keep lower half
            # If signs differ, keep both? No, bisection splits.
            # Standard bisection: evaluate f at midpoint, keep half containing zero
            # But we use inclusion. If f_min < 0 and f_max > 0, zero is in interval.
            # We split the interval.
            
            mid_t = (batch_t_min + batch_t_max) / 2.0
            # Evaluate f at midpoint for decision [G]
            # Note: Inclusion function gives bounds, but we need a point evaluation for bisection direction
            # Or use the sign of f_min/f_max if they don't straddle zero?
            # If they straddle, we must split.
            
            # Re-evaluate for bisection direction using point evaluation at midpoint
            mid_points = batch_origins + mid_t[:, None] * batch_dirs
            f_mid = f_np(mid_points)
            
            # Update t_min/t_max based on sign of f_mid relative to f at endpoints?
            # Standard bisection: if f(mid) * f(t_min) < 0, root is in [t_min, mid]
            # Else root is in [mid, t_max]
            # However, we have f_min and f_max from inclusion.
            # If f_min > 0, root is in [mid, t_max] (assuming f(t_max) < 0? No, f_max < 0 means no root)
            # Let's stick to standard bisection logic for the split, using inclusion only for pruning.
            
            # Update t_min/t_max
            update_t_min = f_mid * (f_np(batch_origins + batch_t_min[:, None] * batch_dirs)) < 0
            current_t_min[batch_indices] = np.where(update_t_min, batch_t_min, mid_t)

**Edge Cases and Pitfalls:**
- **Precision:** Interval arithmetic can suffer from overestimation, leading to unnecessary bisections. Affine Arithmetic reduces this but is more expensive.
- **Lipschitz Estimation:** If `lipschitz` is 'auto', the estimation must cover the entire bounding box. Underestimating $L$ leads to invalid pruning (missing surfaces).
- **Degenerate Input:** Rays parallel to the surface or starting on the surface may cause division by zero in Newton's method. Guard against this.

## Operating characteristics
- **Time Complexity:** $O(N \cdot D \cdot B)$, where $N$ is the number of rays, $D$ is `max_depth`, and $B$ is the cost of the inclusion function evaluation per ray.
- **Memory Complexity:** $O(N)$ for storing ray states and intermediate results.
- **Performance:** Robust but slower than heuristic ray marching due to interval evaluations. Performance scales linearly with ray count.
- **Strengths:** Guaranteed no missing surfaces; handles complex implicit functions.
- **Limitations:** High computational cost; sensitive to Lipschitz constant accuracy.
