# Interval Arithmetic Inclusion Strategies

Also called: InclusionFunction strategies

## Overview
Interval Arithmetic Inclusion Strategies provide the mathematical mechanism to bound the range of an implicit scalar field function $f$ over a 3D bounding box $\mathcal{B}$, ensuring that the true zero-level set is not missed during ray casting. They solve the problem of robust intersection detection by guaranteeing that if an interval $[f](\mathcal{B})$ does not contain zero, the box $\mathcal{B}$ contains no surface points and can be safely pruned. This family differs from its siblings by offering a spectrum of strategies that trade off between black-box compatibility (requiring only point evaluations) and bound tightness (requiring symbolic access to $f$), directly impacting the number of bisection steps required for convergence.

## Shared principles
All strategies in this family compute an interval $[f](\mathcal{B}) = [f_-, f_+]$ such that for all $\mathbf{x} \in \mathcal{B}$, $f(\mathbf{x}) \in [f_-, f_+]$. The core requirement is the **inclusion property**: the computed interval must contain the true range of the function. If $0 \notin [f](\mathcal{B})$, the box is pruned. The strategies are categorized by the information they require about $f$:

1.  **SamplingInclusion**: A black-box baseline strategy. It requires only point evaluations $f(\mathbf{x})$ and a Lipschitz constant $\lambda$. It computes the minimum and maximum sampled values $f_{min}, f_{max}$ over a grid within $\mathcal{B}$ and expands them by the maximum possible variation $\lambda \cdot \text{diam}(\mathcal{B})$. This is the most general but often the loosest bound.
2.  **GradientInclusion**: The default strategy. It uses the gradient $\nabla f(\mathbf{x})$ to compute tighter linear bounds. By evaluating the gradient at the box center or corners, it constructs a linear inclusion function that accounts for the local rate of change, providing tighter bounds than SamplingInclusion without requiring the full symbolic formula.
3.  **NaturalIntervalInclusion (NIA)**: An analytic strategy. It applies interval arithmetic directly to the symbolic expression of $f$. By propagating intervals through the arithmetic operations (addition, multiplication, etc.) defined in the formula, it yields tighter bounds than GradientInclusion for analytic functions, as it avoids the overestimation inherent in linear approximations.
4.  **AffineInclusion (AA)**: The analytic strategy providing the tightest bounds. It uses Affine Arithmetic, which tracks linear correlations between variables in the symbolic expression. This reduces the dependency problem (overestimation due to repeated variables) common in NIA, resulting in the narrowest intervals and the fewest bisection steps, at the cost of higher computational overhead per evaluation.

The choice of strategy is governed by the availability of symbolic information and the desired performance-accuracy trade-off. Black-box functions must use SamplingInclusion or GradientInclusion. Analytic functions can leverage NIA or AA for superior performance.

## Subtopics

### [Lipschitz Constant Estimation](1572-lipschitz-constant-estimation.md)
Lipschitz Constant Estimation computes the maximum rate of change $\lambda$ of the implicit function $f$ over a domain. It is a prerequisite for SamplingInclusion and GradientInclusion to determine safe stepping distances. It differs from the other inclusion strategies by outputting a scalar bound $\lambda$ rather than an interval $[f](\mathcal{B})$, although it is used to construct the bounds in those strategies. Choose this when using black-box or gradient-based inclusion to ensure no surface features are missed due to excessive step sizes.

### [Forward Linear Inclusion Function](1714-forward-linear-inclusion-function.md)
The Forward Linear Inclusion Function computes a valid linear interval bound for $f$ along a ray segment, using the function value and gradient (or Lipschitz constant) at a starting point $t_0$. It sets itself apart by providing a first-order approximation that is simpler than quadratic Taylor bounds but tighter than simple sampling. Choose this when performing sphere tracing or bisection where a linear bound is sufficient to determine the next step size without full box evaluation.

### Parallel Tape Reduction
Parallel Tape Reduction is a method that simplifies the evaluation of SDF construction trees by coupling pruning and rendering using interval arithmetic. It differs from standard Lipschitz pruning by using explicit interval queries for each node in the tree rather than treating primitives as black boxes with 1-Lipschitz bounds. This allows for efficient pruning of hard and smooth boolean operators in large scenes, scaling to thousands of nodes where other methods fail. It is chosen when rendering complex CSG scenes with hierarchical SDF representations.

## Background
The concept of using interval arithmetic for robust geometric queries originated in the 1990s, with early work by H. H. Baker and others on guaranteed intersection detection. The specific application to ray casting for implicit surfaces was formalized in the context of "isoray" and related research, which highlighted the need for robust handling of thin shells, cusps, and high-frequency surfaces where standard floating-point arithmetic fails. The four-strategy framework (Sampling, Gradient, NIA, AA) was popularized by the `iso-surface-rendering` project, which demonstrated the practical trade-offs between black-box compatibility and bound tightness [S1, unofficial]. Parallel Tape Reduction was introduced in recent work on hierarchical SDF simplification, addressing the performance bottleneck of large CSG trees by integrating interval-based pruning directly into the rendering pipeline [S2].
