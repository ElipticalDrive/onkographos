# Quadratic Ray-Gaussian Intersection

Also called: Gaussian Ellipsoid Intersection

## Overview
The Quadratic Ray-Gaussian Intersection method approximates the intersection of a ray with a 3D Gaussian distribution by computing the intersection with the ellipsoid defined by one standard deviation of that distribution [S1]. It serves as a numerically stable alternative to the Cubic Ray-Gaussian Intersection Solver, avoiding the NaN instability inherent in cubic solvers while providing a discriminant to verify intersection existence, which the Linear Ray-Gaussian Intersection lacks [S1]. It yields the lowest depth and mask errors among the three primary methods but is slower than the linear approach [S1].

## How it works
The method solves for the intersection parameter $t$ of a ray with direction $v$ passing through the origin, intersecting the boundary of a Gaussian defined by mean $\mu$ and covariance $\Sigma$ [S1]. The boundary is defined as the set of points where the Mahalanobis distance squared equals 1: $(x - \mu)^T \Sigma^{-1} (x - \mu) = 1$ [S1].

**Inputs:**
- Ray direction $v$ (3D vector) [S1].
- Gaussian mean $\mu$ (3D vector) [S1].
- Gaussian covariance matrix $\Sigma$ (3x3 symmetric matrix) [S1].

**Outputs:**
- Intersection parameters $t_1, t_2$ (scalars), representing the entry and exit points of the ray through the ellipsoid [S1].

**Data Structures:**
- $\Sigma^{-1}$: The inverse of the covariance matrix [G].
- Intermediate vectors: $u = \Sigma^{-1} v$ and $w = \Sigma^{-1} \mu$ [G].

**Steps:**
1. Compute the inverse covariance matrix $\Sigma^{-1}$ [G].
2. Compute the vector $u = \Sigma^{-1} v$ [G].
3. Compute the vector $w = \Sigma^{-1} \mu$ [G].
4. Calculate the quadratic coefficients $a, b, c$:
   - $a = v^T u = v^T \Sigma^{-1} v$ [S1].
   - $b = -2 (v^T w) = -2 v^T \Sigma^{-1} \mu$ [S1].
   - $c = (\mu^T w) - 1 = \mu^T \Sigma^{-1} \mu - 1$ [S1].
5. Compute the discriminant $\Delta = b^2 - 4ac$ [G].
6. If $\Delta < 0$, the ray misses the ellipsoid; clip $\Delta$ to $0$ to produce reasonable results [S1].
7. Compute the square root $D = \sqrt{\Delta}$ [G].
8. Compute the intersection parameters:
   - $t_1 = \frac{-b - D}{2a}$ [S1].
   - $t_2 = \frac{-b + D}{2a}$ [S1].
9. Return $t_1$ and $t_2$ [S1].

**Pseudocode:**
```python
def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def mat_vec(M, v):
    return [M[0][0]*v[0] + M[0][1]*v[1] + M[0][2]*v[2],
            M[1][0]*v[0] + M[1][1]*v[1] + M[1][2]*v[2],
            M[2][0]*v[0] + M[2][1]*v[1] + M[2][2]*v[2]]

def inv_3x3(M):
    det = (M[0][0]*(M[1][1]*M[2][2] - M[1][2]*M[2][1]) -
           M[0][1]*(M[1][0]*M[2][2] - M[1][2]*M[2][0]) +
           M[0][2]*(M[1][0]*M[2][1] - M[1][1]*M[2][0]))
    inv_det = 1.0 / det
    return [[(M[1][1]*M[2][2] - M[1][2]*M[2][1])*inv_det,
             (M[0][2]*M[2][1] - M[0][1]*M[2][2])*inv_det,
             (M[0][1]*M[1][2] - M[0][2]*M[1][1])*inv_det],
            [(M[1][2]*M[2][0] - M[1][0]*M[2][2])*inv_det,
             (M[0][0]*M[2][2] - M[0][2]*M[2][0])*inv_det,
             (M[0][2]*M[1][0] - M[0][0]*M[1][2])*inv_det],
            [(M[1][0]*M[2][1] - M[1][1]*M[2][0])*inv_det,
             (M[0][1]*M[2][0] - M[0][0]*M[2][1])*inv_det,
             (M[0][0]*M[1][1] - M[0][1]*M[1][0])*inv_det]]

def quadratic_ray_gaussian_intersection(ray_direction, gaussian_mean, gaussian_covariance):
    inv_sigma = inv_3x3(gaussian_covariance)
    u = mat_vec(inv_sigma, ray_direction)
    w = mat_vec(inv_sigma, gaussian_mean)
    a = dot(ray_direction, u)
    b = -2.0 * dot(ray_direction, w)
    c = dot(gaussian_mean, w) - 1.0
    discriminant = b * b - 4.0 * a * c
    if discriminant < 0:
        discriminant = 0.0
    sqrt_discriminant = discriminant ** 0.5
    if a == 0:
        return None
    t1 = (-b - sqrt_discriminant) / (2.0 * a)
    t2 = (-b + sqrt_discriminant) / (2.0 * a)
    return t1, t2
```

**Parameters:**
- No tunable parameters [S1].

**Edge Cases and Pitfalls:**
- **Ray Miss:** When the ray misses the ellipsoid, the discriminant $b^2 - 4ac$ becomes negative [S1]. The source specifies clipping this value to be non-negative to produce reasonable results [S1].
- **Precision:** While more stable than the cubic solver, it still operates in floating point [S1]. It does not suffer from the high NaN rate of the cubic solver [S1].
- **Degenerate Covariance:** If $\Sigma$ is singular, $\Sigma^{-1}$ is undefined [G].

## Subtopics

### Cubic Ray-Gaussian Intersection Solver
Solves for the intersection of a ray with a Gaussian distribution by finding the roots of a cubic polynomial derived from the Gaussian's quadratic form [S1]. It provides the most accurate surface representation but suffers from numerical instability [S1]. The cubic equation is derived by setting the gradient of the Gaussian density to zero [S1]. Defining $m = \Sigma \mu$ and $r = \Sigma v$, the equation is:
$$ 0 = - t^3 (r^T r) (v^T r) + t^2 \left[ (m^T r + r^T m) (v^T r) + (r^T r) (v^T m) \right] - t \left[ (m^T m) (v^T r) + (m^T r + r^T m) (v^T m) - r^T r \right] + (m^T m) (v^T m) - r^T m $$
In 32-bit floating point precision, even a numerically stable cubic solver produces NaNs at a rate of approximately 1 in 1,000 pixels, which breaks backpropagation [S1]. It takes twice as long as the linear method for a forward pass [S1].

### Linear Ray-Gaussian Intersection
Approximates the Gaussian surface intersection using a linear method [S1]. It produces smooth surfaces and is the most numerically stable and fastest method, used for all evaluations outside the specific intersection comparison section [S1]. It is the fastest method for a forward pass [S1].

## Operating characteristics
- **Time Complexity:** The quadratic method takes 50% longer than the linear method for a forward pass [S1]. The cubic method takes twice as long as the linear method [S1].
- **Accuracy:** In 3D evaluation on objects, the quadratic method has the lowest errors in depth and mask compared to linear and cubic methods [S1]. The linear method produces smooth surfaces, while the quadratic method shows individual ellipsoids protruding from the object surface [S1].
- **Stability:** The quadratic method is numerically stable and avoids the NaN issues of the cubic solver [S1]. Due to its stability and speed, the linear method is used for all evaluations outside the specific intersection comparison section [S1].
- **When to use:** Use the quadratic method when accuracy (lowest depth/mask error) is prioritized over speed and stability is required compared to the cubic solver [S1]. Use the linear method for general evaluation due to its speed and stability [S1].

## Background
The method is described in "Approximate Differentiable Rendering with Algebraic Surfaces" by Leonid Keselman and Martial Hebert [S1]. The paper compares three methods for ray-Gaussian intersection: Linear, Quadratic, and Cubic [S1]. The quadratic method is introduced as an approximation of the cubic method that avoids numerical instability [S1].
