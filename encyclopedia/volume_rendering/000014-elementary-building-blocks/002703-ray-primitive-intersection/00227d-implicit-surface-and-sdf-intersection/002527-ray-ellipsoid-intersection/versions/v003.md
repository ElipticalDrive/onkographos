# Ray-Ellipsoid Intersection
Also called: Ellipsoid Ray Intersection
## Overview
Computes the intersection of a ray with an ellipsoid defined by rotation, translation, and scale, returning whether an intersection exists and the intersection point in world space [S1, unofficial]. It transforms the ray into the ellipsoid's local space to reduce the problem to a ray-sphere intersection, solving a quadratic equation for the distance along the ray [S1, unofficial]. This method is distinct from general implicit surface intersection by leveraging the specific analytic solution for quadratic forms, offering a closed-form result without iterative refinement [S1, unofficial].
## How it works
### Inputs and Outputs
**Inputs:**
- Ray origin $\mathbf{o}$ (world space, 3D vector).
- Ray direction $\mathbf{d}$ (world space, 3D vector, typically normalized).
- Ellipsoid translation $\mathbf{t}$ (world space, 3D vector).
- Ellipsoid rotation matrix $\mathbf{R}$ (3x3 orthogonal matrix).
- Ellipsoid scale vector $\mathbf{S} = [S_x, S_y, S_z]$ (positive scalars).
- Epsilon $\epsilon$ for numerical stability (default $10^{-5}$) [S1, unofficial].

**Outputs:**
- Boolean indicating intersection existence.
- Intersection point $\mathbf{p}$ in world space (if intersection exists).
- Distance $t$ along the ray (if intersection exists).

### Data Structures
No complex data structures are required. The method operates on standard 3D vectors and 3x3 matrices.

### Steps
1. **Compute Inverse Transformation:** Calculate the matrix that transforms world coordinates to the ellipsoid's local space. This is the inverse of the transformation $\mathbf{T}(\mathbf{R}, \mathbf{S}, \mathbf{t})$. The inverse transformation matrix $\mathbf{M}_{inv}$ is computed as:
   $$ \mathbf{M}_{inv} = \text{diag}\left(\frac{1}{S_x}, \frac{1}{S_y}, \frac{1}{S_z}\right) \mathbf{R}^T $$
   [S1, unofficial]

2. **Transform Ray:** Transform the ray origin and direction into the ellipsoid's local space:
   $$ \mathbf{o}' = \mathbf{M}_{inv} (\mathbf{o} - \mathbf{t}) $$
   $$ \mathbf{d}' = \mathbf{M}_{inv} \mathbf{d} $$
   [S1, unofficial]

3. **Solve Quadratic Equation:** The intersection in local space satisfies $|\mathbf{o}' + t\mathbf{d}'|^2 = 1$. This expands to $At^2 + Bt + C = 0$, where:
   $$ A = \mathbf{d}' \cdot \mathbf{d}' $$
   $$ B = 2 (\mathbf{o}' \cdot \mathbf{d}') $$
   $$ C = \mathbf{o}' \cdot \mathbf{o}' - 1 $$
   [S1, unofficial]

4. **Handle Degenerate Direction:** If $|A| < \epsilon$, set $A = \epsilon$ to avoid division by zero [S1, unofficial].

5. **Compute Discriminant:**
   $$ \Delta = B^2 - 4AC $$
   If $\Delta < 0$, there is no intersection [S1, unofficial].

6. **Handle Near-Zero Discriminant:** If $|\Delta| < \epsilon$, set $\Delta = 0$ [S1, unofficial].

7. **Compute Roots:**
   $$ \sqrt{\Delta} = \sqrt{\Delta} $$
   $$ t_1 = \frac{-B - \sqrt{\Delta}}{2A} $$
   $$ t_2 = \frac{-B + \sqrt{\Delta}}{2A} $$
   [S1, unofficial]

8. **Check Validity:** If both $t_1 < 0$ and $t_2 < 0$, the intersection is behind the ray origin, so there is no valid intersection [S1, unofficial].

9. **Select Intersection Distance:**
   - If $t_1 \ge 0$, $t_{intersect} = t_1$.
   - Else, $t_{intersect} = t_2$.
   - If $|t_1 - t_2| < \epsilon$, $t_{intersect} = \min(t_1, t_2)$ [S1, unofficial].

10. **Compute Intersection Point in Local Space:**
    $$ \mathbf{p}' = \mathbf{o}' + t_{intersect} \mathbf{d}' $$
    [S1, unofficial]

11. **Transform Back to World Space:** Compute the forward transformation matrix $\mathbf{M}_{fwd} = \mathbf{R} \text{diag}(S_x, S_y, S_z)$. The world space intersection point is:
    $$ \mathbf{p} = \mathbf{M}_{fwd} \mathbf{p}' + \mathbf{t} $$
    [S1, unofficial]

### Pseudocode
```python
import math

def ray_ellipsoid_intersection(o, d, t, R, S, eps=1e-5):
    """
    Compute ray-ellipsoid intersection.
    
    Args:
        o: Ray origin (3D vector)
        d: Ray direction (3D vector)
        t: Ellipsoid translation (3D vector)
        R: Ellipsoid rotation matrix (3x3)
        S: Ellipsoid scale vector (3D vector)
        eps: Epsilon for numerical stability
        
    Returns:
        (hit, p, t_intersect): Boolean hit flag, intersection point p, distance t_intersect
    """
    # Step 1: Compute inverse transformation matrix M_inv
    # M_inv = diag(1/S) @ R.T
    inv_S = [1.0/S[0], 1.0/S[1], 1.0/S[2]]
    # R.T is the transpose of R
    R_T = [[R[i][j] for j in range(3)] for i in range(3)]
    
    # M_inv = diag(inv_S) * R_T
    # M_inv[i][j] = inv_S[i] * R_T[i][j]
    M_inv = [[inv_S[i] * R_T[i][j] for j in range(3)] for i in range(3)]
    
    # Step 2: Transform ray origin and direction
    # o' = M_inv @ (o - t)
    o_minus_t = [o[i] - t[i] for i in range(3)]
    o_prime = [sum(M_inv[i][j] * o_minus_t[j] for j in range(3)) for i in range(3)]
    
    # d' = M_inv @ d
    d_prime = [sum(M_inv[i][j] * d[j] for j in range(3)) for i in range(3)]
    
    # Step 3: Compute quadratic coefficients
    # A = d' . d'
    A = sum(d_prime[i] * d_prime[i] for i in range(3))
    # B = 2 * (o' . d')
    B = 2 * sum(o_prime[i] * d_prime[i] for i in range(3))
    # C = o' . o' - 1
    C = sum(o_prime[i] * o_prime[i] for i in range(3)) - 1.0
    
    # Step 4: Handle degenerate direction
    if abs(A) < eps:
        A = eps
        
    # Step 5: Compute discriminant
    discriminant = B * B - 4 * A * C
    
    if discriminant < 0:
        return (False, None, None)
        
    # Step 6: Handle near-zero discriminant
    if abs(discriminant) < eps:
        discriminant = 0.0
        
    # Step 7: Compute roots
    sqrt_discriminant = math.sqrt(discriminant)
    t1 = (-B - sqrt_discriminant) / (2 * A)
    t2 = (-B + sqrt_discriminant) / (2 * A)
    
    # Step 8: Check if both roots are negative
    if t1 < 0 and t2 < 0:
        return (False, None, None)
        
    # Step 9: Select valid t
    if t1 >= 0:
        t_intersect = t1
    else:
        t_intersect = t2
        
    if abs(t1 - t2) < eps:
        t_intersect = min(t1, t2)
        
    # Step 10: Compute intersection point in local space
    # p' = o' + t_intersect * d'
    p_prime = [o_prime[i] + t_intersect * d_prime[i] for i in range(3)]
    
    # Step 11: Transform back to world space
    # M_fwd = R @ diag(S)
    # M_fwd[i][j] = R[i][j] * S[j]
    M_fwd = [[R[i][j] * S[j] for j in range(3)] for i in range(3)]
    
    # p = M_fwd @ p' + t
    p = [sum(M_fwd[i][j] * p_prime[j] for j in range(3)) + t[i] for i in range(3)]
    
    return (True, p, t_intersect)
```
[G] The pseudocode assumes standard 3x3 matrix-vector multiplication. The inverse transformation is derived from the forward transformation $\mathbf{p} = \mathbf{R} \text{diag}(\mathbf{S}) \mathbf{p}' + \mathbf{t}$, so $\mathbf{p}' = \text{diag}(1/\mathbf{S}) \mathbf{R}^T (\mathbf{p} - \mathbf{t})$.

### Parameters
- $\epsilon$: Epsilon for numerical stability, default $10^{-5}$ [S1, unofficial].

### Edge Cases and Pitfalls
- **Degenerate Direction:** If $A \approx 0$, the ray direction is nearly orthogonal to the scaling axes in local space, leading to division by zero. Handled by clamping $A$ to $\epsilon$ [S1, unofficial].
- **Near-Zero Discriminant:** If $\Delta \approx 0$, the ray is tangent to the ellipsoid. Handled by clamping $\Delta$ to 0 [S1, unofficial].
- **Behind Ray Origin:** If both roots are negative, the intersection is behind the ray origin. Handled by checking $t_1, t_2 < 0$ [S1, unofficial].
- **Precision:** Floating-point precision issues may arise for very small or very large ellipsoids. Using $\epsilon$ helps mitigate this [S1, unofficial].

## Operating characteristics
**Time Complexity:** $O(1)$ per ray-ellipsoid intersection. The computation involves a constant number of arithmetic operations and matrix-vector multiplications.
**Memory Complexity:** $O(1)$ auxiliary space.
**Performance:** The method is highly efficient due to its closed-form solution. It is suitable for real-time rendering and large-scale scenes with many ellipsoids [S1, unofficial].
**Strengths:** Analytic solution, no iteration required, robust handling of degenerate cases.
**Limitations:** Assumes ellipsoid is defined by rotation, translation, and scale. Does not handle general quadratic surfaces directly without transformation.
**When to Use:** When intersecting rays with ellipsoidal primitives, especially in contexts like 3D Gaussian Splatting where ellipsoids represent uncertainty or shape [S1, unofficial].
**When Not to Use:** For general implicit surfaces that cannot be easily transformed into a sphere, or when iterative methods are preferred for other reasons.

## Background
The method is based on the geometric principle that an ellipsoid can be transformed into a unit sphere via a linear transformation. The intersection of a ray with a unit sphere is a well-known problem solvable via a quadratic equation. This approach is commonly used in computer graphics for efficient primitive intersection tests [S1, unofficial]. The specific implementation details are derived from an unofficial Taichi 3D Gaussian Splatting repository [S1, unofficial].
