# GPU Fragment Program Ray Casting

Also called: Explicit ray casting, Fragment program ray casting, Ray casting on GPU, Ray casting via fragment shaders, rectilinear volume ray caster on GPU

## Overview
GPU Fragment Program Ray Casting is a volume rendering technique where each fragment or thread casts one ray through the volume, implemented in a fragment shader or compute kernel [S1][S3, unofficial]. It approximates the volume rendering integral via discrete sampling, exploiting the intrinsic parallelism of the fragment unit by associating one ray with each screen pixel [S2][S3, unofficial]. Unlike implicit approaches based on 3D textures, this explicit approach is less performant, although the quality differential tends to decrease with high-quality rendering techniques [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data stored in 3D textures in graphics memory [S3, unofficial]. A polygon covering the screen area to generate fragments [S3, unofficial].
*   **Output:** The final rendered image stored in a 2D texture (framebuffer) [S3, unofficial].

**Data Structures:**
*   **3D Texture:** Stores the scalar field (density/opacity) and potentially color attributes [S3, unofficial].
*   **2D Textures (Ping-Pong Buffers):** Two copies of a 2D texture are required [S3, unofficial]. One acts as the read buffer (accumulated color/opacity from the previous step) and the other as the write buffer (updated values) [S3, unofficial]. There is a direct correspondence between texels and screen pixels [S3, unofficial].

**Parameters:**
*   **Step Size:** Distance advanced along the ray per iteration [S2].
*   **Maximum Loop Count:** Fragment programs historically restricted to 256 iterations per pass [S2].
*   **Iteration Limit:** Determined by the number of rendering passes generated by the CPU [S3, unofficial].

**Numbered Steps:**
1.  **Ray Setup:** The application generates a polygon that covers the screen area, which generates a fragment for each pixel from which a ray must be launched [S3, unofficial].
2.  **Initial Intersection:** Find the initial intersection of the ray with the volume bounding box [S2].
3.  **Fragment Shader Execution:** For each fragment, execute a fragment program that calculates the volume rendering integral [S3, unofficial]. This calculation is iterative and relies on the optical model operators for accumulation [S3, unofficial].
4.  **Voxel Fetching:** Fetch subsequent voxels from the 3D texture map along the ray path at the current sampling position [S2].
5.  **Accumulation:** Update accumulated opacity and color values according to the chosen optical model [S2].
6.  **Advancement:** Advance the sampling position along the ray by the given step size [S2].
7.  **Termination Check:** Repeat steps 4-6 until the ray exits the volume or the iteration limit for the current pass is reached [S2].
8.  **Pass Management:** The iteration loop is managed at the CPU level [S3, unofficial]. The application generates as many rendering passes as there are iterations required to traverse the volume [S3, unofficial].
9.  **Ping-Pong Update:** Due to hardware limitations, simultaneous read and write access to textures in the same rendering pass is not supported [S3, unofficial]. A ping-pong technique is used: two copies of each 2D texture are maintained [S3, unofficial]. One is read, the other written, and their roles are inverted at each new pass [S3, unofficial].
10. **Optimizations:** Apply performance and quality enhancements such as empty space skipping using proxy geometries like bricks, spheres, or occlusion frustums [S1], and early ray termination using the z-buffer [S3, unofficial].

**Pseudocode:**
```python
# CPU-side loop management
# step_size is a fixed parameter provided by the application
# max_pass_iters is the hardware limit (e.g., 256)
num_iterations = ceil(volume_depth / step_size)
texture_read = allocate_2d_texture(screen_width, screen_height)
texture_write = allocate_2d_texture(screen_width, screen_height)
texture_read.clear(0, 0, 0, 0) # Initialize accumulated color/opacity
for i in range(num_iterations):
    if i % 2 == 0:
        read_tex = texture_read
        write_tex = texture_write
    else:
        read_tex = texture_write
        write_tex = texture_read
    render_pass(fragment_shader_code, volume_3d_tex, read_tex, write_tex, step_size, max_pass_iters)
final_image = texture_write if num_iterations % 2 != 0 else texture_read

# Fragment Shader Logic (Conceptual)
# Inputs: ray_origin, ray_direction, volume_3d_tex, accumulated_color, accumulated_opacity, step_size, max_pass_iters
# Output: new_accumulated_color, new_accumulated_opacity

def fragment_shader(ray_origin, ray_direction, volume_3d_tex, accumulated_color, accumulated_opacity, step_size, max_pass_iters):
    # 1. Find initial intersection with volume bounding box
    # [G] Standard slab intersection algorithm; sources do not specify exact implementation
    t_min, t_max = intersect_bounding_box(ray_origin, ray_direction)
    
    if t_min > t_max:
        return accumulated_color, accumulated_opacity

    # 2. Initialize sampling position
    t = t_min
    iter_count = 0
    
    # 3. Iterative traversal (limited by hardware, e.g., 256 iterations)
    while t < t_max and iter_count < max_pass_iters:
        iter_count += 1
        
        # Check for early ray termination
        if accumulated_opacity >= 1.0:
            break
            
        # Check for empty space skipping (if implemented via proxy)
        # [G] Proxy geometry test; sources do not specify exact implementation
        if is_empty_space(t):
            t += step_size * skip_factor
            continue
            
        # Fetch voxel data
        voxel = sample_3d_texture(volume_3d_tex, ray_origin + t * ray_direction)
        density = voxel.density
        color = voxel.color
        
        # Update accumulation (standard front-to-back compositing)
        alpha = 1.0 - exp(-density * step_size)
        color_contrib = color * alpha
        new_accumulated_color = accumulated_color + color_contrib * (1.0 - accumulated_opacity)
        new_accumulated_opacity = accumulated_opacity + alpha * (1.0 - accumulated_opacity)
        
        # Advance position
        t += step_size
        
    return new_accumulated_color, new_accumulated_opacity
```

**Edge Cases and Pitfalls:**
*   **Iteration Limit:** Fragment programs lack recursion and have a restricted loop count (e.g., 256 iterations) [S2]. Volume traversal must be implemented using nested loops or, more commonly in this context, by managing the iteration loop at the CPU level via multiple rendering passes [S2][S3, unofficial].
*   **Read/Write Conflict:** Graphics hardware does not support simultaneous read and write access to textures in the same rendering pass [S3, unofficial]. This requires the ping-pong technique with two copies of each 2D texture [S3, unofficial].
*   **No Recursion:** Secondary rays for advanced shading (e.g., reflections) are difficult or impossible to implement due to the lack of recursion in fragment programs [S2].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of pixels and the number of sampling steps per ray, multiplied by the number of passes required [S2][S3, unofficial].
*   **Memory Complexity:** Requires storage for the 3D volume texture and two ping-pong 2D textures for accumulation [S3, unofficial].
*   **Measured Performance:** Less performant than implicit approaches based on 3D textures [S3, unofficial]. However, the quality differential tends to decrease with high-quality rendering techniques [S3, unofficial].
*   **Strengths:** Fully exploits the built-in parallelism of modern graphics boards [S2]. Simple to implement on consumer graphics hardware [S2].
*   **Limitations:** Lacks recursion and flexible loop structures compared to software ray tracing [S2]. Performance can be limited by the iteration count per pass and the overhead of multiple rendering passes [S2][S3, unofficial].
*   **When to use:** When leveraging the parallelism of consumer graphics hardware for volume rendering is desired, and when the volume can be traversed within the constraints of the fragment program loop limits or via CPU-managed passes [S2][S3, unofficial].
*   **When not to use:** When advanced shading requiring recursion (e.g., global illumination) is needed, or when higher performance is required and implicit methods are suitable [S2][S3, unofficial].

## Background
*   **Origin:** First presented by Stegmaier et al. in 2005 as an implementation of a rectilinear volume ray caster on modern consumer graphics boards [S2].
*   **History:** This technique emerged as graphics boards offered enough flexibility to implement ray casting on the GPU, specifically using fragment programs [S2]. It represents an explicit approach to volume rendering, contrasting with implicit methods based on 3D textures [S3, unofficial].
*   **Usage:** Used in scientific visualization and interactive volume rendering applications that run on consumer graphics hardware [S2].
