# Surface Distance Query

Also called: Closest Surface Query, Point-to-Mesh Distance Query

## Overview
Surface Distance Query finds the minimum Euclidean distance from a query point to any surface in a given list of surfaces, and optionally identifies the closest surface object [S1, unofficial]. It serves as the core geometric primitive for Signed Distance Field (SDF) sampling from meshes, enabling volume rendering techniques to determine occupancy and shading based on proximity to geometry [S1, unofficial]. Unlike global SDF generation which precomputes distances into a volume texture, this method performs a direct query against explicit surface representations, making it suitable for dynamic scenes or when memory constraints prohibit large volume textures [S1, unofficial].

## How it works
**Inputs:**
- `point`: A 3D coordinate $(x, y, z)$ in world space.
- `surfaces`: A list of surface objects, each providing a method to compute the signed distance from a point to that specific surface.

**Outputs:**
- `min_distance`: The scalar minimum distance to the nearest surface.
- `closest_surface`: The reference to the surface object that yielded `min_distance`.

**Data Structures:**
- `Surface`: An abstract interface or class containing a method `distance(p: Point3D) -> float`.
- `Point3D`: A structure with fields `x`, `y`, `z`.

**Algorithm:**
1. Initialize `min_distance` to a predefined maximum bound ($MAX\_DISTANCE$) and `closest_surface` to `null` [S1, unofficial].
2. Iterate through each `surface` in the `surfaces` list:
   a. Compute `d = surface.distance(point)` [S1, unofficial].
   b. If `d < min_distance`:
      i. Set `min_distance = d`.
      ii. Set `closest_surface = surface`.
3. Return `min_distance` and `closest_surface` [S1, unofficial].

**Parameters:**
- `MAX_DISTANCE`: The upper bound for distance initialization. A typical value is $2000.0$ [S1, unofficial].
- `MIN_DISTANCE`: A lower bound threshold often used in ray marching to terminate early, though not strictly part of the query logic itself, it defines the precision floor for intersection checks [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Empty List:** If `surfaces` is empty, the function returns `MAX_DISTANCE` and `null`. Implementers should handle this case explicitly to avoid null pointer exceptions when accessing `closest_surface` [S1, unofficial].
- **Precision:** Floating-point comparisons (`d < min_distance`) are subject to precision errors. For highly dense meshes, consider using a tolerance epsilon if exact equality is not required [G].
- **Performance:** This is a brute-force $O(N)$ search where $N$ is the number of surfaces. It does not use spatial acceleration structures (like BVH or Octrees) [S1, unofficial].

**Pseudocode:**
```python
def surface_distance_query(point, surfaces, max_distance=2000.0):
    """
    Finds the minimum distance from point to any surface in the list.
    
    Args:
        point: Point3D object with x, y, z attributes.
        surfaces: List of Surface objects, each having a distance(p) method.
        max_distance: Upper bound for initialization.
        
    Returns:
        tuple: (min_distance: float, closest_surface: Surface or None)
    """
    min_distance = max_distance
    closest_surface = None
    
    for surface in surfaces:
        # Compute distance to this specific surface
        d = surface.distance(point)
        
        # Update if closer surface found
        if d < min_distance:
            min_distance = d
            closest_surface = surface
            
    return min_distance, closest_surface
```

## Subtopics

### Two-Sided Distance Field Generation
An option for high-density meshes (like trees) where surfaces are made of masked materials with many holes (leaves/branches) that cannot be treated as solid surfaces [S2]. It generates distance fields for both sides of the geometry [S2]. This is chosen when visualizing vegetation or semi-transparent structures where the "inside" of the mesh is also relevant for lighting and shadowing [S2]. The pitfall is increased performance cost: enabling this makes the surface semi-transparent in the distance field representation, requiring more ray marching steps to find intersections compared to opaque surfaces [S2].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of surfaces in the list. Each surface is queried exactly once [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space, excluding the storage of the surface list itself [S1, unofficial].
- **Performance:** The method is computationally lightweight per query but scales linearly with the number of surfaces. It is suitable for scenes with a small number of distinct geometric objects or when surfaces are aggregated into a single complex mesh [S1, unofficial].
- **Strengths:** Simple to implement; no preprocessing required; works with dynamic geometry [S1, unofficial].
- **Limitations:** Slow for large numbers of surfaces; no spatial culling; precision depends on the underlying surface distance implementation [S1, unofficial].
- **When to use:** Small scenes, dynamic objects, or as a fallback when global SDFs are not available [S1, unofficial].
- **When not to use:** Large static scenes with many disjoint meshes, where spatial acceleration structures or precomputed SDF volumes are preferred [S1, unofficial].

## Background
The concept of querying distances to surfaces is fundamental to ray marching and signed distance field rendering. The specific implementation described here, involving a linear scan over a list of surfaces with a fixed maximum distance bound, originates from educational ray marching shader implementations [S1, unofficial]. The broader context of distance fields, including two-sided generation for vegetation, is widely used in game engines like Unreal Engine for efficient global illumination and shadowing [S2].
