# Surface Distance Query

Also called: Minimum Surface Distance Query, Closest Surface Search

## Overview
A Surface Distance Query computes the minimum Euclidean distance from a given query point to a collection of geometric surfaces, optionally identifying the specific surface responsible for that minimum distance. It solves the problem of aggregating distance information from multiple disjoint or overlapping meshes into a single scalar value and a reference identifier. Unlike a Signed Distance Field (SDF) which provides a continuous approximation, this method performs an exact discrete search over explicit surface representations. It is distinct from [Ray-Triangle Intersection](52-ray-triangle-intersection.md) as it does not require a ray direction or camera position, but rather evaluates the point-to-surface metric directly.

## How it works
**Inputs:**
- `query_point`: A 3D point $(x, y, z)$ in world space.
- `surfaces`: A list of surface objects, each providing a method to compute the distance from a point to that surface.

**Outputs:**
- `min_distance`: The smallest distance found among all surfaces.
- `closest_surface`: The surface object corresponding to `min_distance`.

**Data Structures:**
- `surfaces`: An array or list of objects. Each object must implement a `distance(p)` method returning the scalar distance from point `p` to the surface geometry.
- `min_distance`: Initialized to a large constant `MAX_DISTANCE`.
- `closest_surface`: Initialized to `null`.

**Algorithm:**
1. Initialize `min_distance` to `MAX_DISTANCE` and `closest_surface` to `null$.
2. Iterate through each `surface` in the `surfaces` list.
3. For each `surface`, compute `d = surface.distance(query_point)`.
4. If `d < min_distance`:
   - Update `min_distance = d`.
   - Update `closest_surface = surface`.
5. Return `min_distance` and `closest_surface`.

**Parameters:**
- `MAX_DISTANCE`: A sufficiently large value to represent "infinity" or "no intersection". In the reference implementation, this is `2000.0f` [S1, unofficial].
- `MIN_DISTANCE`: A lower bound threshold used in subsequent ray marching steps, not directly in the query itself, but relevant for context. Value: `0.2f` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Empty List:** If `surfaces` is empty, the function should return `MAX_DISTANCE` and `null`.
- **Precision:** Floating-point comparisons (`d < min_distance`) are subject to precision errors. For robust implementations, consider using a small epsilon if exact equality is required, though strict inequality is standard for finding the *minimum*.
- **Performance:** This is a linear scan $O(N)$ where $N$ is the number of surfaces. For large $N$, spatial partitioning (e.g., BVH) is required, but the basic query does not include such optimization.

**Pseudocode:**
```python
def surface_distance_query(query_point, surfaces, MAX_DISTANCE=2000.0):
    """
    Computes the minimum distance from query_point to any surface in the list.
    
    Args:
        query_point: tuple (x, y, z)
        surfaces: list of objects with a .distance(p) method
        MAX_DISTANCE: float, initial maximum distance
        
    Returns:
        tuple: (min_distance, closest_surface)
    """
    min_distance = MAX_DISTANCE
    closest_surface = None
    
    for surface in surfaces:
        # Compute distance to current surface
        d = surface.distance(query_point)
        
        # Check if this surface is closer
        if d < min_distance:
            min_distance = d
            closest_surface = surface
            
    return min_distance, closest_surface
```

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of surfaces in the list. Each surface requires one distance evaluation.
- **Memory Complexity:** $O(1)$ auxiliary space, excluding the storage of the surfaces themselves.
- **Strengths:** Simple to implement; exact distance calculation if the underlying surface distance method is exact; no preprocessing required.
- **Limitations:** Linear scaling makes it inefficient for scenes with many surfaces. Does not provide spatial acceleration.
- **When to use:** Small number of surfaces; debugging; or as a fallback when no spatial index is available.
- **When not to use:** Large-scale scenes; real-time applications with many objects; where spatial coherence is needed.

## Background
The method is derived from basic ray-marching shader implementations where multiple surfaces are rendered in a single pass. The specific implementation details, including the constants `MAX_DISTANCE` (2000.0f) and `MIN_DISTANCE` (0.2f), originate from a Java-based ray-marching shader project [S1, unofficial]. The approach is a fundamental building block for composite distance fields in real-time rendering.
