# Triangle-Box Intersection Voxelization

Also called: Mesh Voxelization via SDF and Occupancy, Triangle-Point Distance Voxelization, Watertight Mesh Voxelization

## Overview
This method voxelizes watertight triangular meshes into Signed Distance Functions (SDFs) or occupancy grids by computing distances from voxel reference points to mesh faces or by testing for geometric intersection between triangles and voxel boxes [S1, unofficial]. It distinguishes itself from pure SDF-based occupancy derivation by using explicit triangle-box intersection tests to guarantee that any voxel intersecting the mesh surface is marked as occupied, avoiding voxels that might be missed by SDF-only approaches [S1, unofficial]. It builds on [Point-Triangle Distance](2776-point-triangle-distance.md) for SDF computation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A watertight triangular mesh in OFF format (or a directory of such files) [S1, unofficial].
- **Output:** An HDF5 tensor of shape $N \times C \times H \times W \times D$ (or $C \times H \times W \times D$ for a single file), where $N$ is the number of input meshes, $C=2$ is the number of channels, $H$ is height (y-axis), $W$ is width (x-axis), and $D$ is depth (z-axis) [S1, unofficial].
- **Optional Output:** If the `--color` flag is set, an additional `[int]_color.h5` file stores original face colors, indexed by face IDs stored in the occupancy grid [S1, unofficial].

**Data Structures:**
- **Voxel Grid:** A 3D array indexed by $(h, w, d)$ corresponding to spatial coordinates [S1, unofficial].
- **Mesh Representation:** A list of triangles, each defined by 3 vertices $(x, y, z)$ [S1, unofficial].
- **HDF5 Tensor:** Dimensions $[N, C, H, W, D]$ [S1, unofficial]. $C=2$ holds SDF sign/distance or occupancy/color data [S1, unofficial]. Values are signed distances in SDF mode, or $0$/face IDs in occupancy mode [S1, unofficial].

**Formulas:**
- Voxel size: $\Delta x = \frac{1}{W}$, $\Delta y = \frac{1}{H}$, $\Delta z = \frac{1}{D}$ [S1, unofficial].
- Voxel bounds for index $(h, w, d)$: $x \in [w\Delta x, (w+1)\Delta x]$, $y \in [h\Delta y, (h+1)\Delta y]$, $z \in [d\Delta z, (d+1)\Delta z]$ [S1, unofficial].
- Voxel center: $c_x = (w+0.5)\Delta x$, $c_y = (h+0.5)\Delta y$, $c_z = (d+0.5)\Delta z$ [S1, unofficial].
- SDF sign: $d_{signed} = -d_{min}$ if point is interior, $d_{signed} = d_{min}$ if exterior [S1, unofficial].

**Parameters:**
- `--mode`: `'occ'` (default) or `'sdf'` [S1, unofficial].
- `--height`, `--width`, `--depth`: Resolution $H, W, D$. Default $32 \times 32 \times 32$ [S1, unofficial].
- `--center`: Boolean. If set, use voxel centers for SDF computation; otherwise, use voxel corners (default) [S1, unofficial].
- `--color`: Boolean. If set, store face IDs in occupancy grid and save colors to a separate file [S1, unofficial].

**Numbered Steps:**
1. **Preprocessing and Scaling:** Load the input mesh [S1, unofficial]. Normalize the mesh to $[-0.5, 0.5]^3$ [S1, unofficial]. Scale and translate the mesh to fit the volume bounds $[0, H] \times [0, W] \times [0, D]$ [S1, unofficial]. The coordinate system assumes $x=$ right, $y=$ up, $z=$ forward [S1, unofficial]. The output volume maps $H \to y$, $W \to x$, $D \to z$ [S1, unofficial].
2. **Voxelization Loop:** Iterate over each voxel $(h, w, d)$ in the grid [S1, unofficial]. Determine the reference point $P$: if `--center` is false, $P$ is the voxel corner (e.g., top-left-front); if true, $P$ is the voxel center [S1, unofficial].
   - If `--mode` is `'sdf'`: Compute the distance from $P$ to the nearest triangle face using the triangle-point distance algorithm [S1, unofficial]. Determine the sign: negative if $P$ is inside the mesh, positive if outside [S1, unofficial]. Store the signed distance in the output tensor [S1, unofficial].
   - If `--mode` is `'occ'`: Perform a triangle-box intersection test between the voxel box (defined by center and half-size) and all mesh triangles [S1, unofficial]. If any intersection is detected, mark the voxel as occupied [S1, unofficial]. If `--color` is set, store the ID of the intersecting face instead of a simple binary 1 [S1, unofficial].
3. **Output Generation:** Save the resulting tensor to an HDF5 file [S1, unofficial]. If `--color` is set, save the face colors to `[int]_color.h5` [S1, unofficial].

**Pseudocode:**

import math

def voxelize_mesh(mesh_triangles, height, width, depth, mode='occ', use_center=False, color=False):
    # Initialize output tensor: N=1, C=2, H, W, D
    output_tensor = [[[[[0.0 for _ in range(depth)] for _ in range(width)] for _ in range(height)] for _ in range(2)] for _ in range(1)]
    color_data = {}
    
    dx, dy, dz = 1.0 / width, 1.0 / height, 1.0 / depth
    
    for h in range(height):
        for w in range(width):
            for d in range(depth):
                # Voxel bounds in world space [0, H]x[0, W]x[0, D]
                # y maps to h, x maps to w, z maps to d
                min_y, max_y = h * dy, (h + 1) * dy
                min_x, max_x = w * dx, (w + 1) * dx
                min_z, max_z = d * dz, (d + 1) * dz
                
                center_y = (min_y + max_y) / 2.0
                center_x = (min_x + max_x) / 2.0
                center_z = (min_z + max_z) / 2.0
                
                half_y, half_x, half_z = dy / 2.0, dx / 2.0, dz / 2.0
                
                if use_center:
                    ref_point = (center_x, center_y, center_z)
                    voxel_center = (center_x, center_y, center_z)
                    voxel_half = (half_x, half_y, half_z)
                else:
                    ref_point = (min_x, min_y, min_z)
                    voxel_center = (center_x, center_y, center_z)
                    voxel_half = (half_x, half_y, half_z)
                
                if mode == 'sdf':
                    min_dist = float('inf')
                    for tri in mesh_triangles:
                        dist = point_triangle_distance(ref_point, tri)
                        if dist < min_dist:
                            min_dist = dist
                    
                    # Determine sign: inside if ray from ref_point intersects odd number of triangles [G]
                    is_inside = ray_cast_intersection(ref_point, mesh_triangles)
                    signed_dist = -min_dist if is_inside else min_dist
                    output_tensor[0][0][h][w][d] = signed_dist
                    
                elif mode == 'occ':
                    is_occupied = False
                    intersecting_face_id = -1
                    for tri_idx, tri in enumerate(mesh_triangles):
                        if tri_box_overlap(voxel_center, voxel_half, tri):
                            is_occupied = True
                            if color:
                                intersecting_face_id = tri_idx
                                break
                    if is_occupied:
                        if color:
                            output_tensor[0][0][h][w][d] = intersecting_face_id
                            if intersecting_face_id not in color_data:
                                color_data[intersecting_face_id] = get_face_color(tri_idx)
                        else:
                            output_tensor[0][0][h][w][d] = 1.0
                    else:
                        output_tensor[0][0][h][w][d] = 0.0
    return output_tensor, color_data

def point_triangle_distance(p, tri):
    # Standard point-triangle distance using barycentric coordinates [G]
    v0, v1, v2 = tri
    edge1 = (v1[0]-v0[0], v1[1]-v0[1], v1[2]-v0[2])
    edge2 = (v2[0]-v0[0], v2[1]-v0[1], v2[2]-v0[2])
    diff = (p[0]-v0[0], p[1]-v0[1], p[2]-v0[2])
    a = edge1[0]**2 + edge1[1]**2 + edge1[2]**2
    b = edge1[0]*edge2[0] + edge1[1]*edge2[1] + edge1[2]*edge2[2]
    c = edge2[0]**2 + edge2[1]**2 + edge2[2]**2
    d = edge1[0]*diff[0] + edge1[1]*diff[1] + edge1[2]*diff[2]
    e = edge2[0]*diff[0] + edge2[1]*diff[1] + edge2[2]*diff[2]
    D = a*c - b*b
    s = (b*e - c*d) / D
    t = (a*e - b*d) / D
    if s + t <= 1:
        if s < 0: s = 0
        if t < 0: t = 0
        if s + t > 1:
            if d < 0: s = 0
            elif e < 0: t = 0
            else:
                num = b - d
                den = a - 2*b + c
                if num/den >= 0: s = num/den
                else: s = 0
            t = 1 - s
        q = (diff[0] - s*edge1[0] - t*edge2[0])**2 + (diff[1] - s*edge1[1] - t*edge2[1])**2 + (diff[2] - s*edge1[2] - t*edge2[2])**2
        return math.sqrt(q)
    if s < 0: s = 0
    if t < 0: t = 0
    if s + t > 1:
        if d < 0: s = 0
        elif e < 0: t = 0
        else:
            num = b - d
            den = a - 2*b + c
            if num/den >= 0: s = num/den
            else: s = 0
        t = 1 - s
    q = (diff[0] - s*edge1[0] - t*edge2[0])**2 + (diff[1] - s*edge1[1] - t*edge2[1])**2 + (diff[2] - s*edge1[2] - t*edge2[2])**2
    return math.sqrt(q)

def tri_box_overlap(center, half_size, tri):
    # Axis-aligned bounding box overlap test [G]
    v0, v1, v2 = tri
    min_tri = (min(v0[0], v1[0], v2[0]), min(v0[1], v1[1], v2[1]), min(v0[2], v1[2], v2[2]))
    max_tri = (max(v0[0], v1[0], v2[0]), max(v0[1], v1[1], v2[1]), max(v0[2], v1[2], v2[2]))
    min_box = (center[0]-half_size[0], center[1]-half_size[1], center[2]-half_size[2])
    max_box = (center[0]+half_size[0], center[1]+half_size[1], center[2]+half_size[2])
    if min_tri[0] > max_box[0] or max_tri[0] < min_box[0]: return False
    if min_tri[1] > max_box[1] or max_tri[1] < min_box[1]: return False
    if min_tri[2] > max_box[2] or max_tri[2] < min_box[2]: return False
    return True

**Edge Cases and Pitfalls:**
- **Non-watertight Meshes:** The method assumes watertight meshes [S1, unofficial]. Non-watertight meshes may produce incorrect SDFs (no negative values) or occupancy [S1, unofficial]. Simplification using a semi-convex hull algorithm is suggested but is crude [S1, unofficial].
- **Coordinate System Mismatch:** The input OFF files assume $x=$ right, $y=$ up, $z=$ forward [S1, unofficial]. The output volume maps height ($y$) to the first dimension, width ($x$) to the second, and depth ($z$) to the third [S1, unofficial].
- **SDF Reference Point:** The choice between voxel corner and center affects the marching cubes implementation used for conversion [S1, unofficial]. Standard marching cubes (e.g., PyMCubes) expect corner-based SDFs [S1, unofficial].

## Subtopics

### [Mesh SDF Sampling](7159-mesh-sdf-sampling.md)
Samples SDF values from a mesh. Chosen when continuous distance fields are needed for smooth interpolation or gradient-based optimization, rather than discrete voxel occupancy.

### [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md)
Computes the distance to the nearest triangle without sign. Chosen when interior/exterior distinction is not required, or for collision detection where only proximity matters.

## Operating characteristics
- **Time Complexity:** $O(V \cdot T)$, where $V$ is the number of voxels ($H \times W \times D$) and $T$ is the number of triangles [S1, unofficial]. Naive implementation checks all triangles for all voxels [S1, unofficial].
- **Memory Complexity:** $O(H \times W \times D)$ for the output grid [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Resolution defaults to $32^3$ [S1, unofficial]. Higher resolutions (e.g., $64^3$) improve reconstruction quality [S1, unofficial].
- **Strengths:** Guarantees watertight occupancy via explicit intersection tests [S1, unofficial]. Supports color preservation [S1, unofficial]. Simple to implement using existing geometric primitives [S1, unofficial].
- **Limitations:** Requires watertight input [S1, unofficial]. Naive implementation is slow for high-resolution grids or complex meshes [S1, unofficial]. Coordinate system swaps can cause confusion [S1, unofficial].
- **When to use:** When a discrete, watertight representation of a mesh is needed for 3D shape completion or volumetric processing, especially when SDF-based occupancy is insufficient due to leakage [S1, unofficial].
- **When not to use:** For non-watertight meshes without preprocessing [S1, unofficial]. When continuous SDF gradients are needed for optimization [S1, unofficial]. When performance is critical and the mesh is highly complex [S1, unofficial].

## Background
The method was introduced by David Stutz and Andreas Geiger in 2018 at CVPR for the paper "Learning 3D Shape Completion from Laser Scan Data with Weak Supervision" [S1, unofficial]. It builds on prior work from 2017 on shape completion from bounding boxes [S1, unofficial]. The implementation is a parallel C++ tool that uses external libraries for triangle-point distance (christopherbatty/SDFGen) and triangle-box intersection (Tomas Akenine-Möller) [S1, unofficial].
