# Point-Triangle Distance

Also called: Closest Point on Triangle, Point to Triangle Distance, closestPointOnTriangleToPoint, pointToTriangleDistSqr

## Overview
Computes the closest point on a triangle to a query point and the squared distance between them [S1][S2, unofficial]. It solves the problem of finding the minimum Euclidean distance from a 3D point to a triangular surface patch, which is a fundamental primitive for signed distance field (SDF) generation, collision detection, and mesh sampling [S1][S2, unofficial][S5]. It sets itself apart from [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) by solving a minimization problem over the triangle's interior and boundary rather than finding a scalar parameter $t$ along a ray, and from [Triangle-Triangle Intersection Test](11175-triangle-triangle-intersection-test.md) by returning a metric and location rather than a boolean overlap result.

## How it works
**Inputs:**
- Triangle vertices $v_0, v_1, v_2 \in \mathbb{R}^3$.
- Query point $p \in \mathbb{R}^3$.

**Outputs:**
- Closest point $c \in \mathbb{R}^3$.
- Barycentric coordinates $t_0, t_1$ such that $c = v_0 + t_0(v_1 - v_0) + t_1(v_2 - v_0)$ [S1].
- Squared distance $d^2 = \|p - c\|^2$ [S1].

**Data Structures:**
- 3D vectors supporting dot product and arithmetic operations [S1].
- Scalar floating-point types for parameters [S1].

**Algorithm (Voronoi Region Decomposition):**
The method decomposes the space around the triangle into Voronoi regions associated with the face, edges, and vertices [S1][S2, unofficial]. It uses quadratic programming logic to determine which region contains the query point $p$ [S2, unofficial].

1.  **Compute Edge Vectors:**
    $$e_0 = v_1 - v_0$$
    $$e_1 = v_2 - v_0$$
    $$v_0' = v_0 - p$$

2.  **Compute Dot Products:**
    $$a = e_0 \cdot e_0$$
    $$b = e_0 \cdot e_1$$
    $$c = e_1 \cdot e_1$$
    $$d = e_0 \cdot v_0'$$
    $$e = e_1 \cdot v_0'$$

3.  **Compute Determinant and Parameters:**
    $$det = a \cdot c - b \cdot b$$
    $$s = b \cdot e - c \cdot d$$
    $$t = b \cdot d - a \cdot e$$

4.  **Determine Region:**
    The parameter $det$ is the squared area of the parallelogram spanned by $e_0$ and $e_1$. If $det$ is near zero, the triangle is degenerate.

    **Case A: Inside or on Edge/Vertex ($s + t < det$)**
    The closest point lies within the triangle's interior or on its boundary. Sub-cases determine if it is on a vertex or edge:
    -   If $s < 0$ and $t < 0$:

5.  **Compute Closest Point:**
    $$c = v_0 + s \cdot e_0 + t \cdot e_1$$
    $$t_0 = s, \quad t_1 = t$$

6.  **Compute Squared Distance:**
    $$d^2 = \|p - c\|^2$$

**Parameters:**
-   `Vec3T`: Any vector type supporting arithmetic and dot product [S1].
-   `RFSaturate(x)`: Clamps $x$ to $[0, 1]$ [S2, unofficial].

**Edge Cases and Pitfalls:**
-   **Degenerate Triangles:** Triangles with zero area (collinear or coincident vertices) are handled implicitly. The face-interior test fails, and the code falls through to the nearest edge or vertex result [S1].
-   **Precision:** Division by zero can occur if $a, c,$ or $a-2b+c$ are zero. These correspond to zero-length edges or degenerate configurations. Clamping or epsilon checks are required in implementation [G].

**Pseudocode:**
```python
def closest_point_on_triangle(v0, v1, v2, p):
    # Edge vectors
    e0 = v1 - v0
    e1 = v2 - v0
    v0_prime = v0 - p
    
    # Dot products
    a = dot(e0, e0)
    b = dot(e0, e1)
    c = dot(e1, e1)
    d = dot(e0, v0_prime)
    e = dot(e1, v0_prime)
    
    # Determinant
    det = a * c - b * b
    
    # Parameters
    s = b * e - c * d
    t = b * d - a * e
    
    # Clamp helper
    def clamp(val, min_val, max_val):
        return max(min_val, min(val, max_val))
    
    # Region determination
    if s + t < det:
        if s < 0 and t < 0:
            if d < 0:
                s = clamp(-d / a, 0.0, 1.0)
                t = 0.0
            else:
                s = 0.0
                t = clamp(-e / c, 0.0, 1.0)
        elif s < 0 and t >= 0:
            s = clamp(-d / a, 0.0, 1.0)
            t = 0.0
        elif s >= 0 and t < 0:
            s = 0.0
            t = clamp(-e / c, 0.0, 1.0)
        else:
            # Inside triangle
            pass
    else:
        # Outside edge opposite v0
        if s < 0:
            tmp0 = b + d
            tmp1 = c + e
            denom = a - 2 * b + c
            if tmp1 > tmp0:
                s = clamp((tmp1 - tmp0) / denom, 0.0, 1.0)
                t = 1.0 - s
            else:
                s = 0.0
                t = clamp(-e / c, 0.0, 1.0)
        elif s >= 0 and t < 0:
            if a + d > b + e:
                denom = a - 2 * b + c
                s = clamp((c + e - b - d) / denom, 0.0, 1.0)
                t = 1.0 - s
            else:
                s = clamp(-e / c, 0.0, 1.0)
                t = 0.0
        else:
            # Inside triangle (s+t >= det but s,t >= 0 implies inside if det > 0)
            # Note: Standard logic usually handles s>=0, t>=0, s+t<=det as inside.
            # If s+t >= det, it's outside. If s>=0 and t>=0 here, it's a boundary case.
            # The source [S2, unofficial] structure implies this block is only for s<0 or (s>=0 and t<0).
            # If s>=0 and t>=0 and s+t>=det, it's technically outside the triangle 
            # but the logic flow in [S2, unofficial] might not cover this explicitly if it falls through.
            # However, s+t >= det with s,t >= 0 is outside the triangle region defined by barycentric coords.
            # We assume the previous if/elif covers the relevant outside cases.
            pass
            
    # Compute closest point
    closest = v0 + s * e0 + t * e1
    
    # Barycentric coords
    t0 = s
    t1 = t
    
    # Squared distance
    dist_sq = dot(p - closest, p - closest)
    
    return closest, t0, t1, dist_sq
```

## Subtopics

### [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md)
Computes the unsigned distance from a query point to a triangle defined by three vertices $a, b, c$. It checks if the point projects inside the triangle to decide between computing the minimum edge distance or the plane distance.

### [Mesh SDF Sampling](7159-mesh-sdf-sampling.md)
Mesh SDF Sampling constructs a callable signed distance field (SDF) sampler function from a `THREE.BufferGeometry` instance and a world transform matrix. It solves the problem of efficiently evaluating the shortest signed distance from arbitrary world-space coordinates to a triangle mesh surface, where negative values indicate interior points and positive values indicate exterior points. It differs from generic geometry samplers by specifically handling the `THREE.Mesh` abstraction, including automatic world matrix updates, and delegates the core geometric computation to a lower-level geometry sampler.

### [Triangle-Box Intersection Voxelization](7408-triangle-box-intersection-voxelization.md)
This method voxelizes watertight triangular meshes into Signed Distance Functions (SDFs) or occupancy grids by computing the distance from voxel reference points to mesh faces or by testing for geometric intersection between triangles and voxel boxes. It distinguishes itself from pure SDF-based occupancy derivation by using explicit triangle-box intersection tests to guarantee that any voxel intersecting the mesh surface is marked as occupied, avoiding the "leaky" voxels common in SDF-only approaches. It builds on [Point-Triangle Distance](2776-point-triangle-distance.md) for SDF computation and relies on [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md) concepts for spatial proximity checks.

### [Barycentric Coordinate Calculation](11142-barycentric-coordinate-calculation.md)
Computes the barycentric coordinates of a 3D point relative to a triangle defined by three vertices. It solves the problem of expressing a point's position within a triangle's local coordinate system, which is a prerequisite for [Point-Triangle Distance](2776-point-triangle-distance.md). It sets itself apart from sibling methods by focusing on the geometric projection and area-based calculation rather than distance minimization or mesh sampling.
#### Unsigned Quadrilateral Distance
Computes the unsigned distance from a point to a quadrilateral defined by four vertices $a, b, c, d$ [S3, unofficial]. It checks if the point is inside the projected quad to decide between edge distance and plane distance [S3, unofficial]. If the point is inside the quad (sum of signs < 3), return the minimum squared distance to the four edges. Otherwise, return the squared distance to the plane containing the quad [S3, unofficial]. Formula: $dot2(v) = v \cdot v$. Edge distance uses projection: $\text{proj}_{ba}(pa) = ba \cdot \text{clamp}(\frac{ba \cdot pa}{\|ba\|^2}, 0, 1)$ [S3, unofficial]. Parameters: $a, b, c, d \in \mathbb{R}^3$ [S3, unofficial].
#### Triangle Coverage Test
A test to verify if a triangle $T$ is completely outside the volume defined by a set of empty spheres, ensuring the sampling of the initial volume is dense enough to create sphere intersections [S4]. The test fails (triangle not covered) if either of two cases is true: 1) one circle is disjoint from the other two, or 2) an intersection point of two circles lies inside $T$ and outside the third circle [S4]. The condition for a triangle $T$ with vertices $v_i$ ($i \in \{0, 1, 2\}$) to be completely outside the volume is: $\forall \mathbf{p} \in T, f(\mathbf{p}) > 0$. This is equivalent to checking that no point of $T$ lies outside the circles centered at its vertices: $\forall \mathbf{p} \in T, \exists i \in \{0, 1, 2\}, \|\mathbf{p} - \mathbf{v}_i\| < f(\mathbf{v}_i)$ [S4]. Pitfall: The test specifically checks for intersection points of two circles that lie inside the triangle but outside the third circle [S4].
#### Zero Set Initialization of Meshes
Initialization of closest points for triangle meshes operating on individual triangles without using edge or vertex adjacency information [S5]. For every triangle $T$: Compute bounding box $(x_{min}, y_{min}, z_{min})$ to $(x_{max}, y_{max}, z_{max})$. Reduce min coords by cell-width. Increase max coords by cell-width [S5]. For each sample $s$ in the adjusted bounding box: Compute $cp(s)$ on $T$. Record if $cp(s)$ lies on face, edge, or vertex. Let $\delta = \|cp(s)\|$. If $\delta \le \sqrt{3} \cdot \text{cell-width}$ and $\delta < d(s)$, place sample on zero set queue, set flag to prohibit duplication, and set $sn(s)$ [S5]. Sign computation for face closest point: sign is $\text{sign}(n' \cdot \vec{v})$, where $n'$ is triangle normal and $\vec{v}$ is vector from closest point to sample [S5]. Sign computation for edge closest point: compute dot products for both triangles sharing the edge. Take sign of the larger absolute dot product [S5]. Parameter: `cell-width` is distance between distance samples [S5]. Pitfall: Vertex closest point may be ambiguous if dot products have mixed signs. Mark sample as ambiguous, do not propagate sign. After transform, resolve ambiguity by assigning sign of majority of 26-neighbors [S5].

## Operating characteristics
- **Time Complexity:** $O(1)$ per triangle. The algorithm involves a fixed number of arithmetic operations and comparisons [S1][S2, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space [S1][S2, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Linear with the number of triangles when processing a mesh [S5].
- **Strengths:** Robust handling of degenerate triangles; provides barycentric coordinates for interpolation; efficient for single-query applications [S1][S2, unofficial].
- **Limitations:** Not optimized for batch processing of many points against the same triangle without vectorization; precision issues may arise with very small or very large coordinates [G].
- **When to use:** When the closest point on a specific triangle is needed for collision response, SDF evaluation, or mesh sampling [S1][S2, unofficial][S5].
- **When not to use:** When processing millions of points against a large mesh, spatial acceleration structures (BVH, Grid) should be used to cull triangles before applying this method [G].

## Background
Originated from Ericson's "Real-Time Collision Detection" (Sec. 5.1.5) [S1]. It is widely used in computer graphics for collision detection, physics simulation, and signed distance field generation [S1][S2, unofficial][S5]. The method is implemented in libraries such as OpenVDB [S1] and various voxelization tools [S2, unofficial].
