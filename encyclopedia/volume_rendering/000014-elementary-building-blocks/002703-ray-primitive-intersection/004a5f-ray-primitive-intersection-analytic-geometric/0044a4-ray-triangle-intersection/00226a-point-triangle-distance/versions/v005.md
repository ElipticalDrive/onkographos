# Point-Triangle Distance

Also called: Closest Point on Triangle, Point to Triangle Distance, closestPointOnTriangleToPoint, pointToTriangleDistSqr

## Overview
Computes the closest point on a triangle to a query point and returns the squared distance, using Voronoi-region decomposition to handle edge and vertex cases [S1][S2, unofficial]. It differs from [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) by solving for the minimum distance from a static point rather than the intersection of a ray, and from [Triangle-Triangle Intersection Test](11175-triangle-triangle-intersection-test.md) by providing a metric rather than a boolean overlap result.

## How it works
**Inputs:** Triangle vertices $v_0, v_1, v_2$ (3D vectors); query point $p$ (3D vector).
**Outputs:** Closest point $cp$ on the triangle; barycentric coordinates $t_0, t_1$ such that $cp = v_0 + t_0(v_1 - v_0) + t_1(v_2 - v_0)$; squared distance $d^2 = \|p - cp\|^2$ [S1].

**Data Structures:**
- Vectors $v_0, v_1, v_2, p$: 3-component floating-point vectors.
- Scalars $a, b, c, d, e, det, s, t$: Floating-point numbers.

**Steps:**
1. Compute edge vectors:
   $$edge0 = v_1 - v_0$$
   $$edge1 = v_2 - v_0$$
2. Compute vector from triangle vertex to query point:
   $$v0 = v_0 - p$$
3. Compute dot products:
   $$a = edge0 \cdot edge0$$
   $$b = edge0 \cdot edge1$$
   $$c = edge1 \cdot edge1$$
   $$d = edge0 \cdot v0$$
   $$e = edge1 \cdot v0$$
4. Compute determinant and barycentric parameters:
   $$det = a \cdot c - b \cdot b$$
   $$s = b \cdot e - c \cdot d$$
   $$t = b \cdot d - a \cdot e$$
5. Determine region:
   - If $s + t < det$: The closest point is inside the triangle or on an edge/vertex.
     - If $s < 0$ and $t < 0$:
       - If $d < 0$: $s = \text{clamp}(-d/a, 0, 1)$, $t = 0$.
       - Else: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$.
     - If $s < 0$ and $t \ge 0$: $s = \text{clamp}(-d/a, 0, 1)$, $t = 0$.
     - If $s \ge 0$ and $t < 0$: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$.
   - If $s + t \ge det$: The closest point is outside the edge opposite $v_0$.
     - If $s < 0$:
       - Let $tmp0 = b + d$, $tmp1 = c + e$.
       - If $tmp1 > tmp0$: $s = \text{clamp}((tmp1 - tmp0) / (a - 2b + c), 0, 1)$, $t = 1 - s$.
       - Else: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$.
     - If $s \ge 0$ and $t < 0$:
       - If $a + d > b + e$: $s = \text{clamp}((c + e - b - d) / (a - 2b + c), 0, 1)$, $t = 1 - s$.
       - Else: $s = \text{clamp}(-e/c, 0, 1)$, $t = 0$.
6. Compute closest point:
   $$cp = v_0 + s \cdot edge0 + t \cdot edge1$$
7. Compute squared distance:
   $$distSq = \|p - cp\|^2$$

**Parameters:**
- `Vec3T`: Any 3D vector type supporting arithmetic and dot product [S1].

**Pitfalls:**
- Degenerate triangles (zero area, collinear, or coincident vertices) are handled implicitly: the face-interior test fails, and the code falls through to the nearest edge or vertex result [S1].
- Division by zero in $a$ or $c$ if edges have zero length; clamping handles the numerator but the denominator must be non-zero. In degenerate cases where $a=0$ or $c=0$, the corresponding edge is a point, and the logic should default to vertex distance [G].

```python
def closest_point_on_triangle(v0, v1, v2, p):
    edge0 = v1 - v0
    edge1 = v2 - v0
    v0_vec = v0 - p
    
    a = dot(edge0, edge0)
    b = dot(edge0, edge1)
    c = dot(edge1, edge1)
    d = dot(edge0, v0_vec)
    e = dot(edge1, v0_vec)
    
    det = a * c - b * b
    s = b * e - c * d
    t = b * d - a * e
    
    if s + t < det:
        if s < 0 and t < 0:
            if d < 0:
                s = clamp(-d / a, 0, 1)
                t = 0
            else:
                s = 0
                t = clamp(-e / c, 0, 1)
        elif s < 0:
            s = clamp(-d / a, 0, 1)
            t = 0
        elif t < 0:
            s = 0
            t = clamp(-e / c, 0, 1)
        else:
            # Inside triangle
            pass
    else:
        if s < 0:
            tmp0 = b + d
            tmp1 = c + e
            denom = a - 2 * b + c
            if tmp1 > tmp0:
                s = clamp((tmp1 - tmp0) / denom, 0, 1)
                t = 1 - s
            else:
                s = 0
                t = clamp(-e / c, 0, 1)
        elif t < 0:
            if a + d > b + e:
                denom = a - 2 * b + c
                s = clamp((c + e - b - d) / denom, 0, 1)
                t = 1 - s
            else:
                s = clamp(-e / c, 0, 1)
                t = 0
        else:
            # On edge opposite v0
            pass
            
    cp = v0 + s * edge0 + t * edge1
    dist_sq = dot(p - cp, p - cp)
    return cp, s, t, dist_sq

def clamp(x, min_val, max_val):
    if x < min_val: return min_val
    if x > max_val: return max_val
    return x
```

## Subtopics

### [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md)
Computes the unsigned distance from a query point to a triangle defined by three vertices $a, b, c$. It checks if the point is inside the projected triangle to decide between edge distance and plane distance.

### [Mesh SDF Sampling](7159-mesh-sdf-sampling.md)
Mesh SDF Sampling creates a signed distance sampler function from a `THREE.BufferGeometry` and a world transform matrix, returning a function that computes the shortest signed distance to the mesh at any given world-space coordinate. Negative values indicate the point is inside the mesh, and positive values indicate it is outside.

### [Triangle-Box Intersection Voxelization](7408-triangle-box-intersection-voxelization.md)
This method voxelizes watertight triangular meshes into Signed Distance Functions (SDFs) or occupancy grids by computing the distance from voxel reference points to mesh faces or by testing for geometric intersection between triangles and voxel boxes. It distinguishes itself from pure SDF-based occupancy derivation by using explicit triangle-box intersection tests to guarantee that any voxel intersecting the mesh surface is marked as occupied, avoiding the "leaky" voxels common in SDF-only approaches. It builds on [Point-Triangle Distance](2776-point-triangle-distance.md) for SDF computation and relies on [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md) concepts for spatial proximity checks.

### Unsigned Quadrilateral Distance
Computes the unsigned distance from a point to a quadrilateral defined by four vertices $a, b, c, d$. It checks if the point is inside the projected quad to decide between edge distance and plane distance [S3, unofficial]. If the point is inside the quad (sum of signs < 3), return the minimum squared distance to the four edges. Otherwise, return the squared distance to the plane containing the quad. Edge distance uses projection: $\text{proj}_{ba}(pa) = ba \cdot \text{clamp}(\frac{ba \cdot pa}{\|ba\|^2}, 0, 1)$ [S3, unofficial].

### Barycentric Coordinate Calculation
Computes the barycentric coordinates of a point relative to a triangle defined by three vertices, by projecting the point onto the triangle's plane and calculating areas of sub-triangles [S4, unofficial]. If the point is not on the triangle's plane, it is projected onto the plane before area calculation. If the triangle is degenerate (area zero), division by zero occurs in the final normalization [S4, unofficial].

### Triangle Coverage Test
A test to verify if a triangle T is completely outside the volume defined by a set of empty spheres, ensuring the sampling of the initial volume is dense enough to create sphere intersections [S5]. The test fails (triangle not covered) if either of two cases is true: 1) one circle is disjoint from the other two, or 2) an intersection point of two circles lies inside T and outside the third circle [S5].

### Zero Set Initialization of Meshes
Initialization of closest points for triangle meshes operating on individual triangles without using edge or vertex adjacency information [S6]. For every triangle T, it computes a bounding box, adjusts it by cell-width, and for each sample s in the adjusted bounding box, computes the closest point cp(s) on T. If the distance is within a threshold, the sample is placed on a zero set queue. Sign computation depends on whether cp(s) lies on a face, edge, or vertex [S6].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Strengths:** Robust handling of all geometric cases (interior, edges, vertices) without branching on normal checks; handles degenerate triangles gracefully [S1].
- **Limitations:** Requires dot products and divisions; precision issues may arise with very small or very large coordinates [G].
- **When to use:** When the closest point on a triangle surface is needed for distance queries, collision response, or SDF computation.

## Background
Originated from Ericson's "Real-Time Collision Detection" (Sec. 5.1.5) [S1]. Implemented in OpenVDB's `nanovdb::math` namespace [S1] and various voxelization tools [S2, unofficial].
