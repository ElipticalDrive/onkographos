# Triangle Circum-Center Calculation

Also called: Circum-center, Circumcircle Center

## Overview
Computes the center and radius of the unique circle passing through the three vertices of a triangle. It serves as the geometric basis for defining bounding spheres in triangle-based volume rendering primitives, specifically within the [TetSplat](https://ken.museth.org/Publications_files/Museth-Lombeyda_VIS04.pdf) framework. It is distinguished from the [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md) method by providing a global bounding volume for the triangle rather than a point-to-surface distance metric.

## How it works
**Inputs:** Three vertices $a, b, c \in \mathbb{R}^3$.
**Outputs:** Circum-center $C$ and circum-radius $R$.

**Data Structures:**
No persistent data structures are required. The calculation is stateless.

**Steps:**
1.  **Check for Degeneracy:** Compute the cross product magnitude $|A(b, c)|$. If this value is near zero, the vertices are co-linear.
    *   *Pitfall:* The denominator in the main formula vanishes for degenerate triangles [S1, unofficial].
    *   *Handling:* If degenerate, the method is undefined or requires fallback logic not specified in the primary formula. The source notes that degenerate triangles are typically removed or collapsed prior to this step in the pipeline [S1, unofficial].
2.  **Check for Obtuseness:** Determine if the triangle is obtuse.
    *   *Handling:* If the triangle is obtuse, approximate the circum-center as the midpoint of the longest edge and the circum-radius as half the length of that edge [S1, unofficial]. This avoids numerical instability associated with large circum-radii for obtuse triangles.
3.  **Compute Relative Center:** For non-degenerate, non-obtuse triangles, calculate the relative circum-center $m_{tri}$ using the analytic formula.
4.  **Compute Absolute Center:** $C = a + m_{tri}$.
5.  **Compute Radius:** $R = |m_{tri}|$.

**Formula:**
Let $A(u, v) = (u - a) \times (v - a)$. The relative circum-center $m_{tri}$ is:

$$
m_{tri} = \frac{|c - a|^2 A(b, c) \times (b - a) + |b - a|^2 (c - a) \times A(b, c)}{2 |A(b, c)|^2}
$$

Where:
*   $| \cdot |$ denotes the Euclidean norm.
*   $\times$ denotes the cross product.
*   The denominator is $2 |A(b, c)|^2$.

**Pitfalls:**
*   **Numerical Stability:** The formula uses differences of coordinates ($u-a$), which reduces relative error compared to using absolute coordinates, as vertices are typically closer to each other than to the origin [S1, unofficial].
*   **Degeneracy:** The denominator vanishes when vertices are co-linear [S1, unofficial].

**Pseudocode:**

```python
import math
from typing import Tuple, List

def cross_product(u: List[float], v: List[float]) -> List[float]:
    return [
        u[1]*v[2] - u[2]*v[1],
        u[2]*v[0] - u[0]*v[2],
        u[0]*v[1] - u[1]*v[0]
    ]

def dot_product(u: List[float], v: List[float]) -> float:
    return u[0]*v[0] + u[1]*v[1] + u[2]*v[2]

def vector_sub(u: List[float], v: List[float]) -> List[float]:
    return [u[0]-v[0], u[1]-v[1], u[2]-v[2]]

def vector_norm_sq(u: List[float]) -> float:
    return dot_product(u, u)

def triangle_circum_center(a: List[float], b: List[float], c: List[float]) -> Tuple[List[float], float]:
    # Step 1: Compute vectors relative to a
    ab = vector_sub(b, a)
    ac = vector_sub(c, a)
    
    # Step 2: Compute A(b, c) = (b-a) x (c-a)
    # Note: Source defines A(u,v) = (u-a) x (v-a). 
    # Formula uses A(b,c). Let's compute A_bc = (b-a) x (c-a)
    A_bc = cross_product(ab, ac)
    
    # Check for degeneracy (co-linear vertices)
    denom_sq = 2.0 * vector_norm_sq(A_bc)
    if denom_sq < 1e-12: # Threshold for near-degeneracy [G]
        # Fallback for degenerate case not specified in source details, 
        # but source implies removal/collapse prior to this step.
        # Return a degenerate sphere or handle upstream.
        # For implementation completeness, return midpoint of longest edge as fallback [G]
        len_ab = math.sqrt(vector_norm_sq(ab))
        len_ac = math.sqrt(vector_norm_sq(ac))
        len_bc = math.sqrt(vector_norm_sq(vector_sub(c, b)))
        
        max_len = max(len_ab, len_ac, len_bc)
        if max_len == len_ab:
            center = [(a[0]+b[0])/2, (a[1]+b[1])/2, (a[2]+b[2])/2]
            radius = len_ab / 2.0
        elif max_len == len_ac:
            center = [(a[0]+c[0])/2, (a[1]+c[1])/2, (a[2]+c[2])/2]
            radius = len_ac / 2.0
        else:
            center = [(b[0]+c[0])/2, (b[1]+c[1])/2, (b[2]+c[2])/2]
            radius = len_bc / 2.0
        return center, radius

    # Step 3: Check for obtuse triangle
    # An obtuse triangle has an angle > 90 degrees.
    # We check dot products of edges.
    # Angle at a: dot(ab, ac)
    # Angle at b: dot(ba, bc) = dot(-ab, c-b)
    # Angle at c: dot(ca, cb) = dot(-ac, b-c)
    
    ba = vector_sub(a, b)
    bc = vector_sub(c, b)
    ca = vector_sub(a, c)
    cb = vector_sub(b, c)
    
    dot_a = dot_product(ab, ac)
    dot_b = dot_product(ba, bc)
    dot_c = dot_product(ca, cb)
    
    # If any dot product is negative, the angle is obtuse
    is_obtuse = (dot_a < 0) or (dot_b < 0) or (dot_c < 0)
    
    if is_obtuse:
        # Approximate circum-center as midpoint of longest edge
        len_ab = math.sqrt(vector_norm_sq(ab))
        len_ac = math.sqrt(vector_norm_sq(ac))
        len_bc = math.sqrt(vector_norm_sq(bc))
        
        max_len = max(len_ab, len_ac, len_bc)
        if max_len == len_ab:
            center = [(a[0]+b[0])/2, (a[1]+b[1])/2, (a[2]+b[2])/2]
            radius = len_ab / 2.0
        elif max_len == len_ac:
            center = [(a[0]+c[0])/2, (a[1]+c[1])/2, (a[2]+c[2])/2]
            radius = len_ac / 2.0
        else:
            center = [(b[0]+c[0])/2, (b[1]+c[1])/2, (b[2]+c[2])/2]
            radius = len_bc / 2.0
        return center, radius

    # Step 4: Compute relative circum-center m_tri
    # Formula: m_tri = ( |c-a|^2 * (A(b,c) x (b-a)) + |b-a|^2 * ((c-a) x A(b,c)) ) / (2 * |A(b,c)|^2)
    
    term1_vec = cross_product(A_bc, ab)
    term2_vec = cross_product(ac, A_bc)
    
    term1 = vector_norm_sq(ac) * term1_vec
    term2 = vector_norm_sq(ab) * term2_vec
    
    numerator = [
        term1[0] + term2[0],
        term1[1] + term2[1],
        term1[2] + term2[2]
    ]
    
    m_tri = [
        numerator[0] / denom_sq,
        numerator[1] / denom_sq,
        numerator[2] / denom_sq
    ]
    
    # Step 5: Absolute center and radius
    center = [
        a[0] + m_tri[0],
        a[1] + m_tri[1],
        a[2] + m_tri[2]
    ]
    
    radius = math.sqrt(vector_norm_sq(m_tri))
    
    return center, radius
```

## Subtopics

### Tetrahedron Circum-Center Calculation
Computes the center and radius of the sphere passing through four vertices $a, b, c, d$. It uses a determinant-based formula involving cross products of edge vectors. It is chosen when tetrahedral primitives are used instead of triangles. The formula is expressed in coordinate differences to minimize relative error [S1, unofficial]. It becomes unstable if the tetrahedron is nearly degenerate (flat or needle-shaped) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ constant time operations (vector arithmetic).
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Strengths:** Analytic solution avoids iterative approximation. Using coordinate differences improves numerical stability for vertices far from the origin [S1, unofficial].
*   **Limitations:** Numerically unstable for degenerate (co-linear) triangles. Obtuse triangles produce large circum-radii, which is why the source recommends a midpoint fallback for them [S1, unofficial].
*   **When to use:** When defining bounding spheres for triangle-based splats in volume rendering.
*   **When not to use:** For degenerate triangles or when a tighter bounding volume is required for obtuse triangles (use the midpoint fallback instead).

## Background
Originated in the TetSplat paper by Museth and Lombeyda (2004) for real-time rendering and volume clipping of large meshes. The method is cited from reference [19] in the original paper, which is not explicitly named in the provided text but is implied to be a standard geometric computation reference. It is used in the context of deriving leaf nodes for hierarchical volume representations from triangle meshes.
