# Möller-Trumbore Ray-Triangle Intersection

Also called: Möller-Trumbore, MT Algorithm, MT intersection, Ray-Triangle Intersection (Möller-Trumbore), Triangle-Ray Intersection (Möller-Trumbore), Moeller-Trumbore Ray-Triangle Intersection (Embree)

## Overview
The Möller-Trumbore algorithm computes the intersection of a ray with a triangle by solving for the parametric distance $t$ and barycentric coordinates $(u, v)$ directly, avoiding the explicit calculation of the triangle's plane equation [S3, unofficial][S11, unofficial]. It translates the ray origin and changes the vector basis to yield a vector $(t, u, v)^T$, minimizing storage requirements and computational overhead [S11, unofficial]. It operates directly in Cartesian space using cross and dot products [S8, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{O}$ (3D vector) [S1, unofficial][S3, unofficial][S9, unofficial]
- Ray direction $\mathbf{D}$ (3D vector) [S1, unofficial][S3, unofficial][S9, unofficial]
- Triangle vertices $\mathbf{V}_1, \mathbf{V}_2, \mathbf{V}_3$ (3D vectors) [S4, unofficial]
- Epsilon threshold $\epsilon$ for numerical stability (typically $10^{-6}$ to $10^{-7}$) [S1, unofficial][S3, unofficial][S4, unofficial][S9, unofficial]

**Outputs:**
- Intersection distance $t$ (scalar) [S1, unofficial][S3, unofficial][S9, unofficial]
- Barycentric coordinates $u, v$ (scalars) [S3, unofficial][S9, unofficial]
- Boolean success flag or `None`/`false` if no intersection [S5, unofficial][S9, unofficial]

**Data Structures:**
- Vectors $\mathbf{e}_1, \mathbf{e}_2, \mathbf{T}, \mathbf{pvec}, \mathbf{qvec}$ are 3D floating-point vectors [S1, unofficial][S3, unofficial][S9, unofficial]
- Scalars $det, inv\_det, u, v, t$ are floating-point numbers [S9, unofficial]

**Steps:**
1. Compute edge vectors of the triangle:
   $$ \mathbf{e}_1 = \mathbf{V}_2 - \mathbf{V}_1 $$
   $$ \mathbf{e}_2 = \mathbf{V}_3 - \mathbf{V}_1 $$ [S1, unofficial][S3, unofficial][S9, unofficial]
2. Compute the vector from $\mathbf{V}_1$ to the ray origin:
   $$ \mathbf{T} = \mathbf{O} - \mathbf{V}_1 $$ [S1, unofficial][S3, unofficial][S9, unofficial]
3. Compute the cross product of the ray direction and the second edge:
   $$ \mathbf{pvec} = \mathbf{D} \times \mathbf{e}_2 $$ [S3, unofficial][S9, unofficial]
4. Compute the determinant of the system:
   $$ det = \mathbf{e}_1 \cdot \mathbf{pvec} $$ [S3, unofficial][S9, unofficial]
5. Check for parallelism:
   - If $|det| < \epsilon$, the ray is parallel to the triangle plane (or lies in it). Return no intersection [S1, unofficial][S3, unofficial][S6, unofficial][S7, unofficial][S9, unofficial].
   - Compute the inverse determinant:
     $$ inv\_det = 1.0 / det $$ [S3, unofficial][S9, unofficial]
6. Compute the first barycentric coordinate $u$:
   $$ u = (\mathbf{T} \cdot \mathbf{pvec}) \times inv\_det $$ [S1, unofficial][S3, unofficial][S9, unofficial]
   - If $u < 0.0$ or $u > 1.0$, the intersection point lies outside the triangle edge. Return no intersection [S1, unofficial][S3, unofficial][S6, unofficial][S7, unofficial][S9, unofficial].
7. Compute the cross product of $\mathbf{T}$ and the first edge:
   $$ \mathbf{qvec} = \mathbf{T} \times \mathbf{e}_1 $$ [S3, unofficial][S9, unofficial]
8. Compute the second barycentric coordinate $v$:
   $$ v = (\mathbf{D} \cdot \mathbf{qvec}) \times inv\_det $$ [S1, unofficial][S3, unofficial][S9, unofficial]
   - If $v < 0.0$ or $u + v > 1.0$, the intersection point lies outside the triangle. Return no intersection [S1, unofficial][S3, unofficial][S6, unofficial][S7, unofficial][S9, unofficial].
9. Compute the intersection distance $t$:
   $$ t = (\mathbf{e}_2 \cdot \mathbf{qvec}) \times inv\_det $$ [S3, unofficial][S9, unofficial]
   - If $t < \epsilon$ (or $t \le 0$), the intersection is behind the ray origin or at the origin. Return no intersection [S6, unofficial][S9, unofficial].
10. Return success with $t, u, v$. [S3, unofficial][S9, unofficial]

**Pseudocode:**
```python
def muller_trumbore(ray_origin, ray_direction, v1, v2, v3, epsilon=1e-7):
    # Step 1: Edge vectors
    e1 = v2 - v1
    e2 = v3 - v1
    
    # Step 2: Vector from V1 to ray origin
    t_vec = ray_origin - v1
    
    # Step 3: Cross product of ray direction and second edge
    p_vec = cross(ray_direction, e2)
    
    # Step 4: Determinant
    det = dot(e1, p_vec)
    
    # Step 5: Check for parallelism
    if abs(det) < epsilon:
        return None
        
    inv_det = 1.0 / det
    
    # Step 6: Compute u
    u = dot(t_vec, p_vec) * inv_det
    if u < 0.0 or u > 1.0:
        return None
        
    # Step 7: Cross product of t_vec and first edge
    q_vec = cross(t_vec, e1)
    
    # Step 8: Compute v
    v = dot(ray_direction, q_vec) * inv_det
    if v < 0.0 or (u + v) > 1.0:
        return None
        
    # Step 9: Compute t
    t = dot(e2, q_vec) * inv_det
    if t < epsilon:
        return None
        
    return {'t': t, 'u': u, 'v': v}
```

**Edge Cases and Pitfalls:**
- **Parallel Rays:** If the determinant is near zero, division by zero occurs. The check $|det| < \epsilon$ prevents this [S1, unofficial][S3, unofficial][S6, unofficial][S7, unofficial][S9, unofficial].
- **Degenerate Triangles:** If the triangle vertices are collinear, the area is zero, and the determinant may be zero or near-zero [G].
- **Back-Facing Triangles:** The algorithm returns intersections for both front and back faces [S10, unofficial].
- **Numerical Precision:** Using a small epsilon is critical for robustness, especially when rays align with mesh vertices or edges [S1, unofficial][S3, unofficial].

## Subtopics

### [Ray Origin Jitter for Mesh Voxelization](15322-ray-origin-jitter-for-mesh-voxelization.md)
Eliminates vertical slice artifacts in mesh voxelization by introducing a small, direction-aware offset to ray origins before performing ray-triangle intersection tests. It specifically addresses numerical instability in the Möller-Trumbore algorithm when rays align exactly with mesh vertices or edges, a common issue in meshes with regular grid topology such as terrain height maps. Unlike alternative approaches that bypass ray-tracing entirely (e.g., using Signed Distance Fields), this technique preserves the geometric fidelity of the original mesh while ensuring robust intersection detection.

## Operating characteristics
- **Time Complexity:** $O(1)$ per triangle [G].
- **Memory Complexity:** $O(1)$ auxiliary space [G].
- **Performance:** It is considered one of the fastest ray-triangle intersection routines for triangles without precomputed plane equations [S11, unofficial]. Optimized variants exist that delay division or handle sign checks differently, but the core logic remains the same [S3, unofficial].
- **Strengths:** Minimal storage, no need to compute plane equations, robust handling of barycentric coordinates directly [S3, unofficial][S10, unofficial].
- **Limitations:** Does not inherently handle back-face culling (requires caller intervention) [S9, unofficial].

## Background
The algorithm was introduced by Tomas Möller and Ben Trumbore in 1997 in the paper "Fast, Minimum Storage Ray/Triangle Intersection" [S1, unofficial][S8, unofficial]. It is widely used in volume rendering for mesh voxelization and ray-triangle intersection tests [S1, unofficial][S7, unofficial][S8, unofficial].
