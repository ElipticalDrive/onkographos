# Triangle-Triangle Intersection Test
Also called: SAT Triangle Intersection, Separating Axis Theorem (SAT) for Triangles, testIntersection

## Overview
The Triangle-Triangle Intersection Test determines whether two triangles in 3D space share any common points, returning true if they intersect and false otherwise [S1, S2, S3, unofficial]. It solves the problem of detecting collisions between triangular primitives without computing the intersection polygon, which is computationally expensive. What sets this method apart from its siblings, such as [General Ray-Triangle Intersection (Plücker Coordinates)](909-general-ray-triangle-intersection-pl-cker-coordinates.md) which tests ray-primitive overlap, is that it operates directly on two planar polygons using the Separating Axis Theorem (SAT) [S1, S2, S3, unofficial]. Unlike [Point-Triangle Distance](2776-point-triangle-distance.md) which measures proximity, this method provides a binary boolean result for full overlap [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Triangle $T_1$ defined by vertices $v_{1,0}, v_{1,1}, v_{1,2} \in \mathbb{R}^3$.
*   Triangle $T_2$ defined by vertices $v_{2,0}, v_{2,1}, v_{2,2} \in \mathbb{R}^3$.

**Output:**
*   Boolean: `true` if the triangles intersect, `false` otherwise.

### Data Structures
The triangles are represented as arrays of 3D coordinates.
*   `Triangle`: An array of 3 vertices, where each vertex is a 3-component float vector $(x, y, z)$.
*   `Vector3`: A 3-component float vector.

### Steps
1.  **Compute Edge Vectors:**
    For each triangle $T_i$ ($i \in \{1, 2\}$), compute the three edge vectors:
    $$
    e_{i,0} = v_{i,1} - v_{i,0}
    $$
    $$
    e_{i,1} = v_{i,2} - v_{i,1}
    $$
    $$
    e_{i,2} = v_{i,0} - v_{i,2}
    $$

2.  **Compute Face Normals:**
    Compute the unnormalized face normal for each triangle using the cross product of two edges:
    $$
    n_1 = e_{1,0} \times e_{1,1}
    $$
    $$
    n_2 = e_{2,0} \times e_{2,1}
    $$
    [S1, S3, unofficial]

3.  **Check for Co-planarity:**
    Compute the cross product of the two face normals:
    $$
    n = n_1 \times n_2
    $$
    If $n$ is the zero vector (i.e., $|n_x| < \epsilon, |n_y| < \epsilon, |n_z| < \epsilon$ for a small tolerance $\epsilon$, typically $10^{-5}$ or $10^{-6}$ depending on implementation [S1, S2, unofficial]), the triangles are co-planar.
    
    *   **If Co-planar:**
        1.  Check if the triangles lie in the same plane. Compute the dot product of $n_1$ with a vertex from each triangle (e.g., $d_1 = n_1 \cdot v_{1,0}$ and $d_2 = n_1 \cdot v_{2,0}$). If $|d_1 - d_2| > \epsilon$, the planes are distinct and the triangles do not intersect. Return `false`. [S3, unofficial]
        2.  If they are in the same plane, test separation along the 6 edge normals: $n_1 \times e_{1,i}$ for $i \in \{0,1,2\}$ and $n_2 \times e_{2,i}$ for $i \in \{0,1,2\}$. [S1, S3, unofficial]
        3.  For each axis, project both triangles and check for overlap. If any axis separates them, return `false`.
        4.  If no axis separates them, return `true`. [S1, S3, unofficial]
        
        *Note: Some implementations (e.g., BBox overloads) explicitly treat co-planar triangles as non-intersecting as a hack to avoid degenerate cases [S1, S2, S3, unofficial].*

    *   **If Non-Co-planar:**
        1.  Test separation along the face normals $n_1$ and $n_2$. If either axis separates the triangles, return `false`. [S1, S3, unofficial]
        2.  Test separation along the 9 edge-edge cross products: $e_{1,i} \times e_{2,j}$ for $i \in \{0,1,2\}$ and $j \in \{0,1,2\}$. [S1, S3, unofficial]
        3.  For each axis, project both triangles and check for overlap. If any axis separates them, return `false`.
        4.  If no axis separates them, return `true`. [S1, S3, unofficial]

4.  **Projection and Separation Check:**
    For a given axis $A$, project the vertices of $T_1$ and $T_2$ onto $A$ to find the minimum and maximum scalar values.
    $$
    \text{min}_1 = \min_{k \in \{0,1,2\}} (A \cdot v_{1,k}), \quad \text{max}_1 = \max_{k \in \{0,1,2\}} (A \cdot v_{1,k})
    $$
    $$
    \text{min}_2 = \min_{k \in \{0,1,2\}} (A \cdot v_{2,k}), \quad \text{max}_2 = \max_{k \in \{0,1,2\}} (A \cdot v_{2,k})
    $$
    The triangles are separated on axis $A$ if:
    $$
    \text{min}_1 \ge \text{max}_2 \quad \text{or} \quad \text{min}_2 \ge \text{max}_1
    $$
    [S2, unofficial]
    
    *Numerical Stability:* To handle floating-point inaccuracies, a small epsilon tolerance is often added to the separation check. For example:
    $$
    \text{min}_1 > \text{max}_2 + \epsilon \quad \text{or} \quad \text{min}_2 > \text{max}_1 + \epsilon
    $$
    where $\epsilon = 0.00001$ is used in some implementations [S2, S3, unofficial].

### Pseudocode

```python
def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def cross(v1, v2):
    return [
        v1[1]*v2[2] - v1[2]*v2[1],
        v1[2]*v2[0] - v1[0]*v2[2],
        v1[0]*v2[1] - v1[1]*v2[0]
    ]

def project(triangle, axis):
    # triangle is list of 3 vertices, each vertex is [x, y, z]
    min_val = dot(axis, triangle[0])
    max_val = min_val
    for i in range(1, 3):
        proj = dot(axis, triangle[i])
        if proj < min_val:
            min_val = proj
        if proj > max_val:
            max_val = proj
    return min_val, max_val

def triangles_intersect(t1, t2):
    # t1, t2 are lists of 3 vertices, each vertex is [x, y, z]
    
    # 1. Compute edge vectors
    e1 = [
        [t1[1][i] - t1[0][i] for i in range(3)],
        [t1[2][i] - t1[1][i] for i in range(3)],
        [t1[0][i] - t1[2][i] for i in range(3)]
    ]
    e2 = [
        [t2[1][i] - t2[0][i] for i in range(3)],
        [t2[2][i] - t2[1][i] for i in range(3)],
        [t2[0][i] - t2[2][i] for i in range(3)]
    ]
    
    # 2. Compute face normals
    n1 = cross(e1[0], e1[1])
    n2 = cross(e2[0], e2[1])
    
    # 3. Check for co-planarity
    n = cross(n1, n2)
    # Check if n is zero vector
    is_zero = (abs(n[0]) < 1e-6 and abs(n[1]) < 1e-6 and abs(n[2]) < 1e-6)
    
    if is_zero:
        # Co-planar case
        # Check if they are in the same plane
        # Plane equation for T1: n1 . (P - v1_0) = 0 => n1 . P = n1 . v1_0
        d1 = dot(n1, t1[0])
        d2 = dot(n1, t2[0])
        if abs(d1 - d2) > 1e-6:
            return False
        
        # Test 6 edge normals: cross(n1, e1[i]) and cross(n2, e2[i])
        axes = []
        for i in range(3):
            axes.append(cross(n1, e1[i]))
            axes.append(cross(n2, e2[i]))
            
        for axis in axes:
            min1, max1 = project(t1, axis)
            min2, max2 = project(t2, axis)
            # Separation check with epsilon
            if min1 > max2 + 1e-6 or min2 > max1 + 1e-6:
                return False
        return True
    else:
        # Non-co-planar case
        # Test face normals n1 and n2
        for axis in [n1, n2]:
            min1, max1 = project(t1, axis)
            min2, max2 = project(t2, axis)
            if min1 > max2 + 1e-6 or min2 > max1 + 1e-6:
                return False
        
        # Test 9 edge-edge cross products
        for i in range(3):
            for j in range(3):
                axis = cross(e1[i], e2[j])
                min1, max1 = project(t1, axis)
                min2, max2 = project(t2, axis)
                if min1 > max2 + 1e-6 or min2 > max1 + 1e-6:
                    return False
                    
        return True
```

### Parameters
*   **Epsilon ($\epsilon$):** A small floating-point tolerance used to handle numerical precision issues. Typical values are $10^{-5}$ or $10^{-6}$ [S1, S2, S3, unofficial].
*   **Zero Vector Tolerance:** Used to determine if the cross product of normals is effectively zero. Same order of magnitude as epsilon [S1, S3, unofficial].

### Edge Cases and Pitfalls
*   **Co-planar Triangles:** This is the most complex case. If the triangles are co-planar but in different planes (parallel but offset), they do not intersect. This is checked by comparing the dot product of the normal with a vertex from each triangle [S3, unofficial].
*   **Degenerate Triangles:** If a triangle has zero area (collinear vertices), its normal is zero. The algorithm assumes valid triangles with non-zero area. Degenerate triangles may lead to division by zero or incorrect normal calculations if not pre-filtered [G].
*   **Floating Point Precision:** The separation check `min1 >= max2` is sensitive to precision errors. Using a strict inequality with an epsilon (`min1 > max2 + epsilon`) is recommended to avoid false positives due to rounding errors [S2, S3, unofficial].
*   **Co-planar Hack:** Some implementations (e.g., those with Bounding Box overloads) explicitly return `false` for co-planar triangles to avoid the complexity of the 2D overlap test, treating them as non-intersecting [S1, S2, S3, unofficial]. This is a design choice, not a mathematical necessity.

## Subtopics

### 2D Triangle Overlap
When triangles are co-planar, the problem reduces to 2D triangle intersection. This is not covered in detail here but is required for the co-planar branch of the SAT test.

### Bounding Box Pre-check
A common optimization is to check if the Axis-Aligned Bounding Boxes (AABBs) of the two triangles intersect before performing the SAT test. If the AABBs do not intersect, the triangles cannot intersect. This is an O(1) early-out [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** O(1) per pair of triangles. The algorithm tests a fixed number of axes: 2 face normals + 9 edge-edge cross products = 11 axes for non-co-planar triangles. For co-planar triangles, it tests up to 6 edge normals [S2, unofficial].
*   **Memory Complexity:** O(1). Only a few temporary vectors and scalars are needed.
*   **Measured Performance:** The method is very fast for individual triangle pairs. However, for large scenes, it is typically used within a spatial acceleration structure (like a BVH or Octree) to reduce the number of pairs tested. The BBox pre-check further optimizes this [S2, unofficial].
*   **Strengths:** Simple to implement, robust for non-co-planar triangles, provides a definitive boolean result.
*   **Limitations:** Does not provide the intersection polygon or depth of intersection. Co-planar case is complex and sometimes skipped. Sensitive to floating-point precision if not handled with epsilon.
*   **When to Use:** When you need a fast boolean check for triangle-triangle collision, such as in physics engines or collision detection systems.
*   **When Not to Use:** When you need the intersection geometry (e.g., for clipping or rendering). In that case, use a triangle-triangle intersection algorithm that computes the intersection polygon.

## Background
The Triangle-Triangle Intersection Test using the Separating Axis Theorem is a standard technique in computational geometry and computer graphics. It is widely used in collision detection systems. The specific implementation details, including the handling of co-planar triangles and the use of epsilon, are documented in various open-source implementations of dual contouring and mesh processing libraries, such as those by Tao Ju [S1, S2, S3, unofficial]. The method relies on the Separating Axis Theorem, which states that two convex shapes are disjoint if and only if there exists a plane (axis) onto which their projections do not overlap. For triangles, the potential separating axes are the face normals and the cross products of their edges.
