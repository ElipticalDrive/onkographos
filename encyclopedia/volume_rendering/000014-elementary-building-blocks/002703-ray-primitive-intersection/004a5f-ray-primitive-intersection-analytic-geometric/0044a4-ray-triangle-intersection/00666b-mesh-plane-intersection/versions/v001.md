# Mesh-Plane Intersection

Also called: Parallel Mesh-Plane Intersection, computePlaneIntersections

## Overview
Mesh-Plane Intersection computes the geometric intersection segments between a polygonal mesh and a set of cutting planes. It solves the problem of extracting cross-sectional contours from 3D geometry, which is a prerequisite for volume visualization techniques such as exploded views or clipping. Unlike [Ray-Triangle Intersection](11312-ray-triangle-intersection.md), which yields a single point or none for a single ray, this method yields line segments (or points) representing the cross-section of each triangle by the plane. It is distinct from [Triangle-Triangle Intersection Test](11175-triangle-triangle-intersection-test.md) as it operates against infinite planes rather than other triangles.

## How it works
**Inputs:**
- `mesh`: A polygonal mesh containing a list of vertices and a list of triangle indices.
- `planes`: A list of cutting planes.

**Outputs:**
- `intersection`: A structure containing a list of `IntersectionSegment` objects and a boolean `visible` flag.

**Data Structures:**
- `Vertex`: A 3-component float vector $(x, y, z)$.
- `IntersectionSegment`: Contains `start` (Vertex), `end` (Vertex), and `planeIndex` (size_t).
- `threadSafeSegments`: A shared vector of `IntersectionSegment` used for parallel accumulation.

**Algorithm Steps:**
1. **Validation**: Check if `mesh.vertices` or `mesh.indices` is empty. If so, set `intersection.visible = false` and return immediately to prevent crashes [S1, unofficial].
2. **Parallel Iteration**: Iterate over each plane in `planes` using parallel execution (e.g., OpenMP) [S1, unofficial].
3. **Triangle Iteration**: For each plane, iterate over the mesh indices in steps of 3. Let the current index be $i$. The triangle vertices are $v_0 = \text{mesh.vertices}[\text{mesh.indices}[i]]$, $v_1 = \text{mesh.vertices}[\text{mesh.indices}[i+1]]$, and $v_2 = \text{mesh.vertices}[\text{mesh.indices}[i+2]]$.
4. **Triangle-Plane Intersection**: Call `trianglePlaneIntersection(v0, v1, v2, plane, segment)` to compute the intersection segment. This function determines if the triangle intersects the plane and calculates the resulting segment endpoints [S1, unofficial].
5. **Segment Assignment**: If an intersection exists, assign `segment.planeIndex = planeIdx` (the current plane's index).
6. **Accumulation**: Push the valid segment into a local buffer `localSegments`.
7. **Merge**: After processing all triangles for a plane (or in a thread-safe manner), merge `localSegments` into the shared `threadSafeSegments` vector under a critical section [S1, unofficial].
8. **Result Assignment**: Assign the merged segments to the result: `intersection.segments = std::move(threadSafeSegments)`.

**Pseudocode:**
```python
def meshPlaneIntersection(mesh, planes):
    # Input validation
    if not mesh.vertices or not mesh.indices:
        return Intersection(visible=False, segments=[])

    threadSafeSegments = []

    # Parallel loop over planes
    for planeIdx in range(len(planes)):
        plane = planes[planeIdx]
        localSegments = []

        # Iterate over triangles in steps of 3
        for i in range(0, len(mesh.indices), 3):
            v0 = mesh.vertices[mesh.indices[i]]
            v1 = mesh.vertices[mesh.indices[i+1]]
            v2 = mesh.vertices[mesh.indices[i+2]]

            # Compute intersection segment
            segment = trianglePlaneIntersection(v0, v1, v2, plane)

            if segment is not None:
                segment.planeIndex = planeIdx
                localSegments.append(segment)

        # Merge local segments into shared list (thread-safe)
        # In a real implementation, this requires a critical section or atomic append
        for seg in localSegments:
            threadSafeSegments.append(seg)

    return Intersection(visible=True, segments=threadSafeSegments)
```

## Subtopics

### [Triangle-Plane Intersection](22936-triangle-plane-intersection.md)
Triangle-plane intersection determines whether a triangle intersects a plane, calculating the resulting intersection segment(s) and handling degenerate cases where vertices lie on the plane. It serves as the core geometric primitive for mesh-plane intersection, enabling the extraction of cutting lines from polygonal meshes. Unlike ray-triangle intersection which yields a single point or none, this method yields a line segment (or points) representing the cross-section of the triangle by the plane.

## Operating characteristics
**Time Complexity:** $O(N \cdot P)$, where $N$ is the number of triangles and $P$ is the number of planes. The parallel implementation distributes the plane iteration across threads.
**Memory Complexity:** $O(S)$, where $S$ is the number of resulting intersection segments.
**Strengths:** Parallelizable across planes; simple geometric primitive.
**Limitations:** Requires a critical section for merging results, which may limit scalability on many-core architectures. Performance depends heavily on the efficiency of the underlying `trianglePlaneIntersection` function.
**When to use:** When extracting cross-sections of a mesh for visualization (e.g., exploded views) is required.
**When not to use:** When ray-based rendering is preferred, or when the mesh is extremely large and memory bandwidth becomes a bottleneck.

## Background
The method is described in the context of the `explodedvolumes` project, which implements exploded view visualization for medical volume data using Marching Cubes and mesh clipping. The implementation uses OpenMP for parallelization and relies on standard linear algebra libraries (GLM, Eigen) for vector operations. The project is a GitHub repository by KillaWan.
