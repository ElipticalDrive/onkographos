# Tensor Field Ray Bending
Also called: Bending rule, Ray direction update

## Overview
Tensor Field Ray Bending is a visualization method where parallel rays are issued toward a tensor field and bent by a transforming force derived from the local tensor value [S1]. It solves the problem of visual clutter inherent in glyph-based methods by projecting the integrated effects of the tensor field onto a 2D receiving plane or by rendering bent ray tubes, revealing spatially continuous deformation patterns [S1]. Unlike path tracing which renders 1D line glyphs, this method uses image distortion or photon distribution to show 2D features and continuous changes through image deformation [S1]. It differs from Hesselink's hyperstreamline algorithm by not requiring symmetric tensors and by providing flexibility to control path traces via a scaling parameter [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A tensor field $T(P)$ defined over a volume, a set of initial parallel rays with direction $D_0$ and position $P_0$, a time step $\Delta t$, and user-specified constants $a$ and $b$ for the scaling parameter.
*   **Output:** A set of bent ray paths (trajectories) and their deformed cross-sections (ellipses or tubes) [S1].

**Data Structures:**
*   **Tensor Field:** A 3D grid or volume where each voxel contains a tensor $T(P)$ (typically a $3 \times 3$ matrix) [S1].
*   **Ray State:** For each ray, store current position $P$, current direction $D$ (normalized), and current velocity $V$ (normalized, $V=D$) [S1].

**Parameters:**
*   $\Delta t$: Time step increment. Not given in the sources.
*   $a, b$: User-specified constants for the linear scaling parameter $s(\lambda) = a + b\lambda$ [S1].
*   $\lambda$: Wavelength of the ray. Not given in the sources.

**Steps:**
1.  **Initialization:** Issue a set of parallel rays toward the tensor field. For each ray, initialize position $P$ and direction $D$ [S1].
2.  **Tensor Lookup:** At the current ray position $P$, retrieve the local tensor value $T(P)$ from the tensor field [S1].
3.  **Bending Force Calculation:** Calculate the net bending force $\Delta D_t$ as the product of the tensor and the current ray direction:
    $$ \Delta D_t = T(P) \cdot D_t \quad (3) $$
    where $D_t$ is the direction of the ray at time step $t$ [S1].
4.  **Direction Update:** Update the ray direction using the bending rule. First, compute the tentative new direction by adding a fraction of the bending force to the current direction, scaled by the ray flexibility $s(\lambda)$ and the time step $\Delta t$:
    $$ D_{t+1} = \frac{D_t + s(\lambda) \cdot \Delta D_t \Delta t}{\|D_t + s(\lambda) \cdot \Delta D_t \Delta t\|} \quad (4) $$
    The new direction is normalized at the end of each step [S1].
5.  **Velocity Update (Differential Form):** Alternatively, or concurrently, update the normalized velocity $V(t)$ using the differential form of the bending rule:
    $$ V'(t) = s(\lambda)\left(T(P) \cdot V - \frac{V^T \cdot T(P) \cdot V}{V^T \cdot V} V\right) \quad (5) $$
    where $V(t) = P'(t)$ is the normalized velocity [S1]. Note that $V^T \cdot T(P) \cdot V$ is a scalar and $V$ is a vector, so the term $\frac{V^T \cdot T(P) \cdot V}{V^T \cdot V} V$ projects the tensor action onto the direction of $V$.
6.  **Position Update:** Update the ray position $P$ using the new direction/velocity. (Not explicitly given in the sources, but implied by $V(t) = P'(t)$). [G] Standard integration: $P_{t+1} = P_t + V_{t+1} \cdot \Delta t$.
7.  **Cross-Section Encoding:** To encode information in other eigendirections along the ray trajectory, use elliptical cross sections. The shape of the ellipse is determined by the eigenvalues of $T(P)$ [S1].
8.  **Rendering:** Draw all bent rays within the tensor field simultaneously. Render ellipses individually or assemble them to form a tube for visualization [S1].

**Pseudocode:**
```python
def tensor_field_ray_bending(tensor_field, initial_rays, a, b, delta_t):
    """
    Simulates ray bending through a tensor field.
    
    Args:
        tensor_field: A function or data structure T(P) returning a 3x3 matrix.
        initial_rays: List of Ray objects with initial P and D.
        a, b: Constants for scaling parameter s(lambda) = a + b*lambda.
        delta_t: Time step for integration.
        
    Returns:
        List of Ray trajectories (lists of points).
    """
    trajectories = []
    
    for ray in initial_rays:
        P = ray.P
        D = ray.D
        # Ensure D is normalized
        D = D / norm(D)
        V = D
        trajectory = [P]
        
        # Note: lambda and s(lambda) are not defined in the source for specific rays.
        # We assume a constant s_lambda for this simulation or it is passed per ray.
        # The source defines s(lambda) = a + b*lambda.
        # Since lambda is not specified, we use a placeholder or assume s_lambda is provided.
        # For implementation completeness, we assume s_lambda is a parameter.
        # If not, this step requires external input. [G]
        s_lambda = get_scaling_parameter(ray.lambda_value, a, b) 
        
        while P is within tensor_field bounds:
            # 1. Get local tensor
            T_P = tensor_field(P)
            
            # 2. Calculate bending force: Delta D_t = T(P) * D_t
            delta_D_t = matrix_vector_multiply(T_P, D)
            
            # 3. Update direction: D_{t+1} = normalize(D_t + s(lambda) * Delta D_t * delta_t)
            new_D_unnormalized = vector_add(D, vector_scale(delta_D_t, s_lambda * delta_t))
            D = vector_normalize(new_D_unnormalized)
            
            # 4. Update velocity (optional, if using differential form for V)
            # V'(t) = s(lambda) * (T(P) * V - (V^T * T(P) * V / V^T * V) * V)
            # Note: V^T * T(P) * V is a scalar. V^T * V is a scalar (norm squared).
            # Since V is normalized, V^T * V = 1.
            # So: V'(t) = s(lambda) * (T(P) * V - (V^T * T(P) * V) * V)
            Tv = matrix_vector_multiply(T_P, V)
            scalar_term = dot_product(V, Tv) # V^T * T(P) * V
            projection_term = vector_scale(V, scalar_term)
            V_prime = vector_scale(vector_subtract(Tv, projection_term), s_lambda)
            
            # Update velocity to new direction (assuming V tracks D)
            V = D 
            
            # 5. Update position
            P = vector_add(P, vector_scale(V, delta_t))
            
            trajectory.append(P)
            
        trajectories.append(trajectory)
        
    return trajectories

def get_scaling_parameter(lambda_val, a, b):
    return a + b * lambda_val
```

**Edge Cases and Pitfalls:**
*   **Sensitivity to Wavelength:** A slight change in $\lambda$ may cause noticeable variations in the result. Results must be interpreted in conjunction with the choice of $\lambda$ [S1].
*   **Visual Clutter:** Bent rays may cross each other (intersect themselves or one another) with no inherent guarantee against intersection. Clutter increases with the number of rays, requiring experimentation to find a balance [S1].
*   **Symmetry:** The method does not require symmetric tensors. It can handle shearing, converging, and rotating properties directly [S1].

## Subtopics

### [Tensor Field Ray Bending (Visualization Method)](23820-tensor-field-ray-bending-visualization-method.md)
A rendering technique that visualizes the internal convergent and divergent properties of a tensor volume by treating the volume as an optical element (lens or prism) that distorts light rays. It solves the problem of visual clutter inherent in glyph-based methods by projecting the integrated effects of the tensor field onto a 2D receiving plane, revealing spatially continuous deformation patterns. Unlike path tracing which renders 1D line glyphs, this method uses image distortion or photon distribution to show 2D features and continuous changes through image deformation.

## Operating characteristics
*   **Time Complexity:** Not given in the sources. Depends on the number of rays, steps per ray, and tensor lookup cost.
*   **Memory Complexity:** Not given in the sources. Depends on storing ray trajectories and tensor field.
*   **Strengths:**
    *   Does not require symmetric tensors [S1].
    *   Shows shearing, converging, and rotating properties [S1].
    *   Provides flexibility to control path traces via $s(\lambda)$ [S1].
    *   When $s(\lambda) \rightarrow \infty$, the normalized version of $P^t(t)$ is the principle eigenvector of $T(P(t))$, making major hyperstreamlines a special case [S1].
*   **Limitations:**
    *   Rays may intersect, causing visual clutter [S1].
    *   Sensitive to the choice of $\lambda$ [S1].
*   **When to use:** When analyzing tensor fields with non-symmetric components or when exploring how different "wavelengths" (flexibility) affect ray paths to reveal different tensor properties [S1].
*   **When not to use:** When visual clutter from intersecting rays is unacceptable and alternative methods like photon distribution are not suitable [S1].

## Background
*   **Origin:** The method was introduced in "Interaction of Light and Tensor Fields" [S1].
*   **History:** It is based on the idea of treating the tensor field as a transforming force that bends simulated light rays [S1]. It extends the concept of hyperstreamlines by allowing non-symmetric tensors and variable flexibility [S1].
*   **Usage:** Used in scientific visualization to understand the underlying nature of tensor volumes by observing the effects on bent rays [S1].
