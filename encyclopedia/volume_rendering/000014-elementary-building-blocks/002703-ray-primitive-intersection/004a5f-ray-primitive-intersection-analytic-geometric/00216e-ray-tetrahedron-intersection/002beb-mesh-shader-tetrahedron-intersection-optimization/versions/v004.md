# Mesh Shader Tetrahedron Intersection Optimization

Also called: Accelerated intersections using wave intrinsics within a mesh shader, Optimized Cyrus-Beck for tetrahedra

## Overview
This method optimizes the ray-tetrahedron intersection test by leveraging mesh shader wave intrinsics to share geometric data among the four vertices of a single tetrahedron [S1, unofficial]. It reduces redundant memory loads by a factor of four and lowers the computational cost of the intersection routine to approximately 12 floating-point operations (FLOPs) [S1, unofficial]. Unlike naive implementations that load tetrahedron data independently for each vertex, this approach precomputes plane parameters in the mesh shader and computes final distances in the fragment shader, building on the standard Cyrus-Beck algorithm [S1, unofficial].

## How it works
The method splits the intersection calculation between a mesh shader (for precomputation) and a fragment shader (for final distance calculation) [S1, unofficial]. It assumes a tetrahedron is defined by four vertices and four outward-facing triangular faces [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$, passed as uniform or per-ray data [S1, unofficial].
- Vertex positions of the tetrahedron, accessible via wave intrinsics [S1, unofficial].
- `tetVertexId`: An identifier for the current vertex within the tetrahedron (0–3) [S1, unofficial].

**Outputs:**
- `planeN`: A vector of four numerators for the plane equations, one per face [S1, unofficial].
- `planeD`: A vector of four denominators for the plane equations, one per face [S1, unofficial].

### Data Structures
**Static Lookup Table (`kTetTriangles`)**
A constant array of 4 `uint4` vectors defining the vertex indices for the 4 faces of a tetrahedron [S1, unofficial]. The indices are ordered to ensure outward-facing normals [S1, unofficial].
$$
\text{kTetTriangles} = \begin{bmatrix}
0, 2, 1, 3 \\
1, 2, 3, 0 \\
0, 3, 2, 1 \\
3, 0, 1, 2
\end{bmatrix}
$$
Each row $i$ corresponds to the face opposite vertex $i$ [S1, unofficial]. The three indices define the triangle vertices [S1, unofficial].

### Algorithm Steps
1. **Face Index Retrieval**: For the current vertex `tetVertexId`, retrieve the face index `tri` from `kTetTriangles[tetVertexId]` [S1, unofficial].
2. **Normal Computation**: Compute the outward-facing normal $\mathbf{n}$ for the triangle defined by `tri` [S1, unofficial]. The vertices of the triangle are accessed using wave intrinsics to read the positions of the other lanes in the wave group [S1, unofficial].
   $$ \mathbf{n} = (\mathbf{v}_{\text{tri}[2]} - \mathbf{v}_{\text{tri}[0]}) \times (\mathbf{v}_{\text{tri}[1]} - \mathbf{v}_{\text{tri}[0]}) $$
   Where $\mathbf{v}_{\text{idx}}$ is the position of the vertex with index `idx`, retrieved via `WaveReadLaneAt` [S1, unofficial].
3. **Plane Numerator**: Compute the numerator for the plane equation [S1, unofficial]. Let $\mathbf{v}_0$ be the position of the first vertex of the triangle (`tri[0]`) [S1, unofficial].
   $$ \text{num} = \mathbf{n} \cdot (\mathbf{v}_0 - \mathbf{o}) $$
   Broadcast this scalar `num` to all lanes in the wave group to populate the `planeN` vector [S1, unofficial].
4. **Plane Denominator**: Compute the denominator for each lane [S1, unofficial]. The normal $\mathbf{n}$ is broadcasted to the specific lane [S1, unofficial].
   $$ \text{planeD}_{\text{lane}} = \mathbf{n}_{\text{lane}} \cdot \mathbf{d} $$
5. **Normalization**: In the fragment shader, normalize the denominator by the length of the ray direction $\mathbf{d}$ [S1, unofficial].
   $$ \text{planeD}' = \frac{\text{planeD}}{\|\mathbf{d}\|} $$
6. **Intersection Parameters**: Compute the intersection parameter $t$ for each plane [S1, unofficial].
   $$ t_i = \frac{\text{planeN}_i}{\text{planeD}'_i} $$
7. **Entry and Exit Distances**:
   - $t_{\text{enter}} = \max \{ t_i \mid \text{planeD}'_i > 0 \}$ [S1, unofficial]. If no such $i$ exists, $t_{\text{enter}} = -\infty$ [S1, unofficial].
   - $t_{\text{exit}} = \min \{ t_i \mid \text{planeD}'_i < 0 \}$ [S1, unofficial]. If no such $i$ exists, $t_{\text{exit}} = +\infty$ [S1, unofficial].

### Pseudocode
```python
# Mesh Shader Pre-calculation
# Assumes a wave group of at least 4 lanes, with 4 lanes assigned to one tetrahedron.
# Standard wave intrinsics [G]:
#   wave_get_lane_index() returns the lane ID within the wave.
#   wave_read_lane_at(value, lane_id) returns the value held by the specified lane.
#   wave_broadcast(value) replicates the value to all lanes in the wave.

def mesh_shader_intersect(ray_origin, ray_dir, tet_vertex_id, vertex_positions):
    # Static lookup table for outward-facing faces [S1, unofficial]
    kTetTriangles = [
        (0, 2, 1, 3),
        (1, 2, 3, 0),
        (0, 3, 2, 1),
        (3, 0, 1, 2)
    ]

    # Base lane index for this tetrahedron [S1, unofficial]
    base_lane = (wave_get_lane_index() // 4) * 4

    # Helper to read vertex position from another lane [S1, unofficial]
    def get_vertex(idx):
        return wave_read_lane_at(vertex_positions, base_lane + idx)

    # Get face indices for the current vertex [S1, unofficial]
    tri = kTetTriangles[tet_vertex_id]

    # Compute outward facing normal n [S1, unofficial]
    v0 = get_vertex(tri[0])
    v1 = get_vertex(tri[1])
    v2 = get_vertex(tri[2])
    edge1 = v2 - v0
    edge2 = v1 - v0
    n = cross(edge1, edge2)

    # Compute numerator num = dot(n, v0 - ray_origin) [S1, unofficial]
    num = dot(n, v0 - ray_origin)

    # Each lane constructs a vector of 4 numerators by reading num from all 4 lanes [S1, unofficial]
    planeN = [wave_read_lane_at(num, base_lane + i) for i in range(4)]

    # Each lane constructs a vector of 4 denominators by reading n from all 4 lanes and dotting with ray_dir [S1, unofficial]
    planeD = [dot(wave_read_lane_at(n, base_lane + i), ray_dir) for i in range(4)]

    return planeN, planeD

def fragment_shader_intersect(planeN, planeD, ray_dir):
    # Normalize denominator by ray direction length [S1, unofficial]
    d_len = length(ray_dir)
    planeD_norm = [d / d_len for d in planeD]

    # Compute t for each plane [S1, unofficial]
    all_t = [n / d for n, d in zip(planeN, planeD_norm)]

    # Compute t_enter: max t where planeD > 0 [S1, unofficial]
    t_enter = float('-inf')
    for i in range(4):
        if planeD_norm[i] > 0.0:
            if all_t[i] > t_enter:
                t_enter = all_t[i]

    # Compute t_exit: min t where planeD < 0 [S1, unofficial]
    t_exit = float('inf')
    for i in range(4):
        if planeD_norm[i] < 0.0:
            if all_t[i] < t_exit:
                t_exit = all_t[i]

    return t_enter, t_exit
```

### Parameters
- **kTetTriangles**: Static constant array. Values are fixed as shown in the Data Structures section [S1, unofficial].

### Edge Cases and Pitfalls
- **Redundant Loads**: The naive version loads tetrahedron information for each of the 4 vertices separately, leading to redundant memory loads [S1, unofficial]. This method avoids this by sharing information between vertices in the mesh shader [S1, unofficial].
- **Wave Size**: The method assumes a wave size of at least 4 to accommodate the 4 vertices of a tetrahedron [S1, unofficial].
- **Parallel Gather Semantics**: The pseudocode uses list comprehensions for clarity, but in hardware these operations execute in parallel across the wave lanes to gather `num` and `n` values [G].

## Operating characteristics
- **Time Complexity**: The optimized implementation reduces the runtime cost to only 12 FLOPs for the intersection calculation [S1, unofficial].
- **Memory Access**: Reduces memory loads by a factor of four compared to the naive version by leveraging wave intrinsics to share data among vertices [S1, unofficial].
- **Strengths**: Significant reduction in computational cost and memory bandwidth usage for tetrahedral mesh rendering [S1, unofficial].
- **Limitations**: Requires hardware support for mesh shaders and wave intrinsics [S1, unofficial]. The method is specific to tetrahedral primitives [S1, unofficial].

## Background
This method addresses the inefficiency of naive ray-tetrahedron intersection tests in volumetric rendering by exploiting the parallel execution model of mesh shaders [S1, unofficial]. It is a specialized application of the Cyrus-Beck algorithm [S1, unofficial].
