# Tetrahedron Face Extraction


## Overview
Computes the four planar faces (unit normals and distances to the origin) from a four-vertex description of a tetrahedron. It serves as the geometric preprocessing step for [Ray-Tetrahedron Intersection](2525-ray-tetrahedron-intersection.md), converting vertex-based topology into half-space representations required for efficient ray-clipping. It differs from [Plücker-based Tetrahedral Cell Intersection](1767-pl-cker-based-tetrahedral-cell-intersection.md) by using explicit plane equations rather than line geometry, and from [Point-in-Tetrahedron Test via Barycentric Coordinates](2591-point-in-tetrahedron-test-via-barycentric-coordinates.md) by outputting boundary definitions rather than containment tests.

## How it works
**Inputs:**
- `verts`: Array of four `r3d_rvec3` vectors ($v_0, v_1, v_2, v_3$) defining the tetrahedron vertices.

**Outputs:**
- `faces`: Array of four `r3d_plane` structures. Each plane is defined by a normal vector $\mathbf{n}$ and a scalar distance $d$ from the origin, such that the plane equation is $\mathbf{n} \cdot \mathbf{x} + d = 0$.

**Data Structures:**
- `r3d_rvec3`: A 3D vector structure containing `x`, `y`, `z` components (typically `float` or `double`).
- `r3d_plane`: A structure containing a normal vector `n` (`r3d_rvec3`) and a scalar `d` (`float` or `double`).

**Algorithm:**
For each of the four faces, identified by the vertex *opposite* to the face, the normal is computed via the cross product of two edge vectors lying on the face. The distance is computed by projecting the origin onto the normal relative to a point on the plane.

1. Define the four faces by their opposite vertices:
   - Face 0: Opposite $v_0$, defined by vertices $v_1, v_2, v_3$.
   - Face 1: Opposite $v_1$, defined by vertices $v_0, v_2, v_3$.
   - Face 2: Opposite $v_2$, defined by vertices $v_0, v_1, v_3$.
   - Face 3: Opposite $v_3$, defined by vertices $v_0, v_1, v_2$.

2. For each face $i$ (where $i \in \{0, 1, 2, 3\}$):
   a. Identify the three vertices forming the face. Let these be $a, b, c$.
   b. Compute two edge vectors: $\mathbf{e}_1 = b - a$ and $\mathbf{e}_2 = c - a$.
   c. Compute the unnormalized normal: $\mathbf{n}_{raw} = \mathbf{e}_1 \times \mathbf{e}_2$.
   d. Normalize the normal: $\mathbf{n} = \frac{\mathbf{n}_{raw}}{\|\mathbf{n}_{raw}\|}$.
   e. Compute the distance to the origin: $d = -\mathbf{n} \cdot a$.
   f. Store $(\mathbf{n}, d)$ in `faces[i]`.

**Pseudocode:**
```python
def tetrahedron_face_extraction(verts):
    """
    verts: list of 4 vectors [v0, v1, v2, v3]
    returns: list of 4 planes [p0, p1, p2, p3]
    """
    faces = []
    
    # Mapping: face index i corresponds to the face NOT containing verts[i]
    # Face 0 uses v1, v2, v3
    # Face 1 uses v0, v2, v3
    # Face 2 uses v0, v1, v3
    # Face 3 uses v0, v1, v2
    face_indices = [
        [1, 2, 3],
        [0, 2, 3],
        [0, 1, 3],
        [0, 1, 2]
    ]
    
    for i in range(4):
        idx = face_indices[i]
        a = verts[idx[0]]
        b = verts[idx[1]]
        c = verts[idx[2]]
        
        # Edge vectors
        e1 = [b[0]-a[0], b[1]-a[1], b[2]-a[2]]
        e2 = [c[0]-a[0], c[1]-a[1], c[2]-a[2]]
        
        # Cross product e1 x e2
        nx = e1[1]*e2[2] - e1[2]*e2[1]
        ny = e1[2]*e2[0] - e1[0]*e2[2]
        nz = e1[0]*e2[1] - e1[1]*e2[0]
        
        # Magnitude
        mag_sq = nx*nx + ny*ny + nz*nz
        
        # Guard against degenerate face (zero area)
        if mag_sq == 0:
            # [G] Return a zero normal or handle error; standard implementation assumes valid tetrahedron
            nx, ny, nz = 0.0, 0.0, 0.0
            mag = 0.0
        else:
            mag = mag_sq ** 0.5
            nx /= mag
            ny /= mag
            nz /= mag
            
        # Distance to origin: d = -n . a
        d = -(nx*a[0] + ny*a[1] + nz*a[2])
        
        faces.append({'n': [nx, ny, nz], 'd': d})
        
    return faces
```

**Edge Cases and Pitfalls:**
- **Degenerate Tetrahedron:** If vertices are coplanar, the cross product magnitude is zero. The normal cannot be normalized. The source does not specify a fallback, but numerically this results in NaN or Inf if not guarded [S1, unofficial].
- **Winding Order:** The direction of the normal depends on the order of vertices $a, b, c$. The source implies a specific winding order consistent with the `r3d` library's expectations [S1, unofficial].

## Subtopics

### Tetrahedron Signed Volume Calculation
Calculates the signed volume of a tetrahedron defined by four input vertices. The return value is the signed volume; a positive volume indicates a specific winding order, while a negative volume indicates the opposite. If the volume is negative, vertices may be swapped to ensure positive volume [S1, unofficial].
- **Inputs:** Four vertices $p_a, p_b, p_c, p_d$.
- **Output:** Scalar signed volume.
- **Formula:** $V = \frac{1}{6} (p_d - p_a) \cdot ((p_b - p_a) \times (p_c - p_a))$ [G]. The sign indicates orientation relative to the vertex order.

## Operating characteristics
- **Time Complexity:** $O(1)$, as it performs a fixed number of arithmetic operations (4 faces $\times$ constant work).
- **Memory Complexity:** $O(1)$, requiring storage for 4 plane structures.
- **Strengths:** Provides explicit plane equations suitable for standard ray-plane intersection tests. Simple to implement.
- **Limitations:** Requires non-degenerate input. Normalization introduces square roots, which may be slower than unnormalized tests if only sign checks are needed.

## Background
Originated in the `r3d` library by Devon Powell [S1, unofficial]. The method is part of the `r3d` geometric primitives suite, designed for ray tracing applications involving irregular volumes. It is used as a dependency in applications linking against `libr3d` [S1, unofficial].
