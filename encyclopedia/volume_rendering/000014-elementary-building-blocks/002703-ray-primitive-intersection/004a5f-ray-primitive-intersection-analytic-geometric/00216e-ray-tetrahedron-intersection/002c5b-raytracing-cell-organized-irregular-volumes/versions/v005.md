# Raytracing Cell-Organized Irregular Volumes

Also called: Cell-based volume raytracing, Raytracing irregular volume data

## Overview
This method renders volumetric data defined by unstructured or irregular cell grids (such as tetrahedra or hexahedra) by traversing the cell structure along a ray [S1]. It solves the problem of efficiently visiting cells intersected by a ray in non-uniform geometries where regular grid acceleration structures are not applicable [S1]. It differs from sibling methods by explicitly handling the topological connectivity of irregular cells and managing concave dataset boundaries, which can cause rays to exit and re-enter the volume multiple times [S1].

## How it works
The method traverses a cell-organized irregular volume by stepping from cell to cell along a ray [S1]. It relies on the geometric intersection of the ray with the faces of the cells to determine entry and exit points [S1].

### Inputs and Outputs
*   **Input**: Ray defined by origin $\mathbf{d}$ and direction $\mathbf{c}$; irregular volume dataset composed of cells (e.g., tetrahedra, hexahedra) with associated vertex positions and face connectivity; scalar or vector field values at vertices [S1].
*   **Output**: Integrated optical properties (color, opacity) along the ray path within the volume [G].

### Data Structures
*   **Cell**: Contains a list of vertices and a list of faces [S1].
*   **Face**: Defined by three vertices for tetrahedra or four for hexahedra; for tetrahedra, a face is a triangle [S1]. The face stores the precomputed cross product of its edge vectors to accelerate intersection tests [S1].
*   **Exposed Faces**: The set of faces on the boundary of the dataset that are not shared with another cell [S1]. These define the entry and exit points for the ray when it leaves the volume [S1].

### Steps
1.  **Initial Intersection**: Intersect the ray against all exposed faces of the dataset to find the first entry point [S1].
2.  **Cell Traversal**: Identify the cell adjacent to the current face [S1]. Intersect the ray with all faces of the current cell to find the exit face [S1]. Use the barycentric coordinate test to verify if the intersection point lies within the triangular face [S1]. If the intersection point is inside the face, the ray passes through to the adjacent cell [S1]. If the face is not shared by another cell, the ray has exited the dataset [S1].
3.  **Re-entry Handling**: If the ray exits the dataset, intersect the ray against all remaining exposed faces to find a new entry point [S1]. This is necessary because irregular volumes can be concave, allowing the ray to intersect the surface in multiple locations [S1].
4.  **Integration**: For each cell traversed, integrate the volume properties along the segment inside the cell [G].
5.  **Termination**: Stop when the ray has exited the dataset and no further re-entries are found, or when the ray direction parameter exceeds a maximum distance [G].

### Formulas
**Plane Intersection**:
The intersection parameter $t$ for a ray defined by point $\mathbf{d}$ (origin) and vector $\mathbf{c}$ (direction) with a plane defined by points $\mathbf{a}, \mathbf{b}, \mathbf{c}$ (where $\mathbf{c}$ is also used as a point on the plane in the source notation) is given by [S1]:
$$ t = \frac{(\mathbf{Ab} \times \mathbf{Ac}) \cdot \mathbf{a} - (\mathbf{Ab} \times \mathbf{Ac}) \cdot \mathbf{d}}{(\mathbf{Ab} \times \mathbf{Ac}) \cdot \mathbf{c}} $$
where $\mathbf{Ab} = \mathbf{b} - \mathbf{a}$ and $\mathbf{Ac} = \mathbf{c} - \mathbf{a}$ [S1]. The cross product $\mathbf{Ab} \times \mathbf{Ac}$ is the plane normal and can be precomputed and stored with the face [S1].

**Barycentric Coordinate Test**:
To verify if an intersection point lies inside a triangular face defined by $\mathbf{a}, \mathbf{b}, \mathbf{c}$ and ray direction $\mathbf{e}$, calculate [S1]:
$$ u = \frac{(\mathbf{Ac} \times \mathbf{e}) \cdot \mathbf{d} - (\mathbf{Ac} \times \mathbf{e}) \cdot \mathbf{a}}{(\mathbf{Ac} \times \mathbf{e}) \cdot \mathbf{b}} $$
$$ v = \frac{(\mathbf{Ab} \times \mathbf{e}) \cdot \mathbf{d} - (\mathbf{Ab} \times \mathbf{e}) \cdot \mathbf{a}}{(\mathbf{Ab} \times \mathbf{e}) \cdot \mathbf{c}} $$
where $\mathbf{d}$ denotes the intersection point in this context [S1]. If $u > 0$, $v > 0$, and $u + v < 1$, the point is inside the face [S1].

### Parameters
*   **Tessellation**: For hexahedral cells, if symmetric tessellation is not possible, add a new vertex at the center of each face and subdivide into twenty-four tetrahedra [S1].

### Edge Cases and Pitfalls
*   **Concave Volumes**: Rays may exit and re-enter the dataset. After exiting, re-intersect with all exposed faces to find new entry points [S1].
*   **Degenerate Tetrahedra (Coincident Vertices)**: Two zero-area triangles and two non-degenerate triangles. Ignore zero-area triangles. If the ray enters through a non-degenerate face, it exits through the other. The distance difference $dt=0$, so no integration is required [S1].
*   **Degenerate Tetrahedra (Planar)**: All face intersection distances are the same. Determine which two triangular faces the ray passes through the interior of (entry and exit). $dt=0$, so no integration is required [S1].

### Pseudocode
```python
def raytrace_irregular_volume(ray_origin, ray_direction, volume):
    # Constants
    INF = float('inf')
    EPS = 1e-9

    # Precomputed adjacency map: face -> cell [G]
    cell_adjacency = {face: cell for cell in volume.cells for face in cell.faces}

    # 1. Initial Intersection: Find first entry point among exposed faces
    min_t = INF
    entry_face = None
    for face in volume.exposed_faces:
        t = intersect_ray_plane(ray_origin, ray_direction, face)
        if t > EPS and t < min_t:
            min_t = t
            entry_face = face

    if entry_face is None:
        return None  # Ray does not hit volume

    current_t = min_t
    current_face = entry_face
    accumulated_color = (0.0, 0.0, 0.0)
    accumulated_opacity = 0.0

    while True:
        # 2. Identify current cell adjacent to the entry face
        cell = cell_adjacency[current_face]

        # 3. Find exit face among cell faces
        exit_face = None
        exit_t = INF
        for face in cell.faces:
            if face is current_face:
                continue
            t = intersect_ray_plane(ray_origin, ray_direction, face)
            if t > current_t + EPS:
                intersection_point = ray_origin + t * ray_direction
                if is_point_in_triangle(intersection_point, face.vertices, ray_direction):
                    if t < exit_t:
                        exit_t = t
                        exit_face = face

        # 4. Handle exit from volume
        if exit_face is None:
            # Ray exited the dataset; re-intersect with all exposed faces
            re_entry_t = INF
            re_entry_face = None
            for face in volume.exposed_faces:
                t = intersect_ray_plane(ray_origin, ray_direction, face)
                if t > current_t + EPS and t < re_entry_t:
                    re_entry_t = t
                    re_entry_face = face

            if re_entry_face is not None:
                current_t = re_entry_t
                current_face = re_entry_face
                continue
            else:
                break  # No further intersections

        # 5. Integrate through the cell
        dt = exit_t - current_t
        if dt > EPS:
            # Integration method depends on the specific volume data representation [G]
            color, opacity = integrate_cell_properties(cell, ray_origin, ray_direction, current_t, exit_t)
            # Standard alpha compositing
            accumulated_color = accumulated_color + color * (1.0 - accumulated_opacity)
            accumulated_opacity = accumulated_opacity + opacity * (1.0 - accumulated_opacity)

        # 6. Move to next cell
        current_t = exit_t
        current_face = exit_face

    return accumulated_color, accumulated_opacity

def intersect_ray_plane(ray_origin, ray_direction, face):
    # Source formula: t = ((Ab x Ac) . a - (Ab x Ac) . d) / ((Ab x Ac) . c)
    # Note: Source uses d for ray origin and c for ray direction (and plane point) [S1]
    a, b, c = face.vertices
    Ab = b - a
    Ac = c - a
    N = cross(Ab, Ac)

    # Denominator uses ray_direction (source calls it c)
    denom = dot(N, ray_direction)
    if abs(denom) < EPS:
        return INF

    # Numerator: N . a - N . ray_origin
    num = dot(N, a) - dot(N, ray_origin)
    return num / denom

def is_point_in_triangle(point, vertices, ray_direction):
    a, b, c = vertices
    Ab = b - a
    Ac = c - a
    e = ray_direction
    d = point  # Intersection point

    term1 = cross(Ac, e)
    u_num = dot(term1, d) - dot(term1, a)
    u_den = dot(term1, b)

    term2 = cross(Ab, e)
    v_num = dot(term2, d) - dot(term2, a)
    v_den = dot(term2, c)

    if abs(u_den) < EPS or abs(v_den) < EPS:
        return False

    u = u_num / u_den
    v = v_num / v_den
    return u > 0 and v > 0 and (u + v) < 1

def integrate_cell_properties(cell, ray_origin, ray_direction, t_start, t_end):

    return (0.0, 0.0, 0.0), 0.0
```

## Operating characteristics
*   **Time Complexity**: Depends on the number of cells intersected by the ray. In the worst case, this is proportional to the number of cells in the volume [S1].
*   **Memory Complexity**: Proportional to the number of cells and faces in the volume [S1].
*   **Strengths**: Handles irregular and unstructured grids efficiently. Can handle concave volumes correctly by re-entering the dataset [S1].
*   **Limitations**: Requires explicit connectivity information. Degenerate cells must be handled explicitly. Performance may degrade for highly complex or concave geometries due to multiple re-entries [S1].

## Background
This method was introduced in the paper "Raytracing irregular volume data" [S1]. It addresses the need for rendering techniques that can handle non-uniform volumetric data, such as those arising from finite element analysis or geological modeling, where regular grid structures are not suitable [S1].
