# Axis-Aligned Rectangle Hit Test

Also called: Plane-Rectangle Intersection, XYRect/XZRect/YZRect Hit

## Overview
The Axis-Aligned Rectangle Hit Test determines whether a ray intersects a finite rectangle lying on an axis-aligned plane (e.g., $x=c$, $y=c$, or $z=c$) [S1, unofficial]. It solves the problem of efficiently testing intersection with planar primitives in ray tracing by decoupling the plane intersection from the 2D boundary check [S1, unofficial]. Unlike infinite plane intersection, this method explicitly validates that the intersection point lies within the rectangle's 2D bounds [S1, unofficial]. It is distinct from [Ray-Sphere Intersection](3539-ray-sphere-intersection.md) and [Plane-Cube Intersection](11468-plane-cube-intersection.md) by its specific geometric constraint to a single planar face [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input**: A ray $\mathbf{r}$ defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a rectangle defined by bounds on two axes and a constant coordinate on the third; minimum and maximum intersection distances $t_{min}, t_{max}$; a hit record structure `rec`.
*   **Output**: Boolean indicating hit; if true, `rec` is populated with intersection distance $t$, point $\mathbf{p}$, normal $\mathbf{n}$, and material.

**Data Structures**
The rectangle is defined by a struct containing bounds on two axes and a constant $K$ on the third axis [S1, unofficial]. For an XYRect:
*   `X0, X1`: Minimum and maximum X coordinates.
*   `Y0, Y1`: Minimum and maximum Y coordinates.
*   `K`: The constant Z coordinate of the plane.
*   `Mat`: The material associated with the rectangle.
Similar structures exist for XZRect (constant Y) and YZRect (constant X) [S1, unofficial].

**Steps**
1.  **Plane Intersection**: Solve for the parameter $t$ where the ray intersects the infinite plane containing the rectangle. For an XYRect (plane $z=K$), the equation is:
    $$ t = \frac{K - o_z}{d_z} $$
    where $o_z$ is the ray's origin Z-component and $d_z$ is the ray's direction Z-component [S1, unofficial].
2.  **Depth Check**: Verify if $t$ is within the valid range $[t_{min}, t_{max}]$. If not, the intersection is outside the desired depth range [S1, unofficial].
3.  **Coordinate Projection**: Calculate the intersection point's coordinates on the plane. For an XYRect:
    $$ x = o_x + t \cdot d_x $$
    $$ y = o_y + t \cdot d_y $$
    [S1, unofficial].
4.  **Boundary Check**: Verify if $x \in [X0, X1]$ and $y \in [Y0, Y1]$. If either coordinate is outside its bounds, the ray misses the rectangle [S1, unofficial].
5.  **Hit Record Population**: If all checks pass:
    *   Set `rec.T = t`.
    *   Set `rec.P = r.At(t)`, where $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [S1, unofficial].
    *   Determine the outward normal. For an XYRect, the geometric normal is $\{0, 0, 1\}$ or $\{0, 0, -1\}$ depending on orientation [S1, unofficial].
    *   Call `rec.SetFaceNormal(r, outwardNormal)` to orient the normal against the ray direction (i.e., if $\mathbf{d} \cdot \mathbf{n} > 0$, flip $\mathbf{n}$) [S1, unofficial].
    *   Set `rec.Mat = rect.Mat` [S1, unofficial].

**Pseudocode**
```python
def hit_xy_rect(rect, ray, t_min, t_max, rec):
    # Step 1: Plane intersection for XYRect (plane z = rect.K)
    denom = ray.direction.z
    if denom == 0:
        # Division by zero; ray is parallel to plane. 
        # In floating point, t becomes inf or nan, failing bounds check.
        # Explicit check omitted in source [S1, unofficial].
        return False
    
    t = (rect.K - ray.origin.z) / denom
    
    # Step 2: Depth check
    if t < t_min or t > t_max:
        return False
        
    # Step 3: Coordinate projection
    x = ray.origin.x + t * ray.direction.x
    y = ray.origin.y + t * ray.direction.y
    
    # Step 4: Boundary check
    if x < rect.X0 or x > rect.X1 or y < rect.Y0 or y > rect.Y1:
        return False
        
    # Step 5: Hit record population
    rec.t = t
    rec.p = ray.at(t)
    
    # Outward normal for XYRect is along Z axis
    # Assuming rect.K defines the plane, normal is typically {0,0,1} or {0,0,-1}
    # Source uses {0,0,1} and relies on SetFaceNormal to orient it [S1, unofficial]
    outward_normal = Vector(0.0, 0.0, 1.0)
    rec.set_face_normal(ray, outward_normal)
    
    rec.mat = rect.mat
    return True
```

**Parameters**
*   `t_min, t_max`: Typically $[0, \infty)$ for primary rays, or adjusted for shadow rays [S1, unofficial].
*   `X0, X1, Y0, Y1, K`: Defined by the scene geometry [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Division by Zero**: If the ray direction component along the fixed axis is zero, division by zero occurs [S1, unofficial]. The source code relies on floating-point behavior (NaN/Inf) to fail the subsequent bounds check, but explicit zero-checks are omitted [S1, unofficial]. Implementers should be aware that this may cause undefined behavior in strict environments [G].
*   **Precision**: Floating-point precision errors may cause points very close to the boundary to be incorrectly classified as inside or outside [G].

## Subtopics

### [Axis-Aligned Plane Intersection](12131-axis-aligned-plane-intersection.md)
Intersects a ray with an axis-aligned plane defined by an anchor point, extent, and direction index `d`. Returns intersection distance `t` and barycentric-like coordinates `u, v`. This is a more general form that handles any axis-aligned plane, whereas the rectangle test specifically checks 2D bounds.

## Operating characteristics
*   **Time Complexity**: $O(1)$ arithmetic operations. It involves a few divisions, multiplications, and comparisons [S1, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary space [S1, unofficial].
*   **Strengths**: Extremely fast; suitable for high-performance ray tracers [S1, unofficial].
*   **Limitations**: Only applies to axis-aligned rectangles; not suitable for rotated or arbitrary planar polygons [S1, unofficial].
*   **When to use**: When rendering scenes with axis-aligned planar primitives (e.g., walls, floors, ceilings) [S1, unofficial].

## Background
The method is implemented in the GoTracer project by hexhowells [S1, unofficial]. It follows the standard analytic approach for ray-primitive intersection, decomposing the 3D problem into a 1D plane intersection and a 2D point-in-rectangle test [S1, unofficial].
