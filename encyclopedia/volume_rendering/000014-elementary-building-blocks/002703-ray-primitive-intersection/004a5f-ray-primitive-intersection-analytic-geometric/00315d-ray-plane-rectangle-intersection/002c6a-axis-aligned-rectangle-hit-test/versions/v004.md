# Axis-Aligned Rectangle Hit Test

Also called: Plane-Rectangle Intersection, XYRect/XZRect/YZRect Hit [S1, unofficial]

## Overview
The Axis-Aligned Rectangle Hit Test determines whether a ray intersects a finite, axis-aligned rectangular surface patch [S1, unofficial]. It solves the problem of intersecting a ray with a bounded planar primitive, returning the intersection point, distance, and surface normal if a hit occurs [S1, unofficial]. It is distinguished from infinite plane intersection by its additional bounds checking on the two free axes, and from general rectangle intersection by its strict alignment with the coordinate axes, which allows for a simplified implementation using a single fixed-axis formula [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, a bounding box $[t_{min}, t_{max}]$ for valid intersection distances, and a rectangle definition specifying bounds on two axes and a constant value for the third [S1, unofficial].
- **Output**: A boolean indicating hit status, and a `HitRecord` structure populated with intersection distance $t$, intersection point $\mathbf{p}$, surface normal $\mathbf{n}$, and material reference [S1, unofficial].

**Data Structures**
Rectangles are defined by structs containing bounds for two axes and a constant $K$ for the third axis [S1, unofficial]. For an XY-aligned rectangle (`XYRect`):
- `X0, X1`: Minimum and maximum X coordinates.
- `Y0, Y1`: Minimum and maximum Y coordinates.
- `K`: The constant Z coordinate of the plane.
- `Mat`: Material reference.
Similar structures exist for XZ and YZ orientations (`XZRect`, `YZRect`) [S1, unofficial].

**Steps**
1. **Compute Intersection Distance ($t$)**: Solve the plane equation for the fixed axis [S1, unofficial]. For an XYRect (fixed Z), the plane equation is $z = K$ [S1, unofficial]. The ray equation is $z(t) = o_z + t \cdot d_z$ [G]. Solving for $t$ yields $t = (K - o_z) / d_z$ [S1, unofficial].
2. **Check Distance Bounds**: Verify that $t$ lies within the valid range $[t_{min}, t_{max}]$ [S1, unofficial]. If not, the intersection is outside the desired segment [S1, unofficial].
3. **Compute Free Coordinates**: Calculate the coordinates on the two free axes at the computed $t$ [S1, unofficial]. For an XYRect: $x = o_x + t \cdot d_x$ and $y = o_y + t \cdot d_y$ [S1, unofficial].
4. **Check Spatial Bounds**: Verify that the computed coordinates lie within the rectangle's bounds: $x \in [X_0, X_1]$ and $y \in [Y_0, Y_1]$ [S1, unofficial].
5. **Populate Hit Record**: If bounds checks pass, the ray hits the rectangle [S1, unofficial]. Set intersection distance $t_{hit} = t$ [S1, unofficial]. Compute intersection point $\mathbf{p} = \mathbf{o} + t_{hit} \cdot \mathbf{d}$ [S1, unofficial]. Determine outward normal (e.g., $\mathbf{n}_{out} = (0, 0, 1)$ for XYRect) [S1, unofficial]. Orient the normal: if $\mathbf{d} \cdot \mathbf{n}_{out} > 0$, the ray hits the back face, so flip the normal ($\mathbf{n} = -\mathbf{n}_{out}$); otherwise, $\mathbf{n} = \mathbf{n}_{out}$ [G]. Assign material [S1, unofficial].

**Pseudocode**
```python
class Vector:
    def __init__(self, x, y, z):
        self.x, self.y, self.z = x, y, z
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y, self.z + other.z)
    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar, self.z * scalar)
    def dot(self, other):
        return self.x * other.x + self.y * other.y + self.z * other.z

class HitRecord:
    def __init__(self):
        self.t = 0.0
        self.p = Vector(0.0, 0.0, 0.0)
        self.normal = Vector(0.0, 0.0, 0.0)
        self.mat = None

def hit_xy_rect(rect, ray, t_min, t_max):
    # Step 1: Compute t for the fixed axis (Z)
    denom = ray.direction.z
    if denom == 0.0:
        return False  # Guard against division by zero; source relies on NaN/Inf behavior [S1, unofficial]
    t = (rect.K - ray.origin.z) / denom

    # Step 2: Check distance bounds
    if t < t_min or t > t_max:
        return False

    # Step 3: Compute free coordinates (X, Y)
    x = ray.origin.x + t * ray.direction.x
    y = ray.origin.y + t * ray.direction.y

    # Step 4: Check spatial bounds
    if x < rect.X0 or x > rect.X1 or y < rect.Y0 or y > rect.Y1:
        return False

    # Step 5: Populate HitRecord
    rec = HitRecord()
    rec.t = t
    rec.p = ray.origin + ray.direction * t

    # Outward normal for XYRect is +Z
    outward_normal = Vector(0.0, 0.0, 1.0)

    # Orient normal: if dot product > 0, ray hits back face, flip normal
    if ray.direction.dot(outward_normal) > 0:
        rec.normal = Vector(-outward_normal.x, -outward_normal.y, -outward_normal.z)
    else:
        rec.normal = outward_normal

    rec.mat = rect.Mat
    return True
```

**Parameters**
- `t_min`, `t_max`: Not given in the sources. [G] Typical values in ray tracers are $[0.001, \infty)$ or scene-specific near/far planes.
- `X0, X1, Y0, Y1`: Rectangle dimensions [S1, unofficial].

**Edge Cases and Pitfalls**
- **Division by Zero**: If the ray direction component along the fixed axis is zero, division by zero occurs [S1, unofficial]. The source code relies on floating-point behavior (producing `Inf` or `NaN`) which fails the subsequent bounds check [S1, unofficial]. Explicit checks are omitted in the reference implementation [S1, unofficial].
- **Precision**: Floating-point precision issues may cause boundary hits to be missed or double-counted [G]. Using a small epsilon for bounds checks can mitigate this [G].

## Subtopics

### [Axis-Aligned Plane Intersection](12131-axis-aligned-plane-intersection.md)
Intersects a ray with an axis-aligned plane defined by an anchor point, extent, and direction index `d`. It returns the intersection distance `t` and barycentric-like coordinates `u, v`. The method uses a direction index to permute coordinate axes, aligning the plane normal with a single axis to simplify the intersection calculation.

## Operating characteristics
- **Time Complexity**: $O(1)$ constant time [G]. Involves a few arithmetic operations and comparisons [G].
- **Memory Complexity**: $O(1)$ auxiliary space [G].
- **Strengths**: Extremely fast due to minimal branching and simple arithmetic [G]. Ideal for bounding boxes and simple planar surfaces [G].
- **Limitations**: Only works for axis-aligned rectangles [G]. Not suitable for rotated or arbitrary polygons [G].
- **When to use**: When intersecting with axis-aligned bounding boxes (AABBs) or simple planar primitives aligned with the coordinate system [G].
- **When not to use**: For rotated objects or non-axis-aligned surfaces [G].
