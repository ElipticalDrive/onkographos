# Sphere Ray Casting Benchmark Methods
Also called: Spherical glyph ray casting

## Overview
This benchmark family evaluates scalability and rendering performance for drawing spherical glyphs in 3D space using proxy geometry for pixel-perfect ray casting [S1]. It distinguishes itself from direct tessellation approaches by comparing various proxy-based ray casting techniques (instanced triangles, instanced quads, geometry-shader-generated polygons) alongside adaptive vertex distribution methods [S1].

## Shared principles
All methods in this family approximate spherical particles with simple proxy geometry and perform a ray-sphere intersection test to determine pixel coverage [S1]. The family focuses on efficient rendering of large particle counts, such as those in molecular dynamics simulations, while maintaining pixel-perfect accuracy [S1].
Key shared characteristics:
- **Proxy Geometry**: Spheres are rendered as simple geometric primitives that serve as a basis for subsequent ray casting [S1].
- **Adaptive Detail**: Adaptive techniques compute the number of vertices created for each particle based on the distance to the camera [S1].
- **Platform Constraints**: Performance measurements must account for hardware limitations, as tessellation shaders could not be made to run on the UWP on the Xbox, restricting tessellation-based measurements to desktop machines [S1].

## Subtopics

### [Adaptive Sphere/Hemisphere Techniques](9513-adaptive-sphere-hemisphere-techniques.md)
Computes the number of vertices for each particle based on camera distance. The hemisphere variant distributes vertices on the hemisphere facing the camera, whereas the sphere variant distributes them over the whole surface. Choose when dynamic level-of-detail is required for spherical particles.

### [Ray Casting on Instanced Triangles](9514-ray-casting-instanced-triangles.md)
Uses instanced triangle geometry as the proxy for ray casting. Choose for minimal vertex overhead when ray casting on simple proxies.

### [Ray Casting on Instanced Quads](9515-ray-casting-instanced-quads.md)
Uses instanced quad geometry as the proxy for ray casting. Choose when quad proxies offer better coverage or performance characteristics than triangles.

### [Ray Casting on Geometry-Shader-Generated Quads/Polygons](9516-ray-casting-geometry-shader-generated.md)
Uses geometry shaders to generate quads or polygons on the fly for ray casting. Choose when dynamic proxy generation is preferred over pre-baked instanced buffers.

### [Tessellation-Based Sphere/Hemisphere Geometry](9517-tessellation-sphere-hemisphere.md)
Creates spherical geometry on the fly using tessellation shaders. Note: This method was only measured on desktop machines due to UWP Xbox limitations. Choose when actual spherical geometry is preferred over flat proxies, provided the target platform supports tessellation shaders.

## Background
The benchmark family was introduced to characterize scalability for spherical glyph rendering across varying input parameters and computing resources [S1]. The methods build on earlier work by Gumhold (2003) regarding pixel-perfect sphere ray casting using proxy geometry [S1].
The benchmarks were tested using real-world molecular dynamics data sets (a time step from the formation of a liquid layer and a time step from a laser ablation simulation) and uniformly distributed random particles positioned in a $10^3$ unit domain [S1]. A significant constraint noted during development was the inability to run tessellation shaders on the UWP platform for Xbox, which limited the scope of tessellation-based measurements to desktop environments [S1].
