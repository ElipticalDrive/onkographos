# Ray-Splat Intersection (Sphere Approximation)
Also called: Approximate Sphere Splat Intersection, Splat Sphere Hit Test

## Overview
This method approximates the intersection of a viewing ray with a Gaussian splat by treating the splat as a sphere, rather than computing the exact intersection with its true ellipsoidal shape [S1, unofficial]. It serves as a faster but less accurate alternative to ellipsoid-based raycasting [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized) [S1, unofficial].
- Splat center $\mathbf{c}$ (world space) [S1, unofficial].
- Splat scale components $s_x, s_y, s_z$ [S1, unofficial].
- Splat render mode (2D or 3D) [S1, unofficial].
- Splat global index [S1, unofficial].

**Outputs:**
- Boolean indicating intersection [S1, unofficial].
- Hit distance $t$ (if intersected) [S1, unofficial].
- Hit point (if intersected) [S1, unofficial].
- Splat global index (if intersected) [S1, unofficial].

**Data Structures:**
- `tempCenter`: Vector3 representing the splat's world-space center [S1, unofficial].
- `tempScale`: Vector3 representing the splat's scale factors [S1, unofficial].
- `SplatRenderMode`: Enum with values `TwoD` and `ThreeD` [S1, unofficial].

**Steps:**
1. **Calculate Approximate Radius:** Compute a scalar radius $r$ that represents the splat's effective size [S1, unofficial]. The formula depends on the render mode:
   - If `SplatRenderMode.ThreeD`:
     $$ r = \frac{s_x + s_y + s_z}{3} $$
   - If `SplatRenderMode.TwoD` (or default):
     $$ r = \frac{s_x + s_y}{2} $$
   [S1, unofficial]
2. **Ray-Sphere Intersection Test:** Perform a standard ray-sphere intersection test using $\mathbf{o}$, $\mathbf{d}$, $\mathbf{c}$, and $r$ [S1, unofficial]. This builds on the analytical method described in [Ray-Sphere Intersection](3539-ray-sphere-intersection.md).
3. **Record Hit:** If the intersection test returns a valid hit (distance $t > 0$), record the hit point, the distance $t$, and the splat's global index [S1, unofficial].

**Pseudocode:**
```python
class SplatRenderMode:
    TwoD = 0
    ThreeD = 1

def ray_splat_intersection_sphere_approx(ray_origin, ray_direction, splat_center, splat_scale, render_mode, splat_index):
    # Step 1: Calculate approximate radius
    if render_mode == SplatRenderMode.ThreeD:
        radius = (splat_scale.x + splat_scale.y + splat_scale.z) / 3.0
    else:
        radius = (splat_scale.x + splat_scale.y) / 2.0

    # Step 2: Ray-sphere intersection
    oc = ray_origin - splat_center
    a = dot(ray_direction, ray_direction)
    b = 2.0 * dot(oc, ray_direction)
    c = dot(oc, oc) - radius * radius
    discriminant = b * b - 4.0 * a * c

    if discriminant < 0:
        return None

    sqrt_disc = sqrt(discriminant)
    t1 = (-b - sqrt_disc) / (2.0 * a)
    t2 = (-b + sqrt_disc) / (2.0 * a)

    # Choose the smallest positive t
    t = t1 if t1 > 0 else t2
    if t <= 0:
        t = t2 if t2 > 0 else None

    if t is None:
        return None

    # Step 3: Record hit
    hit_point = ray_origin + ray_direction * t
    return {'t': t, 'point': hit_point, 'index': splat_index}
```

**Edge Cases and Pitfalls:**
- This method is used when `raycastAgainstTrueSplatEllipsoid` is false, serving as a faster but less accurate approximation than the ellipsoid method [S1, unofficial].

## Subtopics

### Fast Sphere Rendering via Ray-Sphere Test
A method to render spheres using only their radii and centers, avoiding polygon tessellation [S2]. It renders a rectangular region tightly fitting the perspective-projected sphere on the screen and performs a ray-sphere intersection test in the fragment shader [S2]. In the vertex shader, the rectangular region is specified [S2]. For each fragment in this region, an intersection test for the viewing ray and the sphere is performed in the fragment shader [S2]. Fragments with no intersection are discarded [S2]. Only the front or back face of the sphere, whichever is farther away from the previous intersection point, is rendered, as depth peeling does not require both [S2].

## Operating characteristics
Time and memory complexity are not given in the sources. Performance is faster than ellipsoid intersection, but accuracy is lower [S1, unofficial]. Specific conditions for use or avoidance are not given in the sources.

## Background
This method is implemented in GaussianSplats3D, where it is toggled via the `raycastAgainstTrueSplatEllipsoid` flag [S1, unofficial].
