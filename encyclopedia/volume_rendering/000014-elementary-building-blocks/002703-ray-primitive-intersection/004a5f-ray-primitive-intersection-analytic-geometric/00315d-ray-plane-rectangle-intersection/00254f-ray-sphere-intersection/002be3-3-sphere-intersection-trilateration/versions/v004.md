# 3-Sphere Intersection (Trilateration)
Also called: Sphere Trilateration, Trilateration

## Overview
The 3-Sphere Intersection method computes the geometric intersection points of the surfaces of three spheres, generating new sample points on the boundary of a carved volume [S1, S2]. It solves the system of equations defined by the sphere boundaries to find positions that lie on all three surfaces simultaneously [S1, S2]. Unlike [Ray-Sphere Intersection](3539-ray-sphere-intersection.md), which finds where a ray enters or exits a single sphere, this method determines the specific vertices formed by the mutual overlap of three distinct spheres, a process essential for advancing the surface boundary in sphere carving algorithms [S1].

## How it works
**Inputs:** Three spheres $S_0, S_1, S_2$, defined by their centers $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ and radii $r_0, r_1, r_2$.
**Outputs:** A set of intersection points $\mathbf{p}$. Typically, there are two solutions (symmetric with respect to the plane defined by the centers), or none if the spheres do not intersect at a common point.

**Data Structures:**
The method operates on 3D vectors. No persistent data structures are required beyond the input sphere parameters.

**Steps:**

1.  **Define Local Frame:** Construct an orthonormal basis $(\mathbf{e}_x, \mathbf{e}_y, \mathbf{e}_z)$ aligned with the plane passing through the centers $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$.
    *   Compute $\mathbf{e}_z$ as the normalized cross product of the vectors connecting the centers:
        $$ \mathbf{e}_z = \frac{(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)}{\|(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)\|} $$
    *   Compute $\mathbf{e}_x$ as the normalized vector from $\mathbf{p}_0$ to $\mathbf{p}_1$:
        $$ \mathbf{e}_x = \frac{\mathbf{p}_1 - \mathbf{p}_0}{\|\mathbf{p}_1 - \mathbf{p}_0\|} $$
    *   Compute $\mathbf{e}_y$ to complete the right-handed orthonormal basis. The source text explicitly states $\mathbf{e}_y = \mathbf{e}_x \times \mathbf{e}_x$ [S1, S2]. Note: Mathematically, $\mathbf{e}_x \times \mathbf{e}_x = \mathbf{0}$, which is a typo in the source. To form a valid orthonormal frame where $\mathbf{e}_z$ is the normal to the plane of centers, $\mathbf{e}_y$ must be orthogonal to both $\mathbf{e}_x$ and $\mathbf{e}_z$. The standard construction is $\mathbf{e}_y = \mathbf{e}_z \times \mathbf{e}_x$ (or $\mathbf{e}_x \times \mathbf{e}_z$ depending on handedness). Given $\mathbf{e}_z$ is the normal, $\mathbf{e}_y = \mathbf{e}_z \times \mathbf{e}_x$ ensures $\mathbf{e}_x, \mathbf{e}_y, \mathbf{e}_z$ form a right-handed system. [G] Implementation should use $\mathbf{e}_y = \mathbf{e}_z \times \mathbf{e}_x$.

2.  **Compute Local Coordinates of Centers:**
    *   $a = \|\mathbf{p}_1 - \mathbf{p}_0\|$
    *   $b = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_x$
    *   $c = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_y$

3.  **Solve for Local Coordinates $(x, y, z)$:**
    The system of equations in the local frame is:
    $$ x^2 + y^2 + z^2 = r_0^2 $$
    $$ (x - a)^2 + y^2 + z^2 = r_1^2 $$
    $$ (x - b)^2 + (y - c)^2 + z^2 = r_2^2 $$

    *   **Solve for $x$:**
        $$ x = \frac{r_0^2 - r_1^2 + a^2}{2a} $$

    *   **Solve for $y$:**
        $$ y = \frac{r_1^2 - r_2^2 - (x - a)^2 + (x - b)^2 + c^2}{2c} $$
        *Note: This division by $2c$ requires $c \neq 0$. If $c=0$, the centers are collinear or degenerate in the local y-direction, requiring special handling.*

    *   **Solve for $z$:**
        $$ z = \sqrt{r_0^2 - x^2 - y^2} $$
        This step is valid only if the term under the radical is non-negative ($r_0^2 - x^2 - y^2 \ge 0$). If negative, the spheres do not intersect at a common point.

4.  **Transform Back to Original Frame:**
    The intersection points are given by:
    $$ \mathbf{p} = \mathbf{p}_0 + x \cdot \mathbf{e}_x + y \cdot \mathbf{e}_y \pm z \cdot \mathbf{e}_z $$
    This yields two points, symmetric with respect to the plane defined by the three centers.

**Pseudocode:**

```python
import math
from typing import List, Tuple

def cross(v1: List[float], v2: List[float]) -> List[float]:
    return [
        v1[1]*v2[2] - v1[2]*v2[1],
        v1[2]*v2[0] - v1[0]*v2[2],
        v1[0]*v2[1] - v1[1]*v2[0]
    ]

def dot(v1: List[float], v2: List[float]) -> float:
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def sub(v1: List[float], v2: List[float]) -> List[float]:
    return [v1[0]-v2[0], v1[1]-v2[1], v1[2]-v2[2]]

def add(v1: List[float], v2: List[float]) -> List[float]:
    return [v1[0]+v2[0], v1[1]+v2[1], v1[2]+v2[2]]

def scale(v: List[float], s: float) -> List[float]:
    return [v[0]*s, v[1]*s, v[2]*s]

def norm(v: List[float]) -> float:
    return math.sqrt(dot(v, v))

def normalize(v: List[float]) -> List[float]:
    n = norm(v)
    if n == 0:
        return [0, 0, 0] # Degenerate case
    return scale(v, 1.0/n)

def sphere_trilateration(p0: List[float], r0: float,
                         p1: List[float], r1: float,
                         p2: List[float], r2: float) -> List[List[float]]:
    """
    Computes the intersection points of three spheres.
    Returns a list of intersection points (0, 1, or 2 points).
    """
    # Step 1: Define Local Frame
    # ez = normalized((p1 - p0) x (p2 - p0))
    v1 = sub(p1, p0)
    v2 = sub(p2, p0)
    cross_prod = cross(v1, v2)
    norm_cross = norm(cross_prod)
    
    # If centers are collinear, the plane is undefined.
    if norm_cross == 0:
        return [] # Degenerate input

    ez = normalize(cross_prod)
    
    # ex = normalized(p1 - p0)
    norm_v1 = norm(v1)
    if norm_v1 == 0:
        return [] # p0 and p1 are identical
    
    ex = normalize(v1)
    
    # ey = ez x ex (Correcting source typo e_x x e_x)
    ey = cross(ez, ex)

    # Step 2: Compute Local Coordinates
    a = norm_v1
    b = dot(v2, ex)
    c = dot(v2, ey)

    # Step 3: Solve for x, y, z
    # Solve for x
    x = (r0**2 - r1**2 + a**2) / (2 * a)

    # Solve for y
    # Check for division by zero
    if abs(c) < 1e-9:
        return [] # Degenerate case where p2 lies on the x-axis in local frame

    y = (r1**2 - r2**2 - (x - a)**2 + (x - b)**2 + c**2) / (2 * c)

    # Solve for z
    rad = r0**2 - x**2 - y**2
    
    if rad < 0:
        return [] # No intersection

    z = math.sqrt(rad)

    # Step 4: Transform back to original frame
    # p = p0 + x*ex + y*ey +/- z*ez
    
    term_xy = add(scale(ex, x), scale(ey, y))
    
    p_plus = add(p0, add(term_xy, scale(ez, z)))
    p_minus = add(p0, add(term_xy, scale(ez, -z)))
    
    return [p_plus, p_minus]
```

**Parameters:**
*   $a = \|\mathbf{p}_1 - \mathbf{p}_0\|$
*   $b = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_x$
*   $c = (\mathbf{p}_2 - \mathbf{p}_0) \cdot \mathbf{e}_y$

**Edge Cases and Pitfalls:**
*   **Collinear Centers:** If $\mathbf{p}_0, \mathbf{p}_1, \mathbf{p}_2$ are collinear, the cross product $(\mathbf{p}_1 - \mathbf{p}_0) \times (\mathbf{p}_2 - \mathbf{p}_0)$ is zero, making $\mathbf{e}_z$ undefined. The method fails or requires a different basis construction [S1, S2].
*   **Identical Centers:** If $\mathbf{p}_0 = \mathbf{p}_1$, $a=0$, leading to division by zero in the calculation of $x$ [S1, S2].
*   **Degenerate Local Y:** If $c=0$, the denominator in the $y$ calculation is zero. This occurs if $\mathbf{p}_2 - \mathbf{p}_0$ is parallel to $\mathbf{e}_x$ (i.e., $\mathbf{p}_2$ lies on the line connecting $\mathbf{p}_0$ and $\mathbf{p}_1$ in the local frame) [S1, S2].
*   **No Intersection:** If $r_0^2 - x^2 - y^2 < 0$, the spheres do not share a common intersection point [S1, S2].

## Subtopics

### Ray-Splat Intersection (Sphere Approximation)
*   **What it is:** Approximates a primitive using a sphere for intersection testing.
*   **Difference:** Uses a single sphere for ray intersection, whereas 3-Sphere Intersection finds the vertex of three spheres.
*   **When to choose:** When performance is critical and approximate bounds are sufficient.
*   **Link:** [Ray-Splat Intersection (Sphere Approximation)](7123-ray-splat-intersection-sphere-approximation.md)

### Spherical Medium Density Integration
*   **What it is:** Integrates density along a ray through a spherical medium.
*   **Difference:** Focuses on volume integration (transmittance/absorption) rather than geometric surface intersection.
*   **When to choose:** For rendering participating media within spherical volumes.
*   **Link:** [Spherical Medium Density Integration](9077-spherical-medium-density-integration.md)

### Pulsar Forward Pass (Sphere Intersection and Draw)
*   **What it is:** A rendering pass that intersects spheres and draws them.
*   **Difference:** Uses sphere intersection for rasterization/visibility, not for computing boundary points via trilateration.
*   **When to choose:** For forward rendering of point-based or sphere-based primitives.
*   **Link:** [Pulsar Forward Pass (Sphere Intersection and Draw)](9396-pulsar-forward-pass-sphere-intersection-and-draw.md)

### Inverse Transforming Spheres
*   **What it is:** Applies inverse transformations to spheres.
*   **Difference:** Deals with coordinate space transformation of the primitive itself, not the intersection of multiple primitives.
*   **When to choose:** When spheres are defined in a local space and need to be tested in world or view space.
*   **Link:** [Inverse Transforming Spheres](10196-inverse-transforming-spheres.md)

## Operating characteristics
*   **Time Complexity:** Constant time $O(1)$ per triplet of spheres, involving a fixed number of arithmetic operations and square roots.
*   **Memory Complexity:** Constant space $O(1)$, requiring only storage for the input parameters and local basis vectors.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The method scales linearly with the number of sphere triplets considered in a carving iteration.
*   **Strengths:** Provides exact geometric intersection points, ensuring convergence in sphere carving algorithms by placing new spheres on the boundary [S1].
*   **Limitations:** Fails on degenerate inputs (collinear or identical centers). Requires the term under the radical to be non-negative.
*   **When to use:** When generating new sample points on the boundary of a carved volume defined by a set of spheres [S1].
*   **When not:** When spheres do not intersect at a common point, or when the centers are degenerate.

## Background
The method originates from the Sphere Carving algorithm, introduced by Cédric Zanni in 2024 [S1, S2]. It is used to compute the set of points $P_k$ on the surface of the carved volume $V_k$ by finding the intersections of three spheres from the current set $S_k$ [S1]. This technique ensures that new spheres placed at these intersections will create new intersections in the next step, facilitating the convergence of the carving process towards the target shape [S1]. The specific trilateration formulas are detailed in Appendix A.2 of the source paper [S1, S2].
