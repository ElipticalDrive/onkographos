# Ray-Segment Intersection

Also called: 2D Ray-Segment Intersection, 2D cross-product intersection, Cramer's-rule ray-segment intersection, Ray vs. Line-Segment Intersection, rayTrace

## Overview
Computes the intersection between a 2D ray (origin $O$, direction $D$) and a line segment (endpoints $A, B$), returning the intersection point and validity parameters $t$ and $s$ [S1, S2, unofficial]. It is distinguished from [Linear Edge Intersection](868-linear-edge-intersection.md) by its explicit handling of the ray's forward direction constraint and the segment's bounded domain via Cramer's rule, rather than solving for infinite lines [S1, S2, unofficial].

## How it works
**Inputs:**
- Ray origin: $O = (ox, oy)$
- Ray direction: $D = (dx, dy)$ (normalized or unnormalized)
- Segment endpoints: $A = (ax, ay)$, $B = (bx, by)$

**Outputs:**
- Intersection point: $P = (x, y)$
- Ray parameter: $t$
- Segment parameter: $s$
- Validity flag: `valid` (boolean)

**Data Structures:**
- No complex structures; returns a tuple or object containing $t, s, x, y, valid$.

**Steps:**
1. Compute segment vector: $S = B - A = (sx, sy) = (bx - ax, by - ay)$ [S1, S2, unofficial].
2. Compute denominator: $denom = D \times S = dx \cdot sy - dy \cdot sx$ [S1, S2, unofficial].
3. Check for parallelism: If $|denom| < \epsilon$ (where $\epsilon = 10^{-9}$), return null/invalid [S1, S2, unofficial].
4. Compute ray parameter $t$:
   $$ t = \frac{(A - O) \times S}{denom} = \frac{(ax - ox) \cdot sy - (ay - oy) \cdot sx}{denom} $$
   [S1, S2, unofficial]
5. Compute segment parameter $s$:
   $$ s = \frac{(A - O) \times D}{denom} = \frac{(ax - ox) \cdot dy - (ay - oy) \cdot dx}{denom} $$
   [S1, S2, unofficial]
6. Check validity:
   - $t \ge 0$ (intersection is in forward ray direction) [S1, S2, unofficial].
   - $0 \le s \le 1$ (intersection lies within segment bounds) [S1, S2, unofficial].
   - If both conditions hold, the intersection is valid.
7. Compute intersection point:
   $$ x = ox + dx \cdot t $$
   $$ y = oy + dy \cdot t $$
   [S1, S2, unofficial]

**Pseudocode:**
```python
def ray_segment_intersect(ox, oy, dx, dy, ax, ay, bx, by):
    # 1. Segment vector
    sx = bx - ax
    sy = by - ay
    
    # 2. Denominator (2D cross product of D and S)
    denom = dx * sy - dy * sx
    
    # 3. Parallel check
    if abs(denom) < 1e-9:
        return None
        
    # 4. Ray parameter t
    t = ((ax - ox) * sy - (ay - oy) * sx) / denom
    
    # 5. Segment parameter s
    s = ((ax - ox) * dy - (ay - oy) * dx) / denom
    
    # 6. Validity check
    if t >= 0 and 0 <= s <= 1:
        # 7. Intersection point
        x = ox + dx * t
        y = oy + dy * t
        return {'t': t, 's': s, 'x': x, 'y': y, 'valid': True}
    else:
        return None
```

**Parameters:**
- $\epsilon = 10^{-9}$ for parallelism check [S1, unofficial].

**Edge Cases:**
- Parallel rays/segments: Handled by denominator threshold [S1, S2, unofficial].
- Intersection behind ray start: Handled by $t \ge 0$ check [S2, unofficial].
- Intersection outside segment bounds: Handled by $0 \le s \le 1$ check [S1, S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ constant time operations.
- **Memory Complexity:** $O(1)$ space.
- **Strengths:** Simple, robust for 2D, handles bounded segments and forward rays explicitly.
- **Limitations:** Only applicable in 2D. Precision issues may arise with very small or large coordinates if $\epsilon$ is not adjusted.
- **When to use:** 2D raycasting, collision detection with walls/edges, dungeon generation validation.
- **When not to use:** 3D scenes, infinite lines, or when performance is critical and many intersections are expected (consider spatial partitioning).

## Background
Originated in computer graphics for raycasting engines, specifically for 2D maze/wall intersection [S1, unofficial]. Used in procedural dungeon generation to validate corridor connections and wall placements [S2, unofficial].
