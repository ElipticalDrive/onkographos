# Ray-Primitive and Segment Intersection

Also called: Intersection Ordering Optimization, Ray-Primitive and Segment Intersection Ordering

## Overview
This method optimizes the evaluation of multiple ray-primitive intersections along a single ray by enforcing a strict processing order: intersection points are computed before intersection segments. It solves the problem of redundant or unnecessary geometric calculations in volume rendering and ray tracing, where the result of a closer intersection (typically a surface point) can truncate, modify, or entirely invalidate the computation of further segments. It sets itself apart from sibling intersection tests (like [Ray-box intersection](776-ray-box-intersection.md)) by focusing not on the geometric test itself, but on the *ordering* and *culling* of those tests to minimize shader or kernel workload.

## How it works
The method operates on a set of potential intersections along a ray, categorized into intersection points (Class 1) and intersection segments (Classes 2 and 3, or general segments). The core logic relies on the principle that the closest intersection point determines the state of the ray for all subsequent calculations.

### Inputs and Outputs
*   **Input**: A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a list of objects, each with a bounding box and an intersection class (1, 2, or 3).
*   **Output**: A processed sequence of intersection data passed to a shading routine, with unnecessary segment calculations eliminated.

### Data Structures
*   **Intersection Point List ($P$)**: Contains Class 1 intersections. Each entry stores the distance $t$ where the ray enters the object's bounding box.
*   **Intersection Segment List ($S$)**: Contains Class 2 (average value) and Class 3 (max-value) intersections. Each entry stores the entry and exit distances of the ray within the object's bounding box.
*   **$D_{min}$**: A scalar variable initialized to infinity, tracking the distance of the closest intersection point found so far.

### Numbered Steps

1.  **Bounding Box Test**: For each object, compute the entry and exit points of the ray against its bounding box. If no intersection, discard the object.
2.  **Categorization**:
    *   Class 1 (Surface/Point): The intersection is a specific point (e.g., a surface hit). Distance metric is the entry point into the bounding box.
    *   Class 2 (Segment/Average): The intersection is a segment requiring an average value calculation. Distance metric is the exit point of the bounding box.
    *   Class 3 (Segment/Max): The intersection is a segment requiring a maximum value projection. Distance metric is the exit point of the bounding box.
3.  **Sorting**: Sort the lists $P$ and $S$ based on their distance metrics. Class 1 entries are sorted by entry distance. Class 2 and 3 entries are sorted by exit distance.
4.  **Process Points**: Initialize $D_{min} = \infty$. Iterate through the sorted list $P$. For each point at distance $t_p$:
    *   If $t_p < D_{min}$, update $D_{min} = t_p$.
    *   This establishes the closest intersection point along the ray.
5.  **Process Segments**: Iterate through the sorted list $S$. For each segment with entry $t_{start}$ and exit $t_{end}$:
    *   **Case A: Point within Segment**: If a Class 1 intersection point $P$ exists such that $t_{start} < t_P < t_{end}$, the segment is split. Compute the intersection value only for the sub-segment *outside* the point (typically the portion after $t_P$ if the point occludes the front, or as defined by the specific projection class). Do not compute the entire segment.
    *   **Case B: Point before Segment**: If the closest point $D_{min}$ is less than $t_{start}$, the segment is potentially occluded or modified.
        *   For Class 2 (Average): Compute the average value for the segment, but if the point $D_{min}$ is inside the segment, only compute the portion after $D_{min}$.
        *   For Class 3 (Max): Perform the Class 1 calculation first (if not already done) to establish the max value $v_t$ up to point $P_t$. During the segment traversal, if a value $v_2$ is encountered such that $v_2 > v_t$, terminate the segment calculation early.
    *   **Case C: Point after Segment**: If $D_{min} > t_{end}$, the segment is processed normally as it is closer than any point.
    *   **Early Termination**: If a segment is fully occluded by a closer point (depending on the projection class semantics), skip the segment calculation entirely.

### Formulas
*   **Bounding Box Intersection**: Standard slab method to find $t_{entry}$ and $t_{exit}$.
*   **Distance Metric for Sorting**:
    *   Class 1: $d = t_{entry}$
    *   Class 2, 3: $d = t_{exit}$
*   **Max-Value Early Termination**:
    $$ \text{if } v_{current} > v_{max\_so\_far} \text{ then terminate} $$
    Where $v_{max\_so\_far}$ is established by the Class 1 intersection if it is closer.

### Pseudocode

```python
def process_intersections(ray_origin, ray_dir, objects):
    """
    objects: list of dicts with keys:
      'bbox': (t_min, t_max) from ray-box intersection
      'class': 1, 2, or 3
      'compute_point': function(t) -> value (for Class 1)
      'compute_segment': function(t_start, t_end) -> value (for Class 2/3)
    """
    points = []
    segments = []

    # Step 1 & 2: Bounding box and categorization
    for obj in objects:
        t_min, t_max = ray_box_intersect(ray_origin, ray_dir, obj.bbox)
        if t_min is None:
            continue
        
        if obj.class == 1:
            # Class 1: Sort by entry
            points.append({'t': t_min, 'obj': obj, 't_min': t_min, 't_max': t_max})
        else:
            # Class 2 & 3: Sort by exit
            segments.append({'t': t_max, 'obj': obj, 't_min': t_min, 't_max': t_max})

    # Step 3: Sort
    points.sort(key=lambda x: x['t'])
    segments.sort(key=lambda x: x['t'])

    # Step 4: Process Points
    d_min = float('inf')
    closest_point_val = None
    
    # We need to track the closest point to cull segments
    # Also, for Class 3, we need the max value up to the closest point
    max_val_up_to_point = float('-inf')

    for p in points:
        t_p = p['t']
        if t_p < d_min:
            d_min = t_p
            # Compute the point value if needed for Class 3 logic
            # Note: In a real implementation, compute_point might be expensive
            # so we might defer it, but the logic requires it for Class 3 culling
            val = p['obj'].compute_point(t_p)
            if p['obj'].class == 3:
                max_val_up_to_point = val
            closest_point_val = val

    # Step 5: Process Segments
    results = []
    
    for seg in segments:
        t_start = seg['t_min']
        t_end = seg['t_max']
        obj = seg['obj']
        
        # Check if the segment is fully behind the closest point
        # For Class 1 occlusion, if d_min < t_start, the point is in front.
        # The handling depends on the specific projection class.
        
        if obj.class == 1:
            # Should not happen in segments list, but for completeness
            results.append(obj.compute_segment(t_start, t_end))
            
        elif obj.class == 2:
            # Average value projection
            # If the closest point is inside this segment, split it
            if d_min > t_start and d_min < t_end:
                # Compute only the part after the point
                val = obj.compute_segment(d_min, t_end)
                results.append(val)
            else:
                # Compute full segment if no closer point interferes
                # Or if the point is behind
                if d_min < t_start:
                    # Point is in front. Depending on occlusion model, 
                    # this segment might be occluded or just start after the point.
                    # Standard assumption: compute segment from max(t_start, d_min) to t_end
                    # If d_min < t_start, start is t_start.
                    val = obj.compute_segment(t_start, t_end)
                    results.append(val)
                else:
                    # d_min > t_end, segment is fully in front of point
                    val = obj.compute_segment(t_start, t_end)
                    results.append(val)

        elif obj.class == 3:
            # Max value projection
            # Early termination logic
            current_max = max_val_up_to_point
            
            # If the segment is fully behind the closest point, 
            # we might still need to check if it contains a higher max.
            # However, if the point is inside the segment, we start after it.
            
            effective_start = t_start
            if d_min > t_start and d_min < t_end:
                effective_start = d_min
                # Update current_max with the point value if it wasn't already
                # (Assuming compute_point was called in Step 4)
            
            if effective_start >= t_end:
                continue # Segment fully occluded or behind point
            
            # Perform segment traversal with early termination
            # This is a simplified representation of the traversal
            val = obj.compute_segment_with_cull(effective_start, t_end, current_max)
            results.append(val)

    return results
```

### Parameters and Edge Cases
*   **$D_{min}$ Initialization**: Must be infinity. If no Class 1 points exist, $D_{min}$ remains infinity, and all segments are processed normally.
*   **Parallel Rays/Segments**: In the underlying [Ray-Segment Intersection](868-linear-edge-intersection.md) or ray-box tests, if the denominator is near zero, the intersection is invalid.
*   **Degenerate Bounding Boxes**: If $t_{min} == t_{max}$, the ray grazes the box. Treat as a point intersection (Class 1) or handle as a zero-length segment.
*   **Precision**: Floating-point errors near $t_{min}$ or $t_{max}$ can cause segments to be incorrectly culled or duplicated. Use a small epsilon for comparisons.

## Subtopics

### [Linear Edge Intersection](868-linear-edge-intersection.md)
Linear Edge Intersection calculates the exact position where an isosurface (defined by a scalar field threshold) intersects a straight edge connecting two grid vertices, assuming the scalar field varies linearly between those vertices. It solves the geometric problem of locating zero-crossings (or threshold crossings) on discrete grid structures, which is a fundamental step in algorithms like Marching Cubes, Dual Contouring, and ray-marching volume rendering. Unlike [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md), which determines *which* voxel a ray enters, this method determines *where* on a specific segment the surface lies. It is distinguished from [Linear Intersection Approximation](1232-linear-intersection-approximation.md) by using the actual scalar values at the endpoints rather than assuming the midpoint.

### [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md)
This method extracts spatial information from a 3D simulation or volume by determining which voxel corresponds to a user's screen coordinate click. It solves the problem of mapping 2D framebuffer coordinates to 3D volume grid indices for direct manipulation tasks such as segmentation or painting. It differs from [Ray-Box Intersection for Interaction](2638-ray-box-intersection-for-interaction.md) by focusing on discrete voxel traversal (often via Bresenham's algorithm) rather than continuous geometric intersection for physics injection, and from [Linear Edge Intersection](868-linear-edge-intersection.md) by operating on the volume grid rather than mesh edges.

### Ray-Segment Intersection
#### definition
[S2, unofficial] Computes the intersection between a ray defined by origin O and direction D, and a line segment defined by endpoints A and B. Returns the intersection point and validity parameters t and s.

#### formula
[S2, unofficial] 
$$ s_x = b_x - a_x, \quad s_y = b_y - a_y $$
$$ \text{denom} = d_x s_y - d_y s_x $$
$$ t = \frac{(a_x - o_x) s_y - (a_y - o_y) s_x}{\text{denom}} $$
$$ s = \frac{(a_x - o_x) d_y - (a_y - o_y) d_x}{\text{denom}} $$
Valid if $t \ge 0$ AND $0 \le s \le 1$.
Hit point: $x = o_x + d_x t, \quad y = o_y + d_y t$.

#### code
[S2, unofficial]
```python
def ray_segment_intersect(ox, oy, dx, dy, ax, ay, bx, by):
    sx = bx - ax
    sy = by - ay
    denom = dx * sy - dy * sx
    if abs(denom) < 1e-9:
        return None
    t = ((ax - ox) * sy - (ay - oy) * sx) / denom
    s = ((ax - ox) * dy - (ay - oy) * dx) / denom
    return {
        't': t,
        's': s,
        'denom': denom,
        'x': ox + dx * t,
        'y': oy + dy * t,
        'valid': t >= 0 and s >= 0 and s <= 1
    }
```

#### pitfall
[S2, unofficial] If the denominator is near zero (parallel rays/segments), the intersection is invalid. The code uses a threshold of 1e-9.

## Operating characteristics
*   **Time Complexity**: Sorting takes $O(N \log N)$ where $N$ is the number of objects. Processing is $O(N)$ in the worst case, but often significantly faster due to early termination.
*   **Memory Complexity**: $O(N)$ to store the point and segment lists.
*   **Strengths**: Reduces the number of expensive shading/intersection calculations. Particularly effective when Class 1 (surface) intersections are frequent and occlude many segments.
*   **Limitations**: Requires pre-computation of bounding boxes and sorting. Overhead may not be justified for very simple scenes with few objects.
*   **When to Use**: Volume rendering with mixed surface and volume objects, or ray tracing with many potential intersections.
*   **When Not to Use**: Simple scenes with no occlusion potential, or where the cost of sorting exceeds the savings from culling.

## Background
The method originates from volumetric ray tracing optimization techniques, specifically described in the context of ordering intersection calculations to decrease total computation [S1, unofficial]. It is a foundational concept in modern ray tracers and volume renderers that handle complex scenes with multiple object types.
