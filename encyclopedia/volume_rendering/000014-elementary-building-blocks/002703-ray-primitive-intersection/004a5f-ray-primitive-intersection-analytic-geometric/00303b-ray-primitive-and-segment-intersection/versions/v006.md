# Ray-Primitive and Segment Intersection

Also called: Intersection Ordering Optimization, Ray-Primitive and Segment Intersection Ordering

## Overview
This method optimizes the evaluation of volumetric ray primitives by determining the correct processing order of intersection points and segments along a ray, and provides the geometric primitives for intersecting rays with line segments. It solves the problem of redundant or incorrect shading calculations when multiple objects or data structures intersect a single ray. It sets itself apart from sibling methods like [Sphere Intersection](1620-sphere-intersection.md) and [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) by focusing on the *ordering* and *culling* of intersection results rather than the analytic solution of a single primitive, and from [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) by handling general bounding box hierarchies rather than specific voxel grid traversal.

## How it works
The method consists of two distinct components: an optimization strategy for ordering intersection evaluations based on bounding boxes, and the geometric algorithm for intersecting a ray with a line segment.

### Inputs and Outputs
**Inputs:**
- Ray defined by origin $\mathbf{o} = (o_x, o_y)$ and direction $\mathbf{d} = (d_x, d_y)$ [S2, unofficial].
- List of objects, each with an axis-aligned bounding box (AABB) [S1, unofficial].
- For segment intersection: Segment endpoints $\mathbf{A} = (a_x, a_y)$ and $\mathbf{B} = (b_x, b_y)$ [S2, unofficial].

**Outputs:**
- Sorted list of intersection points and segments to be processed by the shader [S1, unofficial].
- For segment intersection: Intersection parameter $t$, segment parameter $s$, and validity flag [S2, unofficial].

### Data Structures
1.  **Intersection Point List ($P$):** Contains objects classified as Class 1 (surface intersections). Each entry stores the object ID and the distance to the entry point of its bounding box [S1, unofficial].
2.  **Intersection Segment List ($S$):** Contains objects classified as Class 2 or 3 (volumetric/average/max-value projections). Each entry stores the object ID and the distance to the exit point of its bounding box [S1, unofficial].
3.  **Bounding Box:** Defined by minimum and maximum coordinates. Used to compute entry and exit distances for the ray [S1, unofficial].

### Numbered Steps

#### Part 1: Intersection Ordering Optimization [S1, unofficial]

1.  **Bounding Box Intersection:** For each object, compute the entry and exit points of the ray with its bounding box. Determine if the ray intersects the box.
2.  **Classification:**
    -   **Class 1:** Surface intersection objects. Distance metric is the entry point of the bounding box.
    -   **Class 2:** Average-value projection objects. Distance metric is the exit point of the bounding box.
    -   **Class 3:** Max-value projection objects. Distance metric is the exit point of the bounding box.
3.  **Sorting:** Sort the lists $P$ and $S$ by distance.
    -   $P$ is sorted by entry distance.
    -   $S$ is sorted by exit distance.
    -   *Note:* The sources imply a unified processing order where Class 1 points are processed before Class 2/3 segments that might contain them, or segments that are occluded by closer Class 1 points [S1, unofficial].
4.  **Initialize Tracker:** Set $D_{min} = \infty$. This variable tracks the closest intersection point found so far.
5.  **Process Intersection Points (Class 1):**
    -   Iterate through the sorted list $P$.
    -   For each point, if its distance is less than $D_{min}$, update $D_{min}$ to this distance.
    -   This establishes the closest surface intersection $P_t$ [S1, unofficial].
6.  **Process Intersection Segments (Class 2/3):**
    -   Iterate through the sorted list $S$.
    -   Use $D_{min}$ to cull or terminate calculations:
        -   If a Class 1 intersection occurs within a Class 4 (or general) segment, compute the average value only for the sub-segment *outside* the Class 1 intersection, not the entire segment [S1, unofficial].
        -   If a Class 1 intersection occurs after a Class 2 or 3 intersection start, perform the Class 1 calculation first. This reduces the segment length for the Class 2/3 calculation or allows early termination of Class 3 [S1, unofficial].
        -   **Class 3 Early Termination:** For max-value projection, if the maximum value encountered along the ray up to point $P_t$ is $v_t$, the Class 3 calculation can terminate as soon as a value $v_2$ is encountered such that $v_2 > v_t$. This requires the Class 1 calculation to be performed first to establish $P_t$ [S1, unofficial].

#### Part 2: Ray-Segment Intersection [S2, unofficial]

1.  **Compute Segment Vector:** $\mathbf{s} = \mathbf{B} - \mathbf{A} = (s_x, s_y) = (b_x - a_x, b_y - a_y)$ [S2, unofficial].
2.  **Compute Denominator:** $denom = d_x s_y - d_y s_x$ [S2, unofficial].
3.  **Check Parallelism:** If $|denom| < \epsilon$ (e.g., $10^{-9}$), the ray and segment are parallel. Return invalid/null [S2, unofficial].
4.  **Compute Parameters:**
    -   $t = \frac{(a_x - o_x) s_y - (a_y - o_y) s_x}{denom}$ [S2, unofficial]
    -   $s = \frac{(a_x - o_x) d_y - (a_y - o_y) d_x}{denom}$ [S2, unofficial]
5.  **Validate:** The intersection is valid if $t \ge 0$ (ray direction) AND $0 \le s \le 1$ (segment bounds) [S2, unofficial].
6.  **Compute Intersection Point:** $\mathbf{hit} = \mathbf{o} + t \mathbf{d} = (o_x + d_x t, o_y + d_y t)$ [S2, unofficial].

### Formulas

**Ray-Segment Intersection Parameters:**
$$ s_x = b_x - a_x $$
$$ s_y = b_y - a_y $$
$$ denom = d_x s_y - d_y s_x $$
$$ t = \frac{(a_x - o_x) s_y - (a_y - o_y) s_x}{denom} $$
$$ s = \frac{(a_x - o_x) d_y - (a_y - o_y) d_x}{denom} $$
$$ valid = (t \ge 0) \land (0 \le s \le 1) $$
$$ hit_x = o_x + d_x t $$
$$ hit_y = o_y + d_y t $$

**Bounding Box Distance (Implicit):**
The distance to entry/exit is derived from standard ray-AABB intersection, where $t_{min}$ and $t_{max}$ are computed for each axis and combined [S1, unofficial].

### Pseudocode

```python
import math

def ray_segment_intersect_2d(ox, oy, dx, dy, ax, ay, bx, by):
    """
    Computes intersection between ray (O, D) and segment (A, B) in 2D.
    Returns dict with t, s, x, y, valid or None if parallel.
    """
    sx = bx - ax
    sy = by - ay
    denom = dx * sy - dy * sx
    
    # Check for parallelism
    if math.abs(denom) < 1e-9:
        return None
        
    t = ((ax - ox) * sy - (ay - oy) * sx) / denom
    s = ((ax - ox) * dy - (ay - oy) * dx) / denom
    
    valid = (t >= 0) and (s >= 0) and (s <= 1)
    
    hit_x = ox + dx * t
    hit_y = oy + dy * t
    
    return {
        "t": t,
        "s": s,
        "x": hit_x,
        "y": hit_y,
        "valid": valid
    }

def process_intersection_ordering(ray_origin, ray_dir, objects):
    """
    Optimizes processing order of intersection points and segments.
    objects: list of dicts with 'bbox' (min, max), 'class' (1, 2, 3), 'id'.
    Returns sorted lists of points and segments to process.
    """
    points = [] # Class 1
    segments = [] # Class 2, 3
    
    for obj in objects:
        # Compute ray-AABB intersection
        # t_min, t_max are entry and exit distances
        t_min, t_max = compute_ray_aabb_intersection(ray_origin, ray_dir, obj['bbox'])
        
        if t_max < 0:
            continue # Behind ray
            
        if t_min < 0:
            t_min = 0 # Ray starts inside
            
        if obj['class'] == 1:
            # Class 1: Surface. Distance is entry point.
            points.append({
                'id': obj['id'],
                'distance': t_min,
                't_min': t_min,
                't_max': t_max
            })
        else:
            # Class 2/3: Volumetric. Distance is exit point.
            segments.append({
                'id': obj['id'],
                'class': obj['class'],
                'distance': t_max,
                't_min': t_min,
                't_max': t_max
            })
            
    # Sort points by entry distance
    points.sort(key=lambda p: p['distance'])
    
    # Sort segments by exit distance
    segments.sort(key=lambda s: s['distance'])
    
    # Process Points to find closest intersection
    d_min = float('inf')
    closest_point = None
    
    for p in points:
        if p['distance'] < d_min:
            d_min = p['distance']
            closest_point = p
            
    # Process Segments with culling
    processed_segments = []
    
    for seg in segments:
        # Check if segment is completely behind the closest point
        if seg['t_max'] < d_min:
            continue # Cull
            
        # Check if segment contains the closest point
        if seg['t_min'] <= d_min <= seg['t_max']:
            # The closest point is inside this segment.
            # If Class 1, it overrides the segment value at that point.
            # For Class 2 (Average), compute average for sub-segments outside the point.
            # For Class 3 (Max), check early termination logic.
            
            # Simplified logic: Split segment or mark for partial evaluation
            # Note: Exact sub-segment calculation depends on specific shader requirements [S1, unofficial]
            processed_segments.append({
                'id': seg['id'],
                'type': 'partial',
                't_start': seg['t_min'],
                't_end': d_min,
                't_start_2': d_min,
                't_end_2': seg['t_max']
            })
        else:
            # Segment is entirely before or after the closest point
            processed_segments.append({
                'id': seg['id'],
                'type': 'full',
                't_min': seg['t_min'],
                't_max': seg['t_max']
            })
            
    return points, processed_segments

def compute_ray_aabb_intersection(origin, direction, bbox):
    """
    Computes t_min and t_max for ray-AABB intersection.
    bbox: {'min': (x,y,z), 'max': (x,y,z)}
    Returns (t_min, t_max).
    """
    # Implementation of standard slab method
    # Not given in sources, standard graphics algorithm [G]
    t_min = -float('inf')
    t_max = float('inf')
    
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < bbox['min'][i] or origin[i] > bbox['max'][i]:
                return (float('inf'), -float('inf')) # No intersection
        else:
            t1 = (bbox['min'][i] - origin[i]) / direction[i]
            t2 = (bbox['max'][i] - origin[i]) / direction[i]
            t_enter = min(t1, t2)
            t_exit = max(t1, t2)
            
            t_min = max(t_min, t_enter)
            t_max = min(t_max, t_exit)
            
    return (t_min, t_max)
```

### Parameters and Edge Cases
-   **Epsilon:** A threshold of $10^{-9}$ is used to detect parallel rays and segments [S2, unofficial].
-   **Inside Ray:** If a ray starts inside a solid, it must report the exit point to prevent holes or inside-out meshes from passing as outside intersections [S3, unofficial].
-   **Class 1 vs Class 2/3:** Class 1 calculations are generally faster and should be performed first to reduce segment lengths or enable early termination for Class 3 [S1, unofficial].

## Subtopics

### [Linear Edge Intersection](868-linear-edge-intersection.md)
Linear Edge Intersection determines the precise position where an isosurface intersects a grid edge by linearly interpolating between the scalar field values at the two vertices defining that edge. It solves the problem of locating surface geometry within a discrete voxel grid, serving as the fundamental geometric primitive for contouring algorithms like Marching Cubes and ray-marching isosurface extraction. It sets itself apart from its siblings by assuming a strictly linear variation of the scalar field along the edge, providing an exact algebraic solution for the intersection point under that assumption, whereas [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) uses numerical approximation and [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md) uses gradient data for higher-order accuracy.

### [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md)
This method extracts spatial information from a simulation by mapping 2D screen coordinates to 3D voxel indices, serving as a direct manipulation interface for tasks such as segmentation seed selection. It differs from [Reverse Index Map for Voxel Location](1097-reverse-index-map-for-voxel-location.md) by computing the intersection dynamically rather than relying on a pre-computed index texture, and from [Ray-Box Intersection for Interaction](2638-ray-box-intersection-for-interaction.md) by focusing on identifying the specific seed voxel for segmentation rather than just the entry point for fluid injection.

### [Boundary Segment Validity Conditions](7652-boundary-segment-validity-conditions.md)
Boundary Segment Validity Conditions define the geometric and topological constraints required for a line segment connecting two points on a polygonal mesh to be classified as a valid spatial boundary segment. These conditions ensure that the segment represents a true visibility boundary (e.g., a silhouette or occlusion edge) rather than a segment penetrating the geometry. This method is distinct from sibling methods like [Linear Edge Intersection](868-linear-edge-intersection.md) and [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) by explicitly validating the segment against the mesh normals and intersection geometry to prevent self-intersection or penetration artifacts in volume rendering integrals.

## Operating characteristics

### Time and Memory Complexity
-   **Ordering Optimization:** Sorting the intersection lists takes $O(N \log N)$ where $N$ is the number of objects intersected by the ray. The processing step is $O(N)$.
-   **Ray-Segment Intersection:** $O(1)$ per segment.

### Measured Performance
-   Specific performance metrics are not given in the sources. However, the method is designed to reduce total computation by avoiding unnecessary segment evaluations [S1, unofficial].

### Scaling
-   The method scales with the number of objects intersected by the ray. Efficient bounding box hierarchies (BVH) are implied to reduce the number of bounding box tests [S1, unofficial].

### Strengths and Limitations
-   **Strengths:** Reduces redundant shading calculations; enables early termination for max-value projections; handles complex ordering of surface and volumetric intersections [S1, unofficial].
-   **Limitations:** Requires classification of objects into classes; relies on accurate bounding box intersection; does not solve the analytic intersection itself but orders the results [S1, unofficial].

### When to Use
-   Use when rendering scenes with multiple overlapping volumetric objects or mixed surface/volume data where shading costs are high and early termination is possible [S1, unofficial].
-   Use when ray-segment intersection is required for 2D grid traversal or wall detection [S2, unofficial].

### When Not to Use
-   Use when only a single primitive intersection is needed (use sibling methods).
-   Use when the scene is static and pre-computed index maps are more efficient for interaction [S1, S3, unofficial].

## Background

### Origin
The intersection ordering optimization was introduced by Sobierajski et al. in "Volumetric Ray Tracing" [S1, unofficial]. The ray-segment intersection formula is a standard 2D geometric primitive often implemented in raycasting tutorials [S2, unofficial]. The ray query interface for general shapes was developed as part of the EBGeometry project [S3, unofficial].

### History and Development
The method evolved from the need to optimize volumetric ray tracing, where shading calculations are expensive. By ordering intersections and culling segments, significant performance gains are achieved [S1, unofficial]. The ray-segment intersection is a foundational component in 2D raycasting engines [S2, unofficial]. The EBGeometry project extended ray queries to support various shape types with device-callable interfaces [S3, unofficial].

### Where it is Used
-   Volumetric ray tracers [S1, unofficial].
-   2D raycasting engines and maze renderers [S2, unofficial].
-   General-purpose geometry libraries supporting ray queries on meshes and distance fields [S3, unofficial].
