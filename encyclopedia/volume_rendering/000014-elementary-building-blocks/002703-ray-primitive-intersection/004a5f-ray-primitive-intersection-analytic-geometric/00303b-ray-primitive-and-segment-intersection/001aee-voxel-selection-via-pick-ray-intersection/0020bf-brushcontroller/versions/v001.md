# BrushController

Also called: BrushController::DDAVoxelRaycast, BrushController::UpdateFromMouse

## Overview
A CPU-side controller for interactive voxel painting and erasing that determines the brush position and surface normal on a voxel grid via DDA raycasting, with a fallback to ray-AABB intersection when voxel data is unavailable [S1, unofficial]. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction [S1, unofficial]. It builds on [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) by implementing the specific raycasting logic for voxel selection.

## How it works
**Inputs and Outputs:**
- **Inputs:** Mouse screen coordinates (NDC), camera state (position, forward, right, up vectors, field of view, aspect ratio), voxel grid data (sparse or dense), brush parameters (radius, material, mode, shape).
- **Outputs:** Updated `m_brushPosition` (world space), updated voxel grid (if painting/erasing), hit voxel and normal (for rendering feedback).

**Data Structures:**
The `BrushConstants` struct is used to pass state to shaders or internal logic. Its layout is:
- `positionX`: `float`
- `positionY`: `float`
- `positionZ`: `float`
- `radius`: `float`
- `material`: `uint32_t`
- `mode`: `uint32_t`
- `shape`: `uint32_t`
- `strength`: `float`
- `gridSizeX`: `uint32_t`
- `gridSizeY`: `uint32_t`
- `gridSizeZ`: `uint32_t`
- `seed`: `uint32_t`

**Parameters:**
- `m_radius`: Brush radius, default `5.0f`, adjustable via scroll wheel [S1, unofficial].
- `m_material`: Material ID for painting, default `3` (Stone). `0` is used for erasing (air) [S1, unofficial].
- `maxDist`: Maximum raycast distance, constant `1024.0f` [S1, unofficial].
- `maxSteps`: Maximum DDA steps, constant `512` [S1, unofficial].
- `epsilon`: Small value for safe inverse direction calculation, `1e-6f` [S1, unofficial].

**Steps:**
1. **Initialize Brush State:** Set `m_brushPosition` to `(64.0f, 64.0f, 64.0f)`, `m_material` to `3`, `m_radius` to `5.0f`, `m_mode` to `Paint`, and `m_shape` to `Sphere` [S1, unofficial].
2. **Update Input State:** In `UpdateFromMouse`, set `m_isPainting` to `true` if the left mouse button is down, and `m_isErasing` to `true` if the right mouse button is down [S1, unofficial].
3. **Adjust Radius:** If `scrollDelta != 0.0f`, call `SetRadius(m_radius + scrollDelta)` [S1, unofficial].
4. **Calculate Ray Direction:** Compute the ray direction from NDC coordinates:
   $$ \text{rayDir} = \text{normalize}(\text{cameraForward} + \text{cameraRight} \times \text{mouseNDC}.x \times \tan(\text{fov} \times 0.5f) \times \text{aspectRatio} + \text{cameraUp} \times \text{mouseNDC}.y \times \tan(\text{fov} \times 0.5f)) $$
   where $\tan(\text{fov} \times 0.5f)$ is precomputed [S1, unofficial].
5. **Raycast:**
   - If `voxelGridData` is not null and size > 0, perform a DDA raycast from `cameraPos` along `rayDir`.
   - If a hit is found:
     - If erasing: `targetVoxel = hitVoxel`.
     - If painting: `targetVoxel = hitVoxel + hitNormal` [S1, unofficial].
   - If voxel data is null, fallback to `RayBoxIntersect`. If hit, set $t = \max(t_{min}, 0.0f) + 10.0f$, `hitPos = cameraPos + rayDir * t`, clamp to grid bounds, and set `targetVoxel` based on `hitPos` [S1, unofficial].
6. **Set Brush Position:** Set `m_brushPosition` to `targetVoxel + (0.5f, 0.5f, 0.5f)` and clamp to `[m_gridMin + 0.5f, m_gridMax - 0.5f]` [S1, unofficial].

**Pseudocode:**
```python
def update_brush(mouse_ndc, camera_forward, camera_right, camera_up, fov, aspect_ratio, camera_pos, voxel_grid_data, voxel_grid_size, grid_min, grid_max):
    # Step 4: Calculate Ray Direction
    tan_half_fov = tan(fov * 0.5f)
    ray_dir = normalize(
        camera_forward + 
        camera_right * mouse_ndc.x * tan_half_fov * aspect_ratio + 
        camera_up * mouse_ndc.y * tan_half_fov
    )
    
    target_voxel = None
    hit_voxel = None
    hit_normal = None
    
    # Step 5: Raycast
    if voxel_grid_data is not None and voxel_grid_size > 0:
        # DDA Voxel Traversal
        voxel_pos = floor(camera_pos) # Initial voxel
        # Calculate inverse ray direction and delta distances
        # Note: Division by zero handled via epsilon
        inv_ray_dir = vec3(
            1.0f / ray_dir.x if abs(ray_dir.x) > epsilon else 1e6f,
            1.0f / ray_dir.y if abs(ray_dir.y) > epsilon else 1e6f,
            1.0f / ray_dir.z if abs(ray_dir.z) > epsilon else 1e6f
        )
        delta_dist = abs(inv_ray_dir)
        
        # Initial side distances
        side_dist = vec3(
            (voxel_pos.x + 0.5f + 1e-4f - camera_pos.x) * inv_ray_dir.x, # Precision fix: add 1e-4f before flooring logic if needed, or adjust start
            (voxel_pos.y + 0.5f + 1e-4f - camera_pos.y) * inv_ray_dir.y,
            (voxel_pos.z + 0.5f + 1e-4f - camera_pos.z) * inv_ray_dir.z
        )
        # Correct side_dist calculation based on standard DDA:
        # side_dist = (next_voxel_boundary - current_pos) * inv_ray_dir
        # Assuming ray_dir is normalized and we start at camera_pos
        # Re-initialize side_dist properly for DDA
        step = vec3(
            sign(ray_dir.x),
            sign(ray_dir.y),
            sign(ray_dir.z)
        )
        
        # Standard DDA initialization
        # side_dist.x = (voxel_pos.x + (step.x > 0 ? 1 : 0) - camera_pos.x) * inv_ray_dir.x
        # This is simplified; actual implementation uses dist variable for maxDist check
        dist = 0.0f
        
        for i in range(maxSteps):
            voxel = get_voxel_at(voxel_pos, voxel_grid_data, voxel_grid_size)
            material = get_material_from_voxel(voxel)
            
            if material != 0:
                hit_voxel = voxel_pos
                # Determine normal based on which face was crossed last
                # This requires tracking previous side_dist or using the step logic below
                # For simplicity, we assume normal is determined by the step that caused the hit
                # In the source code, normal is updated in the step logic
                break
            
            # DDA Step
            if side_dist.x < side_dist.y:
                if side_dist.x < side_dist.z:
                    side_dist.x += delta_dist.x
                    voxel_pos.x += step.x
                    hit_normal = vec3(-step.x, 0, 0) # Normal points opposite to step direction
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
            else:
                if side_dist.y < side_dist.z:
                    side_dist.y += delta_dist.y
                    voxel_pos.y += step.y
                    hit_normal = vec3(0, -step.y, 0)
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
            
            dist += delta_dist[abs(step.x) + abs(step.y) + abs(step.z)] # Approximate distance
            if dist > maxDist:
                break
        
        if hit_voxel is not None:
            if m_isErasing:
                target_voxel = hit_voxel
            else:
                target_voxel = hit_voxel + hit_normal
    else:
        # Fallback to RayBoxIntersect
        t_min, t_max = ray_box_intersect(camera_pos, ray_dir, grid_min, grid_max)
        if t_min is not None:
            t = max(t_min, 0.0f) + 10.0f
            hit_pos = camera_pos + ray_dir * t
            target_voxel = clamp_to_grid(hit_pos, grid_min, grid_max)
            
    # Step 6: Set Brush Position
    if target_voxel is not None:
        m_brush_position = target_voxel + vec3(0.5f, 0.5f, 0.5f)
        m_brush_position = clamp(m_brush_position, grid_min + vec3(0.5f), grid_max - vec3(0.5f))
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `abs(rayDir.x) < epsilon`, use `1e6f` instead of `1/rayDir.x` to prevent NaNs [S1, unofficial].
- **Precision Issues:** Add `1e-4f` to `startPos` before flooring to get `voxelPos` to avoid boundary errors [S1, unofficial].
- **Painting vs Erasing:** Painting places the brush adjacent to the hit voxel (`hitVoxel + hitNormal`), while erasing places the brush on the hit voxel itself [S1, unofficial].

## Subtopics

### [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md)
This method enables interactive voxel painting and erasing by casting a ray from the camera through the mouse cursor to determine the brush position and surface normal on the voxel grid. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction. It builds on [BrushController](2362-brushcontroller.md) by implementing the specific raycasting logic for voxel selection.

### Voxel Edits
A GPU-based variant where a single compute shader thread computes the ray intersection with the world, writing the result to a small storage buffer. A second shader then places a ball of voxels based on the selected material around the found intersection position. This approach avoids moving voxel data to the CPU, allowing virtually unlimited edits constrained only by the world boundary [S2, unofficial].

## Operating characteristics
- **Time Complexity:** DDA raycasting is $O(N)$ where $N$ is the number of voxels traversed, bounded by `maxSteps` (512). Fallback ray-box intersection is $O(1)$.
- **Memory Complexity:** $O(1)$ for the controller state. Voxel grid storage depends on the underlying data structure (sparse/dense).
- **Performance:** CPU-side DDA is efficient for interactive rates. GPU variant (Voxel Edits) reduces CPU-GPU transfer overhead but uses a single thread for raycasting, which may be wasteful for simple scenes but scales well for complex worlds [S2, unofficial].
- **Strengths:** Immediate feedback, localized edits, robust fallback for missing voxel data.
- **Limitations:** CPU bottleneck if voxel grid access is slow; single-threaded GPU raycast may not be optimal for all hardware.

## Background
Originated in the VENPOD project, a DirectX 12 voxel rendering tech demo. The method was developed to provide interactive voxel editing capabilities, moving beyond static generation. It is part of a sparse voxel architecture that supports both dense legacy and sparse brick rendering paths [S1, unofficial].
