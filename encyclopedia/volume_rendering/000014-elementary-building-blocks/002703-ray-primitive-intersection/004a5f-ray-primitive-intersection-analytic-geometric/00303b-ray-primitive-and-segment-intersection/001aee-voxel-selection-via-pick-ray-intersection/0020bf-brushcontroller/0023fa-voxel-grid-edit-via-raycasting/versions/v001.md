# Voxel Grid Edit via Raycasting


## Overview
This method enables interactive voxel painting and erasing by casting a ray from the camera through the mouse cursor to determine the brush position and surface normal on the voxel grid. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction [S1, unofficial]. It builds on [BrushController](2362-brushcontroller.md) by implementing the specific raycasting logic for voxel selection.

## How it works
**Inputs:** Ray origin ($O$), ray direction ($D$), brush mode (Add or Remove), and the voxel grid data structure (typically an Octree).
**Outputs:** Modified voxel grid state and updated hover information.

**Data Structures:**
The method relies on a `HoverInfo` structure to track the current interaction state:
```cpp
struct HoverInfo {
    bool hasHit;       // True if the ray intersected a voxel boundary
    OctreeNode* node;  // Pointer to the intersected node (nullptr if none)
    glm::vec3 position; // World-space hit position
    glm::vec3 normal;   // Surface normal at the hit point
    int depth;          // Depth of the octree node
};
```

**Steps:**
1.  **Raycast for Hit:** Call the voxel grid's raycast function with the ray origin, direction, and the inverse of the brush mode. If `add` is true (painting), the raycast looks for an empty space to fill. If `add` is false (erasing), it looks for an existing voxel to remove.
    *   Formula: `hit = voxelGrid->raycastVoxel(O, D, hitPosition, hitNormal, !add)` [S1, unofficial].
2.  **Adjust Hit Position (Add Mode Only):** If the mode is Add and a hit is found, offset the hit position along the surface normal to prevent self-intersection or z-fighting in subsequent frames.
    *   Formula: $P_{final} = P_{hit} + N_{hit} \times 0.01$ [S1, unofficial].
3.  **Modify Voxel:**
    *   **If Add:** Insert a voxel at $P_{final}$ using `voxelGrid->addVoxel(P_{final})` [S1, unofficial].
    *   **If Remove:** Retrieve the `hoverInfo` node. If `hoverInfo.node` exists and is active, remove the voxel at its position using `voxelGrid->removeVoxel(hoverInfo.node->position)` [S1, unofficial].
4.  **Update Hover State:** Immediately refresh the hover information to reflect the new grid state.
    *   Call `voxelGrid->updateHoveredVoxel(O, D)` [S1, unofficial].
    *   Internally, this resets `hoverInfo.hasHit` to false and calls `raycastOctreeForHover(root, O, D, 1)` to re-evaluate the intersection [S1, unofficial].

**Pseudocode:**
```python
def edit_voxel_grid(ray_origin, ray_dir, is_adding, voxel_grid):
    """
    Perform a single voxel edit operation.
    
    Args:
        ray_origin (vec3): Camera ray origin.
        ray_dir (vec3): Camera ray direction.
        is_adding (bool): True for painting, False for erasing.
        voxel_grid (VoxelGrid): The grid data structure.
        
    Returns:
        bool: True if an edit was performed, False otherwise.
    """
    # Step 1: Raycast
    # Note: The source uses !add for the raycast query. 
    # If adding, we look for empty space (add=False in raycast logic? No, source says !add).
    # Source: "If add is true... look for empty space". 
    # Source: "voxelGrid->raycastVoxel(..., !add)".
    # So if is_adding=True, we pass False to raycastVoxel.
    hit_found, hit_pos, hit_normal = voxel_grid.raycast_voxel(ray_origin, ray_dir, not is_adding)
    
    if not hit_found:
        return False

    # Step 2: Adjust position for adding
    if is_adding:
        hit_pos = hit_pos + hit_normal * 0.01
    
    # Step 3: Modify voxel
    if is_adding:
        voxel_grid.add_voxel(hit_pos)
    else:
        # Retrieve current hover info to get the node pointer
        hover_info = voxel_grid.get_hover_info()
        if hover_info.node is not None and hover_info.node.is_active():
            voxel_grid.remove_voxel(hover_info.node.position)
    
    # Step 4: Update hover state
    voxel_grid.update_hovered_voxel(ray_origin, ray_dir)
    
    return True
```

**Parameters:**
*   Normal offset factor: $0.01$ [S1, unofficial].

**Edge Cases:**
*   **No Hit:** If the ray does not intersect any voxel boundary, the function returns false and no state is modified [S1, unofficial].
*   **Inactive Nodes:** When removing, the method checks if the node is active. If not, no removal occurs [S1, unofficial].
*   **Precision:** The small normal offset ($0.01$) is used to prevent visual artifacts when adding voxels adjacent to existing ones [S1, unofficial].

## Subtopics

### [Raycast-based Voxel Editing](5211-raycast-based-voxel-editing.md)
Modifies density values within a local radius around the hit point to sculpt terrain, triggering chunk regeneration. Chose this when interactive, localized sculpting is required rather than single-voxel placement.

## Operating characteristics
*   **Time Complexity:** Depends on the octree depth and ray traversal. The raycast is $O(\log N)$ for balanced octrees, where $N$ is the number of voxels.
*   **Memory Complexity:** $O(N)$ for the octree structure.
*   **Strengths:** Immediate visual feedback; efficient for sparse voxel grids.
*   **Limitations:** Single-voxel edits may be slow for large-scale terrain sculpting compared to radius-based methods.
*   **When to use:** Interactive modeling, precise placement.
*   **When not to use:** Large-scale terrain generation where noise functions are more efficient.

## Background
Originated in the `model_voxelizer` project by saurlax, this method provides a CPU-side controller for voxel painting [S1, unofficial]. It is used in 3D modeling tools that require interactive voxel manipulation.
