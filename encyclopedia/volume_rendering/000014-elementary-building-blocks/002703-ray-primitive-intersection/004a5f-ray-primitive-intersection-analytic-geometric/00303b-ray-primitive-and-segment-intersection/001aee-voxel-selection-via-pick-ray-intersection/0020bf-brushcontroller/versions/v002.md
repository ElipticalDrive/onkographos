# BrushController

Also called: BrushController::DDAVoxelRaycast, BrushController::UpdateFromMouse

## Overview
A CPU-side controller for interactive voxel painting and erasing that determines the brush position and surface normal on a voxel grid via DDA raycasting, with a fallback to ray-AABB intersection when voxel data is unavailable [S1, unofficial]. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction [S1, unofficial]. It builds on [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) by implementing the specific raycasting logic for voxel selection [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Mouse screen coordinates in normalized device coordinates (NDC), camera state (position, forward, right, up vectors, field of view, aspect ratio), voxel grid data, and brush parameters (radius, material, mode, shape) [S1, unofficial].
- **Outputs:** Updated `m_brushPosition` in world space, updated voxel grid state after painting or erasing, and hit voxel coordinates with surface normal for rendering feedback [S1, unofficial].

**Data Structures:**
The `BrushConstants` struct passes state to shaders or internal logic [S1, unofficial]. Its layout is:
- `positionX`: `float`
- `positionY`: `float`
- `positionZ`: `float`
- `radius`: `float`
- `material`: `uint32_t`
- `mode`: `uint32_t`
- `shape`: `uint32_t`
- `strength`: `float`
- `gridSizeX`: `uint32_t`
- `gridSizeY`: `uint32_t`
- `gridSizeZ`: `uint32_t`
- `seed`: `uint32_t` [S1, unofficial].

**Parameters:**
- `m_radius`: Brush radius, default `5.0`, adjustable via scroll wheel [S1, unofficial].
- `m_material`: Material ID for painting, default `3` (Stone). `0` is used for erasing (air) [S1, unofficial].
- `maxDist`: Maximum raycast distance, constant `1024.0` [S1, unofficial].
- `maxSteps`: Maximum DDA steps, constant `512` [S1, unofficial].
- `epsilon`: Small value for safe inverse direction calculation, `1e-6` [S1, unofficial].

**Steps:**
1. **Initialize Brush State:** Set `m_brushPosition` to `(64.0, 64.0, 64.0)`, `m_material` to `3`, `m_radius` to `5.0`, `m_mode` to `Paint`, and `m_shape` to `Sphere` [S1, unofficial].
2. **Update Input State:** In `UpdateFromMouse`, set `m_isPainting` to `true` if the left mouse button is down, and `m_isErasing` to `true` if the right mouse button is down [S1, unofficial].
3. **Adjust Radius:** If `scrollDelta` is non-zero, call `SetRadius(m_radius + scrollDelta)` [S1, unofficial].
4. **Calculate Ray Direction:** Compute the ray direction from NDC coordinates:
   $$ \text{rayDir} = \text{normalize}(\text{cameraForward} + \text{cameraRight} \times \text{mouseNDC}.x \times \tan(\text{fov} \times 0.5) \times \text{aspectRatio} + \text{cameraUp} \times \text{mouseNDC}.y \times \tan(\text{fov} \times 0.5)) $$
   where $\tan(\text{fov} \times 0.5)$ is precomputed [S1, unofficial].
5. **Raycast:**
   - If `voxelGridData` is not null and size > 0, perform a DDA raycast from `cameraPos` along `rayDir` [S1, unofficial].
   - If a hit is found:
     - If erasing: `targetVoxel = hitVoxel`.
     - If painting: `targetVoxel = hitVoxel + hitNormal` [S1, unofficial].
   - If voxel data is null, fallback to `RayBoxIntersect`. If hit, set $t = \max(t_{min}, 0.0) + 10.0$, `hitPos = cameraPos + rayDir * t`, clamp to grid bounds, and set `targetVoxel` based on `hitPos` [S1, unofficial].
6. **Set Brush Position:** Set `m_brushPosition` to `targetVoxel + (0.5, 0.5, 0.5)` and clamp to `[m_gridMin + 0.5, m_gridMax - 0.5]` [S1, unofficial].

**Pseudocode:**
```python
import math

def normalize(v):
    length = math.sqrt(sum(x*x for x in v))
    return [x/length for x in v] if length > 0 else [0,0,0]

def clamp(val, min_val, max_val):
    return max(min_val, min(max_val, val))

def ray_box_intersect(origin, direction, box_min, box_max):
    # Standard slab method for ray-AABB intersection [G]
    t_min = -math.inf
    t_max = math.inf
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < box_min[i] or origin[i] > box_max[i]:
                return None, None
        else:
            t1 = (box_min[i] - origin[i]) / direction[i]
            t2 = (box_max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    if t_max < t_min:
        return None, None
    return t_min, t_max

def update_brush(mouse_ndc, camera_forward, camera_right, camera_up, fov, aspect_ratio, camera_pos, voxel_grid_data, voxel_grid_size, grid_min, grid_max, max_steps, max_dist, epsilon):
    # Step 4: Calculate Ray Direction
    tan_half_fov = math.tan(fov * 0.5)
    ray_dir = normalize(
        [camera_forward[i] + camera_right[i] * mouse_ndc[0] * tan_half_fov * aspect_ratio + camera_up[i] * mouse_ndc[1] * tan_half_fov for i in range(3)]
    )
    
    target_voxel = None
    hit_voxel = None
    hit_normal = None
    
    # Step 5: Raycast
    if voxel_grid_data is not None and voxel_grid_size > 0:
        # DDA Voxel Traversal
        # Precision fix: add 1e-4 to startPos before flooring to avoid boundary errors [S1, unofficial]
        voxel_pos = [math.floor(p + 1e-4) for p in camera_pos]
        
        # Calculate inverse ray direction with division-by-zero guard [S1, unofficial]
        inv_ray_dir = [
            1.0 / ray_dir[i] if abs(ray_dir[i]) > epsilon else 1e6 for i in range(3)
        ]
        delta_dist = [abs(v) for v in inv_ray_dir]
        
        # Initial side distances to next voxel boundary
        side_dist = [
            (voxel_pos[i] + 0.5 - camera_pos[i]) * inv_ray_dir[i] for i in range(3)
        ]
        
        step = [1 if ray_dir[i] > 0 else -1 for i in range(3)]
        dist = 0.0
        
        for i in range(max_steps):
            # Grid lookup logic not specified in sources [G]
            voxel = 0 
            material = 0
            
            if material != 0:
                hit_voxel = voxel_pos
                break
            
            # DDA Step
            if side_dist[0] < side_dist[1]:
                if side_dist[0] < side_dist[2]:
                    side_dist[0] += delta_dist[0]
                    voxel_pos[0] += step[0]
                    hit_normal = [-step[0], 0, 0]
                else:
                    side_dist[2] += delta_dist[2]
                    voxel_pos[2] += step[2]
                    hit_normal = [0, 0, -step[2]]
            else:
                if side_dist[1] < side_dist[2]:
                    side_dist[1] += delta_dist[1]
                    voxel_pos[1] += step[1]
                    hit_normal = [0, -step[1], 0]
                else:
                    side_dist[2] += delta_dist[2]
                    voxel_pos[2] += step[2]
                    hit_normal = [0, 0, -step[2]]
            
            dist += min(delta_dist)
            if dist > max_dist:
                break
        
        if hit_voxel is not None:
            if m_isErasing:
                target_voxel = hit_voxel
            else:
                target_voxel = [hit_voxel[j] + hit_normal[j] for j in range(3)]
    else:
        # Fallback to RayBoxIntersect
        t_min, t_max = ray_box_intersect(camera_pos, ray_dir, grid_min, grid_max)
        if t_min is not None:
            t = max(t_min, 0.0) + 10.0
            hit_pos = [camera_pos[j] + ray_dir[j] * t for j in range(3)]
            target_voxel = clamp_to_grid(hit_pos, grid_min, grid_max)
            
    # Step 6: Set Brush Position
    if target_voxel is not None:
        m_brush_position = [target_voxel[j] + 0.5 for j in range(3)]
        m_brush_position = clamp(m_brush_position, [grid_min[j] + 0.5 for j in range(3)], [grid_max[j] - 0.5 for j in range(3)])
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `abs(rayDir.x) < epsilon`, use `1e6` instead of `1/rayDir.x` to prevent NaNs [S1, unofficial].
- **Precision Issues:** Add `1e-4` to `startPos` before flooring to get `voxelPos` to avoid boundary errors [S1, unofficial].
- **Painting vs Erasing:** Painting places the brush adjacent to the hit voxel (`hitVoxel + hitNormal`), while erasing places the brush on the hit voxel itself [S1, unofficial].

## Subtopics

### [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md)
This method enables interactive voxel painting and erasing by casting a ray from the camera through the mouse cursor to determine the brush position and surface normal on the voxel grid. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction. It builds on [BrushController](2362-brushcontroller.md) by implementing the specific raycasting logic for voxel selection.

### Voxel Edits
A GPU-based variant where a single compute shader thread computes the ray intersection with the world, writing the result to a small storage buffer [S2, unofficial]. A second shader then places a ball of voxels based on the selected material around the found intersection position [S2, unofficial]. This approach avoids moving voxel data to the CPU, allowing virtually unlimited edits constrained only by the world boundary [S2, unofficial].

### Volume Painting for Selection
A 3D volumetric painting approach for selection definition where a user clicks on the image plane, casting a ray into the volume to find the first non-transparent voxel, then drawing a 3D Gaussian brush into the selection volume [S3]. The process involves computing the ray intersection in a compute shader, placing voxels around the intersection, and applying composition methods such as addition (painting) or subtraction (erasing) [S3].

## Operating characteristics
- **Time Complexity:** DDA raycasting is $O(N)$ where $N$ is the number of voxels traversed, bounded by `maxSteps` (512) [S1, unofficial]. Fallback ray-box intersection is $O(1)$ [G].
- **Memory Complexity:** $O(1)$ for the controller state [S1, unofficial]. Voxel grid storage depends on the underlying data structure (sparse/dense) [S1, unofficial].
- **Performance:** CPU-side DDA is efficient for interactive rates [S1, unofficial]. GPU variant (Voxel Edits) reduces CPU-GPU transfer overhead but uses a single thread for raycasting, which is noted as somewhat wasteful but beats moving all voxel data to the CPU first [S2, unofficial].
- **Strengths:** Immediate feedback, localized edits, robust fallback for missing voxel data [S1, unofficial].
- **Limitations:** CPU bottleneck if voxel grid access is slow; single-threaded GPU raycast may not be optimal for all hardware [S2, unofficial].

## Background
Originated in the VENPOD project, a DirectX 12 voxel rendering tech demo [S1, unofficial]. The method was developed to provide interactive voxel editing capabilities, moving beyond static generation [S1, unofficial]. It is part of a sparse voxel architecture that supports both dense legacy and sparse brick rendering paths [S1, unofficial].
