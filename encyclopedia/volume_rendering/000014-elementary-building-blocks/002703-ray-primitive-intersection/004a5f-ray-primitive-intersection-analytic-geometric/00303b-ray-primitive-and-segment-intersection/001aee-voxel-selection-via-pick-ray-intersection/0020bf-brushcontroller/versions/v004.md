# BrushController

Also called: BrushController::DDAVoxelRaycast, BrushController::UpdateFromMouse

## Overview
A CPU-side controller for voxel painting and erasing that uses Digital Differential Analysis (DDA) raycasting to determine brush position and normal on the voxel grid, with a fallback to ray-AABB intersection if voxel data is unavailable [S1, unofficial]. It solves the problem of translating 2D user input into precise 3D spatial edits within a discrete volumetric representation [S1, unofficial]. Unlike static voxelization, it supports dynamic editing where the system computes the adjacent empty voxel position for addition or the current voxel position for removal based on the raycast hit normal [S1, unofficial]. It differs from [Volume Painting for Selection](6454-volume-painting-for-selection.md) by directly modifying the underlying voxel data structure rather than generating a selection mask for later processing.

## How it works
**Inputs:**
- Camera state: `cameraPos` (vec3), `cameraForward` (vec3), `cameraRight` (vec3), `cameraUp` (vec3).
- Viewport parameters: `fov` (field of view in radians), `aspectRatio` (width/height).
- Input state: `mouseNDC` (vec2, range [-1, 1]), `leftButtonDown` (bool), `rightButtonDown` (bool), `scrollDelta` (float).
- Voxel grid data: `voxelGridData` (pointer/struct), `voxelGridSize` (vec3, uint32_t), `gridMin` (vec3), `gridMax` (vec3).
- Constants: `maxDist` (1024.0f), `maxSteps` (512), `epsilon` (1e-6f).

**Outputs:**
- `m_brushPosition` (vec3): World-space center of the brush.
- `m_isPainting` (bool): True if left mouse button is down.
- `m_isErasing` (bool): True if right mouse button is down.
- `m_radius` (float): Brush radius.
- `m_material` (uint32_t): Material ID to paint (0 for erase/air).

**Data Structures:**
The `BrushConstants` struct is used to pass state to shaders or internal logic. Its layout is:
- `positionX`: float
- `positionY`: float
- `positionZ`: float
- `radius`: float
- `material`: uint32_t
- `mode`: uint32_t
- `shape`: uint32_t
- `strength`: float
- `gridSizeX`: uint32_t
- `gridSizeY`: uint32_t
- `gridSizeZ`: uint32_t
- `seed`: uint32_t

**Algorithm Steps:**

1. **Initialize Brush State:**
   Set default values: `m_brushPosition = (64.0f, 64.0f, 64.0f)`, `m_material = 3` (Stone), `m_radius = 5.0f`, `m_mode = Paint`, `m_shape = Sphere` [S1, unofficial].

2. **Update Input State:**
   Set `m_isPainting = leftButtonDown` and `m_isErasing = rightButtonDown` [S1, unofficial].

3. **Adjust Radius:**
   If `scrollDelta != 0.0f`, update radius: `m_radius = m_radius + scrollDelta` [S1, unofficial].

4. **Calculate Ray Direction:**
   Compute the ray direction in world space from Normalized Device Coordinates (NDC):
   $$ \text{tanHalfFov} = \tan(\text{fov} \times 0.5f) $$
   $$ \text{rayDir} = \text{normalize}(\text{cameraForward} + \text{cameraRight} \times \text{mouseNDC}.x \times \text{tanHalfFov} \times \text{aspectRatio} + \text{cameraUp} \times \text{mouseNDC}.y \times \text{tanHalfFov}) $$
   [S1, unofficial].

5. **Raycast and Determine Target Voxel:**
   Check if `voxelGridData` is not null and `voxelGridSize` > 0.
   
   **Case A: Voxel Data Available (DDA Raycast)**
   Perform a DDA voxel traversal from `cameraPos` along `rayDir` [S1, unofficial].
   - Calculate inverse ray direction components. If `abs(rayDir.x) < epsilon`, use `1e6f` instead of `1/rayDir.x` to prevent division by zero [S1, unofficial].
   - Initialize `sideDist` (distance to next grid boundary) and `deltaDist` (distance to cross one voxel) based on ray direction and voxel size [S1, unofficial].
   - Iterate up to `maxSteps`:
     1. Get current voxel position `voxelPos` from `cameraPos` and ray parameters.
     2. Add a small epsilon (`1e-4f`) to `startPos` before flooring to `voxelPos` to handle precision issues at grid boundaries [S1, unofficial].
     3. Query voxel material at `voxelPos`.
     4. If material is non-zero (hit):
        - Set `hitVoxel = voxelPos`.
        - Determine `hitNormal` based on the face crossed (e.g., if crossing X face, normal is `(-step.x, 0, 0)`).
        - Break loop.
     5. Advance ray to next voxel:
        - Compare `sideDist` components to find the smallest distance.
        - Add `deltaDist` of the smallest component to `sideDist`.
        - Increment `voxelPos` in the corresponding axis by `step` (1 or -1).
        - Update `hitNormal` for the new face.
     6. If `dist > maxDist`, break loop.
   
   - Determine `targetVoxel`:
     - If erasing (`m_isErasing`): `targetVoxel = hitVoxel`.
     - If painting (`m_isPainting`): `targetVoxel = hitVoxel + hitNormal` [S1, unofficial].

   **Case B: Voxel Data Unavailable (Fallback)**
   Perform Ray-Box Intersection with the grid bounds [S1, unofficial].
   - If hit:
     - Set `t = max(tMin, 0.0f) + 10.0f`.
     - Calculate `hitPos = cameraPos + rayDir * t`.
     - Clamp `hitPos` to grid bounds.
     - Set `targetVoxel = hitPos`.

6. **Set Brush Position:**
   Set `m_brushPosition = targetVoxel + (0.5f, 0.5f, 0.5f)` [S1, unofficial].
   Clamp `m_brushPosition` to `[m_gridMin + 0.5f, m_gridMax - 0.5f]` [S1, unofficial].

**Pseudocode:**

```python
def update_brush(camera_pos, camera_forward, camera_right, camera_up, fov, aspect_ratio, mouse_ndc, left_down, right_down, scroll_delta, voxel_grid_data, voxel_grid_size, grid_min, grid_max):
    # Constants
    max_dist = 1024.0
    max_steps = 512
    epsilon = 1e-6
    
    # 1. Initialize State (Defaults if first run)
    brush_pos = vec3(64.0, 64.0, 64.0)
    radius = 5.0
    material = 3
    is_painting = False
    is_erasing = False
    
    # 2. Update Input State
    is_painting = left_down
    is_erasing = right_down
    
    # 3. Adjust Radius
    if scroll_delta != 0.0:
        radius += scroll_delta
        
    # 4. Calculate Ray Direction
    tan_half_fov = tan(fov * 0.5)
    ray_dir = normalize(camera_forward + camera_right * mouse_ndc.x * tan_half_fov * aspect_ratio + camera_up * mouse_ndc.y * tan_half_fov)
    
    target_voxel = vec3(0.0)
    
    # 5. Raycast
    if voxel_grid_data is not None and voxel_grid_size.x > 0:
        # DDA Voxel Traversal
        inv_ray = vec3(0.0)
        inv_ray.x = 1.0 / ray_dir.x if abs(ray_dir.x) > epsilon else 1e6
        inv_ray.y = 1.0 / ray_dir.y if abs(ray_dir.y) > epsilon else 1e6
        inv_ray.z = 1.0 / ray_dir.z if abs(ray_dir.z) > epsilon else 1e6
        
        # Initial voxel position
        # Pitfall: Add epsilon to startPos before flooring
        start_pos = camera_pos + vec3(1e-4, 1e-4, 1e-4)
        voxel_pos = floor(start_pos)
        
        # Distance to next grid boundary
        side_dist = vec3(
            (voxel_pos.x + (1.0 if ray_dir.x > 0 else 0.0) - start_pos.x) * inv_ray.x,
            (voxel_pos.y + (1.0 if ray_dir.y > 0 else 0.0) - start_pos.y) * inv_ray.y,
            (voxel_pos.z + (1.0 if ray_dir.z > 0 else 0.0) - start_pos.z) * inv_ray.z
        )
        
        # Distance to cross one voxel
        delta_dist = abs(inv_ray)
        
        # Step direction
        step = vec3(
            1.0 if ray_dir.x > 0 else -1.0,
            1.0 if ray_dir.y > 0 else -1.0,
            1.0 if ray_dir.z > 0 else -1.0
        )
        
        hit_voxel = vec3(0)
        hit_normal = vec3(0)
        hit = False
        dist = 0.0
        
        for i in range(max_steps):
            # Get voxel material
            voxel = get_voxel_at(voxel_pos, voxel_grid_data, voxel_grid_size)
            material_val = get_material_from_voxel(voxel)
            
            if material_val != 0:
                hit_voxel = voxel_pos
                hit = True
                break
            
            # Advance to next voxel
            if side_dist.x < side_dist.y:
                if side_dist.x < side_dist.z:
                    side_dist.x += delta_dist.x
                    voxel_pos.x += step.x
                    hit_normal = vec3(-step.x, 0, 0)
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
            else:
                if side_dist.y < side_dist.z:
                    side_dist.y += delta_dist.y
                    voxel_pos.y += step.y
                    hit_normal = vec3(0, -step.y, 0)
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
            
            dist = length(voxel_pos - camera_pos) # Approximate distance check
            if dist > max_dist:
                break
        
        if hit:
            if is_erasing:
                target_voxel = hit_voxel
            else:
                target_voxel = hit_voxel + hit_normal
    else:
        # Fallback: Ray-Box Intersection
        t_min, t_max = ray_box_intersect(camera_pos, ray_dir, grid_min, grid_max)
        if t_min is not None:
            t = max(t_min, 0.0) + 10.0
            hit_pos = camera_pos + ray_dir * t
            # Clamp to grid bounds
            hit_pos = clamp(hit_pos, grid_min, grid_max)
            target_voxel = hit_pos
            
    # 6. Set Brush Position
    brush_pos = target_voxel + vec3(0.5, 0.5, 0.5)
    brush_pos = clamp(brush_pos, grid_min + vec3(0.5, 0.5, 0.5), grid_max - vec3(0.5, 0.5, 0.5))
    
    return brush_pos, radius, material, is_painting, is_erasing
```

## Subtopics

### [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md)
This method enables real-time modification of a voxel grid by casting rays from screen-space mouse coordinates into the 3D world to determine interaction points. It solves the problem of translating 2D user input into precise 3D spatial edits (addition or removal of voxels) within a discrete volumetric representation. Unlike static voxelization, it supports dynamic editing where the system computes the adjacent empty voxel position for addition or the current voxel position for removal based on the raycast hit normal. It differs from [Volume Painting for Selection](6454-volume-painting-for-selection.md) by directly modifying the underlying voxel data structure rather than generating a selection mask for later processing.

### [Volume Painting for Selection](6454-volume-painting-for-selection.md)
Volume Painting for Selection is a 3D volumetric painting approach for selection definition where a user clicks on the image plane, casting a ray into the volume to find the first non-transparent voxel, then drawing a 3D Gaussian brush into the selection volume. It differs from [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md) by focusing on defining a fuzzy selection envelope via additive/subtractive painting rather than direct voxel modification, and from its parent [BrushController](2362-brushcontroller.md) by providing the specific interaction logic for brush placement and composition.

## Operating characteristics
**Time Complexity:**
- DDA Raycast: $O(N)$ where $N$ is the number of voxels traversed along the ray, bounded by `maxSteps` (512) [S1, unofficial].
- Ray-Box Fallback: $O(1)$ [S1, unofficial].

**Memory Complexity:**
- $O(1)$ auxiliary memory for the controller state. The voxel grid data is external [S1, unofficial].

**Performance:**
- The DDA approach is efficient for sparse or dense grids as it only visits voxels along the ray path.
- The fallback to Ray-Box intersection is used when voxel data is unavailable, ensuring robustness but potentially less precise placement relative to internal geometry [S1, unofficial].
- On the reference hardware (DX12 capable GPU, Windows 10/11), the CPU-side controller is lightweight, allowing for high-frequency updates (mouse movement) without significant overhead [S1, unofficial].

**Strengths:**
- Precise voxel-level control for painting and erasing.
- Handles both occupied and empty voxel placement (painting adjacent to hit, erasing at hit).
- Robust fallback mechanism.

**Limitations:**
- Limited by `maxDist` (1024.0f) and `maxSteps` (512), which may cause rays to miss distant or complex geometry if not tuned [S1, unofficial].
- Precision issues at grid boundaries require epsilon adjustments [S1, unofficial].
- Division by zero protection requires epsilon checks [S1, unofficial].

**When to Use:**
- Real-time voxel editing in interactive applications (games, editors).
- When direct manipulation of voxel data is required.

**When Not to Use:**
- When selection masks or fuzzy boundaries are preferred over hard voxel edits.
- When raycasting through extremely large volumes without spatial acceleration structures (though DDA is efficient, very long rays may hit step limits).

## Background
The BrushController is part of the VENPOD project, a graphics programming tech demo targeting Windows and DirectX 12 [S1, unofficial]. It was developed as part of the sparse voxel rendering and editing pipeline, allowing users to interactively modify the voxel world [S1, unofficial]. The implementation uses a CPU-side controller for input handling and raycasting, with a fallback to GPU-based compute shaders for more complex edits in some variants [S1, S2, unofficial]. The project is hosted on GitHub as `asajid2-cell/voxelrender` [S1, unofficial].
