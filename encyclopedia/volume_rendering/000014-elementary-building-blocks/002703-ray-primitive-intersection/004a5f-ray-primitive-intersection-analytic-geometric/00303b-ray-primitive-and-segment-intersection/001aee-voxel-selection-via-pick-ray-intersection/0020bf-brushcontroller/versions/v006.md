# BrushController

Also called: BrushController::DDAVoxelRaycast, BrushController::UpdateFromMouse

## Overview
A CPU-side controller for voxel painting and erasing that uses Digital Differential Analysis (DDA) raycasting to determine brush position and normal on the voxel grid, with a fallback to ray-AABB intersection if voxel data is unavailable [S1, unofficial]. It solves the problem of translating 2D user input into precise 3D spatial edits within a discrete volumetric representation [S1, unofficial]. Unlike static voxelization, it supports dynamic editing where the system computes the adjacent empty voxel position for addition or the current voxel position for removal based on the raycast hit normal [S1, unofficial]. It differs from [Volume Painting for Selection](6454-volume-painting-for-selection.md) by directly modifying the underlying voxel data structure rather than generating a selection mask for later processing [S1, unofficial].

## How it works
**Inputs:**
- Camera state: `cameraPos` (vec3), `cameraForward` (vec3), `cameraRight` (vec3), `cameraUp` (vec3) [S1, unofficial].
- Viewport parameters: `fov` (field of view in radians), `aspectRatio` (width/height) [S1, unofficial].
- Input state: `mouseNDC` (vec2, range [-1, 1]), `leftButtonDown` (bool), `rightButtonDown` (bool), `scrollDelta` (float) [S1, unofficial].
- Voxel grid data: `voxelGridData` (pointer/struct), `voxelGridSize` (vec3, uint32_t), `gridMin` (vec3), `gridMax` (vec3) [S1, unofficial].
- Constants: `maxDist` (1024.0f), `maxSteps` (512), `epsilon` (1e-6f) [S1, unofficial].

**Outputs:**
- `m_brushPosition` (vec3): World-space center of the brush [S1, unofficial].
- `m_isPainting` (bool): True if left mouse button is down [S1, unofficial].
- `m_isErasing` (bool): True if right mouse button is down [S1, unofficial].
- `m_radius` (float): Brush radius [S1, unofficial].
- `m_material` (uint32_t): Material ID to paint (0 for erase/air) [S1, unofficial].

**Data Structures:**
The `BrushConstants` struct is used to pass state to shaders or internal logic [S1, unofficial]. Its layout is:
- `positionX`: float
- `positionY`: float
- `positionZ`: float
- `radius`: float
- `material`: uint32_t
- `mode`: uint32_t
- `shape`: uint32_t
- `strength`: float
- `gridSizeX`: uint32_t
- `gridSizeY`: uint32_t
- `gridSizeZ`: uint32_t
- `seed`: uint32_t [S1, unofficial].

**Algorithm Steps:**

1. **Initialize Brush State:** Set default values: `m_brushPosition = (64.0f, 64.0f, 64.0f)`, `m_material = 3` (Stone), `m_radius = 5.0f`, `m_mode = Paint`, `m_shape = Sphere` [S1, unofficial].
2. **Update Input State:** Set `m_isPainting = leftButtonDown` and `m_isErasing = rightButtonDown` [S1, unofficial].
3. **Adjust Radius:** If `scrollDelta != 0.0f`, update radius: `m_radius = m_radius + scrollDelta` [S1, unofficial].
4. **Calculate Ray Direction:** Compute the ray direction in world space from Normalized Device Coordinates (NDC):
   $$ \text{tanHalfFov} = \tan(\text{fov} \times 0.5f) $$
   $$ \text{rayDir} = \text{normalize}(\text{cameraForward} + \text{cameraRight} \times \text{mouseNDC}.x \times \text{tanHalfFov} \times \text{aspectRatio} + \text{cameraUp} \times \text{mouseNDC}.y \times \text{tanHalfFov}) $$
   [S1, unofficial].
5. **Raycast and Determine Target Voxel:** Check if `voxelGridData` is not null and `voxelGridSize` > 0 [S1, unofficial].
   
   **Case A: Voxel Data Available (DDA Raycast)** [S1, unofficial].
   Perform a DDA voxel traversal from `cameraPos` along `rayDir` [S1, unofficial].
   - Calculate inverse ray direction components. If `abs(rayDir.x) < epsilon`, use `1e6f` instead of `1/rayDir.x` to prevent division by zero [S1, unofficial].
   - Initialize `sideDist` (distance to next grid boundary) and `deltaDist` (distance to cross one voxel) based on ray direction and voxel size [S1, unofficial].
   - Iterate up to `maxSteps`:
     1. Add a small epsilon (`1e-4f`) to `startPos` before flooring to `voxelPos` to handle precision issues at grid boundaries [S1, unofficial].
     2. Query voxel material at `voxelPos`.
     3. If material is non-zero (hit):
        - Set `hitVoxel = voxelPos`.
        - Determine `hitNormal` based on the face crossed (e.g., if crossing X face, normal is `(-step.x, 0, 0)`) [S1, unofficial].
        - Break loop.
     4. Advance ray to next voxel:
        - Compare `sideDist` components to find the smallest distance [S1, unofficial].
        - Add `deltaDist` of the smallest component to `sideDist` [S1, unofficial].
        - Increment `voxelPos` in the corresponding axis by `step` (1 or -1) [S1, unofficial].
        - Update `hitNormal` for the new face.
     5. If `dist > maxDist`, break loop.
   
   - Determine `targetVoxel`:
     - If erasing (`m_isErasing`): `targetVoxel = hitVoxel` [S1, unofficial].
     - If painting (`m_isPainting`): `targetVoxel = hitVoxel + hitNormal` [S1, unofficial].

   **Case B: Voxel Data Unavailable (Fallback)** [S1, unofficial].
   Perform Ray-Box Intersection with the grid bounds [S1, unofficial].
   - If hit:
     - Set `t = max(tMin, 0.0f) + 10.0f` [S1, unofficial].
     - Calculate `hitPos = cameraPos + rayDir * t` [S1, unofficial].
     - Clamp `hitPos` to grid bounds [S1, unofficial].
     - Set `targetVoxel = hitPos` [S1, unofficial].

6. **Set Brush Position:** Set `m_brushPosition = targetVoxel + (0.5f, 0.5f, 0.5f)` [S1, unofficial]. Clamp `m_brushPosition` to `[m_gridMin + 0.5f, m_gridMax - 0.5f]` [S1, unofficial].

**Pseudocode:**

```python
def update_brush(camera_pos, camera_forward, camera_right, camera_up, fov, aspect_ratio, mouse_ndc, left_down, right_down, scroll_delta, voxel_grid_data, voxel_grid_size, grid_min, grid_max):
    max_dist = 1024.0
    max_steps = 512
    epsilon = 1e-6

    brush_pos = vec3(64.0, 64.0, 64.0)
    radius = 5.0
    material = 3
    is_painting = False
    is_erasing = False

    is_painting = left_down
    is_erasing = right_down

    if scroll_delta != 0.0:
        radius += scroll_delta

    tan_half_fov = tan(fov * 0.5)
    ray_dir = normalize(camera_forward + camera_right * mouse_ndc.x * tan_half_fov * aspect_ratio + camera_up * mouse_ndc.y * tan_half_fov)

    target_voxel = vec3(0.0)

    if voxel_grid_data is not None and voxel_grid_size.x > 0:
        inv_ray = vec3(0.0)
        inv_ray.x = 1.0 / ray_dir.x if abs(ray_dir.x) > epsilon else 1e6
        inv_ray.y = 1.0 / ray_dir.y if abs(ray_dir.y) > epsilon else 1e6
        inv_ray.z = 1.0 / ray_dir.z if abs(ray_dir.z) > epsilon else 1e6

        start_pos = camera_pos + vec3(1e-4, 1e-4, 1e-4)
        voxel_pos = floor(start_pos)

        side_dist = vec3(
            (voxel_pos.x + (1.0 if ray_dir.x > 0 else 0.0) - start_pos.x) * inv_ray.x,
            (voxel_pos.y + (1.0 if ray_dir.y > 0 else 0.0) - start_pos.y) * inv_ray.y,
            (voxel_pos.z + (1.0 if ray_dir.z > 0 else 0.0) - start_pos.z) * inv_ray.z
        )

        delta_dist = abs(inv_ray)
        step = vec3(
            1.0 if ray_dir.x > 0 else -1.0,
            1.0 if ray_dir.y > 0 else -1.0,
            1.0 if ray_dir.z > 0 else -1.0
        )

        hit_voxel = vec3(0)
        hit_normal = vec3(0)
        hit = False
        dist = 0.0

        for i in range(max_steps):
            voxel = get_voxel_at(voxel_pos, voxel_grid_data, voxel_grid_size)
            material_val = get_material_from_voxel(voxel)

            if material_val != 0:
                hit_voxel = voxel_pos
                hit = True
                break

            if side_dist.x < side_dist.y:
                if side_dist.x < side_dist.z:
                    side_dist.x += delta_dist.x
                    voxel_pos.x += step.x
                    hit_normal = vec3(-step.x, 0, 0)
                    dist += delta_dist.x
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
                    dist += delta_dist.z
            else:
                if side_dist.y < side_dist.z:
                    side_dist.y += delta_dist.y
                    voxel_pos.y += step.y
                    hit_normal = vec3(0, -step.y, 0)
                    dist += delta_dist.y
                else:
                    side_dist.z += delta_dist.z
                    voxel_pos.z += step.z
                    hit_normal = vec3(0, 0, -step.z)
                    dist += delta_dist.z

            if dist > max_dist:
                break

        if hit:
            if is_erasing:
                target_voxel = hit_voxel
            else:
                target_voxel = hit_voxel + hit_normal
    else:
        t_min, t_max = ray_box_intersect(camera_pos, ray_dir, grid_min, grid_max)
        if t_min is not None:
            t = max(t_min, 0.0) + 10.0
            hit_pos = camera_pos + ray_dir * t
            hit_pos = clamp(hit_pos, grid_min, grid_max)
            target_voxel = hit_pos

    brush_pos = target_voxel + vec3(0.5, 0.5, 0.5)
    brush_pos = clamp(brush_pos, grid_min + vec3(0.5, 0.5, 0.5), grid_max - vec3(0.5, 0.5, 0.5))

    return brush_pos, radius, material, is_painting, is_erasing

def get_voxel_at(pos, grid_data, grid_size):
    # Standard 3D array indexing with bounds check [G]
    x, y, z = int(pos.x), int(pos.y), int(pos.z)
    if 0 <= x < grid_size.x and 0 <= y < grid_size.y and 0 <= z < grid_size.z:
        return grid_data[z * grid_size.y * grid_size.x + y * grid_size.x + x]
    return 0

def get_material_from_voxel(voxel):
    # Extract material ID from voxel data (e.g., lower 16 bits) [G]
    return voxel & 0xFFFF

def ray_box_intersect(origin, direction, box_min, box_max):
    # Standard slab method for AABB intersection [G]
    t_min = (box_min.x - origin.x) / direction.x if direction.x != 0 else float('inf')
    t_max = (box_max.x - origin.x) / direction.x if direction.x != 0 else float('-inf')
    if t_min > t_max: t_min, t_max = t_max, t_min

    ty_min = (box_min.y - origin.y) / direction.y if direction.y != 0 else float('inf')
    ty_max = (box_max.y - origin.y) / direction.y if direction.y != 0 else float('-inf')
    if ty_min > ty_max: ty_min, ty_max = ty_max, ty_min

    if t_min > ty_max or ty_min > t_max: return None, None
    t_min = max(t_min, ty_min)
    t_max = min(t_max, ty_max)

    tz_min = (box_min.z - origin.z) / direction.z if direction.z != 0 else float('inf')
    tz_max = (box_max.z - origin.z) / direction.z if direction.z != 0 else float('-inf')
    if tz_min > tz_max: tz_min, tz_max = tz_max, tz_min

    if t_min > tz_max or tz_min > t_max: return None, None
    return max(t_min, tz_min), min(t_max, tz_max)
```

## Subtopics

### [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md)
This method enables real-time modification of a voxel grid by casting rays from screen-space mouse coordinates into the 3D world to determine interaction points. It solves the problem of translating 2D user input into precise 3D spatial edits (addition or removal of voxels) within a discrete volumetric representation. Unlike static voxelization, it supports dynamic editing where the system computes the adjacent empty voxel position for addition or the current voxel position for removal based on the raycast hit normal. It differs from [Volume Painting for Selection](6454-volume-painting-for-selection.md) by directly modifying the underlying voxel data structure rather than generating a selection mask for later processing.

### [Volume Painting for Selection](6454-volume-painting-for-selection.md)
Volume Painting for Selection is a 3D volumetric painting approach for selection definition where a user clicks on the image plane, casting a ray into the volume to find the first non-transparent voxel, then drawing a 3D Gaussian brush into the selection volume. It differs from [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md) by focusing on defining a fuzzy selection envelope via additive/subtractive painting rather than direct voxel modification, and from its parent [BrushController](2362-brushcontroller.md) by providing the specific interaction logic for brush placement and composition.

### Voxel Edits
This variant computes ray intersection with the world in a simple compute shader using a single GPU thread, writing the result to a small storage buffer [S2, unofficial]. In a second shader, it places a ball of voxels based on the selected material around the found intersection position [S2, unofficial].

## Operating characteristics
**Time Complexity:**
- DDA Raycast: $O(N)$ where $N$ is the number of voxels traversed along the ray, bounded by `maxSteps` (512) [S1, unofficial].
- Ray-Box Fallback: Not given in the sources.

**Memory Complexity:**
- $O(1)$ auxiliary memory for the controller state [S1, unofficial]. The voxel grid data is external [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- The DDA approach is efficient for sparse or dense grids as it only visits voxels along the ray path [S1, unofficial].
- The fallback to Ray-Box intersection is used when voxel data is unavailable, ensuring robustness but potentially less precise placement relative to internal geometry [S1, unofficial].

**Strengths:**
- Precise voxel-level control for painting and erasing [S1, unofficial].
- Handles both occupied and empty voxel placement (painting adjacent to hit, erasing at hit) [S1, unofficial].
- Robust fallback mechanism [S1, unofficial].

**Limitations:**
- Limited by `maxDist` (1024.0f) and `maxSteps` (512), which may cause rays to miss distant or complex geometry if not tuned [S1, unofficial].
- Precision issues at grid boundaries require epsilon adjustments [S1, unofficial].
- Division by zero protection requires epsilon checks [S1, unofficial].

**When to Use:**
- Real-time voxel editing in interactive applications (games, editors) [S1, unofficial].
- When direct manipulation of voxel data is required [S1, unofficial].

**When Not to Use:**
- When selection masks or fuzzy boundaries are preferred over hard voxel edits [S1, unofficial].
- When raycasting through extremely large volumes without spatial acceleration structures (though DDA is efficient, very long rays may hit step limits) [S1, unofficial].

## Background
The BrushController is part of the VENPOD project, a graphics programming tech demo targeting Windows and DirectX 12 [S1, unofficial]. It was developed as part of the sparse voxel rendering and editing pipeline, allowing users to interactively modify the voxel world [S1, unofficial]. The implementation uses a CPU-side controller for input handling and raycasting, with a fallback to ray-AABB intersection if voxel data is unavailable [S1, unofficial].
