# Voxel Grid Editing (Add/Remove)

Also called: Interactive voxel manipulation, Raycast-based Voxel Interaction, Screen-to-Voxel Mapping, Voxel Click Handling

## Overview
This method enables the dynamic modification of a voxel grid by adding or removing individual voxels at specific positions determined by raycasting from screen-space mouse input [S1, S2, unofficial]. Unlike static voxelization, this approach supports real-time editing where the user selects a target face on an existing voxel, and the system computes the adjacent empty voxel position for addition or the current voxel position for removal [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Screen-space mouse coordinates, camera parameters, current voxel grid state, and edit mode flag [S1, S2, unofficial].
*   **Output:** Modified voxel grid and regenerated mesh geometry [S1, S2, unofficial].

**Data Structures:**
The method uses a `HoverInfo` structure to track interaction state [S2, unofficial]:

```cpp
struct HoverInfo {
    bool hasHit;          // True if ray intersected a voxel
    OctreeNode* node;     // Pointer to the octree node hit (nullptr if no hit)
    glm::vec3 position;   // 3D world position of the hit point
    glm::vec3 normal;     // Face normal of the hit voxel at the hit point
    int depth;            // Octree depth of the hit node
};
```
The default constructor sets `hasHit=false`, `node=nullptr`, and `depth=0` [S2, unofficial].

**Numbered Steps:**
1.  **Ray Generation:** Convert the screen click position to a 3D ray originating from the camera using `Camera.ScreenPointToRay()` [S1, unofficial]. Let the ray be defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [S1, S2, unofficial].
2.  **Raycasting:** Cast the ray into the scene to detect intersections with the voxel grid. The result provides the hit position $\mathbf{p}$ and the face normal $\mathbf{n}$ at the intersection point [S1, unofficial]. If no hit occurs, the operation terminates [S2, unofficial].
3.  **Hit Voxel Identification:** Convert the 3D hit position $\mathbf{p}$ into voxel grid coordinates $(x, y, z)$ by dividing by the voxel size and applying floor or truncation [S1, unofficial]. Let this be the hit voxel position $\mathbf{v}_{\text{hit}}$ [S1, unofficial].
4.  **Target Position Calculation:** Determine the target voxel position $\mathbf{v}_{\text{target}}$ based on the edit mode and the hit face normal $\mathbf{n}$ [S1, S2, unofficial]:
    *   **Add Mode:** The new voxel is placed adjacent to the hit face. The target position is calculated as $\mathbf{v}_{\text{target}} = \mathbf{v}_{\text{hit}} + \mathbf{n}$ [S1, unofficial]. The normal $\mathbf{n}$ points outward from the hit voxel, indicating the direction of the empty adjacent voxel [S1, unofficial].
    *   **Remove Mode:** The target position is the hit voxel itself, $\mathbf{v}_{\text{target}} = \mathbf{v}_{\text{hit}}$ [S2, unofficial].
5.  **Grid Update:** Modify the voxel grid at $\mathbf{v}_{\text{target}}$:
    *   If **Add**: Set the voxel type/material at $\mathbf{v}_{\text{target}}$ to the current material and mark it as active [S1, unofficial].
    *   If **Remove**: Mark the voxel at $\mathbf{v}_{\text{target}}$ as inactive or delete it from the data structure [S2, unofficial].
6.  **Mesh Regeneration:** Trigger the mesh builder function to regenerate the visual representation of the voxel grid, reflecting the changes made in step 5 [S1, unofficial].

**Pseudocode:**
```python
def handle_voxel_edit(mouse_screen_pos, camera, grid, edit_mode, current_material, voxel_size=1.0):
    # Step 1: Generate Ray
    ray_origin, ray_direction = camera.screen_to_ray(mouse_screen_pos)

    # Step 2: Raycast
    hit = cast_ray(ray_origin, ray_direction, grid)
    if hit is None:
        return

    hit_position = hit.position
    hit_normal = hit.normal

    # Step 3: Identify Hit Voxel
    hit_voxel = (hit_position / voxel_size).astype(int)

    # Step 4 & 5: Determine Target and Update
    if edit_mode == 'add':
        # Convert unit normal to integer grid step, respecting voxel size
        target_voxel = hit_voxel + (hit_normal * voxel_size).astype(int)
        if grid.is_in_bounds(target_voxel):
            grid.set_voxel(target_voxel, current_material)
    elif edit_mode == 'remove':
        if grid.is_in_bounds(hit_voxel):
            grid.set_voxel(hit_voxel, None)

    # Step 6: Regenerate Mesh
    grid.rebuild_mesh()
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in converting hit position to voxel coordinates may cause off-by-one errors. Using consistent floor/truncation logic is critical [S1, unofficial].
*   **Boundary Conditions:** Adding a voxel outside the grid bounds must be handled to prevent array index out-of-bounds errors. Not given in the sources.
*   **Degenerate Input:** Clicking on empty space or non-voxel geometry should be ignored. The `hasHit` flag indicates whether a valid intersection occurred [S2, unofficial].
*   **Normal Direction:** The normal must be correctly interpreted as pointing outward from the hit voxel. If the normal is inverted, the add operation will place the voxel inside the existing one or in the wrong direction [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Depends on the voxel grid storage. The `HoverInfo` structure is $O(1)$ [S2, unofficial].
*   **Performance:** Real-time interaction is achievable on modern hardware. Mesh regeneration is the most expensive operation and should be optimized (e.g., incremental updates) for large grids. Not given in the sources.
*   **Strengths:** Intuitive user interaction, precise voxel placement, supports both addition and removal [S1, S2, unofficial].
*   **Limitations:** Single-voxel operations only; not suitable for large-scale edits without additional brush logic. Mesh regeneration can cause frame drops if not optimized [S1, unofficial].

This method is commonly used in voxel-based games and modeling tools (e.g., Minecraft, Voxel Shop) to allow users to sculpt or build voxel worlds interactively. The technique of converting screen clicks to 3D rays is a standard computer graphics primitive, adapted here for discrete voxel grids [S1, S2, unofficial].
