# BrushController

Also called: BrushController::DDAVoxelRaycast, BrushController::UpdateFromMouse

## Overview
A CPU-side controller for interactive voxel painting and erasing that determines the brush position and surface normal on a voxel grid using Digital Differential Analysis (DDA) raycasting [S1, unofficial]. It differs from its parent [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) by providing the specific state management and fallback logic for direct manipulation, and from siblings like [Reverse Index Map for Voxel Location](1097-reverse-index-map-for-voxel-location.md) by relying on traversal rather than lookup tables [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera position (`cameraPos`), camera basis vectors (`cameraForward`, `cameraRight`, `cameraUp`), field of view (`fov`), aspect ratio, mouse NDC coordinates (`mouseNDC.x`, `mouseNDC.y`), mouse button states (`leftButtonDown`, `rightButtonDown`), scroll delta (`scrollDelta`), voxel grid data (`voxelGridData`), grid size (`voxelGridSize`), and grid bounds (`m_gridMin`, `m_gridMax`).
*   **Outputs:** Updated brush state (`m_brushPosition`, `m_radius`, `m_material`, `m_mode`, `m_shape`), and a hit result indicating whether a voxel was found.

**Data Structures:**
The controller maintains a `BrushConstants` struct (or equivalent state object) with the following fields:
*   `positionX`, `positionY`, `positionZ`: `float` representing the brush center in voxel space.
*   `radius`: `float` defining the brush size.
*   `material`: `uint32_t` the material ID to paint (default 3 for Stone; 0 for air/erase).
*   `mode`: `uint32_t` current operation mode (Paint or Erase).
*   `shape`: `uint32_t` brush shape (default Sphere).
*   `strength`: `float` painting strength.
*   `gridSizeX`, `gridSizeY`, `gridSizeZ`: `uint32_t` dimensions of the voxel grid.
*   `seed`: `uint32_t` random seed for procedural generation if applicable.

**Parameters:**
*   `m_radius`: Default 5.0f. Adjustable via scroll wheel [S1, unofficial].
*   `m_material`: Default 3 (Stone). 0 is used for erasing (air) [S1, unofficial].
*   `maxDist`: Maximum raycast distance, constant 1024.0f [S1, unofficial].
*   `maxSteps`: Maximum DDA steps, constant 512 [S1, unofficial].
*   `epsilon`: Small value for safe inverse direction calculation, 1e-6f [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize State:** Set `m_brushPosition` to `(64.0f, 64.0f, 64.0f)`, `m_material` to 3, `m_radius` to 5.0f, `m_mode` to Paint, and `m_shape` to Sphere [S1, unofficial].
2.  **Process Input:**
    *   Set `m_isPainting = leftButtonDown` and `m_isErasing = rightButtonDown` [S1, unofficial].
    *   If `scrollDelta != 0.0f`, update radius: `SetRadius(m_radius + scrollDelta)` [S1, unofficial].
3.  **Calculate Ray Direction:**
    *   Compute `tanHalfFov = tan(fov * 0.5f)` [S1, unofficial].
    *   Calculate `rayDir` in world space:
        $$ \text{rayDir} = \text{normalize}(\text{cameraForward} + \text{cameraRight} \cdot \text{mouseNDC}.x \cdot \tan\text{HalfFov} \cdot \text{aspectRatio} + \text{cameraUp} \cdot \text{mouseNDC}.y \cdot \tan\text{HalfFov}) $$
        [S1, unofficial]
4.  **Raycasting:**
    *   **Case A: Voxel Data Available:** If `voxelGridData` is not null and `voxelGridSize` > 0:
        *   Perform DDA raycast from `cameraPos` along `rayDir`.
        *   If a hit is found:
            *   If erasing: `targetVoxel = hitVoxel` [S1, unofficial].
            *   If painting: `targetVoxel = hitVoxel + hitNormal` [S1, unofficial].
    *   **Case B: Voxel Data Unavailable (Fallback):**
        *   Perform Ray-AABB intersection (`RayBoxIntersect`) against the grid bounds.
        *   If hit:
            *   Set `t = max(tMin, 0.0f) + 10.0f` [S1, unofficial].
            *   Calculate `hitPos = cameraPos + rayDir * t`.
            *   Clamp `hitPos` to grid bounds.
            *   Set `targetVoxel` to the clamped position.
5.  **Update Brush Position:**
    *   Set `m_brushPosition = targetVoxel + (0.5f, 0.5f, 0.5f)` [S1, unofficial].
    *   Clamp `m_brushPosition` to `[m_gridMin + 0.5f, m_gridMax - 0.5f]` [S1, unofficial].

                target_voxel = hit_voxel

**Edge Cases and Pitfalls:**
*   **Division by Zero:** When calculating inverse ray direction for DDA, if `abs(rayDir.x) < epsilon`, use `1e6f` instead of `1/rayDir.x` to prevent division by zero [S1, unofficial].
*   **Precision Issues:** At grid boundaries, add `1e-4f` to `startPos` before flooring to get `voxelPos` to avoid precision errors [S1, unofficial].
*   **Painting vs. Erasing Placement:** Painting places the brush adjacent to the hit voxel (`hitVoxel + hitNormal`), while erasing places it on the hit voxel itself (`hitVoxel`) [S1, unofficial].

## Subtopics

### [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md)
This method enables interactive voxel painting and erasing by casting a ray from the camera through the mouse cursor to determine the brush position and surface normal on the voxel grid. It differs from global noise generation by allowing localized, immediate edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction. It builds on [BrushController](2362-brushcontroller.md) by implementing the specific raycasting logic for voxel selection.

### [Volume Painting for Selection](6454-volume-painting-for-selection.md)
Volume Painting for Selection is a 3D volumetric painting approach for selection definition where a user clicks on the image plane, casting a ray into the volume to find the first non-transparent voxel, then drawing a 3D Gaussian brush into the selection volume. It differs from [Voxel Grid Edit via Raycasting](3190-voxel-grid-edit-via-raycasting.md) by focusing on defining a fuzzy selection envelope via additive/subtractive painting rather than direct voxel modification, and from its parent [BrushController](2362-brushcontroller.md) by providing the specific interaction logic for brush placement and composition.

### Voxel Edits
A GPU-based variant where a single compute shader thread computes the ray intersection with the world, writing the result to a small storage buffer. A second shader then places a ball of voxels based on the selected material around the found intersection position [S2, unofficial]. This approach avoids moving voxel data to the CPU, allowing virtually unlimited voxel edits constrained only by world boundaries [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** DDA raycasting is $O(N)$ where $N$ is the number of voxels traversed, bounded by `maxSteps` (512) [S1, unofficial].
*   **Memory Complexity:** $O(1)$ for the controller state; $O(V)$ for the voxel grid data where $V$ is the grid size [S1, unofficial].
*   **Performance:** The CPU-side DDA approach is stable but may be slower than GPU variants for large grids due to data transfer overhead if not optimized [S1, unofficial]. The GPU variant ("Voxel Edits") reduces CPU overhead but uses a single thread for raycasting, which is noted as "wasteful" but efficient compared to CPU transfer [S2, unofficial].
*   **Strengths:** Simple implementation, robust fallback to ray-box intersection, immediate visual feedback [S1, unofficial].
*   **Limitations:** CPU-bound DDA may bottleneck on very large grids or high frame rates; precision issues at boundaries require careful handling [S1, unofficial].

## Background
Originating from the VENPOD project, a DirectX 12 voxel rendering tech demo, this method was developed to provide interactive voxel editing capabilities [S1, unofficial]. It is part of a sparse voxel architecture that supports both dense legacy rendering and sparse brick-based rendering [S1, unofficial]. The method is used in the sandbox mode of the VENPOD engine for user-driven world modification [S1, unofficial].
