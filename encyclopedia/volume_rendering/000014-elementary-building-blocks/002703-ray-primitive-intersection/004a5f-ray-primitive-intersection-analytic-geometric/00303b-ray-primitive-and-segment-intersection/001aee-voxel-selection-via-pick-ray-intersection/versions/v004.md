# Voxel selection via pick ray intersection

Also called: Basic picker, Pick ray intersection for voxel selection, Voxel Picking with Bresenham's Algorithm, Voxel Selecting

## Overview
This method extracts spatial information from a simulation or volume by mapping 2D screen coordinates to a specific 3D voxel index, serving as a seed for direct manipulation or segmentation [S1, S2, S3, unofficial]. It differs from [Ray-Box Intersection for Interaction](2638-ray-box-intersection-for-interaction.md) by focusing on identifying a discrete seed voxel for segmentation rather than computing a geometric hit point for fluid injection, and from [Reverse Index Map for Voxel Location](1097-reverse-index-map-for-voxel-location.md) by using algorithmic traversal rather than a pre-computed index texture [S1, S2, S3, unofficial].

## How it works
**Inputs:**
*   Screen coordinates $(x, y)$ of the user click [S2, S3, unofficial].
*   Camera projection parameters (orthographic or perspective, though implementation varies) [S1, S2, unofficial].
*   Volume bounding box defined by minimum $(x_{min}, y_{min}, z_{min})$ and maximum $(x_{max}, y_{max}, z_{max})$ extents [S2, unofficial].
*   Voxel grid dimensions $(N_x, N_y, N_z)$ [S1, S2, unofficial].

**Outputs:**
*   The 3D voxel index $(i, j, k)$ corresponding to the intersection point [S2, unofficial].

**Data Structures:**
*   The volume is represented as a 3D grid. No auxiliary structures are required for the core intersection logic [S1, S2, unofficial].

**Steps:**
1.  **Construct Pick Ray:** Generate a ray from the camera through the screen coordinates $(x, y)$ [S2, unofficial].
    *   For orthographic projection, the ray direction is constant (typically aligned with the view vector) [S1, unofficial].
    *   For perspective projection, the ray origin is the camera position, and the direction is calculated from the camera frustum [S2, unofficial].
2.  **Intersect with Bounding Box:** Perform standard ray-AABB (Axis-Aligned Bounding Box) intersection tests to find the entry and exit points of the ray with the volume's rectangular solid [S2, unofficial]. This is described as a "standard technique" similar to ray tracing [S2, unofficial].
3.  **Traverse Voxel Grid:**
    *   *Approach A (Ray Tracing):* Use the intersection point to determine the voxel index directly via coordinate transformation [S2, unofficial].
    *   *Approach B (Bresenham's):* Use a modified Bresenham's Algorithm to traverse the voxel grid along the ray path [S1, unofficial]. This method is noted as an advantage of using voxels for its efficiency in extracting spatial information [S1, unofficial].
4.  **Return Index:** Output the $(i, j, k)$ coordinates of the first (or closest) voxel intersected [S2, S3, unofficial].

**Formulas:**
*   Ray-Box Intersection: Standard slab method. For each axis $d \in \{x, y, z\}$:
    $$ t_{min} = \max \left( \frac{x_{min} - O_d}{D_d}, \frac{x_{max} - O_d}{D_d} \right) $$
    $$ t_{max} = \min \left( \frac{x_{min} - O_d}{D_d}, \frac{x_{max} - O_d}{D_d} \right) $$
    The ray intersects the box if $\max(t_{min}) \le \min(t_{max})$ [S2, unofficial].
*   Voxel Index from World Position $(X, Y, Z)$:
    $$ i = \lfloor \frac{X - x_{min}}{x_{max} - x_{min}} N_x \rfloor $$
    $$ j = \lfloor \frac{Y - y_{min}}{y_{max} - y_{min}} N_y \rfloor $$
    $$ k = \lfloor \frac{Z - z_{min}}{z_{max} - z_{min}} N_z \rfloor $$
    [S2, inferred from standard volume mapping, unofficial].

**Parameters:**
*   Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Projection Support:** The specific implementation using Bresenham's algorithm described in [S1, unofficial] only works for orthographic projections and does not support perspective projections [S1, unofficial].
*   **Degenerate Input:** If the ray does not intersect the volume bounding box, no voxel is selected [S2, unofficial].

**Pseudocode:**
```python
def pick_voxel(screen_x, screen_y, camera, volume_bounds, voxel_dims):
    # 1. Construct Pick Ray
    # camera.get_ray(screen_x, screen_y) returns (origin, direction)
    ray_origin, ray_direction = camera.get_ray(screen_x, screen_y)
    
    # 2. Intersect with Bounding Box
    # Standard slab method for AABB
    t_min = -float('inf')
    t_max = float('inf')
    
    for axis in range(3):
        if abs(ray_direction[axis]) < 1e-8:
            # Ray is parallel to slab
            if ray_origin[axis] < volume_bounds.min[axis] or ray_origin[axis] > volume_bounds.max[axis]:
                return None # No intersection
        else:
            t1 = (volume_bounds.min[axis] - ray_origin[axis]) / ray_direction[axis]
            t2 = (volume_bounds.max[axis] - ray_origin[axis]) / ray_direction[axis]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
            
    if t_max < t_min:
        return None # No intersection
        
    # Use the entry point of the ray into the volume
    t_entry = max(t_min, 0.0)
    hit_point = ray_origin + ray_direction * t_entry
    
    # 3. Convert World Position to Voxel Index
    # Assuming volume_bounds covers the entire voxel grid
    x_range = volume_bounds.max.x - volume_bounds.min.x
    y_range = volume_bounds.max.y - volume_bounds.min.y
    z_range = volume_bounds.max.z - volume_bounds.min.z
    
    voxel_x = int((hit_point.x - volume_bounds.min.x) / x_range * voxel_dims.x)
    voxel_y = int((hit_point.y - volume_bounds.min.y) / y_range * voxel_dims.y)
    voxel_z = int((hit_point.z - volume_bounds.min.z) / z_range * voxel_dims.z)
    
    # Clamp to valid range
    voxel_x = max(0, min(voxel_x, voxel_dims.x - 1))
    voxel_y = max(0, min(voxel_y, voxel_dims.y - 1))
    voxel_z = max(0, min(voxel_z, voxel_dims.z - 1))
    
    return (voxel_x, voxel_y, voxel_z)
```

## Subtopics

### [Reverse Index Map for Voxel Location](1097-reverse-index-map-for-voxel-location.md)
Uses a pre-computed index texture to map screen pixels to volume coordinates, differing by avoiding runtime ray casting.

### [BrushController](2362-brushcontroller.md)
A CPU-side controller using DDA raycasting for dynamic voxel painting, differing by supporting addition/removal of voxels rather than just selection.

### [Ray-Box Intersection for Interaction](2638-ray-box-intersection-for-interaction.md)
Focuses on geometric intersection for fluid injection, differing by targeting world positions for simulation effects rather than discrete segmentation seeds.

## Operating characteristics
*   **Time Complexity:** $O(1)$ for ray-box intersection and coordinate conversion. $O(N)$ for Bresenham traversal if used, where $N$ is the number of voxels along the ray path [S1, S2, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory [S1, S2, unofficial].
*   **Strengths:** Intuitive user interface for segmentation; efficient for orthographic views [S1, S3, unofficial].
*   **Limitations:** The Bresenham-based implementation is limited to orthographic projections [S1, unofficial].
*   **When to use:** When direct manipulation of segmentation seeds is required in orthographic views [S1, S2, unofficial].

## Background
The method originated in the context of volume visualization and segmentation applications, specifically the SIV (Segmentation of Isosurfaces in Volumes) system [S2, unofficial]. It was also independently implemented in homebrew voxel engines for real-time spatial extraction [S1, unofficial]. It is used in isosurface segmentation workflows to collect seed points via mouse clicks and drags [S3, unofficial].
