# Linear Edge Intersection

Also called: Edge Crossing Linear Interpolation, Edge Intersection Calculation, Edge Intersection Vertex Interpolation, Linear Edge Interpolation, Linear Interpolation for Edge Intersection, Linear Interpolation for Marching Cubes, Linear Interpolation for Marching Cubes Edge Vertices, LinearInterp

## Overview
Linear Edge Intersection determines the precise position of an isosurface intersection on a grid edge by linearly interpolating between the two vertices defining that edge, based on their scalar field values and the target isovalue [S1, S2, S5, unofficial]. It solves the problem of locating the exact geometric point where a scalar field crosses a threshold within a voxel, which is a fundamental step in algorithms like Marching Cubes [S1, unofficial]. It sets itself apart from its siblings, such as [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md) which selects voxels, and [Boundary Segment Validity Conditions](7652-boundary-segment-validity-conditions.md) which checks validity, by explicitly computing the coordinate of the intersection point itself [S1, S5, unofficial]. Unlike [Linear Intersection Approximation](1232-linear-intersection-approximation.md) which uses the geometric midpoint, Linear Edge Intersection uses the scalar values to weight the position, providing higher accuracy for non-uniform fields [S1, S5, unofficial].

## How it works
**Inputs:**
*   $P_1, P_2$: 3D coordinates of the two endpoints of the grid edge (vectors).
*   $V_1, V_2$: Scalar field values (e.g., density, SDF, intensity) at $P_1$ and $P_2$ respectively.
*   $iso$: The target isovalue (threshold) defining the surface.
*   $\epsilon$: A small tolerance for numerical stability checks (typical values: $10^{-5}$ to $10^{-7}$) [S4, S5, unofficial].

**Outputs:**
*   $P$: The 3D coordinate of the intersection point on the edge.

**Data Structures:**
*   The method operates on two points and two scalar values. No complex data structures are required beyond standard vector and scalar types.

**Steps:**
1.  **Identify Intersected Edge:** Determine if the edge intersects the isosurface. This occurs if one endpoint's scalar value is less than or equal to the isovalue and the other is greater than or equal to it (i.e., $(V_1 - iso) \cdot (V_2 - iso) \le 0$) [S1, S5, unofficial]. If both values are on the same side of the isovalue, there is no intersection on this edge.
2.  **Handle Degenerate Cases:** Check if the scalar values at the endpoints are nearly identical or if an endpoint lies exactly on the isosurface.
    *   If $|V_1 - V_2| < \epsilon$, the denominator would be near-zero. Return $P_1$ as the intersection point [S5, S6, unofficial].
    *   Alternatively, if $|V_1 - iso| < \epsilon$, return $P_1$ [S4, unofficial].
    *   If $|V_2 - iso| < \epsilon$, return $P_2$ [S4, unofficial].
3.  **Calculate Interpolation Factor:** Compute the relative position $t$ (or $\mu$) along the edge where the isosurface is crossed. The standard formula is:
    $$ t = \frac{iso - V_1}{V_2 - V_1} $$
    [S1, S4, S5, unofficial].
    
    *Numerical Stability Variant:* To avoid cancellation errors when vertices are near the plane, some implementations use signed distances $d_0 = V_1 - iso$ and $d_1 = V_2 - iso$ (or vice versa depending on convention). If $d_0$ is the signed distance of $P_1$ and $d_1$ is the signed distance of $P_2$, and assuming $P_1$ is "behind" ($d_1 \le 0$) and $P_2$ is "in front" ($d_0 > 0$), the intersection is:
    $$ P = \frac{d_0 P_2 - d_1 P_1}{d_0 - d_1} $$
    [S3, unofficial]. Note that $d_0 - d_1 = (V_1 - iso) - (V_2 - iso) = V_1 - V_2 = -(V_2 - V_1)$. The numerator becomes $(V_1 - iso)P_2 - (V_2 - iso)P_1$. This is algebraically equivalent to the standard interpolation but can be more stable in clipping routines [S3, unofficial].
    
    *Clamping:* To ensure the point lies strictly within the edge segment, clamp $t$ to $[0, 1]$:
    $$ t = \max(0.0, \min(1.0, t)) $$
    [S5, unofficial].
4.  **Compute Intersection Point:** Calculate the final position using linear interpolation:
    $$ P = P_1 + t (P_2 - P_1) $$
    [S1, S5, unofficial].
    
    *Alternative Weighted Form:* Some implementations compute weights $w_1 = \frac{|iso - V_2|}{|V_2 - V_1|}$ and $w_2 = \frac{|iso - V_1|}{|V_2 - V_1|}$ and return $P = w_1 P_1 + w_2 P_2$ [S6, unofficial]. This is equivalent to the standard form if signs are handled correctly.

**Pseudocode:**
```python
def linear_edge_intersection(p1, p2, v1, v2, iso, epsilon=1e-7):
    """
    Calculates the intersection point of an isosurface with a grid edge.
    
    Args:
        p1: Vector3, coordinates of the first endpoint.
        p2: Vector3, coordinates of the second endpoint.
        v1: Float, scalar value at p1.
        v2: Float, scalar value at p2.
        iso: Float, the target isovalue.
        epsilon: Float, tolerance for degenerate cases.
        
    Returns:
        Vector3, the intersection point.
    """
    # Check for degenerate case where scalar values are equal
    if abs(v1 - v2) < epsilon:
        return p1
    
    # Calculate interpolation factor
    # t represents the fraction of the distance from p1 to p2
    t = (iso - v1) / (v2 - v1)
    
    # Clamp t to [0, 1] to handle floating point inaccuracies or edge cases
    # where the intersection might slightly fall outside due to precision
    t = max(0.0, min(1.0, t))
    
    # Compute the intersection point
    # P = P1 + t * (P2 - P1)
    intersection = p1 + t * (p2 - p1)
    
    return intersection
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $V_1 = V_2$, the denominator is zero. This must be guarded against by checking $|V_1 - V_2| < \epsilon$ [S2, S5, S6, unofficial].
*   **Endpoint on Surface:** If $V_1 = iso$ or $V_2 = iso$, the intersection is exactly at the vertex. While the formula works, explicit checks can save computation and avoid precision issues [S4, unofficial].
*   **Vertex Ordering:** In some lookup table implementations, consistent ordering of $P_1$ and $P_2$ (e.g., by coordinate value) is required to ensure correct triangle generation and normal orientation. Incorrect ordering can lead to back-facing triangles or holes [S1, S2, unofficial].
*   **Multiple Roots:** Linear interpolation assumes a single root per edge. If the scalar field has two roots within the voxel (e.g., a thin feature), linear interpolation on the edge will only find one, potentially missing geometry [S8, unofficial].

## Subtopics

### [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md)
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies.

### [Linear Intersection Approximation](1232-linear-intersection-approximation.md)
Linear Intersection Approximation (also known as Midpoint Intersection) estimates the intersection point of an isosurface with a grid edge by calculating the geometric midpoint of the edge, rather than performing linear interpolation based on scalar values. It differs from its parent, [Linear Edge Intersection](868-linear-edge-intersection.md), by ignoring endpoint scalar values entirely, and from its sibling, [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), by using a single fixed geometric step instead of recursive refinement [G].

### [Inverse Linear Interpolation](12154-inverse-linear-interpolation.md)
Inverse Linear Interpolation calculates the non-integer position $x$ corresponding to a specific scalar value $v$ between two known values $v_1$ and $v_2$ at positions $x_1$ and $x_2$, assuming linear variation. It is primarily used for finding iso-surface intersections or specific density levels within a volume. Unlike [Linear Edge Intersection](868-linear-edge-intersection.md), which computes the exact intersection on a grid edge, this method provides the general algebraic inversion of linear interpolation.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per edge. The calculation involves a constant number of arithmetic operations (subtraction, division, multiplication, addition).
*   **Memory Complexity:** $O(1)$. No additional memory is required beyond local variables.
*   **Performance:** Extremely fast. It is the dominant cost in simple Marching Cubes implementations only in terms of total edge count, but per-edge it is negligible compared to ray tracing or volume rendering steps.
*   **Strengths:** Simple to implement, numerically stable with proper epsilon checks, provides exact linear approximation of the surface.
*   **Limitations:** Assumes the scalar field varies linearly between vertices. This is an approximation; if the field is highly non-linear, the intersection point will be inaccurate. It cannot resolve multiple intersections per edge [S8, unofficial].
*   **When to use:** Standard isosurface extraction (Marching Cubes, Marching Tetrahedra) where linear variation is a reasonable assumption.
*   **When not to use:** When high accuracy is required for highly non-linear fields (use [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) or higher-order interpolation), or when multiple roots per edge are expected.

## Background
Linear Edge Intersection is a core component of the Marching Cubes algorithm, introduced by Lorensen and Cline in 1987 [S1, S5, unofficial]. It relies on the assumption that the scalar field within a voxel varies linearly between its vertices. This allows the isosurface to be approximated as a set of planar polygons connecting the intersection points on the edges. The method is widely used in medical imaging, geological modeling, and computer graphics for surface reconstruction from volumetric data. Variants and refinements, such as using signed distances for stability [S3, unofficial] or iterative bisection for accuracy [S13], have been developed to address specific numerical or topological issues.
