# Linear Edge Intersection

Also called: Edge Crossing Linear Interpolation, Edge Intersection Calculation, Edge Intersection Vertex Interpolation, Linear Edge Interpolation, Linear Interpolation for Edge Intersection, Linear Interpolation for Marching Cubes, Linear Interpolation for Marching Cubes Edge Vertices, LinearInterp

## Overview
Linear Edge Intersection determines the precise position where an isosurface intersects a grid edge by linearly interpolating between the scalar field values at the two vertices defining that edge [S1, S2, S5, unofficial]. It solves the geometric reconstruction problem in algorithms like Marching Cubes, where the continuous scalar field is approximated as piecewise linear within each voxel [S1, S8, unofficial]. Unlike [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), which uses repeated subdivision for higher accuracy, or [Linear Intersection Approximation](1232-linear-intersection-approximation.md), which ignores scalar values entirely, Linear Edge Intersection provides a direct, closed-form solution based on the assumption that the scalar field varies linearly between grid points [S1, S8, unofficial].

## How it works
**Inputs:**
*   $P_1, P_2$: 3D coordinates of the two endpoints of the grid edge ($P_1, P_2 \in \mathbb{R}^3$).
*   $V_1, V_2$: Scalar field values (e.g., density, SDF) at $P_1$ and $P_2$ respectively ($V_1, V_2 \in \mathbb{R}$).
*   $iso$: The target isovalue or threshold defining the isosurface ($iso \in \mathbb{R}$).

**Outputs:**
*   $P$: The 3D coordinate of the intersection point on the edge ($P \in \mathbb{R}^3$).

**Data Structures:**
*   The method operates on scalar values and 3D vectors. No complex data structures are required beyond the input coordinates and values.

**Steps:**
1.  **Check for Degeneracy:** Calculate the difference $\Delta V = V_2 - V_1$. If $|\Delta V|$ is less than a small epsilon $\epsilon$ (typically $10^{-5}$ to $10^{-7}$), the scalar values are effectively equal. In this case, the intersection is undefined or coincident with an endpoint. Return $P_1$ (or $P_2$) as the intersection point [S4, S5, S6, unofficial].
2.  **Calculate Interpolation Factor:** Compute the normalized distance $t$ (or $\mu$) along the edge from $P_1$ to $P_2$ where the scalar value equals $iso$.
    $$ t = \frac{iso - V_1}{V_2 - V_1} $$
    Some implementations clamp $t$ to the range $[0, 1]$ to handle numerical noise or out-of-bounds thresholds:
    $$ t = \max(0.0, \min(1.0, t)) $$ [S5, unofficial].
3.  **Compute Intersection Point:** Interpolate the position using the factor $t$:
    $$ P = P_1 + t (P_2 - P_1) $$
    Alternatively, using weighted averages:
    $$ P = (1 - t) P_1 + t P_2 $$ [S7, unofficial].

**Stable Variant (Signed Distance):**
When the intersection is with a plane defined by signed distances $d_0$ and $d_1$ of vertices $x_0$ and $x_1$, a numerically stable formula avoids division by small differences in scalar values:
$$ \mathbf{x}_p = \frac{d_0 \mathbf{x}_1 - d_1 \mathbf{x}_0}{d_0 - d_1} $$
This guarantees $d_0 - d_1 > 0$ if strict inequalities are used in clipping, preventing divide-by-zero errors even in finite precision [S3, unofficial].

**Pseudocode:**
```python
def linear_edge_intersection(p1, p2, v1, v2, iso, epsilon=1e-7):
    """
    Calculate the intersection point of an isosurface with a grid edge.
    
    Args:
        p1 (tuple): 3D coordinates of the first endpoint.
        p2 (tuple): 3D coordinates of the second endpoint.
        v1 (float): Scalar value at p1.
        v2 (float): Scalar value at p2.
        iso (float): The target isovalue.
        epsilon (float): Threshold for detecting degenerate edges.
        
    Returns:
        tuple: 3D coordinates of the intersection point.
    """
    # Step 1: Check for degeneracy (equal scalar values)
    if abs(v2 - v1) < epsilon:
        return p1
    
    # Step 2: Calculate interpolation factor
    # Using the standard linear interpolation formula
    t = (iso - v1) / (v2 - v1)
    
    # Optional: Clamp t to [0, 1] for robustness against numerical noise
    # t = max(0.0, min(1.0, t))
    
    # Step 3: Compute intersection point
    # P = P1 + t * (P2 - P1)
    px = p1[0] + t * (p2[0] - p1[0])
    py = p1[1] + t * (p2[1] - p1[1])
    pz = p1[2] + t * (p2[2] - p1[2])
    
    return (px, py, pz)
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $V_1 = V_2$, the denominator in the interpolation factor becomes zero. This must be handled by checking $|V_2 - V_1| < \epsilon$ [S2, S4, S5, S6, unofficial].
*   **Endpoint Ordering:** Consistency in assigning $P_1/V_1$ and $P_2/V_2$ is crucial. $P_1$ should correspond to the vertex with the lower coordinate value along the edge axis (or consistently ordered by index) to ensure correct normal generation and topology in subsequent meshing steps [S1, S2, unofficial]. Swapping references instead of copying values can lead to side effects if original vectors are modified [S2, unofficial].
*   **Multiple Roots:** Linear interpolation assumes a single root per edge. If the scalar field has two roots within the voxel (e.g., a thin feature smaller than the grid spacing), linear interpolation will fail to find the correct intersection, potentially missing geometry or creating artifacts [S8, unofficial].
*   **Back-facing Triangles:** Incorrect vertex ordering in the lookup table or triangle generation, often stemming from inconsistent edge intersection ordering, can cause triangles to face inwards, resulting in rendering holes [S2, unofficial].

## Subtopics

### [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md)
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies.

### [Linear Intersection Approximation](1232-linear-intersection-approximation.md)
Linear Intersection Approximation (also known as Midpoint Intersection) estimates the intersection point of an isosurface with a grid edge by calculating the geometric midpoint of the edge, rather than performing linear interpolation based on scalar values. It differs from its parent, [Linear Edge Intersection](868-linear-edge-intersection.md), by ignoring endpoint scalar values entirely, and from its sibling, [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), by using a single fixed geometric step instead of recursive refinement [G].

### [Inverse Linear Interpolation](12154-inverse-linear-interpolation.md)
Inverse Linear Interpolation calculates the non-integer position $x$ corresponding to a specific scalar value $v$ between two known values $v_1$ and $v_2$ at positions $x_1$ and $x_2$, assuming linear variation. It is primarily used for finding iso-surface intersections or specific density levels within a volume. Unlike [Linear Edge Intersection](868-linear-edge-intersection.md), which computes the exact intersection on a grid edge, this method provides the general algebraic inversion of linear interpolation.

### [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md)
Hermite interpolation for isosurface extraction determines the precise position of an isovertex along an edge where the scalar field value equals a specific threshold, utilizing both function values and gradients (Hermite data) to perform higher-order interpolation. It solves the problem of reconstruction artifacts caused by non-linear implicit functions, which linear interpolation (as used in [Linear Edge Intersection](868-linear-edge-intersection.md)) fails to capture accurately. By incorporating gradient information, it provides a more accurate isosurface representation for implicit functions that are not piecewise linear.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per edge. The calculation involves a constant number of arithmetic operations (subtraction, division, multiplication, addition).
*   **Memory Complexity:** $O(1)$. No additional memory is required beyond the input variables.
*   **Performance:** This is the fastest method for edge intersection calculation. It is significantly faster than iterative methods like bisection or Newton-Raphson, which require multiple function evaluations per edge [S8, unofficial].
*   **Accuracy:** Provides first-order accuracy. It assumes the scalar field is linear between grid points. Accuracy degrades if the underlying function is highly non-linear or if the grid resolution is insufficient to capture fine details [S8, unofficial][S13].
*   **Strengths:** Simplicity, speed, and numerical stability (especially with the signed distance variant) [S3, unofficial]. It is the standard method for Marching Cubes and similar algorithms.
*   **Limitations:** Cannot resolve multiple intersections per edge. Prone to artifacts if the scalar field varies significantly within a voxel [S8, unofficial].
*   **When to Use:** Standard isosurface extraction (Marching Cubes, Marching Tetrahedra) where performance is critical and the scalar field is relatively smooth or the grid is fine enough.
*   **When Not to Use:** When high geometric accuracy is required for highly non-linear fields, or when multiple roots per edge are expected (use [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) or [Hermite Interpolation](13666-hermite-interpolation-for-isosurface-extraction.md)).

## Background
Linear Edge Intersection is a fundamental technique in computer graphics, primarily associated with the Marching Cubes algorithm introduced by Lorensen and Cline in 1987 [S1, S2, unofficial]. It relies on the assumption that the scalar field within a voxel can be approximated by a linear function between its vertices. This method has become the de facto standard for real-time isosurface extraction due to its computational efficiency. Variants and refinements, such as the stable signed-distance formulation, have been developed to address numerical instability issues in finite precision arithmetic [S3, unofficial].
