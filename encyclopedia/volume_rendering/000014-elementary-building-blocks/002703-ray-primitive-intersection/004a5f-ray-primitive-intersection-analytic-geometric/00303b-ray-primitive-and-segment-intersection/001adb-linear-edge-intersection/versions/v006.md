# Linear Edge Intersection

Also called: Linear Edge Interpolation

## Overview
Linear Edge Intersection determines the precise position where an isosurface intersects a grid edge by linearly interpolating between the scalar field values at the two defining vertices [S1, S2, unofficial][S4][S5, S6, S7, unofficial]. It solves the geometric problem of locating surface vertices for mesh extraction algorithms (such as Marching Cubes) or ray-marching steps [S1, S9, unofficial]. It sets itself apart from [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) by providing a single-step analytical solution rather than an iterative approximation, and from [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md) by ignoring gradient information, assuming strictly linear variation between endpoints [S1, unofficial][S13].

## How it works
**Inputs:**
*   Two edge endpoints: $\mathbf{p}_1, \mathbf{p}_2 \in \mathbb{R}^3$ (3D coordinates).
*   Scalar field values at endpoints: $v_1, v_2 \in \mathbb{R}$.
*   Target isovalue (threshold): $iso \in \mathbb{R}$.
*   (Optional) Epsilon for degenerate checks: $\epsilon$ (typically $10^{-5}$ to $10^{-7}$) [S5, S6, unofficial].

**Outputs:**
*   Intersection point $\mathbf{p} \in \mathbb{R}^3$.

**Data Structures:**
*   Points are represented as 3D vectors.
*   Scalar values are floating-point numbers.

**Steps:**

1.  **Degeneracy Check:** Calculate the difference $\Delta v = v_2 - v_1$. If $|\Delta v| < \epsilon$, the edge is parallel to the isosurface or the values are identical. Return $\mathbf{p}_1$ [S6, S7, S2, unofficial].
    *   *Note:* Some implementations also check if $v_1$ or $v_2$ is exactly equal to $iso$ within $\epsilon$, returning the respective vertex directly [S5, unofficial].
2.  **Calculate Interpolation Factor:** Compute the normalized distance $t$ (or $\mu$) along the edge where the scalar value equals $iso$.
    $$ t = \frac{iso - v_1}{v_2 - v_1} $$
    [S1, S2, unofficial][S4][S5, S6, S9, unofficial]
3.  **Clamping (Optional but Recommended):** To prevent numerical artifacts when $t$ falls slightly outside $[0, 1]$ due to precision errors, clamp $t$:
    $$ t = \max(0.0, \min(1.0, t)) $$
    [S6, unofficial]
4.  **Compute Intersection Point:** Interpolate the position using the factor $t$.
    $$ \mathbf{p} = \mathbf{p}_1 + t (\mathbf{p}_2 - \mathbf{p}_1) $$
    [S1, S2, unofficial][S4][S5, S6, unofficial]
    *   *Alternative Form:* Using weights $\alpha = t$ and $1-\alpha$:
        $$ \mathbf{p} = (1 - t)\mathbf{p}_1 + t\mathbf{p}_2 $$
        [S4][S8, unofficial]
    *   *Signed Distance Form:* If using signed distances $d_1, d_2$ to the plane defined by $iso$ (where $d_i = v_i - iso$), the formula becomes:
        $$ \mathbf{p} = \frac{d_1 \mathbf{p}_2 - d_2 \mathbf{p}_1}{d_1 - d_2} $$
        This form is numerically more stable when vertices are very close to the plane [S3, unofficial]. Note that $d_1 - d_2 = v_1 - v_2 = -\Delta v$, so the denominator is non-zero if the degeneracy check passed.

**Pseudocode:**

```python
def linear_edge_intersection(p1, p2, v1, v2, iso, epsilon=1e-7):
    """
    Calculate the intersection point of an isosurface with a grid edge.
    
    Args:
        p1: 3D vector (x, y, z) of first endpoint.
        p2: 3D vector (x, y, z) of second endpoint.
        v1: Scalar value at p1.
        v2: Scalar value at p2.
        iso: Target isovalue.
        epsilon: Threshold for degenerate case detection.
        
    Returns:
        3D vector (x, y, z) of the intersection point.
    """
    # Step 1: Degeneracy check
    diff = v2 - v1
    if abs(diff) < epsilon:
        return p1
    
    # Step 2: Calculate interpolation factor
    t = (iso - v1) / diff
    
    # Step 3: Clamp to [0, 1] to handle precision errors
    if t < 0.0:
        t = 0.0
    elif t > 1.0:
        t = 1.0
        
    # Step 4: Compute intersection point
    # p = p1 + t * (p2 - p1)
    px = p1[0] + t * (p2[0] - p1[0])
    py = p1[1] + t * (p2[1] - p1[1])
    pz = p1[2] + t * (p2[2] - p1[2])
    
    return (px, py, pz)
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** Occurs if $v_1 = v_2$. Must be guarded by an epsilon check [S2, S6, S7, unofficial].
*   **Vertex Ordering:** The formula assumes consistent assignment of $P_1/V_1$ and $P_2/V_2$. While the math holds regardless of order, some lookup tables or triangle generation logic depend on specific vertex ordering (e.g., lower coordinate index first) to ensure correct normal orientation and avoid back-facing triangles [S1, S2, unofficial].
*   **Multiple Roots:** Linear interpolation assumes a single root per edge. If the scalar field has two roots within the voxel/edge segment, this method will fail to find the correct intersection or return a point between them, potentially causing topological errors [S9, unofficial].
*   **Precision:** When vertices are nearly coplanar with the isosurface, standard parametric intersection can suffer from cancellation errors. The signed distance formulation or clamping helps mitigate this [S3, unofficial].

## Subtopics

### [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md)
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies.

### [Linear Intersection Approximation](1232-linear-intersection-approximation.md)
Linear Intersection Approximation (also known as Midpoint Intersection) estimates the intersection point of an isosurface with a grid edge by calculating the geometric midpoint of the edge, rather than performing linear interpolation based on scalar values. It differs from its parent, [Linear Edge Intersection](868-linear-edge-intersection.md), by ignoring endpoint scalar values entirely, and from its sibling, [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), by using a single fixed geometric step instead of recursive refinement [G].

### [Inverse Linear Interpolation](12154-inverse-linear-interpolation.md)
Inverse Linear Interpolation calculates the non-integer position $x$ corresponding to a specific scalar value $v$ between two known values $v_1$ and $v_2$ at positions $x_1$ and $x_2$, assuming linear variation. It is primarily used for finding iso-surface intersections or specific density levels within a volume. Unlike [Linear Edge Intersection](868-linear-edge-intersection.md), which computes the exact intersection on a grid edge, this method provides the general algebraic inversion of linear interpolation.

### [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md)
Hermite interpolation for isosurface extraction determines the precise position of an isovertex along a zero-crossing edge by utilizing both scalar field values and gradient information (Hermite data) at the edge endpoints. Unlike [Linear Edge Intersection](868-linear-edge-intersection.md), which assumes linear variation and produces artifacts on non-linear implicit functions, this method fits higher-order polynomials to the local field behavior, significantly improving surface accuracy. It is primarily used in contouring algorithms like Marching Cubes where gradient data is available or can be approximated.

### [Edge-Crossing Error Approximation](15075-edge-crossing-error-approximation.md)
This method estimates the positional error introduced by linear interpolation when determining the intersection of a scalar field with an isovalue on a grid edge. It leverages Taylor series expansion to bound the difference between the true root and the linear approximation without solving a linear system. It distinguishes itself from [Linear Edge Intersection](868-linear-edge-intersection.md) by providing a quantitative error metric rather than just the position, and from [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) by offering an analytical estimate rather than a numerical refinement.

### Linear Density Minimization for Zero-Crossing
Approximates the zero-crossing position along an edge by sampling discrete points and selecting the one with minimum absolute density [S10, unofficial]. It initializes a minimum value and iterates through steps along the edge, updating the best position if the absolute density is lower [S10, unofficial]. This is a discrete approximation rather than an analytical interpolation [S10, unofficial].

### Triangle Point Generation (Linear Interpolation with Snap)
Uses linear interpolation but includes "snap" logic: if either endpoint's value is within a `snap` threshold (default 0.01) of the isovalue, or if the difference between endpoints is small, it returns the endpoint directly to avoid numerical instability [S11, unofficial]. Otherwise, it computes the intersection using the standard linear formula [S11, unofficial].

### Wall Edge Clipping
Clips wall edges to a screen/player boundary (e.g., $y < 1$) using linear interpolation to find the intersection point [S12, unofficial]. If an endpoint is behind the boundary, it calculates the interpolation factor $t$ to the boundary plane and interpolates the coordinates [S12, unofficial].

### Three-segment interpolation
An interpolation method between linear interpolation and midpoint selection used to calculate the intersection point of an edge and an iso-surface [S13]. It normalizes the interpolation ratio $k$: if $|k| < m$, set $|k|=q$; if $|k| > n$, set $|k|=p$; otherwise $|k|=0.5$ [S13]. Typical values are $q=0.25, m=0.3, n=0.7, p=0.75$ [S13]. This reduces artifacts near vertices [S13].

### Iterative Bisection for Zero-Crossing
A method to find the point where the SDF assumes the isovalue $c=0$ along an edge exhibiting a material change, reduced to finding a value $t \in [0,1]$ representing the relative intersection point [S14]. It applies binary search limited to 8 iterations or a sub-interval size threshold of $10^{-6}$ [S14]. It assumes only one material change per edge [S14].

### Multiple Edge Intersection Removal
Handling the case where the surface intersects a grid edge more than once (e.g., at consecutive points $\alpha$ and $\beta$) [S15]. It identifies a point $p$ between $\alpha$ and $\beta$ where the gradient is perpendicular to the edge, and deforms the surface to remove the pair of intersections by linear interpolation in the direction of the gradient [S15].

### Vertex Handling for Grid Vertices
Handles the case where the surface passes through vertices of the grid by considering $F$ to be strictly positive whenever $F \ge 0$ [S15]. This ensures consistent topology when vertices lie exactly on the isosurface [S15].

## Operating characteristics
**Time Complexity:** $O(1)$ per edge. The calculation involves a constant number of arithmetic operations (subtraction, division, multiplication, addition) [S1, unofficial][S4][S6, unofficial].

**Memory Complexity:** $O(1)$ auxiliary space. No additional data structures are required beyond the input variables [S1, S6, unofficial].

**Measured Performance:** Linear interpolation is significantly faster than cubic or Hermite interpolation methods [S4]. It is also faster than iterative bisection methods, which require multiple evaluations of the scalar field [S9, unofficial]. However, it is more costly than midpoint approximation, which requires no scalar evaluation at the edge interior [S9, unofficial].

**Strengths:**
*   Simple to implement [S4].
*   Computationally efficient [S4].
*   Provides a smooth surface approximation better than midpoint methods [S9, unofficial].
*   Numerically stable if signed distance formulation or clamping is used [S3, S6, unofficial].

**Limitations:**
*   Approximates the surface as linear between vertices, leading to geometric inaccuracies for highly curved surfaces [S4].
*   Fails to detect multiple roots within a single edge/voxel [S9, unofficial].
*   Can produce artifacts (e.g., "popping" or incorrect topology) if the scalar field is not well-behaved or if the grid resolution is insufficient to capture the surface detail [S14].

**When to use:**
*   Standard Marching Cubes or similar grid-based isosurface extraction where performance is critical and high-order accuracy is not required [S1, unofficial][S4].
*   Ray-marching steps where a quick estimate of the intersection is needed [S9, unofficial].

**When not to use:**
*   When high geometric fidelity is required for highly curved surfaces; use Hermite or Cubic interpolation [S4, S13].
*   When the scalar field is known to have multiple roots within a voxel; use iterative refinement or higher-order analysis [S9, unofficial][S14].

## Background
Linear edge intersection is a fundamental technique in isosurface extraction, primarily associated with the Marching Cubes algorithm introduced by Lorensen and Cline in 1987 [S1, S2, unofficial]. It relies on the assumption that the scalar field varies linearly between grid vertices, allowing the intersection point to be found via simple linear interpolation [S4]. The method has been widely adopted in computer graphics, medical imaging, and scientific visualization due to its simplicity and efficiency [S1, unofficial][S4][S9, unofficial]. Variations and refinements, such as signed distance formulations for stability [S3, unofficial] and snapping for robustness [S11, unofficial], have been developed to address specific implementation challenges.
