# Linear Edge Intersection

Also called: Edge Intersection for Isosurface Extraction, Linear Edge Interpolation, Marching Cubes Edge Crossing

## Overview
Linear Edge Intersection determines the precise position where an isosurface intersects a grid edge by linearly interpolating between the scalar field values at the two vertices defining that edge [S1, S2, unofficial][S4][S5, S6, S7, unofficial]. It solves the problem of locating surface geometry within a discrete voxel grid, serving as the fundamental geometric primitive for contouring algorithms like Marching Cubes and ray-marching isosurface extraction [S1, S9, unofficial]. It sets itself apart from its siblings by assuming a strictly linear variation of the scalar field along the edge, providing an exact algebraic solution for the intersection point under that assumption, whereas [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) uses numerical approximation and [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md) uses gradient data for higher-order accuracy [S1, unofficial][S4, S13].

## How it works
**Inputs:**
*   Two edge endpoints: $\mathbf{p}_1$ and $\mathbf{p}_2$ (3D coordinates) [S7, S8, unofficial].
*   Scalar field values at endpoints: $v_1 = f(\mathbf{p}_1)$ and $v_2 = f(\mathbf{p}_2)$ [S7, S8, unofficial].
*   Target isovalue (threshold): $iso$ (or $k$, $T$, $Y$) [S1, unofficial][S4][S5, S8, unofficial][S13].

**Outputs:**
*   Intersection point $\mathbf{p}$ on the edge segment $[\mathbf{p}_1, \mathbf{p}_2]$ [S3, S7, unofficial].

**Data Structures:**
*   Points are represented as 3D vectors $(x, y, z)$ [S7, S8, unofficial].
*   Scalar values are floating-point numbers [S6, S8, unofficial].

**Steps:**
1.  **Identify Intersection:** Check if the edge crosses the isosurface. This occurs if $(v_1 - iso)$ and $(v_2 - iso)$ have opposite signs [S1, S9, unofficial]. If both values are on the same side of the isovalue, there is no intersection on this edge segment [S1, S9, unofficial].
2.  **Handle Degeneracy:** If the scalar values are nearly identical ($|v_1 - v_2| < \epsilon$), the denominator in the interpolation formula approaches zero. In this case, return $\mathbf{p}_1$ to avoid division by zero [S2, S6, S7, unofficial]. Typical $\epsilon$ values are $10^{-7}$ or $10^{-5}$ [S5, S6, unofficial].
3.  **Calculate Interpolation Factor:** Compute the normalized distance $t$ (or $\mu$, $\alpha$, $k$) from $\mathbf{p}_1$ to the intersection point:
    $$ t = \frac{iso - v_1}{v_2 - v_1} $$
    Alternatively, using signed distances $d_0 = v_1 - iso$ and $d_1 = v_2 - iso$ (where $d_0$ and $d_1$ have opposite signs):
    $$ \mathbf{p} = \frac{d_0 \mathbf{p}_2 - d_1 \mathbf{p}_1}{d_0 - d_1} $$
    This signed-distance form is numerically more stable when vertices are near the plane [S3, unofficial].
4.  **Compute Position:** Calculate the intersection point using vector interpolation:
    $$ \mathbf{p} = \mathbf{p}_1 + t (\mathbf{p}_2 - \mathbf{p}_1) $$
    Or in component form:
    $$ \mathbf{p} = (1 - t) \mathbf{p}_1 + t \mathbf{p}_2 $$
5.  **Clamping (Optional but Recommended):** To handle floating-point inaccuracies where $t$ might slightly exceed $[0, 1]$, clamp $t$ to $[0, 1]$ before computing $\mathbf{p}$ [S6, unofficial].

**Pseudocode:**
```python
def linear_edge_intersection(p1, p2, v1, v2, iso, epsilon=1e-7):
    """
    Calculates the intersection point of an isosurface with an edge.
    
    Args:
        p1: 3D vector (x, y, z) of the first endpoint.
        p2: 3D vector (x, y, z) of the second endpoint.
        v1: Scalar value at p1.
        v2: Scalar value at p2.
        iso: Target isovalue.
        epsilon: Threshold for degenerate case detection.
        
    Returns:
        3D vector representing the intersection point.
    """
    # Check for degenerate case where endpoints have same scalar value
    if abs(v2 - v1) < epsilon:
        return p1
    
    # Calculate interpolation factor t
    t = (iso - v1) / (v2 - v1)
    
    # Clamp t to [0, 1] to handle floating point errors
    t = max(0.0, min(1.0, t))
    
    # Compute intersection point: p = p1 + t * (p2 - p1)
    px = p1[0] + t * (p2[0] - p1[0])
    py = p1[1] + t * (p2[1] - p1[1])
    pz = p1[2] + t * (p2[2] - p1[2])
    
    return (px, py, pz)
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $v_1 = v_2$, the denominator is zero. This must be guarded against [S2, S6, S7, unofficial].
*   **Numerical Stability:** When vertices are very close to the isosurface, standard interpolation can suffer from cancellation errors. Using signed distances ($d_0, d_1$) as in [S3, unofficial] improves stability.
*   **Multiple Roots:** Linear interpolation assumes a single root per edge. If the scalar field has multiple roots within the voxel (e.g., a thin structure passing through), linear interpolation will fail to detect all intersections [S9, unofficial].
*   **Vertex Ordering:** In some implementations (e.g., [S2, unofficial]), consistent ordering of $P_1$ and $P_2$ (e.g., by coordinate value) is required to ensure correct triangle generation and normal orientation.

## Subtopics

### [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md)
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies. Choose it when higher precision is needed than linear interpolation provides but gradient data is unavailable.

### [Linear Intersection Approximation](1232-linear-intersection-approximation.md)
Linear Intersection Approximation (also known as Midpoint Intersection) estimates the intersection point of an isosurface with a grid edge by calculating the geometric midpoint of the edge, rather than performing linear interpolation based on scalar values. It differs from its parent, [Linear Edge Intersection](868-linear-edge-intersection.md), by ignoring endpoint scalar values entirely, and from its sibling, [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), by using a single fixed geometric step instead of recursive refinement [G]. Choose it for maximum performance when scalar field variation is unknown or irrelevant.

### [Triangle Point Generation (Linear Interpolation with Snap)](3506-triangle-point-generation-linear-interpolation-with-snap.md)
This method computes the precise intersection point on a triangle edge where a scalar field equals a threshold, using linear interpolation between two grid vertices. It distinguishes itself from siblings like [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) by avoiding iterative convergence, instead applying a deterministic "snap" heuristic to vertices near the threshold to stabilize the interpolation result. It serves as the geometric foundation for [Triangle Point Sampling](17806-triangle-point-sampling.md), which requires robust point generation to ensure uniform spatial distribution. Choose it when mesh topology stability is critical.

### [Vertex Handling for Grid Vertices](10118-vertex-handling-for-grid-vertices.md)
Vertex Handling for Grid Vertices resolves topological ambiguities in isosurface extraction when the scalar field value at a grid vertex equals the threshold exactly. It sets the convention that the field is considered strictly positive when $F \ge 0$, ensuring consistent connectivity for the marching cubes/tetrahedra algorithm. This method is distinct from refinement techniques like [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) or approximation methods like [Linear Intersection Approximation](1232-linear-intersection-approximation.md) because it relies on a deterministic sign convention rather than geometric correction or iterative solving [G]. Choose it as a mandatory preprocessing step for robust marching algorithms.

### [Inverse Linear Interpolation](12154-inverse-linear-interpolation.md)
Inverse Linear Interpolation calculates the non-integer position $x$ corresponding to a specific scalar value $v$ between two known values $v_1$ and $v_2$ at positions $x_1$ and $x_2$. It solves the inverse interpolation problem for isosurface extraction by determining the exact location along a grid line segment where an interpolated scalar field takes on a specific isosurface value $T_m$. Unlike forward linear interpolation which estimates a value at a known position, this method inverts the relationship to find the exact position for a known value, which is necessary for precise isosurface mesh generation. It builds on [Linear Edge Intersection](868-linear-edge-intersection.md) by providing the specific arithmetic to resolve the intersection point analytically. Choose it when exact coordinate mapping from scalar values is required.

### [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md)
Hermite interpolation for isosurface extraction determines the precise position of an isovertex along a zero-crossing edge by utilizing both scalar field values and gradient information (Hermite data) at the edge endpoints. Unlike [Linear Edge Intersection](868-linear-edge-intersection.md), which assumes linear variation and produces artifacts on non-linear implicit functions, this method fits higher-order polynomials to the local field behavior, significantly improving surface accuracy. It is primarily used in contouring algorithms like Marching Cubes where gradient data is available or can be approximated. Choose it when high geometric fidelity is required and gradients are accessible.

### [Edge-Crossing Error Approximation](15075-edge-crossing-error-approximation.md)
This method estimates the positional error introduced by linear interpolation when determining the intersection of a scalar field with an isovalue on a grid edge. It leverages Taylor series expansion to bound the difference between the true root and the linear approximation without solving a linear system. It distinguishes itself from [Linear Edge Intersection](868-linear-edge-intersection.md) by providing a quantitative error metric rather than just the position, and from [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) by offering an analytical estimate rather than a numerical refinement. Choose it for uncertainty quantification in visualization pipelines.

### Linear Density Minimization for Zero-Crossing
Approximates the zero-crossing position along an edge by sampling discrete points and selecting the one with minimum absolute density [S11, unofficial]. It initializes a minimum value and iterates through a fixed number of steps (e.g., 8) along the edge, updating the best position if a lower absolute density is found [S11, unofficial]. Choose it when discrete sampling is preferred over analytical interpolation.

### Wall Edge Clipping
Clips wall edges to a screen or player boundary (e.g., $y < 1$) using linear interpolation to find the intersection point [S12, unofficial]. If an endpoint is behind the boundary, it calculates the interpolation factor $t$ and updates the coordinates to lie exactly on the boundary plane [S12, unofficial]. Choose it for viewport culling and boundary enforcement in voxel engines.

### Three-segment interpolation
An interpolation method between linear interpolation and midpoint selection used to calculate the intersection point of an edge and an iso-surface [S13]. It normalizes the interpolation ratio $k$ based on thresholds $m$ and $n$: if $|k| < m$, $|k|$ is set to $q$; if $|k| > n$, $|k|$ is set to $p$; otherwise, $|k|$ is set to 0.5 [S13]. This reduces artifacts in specific topological configurations [S13]. Choose it when standard linear interpolation produces visible stair-stepping artifacts.

### Iterative Bisection for Zero-Crossing
A method to find the point where the SDF assumes the isovalue $c=0$ along an edge exhibiting a material change, reduced to finding a value $t \in [0,1]$ [S14]. It applies binary search with a limit of 8 iterations and a sub-interval size threshold of $10^{-6}$ [S14]. Choose it for robust root-finding in terrain or material boundary extraction.

### Multiple Edge Intersection Removal
Handles cases where the surface intersects a grid edge more than once [S15]. It identifies a point where the gradient is perpendicular to the edge and deforms the surface to ensure only single edge intersections remain, using linear interpolation in the direction of the gradient [S15]. Choose it when processing implicit surfaces with complex topology that violate single-crossing assumptions.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Linear interpolation is fast and simple, offering advantages in terms of speed and mathematical model simplicity [S4]. However, it is significantly more costly than the midpoint algorithm because it requires computing scalar values at ray entry and exit points [S10, unofficial].
*   **Accuracy:** Provides an exact solution under the assumption of linear field variation. Accuracy degrades if the scalar field is highly non-linear within the voxel [S4].
*   **Strengths:** Simplicity, speed, and numerical stability when implemented with signed distances [S3, unofficial][S4].
*   **Limitations:** Cannot resolve multiple roots within a single edge or voxel [S9, unofficial]. May produce artifacts if the underlying field is not smooth or linear [S4].
*   **When to Use:** When performance is critical and the scalar field is relatively smooth or linear within voxels [S4][S9, unofficial].
*   **When Not to Use:** When high geometric accuracy is required for highly non-linear fields, or when multiple intersections per voxel are expected [S4][S9, unofficial].
