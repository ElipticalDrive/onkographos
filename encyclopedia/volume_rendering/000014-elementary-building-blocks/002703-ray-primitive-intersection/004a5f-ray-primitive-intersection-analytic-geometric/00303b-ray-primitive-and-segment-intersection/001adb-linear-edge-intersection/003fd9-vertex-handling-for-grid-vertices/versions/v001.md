# Vertex Handling for Grid Vertices

Also called: F >= 0 Handling, Strictly Positive Field at Vertices

## Overview
Vertex Handling for Grid Vertices resolves topological ambiguities in isosurface extraction when the scalar field value at a grid vertex equals the threshold exactly. It sets the convention that the field is considered strictly positive when $F \ge 0$, ensuring consistent connectivity for the marching cubes/tetrahedra algorithm. This method is distinct from refinement techniques like [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md) or approximation methods like [Linear Intersection Approximation](1232-linear-intersection-approximation.md) because it relies on a deterministic sign convention rather than geometric correction or iterative solving.

## How it works
**Inputs and Outputs:**
*   Input: Scalar field values $F(v)$ at grid vertices $v$.
*   Output: A consistent boolean classification of vertices as "inside" ($F < 0$) or "outside" ($F \ge 0$).

**Data Structures:**
*   No additional data structures are required. The method modifies the interpretation of existing scalar values.

**Steps:**
1.  For every vertex $v$ in the grid, evaluate the scalar field value $F(v)$.
2.  Compare $F(v)$ against the isosurface threshold $T$ (typically $0$ for signed distance fields or zero-crossings).
3.  Apply the strict inequality rule:
    *   If $F(v) < T$, classify vertex as inside.
    *   If $P(v) \ge T$, classify vertex as outside.
4.  Use these classifications to determine edge crossings via [Linear Edge Intersection](868-linear-edge-intersection.md).

**Formulas:**
$$
\text{Class}(v) = \begin{cases} 
\text{Inside} & \text{if } F(v) < T \\
\text{Outside} & \text{if } F(v) \ge T 
\end{cases}
$$

**Parameters:**
*   Threshold $T$: Typically $0$.

**Edge Cases and Pitfalls:**
*   **Degenerate Input:** If $F(v) = T$, the standard floating-point comparison might be unstable. The strict $F \ge 0$ rule provides a deterministic tie-breaker, preventing ambiguous cases where a vertex could be counted as both inside and outside depending on rounding errors.
*   **Precision:** This method assumes that the scalar field is well-defined at vertices. It does not handle cases where the surface passes through an edge multiple times (which requires gradient analysis as noted in [S1]).

**Pseudocode:**
```python
def classify_vertex(field_value, threshold):
    """
    Classifies a vertex based on the strict positive field convention.
    
    Args:
        field_value (float): The scalar value F(v) at the vertex.
        threshold (float): The isosurface threshold T.
        
    Returns:
        bool: True if the vertex is considered 'Outside' (F >= T), False if 'Inside' (F < T).
    """
    # Strictly positive field handling: F >= 0 is treated as positive/outside
    return field_value >= threshold
```

## Subtopics

### Consistent Vertex Ordering for Facet Normals
A vertex ordering regimen to ensure consistent planar coefficients and signed area cross products for shared facets, mitigating numeric inaccuracies in nearly parallel ray/cell intersections [S2, unofficial]. Within a cell, vertices of adjacent facets are numbered in opposite directions (CW or CCW) to attain consistent vector directions [S2, unofficial]. Adjacent facets sharing a 'corner' leg also order vertices in opposite directions [S2, unofficial]. Adjacent cells are classified as 'even' and 'odd' in all three logical mesh dimensions (checkerboard pattern) [S2, unofficial]. The vertex order direction for facets of an odd cell is set opposite to that of even cells [S2, unofficial]. These directed line segments generate planar coefficients and signed area cross products for the ray-through-facet test [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   Time: $O(1)$ per vertex.
*   Memory: $O(1)$ additional memory.

**Measured Performance:**
*   Not given in the sources.

**Scaling:**
*   Linear with the number of vertices.

**Strengths and Limitations:**
*   **Strengths:** Deterministic; eliminates topological ambiguities at vertices; simple to implement.
*   **Limitations:** Does not resolve cases where the surface intersects an edge multiple times (requires gradient analysis [S1]); relies on the assumption that the field is well-behaved at vertices.

**When to use it:**
*   Use when extracting isosurfaces from grid-based scalar fields where vertex values may exactly match the threshold.

**When not:**
*   Do not use if the surface intersects edges multiple times within a single cell, as this requires more complex handling [S1].

## Background
Origin: [S1] Isotopic approximation of implicit curves and surfaces (2004) and [S2, unofficial] Ray tracing through a hexahedral mesh in HADES (2004). The method is used in isosurface extraction algorithms (e.g., Marching Cubes) to handle the case where the surface passes through grid vertices.
