# Hitpoint Refinement


## Overview
Hitpoint Refinement is an iterative technique to achieve higher quality in detecting surface intersections (ray-surface intersection) without reducing rendering speed [S1, unofficial]. It allows for coarser initial sampling steps to increase rendering speed, refining the detected intersection point through a binary-search-like procedure [S1, unofficial]. It sets itself apart from its siblings by using a specific "half-step back, then check direction" heuristic rather than standard bisection or secant methods, enabling significant speedups when paired with large initial sampling distances [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A ray, a surface function (implicit or explicit) that returns a scalar value (e.g., distance to surface or density threshold crossing indicator), and an initial coarse intersection estimate $t_{init}$ found via sparse sampling.
- Output: A refined intersection parameter $t_{final}$.

**Data structures:**
- No complex data structures are required. The method operates on scalar values representing the ray parameter $t$ and the step size $\Delta t$.

**Parameters:**
- Initial sampling distance: Can be increased to 400% or 500% of the original fine sampling distance when Hitpoint Refinement is used [S1, unofficial].
- Iteration count: 5 to 6 times [S1, unofficial].

**Steps:**
1. **Initial Coarse Sampling:** Sample along the ray with a relatively small sampling rate (large steps between sampling points) to detect a rough intersection [S1, unofficial]. Let the detected intersection parameter be $t_{curr}$ and the step size used in the coarse grid be $\Delta t_{coarse}$ [S1, unofficial].
2. **Initial Backstep:** Upon detecting an intersection, step back by half a step [S1, unofficial].
   $$ t_{curr} \leftarrow t_{curr} - \frac{\Delta t_{coarse}}{2} $$
   $$ \Delta t_{curr} \leftarrow \frac{\Delta t_{coarse}}{2} $$
3. **Direction Check:** Evaluate the surface function at the current position $t_{curr}$ and compare it to the target value (e.g., zero-crossing or threshold). Determine if moving closer to the target value or further away [S1, unofficial].
4. **Refinement Loop:** Repeat the following 5 to 6 times [S1, unofficial]:
   - If moving back (decreasing $t$) brings the position closer to the desired target value:
     $$ t_{curr} \leftarrow t_{curr} - \frac{\Delta t_{curr}}{2} $$
     $$ \Delta t_{curr} \leftarrow \frac{\Delta t_{curr}}{2} $$
   - Otherwise (if moving back takes the position further away from the target value):
     $$ t_{curr} \leftarrow t_{curr} + \Delta t_{curr} $$
     $$ \Delta t_{curr} \leftarrow \frac{\Delta t_{curr}}{2} $$
5. **Result:** The final $t_{curr}$ is the refined intersection point. This procedure yields a 64-fold better intersection accuracy compared to the initially chosen point [S1, unofficial].

**Pseudocode:**
```python
def hitpoint_refinement(ray, surface_func, t_init, dt_coarse, iterations=6):
    """
    Refines a coarse intersection point t_init found with step size dt_coarse.
    
    Args:
        ray: Ray object with t parameter.
        surface_func: Function f(t) returning scalar value (e.g., distance to surface).
        t_init: Initial coarse intersection estimate.
        dt_coarse: Step size used during initial coarse sampling.
        iterations: Number of refinement steps (typically 5-6).
        
    Returns:
        Refined intersection parameter t.
    """
    # Evaluate surface at initial coarse hit
    # Note: The source implies the coarse sampling detects an "intersection".
    # We assume t_init is the first point where the sign changes or threshold is crossed.
    # To determine "closer to target", we need the target value.
    # For zero-crossing surfaces, target is 0.
    target = 0.0
    
    # Step 2: Step back by half a step
    t_curr = t_init - (dt_coarse / 2.0)
    dt_curr = dt_coarse / 2.0
    
    # Evaluate current position
    val_curr = surface_func(t_curr)
    
    # We need to know the direction of the surface crossing to determine "closer".
    # The source describes a heuristic: "check if moving closer... or further away".
    # This implies comparing the absolute error |f(t) - target|.
    
    for _ in range(iterations):
        # Calculate error at current position
        error_curr = abs(val_curr - target)
        
        # Tentative move: back by half the current step size
        t_next = t_curr - (dt_curr / 2.0)
        val_next = surface_func(t_next)
        error_next = abs(val_next - target)
        
        if error_next < error_curr:
            # Closer to target: move back
            t_curr = t_next
            val_curr = val_next
            dt_curr = dt_curr / 2.0
        else:
            # Further away: move forward by one full current step size
            # Note: Source says "move forward by one such step size"
            # The "step size" here refers to the size of the step we just tried to take backwards?
            # Or the step size before halving?
            # Source: "If closer, move back another half-step (quarter step total). 
            # If further, move forward one such step."
            # "One such step" likely refers to the step size of the previous iteration's half-step?
            # Let's re-read carefully:
            # "If closer, move back another half-step (quarter step total)." -> dt becomes dt/2.
            # "If further, move forward one such step." -> "such step" = the step we just considered?
            # In the second description: "Otherwise (if further away), move forward by one full step size."
            # And then "Repeat steps 3-5". Step 4 says "move back by half the last step size".
            # This implies the step size is always halved.
            # If we move forward, do we halve the step size?
            # The source says: "Repeat this process 5 to 6 times."
            # The process includes halving the step size in the "closer" case.
            # Does the "further" case also halve the step size?
            # "If closer, move back another half-step (quarter step total)." -> dt_new = dt_old / 2.
            # "If further, move forward one such step." -> Does dt change?
            # Usually, bisection halves the interval regardless.
            # The source says: "move forward by one such step size."
            # If we don't halve dt, the step size remains large, which might not converge.
            # However, the source explicitly links the step size reduction to the "closer" move.
            # Let's look at the "64-fold better" claim.
            # 6 iterations of halving step size: 2^6 = 64.
            # This implies the step size is halved every iteration, regardless of direction.
            # If we move forward, we are essentially correcting the overshoot.
            # Let's assume dt is halved in every iteration to achieve the 64x accuracy.
            
            t_curr = t_curr + dt_curr
            val_curr = surface_func(t_curr)
            dt_curr = dt_curr / 2.0
            
    return t_curr
```

**Edge cases and pitfalls:**
- **Precision:** The method relies on the surface function being well-behaved. Discontinuities may cause the "closer/further" check to fail.
- **Boundaries:** If the ray exits the volume or object during refinement, the surface function should return a value indicating "outside" to prevent infinite loops or invalid steps.
- **Degenerate input:** If the initial coarse sampling misses the intersection entirely, the refinement will not trigger.

## Operating characteristics
- **Time complexity:** $O(k)$ where $k$ is the number of iterations (typically 5-6). Each iteration requires one or two surface function evaluations.
- **Memory complexity:** $O(1)$.
- **Measured performance:** Using Hitpoint Refinement allows the initial sampling distance to be increased to 400% or 500% of the original, significantly increasing rendering speed [S1, unofficial]. The refinement yields a 64-fold better intersection accuracy compared to the initially chosen point [S1, unofficial].
- **Strengths:** High accuracy with minimal additional cost; allows for coarser initial sampling.
- **Limitations:** Requires a surface function that can be evaluated at arbitrary $t$; assumes the initial coarse hit is close enough for the heuristic to work.

## Background
Hitpoint Refinement was introduced as an optimization technique for raycasters to improve intersection detection quality without sacrificing rendering speed [S1, unofficial]. It is described in the context of volume raycasting optimization [S1, unofficial].
