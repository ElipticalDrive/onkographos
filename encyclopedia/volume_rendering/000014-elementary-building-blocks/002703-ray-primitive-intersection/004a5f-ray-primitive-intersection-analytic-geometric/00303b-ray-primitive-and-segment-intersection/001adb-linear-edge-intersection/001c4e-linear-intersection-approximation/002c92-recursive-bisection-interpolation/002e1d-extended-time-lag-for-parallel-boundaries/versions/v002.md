# Extended Time Lag for Parallel Boundaries

Also called: Border time lag, Prevention sphere, Time Lag Extension for Block Borders

## Overview
Extended Time Lag for Parallel Boundaries is a geometric constraint technique used during hierarchical isosurface extraction to prevent refinement dependencies and topological artifacts at the interfaces of adjacent sub-blocks [S1, S2]. It extends the standard time lag method by enforcing a local inclusion check against block boundaries, ensuring that edge contractions do not create geometric inconsistencies between neighbors [S1]. Unlike the original time lag which applies globally, this extension specifically targets the borders of current sub-blocks to maintain consistency in parallel or partitioned rendering environments [S1].

## How it works
The method operates during the edge collapse phase of simplification algorithms within a hierarchical block structure [S1, S2]. It prevents the contraction of an edge if the resulting geometric influence sphere would extend outside the current block's boundaries [S1].

**Inputs and Outputs:**
*   **Input:** An edge $ab$ to be considered for collapse, the current block boundary definition, and the radii of the edge endpoints $rad(a)$ and $rad(b)$ [S1].
*   **Output:** A boolean decision indicating whether the edge contraction is permitted or prevented [G].

**Data Structures:**
*   **Edge:** Defined by endpoints $a$ and $b$ [G].
*   **Block:** Defined by its spatial boundaries, typically represented as an axis-aligned bounding box with minimum and maximum extents [G].
*   **Radius Field:** Each vertex $x$ stores a scalar value $rad(x)$ [S1].

**Formulas:**
The radius of a point $c$, which is the result of collapsing edge $ab$ into a single vertex, is calculated as [S1, S2]:

$$
rad(c) = \frac{\|a - b\| + rad(a) + rad(b)}{2}
$$

Where:
*   $\|a - b\|$ is the Euclidean distance between vertices $a$ and $b$ [G].
*   $rad(a)$ and $rad(b)$ are the radii associated with vertices $a$ and $b$ [S1].
*   For original vertices of the isosurface, the radius is defined as [S1, S2]:
    $$
    rad(x) = 1
    $$

**Algorithm Steps:**
1.  Identify the edge $ab$ to be collapsed [S1].
2.  Calculate the midpoint $m$ of the edge: $m = \frac{a + b}{2}$ [G].
3.  Calculate the radius $rad(c)$ of the potential new vertex $c$ using the formula above [S1].
4.  Define a sphere $S$ centered at $m$ with radius $rad(c)$ [S1].
5.  Check if sphere $S$ is **totally included** within the current block's boundaries [S1].
    *   If $S$ is not totally included (i.e., it intersects or crosses the block boundary), **prevent** the contraction of edge $ab$ [S1, S2].
    *   If $S$ is totally included, allow the contraction [G].

**Pseudocode:**

```python
import math

def norm(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def lerp(a, b, t):
    return (a[0] + t * (b[0] - a[0]), a[1] + t * (b[1] - a[1]), a[2] + t * (b[2] - a[2]))

def is_sphere_inside_aabb(center, radius, min_pt, max_pt):
    if center[0] - radius < min_pt[0] or center[0] + radius > max_pt[0]:
        return False
    if center[1] - radius < min_pt[1] or center[1] + radius > max_pt[1]:
        return False
    if center[2] - radius < min_pt[2] or center[2] + radius > max_pt[2]:
        return False
    return True

def is_edge_contraction_allowed(a_pos, b_pos, rad_a, rad_b, min_pt, max_pt):
    """
    Determines if edge ab can be collapsed based on Extended Time Lag constraints.
    
    Args:
        a_pos: Tuple (x, y, z) of vertex a position.
        b_pos: Tuple (x, y, z) of vertex b position.
        rad_a: Radius of vertex a.
        rad_b: Radius of vertex b.
        min_pt: Tuple (x, y, z) of block minimum extent.
        max_pt: Tuple (x, y, z) of block maximum extent.
        
    Returns:
        bool: True if contraction is allowed, False if prevented.
    """
    dist_ab = norm([b_pos[0] - a_pos[0], b_pos[1] - a_pos[1], b_pos[2] - a_pos[2]])
    rad_c = (dist_ab + rad_a + rad_b) / 2.0
    center = lerp(a_pos, b_pos, 0.5)
    return is_sphere_inside_aabb(center, rad_c, min_pt, max_pt)
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in distance calculations may cause a sphere that is mathematically inside to be flagged as outside, or vice versa [G]. A small epsilon tolerance may be required in the inclusion check [G].
*   **Original Vertices:** The radius definition $rad(x)=1$ applies strictly to original vertices [S1]. If intermediate vertices are created, their radii must be propagated correctly using the formula to maintain the prevention sphere logic [S1, S2].
*   **Boundary Definition:** The block boundary must be clearly defined relative to the coordinate system of the vertices [G]. In hierarchical splitting, the boundary of a child block is a subset of the parent, and the check must use the specific child block's limits [S1].

## Operating characteristics
The check adds a constant-time geometric test per edge considered for collapse [G]. It does not change the asymptotic complexity of the simplification algorithm but adds a small constant overhead per edge [G]. No additional significant memory is required beyond storing the block boundaries and the radius field for vertices, which is already part of the tandem algorithm's data structure [S1, S2]. It effectively prevents refinement dependencies and artifacts due to bias in shape during simplification at block borders [S1, S2]. It may prevent valid simplifications near boundaries, potentially leaving more vertices near block edges than would be necessary in a global simplification [G]. Use it when extracting isosurfaces from large datasets partitioned into blocks where visual continuity across block boundaries is critical [S1, S2].

## Background
The method was introduced in the context of isosurface extraction and interpretation for very large geophysical datasets [S1]. It extends the time lag concept, originally designed to prevent refinement dependencies globally, to specifically handle the boundaries of sub-blocks in a parallel or hierarchical extraction framework [S1, S2]. The technique is particularly relevant for algorithms like the tandem algorithm, which is designed for large-scale data but requires careful handling of block interfaces to maintain geometric quality [S2].
