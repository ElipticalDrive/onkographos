# Inverse Linear Interpolation

Also called: Inverse Linear Interpolation for Isosurface Location, Inverse interpolation problem, Isosurface location calculation, Linear Interpolation Position

## Overview
Inverse Linear Interpolation calculates the non-integer position $x$ corresponding to a specific scalar value $v$ between two known values $v_1$ and $v_2$ at positions $x_1$ and $x_2$ [S1, unofficial]. It solves the inverse interpolation problem for isosurface extraction by determining the exact location along a grid line segment where an interpolated scalar field takes on a specific isosurface value $T_m$ [S2, unofficial]. Unlike forward linear interpolation which estimates a value at a known position, this method inverts the relationship to find the exact position for a known value, which is necessary for precise isosurface mesh generation [S2, unofficial]. It builds on [Linear Edge Intersection](868-linear-edge-intersection.md) by providing the specific arithmetic to resolve the intersection point analytically.

## How it works
**Inputs:**
*   $x_1, x_2$: The coordinates of the two endpoints of the grid line segment [S2, unofficial].
*   $T_1, T_2$: The scalar data values at $x_1$ and $x_2$ respectively [S2, unofficial].
*   $T_m$: The target isosurface level value [S2, unofficial].

**Outputs:**
*   $x_m$: The interpolated coordinate along the segment where the scalar value equals $T_m$ [S2, unofficial].

**Data Structures:**
No complex data structures are required; the method operates on scalar values and coordinates [G]. If implemented within a grid context, $x_1$ and $x_2$ are often derived from grid indices $i, j, k$ and cell dimensions [G].

**Steps:**
1. **Validate Monotonicity:** Check if $T_m$ lies between $T_1$ and $T_2$ [S2, unofficial].
2. **Check for Degeneracy:** Check if $T_1 = T_2$ [S2, unofficial].
3. **Compute Interpolation Parameter $\alpha$:** Calculate the normalized distance parameter $\alpha$ using the formula:
   $$ \alpha = \frac{T_m - T_1}{T_2 - T_1} $$
   This parameter represents the fractional distance from $x_1$ to $x_2$ [S2, unofficial].
4. **Compute Intersection Position $x_m$:** Calculate the final position using the weighted average of the endpoints:
   $$ x_m = (1 - \alpha)x_1 + \alpha x_2 $$
   Alternatively, this can be computed directly as:
   $$ x_m = x_1 + (x_2 - x_1) \times \frac{T_m - T_1}{T_2 - T_1} $$
   [S1, unofficial][S2, unofficial]

**Pseudocode:**
```python
def inverse_linear_interpolation(x1: float, x2: float, t1: float, t2: float, tm: float) -> float:
    """
    Calculates the position xm along the segment [x1, x2] where the scalar value equals tm.
    
    Args:
        x1: Start coordinate of the segment.
        x2: End coordinate of the segment.
        t1: Scalar value at x1.
        t2: Scalar value at x2.
        tm: Target isosurface value.
        
    Returns:
        The coordinate xm where the interpolated value is tm.
        
    Raises:
        ValueError: If t1 equals t2 (division by zero).
    """
    # Sources do not specify boundary checks; standard practice validates T1 <= Tm <= T2 and T1 != T2 [S2, unofficial]
    if t1 == t2:
        raise ValueError("Division by zero: t1 equals t2. No unique intersection point.")
    
    alpha = (tm - t1) / (t2 - t1)
    return x1 + (x2 - x1) * alpha
```

**Sensitivity and Error Analysis:**
The position $x_m$ is sensitive to uncertainties $\Delta T_1$ and $\Delta T_2$ in the data values [S2, unofficial]. The error $\Delta x_m$ is given by:
$$ \Delta x_m = \frac{\partial x_m}{\partial T_1} \Delta T_1 + \frac{\partial x_m}{\partial T_2} \Delta T_2 $$
The partial derivatives are:
$$ \frac{\partial x_m}{\partial T_1} = \frac{T_m - T_2}{(T_2 - T_1)^2}(x_2 - x_1) $$
$$ \frac{\partial x_m}{\partial T_2} = \frac{T_1 - T_m}{(T_2 - T_1)^2}(x_2 - x_1) $$
The relative error can be expressed as:
$$ \frac{\Delta x_m}{x_2 - x_1} = -\left(1 - \alpha\right)\frac{\Delta T_1}{T_2 - T_1} + \alpha \frac{\Delta T_2}{T_2 - T_1} $$
The error bound is:
$$ |\Delta x_m| \le |x_2 - x_1| \frac{\max(|\Delta T_1|, |\Delta T_2|)}{|T_2 - T_1|} $$
Uncertainty in isosurface location is proportional to the magnitude of data uncertainty and inversely proportional to the data variation $|T_2 - T_1|$ [S2, unofficial].

## Subtopics

### Approximate Projection
A variant that uses Newton-Raphson iteration to refine the intersection point by projecting a sample point onto the isosurface using the gradient [S3]. It calculates a displacement parameter $t = \frac{f_I - f(x_0)}{\nabla f(x_0) \cdot \nabla f(x_0)}$ and updates the point $p'_\lambda = x_0 + t \nabla f(x_0)$ [S3]. It applies a displacement criterion $\Delta d$ (based on cell dimensions) to discard points projected too far, avoiding convergence to distant roots near local extrema [S3].

## Operating characteristics
**Time Complexity:** $O(1)$ [G]. The method involves a constant number of arithmetic operations (subtraction, division, multiplication, addition) [G].
**Memory Complexity:** $O(1)$ [G]. No additional memory is required beyond the input variables [G].
**Strengths:**
*   Exact analytical solution for linear interpolation [G].
*   Extremely fast computation, suitable for real-time rendering or large-scale mesh generation [G].
*   Assumes linear variation between grid points [G].
**Limitations:**
*   Accuracy degrades if the scalar field varies non-linearly within the cell [G].
*   Numerical instability or division by zero when $T_1 = T_2$ (zero gradient) [S2, unofficial].
*   Sensitivity to data noise increases as $|T_2 - T_1|$ approaches zero [S2, unofficial].
**When to use:**
*   Standard isosurface extraction (e.g., Marching Cubes) where linear interpolation is the standard assumption [G].
*   Real-time volume rendering requiring precise ray-primitive intersection [G].
**When not to use:**
*   When high-order continuity or non-linear field behavior is critical and higher-order interpolation (e.g., [Hermite Interpolation for Isosurface Extraction](13666-hermite-interpolation-for-isosurface-extraction.md)) is available [Siblings: Hermite Interpolation for Isosurface Extraction].
*   When the gradient is known to be zero or near-zero, requiring fallback logic [S2, unofficial].

## Background
Inverse Linear Interpolation is a fundamental technique in scientific visualization and computer graphics, particularly in isosurface extraction algorithms like Marching Cubes [G]. The method is formally described in the verification guide for Smokeview (Version 6), a tool for visualizing Fire Dynamics Simulation data, where it is referred to as the "inverse interpolation problem" [S2, unofficial]. The sensitivity analysis provided in [S2, unofficial] highlights the importance of understanding error propagation in isosurface location due to data uncertainty. A basic implementation appears in open-source volume rendering code [S1, unofficial].
