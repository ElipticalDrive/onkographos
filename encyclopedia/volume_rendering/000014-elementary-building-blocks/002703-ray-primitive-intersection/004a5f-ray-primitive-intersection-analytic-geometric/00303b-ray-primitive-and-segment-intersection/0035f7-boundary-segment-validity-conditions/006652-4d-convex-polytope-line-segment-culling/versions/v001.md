# 4D Convex Polytope Line Segment Culling

Also called: 4D Line Clipping, 4D Line Culling, 4D Wireframe Occlusion Culling, Block4d Algorithm, Hyperplane Clipping for 4D

## Overview
This algorithm culls wireframe line segments in 4D space that are occluded by the faces of a convex 4D polytope, specifically when the camera is located outside the polytope [S1, unofficial]. It solves the problem of occlusion detection in non-rasterized 4D rendering where a depth buffer is unavailable, constructing an occlusion cone from the polytope's front-facing hyperplanes to determine which parts of a line segment remain visible [S1, unofficial]. It sets itself apart from sibling methods by explicitly handling the 4D geometric topology (identifying turning edges and conical occlusion regions) rather than relying on coordinate-aligned simplifications or integration variable changes [S1, unofficial].

## How it works
**Inputs:**
*   A 4D line segment defined by endpoints $A$ and $B$, parameterized by $t \in [0, 1]$.
*   A convex 4D polytope defined by its $(n-1)$-dimensional faces (hyperplanes) and their normals.
*   Camera position $C$.

**Outputs:**
*   A set of valid sub-segments (or a single segment) representing the visible portion of the input segment.

**Data Structures:**
*   **Hyperplane Array $P$**: An array of hyperplanes forming the occlusion cone. Each hyperplane $p$ is defined by a normal vector $\mathbf{n}_p$ and a distance $d_p$ from the origin, such that a point $\mathbf{x}$ is "inside" (unoccluded side) if $\mathbf{n}_p \cdot \mathbf{x} + d_p \ge 0$ (assuming normals point outward) [S1, unofficial].
*   **Safe Interval $[a, b]$**: A pair of floats representing the parameter range $[a, b] \subseteq [0, 1]$ that is currently known to be unoccluded.

**Steps:**

1.  **Identify Front-Facing Faces:** For each $(n-1)$-dimensional face of the 4D convex polytope, determine if it is front-facing relative to the camera. This is done by checking the dot product of the face's normal vector $\mathbf{n}$ and the vector from the face to the camera $C$. If the normal points towards the camera (or away, depending on convention; the source implies normals are adjusted to point outward and front-facing means visible), it is included in the occlusion logic [S1, unofficial].
2.  **Construct Occlusion Cone:** Identify "turning edges" (3D faces in 4D? No, $n-2$ dimensional edges, i.e., 2D faces in 4D) where a front-facing face meets a back-facing face. These edges define the boundary of the occlusion region. Collect all hyperplanes corresponding to front-facing faces into the array $P$. These hyperplanes define an infinite cone of occlusion; any point inside this cone is occluded [S1, unofficial].
3.  **Initialize Safe Interval:** Set $a = 0$ and $b = 1$. This represents that the entire segment is initially considered unoccluded (safe interval is $[0, 1]$) [S1, unofficial]. *Note: The source text contains a contradiction here. One part says "initialize... fully occluded" but the code and subsequent logic ("expand safe interval") imply $[a,b]$ is the safe part. The code comments say "expand safe interval" when updating $a$ or $b$. Let's follow the code logic: $a$ and $b$ bound the SAFE region. Initially $[0,1]$ is safe.*
4.  **Iterate Hyperplanes:** Loop through each hyperplane $p$ in array $P$.
    *   Calculate the side of hyperplane $p$ for endpoints $A$ and $B$. Let $val_A = \mathbf{n}_p \cdot A + d_p$ and $val_B = \mathbf{n}_p \cdot B + d_p$.
    *   **Case 1: Both endpoints outside.** If both $A$ and $B$ are on the "outside" (occluded) side of hyperplane $p$ (i.e., $val_A < 0$ and $val_B < 0$), the entire segment is occluded by this hyperplane. Terminate the algorithm immediately; the segment is fully culled [S1, unofficial].
    *   **Case 2: A outside, B inside.** If $A$ is outside ($val_A < 0$) and $B$ is inside ($val_B \ge 0$), calculate the intersection position $x$ of the segment with plane $p$.
        *   The intersection parameter $t_{int}$ is calculated as:
            $$ t_{int} = \frac{-val_A}{val_B - val_A} $$
        *   If $t_{int} > a$, update $a = t_{int}$. This shrinks the safe interval from the left, expanding the occluded region [S1, unofficial].
    *   **Case 3: B outside, A inside.** If $B$ is outside ($val_B < 0$) and $A$ is inside ($val_A \ge 0$), calculate the intersection position $x$.
        *   The intersection parameter $t_{int}$ is calculated as:
            $$ t_{int} = \frac{-val_A}{val_B - val_A} $$
        *   If $t_{int} < b$, update $b = t_{int}$. This shrinks the safe interval from the right, expanding the occluded region [S1, unofficial].
    *   **Case 4: Both inside.** If both $A$ and $B$ are inside ($val_A \ge 0$ and $val_B \ge 0$), no information is gained regarding occlusion from this hyperplane. Continue to the next hyperplane [S1, unofficial].
5.  **Handle Multiple Objects:** If the scene contains multiple polytopes, apply this culling iteratively. If the final result is $0 < a < b < 1$, the segment is split into two parts: $[0, a]$ and $[b, 1]$. These two resulting segments are treated as separate segments for subsequent culling against other cells [S1, unofficial].

def cull_segment_4d_outside(segment_A, segment_B, hyperplanes_P, epsilon=1e-6):
    """
    Culls a 4D line segment against a convex polytope when the camera is outside.
    
    Args:
        segment_A: 4D vector, start point (t=0)
        segment_B: 4D vector, end point (t=1)
        hyperplanes_P: List of hyperplanes, each is a tuple (normal: 4D vector, distance: float)
                       Normals point OUTWARD. Inside is dot(n, x) + d >= 0.
        epsilon: Small value to inset faces and prevent floating-point errors [S1, unofficial]
        
    Returns:
        List of tuples (t_start, t_end) representing visible sub-segments.
    """
    
    # Initialize safe interval [a, b]
    a = 0.0
    b = 1.0
    
    # Pre-calculate values for endpoints to avoid repeated dot products
    # Note: In a real implementation, hyperplanes should be pre-filtered for front-facing ones
    # and potentially inset by epsilon.
    
    for (normal, dist) in hyperplanes_P:
        # Calculate signed distance from hyperplane for endpoints
        # dist_A = dot(normal, A) + dist
        # dist_B = dot(normal, B) + dist
        dist_A = dot(normal, segment_A) + dist
        dist_B = dot(normal, segment_B)
        
        # Check if endpoints are outside (negative distance) or inside (non-negative)
        # We use a small epsilon to handle floating point errors [S1, unofficial]
        is_A_inside = dist_A >= -epsilon
        is_B_inside = dist_B >= -epsilon
        
        if not is_A_inside and not is_B_inside:
            # Case 1: Both endpoints outside -> Entire segment occluded
            return []
        
        if is_A_inside and is_B_inside:
            # Case 4: Both endpoints inside -> No change to safe interval
            continue
        
        if not is_A_inside and is_B_inside:
            # Case 2: A outside, B inside
            # Intersection parameter t where segment crosses plane
            # t = -dist_A / (dist_B - dist_A)
            denominator = dist_B - dist_A
            if abs(denominator) < 1e-9:
                # Degenerate case: segment parallel to plane or zero length
                continue
            
            t_int = -dist_A / denominator
            
            # Update a (left bound of safe interval)
            # We want to shrink the safe interval from the left if the intersection is to the right of current a
            if t_int > a:
                a = t_int
                
        if is_A_inside and not is_B_inside:
            # Case 3: B outside, A inside
            denominator = dist_B - dist_A
            if abs(denominator) < 1e-9:
                continue
                
            t_int = -dist_A / denominator
            
            # Update b (right bound of safe interval)
            # We want to shrink the safe interval from the right if the intersection is to the left of current b
            if t_int < b:
                b = t_int

    # After processing all hyperplanes, check if a valid safe interval remains
    if a < b:
        return [(a, b)]
    else:
        return []

**Edge Cases and Pitfalls:**
*   **Camera Inside:** If the camera is inside the polytope, the occlusion logic reverses. The region outside the hyperplanes is occluded. The algorithm must be adjusted to initialize $[a, b] = [0, 1]$ as fully safe and shrink it, with occluded regions appearing at the ends (Left End -- Occluded -- $a$ -- Safe -- $b$ -- Occluded -- Right End) [S1, unofficial]. See [4D Convex Polytope Line Segment Culling (Camera Inside)](#4d-convex-polytope-line-segment-culling-camera-inside).
*   **Floating-Point Errors:** Floating-point errors may cause edges to be incorrectly culled. To prevent this, shrink the faces of the polytope inward by a small epsilon value before calculating occlusion [S1, unofficial].
*   **Endpoints on Hyperplane:** If both endpoints of the line segment lie exactly on a hyperplane, no valid information is gained. The algorithm does nothing for this case and continues to the next hyperplane [S1, unofficial].
*   **Multiple Objects:** The algorithm must be applied iteratively. A segment may be split into two parts ($[0, a]$ and $[b, 1]$) if $0 < a < b < 1$. These parts are then processed against subsequent polytopes [S1, unofficial].

## Subtopics

### 4D Convex Polytope Line Segment Culling (Camera Inside)
A variant of the culling algorithm used when the camera is inside the polytope [S1, unofficial]. In this case, the hyperplane array $P$ is empty for the outside logic, and the culling logic is inverted: the clipped regions become the outside (occluded) regions, and the middle region becomes the safe (unoccluded) area [S1, unofficial]. The safe interval $[a, b]$ is initialized to $[0, 1]$ (fully unoccluded) and is compressed from both ends as hyperplanes are processed. The structure is: Left Endpoint $A(0)$ -- Occluded -- $a$ -- Safe -- $b$ -- Occluded -- Right Endpoint $B(1)$ [S1, unofficial]. For each hyperplane, if both endpoints are outside, the line is occluded. If one is inside and one outside, the intersection $x$ is calculated, and $a$ or $b$ is updated to shrink the safe interval based on which side is being occluded [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of front-facing hyperplanes in the occlusion cone. For each segment, it iterates through the array $P$.
*   **Memory Complexity:** Linear with respect to the number of hyperplanes in the occlusion cone.
*   **Performance:** The complex culling logic for wireframe rendering is easy to implement on the CPU but difficult to port to the GPU. No parallelized algorithm has been found for this specific logic [S1, unofficial].
*   **Strengths:** Provides exact analytic occlusion culling for 4D wireframes without a depth buffer.
*   **Limitations:** Difficult to parallelize on GPU. Limited optimizations can be made using hierarchical data structures like bounding boxes [S1, unofficial]. Arbitrary 2D face culling (in 3D projections) is complex, though coordinate-aligned hypercubes simplify it [S1, unofficial].
*   **When to use:** When rendering 4D wireframes in a non-rasterized environment where depth buffering is not available or feasible.
*   **When not to use:** When high-performance GPU parallelization is required, or when the scene consists of arbitrary 2D faces in 3D (which is described as complex) [S1, unofficial].

## Background
The algorithm originates from the implementation 'dearsip' in the context of 4D computer graphics, specifically for rendering 4D polytopes (like hypercubes) [S1, unofficial]. The implementation achieved 3D cell-to-2D face occlusion culling, which was possible because the scene mostly consisted of hypercubes aligned with coordinate axes, making 2D face culling easier [S1, unofficial]. Arbitrary 2D face culling is described as complex [S1, unofficial]. The method was developed to solve the problem of occlusion in 4D wireframe rendering where traditional rasterization techniques (like depth buffers) are not applicable [S1, unofficial].
