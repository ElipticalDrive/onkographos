# Interactive Large Iso-Surface Ray Tracing

Also called: Brute-force ray tracing for isosurfaces, DeMarle approach, Direct ray-isosurface intersection, Interactive Ray Tracing for Isosurface Rendering, Out-of-core iso-surface ray tracing

## Overview
This method renders isosurfaces from large rectilinear scalar fields by tracing rays through the volume and performing analytic intersections, thereby avoiding the explicit generation of polygonal surface meshes (such as Marching Cubes) [S2, unofficial]. It distinguishes itself from sibling methods like [Neubauer Iso-surface Ray Casting](7024-neubauer-iso-surface-ray-casting.md) by computing the exact intersection point analytically within each voxel rather than extracting line segments and testing for occlusion, and from [Bézier Clipping for Metaball Ray Casting](9481-b-zier-clipping-for-metaball-ray-casting.md) by targeting rectilinear grid data rather than implicit metaball fields [S2, unofficial].

## How it works
**Inputs:** A rectilinear scalar field $\rho$ with even grid point spacing, an isovalue $\rho_{\text{iso}}$, and a set of camera rays defined by origin $\vec{a}$ and direction $\vec{b}$.
**Outputs:** The color of the first isosurface intersection for each pixel.

**Data Structures:**
1.  **Volume Data:** Rectilinear array of scalar values.
2.  **Bricks:** The volume is partitioned into 3D tiles ("bricks") to improve cache locality. Brick dimensions are independent of the hierarchy cell sizes. Neither the number of atomic voxels nor the number of bricks needs to be a power of two [S2, unofficial].
3.  **Spatial Hierarchy:** A tri-level hierarchy is used to accelerate traversal of empty cells.
    *   Level 0: Top-level cell covering the entire volume.
    *   Level 1 & 2: Intermediate macrocells.
    *   Level 3: Data cells (voxels).
    *   Each macrocell stores the minimum and maximum data values of its children. The storage overhead is negligible (< 0.5% of data size) [S2, unofficial].
4.  **Work Queue:** A queue of screen-space tiles for dynamic load balancing.

**Algorithm Steps:**

1.  **Initialization:** Split the screen into tiles of 32 pixels width by 4 pixels height. Add all tiles to a work queue [S2, unofficial].
2.  **Tile Processing:** For each tile assigned to a processor:
    a.  For each pixel in the tile, construct the ray $\vec{r}(t) = \vec{a} + t\vec{b}$.
    b.  **Traversal:** Use the Amanatides and Woo incremental method to traverse the ray through the volume cells [S2, unofficial].
        i.  At each step, check the current macrocell's min/max values.
        ii. If $\rho_{\text{iso}} \notin [\min, \max]$, skip the macrocell and advance to the next cell in the traversal order.
        iii. If $\rho_{\text{iso}} \in [\min, \max]$, descend into the hierarchy or proceed to the specific voxel cell.
    c.  **Intersection:** When a voxel containing the isosurface is encountered, solve for the intersection parameter $t$. The density $\rho$ is approximated using trilinear interpolation between the 8 grid points of the voxel. This results in a cubic polynomial in $t$:
        $$ \rho(x_a + tx_b, y_a + ty_b, z_a + tz_b) - \rho_{\text{iso}} = 0 $$
        Solve this cubic polynomial in closed form to find roots $t$ [S2, unofficial].
    d.  **Root Selection:**
        i.  Discard roots that are not contained within the current cell's parameter range.
        ii. If multiple valid roots exist, select the smallest $t$ (closest to the eye).
        iii. If no valid roots exist, the ray misses the isosurface in this cell; continue traversal.
    e.  **Shading:** Compute the color at the intersection point using the selected $t$. This may involve normal estimation via the gradient of the trilinear interpolation [S2, unofficial].
3.  **Load Balancing:** Processors pull tiles from the queue. Initially, large chunks are assigned to reduce contention. As the frame completes, smaller chunks are assigned to balance the load [S2, unofficial].

**Pseudocode:**

```python
def render_tile(tile_coords, volume, hierarchy, isovalue, camera):
    """
    Renders a single tile of the image.
    tile_coords: (x_start, y_start, width, height)
    volume: 3D array of scalar values
    hierarchy: 3-level tree storing min/max per node
    isovalue: float
    camera: object with get_ray(x, y) method
    """
    image_buffer = empty_array(width, height)
    
    for y in range(y_start, y_start + height):
        for x in range(x_start, x_start + width):
            ray = camera.get_ray(x, y)
            intersection_t = None
            
            # Phase 1 & 2: Traverse and Intersect
            current_cell = hierarchy.root
            t_current = ray.origin
            
            while current_cell is not None:
                # Check if isovalue is within the bounds of the current macrocell
                if not (hierarchy.get_min(current_cell) <= isovalue <= hierarchy.get_max(current_cell)):
                    # Skip this macrocell, advance ray to next cell boundary
                    t_current = ray.advance_to_next_cell_boundary(t_current, current_cell)
                    current_cell = hierarchy.get_next_cell(current_cell, t_current)
                    continue
                
                # If we are at the leaf level (data cells), perform analytic intersection
                if current_cell.is_leaf():
                    # Get the 8 corner values of the voxel
                    voxel_values = volume.get_voxel_values(current_cell)
                    
                    # Solve cubic polynomial for trilinear interpolation intersection
                    # Equation: rho(ray(t)) - isovalue = 0
                    roots = solve_cubic_trilinear_intersection(ray, voxel_values, isovalue)
                    
                    # Filter roots: must be within the cell's t-range
                    valid_roots = [t for t in roots if ray.is_in_cell(t, current_cell)]
                    
                    if valid_roots:
                        # Select closest intersection
                        intersection_t = min(valid_roots)
                        break
                
                # Advance to next cell in hierarchy or volume
                t_current = ray.advance_to_next_cell_boundary(t_current, current_cell)
                current_cell = hierarchy.get_next_cell(current_cell, t_current)
            
            # Phase 3: Shade
            if intersection_t is not None:
                point = ray.origin + intersection_t * ray.direction
                color = shade(point, ray, volume, hierarchy)
                image_buffer[y - y_start][x - x_start] = color
            else:
                image_buffer[y - y_start][x - x_start] = background_color
                
    return image_buffer

def solve_cubic_trilinear_intersection(ray, voxel_values, isovalue):
    """
    Solves for t in rho(x(t), y(t), z(t)) = isovalue using trilinear interpolation.
    Returns list of real roots.
    """
    # Define trilinear interpolation coefficients based on ray direction and voxel corners
    # rho(t) = c0 + c1*t + c2*t^2 + c3*t^3
    # The coefficients c0..c3 are derived from the 8 voxel values and ray direction components
    # This is a standard expansion of trilinear interpolation along a line
    coeffs = compute_trilinear_coeffs(ray, voxel_values)
    
    # Solve cubic equation c3*t^3 + c2*t^2 + c1*t + (c0 - isovalue) = 0
    roots = solve_cubic_equation(coeffs[3], coeffs[2], coeffs[1], coeffs[0] - isovalue)
    return roots
```

**Edge Cases and Pitfalls:**
*   **Precision:** Solving the cubic polynomial requires careful handling of numerical precision to avoid missing intersections or finding false ones near cell boundaries [S2, unofficial].
*   **Multiple Roots:** A ray may intersect the same isosurface multiple times within a single voxel (e.g., a thin structure passing through). The algorithm must select the smallest $t$ [S2, unofficial].
*   **Worst Case Complexity:** If the isosurface is highly complex and fills the volume, the hierarchy provides little benefit, and complexity approaches $O(n)$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Average complexity with a three-level hierarchy is $O(\sqrt[3]{n})$, where $n$ is the number of voxels. Worst case is $O(n)$ [S2, unofficial].
*   **Memory Complexity:** The hierarchy overhead is negligible (< 0.5% of data size) [S2, unofficial].
*   **Performance:** On an SGI Reality Monster (64 CPUs), the Visible Woman dataset (910 MB, 1734 slices, 512x512, 16-bit) achieves 7-15 FPS for skin isosurface ($\rho=600.5$) and 6-15 FPS for bone isosurface ($\rho=1224.5$) [S2, unofficial].
*   **Time Distribution:** For skin, traversal takes 55%, intersection 22%, shading 23%. For bone, traversal takes 66%, intersection 21%, shading 13% [S2, unofficial].
*   **Scalability:** On 128 processors, efficiency is 91% for View 1 and 80% for View 2. Efficiency drops for >64 processors due to load imbalance and synchronization overhead [S2, unofficial].
*   **Strengths:** Simplicity, scalability on distributed/shared-memory multiprocessors, no need for explicit mesh generation, correct front-to-back compositing order for transparency [S2, unofficial].
*   **Limitations:** High intrinsic computational cost compared to optimized ray-tracing methods (e.g., Wald's approach is ~5x faster on similar datasets) [S1, unofficial]. Performance is sensitive to load imbalance in complex views [S2, unofficial].

## Background
The method was introduced by DeMarle et al. in "Interactive Ray Tracing for Isosurface Rendering" [S2, unofficial]. It was designed to render the Visible Woman dataset (CT data from the National Library of Medicine Visible Human Project) interactively on high-end systems [S2, unofficial]. The approach leverages the scalability of brute-force ray tracing when combined with optimizations like bricking and spatial hierarchies [S2, unofficial].
