# Ray-Ray Intersection

Also called: Least-squares ray intersection, Ray vs. Ray Intersection

## Overview
Computes the least-squares intersection point of two rays in 3D space [S1, S2, unofficial]. It is used when rays do not intersect exactly (e.g., due to noise or parallax), finding the point that minimizes the squared distance to both rays [S1, S2, unofficial]. It sets itself apart from standard ray-casting which assumes exact intersection by minimizing the squared distance to both rays, making it robust to noise or parallax errors [S1, S2, unofficial].

## How it works
**Inputs:**
- `origins`: Tensor of shape `(2, *shape, 3)` containing the origins of the two rays [S1, S2, unofficial].
- `directions`: Tensor of shape `(2, *shape, 3)` containing the direction vectors of the two rays [S1, S2, unofficial].
- `eps`: Float threshold for detecting parallel rays (default `1e-5`) [S1, S2, unofficial].
- `inf_val`: Float value returned for parallel ray intersections (default `1e10`) [S1, S2, unofficial].

**Outputs:**
- `result`: Tensor of shape `(*shape, 3)` containing the least-squares intersection points; parallel ray pairs are assigned `inf_val` [S1, S2, unofficial].

**Data Structures:**
- The algorithm operates on batched tensors where `shape` represents the batch dimensions (e.g., number of ray pairs) [S1, S2, unofficial].
- Intermediate tensor `n` has shape `(2, *shape, 3, 3)` representing the matrix $n_{r,b,i,j}$ [S2, unofficial].
- Intermediate tensor `lhs` has shape `(*shape, 3, 3)` [S2, unofficial].
- Intermediate tensor `rhs` has shape `(*shape, 3)` [S2, unofficial].

**Steps:**
1. Broadcast `origins` and `directions` to a common shape [S1, S2, unofficial].
2. Detect parallel rays by computing the dot product of the direction vectors for each ray pair; a pair is considered parallel if the dot product exceeds $1 - \text{eps}$ [S1, S2, unofficial].
3. Filter out parallel rays from the `origins` and `directions` tensors [S1, S2, unofficial].
4. Stack rays into tensors of shape `(2, *shape, 3)` [S1, S2, unofficial].
5. Compute the outer product matrix $n_{r,b,i,j} = d_{r,b,i} d_{r,b,j} - \delta_{i,j}$ for each ray, where $d$ is the direction vector and $\delta$ is the Kronecker delta (identity matrix) [S2, unofficial].
6. Compute the left-hand side $L_{b,i,j} = \sum_{r=0}^{1} n_{r,b,i,j}$ by summing $n$ over the ray dimension [S2, unofficial].
7. Compute the right-hand side $R_{b,i} = \sum_{r=0}^{1} \sum_{j=0}^{2} n_{r,b,i,j} o_{r,b,j}$ by multiplying $n$ with the origins $o$ and summing over the ray and inner indices [S2, unofficial].
8. Solve the linear system $L p = R$ for $p$ using least squares [S1, S2, unofficial].
9. Initialize the output tensor with `inf_val` [S1, S2, unofficial].
10. Assign the computed solution $p$ to the non-parallel indices [S1, S2, unofficial].

**Pseudocode:**
```python
import torch

def intersect_rays(origins, directions, eps=1e-5, inf_val=1e10):
    """
    Computes the least-squares intersection point of two rays in 3D space.
    
    Args:
        origins: Tensor of shape (2, *shape, 3)
        directions: Tensor of shape (2, *shape, 3)
        eps: Threshold for parallel ray detection
        inf_val: Value for parallel ray results
        
    Returns:
        result: Tensor of shape (*shape, 3)
    """
    origins = torch.as_tensor(origins, dtype=torch.float32)
    directions = torch.as_tensor(directions, dtype=torch.float32)
    
    shape = origins.shape[1:-1]
    
    # Step 2: Detect parallel rays
    dot_product = torch.sum(directions[0] * directions[1], dim=-1)
    parallel = dot_product > (1.0 - eps)
    
    # Step 3: Filter parallel rays
    non_parallel_mask = ~parallel
    if not torch.any(non_parallel_mask):
        return torch.full((*shape, 3), inf_val, dtype=origins.dtype, device=origins.device)
        
    # Flatten batch dimensions for indexing
    origins_flat = origins.reshape(2, -1, 3)
    directions_flat = directions.reshape(2, -1, 3)
    parallel_flat = parallel.reshape(-1)
    non_parallel_flat = ~parallel_flat
    
    origins_filtered = origins_flat[:, non_parallel_flat, :]
    directions_filtered = directions_flat[:, non_parallel_flat, :]
    
    # Step 5: Compute n
    n = torch.einsum("r b i, r b j -> r b i j", directions_filtered, directions_filtered)
    eye_3 = torch.eye(3, dtype=n.dtype, device=n.device)
    n = n - eye_3.unsqueeze(0).unsqueeze(0)
    
    # Step 6: Compute LHS
    lhs = torch.sum(n, dim=0)
    
    # Step 7: Compute RHS
    rhs_temp = torch.einsum("r b i j, r b j -> r b i", n, origins_filtered)
    rhs = torch.sum(rhs_temp, dim=0)
    
    # Step 8: Solve linear system
    solution = torch.linalg.lstsq(lhs, rhs).solution
    
    # Step 9 & 10: Initialize and assign results
    result = torch.full((*shape, 3), inf_val, dtype=origins.dtype, device=origins.device)
    result_flat = result.reshape(-1, 3)
    result_flat[non_parallel_flat, :] = solution
    result = result_flat.reshape(*shape, 3)
    
    return result
```

**Parameters:**
- `eps`: Float, default `1e-5`. Threshold for detecting parallel rays based on dot product proximity to 1 [S1, S2, unofficial].
- `inf_val`: Float, default `1e10`. Value returned for parallel ray intersections [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **Parallel Rays:** If rays are parallel, the dot product threshold detects them and the algorithm returns `inf_val` [S1, S2, unofficial].
- **Degenerate Input:** If origins or directions contain NaN or Inf, standard floating-point propagation rules apply [G].

## Subtopics

### [Ray Casting and Intersection](17001-ray-casting-and-intersection.md)
Computes 3D ray origins and directions from 2D pixel coordinates and camera parameters, and finds the least-squares intersection point of two rays in 3D space. It extends [Ray-Ray Intersection](7624-ray-ray-intersection.md) by batching the computation over multiple pixel locations and handling the transformation from camera to world space. It is distinct from standard ray-casting which assumes exact intersection; this method minimizes the squared distance to both rays, making it robust to noise or parallax errors.

### Geometry Consistent Filter
A filter to eliminate inaccurate correspondences by computing the minimal distance between two rays; true correspondences should converge at a single point (distance ~ 0) [S3]. It discards paired rays where $d_{ray} > \tau_{ray}$ [S3]. The distance $d_{ray}$ is computed as $\|o_1 - o_2 + m d_1 - n d_2\|_2$, where $o_1, o_2$ are origins, $d_1, d_2$ are directions, and $m, n$ are distances from origins to the closest points on the respective rays [S3]. The values $m$ and $n$ are solved from the system:
$$
\begin{cases}
m(d_1 \cdot d_2) - n(d_1 \cdot d_2) = d_1 \cdot o_2 - d_1 \cdot o_1 \\
m(d_1 \cdot d_2) - n(d_2 \cdot d_2) = d_2 \cdot o_2 - d_2 \cdot o_1
\end{cases}
$$
[S3]
The solution is:
$$
m = \frac{be + cf - cg - bd}{ab - c^2}, \quad n = \frac{ce + af - cd - ag}{ab - c^2}
$$
where $a = d_1 \cdot d_1$, $b = d_2 \cdot d_2$, $c = d_1 \cdot d_2$, $d = d_1 \cdot o_1$, $e = d_1 \cdot o_2$, $f = d_2 \cdot o_1$, $g = d_2 \cdot o_2$ [S3].

## Background
Originated in the context of neural rendering and multi-view geometry, specifically in methods like NoPoSplat and VolSplat [S1, S2, unofficial] and SGCNeRF [S3]. It is used to establish robust correspondences between rays from different views, which is crucial for geometry regularization in neural radiance fields (NeRF) [S3].
