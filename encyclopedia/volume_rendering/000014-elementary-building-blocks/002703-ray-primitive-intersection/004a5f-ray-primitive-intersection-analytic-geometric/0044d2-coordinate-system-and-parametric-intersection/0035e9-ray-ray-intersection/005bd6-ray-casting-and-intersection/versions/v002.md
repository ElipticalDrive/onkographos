# Ray Casting and Intersection

Also called: Least-squares ray intersection, Ray Intersection, Ray intersection via least squares, Ray-Ray Intersection

## Overview
Computes 3D ray origins and directions from 2D pixel coordinates and camera parameters, and finds the least-squares intersection point of two rays in 3D space [S1, unofficial]. It extends [Ray-Ray Intersection](7624-ray-ray-intersection.md) by batching the computation over multiple pixel locations and handling the transformation from camera to world space [S1, unofficial]. It is distinct from standard ray-casting which assumes exact intersection; this method minimizes the squared distance to both rays, making it robust to noise or parallax errors [S1, S2, unofficial].

## How it works
**Inputs:**
- `intrinsics`: Camera intrinsic matrix $K$ (typically $3 \times 3$).
- `extrinsics`: Camera extrinsic matrix $T$ (typically $4 \times 4$), containing rotation $R$ and translation $t$.
- `pixel_coords`: 2D pixel coordinates $(u, v)$ for the rays to be cast.
- `parallel_eps`: Epsilon threshold for detecting parallel rays (default $10^{-5}$) [S1, unofficial].
- `inf_val`: Value used to represent infinity for parallel ray intersections (default $10^{10}$) [S1, unofficial].

**Outputs:**
- `intersection_points`: 3D coordinates $(x, y, z)$ of the least-squares intersection points for each pixel/ray pair.

**Data Structures:**
- Ray directions are stored as unit vectors in world space.
- Ray origins are stored as 3D points (camera centers).
- Matrices $N$ are $3 \times 3$ matrices derived from ray directions.

**Steps:**

1.  **Unproject to Camera Space:**
    Convert 2D pixel coordinates $(u, v)$ to homogeneous coordinates $\mathbf{p}_{cam} = [u, v, 1]^T$. Multiply by the inverse intrinsic matrix $K^{-1}$ to get unprojected direction vectors in camera space:
    $$ \mathbf{d}_{cam} = K^{-1} \mathbf{p}_{cam} $$
    Normalize these vectors by dividing by their $z$-component (depth) to ensure they point forward in the camera frustum:
    $$ \mathbf{d}_{cam} = \frac{\mathbf{d}_{cam}}{\mathbf{d}_{cam}[2]} $$
    [S1, unofficial]

2.  **Transform to World Space:**
    Transform the ray directions from camera space to world space using the rotation component $R$ of the extrinsic matrix:
    $$ \mathbf{d}_{world} = R \mathbf{d}_{cam} $$
    Normalize $\mathbf{d}_{world}$ to obtain unit direction vectors $\mathbf{u}$:
    $$ \mathbf{u} = \frac{\mathbf{d}_{world}}{\|\mathbf{d}_{world}\|} $$
    [S1, unofficial]

3.  **Compute Ray Origins:**
    The origin of each ray is the camera center. Extract the translation vector $t$ from the extrinsic matrix $T$. Tile this origin to match the batch shape of the rays.
    [S1, unofficial]

4.  **Detect Parallel Rays:**
    For a pair of rays with directions $\mathbf{u}_1$ and $\mathbf{u}_2$, compute the dot product. If the dot product is greater than $1 - \text{parallel\_eps}$, the rays are considered parallel.
    $$ \text{parallel} = \mathbf{u}_1 \cdot \mathbf{u}_2 > 1 - \text{parallel\_eps} $$
    [S1, S2, unofficial]

5.  **Construct Least-Squares System:**
    For each ray $i$ with direction $\mathbf{u}_i$, compute the matrix $N_i$:
    $$ N_i = \mathbf{u}_i \mathbf{u}_i^T - I $$
    where $I$ is the $3 \times 3$ identity matrix.
    [S1, S2, unofficial]

    Compute the Left-Hand Side (LHS) of the linear system $A \mathbf{x} = \mathbf{b}$ by summing $N_i$ over all rays involved in the intersection (typically two rays per pixel):
    $$ A = \sum_i N_i $$
    [S1, S2, unofficial]

    Compute the Right-Hand Side (RHS) by summing $N_i \mathbf{o}_i$ over all rays, where $\mathbf{o}_i$ is the origin of ray $i$:
    $$ \mathbf{b} = \sum_i N_i \mathbf{o}_i $$
    [S1, S2, unofficial]

6.  **Solve for Intersection:**
    Solve the linear system $A \mathbf{x} = \mathbf{b}$ for $\mathbf{x}$ using least squares:
    $$ \mathbf{x} = \text{argmin}_{\mathbf{x}} \| A \mathbf{x} - \mathbf{b} \|^2 $$
    [S1, unofficial]

7.  **Handle Parallel Rays:**
    If rays are parallel (detected in Step 4), the system is singular. Set the intersection point for these rays to $\text{inf\_val}$ (default $10^{10}$) to indicate no valid intersection.
    [S1, S2, unofficial]

        intrinsics: (B, 3, 3) Camera intrinsic matrices.

def intersect_rays(
    directions_1: torch.Tensor,
    origins_1: torch.Tensor,
    directions_2: torch.Tensor,
    origins_2: torch.Tensor,
    parallel_eps: float = 1e-5,
    inf_val: float = 1e10
) -> torch.Tensor:
    """
    Computes the least-squares intersection of two rays.
    
    Args:
        directions_1: (B, 3) Unit direction vectors of ray 1.
        origins_1: (B, 3) Origins of ray 1.
        directions_2: (B, 3) Unit direction vectors of ray 2.
        origins_2: (B, 3) Origins of ray 2.
        parallel_eps: Epsilon for parallel ray detection.
        inf_val: Value for parallel ray results.
        
    Returns:
        intersection_points: (B, 3) 3D intersection points.
    """
    B = directions_1.shape[0]
    
    # Step 4: Detect parallel rays
    dot_products = torch.sum(directions_1 * directions_2, dim=1)  # (B,)
    is_parallel = dot_products > (1.0 - parallel_eps)  # (B,)
    
    # Step 5: Construct Least-Squares System
    # N_i = u_i u_i^T - I
    # For ray 1
    u1 = directions_1.unsqueeze(2)  # (B, 3, 1)
    u1_T = directions_1.unsqueeze(1)  # (B, 1, 3)
    N1 = torch.bmm(u1, u1_T) - torch.eye(3, device=directions_1.device).unsqueeze(0)  # (B, 3, 3)
    
    # For ray 2
    u2 = directions_2.unsqueeze(2)  # (B, 3, 1)
    u2_T = directions_2.unsqueeze(1)  # (B, 1, 3)
    N2 = torch.bmm(u2, u2_T) - torch.eye(3, device=directions_2.device).unsqueeze(0)  # (B, 3, 3)
    
    # LHS: A = N1 + N2
    A = N1 + N2  # (B, 3, 3)
    
    # RHS: b = N1 * o1 + N2 * o2
    b1 = torch.bmm(N1, origins_1.unsqueeze(2)).squeeze(2)  # (B, 3)
    b2 = torch.bmm(N2, origins_2.unsqueeze(2)).squeeze(2)  # (B, 3)
    b = b1 + b2  # (B, 3)
    
    # Step 6: Solve for intersection
    # Use lstsq
    # result = torch.linalg.lstsq(A, b).solution
    # Note: lstsq might fail for singular matrices. We handle parallel rays separately.
    
    # Filter out parallel rays for solving
    non_parallel_mask = ~is_parallel  # (B,)
    
    # Initialize result with inf_val
    result = torch.full((B, 3), inf_val, device=directions_1.device)
    
    # Solve for non-parallel rays
    if non_parallel_mask.any():
        A_np = A[non_parallel_mask]  # (K, 3, 3)
        b_np = b[non_parallel_mask]  # (K, 3)
        
        # Solve least squares
        # torch.linalg.lstsq returns a solution, residuals, rank, singular values
        # We only need the solution
        try:
            sol = torch.linalg.lstsq(A_np, b_np).solution  # (K, 3)
            result[non_parallel_mask] = sol
        except RuntimeError:
            # If lstsq fails (e.g., due to numerical issues), keep inf_val
            pass
            
    return result

def ray_casting_and_intersection(
    intrinsics_1: torch.Tensor,
    extrinsics_1: torch.Tensor,
    intrinsics_2: torch.Tensor,
    extrinsics_2: torch.Tensor,
    pixel_coords_1: torch.Tensor,
    pixel_coords_2: torch.Tensor,
    parallel_eps: float = 1e-5,
    inf_val: float = 1e10
) -> torch.Tensor:
    """
    Main function: Casts rays from pixels and computes their intersection.
    
    Args:
        intrinsics_1: (B, 3, 3)
        extrinsics_1: (B, 4, 4)
        intrinsics_2: (B, 3, 3)
        extrinsics_2: (B, 4, 4)
        pixel_coords_1: (B, 2)
        pixel_coords_2: (B, 2)
        parallel_eps: Epsilon for parallel ray detection.
        inf_val: Value for parallel ray results.
        
    Returns:
        intersection_points: (B, 3)
    """
    # Cast rays for camera 1
    rays_1 = _cast_rays(intrinsics_1, extrinsics_1, pixel_coords_1)
    
    # Cast rays for camera 2
    rays_2 = _cast_rays(intrinsics_2, extrinsics_2, pixel_coords_2)
    
    # Intersect
    return intersect_rays(
        rays_1['directions'],
        rays_1['origins'],
        rays_2['directions'],
        rays_2['origins'],
        parallel_eps,
        inf_val
    )

def _cast_rays(intrinsics: torch.Tensor, extrinsics: torch.Tensor, pixel_coords: torch.Tensor) -> dict:
    B = pixel_coords.shape[0]
    
    # Step 1: Unproject to camera space
    ones = torch.ones(B, 1, device=pixel_coords.device)
    p_cam = torch.cat([pixel_coords, ones], dim=1)  # (B, 3)
    
    K_inv = torch.inverse(intrinsics)  # (B, 3, 3)
    d_cam = torch.bmm(K_inv, p_cam.unsqueeze(2)).squeeze(2)  # (B, 3)
    
    # Normalize by z-component
    d_cam_z = d_cam[:, 2:3]  # (B, 1)
    d_cam = d_cam / d_cam_z  # (B, 3)
    
    # Step 2: Transform to world space
    R = extrinsics[:, :3, :3]  # (B, 3, 3)
    d_world = torch.bmm(R, d_cam.unsqueeze(2)).squeeze(2)  # (B, 3)
    
    # Normalize to unit vectors
    norms = torch.norm(d_world, dim=1, keepdim=True)  # (B, 1)
    u = d_world / norms  # (B, 3)
    
    # Step 3: Compute origins
    t = extrinsics[:, :3, 3]  # (B, 3)
    origins = t  # (B, 3)
    
    return {'directions': u, 'origins': origins}

## Operating characteristics
- **Time Complexity:** $O(B)$ where $B$ is the batch size, dominated by matrix multiplications and the least-squares solve. The solve is $O(1)$ per batch item since the system is $3 \times 3$.
- **Memory Complexity:** $O(B)$ for storing directions, origins, and intermediate matrices.
- **Performance:** Efficient on GPU due to batched operations. The use of `torch.linalg.lstsq` is optimized for CUDA.
- **Strengths:** Robust to noise and parallax errors. Handles non-intersecting rays gracefully.
- **Limitations:** Fails for parallel rays (returns infinity). Numerical stability depends on the condition number of the matrix $A$.
- **When to use:** Stereo matching, multi-view geometry, NeRF training where rays from different views need to intersect.
- **When not to use:** When exact intersection is guaranteed and performance is critical (simple geometric intersection is faster).

## Background
Originated in the context of multi-view stereo and neural radiance fields (NeRF) to handle the discrepancy between rays from different cameras that do not intersect exactly due to calibration errors or scene depth variations [S1, S2, unofficial]. The method is commonly used in libraries like `depthsplat` and `VoLoDSplat` for efficient ray intersection computation [S1, S2, unofficial].
