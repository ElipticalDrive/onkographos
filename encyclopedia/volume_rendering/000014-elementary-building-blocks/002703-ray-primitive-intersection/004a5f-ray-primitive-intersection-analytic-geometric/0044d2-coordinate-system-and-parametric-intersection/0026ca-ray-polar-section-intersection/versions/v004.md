# Ray-Polar Section Intersection

Also called: Polar Hit Detection, polarHit

## Overview
Ray-Polar Section Intersection determines whether a polar hit occurs for a given ray [S1, unofficial]. A polar hit is an intersection between the ray and a polar section, where polar sections reside in the XY plane [S1, unofficial].

## How it works
**Inputs and Outputs**
The method takes a ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, a spherical voxel grid containing polar boundary data (`pMaxPolar`, `centerToPolarBound`), a ray segment $\mathbf{s}$ with endpoints $P_1, P_2$ and vector $\mathbf{v} = P_2 - P_1$, traversal bounds $t$ and $\max_t$, and a collinear times container [S1, unofficial]. It outputs a boolean or integer indicating whether a polar hit occurred and the specific polar voxel ID [S1, unofficial].

**Data Structures**
`BoundVec3` is a 3D vector structure where the Z component is fixed at $0.0$ for polar calculations [S1, unofficial]. `LineSegment` represents a polar section boundary with fields `P1` (x-coordinate) and `P2` (y-coordinate) in the XY plane [S1, unofficial]. `SphericalVoxelGrid` provides `pMaxPolar(v)` to return the boundary `LineSegment` for voxel `v`, `centerToPolarBound(v)` to return a pointer to the center boundary vector, and `sphereCenter()` to return the 3D grid center [S1, unofficial].

**Steps**
1. Initialize the current polar voxel index `current_polar_voxel` using the ray's position relative to the sphere center and entry point [S1, unofficial].
2. Construct the minimum and maximum boundary vectors $\mathbf{p}_{\text{one}}$ and $\mathbf{p}_{\text{two}}$ from the current and next voxel boundaries [S1, unofficial].
3. Retrieve pointers to the center bounds $\mathbf{u}_{\text{min}}$ and $\mathbf{u}_{\text{max}}$ for the current and next voxels [S1, unofficial].
4. Compute relative vectors $\mathbf{w}_{\text{min}}$ and $\mathbf{w}_{\text{max}}$ by subtracting the ray segment's first endpoint from $\mathbf{p}_{\text{one}}$ and $\mathbf{p}_{\text{two}}$ [S1, unofficial].
5. Calculate six 2D cross products (perpendicular dot products) between the center bounds, ray vector, and relative vectors [S1, unofficial].
6. Pass all computed values to the angular hit evaluation routine [S1, unofficial].

**Pseudocode**
```python
def ray_polar_section_intersection(grid, ray, ray_segment, collinear_times, t, max_t):
    # 1. Initialize current polar voxel index
    # The index is found by minimizing the squared distance from the ray-sphere vector to boundary segments [S1, unofficial].
    # If sections == 1 or the squared Euclidean distance in the plane is zero, the index is 0 [S1, unofficial].
    current_polar_voxel = initialize_angular_voxel_id(grid, ray, ray_segment)

    # 2. Define boundary points p_one and p_two
    p_one = (grid.pMaxPolar(current_polar_voxel).P1, grid.pMaxPolar(current_polar_voxel).P2, 0.0)
    p_two = (grid.pMaxPolar(current_polar_voxel + 1).P1, grid.pMaxPolar(current_polar_voxel + 1).P2, 0.0)

    # 3. Retrieve center bounds
    u_min = grid.centerToPolarBound(current_polar_voxel)
    u_max = grid.centerToPolarBound(current_polar_voxel + 1)

    # 4. Calculate relative vectors w_min and w_max
    w_min = (p_one[0] - ray_segment.p1[0], p_one[1] - ray_segment.p1[1], 0.0)
    w_max = (p_two[0] - ray_segment.p1[0], p_two[1] - ray_segment.p1[1], 0.0)

    # 5. Calculate perpendicular dot products (2D cross products)
    ray_vec_x = ray_segment.v[0]
    ray_vec_y = ray_segment.v[1]

    perp_uv_min = u_min[0] * ray_vec_y - u_min[1] * ray_vec_x
    perp_uv_max = u_max[0] * ray_vec_y - u_max[1] * ray_vec_x

    perp_uw_min = u_min[0] * w_min[1] - u_min[1] * w_min[0]
    perp_uw_max = u_max[0] * w_max[1] - u_max[1] * w_max[0]

    perp_vw_min = ray_vec_x * w_min[1] - ray_vec_y * w_min[0]
    perp_vw_max = ray_vec_x * w_max[1] - ray_vec_y * w_max[0]

    # 6. Invoke Angular Hit Function
    # The source specifies returning angularHit(...) with these parameters, but does not provide its internal implementation [S1, unofficial].
    # return angularHit(grid, ray, perp_uv_min, perp_uv_max, perp_uw_min, perp_uw_max, perp_vw_min, perp_vw_max, ray_segment, collinear_times, t, max_t, ray.direction[1], grid.sphereCenter[1], grid.pMaxPolar, current_polar_voxel)
    return (perp_uv_min, perp_uv_max, perp_uw_min, perp_uw_max, perp_vw_min, perp_vw_max)
```

**Parameters**
`grid` is the spherical voxel grid structure [S1, unofficial]. `ray` is the ray object containing origin and direction [S1, unofficial]. `ray_segment` is the segment of the ray currently being tested, defined by endpoints and vector [S1, unofficial]. `collinear_times` is a container storing intersection times for collinear cases [S1, unofficial]. `t` is the current traversal parameter [S1, unofficial]. `max_t` is the maximum traversal parameter serving as the exit bound [S1, unofficial].

**Edge Cases and Pitfalls**
Collinearity occurs when the ray aligns with a polar boundary, causing standard cross products to yield zero [S1, unofficial]. The algorithm relies on the `collinear_times` container to resolve these degenerate cases [S1, unofficial]. Zero distance arises when the squared Euclidean distance of the ray-sphere vector in the plane is zero, which forces the voxel ID to $0$ to prevent division by zero during initialization [S1, unofficial]. Double precision is used for boundary calculations to maintain accuracy during angular traversal [S1, unofficial].

## Background
The method originates from the spherical-volume-rendering/svr-algorithm repository [S1, unofficial]. It generalizes ray-box intersection logic to angular sectors in the XY plane for polar coordinates, or the XZ plane for azimuthal coordinates [S1, unofficial].
