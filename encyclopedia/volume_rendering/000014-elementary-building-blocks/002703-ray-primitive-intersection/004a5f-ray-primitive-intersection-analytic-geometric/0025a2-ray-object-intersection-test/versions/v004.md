# Ray-Object Intersection Test

Also called: Child Ray Intersection with Transformation, Ray Intersection Update, Ray-Object Intersection, raytrace

## Overview
The Ray-Object Intersection Test is the fundamental geometric primitive used to determine if a ray intersects a specific scene object and to compute the distance to the closest intersection point [S1, S4, S5, unofficial]. It serves as the core decision unit in ray tracing and volume rendering pipelines, where it is invoked repeatedly to find the nearest surface or volume boundary along a ray's path [S1, S3, unofficial]. Unlike broader traversal algorithms that manage spatial acceleration structures, this test focuses on the analytic or geometric solution between a single ray and a single object (or a list of objects in a naive implementation) [S1, S3, unofficial]. It is distinguished from sibling methods like [Sphere Intersection](1620-sphere-intersection.md) by its general applicability to any object type via coordinate transformation or specific analytic formulas, and from [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) by its potential handling of complex or transformed primitives [S5, unofficial].

## How it works
The method generally follows one of two patterns: a direct test for a single object (often involving coordinate transformation) or a brute-force iteration over a list of objects to find the global closest hit.

### Inputs and Outputs
**Inputs:**
1.  **Ray ($r$):** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].
2.  **Object ($o$):** The geometric primitive or scene object to test against [S1, S5, unofficial].
3.  **Minimum Distance Threshold ($\epsilon$):** A small positive value to prevent self-intersection or near-origin artifacts [S2, S4, S5, unofficial]. Typical values are $1.0 \times 10^{-5}$ or $0.001$ [S2, S5, unofficial].

**Outputs:**
1.  **Intersection Distance ($t$):** The parametric distance along the ray to the intersection point. If no intersection is found, returns $-1$ or $\infty$ [S1, S3, unofficial].
2.  **Hit Status:** A boolean indicating whether an intersection occurred [S2, unofficial].
3.  **Intersection Data (Optional):** Normal $\mathbf{n}$, point $\mathbf{p}$, object pointer, and material properties [S5, unofficial].

### Data Structures
The ray is typically represented as a struct containing:
*   `origin`: Vector3D (x, y, z) [S2, unofficial].
*   `direction`: Vector3D (x, y, z), typically normalized [G].
*   `t`: Float, current distance traveled [S2, unofficial].
*   `hit`: Boolean, true if an intersection has been recorded [S2, unofficial].

For object-based tests involving transformations, the object may provide a transformation matrix $\mathbf{M}$ [S5, unofficial].

### Steps

#### Case A: Single Object with Transformation (Local Space Test)
This approach is used when objects are defined in local coordinates and may have arbitrary transformations [S5, unofficial].

1.  **Transform Ray to Local Space:**
    *   Transform the ray origin $\mathbf{o}$: $\mathbf{o}_{local} = \mathbf{M}^{-1} (\mathbf{o}, 1)$ [S5, unofficial].
    *   Transform the ray direction $\mathbf{d}$: $\mathbf{d}_{local} = \mathbf{M}^{-1} (\mathbf{d}, 0)$ [S5, unofficial].
    *   Note: Directions are transformed as vectors (w=0) to ignore translation [S5, unofficial].
2.  **Perform Local Intersection Test:**
    *   Solve the analytic equations for the object in its local coordinate system (e.g., unit sphere $x^2+y^2+z^2=1$) [S1, S5, unofficial].
    *   Let the resulting parametric distance be $t_{local}$.
3.  **Transform Result Back (if necessary):**
    *   If the object's transformation is uniform scaling, $t_{local}$ can be used directly. Otherwise, the intersection point $\mathbf{p}_{local} = \mathbf{o}_{local} + t_{local}\mathbf{d}_{local}$ must be transformed back to world space to compute the correct world-space distance $t_{world}$ [S5, unofficial].
    *   Alternatively, if the test returns the world-space distance directly, skip this.
4.  **Validate Distance:**
    *   If $t_{world} > \epsilon$ and $t_{world} < t_{current\_closest}$, update the hit state [S2, S4, S5, unofficial].
    *   Compute the world-space normal $\mathbf{n}_{world} = \mathbf{M}^{-T} \mathbf{n}_{local}$, normalize it, and store surface properties [S5, unofficial].

#### Case B: Brute-Force List Intersection
This approach iterates over all objects to find the closest hit [S3, S4, unofficial].

1.  **Initialize:** Set $t_{min} = \infty$ and $obj_{hit} = \text{null}$ [S3, S4, unofficial].
2.  **Iterate:** For each object $o_i$ in the scene:
    *   Compute intersection distance $t_i = \text{intersect}(r, o_i)$ [S3, unofficial].
    *   If $0 < t_i < t_{min}$ and $t_i > \epsilon$:
        *   $t_{min} = t_i$
        *   $obj_{hit} = o_i$
3.  **Return:** If $t_{min} < \infty$, return $t_{min}$ and $obj_{hit}$; else return $-1$ [S1, S3, unofficial].

### Formulas
*   **Ray Equation:** $\mathbf{p}(t) = \mathbf{o} + t\mathbf{d}$, where $t \in \mathbb{R}^+$ [S1, unofficial].
*   **Unit Sphere:** $\{(x, y, z) \mid x^2 + y^2 + z^2 = 1\}$ [S1, unofficial].
*   **Optimization Criterion:** Find object $o$ that minimizes $t$ such that $t = \text{intersection test}(r, o)$ and $t > 0$ [S1, unofficial].
*   **Update Condition:** If $t_{new} < t_{current}$ and $t_{new} > \epsilon$, update hit [S2, S4, unofficial].

### Parameters
*   **SMALLEST_DIST ($\epsilon$):** Minimum distance to accept a hit. Values cited: $1.0 \times 10^{-5}$ [S2, S4, unofficial] or $0.001$ [S5, unofficial].
*   **DT:** Step size for volume traversal (if applicable), used to advance the ray [S2, unofficial].

### Edge Cases and Pitfalls
*   **Self-Intersection/Shadow Acne:** Intersections very close to the ray origin or previous hit point ($t \le \epsilon$) must be rejected to prevent artifacts [S2, S4, S5, unofficial].
*   **Transformation Accuracy:** Transforming normals requires the inverse-transpose of the model matrix to preserve orthogonality [S5, unofficial].
*   **Degenerate Rays:** Rays with zero-length direction vectors should be handled or normalized [G].
*   **Precision:** Floating-point precision errors can cause missed intersections or incorrect ordering in tight loops [G].

def intersect_single_object(ray, obj):
    """
    Performs the intersection test for a single object.
    Handles transformation to local space if the object is transformed.
    
    Args:
        ray: Ray in world space.
        obj: Object with potential transformation matrix.
        
    Returns:
        float: Distance t to intersection, or -1 if no intersection.
    """
    # Check if object requires local space transformation
    if obj.has_transformation():
        # Transform ray origin and direction to local space
        # M_inv is the inverse of the object's transformation matrix
        M_inv = obj.get_inverse_matrix()
        
        # Transform origin (w=1)
        o_local = M_inv.transform_point(ray.origin)
        
        # Transform direction (w=0)
        d_local = M_inv.transform_vector(ray.direction)
        
        # Create temporary local ray
        local_ray = Ray(o_local, d_local)
        
        # Perform intersection in local space
        t_local = intersect_local(local_ray, obj)
        
        if t_local > 0:
            # Transform intersection point back to world space to get correct distance
            # p_world = M * (o_local + t_local * d_local)
            # t_world = |p_world - ray.origin|
            # However, if the transformation is rigid (rotation+translation), 
            # t_world = t_local * |d_local| (if d was not normalized) or just t_local if d is unit.
            # For general affine, we compute the point and distance.
            p_local = o_local + t_local * d_local
            p_world = obj.get_matrix().transform_point(p_local)
            t_world = distance(p_world, ray.origin)
            return t_world
        else:
            return -1
    else:
        # No transformation, direct test
        return intersect_local(ray, obj)

## Subtopics

### [Bounding Box Node Intersection](3958-bounding-box-node-intersection.md)
A recursive ray traversal algorithm for a binary bounding box tree (BBNode) that determines the closest surface intersection by testing the node's bounding box, then recursing into left and right children, and finally comparing hit distances. It is chosen when spatial acceleration is needed to reduce the number of ray-object tests.

## Operating characteristics
*   **Time Complexity:** $O(N)$ for a brute-force list of $N$ objects [S3, S4, unofficial]. $O(1)$ for a single object test [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space for the test itself [S1, unofficial].
*   **Strengths:** Simple to implement; provides exact analytic results for primitive shapes [S1, unofficial].
*   **Limitations:** Naive iteration does not scale to large scenes; requires acceleration structures (like BVH or Octrees) for performance [S1, S5, unofficial].
*   **When to use:** Small scenes, single-object tests, or as the leaf node test in acceleration structures [S1, S5, unofficial].
*   **When not to use:** Large scenes without acceleration; when approximate bounds are sufficient for early rejection.

## Background
The ray-object intersection test is a foundational concept in ray tracing, originating with the work of Turner Whitted in 1980 [S1, unofficial]. It is widely used in computer graphics for rendering, collision detection, and volume rendering [S1, S4, S5, unofficial]. The method involves solving a system of equations between the ray and the object's geometric representation [S1, unofficial].
