# Bounding Box Node Intersection

Also called: BBNode::intersect

## Overview
A recursive ray traversal algorithm for a binary bounding box tree (BBNode) that determines the closest surface intersection by testing the node's bounding box, then recursing into left and right children, and finally comparing hit distances [S1, unofficial]. It differs from generic hierarchical bounding volume searches by enforcing a strict binary split and specific epsilon-based precision handling for distance comparisons [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A ray $R$ (origin $O$, direction $D$), a pointer to the root `BBNode`, and a current minimum hit distance $t_{min}$ (initially $-\infty$ or 0 depending on context, but typically the ray's near plane).
- Output: The closest intersection distance $t$ along the ray, or a sentinel value (e.g., -1 or infinity) if no intersection is found within the tree.

**Data structures:**
The `BBNode` structure contains the following fields [S1, unofficial]:
- `min`: `Vec3`, the minimum corner of the bounding box.
- `max`: `Vec3`, the maximum corner of the bounding box.
- `child_l`: `SceneObject*`, pointer to the left child.
- `child_r`: `SceneObject*`, pointer to the right child.
- `getType()`: A method returning an enum indicating if the node is a `NODE` (internal) or a leaf type.

**Parameters:**
- `epsilon`: A small constant used to handle floating-point precision issues in hit distance comparison. Typical value: `0.001f` [S1, unofficial].

**Steps:**
1. **Bounding Box Test:** Test if the ray intersects the current node's bounding box defined by `min` and `max`. If no intersection, return failure/no hit.
2. **Left Child Recursion:**
   - If `child_l` exists:
     - If `child_l` is a `NODE` (castable to `BBNode`), recursively call `intersect` on `child_l`.
     - Otherwise, call `child_intersect` (the primitive intersection test for the leaf object).
     - Let the result be $t_l$.
3. **Right Child Recursion:**
   - If `child_r` exists:
     - If `child_r` is a `NODE` (castable to `BBNode`), recursively call `intersect` on `child_r`.
     - Otherwise, call `child_intersect` (the primitive intersection test for the leaf object).
     - Let the result be $t_r$.
4. **Comparison and Return:**
   - Compare $t_l$ and $t_r$ to find the closest hit.
   - Handle precision: When comparing hit distances, add `epsilon` to the left hit distance ($t_l + \epsilon$) before comparing against $t_r$ to mitigate floating-point errors [S1, unofficial].
   - Return the smallest valid distance.

**Pseudocode:**

```python
def bbnode_intersect(node, ray, t_min):
    """
    Recursively find the closest intersection in a BBNode tree.
    
    Args:
        node: BBNode object with min, max, child_l, child_r, getType()
        ray: Ray object with origin O and direction D
        t_min: Current minimum valid intersection distance
        
    Returns:
        Closest intersection distance t, or -1 if no intersection.
    """
    # Step 1: Bounding Box Intersection Test
    # Implement standard slab method for AABB-Ray intersection
    # Returns t_hit if intersected, else -1
    t_hit = intersect_aabb(node.min, node.max, ray.O, ray.D)
    
    if t_hit == -1:
        return -1

    # Initialize best hit distance
    best_t = -1
    
    # Step 2: Process Left Child
    if node.child_l is not None:
        if node.getType() == NODE:
            # Cast to BBNode and recurse
            t_left = bbnode_intersect(node.child_l, ray, t_min)
        else:
            # Leaf node: call primitive intersection
            t_left = child_intersect(node.child_l, ray, t_min)
        
        # Step 4: Precision handling for comparison
        # Add epsilon to left hit distance before comparing
        if t_left != -1:
            if best_t == -1 or (t_left + 0.001f) < best_t:
                best_t = t_left

    # Step 3: Process Right Child
    if node.child_r is not None:
        if node.getType() == NODE:
            # Cast to BBNode and recurse
            t_right = bbnode_intersect(node.child_r, ray, t_min)
        else:
            # Leaf node: call primitive intersection
            t_right = child_intersect(node.child_r, ray, t_min)
        
        # Step 4: Precision handling for comparison
        if t_right != -1:
            if best_t == -1 or (t_right + 0.001f) < best_t:
                best_t = t_right

    return best_t

def intersect_aabb(min_vec, max_vec, ray_O, ray_D):
    """
    Standard AABB-Ray intersection test.
    Returns t_min if intersected, else -1.
    """
    t_min = -1.0
    t_max = float('inf')
    
    for i in range(3):
        if ray_D[i] == 0:
            if ray_O[i] < min_vec[i] or ray_O[i] > max_vec[i]:
                return -1
        else:
            t1 = (min_vec[i] - ray_O[i]) / ray_D[i]
            t2 = (max_vec[i] - ray_O[i]) / ray_D[i]
            if t1 > t2:
                t1, t2 = t2, t1
            
            if t1 > t_min:
                t_min = t1
            if t2 < t_max:
                t_max = t2
            
            if t_min > t_max:
                return -1
                
    if t_max < 0:
        return -1
        
    return t_min if t_min >= 0 else t_max

def child_intersect(scene_object, ray, t_min):
    """
    Placeholder for specific primitive intersection logic.
    Returns distance t or -1.
    """
    # Implementation depends on the specific primitive type (Triangle, Sphere, etc.)
    # This function is defined elsewhere in the scene graph.
    return scene_object.intersect(ray, t_min)
```

**Edge cases and pitfalls:**
- **Floating-point precision:** Direct comparison of hit distances can lead to incorrect culling due to precision errors. The method requires adding `epsilon` (0.001f) to the left hit distance before comparison [S1, unofficial].
- **Degenerate input:** If the ray direction components are zero, the AABB test must handle division by zero by checking if the ray origin is within the slab bounds [S1, unofficial].

## Subtopics

### Hierarchical Bounding Volumes (HBV)
A general tree of bounding volumes where children are contained within their parent, used for acceleration [S2, unofficial]. Unlike the strict binary BBNode, HBV creation preprocess can be derived from the model hierarchy or via automatic clustering [S2, unofficial]. The search algorithm iterates through children if the bounding volume intersects the ray [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(\log N)$ on average for balanced trees, where $N$ is the number of primitives, but degrades to $O(N)$ in worst-case scenarios (e.g., highly unbalanced trees or rays intersecting many nodes).
- **Memory Complexity:** $O(N)$ to store the tree nodes and bounding boxes.
- **Strengths:** Efficiently culls large portions of the scene that do not intersect the ray. Simple to implement for axis-aligned boxes.
- **Limitations:** Performance is sensitive to the quality of the bounding volume hierarchy construction. Poorly constructed trees can lead to excessive node visits. The fixed epsilon value may not be suitable for all scales of geometry.
- **When to use:** Suitable for scenes with static geometry where a binary tree structure is beneficial. Not ideal for highly dynamic scenes without frequent tree rebuilds.

## Background
The method originates from early ray tracing implementations using binary bounding box trees. It is documented in the `cgibson/Mr-Voxel` repository, which provides an unofficial implementation of a ray tracer with voxel and bounding box support [S1, unofficial]. The broader concept of hierarchical bounding volumes is discussed in educational materials on ray tracing acceleration structures [S2, unofficial].
