# Bounding Box Node Intersection

Also called: BBNode::intersect

## Overview
Bounding Box Node Intersection is a recursive ray traversal algorithm for a binary bounding box tree (BBNode) that determines the closest surface intersection by testing the node's bounding box, then recursing into left and right children, and finally comparing hit distances [S1, unofficial]. It solves the problem of efficiently finding the nearest primitive in a hierarchical scene structure by pruning branches whose bounding volumes do not intersect the ray [S1, unofficial]. Unlike [Ray-Object Intersection Test](3604-ray-object-intersection-test.md) which tests a single object, this method navigates a tree structure to find the global minimum intersection distance among all contained primitives.

## How it works
**Inputs and Outputs:**
- Input: A ray $R$ (origin $O$, direction $D$), a pointer to the current `BBNode` root, and a small epsilon constant $\epsilon = 0.001f$ [S1, unofficial].
- Output: The closest intersection distance $t$ along the ray, or a sentinel value (e.g., $-\infty$ or infinity) if no intersection is found within the subtree [S1, unofficial].

**Data Structures:**
The `BBNode` structure contains the following fields [S1, unofficial]:
- `min`: A `Vec3` representing the minimum corner of the axis-aligned bounding box (AABB).
- `max`: A `Vec3` representing the maximum corner of the AABB.
- `child_l`: A pointer to `SceneObject` (left child).
- `child_r`: A pointer to `SceneObject` (right child).
- `getType()`: A method returning an enum indicating if the node is a `NODE` (internal) or a leaf type [S1, unofficial].

**Algorithm Steps:**
1. **Bounding Box Test:** Test if the ray intersects the current node's AABB defined by `min` and `max`. If no intersection occurs, return the "no hit" value [S1, unofficial].
2. **Left Child Recursion:** If the left child (`child_l`) exists, determine its type.
   - If `child_l` is a `NODE` (castable to `BBNode`), recursively call `intersect` on it [S1, unofficial].
   - Otherwise, call the primitive intersection function `child_intersect` on the leaf object [S1, unofficial].
   - Store the resulting distance as $t_{left}$.
3. **Right Child Recursion:** If the right child (`child_r`) exists, perform the same type check and recursion/intersection logic as step 2.
   - Store the resulting distance as $t_{right}$.
4. **Distance Comparison:** Compare $t_{left}$ and $t_{right}$ to find the closest intersection.
   - To handle floating-point precision issues, add $\epsilon$ to $t_{left}$ before comparing [S1, unofficial].
   - If $t_{left} + \epsilon < t_{right}$, return $t_{left}$.
   - Otherwise, return $t_{right}$ [S1, unofficial].

**Pseudocode:**
```python
def bbnode_intersect(ray, node, epsilon=0.001):
    # 1. Bounding Box Test
    # Assuming ray_aabb_intersect returns t_min, t_max or None
    hit = ray_aabb_intersect(ray, node.min, node.max)
    if hit is None:
        return INFINITY

    t_left = INFINITY
    t_right = INFINITY

    # 2. Left Child Recursion
    if node.child_l is not None:
        if node.child_l.getType() == NODE:
            t_left = bbnode_intersect(ray, node.child_l, epsilon)
        else:
            t_left = child_intersect(ray, node.child_l)

    # 3. Right Child Recursion
    if node.child_r is not None:
        if node.child_r.getType() == NODE:
            t_right = bbnode_intersect(ray, node.child_r, epsilon)
        else:
            t_right = child_intersect(ray, node.child_r)

    # 4. Distance Comparison with Epsilon
    # Handle floating-point precision issues
    if t_left + epsilon < t_right:
        return t_left
    else:
        return t_right
```

**Edge Cases and Pitfalls:**
- **Floating-Point Precision:** Direct comparison of hit distances can lead to incorrect pruning due to precision errors. The algorithm explicitly adds $\epsilon$ to the left hit distance before comparison to mitigate this [S1, unofficial].
- **Empty Children:** The algorithm checks for the existence of `child_l` and `child_r` before recursion, handling leaf nodes or incomplete trees gracefully [S1, unofficial].
- **No Intersection:** If neither child intersects, the function must correctly propagate the "no hit" value up the recursion stack [S1, unofficial].

## Subtopics

### [Hierarchical Bounding Volumes (HBV)](13475-hierarchical-bounding-volumes-hbv.md)
Generalizes this node intersection test to arbitrary bounding volumes and hierarchical traversal, adapting to spatial distribution rather than uniform grids.

## Operating characteristics
- **Time Complexity:** $O(\log N)$ on average for balanced trees, where $N$ is the number of primitives, but degrades to $O(N)$ in worst-case scenarios (e.g., highly unbalanced trees or rays intersecting many nodes) [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store the tree structure and bounding boxes [S1, unofficial].
- **Strengths:** Significantly reduces the number of primitive intersection tests compared to brute-force linear search [S1, unofficial].
- **Limitations:** Performance depends heavily on the quality of the bounding volume hierarchy construction [S1, unofficial].
- **When to use:** Ideal for scenes with many static primitives where acceleration structures can be precomputed [S1, unofficial].

## Background
Originating from implementations such as `cgibson/Mr-Voxel`, this method is a fundamental component of ray tracing acceleration structures [S1, unofficial]. It builds on the concept of [Ray-Object Intersection Test](3604-ray-object-intersection-test.md) by applying it recursively within a tree hierarchy [S1, unofficial].
