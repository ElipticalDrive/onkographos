# Heuristic BVH Construction (Top-Down with Plane-Sweep)

Also called: Heuristic Aufbau einer BVH, Top-down BVH construction

## Overview
This method constructs a Bounding Volume Hierarchy (BVH) using a recursive top-down approach that optimizes a cost function based on surface area and object count, rather than seeking the mathematically optimal partition which is computationally infeasible [S1, unofficial]. It distinguishes itself from iterative bottom-up methods by generally yielding better BVH quality, and from exact optimal partitioning by using a heuristic plane-sweep strategy to find a near-optimal split [S1, unofficial]. It builds on [Hierarchical Bounding Volumes (HBV)](13475-hierarchical-bounding-volumes-hbv.md) by computing the bounding volume for a given set of objects before partitioning [S1, unofficial].

## How it works
**Inputs:** A set of $n$ geometric primitives (e.g., triangles) $B$ [S1, unofficial].
**Outputs:** A root node of a BVH tree representing the bounding volume of $B$ [S1, unofficial].

**Data Structures:**
*   **Primitive Representation:** Each primitive is represented by its centroid (center point) $c_i$ [S1, unofficial].
*   **Bounding Volume (BV):** An axis-aligned bounding box (AABB) enclosing a set of primitives [S1, unofficial]. For a single primitive $b_j$, the elementary BV is the bounding box of that primitive [S1, unofficial]. For a set, it is the union of its children's BVs [S1, unofficial].
*   **Cost Function:** A scalar value estimating the rendering cost (e.g., ray intersection probability) [S1, unofficial].

**Algorithm Steps:**

1.  **Calculate Parent BV:** Compute the bounding volume $B$ for the current set of objects [S1, unofficial].
2.  **Base Case / Leaf Check:** If the set contains a single primitive, create a leaf node containing that primitive and return [G].
3.  **Select Split Axis:** Determine the axis (x, y, or z) with the greatest extent (largest dimension) of the current bounding volume $B$ [S1, unofficial].
4.  **Sort Primitives:** Sort the primitives in the current set based on the centroid coordinates along the selected axis [S1, unofficial]. Let the sorted list be $p_1, p_2, \dots, p_n$.
5.  **Plane-Sweep for Optimal Split:**
    *   Initialize the left set bounding box $B_L$ to the elementary BV of $p_1$ [S1, unofficial].
    *   Iterate through split index $j$ from $1$ to $n-1$:
        *   Update $B_L$ to include $p_j$.
        *   Compute the bounding box of the right set $B_R$ (primitives $p_{j+1} \dots p_n$) [S1, unofficial].
        *   Calculate the cost for the split at $j$:
            $$ Cost(j) = \frac{\text{Area}(B_L)}{\text{Area}(B)} \cdot j + \frac{\text{Area}(B_R)}{\text{Area}(B)} \cdot (n-j) $$
            where $\text{Area}(\cdot)$ is the surface area of the bounding box, and $j$ and $n-j$ are the number of objects in the left and right child sets, respectively [S1, unofficial].
        *   Track the minimum cost and the corresponding split index $k$ [S1, unofficial].
        *   *Note:* The formula implies a cost model where the probability of a ray hitting a child is proportional to its surface area relative to the parent, and the cost of traversing that child is proportional to the number of primitives it contains [S1, unofficial].
    *   If multiple splits yield identical minimum costs, apply an alternative heuristic such as the number of triangles in the subtree to break the tie [S1, unofficial].
6.  **Partition:** Split the primitives into two subsets $B_1 = \{p_1, \dots, p_k\}$ and $B_2 = \{p_{k+1}, \dots, p_n\}$ based on the optimal split index $k$ [S1, unofficial].
7.  **Recursive Construction:** Recursively construct the BVH for each of the resulting subsets [S1, unofficial].
8.  **Non-Binary Fallback (Heuristic Check):** If the resulting children nodes result in prohibitively high costs (e.g., the area increase is approximately 90% of the parent's area), attach the primitives directly as children of the current node instead of creating binary children [S1, unofficial]. This allows the BVH to be non-binary.
9.  **Return Node:** Create a node with the bounding volume $B$ and children [S1, unofficial].

**Pseudocode:**

```python
class AABB:
    def __init__(self, min_pt, max_pt):
        self.min = min_pt
        self.max = max_pt

class Node:
    def __init__(self, bv, children):
        self.bv = bv
        self.children = children

def surface_area(aabb):
    dx = aabb.max[0] - aabb.min[0]
    dy = aabb.max[1] - aabb.min[1]
    dz = aabb.max[2] - aabb.min[2]
    return 2.0 * (dx * dy + dy * dz + dz * dx)

def union(aabb1, aabb2):
    return AABB(
        (min(aabb1.min[0], aabb2.min[0]), min(aabb1.min[1], aabb2.min[1]), min(aabb1.min[2], aabb2.min[2])),
        (max(aabb1.max[0], aabb2.max[0]), max(aabb1.max[1], aabb2.max[1]), max(aabb1.max[2], aabb2.max[2]))
    )

def compute_bv(primitives):
    if not primitives:
        return AABB((0,0,0), (0,0,0))
    min_pt = (min(p.centroid[0] for p in primitives), min(p.centroid[1] for p in primitives), min(p.centroid[2] for p in primitives))
    max_pt = (max(p.centroid[0] for p in primitives), max(p.centroid[1] for p in primitives), max(p.centroid[2] for p in primitives))
    return AABB(min_pt, max_pt)

def build_bvh_top_down(primitives):
    if not primitives:
        return None
    parent_bv = compute_bv(primitives)
    if len(primitives) == 1:
        return Node(parent_bv, primitives)

    extent = (parent_bv.max[0] - parent_bv.min[0], parent_bv.max[1] - parent_bv.min[1], parent_bv.max[2] - parent_bv.min[2])
    axis = extent.index(max(extent))

    sorted_primitives = sorted(primitives, key=lambda p: p.centroid[axis])
    n = len(sorted_primitives)

    # Precompute right BVs for O(1) access during sweep
    right_bvs = [None] * (n + 1)
    right_bvs[n] = AABB((float('inf'),)*3, (float('-inf'),)*3)
    for i in range(n - 1, -1, -1):
        right_bvs[i] = union(right_bvs[i+1], compute_bv([sorted_primitives[i]]))

    left_bv = compute_bv([sorted_primitives[0]])
    right_bv = right_bvs[1]
    min_cost = float('inf')
    best_k = -1
    parent_area = surface_area(parent_bv)

    for j in range(1, n):
        cost = (surface_area(left_bv) / parent_area) * j + (surface_area(right_bv) / parent_area) * (n - j)
        if cost < min_cost:
            min_cost = cost
            best_k = j
        if j < n - 1:
            left_bv = union(left_bv, compute_bv([sorted_primitives[j]]))
            right_bv = right_bvs[j+1]

    # Fallback: attach directly if area increase is ~90% of parent area
    if (surface_area(left_bv) + surface_area(right_bv)) > 0.9 * parent_area:
        return Node(parent_bv, sorted_primitives)

    left_primitives = sorted_primitives[:best_k]
    right_primitives = sorted_primitives[best_k:]

    left_child = build_bvh_top_down(left_primitives)
    right_child = build_bvh_top_down(right_primitives)

    return Node(parent_bv, [left_child, right_child])
```

## Operating characteristics
*   **Time Complexity:** $O(n \log^2 n)$, derived from the recurrence $T(n) = T(\alpha n) + T((1-\alpha)n) + O(n \log n)$ [S1, unofficial]. The $O(n \log n)$ term comes from sorting the primitives at each node [S1, unofficial].
*   **Memory Complexity:** Not given in the sources [S1, unofficial].
*   **Performance:** Top-down methods generally yield better BVHs than iterative methods [S1, unofficial].
*   **Strengths:** Heuristic approach is computationally feasible compared to exact optimal partitioning [S1, unofficial].
*   **Limitations:** The mathematically optimal partition is not practical, so this method is a heuristic approximation [S1, unofficial].
*   **When to use:** When a good quality BVH is needed and $O(n \log^2 n)$ is acceptable [S1, unofficial].
*   **When not to use:** When exact optimal partitioning is required (infeasible) or when $O(n \log n)$ is strictly required (consider SAH or other methods) [S1, unofficial].
