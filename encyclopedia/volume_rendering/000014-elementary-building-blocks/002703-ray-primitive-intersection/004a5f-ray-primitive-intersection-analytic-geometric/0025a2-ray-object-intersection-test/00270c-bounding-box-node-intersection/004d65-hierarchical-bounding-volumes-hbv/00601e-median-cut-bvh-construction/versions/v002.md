# Median Cut BVH Construction

Also called: Median Cut BVH, Median Split BVH Construction

## Overview
Median Cut BVH Construction is a top-down heuristic method for building a Bounding Volume Hierarchy (BVH) by recursively partitioning a set of primitives based on their spatial centroids [S1, unofficial]. It solves the problem of organizing geometry for efficient ray-primitive intersection by creating a balanced binary tree [G]. It is distinguished from [Heuristic BVH Construction (Top-Down with Plane-Sweep)](18008-heuristic-bvh-construction-top-down-with-plane-sweep.md) by its simplicity and deterministic partitioning via sorting, rather than optimizing surface area or using plane-sweep algorithms [G]. It builds on [Hierarchical Bounding Volumes (HBV)](13475-hierarchical-bounding-volumes-hbv.md) [S1, unofficial].

## How it works
**Inputs:** A list of $N$ primitives, each with an associated bounding volume (BV) and a centroid position [S1, unofficial].
**Outputs:** A BVH tree structure where leaf nodes contain a subset of primitives and internal nodes contain bounding volumes enclosing their children [G].

**Data Structures:**
*   `Primitive`: Contains a bounding box (min, max) and a centroid (center point).
*   `BBox`: Contains `min` and `max` vectors.
*   `LeafNode`: Contains a bounding box and a list of primitives.
*   `InternalNode`: Contains a bounding box, a left child, and a right child.

**Steps:**
1. **Construct BV:** Create a bounding volume enclosing all objects in the current set [S1, unofficial].
2. **Select Axis:** Choose an axis ($x, y,$ or $z$) for partitioning [S1, unofficial].
    *   *Variant A:* Cyclically choose a different axis on each level [S1, unofficial].
    *   *Variant B:* Choose the axis with the longest extent [S1, unofficial].
3. **Sort:** Sort all objects according to their center along the selected axis [S1, unofficial].
4. **Partition:** Partition the scene along the median on the selected axis; assign half of the objects to the left and right subtrees [S1, unofficial].
5. **Recurse:** Repeat steps 1-4 recursively [S1, unofficial].
6. **Terminate:** Stop recursion when a node contains less than $n$ objects [S1, unofficial].

**Formulas:**
*   Centroid: $C = \frac{B_{\min} + B_{\max}}{2}$ [G].
*   Median split index: $m = \lfloor N/2 \rfloor$ [G].
*   Left subset: primitives $[0, m-1]$.
*   Right subset: primitives $[m, N-1]$.

**Parameters:**
*   $n$: Leaf node size threshold. Not given in the sources.

**Edge Cases:**
*   **Degenerate Input:** If all primitives have identical centroids, sorting order is arbitrary [G].
*   **Precision:** Sorting stability may affect tree balance if centroids are identical [G]. Use a stable sort or secondary key (e.g., primitive ID) to ensure deterministic behavior [G].

**Pseudocode:**
```python
def compute_union_bbox(bboxes):
    min_coord = min(b.min for b in bboxes)
    max_coord = max(b.max for b in bboxes)
    return BBox(min_coord, max_coord)

class BBox:
    def __init__(self, min, max):
        self.min = min
        self.max = max

class LeafNode:
    def __init__(self, primitives):
        self.bbox = compute_union_bbox([p.bbox for p in primitives])
        self.primitives = primitives

class InternalNode:
    def __init__(self, bbox, left, right):
        self.bbox = bbox
        self.left = left
        self.right = right

def median_cut_bvh(primitives, depth=0, leaf_threshold=2):
    if len(primitives) <= leaf_threshold:
        return LeafNode(primitives)

    current_bbox = compute_union_bbox([p.bbox for p in primitives])

    # Variant A: Cyclically choose axis
    axis = depth % 3
    # Variant B: Choose axis with longest extent
    # extents = current_bbox.max - current_bbox.min
    # axis = max(range(3), key=lambda i: extents[i])

    sorted_primitives = sorted(primitives, key=lambda p: p.centroid[axis])

    mid = len(sorted_primitives) // 2
    left_primitives = sorted_primitives[:mid]
    right_primitives = sorted_primitives[mid:]

    left_child = median_cut_bvh(left_primitives, depth + 1, leaf_threshold)
    right_child = median_cut_bvh(right_primitives, depth + 1, leaf_threshold)

    internal_bbox = compute_union_bbox([left_child.bbox, right_child.bbox])
    return InternalNode(internal_bbox, left_child, right_child)
```

## Subtopics

### BVH Construction from Triangle Soup
This variant handles raw triangle soup input (vertex and index arrays) before applying the median cut recursion [S2, unofficial]. It involves an initial preprocessing step to convert raw indices into a primitive array with explicit vertex references and type tags [S2, unofficial]. The steps are: calculate `trinum = idxnum / 3`; create a primitive array `prim` of size `trinum`; loop `i` from `0` to `trinum-1` and `j` from `0` to `2`; set `prim[i].v[j] = v[idx[3*i+j]]`; set `prim[i].type = primitive::TRI`; create an intersector from `prim` and `trinum`; delete `prim` [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(N \log N)$ per level due to sorting, leading to $O(N \log^2 N)$ total construction time for a balanced tree [G].
**Memory Complexity:** $O(N)$ for storing the tree nodes and primitive lists [G].
**Performance:** Fast to implement and predictably balanced. However, it does not optimize for ray traversal efficiency (e.g., SAH), so the resulting BVH may have more overlap and lower traversal performance compared to [Heuristic BVH Construction (Top-Down with Plane-Sweep)](18008-heuristic-bvh-construction-top-down-with-plane-sweep.md) [G].
**Strengths:** Simplicity, deterministic output, good balance [G].
**Limitations:** Suboptimal tree quality for ray tracing; sensitive to centroid distribution [G].
**When to use:** When construction speed is critical and traversal performance is secondary, or for debugging/prototyping [G].
**When not to use:** For high-performance ray tracing where BVH quality directly impacts frame rate [G].

## Background
Originated as a simple heuristic for top-down BVH construction in computer graphics. It is described in lecture materials for Advanced Computer Graphics by G. Zachmann [S1, unofficial]. It is a variant of the general Median Cut algorithm applied to spatial partitioning [G].
