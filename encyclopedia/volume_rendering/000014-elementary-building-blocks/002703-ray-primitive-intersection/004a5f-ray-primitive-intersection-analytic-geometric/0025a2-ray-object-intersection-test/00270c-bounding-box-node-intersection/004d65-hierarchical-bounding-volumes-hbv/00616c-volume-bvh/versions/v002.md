# Volume BVH
Also called: Volume Bounding Volume Hierarchy, Scene-level Volume BVH
## Overview
Volume BVH is a hierarchical acceleration structure for volume rendering that handles multiple objects, instances, and transformations by using bounding boxes to quickly identify which volume instances overlap a given ray segment [S1, unofficial]. It solves the problem of efficiently determining which potentially transformed or instanced volume sources contribute to a specific ray, serving as a coarse-level filter before detailed voxel traversal [S1, unofficial]. It sets itself apart from sibling methods by focusing on the scene-level management of multiple distinct volume objects and instances, rather than optimizing the construction of a single object's hierarchy or handling specific primitive types like Gaussian surfels [S1, unofficial][G].
## Shared principles
The family relies on a tree of axis-aligned bounding boxes (AABBs) where each node contains a bounding volume enclosing its children [S1, unofficial]. The traversal mechanism follows these steps: first, construct a BVH using the bounding boxes of each object to find instances overlapping a ray segment from point A to B [S1, unofficial]. Second, gather the list of overlapping objects into an array in the kernel before volume shading begins [S1, unofficial]. Third, optionally refine the BVH by replacing full object bounding boxes with inner or leaf node bounding boxes to reduce false positives [S1, unofficial]. Fourth, optionally extend traversal down to the voxel level using an algorithm like HDDA [S1, unofficial]. Key shared properties include storing AABBs in nodes, robustly detecting overlap for rotated, scaled, or instanced objects, and operating orthogonally to internal voxel traversal [S1, unofficial].

## Background
The concept was proposed for Blender's Cycles renderer to optimize volume stepping and replace or augment the current `shade_volume` kernel logic [S1, unofficial]. It addresses the limitation of existing tree structures like OpenVDB or NanoVDB, which store volumes hierarchically but lack scene-level instance overlap detection for transformed or instanced objects [S1, unofficial].
