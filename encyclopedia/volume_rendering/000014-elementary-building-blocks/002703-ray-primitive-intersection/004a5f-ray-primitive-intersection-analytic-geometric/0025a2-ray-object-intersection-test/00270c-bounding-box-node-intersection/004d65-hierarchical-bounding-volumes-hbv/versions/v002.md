# Hierarchical Bounding Volumes (HBV)
Also called: Bounding Volume Hierarchy, BVH
## Overview
Hierarchical Bounding Volumes (HBV) is a spatial acceleration structure used in ray tracing to reduce the number of primitive intersection tests by organizing geometry into a tree of nested bounding volumes [S1, unofficial]. It solves the problem of $O(N)$ linear search complexity for ray-primitive intersection by enabling $O(\log N)$ traversal, provided the tree is balanced and tight [S1, unofficial]. Unlike flat acceleration structures like Uniform Grids or Hashed Grids, HBV explicitly maintains a hierarchy where children are strictly contained within their parent, allowing early rejection of entire subtrees [S1, unofficial]. It differs from [Bounding Box Node Intersection](3958-bounding-box-node-intersection.md) in that HBV is the general algorithmic framework for any bounding volume hierarchy, whereas the parent article describes a specific recursive traversal implementation for binary bounding box trees.

## How it works
**Inputs and Outputs:**
- Input: A ray $r(t) = o + t \cdot d$, a root node of the HBV tree, and a list of hits.
- Output: A list of intersection points or primitive IDs sorted by distance $t$.

**Data Structures:**
The tree consists of nodes. Each node contains:
- `bound`: A bounding volume (e.g., AABB) enclosing all primitives in the subtree.
- `is_leaf`: Boolean flag indicating if the node contains primitives or children.
- `prims`: List of primitives (if leaf).
- `children`: List of child nodes (if internal).

**Algorithm Steps:**
1. **Traversal:** Start at the root node.
2. **Intersection Test:** Check if the ray intersects the current node's bounding volume.
   - If no intersection, prune this branch.
   - If intersection, proceed.
3. **Leaf Check:**
   - If the node is a leaf, test the ray against all primitives in `prims` and record hits.
   - If the node is internal, recursively call the intersection function on each child.
4. **Ordering:** For correct closest-hit determination, children should be visited in order of increasing distance from the ray origin, or hits should be sorted after traversal [S1, unofficial].

**Pseudocode:**
```python
def intersect(node, ray, hits):
    # Check if ray intersects the node's bounding volume
    if not intersectp(node.bound, ray):
        return
    
    # If leaf, test primitives
    if node.is_leaf:
        for prim in node.prims:
            hit = intersect_primitive(prim, ray)
            if hit is not None:
                hits.append(hit)
    else:
        # Recurse into children
        # Note: For optimal performance, children should be sorted by distance
        # along the ray before iteration, but the basic algorithm iterates all.
        for child in node.children:
            intersect(child, ray, hits)
```

**Parameters and Edge Cases:**
- **Tree Construction:** Can be derived from a model hierarchy or via automatic clustering (e.g., SAH - Surface Area Heuristic) [S1, unofficial].
- **Precision:** Floating-point precision errors in bounding volume tests can cause missed intersections or infinite recursion if not handled with epsilon guards [G].
- **Degenerate Input:** Empty nodes or zero-volume primitives should be handled during construction to prevent division by zero in SAH calculations [G].

## Subtopics

### [BVH for Gaussian Surfels](17858-bvh-for-gaussian-surfels.md)
Accelerates indirect illumination for Gaussian splatting by treating Gaussians as ellipsoidal surfels in a BVH. It enables true inverse rendering by tracing rays through the 3D Gaussian field, unlike standard rasterization-based splatting.

## Operating characteristics
- **Time Complexity:** Average case $O(\log N)$ for balanced trees with tight bounds; worst case $O(N)$ for degenerate trees. Construction is typically $O(N \log N)$ or $O(N)$ depending on the algorithm.
- **Memory Complexity:** $O(N)$ for storing the tree structure and bounding volumes.
- **Strengths:** Excellent for static scenes with high draw call counts; flexible bounding volumes (AABB, OBB, K-DOP).
- **Limitations:** Construction cost is high; updates are expensive for dynamic scenes unless using dynamic BVH variants. Performance degrades if bounding volumes are loose.
- **When to Use:** Static or slowly changing scenes with complex geometry.
- **When Not to Use:** Highly dynamic scenes with frequent geometry changes (consider GPU-based dynamic BVH or other structures).

## Background
HBV is a fundamental concept in ray tracing acceleration, popularized by researchers such as Kaplan, Arvo, and Jansen [S1, unofficial]. It represents a compromise between hierarchical grids and other acceleration structures, favored by many practitioners for its balance of performance and implementation complexity. The technique is widely used in offline renderers and increasingly in real-time ray tracing.
