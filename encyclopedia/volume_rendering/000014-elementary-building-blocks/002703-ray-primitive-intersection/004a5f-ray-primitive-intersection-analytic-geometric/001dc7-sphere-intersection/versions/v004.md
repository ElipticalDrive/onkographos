# Sphere Intersection
Also called: Ray-Marching: Sphere Intersection and Path Calculation, Ray-Sphere Intersection for Volume Rendering, Volumetric Sphere Rendering

## Overview
Sphere Intersection is a method to render a volumetric sphere by intersecting camera rays with the sphere geometry to determine entry and exit points, then applying Beer's Law along the chord length [S1, unofficial]. It calculates the entry and exit $t$-values for a ray intersecting a sphere, returning large sentinel values if no intersection occurs [S2, unofficial]. Unlike [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) which handles discrete surfaces, this method computes the path length through a participating medium to determine transmittance and scattered light contribution [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (typically normalized), sphere center $\mathbf{c}$, sphere radius $r$.
- **Output**: Intersection distance $t$ (smallest positive $t$ for closest hit) or entry/exit $t$-values ($t_{min}, t_{max}$) for chord calculation. If no intersection, returns a sentinel value indicating failure.

**Data Structures**
- Ray: Struct containing `origin` (vec3) and `direction` (vec3).
- Sphere: Struct containing `center` (vec3) and `radius` (float).

**Steps**
1.  **Vector Calculation**: Compute the vector from the ray origin to the sphere center: $\mathbf{l} = \mathbf{c} - \mathbf{o}$ [S3, unofficial]. Alternatively, compute $\mathbf{oc} = \mathbf{c} - \mathbf{o}$ [S4, unofficial] or $\mathbf{dist} = \mathbf{o} - \mathbf{c}$ [S5, unofficial].
2.  **Quadratic Coefficients**: Solve the quadratic equation derived from the sphere implicit function $\|\mathbf{o} + t\mathbf{d} - \mathbf{c}\|^2 = r^2$.
    -   Using $\mathbf{l} = \mathbf{c} - \mathbf{o}$:
        -   $A = \mathbf{d} \cdot \mathbf{d}$
        -   $B = 2.0 \cdot (\mathbf{l} \cdot \mathbf{d})$
        -   $C = (\mathbf{l} \cdot \mathbf{l}) - r^2$
    -   Using $\mathbf{oc} = \mathbf{c} - \mathbf{o}$ (as in [S4, unofficial]):
        -   $a = \mathbf{d} \cdot \mathbf{d}$
        -   $h = \mathbf{d} \cdot \mathbf{oc}$
        -   $c = (\mathbf{oc} \cdot \mathbf{oc}) - r^2$
        -   Discriminant $d = h^2 - a \cdot c$
    -   Using $\mathbf{r0} = \mathbf{o} - \mathbf{c}$ (as in [S2, unofficial], sphere at origin relative to ray):
        -   $a = \mathbf{d} \cdot \mathbf{d}$
        -   $b = \mathbf{d} \cdot \mathbf{r0}$
        -   $c = (\mathbf{r0} \cdot \mathbf{r0}) - r^2$
        -   Discriminant $d = b^2 - 4ac$
3.  **Discriminant Check**:
    -   If $d < 0$, there is no intersection. Return a sentinel value (e.g., `nullopt`, large positive/negative floats) [S2, unofficial][S4, unofficial].
    -   If $d \ge 0$, calculate roots.
4.  **Root Calculation**:
    -   Using coefficients $A, B, C$:
        -   $t_1 = \frac{-B - \sqrt{d}}{2A}$
        -   $t_2 = \frac{-B + \sqrt{d}}{2A}$
    -   Using coefficients $a, h, c$ (where $d = h^2 - ac$):
        -   $t = \frac{h - \sqrt{d}}{a}$ (entry)
        -   $t = \frac{h + \sqrt{d}}{a}$ (exit)
    -   Using coefficients $a, b, c$ (where $d = b^2 - 4ac$):
        -   $t_{entry} = \frac{-b - \sqrt{d}}{2a}$
        -   $t_{exit} = \frac{-b + \sqrt{d}}{2a}$
5.  **Validity Check**:
    -   If both $t_1$ and $t_2$ are negative, the sphere is behind the ray origin. Return no intersection [S3, unofficial].
    -   If only one is positive, the ray origin is inside the sphere; use the positive $t$ as the exit point (or entry if considering back-face, but typically exit for volume rendering entry is handled by checking if $t_{min} < 0$) [S5, unofficial].
    -   For volume rendering, we typically need the chord length. If the ray enters the sphere, $t_{min}$ is the entry point and $t_{max}$ is the exit point. If $t_{min} < 0 < t_{max}$, the ray starts inside, and the chord length is $t_{max} - 0$ (or just $t_{max}$ if measuring from origin). However, standard implementation often returns the smallest positive $t$ for closest hit [S3, unofficial] or both $t$ values for chord calculation [S1, unofficial][S2, unofficial].
6.  **Chord Length**: Compute the distance the ray travels through the sphere: $L = |t_{max} - t_{min}|$ [S1, unofficial]. Note: If the ray origin is inside, $L = t_{max}$ (assuming $t_{min} < 0$).
7.  **Beer's Law**: Apply Beer's Law using the chord length $L$ and density $\rho$ to determine transmittance $T = e^{-\rho L}$ [S1, unofficial].
8.  **Scattering**: Assume uniform scattered light from the sphere and blend with the transmitted background [S1, unofficial].

**Pseudocode**
```python
import math

def ray_sphere_intersection(ray_origin, ray_direction, sphere_center, sphere_radius):
    """
    Intersects a ray with a sphere.
    Returns (t_min, t_max) if intersection occurs, else None.
    t_min is the entry point, t_max is the exit point.
    """
    # Vector from ray origin to sphere center
    oc_x = sphere_center.x - ray_origin.x
    oc_y = sphere_center.y - ray_origin.y
    oc_z = sphere_center.z - ray_origin.z
    
    # Quadratic coefficients: a*t^2 + b*t + c = 0
    # Derived from ||ray_origin + t*ray_direction - sphere_center||^2 = radius^2
    # Let l = sphere_center - ray_origin
    # a = dot(d, d)
    # b = 2 * dot(l, d)
    # c = dot(l, l) - r^2
    
    a = (ray_direction.x * ray_direction.x +
         ray_direction.y * ray_direction.y +
         ray_direction.z * ray_direction.z)
         
    b = 2.0 * ((oc_x * ray_direction.x) +
               (oc_y * ray_direction.y) +
               (oc_z * ray_direction.z))
               
    c = (oc_x * oc_x + oc_y * oc_y + oc_z * oc_z) - (sphere_radius * sphere_radius)
    
    # Discriminant
    discriminant = (b * b) - (4.0 * a * c)
    
    if discriminant < 0.0:
        return None
        
    sqrt_disc = math.sqrt(discriminant)
    
    # Calculate t values
    # t1 = (-b - sqrt(d)) / 2a
    # t2 = (-b + sqrt(d)) / 2a
    
    t1 = (-b - sqrt_disc) / (2.0 * a)
    t2 = (-b + sqrt_disc) / (2.0 * a)
    
    # Ensure t_min is the smaller value
    if t1 > t2:
        t_min = t2
        t_max = t1
    else:
        t_min = t1
        t_max = t2
        
    # If both t are negative, the sphere is behind the ray
    if t_max < 0.0:
        return None
        
    # If t_min is negative, the ray origin is inside the sphere.
    # For volume rendering, we might still want the exit point t_max.
    # However, standard intersection often returns the closest positive t.
    # For chord length calculation in volume rendering, we need the segment inside.
    # If t_min < 0, the entry is effectively at t=0 (ray origin), so chord is t_max.
    # If t_min >= 0, chord is t_max - t_min.
    
    return (t_min, t_max)

def compute_transmittance(t_min, t_max, density):
    """
    Computes transmittance using Beer's Law.
    T = exp(-density * chord_length)
    """
    if t_min is None:
        return 1.0 # No intersection, full transmission of background
        
    # Chord length
    # If ray starts inside (t_min < 0), the path through volume is t_max - 0
    # If ray starts outside, path is t_max - t_min
    if t_min < 0.0:
        chord_length = t_max
    else:
        chord_length = t_max - t_min
        
    # Beer's Law
    transmittance = math.exp(-density * chord_length)
    return transmittance
```

**Parameters**
- **EPS**: Epsilon value used for normal calculation and offsetting, typically 0.0001 [S5, unofficial].
- **Density**: Uniform particle density assumed for the sphere [S1, unofficial].

**Edge Cases and Pitfalls**
- **No Intersection**: If discriminant $< 0$, return sentinel values (e.g., `1e2, -1e5`) [S2, unofficial].
- **Ray Behind Sphere**: If both $t$ values are negative, the sphere is behind the ray origin. Return false/no intersection [S3, unofficial].
- **Ray Origin Inside**: If $t_{min} < 0 < t_{max}$, the ray originates inside the sphere. The chord length is $t_{max}$ (distance to exit) [S1, unofficial].
- **Tangential Intersection**: If discriminant $= 0$, the ray is tangent to the sphere. $t_{min} = t_{max}$. Chord length is 0.
- **Shadow Ignorance**: This specific implementation ignores shadows cast by objects outside or inside the volume [S1, unofficial].
- **Varying Densities**: This specific implementation assumes uniform density and does not handle varying densities [S1, unofficial].

## Subtopics

### Billboard Sphere Projection
A technique to render a 3D sphere as a 2D billboard by calculating a spherical contribution factor based on the fragment's distance from the center [S6, unofficial]. It calculates `sphereContrib = sqrt(max(0, 1 - (distance(center, fragPos)/radius)^2))` [S6, unofficial]. If `showQuad` is true, it sets color to `vec4(sphereContrib)` and discards fragments near edges (`< 0.01` or `> 0.99`) [S6, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per ray, as it involves a fixed number of arithmetic operations (dot products, square root).
- **Memory Complexity**: $O(1)$, requiring only local variables for ray and sphere parameters.
- **Performance**: Extremely fast due to the simplicity of the quadratic formula. Suitable for real-time rendering and GPU parallel execution [G].
- **Strengths**: Analytical solution, no iteration required, robust for simple volumetric spheres.
- **Limitations**: Only applies to spheres. Does not handle complex geometries or varying densities without extension [S1, unofficial]. Ignores shadows and inter-volume scattering [S1, unofficial].

## Background
Originating from basic ray tracing techniques, sphere intersection is a fundamental building block for volume rendering. It is widely used in introductory volume rendering tutorials to demonstrate the application of Beer's Law [S1, unofficial]. The method is implemented in various educational and open-source projects, including Shadertoy examples [S2, unofficial], Rust-based raytracers [S3, unofficial], and WebGL implementations [S5, unofficial]. The billboard variant is used in cloud rendering for efficient sprite-based volume approximation [S6, unofficial].
