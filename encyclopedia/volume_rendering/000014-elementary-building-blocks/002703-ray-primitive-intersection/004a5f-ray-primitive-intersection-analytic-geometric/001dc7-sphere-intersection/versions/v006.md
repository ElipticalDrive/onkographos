# Sphere Intersection
Also called: Ray-Marching: Sphere Intersection and Path Calculation, Ray-Sphere Intersection for Volume Rendering, Volumetric Sphere Rendering

## Overview
Sphere Intersection is a method to render a volumetric sphere by intersecting camera rays with the sphere geometry to determine entry and exit points, then applying Beer's Law along the chord length [S1, unofficial]. It calculates the entry and exit $t$-values for a ray intersecting a sphere, returning sentinel values if no intersection occurs [S2, unofficial]. Unlike [Ray-Triangle Intersection](11312-ray-triangle-intersection.md) which handles discrete surfaces, this method computes the path length through a participating medium to determine transmittance and scattered light contribution [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (typically normalized), sphere center $\mathbf{c}$, sphere radius $r$ [S5, unofficial].
- **Output**: Entry and exit $t$-values ($t_{min}, t_{max}$) for chord calculation, or the smallest positive $t$ for the closest hit [S1, unofficial][S3, unofficial]. If no intersection occurs, returns a sentinel value indicating failure [S2, unofficial][S4, unofficial].

**Data Structures**
- Ray: Struct containing `origin` (vec3) and `direction` (vec3) [G].
- Sphere: Struct containing `center` (vec3) and `radius` (float) [G].

**Steps**
1. **Vector Calculation**: Compute the vector from the sphere center to the ray origin: $\mathbf{l} = \mathbf{o} - \mathbf{c}$ [S5, unofficial].
2. **Quadratic Coefficients**: Solve the quadratic equation derived from the sphere implicit function $\|\mathbf{o} + t\mathbf{d} - \mathbf{c}\|^2 = r^2$ [S5, unofficial].
   - $A = \mathbf{d} \cdot \mathbf{d}$
   - $B = 2.0 \cdot (\mathbf{l} \cdot \mathbf{d})$ [S5, unofficial]
   - $C = (\mathbf{l} \cdot \mathbf{l}) - r^2$ [S5, unofficial]
3. **Discriminant Check**: Compute $d = B^2 - 4AC$. If $d < 0$, there is no intersection. Return a sentinel value (e.g., `None`, `nullopt`, or large floats) [S2, unofficial][S4, unofficial].
4. **Root Calculation**: Compute $\sqrt{d}$. Calculate $t_1 = \frac{-B - \sqrt{d}}{2A}$ and $t_2 = \frac{-B + \sqrt{d}}{2A}$ [S5, unofficial].
5. **Validity Check**: If both $t_1$ and $t_2$ are negative, the sphere is behind the ray origin. Return no intersection [S3, unofficial]. For volume rendering, $t_{min} = \min(t_1, t_2)$ is the entry point and $t_{max} = \max(t_1, t_2)$ is the exit point [S1, unofficial].
6. **Chord Length**: Compute the distance the ray travels through the sphere: $L = t_{max} - t_{min}$ [S1, unofficial]. If $t_{min} < 0 < t_{max}$, the ray starts inside the sphere, and the chord length is $t_{max}$ [S1, unofficial].
7. **Beer's Law**: Apply Beer's Law using the chord length $L$ and uniform density $\rho$ to determine transmittance $T = e^{-\rho L}$ [S1, unofficial].
8. **Scattering**: Assume uniform scattered light from the sphere and blend with the transmitted background [S1, unofficial].

**Pseudocode**
```python
import math

def ray_sphere_intersection(ray_origin, ray_direction, sphere_center, sphere_radius):
    # Vector from sphere center to ray origin
    l_x = ray_origin.x - sphere_center.x
    l_y = ray_origin.y - sphere_center.y
    l_z = ray_origin.z - sphere_center.z

    # Quadratic coefficients: A*t^2 + B*t + C = 0
    A = (ray_direction.x * ray_direction.x +
         ray_direction.y * ray_direction.y +
         ray_direction.z * ray_direction.z)

    B = 2.0 * ((l_x * ray_direction.x) +
               (l_y * ray_direction.y) +
               (l_z * ray_direction.z))

    C = (l_x * l_x + l_y * l_y + l_z * l_z) - (sphere_radius * sphere_radius)

    # Discriminant
    discriminant = (B * B) - (4.0 * A * C)

    if discriminant < 0.0:
        return None

    sqrt_disc = math.sqrt(discriminant)

    # Calculate t values
    t1 = (-B - sqrt_disc) / (2.0 * A)
    t2 = (-B + sqrt_disc) / (2.0 * A)

    # Ensure t_min is the smaller value
    if t1 > t2:
        t_min = t2
        t_max = t1
    else:
        t_min = t1
        t_max = t2

    # If both t are negative, the sphere is behind the ray
    if t_max < 0.0:
        return None

    return (t_min, t_max)

def compute_transmittance(t_min, t_max, density):
    if t_min is None:
        return 1.0

    # Chord length calculation
    if t_min < 0.0:
        chord_length = t_max
    else:
        chord_length = t_max - t_min

    # Beer's Law
    transmittance = math.exp(-density * chord_length)
    return transmittance
```

**Parameters**
- **EPS**: Epsilon value used for normal calculation and offsetting, typically 0.0001 [S5, unofficial].
- **Density**: Uniform particle density assumed for the sphere [S1, unofficial].

**Edge Cases and Pitfalls**
- **No Intersection**: If discriminant $< 0$, return sentinel values (e.g., `1e2, -1e5`) [S2, unofficial].
- **Ray Behind Sphere**: If both $t$ values are negative, the sphere is behind the ray origin. Return false/no intersection [S3, unofficial].
- **Ray Origin Inside**: If $t_{min} < 0 < t_{max}$, the ray originates inside the sphere. The chord length is $t_{max}$ (distance to exit) [S1, unofficial].
- **Tangential Intersection**: If discriminant $= 0$, the ray is tangent to the sphere. $t_{min} = t_{max}$. Chord length is 0 [G].
- **Shadow Ignorance**: This specific implementation ignores shadows cast by objects outside or inside the volume [S1, unofficial].
- **Varying Densities**: This specific implementation assumes uniform density and does not handle varying densities [S1, unofficial].

## Subtopics

### Billboard Sphere Projection
A technique to render a 3D sphere as a 2D billboard by calculating a spherical contribution factor based on the fragment's distance from the center [S6, unofficial]. It calculates `sphereContrib = distance(center, fragPos)/radius`, then `sphereContrib = sqrt(max(0, 1 - sphereContrib * sphereContrib))` [S6, unofficial]. If `showQuad` is true, it sets color to `vec4(sphereContrib)` and discards fragments near edges (`< 0.01` or `> 0.99`) [S6, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per ray, as it involves a fixed number of arithmetic operations (dot products, square root) [G].
- **Memory Complexity**: $O(1)$, requiring only local variables for ray and sphere parameters [G].
- **Performance**: Extremely fast due to the simplicity of the quadratic formula, making it suitable for real-time rendering and GPU parallel execution [G].
- **Strengths**: Analytical solution, no iteration required, and robust for simple volumetric spheres [G].
- **Limitations**: Only applies to spheres, does not handle complex geometries or varying densities without extension [S1, unofficial], and ignores shadows and inter-volume scattering [S1, unofficial].

## Background
Originating from basic ray tracing techniques, sphere intersection is a fundamental building block for volume rendering [G]. It is widely used in introductory volume rendering tutorials to demonstrate the application of Beer's Law [S1, unofficial]. The algorithm appears in educational tutorials [S1, unofficial], Shadertoy examples [S2, unofficial], Rust-based raytracers [S3, unofficial], and WebGL implementations [S5, unofficial]. The billboard variant is used in cloud rendering for efficient sprite-based volume approximation [S6, unofficial].
