# Ray Subtraction

Also called: RaySubstraction

## Overview
Ray Subtraction is a boolean operation that removes material from a target ray (Ray A) using a source ray (Ray B) [S1]. It solves the problem of sculpting or editing volumetric data by defining the region to be removed via a second set of samples. It differs from [Ray Union](13991-region-nesting-merge.md) by inverting the normals of the source samples before merging, which effectively flips the inside/outside logic for the subtracted volume, allowing inner regions to be identified and excised by the subsequent [MergeRegion](13991-region-nesting-merge.md) step.

## How it works
**Inputs:**
*   `Ray A`: The target ray containing the list of samples to be modified.
*   `Ray B`: The source ray defining the material to be removed.

**Outputs:**
*   `Ray A`: Modified such that the volume defined by `Ray B` is subtracted from `Ray A`.

**Data Structures:**
*   `Ray.list`: A list of samples. Each sample `s` contains at least:
    *   `z`: The depth coordinate along the ray (used for sorting).
    *   `normal`: A vector indicating the surface orientation at the sample point.
    *   `direction`: The ray's propagation direction vector (used in `MergeRegion`).

**Algorithm:**
1.  Iterate through each sample `s` in `Ray B.list`.
2.  Negate the normal of sample `s`: $s.normal \leftarrow -s.normal$.
3.  Append the modified sample `s` to `Ray A.list`.
4.  Sort `Ray A.list` in ascending order by the sample's `z` value.
5.  Call `MergeRegion(Ray A)` to remove inner regions based on the nesting level logic [S1].

**Pseudocode:**
```python
def RaySubstraction(Ray A, Ray B):
    # Step 1-3: Invert normals and merge samples
    for s in B.list:
        s.normal = -s.normal
        A.list.append(s)
    
    # Step 4: Sort by depth
    # Assuming standard sort on the 'z' attribute of samples
    A.list.sort(key=lambda sample: sample.z)
    
    # Step 5: Remove inner regions
    MergeRegion(A)
```

**MergeRegion Logic (Required Context):**
The `MergeRegion` procedure, called in Step 5, tracks a nesting `level` initialized to 0. It iterates through `R.list` (the sorted list of `Ray A`):
*   If $Dot(s.normal, R.direction) < 0$, the sample is an "exit" or "inner" boundary relative to the current nesting. Decrement `level`. If `level` becomes 0, keep the sample.
*   Otherwise, the sample is an "entry" or "outer" boundary. If `level` is 0, keep the sample. Increment `level`.
*   The final list `T` contains only the samples that define the outermost boundaries of the remaining volume [S1].

**Parameters:**
*   Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Sorting stability and floating-point precision in `z` values can affect the order of coincident samples, potentially leading to incorrect nesting levels if normals are ambiguous.
*   **Empty Lists:** If `Ray B.list` is empty, `Ray A` remains unchanged. If `Ray A.list` is empty, the result is empty.
*   **Degenerate Input:** If `Ray B` defines a closed volume completely inside `Ray A`, the subtraction correctly removes the inner shell. If `Ray B` is outside `Ray A`, no samples are removed (assuming `MergeRegion` handles the resulting disjoint intervals correctly, which it does by treating the first entry as the start of a region).

## Subtopics

### Shape Removal with Occlusion Handling
This variant addresses the limitation of standard boolean subtraction when the object being removed (foreground) occludes other geometry behind it. Standard subtraction might leave artifacts or fail to remove the occluded parts if the geometry is not explicitly defined in `Ray B`. This method handles occlusion by zeroing out the first mode of density along the ray for rays in the foreground mask [S2]. The first mode of density is defined as starting at the first point with non-zero density up to the first subsequent point with zero density [S2]. While effective for simple occlusion scenarios, this procedure can be slow and may leave artifacts of incomplete removal [S2].

## Operating characteristics
**Time Complexity:**
*   Dominated by the sorting step: $O(N \log N)$, where $N$ is the total number of samples in `Ray A` plus `Ray B` [S1].
*   `MergeRegion` is linear: $O(N)$ [S1].

**Memory Complexity:**
*   $O(N)$ to store the merged list of samples [S1].

**Measured Performance:**
*   Not given in the sources.

**Scaling:**
*   Scales linearly with the number of samples after the initial sort.

**Strengths:**
*   Simple implementation based on existing Union and MergeRegion primitives [S1].
*   Robust for non-occluded boolean operations.

**Limitations:**
*   Does not handle occlusion natively; requires the separate "Shape Removal with Occlusion Handling" procedure for complex scenes [S2].
*   The occlusion handling variant can be slow and may produce artifacts [S2].

**When to use:**
*   Use for standard boolean subtraction of volumetric shapes where occlusion is not a primary concern or is handled by explicit geometry in the subtractor.

**When not to use:**
*   Do not use for editing tasks involving significant occlusion without the supplementary density-zeroing procedure, as it may leave visual artifacts [S2].

## Background
Ray Subtraction was introduced in the context of detail sculpting using cubical marching squares [S1]. It is part of a suite of boolean operations (Union, Intersection, Subtraction) used for editing volumetric representations. The method relies on the topological inside/outside test provided by `MergeRegion` to identify and remove inner regions after the normal inversion [S1]. Later work in editing Conditional Radiance Fields highlighted the limitations of this approach regarding occlusion, proposing density-based zeroing as a supplementary technique [S2].
