# Ray Crossing Count (Winding Number)

Also called: winding number via crossing count, Ray-Triangle Crossing Count, Crossing Count Ray Query

## Overview

The Ray Crossing Count method determines whether a 3D point lies inside or outside a closed triangle mesh by casting a ray and counting surface intersections. It solves the topological "inside/outside" ambiguity that arises in volume rendering and mesh processing, replacing fragile primitive-relative checks (e.g., "behind the pixel") with a robust parity or signed count. It differs from simple parity checks by optionally using signed crossings (winding number) to handle non-manifold or open meshes gracefully, and from [Region Nesting Merge](13991-region-nesting-merge.md) by operating on a single ray query per point rather than merging nested regions.

## How it works

### Inputs and Outputs
- **Input**: A query point $V = (V_x, V_y, V_z)$ and a triangle mesh $\mathcal{M} = \{T_1, \dots, T_N\}$.
- **Output**: A scalar value indicating the topological status of $V$. For closed, outward-oriented meshes, the signed crossing count is $0$ if outside and $1$ if inside. The parity (odd/even) of the total intersection count also indicates inside (odd) or outside (even).

### Data Structures
- **Triangle**: Defined by three vertices $P_0, P_1, P_2$ and a normal vector $\mathbf{n}$. The normal is typically computed as $\mathbf{n} = \frac{(P_1 - P_0) \times (P_2 - P_0)}{\|(P_1 - P_0) \times (P_2 - P_0)\|}$ and oriented outward for closed meshes.
- **Ray**: Defined by origin $O$ and direction $\mathbf{d}$ (unit length).
- **BVH (Bounding Volume Hierarchy)**: A tree structure where each node stores an axis-aligned bounding box (AABB). Used to accelerate ray-triangle intersection queries by traversing only nodes whose AABBs intersect the ray. [S2, unofficial]

### Steps

1. **Initialize Counters**: Set `crossingCount = 0` and `totalCount = 0`. [S2, unofficial]
2. **Ray Definition**: Define a ray starting at $V$ with direction $\mathbf{d}$. Common choices are axis-aligned (e.g., $\mathbf{d} = (0,0,1)$) or arbitrary directions. [S1, unofficial][S3, unofficial]
3. **Intersection Query**: Traverse the BVH to find all triangles $T_i$ whose bounding boxes intersect the ray. For each candidate triangle, perform a precise ray-triangle intersection test (e.g., Möller–Trumbore algorithm). [S2, unofficial][S3, unofficial]
4. **Update Counters**: For each intersecting triangle $T_i$:
   - Increment `totalCount` by 1. [S2, unofficial]
   - Compute the dot product $dp = \mathbf{n}_i \cdot \mathbf{d}$.
   - If $dp > 0$, increment `crossingCount` by $+1$ (crossing out). [S2, unofficial]
   - If $dp < 0$, decrement `crossingCount` by $1$ (crossing in). [S2, unofficial]
   - If $dp = 0$, the ray is parallel to the triangle; handle as a degenerate case (typically ignore or treat as no intersection). [G]
5. **Result Interpretation**:
   - **Signed Winding Number**: For a closed, outward-oriented mesh, `crossingCount` is $1$ if $V$ is inside and $0$ if $V$ is outside. [S2, unofficial]
   - **Parity Check**: If `totalCount` is odd, $V$ is inside; if even, $V$ is outside. [S1, unofficial][S3, unofficial]
   - **Robustness**: For meshes with holes or "soups" (non-closed), the winding number provides a graceful transition between $0$ and $1$. [S2, unofficial]

### Formulas
- **Dot Product Sign**:
  $$
  \text{sign} = \begin{cases} 
  +1 & \text{if } \mathbf{n} \cdot \mathbf{d} > 0 \\
  -1 & \text{if } \mathbf{n} \cdot \mathbf{d} < 0 \\
  0 & \text{if } \mathbf{n} \cdot \mathbf{d} = 0
  \end{cases}
  $$
- **Winding Number**:
  $$
  W(V) = \sum_{T_i \in \text{intersections}} \text{sign}(\mathbf{n}_i \cdot \mathbf{d})
  $$
  For a closed mesh, $W(V) \in \{0, 1\}$. [S2, unofficial]

### Parameters
- **Intersection Algorithm**: Möller–Trumbore is commonly used. [S3, unofficial]
- **Ray Direction**: Any direction works, but axis-aligned rays simplify BVH traversal and intersection tests. [S1, unofficial][S3, unofficial]

### Edge Cases and Pitfalls
- **Edge/Vertex Hits**: Rays hitting triangle edges or vertices may double-count or miscount intersections, leading to unreliable parity. [S2, unofficial]
- **Numerical Precision**: Near-degenerate configurations (grazing rays) can cause sign flipping artifacts. [S3, unofficial]
- **Closed Mesh Assumption**: The method is meaningful only for closed meshes when using strict parity. For open meshes, the winding number is more robust. [S2, unofficial]
- **Performance**: Brute-force intersection testing is $O(N)$ per point, but BVH acceleration reduces average complexity. [S2, unofficial][S3, unofficial]

### Pseudocode

```python
def ray_crossing_count(query_point, mesh, ray_direction):
    """
    Determines if query_point is inside a closed mesh using ray crossing count.
    
    Args:
        query_point: tuple (x, y, z)
        mesh: list of triangles, each triangle is a dict with 'vertices' (list of 3 tuples) and 'normal' (tuple)
        ray_direction: tuple (dx, dy, dz), unit vector
        
    Returns:
        int: 1 if inside, 0 if outside (for closed, outward-oriented mesh)
    """
    crossing_count = 0
    total_count = 0
    
    # Define ray
    ray_origin = query_point
    ray_dir = ray_direction
    
    for triangle in mesh:
        # Ray-triangle intersection test (Möller–Trumbore)
        hit, t = ray_triangle_intersect(ray_origin, ray_dir, triangle['vertices'])
        
        if hit:
            total_count += 1
            # Determine crossing direction
            dot_product = dot(triangle['normal'], ray_dir)
            if dot_product > 0:
                crossing_count += 1
            elif dot_product < 0:
                crossing_count -= 1
            # If dot_product == 0, ignore (parallel)
    
    # For closed, outward-oriented mesh:
    # crossing_count should be 1 if inside, 0 if outside
    # Alternatively, use parity: total_count % 2 == 1 -> inside
    
    return crossing_count

def ray_triangle_intersect(ray_origin, ray_dir, vertices):
    """
    Möller–Trumbore intersection algorithm.
    
    Args:
        ray_origin: tuple (ox, oy, oz)
        ray_dir: tuple (dx, dy, dz)
        vertices: list of 3 tuples [(x0,y0,z0), (x1,y1,z1), (x2,y2,z2)]
        
    Returns:
        tuple: (hit: bool, t: float)
    """
    v0, v1, v2 = vertices
    edge1 = subtract(v1, v0)
    edge2 = subtract(v2, v0)
    h = cross(ray_dir, edge2)
    a = dot(edge1, h)
    
    if -0.0000001 < a < 0.0000001:
        return False, 0.0  # Parallel
    
    f = 1.0 / a
    s = subtract(ray_origin, v0)
    u = f * dot(s, h)
    
    if u < 0.0 or u > 1.0:
        return False, 0.0
    
    q = cross(s, edge1)
    v = f * dot(ray_dir, q)
    
    if v < 0.0 or u + v > 1.0:
        return False, 0.0
    
    t = f * dot(edge2, q)
    
    if t > 0.0000001:
        return True, t
    
    return False, 0.0

def subtract(a, b):
    return (a[0]-b[0], a[1]-b[1], a[2]-b[2])

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])
```

## Subtopics

### Signed Winding Number
A variant that uses the sign of the dot product to compute a continuous winding number, robust to open meshes. [S2, unofficial]

### Parity-Based Crossing Count
A simpler variant that only counts total intersections, relying on odd/even parity. Less robust for non-closed meshes. [S1, unofficial][S3, unofficial]

## Operating characteristics

- **Time Complexity**: $O(N)$ per point for brute-force, $O(\log N)$ average with BVH. [S2, unofficial]
- **Memory Complexity**: $O(N)$ for storing the mesh and BVH. [S2, unofficial]
- **Performance**: Can be performed simultaneously with Signed Distance Field (SDF) calculation, resulting in small overhead. [S3, unofficial]
- **Strengths**: Robust for closed meshes; handles complex topologies better than primitive-relative checks. [S3, unofficial]
- **Limitations**: Sensitive to numerical precision near edges/vertices; requires closed meshes for strict parity. [S2, unofficial]
- **When to Use**: When robust inside/outside testing is needed for volume rendering or mesh processing. [S3, unofficial]
- **When Not to Use**: For open meshes where parity is insufficient; consider winding number instead. [S2, unofficial]

## Background

The Ray Crossing Count method originates from computational geometry and computer graphics, where it is used for point-in-polygon/polyhedron tests. It has been adapted for volume rendering and mesh processing to replace fragile inside/outside tests. The method is discussed in various online resources and implementations, such as the isoext library and game development forums. [S1, unofficial][S2, unofficial][S3, unofficial]
