# Point-in-Tetrahedron Test via Barycentric Coordinates

Also called: Barycentric Point-in-Tetrahedron Test

## Overview
This method determines whether a set of query points lies inside a set of tetrahedra by solving for barycentric coordinates, processing points in chunks for memory efficiency [S1, unofficial]. It serves as a geometric containment primitive for tetrahedral volume rendering [G].

## How it works
### Inputs and Outputs
**Inputs:**
- `points`: A tensor of shape $(P, 3)$ containing $P$ query points in 3D space [S1, unofficial].
- `vertices`: A tensor of shape $(V, 3)$ containing the 3D coordinates of the mesh vertices [S1, unofficial].
- `tetrahedra`: A tensor of shape $(T, 4)$ containing indices into `vertices`, defining $T$ tetrahedra [S1, unofficial].

**Outputs:**
- `inside_tet`: A tensor of shape $(P,)$ containing the index of the first containing tetrahedron for each point, or $-1$ if no containing tetrahedron is found [S1, unofficial].
- `barycentric_coords`: A tensor of shape $(P, 4)$ containing the barycentric weights $[\lambda_0, \lambda_1, \lambda_2, \lambda_3]$ for each point relative to its containing tetrahedron, or zeros if the point is outside [S1, unofficial].

### Data Structures
The algorithm processes points in chunks of size `chunk_size` to manage memory usage [S1, unofficial]. Temporary tensors store edge vectors and point vectors relative to a reference vertex [S1, unofficial].

### Algorithm Steps
1. **Initialization**: Initialize `inside_tet` with $-1$ and `barycentric_coords` with $0$ [S1, unofficial].
2. **Chunking**: Loop over points in chunks: for `start` in `range(0, num_points, chunk_size)`, set `end = min(start + chunk_size, num_points)` [S1, unofficial].
3. **Vertex Retrieval**: Retrieve tetrahedron vertices: `tets_vertices = vertices[tetrahedra]`; unpack into $v_0, v_1, v_2, v_3$ [S1, unofficial].
4. **Edge Vector Computation**: Compute edge vectors originating from $v_3$: $a = v_0 - v_3$, $b = v_1 - v_3$, $c = v_2 - v_3$ [S1, unofficial].
5. **Point Vector Computation**: Compute vectors from $v_3$ to query points: $d = \text{chunk\_points}.\text{unsqueeze}(1) - v_3.\text{unsqueeze}(0)$ [S1, unofficial].
6. **Barycentric Solve**: Construct matrix $M = [a, b, c]$; solve $M \lambda = d$ using a linear solver [S1, unofficial].
7. **Lambda Extraction**: Extract $\lambda_0, \lambda_1, \lambda_2$ from the solution; compute $\lambda_3 = 1 - \lambda_0 - \lambda_1 - \lambda_2$ [S1, unofficial].
8. **Containment Check**: Evaluate $\text{inside} = (\lambda_0 \ge 0) \land (\lambda_1 \ge 0) \land (\lambda_2 \ge 0) \land (\lambda_3 \ge 0)$ [S1, unofficial].
9. **Selection**: Find first containing tetrahedron: $\text{valid\_tet\_exists} = \text{inside}.\text{any}(\text{dim}=1)$; $\text{chunk\_inside\_tet} = \text{where}(\text{valid\_tet\_exists}, \text{argmax}(\text{inside}, \text{dim}=1), -1)$ [S1, unofficial].
10. **Output Update**: Get $\text{chunk\_valid\_mask} = \text{nonzero}(\text{valid\_tet\_exists})[0]$; get $\text{valid\_tet\_idx} = \text{chunk\_inside\_tet}[\text{chunk\_valid\_mask}]$; set `barycentric_coords[start:end, 0:3][chunk_valid_mask]` to corresponding lambda values; set `inside_tet[start:end] = chunk_inside_tet` [S1, unofficial].

### Pseudocode
```python
def point_in_tetrahedron(points, vertices, tetrahedra, chunk_size):
    P = points.shape[0]
    inside_tet = full((P,), -1, dtype=int64)
    barycentric_coords = zeros((P, 4), dtype=float32)
    
    tets_vertices = vertices[tetrahedra]
    
    for start in range(0, P, chunk_size):
        end = min(start + chunk_size, P)
        chunk_points = points[start:end]
        
        v0, v1, v2, v3 = tets_vertices[:, 0], tets_vertices[:, 1], tets_vertices[:, 2], tets_vertices[:, 3]
        
        a = v0 - v3
        b = v1 - v3
        c = v2 - v3
        
        d = chunk_points.unsqueeze(1) - v3.unsqueeze(0)
        
        M = stack([a, b, c], dim=-1)
        d_perm = permute(d, axes=(1, 2, 0))
        sol = solve(M, d_perm)
        chunk_bary_coords = permute(sol, axes=(2, 0, 1))
        
        lambda_0, lambda_1, lambda_2 = unbind(chunk_bary_coords, dim=-1)
        lambda_3 = 1.0 - lambda_0 - lambda_1 - lambda_2
        
        inside = (lambda_0 >= 0) & (lambda_1 >= 0) & (lambda_2 >= 0) & (lambda_3 >= 0)
        
        valid_tet_exists = any(inside, dim=1)
        chunk_inside_tet = where(valid_tet_exists, argmax(inside.float(), dim=1), -1)
        
        chunk_valid_mask = nonzero(valid_tet_exists, as_tuple=True)[0]
        
        if len(chunk_valid_mask) > 0:
            valid_tet_idx = chunk_inside_tet[chunk_valid_mask]
            inside_tet[start:end][chunk_valid_mask] = valid_tet_idx
            
            barycentric_coords[start:end, 0][chunk_valid_mask] = lambda_0[chunk_valid_mask, valid_tet_idx]
            barycentric_coords[start:end, 1][chunk_valid_mask] = lambda_1[chunk_valid_mask, valid_tet_idx]
            barycentric_coords[start:end, 2][chunk_valid_mask] = lambda_2[chunk_valid_mask, valid_tet_idx]
            barycentric_coords[start:end, 3][chunk_valid_mask] = lambda_3[chunk_valid_mask, valid_tet_idx]
            
    return inside_tet, barycentric_coords
```

### Parameters
- `chunk_size`: Controls the batch size for memory efficiency [S1, unofficial].

### Edge Cases and Pitfalls
- **Degenerate Tetrahedra**: If the tetrahedron volume is zero (coplanar vertices), the matrix $M$ is singular and the linear solver will fail or produce NaNs [G]. Implementers should check for zero volume or use a pseudo-inverse if degenerate cases are expected [G].
- **Precision**: Barycentric coordinates should sum to $1.0$. Floating-point errors may cause slight deviations [G]. The condition $\lambda_i \ge 0$ is robust, but strict equality checks for $\sum \lambda_i = 1$ are not required if $\lambda_3$ is computed as $1 - \sum_{i=0}^2 \lambda_i$ [G].
- **Boundary Conditions**: Points exactly on the boundary have $\lambda_i = 0$. The condition $\ge 0$ includes them as "inside" [G].

## Operating characteristics
- **Time Complexity**: $O(P \cdot T)$ in the worst case if checking all tetrahedra per point, but typically $O(P)$ if spatial acceleration structures (like BVH or grid) are used to limit $T$ to a small constant [G]. The linear solve is $O(1)$ per point per tetrahedron [G].
- **Memory Complexity**: $O(P + T)$ for storing inputs and outputs. Chunking reduces peak memory to $O(\text{chunk\_size} \cdot T)$ [G].
- **Strengths**: Vectorizable, numerically stable for non-degenerate tetrahedra, easy to implement with standard linear algebra libraries [G].
- **Limitations**: Requires solving a linear system for each tetrahedron-point pair, which can be expensive without acceleration structures. Degenerate tetrahedra cause numerical instability [G].
- **When to Use**: When high precision is needed for point containment in tetrahedral meshes, and acceleration structures are available to limit the search space [G].
- **When Not to Use**: For degenerate tetrahedra or when memory is extremely constrained and chunking is not feasible [G].

## Background
The method is a standard computational geometry technique for point-in-polyhedron tests [G]. It is implemented in the TetWeave project for resampling and optimization in tetrahedral grids [S1, unofficial].
