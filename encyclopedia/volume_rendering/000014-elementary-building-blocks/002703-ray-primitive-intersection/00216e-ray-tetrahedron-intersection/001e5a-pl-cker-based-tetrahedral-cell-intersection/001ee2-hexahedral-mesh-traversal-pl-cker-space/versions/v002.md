# Hexahedral Mesh Traversal (Plücker Space)

Also called: Hex-P, Hexahedral Plücker traversal

## Overview
A traversal method for hexahedral meshes that uses Plücker coordinates to determine the exit face of a ray intersecting a hexahedral cell, requiring face decomposition into triangles for interpolation [S1]. It sets itself apart from its sibling [Hexahedral Mesh Traversal (Bilinear Patch-Extension)](1904-hexahedral-mesh-traversal-bilinear-patch-extension.md) by relying on triangular decomposition for interpolation, which introduces parametric discontinuities along the diagonal but allows unambiguous face determination [S1].

## How it works
**Inputs and Outputs:**
- Input: A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a hexahedral mesh where each cell has 8 vertices $v_0, \dots, v_7$ [S1]. The entry face is defined by vertices $v_0, v_1, v_2, v_3$ and the opposite face by $v_4, v_5, v_6, v_7$ [S1].
- Output: The index of the next hexahedron in the traversal path and the barycentric coordinates on the exit face for interpolation [S1].

**Data Structures:**
- The mesh topology is implicit in the grid structure; no extra connectivity memory is required [S1].
- Boundary faces are preprocessed and decomposed into two triangles each for efficient kd-tree initialization [S1].

**Steps:**
1. **Initialization:** Find the initial hexahedron along the ray using a kd-tree built from the decomposed boundary faces [S1].
2. **First Plücker Test:** Perform a Plücker test using edges $v_4 \to v_5$ and $v_6 \to v_7$. This test partitions the possible exit faces into three areas $A_0, A_1, A_2$, each containing exactly three faces of the hexahedron [S1].
3. **Second Plücker Test (Conditional):** If the first test does not uniquely identify the exit face, perform a second Plücker test based on the determined area:
   - For area $A_0$: test edges $v_2 \to v_6$ and $v_3 \to v_7$.
   - For area $A_1$: test edges $v_4 \to v_6$ and $v_5 \to v_7$.
   - For area $A_2$: test edges $v_0 \to v_4$ and $v_1 \to v_5$ [S1].
4. **Face Determination:** Determine the correct exit face using simple sign comparisons from the second test [S1].
5. **Traversal Step:** Modify the index pointer by incrementing or decrementing with respect to the dimension corresponding to the exit face to fetch the next cell. Stop if the pointer exits volume bounds [S1].
6. **Interpolation:** Decompose the intersected exit face into two triangles. Compute barycentric coordinates for the intersection point on the selected triangle. Note that Plücker values cannot be directly scaled to receive parametric coordinates for quadrilaterals, necessitating this decomposition [S1].

**Edge Cases and Pitfalls:**
- Decomposing a face into two triangles leads to parametric discontinuities along the diagonal [S1].
- Unwanted artifacts may appear if hexahedra values are badly distributed [S1].
- Plücker values are only suitable for triangles; they cannot be directly scaled to receive parametric coordinates for quadrilaterals [S1].

## Subtopics

### [Hexahedral Mesh Traversal (Bilinear Patch-Extension)](1904-hexahedral-mesh-traversal-bilinear-patch-extension.md)
A hybrid traversal algorithm that combines Plücker-based face selection with bilinear patch intersection tests. It avoids the geometric singularities and discontinuities of pure Plücker traversal by using parametric coordinates $(u, v)$ from bilinear patches for interpolation. Choose this when smooth interpolation across face boundaries is critical and performance overhead of bilinear tests is acceptable.

## Operating characteristics
- **Time Complexity:** The method requires at most four Plücker tests to decide the exit face [S1]. However, the need to decompose faces and compute barycentric coordinates reduces performance significantly compared to tetrahedral traversal [S1].
- **Memory Complexity:** No extra memory for connectivity is required as topology is implicit [S1].
- **Measured Performance:** 3.2 million hexahedra per second on a Dual-core Opteron 2 GHz [S1].
- **Scaling:** Data fetching costs are 7 times higher than tetrahedral traversal because more than one vertex and scalar value must be fetched per step [S1].
- **Strengths:** Unambiguous determination of intersected faces; optimized for convex hexahedral faces; easily extendable to concave faces [S1].
- **Limitations:** Parametric discontinuities along the diagonal of decomposed faces; artifacts with badly distributed values; higher data fetching costs [S1].
- **When to use:** When unambiguous face determination is prioritized over interpolation smoothness and performance overhead is acceptable [S1].
- **When not to use:** When smooth interpolation across face boundaries is required or when performance is critical and tetrahedral meshes are an option [S1].

## Background
Originated in the paper "Fast Ray Traversal of Tetrahedral and Hexahedral Meshes for Direct Volume Rendering" (2006) [S1]. The method extends the Plücker test introduced for tetrahedral traversal to hexahedral grids [S1]. It is used in direct volume rendering for hexahedral meshes [S1].
