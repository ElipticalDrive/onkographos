# Trilinear Isosurface Intersection

Also called: Analytical cubic solution, Isosurface Intersection via Cubic Polynomial

## Overview
Trilinear Isosurface Intersection computes the exact intersection distance $t$ between a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ and the isosurface defined by a threshold value within a single hexahedral voxel, using trilinear interpolation of the eight corner scalar values [S3, S5]. It solves the resulting cubic polynomial to find the hit position, providing a closed-form or iterative solution that avoids the step-size reduction overhead of sphere tracing [S1]. Unlike [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) which relies on iterative refinement, this method derives the intersection directly from the algebraic structure of the trilinear field, offering superior performance for silhouette and secondary rays [S1].

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized).
- Voxel corner scalar values $v_{ijk}$ for $i,j,k \in \{0,1\}$, where indices correspond to the minimum and maximum coordinates of the voxel in world space.
- Isovalue $I$ (threshold).

**Outputs:**
- Intersection distance $t$ (if an intersection exists within the voxel bounds).
- Intersection point $\mathbf{p} = \mathbf{o} + t\mathbf{d}$.

**Data Structures:**
The voxel is treated as a unit cube in parametric space $[0,1]^3$. The scalar field $f(u,v,w)$ is defined by the eight corner values. No additional data structures are required beyond the eight scalar values and the ray parameters.

**Steps:**

1.  **Boundary Check:**
    Compute the minimum ($v_{min}$) and maximum ($v_{max}$) of the eight corner values $v_{ijk}$. If $I < v_{min}$ or $I > v_{max}$, no intersection exists within this voxel [S3, S5]. Return failure.

2.  **Formulate Trilinear Equation:**
    Define the trilinear interpolant $f(u,v,w)$ over the parametric domain $[0,1]^3$. Let the voxel corners be at parametric coordinates $(u_i, v_j, w_k)$ where $u_0=0, u_1=1$, etc. The value at any point $(u,v,w)$ is:
    $$ f(u,v,w) = \sum_{i=0}^1 \sum_{j=0}^1 \sum_{k=0}^1 (1 - U_i)(1 - V_j)(1 - W_k) v_{ijk} $$
    where $U_i = |u - u_i|$, $V_j = |v - v_j|$, and $W_k = |w - w_k|$ [S6].
    The isosurface is defined by $f(u,v,w) = I$.

3.  **Substitute Ray Equation:**
    Substitute the ray equation $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ into the parametric coordinates. Let the voxel be defined by world-space bounds $[x_{min}, x_{max}] \times [y_{min}, y_{max}] \times [z_{min}, z_{max}]$. The parametric coordinates are:
    $$ u(t) = \frac{o_x + t d_x - x_{min}}{x_{max} - x_{min}}, \quad v(t) = \frac{o_y + t d_y - y_{min}}{y_{max} - y_{min}}, \quad w(t) = \frac{o_z + t d_z - z_{min}}{z_{max} - z_{min}} $$
    Substituting these into $f(u,v,w) - I = 0$ yields a cubic polynomial in $t$:
    $$ G_3 t^3 + G_2 t^2 + G_1 t + G_0 = 0 $$
    The coefficients $G_0, G_1, G_2, G_3$ are derived from the corner values and ray/voxel geometry [S6][S7, unofficial].

4.  **Solve Cubic Polynomial:**
    Solve for real roots $t$ in the range $[0, \infty)$ (or $[0, 1]$ if using cell diagonals as rays in specific topological analyses [S6]).
    
    *Method A: Analytical (Cardano's Formula)*
    Compute the discriminant $D_3$ to determine the nature of the roots [S6]:
    $$ \delta^2 = \frac{G_2^2 - 3G_3G_1}{9G_3^2} $$
    $$ x_N = -\frac{G_2}{3G_3} $$
    $$ y_N = G_3 x_N^3 + G_2 x_N^2 + G_1 x_N + G_0 $$
    $$ D_3 = y_N^2 - 4G_3^2 \delta^3 $$
    
    - If $G_3 = 0$, the equation reduces to quadratic $G_2 t^2 + G_1 t + G_0 = 0$. Compute $D_2 = G_1^2 - 4G_2G_0$.
      - If $D_2 > 0$, two distinct real roots.
      - If $D_2 = 0$, two equal real roots.
      - If $D_2 < 0$, no real roots.
    - If $G_3 \neq 0$:
      - If $D_3 > 0$, one real root and two complex conjugate roots.
      - If $D_3 = 0$ and $y_N = 0$, three equal real roots.
      - If $D_3 = 0$ and $y_N \neq 0$, one distinct real root and two equal real roots.
      - If $D_3 < 0$, three distinct real roots.
    
    Use Cardano's method to find the real roots [S6].

    *Method B: Iterative (Neubauer/Marmitt)*
    Iteratively re-parameterize the ray into sub-intervals within the cell until a sign change is detected in the trilinear function values at the interval endpoints, then find the root [S3, S5]. This method is noted to be slightly faster and numerically stable in single precision compared to the analytical solver [S5].

5.  **Select Intersection:**
    Identify the smallest positive root $t$ that lies within the voxel bounds (typically $t \ge 0$ and such that the point is inside the voxel). If using the full ray, select the closest positive $t$ [S5].

**Pseudocode:**

```python
import math

def trilinear_isosurface_intersection(ray_origin, ray_dir, voxel_bounds, corner_values, isovalue):
    """
    ray_origin: (ox, oy, oz)
    ray_dir: (dx, dy, dz)
    voxel_bounds: ((xmin, xmax), (ymin, ymax), (zmin, zmax))
    corner_values: list of 8 floats, indexed by (i,j,k) where i,j,k in {0,1}
                   index = i*4 + j*2 + k
    isovalue: float
    Returns: t (float) or None if no intersection.
    """
    xmin, xmax = voxel_bounds[0]
    ymin, ymax = voxel_bounds[1]
    zmin, zmax = voxel_bounds[2]
    
    ox, oy, oz = ray_origin
    dx, dy, dz = ray_dir
    
    # Step 1: Boundary Check
    v_min = min(corner_values)
    v_max = max(corner_values)
    if isovalue < v_min or isovalue > v_max:
        return None

    # Step 2 & 3: Compute Coefficients G3, G2, G1, G0
    # The trilinear function is f(u,v,w) = sum( (1-Ui)(1-Vj)(1-Wk) * v_ijk )
    # u(t) = (ox + t*dx - xmin) / (xmax - xmin)
    # Let inv_dx = dx / (xmax - xmin), etc.
    # u(t) = u0 + t * inv_dx, where u0 = (ox - xmin) / (xmax - xmin)
    
    inv_x = dx / (xmax - xmin)
    inv_y = dy / (ymax - ymin)
    inv_z = dz / (zmax - zmin)
    
    u0 = (ox - xmin) / (xmax - xmin)
    v0 = (oy - ymin) / (ymax - ymin)
    w0 = (oz - zmin) / (zmax - zmin)
    
    # Extract corner values
    # v_ijk corresponds to corner (i,j,k)
    v_000 = corner_values[0]
    v_100 = corner_values[1]
    v_010 = corner_values[2]
    v_110 = corner_values[3]
    v_001 = corner_values[4]
    v_101 = corner_values[5]
    v_011 = corner_values[6]
    v_111 = corner_values[7]
    
    # Coefficients calculation based on expanding the trilinear polynomial
    # f(u,v,w) = c0 + c1*u + c2*v + c3*w + c4*u*v + c5*u*w + c6*v*w + c7*u*v*w
    # We need to map this to G3*t^3 + G2*t^2 + G1*t + G0 - isovalue = 0
    
    # Linear coefficients in u,v,w
    # u term: (v_100 - v_000)
    # v term: (v_010 - v_000)
    # w term: (v_001 - v_000)
    # uv term: (v_110 - v_100 - v_010 + v_000)
    # uw term: (v_101 - v_100 - v_001 + v_000)
    # vw term: (v_011 - v_010 - v_001 + v_000)
    # uvw term: (v_111 - v_101 - v_011 + v_001 - v_110 + v_100 + v_010 - v_000)
    
    c0 = v_000
    c1 = v_100 - v_000
    c2 = v_010 - v_000
    c3 = v_001 - v_000
    c4 = v_110 - v_100 - v_010 + v_000
    c5 = v_101 - v_100 - v_001 + v_000
    c6 = v_011 - v_010 - v_001 + v_000
    c7 = v_111 - v_101 - v_011 + v_001 - v_110 + v_100 + v_010 - v_000
    
    # Substitute u = u0 + inv_x * t, v = v0 + inv_y * t, w = w0 + inv_z * t
    # Expand to find coefficients of t^3, t^2, t, constant
    
    # t^3 coefficient (G3)
    G3 = c7 * inv_x * inv_y * inv_z
    
    # t^2 coefficient (G2)
    # Terms involving two invs: c4*inv_x*inv_y, c5*inv_x*inv_z, c6*inv_y*inv_z
    # Plus terms from linear coeffs times two linear params? No, linear coeffs are degree 1 in t.
    # c1*u -> c1*inv_x*t. c2*v -> c2*inv_y*t. c3*w -> c3*inv_z*t.
    # c4*u*v -> c4*(u0+inv_x t)(v0+inv_y t) -> c4*(u0*inv_y + v0*inv_x)t + ...
    # So G2 comes from:
    # c4 * (u0*inv_y + v0*inv_x)
    # c5 * (u0*inv_z + w0*inv_x)
    # c6 * (v0*inv_z + w0*inv_y)
    # c7 * (u0*inv_y*inv_z + v0*inv_x*inv_z + w0*inv_x*inv_y)
    
    G2 = (c4 * (u0 * inv_y + v0 * inv_x) +
          c5 * (u0 * inv_z + w0 * inv_x) +
          c6 * (v0 * inv_z + w0 * inv_y) +
          c7 * (u0 * inv_y * inv_z + v0 * inv_x * inv_z + w0 * inv_x * inv_y))
          
    # t^1 coefficient (G1)
    # From c1*u: c1*inv_x
    # From c2*v: c2*inv_y
    # From c3*w: c3*inv_z
    # From c4*u*v: c4 * u0 * v0
    # From c5*u*w: c5 * u0 * w0
    # From c6*v*w: c6 * v0 * w0
    # From c7*u*v*w: c7 * (u0*v0*inv_z + u0*w0*inv_y + v0*w0*inv_x)
    
    G1 = (c1 * inv_x + c2 * inv_y + c3 * inv_z +
          c4 * u0 * v0 + c5 * u0 * w0 + c6 * v0 * w0 +
          c7 * (u0 * v0 * inv_z + u0 * w0 * inv_y + v0 * w0 * inv_x))
          
    # Constant term (G0)
    # From c0
    # From c1*u0
    # From c2*v0
    # From c3*w0
    # From c4*u0*v0
    # From c5*u0*w0
    # From c6*v0*w0
    # From c7*u0*v0*w0
    
    G0 = (c0 + c1 * u0 + c2 * v0 + c3 * w0 +
          c4 * u0 * v0 + c5 * u0 * w0 + c6 * v0 * w0 +
          c7 * u0 * v0 * w0)
          
    # Equation: G3*t^3 + G2*t^2 + G1*t + (G0 - isovalue) = 0
    G0 = G0 - isovalue
    
    # Step 4: Solve Cubic
    roots = solve_cubic(G3, G2, G1, G0)
    
    # Step 5: Select smallest positive root
    valid_roots = [t for t in roots if t >= 0]
    if not valid_roots:
        return None
        
    return min(valid_roots)

def solve_cubic(a, b, c, d):
    """
    Solves ax^3 + bx^2 + cx + d = 0
    Returns list of real roots.
    """
    if abs(a) < 1e-12:
        # Quadratic
        if abs(b) < 1e-12:
            # Linear
            if abs(c) < 1e-12:
                return []
            return [-d / c]
        disc = c*c - 4*b*d
        if disc < 0:
            return []
        sqrt_disc = math.sqrt(disc)
        return [(-c - sqrt_disc) / (2*b), (-c + sqrt_disc) / (2*b)]
    
    # Normalize
    b /= a
    c /= a
    d /= a
    
    # Depressed cubic t^3 + pt + q = 0, where x = t - b/3
    p = c - b*b/3
    q = 2*b*b*b/27 - b*c/3 + d
    
    disc = q*q/4 + p*p*p/27
    
    roots = []
    
    if disc > 0:
        # One real root
        sqrt_disc = math.sqrt(disc)
        u = -q/2 + sqrt_disc
        v = -q/2 - sqrt_disc
        # Cube root
        u = math.copysign(abs(u)**(1/3), u)
        v = math.copysign(abs(v)**(1/3), v)
        t = u + v
        x = t - b/3
        roots.append(x)
    elif disc == 0:
        # Multiple roots
        if q == 0:
            x = -b/3
            roots.append(x) # Triple root
        else:
            u = math.copysign(abs(-q/2)**(1/3), -q/2)
            t1 = 2*u
            t2 = -u
            x1 = t1 - b/3
            x2 = t2 - b/3
            roots.append(x1)
            roots.append(x2)
    else:
        # Three distinct real roots (casus irreducibilis)
        r = math.sqrt(-p*p*p/27)
        theta = math.acos(-q/(2*r))
        m = 2 * r**(1/3)
        t1 = m * math.cos(theta/3)
        t2 = m * math.cos((theta + 2*math.pi)/3)
        t3 = m * math.cos((theta + 4*math.pi)/3)
        x1 = t1 - b/3
        x2 = t2 - b/3
        x3 = t3 - b/3
        roots.append(x1)
        roots.append(x2)
        roots.append(x3)
        
    return roots
```

## Subtopics

### [Analytic Voxel Intersection](9669-analytic-voxel-intersection.md)
Analytic Voxel Intersection is a method for computing the intersection between a ray and the isosurface defined by the zero level set of a signed distance function (SDF) within a single voxel of an SDF grid. It solves the cubic polynomial derived from trilinear interpolation of the corner signed distances to find the exact intersection distance $t$. Unlike sphere tracing, which requires iterative stepping that slows down near the surface, this method provides a direct solution, avoiding iterative step reduction and offering superior performance for silhouette and secondary rays. It builds on [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md) by providing the specific algebraic formulation and solution strategies for the resulting cubic equation.

### No-Body-Saddle Midpoint Transformation
A normalization technique for cubes with no body saddles, mapping the theoretical saddle point $m$ into the block via linear scaling and analyzing gradients to constrain topology [S8]. Compute theoretical midpoint $m = (-c/a - d/a, -b/a)$. If $m$ is outside the block, apply linear transformations to scale the block so $m$ is inside. Assume $m$ is in block and $T_{mmm} = 0$. Gradients along midpoint lines are constant: $a_x/a, a_y/a, a_z/a$. Assume all positive (apply axis reflection if negative). Let function values at positive ends be $\alpha, \beta, \gamma > 0$ [S8].

### Smooth Trilinear Isosurface
A rendering technique that uses fast trilinear interpolation for ray intersection search but uses the gradient from tricubic interpolation for normal calculation to avoid visual discontinuities at node boundaries [S9]. Perform ray intersection search using the trilinear interpolant, which is faster to compute than tricubic. Store tricubic coefficients only at nodes containing the isosurface. Calculate surface normals using the gradient of the tricubic interpolant instead of the trilinear gradient to ensure smoothness [S9]. Trilinear interpolation guarantees shape continuity but not gradient continuity, causing visual discontinuities (grid patterns) at node boundaries if used for normals [S9].

## Operating characteristics
**Time Complexity:** $O(1)$ per voxel intersection, involving a fixed number of arithmetic operations to compute coefficients and solve the cubic equation. The Neubauer iterative method may require multiple iterations but is noted to be slightly faster in single precision than the analytical Cardano solver [S5].

**Memory Complexity:** $O(1)$ auxiliary memory per intersection, requiring storage for the eight corner values and temporary variables for the cubic solver.

**Measured Performance:**
- GPU implementations can fetch as few as 4 data samples per voxel for coefficient extraction, leveraging hardware trilinear interpolation support [S2, unofficial].
- The Neubauer iterative root finder yields single-precision, numerically stable results and is slightly faster than the analytical Schwarze cubic solver [S5].

**Strengths:**
- Provides exact intersection points without iterative marching steps, improving performance for silhouette and secondary rays [S1].
- Avoids the need for Hermite data (normals) required by dual contouring methods [S6].
- Can be optimized using topological look-up tables for cell diagonals [S6].

**Limitations:**
- Trilinear interpolation does not guarantee gradient continuity, leading to visual discontinuities (grid patterns) if normals are derived from the trilinear gradient [S9].
- Degenerate cases (e.g., $G_3=0$) require handling quadratic reductions [S6].
- Precision issues may arise in single precision for the analytical cubic solver compared to iterative methods [S5].

**When to use:**
- When exact intersection points are required for isosurfaces within voxels.
- When performance is critical for rays that frequently intersect surfaces (silhouettes, reflections).
- When Hermite data is not available.

**When not to use:**
- When smooth normals are required and tricubic interpolation is too expensive to store/compute.
- When the scalar field is not defined on a regular hexahedral grid.

## Background
The method originates from the need to efficiently trace rays against implicit surfaces defined by scalar fields on voxel grids. Early implementations used ray marching or linear approximations [S2, unofficial]. The analytical cubic solution was introduced by Parker et al. [S4, unofficial][S5], who used Schwarze's cubic solver. Marmitt et al. later proposed the Neubauer iterative root finder as a faster, single-precision stable alternative [S3, S5]. Lopes and Brodlie (2003) contributed to the topological analysis of trilinear cells, enabling optimization via look-up tables for ray intersections [S6]. The technique is widely used in volume rendering and isosurface extraction, particularly in GPU-based ray casting [S2, unofficial].
