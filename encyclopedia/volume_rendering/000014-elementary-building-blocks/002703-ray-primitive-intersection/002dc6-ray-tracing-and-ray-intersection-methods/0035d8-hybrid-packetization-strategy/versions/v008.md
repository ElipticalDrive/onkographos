# Hybrid Packetization Strategy

Also called: Hybrid Intersector, Hybrid Packetization, Hybrid Packetization for Triangle Intersection, Hybrid Ray-Triangle Intersection

## Overview
The Hybrid Packetization Strategy is a ray-triangle intersection method designed to improve SIMD utilization on GPUs when standard packetization is inefficient due to sparse acceleration structures with high primitive density per leaf [S1, unofficial][S2, unofficial]. It solves the problem of lost coherence in warp-level computations by dynamically switching between standard warp-level intersection and parallel processing of individual rays based on workload [S2, unofficial]. It sets itself apart from standard packetization by distributing the work of a single ray across multiple threads when the number of intersection candidates is high, thereby maintaining throughput even when rays traverse cells with varying densities [S1, unofficial][S2, unofficial].

## How it works
The method operates within a GPU warp (SIMD unit of 32 threads) during the ray-triangle intersection stage of ray traversal [S1, unofficial][S2, unofficial]. It adapts its execution path based on the number of intersection candidates (workload) for the rays in the warp [S1, unofficial].

### Inputs and Outputs
- **Inputs**: A warp of 32 rays, each with a current traversal state and a list of intersection candidates (primitive indices) for the current cell [S1, unofficial][S2, unofficial].
- **Outputs**: The closest intersection distance for each ray, stored in thread-local memory [S1, unofficial][S2, unofficial].

### Data Structures
- **Shared Memory Buffer**: Stores entries for rays with high workload [S2, unofficial]. Each entry contains:
    - `ray_index`: The index of the ray within the warp (0–31).
    - `first_candidate_index`: The index of the first primitive in the ray's candidate list.
    - *Note*: The indices of the remaining primitives are consecutive, so only the first needs to be stored [S1, unofficial][S2, unofficial].
- **Shared Memory Arrays**: Used for reduction of intersection distances [S2, unofficial].

### Parameters
- **High Workload Threshold**: 16 intersection candidates [S1, unofficial][S2, unofficial].
- **Standard Intersection Fallback Threshold**: 20 active rays with high workload [S1, unofficial][S2, unofficial].
- **Parallelization Granularity**: Pairs of rays (2 rays per thread pair) [S1, unofficial][S2, unofficial].

### Steps
1. **Check Uniformity**: Determine if all 32 rays in the warp have intersection candidates [S1, unofficial][S2, unofficial]. If **yes**, proceed with standard ray-triangle intersection [S1, unofficial][S2, unofficial]. If **no**, proceed to step 2.
2. **Check High Workload Count**: Count the number of rays with at least 16 intersection candidates (high workload) [S1, unofficial][S2, unofficial].
3. **Fallback Decision**: If the count is **greater than 20**, proceed with the standard intersection routine [S1, unofficial][S2, unofficial]. This maps better to Fermi GPUs because they support more Boolean operations at the warp level in hardware [S1, unofficial][S2, unofficial]. If the count is **20 or fewer**, proceed to step 4 [S1, unofficial][S2, unofficial].
4. **Buffer High Workload Rays**: For each ray with high workload (≥16 candidates), use an atomic increment on a shared counter to get a unique position in the shared memory buffer [S2, unofficial]. Store the `ray_index` and `first_candidate_index` in the buffer at that position [S2, unofficial].
5. **Process Buffered Rays**: Iterate through the entries in the shared memory buffer, taking two entries at a time [S1, unofficial][S2, unofficial]. For each pair of rays, perform 32 intersection tests in parallel [S1, unofficial][S2, unofficial].
6. **Reduce Results**: Combine results by performing a reduction on the arrays containing intersection distances, which are shared between threads [S1, unofficial][S2, unofficial].
7. **Store Results**: The thread responsible for tracing each ray records the closest intersection (if any) in thread-local memory [S1, unofficial][S2, unofficial].
8. **Process Remaining Rays**: When all rays with high workload have been processed, perform the remaining intersection tests one by one for all rays as usual [S1, unofficial][S2, unofficial].

### Pseudocode
```python
def hybrid_packetization_intersect(warp_rays):
    # warp_rays: list of 32 Ray objects
    # Each Ray has .candidates (list of int) and .closest_dist (float, init to inf)

    # Step 1: Check if all rays have intersection candidates
    all_have_candidates = all(len(r.candidates) > 0 for r in warp_rays)
    if all_have_candidates:
        # [G] Standard warp-level ray-triangle intersection
        return warp_rays

    # Step 2: Count rays with high workload (>= 16 candidates)
    high_workload_threshold = 16
    fallback_threshold = 20
    high_workload_rays = [(i, r) for i, r in enumerate(warp_rays) if len(r.candidates) >= high_workload_threshold]
    num_high = len(high_workload_rays)

    # Step 3: Fallback if too many high-workload rays
    if num_high > fallback_threshold:
        # [G] Standard intersection routine (optimized for Fermi Boolean ops)
        return warp_rays

    # Step 4: Buffer high workload rays
    # [S2, unofficial] Atomic increment on a shared counter to get unique position
    buffer = []
    for idx, ray in high_workload_rays:
        pos = len(buffer)  # Simulates atomic increment on shared counter
        buffer.append((idx, ray.candidates[0]))

    # Step 5: Process buffered rays in pairs
    for i in range(0, len(buffer), 2):
        if i + 1 < len(buffer):
            idx1, _ = buffer[i]
            idx2, _ = buffer[i + 1]
            ray1 = warp_rays[idx1]
            ray2 = warp_rays[idx2]

            # [S1, unofficial][S2, unofficial] Perform 32 intersection tests for a pair of rays in parallel
            shared_dists = [float('inf')] * 32
            all_cands = ray1.candidates + ray2.candidates
            num_cands = len(all_cands)

            for t in range(32):
                for k in range(t, num_cands, 32):
                    prim_idx = all_cands[k]
                    # [G] Standard ray-triangle intersection test
                    pass

            # Step 6: Reduce results on shared distance arrays
            min_dist = min(shared_dists)

            # Step 7: Record closest intersection in thread local memory
            warp_rays[idx1].closest_dist = min_dist
            warp_rays[idx2].closest_dist = min_dist
        else:
            # Odd ray in buffer, process alone
            idx, _ = buffer[i]
            ray = warp_rays[idx]
            min_dist = float('inf')
            for prim_idx in ray.candidates:
                # [G] Standard ray-triangle intersection test
                pass
            warp_rays[idx].closest_dist = min_dist

    # Step 8: Process remaining low-workload rays one by one
    for idx, ray in enumerate(warp_rays):
        if len(ray.candidates) < high_workload_threshold:
            min_dist = float('inf')
            for prim_idx in ray.candidates:
                # [G] Standard ray-triangle intersection test
                pass
            warp_rays[idx].closest_dist = min_dist

    return warp_rays
```

### Edge Cases and Pitfalls
- **Coherence Loss**: SIMD efficiency is tied to ray coherence [S1, unofficial][S2, unofficial]. It is lost as soon as some rays traverse a full cell while others pass through an empty one [S1, unofficial][S2, unofficial].
- **Precision**: Not given in the sources [S1, unofficial].
- **Boundaries**: The method assumes a warp size of 32 threads [S1, unofficial][S2, unofficial].
- **Degenerate Input**: Not given in the sources [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Depends on the number of intersection candidates and the number of high-workload rays [S2, unofficial].
- **Memory Complexity**: Uses shared memory for the buffer and reduction arrays [S2, unofficial]. The buffer holds at most 20 entries; if more than 20 high-workload rays exist, the algorithm falls back to the standard routine instead of using the buffer [S1, unofficial][S2, unofficial].
- **Measured Performance**: Tested on NVIDIA GeForce GTX 285, GTX 280, and GTX 470 [S1, unofficial]. Performance scales with the number of primitive references, which is scene-dependent [S2, unofficial].
- **Strengths**: Improves SIMD utilization for sparse grids with many primitives per leaf [S1, unofficial][S2, unofficial].
- **Limitations**: Requires benchmarking to determine the optimal fallback threshold (20) [S1, unofficial]. The actual SIMD width of 32 was considered too big for processing more than 2 rays at a time due to overhead [S1, unofficial][S2, unofficial].
- **When to Use**: When standard packetization is inefficient due to sparse acceleration structures with high primitive density per leaf [S1, unofficial][S2, unofficial].
- **When Not to Use**: When the number of high-workload rays exceeds 20, or when rays are highly coherent [S1, unofficial][S2, unofficial].

## Background
The Hybrid Packetization Strategy was introduced in the paper "Two-Level Grids for Ray Tracing on GPUs" by J. Kalojanov, M. Billeter, and P. Slusallek [S1, unofficial][S2, unofficial][S3, unofficial]. It was developed to address the inefficiencies of standard packetization in the context of two-level grids, which are sparse and contain many primitives per leaf [S1, unofficial][S2, unofficial]. The method was tested on NVIDIA GPUs, specifically Fermi architecture (GTX 285, GTX 470) and earlier (GTX 280) [S1, unofficial][S2, unofficial].
