# Ray Tracing and Ray Intersection Methods

Also called: Ray Casting, Ray-Surface Intersection

## Overview
Ray tracing determines the first object intersected by a camera ray by analytically computing intersection distances for simple geometries [S1, unofficial]. It solves the problem of identifying visible surfaces in a scene by computing the distance between the camera and the intersection point for each object [S1, unofficial]. This family sets itself apart from ray-marching by relying on analytical solutions for simple primitives, whereas ray-marching is used when geometry is too complex for analytical intersection or when only inside/outside tests are available [S1, unofficial]. It fails when object geometry is too complex for analytical intersection solutions [S1, unofficial].

## Shared principles
The shared principles of this family are the geometric definition of rays and the parallel execution model.

**Ray Definition**
Rays are defined by an origin $\mathbf{o}$ and a direction $\mathbf{d}$. The direction is typically normalized. The origin is often the camera eye position, but can vary based on the camera model.

**Parallel Execution**
Computations are mapped to parallel threads. Each thread typically processes one or more pixels or samples. Memory access patterns are optimized for coalescing. Synchronization is used to manage data dependencies between threads.

## Subtopics

### [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md)
Binary Search IsoSurface Extraction is a ray-tracing method that locates the intersection of a ray with an isosurface by iteratively halving the interval between two sample points whose scalar field values bracket the target isovalue [1316-binary-search-isosurface-extraction]. It relies on discrete sampling and bisection [1316-binary-search-isosurface-extraction]. Unlike Trilinear Isosurface Intersection which solves for the exact crossing using polynomial roots, this method approximates the intersection through iterative refinement [1316-binary-search-isosurface-extraction]. Choose this method when the initial bracketing interval is known and high precision is not required, or when an analytical solver is too expensive. See [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md).

### [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md)
Trilinear Isosurface Intersection detects if a ray crosses an isosurface defined by a threshold value within a hexahedral cell of a structured grid [2213-trilinear-isosurface-intersection]. It solves for the ray position where the trilinear interpolation of the eight cell corner values yields the desired isovalue [2213-trilinear-isosurface-intersection]. Unlike Dual Contouring which requires Hermite data (normals) to determine point placement, this method computes intersection points directly using cell diagonals or arbitrary rays, relying solely on vertex scalar values [2213-trilinear-isosurface-intersection]. It sets itself apart from Binary Search IsoSurface Extraction by providing an analytical (or semi-analytical) solution via cubic root finding rather than iterative bisection [2213-trilinear-isosurface-intersection]. Choose this method when exact intersection within a structured cell is required. See [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md).

### [Hybrid Implicit Isosurface Ray Tracing](3832-hybrid-implicit-isosurface-ray-tracing.md)
Hybrid Implicit Isosurface Ray Tracing is a method for rendering high-quality, crack-free isosurfaces from rectilinear volumes (including AMR) by combining explicit voxel selection with implicit ray-marching [3832-hybrid-implicit-isosurface-ray-tracing]. It extracts a list of active voxels, builds a BVH over them, and performs implicit ray-isosurface intersections within each voxel without extracting polygons [3832-hybrid-implicit-isosurface-ray-tracing]. It sets itself apart from pure sample-based methods by avoiding fixed step-sizes that miss features in refined regions, and from pure explicit extraction by deferring polygon generation until the final shading stage, allowing for exact implicit intersection [3832-hybrid-implicit-isosurface-ray-tracing]. Choose this method for rectilinear volumes with adaptive refinement where crack-free rendering is critical. See [Hybrid Implicit Isosurface Ray Tracing](3832-hybrid-implicit-isosurface-ray-tracing.md).

### Packet Ray List Merging
Packet Ray List Merging is an optimization where lists of adjacent pixels (typically 2x2 groups) are combined into a single list [S2, unofficial]. This exploits spatial coherence where adjacent pixels share common visible blocks, reducing the number of lists generated and processed [S2, unofficial]. In Phase I, the BONO tree is traversed as in the basic scheme, but lists are created for each packet of rays rather than individual pixels [S2, unofficial]. If a group of pixels overlaps with the projection of the current node, the group's list is processed [S2, unofficial]. During Phase II, the upper bound $k$ on the list size is increased compared to single pixels [S2, unofficial]. Best performance is achieved when $k$ is around 20 for packets, compared to 12 for single pixels [S2, unofficial].

### Neubauer Iso-surface Ray Casting
Neubauer Iso-surface Ray Casting is a traversal optimization that subdivides the complete data set into macro-cells of size $m^3$ [S3, unofficial]. It builds a min/max octree from these macro-cells [S3, unofficial]. At a leaf node, the boundaries of the macro-cell are projected/rasterized onto the image plane to yield a hexagonal footprint [S3, unofficial]. Local rays are then used to traverse the macro-cell grid, reducing the number of traversal steps for pixels covered by the hexagon [S3, unofficial]. The macro-cell size dimension $m$ is usually between 4 and 10 [S3, unofficial]. This approach achieved an average frame rate of 0.8 fps with image resolution 512x512 on a single PIV 1.9 GHz [S3, unofficial].

## Background
Ray tracing originated as a technique to determine which object a ray intersects first to compute pixel color [S1, unofficial]. It is one of the most efficient techniques for simple geometries where analytical intersection points can be computed [S1, unofficial]. When geometry is too complex, ray-marching is used instead [S1, unofficial]. The method has been extended to isosurface rendering, with variants like Neubauer's approach using macro-cells and octrees for traversal optimization [S3, unofficial]. Packet ray techniques have also been developed to exploit spatial coherence in adjacent pixels [S2, unofficial].
