# Hybrid Implicit Isosurface Ray Tracing
Also called: Hybrid Isosurface Method

## Overview
Hybrid Implicit Isosurface Ray Tracing is a rendering technique that combines explicit voxel selection with implicit ray-surface intersection to produce high-quality, crack-free isosurfaces from rectilinear volumes [S1, unofficial]. It solves the problem of surface detail loss and artifacts common in fixed-step sample-based methods by restricting ray traversal to active voxels and performing exact implicit intersections within them [S1, unofficial]. Unlike sibling methods such as [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) which may extract polygons, or [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md) which operates on uniform grids, this method builds a Bounding Volume Hierarchy (BVH) over logical voxels (such as octants in AMR data) and uses an implicit intersection routine, allowing for efficient rendering of adaptive mesh refinement (AMR) data [S1, unofficial].

## How it works
**Inputs:** A rectilinear volume (e.g., regular grid, rectilinear grid, or BS-AMR) provided as a `VoxelSource`.
**Outputs:** A ray-traced image of the isosurface defined by a user-specified isovalue.

**Data Structures:**
1.  **Voxel Abstraction:** Each logical voxel is treated as a cube with trilinearly interpolated scalar values at its vertices.
    *   **Fields:**
        *   `x, y, z`: 3D coordinates of the voxel's origin (3 values).
        *   `width`: Size of the voxel along the x-axis (1 value).
        *   `height`: Size of the voxel along the y-axis (1 value, required for general rectilinear volumes).
        *   `depth`: Size of the voxel along the z-axis (1 value, required for general rectilinear volumes).
        *   `v0...v7`: Scalar values at the 8 vertices of the voxel (8 values).
    *   **Total:** 12 values for general rectilinear volumes; 11 values if width=height=depth (regular grid).
    *   **Active Voxel Encoding:** Active voxels are encoded into a single 64-bit integer reference (e.g., 21:21:21 bit partitioning for coordinates) to allow fast lookup in the `VoxelSource` [S1, unofficial].
2.  **Embree User Geometry:** A primitive list where each primitive corresponds to one active voxel. The primitive's bounding box is queried dynamically from the `VoxelSource` [S1, unofficial].

**Algorithm Steps:**
1.  **Active Voxel Extraction:** The `VoxelSource` generates a list of all active voxels. A voxel is active if its value range (min/max of its 8 vertices) contains the target isovalue [S1, unofficial].
2.  **Reference Encoding:** Each active voxel is assigned a unique 64-bit reference ID [S1, unofficial].
3.  **BVH Construction:**
    *   Create an Embree "user geometry" with a number of primitives equal to the number of active voxels.
    *   Implement a `getBounds` callback for the user geometry. When Embree requests the bounds of a primitive (identified by its index/ID), the callback decodes the 64-bit reference, queries the `VoxelSource` for the voxel's spatial dimensions (`width`, `height`, `depth`, `x`, `y`, `z`), and returns the axis-aligned bounding box (AABB) of the voxel [S1, unofficial].
    *   Embree builds the BVH over these dynamic bounding boxes.
4.  **Ray Traversal and Intersection:**
    *   Traverse rays through the BVH.
    *   For each hit primitive, invoke the intersection routine.
    *   The intersection routine decodes the 64-bit reference to fetch the full voxel data (coordinates, dimensions, 8 vertex values) from the `VoxelSource` [S1, unofficial].
    *   Perform an implicit ray-isosurface intersection within the voxel using the trilinear interpolation function. This is implemented using the technique by Marmitt et al. [27], adapted for ISPC [S1, unofficial].
    *   The intersection routine handles ray packets (4-, 8-, or 16-wide) as required by the underlying ray tracer's SIMD execution model [S1, unofficial].

**Parameters:**
*   **Isovalue:** The scalar value defining the isosurface.

**Edge Cases and Pitfalls:**
*   **Precision:** The 64-bit encoding of voxel coordinates must be sufficient to uniquely identify voxels in the volume. If the volume exceeds the addressable space of the encoding scheme, collisions may occur [S1, unofficial].
*   **Refined Regions:** Fixed-step sample-based methods fail in refined regions because the step size is too large to capture the surface. This hybrid method avoids this by using implicit intersection within each voxel, ensuring detail is preserved regardless of voxel size [S1, unofficial].
*   **Empty Voxels:** Voxels that do not contain the isovalue are excluded from the BVH, reducing memory overhead and traversal cost [S1, unofficial].

## Subtopics

### [Active Cell Filtering](9505-active-cell-filtering.md)
A pre-processing optimization that prunes input cells whose value ranges do not overlap with the isovalue before primitive construction.

### [Dual Cell Optimization for Isosurface Extraction](9508-dual-cell-optimization-for-isosurface-extraction.md)
An optimization that merges eight octants into a single dual cell in non-boundary regions to reduce the number of primitives in the BVH.

## Operating characteristics
*   **Time Complexity:** BVH construction is $O(N \log N)$ where $N$ is the number of active voxels, dominated by Embree's build process. Ray traversal is $O(\log N)$ per ray. Intersection per hit is constant time relative to voxel size but depends on the complexity of the trilinear root-finding algorithm [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of active voxels. Each active voxel requires a 64-bit ID and a BVH node. The `VoxelSource` must store the full volume data or provide fast random access [S1, unofficial].
*   **Performance:** In OSPRay, this method yields better framerates than sample-based isosurface rendering for AMR data. It provides high-quality, crack-free surfaces with more detail in refined regions [S1, unofficial].
*   **Strengths:**
    *   Crack-free surfaces.
    *   High detail in adaptive/refined regions.
    *   Reuses standard BVH builders (Embree).
    *   Supports rectilinear and AMR volumes.
*   **Limitations:**
    *   Requires implementation of a custom intersection routine (Marmitt et al.).
    *   Ray packet efficiency may be low if most rays hit only one voxel at a time, though ISPC handles this gracefully [S1, unofficial].
    *   Not given in the sources: Exact scaling behavior with respect to voxel count or hardware generation.

## Background
The method was introduced by Feng et al. in 2018 as part of the OSPRay project [S1, unofficial]. It integrates into the OSPRay ray tracing framework, extending its existing AMR volume structures. The core intersection technique is based on the work of Marmitt et al. [27]. The method addresses the limitations of previous sample-based isosurface rendering in OSPRay, which suffered from missing features and holes in refined regions due to fixed step sizes [S1, unofficial].
