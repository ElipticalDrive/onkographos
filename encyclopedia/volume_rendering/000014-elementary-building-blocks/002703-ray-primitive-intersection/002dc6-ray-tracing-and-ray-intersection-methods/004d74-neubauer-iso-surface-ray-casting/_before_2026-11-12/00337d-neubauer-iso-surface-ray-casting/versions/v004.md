# Neubauer Iso-surface Ray Casting
Also called: Kd-Jump, Neubauer method

## Overview
Neubauer Iso-surface Ray Casting is a single-kernel iso-surface ray casting method that accelerates ray traversal by combining a min/max octree with projection-based rasterization [S2, unofficial]. It sets itself apart from sibling methods like Binary Search IsoSurface Extraction by using spatial subdivision to skip empty regions rather than stepping through voxels, and from Trilinear Isosurface Intersection by rasterizing macro-cell boundaries to determine ray coverage [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A volumetric dataset, an iso-value threshold, and camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$, image plane resolution).
*   **Output:** A rendered image where pixels intersecting the iso-surface are colored, and empty space is transparent or background-colored.

**Data Structures**
1.  **Macro-cells:** The complete data set is subdivided into cubic macro-cells of size $m^3$.
2.  **Min/Max Octree:** A hierarchical structure built from the macro-cells. Each node stores the minimum and maximum scalar values of the voxels contained within its bounding box. This allows for early rejection: if the iso-value is not within $[min, max]$ of a node, the entire subtree is skipped [S1, unofficial].

**Parameters**
*   $m$: Macro-cell size dimension. Typical values are between 4 and 10 [S1, unofficial].

**Algorithm Steps**
1.  **Preprocessing:**
    *   Subdivide the input volume into macro-cells of size $m^3$.
    *   Compute the min/max scalar values for each macro-cell.
    *   Build the min/max octree from these macro-cells [S1, unofficial].

2.  **Ray Traversal (Per Pixel):**
    *   For each pixel, define a ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$.
    *   Traverse the octree from the root.
    *   At each internal node, check if the ray intersects the node's bounding box.
    *   If it intersects, check the node's min/max values. If the iso-value is outside $[min, max]$, prune this branch [S1, unofficial].
    *   If the node is a leaf, proceed to rasterization.

3.  **Rasterization at Leaf Node:**
    *   Project the 3D boundaries of the macro-cell (leaf node) onto the 2D image plane.
    *   This projection yields a hexagonal footprint on the image plane [S1, unofficial].
    *   Identify all pixels whose centers fall within this hexagonal footprint.
    *   For these pixels, perform local ray traversal within the macro-cell grid to find the exact iso-surface intersection [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Precision:** Floating-point precision errors in ray-box intersection tests can lead to missed intersections or artifacts.
*   **Boundary Conditions:** The hexagonal footprint projection must correctly handle pixels on the edge of the image plane.
*   **Degenerate Input:** If the volume contains no voxels above the iso-value, the octree traversal should quickly prune all branches.

## Subtopics

### [Bézier Clipping for Metaball Ray Casting](9481-b-zier-clipping-for-metaball-ray-casting.md)
This method computes the ray-isosurface intersection for metaballs by representing the scalar density field along a ray as a polynomial in Bézier form and applying Bézier clipping to find the root. It sets itself apart from standard Newton-Raphson approaches by providing robust root isolation and handling multiple intersections within a single interval without derivative evaluation, building on [Neubauer Iso-surface Ray Casting](7024-neubauer-iso-surface-ray-casting.md).

## Operating characteristics
*   **Time Complexity:** The octree traversal reduces the number of steps compared to linear voxel stepping. The rasterization step at leaf nodes further optimizes by processing multiple pixels at once for the same macro-cell [S1, unofficial].
*   **Memory Complexity:** The min/max octree requires additional memory proportional to the number of nodes in the tree. The source notes that the octree approach consumes much less additional memory than some other acceleration structures [S1, unofficial].
*   **Measured Performance:** On a single PIV 1.9 GHz processor, an average frame rate of 0.8 fps was achieved with a 512x512 image resolution [S1, unofficial].
*   **Scalability:** In a cluster environment, performance scales linearly with the number of render nodes. For the Visible Female dataset (428 MB), performance ranged from 1 fps with 1 node to 22 fps with 32 nodes [S1, unofficial].
*   **Strengths:** Efficient space-leaping via the octree; reduced memory overhead compared to some alternatives; suitable for cluster rendering [S1, unofficial].
*   **Limitations:** Slower than Wald's kd-tree approach for certain datasets (e.g., Visible Female), where Wald achieved ~8.1 fps on a single PC compared to Neubauer's 1-22 fps on a cluster [S1, unofficial].

## Background
The method was introduced by Neubauer et al. [NMHW02] and is often referred to as Kd-Jump in later literature [HL09]. It is used as a baseline for comparison in single-kernel rendering pipelines [S2, unofficial]. The approach builds on earlier work in tetrahedral mesh ray tracing and projection-based rendering [S1, unofficial].
