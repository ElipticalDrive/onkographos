# Multi-Stage Rasterization for Shaded Isosurfaces

Also called: Fast Shaded Isosurfaces adaptation

## Overview
Multi-Stage Rasterization for Shaded Isosurfaces is an adaptation of the Fast Shaded Isosurfaces method for PC hardware, using multi-stage rasterization and 2D textures to enable efficient rendering of shaded isosurfaces [S1]. It replaces iterative ray-marching with a two-pass rasterization pipeline that leverages fixed-function register combiners for gradient interpolation and dot-product shading [S1]. Unlike general volume rendering that integrates opacity, this method extracts and shades a specific isosurface boundary [S1]. It builds on [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) by rasterizing pre-computed voxel data instead of marching rays [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset represented as a sequence of 2D slices. Each slice contains scalar values (intensity) and pre-computed voxel gradients [S1].
*   **Output:** A shaded 2D image of the isosurface projected onto the screen [S1].

**Data Structures:**
The volume is decomposed into 2D textures [S1].
*   **Texture 0:** Stores the voxel gradients. The RGB components hold the gradient vector $\tilde{n} = (n_x, n_y, n_z)$ [S1].
*   **Texture 1:** Stores the scalar intensity values. The Alpha component holds the intensity $I$. The RGB components are unused or set to zero [S1].
*   **Constant Color Registers:**
    *   `const color 1`: Stores the light direction vector $\tilde{l}$ [S1].
    *   `const color 2`: Stores the diffuse light color $C_{diffuse}$ [S1].
    *   `const color 3`: Stores the ambient light color $C_{ambient}$ [S1].

**Numbered Steps:**
1.  **Gradient and Intensity Encoding:** Compute the voxel gradient $\tilde{n}$ for each voxel in the volume. Encode $\tilde{n}$ into the RGB components of a 2D texture representing the volume slice. Encode the scalar intensity $I$ into the Alpha component of a separate 2D texture [S1].
2.  **First Pass: Interpolation (General Combiner 0):** Render the volume slices using a multi-texture interpolation technique. Input A is the RGB output from Texture 0 (gradient $\tilde{n}$). The combiner interpolates the gradient vector $\tilde{n}$ across the screen space based on the fragment's position relative to the slice boundaries. The result is the interpolated normal $\tilde{n}_{interp}$. The Alpha output is the interpolated intensity [S1].
3.  **Second Pass: Lighting Calculation (General Combiner 1):** Enable the second general combiner to compute the diffuse lighting term. Input A is the RGB output of Combiner 0 (the interpolated normal $\tilde{n}_{interp}$). Input B is Constant Color Register 1 (the light vector $\tilde{l}$). The operation computes the dot product $D = \tilde{n}_{interp} \cdot \tilde{l}$. The Alpha component is not modified by Combiner 1 and remains the interpolated intensity from the previous stage [S1].
4.  **Final Compositing:** Combine the diffuse lighting term with ambient lighting. Input A is the dot product $D$. Input B is Constant Color Register 2 (diffuse light color $C_{diffuse}$). Input C is Constant Color Register 3 (ambient light color $C_{ambient}$). The operation calculates the final color $C_{final} = D \cdot C_{diffuse} + C_{ambient}$ [S1].

**Formulas:**
*   $\tilde{n}$: voxel gradient vector.
*   $\tilde{l}$: light direction vector.
*   $I$: scalar intensity value.
*   $\alpha$: interpolation factor between slice $i$ and slice $i+1$.
*   $D$: dot product $\tilde{n}_{interp} \cdot \tilde{l}$.
*   $C_{diffuse}, C_{ambient}$: RGB light color vectors.
*   $C_{final}$: output pixel color.

**Parameters and Typical Values:**
*   **Light Vector $\tilde{l}$:** Typically normalized. Direction depends on camera or scene setup.
*   **Light Colors:** $C_{diffuse}$ and $C_{ambient}$ are RGB vectors.
*   **Signed Fixed-Point:** The hardware supports signed fixed-point values for combiner inputs, allowing direct storage of negative gradient components without normalization or biasing [S1].

**Edge Cases and Pitfalls:**
*   **Single Light Source:** The method is restricted to a single light source due to the fixed-function dot product calculation in the combiner pipeline [S1].
*   **Monochrome Display:** The description implies a monochrome or single-color shading model unless additional combiner stages are added for color mixing [S1].
*   **Gradient Accuracy:** The quality of the shading depends on the accuracy of the pre-computed voxel gradients [S1].

**Pseudocode:**
```python
def render_shaded_isosurface(volume_slices, light_vector, diffuse_color, ambient_color):
    """
    Simulates the multi-stage register combiner pipeline for shaded isosurfaces.
    volume_slices: list of 2D arrays, each (H, W, 4). RGB=gradient, Alpha=intensity.
    light_vector, diffuse_color, ambient_color: (3,) arrays.
    """
    output_image = None
    
    for i in range(len(volume_slices) - 1):
        alpha = 0.5  # Interpolation factor between slice i and i+1 [G]
        
        s_curr = volume_slices[i]
        s_next = volume_slices[i + 1]
        
        # Combiner 0: Interpolate intermediate slices
        # Interpolate RGB (gradient n) and Alpha (intensity I)
        n_interp = (1.0 - alpha) * s_curr[:, :, :3] + alpha * s_next[:, :, :3]
        i_interp = (1.0 - alpha) * s_curr[:, :, 3] + alpha * s_next[:, :, 3]
        
        # Combiner 1: Compute dot product A . B
        # Input A: n_interp, Input B: light_vector
        # D = n_interp . light_vector
        D = n_interp[:, :, 0] * light_vector[0] + n_interp[:, :, 1] * light_vector[1] + n_interp[:, :, 2] * light_vector[2]
        
        # Final Combiner: C_final = D * C_diffuse + C_ambient
        final_rgb = D[:, :, None] * diffuse_color + ambient_color
        
        output_image = final_rgb
        
    return output_image
```

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels in the screen space projection. The complexity is dominated by the rasterization and texture sampling, which are hardware-accelerated [S1].
*   **Memory Complexity:** $O(V)$ where $V$ is the volume size, stored in 2D textures.
*   **Performance:** Enables interactive frame rates for shaded isosurfaces on standard PC hardware [S1].
*   **Strengths:** Efficient use of fixed-function GPU hardware; avoids software ray-marching.
*   **Limitations:** Restricted to single light sources; limited to monochrome or simple shading models without additional combiner stages; requires pre-computation of gradients [S1].

## Background
The method is an adaptation of the "Fast Shaded Isosurfaces" algorithm, designed to leverage the capabilities of standard PC graphics hardware (specifically OpenGL register combiners) for volume visualization. It was developed to provide efficient rendering of shaded isosurfaces at interactive frame rates [S1].
