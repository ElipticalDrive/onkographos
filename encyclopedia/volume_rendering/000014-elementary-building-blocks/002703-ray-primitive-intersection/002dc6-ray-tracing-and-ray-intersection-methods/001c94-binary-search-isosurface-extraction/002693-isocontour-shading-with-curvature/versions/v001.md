# Isocontour Shading with Curvature

Also called: RayEvaluationSteppingIso

## Overview
Isocontour Shading with Curvature is a shading technique applied to isosurfaces extracted via binary search stepping. It enhances the visual representation of the surface by highlighting specific isocontour levels and optionally modulating the color based on surface curvature features (first, second, mean, or Gaussian curvature) or a pre-computed curvature texture. It distinguishes itself from sibling methods like [Surface Location via Segment Endpoint Values](3756-surface-location-via-segment-endpoint-values.md) by explicitly incorporating curvature data and multi-level isocontour highlighting into the shading kernel, rather than relying solely on geometric position or simple normal-based shading.

## How it works
The method operates as a post-processing shading step applied to rays that have successfully intersected an isosurface. It requires the surface position (determined by the parent [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) method), the surface normal, and optionally curvature data.

### Inputs and Outputs
**Inputs:**
1.  `rayDirections`: Tensor of shape $(N, 3)$, containing the normalized direction vectors of the rays.
2.  `normals`: Tensor of shape $(N, 3)$, containing the surface normals at the intersection points.
3.  `curvature`: Optional tensor of shape $(N, 2)$, containing curvature values (e.g., $k_1, k_2$). If the selected surface feature requires curvature but this tensor is not provided, the method throws a runtime error [S1, unofficial].
4.  `isovalue_`: The scalar threshold used for extraction. Default: $0.5$ [S1, unofficial].
5.  `numIsocontours_`: Number of isocontours to highlight. Default: $5$ [S1, unofficial].
6.  `isocontourRange_`: Range parameter for highlighting. Default: $5$ [S1, unofficial].
7.  `binarySearchSteps_`: Number of refinement steps. Default: $0$ [S1, unofficial].

**Outputs:**
1.  `colors`: Tensor of shape $(N, 4)$, containing the final RGBA color for each ray.

### Data Structures
The method utilizes two CUDA texture objects for sampling:

1.  **Isocontour Texture (`isocontourTextureObject_`)**:
    *   **Layout**: CUDA array `isocontourTextureArray_`.
    *   **Channel Descriptor**: `(32, 32, 32, 32, cudaChannelFormatKindFloat)` [S1, unofficial].
    *   **Size**: `ISOCONTOUR_TEXTURE_RESOLUTION` (value not specified in sources) [S1, unofficial].
    *   **Addressing**: Clamp.
    *   **Filtering**: Linear.
    *   **Coordinates**: Normalized.

2.  **Curvature Texture (`curvatureTextureObject_`)**:
    *   **Layout**: CUDA array `curvatureTextureArray_`.
    *   **Channel Descriptor**: `(8, 8, 8, 8, cudaChannelFormatKindUnsigned)` [S1, unofficial].
    *   **Size**: `textureWidth` x `textureHeight` (loaded from `shaders/curvature-texture.png`, RGBA 8-bit) [S1, unofficial].
    *   **Addressing**: Clamp.
    *   **Filtering**: Linear.
    *   **Read Mode**: Normalized float.

### Parameters and Constants
*   `ISO_WIDTH`: Constant value $20$ [S1, unofficial].
*   `COLOR_NEGATIVE`: Magenta.
*   `COLOR_ZERO`: White.
*   `COLOR_POSITIVE`: Green.
*   `COLOR_ISO_ZERO`: Dark blue.
*   `COLOR_ISO_OTHER`: Black.
*   `KERNEL_DOUBLE_PRECISION`: Integer flag ($1$ for double, $0$ for single) [S1, unofficial].
*   `RAY_EVALUATION_STEPPING__SURFACE_FEATURE`: Integer enum indicating the selected surface feature (e.g., curvature type) [S1, unofficial].

### Algorithm Steps
The shading kernel `RayEvaluationIsoShadingCurvature` executes the following logic for each ray $i$:

1.  **Determine Base Color from Isocontour Texture**:
    The method maps the ray's scalar field value (or a normalized parameter derived from the intersection) to a texture coordinate. Let $v_1$ be the normalized value in $[-1, +1]$.
    $$ v_1 = 2 \cdot \frac{i}{\text{ISOCONTOUR\_TEXTURE\_RESOLUTION} - 1.0} - 1.0 $$
    Where $i$ is the index in the texture array [S1, unofficial].
    Compute base color $C_{base}$:
    $$
    C_{base} = \begin{cases} 
    \text{lerp}(\text{COLOR\_NEGATIVE}, \text{COLOR\_ZERO}, v_1 + 1) & \text{if } v_1 < 0 \\
    \text{lerp}(\text{COLOR\_ZERO}, \text{COLOR\_POSITIVE}, v_1) & \text{otherwise}
    \end{cases}
    $$
    Here, `lerp(a, b, t)` is interpreted as linear interpolation between $a$ and $b$ with parameter $t$ clamped to $[0, 1]$. Note that for $v_1 < 0$, the interpolation factor is $v_1 + 1 \in [0, 1]$. For $v_1 \ge 0$, the factor is $v_1 \in [0, 1]$ [S1, unofficial].

2.  **Apply Isocontour Highlighting**:
    If `numIsocontours_` $> 0$:
    $$ v_2 = v_1 \cdot \text{numIsocontours\_} $$
    $$ \text{closestIsovalue} = \text{round}(v_2) $$
    $$ \text{distanceToIso} = |v_2 - \text{closestIsovalue}| $$
    $$ \text{isoBlend} = \max(0.0, 1.0 - \text{ISO\_WIDTH} \cdot \text{distanceToIso}) $$
    Determine highlight color $C_{iso}$:
    $$
    C_{iso} = \begin{cases} 
    \text{COLOR\_ISO\_ZERO} & \text{if } \text{closestIsovalue} == 0 \\
    \text{COLOR\_ISO\_OTHER} & \text{otherwise}
    \end{cases}
    $$
    Blend the base color with the highlight:
    $$ C_{final} = \text{lerp}(C_{base}, C_{iso}, \text{isoBlend}) $$
    If `numIsocontours_` $\le 0$, $C_{final} = C_{base}$ [S1, unofficial].

3.  **Curvature Modulation (Optional)**:
    If the selected surface feature requires curvature (indicated by `RAY_EVALUATION_STEPPING__SURFACE_FEATURE`):
    *   If `curvature` tensor is provided:
        *   If feature is `CURVATURE_TEXTURE`: Sample from `curvatureTextureObject_` using the curvature values as coordinates.
        *   Otherwise: Use the values from the `curvature` tensor directly (e.g., mean curvature $\frac{k_1+k_2}{2}$ or Gaussian curvature $k_1 \cdot k_2$) to modulate the color or alpha. The exact modulation formula is not specified in the sources, but the kernel accepts `accCurvature` [S1, unofficial].
    *   If `curvature` tensor is **not** provided:
        *   Throw runtime error: "A surface feature requiring curvature is needed, but no curvature tensor is passed" [S1, unofficial].

4.  **Output**:
    Write $C_{final}$ (and alpha, typically $1.0$ or derived from blending) to `accColors` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Missing Curvature**: If a surface feature requiring curvature is selected but no curvature tensor is passed, the method fails with a runtime error [S1, unofficial].
*   **Batched Isovalues**: If `isovalue_` is a tensor (batched), the batch size is determined by the first dimension of the tensor. Otherwise, it returns an empty optional [S1, unofficial].
*   **Precision**: The method supports double precision via `KERNEL_DOUBLE_PRECISION` flag [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of rays $N$, as it involves per-ray texture lookups and arithmetic operations.
*   **Memory Complexity**: Depends on the size of the isocontour and curvature textures. The isocontour texture is `ISOCONTOUR_TEXTURE_RESOLUTION` floats. The curvature texture is `textureWidth` x `textureHeight` unsigned bytes [S1, unofficial].
*   **Strengths**: Provides detailed visual feedback on surface topology via curvature and highlights specific density levels via isocontours.
*   **Limitations**: Requires pre-computed curvature data or textures. Performance depends on texture sampling efficiency.
*   **When to use**: When visualizing the geometric properties (curvature) of an isosurface or emphasizing specific density thresholds is required.
*   **When not to use**: When curvature data is unavailable and cannot be approximated, or when performance is critical and texture sampling is a bottleneck.

## Background
The method is part of the `fV-SRN` (Feature Volume - Scene Reconstruction Networks) project, an unofficial implementation by shamanDevel [S1, unofficial]. It is designed to work with Scene Reconstruction Networks (SRNs) that use tensor cores for volume interpolation [S1, unofficial]. The shading method is implemented in CUDA and integrated into the `renderer_ray_evaluation_stepping_iso.cuh` module [S1, unofficial].
