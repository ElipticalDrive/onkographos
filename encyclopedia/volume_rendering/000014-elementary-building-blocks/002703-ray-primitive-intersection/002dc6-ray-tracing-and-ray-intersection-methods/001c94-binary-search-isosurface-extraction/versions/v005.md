# Binary Search IsoSurface Extraction

Also called: Bisection Isosurface Extraction, Isovalue Stepping, RayEvaluationSteppingIso

## Overview
Binary Search IsoSurface Extraction is a ray-primitive intersection method that approximates the position of an isosurface between two sample points by iteratively halving the interval based on scalar field values [S1, unofficial]. It solves the problem of locating the precise intersection of a ray with a specific isovalue within a volumetric scalar field, offering higher accuracy than discrete marching cubes by refining the hit position through bisection [S3, unofficial]. It distinguishes itself from sibling methods like [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md) by using iterative refinement rather than analytical root-finding, and from [Hybrid Implicit Isosurface Ray Tracing](3832-hybrid-implicit-isosurface-ray-tracing.md) by relying on discrete texture sampling rather than implicit function evaluation [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   `left`: The 3D starting point of the search interval (typically the ray entry point or a previous sample).
    *   `right`: The 3D ending point of the search interval (typically the ray exit point or a subsequent sample).
    *   `iso`: The target isovalue (scalar density) defining the surface. Can be a single scalar or a batched tensor [S2, unofficial].
    *   `texVol`: The volumetric texture object containing the scalar field data [S1, unofficial].
    *   `rec_depth`: The fixed number of bisection iterations [S1, unofficial].
*   **Outputs**:
    *   `surf`: The 3D position of the estimated isosurface intersection, calculated as the midpoint of the final interval [S1, unofficial].

**Data Structures**
The method operates on standard 3D vectors and scalar values. In GPU implementations (e.g., CUDA), parameters are often packed into a struct for constant memory access [S2, unofficial]:

```cpp
struct Parameters {
    scalar_t stepsize;
    int binarySearchSteps;
    // If isovalue is batched:
    ::kernel::Tensor1Read<scalar_t> isovalue;
    // If isovalue is scalar:
    // scalar_t isovalue; 
    scalar_t isocontourRange;
    cudaTextureObject_t isocontourTexture;
};
```
*Note: The specific fields `binarySearchSteps`, `isocontourRange`, and `isocontourTexture` are used in extended implementations for curvature shading, but the core binary search only requires `stepsize` (for world-space conversion if needed) and the volume texture [S2, unofficial].*

**Numbered Steps**
1.  Initialize the recursion depth limit `rec_depth` to 5 [S1, unofficial].
2.  Loop `iter` from 0 to `rec_depth - 1`:
    a. Compute the midpoint of the current interval: `mid = (right + left) / 2.0` [S1, unofficial].
    b. Sample the scalar value at the midpoint from the volume texture: `curIso = texture(texVol, mid).x` [S1, unofficial].
    c. Compare `curIso` with the target `iso`:
        i. If `curIso <= iso`, the surface is in the right half (or at the midpoint); update `left = mid` [S1, unofficial].
        ii. Else (`curIso > iso`), the surface is in the left half; update `right = mid` [S1, unofficial].
3.  After the loop, calculate the final surface position as the midpoint of the remaining interval: `surf = (right + left) / 2.0` [S1, unofficial].

**Formulas**
*   Midpoint Calculation:
    $$ \mathbf{mid} = \frac{\mathbf{right} + \mathbf{left}}{2} $$
*   Interval Update:
    $$ \mathbf{left}_{new} = \begin{cases} \mathbf{mid} & \text{if } f(\mathbf{mid}) \le \sigma \\ \mathbf{left} & \text{otherwise} \end{cases} $$
    $$ \mathbf{right}_{new} = \begin{cases} \mathbf{mid} & \text{if } f(\mathbf{mid}) > \sigma \\ \mathbf{right} & \text{otherwise} \end{cases} $$
    Where $f(\mathbf{mid})$ is the sampled scalar value and $\sigma$ is the isovalue.
*   Final Position:
    $$ \mathbf{surf} = \frac{\mathbf{right}_{final} + \mathbf{left}_{final}}{2} $$

**Parameters**
*   `rec_depth`: Fixed number of bisection iterations. Default/Fixed value: 5 [S1, unofficial].
*   `iso`: The isovalue. Default: 0.5 [S2, unofficial].
*   `binarySearchSteps`: In extended variants, the number of binary search steps to refine hit position. Range: 0-20. Default: 0 [S2, unofficial].

**Edge Cases and Pitfalls**
*   **Bracketing Requirement**: The method assumes the scalar values at `left` and `right` bracket the isovalue (i.e., one is $\le iso$ and the other is $> iso$). If the surface is not present in the interval, the algorithm converges to the midpoint of the interval, which may not be a valid surface point [S1, unofficial].
*   **Precision**: The fixed iteration count of 5 limits the precision. With 5 iterations, the interval size is reduced by a factor of $2^5 = 32$. For high-resolution volumes, this may not be sufficient for pixel-perfect accuracy [S1, unofficial].
*   **Texture Sampling**: The method relies on `texture(texVol, mid)`. If `mid` falls outside the volume bounds, undefined behavior or clamping occurs, depending on the texture addressing mode [S1, unofficial].

**Pseudocode**
```python
def binary_search_isosurface_extraction(left: vec3, right: vec3, iso: float, texVol: Texture, rec_depth: int = 5) -> vec3:
    """
    Approximates the isosurface intersection using binary search.
    
    Args:
        left: Start point of the interval.
        right: End point of the interval.
        iso: Target isovalue.
        texVol: Volumetric texture object.
        rec_depth: Number of bisection iterations.
        
    Returns:
        surf: Estimated surface position.
    """
    # Initialize boundaries
    current_left = left
    current_right = right
    
    for iter in range(rec_depth):
        # Compute midpoint
        mid = (current_right + current_left) / 2.0
        
        # Sample scalar value at midpoint
        # Note: texture() performs interpolation based on texture settings
        cur_iso = texture(texVol, mid).x
        
        # Update interval based on comparison
        if cur_iso <= iso:
            current_left = mid
        else:
            current_right = mid
            
    # Return final midpoint
    surf = (current_right + current_left) / 2.0
    return surf
```

## Subtopics

### [Surface Location via Segment Endpoint Values](3756-surface-location-via-segment-endpoint-values.md)
This variant locates isosurface intersections as a function of the scalar field values at the segment endpoints along a ray to eliminate coverage gaps that cause aliasing artifacts. It builds on [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) by using endpoint values to determine surface presence without intermediate sampling checks [G]. It is chosen when aliasing artifacts from discrete sampling are critical, and it distinguishes itself by avoiding the iterative midpoint sampling of the parent method in favor of endpoint analysis.

### [Isocontour Shading with Curvature](3819-isocontour-shading-with-curvature.md)
Isocontour Shading with Curvature is a shading method for isosurfaces that uses surface features including first curvature ($k_1$), second curvature ($k_2$), mean curvature ($(k_1+k_2)/2$), Gaussian curvature ($k_1 \cdot k_2$), or a curvature texture. It distinguishes itself from sibling methods by explicitly incorporating curvature data and multi-level isocontour highlighting into the shading kernel. It is chosen when visual emphasis on surface geometry is required, and it builds on the intersection point found by [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) to apply curvature-based coloring.

### [Multi-Stage Rasterization for Shaded Isosurfaces](5394-multi-stage-rasterization-for-shaded-isosurfaces.md)
Multi-Stage Rasterization for Shaded Isosurfaces is a hardware-accelerated technique for rendering shaded isosurfaces from volumetric data on standard PC graphics hardware. It adapts the "Fast Shaded Isosurfaces" algorithm by utilizing multi-stage rasterization and 2D textures to compute surface normals and lighting interactions efficiently. Unlike general volume rendering methods that integrate opacity, this method focuses on extracting and shading a specific isosurface boundary. It is distinct from [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) by replacing iterative ray-marching with a two-pass rasterization pipeline that leverages the GPU's fixed-function register combiners for gradient interpolation and dot-product shading.

## Operating characteristics
*   **Time Complexity**: $O(k)$ where $k$ is the number of binary search iterations (fixed at 5 in the standard implementation) [S1, unofficial]. Each iteration involves one vector addition, one division, and one texture lookup.
*   **Memory Complexity**: $O(1)$ auxiliary memory per ray, as it only stores the current interval bounds and midpoint [S1, unofficial].
*   **Measured Performance**: Performance depends heavily on texture fetch latency. The fixed iteration count makes it predictable, but less accurate than higher-iteration methods or analytical solutions [S1, unofficial].
*   **Scaling**: Scales linearly with the number of rays (pixels) in a parallel execution model [G].
*   **Strengths**: Simple to implement, robust against noise if the bracketing condition is met, and provides sub-voxel accuracy compared to simple ray marching [S1, unofficial].
*   **Limitations**: Requires the isovalue to be bracketed by the interval endpoints; fails if the surface is not present or if the interval is too large for the fixed iteration count [S1, unofficial]. Not suitable for complex topologies where multiple intersections exist within a single interval without additional logic [S1, unofficial].
*   **When to Use**: When sub-voxel accuracy is needed for a single isosurface and the ray is guaranteed to intersect the surface within the search interval [S1, unofficial].
*   **When Not to Use**: When the surface topology is complex with multiple intersections per ray, or when the bracketing condition cannot be guaranteed [S1, unofficial].

## Background
Binary Search IsoSurface Extraction originates from the general class of ray evaluation stepping methods in volume rendering [S2, unofficial]. It is a specific application of the bisection method (binary search) to the problem of isosurface extraction, where the scalar field is treated as a function along the ray [S1, unofficial]. The method is often compared to marching cubes, which produces similar results but with lower accuracy due to its discrete grid-based approach [S3, unofficial]. It is used in software ray casting and hardware-accelerated volume rendering pipelines where precise surface localization is required [S3, unofficial].
