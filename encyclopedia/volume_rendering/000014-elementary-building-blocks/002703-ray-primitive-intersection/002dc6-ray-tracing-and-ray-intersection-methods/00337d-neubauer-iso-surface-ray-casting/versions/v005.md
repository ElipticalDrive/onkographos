# Neubauer Iso-surface Ray Casting
Also called: Kd-Jump, Neubauer method

## Overview
Neubauer Iso-surface Ray Casting is a single-kernel iso-surface ray casting method that uses a min/max octree to accelerate ray traversal by skipping empty regions of the volume data [S2, S1, unofficial]. It sets itself apart from sibling methods like [Binary Search IsoSurface Extraction](1316-binary-search-isosurface-extraction.md) and [Trilinear Isosurface Intersection](2213-trilinear-isosurface-intersection.md) by relying on a hierarchical spatial subdivision (octree) with boundary rasterization for culling, rather than direct scalar field evaluation or binary search along the ray [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D scalar volume dataset, an iso-value threshold, and camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$).
- Output: A 2D image where pixels are colored based on the intersection of rays with the iso-surface.

**Data Structures:**
- **Macro-cells:** The volume is subdivided into cubic blocks of size $m^3$.
- **Min/Max Octree:** A hierarchical structure built from the macro-cells. Each node stores the minimum and maximum scalar values found within its bounding volume. This allows for early termination if the iso-value lies outside the $[min, max]$ range of a node [S1, unofficial].

**Steps:**
1. **Preprocessing:**
   - Subdivide the complete data set into macro-cells of size $m^3$ [S1, unofficial].
   - Build a min/max octree from these macro-cells [S1, unofficial].
2. **Ray Traversal (Per Pixel):**
   - Traverse the octree starting from the root.
   - At each internal node, check the min/max values. If the iso-value is not within $[min, max]$, prune the subtree [S1, unofficial].
   - Continue traversal until a leaf node is reached.
3. **Leaf Processing:**
   - At a leaf node (representing a macro-cell), project or rasterize the boundaries of the macro-cell onto the image plane [S1, unofficial].
   - This projection yields a hexagonal footprint on the image plane [S1, unofficial].
   - Identify pixels that fall within this hexagonal footprint.
   - For each such pixel, generate a local ray and traverse the macro-cell grid to find the iso-surface intersection [S1, unofficial].
   - The local traversal within the macro-cell reduces the number of octree traversal steps because pixels covered by the same hexagon share similar traversal paths [S1, unofficial].

**Parameters:**
- $m$: Macro-cell size dimension. Typical values are between 4 and 10 [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision issues may arise during the projection/rasterization of macro-cell boundaries if not handled carefully [S1, unofficial].
- The method assumes the volume data is static or changes infrequently, as the octree construction is a preprocessing step [S1, unofficial].

**Pseudocode:**
```python
def neubauer_ray_casting(volume, iso_value, camera, m):
    # Preprocessing
    macro_cells = subdivide_volume(volume, m)
    octree = build_min_max_octree(macro_cells)
    
    image = create_empty_image(camera.resolution)
    
    for pixel in camera.pixels:
        ray = camera.get_ray(pixel)
        color = trace_ray(ray, octree, iso_value, m)
        image.set_pixel(pixel, color)
        
    return image

def trace_ray(ray, octree, iso_value, m):
    # Traverse octree
    node = octree.root
    while node is not None:
        if not is_in_range(node.min_val, node.max_val, iso_value):
            return None # Pruned
        
        if node.is_leaf:
            # Leaf processing
            hexagon = project_macro_cell_boundaries(node, camera)
            if pixel_in_hexagon(ray.pixel, hexagon):
                # Local traversal within macro-cell
                intersection = traverse_macro_cell_grid(ray, node.data, iso_value, m)
                if intersection is not None:
                    return compute_color(intersection, volume)
            return None # No intersection in this macro-cell
        
        # Move to children
        node = get_next_node(node, ray)
    
    return None
```

## Subtopics

### [Bézier Clipping for Metaball Ray Casting](9481-b-zier-clipping-for-metaball-ray-casting.md)
This method computes the ray-isosurface intersection for metaballs by representing the scalar density field along a ray as a polynomial in Bézier form and applying Bézier clipping to find the root. It sets itself apart from standard Newton-Raphson approaches by providing robust root isolation and handling multiple intersections within a single interval without derivative evaluation, building on [Neubauer Iso-surface Ray Casting](7024-neubauer-iso-surface-ray-casting.md).

## Operating characteristics
- **Time Complexity:** The octree traversal reduces the number of steps compared to linear traversal, but the complexity depends on the tree depth and the distribution of the iso-surface [S1, unofficial].
- **Memory Complexity:** The min/max octree requires additional memory for the tree structure, but it is more memory-efficient than some other acceleration structures like kd-trees for large datasets [S1, unofficial].
- **Performance:** On a single PIV 1.9 GHz processor, an average frame rate of 0.8 fps was achieved with a 512x512 image resolution [S1, unofficial]. In a cluster setting, the Visible Female dataset (428 MB) rendered at 1 fps with 1 render node and up to 22 fps with 32 nodes [S1, unofficial].
- **Comparison:** The performance is almost five times slower than Wald's approach for the Visible Female dataset (Wald: ~8.1 fps on single PC vs DeMarle: ~1-22 fps on cluster) [S1, unofficial].
- **Strengths:** Efficient space leaping for transparent regions; reduced memory overhead compared to kd-tree approaches [S1, unofficial].
- **Limitations:** Slower than optimized kd-tree based methods on single machines; requires preprocessing for octree construction [S1, unofficial].

## Background
The method was introduced by Neubauer et al. in 2002 [S1, unofficial]. It is used as a baseline for comparison in single-kernel iso-surface ray casting implementations [S2, unofficial]. The approach builds on earlier work in min/max octrees for volume rendering [S1, unofficial].
