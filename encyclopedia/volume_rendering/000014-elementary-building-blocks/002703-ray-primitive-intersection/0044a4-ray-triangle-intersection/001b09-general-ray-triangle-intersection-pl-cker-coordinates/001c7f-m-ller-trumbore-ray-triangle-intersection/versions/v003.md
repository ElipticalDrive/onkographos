# Möller-Trumbore Ray-Triangle Intersection

Also called: MT Algorithm, Möller-Trumbore, Ray-Triangle Intersection, SDF Triangle Distance and Ray Intersection, TriRayIntersectCUDA, TriRayIntersection, hitTriangle, udTriangle

## Overview
The Möller-Trumbore algorithm computes the intersection of a ray (origin $O$, direction $D$) with a triangle defined by vertices $V_0, V_1, V_2$, returning the intersection distance $t$ and barycentric coordinates $(u, v)$ [S1, S4, unofficial]. It solves for the intersection point by translating the ray origin and changing the vector basis, yielding a $(t, u, v)^T$ vector without explicitly computing or storing the triangle's plane equation [S5, unofficial]. This approach offers minimal memory overhead and is considered the fastest routine for triangles lacking precomputed plane equations [S5, unofficial].

## How it works
**Inputs:**
- Ray origin $O$ (float3) [G].
- Ray direction $D$ (float3) [G].
- Triangle vertices $V_0, V_1, V_2$ (float3) [S1, S4, unofficial].
- Epsilon threshold $\epsilon$ for numerical stability (default $10^{-6}$) [S1, S4, unofficial].

**Outputs:**
- Intersection distance $t$ (float) [S1, S4, unofficial].
- Barycentric coordinates $u, v$ (float) [S1, S4, unofficial].
- Boolean hit status.

**Data Structures:**
- The algorithm operates on standard 3D vectors [G]. No persistent data structures are required beyond the input vertices [G]. In GPU implementations storing triangles in textures, vertices are packed as 3 consecutive `float3` entries (9 floats total per triangle) [S3, unofficial].

**Steps:**
1. **Compute Edge Vectors:** Calculate two edge vectors from $V_0$:
   $$ e_1 = V_1 - V_0 $$
   $$ e_2 = V_2 - V_0 $$
2. **Compute Helper Vector P:** Calculate the cross product of the ray direction and the second edge:
   $$ P = D \times e_2 $$
3. **Compute Determinant:** Calculate the dot product of the first edge and vector $P$:
   $$ det = e_1 \cdot P $$
4. **Check for Parallelism:** If $|det| < \epsilon$ (where $\epsilon$ is typically $10^{-6}$ or $10^{-8}$), the ray is parallel to the triangle plane or lies in it. Return no hit [S1, S2, S4, unofficial].
5. **Compute Inverse Determinant:**
   $$ inv\_det = 1.0 / det $$
6. **Compute Vector T:** Calculate the vector from $V_0$ to the ray origin:
   $$ T = O - V_0 $$
7. **Compute Barycentric Coordinate u:** Calculate the dot product of $T$ and $P$:
   $$ u = (T \cdot P) \cdot inv\_det $$
   If $u < 0$ or $u > 1$, the intersection lies outside the triangle's edge boundaries. Return no hit [S1, S4, unofficial].
8. **Compute Helper Vector Q:** Calculate the cross product of $T$ and $e_1$:
   $$ Q = T \times e_1 $$
9. **Compute Barycentric Coordinate v:** Calculate the dot product of the ray direction $D$ and vector $Q$:
   $$ v = (D \cdot Q) \cdot inv\_det $$
   If $v < 0$ or $u + v > 1$, the intersection lies outside the triangle. Return no hit [S1, S4, unofficial].
10. **Compute Intersection Distance t:** Calculate the dot product of edge $e_2$ and vector $Q$:
    $$ t = (e_2 \cdot Q) \cdot inv\_det $$
    If $t < \epsilon$, the intersection is behind the ray origin. Return no hit [G].
11. **Result:** The ray intersects the triangle at distance $t$. The intersection point is $O + tD$. The barycentric coordinates are $(u, v)$, and the third coordinate is $w = 1 - u - v$ [S4, G, unofficial].

**Pseudocode:**

```python
def moller_trumbore(ray_origin, ray_direction, v0, v1, v2, epsilon=1e-6):
    """
    Computes ray-triangle intersection using the Möller-Trumbore algorithm.
    
    Args:
        ray_origin: (float, float, float) Ray origin O.
        ray_direction: (float, float, float) Ray direction D.
        v0, v1, v2: (float, float, float) Triangle vertices.
        epsilon: float, threshold for parallelism check.
        
    Returns:
        tuple: (hit: bool, t: float, u: float, v: float)
    """
    # Step 1: Compute edge vectors
    e1 = (v1[0] - v0[0], v1[1] - v0[1], v1[2] - v0[2])
    e2 = (v2[0] - v0[0], v2[1] - v0[1], v2[2] - v0[2])
    
    # Step 2: Compute helper vector P = D x e2
    pvec = (
        ray_direction[1] * e2[2] - ray_direction[2] * e2[1],
        ray_direction[2] * e2[0] - ray_direction[0] * e2[2],
        ray_direction[0] * e2[1] - ray_direction[1] * e2[0]
    )
    
    # Step 3: Compute determinant det = e1 . P
    det = e1[0] * pvec[0] + e1[1] * pvec[1] + e1[2] * pvec[2]
    
    # Step 4: Check for parallelism
    if abs(det) < epsilon:
        return (False, 0.0, 0.0, 0.0)
    
    # Step 5: Compute inverse determinant
    inv_det = 1.0 / det
    
    # Step 6: Compute vector T = O - V0
    tvec = (
        ray_origin[0] - v0[0],
        ray_origin[1] - v0[1],
        ray_origin[2] - v0[2]
    )
    
    # Step 7: Compute barycentric coordinate u
    u = (tvec[0] * pvec[0] + tvec[1] * pvec[1] + tvec[2] * pvec[2]) * inv_det
    
    # Check if u is outside [0, 1]
    if u < 0.0 or u > 1.0:
        return (False, 0.0, 0.0, 0.0)
    
    # Step 8: Compute helper vector Q = T x e1
    qvec = (
        tvec[1] * e1[2] - tvec[2] * e1[1],
        tvec[2] * e1[0] - tvec[0] * e1[2],
        tvec[0] * e1[1] - tvec[1] * e1[0]
    )
    
    # Step 9: Compute barycentric coordinate v
    v = (ray_direction[0] * qvec[0] + ray_direction[1] * qvec[1] + ray_direction[2] * qvec[2]) * inv_det
    
    # Check if v is outside [0, 1] and u+v > 1
    if v < 0.0 or (u + v) > 1.0:
        return (False, 0.0, 0.0, 0.0)
    
    # Step 10: Compute intersection distance t
    t = (e2[0] * qvec[0] + e2[1] * qvec[1] + e2[2] * qvec[2]) * inv_det
    
    # Check if intersection is behind the ray origin
    if t < epsilon:
        return (False, 0.0, 0.0, 0.0)
    
    return (True, t, u, v)
```

**Edge Cases and Pitfalls:**
- **Parallel Rays:** If the ray is parallel to the triangle plane, the determinant approaches zero, causing division by zero. This is handled by the $|det| < \epsilon$ check [S4, unofficial].
- **Degenerate Triangles:** If the triangle vertices are collinear, the area is zero and the determinant will be zero (or near zero). The parallelism check handles this case [G].
- **Precision:** Using a small epsilon for comparisons is crucial for numerical stability, especially when the ray is nearly parallel to the triangle plane [S1, S2, unofficial].
- **Winding Order and Back-Face Culling:** The sign of $det$ indicates the orientation of the hit relative to the ray. If $det > 0$, the ray hits the front face; if $det < 0$, it hits the back face. The algorithm computes intersections for both, but forward-facing hits typically require $t > 0$ [S3, G, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per triangle. The algorithm performs a fixed number of arithmetic operations (cross products, dot products, divisions) [G].
- **Memory Complexity:** $O(1)$. No additional memory is required beyond local variables. This is a key advantage over methods that require precomputed plane equations [S4, S5, unofficial].
- **Performance:** It is considered one of the fastest ray-triangle intersection routines, particularly for meshes without precomputed plane equations [S5, unofficial].
- **Strengths:** Minimal storage requirements, clean implementation, no need for plane equation computation [S5, unofficial].
- **Limitations:** Sensitive to numerical precision in degenerate cases (parallel rays, degenerate triangles) [S1, S2, unofficial]. Does not inherently cull back faces without checking the sign of $det$ or $t$ [G].

## Background
The Möller-Trumbore algorithm was published by Tomas Möller and Ben Trumbore in the article "Fast, Minimum Storage Ray-Triangle Intersection" (1997) [S1, S5, unofficial]. It is used in volume rendering pipelines to determine entry and exit distances (sampling intervals) for triangles [S3, unofficial]. It is referenced in implementations such as GPView [S1, unofficial].
