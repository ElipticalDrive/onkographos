# Region Nesting Merge

Also called: MergeRegion

## Overview
Region Nesting Merge (MergeRegion) is a post-processing step for ray-based constructive solid geometry (CSG) operations that resolves topological inconsistencies in a sorted list of ray-sample intersections. It removes "inner" regions from a ray's sample list by tracking the nesting depth of volumes based on the orientation of surface normals relative to the ray direction [S1]. Unlike sibling methods that compute geometric intersections or occlusion tests, MergeRegion operates on a pre-sorted list of samples to enforce correct set-theoretic logic (union, intersection, subtraction) by discarding samples that lie inside other volumes [S1]. It is primarily used as the final cleanup step in `RayUnion` and `RaySubstraction` to ensure the resulting ray list represents the correct boundary of the CSG result [S1].

## How it works
**Inputs and Outputs**
*   **Input**: A `Ray` object `R` containing:
    *   `R.direction`: A 3D direction vector $\mathbf{d}$ [S1].
    *   `R.list`: A list of `Sample` objects, sorted by their position along the ray (e.g., by z-value or distance from origin) [S1].
*   **Output**: The `R.list` is modified in-place to contain only the samples that define the outer boundaries of the volume union [S1].

**Data Structures**
*   **Sample**: Contains at least:
    *   `normal`: A 3D normal vector $\mathbf{n}$ at the intersection point [S1].
    *   Position data (implicit in the sorting order) [S1].
*   **Ray**: Contains `direction` and `list` [S1].

**Algorithm Steps**
The algorithm iterates through the sorted list of samples, maintaining a counter `level` that represents the current nesting depth of volumes [S1].

1.  Initialize `level` to 0 and an empty temporary list `T` [S1].
2.  Iterate through each sample `s` in `R.list` in sorted order [S1].
3.  Compute the dot product $D = \mathbf{n} \cdot \mathbf{d}$, where $\mathbf{n}$ is `s.normal` and $\mathbf{d}` is `R.direction` [S1].
4.  If $D < 0$ (the normal points against the ray direction, indicating an "entering" intersection):
    *   Decrement `level` by 1 [S1].
    *   If `level` becomes 0, add `s` to `T` [S1].
5.  Else ($D \ge 0$, indicating a "leaving" intersection):
    *   If `level` is 0, add `s` to `T` [S1].
    *   Increment `level` by 1 [S1].
6.  After processing all samples, replace `R.list` with `T` [S1].

**Pseudocode**
```python
def MergeRegion(Ray R):
    level = 0
    T = []
    for s in R.list:
        # Dot product of sample normal and ray direction
        dot_product = Dot(s.normal, R.direction)
        
        if dot_product < 0:
            # Entering a volume (normal opposes ray)
            level = level - 1
            if level == 0:
                T.append(s)
        else:
            # Leaving a volume (normal aligns with ray)
            if level == 0:
                T.append(s)
            level = level + 1
    R.list = T
```

**Parameters and Edge Cases**
*   **Sorting**: The input `R.list` must be sorted by position along the ray (e.g., z-value) before calling `MergeRegion` [S1]. Failure to sort results in incorrect nesting logic [S1].
*   **Normal Orientation**: The logic assumes that normals point outward from the volume they bound [S1]. In `RaySubstraction`, normals of the subtracted volume are inverted before merging to maintain this convention [S1].
*   **Degenerate Input**: If the ray is tangent to a surface ($D = 0$), it is treated as a "leaving" intersection in the `else` branch [S1]. This may require specific handling in production code to avoid double-counting or missing boundaries, though the source treats $D \ge 0$ as leaving [S1].
*   **Precision**: Floating-point precision in the dot product may cause misclassification of tangent cases. [G] A small epsilon threshold is typically used in practice, but the source uses strict inequality `< 0`.

## Operating characteristics
*   **Time Complexity**: $O(N)$, where $N$ is the number of samples in `R.list`, as it performs a single linear pass [S1].
*   **Memory Complexity**: $O(N)$ for the temporary list `T` [S1].
*   **Strengths**: Simple, deterministic, and efficient for resolving CSG topology after merging sample lists [S1].
*   **Limitations**: Relies entirely on correct sorting and consistent normal orientation [S1]. Does not handle complex self-intersections or non-manifold geometry beyond simple nesting [S1].
*   **When to use**: After merging sample lists from multiple volumes in CSG operations (Union, Subtraction) to remove internal boundaries [S1].
*   **When not to use**: For initial ray-primitive intersection; for rendering where all intersections are needed (e.g., transparency without CSG); when normals are inconsistent or undefined.

## Background
Region Nesting Merge was introduced in the context of detail sculpting using cubical marching squares, specifically for performing constructive solid geometry (CSG) operations on ray-based representations of volumes [S1]. The method is part of a suite of algorithms including `RayUnion` and `RaySubstraction` designed to manipulate volumetric data by combining or subtracting geometric primitives [S1]. It addresses the problem of redundant or nested intersections that arise when merging multiple volumes, ensuring that only the outermost boundaries are retained for further processing or rendering [S1].
