# Linear Edge Intersection

Also called: Linear Edge Interpolation, Edge Crossing Linear Interpolation, Edge Intersection Vertex Interpolation, Linear Interpolation for Edge Intersection

## Overview
Linear Edge Intersection calculates the exact position where an isosurface (defined by a scalar field threshold) intersects a straight edge connecting two grid vertices, assuming the scalar field varies linearly between those vertices [S2, unofficial][S3, unofficial][S4, unofficial]. It solves the geometric problem of locating zero-crossings (or threshold crossings) on discrete grid structures, which is a fundamental step in algorithms like Marching Cubes and ray-marching volume rendering [S3, unofficial][S6, unofficial]. Unlike [Voxel selection via pick ray intersection](893-voxel-selection-via-pick-ray-intersection.md), which determines which voxel a ray enters, this method determines where on a specific segment the surface lies [S6, unofficial]. It is distinguished from [Linear Intersection Approximation](1232-linear-intersection-approximation.md) by using the actual scalar values at the endpoints rather than assuming the midpoint [S1, unofficial].

## How it works
**Inputs:**
*   $\mathbf{p}_1, \mathbf{p}_2$: 3D coordinates of the two edge endpoints (vertices) [G].
*   $v_1, v_2$: Scalar field values (e.g., density, SDF, intensity) at $\mathbf{p}_1$ and $\mathbf{p}_2$ [G].
*   $isoLevel$: The threshold value defining the isosurface [G].
*   $eps$: A small tolerance for numerical stability checks (typically $10^{-5}$ to $10^{-7}$) [S2, unofficial][S3, unofficial].

**Outputs:**
*   $\mathbf{p}$: The 3D coordinate of the intersection point on the edge [G].

**Data Structures:**
*   Vectors/Points: 3-element arrays or structs containing $(x, y, z)$ coordinates [G].
*   Scalars: Floating-point numbers for values and thresholds [G].

**Steps:**
1.  **Check for Degeneracy:** Calculate the difference $\Delta v = v_2 - v_1$ [S3, unofficial]. If $|\Delta v| < \text{eps}$, the scalar values are effectively identical, so return $\mathbf{p}_1$ as the intersection point to prevent division by zero [S2, unofficial][S3, unofficial][S4, unofficial].
2.  **Calculate Interpolation Factor:** Compute the normalized distance $\mu$ along the edge where the scalar value equals $isoLevel$ [S3, unofficial]. The standard formula is:
    $$ \mu = \frac{isoLevel - v_1}{v_2 - v_1} $$
    Some implementations clamp $\mu$ to the range $[0.0, 1.0]$ to handle cases where the threshold is slightly outside the sampled range due to noise or precision errors [S3, unofficial].
3.  **Compute Intersection Point:** Interpolate the position using $\mu$:
    $$ \mathbf{p} = \mathbf{p}_1 + \mu (\mathbf{p}_2 - \mathbf{p}_1) $$
    Alternatively, this can be expressed as a weighted average:
    $$ \mathbf{p} = (1 - \mu)\mathbf{p}_1 + \mu\mathbf{p}_2 $$
    [S2, unofficial][S3, unofficial][S5, unofficial].
4.  **Alternative Formulation (Signed Distance/Plane):** In clipping contexts (e.g., convex clipping), if $d_0$ and $d_1$ are the signed distances of $\mathbf{p}_1$ and $\mathbf{p}_2$ to a clipping plane (where $d_0 > 0$ and $d_1 \le 0$), the intersection $\mathbf{x}_p$ is calculated as [S1, unofficial]:
    $$ \mathbf{x}_p = \frac{d_0 \mathbf{p}_2 - d_1 \mathbf{p}_1}{d_0 - d_1} $$
    This form is numerically more stable when vertices lie very near the plane [S1, unofficial].

**Pseudocode:**
```python
def linear_edge_intersection(p1, p2, val1, val2, iso_level, eps=1e-7):
    diff = val2 - val1
    if abs(diff) < eps:
        return p1
    mu = (iso_level - val1) / diff
    mu = max(0.0, min(1.0, mu))  # Clamp to segment bounds [S3, unofficial]
    return (
        p1[0] + mu * (p2[0] - p1[0]),
        p1[1] + mu * (p2[1] - p1[1]),
        p1[2] + mu * (p2[2] - p1[2])
    )
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $v_1 = v_2$, the denominator is zero [S3, unofficial]. The method checks $|v_2 - v_1| < \text{eps}$ and returns an endpoint (typically $p_1$) [S2, unofficial][S3, unofficial][S4, unofficial].
*   **Threshold Outside Range:** If $isoLevel$ is not between $v_1$ and $v_2$, the mathematical intersection lies outside the segment $[p_1, p_2]$ [S4, unofficial]. Implementations clamp $\mu$ or return $p_1$ as a fallback [S3, unofficial][S4, unofficial]. In ray-marching contexts, if the signs of the density differences at the entry and exit points are the same, the method returns "NO HIT" [S6, unofficial].
*   **Multiple Roots:** In ray-marching contexts, if the scalar field has two roots within a voxel, linear interpolation between entry and exit points may fail to detect the intersection because the signs at the endpoints might be identical [S6, unofficial]. This method assumes a single crossing per edge segment [S6, unofficial].
*   **Numerical Stability:** When vertices are very close to the plane (in clipping applications), using signed distances directly in the weighted average formula is more stable than solving parametric equations [S1, unofficial].

## Subtopics

### [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md)
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy compared to closed-form algebraic solutions like [Schwarze's Analytic Inversion](52-schwarze-analytic-inversion.md) or more complex root isolation techniques.

### [Linear Intersection Approximation](1232-linear-intersection-approximation.md)
Linear Intersection Approximation (also known as Midpoint Intersection) estimates the intersection point of an isosurface with a grid edge by calculating the geometric midpoint of the edge, rather than performing linear interpolation based on scalar values. It differs from its parent, [Linear Edge Intersection](868-linear-edge-intersection.md), by ignoring endpoint scalar values entirely, and from its sibling, [Iterative Bisection Intersection Refinement](880-iterative-bisection-intersection-refinement.md), by using a single fixed geometric step instead of recursive refinement.

### Linear Density Minimization for Zero-Crossing
Approximates the zero-crossing position along an edge by sampling discrete points and selecting the one with minimum absolute density [S7, unofficial].
**Steps:**
1. Initialize `minValue` to 100000.0, `t` to 0.0, `currentT` to 0.0, `steps` to 8, and `increment` to $1.0 / 8$ [S7, unofficial].
2. Loop while `currentT` $\le 1.0$:
   * Compute point $p = p_0 + (p_1 - p_0) \times currentT$ [S7, unofficial].
   * Compute density $= |Density\_Func(p)|$ [S7, unofficial].
   * If density $< minValue$, update `minValue` $=$ density and `t` $=$ `currentT` [S7, unofficial].
   * Increment `currentT` $+=$ `increment` [S7, unofficial].
3. Return $p_0 + (p_1 - p_0) \times t$ [S7, unofficial].

### Triangle Point Generation (Linear Interpolation with Snap)
Generates intersection points with snapping behavior for vertices close to the grid edge point [S8, unofficial].
**Steps:**
1. If $|v_1| < snap$, return $p_1$ [S8, unofficial].
2. If $|v_2| < snap$, return $p_2$ [S8, unofficial].
3. If $|v_2 - v_1| < snap$, return $p_1$ [S8, unofficial].
**Formula:**
$$ \mu = \frac{v_2}{v_2 - v_1} $$
$$ point = \mu \mathbf{p}_1 + (1 - \mu) \mathbf{p}_2 $$
**Parameter:**
* $snap$: Threshold to snap vertices when close to grid edge point. Default value is 0.01 [S8, unofficial].

### Wall Edge Clipping
Clips wall edges to the screen/player boundary when they fall behind the player ($y < 1$) using linear interpolation to find the intersection point [S9, unofficial].
**Steps:**
1. If both endpoints have $y < 1$, return immediately [S9, unofficial].
2. If $y_1 < 1$, compute $t = (1 - y_1) / (y_2 - y_1)$, then interpolate: $x_1 = x_1 + t \times (x_2 - x_1)$, $y_1 = 1$, $z_1 = z_1 + t \times (z_2 - z_1)$ [S9, unofficial].
3. Repeat symmetrically for $y_2 < 1$ [S9, unofficial].

## Operating characteristics
* **Time Complexity:** $O(1)$. The calculation involves a constant number of arithmetic operations (subtraction, division, multiplication, addition) regardless of grid size [G].
* **Memory Complexity:** $O(1)$. No additional data structures are required beyond the input variables [G].
* **Strengths:** Exact solution under the linear assumption; numerically stable with proper epsilon checks; simple to implement [G].
* **Limitations:** Assumes linear variation of the scalar field, which is an approximation. It cannot resolve multiple intersections within a single edge segment [S6, unofficial]. Accuracy is limited by the grid resolution; finer grids yield more accurate surface representations [G].
* **When to use:** When extracting surfaces from voxel data (Marching Cubes, Dual Contouring) or performing ray-marching with linear interpolation [G].
* **When not to use:** When the scalar field is known to be highly non-linear within the edge segment and higher-order interpolation (e.g., quadratic or cubic) is required for visual fidelity, or when multiple roots are expected within the segment [G].
