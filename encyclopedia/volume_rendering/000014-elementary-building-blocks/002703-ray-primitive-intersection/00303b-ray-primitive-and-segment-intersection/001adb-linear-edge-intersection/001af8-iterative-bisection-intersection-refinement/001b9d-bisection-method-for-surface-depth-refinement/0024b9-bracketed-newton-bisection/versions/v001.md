# Bracketed Newton Bisection

Also called: BNB

## Overview
Bracketed Newton Bisection is a root-finding algorithm that combines bisection and Newton’s methods with a preliminary step that splits the polynomial into monotonic pieces [S1]. It finds all possible real roots of high-degree polynomials, addressing the problem where simple numerical solvers might miss solutions in high-degree cases [S1]. Unlike other simple numerical solvers, this method guarantees finding all real roots by ensuring at most one solution per interval through derivative-based subdivision [S1].

## How it works
**Inputs:** A polynomial $P(x)$ of degree $n$.
**Outputs:** All real roots of $P(x)$.

**Data Structures:**
*   `roots`: A list to store found roots.
*   `intervals`: A list of tuples $(x_{min}, x_{max})$ representing search intervals.

**Steps:**

1.  **Derivative Chain Construction:** Compute the derivatives of $P(x)$ up to the second derivative. Let $P^{(k)}$ denote the $k$-th derivative, where $P^{(0)} = P$. The degree of $P^{(k)}$ is $n-k$.
2.  **Base Interval Resolution:** Start with the $(n-2)$-th derivative, $P^{(n-2)}$, which is a quadratic polynomial (degree 2). Solve $P^{(n-2)}(x) = 0$ algebraically to find its real roots. These roots serve as the initial interval endpoints for the next level. If $P^{(n-2)}$ has no real roots, the parent polynomial is monotonic over the entire domain of interest, and the single interval is $(-\infty, \infty)$ or the domain bounds.
3.  **Recursive Interval Refinement:** Iterate from $k = n-3$ down to $0$. For each derivative $P^{(k)}$:
    *   Take the intervals established by the roots of $P^{(k+1)}$.
    *   For each interval $[a, b]$ where $P^{(k+1)}$ does not change sign (monotonic segments of the higher derivative), evaluate $P^{(k)}$ at the endpoints.
    *   If $P^{(k)}(a)$ and $P^{(k)}(b)$ have opposite signs, a root of $P^{(k)}$ exists within $[a, b]$. This interval becomes a candidate for the next level.
    *   If $P^{(k)}$ does not change sign, the interval is discarded for root finding of $P^{(k)}$ but may still define monotonicity for $P^{(k-1)}$.
    *   *Note:* The sources state that the roots of $P^{(i)}$ provide interval endpoints for searching roots of $P^{(i-1)}$ [S1]. This implies a bottom-up construction of monotonic intervals.
4.  **Root Finding in Monotonic Intervals:** Once the intervals for the original polynomial $P^{(0)}$ are identified (where $P$ is monotonic and changes sign), find the single root in each interval $[x_{min}, x_{max}]$ using a mixture of bisection and Newton’s methods [S1].

**Root Finding Formula (Mixture of Bisection and Newton):**
For a monotonic interval $[x_{min}, x_{max}]$ with $P(x_{min}) \cdot P(x_{max}) < 0$:
1.  Initialize $x_0$ (e.g., midpoint).
2.  Iterate until convergence:
    *   Compute $f = P(x_k)$ and $f' = P'(x_k)$.
    *   Compute Newton step: $x_{new} = x_k - f / f'$.
    *   *Bracketing Guard:* If $x_{new}$ falls outside $[x_{min}, x_{max}]$ or if the Newton step does not reduce the residual sufficiently, fall back to bisection: $x_{new} = (x_{min} + x_{max}) / 2$.
    *   Update interval: If $P(x_{new}) \cdot P(x_{min}) < 0$, set $x_{max} = x_{new}$; else set $x_{min} = x_{new}$.
    *   Set $x_{k+1} = x_{new}$.

**Parameters:**
*   Convergence tolerance: Not given in the sources.
*   Maximum iterations: Not given in the sources.

**Edge Cases:**
*   **Multiple Roots:** The method splits the polynomial into monotonic pieces to ensure at most one solution per interval [S1].
*   **High Degree:** The method is specifically designed for high-degree polynomials where analytical solutions are unavailable [S1].
*   **No Real Roots:** If the derivative chain yields no sign changes, no roots exist in that interval.

**Pseudocode:**

```python
def bracketed_newton_bisection(P, P_prime, domain):
    """
    Finds all real roots of polynomial P in the given domain.
    P: function evaluating the polynomial.
    P_prime: function evaluating the first derivative.
    domain: tuple (min, max) representing the search range.
    """
    # Step 1: Determine degree n
    # In practice, coefficients are used. Here we assume access to derivative functions.
    # We need derivatives up to order n-2.
    # Let's assume we have a list of derivative functions: derivs[0] = P, derivs[1] = P', etc.
    # For this pseudocode, we assume a generic way to get k-th derivative.
    
    n = get_degree(P)
    if n < 2:
        # Linear or constant case, handle directly
        return solve_linear_or_constant(P, domain)

    # Step 2: Solve quadratic (n-2 th derivative)
    # P^(n-2) is quadratic. Find its roots.
    # These roots split the domain for P^(n-3)
    quadratic_deriv = get_derivative(P, n - 2)
    quad_roots = solve_quadratic(quadratic_deriv, domain)
    
    # Initialize intervals for the next level (n-3)
    # The roots of P^(n-2) define the monotonicity of P^(n-3)
    intervals = get_intervals_from_roots(quad_roots, domain)
    
    # Step 3: Recursive refinement from n-3 down to 0
    # We need to find roots of P^(k) using intervals defined by roots of P^(k+1)
    # Start from k = n-3 down to 1. The roots of P^(1) define intervals for P^(0).
    
    current_intervals = intervals
    
    for k in range(n - 3, 0, -1):
        next_intervals = []
        deriv_k = get_derivative(P, k)
        deriv_k_plus_1 = get_derivative(P, k + 1)
        
        for (x_min, x_max) in current_intervals:
            # Check if P^(k) changes sign in this interval
            # The interval is monotonic for P^(k+1), but we need to find roots of P^(k)
            # Actually, the roots of P^(k+1) are the extrema of P^(k).
            # So P^(k) is monotonic within intervals defined by roots of P^(k+1).
            
            # Evaluate P^(k) at endpoints
            val_min = deriv_k(x_min)
            val_max = deriv_k(x_max)
            
            if val_min * val_max < 0:
                # Root of P^(k) exists in this interval
                # This interval will be used to find roots of P^(k-1)
                # But wait, the algorithm finds roots of P^(0).
                # The intervals for P^(k) are used to find roots of P^(k-1)?
                # No, the roots of P^(k) are the endpoints for P^(k-1).
                # So we need to find the root of P^(k) in this interval.
                root = find_root_in_interval(deriv_k, x_min, x_max)
                next_intervals.append(root)
            else:
                # No root of P^(k) in this interval.
                # The interval remains valid for P^(k-1) search?
                # If P^(k) doesn't change sign, P^(k-1) is monotonic.
                # So the interval boundaries are still the extrema of P^(k-1).
                # We keep the interval boundaries.
                next_intervals.append(x_min)
                next_intervals.append(x_max)
        
        # Sort and unique the intervals for the next level
        current_intervals = sorted(list(set(next_intervals)))
        
        # Re-partition into sub-intervals for the next derivative
        # The roots of P^(k) are now known. They define monotonicity for P^(k-1).
        # We need to pass intervals to the next iteration.
        # If we found roots, they split the domain.
        # If we didn't, the domain remains.
        
        # Reconstruct intervals for P^(k-1)
        # The roots of P^(k) are the points where P^(k-1) has extrema.
        # So the intervals for P^(k-1) are between these roots.
        if len(current_intervals) > 1:
            current_intervals = get_intervals_from_roots(current_intervals, domain)
        else:
            current_intervals = [domain]

    # Step 4: Find roots of P^(0) = P
    # current_intervals now define monotonic segments of P
    final_roots = []
    for (x_min, x_max) in current_intervals:
        val_min = P(x_min)
        val_max = P(x_max)
        if val_min * val_max < 0:
            root = find_root_in_interval(P, x_min, x_max)
            final_roots.append(root)
            
    return final_roots

def find_root_in_interval(f, x_min, x_max):
    """Mixture of Bisection and Newton's method."""
    x = (x_min + x_max) / 2.0
    for _ in range(100): # Max iterations
        fx = f(x)
        if abs(fx) < 1e-10:
            return x
        
        # Compute derivative numerically or analytically
        # Assuming we have f_prime available in the outer scope or passed
        # For simplicity, let's assume f_prime is available
        try:
            fpx = f_prime(x)
        except:
            # Fallback to bisection if derivative unavailable
            x = (x_min + x_max) / 2.0
            continue
            
        if fpx == 0:
            x = (x_min + x_max) / 2.0
            continue
            
        x_new = x - fx / fpx
        
        # Bracketing check
        if x_new < x_min or x_new > x_max:
            x_new = (x_min + x_max) / 2.0
            
        fx_new = f(x_new)
        if fx_new * f(x_min) < 0:
            x_max = x_new
        else:
            x_min = x_new
            
        x = x_new
        
    return x
```

## Subtopics

### [Analytic Ray-Intersection Polynomial Solver](3562-analytic-ray-intersection-polynomial-solver.md)
The Analytic Ray-Intersection Polynomial Solver finds the intersection parameter $t$ where a ray intersects the polynomial approximation of a Signed Distance Function (SDF) leaf node. It solves the problem of slow convergence in sphere marching when rays pass near parallel surfaces or graze the isosurface. Unlike sphere marching, which evaluates the SDF iteratively, this method computes a single polynomial in $t$ per node and solves for its roots, offering a significant performance improvement near the surface at the cost of higher initial coefficient computation.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Able to find all possible real roots of high-degree polynomials [S1].
*   **Limitations:** Requires computation of derivatives and solving lower-degree polynomials iteratively [S1].
*   **When to use:** When high-degree polynomial approximations of SDFs are used and all real roots must be found [S1].
*   **When not to use:** When lower-degree polynomials are sufficient or when analytical solutions are available.

## Background
Bracketed Newton Bisection is a root-finding algorithm named by Peters et al. [29] and first proposed by Yuksel [30] [S1]. It is used in the context of rendering piecewise approximations of SDFs through analytic intersections [S1].
