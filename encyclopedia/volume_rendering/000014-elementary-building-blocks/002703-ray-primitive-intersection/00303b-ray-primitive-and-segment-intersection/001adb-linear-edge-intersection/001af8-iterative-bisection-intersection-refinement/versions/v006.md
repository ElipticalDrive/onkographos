# Iterative Bisection Intersection Refinement

Also called: Bisection Refinement, Intersection refined isosurface rendering, Iso Hit Bisection, Isosurface Rendering with Intersection Refinement, Isosurface shader, Linear Interpolation Refinement, Ray Intersection Refinement

## Overview
Iterative Bisection Intersection Refinement is a post-detection technique used to accurately locate the intersection point of a viewing ray with an isosurface within a volume dataset [S1, unofficial]. It solves the problem of geometric inaccuracy inherent in coarse adaptive sampling or sphere tracing by iteratively narrowing the interval known to contain the root [S1, S3, unofficial]. It sets itself apart from its siblings by relying on repeated linear interpolation (bisection) to refine the position, offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (normalized), the interval $[t_{prev}, t_{curr}]$ (or $[x_{near}, x_{far}]$) where a sign change in the scalar field value has been detected, the scalar field values at the interval endpoints $d_{prev}$ and $d_{curr}$ (or $f_{near}, f_{far}$), and the target isovalue $\rho$ [S1, unofficial][S4].
*   **Outputs:** The refined intersection parameter $t_{hit}$ (or position $\mathbf{x}_{hit}$) [S1, unofficial][S4].

**Data Structures:**
The method operates on scalar values and 3D coordinates [G]. No complex data structures are required beyond the ray parameters and the scalar field texture/volume access function [S1, unofficial][S4].

**Steps:**
1.  **Initialization:** Define the search interval. Let $L$ (or $x_{near}$) be the point outside the isovalue (where $f(L) < \rho$) and $R$ (or $x_{far}$) be the point inside or at the isovalue (where $f(R) \ge \rho$) [S4]. In adaptive sampling contexts, these correspond to $t_{prev}$ and $t_{curr}$ respectively [S1, unofficial].
2.  **Iteration Loop:** Repeat for a fixed number of iterations $N$ (typically 4 to 10) [S2, S4]:
    a.  **Linear Interpolation:** Compute the new candidate point $\mathbf{x}_{new}$ (or parameter $M$) using linear interpolation between the current bounds [S2]. The position is calculated as:
        $$ \mathbf{x}_{new} = (\mathbf{x}_{far} - \mathbf{x}_{near}) \frac{\rho - f_{near}}{f_{far} - f_{near}} + \mathbf{x}_{near} $$
        Alternatively, in parameter space $t$:
        $$ t_{new} = t_{near} + (t_{far} - t_{near}) \frac{\rho - f_{near}}{f_{far} - f_{near}} $$
        [S2, S4]
    b.  **Sampling:** Evaluate the scalar field value $f_{new}$ at $\mathbf{x}_{new}$ (or $d_M$ at $t_{new}$) [S2][S3, unofficial][S4].
    c.  **Interval Update:** Compare $f_{new}$ with $\rho$:
        *   If $f_{new} < \rho$ (the new point is outside the isovalue), update the lower bound: set $x_{near} = \mathbf{x}_{new}$ and $f_{near} = f_{new}$ [S4].
        *   If $f_{new} \ge \rho$ (the new point is inside or at the isovalue), update the upper bound: set $x_{far} = \mathbf{x}_{new}$ and $f_{far} = f_{new}$ [S4].
        *   *Note:* Some implementations use strict inequality for the upper bound update ($d_M > 0$) and lower bound update ($d_M < 0$) assuming centered zero-level sets [S3, unofficial]. While the method is named "bisection", it primarily uses linear interpolation [S2, S4], though some variants use strict midpoint bisection ($M = (L+R)/2$) [S3, unofficial].
3.  **Termination:** After $N$ iterations, the refined intersection position is $\mathbf{x}_{new}$ (or $t_{new}$) [S4]. If $N=0$, return the midpoint of the final interval $(t_{min} + t_{max}) / 2$ [S3, unofficial].
4.  **Shading:** The refined point is shaded using the appropriate lighting model [S4].

**Pseudocode:**
```python
def sample_scalar_field(pos):
    """Standard volume lookup. Returns scalar value at pos."""
    return volume_lookup(pos)

def intersect_domain_box(origin, direction, domain_min, domain_max):
    """Standard ray-AABB intersection. Returns (t_min, t_max)."""
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if abs(direction[i]) < 1e-9:
            if origin[i] < domain_min[i] or origin[i] > domain_max[i]:
                return (float('inf'), -float('inf'))
        else:
            t1 = (domain_min[i] - origin[i]) / direction[i]
            t2 = (domain_max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    return (t_min, t_max)

def refine_iso_hit_bisection(origin, direction, t_prev, t_curr, d_prev, d_curr, isovalue, num_iterations=5):
    """
    Refines the intersection of a ray with an isosurface using bisection.
    """
    t_near = t_prev
    t_far = t_curr
    f_near = d_prev
    f_far = d_curr
    
    # Guard: ensure valid interval for bisection
    if f_near >= isovalue or f_far < isovalue:
        return (t_near + t_far) / 2.0

    for _ in range(num_iterations):
        denom = f_far - f_near
        if abs(denom) < 1e-9:
            t_new = (t_near + t_far) / 2.0
        else:
            t_new = t_near + (t_far - t_near) * (isovalue - f_near) / denom
            
        pos_new = origin + t_new * direction
        f_new = sample_scalar_field(pos_new)
        
        # Update bounds based on S4
        if f_new < isovalue:
            t_near = t_new
            f_near = f_new
        else:
            t_far = t_new
            f_far = f_new
            
    return t_new

def ray_march_with_refinement(origin, direction, domain_min, domain_max, isovalue, step_size, num_refine_iters=5):
    """
    Adaptive ray marching with iterative bisection refinement.
    """
    t_min, t_max = intersect_domain_box(origin, direction, domain_min, domain_max)
    if t_max <= t_min:
        return None
        
    t_prev = t_min
    d_prev = sample_scalar_field(origin + t_prev * direction)
    
    t_curr = t_prev + step_size
    
    while t_curr <= t_max:
        d_curr = sample_scalar_field(origin + t_curr * direction)
        
        # Check for sign change (outside to inside)
        if (d_prev < isovalue) and (d_curr >= isovalue):
            t_hit = refine_iso_hit_bisection(
                origin, direction, t_prev, t_curr, d_prev, d_curr, isovalue, num_refine_iters
            )
            p_hit = origin + t_hit * direction
            # Shading is application-specific; return hit point for shading pipeline
            return p_hit 
            
        t_prev = t_curr
        d_prev = d_curr
        t_curr += step_size
        
    return None
```

**Parameters:**
*   `num_iterations` (or `uRefinementIterations`): The number of bisection steps. Typical values range from 4 to 10, with 5 being common [S1, unofficial][S2, S4]. More iterations improve accuracy at the cost of additional scalar field evaluations [S1, unofficial].
*   `isovalue` ($\rho$): The scalar threshold defining the surface [S2, S4].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If $f_{far} \approx f_{near}$, the linear interpolation formula divides by zero [G]. The pseudocode handles this by falling back to the midpoint.
*   **Sign Change Assumption:** The method assumes a single root within the interval [S4].
*   **Precision:** Floating-point precision errors in $f_{new}$ comparisons can cause infinite loops if not bounded by iteration count [G]. Using a fixed iteration count avoids this [S2, S4].

## Subtopics

### [Neubauer's Ray-Voxel Intersection Algorithm](975-neubauer-s-ray-voxel-intersection-algorithm.md)
Neubauer's algorithm is a method for finding the intersection of a viewing ray with an iso-surface defined by trilinearly interpolated scalar data within a voxel. It solves the problem of locating the precise root of the implicit function $f(t) = \rho(R(t)) - \rho_{iso}$ by using repeated linear interpolation to refine the intersection position within the ray segment containing the root. It is distinguished from its siblings by its reliance on iterative linear approximation rather than closed-form algebraic solutions (like Schwarze's Analytic Inversion) or root isolation techniques (like Isolation and Iterative Root Finding), offering a balance of speed and moderate accuracy at the cost of potential artifacts in complex topologies.

### [Fast Ray-Surface Intersection](994-fast-ray-surface-intersection.md)
Fast Ray-Surface Intersection is an approximate method for determining the intersection point of a ray with an iso-surface within a volume rendering cell, trading geometric accuracy for computational speed. It solves the problem of finding the first-hit surface location without the high cost of inverting trilinear interpolation. Unlike exact intersection methods which compute all roots of the cubic polynomial derived from trilinear interpolation, this method subdivides the ray segment within the cell and uses linear interpolation to estimate the hit point, producing visually indistinguishable results in final renderings while being significantly faster.

### [Secant Method for Surface Depth Refinement](996-secant-method-for-surface-depth-refinement.md)
The Secant Method for Surface Depth Refinement is an iterative root-finding algorithm used to refine the depth value $d$ along a ray where a signed distance function (SDF) or occupancy logit crosses a specific threshold. It distinguishes itself from its sibling [Bisection Method for Surface Depth Refinement](1033-bisection-method-for-surface-depth-refinement.md) by using linear interpolation between two bracketing points to estimate the next probe point, rather than simply halving the interval.

### [Bisection Method for Surface Depth Refinement](1033-bisection-method-for-surface-depth-refinement.md)
The Bisection Method for Surface Depth Refinement is an iterative root-finding algorithm that determines the exact intersection point of a ray with an implicit surface within a segment known to contain an intersection. It serves as an alternative to the Secant method in ray marching pipelines. The method systematically halves the search interval at each step until the midpoint evaluates to zero.

### [Hitpoint Refinement](2712-hitpoint-refinement.md)
Hitpoint Refinement is an iterative technique to achieve higher quality in detecting surface intersections without reducing rendering speed. It allows for coarser initial sampling steps to increase rendering speed, refining the detected intersection point through a specific heuristic procedure. It sets itself apart from its siblings by using a "half-step back, then check direction" adjustment rather than standard bisection or secant methods, enabling significant speedups when paired with large initial sampling distances.

### Windowed Bisection for Isosurface Refinement
Windowed Bisection for Isosurface Refinement refines the isosurface position along a ray using 4 iterations of bisection with windowing, ensuring correctness across brick boundaries by using `sampleWithIndirection` [S5, unofficial]. It initializes `lo = tLow` and `hi = tHigh`, then loops 4 times to calculate the midpoint `mid = (lo + hi) * 0.5`, position `pos = rayOrigin + rayDir * mid`, and voxel coordinates `voxel = normalizedToVoxel(pos, ...)` [S5, unofficial]. It samples density, normalizes it to [0,1] using `uniforms.floatMin` and `uniforms.floatMax`, then applies windowing: `density = applyWindow(normalizedDensity, windowCenter, windowWidth);` [S5, unofficial]. It updates bounds: if `density >= isoValue`, set `hi = mid`; else `lo = mid`, and returns `(lo + hi) * 0.5` [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ scalar field evaluations per intersection, where $N$ is the number of refinement iterations [S4]. This is significantly cheaper than solving cubic polynomials for exact trilinear intersection but more expensive than a single-step detection [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory [G].
*   **Measured Performance:** A fixed number of 4 iterations is empirically sufficient for high-quality positions in many datasets [S2]. Increasing iterations improves accuracy at the cost of additional evaluations [S1, unofficial].
*   **Strengths:** Provides a more accurate hit position than a single-step midpoint detection [S1, unofficial]. Empirically, a fixed number of iterations yields high-quality positions [S2].
*   **Limitations:** Potential artifacts in complex topologies if the initial step size is too large [S1, unofficial].
*   **When to Use:** When adaptive sampling is used and high precision is needed without the cost of analytic inversion [S1, unofficial].
*   **When Not to Use:** When the scalar field is extremely noisy or discontinuous, or when exact geometric precision is required for subsequent physics simulations [G].

## Background
The method originates from real-time volume graphics research, specifically in the context of isosurface rendering [S2, S4]. It is commonly used in GPU-based volume raycasting pipelines where adaptive sampling is employed to balance performance and quality [S1, unofficial].
