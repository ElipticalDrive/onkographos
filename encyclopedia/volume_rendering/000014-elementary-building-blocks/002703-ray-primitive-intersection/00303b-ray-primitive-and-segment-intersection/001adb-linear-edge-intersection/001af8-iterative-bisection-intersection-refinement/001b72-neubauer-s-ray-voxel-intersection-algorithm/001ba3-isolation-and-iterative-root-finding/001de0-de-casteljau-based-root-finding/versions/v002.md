# de Casteljau-based root finding

Also called: Root Finding: de Casteljau Subdivision (LR81), de Casteljau Subdivision

## Overview
A root finding algorithm for polynomials in Bernstein form that isolates and refines the first intersection of a viewing ray with an isosurface by subdividing the control polygon using the de Casteljau algorithm at its intersection with the zero axis [S1, unofficial]. It sets itself apart from knot insertion methods like [MR07] by offering quadratic convergence speed and constant memory usage without index operations, making it significantly faster for GPU architectures [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A polynomial $P(t)$ in Bernstein basis of degree $n$, defined by control points $\mathbf{b}_0, \dots, \mathbf{b}_n$, and an isovalue $c$ [S1, unofficial]. The function to solve is $f(t) = P(t) - c = 0$ for $t \in [0, 1]$ [S1, unofficial].
- Output: The parameter $t$ corresponding to the first root (smallest $t \ge 0$) [S1, unofficial].

**Data structures:**
- Control points: A list or array of values representing the Bernstein control polygon. For a trivariate polynomial evaluated along a ray, these are scalar values [S1, unofficial].
- No auxiliary index arrays or dynamic memory structures are required; the algorithm uses constant memory usage [S1, unofficial].

**Steps:**
1. **Initialization:** Compute the initial control polygon for the function $f(t) = P(t) - c$. If $P(t) = \sum_{i=0}^n \mathbf{b}_i B_{i,n}(t)$, the control points for $f(t)$ are $\mathbf{b}_i - c$ [G].
2. **Iteration:** Repeat the following subdivision step for a fixed number of iterations $k$ (typically 3 to 7, depending on interpolation type) [S1, unofficial]:
   a. Identify the intersection of the current control polygon with the zero axis [S1, unofficial].
   b. Apply the de Casteljau algorithm to subdivide the control polygon at the parameter value corresponding to the intersection [S1, unofficial].
   c. Select the segment containing the root. For the first root, select the leftmost segment [S1, unofficial].
   d. Update the control polygon to the selected segment [S1, unofficial].
3. **Result:** After $k$ iterations, the remaining control polygon is sufficiently small. The root is approximated by the parameter value of the remaining interval or by evaluating the polynomial at the midpoint of the final interval [G].

**Formulas:**
The de Casteljau algorithm for a parameter $t$ and control points $\mathbf{b}_i^{(0)} = \mathbf{b}_i$ computes:
$$ \mathbf{b}_i^{(r)} = (1-t) \mathbf{b}_{i-1}^{(r-1)} + t \mathbf{b}_i^{(r-1)} $$
for $r=1, \dots, n$ and $i=r, \dots, n$ [G]. The left control points are $\mathbf{b}_0^{(r)}$ and the right control points are $\mathbf{b}_n^{(r)}$ [G].

**Parameters:**
- Number of iterations $k$: 3 to 7 [S1, unofficial].

**Edge cases and pitfalls:**
- The method assumes the root is isolated or that the first root is sought. For isolated roots, simpler methods like regula falsi may be faster in the second phase, but the isolation step can cause branch divergence on GPUs [S1, unofficial].
- The Bernstein form offers a control polygon with a variation diminishing property [S1, unofficial].

**Pseudocode:**
```python
def de_casteljau_root_finding(control_points, isovalue, num_iterations):
    """
    Find the root of P(t) - isovalue = 0 using de Casteljau subdivision.
    
    Args:
        control_points: List of control points for the polynomial P(t).
        isovalue: The isovalue c.
        num_iterations: Number of subdivision iterations (3-7).
        
    Returns:
        t: Approximate root parameter.
    """
    # Initialize control points for f(t) = P(t) - c
    cp = [p - isovalue for p in control_points]
    t_start, t_end = 0.0, 1.0
    n = len(cp) - 1

    for _ in range(num_iterations):
        # Subdivide at t = 0.5 (index-free constant memory subdivision)
        # The split parameter can be adapted to the polygon's intersection with zero
        t_split = 0.5
        
        # Compute de Casteljau triangle to extract left control polygon
        left_cp = [cp[0]]
        b = list(cp)
        for r in range(1, n + 1):
            new_b = []
            for i in range(len(b) - 1):
                new_b.append((1 - t_split) * b[i] + t_split * b[i+1])
            b = new_b
            left_cp.append(b[0])
        
        # Update to the left segment (first root)
        cp = left_cp
        t_end = t_split

    return (t_start + t_end) / 2
```

## Subtopics

### Knot insertion root finding
A root finding algorithm based on knot insertion with linear convergence speed and linear complexity per step [S1, unofficial]. It requires index operations and memory usage grows with every iteration step, limiting the maximum number of iterations [S1, unofficial]. For degree 9 (tri-cubic), it has a relative execution time of 1.0, MSE of 0.034, and max error of 0.85, making it more than 10 times slower than de Casteljau-based root finding [S1, unofficial].

### Regula Falsi with De Casteljau
A root finding method using Regula Falsi combined with De Casteljau subdivision for root isolation [S1, unofficial]. While the second phase (Regula Falsi) can outperform de Casteljau-based root finding for isolated roots, the isolation step is not well suited for CUDA due to diverging branches [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Quadratic complexity per step due to the de Casteljau algorithm [S1, unofficial].
- **Convergence:** Quadratic convergence speed [S1, unofficial].
- **Memory:** Constant memory usage, no index operations required [S1, unofficial].
- **Performance:** For degree 9 (tri-cubic), relative execution time is 0.076 (compared to MR07's 1.0), MSE is 0.003, and max error is 0.66 [S1, unofficial]. It is more than 10 times faster than the MR07 knot insertion algorithm [S1, unofficial].
- **Strengths:** Fast, constant memory, suitable for GPU (CUDA) due to lack of diverging branches and index operations [S1, unofficial].
- **Limitations:** Fixed number of iterations required; not optimal for isolated roots where simpler methods like Regula Falsi could be faster in the refinement phase [S1, unofficial].

## Background
Originated from the work cited as [LR81] in the context of volume rendering using wavelet-based multiresolution isosurface rendering [S1, unofficial]. It is used as a primary root finding method in GPU-based volume rendering pipelines due to its efficiency and suitability for parallel architectures [S1, unofficial].
