# Isolation and Iterative Root Finding

Also called: Isolation method, New intersection algorithm

## Overview
Isolation and Iterative Root Finding is a ray-voxel intersection algorithm for iso-surfaces that combines the speed of Neubauer's method with the correctness guarantees of Schwarze's method [S1, unofficial]. It solves the problem of finding the first intersection of a ray with a cubic polynomial within a voxel by first isolating the root interval using the polynomial's extrema, then refining the location via iterative root finding [S1, unofficial]. Unlike Neubauer's method, which can fail or return incorrect intersections when multiple roots exist in a segment, this method guarantees that the final interval contains exactly one root, ensuring the first valid intersection is found [S1, unofficial]. It is roughly three times faster than Schwarze's method while maintaining superior numerical stability [S1, unofficial].

## How it works
The method operates on a cubic polynomial $f(t)$ representing the scalar field along a ray segment $[t_{in}, t_{out}]$. The goal is to find the smallest $t \in [t_{in}, t_{out}]$ such that $f(t) = \rho_{iso}$, where $\rho_{iso}$ is the isovalue. For implementation, we define the residual function $f(t) = \rho(R(t)) - \rho_{iso}$, where $R(t)$ is the ray position.

**Inputs:**
- Ray segment endpoints $t_{in}, t_{out}$.
- Polynomial coefficients $A, B, C, D$ for $f(t) = At^3 + Bt^2 + Ct + D$ in power form, or equivalent Bernstein coefficients.
- Isovalue $\rho_{iso}$ (incorporated into $f(t)$).

**Outputs:**
- Intersection parameter $t_{hit}$ or "NO HIT".

**Data Structures:**
- Floating-point variables for $t, f, e$ (extrema).
- Quadratic solver for $f'(t)$.

**Steps:**

1.  **Initialization:**
    Set $t_0 = t_{in}$, $t_1 = t_{out}$.
    Compute $f_0 = f(t_0)$ and $f_1 = f(t_1)$.

2.  **Extrema Analysis:**
    Compute the derivative $f'(t) = 3At^2 + 2Bt + C$.
    Solve the quadratic equation $f'(t) = 0$ for real roots.
    Let the roots be $e_0$ and $e_1$, with $e_0 \le e_1$. If no real roots exist, skip to Step 4.

3.  **Root Isolation (Segment Advancement):**
    Iterate through the extrema to isolate the interval containing the first root.
    
    -   **First Extremum ($e_0$):**
        If $e_0 \in [t_0, t_1]$:
        -   Compute $f(e_0)$.
        -   If $\text{sign}(f(e_0)) == \text{sign}(f_0)$:
            The function does not cross zero between $t_0$ and $e_0$. Advance to the next segment:
            $t_0 := e_0$
            $f_0 := f(e_0)$
        -   Else:
            The root lies between $t_0$ and $e_0$. Restrict the interval:
            $t_1 := e_0$
            $f_1 := f(e_0)$
    
    -   **Second Extremum ($e_1$):**
        If $e_1 \in [t_0, t_1]$:
        -   Compute $f(e_1)$.
        -   If $\text{sign}(f(e_1)) == \text{sign}(f_0)$:
            The function does not cross zero between $t_0$ and $e_1$. Advance to the next segment:
            $t_0 := e_1$
            $f_0 := f(e_1)$
        -   Else:
            The root lies between $t_0$ and $e_1$. Restrict the interval:
            $t_1 := e_1$
            $f_1 := f(e_1)$

4.  **Hit Test:**
    If $\text{sign}(f_0) == \text{sign}(f_1)$, return **NO HIT**.
    Otherwise, the interval $[t_0, t_1]$ contains exactly one root.

5.  **Iterative Refinement:**
    Refine the root location within $[t_0, t_1]$ using repeated linear interpolation (Regula Falsi).
    Loop $i$ from 1 to $N$ (typically $N=2$ or $3$):
    -   Compute candidate $t$:
        $$ t = t_0 + (t_1 - t_0) \frac{-f_0}{f_1 - f_0} $$
    -   Compute $f(R(t))$.
    -   If $\text{sign}(f(R(t))) == \text{sign}(f_0)$:
        $t_0 := t$
        $f_0 := f(R(t))$
    -   Else:
        $t_1 := t$
        $f_1 := f(R(t))$

6.  **Result:**
    Return $t_{hit} = t_0 + (t_1 - t_0) \frac{-f_0}{f_1 - f_0}$.

**Pseudocode:**

```python
def isolation_and_iterative_root_finding(t_in, t_out, A, B, C, D, rho_iso):
    # Define f(t) = At^3 + Bt^2 + Ct + D - rho_iso
    def f(t):
        return A*t**3 + B*t**2 + C*t + D - rho_iso

    t0 = t_in
    t1 = t_out
    f0 = f(t0)
    f1 = f(t1)

    # Solve f'(t) = 3At^2 + 2Bt + C = 0
    a_quad = 3 * A
    b_quad = 2 * B
    c_quad = C
    
    discriminant = b_quad**2 - 4 * a_quad * c_quad
    
    if discriminant < 0:
        # No real extrema, proceed directly to refinement if signs differ
        pass
    else:
        sqrt_disc = sqrt(discriminant)
        e0 = (-b_quad - sqrt_disc) / (2 * a_quad)
        e1 = (-b_quad + sqrt_disc) / (2 * a_quad)
        
        # Process first extremum e0
        if t0 <= e0 <= t1:
            f_e0 = f(e0)
            if sign(f_e0) == sign(f0):
                # Advance to second segment
                t0 = e0
                f0 = f_e0
            else:
                # Root is in [t0, e0]
                t1 = e0
                f1 = f_e0
        
        # Process second extremum e1
        if t0 <= e1 <= t1:
            f_e1 = f(e1)
            if sign(f_e1) == sign(f0):
                # Advance to third segment
                t0 = e1
                f0 = f_e1
            else:
                # Root is in [t0, e1]
                t1 = e1
                f1 = f_e1

    if sign(f0) == sign(f1):
        return "NO HIT"

    # Iterative refinement (Regula Falsi)
    # Typically 2-3 iterations
    for i in range(1, 4):
        denom = f1 - f0
        if denom == 0:
            # Avoid division by zero; fallback to midpoint or break
            t = (t0 + t1) / 2
        else:
            t = t0 + (t1 - t0) * (-f0) / denom
        
        f_t = f(t)
        if sign(f_t) == sign(f0):
            t0 = t
            f0 = f_t
        else:
            t1 = t
            f1 = f_t

    # Final estimate
    denom = f1 - f0
    if denom == 0:
        return (t0 + t1) / 2
    return t0 + (t1 - t0) * (-f0) / denom

def sign(x):
    if x > 0: return 1
    if x < 0: return -1
    return 0
```

**Parameters:**
-   $N$: Number of refinement iterations. Typical values are 2 or 3 [S1, unofficial]. A fixed number is preferred over adaptive termination for speed [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Multiple Roots:** Neubauer's method can falsely return the last intersection if three intersections exist in a voxel but two are in the first segment. This method isolates the first root, avoiding this error [S1, unofficial].
-   **Numerical Stability:** The method provides better numerical stability than Schwarze's method [S1, unofficial].
-   **Division by Zero:** In the refinement step, if $f_1 \approx f_0$, the denominator becomes small. A guard against zero division is recommended [G].

## Subtopics

### [de Casteljau-based root finding](1596-de-casteljau-based-root-finding.md)
A root finding algorithm for polynomials in Bernstein form that isolates and refines the first intersection of a viewing ray with an isosurface by subdividing the control polygon using the de Casteljau algorithm at its intersection with the zero axis. It sets itself apart from knot insertion methods like [MR07] by offering quadratic convergence speed and constant memory usage without index operations, making it significantly faster for GPU architectures.

### Sturm Series root finding
A root finding approach based on Sturm Series working in power form [S2, unofficial]. It uses the Sturm Series to count multiplicities of roots in a given interval and employs binary subdivision of the search interval [S2, unofficial]. The Sturm Series is computed once at the beginning and evaluated every iteration step. It offers exponential convergence with constant memory consumption during iteration, but high overall memory consumption as the whole series must be kept in memory [S2, unofficial]. Numerical problems inherent to power form implementations become more severe with more iterations [S2, unofficial]. For degree 9 (tri-cubic), it has a relative execution time of 0.077, MSE of 0.003, and max error of 1.0 [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** Roughly a factor of three faster than Schwarze's method [S1, unofficial]. The cost is dominated by solving the quadratic for extrema and evaluating the polynomial.
-   **Memory Complexity:** Low. Only a few floating-point variables are needed.
-   **Performance:** For degree 9 (tri-cubic) polynomials, the related de Casteljau method has a relative execution time of 0.076, while Sturm Series is 0.077 [S2, unofficial]. The isolation method itself is not given a specific relative time in the tables, but is described as "fast" and "well suited for data parallel SIMD implementation" [S1, unofficial].
-   **Strengths:** Correctness guarantees (finds the first root), numerical stability, SIMD friendliness [S1, unofficial].
-   **Limitations:** Requires solving a quadratic equation and evaluating the polynomial at extrema points. Not given in the sources: specific performance on very high-degree polynomials beyond tri-cubic.
-   **When to use:** When correctness is critical and performance is important, especially on SIMD hardware [S1, unofficial].
-   **When not to use:** When extreme simplicity is required and occasional incorrect hits are acceptable (Neubauer's method might be simpler).

## Background
The method was introduced by Wald et al. in 2004 as a new intersection algorithm aiming to balance the speed of Neubauer's method with the correctness of Schwarze's method [S1, unofficial]. It is based on the observation that repeated linear interpolation is fast and reliable if the start interval contains exactly one root, and that roots can be isolated by computing the extrema of the polynomial [S1, unofficial]. The method is well-suited for SIMD implementation, addressing the complex control flow issues of Schwarze's method [S1, unofficial].
