# Raycast-based Voxel Editing

Also called: Chunk Noise Modification, Marching Cubes Voxel Sculpting

## Overview
This method modifies voxel density values within a local radius around a raycast hit point to sculpt terrain or objects, triggering immediate chunk regeneration for visual feedback [S1, unofficial]. It differs from global noise generation by allowing interactive, localized edits via mouse input, bridging the gap between static voxel generation and dynamic user interaction.

## How it works
**Inputs and Outputs:**
- **Input:** Camera screen coordinates (mouse position), current voxel chunk grid state, edit parameters (radius, edit value, direction).
- **Output:** Modified voxel density values in affected chunks, regenerated mesh geometry for those chunks.

**Data Structures:**
- **Chunk Grid:** A 3D array or hash map of `ChunkMatrix` objects. Each chunk contains a 3D array `noiseMatrix[x, y, z]` storing float density values.
- **Hit Point:** A `Vector3` position in world space where the ray intersects a mesh.
- **Chunk Indices:** A 3-tuple `(cx, cy, cz)` identifying the chunk containing the hit point.
- **Local Voxel Indices:** A 3-tuple `(vx, vy, vz)` identifying the specific voxel within the chunk.

**Steps:**
1. **Ray Casting:** Cast a ray from the camera through the current mouse screen position. The ray has a maximum distance of 20 units [S1, unofficial].
2. **Hit Validation:** Check if the ray intersects a transform tagged "Mesh". If no hit or wrong tag, abort [S1, unofficial].
3. **Position Conversion:** Extract the world-space hit point. Convert this position to global chunk indices using `GetCurrentChunkFromPos(hitPos)` [S1, unofficial].
4. **Local Index Calculation:** Convert the hit position to local voxel indices within the identified chunk using `GetCurrentCubeInChunkFromPos(hitPos)` [S1, unofficial].
5. **Direction Determination:** Determine the edit direction based on mouse button: `dir = 1` for left click (add density), `dir = -1` for right click (subtract density) [S1, unofficial].
6. **Voxel Modification:** Call `SetNoiseValues` on the hit chunk. This function modifies the `noiseMatrix` in a spherical radius around the local voxel indices. The modification amount is `dir * editValue`. The specific implementation of `SetNoiseValues` involves iterating over voxels within the radius and adjusting their density [S1, unofficial]. Note: The source code snippet provided in [S1, unofficial] shows a noise *generation* loop using Perlin noise, but the textual description and function calls (`SetNoiseValues`) indicate an *editing* operation. The editing logic is inferred from the function signature and description.
7. **Mesh Regeneration:** Call `UpdateSurroundingChunks` with the global chunk indices. This triggers the regeneration of the Marching Cubes mesh for the hit chunk and its neighbors to reflect the new density values [S1, unofficial].

**Pseudocode:**
```python
def handle_voxel_edit(mouse_screen_pos, camera, chunks, edit_value, radius):
    # Step 1: Cast ray
    ray = camera.screen_point_to_ray(mouse_screen_pos)
    max_distance = 20.0
    
    # Step 2: Hit validation
    hit = physics.raycast(ray, max_distance=max_distance)
    if not hit or hit.transform.tag != "Mesh":
        return

    hit_pos = hit.point

    # Step 3: Position to chunk indices
    chunk_indices = get_current_chunk_from_pos(hit_pos)
    cx, cy, cz = chunk_indices

    # Step 4: Position to local voxel indices
    local_voxel_indices = get_current_cube_in_chunk_from_pos(hit_pos)
    vx, vy, vz = local_voxel_indices

    # Step 5: Direction
    # Assuming left button is 1, right is -1. This logic is external to the core method but implied.
    # For the sake of self-contained pseudocode, we assume a function get_edit_direction() exists.
    dir = get_edit_direction() 

    # Step 6: Modify voxels
    hit_chunk = chunks[cx, cy, cz]
    set_noise_values(hit_chunk, vx, vy, vz, dir * edit_value, radius)

    # Step 7: Regenerate meshes
    update_surrounding_chunks(cx, cy, cz)

def set_noise_values(chunk, center_vx, center_vy, center_vz, value, radius):
    """
    Modifies voxel density in a spherical radius around the center voxel.
    Note: The exact implementation of spherical iteration is not detailed in [S1, unofficial].
    We assume a bounding box iteration with distance check.
    """
    half_radius = int(radius)
    for x in range(center_vx - half_radius, center_vx + half_radius + 1):
        for y in range(center_vy - half_radius, center_vy + half_radius + 1):
            for z in range(center_vz - half_radius, center_vz + half_radius + 1):
                # Check bounds of the chunk
                if not chunk.is_valid_voxel(x, y, z):
                    continue
                
                # Calculate distance from center
                dist_sq = (x - center_vx)**2 + (y - center_vy)**2 + (z - center_vz)**2
                if dist_sq <= radius**2:
                    # Modify density
                    # The source [S1, unofficial] shows noise generation using Perlin,
                    # but the edit function likely adds/subtracts a value or applies a noise perturbation.
                    # Based on "SetNoiseValues... to modify noise", we assume direct addition for simplicity
                    # or a noise-based modification. Given the lack of specific formula in the edit context,
                    # we assume a direct value addition as per "dir * editValue".
                    chunk.noise_matrix[x, y, z] += value
```

**Parameters:**
- **Max Ray Distance:** 20 units [S1, unofficial].
- **Edit Value:** Not specified in sources. [G] Typical values might range from 0.1 to 1.0 depending on density scale.
- **Radius:** Not specified in sources. [G] Typical values might be 1-5 voxels for fine sculpting.

**Edge Cases:**
- **Ray Miss:** If the ray does not hit a "Mesh" tagged object, no edit occurs [S1, unofficial].
- **Chunk Boundaries:** `GetCurrentCubeInChunkFromPos` must correctly handle voxels on chunk boundaries. If the hit point is exactly on a boundary, the chunk index calculation must be deterministic.
- **Precision:** Floating-point precision in `hit.point` and subsequent index calculations can lead to jitter if not handled carefully. [G] Rounding or epsilon checks may be needed.

## Operating characteristics
- **Time Complexity:** Raycasting is $O(1)$ for a single ray. Voxel modification is $O(r^3)$ where $r$ is the radius. Mesh regeneration is $O(v)$ where $v$ is the number of voxels in the chunk and its neighbors.
- **Memory Complexity:** $O(1)$ additional memory for the edit operation, assuming in-place modification of the chunk's noise matrix.
- **Strengths:** Interactive, immediate feedback. Simple to implement.
- **Limitations:** Limited to local edits. Performance may degrade if many chunks are regenerated simultaneously.
- **When to Use:** Interactive voxel sculpting tools.
- **When Not to Use:** Large-scale, non-interactive terrain generation.
