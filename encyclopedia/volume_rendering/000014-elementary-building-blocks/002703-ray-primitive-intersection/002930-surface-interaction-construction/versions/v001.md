# Surface Interaction Construction

Also called: SurfaceInteraction3f Construction

## Overview
Constructs a `SurfaceInteraction3f` structure from a ray and intersection time, computing the surface normal, local frame, and other interaction properties for ray-surface intersection [S1, unofficial]. It determines the sign of the Signed Distance Function (SDF) using the normal of the closest surface point via a dot product [S2, unofficial]. Unlike depth-based sign determination, this method works better for meshes with holes but suffers from cone-shaped artifacts in the SDF volume [S2, unofficial].

## How it works
**Inputs:**
- `ray`: The incident ray, containing origin `ray.o`, direction `ray.d`, and wavelengths `ray.wavelengths`.
- `t`: The intersection time (distance along the ray).
- `gradient(p)`: A function returning the gradient of the SDF at point `p`.

**Outputs:**
- `si`: A `SurfaceInteraction3f` structure containing:
  - `si.t`: Intersection distance.
  - `si.p`: Intersection point.
  - `si.n`: Surface normal.
  - `si.sh_frame`: Shading frame (basis vectors `n`, `s`, `t`).
  - `si.wi`: Incoming direction in local space.
  - `si.wavelengths`: Ray wavelengths.
  - `si.dp_du`, `si.dp_dv`: Tangent and bitangent vectors.

**Parameters:**
- `normal_sample_count`: Number of nearby surface points to check when determining SDF sign using `sign_method='normal'`. Default value is 11 [S2, unofficial].

**Steps:**
1. Set `si.t = t`.
2. Compute intersection point: `si.p = ray.o + t * ray.d`.
3. Compute the unnormalized gradient at `si.p`.
4. Compute the shading normal: `si.sh_frame.n = normalize(gradient(si.p))`.
5. Initialize the shading frame `si.sh_frame` using `si.sh_frame.n` to derive orthogonal tangent `s` and bitangent `t` vectors [G].
6. Set `si.n = si.sh_frame.n`.
7. Compute the incoming direction in local space: `si.wi = to_local(-ray.d)`.
8. Set `si.wavelengths = ray.wavelengths`.
9. Set `si.dp_du = sh_frame.s`.
10. Set `si.dp_dv = sh_frame.t`.
11. Determine the sign of the SDF. If `sign_method='normal'`, use a majority vote on `normal_sample_count` nearby surface points to determine the sign based on the dot product of normals [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Cone-shaped artifacts:** Produces cone-shaped artifacts in the SDF volume, especially when the mesh contains tiny triangles facing differently than surrounding areas [S2, unofficial].
- **Ineffectiveness of sampling increase:** Increasing `normal_sample_count` does not help mitigate cone artifacts [S2, unofficial].
- **Mesh Smoothing:** Smoothing the mesh does not seem to help with these artifacts [S2, unofficial].
- **Holes:** While this method works better for meshes with holes compared to the depth method, it is susceptible to the aforementioned artifacts [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Strengths:** Works better for meshes with holes compared to the depth method [S2, unofficial].
- **Limitations:** Suffers from cone-shaped artifacts in the SDF volume, particularly with tiny triangles facing differently than surrounding areas [S2, unofficial].
- **When to use:** Use when the mesh has holes and the depth method is not viable [S2, unofficial].
- **When not to use:** Avoid if the mesh contains tiny triangles with inconsistent orientations, as this leads to cone artifacts that cannot be easily fixed by increasing sample counts [S2, unofficial].

## Background
This method is part of the `mesh_to_sdf` library ecosystem, which calculates signed distance values for query points [S2, unofficial]. It is used in conjunction with SDF rendering integrators, such as those in the `relaxed-boundary` project, to construct surface interactions for ray marching [S1, unofficial].
