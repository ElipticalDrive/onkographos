# Ray Crossing Count (Winding Number)

Also called: Ray-Triangle Crossing Count, winding number via crossing count, Crossing Count Ray Query

## Overview
The Ray Crossing Count method determines whether a query point lies inside, outside, or on the boundary of a closed triangle mesh by casting rays and counting signed intersections with the mesh geometry [S1, unofficial]. It solves the point-in-mesh containment problem required for interior testing in volume rendering algorithms like Marching Cubes [S1, unofficial]. Unlike simple binary hit tests, this method computes a generalized winding number: it returns exactly 1 for points inside a closed, outward-oriented mesh, 0 for points outside, and a continuous value between 0 and 1 for points near holes or in non-manifold configurations [S1, unofficial]. A point outside the object yields 0, no point yields values < 0, and points inside yield exactly 1 [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Input**: A query point $P$, a ray direction $\mathbf{d}$, and a triangle mesh represented by a bounding volume hierarchy (BVH) [S1, unofficial].
- **Output**: An integer `crossingCount` representing the winding number [S1, unofficial].

**Data Structures**
- **BVH Node**: Contains an axis-aligned bounding box (AABB) and child pointers or triangle indices for leaves [G].
- **Triangle**: Defined by three vertices and a precomputed normal vector $\mathbf{n}$ [G].

**Algorithm Steps**
1. Initialize `crossingCount` to 0 and `totalCount` to 0 [S1, unofficial].
2. Traverse the BVH to find every triangle whose bounding box intersects the given ray originating at $P$ with direction $\mathbf{d}$ [S1, unofficial].
3. For each intersecting triangle $T$:
   a. Increment `totalCount` [S1, unofficial].
   b. Update `crossingCount` by adding +1 if $\mathbf{n}_T \cdot \mathbf{d} > 0$, otherwise adding -1 [S1, unofficial].
4. Return `crossingCount` [S1, unofficial].

**Evaluation Strategy**
The query is evaluated exactly near the point and by a second-order expansion of each far BVH node [S1, unofficial].

**Formula**
For a closed, outward-oriented surface mesh, a ray from an outside point yields a net crossing count of 0, and from an inside point yields +1 (exiting once more than entering) [S1, unofficial]. The contribution of each triangle $i$ is:
$$ W = \sum_{i} \text{sign}(\mathbf{n}_i \cdot \mathbf{d}) $$
where $\text{sign}(x) = +1$ if $x > 0$ and $-1$ otherwise [S1, unofficial].

**Pseudocode**
```python
def ray_crossing_count(query_point, ray_direction, bvh_root):
    """
    Computes the signed ray crossing count for a query point against a mesh in a BVH.
    
    Args:
        query_point: 3D vector (x, y, z)
        ray_direction: 3D vector (x, y, z), assumed normalized
        bvh_root: Root node of a BVH containing triangles with normals
    
    Returns:
        int: The winding number (crossing count)
    """
    crossing_count = 0
    total_count = 0
    stack = [bvh_root]
    
    while stack:
        node = stack.pop()
        
        # Standard BVH traversal and ray-AABB intersection [G]
        if not ray_aabb_intersect(query_point, ray_direction, node.aabb_min, node.aabb_max):
            continue
            
        if node.is_leaf:
            for triangle in node.triangles:
                # Standard ray-triangle intersection [G]
                if ray_triangle_intersect(query_point, ray_direction, triangle):
                    total_count += 1
                    dot_product = dot(triangle.normal, ray_direction)
                    if dot_product > 0.0:
                        crossing_count += 1
                    else:
                        crossing_count -= 1
        else:
            stack.append(node.left_child)
            stack.append(node.right_child)
            
    return crossing_count

def ray_aabb_intersect(origin, direction, aabb_min, aabb_max):
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < aabb_min[i] or origin[i] > aabb_max[i]:
                return False
        else:
            t1 = (aabb_min[i] - origin[i]) / direction[i]
            t2 = (aabb_max[i] - origin[i]) / direction[i]
            if t1 > t2:
                t1, t2 = t2, t1
            t_min = max(t_min, t1)
            t_max = min(t_max, t2)
    return t_max >= t_min

def ray_triangle_intersect(origin, direction, triangle):
    v0, v1, v2 = triangle.vertices
    e1 = v1 - v0
    e2 = v2 - v0
    h = cross(direction, e2)
    a = dot(e1, h)
    if a <= 1e-7:
        return False
    f = 1.0 / a
    s = origin - v0
    u = f * dot(s, h)
    if u < 0.0 or u > 1.0:
        return False
    q = cross(s, e1)
    v = f * dot(direction, q)
    if v < 0.0 or u + v > 1.0:
        return False
    t = f * dot(e2, q)
    return t > 1e-7
```

**Parameters**
- **Ray Direction**: The method supports axis-aligned rays, as indicated by template signatures for signed crossing count on axis-aligned rays in the reference implementation [S1, unofficial].
- **Threshold**: A small epsilon is used in intersection tests to handle numerical precision [G].

**Edge Cases and Pitfalls**
- **Degenerate Intersections**: Rays hitting edges or vertices may double-count triangles, making the theoretical crossing count unreliable for single rays [S1, unofficial].
- **Numerical Stability**: For query rays hitting edges, vertices, or numerically complex configurations, the theory may not match practice [S1, unofficial].
- **Mesh Validity**: This method is meaningful for closed meshes only [S1, unofficial].
- **Multiple Rays**: The method can be evaluated using a majority vote of six rays' crossing parities to improve robustness [S1, unofficial].
