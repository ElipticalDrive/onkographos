# AABB Collision Detection
Also called: Axis-Aligned Bounding Box Collision, Axis-Aligned Bounding Box collision with axis-separated movement, Axis-Aligned Collision Sliding, Axis-Separated AABB Collision, Sliding Collision

## Overview
AABB Collision Detection is a discrete physics resolution method that prevents an Axis-Aligned Bounding Box (AABB) from penetrating solid voxel terrain by processing movement along each spatial axis independently [S1, S2, S3, unofficial]. It solves the problem of objects getting trapped inside walls by allowing sliding along surfaces rather than halting completely on a single-axis collision [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current AABB center position $(c_x, c_y, c_z)$, AABB half-dimensions $(h_x, h_y, h_z)$, intended displacement vector $\Delta = (\Delta_x, \Delta_y, \Delta_z)$, and a voxel world grid where `BlockID > 0` indicates solid terrain [S2, S3, unofficial].
*   **Output:** Updated AABB center position that respects collision constraints [S2, S3, unofficial].

**Data Structures:**
*   **Voxel World:** A 3D array or hash map mapping integer coordinates $(x, y, z)$ to block types, where `BlockID > 0` indicates solid terrain [S3, unofficial].
*   **AABB:** Defined by center position $(c_x, c_y, c_z)$ and half-dimensions $(h_x, h_y, h_z)$ [S2, unofficial].

**Parameters:**
*   **Camera/Player Dimensions:** Typical values include width 0.8, height 1.8, depth 0.2 [S2, unofficial] or width 0.3, height 1.7 [S3, unofficial].
*   **Gravity:** $18.0$ units/s² [S3, unofficial].
*   **Jump Force:** $8.0$ units/s [S3, unofficial].
*   **Time Step:** Movement is scaled by a time factor (e.g., `ms`) [S1, unofficial].
*   **Cell Size:** Assumed to be $1.0$ unit per voxel grid coordinate [G].

**Algorithm Steps:**
1.  **Calculate Displacement:** Compute the intended movement vector $\Delta = \text{new\_position} - \text{current\_position}$ [S2, unofficial].
2.  **Axis Separation:** Iterate through each axis (typically X, then Z, then Y to handle gravity correctly) [S2, S3, unofficial].
3.  **Apply Axis Movement:** Tentatively update the position component for the current axis:
    $$ \text{tentative\_pos}[axis] = \text{current\_pos}[axis] + \Delta[axis] $$
    [S2, unofficial]
4.  **Define Query Volume:** Calculate the voxel grid bounds that the AABB covers at this tentative position [S2, unofficial].
    *   $\text{min\_voxel}[i] = \lfloor \text{tentative\_pos}[i] - h_i \rfloor$ [S2, unofficial]
    *   $\text{max\_voxel}[i] = \lceil \text{tentative\_pos}[i] + h_i \rceil$ [S2, unofficial]
5.  **Collision Check:** Iterate through all voxel coordinates $(v_x, v_y, v_z)$ within the box defined by $\text{min\_voxel}$ and $\text{max\_voxel}$ [S2, S3, unofficial].
    *   *Condition:* If any voxel is solid (`BlockID > 0`), a collision is detected [S3, unofficial].
    *   *Optimization:* Alternatively, sample specific points (e.g., 12 points at Feet, Waist, Head) around the player model instead of iterating every voxel [S3, unofficial].
6.  **Resolution:**
    *   If collision detected: Revert the position component for this axis to its value before step 3 [S2, S3, unofficial].
    *   If no collision: Commit the tentative position for this axis [S2, S3, unofficial].
7.  **Repeat:** Proceed to the next axis [S2, S3, unofficial].

**Pseudocode:**
```python
import math

def aabb_collision_step(camera_pos, camera_half_dims, delta, world_voxel):
    """
    camera_pos: list of 3 floats [x, y, z] (center of AABB)
    camera_half_dims: list of 3 floats [hx, hy, hz]
    delta: list of 3 floats (intended movement)
    world_voxel: callable(x, y, z) -> int (returns BlockID)
    """
    tentative_pos = list(camera_pos)
    axes = [0, 2, 1]  # X, Z, then Y order for gravity handling [S2, S3, unofficial]
    
    for axis in axes:
        # Apply tentative movement on current axis
        tentative_pos[axis] += delta[axis]
        
        # Define voxel bounds for the AABB at tentative_pos
        min_voxel = [math.floor(tentative_pos[i] - camera_half_dims[i]) for i in range(3)]
        max_voxel = [math.ceil(tentative_pos[i] + camera_half_dims[i]) for i in range(3)]
        
        # Check for collisions
        collided = False
        
        # Iterate all voxels in the bounding box [S2, unofficial]
        for x in range(min_voxel[0], max_voxel[0] + 1):
            for y in range(min_voxel[1], max_voxel[1] + 1):
                for z in range(min_voxel[2], max_voxel[2] + 1):
                    if world_voxel(x, y, z) > 0:
                        collided = True
                        break
                if collided: break
            if collided: break
            
        # Resolution
        if not collided:
            camera_pos[axis] = tentative_pos[axis]
        # If collided, axis remains at previous value (movement cancelled)
            
    return camera_pos
```

**Edge Cases and Pitfalls:**
*   **Stuck Bug:** Checking collision against the *current* cell causes permanent sticking if the player starts inside a wall. The check must be against the *next* cell (the target position) [S1, unofficial].
*   **Corner Penetration:** Simple axis checks might allow corners to clip into walls if not validated properly. A "BoxClear Corner Check" tests all four corners of the box on both axis moves to ensure no overlap occurs [S4, unofficial].
*   **Ordering:** The order of axis processing affects behavior. Processing Y last allows sliding along walls while still applying gravity and jumping correctly [S3, unofficial].

## Subtopics

### [AABB Voxel Intersection](6734-aabb-voxel-intersection.md)
Determines whether an AABB overlaps with any solid voxel in a voxel world by iterating through integer coordinates. Unlike hierarchical methods, it performs a direct brute-force check of every voxel coordinate within the bounding volume.

### BoxClear Corner Check
A collision check variant that tests all four corners of the player box on both axis moves to prevent overlap. It asserts that no corner ever enters a solid cell and that pulling away from the wall works from the pressed position, fixing issues where simple axis checks fail to prevent corner clipping [S4, unofficial].

### AABB Collision with Step-Up & Per-Axis Snap-to-Contact
Uses AABB swept against the voxel grid with per-axis snap-to-contact collision resolution and auto step-up over 1-voxel lips. Ground friction is applied, and jump uses fixed-speed so lower gravity results in higher apex and longer hang time. Step-up height is 1 voxel [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the AABB's bounding box, reducible to a constant number of checks via point sampling [S2, S3, unofficial].
*   **Strengths:** Simple to implement; allows natural sliding along walls [S1, S3, unofficial].
*   **Limitations:** Corner clipping can occur without additional checks (BoxClear) [S4, unofficial].

## Background
This method is used in discrete grid-based environments and voxel engines to resolve movement without continuous collision detection [S2, S3, unofficial]. It appears in early 3D raycasting implementations and modern voxel game physics systems [S1, S3, unofficial].
