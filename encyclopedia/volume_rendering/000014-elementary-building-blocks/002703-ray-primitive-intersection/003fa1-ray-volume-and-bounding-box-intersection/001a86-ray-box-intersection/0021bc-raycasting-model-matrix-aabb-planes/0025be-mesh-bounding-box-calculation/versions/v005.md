# Mesh Bounding Box Calculation

Also called: axis-aligned bounding box, min-max vertex bounds

## Overview
Computes the axis-aligned bounding box (AABB) that encloses a mesh by determining the minimum and maximum coordinates across all its vertices [S1, unofficial]. It differs from [Character Bounding Box Initialization](4016-character-bounding-box-initialization.md) by operating on explicit vertex lists rather than parametric primitives, and from [Volume Bounds Computation](5114-volume-bounds-computation.md) by targeting mesh geometry rather than arbitrary point clouds or volumetric data.

## How it works
**Inputs:** A list of 3D vertices $V = \{v_0, v_1, \dots, v_{n-1}\}$, where each $v_i$ has components $(x_i, y_i, z_i)$.
**Outputs:** An AABB defined by a minimum corner $mn$ and a maximum corner $mx$, where $mn = (mn_x, mn_y, mn_z)$ and $mx = (mx_x, mx_y, mx_z)$.

**Data Structures:**
The AABB is typically stored as two 3D vectors or an array of 6 floats: `minmax[6]` where indices 0-2 are mins and 3-5 are maxs, or two separate `Vec3` structures.

**Steps:**
1.  **Initialization:** Set $mn$ and $mx$ to the coordinates of the first vertex $v_0$.
    $$ mn = v_0 $$
    $$ mx = v_0 $$
2.  **Iteration:** For each subsequent vertex $v_i$ where $i$ ranges from $1$ to $n-1$:
    For each dimension $d \in \{0, 1, 2\}$ (representing X, Y, Z):
    $$ mn_d = \min(v_{i,d}, mn_d) $$
    $$ mx_d = \max(v_{i,d}, mx_d) $$

**Pseudocode:**
```python
def compute_mesh_aabb(vertices):
    """
    Computes the AABB for a list of 3D vertices.
    vertices: List of tuples/objects with x, y, z attributes.
    Returns: Tuple (min_vec, max_vec)
    """
    if not vertices:
        raise ValueError("Vertex list cannot be empty") # [G] Guard against pitfall

    # Initialize min and max with the first vertex
    first = vertices[0]
    mn_x, mn_y, mn_z = first.x, first.y, first.z
    mx_x, mx_y, mx_z = first.x, first.y, first.z

    # Iterate through remaining vertices
    for i in range(1, len(vertices)):
        v = vertices[i]
        
        # Update minimums
        if v.x < mn_x: mn_x = v.x
        if v.y < mn_y: mn_y = v.y
        if v.z < mn_z: mn_z = v.z
        
        # Update maximums
        if v.x > mx_x: mx_x = v.x
        if v.y > mx_y: mx_y = v.y
        if v.z > mx_z: mx_z = v.z

    return (mn_x, mn_y, mn_z), (mx_x, mx_y, mx_z)
```

**Parameters:**
-   Precision: Single (`float`) or double (`double`) precision. [S1, unofficial] defines a `precision_type` typedef.
-   Epsilon: A small value (e.g., $10^{-9}$) may be used for numerical stability in comparisons, though not explicitly required for the basic min/max logic [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Empty Input:** Accessing `v[0]` on an empty vertex list causes undefined behavior [S1, unofficial]. The implementation must check for an empty list before initialization [G].
-   **Degenerate Mesh:** If all vertices are identical, $mn$ equals $mx$. This is a valid degenerate AABB with zero volume.

## Subtopics

### [Bounding Cube Creation](4007-bounding-cube-creation.md)
Adjusts an AABB to be a perfect cube by expanding the smaller dimensions to match the largest dimension, centered on the original bounding box center. Used in voxelization and sparse voxel octree (SVO) construction to ensure uniform grid resolution [4007-bounding-cube-creation.md].

### [Character Bounding Box Initialization](4016-character-bounding-box-initialization.md)
Computes the AABB for specific character primitives (arcs, line segments) to optimize sphere tracing. Operates on parametric primitives rather than vertex lists, providing a tighter bound than cube creation [4016-character-bounding-box-initialization.md].

### [Volume Bounds Computation](5114-volume-bounds-computation.md)
Computes an AABB for arbitrary 3D point clouds or sample sets, often with optional padding. Operates on general point sets rather than explicit mesh geometry [5114-volume-bounds-computation.md].

### AABB Vertex Coordinate Encoding
Determines the coordinates of any of the 8 vertices of an AABB using a vertex index (0-7) and bit manipulation, avoiding floating-point arithmetic for coordinate selection [S2, unofficial].
-   **Logic:** Bit 0 of the index corresponds to X, bit 1 to Y, bit 2 to Z. If the bit is 0, the coordinate is the min value; if 1, it is the max value.
-   **Formula:** For vertex index $i$:
    $$ x = \text{minmax}_x[i \& 1] $$
    $$ y = \text{minmax}_y[(i \& 2) >> 1] $$
    $$ z = \text{minmax}_z[(i \& 4) >> 2] $$
    where `minmax_x` is an array `[x_min, x_max]` [S2, unofficial].

### AABB Enclosure (Union)
Computes the AABB enclosing two input AABBs ($b_0$ and $b_1$).
-   **Logic:** Component-wise min/max on the min/max arrays.
-   **Formula:**
    $$ \text{new\_min}_d = \min(b_{0,\text{min}_d}, b_{1,\text{min}_d}) $$
    $$ \text{new\_max}_d = \max(b_{0,\text{max}_d}, b_{1,\text{max}_d}) $$
    for each axis $d \in \{x, y, z\}$ [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** $O(n)$, where $n$ is the number of vertices. Each vertex requires 6 comparisons.
-   **Memory Complexity:** $O(1)$ auxiliary space (storing only min and max vectors).
-   **Strengths:** Extremely fast, cache-friendly, and simple to implement.
-   **Limitations:** Only provides a loose bound for complex shapes; does not account for orientation (requires model matrix transformation for rotated meshes).
-   **When to use:** As a first-pass culling step or for generating initial spatial bounds for meshes.

## Background
This method is a fundamental building block in computer graphics, specifically in raycasting and collision detection. It is often the first step in constructing acceleration structures like BVHs or grids. The specific implementation details (handling of empty lists, precision types) are commonly found in voxelization tools and geometry processing libraries [S1, unofficial]. The bit-manipulation trick for vertex encoding is a known optimization in AABB arithmetic [S2, unofficial].
