# Character Bounding Box Initialization

Also called: Bounding Box Initialization for Characters

## Overview
This method initializes the geometric primitives (characters 'S', 'A', 'N', 'G' and arcs) and computes a surrounding Axis-Aligned Bounding Box (AABB) to optimize sphere tracing queries [S1, unofficial]. It differs from generic mesh bounding box calculation by explicitly defining parametric curves and line segments for stylized text rather than processing a vertex buffer [S1, unofficial]. It serves as a specialized pre-processing step for Signed Distance Field (SDF) rendering of text [S1, unofficial].

## How it works
**Inputs:**
- Character definitions: 'S', 'A', 'N', 'G' composed of spheres and lines.
- Offset value: A scalar added to the bounding box dimensions to prevent ray misses near character edges.

**Outputs:**
- `surrounding_bbox`: An AABB defined by minimum and maximum coordinates enclosing all character primitives.

**Data Structures:**
- Primitive definitions: Each character is defined by a set of geometric primitives.
  - 'S': Two arcs (`sphere_upper_arc`, `sphere_lower_arc`).
  - 'A': Three line segments (`left_leg`, `right_leg`, `horizontal_line`).
  - 'N': Three line segments (`left_leg`, `right_leg`, `connector`).
  - 'G': One arc and multiple line segments.
- Bounding Box: Represented as a pair of 3D vectors `min` and `max`.

**Parameters:**
- `offset`: Value added to the computed bounding box extents. Typical value: `0.1f` [S1, unofficial].

**Steps:**
1. **Define 'S' Character:**
   - Create `sphere_upper_arc` and `sphere_lower_arc`.
   - Specify centers, radii, and start/end angles for each arc [S1, unofficial].
2. **Define 'A' Character:**
   - Create vertices for `left_leg`, `right_leg`, and `horizontal_line` [S1, unofficial].
3. **Define 'N' Character:**
   - Create vertices for `left_leg`, `right_leg`, and `connector` [S1, unofficial].
4. **Define 'G' Character:**
   - Create arc for 'G' [S1, unofficial].
   - Create vertices for line segments of 'G' [S1, unofficial].
5. **Compute Extents:**
   - Initialize `min` to $(+\infty, +\infty, +\infty)$ and `max` to $(-\infty, -\infty, -\infty)$.
   - For each primitive in all characters:
     - Compute the bounding box of the primitive (sphere or line segment).
     - Update `min` and `max` with the element-wise minimum and maximum of the primitive's bounds and the current `min`/`max` [S1, unofficial].
6. **Apply Offset:**
   - Expand `min` by subtracting `offset` from each component.
   - Expand `max` by adding `offset` to each component [S1, unofficial].
7. **Create Bounding Box:**
   - Store the final `min` and `max` in `surrounding_bbox` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Use `float` consistency for all calculations to match the source implementation [S1, unofficial].
- **Offset Value:** The offset `0.1f` is critical to avoid missing points too close to the letters during sphere tracing [S1, unofficial].
- **Arc Bounds:** Computing the AABB of an arc is non-trivial as the extrema may lie at the endpoints or at the points where the tangent is parallel to the axes [G].

## Subtopics

### Player Axis-Aligned Bounding Box (AABB) Construction
Computes the player's collision bounding box by offsetting the center position by a bottom offset and capping at a top offset [S2, unofficial]. It differs from character initialization by using a dynamic player position rather than static character primitives [S2, unofficial]. Choose this for player collision detection in voxel engines [S2, unofficial].
- **Definition:** Computes AABB from player position and height [S2, unofficial].
- **Steps:**
  1. Retrieve player position `pos` (defaults to `this.playerPosition()`) [S2, unofficial].
  2. Initialize `lower` as an empty array [S2, unofficial].
  3. Set `upper` to `[0.5, this.playerHeight, 0.5]` and `playerBottom` to `[0.25, this.playerHeight, 0.25]` [S2, unofficial].
  4. Compute `lower = pos - playerBottom` using vector subtraction [S2, unofficial].
  5. Construct AABB from `lower` and `upper` [S2, unofficial].
- **Parameters:** `this.playerHeight`: Player's vertical extent in world units [S2, unofficial].
- **Layout:** AABB is represented as a pair of 3D coordinate arrays `[x, y, z]` for lower and upper bounds. `lower` and `upper` are standard JavaScript arrays of numbers [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of primitives in the character definitions. The number of primitives is constant for a fixed set of characters.
- **Memory Complexity:** Constant, storing only the bounding box coordinates and primitive definitions.
- **Performance:** Not given in the sources.
- **Strengths:** Optimizes sphere tracing by providing a tight bounding volume for text [S1, unofficial].
- **Limitations:** Specific to the defined characters ('S', 'A', 'N', 'G') [S1, unofficial].
- **When to use:** When rendering static text using SDF sphere tracing [S1, unofficial].
- **When not to use:** For dynamic text or different character sets without re-initialization [S1, unofficial].

## Background
This method originates from the SDF-Sphere-Tracing project by AlerianEmperor [S1, unofficial]. It is used in the context of real-time raymarching of signed distance fields for stylized text [S1, unofficial]. The player AABB construction is part of the voxel-engine-stackgl project [S2, unofficial].
