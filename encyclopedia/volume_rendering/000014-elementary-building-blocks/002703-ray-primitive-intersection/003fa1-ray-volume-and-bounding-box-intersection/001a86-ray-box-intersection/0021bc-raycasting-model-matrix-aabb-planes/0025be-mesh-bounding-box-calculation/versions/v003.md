# Mesh Bounding Box Calculation

Also called: axis-aligned bounding box, min-max vertex bounds

## Overview
Computes the axis-aligned bounding box (AABB) of a mesh by finding the minimum and maximum coordinates across all vertices [S1, unofficial]. It operates on vertex coordinates of explicit geometry, unlike [Volume Bounds Computation](5114-volume-bounds-computation.md), which operates on arbitrary point clouds or sample sets [S1, unofficial].

## How it works
**Inputs:** A list of 3D vertices $V = \{v_0, v_1, \dots, v_{n-1}\}$, where each vertex $v_i$ has coordinates $(x_i, y_i, z_i)$ [S1, unofficial].
**Outputs:** An AABB defined by two 3D vectors: `min` ($mn$) and `max` ($mx$) [S1, unofficial].

**Data Structures:**
*   `Vec3`: A structure containing three floating-point components accessible via array indexing `m_pos[3]` or named fields `m_x`, `m_y`, `m_z` [S1, unofficial].
*   `mn`, `mx`: `Vec3` instances initialized to the bounds [S1, unofficial].

**Steps:**
1.  **Validation:** Check if the vertex list $V$ is empty [S1, unofficial].
2.  **Initialization:** Set `mn` and `mx` to the coordinates of the first vertex $v_0$ [S1, unofficial].
    $$ mn = v_0, \quad mx = v_0 $$
3.  **Iteration:** For each vertex $v_i$ in $V$ where $i$ ranges from $1$ to $n-1$:
    For each dimension $d \in \{0, 1, 2\}$ (representing X, Y, Z):
    $$ mn[d] = \min(v_i[d], mn[d]) $$
    $$ mx[d] = \max(v_i[d], mx[d]) $$

**Pseudocode:**
```python
def compute_mesh_aabb(vertices):
    """
    Computes the AABB for a list of 3D vertices.
    vertices: List of tuples or objects with x, y, z attributes.
    Returns: (min_vec, max_vec)
    """
    if not vertices:
        raise ValueError("Empty vertex list causes undefined behavior")
    
    first = vertices[0]
    mn = [first[0], first[1], first[2]]
    mx = [first[0], first[1], first[2]]
    
    for i in range(1, len(vertices)):
        v = vertices[i]
        for d in range(3):
            if v[d] < mn[d]: mn[d] = v[d]
            if v[d] > mx[d]: mx[d] = v[d]
            
    return mn, mx
```

**Parameters:**
*   `EPSILON`: A small constant defined as $10^{-9}$ in the source implementation [S1, unofficial].
*   `precision_type`: Configurable as `float` or `double` [S1, unofficial].

**Edge Cases:**
*   **Empty Input:** Accessing `v[0]` on an empty list causes undefined behavior [S1, unofficial].
*   **Degenerate Geometry:** The method correctly computes the extent for degenerate meshes (single point, line, or coplanar vertices) [G].

## Subtopics

### Bounding Cube Creation
Creates a cubic bounding box (AABox) by expanding the minimum bounding box dimensions to be equal in all axes, padding equally on both sides [S2, unofficial].
*   **Definition:** Converts an arbitrary AABB into a cube centered at the same centroid.
*   **Steps:**
    1.  Get the mesh's bounding box `min` and `max` [S2, unofficial].
    2.  Calculate axis lengths: $L_x = max_x - min_x$, $L_y = max_y - min_y$, $L_z = max_z - min_z$ [S2, unofficial].
    3.  Find the maximum length $L_{max} = \max(L_x, L_y, L_z)$ [S2, unofficial].
    4.  For each axis $i$, calculate delta: $\delta_i = L_{max} - L_i$ [S2, unofficial].
    5.  Adjust bounds: $min_i = min_i - \delta_i / 2$, $max_i = max_i + \delta_i / 2$ [S2, unofficial].
*   **Layout:** `AABox<vec3>`: A bounding box structure defined by `min` and `max` `vec3` coordinates [S2, unofficial].
*   **When to choose:** When a uniform spatial resolution or cubic voxelization grid is required, ensuring no axis is smaller than the largest dimension of the object [G].
*   **Link:** [Bounding Cube Creation](3612-mesh-bounding-box-calculation.md#bounding-cube-creation) [G]

### Character Bounding Box Initialization
Initializes positions of specific character primitives (S, A, N, G) and arcs, computing a surrounding bounding box to optimize sphere tracing queries [S3, unofficial].
*   **Definition:** A specialized bounding box calculation for signed distance field (SDF) character rendering.
*   **Steps:**
    1.  Define primitives (arcs for 'S', vertices for 'A', 'N', 'G') [S3, unofficial].
    2.  Compute global min/max x, y, z of all primitives [S3, unofficial].
    3.  Apply an offset (default $0.1$) to the bounds to avoid missing points too close to the letters [S3, unofficial].
    4.  Create `surrounding_bbox` with these coordinates [S3, unofficial].
*   **When to choose:** Specifically for SDF-based text rendering where tight bounds improve ray marching efficiency [G].
*   **Link:** [Character Bounding Box Initialization](3612-mesh-bounding-box-calculation.md#character-bounding-box-initialization) [G]

### AABB Vertex Coordinate Encoding
Determines the coordinates of any of the 8 vertices of an AABB using a vertex index (0-7) and bit manipulation, avoiding floating-point arithmetic for coordinate selection [S4, unofficial].
*   **Definition:** A lookup method for AABB corners based on binary encoding.
*   **Steps:**
    1.  The AABB has 8 vertices [S4, unofficial].
    2.  Bit 0 of the index corresponds to X, Bit 1 to Y, Bit 2 to Z [S4, unofficial].
    3.  If the bit is 0, the coordinate is `min`; if 1, it is `max` [S4, unofficial].
    4.  Extract coordinates using bit masking:
        $$ x = aabb.x\_minmax[(i \& 1) >> 0] $$
        $$ y = aabb.y\_minmax[(i \& 2) >> 1] $$
        $$ z = aabb.z\_minmax[(i \& 4) >> 2] $$
*   **When to choose:** When iterating over AABB corners for plane intersection tests or collision detection where floating-point branching is undesirable [G].
*   **Link:** [AABB Vertex Coordinate Encoding](3612-mesh-bounding-box-calculation.md#aabb-vertex-coordinate-encoding) [G]

### AABB Enclosure (Union)
Computes the AABB enclosing two input AABBs by taking the component-wise minimum of their mins and maximum of their maxs [S4, unofficial].
*   **Definition:** Merging two spatial bounds into one.
*   **Steps:**
    1.  Given $b_0$ and $b_1$ [S4, unofficial].
    2.  $new\_min = \min(b_0.min, b_1.min)$ [S4, unofficial].
    3.  $new\_max = \max(b_0.max, b_1.max)$ [S4, unofficial].
*   **When to choose:** When combining multiple objects or sub-grids into a single parent bounding volume [G].
*   **Link:** [AABB Enclosure (Union)](3612-mesh-bounding-box-calculation.md#aabb-enclosure-union) [G]

## Operating characteristics
*   **Time Complexity:** $O(n)$, where $n$ is the number of vertices, as each vertex is visited exactly once [G].
*   **Memory Complexity:** $O(1)$ auxiliary space, maintaining only two `Vec3` structures [G].
*   **Strengths:** Extremely fast, cache-friendly, and numerically stable for standard floating-point ranges.
*   **Limitations:** Does not account for mesh normals or implicit surfaces; only bounds the explicit vertex positions. Empty inputs cause crashes in the basic implementation [S1, unofficial].
*   **When to use:** As a first-pass culling step in raycasting or rasterization [G].
*   **When not to use:** When tighter bounds are required (e.g., oriented bounding boxes) or when the mesh has no vertices (e.g., pure implicit volume) [G].

## Background
The algorithm iterates over vertex coordinates to compute min-max bounds [S1, unofficial]. Variants include cubic expansion for voxelization [S2, unofficial], character primitive bounding for SDF rendering [S3, unofficial], and bit-manipulation vertex encoding for plane tests [S4, unofficial].
