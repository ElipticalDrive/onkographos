# Host-side Bounding Box Computation

Also called: ComputeBoundHost, UnionBoundHost

## Overview
Computes the axis-aligned bounding box (AABB) for each triangle in a mesh on the CPU host, producing separate arrays for minimum and maximum coordinates. It serves as the prerequisite step for GPU-based voxelization by providing the spatial extent of each primitive before ray-primitive intersection or volume rasterization. It differs from [Mesh Bounding Box Calculation](3612-mesh-bounding-box-calculation.md), which computes a single global AABB for the entire mesh, by maintaining per-triangle bounds.

## How it works
**Inputs:**
- `vertices`: Pointer to an array of `float` values representing vertex positions. The layout is contiguous triples (x, y, z), indexed by triangle indices.
- `triangles`: Pointer to an array of `int` indices. Each triangle consists of 3 indices into the `vertices` array.
- `N`: The number of triangles in the mesh.
- `n_cores`: The number of CPU threads to use for parallel execution.

**Outputs:**
- `bbox0`: Output array of `float` of size at least $3 \times N$. Stores the minimum coordinates (min_x, min_y, min_z) for each triangle.
- `bbox1`: Output array of `float` of size at least $3 \times N$. Stores the maximum coordinates (max_x, max_y, max_z) for each triangle.

**Data Structure Layout:**
The output arrays use a Structure of Arrays (SoA) layout optimized for component-wise access. For triangle index $i$ ($0 \le i < N$):
- `bbox0[i]` stores $\min_x$
- `bbox0[i + N]` stores $\min_y$
- `bbox0[i + 2N]` stores $\min_z$
- `bbox1[i]` stores $\max_x$
- `bbox1[i + N]` stores $\max_y$
- `bbox1[i + 2N]` stores $\max_z$

**Algorithm Steps:**
1. **Dispatch:** Check if `n_cores > 1`.
   - If true, call `ComputeBoundParallel` with `begin=0` and `end=N`.
   - If false, call `ComputeBoundSerial` with `begin=0` and `end=N`.
2. **Serial Execution (`ComputeBoundSerial`):**
   - Iterate `tri_idx` from `begin` to `end`.
   - Initialize `bbox0` and `bbox1` entries for `tri_idx` to extreme values:
     - For $c \in \{0, 1, 2\}$:
       - $c\_idx = tri\_idx + c \times N$
       - $bbox0[c\_idx] = \text{FLT\_MAX}$
       - $bbox1[c\_idx] = -\text{FLT\_MAX}$
   - For each vertex $v \in \{0, 1, 2\}$ of the triangle:
     - Retrieve vertex index: $idx = triangles[tri\_idx \times 3 + v]$
     - Retrieve vertex pointer: $ptr = &vertices[3 \times idx]$
     - For $c \in \{0, 1, 2\}$:
       - $val = ptr[c]$
       - $c\_idx = tri\_idx + c \times N$
       - Update bounds:
         - If $val < bbox0[c\_idx]$, set $bbox0[c\_idx] = val$
         - If $val > bbox1[c\_idx]$, set $bbox1[c\_idx] = val$
3. **Parallel Execution (`ComputeBoundParallel`):**
   - Calculate `thread_size = N / n_threads`.
   - Create `n_threads - 1` threads, each processing a chunk of `thread_size` triangles starting from `begin`.
   - The last thread processes the remaining triangles from `begin + (n_threads - 1) * thread_size` to `end`.
   - Each thread executes the logic of `ComputeBoundSerial` for its assigned range.

**Pseudocode:**
```python
import math
import threading

def compute_bound_host(vertices, triangles, N, n_cores=1):
    """
    Computes per-triangle AABBs on the host.
    vertices: list of floats [x0, y0, z0, x1, y1, z1, ...]
    triangles: list of ints [v0, v1, v2, ...]
    N: number of triangles
    n_cores: number of threads
    Returns: bbox0 (min), bbox1 (max) arrays of size 3*N
    """
    if N < 1:
        return [], []

    # Initialize output arrays
    # Size 3*N for SoA layout
    bbox0 = [float('inf')] * (3 * N)
    bbox1 = [float('-inf')] * (3 * N)

    if n_cores > 1:
        compute_bound_parallel(vertices, triangles, N, bbox0, bbox1, n_cores)
    else:
        compute_bound_serial(vertices, triangles, N, 0, N, bbox0, bbox1)

    return bbox0, bbox1

def compute_bound_serial(vertices, triangles, N, begin, end, bbox0, bbox1):
    for tri_idx in range(begin, end):
        # Initialize bounds for this triangle
        for c in range(3):
            c_idx = tri_idx + c * N
            bbox0[c_idx] = float('inf')
            bbox1[c_idx] = float('-inf')

        # Process 3 vertices of the triangle
        base_tri_idx = tri_idx * 3
        for v in range(3):
            vert_idx = triangles[base_tri_idx + v]
            base_vert_idx = vert_idx * 3
            
            # Update bounds for x, y, z
            for c in range(3):
                val = vertices[base_vert_idx + c]
                c_idx = tri_idx + c * N
                
                if val < bbox0[c_idx]:
                    bbox0[c_idx] = val
                if val > bbox1[c_idx]:
                    bbox1[c_idx] = val

def compute_bound_parallel(vertices, triangles, N, bbox0, bbox1, n_cores):
    thread_size = N // n_cores
    threads = []
    
    # Create n_cores - 1 threads
    for t in range(n_cores - 1):
        start_idx = t * thread_size
        end_idx = (t + 1) * thread_size
        thread = threading.Thread(
            target=compute_bound_serial,
            args=(vertices, triangles, N, start_idx, end_idx, bbox0, bbox1)
        )
        threads.append(thread)
        thread.start()
        
    # Last thread processes the remainder
    last_start = (n_cores - 1) * thread_size
    last_end = N
    thread = threading.Thread(
        target=compute_bound_serial,
        args=(vertices, triangles, N, last_start, last_end, bbox0, bbox1)
    )
    threads.append(thread)
    thread.start()
    
    for thread in threads:
        thread.join()
```

**Parameters:**
- `vertices`: Array of floats. Layout is interleaved (x,y,z) per vertex.
- `triangles`: Array of integers. Indices into `vertices`.
- `N`: Integer, number of triangles.
- `n_cores`: Integer, number of CPU threads. Default 4 in source implementation.

**Edge Cases and Pitfalls:**
- If `N < 1`, the function returns immediately to avoid invalid memory access or division by zero in parallel logic [S1, unofficial].
- `ComputeBoundSerial` handles empty ranges (`begin >= end`) by doing nothing, which is safe for the last thread in parallel execution if `N` is not evenly divisible by `n_cores` [S1, unofficial].
- Precision issues are minimal as standard float comparisons are used, but initialization to `FLT_MAX` and `-FLT_MAX` is critical for correctness [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of triangles. Each triangle is processed exactly once.
- **Memory Complexity:** $O(N)$ for the output arrays `bbox0` and `bbox1`.
- **Performance:** Parallel execution scales with `n_cores`. The source implementation uses a simple chunking strategy. No specific hardware benchmarks are provided in the sources.
- **Strengths:** Simple, deterministic, and easy to parallelize. Provides per-triangle bounds necessary for efficient voxelization culling.
- **Limitations:** Does not compute a global mesh bound. Requires host-side memory allocation for output arrays.

## Background
This method is part of the host-side preprocessing pipeline for GPU-based voxelization, specifically from the `hpsoar/voxelizer` project. It prepares the geometric data for the `voxelize_kernel` which runs on the GPU device. The method is distinct from global bounding box computation, focusing on per-primitive bounds to enable efficient spatial partitioning during rasterization.
