# AABB Representation (Min/Max)
Also called: AABB Data Structure, Axis-Aligned Bounding Box data structure, Min/Max corners, Slab representation

## Overview
The Min/Max AABB representation defines an axis-aligned bounding box by explicitly storing the minimum and maximum coordinate values along each of the three spatial axes [S1, unofficial]. It treats the box as the intersection of three orthogonal "slabs" (infinite regions bounded by parallel planes) [S1, unofficial]. This representation is preferred over point-plus-dimensions (centroid + size) because merging two boxes is a trivial component-wise min/max operation, whereas the latter requires extra arithmetic [S1, unofficial].

## How it works
**Data Structures:**
The representation occupies 6 floating-point values. Two common layouts are cited:

1.  **Array-based (Slab) Layout:**
    Three arrays of two floats each.
    *   `x_minmax[2]`: `x_min` at index 0, `x_max` at index 1.
    *   `y_minmax[2]`: `y_min` at index 0, `y_max` at index 1.
    *   `z_minmax[2]`: `z_min` at index 0, `z_max` at index 1.
    *   Total size: 6 floats [S1, unofficial].

2.  **Vector-based Layout:**
    Two 3D vectors.
    *   `lb` (lower bound): `(x_min, y_min, z_min)`.
    *   `ub` (upper bound): `(x_max, y_max, z_max)`.
    *   Total size: 6 floats [S2, unofficial].

**Constructors:**
Common initialization methods include default initialization, construction from coordinates `(lb_x, lb_y, lb_z, ub_x, ub_y, ub_z)`, construction from Eigen vectors, construction from a sphere `(pos, radius)`, construction from a triangle `(v1, v2, v3)`, and merging two AABBs [S2, unofficial].

**Merging Logic:**
To compute the bounding box enclosing two AABBs ($b_0$ and $b_1$), the new bounds are calculated component-wise:
$$
\begin{aligned}
x_{min} &= \min(b_0.x_{min}, b_1.x_{min}) \\
x_{max} &= \max(b_0.x_{max}, b_1.x_{max}) \\
y_{min} &= \min(b_0.y_{min}, b_1.y_{min}) \\
y_{max} &= \max(b_0.y_{max}, b_1.y_{max}) \\
z_{min} &= \min(b_0.z_{min}, b_1.z_{min}) \\
z_{max} &= \max(b_0.z_{max}, b_1.z_{max})
\end{aligned}
$$
This is significantly simpler than the point-plus-dimensions representation, which requires recalculating the centroid and dimensions from the combined extents [S1, unofficial].

**Pseudocode:**
```python
class AABB:
    def __init__(self, lb=None, ub=None):
        # [G] Default constructor initializes to empty/infinite bounds or requires explicit assignment.
        if lb is None or ub is None:
            self.lb = [0.0, 0.0, 0.0]
            self.ub = [0.0, 0.0, 0.0]
        else:
            self.lb = list(lb)
            self.ub = list(ub)

    @classmethod
    def from_coords(cls, lb_x, lb_y, lb_z, ub_x, ub_y, ub_z):
        return cls(lb=[lb_x, lb_y, lb_z], ub=[ub_x, ub_y, ub_z])

    @classmethod
    def from_sphere(cls, center, radius):
        # [G] Sphere bounding box: min = center - radius, max = center + radius
        return cls(
            lb=[center[0] - radius, center[1] - radius, center[2] - radius],
            ub=[center[0] + radius, center[1] + radius, center[2] + radius]
        )

    @classmethod
    def from_triangle(cls, v1, v2, v3):
        # [G] Triangle bounding box: component-wise min/max across vertices
        x_vals = [v1[0], v2[0], v3[0]]
        y_vals = [v1[1], v2[1], v3[1]]
        z_vals = [v1[2], v2[2], v3[2]]
        return cls(
            lb=[min(x_vals), min(y_vals), min(z_vals)],
            ub=[max(x_vals), max(y_vals), max(z_vals)]
        )

    @classmethod
    def merge(cls, a, b):
        # Computes the bounding box enclosing both AABB 'a' and 'b' [S2, unofficial]
        lb = [
            min(a.lb[0], b.lb[0]),
            min(a.lb[1], b.lb[1]),
            min(a.lb[2], b.lb[2])
        ]
        ub = [
            max(a.ub[0], b.ub[0]),
            max(a.ub[1], b.ub[1]),
            max(a.ub[2], b.ub[2])
        ]
        return cls(lb=lb, ub=ub)
```

**Edge Cases and Pitfalls:**
*   **Degenerate Boxes:** If $min > max$ for any axis, the box is invalid. [G] Merging logic must handle empty or invalid boxes explicitly to prevent propagation of invalid bounds.
*   **Precision:** Floating-point comparisons for containment or intersection should account for epsilon errors if exact boundaries are critical. [G]
*   **Axis Alignment:** The representation assumes the box is axis-aligned. [G] If the box is rotated, this representation is invalid; an OBB (Oriented Bounding Box) representation is required instead.

## Operating characteristics
*   **Memory:** Fixed size of 6 floats (24 bytes on standard 32-bit float systems) [S1, S2, unofficial].
*   **Time Complexity:** Merging two AABBs is $O(1)$ [S1, unofficial].
*   **Strengths:** Trivial to merge, simple to implement, and directly compatible with slab-based ray-box intersection algorithms [S1, unofficial].
*   **Limitations:** Does not support rotation. [G] For rotated objects, the AABB must be recomputed or an OBB used.

## Background
The Min/Max representation is a standard data structure in computer graphics, particularly in ray tracing and spatial acceleration structures [S2, unofficial]. It is explicitly used in Peter Shirley's raytracing series [S1, unofficial]. It serves as the foundational primitive for the [Ray-box intersection](776-ray-box-intersection.md) method, where the box is treated as the intersection of three slabs [S1, Parent, unofficial].
