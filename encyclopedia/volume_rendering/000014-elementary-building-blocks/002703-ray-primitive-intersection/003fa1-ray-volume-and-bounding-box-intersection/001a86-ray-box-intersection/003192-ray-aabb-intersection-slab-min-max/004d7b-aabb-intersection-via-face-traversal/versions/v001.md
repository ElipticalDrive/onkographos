# AABB Intersection via Face Traversal

Also called: aabbIntersectBack, aabbIntersectFront

## Overview
A method to find the entry (front) and exit (back) points of a ray intersecting an Axis-Aligned Bounding Box (AABB) by explicitly testing the ray against each of the six faces of the AABB [S1, unofficial]. It is less efficient than the standard slab method (Ray-AABB Intersection (Slab/Min-Max)) because it decomposes each quad face into two triangles and performs ray-triangle intersection tests, but it is explicitly noted as a current limitation in implementations that require ray-to-axis-aligned rectangle intersection rather than full ray-AABB intersection [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, AABB defined by dimensions $XDIM, YDIM, ZDIM$ (or equivalently by its 8 vertices).
- Output: Boolean indicating intersection, and parameter $t$ (entry $t_{min}$ or exit $t_{max}$).

**Data structures:**
- `Face`: A struct containing 4 `glm::vec3` vertices (`v0`, `v1`, `v2`, `v3`) representing the four corners of a quad face [S1, unofficial].
- The AABB is constructed from 6 `Face` objects, derived from its 8 vertices [S1, unofficial].

**Ray-Triangle Intersection Helper:**
The method relies on `glm::intersectRayTriangle` to test ray intersection with triangles. Each quad face is split into two triangles: $(v_0, v_1, v_2)$ and $(v_2, v_1, v_3)$ [S1, unofficial]. Let $T_{intersect}(\mathbf{o}, \mathbf{d}, \mathbf{a}, \mathbf{b}, \mathbf{c})$ return the intersection parameter $t$ if the ray intersects the triangle defined by vertices $\mathbf{a}, \mathbf{b}, \mathbf{c}$, or $-\infty$ otherwise.

**Steps:**

1. **Construct Faces:** Generate the 6 `Face` objects from the AABB's 8 vertices.
2. **Front Intersection (Entry Point):**
   - Initialize $t_{min} = \infty$ and $hit = \text{false}$.
   - Iterate through all 6 faces.
   - For each face, test for ray-face intersection by calling the triangle intersection helper on both constituent triangles.
   - Let $t_m$ be the intersection parameter from the triangle test.
   - If an intersection exists ($t_m \ge 0$), update $t_{min} = \min(t_{min}, t_m)$ and set $hit = \text{true}$.
   - After iterating all faces, if $hit$ is true, set $t = t_{min}$ and return true. Otherwise, return false.
3. **Back Intersection (Exit Point):**
   - Initialize $t_{max} = -\infty$ and $hit = \text{false}$.
   - Iterate through all 6 faces.
   - For each face, test for ray-face intersection.
   - Let $t_m$ be the intersection parameter.
   - If an intersection exists ($t_m \ge 0$), update $t_{max} = \max(t_{max}, t_m)$ and set $hit = \text{true}$.
   - After iterating all faces, if $hit$ is true, set $t = t_{max}$ and return true. Otherwise, return false.

**Edge cases and pitfalls:**
- This method uses ray-triangle intersection for each face (split into two triangles per quad face) [S1, unofficial].
- It is less efficient than the standard slab method (Ray-AABB Intersection (Slab/Min-Max)) [S1, unofficial].
- It is explicitly noted as a current limitation: "currently doing ray to axis aligned rectangle rather than ray-AABB" [S1, unofficial]. This implies potential inaccuracies or inefficiencies if the triangle decomposition does not perfectly align with the axis-aligned nature of the box, or if the implementation is a temporary workaround.

## Operating characteristics
- **Time Complexity:** $O(1)$ constant time, but with a high constant factor due to 6 faces $\times$ 2 triangles = 12 ray-triangle intersection tests.
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Linear with the number of faces (fixed at 6 for AABB).
- **Strengths:** Explicit geometric decomposition; potentially easier to debug or extend for non-axis-aligned cases if modified.
- **Limitations:** Significantly slower than slab method due to repeated triangle intersection calculations; noted as a limitation/placeholder in source implementations [S1, unofficial].
- **When to use:** Only when slab method is unavailable or when debugging ray-face intersection logic.
- **When not to use:** In performance-critical volume rendering paths where slab method is available.

## Background
Originated in the context of a volume ray casting implementation (CSE-333-Computer-Graphics-2020/VolumeRayCasting) where the developers noted a limitation in their intersection routine [S1, unofficial]. The method was used as a temporary solution for ray-to-axis-aligned rectangle intersection before implementing proper voxel intersection or slab-based AABB intersection [S1, unofficial].
