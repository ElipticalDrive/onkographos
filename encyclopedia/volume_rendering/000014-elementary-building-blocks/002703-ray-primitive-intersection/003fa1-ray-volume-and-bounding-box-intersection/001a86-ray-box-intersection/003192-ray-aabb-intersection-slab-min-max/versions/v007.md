# Ray-AABB Intersection (Slab/Min-Max)

Also called: CUDA Octree Box Intersection, Min-Max Method, Slab Test, Slab method

## Overview
The Slab/Min-Max method determines if a ray intersects an Axis-Aligned Bounding Box (AABB) by computing the entry ($t_{near}$) and exit ($t_{far}$) distances along the ray parameter $t$. It solves the problem of efficiently culling rays that miss a volumetric primitive or determining the traversal interval for ray marching. It differs from its sibling [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary axis-aligned bounding boxes rather than just cubes, and from [Ray-OBB Intersection Test](6603-ray-obb-intersection-test.md) by exploiting axis alignment to avoid rotation matrices, making it significantly faster for axis-aligned primitives.

## How it works
**Inputs:**
*   Ray origin $\mathbf{o} = (o_x, o_y, o_z)$
*   Ray direction $\mathbf{d} = (d_x, d_y, d_z)$
*   AABB minimum corner $\mathbf{min} = (min_x, min_y, min_z)$
*   AABB maximum corner $\mathbf{max} = (max_x, max_y, max_z)$
*   Optional: Ray clipping range $[t_{clip\_min}, t_{clip\_max}]$

**Outputs:**
*   Intersection interval $[t_{near}, t_{far}]$
*   Boolean hit status

**Data Structures:**
The AABB is represented by two 3D vectors, $\mathbf{min}$ and $\mathbf{max}$, defining the extents along each axis. The ray is represented by origin and direction vectors.

**Steps:**

1.  **Compute Slab Intersections:** For each axis $i \in \{x, y, z\}$, calculate the intersection distances of the ray with the two planes defining the slab along that axis.
    $$ t_{i1} = \frac{min_i - o_i}{d_i} $$
    $$ t_{i2} = \frac{max_i - o_i}{d_i} $$
    [S1, S3, unofficial]

2.  **Sort Slab Intervals:** For each axis, ensure $t_{i1} \le t_{i2}$. If $d_i < 0$, swap $t_{i1}$ and $t_{i2}$. Alternatively, use min/max functions:
    $$ t_{i\_min} = \min(t_{i1}, t_{i2}) $$
    $$ t_{i\_max} = \max(t_{i1}, t_{i2}) $$
    [S3, unofficial]

3.  **Compute Global Entry and Exit:** The ray enters the box at the maximum of all local entry points and exits at the minimum of all local exit points.
    $$ t_{near} = \max(t_{x\_min}, t_{y\_min}, t_{z\_min}) $$
    $$ t_{far} = \min(t_{x\_max}, t_{y\_max}, t_{z\_max}) $$
    [S3, unofficial]

4.  **Check Intersection:** The ray intersects the AABB if $t_{near} \le t_{far}$.
    [S3, unofficial]

5.  **Clipping (Optional):** If the ray is clipped to a near/far plane, clamp $t_{near}$ and $t_{far}$ to $[t_{clip\_min}, t_{clip\_max}]$. If $t_{near} > t_{far}$ after clamping, there is no intersection.
    [S5, G, unofficial]

**Pseudocode:**

```python
def ray_aabb_intersect_slab(ray_origin, ray_direction, box_min, box_max):
    """
    Computes the intersection interval [t_near, t_far] of a ray with an AABB.
    
    Args:
        ray_origin: tuple/list of 3 floats (ox, oy, oz)
        ray_direction: tuple/list of 3 floats (dx, dy, dz)
        box_min: tuple/list of 3 floats (min_x, min_y, min_z)
        box_max: tuple/list of 3 floats (max_x, max_y, max_z)
        
    Returns:
        (t_near, t_far, hit): 
        t_near: float, entry distance
        t_far: float, exit distance
        hit: bool, True if intersection exists
    """
    # Step 1 & 2: Compute t_min and t_max for each axis
    # Handle division by zero by using inverse direction if needed, 
    # but standard slab method assumes non-zero direction or handles via min/max logic.
    # If d_i is 0, the ray is parallel to the slab planes. 
    # The formula (min - o) / d is undefined. 
    # Robust implementations check for zero direction or use inverse direction.
    # Here we assume general case; for robustness see [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md).
    
    inv_dir = [1.0 / d if d != 0.0 else float('inf') for d in ray_direction]
    
    t1 = [(box_min[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    t2 = [(box_max[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    
    # Step 2: Sort per axis
    t_min_axis = [min(t1[i], t2[i]) for i in range(3)]
    t_max_axis = [max(t1[i], t2[i]) for i in range(3)]
    
    # Step 3: Compute global t_near and t_far
    t_near = max(t_min_axis)
    t_far = min(t_max_axis)
    
    # Step 4: Check intersection
    hit = t_near <= t_far
    
    return t_near, t_far, hit
```

**Parameters:**
*   `voxelsize`: Used in some implementations to define AABB dimensions from voxel indices [S2, unofficial].
*   `n_max`: Maximum number of intersections to store per ray in batched contexts [S2, unofficial].
*   `miss_value`: Value assigned to $t_{min}/t_{max}$ when a ray misses an AABB, typically infinity or a value outside the valid range [S5, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Direction Component:** If $d_i = 0$, the ray is parallel to the slab planes. Division by zero occurs. The standard slab method requires handling this, often by checking if the origin is within the slab bounds $[min_i, max_i]$. If outside, there is no intersection. If inside, the intersection is determined by the other axes. Robust implementations use inverse directions and NaN handling [S2, S3297].
*   **Ray Origin Inside Box:** If the ray origin is inside the box, $t_{near}$ may be negative. This is valid for the interval but may need clamping to $t=0$ for rendering.
*   **NaN Propagation:** If not handled, division by zero or invalid operations can produce NaNs, which propagate through min/max operations and cause false negatives or positives. Branchless methods with NaN handling are recommended for GPU execution [S2, 3297, unofficial].

## Subtopics

### Ray-Bounding Box Intersection
This method computes the intersection interval $[t_{min}, t_{max}]$ of camera rays with a scene bounding box (AABB), clamps these intervals to near/far clipping planes, and generates a set of query points along each ray for volume rendering [S1, unofficial][S2, unofficial][S5, unofficial]. It solves the problem of determining valid spatial extents for ray marching and preparing structured sample coordinates (including ray IDs and step indices) for downstream neural radiance field evaluation [S1, unofficial]. It differs from its sibling [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary axis-aligned bounding boxes rather than just cubes, and from [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md) by explicitly handling the generation of sample points and metadata (ray/step IDs) rather than just returning boolean intersection results [S1, unofficial][S5, unofficial].

### [Ray-Cube Intersection](2466-ray-cube-intersection.md)
This method calculates the precise entry ($t_0$) and exit ($t_1$) intersection points of a ray with an axis-aligned cube defined by lower and upper bounds. It solves the problem of determining the exact boundary hit for ray-casting or ray-marching within voxel grids, providing the entry position and the exit face normal required for subsequent traversal or shading. Unlike [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md), which computes the interval $[t_{min}, t_{max}]$ for traversal logic, this method explicitly returns the 3D intersection coordinates and the specific face index exited, which is critical for hardware-accelerated voxel rendering where the first solid voxel must be identified.

### [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md)
This method computes the intersection of a ray with an Axis-Aligned Bounding Box (AABB) using a branchless algorithm that correctly handles IEEE 754 floating-point edge cases, specifically NaNs generated when a ray direction component is zero. It builds on [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md) by replacing conditional checks for zero direction with precomputed inverse directions and nested min/max operations that suppress NaN propagation. Unlike the standard branchless slab method, this variant guarantees robustness for degenerate cases where the ray origin lies exactly on a box boundary or the ray is parallel to an axis, preventing false positives caused by NaN propagation.

### [AABB Ray Intersection](11086-aabb-ray-intersection.md)
AABB Ray Intersection computes the intersection interval $[t_{min}, t_{max}]$ and hit status for a batch of rays against a batch of Axis-Aligned Bounding Boxes (AABBs). It solves the problem of efficiently determining which volumetric primitives (voxels, grids) a ray traverses in volume rendering pipelines. Unlike the scalar Slab/Min-Max method [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md), this method is optimized for GPU execution, utilizing parallelization over the product of rays and AABBs and handling batching constraints to prevent out-of-memory errors.

### [AABB Intersection via Face Traversal](13498-aabb-intersection-via-face-traversal.md)
A method to find the entry (front) and exit (back) points of a ray intersecting an Axis-Aligned Bounding Box (AABB) by explicitly testing the ray against each of the six faces of the AABB. It is less efficient than the standard slab method (Ray-AABB Intersection (Slab/Min-Max)) because it decomposes each quad face into two triangles and performs ray-triangle intersection tests, but it is explicitly noted as a current limitation in implementations that require ray-to-axis-aligned rectangle intersection rather than full ray-AABB intersection.

### Ray-Bounding Box Intersection
A bounding box is used to determine ray entry and exit from the volumetric dataset, accelerating calculation by skipping rays that miss the volume and enabling 'cutting' the volume to look inside [S4, unofficial]. When looking inside a hollow object (like the Stanford Bunny), the gradient at the start of the ray may be 0 if the ray starts 'inside the material' because gradient calculation uses data before the ray start [S4, unofficial].

### Ray-AABB Intersection and Grid Traversal Setup
Compute ray-AABB intersections for all grids to get entry ($t_{mins}$) and exit ($t_{maxs}$) distances, and a hit flag ($hits$) [S5, unofficial]. Clamp $t_{mins}$ and $t_{maxs}$ to the near and far planes [S5, unofficial]. Set $t_{mins}$ and $t_{maxs}$ to $miss\_value$ if there is no intersection ($hits$ is false) [S5, unofficial]. Sort the concatenated $t_{mins}$ and $t_{maxs}$ values for each ray to prepare for traversal [S5, unofficial]. The parameter $miss\_value$ is the value assigned to $t_{min}/t_{max}$ when a ray misses an AABB (typically infinity or a value outside the valid range) [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray-AABB pair. It involves a constant number of arithmetic operations (subtractions, divisions, min/max comparisons).
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** Extremely fast, making it suitable for real-time rendering and large-scale volume rendering where millions of rays are tested against many primitives.
*   **Strengths:** Simple implementation, no branching required in optimized versions, robust with proper NaN handling.
*   **Limitations:** Only works for axis-aligned boxes. For oriented boxes, OBB intersection is needed, which is more expensive. Degenerate cases (zero direction, origin on boundary) require careful handling to avoid NaNs or false results.
*   **When to use:** When intersecting rays with axis-aligned primitives (voxels, grid cells, scene bounding boxes).
*   **When not to use:** For oriented bounding boxes (use OBB intersection) or complex shapes (use triangle/quad intersection).

## Background
The slab method is a classic technique in ray tracing and volume rendering. It is widely used in voxel-based rendering, octree traversal, and bounding volume hierarchy (BVH) intersection tests. The method is described in various graphics programming resources and implementations, such as those found in [S1, unofficial] (SolidVoxelization), [S2, unofficial] (NSVF), [S3, unofficial] (UnityVolumeRendering), [S4, unofficial] (Volume Raycasting mit OpenCL), and [S5, unofficial] (taylor-nerf). The robustness of the method, particularly regarding NaN handling, has been refined in modern implementations like [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md).
