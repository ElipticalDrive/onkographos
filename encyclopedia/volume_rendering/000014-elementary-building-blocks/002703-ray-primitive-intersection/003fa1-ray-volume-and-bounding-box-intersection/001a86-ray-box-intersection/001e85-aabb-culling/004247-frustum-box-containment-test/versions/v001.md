# Frustum-Box Containment Test

Also called: Frustum vs AABB containment, Inigo Quilez's frustum culling approach

## Overview
Determines if an axis-aligned bounding box (AABB) is fully contained within a view frustum defined by a projection * view matrix, returning true if the box is potentially visible and false if it is completely outside [S1, unofficial]. It differs from [AABB Culling](1789-aabb-culling.md) by testing mutual containment (box inside frustum AND frustum inside box) rather than just box outside frustum, and from [Bounding Box Culling](1806-bounding-box-culling.md) by operating on explicit frustum planes rather than generic bounding volumes.

## How it works
**Inputs and Outputs:**
- Input: A 4x4 projection-view matrix $M$ (column-major), and an AABB defined by minimum corner $(x_l, y_l, z_l)$ and maximum corner $(x_h, y_h, z_h)$.
- Output: Boolean `true` if the box is not completely outside the frustum, `false` otherwise.

**Data Structures:**
- `Plane`: A 4-element vector $(n_x, n_y, n_z, d)$ representing the plane equation $n_x x + n_y y + n_z z + d = 0$. The normal $(n_x, n_y, n_z)$ is normalized.
- `Frustum`: Contains an array of 6 `Plane` objects and an array of 8 `vec4` points representing the frustum corners in world space.
- `Box`: A flat array of 6 floats `[x_l, y_l, z_l, x_h, y_h, z_h]`.

**Steps:**
1. **Extract Frustum Planes:** Compute the 6 planes from the matrix $M$. Let $R_i$ be the $i$-th column of $M$ (for $i=0,1,2,3$). The planes are:
   $$ P_{\pm x} = R_3 \pm R_0 $$
   $$ P_{\pm y} = R_3 \pm R_1 $$
   $$ P_{\pm z} = R_3 \pm R_2 $$
   Normalize each plane $P$ by computing $s = 1/\sqrt{n_x^2+n_y^2+n_z^2}$ and updating $P \leftarrow P \cdot s$ [S1, unofficial].

2. **Test Box Against Planes:** For each of the 6 planes, determine if all 8 corners of the box lie behind the plane. A corner $C_j$ is behind the plane if $P \cdot C_j < 0.0$. If the count of corners behind the plane is 8, the box is outside the frustum [S1, unofficial].

3. **Test Frustum Against Box:** Compute the 8 corners of the frustum in world space (using the inverse projection-view matrix). For each axis ($x, y, z$), check if all 8 frustum corners lie outside the box on the same side (i.e., all $> \text{box}_{\text{max}}$ or all $< \text{box}_{\text{min}}$). If so, the frustum is outside the box, implying no intersection [S1, unofficial].

4. **Result:** If neither condition triggers, return `true` [S1, unofficial].

**Pseudocode:**
```python
def frustum_box_containment(proj_view_matrix, box_min, box_max):
    # Step 1: Extract and normalize planes
    # M is 4x4 column-major: M[i][j] is row i, col j
    # Columns are R0, R1, R2, R3
    R0 = [proj_view_matrix[0][0], proj_view_matrix[1][0], proj_view_matrix[2][0], proj_view_matrix[3][0]]
    R1 = [proj_view_matrix[0][1], proj_view_matrix[1][1], proj_view_matrix[2][1], proj_view_matrix[3][1]]
    R2 = [proj_view_matrix[0][2], proj_view_matrix[1][2], proj_view_matrix[2][2], proj_view_matrix[3][2]]
    R3 = [proj_view_matrix[0][3], proj_view_matrix[1][3], proj_view_matrix[2][3], proj_view_matrix[3][3]]

    planes = []
    # P_plus_x = R3 + R0, P_minus_x = R3 - R0, etc.
    for i in range(3):
        Ri = [R0[i], R1[i], R2[i], R3[i]] # This is actually the i-th row if we access by index, but spec says columns.
        # Re-reading source: "rows[3] ± rows[i]". In column-major storage, row i is accessed as matrix[i][j].
        # Let's stick to the source formula: P = R3 ± Ri where Ri is the i-th column.
        # In a 4x4 array `M`, column i is [M[0][i], M[1][i], M[2][i], M[3][i]].
        pass 

    # Correct extraction based on source "rows[3] ± rows[i]"
    # If M is stored as 4 arrays of 4 floats (rows):
    rows = [
        [proj_view_matrix[0][0], proj_view_matrix[0][1], proj_view_matrix[0][2], proj_view_matrix[0][3]],
        [proj_view_matrix[1][0], proj_view_matrix[1][1], proj_view_matrix[1][2], proj_view_matrix[1][3]],
        [proj_view_matrix[2][0], proj_view_matrix[2][1], proj_view_matrix[2][2], proj_view_matrix[2][3]],
        [proj_view_matrix[3][0], proj_view_matrix[3][1], proj_view_matrix[3][2], proj_view_matrix[3][3]]
    ]
    
    frustum_planes = []
    for i in range(3):
        # P_plus = Row3 + Rowi, P_minus = Row3 - Rowi
        p_plus = [rows[3][j] + rows[i][j] for j in range(4)]
        p_minus = [rows[3][j] - rows[i][j] for j in range(4)]
        frustum_planes.append(p_plus)
        frustum_planes.append(p_minus)
        
    # Normalize planes
    normalized_planes = []
    for p in frustum_planes:
        nx, ny, nz, d = p
        len_sq = nx*nx + ny*ny + nz*nz
        if len_sq == 0:
            continue # Degenerate plane
        s = 1.0 / (len_sq ** 0.5)
        normalized_planes.append([nx*s, ny*s, nz*s, d*s])
        
    # Step 2: Test box against planes
    # Box corners
    corners = []
    for x in [box_min[0], box_max[0]]:
        for y in [box_min[1], box_max[1]]:
            for z in [box_min[2], box_max[2]]:
                corners.append([x, y, z, 1.0])
                
    for p in normalized_planes:
        out_count = 0
        for c in corners:
            # Dot product
            dot = p[0]*c[0] + p[1]*c[1] + p[2]*c[2] + p[3]*c[3]
            if dot < 0.0:
                out_count += 1
        if out_count == 8:
            return False
            
    # Step 3: Test frustum against box
    # Need frustum corners in world space. 
    # Source mentions "points (array of 8 vec4, frustum corners in world space after inverse projection)".
    # We assume a helper `get_frustum_corners` exists or is implemented via inverse matrix.
    # Since we cannot call external APIs, we note this as a required step [G].
    frustum_corners = get_frustum_corners(proj_view_matrix) # [G] Helper to invert matrix and project NDC corners
    
    for i in range(3):
        # Check if all frustum corners are > max on axis i
        all_max = all(frustum_corners[j][i] > box_max[i] for j in range(8))
        # Check if all frustum corners are < min on axis i
        all_min = all(frustum_corners[j][i] < box_min[i] for j in range(8))
        if all_max or all_min:
            return False
            
    return True

def get_frustum_corners(proj_view_matrix):
    # [G] Standard implementation: Invert proj_view, transform 8 NDC corners (-1,-1,-1) to (1,1,1)
    # This is a standard linear algebra operation not detailed in the specific source notes for the containment test itself,
    # but required for the "Frustum against Box" test mentioned in the source.
    inv_matrix = invert_matrix(proj_view_matrix)
    corners = []
    for x in [-1, 1]:
        for y in [-1, 1]:
            for z in [-1, 1]:
                # Homogeneous coordinate w=1 for point
                v = [x, y, z, 1.0]
                # Transform
                res = [
                    inv_matrix[0][0]*v[0] + inv_matrix[1][0]*v[1] + inv_matrix[2][0]*v[2] + inv_matrix[3][0]*v[3],
                    inv_matrix[0][1]*v[0] + inv_matrix[1][1]*v[1] + inv_matrix[2][1]*v[2] + inv_matrix[3][1]*v[3],
                    inv_matrix[0][2]*v[0] + inv_matrix[1][2]*v[1] + inv_matrix[2][2]*v[2] + inv_matrix[3][2]*v[3],
                    inv_matrix[0][3]*v[0] + inv_matrix[1][3]*v[1] + inv_matrix[2][3]*v[2] + inv_matrix[3][3]*v[3]
                ]
                # Perspective divide
                if res[3] != 0:
                    res[0] /= res[3]
                    res[1] /= res[3]
                    res[2] /= res[3]
                corners.append(res)
    return corners
```

**Parameters:**
- `box`: Array of 6 floats `[x_l, y_l, z_l, x_h, y_h, z_h]` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Dot products near zero may cause false negatives/positives due to floating-point error. A small epsilon tolerance is often used in practice, though the source specifies strict `< 0.0` [S1, unofficial].
- **Degenerate Input:** If the projection matrix results in a zero-length normal for a plane, normalization fails. The source implies handling via normalization step [S1, unofficial].
- **Boundary Conditions:** The test returns `true` if the box touches the frustum boundary (not strictly outside).

## Operating characteristics
- **Time Complexity:** Constant time $O(1)$, involving a fixed number of arithmetic operations (6 plane extractions, 6 plane tests with 8 corners each, 3 axis tests with 8 corners each).
- **Memory Complexity:** $O(1)$ auxiliary space for plane and corner calculations.
- **Strengths:** Robust for large bounding boxes where simple view frustum culling might fail due to the box spanning the camera or extending far into the distance.
- **Limitations:** Requires computing frustum corners in world space for the second part of the test, which involves matrix inversion.
- **When to use:** When culling volume rendering geometry that may be large or distant, ensuring no part of the box is missed by the view frustum.

## Background
The method is adapted from Inigo Quilez's article on correct frustum culling for large bounds [S1, unofficial]. It addresses the limitation of standard frustum culling which only checks if the box is outside the frustum, failing when the box is large enough to encompass the camera or extend beyond the frustum boundaries in complex ways.
