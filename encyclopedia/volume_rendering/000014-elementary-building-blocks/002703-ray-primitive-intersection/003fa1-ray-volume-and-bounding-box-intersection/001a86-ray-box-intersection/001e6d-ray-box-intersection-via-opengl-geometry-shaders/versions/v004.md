# Ray-Box Intersection via OpenGL Geometry Shaders

Also called: CubeIntersection, Front/Back Hit Textures

## Overview
This method computes the entry and exit points of rays intersecting a volume's axis-aligned bounding box (AABB) by rendering the box geometry to textures using OpenGL geometry shaders [S1, unofficial]. It solves the problem of providing fragment shaders with precise 3D volume texture coordinates for ray traversal without complex CPU-side intersection calculations [S2, unofficial]. It sets itself apart from sibling methods by using a two-pass rendering approach where the first pass stores exit coordinates in a separate Framebuffer Object (FBO), and the second pass retrieves them [S2, unofficial].

## How it works
**Inputs:**
- Camera projection and view matrices (combined into MVP).
- Bounding box geometry (cube vertices).
- Boolean flag `m_bFront` to select front (entry) or back (exit) face culling.

**Outputs:**
- `TEXTURE_FRONT_HIT`: 2D texture containing entry point coordinates.
- `TEXTURE_BACK_HIT`: 2D texture containing exit point coordinates.
- Both textures are `GL_RGBA16F` format, size `Width x Height`.

**Data Structures:**
- **Framebuffer Object (FBO):** Attached to color textures (`GL_RGBA16F`) and a depth renderbuffer (`GL_DEPTH_COMPONENT16`).
- **Hit Textures:** 2D textures of size `Width x Height`, internal format `GL_RGBA16F`, type `GL_FLOAT` [S1, unofficial].

**Steps:**
1. Create an FBO with a color attachment (either `TEXTURE_FRONT_HIT` or `TEXTURE_BACK_HIT`) of format `GL_RGBA16F` and a depth renderbuffer of format `GL_DEPTH_COMPONENT16` [S1, unofficial].
2. Clear the depth buffer and color buffer [S1, unofficial].
3. Enable `GL_CULL_FACE` and `GL_DEPTH_TEST` [S1, unofficial].
4. Set culling mode: if `m_bFront` is true, cull `GL_BACK` faces; otherwise, cull `GL_FRONT` faces [S1, unofficial].
5. Draw the cube geometry using the hit shader program, passing the MVP matrix as a uniform [S1, unofficial].
6. The geometry shader computes the intersection of the ray (defined by the camera projection) with the box faces and writes the hit position to the color attachment [S1, unofficial].

**Pitfalls:**
- The depth buffer is cleared along with the color buffer, but the depth test is enabled, requiring correct depth writing from the geometry shader [S1, unofficial].

**Pseudocode:**
```python
def render_ray_box_hit(mvp_matrix, m_b_front, width, height):
    # 1. Create FBO and textures
    fbo = create_fbo()
    color_texture = create_texture_2d(width, height, GL_RGBA16F)
    depth_buffer = create_renderbuffer(width, height, GL_DEPTH_COMPONENT16)
    
    attach_texture_to_fbo(fbo, color_texture, GL_COLOR_ATTACHMENT0)
    attach_renderbuffer_to_fbo(fbo, depth_buffer, GL_DEPTH_ATTACHMENT)
    
    # 2. Clear buffers
    gl_clear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)
    
    # 3. Set up state
    gl_enable(GL_CULL_FACE)
    gl_enable(GL_DEPTH_TEST)
    
    # 4. Set culling mode
    if m_b_front:
        gl_cull_face(GL_BACK)
    else:
        gl_cull_face(GL_FRONT)
        
    # 5. Draw cube
    use_shader_program(hit_shader_program)
    set_uniform(hit_shader_program, "mvp_matrix", mvp_matrix)
    draw_cube_geometry()
    
    # 6. Read back results (conceptual)
    # The hit positions are now stored in color_texture
    return color_texture
```
