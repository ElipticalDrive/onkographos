# Ray-Box Intersection via OpenGL Geometry Shaders

Also called: CubeIntersection, Front/Back Hit Textures

## Overview
This method computes the entry and exit points of rays intersecting a volume's bounding box by rendering the box geometry to textures using OpenGL geometry shaders [S1, unofficial]. It provides fragment shaders with precise start and end texture coordinates for volume traversal without complex CPU-side ray-box intersection calculations [S1, unofficial]. It sets itself apart from sibling methods by using a geometry shader rendering approach to compute these points, whereas alternatives like [Two-Pass Ray Entry/Exit Determination](2669-two-pass-ray-entry-exit-determination.md) use a different two-pass rendering strategy [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Camera projection matrix, model-view matrix, volume bounding box geometry (cube), and a boolean flag `m_bFront` to select front (entry) or back (exit) hit computation [S1, unofficial].
- **Outputs:** Two 2D textures (`TEXTURE_FRONT_HIT` and `TEXTURE_BACK_HIT`) storing the 3D world-space hit positions for each pixel [S1, unofficial].

**Data Structures:**
- **Hit Textures:** 2D textures of size `Width x Height`, format `GL_RGBA16F`, internal format `GL_RGBA16F`, type `GL_FLOAT` [S1, unofficial].
- **Framebuffer Object (FBO):** Contains a color attachment (the hit texture) and a depth renderbuffer of format `GL_DEPTH_COMPONENT16` [S1, unofficial].

**Steps:**
1. Create an FBO with a color attachment (`TEXTURE_FRONT_HIT` or `TEXTURE_BACK_HIT`) of format `GL_RGBA16F` and a depth renderbuffer of format `GL_DEPTH_COMPONENT16` [S1, unofficial].
2. Clear the color buffer and the depth buffer [S1, unofficial].
3. Enable `GL_CULL_FACE` and `GL_DEPTH_TEST` [S1, unofficial].
4. If `m_bFront` is true, cull `GL_BACK` faces; otherwise, cull `GL_FRONT` faces [S1, unofficial].
5. Set up the hit shader program. The geometry shader computes the ray-box intersection for the ray defined by the camera projection and outputs the hit position [S1, unofficial].
6. Draw the cube geometry using the hit shader program, passing the Model-View-Projection (MVP) matrix as a uniform [S1, unofficial].
7. The method requires two passes, one for front hits and one for back hits, toggling `m_bFront` and the target FBO/texture [S1, unofficial].

**Pseudocode:**
```python
def compute_ray_box_hits(mvp_matrix, cube_vertices, width, height):
    # Initialize rendering state
    enable(GL_CULL_FACE)
    enable(GL_DEPTH_TEST)
    
    # Create FBO and textures for front and back hits
    front_fbo = allocate_fbo()
    front_tex = allocate_texture(width, height, format=GL_RGBA16F, type=GL_FLOAT)
    front_fbo.color_attachment = front_tex
    front_fbo.depth_attachment = allocate_renderbuffer(width, height, format=GL_DEPTH_COMPONENT16)
    
    back_fbo = allocate_fbo()
    back_tex = allocate_texture(width, height, format=GL_RGBA16F, type=GL_FLOAT)
    back_fbo.color_attachment = back_tex
    back_fbo.depth_attachment = allocate_renderbuffer(width, height, format=GL_DEPTH_COMPONENT16)
    
    # Load and use shader program
    shader_prog = compile_shader_program(vertex_src, geometry_src, fragment_src)
    shader_prog.uniforms["mvp_matrix"] = mvp_matrix
    use_shader_program(shader_prog)
    
    # Pass 1: Front hits (entry)
    bind_framebuffer(GL_FRAMEBUFFER, front_fbo)
    clear_buffer(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)
    set_cull_mode(GL_BACK)
    draw_geometry(GL_TRIANGLES, cube_vertices)
    
    # Pass 2: Back hits (exit)
    bind_framebuffer(GL_FRAMEBUFFER, back_fbo)
    clear_buffer(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)
    set_cull_mode(GL_FRONT)
    draw_geometry(GL_TRIANGLES, cube_vertices)
    
    bind_framebuffer(GL_FRAMEBUFFER, 0)
    return front_tex, back_tex
```

**Geometry Shader Logic (Conceptual):**
The geometry shader computes the ray-box intersection for the ray defined by the camera projection and outputs the hit position [S1, unofficial]. The hit position is written to the output [S1, unofficial].

**Parameters:**
- `m_bFront`: Boolean flag determining whether to compute front (entry) or back (exit) hits [S1, unofficial].

**Edge Cases and Pitfalls:**
- The depth buffer is cleared along with the color buffer, but the depth test is enabled, requiring correct depth writing from the geometry shader [S1, unofficial].
- Precision issues may arise from using 16-bit floating point textures for storing hit positions [S1, unofficial].

## Subtopics

### [Two-Pass Ray Entry/Exit Determination](2669-two-pass-ray-entry-exit-determination.md)
This method determines the 3D volume texture coordinates for the entry and exit points of a ray passing through a volume's bounding box by rendering the box geometry to textures using OpenGL. It solves the problem of providing the fragment shader with the precise start and end texture coordinates required for volume traversal without complex CPU-side ray-box intersection calculations. It sets itself apart from sibling methods by using a two-pass rendering approach where the first pass stores exit coordinates in a separate Framebuffer Object (FBO), and the second pass retrieves them, whereas alternatives like [Ray-Box Intersection via OpenGL Geometry Shaders](ray-box-intersection-via-opengl-geometry-shaders.md) compute these points in a single pass using geometry shaders.

## Operating characteristics
- **Time Complexity:** O(N) where N is the number of pixels in the screen resolution, as each pixel requires a ray-box intersection computation in the geometry shader [G].
- **Memory Complexity:** O(W * H) for storing the hit textures, where W and H are the screen dimensions [G].
- **Measured Performance:** Not given in the sources [S1, unofficial].
- **Scaling:** Performance scales linearly with screen resolution [G].
- **Strengths:** Offloads ray-box intersection computation to the GPU, reducing CPU overhead. Simple to implement using standard OpenGL features [G].
- **Limitations:** Requires OpenGL geometry shaders, which may not be available on all hardware. Precision issues with 16-bit textures [S1, unofficial].
- **When to use:** When GPU-based ray-box intersection is desired and OpenGL geometry shaders are available [G].
- **When not to use:** When high precision is required (use 32-bit textures or CPU-side computation) or when geometry shaders are not supported [G].
