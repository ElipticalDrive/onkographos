# Ray-box intersection

Also called: AABB Ray Intersection, AABB Slab Method, Divide and Conquer Ray/Box Intersection, Ray-AABB Intersection, Slab Test, Ray/Box Intersection Test, Slab intersection, Slab intersection test, Slab-based Ray/Box Intersection, Smits' Ray-Box, Smits' method

## Overview

Ray-box intersection computes the parametric entry ($t_{near}$) and exit ($t_{far}$) distances of a ray intersecting an Axis-Aligned Bounding Box (AABB), returning the interval $[t_{near}, t_{far}]$ along the ray parameter $t$ [S2, S3, S14, S16, S21, S28, S44, S55, unofficial]. It solves the problem of determining the valid sampling range for volume rendering or the traversal bounds for acceleration structures, enabling early rejection of rays that miss the volume entirely [S1, S11, S23, S26, S38, unofficial]. Unlike [Ray-primitive intersection](769-ray-primitive-intersection.md) siblings that return boolean hits or complex normals, this method provides the precise scalar interval required for subsequent volume sampling or traversal [S6, S14, S21, S23, S28, S55, unofficial]. It differs from [Ray-OBB Intersection Test](6603-ray-obb-intersection-test.md) by assuming axis alignment, which allows the use of the efficient slab method without rotation matrices [S6603].

## How it works

**Inputs and Outputs**
*   **Input:** Ray origin $\mathbf{o} = (o_x, o_y, o_z)$, ray direction $\mathbf{d} = (d_x, d_y, d_z)$ (non-zero), and AABB bounds defined by minimum corner $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$ and maximum corner $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$ [S46, S48, unofficial][S50, S54].
*   **Output:** A boolean indicating intersection and the interval $[t_{near}, t_{far}]$ where $t_{near} = \max(t_{min,x}, t_{min,y}, t_{min,z})$ and $t_{far} = \min(t_{max,x}, t_{max,y}, t_{max,z})$ [S2, S3, S14, S28, S44, S55, unofficial]. If no intersection, returns $(\infty, -\infty)$ or a miss flag [S3, unofficial][S56].

**Data Structures**
The AABB is typically stored as two 3D vectors or six floats: `box_min` and `box_max` [S6, S14, S16, S23, S24, S28, S48, unofficial][S54]. Some implementations use an array of three pairs `x_minmax[2]`, `y_minmax[2]`, `z_minmax[2]` to facilitate component-wise operations [S52, unofficial].

**Steps**
1.  **Precompute Inverse Direction:** Calculate $\mathbf{inv\_d} = (1/d_x, 1/d_y, 1/d_z)$ to replace division with multiplication [S8, S12, S15, S29, S45, S48, unofficial][S50][S58, S62, unofficial]. Handle near-zero direction components to avoid division by zero. Common strategies include:
    *   Clamping: If $|d_i| < \epsilon$, set $inv\_d_i = \text{sign}(d_i) \cdot \epsilon^{-1}$ or a large constant like $10^{32}$ [S26, S37, S41, S43, S59, unofficial].
    *   Epsilon addition: Add $\epsilon$ to $d_i$ before inversion [S22, S36, S39, S61, unofficial].
    *   Explicit check: If $d_i = 0$, check if the ray origin lies within the box bounds for that axis; if not, return miss [S2, S3, S5, S6, S17, S51, unofficial].
2.  **Compute Slab Intersections:** For each axis $i \in \{x, y, z\}$, calculate the intersection parameters with the near and far planes of the slab:
    $$ t_{i1} = (b_{min,i} - o_i) \cdot inv\_d_i $$
    $$ t_{i2} = (b_{max,i} - o_i) \cdot inv\_d_i $$
    [S4, S12, S14, S19, S24, unofficial][S27][S28, S30, S35, S37, S41, S43, S49, S51, S59, S60, S62, unofficial].
3.  **Order Slab Intervals:** Ensure $t_{i1} \le t_{i2}$ for each axis. If $d_i < 0$, the ray enters at $b_{max,i}$ and exits at $b_{min,i}$, so swap $t_{i1}$ and $t_{i2}$ [S2, S4, S6, S10, S15, S19, S32, S46, unofficial][S56]. Alternatively, compute $t_{min,i} = \min(t_{i1}, t_{i2})$ and $t_{max,i} = \max(t_{i1}, t_{i2})$ [S7, S23, S24, S28, S39, S51, S55, unofficial].
4.  **Intersect Slabs:** Compute the global entry and exit distances:
    $$ t_{near} = \max(t_{min,x}, t_{min,y}, t_{min,z}) $$
    $$ t_{far} = \min(t_{max,x}, t_{max,y}, t_{max,z}) $$
    [S2, S7, S14, S23, S24, S28, S39, S44, unofficial][S54][S55, unofficial].
5.  **Check Intersection:** The ray intersects the box if $t_{near} \le t_{far}$ and $t_{far} \ge 0$ [S2, S23, S55, unofficial]. If $t_{near} < 0$, the ray origin is inside the box; $t_{near}$ is often clamped to 0 or a small epsilon to avoid self-intersection [S4, S26, S35, S44, unofficial].

**Pseudocode**
```python
def ray_box_intersection(ray_origin, ray_direction, box_min, box_max, epsilon=1e-8):
    """
    Computes the intersection interval [t_near, t_far] of a ray with an AABB.
    
    Args:
        ray_origin: tuple (ox, oy, oz)
        ray_direction: tuple (dx, dy, dz)
        box_min: tuple (xmin, ymin, zmin)
        box_max: tuple (xmax, ymax, zmax)
        epsilon: tolerance for near-zero direction components
        
    Returns:
        (bool, float, float): (hit, t_near, t_far)
    """
    # 1. Precompute inverse direction with robustness
    inv_dir = []
    for i in range(3):
        d = ray_direction[i]
        if abs(d) < epsilon:
            # Handle parallel ray: check if origin is within bounds
            if not (box_min[i] <= ray_origin[i] <= box_max[i]):
                return False, float('inf'), float('-inf')
            # Use a large value for inverse to effectively ignore this axis in min/max logic
            # or handle via explicit bounds check in step 4. 
            # Here we use a large constant to simulate 1/0 without division by zero,
            # but the sign matters for swapping. 
            # A robust approach is to set inv_dir to 0 and handle parallel case separately,
            # or use the explicit check above and return early if out of bounds.
            # For this implementation, we assume the explicit check above handles misses.
            # If we are here, the ray is inside the slab for this axis.
            inv_dir.append(0.0) 
        else:
            inv_dir.append(1.0 / d)

    # 2. Compute slab intersections
    # t_min_vals and t_max_vals will store the entry and exit t for each axis slab
    t_min_vals = []
    t_max_vals = []
    
    for i in range(3):
        # Calculate t values for min and max bounds
        t1 = (box_min[i] - ray_origin[i]) * inv_dir[i]
        t2 = (box_max[i] - ray_origin[i]) * inv_dir[i]
        
        # 3. Order slab intervals
        if t1 <= t2:
            t_min_vals.append(t1)
            t_max_vals.append(t2)
        else:
            t_min_vals.append(t2)
            t_max_vals.append(t1)

    # 4. Intersect slabs
    t_near = max(t_min_vals)
    t_far = min(t_max_vals)

    # 5. Check intersection
    # Intersection is valid if the intervals overlap and the exit is in the future
    if t_near <= t_far and t_far >= 0.0:
        # Clamp t_near to 0 if ray starts inside
        if t_near < 0.0:
            t_near = 0.0
        return True, t_near, t_far
    else:
        return False, float('inf'), float('-inf')
```

**Parameters**
*   `epsilon`: Floating-point tolerance for near-zero direction components. Typical value: $1.0 \times 10^{-6}$ or $1.0 \times 10^{-8}$ [S2, S6, S39, unofficial].
*   `t_near_clip`: Minimum t value to avoid self-intersection. Typical value: $10^{-4}$ [S26, unofficial].

**Edge Cases and Pitfalls**
*   **Parallel Rays:** If a ray direction component is zero, the ray is parallel to the slab planes. If the ray origin is outside the box bounds for that axis, there is no intersection [S2, S3, S5, S6, S17, S51, unofficial]. If inside, the slab imposes no constraint on $t$ [S51, unofficial].
*   **Ray Origin Inside Box:** If $t_{near} < 0$, the ray starts inside the box. The intersection interval should be adjusted to $[0, t_{far}]$ or $[\epsilon, t_{far}]$ to prevent self-intersection in subsequent sampling [S4, S26, S35, S44, unofficial].
*   **Precision:** Using precomputed inverse direction is faster but can introduce precision issues if not handled carefully with epsilon [S8, S15, S58, unofficial]. IEEE floating-point properties can be used to handle -0.0 direction components correctly [S56].

## Subtopics

### Annulus Box Bounds Conversion
Converts an inner bounding box to a list of bounds relative to an enclosing box, adding entries for sides where the inner box is strictly contained [S25, unofficial]. It is used to define clipping planes for ray-box intersection in specific traversal contexts. The data structure `ANNorthHalfSpace` stores the dimension index `cd`, cutting value `cv`, and sign `sd` (+1 or -1) [S25, unofficial].

### AABB Representation (Min/Max)
An AABB represented by storing the minimum and maximum coordinate values for each axis [S52, unofficial]. This representation is preferred over point-plus-dimensions because computing the bounding box enclosing two other boxes is trivial (component-wise min/max) [S52, unofficial].

## Operating characteristics

*   **Time Complexity:** $O(1)$ per ray-box test, involving a constant number of arithmetic operations (6 subtractions, 6 multiplications, 6 comparisons, 3 max/min operations) [S8, S49, S58, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space [S8, unofficial].
*   **Performance:** The slab method is highly efficient and branchless when implemented with SIMD instructions (e.g., SSE) [S49, S60, unofficial]. Precomputing the inverse direction replaces divisions with multiplications, offering a significant speedup [S8, S15, S58, unofficial]. Transformations to axis-normalized space can further reduce branch mispredictions and instruction fetches [S57, S58, unofficial].
*   **Strengths:** Simple, robust, and fast. Handles parallel rays and rays starting inside the box correctly [S2, S3, S5, S6, unofficial][S56].
*   **Limitations:** Assumes axis alignment. For oriented boxes, transformation to local space is required, increasing cost [S6603].
*   **When to use:** As the primary intersection test for volume bounding boxes, voxel grids, and acceleration structures (octrees, BVHs) in volume rendering and ray tracing [S1, S8, S10, S11, S19, S26, S38, S42, S44, unofficial].

## Background

The slab method for ray-AABB intersection is a fundamental technique in computer graphics, originating from the work of Kay and Kajiya (1986) and popularized by Williams et al. (2005) [S5, S10, unofficial][S47]. It is widely used in volume rendering for determining the entry and exit points of rays into the volume dataset, enabling efficient voxel traversal [S1, S3, S8, S11, S13, S21, S23, S28, S38, S44, unofficial]. The method is also a core component of ray tracing acceleration structures like BVHs and octrees [S10, S42, S44, unofficial].
