# Triangle-AABB Intersection (Separating Axis Theorem)

Also called: AABB-Triangle Overlap Test, Fast 3D Triangle-Box Overlap Testing, IntersectsTriangleAabb, SAT Triangle-AABB Intersection, TriBoxOverlap, Triangle-AABB Overlap Test, Triangle-AABB SAT, Triangle-Box Intersection Test

## Overview

This method determines whether a triangle overlaps an axis-aligned bounding box (AABB) by applying the Separating Axis Theorem (SAT) [S2, S3, S6, S7, unofficial][S9]. It tests 15 potential separating axes: the 3 face normals of the box, the 1 normal of the triangle, and the 9 cross products of the triangle's edges against the box's coordinate axes [S7, S8, unofficial][S9]. If the projections of the triangle and the AABB onto all 15 axes overlap, the shapes intersect; otherwise, a separating axis exists and they do not [S9]. It is primarily used for conservative surface voxelization, frustum culling, and spatial partitioning in rendering pipelines [S6, S8, unofficial][S10]. Unlike conservative voxelization methods that reduce the problem to plane overlap and 2D projection checks to save instructions [S1, unofficial][S10], this SAT approach is a general-purpose geometric primitive test that guarantees no false positives or raster gaps [S8, unofficial].

## How it works

**Inputs and Outputs:**
*   **Input:** Three triangle vertices $v_0, v_1, v_2$ (each a 3D vector), the AABB center $c$ (3D vector), and the AABB half-extents $e$ (3D vector, where $e_i$ is the distance from the center to the box face along axis $i$) [S2, S3, unofficial][S9].
*   **Output:** Boolean `true` if the triangle and AABB overlap, `false` otherwise [S4, S7, unofficial].

**Data Structures:**
*   `v0, v1, v2`: `float3` representing triangle vertices.
*   `boxcenter`: `float3` representing the AABB center.
*   `boxhalfsize`: `float3` representing the AABB half-extents $[e_x, e_y, e_z]$ [S2, unofficial].
*   `e0, e1, e2`: `float3` representing triangle edge vectors.
*   `normal`: `float3` representing the triangle plane normal.

**Algorithm Steps:**

1.  **Translate Triangle:** Translate the triangle vertices so the AABB center is at the origin [S2, S3, S7, S8, unofficial].
    $$v_i' = v_i - c \quad \text{for } i \in \{0, 1, 2\}$$
    Let the translated vertices be $v_0, v_1, v_2$ for the remainder of the algorithm [S2, S3, unofficial].

2.  **Compute Triangle Edges:** Calculate the three edge vectors of the triangle [S3, S7, S8, unofficial].
    $$e_0 = v_1 - v_0$$
    $$e_1 = v_2 - v_1$$
    $$e_2 = v_0 - v_2$$

3.  **Test 9 Cross-Product Axes:** For each edge $e_i$ ($i \in \{0, 1, 2\}$), test the 3 axes formed by the cross product of the edge with the coordinate axes $X(1,0,0)$, $Y(0,1,0)$, and $Z(0,0,1)$ [S7, S8, unofficial][S9].
    *   For each test axis $a$, compute the projection radius $r$ of the AABB centered at the origin:
        $$r = e_x |a_x| + e_y |a_y| + e_z |a_z|$$
    *   Project the triangle vertices onto $a$:
        $$p_j = v_j \cdot a \quad \text{for } j \in \{0, 1, 2\}$$
    *   Find the min and max of the triangle projection:
        $$min_P = \min(p_0, p_1, p_2)$$
        $$max_P = \max(p_0, p_1, p_2)$$
    *   Check for separation. If $min_P > r$ or $max_P < -r$, return `false` [S2, S7, unofficial][S9].

    *Optimization Note:* The specific cross products can be computed explicitly or via macros. For edge $e_0$, the axes are $(0, -e_{0z}, e_{0y})$, $(e_{0z}, 0, -e_{0x})$, and $(-e_{0y}, e_{0x}, 0)$ [S4, S8, unofficial]. The projection tests can be optimized by precomputing absolute edge components $fex = |e_{ix}|$, $fey = |e_{iy}|$, $fez = |e_{iz}|$ [S2, S7, unofficial].

4.  **Test 3 Box Face Normals (Coordinate Axes):** Test separation along the X, Y, and Z axes [S2, S3, S7, S8, unofficial].
    *   For each axis $q \in \{X, Y, Z\}$:
        *   Find the min and max of the triangle vertices projected onto $q$:
            $$min = \min(v_0[q], v_1[q], v_2[q])$$
            $$max = \max(v_0[q], v_1[q], v_2[q])$$
        *   The AABB radius along axis $q$ is $e_q$.
        *   If $min > e_q$ or $max < -e_q$, return `false` [S2, S3, S7, unofficial].

5.  **Test Triangle Plane Normal:** Test separation along the triangle's normal [S2, S3, S7, S8, unofficial].
    *   Compute the triangle normal:
        $$n = e_0 \times e_1$$
    *   Compute the plane offset $d$ relative to the translated vertex $v_0$:
        $$d = n \cdot v_0$$
    *   Compute the projection radius $r$ of the AABB along $n$:
        $$r = e_x |n_x| + e_y |n_y| + e_z |n_z|$$
    *   Check for separation. If $d > r$ or $d < -r$, return `false` [S2, S7, S8, unofficial].
    *   *Note:* Some implementations use a plane-box overlap function that checks if the box intersects the plane defined by $n \cdot x + d = 0$ [S3, S5, unofficial]. The condition $d > r$ or $d < -r$ is equivalent to checking if the entire box lies on one side of the plane [S8, unofficial].

6.  **Return Result:** If all 15 tests pass (no separating axis found), return `true` [S1, S7, unofficial].

**Pseudocode:**

```python
def triangle_aabb_overlap(v0, v1, v2, boxcenter, boxhalfsize):
    """
    Tests for intersection between an AABB and a triangle using SAT.
    
    Args:
        v0, v1, v2: float3, triangle vertices
        boxcenter: float3, center of the AABB
        boxhalfsize: float3, half-extents of the AABB [ex, ey, ez]
        
    Returns:
        bool: True if overlapping, False otherwise
    """
    # Step 1: Translate triangle vertices so box center is at origin
    v0 = v0 - boxcenter
    v1 = v1 - boxcenter
    v2 = v2 - boxcenter
    
    # Step 2: Compute triangle edges
    e0 = v1 - v0
    e1 = v2 - v1
    e2 = v0 - v2
    
    # Helper function to test a separating axis
    def test_axis(axis):
        # Project triangle vertices onto axis
        p0 = dot(v0, axis)
        p1 = dot(v1, axis)
        p2 = dot(v2, axis)
        
        # Find min and max projection of triangle
        min_p = min(p0, p1, p2)
        max_p = max(p0, p1, p2)
        
        # Compute radius of AABB projection onto axis
        # r = ex*|axis.x| + ey*|axis.y| + ez*|axis.z|
        r = (boxhalfsize.x * abs(axis.x) + 
             boxhalfsize.y * abs(axis.y) + 
             boxhalfsize.z * abs(axis.z))
        
        # Check for separation
        if min_p > r or max_p < -r:
            return False
        return True

    # Step 3: Test 9 cross-product axes (Edge x Coordinate Axis)
    # For each edge, test cross product with X, Y, Z axes
    
    # Edge e0
    fex = abs(e0.x)
    fey = abs(e0.y)
    fez = abs(e0.z)
    
    # Axis: (0, -e0.z, e0.y) -> Cross(e0, X)
    if not test_axis(float3(0, -e0.z, e0.y)):
        return False
    # Axis: (e0.z, 0, -e0.x) -> Cross(e0, Y)
    if not test_axis(float3(e0.z, 0, -e0.x)):
        return False
    # Axis: (-e0.y, e0.x, 0) -> Cross(e0, Z)
    if not test_axis(float3(-e0.y, e0.x, 0)):
        return False

    # Edge e1
    fex = abs(e1.x)
    fey = abs(e1.y)
    fez = abs(e1.z)
    
    # Axis: (0, -e1.z, e1.y) -> Cross(e1, X)
    if not test_axis(float3(0, -e1.z, e1.y)):
        return False
    # Axis: (e1.z, 0, -e1.x) -> Cross(e1, Y)
    if not test_axis(float3(e1.z, 0, -e1.x)):
        return False
    # Axis: (-e1.y, e1.x, 0) -> Cross(e1, Z)
    if not test_axis(float3(-e1.y, e1.x, 0)):
        return False

    # Edge e2
    fex = abs(e2.x)
    fey = abs(e2.y)
    fez = abs(e2.z)
    
    # Axis: (0, -e2.z, e2.y) -> Cross(e2, X)
    if not test_axis(float3(0, -e2.z, e2.y)):
        return False
    # Axis: (e2.z, 0, -e2.x) -> Cross(e2, Y)
    if not test_axis(float3(e2.z, 0, -e2.x)):
        return False
    # Axis: (-e2.y, e2.x, 0) -> Cross(e2, Z)
    if not test_axis(float3(-e2.y, e2.x, 0)):
        return False

    # Step 4: Test 3 Box Face Normals (Coordinate Axes X, Y, Z)
    # Test X-axis
    min_x = min(v0.x, v1.x, v2.x)
    max_x = max(v0.x, v1.x, v2.x)
    if min_x > boxhalfsize.x or max_x < -boxhalfsize.x:
        return False
        
    # Test Y-axis
    min_y = min(v0.y, v1.y, v2.y)
    max_y = max(v0.y, v1.y, v2.y)
    if min_y > boxhalfsize.y or max_y < -boxhalfsize.y:
        return False
        
    # Test Z-axis
    min_z = min(v0.z, v1.z, v2.z)
    max_z = max(v0.z, v1.z, v2.z)
    if min_z > boxhalfsize.z or max_z < -boxhalfsize.z:
        return False

    # Step 5: Test Triangle Plane Normal
    normal = cross(e0, e1)
    d = dot(normal, v0)
    
    # Radius of AABB projection onto normal
    r = (boxhalfsize.x * abs(normal.x) + 
         boxhalfsize.y * abs(normal.y) + 
         boxhalfsize.z * abs(normal.z))
         
    if d > r or d < -r:
        return False

    # Step 6: No separating axis found
    return True
```

**Parameters:**
*   `boxcenter`: Center of the AABB [S2, unofficial].
*   `boxhalfsize`: Half-extents of the AABB [S2, unofficial].
*   `triverts`: Array of three triangle vertices [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision issues can cause false negatives or positives, especially for grazing contacts. An epsilon may be added to separation checks in variants [S11, unofficial].
*   **Coplanar/Touching:** The plane-box overlap test should treat coplanar or touching boundaries as overlapping (using `>=` for max vertex check) to avoid gaps [S2, unofficial].
*   **Test Order:** The 9 cross-product tests are often executed first, followed by the 3 axis tests, then the plane test, as this order is optimized for performance in many implementations [S2, S7, unofficial].

## Subtopics

### [Triangle / Box Overlap Test (Conservative 26/6-separating)](3528-triangle-box-overlap-test-conservative-26-6-separating.md)
This method determines if a triangle overlaps an axis-aligned box (voxel) for conservative surface voxelization, ensuring that any voxel partially or merely touched by a triangle is marked as occupied. It differs from standard rasterization, which only sets voxels if the triangle overlaps the voxel center, by using linear edge functions evaluated at critical points to guarantee gap-free coverage. Unlike the Separating Axis Theorem (SAT) approach [2050-triangle-aabb-intersection-separating-axis-theorem.md], which projects onto 15 axes, this test reduces the problem to a plane overlap check and three 2D projection checks, requiring fewer instructions and registers on GPU hardware.

## Operating characteristics

*   **Time Complexity:** $O(1)$ time complexity with a fixed sequence of 13 separation tests (9 cross-product, 3 axis, 1 plane) [S2, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory, requiring only a few temporary vectors for edges, normals, and projections [S2, unofficial].
*   **Performance:** The test is highly optimized for GPU and CPU execution. The order of tests (cross-products first) is chosen to maximize early-out probability [S2, S7, unofficial].
*   **Strengths:** Exact geometric test with no false positives or raster gaps [S8, unofficial]. Efficient for conservative voxelization and culling [S6, unofficial][S10].
*   **Limitations:** More computationally expensive than simplified 2D projection methods [S10]. Requires careful handling of floating-point precision [S11, unofficial].
*   **When to Use:** When exact overlap detection is required, such as in conservative voxelization, frustum culling, or spatial partitioning [S6, S8, unofficial][S10].
*   **When Not to Use:** When performance is critical and approximate results are acceptable, or when using methods that reduce the problem to fewer axes [S1, unofficial][S10].

## Background

The Triangle-AABB Intersection test using the Separating Axis Theorem was introduced by Tomas Akenine-Möller, first released on 2001-03-05, with an optimized test ordering applied on 2001-06-18 [S2, S6, unofficial]. It acknowledges contributions from Pierre Terdiman and David Hunt [S6, unofficial]. The method is widely used in bounding volume intersection testing for ray tracing, collision detection, and spatial culling in graphics and physics engines [S2, unofficial].
