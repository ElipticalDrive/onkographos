# Watertight BVH Box Traversal Fix

Also called: BVH Box Traversal Precision Fix, Robust BVH Ray Traversal with ULP Expansion, Slab Test Zero-Inversion Fix, Treat BVH boxes as closed sets in ray traversal

## Overview
This method fixes a robustness bug in shared slab tests where a ray with a zero direction component lying exactly in the plane of a box face misses the box on one side [S1]. It treats BVH boxes as closed sets by expanding them during construction, ensuring grazing and axis-parallel rays correctly intersect triangles whose edges they touch [S1].

## How it works
**Inputs and Outputs:**
- **Input:** Scene geometry and existing BVH structure [S1].
- **Output:** A BVH with expanded bounding boxes [S1].

**Data Structures:**
- **BVH Node/Instance Box:** Axis-Aligned Bounding Box (AABB) defined by minimum $(x_{min}, y_{min}, z_{min})$ and maximum $(x_{max}, y_{max}, z_{max})$ coordinates [S1].
- **ULP Expansion:** The expansion is applied to each coordinate of the AABB [S1].

**Steps:**
1. During BVH construction (`SceneAccel.build`), iterate over every node and instance box [S1].
2. Expand each box outward by one unit in the last place (ULP) [S1].
3. Proceed with standard ray traversal using the expanded boxes [S1].

**Formula:**
The bug occurs when the slab test computes $(hi - o) * inv = 0 * inv = 0$, making the slab appear empty for $t > 0$ [S1]. The fix ensures the ray origin $o$ is strictly inside the expanded slab, so $(hi - o) * inv > 0$ for the relevant side [S1].

**Parameters:**
- **Expansion Amount:** One ULP (Unit in the Last Place) [S1].

**Edge Cases and Pitfalls:**
- **Zero Direction Components:** Rays with zero direction components lying exactly in the plane of a box face previously missed the box on one side [S1].
- **Grazing Rays:** Straight-down rays along the side of a cube missed the top face's edge that it passes through [S1].
- **Orthographic Camera Rays:** Rays landing exactly on a bound previously skipped triangles whose edges they touched [S1].
- **Precision:** The fix relies on floating-point precision; the ULP expansion must be calculated correctly for the specific coordinate values [S1].

**Pseudocode:**
```python
import math

def expand_box_by_ulp(box):
    """Expands an AABB by one ULP in all directions."""
    min_x, min_y, min_z, max_x, max_y, max_z = box
    # Expand minimums outward by one ULP
    new_min_x = min_x - math.ulp(min_x)
    new_min_y = min_y - math.ulp(min_y)
    new_min_z = min_z - math.ulp(min_z)
    # Expand maximums outward by one ULP
    new_max_x = max_x + math.ulp(max_x)
    new_max_y = max_y + math.ulp(max_y)
    new_max_z = max_z + math.ulp(max_z)
    return (new_min_x, new_min_y, new_min_z, new_max_x, new_max_y, new_max_z)

def build_scene_accel(scene):
    """Builds the scene acceleration structure with watertight BVH boxes."""
    bvh_nodes = []
    for node in scene.nodes:
        original_box = node.bounding_box
        expanded_box = expand_box_by_ulp(original_box)
        node.bounding_box = expanded_box
        bvh_nodes.append(node)
    return bvh_nodes
```

## Operating characteristics
- **Time Complexity:** Traversal cost is unchanged [S1].
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Tested on Arch Linux with an Intel i9-12900H CPU and NVIDIA RTX 4060 Laptop GPU [S1].
- **Scaling:** Not given in the sources.
- **Strengths:** Fixes robustness issues with grazing rays without altering golden images or reference outputs for other rays [S1].
- **Limitations:** Only affects renders for grazing rays on face planes; the rest of the test suite and golden images remain unchanged [S1].
- **When to use:** When watertight triangle intersection robustness for axis-parallel or grazing rays is required [S1].
- **When not:** When standard slab test behavior is sufficient and grazing ray precision is not a concern [S1].

## Background
Introduced in commit b43ebc2 of the Aether3D project to address a robustness bug in the shared slab test [S1]. It ensures watertight triangle tests correctly decide intersections for grazing rays that previously missed boxes due to precision errors [S1]. The fix is part of Stage 10 of Aether3D, which focuses on scene intelligence and spatial queries [S1].
