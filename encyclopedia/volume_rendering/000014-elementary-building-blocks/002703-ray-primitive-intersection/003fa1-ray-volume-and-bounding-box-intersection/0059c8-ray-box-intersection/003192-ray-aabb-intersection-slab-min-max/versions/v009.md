# Ray-AABB Intersection (Slab/Min-Max)

Also called: CUDA Octree Box Intersection, Min-Max Method, Slab Test, Slab method

## Overview
The Slab/Min-Max method determines the intersection interval $[t_{min}, t_{max}]$ of a ray with an Axis-Aligned Bounding Box (AABB) by computing the entry and exit distances along each axis independently [S1, S3, unofficial]. It solves the problem of efficiently culling rays that miss a volume or voxel grid, providing the traversal bounds required for subsequent ray marching or sampling [S1, S3, S5, unofficial]. It differs from [Ray-box intersection](8356-ray-box-intersection.md) by operating entirely within the fragment shader using explicit slab calculations, and from [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary rectangular bounding boxes rather than just cubes [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{o} = (o_x, o_y, o_z)$
- Ray direction $\mathbf{d} = (d_x, d_y, d_z)$
- AABB bounds: minimum corner $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$ and maximum corner $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$

**Outputs:**
- Intersection interval $[t_{near}, t_{far}]$
- Boolean hit status

**Data Structures:**
- Vectors are 3-component floats.
- The AABB is defined by two 3D points. No additional metadata is required for the basic test.

**Algorithm Steps:**

1.  **Compute Slab Intersections:**
    For each axis $i \in \{x, y, z\}$, calculate the intersection distances of the ray with the two planes defining the slab along that axis.
    $$ t_{1,i} = \frac{b_{min,i} - o_i}{d_i} $$
    $$ t_{2,i} = \frac{b_{max,i} - o_i}{d_i} $$
    [S1, S3, unofficial]

2.  **Sort Slab Intervals:**
    For each axis, ensure $t_{1,i} \le t_{2,i}$. If $d_i < 0$, the values are swapped.
    $$ t_{min,i} = \min(t_{1,i}, t_{2,i}) $$
    $$ t_{max,i} = \max(t_{1,i}, t_{2,i}) $$
    [S3, unofficial]

3.  **Compute Global Entry and Exit:**
    The ray enters the box at the maximum of all local entry points and exits at the minimum of all local exit points.
    $$ t_{near} = \max(t_{min,x}, t_{min,y}, t_{min,z}) $$
    $$ t_{far} = \min(t_{max,x}, t_{max,y}, t_{max,z}) $$
    [S3, unofficial]

4.  **Determine Hit Status:**
    The ray intersects the AABB if $t_{near} \le t_{far}$ and $t_{far} \ge 0$ (assuming the ray origin is outside or the valid range starts at 0). If $t_{near} > t_{far}$, the ray misses the box.
    [S1, S3, unofficial]

**Parameters:**
- `voxelsize`: The size of the voxels (AABBs) if the AABBs represent a uniform grid [S2, unofficial].
- `n_max`: The maximum number of intersections to store per ray, used in batched implementations [S2, unofficial].
- `miss_value`: A value assigned to $t_{min}/t_{max}$ when a ray misses an AABB, typically infinity or a value outside the valid range [S5, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Direction Component:** If $d_i = 0$, the division in step 1 results in infinity or NaN. If the ray origin is inside the slab ($b_{min,i} \le o_i \le b_{max,i}$), the intersection is valid for that axis. If outside, it misses. Standard implementations must handle this to avoid NaN propagation [S2, unofficial].
- **Ray Origin on Boundary:** If the ray origin lies exactly on a box boundary, precision issues may cause false positives or negatives depending on the comparison operators used ($<$ vs $\le$) [S2, unofficial].
- **NaN Handling:** In branchless implementations, NaNs generated by zero direction components must be suppressed using min/max operations to guarantee robustness [S2, unofficial].

**Pseudocode:**
```python
def ray_aabb_slab_intersect(ray_origin, ray_dir, box_min, box_max):
    """
    Computes the intersection interval [t_near, t_far] of a ray with an AABB.
    
    Args:
        ray_origin: tuple (ox, oy, oz)
        ray_dir: tuple (dx, dy, dz)
        box_min: tuple (xmin, ymin, zmin)
        box_max: tuple (xmax, ymax, zmax)
        
    Returns:
        (t_near, t_far, hit): t_near and t_far are floats, hit is a boolean.
    """
    ox, oy, oz = ray_origin
    dx, dy, dz = ray_dir
    xmin, ymin, zmin = box_min
    xmax, ymax, zmax = box_max

    # Step 1 & 2: Compute and sort slab intersections for each axis
    # Handle division by zero by using large numbers or checking direction
    # Standard slab method assumes non-zero direction or handles it via logic
    
    # X axis
    if dx == 0:
        if ox < xmin or ox > xmax:
            return (float('inf'), float('-inf'), False)
        t1_x = float('-inf')
        t2_x = float('inf')
    else:
        t1_x = (xmin - ox) / dx
        t2_x = (xmax - ox) / dx
        if t1_x > t2_x:
            t1_x, t2_x = t2_x, t1_x

    # Y axis
    if dy == 0:
        if oy < ymin or oy > ymax:
            return (float('inf'), float('-inf'), False)
        t1_y = float('-inf')
        t2_y = float('inf')
    else:
        t1_y = (ymin - oy) / dy
        t2_y = (ymax - oy) / dy
        if t1_y > t2_y:
            t1_y, t2_y = t2_y, t1_y

    # Z axis
    if dz == 0:
        if oz < zmin or oz > zmax:
            return (float('inf'), float('-inf'), False)
        t1_z = float('-inf')
        t2_z = float('inf')
    else:
        t1_z = (zmin - oz) / dz
        t2_z = (zmax - oz) / dz
        if t1_z > t2_z:
            t1_z, t2_z = t2_z, t1_z

    # Step 3: Compute global entry and exit
    t_near = max(t1_x, t1_y, t1_z)
    t_far = min(t2_x, t2_y, t2_z)

    # Step 4: Determine hit status
    # The ray hits if the entry is before the exit and the exit is behind or at the origin
    hit = (t_near <= t_far) and (t_far >= 0)
    
    # If the ray starts inside, t_near might be negative. 
    # For volume rendering, we often care about the positive interval.
    if t_near < 0:
        t_near = 0
        
    return (t_near, t_far, hit)
```

## Subtopics

### Ray-Bounding Box Intersection
This method computes the intersection interval $[t_{min}, t_{max}]$ of camera rays with a scene bounding box (AABB), clamps these intervals to near/far clipping planes, and generates a set of query points along each ray for volume rendering [S1, unofficial][S2, unofficial][S5, unofficial]. It solves the problem of determining valid spatial extents for ray marching and preparing structured sample coordinates (including ray IDs and step indices) for downstream neural radiance field evaluation [S1, unofficial]. It differs from its sibling [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary axis-aligned bounding boxes rather than just cubes, and from [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md) by explicitly handling the generation of sample points and metadata (ray/step IDs) rather than just returning boolean intersection results [S1, unofficial][S5, unofficial]. A pitfall when looking inside hollow objects (like the Stanford Bunny) is that the gradient at the start of the ray may be 0 if the ray starts 'inside the material' because gradient calculation uses data before the ray start [S4, unofficial].

### [Ray-Cube Intersection](2466-ray-cube-intersection.md)
This method calculates the precise entry ($t_0$) and exit ($t_1$) intersection points of a ray with an axis-aligned cube defined by lower and upper bounds. It solves the problem of determining the exact boundary hit for ray-casting or ray-marching within voxel grids, providing the entry position and the exit face normal required for subsequent traversal or shading. Unlike [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md), which computes the interval $[t_{min}, t_{max}]$ for traversal logic, this method explicitly returns the 3D intersection coordinates and the specific face index exited, which is critical for hardware-accelerated voxel rendering where the first solid voxel must be identified.

### [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md)
This method computes the intersection of a ray with an Axis-Aligned Bounding Box (AABB) using a branchless algorithm that correctly handles IEEE 754 floating-point edge cases, specifically NaNs generated when a ray direction component is zero. It builds on [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md) by replacing conditional checks for zero direction with precomputed inverse directions and nested min/max operations that suppress NaN propagation. Unlike the standard branchless slab method, this variant guarantees robustness for degenerate cases where the ray origin lies exactly on a box boundary or the ray is parallel to an axis, preventing false positives caused by NaN propagation.

### [Ray-OBB Intersection Test](6603-ray-obb-intersection-test.md)
The Ray-OBB Intersection Test determines if a ray intersects an Oriented Bounding Box (OBB) and computes the distance to the nearest intersection point. It extends the slab method by projecting the ray onto the OBB's local axes to compute intersection intervals (slabs) along each axis. Unlike [Ray-box intersection](776-ray-box-intersection.md) which assumes axis alignment, this method handles arbitrary orientations by testing intersection with pairs of parallel planes perpendicular to the OBB's local axes.

### [AABB Ray Intersection](11086-aabb-ray-intersection.md)
AABB Ray Intersection computes the intersection interval $[t_{min}, t_{max}]$ and hit status for a batch of rays against a batch of Axis-Aligned Bounding Boxes (AABBs). It solves the problem of efficiently determining which volumetric primitives (voxels, grids) a ray traverses in volume rendering pipelines. Unlike the scalar Slab/Min-Max method [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md), this method is optimized for GPU execution, utilizing parallelization over the product of rays and AABBs and handling batching constraints to prevent out-of-memory errors.

### [AABB Intersection via Face Traversal](13498-aabb-intersection-via-face-traversal.md)
AABB Intersection via Face Traversal is a method to determine the entry (front) and exit (back) points of a ray intersecting an Axis-Aligned Bounding Box (AABB) by explicitly testing the ray against each of the six faces of the box. Unlike the standard slab method which computes intersection intervals along axes, this approach decomposes the AABB into six planar faces and performs individual ray-face intersection tests. It is distinguished from its siblings by its explicit geometric decomposition into faces and triangles, making it conceptually simpler but computationally more expensive than the slab method.

### Ray-Bounding Box Intersection
A bounding box is used to determine ray entry and exit from the volumetric dataset, accelerating calculation by skipping rays that miss the volume and enabling 'cutting' the volume to look inside [S4, unofficial].

### Ray-AABB Intersection and Grid Traversal Setup
This variant computes ray-AABB intersections for all grids to get entry ($t_{mins}$) and exit ($t_{maxs}$) distances, and a hit flag ($hits$) [S5, unofficial]. It clamps $t_{mins}$ and $t_{maxs}$ to the near and far planes, sets them to a `miss_value` if there is no intersection, and sorts the concatenated values for each ray to prepare for traversal [S5, unofficial].

### Slab-based Bounding Volume
A bounding volume defined as the intersection of slabs, where slabs are formed by the intersection of two half-spaces extending in opposite directions [S6]. Utilizing slabs significantly speeds up the evaluation of the signed distance function by dividing the number of scalar products by two [S6].

## Operating characteristics
- **Time Complexity:** $O(1)$ per ray-box pair. The method involves a constant number of arithmetic operations (divisions, min/max comparisons).
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** The slab method is generally faster than face-traversal methods due to fewer comparisons and no branching in optimized implementations [S6]. It is highly parallelizable, making it suitable for GPU batched execution [S1, S3, S4, unofficial].
- **Strengths:** Simplicity, speed, and robustness when combined with NaN handling [S2, unofficial].
- **Limitations:** Does not provide the exit face normal or precise 3D intersection point without additional computation [S1, unofficial]. Degenerate cases (zero direction) require special handling [S2, unofficial].

## Background
The slab method is a fundamental technique in ray tracing and volume rendering for bounding volume intersection tests. It is widely used in voxel-based rendering pipelines to determine the traversal range of rays through a volume [S1, S3, S5, unofficial]. Variants of this method are used in CUDA octree implementations and neural radiance field sampling preparation [S1, unofficial][S2, unofficial][S5, unofficial].
