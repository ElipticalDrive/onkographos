# Ray-AABB Intersection (Slab/Min-Max)

Also called: CUDA Octree Box Intersection, Min-Max Method, Slab Test, Slab method

## Overview
The Slab/Min-Max method determines the intersection interval $[t_{min}, t_{max}]$ along a ray parameter $t$ where the ray enters and exits an Axis-Aligned Bounding Box (AABB) [S1, S3, unofficial]. It solves the problem of efficiently culling rays that miss a volume primitive or defining the valid traversal range for ray marching [S1, S3, unofficial]. It differs from [Ray-box intersection](8356-ray-box-intersection.md) by being the specific algorithmic implementation used to compute the entry and exit distances within the fragment shader, and from [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary box dimensions rather than just cubes [S2, unofficial][S5, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{o} = (o_x, o_y, o_z)$ [S1, S3, unofficial].
- Ray direction $\mathbf{d} = (d_x, d_y, d_z)$ [S1, S3, unofficial].
- AABB bounds: minimum corner $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$ and maximum corner $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$ [S1, S3, unofficial].

**Outputs:**
- Intersection interval $[t_{near}, t_{far}]$ [S3, unofficial].
- Boolean hit status (intersection exists) [S1, S3, unofficial].

**Data Structures:**
- The AABB is represented by two 3D vectors, $\mathbf{b}_{min}$ and $\mathbf{b}_{max}$ [S1, S3, unofficial].
- Intermediate values $t_{min}$ and $t_{max}$ are computed per axis [S1, S3, unofficial].

**Steps:**

1. **Compute Slab Intersections:**
   For each axis $i \in \{x, y, z\}$, calculate the intersection distances of the ray with the two planes defining the slab for that axis:
   $$
   t_{min,i} = \frac{b_{min,i} - o_i}{d_i}
   $$
   $$
   t_{max,i} = \frac{b_{max,i} - o_i}{d_i}
   $$
   [S1, S3, unofficial].

2. **Sort Axis Intervals:**
   For each axis, ensure $t_{min,i} \le t_{max,i}$. If $d_i < 0$, swap $t_{min,i}$ and $t_{max,i}$ [S3, unofficial].
   Let $t_{1,i} = \min(t_{min,i}, t_{max,i})$ and $t_{2,i} = \max(t_{min,i}, t_{max,i})$ [S3, unofficial].

3. **Compute Global Entry and Exit:**
   The ray enters the box at the maximum of the local entry points and exits at the minimum of the local exit points:
   $$
   t_{near} = \max(t_{1,x}, t_{1,y}, t_{1,z})
   $$
   $$
   t_{far} = \min(t_{2,x}, t_{2,y}, t_{2,z})
   $$
   [S3, unofficial].

4. **Determine Hit Status:**
   An intersection exists if $t_{near} \le t_{far}$ [S3, unofficial].
   Additionally, in volume rendering contexts, the interval is often clamped to the camera's near and far clipping planes $[t_{clip\_min}, t_{clip\_max}]$ [S5, unofficial].
   If the ray misses the box ($t_{near} > t_{far}$), the result is typically marked as invalid or assigned a `miss_value` (e.g., infinity) [S5, unofficial].

**Pseudocode:**

```python
def ray_aabb_slab_intersect(ray_o, ray_d, box_min, box_max):
    """
    Computes the intersection interval [t_near, t_far] of a ray with an AABB.
    
    Args:
        ray_o: tuple (ox, oy, oz), ray origin.
        ray_d: tuple (dx, dy, dz), ray direction.
        box_min: tuple (xmin, ymin, zmin), AABB minimum corner.
        box_max: tuple (xmax, ymax, zmax), AABB maximum corner.
        
    Returns:
        tuple (hit, t_near, t_far). hit is boolean.
    """
    # Step 1 & 2: Compute t_min and t_max for each axis and sort them
    # We compute t1 (entry) and t2 (exit) for each axis directly
    
    # Handle division by zero or negative direction by swapping logic implicitly
    # If d[i] is 0, the ray is parallel to the slab normals. 
    # The formula (box[i] - o[i]) / d[i] results in inf or nan.
    # Standard robust implementation checks bounds first or uses inverse direction.
    # Here we follow the direct formula from [S1, S3, unofficial].
    
    t1_x = (box_min[0] - ray_o[0]) / ray_d[0]
    t2_x = (box_max[0] - ray_o[0]) / ray_d[0]
    
    t1_y = (box_min[1] - ray_o[1]) / ray_d[1]
    t2_y = (box_max[1] - ray_o[1]) / ray_d[1]
    
    t1_z = (box_min[2] - ray_o[2]) / ray_d[2]
    t2_z = (box_max[2] - ray_o[2]) / ray_d[2]
    
    # Step 2: Ensure t1 <= t2 for each axis
    # If direction component is negative, t1 and t2 are swapped relative to min/max planes
    # min(t1, t2) gives the entry distance for that axis slab
    # max(t1, t2) gives the exit distance for that axis slab
    
    entry_x = min(t1_x, t2_x)
    exit_x = max(t1_x, t2_x)
    
    entry_y = min(t1_y, t2_y)
    exit_y = max(t1_y, t2_y)
    
    entry_z = min(t1_z, t2_z)
    exit_z = max(t1_z, t2_z)
    
    # Step 3: Compute global t_near and t_far
    t_near = max(entry_x, entry_y, entry_z)
    t_far = min(exit_x, exit_y, exit_z)
    
    # Step 4: Check intersection
    hit = t_near <= t_far
    
    return hit, t_near, t_far
```

**Parameters:**
- `voxelsize`: The size of the voxels (AABBs) if the box represents a voxel grid cell [S2, unofficial].
- `n_max`: The maximum number of intersections to store per ray, used in batched kernels [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Direction Component:** If $d_i = 0$, the division results in infinity or NaN. If the ray origin is outside the slab bounds for that axis, the ray misses. If inside, it intersects. The standard formula produces NaN/Inf which must be handled carefully to avoid false positives or crashes [S2, unofficial][S3, unofficial].
- **Ray Origin on Boundary:** If the ray origin lies exactly on a box boundary, $t=0$ is a valid intersection. Robust implementations must ensure this is not rejected due to precision errors [S2, unofficial].
- **NaN Propagation:** In branchless GPU implementations, NaNs generated by zero-direction divisions can propagate and corrupt results. Special handling (e.g., using `nan_to_num` or conditional logic) is required for robustness [S2, unofficial].

## Subtopics

### Ray-Bounding Box Intersection
This variant computes the intersection interval $[t_{min}, t_{max}]$ of camera rays with a scene bounding box (AABB), clamps these intervals to near/far clipping planes, and generates a set of query points along each ray for volume rendering [S1, unofficial][S2, unofficial][S5, unofficial]. It solves the problem of determining valid spatial extents for ray marching and preparing structured sample coordinates (including ray IDs and step indices) for downstream neural radiance field evaluation [S1, unofficial]. It differs from its sibling [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary axis-aligned bounding boxes rather than just cubes, and from [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md) by explicitly handling the generation of sample points and metadata (ray/step IDs) rather than just returning boolean intersection results [S1, unofficial][S5, unofficial].

### [Ray-Cube Intersection](2466-ray-cube-intersection.md)
This method calculates the precise entry ($t_0$) and exit ($t_1$) intersection points of a ray with an axis-aligned cube defined by lower and upper bounds. It solves the problem of determining the exact boundary hit for ray-casting or ray-marching within voxel grids, providing the entry position and the exit face normal required for subsequent traversal or shading. Unlike [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md), which computes the interval $[t_{min}, t_{max}]$ for traversal logic, this method explicitly returns the 3D intersection coordinates and the specific face index exited, which is critical for hardware-accelerated voxel rendering where the first solid voxel must be identified.

### [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md)
This method computes the intersection of a ray with an Axis-Aligned Bounding Box (AABB) using a branchless algorithm that correctly handles IEEE 754 floating-point edge cases, specifically NaNs generated when a ray direction component is zero. It builds on [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md) by replacing conditional checks for zero direction with precomputed inverse directions and nested min/max operations that suppress NaN propagation. Unlike the standard branchless slab method, this variant guarantees robustness for degenerate cases where the ray origin lies exactly on a box boundary or the ray is parallel to an axis, preventing false positives caused by NaN propagation.

### [Ray-OBB Intersection Test](6603-ray-obb-intersection-test.md)
The Ray-OBB Intersection Test determines if a ray intersects an Oriented Bounding Box (OBB) and computes the distance to the nearest intersection point. It extends the slab method by projecting the ray onto the OBB's local axes to compute intersection intervals (slabs) along each axis. Unlike [Ray-box intersection](776-ray-box-intersection.md) which assumes axis alignment, this method handles arbitrary orientations by testing intersection with pairs of parallel planes perpendicular to the OBB's local axes.

### [AABB Ray Intersection](11086-aabb-ray-intersection.md)
The AABB Ray Intersection method computes the entry ($t_{min}$) and exit ($t_{max}$) distances of a ray against an Axis-Aligned Bounding Box (AABB), returning a boolean hit status. It solves the fundamental problem of determining whether a ray intersects a volume primitive and, if so, the interval along the ray parameter $t$ where the intersection occurs. It is distinguished from its siblings by its reliance on the "slab" method (computing intersections with min/max planes per axis) and its common implementation as a batched kernel for GPU acceleration, whereas [Ray-Bounding Box Intersection and Sampling Preparation](2364-ray-bounding-box-intersection-and-sampling-preparation.md) focuses on sampling preparation and [Ray-Cube Intersection](2466-ray-cube-intersection.md) assumes unit cubes.

### [AABB Intersection via Face Traversal](13498-aabb-intersection-via-face-traversal.md)
AABB Intersection via Face Traversal is a method to determine the entry (front) and exit (back) points of a ray intersecting an Axis-Aligned Bounding Box (AABB) by explicitly testing the ray against each of the six faces of the box. Unlike the standard slab method which computes intersection intervals along axes, this approach decomposes the AABB into six planar faces and performs individual ray-face intersection tests. It is distinguished from its siblings by its explicit geometric decomposition into faces and triangles, making it conceptually simpler but computationally more expensive than the slab method.

### Ray-Bounding Box Intersection
A bounding box is used to determine ray entry and exit from the volumetric dataset, accelerating calculation by skipping rays that miss the volume and enabling 'cutting' the volume to look inside [S4, unofficial]. When looking inside a hollow object (like the Stanford Bunny), the gradient at the start of the ray may be 0 if the ray starts 'inside the material' because gradient calculation uses data before the ray start [S4, unofficial].

### Ray-AABB Intersection and Grid Traversal Setup
This variant computes ray-AABB intersections for all grids to get entry ($t_{mins}$) and exit ($t_{maxs}$) distances, and a hit flag ($hits$) [S5, unofficial]. It clamps $t_{mins}$ and $t_{maxs}$ to the near and far planes, and sets them to a `miss_value` if there is no intersection ($hits$ is false) [S5, unofficial]. It then sorts the concatenated $t_{mins}$ and $t_{maxs}$ values for each ray to prepare for traversal [S5, unofficial]. The parameter `miss_value` is the value assigned to $t_{min}/t_{max}$ when a ray misses an AABB, typically infinity or a value outside the valid range [S5, unofficial].

### Slab-based Bounding Volume
A bounding volume defined as the intersection of slabs, where slabs are formed by the intersection of two half-spaces extending in opposite directions [S6]. Utilizing slabs significantly speeds up the evaluation of the signed distance function $h_e$ by dividing the number of scalar products by two [S6].

## Operating characteristics
The Slab/Min-Max method has constant time complexity $O(1)$ per ray-box pair, involving a fixed number of subtractions, divisions, and comparisons [S1, S3, unofficial]. It is highly efficient for GPU acceleration, often implemented as a batched kernel for processing many rays simultaneously . The method is robust for axis-aligned boxes but requires transformation to local space for oriented boxes, increasing cost . It is the standard choice for ray-box intersection in volume rendering due to its simplicity and speed [S1, S3, unofficial].

## Background
The slab method is a fundamental technique in ray tracing and volume rendering, widely used for bounding volume hierarchy (BVH) traversal and voxel grid intersection [S1, S3, unofficial]. It is implemented in various open-source volume rendering projects such as SolidVoxelization [S1, unofficial], NSVF [S2, unofficial], and UnityVolumeRendering [S3, unofficial]. The method is also referenced in academic works on sphere carving and signed distance fields, where slab-based bounding volumes are used to accelerate rendering [S6].
