# Ray-AABB Intersection (Slab/Min-Max)

Also called: BuildChunkSegments, Min-Max Method, Multi-Chunk Ray-Box Intersection and Segment Building, Ray-Box Intersection for Volume Traversal, Slab Method, Slab Method for Ray-AABB Intersection, Slab Test, Slab/Min-Max

## Overview
The Slab/Min-Max method computes the intersection interval $[t_{min}, t_{max}]$ of a ray with an Axis-Aligned Bounding Box (AABB) by evaluating the ray against the box's six defining planes (slabs) [S3, S4, unofficial]. It solves the problem of efficiently culling rays that miss a volume primitive or defining the valid traversal range for ray marching [S1, S5, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{o} = (o_x, o_y, o_z)$ [S3, S4, unofficial].
- Ray direction $\mathbf{d} = (d_x, d_y, d_z)$ [S3, S4, unofficial].
- AABB defined by minimum corner $\mathbf{b}_{min} = (b_{min,x}, b_{min,y}, b_{min,z})$ and maximum corner $\mathbf{b}_{max} = (b_{max,x}, b_{max,y}, b_{max,z})$ [S3, S4, unofficial].

**Outputs:**
- Boolean hit status [S3, unofficial].
- Intersection interval $[t_{near}, t_{far}]$ [S4, unofficial].
- Intersection point $\mathbf{p} = \mathbf{o} + t_{near}\mathbf{d}$ [S3, unofficial].

**Data Structures:**
- Vectors are 3-component floating-point arrays.
- The AABB is stored as two 3D points representing the min and max corners [S3, S4, unofficial].

**Steps:**
1. **Compute Inverse Direction:** Calculate $\mathbf{d}_{inv} = 1.0 / \mathbf{d}$ [S3, unofficial][S10]. Handle zero direction components by checking against a tolerance $\epsilon$ and using a large constant or skipping the axis constraint [S1, S2, unofficial].
2. **Compute Slab Intersections:** For each axis $i \in \{x, y, z\}$, calculate the parameter $t$ where the ray intersects the min and max planes:
   $$
   t_{min,i} = (b_{min,i} - o_i) \cdot d_{inv,i}
   $$
   $$
   t_{max,i} = (b_{max,i} - o_i) \cdot d_{inv,i}
   $$
   [S3, S4, S8, S9, unofficial]
3. **Determine Local Interval:** For each axis, the ray is inside the slab between the smaller and larger of the two computed $t$ values:
   $$
   t_{1,i} = \min(t_{min,i}, t_{max,i})
   $$
   $$
   t_{2,i} = \max(t_{min,i}, t_{max,i})
   $$
   [S4, S8, S9, unofficial]
4. **Compute Global Interval:** The ray is inside the box only when it is inside all slabs simultaneously. The entry distance $t_{near}$ is the maximum of the local entry distances, and the exit distance $t_{far}$ is the minimum of the local exit distances:
   $$
   t_{near} = \max(t_{1,x}, t_{1,y}, t_{1,z})
   $$
   $$
   t_{far} = \min(t_{2,x}, t_{2,y}, t_{2,z})
   $$
   [S3, S4, S8, S9, unofficial][S10]
5. **Check Intersection:** An intersection exists if the interval is valid and in front of the ray origin:
   $$
   t_{near} \le t_{far} \quad \text{and} \quad t_{near} \ge 0
   $$
   [S3, S4, S8, unofficial]
6. **Calculate Intersection Point:** If an intersection exists, the entry point is:
   $$
   \mathbf{p} = \mathbf{o} + t_{near} \mathbf{d}
   $$
   [S3, S8, unofficial]

**Parameters:**
- `voxelsize`: The size of the voxels (AABBs) if the box is derived from a voxel grid [S7, unofficial].
- `epsilon`: Floating-point tolerance used for approximate equality checks and boundary margin validation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Direction Component:** If $d_i = 0$, division produces infinity or NaN. If the ray origin is outside the slab ($o_i < b_{min,i}$ or $o_i > b_{max,i}$), the ray misses. If the origin is inside, the ray is parallel to the slab and effectively ignores the constraint [S2, S6, unofficial].
- **NaN Propagation:** NaNs from zero-direction divisions can propagate through min/max operations, causing false negatives. Branchless variants use sign masks to select bounds and suppress NaN propagation [S2, unofficial][S10].
- **Grazing Rays:** Rays parallel to a face or lying exactly on a boundary may miss due to precision issues. Watertight fixes treat BVH boxes as closed sets to guarantee consistent intersection decisions for axis-parallel rays on face planes [S2, unofficial][S10].
- **Hollow Objects:** When ray marching inside hollow objects, the gradient at the start of the ray may be zero if the ray starts "inside the material" because gradient calculation uses data before the ray start [S11, unofficial].

**Pseudocode:**
```python
def ray_aabb_slab_intersection(ray_origin, ray_direction, box_min, box_max, epsilon=1e-10):
    """
    Computes the intersection of a ray with an AABB using the slab method.
    
    Args:
        ray_origin: tuple (ox, oy, oz)
        ray_direction: tuple (dx, dy, dz)
        box_min: tuple (bmin_x, bmin_y, bmin_z)
        box_max: tuple (bmax_x, bmax_y, bmax_z)
        epsilon: tolerance for zero direction check
        
    Returns:
        tuple (hit: bool, t_near: float, t_far: float, point: tuple or None)
    """
    ox, oy, oz = ray_origin
    dx, dy, dz = ray_direction
    bmin_x, bmin_y, bmin_z = box_min
    bmax_x, bmax_y, bmax_z = box_max

    # Handle zero direction components to avoid division by zero
    inv_dx = 1.0 / dx if abs(dx) > epsilon else float('inf')
    inv_dy = 1.0 / dy if abs(dy) > epsilon else float('inf')
    inv_dz = 1.0 / dz if abs(dz) > epsilon else float('inf')

    # Compute t values for min and max planes along each axis
    t_min_x = (bmin_x - ox) * inv_dx
    t_max_x = (bmax_x - ox) * inv_dx
    t_min_y = (bmin_y - oy) * inv_dy
    t_max_y = (bmax_y - oy) * inv_dy
    t_min_z = (bmin_z - oz) * inv_dz
    t_max_z = (bmax_z - oz) * inv_dz

    # Determine local min and max intervals for each axis
    t1_x = min(t_min_x, t_max_x)
    t2_x = max(t_min_x, t_max_x)
    t1_y = min(t_min_y, t_max_y)
    t2_y = max(t_min_y, t_max_y)
    t1_z = min(t_min_z, t_max_z)
    t2_z = max(t_min_z, t_max_z)

    # Compute global near and far intersection distances
    t_near = max(t1_x, t1_y, t1_z)
    t_far = min(t2_x, t2_y, t2_z)

    # Check for valid intersection
    if t_near <= t_far and t_near >= 0:
        hit = True
        px = ox + t_near * dx
        py = oy + t_near * dy
        pz = oz + t_near * dz
        point = (px, py, pz)
    else:
        hit = False
        t_near = float('inf')
        t_far = float('-inf')
        point = None

    return hit, t_near, t_far, point
```

## Subtopics

### [Ray-Bounding Box Intersection and Sampling Preparation](2364-ray-bounding-box-intersection-and-sampling-preparation.md)
This method computes the intersection interval $[t_{min}, t_{max}]$ of camera rays with a scene bounding box (AABB), clamps these intervals to near/far clipping planes, and generates a set of query points along each ray for volume rendering. It solves the problem of determining valid spatial extents for ray marching and preparing structured sample coordinates (including ray IDs and step indices) for downstream neural radiance field evaluation. It differs from its sibling [Ray-Cube Intersection](2466-ray-cube-intersection.md) by supporting arbitrary axis-aligned bounding boxes rather than just cubes, and from [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md) by explicitly handling the generation of sample points and metadata (ray/step IDs) rather than just returning boolean intersection results.

### [Branchless Ray/AABB Intersection with NaN Handling](3297-branchless-ray-aabb-intersection-with-nan-handling.md)
This method computes the intersection of a ray with an Axis-Aligned Bounding Box (AABB) using a branchless algorithm that correctly handles IEEE 754 floating-point edge cases, specifically NaNs generated when a ray direction component is zero. It builds on [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md) by replacing conditional checks for zero direction with precomputed inverse directions and nested min/max operations that suppress NaN propagation. Unlike the standard branchless slab method, this variant guarantees robustness for degenerate cases where the ray origin lies exactly on a box boundary or the ray is parallel to an axis, preventing false positives caused by NaN propagation.

### [Ray-OBB Intersection Test](6603-ray-obb-intersection-test.md)
The Ray-OBB Intersection Test determines if a ray intersects an Oriented Bounding Box (OBB) and computes the distance to the nearest intersection point. It extends the slab method by projecting the ray onto the OBB's local axes to compute intersection intervals (slabs) along each axis. Unlike [Ray-box intersection](776-ray-box-intersection.md) which assumes axis alignment, this method handles arbitrary orientations by testing intersection with pairs of parallel planes perpendicular to the OBB's local axes.

### [AABB Intersection via Face Traversal](13498-aabb-intersection-via-face-traversal.md)
AABB Intersection via Face Traversal is a method to determine the entry (front) and exit (back) points of a ray intersecting an Axis-Aligned Bounding Box (AABB) by explicitly testing the ray against each of the six faces of the box. Unlike the standard slab method which computes intersection intervals along axes, this approach decomposes the AABB into six planar faces and performs individual ray-face intersection tests. It is distinguished from its siblings by its explicit geometric decomposition into faces and triangles, making it computationally more expensive than the slab method.

### [Segment-Box Collision Detection with Radius](17033-segment-box-collision-detection-with-radius.md)
Determines if a line segment defined by endpoints $a$ and $b$ intersects an axis-aligned box defined by lower corner $lo$ and upper corner $hi$, considering a spherical radius $r$ around the segment [G]. It sets itself apart from standard ray-box intersection by treating the segment as a capsule (cylinder with hemispherical caps) rather than an infinitely thin line, allowing for collision detection with thickness [G].

### [Watertight BVH Box Traversal Fix](17518-watertight-bvh-box-traversal-fix.md)
This method fixes a robustness bug in shared slab tests where a ray with a zero direction component lying exactly in the plane of a box face misses the box on one side. It ensures that grazing rays, such as orthographic camera rays landing exactly on a bound, correctly intersect triangles whose edges they touch, by treating BVH boxes as closed sets. Unlike standard slab tests which may compute an empty slab for $t > 0$ due to zero-inversion artifacts, this fix guarantees consistent intersection decisions for axis-parallel rays on face planes.

### [Slab-based AABB Intersection](19515-slab-based-aabb-intersection.md)
This family implements the standard algorithm for determining the intersection interval $[t_{min}, t_{max}]$ between a ray and an Axis-Aligned Bounding Box (AABB) by computing intersections with the box's six defining planes (slabs). It solves the fundamental problem of efficiently culling rays that miss a volume primitive or determining the precise entry and exit distances for ray marching. It is distinguished from [Ray-Cube Intersection](2466-ray-cube-intersection.md) by returning scalar $t$-intervals rather than 3D coordinates and face indices, and from [AABB Intersection via Face Traversal](13498-aabb-intersection-via-face-traversal.md) by computing the full interval upfront rather than stepping through voxels.

### Ray-Bounding Box Intersection
A bounding box is used to determine ray entry and exit from the volumetric dataset, accelerating calculation by skipping rays that miss the volume and enabling 'cutting' the volume to look inside [S11, unofficial]. When looking inside a hollow object (like the Stanford Bunny), the gradient at the start of the ray may be 0 if the ray starts 'inside the material' because gradient calculation uses data before the ray start [S11, unofficial].

### Slab-based Bounding Volume
A bounding volume defined as the intersection of slabs, where slabs are formed by the intersection of two half-spaces extending in opposite directions [S12]. Utilizing slabs significantly speeds up the evaluation of the signed distance function $h_e$ by dividing the number of scalar products by two [S12].
