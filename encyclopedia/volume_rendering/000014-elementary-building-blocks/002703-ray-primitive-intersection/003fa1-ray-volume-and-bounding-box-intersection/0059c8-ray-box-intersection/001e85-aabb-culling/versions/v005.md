# AABB Culling

Also called: 8-point frustum test, Box culling

## Overview
AABB Culling determines if a box defined by 8 vertices is completely outside a viewing box along any axis, returning false if culled and true otherwise [S1, unofficial]. It serves as a view-dependent pre-processing step to filter out primitives that do not intersect the camera viewport [S1, unofficial]. Unlike [Ray-box intersection](776-ray-box-intersection.md), which computes precise entry and exit distances for intersection testing, this method performs a binary containment check to reject objects early [S1, unofficial].

## How it works
**Inputs:**
- `points`: An array of 8 vectors `[x, y, z]` representing the vertices of the object box [S1, unofficial].
- `box`: A viewing box defined by 6 scalar values `[box[0], box[1], box[2], box[3], box[4], box[5]]` [S1, unofficial]. The indices correspond to minimum/maximum bounds along the X, Y, and Z axes respectively [G].

**Outputs:**
- `bool`: True if the box is potentially visible (not completely outside), False if culled [S1, unofficial].

**Data Structures:**
- `points`: List of 8 coordinate tuples. The specific vertex ordering is not defined in the sources [S1, unofficial].
- `box`: List of 6 floats `[min_x, min_y, min_z, max_x, max_y, max_z]`.

**Steps:**
1. Initialize a counter `out = 0` [S1, unofficial].
2. Loop `i` from 0 to 7:
   - If `points[i][0] > box[3]`, increment `out` [S1, unofficial].
   - If `out == 8`, return `false` [S1, unofficial].
3. Repeat the check for the remaining half-spaces specified in the source: `x < box[0]`, `y > box[4]`, `y < box[1]`, `z > box[5]`, and `z < box[2]` [S1, unofficial]. For each half-space, reset `out` to 0 before iterating through the 8 points, increment `out` when a point satisfies the condition, and return `false` immediately if `out` reaches 8 [S1, unofficial].
4. Return `true` [S1, unofficial].

**Pseudocode:**
```python
def aabb_culling(points, box):
    # points: list of 8 tuples (x, y, z)
    # box: list of 6 floats [min_x, min_y, min_z, max_x, max_y, max_z]
    
    # Check Max X (box[3])
    out = 0
    for i in range(8):
        if points[i][0] > box[3]:
            out += 1
            if out == 8:
                return False
                
    # Check Min X (box[0])
    out = 0
    for i in range(8):
        if points[i][0] < box[0]:
            out += 1
            if out == 8:
                return False
                
    # Check Max Y (box[4])
    out = 0
    for i in range(8):
        if points[i][1] > box[4]:
            out += 1
            if out == 8:
                return False
                
    # Check Min Y (box[1])
    out = 0
    for i in range(8):
        if points[i][1] < box[1]:
            out += 1
            if out == 8:
                return False
                
    # Check Max Z (box[5])
    out = 0
    for i in range(8):
        if points[i][2] > box[5]:
            out += 1
            if out == 8:
                return False
                
    # Check Min Z (box[2])
    out = 0
    for i in range(8):
        if points[i][2] < box[2]:
            out += 1
            if out == 8:
                return False
                
    return True
```

**Parameters:**
- `points`: Array of 8 vectors `[x, y, z]` representing the vertices of the object box [S1, unofficial].
- `box`: Viewing box boundaries `[min_x, min_y, min_z, max_x, max_y, max_z]` [S1, unofficial].

**Edge Cases and Pitfalls:**
- The source does not specify the vertex ordering of the 8 points [S1, unofficial].
- The source does not specify if the box boundaries are inclusive or exclusive [S1, unofficial].
- Floating-point precision issues may arise if points lie exactly on the viewing box boundaries due to strict inequality comparisons [G].

## Subtopics

### [Bounding Box Culling](1806-bounding-box-culling.md)
Bounding Box Culling is a view-dependent pre-processing step that filters out 3D Gaussians whose projected 2D footprint does not intersect the camera viewport. It differs from general [AABB Culling](1789-aabb-culling.md) by operating on the projected 2D ellipse of a Gaussian rather than a static 3D axis-aligned box, thereby enabling early rejection of primitives that are off-screen in screen space. Choose it when rendering 3D Gaussians and screen-space visibility is the primary bottleneck. See [Bounding Box Culling](1806-bounding-box-culling.md).

### [Frustum-Box Containment Test](10711-frustum-box-containment-test.md)
The Frustum-Box Containment Test determines if an axis-aligned bounding box (AABB) is fully contained within a view frustum defined by a projection * view matrix, returning true if the box is potentially visible and false if it is completely outside. It differs from [AABB Culling](1789-aabb-culling.md) by testing mutual containment (box inside frustum AND frustum inside box) rather than just box outside frustum, and from [Bounding Box Culling](1806-bounding-box-culling.md) by operating on explicit frustum planes rather than generic bounding volumes. Choose it when precise frustum culling against explicit planes is required. See [Frustum-Box Containment Test](10711-frustum-box-containment-test.md).

### Subspace Culling for Ray-Box Intersection
Subspace Culling for Ray-Box Intersection is a culling approach to reduce false-positive hits in ray-box intersection tests by embedding a binary voxel data structure into the volume, allowing cheap ray-voxel intersection via bitwise AND operations [S2, unofficial]. Unlike oriented bounding boxes which reduce false positives but are computationally expensive, this method uses cheap bitwise operations on voxel data [S2, unofficial]. Axis-aligned bounding boxes (AABBs) produce extra empty space, leading to false-positive hits for thin and diagonal primitives, which this method aims to reduce [S2, unofficial]. Choose it when false positives from AABBs are a performance bottleneck in BVH traversal [S2, unofficial].
