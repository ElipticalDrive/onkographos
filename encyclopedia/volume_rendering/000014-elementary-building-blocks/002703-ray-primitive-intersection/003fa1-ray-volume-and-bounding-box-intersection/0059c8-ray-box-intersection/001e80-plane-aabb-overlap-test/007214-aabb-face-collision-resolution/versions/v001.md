# AABB Face Collision Resolution

Also called: Collision Resolution, ResolveCollisionAABB

## Overview
AABB Face Collision Resolution resolves axis-aligned bounding box (AABB) collisions against a planar face by testing the box's desired velocity against the face plane and zeroing out velocity components that would cause penetration [S1, unofficial]. It serves as the final step in a ray-primitive intersection pipeline, converting geometric overlap into a physically valid velocity vector [S1, unofficial]. Unlike [Plane-AABB Overlap Test](1783-plane-aabb-overlap-test.md), which only determines if an overlap exists, this method actively modifies the motion vector to prevent interpenetration [S1, unofficial].

## How it works
**Inputs:**
- `box`: An AABB defined by its minimum and maximum bounds (or vertices).
- `desiredVelocity`: The intended velocity vector $\vec{v}$ for the box.
- `face`: A planar face defined by a normal vector $\vec{n}$ and a distance $d$ from the origin, or equivalently by vertices defining the plane.

**Outputs:**
- `resolvedVelocity`: The adjusted velocity vector $\vec{v}'$ such that the box does not penetrate the face during the time step.

**Data Structures:**
- **Ray**: Defined by an origin point $P$ and a direction vector $\vec{d}$ (normalized or unnormalized, consistent with `desiredVelocity`).
- **Intersection Point**: A 3D coordinate $I$ where the ray intersects the plane.
- **Velocity Planes**: Implicit planes derived from the box's faces, used to determine orientation relative to the collision face.

**Steps:**
1. **Pre-check**: Calculate the dot product between the face normal $\vec{n}$ and the desired velocity $\vec{v}$:
   $$ \text{dot} = \vec{n} \cdot \vec{v} $$
   If $\text{dot} < 0$, the object is moving away from the front side of the face (or the face normal points in the opposite direction of motion). In this case, skip collision resolution and return `desiredVelocity` [S1, unofficial].

2. **Ray Generation**: Define five ray origins on the bounding box:
   - Four corners of the box ($P_1, P_2, P_3, P_4$).
   - One center point on the front face of the box ($P_5$) [S1, unofficial].
   Create rays from each origin along the `desiredVelocity` direction.

3. **Intersection Testing**: For each ray, compute the intersection with the face plane.
   - The intersection point $I$ must lie on the line segment between the ray origin $P$ and $P + \vec{v}$. Verify this using a point-on-segment check [S1, unofficial].
   - If an intersection exists and lies on both the ray segment and the face segment, proceed to normal checking [S1, unofficial].

4. **Velocity Resolution**:
   - Initialize `result` = `desiredVelocity` [S1, unofficial].
   - Check the face normal components:
     - If $\vec{n}_y \neq 0$, set `result.y` = 0 and break the loop [S1, unofficial].
     - If $\vec{n}_z \neq 0$, set `result.z` = 0 [S1, unofficial].
   - Special handling for Y-component: If no intersections exist or specific conditions are met, `result.y` may be set to the difference between the first intersection point's Y and the box's minimum Y, or 0 if no intersections exist [S1, unofficial].

5. **Return**: Return `result` [S1, unofficial].

**Pseudocode:**
```python
def resolve_aabb_face_collision(box, desired_velocity, face_normal, face_distance):
    """
    Resolves AABB collision against a plane.
    
    Args:
        box: AABB with min and max bounds.
        desired_velocity: Vector3 (vx, vy, vz).
        face_normal: Vector3 (nx, ny, nz).
        face_distance: float (d in plane equation nx*x + ny*y + nz*z = d).
        
    Returns:
        Vector3: Resolved velocity.
    """
    # Step 1: Pre-check
    dot = dot_product(face_normal, desired_velocity)
    if dot < 0:
        return desired_velocity

    # Step 2: Ray Generation
    # Get box corners and front face center
    corners = get_box_corners(box)
    front_face_center = get_front_face_center(box, face_normal)
    ray_origins = corners + [front_face_center]
    
    resolved_velocity = copy(desired_velocity)
    
    # Step 3 & 4: Intersection Testing and Resolution
    for origin in ray_origins:
        # Create ray: origin + t * desired_velocity
        # Plane equation: dot(normal, point) = distance
        # Intersection t: t = (distance - dot(normal, origin)) / dot(normal, desired_velocity)
        
        denom = dot_product(face_normal, desired_velocity)
        if abs(denom) < epsilon:
            continue # Ray is parallel to plane
            
        t = (face_distance - dot_product(face_normal, origin)) / denom
        
        # Check if intersection is on the segment [0, 1]
        if 0.0 <= t <= 1.0:
            intersection_point = origin + desired_velocity * t
            
            # Verify point lies on the face segment (if face is bounded)
            # [G] Assuming unbounded plane for basic resolution; if bounded, check containment
            if is_point_on_face_segment(intersection_point, face_vertices):
                # Check normal components to zero out velocity
                if abs(face_normal.y) > epsilon:
                    resolved_velocity.y = 0.0
                    break # First collision breaks loop
                
                if abs(face_normal.z) > epsilon:
                    resolved_velocity.z = 0.0
                    
    # Special Y-component handling if no intersections or specific logic
    # [S1, unofficial] If no intersections, result.Y might be set to diff between intersection Y and box min Y
    # [G] Since we initialized result = desired_velocity and only zeroed components,
    # this specific logic implies a fallback or alternative path not fully detailed in sources.
    # We stick to the primary logic: zeroing components based on normal.
    
    return resolved_velocity

def is_point_on_line_segment(p, a, b):
    """Checks if point p lies on segment ab."""
    # [G] Standard geometric check
    cross = (b.x - a.x) * (p.y - a.y) - (b.y - a.y) * (p.x - a.x)
    if abs(cross) > epsilon:
        return False
    dot = (p.x - a.x) * (b.x - a.x) + (p.y - a.y) * (b.y - a.y)
    if dot < 0:
        return False
    sq_len = (b.x - a.x)**2 + (b.y - a.y)**2
    if dot > sq_len:
        return False
    return True
```

**Parameters:**
- `epsilon`: A small value for floating-point comparisons (Not given in the sources.).

**Edge Cases and Pitfalls:**
- **Incorrect Intersection Values**: The intersection calculation may return values outside the valid segment. Always verify the intersection point lies on the line segment between the ray origin and `origin + desiredVelocity` using `IsPointOnLineSegment` [S1, unofficial].
- **Partial Resolution**: The implementation only adjusts velocity along axes where the face normal is non-zero. It does not compute the exact velocity required to reach the intersection point, merely zeroing the component [S1, unofficial].
- **Early Exit**: Slopes and steps require checking all rays, but only the first collision breaks the loop. This may lead to incomplete resolution if multiple faces are involved, though this method targets a single face [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$, as it involves a fixed number of rays (5) and simple arithmetic operations per ray.
- **Memory Complexity**: $O(1)$, requiring storage for a few vectors and points.
- **Strengths**: Simple to implement; fast execution; effective for single-face collision resolution in voxel or grid-based environments.
- **Limitations**: Does not handle multi-face collisions comprehensively; relies on ray casting which may miss grazing collisions if not sampled densely; velocity adjustment is coarse (zeroing components) rather than reflective or sliding [S1, unofficial].
- **When to Use**: Real-time voxel games or simulations where performance is critical and collisions are primarily against axis-aligned planes.
- **When Not to Use**: High-fidelity physics simulations requiring precise reflection vectors or multi-body collision resolution.

## Background
The method originates from the MonoGame Voxel Game Engine project by Terry Lyons [S1, unofficial]. It is part of a broader effort to implement efficient collision detection in voxel-based environments using XNA/MonoGame frameworks. The approach leverages the simplicity of AABBs and planar faces to achieve real-time performance without complex spatial partitioning for individual collisions.
