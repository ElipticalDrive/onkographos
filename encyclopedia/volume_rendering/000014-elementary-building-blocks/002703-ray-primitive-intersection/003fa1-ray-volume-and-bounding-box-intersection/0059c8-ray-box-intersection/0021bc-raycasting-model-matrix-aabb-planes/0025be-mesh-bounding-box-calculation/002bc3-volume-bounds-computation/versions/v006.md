# Volume Bounds Computation

Also called: computeVolumeBounds

## Overview
Volume Bounds Computation computes an Axis-Aligned Bounding Box (AABB) that encloses a set of 3D points, with optional padding in world units on all sides [S1, unofficial]. It serves as the foundational step for initializing voxel grids and spatial samplers by defining the spatial extent of the scene [S1, unofficial]. Unlike [Bounding Cube Creation](4007-bounding-cube-creation.md), which forces a cubic aspect ratio, or [Character Bounding Box Initialization](4016-character-bounding-box-initialization.md), which targets specific skeletal hierarchies, this method produces a rectangular prism tailored to the input point distribution, with configurable padding in world units on all sides [S1, unofficial].

## How it works
**Inputs:**
- `points`: An array of 3D points, where each point is a tuple or vector `[x, y, z]` [S1, unofficial].
- `padding`: A scalar value representing the padding to add to all sides of the bounding box in world units [S1, unofficial]. If not specified, defaults to 0.0.

**Outputs:**
- `VolumeBounds`: An object containing:
  - `min`: `[number, number, number]` — The minimum coordinates of the AABB.
  - `max`: `[number, number, number]` — The maximum coordinates of the AABB.
  - `size`: `[number, number, number]` — The dimensions of the AABB (`max - min`).
  - `center`: `[number, number, number]` — The geometric center of the AABB.

**Data Structures:**
The `VolumeBounds` object is a flat structure with four fields, each being a 3-element array of floating-point numbers [S1, unofficial].

**Algorithm Steps:**
1. Initialize `min` to `[Infinity, Infinity, Infinity]` and `max` to `[-Infinity, -Infinity, -Infinity]` [G].
2. Iterate through each point `p` in `points`:
   a. Update `min.x = min(min.x, p.x)`, `min.y = min(min.y, p.y)`, `min.z = min(min.z, p.z)` [S1, unofficial].
   b. Update `max.x = max(max.x, p.x)`, `max.y = max(max.y, p.y)`, `max.z = max(max.z, p.z)` [S1, unofficial].
3. Apply padding:
   a. `min.x -= padding`, `min.y -= padding`, `min.z -= padding` [S1, unofficial].
   b. `max.x += padding`, `max.y += padding`, `max.z += padding` [S1, unofficial].
4. Compute `size`:
   a. `size.x = max.x - min.x` [G].
   b. `size.y = max.y - min.y` [G].
   c. `size.z = max.z - min.z` [G].
5. Compute `center`:
   a. `center.x = (min.x + max.x) / 2` [G].
   b. `center.y = (min.y + max.y) / 2` [G].
   c. `center.z = (min.z + max.z) / 2` [G].
6. Return `VolumeBounds` object with `min`, `max`, `size`, and `center` [S1, unofficial].

**Pseudocode:**
```python
def compute_volume_bounds(points: list[tuple[float, float, float]], padding: float = 0.0) -> dict:
    # Initialize min and max with extreme values
    min_val = [float('inf'), float('inf'), float('inf')]
    max_val = [float('-inf'), float('-inf'), float('-inf')]

    # Iterate over all input points to find min and max coordinates
    for p in points:
        if p[0] < min_val[0]: min_val[0] = p[0]
        if p[1] < min_val[1]: min_val[1] = p[1]
        if p[2] < min_val[2]: min_val[2] = p[2]
        
        if p[0] > max_val[0]: max_val[0] = p[0]
        if p[1] > max_val[1]: max_val[1] = p[1]
        if p[2] > max_val[2]: max_val[2] = p[2]

    # Apply configurable padding in world units to all sides
    min_val[0] -= padding
    min_val[1] -= padding
    min_val[2] -= padding
    
    max_val[0] += padding
    max_val[1] += padding
    max_val[2] += padding

    # Compute size and center
    size = [
        max_val[0] - min_val[0],
        max_val[1] - min_val[1],
        max_val[2] - min_val[2]
    ]
    
    center = [
        (min_val[0] + max_val[0]) / 2.0,
        (min_val[1] + max_val[1]) / 2.0,
        (min_val[2] + max_val[2]) / 2.0
    ]

    return {
        "min": min_val,
        "max": max_val,
        "size": size,
        "center": center
    }
```

**Parameters:**
- `padding`: Configurable padding in world units. Typical value: 0.0 for tight bounds, >0.0 for safety margins [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Empty Input:** If `points` is empty, `min` remains `[inf, inf, inf]` and `max` remains `[-inf, -inf, -inf]`. The caller must check for this case before using the result [G].
- **Precision:** Using `float('inf')` ensures correct initialization regardless of the scale of the input data, avoiding underflow/overflow issues with arbitrary initial values [G].
- **Degenerate Input:** If all points are identical, `size` will be `[0, 0, 0]`. Padding ensures the box has non-zero volume if `padding > 0` [S1, unofficial].

## Subtopics

### [Silhouette-based Bounding Box Initialization](5448-silhouette-based-bounding-box-initialization.md)
Silhouette-based Bounding Box Initialization computes an Axis-Aligned Bounding Box (AABB) that tightly encloses the visible geometry of a scene by projecting ground truth silhouettes from training cameras onto the scene space. It serves as a robust initialization step for volume rendering, particularly when the scene is dense or when precise spatial bounds are required before adaptive learning or sparse voxel grid construction begins. Unlike simple extent-based methods, it accounts for camera visibility and occlusion, ensuring the bounding volume only encompasses regions actually observed by the training set.

### [Silhouette-Based Bounding Box Estimation](5457-silhouette-based-bounding-box-estimation.md)
Silhouette-Based Bounding Box Estimation computes a 3D volume that strictly encloses a target object by intersecting the back-projected foreground regions from multiple binary segmentation masks. It differs from [Octree-based Bounding Volume Computation](6270-octree-based-bounding-volume-computation.md) by relying solely on 2D image masks rather than hierarchical spatial partitioning, and from [Silhouette-based Bounding Box Initialization](5448-silhouette-based-bounding-box-initialization.md) by explicitly constructing the full volumetric hull rather than just an initial box.

### [Octree-based Bounding Volume Computation](6270-octree-based-bounding-volume-computation.md)
Octree-based Bounding Volume Computation computes a convex bounding volume for a signed distance field (SDF) by adaptively decomposing space into an octree and extracting the convex hull from cubes that straddle the surface. It serves as an alternative to Sphere Carving, trading higher SDF evaluation costs for potentially faster convergence on shapes with significant anisotropy in the field values. Unlike Sphere Carving, which provides strict bounding guarantees, this approach does not guarantee that the resulting volume encloses the entire surface.

### [Oriented Bounding Box (OBB) Computation](14945-oriented-bounding-box-obb-computation.md)
Oriented Bounding Box (OBB) Computation computes an oriented bounding box (OBB) that tightly encloses a set of 3D points or sub-boxes by fitting an ellipsoid via Principal Component Analysis (PCA) on the covariance matrix of the vertices. Unlike its sibling [Volume Bounds Computation](5114-volume-bounds-computation.md), which produces axis-aligned boxes, this method determines optimal orientation and extent, providing tighter bounds for rotated instances. It is primarily used in 3D cuboid detection for instance segmentation and conservative culling in SDF-based rendering.

### [Selective Bounding Volume (SBV)](20489-selective-bounding-volume-sbv.md)
Selective Bounding Volume (SBV) is a 3D extension of the 2D bounding box method used to identify and extract a Volume of Interest (VOI) from a 3D medical image by ignoring blank slices and confining coordinates to active portions. It sets itself apart from shape-adaptive methods by refusing to discard any active portions in any slices, thereby preserving clinically significant background details that other methods might remove.

### Robust Bounding Box Computation
Robust Bounding Box Computation is a method to compute a bounding box for a 3DGS scene by clipping outliers using percentiles, preventing distant 'floater' splats from dominating the AABB [S2, unofficial]. It differs from the standard method by ignoring extreme values in the coordinate distribution [S2, unofficial].
- **Definition:** Computes a bounding box by sorting splat centers and selecting coordinates at percentile boundaries [S2, unofficial].
- **Steps:**
  1. Collect all X, Y, and Z coordinates of the splat centers into separate arrays [S2, unofficial].
  2. Sort each coordinate array in ascending order [S2, unofficial].
  3. Calculate the lower index as `floor(p * (N - 1))` and the upper index as `ceil((1 - p) * (N - 1))`, where N is the number of splats and p is `bboxPercentile` [S2, unofficial].
  4. Construct the bounding box using the coordinates at the lower and upper indices for each axis [S2, unofficial].
- **Parameters:** `bboxPercentile`: The fraction of splats to clip from each end of the distribution per axis. Typical value: 0.02 (clip outer 2%) [S2, unofficial].
- **Complexity:** O(N log N) due to sorting, where N is the number of splats [S2, unofficial].

## Operating characteristics
- **Time Complexity:** O(N) for the standard AABB computation, where N is the number of input points [S1, unofficial]. O(N log N) for the Robust Bounding Box Computation due to sorting [S2, unofficial].
- **Memory Complexity:** O(N) to store the input points and coordinate arrays for the robust method [S2, unofficial]. The standard method uses O(1) auxiliary space [S1, unofficial].
- **Strengths:** Simple, fast, and predictable performance for static datasets [S1, unofficial]. The robust variant effectively handles outliers common in neural rendering scenes (e.g., 3DGS floaters) [S2, unofficial].
- **Limitations:** The standard AABB may be too loose if the scene has significant anisotropy or outliers [S2, unofficial]. Silhouette-based methods require accurate camera poses and masks [S2, unofficial]. OBB computation is more expensive and complex [S1, unofficial][S2, unofficial].
- **When to use:** Use standard AABB for general point clouds and mesh bounds [S1, unofficial]. Use robust bounding box for 3D Gaussian Splatting scenes with potential outliers [S2, unofficial]. Use silhouette-based when no 3D geometry is available [S1, unofficial]. Use OBB when tight fitting for oriented instances is required [S1, unofficial][S2, unofficial].

## Background
Volume Bounds Computation is a fundamental technique in computer graphics for defining the spatial extent of a scene or object [S1, unofficial]. It is widely used in volume rendering to initialize voxel grids, splat carvers, and raymarchers [S1, S2, unofficial]. The method is often a precursor to more complex bounding volume hierarchies or spatial partitioning structures [S1, unofficial]. In the context of neural rendering and 3D Gaussian Splatting, robust variants have been developed to handle the specific challenges of outlier splats [S2, unofficial]. Silhouette-based methods are common in NeRF-like pipelines where explicit geometry is not available [S2, unofficial].
