# Procedural Ray/Box Intersection
## Overview
Procedural Ray/Box Intersection determines ray entry and exit within a volume's bounding box entirely within the fragment shader, without pre-rendering geometry [S1, unofficial][S2, unofficial]. Unlike rasterization-based setup methods like [Ray-box intersection](776-ray-box-intersection.md) or [Ray-Volume Intersection (Face Distance Method)](2381-ray-volume-intersection-face-distance-method.md), it computes intersection parameters directly in the shader, making it self-contained but placing the full computational load on the fragment shader [S1, unofficial][S2, unofficial].
## How it works
**Inputs and Outputs**
*   **Input:** Camera position $\mathbf{o}_{cam}$, volume entry position $\mathbf{p}_{entry}$, and bounding box corners $\mathbf{b}_{min}$ and $\mathbf{b}_{max}$ [S1, unofficial][S2, unofficial].
*   **Output:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, and exit parameter $t_{exit}$ for the marching loop [S1, unofficial][S2, unofficial].

**Data Structures**
*   **Ray:** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].
*   **Bounding Box:** Axis-aligned box defined by $\mathbf{b}_{min}$ and $\mathbf{b}_{max}$ [G].

**Steps**
1.  **Define the Ray:** Set $\mathbf{o} = \mathbf{o}_{cam}$ [S1, unofficial][S2, unofficial]. Compute $\mathbf{d} = \mathbf{p}_{entry} - \mathbf{o}_{cam}$ [S1, unofficial][S2, unofficial].
2.  **Compute Exit Criterion:** Calculate $t_{exit}$ to determine when the ray leaves the bounding box [S1, unofficial][S2, unofficial].
3.  **Marching Loop:** Use $\mathbf{o}$, $\mathbf{d}$, and $t_{exit}$ to march through volume data, terminating when the exit criterion is met [S1, unofficial][S2, unofficial].

**Formulas**
$$ \mathbf{d} = \mathbf{p}_{entry} - \mathbf{o}_{cam} $$
where $\mathbf{o}_{cam}$ is the camera position and $\mathbf{p}_{entry}$ is the volume entry position [S1, unofficial][S2, unofficial].

**Pseudocode**
```python
def procedural_ray_box_intersection(camera_pos, volume_entry_pos, box_min, box_max):
    """
    Computes ray parameters for volume marching within a bounding box.
    """
    ray_origin = camera_pos
    ray_direction = volume_entry_pos - camera_pos
    
    # Compute t values for intersection with all 6 planes (slab method) [G]
    t1 = (box_min - ray_origin) / ray_direction
    t2 = (box_max - ray_origin) / ray_direction
    
    t_min = min(t1, t2)
    t_max = max(t1, t2)
    
    t_enter = max(t_min.x, t_min.y, t_min.z)
    t_exit = min(t_max.x, t_max.y, t_max.z)
    
    if t_enter > t_exit:
        return None, None, -1.0
            
    return ray_origin, ray_direction, t_exit
```

**Parameters**
*   **Exit Criterion:** Required to determine when the ray has left the volume [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Precision:** Division by zero in direction components is handled by floating-point infinity and min/max operations [G].
*   **Boundaries:** The method assumes the volume entry position lies on the near face of the bounding box [S1, unofficial][S2, unofficial].
*   **Performance:** The entire computational load for intersection and marching is placed on the fragment shader, which is a disadvantage compared to rasterization-based setup [S1, unofficial][S2, unofficial].
## Operating characteristics
*   **Strengths:** Simple and self-contained implementation [S1, unofficial][S2, unofficial].
*   **Limitations:** Full computational load on the fragment shader [S1, unofficial][S2, unofficial].
## Background
The method was introduced by Röttger et al. in 2003 and Green in 2004 [S2, unofficial].
