# Image Bounds Check

## Overview
Image Bounds Check verifies whether 2D coordinates lie within the normalized image plane boundaries (0 to 1) [S1, unofficial]. It serves as a guard clause in ray-image frame intersection logic to prevent out-of-bounds memory access or invalid sampling when projecting rays onto the image plane [S1, unofficial]. Unlike sibling methods that compute intersection points, this method performs a simple validity test with epsilon tolerance to handle floating-point precision errors near the edges [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `xy`, a tensor or array of 2D coordinates with shape `(N, 2)` or `(2,)`, representing normalized image coordinates $(u, v)$ [S1, unofficial].
- Input: `epsilon`, a float tolerance value [S1, unofficial].
- Output: A boolean value or boolean tensor indicating whether all coordinates are within the valid range [S1, unofficial].

**Data Structures:**
- `xy`: Floating-point array/tensor. No specific bit-packing is required beyond standard float representation [S1, unofficial].

**Steps:**
1. Define the tolerance `epsilon`. The typical value is $10^{-6}$ [S1, unofficial].
2. Check if all coordinates in `xy` are greater than or equal to $-\epsilon$ and less than or equal to $1 + \epsilon$ [S1, unofficial].
3. Return the logical AND of the lower and upper bound checks [S1, unofficial].

**Formula:**
$$ \text{valid} = \left( \min(xy) \ge -\epsilon \right) \land \left( \max(xy) \le 1 + \epsilon \right) $$
Where $xy$ represents the coordinate vector(s) [S1, unofficial].

**Parameters:**
- `epsilon`: Float. Default value $10^{-6}$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- Coordinates exactly at 0 or 1 are considered valid due to the epsilon tolerance [S1, unofficial].
- Negative coordinates slightly below 0 (within epsilon) are treated as valid [S1, unofficial].
- Coordinates slightly above 1 (within epsilon) are treated as valid [S1, unofficial].
- If `xy` is empty, the result depends on the implementation of `.all()`, but typically returns `True` for an empty set in many tensor libraries [G].

**Pseudocode:**
```python
def image_bounds_check(xy, epsilon=1e-6):
    """
    Check if 2D coordinates are within the normalized image plane [0, 1] with epsilon tolerance.
    
    Args:
        xy: Array-like of shape (..., 2) or (2,) containing u, v coordinates.
        epsilon: Float tolerance for boundary checks.
        
    Returns:
        Boolean or boolean tensor: True if all coordinates are within [-epsilon, 1+epsilon].
    """
    # Check if all coordinates are >= -epsilon
    lower_bound_check = (xy >= -epsilon)
    
    # Check if all coordinates are <= 1 + epsilon
    upper_bound_check = (xy <= 1 + epsilon)
    
    # Combine checks: all elements must satisfy both conditions
    # .all(dim=-1) ensures the check applies to the last dimension (coordinates)
    # and returns a boolean for each sample if xy is batched
    return (lower_bound_check.all(dim=-1) & upper_bound_check.all(dim=-1))
```

## Subtopics

### Image Sampling
Resolves the color of a sampled point by sampling an image texture at given UV coordinates if a material image index is provided, otherwise returning the base color [S2, unofficial]. It handles boundary clamping and coordinate wrapping for flat image arrays [S2, unofficial]. Choose this when you need to map 3D points to 2D image colors using UV coordinates [S2, unofficial]. Link: [Image Sampling](image-sampling.md).

**Definition:**
- Samples a single pixel color from a flat image array given UV coordinates, handling boundary clamping and coordinate wrapping [S2, unofficial].
- If `material.image_index` is `None` or `uv` is `None`, returns `material.base_color` [S2, unofficial].

**Steps:**
1. If `material.image_index` is `None` or `uv` is `None`, return `material.base_color` [S2, unofficial].
2. Get image width and height from the image data associated with `material.image_index` [S2, unofficial].
3. If width or height is less than or equal to 0, return `None` [S2, unofficial].
4. Wrap UV coordinates to the $[0, 1)$ range using modulo: $u = uv[0] \% 1.0$, $v = uv[1] \% 1.0$ [S2, unofficial].
5. Compute pixel coordinates $x$ and $y$ by multiplying $u$ and $v$ by width and height respectively, casting to integer, and clamping to $[0, \text{width}-1]$ and $[0, \text{height}-1]$ [S2, unofficial].
6. Calculate the linear index in the pixel array assuming RGBA layout (4 bytes per pixel): $\text{index} = (y \times \text{width} + x) \times 4$ [S2, unofficial].
7. Retrieve the pixel data at `index` and return the first three channels (RGB) converted to a byte tuple [S2, unofficial].

**Pitfalls:**
- If width or height is $\le 0$, the function returns `None` [S2, unofficial].
- Coordinate wrapping uses modulo, which can cause discontinuities at image boundaries if not handled carefully [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ for a single point check, $O(N)$ for $N$ points, where $N$ is the number of coordinates [S1, unofficial].
- Memory: $O(1)$ auxiliary space [S1, unofficial].

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with the number of points checked [S1, unofficial].

**Strengths and Limitations:**
- Strengths: Simple, fast, and robust against floating-point errors near boundaries [S1, unofficial].
- Limitations: Only checks bounds [S1, unofficial].

**When to Use:**
- Use when validating 2D coordinates within the normalized image plane [S1, unofficial].

**When Not to Use:**
- Not given in the sources.

## Background
Origin: The method is documented in the NoPoSplat repository [S1, unofficial]. It is used in volume rendering and neural rendering pipelines to ensure that projected points remain within the valid image domain [S1, unofficial].
