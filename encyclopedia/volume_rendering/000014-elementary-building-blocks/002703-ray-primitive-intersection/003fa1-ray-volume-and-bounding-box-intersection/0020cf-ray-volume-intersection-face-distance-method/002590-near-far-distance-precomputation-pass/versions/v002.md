# Near/Far Distance Precomputation Pass

Also called: Voxel Brick Distance Pass, tNear-tFar Rendering

## Overview
The Near/Far Distance Precomputation Pass renders voxel bricks to a render target to compute the entry ($t_{Near}$) and exit ($t_{Far}$) distances of viewing rays intersecting the volume for each pixel [S1, unofficial]. This prepares the bounds for the subsequent raymarching pass, allowing the main rendering pass to skip empty space and focus computation only on occupied regions [S1, unofficial]. It differs from [Homogeneous Volume Intersection](3260-homogeneous-volume-intersection.md) by explicitly rasterizing the volume geometry to derive depth bounds rather than analytically solving for intersections with a homogeneous bounding box [G].

## How it works
**Inputs:**
- A flag volume texture (`m_pFlagVolumeSRV`) indicating which bricks are active [S1, unofficial].
- Camera matrices (`cb_mView`, `cb_mViewProj`) and view position (`cb_f4ViewPos`) [S1, unofficial].
- Volume parameters: `VOXEL_NUM_X/Y/Z`, `VOXEL_BRICK_RATIO`, `VOXEL_SIZE`, `g_cf3VoxelReso`, `g_cf3HalfBrickSize` [S1, unofficial].
- A render target view (`m_pFarNearRTV`) for output [S1, unofficial].

**Outputs:**
- A render target where each pixel stores $t_{Near}$ in the RGB channels and $t_{Far}$ in the Alpha channel [S1, unofficial].

**Data Structures:**
- **Render Target (`m_pFarNearRTV`):** Format not given in the sources.
- **Vertex Buffer (`m_pPassVB`):** Contains point primitives with stride `sizeof(short)` [S1, unofficial]. The content acts as a dummy list of primitive indices, as the actual geometry is generated in the Geometry Shader [S1, unofficial].
- **Flag Volume (`tex_FlagVolume`):** A 3D texture where active bricks are marked with `1` and inactive with `0` [S1, unofficial].

**Numbered Steps:**
1. **Clear Render Target:** Clear `m_pFarNearRTV` with `{50.0f, 50.0f, 50.0f, -10.0f}` [S1, unofficial]. This sets an initial background value where RGB=50 and Alpha=-10 [S1, unofficial].
2. **Set Topology:** Set primitive topology to `D3D11_PRIMITIVE_TOPOLOGY_POINTLIST` [S1, unofficial].
3. **Bind Resources:** Bind input layout `m_pOutVL`, vertex buffer `m_pPassVB` (stride `sizeof(short)`), vertex shader `m_pPassVS`, geometry shader `m_pActiveCellAndSOGS`, and pixel shader `m_pFarNearPS` [S1, unofficial].
4. **Bind Shaders:** Bind GS constant buffer `m_pCBperFrame` and GS shader resource `m_pFlagVolumeSRV` [S1, unofficial].
5. **Set States:** Set rasterizer state `m_pBackFaceRS` and blend state `m_pBlendState` [S1, unofficial].
6. **Draw:** Issue a draw call for `VOXEL_NUM_X * VOXEL_NUM_Y * VOXEL_Z / VOXEL_BRICK_RATIO^3` primitives [S1, unofficial].
7. **Restore:** Restore previous blend state [S1, unofficial].

**Blend State Configuration (`m_pBlendState`):**
- `BlendEnable = true`
- **RGB Channels ($t_{Near}$):** `SrcBlend=D3D11_BLEND_ONE`, `DestBlend=D3D11_BLEND_ONE`, `BlendOp=D3D11_BLEND_OP_MIN` [S1, unofficial]. Result: $t_{Near} = \min(t_{Near}, \text{new\_value})$ [S1, unofficial].
- **Alpha Channel ($t_{Far}$):** `SrcBlendAlpha=D3D11_BLEND_ONE`, `DestBlendAlpha=D3D11_BLEND_ONE`, `BlendOpAlpha=D3D11_BLEND_OP_MAX` [S1, unofficial]. Result: $t_{Far} = \max(t_{Far}, \text{new\_value})$ [S1, unofficial].
- `RenderTargetWriteMask=D3D11_COLOR_WRITE_ENABLE_ALL` [S1, unofficial].

**Pseudocode (Geometry Shader Logic):**
The Geometry Shader iterates over active bricks, generates a cube for each, transforms it to clip space, and outputs it [S1, unofficial].

```python
def geometry_shader(primID, flag_volume, VOXEL_NUM_Y, VOXEL_BRICK_RATIO, 
                    g_cf3VoxelReso, VOXEL_SIZE, g_cf3HalfBrickSize, cb_mViewProj):
    # Decode brick coordinates from primitive ID
    u3Idx_z = primID // (g_cuFlagVolSliceStep * g_cuFlagVolStripStep)
    u3Idx_y = (primID % g_cuFlagVolSliceStep) // g_cuFlagVolStripStep
    u3Idx_x = primID % g_cuFlagVolStripStep

    # Check if the current cell is active, discard if inactive
    if flag_volume[u3Idx_z, u3Idx_y, u3Idx_x] != 1:
        return

    # Adjust Y coordinate (source flips Y)
    u3Idx_y = (VOXEL_NUM_Y // VOXEL_BRICK_RATIO) - 1 - u3Idx_y

    # Calculate the offset vector to move (0,0,0,1) to current cell center
    center_offset = (float3(u3Idx_x, u3Idx_y, u3Idx_z) - 
                     float3(g_cf3VoxelReso.x, g_cf3VoxelReso.y, g_cf3VoxelReso.z) * 0.5 / VOXEL_BRICK_RATIO + 0.5) * VOXEL_SIZE * VOXEL_BRICK_RATIO

    # Get half cell size to expand the cell center point to full cell cube geometry
    half_cell_size = float3(g_cf3HalfBrickSize.x, g_cf3HalfBrickSize.y, g_cf3HalfBrickSize.z)

    # Define cube vertices in local space (-1 to 1)
    verts = [
        float3(-1, -1, -1), float3(-1, 1, -1), float3(1, 1, -1), float3(1, -1, -1),
        float3(-1, -1, 1),  float3(-1, 1, 1),  float3(1, 1, 1),  float3(1, -1, 1)
    ]

    # Output front face vertices as a line strip
    for i in range(4):
        output = PS_INPUT()
        v = verts[i] * half_cell_size + center_offset
        output.Pos = float4(v.x, v.y, v.z, 1.0)
        output.projPos = mul(output.Pos, cb_mViewProj)
        lineStream.Append(output)
    lineStream.RestartStrip()

    # Output back face vertices as a line strip
    for i in range(4, 8):
        output = PS_INPUT()
        v = verts[i] * half_cell_size + center_offset
        output.Pos = float4(v.x, v.y, v.z, 1.0)
        output.projPos = mul(output.Pos, cb_mViewProj)
        lineStream.Append(output)
    lineStream.RestartStrip()

# Pixel Shader (m_pFarNearPS)
# Calculates depth for the projected cube faces.
# Logic not provided in sources. It outputs fragment depth to be blended [S1, unofficial].
def pixel_shader(input):
    # Convert clip space position to view space depth
    z_clip = input.projPos.z / input.projPos.w
    # Convert to linear view space depth (standard D3D11 mapping)
    linear_depth = -(z_clip * 2.0 - 1.0)
    return float4(linear_depth, linear_depth, linear_depth, linear_depth)
```

**Edge Cases and Pitfalls:**
- **Back-Face Culling:** The use of `m_pBackFaceRS` means only front-facing triangles are rendered [S1, unofficial]. The sources enable back-face culling but do not explain how $t_{Far}$ is correctly accumulated when back faces are discarded, given the Alpha channel uses a MAX blend operation [S1, unofficial].
- **Precision:** Using `float` for depth calculations may introduce precision errors for large scenes [S1, unofficial]. The clear value of `{50.0f, 50.0f, 50.0f, -10.0f}` must lie outside the expected range of valid depths to ensure correct min/max accumulation [S1, unofficial].
- **Empty Bricks:** Inactive bricks (flag != 1) are discarded early in the GS, preventing unnecessary rendering and blending operations [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Depends on the number of active bricks and the resolution of the render target [S1, unofficial]. Rasterizing wireframes can be expensive if the number of active bricks is high [S1, unofficial].
- **Strengths:** Efficiently culls empty space using standard rasterization hardware [S1, unofficial].
- **Limitations:** Requires a second raymarching pass; accuracy depends on the rasterization of the cube geometry; back-face culling complicates $t_{Far}$ derivation [S1, unofficial].

## Background
Origin: Part of the Dynamic Volume Raycasting implementation [S1, unofficial]. History: The technique leverages the GPU's rasterization pipeline to compute depth bounds, avoiding the need for complex CPU-side bounding volume hierarchy traversal or analytical intersection tests for every ray [S1, unofficial]. Usage: It is used in real-time volume rendering applications where efficient culling of empty space is critical for performance [S1, unofficial].
