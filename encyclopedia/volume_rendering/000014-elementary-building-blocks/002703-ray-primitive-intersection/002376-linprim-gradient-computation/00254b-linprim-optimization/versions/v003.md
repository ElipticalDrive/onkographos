# LinPrim Optimization

Also called: X-Gaussian Optimization, X-Gaussian Training

## Overview
LinPrim Optimization is the training procedure for Linear Primitives, using differentiable rendering to adjust primitive attributes (center, covariance, opacity, color) by backpropagating gradients from a composite L1 and SSIM loss through the entire rendering pipeline [S2]. It distinguishes itself from standard Gaussian Splatting by explicitly handling the backpropagation through the Linear Primitive Intersection Algorithm (MTIA) and preprocessing steps, including specific handling for ray-space to world-space transformation and adaptive learning rates based on scene scale [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A set of $N_p$ linear primitives, each defined by attributes $\boldsymbol{\mu}_i$ (center), $\boldsymbol{\Sigma}_i$ (covariance), $\alpha_i$ (opacity), and $\mathbf{f}_i$ (color/features) [S1, S2]. Ground-truth images from known views.
*   **Outputs:** Optimized primitive attributes $\boldsymbol{\mu}_i, \boldsymbol{\Sigma}_i, \alpha_i, \mathbf{f}_i$ [S1].

**Data Structures:**
*   **Primitive Attributes:** Each primitive $i$ stores:
    *   $\boldsymbol{\mu}_i$: 3D position vector.
    *   $\boldsymbol{\Sigma}_i$: $3 \times 3$ covariance matrix (or equivalent parameterization).
    *   $\alpha_i$: Scalar opacity.
    *   $\mathbf{f}_i$: Color/feature vector.
*   **Ray Space Geometry:** Primitives are transformed into ray space for intersection computation. The position of corners in ray space depends on the ray space center and offsets [S2].

**Numbered Steps:**
1.  **Forward Rendering:** Render the scene using the current primitive attributes. Compute the intersection depths $\mathbf{i}$ using the Linear Primitive Intersection Algorithm (MTIA) [S2].
2.  **Loss Computation:** Calculate the training objective $\mathcal{L}$ as a weighted sum of L1 loss $\mathcal{L}_1$ and SSIM loss $\mathcal{L}_{\text{SSIM}}$ between the rendered image and the ground-truth image [S1, S2]:
    $$
    \mathcal{L} = (1 - \gamma)\mathcal{L}_1 + \gamma\mathcal{L}_{\text{SSIM}}
    $$
    where $\gamma$ is a hyperparameter balancing the two loss terms [S1].
3.  **Rasterization Backpropagation:**
    *   Backpropagate through the alpha blending process to obtain gradients with respect to each primitive's alpha $\alpha_i$ and color $\mathbf{f}_i$ [S2].
    *   The gradient of alpha $\frac{\partial \mathcal{L}}{\partial \alpha_i}$ indicates whether the primitive should be more or less transparent. This implies whether the intersections should move closer together or farther apart along the pixel's ray [S2].
    *   Propagate gradients through the MTIA to obtain gradients with respect to the intersection depths $\mathbf{i}$ [S2].
    *   Aggregate gradients over the triangle corners and both intersections to propagate gradients from alpha to the geometric features (primitive center and vertices) [S2]. The intersection depth is influenced by the position of each corner of the triangle [S2].
4.  **Preprocessing Backpropagation:**
    *   The gradients obtained in Step 3 are in ray space. Reverse the projection and view transformations to yield world space gradients [S2].
    *   Compute final center gradients by combining the propagated ray space center gradients with the impact of the position on the ray space approximation and view-dependent color [S2].
    *   Split the gradient flow with respect to the corners when undoing the rotation, propagating gradients onto quaternion and distance features respectively [S2].
5.  **Learning Rate Adjustment:**
    *   Approximate the scene size using the maximum distance between two training cameras [S2].
    *   Adjust the learning rates for position and distance features accordingly to handle scene scale ambiguity [S2].
6.  **Parameter Update:**
    *   Optimize the attributes using the ADAM optimizer [S2].
    *   Adjust the number of primitives $N_p$ using adaptive control (e.g., cloning/splitting based on gradient magnitude or opacity, as adapted from 3DGS) [S1, S2].

**Pseudocode:**
```python
def linprim_optimization(primitives, ground_truth_images, cameras, gamma, lr_config):
    """
    Optimizes LinPrim attributes using differentiable rendering.
    primitives: List of primitives with attributes (mu, Sigma, alpha, f)
    ground_truth_images: List of target images
    cameras: List of camera parameters
    gamma: Hyperparameter for loss weighting
    lr_config: Configuration for learning rates and scene size
    """
    # Initialize optimizer with ADAM
    optimizer = Adam(primitives.parameters())
    
    # Approximate scene size for learning rate adjustment
    scene_size = max_distance_between_cameras(cameras)
    adjust_learning_rates(lr_config, scene_size)
    
    for epoch in range(max_epochs):
        total_loss = 0
        for image, camera in zip(ground_truth_images, cameras):
            # 1. Forward Rendering
            # Transform primitives to ray space
            ray_space_primitives = transform_to_ray_space(primitives, camera)
            
            # Render using LinPrim rasterization (MTIA)
            rendered_image = linprim_rasterize(ray_space_primitives, camera)
            
            # 2. Loss Computation
            l1_loss = compute_l1_loss(rendered_image, image)
            ssim_loss = compute_ssim_loss(rendered_image, image)
            loss = (1 - gamma) * l1_loss + gamma * ssim_loss
            
            # 3. Rasterization Backpropagation
            # Backprop through blending to get dL/d_alpha and dL/d_color
            d_alpha, d_color = backprop_blending(loss, rendered_image)
            
            # Backprop through MTIA to get dL/d_intersection_depth
            d_intersection = backprop_mtia(d_alpha, d_color, ray_space_primitives)
            
            # Aggregate gradients to geometric features (corners/vertices)
            d_geometric_ray = aggregate_geometric_gradients(d_intersection, ray_space_primitives)
            
            # 4. Preprocessing Backpropagation
            # Reverse projection and view transformations to get world space gradients
            d_geometric_world = backprop_preprocessing(d_geometric_ray, camera)
            
            # Combine with impact on ray space approximation and view-dependent color
            d_mu_world = combine_center_gradients(d_geometric_world, primitives, camera)
            
            # Split gradient flow for corners (quaternion and distance)
            d_quat, d_dist = split_corner_gradients(d_geometric_world, primitives)
            
            # 5. Update Gradients
            primitives.set_gradients(d_mu_world, d_quat, d_dist, d_alpha, d_color)
            
            total_loss += loss.item()
        
        # 6. Parameter Update
        optimizer.step()
        optimizer.zero_grad()
        
        # Adaptive control for population N_p
        primitives.adaptive_control()
        
    return primitives
```

**Parameters:**
*   $\gamma$: Hyperparameter balancing L1 and SSIM loss. Typical value not given in sources [S1].
*   Learning rates: Adjusted based on scene size (max distance between training cameras) [S2].

**Edge Cases and Pitfalls:**
*   **Scene Scale Ambiguity:** The method explicitly addresses scale ambiguity by adjusting learning rates based on the maximum distance between training cameras [S2].
*   **Ray Space vs. World Space:** Gradients must be correctly transformed from ray space (where intersection occurs) to world space (where primitives are stored) [S2].
*   **Rotation Handling:** Gradient flow splits when undoing rotation onto quaternion and distance features, requiring careful implementation of the inverse rotation [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources. The method mentions "cheaper training costs and faster inference speed" compared to RGB rasterization in 3DGS due to avoiding complex view direction computations [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Differentiable rendering allows end-to-end optimization. Explicit handling of ray-space to world-space gradients and scene scale adaptation [S2].
*   **Limitations:** Requires careful implementation of the backpropagation through the MTIA and preprocessing steps [S2].
*   **When to use:** When optimizing linear primitives for differentiable volumetric rendering, particularly in X-ray or similar modalities where view direction computations can be simplified [S1, S2].

## Background
*   **Origin:** LinPrim Optimization is part of the LinPrim method, introduced in "LinPrim: Linear Primitives for Differentiable Volumetric Rendering" [S2]. It builds on the differentiable rendering framework of 3D Gaussian Splatting (3DGS) [S1, S2].
*   **History:** The method adapts the population control and optimization strategies from 3DGS to linear primitives [S2].
*   **Usage:** Used for differentiable volumetric rendering, with specific application in X-ray novel view synthesis (Radiative Gaussian Splatting) [S1].
