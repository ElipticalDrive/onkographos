# Two-Pass Ray Entry/Exit Determination

Also called: Front/Backface Buffer Raycasting, Ray Setup Pass, Ray casting setup rendering, Two-Pass Raycasting with Back-Face Depth Buffering

## Overview
This method determines the 3D volume texture coordinates for the entry and exit points of a ray passing through a volume's bounding box by rendering the box geometry to textures using OpenGL [S2, unofficial]. It solves the problem of providing the fragment shader with the precise start and end texture coordinates required for volume traversal without complex CPU-side ray-box intersection calculations [S2, unofficial]. It sets itself apart from sibling methods by using a two-pass rendering approach where the first pass stores exit coordinates in a separate Framebuffer Object (FBO), and the second pass retrieves them, whereas alternatives like [Ray-Box Intersection via OpenGL Geometry Shaders](1768-ray-box-intersection-via-opengl-geometry-shaders.md) compute these points in a single pass using geometry shaders [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** The volume's bounding box geometry (typically a cube), the current camera view and projection matrices, and the volume texture dimensions.
*   **Outputs:** Two 2D textures (or a single FBO with multiple attachments) containing the 3D texture coordinates for the ray entry and exit points for each pixel.

**Data Structures:**
*   **Bounding Box Geometry:** A cube defined by 8 vertices. Each vertex has a position and a color attribute representing its 3D texture coordinates.
*   **Framebuffer Object (FBO):** A GPU-resident texture used to store the exit point coordinates from Pass 1.
*   **Vertex Shader Output:** Contains clip-space position and interpolated texture coordinates (color).

**Numbered Steps:**

1.  **Initialize Matrices:** Compute the concatenated World-View-Projection matrix ($M_{WVP}$) [S1, unofficial].
2.  **Pass 1: Render Back Faces (Exit Points):**
    *   Enable face culling to cull front faces: `glEnable(GL_CULL_FACE)` and `glCullFace(GL_FRONT)` [S2, unofficial].
    *   Bind the FBO texture for storing exit coordinates.
    *   Render the bounding box. The vertex shader transforms vertices using $M_{WVP}$ [S1, unofficial]. The fragment shader outputs the vertex color (texture coordinates) [S2, unofficial].
    *   The resulting texture contains the 3D texture coordinates of the exit point for each ray [S2, unofficial].
3.  **Pass 2: Render Front Faces (Entry Points):**
    *   Disable face culling or cull back faces to render front faces [S2, unofficial].
    *   Bind the FBO texture from Pass 1 as a sampler in the fragment shader.
    *   Render the bounding box. The vertex shader transforms vertices using $M_{WVP}$ [S1, unofficial].
    *   The fragment shader receives the vertex color (texture coordinates of the entry point) [S2, unofficial].
    *   The fragment shader samples the FBO texture at the current fragment's screen position to retrieve the exit point coordinates stored in Pass 1 [S2, unofficial].
    *   The fragment shader now has both entry and exit 3D texture coordinates and can proceed with volume rendering [S2, unofficial].

**Formulas:**
*   **Vertex Transformation:** $Pos_{clip} = M_{WVP} \times Pos_{model}$ [S1, unofficial].
*   **Texture Coordinate Mapping:** The vertices of the bounding box are assigned colors corresponding to their 3D texture coordinates. The axes map as follows: $x$ goes from black (0) to red (1), $y$ goes from black (0) to green (1), and $z$ goes from black (0) to blue (1) [S2, unofficial]. The texture coordinates range from $(0,0,0)$ at the lower-left-black corner to $(1,1,1)$ at the upper-right-white corner [S2, unofficial].
*   **DirectX Specific Shift:** If using DirectX-style model space coordinates in the range $[-0.5, 0.5]$, they are shifted to normalized texture coordinates in $[0.0, 1.0]$ using: $output.Tex = Pos.xyz + float3(0.5, 0.5, 0.5)$ [S1, unofficial].

**Parameters:**
*   $M_{WVP}$: Concatenated world-view-projection matrix [S1, unofficial].
*   Culling Mode: `GL_FRONT` for Pass 1, `GL_BACK` or disabled for Pass 2 [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Texture Coordinate Axes:** The mapping of RGB channels to texture axes ($x,y,z$) must be consistent. $x$ is Red, $y$ is Green, $z$ is Blue [S2, unofficial].
*   **Precision:** Using 16-bit floating point textures for the FBO may introduce precision errors in the stored coordinates [S1, unofficial].
*   **Culling:** Incorrect culling settings will result in missing entry or exit points [S2, unofficial].

**Pseudocode:**

```python
# Pass 1: Render Back Faces to FBO
def render_exit_points(fbo_texture, matrix_wvp, bounding_box):
    enable_culling()
    cull_face(GL_FRONT) # Cull front faces, render back faces
    bind_fbo(fbo_texture)
    
    for vertex in bounding_box.vertices:
        # Transform vertex to clip space
        clip_pos = matrix_wvp * vertex.position
        # Vertex color is the 3D texture coordinate
        tex_coord = vertex.color 
        
        # Rasterize
        fragment = interpolate(clip_pos, tex_coord)
        
        # Fragment shader: Output color (exit tex coord)
        fbo_texture[fragment.screen_pos] = fragment.tex_coord

# Pass 2: Render Front Faces and Retrieve Exit Points
def render_entry_points(matrix_wvp, bounding_box, fbo_texture):
    disable_culling() # Or cull back faces
    bind_default_framebuffer()
    
    for vertex in bounding_box.vertices:
        # Transform vertex to clip space
        clip_pos = matrix_wvp * vertex.position
        # Vertex color is the 3D texture coordinate (entry point)
        entry_tex_coord = vertex.color 
        
        # Rasterize
        fragment = interpolate(clip_pos, entry_tex_coord)
        
        # Fragment shader: Sample FBO to get exit point
        exit_tex_coord = fbo_texture.sample(fragment.screen_pos)
        
        # Now fragment has entry_tex_coord and exit_tex_coord
        # Proceed with volume rendering integral
        color = volume_rendering_integral(entry_tex_coord, exit_tex_coord)
        default_framebuffer[fragment.screen_pos] = color
```

## Subtopics

### Ray-Box Intersection via OpenGL Geometry Shaders
Computes entry/exit in a single pass using geometry shaders. Choose when single-pass efficiency is critical and geometry shader support is available. [Ray-Box Intersection via OpenGL Geometry Shaders](1768-ray-box-intersection-via-opengl-geometry-shaders.md)

### CPU-Side Ray-Box Intersection
Computes entry/exit on the CPU. Choose when GPU memory bandwidth for the FBO is a bottleneck or for simpler implementations. [Ray-Box Intersection](1767-ray-box-intersection.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, performed twice (two passes).
*   **Memory Complexity:** Requires storage for one additional FBO texture (typically 3 or 4 channels of 16-bit or 32-bit floats) [S1, S2, unofficial].
*   **Performance:** Dependent on GPU fill rate and memory bandwidth for the FBO read/write operations [S1, S2, unofficial].
*   **Strengths:** Simple to implement using standard OpenGL rendering pipeline; avoids complex ray-box intersection math on the GPU [S2, unofficial].
*   **Limitations:** Requires two rendering passes; precision loss with 16-bit textures; dependent on correct culling setup [S1, S2, unofficial].
*   **When to Use:** When using OpenGL and a two-pass approach is acceptable; when GPU geometry shader support is not desired or available [S2, unofficial].
*   **When Not to Use:** When single-pass performance is critical; when high precision is required and 16-bit textures are insufficient [S1, S2, unofficial].
