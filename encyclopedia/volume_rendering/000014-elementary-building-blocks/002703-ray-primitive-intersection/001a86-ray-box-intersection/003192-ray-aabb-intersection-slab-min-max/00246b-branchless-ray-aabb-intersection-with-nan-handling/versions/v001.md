# Branchless Ray/AABB Intersection with NaN Handling

Also called: Branchless Ray-AABB Intersection, Fast Branchless Ray/Bounding Box Intersection Part 2, NaN-safe Ray-AABB Intersection, Ray-AABB Intersection (Branchless), checkHit

## Overview
This method computes the intersection of a ray with an Axis-Aligned Bounding Box (AABB) in a branchless manner, returning the entry and exit times ($t_{min}, t_{max}$) and the specific faces intersected. It solves the problem of floating-point precision errors and NaN propagation that occur when a ray direction component is zero (resulting in $0 \times \infty$) or when the ray origin lies exactly on a slab boundary. It sets itself apart from the standard [Ray-AABB Intersection (Slab/Min-Max)](6548-ray-aabb-intersection-slab-min-max.md) by explicitly handling IEEE 754 special cases (NaNs and infinities) using nested min/max operations, ensuring robustness in BVH traversal without conditional branches.

## How it works
**Inputs:**
- Ray: `origin` (float3), `dir` (float3).
- AABB: `min` (float3), `max` (float3).

**Outputs:**
- `t_min` (float): Entry time.
- `t_max` (float): Exit time.
- `side_min` (float3): Normalized face index/sign at entry.
- `side_max` (float3): Normalized face index/sign at exit.
- `hit` (bool): True if intersection exists.

**Data Structures:**
- `dir_inv`: Precomputed inverse direction, `1.0 / dir`.
- `center`: `0.5 * (min + max)`.
- `minSize`: `0.5 * (max - min)`.
- `isPositive`: Boolean vector, `dir_inv > 0`.
- `isNegative`: Boolean vector, `1.0 - isPositive`.

**Steps:**
1.  **Precompute Inverse Direction:** Calculate `dir_inv[i] = 1.0 / dir[i]` for $i \in \{0, 1, 2\}$. Note that if `dir[i]` is 0, `dir_inv[i]` becomes $\pm \infty$ [S1, S2, unofficial].
2.  **Initialize Bounds (Dimension 0):** Compute $t_1$ and $t_2$ for the first dimension without bounds checking [S2, unofficial]:
    $$t_1 = (b.min[0] - r.origin[0]) \times r.dir\_inv[0]$$
    $$t_2 = (b.max[0] - r.origin[0]) \times r.dir\_inv[0]$$
    Initialize $t_{min} = \min(t_1, t_2)$ and $t_{max} = \max(t_1, t_2)$ [S2, unofficial].
3.  **Loop Over Remaining Dimensions (1 to 2):** For each dimension $i$:
    a. Compute slab intersections:
    $$t_1 = (b.min[i] - r.origin[i]) \times r.dir\_inv[i]$$
    $$t_2 = (b.max[i] - r.origin[i]) \times r.dir\_inv[i]$$
    b. Update $t_{min}$ to suppress NaNs:
    $$t_{min} = \max(t_{min}, \min(\min(t_1, t_2), t_{max}))$$ [S2, unofficial]
    c. Update $t_{max}$ to suppress NaNs:
    $$t_{max} = \min(t_{max}, \max(\max(t_1, t_2), t_{min}))$$ [S2, unofficial]
    The nested min/max operations ensure that if $t_1$ or $t_2$ is NaN, the current slab's contribution is ignored by propagating the existing valid $t_{min}$ or $t_{max}$ [S2, unofficial].
4.  **Compute Side Normals (Optional but included in source [S1, unofficial]):**
    a. Determine side vectors based on direction sign:
    $$leftSide = center + isPositive \cdot minSize + isNegative \cdot maxSize$$
    $$rightSide = center + isPositive \cdot maxSize + isNegative \cdot minSize$$ [S1, unofficial]
    b. Compute time vectors:
    $$leftTimes = (leftSide - origin) \times dir\_inv$$
    $$rightTimes = (rightSide - origin) \times dir\_inv$$ [S1, unofficial]
    c. Identify faces:
    $$sideMin = (leftTimes == t_{min}) \cdot sign(dir\_inv)$$
    $$sideMax = (rightTimes == t_{max}) \cdot sign(dir\_inv)$$ [S1, unofficial]
    The sign multiplication ensures correct face orientation relative to the viewer [S1, unofficial].
5.  **Return Result:**
    Return `true` if $t_{max} \ge \max(t_{min}, 0.0)$, else `false` [S2, unofficial]. The use of $\ge$ handles degenerate boxes (zero thickness) and floating-point precision edge cases where $t_{max} == t_{min}$ [S2, unofficial].

**Pseudocode:**
```python
def ray_aabb_intersect_branchless_nan_safe(origin, dir, box_min, box_max):
    # Precompute inverse direction
    dir_inv = [1.0 / d if d != 0.0 else (1.0 / d) for d in dir] # Handles 0 -> inf
    
    # Initialize with first dimension (i=0)
    t1 = (box_min[0] - origin[0]) * dir_inv[0]
    t2 = (box_max[0] - origin[0]) * dir_inv[0]
    
    t_min = min(t1, t2)
    t_max = max(t1, t2)
    
    # Loop over dimensions 1 and 2
    for i in range(1, 3):
        t1 = (box_min[i] - origin[i]) * dir_inv[i]
        t2 = (box_max[i] - origin[i]) * dir_inv[i]
        
        # NaN suppression logic
        # min(min(t1, t2), t_max) ensures if t1/t2 is NaN, t_max is preserved
        # max(t_min, ...) ensures if result is NaN, t_min is preserved
        t_min = max(t_min, min(min(t1, t2), t_max))
        t_max = min(t_max, max(max(t1, t2), t_min))
        
    # Check for valid intersection
    # Use >= to handle degenerate boxes and precision issues [S2, unofficial]
    hit = t_max >= max(t_min, 0.0)
    
    # Optional: Compute side normals as per [S1, unofficial]
    # This part is not strictly required for simple hit testing but provides face info
    center = [(box_min[j] + box_max[j]) * 0.5 for j in range(3)]
    min_size = [(box_max[j] - box_min[j]) * 0.5 for j in range(3)]
    
    is_positive = [1.0 if d > 0 else 0.0 for d in dir_inv]
    is_negative = [1.0 - p for p in is_positive]
    
    left_side = [center[j] + is_positive[j] * min_size[j] + is_negative[j] * box_max[j] for j in range(3)]
    right_side = [center[j] + is_positive[j] * box_max[j] + is_negative[j] * min_size[j] for j in range(3)]
    
    left_times = [(left_side[j] - origin[j]) * dir_inv[j] for j in range(3)]
    right_times = [(right_side[j] - origin[j]) * dir_inv[j] for j in range(3)]
    
    sign_dir_inv = [1.0 if d > 0 else (-1.0 if d < 0 else 0.0) for d in dir_inv]
    
    side_min = [1.0 if left_times[j] == t_min else 0.0 for j in range(3)]
    side_max = [1.0 if right_times[j] == t_max else 0.0 for j in range(3)]
    
    side_min = [side_min[j] * sign_dir_inv[j] for j in range(3)]
    side_max = [side_max[j] * sign_dir_inv[j] for j in range(3)]
    
    return hit, t_min, t_max, side_min, side_max
```

**Parameters:**
- No tunable parameters. The algorithm relies on standard IEEE 754 floating-point behavior [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Zero Direction Component:** If `dir[i]` is 0, `dir_inv[i]` is $\pm \infty$. If the ray origin is inside the box in that dimension, $t_1$ and $t_2$ become $\pm \infty$. The NaN suppression logic handles this by ignoring the invalid slab [S2, unofficial].
- **Ray on Boundary:** If the ray origin lies exactly on a slab boundary, $0 \times \infty$ produces NaN. The nested min/max operations suppress these NaNs [S2, unofficial].
- **Degenerate Boxes:** For boxes with zero thickness (e.g., planes), use `>=` instead of `>` in the final check to avoid false negatives due to precision errors [S2, unofficial].
- **Precision Errors:** The side normal calculation uses equality checks (`==`), which can be sensitive to floating-point errors. The sign compensation helps mitigate this [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per ray, with a constant number of arithmetic operations (unrolled loop for 3 dimensions).
- **Memory Complexity:** $O(1)$, requiring only a few temporary variables.
- **Performance:** On GCC 4.9.2 at -O3, the NaN-safe implementation handles approximately 93 million rays per second, taking around 30 clock cycles per ray without vectorization [S2, unofficial].
- **Scaling:** Performance is independent of scene complexity as it operates on a single primitive. Vectorization can improve throughput significantly.
- **Strengths:** Branchless execution improves pipeline efficiency. Robust handling of NaNs and infinities prevents visual artifacts and traversal errors in BVHs.
- **Limitations:** Approximately 30% slower than the fastest non-NaN-safe version (108 million rays/sec) due to extra min/max operations and handling of floating-point special cases [S2, unofficial].
- **When to Use:** Recommended for production ray tracers and BVH traversals where robustness is critical. The non-NaN-safe version may be acceptable in contexts where visual artifacts from degenerate cases are negligible or handled elsewhere [S2, unofficial].

## Background
The branchless approach originated with Brian Smits (1998) and was implemented by Amy Williams et al. (2005) [S2, unofficial]. The specific NaN handling workaround using nested min/max was applied by Thierry Berger-Perrin [S2, unofficial]. The algorithm is widely used in real-time ray tracing and BVH traversal due to its efficiency and robustness.
