# AABB Collision Detection
Also called: Axis-Aligned Bounding Box Collision, Axis-Separated AABB Collision, Sliding Collision, AABB Collision Sliding, Axis-Aligned Collision Sliding, Axis-Separated Movement AABB Collision

## Overview
AABB Collision Detection is a physics resolution method for voxel worlds that prevents entities (players, cameras, NPCs) from passing through solid blocks by separating movement into individual axis checks [S1, S2, S3, unofficial]. Unlike single-step displacement checks, this method applies velocity along one axis, tests for intersection with the voxel grid, and commits or cancels that movement before proceeding to the next axis, enabling "sliding" along walls [S1, S3, unofficial]. It is distinct from [Ray-box intersection](776-ray-box-intersection.md), which determines *if* a ray hits a box, by focusing on *resolving* continuous entity motion against discrete voxel geometry [S2, unofficial].

## How it works
**Inputs:**
- Entity position $P = (x, y, z)$, typically defined as the center of its AABB [S2, unofficial].
- Entity dimensions (half-extents or full width/height): $W, H, D$ [S2, S3, unofficial].
- Velocity or intended displacement vector $V = (v_x, v_y, v_z)$ [S2, S3, unofficial].
- Voxel world data structure (e.g., 2D/3D array `worldMap`) where `BlockID > 0` indicates solid terrain [S3, unofficial].

**Outputs:**
- Updated entity position $P'$ that respects collision constraints [S2, S3, unofficial].

**Data Structures:**
- **Voxel Grid:** A discrete array mapping integer coordinates to block types. Access is typically $O(1)$ [S1, S3, unofficial].
- **AABB:** Defined by center $P$ and half-dimensions $h_x, h_y, h_z$. For a camera, typical dimensions are $(0.8, 1.8, 0.8)$ or $(0.8, 1.8, 0.2)$ [S2, unofficial]. For a player, typical dimensions are Width $0.3$, Height $1.7$ [S3, unofficial].

**Steps:**
1. **Calculate Target Position:** Compute the hypothetical new position if no collisions occurred: $P_{target} = P + V$ [S2, unofficial].
2. **Compute Delta:** Calculate the displacement vector $\Delta = P_{target} - P$ [S2, unofficial].
3. **Axis-Separated Resolution:** Iterate through axes (typically X, then Z, then Y to handle gravity/jumping) [S3, unofficial]:
    a. **Apply Axis Movement:** Create a tentative position $P_{tentative}$ by adding only the current axis component of $\Delta$ to the current safe position $P_{safe}$ [S2, S3, unofficial].
    b. **Define AABB Bounds:** Calculate the voxel grid indices covered by the entity's AABB at $P_{tentative}$ [S2, unofficial]:
       $$min_i = \lfloor P_{tentative, i} - h_i \rfloor$$
       $$max_i = \lceil P_{tentative, i} + h_i \rceil$$
       where $i$ is the axis index (0, 1, 2) [S2, unofficial].
    c. **Collision Check:**
       - *Method A (Voxel Sweep):* Iterate through all voxels in the box defined by $min$ and $max$. If any voxel has `BlockID > 0`, a collision is detected [S2, S3, unofficial].
       - *Method B (Point Sampling):* Sample specific points on the entity's boundary (e.g., Feet, Waist, Head) against the voxel grid. If any point intersects a solid voxel, a collision is detected [S3, unofficial].
    d. **Resolve:**
       - If collision detected: Discard the movement for this axis. $P_{safe}$ remains unchanged for this axis.
       - If no collision: Update $P_{safe}$ with the new coordinate for this axis [S2, S3, unofficial].
4. **Final Position:** The resulting $P_{safe}$ is the new entity position [S2, S3, unofficial].

**Pseudocode:**
```python
def aabb_collision_detection(position, velocity, world, entity_dims):
    """
    position: tuple (x, y, z) - center of AABB
    velocity: tuple (vx, vy, vz) - intended movement
    world: function voxel(x, y, z) -> int (0 for air, >0 for solid)
    entity_dims: tuple (hx, hy, hz) - half-extents of AABB
    """
    # Step 1 & 2: Calculate target and delta
    target_x = position[0] + velocity[0]
    target_y = position[1] + velocity[1]
    target_z = position[2] + velocity[2]
    
    delta_x = target_x - position[0]
    delta_y = target_y - position[1]
    delta_z = target_z - position[2]
    
    # Current safe position starts as original position
    safe_x = position[0]
    safe_y = position[1]
    safe_z = position[2]
    
    # Step 3: Axis-Separated Resolution (Order: X, Z, Y)
    
    # X Axis
    tentative_x = safe_x + delta_x
    # Define voxel bounds for X movement
    min_x = floor(tentative_x - entity_dims[0])
    max_x = ceil(tentative_x + entity_dims[0])
    min_y = floor(safe_y - entity_dims[1])
    max_y = ceil(safe_y + entity_dims[1])
    min_z = floor(safe_z - entity_dims[2])
    max_z = ceil(safe_z + entity_dims[2])
    
    collided_x = False
    for x in range(min_x, max_x + 1):
        for y in range(min_y, max_y + 1):
            for z in range(min_z, max_z + 1):
                if world(x, y, z) > 0:
                    collided_x = True
                    break
            if collided_x: break
        if collided_x: break
        
    if not collided_x:
        safe_x = tentative_x
        
    # Z Axis
    tentative_z = safe_z + delta_z
    min_x = floor(safe_x - entity_dims[0])
    max_x = ceil(safe_x + entity_dims[0])
    min_y = floor(safe_y - entity_dims[1])
    max_y = ceil(safe_y + entity_dims[1])
    min_z = floor(tentative_z - entity_dims[2])
    max_z = ceil(tentative_z + entity_dims[2])
    
    collided_z = False
    for x in range(min_x, max_x + 1):
        for y in range(min_y, max_y + 1):
            for z in range(min_z, max_z + 1):
                if world(x, y, z) > 0:
                    collided_z = True
                    break
            if collided_z: break
        if collided_z: break
        
    if not collided_z:
        safe_z = tentative_z
        
    # Y Axis (Gravity/Jump)
    tentative_y = safe_y + delta_y
    min_x = floor(safe_x - entity_dims[0])
    max_x = ceil(safe_x + entity_dims[0])
    min_y = floor(tentative_y - entity_dims[1])
    max_y = ceil(tentative_y + entity_dims[1])
    min_z = floor(safe_z - entity_dims[2])
    max_z = ceil(safe_z + entity_dims[2])
    
    collided_y = False
    for x in range(min_x, max_x + 1):
        for y in range(min_y, max_y + 1):
            for z in range(min_z, max_z + 1):
                if world(x, y, z) > 0:
                    collided_y = True
                    break
            if collided_y: break
        if collided_y: break
        
    if not collided_y:
        safe_y = tentative_y
        
    return (safe_x, safe_y, safe_z)
```

**Parameters:**
- **Gravity:** Typically $18.0$ units/s² [S3, unofficial].
- **Jump Force:** Typically $8.0$ units/s [S3, unofficial].
- **Player Dimensions:** Width $0.3$, Height $1.7$ [S3, unofficial].
- **Camera Dimensions:** $(0.8, 1.8, 0.8)$ or $(0.8, 1.8, 0.2)$ [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Stuck Bug:** Checking collision against the *current* cell (before moving) causes permanent sticking if the player starts inside a wall or moves into one [S1, unofficial]. The solution is to check the *next* cell (the target position) [S1, unofficial].
- **Corner Penetration:** Simple axis checks may allow corners to penetrate walls slightly if the step size is large, leading to "entombment" in doors or walls [S4, unofficial]. This can be mitigated by testing all four corners of the AABB on both axis moves [S4, unofficial].

## Subtopics

### BoxClear Corner Check
A variant of AABB Collision Detection that tests all four corners of the player box on both axis moves to prevent overlap [S4, unofficial]. It asserts that no corner ever enters a solid cell and ensures that pulling away from a wall works from the pressed position, solving the "entombment" bug where simple axis checks fail to escape narrow gaps [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the AABB's bounding box. For small entities in dense grids, this is small but constant per frame.
- **Memory Complexity:** $O(1)$ auxiliary space, assuming the voxel grid is accessed directly.
- **Strengths:** Simple to implement; allows smooth sliding along walls; prevents tunneling through thin walls if step sizes are small [S1, S3, unofficial].
- **Limitations:** Can be computationally expensive if the AABB is large or the voxel grid is sparse but the AABB covers many empty voxels; prone to "stuck" bugs if not implemented with next-cell checks [S1, unofficial]; may require corner checks for robustness in narrow passages [S4, unofficial].
- **When to Use:** Voxel-based games, simple physics engines, real-time applications where performance is critical and geometry is discrete [S2, S3, unofficial].
- **When Not to Use:** Continuous physics with complex curved surfaces; scenes with large static objects where broad-phase culling is more appropriate.

## Background
Originating from early raycasting engines and voxel games, AABB collision detection became a standard technique for player movement in 3D environments with grid-based worlds [S1, S2, S3, unofficial]. It was popularized by games like Wolfenstein 3D and Minecraft clones, where simple, fast, and predictable collision resolution was essential for gameplay [S1, S3, unofficial]. The method is often cited in tutorials for building voxel engines from scratch [S2, S3, unofficial].
