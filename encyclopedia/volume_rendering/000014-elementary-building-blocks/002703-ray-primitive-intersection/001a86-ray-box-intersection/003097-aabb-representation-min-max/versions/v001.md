# AABB Representation (Min/Max)
Also called: AABB Data Structure, Axis-Aligned Bounding Box data structure, Min/Max corners, Slab representation

## Overview
The Min/Max AABB representation defines an axis-aligned bounding box by explicitly storing the minimum and maximum coordinate values along each of the three spatial axes. It treats the box as the intersection of three orthogonal "slabs" (infinite regions bounded by parallel planes). This representation is preferred over point-plus-dimensions (centroid + size) because merging two boxes is a trivial component-wise min/max operation, whereas the latter requires extra arithmetic [S1, unofficial].

## How it works
**Inputs:** None for the structure definition; constructor inputs vary by variant.
**Outputs:** An AABB object containing boundary coordinates.

**Data Structures:**
The representation occupies 6 floating-point values. Two common layouts are cited:

1.  **Array-based (Slab) Layout:**
    Three arrays of two floats each.
    *   `x_minmax[2]`: `x_min` at index 0, `x_max` at index 1.
    *   `y_minmax[2]`: `y_min` at index 0, `y_max` at index 1.
    *   `z_minmax[2]`: `z_min` at index 0, `z_max` at index 1.
    *   Total size: 6 floats [S1, unofficial].

2.  **Vector-based Layout:**
    Two 3D vectors.
    *   `lb` (lower bound): `(x_min, y_min, z_min)`.
    *   `ub` (upper bound): `(x_max, y_max, z_max)`.
    *   Total size: 6 floats [S2, unofficial].

**Constructors:**
Common initialization methods include:
1.  **Default:** Initializes with undefined or extreme values.
2.  **From Coordinates:** Directly sets `lb` and `ub` from `(lb_x, lb_y, lb_z, ub_x, ub_y, ub_z)`.
3.  **From Sphere:** Computes the bounding box for a sphere defined by center `pos` and `radius`.
4.  **From Triangle:** Computes the bounding box enclosing vertices `v1`, `v2`, `v3`.
5.  **Merge:** Computes the bounding box enclosing two existing AABBs [S2, unofficial].

**Merging Logic:**
To compute the bounding box enclosing two AABBs ($b_0$ and $b_1$), the new bounds are calculated component-wise:
$$
\begin{aligned}
x_{min} &= \min(b_0.x_{min}, b_1.x_{min}) \\
x_{max} &= \max(b_0.x_{max}, b_1.x_{max}) \\
y_{min} &= \min(b_0.y_{min}, b_1.y_{min}) \\
y_{max} &= \max(b_0.y_{max}, b_1.y_{max}) \\
z_{min} &= \min(b_0.z_{min}, b_1.z_{min}) \\
z_{max} &= \max(b_0.z_{max}, b_1.z_{max})
\end{aligned}
$$
This is significantly simpler than the point-plus-dimensions representation, which requires recalculating the centroid and dimensions from the combined extents [S1, unofficial].

**Pseudocode:**
```python
import math

class AABB:
    def __init__(self, lb=None, ub=None):
        """
        Initialize AABB with lower bound (lb) and upper bound (ub).
        Each is a tuple/list of 3 floats (x, y, z).
        """
        if lb is None or ub is None:
            # Default constructor: initialize to empty/infinite bounds
            # [G] Implementation detail: typically set to +inf/-inf or handled via a flag.
            # For this example, we assume valid bounds are always provided or set explicitly.
            self.lb = [0.0, 0.0, 0.0]
            self.ub = [0.0, 0.0, 0.0]
        else:
            self.lb = list(lb)
            self.ub = list(ub)

    @classmethod
    def from_sphere(cls, center, radius):
        """Construct AABB from a sphere defined by center (x,y,z) and radius."""
        lb = [center[0] - radius, center[1] - radius, center[2] - radius]
        ub = [center[0] + radius, center[1] + radius, center[2] + radius]
        return cls(lb=lb, ub=ub)

    @classmethod
    def from_triangle(cls, v1, v2, v3):
        """Construct AABB enclosing three vertices."""
        # [G] Compute min/max across all 3 vertices for each axis.
        x_vals = [v1[0], v2[0], v3[0]]
        y_vals = [v1[1], v2[1], v3[1]]
        z_vals = [v1[2], v2[2], v3[2]]
        
        lb = [min(x_vals), min(y_vals), min(z_vals)]
        ub = [max(x_vals), max(y_vals), max(z_vals)]
        return cls(lb=lb, ub=ub)

    @classmethod
    def merge(cls, a, b):
        """Compute the AABB enclosing both AABB 'a' and 'b'."""
        lb = [
            min(a.lb[0], b.lb[0]),
            min(a.lb[1], b.lb[1]),
            min(a.lb[2], b.lb[2])
        ]
        ub = [
            max(a.ub[0], b.ub[0]),
            max(a.ub[1], b.ub[1]),
            max(a.ub[2], b.ub[2])
        ]
        return cls(lb=lb, ub=ub)

    def contains_point(self, p):
        """Check if point p is inside the AABB."""
        return (self.lb[0] <= p[0] <= self.ub[0] and
                self.lb[1] <= p[1] <= self.ub[1] and
                self.lb[2] <= p[2] <= self.ub[2])
```

**Edge Cases and Pitfalls:**
*   **Degenerate Boxes:** If $min > max$ for any axis, the box is invalid. Merging logic must ensure that if one box is empty, the result is the other box, or handle empty sets explicitly.
*   **Precision:** Floating-point comparisons for containment or intersection should account for epsilon errors if exact boundaries are critical [G].
*   **Axis Alignment:** The representation assumes the box is axis-aligned. If the box is rotated, this representation is invalid; an OBB (Oriented Bounding Box) representation is required instead.

## Operating characteristics
*   **Memory:** Fixed size of 6 floats (24 bytes on standard 32-bit float systems) [S1, S2, unofficial].
*   **Time Complexity:** Merging two AABBs is $O(1)$ with 6 comparisons and 6 assignments [S1, unofficial].
*   **Strengths:** Extremely fast to merge, simple to implement, and directly compatible with slab-based ray-box intersection algorithms [S1, unofficial].
*   **Limitations:** Does not support rotation. For rotated objects, the AABB must be recomputed or an OBB used.

## Background
The Min/Max representation is a standard data structure in computer graphics, particularly in ray tracing and spatial acceleration structures. It is explicitly used in Peter Shirley's raytracing series [S1, unofficial]. It serves as the foundational primitive for the Ray-box intersection method, where the box is treated as the intersection of three slabs [S1, Parent, unofficial].
