# Unsigned Triangle Distance
Also called: Unsigned Triangle, udTriangle
## Overview
Computes the unsigned distance from a query point to a triangle defined by three vertices $a, b, c$ [S1, unofficial]. It checks if the point is inside the projected triangle to decide between edge distance and plane distance [S1, unofficial].
## How it works
**Inputs:**
- `p`: Query point (`vec3`) [S1, unofficial].
- `a, b, c`: Triangle vertices (`vec3`) [S1, unofficial].

**Outputs:**
- `d`: Unsigned distance (`float`) [S1, unofficial].

**Data Structures:**
- Intermediate vectors `ba`, `pa`, `cb`, `pb`, `ac`, `pc`, `nor` (all `vec3`) [S1, unofficial].
- Scalar `inside` (boolean) [G].

**Steps:**
1. Compute edge vectors and point-to-vertex vectors:
   $$ba = b - a, \quad pa = p - a$$
   $$cb = c - b, \quad pb = p - b$$
   $$ac = a - c, \quad pc = p - c$$ [S1, unofficial].
2. Compute the triangle normal:
   $$nor = ba \times ac$$ [S1, unofficial].
3. Determine if the point projects inside the triangle by checking the sign of the cross products of each edge with the normal against the corresponding point vector:
   $$inside = (\text{sign}(\text{dot}(ba \times nor, pa)) + \text{sign}(\text{dot}(cb \times nor, pb)) + \text{sign}(\text{dot}(ac \times nor, pc)) < 2.0)$$ [S1, unofficial].
4. If inside, compute the minimum squared distance to the three edges. For each edge (e.g., $ba$), project $pa$ onto $ba$ clamped to $[0, 1]$:
   $$proj = ba \cdot \text{clamp}\left(\frac{ba \cdot pa}{\|ba\|^2}, 0.0, 1.0\right)$$
   $$dist^2 = \|proj - pa\|^2$$ [S1, unofficial].
5. If not inside, compute the squared distance to the plane containing the triangle:
   $$dist^2 = \frac{(nor \cdot pa)^2}{\|nor\|^2}$$ [S1, unofficial].
6. Return $\sqrt{dist^2}$ [S1, unofficial].

**Pseudocode:**
```python
import math

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def cross(v1, v2):
    return (v1[1]*v2[2] - v1[2]*v2[1],
            v1[2]*v2[0] - v1[0]*v2[2],
            v1[0]*v2[1] - v1[1]*v2[0])

def clamp(x, lo, hi):
    return max(lo, min(hi, x))

def sign(x):
    return 1 if x > 0 else (-1 if x < 0 else 0)

def dot2(v):
    return dot(v, v)

def udTriangle(p, a, b, c):
    ba = (b[0]-a[0], b[1]-a[1], b[2]-a[2])
    pa = (p[0]-a[0], p[1]-a[1], p[2]-a[2])
    cb = (c[0]-b[0], c[1]-b[1], c[2]-b[2])
    pb = (p[0]-b[0], p[1]-b[1], p[2]-b[2])
    ac = (a[0]-c[0], a[1]-c[1], a[2]-c[2])
    pc = (p[0]-c[0], p[1]-c[1], p[2]-c[2])
    nor = cross(ba, ac)

    s1 = sign(dot(cross(ba, nor), pa))
    s2 = sign(dot(cross(cb, nor), pb))
    s3 = sign(dot(cross(ac, nor), pc))

    inside = (s1 + s2 + s3) < 2.0

    if inside:
        proj_ba = (ba[0]*clamp(dot(ba, pa)/dot2(ba), 0.0, 1.0),
                   ba[1]*clamp(dot(ba, pa)/dot2(ba), 0.0, 1.0),
                   ba[2]*clamp(dot(ba, pa)/dot2(ba), 0.0, 1.0))
        dist_ba = dot2((proj_ba[0]-pa[0], proj_ba[1]-pa[1], proj_ba[2]-pa[2]))

        proj_cb = (cb[0]*clamp(dot(cb, pb)/dot2(cb), 0.0, 1.0),
                   cb[1]*clamp(dot(cb, pb)/dot2(cb), 0.0, 1.0),
                   cb[2]*clamp(dot(cb, pb)/dot2(cb), 0.0, 1.0))
        dist_cb = dot2((proj_cb[0]-pb[0], proj_cb[1]-pb[1], proj_cb[2]-pb[2]))

        proj_ac = (ac[0]*clamp(dot(ac, pc)/dot2(ac), 0.0, 1.0),
                   ac[1]*clamp(dot(ac, pc)/dot2(ac), 0.0, 1.0),
                   ac[2]*clamp(dot(ac, pc)/dot2(ac), 0.0, 1.0))
        dist_ac = dot2((proj_ac[0]-pc[0], proj_ac[1]-pc[1], proj_ac[2]-pc[2]))

        return math.sqrt(min(dist_ba, min(dist_cb, dist_ac)))
    else:
        return math.sqrt(dot(nor, pa)*dot(nor, pa) / dot2(nor))
```

**Parameters:**
- `a, b, c`: `vec3`. Vertices of the triangle [S1, unofficial]. Order does not affect unsigned distance magnitude, but affects normal direction (used only for the inside check logic which is robust to winding) [G].

**Edge Cases:**
- **Degenerate Triangle:** If $a, b, c$ are collinear, $nor$ is zero. `dot2(nor)` becomes 0, causing division by zero in the plane distance case. Not given in the sources. [G] A guard should check `dot2(nor) < epsilon` and fallback to point-to-segment distance on the longest edge.
- **Point on Plane:** If the point lies on the plane but outside the triangle, the plane distance is 0. This is correct [S1, unofficial].
- **Precision:** Clamping prevents extrapolation errors on edges [G].

## Subtopics

### [Triangle Circum-Center Calculation](7233-triangle-circum-center-calculation.md)
Computes the center and radius of the unique circle passing through three non-collinear vertices $a, b, c$ of a triangle. This method is primarily used in volume rendering to define the bounding sphere (splat) for triangle-based leaf nodes, as described in [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md). It is distinguished by its formulation using vector cross products and coordinate differences, which minimizes numerical error for vertices far from the origin, and by a specific fallback strategy for obtuse triangles.

## Operating characteristics
- **Time Complexity:** $O(1)$. Fixed number of vector operations [G].
- **Memory Complexity:** $O(1)$. No dynamic allocation [G].
- **Strengths:** Robust handling of edge/vertex proximity without explicit case branching for barycentric coordinates [G]. Fast execution suitable for ray marching [G].
- **Limitations:** Does not provide signed distance (orientation) [S1, unofficial]. Degenerate triangles cause division by zero [G].
- **When to use:** When only magnitude of distance is needed, e.g., for blending or collision response [G].
- **When not to use:** When surface normal orientation is required (use Signed Triangle Distance) [G].

## Background
Originated in the GLSL SDF primitives library by Marklundin [S1, unofficial]. It is a standard primitive in ray marching and distance field rendering [G].
