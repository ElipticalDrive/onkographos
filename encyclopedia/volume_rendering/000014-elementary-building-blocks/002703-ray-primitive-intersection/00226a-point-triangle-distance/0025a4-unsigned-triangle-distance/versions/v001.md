# Unsigned Triangle Distance

Also called: Unsigned Triangle, udTriangle

## Overview
Computes the unsigned Euclidean distance from a 3D point to a triangle defined by three vertices. It distinguishes between the interior region (projecting onto the triangle plane) and the exterior region (projecting onto the triangle edges), returning the minimum squared distance in both cases before taking the square root. It differs from [Point-Triangle Distance](2776-point-triangle-distance.md) by explicitly handling the barycentric sign checks to determine the projection domain, and from [Mesh SDF Sampling](7159-mesh-sdf-sampling.md) by providing a closed-form analytical solution rather than an iterative or sampled approximation.

## How it works
**Inputs:**
- $p$: The query point ($\mathbb{R}^3$).
- $a, b, c$: The three vertices of the triangle ($\mathbb{R}^3$).

**Outputs:**
- $d$: The unsigned Euclidean distance from $p$ to the triangle.

**Data Structures:**
- Vectors are 3-component floating-point arrays.
- No persistent data structures; computation is stateless.

**Steps:**
1. Compute edge vectors and vectors from vertices to the point:
   $$ba = b - a, \quad pa = p - a$$
   $$cb = c - b, \quad pb = p - b$$
   $$ac = a - c, \quad pc = p - c$$
2. Compute the triangle normal:
   $$nor = ba \times ac$$
3. Determine if the point projects into the triangle's interior by checking the signs of the cross products relative to the normal. The point is considered "inside" the projected triangle if the sum of the signs of these dot products is less than 2.0:
   $$inside = \text{sign}(\text{dot}(ba \times nor, pa)) + \text{sign}(\text{dot}(cb \times nor, pb)) + \text{sign}(\text{dot}(ac \times nor, pc)) < 2.0$$
   *Note: This logic relies on the winding order and the fact that for a point inside, the cross products with edges will have consistent signs relative to the normal, or zero. The threshold `< 2.0` effectively captures the interior case where not all signs are positive (assuming consistent winding).*
4. If inside, compute the squared distance to the three edges. For each edge (e.g., $ba$), project the vector from the start vertex to the point ($pa$) onto the edge vector, clamping the parameter $t$ to $[0, 1]$:
   $$t = \text{clamp}\left(\frac{ba \cdot pa}{\|ba\|^2}, 0, 1\right)$$
   The closest point on the edge is $a + t \cdot ba$. The squared distance is:
   $$d_{edge}^2 = \| (a + t \cdot ba) - p \|^2 = \| ba \cdot t - pa \|^2$$
   Compute this for all three edges and take the minimum.
5. If outside, compute the squared distance to the plane containing the triangle:
   $$d_{plane}^2 = \frac{(nor \cdot pa)^2}{\|nor\|^2}$$
6. Return the square root of the minimum squared distance found in steps 4 or 5.

**Pseudocode:**
```python
def dot2(v):
    return v[0]*v[0] + v[1]*v[1] + v[2]*v[2]

def udTriangle(p, a, b, c):
    ba = [b[0]-a[0], b[1]-a[1], b[2]-a[2]]
    pa = [p[0]-a[0], p[1]-a[1], p[2]-a[2]]
    
    cb = [c[0]-b[0], c[1]-b[1], c[2]-b[2]]
    pb = [p[0]-b[0], p[1]-b[1], p[2]-b[2]]
    
    ac = [a[0]-c[0], a[1]-c[1], a[2]-c[2]]
    pc = [p[0]-c[0], p[1]-c[1], p[2]-c[2]]
    
    nor = cross(ba, ac)
    
    # Check if point is inside the projected triangle
    # sign() returns -1, 0, or 1
    s1 = sign(dot(cross(ba, nor), pa))
    s2 = sign(dot(cross(cb, nor), pb))
    s3 = sign(dot(cross(ac, nor), pc))
    
    inside = (s1 + s2 + s3) < 2.0
    
    if inside:
        # Distance to edges
        # Edge ba
        dot_ba_ba = dot2(ba)
        if dot_ba_ba == 0:
            dist_ba_sq = dot2(pa) # Degenerate edge, distance to vertex a
        else:
            t = clamp(dot(ba, pa) / dot_ba_ba, 0.0, 1.0)
            proj_ba = [ba[0]*t - pa[0], ba[1]*t - pa[1], ba[2]*t - pa[2]]
            dist_ba_sq = dot2(proj_ba)
            
        # Edge cb
        dot_cb_cb = dot2(cb)
        if dot_cb_cb == 0:
            dist_cb_sq = dot2(pb)
        else:
            t = clamp(dot(cb, pb) / dot_cb_cb, 0.0, 1.0)
            proj_cb = [cb[0]*t - pb[0], cb[1]*t - pb[1], cb[2]*t - pb[2]]
            dist_cb_sq = dot2(proj_cb)
            
        # Edge ac
        dot_ac_ac = dot2(ac)
        if dot_ac_ac == 0:
            dist_ac_sq = dot2(pc)
        else:
            t = clamp(dot(ac, pc) / dot_ac_ac, 0.0, 1.0)
            proj_ac = [ac[0]*t - pc[0], ac[1]*t - pc[1], ac[2]*t - pc[2]]
            dist_ac_sq = dot2(proj_ac)
            
        min_sq = min(dist_ba_sq, min(dist_cb_sq, dist_ac_sq))
    else:
        # Distance to plane
        dot_nor_nor = dot2(nor)
        if dot_nor_nor == 0:
            # Degenerate triangle (area 0), fallback to min distance to vertices
            # [G] Standard SDF primitives often assume non-degenerate input.
            # Here we compute distance to the closest vertex.
            dist_a_sq = dot2(pa)
            dist_b_sq = dot2(pb) # Note: pb is p-b, but we need p-a relative to b? 
                                 # Actually pb is p-b. Distance to b is |p-b|.
            dist_c_sq = dot2(pc)
            min_sq = min(dist_a_sq, min(dist_b_sq, dist_c_sq))
        else:
            dist_plane_sq = (dot(nor, pa) ** 2) / dot_nor_nor
            min_sq = dist_plane_sq
            
    return sqrt(min_sq)

def cross(u, v):
    return [u[1]*v[2] - u[2]*v[1],
            u[2]*v[0] - u[0]*v[2],
            u[0]*v[1] - u[1]*v[0]]

def dot(u, v):
    return u[0]*v[0] + u[1]*v[1] + u[2]*v[2]

def sign(x):
    if x > 0: return 1.0
    elif x < 0: return -1.0
    else: return 0.0

def clamp(x, min_val, max_val):
    if x < min_val: return min_val
    if x > max_val: return max_val
    return x
```

**Parameters:**
- $a, b, c$: Vertices of the triangle. No specific typical values, but they should form a non-degenerate triangle for optimal performance and accuracy.

**Edge Cases and Pitfalls:**
- **Degenerate Triangles:** If the triangle has zero area (vertices are collinear), the normal $nor$ is zero. The plane distance formula divides by zero. The pseudocode handles this by falling back to vertex distances [G].
- **Precision:** The sign check relies on floating-point comparisons. Near the edges, numerical instability may cause the point to be classified as outside when it is geometrically inside, or vice versa. This may result in a slight discontinuity in the derivative of the distance function.
- **Winding Order:** The sign check assumes a consistent winding order for the triangle vertices. If the winding is inconsistent, the `inside` logic may fail.

## Subtopics

### Triangle Circum-Center Calculation
Used in tetrahedralization or mesh processing contexts (e.g., TetSplat) to derive leaf nodes from triangles. It computes the circum-center and circum-radius of a triangle. The circum-center relative to vertex $a$ is given by $m_{tri} = \frac{|c - a|^2 A(b, c) \times (b - a) + |b - a|^2 (c - a) \times A(b, c)}{2 |A(b, c)|^2}$, where $A(u, v) = (u - a) \times (v - a)$. The absolute center is $a + m_{tri}$ and the radius is $|m_{tri}|$. A pitfall is that the denominator vanishes when triangles are near degenerate (vertices are co-linear). For remaining obtuse triangles after degenerate removal, an approximation is to use the midpoint of the longest edge as the circum-center and half the edge length as the radius [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ constant time. Involves a fixed number of vector operations, dot products, and cross products.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Performance:** Very fast, suitable for real-time rendering and ray tracing. The square root operation is the most expensive part, but it is unavoidable for Euclidean distance.
- **Strengths:** Analytical solution, no iteration, robust for non-degenerate triangles.
- **Limitations:** Degenerate triangles require special handling. Numerical precision issues near edges.

## Background
The unsigned triangle distance function is a standard primitive in Signed Distance Field (SDF) libraries, popularized by shaders and GLSL utilities. It is widely used in ray marching and implicit surface rendering. The specific implementation details, such as the sign-based interior check, are found in community-maintained SDF primitive collections [S1, unofficial]. The related circum-center calculation is discussed in the context of volume rendering and mesh simplification in the TetSplat paper [S2, unofficial].
