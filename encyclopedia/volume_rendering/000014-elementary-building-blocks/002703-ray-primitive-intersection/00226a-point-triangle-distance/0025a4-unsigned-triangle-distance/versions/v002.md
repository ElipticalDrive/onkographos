# Unsigned Triangle Distance
Also called: Unsigned Triangle, udTriangle
## Overview
Computes the unsigned Euclidean distance from a query point to a triangle defined by three vertices. It distinguishes itself from signed variants by returning a non-negative scalar, making it suitable for distance field blending and collision detection where orientation is irrelevant. It builds on [Point-Triangle Distance](2776-point-triangle-distance.md) by simplifying the output to magnitude only, while maintaining robustness for edge and vertex cases via projection logic.
## How it works
**Inputs:**
- `p`: Query point (`vec3`).
- `a, b, c`: Triangle vertices (`vec3`).

**Outputs:**
- `d`: Unsigned distance (`float`).

**Data Structures:**
- Intermediate vectors `ba`, `pa`, `cb`, `pb`, `ac`, `pc`, `nor` (all `vec3`).
- Scalar `inside` (boolean).

**Steps:**
1. Compute edge vectors and point-to-vertex vectors:
   $$ba = b - a, \quad pa = p - a$$
   $$cb = c - b, \quad pb = p - b$$
   $$ac = a - c, \quad pc = p - c$$
2. Compute the triangle normal:
   $$nor = ba \times ac$$
3. Determine if the point projects inside the triangle. This is done by checking the sign of the cross products of each edge with the normal against the corresponding point vector. If the sum of the signs is less than 2.0, the point is considered "inside" the infinite prism of the triangle (projected onto the plane):
   $$inside = (\text{sign}(\text{dot}(ba \times nor, pa)) + \text{sign}(\text{dot}(cb \times nor, pb)) + \text{sign}(\text{dot}(ac \times nor, pc)) < 2.0)$$
   [G] Note: `sign(0)` is typically 0. If the point lies exactly on an edge or vertex, the sum may be less than 2.0, directing the logic to the edge distance calculation, which is correct.
4. If inside, compute the minimum squared distance to the three edges. For each edge (e.g., $ba$), project $pa$ onto $ba$ clamped to $[0, 1]$:
   $$proj = ba \cdot \text{clamp}\left(\frac{ba \cdot pa}{\|ba\|^2}, 0.0, 1.0\right)$$
   $$dist^2 = \|proj \cdot ba - pa\|^2$$
   Return the minimum of the squared distances for edges $ba$, $cb$, and $ac$.
5. If not inside, compute the squared distance to the plane containing the triangle:
   $$dist^2 = \frac{(nor \cdot pa)^2}{\|nor\|^2}$$
6. Return $\sqrt{dist^2}$.

**Pseudocode:**
```python
def dot2(v):
    return v.x * v.x + v.y * v.y + v.z * v.z

def udTriangle(p, a, b, c):
    ba = b - a
    pa = p - a
    cb = c - b
    pb = p - b
    ac = a - c
    pc = p - c
    nor = cross(ba, ac)

    # Check if point is inside the triangle's projected area
    # sign() returns 1 if > 0, -1 if < 0, 0 if == 0
    s1 = sign(dot(cross(ba, nor), pa))
    s2 = sign(dot(cross(cb, nor), pb))
    s3 = sign(dot(cross(ac, nor), pc))
    
    inside = (s1 + s2 + s3) < 2.0

    if inside:
        # Distance to edges
        # Edge ba
        proj_ba = ba * clamp(dot(ba, pa) / dot2(ba), 0.0, 1.0)
        dist_ba = dot2(proj_ba - pa)
        
        # Edge cb
        proj_cb = cb * clamp(dot(cb, pb) / dot2(cb), 0.0, 1.0)
        dist_cb = dot2(proj_cb - pb)
        
        # Edge ac
        proj_ac = ac * clamp(dot(ac, pc) / dot2(ac), 0.0, 1.0)
        dist_ac = dot2(proj_ac - pc)
        
        return sqrt(min(dist_ba, min(dist_cb, dist_ac)))
    else:
        # Distance to plane
        return sqrt(dot(nor, pa) * dot(nor, pa) / dot2(nor))
```

**Parameters:**
- `a, b, c`: `vec3`. Vertices of the triangle. Order does not affect unsigned distance magnitude, but affects normal direction (used only for the inside check logic which is robust to winding).

**Edge Cases:**
- **Degenerate Triangle:** If $a, b, c$ are collinear, $nor$ is zero. `dot2(nor)` becomes 0, causing division by zero in the plane distance case. [G] A guard should check `dot2(nor) < epsilon` and fallback to point-to-segment distance on the longest edge.
- **Point on Plane:** If the point lies on the plane but outside the triangle, the plane distance is 0. This is correct.
- **Precision:** Clamping prevents extrapolation errors on edges.

## Subtopics

### [Triangle Circum-Center Calculation](7233-triangle-circum-center-calculation.md)
Computes the center and radius of the unique circle passing through three non-collinear vertices $a, b, c$ of a triangle. This method is primarily used in volume rendering to define the bounding sphere (splat) for triangle-based leaf nodes, as described in [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md). It is distinguished by its formulation using vector cross products and coordinate differences, which minimizes numerical error for vertices far from the origin, and by a specific fallback strategy for obtuse triangles.

## Operating characteristics
- **Time Complexity:** $O(1)$. Fixed number of vector operations.
- **Memory Complexity:** $O(1)$. No dynamic allocation.
- **Strengths:** Robust handling of edge/vertex proximity without explicit case branching for barycentric coordinates. Fast execution suitable for ray marching.
- **Limitations:** Does not provide signed distance (orientation). Degenerate triangles cause division by zero.
- **When to use:** When only magnitude of distance is needed, e.g., for blending or collision response.
- **When not to use:** When surface normal orientation is required (use Signed Triangle Distance).

Originated in the GLSL SDF primitives library by Marklundin [S1, unofficial]. It is a standard primitive in ray marching and distance field rendering.
