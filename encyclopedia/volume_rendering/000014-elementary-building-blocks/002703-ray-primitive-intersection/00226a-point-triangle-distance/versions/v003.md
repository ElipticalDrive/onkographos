# Point-Triangle Distance

Also called: Closest Point on Triangle, Point to Triangle Distance, closestPointOnTriangleToPoint, pointToTriangleDistSqr

## Overview
Computes the closest point on a triangle to a query point and returns the squared distance, handling all edge and vertex cases via Voronoi-region decomposition [S1][S2, unofficial]. It differs from [Ray-primitive intersection](769-ray-primitive-intersection.md) by solving a static point-to-mesh query rather than a ray-scene traversal, and from [General Ray-Triangle Intersection (Plücker Coordinates)](909-general-ray-triangle-intersection-pl-cker-coordinates.md) by returning the geometric closest point rather than an intersection parameter [G].

## How it works
**Inputs:** Triangle vertices $v_0, v_1, v_2$ (3D vectors); query point $p$ (3D vector) [S1].
**Outputs:** Barycentric coordinates $t_0, t_1$ of the closest point relative to $v_0$, and the squared distance $d^2$ [S1].
**Data Structures:** No persistent structures; local scalar and vector variables [G].

**Steps:**
1.  Compute edge vectors: $e_0 = v_1 - v_0$, $e_1 = v_2 - v_0$ [S2, unofficial].
2.  Compute vector from vertex to point: $w = v_0 - p$ [S2, unofficial].
3.  Compute dot products:
    $$a = e_0 \cdot e_0$$
    $$b = e_0 \cdot e_1$$
    $$c = e_1 \cdot e_1$$
    $$d = e_0 \cdot w$$
    $$e = e_1 \cdot w$$ [S2, unofficial].
4.  Compute determinant and barycentric numerators:
    $$det = a \cdot c - b \cdot b$$
    $$s = b \cdot e - c \cdot d$$
    $$t = b \cdot d - a \cdot e$$ [S2, unofficial].
5.  Determine region based on $s + t$ relative to $det$:
    *   **Case 1: $s + t < det$** (Closest point is in the region of vertex $v_0$ or on an adjacent edge/face interior) [S2, unofficial].
        *   If $s < 0$ and $t < 0$:
            *   If $d < 0$: $s = \text{clamp}(-d/a, 0, 1)$, $t = 0$ [S2, unofficial].
            *   Else: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$ [S2, unofficial].
        *   Else if $s < 0$: $s = \text{clamp}(-d/a, 0, 1)$, $t = 0$ [S2, unofficial].
        *   Else if $t < 0$: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$ [S2, unofficial].
    *   **Case 2: $s + t \ge det$** (Closest point is outside the edge opposite $v_0$) [S2, unofficial].
        *   Compute $tmp_0 = b + d$, $tmp_1 = c + e$ [S2, unofficial].
        *   If $s < 0$:
            *   If $tmp_1 > tmp_0$: $s = \text{clamp}((tmp_1 - tmp_0) / (a - 2b + c), 0, 1)$, $t = 1 - s$ [S2, unofficial].
            *   Else: $s = 0$, $t = \text{clamp}(-e/c, 0, 1)$ [S2, unofficial].
        *   Else if $t < 0$:
            *   If $a + d > b + e$: $s = \text{clamp}((c + e - b - d) / (a - 2b + c), 0, 1)$, $t = 1 - s$ [S2, unofficial].
            *   Else: $s = \text{clamp}(-e/c, 0, 1)$, $t = 0$ [S2, unofficial].
6.  Compute closest point: $closest = v_0 + s \cdot e_0 + t \cdot e_1$ [S2, unofficial].
7.  Return squared distance: $d^2 = \|closest - p\|^2$ [S1].

**Pseudocode:**
```python
def point_to_triangle_dist_sqr(v0, v1, v2, p):
    # Edge vectors
    e0 = v1 - v0
    e1 = v2 - v0
    # Vector from v0 to p
    w = v0 - p
    
    # Dot products
    a = dot(e0, e0)
    b = dot(e0, e1)
    c = dot(e1, e1)
    d = dot(e0, w)
    e = dot(e1, w)
    
    # Determinant and barycentric coordinates
    det = a * c - b * b
    s = b * e - c * d
    t = b * d - a * e
    
    # Clamp function
    def clamp(val, min_val, max_val):
        return max(min_val, min(val, max_val))
    
    # Region checks
    if s + t < det:
        if s < 0 and t < 0:
            if d < 0:
                s = clamp(-d / a, 0, 1)
                t = 0
            else:
                s = 0
                t = clamp(-e / c, 0, 1)
        elif s < 0:
            s = clamp(-d / a, 0, 1)
            t = 0
        elif t < 0:
            s = 0
            t = clamp(-e / c, 0, 1)
    else:
        tmp0 = b + d
        tmp1 = c + e
        if s < 0:
            if tmp1 > tmp0:
                denom = a - 2 * b + c
                s = clamp((tmp1 - tmp0) / denom, 0, 1)
                t = 1 - s
            else:
                s = 0
                t = clamp(-e / c, 0, 1)
        elif t < 0:
            if a + d > b + e:
                denom = a - 2 * b + c
                s = clamp((c + e - b - d) / denom, 0, 1)
                t = 1 - s
            else:
                s = clamp(-e / c, 0, 1)
                t = 0
                
    # Closest point
    closest = v0 + s * e0 + t * e1
    
    # Squared distance
    return dot(closest - p, closest - p)
```

**Parameters:**
*   $v_0, v_1, v_2$: Triangle vertices [S1].
*   $p$: Query point [S1].
*   `Vec3T`: Any vector type supporting arithmetic and dot product [S1].

**Edge Cases:**
*   Degenerate triangles (zero area, collinear, or coincident vertices) are handled implicitly: the face-interior test fails, and the code falls through to the nearest edge or vertex result [S1].

## Subtopics

### [Unsigned Triangle Distance](3587-unsigned-triangle-distance.md)
Computes the unsigned Euclidean distance from a query point to a triangle defined by three vertices. It distinguishes itself from signed variants by returning a non-negative scalar, making it suitable for distance field blending and collision detection where orientation is irrelevant. It builds on [Point-Triangle Distance](2776-point-triangle-distance.md) by simplifying the output to magnitude only, while maintaining robustness for edge and vertex cases via projection logic. Choose it when orientation does not matter and only proximity magnitude is required.

### [Mesh SDF Sampling](7159-mesh-sdf-sampling.md)
Creates a signed distance sampler function from a `THREE.BufferGeometry` and a world transform matrix. Returns a function with signature `(x, y, z) => number` that computes the shortest signed distance to the mesh at world-space coordinate `(x, y, z)`. Negative values indicate the point is inside the mesh, positive values indicate it is outside. Choose it when integrating mesh-based SDF queries into WebGL/Three.js rendering pipelines.

### [Triangle-Box Intersection Voxelization](7408-triangle-box-intersection-voxelization.md)
A parallel C++ implementation that voxelizes watertight triangular meshes into Signed Distance Functions (SDFs) or occupancy grids. SDFs store the distance from a voxel reference point (corner or center) to the nearest mesh face, with negative signs for interior voxels. Occupancy grids identify voxels intersecting the mesh surface. Choose it when converting triangle meshes into voxel-based representations for volume rendering or collision acceleration.

### Unsigned Quadrilateral Distance
Computes the unsigned distance from a point to a quadrilateral defined by four vertices $a, b, c, d$ [S3, unofficial]. It checks if the point is inside the projected quad to decide between edge distance and plane distance [S3, unofficial]. If the point is inside the quad (sum of signs < 3), it returns the minimum squared distance to the four edges [S3, unofficial]. Otherwise, it returns the squared distance to the plane containing the quad [S3, unofficial]. Edge distance uses projection: $\text{proj}_{ba}(pa) = ba \cdot \text{clamp}(\frac{ba \cdot pa}{\|ba\|^2}, 0, 1)$ [S3, unofficial]. Parameters: $a, b, c, d$ are vec3 vertices in order [S3, unofficial].

## Operating characteristics
Time complexity is $O(1)$ with a constant number of arithmetic operations [G]. Memory complexity is $O(1)$ [G]. Performance is hardware-independent but sensitive to branch divergence in SIMD implementations due to the region checks [G]. Strengths include robustness to degenerate triangles and exact handling of edge/vertex cases [S1]. Limitations include lack of explicit normalization for degenerate edges, which may cause division by zero if not guarded [G]. Use for collision detection, point cloud fitting, and SDF generation [G]. Do not use for ray-triangle intersection where parameter $t$ along a ray is required [G].

## Background
Originated from Ericson's "Real-Time Collision Detection" (Sec. 5.1.5) [S1]. Implemented in OpenVDB's `nanovdb::math` namespace [S1] and referenced in voxelization implementations [S2, unofficial]. Used in volume rendering for point-to-mesh distance queries in SDF-based rendering and collision handling [G].
