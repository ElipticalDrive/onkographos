# Ray-primitive intersection

Also called: Ray-object intersection, Ray-scene intersection, Ray-primitive test

## Overview
Ray-primitive intersection determines whether a viewing ray intersects a geometric primitive (such as a triangle, sphere, or box) and computes the parametric distance $t$ to the intersection point. It solves the fundamental geometric query required for volume rendering traversal, occlusion culling, and surface reconstruction, serving as the atomic operation for all higher-level spatial acceleration structures. It is distinguished from sibling methods by its role as the generic interface for arbitrary geometry, often involving coordinate space transformations to local frames, whereas [Ray generation and camera models](770-ray-generation-and-camera-models.md) defines the rays and [Parallel and GPU primitives](771-parallel-and-gpu-primitives.md) handles the execution model.

## Shared principles
The shared principles of this family are the geometric definition of rays and the parallel execution model.

**Ray Definition**
Rays are defined by an origin $\mathbf{o}$ and a direction $\mathbf{d}$. The direction is typically normalized. The origin is often the camera eye position, but can vary based on the camera model.

**Parallel Execution**
Computations are mapped to parallel threads. Each thread typically processes one or more pixels or samples. Memory access patterns are optimized for coalescing. Synchronization is used to manage data dependencies between threads.

## Subtopics

### [Ray-box intersection](776-ray-box-intersection.md)
Determines intersection with axis-aligned bounding boxes using slab tests. Chosen for bounding volume hierarchy (BVH) traversal due to efficiency.

### [General Ray-Triangle Intersection (Plücker Coordinates)](909-general-ray-triangle-intersection-pl-cker-coordinates.md)
Uses Plücker coordinates to evaluate winding order. Chosen for robustness with arbitrary ray directions and avoidance of barycentric linear systems.

### [Ray Crossing Count (Winding Number)](915-ray-crossing-count-winding-number.md)
Computes signed intersections to determine point-in-mesh containment. Chosen for interior testing in algorithms like Marching Cubes.

### [Sphere Intersection](1620-sphere-intersection.md)
Analytical intersection for spherical primitives. Chosen for simple volumetric scenes and as a building block for complex density fields.

### [Ray-Box Intersection via OpenGL Geometry Shaders](1768-ray-box-intersection-via-opengl-geometry-shaders.md)
Computes entry/exit points using geometry shaders. Chosen for providing fragment shaders with precise texture coordinates without CPU-side calculations.

### [Triangle-AABB Intersection (Separating Axis Theorem)](2050-triangle-aabb-intersection-separating-axis-theorem.md)
Tests overlap between a triangle and AABB using SAT. Chosen for frustum culling and voxelization pruning, returning binary overlap rather than hit points.

### [Ray-Volume Intersection (Face Distance Method)](2381-ray-volume-intersection-face-distance-method.md)
Calculates distances to volume faces to find entry points. Chosen for culling rays that miss the volume entirely in volume traversal.

### [Ray-Tetrahedron Intersection](2525-ray-tetrahedron-intersection.md)
Intersects rays with tetrahedral cells. Chosen for unstructured grid rendering and tetrahedral mesh visualization.

### [Point-Triangle Distance](2776-point-triangle-distance.md)
Computes closest point on a triangle to a query point. Chosen for static point-to-mesh queries rather than ray traversal.

### [Implicit Surface and SDF Intersection](2795-implicit-surface-and-sdf-intersection.md)
Intersects rays with implicit surfaces defined by Signed Distance Functions. Chosen for smooth, continuous geometry representation.

### [Exact Rational Ray-Surfel Evaluation](2915-exact-rational-ray-surfel-evaluation.md)
Uses homography approximation for surfel intersection. Chosen for efficient rendering of Gaussian splats with reduced computational cost.

### [Spherical Panoramic Gaussian Splatting (SPaGS)](3042-spherical-panoramic-gaussian-splatting-spags.md)
Ray-splat intersection for spherical panoramas. Chosen for numerically stable rendering of 3D Gaussians on wide-field-of-view spherical projections.

### [Ray ID Caching](3110-ray-id-caching.md)
Caches ray-object intersection results to skip redundant tests. Chosen to eliminate redundant calculations when a ray intersects the same object multiple times.

### [IRIS Ray-Geometry Intersection](3250-iris-ray-geometry-intersection.md)
Uses proxy geometry (icosahedra) for Gaussian intersection. Chosen for efficient sampling of 3D Gaussians in ray-tracing pipelines using hardware-accelerated ray-triangle tests.

### [Ray-Sphere Intersection](3539-ray-sphere-intersection.md)
Solves quadratic equation for sphere intersection. Chosen as the fundamental primitive for spherical geometry and volume marching bounds.

### [Ray-Object Intersection Test](3604-ray-object-intersection-test.md)
Generic interface for finding the closest intersection with arbitrary objects. Chosen for general ray tracing where coordinate space transformations are required.

### [Azimuthal Hit Detection](3885-azimuthal-hit-detection.md)
Tests intersection with azimuthal sections in spherical voxel grids. Chosen for specialized traversal in spherical coordinate systems.

### [Ray-Polar Section Intersection](3886-ray-polar-section-intersection.md)
Tests intersection with polar sections in spherical voxel grids. Chosen for angular traversal steps in spherical volume data.

### [Ray-Cylinder Intersection](5014-ray-cylinder-intersection.md)
Computes entry/exit distances for cylindrical geometry. Chosen for handling curved lateral surfaces via quadratic solving.

### [Ray-Primitive and Segment Intersection](6230-ray-primitive-and-segment-intersection.md)
Handles intersection with line segments. Chosen for specific geometric queries involving linear primitives.

### [Ray-Plane/Rectangle Intersection](6498-ray-plane-rectangle-intersection.md)
Intersects rays with planes and rectangles. Chosen for basic planar geometry tests.

## Background
The classification of ray-object intersections into five classes based on intersection type, data type, and early termination capability was established in volumetric ray tracing literature [S3, unofficial]. Class 1 involves geometric data requiring a single intersection point, computed analytically. Classes 2-5 involve volumetric data, ranging from point intersections with early termination (Class 2) to segment intersections requiring all values for compositing (Class 5) [S3, unofficial]. The field has evolved to include specialized methods for modern rendering techniques, such as Gaussian Splatting [S1, S2, S5, S8, unofficial] and implicit surface rendering [S7, S8, unofficial], as well as hardware-accelerated approaches using OptiX [S1, unofficial] and OpenGL geometry shaders [S1, unofficial].
