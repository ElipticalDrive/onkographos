# Ray-Splat Intersection

Also called: Raycaster Splat Intersection, Raycaster.castRayAtSplatTreeNode, Raycaster.intersectSplatMesh

## Overview
Ray-Splat Intersection intersects a viewing ray against a hierarchical splat mesh to determine visible Gaussian splats for rendering. It supports both exact ellipsoid intersection and approximate sphere intersection, enabling efficient culling of non-visible splats in 3D Gaussian Splatting pipelines. It differs from sibling methods by operating on a tree-structured collection of oriented ellipsoids/spheres rather than static primitives or voxel grids.

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized).
- Camera parameters (projection matrix, view matrix, screen dimensions, near/far planes).
- Splat mesh data: hierarchical tree (`splatTree`) containing nodes with bounding boxes and leaf nodes containing splat indices.
- Splat attributes: center $\mathbf{c}$, scale $\mathbf{s}$, rotation (quaternion or matrix), color, alpha, and visibility flags.
- Boolean flag `raycastAgainstTrueSplatEllipsoid`.
- Render mode: `TwoD` or `ThreeD`.
- Scale epsilon threshold $\epsilon_{scale} = 10^{-7}$ [S1, unofficial].

**Outputs:**
- List of hit splats, sorted by distance from ray origin.

**Data Structures:**
- `SplatTreeNode`: Contains `boundingBox` (AABB), `indexes` (array of global splat indices), and child nodes.
- `Splat`: Contains `center` (vec3), `scale` (vec3), `rotation` (quat/mat3), `color` (vec3/vec4), `alpha` (float), `visible` (bool).

**Steps:**

1. **Ray Construction:**
   - Compute Normalized Device Coordinates (NDC) from screen position $(x, y)$ and screen dimensions $(w, h)$ [S1, unofficial]:
     $$
     ndc_x = \frac{x}{w} \cdot 2.0 - 1.0
     $$
     $$
     ndc_y = \frac{h - y}{h} \cdot 2.0 - 1.0
     $$
   - **Perspective Camera:**
     - Ray origin $\mathbf{o}$ is the camera world position.
     - Unproject NDC coordinates to world space to get a point $\mathbf{p}$ on the far plane (or arbitrary depth).
     - Ray direction $\mathbf{d} = \text{normalize}(\mathbf{p} - \mathbf{o})$ [S1, unofficial].
   - **Orthographic Camera:**
     - Ray origin $\mathbf{o}$ is obtained by unprojecting NDC coordinates with $z$ derived from:
       $$
       z_{ndc} = \frac{near + far}{near - far}
       $$
     - Ray direction $\mathbf{d}$ is the camera's forward vector $(0, 0, -1)$ transformed by the camera's world rotation matrix [S1, unofficial].

2. **Tree Traversal:**
   - For each subtree in `splatTree`:
     - Compute `fromLocal` (world matrix $\times$ scene transform if dynamic) and `toLocal` (inverse of `fromLocal`) [S1, unofficial].
     - Transform ray origin $\mathbf{o}$ and direction $\mathbf{d}$ to local space:
       $$
       \mathbf{o}_{local} = \text{toLocal} \cdot [\mathbf{o}, 1]
       $$
       $$
       \mathbf{d}_{local} = \text{toLocal} \cdot [\mathbf{d}, 0]
       $$
     - Call `castRayAtSplatTreeNode` with local ray, subtree root, and output hits array.

3. **Node Intersection (`castRayAtSplatTreeNode`):**
   - Check if ray intersects node bounding box. If not, return [S1, unofficial].
   - For each splat global index in `node.indexes`:
     - Retrieve splat data. Check visibility. If not visible, continue [S1, unofficial].
     - Check for degenerate splats: if any component of scale $\mathbf{s}$ is $\le \epsilon_{scale}$, skip [S1, unofficial].
     - **Intersection Test:**
       - If `raycastAgainstTrueSplatEllipsoid` is false:
         - Compute approximate radius $r$ [S1, unofficial]:
           - If `TwoD` mode:
             $$
             r = \frac{s_x + s_y}{2}
             $$
           - If `ThreeD` mode:
             $$
             r = \frac{s_x + s_y + s_z}{3}
             $$
         - Perform sphere intersection test with center $\mathbf{c}$ and radius $r$.
       - If `raycastAgainstTrueSplatEllipsoid` is true:
         - Perform exact ellipsoid intersection test using splat scale and rotation. (Note: Source [S1, unofficial] mentions support but does not provide the explicit formula for the true ellipsoid test in the provided notes. Implementers must derive this from standard quadratic form intersection or use the library's internal implementation [G]).

4. **Post-Processing:**
   - Transform hit origins and normals back to world space using `fromLocal` [S1, unofficial].
   - Compute distance $t = \|\mathbf{o} - \mathbf{o}_{hit}\|$ [S1, unofficial].
   - Sort all hits by distance ascending [S1, unofficial].

**Pseudocode:**

```python
def ray_splat_intersection(ray_origin, ray_direction, camera, splat_tree, raycast_ellipsoid, render_mode):
    # 1. Construct Ray
    if camera.is_perspective:
        ndc_x = (screen_x / screen_w) * 2.0 - 1.0
        ndc_y = (screen_h - screen_y) / screen_h * 2.0 - 1.0
        ray_origin = camera.world_position
        unprojected_point = unproject_ndc(ndc_x, ndc_y, camera.projection_matrix, camera.view_matrix)
        ray_direction = normalize(unprojected_point - ray_origin)
    else:
        z_ndc = (camera.near + camera.far) / (camera.near - camera.far)
        ray_origin = unproject_ndc_with_z(screen_x, screen_y, z_ndc, camera.projection_matrix, camera.view_matrix)
        ray_direction = normalize(camera.world_rotation * vec3(0, 0, -1))

    hits = []

    # 2. Traverse Tree
    for subtree in splat_tree.sub_trees:
        from_local = subtree.world_matrix * scene_transform # if dynamic
        to_local = inverse(from_local)

        local_origin = to_local * vec4(ray_origin, 1.0)
        local_direction = to_local * vec4(ray_direction, 0.0)

        cast_ray_at_node(local_origin, local_direction, subtree.root_node, hits, from_local, ray_origin)

    # 3. Sort Hits
    hits.sort(key=lambda h: h.distance)
    return hits

def cast_ray_at_node(origin, direction, node, hits, from_local, global_ray_origin):
    # Check bounding box
    if not ray_intersect_box(origin, direction, node.bounding_box):
        return

    for global_idx in node.indexes:
        splat = get_splat_data(global_idx)
        if not splat.visible:
            continue

        # Check degenerate splats
        if any(s <= 1e-7 for s in splat.scale):
            continue

        hit = None
        if not raycast_ellipsoid:
            # Approximate sphere
            if render_mode == TwoD:
                radius = (splat.scale.x + splat.scale.y) / 2.0
            else: # ThreeD
                radius = (splat.scale.x + splat.scale.y + splat.scale.z) / 3.0
            
            hit = sphere_intersection(origin, direction, splat.center, radius)
        else:
            # True ellipsoid intersection
            # Note: Formula not explicitly provided in source [S1, unofficial].
            # Standard approach: Solve quadratic equation for ellipsoid (x-c)^T S^-1 (x-c) = 1
            # where S is the covariance matrix derived from scale and rotation.
            hit = ellipsoid_intersection(origin, direction, splat.center, splat.scale, splat.rotation)

        if hit is not None:
            # Transform hit back to world space
            world_hit_origin = from_local * vec4(hit.origin, 1.0)
            world_hit_normal = from_local * vec4(hit.normal, 0.0)
            
            distance = length(global_ray_origin - world_hit_origin)
            hits.append(Hit(distance, world_hit_origin, world_hit_normal, splat))
```

## Operating characteristics
- **Time Complexity:** $O(N)$ in the worst case where $N$ is the number of splats, but typically much faster due to hierarchical culling. The tree structure allows skipping large portions of the scene.
- **Memory Complexity:** $O(N)$ to store splat data and tree structure.
- **Strengths:** Efficient culling of non-visible splats; supports both fast approximate sphere tests and accurate ellipsoid tests; handles dynamic scenes via local-to-world transforms.
- **Limitations:** Degenerate splats (zero scale) must be handled explicitly to avoid division by zero or invalid geometry [S1, unofficial]. The exact ellipsoid intersection is more computationally expensive than sphere intersection.
- **When to use:** When rendering 3D Gaussian Splatting scenes and precise visibility determination is required. Use approximate sphere intersection for performance-critical applications where slight inaccuracies are acceptable.

## Background
Originating from the GaussianSplats3D library by mkkellogg [S1, unofficial], this method was developed to support efficient raycasting against 3D Gaussian Splatting representations in web-based and desktop viewers. It addresses the need for accurate intersection tests between rays and oriented ellipsoids, which are the fundamental primitives in 3D Gaussian Splatting. The method supports both traditional 3D rendering modes and newer 2D splatting modes.
