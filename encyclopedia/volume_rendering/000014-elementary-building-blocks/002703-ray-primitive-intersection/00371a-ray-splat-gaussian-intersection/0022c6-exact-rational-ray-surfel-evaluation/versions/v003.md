# Exact Rational Ray-Surfel Evaluation

Also called: Homography-based Ray-Surfel Intersection, Screen-space Homography Surfel Intersection

## Overview
Exact Rational Ray-Surfel Evaluation computes the intersection of a viewing ray with a flat surfel rectangle in its local $(u, v)$ coordinates using a homography approximation around the center of the screen-space bounding box [S1, unofficial]. It sets itself apart from the reference 2DGS formulation by replacing the per-pixel cross-product-based inversion with a precomputed affine approximation, reducing computational cost while maintaining visual fidelity [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Ray direction $\mathbf{d}$, screen-space offset $\Delta$ from the bounding box center to the current pixel, Jacobian matrix $\mathbf{J}$, and bounding box center $(u_0, v_0)$ [S1, unofficial].
*   **Output:** Local coordinates $(u, v)$ of the intersection point on the surfel [S1, unofficial].

**Data Structures**
The method relies on precomputed constants for each surfel:
*   $\mathbf{J}$: A $2 \times 2$ Jacobian matrix representing the linear approximation of the homography [S1, unofficial].
*   $(u_0, v_0)$: The local coordinates of the center of the surfel's screen-space bounding box [S1, unofficial].
*   $\Delta$: A 2D vector representing the screen-space offset from the bounding box center to the current pixel [S1, unofficial].

**Steps**
1.  Compute the screen-space offset $\Delta$ from the center of the surfel's screen-space bounding box to the current pixel's screen-space position [S1, unofficial].
2.  Compute the dot product $\mathbf{d}^{\top}\Delta$ between the ray direction and the offset [S1, unofficial].
3.  Compute the Jacobian-vector product $(\mathbf{J}\Delta)$ to obtain the numerator components $(\mathbf{J}\Delta)_u$ and $(\mathbf{J}\Delta)_v$ [S1, unofficial].
4.  Calculate the local coordinates using the homography approximation formula:
    $$ u = u_0 + \frac{(\mathbf{J}\Delta)_u}{1 + \mathbf{d}^{\top}\Delta}, \quad v = v_0 + \frac{(\mathbf{J}\Delta)_v}{1 + \mathbf{d}^{\top}\Delta} $$

**Pseudocode**
```python
def dot(a, b):
    return a[0] * b[0] + a[1] * b[1]

def mat_vec(M, v):
    return [M[0][0] * v[0] + M[0][1] * v[1], M[1][0] * v[0] + M[1][1] * v[1]]

def exact_rational_ray_surfel_intersection(d, delta, J, u0, v0):
    """
    Computes local (u, v) coordinates of the ray-surfel intersection.
    Args:
        d: (2,) array, ray direction vector compatible with delta space.
        delta: (2,) array, screen-space offset from bounding box center to pixel.
        J: (2, 2) array, Jacobian matrix of the homography approximation.
        u0: float, local u-coordinate of the bounding box center.
        v0: float, local v-coordinate of the bounding box center.
    Returns:
        u: float, local u-coordinate of intersection.
        v: float, local v-coordinate of intersection.
    """
    denom = 1.0 + dot(d, delta)
    J_delta = mat_vec(J, delta)
    u = u0 + J_delta[0] / denom
    v = v0 + J_delta[1] / denom
    return u, v
```

**Parameters**
*   **Jacobian $\mathbf{J}$**: Precomputed for each surfel based on its orientation and position relative to the camera [S1, unofficial].
*   **$(u_0, v_0)$**: Center of the screen-space bounding box of the surfel [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Denominator Zero**: If $1 + \mathbf{d}^{\top}\Delta = 0$, the division is undefined, corresponding to a singularity in the homography approximation [S1, unofficial].
*   **Precision**: The method avoids per-pixel cross products and divisions, improving performance, but relies on the accuracy of the homography approximation around the bounding box center [S1, unofficial].
*   **Boundaries**: The approximation is valid around the center of the screen-space bounding box, and large bounding boxes may reduce accuracy [S1, unofficial].

## Subtopics

### [Closed-form perspective-correct surfel rasterization](3523-closed-form-perspective-correct-surfel-rasterization.md)
A rasterization technique for planar surfels that computes screen-space texture coordinates $(u, v)$ using an algebraically exact rational function of pixel position, avoiding per-pixel cross products and vector constructions. It sets itself apart from the reference 2DGS formulation by replacing the per-pixel cross-product-based inversion with a precomputed affine approximation, reducing computational cost while maintaining visual fidelity.

### Closed-form Intersection
Uses a closed-form ray-surfel intersection calculation instead of the 2DGS formulation to improve performance on fragment-bound scenes [S1, unofficial]. The hardware rasterizer has no ray–surfel variant, so the 2DGS intersection comparison was timed only on the CUDA renderer [S1, unofficial]. The saving is per fragment, so fragment-bound scenes gain the most (+47% on stump and flowers) and scenes bound by sorting and binning gain the least (+20% on train) [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity**
The method reduces the per-pixel computational cost by moving most calculations (Jacobian, center coordinates) to precomputation [S1, unofficial]. The per-pixel cost is reduced to a few dot products and a division [S1, unofficial].

**Measured Performance**
*   On Mip-NeRF 360, Tanks & Temples, and Deep Blending, the hardware rasterizer implementation achieved mean frame rates of 2698, 3016, and 4413 FPS, respectively, which is 1.8× over the CUDA software rasterizer implementation [S1, unofficial].
*   Fragment-bound scenes gain the most performance (+47% on stump and flowers scenes), while scenes bound by sorting and binning gain the least (+20% on train scene) [S1, unofficial].
*   The hardware rasterizer generates fragments only for pixels covered by the surfels, requiring significantly less memory and computation than tile-based binning [S1, unofficial].

**Strengths and Limitations**
*   **Strengths**: High performance due to reduced per-pixel operations and efficient use of hardware rasterization [S1, unofficial]. Maintains visual quality with minimal deviation (at most 0.05 dB and 0.0007 LPIPS) compared to software rasterization [S1, unofficial].
*   **Limitations**: The approximation is local to the bounding box center [S1, unofficial]. The hardware rasterizer does not have a native ray-surfel variant, so the intersection comparison was timed only on the CUDA renderer for some metrics [S1, unofficial].

**When to Use**
Use this method when performance is critical and the surfels are relatively small in screen space, ensuring the homography approximation remains accurate [S1, unofficial]. It is particularly effective for fragment-bound scenes [S1, unofficial].

## Background
This method was introduced in "Bake It Till You Make It: Ultrafast Spatial Texture-Atlas Splatting" by Niedermayr et al. (2024) [S1, unofficial]. It addresses the high per-pixel cost of ray-surfel intersection in 2D Gaussian Splatting (2DGS) by leveraging the homography property of planar surfaces in perspective projection [S1, unofficial].
