# Splat Raycasting Dispatch


## Overview
Splat Raycasting Dispatch is a parallel GPU/CPU dispatch method that computes ray-splat intersections for 3D Gaussian Splatting by batching splat records into fixed-size buffers and invoking a low-level kernel to solve the ray-ellipsoid intersection problem. It differs from naive per-splat raycasting by using pre-allocated, contiguous memory layouts and batched execution to minimize overhead and maximize throughput [S1, unofficial]. It serves as the core intersection engine within the [Ray-primitive intersection](769-ray-primitive-intersection.md) family, specifically handling the quadratic intersection tests required for Gaussian ellipsoids.

## How it works
The method operates in two phases: buffer population (host-side or high-level API) and kernel dispatch (low-level WASM/Rust or GPU compute). The kernel solves for the distance $t$ along the ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ where the ray intersects the implicit surface of a Gaussian splat, defined by its covariance matrix.

### Inputs and Outputs
**Inputs:**
- $\mathbf{o} = (o_x, o_y, o_z)$: Ray origin in mesh space [S1, unofficial].
- $\mathbf{d} = (d_x, d_y, d_z)$: Ray direction vector in mesh space [S1, unofficial].
- $\text{min\_opacity}$: Threshold for inclusion; splats with opacity below this value at the intersection point are discarded [S1, unofficial].
- $\text{near}, \text{far}$: Clipping plane distances along the ray [S1, unofficial].
- $\text{tables}$: Precomputed lookup tables for optimization (e.g., inverse covariance components or opacity mappings) [S1, unofficial].
- $\text{splats}$: Array of splat records, packed as 4 uint32 values per splat [S1, unofficial].
- $\text{splats2}$: Secondary buffer for auxiliary data, packed as 4 uint32 values per splat [S1, unofficial].
- $\text{count}$: Number of splats in the current batch [S1, unofficial].

**Outputs:**
- $\text{distances}$: Array of $f32$ values storing the intersection distance $t$ for each hit splat [S1, unofficial].
- $\text{indices}$: Array of $u32$ values storing the original splat index corresponding to each hit [S1, unofficial].

### Data Structures
The implementation relies on fixed-capacity buffers to avoid dynamic allocation during the critical path.

**Constants:**
- $\text{RAYCAST\_BUFFER\_COUNT} = 65536$: Maximum number of splats per dispatch batch [S1, unofficial].

**Structures:**
1.  **RaycastBuffers**:
    -   $\text{splats}$: `Vec<u32>`, size $\text{RAYCAST\_BUFFER\_COUNT} \times 4$. Stores primary splat attributes (e.g., mean position, covariance, color, opacity) in a Structure of Arrays (SoA) or Array of Structures (AoS) layout, packed into 32-bit integers for memory efficiency [S1, unofficial].
    -   $\text{splats2}$: `Vec<u32>`, size $\text{RAYCAST\_BUFFER\_COUNT} \times 4$. Stores secondary attributes or transformed data [S1, unofficial].
    -   $\text{distances}$: `Vec<f32>`, size $\text{RAYCAST\_BUFFER\_COUNT}$. Output buffer for intersection distances [S1, unofficial].
    -   $\text{indices}$: `Vec<u32>`, capacity $\text{RAYCAST\_BUFFER\_COUNT}$. Output buffer for hit splat indices [S1, unofficial].
    -   $\text{tables}$: `RaycastTables`. Auxiliary data structures for optimization [S1, unofficial].

2.  **raycastVisibleIndices** (High-level wrapper):
    -   `Uint32Array`: Maps buffer slot indices to original splat indices. Size is $\text{buffer.length} / 4$. Reallocated if capacity changes [S1, unofficial].

### Algorithm Steps

1.  **Initialization**:
    -   Clear $\text{distances}$ and $\text{indices}$ buffers to zero or invalid values.
    -   Validate that $\text{count} \le \text{RAYCAST\_BUFFER\_COUNT}$. If $\text{count} > \text{RAYCAST\_BUFFER\_COUNT}$, throw an error or split the batch [S1, unofficial].

2.  **Buffer Population** (Host/Wrapper Side):
    -   Extract subbuffers from the full splat arrays: $\text{subbuffer} = \text{splats}[0 \dots (4 \times \text{count})]$ and $\text{subbuffer2} = \text{splats2}[0 \dots (4 \times \text{count})]$ [S1, unofficial].
    -   If using the high-level wrapper, transform $\mathbf{o}$ and $\mathbf{d}$ from world space to mesh space using the inverse of $\text{matrixWorld}$ [S1, unofficial].
    -   Iterate over splat ranges. For each range, copy splat records into the local buffers using $\text{splats.copySplatRecords}$, mapping original indices to $\text{raycastVisibleIndices}$ [S1, unofficial].
    -   Flush to the WASM/GPU buffer when capacity is reached [S1, unofficial].

3.  **Kernel Dispatch**:
    -   Call the low-level kernel:
        ```python
        raycast_splat_ellipsoids(
            subbuffer, 
            subbuffer2, 
            distances, 
            indices, 
            [o_x, o_y, o_z], 
            [d_x, d_y, d_z], 
            min_opacity, 
            tables, 
            near, 
            far
        )
        ```
    -   The kernel performs the following for each splat $i$ in the batch:
        a.  Retrieve splat parameters from $\text{subbuffer}[i]$ and $\text{subbuffer2}[i]$.
        b.  Construct the ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$.
        c.  Solve the quadratic equation derived from the Gaussian ellipsoid implicit function $f(\mathbf{x}) = (\mathbf{x} - \mathbf{\mu})^T \Sigma^{-1} (\mathbf{x} - \mathbf{\mu}) = 1$.
        d.  Compute the discriminant $\Delta$. If $\Delta < 0$, no intersection.
        e.  If $\Delta \ge 0$, compute the smallest positive root $t$.
        f.  Check if $t \in [\text{near}, \text{far}]$.
        g.  Evaluate the opacity at the intersection point. If opacity $\ge \text{min\_opacity}$, store $t$ in $\text{distances}[k]$ and the original index in $\text{indices}[k]$, where $k$ is the hit counter [S1, unofficial].

4.  **Result Retrieval**:
    -   Return $\text{distances}$ as a `Float32Array` view [S1, unofficial].
    -   For each hit, compute the world-space point $\mathbf{p} = \mathbf{o}_{world} + t \cdot \mathbf{d}_{world}$ and store the distance, point, object reference, and original splat index in the intersection list [S1, unofficial].

### Parameters and Typical Values
-   $\text{min\_opacity}$: Defaults to $0.1$. Must be strictly less than $1.0$ [S1, unofficial].
-   $\text{near}, \text{far}$: Standard camera clipping distances [S1, unofficial].
-   $\text{RAYCAST\_BUFFER\_COUNT}$: $65536$ [S1, unofficial].

### Edge Cases and Pitfalls
-   **Buffer Overflow**: $\text{count}$ must not exceed $\text{RAYCAST\_BUFFER\_COUNT}$. Exceeding this limit throws an error [S1, unofficial].
-   **Opacity Threshold**: $\text{min\_opacity}$ must be $< 1.0$ to avoid degenerate cases where no splats are considered visible [S1, unofficial].
-   **Coordinate Space**: Ray origin and direction must be transformed to mesh space before dispatch if the splats are stored in mesh space [S1, unofficial].

## Subtopics

### Splat Raycasting Implementation
A high-level wrapper that manages the transformation of rays from world to mesh space, the population of the fixed-size buffers via `copySplatRecords`, and the post-processing of hits to compute world-space coordinates. It handles the mapping of buffer indices to original splat indices using `raycastVisibleIndices` and manages buffer flushing when capacity is reached [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: $O(N)$ per batch, where $N$ is the number of splats in the batch. The constant factor is low due to SIMD optimizations in the WASM/Rust kernel [S1, unofficial].
-   **Memory Complexity**: $O(\text{RAYCAST\_BUFFER\_COUNT})$ for the fixed buffers. This is constant regardless of the total scene size, as splats are processed in batches [S1, unofficial].
-   **Performance**: Measured on WASM targets with SIMD128 enabled. Performance scales with the number of splats per batch, up to the limit of 65536 [S1, unofficial].
-   **Strengths**: Low overhead, cache-friendly memory layout, efficient batch processing.
-   **Limitations**: Fixed buffer size requires batching for large scenes. Precision issues may arise if the quadratic solver is not robust [S1, unofficial].

## Background
The method is derived from the Gaussian-Splat-Lite project, which implements efficient 3D Gaussian Splatting rendering in web environments using WebAssembly [S1, unofficial]. It adapts the ray-splat intersection logic from GPU-based renderers to a CPU/WASM context, optimizing for memory bandwidth and parallel execution [S1, unofficial].
