# Splat Raycasting Dispatch
## Overview
Splat Raycasting Dispatch manages the buffer preparation and dispatch call for ray-splat intersection tests, returning hit distances and splat indices [S1, unofficial]. It operates on pre-transformed, packed buffer structures optimized for batched processing, distinguishing it from [Ray-Splat Intersection](6816-ray-splat-intersection.md), and targets standard Euclidean camera models rather than spherical panoramas like [Spherical Panoramic Gaussian Splatting (SPaGS)](3042-spherical-panoramic-gaussian-splatting-spags.md) [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
- `splats`: A flat array of `u32` values representing splat data, size at least `4 * count` [S1, unofficial].
- `splats2`: A secondary buffer of `u32` values, size `4 * count` [S1, unofficial].
- `origin_x`, `origin_y`, `origin_z`: Ray origin coordinates as `f32` [S1, unofficial].
- `dir_x`, `dir_y`, `dir_z`: Ray direction vector components as `f32` [S1, unofficial].
- `min_opacity`: Minimum opacity threshold as `f32` [S1, unofficial].
- `near`: Near plane distance as `f32` [S1, unofficial].
- `far`: Far plane distance as `f32` [S1, unofficial].
- `tables`: Precomputed lookup tables of type `RaycastTables` [S1, unofficial].

**Outputs:**
- `distances`: A `Vec<f32>` of size `RAYCAST_BUFFER_COUNT` containing intersection distances [S1, unofficial].
- `indices`: A `Vec<u32>` of capacity `RAYCAST_BUFFER_COUNT` containing original splat indices for hits [S1, unofficial].

### Data Structures
The implementation uses a fixed-capacity buffer structure to manage memory [S1, unofficial].
- `RAYCAST_BUFFER_COUNT`: `usize` constant set to 65536, defining the maximum number of splats per dispatch batch [S1, unofficial].
- `RaycastBuffers`: Contains `splats` (`Vec<u32>`, size `RAYCAST_BUFFER_COUNT * 4`), `splats2` (`Vec<u32>`, size `RAYCAST_BUFFER_COUNT * 4`), `distances` (`Vec<f32>`, size `RAYCAST_BUFFER_COUNT`), `indices` (`Vec<u32>`, capacity `RAYCAST_BUFFER_COUNT`), and `tables` (`RaycastTables`) [S1, unofficial].

### Algorithm Steps
1. Clear the `distances` and `indices` buffers [S1, unofficial].
2. Extract subbuffers `splats[0..(4 * count)]` and `splats2[0..(4 * count)]` [S1, unofficial].
3. Validate that `count` as `usize` does not exceed `RAYCAST_BUFFER_COUNT`; throw an error if it does [S1, unofficial].
4. Call `raycast_splat_ellipsoids(subbuffer, subbuffer2, distances, indices, [origin_x, origin_y, origin_z], [dir_x, dir_y, dir_z], min_opacity, tables, near, far)` [S1, unofficial].
5. Return `distances` as a `Float32Array` view [S1, unofficial].

### Pseudocode
```python
def splat_ray_casting_dispatch(splats, splats2, count, origin, direction, min_opacity, near, far, tables):
    RAYCAST_BUFFER_COUNT = 65536
    if count > RAYCAST_BUFFER_COUNT:
        raise ValueError(f"Count {count} exceeds buffer capacity {RAYCAST_BUFFER_COUNT}")
    distances = [float('inf')] * RAYCAST_BUFFER_COUNT
    indices = [0] * RAYCAST_BUFFER_COUNT
    subbuffer_splats = splats[0 : 4 * count]
    subbuffer_splats2 = splats2[0 : 4 * count]
    raycast_splat_ellipsoids(
        subbuffer_splats, subbuffer_splats2, distances, indices,
        origin[0], origin[1], origin[2],
        direction[0], direction[1], direction[2],
        min_opacity, tables, near, far
    )
    return distances
```

### Edge Cases and Pitfalls
- **Buffer Overflow**: `count` as `usize` must not exceed `RAYCAST_BUFFER_COUNT` (65536); exceeding this limit throws an error [S1, unofficial].
- **Opacity Threshold**: `min_opacity` must be strictly less than 1.0 [S1, unofficial].
- **Precision**: Not given in the sources.

## Subtopics

### Splat Raycasting Implementation
This variant describes the higher-level integration of the dispatch kernel within a JavaScript/WASM environment [S1, unofficial].
- **Process**:
  1. Transform ray origin and direction from world to mesh space using the inverse of `matrixWorld`, storing results in `raycastOrigin` and `raycastDirection` [S1, unofficial].
  2. Iterate over splat ranges via `splats.forEachRaycastRange`; for each range, copy splat records into buffers using `splats.copySplatRecords`, mapping original indices to `raycastVisibleIndices`, and flush to WASM when buffer capacity is reached [S1, unofficial].
  3. On flush, call `raycast_splat_buffers` with `raycastOrigin`, `raycastDirection`, `minRaycastOpacity`, `near`, `far`, and `count`, then retrieve `distances` and `hitIndices` from WASM [S1, unofficial].
  4. For each hit, compute the world point via `ray.at(distance)` and store the distance, point, object, and original splat index in `intersects` [S1, unofficial].
- **Data Structures**: `raycastVisibleIndices` is a `Uint32Array` mapping buffer slot indices to original splat indices, sized to `buffer.length / 4`, and is reallocated if capacity changes [S1, unofficial].
- **Parameters**: `minRaycastOpacity` is the threshold for raycast inclusion, defaulting to 0.1, and must be strictly less than 1.0 [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Not given in the sources.
- **Performance**: The method is optimized for batched processing on WASM, leveraging SIMD instructions via `RUSTFLAGS="-C target-feature=+simd128,+bulk-memory"` [S1, unofficial].
- **Strengths**: Not given in the sources.
- **Limitations**: Fixed buffer size limits the maximum batch size to `RAYCAST_BUFFER_COUNT` [S1, unofficial].

## Background
Splat Raycasting Dispatch is part of the Gaussian-Splat-Lite project, which builds 3D Gaussian Splatting implementations for WebAssembly [S1, unofficial]. It builds on the geometric principles of ray-splat intersection defined in the parent article [Ray-Splat/Gaussian Intersection](7916-ray-splat-gaussian-intersection.md) [S1, unofficial].
