# GPU Offloaded Calculations

Also called: GPU Compute Offload, GPU Offloading

## Overview
GPU Offloaded Calculations migrates specific computational tasks, such as bias and scale operations, from the CPU to the GPU to leverage parallel processing for faster execution [S1, unofficial]. This method is distinct from general compute shader kernels by focusing specifically on offloading mathematical transformations within the volume rendering pipeline, particularly in OpenGL-based volume mappers [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Volume data (scalar values), transfer function parameters (bias, scale), and a boolean `RenderToImage` flag [S1, unofficial].
- **Output:** Processed volume data or intermediate depth and color textures ready for deferred rendering [S1, unofficial].

**Data Structures:**
- **OpenGL Context:** Requires an OpenGL 3.2 Core context to support the necessary shader and buffer features [S1, unofficial].
- **Textures:** Color and depth textures are exported as `vtkTextureObject` or `vtkImageData` post-rendering [S1, unofficial].

**Steps:**
1. Initialize an OpenGL 3.2 Core context [S1, unofficial].
2. Configure the mapper with volume data and bias/scale parameters [S1, unofficial].
3. Execute GPU shaders to perform bias and scale computations on the volume data [S1, unofficial].
4. If `RenderToImage` is enabled, render to a FrameBufferObject and retrieve depth and color images via `GetDepthImage` and `GetColorImage` [S1, unofficial].

**Formulas:**
The exact mathematical relationship for the bias and scale computations is not specified in the sources [S1, unofficial].

**Parameters:**
- **OpenGL Version:** 3.2 Core [S1, unofficial].
- **RenderToImage:** Boolean flag to enable export of color and depth textures [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Context Compatibility:** Requires OpenGL 3.2 Core; older contexts may not support the offloading mechanism [S1, unofficial].
- **Memory Management:** Exporting textures requires careful handling of FrameBufferObjects and texture retrieval methods [S1, unofficial].

## Operating characteristics
- **Performance:** The new mapper with GPU offloading performs about 35% faster than its OpenGL 1 counterpart and about 135% faster than the `vtkFixedPointVolumeRayCastMapper` with shading enabled [S1, unofficial].
- **Hardware Requirements:** Requires a GPU capable of supporting OpenGL 3.2 Core context [S1, unofficial].
- **Memory Usage:** Additional memory may be required for storing color and depth textures if "RenderToImage" is enabled [S1, unofficial].
- **Strengths:** Significant performance improvement for volume rendering calculations; supports deferred rendering setups [S1, unofficial].
- **Limitations:** Dependent on OpenGL version; may not be suitable for older hardware or software renderers [S1, unofficial].

## Background
In the context of volume rendering, this approach was notably implemented in the Visualization Toolkit (VTK) with the introduction of the `vtkGPUVolumeRayCastMapper` [S1, unofficial]. This mapper leverages OpenGL 3.2 Core features to offload bias and scale computations, enhancing performance compared to previous CPU-based or older OpenGL implementations [S1, unofficial].
