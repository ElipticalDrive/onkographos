# Multi-core BONO Tree Traversal and Ray Casting with Dynamic Tile Grouping

Also called: Phase I/Phase II Multi-core Scheme, Z-ordered Dynamic Tile Allocation

## Overview
A multi-core parallel rendering method that divides screen space into contiguous regions for Phase I (BONO tree traversal to build block lists) and partitions ray casting tasks into Z-ordered tiles grouped by weight for Phase II (dynamic load-balanced ray casting) [S1, unofficial]. It sets itself apart from static tile allocation methods by using dynamic, weight-based grouping of Z-ordered tiles to achieve better load balancing and cache performance while minimizing synchronization overhead [S1, unofficial].

## How it works
**Inputs:**
- $p$: Number of cores/threads on the multicore processor [S1, unofficial].
- $k$: Upper bound on the size of the list of 3D data blocks for each pixel group [S1, unofficial].
- BONO Tree: The hierarchical spatial index structure [S1, unofficial].
- Volume Data: 3D scalar field data [S1, unofficial].
- View Parameters: Zenith angle $\phi$, Azimuth angle $\theta$, screen resolution (e.g., $1024 \times 1024$) [S1, unofficial].

**Outputs:**
- Rendered image pixels with shading [S1, unofficial].

**Data Structures:**
- **Block List:** A list of 3D data blocks associated with a pixel or group of pixels. Size is limited to $k$ [S1, unofficial].
- **Tile:** A small image-size region (e.g., $8 \times 8$ or $16 \times 16$ pixels) [S1, unofficial].
- **Group:** A contiguous set of tiles in Z-order, identified by a pair of indices $(first, last)$ [S1, unofficial].
- **List $L_I$:** A list of groups, ordered by Z-order and weight, used for dynamic task allocation [S1, unofficial].

**Steps:**

1.  **Phase I: Screen Division and BONO Tree Traversal**
    - Divide the screen into almost equal contiguous regions, one per thread [S1, unofficial].
    - Each thread traverses the BONO tree to create lists of 3D data blocks for pixels in its region [S1, unofficial].
    - **Traversal Rule:** Traverse a BONO node's children in front-to-back order only if:
        1. The projection of the node's minimum bounding box intersects the thread's screen region.
        2. The associated list size is less than $k$ [S1, unofficial].
    - Note: Due to the upper bound $k$, only a fraction (no more than 10%) of total BONO tree nodes are accessed during Phase I [S1, unofficial].

2.  **Phase II: Preprocessing and Dynamic Grouping**
    - **Partitioning:** Partition the screen into small image-size tiles (e.g., $8 \times 8$ or $16 \times 16$) [S1, unofficial].
    - **Z-Ordering:** Order these tiles using a Z-order (space-filling curve) to ensure spatial locality and high cache performance [S1, unofficial].
    - **Weighting:** Assign a weight to each tile equal to the number of non-empty block lists within that tile. Compute the total weight $W$ of all tiles [S1, unofficial].
    - **Grouping:** Group tiles from the Z-ordered list into $p$ groups as follows:
        1. Take the first set of tiles whose total weight is $W/2$. Group them equally into $p$ contiguous groups (each group is a contiguous set of tiles following Z-order). Identify each group by a pair of indices $(first, last)$ [S1, unofficial].
        2. Take the second set of remaining tiles whose total weight is $W/4$. Group them equally into $p$ groups [S1, unofficial].
        3. Repeat this process (halving the weight target each time) until all tiles are grouped. This creates list $L_I$ [S1, unofficial].
        4. The grouping process requires at most a logarithmic number of iterations relative to screen size [S1, unofficial].
    - **Overhead:** The time to group image tiles is small, approximately 2-3 milliseconds [S1, unofficial].

3.  **Phase III: Dynamic Ray Casting Allocation**
    - Each thread grabs a group of image tiles from the ordered list $L_I$ [S1, unofficial].
    - Process the group by shooting rays through pixels using the block lists generated in Phase I [S1, unofficial].
    - Upon completion, the thread grabs the next available group from $L_I$ [S1, unofficial].
    - Continue until all image tiles in $L_I$ are processed [S1, unofficial].
    - **Shading:** If a ray intersects the isosurface:
        1. Calculate intersection position by solving a trilinear interpolation equation [S1, unofficial].
        2. Compute the normal using the forward difference gradient [S1, unofficial].
        3. Apply the diffuse shade model [S1, unofficial].

4.  **Handling Unfinished Pixels**
    - Pixels whose lists reached size $k$ but had no intersecting voxels found during the initial ray casting must be handled separately [S1, unofficial].

**Pseudocode:**

```python
def multi_core_bono_ray_casting(p, k, volume_data, bono_tree, screen_width, screen_height, phi, theta):
    # Phase I: Screen Division and BONO Tree Traversal
    screen_regions = divide_screen_into_contiguous_regions(screen_width, screen_height, p)
    block_lists = [None] * p
    
    threads = []
    for i in range(p):
        region = screen_regions[i]
        t = Thread(target=traverse_bono_tree, args=(region, k, bono_tree, volume_data, i))
        threads.append(t)
        t.start()
        
    for t in threads:
        t.join()
        
    # Phase II: Preprocessing and Dynamic Grouping
    tile_size = 16 # Example: 16x16 tiles
    tiles = partition_screen_into_tiles(screen_width, screen_height, tile_size)
    z_ordered_tiles = order_tiles_by_z_order(tiles)
    
    # Calculate weights
    tile_weights = []
    for tile in z_ordered_tiles:
        # Count non-empty block lists within this tile
        weight = count_non_empty_block_lists(tile, block_lists)
        tile_weights.append(weight)
        
    total_weight = sum(tile_weights)
    
    # Group tiles
    list_L_I = []
    remaining_tiles = list(range(len(z_ordered_tiles)))
    remaining_weight = total_weight
    
    while remaining_tiles:
        # Determine target weight for this iteration
        # First iteration: W/2, second: W/4, etc.
        # However, the source says "first set... W/2", "second set... W/4"
        # This implies we take a chunk of tiles whose weight sums to W/2^i
        target_weight = total_weight / (2 ** (len(list_L_I) // p + 1))
        
        # Group into p groups
        # We need to form p groups from the remaining tiles
        # The source says: "The first set of tiles whose total weight is W/2 are grouped into p equal groups"
        # This implies we take a subset of tiles summing to W/2, then split that subset into p groups.
        # Then take next subset summing to W/4, split into p groups.
        
        # Find tiles that sum to target_weight
        current_group_tiles = []
        current_weight = 0
        tiles_to_remove = []
        
        for idx in remaining_tiles:
            if current_weight + tile_weights[idx] <= target_weight:
                current_group_tiles.append(idx)
                current_weight += tile_weights[idx]
                tiles_to_remove.append(idx)
            else:
                break
                
        # Remove processed tiles from remaining
        for idx in tiles_to_remove:
            remaining_tiles.remove(idx)
            
        # Split current_group_tiles into p groups
        # If current_group_tiles is empty or fewer than p tiles, handle edge case?
        # Source implies this process continues until all tiles are grouped.
        # If remaining tiles < p, we might just assign them one by one or in smaller groups.
        # For simplicity, we assume the loop handles the distribution.
        
        num_groups_this_iter = min(p, len(current_group_tiles)) if current_group_tiles else 0
        if num_groups_this_iter == 0:
            break
            
        tiles_per_group = len(current_group_tiles) // num_groups_this_iter
        remainder = len(current_group_tiles) % num_groups_this_iter
        
        start_idx = 0
        for g in range(num_groups_this_iter):
            count = tiles_per_group + (1 if g < remainder else 0)
            end_idx = start_idx + count
            group = current_group_tiles[start_idx:end_idx]
            if group:
                first_tile = z_ordered_tiles[group[0]]
                last_tile = z_ordered_tiles[group[-1]]
                list_L_I.append((first_tile, last_tile))
            start_idx = end_idx
            
    # Phase III: Dynamic Ray Casting Allocation
    # Shared queue for groups
    group_queue = list_L_I
    lock = Lock()
    
    def process_group(group):
        first_tile, last_tile = group
        for tile_idx in range(first_tile, last_tile + 1):
            tile = z_ordered_tiles[tile_idx]
            # Shoot rays through pixels in this tile using block lists
            for pixel in tile:
                ray = create_ray(pixel, phi, theta)
                blocks = get_block_list_for_pixel(pixel, block_lists)
                hit = False
                for block in blocks:
                    intersection = ray_intersect_block(ray, block)
                    if intersection:
                        # Shading
                        pos = solve_trilinear_intersection(ray, block)
                        normal = compute_forward_difference_gradient(pos, volume_data)
                        color = apply_diffuse_shading(pos, normal, light_direction)
                        set_pixel_color(pixel, color)
                        hit = True
                        break
                if not hit:
                    # Check if list was full (size k) but no intersection found
                    if len(get_block_list_for_pixel(pixel, block_lists)) == k:
                        # Handle unfinished pixels separately
                        handle_unfinished_pixel(pixel, ray, volume_data)

    threads = []
    for i in range(p):
        t = Thread(target=worker_thread, args=(group_queue, lock, process_group))
        threads.append(t)
        t.start()
        
    for t in threads:
        t.join()

def worker_thread(group_queue, lock, process_func):
    while True:
        lock.acquire()
        if not group_queue:
            lock.release()
            break
        group = group_queue.pop(0)
        lock.release()
        process_func(group)
```

**Parameters:**
- $p$: Number of cores/threads [S1, unofficial].
- $k$: Upper bound on list size [S1, unofficial].
- Tile size: $8 \times 8$ or $16 \times 16$ pixels [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Unfinished Pixels:** Pixels whose lists reached size $k$ but had no intersecting voxels found during the initial ray casting must be handled separately [S1, unofficial].
- **Precision:** Trilinear interpolation equation solving for intersection position [S1, unofficial].
- **Boundaries:** BONO node traversal only if bounding box projection intersects screen region [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Phase I traversal is limited by $k$, accessing no more than 10% of BONO tree nodes [S1, unofficial]. Phase II grouping takes approximately 2-3 milliseconds [S1, unofficial]. Phase III dynamic allocation provides load balancing.
- **Memory Complexity:** Limited by the block list size $k$ per pixel group [S1, unofficial].
- **Measured Performance:** Tested on a Clovertown platform with two Quad-Core Intel Xeon 5320 (1.86 GHz), 8GB main memory, 8MB total L2 cache [S1, unofficial]. Screen resolution $1024 \times 1024$ [S1, unofficial]. View angles: Zenith $\phi = \{15^\circ, 45^\circ, 75^\circ\}$, Azimuth $\theta = \{22.5^\circ, 45^\circ\}$ [S1, unofficial].
- **Scaling:** Scalability tested with 1, 2, 4, 8 CPU cores [S1, unofficial].
- **Strengths:** Better load balancing and cache performance compared to static tile allocation due to Z-ordering and dynamic weight-based grouping [S1, unofficial]. Minimizes synchronization overhead by using coarse-grained groups initially and fine-grained jobs later [S1, unofficial].
- **Limitations:** Requires handling unfinished pixels separately [S1, unofficial]. Grouping overhead, though small, is non-zero [S1, unofficial].
- **When to Use:** Multi-core CPU environments where load balancing is critical and data distribution is uneven.
- **When Not to Use:** GPU environments where warp-level parallelism is more efficient, or when static tile allocation is sufficient for uniform data distribution.

## Background
Originated from research on interactive high-resolution isosurface ray tracing on multi-core processors [S1, unofficial]. The method was developed to address the challenges of load balancing and cache performance in parallel volume rendering on multi-core CPUs [S1, unofficial]. It builds on the BONO tree indexing structure [S1, unofficial].
