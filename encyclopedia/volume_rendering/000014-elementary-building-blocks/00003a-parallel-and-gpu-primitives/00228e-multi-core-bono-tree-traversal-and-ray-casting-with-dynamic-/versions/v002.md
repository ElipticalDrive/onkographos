# Multi-core BONO Tree Traversal and Ray Casting with Dynamic Tile Grouping

Also called: Phase I/Phase II Multi-core Scheme, Z-ordered Dynamic Tile Allocation

## Overview
A multi-core parallel rendering method that divides screen space into contiguous regions for Phase I (BONO tree traversal to build block lists) and partitions ray casting tasks into Z-ordered tiles grouped by weight for Phase II (dynamic load-balanced ray casting) [S1, unofficial]. It sets itself apart from static tiling siblings by using a weight-based Z-order grouping strategy to achieve tight load balancing while minimizing synchronization overhead [S1, unofficial].

## How it works
**Inputs:**
*   $p$: Number of cores/threads on the multicore processor [S1, unofficial].
*   $k$: Upper bound on the size of the list of 3D data blocks for each pixel group [S1, unofficial].
*   BONO Tree: The spatial index structure [S1, unofficial].
*   Volume Data: The underlying scalar field [S1, unofficial].
*   View Parameters: Zenith angle $\phi$ and Azimuth angle $\theta$ [S1, unofficial].

**Outputs:**
*   Rendered image pixels with shading [S1, unofficial].

**Data Structures:**
*   **Block List:** A list of 3D data blocks associated with a group of pixels. Size is limited to $k$ [S1, unofficial].
*   **Tile:** A small image-size region (e.g., $8 \times 8$ or $16 \times 16$ pixels) [S1, unofficial].
*   **Group:** A contiguous set of tiles in Z-order, identified by a pair of indices $(first, last)$ [S1, unofficial].
*   **List $L_I$:** A list of groups created during preprocessing [S1, unofficial].

**Steps:**

1.  **Phase I: Screen Division and BONO Traversal**
    *   Divide the screen into almost equal contiguous regions, one per thread [S1, unofficial].
    *   Each thread traverses the BONO tree to create lists of 3D data blocks for pixels in its region [S1, unofficial].
    *   **Traversal Rule:** Traverse a BONO node's children in front-to-back order only if:
        1.  The node's minimum bounding box projection intersects the thread's screen region [S1, unofficial].
        2.  The associated list size is less than $k$ [S1, unofficial].
    *   Note: Due to the upper bound $k$, only a fraction (no more than 10%) of total BONO tree nodes are accessed during Phase I [S1, unofficial].

2.  **Phase II: Preprocessing and Dynamic Grouping**
    *   **Partitioning:** Partition the screen into small image-size tiles (e.g., $8 \times 8$ or $16 \times 16$) [S1, unofficial].
    *   **Z-Ordering:** Order these tiles using a Z-order (space-filling curve) to ensure spatial locality and high cache performance [S1, unofficial].
    *   **Weighting:** Assign a weight to each tile equal to the number of non-empty block lists within that tile [S1, unofficial]. Compute the total weight $W$ of all tiles [S1, unofficial].
    *   **Grouping:** Group tiles from the Z-ordered list into $p$ groups using the following iterative process [S1, unofficial]:
        1.  Identify the first set of tiles whose total weight is $W/2$. Group them equally into $p$ contiguous groups (each group is a pair of indices $(first, last)$).
        2.  Identify the second set of remaining tiles whose total weight is $W/4$. Group them equally into $p$ groups.
        3.  Repeat this process (halving the target weight sum each iteration: $W/8, W/16, \dots$) until all tiles are grouped [S1, unofficial].
    *   This process requires at most a logarithmic number of iterations relative to screen size [S1, unofficial].
    *   The result is a list $L_I$ of index pairs delineating groups of image tiles [S1, unofficial].
    *   The time to group image tiles is small, approximately 2-3 milliseconds [S1, unofficial].

3.  **Phase III: Dynamic Ray Casting Allocation**
    *   Initially, each thread grabs a group of image tiles from the ordered list $L_I$ [S1, unofficial].
    *   A thread processes its group by shooting rays through the pixels in the group using the data block lists generated in Phase I [S1, unofficial].
    *   Upon completion, the thread grabs the next available group from $L_I$ [S1, unofficial].
    *   The process continues until all image tiles in $L_I$ are processed [S1, unofficial].
    *   **Shading:** If a ray intersects the isosurface:
        1.  Calculate intersection position by solving a trilinear interpolation equation [S1, unofficial].
        2.  Compute the normal using the forward difference gradient [S1, unofficial].
        3.  Apply the diffuse shade model [S1, unofficial].

4.  **Handling Unfinished Pixels**
    *   Pixels whose lists reached size $k$ but had no intersecting voxels found during the initial ray casting must be handled separately [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The grouping process requires at most a logarithmic number of iterations relative to screen size [S1, unofficial]. The time to group image tiles is small, approximately 2-3 milliseconds [S1, unofficial].
*   **Memory Complexity:** The BONO tree access is limited by $k$, ensuring only a fraction (no more than 10%) of total BONO tree nodes are accessed during Phase I [S1, unofficial].
*   **Measured Performance:** Tested on a Clovertown platform with two Quad-Core Intel Xeon 5320 (1.86 GHz), 8GB main memory, and 8MB total L2 cache [S1, unofficial]. Test resolution was 1024x1024 [S1, unofficial]. View angles included zenith $\phi = \{15^\circ, 45^\circ, 75^\circ\}$ and azimuth $\theta = \{22.5^\circ, 45^\circ\}$ [S1, unofficial].
*   **Scaling:** Scalability was measured in data output size and number of cores used (1, 2, 4, 8 cores) [S1, unofficial].
*   **Strengths:** Achieves better load balancing and cache performance compared to standard octree ray casting with static 16x16 tile allocation [S1, unofficial]. Minimizes synchronization overhead by using dynamic allocation of groups of tiles [S1, unofficial].
*   **Limitations:** Requires handling of unfinished pixels separately [S1, unofficial].

## Background
The method was developed for interactive high-resolution isosurface ray tracing on multi-core processors [S1, unofficial]. It was tested on datasets such as Abdominal, Bunny, Aneurism, Skull, VisMale, and LLNL [S1, unofficial]. The BONO tree is used as the spatial index structure [S1, unofficial].
