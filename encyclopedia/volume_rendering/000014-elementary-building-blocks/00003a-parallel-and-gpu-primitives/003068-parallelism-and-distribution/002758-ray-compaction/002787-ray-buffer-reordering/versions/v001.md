# Ray Buffer Reordering


## Overview
Ray Buffer Reordering is a CUDA kernel step within the Ray Compaction pipeline that physically moves the indices of "alive" rays from the current buffer to the next buffer in a ping-pong memory scheme. It solves the problem of maintaining a contiguous, compacted list of active rays for subsequent processing stages (such as ray marching or feature sampling) while preserving the parallel atomicity required on GPU architectures. It differs from its sibling [In-Kernel Stream Compaction](6991-in-kernel-stream-compaction-ink-compact.md) by explicitly managing a double-buffered index array with atomic counters rather than performing in-place compaction or using shared memory scan primitives.

## How it works
**Inputs and Outputs:**
- Input: `self.alive_indices` (a double-buffered array of ray indices, size $2 \times B$), `self.counter` (an atomic integer counter), `self.current_index` (pointer to the current buffer index, 0 or 1).
- Output: `self.alive_indices` (updated with reordered indices in the next buffer), `self.counter` (updated with the new count of alive rays), `self.current_index` (updated to point to the next buffer).

**Data Structures:**
- `alive_indices`: Array of integers. Layout is `[current_buffer_indices..., next_buffer_indices...]`. The current buffer occupies indices $0$ to $B-1$, and the next buffer occupies $B$ to $2B-1$.
- `counter`: Single integer, initialized to 0.
- `current_index`: Integer, 0 or 1.

**Steps:**
1. **Initialization**: Reset the atomic counter `self.counter` to 0. Determine the next buffer index `n_index` as `(self.current_index + 1) % 2`. Update `self.current_index` to `n_index`.
2. **Iteration**: For each ray $i$ in the batch range $B$:
   - Check if the ray is alive: `if self.alive_indices[i * 2 + self.current_index] >= 0`.
   - If alive, atomically increment `self.counter` to obtain a unique destination index `index`.
   - Write the source ray index to the destination position in the next buffer: `self.alive_indices[index * 2 + n_index] = self.alive_indices[i * 2 + self.current_index]`.

**Edge Cases:**
- **Precision**: Atomic operations on integers are precise.
- **Boundaries**: Ensure `B` does not exceed the allocated buffer size.
- **Degenerate Input**: If no rays are alive, the counter remains 0, and the next buffer is empty.

## Subtopics

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(B)$, where $B$ is the number of rays. Each ray is processed once.
- Memory: $O(B)$ for the double-buffered index array.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scales linearly with the number of rays.

**Strengths and Limitations:**
- Strengths: Simple implementation, robust atomicity, clear separation of buffers.
- Limitations: Requires double the memory for indices compared to in-place compaction. Atomic contention on `counter` may become a bottleneck for very large $B$.

**When to Use:**
- Use when a clean separation between current and next ray lists is required for subsequent processing steps.

**When Not to Use:**
- Avoid if memory is extremely constrained and in-place compaction is feasible.
