# Ray Compaction


## Overview
Ray Compaction is a parallelism optimization technique used in volume rendering to manage the dynamic set of "alive" rays during image-order rendering. It solves the problem of sparse, irregular ray termination by compacting a list of active rays into a contiguous array, removing those that have terminated (e.g., reached opacity threshold or exited the volume). It sets itself apart from sibling methods like [Parallel Ray Casting with Segment Lists](2565-parallel-ray-casting-with-segment-lists.md) by operating on the ray level rather than the voxel/segment level, ensuring that subsequent parallel kernels (such as marching steps) process only valid work units, thereby improving occupancy and reducing divergence.

## How it works
**Inputs and Outputs:**
- Input: `rays_alive_old` (array of ray identifiers or state), `rays_t_old` (array of ray parametric positions), `N` (number of input rays).
- Output: `rays_alive` (contiguous array of alive rays), `rays_t` (contiguous array of corresponding positions), `alive_count` (total number of alive rays).

**Data Structures:**
- `rays_alive_old`: Array of size $N$. Elements are valid ray IDs if the ray is alive, or a sentinel value (e.g., -1) if terminated.
- `rays_t_old`: Array of size $N$. Stores the current parametric position $t$ for each ray.
- `rays_alive`: Array of size $N$ (or dynamically resized). Stores only alive ray IDs.
- `rays_t`: Array of size $N$. Stores $t$ values for alive rays.

**Steps:**
1. Initialize an atomic counter `alive_counter` to 0.
2. For each thread $n$ (corresponding to ray $n$):
   a. Check if `rays_t_old[n] >= 0`. This condition indicates the ray is alive.
   b. If alive, atomically increment `alive_counter` to obtain a new unique index `idx`.
   c. Write `rays_alive_old[n]` to `rays_alive[idx]`.
   d. Write `rays_t_old[n]` to `rays_t[idx]`.
3. After all threads complete, `alive_counter` holds the total number of alive rays.

**Pseudocode:**
```python
def ray_compact(rays_alive_old, rays_t_old, N):
    # Initialize output arrays
    rays_alive = [0] * N
    rays_t = [0] * N
    
    # Atomic counter for compacted indices
    alive_counter = 0
    
    # Parallel loop (conceptual)
    for n in range(N):
        if rays_t_old[n] >= 0:
            # Atomically increment and get index
            idx = atomic_add(alive_counter, 1)
            
            # Compact data
            rays_alive[idx] = rays_alive_old[n]
            rays_t[idx] = rays_t_old[n]
            
    return rays_alive, rays_t, alive_counter
```

**Parameters:**
- Sentinel value: -1 (indicates termination) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Parametric positions $t$ must be compared against 0 with care if floating-point errors are significant. However, the source uses a simple `>= 0` check [S1, unofficial].
- **Boundaries:** The output arrays must be pre-allocated to size $N$ to handle the worst case where all rays survive.
- **Degenerate Input:** If all rays terminate, `alive_counter` is 0, and subsequent kernels must handle empty workloads.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of input rays. Each ray is processed once.
- **Memory Complexity:** $O(N)$ for input and output arrays.
- **Performance:** Improves parallel efficiency by reducing thread divergence in subsequent kernels. The use of `atomicAdd` can cause contention if many rays terminate simultaneously, but this is generally outweighed by the benefit of compacted memory access patterns.
- **Strengths:** Simple to implement on GPUs; effective for dynamic ray termination.
- **Limitations:** Requires atomic operations; does not reorder rays spatially (see [Ray Buffer Reordering](4073-ray-buffer-reordering.md)).

## Background
Ray Compaction is a standard technique in GPU-based volume rendering, particularly in CUDA implementations. It is often used in conjunction with other parallelism strategies to maintain high occupancy. The specific implementation using `atomicAdd` for compaction is documented in unofficial resources [S1, unofficial].
