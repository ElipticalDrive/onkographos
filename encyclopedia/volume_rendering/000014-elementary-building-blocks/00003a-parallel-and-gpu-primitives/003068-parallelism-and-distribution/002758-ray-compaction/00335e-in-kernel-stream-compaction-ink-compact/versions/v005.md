# In-Kernel Stream Compaction (InK-Compact)

Also called: In-Kernel compaction, InK-Compact

## Overview
In-Kernel Stream Compaction (InK-Compact) is a parallel primitive that compacts a stream of valid elements into a contiguous output array while preserving input order, executed entirely within a single GPU kernel as a device function [S1, unofficial]. It solves the performance bottleneck of conventional stream compaction methods (like Thrust or Chag::PP) which require leaving the kernel to launch separate prefix-sum and scatter kernels [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: An array of $N$ elements $X[0 \dots N-1]$ with an associated predicate $P[0 \dots N-1]$ indicating validity [S1, unofficial].
*   Output: An array $Y[0 \dots M-1]$ containing only elements where $P[i]$ is true, preserving their relative order from $X$ [S1, unofficial].
*   Auxiliary: An intermediate buffer $Y'$ of size sufficient to hold block-local outputs and global section management structures [S1, unofficial].

**Data Structures:**
*   **Section Management:** For a kernel divided into $S$ sections, each section $S_i$ has:
    *   `flag` $S_i(f)$: Boolean, initially false, becomes true when section $i$ is ready to write to final output [S1, unofficial].
    *   `offset` $S_i(u)$: Integer, the starting index in the final output array $Y$ for section $i$ [S1, unofficial].
    *   `counter` $S_i(c)$: Integer, atomic counter for the number of blocks in section $i$ that have completed local compaction [S1, unofficial].
*   **Block Counts:** A buffer $B(c)$ to store the total write count $k(c)$ for each block in the current section [S1, unofficial].
*   **Shared Memory:**
    *   `ww(c)[w(n)]`: Stores the total number of valid elements written by each warp in the block [S1, unofficial].
    *   `s(u)[w(n)]`: Stores the warp offset for each warp [S1, unofficial].

**Parameters:**
*   $w(s)$: Warp size, typically 32 threads in CUDA 4.0 [S1, unofficial].
*   $w(n)$: Number of warps within a block [S1, unofficial].
*   $S(N)$: Section size, number of blocks per section. Chosen as 32 to fit bit-decomposition into a single warp [S1, unofficial].

**Algorithm Steps:**

1.  **Thread Offset Computation ($t(u)$):** Each thread $t(i)$ computes its local offset within its warp [S1, unofficial].
    *   Compute warp index: $w(i) = \lfloor t(i) / w(s) \rfloor$ [S1, unofficial].
    *   Compute warp lane: $w(l) = t(i) \pmod{w(s)}$ [S1, unofficial].
    *   Compute thread mask: $t(m) = \text{MAXINT} \gg (w(s) - w(l))$. This mask has bits $0$ to $w(l)-1$ set to 1 [S1, unofficial].
    *   Compute ballot: $b = \text{ballot}(P[t(i)]) \ \& \ t(m)$ [S1, unofficial].
    *   Compute thread offset: $t(u) = \text{popc}(b)$ [S1, unofficial].
    *   Compute warp total: The last thread in the warp ($w(l) = w(s)-1$) computes $w(c) = t(u) + P[t(i)]$ [S1, unofficial].
    *   Store $w(c)$ into shared memory `ww(c)[w(i)]` by the last thread only [S1, unofficial].
    *   Perform memory fence and synchronization `_syncthreads()` to ensure visibility [S1, unofficial].

2.  **Warp Offset Computation ($w_i(u)$):** Compute the offset of the current warp relative to the start of the block [S1, unofficial].
    *   Perform synchronization using `_syncthreads_count()` with each thread's predicate to gather total writes in block and ensure visibility [S1, unofficial].
    *   Perform bit-decomposition scan over $\log_2(w(s))$ bits. For each bit $j$ from $0$ to $\log_2(w(s))-1$:
        *   $b(j) = \text{ballot}(w_i(c) \ \& \ 2^j)$ [S1, unofficial].
        *   Accumulate: $w_i(u) += \text{popc}(b(j) \ \& \ t(m)) \gg j$ [S1, unofficial].
    *   Synchronize `_syncthreads()` to ensure all warps have computed their offsets [S1, unofficial].

3.  **Stage 1: Local Block Compaction:**
    *   Each block computes its local write count $k(c) = \sum w(c)$ [S1, unofficial].
    *   Each thread stores its valid element into the intermediate buffer $Y'$ at index: $\text{index} = (\text{block\_id} \times \text{threads\_per\_block}) + (w(i) \times w(s)) + t(u)$ [S1, unofficial].
    *   A single thread atomically increments the section counter: `atomicAdd(&S_i(c), 1)` [S1, unofficial].
    *   All blocks within the section, except for the section controller block, are allowed to exit the compaction function [S1, unofficial].
    *   The section controller is designated as the block within the section that increments the section-counter $S_i(c)$ to the number of blocks within a section $S(N)$ [S1, unofficial].

4.  **Stage 2: Block Offset Computation:**
    *   The section controller loads the block counts $k(c)$ for all blocks in the section into shared memory [S1, unofficial].
    *   It performs a bit-wise prefix sum scan on these block counts to determine the starting offset for each block within the section [S1, unofficial].
    *   The scan is performed using bit-decomposition over $\log_2(w(s) \times w(n))$ bits, fitting into a single warp if $S(N)=32$ [S1, unofficial].
    *   The total number of valid elements in the section, $t$, is computed [S1, unofficial].
    *   The section offset is calculated: $S_i(u) = S_{i-1}(u) + t$ (for $i>0$). For $S_0$, $S_0(u) = 0$ [S1, unofficial].
    *   The section controller sets the flag $S_i(f) = \text{true}$ after a memory fence [S1, unofficial].

5.  **Stage 3: Section Synchronization:**
    *   Blocks in section $S_i$ (where $i>0$) wait for the flag $S_{i-1}(f)$ to become true [S1, unofficial].
    *   Section $S_0$ proceeds immediately [S1, unofficial].
    *   Once the flag is true, the section controller moves the compacted data from the intermediate buffer $Y'$ to the final output array $Y$ at the computed offset $S_i(u)$ [S1, unofficial].
    *   All blocks in the section then use the block-specific offsets computed in Stage 2 to write their local outputs to the final array $Y$ [S1, unofficial].

**Pseudocode:**

```python
def ink_compact_kernel(input_data, predicates, output_buffer, section_flags, section_offsets, section_counters, intermediate_buffer, block_counts_shared):
    # CUDA helpers defined as standard operations
    def ballot(pred): return 0  # Placeholder for warp-level ballot
    def popc(val): return bin(val).count('1')
    def syncthreads(): pass
    def atomic_add(addr, val): 
        old = section_counters[addr]
        section_counters[addr] += 1
        return old
    def prefix_sum_block_counts(arr, n):
        res = [0]*n
        s = 0
        for i in range(n):
            res[i] = s
            s += arr[i]
        return res

    tid = get_thread_id()
    warp_id = tid // warp_size
    lane_id = tid % warp_size
    
    # Thread mask: bits 0 to lane_id-1 set to 1
    mask = (1 << warp_size) - 1 >> (warp_size - lane_id)
    
    # Ballot for valid threads before current thread
    valid_mask = ballot(predicates[tid]) & mask
    thread_offset = popc(valid_mask)
    
    # Warp total: last thread in warp computes it
    if lane_id == warp_size - 1:
        warp_total = thread_offset + int(predicates[tid])
        shared_warp_totals[warp_id] = warp_total
    syncthreads()
    
    # Warp offset: bit-decomposition scan over log2(warp_size) bits
    warp_offset = 0
    for j in range(int(log2(warp_size))):
        bit_val = shared_warp_totals[warp_id] & (1 << j)
        ballot_result = ballot(bit_val != 0) & mask
        warp_offset += popc(ballot_result) >> j
    syncthreads()
    
    # Stage 1: Local Compaction
    local_idx = (get_block_id() * threads_per_block) + (warp_id * warp_size) + thread_offset
    if predicates[tid]:
        intermediate_buffer[local_idx] = input_data[tid]
        
    my_section_id = get_block_id() // section_size
    old_count = atomic_add(my_section_id, 1)
    is_controller = (old_count == section_size - 1)
    
    if not is_controller:
        return # Exit early to free resources
        
    # Stage 2: Block Offsets (Controller only)
    # Load block counts into shared memory (assumed populated by threads 0 of each block)
    block_offset = prefix_sum_block_counts(block_counts_shared, section_size)
    
    total_valid = block_offset[section_size - 1] + block_counts_shared[section_size - 1]
    
    if my_section_id == 0:
        section_offsets[my_section_id] = 0
    else:
        while not section_flags[my_section_id - 1]:
            pass # Spin wait for previous section
        section_offsets[my_section_id] = section_offsets[my_section_id - 1] + total_valid
        
    memory_fence()
    section_flags[my_section_id] = True
    
    # Stage 3: Write to Final Output
    final_block_offset = section_offsets[my_section_id] + block_offset[get_block_id() % section_size]
    
    # Copy valid elements from intermediate to final
    # Controller handles the scatter from intermediate buffer to final output
    for i in range(threads_per_block):
        start_idx = (get_block_id() * threads_per_block) + i
        if predicates[start_idx]: # Re-check or use stored validity
            output_buffer[final_block_offset + i] = intermediate_buffer[start_idx]
```

## Subtopics

### [Out-of-Kernel Compaction (OfK-Compact)](7270-out-of-kernel-compaction-ofk-compact.md)
Out-of-Kernel Compaction (OfK-Compact) is a stream compaction technique where the compaction logic is executed outside the primary rendering kernel, typically by invoking a host-side library function after the kernel completes. It solves the problem of removing invalid or empty rays from an output array generated by a parallel GPU kernel. Unlike InK-Compact, which performs compaction immediately within the operating kernel to avoid synchronization overhead, OfK-Compact relies on separate kernel launches or library calls, introducing potential bottlenecks but offering a simpler implementation pattern.

### In-Kernel Collation (InK-Collate)
In-Kernel Collation (InK-Collate) is a compromise compaction method that preserves local ordering within a block but not global ordering of kernel blocks, avoiding inter-block dependencies [S1, unofficial]. It computes a kernel offset $k(u)$ using an atomic add on a global counter by thread 0 in the block, then stores output at $t_f = k(u) + s(u)_{w(i)} + t(u)$ [S1, unofficial]. It shows little performance difference from InK-Compact in ray-tracing applications where global order is not strictly required, but avoids the complex section management and synchronization of InK-Compact [S1, unofficial].

### Chag::PP Compaction
Chag::PP Compaction is a conventional out-of-kernel method where kernels output ray indices to an output array in the same location as read, setting non-valid elements to zero/null. After kernel completion, a host-side `Chag::PP.compact` method is called to compact the array [S1, unofficial]. It is slower than InK-Compact [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method performs $O(\log w(s))$ operations per thread for warp offset and $O(\log (w(s) w(n)))$ for block offset, making it efficient for typical warp/block sizes. The overall complexity is dominated by the synchronization and atomic operations, which are minimized by the section-based approach.
*   **Memory Complexity:** Requires an intermediate buffer $Y'$ of size $N$ (or sufficient for block-local outputs) and small shared memory for warp/block counts.
*   **Performance:** On an NVIDIA 480 GTX, InK-Compact is on average 99% faster than Thrust and 28% faster than Chag::PP in a ray-tracing pipeline [S1, unofficial]. When used out-of-kernel, it runs on par with Chag::PP [S1, unofficial].
*   **Strengths:** Eliminates kernel launch overhead, avoids writing invalid elements to global memory, and maintains high thread coherency in multi-kernel pipelines.
*   **Limitations:** Register burden due to running as a device function, though mitigated by register reallocation on architectures like Fermi [S1, unofficial]. Requires careful management of section synchronization.

## Background
In-Kernel Stream Compaction was introduced by D. M. Hughes et al. in 2013 [S1, unofficial]. It was developed to address the inefficiencies of multi-kernel pipelines in GPU ray-tracing, where conventional compaction methods (Thrust, Chag::PP) required leaving the kernel to perform prefix-sum and scatter operations, causing synchronization bottlenecks. The method builds on previous work in warp-level primitives (Billeter, Harris) but introduces bit-decomposition and balloting for inter-warp scans and a novel section-based approach for block-level ordering [S1, unofficial]. It is used in multi-kernel isosurface ray-tracing pipelines for stages such as Generation-Traversal, Traversal-Intersection, Intersection-Traversal, and Intersection-Shade [S1, unofficial].
