# Data Distribution via k-d Trees and Multicast

Also called: Top-down data distribution layout, k-d Tree Based Data Distribution

## Overview
This method is a data distribution strategy for sort-last parallel volume rendering that minimizes network redundancy by assigning volume data based on k-d tree leaf nodes, ensuring each worker node is responsible for exactly one leaf [S1, unofficial]. It differs from its siblings by using a top-down distribution from a master node that holds comprehensive knowledge of the dataset's distribution, rather than relying on static block-splitting or distributed pipeline stages [S1, unofficial]. Unlike [Block-Splitting (BS) method](9229-block-splitting-bs-method.md) which may imply static spatial partitioning without visibility sorting, this approach integrates k-d trees as a visibility sorting structure to guide data assignment [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A volume dataset, a set of worker nodes, a master node, and optionally a parallel file system [S1, unofficial].
*   **Outputs:** Distributed volume data on worker nodes, ready for local rendering and subsequent compositing [S1, unofficial].

**Data Structures:**
*   **k-d Tree:** A binary tree structure used for visibility sorting, where each worker node is responsible for exactly one leaf node [S1, unofficial].
*   **Axis-Aligned Bounding Box (AABB):** Associated with each k-d tree leaf node, defining the spatial extent of the data assigned to a worker [S1, unofficial].
*   **Multicast Group:** A network group identifier used for UDP-based data transmission [S1, unofficial].

**Steps:**
1.  **Tree Construction and Assignment:** A k-d tree is constructed for the volume dataset [S1, unofficial]. Each worker node is assigned responsibility for exactly one leaf node of this tree [S1, unofficial].
2.  **AABB Distribution:** The master node distributes the axis-aligned bounding box (AABB) of each leaf node to the corresponding worker node [S1, unofficial].
3.  **Dataset Location Communication:** The master node communicates the location of the volume dataset on the parallel file system to the worker nodes [S1, unofficial].
4.  **Data Loading (Option A - Parallel File System):** Worker nodes load their own copy of the volume dataset directly from the parallel file system [S1, unofficial]. This imposes network load on the connection between worker nodes and the file server, but allows the master node to be used solely for alpha compositing without storing the dataset permanently [S1, unofficial].
5.  **Data Loading (Option B - Multicast):** The master node sends the whole dataset using IP Multicast [S1, unofficial]. Worker nodes register to the same Multicast group [S1, unofficial]. Each worker node retrieves UDP packages from the Multicast stream [S1, unofficial]. A worker node stores a package permanently only if the data contained in the package is within the AABB of its assigned leaf node [S1, unofficial]. Each worker node allocates enough main memory to accommodate its share of the volume dataset [S1, unofficial].

**Pseudocode:**
```python
def master_distribute(dataset, worker_nodes, k_d_tree):
    # Each worker node is responsible for exactly one leaf node [S1, unofficial]
    assert len(k_d_tree.leaves) == len(worker_nodes)
    for i, leaf in enumerate(k_d_tree.leaves):
        worker = worker_nodes[i]
        # Distribute AABB of the leaf to the responsible worker
        send_message(worker, "AABB", leaf.aabb)
        # Communicate dataset location on parallel file system
        send_message(worker, "FS_PATH", dataset.path)

    # Option B: Multicast distribution
    # Multicast group address and port are not given in the sources [G]
    multicast_group = "239.1.1.1"
    multicast_port = 5000
    join_multicast_group(multicast_group, multicast_port)
    for chunk in dataset.get_chunks():
        send_multicast_packet(multicast_group, multicast_port, chunk)
    # Fallback to TCP per worker if Multicast fails [S1, unofficial]

def worker_receive(worker_id, assigned_leaf, dataset_path):
    aabb = assigned_leaf.aabb
    # Allocate enough main memory to accommodate its share of the volume dataset [S1, unofficial]
    memory_buffer = allocate_memory(aabb.volume)
    # Option A: Load from parallel file system
    load_data_from_filesystem(dataset_path, aabb, memory_buffer)
    # Option B: Receive via Multicast
    multicast_group = "239.1.1.1"
    multicast_port = 5000
    join_multicast_group(multicast_group, multicast_port)
    while True:
        packet = receive_multicast_packet(multicast_group, multicast_port)
        # Store permanently only if contained in the AABB of its leaf node [S1, unofficial]
        if is_within_aabb(packet.data, aabb):
            store_permanently(packet.data, memory_buffer)
        else:
            discard(packet.data)
        # Ensure datagram delivery via additional meta information [S1, unofficial]
        if check_missing_data():
            request_data_via_tcp(worker_id, assigned_leaf)
```

*   **Unreliability of UDP:** IP Multicast uses UDP, which is unreliable [S1, unofficial]. The system ensures datagram delivery by communicating additional meta information [S1, unofficial]. If Multicast fails, the system falls back to sending the dataset to individual worker nodes using TCP [S1, unofficial]. However, because worker nodes are usually in the same local network as the master node, this fallback happens infrequently [S1, unofficial].
*   **Master Node Knowledge:** The master node must maintain comprehensive knowledge of how the dataset is distributed among worker nodes [S1, unofficial].
*   **Memory Allocation:** Worker nodes must allocate enough main memory to accommodate their share of the volume dataset [S1, unofficial].

## Subtopics

### KD-Tree Based Data Partitioning with Clipping
A data partitioning strategy for distributed memory parallel rendering that ensures proper view ordering for all processes by creating a KD-tree and clipping straddling cells to partition boundaries [S2]. Unlike regular grids where KD-tree planes do not intersect cells, unstructured grids require cells to be copied and clipped because KD-tree planes inevitably intersect general unstructured cells [S2]. The process involves creating a KD-tree that partitions cells evenly, identifying cells that straddle multiple KD-tree regions, copying straddling cells to all regions they intersect, and clipping the copied cells by the bounds of each region to ensure every region completely contains all cells within it [S2]. Hardware clipping planes are avoided because they do not support algorithms like projected tetrahedra well, causing artifacts along cutting planes in transparent regions [S2]. This method ensures load balancing as data is split evenly amongst processes cell-wise [S2].
