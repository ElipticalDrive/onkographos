# SHade -> ReSample -> Composite -> ReDistribute

Also called: RD-RS-SH-CO, RD-SH-RS-CO, RS-SH-CO-RD, SH-RS-CO-RD, SH-RS-RD-CO

## Overview
SHade -> ReSample -> Composite -> ReDistribute (SH-RS-CO-RD) is a parallel volume rendering algorithm where each node independently shades its local 3D data, resamples it into 2D projections, performs local compositing, and then redistributes the resulting 2D image sub-images for global compositing [S1, unofficial]. It differs from its siblings by moving 2D image data rather than 3D volume data during the redistribution phase, which reduces the volume of data transferred [S1, unofficial]. Unlike [Associative Image Compositing](9713-associative-image-compositing.md) which blends snapshots, this method explicitly separates the shading/resampling from the final global blend, allowing for distributed or centralized global compositing strategies [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D volume data statically distributed among $N$ nodes. View parameters (camera position, orientation, projection type).
*   **Output:** A single composited 2D image on the screen.

**Data Structures:**
*   **Local Volume Data:** 3D array of voxels, distributed evenly among nodes.
*   **Shaded Data:** 4-tuples (R, G, B, $\alpha$) for each voxel or sample point.
*   **Sub-images:** 2D arrays of pixels (or regions thereof) generated by local compositing.
*   **Global Image:** The final composited frame buffer.

**Steps:**
1.  **Shade:** Each node shades its local 3D data samples to compute R, G, B, $\alpha$ four-tuples [S1, unofficial].
2.  **Resample:** Each node resamples the shaded data to compute its projection onto the view plane. This can be done via ray-casting or splatting [S1, unofficial].
    *   *Ray-casting:* Requires a reconstruction filter kernel with a maximum size such that eight nearest neighbors are sufficient [S1, unofficial].
    *   *Splatting:* Projects volume elements onto the image plane.
3.  **Composite (Local):** Each node performs local compositing of its projected points to generate one or more sub-images. The order is typically front-to-back or back-to-front [S1, unofficial].
4.  **Redistribute:** The sub-images from all nodes are globally collected.
5.  **Composite (Global):** The collected sub-images are composited in front-to-back or back-to-front order to produce the final image [S1, unofficial].

**Pseudocode:**
> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Parallel execution on each node
def node_task(local_voxels, view_params):
    # Step 1: Shade
    shaded_voxels = []
    for voxel in local_voxels:
        color, alpha = shade(voxel, view_params)
        shaded_voxels.append((voxel.position, color, alpha))

    # Step 2: Resample
    # Resampling method: ray-casting or splatting
    projected_points = []
    if use_ray_casting:
        for ray in view_params.rays:
            samples = resample_ray(ray, shaded_voxels)
            projected_points.extend(samples)
    else: # splatting
        for voxel in shaded_voxels:
            splat = splat_voxel(voxel, view_params)
            projected_points.append(splat)

    # Step 3: Local Composite
    sub_image = local_composite(projected_points)

    # Step 4 & 5: Redistribute and Global Composite
    # This part is handled by the communication layer and global compositor
    return sub_image

def global_compositor(all_sub_images):

    # Composite them in front-to-back or back-to-front order
    final_image = global_composite(all_sub_images)
```

**Parameters:**
*   **Macro Size:** In the Goldwasser et al. implementation, the macro size was $64^3$ [S1, unofficial].
*   **Resampling Method:** Ray-casting with interpolation or splatting [S1, unofficial].
*   **Compositing Order:** Front-to-back or back-to-front [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Load Balance:** Load balance is statically set by data distribution since no 3D data samples move. It depends on efficiency techniques at each node and the view-dependent compositing sequence [S1, unofficial]. Medium granularity random or interleaved macro grouping improves load balance due to spatial coherence of interesting voxels, but increases memory requirement and redistribution cost [S1, unofficial].
*   **Centralized vs. Distributed Compositing:** Centralized compositing is a serial operation and may be a poor match for machines with many nodes [S1, unofficial]. Distributed compositing allows parallel processing of sub-regions but requires complex coordination [S1, unofficial].
*   **Alpha Cutoff:** Alpha cutoff efficiencies can be realized in distributed compositing if sub-region propagation prioritizes ray scheduling [S1, unofficial].

## Subtopics

### SH-RD-RS-CO
A variant where shading is performed locally, then data is redistributed, followed by resampling and global compositing [S1, unofficial]. Unlike SH-RS-CO-RD, this moves 3D volume data (macros) rather than 2D image data, which increases the volume of data transferred [S1, unofficial]. It allows perspective projections and arbitrary resampling points because resampling is done after redistribution [S1, unofficial]. Implemented by Westover (1989) and Levoy (1989) on Pixel-Planes 5 [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Includes average number of data samples at each node, shaded and resampled points (same count as samples), screen region memory, and memory for incoming regions in distributed compositing (at least size of own region) [S1, unofficial].
*   **Communication:** Each node may produce a full screen array of pixels as its sub-image if slab-shaped macros are used, requiring each node to send and receive an entire screen array. More cubic macro aspect ratios produce smaller sub-images and lower bandwidth requirements [S1, unofficial].

**Measured Performance:**
*   Not explicitly given for SH-RS-CO-RD in the sources, but related variants achieved 1.4 frames per second for $128^3$ data sets on Pixel-Planes 5 [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Reduces data transfer volume by moving 2D image data instead of 3D volume data [S1, unofficial]. Supports alpha cutoff, adaptive refinement, and octtrees within a node's local data [S1, unofficial].
*   **Limitations:** Centralized compositing is a serial bottleneck [S1, unofficial]. Load balance is static and may vary due to transparent macros affecting resampling and compositing effort [S1, unofficial].

**When to Use:**
*   Use when network bandwidth is limited and 2D image data is smaller than 3D volume data.
*   Use when local shading and resampling can be efficiently parallelized.

**When Not to Use:**
*   Do not use when dynamic load balancing is critical and data distribution is uneven or view-dependent.
*   Do not use when perspective projections require resampling after redistribution (use SH-RD-RS-CO instead).

## Background
**Origin:**
*   Implemented by Goldwasser et al. in 1985 in custom hardware with a macro size of $64^3$ [S1, unofficial].
*   Used by Yazdy et al. in 1990 on an array of transputers [S1, unofficial].
*   Described as a general approach in the taxonomy of volume rendering algorithms on multicomputers [S1, unofficial].

**History and Development:**
*   Part of a taxonomy of 8 possible orderings of Shade, Resample, Composite, and Redistribute tasks [S1, unofficial].
*   The method is one of the four primary approaches analyzed in the taxonomy, distinguished by moving 2D image data during redistribution [S1, unofficial].
