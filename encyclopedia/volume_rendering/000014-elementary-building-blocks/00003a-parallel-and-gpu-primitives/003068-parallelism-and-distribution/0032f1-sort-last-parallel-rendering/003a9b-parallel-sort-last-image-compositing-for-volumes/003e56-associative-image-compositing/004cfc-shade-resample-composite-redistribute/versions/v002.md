# SHade -> ReSample -> Composite -> ReDistribute

Also called: RD-RS-SH-CO, RD-SH-RS-CO, RS-SH-CO-RD, SH-RS-CO-RD, SH-RS-RD-CO

## Overview
SHade -> ReSample -> Composite -> ReDistribute (SH-RS-CO-RD) is a parallel volume rendering algorithm where each node independently shades its local 3D data, resamples it into 2D projections, performs local compositing, and redistributes the resulting 2D image sub-images for global compositing [S1, unofficial]. It differs from its siblings by moving 2D image data rather than 3D volume data during the redistribution phase, which reduces the volume of data transferred [S1, unofficial]. Unlike [Associative Image Compositing](9713-associative-image-compositing.md), which blends snapshots of sub-volumes, this method explicitly separates shading and resampling from the final global blend, supporting both distributed and centralized global compositing strategies [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** 3D volume data statically distributed evenly among $N$ nodes, and view parameters [S1, unofficial].
*   **Output:** A single composited 2D image on the screen [S1, unofficial].

**Data Structures:**
*   **Local Volume Data:** 3D array of voxels, distributed evenly among nodes [S1, unofficial].
*   **Shaded Data:** 4-tuples (R, G, B, $\alpha$) for each voxel or sample point [S1, unofficial].
*   **Sub-images:** 2D arrays of pixels (or regions thereof) generated by local compositing [S1, unofficial].
*   **Global Image:** The final composited frame buffer [S1, unofficial].

**Steps:**
1.  **Shade:** Each node shades its local 3D data samples to compute R, G, B, $\alpha$ four-tuples [S1, unofficial].
2.  **Resample:** Each node resamples the shaded data to compute its projection onto the view plane [S1, unofficial]. This can be done via ray-casting or splatting [S1, unofficial]. Ray-casting requires a reconstruction filter kernel with a maximum size such that eight nearest neighbors are sufficient [S1, unofficial]. Splatting projects volume elements onto the image plane [S1, unofficial].
3.  **Composite (Local):** Each node performs local compositing of its projected points to generate one or more sub-images [S1, unofficial]. The order is typically front-to-back or back-to-front [S1, unofficial].
4.  **Redistribute:** The sub-images from all nodes are globally collected [S1, unofficial].
5.  **Composite (Global):** The collected sub-images are composited in front-to-back or back-to-front order to produce the final image [S1, unofficial].

**Pseudocode:**
```python
def node_task(local_voxels, view_params):
    # Step 1: Shade
    shaded_voxels = []
    for voxel in local_voxels:
        rgba = compute_shading(voxel, view_params)
        shaded_voxels.append((voxel.position, rgba))

    # Step 2: Resample
    projected_points = []
    if view_params.method == "ray_casting":
        for ray in view_params.rays:
            for step in ray.steps:
                if not step.shaded:
                    shade_step_neighbors(step, shaded_voxels)
                sample = resample_step(step, shaded_voxels)
                projected_points.append(sample)
    else: # splatting
        for voxel in shaded_voxels:
            splat = splat_voxel(voxel, view_params)
            projected_points.append(splat)

    # Step 3: Local Composite
    sub_image = local_composite(projected_points, view_params.tile)

    # Step 4: Redistribute
    return sub_image
```

**Parameters:**
*   **Macro Size:** In the Goldwasser et al. implementation, the macro size was $64^3$ [S1, unofficial].
*   **Resampling Method:** Ray-casting with interpolation or splatting [S1, unofficial].
*   **Compositing Order:** Front-to-back or back-to-front [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Load Balance:** Load balance is statically set by the data distribution since no 3D data samples move. It depends on the relative effects of the efficiency techniques at each node, and the view dependent compositing sequence [S1, unofficial]. Medium granularity random or interleaved macro grouping improves load balance due to spatial coherence of interesting voxels, but increases memory requirement and redistribution cost [S1, unofficial].
*   **Centralized vs. Distributed Compositing:** Centralized compositing is a serial operation and may be a poor match for machines with many nodes [S1, unofficial]. Distributed compositing allows parallel processing of sub-regions but requires complex coordination [S1, unofficial].
*   **Alpha Cutoff:** Alpha cutoff efficiencies can be realized in distributed compositing if sub-region propagation prioritizes ray scheduling [S1, unofficial].

## Subtopics

### SH-RD-RS-CO
A variant where shading is performed locally, then data is redistributed, followed by resampling and global compositing [S1, unofficial]. Unlike SH-RS-CO-RD, this moves 3D volume data (macros) rather than 2D image data, which increases the volume of data transferred [S1, unofficial]. It allows perspective projections and arbitrary resampling points because resampling is done after redistribution [S1, unofficial]. Implemented by Westover (1989) and Levoy (1989) on Pixel-Planes 5 [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Includes average number of data samples at each node, shaded and resampled points (same count as samples), screen region memory, and memory for incoming regions in distributed compositing (at least size of own region) [S1, unofficial].
*   **Communication:** Each node may produce a full screen array of pixels as its sub-image if slab-shaped macros are used, requiring each node to send and receive an entire screen array. More cubic macro aspect ratios produce smaller sub-images and lower bandwidth requirements [S1, unofficial].

**Measured Performance:**
*   Not explicitly given for SH-RS-CO-RD in the sources, but related variants achieved 1.4 frames per second for $128^3$ data sets on Pixel-Planes 5 [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Reduces data transfer volume by moving 2D image data instead of 3D volume data [S1, unofficial]. Supports alpha cutoff, adaptive refinement, and octtrees within a node's local data [S1, unofficial].
*   **Limitations:** Centralized compositing is a serial bottleneck [S1, unofficial]. Load balance is statically set by the data distribution since no 3D data samples move. It depends on the relative effects of the efficiency techniques at each node, and the view dependent compositing sequence [S1, unofficial].

## Background
**Origin:**
*   Implemented by Goldwasser et al. in 1985 in custom hardware with a macro size of $64^3$ [S1, unofficial].
*   Used by Yazdy et al. in 1990 on an array of transputers [S1, unofficial].
*   Described as a general approach in the taxonomy of volume rendering algorithms on multicomputers [S1, unofficial].

**History and Development:**
*   Part of a taxonomy of 8 possible orderings of Shade, Resample, Composite, and Redistribute tasks [S1, unofficial].
*   The method is one of the four primary approaches analyzed in the taxonomy, distinguished by moving 2D image data during redistribution [S1, unofficial].
