# Associative Image Compositing

Also called: Concurrent Composition Operator F, Parallel Image Compositing with Associative Operator

## Overview
Associative Image Compositing is a method for blending snapshots of sub-volumes rendered independently by distributed nodes, allowing any geometrically coherent group of sub-volumes to be blended together while respecting distance/priority order [S1, unofficial]. It sets itself apart from sibling methods like [SH-RS-CO-RD](13370-shade-resample-composite-redistribute.md) by treating the compositing step as a direct blend of rendered snapshots rather than separating shading/resampling from global blending, effectively extending classic ray casting to distributed environments by replacing geometric surfaces with images [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of sub-images $i_1, i_2, \dots, i_n$, where each sub-image $i_k$ contains an accumulated color $C_{i_k}$ and accumulated opacity $\alpha_{i_k}$ for every pixel [S1, unofficial]. The sub-images must be geometrically coherent and ordered by their distance to the viewpoint (priority order) [S1, unofficial].
*   **Output:** A single composite image with accumulated color $C_{total}$ and accumulated opacity $\alpha_{total}$ [S1, unofficial].

**Data Structures:**
Each sub-image $i$ is represented as a pair $(C_i, \alpha_i)$, where:
*   $C_i$: A vector representing the accumulated color (typically RGB) [S1, unofficial].
*   $\alpha_i$: A scalar value in the range $[0, 1]$ representing the accumulated opacity [S1, unofficial].

**The Concurrent Composition Operator F:**
The core of the method is the operator $F$, which combines two sub-images $i_1$ and $i_2$ [S1, unofficial]. The operator is defined as [S1, unofficial]:

$$F(i_1, i_2) = (C_{i_1} + (1 - \alpha_{i_1})C_{i_2}, \alpha_{i_1} + (1 - \alpha_{i_1})\alpha_{i_2})$$

Where:
*   $i_1$ is the sub-image closer to the viewpoint (higher priority).
*   $i_2$ is the sub-image further from the viewpoint (lower priority).
*   $C_{i_1}, \alpha_{i_1}$ are the color and opacity of $i_1$.
*   $C_{i_2}, \alpha_{i_2}$ are the color and opacity of $i_2$.

**Numbered Steps:**
1.  **Render Sub-volumes:** Each distributed node renders its assigned sub-volume independently, producing a snapshot (sub-image) for each pixel [S1, unofficial]. This snapshot consists of the accumulated color $C$ and accumulated opacity $\alpha$ along the ray segment within that sub-volume [S1, unofficial].
2.  **Order Sub-images:** For each pixel, identify the set of sub-images covering that pixel [S1, unofficial]. Sort these sub-images based on their distance to the viewpoint (priority order) [S1, unofficial]. Let the sorted sequence be $i_1, i_2, \dots, i_k$, where $i_1$ is closest and $i_k$ is furthest [S1, unofficial].
3.  **Apply Associative Composition:** Combine the sorted sub-images using the operator $F$ [S1, unofficial]. Due to the associativity of $F$, the order of application does not affect the final result, enabling parallel reduction [S1, unofficial]. The composite result for a pixel is:
    $$Result = F(\dots F(F(i_1, i_2), i_3) \dots, i_k)$$
    Alternatively, using the associative property, any grouping can be used:
    $$Result = F(i_1, F(i_2, F(i_3, \dots, i_k)\dots))$$
4.  **Output Composite Image:** The resulting $(C_{total}, \alpha_{total})$ for each pixel forms the final composite image [S1, unofficial].

**Pseudocode:**
```python
def compose_subimages(subimages):
    """
    Compose a list of subimages using the associative operator F.
    subimages: list of tuples (C, alpha), ordered by distance to viewpoint (closest first).
    C is a vector/list of color components. alpha is a scalar.
    Returns: (C_total, alpha_total)
    """
    if not subimages:
        return ([0.0, 0.0, 0.0], 0.0)
    
    current_C, current_alpha = subimages[0]
    
    for i in range(1, len(subimages)):
        next_C, next_alpha = subimages[i]
        
        # Apply operator F: F(i1, i2) where i1 is current (closer), i2 is next (further)
        # C_new = C_current + (1 - alpha_current) * C_next
        # alpha_new = alpha_current + (1 - alpha_current) * alpha_next
        new_alpha = current_alpha + (1.0 - current_alpha) * next_alpha
        new_C = [c1 + (1.0 - current_alpha) * c2 for c1, c2 in zip(current_C, next_C)]
        
        current_C = new_C
        current_alpha = new_alpha
        
    return (current_C, current_alpha)

def parallel_composite(all_subimages_per_pixel):
    """
    For each pixel, compose its subimages.
    all_subimages_per_pixel: dict mapping pixel_id to list of (C, alpha) tuples, sorted by distance.
    Returns: dict mapping pixel_id to (C_total, alpha_total)
    """
    composite_image = {}
    for pixel_id, subimages in all_subimages_per_pixel.items():
        composite_image[pixel_id] = compose_subimages(subimages)
    return composite_image
```

**Parameters:**
*   **Distance Order:** Critical. The operator is not commutative; $F(i_1, i_2) \neq F(i_2, i_1)$ if $i_1$ and $i_2$ are at different depths [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-commutativity:** Applying $F$ in the wrong order (e.g., furthest first) yields an incorrect result [S1, unofficial].
*   **Precision:** Accumulated opacity $\alpha$ should be clamped to $[0, 1]$ to avoid numerical issues [G].

## Subtopics

### [SHade -> ReSample -> Composite -> ReDistribute](13370-shade-resample-composite-redistribute.md)
Moves 2D image data during redistribution, reducing transfer volume compared to 3D data movement. Unlike Associative Image Compositing, it explicitly separates shading/resampling from global blending, allowing for distributed or centralized global compositing strategies.

## Operating characteristics
*   **Time Complexity:** The compositing step for each pixel is linear in the number of sub-images covering that pixel, $O(k)$, where $k$ is the number of sub-images [S1, unofficial]. Due to associativity, this can be parallelized using a tree reduction, reducing the critical path to $O(\log k)$ [G].
*   **Measured Performance:** Rendering time for a given image size is roughly proportionate to the size of the volume rendered [S1, unofficial].
*   **Strengths:** Allows independent rendering of sub-volumes, enabling efficient parallelization. The associativity of $F$ ensures arithmetic equivalence to serial composition, simplifying parallel implementation [S1, unofficial].
*   **Limitations:** Requires careful handling of depth ordering. Not commutative, so order matters [S1, unofficial].
*   **When to Use:** When rendering large volumes distributed across multiple nodes where independent rendering of sub-volumes is beneficial, and geometric coherence allows for clear depth ordering [S1, unofficial].

## Background
The method was proposed by Lombeyda et al. [71] (cited in [S1, unofficial]), who demonstrated the arithmetic equivalence of a single ray casting composite computation and the combined result of a set of smaller composite computations [S1, unofficial]. The concept extends classic ray casting to distributed environments by treating distributed ray casting as an extension of classic ray casting, where geometric surfaces are replaced with images from sub-volumes [S1, unofficial].
