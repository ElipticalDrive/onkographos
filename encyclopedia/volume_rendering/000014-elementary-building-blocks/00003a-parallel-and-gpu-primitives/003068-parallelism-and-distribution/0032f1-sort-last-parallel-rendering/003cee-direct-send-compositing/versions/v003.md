# Direct Send Compositing

Also called: Direct send

## Overview
Direct send compositing is a parallel image compositing method for sort-last rendering that divides the final image into $n$ screen-space tiles to avoid exchanging full-size images [S2, unofficial]. Each processor is associated with compositing one tile and sends all other tiles from the full-size image it rendered to the respective processors [S2, unofficial]. It sets itself apart from hierarchical methods like [Binary swap](7162-binary-swap.md) by using a single all-to-all communication stage rather than a multi-step tree, making it robust even with expensive synchronization mechanisms [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: $n$ partial images (one per processor), where each partial image contains the rendered contribution for the entire volume but is logically divided into $n$ tiles [S2, unofficial].
- Output: $n$ composited tiles, which are then gathered to form the final image [S2, unofficial].

**Data Structures:**
- The final image is divided into $n$ equal-sized tiles in screen space [S2, unofficial].
- Each processor $P_i$ holds a local buffer containing the $n$ tiles it rendered [G]. Let $T_{i,j}$ be the tile $j$ rendered by processor $i$ [G].

**Steps:**
1. **All-to-All Exchange:** Each processor $P_i$ sends its tile $T_{i,j}$ to processor $P_j$ for all $j \neq i$ [S2, unofficial]. Processor $P_i$ also retains its own tile $T_{i,i}$ [G]. This constitutes one communication stage [S2, unofficial].
2. **Independent Compositing:** Once all tiles have arrived, each processor $P_j$ composites its assigned tile $T_{j,j}$ independently [S2, unofficial]. The compositing operation involves blending the incoming tiles $T_{i,j}$ (for all $i$) into the target tile $T_{j,j}$ using standard front-to-back or back-to-front volume compositing equations [G].
3. **Gathering:** The composited tiles are sent to a master process for final assembly [S2, unofficial].

**Parameters:**
- Number of processors $n$ [S2, unofficial].
- Tile size: Typically $1/n$ of the total image area [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Synchronization:** The algorithm has two synchronization points: one after the exchange and one after gathering [S2, unofficial]. It works well even if synchronization is expensive because there are no intermediate synchronization barriers during the compositing phase [S2, unofficial].
- **Network Congestion:** In the worst case, $n(n-1)$ messages are sent [S2, unofficial]. On low-bandwidth networks, this many-to-many pattern can cause bottlenecks [S3].
- **Optimization:** The algorithm can be tuned to send only pixels that need compositing (e.g., those with non-zero opacity), reducing the average number of exchanging nodes to $n$ [S2, unofficial].

**Pseudocode:**
```python
def direct_send_compositing(n, my_id, my_tiles):
    """
    my_tiles: list of n tiles, where my_tiles[i] is the tile i rendered by this processor.
    n: total number of processors.
    """
    # Step 1: All-to-All Exchange
    received_tiles = all_to_all_exchange(my_tiles, n, my_id)
    
    # Step 2: Independent Compositing
    composited_tile = composite_tile(received_tiles, target_tile_index=my_id)
    
    # Step 3: Gathering
    send_to_master(composited_tile, master_id=0)
    
    return composited_tile

def all_to_all_exchange(local_tiles, n, my_id):
    """Simulates an MPI_Alltoall collective operation."""
    received = [None] * n
    for pid in range(n):
        if pid == my_id:
            received[pid] = local_tiles[pid]
        else:
            # Simulate blocking network communication
            received[pid] = network_recv(pid)
            network_send(local_tiles[pid], pid)
    return received

def composite_tile(tiles, target_tile_index):
    """
    Composite a single tile from a list of tiles from different processors.
    Uses standard front-to-back volume compositing.
    """
    output_tile = create_empty_tile(tiles[0].width, tiles[0].height)
    for tile in tiles:
        output_tile = blend(output_tile, tile)
    return output_tile

def create_empty_tile(width, height):
    """Returns a 2D array initialized to zero (fully transparent)."""
    return [[0.0, 0.0, 0.0, 0.0] for _ in range(height)]

def blend(src, dst):
    """
    Standard front-to-back compositing.
    src: incoming tile (C_s, alpha_s)
    dst: accumulated tile (C_d, alpha_d)
    Returns new accumulated tile.
    """
    new_alpha = src.alpha + dst.alpha * (1.0 - src.alpha)
    if new_alpha > 0:
        new_color = (src.color * src.alpha + dst.color * dst.alpha * (1.0 - src.alpha)) / new_alpha
    else:
        new_color = src.color
    return Tile(new_color, new_alpha)

def send_to_master(tile, master_id):
    """Sends the composited tile to the designated master process."""
    network_send(tile, master_id)

def network_send(data, target_id):
    """Standard blocking send to target_id."""
    pass

def network_recv(source_id):
    """Standard blocking receive from source_id."""
    pass

class Tile:
    def __init__(self, color, alpha):
        self.color = color  # RGB tuple
        self.alpha = alpha  # Float [0, 1]
        self.width = 0
        self.height = 0
```

## Subtopics

### [Tiling Compositing](12057-tiling-compositing.md)
Tiling Compositing is a parallel compositing strategy for distributed volume rendering where processing elements (PEs) hold tiles of the final image and pass partial results to adjacent PEs in a staggered, linear fashion to merge them into the final image. It builds on [Direct Send Compositing](9377-direct-send-compositing.md) by organizing the compositing traffic into a linear chain of tiles rather than exchanging full-size images. Unlike the inverted binary tree method, which leaves many PEs idle in later cycles, tiling keeps all PEs working until the final image is completed.

### SLIC Parallel Image Compositing
SLIC is an optimized parallel image compositing algorithm for sort-last rendering that minimizes the number of messages exchanged among processors using a view-dependent precomputed compositing schedule [S3]. It builds on [Direct Send Compositing](9377-direct-send-compositing.md) by replacing the all-to-all exchange with a minimal message set [S3]. The preprocessing step to compute the schedule introduces very low overhead, generally under 10 milliseconds [S3]. SLIC outperforms previous algorithms, especially for high-resolution images (1024x1024 pixels or larger) [S3]. On low-bandwidth networks, care must be taken to avoid the many-to-one or many-to-many communication patterns inherent in direct send [S3].

## Operating characteristics
- **Time Complexity:** The communication phase involves $O(n^2)$ messages in the worst case [S2, unofficial]. However, with optimization (sending only necessary pixels), the average number of exchanging nodes is reduced to $n$ [S2, unofficial].
- **Memory Complexity:** Each processor stores $n$ tiles, so memory usage scales linearly with the number of processors relative to the tile size [G].
- **Performance:** Direct send works well even with expensive synchronization due to its single communication step [S2, unofficial]. As processor count increases, tiles become smaller, potentially reducing communication volume [S2, unofficial].
- **Strengths:** Simple to implement, does not require special network topology, robust to synchronization costs [S3].
- **Limitations:** Can cause network congestion on low-bandwidth networks due to many-to-many communication [S3]. Worst-case message count is $n(n-1)$ [S2, unofficial].
- **When to use:** Suitable for high-performance clusters with high-bandwidth networks where simplicity and low synchronization overhead are prioritized [S3].
- **When not to use:** Unsuitable for low-bandwidth networks or when the number of processors is very large without optimization, due to potential communication bottlenecks [S3].

## Background
Direct send compositing was introduced as a parallel compositing method for sort-last rendering [S2, unofficial]. It has been used in various research contexts, including [Hsu93, Neu94, MC97], because it is easy to implement and does not require a special network topology [S3]. It is a foundational method for parallel image compositing, serving as the basis for more optimized variants like SLIC [S3].
