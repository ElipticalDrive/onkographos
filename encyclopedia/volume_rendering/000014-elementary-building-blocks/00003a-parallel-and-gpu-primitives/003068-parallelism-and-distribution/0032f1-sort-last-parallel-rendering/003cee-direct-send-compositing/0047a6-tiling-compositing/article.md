# Tiling Compositing

Also called: Linear Tiling, Staggered Tiling

## Overview
Tiling Compositing is a parallel compositing strategy for distributed volume rendering where processing elements (PEs) hold tiles of the final image and pass partial results to adjacent PEs in a staggered, linear fashion to merge them into the final image [S1, unofficial]. Unlike the inverted binary tree method, which leaves a majority of PEs idle during latter cycles, tiling keeps all PEs working on the problem until the final image is completed [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** $n$ processing elements (PEs), indexed $0$ to $n-1$. Each PE $i$ initially holds a local tile $T_i$ of the final image [S1, unofficial].
*   **Output:** A fully composited final image distributed across the PEs [S1, unofficial].

**Data Structures:**
*   **Tile ($T_i$):** A 2D array of pixels representing a portion of the screen. For typical views, a tile might be 100 pixels wide with 4 floating-point values per pixel, totaling ~150 KB [S3].

**Parameters:**
*   $n$: The number of processing elements in the system [S1, unofficial].
*   Cycle count: $n-1$ cycles are required to complete the compositing [S1, unofficial].

**Steps:**
1.  **Initialization:** Each PE $i$ holds its local tile $T_i$ [S1, unofficial].
2.  **Loop over Cycles:** Repeat for $c = 0$ to $n-2$:
    a.  **Communication:** Each PE sends its current tile to its right neighbor and receives a tile from its left neighbor [S1, unofficial]. In each of the $n-1$ cycles, $n$ messages are sent across the network (each PE must receive one message) [S1, unofficial].
    b.  **Compositing:** The PE composites the received tile with its local tile [S1, unofficial]. The standard volume rendering compositing operation (e.g., front-to-back alpha compositing) is applied [G].
3.  **Termination:** After $n-1$ cycles, all tiles have been propagated and composited across the network [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Network Contention:** Network contention becomes a severe concern due to the high volume of traffic: $n$ messages are sent across the network in every cycle [S1, unofficial].
*   **Memory Contention:** Memory contention is eliminated by the staggered nature of the tiling approach [S1, unofficial].
*   **Small $n$:** For 8 or fewer PEs, there is no discernible difference in compositing times compared to the inverted binary tree method [S1, unofficial].

## Subtopics

### Hybrid Extensions (Stacked Tiles)
A technique that generalizes screen tiles to be composites of multiple stacked tiles, adding an additional composite phase at the end of rendering algorithms to allow machines with many nodes to maintain larger tiles and minimize volume data replication during redistribution [S2, unofficial]. This technique allows machines with large numbers of nodes to maintain larger tiles, thereby minimizing the replication of volume data during redistribution compared to using smaller tiles [S2, unofficial].

### Two-Step Global Gather (Projection then Composition)
A method to perform the global gather operation with minimal communication by keeping volume blocks stationary (except for load balancing) and transferring the 2D tiles generated by projection, rather than transferring 3D volume blocks [S3]. Step 1 (Projection): Each node generates projected two-dimensional tiles from the blocks it holds [S3]. Step 2 (Composition): Overlapping sets of tiles are collected at some location to be composited together [S3]. An image partition is used to assign single large regions of the screen to processors for the composition step; each processor receives a copy of all tiles that overlap its region of the screen [S3]. This method transfers tiles rather than blocks because typical blocks (2-4 MB) are larger than typical tiles (150 KB) [S3]. It differs from the alternative image partition method where volume blocks are sent to nodes, which may require the entire dataset to move for each frame [S3].

## Operating characteristics
*   **Time Complexity:** The algorithm requires $n-1$ communication cycles, where $n$ is the number of PEs [S1, unofficial].
*   **Memory Contention:** Memory contention is eliminated by the staggered nature of the tiling approach [S1, unofficial].
*   **Network Traffic:** $n$ messages are sent across the network in every cycle, leading to high network occupancy [S1, unofficial].
*   **Performance:** For 8 or fewer PEs, there is no discernible difference in compositing times compared to the inverted binary tree method [S1, unofficial]. As the number of PEs increases, the tiling approach is superior because it keeps all PEs working, whereas the inverted binary tree leaves a majority of PEs idle during latter cycles [S1, unofficial].
*   **Strengths:** Eliminates memory contention; maintains high PE utilization for large $n$ [S1, unofficial].
*   **Limitations:** Severe network contention due to high message volume [S1, unofficial].
*   **When to use:** Suitable for large-scale systems with many PEs where PE utilization is critical and network bandwidth is sufficient to handle the linear traffic pattern [S1, unofficial].
*   **When not to use:** Unsuitable for small numbers of PEs (≤8) where the overhead is not justified, or in systems with severe network contention issues [S1, unofficial].

## Background
Tiling Compositing was examined in the context of high-resolution interactive volume rendering on the Cray T3D [S1, unofficial]. It was compared against an inverted binary tree method for compositing partially completed raster images in a distributed memory environment [S1, unofficial]. The approach is intuitively appropriate for distributed systems as it keeps all processing elements working on the problem until the final image is completed [S1, unofficial].
