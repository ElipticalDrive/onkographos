# Rotate-Tiling (RT) Method

Also called: RT method

## Overview
The Rotate-Tiling (RT) method is a sort-last parallel volume rendering compositing algorithm where the number of processors ($P$) and the number of initial image blocks ($N$) are arbitrary positive integers [S1, unofficial]. It solves the performance optimization problem of image compositing by deriving send/receive equations based on the indexing operations of the Block-Splitting (BS) method and the ring rotation topology of the Parallel Pipeline (PP) method [S1, unofficial]. Unlike the BS method, which fixes $N=2$ and requires $P$ to be a power of two, the RT method allows $N$ to vary, enabling performance tuning for any $P$ [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   $P$: Number of processors ($P > 0$).
    *   $A$: Final image size in pixels.
    *   $N$: Number of initial blocks per partial image ($N > 0$).
    *   $T_s$: Startup time of a communication channel.
    *   $T_p$: Data transmission time per byte.
    *   $T_o$: Computation time of the “over” operation per pixel.
*   **Outputs**: A composite final image distributed across $P$ processors.

**Data Structures**
*   **Partial Image**: Each processor $P_r$ (rank $r$, $0 \le r \le P-1$) holds a partial image $A$ [S1, unofficial].
*   **Blocks**: The partial image is divided into $N$ equal blocks [S1, unofficial].
*   **Notation**: $A_r^k(b)$ represents the block of processor $P_r$ with block number $b$ in the $k$-th communication step [S1, unofficial].
    *   $0 \le b \le N-1$ (initially), expanding as compositing proceeds [S1, unofficial].
    *   $0 \le r \le P-1$ [S1, unofficial].
    *   $1 \le k \le \lceil \log_2 P \rceil$ [S1, unofficial].

**Algorithm Steps**
1.  **Initialization**: Each processor $P_r$ partitions its partial image $A$ into $N$ equal blocks, numbered $A_r^1(0)$ to $A_r^1(N-1)$ [S1, unofficial].
2.  **Communication Loop**: For each communication step $k$ from $1$ to $\lceil \log_2 P \rceil$:
    a.  **Determine Partners**: Each processor $P_r$ calculates the rank of the processor to send to ($P_i$) and the rank of the processor to receive from ($P_j$), along with the block indices $m$ (send) and $n$ (receive), using the equations below [S1, unofficial].
    b.  **Send/Receive**: $P_r$ sends block $A_r^k(m)$ to $P_i$ and receives block $A_j^k(n)$ from $P_j$ [S1, unofficial].
    c.  **Composite**: $P_r$ composites the received block $A_j^k(n)$ with its local block $A_r^k(n)$ using the standard volume rendering "over" operation [S1, unofficial].
    d.  **Tiling (Partition)**: For each block $A_r^k(b)$ held by $P_r$, divide it into two equal sub-blocks: $A_r^{k+1}(2b)$ and $A_r^{k+1}(2b+1)$ [S1, unofficial].

**Formulas**
The send and receive indices are calculated as follows, where $l = 0 \dots k-1$, $w = 0 \dots P/N - 1$, and $v = 0 \dots P/2 - 1$:

**Send Equation**:
$$ m = ((r - 2 + 2l) \bmod 2^k) \times 2^{k-1} + v \times 2^{k-1} + l + P \times w $$
$$ i = (r - 2 + l) \bmod P $$
Processor $P_r$ sends block $A_r^k(m)$ to processor $P_i$ [S1, unofficial].

**Receive Equation**:
$$ n = ((r + l) \bmod 2^k) \times 2^{k-1} + v \times 2^{k-1} + l + P \times w $$
$$ j = (r + 2 - l) \bmod P $$
Processor $P_r$ receives block $A_j^k(n)$ from processor $P_j$ [S1, unofficial].

**Block Size Evolution**:
Let $B_k$ be the number of blocks associated with the tiling hierarchy at step $k$ [S1, unofficial].
*   $B_1 = N$
*   For $k > 1$: $B_k = B_{k-1} - \lfloor B_{k-1} / P \rfloor$ [S1, unofficial].
The size of the block sent/received in step $k$ is proportional to $A \cdot B_k / 2^{k-1}$ [S1, unofficial].

**Total Time Complexity**:
The total compositing time $T_{RT}(N)$ is given by:
$$ T_{RT}(N) = \left( \sum_{k=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_k}{P} \right\rceil + \left\lceil \frac{A}{P} \right\rceil - \left\lceil \frac{N}{P} \right\rceil \right) T_s + N \left( \sum_{k=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_k}{P} \right\rceil \frac{1}{2^{k-1}} + \left\lceil \frac{2N}{P} \right\rceil - \left\lceil \frac{N}{P} \right\rceil \right) (T_p + T_o) $$
where $B_k$ depends on $N$ [S1, unofficial].

**Optimization of N**:
To find the optimal $N$, calculate the difference $\Delta T = T_{RT}(N+1) - T_{RT}(N)$ [S1, unofficial]. Set $\Delta T = 0$ to solve for the theoretical best $N$ [S1, unofficial]. The equation is:
$$ \left( \sum_{k'=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_{k'}}{P} \right\rceil + \left\lceil \frac{A}{P} \right\rceil - \left\lceil \frac{N+1}{P} \right\rceil \right) - \left( \sum_{k=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_k}{P} \right\rceil + \left\lceil \frac{A}{P} \right\rceil - \left\lceil \frac{N}{P} \right\rceil \right) + (N+1)\left(\sum_{k'=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_{k'}}{P} \right\rceil \frac{1}{2^{k'-1}} + \left\lceil \frac{2N+2}{P} \right\rceil - \left\lceil \frac{N+1}{P} \right\rceil \right) - N\left(\sum_{k=1}^{\lceil \log_2 P \rceil} \left\lceil \frac{2 B_k}{P} \right\rceil \frac{1}{2^{k-1}} + \left\lceil \frac{2N}{P} \right\rceil - \left\lceil \frac{N}{P} \right\rceil \right) = \frac{T_p + T_o}{T_s} A $$
Solving this yields the theoretical best $N$ [S1, unofficial].

**Pseudocode**
```python
import math

def rotate_tiling_composite(P, A, N, Ts, Tp, To):
    """
    P: Number of processors
    A: Image size in pixels
    N: Number of initial blocks
    Ts: Startup time
    Tp: Transmission time per byte
    To: Over operation time per pixel
    """
    # Each processor executes this code with its own rank 'r'
    # Assume 'r' is provided by the MPI environment or similar
    
    # Step 1: Partition partial image A into N blocks
    # Blocks are stored in a list/array. Initially, each processor has N blocks.
    # Each block object has fields: data, size_in_pixels
    blocks = [Block(size=A // N) for _ in range(N)]
    
    num_steps = math.ceil(math.log2(P))
    
    for k in range(1, num_steps + 1):
        # Step 2 & 3: Send/Receive and Composite
        # Calculate send/receive parameters for the current step k
        # Using l=0, w=0, v=0 as the primary mapping indices per source equations
        l, w, v = 0, 0, 0
        
        # Send Equation
        m = ((r - 2 + 2 * l) % (2 ** k)) * (2 ** (k - 1)) + v * (2 ** (k - 1)) + l + P * w
        i = (r - 2 + l) % P
        
        # Receive Equation
        n = ((r + l) % (2 ** k)) * (2 ** (k - 1)) + v * (2 ** (k - 1)) + l + P * w
        j = (r + 2 - l) % P
        
        # Send block m to processor i
        send_blocking(i, blocks[m])
        
        # Receive block from processor j
        received_block = recv_blocking(j)
        
        # Composite received block with local block n using "over" operation [G]
        blocks[n] = composite_over(blocks[n], received_block)
        
        # Step 4: Tiling (Partition)
        # Divide each block into two equal sub-blocks
        new_blocks = []
        for b in range(len(blocks)):
            sub_size = blocks[b].size_in_pixels // 2
            new_blocks.append(Block(size=sub_size))
            new_blocks.append(Block(size=sub_size))
        blocks = new_blocks

    # Final compositing of all blocks into the final image [G]
    final_image = composite_all_blocks(blocks)
    return final_image

def composite_over(block_a, block_b):
    """Standard volume rendering 'over' compositing operation [G]."""
    # Returns block_a composited over block_b
    return block_a + block_b * (1.0 - block_a.alpha)

def composite_all_blocks(blocks):
    """Sequentially composite all blocks into a single image [G]."""
    result = Block(size=0)
    for b in blocks:
        result = composite_over(result, b)
    return result
```

## Operating characteristics
*   **Time Complexity**: The total time $T_{total}(RT)$ depends on $N$, $P$, $A$, $T_s$, $T_p$, and $T_o$ [S1, unofficial]. The number of communication steps is $\lceil \log_2 P \rceil$ [S1, unofficial].
*   **Memory Complexity**: Each processor stores $N$ blocks initially, which doubles in number (halving in size) at each step [S1, unofficial].
*   **Performance**: The RT method allows tuning $N$ to minimize compositing time [S1, unofficial]. On an IBM SP2 ($P=32$, $A=512^2$, $T_s=5 \times 10^{-6}$, $T_p=4 \times 10^{-8}$, $T_o=2 \times 10^{-7}$), the theoretical optimal $N$ is $3.5$, with experimental best performance at $N=4$ [S1, unofficial]. On a PC Cluster ($P=32$, $A=512^2$, $T_s=3.5 \times 10^{-7}$, $T_p=8.4 \times 10^{-9}$, $T_o=3.3 \times 10^{-8}$), the theoretical optimal $N$ is $4.6$, with experimental best performance at $N=5$ [S1, unofficial].
*   **Strengths**: Works for arbitrary $P$ and $N$ [S1, unofficial].
*   **Limitations**: The theoretical analysis assumes synchronous communication; asynchronous communication is difficult to analyze [S1, unofficial]. The optimal $N$ may be non-integer, requiring rounding to the nearest positive integers [S1, unofficial].

## Background
The Rotate-Tiling (RT) method was introduced by Chin-Feng Lin, Shih-Kuan Liao, Yeh-Ching Chung, and Don-Lin Yang in 2004 [S1, unofficial]. It is used in sort-last parallel volume rendering systems, implemented with C and MPICH/MPICH_GM on IBM SP2 and PC clusters [S1, unofficial]. It builds on the Block-Splitting (BS) method and the Parallel Pipeline (PP) method [S1, unofficial].
