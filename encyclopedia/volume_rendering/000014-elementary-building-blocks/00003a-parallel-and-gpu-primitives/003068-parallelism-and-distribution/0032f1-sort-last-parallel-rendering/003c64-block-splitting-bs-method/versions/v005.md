# Block-Splitting (BS) method
Also called: BS method, Binary Splitting (BS) Method
## Overview
The Block-Spliting (BS) method is a parallel compositing technique for sort-last parallel volume rendering that reduces the number of communication steps to $\log_2 P$ by doubling the block size at each stage [S1, unofficial]. It serves as a baseline for comparison against hierarchical variants like the DSH method [S2]. Unlike the Parallel Pipeline (PP) method, BS is optimal when the processor count $P$ is a power of two, offering fewer communication steps for square processor grids [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** $P$ processors, each holding a partial image of size $A/P$ pixels. The total image size is $A$.
*   **Output:** One complete composite image held by a designated root processor (or distributed, though the time formula assumes a single final merge point or equivalent load).

**Data Structures:**
*   **Partial Image:** A 2D array of pixels.
*   **Block:** A rectangular sub-region of the partial image. Initially, each processor holds one block of size $A/P$.

**Steps:**
1.  **Initialization:** Each processor $P_i$ ($0 \le i < P$) holds a partial image block $B_i$ of size $A/P$.
2.  **Communication Loop:** Perform $k = 1$ to $\log_2 P$ steps:
    a.  **Pairing:** In step $k$, processors are paired based on their indices. Specifically, processor $i$ communicates with processor $i \oplus 2^{k-1}$ (where $\oplus$ is bitwise XOR). Only one processor in each pair sends, and the other receives. Typically, the processor with the higher index sends to the lower index, or vice versa, following a butterfly topology.
    b.  **Block Size:** In step $k$, the block size being transmitted is $A_k = A / 2^k$.
    c.  **Transmission:** The sending processor transmits its current block to the receiving processor.
    d.  **Compositing:** The receiving processor composites the received block with its own local block using the "over" operator. The result replaces the local block.
3.  **Termination:** After $\log_2 P$ steps, the root processor (or the designated final accumulator) holds the fully composite image.

**Formulas:**
*   **Block Size at Step $k$:** $A_k = \frac{A}{2^k}$ [S1, unofficial].
*   **Communication Time per Step:** $T_s$ (latency) + $A_k \times T_p$ (pixel transfer time) [S1, unofficial].
*   **Compositing Time per Step:** $A_k \times T_o$ (pixel operation time) [S1, unofficial].
*   **Total Time:**
    $$ T_{total}(BS) = \sum_{k=1}^{\log P} \left( T_s + \frac{A}{2^k} T_p \right) + \sum_{k=1}^{\log P} \frac{A}{2^k} T_o $$
    Simplifying the geometric series $\sum_{k=1}^{\log P} \frac{1}{2^k} = 1 - \frac{1}{2^{\log P}} = 1 - \frac{1}{P}$:
    $$ T_{total}(BS) = (\log P) T_s + \left(1 - \frac{1}{P}\right) (T_p + T_o) A $$
    [S1, unofficial]

**Parameters:**
*   $P$: Number of processors. Must be a power of two for the standard binary splitting topology [S1, unofficial].
*   $A$: Total number of pixels in the final image.
*   $T_s$: Communication latency per message.
*   $T_p$: Pixel transfer time per unit area.
*   $T_o$: Compositing operation time per unit area.

**Edge Cases and Pitfalls:**
*   **Non-Power-of-Two Processors:** The standard BS method assumes $P$ is a power of two. If $P$ is not a power of two, the topology must be adapted (e.g., using the Rotate-Tiling method which generalizes BS) [S1, unofficial].
*   **Load Imbalance:** If the "over" operation is not uniform (e.g., sparse data), the actual computation time may vary, but the BS model assumes uniform $T_o$ [S1, unofficial].
*   **Precision:** Standard floating-point compositing is assumed. No specific precision handling is detailed in the source [S1, unofficial].

## Subtopics

### [DSH (Divided-Screenwise Hierarchical) method](9240-dsh-divided-screenwise-hierarchical-method.md)
Eliminates redundant communication by dividing the screen into non-overlapping tiles and dynamically assigning processors. Choose when $P$ is large and data coverage is sparse to avoid transmitting blank regions.

### [Rotate-Tiling (RT) Method](16314-rotate-tiling-rt-method.md)
Generalizes BS to arbitrary $P$ and $N$ (number of blocks) using ring rotations. Choose when $P$ is not a power of two or when performance tuning via $N$ is required.

## Operating characteristics
**Time and Memory Complexity:**
*   **Communication Steps:** $\log_2 P$ [S1, unofficial].
*   **Total Time:** $T_{total}(BS) = (\log P) T_s + (1 - 1/P) (T_p + T_o) A$ [S1, unofficial].
*   **Memory:** Each processor holds one block of size $A/P$ at any time. No significant additional memory for buffering is required beyond the block being transmitted [S1, unofficial].

**Measured Performance:**
*   BS is faster than the Parallel Pipeline (PP) method when $P$ is a power of two, because $T_{total}(BS) \le T_{total}(PP)$ in this case [S1, unofficial].
*   BS transmits more pixels than the DSH method as the number of regions $n$ increases, because DSH avoids transmitting redundant blank regions [S2].

**Strengths and Limitations:**
*   **Strengths:** Simple topology (butterfly), minimal communication steps ($\log P$), optimal for power-of-two processor counts [S1, unofficial].
*   **Limitations:** Inefficient for non-power-of-two processor counts without modification. Transmits all data regardless of sparsity (unlike DSH), leading to higher bandwidth usage on sparse volumes [S2].

**When to Use:**
*   Use when $P$ is a power of two and the dataset is dense enough that the simplicity of the butterfly network outweighs the benefit of hierarchical tiling.
*   Use as a baseline for comparison [S2].

**When Not to Use:**
*   Use when $P$ is not a power of two (use RT instead) [S1, unofficial].
*   Use when the volume is sparse and significant bandwidth can be saved by avoiding transmission of blank regions (use DSH instead) [S2].
## Background
The Block-Splitting method is a foundational sort-last parallel compositing algorithm. It is cited in the context of comparing various parallel volume rendering compositing strategies, specifically against the Parallel Pipeline (PP) and Rotate-Tiling (RT) methods [S1, unofficial]. It is also used as a baseline for the Divided-Screenwise Hierarchical (DSH) method [S2]. The specific origin paper is not explicitly named in the provided notes, but the analysis is attributed to [S1, unofficial] and [S2].
