# Block-Splitting (BS) method
Also called: BS method, Binary Splitting (BS) Method

## Overview
The Block-Spliting (BS) method is a parallel compositing technique for sort-last parallel volume rendering that divides partial images into blocks and doubles the block size in each communication step [S1, unofficial]. It solves the problem of efficiently merging partial images from $P$ processors into a final image by ensuring that every processor participates in every stage, reducing the number of communication steps to $\log P$ [S1, unofficial]. Unlike the Parallel Pipeline (PP) method, which requires a rectangular processor grid and has more communication steps for square grids, the BS method is more efficient when $P$ is a power of two [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: $P$ partial images, each of size $A$ pixels (or voxels projected to screen space), distributed across $P$ processors.
- Output: One final composite image of size $A$ pixels, available on all processors (or a designated root, depending on implementation; the formula assumes global participation).

**Data structures:**
- Each processor holds a local image buffer of size $A$.
- The image is conceptually divided into blocks. In step $k$ ($1 \le k \le \log P$), the block size is $A_k = A / 2^k$.
- No explicit tree structure is stored; the communication pattern is implicit based on processor rank and step number.

**Numbered steps:**
1. Initialize the local image on each processor $P_i$ ($0 \le i < P$) as the partial image $I_i$.
2. For each communication step $k$ from $1$ to $\log P$:
   a. Determine the block size for this step: $A_k = A / 2^k$.
   b. Each processor identifies its partner for compositing. In the standard BS method, processors are paired based on their binary representation or rank. Specifically, processor $P_i$ composites its current block with the block from processor $P_j$, where $j$ is determined by flipping the $k$-th bit of $i$'s rank (or equivalent pairing logic that ensures all $P$ processors are involved in a binary tree fashion).
   c. Perform the "over" compositing operation between the local block and the received block. The compositing time for this step is $T_{comp} = A_k \times T_o$, where $T_o$ is the time per pixel for the over operation [S1, unofficial].
   d. Send the resulting block to the partner processor and receive the partner's block. The communication time is $T_s$ (latency) plus transmission time for $A_k$ pixels. The source formula aggregates communication and computation: $T_s + A_k \times T_p$, where $T_p$ is the time per pixel for transmission [S1, unofficial].
   e. Update the local image with the compositing result.
3. After $\log P$ steps, each processor holds the final composite image.

**Formulas:**
- Total time:
  $$ T_{total}(BS) = (\log P)T_s + \left(1 - \frac{1}{2^{\log P}}\right)(T_p + T_o)A $$
  where:
  - $P$: Number of processors.
  - $T_s$: Communication latency per step.
  - $T_p$: Time per pixel for transmission.
  - $T_o$: Time per pixel for compositing ("over" operation).
  - $A$: Total number of pixels in the image.
  - Note: The term $(1 - 1/2^{\log P})$ simplifies to $(1 - 1/P)$ [S1, unofficial].

**Parameters:**
- $P$ must be a power of two for the standard BS method to work without remainder handling [S1, unofficial].
- Typical values for $T_s, T_p, T_o$ depend on hardware and are not specified in the sources.

**Edge cases and pitfalls:**
- If $P$ is not a power of two, the standard BS method requires modification or padding, which is not detailed in the sources [S1, unofficial].
- The method assumes all processors have equal-sized partial images of size $A$.
- Precision issues in compositing are not addressed in the sources.

## Subtopics

### [DSH (Divided-Screenwise Hierarchical) method](9240-dsh-divided-screenwise-hierarchical-method.md)
Eliminates redundant communication by dividing the screen into non-overlapping tiles and dynamically assigning processors, avoiding the bottleneck of a single processor merging the final image.

### [Rotate-Tiling (RT) Method](16314-rotate-tiling-rt-method.md)
Allows arbitrary numbers of processors and initial blocks by using ring rotation topology, solving the power-of-two constraint of BS.

## Operating characteristics
- **Time complexity:** $O(\log P)$ communication steps [S1, unofficial].
- **Memory complexity:** $O(A)$ per processor to store the image [S1, unofficial].
- **Measured performance:** The total time is given by $T_{total}(BS) = (\log P)T_s + (1 - 1/P)(T_p + T_o)A$ [S1, unofficial].
- **Scaling:** Efficient when $P$ is a power of two. When $P$ is not a power of two, performance degrades or requires modification [S1, unofficial].
- **Strengths:** Simple communication pattern, all processors participate in every step, efficient for power-of-two processor counts [S1, unofficial].
- **Limitations:** Requires $P$ to be a power of two, transmits more pixels than DSH as $n$ increases [S2].
- **When to use:** When $P$ is a power of two and simplicity is preferred.
- **When not to use:** When $P$ is not a power of two, or when minimizing transmitted pixels is critical (use DSH) [S2].

## Background
The Block-Splitting method was introduced as a baseline for comparing other parallel compositing methods like DSH and RT [S1, unofficial][S2]. It is a standard sort-last parallel compositing technique used in volume rendering research [S2].
