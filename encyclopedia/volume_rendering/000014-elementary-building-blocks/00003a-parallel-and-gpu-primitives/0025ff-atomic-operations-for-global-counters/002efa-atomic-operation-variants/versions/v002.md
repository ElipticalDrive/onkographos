# Atomic Operation Variants
Also called: atomicAdd, atomicCAS, atomicMin

## Overview
Atomic operation variants provide specific computational primitives that execute as indivisible units on global memory, extending the basic read-modify-write guarantee of atomic operations [S1, unofficial]. While the parent article [Atomic Operations for Global Counters](3684-atomic-operations-for-global-counters.md) establishes the mechanism for race-free updates, these variants define the specific computation performed during the update [G]. They are distinguished from sibling techniques like the [Thread-Safe Circular Buffer for Brick Allocation](4567-thread-safe-circular-buffer-for-brick-allocation.md) by operating directly on scalar memory locations rather than managing complex data structures or indices [G].

## Shared principles
All variants share the fundamental property of atomicity: the read, computation, and write phases occur without interruption from other threads accessing the same memory location [S1, unofficial]. This ensures that concurrent invocations from multiple GPU threads result in a deterministic final state consistent with some serial execution order [G]. The interface generally follows the pattern `result = operation(inout memory, operand)`, where `memory` is updated and the previous value is returned [S1, unofficial].

## Subtopics

### Arithmetic and Comparison
- **atomicAdd**: Performs addition. `atomicAdd(inout int mem, int data)` adds `data` to `mem` [S1, unofficial].
- **atomicMin**: Computes the minimum. `atomicMin(inout int mem, int data)` updates `mem` to `min(mem, data)` [S1, unofficial].
- **atomicMax**: Computes the maximum. `atomicMax(inout int mem, int data)` updates `mem` to `max(mem, data)` [S1, unofficial].

### Logical Operations
- **atomicAnd**: Logical AND. `atomicAnd(inout int mem, int data)` updates `mem` to `mem & data` [S1, unofficial].
- **atomicOr**: Logical OR. `atomicOr(inout int mem, int data)` updates `mem` to `mem | data` [S1, unofficial].
- **atomicXor**: Logical XOR. `atomicXor(inout int mem, int data)` updates `mem` to `mem ^ data` [S1, unofficial].

### Swap and Compare-Exchange
- **atomicExchange**: Swaps the value. `atomicExchange(inout int mem, int data)` sets `mem = data` and returns the original value of `mem` [S1, unofficial].
- **atomicCompSwap**: Compare-and-swap (CAS). `atomicCompSwap(inout int mem, uint compare, uint data)` checks if `mem == compare` [S1, unofficial]. If true, it sets `mem = data` [S1, unofficial]. It always returns the original value of `mem` regardless of whether the swap occurred [S1, unofficial].

Implementation logic for `atomicCompSwap`:
```python
def atomicCompSwap(mem, compare, data):
    old = mem
    if mem == compare:
        mem = data
    return old
```

### Deprecated Counters
- **atomicCounter**: Dedicated counter functions (`atomicCounterIncrement`, `atomicCounterDecrement`) existed in Vulkan but are deprecated [S1, unofficial]. They can be replaced by `atomicAdd` [S1, unofficial].

## Background
The specific variants listed are documented in practice guides for GPU programming using Vulkan [S1, unofficial]. The distinction between atomic operations and subgroup operations (warp/wave intrinsics) is noted, with atomic operations targeting global memory consistency across threads, whereas subgroup operations coordinate within a hardware thread group [S1, unofficial].
