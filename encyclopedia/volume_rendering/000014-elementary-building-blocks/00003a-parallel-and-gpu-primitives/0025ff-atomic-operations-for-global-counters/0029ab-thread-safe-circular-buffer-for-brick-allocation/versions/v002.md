# Thread-Safe Circular Buffer for Brick Allocation
Also called: Atomic Brick Pool, Prime-Stepped Buffer
## Overview
A thread-safe mechanism for allocating and recycling brick indices on the CPU side using a circular buffer with atomic head and tail pointers [S1, unofficial]. It prevents cache false sharing during concurrent recycling by stepping through the buffer with a prime stride [S1, unofficial]. It sets itself apart from standard circular buffers by using a prime-stepped recycling stride to mitigate false sharing, a critical optimization for CPU cache performance [S1, unofficial].
## How it works
### Inputs and Outputs
- **Input**: A pre-allocated array of brick indices and atomic head/tail counters [S1, unofficial].
- **Output**: A unique brick index for allocation, or a recycled brick index for deallocation [S1, unofficial].

### Data Structures
The buffer is a contiguous array of integers (brick indices) [S1, unofficial].
- **Size**: Must be a power of 2 ($N = 2^k$) [S1, unofficial].
- **Fields**:
  - `buffer`: Array of size $N$ [S1, unofficial].
  - `head`: Atomic integer, index of the next available slot for recycling [S1, unofficial].
  - `tail`: Atomic integer, index of the next available slot for allocation [S1, unofficial].
  - `brick_voxel_count`: Auxiliary array tracking the number of non-zero voxels per brick, used to detect empty bricks [S1, unofficial].

### Numbered Steps
1. **Initialization**: Fill `buffer` with valid brick indices $0 \dots M-1$, where $M \le N$ [S1, unofficial]. Initialize `head = 0`, `tail = 0`, and `brick_voxel_count` to the brick capacity [G].
2. **Allocate a Brick**: Atomically increment `tail` to claim an index [S1, unofficial]. Calculate the index: $idx = tail \ \& \ (N - 1)$ [S1, unofficial]. Return `buffer[idx]` [S1, unofficial].
3. **Recycle a Brick**: Determine the brick index $b$ to recycle [S1, unofficial]. Atomically increment `head` by 17 to claim a slot in the circular buffer [S1, unofficial]. Calculate the slot index: $slot = head \ \& \ (N - 1)$ [S1, unofficial]. Write $b$ to `buffer[slot]` [S1, unofficial].
4. **Wrap Around**: Use bitwise AND with $(N - 1)$ to wrap indices, requiring the buffer size to be a power of 2 [S1, unofficial].
5. **Empty Brick Detection**: When setting a voxel to 0, decrement `brick_voxel_count[brick]` [S1, unofficial]. If `brick_voxel_count[brick]` becomes 0, recycle the brick to the buffer [S1, unofficial].
6. **Redundant Write Check**: Before allocating a brick, check if the new voxel value is identical to the existing value [S1, unofficial]. If so, skip allocation and writing [S1, unofficial].

### Formulas
- **Index Calculation**: $idx = ptr \ \& \ (N - 1)$, where $N$ is the buffer size (power of 2) [S1, unofficial].
- **Cache Line Separation**: Step size $S = 17$. Distance between writes $= S \times \text{sizeof(int)} = 17 \times 4 = 68$ bytes [S1, unofficial]. Since cache line size is 64 bytes, 68 bytes ensures different cache lines [S1, unofficial].

### Parameters
- **Recycle step size**: 17 (a prime number) [S1, unofficial].
- **Cache line size**: 64 bytes [S1, unofficial].
- **Buffer size**: Power of 2, pre-allocated fraction of theoretical upper limit [S1, unofficial].

### Edge Cases and Pitfalls
- **False Sharing**: Multiple threads writing to adjacent locations in the same cache line cause costly synchronization [S1, unofficial]. Solved by stepping 17 elements (68 bytes) between writes, ensuring different cache lines [S1, unofficial].
- **Concurrent Assignment**: Two threads may try to assign a new brick to the same top-level grid cell concurrently [S1, unofficial]. This is currently unimplemented/unhandled [S1, unofficial].
- **Redundant Writes**: If setting a voxel value results in no change (same as existing value), skip the operation to avoid unnecessary brick allocation [S1, unofficial].
- **Empty Brick Detection**: If setting a voxel to 0 makes a brick entirely empty (tracked by a non-zero voxel counter), recycle the brick to the buffer [S1, unofficial].
- **Buffer Exhaustion**: If the buffer is full, allocation fails [S1, unofficial]. Pre-allocate a fraction of the theoretical upper limit to mitigate this [S1, unofficial].

### Pseudocode
```python
class ThreadSafeCircularBuffer:
    def __init__(self, buffer_size, bricks):
        self.N = buffer_size
        self.mask = self.N - 1
        self.buffer = [0] * self.N
        for i in range(len(bricks)):
            self.buffer[i] = bricks[i]
        self.head = 0
        self.tail = 0
        self.brick_voxel_count = {}

    def allocate_brick(self):
        self.tail += 1
        idx = self.tail & self.mask
        return self.buffer[idx]

    def recycle_brick(self, brick):
        self.head += 17
        slot = self.head & self.mask
        self.buffer[slot] = brick

    def set_voxel(self, brick, voxel_index, value, existing_value, brick_capacity):
        if value == existing_value:
            return
        if value == 0:
            self.brick_voxel_count[brick] -= 1
            if self.brick_voxel_count[brick] == 0:
                self.recycle_brick(brick)
                return
```

## Operating characteristics
- **Time Complexity**: Allocation and recycling are $O(1)$ due to atomic operations and bitwise modulo [S1, unofficial].
- **Memory Complexity**: $O(N)$ for the buffer, where $N$ is the buffer size [S1, unofficial].
- **Performance**: The prime-stepped recycling (stride 17) significantly reduces cache false sharing, improving performance in multi-threaded scenarios [S1, unofficial]. Without this, adjacent writes to the same cache line would cause frequent cache invalidations and synchronization [S1, unofficial].
- **Strengths**: Efficient memory reuse, thread-safe, minimizes cache contention [S1, unofficial].
- **Limitations**: Does not handle concurrent assignment to the same grid cell (requires external synchronization or batching) [S1, unofficial]. Buffer exhaustion can occur if pre-allocation is insufficient [S1, unofficial].
- **When to Use**: Multi-threaded voxel rendering on CPU where brick allocation/deallocation is frequent [S1, unofficial].
- **When Not to Use**: Single-threaded environments (overhead of atomic ops), or when concurrent grid cell assignment is common and not handled externally [S1, unofficial].
