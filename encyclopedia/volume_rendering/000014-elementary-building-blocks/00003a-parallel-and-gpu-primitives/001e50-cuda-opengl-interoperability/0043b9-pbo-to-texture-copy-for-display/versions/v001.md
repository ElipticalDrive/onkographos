# PBO to Texture Copy for Display

Also called: OpenGL Display via PBO and Texture, OpenGL PBO Texture Upload & Display, PBO to Texture Copy, fullscreen quad render

## Overview
This method transfers the final rendered image from a CUDA-registered Pixel Buffer Object (PBO) into an OpenGL texture and displays it on screen. It solves the problem of presenting GPU-computed volume data without incurring the latency of copying data back to the CPU system memory. It differs from [Bindless Textures in CUDA](1980-bindless-textures-in-cuda.md) by using explicit buffer-object synchronization rather than direct device pointers, and from [CUDA-OpenGL Interop Surface Write](2228-cuda-opengl-interop-surface-write.md) by writing to a buffer object rather than a surface object, requiring an explicit texture upload step.

## How it works
**Inputs and Outputs:**
- Input: A CUDA-registered PBO (`mem_pbo_out` or `pbo`) containing the rendered image data (typically `GL_RGBA` or `GL_BGRA`, `GL_UNSIGNED_BYTE`).
- Input: OpenGL context with double buffering enabled.
- Output: The display window showing the volume rendering.

**Data Structures:**
- `tex_screen`: A 2D OpenGL texture object.
- `pbo`: A `GL_PIXEL_UNPACK_BUFFER` object.
- `c_invViewMatrix`: A constant buffer in CUDA containing the inverse view matrix, derived from the OpenGL model-view matrix.

**Steps:**

1. **Initialization:**
   - Create the PBO with size `width * height * 4` bytes (assuming 4-channel unsigned byte).
   - Register the PBO with CUDA using `cudaGraphicsGLRegisterBuffer`.
   - Create a 2D texture `tex_screen` with nearest-neighbor filtering.

2. **Per-Frame Rendering Loop:**
   1. **Update View Matrix:** Extract the model-view matrix from OpenGL, compute its inverse, and upload it to the CUDA constant buffer `c_invViewMatrix` [S2, unofficial].
   2. **Render Volume:** Launch the CUDA volume rendering kernel. The kernel writes the final pixel colors directly into the registered PBO [S2, unofficial].
   3. **Synchronize:** Ensure CUDA completion before accessing the PBO for display.
   4. **Copy to Texture:**
      - Bind the PBO as `GL_PIXEL_UNPACK_BUFFER`.
      - Bind the texture `tex_screen`.
      - Call `glTexSubImage2D` with `data` pointer set to `NULL` (or `0`). This tells OpenGL to read the texture data from the currently bound PBO [S1, S2, unofficial].
      - Parameters: `width`, `height`, format `GL_RGBA` (or `GL_BGRA` depending on kernel output), type `GL_UNSIGNED_BYTE` [S1, S2, unofficial].
   5. **Display:**
      - Unbind the PBO and texture.
      - Draw a fullscreen quad. The quad vertices are typically `(-1,-1), (1,-1), (1,1), (-1,1)` [S1, unofficial].
      - Texture coordinates map the image aspect ratio. If the image resolution is `res_x, res_y` and the texture is `2048x2048`, the texture coordinates are `(0,0)`, `(res_x/2048.0, 0)`, `(res_x/2048.0, res_y/2048.0)`, `(0, res_y/2048.0)` [S1, unofficial].
      - Alternatively, draw a quad from `(0,0)` to `(1,1)` in screen space if the texture covers the full viewport [S2, unofficial].
   6. **Swap Buffers:** Call `glutSwapBuffers()` or equivalent to present the frame [S2, unofficial].

**Pseudocode:**

```python
def display_frame(gl_context, cuda_stream, pbo, tex, width, height):
    # 1. Update inverse view matrix in CUDA constant memory
    # [S2, unofficial] Extract model-view matrix from OpenGL, invert, transpose, upload to c_invViewMatrix
    inv_view_matrix = get_opengl_inverse_view_matrix()
    set_cuda_constant('c_invViewMatrix', inv_view_matrix)

    # 2. Launch CUDA volume rendering kernel
    # [S2, unofficial] Kernel writes to the registered PBO
    launch_volume_render_kernel(pbo, width, height, cuda_stream)

    # 3. Synchronize CUDA to ensure PBO is written
    # [G] Standard CUDA synchronization
    cuda_stream_synchronize(cuda_stream)

    # 4. Copy PBO data to OpenGL Texture
    # [S1, S2, unofficial] Bind PBO as unpack buffer
    glBindBuffer(GL_PIXEL_UNPACK_BUFFER, pbo)
    
    # [S1, S2, unofficial] Bind texture
    glBindTexture(GL_TEXTURE_2D, tex)
    
    # [S1, S2, unofficial] Upload data from PBO to texture
    # Format is GL_RGBA or GL_BGRA, type GL_UNSIGNED_BYTE
    glTexSubImage2D(
        GL_TEXTURE_2D, 0, 
        0, 0, 
        width, height, 
        GL_RGBA, GL_UNSIGNED_BYTE, 
        None  # NULL pointer indicates data is in PBO
    )
    
    # Unbind PBO to avoid conflicts
    glBindBuffer(GL_PIXEL_UNPACK_BUFFER, 0)

    # 5. Render Fullscreen Quad
    # [S1, unofficial] Set up projection and modelview for orthographic screen space
    glMatrixMode(GL_PROJECTION)
    glLoadIdentity()
    glOrtho(0, width, 0, height, -1, 1)
    glMatrixMode(GL_MODELVIEW)
    glLoadIdentity()

    # [S1, unofficial] Calculate texture coordinates for aspect ratio correction
    tx = float(width) / 2048.0
    ty = float(height) / 2048.0

    # [S1, unofficial] Draw quad with vertices and texture coordinates
    glBegin(GL_QUADS)
    glTexCoord2f(0.0, 0.0); glVertex2f(-1.0, -1.0)
    glTexCoord2f(tx, 0.0);   glVertex2f(1.0, -1.0)
    glTexCoord2f(tx, ty);    glVertex2f(1.0, 1.0)
    glTexCoord2f(0.0, ty);   glVertex2f(-1.0, 1.0)
    glEnd()

    # [S2, unofficial] Swap buffers
    glutSwapBuffers()
```

**Parameters:**
- `width`, `height`: Image resolution.
- `2048`: Texture size used in [S1, unofficial] for aspect ratio calculation.
- `GL_RGBA` / `GL_BGRA`: Color format. [S1, unofficial] uses `GL_BGRA`, [S2, unofficial] uses `GL_RGBA`.
- `GL_UNSIGNED_BYTE`: Data type.

**Edge Cases and Pitfalls:**
- **Format Mismatch:** Ensure the format used in `glTexSubImage2D` matches the data layout written by the CUDA kernel. [S1, unofficial] uses `GL_BGRA` while [S2, unofficial] uses `GL_RGBA`. Mismatch causes color channel swapping or corruption.
- **Aspect Ratio:** If the texture is square (e.g., 2048x2048) but the image is not, texture coordinates must be scaled to prevent distortion [S1, unofficial].
- **Synchronization:** Failing to synchronize CUDA before accessing the PBO results in displaying stale or corrupted data.

## Operating characteristics
- **Time Complexity:** O(1) for the copy and display steps relative to scene complexity, but O(W*H) for the data transfer size. The dominant cost is the volume rendering kernel itself.
- **Memory Complexity:** O(W*H) for the PBO and texture storage.
- **Performance:** Avoids CPU-GPU round-trip latency for the final image. The `glTexSubImage2D` with a PBO is efficient as it keeps data on the GPU.
- **Strengths:** Simple integration with existing OpenGL rendering pipelines; avoids CPU overhead.
- **Limitations:** Requires OpenGL 2.0+ and `GL_ARB_pixel_buffer_object` extension [S2, unofficial]. Synchronization overhead between CUDA and OpenGL can limit frame rate if not managed carefully.

## Background
This technique is part of the CUDA-OpenGL Interoperability suite, enabling GPU-accelerated volume rendering to be displayed in standard OpenGL windows. It was demonstrated in NVIDIA's CUDA SDK Volume Rendering sample [S2, unofficial] and in open-source implementations like Sparse-Voxel-Octree-Raycasting [S1, unofficial].
