# 2-3 Swap Compositing

Also called: 2-3 Swap

## Overview
2-3 Swap Compositing is a parallel compositing technique that combines independently rendered image tiles across multiple processors in a distributed-memory environment [S1]. It overcomes the power-of-two processor requirement of Parallel Binary-Swap Compositing by partitioning processors into groups of two or three and exchanging data in multiple rounds [S1].

## How it works
**Inputs and Outputs:**
- Input: $N$ processors, each holding a partial image tile or volume slice contribution [S1].
- Output: A single composited image distributed across the processors [G].

**Data Structures:**
- Each processor maintains a local image tile buffer containing its partial compositing result [G].

**Algorithm Steps:**
1. **Initialization**: Each processor $p$ holds its local image tile $I_p$ [G].
2. **Grouping**: The $N$ processors are logically divided into groups of size 2 or 3 [S1].
3. **Communication Rounds**: The algorithm proceeds in multiple rounds [S1].
4. **Data Exchange**: Within each group, processors exchange their current image tiles using a direct send approach [S1].
5. **Compositing**: Upon receiving tiles, each processor composites the received data with its local tile using front-to-back alpha compositing [G]:
   $$ C_{out} = C_{in} + (1 - \alpha_{in}) C_{peer} $$
   $$ \alpha_{out} = \alpha_{in} + (1 - \alpha_{in}) \alpha_{peer} $$
   where $C$ is color and $\alpha$ is opacity [G].
6. **Iteration**: Steps 2–5 repeat across rounds until all processors have exchanged data globally [S1].

**Parameters:**
- $N$: Total number of processors, any integer $\ge 2$ [S1].
- Group sizes: 2 or 3 per round [S1].

**Edge Cases and Pitfalls:**
- **Non-Power-of-Two $N$**: The method explicitly supports arbitrary $N$ without padding to the next power of two [S1].
- **Synchronization**: Processors must synchronize after each round to ensure all direct sends complete before the next compositing step [G].
- **Grouping Strategy**: The exact schedule for arbitrary $N$ is implementation-specific; it must ensure all processors participate and the product of group sizes across rounds covers all necessary exchanges [G].

**Pseudocode:**
```python
def two_three_swap_compositing(N, my_id, my_tile):
    """
    Performs 2-3 swap compositing for N processors.
    my_id: Integer ID of this processor (0 to N-1).
    my_tile: The initial image tile held by this processor.
    """
    current_tile = my_tile
    # The source does not specify the exact round schedule for arbitrary N [G].
    # A standard factorization into 2s and 3s determines the grouping per round.
    group_sizes = factorize(N)
    
    for size in group_sizes:
        # Determine group peers based on current group size [G]
        group_base = (my_id // size) * size
        peers = [p for p in range(group_base, group_base + size) if p != my_id]
        
        # Direct send/receive within the group [S1]
        received_tiles = []
        for peer in peers:
            send(peer, current_tile)
            received_tiles.append(receive(peer))
        
        # Composite received data with local tile [G]
        for peer_tile in received_tiles:
            current_tile = composite(current_tile, peer_tile)
            
    return current_tile

def composite(tile1, tile2):
    """Performs front-to-back alpha compositing of two tiles [G]."""
    c1, a1 = tile1.color, tile1.alpha
    c2, a2 = tile2.color, tile2.alpha
    out_c = c1 + (1.0 - a1) * c2
    out_a = a1 + (1.0 - a1) * a2
    return Tile(out_c, out_a)

def factorize(n):
    """Factorizes n into a sequence of 2s and 3s to determine round group sizes [G]."""
    factors = []
    while n % 2 == 0:
        factors.append(2)
        n //= 2
    while n % 3 == 0:
        factors.append(3)
        n //= 3
    if n > 1:
        factors.append(n)
    return factors
```

## Subtopics

### [Radix-k Compositing](12235-radix-k-compositing.md)
Radix-k compositing is a parallel image compositing strategy for distributed-memory systems that combines the flexibility of direct send with the performance of binary-swap compositing. It divides communication into multiple rounds, defining a group size $k_i$ for each round $i$, where the product of all $k_i$ equals the total number of processors $N$. Unlike 2-3 Swap Compositing, which restricts group sizes to 2 or 3, Radix-k allows variable group sizes per round to optimize for specific network topologies or processor counts.

## Operating characteristics
- **Time Complexity**: The number of rounds depends on the factorization of $N$ into 2s and 3s, yielding approximately $\log_2 N$ rounds [G].
- **Memory Complexity**: $O(1)$ auxiliary memory per processor for storing the image tile and temporary communication buffers [G].
- **Strengths**: Handles arbitrary processor counts without padding; reduces synchronization overhead compared to all-to-all approaches [G].
- **Limitations**: Grouping logic is more complex than binary swap; performance varies depending on the specific factorization of $N$ [G].
- **When to use**: Distributed volume rendering when the processor count is not a power of two and flexible scaling is required [S1].

## Background
2-3 Swap Compositing was implemented by Yu et al. [S1] as a modification of binary swap to overcome the limitation that the number of processors had to be a power of two. It is part of the broader field of hybrid distributed-memory parallel volume rendering techniques [S1].
