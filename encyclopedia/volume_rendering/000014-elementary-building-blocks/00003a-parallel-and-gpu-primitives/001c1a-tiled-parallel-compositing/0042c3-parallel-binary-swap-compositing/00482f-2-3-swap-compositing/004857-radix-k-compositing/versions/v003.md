# Radix-k Compositing

Also called: Radix-k

## Overview
Radix-k compositing is a parallel image compositing strategy for distributed-memory systems that combines the flexibility of direct send with the performance of binary-swap compositing [S1]. It divides communication into multiple rounds, defining a group size $k_i$ for each round $i$, where the product of all $k_i$ equals the total number of processors $N$ [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** $N$ processors, each holding a partial image region generated from their assigned volume data [S1].
*   **Output:** A fully composited image distributed across the processors, with each processor retaining ownership of its assigned spatial region [S1].

**Data Structures:**
*   **Processor Grouping:** A sequence of integers $k_1, k_2, \dots, k_m$ representing the group sizes for each communication round [S1].
*   **Image Region:** Each processor $p$ owns a specific spatial region of the current image [S1].

**Algorithm Steps:**
1.  **Factorization:** Determine a sequence of group sizes $k_i$ for $i = 1$ to $m$ such that the product of all group sizes equals the total number of processors $N$ [S1].
2.  **Round Execution:** For each round $i$ from 1 to $m$:
    a. Partition the $N$ processors into disjoint groups of size $k_i$ [S1].
    b. Within each group, processors exchange their current image data using a direct send method, with each processor owning a region of the current image [S1].
    c. Each processor composites the received data with its own local data [G].
    d. The result is the updated image region for that processor [G].
3.  **Completion:** After $m$ rounds, the compositing is complete [S1].

**Formula:**
$$ \prod_{i=1}^{m} k_i = N $$
where $N$ is the total number of processors, $m$ is the number of rounds, and $k_i$ is the group size for round $i$ [S1].

**Parameters:**
*   $N$: Total number of processors [S1].
*   $k_i$: Group size for round $i$ [S1].

**Edge Cases and Pitfalls:**
*   **Factorization:** The choice of $k_i$ values affects performance, with sources suggesting groups of twos or threes [S1]. The source does not specify an optimal factorization algorithm [S1].
*   **Load Imbalance:** As with other hybrid distributed-memory parallel volume rendering techniques, load imbalance can impact performance, as execution time is determined by the slowest processor [S1].

**Pseudocode:**
```python
def radix_k_compositing(N, initial_regions):
    """
    Perform radix-k compositing on distributed image regions.
    
    Args:
        N: Total number of processors
        initial_regions: Dict mapping processor_id to its initial image region data (C, alpha)
        
    Returns:
        Dict mapping processor_id to the final composited image region (C, alpha)
    """
    # Determine group sizes k_i such that product(k_i) == N.
    # Sources suggest using factors of twos or threes [S1].
    group_sizes = factorize(N)
    
    current_regions = dict(initial_regions)
    
    for k in group_sizes:
        # Partition N processors into disjoint groups of size k
        groups = [list(range(i, i + k)) for i in range(0, N, k)]
        
        for group in groups:
            # Direct send exchange within the group
            received = {p: current_regions[p] for p in group}
            
            # Each processor composites received data with its own local data [G]
            for p in group:
                # Standard front-to-back volume compositing [G]
                C_out, alpha_out = 0.0, 0.0
                for src_p in group:
                    C_src, alpha_src = received[src_p]
                    C_out = C_src + (1.0 - alpha_src) * C_out
                    alpha_out = alpha_src + (1.0 - alpha_src) * alpha_out
                current_regions[p] = (C_out, alpha_out)
    return current_regions

def factorize(n):
    """Return a list of factors whose product is n."""
    factors = []
    d = 2
    while d * d <= n:
        while n % d == 0:
            factors.append(d)
            n //= d
        d += 1
    if n > 1:
        factors.append(n)
    return factors
```

## Subtopics

### Binary-Tree Compositing
A compositing strategy for combining partial images from processing nodes, initially implemented as a simple binary-tree step [S2, unofficial]. It involves implementing a simple binary-tree compositing step to combine partial images [S2, unofficial]. It may be replaced later with a more elaborate binary-swap compositing algorithm [S2, unofficial]. This approach is noted in the context of AMR data visualization where partial images are composited in order of node numbers [S2, unofficial].

## Operating characteristics
*   **Flexibility:** Allows any number of processors $N$ [S1].
*   **Performance:** Combines the flexibility of direct send with the performance of binary swap [S1].
*   **Load Imbalance:** Can suffer from load imbalance, where execution time is determined by the slowest processor [S1].
*   **Complexity:** The number of rounds $m$ depends on the factorization of $N$ [S1]. The communication pattern involves direct sends within groups of size $k_i$ [S1].

## Background
Radix-k compositing was proposed by Peterka et al. [S1]. It is used within hybrid distributed-memory parallel volume rendering techniques to manage communication across multiple rounds [S1].
