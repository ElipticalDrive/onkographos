# Radix-k Compositing

Also called: Radix-k

## Overview
Radix-k compositing is a parallel compositing strategy that combines the flexibility of direct send with the performance of binary swap, allowing any number of processors to participate without requiring the count to be a power of two [S1]. It differs from its parent, 2-3 Swap Compositing, by generalizing the group size per round to an arbitrary integer $k_i$, enabling a customizable decomposition of the processor count $N$ into a product of group sizes [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** $N$ processors, where $N$ is the total number of participating nodes. Each processor $p$ holds a partial image region.
*   **Output:** A fully composited image distributed across the processors (or gathered, depending on the specific implementation context, though the core algorithm focuses on the exchange pattern).

**Data Structures:**
*   **Group Size Sequence:** A sequence of integers $k_1, k_2, \dots, k_m$ such that $\prod_{i=1}^{m} k_i = N$.
*   **Processor State:** Each processor maintains its current partial image data.

**Steps:**
1.  **Decomposition:** Determine a sequence of group sizes $k_1, k_2, \dots, k_m$ such that their product equals the total number of processors $N$. The sources do not specify a unique algorithm for choosing this sequence, only that it must satisfy the product constraint [S1].
2.  **Round Initialization:** Set the current round index $i = 1$.
3.  **Group Formation:** Divide the $N$ processors into groups of size $k_i$. The mapping of processors to groups is not explicitly defined in the provided text, but typically implies a logical partitioning (e.g., based on processor ID) [S1].
4.  **Direct Send Exchange:** Within each group of size $k_i$, processors exchange data using a direct send method. Each processor owns a specific region of the current image and sends/receives data from other members of its group to update its partial image [S1].
5.  **Iteration:** Increment $i$. If $i \le m$, return to Step 3. Otherwise, the compositing is complete.

**Formula:**
The fundamental constraint for the group sizes is:
$$ \prod_{i=1}^{m} k_i = N $$
where $N$ is the number of processors and $k_i$ is the group size in round $i$ [S1].

**Parameters:**
*   $N$: Total number of processors.
*   $k_i$: Group size for round $i$.

**Edge Cases and Pitfalls:**
*   **Factorization:** If $N$ is prime, the only valid sequence is $k_1 = N$ (one round of all-to-all) or potentially $k_1=1, k_2=N$ depending on implementation constraints, though a single round of size $N$ is the most direct interpretation. The sources do not specify how to handle prime $N$ or non-composite $N$ beyond the product rule [S1].
*   **Precision:** Not applicable as the method is logical/communication-based.
*   **Boundaries:** The method assumes $N$ can be fully factored into integers $k_i \ge 2$ (or $1$ if trivial rounds are allowed, though $k_i=1$ implies no communication).

## Subtopics

### Binary-Tree Compositing
A compositing strategy initially implemented as a simple binary-tree step to combine partial images from processing nodes [S2, unofficial]. It may be replaced later with a more elaborate binary-swap compositing algorithm [S2, unofficial]. It is less flexible than Radix-k as it typically assumes a power-of-two structure or requires additional handling for non-power-of-two node counts, whereas Radix-k explicitly generalizes this.

### Binary All-to-All Communication
An optimized all-to-all communication algorithm used to maintain an up-to-date image of the entire cluster memory state on each rendering node, replacing pre-determined page positions [S3]. It involves pairs of nodes exchanging a growing buffer in each step, resulting in $O(\log(P))$ communication steps [S3]. It is more latency-sensitive than Radix-k if the number of steps is high, but Radix-k's step count depends on the factorization of $N$. Radix-k is a compositing strategy, while this is a communication primitive that can be used within compositing strategies.

## Operating characteristics
*   **Time Complexity:** The number of communication rounds is determined by the number of factors in the factorization of $N$. In the worst case (prime $N$), it is 1 round of size $N$. In the best case (highly composite $N$ with small factors), it can be $\log_2 N$ rounds. The sources do not provide a precise time complexity formula, but the flexibility allows tuning for specific $N$ [S1].
*   **Memory Complexity:** Each processor stores its partial image. The direct send approach requires buffering data for the group size $k_i$ [S1].
*   **Strengths:** Allows any number of processors $N$ to be used, overcoming the power-of-two limitation of binary swap [S1]. Combines the flexibility of direct send with the performance of binary swap [S1].
*   **Limitations:** The performance depends heavily on the choice of factorization. Poor factorization choices could lead to inefficient communication patterns. The sources do not specify how to optimize the choice of $k_i$ [S1].
*   **When to use:** When the number of processors $N$ is not a power of two and a flexible compositing strategy is needed.
*   **When not to use:** When $N$ is a power of two and binary swap is preferred for its simplicity and well-understood performance characteristics.

## Background
Radix-k compositing was proposed by Peterka et al. [S1]. It is part of the broader field of hybrid distributed-memory parallel volume rendering, which aims to reduce load imbalance by combining object order and image order approaches [S1]. The method is cited in the context of scalable hybrid schemes for ray-casting of unstructured volume data [S1].
