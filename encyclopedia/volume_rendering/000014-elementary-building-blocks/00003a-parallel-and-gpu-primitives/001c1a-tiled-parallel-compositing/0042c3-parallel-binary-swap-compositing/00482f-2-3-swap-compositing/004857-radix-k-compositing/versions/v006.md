# Radix-k Compositing

Also called: Radix-k

## Overview
Radix-k Compositing is a distributed-memory compositing strategy that combines the flexibility of direct send with the performance of binary swap [S1]. It allows any number of processors $N$ to participate in the compositing phase, solving the power-of-two restriction of binary-swap methods [S1]. It sets itself apart from its parent [2-3 Swap Compositing](12223-2-3-swap-compositing.md) by generalizing the group size per round, whereas 2-3 swap is restricted to groups of two or three [G]. It shows good scaling up to 16,000-way concurrency [S2] and is compatible with hybrid parallel systems [S2].

## How it works
**Inputs:**
- $N$: Total number of processors involved in compositing.
- $P$: Set of processors, indexed $0 \dots N-1$.
- Image data: Each processor holds a region of the current partial image to be composited [S1].

**Outputs:**
- A fully composited image distributed across the processors or gathered to a specific node, depending on the higher-level scheme [G].

**Data Structures:**
- Standard image buffers partitioned among processors; each processor owns a specific region of the current image [S1].
- No specific bit-packing is defined in the sources; standard image buffers are assumed [G].

**Steps:**
1. **Factorization:** Determine a sequence of group sizes $k_1, k_2, \dots, k_m$ such that:
   $$ \prod_{i=1}^{m} k_i = N $$
   The factors $k_i$ are typically small integers (e.g., 2s and 3s) [S1].
2. **Round Execution:** For each round $i$ from $1$ to $m$:
   a. Divide the $N$ processors into groups of size $k_i$ [S1].
   b. Within each group, processors exchange their current image regions using a direct send method [S1].
   c. Each processor composites the received data with its own local image data to update its region [G].
3. **Completion:** After $m$ rounds, the compositing is complete [G].

**Parameters:**
- $k_i$: Group size for round $i$. The choice of factors affects the number of communication rounds ($m$) and the volume of data sent per round [G].
- $N$: Number of processors [S1].

**Edge Cases and Pitfalls:**
- If $N$ is prime, the only valid factorization is $k_1 = N$, resulting in a single round of all-to-all communication [G].
- The algorithm requires a valid factorization of $N$; if $N$ is prime, the single-round all-to-all pattern may increase communication volume compared to multi-round strategies [G].

**Pseudocode:**
```python
def composite_front_to_back(img1, img2):
    """Standard front-to-back volume compositing."""
    return img1 * (1.0 - img2.alpha) + img2

def radix_k_compositing(N, my_id, my_image, all_images):
    """
    Perform Radix-k compositing.
    N: Total number of processors.
    my_id: ID of this processor (0 to N-1).
    my_image: The partial image held by this processor.
    all_images: List of images held by all processors (simulated for algorithm clarity).
    """
    # Step 1: Factorize N into group sizes k_i
    # Note: The sources do not specify the exact factorization algorithm.
    factors = []
    n_temp = N
    for k in [2, 3, 5, 7]:
        while n_temp % k == 0:
            factors.append(k)
            n_temp //= k
    if n_temp > 1:
        factors.append(n_temp)

    # Step 2: Execute rounds
    current_images = list(all_images)
    current_images[my_id] = my_image

    for k in factors:
        # Determine group boundaries for this processor
        group_id = my_id // k
        group_start = group_id * k
        group_end = group_start + k

        # Collect images from all processors in this group
        # In a distributed system, this corresponds to the direct send exchange
        group_images = [current_images[p] for p in range(group_start, group_end)]

        # Composite all images in the group
        combined = group_images[0]
        for img in group_images[1:]:
            combined = composite_front_to_back(combined, img)

        # Update local image
        current_images[my_id] = combined

    return current_images[my_id]
```

## Subtopics

### [Binary All-to-All Communication](17921-binary-all-to-all-communication.md)
Binary All-to-All Communication is an optimized distributed communication algorithm used to maintain an up-to-date image of the entire cluster memory state on each rendering node, replacing pre-determined page positions. It sets itself apart from the classical logical ring approach by reducing the number of communication steps from $P-1$ to $\log(P)$, thereby improving scalability and reducing sensitivity to communication latency.

### Binary-Tree Compositing
Binary-Tree Compositing is a compositing strategy for combining partial images from processing nodes, initially implemented as a simple binary-tree step [S3, unofficial]. It sets itself apart from Radix-k by using a fixed hierarchical tree structure rather than configurable group sizes per round [G]. It may be replaced later with more elaborate algorithms like binary-swap [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Scales to 16,000-way concurrency [S2]. Compatible with hybrid parallel systems, potentially leading to faster compositing times than MPI Alltoallv-based approaches [S2].
- **Strengths:** Allows any number of processors [S1]. Combines direct send flexibility with binary swap performance [S1].
- **Limitations:** Performance depends on the factorization of $N$ [G]. Not given in the sources.

## Background
Radix-k Compositing was proposed by Peterka et al. [S1]. It was introduced in a paper demonstrating good scaling up to 16,000-way concurrency [S2]. The method is part of a hybrid distributed-memory parallel volume rendering scheme that combines object-order and image-order approaches to reduce load imbalance [S1].
