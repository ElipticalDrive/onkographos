# Radix-k Compositing

Also called: Radix-k

## Overview
Radix-k compositing is a parallel image compositing strategy designed for distributed-memory systems that combines the flexibility of direct send with the performance characteristics of binary-swap compositing [S1]. It solves the limitation of binary-swap methods, which require the number of processors to be a power of two, by allowing any number of processors $N$ to participate in the compositing phase [S1]. Unlike its parent method, 2-3 Swap Compositing, which restricts group sizes to 2 or 3, Radix-k allows variable group sizes per round, provided their product equals $N$ [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** $N$ processors, each holding a partial image (or region thereof) generated from their assigned volume data.
*   **Output:** A single fully composited image distributed across the processors (or gathered to a root, depending on the specific implementation context, though the source implies distributed ownership of regions).

**Data Structures:**
*   **Processor Grouping:** A sequence of integers $k_1, k_2, \dots, k_m$ representing the group sizes for each round of communication.
*   **Image Region:** Each processor $p$ owns a specific spatial region of the current image.

**Algorithm Steps:**
1.  **Decomposition:** Determine a sequence of group sizes $k_i$ for $i = 1$ to $m$ such that the product of all group sizes equals the total number of processors:
    $$ \prod_{i=1}^{m} k_i = N $$
    The source notes that processors are divided into groups of twos or threes in the general description, but the specific Radix-k definition allows variable $k_i$ [S1].
2.  **Round Execution:** For each round $i$ from 1 to $m$:
    a.  Partition the $N$ processors into disjoint groups of size $k_i$.
    b.  Within each group, processors exchange their current image data using a direct send method.
    c.  Each processor composites the received data with its own local data.
    d.  The result is the updated image region for that processor.
3.  **Completion:** After $m$ rounds, the compositing is complete.

**Parameters:**
*   $N$: Total number of processors.
*   $k_i$: Group size for round $i$.

**Edge Cases and Pitfalls:**
*   **Factorization:** The choice of $k_i$ values affects performance. The source does not specify an optimal factorization strategy, only that the product must equal $N$ [S1].
*   **Load Imbalance:** As with other hybrid schemes, load imbalance can impact performance, as execution time is determined by the slowest processor [S1].

## Subtopics

### Binary-Tree Compositing
A compositing strategy for combining partial images from processing nodes, initially implemented as a simple binary-tree step [S2, unofficial]. It involves implementing a simple binary-tree compositing step to combine partial images [S2, unofficial]. It may be replaced later with a more elaborate binary-swap compositing algorithm [S2, unofficial]. This approach is noted in the context of AMR data visualization where partial images are composited in order of node numbers [S2, unofficial].

## Operating characteristics
*   **Flexibility:** Allows any number of processors $N$, unlike binary-swap which requires $N$ to be a power of two [S1].
*   **Performance:** Combines the flexibility of direct send with the performance of binary swap [S1].
*   **Load Imbalance:** Like other hybrid distributed-memory parallel volume rendering techniques, it can suffer from load imbalance, where execution time is determined by the slowest processor [S1].
*   **Complexity:** The number of rounds $m$ depends on the factorization of $N$. The communication pattern involves direct sends within groups of size $k_i$.

## Background
Radix-k compositing was proposed by Peterka et al. [S1]. It is part of the development of scalable hybrid schemes for ray-casting of unstructured volume data [S1]. The method addresses the limitations of previous parallel compositing techniques that were constrained by processor count requirements [S1].
