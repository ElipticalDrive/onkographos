# Parallel Binary-Swap Compositing


## Overview
Parallel Binary-Swap Compositing is a method for combining independently rendered image tiles from multiple processors in a massively parallel environment [S1]. It solves the synchronization and communication bottlenecks of naive parallel compositing by reducing the image size at each step, ensuring all processors remain busy with useful work [S1]. Unlike approaches where communication dominates or processors idle, this method maintains full processor utilization by pairing processors in a binary-swap fashion [S1].

## How it works
**Inputs and Outputs:**
- Input: $N$ independent rendered image tiles, one per processor. The total image dimensions are $W \times H$.
- Output: A single composite image of size $W \times H$.

**Data Structures:**
- The method utilizes a k-D tree structure to manage the compositing tree and data distribution [S1]. The specific layout of the k-D tree nodes is not detailed in the sources, but it serves to organize the pairwise compositing operations [S1].

**Steps:**
1. **Initialization:** Each processor holds its own rendered tile. The current image width $W_{curr}$ is set to the full image width $W$. The number of active processors is $N$.
2. **Pairing:** Processors are paired. In a standard binary-swap, processor $i$ pairs with processor $i \oplus 2^k$, where $k$ is the current step index (starting from 0). The sources note that the method requires $N$ to be a power of two for the basic implementation [S1].
3. **Compositing and Reduction:**
   - For each pair, one processor (the receiver) composites its current image with the image received from the other processor (the sender).
   - The compositing operation is typically front-to-back alpha compositing: $C_{out} = C_{src} + (1 - \alpha_{src}) C_{dst}$.
   - Crucially, the image size for sending and compositing decreases at each step [S1]. This implies that the spatial resolution of the tiles being exchanged is halved (or reduced) in one dimension (likely the width) at each stage, or the tiles are aggregated into larger blocks while the number of tiles decreases. The sources state "decreasing image size for sending and compositing makes the overall compositing process very efficient" [S1].
   - The sender transmits its tile to the receiver.
   - The receiver updates its local image.
   - The sender becomes inactive for this step.
4. **Iteration:** The number of active processors is halved ($N \leftarrow N/2$). The step index $k$ increments. The process repeats until only one processor remains with the final composite image.
5. **Termination:** The single remaining processor holds the final composite image.

**Parameters:**
- $N$: Number of processors. Must be a power of two for the basic method [S1].
- $W, H$: Initial image dimensions.

**Edge Cases and Pitfalls:**
- If $N$ is not a power of two, the basic method requires padding or masking unused processors, which reduces efficiency [S1]. This limitation is addressed by the child method [2-3 Swap Compositing](12223-2-3-swap-compositing.md).
- Precision issues in alpha compositing accumulation over many steps are not explicitly detailed but are a general concern in volume rendering [G].

## Subtopics

### [2-3 Swap Compositing](12223-2-3-swap-compositing.md)
A variant that allows any number of processors $N$, eliminating the power-of-two requirement and improving scalability.

## Operating characteristics
- **Time Complexity:** $O(\log N)$ steps, where $N$ is the number of processors [S1].
- **Memory Complexity:** Each processor stores its local image tile. The total memory is proportional to the image size [S1].
- **Performance:** The method is efficient because it decreases the image size for sending and compositing at each step, reducing communication overhead [S1]. It keeps all processors busy, avoiding idle time [S1].
- **Strengths:** Simple implementation using a k-D tree structure [S1]. High efficiency in massively parallel environments [S1].
- **Limitations:** Requires $N$ to be a power of two for the basic implementation, leading to wasted resources if $N$ is not a power of two [S1].

## Background
The method was developed for parallel volume ray-tracing algorithms [S1]. It was implemented on the CM-5 and a network of scientific workstations [S1]. The tests used 32 high-performance workstations, including IBM RS/6000-550, HP9000/730, and Sun Sparc-10/30 machines [S1]. The algorithm divides both computation and memory load across all processors, allowing it to render data sets too large for a single uniprocessor [S1].
