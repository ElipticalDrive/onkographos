# Multi-Threaded Tile-Based Rendering

Also called: threaded rasterization

## Overview
Multi-Threaded Tile-Based Rendering is a parallelization strategy that divides the screen height into tiles and processes each tile in a separate thread to parallelize the rasterization workload [S1, unofficial]. It differs from [Tile-Based Alpha Compositing](1215-tile-based-alpha-compositing.md) by focusing on the rasterization phase itself rather than just compositing pre-rasterized fragments, and from [Screen Parallel Rendering](5725-screen-parallel-rendering.md) by dividing the screen into tiles processed by threads on a single machine rather than subscreens distributed across multiple processors [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Screen height ($H$), screen width ($W$), and the number of available hardware threads.
*   **Output:** A fully rasterized framebuffer.

**Data Structures:**
*   **Tile Struct:** Contains four integer fields defining the rectangular region of the screen to render: `x_min`, `x_max`, `y_min`, and `y_max` [S1, unofficial].

**Algorithm Steps:**
1.  **Determine Thread Count:** Calculate the number of threads ($T$) as the maximum of 1 and the system's reported hardware concurrency. If `std::thread::hardware_concurrency()` returns 0, $T$ is set to 1 to prevent division by zero or empty thread vectors [S1, unofficial].
2.  **Calculate Tile Height:** Compute the height of each tile ($h_{tile}$) as $H / T$ [S1, unofficial].
3.  **Initialize Threads:** For each thread index $i$ from 0 to $T-1$:
    *   Calculate the vertical range for the tile.
    *   Set `y_min` = $i \times h_{tile}$.
    *   Set `y_max` = $(i == T-1) ? H-1 : (i+1) \times h_{tile} - 1$.
    *   Set `x_min` = 0 and `x_max` = $W-1$ (assuming full width per tile).
    *   Launch a worker thread executing the `renderTile` function with this tile's coordinates [S1, unofficial].
4.  **Join Threads:** Wait for all worker threads to complete [S1, unofficial].

**Pseudocode:**
```python
import threading

def hardware_concurrency():
    """Returns the number of logical processors available [G]."""
    import os
    return os.cpu_count() or 1

def render_tile(tile):
    """Renders the specific tile region. Actual rasterization logic is not provided in the sources [S1, unofficial]."""
    # Process pixels within tile.x_min, tile.x_max, tile.y_min, tile.y_max
    pass

def multi_threaded_tile_rendering(screen_height, screen_width):
    # Step 1: Determine number of threads
    threads_count = max(1, hardware_concurrency())

    # Step 2: Calculate tile height
    tile_height = screen_height // threads_count

    threads = []

    # Step 3: Create and launch threads
    for i in range(threads_count):
        y_min = i * tile_height
        # Last tile extends to the end of the screen to handle non-divisible heights
        if i == threads_count - 1:
            y_max = screen_height - 1
        else:
            y_max = (i + 1) * tile_height - 1
        
        tile = {
            'x_min': 0,
            'x_max': screen_width - 1,
            'y_min': y_min,
            'y_max': y_max
        }
        
        thread = threading.Thread(target=render_tile, args=(tile,))
        threads.append(thread)
        thread.start()

    # Step 4: Join all worker threads
    for thread in threads:
        thread.join()
```

**Parameters:**
*   `threads_count`: Typically equal to `std::thread::hardware_concurrency()` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Hardware Concurrency:** If the system reports 0 cores, the algorithm defaults to 1 thread to avoid runtime errors [S1, unofficial].
*   **Non-Divisible Heights:** The last tile must explicitly extend to `screen_height - 1` to ensure all pixels are covered when $H$ is not evenly divisible by $T$ [S1, unofficial].

## Subtopics

### [Screen Parallel Rendering](5725-screen-parallel-rendering.md)
Screen Parallel Rendering is a parallelization technique that exploits parallelism in screen space by dividing the screen into regions and assigning each region to a processor. It solves the problem of rendering large scenes by distributing the workload of ray traversal across multiple processors, where each processor is responsible for the entire ray for its assigned subscreen. Unlike object-parallel methods that partition the volume data, this approach partitions the image space, allowing each processor to access the full dataset. It is a form of sort-first parallel rendering, where primitives are distributed based on their projected screen location.

### [Tile-Based Rasterization](5910-tile-based-rasterization.md)
Tile-Based Rasterization is a GPU-accelerated rendering primitive that divides the image plane into fixed-size tiles, assigning one CUDA thread block to each tile to process all fragments within that region. It solves the parallelization bottleneck of global rasterization by localizing the workload, allowing threads within a block to share splat data in fast shared memory and blend them in front-to-back order. Unlike Screen Parallel Rendering, which assigns individual threads to pixels without explicit tile-level coordination, this method leverages the spatial coherence of tiles to optimize memory access patterns for splat blending.
