# CUDA Tile-and-Bin Implementation

Also called: Tile-and-Bin CUDA Pipeline, Tile-and-Bin CUDA Pipeline for 2D Bitmaps, tile-based differentiable splatting for 2D bitmaps

## Overview
The CUDA Tile-and-Bin Implementation is a parallelization strategy for computing the forward and backward passes of 2D bitmap primitive rendering on a GPU [S1, unofficial]. It partitions the image plane into tiles and assigns primitives to the tiles they overlap, using one CUDA thread block per tile to achieve complete pixel-level parallelism [S1, unofficial]. It differs from its parent, [Binned Raster Traversal](10295-binned-raster-traversal.md), by explicitly managing the tile-primitive mapping on the CPU and staging primitive parameters in shared memory for cooperative compositing, rather than relying on a linear scan of a pre-binned pair stream [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ primitives, each defined by parameters $\{(x_i, y_i, s_i, \theta_i, \nu_i, c_i)\}_{i=1}^N$, where $(x_i, y_i)$ is position, $s_i$ is scale, $\theta_i$ is rotation, $\nu_i$ is opacity logit, and $c_i$ is color logit [S1, unofficial].
*   **Input:** Image dimensions $W_{canvas} \times H_{canvas}$ and tile size $T$ (default 32) [S1, unofficial].
*   **Output:** Rendered image $I \in [0,1]^3$ and alpha channel $I_\alpha$ [S1, unofficial].

**Data Structures:**
*   **Tile-Primitive Mapping:** A CPU-side structure mapping each tile to a list of primitives whose bounding boxes overlap the tile region (with a small padding margin) [S1, unofficial].
*   **Shared Memory:** Stages per-primitive parameters cooperatively by threads in a block [S1, unofficial].
*   **Global Memory:** Caches computed $\alpha_k$ and $c_k$ values in FP16 for each primitive assigned to the tile [S1, unofficial].

**Formulas:**
The transmittance $T_k(x,y)$ before primitive $k$ and the final image color $I(x,y)$ are computed as [S1, unofficial]:
$$
T_k(x,y) = \prod_{j=0}^{k-1} (1 - \alpha_j(x,y))
$$
$$
I(x,y) = \sum_{k=0}^{N-1} T_k(x,y) \alpha_k(x,y) \sigma(c_k) \in [0,1]^3
$$
where $\alpha_k$ is the opacity, $\sigma$ is the sigmoid function, and $c_k$ is the primitive color [S1, unofficial].

The interpolated primitive value $M_i(x,y)$ at pixel $(x,y)$ is computed via bilinear interpolation [S1, unofficial]:
$$
M_i(x,y) = \mathbf{w}^T \mathbf{p} = \sum_{j=0}^{3} w_j p_j
$$
where $\mathbf{p}$ are the four corner values of the primitive template and $\mathbf{w}$ are the interpolation weights [S1, unofficial].

**Parameters:**
*   **Tile Size ($T$):** Default value is 32 pixels [S1, unofficial].

**Algorithm Steps:**

1.  **CPU Preprocessing:** Partition the image plane into $T \times T$ tiles. Assign each primitive to every tile whose bounding box on the image plane overlaps the tile region [S1, unofficial].
2.  **Kernel Launch:** Launch a CUDA grid with dimensions $(\lceil W_{canvas}/32 \rceil, \lceil H_{canvas}/32 \rceil)$ blocks. Each block contains $32 \times 32$ threads [S1, unofficial].
3.  **Forward Pass (Per Tile):**
    *   Each thread block loads the primitives assigned to its tile into shared memory [S1, unofficial].
    *   Each thread $(x,y)$ iterates through the primitives assigned to the tile:
        *   Transform $(x,y)$ to primitive space $(u,v)$ [S1, unofficial].
        *   Compute $M_i(x,y)$ via bilinear interpolation at $(u,v)$ [S1, unofficial].
        *   If $M_i(x,y) < \epsilon$, skip the primitive [S1, unofficial].
        *   Compute $\alpha_k = \alpha_{max} \cdot \sigma(\nu_i) \cdot M_i(x,y)$ and $c_k = \sigma(c_i)$ [S1, unofficial].
        *   Cache $\alpha_k$ and $c_k$ in global memory (FP16) [S1, unofficial].
    *   **Alpha Compositing:**
        *   Initialize transmittance $T \leftarrow 1$ and accumulated color $C \leftarrow (0,0,0)$ [S1, unofficial].
        *   Iterate through the cached primitives $k$ in front-to-back order:
            *   Store $T_k$ for the backward pass [S1, unofficial].
            *   Update $C \leftarrow C + T \alpha_k c_k$ [S1, unofficial].
            *   Update $T \leftarrow T (1 - \alpha_k)$ [S1, unofficial].
        *   Write $I[x,y] \leftarrow C$ and $I_\alpha[x,y] \leftarrow 1 - T$ [S1, unofficial].
4.  **Backward Pass:**
    *   Uses the same grid structure [S1, unofficial].
    *   Each thread rebuilds its cached primitive list [S1, unofficial].
    *   Computes gradients via the chain rule [S1, unofficial].
    *   Accumulates gradients using packed `half2` atomic operations for parameter pairs $(x_i, y_i)$, $(\nu_i, s_i)$, $(\theta_i, c_{r,i})$, and $(c_{g,i}, c_{b,i})$ [S1, unofficial].

    # Global coordinates
    gx = blockIdx.x * T + x
    gy = blockIdx.y * T + y

        return

    # Cache alpha and color for this pixel
    cached_alphas = []
    cached_colors = []
    
    for prim in shared_prims:
        # Transform (gx, gy) to (u, v) in primitive space
        u, v = transform(prim, gx, gy)
        
        # Bilinear interpolation
        Mi = bilinear_interpolate(prim.template, u, v)
        
        if Mi < epsilon:
            continue
            
        alpha = alpha_max * sigmoid(prim.nu) * Mi
        color = sigmoid(prim.c)
        
        cached_alphas.append(alpha)
        cached_colors.append(color)
        
    # Alpha compositing
    T_trans = 1.0
    C_color = (0.0, 0.0, 0.0)
    stored_Ts = []
    
    for k in range(len(cached_alphas)):
        stored_Ts.append(T_trans)
        ak = cached_alphas[k]
        ck = cached_colors[k]
        
        C_color = C_color + T_trans * ak * ck
        T_trans = T_trans * (1.0 - ak)
        
    # Write output
    write_pixel(gx, gy, C_color, 1.0 - T_trans)

## Operating characteristics
*   **Time Complexity:** The forward pass is $O(N_{tile} \cdot N_{prim\_tile})$ where $N_{tile}$ is the number of tiles and $N_{prim\_tile}$ is the average number of primitives per tile. The backward pass has similar complexity but includes atomic operations.
*   **Memory Complexity:** Requires shared memory for primitive staging and global memory for caching intermediate values. The use of FP16 halves bandwidth requirements [S1, unofficial].
*   **Performance:** Achieves full pixel-level parallelism within a tile [S1, unofficial]. The use of `half2` atomic operations reduces contention and halves atomic bandwidth usage [S1, unofficial].
*   **Strengths:** Efficient for 2D bitmap primitives; supports differentiable rendering; allows optimization at low resolution and export at high resolution [S1, unofficial].
*   **Limitations:** Atomic operations are unsuitable for generating layered PSD files; requires a dedicated export kernel for non-differentiable rendering [S1, unofficial].

## Background
The method was introduced in "DiffBMP: Differentiable Rendering with Bitmap Primitives" [S1, unofficial]. It follows tile-based differentiable splatting practices as in [57], adapted for 2D bitmap primitives [S1, unofficial].
