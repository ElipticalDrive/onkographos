# XPR Rasterizer

Also called: XPR's rasterizer, static-shape rasterization

## Overview
The XPR rasterizer converts variable-length per-tile primitive lists into a fixed-size matrix $Q$ of dimensions $T \times P_{\max}$, enabling execution on accelerators that require static tensor shapes and prohibit dynamic control flow [S1, unofficial]. Unlike traditional rasterizers that rely on dynamic lists or linked structures, this method uses a sequence of static-shape modules (Replicate, Assign, Cull, Sort, Gather) to produce a dense, depth-sorted array of primitive indices for each tile, padding unused entries with a sentinel value [S1, unofficial]. It builds on [CUDA Tile-and-Bin Implementation](13681-cuda-tile-and-bin-implementation.md) by replacing dynamic per-tile lists with fixed-size tensors.

## How it works
**Inputs and Outputs:**
*   **Input:** $M$ visible primitives $p_0, \dots, p_{M-1}$ from the filter stage. Each primitive $p_i$ provides its depth $z_i$, tile-space bounding box $[x_i^{\min}, x_i^{\max}) \times [y_i^{\min}, y_i^{\max})$, and tile count $tc_i$ (the number of tiles its bounding box intersects) [S1, unofficial].
*   **Output:** A fixed-size matrix $Q$ of size $T \times P_{\max}$, where row $t$ contains up to $P_{\max}$ depth-sorted primitive indices for tile $t$ [S1, unofficial]. Entries beyond the valid count $c_t$ are padded with $-1$ [S1, unofficial].

**Data Structures:**
*   **Flat Intersection Array:** A temporary array of size $I$, where $I = \sum_{i=0}^{M-1} tc_i$ is the total intersection count [S1, unofficial]. Each element corresponds to a specific tile-primitive intersection [S1, unofficial].
*   **Matrix $Q$:** Dimensions $T \times P_{\max}$ [S1, unofficial]. $T$ is the number of tiles [S1, unofficial]. $P_{\max}$ is the maximum number of primitives per tile [S1, unofficial].
*   **Bounds Array:** Stores start index $b_j$ and count $c_j$ for each valid tile $j$ [S1, unofficial].

**Parameters:**
*   $P_{\max}$: Maximum primitives per tile. Typical values are 4096 or 8192 [S1, unofficial].
*   $T$: Total number of tiles [S1, unofficial].
*   $W'$: Tile-grid width [S1, unofficial].
*   $T_{sentinel}$: Sentinel tile ID (denoted as $T$ in sources) indicating rejection [S1, unofficial].

**Steps:**

1.  **Replicate:** Compute prefix sums of the tile counts $tc_i$ to determine the start offset $s_i$ for each primitive in the flat intersection array of size $I$ [S1, unofficial]. For each primitive $p_i$, generate $tc_i$ entries in the flat array starting at $s_i$ [S1, unofficial].
2.  **Assign Tile ID:** For each replicated entry with local offset $r$ within primitive $p_i$'s bounding box, compute the tile coordinates:
    $$ w_i = x_i^{\max} - x_i^{\min} $$
    $$ x = x_i^{\min} + (r \bmod w_i) $$
    $$ y = y_i^{\min} + \lfloor r / w_i \rfloor $$
    $$ t = y W' + x $$
    Assign tile ID $t$ to the entry [S1, unofficial].
3.  **Cull:** Apply an optional `tile_cull` function to each candidate primitive-tile pair using tile-cull data returned by the projection stage [S1, unofficial]. If a candidate fails `tile_cull` or a contribution threshold, reassign its tile ID to $T_{sentinel}$ [S1, unofficial]. If no `tile_cull` is provided, keep all candidates [S1, unofficial].
4.  **Sort and Identify Bounds:** Lexicographically sort the flat array by $(tile\ ID, depth)$ [S1, unofficial]. Rejected candidates (ID $T_{sentinel}$) move to the end [S1, unofficial]. For each valid tile $t_j$, the surviving candidates form a contiguous segment [S1, unofficial]. Record each segment's start $b_j$ and count $c_j$ [S1, unofficial].
5.  **Gather:** Using $b_j$ and $c_j$, write to matrix $Q$:
    $$ Q[j, k] = P_{sort}[b_j + k] \quad \text{for } 0 \le k < \min(c_j, P_{\max}) $$
    where $P_{sort}$ is the sorted primitive-index array [S1, unofficial]. Pad remaining entries of $Q[j, :]$ with $-1$ [S1, unofficial].

**Pseudocode:**

```python
def xpr_rasterizer(primitives, tile_grid_width, num_tiles, p_max, tile_cull_func=None):
    """
    primitives: list of M primitives. Each primitive has:
        - depth: float
        - bbox: (x_min, x_max, y_min, y_max)
        - tc: int (tile count)
    tile_grid_width: int W'
    num_tiles: int T
    p_max: int P_max
    tile_cull_func: optional function(tile_id, primitive_data) -> bool
    """
    m = len(primitives)
    sentinel_t = num_tiles  # Sentinel ID larger than any valid tile ID (0 to T-1)

    # Step 1: Replicate
    tile_counts = [p.tc for p in primitives]
    start_offsets = [0] * m
    current_offset = 0
    for i in range(m):
        start_offsets[i] = current_offset
        current_offset += tile_counts[i]
    total_intersections = current_offset  # I
    flat_array = []

    # Step 2: Assign Tile ID
    for i in range(m):
        p = primitives[i]
        x_min, x_max, y_min, y_max = p.bbox
        w_i = x_max - x_min
        for r in range(tile_counts[i]):
            x = x_min + (r % w_i)
            y = y_min + (r // w_i)
            t = y * tile_grid_width + x
            flat_array.append((t, p.depth, i))

    # Step 3: Cull
    culled_flat_array = []
    for tile_id, depth, p_idx in flat_array:
        is_valid = True
        if tile_cull_func is not None:
            # The exact tile_cull function and contribution threshold logic are not specified in the sources [G].
            # is_valid = tile_cull_func(tile_id, primitives[p_idx])
            pass
        if is_valid:
            culled_flat_array.append((tile_id, depth, p_idx))
        else:
            culled_flat_array.append((sentinel_t, depth, p_idx))

    # Step 4: Sort and Identify Bounds
    # Lexicographically sort by (tile_id, depth). Sentinels (sentinel_t) sort to the end.
    culled_flat_array.sort(key=lambda x: (x[0], x[1]))

    bounds = {}  # tile_id -> (start_index, count)
    n = len(culled_flat_array)
    i = 0
    while i < n:
        tile_id = culled_flat_array[i][0]
        if tile_id == sentinel_t:
            break  # Remaining are rejected
        j = i
        while j < n and culled_flat_array[j][0] == tile_id:
            j += 1
        count = j - i
        bounds[tile_id] = (i, count)
        i = j

    # Step 5: Gather
    Q = [[-1] * p_max for _ in range(num_tiles)]
    for tile_id, (start_idx, count) in bounds.items():
        for k in range(min(count, p_max)):
            p_idx = culled_flat_array[start_idx + k][2]
            Q[tile_id][k] = p_idx

    return Q
```

**Edge Cases and Pitfalls:**
*   Dynamic memory and control flow are not well supported on accelerators compiling to static tensor shapes (e.g., TPUs) [S1, unofficial]. XPR avoids this by using fixed-size matrices and static loops [S1, unofficial].
*   If a tile exceeds $P_{\max}$ primitives, excess entries are padded with $-1$ and ignored by the shader [S1, unofficial].
*   The sentinel tile ID must be larger than any valid tile ID to ensure lexicographic sorting places rejected candidates at the end of the flat array [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Dominated by the sorting step in "Sort and Identify Bounds", which is $O(I \log I)$ where $I$ is the total intersection count [G].
*   **Memory Complexity:** Requires $O(I)$ for the flat intersection array and $O(T \times P_{\max})$ for the output matrix $Q$ [S1, unofficial].
*   **Strengths:** Eliminates dynamic memory allocation and dynamic control flow, making it suitable for accelerators like TPUs that compile to static tensor shapes [S1, unofficial].
*   **Limitations:** Requires setting $P_{\max}$ statically [S1, unofficial]. Performance depends on the choice of $P_{\max}$; larger values increase memory usage but reduce the risk of clipping [S1, unofficial].
*   **When to use:** When rendering on hardware with limited dynamic control flow support or when a static-shape pipeline is required [S1, unofficial].
*   **When not to use:** When memory is extremely constrained and $P_{\max}$ must be small, leading to significant primitive clipping, or when the scene has highly variable and unpredictable primitive densities that cannot be bounded by a reasonable $P_{\max}$ [S1, unofficial].

## Background
The XPR rasterizer was introduced in the XPR renderer, an extensible cross-platform point-based differentiable renderer [S1, unofficial]. It was designed to address the limitations of dynamic data structures on modern accelerators, specifically targeting compatibility with TPUs and other static-shape hardware [S1, unofficial]. The method is part of a broader pipeline that includes filtering, projection, and shader stages, all expressed as static-shape operations [S1, unofficial].
