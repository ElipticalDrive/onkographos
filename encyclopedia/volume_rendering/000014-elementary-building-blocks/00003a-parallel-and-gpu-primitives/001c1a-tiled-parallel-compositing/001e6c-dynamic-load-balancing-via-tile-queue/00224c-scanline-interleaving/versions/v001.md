# Scanline Interleaving

Also called: Image partitioning strategy, Scanline Interleaving Image Partitioning

## Overview
Scanline Interleaving is an image-space partitioning strategy that distributes pixels across processors in a striped, round-robin pattern to balance the computational load of ray-merging operations [S1, unofficial][S2]. It addresses the unpredictability of depth complexity caused by local variations in cell sizes, which can lead to uneven workloads if pixels are assigned contiguously [S2]. Unlike sibling methods that may rely on complex load estimation or cell-based assignment, this approach uses a simple geometric distribution to disperse merging operations evenly across the screen [S1, unofficial][S2].

## How it works
**Inputs:**
- Image dimensions: width $W$, height $H$ (number of scanlines).
- Number of processors: $P$.
- Pixel coordinates: $(x, y)$ where $0 \le x < W$ and $0 \le y < H$.

**Outputs:**
- Processor ID $p$ assigned to each pixel.
- Per-pixel data structure: A linked list of ray segments maintained at each pixel location, which are merged to form the final pixel value [S2].

**Data Structures:**
- **Pixel Buffer:** An array of size $W \times H$. Each element contains a pointer to a linked list of ray segments.
- **Ray Segment:** A structure containing color, opacity, and depth information, linked via a `next` pointer.

**Algorithm:**
1. For each scanline $y$ from $0$ to $H-1$:
2.   Calculate the processor ID $p$ using the formula:
       $$ p = y \mod P $$
3.   For each pixel $x$ from $0$ to $W-1$:
4.     Assign the pixel $(x, y)$ to processor $p$.
5.     Initialize the linked list at $(x, y)$ to empty.

**Parameters:**
- $P$: Number of processors.
- $H$: Vertical resolution.

**Edge Cases and Pitfalls:**
- **Vertical Resolution Constraint:** Performance degrades if the vertical resolution $H$ is not several times larger than the number of processors $P$ [S2]. If $H \approx P$, the granularity of load balancing becomes too coarse, potentially leading to imbalance if certain scanlines have significantly higher depth complexity [S2].
- **Fine-Grained Interleave:** For scenarios with many processors ($P > H$), a finer-grained pixel interleave (e.g., block-based or 2D tiling) is conjectured to be advantageous, though not detailed in the primary sources [S2].
- **Cell Size Variations:** The method is specifically designed to handle variations in depth complexity caused by local variations in cell sizes [S2].

**Pseudocode:**
```python
def assign_scanline_interleaving(width, height, num_processors):
    """
    Assigns pixels to processors using scanline interleaving.
    
    Args:
        width (int): Image width in pixels.
        height (int): Image height in pixels (number of scanlines).
        num_processors (int): Number of available processors.
        
    Returns:
        dict: A mapping of (x, y) coordinates to processor IDs.
    """
    assignments = {}
    
    # Iterate over each scanline (row)
    for y in range(height):
        # Determine processor ID for this scanline using round-robin
        processor_id = y % num_processors
        
        # Assign all pixels in this scanline to the same processor
        for x in range(width):
            assignments[(x, y)] = processor_id
            
    return assignments
```

## Subtopics

### Load-Balanced Cell Assignment
Assigns cells to processors based on estimated workload rather than image space. Choose when cell complexity varies significantly more than image-space depth complexity. See [Load-Balanced Cell Assignment](4194-load-balanced-cell-assignment.md).

## Operating characteristics
- **Time Complexity:** $O(W \times H)$ for the assignment phase, where $W$ is width and $H$ is height. The modulo operation is constant time per pixel.
- **Memory Complexity:** $O(W \times H)$ to store the assignment map and per-pixel linked lists.
- **Performance:** Effective when $H \gg P$. Performance degrades if $H$ is not several times larger than $P$ [S2].
- **Strengths:** Simple to implement; requires no preprocessing or load estimation; disperses merging operations evenly [S1, unofficial][S2].
- **Limitations:** Coarse granularity when $P$ is large relative to $H$; does not account for horizontal variations in complexity within a scanline [S2].
- **When to Use:** When vertical resolution is high relative to the number of processors and cell sizes vary locally, causing depth complexity variations [S2].
- **When Not to Use:** When the number of processors exceeds the vertical resolution significantly, or when horizontal complexity variations are dominant.

## Background
Scanline Interleaving was introduced as part of a scalable parallel cell-projection volume rendering algorithm for three-dimensional unstructured data [S1, unofficial][S2]. The method was developed to address the challenges of rendering unstructured grids where cell sizes vary, leading to unpredictable depth complexity in image space [S2]. It is used in conjunction with a cell-projection rendering algorithm, where processors scan-convert local cells into ray segments that are routed to their final destinations for merging [S1, unofficial][S2]. The approach complements a round-robin data distribution scheme for volume cells, which disperses nearby cells widely among processors [S1, unofficial].
