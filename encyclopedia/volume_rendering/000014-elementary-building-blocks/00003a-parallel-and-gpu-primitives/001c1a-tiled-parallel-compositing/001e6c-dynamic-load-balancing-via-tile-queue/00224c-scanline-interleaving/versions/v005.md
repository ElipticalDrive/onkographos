# Scanline Interleaving


## Overview
Scanline Interleaving is an image-space partitioning strategy that distributes pixels across processors in a striped, round-robin pattern to balance the computational load of ray-merging operations [S1, unofficial][S3, unofficial]. It addresses the problem of uneven depth complexity caused by local variations in cell sizes within unstructured meshes [S2, unofficial][S3, unofficial]. It operates on the image plane rather than the volume data space, distinguishing it from [Load-Balanced Cell Assignment](4194-load-balanced-cell-assignment.md), and uses static cyclic assignment rather than dynamic task queuing, distinguishing it from [Farm on Demand (FD)](7455-farm-on-demand-fd.md) [G]. The volumetric rendering integral for each sub-part is calculated independently on different processors, and the final image is reconstructed by placing these sub-images side-by-side according to their positions [S2, unofficial].

## How it works
**Inputs:**
- Image dimensions: width $W$, height $H$ (number of scanlines).
- Number of processors: $P$.

**Outputs:**
- Assignment of each pixel to a processor.
- Final merged pixel values (color and opacity).

**Data Structures:**
- Per-pixel linked list of ray segments maintained at each pixel location, which are merged to form the final pixel value [S4].

**Steps:**
1. Partition the image space such that rows (scanlines) are distributed cyclically among processors [S1, unofficial].
2. Assign successive scanlines to processors in round-robin fashion using the formula $\text{processor\_id} = y \pmod P$, where $y$ is the scanline index ($0 \le y < H$) and $P$ is the number of processors [S3, unofficial][S4].
3. Each processor scan-converts its local cells to produce ray segments, which are routed to their final destinations in image space for merging [S1, unofficial].
4. At each pixel location, maintain a linked list of ray segments, which are merged to form the final pixel value [S4].
5. Reconstruct the final image by placing the independently calculated sub-images side-by-side according to their positions [S2, unofficial].

**Parameters:**
- $P$: Number of processors.
- $H$: Vertical resolution.

**Edge Cases and Pitfalls:**
- Performance degrades if the vertical resolution is not several times larger than the number of processors [S2, unofficial][S3, unofficial][S4].
- Suffers from load imbalance due to transparent pixels in the final image [S2, unofficial].
- A single data block may be accessed by multiple processors to calculate a single image, requiring data sharing between processors, which is exacerbated when the viewpoint changes [S2, unofficial].
- When using numerous processors, finer-grained pixel interleaving is required to more effectively distribute high-density regions over more processors [S3, unofficial][S4].

**Pseudocode:**
```python
def assign_scanlines(width, height, num_processors):
    """
    Assigns each pixel in the image to a processor using scanline interleaving.
    
    Args:
        width (int): Number of columns (x-resolution).
        height (int): Number of rows (y-resolution).
        num_processors (int): Total number of processors P.
        
    Returns:
        dict: A dictionary mapping (x, y) coordinates to processor IDs.
    """
    assignment = {}
    for y in range(height):
        processor_id = y % num_processors
        for x in range(width):
            assignment[(x, y)] = processor_id
    return assignment
```

## Subtopics

### Pixel Interleaving
A finer-grained variant that assigns individual pixels or small blocks in round-robin order rather than entire scanlines [S3, unofficial][S4]. It sets itself apart by distributing high-density regions more effectively across many processors [S3, unofficial]. Choose it when using numerous processors or when scanline granularity is insufficient [S3, unofficial][S4].

### Hybrid Image Partitioning
Combines multiple partitioning strategies to handle varying scene complexities. Choose it when a single static scheme fails to balance load across diverse views. [Hybrid Image Partitioning](7675-hybrid-image-partitioning.md)

## Operating characteristics
- **Measured Performance:** Pixel interleaving speeds up overall rendering by nearly 10 percent on large systems compared to coarser partitioning [S3, unofficial].
- **Strengths:** Simple to implement; effectively disperses ray-merging operations when vertical resolution is high relative to processor count [S3, unofficial][S4].
- **Limitations:** Performance degrades if vertical resolution is not several times larger than processor count [S2, unofficial][S3, unofficial][S4]. Suffers from load imbalance due to transparent pixels [S2, unofficial]. Requires data sharing between processors [S2, unofficial].
- **When to Use:** When vertical resolution is several times larger than the number of processors and depth complexity is relatively uniform vertically [S3, unofficial][S4].
- **When Not to Use:** When the number of processors is large relative to vertical resolution, or when depth complexity is highly localized [S3, unofficial][S4]. Use finer-grained pixel interleaving instead [S3, unofficial].

## Background
Developed as part of a scalable parallel cell-projection volume rendering algorithm for three-dimensional unstructured data [S1, unofficial][S3, unofficial]. It is used in conjunction with cell-projection rendering algorithms, where cells are scan-converted into ray segments and routed to image space for merging [S1, unofficial]. The approach addresses local variations in cell sizes leading to variations in depth complexity in image space [S3, unofficial][S4].
