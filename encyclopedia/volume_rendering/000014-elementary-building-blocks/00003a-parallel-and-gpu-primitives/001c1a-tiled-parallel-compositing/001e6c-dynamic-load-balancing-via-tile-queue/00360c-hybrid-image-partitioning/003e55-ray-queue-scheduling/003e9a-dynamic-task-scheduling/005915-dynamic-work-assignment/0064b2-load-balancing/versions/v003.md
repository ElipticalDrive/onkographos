# Load Balancing

## Overview
Load balancing is a technique applied in both point assignment and image assignment to balance workload [S1, unofficial]. It operates as part of a locality-aware distribution framework that combines offline graph partitioning with online scheduling to reduce communication overhead [S1, unofficial]. Its impact is modest because communication time typically dominates the overall runtime in the tested setting [S1, unofficial].

## How it works
Inputs: A set of tasks (points or image patches) and a set of processing units (GPUs/nodes) [S1, unofficial].
Outputs: An assignment mapping that distributes tasks across processing units [S1, unofficial].

Numbered steps:
1. Offline Partitioning: The dataset is initially divided using a graph partitioning algorithm (e.g., METIS) to ensure spatial locality [S1, unofficial].
2. Online Scheduling: An online linear sum assignment algorithm is applied to the partitions to further balance the load [S1, unofficial].

Edge cases and pitfalls:

- Overhead: Online scheduling must be fast; however, studies show it introduces no significant overhead [S1, unofficial].

## Subtopics

### Online Linear Sum Assignment
An online scheduling technique paired with offline METIS partitioning to assign points or images, reducing communication overhead [S1, unofficial]. End-to-end speedups across scenes indicate that this online scheduling introduces no significant overhead [S1, unofficial].

## Operating characteristics
Time and Memory Complexity:
- The exact complexity depends on the solver used for the linear sum assignment and is not given in the sources [S1, unofficial].
- METIS partitioning time varies by scene complexity, ranging from 1.9s to 31.0s for large scenes [S1, unofficial].

Measured Performance:
- Removing load balancing causes performance reductions ranging from 1% to 14% [S1, unofficial].
- In contrast, removing hierarchical assignment ("w/o Hier.") results in 16% to 35% slower performance, and removing patching ("w/o Patch") results in 10% to 52% slower performance [S1, unofficial].
- The modest effect of load balancing stems from the fact that communication time dominates the overall runtime in the tested setting [S1, unofficial].

Strengths and Limitations:
- Strengths: Reduces communication overhead; complements hierarchical assignment; no significant scheduling overhead [S1, unofficial].
- Limitations: Modest impact compared to hierarchical partitioning and patching; less effective when communication is not the bottleneck [S1, unofficial].

## Background
The technique is implemented within a locality-aware distribution framework for large-scale point-based rendering [S1, unofficial]. The framework combines offline METIS bipartite graph partitioning with online linear sum assignment to significantly reduce communication overhead compared to random distribution strategies [S1, unofficial]. Prior work in point cloud partitioning includes manual heuristics, graphics data structures like KD-Trees, and clustering techniques like k-means [S1, unofficial].
