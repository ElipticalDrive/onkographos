# Load Balanced on Active Cells (LBAC)

Also called: LBAC Algorithm, LBC Algorithm, Load Balanced on Cells

## Overview
LBAC is a parallel isosurface extraction algorithm that partitions a 3D volume into contiguous regions along the Z-axis and dynamically balances the computational workload by equalizing the number of active cells among worker processes [S1]. Unlike its sibling [Load Balanced on Cells (LBC)](52-load-balanced-on-cells-lbc.md), which distributes the total number of cells evenly but suffers from unpredictable active cell distribution, LBAC ensures near-perfect load balancing for the triangulation phase by performing a preliminary analysis of active slice weights [S1]. It builds on [Farm on Demand (FD)](7455-farm-on-demand-fd.md) by using a static, contiguous Z-axis partitioning strategy rather than FD's random task assignment, which minimizes shared vertex overhead but requires a two-phase approach to achieve balance [S1].

## How it works
**Inputs:** A 3D volumetric dataset, an isovalue, and the number of parallel processes `numP` [S1].
**Outputs:** A partitioned isosurface mesh consisting of a Vertex table, a Triangle table, and an Index table containing indices of shared vertices [S1].

**Data Structures:**
*   `weight[w]`: An array of size `numW` (workers), storing the number of intersections (active cells) found in the slices assigned to worker `w` during the Analysis phase [S1].
*   `start[w]`, `stop[w]`: Arrays of size `numW`, defining the Z-axis slice interval boundaries assigned to each worker for the Isoextraction phase [S1].
*   `numW`: The number of worker processes, calculated as `numP - 1` (where one process acts as the coordinator) [S1].

**Algorithm Steps:**
The algorithm logically subdivides `numP` processes into one coordinator and `numW` workers [S1]. It executes three distinct phases:

1.  **Analysis Phase (Data Parallel):**
    *   The volume is partitioned into `numP` intervals of approximately `Zmax / numP` slices, identical to the LBC partitioning strategy [S1].
    *   Each worker independently processes its assigned interval [S1].
    *   Workers perform a lightweight "Cell Classification" equivalent to identify **active slices** (slices containing at least one intersection) [S1].
    *   Each worker counts the number of intersections in its interval and sends this count as `weight[w]` to the coordinator [S1].
    *   If the coordinator receives zero active slices from all workers, the algorithm terminates early, as no isosurface exists [S1].

2.  **Balancing Phase (Coordinator):**
    *   The coordinator receives the `weight` array from all workers [S1].
    *   It performs `ActiveSliceBalancing(weight, &start, &stop)` to redistribute the slices [S1].
    *   The goal is to assign contiguous slice intervals to each worker such that the sum of active cells in each worker's interval is approximately equal [S1].
    *   The granularity of this balancing is the **single slice**, allowing for fine-grained load distribution [S1].
    *   The coordinator communicates the new interval boundaries (`start[w]`, `stop[w]`) to each worker [S1].

3.  **Isoextraction Phase (Data Parallel):**
    *   Each worker executes the standard isosurface extraction algorithm (based on WWMC, modified for shared vertices) on its newly assigned slice interval [S1].
    *   Workers produce a Vertex table, a Triangle table, and an Index table containing indices of shared vertices on the boundaries of their intervals [S1].
    *   Shared vertices are communicated to neighboring processes to ensure topological consistency [S1].

**Pseudocode:**
```python
def lbac_algorithm(volume, isovalue, numP):
    """
    Simulates the LBAC parallel isosurface extraction algorithm.
    volume: 3D array of dimensions (X, Y, Z)
    isovalue: float threshold for extraction
    numP: number of parallel processes
    """
    numW = numP - 1
    coordinator_id = 0
    z_max = volume.shape[2]
    
    # Phase 1: Analysis (Data Parallel)
    # Each worker processes its initial interval
    weights = [0] * numW
    for w in range(numW):
        initial_start = w * (z_max // numP)
        initial_stop = (w + 1) * (z_max // numP)
        
        active_count = 0
        for z in range(initial_start, initial_stop):
            # Lightweight classification: count intersections in slice z
            # [G] Standard edge-vertex intersection check for marching cubes
            active_count += count_intersections_in_slice(volume, z, isovalue)
        weights[w] = active_count
        
    # Coordinator checks for empty isosurface
    if sum(weights) == 0:
        return None  # Early termination
        
    # Phase 2: Balancing (Coordinator)
    # Distribute slices to balance active cell counts
    starts = [0] * numW
    stops = [0] * numW
    active_slice_balancing(weights, starts, stops)
    
    # Phase 3: Isoextraction (Data Parallel)
    results = [None] * numW
    for w in range(numW):
        new_start = starts[w]
        new_stop = stops[w]
        
        vertex_table = []
        triangle_table = []
        index_table = []
        
        for z in range(new_start, new_stop):
            # Extract triangles for slice z using modified WWMC
            # [G] Standard isosurface extraction step
            triangles = extract_slice_triangles(volume, z, isovalue)
            triangle_table.extend(triangles)
            
        # Generate index table for shared vertices at interval boundaries
        # [G] Standard shared vertex handling step
        index_table = generate_shared_vertex_indices(vertex_table, new_start, new_stop)
        
        results[w] = {
            "vertices": vertex_table,
            "triangles": triangle_table,
            "indices": index_table
        }
        
    return results

def active_slice_balancing(weights, starts, stops):
    """
    Distributes slice intervals to balance active cell counts.
    Uses single-slice granularity.
    """
    total_active = sum(weights)
    if total_active == 0:
        return
        
    target_load = total_active / len(weights)
    current_load = 0
    current_start = 0
    
    for w in range(len(weights)):
        # Accumulate slices until target load is reached
        while current_load < target_load and current_start < len(weights):
            # [G] Standard load balancing accumulation step
            current_load += weights[current_start]
            current_start += 1
            
        starts[w] = current_start
        stops[w] = current_start  # [G] Placeholder for exact interval end logic based on evidence
        current_load = 0
```

**Parameters:**
*   `numP`: Number of parallel processes. Determines the initial slice interval size [S1].
*   `numW`: Number of worker processes (`numP - 1`) [S1].

**Edge Cases and Pitfalls:**
*   **Double Execution Overhead:** The Cell Classification operation (or its lightweight equivalent) is performed twice: once in the Analysis phase and again in the Isoextraction phase [S1].
*   **Empty Isosurfaces:** If the Analysis phase finds no active slices, the algorithm terminates early [S1].
*   **I/O Contiguity:** The algorithm assumes contiguous slice access [S1].
*   **Shared Vertices:** While LBAC balances triangles well, it produces more shared vertices than LBC because the rebalancing may split contiguous regions differently, though fewer than FD [S1].

## Subtopics

### Load Balanced on Cells (LBC)
Partitions volume by total cell count. Simpler but suffers from uneven active cell distribution. Choose when isosurfaces are homogeneous or when avoiding the Analysis phase overhead is critical [S1]. [LBC](52-load-balanced-on-cells-lbc.md)

### Farm on Demand (FD)
Uses random task assignment for fine-grained balancing. Produces more shared vertices and higher I/O overhead for contiguous data. Choose when data is already partitioned into scattered blocks or when extreme heterogeneity requires dynamic task stealing [S1]. [FD](7455-farm-on-demand-fd.md)

## Operating characteristics
**Time and Memory Complexity:**
*   The speedup depends heavily on the percentage of active cells [S1].
*   Achievable speedup depends on the incidence of the double execution of the input acquisition and the Cell Classification operations on the whole execution time, which is inversely related to the size of resulting isosurfaces [S1].
*   For small-to-medium isosurfaces, the overhead of the Analysis phase and the double execution of input acquisition/Cell Classification degrade performance, making LBAC less efficient than LBC [S1].

**Measured Performance:**
*   On dataset **1NKW-3018** (large, homogeneous) with 16 processes: LBC spends 0.30s on I/O and 0.66s on CPU computation, outperforming LBAC due to lower I/O overhead from single contiguous acquisition [S1].
*   On dataset **XT-25** (medium, large isosurface) with 16 processes: LBAC spends 10.2s on CPU and 9.1s on I/O [S1].
*   On dataset **XT-180**, LBAC spends 6.0s on CPU [S1].
*   On dataset **FC-1000** (non-homogeneous): LBC was severely unbalanced (process 5 had 7x the load of others) [S1]. LBAC achieved nearly perfect balance (5.5% to 6.4% load per worker) but produced 318,472 shared vertices (vs. 195,804 for LBC) [S1].

**Strengths and Limitations:**
*   **Strengths:** Achieves near-perfect load balancing of triangles and handles non-homogeneous isosurfaces effectively, while producing fewer shared vertices than FD [S1].
*   **Limitations:** Higher overhead for small/medium isosurfaces; sensitive to I/O patterns (requires contiguous slice storage); requires a coordinator process [S1].
*   **When to use:** Large datasets with large, non-homogeneous isosurfaces where perfect load balancing is required [S1].
*   **When not to use:** Small-to-medium isosurfaces (overhead dominates); datasets stored in scattered blocks (I/O penalty) [S1].

## Background
LBAC was introduced by D. D’Agostino, A. Clematis, and V. Gianuzzi in their 2000 paper "Parallel Isosurface Extraction for 3D Data Analysis Workflows in Distributed Environments" [S1]. It represents the third class of parallel algorithms in their classification, improving upon the LBC algorithm (first class) by adding a dynamic load balancing strategy based on active cell counts [S1]. It is distinct from the Farm on Demand (FD) algorithm (fourth class) by using a static, contiguous Z-axis partitioning rather than dynamic task distribution [S1].
