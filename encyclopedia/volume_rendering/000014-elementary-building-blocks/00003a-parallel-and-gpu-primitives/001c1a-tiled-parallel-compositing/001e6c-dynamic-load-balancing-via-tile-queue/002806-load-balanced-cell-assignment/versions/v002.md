# Load-Balanced Cell Assignment
Also called: Pixel Assignment

## Overview
Load-Balanced Cell Assignment (PA) distributes the ray-segment merging workload in tiled parallel volume rendering by assigning coarse 2D mesh-cells to processors [S1, unofficial]. It solves the problem of balancing computational load during the Local Pixel Merging (LPM) phase, where ray-segments generated by different processors for the same pixel must be combined into an atomic task per mesh-cell [S1, unofficial]. Unlike [Scanline Interleaving](2757-scanline-interleaving.md), which assumes neighbor mesh-cells have equal workload, PA explicitly models each mesh-cell's computational load based on its global ray-segment count to achieve a balanced distribution [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A set of processors $\{P_1, \dots, P_r\}$; a 2D coarse mesh imposed on the image screen; for each mesh-cell $m$, the subset of processors $P_m \subseteq \{P_1, \dots, P_r\}$ that generated ray-segments for pixels in $m$ during the local rendering phase; the local ray-segment count $r_{km}$ for each processor $P_k \in P_m$; and the global ray-segment count $R_m$ [S1, unofficial].
*   **Output:** An assignment mapping each mesh-cell $m$ to a single processor $P_{\text{assign}}(m)$ [S1, unofficial].

**Data Structures**
*   **Mesh:** A 2D grid of cells covering the image screen. Cells should be close to square shapes to ensure scalability of the decomposition [S1, unofficial].

**Definitions**
*   Let $P_m$ be the subset of processors that generated ray-segments for pixels in mesh-cell $m$ [S1, unofficial].
*   Let $r_{km}$ be the local ray-segment count of processor $P_k$ for mesh-cell $m$ [S1, unofficial].
*   Let $R_m$ be the global ray-segment count of mesh-cell $m$, defined as:
    $$ R_m = \sum_{P_k \in P_m} r_{km} $$
    The computational load of $m$ during the LPM step is assumed to be proportional to $R_m$ [S1, unofficial].

**Algorithm Steps**
1. Impose a 2D coarse mesh on the image screen, ensuring cells are close to square for scalability [S1, unofficial].
2. For each mesh-cell $m$, identify the subset of processors $P_m$ that generated ray-segments for its pixels during the local rendering phase [S1, unofficial].
3. Compute the local ray-segment count $r_{km}$ for each processor $P_k \in P_m$ and the global ray-segment count $R_m = \sum_{P_k \in P_m} r_{km}$ [S1, unofficial].
4. Assign the atomic task of merging ray-segments for mesh-cell $m$ to a single processor, using $R_m$ as the computational load metric [S1, unofficial].

**Pseudocode**
```python
def assign_cells(mesh_cells, processors):
    """
    Assigns mesh-cells to processors to balance load based on global ray-segment counts.
    mesh_cells: list of dicts with keys 'id', 'R_m' (global ray-segment count)
    processors: list of processor IDs
    """
    # Initialize load tracker for each processor
    processor_loads = {p: 0 for p in processors}
    assignment = {}

    # Assign each mesh-cell to the processor with the current minimum load
    # The source does not specify a sorting or scheduling heuristic [G]
    for cell in mesh_cells:
        target_proc = min(processor_loads, key=processor_loads.get)
        assignment[cell['id']] = target_proc
        processor_loads[target_proc] += cell['R_m']

    return assignment
```

**Parameters and Edge Cases**
*   **Mesh Shape:** Mesh-cells should be close to square shapes for scalability [S1, unofficial].
*   **Granularity:** The overhead of the assignment step must be kept minimal because of the fine granularity of the pixel merging operations [S1, unofficial].

## Subtopics

### [Balanced-Load Minimized-Communication Assignment (BLMCA)](4259-balanced-load-minimized-communication-assignment-blmca.md)
BLMCA is a load-balanced cell assignment method for tiled parallel volume rendering that simultaneously minimizes inter-processor communication volume and load imbalance. It improves upon pure Minimized-Communication Assignment (MCA) and pure Best-Fit Decreasing (BFD) load balancing by incorporating MCA’s greedy communication criterion into the BFD heuristic, prioritizing the assignment of heavily loaded mesh-cells to reduce communication overhead while maintaining balanced workloads. Choose BLMCA when both communication volume and load balance are critical, as it balances the trade-off that pure MCA or pure BFD neglect.

## Operating characteristics
*   **Complexity:** The source does not provide explicit time or memory complexity for the assignment algorithm itself, only noting that the overhead must be minimal [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scalability of the decomposition depends on mesh-cells being close to square shapes [S1, unofficial].
*   **Strengths:** Explicitly minimizes load imbalance by using $R_m$ as the load metric, avoiding the communication overhead issues of Scanline Interleaving (SCA) which lacks explicit communication minimization [S1, unofficial].
*   **Limitations:** The source does not detail communication volume minimization for PA itself, only for MCA and BLMCA [S1, unofficial]. PA is described as simple but distinct from SCA's assumption that neighbor cells have equal workload [S1, unofficial].
*   **When to use/not use:** Use PA when computational load varies significantly across the image and must be explicitly balanced per mesh-cell; avoid it when neighbor cells can be assumed to have equal workload and zero-communication assignment is preferred [S1, unofficial].

## Background
The method is proposed in research on parallel direct volume rendering of unstructured grids based on object-space decomposition [S1, unofficial]. It addresses the Local Pixel Merging (LPM) phase where ray-segments generated by different processors must be merged, reducing the merging problem to an assignment problem on a 2D coarse mesh imposed on the image screen [S1, unofficial].
