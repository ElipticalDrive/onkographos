# Host-Device Memory Transfer with Events

Also called: CUDA Event-based H2D/D2H Benchmarking

## Overview
This method provides a precise measurement pipeline for Host-to-Device (H2D) and Device-to-Host (D2H) memory transfer times, as well as kernel execution latency, using CUDA events [S1, unofficial]. It isolates transfer and compute phases to benchmark hardware throughput independently of CPU scheduling noise [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Host pointers for source data, device pointers for destination buffers, kernel launch parameters, and an output device pointer [S1, unofficial].
- **Outputs:** Elapsed times in milliseconds for H2D, kernel execution, and D2H phases, plus calculated throughput in GB/s and samples per second [S1, unofficial].

**Data Structures:**
- **CUDA Events:** Eight event handles are created to mark specific points in the execution stream: `e2e_start`, `e2e_stop`, `h2d_start`, `h2d_stop`, `kernel_start`, `kernel_stop`, `d2h_start`, `d2h_stop` [S1, unofficial].
- **Streams:** All operations are recorded on a CUDA stream to ensure sequential ordering of events [S1, unofficial].

**Steps:**
1. Create the eight CUDA events using `cudaEventCreate` [S1, unofficial].
2. Record the start of the H2D transfer: `cudaEventRecord(h2d_start, stream)` [S1, unofficial].
3. Perform H2D memory copies for sigma, source, and I0 data [S1, unofficial].
4. Record the stop of the H2D transfer: `cudaEventRecord(h2d_stop, stream)` [S1, unofficial].
5. Record the start of the kernel execution: `cudaEventRecord(kernel_start, stream)` [S1, unofficial].
6. Launch the kernel [S1, unofficial].
7. Record the stop of the kernel execution: `cudaEventRecord(kernel_stop, stream)` [S1, unofficial].
8. Record the start of the D2H transfer: `cudaEventRecord(d2h_start, stream)` [S1, unofficial].
9. Perform D2H memory copy from the output device buffer to the host buffer [S1, unofficial].
10. Record the stop of the D2H transfer: `cudaEventRecord(d2h_stop, stream)` [S1, unofficial].
11. Record the end-to-end stop event: `cudaEventRecord(e2e_stop, stream)` [S1, unofficial].
12. Synchronize the end-to-end stop event to ensure all preceding operations on the stream are complete: `cudaEventSynchronize(e2e_stop)` [S1, unofficial].
13. Calculate elapsed times using `cudaEventElapsedTime` for each phase: `h2d_ms`, `kernel_ms`, and `d2h_ms` [S1, unofficial].

**Formulas:**
- **H2D Throughput:**
  $$ \text{Throughput}_{H2D} = \frac{2.0 \times \text{sample\_bytes} + \text{ray\_bytes}}{1.0 \times 10^9 / (\text{h2d\_ms} / 1000.0)} \text{ GB/s} $$
  Where `sample_bytes` is the size of a single sample structure and `ray_bytes` is the size of ray data [S1, unofficial].
- **D2H Throughput:**
  $$ \text{Throughput}_{D2H} = \frac{\text{ray\_bytes}}{1.0 \times 10^9 / (\text{d2h\_ms} / 1000.0)} \text{ GB/s} $$
  [S1, unofficial].
- **Samples per Second:**
  $$ \text{Samples/sec} = \frac{\text{total\_samples}}{\text{kernel\_ms} / 1000.0} $$
  [S1, unofficial].

**Parameters:**
- `sample_bytes`: Size of the sample data structure in bytes [S1, unofficial].
- `ray_bytes`: Size of the ray data structure in bytes [S1, unofficial].
- `total_samples`: Total number of samples processed by the kernel [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Warm-up:** The source explicitly excludes warm-up runs from the benchmarking pipeline to avoid measuring hardware initialization overhead [S1, unofficial].
- **Synchronization:** `cudaEventSynchronize` is required to ensure accurate timing, as CUDA events are asynchronous with respect to the host [S1, unofficial].

**Pseudocode:**
```python
class CUDA:
    @staticmethod
    def create_event(): return object()
    @staticmethod
    def create_stream(): return object()
    @staticmethod
    def record_event(event, stream): pass
    @staticmethod
    def memcpy_htod(dst, src, stream): pass
    @staticmethod
    def memcpy_dtoh(dst, src, stream): pass
    @staticmethod
    def elapsed_time(start, stop): return 0.0
    @staticmethod
    def synchronize_event(event): pass

def benchmark_memory_transfer_and_kernel(h_sigma, h_source, h_I0, d_sigma, d_source, d_I0, d_output, h_output_gpu, sample_bytes, ray_bytes, total_samples):
    cuda = CUDA()
    e2e_start = cuda.create_event()
    e2e_stop = cuda.create_event()
    h2d_start = cuda.create_event()
    h2d_stop = cuda.create_event()
    kernel_start = cuda.create_event()
    kernel_stop = cuda.create_event()
    d2h_start = cuda.create_event()
    d2h_stop = cuda.create_event()
    stream = cuda.create_stream()
    
    cuda.record_event(h2d_start, stream)
    cuda.memcpy_htod(d_sigma, h_sigma, stream)
    cuda.memcpy_htod(d_source, h_source, stream)
    cuda.memcpy_htod(d_I0, h_I0, stream)
    cuda.record_event(h2d_stop, stream)
    
    cuda.record_event(kernel_start, stream)
    # launch_kernel(stream)
    cuda.record_event(kernel_stop, stream)
    
    cuda.record_event(d2h_start, stream)
    cuda.memcpy_dtoh(h_output_gpu, d_output, stream)
    cuda.record_event(d2h_stop, stream)
    
    cuda.record_event(e2e_stop, stream)
    cuda.synchronize_event(e2e_stop)
    
    h2d_ms = cuda.elapsed_time(h2d_start, h2d_stop)
    kernel_ms = cuda.elapsed_time(kernel_start, kernel_stop)
    d2h_ms = cuda.elapsed_time(d2h_start, d2h_stop)
    
    h2d_throughput = (2.0 * sample_bytes + ray_bytes) / (1.0e9 / (h2d_ms / 1000.0))
    d2h_throughput = ray_bytes / (1.0e9 / (d2h_ms / 1000.0))
    samples_per_sec = total_samples / (kernel_ms / 1000.0)
    
    return h2d_ms, kernel_ms, d2h_ms, h2d_throughput, d2h_throughput, samples_per_sec
```

## Subtopics

### Neural-module Latency Benchmark
A variant used to measure feed-forward neural-module latency on discrete GPUs (specifically an H20) [S2, unofficial]. The method executes one warmup run to stabilize hardware state, followed by five synchronized CUDA-event measurements to capture execution time [S2, unofficial]. It was tested on the ETH3D scene with 8 input views at resolutions 1022×756, 756×560, 504×378, and 378×280 [S2, unofficial]. Measured latencies were: 5.619 s (mean) at 1022×756, 2.533 s at 756×560, 1.032 s at 504×378, and 0.564 s at 378×280 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The measurement overhead is constant relative to the number of events, but the benchmarked operations (memory copy, kernel execution) dominate the time [S1, unofficial].
- **Memory Complexity:** Requires memory for the CUDA event handles and the data buffers being transferred [S1, unofficial].
- **Performance:** The method measures raw PCIe bandwidth and kernel execution speed [S1, unofficial]. H2D throughput depends on `sample_bytes` and `ray_bytes` [S1, unofficial].
- **Strengths:** Isolates H2D, D2H, and kernel times, allowing precise bottleneck identification [S1, unofficial].
- **Limitations:** Requires synchronization for accurate timing, which can stall the CPU [S1, unofficial].

## Background
The method originates from high-performance computing benchmarks for matrix multiplication and GPU kernels, specifically documented in the `hpc_foundational_demos` repository [S1, unofficial]. It is also applied in recent research on feed-forward 3D Gaussian Splatting (InfiniSplat v2) to benchmark neural module latency on discrete GPUs [S2, unofficial].
