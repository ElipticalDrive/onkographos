# Asynchronous Pipeline (Overlap)
Also called: Concurrent SSD Read and GPU Rendering, Hierarchical Asynchronous Execution, Overlap, Overlap operations

## Overview
A pipelining strategy that overlaps SSD read/prefetch, Host-to-Device (H2D) staging, and GPU rendering/backpropagation to hide I/O latency in out-of-core volume rendering [S1, unofficial]. It sets itself apart from naive out-of-core loops by ensuring the GPU never stalls waiting for data, maintaining high utilization even when PCIe traffic is minimal [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of training iterations, each requiring a specific set of 3D Gaussian blocks (or volume chunks) resident in VRAM.
*   **Output:** Rendered images and gradients for the current iteration, with the working set updated for the next iteration.

**Data Structures:**
*   **CPU Cache:** Manages block residency and dirty tracking.
*   **GPU Block Buffers:** Double-buffered buffers to hold the current iteration's resident blocks and the next iteration's incoming blocks [S1, unofficial].
*   **CUDA Streams:** Separate streams for GPU compute and memory copies [S1, unofficial].
*   **I/O Threads:** Dedicated threads for SSD operations [S1, unofficial].

**Steps:**
1.  **Initialization:** Set up double-buffered GPU block buffers and separate CUDA streams for compute and copy operations. Initialize dedicated I/O threads for SSD read/prefetch/flush [S1, unofficial].
2.  **Overlap Execution:** For each iteration $t$, execute the following four operations concurrently:
    *   (i) **SSD Read/Prefetch:** Read/prefetch blocks required for iteration $t+1$ from SSD into CPU cache [S1, unofficial].
    *   (ii) **H2D Transfer:** Transfer incoming blocks for iteration $t+1$ from CPU cache to VRAM [S1, unofficial].
    *   (iii) **GPU Compute:** Render and backpropagate using the resident blocks for iteration $t$ [S1, unofficial].
    *   (iv) **D2H Transfer & Flush:** Transfer evicted blocks from VRAM back to CPU cache and asynchronously flush dirty blocks to SSD [S1, unofficial].
3.  **Synchronization:** Ensure that the GPU compute for iteration $t$ completes before the H2D transfer for iteration $t+1$ begins if there are dependencies, but overlap the I/O and compute phases as much as possible [S1, unofficial].
4.  **Block Management:** On re-admission, blocks are always fetched via an index, ensuring the GPU materializes the most recent version [S1, unofficial].

**Pseudocode:**
```python
# Initialize double-buffered GPU buffers
gpu_buffers = [Buffer(), Buffer()]
current_buf_idx = 0
next_buf_idx = 1

# Initialize CUDA streams
compute_stream = cuda.Stream()
copy_stream = cuda.Stream()

# Initialize I/O threads
io_thread = I/OThread()

def process_iteration(iteration):
    global current_buf_idx, next_buf_idx
    
    # Step 1: Prepare next iteration's data (Overlap with current compute)
    # Prefetch blocks for iteration + 1 from SSD to CPU cache
    io_thread.prefetch(iteration + 1)
    
    # Transfer next iteration's blocks from CPU cache to VRAM (Async)
    with copy_stream:
        transfer_blocks_to_gpu(gpu_buffers[next_buf_idx], iteration + 1)
        
    # Step 2: Compute current iteration (Overlap with next iteration's I/O)
    with compute_stream:
        render_and_backpropagate(gpu_buffers[current_buf_idx], iteration)
        
    # Step 3: Cleanup current iteration's data (Overlap with next iteration's compute)
    # Transfer evicted blocks from VRAM to CPU cache
    with copy_stream:
        transfer_evicted_blocks_to_cpu(gpu_buffers[current_buf_idx])
        
    # Flush dirty blocks from CPU cache to SSD
    io_thread.flush()
    
    # Swap buffers
    current_buf_idx, next_buf_idx = next_buf_idx, current_buf_idx
```

**Parameters:**
*   **Double Buffering:** Essential to allow simultaneous read/write of different block sets [S1, unofficial].
*   **CUDA Streams:** Must be separate to allow true concurrency between compute and copy [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **PCIe Saturation:** While overlap hides latency, excessive PCIe traffic can still bottleneck the system. Differential streaming (Tide) is often used in conjunction to minimize transfer volume [S1, unofficial].
*   **Stalls:** If the I/O or H2D transfer takes longer than the GPU compute, the GPU may still stall. Proper sizing of the working set and prefetching ahead is critical [S1, unofficial].
*   **Dirty Tracking:** Incorrect tracking of dirty blocks can lead to data loss or inconsistency [S1, unofficial].

## Subtopics

### Concurrent 3-Stage Pipeline
A pipeline architecture that maximizes hardware utilization by running three stages (Image Preparation, TripoSR Inference, Voxelization) simultaneously using queues and separate process pools [S2, unofficial]. Stage 1 (CPU) uses `ProcessPoolExecutor` to render emojis and apply stylization. Stage 2 (GPU) uses MPS to run TripoSR inference, processing 4 images per forward pass. Stage 3 (CPU) uses `ProcessPoolExecutor` to voxelize meshes. Stages are orchestrated using queues so that while the GPU processes batch $N$, CPUs prepare batch $N+1$ and voxelize batch $N-1$ [S2, unofficial]. On an M4 Pro, this achieves ~5 seconds per emoji, with ~80% GPU utilization and ~60% CPU utilization [S2, unofficial]. The GPU is the bottleneck due to sequential inference, whereas CPU stages are parallelizable [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces iteration time from 210.5 ms (serial) to 90.7 ms (overlapped) [S1, unofficial].
*   **Memory Complexity:** Requires double-buffered GPU memory for the working set [S1, unofficial].
*   **Performance:** Maintains low PCIe traffic (0.10 GB/iter) while achieving high throughput [S1, unofficial].
*   **Strengths:** Hides I/O latency, maximizes GPU utilization, scalable to large datasets (e.g., 102M primitives) [S1, unofficial].
*   **Limitations:** Complex implementation due to multi-threading and stream management. Sensitive to PCIe bandwidth and SSD speed [S1, unofficial].
*   **When to Use:** Out-of-core training/rendering where I/O latency is significant and GPU utilization is critical [S1, unofficial].
*   **When Not to Use:** In-core scenarios where all data fits in VRAM, or when I/O is extremely fast (e.g., NVMe with sufficient bandwidth) and overhead of pipelining is not justified [S1, unofficial].

## Background
Originated in TideGS (Scalable Training of Over One Billion 3D Gaussian Splatting Primitives via Out-of-Core Optimization) to handle training on datasets exceeding VRAM capacity [S1, unofficial]. It builds on GPU Asynchronous Streaming by adding a multi-stage overlap strategy [S1, unofficial].
