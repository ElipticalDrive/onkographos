# CPU-GPU Memory Transfer and Synchronization

Also called: Staging Buffer Transfer

## Overview
This method transfers Gaussian splatting pages from CPU-accessible memory to discrete GPU memory via PCIe using host-visible staging buffers [S1]. It solves the independent memory space problem of discrete GPUs, where the CPU cannot directly write to GPU VRAM [S1]. It differs from direct memory mapping used by integrated GPUs by explicitly staging data transfers [S1].

## How it works
**Inputs:**
- Gaussian data buffer (memory-mapped on CPU) [S1].
- Page table data [S1].
- Command buffers for graphics and compute queues [S1].

**Outputs:**
- Updated GPU memory with Gaussian data [S1].
- Updated index buffer for depth-sorted rendering [S1].
- Presented image frame [S1].

**Data Structures:**
- **Staging Buffer:** Host-visible memory on the GPU used for writing data from the CPU; its size limits the copy budget [S1].
- **Uniform Buffer:** Stores metadata for compute shader dispatches [S1].
- **Push Constant:** Defines parameters for the compute shader [S1].
- **Index Buffer:** Receives depth results post-dispatch [S1].

**Steps:**
1. **Page Update Initiation:** Record commands to draw a proxy mesh and reduce page IDs [S1]. Insert a pipeline barrier to ensure memory is flushed before processing results [S1].
2. **Command Submission:** Submit commands to a graphics and compute-capable queue [S1].
3. **CPU Wait:** Use a fence to wait for GPU completion before updating the page table on the CPU [S1].
4. **Data Transfer:** Begin transferring data to the staging buffer during the page table update; multi-threaded transfers are handled by drivers [S1].
5. **Second Command Buffer:** After the page table update, copy Gaussians to a second command buffer containing depth sorting and drawing commands, separated by a barrier [S1].
6. **Concurrent Recording:** Record commands for the second buffer in separate threads while data transfer occurs [S1].
7. **Depth Sorting:** Execute depth sorting via compute shaders, requiring nine dispatches with metadata in a uniform buffer defined by a push constant [S1].
8. **Index Buffer Update:** Post-dispatch, move depth results to the index buffer [S1].
9. **Rendering:** Render the final 3DGS scene using the updated index buffer [S1].
10. **Presentation:** After updating the page table and completing transfers, submit the command buffer; this triggers a semaphore to present the image [S1].
11. **Double Buffering:** Process two frames simultaneously, performing CPU work while the GPU presents the previous frame [S1].

**Parameters:**
- **Hardware:** NVIDIA GeForce GTX 1070 GPU, Intel Core i7-4770k CPU, DDR3 system memory, PCIe 3.0 [S1].
- **Proxy Mesh Resolution:** Low, Medium, High spatial resolutions affect quality and performance [S1].

**Pitfalls:**
- **Pipeline Stalls:** Strict synchronization during frame rendering causes the GPU to wait for task completion, reducing parallelism [S1].
- **Copy Budget:** Limited by staging buffer size and transfer time; prioritize important copies and delay LOD transitions under high load [S1].
- **Integrated GPUs:** This method targets discrete GPUs; integrated GPUs share memory with the CPU and do not require staging buffers [S1].

def submit_to_queue(queue):

def update_page_table(page_table):
    """Update the page table on the CPU."""
    page_table["updated"] = True

def transfer_to_staging_buffer(cpu_buffer, staging_buffer):
    """Begin transferring data to the staging buffer. Multi-threaded transfers are handled by drivers."""
    staging_buffer[:] = cpu_buffer[:]

def record_second_command_buffer(queue):
    """Record commands for the second buffer in a separate thread."""
    queue.append("second_buffer_commands")

def dispatch_compute_shaders(queue, num_dispatches=9):
    """Execute depth sorting via compute shaders. Requires nine dispatches with metadata in a uniform buffer, defined by a push constant."""
    for i in range(num_dispatches):
        queue.append(f"compute_dispatch_{i}")

def update_index_buffer(index_buffer, depth_results):
    """Post-dispatch, move depth results to the index buffer."""
    index_buffer[:] = depth_results

def render_scene(index_buffer):
    """Render the final 3DGS scene using the updated index buffer."""
    pass

def trigger_semaphore_and_present():
    """Submit command buffer triggers a semaphore, presenting the image."""
    pass

def render_frame(cpu_gaussian_buffer, page_table):
    command_queue = []
    staging_buffer = [0] * len(cpu_gaussian_buffer)
    index_buffer = []
    depth_results = []

    # Step 1: Page Update Initiation
    record_draw_proxy_mesh(command_queue)
    reduce_page_ids(command_queue)
    insert_pipeline_barrier(command_queue)

    # Step 2: Command Submission & CPU Wait
    submit_to_queue(command_queue)
    wait_for_fence(command_queue)

    # Step 3: Page Table Update & Data Transfer
    update_page_table(page_table)
    transfer_thread = threading.Thread(target=transfer_to_staging_buffer, args=(cpu_gaussian_buffer, staging_buffer))
    transfer_thread.start()

    # Step 4: Concurrent Command Recording
    second_buffer_thread = threading.Thread(target=record_second_command_buffer, args=(command_queue,))
    second_buffer_thread.start()

    transfer_thread.join()
    second_buffer_thread.join()

    # Step 5: Barrier & Depth Sorting
    insert_pipeline_barrier(command_queue)
    dispatch_compute_shaders(command_queue, num_dispatches=9)

    # Step 6: Index Buffer Update & Rendering
    update_index_buffer(index_buffer, depth_results)
    render_scene(index_buffer)

    # Step 7: Presentation
    trigger_semaphore_and_present()

    return command_queue, index_buffer

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Limited by staging buffer size [S1].
- **Performance:** Tested on NVIDIA GeForce GTX 1070, Intel Core i7-4770k, DDR3, PCIe 3.0 [S1]. Performance is crucial for 3DGS adoption on consumer hardware [S1].
- **Scaling:** Two frames can be processed simultaneously, allowing CPU work while GPU presents previous frame [S1].
- **Strengths:** Enables rendering on discrete GPUs with independent memory; allows concurrent CPU/GPU work [S1].
- **Limitations:** Staging buffer size limits copy budget; strict synchronization causes pipeline stalls [S1].
- **When to Use:** Discrete GPUs with independent memory [S1].
- **When Not to Use:** Integrated GPUs (shared memory) [S1].

## Background
Originated in the context of 3D Gaussian Splatting (3DGS) rendering on virtual memory systems [S1]. The method addresses the specific hardware constraints of discrete GPUs, which have independent memory connected via PCIe, unlike integrated GPUs found in mobile devices [S1]. The approach was evaluated on consumer-grade hardware (GTX 1070, i7-4770k) to ensure broad compatibility [S1].
