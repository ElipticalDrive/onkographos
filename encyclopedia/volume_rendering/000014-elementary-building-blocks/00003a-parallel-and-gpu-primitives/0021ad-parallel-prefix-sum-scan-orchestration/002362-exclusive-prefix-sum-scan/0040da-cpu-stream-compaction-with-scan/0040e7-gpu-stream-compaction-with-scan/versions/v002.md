# GPU Stream Compaction with Scan

Also called: Map-Scan-Scatter, Stream Compaction via Scan, GPU Stream Compaction (Work-Efficient)

## Overview
GPU Stream Compaction with Scan filters an input array of integers based on a boolean flag array, returning only elements where the flag is true into an output array while preserving their relative order [S1]. It efficiently compacts data by mapping input values to a binary mask, computing an exclusive prefix sum on the mask to generate output indices, and scattering the retained elements to those indices [S2, unofficial][S3, unofficial]. It sets itself apart from CPU-based compaction by leveraging the GPU's parallel architecture and a work-efficient parallel scan algorithm, achieving performance improvements of over 4x for large arrays [S3, unofficial].

## How it works
**Inputs and Outputs:**
- `idata`: Pointer to the constant input array of integers (size $n$) [S2, unofficial].
- `odata`: Pointer to the output buffer (size at least $n$) [S2, unofficial].
- `n`: Number of elements in the input array [S2, unofficial].
- `Output`: The resulting compacted array of size $M$ (where $M \le N$) [S1].

**Data Structures:**
The algorithm requires four device arrays, all allocated with size $N = 2^{\lceil \log_2 n \rceil}$ (the next power of two greater than or equal to $n$) [S2, unofficial]:
1. `dev_idata`: `int` array of size $N$. Stores the input data, zero-padded from index $n$ to $N-1$ [S2, unofficial].
2. `dev_temp`: `int` array of size $N$. Stores the binary mask (1 for keep, 0 for discard) [S2, unofficial].
3. `dev_scanArr`: `int` array of size $N$. Stores the exclusive prefix sum of the mask, representing output indices [S2, unofficial].
4. `dev_odata`: `int` array of size $N$. Stores the compacted output [S2, unofficial].

**Formal Specification:**
Given `Input` of integers and `Flag` of booleans of size $N$, the output `Output` of size $M$ satisfies:
$$ \forall j . 0 \le j < M: \text{Output}[j] = t \Rightarrow \exists i . 0 \le i < N: \text{Input}[i] = t \land \text{Flag}[i] $$
$$ \forall i . 0 \le i < N: \text{Input}[i] = t \land \text{Flag}[i] \Rightarrow \exists j . 0 \le j < M: \text{Output}[j] = t $$
$$ \forall i, j . 0 \le i, j < N: (\text{Flag}[i] \land \text{Flag}[j] \land i < j \iff \exists k, l. 0 \le k, l < M: \text{Output}[k] = \text{Input}[i] \land \text{Output}[l] = \text{Input}[j] \land k < l) $$ [S1].

**Steps:**
1. **Preprocessing (Zero-Padding):**
   - Compute $N = 2^{\lceil \log_2 n \rceil}$ [S2, unofficial].
   - Allocate `dev_idata`, `dev_odata`, `dev_temp`, and `dev_scanArr` of size $N$ [S2, unofficial].
   - Copy `idata` to `dev_idata` for the first $n$ elements [S2, unofficial].
   - Zero-pad `dev_idata` from index $n$ to $N-1$ [S2, unofficial].

2. **Map (Kernel `kernMapToBoolean`):**
   - For each thread $i$ in $[0, N)$:
     - If `dev_idata[i] != 0`, set `dev_temp[i] = 1`.
     - Else, set `dev_temp[i] = 0` [S2, unofficial][S3, unofficial].

3. **Scan (Exclusive Prefix Sum):**
   - Perform a work-efficient parallel exclusive scan on `dev_temp` to produce `dev_scanArr` [S2, unofficial][S3, unofficial].
   - The work-efficient scan proceeds in three phases: an Up-Sweep pass to compute inclusive sums in a tree structure, a root reset setting the final element to 0, and a Down-Sweep pass to compute exclusive sums [S2, unofficial].
   - The padded zeros do not affect the sum but ensure the tree structure remains complete [S2, unofficial].

4. **Scatter (Kernel `kernScatter`):**
   - For each thread $i$ in $[0, N)$:
     - If `dev_temp[i] == 1`:
       - Let `idx = dev_scanArr[i]`.
       - Set `dev_odata[idx] = dev_idata[i]` [S1][S3, unofficial].
     - Else:
       - Skip the thread; no write occurs [S1].

5. **Result Count:**
   - The number of remaining elements is derived from the scan result [S1].
   - The total count of kept elements equals the sum of the mask, which can be computed as `dev_scanArr[N-1] + dev_temp[N-1]` [S1].

**Pseudocode:**
```python
import math

def gpu_stream_compaction_with_scan(idata, n):
    if n == 0:
        return [], 0
    
    # Step 1: Preprocessing
    N = 1 << (math.ceil(math.log2(n)) if n > 1 else 0)
    dev_idata = [0] * N
    dev_odata = [0] * N
    dev_temp = [0] * N
    dev_scanArr = [0] * N
    
    for i in range(n):
        dev_idata[i] = idata[i]
        
    # Step 2: Map to Boolean
    for i in range(N):
        dev_temp[i] = 1 if dev_idata[i] != 0 else 0
            
    # Step 3: Exclusive Scan (Work-Efficient Simulation)
    # Up-Sweep (Inclusive)
    inclusive = [0] * N
    inclusive[0] = dev_temp[0]
    for i in range(1, N):
        inclusive[i] = inclusive[i-1] + dev_temp[i]
        
    # Root Reset & Down-Sweep (Exclusive)
    dev_scanArr[0] = 0
    for i in range(1, N):
        dev_scanArr[i] = inclusive[i-1]
        
    # Step 4: Scatter
    for i in range(N):
        if dev_temp[i] == 1:
            idx = dev_scanArr[i]
            dev_odata[idx] = dev_idata[i]
            
    # Step 5: Count
    count = dev_scanArr[N-1] + dev_temp[N-1]
    
    return dev_odata[:count], count
```

**Parameters:**
- `n`: Number of elements in the input array [S2, unofficial].
- `blockSize`: Thread block size for CUDA kernels (e.g., 1024) [S2, unofficial].
- `gridSize`: Calculated as `(N + blockSize - 1) / blockSize` [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Non-power-of-two sizes:** Input arrays must be zero-padded to the next power of two to ensure the work-efficient scan tree is complete [S2, unofficial][S3, unofficial].
- **Precision:** Integer types are used for indices and counts, avoiding floating-point precision issues [S1].
- **Boundaries:** The exclusive prefix sum values must be within the valid range of the Output array ($0$ to $M-1$) to be used safely as indices, which is guaranteed because for elements where `Flag[i]=1`, the exclusive prefix sum is strictly less than the total sum of flags ($M$) [S1].

## Operating characteristics
- **Time Complexity:** $O(N)$ work and $O(\log N)$ depth for the scan, where $N$ is the next power of two greater than or equal to $n$ [S2, unofficial].
- **Memory Complexity:** $O(N)$ additional memory for `dev_temp` and `dev_scanArr` [S2, unofficial].
- **Measured Performance:** On an RTX 2060 Super, for an array size of $2^{27}$, the work-efficient compact took 58.4025ms for power-of-two and 48.5331ms for non-power-of-two, over 4x faster than the CPU version (886.643ms) [S3, unofficial].
- **Strengths:** High performance on GPU, handles arbitrary input sizes via padding, work-efficient scan minimizes redundant operations [S1][S3, unofficial].
- **Limitations:** Requires additional memory for intermediate arrays, padding overhead for non-power-of-two sizes [S2, unofficial].
- **When to use:** When compacting large arrays on GPU and performance is critical [S3, unofficial].
- **When not to use:** For small arrays where CPU overhead is negligible, or when memory is constrained [S1].
