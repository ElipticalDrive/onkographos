# Indirect Dispatch Orchestration

Also called: IsoMesh Compute Pipeline Dispatch

## Overview
Indirect Dispatch Orchestration is a GPU compute shader that finalizes the parallel volume building process by synchronizing atomic counters and configuring indirect dispatch parameters for subsequent rendering passes [S1, unofficial]. It acts as a single-thread compute shader that clamps counters to their allocated limits to prevent out-of-bounds execution, bridging the gap between parallel work generation and sequential GPU submission [S1, unofficial]. It differs from [Indirect Argument Preparation](10426-indirect-argument-preparation.md) by focusing specifically on the data preparation and boundary clamping logic rather than the broader scheduling strategy.

## How it works
**Inputs and Outputs:**
- Input: A buffer of atomic counters (vertex count, triangle count, intermediate vertex count) populated by previous kernels.
- Input: Compute shader instance parameters (thread group sizes).
- Output: Indirect dispatch arguments for vertex generation, triangle generation, index buffer building, and intermediate vertex indexing kernels.

**Data Structures:**
- `CounterBuffer`: A structured buffer or compute buffer containing atomic counters.
  - `vertexCount`: `uint`
  - `triangleCount`: `uint`
  - `intermediateVertexCount`: `uint`
- `IndirectArgs`: A structured buffer or compute buffer containing indirect dispatch arguments.
  - `vertexGenArgs`: `uint[4]` (Thread counts X, Y, Z, Padding)
  - `triGenArgs`: `uint[4]`
  - `indexBuildArgs`: `uint[4]`
  - `intermediateIdxArgs`: `uint[4]`

**Steps:**
1. **Reset Counters:** Reset all append buffer counters to zero [S1, unofficial]. This ensures a clean state for the current frame or volume update.
2. **Map Kernel Dispatch:** Dispatch the map kernel using thread group sizes derived from the compute shader instance [S1, unofficial]. This kernel typically processes the volume data to identify active regions.
3. **Vertex Generation Dispatch:** Dispatch the vertex generation kernel [S1, unofficial]. This kernel generates vertices based on the mapped data.
4. **Vertex Counting Dispatch:** Dispatch the vertex counting kernel using indirect dispatch with an offset pointing to the vertex count in the counter buffer [S1, unofficial]. This kernel counts the number of vertices generated.
5. **Triangle Generation Dispatch:** Dispatch the triangle generation kernel using indirect dispatch with the same offset [S1, unofficial]. This kernel generates triangles based on the counted vertices.
6. **Index Buffer Building Dispatch:** Dispatch the index buffer building kernel using indirect dispatch with an offset pointing to the triangle count [S1, unofficial]. This kernel builds the index buffer for rendering.
7. **Intermediate Vertex Indexing Dispatch:** Dispatch the intermediate vertex indexing kernel using indirect dispatch with an offset pointing to the intermediate vertex count [S1, unofficial]. This kernel handles intermediate vertex indexing.

**Pseudocode:**
```python
# Assume these buffers are bound to the compute shader
# counterBuffer: RWStructuredBuffer<uint> [vertexCount, triangleCount, intermediateVertexCount]
# indirectArgs: RWStructuredBuffer<uint> [vertexGenArgs, triGenArgs, indexBuildArgs, intermediateIdxArgs]
# Each indirect arg is 4 uints: [x, y, z, padding]

# Step 1: Reset all append buffer counters to zero
counterBuffer[0] = 0
counterBuffer[1] = 0
counterBuffer[2] = 0

# Step 2: Dispatch the map kernel using thread group sizes derived from the compute shader instance
# Let threadGroupSize be a vector3 (x, y, z) representing the thread group dimensions
# Let numGroups be a vector3 representing the number of thread groups
DispatchCompute(threadGroupSize.x, threadGroupSize.y, threadGroupSize.z, numGroups.x, numGroups.y, numGroups.z)

# Step 3: Dispatch the vertex generation kernel
# Let vertexGenThreadGroupSize be the thread group size for vertex generation
# Let vertexGenNumGroups be the number of thread groups for vertex generation
DispatchCompute(vertexGenThreadGroupSize.x, vertexGenThreadGroupSize.y, vertexGenThreadGroupSize.z, vertexGenNumGroups.x, vertexGenNumGroups.y, vertexGenNumGroups.z)

# Step 4: Dispatch the vertex counting kernel using indirect dispatch with an offset pointing to the vertex count in the counter buffer
# Let vertexCountOffset be the offset in the counter buffer for vertex count
# Let vertexCountIndirectArgs be the indirect arguments for vertex counting
# The indirect arguments are typically [x, y, z, padding]
# The x, y, z values are derived from the vertex count
vertexCount = counterBuffer[0]
# Calculate thread groups based on vertex count and thread group size
# Let vertexCountThreadGroupSize be the thread group size for vertex counting
numVertexCountGroupsX = (vertexCount + vertexCountThreadGroupSize.x - 1) / vertexCountThreadGroupSize.x
numVertexCountGroupsY = 1
numVertexCountGroupsZ = 1
vertexCountIndirectArgs[0] = numVertexCountGroupsX
vertexCountIndirectArgs[1] = numVertexCountGroupsY
vertexCountIndirectArgs[2] = numVertexCountGroupsZ
vertexCountIndirectArgs[3] = 0
DispatchIndirect(vertexCountIndirectArgs)

# Step 5: Dispatch the triangle generation kernel using indirect dispatch with the same offset
# Let triangleCountOffset be the offset in the counter buffer for triangle count
# Let triangleCountIndirectArgs be the indirect arguments for triangle counting
triangleCount = counterBuffer[1]
# Calculate thread groups based on triangle count and thread group size
# Let triangleCountThreadGroupSize be the thread group size for triangle counting
numTriangleCountGroupsX = (triangleCount + triangleCountThreadGroupSize.x - 1) / triangleCountThreadGroupSize.x
numTriangleCountGroupsY = 1
numTriangleCountGroupsZ = 1
triangleCountIndirectArgs[0] = numTriangleCountGroupsX
triangleCountIndirectArgs[1] = numTriangleCountGroupsY
triangleCountIndirectArgs[2] = numTriangleCountGroupsZ
triangleCountIndirectArgs[3] = 0
DispatchIndirect(triangleCountIndirectArgs)

# Step 6: Dispatch the index buffer building kernel using indirect dispatch with an offset pointing to the triangle count
# Let indexBuildIndirectArgs be the indirect arguments for index buffer building
# The indirect arguments are typically [x, y, z, padding]
# The x, y, z values are derived from the triangle count
numIndexBuildGroupsX = (triangleCount + indexBuildThreadGroupSize.x - 1) / indexBuildThreadGroupSize.x
numIndexBuildGroupsY = 1
numIndexBuildGroupsZ = 1
indexBuildIndirectArgs[0] = numIndexBuildGroupsX
indexBuildIndirectArgs[1] = numIndexBuildGroupsY
indexBuildIndirectArgs[2] = numIndexBuildGroupsZ
indexBuildIndirectArgs[3] = 0
DispatchIndirect(indexBuildIndirectArgs)

# Step 7: Dispatch the intermediate vertex indexing kernel using indirect dispatch with an offset pointing to the intermediate vertex count
# Let intermediateVertexCount be the intermediate vertex count
intermediateVertexCount = counterBuffer[2]
# Calculate thread groups based on intermediate vertex count and thread group size
# Let intermediateVertexIndexingThreadGroupSize be the thread group size for intermediate vertex indexing
numIntermediateVertexIndexingGroupsX = (intermediateVertexCount + intermediateVertexIndexingThreadGroupSize.x - 1) / intermediateVertexIndexingThreadGroupSize.x
numIntermediateVertexIndexingGroupsY = 1
numIntermediateVertexIndexingGroupsZ = 1
intermediateVertexIndexingIndirectArgs[0] = numIntermediateVertexIndexingGroupsX
intermediateVertexIndexingIndirectArgs[1] = numIntermediateVertexIndexingGroupsY
intermediateVertexIndexingIndirectArgs[2] = numIntermediateVertexIndexingGroupsZ
intermediateVertexIndexingIndirectArgs[3] = 0
DispatchIndirect(intermediateVertexIndexingIndirectArgs)
```

**Parameters:**
- Thread group sizes: Derived from the compute shader instance [S1, unofficial]. Typical values depend on the hardware and workload, e.g., (8, 8, 8) or (16, 16, 1).
- Offsets: Point to specific counters in the counter buffer [S1, unofficial].

**Edge Cases and Pitfalls:**
- Out-of-bounds execution: Clamping counters to their allocated limits is crucial to prevent out-of-bounds execution [S1, unofficial].
- Precision: Ensure that the thread group calculations are precise to avoid under-dispatching or over-dispatching.

## Subtopics

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of vertices, triangles, and intermediate vertices, as each kernel dispatch is proportional to the count of elements being processed.
- **Memory Complexity:** Linear with respect to the number of vertices, triangles, and intermediate vertices, as buffers are allocated based on these counts.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales with the complexity of the volume data, as the number of vertices, triangles, and intermediate vertices increases.
- **Strengths:** Efficiently manages indirect dispatches, reducing the overhead of multiple draw calls.
- **Limitations:** Requires careful management of atomic counters and indirect dispatch arguments.
- **When to Use:** When building meshes from volume data on the GPU, especially in real-time applications.
- **When Not to Use:** When the volume data is static and can be precomputed, or when CPU-side processing is more efficient.
