# Indirect Argument Preparation

Also called: FPrepareIndirectArgsCS

## Overview
Indirect Argument Preparation is a GPU compute shader that prepares indirect dispatch and draw arguments from the visible splat count [S1, unofficial]. It translates raw visibility data into the specific argument structures required by the graphics API for subsequent rendering and sorting kernels, differing from sibling methods by focusing on argument buffer population rather than data compaction or scheduling [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: `VisibleSplatCount` (`StructuredBuffer<uint>`) [S1, unofficial].
*   Output 1: `IndirectDispatchArgs` (`RWStructuredBuffer<uint>`, `uint3` storing `numGroupsX`, `numGroupsY`, `numGroupsZ`) [S1, unofficial].
*   Output 2: `IndirectDrawArgs` (`RWStructuredBuffer<uint>`, 5 `uint`s for `DrawIndexedIndirect`) [S1, unofficial].
*   Output 3: `SortIndirectArgs` (`RWStructuredBuffer<uint>`, `uint3` storing `NumTiles`, `1`, `1`) [S1, unofficial].
*   Output 4: `SortParamsBuffer` (`RWStructuredBuffer<uint>`, `uint2` storing `SortCount`, `NumTiles`) [S1, unofficial].

**Parameters:**
*   `ComputeThreadGroupSize` (`uint32`): Thread group size for compute shaders [S1, unofficial].

**Steps:**
1.  Read the `VisibleSplatCount` buffer to determine the total number of visible splats for the current frame.
2.  Calculate the number of work groups required by dividing the total splat count by `ComputeThreadGroupSize`, rounding up to the nearest integer.
3.  Populate `IndirectDispatchArgs` with the calculated group counts for X, Y, and Z axes.
4.  Populate `IndirectDrawArgs` with the five `uint` parameters required by `DrawIndexedIndirect` (index count, start index location, start vertex location, start instance location, instance count).
5.  Populate `SortIndirectArgs` with `NumTiles` and fixed `1` values for Y and Z axes.
6.  Populate `SortParamsBuffer` with `SortCount` and `NumTiles`.

**Pseudocode:**
```python
def PrepareIndirectArgsCS(visible_splat_count: list[int], compute_thread_group_size: int) -> dict:
    # Input: visible_splat_count (StructuredBuffer<uint>)
    # Parameter: compute_thread_group_size (uint32)
    # Outputs: IndirectDispatchArgs, IndirectDrawArgs, SortIndirectArgs, SortParamsBuffer

    # Step 1: Compute total visible splats [G]
    total_splats = sum(visible_splat_count)

    # Step 2: Calculate dispatch group counts [G]
    num_groups = (total_splats + compute_thread_group_size - 1) // compute_thread_group_size

    # Step 3: IndirectDispatchArgs (uint3: numGroupsX, numGroupsY, numGroupsZ)
    indirect_dispatch_args = [num_groups, 1, 1]

    # Step 4: IndirectDrawArgs (5 uints for DrawIndexedIndirect) [G]
    # Standard Direct3D/Vulkan layout: index_count, start_index_location, start_vertex_location, start_instance_location, instance_count
    indirect_draw_args = [total_splats, 0, 0, 0, 0]

    # Step 5: SortIndirectArgs (uint3: NumTiles, 1, 1)
    sort_indirect_args = [1, 1, 1]

    # Step 6: SortParamsBuffer (uint2: SortCount, NumTiles)
    sort_params_buffer = [total_splats, 1]

    return {
        "IndirectDispatchArgs": indirect_dispatch_args,
        "IndirectDrawArgs": indirect_draw_args,
        "SortIndirectArgs": sort_indirect_args,
        "SortParamsBuffer": sort_params_buffer
    }
```

## Subtopics

### [Indirect Dispatch Orchestration](15194-indirect-dispatch-orchestration.md)
A GPU compute shader that finalizes the parallel volume building process by synchronizing atomic counters and configuring indirect dispatch parameters for subsequent rendering passes. It acts as a single-thread compute shader that clamps counters to their allocated limits to prevent out-of-bounds execution, bridging the gap between parallel work generation and sequential GPU submission. It differs from Indirect Argument Preparation by focusing specifically on the data preparation and boundary clamping logic rather than the broader scheduling strategy. Choose this variant when precise counter synchronization and out-of-bounds protection are required before sequential GPU submission.

## Background
Indirect Argument Preparation is part of the rendering pipeline for Gaussian Splatting, specifically within the OpenSplat4D plugin ecosystem [S1, unofficial]. The method is implemented as a compute shader (`FPrepareIndirectArgsCS`) and is used in conjunction with other compute kernels for map, vertex, triangle, and index generation. The broader context includes the use of Nanite-like precision settings and sort intervals to optimize performance in large-scale Gaussian Splatting scenes [S1, unofficial].
