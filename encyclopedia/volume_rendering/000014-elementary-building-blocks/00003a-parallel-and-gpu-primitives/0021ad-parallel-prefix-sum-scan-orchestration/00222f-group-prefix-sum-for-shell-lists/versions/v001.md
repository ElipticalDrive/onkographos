# Group Prefix Sum for Shell Lists


## Overview
Group Prefix Sum for Shell Lists is a parallel compaction method used in GPU-based isosurface extraction to reorganize shell list data structures. It replaces sequential compaction by a single thread with a parallel group-scan operation, enabling efficient packing of Active Octants (AOs) into brick-aligned chunks. It is distinguished from standard [Exclusive Prefix Sum (Scan)](3007-exclusive-prefix-sum-scan.md) by its specific application to shell lists and its integration with group-shared memory constraints in the `md_gto_iso_gpu` implementation.

## How it works
**Inputs and Outputs:**
*   Input: A list of shell records, where each shell contains references to AOs. Shells are grouped into blocks of 128.
*   Output: A compacted list of AOs, packed into chunks of at most 32 AOs. The octree ranges for a block are derived from the AO offsets of the first AOs in the shells.

**Data Structures:**
*   **Shells:** Stored in group-shared memory. Each block of 128 shells is packed into chunks.
*   **AOs:** Active Octants. Rows of C (likely coefficients or coordinates) are staged in group-shared memory.
*   **Field Records:** 16 field records are uploaded per group.

**Steps:**
1.  **Load Shells:** Load the shell records for a block of 128 into group-shared memory. All 16 field records are uploaded for each group.
2.  **Handle Inactive Lanes:** For inactive lanes (e.g., due to warp divergence or boundary conditions), loads from group-shared indices are clamped. This ensures that `llvmpipe` or similar backends do not fault on inactive lane accesses [S1, unofficial].
3.  **Compute Group Prefix Sum:** Apply `iso_group_prefix` to the shell list. This parallel scan determines the destination offsets for each shell's AOs in the compacted output buffer. Unlike sequential compaction by thread 0, this distributes the work across the group [S1, unofficial].
4.  **Pack AOs:** Using the computed offsets, scatter the AOs from the shells into the output buffer. Each chunk contains at most 32 AOs.
5.  **Update Octree:** Extract the AO offsets of the first AOs in the shells to define the octree ranges for the block. This is done once per pass for up to 4 tiles of 64 functions, where each lane owns a portion of the computation [S1, unofficial].

**Pseudocode:**
```python
def iso_group_prefix_compact(shells, group_size=128, max_aos_per_chunk=32):
    # Assume shells is a list of shell objects, each with an AO count or list
    # Output buffer for compacted AOs
    output_buffer = []
    
    # Step 1: Load into group-shared memory (conceptual)
    # In GPU code, this is handled by shared memory allocation and loading.
    # All 16 field records are uploaded.
    shared_shells = load_to_shared_memory(shells[:group_size])
    
    # Step 2: Compute prefix sums for offsets
    # iso_group_prefix computes exclusive prefix sums of AO counts
    # to determine start indices in the output buffer.
    offsets = compute_group_prefix_sum(shared_shells)
    
    # Step 3: Scatter AOs
    # Each thread/lane handles a subset of shells or AOs.
    # Inactive lanes must have clamped loads to avoid faults.
    for i in range(group_size):
        if is_active_lane(i):
            shell = shared_shells[i]
            start_idx = offsets[i]
            # Pack AOs into chunks of max_aos_per_chunk
            # This logic is implicit in the buffer management
            pack_aos(shell.aos, output_buffer, start_idx, max_aos_per_chunk)
        else:
            # Clamp loads for inactive lanes (llvmpipe compatibility)
            clamp_loads_for_inactive_lane(i)
            
    # Step 4: Update Octree
    # Octree ranges are derived from the first AO's offset in each shell
    octree_ranges = []
    for i in range(group_size):
        if is_active_lane(i):
            shell = shared_shells[i]
            if shell.aos:
                first_ao_offset = offsets[i] # Or computed from compacted position
                octree_ranges.append(first_ao_offset)
                
    return output_buffer, octree_ranges
```

**Parameters:**
*   `group_size`: 128 shells per block [S1, unofficial].
*   `max_aos_per_chunk`: 32 AOs per chunk [S1, unofficial].
*   `field_records`: 16 records uploaded per group [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Inactive Lanes:** If inactive lanes access group-shared memory without clamping, it may cause faults on certain backends like `llvmpipe` [S1, unofficial].
*   **Padding:** Orbital sets no longer pad their functions to even indices, which may affect alignment assumptions [S1, unofficial].
*   **Environment Flags:** The behavior can be reverted to old forms using `GTO_ISO_RELAX_FIRST=0` and `GTO_ISO_CORNERS_V2=0` [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** Parallel prefix sum is $O(\log n)$ for $n$ elements in the group, but with a small constant factor due to the fixed group size (128).
*   **Memory Complexity:** Requires group-shared memory for shells and field records. The output buffer size is proportional to the number of AOs.
*   **Performance:** The method is optimized for GPU execution, reducing the bottleneck of sequential compaction by thread 0. It allows for concurrent processing of shell lists.
*   **Strengths:** Efficient parallel compaction, reduced synchronization overhead compared to sequential methods, compatibility with various GPU backends via clamping.
*   **Limitations:** Fixed group size and chunk size may not be optimal for all scene densities. Requires careful handling of inactive lanes.

## Background
This method is part of the `md_gto_iso_gpu` implementation in the `mdlib` library, specifically in the context of optimized GPU isosurface extraction. It was introduced to improve performance by parallelizing the compaction of shell lists. The implementation details are found in the pull request `mdlib/pull/15` [S1, unofficial].
