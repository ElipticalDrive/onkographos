# Parallel Prefix Sum (Scan) Orchestration

Also called: Blelloch Scan, Exclusive/Inclusive Scan via Ping-Pong, Parallel Prefix Sum, Prefix Sum (Scan), Up-Sweep Down-Sweep Scan, Work-Efficient GPU Scan

## Overview
Parallel Prefix Sum (Scan) Orchestration is a method for computing prefix sums (scans) of an input array on the GPU using a multi-timestep iterative reduction strategy with a ping-pong buffer swap. It solves the problem of efficiently aggregating data (such as vertex counts or fragment indices) into a sequential format for subsequent parallel processing steps like stream compaction or indirect dispatch. Unlike naive iterative approaches that may require multiple kernel launches per level or fixed-size assumptions, this orchestration explicitly manages the up-sweep and down-sweep phases of a work-efficient tree-based scan (Blelloch scan) across discrete timesteps, handling arbitrary input sizes via padding and ensuring memory consistency through strict barrier synchronization between ping-pong buffers.

## How it works
**Inputs and Outputs:**
- Input: An array of $N$ elements (typically integers or floats) representing values to be summed.
- Output: An array of prefix sums. The method can produce either an exclusive scan ($O[i] = \sum_{j=0}^{i-1} I[j]$) or an inclusive scan ($O[i] = \sum_{j=0}^{i} I[j]$), depending on post-processing or specific kernel configuration.

**Data Structures:**
1.  **Ping-Pong Buffers (`prefixSumPingBuffer`, `prefixSumPongBuffer`):** Two storage buffers (e.g., `std430` in Vulkan or `cudaBuffer` in CUDA) of size equal to the padded input length (next power of two). They hold intermediate results during the up-sweep and down-sweep phases.
2.  **Push Constant (`timestep`):** A 32-bit integer indicating the current iteration step of the scan algorithm, used to determine the stride and operation within the kernel.
3.  **Host Buffer (`totalSumBufferHost`):** A host-accessible buffer used to retrieve the final total sum from the last element of the active ping-pong buffer after computation completes.

**Algorithm Steps:**
1.  **Padding:** Pad the input array size $N$ to the next power of two, $N_{p2}$. Let $L = \log_2(N_{p2})$.
2.  **Initialization:** Allocate `prefixSumPingBuffer` and `prefixSumPongBuffer` of size $N_{p2}$. Copy input data to `prefixSumPingBuffer`.
3.  **Iteration Count:** Calculate the number of timesteps (iterations) required: $T = \lceil \log_2(N) \rceil$. Note: Some implementations use $L$ for the full tree depth.
4.  **Loop over Timesteps ($t = 0$ to $T-1$):**
    a.  **Dispatch:** Launch a compute shader/kernel with workgroup size $W$ (e.g., 256) and grid size $\lceil N_{p2} / W \rceil$. Pass `timestep = t` as a push constant.
    b.  **Kernel Execution:**
        i.  Calculate global index: $idx = gl\_GlobalInvocationID.x$ (or equivalent).
        ii. **Bounds Check:** If $idx \ge N_{p2}$, return immediately.
        iii. **Up-Sweep Phase (if $t < L$):**
            -   Stride $s = 2^t$.
            -   If $idx$ is even and $idx + s < N_{p2}$:
                -   Read $val_{left} = src[idx]$, $val_{right} = src[idx+s]$.
                -   Write $dst[idx+s] = val_{left} + val_{right}$.
            -   Else if $idx$ is odd:
                -   Write $dst[idx] = src[idx]$.
        iv. **Down-Sweep Phase (if $t \ge L$):**
            -   Stride $s = 2^{L-1-t}$.
            -   If $idx$ is even:
                -   Read $val_{left} = src[idx]$, $val_{right} = src[idx+s]$.
                -   Write $dst[idx] = val_{left}$.
                -   Write $dst[idx+s] = val_{left} + val_{right}$.
            -   Else if $idx$ is odd:
                -   Write $dst[idx] = src[idx]$.
        v.  **Simplification for Orchestration (Ping-Pong Swap):**
            -   The orchestration described in [S1, unofficial] uses a simplified timestep-based logic where each kernel launch performs a specific update based on parity of $t$.
            -   If $t$ is even:
                -   If $idx < 2^t$: $dst[idx] = src[idx]$.
                -   Else: $dst[idx] = src[idx] + src[idx - 2^t]$.
            -   If $t$ is odd:
                -   If $idx < 2^t$: $src[idx] = dst[idx]$.
                -   Else: $src[idx] = dst[idx] + dst[idx - 2^t]$.
            -   *Note: This simplified logic effectively performs the up-sweep and down-sweep in a unified manner across timesteps, relying on the ping-pong swap to manage read/write dependencies.*
    c.  **Swap Buffers:** Swap `prefixSumPingBuffer` and `prefixSumPongBuffer`. Apply memory barriers to ensure all writes to the previous buffer are visible before the next kernel reads from it. The direction of the swap depends on the parity of $t$ to maintain data flow consistency.
5.  **Finalization:**
    a.  After the loop, the total sum is located at the last element ($N_{p2}-1$) of the active buffer.
    b.  Copy this value to `totalSumBufferHost` using a buffer copy region targeting the last element.
    c.  If an exclusive scan is required, shift the inclusive result right by one position and set $O[0] = 0$.

**Pseudocode:**
```python
def parallel_prefix_sum_orchestration(input_array, N):
    # 1. Padding
    N_p2 = 1
    while N_p2 < N:
        N_p2 *= 2
    
    # 2. Initialization
    ping_buffer = [0] * N_p2
    pong_buffer = [0] * N_p2
    for i in range(N):
        ping_buffer[i] = input_array[i]
    
    # 3. Iteration Count
    iters = ceil(log2(N))
    
    # 4. Loop over Timesteps
    for t in range(iters):
        timestep = t
        # Dispatch kernel with workgroup size 256
        # Kernel arguments: src=ping_buffer, dst=pong_buffer, index=gl_GlobalInvocationID.x, timestep=timestep
        
        # Simulate Kernel Execution for each thread index
        for idx in range(N_p2):
            if idx >= N_p2:
                continue
            
            if timestep % 2 == 0: # Even timestep
                if idx < 2**timestep:
                    pong_buffer[idx] = ping_buffer[idx]
                else:
                    index2 = idx - 2**timestep
                    pong_buffer[idx] = ping_buffer[idx] + ping_buffer[index2]
            else: # Odd timestep
                if idx < 2**timestep:
                    ping_buffer[idx] = pong_buffer[idx]
                else:
                    index2 = idx - 2**timestep
                    ping_buffer[idx] = pong_buffer[idx] + pong_buffer[index2]
        
        # Swap Buffers
        ping_buffer, pong_buffer = pong_buffer, ping_buffer
        
        # Apply synchronization barriers here in real implementation
        
    # 5. Finalization
    total_sum = ping_buffer[N_p2 - 1]
    
    # Optional: Convert to exclusive scan
    # exclusive_scan = [0] + ping_buffer[:-1]
    
    return ping_buffer, total_sum
```

**Parameters:**
-   `timestep`: Integer push constant, current iteration step $t$.
-   `numGroups`: Number of compute shader workgroups, calculated as $\lceil N_{p2} / 256 \rceil$.
-   `iters`: Number of iterations, $\lceil \log_2(N) \rceil$.

**Edge Cases and Pitfalls:**
-   **Non-Power-of-Two Inputs:** Must be padded to the next power of two. Elements beyond $N$ should be initialized to 0 to avoid affecting the sum.
-   **Barrier Ordering:** The ping-pong swap direction and barrier placement must strictly match the timestep parity to prevent read/write conflicts. [S1, unofficial]
-   **Power Calculation:** Using a naive loop for $2^t$ is inefficient; bit shifting (`1 << t`) should be used. [S1, unofficial]
-   **Bounds Checking:** Threads with $idx \ge N_{p2}$ must return immediately to avoid out-of-bounds memory access.

## Operating characteristics
-   **Time Complexity:** $O(\log N)$ parallel steps for the tree-based scan. Each step involves $O(N)$ work, but parallelized across threads.
-   **Memory Complexity:** $O(N)$ for the input and output arrays, plus $O(N)$ for the ping-pong buffers.
-   **Performance:** Work-efficient variants (Blelloch) perform $2N$ additions for up-sweep and $2N$ for down-sweep, totaling $4N$ operations. Naive iterative methods may perform more. [S2, unofficial]
-   **Strengths:** Handles arbitrary input sizes, work-efficient, suitable for GPU architectures with shared memory and barriers.
-   **Limitations:** Requires padding to power of two, complex synchronization logic, potential for race conditions if barriers are mismanaged.
-   **When to Use:** When stream compaction, indirect dispatch, or parallel aggregation is needed in volume rendering or isosurface extraction.
-   **When Not to Use:** For small arrays where CPU sequential scan is faster, or when memory bandwidth is severely constrained and $O(N)$ extra storage is prohibitive.

## Background
The parallel prefix sum is a fundamental primitive in parallel computing, with origins in the 1970s. The Blelloch scan algorithm, introduced by Guy E. Blelloch in 1990, is a work-efficient method using up-sweep and down-sweep phases. It has become a standard for GPU implementations due to its balance of work efficiency and memory access patterns. In volume rendering, it is used for tasks like fragment list compaction, vertex indexing, and indirect draw call generation.
