# Wait-Free Radix Sort

Also called: Hierarchical Blelloch Scan Sort

## Overview
A parallel sorting algorithm designed for heterogeneous GPU environments (specifically WebGPU) that avoids inter-workgroup spin-waiting by using a hierarchical Blelloch scan to compute element positions [S1, unofficial]. It solves the problem of stable, wait-free sorting across workgroups where scheduling order is not guaranteed, ensuring consistent behavior without busy-waiting [S1, unofficial]. It sets itself apart from siblings like [CUDA-based Exclusive Prefix Sum for Vertex Indexing](1112-cuda-based-exclusive-prefix-sum-for-vertex-indexing.md) by explicitly decoupling workgroup synchronization via a multi-level scan dispatch rather than relying on fixed scheduling assumptions or tile-based rasterizer constraints [S1, unofficial].

## How it works
**Inputs:** An array of $N$ 32-bit keys (e.g., depth values) to be sorted [S1, unofficial].
**Outputs:** A permutation of the input array sorted by key [G].

**Data Structures:**
*   `input`: Array of $N$ keys.
*   `output`: Array of $N$ values to be reordered.
*   `histogram`: Local buffer per workgroup of size 256, storing counts of each digit value $d \in [0, 255]$ [S1, unofficial].
*   `tile_sums`: Array of size $N/wg$, storing the sum of each workgroup's histogram for a specific digit [S1, unofficial].
*   `prefixes`: Array of size $N/wg$, storing the exclusive prefix sums of `tile_sums` [S1, unofficial].

**Parameters:**
*   $N$: Number of elements.
*   $wg$: Workgroup size (tile size).
*   $B$: Number of bits per pass (8).
*   $R$: Radix size ($2^B = 256$).
*   $P$: Number of passes ($32/B = 4$).

**Algorithm Steps:**
The full sort is performed by executing $P$ consecutive passes of an 8-bit radix sort, starting from the least significant bits [S1, unofficial]. In the $k$-th pass ($k=0 \dots P-1$), the algorithm processes bits $k \times 8$ to $(k + 1) \times 8 - 1$ of the key [S1, unofficial]. Each pass consists of three steps:

1.  **Local Histogram:** Each workgroup counts digit frequencies within its assigned elements [S1, unofficial].
2.  **Prefix Scan:** A hierarchical Blelloch scan is executed to compute two values:
    *   $\text{base}_d$: The global offset for digit $d$, equal to the total count of all elements with a digit value less than $d$ across all workgroups.
    *   $\text{prefix}_{wg}$: The inter-workgroup rank, representing the total count of elements with digit $d$ in all workgroups processed before the current workgroup.
    
    The Blelloch scan is implemented as a two-phase process:
    *   **Forward Pass (Upsweep):** Level $l_0$ performs an exclusive scan inside each workgroup tile of size $wg$ over the indicator stream for digit $d$, producing tile sums forming an array of length $N/wg$ [S1, unofficial]. Level $l_1$ runs the same Blelloch scan on this array to obtain prefixes across tiles, recursing until a single level remains [S1, unofficial].
    *   **Backward Pass (Downsweep):** The prefixes computed at level $l_1$ are added back to their corresponding $l_0$ tiles, and then to individual elements, yielding the inter-workgroup offset $\text{prefix}_{wg}$ [S1, unofficial].
    *   $\text{base}_d$ is read from the last level as the sum of counts of digits smaller than $d$ [S1, unofficial].
3.  **Scatter:** Each element $i$ is written to its new position $pos$ in the sorted array [S1, unofficial].

**Formulas:**
$$pos = \text{base}_d + \text{rank}_i$$
where $pos$ is the final position for an element originally at index $i$, $d$ is the specific digit value of the element, $\text{base}_d$ is the global offset equal to the total count of all elements with a digit value less than $d$, and $\text{rank}_i$ is the count of elements appearing before index $i$ sharing the same digit value $d$ [S1, unofficial].

$$\text{rank}_i = \text{prefix}_{wg} + \text{rank}_{\text{local}_i}$$
where $\text{prefix}_{wg}$ is the inter-workgroup rank (total count of elements with digit $d$ in all workgroups processed before the current one) and $\text{rank}_{\text{local}_i}$ is the intra-workgroup rank (number of elements with digit $d$ within the current workgroup before index $i$) [S1, unofficial].

**Pseudocode:**

```python
def wait_free_radix_sort(input_keys, N, wg):
    output = [0] * N
    # 32-bit sort requires 4 passes of 8-bit radix sort, LSB first [S1, unofficial]
    for k in range(4):
        shift = k * 8
        # Extract digit d for each element [S1, unofficial]
        digits = [(key >> shift) & 0xFF for key in input_keys]
        
        # Step 1: Local Histogram [S1, unofficial]
        # Each workgroup counts digit frequencies within its assigned elements.
        num_wgs = (N + wg - 1) // wg
        local_histograms = [[0] * 256 for _ in range(num_wgs)]
        for i in range(N):
            w = i // wg
            d = digits[i]
            local_histograms[w][d] += 1
        
        # Step 2: Prefix Scan (Hierarchical Blelloch) [S1, unofficial]
        # Compute tile sums for the current digit d across workgroups
        tile_sums = [hist[d] for hist in local_histograms]
        
        # Forward pass (upsweep): exclusive scan on tile_sums [S1, unofficial]
        prefixes = blelloch_exclusive_scan(tile_sums)
        
        # base_d is the sum of counts of digits smaller than d across all workgroups [S1, unofficial]
        base_d = sum(local_histograms[w][d_small] for w in range(num_wgs) for d_small in range(d))
        
        # Step 3: Scatter [S1, unofficial]
        for i in range(N):
            d_i = digits[i]
            w = i // wg
            idx_in_wg = i % wg
            
            # prefix_wg: inter-workgroup rank [S1, unofficial]
            prefix_wg = prefixes[w]
            
            # rank_local_i: intra-workgroup rank [S1, unofficial]
            # Count elements with digit d_i in the current workgroup before index i
            rank_local_i = sum(1 for j in range(idx_in_wg) if digits[w * wg + j] == d_i)
            
            rank_i = prefix_wg + rank_local_i
            pos = base_d + rank_i
            output[pos] = input_keys[i]
        
        input_keys = output
    return output

def blelloch_exclusive_scan(data):
    """Standard Blelloch exclusive scan on an array [G]."""
    n = len(data)
    if n == 0: return []
    if n == 1: return [0]
    
    # Upsweep (reduce)
    tree = [0] * (2 * n)
    tree[n:] = data[:]
    level = n
    while level > 1:
        for i in range(0, level, 2):
            tree[i // 2] = tree[i] + tree[i + 1]
        level //= 2
    
    # Set root to 0 for exclusive scan
    tree[0] = 0
    
    # Downsweep
    level = 1
    while level < n:
        for i in range(level * 2 - 1, -1, -2):
            if i + 1 < 2 * n:
                tree[i + 1] += tree[i]
        level *= 2
        
    return tree[n:]
```

**Edge Cases and Pitfalls:**
*   **Stability:** The algorithm guarantees that elements with identical digits are placed into the output array in the same relative order in which they appeared in the input [S1, unofficial].
*   **Dispatch Overhead:** Each hierarchical level executes as an independent compute dispatch consuming the previous level's buffers, with only intra-workgroup barriers inside a tile [S1, unofficial].
*   **Precision:** The algorithm relies on integer arithmetic for counts. Ensure that the total count $N$ fits within the data type used for offsets [G].

## Subtopics

### [8-bit Radix Sort](2599-8-bit-radix-sort.md)
The fundamental pass used in the wait-free radix sort. It sorts elements based on a single 8-bit digit of the key. It is chosen for its efficiency in parallel histogram computation and its compatibility with the hierarchical scan structure.

## Operating characteristics
*   **Time Complexity:** Linear work $O(N)$ per pass, with $P=4$ passes, resulting in $O(P \cdot N)$ total work [S1, unofficial].
*   **Memory Complexity:** $O(N/wg)$ auxiliary storage for the tile sums and prefixes [S1, unofficial].
*   **Performance:** Avoids spin waiting across heterogeneous GPU schedulers, making it robust across different hardware [S1, unofficial].
*   **Strengths:** Wait-free, stable, works on WebGPU and heterogeneous devices.
*   **Limitations:** Requires multiple compute dispatches for the hierarchical scan levels, which may introduce overhead.

## Background
Designed for WebGPU to enable efficient Gaussian Splatting in web browsers, this method addresses the limitations of CUDA-based approaches that assume fixed scheduling orders, which can degenerate into busy-waits on devices without such guarantees [S1, unofficial].
