# Wait-Free Radix Sort

Also called: Hierarchical Blelloch Scan Sort

## Overview
A parallel sorting algorithm designed for GPU execution that avoids inter-workgroup spin-waiting by using a hierarchical Blelloch scan to compute element positions, ensuring consistent behavior across heterogeneous GPU schedulers [S1, unofficial]. It sets itself apart from sibling methods like [Global Accumulator + Compaction](10410-global-accumulator-compaction.md) by eliminating cross-workgroup polling and busy-waits, which can degenerate into wasted cycles on devices without fixed scheduling guarantees [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An array of $N$ elements with 32-bit keys.
- Output: The same array sorted by key.
- Auxiliary storage: $O(N/w_g)$ for tile sums during the scan hierarchy, where $w_g$ is the workgroup size.

**Data Structures:**
- `histogram[w_g][256]`: Local histogram for each workgroup, counting frequencies of each 8-bit digit value.
- `tile_sums[256][N/w_g]`: Array storing the sum of counts for each digit value per workgroup tile.
- `prefix_wg[256][N/w_g]`: Inter-workgroup prefix sums for each digit value.
- `base_d[256]`: Global base offset for each digit value $d$.

**Parameters:**
- Radix size: 256 (8 bits).
- Number of passes: 4 (for 32-bit keys).
- Workgroup size ($w_g$): Not given in the sources.

**Steps:**
The algorithm performs a full 32-bit sort via four consecutive passes of an 8-bit radix sort, starting from the least significant bits. In the $k$-th pass ($k \in \{0, 1, 2, 3\}$), bits $k \times 8$ to $(k + 1) \times 8 - 1$ of the key are processed. Each pass consists of three steps:

1.  **Local Histogram:** Each workgroup counts the frequency of each digit value $d \in [0, 255]$ among its elements. This populates `histogram[wg_id][d]`.

2.  **Prefix Scan:** A hierarchical Blelloch scan computes `base_d` and `prefix_wg`.
    -   **Forward Pass (Upsweep):**
        -   Level $l_0$: Perform an exclusive scan inside each workgroup tile of size $w_g$ over the indicator stream for digit $d$. This produces tile sums, forming an array of length $N/w_g$.
        -   Level $l_1$: Run the same Blelloch scan on the tile sums array to obtain prefixes across tiles. Recurse until a single level remains.
        -   Read `base_d` from the last level as the sum of counts of digits smaller than $d$.
    -   **Backward Pass (Downsweep):**
        -   Add prefixes computed at level $l_1$ back to their corresponding $l_0$ tiles, and then to individual elements, yielding the inter-workgroup offset `prefix_wg`.
    -   Each level is executed as an independent compute dispatch consuming the previous level's buffers, with only intra-workgroup barriers inside a tile.

3.  **Scatter:** Write each element to its new position `pos` in the sorted array. The position is calculated as:
    $$pos = \text{base}_d + \text{rank}_i$$
    where $\text{rank}_i$ is decomposed into:
    $$\text{rank}_i = \text{prefix}_{wg} + \text{rank}_{\text{local}_i}$$
    Here, $\text{prefix}_{wg}$ is the inter-workgroup rank (total count of elements with digit $d$ in all workgroups processed before the current one), and $\text{rank}_{\text{local}_i}$ is the intra-workgroup rank (number of elements with digit $d$ within the current workgroup before index $i$).

**Pseudocode:**

```python
def wait_free_radix_sort(keys, values, N, wg_size):
    # keys and values are arrays of length N
    # wg_size is the workgroup size
    
    for k in range(4): # 4 passes for 32-bit keys
        shift = k * 8
        # Extract 8-bit digit for each element
        digits = [(keys[i] >> shift) & 0xFF for i in range(N)]
        
        # Step 1: Local Histogram
        # Each workgroup computes its local histogram
        # hist[wg_id][d] stores count of digit d in workgroup wg_id
        hist = compute_local_histogram(digits, N, wg_size)
        
        # Step 2: Prefix Scan (Hierarchical Blelloch)
        # Compute base_d and prefix_wg
        # base_d[d] is the global offset for digit d
        # prefix_wg[wg_id][d] is the inter-workgroup prefix for digit d in workgroup wg_id
        base_d, prefix_wg = hierarchical_blelloch_scan(hist, N, wg_size)
        
        # Step 3: Scatter
        # Compute final positions and scatter
        new_keys = [0] * N
        new_values = [0] * N
        
        for i in range(N):
            d = digits[i]
            wg_id = i // wg_size
            local_idx = i % wg_size
            
            # Calculate rank_i
            # rank_local_i: count of elements with digit d before i in the same workgroup
            rank_local_i = count_elements_before_in_workgroup(digits, i, wg_id, d)
            
            # prefix_wg[wg_id][d]: inter-workgroup rank
            prefix_wg_val = prefix_wg[wg_id][d]
            
            rank_i = prefix_wg_val + rank_local_i
            pos = base_d[d] + rank_i
            
            new_keys[pos] = keys[i]
            new_values[pos] = values[i]
            
        keys = new_keys
        values = new_values

def compute_local_histogram(digits, N, wg_size):
    # Initialize histogram
    num_wgs = (N + wg_size - 1) // wg_size
    hist = [[0] * 256 for _ in range(num_wgs)]
    
    for i in range(N):
        d = digits[i]
        wg_id = i // wg_size
        hist[wg_id][d] += 1
        
    return hist

def hierarchical_blelloch_scan(hist, N, wg_size):
    num_wgs = (N + wg_size - 1) // wg_size
    base_d = [0] * 256
    prefix_wg = [[0] * 256 for _ in range(num_wgs)]
    
    for d in range(256):
        # Extract counts for digit d from all workgroups
        counts = [hist[wg_id][d] for wg_id in range(num_wgs)]
        
        # Perform Blelloch scan on counts to get tile sums and prefixes
        # This is a simplified representation; actual implementation uses multiple dispatches
        tile_sums = blelloch_upsweep(counts)
        prefixes = blelloch_downsweep(tile_sums, counts)
        
        # base_d[d] is the total sum of counts for digit d
        base_d[d] = sum(counts)
        
        # prefix_wg[wg_id][d] is the prefix sum for workgroup wg_id
        for wg_id in range(num_wgs):
            prefix_wg[wg_id][d] = prefixes[wg_id]
            
    return base_d, prefix_wg

def blelloch_upsweep(counts):
    # Simplified upsweep: sum adjacent pairs
    # In reality, this is done hierarchically across levels
    # For simplicity, we assume a single level upsweep for demonstration
    # Actual implementation recurses until single level remains
    tile_sums = [0] * len(counts)
    for i in range(0, len(counts), 2):
        if i + 1 < len(counts):
            tile_sums[i // 2] = counts[i] + counts[i + 1]
        else:
            tile_sums[i // 2] = counts[i]
    return tile_sums

def blelloch_downsweep(tile_sums, counts):
    # Simplified downsweep: add prefixes back
    # In reality, this is done hierarchically
    prefixes = [0] * len(counts)
    for i in range(len(counts)):
        if i % 2 == 0:
            prefixes[i] = 0
            if i + 1 < len(counts):
                prefixes[i + 1] = tile_sums[i // 2]
        else:
            prefixes[i] = tile_sums[i // 2]
    return prefixes

def count_elements_before_in_workgroup(digits, i, wg_id, d):
    # Count elements with digit d before index i in the same workgroup
    count = 0
    start = wg_id * wg_size
    end = min((wg_id + 1) * wg_size, len(digits))
    for j in range(start, i):
        if digits[j] == d:
            count += 1
    return count
```

### [In-block shuffle and coalesced mapping](15056-in-block-shuffle-and-coalesced-mapping.md)
This method modifies the shuffle steps of radix sorting to achieve coalesced memory access, addressing the performance penalty of random-like scattering patterns in global memory writes. It sets itself apart from standard element-wise mapping by performing local shuffling in shared memory to cluster same-radix elements, followed by a coalesced cluster-wise mapping to global memory, ensuring that the $i$-th thread outputs data to the $i$-th position in a 128-byte aligned region.

## Operating characteristics
- Time Complexity: Linear work $O(N)$ per pass, with 4 passes for 32-bit keys.
- Memory Complexity: $O(N/w_g)$ auxiliary storage for tile sums.
- Measured Performance: Not given in the sources.
- Scaling: Not given in the sources.
- Strengths: Avoids spin waiting across heterogeneous GPU schedulers, ensuring consistent behavior [S1, unofficial].
- Limitations: Requires multiple compute dispatches for each level of the Blelloch scan, which may introduce overhead [S1, unofficial].
- When to Use: When consistent performance across heterogeneous GPU schedulers is required, and inter-workgroup spin-waiting is undesirable [S1, unofficial].
- When Not to Use: When hardware-specific optimizations (e.g., CUDA-based methods) can provide better performance on specific architectures [S1, unofficial].

## Background
Origin: The method was introduced in "WebSplatter: Enabling Cross-Device Efficient Gaussian Splatting in Web Browsers via WebGPU" [S1, unofficial]. It was designed to address the limitations of existing parallel sorting algorithms on WebGPU, which often rely on inter-workgroup spin-waiting that can degenerate into busy-waits on devices without fixed scheduling guarantees [S1, unofficial].
