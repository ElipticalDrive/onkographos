# Binning State Allocation and Sorting

Also called: Radix Sort on Point List Keys

## Overview
This method allocates and initializes the `BinningState` structure required for parallel processing and performs a radix sort on point list keys to reorder associated data. It is a specialized orchestration step within GPU-based volume rendering pipelines that relies on [Radix Sort (GPU)](10404-radix-sort-gpu.md) to manage point cloud data ordering. Unlike general-purpose sorting, this method is tightly coupled with the memory layout of binning states, ensuring that keys and their corresponding indices are sorted in tandem for efficient subsequent rendering passes.

## How it works
The method operates on a `BinningState` structure that manages device memory for point list sorting. It utilizes a radix sort algorithm to sort pairs of keys and indices.

**Inputs:**
- `P`: The total number of points to be sorted.
- `binning`: An object or context containing the `BinningState` and sorting parameters.
- `binning.point_list_keys_unsorted`: Array of unsorted keys (uint32_t).
- `binning.point_list_unsorted`: Array of unsorted indices/values (uint32_t).
- `binning.sorting_size`: The size of the temporary sorting space required.

**Outputs:**
- `binning.point_list_keys`: Sorted keys.
- `binning.point_list`: Sorted indices/values corresponding to the sorted keys.

**Data Structures:**
The `BinningState` is a struct containing pointers to device memory. The fields are allocated via an `obtain` mechanism [S2, unofficial]. The layout is as follows:
- `point_list`: `uint32_t*`, size `P` [S2, unofficial].
- `point_list_unsorted`: `uint32_t*`, size `P` [S2, unofficial].
- `point_list_keys`: `uint32_t*`, size `P` [S2, unofficial].
- `point_list_keys_unsorted`: `uint32_t*`, size `P` [S2, unofficial].
- `list_sorting_space`: `char*`, dynamic size determined by `sorting_size` [S2, unofficial].

**Steps:**
1. Allocate the `BinningState` structure and its associated device memory buffers using the `obtain` function [S1, S2, unofficial].
2. Initialize `point_list_keys_unsorted` and `point_list_unsorted` with the raw point data [S1, unofficial].
3. Perform radix sort on the pairs of keys and indices. The sort operation uses a temporary sorting space (`binning.sorting_size`) and the total number of points (`P`) [S1, unofficial].
4. The sort function reorders `point_list_keys` and `point_list` such that `point_list_keys` is in ascending order, and `point_list` is permuted accordingly [S1, unofficial].

**Pseudocode:**
```python
def binning_state_allocation_and_sorting(P, binning):
    # Step 1: Allocate BinningState and buffers
    # The obtain function allocates device memory for the struct fields
    binning.point_list = obtain_device_memory(P, dtype=uint32_t)
    binning.point_list_unsorted = obtain_device_memory(P, dtype=uint32_t)
    binning.point_list_keys = obtain_device_memory(P, dtype=uint32_t)
    binning.point_list_keys_unsorted = obtain_device_memory(P, dtype=uint32_t)
    
    # Determine sorting space size dynamically
    sorting_size = compute_sorting_space_size(P)
    binning.list_sorting_space = obtain_device_memory(sorting_size, dtype=char)
    binning.sorting_size = sorting_size

    # Step 2: Initialize unsorted arrays
    # Assume raw_keys and raw_indices are provided or pre-populated
    # copy_to_device(binning.point_list_keys_unsorted, raw_keys)
    # copy_to_device(binning.point_list_unsorted, raw_indices)
    
    # Step 3: Perform Radix Sort on pairs
    # This call sorts point_list_keys and permutes point_list accordingly
    # using the temporary sorting space
    cub_device_radix_sort_sort_pairs(
        dest_tmp=binning.list_sorting_space,
        dest_tmp_size=binning.sorting_size,
        keys_in=binning.point_list_keys_unsorted,
        keys_out=binning.point_list_keys,
        values_in=binning.point_list_unsorted,
        values_out=binning.point_list,
        num_items=P
    )
```

**Parameters:**
- `P`: Number of points. Typical values depend on the scene resolution and point cloud density.
- `sorting_size`: Size of temporary memory for radix sort. Depends on `P` and the radix sort implementation [S2, unofficial].

**Edge Cases and Pitfalls:**
- Memory allocation failure if `P` is excessively large for the available GPU memory [S2, unofficial].
- Precision issues are minimal as keys are `uint32_t`, but incorrect key initialization leads to wrong ordering [S1, unofficial].
- The `list_sorting_space` must be large enough for the radix sort implementation; under-allocation causes undefined behavior [S2, unofficial].

## Subtopics

### BinningState Buffer Layout
This variant focuses specifically on the memory layout of the `BinningState` struct. It defines the five fields (`point_list`, `point_list_unsorted`, `point_list_keys`, `point_list_keys_unsorted`, `list_sorting_space`) and their types (`uint32_t*` or `char*`) and sizes (`P` or dynamic) [S2, unofficial]. It is chosen when memory management and alignment are critical for performance. It differs from the general allocation method by emphasizing the static structure definition over the dynamic sorting execution.

## Operating characteristics
- **Time Complexity:** Dominated by the radix sort step, which is $O(P \cdot \log_2(\max\_key))$ or $O(P)$ depending on the radix width and implementation [S1, unofficial].
- **Memory Complexity:** $O(P)$ for the four point list arrays plus $O(sorting\_size)$ for the temporary sort space [S2, unofficial].
- **Performance:** Efficient on GPU due to parallel radix sort implementation. Performance scales with `P` and the efficiency of the underlying `cub::DeviceRadixSort` [S1, unofficial].
- **Strengths:** Provides a structured way to manage point list sorting in binning contexts.
- **Limitations:** Requires significant temporary memory for sorting. Not suitable for CPU-only implementations without porting the radix sort logic.

## Background
This method is part of the Gaussian Splatting rendering pipeline, specifically used in implementations like r2_gaussian and PFGS. It was developed to efficiently manage point cloud data for volume rendering on GPUs. The use of `cub::DeviceRadixSort` indicates reliance on NVIDIA's CUDA Utilities for high-performance sorting [S1, S2, unofficial].
