# Radix Sort (GPU)
Also called: RadixSortCountCS, RadixSortDigitPrefixSumCS, RadixSortPrefixSumCS, RadixSortScatterCS

## Overview
A GPU-based integer sorting algorithm implemented via four compute shader passes: histogram counting, prefix sum, digit prefix sum, and scatter [S1, unofficial]. It uses a parallel prefix sum (scan) implementation as a subroutine to compute output positions for each radix digit [S2].

## How it works
### Inputs and Outputs
The method operates on the following buffers and parameters, all defined in the source shader signatures [S1, unofficial]:
*   **Input Keys**: `SrcKeys` (`SRV StructuredBuffer<uint>`)
*   **Input Values**: `SrcVals` (`UAV RWStructuredBuffer<uint>`)
*   **Output Keys**: `DstKeys` (`UAV RWStructuredBuffer<uint>`)
*   **Output Values**: `DstVals` (`UAV RWStructuredBuffer<uint>`)
*   **Histogram**: `HistogramBuffer` (`UAV RWStructuredBuffer<uint>`)
*   **Digit Offsets**: `DigitOffsetBuffer` (`UAV RWStructuredBuffer<uint>`)
*   **Sort Parameters**: `SortParams` (`SRV StructuredBuffer<uint>`) containing `RadixShift`, `Count`, `NumTiles`, `UseIndirectSort` [S1, unofficial].

### Data Structures
The parameters are passed via the `SortParams` structured buffer or directly as shader constants [S1, unofficial]. The `RadixShift` parameter specifies the bit shift amount for the current radix digit being processed [S1, unofficial]. `Count` specifies the total number of elements to sort [S1, unofficial]. `NumTiles` specifies the number of tiles used for parallel histogramming [S1, unofficial]. `UseIndirectSort` is a flag indicating whether indirect dispatch is used [S1, unofficial].

### Steps
1.  **Histogram Counting (`RadixSortCountCS`)**
    *   **Input**: `SrcKeys`, `SortParams`.
    *   **Output**: `HistogramBuffer`.
    *   **Logic**: Each thread block processes a tile of elements. For each element, extract the current 8-bit radix digit using `(key >> RadixShift) & 0xFF` [G]. Increment the corresponding bin in the global histogram buffer using an atomic operation [G].
    *   **Parameters**: `RadixShift`, `Count`, `NumTiles`, `UseIndirectSort` [S1, unofficial].

2.  **Prefix Sum (`RadixSortPrefixSumCS`)**
    *   **Input**: `HistogramBuffer`, `SortParams`.
    *   **Output**: `DigitOffsetBuffer`.
    *   **Logic**: Perform a parallel prefix sum (scan) on the `HistogramBuffer` to compute the starting offsets for each digit bin [G]. The result is stored in `DigitOffsetBuffer` [S1, unofficial].
    *   **Parameters**: `NumTiles`, `UseIndirectSort` [S1, unofficial].

3.  **Digit Prefix Sum (`RadixSortDigitPrefixSumCS`)**
    *   **Input**: `DigitOffsetBuffer`.
    *   **Output**: `DigitOffsetBuffer` (updated).
    *   **Logic**: This pass refines or finalizes the offsets for the scatter phase. The exact transformation logic is not detailed in the sources [S1, unofficial].
    *   **Parameters**: None explicitly listed beyond the buffer itself [S1, unofficial].

4.  **Scatter (`RadixSortScatterCS`)**
    *   **Input**: `SrcKeys`, `SrcVals`, `HistogramBuffer`, `DigitOffsetBuffer`, `SortParams`.
    *   **Output**: `DstKeys`, `DstVals`.
    *   **Logic**: For each element, extract the current radix digit. Use the `DigitOffsetBuffer` to find the starting position for that digit. Scatter the key and value to the correct location in `DstKeys` and `DstVals`. Increment the offset for the next element with the same digit using an atomic add or pre-computed position [G].
    *   **Parameters**: `RadixShift`, `Count`, `NumTiles`, `UseIndirectSort` [S1, unofficial].

def scan(arr):
    # Standard inclusive prefix sum [G]
    result = [0] * len(arr)
    result[0] = arr[0]
    for i in range(1, len(arr)):
        result[i] = result[i-1] + arr[i]
    return result

def atomic_add(buffer, index, value):
    # Simulates GPU atomic add [G]
    old = buffer[index]
    buffer[index] += value
    return old

def RadixSortCountCS(SrcKeys, SortParams, HistogramBuffer):
    RadixShift = SortParams['RadixShift']
    Count = SortParams['Count']
    
    # Initialize histogram to zero
    for i in range(256):
        HistogramBuffer[i] = 0
        
    # Process elements
    for idx in range(Count):
        key = SrcKeys[idx]
        # Extract 8-bit digit
        digit = (key >> RadixShift) & 0xFF
        # Atomic increment
        atomic_add(HistogramBuffer, digit, 1)

### Edge Cases and Pitfalls
*   **DX11 UAV Limit**: DX11 has a strict limit on the number of simultaneous UAVs, which may prevent running the full pipeline if not optimized [S1, unofficial].
*   **Indirect Dispatch**: The `UseIndirectSort` flag indicates that indirect dispatch may be required for certain configurations [S1, unofficial].
*   **Precision**: Using `uint32` for keys and values ensures no precision loss for standard integer types [S1, unofficial].
*   **Boundaries**: The algorithm assumes `Count` is accurate and `SrcKeys`/`SrcVals` are valid [S1, unofficial].
