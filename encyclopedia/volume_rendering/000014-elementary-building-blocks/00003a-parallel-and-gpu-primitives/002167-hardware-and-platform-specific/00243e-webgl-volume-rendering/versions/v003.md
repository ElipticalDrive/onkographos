# WebGL Volume Rendering

Also called: Direct Volume Rendering in WebGL, Ray Casting in Fragment Shader

## Overview
WebGL Volume Rendering implements direct volume rendering (DVR) via ray casting executed in the fragment shader of a WebGL context [S1, unofficial]. It solves the problem of interactive 3D visualization of scalar volumes in web browsers without requiring native plugins or server-side rendering [S1, unofficial]. It is distinguished from [GPU Raycasting](6192-gpu-raycasting.md) by its specific integration with the Three.js library and its support for H5J file formats, and from [CUDA Volume Ray Casting](2048-cuda-volume-ray-casting.md) by its execution on the client-side GPU via WebGL rather than a CUDA-capable device [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input Volume Data**: A `Uint8Array` containing 8-bit scalar values for each voxel [S1, unofficial].
*   **Volume Metadata**: `volumeSize` (array `[x, y, z]` in voxels) and `voxelSize` (array `[x, y, z]` in consistent units, e.g., microns) [S1, unofficial].
*   **Transfer Function**: A Three.js `DataTexture` with width 256, height 1, and format `THREE.RGBAFormat` [S1, unofficial]. The data is a `Uint8Array` of size $256 \times 4$, mapping each 8-bit input value to an RGBA color [S1, unofficial].
*   **Camera Parameters**: Position, target, up vector, field of view, and interaction speeds [S1, unofficial].
*   **Rendering Parameters**: Opacity scaling, step size, gamma correction, lighting, and surface mesh visibility [S1, unofficial].
*   **Output**: A rendered 2D image displayed in the WebGL canvas [S1, unofficial].

**Data Structures**
*   **Volume Texture**: The `Uint8Array` is uploaded to a WebGL texture (typically `GL_R8` or similar 8-bit format) for sampling in the shader [S1, unofficial].
*   **Transfer Function Texture**: As defined above, a 1D texture mapping intensity to color/opacity [S1, unofficial].

**Parameters**
*   `alphaScale` (default: 1): Scales opacity $\alpha$ at each sample. Lower values decrease opacity [S1, unofficial].
*   `dtScale` (default: 1): Scales the step size $dt$. Higher values increase step size, reducing sample count and increasing performance at the cost of quality [S1, unofficial].
*   `finalGamma` (default: 4.5): Applied to accumulated color $c$ (normalized [0,1]) after transfer function application. Formula: $c^{(1.0 / \text{finalGamma})}$ [S1, unofficial]. Increases visibility of faint details [S1, unofficial].
*   `useLighting` (default: true): Enables lighting using volume gradients as surface normals. If false, rendering resembles maximum intensity projection (MIP) [S1, unofficial].
*   `useVolumeMirrorX` (default: false): Mirrors volume data along the x-axis [S1, unofficial].
*   `interactionSpeedup` (default: 1): Reduces rendering resolution during interactive camera manipulation to increase interactivity [S1, unofficial].
*   `cameraPosition` (default: `[0, 0, -2]`): Initial camera position relative to the volume box (centered at origin, longest dimension -0.5 to 0.5) [S1, unofficial].
*   `cameraTarget` (default: `[0, 0, 0]`): Initial point the camera looks at [S1, unofficial].
*   `cameraUp` (default: `[0, -1, 0]`): Initial 'up' direction [S1, unofficial].
*   `cameraFovDegrees` (default: 45.0): Vertical field of view in degrees [S1, unofficial].
*   `orbitZoomSpeed` (default: 0.15): Speed of camera zoom on mouse-wheel event [S1, unofficial].
*   `useSurface` (default: false): Controls visibility of an optional surface mesh [S1, unofficial].
*   `surfaceColor` (default: `'#00ff00'`): Color of the opaque surface mesh. No alpha allowed [S1, unofficial].
*   `heightCorrection` (default: true): Applies correction when resizing DOM item height to be smaller than current height [S1, unofficial].

**Algorithm Steps**
1.  **Initialization**: Load volume data into a WebGL texture and transfer function into a `DataTexture` [S1, unofficial]. Initialize camera parameters [S1, unofficial].
2.  **Ray Generation**: For each pixel in the viewport, compute the ray origin and direction based on the current camera matrix and viewport dimensions [S1, unofficial].
3.  **Ray Casting Loop**:
    a. Determine the entry and exit points of the ray into the volume bounding box [S1, unofficial].
    b. Iterate along the ray with step size $dt = \text{voxel\_size} \times \text{dtScale}$ [S1, unofficial].
    c. Sample the volume texture at the current ray position to get scalar value $v$ [S1, unofficial].
    d. Map $v$ to color $C$ and opacity $\alpha$ using the transfer function texture [S1, unofficial].
    e. Apply `alphaScale` to $\alpha$ [S1, unofficial].
    f. Composite the sample color and opacity into the accumulated color $C_{acc}$ and opacity $A_{acc}$ using front-to-back or back-to-front blending [S1, unofficial].
    g. If $A_{acc} \ge 1.0$ or the ray exits the volume, terminate [S1, unofficial].
4.  **Lighting (if `useLighting` is true)**: Compute the gradient at the current sample position to estimate surface normal. Use this normal for lighting calculations (e.g., Phong shading) to modify the sample color [S1, unofficial].
5.  **Gamma Correction**: Apply final gamma correction to the accumulated color components $c$: $c_{final} = c_{acc}^{(1.0 / \text{finalGamma})}$ [S1, unofficial].
6.  **Surface Mesh Rendering**: If `useSurface` is true, render the provided `surfaceMesh` (e.g., an isosurface) with `surfaceColor` [S1, unofficial].
7.  **Output**: Write the final color to the framebuffer [S1, unofficial].

**Pseudocode**
```python
# Pseudocode for the fragment shader logic
# Inputs: ray_origin, ray_direction, volume_texture, tf_texture, params
# Outputs: out_color

def render_fragment(ray_origin, ray_direction, params):
    # 1. Intersect ray with volume bounding box
    # Assume volume is axis-aligned and centered at origin with size defined by params.volume_size
    # Compute t_min and t_max for entry and exit
    t_min, t_max = intersect_box(ray_origin, ray_direction, params.volume_size)
    
    if t_max < 0 or t_min > t_max:
        return vec4(0.0, 0.0, 0.0, 0.0)

    # 2. Initialize accumulation
    acc_color = vec4(0.0, 0.0, 0.0, 0.0)
    acc_alpha = 0.0
    
    # 3. Ray marching
    step_size = params.voxel_size * params.dtScale
    # Determine number of steps or iterate until exit
    t = t_min
    while t < t_max and acc_alpha < 1.0:
        # Sample position in volume space
        pos = ray_origin + ray_direction * t
        
        # Handle mirroring if enabled
        if params.useVolumeMirrorX:
            pos.x = -pos.x
            
        # Sample volume data
        v = sample_volume(pos, params.volume_texture)
        
        # Map to color and opacity via transfer function
        tf_color, tf_alpha = sample_transfer_function(v, params.tf_texture)
        
        # Apply alpha scale
        alpha = tf_alpha * params.alphaScale
        
        # Front-to-back compositing
        # C_out = C_in + (1 - A_in) * C_sample * alpha_sample
        # A_out = A_in + (1 - A_in) * alpha_sample
        weight = (1.0 - acc_alpha) * alpha
        acc_color += weight * tf_color
        acc_alpha += weight
        
        # Advance ray
        t += length(step_size) # Or use dot product for step along ray direction
        
    # 4. Lighting (if enabled)
    if params.useLighting:
        # Compute gradient at current position for normal estimation
        normal = compute_gradient_normal(pos, params.volume_texture)
        # Apply lighting model (e.g., Phong) to acc_color
        acc_color = apply_lighting(acc_color, normal, ray_direction)
        
    # 5. Final Gamma Correction
    # Apply gamma to each color component
    final_color = vec4(
        pow(acc_color.r, 1.0 / params.finalGamma),
        pow(acc_color.g, 1.0 / params.finalGamma),
        pow(acc_color.b, 1.0 / params.finalGamma),
        acc_color.a
    )
    
    return final_color
```

**Edge Cases and Pitfalls**
*   **SharedArrayBuffer Error**: Opening H5J files may produce a "SharedArrayBuffer is not defined" error if the server is not configured for cross-origin isolation [S1, unofficial].
*   **Precision**: Using 8-bit volume data limits dynamic range; transfer functions must be tuned accordingly [S1, unofficial].
*   **Boundary Conditions**: Ray-box intersection must be handled correctly to avoid sampling outside the volume [S1, unofficial].

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of samples per pixel, which depends on volume depth and `dtScale` [S1, unofficial].
*   **Memory Complexity**: Linear with respect to volume size for storing the volume texture and transfer function [S1, unofficial].
*   **Performance**: `dtScale` and `interactionSpeedup` allow trade-offs between quality and frame rate [S1, unofficial].
*   **Strengths**: Runs in standard web browsers; integrates with Three.js ecosystem; supports interactive camera controls [S1, unofficial].
*   **Limitations**: Limited by WebGL capabilities (e.g., texture size limits, precision); requires cross-origin isolation for certain file formats like H5J [S1, unofficial].
