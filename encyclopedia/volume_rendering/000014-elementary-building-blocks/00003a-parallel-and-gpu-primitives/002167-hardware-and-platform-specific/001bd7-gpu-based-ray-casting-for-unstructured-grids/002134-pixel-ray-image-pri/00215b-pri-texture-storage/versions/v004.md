# PRI Texture Storage

Also called: PRI data layout, PRI index and knots textures

## Overview
PRI Texture Storage is the GPU-friendly data layout for the Pixel Ray Image (PRI), a semi-regular structure for unstructured grid volume rendering [S1, S2, unofficial]. It solves the difficulty of mapping irregular unstructured grid data efficiently to GPU hardware by replacing the grid with a pixelized projection plane and 1D scalar functions (linear splines) defined on sampling rays [S1, S2, unofficial]. It sets itself apart from sibling methods like [PRI Approximation Error Measurement](2893-pri-approximation-error-measurement.md) by focusing on the compact, texture-based representation of these splines rather than their geometric fidelity [S2, unofficial].

## How it works
The PRI is represented as two 2D textures: an **Index Texture** and a **Knots Texture** [S1, S2, unofficial]. The Index Texture has the same resolution as the PRI pixel plane (sampling plane) [S1, S2, unofficial]. The Knots Texture stores the actual spline data [S1, S2, unofficial].

### Data Structures

**Index Texture**
A 2D texture with the same resolution as the PRI pixel plane [S1, S2, unofficial]. Each texel holds four channels `(r, g, b, a)` mapping to:
*   `r, g`: The 2D address (coordinates) of the first spline knot in the Knots Texture [S1, S2, unofficial].
*   `b`: The number of knots in the spline for this pixel [S1, S2, unofficial].
*   `a`: The normalized distance of the last knot from the sampling plane [S1, S2, unofficial].

If channel `b` is zero, the sampling ray does not intersect the grid [S1, S2, unofficial].

**Knots Texture**
A 2D texture containing the packed per-pixel splines [S1, S2, unofficial]. To ensure high precision, it is stored as two separate float-format textures:
1.  One texture holds the **scalar values** of the knots [S1, S2, unofficial].
2.  One texture holds the **distance values** (depth) of the knots [S1, S2, unofficial].

The splines are laid out in a pre-determined traversal order of the pixels (e.g., row-order or column-order) [S1, S2, unofficial].

### Algorithm: Building the Layout

1.  **Traverse Pixels**: Iterate through the PRI pixel plane in a pre-determined order (e.g., row-major) [S1, S2, unofficial].
2.  **Collect Splines**: For each pixel, determine the linear spline defined by the intersection of the sampling ray with the unstructured grid [G].
3.  **Pack Knots**: Append the knot data (scalar value and distance) for the current pixel's spline to the end of the Knots Texture arrays [S1, S2, unofficial].
4.  **Write Index**: For the current pixel, write the Index Texture texel: set `r, g` to the current write pointer (2D address) in the Knots Texture, set `b` to the count of knots in the current spline, and set `a` to the normalized distance of the last knot [S1, S2, unofficial].
5.  **Advance Pointer**: Increment the Knots Texture write pointer by the number of knots added [G].

### Edge Cases and Pitfalls

*   **Non-intersecting Rays**: If a sampling ray does not intersect the grid, the spline has zero knots. The Index Texture texel must have `b = 0` [S1, S2, unofficial].
*   **Out-of-Bounds Slicing**: A slicing plane (or fragment) can be quickly identified as lying outside the unstructured grid using two checks [S1, S2, unofficial]:
    1.  Its z-location overlaps a spline with zero knots (ray does not enter the volume grid).
    2.  Its distance to the sampling plane is less than the distance to the first knot or greater than the distance to the last knot of the spline.
*   **Precision**: Using separate float textures for scalar and distance values is critical for maintaining high precision in the knot data [S1, S2, unofficial].

### Pseudocode: Compact Node Index Texture Generation
*Note: This variant is used when transferring data back to the CPU, where pixel position must be recovered [S3, unofficial].*

```python
def generate_compact_node_index_texture(ray_data, width, height):
    """
    Generates a compact RGBA32 texture for CPU read-back.
    ray_data: List of lists of rays, each containing up to 12 node entries.
    Returns: 2D texture (RGBA32) where each pixel stores 4 node indices.
    """
    # Initialize output texture with zeros
    output_texture = [[0, 0, 0, 0] for _ in range(height)]
    
    for pixel_y in range(height):
        for pixel_x in range(width):
            ray = ray_data[pixel_y][pixel_x]
            
            # Extract nodes and bitmask
            nodes = ray.nodes[:4]
            bitmask = ray.bitmask
            
            # Count non-zero entries in bitmask
            non_zero_count = bin(bitmask).count('1')
            
            # Check if bitmask exceeds limit (more than 4 nodes active)
            if non_zero_count > 4:
                # Postpone request to next frame [S3, unofficial]
                continue
            
            # Encode pixel position into the remaining bits of the node entries
            # Each 32-bit entry uses 20 bits for pixel position and 12 bits for node index [S3, unofficial]
            pixel_pos = pixel_y * width + pixel_x
            encoded_nodes = []
            for node in nodes:
                # Pack: [PixelPos (20 bits) | NodeIndex (12 bits)]
                packed = (pixel_pos << 12) | node
                encoded_nodes.append(packed)
            
            # Fill RGBA channels based on bitmask
            output_texture[pixel_y][pixel_x][0] = encoded_nodes[0] if bitmask & 1 else 0
            output_texture[pixel_y][pixel_x][1] = encoded_nodes[1] if bitmask & 2 else 0
            output_texture[pixel_y][pixel_x][2] = encoded_nodes[2] if bitmask & 4 else 0
            output_texture[pixel_y][pixel_x][3] = encoded_nodes[3] if bitmask & 8 else 0
            
    return output_texture
```

## Subtopics

### Compact Node Index Texture Generation
A variant of the storage layout used during GPU-to-CPU data transfer. It addresses the loss of original pixel position during texture reduction. It encodes the pixel position (using 20 bits of a 32-bit entry) alongside node indices (12 bits). The final texture is a single RGBA32 texture storing indices of four nodes per pixel. The bitmask usually contains 2-3 non-zero entries. If the limit of 4 nodes is exceeded, requests are postponed to the next frame [S3, unofficial].

## Operating characteristics
*   **Memory**: Requires two 2D textures (Index and Knots). The Index Texture size is fixed by the PRI resolution. The Knots Texture size depends on the number of intersections (knots) per ray [S1, S2, unofficial].
*   **Performance**: Allows for efficient texture lookups on the GPU [S1, S2, unofficial].
*   **Precision**: High precision is maintained by using separate float textures for scalar and distance values [S1, S2, unofficial].
*   **Limitations**: The layout is static once generated. Dynamic updates require rebuilding the textures. The compact node index variant has a hard limit of 4 nodes per pixel; exceeding this causes frame postponement [S3, unofficial].

## Background
The PRI Texture Storage method was introduced in the context of GPU-based unstructured grid volume rendering. It was presented in the paper "An Image-Based Modelling Approach To GPU-based Unstructured Grid Volume Rendering" [S1, S2, unofficial]. The compact node index variant was later described in "Ray-Guided Streaming for Efficient and Detailed Voxel Rendering" [S3, unofficial].
