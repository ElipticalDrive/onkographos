# CUDA Raymarching Pipeline

Also called: Full GPU-Based FVR Pipeline, GPU-based pre-processing (CUDA)

## Overview
The CUDA Raymarching Pipeline is a rendering architecture where the majority of processing, including computational kernels and rendering contexts, resides on the GPU device [S2]. This design eliminates data transfer and API call bottlenecks between the host CPU and the device GPU, which are common in traditional raster engines where the host controls data assembly via draw calls [S2]. It builds on [GPU-Driven Architecture](6408-gpu-driven-architecture.md) by fully implementing the residency octree and renderer on the GPU, while the CPU handles only high-level orchestration such as loading data and switching contexts [S3, unofficial]. It addresses the performance drop on discrete GPUs caused by CPU-to-GPU memory transfers and excessive draw calls by executing pre-processing tasks like partitioning and packing concurrently on the GPU [S1]. It differs from [Custom GPU Architecture for Sphere Tracing](7147-custom-gpu-architecture-for-sphere-tracing.md) by integrating Fourier-based volume rendering steps directly into the GPU pipeline.

## How it works
**Inputs and Outputs:**
- **Input:** Volume dataset (loaded on CPU), light and object data (stored in vectors on host CPU) [S2].
- **Output:** Final reconstructed image displayed on screen [S3, unofficial].

**Data Structures:**
- **Host Memory:** Vectors for light and object data; volume dataset before upload [S2].
- **Device Global Memory:** Volume dataset, spectral volume (complex array), intermediate images [S3, unofficial].
- **Device Texture Memory:** 3D texture for spectral volume, 2D texture for projection-slice and final image [S3, unofficial].
- **Pixel Buffer Object (PBO):** Shared buffer between CUDA and OpenGL contexts to avoid CPU round-trips [S3, unofficial].
- **Frame Buffer Object (FBO):** Attached to a 2D texture for off-screen rendering [S3, unofficial].

**Numbered Steps:**
1. **Host Initialization:** Store light and object data in vectors on the host CPU [S2]. Load the volume dataset on the CPU [S3, unofficial].
2. **Data Upload:** Copy light and object data from host memory to device memory once per frame [S2]. Copy the volume directly to GPU global memory using `cudaMemcpy` [S3, unofficial]. Upload textures into VRAM [S2].
3. **Context Setup:** Create and activate a CUDA context on the GPU [S3, unofficial]. Expose uploaded textures using a texture object descriptor [S2].
4. **Spatial Centering:** Execute the `FFT_SHIFT_3D_REAL` kernel to center the 3D spatial volume [S3, unofficial].
5. **3D FFT:** Invoke `CUDA_FFT_3D` to obtain the 3D frequency spectrum of the input spatial volume [S3, unofficial].
6. **Spectral Centering:** Invoke `FFT_SHIFT_3D_COMPLEX` to center the spectral volume at the origin of k-space [S3, unofficial].
7. **Format Conversion:** Convert the complex array to a format compatible with an OpenGL 3D texture (two components) using the `REPACK_ARRAY` kernel [S3, unofficial].
8. **Interoperability Setup:** Solve the interoperability issue between CUDA and OpenGL by using an OpenGL Pixel Buffer Object (PBO) registered in the CUDA memory space to share the spectral array [S3, unofficial]. This avoids copying data back to the CPU and re-uploading, which is inefficient [S3, unofficial].
9. **Projection-Slice Extraction:** Map the shared spectral array to the OpenGL off-screen rendering context for projection-slice extraction [S3, unofficial]. Extract the projection-slice via intersection with a proxy quadrant (same as hybrid method) [S3, unofficial].
10. **2D Texture Packing:** Pack the projection-slice into a 2D texture attached to an FBO [S3, unofficial].
11. **CUDA Mapping:** Map the 2D texture to a CUDA array for processing [S3, unofficial].
12. **Resampling:** Execute the `RESAMPLE_SLICE` kernel on the GPU to resample the slice [S3, unofficial].
13. **Inverse 2D FFT:** Execute the `CUDA_FFT_2D` kernel to perform the inverse 2D FFT [S3, unofficial].
14. **Image Shifting:** Execute the `FFT_SHIFT_2D_REAL` kernel to shift the resulting image [S3, unofficial].
15. **Final Display:** Pack the final image into a 2D OpenGL texture and upload to GPU memory [S3, unofficial]. Activate the on-screen rendering context and display the texture [S3, unofficial].

    execute_kernel(fft_shift_3d_real, d_volume, d_volume_centered)

    # 5. 3D FFT

    # 6. Spectral Centering
    # Invoke FFT_SHIFT_3D_COMPLEX to center the spectral volume at the origin of k-space [S3, unofficial]
    d_spectrum_centered = allocate_device_memory_like(d_spectrum)
    execute_kernel(fft_shift_3d_complex, d_spectrum, d_spectrum_centered)

    # 7. Format Conversion
    # Convert the complex array to a format compatible with an OpenGL 3D texture (two components) using the REPACK_ARRAY kernel [S3, unofficial]
    d_spectrum_repacked = execute_kernel(repack_array, d_spectrum_centered)

    # 8. Interoperability Setup
    # Solve the interoperability issue by using an OpenGL Pixel Buffer Object (PBO) registered in the CUDA memory space to share the spectral array [S3, unofficial]
    pbo = create_pbo_registered_with_cuda()
    copy_device_to_device(pbo, d_spectrum_repacked)

    # 9. Projection-Slice Extraction
    # Map the shared spectral array to the OpenGL off-screen rendering context for projection-slice extraction [S3, unofficial]
    gl_offscreen_context = create_offscreen_context()
    activate_gl_context(gl_offscreen_context)

    # Map PBO to OpenGL texture
    gl_texture_3d = create_3d_texture_from_pbo(pbo)

    # Extract the projection-slice via intersection with a proxy quadrant (same as hybrid method) [S3, unofficial]
    bind_fbo(fbo)
    bind_texture(gl_texture_3d)
    draw_proxy_quadrant()
    unbind_fbo()

    # 10. 2D Texture Packing
    # Projection-slice is now in FBO's attached 2D texture
    d_2d_texture_ref = get_texture_reference(fbo)

    # 11. CUDA Mapping
    # Map the 2D texture to a CUDA array for processing [S3, unofficial]
    cuda_array_2d = map_gl_texture_to_cuda_array(d_2d_texture_ref)

    # 12. Resampling
    # Execute the RESAMPLE_SLICE kernel on the GPU to resample the slice [S3, unofficial]
    d_resampled_slice = execute_kernel(resample_slice, cuda_array_2d)

    # 13. Inverse 2D FFT
    # Execute the CUDA_FFT_2D kernel to perform the inverse 2D FFT [S3, unofficial]
    d_image_freq = execute_fft_2d(d_resampled_slice, inverse=True)

    # 14. Image Shifting
    # Execute the FFT_SHIFT_2D_REAL kernel to shift the resulting image [S3, unofficial]
    d_image_shifted = allocate_device_memory_like(d_image_freq)
    execute_kernel(fft_shift_2d_real, d_image_freq, d_image_shifted)

    # 15. Final Display
    # Pack the final image into a 2D OpenGL texture and upload to GPU memory [S3, unofficial]
    gl_texture_2d_final = create_2d_texture_from_cuda_array(d_image_shifted)

    # Activate the on-screen rendering context and display the texture [S3, unofficial]
    gl_onscreen_context = create_onscreen_context()
    activate_gl_context(gl_onscreen_context)
    display_texture(gl_texture_2d_final)

**Edge Cases and Pitfalls:**
- CUDA address space arrays cannot be accessed directly by OpenGL [S3, unofficial]. Copying back to CPU and re-uploading is inefficient [S3, unofficial]. This is solved by using an OpenGL PBO registered in the CUDA memory space [S3, unofficial].
- Performance drop on discrete GPUs caused by CPU-to-GPU memory transfers and excessive draw calls is addressed by keeping geometric data entirely resident in video memory [S1].

## Operating characteristics
- **Time and Memory Complexity:** Not given in the sources.
- **Measured Performance:** Not given in the sources.
- **Scaling:** Not given in the sources.
- **Strengths and Limitations:** Eliminates data transfer and API call bottlenecks from host to device [S2]. The hybrid implementation lacked interactivity due to bottlenecks, which this full GPU-based pipeline aims to suppress [S3, unofficial].
- **When to Use:** When minimizing data transfer overhead is critical and the entire pipeline can be executed on the GPU [S1][S3, unofficial].
- **When Not to Use:** When CPU-based control is required for complex scene management not easily offloaded to GPU [S3, unofficial].

## Background
- **Origin:** The pipeline was developed to address bottlenecks in raymarching engines, which were largely unexplored in terms of pipeline architecture compared to ray tracing and raster engines [S2]. It was presented in the context of High Performance GPU-Based Fourier Volume Rendering [S3, unofficial].
- **History and Development:** The approach reuses OpenGL rendering contexts from a previous hybrid implementation but reimplements the computational context in CUDA [S3, unofficial]. It utilizes CUFFT library functions for FFT operations [S3, unofficial].
- **Where it is Used:** Fourier Volume Rendering (FVR) [S3, unofficial].
