# FPGA-based Raycasting
Also called: Raycasting Hardware (UVIZARD), VIZARD II

## Overview
FPGA-based raycasting refers to specialized hardware architectures, specifically the UVIZARD and VIZARD II systems developed at the University of Tübingen, designed to accelerate perspective volume raycasting on custom PCI boards [S1, unofficial][S2, book]. Unlike general-purpose GPU solutions that emerged later, these systems rely on long pre-processing and fixed-function pipelines to achieve real-time performance for large datasets [S1, unofficial][S2, book]. It is distinguished by its implementation of early ray-termination and table-based gradient lookup on field-programmable gate arrays (FPGAs) [S2, book].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (e.g., $256^3$ voxels), a camera view matrix (perspective), and transfer function parameters.
*   **Output:** A 2D rendered image.

**Data Structures:**
*   **Volume Data:** Stored in off-chip memory (SDRAM/SRAM). The sources do not specify a specific compression or brick layout for UVIZARD, unlike later systems like VolumePRO [S2, book].
*   **Gradient Lookup Table:** A pre-computed table mapping sample positions or density values to gradient vectors, used to avoid on-the-fly finite difference calculations [S2, book].
*   **Ray State Registers:** Hardware registers holding current ray origin, direction, accumulated color, opacity, and remaining step size [S2, book].

**Numbered Steps:**
1.  **Pre-processing:** The system requires significant pre-processing time to configure the FPGAs and load necessary lookup tables [S1, unofficial].
2.  **Ray Generation:** For each pixel, a ray is generated based on the perspective view matrix [S2, book].
3.  **Sampling and Gradient Lookup:** As the ray traverses the volume, sample positions are determined. The gradient at each sample is retrieved from the table-based gradient vector lookup scheme rather than computed via finite differences [S2, book].
4.  **Classification and Shading:** The sample value and gradient are used to classify the material and compute shading (lighting) [S2, book].
5.  **Compositing:** The sample's color and opacity are composited into the accumulated ray state using front-to-back or back-to-front accumulation [S2, book].
6.  **Early Ray Termination:** If the accumulated opacity exceeds a threshold (or transmittance drops below a threshold), the ray is terminated early to save computation [S2, book].
7.  **Image Output:** The final accumulated color is written to the frame buffer [S2, book].

**Formulas:**
The rendering equation for volume raycasting is approximated by the discrete sum:
$$ C = \sum_{i=0}^{N-1} c_i \alpha_i \prod_{j=0}^{i-1} (1 - \alpha_j) $$
Where $c_i$ is the color, $\alpha_i$ is the opacity, and $N$ is the number of samples. The sources note that pre-integration can be used to tabulate the integral of the transfer function, but UVIZARD specifically emphasizes the gradient lookup for shading [S1, unofficial][S2, book].

**Parameters:**
*   **Volume Size:** Tested on $256^3$ datasets [S1, unofficial][S2, book].
*   **Hardware:** PCI board with four FPGAs, a DSP, and SDRAM/SRAM [S2, book].

**Edge Cases and Pitfalls:**
*   **Pre-processing Latency:** The system requires long pre-processing times, making it less suitable for dynamic scenes requiring rapid reconfiguration [S1, unofficial].
*   **Precision:** Fixed-point arithmetic is implied by the hardware nature, but specific bit-widths are not given in the sources [S2, book].

## Subtopics

### VolumePRO
A successor architecture using ASICs instead of FPGAs, employing shear-warp methods and empty space skipping [S2, book].

### VolumePro1000
An advanced ASIC-based system using shear-image order ray casting, eliminating intermediate image steps [S2, book].

## Operating characteristics
*   **Performance:** The UVIZARD system achieved 10 Hz for a $256^3$ volume with perspective view [S1, unofficial]. The VIZARD II was anticipated to render $256^3$ datasets at interactive framerates (e.g., 30 fps) [S2, book].
*   **Memory:** Uses off-chip SDRAM/SRAM for volume storage [S2, book].
*   **Strengths:** Supports perspective rendering and early ray termination, which are not present in earlier brute-force hardware like VolumePRO [S2, book].
*   **Limitations:** Requires long pre-processing times, limiting flexibility for dynamic data [S1, unofficial]. Fixed-function hardware lacks the programmability of modern GPUs.

## Background
The UVIZARD and VIZARD II systems were developed at the University of Tübingen in the late 1990s [S1, unofficial][S2, book]. They represent an early attempt to use reconfigurable hardware (FPGAs) for volume rendering, preceding the dominance of GPU-based solutions. The work was presented in the context of specialized hardware for scientific visualization [S1, unofficial].
