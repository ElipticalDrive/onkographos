# GPU Raycasting
Also called: Hardware-accelerated Volume Raycasting, Ray-casting algorithm base on GPU, Ray-casting algorithm based GPU, Stegmaier's approach, rectilinear volume ray caster on GPU

## Overview
GPU Raycasting is a direct volume rendering technique that generates 2D images from 3D data fields by casting rays through the volume, where the computation of resampling and image synthesis is processed by the GPU fragment shader for parallel calculation [S2][S3, unofficial]. It approximates the volume rendering integral by sampling at a finite number of positions along each ray [S1, unofficial]. It differs from its siblings [GPU-based Ray-casting for Unstructured Grids](1118-gpu-based-ray-casting-for-unstructured-grids.md) and [CUDA Volume Ray Casting](2048-cuda-volume-ray-casting.md) by typically relying on regular 3D textures and fixed-function pipeline optimizations rather than complex unstructured grid traversal or explicit CUDA kernel management, though it shares the core principle of mapping rays to parallel execution units [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D volume data (loaded as a 3D texture), transfer function (loaded as a 1D texture), ray entry point ($p_{in}$), ray exit point ($p_{out}$), and ray direction step size ($rayDir$) [S2].
*   **Outputs:** Final color ($destColor$) and accumulated transparency ($remainOpacity$) for each pixel/fragment [S2].

**Data Structures:**
*   **3D Texture:** Stores the scalar volume data [S2].
*   **1D Texture:** Stores the transfer function mapping scalar values to color and opacity [S2].
*   **Fragment State:** Per-fragment variables include `destColor` (accumulated color), `remainOpacity` (accumulated transparency), `pos` (current sampling position), and `inside` (boolean flag for volume containment) [S2].

**Parameters:**
*   $p_{in}$: Position of ray entering data volume [S2].
*   $p_{out}$: Position of ray running out of data volume [S2].
*   $rayDir$: Distance of resampling point (step size) [S2].
*   $t_{Max}$: Total number of sampling points [S2].
*   Threshold: $1/255 \approx 0.0039$ for early ray termination [S2].

**Numbered Steps:**
1.  **Initialization:** Calculate the incident point ($p_{in}$) and the most distant point ($p_{out}$) of the ray through the volume bounding box [G]. Convert these to volume texture coordinates [G]. Initialize `destColor` to the initial color (typically transparent black) and `remainOpacity` to $1.0 - destColor.a$ (typically 1.0) [S2].
2.  **Ray Parameterization:** For each sampling index $i \in \mathbb{N}$, calculate the sampling position:
    $$pos = p_{in} + i \cdot rayDir \cdot \text{normalize}(p_{out} - p_{in})$$
    [S2]
3.  **Containment Check:** If the scalar distance along the ray satisfies $pos - p_{in} > p_{out} - p_{in}$, the resampling point is out of volume data [S2]. Set `inside` to false.
4.  **Sampling Loop:** While `inside` is true:
    a.  Sample the volume texture at `pos`:
        $$value \leftarrow \text{texture3D}(dataSetTexture, pos)$$
        [S2]
    b.  Map the scalar value to a transfer function index:
        $$scalar \leftarrow \text{scalarFromValue}(value)$$
        [S2]
    c.  Retrieve opacity from the 1D transfer function texture:
        $$opacity \leftarrow \text{texture1D}(opacityTexture, scalar)$$
        [S2]
    d.  If $opacity > 0.0$:
        i.  Calculate the color contribution (shading):
            $$color \leftarrow \text{shade}(value)$$
            [S2]
        ii. Modulate color by opacity:
            $$color \leftarrow color \cdot opacity$$
            [S2]
        iii. Accumulate color using front-to-back blending:
            $$destColor \leftarrow destColor + color \cdot remainOpacity$$
            [S2]
        iv. Update remaining opacity:
            $$remainOpacity \leftarrow remainOpacity \cdot (1.0 - opacity)$$
            [S2]
    e.  Advance the sampling position:
        $$pos \leftarrow pos + rayDir$$
        [S2]
    f.  Increment the sampling counter $t$ [S2].
    g.  Check termination conditions:
        $$inside \leftarrow (t < t_{Max}) \land (remainOpacity \ge 0.0039)$$
        [S2]
5.  **Output:** Write `destColor` to the framebuffer and set the alpha channel to $1.0 - remainOpacity$ [S2].

**Pseudocode:**
```python
# GPU Raycasting Fragment Shader Implementation
# Inputs: dataSetTexture (3D), opacityTexture (1D), pin, pout, rayDir, tMax

def trace(pin, pout, rayDir, tMax):
    # 1. Initialization [S2]
    destColor = [0.0, 0.0, 0.0, 0.0]  # RGBA
    remainOpacity = 1.0 - destColor[3]
    dir = normalize(pout - pin)
    pos = pin
    t = 0
    inside = True

    # 2. Ray Marching Loop [S2]
    while inside:
        # Containment check: scalar distance along ray direction [S2]
        if dot(pos - pin, dir) > dot(pout - pin, dir):
            inside = False
            break

        # Sample volume texture [S2]
        value = texture3D_lookup(dataSetTexture, pos)

        # Map to transfer function index [S2]
        scalar = extract_scalar(value)

        # Retrieve opacity from 1D transfer function texture [S2]
        opacity = texture1D_lookup(opacityTexture, scalar)

        if opacity > 0.0:
            # Calculate color contribution (shading) [S2]
            # Note: shading model is implementation-specific per [S2]
            color = compute_shading(value) * opacity

            # Accumulate color using front-to-back blending [S2]
            destColor = [destColor[0] + color[0] * remainOpacity,
                         destColor[1] + color[1] * remainOpacity,
                         destColor[2] + color[2] * remainOpacity,
                         destColor[3]]

            # Update remaining opacity [S2]
            remainOpacity = remainOpacity * (1.0 - opacity)

        # Advance sampling position [S2]
        pos = pos + rayDir * dir

        # Increment sampling counter [S2]
        t += 1

        # Termination check: tMax or early ray termination threshold [S2]
        if t >= tMax or remainOpacity < 0.0039:
            inside = False

    return destColor, remainOpacity

# Standard mathematical operations
def normalize(v):
    return v / magnitude(v)

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def magnitude(v):
    return sum(x * x for x in v) ** 0.5

def texture3D_lookup(texture, pos):
    # Standard 3D texture fetch at normalized coordinates [S2]
    return texture[pos]

def extract_scalar(value):
    # Extract scalar component from volume sample [S2]
    return value[0]

def texture1D_lookup(texture, scalar):
    # Standard 1D texture fetch for transfer function [S2]
    return texture[scalar]

def compute_shading(value):
    # Standard lighting model (e.g., Phong or gradient-based) [G]
    return [0.8, 0.8, 0.8]
```

**Edge Cases and Pitfalls:**
*   **Out of Bounds:** If the scalar distance along the ray satisfies $pos - p_{in} > p_{out} - p_{in}$, the point is outside the volume data [S2].
*   **Early Termination:** The loop terminates if $remainOpacity < 0.0039$ (equivalent to $1/255$) or $t \ge t_{Max}$ [S2].
*   **Accuracy Limitations:** Ray-triangle intersections (if used for boundary detection) have accuracy limitations that can lower image quality [S5, unofficial].
*   **Memory Constraints:** All data must reside in GPU memory, which limits the size of datasets that can be rendered compared to techniques that stream from CPU memory [S5, unofficial].

## Subtopics

### [GPU Ray Casting with Fast Intersection](7032-gpu-ray-casting-with-fast-intersection.md)
This method implements a single-pass GPU ray casting technique that tests each ray for intersection with the volume exactly once per rendering pass, supporting one object per pass. It solves the problem of efficiently rendering volumetric data by avoiding complex hierarchical data structures for empty space skipping, relying instead on a simplified fast intersection test effective for single-intersection scenarios. It differs from its sibling [GPU-based Ray Casting](7131-gpu-based-ray-casting.md) by explicitly optimizing for a single intersection per ray and utilizing a specific camera projection geometry defined in normalized coordinates, whereas general GPU ray casting may employ more complex traversal structures or multiple passes.

### [GPU-based Ray Casting](7131-gpu-based-ray-casting.md)
GPU-based ray casting is a rendering technique for unstructured grids that appears to sidestep the limitations of visibility orders and path tracing (PT) by avoiding explicit visibility order computation and many PT accuracy issues. It differs from PT by requiring all data to reside in GPU memory, which limits dataset size, whereas PT streams data from CPU memory.

### [GPU Ray Casting with Depth Peeling and Tile-Based Subdivision](7813-gpu-ray-casting-with-depth-peeling-and-tile-based-subdivisio.md)
This method improves GPU-based ray casting for unstructured grids by combining tile-based screen subdivision with depth peeling to handle non-convex meshes efficiently. It solves the problem of "imaginary cells" caused by mesh non-convexities without requiring convexification, while reducing fragment processing overhead by restricting computation to relevant screen regions. It differs from standard GPU ray casting by explicitly managing visibility layers via depth peeling per tile, and from convexification-based approaches by capturing ray re-entry into the mesh naturally.

### [Recursive Ray-casting for Global Illumination](8544-recursive-ray-casting-for-global-illumination.md)
Recursive Ray-casting for Global Illumination is an extension of GPU-based volume ray-casting that computes specular reflection and refraction effects at interactive frame rates by processing a ray-caster multiple times with different entry and exit points, supporting both Direct Volume Rendering (DVR) and isosurface rendering. Unlike techniques that focus on the exchangeability of ray-casters, this method aims to combine specular reflection and refraction effects within a single image.

### [FPGA-based Raycasting](8615-fpga-based-raycasting.md)
FPGA-based raycasting refers to specialized hardware architectures, specifically the UVIZARD and VIZARD II systems developed at the University of Tübingen, designed to accelerate perspective volume raycasting on custom PCI boards. Unlike general-purpose GPU solutions that emerged later, these systems rely on long pre-processing and fixed-function pipelines to achieve real-time performance for large datasets. It is distinguished by its implementation of early ray-termination and table-based gradient lookup on field-programmable gate arrays (FPGAs).

### [Single Scattering Illumination](9628-single-scattering-illumination.md)
Single Scattering Illumination is a volumetric lighting model that computes the radiance contribution of light undergoing exactly one scattering event within a participating medium. It distinguishes between light scattered along the view ray (Direct Single Scattering, DSS) and light scattered along illumination rays from scene points (Indirect Single Scattering, ISS). Unlike basic volume rendering that often ignores volumetric shadows, this method provides an analytic formulation for both contributions, including occlusion handling via shadow volumes, enabling real-time hardware rendering.

### [Distributed Volume Raycasting with Bricks](9869-distributed-volume-raycasting-with-bricks.md)
Distributed Volume Raycasting with Bricks is a parallel rendering technique that subdivides a volumetric dataset into convex subvolumes (bricks), assigning each to a separate node in a cluster for independent GPU raycasting. It differs from single-GPU methods by distributing the computational load across multiple machines and using software-based compositing to handle the final image assembly, thereby avoiding hardware blending limitations and `glReadPixels` performance bottlenecks.

### Stochastic Ray Shifting
Stochastic Ray Shifting is a technique applied during ray casting to reduce banding artifacts by shifting ray origins stochastically [S6]. It is controlled by a boolean parameter "Apply Noise" in the user interface that toggles the application of stochastic ray-shifting [S6].

## Background
GPU Raycasting was introduced by Kruger in 2003, making it feasible from a computational standpoint due to advances in graphics hardware and algorithms [S4, unofficial]. It was developed to overcome the performance constraints that previously prevented the practical application of illustrative visualization techniques [S4, unofficial]. The method is implemented within projects such as 'vize', consisting of vertex and fragment shaders (`mpr_ray_casting.vs` and `mpr_ray_casting.fs`) and a CPU-side C++ class `VolumePainter` for configuration and dispatch [S3, unofficial].
