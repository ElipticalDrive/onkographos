# GPU Raycasting
Also called: Hardware-accelerated Volume Raycasting, Ray-casting algorithm base on GPU, Ray-casting algorithm based GPU, Stegmaier's approach, rectilinear volume ray caster on GPU

## Overview
GPU Raycasting is a volume rendering technique that generates 2D images from 3D data fields by casting rays through the volume, where the calculation of resampling and image synthesis is processed by the GPU fragment shader for parallel calculation [S2]. It approximates the volume rendering integral by sampling at a finite number of positions along each ray [S1, unofficial]. Unlike parent methods that may rely on complex hierarchical structures or visibility ordering, this approach maps the ray traversal directly to the GPU's parallel execution units, leveraging the graphics pipeline's texture sampling and blending capabilities [S2][S4, unofficial]. It differs from its sibling [CUDA Volume Ray Casting](2048-cuda-volume-ray-casting.md) by typically utilizing the fixed-function or programmable fragment shader pipeline of standard graphics APIs (like OpenGL) rather than general-purpose compute shaders, and from [WebGL Volume Rendering](3243-webgl-volume-rendering.md) by often assuming higher-end consumer or professional graphics hardware capabilities [S2, S6].

## How it works
**Inputs and Outputs:**
*   **Inputs:** 3D volume data (loaded as a 3D texture), transfer functions (loaded as 1D textures for color and opacity), ray entry point ($p_{in}$), ray exit point ($p_{out}$), and sampling step size ($rayDir$) [S2].
*   **Outputs:** A 2D color buffer (fragment color) and optionally an alpha channel representing accumulated opacity [S2].

**Data Structures:**
*   **3D Texture (`dataSetTexture`):** Stores the scalar volume data. Accessed via `texture3D` [S2].
*   **1D Texture (`opacityTexture`):** Stores the opacity transfer function. Accesses are indexed by scalar values derived from volume data [S2].
*   **Per-Thread State:**
    *   `pos`: Current sampling position in 3D space.
    *   `destColor`: Accumulated color (RGB).
    *   `remainOpacity`: Accumulated transparency (1.0 - accumulated opacity).
    *   `t`: Counter for the number of sampling steps.
    *   `tMax`: Maximum number of sampling steps (determined by volume extent and step size) [S2].

**Numbered Steps:**
1.  **Initialization:**
    *   Calculate the normalized ray direction vector: $\vec{d} = \text{normalize}(p_{out} - p_{in})$ [S2].
    *   Initialize the current position: $pos = p_{in}$ [S2].
    *   Initialize accumulated color: $destColor \leftarrow \text{initialColor()}$ (typically black or background color) [S2].
    *   Initialize remaining opacity: $remainOpacity \leftarrow 1.0 - destColor.a$ [S2].
    *   Initialize step counter: $t \leftarrow 0$ [S2].
2.  **Ray Traversal Loop:**
    *   While the sampling point is inside the volume ($inside == \text{TRUE}$):
        1.  **Sample Volume:** Retrieve the scalar value at the current position: $value \leftarrow \text{texture3D}(dataSetTexture, pos)$ [S2].
        2.  **Transfer Function:** Map the scalar value to a color and opacity using transfer functions:
            *   $scalar \leftarrow \text{scalarFromValue}(value)$ [S2].
            *   $opacity \leftarrow \text{texture1D}(opacityTexture, scalar)$ [S2].
            *   $color \leftarrow \text{shade}(value)$ (if $opacity > 0.0$) [S2].
            *   $color \leftarrow color \times opacity$ [S2].
        3.  **Compositing (Front-to-Back):**
            *   Update accumulated color: $destColor \leftarrow destColor + color \times remainOpacity$ [S2].
            *   Update remaining opacity: $remainOpacity \leftarrow remainOpacity \times (1.0 - opacity)$ [S2].
        4.  **Advance Ray:**
            *   Update position: $pos \leftarrow pos + rayDir$ [S2].
            *   Increment step counter: $t \leftarrow t + 1.0$ [S2].
        5.  **Termination Check:**
            *   Determine if the point is still inside: $inside \leftarrow (t < tMax) \land (remainOpacity \ge 0.0039)$ [S2]. Note: $0.0039 \approx 1/255$ [S2].
3.  **Output:**
    *   Set fragment color: $gl\_FragColor \leftarrow destColor$ [S2].
    *   Set fragment alpha: $gl\_FragColor.a \leftarrow 1.0 - remainOpacity$ [S2].

**Formulas:**
*   **Sampling Position:**
    $$pos = p_{in} + i \cdot rayDir \cdot \text{normalize}(p_{out} - p_{in})$$
    where $i \in \mathbb{N}$ is the index of the resampling point [S2].
*   **Color Accumulation:**
    $$destColor_i = destColor_{i-1} + color \cdot remainOpacity_{i-1}$$
    where $destColor_i$ is the color value after passing through the $i$-th volume element [S2].
*   **Opacity Accumulation:**
    $$remainOpacity_i = remainOpacity_{i-1} \cdot (1.0 - opacity)$$
    where $remainOpacity_i$ is the opacity value after passing through the $i$-th volume element [S2].

**Parameters:**
*   $p_{in}$: Position of ray entering data volume [S2].
*   $p_{out}$: Position of ray running out of data volume [S2].
*   $rayDir$: Distance of resampling point (step size) [S2].
*   $tMax$: Total number of sampling points [S2].

**Edge Cases and Pitfalls:**
*   **Out of Bounds:** If $pos - p_{in} > p_{out} - p_{in}$, the resampling point is out of volume data [S2].
*   **Precision Limits:** Loop termination uses a threshold of $0.0039$ ($1/255$) for remaining opacity, which may lead to slight inaccuracies in very transparent regions or very deep volumes [S2].
*   **Accuracy Limitations:** GPU-based ray casting may suffer from accuracy limitations in ray-triangle intersections if used for unstructured grids, potentially lowering image quality [S4, unofficial].
*   **Memory Constraints:** Requires all data to reside in GPU memory, which limits the size of datasets that can be rendered compared to CPU-based streaming methods [S4, unofficial].

**Pseudocode:**
```python
def gpu_ray_casting(p_in, p_out, volume_texture, opacity_texture, step_size):
    # Initialize ray direction
    ray_direction = normalize(p_out - p_in)
    
    # Initialize state
    pos = p_in
    dest_color = vec4(0.0, 0.0, 0.0, 0.0) # Initial color (e.g., black)
    remain_opacity = 1.0 - dest_color.a
    t = 0
    
    # Calculate max steps based on volume extent and step size
    # Note: tMax calculation depends on specific volume bounds and step_size
    # For simplicity, assume tMax is provided or calculated externally
    # tMax = length(p_out - p_in) / step_size 
    
    while True:
        # Check termination conditions
        # inside check: t < tMax AND remain_opacity >= 0.0039
        if t >= tMax or remain_opacity < 0.0039:
            break
            
        # Sample volume
        value = texture3D(volume_texture, pos)
        
        # Get scalar and opacity
        scalar = scalar_from_value(value)
        opacity = texture1D(opacity_texture, scalar)
        
        if opacity > 0.0:
            # Shade the point
            color = shade(value)
            color = color * opacity
            
            # Composite
            dest_color = dest_color + color * remain_opacity
            remain_opacity = remain_opacity * (1.0 - opacity)
            
        # Advance ray
        pos = pos + step_size * ray_direction
        t = t + 1.0
        
    # Output
    gl_FragColor = dest_color
    gl_FragColor.a = 1.0 - remain_opacity
```

## Subtopics

### [GPU Ray Casting with Fast Intersection](7032-gpu-ray-casting-with-fast-intersection.md)
Implements a single-pass technique testing each ray for intersection exactly once per pass, supporting one object per pass. It avoids complex hierarchical data structures for empty space skipping, relying on a simplified fast intersection test effective for single-intersection scenarios. It differs from general GPU ray casting by explicitly optimizing for a single intersection per ray and utilizing specific camera projection geometry in normalized coordinates.

### [GPU-based Ray Casting](7131-gpu-based-ray-casting.md)
A rendering technique for unstructured grids that sidesteps visibility order limitations and path tracing (PT) accuracy issues. It differs from PT by requiring all data to reside in GPU memory, limiting dataset size, whereas PT streams data from CPU memory.

### [GPU Ray Casting with Depth Peeling and Tile-Based Subdivision](7813-gpu-ray-casting-with-depth-peeling-and-tile-based-subdivisio.md)
Improves GPU-based ray casting for unstructured grids by combining tile-based screen subdivision with depth peeling to handle non-convex meshes efficiently. It solves the problem of "imaginary cells" caused by mesh non-convexities without requiring convexification, while reducing fragment processing overhead.

### [Recursive Ray-casting for Global Illumination](8544-recursive-ray-casting-for-global-illumination.md)
An extension that computes specular reflection and refraction effects at interactive frame rates by processing a ray-caster multiple times with different entry and exit points. It supports both Direct Volume Rendering (DVR) and isosurface rendering, aiming to combine specular effects within a single image.

### [Single Scattering Illumination](9628-single-scattering-illumination.md)
A volumetric lighting model computing radiance from light undergoing exactly one scattering event. It distinguishes between Direct Single Scattering (DSS) and Indirect Single Scattering (ISS), providing analytic formulations for both, including occlusion handling via shadow volumes for real-time hardware rendering.

### [Distributed Volume Raycasting with Bricks](9869-distributed-volume-raycasting-with-bricks.md)
Subdivides volumetric data into convex subvolumes (bricks) assigned to separate cluster nodes for independent GPU raycasting. It uses software-based compositing to handle final image assembly, avoiding hardware blending limitations and `glReadPixels` bottlenecks.

### FPGA-based Raycasting
An FPGA-based system introduced in 1997 by the University of Tübingen (U. Tbingen) for perspective view raycasting. It requires long pre-processing but achieves 10 Hz performance for a $256^3$ volume with perspective view [S5, unofficial].

### Stochastic Ray Shifting
A technique applied during ray casting to reduce banding artifacts by shifting ray origins stochastically. It is controlled by a boolean parameter "Apply Noise" in the user interface, which toggles the application of this shifting [S6].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples per ray and the number of pixels (rays). The complexity is $O(N_{pixels} \cdot N_{samples})$ [S1, unofficial][S2].
*   **Memory Complexity:** Proportional to the size of the 3D volume texture and 1D transfer function textures stored in GPU memory [S2][S4, unofficial].
*   **Measured Performance:** Specific performance metrics vary by hardware. For example, an FPGA-based predecessor achieved 10 Hz for a $256^3$ volume [S5, unofficial], while modern GPU implementations can achieve interactive rates depending on resolution and volume size [S2, S6].
*   **Scaling:** Performance scales with the number of GPU cores and memory bandwidth. Multi-core CPUs and clustered graphics boards can offer near-linear scaling [S1, unofficial].
*   **Strengths:** High parallelism, leverages existing graphics hardware, avoids complex visibility ordering [S2][S4, unofficial].
*   **Limitations:** Limited by GPU memory capacity for large datasets, potential accuracy issues with ray-triangle intersections in unstructured grids, and fixed-function pipeline limitations in older APIs [S4, unofficial].
*   **When to Use:** Suitable for real-time or near-real-time visualization of moderate-sized volumetric datasets on hardware with sufficient GPU memory and graphics capabilities [S2, S6].
*   **When Not to Use:** Unsuitable for extremely large datasets that exceed GPU memory, or when high-precision geometric accuracy is critical for unstructured grids with complex topology [S4, unofficial].

## Background
GPU Raycasting was introduced by Kruger in 2003, making it feasible from a computational standpoint due to advances in graphics hardware and algorithms [S3, unofficial]. Prior to this, performance constraints limited the practical application of illustrative visualization techniques [S3, unofficial]. The method leverages the parallel processing capabilities of GPUs to accelerate the ray casting process, which was previously computationally expensive on CPUs [S2][S3, unofficial]. It has since become a foundational technique in medical visualization and scientific visualization, enabling interactive exploration of 3D data [S3, unofficial].
