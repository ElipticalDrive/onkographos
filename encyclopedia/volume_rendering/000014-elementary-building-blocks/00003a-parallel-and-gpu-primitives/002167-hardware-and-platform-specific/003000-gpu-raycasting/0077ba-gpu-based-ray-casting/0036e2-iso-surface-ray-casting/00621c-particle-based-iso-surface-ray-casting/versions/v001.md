# Particle-based Iso-surface Ray Casting

Also called: Fluid Surface Rendering via Particles, Particle-based Iso-surface Rendering

## Overview
This method renders fluid surfaces directly by extracting an iso-surface from a scalar field $\phi$ defined by particle data, rather than rendering the particles themselves or using a voxelized grid. It solves the problem of high-quality, alias-free surface rendering for particle-based simulations (like SPH) by combining the spatial efficiency of particle data structures with the visual fidelity of ray casting. It differs from standard particle rendering by evaluating a continuous field function to find precise intersection points, and from grid-based ray casting by avoiding the memory overhead and quantization errors of voxelization.

## How it works
The method performs back-to-front ray traversal through the simulation domain. For each ray, it identifies cells containing particles, evaluates the scalar field $\phi$ within those cells using shared memory, and computes the intersection depth with the iso-surface $\phi(x) = \phi_{iso}$.

### Inputs and Outputs
*   **Input:** Ray origin $\mathbf{o}$ and direction $\mathbf{d}$; particle simulation data (positions, properties); scalar field function $\phi(\mathbf{x})$; iso-value $\phi_{iso}$.
*   **Output:** Intersection depth $t$ (or $\lambda_f$); intersection normal $\nabla \phi(\mathbf{x})$; color/illumination at the hit point.

### Data Structures
*   **Particle Data:** Stored in cells. Cell entries (lists of particle indices or data) are loaded into **shared memory** for fast access by threads in a warp [S1].
*   **Field Function:** $\phi: \mathbb{R}^3 \rightarrow \mathbb{R}$. Common choices include density $\rho$ [ZB05], surface distance function [ZB05], or anisotropic surface distance function [YT13]. The choice affects computational workload but not the algorithmic structure [S1].

### Algorithm Steps

1.  **Domain Traversal:**
    *   Traverse the simulation domain along the ray to find the next cell $\bar{c}$ containing particles.
    *   If no cell contains particles, continue traversal or terminate [S1].
    *   Calculate the center of the found cell $\bar{c}$:
        $$ \bar{x} = \frac{1}{2} (\bar{x}_{min} + \bar{x}_{max}) $$
    *   Determine the next cell boundary intersected by the ray:
        $$ x_{next} = \bar{D}_{min} + \bar{x}_{min} + \max(\bar{d}, 0) \circ C_{max} $$
        where $\circ$ denotes component-wise multiplication, $\bar{D}_{min}$ is the minimum boundary of the domain/cell, $\bar{x}_{min}$ is the minimum coordinate of the cell, $\bar{d}$ is the ray direction component, and $C_{max}$ is the cell size [S1].
    *   Calculate the intersection of the ray with the found cell $\bar{c}$, yielding entry depth $\lambda_{min\_c}$ and exit depth $\lambda_{max\_c}$ [S1].

2.  **Segmentation and Thread Assignment:**
    *   Subdivide the interval $[\max\{\lambda_{min\_c}, 0\}, \lambda_{max\_c})$ into $w-1$ segments, where $w$ is the warp size.
    *   Assign starting positions $x_s$ to threads in the warp:
        $$ x_s = \text{ray}\left( \max\{\lambda_{min\_c}, 0\} + \frac{\lambda_{max\_c} - \max\{\lambda_{min\_c}, 0\}}{w-1} \cdot s \right) $$
        where $s$ is the thread index within the warp ($0 \le s < w-1$). The last thread is assigned $x = \text{ray}(\lambda_{max\_c})$ [S1].
    *   Each thread calculates its corresponding distance value $\lambda_s$ [S1].

3.  **Field Evaluation:**
    *   Load particle data for all neighboring cells of $\bar{c}$ into shared memory [S1].
    *   Each thread evaluates the scalar field $\phi_s = \phi(x_s)$ by iterating over all particles in the neighboring cells using the shared memory data [S1].

4.  **Intersection Calculation (Algorithm 6):**
    *   Use intra-warp voting to find the intersection depth $\lambda_f$ if an intersection exists within the segment.
    *   Define predicate $p$: $\phi_s$ crosses $\phi_{iso}$ (sign change detected between adjacent samples or based on specific root-finding criteria implied by the ballot usage).
    *   Compute active mask: `active = ballot(p)` [S1].
    *   If `active` is non-zero, use `ffs(active)` to find the first thread with an intersection.
    *   Use `shuffle(t, i)` to retrieve the depth value $t$ from the identified thread [S1].
    *   If an intersection is found, store $\lambda_f = t$ and mark the ray as processed. Otherwise, continue traversal to the next cell [S1].

5.  **Normal Calculation:**
    *   If an intersection is found, calculate the normal by evaluating the gradient $\nabla \phi(\mathbf{x})$ at the intersection point [S1].

def ballot(predicates):
    """
    Simulates GPU ballot instruction: returns a bitmask of threads where predicate is true.
    """
    mask = 0
    for i, p in enumerate(predicates):
        if p:
            mask |= (1 << i)
    return mask

def ffs(mask):
    """
    Returns the index of the first set bit (least significant).
    """
    if mask == 0:
        return -1
    return (mask & -mask).bit_length() - 1

def compute_gradient(phi_func, point, particles):
    """
    Computes gradient of phi at point using particles.
    """
    # Numerical gradient or analytical if available
    epsilon = 1e-5
    grad = [0.0, 0.0, 0.0]
    for i in range(3):
        point_plus = point.copy()
        point_plus[i] += epsilon
        point_minus = point.copy()
        point_minus[i] -= epsilon
        grad[i] = (phi_func(point_plus, particles) - phi_func(point_minus, particles)) / (2 * epsilon)
    return grad

### Parameters and Edge Cases
*   **Warp Size ($w$):** Typically 32 for NVIDIA GPUs. The interval is divided into $w-1$ segments [S1].
*   **Iso-value ($\phi_{iso}$):** Depends on the field. For density, it is a threshold; for distance functions, it is 0 [S1].
*   **Synchronization:** Implicit synchronization is used by checking after each cell traversal if any thread in the warp has found a cell with fluid surfaces. This avoids warp divergence [S1].
*   **Precision:** Evaluating $\phi$ requires iterating over particles. Precision depends on the particle distribution and the field function's smoothness.
*   **Degenerate Input:** If a cell contains no particles, traversal continues. If no cells are found, the ray terminates [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the number of particles per cell and the number of cells traversed. Evaluating $\phi$ requires iterating over neighboring particles, which is $O(N_p)$ per sample, where $N_p$ is the number of particles in the neighborhood.
*   **Memory Complexity:** Shared memory usage is proportional to the number of particles in neighboring cells loaded for evaluation [S1].
*   **Performance:** Tested on Nvidia RTX 2080 Ti GPU with 11 GiB VRAM [S1].
*   **Strengths:** High-quality surfaces, no voxelization artifacts, efficient use of shared memory for particle access.
*   **Limitations:** Requires efficient particle data structure (e.g., grid-based partitioning) to find neighboring cells quickly. Performance degrades if particle density is very high or uneven.
*   **When to use:** When high-quality, smooth surfaces are required for particle-based simulations (SPH, etc.) and voxelization is undesirable.
