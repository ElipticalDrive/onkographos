# Compute Shader Volume Ray Casting

Also called: OpenGL Compute Shader Volume Rendering

## Overview
Compute Shader Volume Ray Casting is a GPU-accelerated volume rendering technique that offloads the ray-marching loop from the fragment shader to a compute shader kernel [S1]. It solves the problem of rendering volumetric data by calculating the entry and exit points of rays through the volume in a prior pass, then using a compute shader to perform the integration for each pixel in parallel [S1]. It differs from its sibling [GPU Ray Casting with Fast Intersection](7032-gpu-ray-casting-with-fast-intersection.md) by explicitly utilizing the compute shader model for the heavy lifting of ray traversal, allowing for more flexible thread organization and memory access patterns compared to fixed-function fragment pipelines [S1].

## How it works
The method operates in two distinct stages: a rasterization pass to determine ray boundaries and a compute pass to perform volume integration [S1].

**Inputs and Outputs:**
- **Inputs:** `firstHit` (2D texture storing entry points), `lastHit` (2D texture storing exit points), `volume` (3D texture for scalar field), `transferFunc` (1D texture for color/opacity mapping), and `h` (uniform float for step size) [S1].
- **Outputs:** `destTex` (write-only 2D image in RGBA8 format storing the final color and alpha) [S1].

**Data Structures:**
- `firstHit` and `lastHit` are accessed via `sampler2D` [S1].
- `volume` is accessed via `sampler3D` [S1].
- `transferFunc` is accessed via `sampler1D` [S1].
- `destTex` is accessed via `imageStore` using `image2D` [S1].

**Algorithm Steps:**
1. **Initialization:** The compute shader kernel is launched for every pixel in the output resolution [S1]. Each thread identifies its global position using `gl_GlobalInvocationID.xy` [S1].
2. **Boundary Check:** The thread checks if its position is within the bounds of the output texture dimensions [S1].
3. **Coordinate Flip:** The Y-coordinate of the store position is flipped to match OpenGL's texture coordinate system: $storePos.y = size.y - storePos.y$ [S1].
4. **Ray Definition:**
   - Fetch the entry point ($first$) from `firstHit` and the exit point ($last$) from `lastHit` at `storePos` [S1].
   - Calculate the ray direction vector: $\vec{d} = last - first$ [S1].
   - Calculate the ray length $D = \|\vec{d}\|$ [S1].
   - Normalize the direction: $\vec{d} = \frac{\vec{d}}{\|\vec{d}\|}$ [S1].
5. **State Initialization:**
   - Initialize accumulated color $C = (0.0, 0.0, 0.0, 1.0)$ [S1].
   - Initialize current ray position $tr = first$ [S1].
   - Calculate step vector: $\vec{step} = \vec{d} \times h$ [S1].
6. **Ray Marching Loop:** Iterate with parameter $t$ from $0$ to $D$ with increment $h$:
   - Sample the scalar field value $s$ from `volume` at position $tr$ [S1].
   - Sample the transfer function using $s$ to get color $c_{samp}$ and opacity $\alpha_{samp}$ [S1].
   - Adjust opacity using the formula: $\alpha_{samp} = 1.0 - \exp(-0.5 \times \alpha_{samp})$ [S1].
   - Apply the under operator for color accumulation as specified in the source:
     $$c_{samp.rgb} \leftarrow c_{samp.rgb} \cdot \alpha_{samp}$$
     $$C_{rgb} \leftarrow C_{rgb} + c_{samp.rgb} \cdot C_{a}$$
     $$C_{a} \leftarrow 1.0 - \alpha_{samp}$$
   - **Early Ray Termination:** If $1.0 - C_{a} > \text{opacityThreshold}$ (where $\text{opacityThreshold} = 0.99$), break the loop [S1].
   - Advance ray position: $tr \leftarrow tr + \vec{step}$ [S1].
7. **Finalization:**
   - Compute final alpha: $C_{a} = 1.0 - C_{a}$ [S1].
   - Store the resulting color $C$ into `destTex` at `storePos` using `imageStore` [S1].
8. **Execution:**
   - Launch the kernel using `glDispatchCompute` [S1].
   - Call `glMemoryBarrier` with `GL_SHADER_IMAGE_ACCESS_BARRIER_BIT` to ensure writes are visible [S1].
   - Rasterize a full-screen quad using `destTex` for final display [S1].

**Pseudocode:**
```python
import math

def compute_shader_volume_ray_casting(firstHit, lastHit, volume, transferFunc, destTex, h, opacityThreshold=0.99):
    # 1. Get thread position (simulated GLSL entry)
    store_pos = get_global_invocation_id() # Returns (x, y)
    size = destTex.shape # (width, height)

    # 2. Boundary check
    if store_pos[0] >= size[0] or store_pos[1] >= size[1]:
        return

    # 3. Flip Y coordinate
    store_pos_y = size[1] - store_pos[1]
    store_pos = (store_pos[0], store_pos_y)

    # 4. Fetch entry and exit points
    first = firstHit[store_pos] # vec3
    last = lastHit[store_pos]   # vec3

    # 5. Calculate ray properties
    direction = last - first
    D = math.sqrt(sum((c**2 for c in direction)))
    norm = math.sqrt(sum((c**2 for c in direction)))
    direction = tuple(c / norm for c in direction)

    # 6. Initialize state
    color = (0.0, 0.0, 0.0, 1.0) # (r, g, b, a)
    tr = first
    ray_step = tuple(d * h for d in direction)

    # 7. Ray marching loop
    t = 0.0
    while t <= D:
        # Sample scalar field
        scalar = volume[tr][0]

        # Sample transfer function
        samp = transferFunc[scalar] # vec4 (r, g, b, a)

        # Calculate adjusted alpha
        samp_a = 1.0 - math.exp(-0.5 * samp[3])

        # Accumulate color and alpha (Under operator variant from source)
        samp_rgb = tuple(s * samp_a for s in samp[:3])
        color_rgb = tuple(c + s * color[3] for c, s in zip(color[:3], samp_rgb))
        color_a = 1.0 - samp_a

        # Early ray termination
        if (1.0 - color_a) > opacityThreshold:
            break

        # Increment ray position
        tr = tuple(t + r for t, r in zip(tr, ray_step))
        t += h

    # 8. Finalize alpha
    color_a = 1.0 - color_a
    color = (color_rgb[0], color_rgb[1], color_rgb[2], color_a)

    # 9. Store result
    destTex[store_pos] = color
```

**Parameters:**
- `h`: Step size for ray marching [S1].
- `opacityThreshold`: Constant set to 0.99 [S1].

**Edge Cases and Pitfalls:**
- **Precision:** The loop uses a floating-point counter `t` compared against `D`. Accumulation errors in `t` or `tr` may cause the loop to run slightly longer or shorter than intended [S1].
- **Boundaries:** The explicit check `storePos.x < size.x && storePos.y < size.y` prevents out-of-bounds memory access [S1].
- **Coordinate System:** The Y-flip is critical because OpenGL textures typically have the origin at the bottom-left, while screen coordinates often assume top-left [S1].
