# Efficient Ray Casting Pipeline

Also called: EfficientRayCast, Raycasting Rendering Pipeline

## Overview
The Efficient Ray Casting Pipeline encompasses two distinct real-time rendering approaches: a CPU-based column-casting method for pseudo-3D 2D maps that writes directly to raw pixel buffers [S1, unofficial], and a GPU-based Direct3D 11 pipeline that uses geometry shaders for active brick detection and ray marching through volumetric data [S2, unofficial]. Both prioritize predictable, low-latency operations over complex mathematical approximations to achieve real-time performance on their respective platforms [S1, S2, unofficial].

## How it works

### CPU-Based 2D Raycasting
**Inputs and Outputs**
*   **Input:** 2D grid map (wall/empty cells), camera position, camera direction angle, viewport dimensions.
*   **Output:** Raw pixel buffer (e.g., `Uint32Array`) representing the final image.

**Data Structures**
*   **Map:** 2D array or grid representing wall cells.
*   **Framebuffer:** Linear array of pixel values mapped directly to the canvas's raw pixel buffer.

**Steps**
1.  Initialize an internal framebuffer at 480×300 resolution [S1, unofficial].
2.  Cast one ray per screen column [S1, unofficial].
3.  In the hot column loop, perform a texture fetch and fog multiply (three integer multiplies and shifts) per pixel [S1, unofficial].
4.  Write every visible pixel exactly once directly into the `Uint32Array` view over the canvas's raw pixel buffer [S1, unofficial].
5.  Upscale the internal framebuffer to fill the viewport using an integer scale factor and `image-rendering: pixelated` filtering [S1, unofficial].

**Formulas**
*   Ray angle for column $c$: $\theta_c = \theta_{cam} + \arctan\left(\frac{c - W_{fb}/2}{W_{fb}/2}\right)$
*   Fisheye-corrected distance: $d_{corr} = d \cdot \cos(\theta_c - \theta_{cam})$
*   Wall strip height: $h_{wall} = H_{fb} / d_{corr}$
*   Fog multiply: $C_{out} = C_{tex} \cdot F_{fog}$ using three integer multiplies and bit shifts per pixel [S1, unofficial].

**Parameters**
*   Internal framebuffer resolution: 480×300 [S1, unofficial].
*   Upscaling: Integer scale factor applied to both axes [S1, unofficial].

**Edge Cases and Pitfalls**
*   Zero-direction components in ray traversal require handling division by zero in DDA step calculations [G].
*   Integer scaling boundaries must clamp target coordinates to viewport dimensions to prevent out-of-bounds writes [G].
*   Fisheye distortion correction fails if $d_{corr}$ approaches zero; a minimum distance guard is required [G].

**Pseudocode**
```python
def render_cpu_column_cast(map_grid, camera, viewport_width, viewport_height):
    fb_width, fb_height = 480, 300
    scale_x = viewport_width // fb_width
    scale_y = viewport_height // fb_height
    framebuffer = [0] * (fb_width * fb_height)

    for col in range(fb_width):
        ray_angle = camera.angle + atan((col - fb_width / 2) / (fb_width / 2))
        dist = cast_ray_dda(map_grid, camera.pos, ray_angle)
        corrected_dist = dist * cos(ray_angle - camera.angle)
        wall_height = fb_height / corrected_dist
        start_y = (fb_height - wall_height) / 2
        end_y = start_y + wall_height

        for row in range(fb_height):
            if start_y <= row < end_y:
                tex_y = (row - start_y) / wall_height
                # Three integer multiplies and shifts for fog multiply [S1, unofficial]
                fog_factor = (tex_y * 255) >> 8
                color = (fog_factor * 255) & 0xFFFFFF
                framebuffer[row * fb_width + col] = color

    raw_buffer = bytearray(viewport_width * viewport_height * 4)
    for y in range(fb_height):
        for x in range(fb_width):
            pixel = framebuffer[y * fb_width + x]
            for dy in range(scale_y):
                for dx in range(scale_x):
                    ty = y * scale_y + dy
                    tx = x * scale_x + dx
                    if ty < viewport_height and tx < viewport_width:
                        idx = (ty * viewport_width + tx) * 4
                        raw_buffer[idx:idx+4] = pixel.to_bytes(4, 'little')
    return raw_buffer

def cast_ray_dda(grid, pos, angle):
    dx, dy = cos(angle), sin(angle)
    step_x = 1 if dx > 0 else -1
    step_y = 1 if dy > 0 else -1
    t_delta_x = abs(1.0 / dx) if dx != 0 else float('inf')
    t_delta_y = abs(1.0 / dy) if dy != 0 else float('inf')
    t_max_x = (step_x > 0 and (int(pos.x) + 1 - pos.x) * t_delta_x) or (pos.x - int(pos.x)) * t_delta_x
    t_max_y = (step_y > 0 and (int(pos.y) + 1 - pos.y) * t_delta_y) or (pos.y - int(pos.y)) * t_delta_y
    x, y = int(pos.x), int(pos.y)
    while grid[y][x] == 0:
        if t_max_x < t_max_y:
            t_max_x += t_delta_x; x += step_x
        else:
            t_max_y += t_delta_y; y += step_y
    return sqrt((x - pos.x)**2 + (y - pos.y)**2)
```

### GPU-Based 3D Volume Raycasting
**Inputs and Outputs**
*   **Input:** Volumetric data (bricked), view/projection matrices, camera position, density range constants.
*   **Output:** Final output texture (`m_pOutputTex`).

**Data Structures**
*   **Constant Buffer (`CB_EfficientRayCast_Frame`):** `mInvView` (XMMATRIX), `mView` (XMMATRIX), `mViewProj` (XMMATRIX), `f4ViewPos` (XMFLOAT4), `f2HalfWinSize` (XMFLOAT2), `f2WinReso` (XMFLOAT2), `f2MinMaxDensity` (XMFLOAT2), `NIU` (float), `NIU1` (float) [S2, unofficial].
*   **Textures:** `m_pFarNearTex` (stores near/far ray positions), `m_pOutputTex` (final output), `m_pBrickVolTex` (bricked volume) [S2, unofficial].

**Steps**
1.  Initialize constant buffer with view matrices, camera position, window size, and density range [S2, unofficial].
2.  Allocate separate buffers for output, far/near positions, and debug visualization [S2, unofficial].
3.  Use `m_pActiveCellAndSOGS` geometry shader for active brick detection and cube mesh generation [S2, unofficial].
4.  Use `m_pRaymarchGS` geometry shader for ray generation and marching through active bricks [S2, unofficial].
5.  Write the composited result to `m_pOutputTex` [S2, unofficial].

**Formulas**
*   Normalization factor: $NIU = 1.0 / MAX\_DENSITY$
*   Normalization factor + 1: $NIU1 = NIU + 1.0$
*   Ray position storage: $P_{near}, P_{far}$ written to `m_pFarNearTex` per active brick [S2, unofficial].

**Parameters**
*   `MIN_DENSITY`, `MAX_DENSITY`: Constants for density range, initialized in constructor [S2, unofficial].

**Edge Cases and Pitfalls**
*   Geometry shader input limits require culling bricks that exceed primitive count thresholds [G].
*   Ray marching precision degrades near brick boundaries; epsilon offsets are required to prevent z-fighting [G].
*   Constant buffer alignment must match HLSL struct packing rules to avoid misaligned matrix reads [G].

**Pseudocode**
```python
def render_gpu_volume_pipeline(volume_data, camera_info, brick_data):
    cb_frame = {
        'mInvView': camera_info.inv_view,
        'mView': camera_info.view,
        'mViewProj': camera_info.view_proj,
        'f4ViewPos': camera_info.pos,
        'f2HalfWinSize': (camera_info.width / 2, camera_info.height / 2),
        'f2WinReso': (camera_info.width, camera_info.height),
        'f2MinMaxDensity': (MIN_DENSITY, MAX_DENSITY),
        'NIU': 1.0 / MAX_DENSITY,
        'NIU1': 1.0 / MAX_DENSITY + 1.0
    }
    far_near_tex = Texture2D()
    output_tex = Texture2D()
    active_bricks = detect_active_bricks(brick_data, cb_frame)
    cube_meshes = generate_cube_meshes(active_bricks)
    for mesh in cube_meshes:
        ray_positions = cast_rays_through_brick(mesh, cb_frame)
        far_near_tex.write(ray_positions)
    output_tex.write(composite_rays(far_near_tex, cb_frame))
    return output_tex
```

## Operating characteristics

### CPU-Based 2D Raycasting
*   **Time Complexity:** $O(C \times H + S)$, where $C$ is screen columns, $H$ is screen height, and $S$ is visible sprites [S1, unofficial]. Rendering time depends on screen resolution and visible sprites, not map size [S1, unofficial].
*   **Memory Complexity:** $O(W \times H)$ for the 480×300 internal framebuffer [S1, unofficial].
*   **Strengths:** Predictable cheap operations; direct `Uint32Array` buffer writes; hot loop uses only three integer multiplies and shifts per pixel [S1, unofficial].
*   **Limitations:** Restricted to 2D maps with vertical walls; requires integer upscaling with pixelated filtering [S1, unofficial].

### GPU-Based 3D Volume Raycasting
*   **Time Complexity:** Depends on the number of active bricks and ray marching steps per brick [S2, unofficial].
*   **Memory Complexity:** $O(V)$ for volume data and $O(B)$ for bricked data, where $V$ is voxels and $B$ is bricks [S2, unofficial].
*   **Strengths:** Leverages geometry shaders for active brick detection and ray generation; separates far/near position buffers for efficient compositing [S2, unofficial].
*   **Limitations:** Requires Direct3D 11 support; relies on geometry shader pipeline constraints [S2, unofficial].

## Background
The CPU-based approach traces its technical lineage to early FPS games like Wolfenstein 3D, which pioneered column-casting for pseudo-3D environments [S1, unofficial]. The GPU-based pipeline implements a multi-pass Direct3D 11 architecture for volumetric data, utilizing geometry shaders for spatial culling and ray marching [S2, unofficial].
