# Efficient Ray Casting Pipeline

Also called: EfficientRayCast, Raycasting Rendering Pipeline

## Overview
The Efficient Ray Casting Pipeline refers to two distinct implementations of raycasting techniques optimized for specific hardware and rendering constraints. The first is a CPU-based Wolfenstein 3D-style engine that casts one ray per screen column to render a 2.5D grid, writing directly to raw pixel buffers with minimal per-pixel arithmetic [S1, unofficial]. The second is a DirectX 11 GPU pipeline that uses geometry shaders for active brick detection and ray generation to render volumetric data, separating output, near/far positions, and debug visualization into distinct buffers [S2, unofficial]. Both methods prioritize predictable, cheap operations over complex mathematics to achieve high performance on their respective targets.

## How it works

### CPU-based Column Raycasting (Wolfenstein 3D Style)
This method renders a 2D grid map as a 3D perspective view by casting rays along screen columns.

**Inputs and Outputs:**
- **Input:** A 2D grid map (integer array representing walls/empty space), camera position $(x, y)$, camera direction angle $\theta$, screen height $H$, and screen width $W$ (number of columns).
- **Output:** A raw pixel buffer (e.g., `Uint32Array`) containing the final image.

**Data Structures:**
- **Map:** 2D integer array where non-zero values represent walls.
- **Pixel Buffer:** Linear array of size $W \times H$.

**Steps:**
1. **Initialize:** Set camera position $(x, y)$ and direction $\theta$. Define screen resolution $W \times H$.
2. **Loop Columns:** For each column $c$ from $0$ to $W-1$:
   a. **Calculate Ray Angle:** Compute the ray angle $\alpha$ for the current column relative to the camera direction.
      $$ \alpha = \theta + \arctan\left(\frac{c - W/2}{W/2}\right) $$
      [G] Note: The exact formula may vary based on field of view (FOV) definition. A common approximation for small FOV is $\alpha = \theta + (c - W/2) \cdot \frac{\text{FOV}}{W}$.
   b. **Voxel Traversal:** Use a fast voxel traversal algorithm (e.g., Amanatides & Woo [S3]) to find the first wall cell intersected by the ray.
      - Initialize step variables $dx, dy$ based on ray direction signs.
      - Initialize distance to next vertical/horizontal grid line $tX, tY$.
      - Initialize delta distances $dX, dY$.
      - Iterate until a wall cell is found.
   c. **Calculate Distance:** Compute the perpendicular distance $d$ from the camera to the hit wall to correct fisheye effect.
      $$ d = \text{dist} \cdot \cos(\alpha - \theta) $$
   d. **Calculate Wall Height:** Determine the height of the wall line to draw.
      $$ \text{lineHeight} = \frac{H}{d} $$
   e. **Draw Vertical Line:** Draw a vertical line of the calculated height centered on the column.
      - Start Y: $y_{start} = (H - \text{lineHeight}) / 2$.
      - End Y: $y_{end} = y_{start} + \text{lineHeight}$.
      - Write pixel colors directly to the buffer for rows $y_{start}$ to $y_{end}$.
      - Apply fog effect if applicable: multiply color by distance-based factor.

**Parameters:**
- **Resolution:** Internal framebuffer of 480x300 pixels [S1, unofficial].
- **Upscaling:** Integer scale factor applied to the internal framebuffer to fill the viewport using `image-rendering: pixelated` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Fisheye Effect:** Must be corrected by multiplying the distance by the cosine of the angle difference between the ray and the camera direction [S1, unofficial].
- **Precision:** Use integer arithmetic where possible for speed, as the hot loop involves only three integer multiplies and shifts per pixel [S1, unofficial].
- **Boundary Conditions:** Ensure ray traversal handles edge cases where the ray hits exactly on a grid line [S3].

### GPU-based Volume Raycasting (DirectX 11)
This method renders volumetric data using a multi-pass pipeline with geometry shaders.

**Inputs and Outputs:**
- **Input:** 3D volume texture, transfer function (1D/2D texture), camera matrices, brick volume data.
- **Output:** Final output texture, far/near position texture, debug visualization texture.

**Data Structures:**
- **Constant Buffer (`CB_EfficientRayCast_Frame`):**
  - `mInvView`: Inverse view matrix (XMMATRIX).
  - `mView`: View matrix (XMMATRIX).
  - `mViewProj`: View-projection matrix (XMMATRIX).
  - `f4ViewPos`: Camera position (XMFLOAT4).
  - `f2HalfWinSize`: Half window size (XMFLOAT2).
  - `f2WinReso`: Window resolution (XMFLOAT2).
  - `f2MinMaxDensity`: Density range constants (XMFLOAT2).
  - `NIU`: Normalization factor (float).
  - `NIU1`: Normalization factor + 1 (float).
- **Textures:**
  - `m_pVolTex`: Volume data texture.
  - `m_pBrickVolTex`: Brick volume texture.
  - `m_pFarNearTex`: Texture for storing near/far ray positions.
  - `m_pOutputTex`: Final output texture.
- **Shaders:**
  - `m_pActiveCellAndSOGS`: Geometry shader for active brick check and cube mesh generation.
  - `m_pRaymarchGS`: Geometry shader for ray casting.

**Steps:**
1. **Initialize:** Load volume data and transfer functions into GPU textures. Update constant buffers with camera and scene parameters.
2. **Reset Volumes:** Use compute shaders to reset data and flag volumes if necessary.
   - Dispatch compute shader with thread groups sized according to volume dimensions and brick ratio.
3. **Active Brick Detection:** Use `m_pActiveCellAndSOGS` geometry shader to identify active bricks (non-empty regions) in the volume.
   - Generate cube meshes for active bricks.
4. **Ray Generation and Marching:** Use `m_pRaymarchGS` geometry shader to cast rays through the active bricks.
   - For each pixel, calculate ray origin and direction.
   - March along the ray, sampling the volume texture.
   - Apply transfer function to convert density to color and opacity.
   - Accumulate color and opacity using front-to-back compositing.
5. **Output:** Write the final color and opacity to `m_pOutputTex`. Store near/far positions in `m_pFarNearTex` for debugging or further processing.

**Parameters:**
- **MIN_DENSITY, MAX_DENSITY:** Constants for density range, initialized in constructor [S2, unofficial].
- **Brick Ratio:** Ratio of brick size to voxel size, used to determine thread group sizes for flag volume reset [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Empty Bricks:** Ensure active brick detection correctly identifies empty regions to avoid unnecessary ray marching.
- **Precision:** Use appropriate data types for density and color values to maintain visual quality.
- **Memory Bandwidth:** Optimize texture sampling and memory access patterns to reduce bandwidth usage.

## Operating characteristics

### CPU-based Column Raycasting
- **Time Complexity:** $O(W \times H + N)$, where $W$ is screen width, $H$ is screen height, and $N$ is the number of visible sprites/walls. The rendering time depends on screen resolution and the number of visible sprites, not on the size of the map [S1, unofficial].
- **Memory Complexity:** $O(W \times H)$ for the pixel buffer.
- **Performance:** Very fast for 2D grid maps due to simple arithmetic and direct memory access. Suitable for real-time applications on low-end hardware.
- **Strengths:** Predictable performance, low memory usage, simple implementation.
- **Limitations:** Limited to 2.5D rendering, not suitable for complex 3D scenes or volumetric data.

### GPU-based Volume Raycasting
- **Time Complexity:** $O(W \times H \times L)$, where $L$ is the number of samples per ray. Performance depends on resolution, ray length, and volume density.
- **Memory Complexity:** $O(V)$ for volume data, where $V$ is the number of voxels.
- **Performance:** High performance on modern GPUs due to parallel processing. Suitable for real-time volumetric rendering.
- **Strengths:** Supports complex 3D scenes and volumetric data, high visual quality.
- **Limitations:** Requires powerful GPU, higher memory usage, complex implementation.

## Background

### CPU-based Column Raycasting
Originated from early 3D games like Wolfenstein 3D [S5, unofficial]. The technique was popularized by Lode Vandevenne's tutorial [S1, unofficial] and Fredrik Permadi's raycasting tutorial [S2, unofficial]. It is based on the Amanatides & Woo voxel traversal algorithm [S3, unofficial].

### GPU-based Volume Raycasting
Developed for DirectX 11, this pipeline leverages geometry shaders for efficient brick detection and ray generation. It is part of the DynamicVolumeRayCasting project by pengliu916 [S2, unofficial]. The method builds on shared principles of GPU-driven architecture, mapping rendering tasks to GPU execution units [Parent].
