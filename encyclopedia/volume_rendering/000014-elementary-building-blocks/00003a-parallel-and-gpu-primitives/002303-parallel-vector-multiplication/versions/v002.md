# Parallel Vector Multiplication

Also called: CUDA Vector Multiplication, OpenCL Parallel Vector Multiplication, Vector Add/Multiply Kernel

## Overview
Parallel Vector Multiplication is a fundamental GPU primitive where each thread independently multiplies corresponding elements from two input arrays to produce an output array [S1, unofficial]. It solves the problem of element-wise vector scaling or Hadamard product computation at massive scale by mapping one thread per data element [G]. It is distinct from sibling primitives like [Parallel Prefix Sum](2593-parallel-prefix-sum-scan-orchestration.md) (which requires inter-thread dependency) or [Atomic Fragment List Insertion](2465-atomic-fragment-list-insertion.md) (which requires synchronization), as it involves no communication between threads [G].

## How it works
**Inputs and Outputs:**
- Input: Two arrays of floating-point values, $A$ and $B$, of size $N$ [S2, unofficial].
- Output: One array $C$ of size $N$, where $C[i] = A[i] \times B[i]$ [S2, unofficial].

**Data Structures:**
- Arrays are stored in global memory [S2, unofficial].
- Data types: `global const float *` for inputs and `global float *` for output [S2, unofficial].
- Vector types `float2`, `float3`, `float4`, `float8`, and `float16` are supported to increase arithmetic throughput per instruction [S2, unofficial].
- In compressive rendering contexts, vectors may represent sampling matrices where $S^T S x$ operations insert 0 in the location of missing pixels [S1, unofficial].

**Steps:**
1. The GPU kernel is launched with a grid of threads sized to cover the entire vector length $N$ [G].
2. Each thread calculates its unique global index $id$ using `get_global_id(0)` [S2, unofficial].
3. The thread reads $A[id]$ and $B[id]$ from global memory [S2, unofficial].
4. The thread computes the product $P = A[id] \times B[id]$ [S2, unofficial].
5. The thread writes $P$ to $C[id]$ in global memory [S2, unofficial].

**Pseudocode:**
```python
def vector_multiply_kernel(global_id, a, b, c, n):
    # 1. Retrieve global unique ID
    id = global_id
    # 2. Bounds check to prevent out-of-bounds access
    if id < n:
        # 3. Load inputs from global memory
        val_a = a[id]
        val_b = b[id]
        # 4. Multiply
        result = val_a * val_b
        # 5. Store output to global memory
        c[id] = result
```

**Parameters:**
- **Vector Width:** Vector types `float2`, `float3`, `float4`, `float8`, and `float16` are supported, with arithmetic operations on these types being as fast or faster than scalar floats [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Boundaries:** If $N$ is not a multiple of the grid size, a bounds check is required [G].
- **Missing Pixels:** In compressive rendering contexts, "multiplication" may involve sparse matrices where missing pixels are treated as zero [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of elements [G].
- **Memory Complexity:** $O(N)$ for input and output arrays [G].
- **Performance:** Massive calculations (e.g., $S^T S x$ in compressive rendering) complete in a few milliseconds using CUDA [S1, unofficial]. Modern GPUs feature between 16 and 480 stream processors, with adding processors halving calculation time [S2, unofficial].
- **Strengths:** Extremely high throughput for independent element-wise operations with minimal synchronization overhead [G].
- **Limitations:** Does not handle dependencies between elements, and memory bandwidth becomes the primary bottleneck due to low arithmetic intensity [G].

## Background
The method originates from early GPU computing frameworks like CUDA and OpenCL, leveraging the SIMT (Single Instruction, Multiple Threads) architecture [G]. It is used in compressive rendering for applying large sampling matrices [S1, unofficial]. It also accelerates raycasting and raytracing by distributing independent pixel calculations across multiprocessors [S2, unofficial].

## Subtopics

### Tiled Parallel Compositing
Groups pixels into tiles to reduce memory latency and enable shared memory usage [G]. It differs from global compositing by optimizing cache locality and is chosen for high-resolution volumes [G]. [Tiled Parallel Compositing](1192-tiled-parallel-compositing.md)

### Parallel Direct Compositing
Computes final pixel colors directly without intermediate buffers [G]. It avoids the overhead of fragment lists and is chosen for simple transparency models [G]. [Parallel Direct Compositing](3201-parallel-direct-compositing.md)

### Subgroup Operations
Executes instructions across hardware subgroups to share data without global memory [G]. It differs from thread-level primitives by enabling fast intra-group communication and is chosen for reductions or shuffles [G]. [Subgroup Operations](3683-subgroup-operations.md)
