# Y-Bucket Parallelization

Also called: Y-bucket grouping

## Overview
Y-Bucket Parallelization is a two-pass parallel algorithm for direct volume rendering that processes polygonal representations of isosurfaces or volume slices by grouping them into scanline-based "y-buckets" [S1]. It solves the problem of efficiently rendering irregular and multiple grids in software by maximizing spatial coherence and avoiding the computational difficulties associated with ray-casting intersecting cells [S1]. Unlike tile-based parallelization methods that break scanlines and lose coherence, this method parallelizes on a scanline basis to limit duplication [S1].

## How it works
The method operates on polygonal data representing volume slices or isosurfaces. The polygons are stored in counter-clockwise order when viewed from outside the grid, allowing the system to easily recognize boundaries and the last polygon in its grid within the visibility order [S1].

**Inputs:**
- A set of polygons representing the volume data.
- A set of processors (or threads).
- The image resolution (width and height).

**Outputs:**
- A rendered image.

**Data Structures:**
1.  **Y-Bucket Array:** An array indexed by scanline (y-coordinate). Each entry stores the count of polygons intersecting that scanline.
2.  **Output Array:** A common output array partitioned to store the final pixel values.
3.  **X-Bucket Structures:** Associated with the leftmost pixel of a polygon's bounding box on a scanline. Contains a linked list of active polygons in front-to-back visibility order.

**Steps:**

1.  **First Pass: Polygon Distribution**
    -   Each processor iterates through the input polygons.
    -   For each polygon, determine the range of scanlines (y-coordinates) it intersects.
    -   Increment the counter in the Y-Bucket Array for each intersected scanline.
    -   Store the polygon in a temporary structure associated with its corresponding y-bucket, marking it as processed.

2.  **Second Pass: Bucket Allocation and Structure Creation**
    -   Access the Y-Bucket Array to determine the number of polygons belonging to each y-bucket.
    -   Allocate space for each y-bucket by partitioning the common output array.
    -   Partition the space for one y-bucket further into space for each processor to fill within that y-bucket.
    -   Each processor creates appropriate y-bucket structures for all polygons it processed in the first pass, excluding any that were invalidated.
    -   *Note:* The work per processor in this step is proportional to the number of scanlines, not the number of polygons [S1].

3.  **Third Pass: Scanline Processing**
    -   Process each scanline in order from bottom to top.
    -   For each scanline, transfer information for each active polygon to an x-bucket data structure associated with the leftmost pixel in which the polygon appears.
    -   Maintain a linked list of these x-bucket structures in front-to-back visibility order.
    -   Perform the compositing computation for the pixels in the scanline using the active polygons in the x-buckets.

## Subtopics

### [Parallel Direct Volume Rendering with Y-Buckets and X-Buckets](2123-parallel-direct-volume-rendering-with-y-buckets-and-x-bucket.md)
This method is a parallel direct volume rendering algorithm that processes polygons representing isosurfaces or volume slices by grouping them into scanline-based 'y-buckets' and processing pixels within those buckets using 'x-buckets' and 'x-actives' lists to maintain front-to-back visibility order. It solves the problem of rendering irregular and multiple grids efficiently in software by maximizing coherence and avoiding the difficulties of ray-casting intersecting cells. Unlike tile-based parallelization methods that break scanlines and lose coherence, this method parallelizes on a scanline basis to limit duplication.

## Operating characteristics
-   **Time Complexity:** The first pass is proportional to the number of polygons. The second pass is proportional to the number of scanlines. The third pass is proportional to the number of active polygons per scanline.
-   **Memory Complexity:** Proportional to the number of scanlines and the number of polygons.
-   **Strengths:** Maximizes coherence by processing scanlines, limiting duplication compared to tile-based methods. Efficient for irregular and multiple grids.
-   **Limitations:** The second pass is a transitional step. Requires careful management of polygon visibility order.
-   **When to Use:** When rendering irregular and multiple grids in software, and maximizing coherence is critical.
-   **When Not to Use:** When hardware acceleration is available and tile-based methods are more suitable.
