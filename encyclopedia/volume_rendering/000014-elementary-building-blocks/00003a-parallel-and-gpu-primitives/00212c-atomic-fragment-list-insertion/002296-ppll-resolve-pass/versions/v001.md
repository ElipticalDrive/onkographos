# PPLL Resolve Pass
Also called: Parallel Prefix List List Resolve
## Overview
The PPLL Resolve Pass is a fragment shader pass that resolves a linked list of fragments per pixel into a final color by sorting and front-to-back blending [S1, unofficial]. It takes the raw fragment data collected by the [Atomic Fragment List Insertion](2465-atomic-fragment-list-insertion.md) method and produces the final image, distinguishing itself from sibling methods like [A-buffer linked-list creation and ray processing](3878-a-buffer-linked-list-creation-and-ray-processing.md) by relying on a global atomic counter for list construction and a subsequent CPU/GPU synchronization to resolve the lists via sorting and blending [S1, unofficial].
## How it works
### Inputs and Outputs
**Inputs:**
- `uStartOffsetTex`: A texture storing the head pointer (fragment index) for each pixel. Initialized to `0xFFFFFFFFu` (end of list) by the Clear Pass.
- `uFragmentBufferTex`: A texture storing the fragment nodes. Layout is `RGBA32UI` with dimensions `FRAG_BUFFER_W` × `FRAG_BUFFER_H`.
- `uViewportW`, `uViewportH`: Viewport dimensions.
- `FRAG_BUFFER_W`: Width of the fragment buffer texture (constant, typically 2048).
- `MAX_NUM_FRAGS`: Maximum number of fragments to process per pixel (constant, typically 32).

**Outputs:**
- `gl_FragColor`: The final color for the current pixel.

### Data Structures
- **Per-pixel local storage:**
  - `colorList[MAX_NUM_FRAGS]`: Array of `uint` storing packed fragment colors.
  - `depthList[MAX_NUM_FRAGS]`: Array of `float` storing fragment depths.
  - Total size: $32 \times 12$ bytes = 384 bytes.

### Steps
1. **Boundary Check:** Get pixel coordinates `x`, `y`. If `x >= uViewportW` or `y >= uViewportH`, discard.
2. **Load Head:** Load the starting offset (head pointer) from `uStartOffsetTex` at `(x, y)` into `fragOffset`.
3. **Initialize:** Set `numFrags = 0`.
4. **Traverse List:** Loop `i` from 0 to `MAX_NUM_FRAGS - 1`:
   - If `fragOffset == 0xFFFFFFFFu`, break (end of list).
   - Calculate address `ivec2(int(fragOffset) % FRAG_BUFFER_W, int(fragOffset) / FRAG_BUFFER_W)`.
   - Load `frag` from `uFragmentBufferTex` at the calculated address.
   - Update `fragOffset = frag.b` (the next pointer).
   - Store `frag.r` in `colorList[i]`.
   - Store `uintBitsToFloat(frag.g)` in `depthList[i]`.
   - Increment `numFrags`.
5. **Empty Check:** If `numFrags == 0`, discard.
6. **Sort:** Insertion sort `colorList` and `depthList` by `depthList` ascending.
   - Loop `i` from 1 to `numFrags - 1`:
     - Store `fragColor = colorList[i]`, `fragDepth = depthList[i]`.
     - Loop `j` from `i` down to 1:
       - If `depthList[j-1] > fragDepth`, shift `colorList[j-1]` to `colorList[j]` and `depthList[j-1]` to `depthList[j]`.
       - Decrement `j`.
     - Place `fragColor` and `fragDepth` at `j`.
7. **Blend:** Initialize `outColor = vec4(0.0)`.
   - Loop `i` from 0 to `MAX_NUM_FRAGS - 1`:
     - If `i >= numFrags`, break.
     - Unpack `src = unpackColor(colorList[i])`.
     - Update `outColor.rgb = outColor.rgb + (1.0 - outColor.a) * src.a * src.rgb`.
     - Update `outColor.a = outColor.a + (1.0 - outColor.a) * src.a`.
     - If `outColor.a > 0.995`, break (early-out optimization).
8. **Convert:** If `outColor.a > 1e-4`, divide `outColor.rgb` by `outColor.a` (premultiplied to straight alpha conversion).
9. **Output:** Output `outColor` to `gl_FragColor`.

### Pseudocode
```python
# Pseudocode for PPLL Resolve Pass
# Assumes access to texture fetch functions and standard math operations

def resolve_pass(x, y):
    if x >= uViewportW or y >= uViewportH:
        return None

    # Load head pointer
    frag_offset = texel_fetch(uStartOffsetTex, ivec2(x, y)).r
    
    num_frags = 0
    color_list = [0] * MAX_NUM_FRAGS
    depth_list = [0.0] * MAX_NUM_FRAGS

    # Traverse linked list
    i = 0
    while i < MAX_NUM_FRAGS and frag_offset != 0xFFFFFFFFu:
        # Calculate buffer address
        buf_x = frag_offset % FRAG_BUFFER_W
        buf_y = frag_offset / FRAG_BUFFER_W
        
        frag = texel_fetch(uFragmentBufferTex, ivec2(buf_x, buf_y))
        
        # Extract next pointer
        frag_offset = frag.b
        
        # Store color and depth
        color_list[i] = frag.r
        depth_list[i] = uint_bits_to_float(frag.g)
        
        i += 1
        num_frags += 1

    if num_frags == 0:
        return None

    # Insertion sort by depth
    for i in range(1, num_frags):
        frag_color = color_list[i]
        frag_depth = depth_list[i]
        
        j = i
        while j > 0 and depth_list[j-1] > frag_depth:
            color_list[j] = color_list[j-1]
            depth_list[j] = depth_list[j-1]
            j -= 1
            
        color_list[j] = frag_color
        depth_list[j] = frag_depth

    # Front-to-back blending
    out_color = vec4(0.0)
    
    for i in range(num_frags):
        src = unpack_color(color_list[i])
        
        out_color.rgb = out_color.rgb + (1.0 - out_color.a) * src.a * src.rgb
        out_color.a = out_color.a + (1.0 - out_color.a) * src.a
        
        if out_color.a > 0.995:
            break

    # Premultiplied to straight alpha
    if out_color.a > 1e-4:
        out_color.rgb = out_color.rgb / out_color.a

    return out_color
```

### Parameters
- `MAX_NUM_FRAGS`: Maximum number of fragments to process per pixel. Typical value: 32 [S1, unofficial].
- `FRAG_BUFFER_W`: Width of the fragment buffer texture. Typical value: 2048 [S1, unofficial].

### Edge Cases and Pitfalls
- **Early-out optimization:** The blend loop breaks if `outColor.a > 0.995` to save computation when the pixel is effectively opaque [S1, unofficial].
- **Empty list handling:** If no fragments are collected (`numFrags == 0`), the fragment is discarded [S1, unofficial].
- **Buffer Full:** If the fragment buffer is full, fragments are silently dropped during the gather phase, which may result in missing fragments in the resolve pass [S1, unofficial].
- **Precision:** Depth is stored as `uintBitsToFloat(frag.g)`, implying a specific bit-packing scheme for depth in the fragment node [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ or $O(N^2)$ depending on the sort implementation. The provided method uses insertion sort, which is $O(N^2)$ in the worst case, but efficient for small $N$ (e.g., $N=32$). The traversal is $O(N)$.
- **Memory Complexity:** $O(N)$ per pixel for local storage, where $N = MAX\_NUM\_FRAGS$.
- **Strengths:** Simple implementation, efficient for low fragment counts per pixel.
- **Limitations:** Insertion sort becomes inefficient for high fragment counts. The global atomic counter approach can lead to buffer overflow if not managed carefully.
- **When to use:** Suitable for scenes with moderate fragment density per pixel.
- **When not to use:** Not suitable for scenes with very high fragment density per pixel where sorting overhead becomes significant.

## Background
The PPLL Resolve Pass is part of the Parallel Prefix List List (PPLL) method for volume rendering. It was described in the context of a WebGL2-based volume renderer [S1, unofficial]. The method relies on atomic operations for fragment list construction and a subsequent resolve pass for final color computation.
