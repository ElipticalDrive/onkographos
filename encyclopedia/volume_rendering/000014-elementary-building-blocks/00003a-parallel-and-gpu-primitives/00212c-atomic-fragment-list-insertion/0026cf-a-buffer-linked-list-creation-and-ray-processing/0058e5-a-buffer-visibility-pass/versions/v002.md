# A-Buffer Visibility Pass

Also called: Approximate Visibility Function Generation, Approximate Visibility Pass, Deep Shadow Map Generation, GPU Visibility Pass, Visibility Pass (A-Buffer), Visibility Pass Implementation, Visibility buffer generation

## Overview
The A-Buffer Visibility Pass is a GPU fragment-stage algorithm that generates an approximate visibility function $\tilde{v}(x_e, x)$ for each view ray by storing depth and visibility control points in an A-Buffer [S1, unofficial]. It solves the problem of efficiently representing volumetric occlusion along semi-transparent view rays to enable optimized illumination calculations, such as determining entry points for light rays or approximating multiple scattering [S1, unofficial]. Unlike sibling methods that focus on primitive intersection or general buffer construction, this method specifically targets the generation of a sparse, error-thresholded visibility function using a fixed maximum number of layers, similar in concept to deep shadow maps but applied to view-space volumetric visibility [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Volumetric data (voxels with color/opacity), camera ray definition (origin, direction, length), A-Buffer storage structure, error threshold for accumulated opacity difference, maximum layer count [S1, unofficial].
*   **Output:** An A-Buffer containing control points (depth $d$, visibility $v$) for each pixel, and textures storing the first and last hit points of the volume traversal [S1, unofficial].

**Data Structures:**
*   **A-Buffer:** A 2D texture array [S1, unofficial].
    *   Each texture in the array corresponds to a specific layer index (up to a maximum of 32) [S1, unofficial].
    *   Each texture has two channels:
        1.  Depth to camera ($d$) in volume space.
        2.  Visibility ($v$), defined as $1 - \text{accumulated opacity}$ [S1, unofficial].
*   **Hit Point Textures:** Two separate textures storing the first and last hit points (coordinates) for each ray [S1, unofficial].

**Parameters:**
*   **Maximum Layers:** 32 [S1, unofficial].
*   **Sampling Frequency:** One sample per voxel during the unshaded raycasting pass [S1, unofficial].
*   **Storage Threshold:** An error threshold for the difference in accumulated opacity; a new control point is added when this threshold is exceeded [S1, unofficial].

**Algorithm Steps:**
1.  **Ray Definition:** Define a ray from front to back (from the camera) for each pixel [S1, unofficial].
2.  **Ray Marching:** Iterate through all samples $s$ along the ray at a frequency of one sample per voxel [S1, unofficial].
3.  **Voxel Classification:** Read and classify the voxel at sample $s$ to obtain color and opacity $c$ [S1, unofficial].
4.  **Compositing:** If the opacity in $c$ is greater than 0, perform front-to-back compositing along the ray into the accumulated result $r$ [S1, unofficial].
5.  **Threshold Check:** If the difference in accumulated opacity exceeds the a-buffer storage threshold:
    a.  Calculate the distance to the camera $d$ in volume space [S1, unofficial].
    b.  Calculate the visibility $v = 1 - r.a$, where $r.a$ is the accumulated opacity [S1, unofficial].
    c.  **Buffer Management:** If the A-Buffer is full (reached maximum layers):
        i.  Perform an iterative merging process to decimate existing control points. Remove the control point that introduces the smallest difference to make room for the new point [S1, unofficial].
    d.  Store $v$ and $d$ as the next entry in the A-Buffer [S1, unofficial].
    e.  Write the visibility value $lv$ to the write cache [S1, unofficial].
6.  **Termination Check:** Determine the next position. If the end of the ray is reached or the accumulated opacity is considered opaque, end the loop [S1, unofficial].
7.  **Hit Point Storage:** After the loop, write the first and last hit points into two separate textures [S1, unofficial].

**Pseudocode:**
```python
def visibility_pass(ray_origin, ray_direction, voxel_size, ray_length, threshold, max_layers, width, height):
    # A-Buffer: 2D texture array [width, height, max_layers]
    # Channel 0: depth d, Channel 1: visibility v
    a_buffer = [[[[0.0, 0.0] for _ in range(max_layers)] for _ in range(height)] for _ in range(width)]
    first_hit_texture = [[None for _ in range(height)] for _ in range(width)]
    last_hit_texture = [[None for _ in range(height)] for _ in range(width)]
    write_cache = []
    
    for y in range(height):
        for x in range(width):
            pixel_coord = (x, y)
            current_layer = 0
            acc_opacity = 0.0
            prev_acc_opacity = 0.0
            first_point_added = True
            first_hit = None
            last_hit = None
            
            num_samples = int(ray_length / voxel_size)
            for i in range(num_samples):
                t = i * voxel_size
                sample_pos = (ray_origin[0] + ray_direction[0] * t,
                              ray_origin[1] + ray_direction[1] * t,
                              ray_origin[2] + ray_direction[2] * t)
                
                # Read/classify voxel at s to color/opacity c [G] standard volume access
                c_opacity = 0.0
                if is_inside_volume(sample_pos):
                    c_opacity = get_voxel_opacity(sample_pos)
                
                if c_opacity > 0.0:
                    # Perform compositing front-to-back along ray into r
                    acc_opacity = 1.0 - (1.0 - acc_opacity) * (1.0 - c_opacity)
                    
                    # Check difference in accumulated opacity against threshold
                    opacity_diff = acc_opacity - prev_acc_opacity
                    
                    if opacity_diff > threshold:
                        # Calculate distance to camera d (volume space)
                        d = t
                        # Calculate visibility v = 1 - r.a
                        v = 1.0 - acc_opacity
                        
                        # If a-buffer is full, merge smallest threshold distance
                        if current_layer >= max_layers:
                            # [G] Standard decimation: find adjacent pair with smallest visibility/depth error and remove the middle point
                            merge_control_points(a_buffer, pixel_coord, current_layer, max_layers)
                        else:
                            current_layer += 1
                        
                        # Store v and d as next entry in a-buffer
                        # The first control point of the visibility function is not stored [S1, unofficial]
                        if first_point_added:
                            first_point_added = False
                        else:
                            a_buffer[x][y][current_layer - 1][0] = d
                            a_buffer[x][y][current_layer - 1][1] = v
                        
                        # Write lv to write cache [S1, unofficial]
                        write_cache.append(v)
                        
                        # Track hit points
                        if first_hit is None:
                            first_hit = sample_pos
                        last_hit = sample_pos
                        
                        prev_acc_opacity = acc_opacity
                    
                    # Termination check: end of ray or accumulated opacity considered opaque
                    if acc_opacity >= 1.0:
                        break
                        
            first_hit_texture[x][y] = first_hit
            last_hit_texture[x][y] = last_hit
```

**Edge Cases and Pitfalls:**
*   **Buffer Fullness:** If the visibility map is full when a new control point is needed, an iterative merging process is used [S1, unofficial]. This increases computation time if peak finding is used for higher accuracy [S1, unofficial].
*   **First Control Point:** The first control point of the visibility function is not stored because the first hit point results in the first visibility change [S1, unofficial].
*   **Precision:** Using peak finding similar to [48] increases accuracy but also increases computation time [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The base pass is $O(N)$ per ray where $N$ is the number of voxels sampled (one sample per voxel) [S1, unofficial]. The merging process adds overhead when the buffer is full, potentially increasing complexity depending on the number of merges required [S1, unofficial]. Peak finding can further increase computation time [S1, unofficial].
*   **Memory Complexity:** $O(W \times H \times L)$ where $W, H$ are image dimensions and $L$ is the maximum number of layers (32) [S1, unofficial]. Each layer stores 2 channels (depth, visibility) [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Allows representation of transparency effects from high depth complexity with a low number of control points [S1, unofficial]. Enables optimized entry points for light rays by projecting first/last hit points into light space [S1, unofficial].
*   **Limitations:** Approximate nature may lose detail if the number of layers is too low or threshold is too high. Merging process can be computationally expensive [S1, unofficial].

*   **When not to use:** Not given in the sources.

## Background
The A-Buffer Visibility Pass is based on the work of Sundén et al. in "Multimodal Volume Illumination" (2015) [S1, unofficial]. It builds on the concept of approximate visibility functions using a low number of control points, as shown by Salvi et al. [39, cited in S1, unofficial]. The method is similar to deep shadow maps [52, cited in S1, unofficial] but applies the A-Buffer concept to view-space volumetric visibility rather than shadow occlusion. It is used in multimodal volume rendering to account for multiple scattering effects and to optimize illumination computations by providing entry points for light rays [S1, unofficial].
