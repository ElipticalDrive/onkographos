# GPU A-Buffer Construction for Ray-Primitive Intersection

Also called: Dynamic Data Structure for Ray Processing, Dynamic Linked List for Primitive Supports, Sphere-Cone A-Buffer

## Overview
This method constructs a dynamic acceleration structure (A-buffer) on the GPU to efficiently identify which segment primitives overlap a given ray, avoiding the evaluation of empty space in expensive field computations [S1]. It differs from brute-force ray marching by using a geometry shader to generate quads covering primitive supports and a fragment shader to compute ray-support intersections, storing entry/exit points in a linked list [S1]. Unlike [Bru19], which requires explicit cutoff of primitive influences, this approach leverages compact support kernels (specifically clipped sphere-cones for Cauchy kernels) to naturally limit the interaction domain [S1].

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].
- Skeleton segment primitives, each defined by a center line segment and a radius function (potentially varying) [S1].
- Kernel parameters: For Cauchy kernels, a clipping scaling factor $\sigma_{\text{clipping}}$ is computed to guarantee a maximal error $\varepsilon_{\text{clipping}}$ [S1].

**Outputs:**
- A linked list per ray containing sorted entry and exit points of the ray within each primitive's support, along with the associated primitive ID [S1].

**Data Structures:**
- **A-Buffer Linked List:** Stores tuples of $(t_{\text{entry}}, t_{\text{exit}}, \text{primitive\_id})$ sorted by $t_{\text{entry}}$ [S1].
- **Quad:** Generated per skeleton segment to cover the projected primitive support. The quad is segment-aligned [S1].

**Steps:**
1. **Geometry Shader Execution:** For each skeleton segment, generate a quad that covers the projected support of the primitive [S1]. The quad is computed using the method from [SWBG06], adapted for segment-aligned quads to minimize fragment generation, particularly for primitives with small radii relative to segment length [S1].
2. **Fragment Shader Execution:** For each fragment generated by the quad, compute the intersection of the ray with the primitive's support (a sphere-cone) [S1].
3. **Intersection Calculation:** Determine the entry ($t_{\text{entry}}$) and exit ($t_{\text{exit}}$) points of the ray within the support [S1].
4. **Atomic Insertion:** Insert the tuple $(t_{\text{entry}}, t_{\text{exit}}, \text{primitive\_id})$ into the A-buffer linked list for the current ray using atomic operations [S1].
5. **Sorting:** Sort the fragments in the linked list on the fly according to the depth of the entry point $t_{\text{entry}}$ [S1].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision in intersection calculations may affect the accuracy of $t_{\text{entry}}$ and $t_{\text{exit}}$, potentially leading to gaps or overlaps in the linked list [G].
- **Boundary Conditions:** Ensure that the quad generation covers the entire support, especially for primitives with varying radii [S1].
- **Degenerate Input:** Handle cases where the ray is parallel to the segment or the support is degenerate (e.g., zero radius) [G].

## Operating characteristics
- **Time Complexity:** The construction time is correlated with the number of primitives influencing a given point along the ray [S1]. The use of a compact support kernel reduces the number of primitives to consider, improving performance [S1].
- **Memory Complexity:** The A-buffer stores entry/exit points and primitive IDs for each ray. The memory usage depends on the number of overlapping primitives per ray [S1].
- **Strengths:** Efficiently avoids processing empty areas and limits compulsory field evaluations [S1]. The use of compact support kernels simplifies the A-buffer construction by avoiding explicit cutoff of primitive influences [S1].
- **Limitations:** The performance is highly correlated with the number of primitives influencing a given point [S1]. The method may require significant memory for rays with many overlapping primitives [G].
- **When to Use:** Suitable for large skeletons with compact kernels where field evaluations are expensive [S1].

## Background
The method extends the approach proposed by [Bru19], which relies on a dynamic data structure efficiently rebuilt at each frame using the GPU rendering pipeline [S1]. The original approach used a GPU-based quadric visualization algorithm [SWBG06] to compute a linked list of intersection points with supports of each primitive [S1]. This extension adapts the method for segment primitives with varying radius, specifically handling sphere-cone supports [S1]. The use of compact support kernels, such as the Cauchy kernel, allows for the clipping of primitive supports by a sphere-cone, ensuring a maximal error $\varepsilon_{\text{clipping}}$ [S1].
