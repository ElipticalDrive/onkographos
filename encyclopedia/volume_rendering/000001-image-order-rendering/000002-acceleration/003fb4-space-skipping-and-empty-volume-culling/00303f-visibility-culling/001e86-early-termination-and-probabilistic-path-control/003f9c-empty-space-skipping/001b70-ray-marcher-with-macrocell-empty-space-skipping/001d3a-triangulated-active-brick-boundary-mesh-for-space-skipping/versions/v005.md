# Triangulated Active Brick Boundary Mesh for Space Skipping

Also called: Active Brick Boundary Mesh, Triangulated Active Region Boundary Geometry, Triangulated Active Region Boundary Geometry for RTX Space Skipping

## Overview
A GPU-accelerated space-skipping technique for structured volume rendering that replaces clustered proxy boxes with a triangle mesh bounding the surface between active and inactive macrocells [S1, S2][S3, unofficial]. It differs from sibling methods by generating the boundary mesh entirely on the GPU, avoiding host-to-device transfers and user-defined intersection programs, and leveraging native hardware-accelerated triangle intersection to reduce depth complexity and warp divergence [S1, S2].

## How it works
**Inputs:**
- Input volume dimensions $V_x \times V_y \times V_z$ (voxels) [S1].
- Brick size $K$ (default 16, also 8 or 32) [S1, S2][S3, unofficial].
- Transfer function (TF) defining active/inactive regions [S1][S3, unofficial].
- OptiX 7.2 (or equivalent DXR/VKR) runtime [S1, S2][S3, unofficial].

**Outputs:**
- Rendering intervals $[t_0, t_1]$ for volume integration [S2][S3, unofficial].
- Final pixel color [G].

**Data Structures:**
1. **Macrocell Grid:** 3D grid of size $M_x \times M_y \times M_z$, where $M_x = \lceil V_x / K \rceil$, $M_y = \lceil V_y / K \rceil$, $M_z = \lceil V_z / K \rceil$ [S1][S3, unofficial]. Each cell stores $\{min\_val, max\_val\}$ of all input voxels mapping to it [S1, S2][S3, unofficial]. Computed on host, uploaded to GPU [S1, S2][S3, unofficial].
2. **Active Bricks Mask:** Boolean grid of size $M_x \times M_y \times M_z$ on GPU. `active[i][j][k]` is true if the macrocell's value range maps to any non-zero alpha in the TF [S1, S2][S3, unofficial].
3. **Vertex Array:** Pre-allocated device array of `float3` vertices. Size $N_{vtxMax} = (M_x + 1) \times (M_y + 1) \times (M_z + 1)$ [S1, S2][S3, unofficial]. Contains all possible macrocell grid vertices [S1, S2][S3, unofficial].
4. **Triangle Index Array:** Pre-allocated device array of `int3` indices. Size $N_{triMax}$ (upper bound derived from boundary geometry on macrocell faces) [S1, S2][S3, unofficial].
5. **numTriangles Counter:** Single device-side integer, initialized to 0. Used as atomic offset for writing triangles [S1, S2][S3, unofficial].

**Steps:**
1. **Initial Setup:** Build macrocell grid on host. Upload to GPU. Allocate GPU memory for Active Bricks Mask, Vertex Array, Triangle Index Array, and `numTriangles` counter [S1, S2][S3, unofficial].
2. **Active Cell Classification (Rebuild Step 1):** Launch CUDA kernel. Each thread maps to one macrocell $(i, j, k)$ [S1, S2][S3, unofficial]. Thread checks if `macrocell_grid[i][j][k].min_val` to `macrocell_grid[i][j][k].max_val` intersects the non-zero alpha range of the current TF [S1, S2][S3, unofficial]. Write result to `active_cells[i][j][k]` [S1, S2][S3, unofficial].
3. **Boundary Triangle Generation (Rebuild Step 2):** Reset `numTriangles` to 0 [S1, S2][S3, unofficial]. Launch three templated CUDA kernels (for X, Y, Z orientations) [S1, S2][S3, unofficial]. For each orientation, threads map to faces perpendicular to that axis [S1, S2][S3, unofficial]. For a face between `curr` and `prev` macrocells: if `active_cells[prev] == active_cells[curr]`, return [S1, S2][S3, unofficial]. Compute indices of four vertices spanning the face [S1, S2][S3, unofficial]. Atomically increment `numTriangles` by 2 [S1, S2][S3, unofficial]. Write two triangle indices to `triangles` buffer at offset `numTriangles - 2` [S1, S2][S3, unofficial]. Winding order points away from active to inactive cell [S1, S2][S3, unofficial]. Download `numTriangles` to host [S1, S2][S3, unofficial].
4. **BVH Rebuild (Rebuild Step 3):** Update OptiX triangle geometry to reference the generated mesh (triangle count and index array pointer) [S1, S2][S3, unofficial]. Ask OptiX to rebuild BVH with 'optimize for traversal' flag [S1, S2][S3, unofficial]. Compact BVH to conserve memory [S1, S2][S3, unofficial].
5. **Space Skipping during Rendering:** Trace ray against boundary mesh [S1, S2][S3, unofficial]. **Closest Hit:** Record hit distance $t_{hit}$ and hit kind (front/back) [S1, S2][S3, unofficial]. **No Hit:** Terminate ray (no active regions) [S1, S2][S3, unofficial]. **Back-Facing Hit:** Ray is inside volume. Integration interval is $[0, t_{hit}]$ [S1, S2][S3, unofficial]. **Front-Facing Hit:** Ray enters volume at $t_0 = t_{hit}$. Trace again with $ray.t_{min}=t_0$ to find exit distance $t_1$ [S1, S2][S3, unofficial]. Integrate volume over $[t_0, t_1]$ using gradient shading and early ray termination [S2][S3, unofficial]. If early termination, return. Otherwise, iterate: trace new ray from $t_1$ to find next segment [S1, S2][S3, unofficial].

**Pseudocode:**
```python
def get_quad_indices(face_coord, dim, Mx, My, Mz):
    """Returns 4 vertex indices spanning the macrocell face perpendicular to `dim`."""
    x, y, z = face_coord
    if dim == 0:  # X-face
        return [(x, y, z), (x, y+1, z), (x, y+1, z+1), (x, y, z+1)]
    elif dim == 1:  # Y-face
        return [(x, y, z), (x+1, y, z), (x+1, y, z+1), (x, y, z+1)]
    else:  # Z-face
        return [(x, y, z), (x+1, y, z), (x+1, y+1, z), (x, y+1, z)]

def generate_boundary_mesh(active_cells, num_triangles, triangles, Mx, My, Mz, dim):
    """Simulates the CUDA kernel for one dimension."""
    for i in range(Mx + 1):
        for j in range(My + 1):
            for k in range(Mz + 1):
                curr = (i, j, k)
                if dim == 0: prev = (i - 1, j, k)
                elif dim == 1: prev = (i, j - 1, k)
                else: prev = (i, j, k - 1)
                
                # Boundary check: treat out-of-bounds as inactive
                if not (0 <= prev[0] < Mx and 0 <= prev[1] < My and 0 <= prev[2] < Mz):
                    prev_active = False
                else:
                    prev_active = active_cells[prev]
                
                curr_active = active_cells[curr]
                
                if prev_active == curr_active:
                    continue
                
                vi = get_quad_indices(curr, dim, Mx, My, Mz)
                tri_id = num_triangles[0]
                num_triangles[0] += 2
                
                if prev_active:
                    triangles[tri_id] = (vi[0], vi[1], vi[2])
                    triangles[tri_id + 1] = (vi[0], vi[2], vi[3])
                else:
                    triangles[tri_id] = (vi[1], vi[0], vi[2])
                    triangles[tri_id + 1] = (vi[2], vi[0], vi[3])

def render_ray(ray_origin, ray_direction, boundary_mesh, tf, volume_texture, dt=0.5):
    """Space skipping and volume integration loop."""
    t_min = 0.0
    while True:
        hit = trace_against_mesh(ray_origin, ray_direction, t_min)
        if hit is None:
            break
        
        t_hit = hit.distance
        is_back_facing = hit.kind == 'BACK'
        
        if is_back_facing:
            t_end = t_hit
            integrate_volume(ray_origin, ray_direction, t_min, t_end, tf, volume_texture, dt)
            if early_termination_reached():
                return
            t_min = t_end
        else:
            t_enter = t_hit
            exit_hit = trace_against_mesh(ray_origin, ray_direction, t_enter)
            if exit_hit is None:
                break
            t_exit = exit_hit.distance
            integrate_volume(ray_origin, ray_direction, t_enter, t_exit, tf, volume_texture, dt)
            if early_termination_reached():
                return
            t_min = t_exit
```

**Parameters:**
- $K$: Brick size (8, 16, 32). Default 16 [S1, S2][S3, unofficial].
- $dt$: Fixed sampling rate for volume integration (0.5) [S2][S3, unofficial].
- Interleaved Sampling: Used to reduce aliasing [S2].

**Edge Cases and Pitfalls:**
- **Boundary Faces:** Faces on the outside of the volume have indices mapping outside the macrocell grid. These are treated as inactive macrocells to ensure correct boundary detection [S1, S2][S3, unofficial].
- **Winding Order:** Must point away from active to inactive cell for correct front/back face detection [S1, S2][S3, unofficial].
- **Unused Vertices:** Pre-allocating all possible vertices results in unused vertices, accepted as memory cost [S1, S2][S3, unofficial].
- **Warp Divergence:** Reduced by lowering depth complexity to transitions between active/inactive regions [S1, S2][S3, unofficial].
- **Timings less than 1ms:** Should be considered with caution and interpreted as 'less than one millisecond' [S3, unofficial].

## Subtopics

### [RTX-Accelerated Empty Space Skipping using Triangulated Active Bricks](6384-rtx-accelerated-empty-space-skipping-using-triangulated-acti.md)
Accelerates volume rendering by using RTX-accelerated ray tracing to skip empty space. It constructs a BVH over the boundary surface between active and inactive macrocells, rather than over all active regions, to determine ray integration intervals. It differs from this method by explicitly leveraging hardware-accelerated BVH traversal and triangle intersection via OptiX/OWL to replace costly software intersection tests, and from Ganter and Manzke's method by replacing the BVH over active brick regions with a BVH over only the boundary, resulting in lower depth complexity and fewer rays.

## Operating characteristics
- **Time Complexity:** BVH rebuild and triangle generation are GPU-side, avoiding host-GPU transfer bottlenecks. Depth complexity is reduced to transitions between active/inactive regions [S1, S2][S3, unofficial].
- **Memory Complexity:** Upper bounds for vertices and triangles are 3-5 orders of magnitude lower than the number of voxels [S1].
- **Performance:** Reduces per-pixel cost by freeing CUDA cores for volume integration. Eliminates warp divergence caused by varying numbers of samples per box [S1, S2][S3, unofficial].
- **Strengths:** No host-GPU transfer for mesh generation. Native hardware acceleration for intersection tests. Lower depth complexity than proxy box methods [S1, S2][S3, unofficial].
- **Limitations:** Requires BVH rebuild on TF change. Pre-allocated vertex array may waste memory [S1, S2][S3, unofficial].
- **When to Use:** Structured volumes with interactive TF editing. When hardware ray tracing is available [S1, S2][S3, unofficial].
- **When Not to Use:** Unstructured volumes (use [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) or unstructured methods). When TF changes are rare and host-side preprocessing is acceptable [S1, S2][S3, unofficial].

## Background
Originated from Ganter and Manzke's method [GM19], which used proxy boxes and user-defined intersection programs [S1, S2][S3, unofficial]. This method improves on it by using a GPU-generated boundary mesh and native triangle primitives [S1, S2][S3, unofficial]. The core idea draws motivation from unstructured volume rendering where rays are intersected with outside-facing triangles of boundary tetrahedra [BKS97]. Presented by Ingo Wald, Stefan Zellmann & Nate Morrical in Eurographics Proceedings 2021 [S3, unofficial]. Implemented using OptiX 7.2, but maps to DXR and VKR [S1, S2][S3, unofficial]. Used in evaluation datasets including HEPTANE, FLOWER, DNS-4, and LLNL Richtmyer-Meshkov instability [S1, S2][S3, unofficial].
