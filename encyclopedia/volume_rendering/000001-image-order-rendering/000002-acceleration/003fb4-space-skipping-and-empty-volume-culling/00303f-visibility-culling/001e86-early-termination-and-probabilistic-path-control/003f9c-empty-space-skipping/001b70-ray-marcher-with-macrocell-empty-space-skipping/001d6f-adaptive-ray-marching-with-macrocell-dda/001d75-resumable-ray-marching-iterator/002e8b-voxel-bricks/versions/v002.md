# Voxel Bricks

Also called: Brickmap, Brickmap Traversal, Brickmap approach

## Overview
Voxel Bricks is a hierarchical culling method for volume rendering that groups voxels into fixed-size $8 \times 8 \times 8$ blocks called "bricks" or "brickmaps" [S1, S2, unofficial]. It optimizes sparse voxel ray marching by maintaining a secondary "brickgrid" that references only occupied bricks, allowing the renderer to skip entire regions of empty space [S1, unofficial]. S2 describes a variant where empty bricks are explicitly marked within the structure rather than omitted [S2, unofficial]. It differs from [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md) by using a fixed two-level hierarchy [S1, S2, unofficial].

## How it works
**Inputs:** A volumetric dataset represented as a set of occupied $8 \times 8 \times 8$ bricks; a ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [S1, S2, unofficial].
**Outputs:** A color and transmittance value for the ray intersection [G].

**Data Structures:**
1. **Brick:** A static array of $8 \times 8 \times 8 = 512$ voxels [S1, unofficial]. The internal memory layout is not specified in the sources [G].
2. **Brickgrid:** An infinite, sparse 3D grid that maps integer brick coordinates $(b_x, b_y, b_z)$ to references to Brick objects [S1, unofficial]. Empty entries contain no reference or are explicitly marked as empty [S1, S2, unofficial].

**Algorithm Steps:**
1. **Brickgrid Traversal:** Perform a 3D-DDA traversal on the brickgrid using the ray parameters [S1, unofficial]. This yields the sequence of brick coordinates $(b_x, b_y, b_z)$ that the ray intersects [G].
2. **Empty Check:** For each brick coordinate visited by the DDA, check if the brickgrid entry is null or marked empty [S1, S2, unofficial].
3. **Skip or March:** If the brick is empty, skip to the next brick coordinate [S1, S2, unofficial]. If non-null, retrieve the Brick reference and perform standard ray marching within the $8 \times 8 \times 8$ voxel volume of that brick [S2, unofficial].
4. **Termination:** Continue until the ray exits the volume [S2, unofficial].

**Pseudocode:**
```python
import math

def render_voxel_bricks(ray_origin, ray_direction, occupied_bricks, brick_size=8.0):
    # 1. Initialize DDA state for brickgrid traversal
    bx = int(math.floor(ray_origin[0] / brick_size))
    by = int(math.floor(ray_origin[1] / brick_size))
    bz = int(math.floor(ray_origin[2] / brick_size))

    step_x = 1 if ray_direction[0] > 0 else -1
    step_y = 1 if ray_direction[1] > 0 else -1
    step_z = 1 if ray_direction[2] > 0 else -1

    # Handle zero direction components
    if ray_direction[0] == 0: step_x = 0
    if ray_direction[1] == 0: step_y = 0
    if ray_direction[2] == 0: step_z = 0

    # Distance to next brick boundary in world space
    next_x = (bx + 1) * brick_size if step_x > 0 else bx * brick_size
    next_y = (by + 1) * brick_size if step_y > 0 else by * brick_size
    next_z = (bz + 1) * brick_size if step_z > 0 else bz * brick_size

    t_max_x = (next_x - ray_origin[0]) / ray_direction[0] if ray_direction[0] != 0 else float('inf')
    t_max_y = (next_y - ray_origin[1]) / ray_direction[1] if ray_direction[1] != 0 else float('inf')
    t_max_z = (next_z - ray_origin[2]) / ray_direction[2] if ray_direction[2] != 0 else float('inf')

    t_delta_x = brick_size / ray_direction[0] if ray_direction[0] != 0 else float('inf')
    t_delta_y = brick_size / ray_direction[1] if ray_direction[1] != 0 else float('inf')
    t_delta_z = brick_size / ray_direction[2] if ray_direction[2] != 0 else float('inf')

    # 2. Traverse brickgrid
    while True:
        # Check if current brick is occupied
        if (bx, by, bz) in occupied_bricks:
            # 3. March inside the brick
            brick_origin = [bx * brick_size, by * brick_size, bz * brick_size]
            color, transmittance = march_bricks(ray_origin, ray_direction, brick_origin, brick_size)
            if transmittance < 1e-6:
                return color

        # Advance DDA to next brick
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                bx += step_x
                t_max_x += t_delta_x
            else:
                bz += step_z
                t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                by += step_y
                t_max_y += t_delta_y
            else:
                bz += step_z
                t_max_z += t_delta_z

        # Termination: ray has exited the volume
        if t_max_x < 0 and t_max_y < 0 and t_max_z < 0:
            break
```

**Edge Cases and Pitfalls:**
* **Precision:** The brickgrid is described as "infinite," implying it must handle large coordinate ranges. Implementers must ensure the DDA handles large integer steps without overflow [S1, unofficial].
* **Boundary Conditions:** The brickgrid has "no particular size," meaning the renderer must handle rays that start or end outside the defined brickgrid bounds [S1, unofficial].
* **Degenerate Input:** If a brick contains only air voxels, it is marked empty in the brickgrid [S2, unofficial].

## Subtopics

## Operating characteristics
**Time Complexity:** Worst-case scenario for brickgrid traversal is $n\sqrt{2}$ iterations for an $n \times n$ grid area, though typical sparse scenes are much faster due to skipping [S1, unofficial].
**Memory Complexity:** Memory usage is proportional to the number of occupied bricks [G]. Empty bricks consume no memory for voxel data [S1, unofficial].
**Performance:** Drastically improves render times by reducing the number of ray marching steps, primarily through the reduction of steps each ray has to take [S2, unofficial].
**Strengths:** Minimal structure overhead, suitable for interactive simulations where voxels change frequently [S2, unofficial]. Simple to implement [S1, unofficial].
**Limitations:** Fixed brick size ($8 \times 8 \times 8$) may not be optimal for all scene densities [G].

## Background
The method was proposed in the context of voxel simulation and rendering, prioritizing interactivity and minimal structure overhead for dynamic voxel changes [S2, unofficial]. It is described as a simpler alternative to distance fields and Sparse Voxel Octrees (SVOs) [S1, unofficial]. The author notes that the original paper stops short of discussing further hierarchical expansions (like fat-trees) [S1, unofficial].
