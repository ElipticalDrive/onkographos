# Octree Empty Block Culling

Also called: Octree Leaf Culling, Recursive Status Check

## Overview
Octree Empty Block Culling is a visibility culling technique that recursively traverses an octree to determine if a node contains any non-empty data blocks, returning a status of `EMPTY` or `NONEMPTY` to enable early ray termination or skipping of empty regions [S1, unofficial]. It sets itself apart from siblings like [Octree Traversal with Min/Max Pruning](1739-octree-traversal-with-min-max-pruning.md) by relying on explicit block existence checks rather than bounding volume overlaps, and from [View-Dependent Working Set Generation](4965-view-dependent-working-set-generation.md) by being view-independent and static [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: An octree node pointer (or index) and the global maximum tree depth.
- Output: A boolean or enum indicating `NONEMPTY` (true) or `EMPTY` (false).

**Data Structures:**
- `Node`: Contains a `depth` field (integer) and a `status` field (enum: `EMPTY`, `NONEMPTY`).
- `MMU` (Memory Management Unit): Provides a `getBlock` method to retrieve data blocks associated with leaf nodes.

**Numbered Steps:**
1. Initialize the current node's `status` to `EMPTY`.
2. Check if the node is a leaf:
   - If `node->depth == global_max_depth`:
     - Attempt to load the block using `mmu->getBlock(node)`.
     - If the returned block pointer is `nullptr`, set `status = EMPTY` and return `false`.
     - Otherwise, set `status = NONEMPTY` and return `true`.
3. If the node is internal:
   - Iterate through all 8 children.
   - Calculate the linear index of each child using the formula: `child_index = (parent_index << 3) + i + 1`, where `i` is the child index (0–7) [S1, unofficial].
   - Recursively call the status check on each child.
   - If any child returns `true` (is `NONEMPTY`), set `node->status = NONEMPTY` and return `true`.
4. If all children are `EMPTY`, return `node->status == NONEMPTY` (which is `false`).

**Formulas:**
- Child Linear Index: $I_{child} = (I_{parent} \ll 3) + i + 1$ for $i \in \{0, \dots, 7\}$ [S1, unofficial].

**Parameters:**
- `global_max_depth`: The maximum depth of the octree. Typical values depend on the dataset resolution (e.g., 8–12 for 256–4096^3 volumes).

**Edge Cases and Pitfalls:**
- **Depth Initialization:** The leaf check relies on comparing `node->depth` to a class member `depth`. If the tree depth is not set correctly during initialization, all nodes may be treated as internal or leaf incorrectly, leading to infinite recursion or premature termination [S1, unofficial].
- **Null Pointers:** The method assumes `mmu->getBlock` returns `nullptr` for empty leaves. If the MMU does not support this, the culling fails.

**Pseudocode:**
```python
def check_node_status(node, global_max_depth, mmu):
    """
    Recursively checks if an octree node contains non-empty data.
    
    Args:
        node: The current octree node object.
        global_max_depth: The maximum depth of the octree.
        mmu: Memory Management Unit with getBlock method.
        
    Returns:
        bool: True if node is NONEMPTY, False if EMPTY.
    """
    # Initialize status to EMPTY
    node.status = Status.EMPTY
    
    # Check if leaf
    if node.depth == global_max_depth:
        # Attempt to load block
        block = mmu.getBlock(node)
        if block is None:
            node.status = Status.EMPTY
            return False
        else:
            node.status = Status.NONEMPTY
            return True
            
    # Internal node: check all 8 children
    for i in range(8):
        # Calculate linear index of child
        # Assuming node has a linear_index field
        child_index = (node.linear_index << 3) + i + 1
        
        # Get child node (implementation detail: how to retrieve child from index)
        # [G] Assuming a standard octree array representation where children are contiguous
        child = get_node_at_index(child_index)
        
        # Recursive call
        if check_node_status(child, global_max_depth, mmu):
            node.status = Status.NONEMPTY
            return True
            
    # If no child is non-empty
    return node.status == Status.NONEMPTY
```

## Subtopics

### [View-Dependent Visibility Culling](11833-view-dependent-visibility-culling.md)
View-dependent visibility culling is an acceleration technique for volume rendering that discards voxels or nodes occluded by previously traversed geometry closer to the camera. It extends empty-space skipping by ordering traversal based on camera position, allowing the renderer to skip nodes that are hidden behind already-rendered surfaces. Unlike static culling, it leverages the multiresolution nature of hierarchical structures (like octrees or quadtrees) to adaptively decide extraction or rendering resolution based on visibility.

### Octree Range Culling
In this variant, shells' ranges over a node are computed once per pass for up to 4 tiles of 64 functions (each lane owns a function of every tile) instead of once per tile, only for shells reaching the node [S2, unofficial]. A dropped shell has every AO below $10^{-10}$ over the node. The term $fn\_tail$ ($2 \times 10^{-10}$ times the column sum of $|C|$) is added to every function's bound for them [S2, unofficial].

### Octree Node Collision Test
This method tests whether an octree node collides with obstacles to classify it as `Empty` or `Mixed`, avoiding explicit `Blocked` detection [S3, unofficial]. It runs a collision test using the node's size; if no collision is detected, it returns `Empty`; if a collision is detected, it returns `Mixed` [S3, unofficial]. A pitfall is that a single-pass size test may miss internal full occlusion, which is resolved by recursive subdivision in `BuildNodeRecursive` [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ in the worst case where $N$ is the number of nodes, as it may visit every node. However, for sparse volumes, it is significantly faster as it prunes empty subtrees.
- **Memory Complexity:** $O(D)$ where $D$ is the tree depth, due to recursion stack.
- **Strengths:** Simple to implement; effective for sparse data; enables early termination in ray casting.
- **Limitations:** Requires explicit block existence metadata; less effective for dense data where most nodes are non-empty.
- **When to use:** Sparse volume rendering; isosurface extraction where empty space is common.
- **When not to use:** Dense volumes; when bounding volume overlap is sufficient and cheaper to compute.

## Background
Originating from parallel volume rendering implementations, this method is used to accelerate ray casting by skipping empty regions in octree-structured data [S1, unofficial]. It is commonly found in MPI-based volume rendering systems where efficient load balancing and data access are critical.
