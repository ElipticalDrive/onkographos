# Parallel K-d Tree Construction

Also called: Global spatial partitioning, Hierarchical spatial data structure, Parallel K-d Tree Spatial Partitioning

## Overview
Parallel K-d Tree Construction is a cooperative parallel partitioning process that uses a k-d tree to group data cells into local regions, restoring spatial ordering to allow early ray merging and efficient rendering in distributed-memory systems [S1]. It sets itself apart from static partitioning methods by dynamically determining split planes via global consensus and managing neighbor links to handle boundary conditions, ensuring that processors render cells in the same neighborhood at approximately the same time [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of data cells (e.g., volume mesh cells) initially distributed across $P$ processors. Each cell has a geometric representation (typically defined by vertices or a centroid).
*   **Output:** A global k-d tree structure that is identical on every processor, defining a partitioning of the spatial domain. Each cell is assigned to a specific leaf node (region) of the tree, which corresponds to a specific processor or group of processors.

**Data Structures:**
*   **Cell Data:** Each cell $C_i$ is represented by its centroid $Centroid(C_i) = (x_i, y_i, z_i)$ and its local index or identifier.
*   **K-d Tree Node:** Each node in the k-d tree contains:
    *   `split_axis`: The dimension (0, 1, or 2) along which the split occurs.
    *   `split_value`: The coordinate value along `split_axis` where the split occurs.
    *   `left_child`: Reference to the left sub-tree (cells with coordinate < `split_value`).
    *   `right_child`: Reference to the right sub-tree (cells with coordinate >= `split_value`).
    *   `region_id`: Identifier for the leaf node, indicating which processor is responsible for rendering cells in this region.

**Parameters:**
*   `max_depth`: Maximum depth of the k-d tree. Not given in the sources.
*   `min_cells_per_leaf`: Minimum number of cells per leaf node to stop recursion. Not given in the sources.
*   `num_processors`: Total number of processors $P$ participating in the partitioning.

**Steps:**
The algorithm operates in a synchronized, cooperative manner across all processors. The goal is to build the same k-d tree on every processor.

1.  **Initial Distribution:** Data cells are initially distributed among the $P$ processors. This distribution may be arbitrary or based on a simple domain decomposition, but it does not need to be spatially coherent.
2.  **Local Cut Proposal:**
    *   Each processor examines its local collection of cells.
    *   The processor determines a local cutting position along the current split axis. The direction of the cut alternates at each level of the partitioning (e.g., X, then Y, then Z, then X...).
    *   The local cut is chosen such that it divides the processor's local cells into two sub-regions containing approximately the same number of cells.
    *   The processor sends this local cutting position to a designated host node.
3.  **Global Cut Determination:**
    *   The designated host node receives proposed local cutting positions from all $P$ processors.
    *   The host node averages these positions to obtain a global cutting position.
    *   The host node broadcasts this global cutting position, along with the next subregion to be partitioned (or the next split axis), to all processors.
4.  **Cell Assignment:**
    *   Each processor iterates through its local cells.
    *   For each cell, the processor checks if the cell intersects the cut boundary.
    *   If a cell intersects the boundary, it is assigned to the region containing its centroid. Specifically:
        *   If $Centroid(C_i)[split\_axis] < split\_value$, the cell is assigned to the left region.
        *   Otherwise, the cell is assigned to the right region.
    *   Cells are physically moved or logically reassigned to the processors responsible for the target regions. This may involve communication between processors.
5.  **Recursion:**
    *   The process repeats recursively for each new subregion until the desired number of regions (leaves) is reached or a maximum depth is exceeded.
    *   The tree structure is built identically on all processors.

**Pseudocode:**
```python
def parallel_kd_tree_build(cells, processors, depth=0, axis=0):
    """
    Cooperative parallel k-d tree construction.
    cells: List of cells on this processor.
    processors: List of processor IDs.
    depth: Current depth in the tree.
    axis: Current split axis (0=x, 1=y, 2=z).
    """
    if not cells:
        return None

    # Step 1: Determine local cut
    local_cut = determine_local_cut(cells, axis)
    
    # Step 2: Communicate with host
    if is_host(processor_id):
        global_cut = average_cuts(receive_cuts_from_all_processors())
        broadcast(global_cut, next_axis(axis))
    else:
        send_cut(local_cut)
        global_cut = receive_broadcast()
        next_ax = receive_broadcast()

    # Step 3: Partition cells
    left_cells = []
    right_cells = []
    
    for cell in cells:
        centroid_val = cell.centroid[axis]
        if centroid_val < global_cut:
            left_cells.append(cell)
        else:
            right_cells.append(cell)
            
    # Step 4: Assign to processors (simplified)
    # In reality, this involves MPI_Send/MPI_Recv or similar
    # For the purpose of building the tree structure, we assume
    # the tree node knows which processors are in left/right subtrees.
    
    # Step 5: Recurse
    left_node = parallel_kd_tree_build(left_cells, left_processors, depth+1, next_ax)
    right_node = parallel_kd_tree_build(right_cells, right_processors, depth+1, next_ax)
    
    return Node(axis=axis, value=global_cut, left=left_node, right=right_node)

def determine_local_cut(cells, axis):
    """
    Find a cut that divides local cells into two equal halves.
    """
    centroids = [c.centroid[axis] for c in cells]
    centroids.sort()
    median_idx = len(centroids) // 2
    return centroids[median_idx]
```

**Edge Cases and Pitfalls:**
*   **Unbalanced Tree:** The implementation does not guarantee a well-balanced tree. However, the extra searching overhead is insignificant compared to the time required for rendering calculations [S1].
*   **Identical Values:** The Floyd-Rivest selection algorithm (used in some variants) exhibits worst-case behavior with long sequences of identical values, which is common in aligned volume models. This can increase runtime from seconds to hours. A modified algorithm to detect and skip duplicate entries is essential [S2].
*   **Boundary Conditions:** Cells intersecting the cut boundary must be assigned to the region containing their centroid. This requires careful handling to ensure consistency across processors [S1].

## Subtopics

### [KDTreeSamplingPartition](8210-kdtreesamplingpartition.md)
KDTreeSamplingPartition is a domain decomposition algorithm for distributing volume rendering samples across multiple compute blocks in a distributed-memory system. It builds a k-d tree structure over spatial data points by recursively splitting blocks along coordinate dimensions using a sampling-based approach to determine split positions. It sets itself apart from static partitioning methods by dynamically determining split planes via random sampling and managing neighbor links via a reduce proxy to handle wrap-around or boundary conditions.

### Parallel Recursive Coordinate Bisection for KD-Tree Building
Parallel Recursive Coordinate Bisection for KD-Tree Building is a parallel algorithm to build a KD-tree for data partitioning, using a recursive coordinate bisection approach with a parallel selection step to find medians [S2]. It sets itself apart by using the Floyd-Rivest selection algorithm to find the median in parallel, which rearranges array elements into those less than and greater than a proposed median. It prefetches a range of values when performing off-processor tests in the parallel selection to improve run times [S2]. Pitfalls include the worst-case behavior of the Floyd-Rivest algorithm with long sequences of identical values, which is common in aligned volume models, potentially increasing runtime from expected times to hours [S2].

## Operating characteristics
*   **Time Complexity:** The time complexity is dominated by the parallel median finding step. The Floyd-Rivest selection algorithm has sub-linear average complexity with respect to the size of the array [S2]. However, worst-case behavior can be $O(n^2)$ or worse with identical values [S2].
*   **Memory Complexity:** Linear in the number of cells, as each cell is stored once and the tree structure is replicated on all processors [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** The algorithm is designed for distributed-memory systems and scales with the number of processors. The cooperative nature ensures that all processors participate in the partitioning, leading to a balanced workload if the data is uniformly distributed [S1].
*   **Strengths:** Restores spatial ordering, allowing for early ray merging and reduced memory usage for unmerged ray segments [S1]. Supports adaptive partitioning along orthogonal coordinate planes [S1].
*   **Limitations:** Does not guarantee a well-balanced tree [S1]. Sensitive to data alignment, which can cause performance degradation with the Floyd-Rivest algorithm [S2].
*   **When to use:** When early ray merging is critical for performance and the data is distributed across multiple processors [S1].
*   **When not to use:** When the data has many identical coordinate values and the Floyd-Rivest algorithm is used without modification [S2].

## Background
Parallel K-d Tree Construction was introduced in the context of scalable parallel cell-projection volume rendering algorithms [S1]. It was developed to address the issue of load balance and spatial coherence in distributed-memory volume rendering systems. The method was proposed by researchers at UC Davis, as indicated by the source URL [S1]. It is used in parallel volume rendering systems, such as those implemented in ParaView [S2].
