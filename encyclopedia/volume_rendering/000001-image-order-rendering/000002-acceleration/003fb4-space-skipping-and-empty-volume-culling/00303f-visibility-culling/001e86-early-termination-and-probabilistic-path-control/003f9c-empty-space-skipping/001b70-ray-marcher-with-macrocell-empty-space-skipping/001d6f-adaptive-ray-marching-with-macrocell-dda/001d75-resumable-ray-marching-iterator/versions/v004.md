# Resumable Ray Marching Iterator

Also called: OptiX7 Adaptive Ray Marching, Resumable Ray Marching

## Overview
The Resumable Ray Marching Iterator traverses a volumetric grid using a 3D Digital Differential Analyzer (DDA) over macrocells, adapting the sampling step size based on opacity upper bounds to skip empty regions [S1, S2, unofficial]. It differs from its parent [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) by explicitly supporting interruption and resumption of the ray traversal state, allowing the algorithm to pause mid-ray for external operations and resume later without losing progress [S1, S3, unofficial].

## How it works
### Inputs and Outputs
*   **Inputs**: Ray origin `org`, ray direction `dir`, ray segment bounds `tMin`, `tMax`, volume dimensions `dims`, macrocell spacing inverse `macrocell_spacings_rcp`, fixed step size `step`, and a callback `body(t)` [S1, S2, unofficial].
*   **Outputs**: Accumulated radiance/color and opacity, computed via `body(t)` invoked for each sampled segment [S2, unofficial].

### Data Structures
The iterator maintains state in a payload structure to support resumption [S1, unofficial].
**SampleStreamingPayload** (stores iteration state):
*   `iter.cell`: Current macrocell coordinates (integer vector). Present only if `ADAPTIVE_SAMPLING` is defined [S1, unofficial].
*   `iter.t_next`: The next time parameter to process. Present only if `ADAPTIVE_SAMPLING` is defined [S1, unofficial].
*   `iter.next_cell_begin`: Offset from `tMin` to the next cell boundary. Always present [S1, unofficial].
*   `pixel_index`: Pixel identifier [S1, unofficial].
*   `jitter`: Sampling jitter [S1, unofficial].
*   `alpha`: Accumulated opacity [S1, unofficial].
*   `color`: Accumulated color [S1, unofficial].
**RadiancePayload** (for ray generation):
*   `alpha`: Float, initialized to `0.f` [S2, unofficial].
*   `color`: `vec3f`, initialized to `0.f` [S2, unofficial].
*   `rng`: Pointer to random number generator state, initialized to `nullptr` [S2, unofficial].
**ShadowPayload** (for shadow rays):
*   `alpha`: Float, initialized to `0.f` [S2, unofficial].
*   `rng`: Pointer to random number generator state, initialized to `nullptr` [S2, unofficial].

### Pseudocode
```python
def resumable_ray_marching_iterator(org, dir, tMin, tMax, dims, macrocell_spacings_rcp, step, body, ADAPTIVE_SAMPLING):
    next_cell_begin = 0.0
    if ADAPTIVE_SAMPLING:
        m_org = org * macrocell_spacings_rcp
        m_dir = dir * macrocell_spacings_rcp
        DDAIter.init(m_org, m_dir, tMin, tMax, dims)
        while DDAIter.next(lambda cell, t0, t1: process_macrocell(cell, t0, t1)):
            pass
    else:
        t = [max(tMin + next_cell_begin, tMin), min(max(tMin + next_cell_begin, tMin) + step, tMax)]
        while t[1] > t[0]:
            next_cell_begin = t[1] - tMin
            body(t[0], t[1])
            t[0] = t[1]
            t[1] = min(t[0] + step, tMax)
        next_cell_begin = float('inf')
    return resumable_check(ADAPTIVE_SAMPLING, m_dir, tMin, tMax, dims, next_cell_begin)

def process_macrocell(cell, t0, t1):
    r = opacityUpperBound(cell)
    if abs(r) <= float_epsilon:
        return True
    ss = sample_size_scaler(adaptiveSamplingRate(step, r), t0, t1)
    t = [t0, min(t1, t0 + ss)]
    while t[1] > t[0]:
        next_cell_begin = t[1] - tMin
        body(t[0], t[1])
        t[0] = t[1]
        t[1] = min(t[0] + ss, t1)
    return True

def sample_size_scaler(ss, t0, t1):
    N = floor((t1 - t0) / ss) + 1
    return (t1 - t0) / N

def resumable_check(ADAPTIVE_SAMPLING, m_dir, tMin, tMax, dims, next_cell_begin):
    if ADAPTIVE_SAMPLING:
        return DDAIter.resumable(m_dir, tMin, tMax, dims)
    else:
        return tMin + next_cell_begin < tMax
```

### Parameters
*   `ADAPTIVE_SAMPLING`: Preprocessor macro. Must be defined to enable adaptive logic [S2, unofficial].
*   `step`: Fixed step size for non-adaptive mode [S1, unofficial].
*   `adaptiveSamplingRate`: Function determining base step size based on opacity bound `r` [S1, unofficial].
*   `sample_size_scaler`: Normalizes step size to fit an integer number of steps in interval `[t0, t1]` [S2, unofficial].
*   `next_cell_begin`: Member variable tracking the offset from `tMin` to the next cell boundary, used for resumption [S1, unofficial].

### Edge Cases and Pitfalls
*   **Empty Cells**: If `fabsf(r) <= float_epsilon`, the cell is skipped to avoid unnecessary sampling [S1, S2, unofficial].
*   **Precision**: `float_epsilon` is used for empty space detection; its value must match the volume's density range [S1, unofficial].
*   **Resumption State**: `next_cell_begin` must be correctly updated and stored. If interrupted, `iter.cell` and `iter.t_next` must be preserved for adaptive mode [S1, unofficial].
*   **Boundary Conditions**: `t.y` is clamped to `t1` (macrocell end) or `tMax` (ray end) to prevent overshooting [S1, unofficial].

## Subtopics

### [Woodcock Collision Estimation (Standard)](3331-woodcock-collision-estimation-standard.md)
A ray marching technique for volume rendering that uses Woodcock collision estimation (delta tracking) to skip empty space, avoiding the need for spatial acceleration structures for sampling but requiring a global maximum density estimate. It differs from sibling methods like [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md) by avoiding the need for spatial acceleration structures for sampling, instead relying on probabilistic step sizing based on a global maximum density estimate.

### [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md)
Adaptive Ray Marching with Voxel Skipping is a two-pass algorithm that determines the optimal sampling positions for rays traversing a volumetric density grid, skipping empty space to reduce computational load [G]. It solves the problem of inefficient uniform sampling in sparse volumes by dynamically adjusting step sizes based on local density [G]. It differs from its parent, the Resumable Ray Marching Iterator, by pre-computing the exact number of steps and their locations in a dedicated pass, allowing for compact, contiguous memory storage of samples, whereas the parent yields samples on-the-fly [G]. It differs from [Woodcock Collision Estimation (Standard)](3331-woodcock-collision-estimation-standard.md) by using deterministic DDA-based boundary traversal rather than probabilistic collision estimation [G].

### Ray-Guided Streaming with Interrupt/Resume
A method for handling missing GPU memory by stopping ray tracing when data is absent, communicating this to the CPU for loading, and resuming the ray at the last position in subsequent passes [S3, unofficial].
*   **Definition**: The algorithm stops rays when data is missing, communicates this to the CPU, loads the data, and resumes ray tracing at the last position [S3, unofficial].
*   **Steps**:
    1.  Start ray tracing; if data is missing, stop the ray and communicate to CPU [S3, unofficial].
    2.  CPU initiates loading of missing data [S3, unofficial].
    3.  Algorithm resumes ray tracing at the last ray position [S3, unofficial].
    4.  Block terminated pixels with the Z-Buffer to treat only active rays, relying on z-cull and early-Z GPU features [S3, unofficial].
    5.  Maintain ray status information in two Multiple Render Targets (MRTs): preliminary output color accumulation, missing node ID, and current marching position [S3, unofficial].
    6.  Download missing IDs to CPU so it can adapt the data structure [S3, unofficial].
    7.  In the next rendering pass, initiate with a proxy surface and use the MRTs as input textures; earlyZ ensures only active pixels execute the fragment shader [S3, unofficial].
*   **Advantages**: Loaded data is directly traversed by the ray, and no data lying outside the frustum is loaded [S3, unofficial]. The CPU does not need to track LODs; rays indicate required precision [S3, unofficial].

## Operating characteristics
*   **Time Complexity**: Not given in the sources. Adaptive sampling reduces the number of samples in empty regions, improving performance for sparse volumes [S1, S2, unofficial].
*   **Memory Complexity**: Not given in the sources. Low, as it processes rays on-the-fly and only stores minimal state per ray for resumption [S1, unofficial].
*   **Performance**: Not given in the sources. Efficient for large volumes with significant empty space due to macrocell skipping. Performance is hardware-dependent, leveraging GPU parallelism and early-Z culling [S1, S2, unofficial].
*   **Strengths**: Resumability allows for complex data streaming and neural network integration. Adaptive sampling reduces computational load [S1, S3, unofficial].
*   **Limitations**: Requires careful management of resumption state. Adaptive sampling may introduce complexity in step size calculation [S1, unofficial].
*   **When to Use**: Suitable for large volumetric datasets, especially when data streaming or neural network inference is involved [S1, S3, unofficial].
*   **When Not to Use**: Not given in the sources.

## Background
The method is implemented in C++ and utilizes NVIDIA OptiX for ray tracing, found in the `instantvnr` and `open-volume-renderer` repositories [S1, S2, unofficial]. The interrupt/resume capability enables ray-guided streaming for missing GPU memory, allowing multiple passes to complete a frame by loading data on-demand [S3, unofficial].
