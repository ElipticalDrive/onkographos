# K-D Tree Hierarchy Construction

Also called: Polygon distribution in k-d tree, Spatial partitioning with k-d trees

## Overview
K-D Tree Hierarchy Construction builds a binary space-partitioning structure to organize geometric primitives (typically polygons) for efficient spatial queries, such as visibility culling in volume rendering. It sets itself apart from its parent method, [Orthogonal BSP Tree Construction](1134-orthogonal-bsp-tree-construction.md), by storing polygons in leaf nodes or internal nodes based on containment rather than splitting them at the plane, thereby avoiding explicit polygon clipping [S1]. Unlike fixed-viewpoint partitioning, it is view-independent, making it suitable for animation sequences [S2, unofficial].

## How it works
**Inputs:** A set of polygons $P$, each defined by vertices in 3D space. A user-defined leaf threshold $T_{leaf}$.
**Outputs:** A binary tree where each node $v$ contains a list of polygon IDs and a splitting dimension $i$ (if internal).

**Data Structures:**
*   **Tree Node:** Contains `split_dim` (integer, 0-2), `split_val` (float), `left_child` (pointer/index), `right_child` (pointer/index), and `poly_ids` (list of integers).
*   **Polygon ID Array (`Tid`):** A flat array storing polygon IDs in prefix-order traversal sequence. This allows all polygons in a subtree to be passed in one operation without linked lists [S1].

**Algorithm:**
1.  **Root Initialization:** Create the root node. Assign all input polygons to the root's `poly_ids` list.
2.  **Recursive Build Function `Build(node, polygons)`:**
    a.  **Leaf Check:** If `len(polygons) <= T_leaf`, mark `node` as a leaf. Return.
    b.  **Splitting Dimension Selection:** Determine dimension $i$ to split on. The basic implementation uses round-robin selection (e.g., $i = depth \mod 3$) [S1]. More sophisticated policies may use variance analysis [S2, unofficial].
    c.  **Split Value Selection:** Determine the splitting value $X_i$. The basic implementation bisects the region along dimension $i$ [S1].
    d.  **Polygon Classification:** Initialize `left_polys` and `right_polys` as empty lists. For each polygon $p$ in `polygons`:
        i.  Check all vertices of $p$.
        ii. If all vertices have coordinate $x_i < X_i$, add $p$ to `left_polys`.
        iii. If all vertices have coordinate $x_i > X_i$, add $p$ to `right_polys`.
        iv. Otherwise, retain $p$ in `node.poly_ids`. This associates the polygon with the smallest node region that completely contains it, avoiding subdivision [S1].
    e.  **Recursive Step:**
        i.  If `left_polys` is not empty, create `node.left_child` and call `Build(node.left_child, left_polys)`.
        ii. If `right_polys` is not empty, create `node.right_child` and call `Build(node.right_child, right_polys)`.
        iii. If both are empty, the node is a leaf (or contains only overlapping polygons).
3.  **Serialization:** Traverse the tree in prefix order to populate the `Tid` array.

**Parameters:**
*   $T_{leaf}$: Typical values are not given in the sources. [G] Common practice suggests 1-10 depending on cache size.

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point comparisons for $x_i < X_i$ and $x_i > X_i$ must be consistent to avoid polygons being lost or duplicated.
*   **Empty Subtrees:** If a split results in no polygons on one side, that child should not be created to save space.
*   **Degenerate Input:** Polygons with zero area or vertices exactly on the split plane are handled by the "retain in node" rule (case iv), ensuring they are not lost [S1].

```python
def build_kd_tree(polygons, depth=0, leaf_threshold=4):
    """
    Builds a K-D tree hierarchy.
    polygons: List of Polygon objects, each with vertices (list of Vec3) and id.
    depth: Current tree depth.
    leaf_threshold: Minimum number of polygons to trigger a split.
    Returns: TreeNode object.
    """
    node = TreeNode()
    node.poly_ids = [p.id for p in polygons]
    
    # Leaf check
    if len(polygons) <= leaf_threshold:
        node.is_leaf = True
        node.split_dim = -1
        node.split_val = 0.0
        node.left_child = None
        node.right_child = None
        return node

    # Splitting dimension selection (Round-robin as per [S1])
    split_dim = depth % 3
    
    # Split value selection (Bisection as per [S1])
    # Find min and max extent along split_dim
    min_val = float('inf')
    max_val = float('-inf')
    for p in polygons:
        for v in p.vertices:
            val = v[split_dim]
            if val < min_val: min_val = val
            if val > max_val: max_val = val
    
    split_val = (min_val + max_val) / 2.0
    node.split_dim = split_dim
    node.split_val = split_val
    
    left_polys = []
    right_polys = []
    node.poly_ids = [] # Will store IDs of polygons retained at this node
    
    for p in polygons:
        all_less = True
        all_greater = True
        for v in p.vertices:
            val = v[split_dim]
            if val >= split_val:
                all_less = False
            if val <= split_val:
                all_greater = False
        
        if all_less:
            left_polys.append(p)
        elif all_greater:
            right_polys.append(p)
        else:
            node.poly_ids.append(p.id)
            
    # Recursive step
    if left_polys:
        node.left_child = build_kd_tree(left_polys, depth + 1, leaf_threshold)
    else:
        node.left_child = None
        
    if right_polys:
        node.right_child = build_kd_tree(right_polys, depth + 1, leaf_threshold)
    else:
        node.right_child = None
        
    node.is_leaf = (node.left_child is None and node.right_child is None)
    return node
```

## Subtopics

### [Real-time KD Tree Construction](4437-real-time-kd-tree-construction.md)
Real-time KD Tree Construction is a technique for building k-d tree spatial partitioning structures on the GPU to enable immediate use in rendering pipelines. It sets itself apart from its parent method, [K-D Tree Hierarchy Construction](2300-k-d-tree-hierarchy-construction.md), by utilizing GPU parallelism and breadth-first search (BFS) to achieve real-time performance. It differs from [GPU K-D Tree Ray Traversal](4575-gpu-k-d-tree-ray-traversal.md) by focusing on the *construction* phase rather than the *traversal* phase [G].

### [GPU K-D Tree Ray Traversal](4575-gpu-k-d-tree-ray-traversal.md)
GPU K-D Tree Ray Traversal accelerates ray tracing on graphics hardware by intersecting rays with a hierarchical spatial partitioning structure (K-D tree). It efficiently skips empty space and identifies intersected primitives, avoiding the computational cost of testing every primitive in the scene. It is distinguished from CPU implementations by its adaptation to GPU architectures: early Shader Model 2.0 hardware used stackless multi-pass streaming kernels, while Shader Model 3.0 introduced single-pass traversal via dynamic branching. It builds on [K-D Tree Hierarchy Construction](2300-k-d-tree-hierarchy-construction.md).

### [Parallel K-d Tree Construction](5421-parallel-k-d-tree-construction.md)
Parallel k-d tree construction algorithms partition sparse volumetric or unstructured data into spatial regions to enable efficient ray traversal, early termination, and workload distribution in parallel volume rendering. Unlike static partitioning, these methods dynamically determine split planes using occupancy queries or median selection to balance tree depth and node count. They differ from [Real-time KD Tree Construction](4437-real-time-kd-tree-construction.md) by focusing on distributed-memory or GPU-accelerated top-down recursion rather than single-node heuristic optimization, and from [K-D Tree Subdivision](8148-k-d-tree-subdivision.md) by explicitly managing inter-processor communication or GPU kernel synchronization during the build phase.

### [K-D Tree Subdivision](8148-k-d-tree-subdivision.md)
K-D Tree Subdivision partitions a 3D volume into subvolumes using a k-d tree structure with alternating binary subdivision of coordinate planes, enabling unambiguous front-to-back ordering for compositing. Unlike fixed viewpoint partitioning which minimizes overlap by slicing orthogonal to the view, k-D tree partitioning is view-independent and suitable for animation sequences where the viewpoint changes. It is used to determine the front-to-back image compositing order hierarchically by recursive traversal, visiting the 'front' child before the 'back' child.

### Axis Selection via Variance
Selects the splitting axis for a K-D tree node by analyzing the variance of the QEF (Quadratic Error Function) solution along each dimension, scaled by the box size [S2, unofficial]. The process involves solving the QEF to get an approximate solution and error, then calculating variance for each axis: $variance[i] = qef.getVariance(approximate) \times size[i]$ [S2, unofficial]. The axis with maximum variance is chosen (`dir = maxVarDir`). Fallback logic applies if the box size along the selected axis is less than 2, choosing `3 - maxVarDir - minVarDir`, and if that is also small, falling back to `minVarDir` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ on average for balanced trees, where $N$ is the number of polygons. Worst case $O(N^2)$ for degenerate inputs.
*   **Memory Complexity:** $O(N)$ for storing polygons and tree nodes. The flat `Tid` array avoids overhead of linked lists [S1].
*   **Strengths:** Avoids explicit polygon clipping, reducing computational cost during rendering. Efficient for static scenes.
*   **Limitations:** Construction can be slow for very large datasets. Sensitive to the choice of split plane and leaf threshold.
*   **When to use:** Static scenes with many polygons where visibility culling is critical.
*   **When not to use:** Highly dynamic scenes where frequent tree rebuilds are prohibitive.

## Background
The k-d tree was introduced by Jon Bentley in 1975 [S1]. It was originally designed for efficient spatial partitioning in computer graphics, specifically for hidden surface removal and ray tracing. The method described here, which stores polygons in nodes rather than splitting them, is a variation that avoids the need for explicit clipping, as noted in early volume rendering implementations [S1].
