# Proximity Clouds


## Overview
Proximity clouds are an acceleration technique for 3D grid traversal that assists rays traversing empty space by using pre-computed distance values to perform long skips along the ray direction [S1][S2, S3, unofficial]. Unlike standard empty-space skipping which may step voxel-by-voxel, proximity clouds store distance transform values in empty volume regions where volume densities are irrelevant, allowing the ray to leap over large empty volumes [S3, unofficial]. This method is an extension of adaptive ray traversal [8185-adaptive-ray-traversal.md] that trades storage for traversal speed in sparse datasets.

## How it works
**Inputs and Outputs:**
- Input: A 3D volume grid where empty voxels store distance transform values instead of density/opacity.
- Output: A ray traversal path that skips empty regions based on stored distance values.

**Data Structures:**
- The volume grid is a 3D array of voxels.
- For occupied voxels, standard density/opacity values are stored.
- For empty voxels, a single integer or float value representing the distance to the nearest non-empty (data) voxel is stored. This value effectively replaces the density value, so storage size is not increased [S3, unofficial].

**Steps:**
1. **Pre-processing:** Compute the distance transform of the object. For each empty voxel, calculate the distance to the nearest data voxel. Store this value in the voxel's data field [S2, S3, unofficial].
2. **Ray Traversal:** When a ray enters the volume, it traverses the grid.
3. **Empty Space Skip:** If the current voxel is empty and has a proximity value $n$, the ray skips the next $n$ voxels along its direction [S2, unofficial].
4. **Boundary Check:** After skipping, the ray checks the new voxel. If it is a data voxel, rendering proceeds. If it is still empty, the process repeats with the new voxel's proximity value [S2, unofficial].

**Formulas:**
- Let $d(v)$ be the proximity value of voxel $v$.
- If ray $r$ intersects voxel $v$ and $v$ is empty, the next voxel to check is $v' = v + n \cdot \vec{d}$, where $\vec{d}$ is the ray direction and $n = d(v)$ [S2, unofficial].

**Parameters:**
- Distance metric: Typically Euclidean or Manhattan distance, though not explicitly specified in sources [S2, S3, unofficial].

**Edge Cases and Pitfalls:**
- Rays that miss the object entirely are often slowed down because proximity clouds are iso-distance layers insensitive to viewing direction [S3, unofficial].
- Precision issues may arise if distance values are not accurately computed, leading to incorrect skips.

**Pseudocode:**
```python
def traverse_proximity_cloud(ray_origin, ray_direction, volume_grid):
    # Initialize ray position
    current_voxel = get_voxel_index(ray_origin, volume_grid)
    
    while current_voxel is within volume bounds:
        voxel_data = volume_grid[current_voxel]
        
        if voxel_data is empty:
            # Get proximity value (distance to nearest data voxel)
            distance = voxel_data.proximity_value
            
            # Skip 'distance' voxels along the ray direction
            # Note: This assumes a simple grid traversal where skipping
            # 'distance' steps is equivalent to moving 'distance' voxels.
            # In practice, this requires careful handling of ray-grid intersections.
            current_voxel = skip_voxels(current_voxel, distance, ray_direction, volume_grid)
        else:
            # Render the data voxel
            render(voxel_data)
            break
            
        # Update current_voxel to the next voxel after skipping
```

## Subtopics

### View-Sensitive Proximity Clouds
An extension by Sramek and Kaufman that addresses the insensitivity to viewing direction by incorporating view-dependent information [S3, unofficial].

### Sphere-Based Proximity
A technique by Wan that places a sphere at every empty voxel position, where the sphere radius indicates the closest non-empty voxel, useful for navigation in hollow volumetric objects [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Reduces traversal time in empty regions by allowing large skips, but may increase overhead in pre-processing [S1][S3, unofficial].
- **Memory Complexity:** No additional storage is required as distance values replace density values in empty voxels [S3, unofficial].
- **Strengths:** Efficient for sparse datasets with large empty regions [S3, unofficial].
- **Limitations:** Insensitive to viewing direction, which can slow down rays that miss the object [S3, unofficial].

## Background
Proximity clouds were proposed by Cohen and Sheffer in 1994 [S1][S3, unofficial]. The technique has been extended by various researchers, including Sramek and Kaufman, Wan, and Meissner, to address its limitations and adapt it to specific use cases [S3, unofficial].
