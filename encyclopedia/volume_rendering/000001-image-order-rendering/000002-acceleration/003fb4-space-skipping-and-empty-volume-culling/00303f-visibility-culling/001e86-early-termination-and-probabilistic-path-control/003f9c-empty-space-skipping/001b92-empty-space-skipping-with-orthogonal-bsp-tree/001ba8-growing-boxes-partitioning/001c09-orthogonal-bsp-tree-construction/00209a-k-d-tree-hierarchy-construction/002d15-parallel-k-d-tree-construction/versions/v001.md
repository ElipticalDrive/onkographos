# Parallel K-d Tree Construction

Also called: Global spatial partitioning, Hierarchical spatial data structure, Parallel K-d Tree Spatial Partitioning

## Overview
Parallel K-d Tree Construction is a cooperative parallel partitioning process that groups data cells into local regions using a k-d tree to restore spatial ordering in distributed datasets [S1]. This ordering allows early ray merging and efficient rendering by ensuring processors render cells in the same neighborhood simultaneously [S1]. It is distinguished from sibling methods by its focus on global synchronization for load balancing and ray merging rather than just raw construction speed or traversal optimization [S1, S2].

## How it works
**Inputs:** A distributed set of data cells (polygons or volume elements) across multiple processors.
**Outputs:** A globally consistent k-d tree structure and a partitioning of cells into subregions assigned to specific processors.

**Data Structures:**
*   **Cell Array:** Stores cell geometries and centroids.
*   **K-d Tree Nodes:** Each node defines a splitting plane (axis and position) and references two child nodes or leaf regions.
*   **Processor State:** Each processor maintains a local subset of cells.

**Parameters:**
*   **Split Axis:** Typically the longest axis of the current region [S2].
*   **Split Position:** Determined by the median of cell centroids along the split axis [S2].
*   **Target Regions:** The desired number of leaf nodes in the tree [S2].

**Steps:**
1.  **Initial Distribution:** Data cells are initially distributed across processors [S1].
2.  **Synchronized Partitioning Loop:** All processors participate in a synchronized process to build the tree cooperatively [S1].
3.  **Local Cut Proposal:** Each processor examines its local collection of cells and establishes a local cutting position such that the two resulting sub-regions contain approximately the same number of cells [S1]. The direction of the cut alternates at each level of the partitioning [S1].
4.  **Global Cut Determination:** A designated host node receives proposed local cutting positions from each processor. It averages them to obtain a global cutting position [S1].
5.  **Broadcast:** The host node broadcasts the global cutting position and the next subregion to be partitioned to all processors [S1].
6.  **Cell Assignment:** Each processor assigns its cells to the appropriate region based on the global cut. A cell intersecting the cut boundary is assigned to the region containing its centroid [S1].
7.  **Recursive Selection (Alternative/Variant):** In some implementations, the median is found using a parallel selection algorithm (e.g., Floyd-Rivest) to rearrange array elements into those less than and greater than the proposed median [S2].
8.  **Prefetching:** When performing off-processor tests during parallel selection, a range of values is prefetched to improve run times [S2].
9.  **Recursion:** Steps 3-8 are repeated recursively on subregions until the desired number of regions is reached [S2].

*   **Unbalanced Tree:** The implementation does not guarantee a well-balanced tree [S1]. However, the extra searching overhead is insignificant compared to rendering calculation time [S1].

## Subtopics

### [KDTreeSamplingPartition](8210-kdtreesamplingpartition.md)
A distributed partitioning algorithm that builds a k-d tree structure over spatial data points by recursively splitting blocks along coordinate dimensions. It uses a sampling-based approach to determine split positions and manages neighbor links via a reduce proxy.

## Operating characteristics
*   **Time Complexity:** The parallel median find is the computationally intensive part. The Floyd-Rivest algorithm has sub-linear average comparisons with respect to array size, but worst-case behavior can degrade performance significantly on aligned data [S2].
*   **Memory Complexity:** Requires storage for the k-d tree structure and cell data distributed across processors [S1].
*   **Strengths:** Restores spatial ordering for early ray merging, reducing memory for unmerged ray segments and limiting list lengths [S1]. Supports adaptive partitioning along orthogonal planes and straightforward depth ordering determination [S1].
*   **Limitations:** Does not guarantee a well-balanced tree [S1]. Synchronization overhead for global cut determination [S1]. Vulnerable to worst-case performance on aligned data without modification [S2].
*   **When to Use:** When early ray merging is critical for performance and data is distributed across multiple processors [S1]. Preferred over octrees for adaptive partitioning and depth ordering [S1].

## Background
Parallel K-d Tree Construction was introduced in the context of scalable parallel cell-projection volume rendering [S1]. It was developed to address the loss of spatial relationships in unstructured datasets caused by load balancing, enabling efficient rendering through early ray merging [S1]. The method builds on the concept of recursive coordinate bisection, analyzed by Berger and Bokhari, and adapts the Floyd-Rivest selection algorithm for parallel median finding [S2].
