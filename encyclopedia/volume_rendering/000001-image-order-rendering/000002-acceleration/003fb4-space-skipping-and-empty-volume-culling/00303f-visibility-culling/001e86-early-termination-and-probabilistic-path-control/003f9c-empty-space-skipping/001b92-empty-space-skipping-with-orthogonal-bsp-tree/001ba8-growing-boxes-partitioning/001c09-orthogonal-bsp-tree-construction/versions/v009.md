# Orthogonal BSP Tree Construction

Also called: BSP tree conversion, Orthogonal BSP

## Overview
Orthogonal BSP Tree Construction converts a set of arbitrarily sized, grown boxes into a binary space-partitioning (BSP) tree where every splitting plane is object-aligned (parallel to the coordinate axes) [S1]. This structure enables trivial visibility sorting for 3D texture rendering, solving the problem that arbitrary box positions prevent simple front-to-back traversal [S1]. It sets itself apart from its parent method, [Growing Boxes Partitioning](1065-growing-boxes-partitioning.md), by imposing a strict hierarchical spatial index on the adaptive volumes, whereas the parent method only produces a flat list of clusters.

## How it works
**Inputs:** A list of grown boxes (from [Growing Boxes Partitioning](1065-growing-boxes-partitioning.md)). Each box has a bounding box, a type (uniform, gradient, other), and a parent pointer (initially null for original grown boxes).
**Outputs:** A BSP tree where leaf nodes contain exactly one box (either an original grown box or a child box generated from splitting). Non-leaf nodes contain lists of boxes and a "room" (the bounding box of their union).

**Data Structures:**
*   **Box:**
    *   `min`: 3D vector (min corner).
    *   `max`: 3D vector (max corner).
    *   `type`: Enum {uniform, gradient, other}.
    *   `parent`: Pointer to parent Box or null.
*   **BSP Node:**
    *   `boxes`: List of Box pointers.
    *   `room`: 3D bounding box (union of all boxes in `boxes`).
    *   `front`: Pointer to child BSP Node.
    *   `back`: Pointer to child BSP Node.
    *   `split_plane`: 3D vector (axis-aligned plane normal and distance, or axis index + coordinate).

**Algorithm Steps:**

1.  **Initialization:** Create a root BSP Node. Set its `boxes` list to all input grown boxes. Compute `room` as the union of all box bounding boxes.

2.  **Recursive Splitting:** Process a node $N$ with room $R$ and box list $L$.
    *   If $N$ is a leaf (e.g., contains only one box or meets a stopping criterion), return.
    *   **Choose Partitioning Plane:** Select an axis-aligned plane $P$ that coincides with the faces of at least two boxes in $L$ [S1]. The criterion is to minimize the number of boxes split by $P$ [S1].
    *   **Create Children:** Create two child nodes, $N_{front}$ and $N_{back}$.
    *   **Split Room:** Split $R$ by $P$ into two sub-boxes $R_{front}$ and $R_{back}$. Set $N_{front}.room = R_{front}$ and $N_{back}.room = R_{back}$.
    *   **Distribute Boxes:** For each box $B$ in $L$:
        *   If $B$ is completely enclosed in $R_{front}$, move $B$ to $N_{front}.boxes$.
        *   If $B$ is completely enclosed in $R_{back}$, move $B$ to $N_{back}.boxes$.
        *   If $B$ is cut by $P$:
            *   Split $B$ into $B_{front}$ and $B_{back}$ by $P$.
            *   Add $B_{front}$ to $N_{front}.boxes$ and $B_{back}$ to $N_{back}.boxes$.
            *   **Parent Hierarchy Management:**
                *   If $B.parent$ is null (original grown box): Set $B_{front}.parent = B$ and $B_{back}.parent = B$.
                *   Else: Set $B_{front}.parent = B.parent$ and $B_{back}.parent = B.parent$.
                *   Remove $B$ from $L$ (it is replaced by its children).
    *   **Recurse:** Call Split on $N_{front}$ and $N_{back}$.

3.  **Bottom-Up Merging:** After the tree is built, traverse it bottom-up to reduce node count. Merge $N_{front}$ and $N_{back}$ into a single node if:
    *   Both children are uniform boxes, and the merged box (union of their rooms) is still uniform.
    *   Both children are 'other' boxes or both are 'gradient' boxes.
    *   One of the boxes is tiny or very thin (size along one axis < threshold) [S1].
    *   **Merge Logic:** If merged, the new node's `boxes` list contains the union of the children's boxes. If the children had different parent boxes, those parent boxes are deleted, and all their children become parentless (their `parent` pointer becomes null). The type of the resulting merged box is redetermined based on enclosed voxel properties [S1].

**Pseudocode:**

```python
def split_node(node):
    if node.is_leaf():
        return

    # 1. Choose partitioning plane P that minimizes splits
    #    P must coincide with faces of at least two boxes in node.boxes
    plane = choose_optimal_plane(node.boxes, node.room)

    # 2. Create children and split room
    front_node = BSPNode()
    back_node = BSPNode()
    front_node.room, back_node.room = split_box(node.room, plane)

    node.front = front_node
    node.back = back_node

    # 3. Distribute boxes
    boxes_to_process = list(node.boxes)
    node.boxes = [] # Clear current list as boxes move to children

    for box in boxes_to_process:
        if box.is_enclosed_in(front_node.room):
            front_node.boxes.append(box)
        elif box.is_enclosed_in(back_node.room):
            back_node.boxes.append(box)
        elif box.is_cut_by(plane):
            # Split box
            front_box, back_box = split_box(box, plane)
            
            # Add to children
            front_node.boxes.append(front_box)
            back_node.boxes.append(back_box)
            
            # Manage parent hierarchy
            if box.parent is None:
                # Original grown box
                front_box.parent = box
                back_box.parent = box
            else:
                # Child box
                front_box.parent = box.parent
                back_box.parent = box.parent
            
            # Delete original box from current node's list (already cleared)
            # Note: The source implies the box is removed from the list being processed
        else:
            # Should not happen if plane is within room and box is within room
            pass

    # Recurse
    split_node(front_node)
    split_node(back_node)

def merge_bottom_up(node):
    if node.is_leaf():
        return

    merge_bottom_up(node.front)
    merge_bottom_up(node.back)

    if can_merge(node.front, node.back):
        # Merge logic
        merged_node = BSPNode()
        merged_node.room = union_boxes(node.front.room, node.back.room)
        merged_node.boxes = node.front.boxes + node.back.boxes
        
        # Redetermine type based on voxel properties
        merged_node.type = determine_type(merged_node.boxes)

        # Handle parent pointers
        # If children had different parents, delete those parents
        # and make their children parentless
        parents_to_delete = set()
        for box in merged_node.boxes:
            if box.parent is not None:
                parents_to_delete.add(box.parent)
        
        for parent in parents_to_delete:
            # Remove parent from its parent's children list if applicable
            # Set all children of this parent to have null parent
            for child in parent.children: # Assuming parent tracks children
                child.parent = None
        
        # Replace current node with merged_node in parent's reference
        # (Implementation detail: caller handles replacing node in parent)
        return merged_node
    else:
        return node

def can_merge(front_node, back_node):
    # Condition 1: Both uniform, merged is uniform
    if front_node.type == 'uniform' and back_node.type == 'uniform':
        if is_uniform(union_boxes(front_node.room, back_node.room)):
            return True
    
    # Condition 2: Both other or both gradient
    if front_node.type == back_node.type:
        if front_node.type in ['other', 'gradient']:
            return True
            
    # Condition 3: One is tiny/thin
    if is_tiny_or_thin(front_node.room) or is_tiny_or_thin(back_node.room):
        return True
        
    return False
```

**Parameters:**
*   **Threshold for tiny/thin:** Not given in the sources. [G] Typically a small fraction of the volume dimensions or a fixed voxel count.
*   **Stopping Criterion for Splitting:** Not given in the sources. [G] Typically when a node contains a single box or the box count is below a threshold.

**Edge Cases and Pitfalls:**
*   **Hierarchy Constraint:** No box can be a child and a parent at the same time. There is only one level of parent-child hierarchy. Parent boxes reside on non-leaf nodes; rendering uses only leaf nodes [S1].
*   **Texture Sharing:** Child boxes share the texture of their parent with siblings to avoid replicating texels along boundaries. Replicating texels would increase memory requirements [S1].
*   **Box Count:** The total number of boxes at leaf nodes after splitting can be significantly greater than the original grown boxes, necessitating the bottom-up merging step [S1].

## Subtopics

### [K-D Tree Hierarchy Construction](2300-k-d-tree-hierarchy-construction.md)
Builds a binary space-partitioning structure to organize geometric primitives for efficient spatial queries. It sets itself apart by storing polygons in leaf or internal nodes based on containment rather than splitting them, avoiding explicit clipping. It is view-independent, suitable for animation sequences.

## Operating characteristics
*   **Time Complexity:** Splitting requires iterating over boxes and potentially splitting them. Choosing the optimal plane requires checking candidate planes defined by box faces. Merging is a bottom-up pass. Exact complexity not given. [G] Likely $O(N \log N)$ or $O(N^2)$ depending on plane selection strategy, where $N$ is the number of boxes.
*   **Memory Complexity:** Stores boxes and tree nodes. Texture sharing reduces memory overhead compared to replicating textures. Exact complexity not given.
*   **Strengths:** Enables trivial visibility sorting for 3D texture rendering. Handles arbitrary box sizes and positions.
*   **Limitations:** Requires bottom-up merging to control box count. Texture sharing adds complexity to texture coordinate computation.
*   **When to use:** When using texture-based volume rendering with adaptive partitioning (grown boxes) and needing efficient visibility culling.
*   **When not to use:** When uniform partitioning is sufficient, or when geometric primitives are better suited for K-D trees.

## Background
Originated in the context of adaptive partitioning for texture-based volume rendering. The method addresses the issue that arbitrary box sizes and positions from adaptive partitioning prevent trivial visibility sorting [S1]. The conversion to an orthogonal BSP tree allows for efficient occlusion clipping and empty-space skipping.
