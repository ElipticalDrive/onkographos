# K-D Tree Hierarchy Construction

Also called: Polygon distribution in k-d tree, Spatial partitioning with k-d trees

## Overview
K-D Tree Hierarchy Construction is a method for building a spatial partitioning data structure to organize geometric primitives (typically polygons) for efficient rendering and ray tracing. It solves the problem of explicitly clipping polygons against view frustums or pixel boundaries by grouping them into hierarchical regions [S1]. It sets itself apart from its sibling [Orthogonal BSP Tree Construction](1134-orthogonal-bsp-tree-construction.md) by using a fixed axis-aligned splitting strategy (often round-robin or variance-based) rather than object-aligned planes derived from grown boxes, and from [Real-time KD Tree Construction](4437-real-time-kd-tree-construction.md) by focusing on the general algorithmic definition rather than GPU-specific parallel implementation details.

## How it works
**Inputs:** A set of polygons $P$, each defined by a list of vertices with coordinates $(x, y, z)$. A user-defined leaf threshold $T_{leaf}$ (integer).
**Outputs:** A binary tree where each node $v$ contains a list of polygon IDs, and pointers to left and right children. The polygons are stored in a flat array `Tid` in prefix-order traversal sequence.

**Data Structures:**
*   `Node`:
    *   `split_dim`: Integer, the dimension index ($0, 1, 2$) along which the region is split.
    *   `split_val`: Float, the coordinate value $X_i$ of the splitting hyperplane.
    *   `poly_ids`: List of integers, polygon IDs associated with this node.
    *   `left`: Pointer to child Node (or null).
    *   `right`: Pointer to child Node (or null).
*   `Tid`: Array of integers, storing polygon IDs. The position in `Tid` corresponds to the prefix-order traversal index of the node containing that polygon.

**Algorithm Steps:**
1.  **Initialization:** Create a root node $v_{root}$. Assign all input polygons to $v_{root}$.
2.  **Recursive Construction:** Define function `Build(node, polygons)`:
    a.  **Leaf Check:** If `len(polygons) <= T_leaf`, mark `node` as a leaf. Store `polygons` in `node.poly_ids`. Return.
    b.  **Axis Selection:** Determine the splitting dimension $i$.
        *   *Standard Approach:* Use round-robin selection based on tree depth (e.g., $i = \text{depth} \pmod 3$) [S1].
        *   *Variance Approach:* Calculate the variance of the QEF solution along each dimension, scaled by box size, and select the axis with maximum variance [S2, unofficial]. (See Subtopics for details).
    c.  **Split Value Determination:** Determine the splitting value $X_i$.
        *   *Standard Approach:* Bisect the region bounds along dimension $i$ [S1].
        *   *Note:* Any partitioning value $X_i$ can be chosen, but bisection is common [S1].
    d.  **Polygon Partitioning:** Initialize two empty lists: `left_polys` and `right_polys`. Initialize `node_polys` (polygons retained at this node).
    e.  For each polygon $p$ in `polygons`:
        i.  Check all vertices of $p$. Let $v_{x_i}$ be the coordinate of vertex $v$ along dimension $i$.
        ii. If $\forall v \in p, v_{x_i} < X_i$: Add $p$ to `left_polys`.
        iii. If $\forall v \in p, v_{x_i} > X_i$: Add $p$ to `right_polys`.
        iv. Otherwise (polygon intersects or straddles the plane): Add $p$ to `node_polys`.
    f.  **Node Assignment:** Store `node_polys` in `node.poly_ids`.
    g.  **Recursive Calls:**
        i.  If `left_polys` is not empty:
            1. Create `node.left`.
            2. Set `node.left.split_dim = (i + 1) \pmod 3` (for round-robin) or next axis.
            3. Set `node.left.split_val = X_i` (or appropriate value for left child if not simple bisection).
            4. `Build(node.left, left_polys)`.
        ii. If `right_polys` is not empty:
            1. Create `node.right`.
            2. Set `node.right.split_dim = (i + 1) \pmod 3` (for round-robin) or next axis.
            3. Set `node.right.split_val = X_i`.
            4. `Build(node.right, right_polys)`.

**Edge Cases and Pitfalls:**
*   **Polygon Association:** Polygons are associated with the smallest node region that completely contains them. This avoids subdividing polygons but means a polygon may be stored in an internal node if it straddles the split plane [S1].
*   **Precision:** Floating-point comparisons for vertex positions against $X_i$ must handle cases where vertices lie exactly on the plane. The logic "less than" and "greater than" must be consistent (e.g., strict inequality) to avoid infinite recursion or lost polygons [S1].
*   **Empty Subtrees:** If a partition results in an empty list for one side, that child is not created [S1].

**Pseudocode:**
```python
def build_kd_tree(polygons, threshold=10, depth=0):
    """
    Builds a K-D tree hierarchy.
    :param polygons: List of polygon objects, each having a method get_vertices() returning list of (x,y,z) tuples.
    :param threshold: Integer, minimum number of polygons to trigger a split.
    :param depth: Integer, current tree depth for axis selection.
    :return: Node object or None.
    """
    if len(polygons) <= threshold:
        return NodeLeaf(polygons)

    # Axis selection: Round-robin based on depth [S1]
    split_dim = depth % 3
    
    # Determine bounding box of current polygons to find split value
    # (Simplified: assume we have bounds or use median/bisector)
    # For bisection, we need min/max of split_dim across all vertices
    min_val = float('inf')
    max_val = float('-inf')
    for p in polygons:
        for v in p.get_vertices():
            coord = v[split_dim]
            if coord < min_val: min_val = coord
            if coord > max_val: max_val = coord
            
    # Bisect the region [S1]
    split_val = (min_val + max_val) / 2.0

    left_polys = []
    right_polys = []
    node_polys = []

    for p in polygons:
        vertices = p.get_vertices()
        all_less = True
        all_greater = True
        
        for v in vertices:
            coord = v[split_dim]
            if coord >= split_val:
                all_less = False
            if coord <= split_val:
                all_greater = False
        
        if all_less:
            left_polys.append(p)
        elif all_greater:
            right_polys.append(p)
        else:
            node_polys.append(p)

    # Create internal node
    node = NodeInternal(
        split_dim=split_dim,
        split_val=split_val,
        poly_ids=node_polys
    )

    # Recurse
    if left_polys:
        node.left = build_kd_tree(left_polys, threshold, depth + 1)
    if right_polys:
        node.right = build_kd_tree(right_polys, threshold, depth + 1)

    return node
```

## Subtopics

### Axis Selection via Variance
Selects the splitting axis by analyzing the variance of the QEF (Quadratic Error Function) solution along each dimension, scaled by the box size [S2, unofficial]. It solves the QEF to get an approximate solution and error, then calculates variance for each axis: $variance[i] = qef.getVariance(approximate) \times size[i]$ [S2, unofficial]. It selects the axis with maximum variance. If the size of the max-variance axis is less than 2, it falls back to $3 - maxVarDir - minVarDir$, and if that size is also less than 2, it falls back to the min-variance axis [S2, unofficial]. This is used in contexts like KdtreeISO [S2, unofficial].

### Parallel K-d Tree Construction
A cooperative parallel partitioning process where all processors participate in a synchronized partitioning after initial data distribution [S3]. A designated host node receives proposed local cutting positions from each processor, averages them to obtain a global cutting position, and broadcasts this position along with the next subregion to be partitioned [S3]. Cells intersecting the cut boundary are assigned to the region containing their centroid [S3]. It is preferred over octrees because it supports adaptive partitioning along orthogonal coordinate planes and allows straightforward determination of depth ordering [S3]. It does not guarantee a well-balanced tree, but the searching overhead is insignificant compared to rendering time [S3].

## Operating characteristics
*   **Time Complexity:** $O(N \log N)$ for balanced trees, where $N$ is the number of polygons. Construction is $O(N \log N)$ if splitting is efficient (e.g., median finding). Round-robin splitting is simple but may not produce optimal balance [S1].
*   **Memory Complexity:** $O(N)$ for storing polygons and tree nodes. The flat array `Tid` avoids linked list overhead [S1].
*   **Performance:** Extends to about 16 processors before contention becomes a serious drawback in parallel implementations [S1].
*   **Strengths:** Avoids explicit polygon clipping; efficient for spatial queries; supports adaptive partitioning [S1, S3].
*   **Limitations:** May produce unbalanced trees if data distribution is skewed or if splitting strategy is poor [S3]. Parallel construction requires synchronization [S3].

## Background
The k-d tree was introduced by Jon Bentley in 1975 [S1]. It has been used in direct volume rendering for irregular and multiple grids [S1]. The method of storing polygon IDs in prefix-order traversal order in a common array was developed to avoid the extra space of linked lists [S1].
