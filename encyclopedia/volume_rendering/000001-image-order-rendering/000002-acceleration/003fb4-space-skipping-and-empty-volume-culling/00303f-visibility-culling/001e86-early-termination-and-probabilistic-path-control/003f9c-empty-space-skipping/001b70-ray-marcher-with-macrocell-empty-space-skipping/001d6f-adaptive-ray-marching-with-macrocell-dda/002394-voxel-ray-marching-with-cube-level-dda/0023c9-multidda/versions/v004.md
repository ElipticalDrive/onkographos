# MultiDDA

Also called: 2-Level DDA (Brick Grid), Coarse-to-Fine Traversal, Nested DDA for hierarchical grids, Two-level DDA with brickmap

## Overview
MultiDDA is an acceleration method for volume rendering that performs incremental Digital Differential Analyzer (DDA) traversal over a two-level hierarchical grid to skip empty space more efficiently than a flat grid [S1, S2, unofficial]. It builds on [Voxel Ray Marching with Cube-Level DDA](3069-voxel-ray-marching-with-cube-level-dda.md) by replacing the single-level voxel traversal with a nested approach: a coarse traversal over "bricks" (8³ voxel blocks) followed by a fine traversal over individual voxels only within occupied bricks [S1, S2, unofficial]. It differs from its parent by explicitly decoupling the empty-space skipping logic into a separate coarse grid layer, whereas the parent uses a fixed-size cube-level DDA that may not align with the data structure's logical blocks [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray origin $O$, ray direction $D$, inverse direction $D^{-1}$, brick grid dimensions $B_{ext}$, brick size $S_b = 8$, voxel grid texture $V$, brick grid texture $Br$.
- Output: Index of the first occupied voxel along the ray, or 0 if empty.

**Data Structures:**
1.  **Brick Grid:** `Texture3D<uint> bricks` [S2, unofficial]. Each texel corresponds to an $8 \times 8 \times 8$ block of voxels. A value $>0$ indicates the brick is occupied; $0$ indicates empty.
2.  **Voxel Grid:** `Texture3D<uint> voxels` [S2, unofficial]. Stores the actual voxel data (e.g., density, color index).

**Algorithm Steps:**
1.  **Initialize Coarse DDA:** Calculate the initial brick cell $C_b$ and step parameters ($t_{next}$, $t_{delta}$, $step\_dir$) for the brick grid based on ray origin and direction, similar to standard voxel DDA [S2, unofficial].
2.  **Coarse Traversal Loop:** Iterate through the brick grid. The loop bound is typically $3 \times B_{ext}$ to ensure the ray exits the volume [S2, unofficial].
    a.  **Boundary Check:** If $C_b$ is outside $[min\_brick\_cell, max\_brick\_cell]$, return 0 [S2, unofficial].
    b.  **Occupancy Test:** Sample `bricks[C_b]`. If the value is 0, the brick is empty.
    c.  **Advance Coarse DDA:** Update $C_b$ using the DDA step logic:
        $$ axis\_mask = step(t_{next}, \min(t_{next.yzx}, t_{next.zxy})) $$
        $$ t_{next} += axis\_mask \cdot t_{delta} $$
        $$ C_b += int3(axis\_mask) \cdot step\_dir $$
    d.  **Fine Traversal:** If `bricks[C_b] > 0`, call `trace_brick(O, D, D^{-1}, t_{delta}, C_b, V)` [S2, unofficial].
        i.  Inside `trace_brick`, perform a standard DDA traversal within the $8 \times 8 \times 8$ local coordinates of the brick.
        ii. If an occupied voxel is found, return its global index.
        iii. If the brick is traversed without finding an occupied voxel, continue the coarse loop.
3.  **Return:** If the loop completes without finding a voxel, return 0.

**Pseudocode:**
```python
def multi_dda(O, D, D_inv, brick_grid_ext, voxels, bricks):
    # Initialize coarse DDA state for brick grid
    # Note: Exact initialization depends on ray-box intersection logic
    # Assuming standard DDA setup for a grid of size brick_grid_ext
    brick_cell = int3(floor(O / 8.0)) # Assuming brick size is 8
    t_delta = float3(abs(D_inv) * 8.0) # Step size in t for one brick
    t_next = float3(0.0)
    step_dir = int3(sign(D))
    
    # Adjust t_next for initial brick
    # This is a simplified representation; actual DDA requires precise t_max calculations
    # [G] Standard DDA initialization: calculate t_max for each axis at entry point
    for axis in range(3):
        if D[axis] > 0:
            t_next[axis] = (brick_cell[axis] + 1 - O[axis] / D[axis]) * abs(D_inv[axis])
        else:
            t_next[axis] = (brick_cell[axis] - O[axis] / D[axis]) * abs(D_inv[axis])

    for i in range(3 * brick_grid_ext):
        # Boundary check
        if any(brick_cell < 0) or any(brick_cell >= brick_grid_ext):
            return 0

        # Check if brick is occupied
        # [G] Assuming bricks is a 3D texture lookup
        brick_val = bricks[brick_cell]
        
        if brick_val > 0:
            # Trace inside the brick
            # Local coordinates relative to brick origin
            local_origin = O - float3(brick_cell) * 8.0
            # Re-normalize DDA for the brick's local space
            # [G] The direction and inverse direction remain the same, 
            # but t_delta and t_next must be reset for the 8x8x8 space
            local_t_delta = abs(D_inv) * 8.0 # Step for one voxel
            local_t_next = float3(0.0)
            local_cell = int3(floor(local_origin / 1.0)) # Voxel coordinates
            
            # Reset t_next for local DDA
            for axis in range(3):
                if D[axis] > 0:
                    local_t_next[axis] = (local_cell[axis] + 1 - local_origin[axis] / D[axis]) * abs(D_inv[axis])
                else:
                    local_t_next[axis] = (local_cell[axis] - local_origin[axis] / D[axis]) * abs(D_inv[axis])

            # Inner DDA loop for the brick
            for j in range(8 * 8 * 8): # Max voxels in brick
                if any(local_cell < 0) or any(local_cell >= 8):
                    break
                
                # Check voxel occupancy
                voxel_val = voxels[local_cell]
                if voxel_val > 0:
                    return voxel_val # Or return index/color
                
                # Advance local DDA
                axis_mask = step(local_t_next, min(local_t_next.yzx, local_t_next.zxy))
                local_t_next += axis_mask * local_t_delta
                local_cell += int3(axis_mask) * step_dir
            
            # If we exit the inner loop without finding a voxel, continue outer loop
            # [G] No need to update brick_cell here, it happens at the end of outer loop
        
        # Advance coarse DDA
        axis_mask = step(t_next, min(t_next.yzx, t_next.zxy))
        t_next += axis_mask * t_delta
        brick_cell += int3(axis_mask) * step_dir

    return 0
```

**Parameters:**
- `brick_grid_ext`: Side length of the brick grid. [S2, unofficial]
- Brick size: Fixed at $8 \times 8 \times 8$ voxels in the primary implementation [S1, S2, unofficial].

**Edge Cases and Pitfalls:**
- **SIMD Divergence:** Incoherent rays cause control-flow divergence when entering the inner traversal loop, as not all SIMD lanes hit a brick at the same time, leading to stalls [S1, unofficial].
- **Dense Scenes:** In dense scenes or when viewing from afar with loose brick sizes, the overhead of two-level traversal may not provide gains over naive DDA if the brick grid is not selective enough [S2, unofficial].
- **Viewing Angle:** Performance degrades significantly when viewing along a surface inside a brick, as the full brick and voxel traversal is required [S2, unofficial].

## Subtopics

### [VRI Ray Advancement](3187-vri-ray-advancement.md)
A three-level hierarchical traversal method that separates traversal into draining the current I1 DDA, stepping the I2 DDA, and advancing to the next root entry. It differs from MultiDDA by managing three distinct node types (I2, I1, leaf) rather than two levels of DDA loops.

## Operating characteristics
- **Time Complexity:** $O(N_{bricks} + N_{voxels\_in\_occupied\_bricks})$ in the worst case, but significantly reduced in sparse scenes.
- **Memory Complexity:** Requires storage for both the voxel grid and the brick grid. The brick grid adds overhead but allows for faster empty-space skipping [S1, S2, unofficial].
- **Performance:**
    - In sparse scenes (e.g., sponza-256-2), MultiDDA provides significant speedups: FPS increased by +184.93% and walltime decreased by -82.73% compared to naive DDA [S2, unofficial].
    - In dense scenes (e.g., sponza-256-1), the impact is minimal: FPS increased by only +0.04% [S2, unofficial].
- **Strengths:** Simple to implement, effective for scenes with large empty spaces, improves throughput for incoherent rays by ~30-50% compared to flat DDA [S1, unofficial].
- **Limitations:** Suffers from SIMD divergence due to nested loops, less effective in dense scenes or with poor brick granularity [S1, S2, unofficial].

## Background
MultiDDA was developed as part of the VoxelRT project, an experimental voxel rendering framework [S1, unofficial]. It was introduced in July 2026 as a "2-level DDA" optimization to improve empty-space skipping performance over a flat voxel grid [S2, unofficial]. The method is a direct response to the limitations of naive DDA in sparse volumes, leveraging the hierarchical nature of voxel data to skip large empty regions [S1, S2, unofficial].
