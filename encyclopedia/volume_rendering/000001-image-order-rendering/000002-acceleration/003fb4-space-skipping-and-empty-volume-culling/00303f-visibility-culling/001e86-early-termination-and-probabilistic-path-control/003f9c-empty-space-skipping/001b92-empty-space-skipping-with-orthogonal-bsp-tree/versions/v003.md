# Empty Space Skipping with Orthogonal BSP Tree

Also called: Empty space skipping with texture hulls, Growing boxes with orthogonal BSP, Orthogonal BSP tree empty space skipping, Texture Hulls with BSP Tree

## Overview
An acceleration technique for texture-based volume rendering that partitions a volume into sub-volumes based on voxel properties, reorganizes them into an orthogonal Binary Space Partitioning (BSP) tree, and skips sub-volumes that are fully transparent according to the transfer function [S1, S2]. It sets itself apart from sibling methods like [Empty Space Skipping with Octree](1610-empty-space-skipping-with-octree.md) by using an orthogonal BSP tree to handle the arbitrary slicing plane orientations inherent in 3D texture rendering, whereas octrees typically rely on axis-aligned hierarchical subdivision that may not align with the view-dependent sorting requirements of texture slicing [S1].

## How it works
**Inputs:**
- A 3D volume dataset represented as one or more 3D textures [S1].
- A transfer function mapping density (and optionally gradient magnitude) to color and opacity [S1].
- A camera configuration (viewpoint for perspective, or view direction for parallel projection) [S1].

**Outputs:**
- A rendered image identical to the unaccelerated result [S1].
- An orthogonal BSP tree structure representing the spatial partitioning of the volume [S1].

**Data Structures:**
1.  **Sub-volume (Box):** An axis-aligned bounding box enclosing a set of voxels. It contains:
    -   `min`: 3D vector $(x_{min}, y_{min}, z_{min})$ representing the lower corner of the box in texture space.
    -   `max`: 3D vector $(x_{max}, y_{max}, z_{max})$ representing the upper corner of the box in texture space.
    -   `type`: Enum indicating if the box is a "uniform box" (based on density range) or a "gradient box" (based on non-zero gradient magnitude) [S1].
2.  **Orthogonal BSP Tree:** A binary tree where each node represents a partitioning plane orthogonal to one of the major axes (X, Y, or Z).
    -   `node`: Contains a `plane_normal` (one of $\pm \hat{x}, \pm \hat{y}, \pm \hat{z}$), a `plane_offset` (scalar distance from origin along the normal), and two children (`left`, `right`).
    -   `leaf`: Contains a list of sub-volume boxes that fall within that partition [S1].

**Steps:**

1.  **Partitioning (Growing Boxes):**
    Group voxels with similar properties in both the volume domain (position) and the transfer function domain (density and gradient magnitude) into sub-volumes [S1].
    -   **Uniform Boxes:** Partition neighboring texels whose densities vary in a small range. A typical parameter value for this density range is 32 [S1]. These boxes enclose regions where voxels are mapped to similar opacities.
    -   **Gradient Boxes:** For lit rendering, separate voxels with non-zero gradient magnitude from the rest. This ensures that only surface voxels (which contribute to lighting) are processed, avoiding unnecessary lighting computations for interior voxels with zero gradient [S1].
    -   The process is a direct one-stage goal-oriented growth, clustering voxels to ensure visible boxes enclose few invisible voxels [S1].

2.  **Texture Hull Computation:**
    Compute texture hulls of all connected non-empty regions. This step identifies the spatial extent of regions that contain non-transparent data [S2].

3.  **Visibility Classification:**
    Classify each sub-volume as invisible if it is comprised *only* of voxels mapped to empty (fully transparent) by the transfer function. These sub-volumes are marked for skipping [S1].

4.  **BSP Tree Construction:**
    Reorganize the arbitrary set of sub-volume bounding boxes into an orthogonal BSP tree [S1].
    -   All partitioning planes in the tree are orthogonal to a major axis (X, Y, or Z) [S1].
    -   This orthogonality simplifies the visibility sorting process compared to arbitrary planes [S1].

5.  **Visibility Sorting:**
    Determine the rendering order of the sub-volumes based on the camera configuration.
    -   For perspective projection, sort based on the viewpoint.
    -   For parallel projection, sort based on the view direction.
    -   The tree must be resorted whenever the viewpoint or view direction changes [S1].

6.  **Incremental Intersection Computation:**
    Compute the intersection of the axis-aligned sub-volumes with the slicing planes incrementally [S1].
    -   This avoids the overhead of computing intersections and texture coordinates from scratch for each partition [S1].
    -   The algorithm leverages the coherence between adjacent slices to update intersection points efficiently [S1].

7.  **Rendering:**
    Render the sub-volumes in the visibility order determined by the BSP tree.
    -   Skip any sub-volume classified as invisible in Step 3 [S1].
    -   Use the incremental intersection results to sample the 3D texture [S1].

**Pseudocode:**

```python
def build_orthogonal_bsp_tree(sub_volumes):
    """
    Constructs an orthogonal BSP tree from a list of sub-volume boxes.
    sub_volumes: List of Box objects with min, max, and type.
    Returns: Root Node of the BSP tree.
    """
    if not sub_volumes:
        return None
    
    # Select axis with largest extent among all boxes
    extents = [
        max(b.max.x - b.min.x for b in sub_volumes),
        max(b.max.y - b.min.y for b in sub_volumes),
        max(b.max.z - b.min.z for b in sub_volumes)
    ]
    axis = extents.index(max(extents))
    
    # Sort boxes by their center along the selected axis
    centers = [get_center(b, axis) for b in sub_volumes]
    sorted_indices = sorted(range(len(sub_volumes)), key=lambda k: centers[k])
    sorted_boxes = [sub_volumes[i] for i in sorted_indices]
    
    # Split into two halves
    mid = len(sorted_boxes) // 2
    left_boxes = sorted_boxes[:mid]
    right_boxes = sorted_boxes[mid:]
    
    # Create partitioning plane
    # Plane is orthogonal to the selected axis, passing through the midpoint
    # of the split point's extent
    split_box = sorted_boxes[mid]
    plane_offset = get_coord(split_box.min, axis) # Or midpoint, implementation detail [G]
    
    left_node = build_orthogonal_bsp_tree(left_boxes)
    right_node = build_orthogonal_bsp_tree(right_boxes)
    
    return Node(axis=axis, offset=plane_offset, left=left_node, right=right_node)

def get_center(box, axis):
    return (box.min[axis] + box.max[axis]) / 2.0

def get_coord(box, axis):
    return box.min[axis]

def render_volume(camera, bsp_root, transfer_function):
    """
    Renders the volume using the BSP tree for visibility sorting.
    """
    # Resort tree if camera changed
    if camera_changed:
        resort_bsp_tree(bsp_root, camera)
    
    render_recursive(bsp_root, camera, transfer_function)

def render_recursive(node, camera, transfer_function):
    if node is None:
        return
    
    # Check if node's region is fully transparent
    if is_fully_transparent(node, transfer_function):
        return
    
    # Determine visibility order based on camera
    # For orthogonal BSP, this is simplified by axis alignment
    if is_behind_camera(node, camera):
        return
    
    # Render children in correct order
    # Left child is 'behind' or 'left' depending on axis and view
    # Right child is 'in front' or 'right'
    # Note: Exact order depends on camera direction relative to axis [G]
    if node.axis == 0: # X-axis
        if camera.view_direction.x > 0:
            render_recursive(node.left, camera, transfer_function)
            render_recursive(node.right, camera, transfer_function)
        else:
            render_recursive(node.right, camera, transfer_function)
            render_recursive(node.left, camera, transfer_function)
    elif node.axis == 1: # Y-axis
        if camera.view_direction.y > 0:
            render_recursive(node.left, camera, transfer_function)
            render_recursive(node.right, camera, transfer_function)
        else:
            render_recursive(node.right, camera, transfer_function)
            render_recursive(node.left, camera, transfer_function)
    else: # Z-axis
        if camera.view_direction.z > 0:
            render_recursive(node.left, camera, transfer_function)
            render_recursive(node.right, camera, transfer_function)
        else:
            render_recursive(node.right, camera, transfer_function)
            render_recursive(node.left, camera, transfer_function)

def is_fully_transparent(node, transfer_function):
    """
    Returns True if all sub-volumes in this node's leaf list are fully transparent.
    """
    if node.left is None and node.right is None:
        # Leaf node
        for box in node.boxes:
            if not box.is_transparent(transfer_function):
                return False
        return True
    else:
        return is_fully_transparent(node.left, transfer_function) and \
               is_fully_transparent(node.right, transfer_function)
```

**Edge Cases and Pitfalls:**
-   **Viewpoint Changes:** The BSP tree must be resorted whenever the viewpoint (perspective) or view direction (parallel) changes. Failure to do so results in incorrect rendering order and artifacts [S1].
-   **Arbitrary Slicing Planes:** Unlike 2D texture stacks, 3D textures involve arbitrary slicing plane orientations. The orthogonal BSP tree is specifically designed to handle this, but the sorting logic must correctly account for the plane normal relative to the view direction [S1].
-   **Lighting Overhead:** Without gradient boxes, uniform boxes may include many interior voxels with zero gradient magnitude, leading to unnecessary lighting computations. The separation of gradient boxes is critical for lit rendering performance [S1].

## Subtopics

### [Growing Boxes Partitioning](1065-growing-boxes-partitioning.md)
An adaptive volume partitioning method that divides a volume into sub-volumes (boxes) by clustering voxels based on their properties in both the volume domain and the transfer function domain. It separates surface voxels from interior voxels to optimize lit rendering, using a direct one-stage goal-oriented growth process. Choose this when you need to minimize unnecessary lighting computations in textured volume rendering.

## Operating characteristics
-   **Time Complexity:** The construction of the BSP tree is $O(N \log N)$ where $N$ is the number of sub-volumes, assuming balanced splitting. Rendering time depends on the number of visible sub-volumes and the cost of incremental intersection computation.
-   **Memory Complexity:** $O(N)$ to store the sub-volumes and the BSP tree structure.
-   **Measured Performance:** Rendering with empty space skipping is 2 to 5 times faster than without it, with identical image quality [S1].
-   **Strengths:**
    -   Handles 3D textures effectively, which produce better image quality than stacks of 2D textures [S1].
    -   Orthogonal BSP tree simplifies visibility sorting for arbitrary slicing planes [S1].
    -   Incremental intersection computation minimizes overhead [S1].
-   **Limitations:**
    -   Requires resorting the tree for every viewpoint or view direction change [S1].
    -   Partitioning strategy (uniform vs. gradient boxes) must be tuned for the specific transfer function and lighting model [S1].
-   **When to Use:** Texture-based volume rendering with 3D textures, especially when lighting is involved and empty space skipping is beneficial.
-   **When Not to Use:** When the volume is mostly opaque or has very little empty space, the overhead of partitioning and sorting may outweigh the benefits.

## Background
-   **Origin:** Proposed by Li, Mueller, and colleagues at Stony Brook University [S1].
-   **History:** The method extends previous work on empty space skipping using stacks of 2D textures [S1]. It was developed to address the challenges of sorting sub-volumes for 3D textures, which have arbitrary slicing plane orientations [S1].
-   **Usage:** Used in texture-based volume rendering pipelines on commodity GPU hardware [S1].
