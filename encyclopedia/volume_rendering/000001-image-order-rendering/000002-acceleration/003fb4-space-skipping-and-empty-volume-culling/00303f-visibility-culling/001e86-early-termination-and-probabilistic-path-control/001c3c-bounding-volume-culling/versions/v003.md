# Bounding Volume Culling

Also called: Distance-based Culling, Ray Termination by Distance

## Overview
Bounding Volume Culling is an optimization that limits ray marching to a specific geometric region, dropping rays that exceed a predefined distance from the eye or exit a bounding volume to accelerate rendering [S1, unofficial]. It differs from its sibling [Empty-space skipping](1002-empty-space-skipping.md), which skips empty regions within a volume, by entirely discarding rays that traverse beyond a global or local distance limit [S1, unofficial]. Unlike [Early ray termination](1019-early-ray-termination.md), which stops based on accumulated opacity, Bounding Volume Culling relies on geometric traversal distance [S1, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, maximum travel distance $t_{\text{max}}$, and a distance field function $S(\mathbf{p})$ returning the distance to the closest surface from point $\mathbf{p}$ [S1, unofficial].
**Outputs:** Accumulated color and opacity, or a terminated state if $t > t_{\text{max}}$ [S1, unofficial].

**Data Structures:**
*   $t$: Scalar float, total distance traveled along the ray. Initialized to 0.0 [S1, unofficial].
*   $t_{\text{max}}$: Scalar float, the predefined limit. [S1, unofficial].

**Steps:**
1.  Initialize $t = 0.0$ [S1, unofficial].
2.  Loop while $t < t_{\text{max}}$:
    a. Evaluate the current position $\mathbf{p} = \mathbf{o} + t \cdot \mathbf{d}$ [S1, unofficial].
    b. Compute the distance to the closest surface $d = S(\mathbf{p})$ [S1, unofficial].
    c. Perform front-to-back compositing update using $d$ as the step size or sample parameter [S1, unofficial].
    d. Update $t \leftarrow t + d$ (or step size) [S1, unofficial].
    e. **Termination Check:** If $t \ge t_{\text{max}}$, break the loop and return the accumulated result [S1, unofficial].

**Edge Cases:**
*   If $t_{\text{max}}$ is too small, valid geometry may be clipped.
*   Precision errors in $t$ accumulation may cause rays to slightly overshoot or undershoot the boundary [G].

```python
def bounding_volume_culling(ray_origin, ray_direction, max_distance, distance_field):
    t = 0.0
    accumulated_color = (0.0, 0.0, 0.0)
    accumulated_alpha = 0.0
    
    while t < max_distance:
        # Current position
        p = ray_origin + t * ray_direction
        
        # Distance to closest surface
        d = distance_field(p)
        
        # Safety guard: if d is non-positive or too small, break to avoid infinite loops
        if d <= 0.0 or d < 1e-6:
            break
            
        # Sample color and alpha at p using step size d
        # Note: Standard sphere tracing uses d as step size
        color_sample, alpha_sample = sample_volume(p, d)
        
        # Front-to-back compositing
        # C_acc = C_acc + C_sample * alpha_sample * (1 - alpha_acc)
        # alpha_acc = alpha_acc + alpha_sample * (1 - alpha_acc)
        # [Implementation detail: specific compositing formula depends on parent method]
        
        # Advance ray
        t += d
        
        # Check bounding volume limit
        if t >= max_distance:
            break
            
    return accumulated_color, accumulated_alpha
```

## Subtopics

### Heap-based Bounding Volume Culling for Sphere Tracing
An algorithm to find the closest object in a collection by maintaining a heap of bounding volume distances. It computes distances to bounding volumes first, then contents, culling based on the smallest bounding volume distance [S2]. It differs from standard culling by dynamically managing the active set of distance fields based on ray proximity, deferring expensive content distance calculations until necessary [S2].

**Steps:**
1.  Compute distances to each bounding volume in the union/collection [S2].
2.  Create a min-heap of these distances [S2].
3.  Initialize $d_{\text{min}} = \infty$ [S2].
4.  Loop:
    a. Let $d_{\text{content}}$ be $\min(d_{\text{min}}, \text{distance to contents of top BV})$ [S2].
    b. Remove top of heap [S2].
    c. Let $d_{\text{bv}}$ be the distance to the new top BV (or $\infty$ if empty) [S2].
    d. Stop if $d_{\text{content}} < d_{\text{bv}}$ or heap is empty [S2].
    e. Update $d_{\text{min}} = d_{\text{content}}$ [S2].
5.  Return $d_{\text{content}}$ [S2].

**Parameters:**
*   $d_{\text{bv}}$: The distance to the bounding volume currently at the top of the heap [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray if a single global bound is used [S1, unofficial]. For heap-based variants, $O(\log N)$ per step where $N$ is the number of bounding volumes [S2].
*   **Memory Complexity:** $O(1)$ for global bounds; $O(N)$ for heap-based variants storing bounding volume distances [S2].
*   **Strengths:** Significantly reduces the number of distance field evaluations for rays that miss the scene or travel far into empty space [S1, unofficial][S2].
*   **Limitations:** Does not help with rays that stay within the bound but traverse complex geometry; overhead of heap management may negate benefits for small collections [S2].
*   **When to use:** When the scene has significant empty space or when rays frequently miss the target geometry [S1, unofficial].

## Background
Originating from early ray marching and sphere tracing techniques, this method leverages the fact that ray marching steps accumulate distance [S1, unofficial]. It is commonly used in distance field rendering to prevent infinite loops and to limit computational effort to relevant regions [S1, unofficial]. The heap-based variant was introduced to optimize sphere tracing for collections of implicit surfaces [S2].
