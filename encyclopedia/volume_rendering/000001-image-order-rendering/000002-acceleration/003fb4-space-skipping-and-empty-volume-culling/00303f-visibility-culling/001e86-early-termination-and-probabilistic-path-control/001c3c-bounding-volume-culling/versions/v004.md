# Bounding Volume Culling

Also called: Distance-based Culling, Ray Termination by Distance

## Overview
Bounding Volume Culling is an optimization that limits raymarching to a specific bounding volume, dropping rays that exceed a certain distance from the eye to speed up rendering [S1, unofficial]. It differs from its siblings, such as [Early ray termination](1019-early-ray-termination.md) which terminates based on accumulated opacity, by terminating based on geometric distance traveled [S1, unofficial]. It is distinct from [Empty-space skipping](1002-empty-space-skipping.md) which skips empty regions, as Bounding Volume Culling actively discards rays that have traveled too far, regardless of whether the space is empty or filled, provided it is outside the defined bounds [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, maximum travel distance $T_{max}$.
*   **Output:** A boolean indicating whether the ray should be terminated early, or a modified ray segment $[\mathbf{o}, \mathbf{o} + T_{max}\mathbf{d}]$.

**Data Structures:**
*   $T_{max}$: A scalar float representing the maximum distance from the ray origin that is considered valid for rendering.

**Steps:**
1.  Initialize the total distance traveled $t = 0$.
2.  During the raymarching loop, after each step, update $t$ by adding the step size $\Delta t$:
    $$ t = t + \Delta t $$
3.  Check if $t > T_{max}$.
4.  If true, terminate the raymarch process immediately [S1, unofficial].

**Pseudocode:**
```python
def bounding_volume_culling(ray_origin, ray_direction, max_distance):
    """
    Determines if a ray should be terminated based on distance traveled.
    
    Args:
        ray_origin: Vector3, origin of the ray.
        ray_direction: Vector3, normalized direction of the ray.
        max_distance: Float, the maximum allowed distance from the origin.
        
    Returns:
        Boolean, True if the ray has exceeded the bounding volume and should be culled.
    """
    # Note: In a full implementation, this check is performed inside the marching loop.
    # Here we simulate the state after a step.
    
    # Current position along the ray
    current_position = ray_origin + ray_direction * current_step_distance
    
    # Calculate Euclidean distance from origin
    distance_traveled = length(current_position - ray_origin)
    
    # Check against bounding volume limit
    if distance_traveled > max_distance:
        return True # Cull the ray
        
    return False # Continue marching
```

**Parameters:**
*   $T_{max}$: The predefined limit. Typical values depend on the scene scale. For unit-sized implicit surfaces, this might be 10.0 [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors in $t$ accumulation can cause premature or delayed termination. Using the exact distance from the origin ($\|\mathbf{p} - \mathbf{o}\|$) is more robust than accumulating $\Delta t$ if the step sizes vary significantly [S1, unofficial].
*   **Boundary Artifacts:** Rays terminating exactly at $T_{max}$ may leave visible artifacts if the geometry extends slightly beyond due to sampling noise. A small epsilon margin is often added [G].

## Subtopics

### [Bounding Spheres Optimization](1567-bounding-spheres-optimization.md)
Bounding Spheres Optimization reduces the computational cost of sphere tracing by grouping scene objects into larger enclosing spheres, thereby eliminating unnecessary distance calculations during ray traversal. It differs from its parent, [Bounding Volume Culling](1239-bounding-volume-culling.md), which typically discards rays entirely based on geometric bounds, by deferring the evaluation of individual object distances until the ray actually penetrates the enclosing volume. Unlike [Orthogonal Culling Optimization](4034-orthogonal-culling-optimization.md), which pre-computes object visibility via orthogonal projection to reduce per-step evaluations, Bounding Spheres Optimization dynamically manages the active set of distance fields based on ray proximity.

### Heap-based Bounding Volume Culling for Sphere Tracing
An algorithm to find the closest object in a collection by maintaining a heap of bounding volume distances. It computes distances to bounding volumes first, then contents, culling based on the smallest bounding volume distance [S2].

**Steps:**
1.  Compute distances to each bounding volume in the union/collection.
2.  Create a heap of these distances.
3.  Initialize $d_{min}$ to infinity.
4.  Loop: Let $d_{content}$ be $\min(d_{min}, \text{distance to contents of top BV})$.
5.  Remove top of heap.
6.  Let $d_{bv}$ be distance to new top BV.
7.  Stop if $d_{content} < d_{bv}$ or heap empty.
8.  Return $d_{content}$ [S2].

**Parameters:**
*   $d_{bv}$: The distance to the bounding volume currently at the top of the heap [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray for simple distance culling. For heap-based variants, $O(N \log N)$ for heap construction and $O(\log N)$ per query, where $N$ is the number of bounding volumes [S2].
*   **Memory Complexity:** $O(N)$ to store bounding volumes and the heap [S2].
*   **Strengths:** Significantly reduces the number of expensive distance function evaluations for rays that miss the scene or travel far into empty space [S2].
*   **Limitations:** Requires pre-computation of bounding volumes. The overhead of computing bounding volume distances may outweigh benefits for simple scenes or perspective cameras if not optimized [S2].
*   **When to use:** Scenes with large empty spaces or distant objects.
*   **When not to use:** Scenes where rays are likely to intersect objects close to the camera, or where the bounding volume computation cost is high relative to the savings [S2].

## Background
Bounding volume culling in the context of raymarching distance fields was discussed in early online tutorials and presentations on the topic [S1, unofficial]. The geometric method of sphere tracing and the use of bounding volumes to cull distance computations were formalized in the seminal paper "Sphere Tracing: A Geometric Method for the Antialiased Ray Tracing of Implicit Surfaces" [S2].
