# Frustum Culling (Sphere vs Frustum)

Also called: Chunk Frustum Culling, SIMD Sphere/Frustum Culling, Sphere vs Frustum Culling

## Overview
Frustum culling for spheres is a geometric rejection technique used to discard bounding volumes that do not intersect the camera's view frustum, thereby avoiding expensive ray-sphere intersection tests during volume rendering traversal [S1]. Unlike SIMD shaft culling, which is restricted to primitives with planar edges such as triangles, this method is specifically designed for spherical bounding volumes and operates by comparing the signed distance from a sphere's center to the frustum planes against the sphere's radius [S1]. It serves as an optimization within the Bounding Spheres Optimization framework, building on [Bounding Spheres Optimization](1567-bounding-spheres-optimization.md) to eliminate unnecessary distance computations for spheres that lie outside the view volume [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A list of spheres (or chunks), each defined by a center position $\mathbf{c}$ and a radius $r$. The camera frustum is defined by its origin (camera position $\mathbf{p}$), forward vector $\mathbf{f}$, up vector $\mathbf{u}$, right vector $\mathbf{r}$, and clipping distances $d_{near}$ and $d_{far}$ [G].
*   **Output:** A subset of spheres that potentially intersect the frustum [S1].

**Data Structures:**
The sphere is represented as a structure containing:
*   `center`: A 3D vector $(x, y, z)$ [G].
*   `radius`: A scalar float [G].

The camera frustum is represented by:
*   `position`: The camera origin $\mathbf{p}$ [G].
*   `forward`: Unit vector $\mathbf{f}$ pointing along the viewing axis [G].
*   `up`: Unit vector $\mathbf{u}$ perpendicular to $\mathbf{f}$ [G].
*   `right`: Unit vector $\mathbf{r}$ perpendicular to $\mathbf{f}$ and $\mathbf{u}$, computed as $\mathbf{f} \times \mathbf{u}$ (normalized) [G].
*   `tan_x`: Tangent of the horizontal field of view angle or derived value [S2, unofficial].
*   `tan_y`: Tangent of the vertical field of view angle [S2, unofficial].
*   `factor_x`: Scaling factor for the horizontal frustum width [S2, unofficial].
*   `factor_y`: Scaling factor for the vertical frustum height [S2, unofficial].
*   `near`: Near clipping plane distance $d_{near}$ [S2, unofficial].
*   `far`: Far clipping plane distance $d_{far}$ [S2, unofficial].

**Parameters:**
*   $d_{near}$: Near clipping plane distance. Typical value: $0.1$ [S2, unofficial].
*   $d_{far}$: Far clipping plane distance. Typical value: $2000.0$ [S2, unofficial].
*   $R_{max}$: Maximum radius of spheres considered for the "enlarged frustum" test. Spheres with $r < R_{max}$ may pass the enlarged frustum test but fail the original frustum test [S1]. In chunk-based culling, $R_{max}$ corresponds to the chunk bounding sphere radius [S2, unofficial]. For a chunk of size $CHUNK\_SIZE$, the half-size is $H\_CHUNK\_SIZE = CHUNK\_SIZE // 2$ [S2, unofficial]. The chunk bounding sphere radius is $R = H\_CHUNK\_SIZE \times \sqrt{3}$ [S2, unofficial]. For $CHUNK\_SIZE = 48$, $R \approx 41.57$ [S2, unofficial].

**Algorithm Steps:**
1.  Compute the vector from the camera position to the sphere center: $\mathbf{v} = \mathbf{c} - \mathbf{p}$ [S2, unofficial].
2.  Project $\mathbf{v}$ onto the camera's forward, up, and right axes to get coordinates in the camera's local space:
    *   $z_{cam} = \mathbf{v} \cdot \mathbf{f}$ [S2, unofficial]
    *   $y_{cam} = \mathbf{v} \cdot \mathbf{u}$ [S2, unofficial]
    *   $x_{cam} = \mathbf{v} \cdot \mathbf{r}$ [S2, unofficial]
3.  **Far/Near Plane Test:** Check if the sphere is within the depth range of the frustum, accounting for its radius. The sphere is outside if $z_{cam} < d_{near} - r$ or $z_{cam} > d_{far} + r$ [S2, unofficial].
4.  **Side Plane Tests:** Check if the sphere is within the horizontal and vertical extents of the frustum at depth $z_{cam}$. The frustum width and height at depth $z_{cam}$ are proportional to $z_{cam} \times \tan(\theta)$ [S2, unofficial].
    *   Calculate the maximum allowed horizontal extent at $z_{cam}$: $W_{max} = r + z_{cam} \times \text{tan\_x} \times \text{factor\_x}$ [S2, unofficial].
    *   Calculate the maximum allowed vertical extent at $z_{cam}$: $H_{max} = r + z_{cam} \times \text{tan\_y} \times \text{factor\_y}$ [S2, unofficial].
    *   The sphere is outside if $|x_{cam}| > W_{max}$ or $|y_{cam}| > H_{max}$ [S2, unofficial].
5.  If the sphere passes all tests, it is retained for further intersection testing [S1].

**Pseudocode:**
```python
def is_sphere_in_frustum(sphere_center, sphere_radius, camera):
    # Vector from camera to sphere center
    v = sphere_center - camera.position
    
    # Project onto camera axes
    sz = dot(v, camera.forward)
    sy = dot(v, camera.up)
    sx = dot(v, camera.right)
    
    # Far/Near plane test
    if sz < camera.near - sphere_radius or sz > camera.far + sphere_radius:
        return False
    
    # Side plane tests
    # Note: Reference implementation uses a fixed CHUNK_SPHERE_RADIUS for the offset [S2, unofficial]
    max_x = sphere_radius + sz * camera.tan_x * camera.factor_x
    if sx < -max_x or sx > max_x:
        return False
        
    max_y = sphere_radius + sz * camera.tan_y * camera.factor_y
    if sy < -max_y or sy > max_y:
        return False
        
    return True
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors can cause spheres on the boundary of the frustum to be incorrectly culled or retained. Using a small epsilon tolerance in comparisons can help, but the standard test is robust for most rendering scenarios [G].
*   **Degenerate Input:** If the camera's forward, up, or right vectors are not orthogonal or normalized, the projection calculations will be incorrect. Ensure these vectors are properly normalized and orthogonalized [G].
*   **Small Radii:** Spheres with radii smaller than $R_{max}$ (the radius used to define the "enlarged frustum" in some contexts) may pass the enlarged frustum test but fail the original frustum test. This method handles this by using the actual sphere radius $r$ in the calculations, ensuring accurate culling for all sphere sizes [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sphere. The test involves a constant number of vector operations (dot products, additions, comparisons) [G].
*   **Memory Complexity:** $O(1)$ additional memory per sphere, as no auxiliary data structures are required [G].
*   **Performance:** This test is significantly faster than ray-sphere intersection tests, which involve square roots and quadratic equation solving [G]. It is particularly effective in scenes with many small spheres or chunks, where a large fraction of objects are outside the view frustum [S1].
*   **Strengths:** Simple to implement, computationally inexpensive, and effective for spherical bounding volumes [S1].
*   **Limitations:** Only applicable to spherical bounding volumes. For non-spherical volumes, other culling techniques (e.g., AABB culling) may be more appropriate [G].
*   **When to Use:** Use this method when rendering scenes with many spherical objects or when using bounding spheres for acceleration structures in volume rendering [S1].

## Background
Frustum culling for spheres was introduced as a simpler alternative to SIMD shaft culling, which is limited to primitives with planar edges like triangles [S1]. The technique is described in the context of the Coherent Grid Traversal (CGT) algorithm for visualizing particle data, where it is used to efficiently reject non-overlapping spheres during ray traversal [S1]. The method leverages the geometric properties of spheres and the camera frustum to perform a quick rejection test before more expensive intersection calculations [S1].
