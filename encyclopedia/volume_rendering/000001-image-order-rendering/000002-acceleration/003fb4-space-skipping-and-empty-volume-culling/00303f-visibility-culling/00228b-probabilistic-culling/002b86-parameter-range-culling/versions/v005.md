# Parameter Range Culling

Also called: PIC culling, PR culling, Property Range Culling, Run Time Parameter Range Culling

## Overview
Parameter Range Culling is a runtime optimization that isolates particle subsets by culling particles whose simulation property values do not overlap a user-defined valid range [S1, S2]. It solves the problem of visualizing specific behaviors within large particle datasets by avoiding unnecessary ray/sphere intersection tests for particles outside the range of interest [S1, S2]. It sets itself apart from static culling methods by allowing the valid range to be changed interactively at runtime, providing flexibility for data analysis, albeit with some computational overhead compared to pre-cropped data [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A particle dataset organized in a macrocell hierarchy (see [Coherent Grid Traversal](52-coherent-grid-traversal.md)), where each particle has a position, radius, and up to four additional simulation properties (e.g., density, velocity) [S1, S2].
*   **Input:** The user specifies a valid range for these properties [S1, S2].
*   **Output:** A subset of particles that lie within the valid range, which are then subjected to ray/sphere intersection tests [S1, S2].

**Data Structures:**
*   **Macrocell:** Each macrocell stores the minimum and maximum values for each of the four properties (eight values total) across all particles it contains [S1, S2].
*   **Particle:** Each particle stores its position, radius, and the values for the four additional properties [S1].

**Numbered Steps:**
1.  **Macrocell Culling:** During grid traversal, check if the macrocell's stored min/max range for each of the eight parameters overlaps the user-specified valid range [S1, S2].
    *   If the macrocell range does not overlap the user-specified range, skip the macrocell and cull all contained particles [S1, S2].
    *   This check requires eight SIMD operations: four comparisons, two Boolean AND operations, and two masking operations [S1].
2.  **Particle Culling:** If at least one particle in a macrocell lies within the valid range, the macrocell cannot be skipped [S1, S2].
    *   Apply the same range check to individual particles before performing the intersection test [S1, S2].
    *   If any of the particle's values lie outside the user-specified range, skip the intersection test and cull the particle [S1, S2].
    *   This also requires eight SIMD operations per sphere: four comparisons, two Boolean AND operations, and two masking operations [S1].

**Formulas:**
Let $P_i$ be a particle with property values $v_{i,1}, v_{i,2}, v_{i,3}, v_{i,4}$ [S1].
Let $[L_k, U_k]$ be the user-specified valid range for property $k$ [S1].
Let $[min_{c,k}, max_{c,k}]$ be the stored min/max range for property $k$ in macrocell $c$ [S1].

A macrocell $c$ is culled if for any property $k \in \{1, 2, 3, 4\}$:
$$ max_{c,k} < L_k \quad \text{or} \quad min_{c,k} > U_k $$

A particle $i$ is culled if for any property $k \in \{1, 2, 3, 4\}$:
$$ v_{i,k} < L_k \quad \text{or} \quad v_{i,k} > U_k $$

**Parameters:**
*   **Number of Properties:** Up to four additional properties per particle [S1].
*   **SIMD Operations:** 16 SIMD operations total for macrocell and particle range checking (8 for macrocell, 8 for particle) [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Not given in the sources.
*   **Boundaries:** The sources define culling based on non-overlap, implying inclusive bounds for valid ranges [S1].
*   **Degenerate Input:** If the user specifies an empty range, all particles are culled [G].

**Pseudocode:**
```python
def parameter_range_culling(macrocell, user_ranges, particles):
    """
    macrocell: object with min_max_properties (list of 4 tuples, each tuple is (min, max))
    user_ranges: list of 4 tuples, each tuple is (lower_bound, upper_bound)
    particles: list of particle objects, each with properties (list of 4 values)
    """
    # Step 1: Macrocell Culling
    for k in range(4):
        cell_min, cell_max = macrocell.min_max_properties[k]
        lower, upper = user_ranges[k]
        # Check for non-overlap
        if cell_max < lower or cell_min > upper:
            return [] # Cull entire macrocell

    # Step 2: Particle Culling
    valid_particles = []
    for particle in particles:
        is_valid = True
        for k in range(4):
            val = particle.properties[k]
            lower, upper = user_ranges[k]
            if val < lower or val > upper:
                is_valid = False
                break
        if is_valid:
            valid_particles.append(particle)
    
    return valid_particles
```

## Operating characteristics
*   **Time Complexity:** The cost of range checking is amortized over the number of particles in a macrocell and is significantly less than the ray/sphere intersection tests [S1]. However, the 16 SIMD operations add computational overhead [S1, S2].
*   **Memory Complexity:** Requires storing min/max values for eight parameters per macrocell [S1].
*   **Measured Performance:**
    *   Thunder dataset: 43.06 fps (PR cull) vs 59.55 fps (Pre-crop) [S1, S2]. Total processing time reduced by 43.00%, mean culling rate 14.23%, max culling rate 43.06% [S2].
    *   BulletTorso dataset: 11.18 fps (PR cull) vs 25.49 fps (Pre-crop) [S1, S2]. Total processing time reduced by 34.17%, mean culling rate 3.17%, max culling rate 11.18% [S2].
    *   Performance degradation compared to preprocessed data: Factor of 1.38–2.28 [S1, S2].
*   **Strengths:** Provides interactive flexibility for data analysis by allowing runtime range changes [S1, S2].
*   **Limitations:** Adds computational overhead due to SIMD operations, resulting in lower frame rates compared to pre-cropped data [S1, S2].
*   **When to use:** When interactive exploration of specific simulation properties is required [S1, S2].
*   **When not to use:** When maximum performance is needed and the particle subset is static (use pre-cropping instead) [S1, S2].

## Background
Parameter Range Culling was introduced in the context of coherent grid traversal for visualizing particle-based simulation data [S1, S2]. It was developed to allow investigators to isolate particles with specific parameter values (e.g., density, velocity) to gain insight into simulation behavior [S1, S2]. The method is part of a broader suite of culling techniques including frustum culling and ray/box culling [S1].
