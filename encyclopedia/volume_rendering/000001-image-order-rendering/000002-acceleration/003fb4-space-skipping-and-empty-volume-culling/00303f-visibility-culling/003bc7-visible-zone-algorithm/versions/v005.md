# Visible Zone Algorithm

Also called: Hall-Holt and Rusinkiewicz Visible Zone Algorithm

## Overview
The Visible Zone Algorithm is a conservative visibility computation method that determines which primitives (typically points or voxels) are potentially visible from a set of viewpoints by projecting them into screen space and retaining only those within a specified depth thickness [S2, unofficial]. It solves the problem of efficiently culling occluded geometry in volume rendering and point cloud visualization by precomputing a visibility mask, allowing for significant reduction in rendering work without sacrificing visual correctness [S2, unofficial]. It sets itself apart from its siblings by providing a strict worst-case correctness guarantee for visibility, unlike approximate methods that trade accuracy for speed [S1].

## How it works
The algorithm computes a binary visibility matrix $O$ of size $N \times K$, where $N$ is the number of input points and $K$ is the number of viewpoints. It operates by projecting all points from each viewpoint, grouping them by pixel, sorting by depth, and marking the top $\tau$ points as visible.

**Inputs:**
- $P$: Set of $N$ points (e.g., Gaussian centroids or voxel centers) [S1].
- $V$: Set of $K$ viewpoints [S1].
- $\tau$: Thickness parameter, defining the number of visible layers per pixel [S1].

**Outputs:**
- $O$: $N \times K$ visibility matrix, where $O[i, j] = 1$ if point $i$ is visible from viewpoint $j$, else $0$ [S1].

**Data Structures:**
- $M$: A dictionary or hash map mapping pixel coordinates $(u, v)$ to a list of points projected to that pixel [S1].
- $M^*$: A set of points identified as visible for the current viewpoint [S1].

**Steps:**
1. Initialize $O$ with zeros [S1].
2. For each viewpoint $j$ from $1$ to $K$:
   a. Let $c$ be the current viewpoint [S1].
   b. Retrieve extrinsic matrix $d$ and intrinsic matrix $K_{intr}$ for $c$ [S1].
   c. Initialize empty list $M$ [S1].
   d. For each point $i$ from $1$ to $N$:
      i. Let $p$ be point $P[i]$ [S1].
      ii. Compute 2D projection $x_c = (u, v)$ using forward projection with $d$ and $K_{intr}$ [S1].
      iii. Add $p$ to the list $M_{u,v}$ associated with pixel $(u, v)$ in $M$ [S1].
   e. Initialize empty set $M^*$ [S1].
   f. For each list $M_{u,v}$ in $M$:
      i. Sort $M_{u,v}$ by depth $z$ (ascending) [S1].
      ii. For $k$ from $1$ to $\tau$:
          1. Add the $k$-th point in the sorted list to $M^*$ [S1].
   g. For each point $i$ from $1$ to $N$:
      i. If $P[i]$ is in $M^*$, set $O[i, j] = 1$ [S1].
3. Return $O$ [S1].

**Pseudocode:**
```python
def compute_visibility_mask(P, V, tau):
    """
    Compute visibility mask for points P from viewpoints V with thickness tau.
    P: List of N points, each with 3D coordinates (x, y, z).
    V: List of K viewpoints, each with extrinsic (d) and intrinsic (K_intr) matrices.
    tau: Integer, number of visible layers per pixel.
    Returns: N x K matrix O.
    """
    N = len(P)
    K = len(V)
    O = [[0 for _ in range(K)] for _ in range(N)]

    for j in range(K):
        c = V[j]
        d = c.extrinsic_matrix
        K_intr = c.intrinsic_matrix
        M = {}  # Dictionary mapping (u, v) to list of points

        # Project all points
        for i in range(N):
            p = P[i]
            # Forward projection: 3D to 2D
            u, v = forward_projection(p, d, K_intr)
            if (u, v) not in M:
                M[(u, v)] = []
            M[(u, v)].append(p)

        M_star = set()

        # Determine visible points per pixel
        for pixel_coords, point_list in M.items():
            # Sort by depth z
            point_list.sort(key=lambda pt: pt.z)
            # Pick first tau points
            for k in range(min(tau, len(point_list))):
                M_star.add(point_list[k])

        # Update visibility matrix
        for i in range(N):
            if P[i] in M_star:
                O[i][j] = 1

    return O

def forward_projection(p, d, K_intr):
    """
    Project 3D point p using extrinsic d and intrinsic K_intr.
    Returns (u, v) pixel coordinates.
    """
    # Transform to camera coordinates
    p_cam = transform(p, d)
    # Project to normalized device coordinates
    p_ndc = project(p_cam, K_intr)
    # Convert to pixel coordinates
    u, v = pixel_coords(p_ndc)
    return u, v
```

**Parameters:**
- $\tau$: Thickness. Typical values are not specified in the sources, but it controls the trade-off between culling aggressiveness and correctness [S1].

**Edge Cases and Pitfalls:**
- If $\tau$ is larger than the number of points projected to a pixel, all points are marked visible [S1].
- Precision in projection and sorting can affect which points are considered "in front" [G].
- The algorithm assumes points are distinct; overlapping points at the same depth may require tie-breaking logic [G].

## Subtopics

### [Approximate Visibility Algorithm](13128-approximate-visibility-algorithm.md)
A method to compute approximate visibility for line drawings from volume data by reducing the number of vertices checked for occlusion, trading accuracy for performance. It sets itself apart from the exact visibility algorithm [Visible Zone Algorithm](9086-visible-zone-algorithm.md) by sacrificing worst-case correctness for a predictable speedup factor, making it suitable for large datasets where interactive frame rates are prioritized over perfect occlusion handling.

## Operating characteristics
The algorithm achieves real-time frame rates for 2D and 2.5D datasets [S2, unofficial]. However, the precomputation cost can be high; for a model with 13 million triangles, the accuracy guarantee costs 128 hours of precomputation on a cluster of 16 PCs [S2, unofficial]. It is suitable for scenarios where conservative visibility is critical and precomputation time is acceptable [S2, unofficial]. It is less suitable for dynamic scenes where viewpoints change frequently, as the mask must be recomputed [G].

## Background
The Visible Zone Algorithm was developed by Hall-Holt and Rusinkiewicz [S2, unofficial]. It is designed for conservative visibility computation with incremental updates [S2, unofficial]. It is used in out-of-core visualization of large datasets [S2, unofficial].
