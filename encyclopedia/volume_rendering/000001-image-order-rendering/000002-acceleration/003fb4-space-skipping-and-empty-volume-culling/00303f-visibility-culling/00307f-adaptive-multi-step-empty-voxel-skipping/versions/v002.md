# Adaptive Multi-Step Empty Voxel Skipping

Also called: Improved Ray Casting with Empty Voxel Skipping and Multi-Step Length, Space leap empty voxel ray-casting algorithm, Three-step jump algorithm

## Overview
Adaptive Multi-Step Empty Voxel Skipping is an acceleration technique for direct volume rendering that combines space leaping (empty voxel skipping) with adaptive variable step sampling to reduce redundant computation in empty regions while maintaining image quality [S1]. It differs from traditional equidistant ray casting by entirely skipping empty voxels and varying the sampling interval based on local density, and it differs from its siblings like [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md) by relying on deterministic density-based step sizing rather than opacity thresholds or probabilistic models for culling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (e.g., CT scan data) and a set of rays cast from the image plane into the volume [S1].
*   **Output:** A 2D rendered image with color and transparency values [S1].

**Data Structures:**
The method operates on the standard ray-casting state. In the VTK implementation context, it inherits from `vtkVolumeRayCastingFunction` [S1]. The core data structure is the ray state, which tracks two modes:
1.  **Search Mode:** Traversing empty voxels to find the next non-empty voxel.
2.  **Accumulation Mode:** Sampling and compositing color/transparency at non-empty voxels [S1].

**Algorithm Steps:**
1.  **Pre-check Validity:** For each ray, determine if any non-empty voxels exist along its path. This is typically done by checking the bounding box or a sparse representation of the volume. If no non-empty voxels are detected, the ray is marked as invalid, and all further processing for that ray is skipped [S1].
2.  **Initialize Ray State:** Set the ray to "Search Mode" [S1].
3.  **Adaptive Step Selection:** Calculate the sampling step length $s$ based on the local voxel density or emptiness of the current region:
    *   If the current region contains many empty voxels, set $s$ to a longer value [S1].
    *   If the voxel density is high, set $s$ to a shorter value to increase accuracy [S1].
    *   *Note:* The source describes this as a "three-step length" method, implying a discrete set of step sizes or a specific heuristic for transitioning between them, though the exact mathematical function for $s$ is not provided [S1].
4.  **Advance Ray:** Move the ray position forward by $s$ units along the ray direction.
5.  **Check for Empty Voxels:**
    *   If the current voxel is empty, remain in "Search Mode" and repeat Step 3 (potentially adjusting $s$ if density changes) and Step 4.
    *   If the current voxel is non-empty, switch to "Accumulation Mode" [S1].
6.  **Resample and Synthesize:** In "Accumulation Mode", sample the color and transparency at the current voxel position using the current step length $s$. Composite these values into the ray accumulator [S1].
7.  **Termination:** Continue Steps 3-6 until the ray exits the volume or the accumulated opacity reaches a threshold (if early termination is implemented, though the core algorithm described focuses on skipping empty space) [S1].

**Parameters:**
*   **Step Length ($s$):** Variable. Not fixed. Values are chosen from a set (implied "three-step") or calculated based on density. Typical values are not given, but the concept is "longer" for empty and "shorter" for dense [S1].
*   **Empty Threshold:** A density value below which a region is considered empty. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Visual Artifacts:** The combination of empty voxel jumping and uneven sampling can cause "porphyritic" (patchy/mottled) appearance in the rendered image, particularly noticeable during rotation interactions [S1].
*   **Precision:** The source does not specify how to handle ray positions that fall between voxel centers when using variable step sizes. Standard interpolation (trilinear) is assumed for sampling, but the step size variation may lead to inconsistent sampling rates [S1].
*   **Boundary Handling:** The source does not specify how to handle rays that exit the volume between steps. Standard boundary checks are assumed [S1].

## Operating characteristics
*   **Time Complexity:** Reduces computational overhead by skipping empty voxels entirely and using larger steps in empty regions. The complexity is proportional to the number of non-empty voxels sampled, which is less than the total number of voxels intersected by the ray [S1].
*   **Memory Complexity:** Requires storage for the volume data and potentially a sparse representation or bounding box structure for the pre-check validity step. The VTK implementation inherits from `vtkVolumeRayCastingFunction`, implying standard memory usage for ray casting [S1].
*   **Measured Performance:** Tested on Windows 7, Visual Studio 2010, VTK 5.10.1, using virtual human head CT scan data. Rendering speed was measured by rotation time. The method achieved faster rendering speeds compared to traditional equidistant sampling [S1].
*   **Strengths:** Reduces redundant computation on empty regions; maintains image quality (almost same as original) without changing input 2D sequence images [S1].
*   **Limitations:** Can introduce visual artifacts ("porphyritic" appearance) due to uneven sampling [S1].
*   **When to Use:** Suitable for large volume datasets with significant empty space (e.g., medical images with independent organs) where rendering speed is critical and minor visual artifacts are acceptable [S1].
*   **When Not to Use:** When high visual fidelity is required without any artifacts, or when the volume has very low empty space (where the overhead of step calculation might not be worth it) [S1].

## Background
*   **Origin:** The method was proposed in a paper titled "The research of improved ray casting algorithm on VTK" [S1].
*   **History:** It builds on the traditional ray-casting algorithm proposed by Marc Levoy [S1, S8] and space leaping algorithms [S1, S7]. It was implemented using the Visualization Toolkit (VTK) [S1, S10].
*   **Usage:** Used in medical image visualization, specifically for CT scan data [S1].
