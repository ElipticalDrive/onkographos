# Frustum Culling

Also called: ToF View Frustum Culling, View Frustum Culling, markVisible

## Overview
Frustum culling is a visibility culling technique that avoids rendering geometry outside the user's camera field of view, thereby eliminating unnecessary computation [S2, S1, unofficial]. It is distinguished from its siblings by operating on the geometric bounds of data structures (boxes, spheres, or nodes) against the six planes of the viewing frustum, rather than on pixel-level occlusion or probabilistic sampling [S2, 990-occlusion-clipping-with-orthogonal-opacity.md, 1791-early-termination-and-probabilistic-path-control.md, unofficial].

## How it works
**Inputs:**
- Positions of bounding volumes (e.g., centers and radii for spheres, or min/max extents for boxes) [S2, S4, unofficial].
- View matrix and projection matrix defining the camera [S1, S2, unofficial].
- Near and far clipping plane distances ($n, f$) [S1, S2, unofficial].

**Outputs:**
- A boolean tensor or list indicating which bounding volumes (or their associated data points) are visible within the frustum [S1, S2, unofficial].

**Data Structures:**
- **Bounding Sphere:** Defined by center $c_k = (x_k, y_k, z_k)$ and radius $r_k$ [S4, unofficial].
- **Frustum Planes:** Six planes derived from the combined view-projection matrix. Each plane $i$ is defined by a normal vector $\mathbf{n}_i$ and a distance $d_i$ from the origin [S2, S4, unofficial].

**Steps:**
1. **Extract Frustum Planes:** Compute the six planes of the viewing frustum from the view and projection matrices. For a standard right-handed coordinate system, the planes are typically ordered as Left, Right, Bottom, Top, Near, Far [S2, unofficial].
2. **Hierarchical Check (Optional):** If using a hierarchical spatial partitioning (e.g., a tree), check the current node's bounding volume against the frustum planes [S2, unofficial].
   - If the node is totally outside, discard it and all descendants [S2, unofficial].
   - If the node is totally inside, accept it and all descendants [S2, unofficial].
   - If it intersects, recurse or process children [S2, unofficial].
3. **Sphere-Plane Test:** For each bounding sphere $k$ with center $c_k$ and radius $r_k$:
   - Calculate the signed distance $d$ from the sphere center to each of the six frustum planes [S4, unofficial].
   - The sphere is considered **outside** (culled) if $d < -r_k$ for any plane [S4, unofficial].
   - The sphere is considered **inside** (visible) if it is not culled by any plane [S2, S4, unofficial].
4. **Mark Visible:** Return the boolean status for each volume [S1, unofficial].

**Formula:**
A sphere $k$ is kept in the active set $\mathcal{K}_t$ for a camera batch $\mathcal{B}_t$ if:
$$ \mathcal{K}_t = \bigcup_{c \in \mathcal{B}_t} \{k \mid \text{visible}(k, c)\} $$
where $\text{visible}(k, c)$ is true if for all frustum planes $i$:
$$ d_i \ge -r_k $$
Here, $d_i$ is the signed distance from $c_k$ to plane $i$ [S4, unofficial].

**Parameters:**
- $r_k$: Radius of the bounding sphere.
- $n, f$: Near and far clipping distances.

**Edge Cases and Pitfalls:**
- **Precision:** Signed distance calculations must handle floating-point precision issues near the clipping planes [S2, unofficial].
- **Degenerate Input:** If the view or projection matrix is singular, plane extraction fails [G].
- **Conservatism:** Hierarchical culling may be conservative, admitting blocks that contain no visible primitives if the bounding volume is loose [S4, unofficial].

## Subtopics

### View Frustum Culling for Segments
An optimization technique used in segment-based tetrahedral meshing to reject segments outside the view frustum early in the rendering pipeline [S3]. It counters over-refinement caused by DAG dependencies, where regions outside the view frustum might otherwise be refined unnecessarily, increasing mesh size [S3]. It is chosen when rendering adaptive tetrahedral meshes with DAG-based refinement [S3].

### Two-Level Visibility Culling
A hierarchical culling method used in out-of-core 3D Gaussian Splatting (TideGS) [S4, unofficial]. Level 1 (CPU) computes an active block set using coarse bounding spheres and a 6-plane frustum test, ensuring conservative filtering [S4, unofficial]. Level 2 (GPU) materializes selected blocks and applies exact 3DGS projection/rasterization to determine the final contributing set [S4, unofficial]. It is chosen when scaling 3DGS training to over one billion primitives to reduce SSD/PCIe traffic [S4, unofficial]. It preserves standard 3DGS rendering semantics while allowing block-level storage [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ for $N$ bounding volumes, where each volume requires a constant number of plane tests (6 for frustum) [S2, S4, unofficial]. Hierarchical culling can reduce this to $O(\log N)$ or better depending on the tree structure and scene distribution [S2, unofficial].
- **Memory Complexity:** $O(N)$ to store bounding volumes and visibility flags [S1, S4, unofficial].
- **Measured Performance:** Specific performance metrics for general frustum culling are not given in the sources [S2, unofficial]. TideGS reports that Level 1 culling ensures subsequent transfers scale with the selected block working set rather than the full model size $N$ [S4, unofficial].
- **Strengths:** Simple to implement; effective at rejecting large portions of the scene early; reduces GPU workload [S2, S4, unofficial].
- **Limitations:** Conservative; may admit blocks that contain no visible primitives if bounding volumes are loose [S4, unofficial]. Does not account for occlusion by other geometry [S2, unofficial].
- **When to use:** When the camera moves and large parts of the scene are outside the field of view [S2, unofficial].
- **When not to use:** When the scene is fully contained within the frustum or when occlusion is the primary bottleneck [S2, unofficial].

## Background
Frustum culling is a standard technique in computer graphics for optimizing rendering by avoiding the processing of geometry outside the camera's field of view [S2, unofficial]. It is often implemented alongside back-face culling and occlusion culling [S2, unofficial]. Møller and Haines [93] discuss several algorithms for volume/frustum intersection [S2, unofficial]. Hierarchical spatial partitioning can be used to accelerate the process [S2, unofficial].
