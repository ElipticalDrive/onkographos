# Orthogonal Opacity Map Creation


## Overview
This method creates a 2D opacity map on a plane orthogonal to a major axis by projecting the rendered frame buffer onto that plane and downsampling the result [S1]. It solves the problem of efficiently generating a low-resolution occlusion mask for volume rendering culling, minimizing data transfer costs between graphics and main memory while preserving sufficient occlusion information [S1]. It differs from hierarchical approaches by using a fixed-resolution, multi-pass averaging strategy rather than a tree structure [S1].

## How it works
**Inputs:**
- Current frame buffer $FB$ containing color/opacity data.
- Desired low-resolution map dimensions $n \times n$ (typical value: $64 \times 64$) [S1].
- Camera projection/view matrices used for the current frame.
- High-resolution map side length $N$ (derived from projection geometry so each $FB$ pixel maps to at least one pixel in the high-resolution buffer) [S1].

**Outputs:**
- A low-resolution opacity map of size $n \times n$ in main memory [S1].

**Data Structures:**
- $T_{FB}$: Texture copy of the frame buffer $FB$.
- $PB_{hm}$: High-resolution pixel buffer (optional intermediate; see Optimization).
- $T_{hm}$: Texture bound to $PB_{hm}$, holding the high-resolution opacity map.
- $PB_m$: Low-resolution pixel buffer of size $n \times n$.

**Steps:**
1. **Frame Buffer Copy:** Copy the current frame buffer $FB$ into a texture $T_{FB}$ [S1].
2. **Projective Texturing:** Imagine a rectangle $R$ parallel to the object-aligned orthogonal plane, oriented orthogonal to the camera. Apply projective texturing: treat $T_{FB}$ as a slide projected from the camera position onto $R$ [S1].
3. **High-Resolution Projection:** Orthogonally project the textured rectangle $R$ onto a high-resolution pixel buffer $PB_{hm}$. The resolution of $PB_{hm}$ must be sufficient so that each pixel in $FB$ maps to at least one pixel in $PB_{hm}$ [S1]. Bind $PB_{hm}$ to texture $T_{hm}$ [S1].
4. **Multi-Pass Downsampling:**
   - Initialize $PB_m$ (size $n \times n$) [S1].
   - Calculate the number of passes required:
     $$ P = \left\lceil \frac{N/2}{n^2} \right\rceil $$
     where $N$ is the side length of the high-resolution map ($N \times N$) and $n$ is the side length of the low-resolution map ($n \times n$) [S1].
   - For pass $k$ from $0$ to $P-1$:
     - Set the blending function to `MIN` [S1].
     - Configure texture coordinates so that each pixel in $PB_m$ aligns with the center of 4 neighboring texels in $T_{hm}$ and uses linear interpolation to fetch their average [S1].
     - Translate the texture coordinates (or view volume) so that each pixel in $PB_m$ maps to the center of another 4 uncontributed texels in $T_{hm}$ [S1].
     - Render $T_{hm}$ to $PB_m$ using the configured coordinates and `MIN` blending [S1].
   - Repeat until all texels in $T_{hm}$ have contributed [S1].
5. **Readback:** Read the contents of $PB_m$ to main memory [S1].

**Optimization:**
- Combine projection and downsampling into a single step by targeting projective texturing directly to $PB_m$ (the low-resolution pixel buffer) instead of creating $T_{hm}$ explicitly [S1].
- Since hardware auto-generated texture coordinates (TexGen) cannot be translated for downsampling in this direct path, apply a translation to the view volume using `glOrtho()` in OpenGL to shift the sampling region for each pass [S1].

**Pseudocode:**
```python
import math

def create_orthogonal_opacity_map(FB_texture, N, n=64):
    """
    Creates a low-resolution orthogonal opacity map from the frame buffer.
    FB_texture: 2D list/array of shape (W, H) containing frame buffer data.
    N: Side length of the high-resolution projected map (N x N).
    n: Side length of the low-resolution output map (n x n).
    Returns: 2D list of shape (n, n) containing opacity values.
    """
    # Calculate number of multi-pass rendering steps
    P = math.ceil((N / 2) / (n * n))
    
    # Initialize low-resolution pixel buffer
    PBm = [[0.0] * n for _ in range(n)]
    
    for k in range(P):
        # Calculate grid offset for this pass.
        # The translation shifts the sampling window by half a pixel in x and y
        # to cover the next set of 4 uncontributed texels per output pixel.
        dx = (k % 2) * 0.5
        dy = (k // 2) * 0.5
        
        # Simulate GPU projective texturing and downsampling:
        # For each pixel (i, j) in PBm, sample 4 neighboring texels from the 
        # projected image (shifted by dx, dy) and average them.
        # Apply MIN blending with existing PBm values.
        for i in range(n):
            for j in range(n):
                # Map PBm pixel center to projected texture coordinates
                u = (i + dx) / n
                v = (j + dy) / n
                
                # Sample 4 neighboring texels in the high-res projected image
                tex_u = u * N
                tex_v = v * N
                
                # Bilinear interpolation of 4 texels
                x0, y0 = math.floor(tex_u), math.floor(tex_v)
                x1, y1 = x0 + 1, y0 + 1
                fx, fy = tex_u - x0, tex_v - y0
                
                # Fetch texels (clamp to boundaries as standard for opacity)
                W, H = len(FB_texture[0]), len(FB_texture)
                t00 = FB_texture[min(y0, H-1)][min(x0, W-1)]
                t01 = FB_texture[min(y0, H-1)][min(x1, W-1)]
                t10 = FB_texture[min(y1, H-1)][min(x0, W-1)]
                t11 = FB_texture[min(y1, H-1)][min(x1, W-1)]
                
                avg = (t00 * (1-fx)*(1-fy) + t01 * fx*(1-fy) + 
                       t10 * (1-fx)*fy + t11 * fx*fy)
                
                # MIN blending: keep the smaller opacity value
                PBm[i][j] = min(PBm[i][j], avg)
                
    return PBm
```

**Edge Cases and Pitfalls:**
- **Coverage:** The translation step ensures complete coverage of the high-resolution map without gaps or overlaps that would skew the average [S1].
- **Precision:** Linear interpolation is used for averaging 4 texels; standard floating-point precision is sufficient for opacity values [G].

## Operating characteristics
- **Performance:** Typical low-resolution map size is $64 \times 64$ [S1]. Downsampling reduces the resolution to limit transfer costs from graphics to main memory and reduces the amount of comparisons required for occlusion clipping [S1].
- **Strengths:** Simple implementation on GPU; effective for orthogonal views; reduces data transfer overhead [S1].
- **Limitations:** Fixed resolution; requires multiple passes for downsampling [S1].
- **Not given in the sources:** Exact time and memory complexity, measured performance on specific hardware, or scaling laws.

## Background
Originated in the context of texture-based volume rendering for empty space skipping and occlusion clipping [S1]. The method was proposed by Mueller et al. in "Empty Space Skipping and Occlusion Clipping for Texture-based Volume Rendering" [S1]. It is used in real-time volume rendering applications where culling occluded voxels improves performance [S1].
