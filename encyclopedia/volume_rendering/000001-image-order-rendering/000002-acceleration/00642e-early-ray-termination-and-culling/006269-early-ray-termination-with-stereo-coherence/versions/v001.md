# Early Ray Termination with Stereo Coherence

Also called: Guaranteeing Correct Stereoscopic Views with Early Termination, Stereo Early Ray Termination

## Overview
Early Ray Termination with Stereo Coherence is an acceleration technique for stereoscopic volume rendering that allows rays to terminate when accumulated opacity reaches 1.0, while ensuring that samples ignored by the left-eye ray do not cause visual errors in the right-eye view [S1]. It differs from standard early termination by bounding the right-eye projection of subsequent left-eye rays to prevent the accumulation of data from unknown regions behind the termination point [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A volume dataset, left-eye and right-eye camera parameters (typically defined by a shear or rotation angle), and a scan-line processing order.
*   **Output:** Correctly rendered left-eye and right-eye images.

**Data Structures**
*   **Ray State:** Each ray maintains an accumulated color $C$ and opacity $\alpha$.
*   **Projection State:** For each right-eye ray, the current projection coordinate along the scan-line is tracked.
*   **Bounding State:** A global or per-scan-line variable `max_right_proj` stores the maximum allowable right-eye projection coordinate for the current batch of left-eye rays.

**Formulas**
The accumulation of samples uses the Porter-Duff over operator [S1]:
$$ S(i) \text{ over } S(f) = S(i) + (1 - \alpha(i)) S(f) $$
where $S(i) = [C(i), \alpha(i)]$ is the color/opacity pair of the sample closer to the viewpoint, and $S(f) = [C(f), \alpha(f)]$ is the accumulated result of the samples further from the viewpoint [S1].

For regularly spaced samples, the projection shift between consecutive left-eye rays is a constant $\Delta x$ (or $\Delta x \cos(\theta)$ if rotations are used) [S1].

**Parameters**
*   **Termination Threshold:** $\alpha_{max} = 1.0$. When accumulated opacity reaches this value, the left-eye ray traversal stops [S1].
*   **Processing Order:** Left-eye rays are processed sequentially along scan-lines, right to left, and front to back along the ray [S1].

**Steps**
1.  Initialize `max_right_proj` to the maximum possible projection coordinate (or the projection of the first left-eye ray processed).
2.  For each left-eye ray, starting from the rightmost scan-line and moving left:
    a. Initialize left-eye accumulated color $C_L = 0$ and opacity $\alpha_L = 0$.
    b. Initialize right-eye accumulated color $C_R = 0$ and opacity $\alpha_R = 0$ for the corresponding right-eye ray.
    c. Determine the initial right-eye projection coordinate $P_R$ for the current left-eye ray.
    d. March samples along the left-eye ray from front to back:
        i. Sample the volume at the current position to get $[C_s, \alpha_s]$.
        ii. Calculate the right-eye projection coordinate $P_{sample}$ for this sample.
        iii. Check if the left-eye ray has terminated:
            *   If $\alpha_L \ge 1.0$, set `max_right_proj` = $P_{sample}$ (the final projection of this ray) and break the marching loop [S1].
        iv. Check if the sample should be accumulated into the right-eye ray:
            *   If $\alpha_R < 1.0$ AND $P_{sample} \le \text{max\_right\_proj}$:
                *   Accumulate $[C_s, \alpha_s]$ into the right-eye ray using the over operator.
                *   Update $\alpha_R$ and $C_R$.
        v. Accumulate $[C_s, \alpha_s]$ into the left-eye ray using the over operator.
        vi. Update $\alpha_L$ and $C_L$.
        vii. Increment the sample position.
    e. Store the final $C_L$ and $C_R$ for the respective pixels.

**Pseudocode**
```python
def render_stereo_volume(volume, left_cam, right_cam, width, height):
    # Initialize output buffers
    left_image = zeros((height, width, 3))
    right_image = zeros((height, width, 3))
    
    # Constants
    ALPHA_THRESHOLD = 1.0
    
    # Process scan-lines right to left
    for y in range(height):
        for x in range(width - 1, -1, -1):
            # Initialize ray states
            left_alpha = 0.0
            left_color = [0.0, 0.0, 0.0]
            right_alpha = 0.0
            right_color = [0.0, 0.0, 0.0]
            
            # Determine initial right-eye projection for this left-eye ray
            # In a shear-based stereo setup, this is often x + offset
            # Assuming a simple shear for demonstration:
            right_proj_offset = get_stereo_offset(left_cam, right_cam, x, y)
            current_right_proj = x + right_proj_offset
            
            # Bounding variable for this scan-line
            # Initialized to infinity or the max possible x coordinate
            max_right_proj = float('inf')
            
            # March front to back
            t = 0.0
            while t < max_depth:
                # Sample volume
                sample_pos = get_ray_position(left_cam, x, y, t)
                sample = volume.sample(sample_pos) # Returns (color, alpha)
                s_color, s_alpha = sample
                
                # Calculate right-eye projection for this sample
                # Assuming regular spacing, projection increases by constant delta_x
                # For simplicity, we assume the projection coordinate tracks with t
                # or is derived from the camera geometry.
                # The key constraint is that we cannot project beyond max_right_proj
                # if the left ray has terminated.
                
                # Check if left ray has terminated in previous step
                if left_alpha >= ALPHA_THRESHOLD:
                    # Update max_right_proj to the projection of the last valid sample
                    # This prevents future rays from projecting into "unknown" space
                    # obscured by the terminated ray.
                    max_right_proj = current_right_proj
                    break
                
                # Check if we should accumulate into right eye
                # Condition: Right eye not opaque AND projection is within bounds
                if right_alpha < ALPHA_THRESHOLD and current_right_proj <= max_right_proj:
                    # Accumulate into right eye
                    # Porter-Duff over: S_new = S_sample + (1 - alpha_sample) * S_accum
                    right_color = [
                        s_color[0] + (1 - s_alpha) * right_color[0],
                        s_color[1] + (1 - s_alpha) * right_color[1],
                        s_color[2] + (1 - s_alpha) * right_color[2]
                    ]
                    right_alpha = s_alpha + (1 - s_alpha) * right_alpha
                
                # Accumulate into left eye
                left_color = [
                    s_color[0] + (1 - s_alpha) * left_color[0],
                    s_color[1] + (1 - s_alpha) * left_color[1],
                    s_color[2] + (1 - s_alpha) * left_color[2]
                ]
                left_alpha = s_alpha + (1 - s_alpha) * left_alpha
                
                # Advance ray
                t += step_size
                # Update right projection coordinate
                # In shear stereo, this is typically x + t * shear_factor
                current_right_proj = x + get_projection_shift(t, right_cam)
            
            left_image[y, x] = left_color
            right_image[y, x] = right_color
            
    return left_image, right_image
```

**Edge Cases and Pitfalls**
*   **Termination Bounding:** If a left-eye ray terminates early, samples beyond that point are ignored. If these samples would project into a right-eye ray that is not yet opaque, failing to accumulate them results in an incorrect stereoscopic view [S1]. The method handles this by setting `max_right_proj` to the final projection of the terminated ray, ensuring no subsequent left-eye ray projects into the "unknown" region behind the termination [S1].
*   **Precision:** The comparison `current_right_proj <= max_right_proj` must handle floating-point precision carefully to avoid excluding valid samples or including invalid ones due to rounding errors [G].
*   **Degenerate Input:** If the stereo baseline is zero, the left and right rays are identical, and the bounding logic is trivial. If the volume is fully transparent, no termination occurs, and the method degrades to standard stereo rendering.

## Operating characteristics
*   **Time Complexity:** The method adds a constant-time check per sample for the right-eye accumulation and bounding logic. The overall complexity remains linear with respect to the number of samples traversed, but the number of samples is reduced by early termination [S1].
*   **Memory Complexity:** Requires storing the volume data and two output images. No additional significant memory is required beyond the ray state variables [S1].
*   **Strengths:** Ensures correct stereoscopic depth perception by preventing missing data in the right eye due to left-eye early termination [S1]. Efficiently accelerates rendering by terminating rays early [S1].
*   **Limitations:** Requires processing left-eye rays in a specific order (right to left) to maintain the bounding property [S1]. May be less efficient if the volume is mostly transparent, as early termination does not occur [G].
*   **When to Use:** When rendering stereoscopic volumes where performance is critical and correct depth perception is required [S1].
*   **When Not to Use:** When the volume is fully opaque or fully transparent, or when non-stereoscopic rendering is sufficient.

## Background
The method was introduced in the context of fast stereoscopic volume rendering [S1]. It addresses the specific problem that standard early ray termination, while efficient for monoscopic views, breaks the correspondence between left and right eye views in stereoscopy [S1]. The technique relies on the observation that if left-eye rays are processed in a specific order, the right-eye projections can be bounded to ensure correctness [S1].
