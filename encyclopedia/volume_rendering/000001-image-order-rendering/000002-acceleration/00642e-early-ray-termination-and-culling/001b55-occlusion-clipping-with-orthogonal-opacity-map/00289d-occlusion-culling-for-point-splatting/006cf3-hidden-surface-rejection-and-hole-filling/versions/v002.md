# Hidden Surface Rejection and Hole Filling
Also called: Point Rejection and Hole Filling, Screen-space Point Rejection and Hole Filling

## Overview
Hidden Surface Rejection and Hole Filling is a post-processing technique applied to point-splatted volume renderings to improve visual quality by removing occluded points and filling the resulting gaps with surviving data [S1, unofficial]. It distinguishes itself from standard alpha blending by explicitly discarding points deemed occluded by closer neighbors in screen space, followed by a recursive expansion of valid pixels to eliminate holes, thereby creating a solid appearance from dense point clouds [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A buffer of point splats containing color and depth attributes for each pixel, with multiple points per pixel accumulated via atomic operations [S1, unofficial].
*   **Output:** A final color buffer where occluded points are removed and empty pixels are filled by expanding surviving points [S1, unofficial].

**Data Structures:**
*   **Attribute Buffer:** A texture at backbuffer resolution storing per-pixel color, depth, and a point count [S1, unofficial].
*   **Temporary Texture:** An intermediate buffer at backbuffer resolution used to store the result of the rejection and resolve pass [S1, unofficial].

**Parameters:**
*   **Neighbor Grid Size:** $7 \times 7$ pixels centered on the current pixel [S1, unofficial].
*   **Hole Filling Iterations:** 3 iterations [S1, unofficial].
*   **Occlusion Threshold:** A defined threshold for the calculated cone size; if the cone is smaller than this, the point is rejected [S1, unofficial].

**Steps:**
1.  **Point Rejection and Resolve:** For each pixel in the attribute buffer, evaluate a $7 \times 7$ grid of neighboring pixels centered on the current pixel [S1, unofficial]. Test each neighbor to determine if it is closer to the camera than the current point [S1, unofficial]. Calculate the largest cone around the current point's center that does not intersect any of the closer points in the grid [S1, unofficial]. If the calculated cone size is smaller than the defined threshold, mark the point as occluded and exclude it from the output [S1, unofficial]. If the point is not occluded, compute its final color by dividing its accumulated color data by the number of points added to the buffer at that pixel [S1, unofficial]. Write the valid color and depth to the temporary texture [S1, unofficial].
2.  **Hole Filling (Recursive Expansion):** Initialize the working buffer with the output from the Rejection and Resolve step [S1, unofficial]. For 3 iterations, process every empty pixel (no valid color/depth) in the buffer [S1, unofficial]. Identify neighboring pixels that have valid color data [S1, unofficial]. Update the empty pixel's color and depth to the average of these valid neighbors [S1, unofficial]. The expansion continues until the bounds of the $7 \times 7$ grid used in rejection are effectively covered [S1, unofficial].
3.  **Compositing:** Blit the temporary render texture to the framebuffer [S1, unofficial]. Perform a depth comparison to integrate the point cloud pixels with traditional polygon geometry before transparent rendering [S1, unofficial].

**Pseudocode:**
```python
def hidden_surface_rejection_and_hole_filling(attribute_buffer, resolution, occlusion_threshold):
    """
    attribute_buffer: 2D list of dicts {color: vec3, depth: float, count: int, x: int, y: int}
    resolution: (width, height)
    occlusion_threshold: float
    """
    width, height = resolution
    # Step 1: Point Rejection and Resolve
    temp_texture = [[None] * width for _ in range(height)]
    for y in range(height):
        for x in range(width):
            current = attribute_buffer[y][x]
            if current['count'] == 0:
                continue
            is_occluded = False
            for dy in range(-3, 4):
                for dx in range(-3, 4):
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < width and 0 <= ny < height:
                        neighbor = attribute_buffer[ny][nx]
                        if neighbor['count'] > 0 and neighbor['depth'] < current['depth']:
                            if calculate_cone_metric(current, neighbor) < occlusion_threshold:
                                is_occluded = True
                                break
                if is_occluded:
                    break
            if not is_occluded:
                temp_texture[y][x] = {
                    'color': current['color'] / current['count'],
                    'depth': current['depth']
                }
    # Step 2: Hole Filling
    working_buffer = temp_texture
    for _ in range(3):
        new_buffer = [[None] * width for _ in range(height)]
        for y in range(height):
            for x in range(width):
                pixel = working_buffer[y][x]
                if pixel is None:
                    valid = []
                    for dy in range(-1, 2):
                        for dx in range(-1, 2):
                            nx, ny = x + dx, y + dy
                            if 0 <= nx < width and 0 <= ny < height:
                                n = working_buffer[ny][nx]
                                if n is not None:
                                    valid.append(n)
                    if valid:
                        new_buffer[y][x] = {
                            'color': sum(v['color'] for v in valid) / len(valid),
                            'depth': sum(v['depth'] for v in valid) / len(valid)
                        }
                else:
                    new_buffer[y][x] = pixel
        working_buffer = new_buffer
    return working_buffer

def calculate_cone_metric(current, neighbor):
    # The exact geometric formula for the cone size is not provided in the sources [G].
    # This function implements a standard screen-space occlusion check based on depth difference and radial distance.
    depth_diff = current['depth'] - neighbor['depth']
    screen_dist = ((neighbor['x'] - current['x'])**2 + (neighbor['y'] - current['y'])**2)**0.5
    return depth_diff / (screen_dist + 1e-6)
```

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, with a constant factor determined by the $7 \times 7$ grid evaluation and 3 iterations of hole filling [S1, unofficial].
*   **Memory Complexity:** Requires a temporary texture at backbuffer resolution [S1, unofficial].
*   **Performance:** Merging the point rejection pass with the color resolve pass saves performance by avoiding an intermediate buffer write/read cycle [S1, unofficial].
*   **Strengths:** Improves frame quality by removing occluded points and filling holes, making dense point clouds look solid [S1, unofficial].
*   **Limitations:** Increasing the neighbor grid size makes rejection overly aggressive, removing visible points. Increasing hole filling iterations creates a "muddy mess" by over-filling rejected data [S1, unofficial].
*   **When to use:** When rendering extremely large, dense point clouds where atomic operation bottlenecks and visual holes are problematic [S1, unofficial].
*   **When not to use:** When preserving fine, sparse details is critical, as aggressive rejection and hole filling will obscure them [S1, unofficial].

## Background
This method is described in the context of rendering extremely large unstructured raw point clouds [S1, unofficial]. It builds on the paper "Real-time Rendering of Massive Unstructured Raw Point Clouds using Screen-space Operators" [S1, unofficial]. The implementation described combines the point rejection pass with the color resolve pass, differing from the referenced paper which likely separates them [S1, unofficial]. It is used in real-time rendering pipelines to handle overdraw and improve visual fidelity of point-based volume representations [S1, unofficial].
