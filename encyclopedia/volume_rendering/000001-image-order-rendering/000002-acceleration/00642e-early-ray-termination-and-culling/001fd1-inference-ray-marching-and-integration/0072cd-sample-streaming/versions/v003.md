# Sample Streaming

Also called: Batched Ray Marching, Streaming Renderer

## Overview
Sample Streaming is a rendering execution model that decomposes volume rendering into distinct kernels (ray generation, coordinate computation, and shading) to align with the batch inference execution model of machine learning frameworks [S1]. It reduces control flow divergence and hides high-latency memory accesses by processing rays in batches, where sample coordinates are streamed out for network inference before shading values are retrieved [S1]. Unlike traditional ray marching which computes samples sequentially per ray, this method processes a fixed number of samples $K$ across all active rays simultaneously, optimizing for GPU throughput in neural rendering contexts [S1].

## How it works
The method splits the rendering loop into three primary kernels: ray generation, coordinate computation, and shading [S1]. It operates on a batch of rays, managing their validity state to prune inactive rays over time [S1].

**Inputs and Outputs:**
*   **Input:** A batch of $N$ rays, neural network parameters, and frame buffer state [S1].
*   **Output:** Accumulated pixel color for the frame [S1].
*   **Parameters:** $K$, the number of sample coordinates generated per iteration per ray [S1].

**Data Structures:**
*   **Ray State:** Stored in global memory; includes ray origin, direction, current position, throughput, and a validity flag [S1].
*   **Sample Buffer:** A buffer of size $N \times K$ storing the next $K$ sample coordinates for each ray [S1].
*   **Inference Output:** A buffer storing the inferred density and color values corresponding to the sample coordinates [S1].

**Numbered Steps:**
1.  **Ray Generation:** Initialize primary rays and intersect them with the volume; if no intersection is found, invalidate the ray [S1].
2.  **Stream Compaction:** Remove invalid rays from the active batch to reduce kernel launch overhead in subsequent iterations [S1].
3.  **Coordinate Computation:** For each active ray, compute the next $K$ sample coordinates along the ray direction and stream them out for network inference [S1].
4.  **Shading:** Retrieve inferred sample values, perform volume integration using the emission-absorption model, update ray throughput and position, and advance the ray [S1].
5.  **Termination Check:** Terminate the loop if all rays are invalid [S1].

**Formulas:**
The volume rendering integral is approximated using the sampled values [G]. For a ray $r$, the color $C(r)$ is:
$$ C(r) = \sum_{i=1}^{M} T_i \alpha_i c_i $$
where $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \Delta_j\right)$ is the transmittance, $\alpha_i = 1 - \exp(-\sigma_i \Delta_i)$ is the opacity, $\sigma_i$ is the density, $\Delta_i$ is the step size, and $c_i$ is the emitted color at sample $i$ [G]. In Sample Streaming, these samples are computed in batches of $K$ [S1].

**Pseudocode:**
The following pseudocode illustrates the kernel structure, rewritten in a self-contained Python-like style [S1].

```python
def streaming_renderer(params, n_rays):
    raygen_kernel(params, n_rays)
    while (n_rays := compaction(params, n_rays)) > 0:
        coordinate_kernel(params, n_rays)
        batch_inference(params.net, params, n_rays)
        shading_kernel(params, n_rays)

def raygen_kernel(params, n_rays):
    for i in range(n_rays):
        ray = initialize_ray(params, i)
        valid = sample(ray, params)
        if valid:
            save_ray(params, ray)
        else:
            accumulate_pixel_color(params, ray)

def coordinate_kernel(params, n_rays):
    params.active_count = 0
    for i in range(n_rays):
        ray = load_ray(params, i)
        ray.next_coords = compute_next_k_samples(ray, params.K)
        save_ray(params, ray)

def shading_kernel(params, n_rays):
    params.active_count = 0
    for i in range(n_rays):
        ray = load_ray(params, i)
        ray.coord_offset = i * params.K
        valid = shade(params, ray) and sample(ray, params)
        if valid:
            save_ray(params, ray)
        else:
            accumulate_pixel_color(params, ray)

def initialize_ray(params, i):
    return Ray(origin=params.camera.origin, direction=params.camera.directions[i])

def sample(ray, params):
    ray.origin = ray.origin + ray.direction * params.step_size
    return ray.origin in_volume(params.volume_bounds)

def save_ray(params, ray):
    params.ray_buffer[params.active_count] = ray
    params.active_count += 1

def accumulate_pixel_color(params, ray):
    params.framebuffer[ray.pixel_id] += ray.throughput * ray.color

def compaction(params, n_rays):
    valid_indices = [i for i in range(n_rays) if params.ray_buffer[i].valid]
    for i, idx in enumerate(valid_indices):
        params.ray_buffer[i] = params.ray_buffer[idx]
    return len(valid_indices)

def load_ray(params, i):
    return params.ray_buffer[i]

def compute_next_k_samples(ray, K):
    return [ray.origin + ray.direction * (j + 1) * params.step_size for j in range(K)]

def batch_inference(net, params, n_rays):
    coords = [coord for ray in params.ray_buffer[:n_rays] for coord in ray.next_coords]
    params.inference_output = net.forward(coords)

def shade(params, ray):
    samples = get_samples_for_ray(params, ray)
    ray.color, ray.throughput = integrate_emission_absorption(samples, ray.throughput)
    return ray.throughput > 0.01

def get_samples_for_ray(params, ray):
    return params.inference_output[ray.coord_offset:ray.coord_offset + params.K]
```

**Parameters:**
*   $K$: The number of samples generated by each iteration. Tuning results suggest optimal performance when $K$ is around 8 [S1].
*   Step size: Set to 1 for ray marching methods [S1].
*   Russian roulette depth: Set to 4 for path tracing methods [S1].
*   Frame buffer size: 768×768 in reported experiments [S1].
*   World scaling: Datasets are scaled so that each voxel corresponds to a unit cube in the world coordinate system prior to rendering [S1].

**Edge Cases and Pitfalls:**
*   **Large $K$:** If $K$ is too large, more samples are computed than necessary because many rays exit the volume earlier [S1]. These unused samples must be discarded, wasting computation time [S1].
*   **Small $K$:** If $K$ is too small, the overhead of kernel launches and data transfers dominates execution time [S1].
*   **Memory Access:** High-latency memory accesses are hidden by the batch processing, but insufficient batch size may fail to hide this latency effectively [S1].

## Operating characteristics
*   **Time Complexity:** The number of iterations is reduced by a factor of $K$ compared to single-sample marching, reducing CUDA kernel launch overheads [S1]. However, the total number of samples computed may exceed the minimum required due to the batch nature, potentially increasing total compute time if $K$ is poorly tuned [S1]. Sample Streaming is 3-8x faster than in-shader rendering [S1]. With macro-cells, it achieves up to 40x speedup over in-shader methods [S1].
*   **Memory Complexity:** Requires storage for $N \times K$ sample coordinates and their corresponding inference outputs [S1]. The active ray buffer size decreases over time due to stream compaction [S1].
*   **Strengths:** Effectively hides high-latency memory accesses by providing enough data for the processor to work on while waiting for memory requests [S1]. Reduces control flow divergence by processing rays in batches [S1]. Compatible with neural network inference engines [S1].
*   **Limitations:** Increases algorithm complexity [S1]. The batch optimization currently only applies to ray marching algorithms [S1]. Requires tuning of $K$ for optimal performance [S1].
*   **When to Use:** Real-time volume rendering with neural networks where inference latency is significant and can be overlapped with computation [S1].
*   **When Not to Use:** Scenes with highly variable ray lengths where $K$ cannot be tuned effectively, or when memory bandwidth is the primary bottleneck and batch overhead is too high [S1].

## Background
Sample Streaming was introduced to render volumetric neural representations efficiently [S1]. It adapts the spirit of wavefront path tracers to the constraints of neural volume rendering, where densities are unknown in advance and expensive to compute [S1]. The method was developed to leverage the batch inference execution model of modern machine learning frameworks, addressing the challenge of high-latency memory accesses and control flow divergence in GPU-based volume rendering [S1].
