# Inference Pipeline
Also called: Inference Module
## Overview
The Inference Pipeline renders images from a trained dense point cloud (specifically Gaussian Splatting models) and new camera poses without requiring further optimization [S1, unofficial]. It differs from its sibling [Inference Ray Compositing](3790-inference-ray-compositing.md) by focusing on the complete evaluation loop including rasterization and output generation, rather than just the compositing step. It also differs from [Sparse Ray Marching (Training)](3890-sparse-ray-marching-training.md) by operating in a fixed, post-training state.
## How it works
**Inputs:**
1.  `DensePointCloudWithExtraFeatures`: The trained model data, including Gaussian parameters (position, covariance, opacity, spherical harmonics coefficients) and any additional learned features [S1, unofficial].
2.  `NewCameraPose`: The extrinsic and intrinsic parameters defining the view for which the image is to be rendered [S1, unofficial].

**Outputs:**
1.  `Image`: The final rendered color image [S1, unofficial].

**Data Structures:**
*   `Gaussian`: A structure containing position ($\mathbf{p}$), covariance matrix ($\Sigma$), opacity ($\alpha$), and spherical harmonics coefficients ($\mathbf{c}$) [S1, unofficial].
*   `Camera`: A structure containing view matrix ($\mathbf{V}$), projection matrix ($\mathbf{P}$), and resolution dimensions [S1, unofficial].

**Steps:**
1.  **Initialization**: Load the `DensePointCloudWithExtraFeatures` into memory. Initialize the rasterizer with the resolution defined by `NewCameraPose` [S1, unofficial].
2.  **Projection**: For each Gaussian in the point cloud, project its center $\mathbf{p}$ from world space to screen space using the view and projection matrices from `NewCameraPose` [S1, unofficial].
3.  **Culling**: Prune points that are occluded by other geometry or are too close to the camera to be validly rendered [S1, unofficial]. This step ensures only visible and geometrically valid Gaussians contribute to the final image.
4.  **Rasterization**: Use the rasterizer to map the projected Gaussians to screen pixels. This involves sorting Gaussians by depth and compositing their contributions based on opacity and color [S1, unofficial].
5.  **Output Generation**: Generate the final `Image` from the rasterized data. Optionally, generate depth maps and colored depth maps for visualization purposes [S1, unofficial].

**Pseudocode:**
```python
def inference_pipeline(point_cloud: DensePointCloudWithExtraFeatures, camera_pose: NewCameraPose) -> Image:
    """
    Renders an image from a trained dense point cloud and new camera pose.
    """
    # Step 1: Initialize rasterizer with camera resolution
    rasterizer = Rasterizer(camera_pose.resolution)
    
    # Step 2: Project Gaussians to screen space
    projected_gaussians = []
    for gaussian in point_cloud.gaussians:
        # Project center to screen space
        screen_pos = project_to_screen(gaussian.position, camera_pose.view_matrix, camera_pose.projection_matrix)
        
        # Step 3: Culling - check if point is valid and not occluded
        if is_valid_and_visible(gaussian, screen_pos, camera_pose):
            projected_gaussians.append(GaussianProjection(
                position=screen_pos,
                covariance=project_covariance(gaussian.covariance, camera_pose.view_matrix),
                opacity=gaussian.opacity,
                color=gaussian.color,
                original_index=gaussian.id
            ))
    
    # Sort by depth for correct compositing
    projected_gaussians.sort(key=lambda g: g.position.z)
    
    # Step 4: Rasterize
    # The rasterizer handles the compositing of Gaussians to pixels
    image = rasterizer.render(projected_gaussians, camera_pose)
    
    # Step 5: Output
    return image
```

**Parameters:**
*   `point_cloud`: The trained model. Size depends on the training dataset. Typical values for the number of Gaussians range from 5,000 to 30,000 or more [S1, unofficial].
*   `camera_pose`: Defines the view. No specific typical values, but must be consistent with the training coordinate system.

**Edge Cases and Pitfalls:**
*   **Occlusion**: Incorrect culling can lead to artifacts. The method prunes points occluded by or too close to the camera [S1, unofficial].
*   **Precision**: Floating-point precision in projection and rasterization can affect quality, especially for distant or small Gaussians.
*   **Degenerate Input**: If the point cloud is empty or the camera pose is invalid, the pipeline should handle these gracefully, potentially returning a blank image or an error.

## Subtopics

### [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md)
Renders a set of views from a trained dense point cloud, specifically Gaussian Splatting models, and saves rendered images, depth maps, and colored depth maps. It differs from the parent [Inference Pipeline](5924-inference-pipeline.md) by focusing specifically on the extraction and visualization of depth data and the pruning of invalid geometry, rather than the full evaluation loop including FPS calculation and video generation.

### Runtime Inference with Control Encoding
After training, uses only the forward flow to render images [S2]. Passes control encoding to the MLPs to determine the object to be rendered at runtime [S2]. Invokes the MLPs whenever a change in the encoding is necessary [S2]. Re-evaluates the color MLP whenever the viewing angle shifts to account for scene colors changing with viewing direction [S2]. For other MLPs, predicts $k$ parameters for each anchor point instead of inferring for every viewing direction [S2].

## Operating characteristics
**Time Complexity:** Linear with respect to the number of Gaussians and pixels, $O(N \cdot P)$, where $N$ is the number of Gaussians and $P$ is the number of pixels [S1, unofficial].
**Memory Complexity:** Linear with respect to the number of Gaussians, $O(N)$, to store the point cloud data [S1, unofficial].
**Measured Performance:** Not given in the sources.
**Scaling:** Scales with the number of Gaussians and resolution.
**Strengths:** Real-time rendering capability, no optimization required at inference time [S1, unofficial][S2].
**Limitations:** Requires pre-training, memory intensive for large point clouds [S1, unofficial].
**When to use:** When real-time rendering of trained Gaussian Splatting models is required [S1, unofficial][S2].
**When not to use:** When dynamic scene changes require re-optimization [S1, unofficial].

## Background
Originated in the context of 3D Gaussian Splatting for real-time rendering [S1, unofficial][S2]. Used in applications such as Gaming, E-Commerce, and Industrial visualization [S2].
