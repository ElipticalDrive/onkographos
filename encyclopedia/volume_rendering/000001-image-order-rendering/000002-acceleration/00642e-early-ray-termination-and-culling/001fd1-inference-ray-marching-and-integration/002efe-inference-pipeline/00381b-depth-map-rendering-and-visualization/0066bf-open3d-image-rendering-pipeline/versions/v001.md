# Open3D Image Rendering Pipeline

Also called: Open3D Geometry Image Conversion, Open3D Visualization Pipeline

## Overview
This method converts raw rendering outputs (depth, opacity, ellipsoid parameters, or RGB images) into Open3D-compatible geometry images for visualization, handling different modalities via UI checkboxes. It sets itself apart from sibling pipelines by directly interfacing with OpenGL for ellipsoid rendering and using `imgviz` for depth/opacity normalization, whereas siblings like the 4DGS pipeline may use different backend renderers or data structures.

## How it works
**Inputs:**
- `results`: Dictionary containing rendering data. Keys may include `depth`, `opacity`, or RGB image data.
- `current_cam`: Camera object containing intrinsic and extrinsic parameters (e.g., `FoVy`, view matrix).
- `gaussian_cur`: Current Gaussian Splatting model instance containing attributes (`xyz`, `opacity`, `scaling`, `rotation`, `features`).
- `self.g_renderer`: OpenGL-based Gaussian renderer instance.
- `self.g_camera`: OpenGL camera state instance.
- `self.depth_chbox`, `self.opacity_chbox`, `self.ellipsoid_chbox`: UI checkbox states indicating which modalities to render.
- `self.background`: Background color tensor.
- `self.scaling_slider`: Scaling factor for Gaussian sizes.

**Outputs:**
- Rendered images as Open3D `Image` objects (RGB, depth, opacity, or ellipsoid views).

**Data Structures:**
- **Gaussian Attributes (OpenGL Upload):**
  - `xyz`: Position tensor, shape $(N, 3)$, type float32.
  - `opacity`: Scalar opacity tensor, shape $(N, 1)$, type float32.
  - `scale`: Scaling tensor, shape $(N, 3)$, type float32.
  - `rot`: Rotation quaternions, shape $(N, 4)$, type float32.
  - `sh`: Spherical Harmonics coefficients, specifically the 0th degree, shape $(N, 3)$, extracted from features tensor `[:, 0, :]`.

**Steps:**

1. **Check Modality:** Determine which checkboxes are active (`depth`, `opacity`, `ellipsoid`). If none are active, default to RGB processing.

2. **Depth Rendering (if `depth_chbox` is checked):**
   a. Extract depth from `results["depth"]`. Shape is typically $(1, H, W)$. Detach from computation graph, move to CPU, and convert to NumPy array.
   b. Calculate `max_depth = np.max(depth)`.
   c. Normalize depth to RGB using `imgviz.depth2rgb(depth, min_value=0.1, max_value=max_depth, colormap="jet")`. This produces an array of shape $(H, W, 3)$ with values in $[0, 1]$.
   d. Convert back to PyTorch tensor.
   e. Permute dimensions from $(H, W, 3)$ to $(3, H, W)$ then to $(H, W, 3)$ for Open3D compatibility.
   f. Convert to byte type and make contiguous.
   g. Create Open3D `Image` object.

3. **Opacity Rendering (if `opacity_chbox` is checked):**
   a. Extract opacity from `results["opacity"]`.
   b. Calculate `max_opacity = np.max(opacity)`.
   c. Normalize opacity to RGB using `imgviz.depth2rgb(opacity, min_value=0.0, max_value=max_opacity, colormap="jet")`.
   d. Permute and convert to Open3D `Image` as in Step 2.

4. **Ellipsoid Rendering (if `ellipsoid_chbox` is checked):**
   a. **Setup OpenGL Context:**
      - Poll GLFW events.
      - Clear color, depth, and stencil buffers: `gl.glClearColor(0, 0, 0, 1.0)`, `gl.glClear(...)`.
      - Adjust window size if necessary based on `self.widget3d_width_ratio`.
   b. **Configure Camera:**
      - Set `self.g_camera.fovy` from `current_cam.FoVy`.
      - Update resolution: `self.g_camera.update_resolution(height, width)`.
      - Set renderer resolution: `self.g_renderer.set_render_reso(width, height)`.
      - Compute frustum from camera view matrix: `frustum = create_frustum(np.linalg.inv(cv_gl @ current_cam.get_view_matrix()))`.
      - Set camera position, target, and up vectors from frustum properties.
   c. **Upload Gaussian Attributes:**
      - Assign `self.gaussians_gl.xyz`, `opacity`, `scale`, `rot` from `gaussian_cur` attributes (CPU NumPy arrays).
      - Assign `self.gaussians_gl.sh` from `gaussian_cur.get_features.cpu().numpy()[:, 0, :]`.
   d. **Render:**
      - Update renderer state: `self.update_activated_renderer_state(self.gaussians_gl)`.
      - Sort and update Gaussians: `self.g_renderer.sort_and_update(self.g_camera)`.
      - Draw scene: `self.g_renderer.draw()`.
   e. **Read Pixels:**
      - Read framebuffer: `bufferdata = gl.glReadPixels(0, 0, width, height, gl.GL_RGB, gl.GL_UNSIGNED_BYTE)`.
      - Convert to NumPy array and reshape to $(H, W, 3)$.
      - **Flip Vertically:** OpenGL reads from bottom-left origin. Use `cv2.flip(img, 0, img)` to flip vertically to match standard image coordinates (top-left origin).
   f. Convert to Open3D `Image`.

5. **RGB Rendering (default or if no specific modality is selected):**
   a. Extract RGB image from `results`.
   b. Clamp values to $[0, 1]$.
   c. Scale to $[0, 255]$ and convert to byte.
   d. Permute to $(H, W, 3)$.
   e. Create Open3D `Image`.

**Pseudocode:**

```python
import numpy as np
import torch
import imgviz
import cv2
import open3d as o3d
import glfw
import OpenGL.GL as gl

def render_o3d_image(results, current_cam, gaussian_cur, self):
    """
    Renders depth, opacity, ellipsoid, or RGB images using Open3D.
    """
    # Helper to create Open3D image from numpy array (H, W, 3) uint8
    def to_o3d_image(np_img):
        return o3d.geometry.Image(np_img)

    if self.depth_chbox.checked:
        # 1. Depth Rendering
        depth = results["depth"]
        # Shape: (1, H, W) -> (H, W)
        depth = depth[0, :, :].detach().cpu().numpy()
        max_depth = np.max(depth)
        
        # Normalize using imgviz
        # Returns (H, W, 3) float32 in [0, 1]
        depth_rgb = imgviz.depth2rgb(
            depth, 
            min_value=0.1, 
            max_value=max_depth, 
            colormap="jet"
        )
        
        # Convert to Open3D Image
        # imgviz returns float32, Open3D expects uint8 or float32 depending on version
        # Assuming uint8 conversion for standard visualization
        depth_uint8 = (depth_rgb * 255).astype(np.uint8)
        return to_o3d_image(depth_uint8)

    elif self.opacity_chbox.checked:
        # 2. Opacity Rendering
        opacity = results["opacity"]
        # Shape: (1, H, W) -> (H, W)
        opacity = opacity[0, :, :].detach().cpu().numpy()
        max_opacity = np.max(opacity)
        
        opacity_rgb = imgviz.depth2rgb(
            opacity, 
            min_value=0.0, 
            max_value=max_opacity, 
            colormap="jet"
        )
        
        opacity_uint8 = (opacity_rgb * 255).astype(np.uint8)
        return to_o3d_image(opacity_uint8)

    elif self.ellipsoid_chbox.checked:
        # 3. Ellipsoid Rendering via OpenGL
        if gaussian_cur is None:
            return None

        # Setup OpenGL
        glfw.poll_events()
        gl.glClearColor(0, 0, 0, 1.0)
        gl.glClear(
            gl.GL_COLOR_BUFFER_BIT | 
            gl.GL_DEPTH_BUFFER_BIT | 
            gl.GL_STENCIL_BUFFER_BIT
        )

        # Adjust window size if needed
        w = int(self.window.size.width * self.widget3d_width_ratio)
        h = self.window.size.height
        glfw.set_window_size(self.window_gl, w, h)
        
        # Configure Camera
        self.g_camera.fovy = current_cam.FoVy
        self.g_camera.update_resolution(h, w)
        self.g_renderer.set_render_reso(w, h)
        
        # Compute frustum from view matrix
        # cv_gl is likely a coordinate system conversion matrix (e.g., OpenGL to OpenCV)
        view_matrix = current_cam.get_view_matrix()
        inv_view = np.linalg.inv(cv_gl @ view_matrix)
        frustum = create_frustum(inv_view)
        
        self.g_camera.position = frustum.eye.astype(np.float32)
        self.g_camera.target = frustum.center.astype(np.float32)
        self.g_camera.up = frustum.up.astype(np.float32)
        
        # Upload Gaussian Attributes
        self.gaussians_gl.xyz = gaussian_cur.get_xyz.cpu().numpy()
        self.gaussians_gl.opacity = gaussian_cur.get_opacity.cpu().numpy()
        self.gaussians_gl.scale = gaussian_cur.get_scaling.cpu().numpy()
        self.gaussians_gl.rot = gaussian_cur.get_rotation.cpu().numpy()
        # Extract 0th degree SH coefficients
        features = gaussian_cur.get_features.cpu().numpy()
        self.gaussians_gl.sh = features[:, 0, :]
        
        # Render
        self.update_activated_renderer_state(self.gaussians_gl)
        self.g_renderer.sort_and_update(self.g_camera)
        
        width, height = glfw.get_framebuffer_size(self.window_gl)
        self.g_renderer.draw()
        
        # Read Pixels
        # glReadPixels returns bytes in row-major order, bottom-left origin
        bufferdata = gl.glReadPixels(0, 0, width, height, gl.GL_RGB, gl.GL_UNSIGNED_BYTE)
        img = np.frombuffer(bufferdata, dtype=np.uint8).reshape((height, width, 3))
        
        # Flip vertically to match standard image coordinates (top-left origin)
        img = cv2.flip(img, 0)
        
        return to_o3d_image(img)

    else:
        # 4. Default RGB Rendering
        rgb = results["rgb"]
        # Shape: (1, H, W, 3) or (H, W, 3) depending on source
        # Assuming (1, H, W, 3)
        rgb = rgb[0].detach().cpu().numpy()
        
        # Clamp to [0, 1]
        rgb = np.clip(rgb, 0.0, 1.0)
        
        # Scale to [0, 255]
        rgb_uint8 = (rgb * 255).astype(np.uint8)
        
        return to_o3d_image(rgb_uint8)
```

**Parameters:**
- `min_value` for depth: `0.1` [S1, unofficial].
- `colormap`: `"jet"` [S1, unofficial].
- `cv_gl`: Coordinate transformation matrix (not defined in sources, assumed to be a standard OpenGL-to-OpenCV conversion matrix) [G].

**Edge Cases and Pitfalls:**
- **OpenGL Origin:** `glReadPixels` returns images with the origin at the bottom-left. Failure to flip vertically results in an upside-down image [S1, unofficial].
- **Depth Normalization:** The `min_value` for depth normalization is hardcoded to `0.1` in the source, which may clip very close depth values [S1, unofficial].
- **SH Coefficients:** Only the 0th degree (constant term) of Spherical Harmonics is used for ellipsoid rendering, ignoring higher-order color variations [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by the OpenGL rendering pass for ellipsoids, which involves sorting Gaussians ($O(N \log N)$ or $O(N)$ with spatial hashing) and rasterization. Depth/opacity rendering is $O(H \times W)$ for normalization.
- **Memory Complexity:** Requires storing Gaussian attributes in CPU and GPU memory. The OpenGL framebuffer requires $O(H \times W)$ memory for the pixel buffer.
- **Strengths:** Direct integration with Open3D for visualization; supports multiple modalities (depth, opacity, ellipsoid, RGB) in a single pipeline.
- **Limitations:** Relies on OpenGL context management, which can be complex to set up in headless environments. The hardcoded depth normalization parameters may not suit all scenes [S1, unofficial].
- **When to Use:** For visualizing Gaussian Splatting results in Open3D, especially when inspecting depth, opacity, or 3D ellipsoid structure.
- **When Not to Use:** For high-performance batch rendering where OpenGL overhead is prohibitive, or when higher-order SH color is required for visualization.

## Background
This pipeline is part of the MonoGS project, which integrates Gaussian Splatting with SLAM. It was developed to provide a flexible visualization interface for different aspects of the Gaussian Splatting representation [S1, unofficial]. The use of `imgviz` for depth/opacity visualization and OpenGL for ellipsoid rendering reflects common practices in 3D computer vision visualization tools.
