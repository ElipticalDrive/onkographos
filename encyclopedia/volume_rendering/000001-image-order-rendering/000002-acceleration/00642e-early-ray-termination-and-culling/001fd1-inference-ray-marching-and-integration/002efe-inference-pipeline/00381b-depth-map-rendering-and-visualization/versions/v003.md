# Depth Map Rendering and Visualization


## Overview
Depth Map Rendering and Visualization is the inference-stage script that renders a set of views from a trained dense point cloud (specifically Gaussian Splatting models), prunes points occluded by or near the camera, and saves rendered images, depth maps, and colored depth maps [S1, unofficial]. It differs from its parent [Inference Pipeline](5924-inference-pipeline.md) by focusing specifically on the extraction of depth data and pruning logic rather than the full image-order rendering loop for evaluation and video generation, which is handled by variants like [4DGS Rendering Pipeline](16175-4dgs-rendering-pipeline.md) [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A trained Gaussian model (`gaussians`), a list of camera views (`view`), camera intrinsics/extrinsics, a `near` distance threshold, and a background color tensor.
*   **Outputs:** Rendered RGB images, normalized depth maps, and colored depth maps saved as PNG files.

**Data Structures:**
*   `gaussians`: Contains `xyz` (positions), `opacity`, `scaling`, `rotation`, and SH coefficients.
*   `view`: Contains `camera_center`, `image`, and projection matrices.
*   `render_pkg`: Dictionary returned by the renderer containing `render` (RGB), `depth` (raw depth), and `alpha` (accumulated opacity).

**Parameters:**
*   `near`: The distance threshold (in world units) for pruning points near the camera. Typical values depend on the scene scale; [S1, unofficial] uses it to mask points within `near` units of the camera center.

**Steps:**
1.  **Initialize Output Directory:** Create a directory `render_path` at `model_path/name/ours_{iteration}`.
2.  **Compute Proximity Mask:** For all points, calculate the Euclidean distance to the camera center:
    $$ \text{dist}_i = \| \mathbf{p}_i - \mathbf{c}_{cam} \| $$
    where $\mathbf{p}_i$ is the position of point $i$ and $\mathbf{c}_{cam}$ is the camera center.
3.  **Accumulate Mask:** If rendering multiple views, accumulate the boolean mask of points where $\text{dist}_i < \text{near}$ across all views into `mask_near`.
4.  **Prune Points:** Remove points from the Gaussian model where `mask_near` is true using `gaussians.prune_points_inference(mask_near)` [S1, unofficial].
5.  **Render View:** For each view, call the renderer with `inference=True`:
    $$ \text{render\_pkg} = \text{render}(\text{view}, \text{gaussians}, \text{pipeline}, \text{background}, \text{inference}=\text{True}) $$
6.  **Extract Depth:** Retrieve raw depth `d_raw` and alpha `a` from `render_pkg`. Normalize the depth to $[0, 1]$ and combine with alpha to handle background:
    $$ d_{norm} = \frac{d_{raw} - \min(d_{raw})}{\max(d_{raw}) - \min(d_{raw})} $$
    $$ d_{final} = d_{norm} + (1 - a) $$
    *Note: The source formula adds $(1 - \text{alpha})$ after normalization. This effectively sets the background to 1.0 (farthest) if alpha is 0, assuming normalized depth is 0 at near and 1 at far.* [S1, unofficial].
7.  **Save Rendered Image:** Save `render_pkg["render"]` as a PNG.
8.  **Save Inverted Depth Map:** Save `1 - d_{final}` as a PNG.
9.  **Generate Colored Depth Map:**
    *   Convert `d_{final}` to numpy array.
    *   Apply a logarithmic curve function: $f(x) = -\ln(x + \epsilon)$, where $\epsilon$ is machine epsilon for float32.
    *   Apply the 'turbo' colormap to the result.
    *   Save the resulting RGB image as `cdepth_{idx}.png`.
10. **Video Generation:** (Optional) Use `ffmpeg` to compile the saved images into video summaries for renders, depths, and colored depths.

**Pseudocode:**
```python
import torch
import numpy as np
import torchvision.utils
import matplotlib.cm as cm
from scipy.ndimage import map_coordinates # Assuming standard libs, though source uses custom visualize_cmap

def render_depth_map(gaussians, views, near, model_path, iteration):
    import os
    from os.path import join
    from os import makedirs
    
    # 1. Initialize Output Directory
    render_path = join(model_path, "ours_{}".format(iteration))
    makedirs(render_path, exist_ok=True)
    
    # 2. Compute Proximity Mask (Global Pruning)
    mask_near = None
    for view in views:
        # Calculate distance from each Gaussian to the camera center
        # view.camera_center is (3,) or (1,3), gaussians.get_xyz is (N,3)
        dist = torch.norm(gaussians.get_xyz - view.camera_center, dim=1, keepdim=True)
        is_near = dist < near
        
        if mask_near is None:
            mask_near = is_near
        else:
            mask_near = mask_near | is_near
            
    # 3. Prune Points
    if mask_near is not None:
        gaussians.prune_points_inference(mask_near)

    # 4. Render and Save for each view
    for idx, view in enumerate(views):
        # 5. Render View
        with torch.no_grad():
            render_pkg = render(view, gaussians, pipeline, background, inference=True)
            
        rendering = render_pkg["render"]
        depth_raw = render_pkg['depth']
        alpha = render_pkg["alpha"]
        
        # 6. Extract and Normalize Depth
        # Normalize depth to [0, 1]
        d_min = depth_raw.min()
        d_max = depth_raw.max()
        if d_max - d_min < 1e-6:
            depth_norm = torch.zeros_like(depth_raw)
        else:
            depth_norm = (depth_raw - d_min) / (d_max - d_min)
            
        # Combine with alpha: background (alpha=0) becomes 1.0
        depth = depth_norm + (1.0 - alpha)
        
        # 7. Save Rendered Image
        torchvision.utils.save_image(rendering, join(render_path, '{0:05d}'.format(idx) + ".png"))
        
        # 8. Save Inverted Depth Map
        torchvision.utils.save_image(1 - depth, join(render_path, 'depth_{0:05d}'.format(idx) + ".png"))
        
        # 9. Generate Colored Depth Map
        depth_est = depth.squeeze().cpu().numpy()
        
        # Apply log curve
        eps = np.finfo(np.float32).eps
        depth_curve_fn = lambda x: -np.log(x + eps)
        
        # Apply colormap (simplified visualization logic)
        # Note: Source uses custom visualize_cmap. Standard implementation:
        depth_mapped = depth_curve_fn(depth_est)
        # Normalize mapped depth for colormap
        d_min_c = depth_mapped.min()
        d_max_c = depth_mapped.max()
        if d_max_c - d_min_c < 1e-6:
            depth_norm_c = np.zeros_like(depth_mapped)
        else:
            depth_norm_c = (depth_mapped - d_min_c) / (d_max_c - d_min_c)
            
        # Apply 'turbo' colormap
        # Assuming visualize_cmap handles the tensor conversion and permutation
        # Standard matplotlib approach:
        cmap = cm.get_cmap('turbo')
        depth_colored = cmap(depth_norm_c)[..., :3] # RGB
        
        # Convert to tensor and save
        depth_est_tensor = torch.as_tensor(depth_colored).permute(2, 0, 1)
        torchvision.utils.save_image(depth_est_tensor, join(render_path, 'cdepth_{0:05d}'.format(idx) + ".png"))

    # 10. Video Generation (Placeholder for ffmpeg command)
    # subprocess.run(["ffmpeg", "-framerate", "30", "-i", ...])
```

**Edge Cases and Pitfalls:**
*   **Depth Normalization:** If `depth_raw` has constant values (e.g., all background), division by zero occurs in normalization. A guard is required [G].
*   **Pruning Logic:** Pruning points near the camera is critical for stability in Gaussian Splatting inference to prevent artifacts from points inside the camera frustum or too close to the lens plane.
*   **Alpha Combination:** The formula $d_{final} = d_{norm} + (1 - \alpha)$ assumes that unrendered pixels (alpha=0) should be treated as "far" (depth=1). This is specific to the visualization pipeline and may not represent true geometric depth for transparent regions.

It differs from the parent [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md) by focusing specifically on the full image-order rendering loop for evaluation and visualization, including FPS calculation and video generation, rather than just depth map extraction and pruning.

### Flow Data Depth Rendering
Flow Data Depth Rendering converts optical flow and camera intrinsics/extrinsics into a depth map [S2, unofficial]. It handles validity, mesh export, and depth padding via morphological operations.
**Steps:**
1.  Calculate offset: $\text{offset} = \text{ref\_intr}[:, 0, 2] - \text{intr}[:, 0, 2]$.
2.  Compute disparity: $\text{disparity} = \text{offset} - \text{flow\_pred}$.
3.  Compute depth: $\text{depth} = -\text{disparity} / \text{Tf\_x}$.
4.  Multiply depth by mask to zero out invalid regions.
5.  If `pts_out_path` is provided, export depth mesh using `depth2mesh`.
6.  Transform points to original camera space using `perspective` with $\text{calib\_ori} = \text{intr\_ori} @ \text{extr\_ori}$. Invert z-depth.
7.  Render perspective depth using `taichi_render.render_perspective_depth` with valid mask.
8.  Apply padding to `render_depth` using `taichi_render.pad_depth` and store in `data['lmain']['depth_ori']` [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of Gaussians and the number of views. The pruning step is $O(N)$ where $N$ is the number of Gaussians. Rendering is $O(N \cdot V)$ where $V$ is the number of views.
*   **Memory Complexity:** $O(N)$ to store Gaussian attributes. The mask accumulation requires $O(N)$ bits.
*   **Strengths:** Efficiently handles large point clouds by pruning irrelevant points near the camera, improving rendering stability and speed. Provides standardized visualization outputs (RGB, Depth, Colored Depth).
*   **Limitations:** The depth normalization is view-dependent (min-max per view), which makes depth values non-comparable across different views or scenes without additional scaling. The pruning strategy is aggressive and may remove valid points if `near` is set too high.
*   **When to use:** When evaluating Gaussian Splatting models for geometric consistency or generating visualization datasets.
*   **When not to use:** When absolute metric depth is required without per-view normalization, or when real-time interactive rendering is needed (this is an offline inference script).

## Background
The method originates from the DNGaussian project, which extends 3D Gaussian Splatting to dynamic scenes (4D) [S1, unofficial]. The specific rendering and visualization pipeline was designed to support the evaluation of these dynamic models by providing consistent depth and color outputs. The Flow Data Depth Rendering variant is associated with the GPS-Gaussian+ project, which focuses on generalizable pixel-wise 3D Gaussian Splatting from sparse views [S2, unofficial].
