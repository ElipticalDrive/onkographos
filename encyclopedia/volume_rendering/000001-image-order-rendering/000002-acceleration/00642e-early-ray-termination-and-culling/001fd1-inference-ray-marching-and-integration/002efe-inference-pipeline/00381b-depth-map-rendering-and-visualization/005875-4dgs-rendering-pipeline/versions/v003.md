# 4DGS Rendering Pipeline
Also called: Rendering Pipeline for 4DGS, render_sets [S1, unofficial]

## Overview
The 4DGS Rendering Pipeline is the inference-stage script that iterates over a sequence of camera views to render images using the trained 4D Gaussian Splatting model, saves ground truth and rendered images, and generates a video summary [S1, unofficial]. It differs from the parent [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md) by focusing specifically on the full image-order rendering loop for evaluation and visualization, including FPS calculation and video generation, rather than just depth map extraction and pruning [S1, unofficial].

## How it works
**Inputs:**
- `views`: A list of camera view objects containing projection matrices, image data, and metadata [S1, unofficial].
- `gaussians`: The 4D Gaussian splatting model parameters (positions, covariances, opacities, colors, etc.) [S1, unofficial].
- `pipeline`: Rendering configuration parameters (e.g., rasterization settings) [S1, unofficial].
- `background`: Background color tensor [S1, unofficial].
- `name`: Dataset identifier (e.g., 'train', 'test', or specific scene name) [S1, unofficial].
- `cam_type`: Camera type string (e.g., 'PanopticSports' or standard pinhole) [S1, unofficial].
- `model_path`, `iteration`: Paths to locate output directories [S1, unofficial].

**Outputs:**
- Rendered images (PNG) in `renders/` [S1, unofficial].
- Ground truth images (PNG) in `gt/` [S1, unofficial].
- Video file `video_rgb.mp4` [S1, unofficial].
- Console output: FPS metric [S1, unofficial].

**Data Structures:**
- `render_images`: List of HWC uint8 numpy arrays for visualization [S1, unofficial].
- `render_list`: List of raw tensor renders (CHW format) for saving [S1, unofficial].
- `gt_list`: List of raw tensor ground truth images (CHW format) [S1, unofficial].

**Steps:**
1. **Setup Paths**: Create `render_path` and `gts_path` directories under `model_path/name/ours_{iteration}/renders` and `gt` respectively [S1, unofficial].
2. **Initialize**: Create empty lists `render_images`, `gt_list`, and `render_list` [S1, unofficial].
3. **Iterate Views**: Loop through `views` with a progress bar; record start time `time1` on the first view [S1, unofficial].
4. **Render**: Call `render(view, gaussians, pipeline, background, cam_type=cam_type)` and extract the `'render'` key from the returned dictionary [S1, unofficial].
5. **Convert and Store**: Convert rendering to 8-bit uint8 using `to8b` (clip to [0,1], multiply by 255, cast to uint8), transpose to HWC, and append to `render_images`; append raw tensor to `render_list` [S1, unofficial].
6. **Handle Ground Truth**: If `name` is 'train' or 'test', get GT; if `cam_type` is not 'PanopticSports', use `view.original_image[0:3, :, :]`; else, use `view['image'].cuda()` [S1, unofficial].
7. **Calculate FPS**: After loop, calculate FPS as `(len(views)-1)/(time2-time1)` [S1, unofficial].
8. **Save Images**: Use `multithread_write` to save `gt_list` to `gts_path` and `render_list` to `render_path` as PNGs named `{0:05d}.png` [S1, unofficial].
9. **Create Video**: Use `imageio.mimwrite` to create `video_rgb.mp4` in the output directory with fps=36 [S1, unofficial].

**Pseudocode:**
```python
import time
import os
import imageio
import numpy as np
import torch
from concurrent.futures import ThreadPoolExecutor

def to8b(tensor):
    """Clip to [0, 1], multiply by 255, cast to uint8."""
    return np.clip(tensor.cpu().numpy(), 0.0, 1.0) * 255.0

def multithread_write(tensor_list, save_dir):
    """Save list of tensors to PNG files named {index:05d}.png using a thread pool."""
    os.makedirs(save_dir, exist_ok=True)
    def save_one(idx, tensor):
        img = np.clip(tensor.cpu().numpy(), 0.0, 1.0) * 255.0
        img_uint8 = img.astype(np.uint8)
        imageio.imwrite(os.path.join(save_dir, f"{idx:05d}.png"), img_uint8)
    with ThreadPoolExecutor() as executor:
        list(executor.map(save_one, range(len(tensor_list)), tensor_list))

def render_pipeline(views, gaussians, pipeline, background, name, cam_type, model_path, iteration):
    # Setup Paths
    method_dir = os.path.join(model_path, name, f"ours_{iteration}")
    render_path = os.path.join(method_dir, "renders")
    gts_path = os.path.join(method_dir, "gt")
    os.makedirs(render_path, exist_ok=True)
    os.makedirs(gts_path, exist_ok=True)

    render_images = []
    gt_list = []
    render_list = []

    # Iterate Views
    for idx, view in enumerate(views):
        if idx == 0:
            time1 = time.time()
        
        # Render (core Gaussian rasterizer, implementation external to pipeline)
        rendering = render(view, gaussians, pipeline, background, cam_type=cam_type)["render"]
        
        # Convert and Store
        render_uint8 = to8b(rendering)
        render_hwc = render_uint8.transpose(1, 2, 0)
        render_images.append(render_hwc)
        render_list.append(rendering)
        
        # Handle Ground Truth
        if name in ["train", "test"]:
            if cam_type != "PanopticSports":
                gt = view.original_image[0:3, :, :]
            else:
                gt = view['image'].cuda()
            gt_list.append(gt)

    time2 = time.time()
    # Calculate FPS
    fps = (len(views) - 1) / (time2 - time1)
    print(f"FPS: {fps}")

    # Save Images
    multithread_write(gt_list, gts_path)
    multithread_write(render_list, render_path)

    # Create Video
    video_path = os.path.join(method_dir, "video_rgb.mp4")
    imageio.mimwrite(video_path, render_images, fps=36)
```

**Parameters:**
- `fps` for video: 36 [S1, unofficial].
- `resolution`: Performance metrics provided for 800x800 and 1352x1014 [S1, unofficial].

**Edge Cases:**
- If `name` is not 'train' or 'test', ground truth is not collected [S1, unofficial].
- If `cam_type` is 'PanopticSports', the GT extraction logic differs, requiring access to `view['image']` instead of `view.original_image` [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of views $N$ [S1, unofficial].
- **Measured Performance**: 82 FPS at 800x800 resolution for synthetic data; 30 FPS at 1352x1014 resolution for real datasets [S1, unofficial].
- **Strengths**: Provides standardized evaluation metrics (SSIM, PSNR, LPIPS) and visualization outputs for 4DGS models [S1, unofficial].
- **Limitations**: Performance is resolution-dependent and varies between synthetic and real-world datasets [S1, unofficial].

## Background
The 4DGS Rendering Pipeline originates from the 4D Gaussian Splatting method for dynamic scene reconstruction [S1, unofficial]. It is part of the evaluation and visualization suite provided in the implementation repository [S1, unofficial].
