# 4DGS Rendering Pipeline

Also called: Rendering Pipeline for 4DGS

## Overview
The 4DGS Rendering Pipeline is the inference-stage script that iterates over a sequence of camera views to render images using the trained 4D Gaussian Splatting model, saves the ground truth and rendered images, and generates a video summary. It distinguishes itself from standard 3DGS rendering by handling the temporal dimension implicitly through the view iteration loop and specific camera type handling (e.g., PanopticSports), while maintaining the same core rasterization backend. It builds on [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md) by extending the output to include video generation and specific metric evaluation contexts.

## How it works
**Inputs and Outputs:**
- **Inputs:** A list of camera views (`views`), the trained Gaussian model (`gaussians`), the rendering pipeline configuration (`pipeline`), a background color tensor (`background`), the scene name (`name`), and the camera type (`cam_type`).
- **Outputs:** Rendered images (PNGs), ground truth images (PNGs), and a video file (`video_rgb.mp4`).

**Data Structures:**
- `render_images`: List of numpy arrays (HWC, uint8) for display/debugging.
- `render_list`: List of raw tensors (CHW, float32) for saving.
- `gt_list`: List of raw tensors (CHW, float32) for saving.
- `render_path`: Directory path for rendered images.
- `gts_path`: Directory path for ground truth images.

**Steps:**
1. **Setup Paths:** Create directories `render_path` and `gts_path` under `model_path/name/ours_{iteration}/renders` and `gt` respectively. Ensure existence with `exist_ok=True`.
2. **Initialize Containers:** Initialize `render_images`, `gt_list`, and `render_list` as empty lists.
3. **Iterate Views:** Loop through `views` using `tqdm` for progress tracking.
4. **Timing:** If `idx == 0`, record start time `time1 = time()`.
5. **Render:** Call `rendering = render(view, gaussians, pipeline, background, cam_type=cam_type)["render"]`. This function performs the actual 4D Gaussian rasterization.
6. **Convert and Store:**
   - Convert `rendering` to 8-bit uint8 using `to8b` (clip to [0,1], multiply by 255, cast to uint8).
   - Transpose to HWC format: `render_images.append(to8b(rendering).transpose(1,2,0))`.
   - Append raw tensor to `render_list`: `render_list.append(rendering)`.
7. **Handle Ground Truth:** If `name` is 'train' or 'test':
   - If `cam_type` is not 'PanopticSports', extract GT: `gt = view.original_image[0:3, :, :]`.
   - Else (PanopticSports), extract GT: `gt = view['image'].cuda()`.
   - Append `gt` to `gt_list`.
8. **Calculate FPS:** After the loop, record end time `time2 = time()`. Calculate FPS as `(len(views)-1)/(time2-time1)`.
9. **Save Images:** Use `multithread_write` to save `gt_list` to `gts_path` and `render_list` to `render_path` as PNGs named `{idx:05d}.png`.
10. **Create Video:** Use `imageio.mimwrite` to create `video_rgb.mp4` in the output directory with `fps=36`.

```python
    x = torch.clamp(x, 0.0, 1.0)
    return (x * 255).to(torch.uint8)

def render_4dgs_pipeline(views, gaussians, pipeline, background, name, cam_type, model_path, iteration):
    # 1. Setup Paths
    method_dir = Path(model_path) / name / f"ours_{iteration}"
    renders_dir = method_dir / "renders"
    gts_dir = method_dir / "gt"
    renders_dir.mkdir(parents=True, exist_ok=True)
    gts_dir.mkdir(parents=True, exist_ok=True)
    
    render_images = []
    gt_list = []
    render_list = []
    
    print(f"point nums: {gaussians._xyz.shape[0]}")
    
    # 2. Iterate Views
    for idx, view in enumerate(views):
        if idx == 0:
            time1 = time.time()
        
        # 3. Render
        # The render function is assumed to be defined in the pipeline module
        rendering = render(view, gaussians, pipeline, background, cam_type=cam_type)["render"]
        
        # 4. Convert and Store
        # to8b clips to [0,1], multiplies by 255, casts to uint8
        # Transpose from CHW to HWC
        render_images.append(to8b(rendering).transpose(1, 2, 0))
        render_list.append(rendering)
        
        # 5. Handle Ground Truth
        if name in ["train", "test"]:
            if cam_type != "PanopticSports":
                gt = view.original_image[0:3, :, :]
            else:
                gt = view['image'].cuda()
            gt_list.append(gt)
            
    time2 = time.time()
    fps = (len(views) - 1) / (time2 - time1)
    print(f"FPS: {fps}")
    
    # 6. Save Images
    multithread_write(gt_list, gts_dir)
    multithread_write(render_list, renders_dir)
    
    # 7. Create Video
    # Note: render_images are HWC uint8. imageio expects this format.
    video_path = os.path.join(renders_dir, "video_rgb.mp4")
    imageio.mimwrite(video_path, render_images, fps=36)
```

**Parameters:**
- `fps`: 36 (for video generation).
- `resolution`: Varies by dataset (e.g., 800x800 for synthetic, 1352x1014 for real).

**Edge Cases and Pitfalls:**
- **PanopticSports:** Requires specific handling for GT extraction (`view['image'].cuda()` vs `view.original_image`).
- **Timing:** FPS calculation excludes the first view's rendering time in the denominator logic `(len(views)-1)`, which may skew performance metrics if the first view is significantly slower or faster.
- **Memory:** `render_list` stores all raw tensors in memory before saving. For very long sequences, this may cause OOM errors.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of views $N$. $O(N \cdot M)$ where $M$ is the number of Gaussians.
- **Memory Complexity:** $O(N \cdot H \cdot W \cdot C)$ for storing all rendered images in `render_list` and `render_images` before saving.
- **Measured Performance:** 82 FPS at 800x800 resolution for synthetic data; 30 FPS at 1352x1014 resolution for real datasets [S1, unofficial].
- **Strengths:** Simple, script-based pipeline; integrates video generation; handles multiple camera types.
- **Limitations:** High memory usage for long sequences; FPS calculation method is non-standard (excludes first frame).

## Background
The 4DGS Rendering Pipeline is part of the 4D Gaussian Splatting framework, which extends 3DGS to dynamic scenes. It was introduced in the context of the `ElenaViewSynthesis/4dgs` repository [S1, unofficial]. The pipeline serves as the inference counterpart to the training loop, allowing for the visualization and evaluation of the learned 4D scene.
