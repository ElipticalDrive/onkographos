# Chunked Volume Rendering

Also called: Chunked Volume Rendering with Early Stopping, Memory-efficient chunked rendering, NeRF-style Volume Rendering, TBRayMarcher Plugin, Volume Rendering (NeRF-style), VolumeRenderer, VolumeRendererChunk

## Overview
Chunked Volume Rendering is a memory-efficient inference technique that integrates color and density along rays by processing sampled points in fixed-size batches (chunks) [S1, S3, unofficial]. It solves the GPU memory bottleneck associated with rendering large scenes or high-resolution implicit fields by allowing a trade-off between memory usage and computational throughput [S3, unofficial]. It differs from its parent [Inference Ray Marching and Integration](2148-inference-ray-marching-and-integration.md) by explicitly batching the forward pass to constrain VRAM [S3, unofficial], and from its sibling [Inference Ray Compositing](3790-inference-ray-compositing.md) by focusing on the chunked accumulation of radiance rather than just the compositing logic [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A `ray_bundle` containing origins `[B, 3]`, directions `[B, 3]`, and pre-sampled 3D points `[B, N, 3]`; an implicit function `implicit_fn` to query density and features; a `sampler` to generate points; and configuration parameters (`chunk_size`, `raymarching_tolerance`, `white_background`) [S1, S3, unofficial].
*   **Output:** A dictionary containing `feature` (rendered color, shape `[B, 3]`) and `depth` (rendered depth, shape `[B, 1]`) [S1, unofficial].

**Data Structures:**
*   `chunk_features`: List of tensors storing rendered features for each chunk.
*   `chunk_depths`: List of tensors storing rendered depths for each chunk.
*   `accumulated_free_energy`: Tensor tracking the cumulative free energy (opacity) for early stopping [S3, unofficial].

**Parameters:**
*   `chunk_size`: Number of rays processed per iteration. Default is 65,536 (1024 * 64) for training, or `chunk_size // 1024` for inference [S3, unofficial].
*   `raymarching_tolerance`: Threshold for early stopping. If > 0, rays terminate when accumulated free energy exceeds `-log(tolerance)` [S3, unofficial].
*   `white_background`: Boolean. If True, background is white; otherwise black [S1, unofficial].

**Formulas:**
1.  **Segment Lengths (Deltas):**
    $$ \delta = [d_2-d_1, \dots, d_n-d_{n-1}, 10^{10}] $$
    where $d_i$ are the distances of sample points from the origin [S1, unofficial]. The last delta is set to a large value to ensure termination [S1, unofficial].

2.  **Hit and Empty Probabilities:**
    Let $f_t$ be the "free energy" (density $\times$ delta) at step $t$ [S3, unofficial].
    $$ a_t = 1 - \exp(-f_t) \quad \text{(Probability of hit at step } t \text{)} $$
    $$ b_t = \exp\left(-\sum_{k=0}^{t-1} f_k\right) \quad \text{(Probability of empty space up to step } t \text{)} $$
    $$ \text{probs}_t = a_t \times b_t $$
    [S3, unofficial]

3.  **Rendering:**
    $$ \text{color} = \sum_t \text{texture}_t \times \text{probs}_t $$
    $$ \text{depth} = \sum_t \text{sampled\_depth}_t \times \text{probs}_t $$
    $$ \text{missed} = 1 - \sum_t \text{probs}_t $$
    [S3, unofficial]

**Algorithm:**
1.  Initialize `accumulated_free_energy` to zeros, `chunk_features` and `chunk_depths` to empty lists [S4, unofficial].
2.  Determine total rays $N$. Iterate `chunk_start` from 0 to $N$ with step `chunk_size` [S4, unofficial].
3.  Slice `ray_bundle` for the current chunk: `cur_ray_bundle = ray_bundle[chunk_start : chunk_start + chunk_size]` [S4, unofficial].
4.  Call the parent forward method (or `forward_once`) with `cur_ray_bundle` to get `cur_feature` and `cur_depth` [S4, unofficial].
    *   *Note:* If the implementation uses explicit accumulation within the chunk loop (as in [S3, unofficial]), iterate through sample indices $i$. Compute weights $w_t = \text{probs}_t$. Update `accumulated_free_energy`. The logic for early stopping is: if `raymarching_tolerance > 0`, maintain a running sum of `free_energy` [S3, unofficial]. If the sum exceeds `-log(raymarching_tolerance)`, set `alpha` to 0 for all subsequent steps for that ray [S3, unofficial].
5.  Append `cur_feature` to `chunk_features` and `cur_depth` to `chunk_depths` [S4, unofficial].
6.  Concatenate all chunks:
    $$ \text{feature} = \text{cat}(chunk\_features, \text{dim}=0) $$
    $$ \text{depth} = \text{cat}(chunk\_depths, \text{dim}=0) $$
7.  If `white_background` is True, add `(1 - missed) * 1.0` to color [S1, unofficial].
8.  Return `feature` and `depth`.

**Pseudocode:**
```python
import torch
import math

def chunked_volume_render(ray_bundle, implicit_fn, sampler, chunk_size=65536, raymarching_tolerance=0.0, white_background=False):
    # ray_bundle: dict with 'origins' [B, 3], 'directions' [B, 3], 'points' [B, N, 3]
    # Returns: feature [B, 3], depth [B, 1]
    
    B = ray_bundle['origins'].shape[0]
    chunk_features = []
    chunk_depths = []
    
    # Handle edge case: no rays
    if B == 0:
        return torch.zeros((0, 3)), torch.zeros((0, 1))

    for chunk_start in range(0, B, chunk_size):
        # Slice current chunk
        end_idx = min(chunk_start + chunk_size, B)
        cur_ray_bundle = {
            'origins': ray_bundle['origins'][chunk_start:end_idx],
            'directions': ray_bundle['directions'][chunk_start:end_idx],
            'points': ray_bundle['points'][chunk_start:end_idx]
        }
        
        # Sample points if not provided, or use provided points
        # Assuming sampler returns points [B_chunk, N, 3]
        points = sampler(cur_ray_bundle)
        
        # Compute deltas: distances from origin, then differences, then large final delta
        dists = torch.sqrt(((points - cur_ray_bundle['origins'].unsqueeze(1)) ** 2).sum(dim=-1)) # [B_chunk, N]
        diffs = dists[:, 1:] - dists[:, :-1] # [B_chunk, N-1]
        large_delta = torch.ones_like(diffs[:, :1]) * 1e10
        deltas = torch.cat([diffs, large_delta], dim=1) # [B_chunk, N]
        
        # Query implicit function for density and color
        # density [B_chunk, N, 1], color [B_chunk, N, 3]
        density, color = implicit_fn(points)
        
        # Compute probabilities
        # free_energy = density * deltas
        free_energy = density.squeeze(-1) * deltas # [B_chunk, N]
        
        # Shifted free energy for transmittance
        # b_t = exp(-cumsum(shifted_free_energy))
        shifted_free_energy = torch.cat([torch.zeros_like(free_energy[:, :1]), free_energy[:, :-1]], dim=1)
        transmittance = torch.exp(-torch.cumsum(shifted_free_energy, dim=1))
        
        # Alpha and weights
        alpha = 1.0 - torch.exp(-free_energy)
        weights = alpha * transmittance
        
        # Early stopping logic per [S3, unofficial]
        if raymarching_tolerance > 0:
            cum_free_energy = torch.cumsum(free_energy, dim=1)
            early_stop_mask = cum_free_energy > -math.log(raymarching_tolerance)
            # Zero out weights for steps after early stop
            weights = weights * (~early_stop_mask).float()
        
        # Render Color and Depth
        # color = sum(weights * color)
        rendered_color = torch.sum(weights.unsqueeze(-1) * color, dim=1)
        
        # depth = sum(weights * depth_samples)
        # depth_samples are distances of points from origin
        depth_samples = dists # [B_chunk, N]
        rendered_depth = torch.sum(weights * depth_samples, dim=1)
        
        # Missed probability
        missed = 1.0 - torch.sum(weights, dim=1)
        
        # Apply background
        if white_background:
            rendered_color = rendered_color + (1.0 - missed.unsqueeze(-1)) * 1.0
        else:
            rendered_color = rendered_color # Black background (0)
            
        chunk_features.append(rendered_color)
        chunk_depths.append(rendered_depth.unsqueeze(-1))
        
    # Concatenate results
    final_feature = torch.cat(chunk_features, dim=0)
    final_depth = torch.cat(chunk_depths, dim=0)
    
    return final_feature, final_depth
```
[G] The pseudocode above implements the standard NeRF-style integration [S1, S3, unofficial]. The source [S3, unofficial] mentions an `accumulated_free_energy` variable used for early stopping within a loop over samples. The logic for early stopping is: if `raymarching_tolerance > 0`, maintain a running sum of `free_energy` [S3, unofficial]. If the sum exceeds `-log(raymarching_tolerance)`, set `alpha` to 0 for all subsequent steps for that ray [S3, unofficial]. This is implemented as a vectorized mask in the pseudocode for efficiency, matching the source's intent.

## Subtopics

### [Chunked Volume Rendering with Occupancy Grid Estimator](4652-chunked-volume-rendering-with-occupancy-grid-estimator.md)
This method accelerates volume rendering by combining chunked ray batching with an occupancy grid estimator to sample along rays, query a radiance field for density and color at sample midpoints, and composite the result per chunk. It differs from its parent [Chunked Volume Rendering](4310-chunked-volume-rendering.md) by integrating a hierarchical occupancy grid for adaptive sampling, and from its sibling [Block-based Volume Rendering Strategy](13140-block-based-volume-rendering-strategy.md) by using a continuous grid-based estimator rather than discrete block structures [G].

### [Partitioned Volume Rendering Derivation](10384-partitioned-volume-rendering-derivation.md)
Partitioned Volume Rendering Derivation provides the mathematical foundation for distributing volumetric rendering across multiple disjoint spatial segments (partitions) along a ray. It solves the problem of correctly accumulating color, transmittance, and auxiliary losses (such as distortion) when a ray traverses multiple independent volume tiles, which may be processed by different compute units. It sets itself apart from standard single-volume ray marching by explicitly decomposing global integrals into sums of local segment integrals weighted by upstream transmittance, enabling parallel prefix-scan accumulation.

### [Block-based Volume Rendering Strategy](13140-block-based-volume-rendering-strategy.md)
A rendering strategy for large scenes partitioned into blocks, where each block uses a separate shader due to web texture unit limits. It solves the problem where standard volume rendering fails because sampling points across a ray may belong to different blocks loaded by different shaders, breaking 3D consistency and correct occlusion. It differs from [Chunked Volume Rendering with Occupancy Grid Estimator](4652-chunked-volume-rendering-with-occupancy-grid-estimator.md) by using sequential block rendering with separate shaders rather than occupancy grids to skip empty space, and from [Partitioned Volume Rendering Derivation](10384-partitioned-volume-rendering-derivation.md) by enforcing strict back-to-front sorting and post-hoc accumulation.

### Tricubic B-Spline Reconstruction
Opt-in tricubic B-spline reconstruction fixes texel staircase artifacts but does not remove ringing [S5, unofficial]. It requires a 2-voxel halo [S5, unofficial]. Implementation involves `chunking.ts` defining `LINEAR_MIN_HALO` / `CUBIC_MIN_HALO` / `planSupportsHalo` / `planSupportsCubic`, and `NVChunkedVolume.raiseHaloTo()` re-planning loaded volumes when the setter fires [S5, unofficial]. Both views gate cubic per draw on halo >= 2 and not-a-label-volume (including coarse-floor cube) [S5, unofficial]. The `volumeIsCubicInterpolation` boolean defaults to off and is available on both backends [S5, unofficial]. The public default halo stays [1,1,1] [S5, unofficial].

### Chunk 0 Eviction Fix
Fixes WebGL2 volume blanking when chunk 0 is evicted, caused by `draw()` early-returning on null `volumeTexture`/`volumeGradientTexture` which were best-effort aliases of chunk 0 [S5, unofficial]. The fix removes the early-return on null textures for chunked volumes [S5, unofficial]. It fixes `swapChunkedVolumePlan` to refresh aliases after `manager.remap()` destroys unmatched chunks [S5, unofficial]. It also fixes switching from chunked to single volume to prevent the single-volume path from deleting textures the chunked cache entry still owns [S5, unofficial].

### 4-in-1 Material Workaround
Hacks the Material of the Heterogeneous Volume Actor (HVA) to extend the single SVT evaluation to select and sample from four different chunks, feeding the internal lighting cache with values from all chunks to create seamless rendering [S6, unofficial]. Uses an SVT of full resolution spanning the volume with values only at min/max corners to trick the HVA into believing it has one volume of a certain resolution, while sampling four payload chunks as if they were one texture [S6, unofficial]. Compensates for heavy performance impact (~1fps) by allowing interactive navigation with fewer samples per ray march (e.g., 32) and rendering with more samples (e.g., 512) when an interesting view is found [S6, unofficial]. Controlled via console command `r.HeterogeneousVolumes.MaxStepCount=32` [S6, unofficial]. This workaround results in a heavy performance hit, dropping framerates to ~1fps, and requires a complicated chunking/importing setup and custom material [S6, unofficial].

### Surface Volume Rendering
A rendering method that renders at the estimated intersection point of the ray with the surface, rather than integrating along the entire ray [S3, unofficial]. Computes normalized probabilities by clamping min 1e-6 and masking out non-hit voxels [S3, unofficial]. Determines voxel index at intersection by counting how many boundaries are less than or equal to `n_depth` [S3, unofficial]. Gathers the voxel index at the intersection depth [S3, unofficial]. Calls `forward_once` with new samples to get texture and normal at the intersection [S3, unofficial]. Intersection depth: $\text{n\_depth} = \frac{\sum_t \text{sampled\_depth}_t \times \text{n\_probs}_t}{\sum_t \text{n\_probs}_t}$ [S3, unofficial]. Boundary depth: $\text{n\_bound} = \text{sampled\_depth} + \frac{\text{sampled\_distance}}{2}$ [S3, unofficial]. Rendered color: $\text{color} = \text{texture} \times (1 - \text{missed})$ [S3, unofficial]. Eikonal term for surface rendering: $\text{eikonal} = (\|\text{normal}\|_2 - 1)^2$ [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot B)$, where $N$ is the number of samples per ray and $B$ is the number of rays [S3, unofficial]. Chunking does not change the asymptotic complexity but increases overhead due to loop iterations [S3, unofficial].
*   **Memory Complexity:** $O(B_{chunk} \cdot N)$, where $B_{chunk}$ is the `chunk_size` [S3, unofficial]. This allows rendering scenes with $B \gg B_{chunk}$ by trading memory for time [S3, unofficial].
*   **Performance:** In Unreal Engine, chunking allows rendering datasets >1 gigavoxel, but introduces visual artifacts at chunk borders if lighting is computed independently per chunk [S2, unofficial]. A workaround using a "4-in-1" material can achieve seamless lighting but drops framerates to ~1fps [S6, unofficial].
*   **Strengths:** Enables rendering of very large scenes or high-resolution implicit fields on GPUs with limited VRAM [S3, unofficial].
*   **Limitations:** Chunking can introduce artifacts if not handled correctly (e.g., lighting discontinuities) [S2, unofficial]. Early stopping requires careful tolerance tuning to avoid premature termination [S3, unofficial].

## Background
Chunked Volume Rendering is based on the volume rendering equations defined in [Mildenhall et al. 2020] (NeRF) [S1, unofficial]. It has been implemented in various contexts, including the TBRayMarcher plugin for Unreal Engine [S2, unofficial], the NSVF framework by Facebook Research [S3, unofficial], and web-based viewers like Niivue [S5, unofficial]. The technique is essential for real-time inference of large neural radiance fields and volumetric datasets [S3, unofficial].
