# Patch-based Volume Rendering

Also called: Image Patching, Patch-based rendering strategy

## Overview
A memory-saving rendering strategy for high-resolution volumes that splits the spatial dimensions into overlapping patches, renders them independently, and merges the results to scale to arbitrary image resolutions [S2]. Unlike full-volume rendering which requires memory proportional to $H \times W$, the patch-based approach trades redundant computation in overlapping regions for drastically reduced memory footprint, enabling scaling to arbitrary resolutions [S2]. Partitions the spatial domain into smaller, independently processed regions [S2].

## How it works
**Inputs and Outputs:**
- Input: A target image resolution $H \times W$, a volume representation (coarse and fine models), and a patch grid configuration $P \times P$ [S2].
- Output: A rendered image of resolution $H \times W$ [S2].

**Data Structures:**
The method relies on the standard volume representation used in MuRF [S2]:
- **Coarse Volume:** Resolution $H/8 \times W/8 \times D_1 \times C_1$ [S2].
- **Fine Volume:** Resolution $H \times W \times D_2 \times C_2$ [S2].
- **Patches:** The spatial dimensions ($H, W$) are divided into a grid of $P \times P$ overlapping patches [S2].

**Parameters:**
- $P \times P$: Grid size of overlapping patches along the spatial dimensions. Typical value: $4 \times 4$ (yielding 16 patches) [S2].
- $D_1$: Number of sampling points per ray for the coarse model. Value: 64 [S2].
- $D_2$: Number of sampling points per ray for the fine model. Value: 16 [S2].
- $C_1$: Feature dimension of the coarse volume representation. Value: 128 [S2].
- $C_2$: Feature dimension of the fine volume representation. Value: 16 [S2].

**Steps:**
1. **Partition:** Split the volume's first two spatial dimensions into a grid of $P \times P$ overlapping patches [S2].
2. **Render:** Render each patch independently using the standard volume rendering pipeline [S2].
3. **Merge:** Combine all patch results into a full image, combining overlapping regions with simple averaging [S2].

**Pseudocode:**
```python
import numpy as np

def patch_based_volume_rendering(target_h, target_w, P, volume_model):
    """
    Renders a high-resolution image using patch-based volume rendering.
    
    Args:
        target_h (int): Target image height.
        target_w (int): Target image width.
        P (int): Number of patches per spatial dimension.
        volume_model: Volume representation containing coarse and fine models [S2].
        
    Returns:
        numpy.ndarray: Rendered image of shape (target_h, target_w, 3).
    """
    patch_h = target_h // P
    patch_w = target_w // P
    
    # Overlap ratio is not specified in the sources [G].
    # Implementation typically uses a fixed fraction or pixel margin.
    overlap_h = int(patch_h * 0.25)
    overlap_w = int(patch_w * 0.25)
    
    accumulated_color = np.zeros((target_h, target_w, 3))
    coverage_count = np.zeros((target_h, target_w))
    
    for i in range(P):
        for j in range(P):
            # Define patch bounds with overlap, clamped to image dimensions
            y_start = max(0, i * patch_h - overlap_h)
            y_end = min(target_h, (i + 1) * patch_h + overlap_h)
            x_start = max(0, j * patch_w - overlap_w)
            x_end = min(target_w, (j + 1) * patch_w + overlap_w)
            
            # Standard volume rendering pipeline for the region [G].
            # Generates rays for the region, samples coarse (D1=64, C1=128) and fine (D2=16, C2=16) volumes,
            # and composites color and opacity. Implementation details are not provided in the sources [G].
            patch_img = np.zeros((y_end - y_start, x_end - x_start, 3))  # Placeholder for actual rendering [G]
            
            # Accumulate results for simple averaging in overlapping regions [S2]
            accumulated_color[y_start:y_end, x_start:x_end] += patch_img
            coverage_count[y_start:y_end, x_start:x_end] += 1.0
            
    # Combine overlapping regions with simple averaging [S2]
    safe_count = np.maximum(coverage_count, 1e-8)
    final_image = accumulated_color / safe_count[:, :, np.newaxis]
    return final_image
```

**Edge Cases and Pitfalls:**
- **Precision:** Standard volume rendering precision applies. No specific numerical issues are noted for the patching strategy itself [S2].
- **Boundaries:** The merging step handles boundaries by averaging. Pixels on the edge of the image may be covered by fewer patches if the patches do not extend to the image border; the accumulator naturally divides by the coverage count for these pixels [S2].
- **Degenerate Input:** Not applicable.

## Operating characteristics
- **Time Complexity:** Increases by a factor related to the overlap ratio, as redundant computation occurs in overlapping regions [S2].
- **Memory Complexity:** Drastically reduced compared to full-volume rendering, as the memory footprint is proportional to the size of a single patch's volume representation rather than the full $H \times W$ volume [S2].
- **Measured Performance:** 1536 × 2048 resolution renderings were produced on the LLFF dataset using 16 (4 × 4) overlapping patches [S2]. Removing patching makes the system 10% to 52% slower [S1, unofficial].
- **Strengths:** Enables scaling to virtually arbitrary image resolutions on general hardware where standard volume resolution becomes a memory bottleneck [S2].
- **Limitations:** Redundant computation in overlapping regions [S2].
- **When to use:** High-resolution rendering on general hardware when standard volume resolution becomes a memory bottleneck [S2].
- **When not:** When memory is not a constraint and computational efficiency is prioritized over resolution scaling [S2].

## Background
- **Origin:** Developed as part of MuRF (Multi-Baseline Radiance Fields) [S2].
- **History:** The method was introduced to handle high-resolution rendering targets (e.g., 1536 × 2048) that exceed the memory capacity of typical hardware for full-volume representations [S2]. Patching has an especially high impact for high-resolution scenes such as Sci-Art (6K), where cutting these higher-resolution images into patches gives more potential for flexible assignment [S1, unofficial].
- **Usage:** Implemented in MuRF for high-resolution rendering on general hardware [S2].
