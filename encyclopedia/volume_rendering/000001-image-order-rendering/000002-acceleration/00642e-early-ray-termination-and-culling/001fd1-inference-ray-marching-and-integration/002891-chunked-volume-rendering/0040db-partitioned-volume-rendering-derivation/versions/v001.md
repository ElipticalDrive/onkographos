# Partitioned Volume Rendering Derivation

Also called: Distributed Volume Rendering Equations

## Overview
Partitioned Volume Rendering Derivation is a method for performing volumetric rendering over a partition of possible $t$ values in the union of rendering volumes, combining results from disjoint volume integrals and a void model for empty space [S2, unofficial]. It enables the decomposition of global volume rendering integrals into local segment contributions that can be computed independently and aggregated, facilitating distributed rendering across multiple GPUs or tiles [S1]. Unlike sibling methods that may rely on occupancy grids or specific block-based strategies for culling, this approach focuses on the mathematical derivation of how color, transmittance, and distortion losses decompose across arbitrary spatial partitions [S1][S2, unofficial].

## How it works
The method operates by intersecting rays with spatial partitions, computing local volume integrals for each partition, and combining them using a recursive composition rule that accounts for upstream transmittance.

### Inputs and Outputs
**Inputs:**
- Ray origin $o$ and direction $d$.
- A set of spatial partitions (tiles) defined by volume ranges $[t_k, t_{k+1}]$.
- A neural volume model (e.g., NeRF) capable of querying density $\sigma$ and color $c$ at 3D positions.
- A void model for empty space background.
- Number of samples per partition segment, $N_{samples}$ (denoted as `n_samples` in implementation) [S2, unofficial].

**Outputs:**
- Rendered color $C(r)$ for the ray.
- Transmittance $T$ at the end of the ray.
- Optionally, accumulated depth and distortion loss components for training [S1].

### Data Structures
The core data structure for accumulating results is `RayVolumeIntegralResults` (or equivalent), which typically contains:
- `output`: Accumulated color (and other auxiliary channels like depth, opacity).
- `transmittance`: Scalar or tensor representing the transmittance through the accumulated segments.
- `volume_range`: Metadata defining the $t$ interval $[t_0, t_{end}]$ covered by the accumulated results.

In the implementation source [S2, unofficial], the `RayVolumeIntegral` class holds:
- `model`: The neural network (NeRFModel).
- `volume`: The spatial volume definition (Volume).
- `sampler`: The ray sampler (RaySampler).
- `n_samples`: Integer, number of samples per segment.

### Numbered Steps

1. **Initialization**: Initialize `results` to `None`, `samplers` to an empty list, `raw_outputs` to an empty list, and `t0` to `None` [S2, unofficial].

2. **Iterate over Partitions**: For each partition $i$ in the ray's path:
    a. **Create Sampler**: Create an `ImportanceRaySampler` using the partition's `volume_range`, the previous `raw_outputs` (if any, for stratified/importance sampling context), and `importance_sampling_options` [S2, unofficial]. Append to `samplers`.
    b. **Store Raw Data**: Append the partition's raw output metadata (e.g., `results_i.raw`) to `raw_outputs` [S2, unofficial].
    c. **Update Start Time**: Update `t0` to `results_i.volume_range.next_t0()` [S2, unofficial].
    d. **Render Segment**: Perform `RayVolumeIntegral.render_rays` for the current partition (see Sub-steps 2.1-2.4 below).
    e. **Combine Results**: Combine the current segment's result `results_i` with the accumulated `results`. If `results` is `None`, set `results = results_i`. Otherwise, `results = results_i.combine(results)` [S2, unofficial]. The combination rule is defined in the Formulas section.

3. **Add Void Background**: After processing all partitions, add the void background contribution:
   $$ \text{results.output.channels} = \text{results.output.channels} + \text{results.transmittance} \cdot \text{void\_model}(\text{Query}(origin, direction)) $$
   [S2, unofficial]

#### Sub-steps for `RayVolumeIntegral.render_rays` (per partition):

1. **Intersect and Sample**:
   - Intersect rays with the volume partition to get $t$ range $[t_0, t_1]$ (denoted as `vrange`). If the ray does not intersect, mark as non-intersected [S2, unofficial].
   - Sample $N_{samples}$ points $t$ within $[t_0, t_1]$ using the sampler [S2, unofficial].

2. **Query Model**:
   - Compute positions: $p = o + t \cdot d$ [S2, unofficial].
   - Compute midpoints between samples: $m = (t_{i+1} + t_i) / 2$ [S2, unofficial].
   - Query the neural model with positions $p$, direction $d$, and integration bounds $[t_{min}, t_{max}]$ where $t_{min} = [t_0, m_1, m_2, \dots]$ and $t_{max} = [m_1, m_2, \dots, t_1]$ [S2, unofficial]. The model returns raw outputs (density $\sigma$, color $c$, etc.) [S2, unofficial].

3. **Integrate Samples**:
   - Call `integrate_samples` with the volume range and raw outputs to compute local `output` and `transmittance` [S2, unofficial].

4. **Mask Non-Intersected Rays**:
   - If the ray did not intersect the partition volume, mask the results:
     - Set `transmittance` to 1.0 (no absorption) [S2, unofficial].
     - Set `output` channels to 0.0 (no emission) [S2, unofficial].

#### Sub-steps for `RayVolumeIntegral.integrate_samples`:

1. **Compute Transmittance and Weights**:
   - Calculate step sizes: $\Delta t = \text{partition}(raw.ts)$ [S2, unofficial].
   - Compute optical depth per step: $ddensity = \sigma \cdot \Delta t$ [S2, unofficial].
   - Compute cumulative optical depth: $mass = \text{cumsum}(ddensity, \text{dim}=-2)$ [S2, unofficial].
   - Compute final transmittance for the segment: $T_{end} = \exp(-mass_{last})$ [S2, unofficial].
   - Compute per-sample alphas: $\alpha = 1.0 - \exp(-ddensity)$ [S2, unofficial].
   - Compute per-sample transmittance $T_s$:
     $$ T_s = \exp\left( \text{concat}([0, -mass_{:-1}]) \right) $$
     (i.e., $T_s$ at index $i$ is $\exp(-\sum_{j=0}^{i-1} ddensity_j)$) [S2, unofficial].
   - Compute weights: $w = \alpha \cdot T_s$ [S2, unofficial].

2. **Accumulate Output**:
   - For each output channel (e.g., color), compute:
     $$ \text{channel\_output} = \sum_{i} \text{channel\_sample}_i \cdot w_i $$
   - If auxiliary losses (like distortion) are tracked, integrate them using detached weights to prevent gradient flow through the weighting mechanism if required by the loss formulation [S2, unofficial].

### Formulas

**1. Color Accumulation Decomposition**
The total color $C(r)$ for a ray passing through $N$ partitions is:
$$ C(r) = \sum_{i=1}^N \left( T(t_{i-1}) \cdot \int_{t_{i-1}}^{t_i} \sigma(t) c(t) T(t_{i-1} \rightarrow t) \, dt \right) + T(t_N) \cdot C_{void} $$
Where:
- $t_0$ is the ray origin.
- $T(t_a \rightarrow t_b) = \exp\left(-\int_{t_a}^{t_b} \sigma(u) \, du\right)$ is the transmittance from $t_a$ to $t_b$.
- $C_{void}$ is the background color from the void model [S2, unofficial].

This can be viewed recursively. For two adjacent segments $[t_0, t_1]$ and $[t_1, t_2]$:
$$ \int_{t_0}^{t_2} = \int_{t_0}^{t_1} + T(t_0 \rightarrow t_1) \cdot \int_{t_1}^{t_2} $$
Implemented as: `prev_val + prev_transmittance * cur_val` [S1][S2, unofficial].

**2. Distortion Loss Decomposition**
The distortion loss $\mathcal{L}_{dist}$ over $N$ segments decomposes as [S1]:
$$ \mathcal{L}_{dist}(t_1 \rightarrow t_{N+1}) = 2 \sum_{k=1}^N T(t_1 \rightarrow t_k) S(t_1 \rightarrow t_k) + \sum_{k=1}^N T(t_1 \rightarrow t_k)^2 \mathcal{L}_{dist}(t_k \rightarrow t_{k+1}) $$
Where:
- $S(t_1 \rightarrow t_k) = D(t_k \rightarrow t_{k+1})A(t_1 \rightarrow t_k) - A(t_k \rightarrow t_{k+1})D(t_1 \rightarrow t_k)$
- $A$ is accumulated weight (opacity).
- $D$ is accumulated depth.
- $\mathcal{L}_{dist}(t_k \rightarrow t_{k+1})$ is the local distortion loss for segment $k$ [S1].

**3. Intermediate Term S**
$$ S(t_1 \rightarrow t_k) = D(t_k \rightarrow t_{k+1})A(t_1 \rightarrow t_k) - A(t_k \rightarrow t_{k+1})D(t_1 \rightarrow t_k) $$
This term captures the interaction between the depth/weight statistics of the current segment and the accumulated statistics from previous segments [S1].

### Parameters
- **N**: The number of segments (partitions) along the ray, corresponding to the number of tiles the ray intersects [S1].
- **n_samples**: Number of samples per segment. Typical values depend on the desired accuracy and computational budget; not explicitly fixed in sources but implied by `RayVolumeIntegral` layout [S2, unofficial].
- **void_model**: A function or model providing background color for empty space [S2, unofficial].

### Edge Cases and Pitfalls
- **Non-Intersected Rays**: Rays that do not intersect any volume partition must be handled by masking outputs to zero and transmittance to one to avoid incorrect accumulation [S2, unofficial].
- **Precision**: Cumulative sums of optical depth (`mass`) can suffer from precision issues for very long rays or high-density volumes. Using `torch.cumsum` is standard, but extreme cases may require higher precision types [S2, unofficial].
- **Boundary Continuity**: The partitioning scheme should ensure that boundaries between partitions do not introduce artifacts. The recursive spatial partitioning (e.g., splitting at CDF 0.5) aims to create nearly cubic partitions to minimize aspect ratio issues [S1].
- **Gradient Flow**: When computing auxiliary losses like distortion, weights may need to be detached (`weights.detach()`) to prevent unintended gradient paths through the weighting mechanism, depending on the specific loss formulation [S2, unofficial].

## Operating characteristics
- **Time Complexity**: Linear in the number of partitions $N$ and samples per partition $S$. Total complexity $O(N \cdot S)$. Since partitions are processed independently, this scales well with parallel hardware (e.g., multiple GPUs) [S1].
- **Memory Complexity**: Linear in the number of active partitions and samples. Each partition's raw output and intermediate results must be stored until combination [S2, unofficial].
- **Strengths**: Enables distributed rendering across multiple GPUs by allowing independent computation of segment integrals. Facilitates efficient training by decomposing global losses into local components [S1].
- **Limitations**: Requires a spatial partitioning scheme (e.g., grid, octree) to define the segments. Over-partitioning can increase overhead; under-partitioning reduces parallelism benefits [S1].
- **When to Use**: Large-scale scenes that exceed single-GPU memory or require distributed training/inference. When distortion loss is used, as it provides a clean decomposition [S1].

## Background
The method originates from **NeRF-XL**, which proposed scaling NeRFs using multiple GPUs by partitioning the spatial domain [S1]. The derivation of the volume rendering integrals and distortion loss across partitions allows for distributed computation. The implementation details in [S2, unofficial] reflect a modern PyTorch-based approach to these principles, integrating them into a training pipeline for 3D generation.
