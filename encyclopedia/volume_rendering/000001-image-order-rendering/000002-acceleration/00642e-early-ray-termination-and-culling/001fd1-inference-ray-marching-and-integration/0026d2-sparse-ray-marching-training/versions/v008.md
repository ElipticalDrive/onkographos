# Sparse Ray Marching (Training)

Also called: Grid-based ray marching, Ray Marching (Training)

## Overview
Sparse Ray Marching (Training) is a GPU-accelerated algorithm that samples points along rays through a hierarchical sparse voxel grid to collect 3D positions, directions, step sizes, and t-values for training neural radiance fields [S1, S2, unofficial]. It solves the inefficiency of uniform ray marching by skipping empty regions using a density bitfield, while explicitly decoupling the counting of occupied samples from the writing of sample data to allow for dynamic memory allocation based on actual occupancy rather than fixed worst-case bounds [S1, S2, unofficial]. It differs from its siblings by focusing on the training phase's need for variable-length sample buffers and adaptive step sizing, whereas [Inference Ray Compositing](3790-inference-ray-compositing.md) focuses on final pixel synthesis and [Chunked Volume Rendering](4310-chunked-volume-rendering.md) focuses on memory management for large scenes during inference.

## How it works
**Inputs:**
- `rays_o`: Tensor of ray origins, shape $(N, 3)$ [S1, unofficial].
- `rays_d`: Tensor of ray directions, shape $(N, 3)$ [S1, unofficial].
- `near`/`far`: Scalar bounds for ray clipping [S1, unofficial].
- `density_bitfield`: Sparse grid structure (e.g., hash grid or bitfield) storing density information [S1, S2, unofficial].
- `cascades`: Hierarchical grid levels [S1, unofficial].
- `scale`: Grid scaling factor [S1, unofficial].
- `exp_step_factor`: Exponential factor to scale step sizes [S1, unofficial].
- `grid_size`: Base grid resolution for the density bitfield [S1, unofficial].
- `max_samples`: Maximum number of samples per ray [S1, unofficial].
- `perturb`: Boolean flag to enable random jittering [S2, unofficial].
- `bound`: Spatial extent of the grid [S2, unofficial].

**Outputs:**
- `xyzs`: Collected 3D positions, shape $(TotalSamples, 3)$ [S1, unofficial].
- `dirs`: Collected directions, shape $(TotalSamples, 3)$ [S1, unofficial].
- `deltas`: Step sizes (deltas), shape $(TotalSamples, 2)$ where `deltas[:, 0]` is the step length and `deltas[:, 1]` is the t-value difference [S2, unofficial].
- `ts`: T-values at sample points, shape $(TotalSamples)$ [S1, unofficial].
- `counter`: Scalar tensor containing the total number of valid samples collected [S1, unofficial].

**Data Structures:**
- **Density Bitfield/Grid**: A sparse representation where density is queried via grid indices. For a cubic grid of resolution $H \times H \times H$, the index is calculated as $nx \cdot H^2 + ny \cdot H + nz$ [S2, unofficial].
- **Output Buffers**: Flat tensors pre-allocated to a maximum capacity (often estimated from previous epochs) to store samples. A global counter tracks the current write position [S2, unofficial].

**Parameters:**
- `dt_min`: Minimum step size [S2, unofficial].
- `dt_max`: Maximum step size [S2, unofficial].
- `density_thresh`: Threshold to determine if a voxel is occupied [S2, unofficial].
- `N_THREAD`: Number of threads per CUDA block, typically 256 [S2, unofficial].

**Algorithm Steps:**
1.  **Initialization**:
    -   Generate random noise for each ray: `noise = torch.rand_like(rays_o[:, 0])` [S1, unofficial].
    -   Initialize thread index $n$. If $n \ge N_{alive}$, return [S2, unofficial].
    -   Load ray index from `rays_alive[n]` and current $t$ from `rays_t[n]` [S2, unofficial].
    -   If `perturb` is true, initialize a PCG32 random number generator with seed $(n, \text{perturb})$ and add $dt_{min} \cdot \text{rng.next\_float()}$ to $t$ [S2, unofficial].

2.  **Ray Marching Loop**:
    -   Loop while $t < \text{far}$ and step count $< n_{step}$ [S2, unofficial].
    -   Calculate current point $(x, y, z)$ by clamping $ox + t \cdot dx$, $oy + t \cdot dy$, $oz + t \cdot dz$ to $[-\text{bound}, \text{bound}]$ [S2, unofficial].
    -   Map $(x, y, z)$ to grid indices $(nx, ny, nz)$ by clamping $0.5 \cdot (\text{coord} \cdot r_{bound} + 1) \cdot H$ to $[0, H-1]$, where $r_{bound} = 1 / \text{bound}$ [S2, unofficial].
    -   Query grid density at index $nx \cdot H^2 + ny \cdot H + nz$ [S2, unofficial].

3.  **Occupancy Handling**:
    -   **If density > density_thresh**:
        -   Write $xyz$, $dir$, and $delta$ to output buffers [S2, unofficial].
        -   Calculate step size $dt = \text{clamp}(t \cdot dt_{gamma}, dt_{min}, dt_{max})$ [S2, unofficial].
        -   Update $t \leftarrow t + dt$ [S2, unofficial].
        -   Record $delta[0] = dt$ and $delta[1] = t - last\_t$ [S2, unofficial].
        -   Update $last\_t = t$ [S2, unofficial].
        -   Increment step counter and output pointers [S2, unofficial].
    -   **Else (empty space)**:
        -   Calculate distance to next voxel boundary in $x, y, z$ using $\text{signf}(dx), \text{signf}(dy), \text{signf}(dz)$ [S2, unofficial].
        -   Compute $tt = t + \max(0, \min(tx, ty, tz))$ [S2, unofficial].
        -   Advance $t$ in a do-while loop until $t \ge tt$, using the same $dt$ calculation as occupied space [S2, unofficial].

4.  **Finalization**:
    -   Extract total sample count: `total_samples = counter[0]` [S1, unofficial].
    -   Flatten outputs to `total_samples`: `xyzs = xyzs[:total_samples]`, `dirs = dirs[:total_samples]`, `deltas = deltas[:total_samples]`, `ts = ts[:total_samples]` [S1, unofficial].

**Pseudocode:**
```python
def sparse_ray_marching_train(rays_o, rays_d, near, far, density_bitfield, 
                              exp_step_factor, grid_size, max_samples, 
                              perturb, bound, dt_min, dt_max, density_thresh):
    """
    Sparse Ray Marching for Training.
    Returns: xyzs, dirs, deltas, ts, total_samples
    """
    N = rays_o.shape[0]
    # Pre-allocate buffers with max capacity
    max_total_samples = N * max_samples
    xyzs = torch.zeros((max_total_samples, 3), dtype=torch.float32)
    dirs = torch.zeros((max_total_samples, 3), dtype=torch.float32)
    deltas = torch.zeros((max_total_samples, 2), dtype=torch.float32)
    ts = torch.zeros((max_total_samples), dtype=torch.float32)
    
    counter = torch.tensor([0], dtype=torch.int32)
    
    # Generate noise for perturbation
    noise = torch.rand_like(rays_o[:, 0])
    
    rbound = 1.0 / bound
    
    for n in range(N):
        t = near
        last_t = near
        step = 0
        # Initialize RNG if perturb is enabled
        if perturb:
            rng = PCG32(seed=(n, perturb))
            t += dt_min * rng.next_float()
            
        while t < far and step < max_samples:
            # Calculate current point
            x = rays_o[n, 0] + t * rays_d[n, 0]
            y = rays_o[n, 1] + t * rays_d[n, 1]
            z = rays_o[n, 2] + t * rays_d[n, 2]
            
            # Clamp to bound
            x = torch.clamp(x, -bound, bound)
            y = torch.clamp(y, -bound, bound)
            z = torch.clamp(z, -bound, bound)
            
            # Map to grid indices
            nx = int(torch.clamp(0.5 * (x * rbound + 1) * grid_size, 0, grid_size - 1))
            ny = int(torch.clamp(0.5 * (y * rbound + 1) * grid_size, 0, grid_size - 1))
            nz = int(torch.clamp(0.5 * (z * rbound + 1) * grid_size, 0, grid_size - 1))
            
            # Query density
            density = query_density(density_bitfield, nx, ny, nz)
            
            if density > density_thresh:
                # Occupied: write sample
                idx = counter[0]
                xyzs[idx] = torch.tensor([x, y, z])
                dirs[idx] = rays_d[n]
                
                # Calculate step size
                dt = torch.clamp(t * exp_step_factor, dt_min, dt_max)
                deltas[idx, 0] = dt
                deltas[idx, 1] = t - last_t
                ts[idx] = t
                
                counter[0] += 1
                last_t = t
                t += dt
                step += 1
            else:
                # Empty: skip to next voxel boundary
                # Calculate distances to next boundaries
                sign_x = 1.0 if rays_d[n, 0] > 0 else -1.0
                sign_y = 1.0 if rays_d[n, 1] > 0 else -1.0
                sign_z = 1.0 if rays_d[n, 2] > 0 else -1.0
                
                # Distance to next voxel face
                tx = (sign_x * bound - x) / rays_d[n, 0] if rays_d[n, 0] != 0 else float('inf')
                ty = (sign_y * bound - y) / rays_d[n, 1] if rays_d[n, 1] != 0 else float('inf')
                tz = (sign_z * bound - z) / rays_d[n, 2] if rays_d[n, 2] != 0 else float('inf')
                
                # Note: The source describes a more complex boundary calculation 
                # involving grid cell boundaries, not just scene bounds. 
                # Simplified approximation for empty space skipping:
                # In practice, this involves traversing the sparse grid structure.
                # Here we assume a uniform grid step for empty space if sparse traversal 
                # logic is abstracted into query_density returning 0.
                # However, source [S2, unofficial] specifies: "Calculate distance to next voxel boundary... 
                # Compute tt = t + max(0, min(tx, ty, tz))". 
                # We approximate tx, ty, tz as distance to next integer grid coordinate.
                
                voxel_size = 2.0 * bound / grid_size
                if rays_d[n, 0] != 0:
                    tx = ((torch.floor(x / voxel_size) + (1.0 if rays_d[n, 0] > 0 else 0.0)) * voxel_size - x) / rays_d[n, 0]
                else:
                    tx = float('inf')
                if rays_d[n, 1] != 0:
                    ty = ((torch.floor(y / voxel_size) + (1.0 if rays_d[n, 1] > 0 else 0.0)) * voxel_size - y) / rays_d[n, 1]
                else:
                    ty = float('inf')
                if rays_d[n, 2] != 0:
                    tz = ((torch.floor(z / voxel_size) + (1.0 if rays_d[n, 2] > 0 else 0.0)) * voxel_size - z) / rays_d[n, 2]
                else:
                    tz = float('inf')
                    
                tt = t + max(0.0, min(tx, ty, tz))
                
                # Advance t until it reaches the next boundary
                while t < tt:
                    dt = torch.clamp(t * exp_step_factor, dt_min, dt_max)
                    t += dt
                    
    # Flatten outputs
    total_samples = counter[0]
    return xyzs[:total_samples], dirs[:total_samples], deltas[:total_samples], ts[:total_samples], total_samples
```

**Edge Cases and Pitfalls:**
-   **Precision**: Floating point errors in boundary calculations can cause rays to miss occupied voxels or sample empty space repeatedly. Clamping coordinates to $[-\text{bound}, \text{bound}]$ is critical [S2, unofficial].
-   **Degenerate Input**: Rays with zero direction components must be handled to avoid division by zero in boundary calculations [S2, unofficial].
-   **Memory Overflow**: If `max_samples` is underestimated, the output buffers may overflow. Dynamic allocation or large pre-allocation is required [S2, unofficial].

## Subtopics

### [CUDA Ray Marching (IDDR-NGP Backend)](5788-cuda-ray-marching-iddr-ngp-backend.md)
A GPU-accelerated ray marching kernel that samples points along rays using a hashed density grid, supporting adaptive step sizes and perturbation. It serves as the core inference and training step for the IDDR-NGP backend, differing from standard uniform ray marching by integrating spherical harmonic (SH) evaluation and adaptive step sizing within a single warp-synchronized launch, and from dense voxel tracing by operating on a sparse grid structure with specific boundary handling.

### [Training Ray Marching (Forward Only)](6205-training-ray-marching-forward-only.md)
A two-pass GPU algorithm that samples a ray through a sparse voxel grid (density bitfield) to collect 3D positions, directions, step sizes (deltas), and t-values for training neural radiance fields. It sets itself apart from its siblings by explicitly decoupling the counting of occupied samples from the writing of sample data, allowing for dynamic memory allocation based on actual occupancy rather than fixed worst-case bounds, while supporting an optimization where the maximum allocation size is estimated from previous training epochs.

### [Sparse Packed Radiance Field Tracer](13126-sparse-packed-radiance-field-tracer.md)
The Sparse Packed Radiance Field Tracer is a differentiable rendering method for sparse, packed radiance fields (or SDFs) that generates a variable number of samples per ray, packed into a flat tensor structure. It solves the inefficiency of standard ray marching by using a sparse acceleration structure to sample only within occupied cells, resulting in a custom number of samples per ray rather than a fixed grid. Unlike its siblings, it explicitly manages the "packed" data layout where rays with different intersection counts share a single contiguous buffer, requiring specific reduction operations to handle boundaries between rays.

### [Sparse Grid Volume Rendering (Foreground)](15051-sparse-grid-volume-rendering-foreground.md)
Sparse Grid Volume Rendering (Foreground) is a CUDA-based volume rendering method that traces rays through a sparse voxel grid to compute final color and log-transmittance using volume rendering with spherical harmonics (SH) coefficients. It differs from its siblings by explicitly managing warp-level parallelism for SH basis evaluation and accumulation, utilizing shared memory for warp-local data to minimize global memory traffic, and employing early termination based on transmission thresholds. Unlike [CUDA Ray Marching (IDDR-NGP Backend)](5788-cuda-ray-marching-iddr-ngp-backend.md) which uses hash encoding, or [Sparse Packed Radiance Field Tracer](13126-sparse-packed-radiance-field-tracer.md) which may use different interpolation schemes, this method relies on trilinear interpolation over a sparse connectivity structure.

### Differentiable Ray Marching (SRN variant)
A technique using LSTM to adaptively sample points along a query ray until it finds the intersection with the scene, then passing this point to a pixel generator network [S3, unofficial]. It employs an LSTM to adaptively sample points along the query ray, continuing sampling until the intersection of the query ray with the scene is found, and passes the intersection point through a pixel generator network to yield color directly [S3, unofficial].

### Object-space AImC
An approach to avoid suppression of context behind the focus object by suppressing only those samples of the context object that are in front of the focus object [S4]. The countersink geometry defines the region of different levels of sparseness, but the starting position of the ray is not changed. During the ray traversal of final image synthesis, each sample location is evaluated whether it belongs to the countersink area or not. Outside the countersink area, the context is represented using a more dense representation, and inside, a more sparse form is chosen [S4]. Unlike image-space AImC where the level of sparseness is constant for all samples of one object along a particular ray, object-space AImC has a level of sparseness that is not constant for one object along a particular ray [S4].

## Operating characteristics
-   **Time Complexity**: $O(N \cdot S)$ where $N$ is the number of rays and $S$ is the average number of samples per ray. However, due to sparse skipping, $S$ is significantly reduced compared to uniform marching in sparse scenes.
-   **Memory Complexity**: $O(N \cdot S_{max})$ for output buffers, where $S_{max}$ is the maximum samples per ray. The density grid memory depends on the hash table size or voxel grid resolution.
-   **Measured Performance**: Tested on RTX 2080 Ti with CUDA 11.3, requiring >6GB memory and 32GB RAM for full-size images [S1, unofficial].
-   **Strengths**: Efficiently handles sparse scenes by skipping empty space; dynamic memory allocation reduces waste; adaptive step sizing improves sampling quality.
-   **Limitations**: Requires careful tuning of density thresholds and step factors; performance degrades in dense scenes where most voxels are occupied; perturbation adds computational overhead.
-   **When to Use**: Training neural radiance fields where memory efficiency and adaptive sampling are critical.
-   **When Not to Use**: Inference where deterministic, fixed-step marching is preferred for consistency, or in extremely dense scenes where sparse acceleration provides little benefit.

## Background
Sparse Ray Marching (Training) originated from the need to efficiently train neural radiance fields (NeRFs) on large, sparse scenes. It builds on [Inference Ray Marching and Integration](2148-inference-ray-marching-and-integration.md) by adapting the ray marching process for the training phase, where variable-length sample buffers and adaptive step sizing are more important than fixed-latency inference. The method is closely associated with the IDDR-NGP backend and hash-based encoding techniques [S1, S2, unofficial]. Variants like Differentiable Ray Marching (SRN variant) explore LSTM-based adaptive sampling for faster convergence [S3, unofficial], while Object-space AImC addresses context suppression in volume visualization [S4].
