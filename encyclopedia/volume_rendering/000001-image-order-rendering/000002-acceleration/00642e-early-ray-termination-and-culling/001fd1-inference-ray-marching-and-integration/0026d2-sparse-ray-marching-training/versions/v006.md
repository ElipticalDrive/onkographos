# Sparse Ray Marching (Training)
## Overview
Sparse Ray Marching (Training) is a GPU-accelerated kernel that samples points along active rays for volume rendering training, utilizing a sparse hashed density grid to skip empty space and an adaptive step size to concentrate samples near geometry [S1, unofficial]. It differs from inference-only marchers by maintaining state across iterations (active ray lists, current t) to support backpropagation and dynamic scene updates, and from dense voxel tracing by operating on a sparse grid structure with specific boundary handling [S1, unofficial].
## How it works
**Inputs and Outputs:**
- `rays_alive`: Array of indices for rays currently being traced.
- `rays_t`: Current distance along each active ray.
- `ox, oy, oz`: Origin coordinates of all rays.
- `dx, dy, dz`: Direction vectors of all rays.
- `grid_density`: Sparse hashed density grid lookup function.
- `H`: Grid resolution (cubic $H \times H \times H$).
- `bound`: Spatial extent of the grid.
- `density_thresh`: Threshold to determine occupied space.
- `dt_min, dt_max`: Minimum and maximum step sizes.
- `dt_gamma`: Step size scaling factor.
- `far`: Far plane distance.
- `n_step`: Maximum steps per ray.
- `perturb`: Boolean flag for jittering.
- **Outputs**: Buffers for sampled `xyz`, `dir`, and `delta` (step size and accumulated distance).

**Data Structures:**
- The density grid is accessed via a hash function mapping 3D coordinates to indices, returning a scalar density value [S1, unofficial].
- Output buffers are pre-allocated or dynamically resized to hold samples [S1, unofficial].

**Parameters:**
- `N_THREAD`: 256 threads per block [S1, unofficial].
- `perturb`: Enables random jittering to reduce banding artifacts [S1, unofficial].
- `bound`: Spatial extent. Inverse `rbound = 1 / bound` [S1, unofficial].
- `H`: Grid resolution [S1, unofficial].
- `mean_density`: Average density, used as fallback threshold [S1, unofficial].

**Steps:**
1. Initialize thread index `n`. If `n >= n_alive`, return.
2. Load ray index from `rays_alive[n]` and current distance `t` from `rays_t[n]`.
3. If `perturb` is true, initialize a PCG32 random number generator with seed `(n, perturb)` and add `dt_min * rng.next_float()` to `t` [S1, unofficial].
4. Loop while `t < far` and `step < n_step`:
   a. Calculate current point $(x, y, z)$ by clamping $ox + t \cdot dx$, $oy + t \cdot dy$, $oz + t \cdot dz$ to $[-bound, bound]$.
   b. Map $(x, y, z)$ to grid indices $(nx, ny, nz)$ by clamping $0.5 \cdot (coord \cdot rbound + 1) \cdot H$ to $[0, H-1]$.
   c. Query grid density at index $nx \cdot H \cdot H + ny \cdot H + nz$.
   d. If `density > density_thresh`:
      i. Write `xyz`, `dir`, and `delta` to output buffers.
      ii. Calculate `dt = clamp(t * dt_gamma, dt_min, dt_max)`.
      iii. Update `t += dt`.
      iv. Record `delta[0] = dt` and `delta[1] = t - last_t`.
      v. Update `last_t = t`.
      vi. Increment `step` and pointers.
   e. Else (empty space):
      i. Calculate distance to next voxel boundary in x, y, z using `signf(dx)`, `signf(dy)`, `signf(dz)`.
      ii. Compute `tt = t + max(0, min(tx, ty, tz))`.
      iii. Advance `t` in a do-while loop until `t >= tt`, using the same `dt` calculation as occupied space.

**Pseudocode:**
```python
def sparse_ray_marching_train(rays_alive, rays_t, ox, oy, oz, dx, dy, dz,
                              grid_density, H, bound, density_thresh,
                              dt_min, dt_max, dt_gamma, far, n_step, perturb):
    # Helper definitions for valid Python
    def clamp(v, lo, hi): return max(lo, min(v, hi))
    def signf(v): return 1.0 if v > 0 else (-1.0 if v < 0 else 0.0)
    
    class PCG32:
        def __init__(self, seed): self.state = seed
        def next_float(self): return (self.state % 10000) / 10000.0

    n_alive = len(rays_alive)
    thread_id = 0  # Represents per-thread index in CUDA launch
    if thread_id >= n_alive:
        return

    ray_idx = rays_alive[thread_id]
    t = rays_t[thread_id]
    last_t = t
    step = 0

    if perturb:
        rng = PCG32(seed=(thread_id, perturb))
        t += dt_min * rng.next_float()

    while t < far and step < n_step:
        x = clamp(ox[ray_idx] + t * dx[ray_idx], -bound, bound)
        y = clamp(oy[ray_idx] + t * dy[ray_idx], -bound, bound)
        z = clamp(oz[ray_idx] + t * dz[ray_idx], -bound, bound)

        rbound = 1.0 / bound
        nx = clamp(int(0.5 * (x * rbound + 1) * H), 0, H - 1)
        ny = clamp(int(0.5 * (y * rbound + 1) * H), 0, H - 1)
        nz = clamp(int(0.5 * (z * rbound + 1) * H), 0, H - 1)

        density = grid_density(nx * H * H + ny * H + nz)

        if density > density_thresh:
            write_sample_xyz(x, y, z)
            write_sample_dir(dx[ray_idx], dy[ray_idx], dz[ray_idx])

            dt = clamp(t * dt_gamma, dt_min, dt_max)
            t += dt

            delta_accumulated = dt
            delta_step = t - last_t
            write_sample_delta(delta_accumulated, delta_step)

            last_t = t
            step += 1
        else:
            # Calculate distance to next voxel boundary [G]
            voxel_size = 2.0 * bound / H
            tx = (voxel_size * (nx + 1) - x) / dx[ray_idx] if dx[ray_idx] > 0 else (voxel_size * nx - x) / dx[ray_idx]
            ty = (voxel_size * (ny + 1) - y) / dy[ray_idx] if dy[ray_idx] > 0 else (voxel_size * ny - y) / dy[ray_idx]
            tz = (voxel_size * (nz + 1) - z) / dz[ray_idx] if dz[ray_idx] > 0 else (voxel_size * nz - z) / dz[ray_idx]

            tt = t + max(0.0, min(tx, ty, tz))
            while t < tt:
                dt = clamp(t * dt_gamma, dt_min, dt_max)
                t += dt
```
## Subtopics

### [CUDA Ray Marching (IDDR-NGP Backend)](5788-cuda-ray-marching-iddr-ngp-backend.md)
A GPU-accelerated ray marching kernel that samples points along rays using a hashed density grid, supporting adaptive step sizes and perturbation. It serves as the core inference and training step for the IDDR-NGP backend, differing from standard uniform ray marching by integrating spherical harmonic (SH) evaluation and adaptive step sizing within a single warp-synchronized launch, and from dense voxel tracing by operating on a sparse grid structure with specific boundary handling. Choose it when warp-level synchronization and SH evaluation are required. [5788-cuda-ray-marching-iddr-ngp-backend.md]

### [Training Ray Marching (Forward Only)](6205-training-ray-marching-forward-only.md)
Training Ray Marching is a training-specific ray marching function that estimates the maximum number of points to allocate based on the mean count from previous epochs, enabling faster training by avoiding over-allocation, while supporting a force-all-rays mode for stability. It differs from inference-only marchers by maintaining state (step counters) across iterations to adaptively tune memory usage, and from static allocation methods by using historical data to predict resource needs. Choose it when memory allocation must adapt to training progress. [6205-training-ray-marching-forward-only.md]

### [Sparse Packed Radiance Field Tracer](13126-sparse-packed-radiance-field-tracer.md)
The Sparse Packed Radiance Field Tracer is a differentiable rendering method for sparse, packed radiance fields (or SDFs) that generates a variable number of samples per ray, packed into a flat tensor structure. It solves the inefficiency of standard ray marching by using a sparse acceleration structure to sample only within occupied cells, resulting in a custom number of samples per ray rather than a fixed grid. Unlike its siblings, it explicitly manages the "packed" data layout where rays with different intersection counts share a single contiguous buffer, requiring specific reduction operations to handle boundaries between rays. Choose it when variable sample counts and packed tensor layouts are needed. [13126-sparse-packed-radiance-field-tracer.md]

### [Sparse Grid Volume Rendering (Foreground)](15051-sparse-grid-volume-rendering-foreground.md)
Sparse Grid Volume Rendering (Foreground) is a CUDA kernel that performs image-order volume rendering through a sparse 3D voxel grid using trilinear interpolation and spherical harmonics (SH) coefficients. It solves the problem of efficiently rendering high-frequency radiance fields by skipping transparent regions and accumulating color and opacity along rays. It is distinguished from its siblings by its specific implementation in the NeRF-Factory/Plenoxels ecosystem, utilizing warp-level reductions for SH evaluation and specific sparsity-aware early termination. Choose it for Plenoxels-style SH-based sparse rendering. [15051-sparse-grid-volume-rendering-foreground.md]
