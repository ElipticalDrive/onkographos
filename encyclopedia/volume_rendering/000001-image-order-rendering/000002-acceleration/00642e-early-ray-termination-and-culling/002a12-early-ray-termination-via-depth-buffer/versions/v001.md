# Early Ray Termination via Depth Buffer

Also called: Depth-based Early Termination, Early Z-Test

## Overview
Early Ray Termination via Depth Buffer is a hardware-accelerated optimization that skips fragment shader execution for rays that have already accumulated sufficient opacity to be considered saturated (effectively opaque) [S1, unofficial]. It solves the problem of redundant computation in front-to-back volume rendering where subsequent samples contribute negligibly to the final color but still incur rasterization and shading overhead [S1, unofficial]. Unlike [Opacity-based Early Termination](7920-opacity-based-early-termination.md), which relies on software checks within the fragment shader, this method leverages the GPU's fixed-function depth buffer to cull fragments before the shader runs, thereby bypassing the rasterization bottleneck [S1, unofficial]. It differs from [Depth-Prior Ray Truncation](5456-depth-prior-ray-truncation.md) by using the depth buffer as a binary saturation mask rather than a geometric occlusion query for ray length.

## How it works
The method operates in two distinct passes to ensure consistent depth testing and to avoid the performance penalty of dynamic shader switching during the main rendering loop.

### Inputs and Outputs
*   **Input:** A volume dataset partitioned into bricks (or similar spatial units), a depth buffer initialized from a previous pass or cleared, and the current camera/view matrix.
*   **Output:** A rendered image where saturated rays skip fragment processing, and a depth buffer updated with the maximum depth of saturated rays for subsequent bricks.

### Data Structures
*   **Depth Buffer:** A standard 2D array of depth values (typically 24-bit or 32-bit float), storing the depth of the nearest saturated surface encountered so far for each pixel.
*   **Brick Bounding Box:** A 3D axis-aligned bounding box (AABB) defining the spatial extent of the current volume brick.

### Steps
1.  **Prepass (Saturation Depth Capture):**
    *   For the current brick, render a solid, back-face-culled bounding box that encloses the brick.
    *   Execute a specialized fragment shader during this pass. This shader does not sample the volume texture. Instead, it calculates the ray's accumulated opacity up to the entry point of the brick (or assumes saturation if the ray is already saturated from previous bricks).
    *   If the ray is saturated (accumulated opacity $A \approx 1$), the shader writes the depth of the far plane of the bounding box (or the maximum depth of the brick along the ray) to the depth buffer. If the ray is not saturated, it writes nothing or a value that fails the subsequent test.
    *   *Note:* This pass is performed once per brick, not per sample or octree node, to avoid the overhead of changing fragment shaders and state [S1, unofficial].

2.  **Shading Pass (Early Z-Test):**
    *   Render the actual volume brick (e.g., as a textured quad or via ray marching within the fragment shader).
    *   Configure the depth test to `Equal` and disable depth writes (`depth_write: false`) [S2, unofficial].
    *   The GPU's hidden-surface removal logic compares the depth of the current fragment against the depth buffer populated in the prepass.
    *   If the depth test fails (i.e., the current fragment's depth is not equal to the saturated depth recorded, implying the ray was not marked as saturated or the geometry is behind a saturated surface), the fragment shader is skipped entirely [S1, unofficial].
    *   If the test passes, the fragment shader executes, sampling the volume texture and performing the compositing step.

### Formulas
The saturation condition is based on the front-to-back compositing equations [S1, unofficial]:

$$ C_{i+1} = (1 - A_i) \cdot \alpha_i \cdot c_i + C_i $$

$$ A_{i+1} = (1 - A_i) \cdot \alpha_i + A_i $$

Where:
*   $C_i, A_i$ are the accumulated color and opacity before sample $i$.
*   $c_i, \alpha_i$ are the color and opacity of the current sample.
*   A ray is considered **saturated** when $A_i \approx 1$.

In the prepass, if $A_{entry} \approx 1$, the depth of the brick's far boundary is written. In the shading pass, the depth test ensures that only fragments corresponding to these saturated depths (or non-saturated rays that haven't been marked) proceed.

### Parameters
*   **Depth Comparison:** `Equal` [S2, unofficial].
*   **Depth Write:** `False` [S2, unofficial].
*   **Invariant Position:** The vertex position input must be marked as `@invariant` (or equivalent) to ensure consistent depth rounding between the prepass and the shading pass, preventing precision mismatches that would cause the depth test to fail incorrectly [S2, unofficial].

### Pseudocode

```python
# Prepass: Mark saturated rays
def render_brick_depth_pass(brick, depth_buffer, camera):
    """
    Renders the bounding box of the brick to mark saturated rays in the depth buffer.
    """
    # Set up render state for prepass
    set_depth_test(LESS_EQUAL)
    set_depth_write(True)
    set_fragment_shader(SATURATION_SHADER)
    
    # Draw the solid bounding box of the brick
    # Back face culling is enabled to ensure we see the front of the box
    draw_bounding_box(brick.bbox)

# Shading Pass: Render volume with early termination
def render_brick_shading_pass(brick, depth_buffer, camera):
    """
    Renders the volume brick, skipping fragments for saturated rays.
    """
    # Set up render state for shading pass
    set_depth_test(EQUAL)  # Only proceed if depth matches the saturated marker
    set_depth_write(False) # Do not update depth buffer
    set_fragment_shader(VOLUME_SHADER)
    
    # Draw the volume representation (e.g., textured quad or ray-marched geometry)
    draw_volume(brick)

# Fragment Shader: Saturation Check (Prepass)
fragment_color SATURATION_SHADER(vec3 frag_pos, vec3 ray_dir):
    """
    Determines if the ray is saturated at the entry of the brick.
    """
    # Assume accumulated opacity A_prev is passed from CPU or previous step
    # If the ray is already saturated from previous bricks, mark the depth
    if accumulated_opacity > 0.99:
        # Write the depth of the far plane of the brick
        return vec4(1.0, 0.0, 0.0, 1.0) # Color doesn't matter, depth is key
    else:
        # Ray is not saturated, do not write to depth buffer (or write a value that won't match)
        discard()

# Fragment Shader: Volume Rendering (Shading Pass)
fragment_color VOLUME_SHADER(vec3 frag_pos, vec3 ray_dir):
    """
    Standard volume rendering for rays that passed the depth test.
    """
    # Sample volume and composite
    color = sample_and_composite(brick, ray_dir)
    return color
```

### Edge Cases and Pitfalls
*   **Precision Mismatches:** If the depth values calculated in the prepass and shading pass differ due to floating-point rounding errors, the `Equal` depth test will fail, causing the optimization to be ineffective (shading runs when it shouldn't) or incorrect (shading is skipped when it shouldn't). Using `@invariant` vertex attributes is critical [S2, unofficial].
*   **Overhead:** Performing the early termination test more frequently than once per brick (e.g., per octree node or per sample) introduces significant overhead from changing fragment shaders and state, which can negate the performance gains [S1, unofficial].
*   **Hardware Specifics:** On some GPUs (e.g., Apple Silicon), using `discard` in fragment shaders can disable hardware hidden-surface removal. This method avoids `discard` by using the depth buffer, restoring the GPU's ability to cull fragments efficiently [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces fragment shader invocations for saturated rays to zero. The cost is the overhead of the prepass (rendering a bounding box) and the depth buffer update.
*   **Memory Complexity:** Requires one additional depth buffer (or reuse of the existing one) and minimal CPU/GPU state management.
*   **Performance:** Significant speedup in scenes with high opacity or saturated regions. In the cited implementation, a depth prepass reduced the main pass workload by 27% [S2, unofficial].
*   **Strengths:** Leverages hardware depth testing, avoiding software-based opacity checks. Effective for opaque or semi-opaque volumes.
*   **Limitations:** Requires a front-to-back traversal order. Not suitable for back-to-front rendering without modification. Precision issues can arise if not handled carefully.

## Background
This technique is described in the context of optimizing GPU volume rendering, particularly for brick-based rendering schemes [S1, unofficial]. It addresses the inefficiency of rendering fragments that do not contribute to the final image due to ray saturation. The method is also applied in other contexts, such as rendering overlapping opaque spheres, where it restores hidden-surface removal that might be disabled by other optimization techniques like impostor discard [S2, unofficial].
