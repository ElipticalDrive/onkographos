# Early Ray Termination via Depth Buffer

Also called: Depth-based Early Termination, Early Z-Test

## Overview
Early Ray Termination via Depth Buffer is a GPU optimization technique that skips fragment shader execution for rays that have already accumulated sufficient opacity (are saturated) by performing a depth test before the main volume rendering pass [S1, unofficial]. It sets itself apart from [Opacity-based Early Termination](7920-opacity-based-early-termination.md) by deferring the termination decision to the rasterizer's depth buffer, thereby avoiding the computational cost of evaluating the transfer function and compositing loop for saturated pixels, and from [Empty-space skipping](1002-empty-space-skipping.md) by operating on the accumulated result of previous bricks rather than pre-computed empty regions.

## How it works
**Inputs and Outputs:**
*   Input: A volume dataset divided into bricks, a depth buffer containing the depth of the nearest opaque surface rendered so far, and the current brick's geometry.
*   Output: A color buffer where saturated pixels are skipped, reducing fragment shader load.

**Data Structures:**
*   **Depth Buffer:** Standard GPU depth buffer storing depth values ($z$) for each pixel.
*   **Brick Geometry:** A solid bounding box representing the brick, rendered with back-face culling enabled.

**Steps:**
1.  **Traversal Order:** Ensure the volume is traversed in front-to-back order. This is a prerequisite for early ray termination to be valid, as saturation must be detected before it is obscured by further samples [S1, unofficial].
2.  **Pre-pass for Saturation Detection:** Before rendering the actual brick texture, execute a preliminary fragment shader program. This is done by drawing a solid bounding box around the brick with back-face culling switched on [S1, unofficial].
3.  **Depth Update:** The fragment shader in the pre-pass writes the maximal depth value in the depth buffer for rays that are already saturated. A ray is considered saturated when its accumulated opacity $A_i$ approximates 1 [S1, unofficial].
4.  **Main Rendering Pass:** Render the brick's texture slices. The GPU's early Z-test compares the depth of the current fragment against the depth buffer.
5.  **Termination:** If the depth test fails (indicating the ray is already saturated and occluded by the depth written in step 3), fragment operations are prevented. This reduces the load on rasterization and fragment shader bottlenecks [S1, unofficial].

**Formulas:**
The compositing loop determines saturation. Let $C_i$ and $A_i$ be the accumulated color and opacity at sample index $i$, and $c_i, \alpha_i$ be the sample color and opacity from the transfer function:

$$ C_{i+1} = (1 - A_i) \cdot \alpha_i \cdot c_i + C_i $$
$$ A_{i+1} = (1 - A_i) \cdot \alpha_i + A_i $$

A ray is saturated when $A_i \approx 1$ [S1, unofficial].

**Parameters:**
*   **Saturation Threshold:** Not explicitly defined in sources, but implied to be $A_i \approx 1$ [S1, unofficial].
*   **Brick Size:** Depends on available texture memory, optimal texture size, data nature, and hardware constraints [S1, unofficial].

**Pitfalls:**
*   **Granularity:** Early ray termination is performed only once per brick, not per octree node or per sample. Performing it more frequently (e.g., for every sample) would incur overhead from changing fragment shaders and performing tests that would annihilate the benefits [S1, unofficial].
*   **Ordering:** Front-to-back traversal is mandatory. Back-to-front traversal would not allow early termination based on accumulated opacity [S1, unofficial].

**Pseudocode:**
```python
def render_brick_with_early_termination(brick, depth_buffer):
    # Step 1: Pre-pass to mark saturated rays in depth buffer
    # Draw solid bounding box of the brick with back-face culling ON
    set_fragment_shader(mark_saturated_depth_shader)
    set_depth_write_enabled(True)
    set_depth_func(GREATER) # Write if current depth is greater (further)
    draw_brick_bounding_box()
    
    # Step 2: Main pass to render brick texture
    # The early Z-test will now skip fragments where depth test fails
    # (i.e., where the ray was marked as saturated in the pre-pass)
    set_fragment_shader(volume_rendering_shader)
    set_depth_write_enabled(False) # Or keep write, depending on specific implementation
    set_depth_func(LESS) # Standard depth test
    draw_brick_texture_slices()

def mark_saturated_depth_shader(pixel):
    # This shader is executed for the bounding box
    # It checks if the ray corresponding to this pixel is saturated
    # If saturated, it writes the maximal depth value to the depth buffer
    if is_ray_saturated(pixel.ray):
        write_depth_to_buffer(pixel, MAX_DEPTH)
```

## Operating characteristics
*   **Time Complexity:** Reduces fragment shader execution time for saturated pixels. The overhead is limited to one additional draw call (the bounding box) per brick [S1, unofficial].
*   **Memory Complexity:** Requires a depth buffer. No additional significant memory structures are described beyond the standard depth buffer [S1, unofficial].
*   **Strengths:** Significantly reduces load on rasterization and fragment shader bottlenecks for scenes with high opacity or saturated regions [S1, unofficial].
*   **Limitations:** Only effective when rays are saturated. Overhead of the pre-pass must be justified by the number of skipped fragments. Not suitable for back-to-front traversal [S1, unofficial].
*   **When to use:** When rendering volumes with significant opaque regions and using a GPU architecture where fragment shader execution is a bottleneck.
*   **When not to use:** When the volume is mostly transparent, or when the overhead of the pre-pass exceeds the savings from skipped fragments.

## Background
The technique was described by Danny Ruijters in "Optimizing GPU Volume Rendering" [S1, unofficial]. It builds on earlier work by Kruger and Westin [KW03] and Ropinski et al. [RGW+03], cited within the source [S1, unofficial]. The method leverages standard GPU depth testing capabilities to implement early termination, a common optimization in rasterization-based volume rendering.
