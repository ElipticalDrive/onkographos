# Direct Volume Rendering with Partitioned Distance Maps (PDM) based Empty Space Skipping

Also called: Accelerating Transfer Function Update for Distance Map based Volume Rendering, Intensity-Partitioned Occupancy/Distance Maps, PDM-based Empty Space Skipping, Partitioned Distance Map (PDM) Acceleration

## Overview
Direct Volume Rendering (DVR) with Partitioned Distance Maps (PDM) based Empty Space Skipping (ESS) is an acceleration technique for distance-field ray marching that subdivides the volume's intensity range into $n$ partitions to precompute individual distance maps [S1]. When a transfer function (TF) changes, only the relevant PDMs are merged to form the final distance map $D'$, avoiding a full recomputation of the distance transform [S1]. Unlike the base method [Partitioned Distance Map Combination](1191-partitioned-distance-map-combination.md) which recomputes the global distance map on every TF change, PDM-based ESS trades higher memory usage and one-time initialization cost for significantly faster TF update times, maintaining high frame rates during frequent TF adjustments [S1][S2].

## How it works
### Inputs and Outputs
**Inputs:**
- Volume dataset $V$ with intensity values.
- Number of intensity partitions $n$.
- Block size $b$ for block-reduction (typically $b=4$) [S1].
- Transfer Function (TF) mapping intensities to RGBA [S2].
- Camera parameters (position, view matrix) [S2].

**Outputs:**
- Final distance map $D'$ used for ESS during ray casting [S1].
- Rendered image via ray casting [S2].

### Data Structures

**Partitioned Occupancy Maps (POMs) and Partitioned Distance Maps (PDMs):**
- **Type:** `uint8` (unsigned 8-bit integer) [S1].
- **Layout:** Block-reduced dimensions. If the volume has dimensions $D_x \times D_y \times D_z$, the map dimensions are $\lceil D_x/b \rceil \times \lceil D_y/b \rceil \times \lceil D_z/b \rceil$ [S1].
- **Content:**
  - POM: Stores occupancy status. Value `0` indicates occupied (contains at least one voxel in the partition's intensity range), `1` indicates empty [S2, code].
  - PDM: Stores Chebyshev distance to the nearest non-empty block within that specific intensity partition. Distances $> 255$ are clamped to 255 [S1].

### Preprocessing Steps
1.  **Partition Definition:** Subdivide the total intensity range of the volume into $n$ partitions. Each partition $p$ is defined by lower and upper integer intensity borders $\rho_{min}^p$ and $\rho_{max}^p$ [S1].
2.  **POM Computation:** Compute $n$ Partitioned Occupancy Maps (POMs). The original volume is block-reduced into non-overlapping blocks of size $b^3$. A block is considered occupied in partition $p$ if it contains at least one voxel with an intensity value within $[\rho_{min}^p, \rho_{max}^p]$ [S1].
3.  **PDM Computation:** Compute $n$ Partitioned Distance Maps (PDMs) from the POMs. Each PDM encodes the Chebyshev distance to the nearest non-empty voxel block within that specific intensity partition [S1]. This is typically done using a multi-pass distance transform algorithm on the GPU [S2, code].

### Update Step (TF Change)
When the TF is updated, the final distance map $D'$ is assembled without recomputing the underlying PDMs:
1.  **Determine Active Partitions:** Identify the set $S$ of partition indices $p$ such that the TF maps at least one intensity value in partition $p$ to a non-zero alpha value [S1].
2.  **Merge PDMs:** Compute the element-wise minimum of the corresponding PDMs to form $D'$ [S1]:
    $$ D'(x, y, z) = \min_{p \in S} (PDM_p(x, y, z)) $$
    This merging is performed in a GLSL Compute Shader. Up to a maximum of 6 PDMs are bound as input textures per pass, aggregating distances to produce $D'$. If more PDMs are needed, multiple passes are used with flip-flopping input/output textures [S1].

### Rendering Steps (Ray Casting)
1.  **Ray Origin and Direction:**
    -   Get camera position in object coordinates: `ray_origin = inverseModelView * vec4(view[0][3], view[1][3], view[2][3], 1.0f)` [S2].
    -   Intersect ray with bounding box (AABB: minBB=(-0.5,-0.5,-0.5), maxBB=(0.5,0.5,0.5)) using the slab method to find entry ($t_0$) and exit ($t_1$) distances [S2].
2.  **Normalize to Texture Coordinates:**
    -   `ray_start = (ray_origin + ray_direction * t_0 - minBB) / (maxBB - minBB)`
    -   `ray_stop = (ray_origin + ray_direction * t_1 - minBB) / (maxBB - minBB)` [S2].
3.  **Calculate Step Parameters:**
    -   `ray = ray_stop - ray_start`
    -   `ray_length = length(ray)`
    -   Check for degenerate rays: If `ray_length` is infinite, NaN, or $> \sqrt{3}$ (~1.732051f), return immediately [S2].
    -   `n_steps = int(ceil(float(dim_max) * ray_length * sampling_factor))` where `dim_max` is the maximum dimension of the volume texture [S2].
    -   `step_vector = normalize(ray) * ray_length / (float(n_steps) - 1.0f)` [S2].
4.  **Ray Marching Loop:**
    -   For each step $i$ from $0$ to $n\_steps - 1$:
        -   Calculate sampling position: `samplingPos = ray_start + step_vector * float(i)` [S2].
        -   **Empty Space Skipping:** Use $D'$ to determine the step size. The distance map value at the current block position indicates how many blocks can be skipped. Convert this block distance to world/texture space distance and advance the ray [S1][S2].
        -   **Volume Sampling:**
            -   Sample intensity from `texVolume` at `samplingPos`.
            -   **Gradient Calculation:**
                -   If `gradientType == 0` (on-the-fly): Approximate gradient using tetrahedron technique. Sample 4 voxels at offsets `k.xyy`, `k.yyx`, `k.yxy`, `k.xxx` where `k=ivec2(-1,1)`. Compute `gradientVec = 0.25 * sum(k_i * value_i)`. Normalize and store magnitude in alpha channel [S2].
                -   If `gradientType == 1` (precomputed): Sample from `texGradient` at `samplingPos + 0.5/vec3(volumeSize)`. Normalize xyz components and store original magnitude in alpha [S2].
            -   **Interpolation:** If `enable_bicubic_filtering` is true, calculate tricubic interpolation weights and mix samples [S2].
        -   **Transfer Function:** Map intensity to RGBA using `texITF`. Apply gamma correction if `itf_gamma_correction` is true [S2].
        -   **Compositing:** Accumulate color and opacity. If `earlyRayTermination` is true, break loop if accumulated opacity exceeds a threshold [S2].

```python
def compute_pom(volume, block_size, partition_min, partition_max):
    """
    Computes a Partitioned Occupancy Map for a specific intensity partition.
    volume: 3D array of voxel intensities.
    block_size: int, side length of blocks (e.g., 4).
    partition_min, partition_max: int, intensity range.
    Returns: 3D array of uint8 (0=occupied, 1=empty).
    """
    dim = volume.shape
    pom_dim = tuple((d + block_size - 1) // block_size for d in dim)
    pom = np.ones(pom_dim, dtype=np.uint8) # Initialize as empty
    
    for z in range(pom_dim[2]):
        for y in range(pom_dim[1]):
            for x in range(pom_dim[0]):
                # Define block boundaries in original volume
                x_start, x_end = x * block_size, min((x + 1) * block_size, dim[0])
                y_start, y_end = y * block_size, min((y + 1) * block_size, dim[1])
                z_start, z_end = z * block_size, min((z + 1) * block_size, dim[2])
                
                # Check if any voxel in this block falls within the partition

def merge_pdms(pdms, active_indices):
    """
    Merges selected PDMs into a final distance map D'.
    pdms: list of 3D arrays (PDMs).
    active_indices: list of indices into pdms.
    Returns: 3D array of uint8 (D').
    """

# Rendering: Ray Casting
def ray_cast(volume, d_prime, camera_matrix, tf, params):
    """
    Performs direct volume rendering using PDM-based ESS.
    volume: 3D array of intensities.
    d_prime: 3D array of uint8 (final distance map).
    camera_matrix: 4x4 matrix (inverseModelView).
    tf: Transfer function function/intensity map.
    params: dict with sampling_factor, earlyRayTermination, etc.
    Returns: 2D image (RGBA).
    """
    # 1. Ray Origin and Direction
    # Assuming standard OpenGL camera setup
    view = camera_matrix # Simplified; actual code uses inverseModelView * view[3]
    ray_origin = vec4(camera_matrix[0][3], camera_matrix[1][3], camera_matrix[2][3], 1.0)
    
    # For each pixel (x, y) in screen
    for y in range(height):
        for x in range(width):
            # Calculate ray direction to front face of bounding box
            # bb_bf_positions depends on projection matrix and pixel coords
            ray_dir = normalize(bb_bf_positions - ray_origin)
            
            # 2. Intersect with Bounding Box
            minBB = vec3(-0.5, -0.5, -0.5)
            maxBB = vec3(0.5, 0.5, 0.5)
            t0, t1 = intersect_slab(ray_origin, ray_dir, minBB, maxBB)
            
            if t0 > t1: continue # Ray misses box
            
            # 3. Normalize to Texture Coordinates
            ray_start = (ray_origin + ray_dir * t0 - minBB) / (maxBB - minBB)
            ray_stop = (ray_origin + ray_dir * t1 - minBB) / (maxBB - minBB)
            
            ray_vec = ray_stop - ray_start
            ray_length = length(ray_vec)
            
            # Degenerate ray check
            if ray_length <= 0 or ray_length > sqrt(3.0) or isnan(ray_length):
                continue
                
            dim_max = max(volume.shape)
            n_steps = int(ceil(dim_max * ray_length * params['sampling_factor']))
            step_vector = normalize(ray_vec) * ray_length / (n_steps - 1.0)
            
            # 4. Ray Marching
            accumulated_color = vec4(0.0)
            accumulated_alpha = 0.0
            
            for i in range(n_steps):
                sampling_pos = ray_start + step_vector * i
                
                # ESS Step
                # Get block coordinate from sampling_pos
                block_coord = ivec3(sampling_pos * vec3(volume.shape))
                # Clamp block_coord to valid range
                block_coord = clamp(block_coord, ivec3(0), ivec3(volume.shape) - ivec3(1))
                
                # Get distance from D'
                dist = d_prime[block_coord.z, block_coord.y, block_coord.x]
                
                # Skip voxels
                # Convert block distance to texture space distance
                # Note: D' is in block units. Need to scale by block size and volume dimensions
                skip_distance = dist * params['block_size'] / dim_max 
                # Advance sampling_pos by skip_distance along ray
                sampling_pos += step_vector * (n_steps - 1.0) * skip_distance / ray_length # Approximation for step advancement
                
                # Sample Volume
                intensity = sample_volume(volume, sampling_pos, params)
                
                # TF Mapping
                rgba = apply_tf(tf, intensity, params)
                
                # Compositing
                if params['earlyRayTermination'] and accumulated_alpha > 0.99:
                    break
                    
                # Front-to-back compositing
                c = rgba.rgb * rgba.a * (1.0 - accumulated_alpha)
                accumulated_color += c
                accumulated_alpha += rgba.a * (1.0 - accumulated_alpha)
                
            image[y, x] = accumulated_color
    return image
```

### Parameters
-   **Block size $b$:** Side length of non-overlapping voxel blocks. Typical value: 4 [S1].
-   **Number of partitions $n$:** Number of intensity subranges. Evaluated values: 16, 32, 64, 128, 256 [S1].
-   **sampling_factor:** Float parameter scaling the number of sampling steps. Typical values depend on resolution/quality [S2].
-   **essType:** Integer selecting ESS algorithm (e.g., distance ESS) [S2].
-   **earlyRayTermination:** Boolean enabling/disabling early termination [S2].
-   **enable_bicubic_filtering:** Boolean enabling/disabling tricubic interpolation [S2].
-   **gradientType:** Integer (0: on-the-fly, 1: precomputed) [S2].
-   **MAX_SEGMENTS:** Compile-time constant, value 64 [S2].

### Edge Cases and Pitfalls
-   **Approximation Error:** $D'$ is an element-wise lower limit of the standard non-partitioned distance map $D$ ($D' \le D$) [S1]. This means ESS may skip fewer voxels (worse performance) if different intensity values in the same partition are mapped to both zero and non-zero alpha by the TF. However, it never skips more voxels than allowed, ensuring correctness [S1].
-   **Degenerate Rays:** If `ray_length` is infinite, NaN, or greater than $\sqrt{3}$ (~1.732051f), the ray is degenerate (e.g., start and endpoint coinciding or outside bounds). The shader returns immediately to prevent performance regressions [S2].
-   **Data Type Clamping:** PDM/POM data types are `uint8`. Distances higher than 255 are clamped, which may affect accuracy for very large volumes or large block sizes [S1].

## Operating characteristics
-   **Time Complexity:**
    -   **Preprocessing:** $O(n \cdot V)$ where $V$ is the number of voxels and $n$ is the number of partitions. One-time initialization cost increases with $n$ (e.g., 905.2ms for 256 partitions on Manix dataset) [S1].
    -   **TF Update:** $O(k \cdot V_{blocks})$ where $k$ is the number of active partitions and $V_{blocks}$ is the number of blocks. Significantly faster than full distance map recomputation (e.g., 0.20ms to 1.30ms for 16-256 partitions vs 58.1ms for original method on Manix) [S1].
    -   **Rendering:** $O(R \cdot S)$ where $R$ is the number of rays and $S$ is the average number of steps per ray. ESS reduces $S$.
-   **Memory Complexity:** $O(n \cdot V_{blocks})$ for storing $n$ PDMs. Higher memory usage compared to a single distance map [S1].
-   **Measured Performance:**
    -   **Manix (512x512x460):** Original distance map: 58.1ms. PDM (16 partitions) update: 0.20ms. PDM (256 partitions) update: 1.30ms [S1].
    -   **Stag Beetle (832x832x494):** Original: 146.4ms. PDM (16 partitions) update: 0.41ms. PDM (256 partitions) update: 2.58ms [S1].
    -   **Kingsnake (1024x1024x795):** Original: 228.2ms. PDM (16 partitions) update: 0.80ms. PDM (256 partitions) update: 6.71ms [S1].
-   **Scaling:** Performance gain in TF update time is consistent across datasets, but initialization cost scales with $n$ and volume size [S1].
-   **Strengths:** Fast TF updates, high frame rates during interactive TF adjustment, correctness guaranteed (no over-skipping) [S1].
-   **Limitations:** Higher memory usage, slower one-time initialization, potential performance degradation in rendering if ESS skips fewer voxels due to approximation [S1].
-   **When to use:** Interactive volume rendering with frequent TF changes [S1].
-   **When not to use:** Static TFs, memory-constrained environments, or when one-time initialization time is critical [S1].

## Background
-   **Origin:** Proposed by Michael Rauter in "Accelerating Transfer Function Update for Distance Map based Volume Rendering" (IEEE VIS 2024) [S1].
-   **History:** Extends the work of Deakin and Knackstedt on distance map based ESS [S1][S2]. The original approach required full distance map recomputation on TF change, which was a limiting performance factor [S1]. Faludi et al. [5] used an octree of bitfields, reporting ray marching times 35% slower than Deakin’s approach [S1]. PDM-based ESS improves upon this by using partitioned distance maps for faster updates [S1].
-   **Usage:** Used in GPU-based direct volume rendering, particularly in virtual reality and interactive visualization applications [S1][S2].
