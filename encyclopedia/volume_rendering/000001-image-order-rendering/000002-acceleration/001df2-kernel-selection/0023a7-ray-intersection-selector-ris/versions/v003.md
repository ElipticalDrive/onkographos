# Ray Intersection Selector (RIS)
Also called: IRIS (Intersection-aware Ray-based Implicit Editable Scenes)

## Overview
Ray Intersection Selector (RIS) is a sampling strategy for neural rendering that replaces stochastic volumetric sampling with analytical ray-primitive intersection detection to identify high-density regions for volumetric rendering [S1]. It solves the problem of empty space processing and costly 3D neighbor lookups by generating meaningful samples in a single pass, eliminating the need for auxiliary networks or voxel grids [S1]. Unlike [Kernel Selection](1647-kernel-selection.md) which selects a subset of Gaussoids based on density thresholds, RIS analytically determines precise intersection points between camera rays and 3D Gaussians, ensuring that every neural query contributes directly to surface reconstruction [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ Neural Anchors (primitives) $\mathcal{P}$, a camera ray $r(t) = \mathbf{o} + t\mathbf{d}$, and a distance threshold $\tau_{\text{dist}}$ [S1].
*   **Output:** A sorted sequence of intersection points (samples) $\{x_k\}$ along the ray, and aggregated neural features for volumetric rendering [S1].

**Data Structures**
The scene is parameterized as a set of $N$ Neural Anchors [S1]. Each anchor $i$ consists of:
1.  A 3D normal distribution defined by mean position $\boldsymbol{\mu}_i \in \mathbb{R}^3$ and covariance matrix $\boldsymbol{\Sigma}_i$ [S1].
2.  A logit parameter $\omega_i \in \mathbb{R}$ controlling opacity [S1].
3.  A latent feature vector $\mathbf{f}_i \in \mathbb{R}^D$ [S1].
The covariance is factorized into a rotation matrix $R_i$ (stored as a quaternion) and a scaling vector $S_i$ [S1].

**Algorithm Steps**

1.  **Proxy Geometry Construction:** Bound each Gaussian primitive $i$ with an affine-transformed icosahedron to create a proxy geometry [S1].
2.  **Ray-Primitive Intersection:** Use the OptiX API to perform ray tracing against the proxy geometry, offloading intersection logic to dedicated RT cores [S1]. Solve the intersection equations for a ray traversing an oriented ellipsoid to determine precise interaction points [S1].
3.  **Sample Generation:** Generate a sorted sequence of intersection points (samples) $\{x_k\}$ only where density contribution is guaranteed to be significant, skipping empty space [S1].
4.  **Ray-Coherent Aggregation (RCA):** For each sample point $x_k$, define a symmetric neighborhood window $W_k$ of size $2K+1$ indices centered at $k$: $\{k-K, \dots, k, \dots, k+K\}$ [S1].
5.  **Validity Masking:** Apply a binary validity mask $M_{kj}$ to enforce spatial locality [S1]. A neighbor $j \in W_k$ is valid only if it belongs to the same ray index and the Euclidean distance $\|\mathbf{x}_k - \boldsymbol{\mu}_j\|_2$ is below a fixed threshold $\tau_{\text{dist}}$ [S1].
6.  **Feature Aggregation:** For every valid neighbor $j$, compute the unnormalized logit $l_{kj}$ based on the Mahalanobis distance $\Delta^2(\mathbf{x}_k, \boldsymbol{\mu}_j, \boldsymbol{\Sigma}_j) = (\mathbf{x}_k - \boldsymbol{\mu}_j)^\top \boldsymbol{\Sigma}_j^{-1} (\mathbf{x}_k - \boldsymbol{\mu}_j)$ [S1]. Normalize these logits to obtain aggregation weights $w_{kj}$ [G]. Synthesize a continuous latent vector $\mathbf{z}_k$ by weighting the latent features $\mathbf{f}_j$ of valid neighbors:
    $$ \mathbf{z}_k = \sum_{j \in W_k, M_{kj}=1} w_{kj} \mathbf{f}_j $$
7.  **Neural Decoding:** Use shallow Multi-Layer Perceptrons (MLPs) to decode the aggregated continuous latent vector $\mathbf{z}_k$ into view-dependent color and material density $\sigma$ [S1].
8.  **Volumetric Rendering:** The neural density $\sigma$ is spatially modulated by the explicit Gaussian opacity $\omega_i$ and integrated via point-based volumetric rendering to produce the final image [S1].

**Pseudocode**

```python
import math

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def mat_vec(M, v):
    return [dot(row, v) for row in M]

def ray_intersection_selector(anchors, ray_origin, ray_direction, tau_dist, window_half_width):
    """
    RIS: Analytically determines precise intersection points between camera rays and 3D Gaussians.
    """
    # Step 1 & 2: Ray-Primitive Intersection
    # Gaussians are bounded by affine-transformed icosahedrons for OptiX RT core offload [S1].
    # Here we compute analytical ray-ellipsoid intersections as the mathematical basis.
    t_values = []
    for anchor in anchors:
        mu = anchor['mu']
        Sigma_inv = anchor['Sigma_inv']
        # Ray: o + t*d. Ellipsoid: (x-mu)^T Sigma^{-1} (x-mu) = 1
        # Quadratic: a t^2 + b t + c = 0
        a = dot(ray_direction, mat_vec(Sigma_inv, ray_direction))
        b = 2.0 * dot(ray_direction, mat_vec(Sigma_inv, [ray_origin[i] - mu[i] for i in range(3)]))
        c = dot([ray_origin[i] - mu[i] for i in range(3)], mat_vec(Sigma_inv, [ray_origin[i] - mu[i] for i in range(3)])) - 1.0
        disc = b*b - 4*a*c
        if disc >= 0:
            sqrt_disc = math.sqrt(disc)
            t1 = (-b - sqrt_disc) / (2*a)
            t2 = (-b + sqrt_disc) / (2*a)
            if t1 > 1e-6: t_values.append(t1)
            if t2 > 1e-6: t_values.append(t2)
    t_values.sort()

    samples = []
    for k, t in enumerate(t_values):
        x_k = [ray_origin[i] + t * ray_direction[i] for i in range(3)]

        # Step 4: Define window bounds W = 2*K + 1
        start_idx = max(0, k - window_half_width)
        end_idx = min(len(t_values), k + window_half_width + 1)

        valid_indices = []
        logits = []

        # Step 5 & 6: Validity masking and aggregation
        for j in range(start_idx, end_idx):
            mu_j = anchors[j]['mu']
            diff = [x_k[i] - mu_j[i] for i in range(3)]
            dist_sq = dot(diff, diff)
            # Step 5: Validity mask M_kj: same ray and Euclidean distance < tau_dist [S1]
            if dist_sq < tau_dist**2:
                Sigma_inv_j = anchors[j]['Sigma_inv']
                # Mahalanobis distance squared: (x_k - mu_j)^T Sigma_j^{-1} (x_k - mu_j) [S1]
                mahal_sq = dot(diff, mat_vec(Sigma_inv_j, diff))
                # Unnormalized logit l_kj [S1]
                l_kj = math.exp(-0.5 * mahal_sq)
                valid_indices.append(j)
                logits.append(l_kj)

        # Normalize weights [G]
        if logits:
            total_logit = sum(logits)
            weights = [l / total_logit for l in logits]
            z_k = [0.0] * len(anchors[0]['f'])
            for idx, w in zip(valid_indices, weights):
                for d in range(len(z_k)):
                    z_k[d] += w * anchors[idx]['f'][d]
        else:
            z_k = [0.0] * len(anchors[0]['f'])

        # Step 7: Neural decoding [G]
        # Shallow MLP decodes z_k into view-dependent color and density sigma [S1]
        sigma = max(0.0, dot(z_k, [1.0, 0.0, 0.0]))
        color = [max(0.0, min(1.0, dot(z_k, [0.0, 1.0, 0.0])))] * 3

        # Step 8: Modulate by opacity and integrate [S1]
        omega_k = anchors[k]['omega']
        modulated_sigma = sigma * math.exp(omega_k)
        opacity = math.exp(omega_k) / (1 + math.exp(omega_k))

        samples.append({
            'x': x_k,
            'sigma': modulated_sigma,
            'color': color,
            'opacity': opacity
        })
    return samples
```

**Parameters**
*   $\tau_{\text{dist}}$: A fixed Euclidean distance threshold used in the validity mask to ensure spatial locality between samples [S1]. Value not given in the sources.
*   $K$: Window half-width parameter for the RCA sliding window. Value not given in the sources.

**Edge Cases and Pitfalls**
*   **Empty Space Processing:** Standard volumetric sampling queries empty space, wasting computation. IRIS handles this by only evaluating structurally meaningful intersection points [S1].
*   **Geometric Discontinuity:** Naive index-based aggregation along the sorted ray list risks blending geometrically disjoint objects (e.g., foreground and background) that are adjacent in the list but distant in 3D space. This is mitigated by the validity mask $M_{kj}$ [S1].
*   **Precision:** The method relies on analytical intersection equations. Precision depends on the accuracy of the ray-triangle intersection within the OptiX API and the numerical stability of the covariance matrix inversion for Mahalanobis distance [S1].

## Operating characteristics
*   **Time Complexity:** RIS operates in a single pass, demonstrating linear scalability with batch size and primitives [S1]. It avoids the computational overhead of 3D KNN lookups and auxiliary network queries [S1].
*   **Memory Complexity:** Requires storage for $N$ Neural Anchors and their proxy geometries. No auxiliary voxel grids or occupancy grids are needed [S1].
*   **Measured Performance:** On the NeRF Synthetic dataset, IRIS achieves 6.038 FPS, approximately 30x higher than EKS (0.183 FPS) [S1]. Training time is reduced to 51 minutes compared to EKS's 26 hours [S1].
*   **Strengths:** Eliminates empty space processing; bypasses costly 3D KNN lookups; enables high-fidelity rendering with explicit geometry; supports topology-agnostic editing and physics simulation [S1].
*   **Limitations:** Requires GPU RT cores for optimal performance (OptiX); relies on the accuracy of the proxy geometry bounds [S1].
*   **When to Use:** When high rendering throughput is required and the scene is represented by explicit Gaussian primitives. Suitable for interactive editing and physics simulation [S1].
*   **When Not to Use:** Not given in the sources.

## Background
IRIS (Intersection-aware Ray-based Implicit Editable Scenes) was introduced to address the computational inefficiencies of standard ray marching and stochastic sampling in neural rendering [S1]. It builds on the paradigms of Neural Radiance Fields (NeRF) and 3D Gaussian Splatting (3DGS), combining the view-dependent effects of NeRF with the explicit, editable nature of 3DGS [S1]. The method was developed to enable efficient and interactive scene editing while maintaining high visual fidelity [S1].
