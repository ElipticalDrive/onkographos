# MultiDDA

Also called: Nested DDA for hierarchical grids, Two-level DDA with brickmap

## Overview
MultiDDA is a ray traversal algorithm for sparse voxel grids that uses a two-level Digital Differential Analyzer (DDA) to skip empty space efficiently [S1, unofficial]. It builds on [Voxel Ray Marching with Cube-Level DDA](3069-voxel-ray-marching-with-cube-level-dda.md) by structuring the grid into bricks of $8^3$ voxels, allowing the ray to step through the top-level brick grid before entering the inner voxel loop [S1, unofficial]. It differs from its parent by explicitly separating the traversal into two distinct DDA loops: one for the brick map and one for the voxel sub-grid within occupied bricks [S1, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (normalized), brick map dimensions $W \times H \times D$, brick size $B=8$, voxel size $v=1$.
**Outputs:** List of occupied voxel coordinates $(x, y, z)$ intersected by the ray.

**Data Structures:**
1.  **Brick Map:** A 3D array of size $\lceil W/B \rceil \times \lceil H/B \rceil \times \lceil D/B \rceil$. Each entry is a boolean or bitmask indicating if the brick contains any occupied voxels.
2.  **Voxel Data:** A flat array or sparse structure storing voxel properties (e.g., density, color) for occupied voxels.

**Algorithm:**
1.  **Initialize Brick DDA:** Compute the initial brick coordinates $(bx, by, bz)$ containing $\mathbf{o}$. Compute step directions $(dx, dy, dz)$ for the brick DDA based on $\mathbf{d}$. Compute $\Delta t$ values for crossing brick boundaries.
2.  **Brick Traversal Loop:** While the ray is within the grid bounds:
    a.  Check if the current brick $(bx, by, bz)$ is occupied.
    b.  If occupied, enter the **Voxel Traversal Loop** (see below) starting from the entry point into the brick.
    c.  Advance the brick DDA to the next brick along the ray.
3.  **Voxel Traversal Loop (Inner):**
    a.  Initialize voxel DDA within the current brick. The entry point is the intersection of the ray with the brick boundary.
    b.  Compute initial voxel coordinates $(vx, vy, vz)$ relative to the brick.
    c.  Compute $\Delta t$ values for crossing voxel boundaries within the brick.
    d.  While the ray is within the current brick:
        i.  Process the current voxel $(vx, vy, vz)$ (e.g., volume rendering step).
        ii. Advance the voxel DDA to the next voxel.
    e.  Exit the loop when the ray leaves the brick.

**Formulas:**
*   Brick coordinates: $bx = \lfloor x / B \rfloor$, $by = \lfloor y / B \rfloor$, $bz = \lfloor z / B \rfloor$.
*   Voxel coordinates within brick: $vx = \lfloor (x - bx \cdot B) / v \rfloor$, etc.
*   DDA step: $t_{next} = t_{current} + \Delta t_{min}$, where $\Delta t_{min}$ is the smallest positive $t$ to cross a boundary in $x, y,$ or $z$.

**Parameters:**
*   Brick size $B=8$ [S1, unofficial].
*   Voxel size $v=1$ [S1, unofficial].

**Edge Cases:**
*   **Ray origin outside grid:** Return empty list.
*   **Empty bricks:** Skip inner loop entirely.
*   **Ray grazing brick/voxel boundaries:** Use epsilon bias to avoid double-counting or missing voxels [G].

**Pseudocode:**
```python
def multi_dda(ray_origin, ray_direction, brick_map, brick_size=8):
    # Initialize brick DDA
    bx, by, bz = brick_dda_init(ray_origin, brick_size)
    dx, dy, dz = brick_dda_step(ray_direction, brick_size)
    t_x, t_y, t_z = brick_dda_t_values(ray_origin, ray_direction, brick_size)
    step_x, step_y, step_z = brick_dda_steps(ray_direction)
    
    while in_bounds(bx, by, bz):
        if brick_map[bx, by, bz]:
            # Enter voxel DDA within this brick
            voxel_dda(ray_origin, ray_direction, bx, by, bz, brick_size)
        
        # Advance brick DDA
        if t_x < t_y and t_x < t_z:
            bx += step_x
            t_x += dx
        elif t_y < t_z:
            by += step_y
            t_y += dy
        else:
            bz += step_z
            t_z += dz

def voxel_dda(ray_origin, ray_direction, bx, by, bz, brick_size):
    # Calculate entry point into the brick
    brick_origin = [bx * brick_size, by * brick_size, bz * brick_size]
    t_enter, t_exit = ray_brick_intersection(ray_origin, ray_direction, brick_origin, brick_size)
    
    if t_enter < 0:
        t_enter = 0
    
    # Initialize voxel DDA within the brick
    vx, vy, vz = voxel_dda_init(ray_origin, ray_direction, brick_origin, brick_size)
    dvx, dvy, dvz = voxel_dda_step(ray_direction, 1) # voxel size = 1
    tvx, tvy, tvz = voxel_dda_t_values(ray_origin, ray_direction, brick_origin, brick_size)
    s_vx, s_vy, s_vz = voxel_dda_steps(ray_direction)
    
    while t_enter < t_exit:
        # Process voxel (vx, vy, vz)
        process_voxel(vx, vy, vz)
        
        # Advance voxel DDA
        if tvx < tvy and tvx < tvz:
            vx += s_vx
            tvx += dvx
        elif tvy < tvz:
            vy += s_vy
            tvy += dvy
        else:
            vz += s_vz
            tvz += dvz
```

## Subtopics

### [VRI Ray Advancement](3187-vri-ray-advancement.md)
A three-level hierarchy method that separates traversal into draining I1 DDA, stepping I2 DDA, and advancing root entries. Choose when deeper hierarchy is needed for very large scenes.

## Operating characteristics
*   **Time Complexity:** $O(N_{bricks} + N_{voxels})$, where $N_{bricks}$ is the number of bricks traversed and $N_{voxels}$ is the number of occupied voxels.
*   **Memory Complexity:** $O(W \cdot H \cdot D / B^3)$ for the brick map, plus $O(N_{voxels})$ for voxel data.
*   **Performance:** Offers good performance relative to its simplicity [S1, unofficial]. However, it suffers from SIMD divergence due to control-flow divergence when entering the inner traversal loop, as not all SIMD lanes hit a brick at the same time, causing stalls [S1, unofficial].
*   **Strengths:** Simple to implement, effective space skipping for coherent rays.
*   **Limitations:** Poor performance with incoherent rays due to SIMD divergence [S1, unofficial].
*   **When to use:** Coherent ray batches, simple hardware, or when implementation complexity must be minimized.
*   **When not to use:** Highly incoherent rays, SIMD-heavy architectures, or scenes with very large empty spaces where deeper hierarchy (e.g., [eXtendedBrickMap](3070-extended-brickmap.md)) is beneficial.

## Background
MultiDDA is part of the VoxelRT project, which benchmarks various voxel rendering acceleration structures [S1, unofficial]. It is a straightforward extension of flat DDA to a hierarchical grid, designed to balance simplicity and performance for brick-based voxel representations.
