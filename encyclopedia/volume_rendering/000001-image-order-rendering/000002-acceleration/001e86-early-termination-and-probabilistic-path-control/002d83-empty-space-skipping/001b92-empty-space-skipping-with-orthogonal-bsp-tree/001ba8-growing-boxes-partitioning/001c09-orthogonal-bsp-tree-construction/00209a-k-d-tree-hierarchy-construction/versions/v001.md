# K-D Tree Hierarchy Construction

Also called: Polygon distribution in k-d tree, Spatial partitioning with k-d trees

## Overview
K-D Tree Hierarchy Construction is a spatial partitioning method that organizes polygons into a binary tree structure to enable efficient ray traversal and early termination in volume rendering [S1]. It solves the problem of explicitly clipping polygons against view frustums or traversal planes by associating each polygon with the smallest node region that completely contains it [S1]. Unlike its parent method, Orthogonal BSP Tree Construction, which uses object-aligned splitting planes, the K-D tree splits regions along axis-aligned hyperplanes, typically bisecting the space [S1]. This approach avoids subdividing polygons, ensuring they are stored only in leaf or internal nodes where they fit entirely, thereby simplifying the active polygon list during rendering [S1].

## How it works
**Inputs:** A set of polygons $P$, each defined by a list of vertices. A user-defined threshold $T$ for leaf node creation.
**Outputs:** A K-D tree structure where each node $v$ contains a list of polygon IDs and references to left and right children.

**Data Structures:**
*   **Node $v$:**
    *   `split_dim`: Integer index $i \in \{0, 1, 2\}$ indicating the axis of splitting.
    *   `split_val`: Float value $X_i$ defining the position of the splitting hyperplane orthogonal to the $x_i$-axis.
    *   `polygons`: List of polygon IDs (integers) stored in prefix-order traversal order within a common array `Tid` [S1].
    *   `left`: Pointer to left child node.
    *   `right`: Pointer to right child node.
*   **Polygon $p$:** Defined by vertices $V_p = \{v_1, v_2, \dots, v_k\}$, where each vertex $v_j$ has coordinates $(x_j, y_j, z_j)$.

**Algorithm Steps:**
1.  **Initialization:** Create a root node $r$ containing all input polygons $P$.
2.  **Recursive Construction:** For a given node $v$ containing a set of polygons $P_v$:
    a.  **Leaf Check:** If $|P_v| \le T$, mark $v$ as a leaf node. Store the IDs of polygons in $P_v$ in the `Tid` array at the current traversal index. Return.
    b.  **Splitting Dimension Selection:** Determine the splitting dimension $i$. The standard implementation uses a round-robin fashion (e.g., $x, y, z, x, \dots$) [S1]. *Note: Variants exist that select the axis based on variance (see Subtopics).*
    c.  **Splitting Value Selection:** Determine the splitting value $X_i$. The standard implementation bisects the region, setting $X_i$ to the midpoint of the bounding box along dimension $i$ [S1].
    d.  **Polygon Classification:** Partition $P_v$ into three sets:
        *   $P_{left}$: Polygons where all vertices have coordinate $x_i < X_i$.
        *   $P_{right}$: Polygons where all vertices have coordinate $x_i > X_i$.
        *   $P_{overlap}$: Polygons where some vertices have $x_i < X_i$ and others have $x_i > X_i$ (or equal).
    e.  **Storage:** Store the IDs of polygons in $P_{overlap}$ in the `Tid` array at the current traversal index. These polygons are associated with node $v$ [S1].
    f.  **Recursion:**
        *   Create left child node $v_L$. Recursively construct the subtree for $P_{left}$.
        *   Create right child node $v_R$. Recursively construct the subtree for $P_{right}$.
        *   Set $v.left = v_L$ and $v.right = v_R$.

**Pseudocode:**
```python
def build_kd_tree(polygons, threshold, depth=0):
    """
    Recursively builds a K-D tree.
    polygons: List of Polygon objects.
    threshold: Integer, max polygons per leaf.
    depth: Integer, current tree depth (used for round-robin axis selection).
    Returns: Node object or None if polygons is empty.
    """
    if not polygons:
        return None

    # Leaf check
    if len(polygons) <= threshold:
        return Node(leaf=True, polygons=polygons, split_dim=None, split_val=None)

    # Axis selection: Round-robin based on depth [S1]
    # Dimensions: 0=x, 1=y, 2=z
    split_dim = depth % 3

    # Splitting value: Bisect the bounding box of all polygons [S1]
    min_coord = min(p.min_coord[split_dim] for p in polygons)
    max_coord = max(p.max_coord[split_dim] for p in polygons)
    split_val = (min_coord + max_coord) / 2.0

    # Classification
    left_polys = []
    right_polys = []
    overlap_polys = []

    for p in polygons:
        # Check if all vertices are strictly less than split_val
        all_less = all(v[split_dim] < split_val for v in p.vertices)
        # Check if all vertices are strictly greater than split_val
        all_greater = all(v[split_dim] > split_val for v in p.vertices)

        if all_less:
            left_polys.append(p)
        elif all_greater:
            right_polys.append(p)
        else:
            overlap_polys.append(p)

    # Recursive construction
    left_node = build_kd_tree(left_polys, threshold, depth + 1)
    right_node = build_kd_tree(right_polys, threshold, depth + 1)

    return Node(
        leaf=False,
        polygons=overlap_polys,
        split_dim=split_dim,
        split_val=split_val,
        left=left_node,
        right=right_node
    )
```

**Edge Cases and Pitfalls:**
*   **Polygon Association:** Polygons are associated with the smallest node region that completely contains them [S1]. This avoids subdividing polygons but means a polygon may be stored in an internal node if it spans the splitting plane [S1].
*   **Precision:** Floating-point comparisons for vertex positions against `split_val` must be consistent to avoid ambiguity. Strict inequality (`<` and `>`) is used in the standard definition [S1].
*   **Empty Subtrees:** If $P_{left}$ or $P_{right}$ is empty, the corresponding child node should be `None` or handled appropriately to avoid infinite recursion or null pointer dereferences.

## Subtopics

### Axis Selection via Variance
A variant that selects the splitting axis by analyzing the variance of the QEF (Quadratic Error Function) solution along each dimension, scaled by the box size [S2, unofficial]. It solves the QEF to get an approximate solution and error, then calculates variance for each axis: $variance[i] = qef.getVariance(approximate) \times size[i]$ [S2, unofficial]. It selects the axis with maximum variance (`maxVarDir`). If the box size along `maxVarDir` is less than 2, it falls back to $3 - maxVarDir - minVarDir$; if that size is also less than 2, it falls back to `minVarDir` [S2, unofficial]. This method is used in specific implementations like KdtreeISO for isosurface extraction [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Building the tree takes $O(N \log N)$ on average for $N$ polygons, assuming balanced splits [S1]. Worst-case is $O(N^2)$ if splits are unbalanced.
*   **Memory Complexity:** $O(N)$ for storing polygon IDs in the `Tid` array and tree nodes [S1].
*   **Performance:** The method is highly scalable and was shown to extend to about 16 processors before contention became a serious drawback [S1]. It removes the need for explicit polygon clipping, reducing per-pixel overhead [S1].
*   **Strengths:** Avoids polygon subdivision; efficient for ray traversal; simple implementation [S1].
*   **Limitations:** Round-robin splitting may not be optimal for non-uniform polygon distributions [S1].

## Background
The K-D tree was introduced by Jon Bentley in 1975 [S1]. It was adapted for volume rendering in the context of hierarchical and parallelizable direct volume rendering for irregular and multiple grids [S1]. The method was developed to group polygons by scanline into y-buckets in a parallelizable manner [S1].
