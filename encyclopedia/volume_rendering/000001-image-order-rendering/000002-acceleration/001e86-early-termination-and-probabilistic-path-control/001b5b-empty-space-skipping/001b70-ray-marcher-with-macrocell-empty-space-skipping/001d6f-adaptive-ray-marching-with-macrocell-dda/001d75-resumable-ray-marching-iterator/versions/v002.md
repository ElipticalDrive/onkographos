# Resumable Ray Marching Iterator

Also called: OptiX7 Adaptive Ray Marching, Resumable Ray Marching

## Overview
The Resumable Ray Marching Iterator is a GPU-based ray traversal method that adapts step sizes via macrocell DDA and persists ray state to enable out-of-core volume rendering [S1, S2]. It builds on [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) by adding state persistence and resumability checks to handle dynamic data loading [S1, S2]. Unlike [Network Ray Marching Iterator](1510-network-ray-marching-iterator.md) which relies on different streaming heuristics, or [Macrocell Grid Traversal with Majorant Densities](1528-macrocell-grid-traversal-with-majorant-densities.md) which focuses on density bounds, this method explicitly manages CPU-GPU synchronization for on-demand data streaming [S2].

## How it works
### Inputs and Outputs
**Inputs:**
- Ray origin `org` and direction `dir` [S1, S2].
- Volume bounds `tMin`, `tMax` [S1].
- Volume dimensions `dims` [S1].
- Macrocell spacing via `macrocell_spacings_rcp` [S2].
- Base sample step `step` [S1].
- Adaptive sampling rate parameter `adaptiveSamplingRate` [S2].

**Outputs:**
- Accumulated color and alpha for the pixel [S3].
- Updated ray state (position, accumulated color) for resumption [S3].
- Missing node IDs for CPU-side data loading [S3].

### Data Structures
The method relies on specific payload structures to store ray state and traversal context [S1, S2].

**SampleStreamingPayload**
Stores the state of a ray for resumption and output [S1].
- `pixel_index`: Integer identifying the pixel [S1].
- `jitter`: Floating point jitter value [S1].
- `alpha`: Accumulated alpha (float) [S1].
- `color`: Accumulated color (vec3f) [S1].
- `iter.cell`: Current macrocell coordinates (vec3i, present if `ADAPTIVE_SAMPLING` is defined) [S1].
- `iter.t_next`: Next traversal position (vec2f, present if `ADAPTIVE_SAMPLING` is defined) [S1].
- `iter.next_cell_begin`: Offset from `tMin` to the next cell boundary (float, always present) [S1].

**RadiancePayload**
Used for primary ray tracing [S2].
- `alpha`: Initialized to `0.f` [S2].
- `color`: Initialized to `0.f` [S2].
- `rng`: Pointer to random number generator state, initialized to `nullptr` [S2].

**ShadowPayload**
Used for shadow ray tracing [S2].
- `alpha`: Initialized to `0.f` [S2].
- `rng`: Pointer to random number generator state, initialized to `nullptr` [S2].

### Numbered Steps
1. **Initialization**: If `ADAPTIVE_SAMPLING` is defined, initialize the DDA iterator with `DDAIter::init(m_org, m_dir, tMin, tMax, dims)` [S1]. If not defined, initialize `t.x = max(tMin + next_cell_begin, tMin)` and `t.y = min(t.x + step, tMax)` [S1].
2. **Ray Marching Loop**: 
   - **Adaptive Mode**: Compute macrocell coordinates `m_org = org * macrocell_spacings_rcp` and `m_dir = dir * macrocell_spacings_rcp` [S2]. Perform DDA traversal over macrocells using `dda::dda3` [S2]. For each interval `[t0, t1]`, calculate opacity upper bound `r = opacityUpperBound(self, cell)` [S1]. If `fabsf(r) <= float_epsilon`, skip the cell and continue DDA [S1]. Calculate adaptive step `ss = sample_size_scaler(adaptiveSamplingRate(step, r), t0, t1)` [S2]. Initialize `t = vec2f(t0, min(t1, t0 + ss))` [S1]. Loop while `t.y > t.x`: set `DDAIter::next_cell_begin = t.y - tMin`, call `body(t)`, update `t.x = t.y` and `t.y = min(t.x + ss, t1)` [S1].
   - **Non-Adaptive Mode**: Loop while `t.y > t.x`: set `next_cell_begin = t.y - tMin`, call `body(t)`, update `t.x = t.y` and `t.y = min(t.x + step, tMax)` [S1]. Set `next_cell_begin = float_large` and return [S1].
3. **Resumability Check**: If `ADAPTIVE_SAMPLING` is defined, return `DDAIter::resumable(m_dir, tMin, tMax, dims)` [S1]. If not defined, return `tMin + next_cell_begin < tMax` [S1].
4. **Shadow Ray Tracing**: Create `ShadowPayload` with a new RNG [S2]. Pack pointer to shadow into `u0`, `u1` using `packPointer` [S2]. Call `optixTrace` with traversable from `optixLaunchParams`, origin `org`, direction `dir`, `tmin=0.f`, `tmax=float_large`, `time=0.0f`, `mask=255`, `flag=OPTIX_RAY_FLAG_DISABLE_ANYHIT`, `rayType=SHADOW_RAY_TYPE`, `sbtStride=RAY_TYPE_COUNT`, `missIndex=SHADOW_RAY_TYPE`, `u0`, `u1` [S2]. Return `1.f - shadow.alpha` [S2].

### Formulas
**Sample Size Scaler**
Calculates the effective step size to fit an integer number of steps within an interval `[t0, t1]`:
$$ N = \lfloor (t1 - t0) / ss \rfloor + 1 $$
$$ \text{effective\_step} = (t1 - t0) / N $$
where `ss` is the initial adaptive step size estimate [S2].

**Resumability Condition (Non-Adaptive)**
$$ \text{resumable} = (tMin + next\_cell\_begin < tMax) $$
[S1]

### Parameters
- `ADAPTIVE_SAMPLING`: A preprocessor macro that must be defined to enable adaptive sampling logic; if not defined, compilation fails with error "ADAPTIVE_SAMPLING is not defined" [S2].
- `next_cell_begin`: Member variable tracking the offset from `tMin` to the next cell boundary, used for resuming the march [S1].
- `adaptiveSamplingRate`: Function or parameter controlling the base adaptive step size based on opacity [S2].
- `step`: Base sample step size for non-adaptive mode [S1].

### Edge Cases and Pitfalls
- **Precision**: The use of `float_epsilon` for empty cell detection (`fabsf(r) <= float_epsilon`) requires careful consideration of floating-point precision in opacity bounds [S1].
- **Boundary Conditions**: The loop condition `t.y > t.x` and the clamping `min(t.y, t1)` or `min(t.y, tMax)` must handle cases where the interval is smaller than the step size [S1].
- **Data Loading Latency**: The method assumes the CPU can load data fast enough to keep up with rendering; otherwise, frames may be delayed or require multiple passes per frame [S3].
- **Z-Buffer Culling**: Relies on early-Z features; if early-Z is disabled or fails, inactive pixels may still execute, wasting resources [S3].

### Pseudocode
```python
def raymarching_iterator(org, dir, tMin, tMax, dims, step, macrocell_spacings_rcp):
    if ADAPTIVE_SAMPLING:
        m_org = org * macrocell_spacings_rcp
        m_dir = dir * macrocell_spacings_rcp
        DDAIter.init(m_org, m_dir, tMin, tMax, dims)
        while DDAIter.next(lambda cell, t0, t1):
            r = opacityUpperBound(self, cell)
            if abs(r) <= float_epsilon:
                continue
            ss = sample_size_scaler(adaptiveSamplingRate(step, r), t0, t1)
            t = vec2f(t0, min(t1, t0 + ss))
            while t.y > t.x:
                DDAIter.next_cell_begin = t.y - tMin
                body(t)
                t.x = t.y
                t.y = min(t.x + ss, t1)
    else:
        t.x = max(tMin + next_cell_begin, tMin)
        t.y = min(t.x + step, tMax)
        while t.y > t.x:
            next_cell_begin = t.y - tMin
            body(t)
            t.x = t.y
            t.y = min(t.x + step, tMax)
        next_cell_begin = float_large
        return

    if ADAPTIVE_SAMPLING:
        return DDAIter.resumable(m_dir, tMin, tMax, dims)
    else:
        return tMin + next_cell_begin < tMax
```

## Subtopics

### Ray-Guided Streaming with Interrupt/Resume
A method for handling missing GPU memory by stopping ray tracing when data is absent, communicating this to the CPU for loading, and resuming the ray at the last position in subsequent passes [S3]. The algorithm starts ray tracing and stops rays whenever data is missing, communicating the missing node ID to the CPU which initiates loading [S3]. Ray status information (preliminary output color accumulation, missing node ID, and current marching position) is maintained in two Multiple Render Targets (MRTs) [S3]. Missing IDs are downloaded to the CPU so it can adapt the data structure [S3]. In the next rendering pass, a proxy surface initiates rendering and the MRTs are used as input textures; early-Z ensures only active pixels execute the fragment shader [S3]. This approach ensures loaded data is directly traversed by the ray and no data outside the frustum is loaded, while the CPU does not need to track LODs [S3].

## Operating characteristics
- **Time Complexity**: Depends on the number of macrocells traversed and the adaptive step size; adaptive sampling reduces steps in empty regions [S1].
- **Memory Complexity**: Requires additional memory for MRTs to store ray state (color, alpha, position, missing ID) for all active pixels [S2].
- **Measured Performance**: Not given in the sources.
- **Scaling**: Scales with the number of active rays and the complexity of the volume data; more missing data leads to more passes, increasing total time [S3].
- **Strengths**: Handles out-of-core data efficiently; only loads data within the frustum; adaptive sampling reduces computation in empty regions [S3].
- **Limitations**: Requires multiple rendering passes for complete frames if data is missing; relies on CPU-GPU synchronization; complexity in managing ray state [S3].
- **When to use**: When volume data exceeds GPU memory capacity and dynamic loading is required [S3].
- **When not to use**: When all data fits in GPU memory and low latency is critical, as the overhead of state management and multiple passes may not be justified [S3].

## Background
The method originates from research on ray-guided streaming for efficient and detailed voxel rendering [S3]. It was implemented in the context of OptiX7-based volume renderers, as indicated by the alias "OptiX7 Adaptive Ray Marching" and the use of OptiX-specific features like `optixTrace` and SBT configuration [S2]. The approach addresses the challenge of rendering large volumetric datasets that cannot fit entirely in GPU memory by streaming data on-demand [S3].
