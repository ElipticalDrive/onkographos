# Ray Casting with Depth/Alpha Test for Empty Space Skipping

Also called: Westermann & Sevenich method, Ray Casting using Alpha and Depth Tests, Empty Space Skipping via OpenGL Tests, Westermann & Sevenich Empty Space Skipping

## Overview
This method accelerates direct volume rendering by skipping empty space intervals in the volume integral, using 2D textures and OpenGL alpha/depth tests to discard non-contributing intervals [S1]. It determines the near and far intersection points of rays with the volume by leveraging the GPU's depth buffer, allowing samples to be taken only between these points [S1]. Unlike sibling methods that may use complex data structures like octrees or BSP trees, this technique relies on standard OpenGL pipeline tests to bound the ray segment, reducing the number of samples and framebuffer writes [S1]. It is particularly effective when the volume has significant external empty space, though its benefit diminishes with high internal data dispersion [S1].

## How it works
**Inputs:**
*   3D volume data (scalar field).
*   Camera parameters (projection matrix $P$, modelview matrix $V$).
*   Rendering context supporting OpenGL alpha and depth tests.

**Outputs:**
*   Final color image in the framebuffer.

**Data Structures:**
*   **2D Textures:** The volume is sliced into 2D planes parallel to the X, Y, and Z axes. For each axis, a set of 2D textures is created, one for each slice [S1].
*   **Display Lists:** Created for each set of textures (front-to-back and back-to-front) to optimize rendering order [S1].
*   **Depth Buffer:** Used to store normalized device coordinates (NDC) of the nearest and farthest visible fragments [S1].

**Algorithm Steps:**

1.  **Preprocessing (CPU):**
    *   Calculate the gradient of each volume element using central differences [S1].
    *   Perform illumination and shading based on the lighting model variables. Store the resulting color and opacity data in main memory [S1]. This step is performed once on the CPU, unlike methods that compute shading dynamically on the GPU [S1].

2.  **Texture Preparation (CPU/GPU):**
    *   For each axis (X, Y, Z):
        *   For each plane parallel to the axis:
            *   Create a 2D texture from the slice data [S1].
            *   Load the texture into GPU memory [S1].
            *   Create a display list for the set of textures, ordered front-to-back and back-to-front [S1].

3.  **Determine Ray Bounds (GPU Passes):**
    *   The goal is to find the entry ($P$) and exit ($Q$) points of the ray through the volume.
    *   **Pass 1 (Near Point):**
        *   Initialize the depth buffer to 1.0 (maximum NDC depth).
        *   Enable the **Alpha Test** with `GL_GREATER` and a reference value $> 0$. This discards fragments with zero opacity (empty space) [S1].
        *   Set the **Depth Test** criterion to `GL_LESS`.
        *   Render the volume slices. The depth buffer will store the distance of the closest significant fragment to the projection plane for each pixel [S1].
    *   **Pass 2 (Far Point):**
        *   Initialize the depth buffer to 0.0 (minimum NDC depth).
        *   Keep the **Alpha Test** enabled (`GL_GREATER`, ref $> 0$) [S1].
        *   Set the **Depth Test** criterion to `GL_GREATER`.
        *   Render the volume slices. The depth buffer will store the distance of the farthest significant fragment from the projection plane for each pixel [S1].

4.  **Coordinate Transformation:**
    *   Read the depth values from the depth buffer for each pixel $(x_s, y_s, z_s)$ in NDC.
    *   Transform these NDC coordinates to world coordinates to obtain the ray origin $P$ and ray end $Q$.
    *   The transformation uses the inverse of the projection and modelview matrices:
        $$
        \begin{bmatrix} x \\ y \\ z \\ w \end{bmatrix} = (P M)^{-1} V \begin{bmatrix} x_s \\ y_s \\ z_s \\ 1 \end{bmatrix}
        $$
        where $P$ is the projection matrix, $M$ is the model matrix, and $V$ is the view matrix [S1]. Note: The source notation $(PM)^{-1}V$ implies the combined inverse projection-model matrix applied to the view-transformed NDC point. In standard OpenGL, NDC is derived from clip coordinates, which are derived from eye coordinates via $V$ and $P$. To go from NDC to World, one typically inverts $P$ and $V$ and applies them in reverse order. The source formula is interpreted as transforming the NDC point back to world space using the inverse of the modelview-projection chain [S1].

5.  **Ray Casting and Compositing:**
    *   For each pixel, cast a ray between $P$ (near) and $Q$ (far).
    *   Sample the volume along the ray segment defined by $t \in [0, 1]$:
        $$
        X(t) = P_x + (Q_x - P_x)t
        $$
        $$
        Y(t) = P_y + (Q_y - P_y)t
        $$
        $$
        Z(t) = P_z + (Q_z - P_z)t
        $$
    *   The increment in $t$ is determined by the number of samples $n$ per ray (e.g., $\Delta t = 1/n$) [S1].
    *   Composite the samples using the volume rendering integral. Since empty space outside $[P, Q]$ is skipped, the integral is reduced:
        $$
        L(x) = \int_{x_A'}^{x_B'} \left[ e^{-\int_{x_A'}^{x_0'} \phi_t(x'')dx''} \epsilon(x_0') dx_0' \right]
        $$
        where $x_A'$ and $x_B'$ correspond to points $P$ and $Q$, $\phi_t$ is the extinction coefficient, and $\epsilon$ is the color [S1].
    *   Draw the final composed color to the framebuffer [S1].

**Pseudocode:**

```python
def westermann_sevenich_render(volume_data, camera_params):
    """
    volume_data: 3D array of scalar values
    camera_params: dict with 'projection_matrix', 'modelview_matrix', 'view_matrix'
    """
    # Step 1: Preprocessing on CPU
    gradients = calculate_central_differences(volume_data)
    shaded_volume = apply_lighting(volume_data, gradients, lighting_model)
    
    # Step 2: Create 2D textures for slices
    # Determine optimal axis based on camera angle
    axis = determine_optimal_axis(volume_data, camera_params)
    textures = create_2d_textures_from_slices(shaded_volume, axis)
    
    # Step 3: Pass 1 - Find Near Point (P)
    gl_init_depth_buffer(1.0)
    gl_enable_alpha_test()
    gl_alpha_func(GL_GREATER, 0.0) # Discard zero opacity
    gl_depth_func(GL_LESS)
    render_slices(textures, front_to_back_order)
    near_depth_buffer = gl_read_depth_buffer()
    
    # Step 4: Pass 2 - Find Far Point (Q)
    gl_init_depth_buffer(0.0)
    gl_enable_alpha_test()
    gl_alpha_func(GL_GREATER, 0.0)
    gl_depth_func(GL_GREATER)
    render_slices(textures, back_to_front_order)
    far_depth_buffer = gl_read_depth_buffer()
    
    # Step 5: Transform NDC to World Coordinates
    inv_proj_model = invert_matrix(multiply_matrices(camera_params['projection_matrix'], camera_params['model_matrix']))
    # Note: Source formula uses (PM)^-1 V. Standard OpenGL pipeline: World -> Model -> View -> Projection.
    # NDC is after Projection. To get World from NDC: NDC -> Clip -> Eye -> World.
    # The source formula is specific to the implementation context. We follow the source's variable mapping.
    # P_world and Q_world are computed for each pixel (x_s, y_s) using near_depth_buffer and far_depth_buffer.
    
    # Step 6: Ray Casting
    for each pixel (x_s, y_s):
        z_near_ndc = near_depth_buffer[x_s, y_s]
        z_far_ndc = far_depth_buffer[x_s, y_s]
        
        # Convert NDC to World
        P_world = ndc_to_world(x_s, y_s, z_near_ndc, inv_proj_model, camera_params['view_matrix'])
        Q_world = ndc_to_world(x_s, y_s, z_far_ndc, inv_proj_model, camera_params['view_matrix'])
        
        # Ray Casting between P and Q
        color = composite_ray(P_world, Q_world, volume_data, num_samples)
        
        gl_set_framebuffer_color(x_s, y_s, color)

def ndc_to_world(x_ndc, y_ndc, z_ndc, inv_pm, view_matrix):
    """
    Transforms NDC coordinates to World coordinates.
    Follows the source's implication of using inverse projection-model and view matrix.
    """
    # Homogeneous NDC point
    ndc_point = [x_ndc, y_ndc, z_ndc, 1.0]
    
    # Apply inverse projection-model matrix
    # Note: In standard OpenGL, we invert Projection then ModelView.
    # The source formula: [x,y,z,w] = (PM)^-1 V [xs,ys,zs,1]
    # This suggests V is applied to the NDC point? No, V is part of the forward transform.
    # Let's stick to the source's explicit formula structure for fidelity, 
    # interpreting V as the view matrix and PM as projection*model.
    # However, mathematically, to go from NDC to World:
    # 1. NDC to Clip: w=1 (after perspective divide)
    # 2. Clip to Eye: Inv(P) * Clip
    # 3. Eye to World: Inv(V) * Eye
    
    # The source formula seems to conflate or simplify. 
    # We will implement the standard inverse chain which achieves the goal described.
    clip_point = [x_ndc, y_ndc, z_ndc, 1.0]
    eye_point = multiply_matrix_vector(invert(camera_params['projection_matrix']), clip_point)
    world_point = multiply_matrix_vector(invert(camera_params['view_matrix']), eye_point)
    
    # Perspective divide if necessary (though NDC is already divided)
    # NDC is [x/w, y/w, z/w]. The input to the inverse is the NDC coordinates.
    # If the depth buffer stores z_ndc, we reconstruct the clip z.
    # This is a simplification for the purpose of the article based on source [S1].
    return world_point

def composite_ray(P, Q, volume, n_samples):
    """
    Standard front-to-back compositing along the ray segment P to Q.
    """
    t_step = 1.0 / n_samples
    alpha_accum = 0.0
    color_accum = [0.0, 0.0, 0.0]
    
    for i in range(n_samples):
        t = i * t_step
        # Interpolate position
        pos = P + (Q - P) * t
        
        # Sample volume (trilinear interpolation)
        density = sample_volume(pos, volume)
        
        # Get color and opacity from transfer function
        color, opacity = transfer_function(density)
        
        # Composite
        # C_out = C_in + (1 - alpha_in) * C_sample * alpha_sample
        # A_out = A_in + (1 - A_in) * alpha_sample
        weight = (1.0 - alpha_accum) * opacity
        color_accum += weight * color
        alpha_accum += weight
        
        if alpha_accum >= 1.0:
            break
            
    return color_accum
```

## Subtopics

### Polygon Assisted Ray Casting
An optimization for primary rays in volumetric ray tracing that creates a polygonal representation of all objects and projects them into two Z-buffers (nearest and farthest distances) [S2]. It ensures polygonal models completely contain the actual volumetric objects to bound the ray segment [S2]. If no Z-buffer information exists for a pixel, intersection calculations are skipped [S2]. It typically reduces primary ray computation by a factor of four [S2]. It can also be extended to shadow rays by creating Z-buffer projections from light locations [S2].

## Operating characteristics
*   **Time Complexity:** Reduces ray casting time to approximately one-quarter of a naive ray caster that samples the entire ray extension [S1]. Performance improvements of 3 to 4 times faster are observed when using alpha and depth tests compared to not using them [S1].
*   **Memory Complexity:** Requires storing 2D textures for all slices along the optimal axis, plus display lists. This is generally less memory-intensive than 3D textures or complex tree structures but requires multiple passes over the data [S1].
*   **Strengths:** Simple to implement using standard OpenGL features; effective for volumes with large empty regions outside the object; avoids complex data structure traversal [S1].
*   **Limitations:** Only skips external empty spaces; high internal data dispersion reduces effectiveness as the ray length with skipping becomes similar to the unoptimized length [S1]. Illumination is calculated on the CPU in a single pass, preventing dynamic lighting updates without recomputation [S1].
*   **When to use:** When the volume has significant transparent regions outside the object and dynamic lighting is not required.
*   **When not to use:** When the volume has high internal dispersion (many small opaque regions throughout) or when dynamic lighting is needed (consider Engel, Kraus & Ertl instead) [S1].

## Background
The method was introduced by Westermann and Sevenich in their work [WS01] [S1]. It is a hybrid volume rendering technique that leverages the GPU's depth buffer to skip empty spaces, allowing ray casting to sample only non-transparent material [S1]. It differs from Engel, Kraus & Ertl's method by performing illumination calculation uniquely and in the initial phase on the CPU, whereas Engel's method computes it on the GPU [S1]. The technique is part of the broader family of empty-space skipping methods aimed at accelerating volume rendering by avoiding regions in the volume that are completely transparent [Parent].
