# Early Shader Termination

Also called: Early End of Computation, Early z-test optimization, Two-pass empty space culling

## Overview
Early Shader Termination is an optimization technique that discards the execution of complex decoding shaders for fragments likely to represent empty space by using an early z-test in a two-pass rendering approach [S1]. It builds on [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) by adding a lightweight pre-check to avoid expensive shader execution in empty regions. Compared to rendering uncompressed data, this approach initially perceives a loss in performance of a factor of 2-3 due to complex shaders and texture indirections; however, in empty regions, it results in a considerable speed-up because only one texture fetch is needed to check the mean [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A compressed volume dataset where each block (macro-cell) has an associated index texture $I$ storing metadata (specifically the mean value in the R-component) and dependent data textures $C_1, C_2$ [S1]. A slicing polygon representing the current view frustum or volume boundary.
*   **Output:** A rendered image where empty space fragments are skipped, and depth values are correctly updated to allow subsequent fragments to pass depth tests.

**Data Structures:**
*   **Index Texture $I$:** Stores block metadata. The R-component holds the mean value of the block [S1].
*   **Dependent Textures $C_1, C_2$:** Store difference information or raw data, addressed using components of $I$ [S1].

**Steps:**
1.  **First Pass (Empty Space Detection):**
    1.  Render the slicing polygon with a simple pixel shader.
    2.  In the shader, access the index texture $I$ and read the mean value from the R-component.
    3.  If the mean value is zero:
        *   Set the fragment's color and opacity to zero.
        *   Write the fragment's depth to the depth buffer. This marks the space as "empty but processed" without affecting the color buffer [S1].
    4.  If the mean value is not zero:
        *   Discard the fragment using a `kill` instruction (or equivalent discard mechanism).
        *   Do **not** write to the depth buffer. The depth value of the last rendered fragment remains valid [S1].

2.  **Second Pass (Complex Rendering):**
    1.  Render the same slicing polygon again.
    2.  Set the depth test function to `GL_GREATER` (or equivalent logic that passes fragments with depth greater than the current buffer value).
    3.  Execute the complex decoding shader (as described in Compression Domain Rendering).
    4.  The early z-test ensures that only fragments discarded in the first pass (where mean $\neq 0$) pass the depth test and enter the complex shader. Fragments where mean $= 0$ are discarded before shader execution because their depth is already in the buffer and they do not satisfy `GL_GREATER` [S1].

**Pseudocode:**

```python
# First Pass Shader: Simple Empty Space Check
def simple_shader(fragment_depth, index_texture_I):
    # Read mean value from R-component of index texture
    mean_value = index_texture_I.read(fragment_depth).R
    
    if mean_value == 0:
        # Empty space: write depth, zero color/opacity
        depth_buffer.write(fragment_depth)
        return Color(0, 0, 0, 0)
    else:
        # Potential non-empty space: discard to prevent depth write
        # The depth buffer retains the last valid depth
        discard_fragment()
        return None

# Rendering Loop

    set_shader(simple_shader)
    render_slicing_polygon()
    
    # Pass 2: Render non-empty blocks

    set_shader(complex_shader)

```

**Parameters:**
*   **Depth Test Function:** Must be set to `GL_GREATER` in the second pass to leverage the early z-test correctly [S1].
*   **Mean Threshold:** Zero is used as the threshold for empty space [S1].

**Edge Cases and Pitfalls:**
*   **Depth Buffer Consistency:** If a fragment is discarded in the shader (via `kill`), the depth value of the fragment rendered last is still valid in the depth buffer. This must be accounted for when using depth tests, as the discarded fragment does not update the depth buffer [S1].
*   **Performance Overhead:** The two-pass approach introduces overhead. The initial performance loss compared to uncompressed rendering is a factor of 2-3 due to the complexity of the shaders and texture indirections [S1].

## Operating characteristics
*   **Time Complexity:** In empty regions, the complexity is reduced to one texture fetch per block to check the mean [S1]. In non-empty regions, the full complex shader is executed.
*   **Memory Complexity:** Requires storage for the index texture $I$ and dependent textures $C_1, C_2$ [S1].
*   **Measured Performance:** On an Intel P4 1900 MHz machine, this approach saves another 5 percent of overall rendering time on average when combined with other optimizations like Early End of Computation [S2, unofficial].
*   **Strengths:** Considerable speed-up in empty regions, which are frequent in numerical simulation results [S1].
*   **Limitations:** Initial performance loss of 2-3x compared to uncompressed rendering due to shader complexity and indirections [S1]. Requires hardware support for early z-test [S1].

## Background
The technique was proposed in the context of compression domain volume rendering to address performance losses caused by complex shader programs and texture indirections [S1]. It leverages the early z-test feature available on target graphics architectures to avoid executing pixel shaders for fragments that are likely to decode empty space [S1]. The concept of terminating computation early is also discussed in the context of cell-based first-hit ray casting, where rendering ends as soon as all pixels are covered, saving approximately 5% of overall rendering time [S2, unofficial].
