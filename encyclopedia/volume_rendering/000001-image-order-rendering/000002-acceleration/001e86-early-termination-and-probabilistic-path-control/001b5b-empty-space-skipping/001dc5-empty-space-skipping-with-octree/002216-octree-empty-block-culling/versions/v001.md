# Octree Empty Block Culling

Also called: Octree Leaf Culling, Recursive Status Check

## Overview
Octree Empty Block Culling is a method for accelerating volume rendering by recursively traversing an octree to determine if a node contains any non-empty data blocks, returning a status of `EMPTY` or `NONEMPTY` to enable early ray termination or skipping of empty regions [S1, unofficial]. It differs from sibling methods like [Octree Traversal with Min/Max Pruning](1739-octree-traversal-with-min-max-pruning.md) by relying on explicit occupancy flags stored in the octree nodes rather than bounding volume bounds or min/max values of the data within the blocks [S1, unofficial].

## How it works
**Inputs:** An octree structure where each node has a `depth` field and a `status` field. The root node's depth is 0. A memory management unit (MMU) or similar accessor providing a `getBlock` function that returns a pointer to the data block associated with a leaf node, or `nullptr` if the block is not loaded/exists.

**Outputs:** A boolean indicating whether the node (and its subtree) contains non-empty data (`true` for `NONEMPTY`, `false` for `EMPTY`).

**Data Structures:**
*   `Node`:
    *   `depth`: Integer, the depth of the node in the octree (0 for root).
    *   `status`: Enum or Boolean, `EMPTY` or `NONEMPTY`.
    *   `children`: Array of 8 pointers to child nodes (for internal nodes).
*   `MMU`:
    *   `getBlock(node_index)`: Returns a pointer to the data block for the leaf node identified by `node_index`, or `nullptr`.

**Algorithm Steps:**
1.  Initialize the current node's `status` to `EMPTY`.
2.  Check if the current node is a leaf. A node is a leaf if `node->depth` equals the maximum tree depth.
    *   If it is a leaf:
        *   Attempt to load the block using `mmu->getBlock(node_index)`.
        *   If the returned block is `nullptr`, set `node->status = EMPTY` and return `false`.
        *   Otherwise, set `node->status = NONEMPTY` and return `true`.
    *   If it is an internal node:
        *   Recursively call the status check function on all 8 children.
        *   Children are accessed using linear indexing: `child_index = (index << 3) + i + 1` for `i` from 0 to 7, where `index` is the index of the current node in a flat array representation (if applicable) or passed recursively.
        *   If any child returns `true` (indicating `NONEMPTY`), set `node->status = NONEMPTY`.
        *   Return `node->status == NONEMPTY`.

**Pseudocode:**
```python
def check_status(node, mmu, max_depth, node_index):
    """
    Recursively checks if a node or its subtree contains non-empty data.
    
    Args:
        node: The current octree node.
        mmu: Memory management unit with getBlock method.
        max_depth: The maximum depth of the octree.
        node_index: The linear index of the node in the octree array (0 for root).
        
    Returns:
        bool: True if the node contains non-empty data, False otherwise.
    """
    # Initialize status to EMPTY
    node.status = EMPTY
    
    # Check if leaf
    if node.depth == max_depth:
        # Attempt to load block
        block = mmu.getBlock(node_index)
        if block is None:
            node.status = EMPTY
            return False
        else:
            node.status = NONEMPTY
            return True
    else:
        # Internal node: check all 8 children
        # Linear indexing: children of index i are at (i << 3) + 1 to (i << 3) + 8
        base_index = (node_index << 3) + 1
        for i in range(8):
            child_index = base_index + i
            # Assuming node.children[i] is the child node object
            # We need to pass the child node and its index
            if check_status(node.children[i], mmu, max_depth, child_index):
                node.status = NONEMPTY
                return True
        return node.status == NONEMPTY
```

**Parameters:**
*   `max_depth`: The maximum depth of the octree. This must be set correctly during initialization. If incorrect, all nodes may be treated as internal or leaf incorrectly [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Incorrect Depth Initialization:** If the tree depth is not set correctly during initialization, the leaf check `node->depth == depth` may fail, causing all nodes to be treated as internal or leaf incorrectly [S1, unofficial].
*   **Empty Blocks:** A leaf node may exist in the octree structure but have no associated data block (e.g., not loaded into memory). The `getBlock` function must return `nullptr` in this case, and the node should be marked as `EMPTY`.

## Subtopics

### Octree Range Culling
Octree Range Culling is a variant where shells' ranges over a node are computed once per pass for up to 4 tiles of 64 functions (each lane owns a function of every tile) instead of once per tile, only for shells reaching the node [S2, unofficial]. A dropped shell has every AO below $10^{-10}$ over the node; `fn_tail` ($2 \times 10^{-10}$ times the column sum of $|C|$) is added to every function's bound for them [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(N)$ in the worst case, where $N$ is the number of nodes in the octree, as it may need to traverse all nodes. However, in practice, it is much faster due to early termination when empty subtrees are encountered.
**Memory Complexity:** $O(N)$ for storing the octree structure and status flags.
**Strengths:** Simple to implement, effective for sparse data where large portions of the volume are empty.
**Limitations:** Requires storing status flags in the octree nodes, increasing memory usage. Performance depends on the distribution of empty vs. non-empty regions.
**When to use:** When the volume data is sparse and large empty regions are common.
**When not to use:** When the volume data is dense and most regions contain non-empty data, as the overhead of traversal may not be justified.

## Background
The method is described in the context of parallel volume rendering systems, specifically in the `VolumeRenderingParallel` project [S1, unofficial]. It is used to optimize ray traversal by skipping empty regions of the volume, thereby reducing the number of samples taken and improving rendering performance.
