# Adaptive Undersampling

Also called: Fast Adaptive Undersampling, Two-pass Adaptive Undersampling with Pre-computed Intervals

## Overview
Adaptive Undersampling is a two-pass rendering method that accelerates volume integral calculation by pre-computing integral values over $M$ equal intervals for a subset of pixels and storing them in a G-buffer [S1]. On the second pass, pixels use bilinear interpolation of these interval values for speed, or calculate integrals only over specific intervals if interpolation accuracy is insufficient, rather than integrating over the entire ray [S1]. It builds on [Adaptive Sampling and Resolution](1412-adaptive-sampling-and-resolution.md) by increasing the adaptive undersampling factor, allowing fewer pixels to be processed in the first pass while maintaining image quality through spatial interpolation in the second pass [S1]. Compared to standard adaptive undersampling, it increases frames per second (FPS) by a factor of 1.5 on average, and provides further acceleration over two-pass adaptive screen sampling without interval partitioning [S1].

## How it works
**Inputs:**
- 3D volume texture (data to be visualized) [S1].
- Transfer function $f$ [S1].
- Viewport resolution $(W, H)$ [G].
- Block size parameter $n$ (side length of square blocks) [S1].
- Maximum number of intervals $M$ [S1].

**Outputs:**
- Final rendered image [G].

**Data Structures:**
- **G-buffer:** Contains $M+1$ parallel textures with resolution $\frac{W}{n} \times \frac{H}{n}$ [S1].
    - Texture 0 (`G[0]`): Stores the final composited color $C$ (4-component vector: RGB + Transparency $A$) [S1].
    - Textures $1 \dots M$ (`G[1] \dots G[M]`): Store the volume integral values $I_i$ for each of the $M$ equal-length intervals. Each $I_i$ is a 4-component vector containing the color and transparency components accumulated over that specific interval [S1].

**Numbered Steps:**

1.  **Pass 1: Pre-computation**
    1.  Partition the pixel set into $n \times n$ blocks [S1].
    2.  For one pixel per block (e.g., the top-left pixel), perform the following:
        a.  Find the starting point $v$ of the non-zero transfer function domain using `GetDistanceForStart(s, f)`, where $s$ is the ray origin and $f$ is the final point. If $v$ is not found (function returns -1), halt processing for this ray [S1].
        b.  Calculate the interval length. Since samples are in a unit cube, the maximum ray length is $\sqrt{3}$. The length of each of the $M$ equal intervals is $L = \frac{\sqrt{3}}{M}$ [S1].
        c.  Compute the volume integrals over the $M$ equal intervals starting from $v$. Let $I_i$ be the integral over the $i$-th interval ($0 \le i < M$) [S1].
        d.  Compute the final pixel color $C$ by integrating over the entire active ray segment [S1].
        e.  Store $C$ in `G[0]` and the interval integrals $I_i$ in `G[i+1]` for the corresponding block coordinate [S1].
    3.  Handle the last interval: The last interval of integration may be shorter than the others because the ray may exit the volume before completing the $M$-th equal interval. This is handled by a separate calculation for the remaining segment [S1].

2.  **Pass 2: Interpolation and Refinement**
    1.  For each remaining pixel (those not processed in Pass 1):
        a.  Retrieve the colors $C_{neighbor}$ of the four adjacent pixels processed in Pass 1 [S1].
        b.  Check if the colors of the adjacent pixels are sufficiently close [S1].
        c.  **If yes:** Interpolate the current pixel color $C_P$ bilinearly from the adjacent pixels' colors stored in `G[0]` [S1].
        d.  **If no:** Calculate $C_P$ using the recurrence relation, starting from the beginning of the ray. For $0 \le i \le M-1$:
            $$C_{P_{i+1}} = C_{P_i} + (1 - A_{P_i}) \cdot A_i^* \cdot C_i^*$$
            $$A_{P_{i+1}} = A_{P_i} + (1 - A_{P_i}) \cdot A_i^*$$
            Where $A_i^*$ and $C_i^*$ are the transparency and color components of the interval integral $I_i$.
            - If the adjacent pixels' interval values $I_i$ are sufficiently close, $A_i^*$ and $C_i^*$ are interpolated bilinearly from the G-buffer values [S1].
            - If interpolation is insufficient, $A_i^*$ and $C_i^*$ are calculated via volume integration over that specific interval only [S1].
        e.  The final color $C_P$ is the result after processing all necessary intervals [G].

**Pseudocode:**

```python
import math

def get_distance_for_start(ray_start, ray_end, transfer_function):
    """Finds distance from ray_start to point v where transfer function first becomes non-zero. Returns -1 if not found."""
    # [G] Standard ray-marching to find first non-zero opacity sample.
    return 0.0

def compute_interval_integral(ray_start, ray_end, interval_start_t, interval_end_t, transfer_function, volume_data):
    """Computes volume integral (color and transparency) over a specific interval along the ray."""
    c_acc = (0.0, 0.0, 0.0)
    a_acc = 0.0
    t = interval_start_t
    step = 1.0 / 64.0
    while t < interval_end_t:
        sample_color, sample_alpha = sample_volume(ray_start, ray_end, t, transfer_function, volume_data)
        one_minus_a = 1.0 - a_acc
        c_acc = (c_acc[0] + one_minus_a * sample_alpha * sample_color[0],
                 c_acc[1] + one_minus_a * sample_alpha * sample_color[1],
                 c_acc[2] + one_minus_a * sample_alpha * sample_color[2])
        a_acc = a_acc + one_minus_a * sample_alpha
        if a_acc >= 1.0:
            break
        t += step
    return c_acc, a_acc

def sample_volume(ray_start, ray_end, t, transfer_function, volume_data):
    """Returns sample color and alpha at parameter t."""
    # [G] Linear interpolation in volume, apply transfer function.
    return (0.5, 0.5, 0.5), 0.1

def bilinear_interpolate(g_buffer, x, y, texture_index):
    """Performs bilinear interpolation on the G-buffer texture at index texture_index."""
    # [G] Standard bilinear interpolation.
    return (0.5, 0.5, 0.5, 0.5)

def are_colors_close(colors):
    """Checks if all colors in the list are sufficiently close to each other."""
    # [G] Simple max difference check.
    return True

def adaptive_undersampling_pass1(viewport_w, viewport_h, n, m, transfer_function, volume_data):
    buf_w = viewport_w // n
    buf_h = viewport_h // n
    # Initialize G-buffer: list of (buf_h x buf_w) arrays for RGBA
    g_buffer = [[[(0.0, 0.0, 0.0, 0.0) for _ in range(buf_w)] for _ in range(buf_h)] for _ in range(m + 1)]
    
    max_ray_length = math.sqrt(3.0)
    interval_length = max_ray_length / m
    
    for block_y in range(buf_h):
        for block_x in range(buf_w):
            pixel_x = block_x * n
            pixel_y = block_y * n
            
            # [G] Standard ray generation for pixel (pixel_x, pixel_y)
            ray_start = (0.0, 0.0, 0.0)
            ray_end = (1.0, 1.0, 1.0)
            
            v = get_distance_for_start(ray_start, ray_end, transfer_function)
            
            if v == -1:
                continue 
            
            interval_integrals = []
            current_pos = v
            
            for i in range(m):
                next_pos = current_pos + interval_length
                if next_pos > ray_end[0]:
                    next_pos = ray_end[0]
                
                c_i, a_i = compute_interval_integral(ray_start, ray_end, current_pos, next_pos, transfer_function, volume_data)
                interval_integrals.append((c_i, a_i))
                
                current_pos = next_pos
                if current_pos >= ray_end[0]:
                    break
            
            # Compute final color C
            final_c, final_a = compute_interval_integral(ray_start, ray_end, v, ray_end[0], transfer_function, volume_data)
            
            # Store in G-buffer
            g_buffer[0][block_y][block_x] = (final_c[0], final_c[1], final_c[2], final_a)
            
            for i, (c_i, a_i) in enumerate(interval_integrals):
                if i < m:
                    g_buffer[i + 1][block_y][block_x] = (c_i[0], c_i[1], c_i[2], a_i)
    
    return g_buffer

def adaptive_undersampling_pass2(viewport_w, viewport_h, n, m, g_buffer, transfer_function, volume_data):
    image = [[(0.0, 0.0, 0.0, 0.0) for _ in range(viewport_w)] for _ in range(viewport_h)]
    
    for y in range(viewport_h):
        for x in range(viewport_w):
            if x % n == 0 and y % n == 0:
                continue
            
            block_x = x // n
            block_y = y // n
            
            # Retrieve neighbors from G[0]
            neighbors = []
            for dy in range(-1, 2):
                for dx in range(-1, 2):
                    ny, nx = block_y + dy, block_x + dx
                    if 0 <= ny < len(g_buffer[0]) and 0 <= nx < len(g_buffer[0][0]):
                        neighbors.append(g_buffer[0][ny][nx])
            
            if are_colors_close(neighbors):
                image[y][x] = bilinear_interpolate(g_buffer, x % n, y % n, 0)
            else:
                ray_start = (0.0, 0.0, 0.0)
                ray_end = (1.0, 1.0, 1.0)
                v = get_distance_for_start(ray_start, ray_end, transfer_function)
                
                if v == -1:
                    image[y][x] = (0.0, 0.0, 0.0, 0.0)
                    continue
                
                c_p = (0.0, 0.0, 0.0)
                a_p = 0.0
                
                for i in range(m):
                    # Get interval integral I_i from G-buffer
                    c_i_star, a_i_star = g_buffer[i + 1][block_y][block_x]
                    
                    one_minus_a_p = 1.0 - a_p
                    c_p = (c_p[0] + one_minus_a_p * a_i_star * c_i_star[0],
                           c_p[1] + one_minus_a_p * a_i_star * c_i_star[1],
                           c_p[2] + one_minus_a_p * a_i_star * c_i_star[2])
                    a_p = a_p + one_minus_a_p * a_i_star
                    
                    if a_p >= 1.0:
                        break
                
                image[y][x] = (c_p[0], c_p[1], c_p[2], a_p)
    
    return image
```

**Parameters:**
- $n$: The side length of the square blocks into which the pixel set is partitioned. One pixel is processed per $n \times n$ block on the first pass [S1].
- $M$: The user-selected maximum number of equal-length intervals into which the integration domain is divided. The G-buffer stores $M$ parallel textures [S1].

**Edge Cases and Pitfalls:**
- **Woodgrain artifacts:** Caused by high derivatives of the opacity function near the ray start. Mitigated by finding the starting point $v$ where the transfer function becomes non-zero, rather than starting at the ray origin. This also increases the probability that the first integrals $I_0$ coincide on adjacent rays [S1].
- **Last interval length:** The last interval of integration may be shorter than the others because the ray may exit the volume before completing the $M$-th equal interval. This is handled by a separate 'lastStep' calculation [S1].
- **GPU Efficiency:** Unlike recursive block division methods which are inefficient on GPUs due to concurrent processing groups, this fixed two-pass approach avoids the overhead of recursive subdivision [S1].

## Subtopics

### [Two-pass Adaptive Screen Sampling with Interval Partitioning](5460-two-pass-adaptive-screen-sampling-with-interval-partitioning.md)
This method accelerates volume integral calculation by partitioning the ray integration interval into $M$ equal pieces and using a second pass to interpolate or recompute integrals for pixels based on neighborhood coherence. It builds on [Adaptive Undersampling](5397-adaptive-undersampling.md) by increasing the adaptive undersampling factor, allowing fewer pixels to be processed in the first pass while maintaining image quality through spatial interpolation in the second pass. Compared to standard adaptive undersampling, it increases frames per second (FPS) by a factor of 1.5 on average, and provides further acceleration over two-pass adaptive screen sampling without interval partitioning.

### Optional Sparse Sampling
Trades accuracy for performance by sampling accessibility at low resolution and reconstructing full-screen result with a cross-bilateral filter. Filter falls off with surface normal discrepancy and 3D distance between desired and available samples. Implemented as separate 1D horizontal and vertical passes [S2, unofficial]. Undersampling is a source of error when geometry changes rapidly in screen space [S2, unofficial]. Reconstruction passes account for 1.1-1.3 ms of total render time at 1280×720. This is independent of the resolution reduction [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Accelerates rendering by reducing the length of the interval of integration. On average, it accelerates adaptive undersampling by a factor of 1.5 [S1].
- **Measured Performance:** In a real dataset example, 91.7% of pixels were interpolated, 5.7% required 1 interval calculation, 2.1% required 2, 0.1% required 3, and 0.4% required >3 intervals [S1].
- **Scaling:** The method scales with the viewport resolution and the number of intervals $M$. The G-buffer resolution is $n$ times less than the viewport along each side [S1].
- **Strengths:** Avoids recursive subdivision overhead on GPUs; reduces computation for most pixels via interpolation; handles high-opacity gradients effectively by starting integration at the non-zero transfer function domain [S1].
- **Limitations:** Requires two passes; performance depends on the coherence of adjacent pixels; requires storing $M$ parallel textures in the G-buffer [S1].
- **When to use:** When rendering volumetric data on GPUs where recursive algorithms are inefficient, and when high frame rates are needed with acceptable interpolation artifacts [S1].
- **When not to use:** When the volume has high-frequency details that are not coherent between adjacent pixels, leading to frequent interval recomputation [S1].

## Background
Adaptive Undersampling was proposed in the paper "Fast Adaptive Undersampling for Volume Rendering" by Smirnova and Shubnikov (2019) [S1]. It addresses the computational expense of direct volume rendering, where running time is proportional to the number of pixels. The method improves upon earlier two-pass algorithms by pre-computing interval integrals, allowing for more efficient partial integration in the second pass [S1].
