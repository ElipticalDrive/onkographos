# Progressive Refinement

Also called: Progressive Path Tracing with Preview Scaling, Progressive Refinement Ray Casting, Progressive Rendering with Pause

## Overview
Progressive refinement is a rendering technique that accumulates samples over frames to gradually improve image quality, enabling initial low-fidelity previews that refine interactively [S1, unofficial]. It solves the problem of long rendering times by generating partial images that are progressively refined as the user interacts with the crude image [S3, unofficial]. Unlike static rendering, it allows users to pause the process and immediately see material changes without restarting [S2]. It sets itself apart from [Temporal and Progressive Rendering](11267-temporal-and-progressive-rendering.md) by focusing on spatial accumulation of samples within a single view session rather than temporal stability across frames, and from [Checkerboard Progressive Rendering](4836-checkerboard-progressive-rendering.md) by its ability to support both forward (pyramid-based) and backward (screen-space) viewing approaches [S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Volume dataset, camera parameters, transfer function, initial low-resolution image or empty frame buffer.
- Output: High-fidelity volume rendering image.

**Data Structures:**
1.  **Pyramid Data Structure:** A hierarchical representation of the volume data, where smaller volumes are rendered first using large-footprint splats, followed by higher-resolution components [S3, unofficial].
2.  **Screen Buffer:** Stores the current accumulated image. In backward viewing, it stores interpolated values for regions where no rays were emitted [S3, unofficial].

**Steps:**
The method supports two primary implementations: Forward Viewing and Backward Viewing [S3, unofficial].

### Forward Viewing Implementation
1.  **Initialize Pyramid:** Construct or access a pyramid data structure of the volume [S3, unofficial].
2.  **Render Low-Resolution Base:** Render the smallest volume in the pyramid using large-footprint splats to cover large screen areas [S3, unofficial]. Rays intended to cover large screen areas are traced in these lower-resolution components [S3, unofficial].
3.  **Accumulate Higher Resolutions:** Render higher-resolution components of the pyramid later, adding detail to the image [S3, unofficial].
4.  **Refine Sampling:** Progressively refine the sampling rate and stopping criteria as the user interacts [S3, unofficial].

### Backward Viewing Implementation
1.  **Low-Resolution Sampling:** First, sample the screen in low resolution. Assign rays to a subset of pixels [S3, unofficial].
2.  **Interpolate Missing Regions:** For regions in the screen where no rays were emitted, assign a value interpolated from close pixels that were assigned rays [S3, unofficial].
3.  **Cast Additional Rays:** Later, cast more rays to cover the previously interpolated regions or refine existing samples [S3, unofficial].
4.  **Replace Interpolated Values:** Replace the interpolated values with accurate results from the newly cast rays [S3, unofficial].

**Pseudocode:**
```python
def progressive_refinement(volume, camera, transfer_function, max_iterations):
    # Initialize screen buffer with zeros or low-res estimate
    screen_buffer = initialize_screen_buffer(camera.resolution)
    
    # Determine implementation mode: 'forward' or 'backward'
    mode = 'forward' # or 'backward'
    
    for iteration in range(max_iterations):
        if mode == 'forward':
            # Forward Viewing: Render pyramid levels
            # Level 0 is the smallest volume
            level = get_pyramid_level(iteration)
            if level is None:
                break
            
            # Render using large-footprint splats for coarse levels
            # or standard ray casting for finer levels
            coarse_image = render_pyramid_level(volume, level, camera, transfer_function)
            
            # Accumulate into screen buffer
            # Note: Exact accumulation strategy (additive, weighted) depends on specific implementation
            screen_buffer = accumulate(screen_buffer, coarse_image)
            
        elif mode == 'backward':
            # Backward Viewing: Screen-space refinement
            # Identify pixels that have not been sampled or are low-confidence
            unsampled_pixels = get_unsampled_pixels(screen_buffer)
            
            # If unsampled_pixels is empty, refine existing samples
            if len(unsampled_pixels) == 0:
                refine_existing_samples(screen_buffer, camera, volume, transfer_function)
            else:
                # Cast rays for unsampled pixels
                for pixel in unsampled_pixels:
                    color = cast_ray(volume, camera, pixel)
                    screen_buffer[pixel] = color
                
                # Interpolate missing regions if any remain (e.g., due to sparse sampling)
                interpolate_missing_regions(screen_buffer)
        
        # Check stopping criteria (e.g., convergence, user pause, max iterations)
        if check_stopping_criteria(screen_buffer, iteration):
            break
            
    return screen_buffer
```

**Edge Cases and Pitfalls:**
- **GPU Intensity:** Highly GPU-intensive; requires a high-end GPU for responsive viewport feedback [S2].
- **Precision:** Interpolated values in backward viewing may introduce artifacts if the underlying volume has high-frequency details [S3, unofficial].
- **Boundaries:** Rays intended to cover large screen areas in lower-resolution components must be carefully managed to avoid aliasing when higher-resolution components are added [S3, unofficial].

## Subtopics

### Adaptive-Progressive Refinement
A rendering strategy that balances image quality and generation speed by displaying coarse frames at interactive rates and using spare cycles to increase resolution when the user pauses, supplemented by kinetic depth cues via rocking cineloops [S4, unofficial]. It computes images at lower resolution while view parameters are changing, increases computed resolution when parameters remain fixed, and sends variable-resolution images from ray casters/compositors to splat processors, which interpolate the image over the full frame buffer resolution [S4, unofficial]. It displays coarse frames at interactive rates and uses spare cycles to increase overall resolution as the user pauses [S4, unofficial]. A series of seven highest-resolution frames displaying visualized structures in animated oscillatory rotation (rocking cineloop) is appended to provide kinetic depth effect [S4, unofficial]. Rendering time is several seconds to render a high-resolution VISTAnet image on Pixel-Planes 5 [S4, unofficial]. A fully refined image uses 1 ray per image pixel, while an adaptively sampled image uses 1 ray every 4-16 pixels [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** Rendering time is several seconds to render a high-resolution VISTAnet image on Pixel-Planes 5 [S4, unofficial].
- **Scaling:** Scalability to 4K or 8K displays remains challenging, as pixel counts quadruple or nonuple, often halving frame rates [S1, unofficial].
- **Strengths:** Enables initial low-fidelity previews that refine interactively [S1, unofficial]. Allows users to pause the process and immediately see material changes without restarting [S2]. Supports both forward and backward viewing approaches [S3, unofficial].
- **Limitations:** Highly GPU-intensive; requires a high-end GPU for responsive viewport feedback [S2].
- **When to Use:** When interactive feedback is required during rendering, or when the user needs to inspect details progressively.
- **When Not to Use:** When real-time performance is critical and hardware is limited, or when a single high-quality image is needed without interaction.

## Background
Progressive refinement was introduced as a practical solution to the rendering time problem in volume visualization [S3, unofficial]. An efficient implementation was reported by Danskin and Hanrahan [S3, unofficial]. The technique has been used in various volume visualization systems, including those running on specialized hardware like Pixel-Planes 5 [S4, unofficial]. In the 2025 context, AI-based denoising, such as neural networks with dual-input feature fusion, outperforms traditional spatiotemporal filters at low sample counts, enabling real-time rendering with reduced bias, though it requires training data specific to volume types [S1, unofficial].
