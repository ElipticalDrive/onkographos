# Progressive Refinement

Also called: Progressive Path Tracing with Preview Scaling, Progressive Refinement Ray Casting, Progressive Rendering with Pause

## Overview
Progressive refinement is a rendering technique that accumulates samples over frames to gradually improve image quality, enabling initial low-fidelity previews that refine interactively [S1, unofficial]. It solves the problem of long rendering times by generating partial images that are progressively refined as the user interacts with the crude image [S3, unofficial]. It sets itself apart from [Temporal and Progressive Rendering](11267-temporal-and-progressive-rendering.md) by focusing on spatial accumulation of samples within a single view session rather than temporal stability across frames, and from [Checkerboard Progressive Rendering](4836-checkerboard-progressive-rendering.md) by its ability to support both forward (pyramid-based) and backward (screen-space) viewing approaches [S3, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Volume dataset, camera parameters, transfer function, initial frame buffer state.
- Output: High-fidelity volume rendering image.

**Data Structures:**
1. **Pyramid Data Structure:** A hierarchical representation of the volume data where smaller volumes are rendered first using large-footprint splats, followed by higher-resolution components [S3, unofficial].
2. **Screen Buffer:** Stores the current accumulated color and sample count per pixel [G]. In backward viewing, it temporarily holds interpolated values for regions where no rays were emitted [S3, unofficial].

**Steps:**
The method supports two primary implementations [S3, unofficial]:
1. **Forward Viewing:** Render the smallest volume in a pyramid data structure using large-footprint splats first [S3, unofficial]. Rays intended to cover large screen areas are traced in these lower-resolution components [S3, unofficial]. Later, higher-resolution pyramid components are rendered and added to the buffer [S3, unofficial].
2. **Backward Viewing:** First sample the screen in low resolution [S3, unofficial]. Regions where no rays were emitted receive a value interpolated from close pixels that were assigned rays [S3, unofficial]. Later, more rays are cast and the interpolated values are replaced by accurate results [S3, unofficial]. Sampling rate and stopping criteria are progressively refined [S3, unofficial].

**Formulas:**
The accumulated pixel color $C$ after $N$ samples is computed as:
$$C = \frac{1}{N} \sum_{k=1}^{N} \left( \sum_{i=1}^{M} T_i \cdot (1 - e^{-\rho_i \Delta t}) \cdot c_i \right)$$
where $T_i = \prod_{j=1}^{i-1} e^{-\rho_j \Delta t}$ is the transmittance at step $i$, $\rho_i$ is the density sampled at step $i$, $\Delta t$ is the step size along the ray, $c_i$ is the emitted color from the transfer function, and $M$ is the number of steps per ray [G].

**Parameters:**
- `max_frames`: Maximum number of refinement iterations. Not given in the sources.
- `step_size`: Distance between volume samples along a ray. Typical value: 0.5 [G].
- `new_samples_per_frame`: Number of additional samples cast per pixel each frame. Typical value: $2^{\text{frame}}$ capped at 16 [G].

**Edge Cases and Pitfalls:**
- **GPU Intensity:** Highly GPU-intensive; requires a high-end GPU for responsive viewport feedback [S2].
- **Boundaries:** Rays intended to cover large screen areas in lower-resolution components must be carefully managed to avoid aliasing when higher-resolution components are added [S3, unofficial].

**Pseudocode:**
```python
from math import sqrt

def norm(v):
    return sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def progressive_refinement(volume, camera, transfer_function, max_frames):
    acc_color = zeros((camera.height, camera.width, 3))
    acc_count = zeros((camera.height, camera.width), dtype=int)
    step_size = 0.5  # Typical volume traversal step [G]
    
    for frame in range(max_frames):
        new_samples = min(2 ** frame, 16)
        
        for y in range(camera.height):
            for x in range(camera.width):
                if acc_count[y, x] >= new_samples:
                    continue
                
                for _ in range(new_samples):
                    ray_o, ray_d = camera.get_ray(x, y)
                    ray_d = (ray_d[0]/norm(ray_d), ray_d[1]/norm(ray_d), ray_d[2]/norm(ray_d))  # Normalize for consistent step size [G]
                    pos = ray_o
                    transmittance = 1.0
                    pixel_color = [0.0, 0.0, 0.0]
                    
                    while pos inside volume bounds:
                        density = volume.sample(pos)
                        if density > 0.0:
                            c = transfer_function(density)
                            alpha = 1.0 - exp(-density * step_size)
                            pixel_color += transmittance * alpha * c
                            transmittance *= exp(-density * step_size)
                        pos += (ray_d[0]*step_size, ray_d[1]*step_size, ray_d[2]*step_size)
                        
                    acc_color[y, x] += pixel_color
                    acc_count[y, x] += 1
        
        for y in range(camera.height):
            for x in range(camera.width):
                if acc_count[y, x] == 0:
                    neighbors = []
                    for dy in [-1, 0, 1]:
                        for dx in [-1, 0, 1]:
                            if dy == 0 and dx == 0: continue
                            ny, nx = y + dy, x + dx
                            if 0 <= ny < camera.height and 0 <= nx < camera.width and acc_count[ny, nx] > 0:
                                neighbors.append(acc_color[ny, nx])
                    if neighbors:
                        acc_color[y, x] = sum(neighbors) / len(neighbors)
        
        yield acc_color / (acc_count + 1e-6)
```

## Subtopics

### Adaptive-Progressive Refinement
A rendering strategy that balances image quality and generation speed by displaying coarse frames at interactive rates and using spare cycles to increase resolution when the user pauses, supplemented by kinetic depth cues via rocking cineloops [S4, unofficial]. It computes images at lower resolution while view parameters are changing, increases computed resolution when parameters remain fixed, and sends variable-resolution images from ray casters/compositors to splat processors, which interpolate the image over the full frame buffer resolution [S4, unofficial]. It displays coarse frames at interactive rates and uses spare cycles to increase overall resolution as the user pauses [S4, unofficial]. A series of seven highest-resolution frames displaying visualized structures in animated oscillatory rotation (rocking cineloop) is appended to provide kinetic depth effect [S4, unofficial]. Rendering time is several seconds to render a high-resolution VISTAnet image on Pixel-Planes 5 [S4, unofficial]. A fully refined image uses 1 ray per image pixel, while an adaptively sampled image uses 1 ray every 4-16 pixels [S4, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources. [S3, unofficial]
- **Memory Complexity:** Not given in the sources. [S3, unofficial]
- **Measured Performance:** Rendering time is several seconds to render a high-resolution VISTAnet image on Pixel-Planes 5 [S4, unofficial].
- **Scaling:** Scalability to 4K or 8K displays remains challenging, as pixel counts quadruple or nonuple, often halving frame rates [S1, unofficial].
- **Strengths:** Enables initial low-fidelity previews that refine interactively [S1, unofficial]. Allows users to pause the process and immediately see material changes without restarting [S2]. Supports both forward and backward viewing approaches [S3, unofficial].
- **Limitations:** Highly GPU-intensive; requires a high-end GPU for responsive viewport feedback [S2].

## Background
Progressive refinement was introduced as a practical solution to the rendering time problem in volume visualization [S3, unofficial]. An efficient implementation was reported by Danskin and Hanrahan [S3, unofficial]. The technique has been used in various volume visualization systems, including those running on specialized hardware like Pixel-Planes 5 [S4, unofficial]. In the 2025 context, AI-based denoising, such as neural networks with dual-input feature fusion, outperforms traditional spatiotemporal filters at low sample counts, enabling real-time rendering with reduced bias, though it requires training data specific to volume types [S1, unofficial].
