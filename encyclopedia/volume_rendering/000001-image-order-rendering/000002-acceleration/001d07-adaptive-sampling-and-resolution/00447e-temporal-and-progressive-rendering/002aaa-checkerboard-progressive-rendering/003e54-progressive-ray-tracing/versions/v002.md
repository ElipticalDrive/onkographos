# Progressive Ray Tracing

Also called: Progressive Refinement Ray Casting

## Overview
Progressive Ray Tracing is an adaptive sampling technique that produces lower-quality images which are then improved over time [S1, unofficial]. It solves the problem of maintaining interactive frame rates during user interaction by computing only a subset of rays, then progressively filling in the remaining pixels with actual values once interaction ceases [S2, book].

## How it works
**Inputs and Outputs:**
- Input: Scene data, camera parameters, subsampling stride $n$, interaction state.
- Output: A rendered image that transitions from an interpolated approximation to a fully ray-traced result.

**Data Structures:**
- Image buffer: 2D array of color values per pixel.

**Steps:**
1. During interaction, compute ray casting results only for every $n$-th pixel along each image dimension [S2, book].
2. Use interpolation to calculate color values for the remaining unsampled pixels [S2, book].
3. Display the interpolated image to maintain interactivity [S2, book].
4. When the user stops interacting, progressively replace the interpolated pixels with their actual ray-traced values [S2, book].

**Parameters:**
- $n$: The subsampling stride. A typical value is $n=2$, which yields a four-times speed-up [S2, book]. Larger values of $n$ increase speed but produce blurrier, less detailed images [S2, book].

**Edge Cases and Pitfalls:**
- High-frequency details tend to get lost during the interpolated phase [S1, unofficial].
- The method may introduce bias or noise if not combined with termination techniques like Russian roulette [S1, unofficial].
- The quality of the interpolated image depends heavily on the interpolation method used [G].

**Pseudocode:**
```python
def progressive_ray_tracing(scene, camera, width, height, n=2):
    image = [[0.0] * width for _ in range(height)]
    user_interacting = True
    while True:
        if user_interacting:
            for y in range(0, height, n):
                for x in range(0, width, n):
                    ray = camera.generate_ray(x, y)
                    image[y][x] = trace_ray(scene, ray) # [G] standard ray-scene intersection
            interpolate_missing_pixels(image, n, width, height) # [G] bilinear or nearest-neighbor fill
            if not check_user_input(): # [G] event loop check
                user_interacting = False
        else:
            pixels_to_trace = []
            for y in range(height):
                for x in range(width):
                    if is_interpolated(image[y][x]): # [G] flag or heuristic
                        pixels_to_trace.append((x, y))
            if not pixels_to_trace:
                break
            for (x, y) in pixels_to_trace:
                ray = camera.generate_ray(x, y)
                image[y][x] = trace_ray(scene, ray)
            display_image(image) # [G] buffer swap
            if not pixels_to_trace:
                break
        display_image(image)
```

## Operating characteristics
- Time Complexity: During interaction, compute time is reduced by a factor of $n^2$ for 2D subsampling, yielding a four-times speed-up for $n=2$ [S2, book]. Refinement complexity is proportional to the number of missing pixels [G].
- Memory Complexity: Requires storage for the image buffer and a mask or flags to track traced pixels [G].
- Performance: Provides a four-times speed-up with $n=2$ without a noticeable decrease in image quality during interaction [S2, book]. Larger reductions increase speed but degrade image quality [S2, book].
- Strengths: Maintains interactivity during view manipulation; improves image quality progressively after interaction stops [G].
- Limitations: Loses high-frequency details during the interpolated phase [S1, unofficial]; requires interpolation which may introduce artifacts [G]; refinement phase may still be slow for large scenes [G].
- When to Use: Interactive volume visualization where user interaction is frequent but final high-quality rendering can be deferred [G].
- When Not to Use: When high-frequency details are critical during interaction; when real-time feedback is required without any interpolation artifacts [G].

## Background
Progressive ray tracing was introduced as a technique to produce lower quality images which are then improved with time [S1, unofficial]. It is part of the broader field of adaptive sampling and resolution techniques in volume rendering [G]. The method is discussed in the context of advanced computer graphics [S2, book]. It is often compared with object-order techniques like splatting, which may use precomputed resolution levels or octree representations [S2, book].
