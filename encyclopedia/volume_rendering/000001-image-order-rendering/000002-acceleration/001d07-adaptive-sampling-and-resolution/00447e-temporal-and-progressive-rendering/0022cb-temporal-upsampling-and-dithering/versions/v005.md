# Temporal Upsampling and Dithering

Also called: Temporal Upsampling

## Overview
Temporal Upsampling and Dithering is a technique that combines spatial dithering to mitigate sampling artifacts with temporal accumulation to reduce noise, primarily used in real-time volume rendering (such as volumetric clouds) where computational budget limits per-frame sampling density [S1, unofficial]. It distinguishes itself from its siblings by addressing the specific trade-off between spatial aliasing (slicing artifacts from coarse steps) and temporal noise (stochastic variation from dithering), whereas Checkerboard Progressive Rendering focuses on spatial resolution adaptation and Multi-Resolution Rendering for Clouds focuses on hierarchical data structures [4836-checkerboard-progressive-rendering.md][7260-multi-resolution-rendering-for-clouds.md].

## How it works
**Inputs and Outputs:**
*   **Input:** Current frame's color buffer (often at reduced resolution or with coarse sampling), previous frame's accumulated color buffer, and depth/velocity buffers for reprojection.
*   **Output:** High-resolution, denoised color frame.

**Data Structures:**
*   **History Buffer:** A texture storing the accumulated color values from previous frames.
*   **Depth/Velocity Buffers:** Used to reproject the history buffer into the current frame's pixel coordinates.

**Steps:**
1.  **Blue Noise Dithering:** Apply blue noise dithering to the sampling positions or step sizes during the volume integration pass. This breaks up regular aliasing patterns (slicing artifacts) caused by insufficient sampling steps [S1, unofficial].
2.  **Temporal Accumulation:** Reproject the previous frame's color into the current frame's coordinate space using depth and velocity information. Blend the reprojected color with the current frame's dithered result. This reduces the high-frequency noise introduced by the dithering process [S1, unofficial].
3.  **Upsampling:** If the rendering was performed at a lower resolution (e.g., 1/2x1/2), upsample the final accumulated result to the full screen resolution [S1, unofficial].

**Formulas:**
*   **Reprojection:** $C_{reprojected}(x, y) = C_{history}(x - v_x, y - v_y)$, where $(v_x, v_y)$ is the pixel velocity.
*   **Blending:** $C_{final}(x, y) = \alpha \cdot C_{current}(x, y) + (1 - \alpha) \cdot C_{reprojected}(x, y)$, where $\alpha$ is a blending factor (often related to temporal stability or motion speed).

**Parameters:**
*   **Dither Pattern:** Blue noise texture.
*   **Blending Factor $\alpha$:** Typically small (e.g., 0.1-0.3) to favor history, but adjusted based on motion to prevent ghosting.

**Edge Cases and Pitfalls:**
*   **Ghosting:** If depth or velocity is inaccurate, the reprojected history will misalign, causing ghosting artifacts. Anti-smear techniques (discarding history pixels with large depth differences) may be required [3614-temporal-anti-aliasing-with-anti-smear.md].
*   **Streaking:** Blue noise dithering can introduce streaking artifacts if the temporal blending is too aggressive or if the motion is complex [S1, unofficial].

**Pseudocode:**
```python
def temporal_upsampling_and_dithering(current_frame, history_buffer, depth_buffer, velocity_buffer, blue_noise_texture):
    # Step 1: Apply Blue Noise Dithering to the current frame's volume rendering
    # This assumes the volume rendering pass has already produced a noisy color buffer
    dithered_color = apply_blue_noise_dither(current_frame.color, blue_noise_texture)
    
    # Step 2: Reproject the history buffer
    # Calculate the offset based on pixel velocity
    offset_x = velocity_buffer.x * depth_buffer.z
    offset_y = velocity_buffer.y * depth_buffer.z
    
    # Sample the history buffer at the reprojected coordinates
    # Handle boundary checks and invalid depth values
    reprojected_color = sample_history(history_buffer, current_frame.uv + offset)
    
    # Step 3: Blend the current dithered frame with the reprojected history
    # Alpha is determined by motion speed or a fixed temporal weight
    alpha = compute_temporal_alpha(velocity_buffer.magnitude)
    blended_color = mix(dithered_color, reprojected_color, alpha)
    
    # Step 4: Upsample if necessary
    # If the rendering was done at half resolution, upscale to full resolution
    final_color = upscale(blended_color)
    
    # Step 5: Update the history buffer for the next frame
    # Store the blended color for temporal accumulation
    update_history_buffer(history_buffer, final_color)
    
    return final_color
```

## Subtopics

### [Temporal Anti-Aliasing with Anti-Smear](3614-temporal-anti-aliasing-with-anti-smear.md)
Temporal Anti-Aliasing with Anti-Smear is a post-processing technique that blends the current frame's color with an accumulated history buffer using pixel velocity for reprojection, with an optional anti-smear feature that discards accumulated pixels with large depth differences to prevent ghosting. It distinguishes itself from standard TAA by explicitly checking depth discontinuities during reprojection to avoid smearing artifacts.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, dominated by the reprojection and blending steps.
*   **Memory Complexity:** $O(N)$ for storing the history buffer, depth buffer, and velocity buffer.
*   **Performance:** Significantly reduces the need for high per-frame sampling rates, allowing for real-time rendering of complex volumes like clouds [S1, unofficial].
*   **Strengths:** Effective at reducing noise and aliasing artifacts with minimal additional computational cost per frame.
*   **Limitations:** Can introduce ghosting or smearing artifacts if motion estimation is inaccurate or if there are rapid scene changes. Requires careful tuning of the blending factor and anti-smear thresholds.

## Background
The technique is commonly used in real-time graphics engines for rendering volumetric effects such as clouds and fog, where high sampling rates are computationally prohibitive [S1, unofficial]. It builds on the principles of Temporal Anti-Aliasing (TAA) and blue noise dithering, adapting them to the specific challenges of volume rendering.
