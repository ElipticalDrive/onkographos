# Two-pass Adaptive Screen Sampling with Interval Partitioning

Also called: Two-pass Adaptive Undersampling with Interval Partitioning, Two-pass adaptive screen sampling plus partitioning the interval of integration into M pieces

## Overview
This method accelerates volume integral calculation by partitioning the ray integration interval into $M$ equal pieces and using a second pass to interpolate or recompute integrals for pixels based on neighborhood coherence [S1]. It builds on [Adaptive Undersampling](5397-adaptive-undersampling.md) by increasing the adaptive undersampling factor, allowing fewer pixels to be processed in the first pass while maintaining image quality through spatial interpolation in the second pass [S1]. Compared to standard adaptive undersampling, it increases frames per second (FPS) by a factor of 1.5 on average, and provides further acceleration over two-pass adaptive screen sampling without interval partitioning [S1].

## How it works
The method consists of two passes. The first pass computes volume integrals over $M$ equal-length intervals for a subset of pixels (typically one per $n \times n$ block, as defined in the parent article) [S1]. The second pass processes the remaining pixels, using data from the G-buffer of neighboring pixels to either interpolate colors or compute integrals for specific intervals [S1].

### Inputs and Outputs
*   **Inputs**: 3D texture data (volume), transfer function, ray origin $s$, ray end $f$, maximum number of intervals $M$, color difference threshold $\delta$ [S1].
*   **Outputs**: Final pixel color $C_{final}$ and alpha $A_{final}$ for each pixel [S1].

### Data Structures
The G-buffer $G$ stores integration results per pixel [S1]. The layout is defined as follows [S1]:
*   $G[0].rgb$: Final pixel color.
*   $G[0].a$: Distance to the start of the volume (transparency) or background distance.
*   $G[i]$ for $i > 0$: Intermediate integral results for the $i$-th interval. Each $G[i]$ contains:
    *   $G[i].rgb$: Color contribution of the interval.
    *   $G[i].a$: Alpha (opacity) contribution of the interval.

*Note: On hardware with limited G-buffer size (e.g., GTX 780 Ti with 8 elements), multiple integrals can be stored in one element by using only one color component, effectively increasing $M$ [S1].*

### Parameters
*   $M$: User-selected maximum number of intervals for partitioning the ray. Typical value: 8 [S1].
*   $\delta$: Threshold for color difference to determine if bilinear interpolation is sufficient. Typical value: 0.05 [S1].

### Algorithm Steps

#### Pass 1: Interval Partitioning and Integration
For selected pixels (e.g., one per $n \times n$ block):

1.  Calculate the distance to the start of the volume $d_{start}$ using `GetDistanceForStart(s, f)` [S1].
2.  If $d_{start} \le 0$, set $G[0].rgb = BackgroundColor$ and terminate [S1].
3.  Initialize $G = 0$, $i = 0$, accumulated color $C = 0$, accumulated alpha $A = 0$ [S1].
4.  Calculate step size: $step = \sqrt{3} / M$ [S1]. (The longest ray in texture space is $\sqrt{3}$, the diagonal of the unit cube) [S1].
5.  Calculate maximum number of full steps: $imax = \lfloor length(f - s) / step \rfloor$ [S1].
6.  Calculate length of the last interval: $lastStep = length(f - s) - step \times imax$ [S1].
7.  Normalize ray direction: $r = normalize(f - s)$ [S1].
8.  Set current position: $v = s + d_{start} \cdot r$ [S1].
9.  Loop while $A < 1$ and $i \le imax$:
    a. Compute interval integral: $G[i+1] = VolumeIntegral(v, step)$ [S1].
    b. Update accumulated color: $C = C + (1 - A) \cdot G[i+1].rgb \times G[i+1].a$ [S1].
    c. Update accumulated alpha: $A = A + (1 - A) \cdot G[i+1].a$ [S1].
    d. Advance position: $v = v + step \cdot r$ [S1].
    e. Increment $i$ [S1].
10. Handle last shorter interval if $A < 1$ and $lastStep > 0$:
    a. Compute interval integral: $G[i+1] = VolumeIntegral(v, lastStep)$ [S1].
    b. Update accumulated color: $C = C + (1 - A) \cdot G[i+1].rgb \times G[i+1].a$ [S1].
    c. Update accumulated alpha: $A = A + (1 - A) \cdot G[i+1].a$ [S1].
11. Store final color: $G[0].rgb = C$ [S1].

#### Pass 2: Interpolation or Recomputation
For pixels not processed in Pass 1:

1.  Get distance to start for current pixel: $G[0].a = GetDistanceForStart(s, f)$ [S1].
2.  If $G[0].a \le 0$, set $G[0].rgb = BackgroundColor$ and terminate [S1].
3.  Initialize $G = 0$, $i = 0$, $C = 0$, $A = 0$ [S1].
4.  **Optimization**: Determine accelerated start point. Cast ray from $s + r \cdot \min\{G_{neighbor}[0].a\}$ for the 4 neighboring pixels to find the earliest start distance [S1].
5.  Calculate step size: $step = \sqrt{3} / M$ [S1].
6.  Calculate $imax = \lfloor length(f - s) / step \rfloor$ [S1].
7.  Calculate $lastStep = length(f - s) - step \times imax$ [S1].
8.  Normalize ray direction: $r = normalize(f - s)$ [S1].
9.  Set current position: $v = s + G[0].a \cdot r$ [S1].
10. Loop for each interval $k$ from 1 to $imax$:
    a. Check neighborhood coherence. Let $C_{neighbors}$ be the colors of the 4 neighboring pixels [S1].
    b. If $\max(|C_{neighbor} - C_{current}|) < \delta / M$:
        i. Use bilinear interpolation of neighbor colors for this interval's contribution [S1].
        ii. Update $C$ and $A$ using interpolated values [S1].
    c. Else:
        i. Compute integral $I = VolumeIntegral(v, step)$ (or $lastStep$ if $k=imax$) [S1].
        ii. Update $C = C + (1 - A) \cdot I.rgb \times I.a$ [S1].
        iii. Update $A = A + (1 - A) \cdot I.a$ [S1].
    d. Advance position: $v = v + step \cdot r$ [S1].
11. Store final color: $G[0].rgb = C$ [S1].

### Edge Cases and Pitfalls
*   **High Coherence**: Performance decreases if data has high coherence because many pixels are interpolated, reducing the benefit of the second pass [S1].
*   **Low Coherence**: Performance decreases if data has low coherence because many pixels require full recomputation in the second pass [S1]. Optimal performance is at medium coherence [S1].
*   **Early Ray Termination**: If a significant number of rays end early (e.g., bones), acceleration factor decreases because intervals are short and harder to partition [S1].
*   **Precision**: The step size is calculated as $\sqrt{3}/M$. For large $M$, precision issues may arise. The sources note that increasing $M$ beyond 16 is ineffective [S1].

## Subtopics

### [Visibility Prefiltering](6395-visibility-prefiltering.md)
Visibility Prefiltering is a technique used in hierarchical volumetric shadowing to reduce correlated artifacts inherent in Riemann sum integration by storing a distribution of blocker depths rather than a single depth value per integration sample. It approximates the percentage of visibility changes along the angular axis ($\beta$) for each sample, converting structured aliasing into less objectionable noise similar to Monte Carlo sampling while requiring significantly fewer light rays.

## Operating characteristics
*   **Time Complexity**: The method reduces the number of pixels processed in the first pass, but adds a second pass. The complexity depends on the coherence of the data. For medium coherence, it provides significant speedup [S1].
*   **Memory Complexity**: Requires a G-buffer of size $M+1$ per pixel. On hardware with limited G-buffer size (e.g., 8 elements), multiple integrals can be stored in one element [S1].
*   **Measured Performance**: On a 3.4GHz Intel Core i7 2600, 4.0GB RAM, NVidia GForce GTX 780 Ti, at 1200x900 resolution, with dataset (a) 256x256x256:
    *   Standard adaptive undersampling (A): 32 FPS
    *   Two-pass adaptive screen sampling without interval partitioning (B): 72 FPS
    *   Proposed method (C): 118 FPS
    *   Acceleration C/A = 3.69, C/B = 1.64 [S1].
*   **Scaling**: Increasing $M$ from 8 to 16 increases performance by ~21% on average, but further increases are ineffective [S1].
*   **Strengths**: Increases FPS by a factor of 1.5 on average compared to standard adaptive undersampling [S1]. Most efficient when input data has medium coherence and the transfer function excludes early ray termination [S1].
*   **Limitations**: Inherits the limitation of adaptive undersampling: input data must be spatially coherent [S1]. Performance degrades with high or low coherence [S1].

## Background
The method was proposed in "Fast Adaptive Undersampling for Volume Rendering" [S1]. It is implemented in Unity3D using OpenGL ES 3.1 [S1]. The volume integrals were calculated using the standard method [KW03] with 1/4 of the voxel size as the step size. The bounding volume was chosen as a box [S1].
