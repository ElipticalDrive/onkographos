# Adaptive Refinement for Volume Rendering

Also called: Adaptive Refinement Volume Rendering, Image-order adaptive refinement, Interactive Adaptive Refinement, Feedback-based Adaptive Refinement

## Overview
Adaptive Refinement for Volume Rendering is an image-order technique that reduces the number of rays and sampling points by increasing sampling frequency in regions with high color variation (edges) and decreasing it in homogeneous regions, using explicit error control based on Finite Element Method (FEM) theory [S2, unofficial]. It solves the problem of high computational cost in volume ray-casting by iteratively computing approximations of the exact volume rendering solution, refining the image plane only where necessary to maintain visual fidelity [S2, unofficial]. Unlike brute-force ray tracing which casts rays from every pixel immediately, this method casts rays incrementally, allowing for interactive frame rates by focusing computational effort only where necessary [S3]. It is distinguished from [Adaptive Screen Sampling](5838-adaptive-screen-sampling.md) by its use of hierarchical quadtree subdivision and FEM-based error estimation rather than simple variance metrics, and from [Adaptive Ray Shooting & Quadtree Subdivision](8158-adaptive-ray-shooting-quadtree-subdivision.md) by its focus on screen-space (image-order) refinement rather than object-space (voxel) traversal [S2, unofficial].

## How it works
The method operates as a reactive control loop that adjusts the number of rendered cells to maintain a target frame rate while bounding visual error in pixels per texel [S1]. It builds on the shared principles of [Spatial Subdivision and Hierarchical Sampling](10997-spatial-subdivision-and-hierarchical-sampling.md).

### Inputs and Outputs
*   **Inputs:** 3D scalar field data (voxels), transfer function (mapping scalar to color/opacity), camera parameters (view matrix, projection), target frame rate (optional, for feedback control), initial level-of-detail parameters ($romax, romin, \epsilon$ or $m$).
*   **Outputs:** Rendered image (color buffer), error map (optional, for debugging/feedback).

### Data Structures
1.  **Quadtree:** Stores image regions (quadratic cells) on the CPU. Each leaf node represents a cell that can be refined into four children [S2, unofficial].
2.  **Error Map / Ray Density Map ($F$ array):** A boolean or integer array matching the image resolution. White pixels (or flag set) indicate areas computed by ray tracing (high detail/error); black pixels (or flag clear) indicate areas computed by interpolation (low detail/error) [S3].
3.  **Interpolation Flag Map ($G$ array):** A boolean array matching the image resolution. Tracks which pixels have been interpolated in the current frame to avoid redundant interpolation [S3].
4.  **Color Buffer ($C$):** Stores the computed color for each pixel.
5.  **Error Texture (GPU):** A 1D single-channel floating-point texture with $m$ entries, output by the GPU estimator, read back to main memory for marking [S2, unofficial].

### Parameters
*   **$romax$:** Maximum ray density parameter / maximum size of square regions for ray tracing. Range: $1 \le romax \le R$ (image side length). Typical initial value: 16 [S3]. High values cause features to be missed [S3].
*   **$romin$:** Minimum ray density parameter / minimum size of square regions. Subdivision stops when region size reaches $romin$. Range: $1 \le romin \le romax$. Typical initial value: 2 [S3]. High values cause features to be poorly resolved [S3].
*   **$\epsilon$ (e):** Error threshold parameter. If the range of colors in a region is less than $\epsilon$, no further processing is performed. Value: $\epsilon > 0$. Typical initial value: 16-32 [S3]. High values cause features to be ignored [S3].
*   **$m$:** Fixed number of cells to mark for refinement in each iteration (FEM-based method). User-adjustable. Typical value: 1000 [S2, unofficial].
*   **$W$:** Number of evenly spaced locations along a ray where data is resampled.
*   **$p$:** Polynomial degree for interpolation during reconstruction. Fixed value: 2 (bilinear/quadratic interpolation) [S2, unofficial].
*   **target_frame_rate:** Desired frame rate budget for the feedback loop. Typical value: 10 fps [S1].
*   **error_threshold:** Maximum allowable visual error metric. Typical value: 1 pixel per texel [S1].

### Formulas
The volume rendering integral along a ray parametrized by arc length $w^x$ of length $L^x$ is [S2, unofficial]:
$$ I(x) = \int_0^{L^x} E(w^x) \exp\left(-\int_0^t A(w^x) ds\right) dt $$
where $E$ is emission and $A$ is absorption.

The approximation error is measured using the $L^2$ error norm [S2, unofficial]:
$$ \boldsymbol{\eta} = \|u - u_n\|_S := \left( \int_S (u - u_n)^2 dx \right)^{\frac{1}{2}} $$
where $u$ is the exact solution on the viewport $S$ and $u_n$ is the approximative solution.

The nodal interpolant is [S2, unofficial]:
$$ \mathcal{I}_n(u) = \sum_{q \in \mathcal{Q}} u(q) \Phi_q $$
where $\mathcal{Q}$ is the set of evaluation points and $\Phi_q$ are the basis functions.

The approximative solution function is [S2, unofficial]:
$$ u_n = \sum_{q \in \mathcal{Q}} I_h(q) \Phi_q $$
where $I_h(q)$ is the approximation of the volume rendering integral at point $q$.

The total approximation error is bounded by [S2, unofficial]:
$$ \boldsymbol{\eta} = \|\boldsymbol{u} - \boldsymbol{u}_n\|_S \leq \|\boldsymbol{u} - \mathcal{I}_n(\boldsymbol{u})\|_S + \|\mathcal{I}_n(\boldsymbol{u}) - \boldsymbol{u}_n\|_S $$

The local error contribution on each cell $T \in \mathcal{T}_n$ is estimated by comparing two subsequent approximations [S2, unofficial]:
$$ \eta_{V_n}^T \approx \|u_{n-1} - u_n\|_T = \left( \int_T (u_{n-1} - u_n)^2 dx \right)^{\frac{1}{2}} $$
This integral is solved numerically using a Gaussian quadrature rule with $N=3$ points [S2, unofficial].

Relative $L^2$ error is [S2, unofficial]:
$$ \eta_{rel} = \|u - u_n\|_S / \|u\|_S $$

### Steps
The algorithm iteratively computes approximations $u_n$ of the exact solution $u$ [S2, unofficial].

1.  **Initialization:**
    *   Initialize level-of-detail parameters: $romax := Firstromax()$, $romin := Firstromin()$, $e := Firste()$ [S3].
    *   Initialize flags $F(u,v) := 0$, $G(u,v) := 0$, and colors $C(u,v) := 0$ for all pixels [S3].
    *   Initialize Quadtree with a single root node covering the entire image [S2, unofficial].

2.  **Ray Tracing (Adaptive Subdivision):**
    *   Divide image into square regions of size $romax$.
    *   For each region starting at $(u,v)$, call `RayTraceRegion(u,v,romax,romin,e)` [S3].
    *   **RayTraceRegion(u,v,w,wmin,e):**
        *   Cast rays from the four corner pixels of the current region (size $w$). For $j=0$ to $w$ by $w$, for $i=0$ to $w$ by $w$:
            *   If pixel $(u+i, v+j)$ is within bounds and flag $F(u+i,v+j)$ is clear:
                *   Trace ray using standard volume rendering (resample data at $W$ evenly spaced locations, tri-linear interpolation, composite with fully opaque background) [S3].
                *   Set $F(u+i,v+j) := 1$ [S3].
        *   If $w > wmin$ AND `Difference(u,v,w,e)` is true:
            *   Divide region into four subregions of size $w/2$.
            *   Recursively call `RayTraceRegion` for each subregion [S3].
    *   **Difference(u,v,w,e):** Checks if the range of intensity values for any color component (R, G, or B) of the colors at the four corners of the specified region exceeds $\epsilon$ [S3].

3.  **Interpolation (Image Formation):**
    *   Divide image into square regions of size $romax$.
    *   For each region starting at $(u,v)$, call `InterpolateRegion(u,v,romax)` [S3].
    *   **InterpolateRegion(u,v,w):**
        *   Interpolate colors at midpoints of sides and center of the current region (size $w$). For $j=0$ to $w$ by $w/2$, for $i=0$ to $w$ by $w/2$:
            *   If pixel $(u+i, v+j)$ is within bounds and flags $F(u+i,v+j)$ and $G(u+i,v+j)$ are clear:
                *   Call `Interpolate(u,v,w,u+i,v+j)`.
                *   Set $G(u+i,v+j) := 1$ [S3].
        *   If $w/2 > 1$:
            *   Divide region into four subregions of size $w/2$.
            *   Recursively call `InterpolateRegion` for each subregion [S3].
    *   **Interpolate(u,v,w,x,y):** Computes color for pixel $(x,y)$ using linear interpolation (for region boundary midpoints) or bi-linear interpolation (for region centers) based on available colors in the region [S3].

4.  **Display:**
    *   Display the interpolated image [S3].

5.  **Cleanup:**
    *   After display, for all pixels $(u,v)$, if flag $F(u,v)$ is clear, set $C(u,v) := 0$ and $G(u,v) := 0$ [S3].

6.  **Adaptation (Feedback or Error-Based):**
    *   **Feedback-based (S1):**
        *   Monitor current frame rate.
        *   Compare measured frame rate to target budget.
        *   If frame rate exceeds budget, incrementally add more cells (decrease $romax$ or refine quadtree) to the rendering.
        *   If maximum error metric (pixels per texel) is below threshold, skip refinement to save cost.
        *   Stop adding cells once maximum error drops below quality threshold.
    *   **Error-based (S2):**
        *   Estimate error $\eta_T$ for each new quadtree leaf using FEM estimator (Equation 9).
        *   Mark a fixed number $m$ of cells with the biggest impact on total error $\eta$ using a heap data structure. Sorting cost is $O(m \log n)$ where $n$ is number of leaves [S2, unofficial].
        *   Refine marked cells by creating four new quadtree leaves per marked cell, generating new evaluation points (center + 4 edge midpoints) [S2, unofficial].
        *   Compute volume rendering integral approximation for new evaluation points. Use **Step Doubling** for ray integration error control: compute color with full stepsize $h$ and two half steps $h/2.0$. If squared difference < error bound, accept step and increase $h$; otherwise decrease $h$ and repeat [S2, unofficial].
        *   Reconstruct approximation $u_n$ using polynomial degree $p=2$ and render to screen [S2, unofficial].
        *   Repeat until convergence (e.g., error $< 10^{-2}$) or user interrupt.

7.  **Increment Level-of-Detail (S3 specific):**
    *   Update parameters: $romax := Nextromax()$, $romin := Nextromin()$, $e := Nexte()$ [S3].
    *   Loop until $romax = 1$ (full resolution) or convergence criteria met [S3].

### Edge Cases and Pitfalls
*   **Manual Parameter Selection:** Manual selection of $romax, romin, \epsilon$ can lead to sub-optimal presentation. Inappropriate values cause features to be missed, ignored, or poorly resolved, and result in unequal intervals between successive frames [S3].
*   **Interactivity Interruption:** The loop is interrupted whenever the camera moves or the transfer function changes to guarantee interactivity [S2, unofficial].
*   **Feedback Latency:** Reactive feedback introduces scheduling latency; proactive scheduling using system timing parameters like fill rates is recommended to reduce reliance on feedback [S1].
*   **Precision:** Step doubling for ray integration requires careful handling of floating-point precision to accurately estimate the difference between full and half steps [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time grows linearly with dataset size for full ray tracing, but adaptive refinement reduces effective cost by casting fewer rays in smooth regions [S3]. Marking complexity is $O(m \log n)$ for sorting quadtree leaves using a heap, where $m$ is number of marked cells and $n$ is number of leaves [S2, unofficial].
*   **Memory Complexity:** Quadtree data structures stored on CPU. Error texture is $O(m)$ on GPU [S2, unofficial].
*   **Measured Performance:**
    *   **S2:** 7 iterations needed for approximation error $10^{-2}$ on Mixing Layer dataset with initial grid 256x256 and $m=1000$. Single iteration takes 20-40 ms for screen resolutions 512x512 and 2048x2048 respectively. Hardware: Intel Core 2 Duo CPU 3.0 GHz, NVIDIA GeForce 8800GT GPU [S2, unofficial].
    *   **S3:** Cytochrome dataset (113 slices of 256x256): Frame 1 took 4.6 seconds with 3,870 image rays (20% coverage). Frame 4 took 25.7 seconds total with 19,289 rays (100% coverage). Head dataset (CT scan, 113 slices of 256x256): Frame 1 took 13 seconds with 5,179 rays (16% coverage). Frame 4 took 104 seconds total with 30,603 rays (100% coverage). Performance on Cytochrome B5 (123x123x123 voxels) on Sun 4/280: Four-frame sequence generated, with subsequent images appearing at intervals of approximately five seconds each [S3].
    *   **S1:** Tested on a GeForce3 GPU without register combiners; frame rate fluctuated above the 10 fps budget, and the system successfully added cells to reduce error below 1 pixel/texel [S1].
*   **Scaling:** The method scales well with resolution due to the adaptive nature, focusing computation on high-error regions.
*   **Strengths:** Reduces number of rays and sampling points while maintaining visual fidelity. Provides explicit error control. Interactive frame rates possible.
*   **Limitations:** Reactive feedback introduces latency. Manual parameter tuning can be difficult. Interactivity is interrupted on camera/transfer function changes.

## Background
*   **Origin:** The concept of adaptive refinement in volume rendering was introduced by [Lev90] (Levoy), who proposed adaptive image-space subdivision combined with progressive image generation for performance improvement [S2, unofficial][S3].
*   **Development:** [S2, unofficial] (Hadwiger et al.) extended this by introducing an error estimator founded in Finite Element Method (FEM) theory, providing a well-founded theory for convergence analysis and explicit error control. This method uses h-adaptivity (subdividing image regions) rather than p-adaptivity (increasing polynomial degree) because real volume data often has discontinuities [S2, unofficial].
*   **Usage:** Demonstrated in interactive exploration paths for unstructured grids [S1], medical imaging (CT scans) [S2, unofficial][S3], and molecular graphics (cytochrome) [S3]. Implemented in C++ and OpenGL/GLSL requiring Shader Model 4.0 GPU [S2, unofficial].
