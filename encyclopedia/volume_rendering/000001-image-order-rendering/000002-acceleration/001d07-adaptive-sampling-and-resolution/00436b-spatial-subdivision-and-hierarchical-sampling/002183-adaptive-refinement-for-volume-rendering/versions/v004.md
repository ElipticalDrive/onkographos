# Adaptive Refinement for Volume Rendering

Also called: Adaptive Refinement Volume Rendering, Image-order adaptive refinement, Interactive Adaptive Refinement, Feedback-based Adaptive Refinement

## Overview

Adaptive Refinement for Volume Rendering is an image-order technique that balances rendering quality and performance by iteratively refining the image resolution based on local error estimates [S2, unofficial][S3]. It solves the problem of high computational cost in volume ray-casting by casting rays non-uniformly, focusing computational effort on regions with high color variation (edges, silhouettes) while relying on interpolation in homogeneous regions [S2, unofficial][S3]. Unlike brute-force ray tracing which casts rays from every pixel immediately, this method starts with a coarse approximation and incrementally adds rays, allowing for interactive frame rates during exploration [S3]. It differs from [Two-stage NeRF Rendering](925-two-stage-nerf-rendering.md) by using explicit geometric error control (FEM-based or corner-difference) rather than neural network uncertainty, and from [Random Pixel Subsampling](1668-random-pixel-subsampling.md) by using deterministic, error-guided refinement rather than stochastic sampling [S2, unofficial][S3].

## How it works

### Inputs and Outputs
*   **Inputs:** 3D scalar field (voxel grid), camera parameters (position, orientation, projection), transfer function (mapping scalar values to color/opacity), and control parameters (target frame rate, error thresholds, initial ray density).
*   **Outputs:** A rendered 2D image on the screen, progressively refined over time.

### Data Structures

1.  **Quadtree (CPU/GPU Hybrid):** Stores image regions as quadratic cells. Each leaf node represents a cell that can be subdivided into four children. Used to track which regions have been fully refined [S2, unofficial].
2.  **Error Map / Ray Density Map (F Array):** A 2D array of flags corresponding to the image plane.
    *   `F(u,v) = 1`: Ray has been traced for pixel `(u,v)` (high detail/error region).
    *   `F(u,v) = 0`: Pixel color is derived from interpolation (low detail/error region) [S3].
3.  **Interpolation Flag Map (G Array):** A 2D array of flags.
    *   `G(u,v) = 1`: Color at `(u,v)` has been computed via interpolation [S3].
4.  **Error Texture (GPU):** A 1D single-channel floating-point texture with $m$ entries, storing the estimated error for the $m$ most significant quadtree leaves. Output by the GPU estimator, read back to main memory for marking [S2, unofficial].
5.  **Heap:** A data structure on quadtree leaves used to select the $m$ cells contributing most to the total error. Updated each time new leaves are created [S2, unofficial].

### Parameters

*   **romax:** Maximum size of square regions (in pixels) into which the image is divided for ray tracing and interpolation. Range: $1 \le \text{romax} \le R$ (image side length). Typical initial value: 16 [S3]. High values cause features to be missed [S3].
*   **romin:** Minimum size of square regions. Subdivision stops when region size reaches romin. Range: $1 \le \text{romin} \le \text{romax}$. Typical initial value: 2 [S3]. High values cause features to be poorly resolved [S3].
*   **epsilon (e):** Error threshold parameter. If the range of colors in a region is less than $e$, no further processing is performed. Value: $e > 0$. Typical initial value: 16–32 [S3]. High values cause features to be ignored [S3].
*   **m:** Fixed number of cells to mark for refinement in each iteration (FEM-based method). Typical value: 1000 [S2, unofficial].
*   **target_frame_rate:** Desired frame rate budget for the feedback loop. Typical value: 10 fps [S1].
*   **error_threshold:** Maximum allowable visual error metric. Typical value: 1 pixel per texel [S1].
*   **W:** Number of evenly spaced locations along a ray where data is resampled [S3].
*   **p:** Polynomial degree for interpolation during reconstruction. Fixed value: 2 (bilinear/quadratic) [S2, unofficial].

### Formulas

**Volume Rendering Integral:**
The radiance $I(x)$ along a ray parametrized by arc length $w^x$ of length $L^x$ is:
$$ I(x) = \int_0^{L^x} E(w^x) \exp\left(-\int_0^t A(w^x) ds\right) dt \quad \text{[S2, unofficial]} $$
where $E$ is emission and $A$ is absorption.

**Approximation Error (FEM-based):**
The total approximation error is measured using the $L^2$ error norm:
$$ \boldsymbol{\eta} = \|u - u_n\|_S := \left( \int_S (u - u_n)^2 dx \right)^{\frac{1}{2}} \quad \text{[S2, unofficial]} $$
where $u$ is the exact solution on the viewport $S$ and $u_n$ is the approximative solution.

**Local Error Estimation:**
The local error contribution on each cell $T$ is estimated by comparing two subsequent approximations:
$$ \eta_{V_n}^T \approx \|u_{n-1} - u_n\|_T = \left( \int_T (u_{n-1} - u_n)^2 dx \right)^{\frac{1}{2}} \quad \text{[S2, unofficial]} $$
This integral is solved numerically using a Gaussian quadrature rule with $N=3$ points [S2, unofficial].

**Relative L2 Error:**
$$ \eta_{rel} = \|u - u_n\|_S / \|u\|_S \quad \text{[S2, unofficial]} $$

### Steps

The method operates as an iterative loop. Two primary variants exist: the **FEM-based Adaptive Screen-Space Sampling** [S2, unofficial] and the **Recursive Corner-Difference Refinement** [S3].

#### Variant 1: FEM-based Adaptive Refinement [S2, unofficial]

1.  **Initialize:** Start with a coarse uniform grid (quadtree root).
2.  **Estimate Error:** For each new quadtree leaf, estimate the local error $\eta_T$ using the hierarchical a-posteriori error estimator (Equation 9) [S2, unofficial].
3.  **Mark Cells:** Use a heap to select the $m$ cells with the biggest impact on the total error $\eta$. Sorting cost is $O(m \log n)$ [S2, unofficial].
4.  **Refine:** Subdivide the marked cells into four new quadtree leaves. This generates new evaluation points: one at the cell's center and four at the midpoints of the cell's edges. At least one sample (center) is computed per new leaf. Samples are never computed twice [S2, unofficial].
5.  **Ray Casting (Step Doubling):** For each new evaluation point, perform standard ray-casting. To control integration error, use step doubling:
    *   Compute color with full step size $h$.
    *   Compute color with two half steps $h/2.0$.
    *   If squared difference < error bound, accept step and increase $h$. Otherwise, decrease $h$ and repeat [S2, unofficial].
6.  **Reconstruct:** Reconstruct the approximation $u_n$ on a uniform grid using polynomial degree $p=2$ (bilinear interpolation) and render to screen [S2, unofficial].
7.  **Repeat:** Loop until convergence to pixel accuracy or user-specified error bound. Interrupt if camera or transfer function changes [S2, unofficial].

#### Variant 2: Recursive Corner-Difference Refinement [S3]

1.  **Initialize:** Set `romax`, `romin`, and `epsilon` (e). Initialize flags `F` and `G` to 0. Clear color buffer `C` [S3].
2.  **Loop:** While `romax > 1`:
    a.  **Ray Trace:** Call `RayTraceData(romax, romin, e)`.
        *   Divide image into square regions of size `romax`.
        *   For each region, call `RayTraceRegion(u, v, romax, romin, e)`.
        *   `RayTraceRegion(u, v, w, wmin, e)`:
            *   Cast rays from the four corner pixels of the current region (size $w$).
            *   For each corner $(u+i, v+j)$, if within bounds and `F(u+i, v+j)` is clear, trace ray and set `F(u+i, v+j) := 1`.
            *   Ray Tracing: Resample data at $W$ evenly spaced locations. Tri-linearly interpolate from 8 surrounding voxels. Composite with fully opaque background to yield color $C(u)$ [S3].
            *   If $w > wmin$ AND `Difference(u, v, w, e)` is true, divide region into four subregions of size $w/2$ and recursively call `RayTraceRegion` for each.
            *   `Difference(u, v, w, e)`: Check if the range of intensity values for any color component (R, G, B) of the colors at the four corners of the region exceeds $e$ [S3].
    b.  **Interpolate:** Call `InterpolateImage(romax)`.
        *   Divide image into square regions of size `romax`.
        *   For each region, call `InterpolateRegion(u, v, romax)`.
        *   `InterpolateRegion(u, v, w)`:
            *   Interpolate colors at midpoints of sides and center of the current region (size $w$).
            *   For each point $(u+i, v+j)$, if within bounds and `F(u+i, v+j)` and `G(u+i, v+j)` are clear, call `Interpolate(u, v, w, u+i, v+j)` and set `G(u+i, v+j) := 1`.
            *   `Interpolate`: Compute color using linear interpolation (for boundary midpoints) or bi-linear interpolation (for region centers) [S3].
            *   If $w/2 > 1$, divide region into four subregions of size $w/2$ and recursively call `InterpolateRegion` for each.
    c.  **Display:** Show the interpolated image.
    d.  **Clear:** For all pixels $(u,v)$, if `F(u,v)` is clear, set `C(u,v) := 0` and `G(u,v) := 0` [S3].
    e.  **Increment:** Update parameters: `romax := Nextromax()`, `romin := Nextromin()`, `e := Nexte()` [S3].

### Pseudocode (Variant 2: Recursive Corner-Difference)

# Global state

G = 2D array of booleans initialized to False
C = 2D array of colors initialized to 0
image_width, image_height = R, R

    romax = Firstromax()
    romin = Firstromin()
    e = Firste()
    
    while romax > 1:
        RayTraceData(romax, romin, e)
        InterpolateImage(romax)
        DisplayImage()
        
        # Clear interpolated colors for next iteration
        for v in range(image_height):
            for u in range(image_width):

        romax = Nextromax()

    for v in range(0, image_height, romax):
        for u in range(0, image_width, romax):
            RayTraceRegion(u, v, romax, romin, e)

def RayTraceRegion(u, v, w, wmin, e):
    # Cast rays from four corners
    for j in range(0, w, w):
        for i in range(0, w, w):
            px, py = u + i, v + j
            if 0 <= px < image_width and 0 <= py < image_height and not F[px][py]:
                C[px][py] = RayTrace(px, py)
                F[px][py] = True
    
    # Subdivide if necessary
    if w > wmin and Difference(u, v, w, e):
        half_w = w // 2
        for j in range(0, half_w, half_w):
            for i in range(0, half_w, half_w):
                RayTraceRegion(u + i, v + j, half_w, wmin, e)

def Difference(u, v, w, e):
    # Check corners of the region
    corners = [
        (u, v),
        (u + w, v),
        (u, v + w),
        (u + w, v + w)
    ]
    min_color = [255, 255, 255]
    max_color = [0, 0, 0]
    
    for cx, cy in corners:
        if 0 <= cx < image_width and 0 <= cy < image_height:
            color = C[cx][cy]
            for k in range(3):
                if color[k] < min_color[k]: min_color[k] = color[k]
                if color[k] > max_color[k]: max_color[k] = color[k]
                
    for k in range(3):
        if max_color[k] - min_color[k] > e:
            return True
    return False

    points = [
        (u + half_w, v),       # Top midpoint
        (u + w, v + half_w),  # Right midpoint
        (u + half_w, v + w),  # Bottom midpoint
        (u, v + half_w),      # Left midpoint
        (u + half_w, v + half_w) # Center
    ]
    
    for px, py in points:
        if 0 <= px < image_width and 0 <= py < image_height and not F[px][py] and not G[px][py]:
            C[px][py] = Interpolate(u, v, w, px, py)
            G[px][py] = True
            
    # Recurse if region is large enough
    if half_w > 1:
        for j in range(0, half_w, half_w):
            for i in range(0, half_w, half_w):

### Edge Cases and Pitfalls

*   **Manual Parameter Selection:** Manual selection of `romax`, `romin`, and `epsilon` can lead to sub-optimal presentation. Inappropriate values cause features to be missed, ignored, or poorly resolved, and result in unequal intervals between successive frames [S3].
*   **Interactivity Interruption:** The loop is interrupted whenever the camera moves or the transfer function changes to guarantee interactivity. This may leave the image in a partially refined state [S2, unofficial].
*   **Reactive Feedback Latency:** Reactive feedback (monitoring frame rate) introduces scheduling latency. Proactive scheduling using system timing parameters like fill rates is recommended to reduce reliance on feedback [S1].
*   **Levoy's Estimator Flaw:** Unlike Levoy's estimator which uses variance of corner pixels (sensitive to edges but causing unnecessary refinement in linear regions with strong slopes), this method's hierarchical estimator notices good approximation in linear regions and focuses on interior edges [S2, unofficial].

## Operating characteristics

*   **Time Complexity:** Rendering time grows linearly with dataset size for full ray tracing, but adaptive refinement reduces effective cost by casting fewer rays in smooth regions [S3]. Marking complexity is $O(m \log n)$ for sorting quadtree leaves using a heap, where $m$ is the number of marked cells and $n$ is the number of leaves [S2, unofficial].
*   **Memory Complexity:** Requires storage for the quadtree data structure (CPU) and error textures (GPU). The error texture is a 1D single-channel floating-point texture with $m$ entries [S2, unofficial].
*   **Measured Performance:**
    *   **FEM-based:** On Intel Core 2 Duo 3.0 GHz, NVIDIA GeForce 8800GT GPU, 7 iterations needed for approximation error $10^{-2}$ on Mixing Layer dataset (initial grid 256x256, m=1000). Single iteration takes 20-40 ms for screen resolutions 512x512 and 2048x2048 respectively [S2, unofficial].
    *   **Recursive:** On Sun 4/280, Cytochrome B5 dataset (123x123x123 voxels): Frame 1 took 4.6 seconds with 3,870 rays (20% coverage). Frame 4 took 25.7 seconds total with 19,289 rays (100% coverage). Head dataset (CT scan, 113 slices of 256x256): Frame 1 took 13 seconds with 5,179 rays (16% coverage). Frame 4 took 104 seconds total with 30,603 rays (100% coverage) [S3].
    *   **Feedback-based:** Tested on GeForce3 GPU, frame rate fluctuated above 10 fps budget, system successfully added cells to reduce error below 1 pixel/texel [S1].
*   **Strengths:** Faster convergence (fewer rays for desired quality) compared to uniform discretization. Interactive frame rates by focusing computational effort only where necessary.
*   **Limitations:** Reactive feedback introduces latency. Manual parameter tuning can be difficult. Interactivity is interrupted on camera/transfer function changes.
*   **When to Use:** Interactive exploration of large volume datasets where immediate feedback is required, and the scene is static or changes slowly.
*   **When Not to Use:** When high-frequency transfer functions are desired and p-adaptivity would be more effective (though real data often has discontinuities preventing this) [S2, unofficial]. When proactive scheduling is critical to avoid feedback latency [S1].

## Background

*   **Origin:** The concept of adaptive image-space subdivision for volume rendering was introduced by Marc Levoy in 1990 [Lev90], who used a simple error measure based on corner pixel variance [S2, unofficial][S3].
*   **Development:**
    *   **1988:** Upson and Mueller proposed recursive bi-linear interpolation for adaptive refinement [S3].
    *   **2011:** Hadwiger et al. introduced Adaptive Screen-Space Sampling for Volume Ray-Casting, using FEM-based error estimation and GPU implementation [S2, unofficial].
    *   **2002:** Leven et al. demonstrated interactive visualization of unstructured grids using hierarchical 3D structures with feedback-based frame rate control [S1].
*   **Usage:** Implemented in C++ and OpenGL/GLSL requiring Shader Model 4.0 GPU. Work distributed between CPU (data structures) and GPU (error estimation, raycasting, reconstruction) [S2, unofficial]. Demonstrated in interactive exploration paths around models like Blunt Fin, Cytochrome B5, and CT Head Scan [S1, S3].
