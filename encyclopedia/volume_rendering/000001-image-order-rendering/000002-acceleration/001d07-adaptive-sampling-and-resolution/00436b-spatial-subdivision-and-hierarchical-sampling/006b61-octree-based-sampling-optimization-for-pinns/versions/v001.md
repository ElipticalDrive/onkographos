# Octree-based Sampling Optimization for PINNs

Also called: Octree-based hierarchical sampling optimization for PINNs

## Overview
An importance sampling strategy for training Physics-Informed Neural Networks (PINNs) that partitions the spatio-temporal domain using an octree to reduce the number of sample points required for convergence [S1]. Unlike volumetric super-resolution methods that require computing intersection spaces for unknown ground truth, this method operates solely within specific areas where limited training data exists, making it suitable for scientific data with sparse observations [S1]. It sets itself apart from sibling methods by explicitly modeling the importance distribution of training data via octree leaf nodes as indivisible subblocks, rather than relying on continuous gradient metrics or screen-space heuristics [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Limited training data in a specific area of interest (e.g., cylinder wake); Physics-Informed Neural Network (PINN) architecture; PDE equations with unknown parameters; total loss threshold for bottleneck detection.
*   **Outputs:** Trained PINN model; optimized sampling distribution defined by the octree structure.

**Data Structures:**
*   **Octree:** A hierarchical spatial subdivision of the spatio-temporal domain.
    *   **Root:** Represents the entire domain of interest.
    *   **Internal Nodes:** Represent sub-volumes.
    *   **Leaf Nodes:** Represent indivisible subblocks. Each leaf node corresponds to a specific region in the spatio-temporal grid where sampling occurs sequentially.
    *   **Layout:** Standard octree structure where each node has up to 8 children. The depth is determined by the convergence level of the training data or a predefined resolution limit.

**Parameters:**
*   $q$: Parameter controlling octree reconstruction frequency.
    *   $q=0$: Reconstruct octree immediately after every epoch.
    *   $q=5$: Start bottleneck evaluation from the 5th epoch, using loss values of the last 5 epochs for linear regression to determine reconstruction timing.
    *   $q=+\infty$: Never reconstruct the octree (use initial structure forever).
    *   Typical value: $q=5$ [S1].

**Algorithm Steps:**
1.  **Initialization:** Initialize the first octree based on the limited training data available in the specific area of interest [S1].
2.  **Initial Training:** Train the PINN using importance sampling of input coordinates from the beginning, guided by the initialized octree. Sampling is performed sequentially in each indivisible subblock corresponding to each leaf node of the octree within the entire domain [S1].
3.  **Bottleneck Detection:** Monitor the total loss during training. When the total loss reaches a bottleneck (plateaus or fails to decrease significantly), trigger octree reconstruction [S1].
4.  **Loss Distribution Computation:** Compute the loss value at each coordinate in the spatio-temporal grid according to the current best model [S1]. This involves evaluating the PINN's residual (PDE loss) and data loss (if applicable) at a set of grid points.
5.  **Octree Reconstruction:** Rebuild the octree based on the computed loss distribution to reflect the new importance distribution of the training data. Regions with higher loss (higher importance) are subdivided further [S1].
6.  **Iterative Training:** Resume training with the new octree structure, performing importance sampling sequentially in the new leaf nodes [S1].
7.  **Repeat:** Repeat steps 3-5 whenever the total loss reaches a bottleneck to avoid the failure of importance sampling due to outdated importance distributions [S1].

**Pseudocode:**
```python
def train_pinn_octree(training_data, pde_equations, network, q):
    """
    Train PINN using octree-based sampling optimization.
    
    Args:
        training_data: Limited training data in specific area.
        pde_equations: PDE equations with unknown parameters.
        network: PINN architecture.
        q: Reconstruction frequency parameter.
        
    Returns:
        trained_network: The trained PINN model.
    """
    # Step 1: Initialize octree based on limited training data
    octree = initialize_octree(training_data)
    
    # Step 2: Initial training with importance sampling
    current_epoch = 0
    total_loss_history = []
    
    while not convergence_criteria_met(network):
        # Perform importance sampling based on current octree
        # Sampling is sequential in each indivisible subblock (leaf node)
        sample_points = sample_from_octree(octree)
        
        # Train network for one epoch
        loss = train_epoch(network, sample_points, training_data, pde_equations)
        total_loss_history.append(loss)
        current_epoch += 1
        
        # Step 3: Bottleneck detection and reconstruction logic
        if should_reconstruct(q, current_epoch, total_loss_history):
            # Step 4: Compute loss distribution on spatio-temporal grid
            # Evaluate current best model on a grid covering the domain of interest
            grid_points = generate_spatio_temporal_grid(domain_of_interest)
            loss_distribution = compute_loss_distribution(network, grid_points, pde_equations, training_data)
            
            # Step 5: Rebuild octree based on loss distribution
            octree = rebuild_octree(loss_distribution, domain_of_interest)
            
            # Note: Reconstruction is time-consuming; frequent reconstruction (q=0) 
            # increases training time significantly (e.g., by 105.45%) [S1].
            
    return network

def should_reconstruct(q, current_epoch, total_loss_history):
    """
    Determine if octree reconstruction should occur based on q and loss history.
    """
    if q == 0:
        # Reconstruct immediately after every epoch
        return True
    elif q == float('inf'):
        # Never reconstruct
        return False
    else:
        # Start bottleneck evaluation from q-th epoch
        if current_epoch < q:
            return False
        
        # Use loss values of the last q epochs for linear regression
        # to detect if loss has reached a bottleneck
        recent_losses = total_loss_history[-q:]
        # Linear regression to check for plateau
        # If slope is near zero or loss variance is low, consider it a bottleneck
        # Implementation detail: [G] Simple heuristic: if max(recent_losses) - min(recent_losses) < threshold
        threshold = 1e-4 # Example threshold, specific value not given in sources
        if max(recent_losses) - min(recent_losses) < threshold:
            return True
        return False

def compute_loss_distribution(network, grid_points, pde_equations, training_data):
    """
    Compute the loss value at each coordinate in the spatio-temporal grid.
    """
    loss_values = []
    for point in grid_points:
        # Compute PDE residual loss
        pde_loss = compute_pde_residual(network, point, pde_equations)
        # Compute data loss if point is in training data area
        data_loss = compute_data_loss(network, point, training_data)
        # Total loss
        total_loss = pde_loss + data_loss
        loss_values.append(total_loss)
    return loss_values

def sample_from_octree(octree):
    """
    Perform importance sampling sequentially in each indivisible subblock (leaf node).
    """
    samples = []
    for leaf_node in octree.get_leaf_nodes():
        # Sample points within the leaf node's subblock
        # Importance is proportional to the volume or predefined weight of the leaf
        points = sample_in_subblock(leaf_node)
        samples.extend(points)
    return samples
```

**Edge Cases and Pitfalls:**
*   **No Reconstruction ($q=+\infty$):** The variance-based initial octree gradually fails to represent the importance distribution of training data, leading to no promotion in prediction performance [S1].
*   **Frequent Reconstruction ($q=0$):** Increases training time significantly (by 105.45% in experiments) because reconstruction is time-consuming, even though it reduces sample points [S1].
*   **Downsampling:** To reduce the time for rebuilding the loss distribution, the training data may be downsampled, but a larger downsampling factor affects the performance of the reconstructed octree [S1].
*   **Hyperparameter Sensitivity:** The minimum number of epochs for each stage of training is a key hyperparameter; determining it reasonably according to the specific application is an open problem [S1].

## Operating characteristics
*   **Time Complexity:** The method relies on time-consuming computation of the loss distribution for octree reconstruction, which limits the dramatic saving of training time despite sample point reduction [S1]. Frequent reconstruction (e.g., $q=0$) increases training time by 105.45% [S1].
*   **Memory Complexity:** Depends on the depth and branching factor of the octree. The octree structure itself is lightweight compared to the network weights, but storing the loss distribution on the spatio-temporal grid requires memory proportional to the grid resolution [S1].
*   **Measured Performance:** On 2D Navier-Stokes equations, the method achieved L2 relative error improvements of 33.33% on $u$, 31.58% on $v$, 75.76% on $p$, 25.86% on $\lambda_1$, and 22.00% on $\lambda_2$ compared to original PINNs, using only 78.40% of sample points [S1].
*   **Scaling:** The method is effective for problems with limited training data in specific areas. It scales with the complexity of the spatio-temporal domain and the frequency of octree reconstruction [S1].
*   **Strengths:** Reduces the total number of sampling points required for convergence; improves prediction accuracy with fewer samples; avoids computing intersection spaces required in volumetric super-resolution [S1].
*   **Limitations:** Training time savings are not as dramatic as sample point reductions due to the cost of octree reconstruction; sensitive to the choice of $q$ and downsampling factors; requires careful tuning of the minimum number of epochs per stage [S1].
*   **When to Use:** When training PINNs with limited training data in specific areas of interest, and when reducing the number of network evaluations (sample points) is a priority over absolute training time.
*   **When Not to Use:** When training time is the primary concern and the cost of octree reconstruction outweighs the benefits of reduced sampling; when the domain is fully observed with abundant training data, making importance sampling less critical.

## Background
*   **Origin:** Proposed in "Octree-based hierarchical sampling optimization for the volumetric super-resolution of scientific data" (2024) [S1].
*   **History and Development:** The method addresses the challenge of training PINNs efficiently with sparse data. It builds on the concept of importance sampling in PINNs, where sample points are concentrated in regions of high error or complexity. The use of an octree allows for hierarchical partitioning of the domain, enabling adaptive sampling. The method distinguishes itself from volumetric super-resolution by operating only in areas with existing training data, avoiding the need for intersection space computations [S1].
*   **Usage:** Applied to scientific data problems, such as incompressible flow past a circular cylinder (2D Navier-Stokes equations) [S1].
