# Adaptive Ray Shooting & Quadtree Subdivision

Also called: Adaptive quadtree subdivision, Image context based probability distribution

## Overview
Adaptive Ray Shooting & Quadtree Subdivision is a general strategy to accelerate the training of radiance field-based methods by reducing ray redundancy during volume rendering [S1]. It solves the problem of excessive computational cost in multi-view volume rendering by dynamically adjusting the number of rays cast per pixel based on local image complexity [S1]. Unlike specialized architectures such as Plenoxels, TensoRF, or Instant-NGP that require specific data structures like sparse voxel grids or hash coding, this method is a general framework applicable to almost all radiance field methods without architectural modification [S1].

## How it works
The method operates as a preprocessing step for the volume rendering loop, determining which rays to evaluate based on a quadtree decomposition of the image plane [G].

**Inputs and Outputs**
*   **Input:** A set of $N$ training images $\mathcal{I}$ [S1]. A radiance field model $F_\Theta: (x, d) \mapsto (c, \sigma)$ that maps a 5D point to emitted color $c$ and volume density $\sigma$ [S1].
*   **Output:** A subset of rays $R_i \subset \text{All Rays}_i$ for each image $I_i$, selected via adaptive subdivision [S1].

**Data Structures**
*   **Quadtree:** Each view is adaptively subdivided into a quadtree according to the average rendering error in each node [S1].
*   **Node Metric:** Each node stores the average rendering error of the rays passing through its region [S1].
*   **5D Point Representation:** Points are defined as $\mathbf{x} = (x, y, z) \in \mathbb{R}^3$ and viewing direction $\mathbf{d} = (\theta, \phi) \in \mathbb{R}^2$ [S1].

**Algorithm Steps**
1.  **Initialization:** For each training image $I_i \in \mathcal{I}$, initialize a quadtree with a single root node covering the full image dimensions [G].
2.  **Initial Ray Casting:** Cast a uniform set of rays for all pixels in the initial quadtree nodes [G].
3.  **Error Computation:** For each node in the quadtree, compute the average rendering error [S1]. The error is derived from the difference between the rendered color and the target pixel color [S1].
4.  **Subdivision Decision:** Compare the average error $E_j$ of each node against a threshold [G]. If $E_j$ exceeds the threshold, subdivide the node into four children [G]. Repeat this process recursively until a maximum depth is reached or the error is below the threshold [G].
5.  **Adaptive Ray Shooting:** For leaf nodes in the final quadtree, if the node is in a complex region with larger rendering error, dynamically shoot more rays [S1]. If the node is in a simple region, cast fewer rays [S1]. Rays are shot primarily at pixels with dramatic color change [S1].
6.  **Volume Rendering:** For each selected ray $r_{ki}$, sample 5D points along the ray [G]. The network $F_\Theta$ predicts color $c$ and density $\sigma$ [S1]. Render the pixel color $\hat{c}_{ki}$ using standard volume rendering integration [G].
7.  **Loss Calculation:** Compute the loss $L$ over all selected rays:
    $$ L = \frac{1}{NM} \sum_{I_i \in \mathcal{I}} \sum_{r_{ki} \in R_i} ||V_\Theta(r_{ki}) - c_{ki}||_2^2 $$
    Where:
    *   $N$ is the number of training images [S1].
    *   $M$ is the number of rays per image [S1].
    *   $\mathcal{I}$ is the set of all training images [S1].
    *   $R_i$ is the set of rays generated from $I_i$ [S1].
    *   $r_{ki}$ is the $k$-th ray from the $i$-th training image [S1].
    *   $V_\Theta$ is the volume rendering function mapping a ray to rendered color $\hat{c}_{ki}$ [S1].
    *   $c_{ki}$ is the target pixel color [S1].
8.  **Optimization:** Update network parameters $\Theta$ to minimize $L$ [G].
9.  **Iteration:** Repeat steps 2–8 for subsequent training iterations, updating the quadtree structure based on the latest rendering errors [S1].

    quadtrees = []
    for img in images:
        qt = Quadtree(root=Node(0, 0, img.width, img.height, 0))
        quadtrees.append(qt)

    for iteration in range(num_iterations):
        total_loss = 0.0
        rays_per_image = []

        for idx, img in enumerate(images):
            qt = quadtrees[idx]
            # Subdivide based on gradient (iteration 0) or rendering error (subsequent) [G]
            if iteration == 0:
                qt.subdivide_on_gradient(error_threshold, max_depth)
            else:
                qt.subdivide_on_error(error_threshold, max_depth, radiance_field)

            rays = []
            for leaf in qt.get_leaves():
                # Higher error -> more rays [S1]
                num_rays = int(leaf.error * 10) + 1  # [G] heuristic scaling
                rays.extend(leaf.generate_rays(num_rays))
            rays_per_image.append(len(rays))

            rendered = []
            for ray in rays:
                pts = sample_5d_points(ray)  # [G]
                c_hat = volume_render(ray, pts, radiance_field)  # [G]
                rendered.append(c_hat)

            target = img.get_pixel_colors()
            loss = sum((r - t)**2 for r, t in zip(rendered, target)) / len(rendered)  # [G]

            qt.update_errors(rendered, rays)

        N = len(images)
        M = sum(rays_per_image) / N  # Average rays per image [G]
        avg_loss = total_loss / (N * M)
        radiance_field.update(avg_loss)

    return radiance_field

**Edge Cases and Pitfalls**
*   **Precision:** Rendering error computation must be stable to avoid oscillating subdivision patterns [G].
*   **Boundaries:** Quadtree nodes must align with pixel boundaries to ensure correct ray mapping [G].
*   **Degenerate Input:** If an image is uniform, the quadtree will remain at the root level, casting minimal rays [G]. If an image is highly noisy, the quadtree may reach max depth everywhere, resulting in uniform sampling [G].

## Operating characteristics
*   **Time Complexity:** The method reduces the total number of rays $M$ significantly compared to uniform sampling, thereby reducing the time spent in volume rendering per epoch [S1]. The overhead of quadtree management and error computation adds a small constant cost [G].
*   **Memory Complexity:** Requires storing the quadtree structure for each image [G]. The size is proportional to the number of nodes, which is bounded by $4 \times \text{Image Resolution}$ in the worst case (full subdivision) [G].
*   **Measured Performance:** Evaluated with NeRF and Plenoxels under widely used benchmarks, achieving comparable accuracy to state-of-the-art methods with much faster training [S1].
*   **Strengths:** General applicability to various radiance field methods; reduces training burden by focusing on complex regions; barely affects accuracy [S1].
*   **Limitations:** Requires an initial pass or heuristic to determine error before accurate subdivision can occur; overhead of dynamic ray generation [G].
*   **When to Use:** When training radiance fields is computationally expensive and the scene has varying levels of detail [G].
*   **When Not to Use:** When real-time inference is the primary concern (this is a training acceleration method); when the scene is uniformly simple (overhead may not be justified) [G].

## Background
The method was introduced in the paper "Fast Learning Radiance Fields by Shooting Much Fewer Rays" [S1]. It addresses the limitation of specialized fast training methods (like Plenoxels, TensoRF, Instant-NGP) that require specific architectures [S1]. The key insight is that radiance fields can be perceived without dramatically sacrificing accuracy by shooting fewer rays in redundant regions [S1]. The method leverages the fact that pixels with dramatic color change contain more information and require more samples [S1].
