# Adaptive Screen Sampling

Also called: Adaptive Subdivision of Screen Space, Gradient-based Adaptive Sampling, Screen-Space Adaptive Refinement

## Overview
Adaptive screen sampling is a dynamic sampling technique that reduces the average number of rays cast per pixel by evaluating local color variance and refining samples only where the scene changes rapidly [S1, S2, S3, unofficial]. Introduced by Levoy [S1, S3, unofficial], it adapts the sampling rate based on color change in a small pixel neighborhood, switching to a higher sampling rate in areas with high value gradients to replace interpolated values with exact color values [S1, S3, unofficial]. It differs from fixed-rate sampling by trading uniform compute time for variable quality, and from hierarchical spatial methods by operating directly on the screen-space pixel grid rather than the volume data structure.

## How it works
**Inputs:**
*   A volume dataset $V$.
*   A camera model defining ray origins and directions.
*   A target image resolution $W \times H$.
*   A neighborhood radius $r$ (typically small, e.g., 1-2 pixels) for gradient estimation.
*   A threshold $\tau$ for color variance.

**Outputs:**
*   A final rendered image $I$ of size $W \times H$.

**Data Structures:**
*   `ImageBuffer`: A 2D array of color values $C(x,y)$ and accumulation counts $N(x,y)$.
*   `RayQueue`: A list of rays to be traced, initially containing one ray per pixel.

**Algorithm:**

1.  **Initial Sampling:** Cast an initial small number of rays $k$ (e.g., $k=1$ or $k=2$) per pixel. For each ray, perform volume integration (e.g., ray marching) to obtain a color value $C_i$. [S2, unofficial]
2.  **Metric Evaluation:** For each pixel $(x,y)$, compute the color variance $M$ within the neighborhood defined by radius $r$. Let $C_{i,j}$ be the color values of the $k$ samples taken at pixel $(x,y)$ and its neighbors.
    $$ M(x,y) = \text{Var}(\{C_{i,j}\}) $$
    If $k=1$, $M$ may be estimated by comparing the current pixel's color to its neighbors' colors from previous iterations or a coarse pass. [S1, S3, unofficial]
3.  **Adaptation Decision:**
    *   If $M(x,y) < \tau$: The scene is homogeneous. Terminate sampling for this pixel. Use the accumulated result $C_{avg} = \frac{1}{k}\sum C_i$. [S2, unofficial]
    *   If $M(x,y) \ge \tau$: The scene has high value gradients. Proceed to Step 4. [S1, S3, unofficial]
4.  **Refinement:**
    *   Cast additional rays in the pixel region to capture rapid scene changes. The number of additional rays $k_{add}$ is determined by the magnitude of $M$ or a fixed higher sampling rate. [S1, S3, unofficial]
    *   Trace these rays and accumulate their color values. [S2, unofficial]
5.  **Handling Misses:** If rays miss the volume surface (e.g., due to sparse sampling or geometry gaps), interpolate missing values from surrounding valid samples. [S1, S3, unofficial]
6.  **Iteration:** Repeat Steps 2-5 until the variance $M$ falls below $\tau$ or a maximum number of samples is reached. [S2, unofficial]

**Pseudocode:**

```python
def adaptive_screen_sampling(volume, camera, width, height, threshold, max_samples, neighborhood_radius):
    # Initialize image buffer
    image = zeros((height, width, 3))
    sample_counts = zeros((height, width))
    
    # Initial ray generation: one ray per pixel
    rays = []
    for y in range(height):
        for x in range(width):
            rays.append(camera.get_ray(x, y))
            
    # First pass: initial sampling
    for ray in rays:
        color = trace_volume(volume, ray)
        x, y = ray.screen_position
        image[y, x] += color
        sample_counts[y, x] += 1
        
    # Adaptive refinement loop
    changed = True
    while changed and sample_counts.max() < max_samples:
        changed = False
        next_rays = []
        
        for y in range(height):
            for x in range(width):
                if sample_counts[y, x] >= max_samples:
                    continue
                    
                # Calculate variance in neighborhood
                neighbors = []
                for dy in range(-neighborhood_radius, neighborhood_radius + 1):
                    for dx in range(-neighborhood_radius, neighborhood_radius + 1):
                        ny, nx = y + dy, x + dx
                        if 0 <= ny < height and 0 <= nx < width:
                            neighbors.append(image[ny, nx])
                
                if len(neighbors) < 2:
                    continue
                    
                variance = compute_variance(neighbors)
                
                if variance >= threshold:
                    # High gradient: cast additional rays
                    num_additional = estimate_additional_rays(variance)
                    for _ in range(num_additional):
                        # Perturb ray direction or origin slightly for distributed sampling
                        perturbed_ray = camera.get_ray(x, y, perturbation=True)
                        next_rays.append(perturbed_ray)
                    changed = True
                else:
                    # Low gradient: finalize pixel
                    image[y, x] /= sample_counts[y, x]
                    sample_counts[y, x] = max_samples # Mark as done
                    
        # Trace new rays
        for ray in next_rays:
            color = trace_volume(volume, ray)
            x, y = ray.screen_position
            image[y, x] += color
            sample_counts[y, x] += 1
            
    # Finalize remaining pixels
    for y in range(height):
        for x in range(width):
            if sample_counts[y, x] > 0:
                image[y, x] /= sample_counts[y, x]
                
    return image
```

**Edge Cases and Pitfalls:**
*   **Ray Misses:** Rays may occasionally miss the surface, requiring interpolation of missing values [S1, S3, unofficial].
*   **Heuristic Failure:** The method is heuristic-based and may fail to produce desired visual results if parameters are not carefully tuned [S2, unofficial].
*   **Overhead:** The computation time spent determining sample rates can equal or exceed the cost of constant-rate sampling, especially in non-homogeneous scenes [S2, unofficial].
*   **Aliasing:** If not carefully tuned, the method risks aliasing and quality loss in non-homogeneous regions [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Variable. Average case is $O(W \cdot H \cdot k_{avg})$ where $k_{avg}$ is the average samples per pixel. Worst case is $O(W \cdot H \cdot k_{max})$.
*   **Memory Complexity:** $O(W \cdot H)$ for the image buffer and sample counts.
*   **Performance:** Reduces average compute time for homogeneous scenes [S2, unofficial]. However, in non-homogeneous scenes, the overhead of variance calculation and ray management can negate savings [S2, unofficial].
*   **Strengths:** Efficient for scenes with large homogeneous regions; reduces ray count where detail is low.
*   **Limitations:** Heuristic nature makes it difficult to guarantee quality; overhead can be significant; prone to aliasing if thresholds are poorly chosen [S2, unofficial].
*   **When to use:** Scenes with large uniform areas and distinct boundaries; when computational resources are limited and homogeneous regions dominate.
*   **When not to use:** Highly heterogeneous scenes; when consistent quality is required regardless of scene content; when overhead of variance calculation is prohibitive.

## Background
Adaptive screen sampling was introduced by Levoy in 1990 [S1, S3, unofficial]. It is well known in traditional ray tracing and has been applied to volume rendering as a method to adaptively switch sampling rates based on color change in a pixel neighborhood [S1, S3, unofficial]. The technique is part of the broader family of adaptive sampling methods aimed at reducing aliasing and computational cost by focusing samples where they are most needed [S2, unofficial].
