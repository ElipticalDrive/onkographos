# Adaptive Sampling
Also called: Adaptive Sampling Rate, Adaptive Sampling Strategy, Adaptive Sampling with Bricking, Adaptive Volume Sampling, Opacity-based Adaptation

## Overview
Adaptive sampling is a strategy that improves rendering quality and reduces computational cost by sampling non-homogeneous or high-detail regions more densely than homogeneous or low-detail regions [S1, unofficial][S3, unofficial][S5]. It sets itself apart from siblings like [Two-stage NeRF Rendering](925-two-stage-nerf-rendering.md) by often employing discrete rate changes or variance-based block analysis rather than neural network-based uncertainty estimation, and from [Random Pixel Subsampling](1668-random-pixel-subsampling.md) by actively increasing samples in noisy areas rather than just reducing them [G].

## How it works
Adaptive sampling generally follows one of several patterns depending on the specific variant (e.g., variance-based, silhouette-based, or density-based) [G]. The core inputs are the volumetric dataset, ray origins/directions, and a target quality or performance metric [G]. The output is the final pixel color and/or opacity [G].

### Data Structures
*   **Block/Cell Metadata:** Stores variance metrics or detail levels for regions of the volume [S2, unofficial][S6].
*   **Film Buffer:** Stores per-pixel luminance and luminance squares to estimate error [S9].
*   **Sampling State:** Tracks current sample count, zero-density counts, and convergence status [S8, unofficial][S9].

### General Algorithm (Variance-Based Two-Stage Approach)
This method, often used with local solvers, reduces cost by casting rays in two steps [S2, unofficial].
1.  **Initial Cast:** Cast a sparse set of rays (e.g., 12.5% or 32 rays per block) simultaneously for all pixels [S2, unofficial]. In padded regions, 100% of rays are cast [S2, unofficial].
2.  **Variance Analysis:** Perform variance analysis on the turned-on pixels for each block based on the initial render results [S2, unofficial].
3.  **Adaptive Cast:** Identify blocks with high variance. Cast additional rays for these blocks [S2, unofficial].
4.  **Reconstruction:** Run the local solver on each block to reconstruct the image, using padded region pixel information for convolution [S2, unofficial].

### Density-Based Algorithm (Cloud/Atmosphere)
This method uses adaptive step counts based on local density to skip empty space [S8, unofficial].
1.  **Initialization:** Initialize `colorpixel = vec3(0.0)`, `density = 0.0`, `cloud_test = 0.0`, `zero_density_sample_count = 0`, and `sample_cout` (e.g., 128) [S8, unofficial].
2.  **Step Size Calculation:** Calculate `thick_ = length(endPoint - startPoint)`, `stepsize = thick_ / sample_cout`, `start_ = length(startPoint - rayOrigin)`, `end_ = length(endPoint - rayOrigin)` [S8, unofficial]. If `end_ < start_`, swap `start_` and `end_` [S8, unofficial].
3.  **Ray Marching Loop:** Iterate `t` from `start_` to `end_` with `stepsize` [S8, unofficial].
    *   Calculate jittered position `posInAtm` using ray origin, direction, and jitter offset [S8, unofficial].
    *   Get weather data and relative height [S8, unofficial].
    *   **Light Test:** If `cloud_test <= 0.0`, perform a light test by sampling cloud density at a specific point [S8, unofficial]. If `cloud_test > 0.0`, proceed to density accumulation [S8, unofficial].
    *   **Density Accumulation:** If `cloud_test > 0.0`:
        *   Increment `samplepoint` by `testsize` (where `testsize = rayDirection / float(sample_cout)`) and divide by 8.0 (or 1.0 depending on implementation detail) [S8, unofficial].
        *   Sample density at `samplepoint` using `SampleCloudDensity` [S8, unofficial].
        *   Track zero density samples: If `sampled_density == 0.0`, increment `zero_density_sample_count` [S8, unofficial].
        *   If `zero_density_sample_count != 6`, add `sampled_density` to `density` and `sampled_density * 0.1` (or `0.07`) to `colorpixel` [S8, unofficial].
        *   If `sampled_density != 0.0`, calculate light energy based on precipitation and density along the light ray, then add to `colorpixel` [S8, unofficial].
        *   If `zero_density_sample_count == 6`, reset `cloud_test = 0.0` and `zero_density_sample_count = 0` to exit dense region mode [S8, unofficial].
    *   **Termination:** Break loop if `density >= 1.0` to prevent over-saturation [S8, unofficial].
4.  **Return:** Return `colorpixel` and update `density_inout` with final `density` [S8, unofficial].

### Silhouette-Based Algorithm (Discrete Rates)
This method uses two discrete rates to improve intersection detection near silhouettes without diverging parallel execution pipelines [S6].
1.  **Base Sampling:** Cast rays at base sampling rate $r_0$ [S6].
2.  **Threshold Check:** For each sample, check if the sample value $f$ is within a threshold $\delta$ of the isovalue $\rho$ (i.e., $|f - \rho| < \delta$) [S6].
3.  **Rate Adjustment:** If the threshold is met, switch to maximum sampling rate $r_1 = n \cdot r_0$ (typically $n=8$) [S6].
4.  **Intersection Detection:** Intersection is detected when $f < \rho$ (assuming front-to-back and isosurface defined by $f < \rho$) [S6].

### Macrocell-Based Algorithm (GPU Optimized)
This method varies sampling rate on a per-macrocell basis to maintain thread coherence on GPUs [S7].
1.  **Metric Calculation:** For each macrocell, compute $m = \sqrt{dVar(f_{cell})} / \sqrt{dVar(f_{vol})}$, where $m$ is the ratio of max standard deviation of cell voxels to the entire volume [S7].
2.  **Multiplier Calculation:** Compute multiplier $M = 2m - 1 + 1$ (or similar positive integer mapping) [S7].
3.  **Step Size Variation:** Use $M$ to vary the sampling step size $\Delta t$. For uniform sampling, new rate is $M\Delta t$. For differential sampling, modify increments:
    $$ \frac{\partial^2 T_M}{\partial x^2} = \sum_{i=1}^M a = \frac{M(M+1)}{2} a $$
    $$ \frac{\partial T_M}{\partial x} = Max + \frac{\partial^2 T_M}{\partial x^2} + b $$
    [S7].

### Error-Based Algorithm (Progressive Rendering)
This method tracks per-pixel luminance squares to estimate relative standard error [S10, unofficial].
1.  **Tracking:** Track per-pixel luminance squares in the film buffer [S10, unofficial].
2.  **Error Estimation:** Report relative standard error for each pixel [S10, unofficial].
3.  **Convergence Check:** In final renders, stop sampling converged pixels every 8 samples [S10, unofficial]. In progressive passes, skip pixels whose 3x3 neighborhood is under the noise threshold [S10, unofficial].

### Parameters
*   **Target Frame Time:** Desired frame budget (e.g., 32 ms) [S4, unofficial].
*   **Sampling Rate:** Initialized to 0.5, resets to 0.5 on new volume upload [S4, unofficial].
*   **Base Rate ($r_0$):** Specified by user; 1.0 corresponds to a single voxel [S6].
*   **Multiplier ($n$):** Constant multiple for max rate; typical value 8 [S6].
*   **Threshold ($\delta$):** Quality parameter for silhouette detection; constant for distance fields, data-dependent for CT scans [S6].
*   **Sample Count ($sample\_cout$):** Calculated as $128 - 64 \cdot \text{int}(\text{dot}(rayDirection, vec3(0.0, 1.0, 0.0)))$ [S8, unofficial].

### Edge Cases and Pitfalls
*   **Pipeline Divergence:** Completely adaptive sampling causes neighboring pixels in parallel pipelines to diverge, under-utilizing the texture cache. Solution: Use only two discrete rates [S6].
*   **Missed Intersections:** Discrete sampling may miss intersections if the segment between two successive samples crosses the isosurface twice. Guaranteed if gradient length is bounded by $L$: $h = |f - \rho|/L$ [S6].
*   **AMR Awareness:** Standard adaptive sampling may severely under- or over-sample AMR data if not aware of the hierarchy [S9].

## Subtopics

### [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md)
An optimization taking advantage of coherence in projections (often from sensing device blurring) by casting a sparse grid of rays (less than one per pixel) and adaptively increasing rays in high-complexity regions [Link to 1656-adaptive-sampling-sparse-grid.md].

### Adaptive Sampling for Silhouettes
A sampling strategy using two discrete rates (base $r_0$ and max $r_1$) to improve intersection detection near silhouettes without diverging parallel execution pipelines [S6]. It uses a threshold $\delta$ to switch rates when $|sample\_value - isovalue| < \delta$. Typical multiplier $n=8$ [S6].

### Adaptive Sampling with Opacity Correction
An adaptive sampling approach that guarantees the sampling frequency can adapt to the finest level cell size while keeping total sample counts tractable, combined with opacity correction [S9]. It is tailored for AMR data, unlike OSPRay's existing code which may under- or over-sample [S9].

### Adaptive Sampling with Relative Standard Error
An adaptive sampling strategy that tracks per-pixel luminance squares to estimate relative standard error, stopping converged pixels and skipping noisy neighborhoods [S10, unofficial]. Measured relMSE on showcase scene: 0.0036 (uniform, extrapolated) vs 0.0024 (adaptive) at the same mean spp [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the variance/density distribution. Generally reduces total samples in low-detail regions, speeding up rendering [S3, unofficial].
*   **Memory Complexity:** Requires additional buffers for variance analysis, error tracking, or block metadata [S2, unofficial][S9].
*   **Performance:** On the Asian Dragon dataset (512x256x256), with brick size 32 and adaptive sampling ($r_1=8r_0$), frame rates are 19.2 fps at sampling rate 0.25, 13.8 fps at 0.5, 10.2 fps at 1, and 6.9 fps at 2 [S6]. Adaptive sampling with bricking achieves 80-85% of the performance of rendering without bricking and without adaptive sampling [S6].
*   **Strengths:** Significantly increases rendering speed for datasets with large empty or low-detail regions [S3, unofficial]. Improves quality in high-detail areas [S1, unofficial].
*   **Limitations:** Can cause thread divergence on GPUs if not constrained to discrete rates [S6]. Requires additional passes or analysis steps [S2, unofficial].

## Background
Adaptive sampling originated as a response to the inefficiencies of uniform sampling in volume rendering, where homogeneous regions are over-sampled and detailed regions are under-sampled [S1, unofficial]. It has been developed in various forms for different rendering pipelines, including GPU-based compressive rendering [S2, unofficial], real-time ray-casting of isosurfaces [S6], and AMR data visualization [S9].
