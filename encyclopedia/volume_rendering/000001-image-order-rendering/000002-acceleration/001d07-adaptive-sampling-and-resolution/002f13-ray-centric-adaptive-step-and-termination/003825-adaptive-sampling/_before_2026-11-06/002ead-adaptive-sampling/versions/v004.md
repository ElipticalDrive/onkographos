# Adaptive Sampling

Also called: Adaptive Sampling Rate, Adaptive Sampling Strategy, Adaptive Sampling with Bricking, Adaptive Volume Sampling, Opacity-based Adaptation

## Overview
Adaptive sampling is a rendering optimization that varies the discretization of the volumetric integration process to reduce computational cost while preserving visual quality [S1, unofficial][S5]. Unlike uniform sampling, which casts a fixed number of samples per ray regardless of content, adaptive sampling increases sample density in regions of high detail (e.g., near surfaces or high gradients) and decreases it in homogeneous or empty regions [S1, S3, unofficial]. This method is particularly effective for datasets dominated by low-detail areas, such as empty space, where it can achieve significant speedups [S3, unofficial]. It builds on [Ray-Centric Adaptive Step and Termination](5938-ray-centric-adaptive-step-and-termination.md) by dynamically adjusting the step size $\Delta t$ or sample count based on local data characteristics [G].

## How it works
Adaptive sampling strategies generally fall into two categories: per-ray adaptation (adjusting step size along the ray) and per-pixel/block adaptation (adjusting the number of rays or samples based on variance or detail metrics). The following sections detail the most common implementations found in the literature.

### Inputs and Outputs
*   **Inputs:** Volumetric scalar field $f(\mathbf{x})$, transfer function $T$, ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, bounding box $[t_{near}, t_{far}]$, and optional metadata (e.g., brick size, octree level, isovalue $\rho$).
*   **Outputs:** Final pixel color $C$, accumulated opacity $\alpha$, and potentially intermediate metrics (variance, error estimates).

### Data Structures
*   **Scalar Field:** Stored in bricks or octrees. For brick-based methods, data is accessed via texture units [S6]. For octree-based methods, leaf nodes store voxel density [S11].
*   **Film Buffer:** Stores per-pixel accumulators for color, opacity, and optionally variance or squared luminance for error estimation [S10, unofficial].
*   **Macrocell/Metric Storage:** For block-based adaptation, a metric $m$ is computed per block to determine sampling intensity [S7].

### Core Algorithms

#### 1. Opacity-Based and Gradient-Driven Adaptation
This method adjusts the step size $\Delta t$ along the ray based on local field properties [S5].

**Parameters:**
*   $\epsilon$: Termination threshold (typically $0.01$ to $0.05$) [S5].
*   $L$: Bound on gradient magnitude (e.g., $1.0$ for distance fields) [S6].
*   $\Delta t_{min}, \Delta t_{max}$: Bounds for step size [S5].

**Steps:**
1.  Initialize $t = t_{near}$, accumulated opacity $\alpha = 0$, color $C = \mathbf{0}$.
2.  Loop while $t < t_{far}$ and $\alpha < 1 - \epsilon$:
    a.  Sample scalar value $s = f(\mathbf{o} + t\mathbf{d})$.
    b.  Compute local gradient magnitude $g = \|\nabla f(\mathbf{o} + t\mathbf{d})\|$ [S5].
    c.  Calculate step size $\Delta t$:
        *   If using gradient-driven sampling: $\Delta t \propto 1/g$. Clamp to $[\Delta t_{min}, \Delta t_{max}]$ [S5].
        *   If using opacity-based sampling: $\Delta t \propto 1/s$ (or similar inverse relation to local opacity) [S5].
    d.  Sample color and opacity contribution $c, a$ at $t$ using transfer function [S5].
    e.  Update $\alpha = \alpha + a(1-\alpha)$ and $C = C + c(1-\alpha)$ (front-to-back compositing) [S5].
    f.  $t = t + \Delta t$.
3.  Return $C$.

#### 2. Variance-Based Block Adaptation (Two-Step Casting)
Used in compressive rendering or local solver contexts, this method casts an initial sparse set of rays, analyzes variance, and casts additional rays for high-variance blocks [S2, unofficial].

**Parameters:**
*   $N_{init}$: Initial ray count per block (e.g., 12.5% of total or 32 rays) [S2, unofficial].
*   $N_{total}$: Total rays per block.

**Steps:**
1.  Divide the image into blocks.
2.  **Step 1:** Cast $N_{init}$ rays per block in parallel. For padded regions, cast 100% of rays [S2, unofficial].
3.  Compute the variance $\sigma^2$ of the rendered result for each block [S2, unofficial].
4.  **Step 2:** Identify blocks with variance above a threshold. Cast additional rays for these blocks to fill the remaining $N_{total} - N_{init}$ samples [S2, unofficial].
5.  Run the local solver/reconstruction using all cast rays and padded pixel information [S2, unofficial].

#### 3. Discrete Rate Adaptation for Silhouettes (Bricking)
To maintain GPU thread coherence and texture cache efficiency, completely adaptive rates are avoided. Instead, two discrete rates are used: a base rate $r_0$ and a max rate $r_1 = n \cdot r_0$ (typically $n=8$) [S6].

**Parameters:**
*   $r_0$: Base sampling rate (1.0 = 1 voxel) [S6].
*   $n$: Multiplier for max rate (typically 8) [S6].
*   $\delta$: Threshold for switching rates. If $|f(\mathbf{x}) - \rho| < \delta$, use $r_1$; otherwise use $r_0$ [S6].

**Steps:**
1.  For each ray, determine current sample value $f$.
2.  If $|f - \rho| < \delta$, set step size corresponding to $r_1$.
3.  Else, set step size corresponding to $r_0$.
4.  March ray using the selected step size.
5.  Detect intersection when $f < \rho$ (for front-to-back) [S6].

#### 4. Hierarchical/Octree-Based Adaptation
In octree structures, step size is determined by the current octree level [S11].

**Steps:**
1.  Traverse octree to find non-empty leaves pierced by the ray [S11].
2.  For each leaf, determine the step size matching the local voxel density (coarser for higher levels, finer for lower levels) [S11].
3.  Accumulate color/opacity using a 2D transfer function indexed by scalar value and octree level [S11].
4.  Terminate if accumulated opacity $> 0.99$ [S11].

#### 5. Error-Driven Progressive Adaptation
Tracks statistical error to stop sampling converged pixels [S10, unofficial].

**Steps:**
1.  Track per-pixel luminance $L$ and squared luminance $L^2$ in the film buffer [S10, unofficial].
2.  Compute relative standard error (RSE) for each pixel [S10, unofficial].
3.  In final renders, stop sampling pixels where RSE is below a threshold every 8 samples [S10, unofficial].
4.  In progressive passes, skip pixels whose 3x3 neighborhood is under the noise threshold [S10, unofficial].

### Pseudocode: Gradient/Opacity Adaptive Marching
```python
def adaptive_march(ray_origin, ray_direction, volume, transfer_func, epsilon=0.02):
    t = ray_origin.t_near
    accumulated_alpha = 0.0
    accumulated_color = vec3(0.0)
    
    while t < ray_origin.t_far and accumulated_alpha < 1.0 - epsilon:
        pos = ray_origin + t * ray_direction
        scalar = volume.sample(pos)
        
        # Compute gradient magnitude for step size adaptation
        grad_mag = length(volume.gradient(pos))
        
        # Determine step size: smaller steps for high gradient/high scalar
        # Base step size dt_base
        if grad_mag > 0:
            dt = dt_base / (1.0 + grad_mag)
        else:
            dt = dt_base
            
        # Clamp step size
        dt = max(dt_min, min(dt_max, dt))
        
        # Sample contribution
        color, alpha = transfer_func(scalar)
        
        # Front-to-back compositing
        weight = alpha * (1.0 - accumulated_alpha)
        accumulated_color += color * weight
        accumulated_alpha += weight
        
        t += dt
        
    return accumulated_color
```

### Edge Cases and Pitfalls
*   **Thread Divergence:** Completely adaptive sampling causes neighboring pixels in parallel pipelines to diverge, under-utilizing the texture cache and warp execution units [S6, S7]. Solution: Use discrete sampling rates (e.g., two rates) or quantize step sizes [S6, S7].
*   **Missed Intersections:** If the step size is too large relative to the gradient bound $L$, an isosurface may be missed if the segment crosses it twice [S6]. Guaranteed intersection requires $h = |f - \rho|/L$ to be respected by the step size [S6].
*   **AMR Awareness:** Standard adaptive sampling code may not be aware of AMR (Adaptive Mesh Refinement) hierarchies, leading to severe under- or over-sampling [S9]. Tailored methods are required for AMR data [S9].

## Subtopics

### [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md)
Adaptive Sampling (Sparse Grid) exploits coherence in projections (often from sensing device blurring) to reduce computational overhead by casting a sparse grid of rays (less than one per pixel) and adaptively increasing ray density in regions of high image complexity. It differs from uniform sampling by prioritizing high-frequency details and from brute-force methods by achieving savings of more than two orders of magnitude for many datasets. It is particularly well-suited for scan-conversion methods where polygons are filtered prior to ray tracing.

### Adaptive Sampling for Silhouettes
A sampling strategy using two discrete rates (base $r_0$ and max $r_1$) to improve intersection detection near silhouettes without diverging parallel execution pipelines [S6]. Intersection is detected when sample value $f < \text{isovalue } \rho$. Guaranteed intersections for thin sheets require the gradient length to be bounded by $L$, with step size $h = |f - \rho|/L$ [S6]. Base rate $r_0$ is user-specified (1.0 = 1 voxel). Max rate $r_1 = n \cdot r_0$ (typical $n=8$). Rate increases to $r_1$ when $|sample\_value - \rho| < \delta$ [S6]. Pitfall: Completely adaptive sampling causes thread divergence; solution is using only two discrete rates [S6].

### Adaptive Sampling with Opacity Correction
An adaptive sampling approach that guarantees the sampling frequency can adapt to the finest level cell size while keeping total sample counts tractable, combined with opacity correction [S9]. Unlike OSPRay's existing adaptive sampling code which is not aware of the underlying AMR hierarchy and may severely under- or over-sample, this method is tailored for AMR data [S9].

### Adaptive Sampling with Relative Standard Error
An adaptive sampling strategy that tracks per-pixel luminance squares to estimate relative standard error, stopping converged pixels and skipping noisy neighborhoods [S10, unofficial]. It tracks per-pixel luminance squares in the film buffer and reports the relative standard error for each pixel [S10, unofficial]. In final renders, it stops sampling converged pixels every 8 samples [S10, unofficial]. In progressive passes, it skips pixels whose 3x3 neighborhood is under the noise threshold [S10, unofficial]. Measured relMSE on showcase scene: 0.0036 (uniform, extrapolated) vs 0.0024 (adaptive) at the same mean spp [S10, unofficial].

### Adaptive Sampling in Volume Rendering
A technique where the fragment shader enumerates non-empty leaves in front-to-back order and chooses a step size matching local voxel density [S11]. It adapts sampling density to brick resolution [S11]. For isosurface rendering, it looks for intervals that bracket the selected isovalue. For semitransparent direct volume rendering, it implements a Phong illumination model with boundary enhancement and view-dependent transparency [S11]. Stepping is done by a discrete number of intervals directly associated to octree levels [S11]. It uses a compact precomputed 2D transfer function, using the octree level for the second dimension to adjust opacity and color weighting [S11].

## Operating characteristics
*   **Time Complexity:** Depends on the adaptation metric. Variance-based methods require two passes (initial cast + variance analysis + secondary cast), increasing overhead but reducing total samples in smooth regions [S2, unofficial]. Gradient/opacity methods reduce samples in empty space, potentially achieving 2-3x speedup over uniform sampling [S5].
*   **Memory Complexity:** Minimal overhead for per-pixel variance/error tracking in progressive methods [S10, unofficial]. Block-based methods require storing variance metrics per block [S2, unofficial].
*   **Measured Performance:** On the Asian Dragon dataset (512x256x256), with brick size 32 and adaptive sampling ($r_1=8r_0$), frame rates were 19.2 fps at sampling rate 0.25, 13.8 fps at 0.5, 10.2 fps at 1, and 6.9 fps at 2 [S6]. Adaptive sampling with bricking achieves 80-85% of the performance of rendering without bricking and without adaptive sampling [S6].
*   **Strengths:** Significant speedup in datasets with large empty or homogeneous regions [S3, unofficial]. Improved quality in high-detail regions compared to uniform sampling at the same average cost [S1, unofficial].
*   **Limitations:** GPU thread divergence if adaptation is too fine-grained [S6, S7]. Risk of missing thin structures if step size is not bounded by gradient [S6]. Not suitable for AMR data without specific hierarchy awareness [S9].

## Background
Adaptive sampling in volume rendering originated as a response to the inefficiency of uniform sampling, which wastes samples in empty space and undersamples complex regions [S1, unofficial]. Early work highlighted that uniform sampling may result in artifacts due to homogeneous material assumptions, whereas adaptive sampling provides better quality by sampling non-homogeneous regions more densely [S1, unofficial]. The technique has been widely adopted in GPU-based rendering to balance performance and quality, with specific optimizations for bricking [S6], AMR data [S9], and progressive rendering [S10, unofficial].
