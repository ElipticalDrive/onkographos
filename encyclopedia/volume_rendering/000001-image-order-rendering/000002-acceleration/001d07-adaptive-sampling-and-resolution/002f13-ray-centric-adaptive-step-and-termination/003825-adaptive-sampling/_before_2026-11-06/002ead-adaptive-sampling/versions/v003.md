# Adaptive Sampling

Also called: Adaptive Sampling Rate, Adaptive Sampling Strategy, Adaptive Sampling with Bricking, Adaptive Volume Sampling, Opacity-based Adaptation

## Overview
Adaptive sampling is a rendering optimization that varies the density and distribution of samples along rays to reduce computational cost in low-detail regions while preserving quality in high-detail areas [S1, unofficial][S5, S6]. Unlike uniform sampling, which treats all regions equally, adaptive sampling prioritizes high-frequency details and empty space, achieving savings of more than two orders of magnitude for many datasets [S1, S3, unofficial]. It differs from its sibling [Adaptive Sampling for Interaction](5643-adaptive-sampling-for-interaction.md) by focusing on static or semi-static volume fidelity rather than interactive frame-rate stabilization via global rate adjustment [S4, unofficial].

## How it works
Adaptive sampling operates by modulating the step size $\Delta t$ or the number of rays cast per pixel based on local data characteristics (density, gradient, or opacity) or image-space variance. The method generally follows one of three strategies: opacity-based, gradient-driven, or variance-based block sampling.

### Inputs and Outputs
*   **Inputs:** Volumetric scalar field $f(\mathbf{x})$, transfer function $T$, ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, and optional metadata (e.g., brick size, octree levels, or block variance).
*   **Outputs:** Final pixel color $C$, accumulated opacity $\alpha$, and potentially a refined intersection point.

### Data Structures
*   **Macrocell/Block:** A spatial subdivision of the volume (e.g., brick or tile). For variance-based methods, each block stores a variance metric $Var(f_{block})$ [S2, unofficial].
*   **Film Buffer:** Stores per-pixel accumulators for luminance and luminance squares to estimate error [S10, unofficial].
*   **Sampling State:** Tracks current position $t$, accumulated opacity $\alpha$, and zero-density counts for early termination [S8, unofficial].

### Algorithm Steps

#### 1. Opacity-Based Adaptation
This method adjusts step sizes inversely with local opacity to skip empty space [S5].

1.  **Initialize:** Set `color = 0`, `alpha = 0`, `t = t_near`.
2.  **Loop:** While `alpha < 1 - \epsilon` (typically $\epsilon = 0.01$ to $0.05$) and `t < t_far`:
    *   Sample scalar value $s = f(\mathbf{o} + t\mathbf{d})$.
    *   Compute local opacity contribution $\alpha_{local}$ from $s$ using the transfer function.
    *   **Step Size Calculation:** If $\alpha_{local}$ is low, increase step size $\Delta t$. A common heuristic is $\Delta t \propto 1/\alpha_{local}$ or based on the distance to the nearest surface [S5].
    *   **Accumulate:** Update `color` and `alpha` using front-to-back compositing:
        $$ \alpha_{new} = \alpha + (1 - \alpha) \alpha_{local} $$
        $$ color_{new} = color + (1 - \alpha) \alpha_{local} c(s) $$
        where $c(s)$ is the color from the transfer function.
    *   **Advance:** $t \leftarrow t + \Delta t$.
3.  **Terminate:** If `alpha` exceeds $1 - \epsilon$, break loop [S5].

#### 2. Gradient-Driven Adaptation
Refines steps near high-gradient regions (surfaces) [S5].

1.  **Compute Gradient:** Calculate $\nabla f(\mathbf{x})$ at current position.
2.  **Step Size:** Set $\Delta t = \min(\Delta t_{max}, \max(\Delta t_{min}, k / \|\nabla f\|))$, where $k$ is a scaling constant [S5].
3.  **Trace:** Proceed with compositing as in Opacity-Based Adaptation.

#### 3. Variance-Based Block Sampling (Two-Phase)
Used in local solver contexts to reduce warp divergence [S2, unofficial].

1.  **Phase 1 (Sparse Cast):** Cast an initial sparse set of rays (e.g., 12.5% or 32 rays per block) simultaneously [S2, unofficial].
2.  **Variance Analysis:** Compute the variance of the rendered result for each block. Blocks with high variance indicate high detail or noise [S2, unofficial].
3.  **Phase 2 (Adaptive Cast):** Cast additional rays only for blocks identified with high variance [S2, unofficial].
4.  **Reconstruction:** Run the local solver on all blocks, using padded region pixel information for convolution [S2, unofficial].

#### 4. Discrete Rate Adaptation (Silhouettes)
To maintain GPU thread coherence, sampling rates are quantized to a small set of discrete values [S6].

1.  **Define Rates:** Base rate $r_0$ (e.g., 1 voxel) and max rate $r_1 = n \cdot r_0$ (typically $n=8$) [S6].
2.  **Threshold Check:** For each sample, if $|f(\mathbf{x}) - \rho| < \delta$ (where $\rho$ is the isovalue and $\delta$ is a threshold), use rate $r_1$. Otherwise, use $r_0$ [S6].
3.  **Intersection Detection:** Intersection is detected when $f(\mathbf{x}) < \rho$. To guarantee detection of thin sheets, ensure step size $h \le |f - \rho|/L$, where $L$ is the bound on gradient length [S6].

#### 5. Adaptive Sampling with Relative Standard Error (Monte Carlo)
Tracks convergence per pixel [S10, unofficial].

1.  **Accumulate:** Track per-pixel luminance $L$ and luminance squares $L^2$ in the film buffer.
2.  **Estimate Error:** Compute relative standard error $\sigma_{rel} = \sqrt{Var(L)} / E[L]$.
3.  **Skip/Stop:** In final renders, stop sampling converged pixels every 8 samples. In progressive passes, skip pixels whose 3x3 neighborhood is under the noise threshold [S10, unofficial].

### Pseudocode: General Adaptive Ray Marching (Opacity/Gradient Hybrid)

```python
def adaptive_ray_march(ray_origin, ray_direction, volume_field, transfer_func, epsilon=0.01):
    """
    Performs adaptive ray marching using opacity and gradient information.
    """
    color = vec3(0.0)
    alpha = 0.0
    t = ray_origin.t_near
    t_far = ray_origin.t_far
    
    # Precompute ray length for normalization if needed
    ray_length = length(ray_direction)
    
    while t < t_far and alpha < (1.0 - epsilon):
        # Current position
        pos = ray_origin + t * ray_direction
        
        # Sample scalar field
        s = volume_field.sample(pos)
        
        # Get color and opacity from transfer function
        c, alpha_local = transfer_func(s)
        
        # If no opacity, skip ahead using empty space skipping or large step
        if alpha_local == 0.0:
            # [G] In practice, use a large step or spatial acceleration structure to skip
            t += 1.0 
            continue
            
        # Compute gradient for step size adaptation
        grad = volume_field.gradient(pos)
        grad_mag = length(grad)
        
        # Adaptive step size: smaller steps for high gradients, larger for low
        # Base step size (e.g., 1 voxel)
        base_step = 1.0 
        # Inverse proportionality to gradient magnitude, bounded
        # Avoid division by zero
        if grad_mag > 0.001:
            step_factor = 1.0 / grad_mag
        else:
            step_factor = 1.0
            
        # Clamp step size to reasonable bounds
        delta_t = clamp(base_step * step_factor, 0.1, 5.0)
        
        # Front-to-back compositing
        alpha_new = alpha + (1.0 - alpha) * alpha_local
        color_new = color + (1.0 - alpha) * alpha_local * c
        
        color = color_new
        alpha = alpha_new
        
        # Advance
        t += delta_t
        
    return color, alpha
```

### Parameters
*   **$\epsilon$:** Termination threshold for accumulated opacity. Typical values: $0.01$ to $0.05$ [S5].
*   **$r_0, r_1$:** Base and maximum sampling rates. $r_0=1.0$ corresponds to one voxel. $n$ (multiplier for $r_1$) is typically $8$ [S6].
*   **$\delta$:** Threshold for switching to max sampling rate near isosurface. Depends on data (constant for distance fields, data-dependent for CT) [S6].
*   **Target Frame Time:** Used in dynamic rate adjustment. `targetSamplingRate = renderTime / targetFrameTime` [S4, unofficial].
*   **Sample Count:** Initial sparse cast often uses 12.5% or 32 rays per block [S2, unofficial].

### Edge Cases and Pitfalls
*   **Thread Divergence:** Completely adaptive sampling causes neighboring pixels to diverge, under-utilizing the texture cache. Solution: Use only two discrete rates ($r_0, r_1$) [S6].
*   **Missed Intersections:** Discrete sampling may miss thin sheets if the segment crosses the isosurface twice. Guaranteed if step size $h \le |f - \rho|/L$ [S6].
*   **AMR Under-sampling:** Standard adaptive sampling may severely under- or over-sample AMR data if not aware of the hierarchy. Tailored methods are required [S9].
*   **Precision:** Floating-point precision issues may arise when comparing sample values to isovales in thin structures [S6].

## Subtopics

### [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md)
Adaptive Sampling (Sparse Grid) exploits coherence in projections to reduce computational overhead by casting a sparse grid of rays (less than one per pixel) and adaptively increasing ray density in regions of high image complexity. It differs from uniform sampling by prioritizing high-frequency details and from brute-force methods by achieving savings of more than two orders of magnitude. It is particularly well-suited for scan-conversion methods where polygons are filtered prior to ray tracing.

### Adaptive Sampling for Silhouettes
A sampling strategy using two discrete rates (base $r_0$ and max $r_1$) to improve intersection detection near silhouettes without diverging parallel execution pipelines [S6]. Intersection is detected when sample value $f < \text{isovalue } \rho$. Guaranteed intersections for thin sheets require step size $h = |f - \rho|/L$, where $L$ is the bound on gradient length [S6]. Base rate $r_0$ is user-specified (1.0 = 1 voxel). Max rate $r_1 = n r_0$ with typical $n=8$. Rate increases to $r_1$ when $|sample\_value - \rho| < \delta$ [S6].

### Adaptive Sampling with Opacity Correction
An adaptive sampling approach that guarantees the sampling frequency can adapt to the finest level cell size while keeping total sample counts tractable, combined with opacity correction [S9]. Unlike OSPRay's existing adaptive sampling code which is not aware of the underlying AMR hierarchy and may severely under- or over-sample, this method is tailored for AMR data [S9].

### Adaptive Sampling with Relative Standard Error
An adaptive sampling strategy that tracks per-pixel luminance squares to estimate relative standard error, stopping converged pixels and skipping noisy neighborhoods [S10, unofficial]. It tracks per-pixel luminance squares in the film buffer, reports relative standard error, stops converged pixels every 8 samples in final renders, and skips pixels whose 3x3 neighborhood is under the noise threshold in progressive passes [S10, unofficial]. Measured relMSE on showcase scene: 0.0036 (uniform, extrapolated) vs 0.0024 (adaptive) at the same mean spp [S10, unofficial].

### Adaptive Sampling in Volume Rendering
A technique where the fragment shader enumerates non-empty leaves in front-to-back order and chooses a step size matching local voxel density. It adapts sampling density to brick resolution [S11]. For isosurface rendering, it looks for intervals that bracket the selected isovalue. For semitransparent direct volume rendering, it implements a Phong illumination model with boundary enhancement and view-dependent transparency. Stepping is done by a discrete number of intervals directly associated to octree levels. It uses a compact precomputed 2D transfer function, using the octree level for the second dimension to adjust opacity and color weighting [S11].

## Operating characteristics
*   **Time Complexity:** Depends on the distribution of detail. In homogeneous regions, complexity approaches $O(1)$ per pixel due to large steps or skipping. In high-detail regions, it approaches uniform sampling complexity $O(N)$ [S3, unofficial][S5].
*   **Memory Complexity:** Low overhead for opacity/gradient methods. Variance-based methods require storing variance metrics per block [S2, unofficial].
*   **Measured Performance:** On the Asian Dragon dataset (512x256x256), with brick size 32 and adaptive sampling ($r_1=8r_0$), frame rates are 19.2 fps at sampling rate 0.25, 13.8 fps at 0.5, 10.2 fps at 1, and 6.9 fps at 2 [S6]. Adaptive sampling with bricking achieves 80-85% of the performance of rendering without bricking and without adaptive sampling [S6].
*   **Strengths:** Significant speedup in empty space or homogeneous regions; improved quality in high-detail areas; reduced cache misses when using discrete rates [S6].
*   **Limitations:** Potential for thread divergence if not quantized; risk of missing thin structures if step size is not bounded by gradient [S6]; complexity in implementing for AMR data [S9].
*   **When to Use:** Large volumes with significant empty space or smooth regions; interactive rendering where frame rate stability is needed; isosurface rendering with thin features.
*   **When Not to Use:** Uniform, high-detail volumes where adaptive steps provide little benefit; scenarios requiring guaranteed intersection detection for extremely thin structures without careful gradient bounding [S6].

## Background
Adaptive sampling originated as a response to the inefficiency of uniform sampling in volume rendering, where most of the volume is empty or homogeneous [S1, S3, unofficial]. Early work by [S1, unofficial] highlighted that uniform sampling assumes homogeneity, leading to artifacts or wasted computation. [S6] introduced discrete adaptive sampling to address GPU thread coherence issues, a critical insight for hardware implementation. [S2, unofficial] applied adaptive sampling to compressive rendering, using variance analysis to guide ray casting. More recently, [S9] and [S10, unofficial] have extended adaptive sampling to handle AMR data and Monte Carlo convergence, respectively.
