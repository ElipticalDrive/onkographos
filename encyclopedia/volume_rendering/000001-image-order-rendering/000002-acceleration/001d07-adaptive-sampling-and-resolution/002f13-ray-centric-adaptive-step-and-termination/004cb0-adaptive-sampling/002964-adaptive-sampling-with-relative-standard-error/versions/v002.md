# Adaptive Sampling with Relative Standard Error

Also called: Noise-Threshold Adaptive Sampling

## Overview
An adaptive sampling strategy that tracks per-pixel luminance squares to estimate relative standard error, stopping converged pixels and skipping noisy neighborhoods [S1, unofficial]. It differs from [Adaptive Sampling](1385-adaptive-sampling.md) by using statistical error metrics rather than geometric proximity to the isosurface to determine sampling rates, and from [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md) by operating in image order per-pixel rather than modifying the underlying voxel data structure [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Per-pixel luminance samples accumulated in a film buffer, and a noise threshold parameter [S1, unofficial].
*   **Output:** A convergence mask indicating which pixels require further sampling and which are converged [G].

**Data Structures:**
*   **Film Buffer:** Stores per-pixel accumulated luminance $L$ and accumulated luminance squares $L^2$ [S1, unofficial]. The exact bit packing and field sizes are not given in the sources [G].

**Steps:**
1.  **Accumulate Samples:** For each new sample ray contributing to a pixel, update the accumulated luminance $L$ and the accumulated luminance squares $L^2$ in the film buffer [S1, unofficial].
2.  **Estimate Error:** Calculate the relative standard error (RSE) for each pixel from the tracked luminance and luminance squares [S1, unofficial].
3.  **Final Render Termination:** In final (non-progressive) renders, check convergence every 8 samples. If a pixel is converged, stop sampling it [S1, unofficial].
4.  **Progressive Pass Skipping:** In progressive passes, examine the 3x3 neighborhood of each pixel. Skip sampling for pixels whose 3x3 neighborhood is under the noise threshold [S1, unofficial].

**Parameters:**
*   **Noise Threshold:** The RSE value below which a pixel is considered converged [S1, unofficial]. Not given in the sources [G].
*   **Check Interval:** 8 samples for final renders [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Tracking luminance squares can lead to numerical instability if the accumulated values become very large or if the variance is small relative to the mean [G].
*   **Boundaries:** The 3x3 neighborhood check at image boundaries requires handling pixels with fewer than 8 neighbors [G].
*   **Degenerate Input:** Pixels with zero luminance (e.g., pure black) may cause division by zero in RSE calculation [G].

**Pseudocode:**
```python
def compute_rse(luminance, luminance_squares, n):
    if n == 0:
        return 0.0
    mean = luminance / n
    mean_sq = luminance_squares / n
    variance = mean_sq - mean * mean
    if variance < 0.0:
        variance = 0.0
    std_dev = variance ** 0.5
    if mean == 0.0:
        return 0.0
    return std_dev / (mean * (n ** 0.5))

def render_adaptive(width, height, noise_threshold, is_progressive, check_interval=8):
    luminance = [[0.0] * width for _ in range(height)]
    luminance_squares = [[0.0] * width for _ in range(height)]
    sample_count = [[0] * width for _ in range(height)]
    converged = [[False] * width for _ in range(height)]
    sample_counter = 0

    while True:
        sample_counter += 1
        all_done = True
        for y in range(height):
            for x in range(width):
                if converged[y][x]:
                    continue
                all_done = False
                if is_progressive:
                    # Check 3x3 neighborhood
                    neighborhood_ok = True
                    for dy in (-1, 0, 1):
                        for dx in (-1, 0, 1):
                            nx, ny = x + dx, y + dy
                            if 0 <= nx < width and 0 <= ny < height:
                                if not converged[ny][nx]:
                                    neighborhood_ok = False
                                    break
                        if not neighborhood_ok:
                            break
                    if neighborhood_ok:
                        continue
                # Accumulate sample
                val = sample_ray(x, y)
                luminance[y][x] += val
                luminance_squares[y][x] += val * val
                sample_count[y][x] += 1
                # Check convergence for final renders
                if not is_progressive and sample_counter % check_interval == 0:
                    rse = compute_rse(luminance[y][x], luminance_squares[y][x], sample_count[y][x])
                    if rse <= noise_threshold:
                        converged[y][x] = True
        if all_done:
            break
```

## Subtopics

### Monte Carlo Averaging for Noise Reduction
A technique used in conjunction with adaptive sampling to reduce Monte Carlo noise by rendering the predicted color image multiple times and averaging the results [S2]. Specifically, 64 secondary rays are used per primary ray, and the image is rendered 32 times and averaged [S2]. A pitfall is that renderings from baselines like TensoIR may still contain residual noise despite averaging, indicating that sample counts and importance sampling schemes significantly affect final quality [S2].

## Operating characteristics
*   **Time and Memory Complexity:** Memory complexity is $O(W \times H)$ for the film buffer storing luminance, luminance squares, and sample counts [G]. Time complexity is proportional to the number of samples taken by non-converged pixels [G].
*   **Measured Performance:** On a showcase scene at the same mean samples per pixel (spp), the relative mean squared error (relMSE) was 0.0036 for uniform sampling (extrapolated) versus 0.0024 for adaptive sampling [S1, unofficial].
*   **Strengths:** Reduces computational overhead by stopping sampling on converged pixels and skipping noisy neighborhoods in progressive passes [S1, unofficial].
*   **Limitations:** Requires tracking additional state (luminance squares) per pixel. The effectiveness depends on the choice of noise threshold [G].
*   **When to Use:** When visual quality is prioritized and computational resources are limited, especially in scenes with varying levels of noise [G].
*   **When Not to Use:** When a strict time limit is imposed and the overhead of checking convergence is too high, or when the scene has uniform noise characteristics where uniform sampling might be simpler [G].
