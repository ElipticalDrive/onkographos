# Adaptive Sampling for Interaction

Also called: Adaptive Sampling for Interactive Volume Rendering, Dynamic Sampling Rate, Interaction-aware Adaptive Sampling, Two-rate Interaction Sampling

## Overview
Adaptive Sampling for Interaction is a technique designed to maintain real-time interactivity during user input (such as camera movement or transfer function adjustment) by temporarily lowering the volume sampling rate, then restoring high fidelity once the interaction ceases [S1, S2]. It differs from spatially adaptive methods (like [Adaptive Sampling](1385-adaptive-sampling.md)) by modulating the global sampling density based on temporal user activity rather than local scene complexity, and from [Adaptive Preintegration Termination Criteria](9804-adaptive-preintegration-termination-criteria.md) by focusing on the trade-off between frame latency and visual smoothness during dynamic exploration [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Volume dataset, current transfer function, user interaction state (active/inactive), target high sampling rate ($N_{high}$).
*   **Output:** Rendered image with adaptive sampling density.

**Data Structures:**
*   **Interaction State:** A boolean flag or timer indicating if the user is currently interacting.
*   **Sampling Rate:** A scalar value representing samples per voxel.

**Parameters:**
*   **High Sampling Rate ($N_{high}$):** The target fidelity level. Typical values are 6 to 10 samples per voxel [S1, S2].
*   **Low Sampling Rate ($N_{low}$):** The reduced rate during interaction. Not given in the sources.
*   **Thresholds:** Criteria for switching between states. Not given in the sources.

**Steps:**
1.  **Detect Interaction:** Monitor user input events (mouse, keyboard). If an event occurs, set interaction state to `active`. If no events occur for a duration $T_{idle}$, set state to `inactive`.
2.  **Select Sampling Rate:**
    *   If `state == active`, set current sampling rate $N = N_{low}$.
    *   If `state == inactive`, set current sampling rate $N = N_{high}$.
3.  **Render:** Perform volume rendering using the selected sampling rate $N$. This involves casting rays and evaluating the volume integral with step size $\Delta t$ derived from $N$ relative to the voxel dimensions.
4.  **Update:** Repeat for each frame.

**Pseudocode:**
```python
# Constants
N_HIGH = 8  # Typical value from [S1, S2]
N_LOW = ?   # Not given in the sources
IDLE_TIMEOUT = ? # Not given in the sources

# State
interaction_active = False
last_interaction_time = 0

def render_frame(time):
    global interaction_active, last_interaction_time
    
    # Step 1: Detect Interaction
    if user_has_input():
        interaction_active = True
        last_interaction_time = time
    
    # Check for idle period to restore high quality
    if interaction_active and (time - last_interaction_time > IDLE_TIMEOUT):
        interaction_active = False
        
    # Step 2: Select Sampling Rate
    if interaction_active:
        current_samples_per_voxel = N_LOW
    else:
        current_samples_per_voxel = N_HIGH
        
    # Step 3: Render
    image = volume_render(volume_data, transfer_function, current_samples_per_voxel)
    return image
```

**Edge Cases and Pitfalls:**
*   **Transition Artifacts:** Sudden switching between $N_{low}$ and $N_{high}$ may cause visible popping. A smooth interpolation of the sampling rate or resolution is not specified in the sources [G].
*   **Idle Timeout:** The choice of $T_{idle$ is critical. Too short, and the system flickers between qualities; too long, and the user experiences lag during exploration. Not given in the sources.

## Subtopics

### [Interaction Render Scale Damping](8891-interaction-render-scale-damping.md)
A strategy that dynamically reduces render resolution (not just sampling rate) during interaction to maintain frame rate, then restores it. It differs by operating on image resolution rather than volume sampling density and is designed to decouple performance from input latency. It builds on [Adaptive Sampling for Interaction](5643-adaptive-sampling-for-interaction.md).

## Operating characteristics
*   **Time Complexity:** Rendering time is proportional to the number of samples. At the high sampling rate (6-10 samples/voxel), frame updates take nearly two seconds on an Octane2 and nearly one second on a GeForce3 [S1, S2]. Lowering the rate during interaction reduces this time proportionally, enabling interactivity.
*   **Memory Complexity:** No additional memory overhead beyond the volume data and standard rendering buffers.
*   **Strengths:** Preserves high visual fidelity when the user is not interacting, which is crucial for detailed exploration of boundaries. Provides effective feedback during interaction by maintaining surface location and size, even if the surface appears coarser [S1, S2].
*   **Limitations:** Visual quality degrades during interaction. The method assumes that surface location is sufficient for guidance, which may not hold for all transfer functions or data types.
*   **When to use:** Interactive volume exploration where high fidelity is required for final inspection but latency is unacceptable during navigation.
*   **When not to use:** Applications requiring continuous high-fidelity visualization without user pauses, or where the "coarse" appearance during interaction is unacceptable.

## Background
This technique was introduced in the context of interactive volume rendering using multi-dimensional transfer functions [S1, S2]. The authors noted that high sampling rates (6-10 samples per voxel) were necessary to render boundaries smoothly, but this led to frame times of nearly one to two seconds on contemporary hardware (Octane2, GeForce3) [S1, S2]. To address this, they proposed lowering the sample rate during user interaction and restoring it afterward, leveraging the fact that surface size and location remain apparent even at lower rates [S1, S2].
