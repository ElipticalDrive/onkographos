# VF-NeRF Rendering Pipeline

Also called: Coarse-Fine Volume Rendering with Vector Fields, Vector Field NeRF Rendering

## Overview
The VF-NeRF rendering pipeline is a two-stage volume rendering method that uses a vector field network to predict surface normals, features, and Jacobians for density estimation and shading. It differs from standard NeRF by deriving density from the directional derivative of the vector field rather than a direct scalar field prediction, enabling explicit surface representation within the implicit volume. It builds on [Two-stage NeRF Rendering](925-two-stage-nerf-rendering.md) by integrating vector field-based density computation into the coarse and fine sampling passes.

## How it works
**Inputs:**
- Pixel coordinates, camera pose (extrinsics), and camera intrinsics.
- Pre-trained Vector Field Network (VFNet) and optional Rendering Network.
- Configuration parameters: `numerical_jacobian` (bool), `rendering` (string: "volsdf" or "nerf"), `feature_vector_dims` (int).
- Ray sampler configurations for coarse and fine passes.

**Outputs:**
- RGB image.
- Depth map.
- Accumulated alpha (optional).

**Data Structures:**
- `vf_output`: Tensor of shape `(-1, C)` where $C = 3 + \text{feature\_vector\_dims} + J$.
  - Columns 0-2: Surface normals $\mathbf{n}$.
  - Columns 3 to $\text{feature\_vector\_dims}+2$: Feature vectors $\mathbf{f}$.
  - Columns $\text{feature\_vector\_dims}+3$ onward: Jacobian entries $J$.
- `points_coarse`: Tensor of shape `(-1, 3)` containing 3D points along rays.
- `z_vals`: Tensor of shape `(-1, 1)` containing depth values along rays.
- `ray_dirs`: Tensor of shape `(-1, 3)` containing ray directions.

**Parameters:**
- `numerical_jacobian`: If true, compute directional derivatives numerically; otherwise, use analytical Jacobian from network output if in training mode.
- `rendering`: Backend for volume rendering integration ("volsdf" or "nerf").
- `feature_vector_dims`: Number of feature channels in the vector field output.
- `fine_sampler.N_samples`: Number of fine samples per ray.
- `fine_sampler.max_samples`: Maximum allowed fine samples to prevent memory overflow.

**Steps:**

1. **Ray Generation:** Compute ray origins $\mathbf{o}$ and directions $\mathbf{d}$ from pixel coordinates, camera pose, and intrinsics. Reshape to $(-1, 3)$.
2. **Coarse Sampling:** Sample coarse 3D points $\mathbf{p}_{\text{coarse}}$ along rays using the ray sampler, producing `points_coarse` and `z_vals`. Flatten `points_coarse` to $(-1, 3)$.
3. **Direction Repetition:** Repeat ray directions to match the number of coarse samples. Unsqueeze `ray_dirs` and repeat along the sample dimension, reshaping to $(-1, 3)$.
4. **Vector Field Forward Pass:** Forward `points_coarse` through the coarse vector field network. Extract `vf_output`.
   - Normals $\mathbf{n} = \text{vf\_output}[:, 0:3]$.
   - Features $\mathbf{f} = \text{vf\_output}[:, 3 : 3 + \text{feature\_vector\_dims}]$.
   - Jacobian $J = \text{vf\_output}[:, 3 + \text{feature\_vector\_dims} :]$.
5. **Directional Derivative Computation:** Compute the directional derivative $D_{\mathbf{d}} = \mathbf{n} \cdot \mathbf{d}$ (or equivalent via Jacobian).
   - If `numerical_jacobian` is enabled, compute numerically.
   - Else if network is in training mode, compute analytically using $J$.
   - Otherwise, set $D_{\mathbf{d}} = \text{None}$ [G: This state requires a null check before norm computation].
6. **Density Estimation:** Compute density $\sigma$ from coarse normals and repeated ray directions using `get_density()`. The exact formula depends on the vector field definition, typically $\sigma = \max(0, -\nabla \cdot \mathbf{V})$ or derived from the normal's divergence along the ray.
7. **Coarse Volume Rendering:** Compute coarse volume rendering weights $\alpha_i$ and accumulated color/depth.
   - If `rendering` == "volsdf", call `volsdf_volume_rendering(z_vals, density, normalize_rendering)`.
   - If `rendering` == "nerf", call `nerf_volume_rendering(z_vals, density, normalize_rendering)`.
8. **Fine Sampling (Optional):** If fine sampling is enabled, sample fine points $\mathbf{p}_{\text{fine}}$ using coarse `z_vals` and weights. Limit fine samples to $N_{\text{fine}} = \min(\text{fine\_sampler.N\_samples}, \text{fine\_sampler.max\_samples})$.
9. **Fine Vector Field Forward Pass:** Forward `points_fine` through the fine vector field network (if present) or coarse network. Extract normals, features, and Jacobian.
10. **Fine Density and Weights:** Compute density for fine points. Combine coarse and fine weights.
11. **Final Rendering:** Compute final RGB and depth maps by weighting predicted RGB and `z_vals` by the combined weights along the sample dimension.
12. **Background Correction:** Accumulate weights $\alpha_{\text{acc}}$. Add $(1 - \alpha_{\text{acc}}) \times \mathbf{c}_{\text{bg}}$ to RGB values, where $\mathbf{c}_{\text{bg}}$ is typically white $(1, 1, 1)$.

                z_vals_fine, density_fine, normalize_rendering
            )

            alpha_fine, rgb_fine, depth_fine = nerf_volume_rendering(

            )

        # Assuming alpha_coarse and alpha_fine are aligned or need reshaping
        # Standard two-stage combination:
        alpha_combined = alpha_coarse + alpha_fine * (1 - alpha_coarse)
        rgb_combined = rgb_coarse + rgb_fine * (1 - alpha_coarse)
        depth_combined = depth_coarse + depth_fine * (1 - alpha_coarse)
    else:
        alpha_combined = alpha_coarse
        rgb_combined = rgb_coarse
        depth_combined = depth_coarse
        
    # 7. Background Correction
    accumulated_alpha = torch.sum(alpha_combined, dim=-1, keepdim=True)
    rgb_final = rgb_combined + (1 - accumulated_alpha) * torch.ones_like(rgb_combined)
    
    return rgb_final, depth_combined, accumulated_alpha

**Edge Cases and Pitfalls:**
- **Null Directional Derivatives:** If `numerical_jacobian` is disabled and the network is not in training mode, directional derivatives may be `None`. A null check is required before computing norms or densities [S1, unofficial].
- **Memory Overflow:** Fine sampling must cap the number of samples at `max_samples` to prevent GPU memory overflow [S1, unofficial].
- **Jacobian Layout:** The Jacobian layout in `vf_output` starts at index `feature_vector_dims + 3`. Incorrect slicing will lead to invalid density calculations.

## Operating characteristics
- **Time Complexity:** $O(N_{\text{coarse}} + N_{\text{fine}})$ per ray, where $N$ is the number of samples. The vector field forward pass dominates computation.
- **Memory Complexity:** $O(N_{\text{coarse}} + N_{\text{fine}})$ for storing intermediate tensors. Fine sampling increases memory usage proportionally to the number of fine samples.
- **Strengths:** Explicit surface representation via vector field normals; efficient density estimation without explicit MLP for density; supports both VOLSDF and standard NeRF rendering backends.
- **Limitations:** Requires careful tuning of `feature_vector_dims` and Jacobian computation; fine sampling cap may limit quality if `max_samples` is too low; numerical Jacobian computation is slower.
- **When to Use:** When explicit surface normals are desired for shading or mesh extraction; when integrating with VOLSDF rendering.
- **When Not to Use:** When high-quality texture synthesis is the primary goal and surface geometry is less critical; when computational resources are extremely limited and fine sampling is disabled.

## Background
VF-NeRF was introduced by Albert Gassol et al. as an unofficial implementation leveraging vector fields for NeRF rendering. It extends the NeRF framework by predicting a vector field instead of a scalar density and color, allowing for explicit surface normal estimation. The method supports both analytical and numerical Jacobian computation for density derivation.
