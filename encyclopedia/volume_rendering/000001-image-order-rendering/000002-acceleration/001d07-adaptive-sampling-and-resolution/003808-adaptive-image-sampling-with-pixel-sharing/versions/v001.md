# Adaptive Image Sampling with Pixel Sharing

Also called: adaptive sampling with synchronization

## Overview
Adaptive Image Sampling with Pixel Sharing is a parallel volume rendering acceleration technique that reduces computational cost by casting rays only from the corners of square image regions and interpolating the interior [S1]. It solves the problem of redundant ray tracing in smooth volume areas while addressing the synchronization overhead inherent in parallel adaptive sampling, where adjacent regions share corner pixels [S1]. Unlike static partitioning or methods that replicate ray tracing for synchronization, this method communicates pixel values to avoid redundant computation, making it suitable for MIMD shared-memory architectures [S1].

## How it works
The method partitions the image plane into square sample regions and uses a recursive subdivision strategy based on local image complexity. It handles parallel execution by managing dependencies between adjacent regions that share corner pixels.

### Inputs and Outputs
*   **Inputs:**
    *   Volume data (voxel array).
    *   Precomputed normals, opacities, and an octree structure [S1].
    *   Lookup table for shading (color as a function of local voxel gradient) [S1].
    *   Parameters: $w_{max}$ (initial region side length in pixels), $T$ (color threshold).
    *   Number of processors $P$ [S1].
*   **Outputs:**
    *   Final rendered image with pixel values for all regions.

### Data Structures
*   **Image Plane:** Partitioned into square sample regions of size $w_{max} \times w_{max}$ initially [S1].
*   **Task Queue:** A queue of image tiles/regions to be processed by each processor [S1].
*   **Local Wait Queue:** A per-processor queue storing the state of sample regions that cannot be fully processed because some corner pixels are currently being traced by other processors [S1].
*   **Pixel State:** Tracks whether a corner pixel has been traced, is currently being traced, or is untraced [S1].

### Algorithm Steps
1.  **Initialization:** Divide the image plane into square sample regions of size $w_{max} \times w_{max}$ [S1]. Distribute image tiles to processor task queues [S1].
2.  **Ray Tracing Corners:** For a given sample region, identify the four corner pixels. Ray trace only those corner pixels that have not already been traced by adjacent regions and are not currently being traced by other processors [S1].
3.  **Complexity Measurement:** Compute the image complexity of the sample region by calculating the color difference among the corner pixels that have been successfully ray traced. Exclude pixels currently being traced by other processors from this calculation [S1].
4.  **Decision:**
    *   If the color difference exceeds the user-selected color threshold $T$, subdivide the sample region into four smaller square subregions and recursively apply the algorithm to them [S1].
    *   If the color difference does not exceed $T$, bilinearly interpolate the untraced pixels in the region from the traced corner pixels [S1].
5.  **Handling Dependencies (Wait Queue):**
    *   If subdivision is required but some corner pixels are still being traced by other processors, or if subdivision is not required but some pixels are still being traced, store the sample region's state in the local wait queue [S1].
    *   If all necessary corner pixels are available and processed, proceed to the next region [S1].
6.  **Completion Phase:** After all task queues are empty, process the local wait queues [S1].
7.  **Re-evaluation:** For each sample region in the wait queue, re-evaluate complexity (Step 3).
    *   If corner pixels are still being traced, busy wait until they are ray traced [S1].
    *   Once available, proceed with the decision logic (Step 4) [S1].

def parallel_execution_loop(processor_id, task_queue, wait_queue, shared_pixel_state):
    """
    Main loop for a processor.
    """
    while not task_queue.empty():
        region = task_queue.pop()
        result = adaptive_sampling_with_pixel_sharing(region, w_max, threshold, shared_pixel_state)

### Parameters
*   $w_{max}$: The side length in pixels of the initial square sample regions [S1].
*   Color threshold ($T$): A user-selected threshold for color difference used to determine if a sample region should be subdivided [S1].

### Edge Cases and Pitfalls
*   **Pixel Sharing Dependencies:** Adjacent sample regions share corner pixel values. If adjacent tiles are processed by different processors, synchronization is required [S1].
*   **Synchronization Overhead:** The method minimizes replicated ray tracing by communicating pixel values. Synchronization overhead is small because task queue partitioning usually results in adjacent image tiles being ray traced by the same processor [S1].
*   **Partial Information:** When measuring complexity, pixels currently being traced by other processors are excluded. This may lead to inaccurate complexity measurements if too many corners are unavailable [S1].

## Operating characteristics
*   **Time Complexity:** Reduces total ray tracing cost by avoiding resampling in transparent or smooth regions [S1]. The cost depends on the image complexity and the threshold $T$.
*   **Memory Complexity:** Requires storage for the volume data, octree, lookup table, and pixel state tracking [S1].
*   **Performance:** Implemented on the DASH (Directory Architecture for SHared memory) Multiprocessor, a scalable shared-memory MIMD machine [S1].
*   **Strengths:** Avoids the cost of replicated ray tracing; synchronization overhead is small due to spatial locality of task queues [S1].
*   **Limitations:** Requires communication of 3D voxel values (a potential disadvantage of parallel ray tracing algorithms in general) [S1].

## Background
The method was implemented on the DASH (Directory Architecture for SHared memory) Multiprocessor, a scalable shared-memory MIMD machine under construction in the Computer Systems Laboratory at Stanford University [S1]. It was designed to support a wide variety of applications, including volume rendering [S1]. The approach builds on earlier work in adaptive sampling and parallel ray tracing, specifically addressing the synchronization issues that arise when partitioning adaptive regions across multiple processors [S1].
