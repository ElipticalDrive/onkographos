# Uniforms::Iteration

Also called: Iteration Uniform Update, Debug Uniform Synchronization

## Overview
`Uniforms::Iteration` is a utility method within the Interactive SDF Renderer that synchronizes rendering parameters with the current iteration count of the adaptive sampling loop. It updates resolution multipliers, pixel growth factors, step counts for sphere tracing and shadows, and ambient occlusion settings based on the progression of the render. It is distinct from the core sampling logic by focusing on the dynamic adjustment of shader uniforms and debug visualization parameters rather than ray marching or accumulation.

## How it works
**Inputs and Outputs:**
- Input: Current iteration index $it$, debug configuration object `debug` (containing functions and ambient settings), and current camera dimensions $w, h$.
- Output: Updated values in the `Uniforms` structure, specifically `resolution_multipiers`, `camera`, `sphere_trace`, `shadows`, `user_itercount`, and `ambient_occolution`.

**Data Structures:**
The method assumes the existence of a `debug` object with the following layout:
- `debug.functions`: An object providing callable functions for dynamic parameters.
  - `resolution_multipier(t)`: Returns a float multiplier for resolution at iteration $t$.
  - `spheretrace_stepcount(t)`: Returns an integer step count for sphere tracing at iteration $t$.
  - `shadow_stepcount(t)`: Returns an integer step count for shadow rays at iteration $t$.
  - `user_itercount(t)`: Returns an integer user-defined iteration count at iteration $t$.
- `debug.ambient`: An object containing ambient occlusion settings.
  - `start_iternum`: The iteration number at which AO begins.
  - `algorithm`: An integer offset selecting the AO algorithm variant.
- `debug.view`: An object containing view settings.
  - `fow_mult`: A float multiplier for the field of view normalization.

**Numbered Steps:**
1. **Update Texture Resolution:** Set the texture resolution multiplier to match the camera resolution multiplier.
   $$resolution\_multipiers.texture = resolution\_multipiers.camera$$
2. **Calculate Pixel Growth:** Compute the pixel growth factor based on the current resolution and a debug multiplier $m$.
   $$m = debug.functions.resolution\_multipier(it)$$
   $$camera.pixel\_growth = \frac{1.41421356237f}{\|glm::vec2(w \times m, h \times m)\|} \times 2.f$$
   Where $\| \cdot \|$ denotes the Euclidean norm (length) of the vector.
3. **Update Camera Resolution Multiplier:** Set the camera resolution multiplier to $m$.
   $$resolution\_multipiers.camera = glm::vec2(m)$$
4. **Update Normalized Size (Raw):** Set the camera's normalized size to the scaled dimensions.
   $$camera.normalized\_size = glm::vec2(w \times m, h \times m)$$
5. **Normalize and Scale by FOV:** Normalize the normalized size vector and scale it by the field of view multiplier.
   $$camera.normalized\_size = glm::normalize(camera.normalized\_size) \times debug.view.fow\_mult$$
6. **Set Sphere Trace Step Count:** Update the sphere trace step count using the debug function.
   $$sphere\_trace.stepcount = (int)debug.functions.spheretrace\_stepcount(it)$$
7. **Set Shadow Step Count:** Update the shadow ray step count using the debug function.
   $$shadows.stepcount = (int)debug.functions.shadow\_stepcount(it)$$
8. **Set User Iteration Count:** Update the user iteration count using the debug function.
   $$user\_itercount = (int)debug.functions.user\_itercount(it)$$
9. **Calculate AO Iteration Number:** Determine the effective iteration number for ambient occlusion.
   $$ambient\_occolution.ao\_iternum = it - debug.ambient.start\_iternum$$
10. **Select AO Algorithm:** Choose the AO algorithm based on whether the current iteration has reached the start threshold.
    $$if \ it \le debug.ambient.start\_iternum \ then \ Uniforms::AMBIENT\_0 \ else \ Uniforms::AMBIENT\_0 + debug.ambient.algorithm$$

**Pseudocode:**
```python
def uniforms_iteration_update(it, w, h, debug, uniforms):
    # Step 1: Update texture resolution
    uniforms.resolution_multipiers.texture = uniforms.resolution_multipiers.camera

    # Step 2: Calculate pixel growth
    m = debug.functions.resolution_multipier(it)
    scaled_dims = vec2(w * m, h * m)
    # Note: 1.41421356237f is sqrt(2)
    uniforms.camera.pixel_growth = (1.41421356237f / length(scaled_dims)) * 2.0f

    # Step 3: Update camera resolution
    uniforms.resolution_multipiers.camera = vec2(m)

    # Step 4: Update normalized size
    uniforms.camera.normalized_size = scaled_dims

    # Step 5: Normalize and scale by FOV
    uniforms.camera.normalized_size = normalize(uniforms.camera.normalized_size) * debug.view.fow_mult

    # Step 6: Set sphere trace step count
    uniforms.sphere_trace.stepcount = int(debug.functions.spheretrace_stepcount(it))

    # Step 7: Set shadow step count
    uniforms.shadows.stepcount = int(debug.functions.shadow_stepcount(it))

    # Step 8: Set user iteration count
    uniforms.user_itercount = int(debug.functions.user_itercount(it))

    # Step 9: Calculate AO iteration number
    uniforms.ambient_occolution.ao_iternum = it - debug.ambient.start_iternum

    # Step 10: Select AO algorithm
    if it <= debug.ambient.start_iternum:
        uniforms.ambient_occolution.algorithm = AMBIENT_0
    else:
        uniforms.ambient_occolution.algorithm = AMBIENT_0 + debug.ambient.algorithm
```

**Parameters with Typical Values:**
- `1.41421356237f`: Approximation of $\sqrt{2}$, used to maintain aspect ratio or diagonal consistency in pixel growth calculation.
- `AMBIENT_0`: Base constant for the first ambient occlusion algorithm.

**Edge Cases and Pitfalls:**
- **Division by Zero:** If $w \times m$ and $h \times m$ are both zero, the length in Step 2 is zero, causing division by zero. This is unlikely in practice as $w, h > 0$ and $m$ is typically $\ge 1$.
- **Negative Iteration:** If $it < debug.ambient.start\_iternum$, `ao_iternum` will be negative. The AO algorithm must handle negative iteration indices or clamp them.
- **Precision:** The pixel growth calculation uses floating-point arithmetic. Small errors in $m$ can accumulate, but the normalization in Step 5 mitigates scale drift.

## Operating characteristics
- **Time Complexity:** $O(1)$ per iteration. The method performs a fixed number of arithmetic operations and function calls.
- **Memory Complexity:** $O(1)$. No additional memory is allocated; it updates existing uniform structures.
- **Strengths:** Provides a centralized point for updating dynamic rendering parameters, ensuring consistency between debug visualization and actual rendering.
- **Limitations:** Tightly coupled to the `debug` object structure. If the debug functions change signature, this method must be updated.
- **When to Use:** When implementing iterative adaptive sampling where parameters like resolution and step counts need to evolve over iterations.
- **When Not to Use:** For static rendering passes where parameters do not change.

## Background
`Uniforms::Iteration` originates from the **Interactive SDF Renderer** project by Csabix [S1, unofficial]. It is part of the debug and control infrastructure that allows real-time adjustment of rendering parameters during the iterative sampling process. The method reflects the specific implementation choices of this renderer, particularly the use of debug functions to drive parameter evolution and the specific pixel growth formula derived from the renderer's camera model.
