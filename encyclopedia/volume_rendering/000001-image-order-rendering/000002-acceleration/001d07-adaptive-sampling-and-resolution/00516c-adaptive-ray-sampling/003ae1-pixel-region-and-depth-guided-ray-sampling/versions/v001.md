# Pixel Region and Depth Guided Ray Sampling


## Overview
Pixel Region and Depth Guided Ray Sampling is a ray sampling strategy that increases sampling probability in pixel areas exhibiting significant color and depth variation, reducing redundant rays in flat regions to accelerate network convergence and improve geometry perception [S1]. It sets itself apart from uniform sampling by dynamically allocating ray density based on scene complexity, and from sibling methods like [Coarse-to-Fine NeRF](3406-coarse-to-fine-nerf.md) by utilizing explicit depth boundaries and color variance rather than hierarchical coarse-to-fine refinement or quadtree subdivision [S1].

## How it works
**Inputs:**
- Set of $N$ training source images $\mathcal{I} = \{I_1, I_2, ..., I_N\}$ [S1].
- Camera parameters for each source image (intrinsic and extrinsic) to define ray origins and directions [S1].
- A depth estimation module (specifically from the ENeRF framework) to provide rough depth information [S1].
- A cost volume from the ENeRF framework to obtain depth information for each pixel [S1].

**Outputs:**
- A set of sampled rays $\mathbb{R}_i$ for each image $I_i$, where the density of rays varies across the image plane [S1].
- Rendered pixel colors and densities via volume rendering [S1].

**Data Structures:**
- **Image $I_i$**: 2D array of color values with height $H_i$ and width $W_i$ [S1].
- **Depth Map $D_i$**: 2D array of estimated depth values for each pixel $(u, v)$, derived from the ENeRF cost volume [S1].
- **Sampling Probability Map $P_i$**: 2D array where $P_i(u, v)$ represents the probability of sampling a ray at pixel $(u, v)$ [S1].

**Parameters:**
- $N$: The number of trained images (source views) [S1].
- $M$: The total number of sampled rays per image [S1].
- $\Theta$: The network parameters (MLP weights) optimized by minimizing the color error [S1].
- $H_i, W_i$: Height and width of image $I_i$ [S1].

**Steps:**
1. **Depth Estimation**: Obtain rough depth information for the scene using the depth estimation module from the ENeRF framework [S1]. Specifically, leverage the cost volume from ENeRF to obtain depth information for each pixel $(u, v)$ [S1]. Let $D_i(u, v)$ be the estimated depth at pixel $(u, v)$ in image $I_i$ [S1].

2. **Calculate Sampling Probability**: Calculate the sampling probability $P_i(u, v)$ for each pixel $(u, v)$ based on its color value and the estimated depth information [S1].
   - **Color Variation Component**: Compute the local color variance or gradient magnitude at pixel $(u, v)$. High variance indicates significant color variation [S1]. Let $C_i(u, v)$ be a measure of color variation (e.g., gradient norm) at $(u, v)$ [S1].
   - **Depth Variation Component**: Compute the local depth variance or gradient magnitude at pixel $(u, v)$. High variance indicates marked geometric depth variation [S1]. Let $G_i(u, v)$ be a measure of depth variation (e.g., gradient norm of $D_i$) at $(u, v)$ [S1].
   - **Combined Probability**: Combine these measures to form the sampling probability. A common implementation (implied by the description of "significant color and depth variations") is to sum or weight these components:
     $$ P_i(u, v) = \alpha C_i(u, v) + \beta G_i(u, v) $$
     where $\alpha$ and $\beta$ are weighting factors. If not specified, assume equal weighting or normalization [G]. Normalize $P_i(u, v)$ across all pixels in the image to form a probability distribution:
     $$ \hat{P}_i(u, v) = \frac{P_i(u, v)}{\sum_{u', v'} P_i(u', v')} $$
     [S1].

3. **Ray Sampling**: During ray sampling, sample $M$ rays for image $I_i$ according to the probability distribution $\hat{P}_i(u, v)$ [S1].
   - Use stratified sampling or cumulative distribution function (CDF) sampling to select $M$ pixel coordinates $(u_k, v_k)$ for $k = 1, ..., M$ [G].
   - For each selected pixel $(u_k, v_k)$, generate a ray $r_i^k$ originating from the camera center and passing through $(u_k, v_k)$ [S1].
   - This results in additional rays being sampled in pixel areas exhibiting substantial color variation and regions where geometric depth varies markedly [S1].

4. **Volume Rendering**: Perform volume rendering using the network to output colors and densities along the sampled rays [S1].
   - For each ray $r_i^k$, sample $K$ points along the ray [S1].
   - Query the neural network $F_\Theta$ at each point to obtain density $\sigma$ and color $c$ [S1].
   - Compute the rendered color $\hat{c}_i^k$ using standard volume rendering integration [S1].

5. **Loss Calculation and Optimization**: Minimize the volume rendering loss to update network parameters $\Theta$ [S1].
   - The optimization goal is:
     $$ \min_{\Theta} \mathcal{L} = \frac{1}{NM} \sum_{i=1}^{N} \sum_{k=1}^{M} \|V_{\Theta}(r_i^k) - c_i^k\|_2^2 $$
     where $c_i^k$ is the true color of the pixel corresponding to ray $r_i^k$ in image $I_i$, and $V_{\Theta}(r_i^k)$ is the rendered color [S1].

**Pseudocode:**

```python
import numpy as np

def calculate_color_gradient(image):
    """
    Calculate the gradient magnitude of an image to measure color variation.
    image: numpy array of shape (H, W, 3)
    returns: numpy array of shape (H, W)
    """
    # Convert to grayscale for simplicity or compute per-channel gradients
    # Using Sobel operators for gradient magnitude
    # This is a standard image processing operation [G]
    gray = np.mean(image, axis=2)
    # Compute gradients
    dy, dx = np.gradient(gray)
    magnitude = np.sqrt(dx**2 + dy**2)
    return magnitude

def calculate_depth_gradient(depth_map):
    """
    Calculate the gradient magnitude of a depth map to measure depth variation.
    depth_map: numpy array of shape (H, W)
    returns: numpy array of shape (H, W)
    """
    dy, dx = np.gradient(depth_map)
    magnitude = np.sqrt(dx**2 + dy**2)
    return magnitude

def sample_rays(probability_map, num_rays):
    """
    Sample pixel coordinates based on a probability map.
    probability_map: numpy array of shape (H, W) with values summing to 1
    num_rays: int, number of rays to sample
    returns: list of (u, v) tuples
    """
    H, W = probability_map.shape
    # Flatten the probability map
    flat_probs = probability_map.flatten()
    # Sample indices
    indices = np.random.choice(H * W, size=num_rays, p=flat_probs)
    # Convert flat indices to (u, v) coordinates
    u_coords = indices // W
    v_coords = indices % W
    return list(zip(u_coords, v_coords))

def pixel_region_depth_guided_sampling(images, depth_maps, num_rays_per_image):
    """
    Main sampling function.
    images: list of numpy arrays, each of shape (H, W, 3)
    depth_maps: list of numpy arrays, each of shape (H, W)
    num_rays_per_image: int, M
    returns: list of lists of rays, where each ray is defined by origin and direction
    """
    all_rays = []
    
    for i in range(len(images)):
        image = images[i]
        depth_map = depth_maps[i]
        H, W, _ = image.shape
        
        # Step 2: Calculate Sampling Probability
        # Color variation
        color_grad = calculate_color_gradient(image)
        # Depth variation
        depth_grad = calculate_depth_gradient(depth_map)
        
        # Combine variations (assuming equal weighting as not specified [G])
        # Add small epsilon to avoid division by zero
        epsilon = 1e-6
        probability_map = color_grad + depth_grad + epsilon
        
        # Normalize to form a probability distribution
        probability_map = probability_map / np.sum(probability_map)
        
        # Step 3: Ray Sampling
        sampled_pixels = sample_rays(probability_map, num_rays_per_image)
        
        # Generate rays for sampled pixels
        # Assuming pinhole camera model for simplicity [G]
        # Ray origin is camera center (0,0,0)
        # Ray direction is determined by pixel coordinates and camera intrinsics
        # This part depends on specific camera parameters which are assumed to be available [G]
        rays_for_image = []
        for u, v in sampled_pixels:
            # Placeholder for ray generation based on camera intrinsics
            # In a real implementation, this would use K^-1 * [u, v, 1] to get direction
            direction = np.array([u, v, 1.0]) # Simplified direction [G]
            origin = np.array([0.0, 0.0, 0.0]) # Simplified origin [G]
            rays_for_image.append((origin, direction))
            
        all_rays.append(rays_for_image)
        
    return all_rays
```

**Edge Cases and Pitfalls:**
- **Flat Regions**: In regions with no color or depth variation, the probability map may be uniform or near-zero, leading to under-sampling if not handled. The addition of epsilon in normalization prevents zero probabilities [G].
- **Depth Estimation Errors**: The method relies on the accuracy of the depth estimation module from ENeRF. Inaccurate depth estimates can lead to incorrect sampling probabilities, potentially missing important geometric details or oversampling noisy regions [S1].
- **Boundary Effects**: Gradient calculations at image boundaries may be less accurate. Padding or boundary handling should be considered in the gradient calculation step [G].

## Operating characteristics
- **Time Complexity**: The sampling step involves calculating gradients and sampling, which is $O(H \times W)$ per image for gradient calculation and $O(M \log(H \times W))$ or $O(M)$ for sampling depending on the sampling algorithm [G]. This is generally faster than uniform sampling if $M < H \times W$, as it reduces the number of rays processed by the neural network [S1].
- **Memory Complexity**: Requires storing the depth map and probability map for each image, which is $O(H \times W)$ per image [S1].
- **Measured Performance**: Applied to the ENeRF framework, this method achieves state-of-the-art performance on both view synthesis and training time, enabling faster per-scene optimization and achieving the same convergence effect in minutes through fine-tuning [S1].
- **Strengths**: Accelerates network convergence by focusing on informative regions; improves geometry perception by sampling more rays at depth boundaries; reduces redundant rays in flat regions [S1].
- **Limitations**: Relies on the quality of the depth estimation module; may not be as effective for scenes with uniform color and depth variations [S1].
- **When to Use**: Suitable for scenes with significant texture and geometric complexity where uniform sampling is inefficient [S1].
- **When Not to Use**: Not recommended for scenes with uniform appearance and geometry, or when high-quality depth estimation is not available [S1].

## Background
- **Origin**: Introduced in the paper "Efficient ray sampling for radiance fields reconstruction" [S1].
- **History and Development**: The method builds upon the ENeRF framework [15] and addresses the inefficiency of uniform ray sampling in NeRF [18]. It leverages the cost volume from ENeRF to obtain depth information, which is then used to guide ray sampling [S1].
- **Usage**: Applied to the ENeRF framework for novel view synthesis and training acceleration [S1].
