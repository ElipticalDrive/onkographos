# Stochastic Laplacian Path Tracing

Also called: Frequency band masking, Spectral selectivity acceleration, Stochastic Laplacian Rendering, Stochastic-analytical estimators

## Overview
Stochastic Laplacian Path Tracing accelerates volume rendering by stochastically selecting which frequency bands (pyramid levels) of a Gabor asset to integrate for each path segment, trading increased variance or bias for substantially reduced traversal time [S1]. Unlike deterministic full integration which intersects all primitives, this method reduces the number of ray-primitive intersections per sample, making it particularly effective for high-frequency content where analytic rendering is expensive [S1]. It builds on [Stochastic Orientation-selective Path Tracing](22760-stochastic-orientation-selective-path-tracing.md) by adding spectral selection to angular selection.

## How it works
**Inputs and Outputs:**
*   **Input:** A Gabor Field asset decomposed into frequency bands (a low-pass Gaussian base and higher-frequency Gabor residuals); a ray segment defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a power law shape parameter $\alpha$.
*   **Output:** An unbiased (in tomographic contexts) or biased (in standard stochastic contexts) estimate of the volume integral contribution for the segment.

**Data Structures:**
The asset is represented as a set of primitives partitioned into frequency bands.
*   **Low-pass band:** Contains the Gaussian base component.
*   **High-frequency bands:** Contain Gabor kernel residuals.
*   **Selection Mask:** A boolean vector indicating which bands are active for the current sample.

**Parameters:**
*   $\alpha$: The shape parameter for the power law curve controlling the probability of selecting higher frequency bands. Typical value: $\alpha = 0.2$ [S1].

**Algorithm:**
1.  **Decomposition:** The volume asset is pre-computed into a hierarchy of frequency bands. The lowest level is a smooth Gaussian approximation; higher levels contain Gabor kernels capturing finer details [S1].
2.  **Stochastic Selection:** For each path segment, determine the subset of bands to intersect.
    *   Always include the low-pass (Gaussian) band to ensure baseline stability [S1].
    *   Stochastically select one or more higher-frequency bands based on a power law distribution governed by $\alpha$ [S1].
3.  **Integration:** Perform ray-primitive intersection tests only against the selected subset of primitives. Accumulate the contribution from these primitives [S1].
4.  **Estimation:** Compute the final pixel value by averaging the contributions from all samples, accounting for the selection probabilities if an unbiased estimator is required, or accepting the bias if using the biased control-variate inspired technique [S1].

**Pseudocode:**
```python
def stochastic_laplacian_trace(ray_origin, ray_direction, asset_bands, alpha):
    """
    ray_origin: 3D vector
    ray_direction: 3D vector
    asset_bands: List of primitive sets, where bands[0] is low-pass Gaussian,
                 bands[1..n] are higher-frequency Gabor residuals.
    alpha: float, power law shape parameter (e.g., 0.2).
    """
    # Step 1: Always include the low-pass band (index 0)
    selected_indices = [0]
    
    # Step 2: Stochastically select higher frequency bands
    # The probability of selecting a band decreases with its frequency level.
    # Using a power law distribution P(k) ~ k^(-alpha) for band index k > 0.
    # Note: Exact normalization constants depend on the number of bands.
    # For implementation simplicity, we sample from the available higher bands.
    
    num_higher_bands = len(asset_bands) - 1
    if num_higher_bands > 0:
        # Generate a random number to decide if we pick a higher band
        # In a full implementation, this might involve multiple samples or 
        # a specific sampling strategy defined in the source's Appendix (Table 5).
        # Here we assume a simplified single-band selection for the segment.
        
        # Calculate weights for power law distribution
        weights = []
        for k in range(1, len(asset_bands)):
            # k is the band index relative to the start of higher bands
            # Using (k) as the frequency level proxy
            weights.append(k ** (-alpha))
            
        # Normalize weights
        total_weight = sum(weights)
        probs = [w / total_weight for w in weights]
        
        # Sample one higher band index (relative to asset_bands)
        # Using inverse transform sampling or a library call for discrete distribution
        r = random.uniform(0, 1)
        cumulative = 0.0
        selected_higher_idx = -1
        for i, p in enumerate(probs):
            cumulative += p
            if r <= cumulative:
                selected_higher_idx = i + 1 # +1 because indices start at 1
                break
        
        if selected_higher_idx != -1:
            selected_indices.append(selected_higher_idx)
            
    # Step 3: Intersect ray with selected primitives
    total_contribution = 0.0
    for idx in selected_indices:
        primitives = asset_bands[idx]
        # Perform ray-primitive intersection for all primitives in this band
        for primitive in primitives:
            contribution = integrate_primitive(primitive, ray_origin, ray_direction)
            total_contribution += contribution
            
    # Step 4: Return contribution
    # Note: To be strictly unbiased, one must divide by the probability of selection.
    # The source notes that this method can be biased depending on the strategy [S1].
    # The "control-variate inspired technique" implies a specific estimator form.
    # Without the exact formula from Table 5, we return the raw sum as a biased estimate
    # or assume the caller handles the weighting if an unbiased variant is chosen [S1].
    return total_contribution
```

**Edge Cases and Pitfalls:**
*   **Bias vs. Variance:** The method introduces bias if the selection probabilities are not correctly accounted for in the estimator. The amount of bias depends on the scene and the parameter $\alpha$ [S1].
*   **Parameter Selection:** A poor choice of $\alpha$ can lead to excessive bias at high frequencies or insufficient acceleration [S1].
*   **Degenerate Input:** If the asset has no high-frequency bands, the stochastic selection step is skipped, and the method degrades to deterministic low-pass rendering [S1].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** Reduces per-sample cost by decreasing the number of ray-primitive intersections. The runtime scales with the number of selected bands. In the ablation study, removing scale regularization increased runtime from 24.1 ms to 37.7 ms, while removing importance sampling centers increased it to 38.0 ms, indicating that the full method (including stochastic acceleration) is significantly faster than variants without these optimizations [S1].
*   **Memory:** Storage costs assume 32-bit floating-point precision without compression. The decomposition into bands does not significantly increase memory overhead compared to storing the full asset, as the bands are derived from the same underlying representation [S1].

**Measured Performance:**
*   On an RTX 4090, the full Gabor Fields method renders at 24.1 ms with 48.86 dB PSNR [S1].
*   Removing Scale Regularization increases runtime to 37.7 ms with 48.78 dB PSNR [S1].
*   Removing Importance Sampling Centers increases runtime to 38.0 ms with 46.36 dB PSNR [S1].

**Strengths and Limitations:**
*   **Strengths:** Substantially faster traversal time; good compromise between rendering performance and variance when using control-variate inspired techniques [S1]. Supports seamless Level-of-Detail (LoD) rendering by masking out high-frequency kernels [S1].
*   **Limitations:** Introduces bias or variance depending on the scenario; requires careful selection of the power law parameter $\alpha$ to manage the "exactness or quality price" [S1].

**When to Use:**
*   Use when rendering high-frequency volume data where analytic integration is too slow.
*   Use when some bias is acceptable for significant performance gains.
*   Use in tomographic rendering contexts where the method remains unbiased [S1].

**When Not to Use:**
*   Use when strict unbiasedness is required in non-tomographic contexts without proper estimator weighting.
*   Use when the asset lacks high-frequency content, as the acceleration benefit is minimal.

## Background
**Origin:**
Stochastic Laplacian Path Tracing was introduced in the paper "Gabor Fields: Orientation-Selective Level-of-Detail for Volume Rendering" by Fajardo et al. [S1]. It builds upon recent work on stochastic texture filtering and procedural noise using Monte Carlo sampling [S1].

**History and Development:**
The method was developed to address the performance bottlenecks of analytic rendering in Gaussian Primitive Volumes and Gabor Fields. It leverages the spectral properties of Gabor kernels to allow for stochastic sampling of frequency bands, similar to techniques used in stochastic texture filtering [S1].

**Applications:**
*   Volume rendering of complex scenes with high-frequency details (e.g., smoke, clouds, explosions) [S1].
*   Tomographic rendering where unbiasedness is critical [S1].
*   Level-of-Detail (LoD) rendering, where high-frequency bands can be masked out based on viewing distance or resolution [S1].
