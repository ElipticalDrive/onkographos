# NeRF-ID

Also called: NeRF in detail

## Overview
NeRF-ID (NeRF in detail) is a method that replaces the heuristic coarse-to-fine sampling of NeRF with a differentiable 'proposer' module, enabling end-to-end training of the entire system (coarse network, proposer, and fine network) to improve view synthesis quality [S1, unofficial]. It addresses the limitation that standard coarse-to-fine approaches rely on handcrafted probability density functions rather than being optimized for the specific task [S1, unofficial]. Unlike [Coarse-to-Fine NeRF](3406-coarse-to-fine-nerf.md) which uses fixed heuristics, NeRF-ID learns the sampling distribution directly from data [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin and direction. The coarse network outputs $N_c$ feature vectors and densities for equally spaced samples.
*   **Output:** A rendered color $\hat{\mathbf{C}}$ for the ray, computed using samples from both the coarse and fine networks.

**Data Structures:**
*   **Coarse Samples:** $N_c$ points $t_i$ equally spaced in $[0, 1]$.
*   **Coarse Features:** $N_c$ feature vectors $\mathbf{f}_i$ (activations before the density projection).
*   **Proposer Output:** $N_f$ scalar positions $p_j \in [0, 1]$.

**Rendering Equation:**
The color $\hat{\mathbf{C}}$ is computed as [S1, unofficial]:
$$ \hat{\mathbf{C}} = \sum_{i=1}^N w_i \mathbf{c}_i $$
where $N = N_c + N_f$, $\mathbf{c}_i$ is the color, and weights $w_i$ and transmittance $T_i$ are:
$$ w_i = T_i \left( 1 - \exp(-\sigma_i(t_{i+1} - t_i)) \right) $$
$$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j(t_{i+1} - t_i)\right) $$
Here $\sigma_i$ is the density, $t_i$ is the location along the ray, and $t_{i+1}$ is the next sample's location [S1, unofficial]. Note: For the last sample, $t_{N+1}$ is typically the far plane or handled via boundary conditions [G].

**Parameters:**
*   $N_c$: Number of coarse samples. Typical values are not explicitly fixed in the abstract but are standard for NeRF (e.g., 64) [S1, unofficial].
*   $N_f$: Number of fine samples proposed by the proposer. Typical values are not explicitly fixed in the abstract but are standard for NeRF (e.g., 48) [S1, unofficial].

**Steps:**
1.  **Coarse Sampling:** Query the coarse network on $N_c$ equally spaced samples along the ray to obtain features $\mathbf{f}_i$ and densities $\sigma_i$.
2.  **Proposer Input Preparation:** Concatenate each feature vector $\mathbf{f}_i$ with its normalized position $t_i \in [0, 1]$.
3.  **Proposer Execution:** Pass the sequence of $(\mathbf{f}_i, t_i)$ pairs through the chosen proposer architecture to generate $N_f$ proposed positions.
4.  **Fine Sampling:** Query the fine network on the union of the $N_c$ coarse samples and the $N_f$ proposed samples.
5.  **Rendering:** Compute the final color using the rendering equation with all $N_c + N_f$ samples.

**Proposer Architectures:**
The proposer takes $N_c$ feature vectors and their positions as input and outputs $N_f$ positions in $[0, 1]$ via a sigmoid function [S1, unofficial]. Three architectures are described:

1.  **Transformer:** A transformer encoder processes the input features. A transformer decoder produces the proposals via cross-attention with $N_f$ learned queries [S1, unofficial].
2.  **Pool:**
    *   Sum each point feature $\mathbf{f}_i$ with a positional encoding of its location $t_i$.
    *   Pass through a Fully Connected (FC) layer followed by ReLU.
    *   Average the processed features to form a single ray representation vector.
    *   Pass through an FC layer with output dimension $N_f$ to produce proposals [S1, unofficial].
3.  **MLPMix:**
    *   Stack point features sorted by position.
    *   Apply a single MLPMix block.
    *   Average pool to get the ray representation.
    *   Decode proposals via an FC layer [S1, unofficial].

**Training Strategy:**
Training from scratch is unstable due to weak supervision (only final color loss) [S1, unofficial]. A two-stage strategy is used:
1.  **Pre-training:** Train the network to mimic vanilla NeRF (heuristic sampling) to stabilize the proposer [S1, unofficial].
2.  **Fine-tuning:** Enable end-to-end training of the coarse network, proposer, and fine network jointly [S1, unofficial].

## Subtopics

### Transformer Proposer
Uses transformer encoder/decoder with cross-attention. Sets it apart by capturing complex dependencies between coarse samples. Choose when computational budget allows for larger proposer overhead [S1, unofficial].

### Pool Proposer
Uses FC layers and average pooling. Sets it apart by being lightweight and simple. Choose for efficiency [S1, unofficial].

### MLPMix Proposer
Uses MLPMix block. Sets it apart by using a specific mixing mechanism for sequence processing. Choose as a middle ground between Transformer and Pool [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on $N_c$ and $N_f$. The proposer adds negligible overhead as it is designed to be small [S1, unofficial].
*   **Memory Complexity:** Stores features for $N_c$ coarse samples and $N_f$ fine samples.
*   **Performance:** Achieves superior view synthesis quality over NeRF and state-of-the-art on synthetic Blender benchmark and comparable performance on real LLFF-NeRF scenes [S1, unofficial].
*   **Scaling:** Can achieve 25% computation saving by filtering out least promising samples based on predicted importance, without significant quality loss [S1, unofficial].
*   **Strengths:** End-to-end differentiable training, better sampling distribution learning.
*   **Limitations:** Training from scratch is unstable; requires two-stage training [S1, unofficial].

## Background
NeRF-ID was introduced in "NeRF in detail: Learning to sample for view synthesis" (2021) [S1, unofficial]. It addresses the limitations of the original NeRF's heuristic coarse-to-fine sampling by introducing a learnable proposer module [S1, unofficial].
