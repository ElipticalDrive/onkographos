# NeRF-ID

Also called: NeRF in detail

## Overview
NeRF-ID (NeRF in detail) replaces the heuristic coarse-to-fine sampling of NeRF with a differentiable 'proposer' module, enabling end-to-end training of the coarse network, proposer, and fine network to improve view synthesis quality [S1, unofficial]. It solves the limitation of vanilla coarse-to-fine approaches where the sample proposal procedure is handcrafted and not trained for the specific task [S1, unofficial]. Unlike [Coarse-to-Fine NeRF](3406-coarse-to-fine-nerf.md) which relies on density-based heuristics, NeRF-ID uses a learnable neural network to directly output fine sample locations from coarse features [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin and direction [S1, unofficial].
*   **Output:** A rendered color $\hat{\mathbf{C}}$ for the ray [S1, unofficial].

**Data Structures:**
*   **Coarse Samples:** $N_c$ points $t_i$ equally spaced along the ray interval $[0, 1]$ (normalized near to far) [S1, unofficial].
*   **Coarse Features:** For each coarse sample $i$, a feature vector $\mathbf{f}_i$ extracted from the coarse network (last activations before the density projection) [S1, unofficial].
*   **Proposer:** A neural network taking $\{\mathbf{f}_i, t_i\}_{i=1}^{N_c}$ as input and outputting $N_f$ scalar positions [S1, unofficial].
*   **Fine Samples:** $N_f$ points $t'_j$ proposed by the proposer [S1, unofficial].

**Numbered Steps:**
1.  **Coarse Sampling:** Query the coarse network on $N_c$ equally spaced samples along the ray to obtain densities $\sigma_i$ and features $\mathbf{f}_i$ [S1, unofficial].
2.  **Proposal Generation:** Pass the coarse features $\mathbf{f}_i$ and their normalized positions $t_i \in [0, 1]$ through the proposer network [S1, unofficial].
3.  **Position Clamping:** The proposer outputs $N_f$ scalars, which are passed through a sigmoid function to constrain them to $[0, 1]$ [S1, unofficial].
4.  **Fine Sampling:** Query the fine network on the union of the $N_c$ coarse samples and the $N_f$ proposed fine samples [S1, unofficial].
5.  **Rendering:** Compute the final ray color using the standard volume rendering equation with all $N_c + N_f$ samples [S1, unofficial].

**Formulas:**
The rendering equation for ray color $\hat{\mathbf{C}}$ is:
$$ \hat{\mathbf{C}} = \sum_{i=1}^N w_i \mathbf{c}_i $$
where $N = N_c + N_f$, and for each sample $i$:
$$ w_i = T_i \left( 1 - \exp(-\sigma_i(t_{i+1} - t_i)) \right) $$
$$ T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j(t_{i+1} - t_i)\right) $$
Here $\sigma_i$ is density, $\mathbf{c}_i$ is color, and $t_i$ is the location along the ray for the $i$-th sample [S1, unofficial].

**Parameters:**
*   $N_c$: Number of equally spaced samples queried from the coarse network [S1, unofficial].
*   $N_f$: Number of additional samples proposed by the proposer for the fine network [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Training Instability:** Training the proposer from scratch can be unstable due to lack of supervision [S1, unofficial].
*   **Feature Extraction:** The proposer requires specific internal features (last activations before density projection) from the coarse network, not just the final density output [S1, unofficial].
*   **Training Strategy:** A two-stage training strategy is required: first train the network to mimic vanilla NeRF (pre-training), then make the network free to learn better sampling strategies (fine-tuning) [S1, unofficial].

**Pseudocode:**
```python
import math

def linspace(start, stop, num):
    if num == 1: return [start]
    step = (stop - start) / (num - 1)
    return [start + i * step for i in range(num)]

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

def exp(x):
    return math.exp(x)

def nerf_id_render(ray_origin, ray_direction, coarse_net, proposer_net, fine_net, Nc, Nf):
    # Step 1: Coarse Sampling
    coarse_t = linspace(0.0, 1.0, Nc)
    coarse_features, coarse_densities = coarse_net(ray_origin, ray_direction, coarse_t)
    
    # Step 2 & 3: Proposal Generation
    proposed_raw = proposer_net(coarse_features, coarse_t)
    proposed_t = [sigmoid(x) for x in proposed_raw]
    
    # Step 4: Fine Sampling
    all_t = coarse_t + proposed_t
    all_t.sort()
    N = len(all_t)
    fine_colors, fine_densities = fine_net(ray_origin, ray_direction, all_t)
    
    # Step 5: Rendering
    T = 1.0
    color = [0.0, 0.0, 0.0]
    for i in range(N):
        delta_t = all_t[i+1] - all_t[i] if i < N - 1 else 0.0
        weight = T * (1.0 - exp(-fine_densities[i] * delta_t))
        color = [color[k] + weight * fine_colors[i][k] for k in range(3)]
        T = T * exp(-fine_densities[i] * delta_t)
    return color
```

## Subtopics

### Transformer Proposer
A transformer encoder processes the input features, and a transformer decoder produces the final set of proposals via cross-attention with $N_f$ learned queries [S1, unofficial]. It is one of several architectures considered, all designed to be small relative to the coarse and fine networks to maintain negligible computational overhead [S1, unofficial].

### Pool Proposer
Each point feature is summed with the positional encoding of its location along the ray, passed through a fully connected layer and ReLU, averaged to form a single ray representation vector, and decoded via a fully connected layer to produce proposals [S1, unofficial].

### MLPMix Proposer
A single MLPMix block is applied to the stacked point features sorted by their position along the ray, followed by average pooling to get the ray representation, then proposals are decoded via a fully connected layer [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Adds the computational cost of the proposer network to the standard NeRF rendering time, but the proposer is designed to be small relative to coarse/fine networks to have negligible overhead [S1, unofficial].
*   **Memory Complexity:** Requires storing coarse features for all $N_c$ samples to pass to the proposer [S1, unofficial].
*   **Performance:** Achieves superior view synthesis quality over NeRF and state-of-the-art on synthetic Blender benchmarks and comparable performance on real LLFF-NeRF scenes [S1, unofficial].
*   **Strengths:** End-to-end differentiability allows learning optimal sampling strategies; predicted sample importance enables a 25% saving in computation without significantly sacrificing rendering quality [S1, unofficial].
*   **Limitations:** Training from scratch is unstable due to weak supervision; requires a two-stage training strategy (pre-training to mimic vanilla NeRF, then fine-tuning) [S1, unofficial].

## Background
NeRF-ID was introduced in the paper "NeRF in detail: Learning to sample for view synthesis" [S1, unofficial]. It addresses the limitation of vanilla NeRF's coarse-to-fine sampling, which relies on a heuristic piece-wise constant probability density function computed from coarse densities [S1, unofficial]. The method was developed to enable end-to-end training of the sampling mechanism, improving scene representations and view synthesis quality [S1, unofficial].
