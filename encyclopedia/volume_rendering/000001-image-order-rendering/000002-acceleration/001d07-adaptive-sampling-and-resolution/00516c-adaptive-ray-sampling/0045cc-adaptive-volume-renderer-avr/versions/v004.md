# Adaptive Volume Renderer (AVR)

Also called: Adapted version of differentiable ray marching algorithm, RM-LSTM based adaptive sampling

## Overview
The Adaptive Volume Renderer (AVR) is a rendering procedure that combines adaptive ray sampling with standard volume rendering to reduce computational cost while maintaining visual quality [S1, unofficial]. It addresses the high latency of standard volume rendering by using a recurrent neural network (RM-LSTM) to predict a surface intersection point, then samples points around that prediction for volume rendering [S1, unofficial]. It sets itself apart from its sibling [Raymarcher](14469-adaptive-ray-sampling.md) by performing volume rendering around the predicted depth rather than outputting a single point, achieving comparable quality to standard volume rendering but approximately 7 times faster [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Latent features extracted from a CNN encoder (specifically a pretrained ResNet 34 as used in PixelNeRF) [S1, unofficial].
*   **Output:** Final RGB color value for the pixel [S1, unofficial].

**Data Structures:**
*   **RM-LSTM State:** Hidden state and cell state for the LSTM [G].
*   **Feature Vector:** Input to the LSTM, dimension matching the CNN encoder's output [S1, unofficial].
*   **Depth:** Scalar value representing the distance along the ray [S1, unofficial].

**Parameters:**
*   **RM-LSTM Feature Channels:** 512 [S1, unofficial].
*   **RM-LSTM Steps:** 10 [S1, unofficial].
*   **Volume Rendering Sample Count ($n$):** 10 [S1, unofficial].
*   **Sampling Neighborhood Radius:** $\pm 0.05$ around the predicted depth [S1, unofficial].
*   **Depth Bounds:** Near plane $d_{min} = 0.5$, Far plane $d_{max} = 2.0$ [S1, unofficial].

**Algorithm Steps:**
1.  **Feature Extraction:** Extract latent features $F$ from the CNN encoder for the input view [S1, unofficial].
2.  **Initialization:** Initialize the RM-LSTM hidden state $h_0$ and cell state $c_0$ to zeros [G]. Initialize current depth $d_0 = 0.0$ [G].
3.  **LSTM Prediction Loop:** For step $t$ from 1 to 10:
    *   Input the latent features $F$ and current depth $d_{t-1}$ into the RM-LSTM [S1, unofficial].
    *   Compute new hidden state $h_t$ and cell state $c_t$ [G].
    *   Predict step length $\Delta d_t$ and update depth $d_t = d_{t-1} + \Delta d_t$ [S1, unofficial].
    *   *Note:* The exact mapping from LSTM output to $\Delta d_t$ is a learned transformation not specified in the source [S1, unofficial].
4.  **Depth Regularization:** If the final predicted depth $d_{10}$ falls outside $[0.5, 2.0]$, apply a penalty to the reconstruction loss during training [S1, unofficial].
5.  **Sampling:** Generate $n=10$ sample points uniformly distributed within the neighborhood $[d_{10} - 0.05, d_{10} + 0.05]$ [S1, unofficial].
6.  **Volume Rendering:** Perform standard discrete volume rendering (alpha compositing) along these 10 sampled points using the neural field to obtain RGB values [S1, unofficial].

**Pseudocode:**

```python
import math

def adaptive_volume_renderer(latent_features, rm_lstm_channels, rm_lstm_steps, n_samples, radius, near_plane, far_plane):
    """
    Renders a pixel using the Adaptive Volume Renderer method.
    
    Args:
        latent_features: Tensor from CNN encoder (ResNet 34).
        rm_lstm_channels: Number of feature channels in RM-LSTM (512).
        rm_lstm_steps: Number of LSTM steps (10).
        n_samples: Number of volume rendering samples (10).
        radius: Sampling neighborhood radius (0.05).
        near_plane: Near plane bound (0.5).
        far_plane: Far plane bound (2.0).
        
    Returns:
        rgb: Final RGB color value.
    """
    # Step 1: Latent features F are extracted from the CNN encoder [S1, unofficial]
    F = latent_features

    # Step 2: Initialize RM-LSTM hidden and cell states to zeros [G]
    h = [0.0] * rm_lstm_channels
    c = [0.0] * rm_lstm_channels
    current_depth = 0.0  # [G] Initial ray depth

    # Step 3: RM-LSTM Prediction Loop
    for t in range(rm_lstm_steps):
        # [G] RM-LSTM internal computation is a learned mapping not specified in the source [S1, unofficial]
        # It takes F and current_depth, outputs a step length delta_d
        delta_d = 0.0  # Placeholder for learned step prediction
        current_depth += delta_d

    # Step 4: Depth regularization penalizes final depth outside [0.5, 2.0] during training loss [S1, unofficial]

    # Step 5: Sample n points around predicted depth
    sample_depths = [current_depth - radius + i * (2 * radius / (n_samples - 1)) for i in range(n_samples)]

    # Step 6: Standard volume rendering (discrete alpha compositing)
    transmittance = 1.0
    rgb = [0.0, 0.0, 0.0]
    for i in range(n_samples):
        # [G] Query neural field for density sigma and color at sample_depths[i]
        sigma, color = 0.0, [0.0, 0.0, 0.0]  # Placeholder for neural field query
        # Compute step size between consecutive samples
        step = sample_depths[i+1] - sample_depths[i] if i < n_samples - 1 else radius
        # Update transmittance and accumulate color
        alpha = 1.0 - math.exp(-sigma * step)
        rgb[0] += transmittance * alpha * color[0]
        rgb[1] += transmittance * alpha * color[1]
        rgb[2] += transmittance * alpha * color[2]
        transmittance *= (1.0 - alpha)

    return rgb
```

**Edge Cases and Pitfalls:**
*   **Depth Bounds:** If the predicted depth falls outside $[0.5, 2.0]$, the model may produce incorrect results; the source specifies a regularization term to penalize this during training, but does not define inference-time clamping [S1, unofficial].
*   **Precision:** The small neighborhood size ($\pm 0.05$) requires accurate depth prediction; errors in LSTM prediction may lead to sampling in empty space or incorrect surface regions [G].
*   **Computational Constraints:** The number of LSTM steps is fixed at 10 due to computational constraints, which may limit the accuracy of depth prediction for complex scenes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Approximately 7 times faster than standard volume rendering, achieving 4.2 fps compared to 0.4 fps on the ShapeNet cars dataset [S1, unofficial].
*   **Memory Complexity:** Requires storing the LSTM state and the latent features from the CNN encoder; the RM-LSTM uses 512 feature channels [S1, unofficial].
*   **Quality:** Achieves comparable quality to standard volume rendering (PSNR 23.22 vs 23.34, SSIM 0.9056 vs 0.9048, LPIPS 0.108 vs 0.111) [S1, unofficial].
*   **Comparison to Raymarcher:** AVR is slower than the Raymarcher variant (4.2 fps vs 34.9 fps) but achieves better quality (PSNR 23.22 vs 23.02) [S1, unofficial].
*   **Strengths:** Maintains high visual fidelity while reducing computational cost [S1, unofficial].
*   **Limitations:** Requires training a separate LSTM module; performance is dependent on the accuracy of the LSTM depth prediction [G].

## Background
The Adaptive Volume Renderer was proposed by Philipp Henzler, Jeremy Reizenstein, Patrick Labatut, Roman Shapovalov, Tobias … as an adaptation of the differentiable ray marching algorithm [S1, unofficial]. It builds on the PixelNeRF architecture, which uses a CNN encoder (pretrained ResNet 34) to extract latent features [S1, unofficial]. The method was evaluated on the ShapeNet cars dataset, with 2150 training cars and 352 test cars, using 8 views per scene [S1, unofficial]. The work was presented in an unofficial source, likely a project report or preprint [S1, unofficial].
