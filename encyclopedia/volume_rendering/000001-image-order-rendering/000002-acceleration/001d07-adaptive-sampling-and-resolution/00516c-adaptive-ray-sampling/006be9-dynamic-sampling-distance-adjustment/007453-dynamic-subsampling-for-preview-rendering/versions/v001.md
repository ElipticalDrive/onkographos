# Dynamic Subsampling for Preview Rendering

Also called: Adaptive Preview Rendering, Adaptive sampling adjustment, Adaptive sub-sampling, Adaptive sub-sampling along the ray, Preview rendering, Subsample VDI, VDI Subsampling for Preview Rendering

## Overview
Dynamic Subsampling for Preview Rendering is a technique to maintain high frame rates during interactive remote visualization when the camera viewpoint deviates significantly from the VDI generation viewpoint [S1]. It solves the performance degradation caused by the anisotropic shape of Volumetric Depth Images (VDIs) by adaptively subsampling along the view ray and in image space [S1]. Unlike standard downsampling which only reduces ray count, this method combines image-space downsampling with adaptive ray-space subsampling to achieve higher frame rates with significantly better structural similarity (SSIM) than image-space subsampling alone [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A Volumetric Depth Image (VDI) consisting of supersegment lists $\mathbb{L}$ and supersegments $\mathbb{S}$, an acceleration grid storing the number of supersegments per cell, the current camera viewpoint, and target frame rate parameters.
*   **Output:** A rendered image at display resolution (e.g., $1920 \times 1080$).

**Data Structures:**
*   **Acceleration Grid:** A 3D grid where each cell stores the count of supersegments $\mathbb{S}$ intersecting that cell [S1].
*   **Supersegment List ($\mathbb{L}_i$):** A list of supersegments associated with a specific image coordinate, found using the sample's x- and y-coordinates in Normalized Device Coordinates (NDC) [S1].
*   **Supersegment ($\mathbb{S}_j^i$):** A geometric primitive storing color and opacity information [S1].

**Parameters:**
*   $D_I$: Image space downsampling factor. $D_I=1.0$ is full resolution. Values $<1.0$ decrease the number of rays [S1].
*   $D_R$: Ray space subsampling factor. Used to thin samples uniformly along the ray. Typically manually chosen (e.g., $0.3$ during navigation phases) [S1].
*   Target Frame Rate: Used by a dynamic PI Controller to modulate $D_I$ [S1].

**Algorithm Steps:**
1.  **Determine Image Resolution:** Calculate the number of rays to cast based on $D_I$. If $D_I < 1.0$, cast rays at a lower resolution grid [S1].
2.  **Iterate Over Rays:** For each ray $(x, y)$ in the lower-resolution image grid:
    a.  **Traverse Acceleration Grid:** March the ray through the acceleration grid cells [S1].
    b.  **Calculate Samples per Cell:** For each intersected cell, determine the number of samples $N_{cell}$ to place within that cell:
        $$ N_{cell} = D_R \times L_{cell} \times C_{cell} $$
        Where:
        *   $D_R$ is the ray subsampling factor [S1].
        *   $L_{cell}$ is the intersection length of the ray with the cell [S1].
        *   $C_{cell}$ is the number of supersegments $\mathbb{S}$ stored in that cell [S1].
    c.  **Place Samples:** Place $N_{cell}$ samples at regular intervals along the ray segment within the cell [S1].
    d.  **Query Supersegment:** For each sample point $P$:
        i.  Convert $P$ to NDC coordinates $(x_{ndc}, y_{ndc})$ [S1].
        ii. Retrieve the supersegment list $\mathbb{L}_i$ corresponding to $(x_{ndc}, y_{ndc})$ [S1].
        iii. Find the specific supersegment $\mathbb{S}_j^i$ containing $P$ using the intersection algorithm defined in the parent article (Section 4.2 of [S1]) [S1].
        iv. If a supersegment is found, obtain its color. If not, the sample is transparent [S1].
    e.  **Accumulate Color:** Perform volume rendering accumulation (e.g., standard front-to-back compositing) using the colors obtained from the samples [S1].
        *   **Opacity Correction:** Approximate length-based opacity correction using the distance from the previous sample instead of calculating exact intersection lengths with the supersegment boundaries [S1].
3.  **Upsample:** If $D_I < 1.0$, upsample the resulting lower-resolution image to the display resolution using bilinear interpolation [S1].

**Pseudocode:**
```python
def render_vdi_preview(vdi, camera, D_I, D_R, target_fps):
    # 1. Determine image resolution based on D_I
    display_width, display_height = get_display_resolution()
    render_width = int(display_width * D_I)
    render_height = int(display_height * D_I)
    
    # 2. Initialize output image
    output_image = zeros((render_height, render_width, 3))
    
    # 3. Iterate over lower-resolution image grid
    for y in range(render_height):
        for x in range(render_width):
            # Get ray for this pixel
            ray = camera.get_ray(x, y, display_width, display_height)
            
            # Initialize accumulation
            accumulated_color = (0.0, 0.0, 0.0)
            accumulated_opacity = 0.0
            prev_sample_dist = 0.0
            
            # 4. Traverse acceleration grid
            for cell in ray.traverse(vdi.acceleration_grid):
                if cell.supersegment_count == 0:
                    continue
                
                # Calculate number of samples for this cell
                # L_cell is intersection length of ray with cell
                # C_cell is number of supersegments in cell
                num_samples = D_R * cell.intersection_length * cell.supersegment_count
                
                # Place samples at regular intervals within the cell segment
                cell_start, cell_end = ray.get_cell_bounds(cell)
                step_size = (cell_end - cell_start) / max(num_samples, 1)
                
                for k in range(num_samples):
                    sample_dist = cell_start + k * step_size
                    sample_point = ray.get_point(sample_dist)
                    
                    # 5. Query supersegment
                    # Find list L_i using NDC coordinates of sample_point
                    ndc_x, ndc_y = camera.world_to_ndc(sample_point)
                    supersegment_list = vdi.get_supersegment_list(ndc_x, ndc_y)
                    
                    # Find specific supersegment S_j^i containing sample_point
                    supersegment = supersegment_list.find_containing_supersegment(sample_point)
                    
                    if supersegment is not None:
                        color = supersegment.color
                        opacity = supersegment.opacity
                        
                        # Approximate opacity correction using distance from previous sample
                        # [G] Standard front-to-back compositing formula
                        # alpha = opacity * exp(-opacity * distance) is an approximation
                        # Here we use simple distance delta for correction as per source
                        dist_delta = sample_dist - prev_sample_dist
                        # [G] Assuming standard compositing: C_out = C_in + (1 - alpha_in) * C_sample * alpha_sample
                        # The source mentions "length-based opacity correction... approximated using distance"
                        # This implies modulating the sample's contribution by the step size or distance
                        # Since exact intersection is skipped, we use the step size as a proxy for path length
                        effective_opacity = opacity * dist_delta # [G] Interpretation of "approximation"
                        
                        # Composite
                        weight = (1.0 - accumulated_opacity) * effective_opacity
                        accumulated_color += weight * color
                        accumulated_opacity += weight
                        
                        prev_sample_dist = sample_dist
                    else:
                        prev_sample_dist = sample_dist

            output_image[y, x] = accumulated_color

    # 6. Upsample to display resolution if D_I < 1.0
    if D_I < 1.0:
        output_image = bilinear_interpolate_upsample(output_image, display_width, display_height)
        
    return output_image
```

**Edge Cases and Pitfalls:**
*   **Manual Tuning:** $D_R$ lacks automatic control and requires manual activation and tuning, which can lead to jerkiness during rapid navigation phases [S1].
*   **Precision:** The approximation of opacity correction using distance from the previous sample may introduce artifacts if the step size is large or if supersegment boundaries are not aligned with sample points [S1].
*   **NDC Lookup:** Finding the supersegment list requires accurate conversion to NDC space; errors here may lead to incorrect supersegment retrieval [S1].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of rays cast ($D_I^2$) times the average number of samples per ray. The number of samples per ray is proportional to $D_R$ and the density of supersegments in the VDI [S1].
*   **Memory Complexity:** Dominated by the VDI storage and acceleration grid. The rendering process itself uses minimal additional memory [S1].
*   **Measured Performance:** On the Richtmyer-Meshkov dataset with a $30^\circ$ viewpoint deviation:
    *   Full resolution ($D_I=1.0$) yields 45 fps with SSIM=1.0 [S1].
    *   Image subsampling alone ($D_I=0.2$) yields ~150 fps but SSIM=0.88 [S1].
    *   Combined adaptive ray subsampling ($D_R=0.14$) and image subsampling ($D_I=0.6$) yields ~150 fps with SSIM=0.94 [S1].
    *   In an interactive session, the method maintained a steady 25 fps through most of the session, with jerkiness during rapid navigation phases [S1].
*   **Strengths:** Significantly improves SSIM compared to image-space subsampling alone for the same frame rate. Effective for remote visualization where bandwidth or server-side generation latency is a constraint [S1].
*   **Limitations:** Requires manual tuning of $D_R$. Does not support directional lighting effects like specular highlights because the VDI stores classified color and opacity [S1].
*   **When to Use:** When rendering large volumes remotely with significant viewpoint deviations and maintaining high frame rates is critical, and some quality loss is acceptable [S1].
*   **When Not to Use:** When high-fidelity directional lighting is required, or when automatic parameter tuning is necessary without user intervention [S1].

## Background
Dynamic Subsampling for Preview Rendering was proposed by Gupta and Sbalzarini in 2023 as part of an efficient raycasting method for Volumetric Depth Images (VDIs) [S1]. It addresses the challenge of interactive direct volume rendering in remote visualization scenarios, where the VDI is generated on a server and streamed to a client [S1]. The method builds on the VDI data structure, which uses supersegments to represent volume data efficiently [S1]. It is implemented as an extension of the scenery visualization library [S1].
