# Hard Sample Mining

Also called: HSM

## Overview
Hard Sample Mining (HSM) is an optimization strategy for neural radiance field (NeRF) training that reduces iteration time and memory usage by focusing gradient updates on a subsampled "hard" minibatch of point samples [S1]. It differs from sibling methods like [Mip-NeRF 360 Sampling and Training](3393-mip-nerf-360-sampling-and-training.md) or [Adaptive Sparse Ray Sampling](8313-adaptive-sparse-ray-sampling.md) by explicitly ranking samples based on propagated pixel loss rather than geometric density or weight thresholds [S1]. This allows the method to retain most of the update information while discarding samples that contribute little to the loss, achieving ~2x faster convergence and ~1 dB higher PSNR per training time on Mip-NeRF-360 scenes compared to baselines [S1].

## How it works
**Inputs:**
- A set of $N$ point samples $\{p_i\}_{i=1}^N$ per ray, typically generated by a sampler (e.g., uniform or stratified sampling).
- The rendered pixel color $C$ and the ground truth pixel color $C_{gt}$.
- The total batch size $B$ (number of rays processed per iteration).

**Outputs:**
- A subset of indices $I_{hard} \subset \{1, \dots, N \times B\}$ corresponding to the "hard" samples used for the backward pass.

**Data Structures:**
- A list of loss values $L = [l_1, l_2, \dots, l_{N \times B}]$, where each $l_i$ is the scalar pixel loss for the $i$-th sample.
- A sorted index array mapping samples to their loss rank.

**Parameters:**
- $B$: Total batch size (number of rays). Typical values are $2^{18}$ (262,144) for Nerfacto and $2^{18}$ for Instant-NGP [S1]. Note: The source text specifies "220" and "218" which appear to be typos for $2^{18}$ given the context of NeRF batch sizes, but we retain the source's explicit notation if it refers to a specific hyperparameter configuration not fully clarified. However, standard NeRF batch sizes are powers of 2. The source explicitly states: "$B$: Total batch size. Typical values: 220 for Instant-NGP, 218 for Nerfacto." [S1]. We interpret this as the source's specific notation for the batch size parameter in their implementation.
- $K$: The number of hard samples to select. The source does not explicitly define $K$ as a separate variable but implies subsampling a "hard minibatch". In standard HSM implementations, $K$ is often a fraction of $B$ or a fixed small number. The source states "subsamples a hard minibatch, estimated to retain most of the update information" [S1]. Without a specific formula for $K$, we assume $K$ is a hyperparameter controlling the subsample size.

**Steps:**
1. **Forward Pass:** Render the batch of $B$ rays using the current network state to obtain predicted colors $C$.
2. **Loss Calculation:** Compute the pixel-wise loss $l_i$ for each sample $i$ in the batch. The loss is typically the $L_1$ or $L_2$ difference between the predicted color and the ground truth color for the pixel associated with the sample's ray.
   $$ l_i = \| C_i - C_{gt} \| $$
   [S1]
3. **Ranking:** Sort all $N \times B$ samples in descending order of their loss $l_i$.
4. **Subsampling:** Select the top $K$ samples with the highest loss values to form the hard minibatch. The remaining samples are discarded for the backward pass.
5. **Backward Pass:** Compute gradients and update network parameters using only the selected hard minibatch.

**Pseudocode:**
```python
def hard_sample_mining(rays, gt_colors, network, batch_size, hard_sample_ratio):
    """
    Performs hard sample mining for a batch of rays.
    
    Args:
        rays: Tensor of shape (batch_size, num_samples_per_ray, 3) or similar, 
              containing ray origins and directions.
        gt_colors: Tensor of shape (batch_size, 3), ground truth pixel colors.
        network: The NeRF network model.
        batch_size: Number of rays to process.
        hard_sample_ratio: Fraction of total samples to keep (e.g., 0.1).
        
    Returns:
        gradients: Gradients for the network parameters.
    """
    # 1. Forward pass to get predictions for all samples
    # Assume network returns color for each sample along the ray
    # colors shape: (batch_size, num_samples_per_ray, 3)
    colors = network(rays)
    
    # 2. Calculate loss for each sample
    # Expand gt_colors to match sample dimensions
    gt_expanded = gt_colors.unsqueeze(1).expand_as(colors)
    losses = torch.abs(colors - gt_expanded) # L1 loss per channel
    losses = losses.mean(dim=2) # Average over channels to get scalar loss per sample
    # losses shape: (batch_size, num_samples_per_ray)
    
    # Flatten losses to a 1D array
    flat_losses = losses.flatten()
    
    # 3. Rank samples by loss (descending)
    # Get indices of top K samples
    num_samples = flat_losses.shape[0]
    num_hard_samples = int(num_samples * hard_sample_ratio)
    
    # Get indices of the hardest samples
    _, top_indices = torch.topk(flat_losses, num_hard_samples)
    
    # 4. Create a mask for the hard samples
    # We need to map these flat indices back to the original ray/sample structure
    # to compute gradients correctly.
    # However, in PyTorch, we can simply zero out gradients for non-hard samples
    # or restructure the input to the backward pass.
    
    # A common implementation strategy is to re-construct the ray/sample inputs
    # for only the hard samples and run backward on that subset.
    
    # Extract the hard samples' ray indices and sample indices
    ray_indices = top_indices // num_samples_per_ray
    sample_indices = top_indices % num_samples_per_ray
    
    # Gather the specific rays and sample positions
    # This step depends on the specific data structure of 'rays'
    # Assuming 'rays' is a list of rays or a tensor where we can index
    hard_rays = gather_hard_samples(rays, ray_indices, sample_indices)
    
    # 5. Backward pass on hard samples only
    # Re-render only the hard samples
    hard_colors = network(hard_rays)
    hard_gt = gather_hard_gt(gt_colors, ray_indices)
    
    hard_loss = torch.abs(hard_colors - hard_gt).mean()
    
    # Compute gradients
    gradients = torch.autograd.grad(hard_loss, network.parameters())
    
    return gradients

def gather_hard_samples(rays, ray_indices, sample_indices):
    """
    Helper to gather specific samples from rays.
    Implementation detail: [G]
    """
    # This function is implementation-specific.
    # It should return a tensor containing only the ray origins/directions
    # and the specific sample positions (t values) for the hard samples.
    pass

def gather_hard_gt(gt_colors, ray_indices):
    """
    Helper to gather ground truth colors for the selected rays.
    """
    return gt_colors[ray_indices]
```

**Edge Cases and Pitfalls:**
- **Uniformly Challenging Content:** In scenes with unbounded backgrounds or multiple outward-facing objects, the pixel loss distribution is more uniform. This limits the computational efficiency gains because most samples have similar loss values, reducing the benefit of subsampling [S1].
- **Pose Errors:** Severe pose mistakes in the dataset can produce "impossible to learn" point samples. These samples will consistently have high loss and crowd the hard minibatch, potentially degrading training stability [S1]. Mitigation techniques like uncertainty or pose estimation can be applied [S1].

## Operating characteristics
- **Time Complexity:** Reduces iteration time by performing the backward pass on a smaller subset of samples. The forward pass still requires evaluating all samples to compute losses, but the expensive gradient computation is reduced [S1].
- **Memory Complexity:** Reduces dynamic memory footprint. For example, in Nerfacto, memory usage dropped from 300 MB to 160 MB for normal iterations [S1].
- **Performance:** On Mip-NeRF-360 scenes, HSM achieves ~1 dB higher validation PSNR per same training time and converges ~2x faster to a given PSNR level compared to the baseline [S1].
- **Strengths:** Significant reduction in training time and memory; improved convergence speed.
- **Limitations:** Less effective in scenes with uniform loss distribution; sensitive to pose errors in the dataset.
- **When to Use:** When training time and memory are constrained, and the scene has varying levels of difficulty (e.g., occluded regions, complex textures).
- **When Not to Use:** In scenes with uniformly challenging content or when pose accuracy is low.

## Background
Hard Sample Mining was introduced by J. Korhonen et al. in the paper "Efficient NeRF Optimization -- Not All Samples Remain Equally Hard" [S1]. The method was applied to PyTorch reimplementations of Instant-NGP and Nerfacto on Mip-NeRF-360 and NeRF synthetic datasets [S1]. It is distinct from Nerfacc's approach of pruning low-weight samples, as HSM uses propagated pixel loss to rank and subsample [S1].
