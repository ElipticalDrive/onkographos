# Adaptive Sampling

Also called: Adaptive Sampling Rate, Adaptive Sampling Strategy, Adaptive Sampling with Bricking

## Overview
Adaptive sampling is a volume rendering optimization that varies the density of samples along rays to match local data complexity, providing higher quality in non-homogeneous regions while reducing computational cost in homogeneous or empty areas [S1, S2, unofficial][S9]. It sets itself apart from its siblings by focusing on the spatial distribution of samples based on geometric or scalar field properties (such as gradient magnitude or opacity) rather than purely statistical error bounds [S1, S2, S5, S7, unofficial][S9, S10, S12][S13, unofficial][S14][S15, unofficial] or interaction latency targets [S8, unofficial]. Unlike [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md) which uses per-pixel luminance variance, or [Loss-based Adaptive Sampling](6928-loss-based-adaptive-sampling.md) which minimizes training loss, this method relies on local data characteristics to determine step sizes or sampling rates [S1, S2, S7, unofficial][S9, S10, S12].

## How it works
**Inputs:**
*   Volume dataset $V$ (scalar field).
*   Ray origin $O$ and direction $D$.
*   Entry and exit points $t_{start}$ and $t_{end}$ (or bounding box intersection).
*   Transfer function $T(s)$ mapping scalar values to color and opacity.
*   Isosurface threshold $\rho$ (optional, for silhouette detection).
*   Parameters: $\Delta t_{min}$, $\Delta t_{max}$, $\epsilon$ (opacity threshold), $\delta$ (silhouette threshold), $L$ (gradient bound).

**Outputs:**
*   Final pixel color $C$ and accumulated opacity $A$.

**Data Structures:**
*   Accumulators: `color` (RGB), `opacity` (scalar), `density` (scalar, optional).
*   State variables: `current_t` (float), `step_size` (float).

**Algorithm Steps:**

1.  **Initialization:**
    Set `color = (0, 0, 0)`, `opacity = 0.0`, `current_t = t_start`.
    Determine initial `step_size` based on the chosen adaptation strategy (see variants below).

2.  **Ray Marching Loop:**
    While `current_t < t_end` and `opacity < 1.0 - \epsilon` (where $\epsilon \approx 0.01$ to $0.05$) [S9][S15, unofficial]:
    
    a. **Sample:** Evaluate scalar value $s = V(O + current_t \cdot D)$.
    
    b. **Compute Contribution:**
       Calculate opacity $\alpha = 1 - e^{-\kappa(s) \cdot \Delta t}$ and color contribution $c = q(s) \cdot \Delta t$ [S1, unofficial].
       Or use pre-integrated values if applicable.
    
    c. **Front-to-Back Compositing:**
       $C_{new} = C_{old} + (1 - A_{old}) \cdot c$
       $A_{new} = A_{old} + (1 - A_{old}) \cdot \alpha$
       Update `color` and `opacity`.
    
    d. **Adapt Step Size:**
       Compute metric $M$ based on local data (see variants).
       Update `step_size` using adaptation law:
       $$ \Delta t_{new} = \min(\Delta t_{max}, \max(\Delta t_{min}, f(M))) $$
       [G] Common functions $f(M)$ include $1/M$ or proportional scaling.
    
    e. **Advance:**
       `current_t += step_size`

3.  **Termination:**
    If `opacity >= 1.0 - \epsilon`, break loop (Early Ray Termination) [S9][S15, unofficial].
    Return `color`.

**Variants of Metric Evaluation and Adaptation:**

*   **Opacity-Based:** Increase step size inversely with local opacity. If accumulated opacity change $\Delta A = A_i - A_{i-1} < \epsilon$, the ray is in a null-value region; increase step size [S9][S15, unofficial].
*   **Gradient-Based:** Compute gradient magnitude $|\nabla s|$. Take smaller steps where $|\nabla s|$ is high (surfaces) and larger steps in smooth interiors [S9].
*   **Variance-Based (Macrocell):** For each macrocell, compute $m = \sqrt{dVar(f_{cell})} / \sqrt{dVar(f_{vol})}$. Multiplier $M = 2m - 1 + 1$. Use $M \Delta t$ as the new sampling rate for uniform sampling, or modify increments for differential sampling [S12].
*   **Two-Rate Silhouette Detection:** Use base rate $r_0$ and max rate $r_1 = n r_0$ (typically $n=8$). Switch to $r_1$ when $|sample\_value - \rho| < \delta$ to guarantee intersection detection near silhouettes [S10].
*   **Two-Phase Cloud Sampling:** Initialize `zero_density_sample_count = 0`. If `sampled_density == 0.0`, increment count. If count < 6, accumulate density with reduced weight. If count == 6, reset and exit dense mode [S13, unofficial].

**Pseudocode (Gradient-Based with Early Termination):**

```python
def adaptive_sample_ray(ray_origin, ray_direction, volume, t_start, t_end, 
                        isovalue, delta_threshold, epsilon=0.02):
    color = vec3(0.0)
    opacity = 0.0
    t = t_start
    
    # Initial step size based on voxel size
    step_size = get_initial_step_size(volume) 
    
    while t < t_end and opacity < 1.0 - epsilon:
        # Sample scalar value
        pos = ray_origin + t * ray_direction
        s = volume.sample(pos)
        
        # Compute transfer function values
        alpha, color_contrib = transfer_function(s, step_size)
        
        # Composite
        color += (1.0 - opacity) * color_contrib
        opacity += (1.0 - opacity) * alpha
        
        # Check for early termination
        if opacity >= 1.0 - epsilon:
            break
            
        # Adaptive Step Size Calculation
        # Example: Gradient-based
        grad_mag = compute_gradient_magnitude(volume, pos)
        
        # Bound step size
        min_step = get_min_step(volume)
        max_step = get_max_step(volume)
        
        # Adapt: smaller steps for high gradient
        new_step = max_step / (1.0 + grad_mag)
        step_size = clamp(new_step, min_step, max_step)
        
        # Special case: Silhouette detection (if isosurface rendering)
        if isovalue is not None:
            if abs(s - isovalue) < delta_threshold:
                step_size = min(step_size, get_max_step(volume) / 8.0)
        
        t += step_size
        
    return color
```

## Subtopics

### [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md)
Uses a sparse grid of rays and increases density in high-complexity regions. Sets itself apart by using sparse data structures to reduce bricking overhead, relying on spatial heuristics rather than statistical error bounds.

### [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md)
Tracks per-pixel luminance squares to estimate error. Sets itself apart by using statistical error metrics per-pixel rather than geometric proximity to isosurfaces.

### [Adaptive Sampling in Volume Rendering](5700-adaptive-sampling-in-volume-rendering.md)
Enumerates non-empty leaves in front-to-back order and matches step size to local voxel density. Sets itself apart by linking discrete step size to octree levels for compact 2D transfer functions.

### [Bricked Multi-Resolution Single-Pass Ray-Casting](13222-bricked-multi-resolution-single-pass-ray-casting.md)
Combines hierarchical bricking with adaptive sampling. Sets itself apart by executing a single-pass fragment program that performs both adaptive object-space and image-space sampling, using LOD selection for neighborhood samples.

### Adaptive Sampling for Silhouettes
A strategy using two discrete rates (base $r_0$ and max $r_1$) to improve intersection detection near silhouettes without diverging parallel execution pipelines [S10]. Intersection is detected when sample value $f < \rho$. Guaranteed intersections for thin sheets require gradient length bounded by $L$, with step size $h = |f - \rho|/L$ [S10]. Base rate $r_0$ is user-specified (1.0 = 1 voxel). Max rate $r_1 = n r_0$ (typical $n=8$). Rate increases from $r_0$ to $r_1$ when $|sample\_value - \rho| < \delta$ [S10]. Pitfall: Completely adaptive sampling causes thread divergence in SIMD GPUs; using only two discrete rates mitigates this [S10].

### Adaptive Sampling with Opacity Correction
An approach that adapts sampling frequency to the finest level cell size while keeping total samples tractable, combined with opacity correction [S16]. Unlike generic adaptive sampling, it is tailored for AMR (Adaptive Mesh Refinement) hierarchies, avoiding the under- or over-sampling issues of hierarchy-unaware methods [S16].

### Adaptive Slicing with Slant Limiting
Calculates slant $dh = k_{max} - k_{min}$ and slices the volume into a prism [S17]. Uses slant-limited parameters to prevent infinity at grazing angles ($k_M = 2h$) [S17]. Chooses sampling rates close to voxel size to improve time, unlike applications that choose higher rates for quality [S17]. Pitfall: Grazing angles cause infinite slant; handled by limiting to $k_M$ [S17].

## Operating characteristics
*   **Time Complexity:** Can achieve logarithmic time complexity for low-opacity uniform fog or hit-and-stop high-opacity cases [S3, unofficial]. Generally reduces total samples compared to uniform sampling, but adds overhead for metric computation.
*   **Memory Complexity:** Depends on the underlying data structure (e.g., bricking, octree). Adaptive sampling itself does not significantly increase memory usage beyond the volume data and temporary accumulators.
*   **Performance:** Achieves speed-ups of 2.6–2.8 compared to full density sampling [S6, unofficial]. On the Asian Dragon dataset (512x256x256), adaptive sampling with bricking achieves 80–85% of the performance of rendering without bricking and without adaptive sampling [S10]. Frame rates vary significantly with sampling rate; e.g., 19.2 fps at rate 0.25 vs 6.9 fps at rate 2 for $r_1=8r_0$ with brick size 32 [S10].
*   **Strengths:** Significantly reduces computation in low-detail/empty regions [S7, unofficial][S14]. Preserves visual quality in high-detail areas [S1, unofficial][S9].
*   **Limitations:** Purely adaptive methods (e.g., per-pixel gradient) perform poorly on GPUs due to poor thread coherence [S12, S14]. Requires careful tuning of parameters ($\epsilon, \delta, \Delta t_{min/max}$) [S10]. Silhouette detection may miss intersections if step size is too large relative to gradient bounds [S10].
*   **When to Use:** Large datasets with significant empty space or homogeneous regions [S7, unofficial][S14]. Real-time rendering where frame budget is critical [S8, unofficial].
*   **When Not to Use:** Highly uniform data where overhead outweighs benefits. Scenes requiring strict statistical convergence guarantees (use [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md) instead).

## Background
Adaptive sampling was introduced by Hanrahan et al. in 1992 [S2, unofficial]. It was developed to address the inefficiency of uniform sampling in volume rendering, where many samples contribute little to the final image. The technique has since been adapted for various hardware architectures, including multi-core CPUs [S3, unofficial] and GPUs [S6, unofficial][S10, S12], with modifications to handle SIMD constraints [S14]. It is widely used in medical imaging, scientific visualization, and real-time cloud rendering [S1, unofficial][S9][S13, unofficial].
