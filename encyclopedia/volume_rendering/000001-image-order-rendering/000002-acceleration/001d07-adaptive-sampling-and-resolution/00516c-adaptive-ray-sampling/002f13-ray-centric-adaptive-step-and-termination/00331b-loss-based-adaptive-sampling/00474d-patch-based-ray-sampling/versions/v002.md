# Patch-based Ray Sampling
Also called: DW loss ray sampling, adjacent ray sampling

## Overview
A ray sampling strategy where rays are sampled in contiguous 2D patches to form a local image grid, ensuring the spatial adjacency required for Discrete Wavelet Transform (DWT) based loss calculation [S1, unofficial]. It is distinguished from random ray sampling by its focus on capturing local high-frequency structures rather than global scene geometry [S1, unofficial].

## How it works
**Inputs and outputs:**
- Input: A batch of rays intended for a specific loss component (specifically $L_{DW}$).
- Output: A set of ray origins and directions that form a contiguous $W \times H$ rectangular region in the image plane.

**Data structures:**
- The rays are organized into a 2D grid structure corresponding to pixel coordinates $(u, v)$ within the patch.
- Each ray $r_{i,j}$ corresponds to the pixel at row $i$ and column $j$ of the patch.

**Parameters:**
- Patch size: Typically $192 \times 192$ square patches [S1, unofficial].
- Ray count per patch: $192 \times 192 = 36,864$ rays [S1, unofficial].

**Steps:**
1. Select a starting pixel coordinate $(u_0, v_0)$ within the image bounds.
2. Define the patch dimensions $W \times H$ (e.g., $192 \times 192$) [S1, unofficial].
3. For each local coordinate $(i, j)$ where $0 \le i < H$ and $0 \le j < W$:
   - Compute global pixel coordinates: $u = u_0 + j$, $v = v_0 + i$.
   - Generate the ray $r_{u,v}$ passing through pixel $(u, v)$ from the camera center.
   - Store $r_{u,v}$ in the patch buffer at index $(i, j)$.
4. Return the patch buffer containing the $W \times H$ rays [S1, unofficial].

**Edge cases and pitfalls:**
- Boundary conditions: The starting coordinate $(u_0, v_0)$ must ensure the entire $W \times H$ patch fits within the image resolution. If the image is smaller than the patch size, the method cannot be applied as defined [S1, unofficial].
- Loss application: This sampling mode is exclusively used for calculating the DWT loss ($L_{DW}$). Random ray sampling is used for Mean Squared Error loss ($L_{MSE}$) to capture global structures [S1, unofficial].

## Subtopics

### Grid-based Patch Sampling
A variant where rays are divided into equal-size patches following rigid grid lines determined by a fixed grid size, which are then shuffled and fed into the super-resolution NeRF pipeline [S2]. It is chosen for its simplicity in implementation but suffers from a specific pitfall: the rigid grid cuts ray space strictly, causing variations located between grid boundaries to never be seen by convolutional kernels during training [S2].

## Operating characteristics
- **Time complexity:** Not given in the sources.
- **Memory complexity:** Requires storing $W \times H$ rays per patch. For a $192 \times 192$ patch, this is 36,864 rays [S1, unofficial].
- **Performance:** Used in DWTNeRF on LLFF and NeRF-Synthetic datasets with GeForce RTX 4070 Ti Super [S1, unofficial].
- **Strengths:** Enables the calculation of DWT loss by providing the necessary spatial adjacency of rays [S1, unofficial].
- **Limitations:** Rigid grid variants (Grid-based Patch Sampling) fail to capture patterns at grid boundaries [S2].

## Background
Originated in DWTNeRF, which boosts few-shot Neural Radiance Fields via Discrete Wavelet Transform [S1, unofficial]. The method was introduced to address the need for local structure encoding in super-resolution-based NeRF pipelines, contrasting with the global structure focus of random sampling [S1, unofficial]. Grid-based patch sampling was later critiqued and refined by FastSR-NeRF, which proposed random patch sampling to mitigate boundary artifacts [S2].
