# Adaptive Sampling

Also called: Adaptive Sampling Rate, Adaptive Sampling Strategy, Adaptive allocation of samples

## Overview
Adaptive sampling is a volume rendering optimization that varies the density of samples along rays to match local data complexity, providing higher quality in non-homogeneous regions while reducing computational cost in homogeneous or empty areas [S1, S2, unofficial][S10]. It sets itself apart from its siblings by focusing on the spatial distribution of samples based on geometric or scalar field properties (such as gradient magnitude or opacity) rather than purely statistical error bounds [S1, S2, S5, S7, unofficial][S10][S12, unofficial][S13][S14][S15] or interaction latency targets [S8, unofficial]. Unlike [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md) which uses per-pixel luminance variance, or [Loss-based Adaptive Sampling](6928-loss-based-adaptive-sampling.md) which minimizes training loss, this method relies on local data characteristics to determine step sizes or sampling rates [S1, S2, S7, unofficial][S10][S12, unofficial].

## How it works
**Inputs:**
*   Volume dataset $V$ (scalar field) [G].
*   Ray origin $O$ and direction $D$ [G].
*   Entry and exit points $t_{start}$ and $t_{end}$ (bounding box intersection) [G].
*   Transfer function parameters: absorption $\kappa(s)$ and emission $q(s)$ mapping scalar values to color and opacity [S1, unofficial].
*   Isosurface threshold $\rho$ (optional, for silhouette detection) [S10].
*   Parameters: $\Delta t_{min}$, $\Delta t_{max}$, $\epsilon$ (opacity threshold, typically $0.01$ to $0.05$) [S10], $\delta$ (silhouette threshold) [S11], $L$ (gradient bound) [S11].

**Outputs:**
*   Final pixel color $C$ and accumulated opacity $A$ [G].

**Data Structures:**
*   Accumulators: `color` (RGB vector), `opacity` (scalar) [G].
*   State variables: `current_t` (float), `step_size` (float) [G].

**Algorithm Steps:**

1.  **Initialization:**
    Set `color = (0, 0, 0)`, `opacity = 0.0`, `current_t = t_start` [G].
    Set initial `step_size` to the base voxel spacing or a user-defined constant [G].

2.  **Ray Marching Loop:**
    While `current_t < t_end` and `opacity < 1.0 - \epsilon` [S10]:
    
    a. **Sample:** Evaluate scalar value $s = V(O + current_t \cdot D)$ [G].
    
    b. **Compute Contribution:**
       Calculate opacity $\alpha = 1 - e^{-\kappa(s) \cdot \Delta t}$ and color contribution $c = q(s) \cdot \Delta t$ [S1, unofficial].
    
    c. **Front-to-Back Compositing:**
       $C_{new} = C_{old} + (1 - A_{old}) \cdot c$ [G]
       $A_{new} = A_{old} + (1 - A_{old}) \cdot \alpha$ [G]
       Update `color` and `opacity` [G].
    
    d. **Adapt Step Size:**
       Compute metric $M$ based on local data (see variants) [G].
       Update `step_size` using adaptation law:
       $$ \Delta t_{new} = \min(\Delta t_{max}, \max(\Delta t_{min}, f(M))) $$
       [G] Common functions $f(M)$ include $1/M$ or proportional scaling.
    
    e. **Advance:**
       `current_t += step_size` [G].

3.  **Termination:**
    If `opacity >= 1.0 - \epsilon`, break loop (Early Ray Termination) [S10].
    Return `color` [G].

**Variants of Metric Evaluation and Adaptation:**

*   **Opacity-Based:** Increase step size inversely with local opacity. If accumulated opacity change $\Delta A = A_i - A_{i-1} < \epsilon$, the ray is in a null-value region; increase step size [S10].
*   **Gradient-Based:** Compute gradient magnitude $|\nabla s|$. Take smaller steps where $|\nabla s|$ is high (surfaces) and larger steps in smooth interiors [S10].
*   **Variance-Based (Macrocell):** For each macrocell, compute $m = \sqrt{dVar(f_{cell})} / \sqrt{dVar(f_{vol})}$. Multiplier $M = 2m - 1 + 1$. Use $M \Delta t$ as the new sampling rate for uniform sampling, or modify increments for differential sampling [S15].
*   **Two-Rate Silhouette Detection:** Use base rate $r_0$ and max rate $r_1 = n r_0$ (typically $n=8$). Switch to $r_1$ when $|sample\_value - \rho| < \delta$ to guarantee intersection detection near silhouettes [S11].
*   **Two-Phase Cloud Sampling:** Initialize `zero_density_sample_count = 0`. If `sampled_density == 0.0`, increment count. If count < 6, accumulate density with reduced weight. If count == 6, reset and exit dense mode [S16, unofficial].

**Pseudocode (Gradient-Based with Early Termination):**

```python
import math

def adaptive_sample_ray(ray_origin, ray_direction, volume_sample_fn, t_start, t_end, 
                        kappa_fn, q_fn, min_step, max_step, epsilon=0.02, 
                        isovalue=None, delta_threshold=None):
    color = [0.0, 0.0, 0.0]
    opacity = 0.0
    t = t_start
    step_size = max_step  # Initialize to maximum allowed step

    while t < t_end and opacity < 1.0 - epsilon:
        pos = ray_origin + t * ray_direction
        s = volume_sample_fn(pos)

        # Compute transfer function values for current step
        k = kappa_fn(s)
        q = q_fn(s)
        alpha = 1.0 - math.exp(-k * step_size)
        color_contrib = [q * step_size, q * step_size, q * step_size]  # Simplified emission

        # Front-to-back compositing
        color[0] += (1.0 - opacity) * color_contrib[0]
        color[1] += (1.0 - opacity) * color_contrib[1]
        color[2] += (1.0 - opacity) * color_contrib[2]
        opacity += (1.0 - opacity) * alpha

        if opacity >= 1.0 - epsilon:
            break

        # Adaptive step size calculation
        # Example: Gradient-based metric using finite difference
        s_next = volume_sample_fn(pos + ray_direction * step_size)
        grad_mag = abs(s_next - s) / step_size

        # Adapt: smaller steps for high gradient
        new_step = max_step / (1.0 + grad_mag)
        step_size = max(min_step, min(max_step, new_step))

        # Special case: Silhouette detection
        if isovalue is not None and delta_threshold is not None:
            if abs(s - isovalue) < delta_threshold:
                step_size = min(step_size, max_step / 8.0)

        t += step_size

    return color
```

## Subtopics

### [Adaptive Sampling (Sparse Grid)](1656-adaptive-sampling-sparse-grid.md)
Generates successively refined images by casting a sparse grid of rays and adaptively increasing density in high-complexity regions. Sets itself apart by using sparse data structures and spatial heuristics rather than statistical error bounds. Choose when memory bandwidth is limited and spatial coherence can be exploited.

### [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md)
Tracks per-pixel luminance squares to estimate relative standard error, stopping converged pixels and skipping noisy neighborhoods. Sets itself apart by using statistical error metrics per-pixel rather than geometric proximity to isosurfaces. Choose when strict visual convergence guarantees are required over raw speed.

### [Adaptive Sampling in Volume Rendering](5700-adaptive-sampling-in-volume-rendering.md)
Enumerates non-empty leaves in front-to-back order and matches step size to local voxel density, adapting sampling density to brick resolution. Sets itself apart by explicitly linking discrete step size to octree levels to enable compact 2D transfer functions. Choose when rendering hierarchical brick-based volumes with complex transfer functions.

### [Bricked Multi-Resolution Single-Pass Ray-Casting](13222-bricked-multi-resolution-single-pass-ray-casting.md)
Combines hierarchical data storage (bricking) with adaptive sampling to render large-scale multi-resolution volumes in a single pass. Sets itself apart by executing a single-pass fragment program that performs both adaptive object-space and image-space sampling, using LOD selection for neighborhood samples. Choose for interactive rendering of massive datasets on GPUs.

### Adaptive Sampling for Silhouettes
A strategy using two discrete rates (base $r_0$ and max $r_1$) to improve intersection detection near silhouettes without diverging parallel execution pipelines [S11]. Sets itself apart by guaranteeing intersection detection for thin sheets via bounded gradient steps, unlike fully continuous adaptive methods [S11]. Choose when rendering isosurfaces or distance fields where silhouette accuracy is critical [S11].

### Adaptive Sampling with Opacity Correction
An approach that adapts sampling frequency to the finest level cell size while keeping total samples tractable, combined with opacity correction [S23]. Sets itself apart by being tailored for AMR (Adaptive Mesh Refinement) hierarchies, avoiding the under- or over-sampling issues of hierarchy-unaware methods [S23]. Choose when rendering AMR datasets where cell sizes vary drastically [S23].

### Adaptive Slicing with Slant Limiting
Calculates slant $dh = k_{max} - k_{min}$ and slices the volume into a prism, choosing sampling rates close to voxel size to improve rendering time [S24]. Sets itself apart by using slant-limited parameters to prevent infinity at grazing angles ($k_M = 2h$), unlike applications that choose higher rates for quality [S24]. Choose when rendering forest scenes or terrain with extreme view angles [S24].

## Operating characteristics
*   **Time Complexity:** Can achieve logarithmic time complexity for low-opacity uniform fog or hit-and-stop high-opacity cases [S3, unofficial]. Generally reduces total samples compared to uniform sampling, but adds overhead for metric computation [S10].
*   **Memory Complexity:** Depends on the underlying data structure (e.g., bricking, octree) [S11]. Adaptive sampling itself does not significantly increase memory usage beyond the volume data and temporary accumulators [G].
*   **Performance:** Achieves speed-ups of 2.6–2.8 compared to full density sampling [S6, unofficial]. On the Asian Dragon dataset (512x256x256), adaptive sampling with bricking achieves 80–85% of the performance of rendering without bricking and without adaptive sampling [S11]. Frame rates vary significantly with sampling rate; e.g., 19.2 fps at rate 0.25 vs 6.9 fps at rate 2 for $r_1=8r_0$ with brick size 32 [S11].
*   **Strengths:** Significantly reduces computation in low-detail/empty regions [S7, unofficial][S14]. Preserves visual quality in high-detail areas [S1, unofficial][S10].
*   **Limitations:** Purely adaptive methods (e.g., per-pixel gradient) perform poorly on GPUs due to poor thread coherence [S12, unofficial][S14]. Requires careful tuning of parameters ($\epsilon, \delta, \Delta t_{min/max}$) [S10]. Silhouette detection may miss intersections if step size is too large relative to gradient bounds [S11].
*   **When to Use:** Large datasets with significant empty space or homogeneous regions [S7, unofficial][S14]. Real-time rendering where frame budget is critical [S8, unofficial].
*   **When Not to Use:** Highly uniform data where overhead outweighs benefits [S7, unofficial]. Scenes requiring strict statistical convergence guarantees (use [Adaptive Sampling with Relative Standard Error](4545-adaptive-sampling-with-relative-standard-error.md) instead) [G].

## Background
Adaptive sampling was introduced by Hanrahan et al. in 1992 [S2, unofficial]. It was developed to address the inefficiency of uniform sampling in volume rendering, where many samples contribute little to the final image. The technique has since been adapted for various hardware architectures, including multi-core CPUs [S3, unofficial] and GPUs [S6, unofficial][S10][S12, unofficial], with modifications to handle SIMD constraints [S14]. It is widely used in medical imaging, scientific visualization, and real-time cloud rendering [S1, unofficial][S10][S13].
