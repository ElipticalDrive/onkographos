# Mixed-Resolution Multi-Volume Rendering
Also called: Per-channel resolution selection
## Overview
Mixed-resolution multi-volume rendering is a technique where different channels of a multi-volume dataset are rendered at different resolution levels to save memory and reduce sample evaluation [S1, unofficial][S2]. It addresses the inefficiency of rendering all channels at the highest resolution when some channels have lower frequency content or lower visual importance [S1, unofficial][S2]. It is distinct from [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) which typically apply uniform resolution changes across the entire volume, and from [Dynamic Volume Resolution & Alpha Mask Update](2539-dynamic-volume-resolution-alpha-mask-update.md) which focuses on global resolution updates based on occupancy [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
- Input: A multi-volume dataset with $N$ channels, each having a multi-resolution hierarchy (levels $l_0$ to $l_{max}$, where $l_0$ is highest resolution).
- Input: Viewing parameters (camera position, ray direction).
- Input: Per-channel resolution constraint functions.
- Output: Rendered image with each channel sampled at its selected resolution level.

**Data Structures:**
- **Channel Resolution Map**: A mapping from channel index $c$ to a selected resolution level $l_c$. This can be static or dynamic.
- **Resolution Constraint Function**: A function $f_c(view\_params)$ that returns a valid resolution level or range for channel $c$.

**Steps:**
1. **Initialize**: For each ray, determine the viewing parameters (e.g., distance to camera for each sample point).
2. **Select Resolution**: For each channel $c$, evaluate its constraint function $f_c$ to determine the resolution level $l_c$ to use. The function may consider:
   - Frequency content of the channel [S1, unofficial][S2].
   - Viewing parameters (e.g., distance to camera) [S1, unofficial][S2].
   - Transfer functions [S1, unofficial][S2].
   - User-defined bounds [S1, unofficial][S2].
3. **Upload Data**: Upload only the bricks/data for the selected resolution level $l_c$ for each channel $c$ to the GPU [S1, unofficial][S2]. This limits the range of resolutions uploaded per channel [S1, unofficial][S2].
4. **Sample**: For each ray sample, sample channel $c$ at resolution $l_c$. The sampling rate may vary per channel; e.g., high-frequency channels may require sampling at every step, while low-frequency channels may be sampled every second step [S1, unofficial][S2].
5. **Composite**: Composite the samples from all channels at their respective resolutions to form the final pixel color.

**Formulas:**
- Resolution Level Selection: $l_c = f_c(view\_params)$
- Sampling Rate: $s_c$ samples per unit distance for channel $c$, where $s_c$ may depend on $l_c$ and frequency content [S1, unofficial][S2].

**Parameters:**
- Resolution Levels: $l_0$ (highest), $l_1$, ..., $l_{max}$ (lowest). Typical values depend on the dataset; e.g., $l_0$ to $l_5$ [S1, unofficial].
- Sampling Rate: Can be fixed per channel or adaptive. Example: high-frequency channel sampled every step, low-frequency every second step [S1, unofficial][S2].

**Edge Cases and Pitfalls:**
- **High-Frequency Content**: A channel with high-frequency content may require a higher sampling rate or higher resolution level to avoid aliasing [S1, unofficial][S2].
- **Boundary Conditions**: Ensure that the resolution constraint function handles edge cases, such as when the camera is very close or far [S1, unofficial][S2].
- **Memory Management**: Limiting the range of resolutions uploaded per channel helps manage GPU memory, but requires careful management of data loading/unloading [S1, unofficial][S2].

**Pseudocode:**

def render_mixed_resolution_volume(rays, channels, resolution_functions):
    """
    rays: list of ray objects, each with position and direction
    channels: list of channel objects, each with multi-resolution data
    resolution_functions: list of functions, one per channel, taking view_params and returning resolution level
    """
    image = zeros_like(rays)
    
    for ray in rays:
        # Determine view parameters for this ray
        view_params = get_view_params(ray)
        
        # Initialize accumulated color and alpha
        acc_color = vec3(0.0)
        acc_alpha = 0.0
        
        # Determine sampling parameters for each channel
        channel_params = []
        for c_idx, channel in enumerate(channels):
            # Select resolution level for this channel
            l_c = resolution_functions[c_idx](view_params)
            
            # Determine sampling rate based on resolution and frequency content
            # [G] Assuming a simple heuristic: higher resolution -> higher sampling rate
            # This is a placeholder for the actual logic described in [S1, unofficial][S2]
            sampling_rate = get_sampling_rate(channel, l_c)
            
            channel_params.append({
                'channel': channel,
                'resolution_level': l_c,
                'sampling_rate': sampling_rate
            })
        
        # Sample along the ray
        t = ray.origin
        dt = get_step_size(ray, max(channel_params, key=lambda x: x['sampling_rate'])['sampling_rate'])
        
        while t < ray.far_plane:
            # Evaluate all channels at current t
            for cp in channel_params:
                channel = cp['channel']
                l_c = cp['resolution_level']
                sampling_rate = cp['sampling_rate']
                
                # Sample the channel at the selected resolution
                # [G] Assuming a function to sample a channel at a specific resolution
                value = sample_channel_at_resolution(channel, l_c, t)
                
                # Get transfer function value
                color, alpha = apply_transfer_function(value)
                
                # Composite
                # [G] Standard front-to-back compositing
                weight = alpha * (1.0 - acc_alpha)
                acc_color += weight * color
                acc_alpha += weight
                
                if acc_alpha > 0.99:
                    break
            
            t += dt
        
        image[ray.id] = acc_color
    
    return image

## Operating characteristics
- **Time Complexity**: Depends on the number of channels and the selected resolution levels. Lower resolution levels reduce the number of samples and data transfer, improving performance [S1, unofficial][S2].
- **Memory Complexity**: Reduced by uploading only the necessary resolution levels per channel to the GPU [S1, unofficial][S2].
- **Performance**: Significant memory savings and reduced sample evaluation for channels with lower frequency content or importance [S1, unofficial][S2].
- **Strengths**: Efficient rendering of large-scale multi-volume data by exploiting differences in channel frequency and importance [S1, unofficial][S2].
- **Limitations**: Requires careful selection of resolution levels and sampling rates to avoid visual artifacts, especially for high-frequency channels [S1, unofficial][S2].

## Background
Mixed-resolution multi-volume rendering was introduced in the context of scalable web-based volume rendering of large biomedical datasets [S1, unofficial][S2]. It leverages multi-resolution hierarchies and out-of-core methods to manage memory and computational load [S1, unofficial][S2]. The technique is particularly useful for datasets with multiple channels where not all channels require the same level of detail [S1, unofficial][S2].
