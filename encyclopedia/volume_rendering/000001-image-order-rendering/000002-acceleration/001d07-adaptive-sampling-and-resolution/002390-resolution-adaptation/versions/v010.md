# Resolution Adaptation

Also called: Adaptive Resolution, Dynamic Resolution, View-Dependent Resolution

## Overview
Resolution Adaptation is a family of image-order rendering acceleration techniques that dynamically adjust the spatial discretization of the volume rendering process—such as voxel grid resolution, ray step size, or screen-space sampling density—to balance computational cost and visual fidelity [S1][S2, unofficial][S3]. It solves the problem of computational intensity in large or complex scalar fields by trading accuracy for speed in real-time, ensuring responsive frame rates during user interaction or maintaining target frame rates under variable load [S2, unofficial][S4, unofficial]. Unlike static hierarchical structures, these methods adapt continuously or periodically based on performance metrics (e.g., frame time) or visual error metrics, distinguishing them from sibling methods like [Two-stage NeRF Rendering](925-two-stage-nerf-rendering.md) which uses fixed coarse-to-fine passes, or [Random Pixel Subsampling](1668-random-pixel-subsampling.md) which reduces sample count without changing spatial resolution [S1][S2, unofficial].

## Shared principles
All methods in this family share the core mechanism of modulating the granularity of the rendering representation to control the number of evaluated samples or the complexity of the geometry. The fundamental trade-off is between the error $\epsilon$ in the approximate field $\bar{f}$ and the computational cost, where $|\bar{f} - f| \le \epsilon$ [S1].

The general loop involves:
1.  **Metric Evaluation:** Computing a scalar value that dictates the required resolution. This is either a **performance-based** metric (e.g., ratio of actual render time to target frame time) or a **visual error-based** metric (e.g., texel density, frequency content, or distance to camera) [S1][S2, unofficial].
2.  **Discretization Adjustment:** Modifying parameters such as the voxel grid resolution $R$, the step size $\Delta t$, the number of slices, or the screen-space reduction factor $n$ [S2, unofficial][S4, unofficial].
3.  **Rendering:** Executing the volume integral using the adjusted discretization [S1].

Key mathematical constraints often include clamping the resolution factor to a valid range (e.g., $n \in [2, 5]$ or reduction factor $\in (0.0, 1.0]$) to prevent instability or infinite resolution [S4, unofficial][S1].

## Subtopics

### [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md)
LOD methods maintain responsive frame rates by generating reduced-resolution approximations of the original data during viewpoint interaction. They solve the problem of computational intensity by dynamically adjusting discretization (step size, sample count, or spatial resolution) based on visual error or performance metrics. Unlike static hierarchical structures, these methods adapt in real-time to user manipulation, trading accuracy for speed. They differ from siblings like [Dynamic Volume Resolution](2683-dynamic-resolution-adaptation.md) by often using geometric distance or texel density metrics rather than pure frame-time feedback loops.

### [Dynamic Volume Resolution & Alpha Mask Update](2539-dynamic-volume-resolution-alpha-mask-update.md)
This method dynamically adjusts the spatial resolution of a volume representation and updates an occupancy alpha mask during the training or rendering pipeline. It solves the problem of inefficient rendering in sparse regions by pruning empty space and adapting voxel grid density based on scheduled iteration milestones. It differs from static LOD methods by using a feedback loop of scheduled upscaling and mask regeneration rather than geometric distance metrics, and from pure dynamic resolution methods by explicitly maintaining a binary occupancy mask to cull empty voxels.

### [Dynamic Resolution Adaptation](2683-dynamic-resolution-adaptation.md)
Dynamic Resolution Adaptation is a runtime performance management technique that adjusts the render viewport reduction factor based on previous frame render time and an allocated time budget to maintain a target frame rate. It solves the problem of performance instability in volume rendering, where small parametric changes can cause frame rate dips leading to cybersickness. It sets itself apart from static resolution schemes by continuously shifting the "anchor points" between resolution levels based on the gradient of recent frame times, rather than using fixed blending factors.

### [Mixed-Resolution Multi-Volume Rendering](3193-mixed-resolution-multi-volume-rendering.md)
Mixed-resolution multi-volume rendering is a technique where different channels of a multi-volume dataset are rendered at different spatial resolution levels to save memory and reduce sample evaluation costs. It addresses the inefficiency of rendering all channels at the highest resolution when some channels have lower frequency content or lower visual importance. It differs from [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) by applying resolution variation per-channel rather than per-viewpoint-distance.

### [Focus and Context Multiresolution Rendering](8163-focus-and-context-multiresolution-rendering.md)
Focus and Context Multiresolution Rendering is a technique to balance processing capacity between a high-detail focus region and a lower-detail context region to improve interactivity in time-critical applications. It sets itself apart from sibling methods like [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) by explicitly separating the scene into two distinct rendering passes with different resolutions and complexity levels, rather than adapting a single view's resolution based on distance or error metrics. The goal is not seamless integration but a tradeoff between achievable quality and speed.

### [Multiresolution Atlas Buffer (MAB)](8219-multiresolution-atlas-buffer-mab.md)
The Multiresolution Atlas Buffer (MAB) is an acceleration wrapper for Direct Volume Rendering (DVR) in Virtual Reality (VR) that reduces ray density adaptively based on peripheral vision and Head-Mounted Display (HMD) lens distortion, then reconstructs the full-resolution image via compositing. It differs from standard foveated rendering by not requiring high-speed eye-tracking hardware, relying instead on the fixed nature of HMD lenses and the known non-uniform resolution of the human visual system. Unlike [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) which often modify the geometry or volume data structure itself, MAB operates as a "bracket" around existing raycasting implementations, modifying ray construction and post-traversal compositing without altering the core traversal logic.

### Mixed Resolution Scene Rendering
- [S1] Combines full-resolution scene elements with low-resolution high-density volume data by rendering the volume to off-screen targets and projecting them onto a quad.
- [S1] Setup two off-screen cameras, one to follow each eye that update each frame.
- [S1] Setup two low-resolution render targets (that is, 200x200 each) that the cameras render into.
- [S1] Set up a quad that moves in front of the user.
- [S1] Each Frame: Draw the render targets for each eye at low-resolution (volume data, expensive shaders, and so on).
- [S1] Each Frame: Draw the scene normally as full resolution (meshes, UI, and so on).
- [S1] Each Frame: Draw a quad in front of the user, over the scene, and project the low-res renders onto that.

### Volume Level-of-Detail (LOD) Rendering
- [S3] A rendering process that maximizes image quality within user-specified frame rate and system constraints (RAM, texture memory, bandwidth) by adaptively modifying the set of rendered cells.
- [S3] Adapt/Load Phase: Determine which octree cells to render. Load non-resident textures from RAM or disk to texture memory. Maintain an 'active cut' (nodes covering space exactly once).
- [S3] Active Cut Maintenance: Split queue contains non-leaf nodes on active cut, sorted by decreasing error. To decrease error: Move first split node to merge queue (mark inactive), add its children to split queue (mark active). To increase error (frame rate): Remove first node from merge queue to split queue (mark active), add its parent to merge queue, remove children from split queue (mark inactive).
- [S3] Cull/Render Phase: Traverse octree from root. Perform hierarchical cull. Render flagged nodes using 3D texture mapping and blending in back-to-front order.
- [S3] User parameters: Desired frame rate, transfer function (data to RGBA), view position.
- [S3] System parameters: RAM, texture memory size, bandwidths, polygon and fill performance.

## Background
The concept of Level-of-Detail (LOD) in volume rendering originated from the need to handle large unstructured grids and voxel datasets interactively. Early work by Leven et al. (2002) introduced adaptive voxelization using hierarchical 3D structures (octrees) to manage the trade-off between image quality and system constraints like RAM and bandwidth [S3]. This was followed by various implementations focusing on GPU-based isosurface rendering and texture-based LOD, where metrics like texel density were used to adjust resolution [S4, unofficial]. In the context of Neural Radiance Fields (NeRF) and implicit representations, dynamic resolution and alpha mask updates were introduced to handle sparse data efficiently during training and rendering [S1]. More recently, techniques like MAB have been applied to VR to address the specific constraints of head-mounted displays and peripheral vision [S1].
