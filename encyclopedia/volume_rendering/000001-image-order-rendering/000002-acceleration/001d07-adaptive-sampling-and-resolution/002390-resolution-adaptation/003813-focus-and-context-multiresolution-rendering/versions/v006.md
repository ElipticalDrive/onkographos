# Focus and Context Multiresolution Rendering

Also called: Interactive lenses multiresolution, Time-critical multiresolution rendering

## Overview
Focus and Context Multiresolution Rendering is a technique to balance processing capacity between a high-detail focus region and a lower-detail context region to improve interactivity in time-critical applications [S1, unofficial]. It sets itself apart from sibling methods like [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) by explicitly decoupling the rendering parameters (resolution, lighting, sampling) of two distinct spatial regions rather than adjusting a single global level of detail. The goal is not seamless integration but a tradeoff between quality and speed [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset, a transfer function, a camera viewpoint, and a defined "focus" region (typically attached to a data probe or specific interest area).
*   **Output:** A composite image where the focus region is rendered at high fidelity and the context region is rendered at reduced fidelity.

**Data Structures:**
The method utilizes two distinct rendering configurations, often referred to as "Focus" and "Context" passes. The specific parameters used in the source evaluation are detailed below [S1, unofficial].

| Parameter | Focus Configuration | Context Configuration |
| :--- | :--- | :--- |
| **Volume Resolution** | $4 \times 256^3$ | $1 \times 128^3$ |
| **Lookup Table Size** | $5 \times 256^2$ | $4 \times 128^2$ |
| **Rendering Model** | Local lighting | Unshaded |
| **Sampling Rate** | 4 | 1 |
| **Viewport Size** | 100% | 50% |

*Note: All textures had 8-bit components [S1, unofficial].*

**Numbered Steps:**
1.  **Define Regions:** Identify the focus region (high detail) and the context region (low detail). The focus is placed closest to the user, mimicking typical interface usage [S1, unofficial].
2.  **Render Context:**
    *   Render the volume data for the context region into a smaller viewport (e.g., 50% of the screen width/height) [S1, unofficial].
    *   Use reduced resolution data (e.g., $128^3$ vs $256^3$) and a simpler rendering model (unshaded) [S1, unofficial].
    *   If the transfer function contains only low-frequency components, the context can be sampled sparsely [S1, unofficial].
    *   Apply a Gaussian filter to the resulting context image to reduce aliasing artifacts [S1, unofficial].
    *   Enlarge and composite the context image to fill its designated area of the final frame [S1, unofficial].
3.  **Render Focus:**
    *   Render the volume data for the focus region using the full viewport size (100%) [S1, unofficial].
    *   Use higher resolution data ($256^3$) and complex rendering models (local lighting) [S1, unofficial].
    *   The focus may be combined with polygonal visualization techniques (icons, streamlines) [S1, unofficial].
4.  **Composite:** Combine the rendered focus and context images. The method does not attempt seamless blending between the regions [S1, unofficial].

**Pseudocode:**
```python
def render_focus_context(volume_data, transfer_function, camera, focus_region, context_region):
    # Step 1: Setup Context Rendering
    # Use reduced resolution for context
    context_vol = downsample(volume_data, factor=2) # 256^3 -> 128^3
    context_lut = reduce_lut_size(transfer_function, base=128) # 256^2 -> 128^2
    
    # Render context into a smaller viewport (e.g., 50% size)
    # The source specifies drawing into a smaller viewport to reduce fragment count
    small_viewport_width = screen_width / 2
    small_viewport_height = screen_height / 2
    
    context_image = ray_march(
        volume=context_vol,
        lut=context_lut,
        camera=camera,
        viewport=(small_viewport_width, small_viewport_height),
        sampling_rate=1,
        shading_model="unshaded"
    )
    
    # Apply Gaussian filter to reduce aliasing
    context_image = gaussian_filter(context_image, sigma=1.0)
    
    # Enlarge context image to fill its portion of the screen
    # Assuming context occupies the background or non-focus area
    enlarged_context = resize(context_image, (screen_width, screen_height))
    
    # Step 2: Setup Focus Rendering
    # Use full resolution for focus
    focus_vol = volume_data # 256^3
    focus_lut = transfer_function # 256^2
    
    # Render focus into full viewport
    focus_image = ray_march(
        volume=focus_vol,
        lut=focus_lut,
        camera=camera,
        viewport=(screen_width, screen_height),
        sampling_rate=4,
        shading_model="local_lighting"
    )
    
    # Step 3: Composite
    # The source does not specify exact blending, but notes the goal is not seamless integration.
    # Typically, the focus region is drawn on top of the context.
    # For implementation, a mask defining the focus region is required.
    # [G] Assuming a binary mask 'focus_mask' is available where 1 is focus, 0 is context.
    final_image = blend(focus_image, enlarged_context, focus_mask)
    
    return final_image
```

**Parameters:**
*   **Context Rendering Mode:** Can be transparent (for orientation) or opaque (for external view) [S1, unofficial].
*   **Context Sampling:** Can be sparse if the transfer function contains only low frequency components [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Overhead:** Performance overhead comes from rendering slices multiple times and setting up clip textures and the depth buffer for each pass [S1, unofficial].
*   **Seamlessness:** The method does not aim for seamless integration between focus and context regions; visible seams or quality drops are expected [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The method achieves 2-6 times faster rendering rates than single high-resolution mode by reducing focus fragments aggressively [S1, unofficial].
*   **Memory:** Uses two sets of textures/LUTs with different resolutions. The source uses 8-bit components [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Effective for reducing clutter when exploring multidimensional or multifield datasets; allows complex transfer functions in the focus region while maintaining interactivity [S1, unofficial].
*   **Limitations:** Overhead from multiple render passes; not suitable for applications requiring seamless visual continuity between regions [S1, unofficial].

## Background
**Origin:**
The method was presented in "A Focus and Context Interface for Interactive Volume Rendering" by I. Kits et al. [S1, unofficial].

**History and Development:**
The approach was developed to address the limitations of hardware-accelerated volume rendering in time-critical applications. It builds on the principle that performance depends on the number of fragments processed, the work per fragment, and cache utilization [S1, unofficial].

**Where it is used:**
Used in interactive volume rendering applications where user interactivity is prioritized over perfect visual fidelity, particularly for exploring multidimensional datasets or combining volume rendering with polygonal visualization [S1, unofficial].
