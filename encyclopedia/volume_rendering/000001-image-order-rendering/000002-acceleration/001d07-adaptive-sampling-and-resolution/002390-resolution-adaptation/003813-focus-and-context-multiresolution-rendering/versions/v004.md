# Focus and Context Multiresolution Rendering

Also called: Interactive lenses multiresolution, Time-critical multiresolution rendering

## Overview
Focus and Context Multiresolution Rendering is a technique that balances processing capacity between a high-detail "focus" region and a lower-detail "context" region to improve interactivity in time-critical volume rendering applications [S1, unofficial]. It sets itself apart from sibling methods like [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) by explicitly separating the scene into two distinct rendering passes with different resolutions and rendering models, rather than adapting a single representation based on distance or error metrics. The goal is not seamless integration but a trade-off between achievable quality and speed [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A 3D volume dataset, a transfer function, a camera view, and a defined "focus" region (typically a data probe or specific object of interest).
*   **Outputs:** A composite image where the focus region is rendered at high resolution and the context region is rendered at lower resolution and enlarged.

**Data Structures and Layout:**
The method utilizes two distinct rendering configurations, often defined by parameters such as those in Table 1 of the source [S1, unofficial]:

| Parameter | Focus Region | Context Region |
| :--- | :--- | :--- |
| **Volume Resolution** | $4 \times 256^3$ (or full resolution subset) | $1 \times 128^3$ (subsampled) |
| **Lookup Table Size** | $5 \times 256^2$ | $4 \times 128^2$ |
| **Rendering Model** | Local lighting (shaded) | Unshaded |
| **Sampling Rate** | 4 | 1 |
| **Viewport Size** | 100% (of focus area) | 50% (of context area) |

*Note: The volume resolution for context is subsampled (e.g., $128^3$ vs $256^3$). The lookup table dimensions match the volume resolution.*

**Numbered Steps:**
1.  **Decomposition:** Divide the rendering task into two passes: one for the focus region and one for the context region. The focus is typically placed closest to the user [S1, unofficial].
2.  **Context Rendering:**
    *   Render the context volume into a smaller viewport (e.g., 50% of the screen or a reduced resolution buffer) [S1, unofficial].
    *   Use a simpler rendering model (e.g., unshaded) and lower sampling rate (e.g., 1) to reduce fragment count [S1, unofficial].
    *   If the transfer function contains only low-frequency components, sparse sampling may be used for the context [S1, unofficial].
    *   Apply a Gaussian filter to the resulting context image to reduce aliasing artifacts caused by the enlargement [S1, unofficial].
3.  **Focus Rendering:**
    *   Render the focus volume into the remaining viewport area (or full screen if context is overlaid) at high resolution [S1, unofficial].
    *   Use high-quality rendering settings (e.g., local lighting, higher sampling rate) [S1, unofficial].
4.  **Compositing:**
    *   Enlarge the filtered context image to match the screen resolution.
    *   Composite the focus and context images. The context may be transparent (for orientation) or opaque (for external view) [S1, unofficial].

**Pseudocode:**
```python
def render_focus_and_context(volume, transfer_function, camera, focus_region, screen_width, screen_height):
    # Define parameters based on source [S1, unofficial]
    focus_vol_res = 256
    context_vol_res = 128
    focus_sampling_rate = 4
    context_sampling_rate = 1
    context_viewport_scale = 0.5  # 50% viewport size
    
    # Step 1: Render Context
    # Render into a smaller buffer to reduce fragment count
    context_buffer_width = int(screen_width * context_viewport_scale)
    context_buffer_height = int(screen_height * context_viewport_scale)
    
    # Use subsampled volume and unshaded model
    context_image = render_volume(
        volume=volume,
        resolution=context_vol_res,
        transfer_function=transfer_function,
        sampling_rate=context_sampling_rate,
        model="unshaded",
        viewport_width=context_buffer_width,
        viewport_height=context_buffer_height
    )
    
    # Step 2: Filter Context to reduce aliasing
    # Apply Gaussian blur
    context_image_blurred = gaussian_filter(context_image, sigma=1.0)
    
    # Step 3: Enlarge Context Image
    # Resize to full screen resolution
    context_image_full = resize(context_image_blurred, (screen_width, screen_height))
    
    # Step 4: Render Focus
    # Render focus region at high resolution
    # Note: The focus region is typically a subset or the whole volume 
    # but rendered with higher quality settings.
    focus_image = render_volume(
        volume=volume,
        resolution=focus_vol_res,
        transfer_function=transfer_function,
        sampling_rate=focus_sampling_rate,
        model="local_lighting",
        viewport_width=screen_width,
        viewport_height=screen_height,
        region=focus_region  # Clip or mask to focus area
    )
    
    # Step 5: Composite
    # Combine focus and context. 
    # If context is transparent, blend. If opaque, replace.
    # The source implies context is often for orientation (transparent) 
    # or external view (opaque).
    if context_mode == "transparent":
        final_image = blend(focus_image, context_image_full, alpha=0.5) # Alpha not specified, [G]
    else:
        final_image = context_image_full # Opaque context replaces background
        
    return final_image
```

**Edge Cases and Pitfalls:**
*   **Overhead:** Rendering slices multiple times and setting up clip textures/depth buffers for each pass introduces overhead [S1, unofficial].
*   **Seamlessness:** The method does not aim for seamless integration; visible seams or quality drops at the boundary between focus and context are expected [S1, unofficial].
*   **Hardware Variability:** Performance can vary significantly depending on the graphics hardware (e.g., ATI Radeon 9800 Pro showed high variability in slicing performance from different directions) [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The method achieves 2-6 times faster rendering rates than single high-resolution mode by reducing focus fragments aggressively [S1, unofficial].
*   **Memory:** Uses two lookup tables and potentially two volume representations (or subsampled versions), increasing memory usage compared to a single-pass renderer.

**Measured Performance:**
Tests were conducted on a 2.0GHz Pentium 4, 2GB memory, ATI Radeon 9800 Pro [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Effective for time-critical applications where interactivity is more important than visual perfection. Simple to implement as a generic approach [S1, unofficial].
*   **Limitations:** Not suitable for applications requiring seamless visualization. Performance overhead from multiple rendering passes can negate gains on some hardware.

**When to Use:**
*   When exploring multidimensional or multifield datasets where clutter reduction is needed.
*   When a data probe with multiple attributes requires high-quality rendering while the surrounding context only needs orientation.

**When Not to Use:**
*   When seamless integration is required.
*   When the transfer function has high-frequency components in the context region (requires higher resolution context).

## Background
**Origin:**
The method was presented in the unpublished paper "A Focus and Context Interface for Interactive Volume Rendering" by I. Kits et al. [S1, unofficial].

**History and Development:**
The approach was developed to address the limitations of hardware-accelerated volume rendering in interactive applications. It builds on the idea of using subsampled data blocks to increase cache coherency and reduce sampling rates [S1, unofficial]. The authors noted that by incorporating early ray termination and empty space skipping acceleration, further improvements could be made [S1, unofficial].

**Usage:**
Used in interactive volume rendering applications where user interactivity is prioritized over visual fidelity, such as medical imaging exploration or scientific data analysis with multidimensional datasets.
