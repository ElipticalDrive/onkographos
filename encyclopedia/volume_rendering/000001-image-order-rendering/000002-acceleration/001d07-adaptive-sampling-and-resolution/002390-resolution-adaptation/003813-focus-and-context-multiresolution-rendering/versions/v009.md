# Focus and Context Multiresolution Rendering

Also called: Interactive lenses multiresolution, Time-critical multiresolution rendering

## Overview
Focus and Context Multiresolution Rendering is a technique that balances processing capacity between a high-detail "focus" region and a lower-detail "context" region to improve interactivity in time-critical applications [S1, unofficial]. It solves the problem of limited hardware resources in volume rendering by decomposing the scene into two rendering passes with distinct parameters, rather than attempting seamless integration [S1, unofficial]. It sets itself apart from sibling methods like [Level-of-detail (LOD) methods](1007-level-of-detail-lod-methods.md) by using a fixed spatial decomposition (lens) rather than geometric simplification, and from [Dynamic Volume Resolution & Alpha Mask Update](2539-dynamic-volume-resolution-alpha-mask-update.md) by relying on viewport scaling and sampling rate changes rather than data subsampling or alpha masking.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset, a transfer function, a camera view, and a focus region definition (typically a probe or sub-volume).
*   **Output:** A composite image where the focus region is rendered at high fidelity and the context region is rendered at reduced fidelity.

**Data Structures and Layout:**
The method utilizes two distinct rendering configurations for the same or different datasets. The specific parameters used in the source evaluation are defined in Table 1 [S1, unofficial]:

| Parameter | Focus Configuration | Context Configuration |
| :--- | :--- | :--- |
| **Volume Size** | $4 \times 256^3$ | $1 \times 128^3$ |
| **Lookup Table Size** | $5 \times 256^2$ | $4 \times 128^2$ |
| **Rendering Model** | Local lighting | Unshaded |
| **Sampling Rate** | 4 | 1 |
| **Viewport Size** | 100% | 50% |

**Steps:**
1.  **Decomposition:** Divide the rendering task into a Focus pass and a Context pass. The Focus region is defined by the user (e.g., a data probe) and is placed closest to the user [S1, unofficial].
2.  **Context Rendering:** Render the context volume into a smaller viewport (e.g., 50% of the screen width/height) using a simpler rendering model (unshaded) and lower sampling rate [S1, unofficial].
3.  **Filtering:** Apply a Gaussian filter to the resulting context image to reduce aliasing artifacts introduced by the lower resolution and sampling rate [S1, unofficial].
4.  **Scaling:** Enlarge the filtered context image to fill its designated portion of the final framebuffer.
5.  **Focus Rendering:** Render the focus volume into the remaining viewport area (or full screen if context is transparent/overlay) using high-quality settings (local lighting, higher sampling rate) [S1, unofficial].
6.  **Compositing:** Composite the focus and context images. If the context is transparent, it serves as an orientation aid; if opaque, it provides an external view [S1, unofficial].

**Pseudocode:**
```python
def render_focus_and_context(volume_data, focus_region, camera, viewport_width, viewport_height):
    # Define context parameters based on source [S1, unofficial]
    context_volume_scale = 0.5  # 128^3 vs 256^3
    context_viewport_scale = 0.5 # 50% viewport
    
    # Calculate context viewport dimensions
    ctx_w = int(viewport_width * context_viewport_scale)
    ctx_h = int(viewport_height * context_viewport_scale)
    
    # Step 2: Render Context into smaller viewport
    # Uses unshaded model, sampling rate 1, smaller LUT
    context_image = render_volume(
        volume=volume_data,
        scale=context_volume_scale,
        viewport_size=(ctx_w, ctx_h),
        sampling_rate=1,
        shading_model="unshaded",
        camera=camera
    )
    
    # Step 3: Apply Gaussian filter to reduce aliasing
    context_image = gaussian_filter(context_image, sigma=1.0)
    
    # Step 4: Scale up context image
    context_image_scaled = resize(context_image, (viewport_width, viewport_height), interpolation="linear")
    
    # Step 5: Render Focus
    # Uses local lighting, sampling rate 4, full resolution LUT
    focus_image = render_volume(
        volume=volume_data,
        scale=1.0,
        viewport_size=(viewport_width, viewport_height),
        sampling_rate=4,
        shading_model="local_lighting",
        camera=camera,
        clip_region=focus_region # Render only focus region or overlay
    )
    
    # Step 6: Composite
    # Note: Source does not specify exact blending equation, 
    # but implies context is background/orientation.
    # [G] Assuming standard alpha compositing or simple overlay if context is transparent.
    final_image = composite(focus_image, context_image_scaled)
    
    return final_image
```

**Parameters and Edge Cases:**
*   **Context Mode:** Can be transparent (for orientation) or opaque (for external view) [S1, unofficial].
*   **Sampling:** Context sampling can be sparse if the transfer function contains only low-frequency components [S1, unofficial].
*   **Pitfalls:** Overhead comes from rendering slices multiple times and setting up clip textures/depth buffers for each pass [S1, unofficial]. The goal is not seamless integration, so visible seams or quality drops in the context are acceptable trade-offs for speed [S1, unofficial].

## Operating characteristics
*   **Performance:** Achieves 2-6 times faster rendering rates than single high-resolution mode by reducing focus fragments aggressively [S1, unofficial].
*   **Measured Performance:** Tested on a 2.0GHz Pentium 4, 2GB memory, ATI Radeon 9800 Pro [S1, unofficial].
    *   **512x512 Viewport:**
        *   100% Focus Size: 3.39 FPS
        *   50% Volume Size: 4.22 FPS
        *   25% Volume Size: 7.55 FPS
        *   12.5% Volume Size: 12.99 FPS
        *   6.25% Volume Size: 20.87 FPS
    *   **1024x1024 Viewport:**
        *   100% Focus Size: 1.06 FPS
        *   50% Volume Size: 1.28 FPS
        *   25% Volume Size: 2.31 FPS
        *   12.5% Volume Size: 3.97 FPS
        *   6.25% Volume Size: 6.33 FPS
*   **Scaling:** Performance gains increase as the focus size (volume percentage) decreases. The speedup is empirical and depends on the rendering parameters used, not the transfer function [S1, unofficial].
*   **Strengths:** Simple, generic approach; effective for time-critical applications; reduces clutter in multidimensional exploration.
*   **Limitations:** Not seamless; overhead from multiple rendering passes; performance variability on ATI cards depending on slicing direction (mitigated by using fixed viewpoints in tests) [S1, unofficial].

## Background
This technique was presented in the unpublished work "A Focus and Context Interface for Interactive Volume Rendering" by I. Kits et al. [S1, unofficial]. It was developed to address the limitations of hardware-accelerated volume rendering where processing capacity is limited. The method builds on the principle that performance depends on fragment count, work per fragment, and cache utilization [S1, unofficial]. It is used in interactive visualization tools where users need to explore large datasets with a specific area of interest (focus) while maintaining spatial awareness (context).
