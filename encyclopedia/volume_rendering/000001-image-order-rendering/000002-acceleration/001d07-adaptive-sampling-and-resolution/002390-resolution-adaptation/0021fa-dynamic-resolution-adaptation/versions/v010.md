# Dynamic Resolution Adaptation

Also called: ComputeReductionFactor, Frame Rate Maintenance via Resolution Adjustment

## Overview
Dynamic Resolution Adaptation is a runtime adjustment system that tracks rendering performance and adjusts the distribution of resolution levels on the fly to maintain a consistently high update rate above a set threshold [S1, unofficial]. It solves the problem of performance instability in volume rendering, where small parametric changes (e.g., transfer function modifications) can cause frame rate dips leading to cybersickness [S1, unofficial]. It sets itself apart from static resolution schemes by continuously shifting the "anchor points" between resolution levels based on the gradient of recent frame times, rather than using fixed blending factors [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Previous frame render time ($t_{actual}$), allocated time budget for the next frame ($t_{target}$), and current viewport reduction factor ($R_{old}$).
*   **Output:** New viewport reduction factor ($R_{new}$).

**Data Structures:**
*   $R$: A scalar floating-point value representing the viewport reduction factor, constrained to the range $(0.0, 1.0]$.
*   $t_{target}$: A double-precision floating-point value representing the time budget in seconds.
*   $t_{actual}$: A double-precision floating-point value representing the time taken to draw the previous frame.

**Steps:**
1.  **Validate State:** Ensure $R_{old} > 0.0$ and $R_{old} \le 1.0$, and that $t_{actual} \ge 0.0$. If these conditions are not met, the adaptation cannot proceed safely [S1, unofficial].
2.  **Compute Adjustment:** Calculate the new reduction factor $R_{new}$ based on the difference between the target time and actual time. The specific proportional formula is not explicitly detailed in the source, but the goal is to ensure $R_{new}$ stays within the valid range $(0.0, 1.0]$ [S1, unofficial].
3.  **Clamp:** Apply clamping to $R_{new}$ to ensure it remains within $(0.0, 1.0]$.

## Subtopics

### Time-critical level-of-detail selection
An algorithm that performs automatic level-of-detail selection to match different parameters like the desired frame rate by predicting rendering time and dynamically selecting the level-of-detail for the next frame. It sets itself apart by using performance statistics to predict time rather than just reacting to the current frame's duration. It is chosen when the system needs to proactively adjust complexity to meet a target frame rate. Link: [Time-critical level-of-detail selection](8221-dynamic-frame-rate-adaptation.md) (Note: The source links this concept to the broader dynamic adaptation family).

## Operating characteristics
*   **Time Complexity:** The adaptation logic itself is $O(1)$ as it involves simple arithmetic operations on scalar values. The rendering cost varies based on the chosen resolution factor.
*   **Memory Complexity:** $O(1)$ for the adaptation state (current reduction factor, timing stats).
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with the frame time budget; tighter budgets require more aggressive resolution reduction.
*   **Strengths:** Maintains consistent frame rates, preventing cybersickness in interactive volume rendering [S1, unofficial].
*   **Limitations:** Requires accurate timing measurements; may cause visible resolution fluctuations if the control loop is not tuned properly.
*   **When to use:** Interactive volume rendering where frame rate stability is critical.
*   **When not:** When visual fidelity is strictly prioritized over frame rate, or in offline batch rendering.
