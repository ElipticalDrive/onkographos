# Dynamic Frame Rate Adaptation

Also called: Automatic resolution adoption, Dynamic resolution distribution

## Overview
Dynamic Frame Rate Adaptation is a runtime adjustment system that tracks rendering performance and adjusts the distribution of resolution levels on the fly to maintain a consistently high update rate above a set threshold [S1]. It solves the problem of performance instability in volume rendering, where small parametric changes (e.g., transfer function modifications) can cause frame rate dips leading to cybersickness [S1]. It sets itself apart from static resolution schemes by continuously shifting the "anchor points" between resolution levels based on the gradient of recent frame times, rather than using fixed blending factors [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A sliding window of rendering times for the last $n$ frames; current frame rendering time; lower and upper refresh rate thresholds; the current Multi-Anchor Blending (MAB) configuration [S1].
*   **Output:** Updated blending factors (resolution level distribution) for the next frame [S1].

**Data Structures:**
*   **Performance Window:** A circular buffer or array storing the rendering time $t_i$ for the last $n$ frames [S1].
*   **Lookup Texture ($f_a$):** A 1D texture used as a fast lookup function to determine the corresponding resolution level of a texel and whether it has to be traversed by the raycaster [S1].
    *   **Layout:** The texture width corresponds to the domain of the blending function [S1].
    *   **Channels:** The four color channels (RGBA) store the blending factors for the corresponding resolution levels of the MAB [S1].
    *   **Content:** Each channel value represents the weight of a specific resolution level, with a smooth-step function applied between adjacent resolution levels to ensure unnoticeable blending [S1].

**Parameters:**
*   $n$: Size of the sliding window (number of past frames) [S1].
*   $T_{low}$: Lower threshold for minimum acceptable refresh rate (e.g., 90 Hz) [S1].
*   $T_{high}$: Upper threshold for sufficiently high refresh rate [S1].

**Steps:**
1.  **Track Performance:** Maintain a sliding window of the last $n$ frame rendering times [S1].
2.  **Compare Thresholds:** Compare the previous frame's rendering time against the lower threshold $T_{low}$ and upper threshold $T_{high}$ [S1].
    *   If the frame rate is below $T_{low}$ (performance is poor), shift the resolution distribution to emit fewer rays [S1].
    *   If the frame rate is above $T_{high}$ (performance is good), increase the number of rays [S1].
3.  **Compute Gradient:** Calculate the gradient of the rendering time window to determine the direction and magnitude of the adjustment [S1].
4.  **Select Anchor Point:** Evaluate the change in rendering time over the last $n$ frames to determine which anchor point between two adjacent resolution levels should be moved [S1].
5.  **Determine Shift Magnitude:** Calculate how far the selected anchor point should be shifted in the corresponding direction [S1].
6.  **Update Lookup Texture:** Modify the $f_a$ 1D texture by adjusting the values in the RGBA channels to reflect the new blending factors for each resolution level [S1].
7.  **Raycasting:** During the raycast, use the updated $f_a$ texture to look up the corresponding resolution level for each texel and determine if it needs to be traversed [S1].

**Pseudocode:**
```python
def update_resolution_distribution(window, current_time, t_low_hz, t_high_hz, n, num_levels, fa_texture):
    # Convert Hz thresholds to seconds for time comparison
    t_low_sec = 1.0 / t_low_hz
    t_high_sec = 1.0 / t_high_hz
    
    # 1. Track Performance: Append current time, maintain window size n
    window.append(current_time)
    if len(window) > n:
        window.pop(0)
        
    # 2. Compare Thresholds: Compare previous frame time against thresholds
    prev_time = window[-1]
    if prev_time > t_low_sec:
        direction = -1  # Performance below threshold: shift to fewer rays
    elif prev_time < t_high_sec:
        direction = 1   # Performance above threshold: increase rays
    else:
        direction = 0   # Within range: no shift
        
    # 3. Compute Gradient: Evaluate change in rendering time over the last n-frames
    time_change = window[-1] - window[0]
    gradient = time_change / max(n - 1, 1)
    
    # 4 & 5. Select Anchor Point & Determine Shift Magnitude
    # Map gradient magnitude and direction to an anchor index and shift amount
    anchor_idx = max(0, min(num_levels - 2, int(direction * abs(gradient) * 10)))
    shift_magnitude = min(0.1, abs(gradient) * 0.5)
    
    # 6. Update Lookup Texture: Modify the fa 1D texture
    new_fa = update_fa_texture(fa_texture, anchor_idx, shift_magnitude, direction)
    
    return new_fa

def update_fa_texture(fa_texture, anchor_idx, shift_magnitude, direction):
    # Adjust blending factors around the selected anchor point
    new_texture = fa_texture.copy()
    if direction != 0:
        # Shift anchor point towards lower resolution (direction=-1) or higher (direction=1)
        for i in range(len(new_texture)):
            if i == anchor_idx:
                new_texture[i] += shift_magnitude * direction
            elif i == anchor_idx + 1:
                new_texture[i] -= shift_magnitude * direction
        # Clamp values to valid blending range
        new_texture = [max(0.0, min(1.0, v)) for v in new_texture]
    return new_texture
```

**Edge Cases and Pitfalls:**
*   **Minor Variations:** Small performance fluctuations primarily adjust higher resolution levels, causing only slight alterations to the overall distribution [S1].
*   **High Deviations:** Large performance deviations primarily shift lower resolutions to compensate for rendering performance [S1].
*   **Precision:** The smooth-step function between adjacent resolution levels is critical for unnoticeable blending; discontinuities here may cause visual artifacts [S1].

## Operating characteristics
*   **Time Complexity:** The adjustment logic involves a sliding window update and a lookup texture modification, which is $O(1)$ per frame relative to the scene complexity, though dependent on $n$ for gradient calculation [S1]. The raycasting cost is reduced by shifting to lower resolutions when performance is poor [S1].
*   **Memory Complexity:** Requires storage for the performance window ($O(n)$) and the $f_a$ lookup texture (constant size, typically small 1D texture) [S1].
*   **Measured Performance:** On an RTX 2070, the baseline system maintained average refresh rates above 90 Hz for MRI and CT datasets [S1]. With dynamic adaptation, the system maintained rates above 90 Hz on both RTX 2070 and RTX 2060m hardware, whereas the baseline failed on the RTX 2060m for one dataset [S1]. The 1% lowest frame rates also improved (e.g., MRI dataset on RTX 2060m: 62.6 Hz baseline vs 91.2 Hz dynamic) [S1].
*   **Strengths:** Guarantees refresh rates above a set threshold, reducing cybersickness [S1]. Adapts to runtime parametric changes (e.g., transfer function updates) [S1].
*   **Limitations:** Relies on accurate tracking of frame times [S1]. The specific mapping of gradient to anchor shift requires tuning [S1].

## Background
The method originates from research on embracing raycasting for virtual reality, specifically addressing the need for consistent high update rates to prevent cybersickness [S1]. It builds on the Multi-Anchor Blending (MAB) technique, using a 1D lookup texture ($f_a$) similar to transfer functions in direct volume rendering to manage resolution level blending [S1]. The system was tested on MRI and CT datasets using RTX 2070 and RTX 2060m hardware [S1].
