# Frustum-based LOD Selection

Also called: Auto Level of Detail (LOD), Distance-based LOD, Frustum Face Distance LOD, Multi-resolution volumes (LOD), Simple LOD

## Overview
Frustum-based LOD Selection determines the appropriate level of detail (LOD) depth for a volumetric entity by calculating the distance from the camera to the entity's frustum faces, ensuring that the projected voxel size remains smaller than a screen pixel [S1, unofficial]. Unlike [View-Dependent Adaptive Refinement](6952-view-dependent-adaptive-refinement.md), which refines resolution based on local scalar variance or error metrics, this method relies on global geometric distance to the camera frustum to select a coarser resolution for distant or peripheral rays, thereby minimizing sample counts [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera world-space position, camera view/projection matrices (or inverse MVP), entity world-space position and scale, array of depth thresholds, screen width.
*   **Outputs:** Selected LOD integer level.

**Data Structures:**
*   `depthTresholds_`: An array of floats where each element corresponds to a LOD depth. The value is calculated as $1.0f / 2^{depth}$ for depths $1$ to `maxSvoDepth_` [S1, unofficial].
*   `camera_position`: World-space position of the camera [S3, unofficial].
*   `transformComponent`: Contains the entity's world-space position and scale [S1, unofficial].

**Steps:**
1.  **Calculate Camera-to-Entity Distance:** Compute the Euclidean distance between the camera position and the entity's transformed position [S1, unofficial].
    $$ d_{cam} = \| \text{camera\_position} - \text{entity\_position} \| $$
2.  **Determine Frustum Face Positions:** To account for the angular spread of the frustum, calculate the positions of the left and right frustum faces at the depth of the entity.
    *   Define Normalized Device Coordinate (NDC) points representing the left and right edges of the view volume, e.g., $A = (-1, 0, 0, 1)$ and $B = (1, 0, 0, 1)$ [S1, unofficial].
    *   Transform these NDC points to view space using the inverse Model-View-Projection matrix ($MVP^{-1}$) [S1, unofficial]:
        $$ V_A = MVP^{-1} \cdot A, \quad V_B = MVP^{-1} \cdot B $$
    *   Scale these vectors by the camera-to-entity distance $d_{cam}$ and add the camera position to find the world-space positions of the frustum faces at that depth [S1, unofficial]:
        $$ P_{left} = \text{camera\_position} + V_A \cdot d_{cam} $$
        $$ P_{right} = \text{camera\_position} + V_B \cdot d_{cam} $$
3.  **Calculate Normalized Frustum Width:** Compute the distance between the left and right frustum face positions and normalize it by the screen width $W$ [S1, unofficial]:
    $$ D_{norm} = \frac{\| P_{left} - P_{right} \|}{W} $$
    *Note: Some implementations may use the direct camera-to-entity distance $d_{cam}$ for threshold comparison if the frustum width normalization is handled implicitly by the threshold array scaling [S1, unofficial].*
4.  **Select LOD Level:** Iterate through the `depthTresholds_` array to find the first threshold that the calculated distance exceeds.
    *   For each index $i$ from $0$ to `depthTresholds_.size() - 1`:
        *   Let $depth = i + 1$.
        *   Let $T_i$ be `depthTresholds_[i]`.
        *   If $d_{cam} > T_i \times \text{entity\_scale}$, then set $LOD = depth$ and break [S1, unofficial].
    *   If no threshold is exceeded, the finest LOD (e.g., 1) is used.

**Pseudocode:**
```python
def select_frustum_lod(camera_pos, entity_pos, entity_scale, depth_thresholds, screen_width, inverse_mvp):
    """
    Selects LOD based on distance to frustum faces.
    
    Args:
        camera_pos: vec3, world position of camera
        entity_pos: vec3, world position of entity
        entity_scale: float, scale of the entity
        depth_thresholds: list of float, precomputed thresholds [1/2^1, 1/2^2, ...]
        screen_width: float, width of the screen in pixels
        inverse_mvp: mat4, inverse model-view-projection matrix
        
    Returns:
        int: Selected LOD level (1-based index)
    """
    # Step 1: Calculate camera-to-entity distance
    camera_to_entity_dist = glm_distance(camera_pos, entity_pos)
    
    # Step 2: Determine Frustum Face Positions
    # Define NDC points for left and right edges
    point_a_ndc = vec4(-1.0, 0.0, 0.0, 1.0)
    point_b_ndc = vec4(1.0, 0.0, 0.0, 1.0)
    
    # Transform NDC points to view space (assuming inverse_mvp handles projection to view/world)
    # Note: Inverse MVP typically goes from Clip to World. If inverse_mvp is View-World inverse, adjust accordingly.
    # Based on source [S1, unofficial], it transforms NDC to view space relative to camera.
    view_vec_a = inverse_mvp * point_a_ndc
    view_vec_b = inverse_mvp * point_b_ndc
    
    # Calculate left and right frustum face positions at the entity's depth
    # The source adds the vector scaled by distance to the camera position
    left_frustum_face_pos = camera_pos + (view_vec_a.xyz * camera_to_entity_dist)
    right_frustum_face_pos = camera_pos + (view_vec_b.xyz * camera_to_entity_dist)
    
    # Step 3: Calculate normalized distance (optional depending on threshold definition)
    # Source [S1, unofficial] calculates distance between faces normalized by screen width.
    # However, Step 4 in source [S1, unofficial] compares camera_to_entity_dist against thresholds.
    # We follow the explicit threshold check logic from source [S1, unofficial].
    
    # Step 4: Iterate through depth thresholds
    for i in range(len(depth_thresholds)):
        depth = i + 1
        threshold = depth_thresholds[i]
        
        # Check if distance exceeds threshold scaled by entity scale
        if camera_to_entity_dist > threshold * entity_scale:
            return depth
            
    # Default to finest LOD if no threshold exceeded
    return 1

def glm_distance(v1, v2):
    return sqrt((v1.x - v2.x)**2 + (v1.y - v2.y)**2 + (v1.z - v2.z)**2)
```

**Parameters:**
*   `depthTresholds_`: Array of floats. Typical values are $1.0/2^d$ for $d \in [1, \text{max\_depth}]$ [S1, unofficial].
*   `lod`: Integer uniform variable controlling the active LOD state in the shader [S3, unofficial].
*   `camera_position`: World-space position of the camera [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors in matrix inversion or distance calculation can cause jittering at threshold boundaries. [G] Clamping the distance or using a small epsilon when comparing against thresholds can mitigate this.
*   **Boundaries:** If the entity is partially outside the frustum, the distance calculation to the "frustum faces" might need to account for the closest visible face rather than the center. The provided method assumes the entity is within the frustum or uses the center distance as an approximation [S1, unofficial].
*   **Degenerate Input:** If `screen_width` is zero, the normalized distance calculation fails. [G] Ensure screen width is at least 1.

## Subtopics

### [Footprint-based LOD Selection](3088-footprint-based-lod-selection.md)
Determines LOD by ensuring the projected voxel size does not exceed a pixel threshold, using the actual projected footprint rather than just distance to frustum faces.

### [Pixel-Sized Clipmap LOD for Voxels](6934-pixel-sized-clipmap-lod-for-voxels.md)
Retains full-resolution voxels only within a radius defined by the camera's pixel footprint, using concentric clipmap rings.

## Operating characteristics
*   **Time Complexity:** $O(1)$ for LOD selection per entity, as it involves a fixed number of vector operations and a loop over a small, fixed number of LOD levels (typically < 10) [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the multi-resolution volume data (MIP-map pyramid), where $N$ is the number of voxels in the finest resolution [S2].
*   **Performance:** Significantly reduces memory bandwidth and sample counts for large-scale datasets by skipping distant regions [S2].
*   **Strengths:** Simple to implement, deterministic, and effective for large volumes where distant details are less perceptible [S2].
*   **Limitations:** Does not account for local detail density or scalar variance; may over-refine or under-refine in regions with high-frequency content far from the camera but within the frustum [S2].
*   **When to use:** Large-scale volumetric datasets (e.g., geophysical simulations) where performance is critical and visual quality degradation at distance is acceptable [S2].
*   **When not to use:** Scenes requiring high-fidelity detail throughout the volume or where scalar variance is a better indicator of needed resolution [S2].

## Background
Frustum-based LOD selection is a technique used in volume ray casting to optimize rendering performance by adapting resolution based on ray distance from the viewer [S2]. It is commonly used in conjunction with hierarchical representations such as octree-based voxel MIP-map pyramids [S2]. The method is particularly suited for large-scale datasets like geophysical simulations, where it cuts memory and sample requirements significantly while maintaining perceptual quality [S2]. The specific implementation details involving frustum face distance calculations are found in unofficial source code repositories [S1, unofficial].
