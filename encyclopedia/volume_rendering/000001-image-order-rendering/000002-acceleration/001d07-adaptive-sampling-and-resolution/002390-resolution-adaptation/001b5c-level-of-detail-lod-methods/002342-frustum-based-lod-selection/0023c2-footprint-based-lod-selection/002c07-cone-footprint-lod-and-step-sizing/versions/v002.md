# Cone-Footprint LOD and Step Sizing

Also called: cone LOD, cone-footprint LOD

## Overview
Cone-Footprint LOD replaces fixed step counts with sample density proportional to the screen-space footprint of a voxel rather than camera distance, effectively reducing stationary shimmer and aliasing [S1, unofficial]. It sets itself apart from distance-based LOD methods by dynamically matching the sampling rate to the projected pixel area at the current march distance [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** Ray origin $O$, ray direction $D$, entry distance $t_{min}$, exit distance $t_{max}$, voxel size in world units $V_{world}$, pyramid mip levels $L=0 \dots N$, and tuning parameters $STEP\_QUALITY$ and $SKIP\_CHECK\_STRIDE$ [S1, unofficial].
*   **Outputs:** A sequence of sample positions and values along the ray, terminated when $t \ge t_{max}$ or a skip condition is met [S1, unofficial].

**Data Structures**
*   **Pyramid Mips:** A hierarchy of voxel grids where level $l$ has texel size $V_{world} \cdot 2^l$ [S1, unofficial].
*   **Ray State:** Current distance $t$, current LOD level $lod$, and iteration counter $i$ [S1, unofficial].

**Parameters**
*   $STEP\_QUALITY = 2.0$: Multiplier for the base step size to ensure sufficient oversampling [S1, unofficial].
*   $SKIP\_CHECK\_STRIDE = 4$: Frequency of pyramid skip checks [S1, unofficial].
*   $STEP\_COUNT = 256$: Maximum iteration safety cap, increased from 128 [S1, unofficial].

**Algorithm Steps**
1.  **Initialization:** Set $t = t_{min}$, $i = 0$. Compute initial LOD: $lod = coneLod(t, O, D, V_{world})$, which returns the mip level $l$ such that the texel size at level $l$ approximates the screen-space footprint of a pixel at distance $t$ [S1, unofficial].
2.  **Main Loop:** While $t < t_{max}$ and $i < STEP\_COUNT$:
    a. **Skip Check:** If $i \pmod{SKIP\_CHECK\_STRIDE} == 0$, check if the ray is inside a skip region (e.g., empty space or low-contrast volume) using the pyramid data at the current $lod$ [S1, unofficial]. If the skip condition is met:
       *   Calculate the exit distance of the current skip cell, $t_{skip\_exit}$ [S1, unofficial].
       *   Jump $t$ to $t_{skip\_exit}$ and apply a jitter offset to prevent ray synchronization [S1, unofficial].
       *   Update $lod$ based on the new $t$ [S1, unofficial].
       *   Increment $i$ and continue to the next iteration without sampling [S1, unofficial].
    b. **Step Sizing:** Compute the base step length from the current LOD: $lod\_step = V_{world} \cdot 2^{lod} \cdot STEP\_QUALITY$ [S1, unofficial]. Compute the safety floor to prevent truncation at large tiers: $floor\_step = \frac{t_{max} - t}{STEP\_COUNT - i}$ [S1, unofficial]. Determine the actual step length: $step\_length = \max(lod\_step, floor\_step)$ [S1, unofficial].
    c. **Sampling:** Sample the volume texture at position $P = O + t \cdot D$ using the current $lod$ [S1, unofficial].
    d. **Advance:** $t = t + step\_length$, $i = i + 1$ [S1, unofficial].

**Pseudocode**
```python
def cone_footprint_march(ray_origin, ray_direction, t_min, t_max, voxel_size_local, pyramid, step_quality=2.0, skip_check_stride=4, step_count=256):
    t = t_min
    i = 0
    lod = cone_lod(t, ray_origin, ray_direction, voxel_size_local)
    while t < t_max and i < step_count:
        if i % skip_check_stride == 0:
            if pyramid.is_skip_region(t, lod):
                t_skip_exit = pyramid.cell_exit_t(t, lod)
                t = t_skip_exit + hash(ray_origin, i) * 1e-6
                lod = cone_lod(t, ray_origin, ray_direction, voxel_size_local)
                i += 1
                continue
        lod_step = voxel_size_local * (2 ** lod) * step_quality
        remaining_steps = step_count - i
        floor_step = (t_max - t) / remaining_steps
        step_length = max(lod_step, floor_step)
        sample_position = ray_origin + t * ray_direction
        value = pyramid.sample_lod(sample_position, lod, mipmap_filter='linear')
        t += step_length
        i += 1
    return samples
```

**Edge Cases and Pitfalls**
*   **Truncation:** $STEP\_COUNT=256$ can truncate a ray mid-cube at large tiers because honest LOD-driven steps near the camera are voxel-sized, and 256 of them fall short of a large-tier cube's diagonal [S1, unofficial]. The per-iteration step floor guarantees every ray reaches $t_{max}$ [S1, unofficial].
*   **Banding:** The skip-jump's direct $t = skipExitT + \epsilon$ re-synchronizes every ray that skipped the same pyramid cell onto that cell's exit plane, causing stationary banding [S1, unofficial]. Re-jittering on resume with the ray's own hash, salted by iteration count, breaks this correlation [S1, unofficial].
*   **Mipmap Filtering:** The WebGPU default `mipmapFilter: 'nearest'` causes fractional cone-LOD to snap between mips instead of blending, creating hard detail-shell edges [S1, unofficial]. The sampler must be set to `mipmapFilter: 'linear'` to fix this [S1, unofficial].
*   **Redundant Checks:** Near the camera, LOD-0 steps are voxel-sized, making re-testing membership every step redundant [S1, unofficial]. Throttling the skip check to every 4th iteration ($SKIP\_CHECK\_STRIDE=4$) optimizes performance without quality loss [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of samples, but $N$ is now adaptive [S1, unofficial]. The skip check adds a constant overhead every $SKIP\_CHECK\_STRIDE$ iterations [S1, unofficial].
*   **Memory Complexity:** Depends on the pyramid storage, which is stored in deviation space [S1, unofficial].
*   **Performance:** In paired A/B testing against a baseline with fixed steps, this method recovered most of the performance regression caused by aggressive skipping in previous tasks [S1, unofficial]. For example, in a "volume-inside" scenario, total merged time dropped from 2.2ms (Task 5) to 1.4ms (Task 6) [S1, unofficial].
*   **Strengths:** Eliminates stationary shimmer by aligning sample density with screen content [S1, unofficial]. Adaptive skipping reduces cost in empty regions [S1, unofficial].
*   **Limitations:** Requires a pyramid structure [S1, unofficial]. Tuning parameters ($STEP\_QUALITY$, $SKIP\_CHECK\_STRIDE$) are critical for performance/quality balance [S1, unofficial]. $STEP\_QUALITY=1.0$ was found to increase cost by 68% with no visible quality gain compared to 2.0 [S1, unofficial].
