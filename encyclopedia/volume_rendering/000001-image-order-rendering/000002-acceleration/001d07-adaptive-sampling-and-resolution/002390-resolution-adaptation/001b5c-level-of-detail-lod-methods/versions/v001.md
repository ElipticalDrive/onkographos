# Level-of-detail (LOD) methods

Also called: Adaptive resolution rendering, Dynamic LOD, Dynamic Level-of-Detail (LOD) Framework, Sample-Based LOD

## Overview
Level-of-detail (LOD) methods are techniques that change the resolution of the rendering during viewpoint interaction to maintain responsive frame rates [S2, book]. They solve the problem of interactive visualization for large scalar fields by generating reduced-resolution approximations of the original field [S1, unofficial]. What sets them apart from static resolution methods is the dynamic adaptation of discretization based on performance metrics or view complexity, building on the feedback loop principles of [Resolution Adaptation](3063-resolution-adaptation.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Original scalar field $f$ defined on domain $D$ (e.g., tetrahedral mesh or voxel grid), current render time, target frame time.
*   **Output:** Reduced-resolution approximation $\bar{f}$ defined on domain $\bar{D} \subseteq D$, where $|\bar{f} - f| \leq \epsilon$.

**Data Structures:**
*   **Mesh/Domain Representation:** For unstructured grids, the domain $D$ is represented by a set of faces $F$ and internal faces $I$. The approximation uses a subset $B \cup I \subseteq F$, where $B$ is the boundary and $I$ is the selected internal faces [S1, unofficial].
*   **Hierarchical Structures:** Octrees or similar hierarchical representations can be used to store data at multiple resolutions, allowing easy traversal for higher or lower resolutions [S2, book].

**Steps:**
1.  **Metric Evaluation:** Monitor the render time of the previous frame.
2.  **LOD Selection:** Calculate the number of elements (faces, samples, or slices) to include in the current frame based on the ratio of target time to actual render time.
3.  **Approximation Generation:**
    *   *Sample-Based:* Use the original geometry to compute an approximate volume integral. This involves selecting a subset of samples or faces [S1, unofficial].
    *   *Domain-Based:* Approximate the domain geometry first, then compute an exact integral over the approximate geometry [S1, unofficial].
    *   *Ray-Casting:* Use larger step sizes or fewer rays [S2, book].
    *   *Texture Slicing:* Use fewer slices through the data (e.g., every fourth slice) [S2, book].
4.  **Rendering:** Render the approximation $\bar{f}$.
5.  **Feedback:** Update the LOD for the next frame based on the new render time.

**Formulas:**
The number of internal faces $|I|$ to select for a given LOD pass is calculated as [S1, unofficial]:

$$|I| = \frac{|I| \times \text{TargetTime}}{\text{RenderTime}}$$

Where:
*   $|I|$: Number of internal faces selected.
*   $\text{TargetTime}$: Desired frame time (e.g., 0.01 seconds).
*   $\text{RenderTime}$: Time required to render the previous frame.

**Parameters:**
*   **TargetTime:** The amount of time desired for each frame for interactive viewing. Typical value: 0.01 seconds [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Visual Error:** Sample-based simplification provides different, though not necessarily better, results than domain-based simplification [S1, unofficial].
*   **Smoothness:** To maximize visual smoothness when the viewpoint or transfer function changes, face selection should be based only on mesh geometry and scalar values, rather than transfer function and viewpoint [S1, unofficial].
*   **Boundary Conditions:** When simplifying, the boundary $B$ should remain constant to ensure a good approximation of $f$ [S1, unofficial].

**Pseudocode:**
```python
def render_lod_frame(original_mesh, target_time=0.01):
    """
    Renders a frame using LOD methods.
    
    Args:
        original_mesh: The full-resolution mesh or volume data.
        target_time: Desired frame time in seconds.
        
    Returns:
        Rendered image and new render time.
    """
    # Get previous frame's render time (from feedback loop)
    # If first frame, use a default or estimated time
    if not hasattr(render_lod_frame, 'prev_render_time'):
        render_lod_frame.prev_render_time = target_time
    
    prev_render_time = render_lod_frame.prev_render_time
    
    # Calculate number of internal faces to include
    # |I| = (|I| * TargetTime) / RenderTime
    # Note: This formula assumes |I| on RHS is the total available internal faces
    # and |I| on LHS is the subset to select.
    total_internal_faces = original_mesh.get_total_internal_faces()
    selected_faces_count = (total_internal_faces * target_time) / prev_render_time
    
    # Clamp to valid range
    selected_faces_count = max(0, min(selected_faces_count, total_internal_faces))
    
    # Select faces based on error criterion or geometry
    # To maximize smoothness, base selection on mesh geometry and scalar values
    selected_faces = original_mesh.select_faces_by_geometry_and_scalar(selected_faces_count)
    
    # Construct approximation mesh
    boundary_faces = original_mesh.get_boundary_faces()
    approximation_mesh = Mesh(faces=boundary_faces + selected_faces)
    
    # Render the approximation
    # For ray-casting: use larger step sizes or fewer rays
    # For texture slicing: use fewer slices
    image = render_volume(approximation_mesh)
    
    # Measure actual render time
    current_render_time = measure_render_time()
    
    # Update feedback state
    render_lod_frame.prev_render_time = current_render_time
    
    return image, current_render_time
```

## Subtopics

### [Frustum-based LOD Selection](2986-frustum-based-lod-selection.md)
A technique to determine the appropriate LOD depth for an entity based on the distance from the camera to the frustum faces, ensuring voxel sizes are smaller than a pixel.

## Operating characteristics
*   **Time Complexity:** Depends on the number of selected faces/samples. The selection process is $O(1)$ if using the feedback formula, but the rendering is proportional to the selected LOD level.
*   **Memory Complexity:** Can be $O(N)$ if storing all LOD levels, or $O(1)$ if recomputing selection dynamically from the full mesh [S1, unofficial].
*   **Performance:** Improves interactivity substantially, especially on GPUs [S2, book].
*   **Strengths:** Maintains responsive frame rates during viewpoint interaction [S2, book]. Simple data structures for dynamic LOD [S1, unofficial].
*   **Limitations:** Visual artifacts may occur if LOD changes are too abrupt. Sample-based methods may not always provide better results than domain-based methods [S1, unofficial].
*   **When to use:** Interactive visualization of large scalar fields where frame rate is critical [S1, unofficial].
*   **When not to use:** When visual fidelity is more important than interactivity, or when the scene complexity does not vary significantly with viewpoint.

## Background
LOD techniques were proposed for interactive visualization of large scalar fields represented as tetrahedral meshes [S1, unofficial]. They work similarly to triangle-based simplification and use connectivity information to incrementally cull simplices [S1, unofficial]. The concept of using coarser sampling for ray-casting was established by Levoy [S2, book]. Hierarchical representations like octrees were proposed by Danskin and Hanrahan [S2, book]. Advances in GPU hardware have further improved the efficiency of LOD methods [S2, book].
