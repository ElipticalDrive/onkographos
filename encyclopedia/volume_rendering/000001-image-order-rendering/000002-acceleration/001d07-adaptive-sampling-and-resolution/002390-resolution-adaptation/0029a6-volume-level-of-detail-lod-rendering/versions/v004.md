# Volume Level-of-Detail (LOD) Rendering

Also called: Active Cut Rendering, Adaptive LOD Rendering

## Overview
Volume Level-of-Detail (LOD) Rendering is a method that maximizes image quality within user-specified frame rate and system constraints (RAM, texture memory, bandwidth) by adaptively modifying the set of rendered octree cells [S1]. It solves the problem of maintaining interactivity for large datasets by dynamically adjusting the resolution of the volume representation based on viewing parameters and hardware limits [S1]. Unlike static LOD methods that precompute fixed levels, this approach maintains an "active cut" of the octree, splitting or merging nodes every frame to balance visual fidelity against rendering cost [S1]. It differs from sibling methods like [Dynamic Volume Resolution & Alpha Mask Update](2539-dynamic-volume-resolution-alpha-mask-update.md) by explicitly managing a hierarchical cut of non-leaf nodes rather than just updating alpha masks or global resolution scales [S1, S2].

## How it works
The method operates in two primary phases: Adapt/Load and Cull/Render. It assumes the volume data is organized in an adaptive octree where leaf nodes contain voxelized cells [S1].

### Inputs and Outputs
*   **Inputs:**
    *   Octree structure with voxelized cells [S1].
    *   User parameters: Desired frame rate, transfer function (data to RGBA), view position [S1].
    *   System parameters: RAM size, texture memory size, bandwidths, polygon/fill performance [S1].
*   **Outputs:**
    *   A set of flagged octree nodes rendered to the screen [S1].
    *   Updated active cut for the next frame [S1].

### Data Structures
1.  **Active Cut:** A set of octree nodes whose cells cover the model space exactly once [S1].
2.  **Split Queue:** Contains non-leaf nodes currently on the active cut, sorted by decreasing error [S1].
3.  **Merge Queue:** Contains nodes that are inactive (merged) but can be split if error increases [S1].
4.  **Node State:** Each node has a boolean flag `active` (true if on active cut, false if merged) [S1].

### Algorithm Steps

1.  **Initialize Active Cut:**
    *   Start with the root node as active.
    *   Maintain the invariant that the active cut covers the volume space exactly once [S1].

2.  **Adapt Phase (Error Adjustment):**
    *   Compute a local error metric $E_i$ for each non-leaf node $i$ in the split queue. The metric represents the visual difference between the node and its children [S1].
    *   **To Decrease Error (Increase Quality):**
        1.  Select the node $N$ with the highest error from the Split Queue [S1].
        2.  Move $N$ to the Merge Queue and mark it `inactive` [S1].
        3.  Add $N$'s children to the Split Queue and mark them `active` [S1].
        4.  **Border Continuity Fix:** If children are at different levels or have different resolutions, copy border data from the parent to children to fix internal border discontinuities [S1].
    *   **To Increase Error (Increase Frame Rate):**
        1.  Select the node $M$ from the Merge Queue [S1].
        2.  Move $M$ to the Split Queue and mark it `active` [S1].
        3.  Add $M$'s parent to the Merge Queue and mark it `inactive` [S1].
        4.  Remove $M$'s children from the Split Queue and mark them `inactive` [S1].

3.  **Load Phase:**
    *   Traverse the active cut.
    *   For any flagged node whose texture data is not resident in texture memory, load it from RAM or disk [S1].

4.  **Cull/Render Phase:**
    *   Traverse the octree from the root [S1].
    *   Perform hierarchical culling based on the view frustum and occlusion [S1].
    *   Render flagged (active) nodes using 3D texture mapping and blending in back-to-front order [S1].

### Pseudocode

```python
def volume_lod_render(octree, user_params, system_params):
    # user_params: {desired_frame_rate, transfer_function, view_position}
    # system_params: {ram_size, tex_mem_size, bandwidth}
    
    # 1. Adapt Phase
    # Calculate error for all non-leaf nodes in split_queue
    for node in split_queue:
        node.error = compute_error(node, octree)
    
    # Sort split_queue by decreasing error
    split_queue.sort(key=lambda n: n.error, reverse=True)
    
    # Adjust cut based on current frame rate vs desired frame rate
    current_frame_rate = measure_frame_rate()
    
    if current_frame_rate < user_params.desired_frame_rate:
        # Need to increase quality (decrease error)
        # Split the highest error node
        if split_queue:
            node = split_queue.pop(0)
            node.active = False
            merge_queue.append(node)
            
            for child in node.children:
                child.active = True
                split_queue.append(child)
            
            # Fix border discontinuities between cells of different levels
            fix_border_continuity(node, node.children)
            
    elif current_frame_rate > user_params.desired_frame_rate:
        # Need to increase speed (increase error)
        # Merge the lowest error node from merge queue
        if merge_queue:
            node = merge_queue.pop(0)
            node.active = True
            split_queue.append(node)
            
            # Mark children inactive and remove from split queue
            for child in node.children:
                child.active = False
                if child in split_queue:
                    split_queue.remove(child)
            
            # Add parent to merge queue if it exists and is not root
            if node.parent:
                node.parent.active = False
                merge_queue.append(node.parent)
                if node.parent in split_queue:
                    split_queue.remove(node.parent)

    # 2. Load Phase
    for node in active_cut:
        if not node.texture_resident:
            load_texture_from_ram_or_disk(node)

    # 3. Cull/Render Phase
    render_nodes = []
    traverse_octree(octree.root, render_nodes)
    
    # Sort by back-to-front for correct blending
    render_nodes.sort(key=lambda n: distance_to_camera(n))
    
    for node in render_nodes:
        if node.active:
            render_3d_texture(node, user_params.transfer_function)

def fix_border_continuity(parent, children):
    """
    Copies border data from parent to children to ensure
    continuity when merging nodes of different levels.
    """
    for child in children:
        copy_border_data(parent, child)
```

### Parameters and Edge Cases
*   **Error Metric:** The specific formula for error is not given in the sources, but it must reflect visual difference between a node and its children [S1].
*   **Border Discontinuity:** A critical pitfall is visual artifacts at the boundaries of merged/split nodes. The method explicitly fixes this by copying border data from the parent to the children during the split operation [S1].
*   **Active Cut Invariant:** The cut must always cover the space exactly once. Failure to maintain this leads to over-rendering (holes or overlaps) [S1].

## Subtopics

### Octree-Level Adaptive Rendering
A technique that cuts rendering cost by rendering at coarser octree levels (moving up the octree) to match data resolution to image resolution, maintaining interactivity [S2]. It selectively reduces computation and data transfer based on visualization requirements [S2]. It is chosen when rendering large datasets (e.g., tens of millions of elements) where high-resolution rendering is unnecessary for the current view [S2]. It reduces rendering time and data transfer from disk but does not change the effectiveness of 1DIP/2DIP I/O strategies [S2]. In experiments, adaptive rendering (level 6) provided enough high-level information and was generated about 3 times faster than high-resolution rendering (level 11) [S2].

## Operating characteristics
*   **Time Complexity:** The adapt phase requires sorting the split queue by error, which is $O(N \log N)$ where $N$ is the number of nodes in the active cut [S1]. The render phase is proportional to the number of active nodes [S1].
*   **Memory Complexity:** Requires storing the octree structure, texture data for active nodes, and the split/merge queues [S1]. Memory usage is bounded by texture memory size [S1].
*   **Measured Performance:** Adaptive rendering (level 6) was generated about 3 times faster than high-resolution rendering (level 11) [S2].
*   **Strengths:** Maximizes image quality within system constraints; maintains interactivity for large datasets; reduces data transfer from disk [S1, S2].
*   **Limitations:** Requires complex bookkeeping for the active cut and border continuity; performance depends on the accuracy of the error metric [S1].
*   **When to Use:** Interactive visualization of large unstructured grids where frame rate is critical [S1].
*   **When Not to Use:** When static high-fidelity rendering is required without interactivity constraints [S1].

## Background
The method was introduced in the context of interactive visualization of unstructured grids using hierarchical 3D texture mapping [S1]. It builds on the concept of view-dependent continuous level of detail for polygonal models [S1]. The approach was applied to large-scale time-varying volume data, such as earthquake simulations, to enable near-interactive visualization [S2].
