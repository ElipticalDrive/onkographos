# Random Pixel Subsampling

Also called: Pixel Subsampling, Random Pixel Sampling, Random Ray Sampling

## Overview
Random Pixel Subsampling is a training optimization technique that selects a random subset of pixel coordinates from a full image grid for each iteration, rather than processing the entire image [S2, S3, unofficial]. This reduces GPU memory consumption during the backward pass and accelerates training iterations by limiting the number of volume queries [S3, unofficial]. Unlike its siblings, which often use error metrics or spatial hierarchies to guide sampling, this method relies on uniform stochastic selection to maintain a low average computational cost per step [S1, S2, unofficial].

## How it works
**Inputs:**
*   `image_size`: Tuple $(W, H)$ representing width and height of the target image [S2, unofficial].
*   `n_pixels`: Integer specifying the number of pixels to sample per iteration [S2, unofficial].
*   `camera`: Camera object (e.g., `PerspectiveCameras`) required to map pixel coordinates to ray origins and directions [S2, unofficial].

**Outputs:**
*   `selected_pixels`: Tensor of shape `[n_pixels, 2]` containing the $(x, y)$ coordinates of the sampled pixels [S1, unofficial].
*   `rays`: Corresponding ray bundles (origins and directions) for the selected pixels [S3, unofficial].

**Data Structures:**
*   **Pixel Grid:** A tensor of shape `[W*H, 2]` containing all valid pixel coordinates in Normalized Device Coordinates (NDC), typically ranging from $[-1, 1]$ [S1, unofficial].
*   **Index Permutation:** A 1D tensor of shape `[W*H]` containing a random permutation of indices $0$ to $W*H-1$ [S1, unofficial].

**Steps:**
1.  **Generate Full Grid:** Compute the complete set of pixel coordinates for the image resolution. If using NDC, coordinates range from $-1$ to $1$ across both axes [S1, unofficial].
2.  **Flatten and Reshape:** Flatten the 2D grid into a 1D list of coordinates and reshape to `[W*H, 1, 2]` to prepare for indexing [S1, unofficial].
3.  **Random Permutation:** Generate a random permutation of all pixel indices using a function such as `torch.randperm` [S1, unofficial]. This ensures every pixel has an equal probability of selection without replacement within the batch [S2, unofficial].
4.  **Select Subset:** Slice the first `n_pixels` indices from the permutation [S1, unofficial].
5.  **Extract Coordinates:** Gather the coordinates corresponding to the selected indices and reshape to `[n_pixels, 2]` [S1, unofficial].
6.  **Ray Generation:** Use the selected pixel coordinates to compute ray origins and directions via the camera projection model [S3, unofficial].

**Pseudocode:**
```python
import torch

def get_random_pixels_from_image(image_size, n_pixels, camera):
    """
    Selects a random subset of pixel coordinates from a full image grid.
    
    Args:
        image_size: Tuple (W, H)
        n_pixels: Number of pixels to sample
        camera: Camera object with method to generate rays from pixels
        
    Returns:
        rays: RayBundle containing origins and directions for selected pixels
    """
    W, H = image_size
    
    # Step 1: Generate full pixel grid in NDC coordinates [-1, 1]
    # Assuming get_pixels_from_image returns shape [W*H, 2]
    xy_grid = get_pixels_from_image(image_size, camera) 
    
    # Step 2: Generate random permutation of indices
    # torch.randperm generates indices 0 to N-1 in random order
    num_pixels_total = W * H
    perm_indices = torch.randperm(num_pixels_total, device=xy_grid.device)
    
    # Step 3: Select first n_pixels indices
    selected_indices = perm_indices[:n_pixels]
    
    # Step 4: Gather coordinates
    # Reshape to [n_pixels, 2]
    selected_pixels = xy_grid[selected_indices].reshape(n_pixels, 2)
    
    # Step 5: Generate rays from selected pixels
    # get_rays_from_pixels handles the projection math
    rays = get_rays_from_pixels(selected_pixels, camera)
    
    return rays
```

**Parameters:**
*   `n_pixels`: The batch size in pixel space. Typical values depend on GPU memory constraints; often significantly smaller than $W \times H$ (e.g., 1024–4096 pixels) [S3, unofficial].
*   `image_size`: Determined by the target resolution [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Memory Overflow:** If `n_pixels` is too large, the backward pass may exceed GPU memory limits [S3, unofficial].
*   **Bias:** Pure random sampling does not account for image complexity. Uniform random selection may undersample high-frequency regions if not combined with other techniques [S5, unofficial].
*   **Reproducibility:** Random permutations require seed management for reproducible training logs [S1, unofficial].

## Subtopics

### [Frequency-aware Mask Generation](2537-frequency-aware-mask-generation.md)
Frequency-aware Mask Generation produces binary spatial masks to guide neural rendering training by highlighting frequency-specific structures in rendered images. It distinguishes between coarse structures (prioritized in early training) and fine structures (prioritized in late training) to improve high-frequency detail reconstruction. Unlike random subsampling methods that select pixels uniformly or via simple heuristics, this method weights the reconstruction loss based on the spectral content of the ground truth image, allowing the model to adaptively focus optimization on relevant spatial frequencies. It builds on [Random Pixel Subsampling](1668-random-pixel-subsampling.md) by providing a structured, frequency-dependent selection signal rather than a purely stochastic one.

### Ray Sampling with Precropping
Ray Sampling with Precropping is a random pixel sampling strategy that restricts coordinate selection to the image center during early training iterations to stabilize optimization, then expands to the full image [S4, unofficial].
*   **Mechanism:** If the current iteration $i < \text{precrop\_iters}$, crop margins are computed as $d_H = \lfloor H/2 \cdot \text{precrop\_frac} \rfloor$ and $d_W = \lfloor W/2 \cdot \text{precrop\_frac} \rfloor$. A coordinate grid is created using `tf.meshgrid` with ranges $[H/2 - d_H, H/2 + d_H)$ and $[W/2 - d_W, W/2 + d_W)$ using `indexing='ij'` to match $(y, x)$ layout [S4, unofficial]. Otherwise, the full grid is used [S4, unofficial].
*   **Parameters:** `precrop_iters` (typical value: 10000) and `precrop_frac` (typical value: 0.5, sampling the center 50%) [S4, unofficial].
*   **Pitfall:** Coordinate indexing mismatch can occur if `indexing='ij'` is not used in `meshgrid`, leading to incorrect ray gathering [S4, unofficial].

### Pixel Shuffle Sampling
Pixel Shuffle Sampling is a pixel distribution algorithm based on Fibonacci numbers that progressively adds or removes pixels to maintain low discrepancy [S5, unofficial].
*   **Comparison:** Unlike random distribution, which leads to inhomogeneous regions, Pixel Shuffle provides low discrepancy (LD) and uniform distribution, leading to better recovery results [S5, unofficial]. Unlike Poisson Disk Sampling, which achieves LD and blue-noise distribution but is not progressive (high coverage does not contain low coverage), Pixel Shuffle is progressive, allowing for progressive image updates [S5, unofficial].
*   **Use Case:** Compressive rendering where a subset of pixels is recovered to reconstruct the full image [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(n_{pixels})$ per iteration, independent of total image resolution $W \times H$ [S3, unofficial].
*   **Memory Complexity:** $O(n_{pixels} \cdot N_{samples})$, where $N_{samples}$ is the number of points per ray [S3, unofficial]. This is significantly lower than full-image rendering $O(W \cdot H \cdot N_{samples})$.
*   **Performance:** Reduces training time per iteration linearly with the subsampling ratio [S3, unofficial]. However, convergence may require more iterations to cover the full image space uniformly compared to full-batch training [S1, unofficial].
*   **Strengths:** Enables training on high-resolution images that would otherwise exceed GPU memory limits [S3, unofficial]. Simple to implement [S2, unofficial].
*   **Limitations:** Does not adapt to local scene complexity; uniform random sampling may waste queries on empty background regions [S5, unofficial].
*   **When to use:** When GPU memory is constrained or when rapid iteration is prioritized over per-step accuracy [S3, unofficial].
*   **When not to use:** When high-frequency detail preservation is critical without additional weighting mechanisms [S5, unofficial].

## Background
Random Pixel Subsampling originated as a practical solution for scaling Neural Radiance Fields (NeRF) and other implicit volume representations to higher resolutions [S1, S3, unofficial]. It was popularized in early NeRF implementations to manage the computational cost of evaluating dense neural networks along millions of rays [S4, unofficial]. The technique is widely used in open-source volume rendering assignments and frameworks to facilitate efficient training loops [S1, S2, S3, unofficial].
