# Random Pixel Subsampling

Also called: Pixel Subsampling, Random Pixel Sampling

## Overview
Random Pixel Subsampling selects a random subset of pixel coordinates from a full image grid to reduce the computational cost of training volume rendering models, such as Neural Radiance Fields (NeRFs), by evaluating the scene only at a fraction of the pixels per iteration [S1, S2, unofficial]. It differs from [Two-stage NeRF Rendering](925-two-stage-nerf-rendering.md) by operating within a single training pass using stochastic gradient descent on a pixel subset, rather than separating coarse and fine rendering stages, and from [Resolution Adaptation](3063-resolution-adaptation.md) by keeping the image resolution constant while varying the number of active pixels [S1, S2, unofficial].

## How it works
**Inputs:**
- `image_size`: Tuple `(W, H)` representing image width and height [S2, unofficial].
- `n_pixels`: Integer, the number of pixels to sample per iteration [S2, unofficial].
- `camera`: Camera object providing projection parameters (e.g., `PerspectiveCameras`) [S2, unofficial].

**Outputs:**
- `pixel_coords`: Tensor of shape `[n_pixels, 2]` containing the $(x, y)$ coordinates of the selected pixels in Normalized Device Coordinates (NDC) or pixel space, depending on the implementation [S1, S2, unofficial].

**Data Structures:**
- `pixel_coords`: A 2D tensor/array where each row is a pixel coordinate pair.
- `indices`: A 1D tensor/array of integers representing the linear indices of the pixels in the flattened grid.

**Steps:**
1. **Generate Full Grid:** Create a grid of all pixel coordinates for the image.
   - If using NDC coordinates (range $[-1, 1]$), generate coordinates for each pixel center.
   - Flatten the grid to a 1D list of coordinates with shape `[W*H, 2]` [S1, S2, unofficial].
2. **Generate Indices:** Create a list of linear indices corresponding to the flattened grid, i.e., `[0, 1, ..., W*H - 1]` [S1, S2, unofficial].
3. **Shuffle Indices:** Apply a random permutation to the indices to ensure unbiased sampling.
   - Use a pseudo-random number generator to shuffle the indices [S1, S2, unofficial].
4. **Select Subset:** Select the first `n_pixels` indices from the shuffled list [S1, S2, unofficial].
5. **Map to Coordinates:** Use the selected indices to gather the corresponding pixel coordinates from the full grid [S1, S2, unofficial].
6. **Reshape:** Reshape the selected coordinates to `[n_pixels, 2]` [S1, S2, unofficial].

**Pseudocode:**
```python
import torch

def get_random_pixels_from_image(image_size, n_pixels, camera=None):
    """
    Selects a random subset of pixel coordinates from a full image grid.
    
    Args:
        image_size: Tuple (W, H)
        n_pixels: Number of pixels to sample
        camera: Optional camera object (unused in basic random sampling, 
                but may be used for coordinate generation in some implementations)
    
    Returns:
        pixel_coords: Tensor of shape [n_pixels, 2]
    """
    W, H = image_size
    total_pixels = W * H
    
    # Step 1: Generate full pixel grid
    # Assuming NDC coordinates [-1, 1] for x and y
    # Create meshgrid of pixel centers
    x_coords = torch.linspace(-1 + 1/W, 1 - 1/W, W)
    y_coords = torch.linspace(-1 + 1/H, 1 - 1/H, H)
    xx, yy = torch.meshgrid(x_coords, y_coords, indexing='ij')
    
    # Flatten and stack to get [W*H, 2]
    pixel_grid = torch.stack([xx.flatten(), yy.flatten()], dim=-1)
    
    # Step 2: Generate indices
    indices = torch.arange(total_pixels)
    
    # Step 3: Shuffle indices
    shuffled_indices = torch.randperm(total_pixels)
    
    # Step 4: Select first n_pixels indices
    selected_indices = shuffled_indices[:n_pixels]
    
    # Step 5: Map to coordinates
    pixel_coords = pixel_grid[selected_indices]
    
    # Step 6: Reshape (already [n_pixels, 2])
    return pixel_coords
```

**Parameters:**
- `n_pixels`: Number of pixels to sample. Typical values depend on the total resolution; for a $512 \times 512$ image, sampling 10,000–20,000 pixels is common [S1, S2, unofficial].
- `image_size`: Tuple `(W, H)`.
- `camera`: Optional, used if coordinate generation requires camera parameters [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Ensure that coordinate generation matches the expected range (NDC vs. pixel indices) to avoid misalignment with the camera model [S1, unofficial].
- **Boundaries:** When generating NDC coordinates, ensure pixel centers are correctly calculated to avoid edge artifacts [S1, unofficial].
- **Degenerate Input:** If `n_pixels` > `W*H`, the method should either raise an error or return all pixels [G].

## Subtopics

### [Frequency-aware Mask Generation](2537-frequency-aware-mask-generation.md)
Frequency-aware Mask Generation produces a binary spatial mask $M_{freq}$ that highlights frequency-specific structures in rendered images to guide training. It distinguishes between coarse structures (prioritized early in training) and fine structures (prioritized later) by modulating Gaussian filter scales based on a schedule parameter. Unlike standard pixel-wise losses, this method spatially weights the error based on the spectral content of the ground truth image, allowing the model to prioritize low-frequency structures early and high-frequency details later.

### Ray Sampling with Precropping
Ray Sampling with Precropping restricts coordinate selection to the image center during early training iterations to stabilize optimization, then expands to the full image [S3, unofficial].
- **Steps:**
  1. If iteration $i < \text{args.precrop\_iters}$, compute crop margins $dH = \text{int}(H//2 \times \text{args.precrop\_frac})$ and $dW = \text{int}(W//2 \times \text{args.precrop\_frac})$ [S3, unofficial].
  2. Create a coordinate grid using `tf.meshgrid` with ranges $[H//2 - dH, H//2 + dH)$ and $[W//2 - dW, W//2 + dW)$, using `indexing='ij'` [S3, unofficial].
  3. Else, create a full grid using `tf.range(H)` and `tf.range(W)` [S3, unofficial].
  4. Reshape coordinates to `[-1, 2]`, randomly sample $N_{rand}$ indices without replacement via `np.random.choice`, and gather ray origins/directions and target colors using `tf.gather_nd` [S3, unofficial].
- **Parameters:**
  - `args.precrop_iters`: Number of iterations to apply precropping. Typical value: 10,000 [S3, unofficial].
  - `args.precrop_frac`: Fraction of half-dimensions to crop. Typical value: 0.5 (samples center 50%) [S3, unofficial].
- **Pitfall:** Coordinate indexing mismatch; resolved by using `indexing='ij'` in `meshgrid` to match the $(row, col) \rightarrow (y, x)$ layout expected by `gather_nd` [S3, unofficial].

### Pixel Shuffle Sampling
Pixel Shuffle Sampling is a pixel distribution algorithm based on Fibonacci numbers that progressively adds or removes pixels to maintain low discrepancy [S4, unofficial].
- **Comparison:**
  - **vs. Random Distribution:** Random distribution leads to inhomogeneous regions, while Pixel Shuffle provides low discrepancy (LD) and uniform distribution, leading to better recovery results [S4, unofficial].
  - **vs. Poisson Disk Sampling:** Poisson disk sampling achieves low discrepancy and blue-noise distribution but is not progressive (high coverage does not contain low coverage). Pixel Shuffle is progressive, allowing for progressive image updates [S4, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \cdot H)$ to generate the full grid, $O(W \cdot H)$ to shuffle indices, and $O(n_{pixels})$ to select and gather coordinates. The dominant cost is the initial grid generation and shuffling, which is done once per iteration or cached [S1, S2, unofficial].
- **Memory Complexity:** $O(W \cdot H)$ to store the full pixel grid and indices [S1, S2, unofficial].
- **Measured Performance:** Reduces training time per iteration by a factor of $\frac{W \cdot H}{n_{pixels}}$ [S1, S2, unofficial].
- **Scaling:** Scales linearly with image resolution for grid generation, but the sampling cost is independent of resolution once the grid is generated [S1, S2, unofficial].
- **Strengths:** Simple to implement, reduces memory bandwidth and computation per iteration, easy to parallelize [S1, S2, unofficial].
- **Limitations:** May miss important details if the random subset is not representative, especially in early training [S1, S2, unofficial].
- **When to Use:** When training large scenes or high-resolution images where full-pixel rendering is too slow [S1, S2, unofficial].
- **When Not to Use:** When precise pixel-level accuracy is required in every iteration, or when the scene has highly localized features that might be missed by random sampling [S1, S2, unofficial].

## Background
Random Pixel Subsampling was introduced as a practical optimization for training Neural Radiance Fields (NeRFs) and other volume rendering models, where evaluating the neural network at every pixel is computationally expensive [S1, S2, unofficial]. The method leverages the fact that stochastic gradient descent does not require the full dataset in every iteration, allowing for a subset of pixels to be used for gradient updates [S1, S2, unofficial]. The technique has been widely adopted in open-source NeRF implementations, such as those by [Samiran Angode](https://github.com/samirangode/Volume-Rendering-and-Neural-Radiance-Fields) and [Shyam-pi](https://github.com/Shyam-pi/Volume-Rendering-and-Neural-Radiance-Fields) [S1, S2, unofficial].
