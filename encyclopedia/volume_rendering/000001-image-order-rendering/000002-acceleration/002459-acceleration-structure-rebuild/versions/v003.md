# Acceleration Structure Rebuild
Also called: Per-Frame Grid Rebuild

## Overview
Acceleration Structure Rebuild discards the previous frame's acceleration structure and constructs a new one from scratch every frame for animated scenes [S2]. It supports arbitrary, unrestricted animation types by avoiding the complexity and limitations of incremental or hierarchical update schemes [S1]. It differs from siblings like [Adaptive Multi-Step Empty Voxel Skipping](6289-adaptive-multi-step-empty-voxel-skipping.md) or [Temporal Coherence and Caching](6372-temporal-coherence-and-caching.md) by rejecting temporal reuse of the structure itself, relying instead on full reconstruction speed and parallel processing [G].

## How it works
### Inputs and Outputs
- **Inputs**: 
  - $N$: Number of triangles in the scene [S1, S2].
  - $V$: Volume of the grid bounding box [S1, S2].
  - $\mathbf{d}$: Diagonal vector of the grid bounding box [S1, S2].
  - $\lambda$: Multiplier parameter for grid resolution [S1, S2].
  - Previous frame's macrocell information (optional, for optimization) [S1, S2].
  - Triangle list (positions, normals, etc.) [G].
- **Outputs**: 
  - A new acceleration grid mapping grid cells to triangle references [S1, S2].
  - Derived data structures for triangle intersection tests [S1, S2].

### Data Structures
1. **Grid**: A sparse array or hash map mapping 3D cell coordinates $(i, j, k)$ to lists of triangle indices. The grid dimensions $(N_x, N_y, N_z)$ are calculated per frame [S1, S2].
2. **Triangle List**: An array of triangle primitives [G].
3. **Derived Data**: Precomputed data for fast triangle-ray intersection as described by Wald [S1, S2].
4. **Macrocell Map**: A coarse grid structure from the previous frame, used to identify which fine cells might contain changed geometry [S1, S2].

### Parameters
- $\lambda$: The multiplier determining the total number of cells relative to the number of triangles. Optimal performance is typically achieved around $\lambda \approx 5$ for most scenes [S1, S2].

### Steps
1. **Calculate Grid Resolution**: Determine the number of cells along each axis to approximate cubic cells, which minimize the surface-area-to-volume ratio and thus expected ray-tracing cost [S1, S2].
   $$ N_x = d_x \sqrt[3]{\frac{\lambda N}{V}} $$
   $$ N_y = d_y \sqrt[3]{\frac{\lambda N}{V}} $$
   $$ N_z = d_z \sqrt[3]{\frac{\lambda N}{V}} $$
   where $d_x, d_y, d_z$ are the components of the grid diagonal $\mathbf{d}$, and $V$ is the grid volume [S1, S2].
2. **Clear Grid**: Initialize the new grid. To optimize, use macrocell information from the previous frame to identify only the cells that need to be cleared or updated, rather than clearing the entire grid if it is sparse [S1, S2].
3. **Insert Triangles**: For each triangle in the scene:
   a. Compute the triangle's axis-aligned bounding box (AABB).
   b. Determine all grid cells overlapped by this AABB.
   c. Add a reference to the triangle to each of these cells.
   A conservative bounding box test is used instead of an exact triangle-in-box test. While the exact test reduces triangle references by more than one third, it increases rebuild cost significantly with only a few percent gain in ray-triangle test reduction [S1, S2]. For scenes with dominantly long, skinny, diagonal triangles, an exact test may be preferable [S2].
4. **Build Derived Data**: Create derived data structures for triangle intersection tests (e.g., as described by Wald [S1, S2]). This step is parallelizable and can be executed concurrently with the grid rebuild [S1, S2]. Storage-free triangle tests (e.g., Möller-Trumbore) were found to be slightly inferior in overall performance compared to derived data, even when accounting for rebuild time [S1, S2].
5. **Memory Management**: Use a preallocated pooled-memory scheme for cell lists to prevent per-cell memory allocations and fragmentation during the frame-to-frame transition [S1, S2].

### Pseudocode
```python
import math

def rebuild_acceleration_structure(triangles, grid_min, grid_max, lambda_param, prev_macrocells=None):
    # 1. Calculate Grid Resolution
    diag = [grid_max[i] - grid_min[i] for i in range(3)]
    volume = diag[0] * diag[1] * diag[2]
    num_triangles = len(triangles)
    cell_count_factor = (lambda_param * num_triangles / volume) ** (1.0/3.0)
    
    nx = max(1, round(diag[0] * cell_count_factor))
    ny = max(1, round(diag[1] * cell_count_factor))
    nz = max(1, round(diag[2] * cell_count_factor))
    
    # 2. Initialize Grid & Clear
    new_grid = {}
    if prev_macrocells is not None:
        # Use macrocell info to clear only relevant cells [S1, S2]
        for cell in prev_macrocells:
            new_grid.pop(cell, None)
    else:
        new_grid.clear()
        
    # 3. Insert Triangles
    for tri_idx, tri in enumerate(triangles):
        aabb_min = [min(v[i] for v in tri.vertices) for i in range(3)]
        aabb_max = [max(v[i] for v in tri.vertices) for i in range(3)]
        
        min_cell = [0, 0, 0]
        max_cell = [0, 0, 0]
        dims = [nx, ny, nz]
        for i in range(3):
            t_min = (aabb_min[i] - grid_min[i]) / diag[i]
            t_max = (aabb_max[i] - grid_min[i]) / diag[i]
            min_cell[i] = max(0, int(t_min * dims[i]))
            max_cell[i] = min(dims[i] - 1, int(t_max * dims[i]))
            # Clamp to prevent out-of-bounds when t_max is exactly 1.0
            if max_cell[i] >= dims[i]:
                max_cell[i] = dims[i] - 1
                
        for x in range(min_cell[0], max_cell[0] + 1):
            for y in range(min_cell[1], max_cell[1] + 1):
                for z in range(min_cell[2], max_cell[2] + 1):
                    if (x, y, z) not in new_grid:
                        new_grid[(x, y, z)] = []
                    new_grid[(x, y, z)].append(tri_idx)
                    
    # 4. Build Derived Data (Parallelizable)
    # Precompute plane normal and D for fast triangle-ray intersection [G]
    derived_data = []
    for tri in triangles:
        v0, v1, v2 = tri.vertices
        normal = cross(sub(v1, v0), sub(v2, v0))
        d = dot(normal, v0)
        derived_data.append({"normal": normal, "d": d})
            
    return new_grid, derived_data, (nx, ny, nz)

def sub(a, b): return [a[i] - b[i] for i in range(3)]
def cross(a, b): return [a[1]*b[2]-a[2]*b[1], a[2]*b[0]-a[0]*b[2], a[0]*b[1]-a[1]*b[0]]
def dot(a, b): return sum(a[i]*b[i] for i in range(3))
```

### Edge Cases and Pitfalls
- **Long, Skinny, Diagonal Triangles**: The conservative bounding box test may insert too many references for such triangles. In these specific cases, an exact triangle-in-box test might be justified despite the higher rebuild cost [S2].
- **Large Scenes**: The performance characteristics described (e.g., derived data superiority) are based on medium-size scenes. For much larger scenes, storage-free tests or bricking techniques might yield different results [S1, S2].
- **Memory Fragmentation**: Without a pooled memory scheme, frequent rebuilds can lead to significant fragmentation and allocation overhead [S1, S2].

## Operating characteristics
- **Time Complexity**: Not given in the sources [S1, S2].
- **Memory Complexity**: Not given in the sources [S1, S2].
- **Performance**: Optimal $\lambda \approx 5$ for most scenes [S1, S2]. The triangle rebuild takes less time than the grid rebuild and can be run in parallel [S1, S2].
- **Strengths**: Supports any type of animation without restrictions; simple implementation; no need for complex incremental update logic [S1, S2].
- **Limitations**: High build cost per frame compared to incremental updates; not suitable for static scenes where incremental or hierarchical updates would be more efficient; conservative bounding box test may lead to more ray-triangle intersections than necessary [S1, S2].

## Background
The method was introduced in "Ray Tracing Animated Scenes using Coherent Grid Traversal" by Wald et al. (2006) [S1, S2]. It was chosen over incremental [Reinhard et al. 2000] or hierarchical [Lext and Akenine-Moller 2001] updates to support arbitrary animations without restrictions [S1]. The grid resolution formula is based on the work of Cleary et al. (1983) [S1, S2].
