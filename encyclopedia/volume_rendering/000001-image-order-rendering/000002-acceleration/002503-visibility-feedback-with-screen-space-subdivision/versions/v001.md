# Visibility Feedback with Screen Space Subdivision

Also called: Occlusion Culling Feedback, Visibility Feedback for Occlusion Culling, Visibility-based Node Refinement

## Overview
Visibility Feedback with Screen Space Subdivision is an optimization technique for out-of-core volume rendering that uses visibility information gathered during rendering to optimize data management in the loader [S1]. It prevents wasting GPU memory resources and bandwidth by only refining nodes marked as visible in the previous frame, avoiding the inefficiency of discovering occluded areas only at rasterization time after data is loaded [S1]. Unlike standard early ray termination which discovers occlusion after data is in the working set, this method incorporates visibility feedback into the loader to prevent loading or refining occluded areas beforehand [S1].

## How it works
### Inputs and Outputs
**Inputs:**
*   An octree data structure representing the volume, where nodes have associated 3D bounding boxes and projected 2D screen-space bounding rectangles [S1].
*   A budget of visibility queries allowed per frame [S1].
*   A visibility threshold (number of visible pixels below which a node is considered occluded) [S1].

**Outputs:**
*   A refined view-dependent working set of non-empty nodes for the current frame [S1].
*   Updated visibility status for nodes in the graph [S1].
*   A list of screen tiles partitioning the viewport and a list of blocks whose projection is entirely contained within one of the tiles [S1].

### Data Structures
*   **Octree Node:** Contains a 3D bounding box, a flag for emptiness, and a visibility status (boolean) [S1].
*   **Projected Rectangle:** A 2D bounding box representing the projection of a node's 3D bounding box onto the screen [S1].
*   **Visibility Status:** A boolean flag per node. A leaf is visible if its occlusion query returns more visible pixels than the threshold. An inner node is visible if at least one of its children is visible [S1].

### Numbered Steps

1.  **Initialize Visibility:** At the start of the refinement cycle, initialize a sorted set of visible non-empty nodes with the octree root [S1].
2.  **Screen Space Subdivision (Query Scheduling):**
    *   Given the budget of visibility queries per frame, recursively partition the screen into tiles to separate blocks for which visibility will be queried from others [S1].
    *   Use a 2D binary space subdivision of the list of 2D rectangles bounding the block projection [S1].
    *   At each subdivision step, place a split plane along one of the axes at the position that separates the set into two equally sized subsets, defining two screen tiles [S1].
    *   Select one of the two tiles as containing the occlusion queried subset of octree nodes [S1].
    *   Continue subdivision only on that selected tile until its size is below a certain threshold [S1].
    *   At each frame, take different decisions when selecting the halfspaces to ensure the entire set of octree nodes is covered after a minimum number of frames [S1].
    *   Obtain a list of tiles partitioning the viewport and a list of blocks whose projection is entirely contained within one of the tiles, placed at the beginning of the list [S1].
3.  **Rendering and Depth Buffer Update:**
    *   Instruct the graphics pipeline to raycast each tile [S1].
    *   During raycasting, the fragment shader writes the depth of the last visited sample into the depth buffer [S1].
4.  **Occlusion Query Issuance:**
    *   Perform occlusion queries for the selected subset of octree nodes (non-empty leaves) just after issuing the rendering command of the first tile [S1]. This interleaving reduces end-to-end latency [S1].
5.  **Visibility Propagation:**
    *   If the occlusion query result indicates that the number of visible pixels is below the visibility threshold, mark the node as not visible [S1].
    *   Propagate visibility information up the tree: consider an inner node visible only if at least one of its children is visible [S1].
6.  **Refinement:**
    *   During the refinement cycle, only refine nodes that were marked as visible during the previous frame [S1]. Empty nodes are terminal in the refinement process [S1].

    for node in octree.leaves:

        else:

### Parameters
*   **Visibility Threshold:** The number of visible pixels below which a node is marked as not visible. Typical value: 4 pixels [S1].
*   **Visibility Incorporation Delay:** $N + 1$ frames, where $N$ is the number of partitions required to cover all blocks. Typical value: 2 to 4 frames [S1].

### Edge Cases and Pitfalls
*   **Pipeline Delay:** Occlusion query results are not available immediately due to the delay between issuing the query and its actual processing by the graphics pipeline [S1]. A straightforward implementation issuing queries for all rendered nodes is inefficient [S1]. The screen space subdivision interleaves query processing with rasterization to mitigate this [S1].
*   **Semitransparent Materials:** Visibility culling is less effective for semitransparent materials, resulting in a smaller working set reduction (50%) compared to opaque surfaces (60%) [S1].

## Operating characteristics
*   **Working Set Reduction:** Reduces the working set by about 50% in semitransparent cases and by about 60% when surfaces are more opaque [S1].
*   **Memory Occupation:**
    *   Isosurface rendering: Average 1560 bricks, peak 1820 bricks [S1].
    *   Direct volume rendering: Average 1890 bricks, peak 2450 bricks [S1].
    *   Minimum texture memory occupation for both: about 475 octree bricks [S1].
*   **Performance:**
    *   Isosurface rendering: 20 Hz average, 40 Hz peak [S1].
    *   Direct volume rendering: 12-30 Hz average, 16 Hz average [S1].
    *   Scaling: On a 1024x1024 window, average slowdown of a factor of 3 compared to 640x480, roughly corresponding to the increase in number of pixels [S1].
*   **Strengths:** Optimizes GPU memory and bandwidth by preventing loading/refining of occluded areas. Reduces end-to-end latency through interleaved query processing [S1].
*   **Limitations:** Less effective for semitransparent materials. Requires additional overhead for screen space subdivision and managing query scheduling [S1].

## Background
*   **Origin:** The method is described in "A single-pass GPU ray casting framework for interactive out-of-core volume rendering" [S1].
*   **History:** It was developed to address the inefficiency of standard early ray termination, which discovers occluded areas only at rasterization time, after data is already part of the working set [S1]. The technique exploits spatial and temporal coherence to schedule queries [S1].
