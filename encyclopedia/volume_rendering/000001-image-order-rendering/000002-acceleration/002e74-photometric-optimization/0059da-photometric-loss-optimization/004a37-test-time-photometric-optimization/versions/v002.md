# Test-Time Photometric Optimization

Also called: Gradient-driven camera pose refinement at test time, Test-time pose alignment via photometric error

## Overview
Test-Time Photometric Optimization (TTPO) is a post-processing step applied to trained Neural Radiance Field (NeRF) models to refine camera poses or factor out pose errors during novel view synthesis [S1]. It solves the problem where initial camera poses (e.g., from COLMAP or sparse reconstruction) are noisy or misaligned, causing artifacts in rendered images [S1]. Unlike standard training which updates both scene and pose parameters, TTPO keeps the NeRF model fixed and optimizes only the camera parameters to minimize the photometric difference between rendered and target images [S1]. It is distinguished from [Gradient-Based SE(3) Optimization](7526-gradient-based-se-3-optimization.md) by its specific application as a fine-grained refinement step *after* model training, often used to evaluate view synthesis quality independently of pose accuracy [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A pre-trained NeRF model $\hat{F}_\theta$ with fixed weights $\theta$; a set of target images $\hat{C}(r)$ for specific camera poses; initial camera poses $v$ (rotation $R$, translation $t$); learning rate $\eta$.
*   **Outputs:** Refined camera poses $v^*$ that minimize photometric error.

**Data Structures:**
*   **NeRF Model:** A function $I(r; \theta)$ mapping ray $r$ (defined by camera pose $v$ and direction) to color. The parameters $\theta$ are frozen.
*   **Camera Pose:** Represented as a transformation matrix or SE(3) parameters. In [S1], poses are transformed to a coordinate system aligned with optimized poses before optimization [S1].

**Steps:**
1.  **Coordinate Alignment:** Transform test views to the coordinate system of the optimized poses by applying scale, rotation, and translation derived from prior alignment analysis [S1].
2.  **Ray Generation:** For each target image, generate rays $R$ passing through the camera center defined by the current pose $v_t$ and image pixel coordinates.
3.  **Rendering:** Compute the rendered color $I(r; \hat{\theta})$ for each ray $r \in R$ using the fixed NeRF model [S1].
4.  **Loss Calculation:** Compute the photometric loss $\mathcal{L}_{photo}$ between the rendered image and the target image $\hat{C}$ [S1]:
    $$
    \mathcal{L}_{photo} = \frac{1}{|R|} \sum_{r \in R} \| I(r; \hat{\theta}) - \hat{C}(r) \|^2
    $$
5.  **Gradient Computation:** Compute the gradient of the loss with respect to the camera pose parameters $v$ via backpropagation through the differentiable renderer [S1]:
    $$
    \nabla_v \mathcal{L}_{photo}
    $$
6.  **Pose Update:** Update the camera pose using gradient descent [S1]:
    $$
    v_{t+1} = v_t - \eta \nabla_v \mathcal{L}_{photo}
    $$
7.  **Iteration:** Repeat steps 3-6 until convergence or a fixed number of iterations.

**Parameters:**
*   **Learning Rate ($\eta$):** Not given in the sources.
*   **Iterations:** Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Local Minima:** Photometric optimization can converge to local minima if the initial pose error is large. [S1] suggests using it in conjunction with coarser alignment methods.
*   **Occlusions/Inaccuracies:** High-confidence regions should be used to avoid artifacts from NeRF inaccuracies or occlusions, often utilizing masks or viewshed fields [S1].
*   **Metric Space:** In datasets where pose positions are not in metric space, translation error has no units, which may affect optimization stability [S1].

**Pseudocode:**
```python
def test_time_photometric_optimization(nerf_model, target_images, initial_poses, learning_rate, num_iterations):
    """
    Refines camera poses for a fixed NeRF model to minimize photometric error.
    
    Args:
        nerf_model: Pre-trained NeRF model with fixed weights.
        target_images: List of target images corresponding to initial_poses.
        initial_poses: List of initial camera poses (SE(3) or similar).
        learning_rate: Step size for gradient descent.
        num_iterations: Number of optimization steps.
        
    Returns:
        refined_poses: List of optimized camera poses.
    """
    # Copy initial poses to allow in-place updates
    current_poses = [pose.copy() for pose in initial_poses]
    
    for i in range(num_iterations):
        total_loss = 0.0
        # Accumulate gradients for all poses (or optimize one by one)
        # Here we assume batch optimization over rays for a single pose for clarity
        # In practice, this might be done per-image or per-batch
        
        for pose, target_img in zip(current_poses, target_images):
            # 1. Generate rays for the current pose
            rays = generate_rays(pose, target_img.shape)
            
            # 2. Render image using fixed NeRF model
            rendered_img = render_image(nerf_model, rays)
            
            # 3. Compute photometric loss (MSE)
            loss = mean_squared_error(rendered_img, target_img)
            total_loss += loss
            
            # 4. Compute gradients w.r.t. pose parameters
            # Note: nerf_model weights are frozen
            pose_gradients = compute_gradients(loss, pose, nerf_model, rays)
            
            # 5. Update pose
            current_pose = pose - learning_rate * pose_gradients
            
        # Optional: Check convergence
        if total_loss < threshold:
            break
            
    return current_poses
```

## Subtopics

### Inverse Manipulation (Inversion)
An iterative method to optimize generation conditions (shape code $z_s$, appearance code $z_a$, camera $v$) to inversely project an input image $I_r$ to the generation manifold, following the EM algorithm [S2]. It alternates between optimizing the camera pose, shape code, and appearance code [S2].
*   **Camera Step:** Optimizes $v$ while keeping $z_s$ and $z_a$ fixed using loss $L_v$:
    $$
    L_v = \| \hat{F}_\theta(v, \hat{z}_s, \hat{z}_a) - I_r \|^2 + \lambda_v D_{CLIP}(\hat{F}_\theta(v, \hat{z}_s, \hat{z}_a), I_r)
    $$
*   **Shape Step:** Updates $z_s$ by minimizing $L_s$:
    $$
    L_s = \| \hat{F}_\theta(\hat{v}, z_s + \lambda_n z_n, \hat{z}_a) - I_r \|^2 + \lambda_s D_{CLIP}(\hat{F}_\theta(\hat{v}, z_s + \lambda_n z_n, \hat{z}_a), I_r)
    $$
*   **Appearance Step:** Updates $z_a$ by minimizing $L_a$:
    $$
    L_a = \| \hat{F}_\theta(\hat{v}, \hat{z}_s, z_a + \lambda_n z_n) - I_r \|^2 + \lambda_a D_{CLIP}(\hat{F}_\theta(\hat{v}, \hat{z}_s, z_a + \lambda_n z_n), I_r)
    $$
*   **Parameters:** $z_n$ is a random standard Gaussian noise vector sampled in each step to improve robustness. $\lambda_n$ is a noise scaling factor that linearly decays from 1 to 0 through the optimization iterations [S2]. $\lambda_v, \lambda_s, \lambda_a$ are loss weights [S2].

## Operating characteristics
*   **Time Complexity:** Linear in the number of rays and iterations. Each iteration requires a forward pass through the NeRF for all rays and a backward pass for the pose gradients.
*   **Memory Complexity:** Depends on the NeRF model size and the number of rays processed per batch. The NeRF weights are loaded once and kept in memory.
*   **Performance:** Improves view synthesis quality by correcting pose errors [S1]. It is effective when initial poses are noisy but not severely misaligned [S1].
*   **Strengths:** Decouples pose error from view synthesis quality evaluation [S1]. Simple to implement as it reuses the differentiable renderer.
*   **Limitations:** Computationally expensive if many iterations are needed. Sensitive to local minima if initial poses are poor [S1]. Requires high-confidence regions to avoid artifacts [S1].
*   **When to Use:** When evaluating novel view synthesis quality independently of pose accuracy, or when refining poses after a coarse alignment step [S1].
*   **When Not to Use:** When the initial pose error is too large for gradient-based methods to converge, or when the NeRF model itself is inaccurate and needs retraining.

## Background
Test-Time Photometric Optimization was introduced in the context of evaluating novel view synthesis in the presence of sparse and noisy poses [S1]. It is used in works like SPARF to factor out pose error from view synthesis quality metrics (PSNR, SSIM, LPIPs) [S1]. The method builds on the principle of differentiable rendering and photometric loss optimization [S1].
