# Photometric Optimization

Also called: Albedo/Emission/Extinction optimization, EgoNeRF Training, Property reconstruction, Volume Optimization

## Overview
Photometric optimization is an inverse rendering technique that recovers latent scene parameters—such as 3D geometry, pose, texture, and lighting—by minimizing the photometric difference between a target image and a rendered image [S1][S2, S3]. Unlike methods that rely on discrete candidate light sources or explicit shadow detection, this approach performs continuous optimization of scene properties, often utilizing shape priors to regularize the solution space [S1][S2, S3]. It distinguishes itself from finite difference methods by providing cleaner, unbiased derivative estimations, and from feed-forward networks by allowing explicit control over geometry and lighting through iterative refinement [S1][S2, S3].

## How it works
The method minimizes a photometric loss function to update scene parameters. The standard emission-absorption model computes the color $\hat{C}(\mathbf{r})$ for a ray $\mathbf{r}$ as [44-radiance-field-optimization.md]:

$$
\hat{C}(\mathbf{r}) = \sum_{i=1}^N T_i (1 - \exp(-\sigma_i \delta_i)) \mathbf{c}_i
$$

where $\sigma_i$ is the density, $\delta_i$ is the step size, $\mathbf{c}_i$ is the color, and $T_i = \exp\left(-\sum_{j=1}^{i-1} \sigma_j \delta_j\right)$ is the transmittance [44-radiance-field-optimization.md].

### Inputs and Outputs
*   **Inputs:** A set of target images (ground truth colors $C(\mathbf{r})$), initial scene parameters (e.g., voxel grid densities $\sigma$, albedo $\mathbf{a}$, emission $\mathbf{e}$, or neural network weights), and camera poses.
*   **Outputs:** Optimized scene parameters that minimize the difference between rendered and target images.

### Data Structures
*   **Voxel Grid:** Stores volume properties. For example, in [S1], a 3D grid of voxels stores extinction, albedo, and emission.
*   **Feature Grids:** In methods like EgoNeRF [S2], balanced spherical grids $G_\sigma, G_a$ store density and appearance features.
*   **Ray Batch:** A set of randomly sampled rays $\mathcal{R}$ for each optimization step.

### Numbered Steps
1.  **Ray Sampling:** Sample a batch of rays $\mathcal{R}$ from the target images.
2.  **Volume Rendering:** Compute the rendered color $\hat{C}(\mathbf{r})$ for each ray $\mathbf{r} \in \mathcal{R}$ using the current scene parameters and the volume rendering equation [44-radiance-field-optimization.md].
3.  **Loss Computation:** Calculate the photometric loss $\mathcal{L}$ between the rendered color $\hat{C}(\mathbf{r})$ and the ground-truth color $C(\mathbf{r})$ [S2]:
    $$
    \mathcal{L} = \frac{1}{|\mathcal{R}|} \sum_{\mathbf{r} \in \mathcal{R}} \| \hat{C}(\mathbf{r}) - C(\mathbf{r}) \|_2^2
    $$
4.  **Regularization (Optional):** Apply regularization terms to improve stability and reduce artifacts.
    *   **Laplacian Regularizer:** In [S1], a weak Laplacian regularizer is applied to introduce diffusion between neighboring voxels, reducing stripe and edge artifacts without smoothing intricate detail.
    *   **Total Variation (TV) Loss:** In [S2] and [S5], TV loss is applied to feature grids or direction-aware representations to enforce spatio-temporal continuity and reduce noise, especially for real-world datasets with imperfect camera poses.
    *   **Mask Sparsity Loss:** In [S5], a mask sparsity loss $L_m$ (sum of all mask values) is combined with photometric and regularization losses.
5.  **Gradient Computation:** Compute gradients of the total loss with respect to the scene parameters. This can be done using:
    *   **Conjugate Gradient Solver:** As used in [S1] for volume property optimization.
    *   **Automatic Differentiation:** Standard backpropagation through the computational graph [44-radiance-field-optimization.md].
6.  **Parameter Update:** Update the scene parameters using an optimizer (e.g., Adam, Conjugate Gradient).
7.  **Iteration:** Repeat steps 1-6 until convergence.

### Formulas
*   **Photometric Loss:** $\mathcal{L} = \frac{1}{|\mathcal{R}|} \sum_{\mathbf{r} \in \mathcal{R}} \| \hat{C}(\mathbf{r}) - C(\mathbf{r}) \|_2^2$ [S2].
*   **Histogram Matching Loss (for cloud synthesis):** $\arg \min_{L_0, L_a} \sum_{n=1}^{n_L} [h(I_{ph}, n) - h(I(L_0, L_a), n)]^2$, where $n_L$ is the number of intensity levels, $h(I, n)$ is the normalized $n$-th histogram of image $I$, and $I(L_0, L_a)$ is the rendered image using parameters $L_0$ and $L_a$ [S7].
*   **Combined Loss (DaReNeRF):** $L = L_{photo} + \lambda_{reg} L_{reg} + \lambda_m L_m$ [S5].

### Parameters
*   **Ray Marching Steps:** In [S1], twice the number of ray marching steps for the length of the diagonal as the number of voxels along an axis is a good choice.
*   **Convergence:** The process converges after three to five conjugate gradient steps [S1].
*   **Regularization Weights:** $\lambda_{reg}$ for TV loss [S5], $\lambda_m$ for mask sparsity loss [S5].
*   **Histogram Matching Parameters:** $L_0$ and $L_a$ are optimized parameters for cloud synthesis [S7].

### Edge Cases and Pitfalls
*   **Insufficient Views:** May induce stripe patterns into the volume because constraint pixels affect only voxels along their corresponding ray [S1].
*   **Edges Between Regions:** Edges can appear between constrained and unconstrained regions if only parts of the object are specified in target images [S1].
*   **Emission/Albedo Constraints:** If only emission is optimized, the result cannot fully match desired appearance as light is only added. If only albedo is optimized, light is only removed, preventing perfect matching [S1].
*   **Floating Noisy Points:** Removing per-vertex deformation vectors $\Delta v$ in exploitation stage optimization causes floating noisy points in the reconstructed mesh, degrading lighting quality [S3].
*   **Pose Error:** Test-time photometric optimization is needed to factor out pose error from view synthesis quality when poses are noisy [S6].

### Pseudocode
```python
def photometric_optimization(scene_params, target_images, camera_poses, num_iterations):
    """
    Optimizes scene parameters to match target images using photometric loss.
    
    Args:
        scene_params: Initial scene parameters (e.g., voxel grid, MLP weights).
        target_images: List of target images.
        camera_poses: Camera poses for each target image.
        num_iterations: Number of optimization iterations.
        
    Returns:
        Optimized scene parameters.
    """
    for iteration in range(num_iterations):
        # 1. Sample rays
        rays = sample_rays(target_images, camera_poses)
        
        # 2. Render images
        rendered_colors = volume_render(rays, scene_params)
        
        # 3. Compute photometric loss
        gt_colors = get_ground_truth_colors(rays, target_images)
        loss = mean_squared_error(rendered_colors, gt_colors)
        
        # 4. Add regularization (optional)
        if use_laplacian_regularization:
            loss += laplacian_regularization(scene_params)
        if use_tv_regularization:
            loss += total_variation_loss(scene_params)
        if use_mask_sparsity_loss:
            loss += mask_sparsity_loss(scene_params)
            
        # 5. Compute gradients
        gradients = compute_gradients(loss, scene_params)
        
        # 6. Update parameters
        scene_params = update_parameters(scene_params, gradients)
        
    return scene_params
```

## Subtopics

### [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md)
Image-based reconstruction optimization is an inverse rendering technique that recovers latent scene parameters—such as 3D geometry, pose, texture, and lighting—by minimizing the photometric difference between a target image and a rendered image. It formulates the problem as an unconstrained optimization task, leveraging gradients estimated via differentiable rendering pipelines (e.g., boundary integral techniques or Monte Carlo path tracing) to update parameters using gradient descent. Unlike methods that rely on discrete candidate light sources or explicit shadow detection, this approach performs continuous optimization of scene properties, often utilizing shape priors to regularize the solution space. It distinguishes itself from finite difference methods by providing cleaner, unbiased derivative estimations, and from feed-forward networks by allowing explicit control over geometry and lighting through iterative refinement.

### [Gradient-Based SE(3) Optimization](7526-gradient-based-se-3-optimization.md)
This method refines the rigid transformation $\hat{T} \in SE(3)$ between two NeRF scenes (Scene A and Scene B) by minimizing photometric error on rays sampled from high-confidence regions. It differs from single-image alignment methods (like iNeRF) by optimizing over multiple images in the source set $C_A$ and utilizes Viewshed Fields (VF) to mask out unreliable pixels, thereby avoiding NeRF artifacts.

### [Joint Optimization of Scene and Renderer](11490-joint-optimization-of-scene-and-renderer.md)
Joint Optimization of Scene and Renderer is a photometric optimization method that simultaneously refines the geometric and appearance attributes of a scene representation alongside the parameters of a neural renderer. It solves the problem of reconstructing high-quality novel views from a sparse set of input images by treating per-pixel attributes (color, depth, normal, uncertainty, and latent features) as learnable parameters. It differs from [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md) by explicitly optimizing the scene's underlying point-based representation attributes rather than just camera poses or static geometry, and it differs from [Gradient-Based SE(3) Optimization](7526-gradient-based-se-3-optimization.md) by focusing on per-view attribute refinement rather than global camera pose estimation.

### [Adaptive IOR Optimization](13856-adaptive-ior-optimization.md)
Adaptive IOR Optimization is a training procedure for neural radiance fields that iteratively searches for the optimal Index of Refraction (IOR) to minimize the reconstruction error of transparent foreground objects. It solves the problem of unknown or inaccurate IOR values in refractive scene reconstruction by decoupling background training from foreground IOR selection. It differs from sibling methods like [Image-based reconstruction optimization](6677-image-based-reconstruction-optimization.md) by explicitly treating IOR as a discrete search parameter rather than a continuous gradient-based variable, and from [Gradient-Based SE(3) Optimization](7526-gradient-based-se-3-optimization.md) by focusing on material properties rather than camera pose.

### Exploitation Stage Optimization Vectors
Optimization parameters used during the explicit mesh shading pass to refine geometry and scene elements (materials, lighting). Removing the per-vertex deformation vector $\Delta v$ causes floating noisy points in the reconstructed mesh, which degrades lighting quality. Both $\Delta v$ and $\Delta m$ are crucial for high-quality reconstruction. Ablation results show full model PSNR/SSIM/LPIPS significantly outperforms variants without $\Delta v$ or $\Delta m$ on both NeRF-synthetic and RefNeRF-synthetic datasets [S3].

### NeRFLiX
Constructs training data $\{I_{gt}, I_{1r}, I_{2r}\}$ from original image sequence $\{I, I_{1r}, I_{2r} | I_{gt}\}$, where $I_{ir}$ uses high-quality supervised views. Extracts useful information from two high-quality supervised views $I_{1r}$ and $I_{2r}$ to recover the enhanced view $\hat{I}$ [S4].

### DaReNeRF Training Strategy
Training process using photometric loss, total variation regularization, coarse-to-fine resolution scheduling, and emptiness voxel skipping. Compute photometric loss between rendered colors $C(r)$ and ground-truth colors $\hat{C}(r)$. Compute total variation (TV) loss on the direction-aware representation to enforce spatio-temporal continuity. Compute mask sparsity loss $L_m$ as the sum of all mask values. Combine losses: $L = L_{photo} + \lambda_{reg} L_{reg} + \lambda_m L_m$. Use coarse-to-fine training strategy, progressively increasing grid resolution. Generate emptiness voxel by evaluating opacities across time steps and aggregating via maximum operation. Skip points in empty regions using the emptiness voxel during rendering. Regularization weight: $\lambda_{reg}$ [S5].

### Test-Time Photometric Optimization
Transform test views to coordinate system of optimized poses by applying scale/rotation/translation from alignment analysis. Run test-time photometric optimization on trained models to factor out pose error from view synthesis quality. This is a gradient-driven camera pose alignment minimizing photometric error on synthesized image while keeping NeRF model fixed. Use test-time photometric optimization in experiments where poses are refined, and also in experiments with fixed initial noisy poses for fairness [S6].

### Histogram Matching for Parameter Optimization
A technique to determine parameters L0 and La by minimizing the difference between the histogram of the input photograph and the histogram of rendered example cloud volumes. Solve the nonlinear least square problem using a quasi-Newton method. $\arg \min_{L0, La} \Sigma(n=1 to nL) [h(Iph, n) - h(I(L0, La), n)]^2$, where nL is number of intensity levels, h(I, n) is the normalized n-th histogram of image I, and I(L0, La) is the rendered image of example volumes using L0 and La. L*0, L*a: The optimized parameters for L0 and La after minimization [S7].

### Combined Light and Volume Optimization
Apply volume optimization on the result of light optimization to better match desired appearance using the same target images. Light optimization is theoretically redundant if emission is allowed, but useful when volume properties must not change or emission is to be avoided. Light optimization has a more global character as each light source affects the entire volume, connecting appearance to the rest of the scene. Used for rapid preview with a single view without introducing high-frequency artifacts from low input image counts [S1].

## Operating characteristics
*   **Time Complexity:** Scales with the number of voxels, ray marching steps, and number of views. For 128^3 voxels, 256 ray marching steps, and 460K constraint pixels (2 views), the result is computed in less than two seconds. With 2.3M constraint pixels (10 views), computation takes seven seconds [S1].
*   **Memory Complexity:** Depends on the scene representation. Voxel grids require $O(V)$ memory where $V$ is the number of voxels. Neural networks require memory proportional to the number of parameters.
*   **Strengths:** Can reconstruct higher frequencies than light optimization because it modifies the volume locally [S1]. EgoNeRF does not need a coarse-to-fine reconstruction approach for robust optimization because the balanced feature grid guarantees a nearly uniform ray-grid hitting rate [S2].
*   **Limitations:** Insufficient views may induce stripe patterns. Edges can appear between constrained and unconstrained regions. Emission-only or albedo-only optimization cannot perfectly match desired appearance [S1].
*   **When to Use:** When high-frequency details need to be reconstructed, or when specific volume properties (like albedo or emission) need to be stylized or corrected [S1].
*   **When Not to Use:** When only global lighting changes are needed, or when volume properties must remain unchanged [S1].

## Background
Photometric optimization for volume rendering was introduced in the context of volume stylization and property manipulation. The method was proposed by [S1] for static volume stylization using a painting metaphor, allowing users to modify albedo, emission, and extinction to match target images. It has since been applied to various domains, including cloud synthesis [S7], egocentric view synthesis [S2], dynamic scene representation [S5], and inverse rendering [S3].
