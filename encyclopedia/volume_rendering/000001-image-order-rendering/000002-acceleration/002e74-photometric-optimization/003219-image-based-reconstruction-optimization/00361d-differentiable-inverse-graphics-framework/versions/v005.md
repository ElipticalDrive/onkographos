# Differentiable Inverse Graphics Framework

Also called: Analysis-by-synthesis with differentiable rendering, Differentiable Inverse Rendering for Joint Reconstruction, End-to-end differentiable inverse graphics, Inverse parameter optimization pipeline, Joint geometry and reflectance reconstruction

## Overview
The Differentiable Inverse Graphics Framework simultaneously reconstructs 3D geometry, diffuse/specular reflectance, and environment lighting from multi-view photography by minimizing photometric error in a differentiable rendering pipeline [S1, S2, unofficial]. It sets itself apart from its siblings by explicitly alternating the optimization of discrete parameter sets (geometry, diffuse, specular, lighting) to manage GPU memory constraints, while relying on a physically-based Monte Carlo path tracer (Mitsuba2) for the forward model [S1, unofficial]. Unlike [Inverse Rendering with Differentiable Ray Tracing](7478-inverse-rendering-with-differentiable-ray-tracing.md) which may focus on general ray tracing differentiability, or [Inverse Rendering with Shape Prior](7506-inverse-rendering-with-shape-prior.md) which emphasizes geometric priors, this framework focuses on the joint stochastic optimization of all intrinsic scene properties from uncontrolled environments [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of RGB images $I = \{I_k\}$ from arbitrary viewpoints $k=1 \dots K$.
*   **Output:** Optimized scene parameters $\theta = \{\theta_g, \theta_d, \theta_s, \theta_l\}$ representing geometry, diffuse reflectance, specular reflectance, and lighting, enabling novel view synthesis and relighting [S1, unofficial].

**Data Structures:**
The scene is represented by a parametric vector $\theta$ containing:
1.  **Geometry ($\theta_g$):** Set of 3D positions corresponding to mesh vertices $\{x_0, \dots, x_N\}$ [S1, unofficial].
2.  **Diffuse Reflectance ($\theta_d$):** Set of per-vertex color reflectances $\{\theta_d(x_0), \dots, \theta_d(x_N)\}$, where $\theta_d(x) \in \mathbb{R}^3$ [S1, unofficial].
3.  **Specular Reflectance ($\theta_s$):** Set of specular reflectance parameters (e.g., roughness $\alpha$) [S1, unofficial].
4.  **Lighting ($\theta_l$):** Set of isotropic point sources for environment lighting $\{l_0, l_1, \dots, l_M\}$, where $l_n$ is the intensity of the $n$-th light source [S1, unofficial].

**Algorithm:**
The method implements an analysis-by-synthesis loop. It initializes the virtual scene using Structure-from-Motion (Colmap) to roughly match real-world camera poses and geometry [S1, unofficial]. It then iteratively optimizes the parameters by minimizing the difference between observed images and rendered images [S2, unofficial].

1.  **Initialization:**
    *   Generate initial mesh vertices $\theta_g$ and camera poses using Colmap [S1, unofficial].
    *   Initialize lighting intensities $\theta_l$ (e.g., radiance 0.5) [S1, unofficial].
    *   Initialize diffuse colors $\theta_d$ and specular parameters $\theta_s$ [S1, unofficial].
    *   Compute binary masks $M_k$ for each view using GrabCut segmentation to exclude background [S1, unofficial].

2.  **Forward Rendering:**
    *   For each viewpoint $k$, render the synthetic image $\hat{I}_k$ using the differentiable renderer $\Phi(\theta_g, \theta_d, \theta_s, \theta_l)$ [S1, unofficial].
    *   The renderer simulates light transport via path tracing. The radiance $L_o$ at a point $x$ in direction $\omega_o$ is computed via the rendering equation [S2, unofficial]:
        $$ L_o(x, \boldsymbol{\omega}_o) = L_e(x, \boldsymbol{\omega}_o) + \int_{\Omega} f_r(x, \boldsymbol{\omega}_i, \boldsymbol{\omega}_o) L_i(x, \boldsymbol{\omega}_i) (n \cdot \boldsymbol{\omega}_i) d\boldsymbol{\omega}_i $$
        where $L_e$ is emitted radiance, $f_r$ is the BRDF, $L_i$ is incoming radiance, $n$ is the surface normal, and $\Omega$ is the hemisphere of incoming directions [S2, unofficial].
    *   The final pixel value $I(u)$ for image coordinate $u$ is scaled by exposure time $\Delta t$ [S1, unofficial]:
        $$ I(u) = L(\omega_o; x) \Delta t $$
    *   Parameters: Maximum ray bounces $T=3$, samples per pixel $spp=1$ during optimization [S1, unofficial].

3.  **Loss Calculation:**
    *   Compute the photometric loss $\mathcal{O}$ between the masked observed image $M_k I_k$ and the rendered image $\Phi_k(\theta)$ [S1, unofficial]:
        $$ \mathcal{O} = \sum_{k=1}^K \| M_k I_k - \Phi_k(\theta_g, \theta_d, \theta_s, \theta_l) \|_2^2 $$
    *   General loss formulation includes regularization terms [S2, unofficial]:
        $$ \mathcal{L}(\theta) = \| I_{\text{obs}} - R(\theta) \|^2 + \lambda_{g}\, \text{GeomReg}(\theta) + \lambda_{m}\, \text{MatReg}(\theta) + \dots $$

4.  **Alternating Optimization:**
    *   Due to limited GPU memory, the framework alternates updates of parameter subsets $\theta \in \{\theta_d, \theta_g, \theta_s, \theta_l\}$ while keeping others fixed [S1, unofficial].
    *   For the active subset, compute gradients via backpropagation through the differentiable renderer [S1, unofficial].
    *   Update parameters using the Adam optimizer [S1, unofficial].
    *   Repeat for a maximum of 400 iterations per viewpoint [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.optim as optim

def differentiable_inverse_graphics(images, masks, colmap_mesh, colmap_poses):
    """
    Reconstructs geometry, reflectance, and lighting from multi-view images.
    
    Args:
        images: List of RGB images I_k.
        masks: List of binary masks M_k from GrabCut.
        colmap_mesh: Initial mesh vertices from Colmap.
        colmap_poses: Initial camera poses from Colmap.
        
    Returns:
        Optimized parameters theta_g, theta_d, theta_s, theta_l.
    """
    # 1. Initialize Parameters
    # theta_g: Mesh vertices (requires_grad=True for optimization)
    theta_g = torch.tensor(colmap_mesh.vertices, dtype=torch.float32, requires_grad=True)
    
    # theta_d: Diffuse per-vertex colors (R^3)
    theta_d = torch.ones(len(colmap_mesh.vertices), 3, dtype=torch.float32, requires_grad=True)
    
    # theta_s: Specular parameters (e.g., roughness alpha)
    alpha = torch.tensor(0.1, dtype=torch.float32, requires_grad=True) # Surface roughness [S1, unofficial]
    
    # theta_l: Lighting intensities (isotropic point sources)
    # Initialize with 0.5 as per [S1, unofficial]
    theta_l = torch.ones(1, dtype=torch.float32, requires_grad=True) * 0.5 
    
    # 2. Setup Optimizer
    # Note: Adam is used [S1, unofficial]. Learning rates are specified in [S1, unofficial] as lambda_d=0.1, lambda_g=0.5, etc.
    # In practice, these are often handled via optimizer parameter groups or separate optimizers.
    optimizer = optim.Adam([
        {'params': theta_g, 'lr': 0.5},
        {'params': theta_d, 'lr': 0.1},
        {'params': alpha, 'lr': 0.01},
        {'params': theta_l, 'lr': 0.05}
    ])
    
    # 3. Optimization Loop
    num_iterations = 400 # [S1, unofficial]
    max_bounces = 3      # [S1, unofficial]
    spp = 1              # Samples per pixel during optimization [S1, unofficial]
    
    for iteration in range(num_iterations):
        total_loss = 0.0
        
        # Alternate optimization: Update one parameter set at a time to save memory [S1, unofficial]
        # In a simplified implementation, we might update all, but the source specifies alternation.
        # Here we demonstrate the full gradient step for clarity, noting the alternation constraint [S1, unofficial].
        
        optimizer.zero_grad()
        
        for k, (img, mask) in enumerate(zip(images, masks)):
            # Forward Render
            # R(theta) calls the differentiable renderer (e.g., Mitsuba2)
            # Inputs: theta_g, theta_d, alpha, theta_l, camera_poses[k]
            rendered_img = differentiable_renderer(
                vertices=theta_g,
                colors=theta_d,
                roughness=alpha,
                lighting=theta_l,
                camera_poses=colmap_poses[k],
                max_bounces=max_bounces,
                spp=spp
            )
            
            # Apply Mask to remove background contribution [S1, unofficial]
            masked_rendered = rendered_img * mask
            masked_observed = img * mask
            
            # Compute L2 Loss
            loss = torch.mean((masked_rendered - masked_observed) ** 2)
            total_loss += loss
            
        # Backward Pass
        total_loss.backward()
        
        # Step
        optimizer.step()
        
        if iteration % 100 == 0:
            print(f"Iteration {iteration}, Loss: {total_loss.item()}")
            
    return theta_g, theta_d, alpha, theta_l
```

**Edge Cases and Pitfalls:**
*   **Background Dominance:** Background pixels can dominate the objective value. This is mitigated by using precomputed binary masks $M_k$ generated by GrabCut segmentation [S1, unofficial].
*   **GPU Memory:** The physically-based rendering is GPU memory-intensive. The solution is to alternate parameter updates and downsample raw images 8x during optimization [S1, unofficial].
*   **Visibility Discontinuities:** Silhouette edges cause gradient issues. These are handled by MC edge sampling, area-sampling, or thin-band relaxed indicators [S2, unofficial].
*   **Precision:** The method uses standard floating-point arithmetic. The exposure time $\Delta t$ must be known or estimated [S1, unofficial].

## Subtopics

### [Differentiable Re-rendering Module](14687-differentiable-re-rendering-module.md)
A raytracing-based differentiable renderer using Volumetric Spherical Gaussian (VSG) lighting and predicted intrinsic properties to enforce energy conservation. It sets itself apart by enabling the estimation of a complete continuous light field function from LDR images.

### [Physically Based Differentiable Rendering](14937-physically-based-differentiable-rendering.md)
A rendering approach that differentiates through physically based integrators like path tracing to preserve derivatives of light transport. It sets itself apart from rasterization-based methods by preserving physical accuracy for complex material and lighting optimization.

### [Differentiable Uncalibrated Imaging Framework](15690-differentiable-uncalibrated-imaging-framework.md)
Addresses image reconstruction under uncertain measurement coordinates by jointly optimizing a continuous measurement representation and the coordinates. It sets itself apart by avoiding fine-tuning or distributional tradeoffs required by other methods.

### Neural Programmatic Scene Code Pipeline
A pipeline where an image is encoded into a discrete scene program (geometry, materials, arrangements) via an encoder and LLM/programmatic decoder, which is then rendered by any downstream renderer [S2, unofficial]. It sets itself apart by training purely on code or numeric losses rather than image losses, allowing the discrete scene program to be optimized [S2, unofficial]. The pipeline flow is $I \xrightarrow{\Phi} E \xrightarrow{f_\theta} (s_1, ..., s_N) \xrightarrow{h} S$, where $I$ is the input image, $E$ is the encoded representation, $f_\theta$ generates scene tokens/parameters $s_i$, and $h$ renders the scene program $S$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The method runs approximately 140ms per iteration [S1, unofficial]. Total iterations are 400 per viewpoint [S1, unofficial].
*   **Memory Complexity:** High GPU memory usage due to physically-based rendering. Mitigated by alternating parameter updates and downsampling images 8x [S1, unofficial].
*   **Measured Performance:** Physics-based MC approaches achieve low reconstruction errors (RE $\approx$ 0.0087 vs Mitsuba's 0.0102) and normal MAE of 9.81° with sparse Gaussian basis [S2, unofficial]. Point-based splatting and hybrid methods achieve PSNR 38–43 dB and normal MAE $\approx$ 4–11° [S2, unofficial].
*   **Strengths:** Enables photo-realistic novel view synthesis, environment light editing, and joint reconstruction of geometry and reflectance in uncontrolled environments [S1, unofficial].
*   **Limitations:** Limited by GPU memory, requiring stochastic/alternating optimization. Performance may degrade on extremely high-genus shapes or strongly non-Lambertian surfaces if not properly regularized [S2, unofficial].
*   **When to Use:** When high-fidelity reconstruction of geometry, materials, and lighting is required from multi-view photography, and computational resources allow for iterative optimization.
*   **When Not to Use:** When real-time performance is required, or when camera calibration is highly uncertain without additional uncalibrated framework components [S2, unofficial].

## Background
The Differentiable Inverse Graphics Framework originates from the work of Li et al. (2021), titled "Shape and Reflectance Reconstruction in Uncontrolled Environments by Differentiable Rendering" [S1, unofficial]. It builds on the principles of differentiable rendering introduced in earlier works and implements the analysis-by-synthesis paradigm within a physically-based rendering engine (Mitsuba2) [S1, unofficial]. The framework addresses the challenge of simultaneous reconstruction of geometry and reflectance in uncontrolled environments, a problem previously difficult due to the ill-posed nature of inverse rendering [S1, unofficial]. It has been cited and expanded upon in broader surveys of end-to-end differentiable inverse graphics frameworks [S2, unofficial].
