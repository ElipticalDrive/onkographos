# LockSampleDistanceToInputSpacing

Also called: LockSampleDistanceToInputSpacing Correction, Sampling distance equalization

## Overview
LockSampleDistanceToInputSpacing is a correction technique used in volume rendering mappers to equalize the ray sampling distance between CPU and GPU implementations, thereby reducing visible sampling seams in parallel or hybrid rendering pipelines [S1, unofficial]. It addresses the discrepancy where CPU mappers (e.g., `vtkFixedPointVolumeRayCastMapper`) previously used a finer sampling distance than GPU mappers, causing artifacts to become more evident when switching to or comparing with GPU rendering [S1, unofficial]. By enforcing a consistent, input-spacing-based sample distance, it ensures visual continuity across different rendering backends [S1, unofficial].

## How it works
The method modifies the ray marching step size calculation in the volume mapper to lock the sampling distance to the input data's physical spacing, rather than using a heuristic or fixed value that might differ between CPU and GPU paths [S1, unofficial].

**Inputs and Outputs:**
- **Input:** Volume dataset with defined voxel spacing (physical dimensions per voxel) [S1, unofficial].
- **Output:** A ray sampling distance value used during front-to-back compositing [S1, unofficial].

**Data Structures:**
- The volume data structure contains spacing information (e.g., `spacing[0]`, `spacing[1]`, `spacing[2]` in VTK) [S1, unofficial].
- The mapper maintains an internal mode flag `LockSampleDistanceToInputSpacing` [S1, unofficial].

**Steps:**
1. **Enable Mode:** The GPU mapper (e.g., `vtkSmartVolumeMapper` or `GPUMapper`) enables the internal mode `LockSampleDistanceToInputSpacing` [S1, unofficial].
2. **Calculate Distance:** The sampling distance is derived from the input volume's spacing or the active texture grid's spacing [S1, unofficial][S2, unofficial].
3. **Apply Step:** The calculated distance is passed to the ray marching loop as the step size $\Delta s$ [S1, unofficial].

**Formulas:**
Let $s_i$ be the voxel spacing along each axis $i \in \{x, y, z\}$. The sampling distance $d_{sample}$ is calculated as half the mean voxel side of the active grid:
$$ d_{sample} = 0.5 \times \frac{1}{3} \sum_{i=1}^{3} s_i $$
The distance is constrained to never fall below the volume diagonal divided by the maximum allowed samples per ray:
$$ d_{min} = \frac{\sqrt{s_x^2 + s_y^2 + s_z^2}}{MAXIMUM\_SAMPLES\_PER\_RAY} $$
$$ d_{sample} = \max(d_{sample}, d_{min}) $$

**Parameters:**
- `LockSampleDistanceToInputSpacing`: Boolean flag, default `false` in older versions, `true` in corrected versions [S1, unofficial].
- `MAXIMUM_SAMPLES_PER_RAY`: Constant set to 4000, used as the divisor for the minimum sample distance calculation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Block-Edge Seams:** Even after enabling this correction, seams may remain visible at block-edge planes in parallel rendering scenarios, indicating that equalizing sample distance alone is insufficient for all artifacts [S1, unofficial].
- **Point vs. Cell Data:** When using point data, a transformation is required to align points with texture cell centers [S1, unofficial]. If the ray step is not scaled accordingly with this transformation, errors persist [S1, unofficial].
- **Excessive Sample Counts:** Using half the mean voxel side of the full-resolution volume for long series can cause the sample count to exceed the 4000 limit (e.g., ~5575 samples), triggering warnings and degrading performance [S2, unofficial]. The fix is to use the active grid's spacing instead [S2, unofficial].

**Pseudocode:**
```python
def compute_sampling_distance(volume_spacing, grid_spacing=None, use_lock_mode=True, max_samples_per_ray=4000):
    """
    Computes the ray sampling distance based on volume/grid spacing and lock mode.
    
    Args:
        volume_spacing: tuple or list of 3 floats (dx, dy, dz) for the full volume.
        grid_spacing: tuple or list of 3 floats for the active texture grid (optional).
        use_lock_mode: bool, enables LockSampleDistanceToInputSpacing.
        max_samples_per_ray: int, maximum allowed samples per ray.
        
    Returns:
        float: The sampling distance.
    """
    if not use_lock_mode:
        # Default behavior not specified in the sources [G]
        return 0.0

    # Use grid spacing if available, otherwise fall back to volume spacing [S2, unofficial]
    spacing = grid_spacing if grid_spacing is not None else volume_spacing
    
    # Calculate half the mean voxel side of the active grid [S2, unofficial]
    mean_side = sum(spacing) / len(spacing)
    sample_distance = 0.5 * mean_side

    # Enforce maximum samples per ray constraint [S2, unofficial]
    volume_diagonal = (volume_spacing[0]**2 + volume_spacing[1]**2 + volume_spacing[2]**2)**0.5
    min_distance = volume_diagonal / max_samples_per_ray
    
    # Distance never falls below the calculated minimum [S2, unofficial]
    if sample_distance < min_distance:
        sample_distance = min_distance

    return sample_distance
```

## Subtopics

### Grid-Aware Sample Distance Calculation
A method used in streaming or multi-resolution volume rendering (e.g., in `vtk.js`) to compute the ray sampling distance based on the active texture grid rather than the full-resolution volume [S2, unofficial]. This prevents excessive sample counts and performance degradation when rendering reduced-resolution textures [S2, unofficial].
- **Definition:** The sample distance is calculated as half the mean voxel side of the grid that the current texture holds [S2, unofficial].
- **Rationale:** A reduced texture has a larger spacing, and using a finer sample (based on full resolution) adds no detail [S2, unofficial].
- **Constraint:** The distance never falls below the diagonal of the volume divided by 4000, capping the maximum samples per ray at 4000 [S2, unofficial].
- **Pitfall:** Using half the mean voxel side of the *full-resolution* volume for long series can cause the sample count to exceed the 4000 limit (e.g., ~5575 samples), triggering warnings and potentially degrading performance [S2, unofficial]. The fix is to use the grid's spacing instead [S2, unofficial].
- **Parameter:** `MAXIMUM_SAMPLES_PER_RAY` is set to 4000 [S2, unofficial].

## Operating characteristics
- **Visual Quality:** Reduces sampling seams between CPU and GPU mappers by equalizing sample density [S1, unofficial]. However, it does not eliminate seams at block-edge planes in parallel rendering [S1, unofficial].
- **Performance:** By locking the sample distance to input spacing, it ensures consistent computational load across different mappers [S1, unofficial]. The grid-aware variant prevents excessive sample counts, improving performance for large or multi-resolution volumes [S2, unofficial].

## Background
The technique was introduced in ParaView 5.2 (OpenGL2) to correct discrepancies between the `vtkFixedPointVolumeRayCastMapper` (CPU) and the GPU mapper [S1, unofficial]. The CPU mapper had an internal mode `LockSampleDistanceToInputSpacing` that decreased the sampling distance, making artifacts more evident in the GPU mapper; enabling this mode in the GPU mapper corrected the issue [S1, unofficial]. A variant, Grid-Aware Sample Distance Calculation, was implemented in `vtk.js` to handle multi-resolution streaming volumes [S2, unofficial].
