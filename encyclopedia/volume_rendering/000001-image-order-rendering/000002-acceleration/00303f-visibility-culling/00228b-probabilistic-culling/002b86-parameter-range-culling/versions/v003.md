# Parameter Range Culling

Also called: PIC culling, Run Time Parameter Range Culling

## Overview
Parameter Range Culling is a runtime visibility optimization that isolates particle subsets by culling particles whose scalar parameter values do not overlap a user-defined valid range [S1]. It sets itself apart from static culling by performing these checks dynamically during traversal, allowing for interactive exploration of simulation data without pre-processing [S1]. Builds on [Probabilistic Culling](2833-probabilistic-culling.md), which justifies intersection tests with false-negatives during rendering to reduce duplicated fragments and rendering times, particularly in VR [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A macrocell hierarchy of particle packets, where each macrocell stores the minimum and maximum values of a specific scalar parameter for all contained particles, alongside a user-defined valid range $[R_{min}, R_{max}]$ [S1].
*   **Output:** A subset of particles satisfying the range constraint, which reduces the number of ray/sphere intersection tests performed [S1].

**Data Structures:**
*   **Macrocell:** Contains bounding geometry for the particle packet and two scalar fields, $P_{min}$ and $P_{max}$, representing the minimum and maximum parameter values of all particles within that macrocell [S1].

**Steps:**
1.  **Macrocell-Level Culling:** During traversal of the macrocell hierarchy, compare the macrocell's stored range $[P_{min}, P_{max}]$ against the user-defined valid range $[R_{min}, R_{max}]$ [S1].
    *   If the intervals do not overlap, defined by the condition $P_{max} < R_{min} \lor P_{min} > R_{max}$, the macrocell is skipped entirely [S1].
    *   This check is amortized over the number of particles in the macrocell, making it significantly cheaper than individual intersection tests [S1].
2.  **Particle-Level Culling:** If the macrocell's range overlaps with the valid range, traverse the individual particles within the macrocell [S1].
    *   For each particle, check if its specific parameter value $p$ lies within $[R_{min}, R_{max}]$ [S1].
    *   Only perform the ray/sphere intersection test if $R_{min} \le p \le R_{max}$ [S1].

**Pseudocode:**
```python
def parameter_range_culling(macrocell, ray, r_min, r_max):
    # Step 1: Macrocell-level culling
    if macrocell.p_max < r_min or macrocell.p_min > r_max:
        return []  # Macrocell range does not overlap valid range
    # Step 2: Particle-level culling
    valid_particles = []
    for particle in macrocell.particles:
        if r_min <= particle.parameter_value <= r_max:
            # Ray-sphere intersection test is performed here [G]
            valid_particles.append(particle)
    return valid_particles
```

**Parameters:**
*   $R_{min}, R_{max}$: User-defined bounds for the scalar parameter [S1].
*   Typical values: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **SIMD Overhead:** Efficient SIMD implementation of range checking operations adds computational overhead, specifically requiring 16 SIMD operations to implement macrocell and particle range checking [S1].
*   **Performance Degradation:** This overhead decreases performance by a factor of 1.38–2.28 compared to preprocessed versions of the data [S1].
*   **Grid Bounds:** Some performance difference is attributed to grid bounds, where smaller bounds lead to fewer packet traversals [S1].

## Operating characteristics
*   **Time Complexity:** The macrocell check is $O(1)$ per macrocell and amortized over the contained particles [S1]. The particle check is $O(N)$ for $N$ particles in the macrocell, but reduces the constant factor by skipping intersection tests for out-of-range particles [S1].
*   **Memory Complexity:** Requires storing $P_{min}$ and $P_{max}$ per macrocell [S1].
*   **Measured Performance:** On the Thunder dataset, parameter range culling reduces total processing time by 43.00%, with a mean culling rate of 14.23% and a max culling rate of 43.06% [S1]. On the BulletTorso dataset, it reduces total processing time by 34.17%, with a mean culling rate of 3.17% and a max culling rate of 11.18% [S1].
*   **Strengths:** Provides flexibility for data analysis by allowing dynamic isolation of particle subsets without pre-processing [S1].
*   **Limitations:** The runtime overhead of SIMD range checks can degrade interactive performance compared to static preprocessed data [S1].
*   **When to use:** It is used when interactive exploration of simulation data based on scalar parameters (e.g., temperature, velocity) is required [S1].

## Background
*   **Origin:** The method was introduced in "A Coherent Grid Traversal Approach to Visualizing Particle Data" by Thiago Ize et al. [S1].
*   **History:** It was developed as part of the Particle Coherent Grid Traversal (PCGT) framework to support interactive visualization of large-scale particle simulations [S1].
*   **Usage:** It is used in scientific visualization for analyzing particle-based simulations, such as fluid dynamics or astrophysical data, where researchers need to filter particles based on physical properties [S1].
