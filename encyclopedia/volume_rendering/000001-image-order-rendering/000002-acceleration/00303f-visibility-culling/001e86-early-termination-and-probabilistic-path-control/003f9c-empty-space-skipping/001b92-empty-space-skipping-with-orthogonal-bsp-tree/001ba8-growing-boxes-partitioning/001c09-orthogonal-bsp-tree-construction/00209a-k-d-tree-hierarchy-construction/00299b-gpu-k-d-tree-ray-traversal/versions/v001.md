# GPU K-D Tree Ray Traversal

Also called: K-D Tree GPU Traversal, Kd-Tree, Kd-Tree Ray Tracing on GPU

## Overview
GPU K-D Tree Ray Traversal is the process of intersecting rays with a hierarchical spatial partitioning structure (a K-D tree) to accelerate ray tracing on graphics hardware. It solves the problem of efficiently skipping empty space and determining which primitives a ray intersects, avoiding the computational cost of testing every primitive in the scene. It is distinguished from CPU implementations by its adaptation to GPU architectures, specifically addressing the lack of dynamic branching in early generations (Shader Model 2.0) via stackless multi-pass algorithms, and later leveraging dynamic branching in Shader Model 3.0 for single-pass traversal. It builds on [K-D Tree Hierarchy Construction](2300-k-d-tree-hierarchy-construction.md).

## How it works
The K-D tree is a hierarchical spatial partitioning structure where each node is divided into two sub-nodes by a plane orthogonal to an axis, positioned arbitrarily along that axis within the node [S1, unofficial]. It is a special case of a BSP-Tree [S1, unofficial].

### Inputs and Outputs
- **Input**: A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a K-D tree structure where each node contains a split axis, split position, and references to left/right children or leaf primitives.
- **Output**: The closest intersection point or hit primitive along the ray.

### Data Structures
The tree nodes are typically stored in a flat array. Each node contains:
- `axis`: The dimension (0, 1, or 2) along which the split occurs.
- `split`: The position of the splitting plane along the specified axis.
- `left`: Index of the left child node.
- `right`: Index of the right child node.
- `primitive`: (For leaves) Index of the primitive(s) contained in this leaf.

### Traversal Methods

#### 1. Stackless Multi-Pass (Foley and Sugerman [FS05])
Proposed for Shader Model 2.0 GPUs which do not allow dynamic branching [S1, unofficial].
- **Concept**: Uses a pure streaming programming mode. A dedicated processing kernel is used for each traversal step. A multi-pass algorithm chains these kernels [S1, unofficial].
- **Mechanism**: The traversal is unrolled into a fixed number of passes. In each pass, all active rays are processed. Rays that hit a leaf or exit the tree are marked as done. Rays that hit an internal node are updated to point to the next node to visit. This avoids the need for a stack but requires multiple passes through the shader code.
- **Pitfall**: Suffers from poor performance due to the inability to reuse previously calculated data efficiently and inefficient load balancing between steps [S1, unofficial].

#### 2. Single-Pass Dynamic Branching (Horn et al. [HSHH07])
Proposed for Shader Model 3.0 GPUs, improving upon Foley and Sugerman's method [S1, unofficial].
- **Concept**: Leverages dynamic branching (conditional structures and loops) in fragment shaders to provide a single-pass algorithm [S1, unofficial].
- **Mechanism**: A single shader invocation traverses the tree for each ray. The shader uses a loop to traverse from the root to a leaf. Inside the loop, conditional branches determine whether to go left or right based on the ray's position relative to the split plane.
- **Pitfall**: Does not significantly exceed CPU performance due to the penalty of dynamic branching on third-generation GPU architectures [S1, unofficial]. These GPUs remain largely SIMD, processing hundreds of fragments in flux. Divergent parts of the program (where some fragments take the left branch and others the right) must be serialized, causing strong performance penalties [S1, unofficial].

### Pseudocode (Single-Pass Dynamic Branching)

```python
def traverse_kd_tree(ray_origin, ray_direction, tree_nodes, max_depth):
    """
    Traverses a K-D tree for a single ray using dynamic branching.
    Assumes tree_nodes is an array of node structures.
    Returns the closest hit primitive index or -1 if no hit.
    """
    current_node = 0  # Start at root
    t_min = 0.0
    t_max = ray_max_distance  # Defined by ray context
    
    for step in range(max_depth):
        node = tree_nodes[current_node]
        
        # Check if leaf
        if node.is_leaf:
            # Intersect with primitives in this leaf
            hit_primitive = intersect_primitives(ray_origin, ray_direction, node.primitives, t_min, t_max)
            if hit_primitive != -1:
                return hit_primitive
            else:
                return -1
        
        # Determine which child to visit first
        # Calculate intersection with split plane
        split_axis = node.axis
        split_pos = node.split
        
        # Ray parameter to intersection with split plane
        # t = (split_pos - origin[axis]) / direction[axis]
        t_split = (split_pos - ray_origin[split_axis]) / ray_direction[split_axis]
        
        # Determine if ray origin is on the negative or positive side of the split plane
        if ray_origin[split_axis] < split_pos:
            # Ray starts on the negative side
            # Visit left child first
            if t_split < t_min:
                # Split plane is behind the near clip, go right
                current_node = node.right
            else:
                # Split plane is in front, go left
                current_node = node.left
                # Update t_max if split plane is closer than current t_max
                if t_split < t_max:
                    t_max = t_split
        else:
            # Ray starts on the positive side
            # Visit right child first
            if t_split < t_min:
                # Split plane is behind the near clip, go left
                current_node = node.left
            else:
                # Split plane is in front, go right
                current_node = node.right
                # Update t_max if split plane is closer than current t_max
                if t_split < t_max:
                    t_max = t_split
        
        # If t_max <= t_min, we have passed the region of interest
        if t_max <= t_min:
            return -1
            
    return -1
```

## Operating characteristics
- **Time Complexity**: $O(\log N)$ on average for balanced trees, where $N$ is the number of primitives. Worst case $O(N)$ for degenerate trees.
- **Memory Complexity**: $O(N)$ to store the tree nodes.
- **Performance**: Early GPU implementations (Foley and Sugerman) were slower than CPU counterparts due to streaming limitations [S1, unofficial]. Later implementations (Horn et al.) became competitive with CPU but were limited by SIMD divergence penalties on Shader Model 3.0 hardware [S1, unofficial].
- **Strengths**: Efficient empty-space skipping; flexible for arbitrary scenes [S1, unofficial].
- **Limitations**: Dynamic branching causes divergence penalties on SIMD GPUs; stackless methods require multiple passes or fixed-depth loops.

## Background
- **Origin**: The K-D tree was shown by Havran [Hav00] to be the most flexible and provide average best results for arbitrary scenes in CPU ray tracing.
- **History**: The first GPU ray tracing use of K-D trees was proposed by Ernst et al. [EVG04], using a stack and a heavy multi-pass algorithm, which did not achieve high performance. Foley and Sugerman [FS05] improved this with stackless multi-pass methods for Shader Model 2.0. Horn et al. [HSHH07] proposed the first efficient GPU method competitive with CPU implementations, using Shader Model 3.0 dynamic branching for a single-pass algorithm.
