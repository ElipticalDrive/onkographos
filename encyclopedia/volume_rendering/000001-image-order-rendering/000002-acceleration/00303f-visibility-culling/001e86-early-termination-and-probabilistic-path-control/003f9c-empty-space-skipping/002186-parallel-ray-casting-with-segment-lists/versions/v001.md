# Parallel Ray Casting with Segment Lists


## Overview
Parallel Ray Casting with Segment Lists is a volume rendering algorithm that distributes image rows across MPI ranks and OpenMP threads to accelerate ray casting [S1, unofficial]. It uses segment lists to skip empty space and calculates sampling points based on a step length derived from the sampling rate and volume dimensions [S1, unofficial]. It differs from [Parallel Image Compositing with Overlapping](3554-parallel-image-compositing-with-overlapping.md) by operating in image-order ray casting rather than object-order compositing, and from [Ray Compaction](4039-ray-compaction.md) by using explicit segment lists for empty space skipping rather than compacting active rays [S1, unofficial].

## How it works
**Inputs:**
- Image dimensions: `width`, `height`.
- Camera parameters: `cam_pos`, `ray_dir` (normalized), `aspect` ratio.
- Volume parameters: `dims` (3D dimensions), `sampling_rate` (typical value 1.0) [S1, unofficial].
- Configuration: `config::multi_threading` (bool), `config::core_count`, `config::core_thread_count`, `thread_nums` (default 4) [S1, unofficial].
- MPI environment: `comm_size` (number of ranks), `my_rank` (current rank) [S1, unofficial].

**Outputs:**
- Rendered image pixels.

**Data Structures:**
- `raytracer` struct fields: `m_start_x`, `m_start_y`, `m_end_x`, `m_end_y`, `m_width`, `m_height`, `m_depth`, `m_writer`, `m_threadId` [S2, unofficial].
- `seg_list`: List of segments, where each segment is a pair `(s_beg, s_end)` representing the entry and exit distances of the ray within the volume [S1, unofficial].
- `point_list`: List of sampling points along the ray [S1, unofficial].
- Block offsets: Precomputed offsets for MMU access, stored per brick [S1, unofficial].

**Steps:**

1. **Calculate step length:**
   $$ \text{step\_len} = \frac{1.0}{\text{sampling\_rate} \times \|\text{dims}\|} $$
   where $\|\text{dims}\|$ is the Euclidean norm of the volume dimensions [S1, unofficial].

2. **Determine job count:**
   If `config::multi_threading` is true, `jobs = config::core_count * config::core_thread_count`; else `jobs = 1` [S1, unofficial].

3. **Calculate row distribution:**
   $$ \text{line\_nums} = \lceil \frac{\text{height}}{\text{comm\_size}} \rceil $$
   $$ \text{t\_line\_nums} = \lceil \frac{\text{line\_nums}}{\text{thread\_nums}} \rceil $$
   where `thread_nums` is the number of OpenMP threads [S1, unofficial].

4. **Divide image height into jobs segments:**
   Each job processes rows from $i \times \frac{\text{height}}{\text{jobs}}$ to $(i+1) \times \frac{\text{height}}{\text{jobs}}$ [S1, unofficial].

5. **Precompute block offsets for MMU access:**
   Iterate over brick dimensions $(k, j, i)$. Get block. If block is null, offset is -1. Else offset is `block->data - buf_base` [S1, unofficial].

6. **Parallel region:**
   For each thread `t_id`, iterate over `t_line_nums`. Calculate row index:
   $$ \text{row} = \text{my\_rank} + (\text{t\_id} \times \text{t\_line\_nums} + i) \times \text{comm\_size} $$
   Break if `row >= height` [S1, unofficial].

7. **For each column `col`:**
   a. Calculate pixel coordinates:
      $$ u = \left(-0.5 + \frac{\text{col} + 0.5}{\text{width}}\right) \times \text{aspect} $$
      $$ v = -0.5 + \frac{\text{row} + 0.5}{\text{height}} $$
   b. Calculate `ray_dir` using `cal_ray_dir`. Normalize `ray_dir` [S1, unofficial].
   c. Get ray distance to volume bbox: `seg = volume->getRayDistance(cam_pos, ray_dir)` [S1, unofficial].
   d. Get segment list for this ray: `volume->getSegList(*seg_list, cam_pos, ray_dir)`. Clear `point_list` [S1, unofficial].
   e. Iterate over segments in `seg_list`. For each segment $(s\_beg, s\_end)$:
      i. Align $s\_beg$ to step grid:
         $$ s\_beg = \text{seg}.x + \left\lceil \frac{s\_beg - \text{seg}.x}{\text{step\_len}} \right\rceil \times \text{step\_len} $$
      ii. While $s\_beg \le s\_end$:
          - Push $s\_beg$ to `point_list`.
          - $s\_beg += \text{step\_len}$ [S1, unofficial].

**Parameters:**
- `sampling_rate`: Controls step length. Typical value 1.0 [S1, unofficial].
- `thread_nums`: Number of OpenMP threads. Default 4 [S1, unofficial].

**Edge cases and pitfalls:**
- Precision: Aligning $s\_beg$ to the step grid uses ceiling division, which may introduce small errors if `step_len` is not a power of two or if floating-point precision is limited [S1, unofficial].
- Boundaries: The row index calculation must ensure that `row` does not exceed `height` [S1, unofficial].
- Degenerate input: If `dims` is zero or `sampling_rate` is zero, `step_len` will be undefined or infinite [S1, unofficial].
