# VRI Ray Advancement


## Overview
VRI Ray Advancement is a hierarchical ray traversal method that advances a Volume Ray Intersection (VRI) state machine to the next leaf voxel intersection by managing a three-level hierarchy of I2 nodes, I1 nodes, and leaf voxels using Digital Differential Analyzer (DDA) stepping [S1, unofficial]. It differs from its parent [MultiDDA](3123-multidda.md) by explicitly separating the traversal into three distinct phases: draining the current I1 DDA for leaf hits, stepping the I2 DDA to find the next active I1 child, and advancing to the next pre-sorted root entry when the hierarchy is exhausted [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $O$ and direction $D$; a pre-sorted list of root entries `state.roots`, where each entry is a tuple $(t_{min}, \text{I2\_node})$; and the current `state` containing DDA iterators and node references for I2 and I1 levels.
*   **Output:** A `LeafIntersection` object containing $t_{enter}$, $t_{exit}$, and the leaf voxel reference, along with the updated `state`; or `nothing` if no further intersections exist.

**Data Structures:**
*   **I2 Node:** Represents a coarse block. Contains a `children` array of I1 nodes.
*   **I1 Node:** Represents a $8^3$ voxel sub-grid (brick). Contains a `child_mask` (bitmask indicating active children) and a `children` array of leaf voxels.
*   **Leaf Voxel:** The finest granularity.
*   **DDA State:** `state.i2_ndda`, `state.i1_ndda` store the current DDA iterators. `state.i2_node`, `state.i1_node` store the current node references. `state.root_idx` tracks the current root entry.

**Parameters:**
*   I1 brick size: $8^3$ voxels.
*   I2 node size: $128$ units (implied by $16 \times 8$).
*   Root block size: $32$ units (implied by DDA init).
*   Leaf voxel size: $1$ unit.

**Algorithm Steps:**

1.  **Phase 1: Drain Current I1 DDA for Leaf Hits.**
    While `state.i1_ndda` is not `nothing`:
    1.  Query the DDA: `(inside, child_idx) = node_dda_query(state.i1_ndda)`.
    2.  If `!inside`, break loop.
    3.  If `is_on(state.i1_node.child_mask, child_idx)`:
        a.  Calculate index: `idx = count_on_before(state.i1_node.child_mask, child_idx) + 1`.
        b.  Get leaf: `leaf = state.i1_node.children[idx]`.
        c.  Compute bounding box: `s = 8`. `bbox = BBox(O, Coord(O[1] + s - 1, O[2] + s - 1, O[3] + s - 1))`.
        d.  Intersect ray with `bbox`. If hit, return `(LeafIntersection(t_enter, t_exit, leaf), state)` and step `state.i1_ndda`.

2.  **Phase 2: Step I2 DDA to Find Next I1 Child.**
    If Phase 1 drained (or initially), set `state.i1_ndda = nothing` and `state.i1_node = nothing`.
    While `state.i2_ndda` is not `nothing`:
    1.  Query the DDA: `(inside, child_idx) = node_dda_query(state.i2_ndda)`.
    2.  If `inside` and `is_on(state.i2_node.child_mask, child_idx)`:
        a.  Get I1 node: `i1_node = state.i2_node.children[child_idx]`.
        b.  Compute AABB: `aabb` from $O$ to $O + 128.0$.
        c.  Intersect ray with `aabb` to get $t_{min}$.
        d.  Initialize I1 DDA: `state.i1_ndda = node_dda_init(ray, t_min, O, 16, 8)`.
        e.  Set `state.i1_node = i1_node`.
        f.  Step `state.i2_ndda`.
        g.  Set `found_i1 = true` and break loop.

3.  **Phase 3: Advance to Next Pre-Sorted Root Entry.**
    If no I1 was found in Phase 2:
    1.  Set `state.i2_ndda = nothing` and `state.i2_node = nothing`.
    2.  Increment `state.root_idx`.
    3.  If `state.root_idx > length(state.roots)`, return `nothing`.
    4.  Get next root: `(t_min, i2_node) = state.roots[state.root_idx]`.
    5.  Initialize I2 DDA: `state.i2_ndda = node_dda_init(ray, t_min, O, 32, 128)`.
    6.  Set `state.i2_node = i2_node`.
    7.  Loop back to Phase 1.

**Pseudocode:**

```python
def vri_advance(state, ray, roots):
    """
    Advances VRI state to next leaf intersection.
    state: object with fields i1_ndda, i1_node, i2_ndda, i2_node, root_idx
    ray: object with origin O and direction D
    roots: list of (t_min, i2_node) tuples, pre-sorted by t_min
    """
    # Phase 1: Drain current I1 DDA
    while state.i1_ndda is not None:
        inside, child_idx = node_dda_query(state.i1_ndda)
        if not inside:
            break
        
        if is_on(state.i1_node.child_mask, child_idx):
            idx = count_on_before(state.i1_node.child_mask, child_idx) + 1
            leaf = state.i1_node.children[idx]
            
            # Leaf bbox: 8x8x8 voxel block
            s = 8
            bbox_min = state.i1_node.origin # Assumed field for bbox calculation context
            # Note: Source uses O (ray origin) for bbox calculation in a specific way.
            # Re-reading source: `bbox = BBox(o, Coord(o[1] + s - 1, ...))`
            # This implies the bbox is relative to the ray origin or a specific coordinate frame.
            # However, standard DDA usually uses node-local or world coords.
            # The source snippet: `bbox = BBox(o, Coord(o[1] + s - 1, o[2] + s - 1, o[3] + s - 1))`
            # This looks like a local block bbox if 'o' is the block origin.
            # Let's assume 'o' in the source refers to the current node's origin or the ray origin?
            # Context: "Intersect ray with bbox". If 'o' is ray origin, this bbox is tiny and likely wrong for world space.
            # In Lyr.jl, 'o' often denotes origin. In the DDA query context, it might be the current voxel origin.
            # Given the ambiguity, we stick to the source formula literally but note 'o' is likely the current voxel/block origin.
            # For implementation, 'o' is typically the origin of the current leaf voxel being traversed.
            # Let's assume 'o' is the origin of the current leaf voxel.
            o = leaf.origin 
            bbox = BBox(o, Coord(o[1] + s - 1, o[2] + s - 1, o[3] + s - 1))
            
            t_enter, t_exit = intersect_ray_bbox(ray, bbox)
            if t_enter is not None:
                return LeafIntersection(t_enter, t_exit, leaf), state
            
            step_dda(state.i1_ndda)

    # Phase 2: Step I2 DDA to find next I1 child
    if state.i1_ndda is None:
        state.i1_ndda = None
        state.i1_node = None
        
    while state.i2_ndda is not None:
        inside, child_idx = node_dda_query(state.i2_ndda)
        
        if inside and is_on(state.i2_node.child_mask, child_idx):
            i1_node = state.i2_node.children[child_idx]
            
            # Compute AABB for I2 child (128x128x128 block)
            # Source: `aabb` from `o` to `o + 128.0`
            # Again, 'o' is likely the origin of the I2 node or the current position.
            # Assuming 'o' is the origin of the I2 node.
            o = state.i2_node.origin
            aabb = BBox(o, Coord(o[1] + 128.0, o[2] + 128.0, o[3] + 128.0))
            
            t_min = intersect_ray_aabb(ray, aabb)
            
            if t_min is not None:
                # Initialize I1 DDA: 16 steps, 8x8x8 voxels
                state.i1_ndda = node_dda_init(ray, t_min, o, 16, 8)
                state.i1_node = i1_node
                step_dda(state.i2_ndda)
                return vri_advance(state, ray, roots) # Recurse to Phase 1 for the new I1

    # Phase 3: Advance to next pre-sorted root entry
    if state.i2_ndda is None:
        state.i2_ndda = None
        state.i2_node = None
        
    state.root_idx += 1
    
    if state.root_idx > len(roots):
        return None, state
    
    t_min, i2_node = roots[state.root_idx]
    
    # Initialize I2 DDA: 32 steps, 128x128x128 blocks
    # 'o' here is likely the global origin or the start of the root block
    o = roots[0][1].origin # Assumption: all roots share a common origin reference or 'o' is global 0
    # Actually, roots are pre-sorted. The origin 'o' in DDA init usually refers to the start of the traversal range.
    # Let's assume 'o' is the origin of the current root block.
    # Since roots are sorted by t_min, the origin might vary or be fixed.
    # Standard DDA init: `node_dda_init(ray, t_min, o, steps, size)`
    # We assume 'o' is the origin of the I2 node being entered.
    state.i2_ndda = node_dda_init(ray, t_min, i2_node.origin, 32, 128)
    state.i2_node = i2_node
    
    return vri_advance(state, ray, roots) # Recurse to Phase 1
```

**Edge Cases and Pitfalls:**
*   **Precision:** DDA stepping can suffer from floating-point precision errors at large distances. Use double precision for DDA coordinates if necessary [G].
*   **Boundaries:** Ensure `intersect_ray_bbox` and `intersect_ray_aabb` handle edge cases where the ray is parallel to a face or originates inside the volume [G].
*   **Degenerate Input:** If `roots` is empty, the method should immediately return `nothing` [G].
*   **Mask Handling:** `is_on` and `count_on_before` must correctly handle the bitmasks. `child_idx` is the linear index in the DDA, not the bit position.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of leaf voxels intersected, but with a significantly reduced constant factor due to skipping empty space at multiple levels. The hierarchical DDA allows skipping large empty regions in $O(1)$ per level hop.
*   **Memory Complexity:** $O(M)$ where $M$ is the size of the hierarchical grid (I2 and I1 nodes). The state machine uses minimal additional memory.
*   **Performance:** Designed for GPU execution (CUDA/JULIA KernelAbstractions) [S1, unofficial]. Outperforms flat DDA in sparse volumes.
*   **Strengths:** Efficient empty-space skipping; leverages pre-sorted root entries for coherent traversal.
*   **Limitations:** Requires a pre-built hierarchical grid; overhead of managing multiple DDA states.

## Background
VRI Ray Advancement is part of the Lyr.jl volume rendering engine, developed by Tobias Osborne [S1, unofficial]. It is designed to compete with other high-performance volume rendering phases (C: device-cache, D: fused-spp, E: CuTexture) [S1, unofficial]. The method is used in the `gpu_render_volume` phase of the engine [S1, unofficial].
