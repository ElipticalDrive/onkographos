# Homogeneity Acceleration

Also called: Denskin-Hanrahan acceleration, Range pyramid traversal

## Overview
Homogeneity acceleration is an image-order volume rendering technique that extends empty-space skipping by approximating the contribution of uniform, non-empty regions instead of sampling them voxel-by-voxel [S1, unofficial][S2, unofficial]. It distinguishes itself from its sibling [Empty-space skipping](1002-empty-space-skipping.md) by handling regions that contain data but lack internal variation, thereby reducing computational load where presence acceleration alone would still require per-sample evaluation [S1, unofficial][S2, unofficial].

## How it works
**Inputs:** A scalar volume dataset and a set of rays cast from the image plane into the volume [G].
**Outputs:** The final color and opacity for each pixel [G].

**Data Structures:**
The method relies on a range pyramid, a hierarchical data structure built over the volume [S1, unofficial][S2, unofficial]. Unlike the binary pyramids used in presence acceleration, each node in the range pyramid stores two values: the minimum scalar value and the maximum scalar value found in the subvolume covered by the node [S1, unofficial][S2, unofficial]. The pyramid is constructed such that each level contains the maximum and minimum values of the subvolumes at the level immediately below it [S1, unofficial][S2, unofficial].

**Algorithm Steps:**
1. Construct the range pyramid containing the maximum and minimum values of subvolumes at the level below [S2, unofficial].
2. For each ray, traverse the range pyramid from the root to the leaves [G].
3. At each node visited, compare the stored minimum and maximum values [S1, unofficial][S2, unofficial].
4. If the maximum and minimum values of a cell are nearly the same, the region is considered homogeneous and an approximate evaluation is performed instead of detailed sampling [S1, unofficial][S2, unofficial].
5. If the values differ significantly, the region is heterogeneous; descend to its children and repeat the check [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
def build_range_pyramid(volume):
    # Leaf level: min and max are the scalar value of each voxel [G]
    pyramid = [level for level in volume]
    for level in reversed(pyramid[:-1]):
        for node in level:
            node.min = min(child.min for child in node.children)
            node.max = max(child.max for child in node.children)
    return pyramid

def render_ray(ray, pyramid, epsilon):
    node = pyramid[0]
    accumulated_color = 0.0
    accumulated_opacity = 0.0
    while node is not None:
        if node.max - node.min < epsilon:
            # Homogeneous region: perform approximate evaluation [S1, unofficial][S2, unofficial]
            # The exact representative value and compositing formula are not given in the sources [G]
            representative_value = (node.min + node.max) / 2.0
            color, opacity = evaluate_transfer_function(representative_value, ray)
            accumulated_color += color * (1.0 - accumulated_opacity)
            accumulated_opacity += opacity * (1.0 - accumulated_opacity)
            break
        else:
            # Heterogeneous region: descend to children [S1, unofficial][S2, unofficial]
            if node.children:
                node = node.children[0]
            else:
                # Leaf node is heterogeneous: sample directly [G]
                color, opacity = evaluate_transfer_function(node.min, ray)
                accumulated_color += color * (1.0 - accumulated_opacity)
                accumulated_opacity += opacity * (1.0 - accumulated_opacity)
                break
    return accumulated_color, accumulated_opacity
```

**Parameters:**
* $\epsilon$: The homogeneity threshold. Not given in the sources. Typical values depend on the data range and transfer function sensitivity [G].

**Edge Cases and Pitfalls:**
* **Precision:** Comparing floating-point minimum and maximum values requires care. A fixed $\epsilon$ may not scale well across different data ranges [G].
* **Approximation Error:** The approximate evaluation assumes uniformity. If the transfer function is highly non-linear, even small variations within the homogeneous range can cause significant color changes [G].

## Operating characteristics
**Time Complexity:** Reduces the number of ray-marching steps in homogeneous regions from $O(N)$ to $O(1)$ per region, where $N$ is the number of voxels in the region [G]. The construction time is $O(V)$ where $V$ is the total number of voxels [G].
**Memory Complexity:** Requires storing two scalar values per node in the pyramid. The size is proportional to the number of nodes in the pyramid, which is $O(V)$ for a full pyramid [G].
**Measured Performance:** Denskin and Hanrahan reported improvements over presence acceleration, particularly in volumes with large uniform regions [S1, unofficial][S2, unofficial]. Specific speedup factors are not given in the sources [G].
**Strengths:** Effective for volumes with large homogeneous areas. Reduces redundant sampling [G].
**Limitations:** Approximation may reduce visual fidelity if the transfer function is sensitive to small value changes. Requires additional memory for the range pyramid [G].
**When to use:** When the volume contains significant homogeneous regions and the transfer function is relatively smooth or linear in those regions [G].
**When not to use:** When the volume is highly heterogeneous or the transfer function is highly non-linear, as the approximation error may be visually unacceptable [G].

## Background
Homogeneity acceleration was introduced by Denskin and Hanrahan in 1992 [S2, unofficial]. It was an improvement over presence acceleration, which only skipped empty regions [S1, unofficial][S2, unofficial]. The technique uses a range pyramid instead of a binary pyramid to skip empty ray segments and approximately evaluate homogeneous regions [S1, unofficial][S2, unofficial].
