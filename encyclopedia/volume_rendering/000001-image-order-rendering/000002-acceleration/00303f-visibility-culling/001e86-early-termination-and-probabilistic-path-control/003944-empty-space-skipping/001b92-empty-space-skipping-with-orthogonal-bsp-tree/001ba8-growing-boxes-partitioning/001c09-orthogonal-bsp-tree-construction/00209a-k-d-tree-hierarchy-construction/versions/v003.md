# K-D Tree Hierarchy Construction

Also called: Polygon distribution in k-d tree, Spatial partitioning with k-d trees

## Overview
K-D Tree Hierarchy Construction is a method for building a spatial partitioning data structure to organize polygons (or volumetric primitives) for efficient rendering and ray traversal. It solves the problem of explicitly clipping polygons against view frustums or traversal planes by storing them in a binary tree where each node splits a region in one dimension at a time [S1]. It sets itself apart from its sibling [Orthogonal BSP Tree Construction](1134-orthogonal-bsp-tree-construction.md) by allowing splitting planes to be positioned arbitrarily within a node's bounds (often via bisection) rather than being strictly object-aligned, and by associating polygons with the smallest node region that completely contains them, thereby avoiding polygon subdivision [S1].

## How it works
**Inputs:** A set of polygons (or primitives) $P$, each defined by its vertices. A user-defined leaf threshold $T_{leaf}$.
**Outputs:** A binary tree where each node $v$ contains a list of polygon IDs and references to left/right children.

**Data Structures:**
*   **Tree Node $v$:**
    *   `split_dim`: Integer index $i \in \{0, 1, 2\}$ indicating the axis of splitting.
    *   `split_val`: Float value $X_i$ along axis $i$ defining the hyperplane.
    *   `poly_ids`: List of polygon identifiers.
    *   `left_child`: Reference to left subtree node.
    *   `right_child`: Reference to right subtree node.
*   **Polygon Storage:** Polygon IDs are stored in a common array `Tid` arranged in prefix-order traversal order to allow passing all objects associated with a subtree in one operation [S1].

**Algorithm Steps:**
1.  **Initialization:** Start with the root node $v_{root}$ containing all input polygons $P$.
2.  **Recursive Construction:** For a node $v$ receiving a set of polygons $P_v$:
    a.  **Leaf Check:** If $|P_v| \le T_{leaf}$, mark $v$ as a leaf. Store $P_v$ in $v$. Return.
    b.  **Splitting Axis Selection:** Determine the splitting dimension $i$. The standard implementation uses a round-robin fashion (e.g., $i = \text{depth} \pmod 3$) [S1]. More sophisticated policies may analyze variance (see [Axis Selection via Variance](#axis-selection-via-variance)).
    c.  **Splitting Value Selection:** Determine the split value $X_i$. The standard implementation bisects the region along axis $i$ [S1].
    d.  **Polygon Classification:** For each polygon $p \in P_v$:
        i.  Check the $x_i$ coordinate of all vertices of $p$.
        ii. If all vertices have $x_i < X_i$, add $p$ to the left set $P_{left}$.
        iii. If all vertices have $x_i > X_i$, add $p$ to the right set $P_{right}$.
        iv. Otherwise, retain $p$ in the current node's list $P_v$.
    e.  **Recursion:**
        i.  If $P_{left}$ is not empty, create left child $v_{left}$, set $v_{left}.poly\_ids = P_{left}$, and recursively construct $v_{left}$.
        ii. If $P_{right}$ is not empty, create right child $v_{right}$, set $v_{right}.poly\_ids = P_{right}$, and recursively construct $v_{right}$.
        iii. If a child set is empty, the corresponding child pointer is null (or the node remains a leaf if the threshold was not met, though typically empty subtrees are pruned).

**Edge Cases and Pitfalls:**
*   **Polygon Association:** Polygons are associated with the smallest node region that completely contains them. This avoids subdividing polygons but means a polygon may be stored in an internal node rather than a leaf if it spans the split plane [S1].
*   **Precision:** Floating-point comparisons for vertex positions against $X_i$ must be consistent to avoid ambiguity.
*   **Empty Subtrees:** If all polygons fall into one side, the other child is empty. The algorithm should handle this by not creating a child node or marking it as null.

**Pseudocode:**
```python
def build_kd_tree(polygons, depth=0, threshold=10):
    """
    Recursively builds a K-D tree.
    polygons: List of polygon objects, each having a method get_vertices() returning list of (x,y,z) tuples.
    depth: Current tree depth.
    threshold: Leaf node threshold.
    Returns: Node object or None if no polygons.
    """
    if not polygons:
        return None

    node = Node()
    node.poly_ids = [p.id for p in polygons]

    if len(polygons) <= threshold:
        node.is_leaf = True
        node.left_child = None
        node.right_child = None
        return node

    # Round-robin axis selection
    split_dim = depth % 3

    # Calculate bounds to find bisection point
    min_val = float('inf')
    max_val = float('-inf')
    for p in polygons:
        for v in p.get_vertices():
            val = v[split_dim]
            if val < min_val: min_val = val
            if val > max_val: max_val = val

    # Bisection value
    split_val = (min_val + max_val) / 2.0

    node.split_dim = split_dim
    node.split_val = split_val
    node.is_leaf = False

    left_polys = []
    right_polys = []
    current_polys = []

    for p in polygons:
        all_less = True
        all_greater = True
        for v in p.get_vertices():
            val = v[split_dim]
            if val >= split_val:
                all_less = False
            if val <= split_val:
                all_greater = False
        
        if all_less:
            left_polys.append(p)
        elif all_greater:
            right_polys.append(p)
        else:
            current_polys.append(p)

    node.poly_ids = [p.id for p in current_polys]

    node.left_child = build_kd_tree(left_polys, depth + 1, threshold)
    node.right_child = build_kd_tree(right_polys, depth + 1, threshold)

    return node

class Node:
    def __init__(self):
        self.split_dim = 0
        self.split_val = 0.0
        self.poly_ids = []
        self.left_child = None
        self.right_child = None
        self.is_leaf = False
```

## Subtopics

### Axis Selection via Variance
Selects the splitting axis by analyzing the variance of the QEF (Quadratic Error Function) solution along each dimension, scaled by the box size [S2, unofficial]. Steps: 1. Solve QEF to get approximate solution and error. 2. Calculate variance for each axis: $variance[i] = qef.getVariance(approximate) \times size[i]$. 3. Find $maxVarDir$ (index of max variance) and $minVarDir$ (index of min variance). 4. Set $dir = maxVarDir$. If $size[maxVarDir] < 2$, fallback to $3 - maxVarDir - minVarDir$. If that size $< 2$, fallback to $minVarDir$ [S2, unofficial].

### Real-time KD Tree Construction
A technique proposed by Zhou et al. for building KD tree nodes in real-time using GPU programming via breadth-first search [S3]. This allows for dynamic updates and is suitable for scenarios requiring frequent tree reconstruction, such as real-time volume rendering or photon mapping [S3].

### [GPU K-D Tree Ray Traversal](4575-gpu-k-d-tree-ray-traversal.md)
A hierarchical spatial partitioning structure where each node is divided into two sub-nodes by a plane orthogonal to an axis, positioned arbitrarily along that axis within the node. It is a special case of BSP-Tree [4575-gpu-k-d-tree-ray-traversal.md]. This variant focuses on the traversal efficiency on GPU hardware rather than the construction method itself.

## Operating characteristics
*   **Time Complexity:** Construction is $O(N \log N)$ on average for balanced trees, where $N$ is the number of polygons. Worst-case is $O(N^2)$ for degenerate inputs (e.g., all polygons overlapping at a single point).
*   **Memory Complexity:** $O(N)$ for storing polygon IDs and tree nodes. The prefix-order storage in `Tid` array minimizes overhead compared to linked lists [S1].
*   **Performance:** Efficient for static scenes. Parallelization is possible but contention can become a drawback on more than ~16 processors [S1].
*   **Strengths:** Avoids explicit polygon clipping; simple implementation; effective for empty-space skipping.
*   **Limitations:** Sensitive to input distribution; round-robin splitting may not be optimal for all scenes; requires careful handling of polygons spanning split planes.

## Background
The k-d tree was introduced by Jon Bentley [S1]. It is widely used in computer graphics for spatial partitioning, ray tracing, and nearest-neighbor searches. In volume rendering, it is used to organize polygons for efficient visibility sorting and early termination [S1].
