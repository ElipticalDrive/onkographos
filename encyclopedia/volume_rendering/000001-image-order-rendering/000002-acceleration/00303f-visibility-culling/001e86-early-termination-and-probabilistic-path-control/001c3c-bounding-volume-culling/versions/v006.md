# Bounding Volume Culling

Also called: Distance-based Culling, Ray Termination by Distance

## Overview
Bounding Volume Culling is an optimization that limits raymarching to a specific bounding volume, dropping rays that exceed a certain distance from the eye to speed up rendering [S1, unofficial]. It differs from its siblings, [Empty-space skipping](1002-empty-space-skipping.md) and [Early ray termination](1019-early-ray-termination.md), by using a global geometric constraint (maximum travel distance) rather than local density or opacity thresholds to terminate the integration loop.

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, maximum travel distance $T_{max}$, and a distance field function $S(\mathbf{p})$ that returns the distance to the closest surface at point $\mathbf{p}$.
*   **Output:** The final color or termination status of the ray.

**Data Structures:**
*   No complex data structures are required for the basic method. A single scalar variable tracks the accumulated distance.

**Steps:**
1.  Initialize the accumulated distance traveled by the ray, $t$, to $0$.
2.  While $t < T_{max}$:
    a.  Evaluate the current position $\mathbf{p} = \mathbf{o} + t \mathbf{d}$.
    b.  Compute the distance to the closest surface, $d = S(\mathbf{p})$.
    c.  If $d$ is sufficiently small (surface hit), terminate and shade.
    d.  Advance the ray: $t \leftarrow t + d$.
3.  If the loop completes without hitting a surface (i.e., $t \ge T_{max}$), terminate the ray.

**Formulas:**
*   Ray position: $\mathbf{p}(t) = \mathbf{o} + t \mathbf{d}$
*   Termination condition: $t \ge T_{max}$

**Parameters:**
*   $T_{max}$: The predefined limit for ray travel. Typical values depend on the scene scale; for example, a maximum step count of 64 steps with a step size of 1.0 implies $T_{max} = 64$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** If $T_{max}$ is very large, floating-point precision errors in $t$ may cause the ray to overshoot or fail to terminate correctly.
*   **Boundaries:** Rays originating outside the bounding volume may terminate immediately if $T_{max}$ is set relative to the volume's extent rather than the ray's path.

**Pseudocode:**
```python
def bounding_volume_culling(ray_origin, ray_direction, max_distance, distance_field):
    t = 0.0
    while t < max_distance:
        p = ray_origin + t * ray_direction
        d = distance_field(p)
        if d < epsilon:  # epsilon is a small threshold for surface hit
            return shade(p, ray_direction)
        t += d
    # Ray exceeded the bounding volume limit
    return background_color
```

## Subtopics

### Heap-based Bounding Volume Culling for Sphere Tracing
An algorithm to find the closest object in a collection by maintaining a heap of bounding volume distances. It computes distances to bounding volumes first, then contents, culling based on the smallest bounding volume distance [S2]. It differs from the parent method by managing a collection of objects rather than a single global limit, deferring expensive distance computations until necessary [S2].

**Steps:**
1.  Compute distances to each bounding volume in the union/collection.
2.  Create a min-heap of these distances.
3.  Initialize $d_{min}$ to infinity.
4.  Loop:
    a. Let $d_{content}$ be $\min(d_{min}, \text{distance to contents of top BV})$.
    b. Remove top of heap.
    c. Let $d_{bv}$ be distance to new top BV.
    d. Stop if $d_{content} < d_{bv}$ or heap is empty.
5.  Return $d_{content}$.

**Parameters:**
*   $d_{bv}$: The distance to the bounding volume currently at the top of the heap [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray for the basic method, assuming $T_{max}$ is fixed. For heap-based variants, it is $O(N \log N)$ for initialization and $O(\log N)$ per query, where $N$ is the number of bounding volumes.
*   **Memory Complexity:** $O(1)$ for basic; $O(N)$ for heap-based.
*   **Strengths:** Simple to implement; effective for scenes with known bounds; reduces unnecessary shading calculations.
*   **Limitations:** Does not account for empty space within the volume; may terminate rays that would have contributed to fog or global illumination if not handled carefully.
*   **When to use:** When the scene has a clear spatial extent and rays rarely need to travel beyond a certain distance.

## Background
The concept of limiting raymarching to a bounding volume was introduced in early raymarching literature as a way to speed up rendering by avoiding calculations for rays that have traveled too far [S1, unofficial]. The heap-based variant for sphere tracing was described in the context of geometric methods for antialiased ray tracing of implicit surfaces [S2].
