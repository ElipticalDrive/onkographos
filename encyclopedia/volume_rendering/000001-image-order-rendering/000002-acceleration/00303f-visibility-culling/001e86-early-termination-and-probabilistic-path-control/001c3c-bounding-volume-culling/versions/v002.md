# Bounding Volume Culling

Also called: Distance-based Culling, Ray Termination by Distance

## Overview
Bounding Volume Culling is an acceleration technique for volume rendering and Signed Distance Field (SDF) raymarching that limits ray traversal to a specific spatial extent, dropping rays that exceed a predefined distance from the eye [S1, unofficial]. It solves the problem of unnecessary computation for rays that have traveled beyond the relevant scene geometry or desired visual range [S1, unofficial]. Unlike [Empty-space skipping](1002-empty-space-skipping.md) which skips empty regions, or [Early ray termination](1019-early-ray-termination.md) which stops based on opacity accumulation, this method terminates based on absolute geometric distance [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (normalized), maximum travel distance $t_{\text{max}}$, and scene evaluation functions [G].
- Output: Accumulated color and opacity, or a termination flag when the distance limit is reached [G].

**Data Structures:**
- $t$: A scalar accumulator tracking the total distance traveled along the ray [S1, unofficial].
- $t_{\text{max}}$: A scalar constant defining the culling threshold [S1, unofficial].

**Steps:**
1. Initialize the traveled distance $t \leftarrow 0$ [G].
2. Evaluate the scene distance function at the current ray position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [G].
3. Update $t$ by adding the step size $\Delta t$ (typically the distance function value) [G].
4. Perform front-to-back compositing updates using the sampled color and opacity [G].
5. Check the culling condition: If $t > t_{\text{max}}$, terminate the raymarch process immediately [S1, unofficial].

**Formulas:**
- Ray position: $\mathbf{p}(t) = \mathbf{o} + t\mathbf{d}$ [G].
- Termination condition: $t > t_{\text{max}}$ [S1, unofficial].

**Parameters:**
- $t_{\text{max}}$: The maximum distance from the eye; for fog effects it may correspond to the far clipping plane [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision errors in $t$ accumulation can cause premature termination or infinite loops if not handled with a small epsilon [G].

**Pseudocode:**
```python
def bounding_volume_culling(ray_origin, ray_direction, max_distance, scene_dist_func, sample_color_func):
    """
    Raymarch with bounding volume culling.
    
    Args:
        ray_origin: vec3, origin of the ray.
        ray_direction: vec3, normalized direction of the ray.
        max_distance: float, maximum allowed distance from ray_origin.
        scene_dist_func: function, returns distance to closest surface at point p.
        sample_color_func: function, returns color and opacity at point p.
        
    Returns:
        acc_color: vec3, the final accumulated color.
    """
    t = 0.0
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    while True:
        p = ray_origin + t * ray_direction
        dist = scene_dist_func(p)
        
        if dist < 1e-4:
            break
            
        color_sample, alpha_sample = sample_color_func(p)
        acc_color = acc_color + color_sample * alpha_sample * (1.0 - acc_alpha)
        acc_alpha = acc_alpha + alpha_sample * (1.0 - acc_alpha)
        
        t += dist
        
        if t > max_distance:
            break
            
    return acc_color
```

## Subtopics

### [Bounding Spheres Optimization](1567-bounding-spheres-optimization.md)
Bounding Spheres Optimization is an acceleration technique that eliminates unnecessary distance computations by culling rays that miss a scene object's bounding sphere. It is a specific application of bounding volume optimization, minimizing the cost of the map function by skipping SDF evaluations for objects that do not contribute to the minimal distance field. It is chosen when the scene contains discrete objects with known spherical bounds, offering a low-overhead check compared to complex bounding volumes.

### Heap-based Bounding Volume Culling for Sphere Tracing
Heap-based Bounding Volume Culling for Sphere Tracing is an algorithm to find the closest object in a collection by maintaining a heap of bounding volume distances [S2]. It computes distances to bounding volumes first, then contents, culling based on the smallest bounding volume distance [S2]. It is chosen when rendering a union or collection of implicit surfaces, as it avoids computing expensive content distances for objects that are farther away than the currently closest candidate [S2].

**Steps:**
1. Compute distances to each bounding volume in the union/collection [S2].
2. Create a min-heap of these distances [S2].
3. Initialize $d_{\text{min}} \leftarrow \infty$ [S2].
4. Loop:
   a. Let $d_{\text{content}} \leftarrow \min(d_{\text{min}}, \text{distance to contents of top BV})$ [S2].
   b. Remove top of heap and re-heap [S2].
   c. Let $d_{\text{bv}}$ be the distance to the new top BV [S2].
   d. Stop if $d_{\text{content}} < d_{\text{bv}}$ or heap is empty [S2].
5. Return $d_{\text{content}}$ [S2].

**Parameters:**
- $d_{\text{bv}}$: The distance to the bounding volume currently at the top of the heap [S2].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Reduces rendering time by avoiding expensive distance function evaluations for irrelevant geometry [S2]. Initial tests suggest it may degrade performance in perspective cases for typical implicit surfaces if the overhead of sphere intersection computation outweighs the savings [S2].
- **Strengths:** Simple to implement; effective for fog and limited-range effects [S1, unofficial].
- **Limitations:** Overhead of maintaining heaps for large collections [S2].

## Background
The concept of limiting raymarching to a bounding volume to speed up rendering was discussed in early online presentations and blogs [S1, unofficial]. The formalization of bounding volumes for sphere tracing, including heap-based selection for collections of implicit surfaces, was presented in the "Sphere Tracing: A Geometric Method for the Antialiased Ray Tracing of Implicit Surfaces" paper [S2].
