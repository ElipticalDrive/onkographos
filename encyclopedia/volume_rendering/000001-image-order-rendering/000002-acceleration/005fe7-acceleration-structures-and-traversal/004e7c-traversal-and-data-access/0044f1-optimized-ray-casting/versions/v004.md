# Optimized Ray Casting

Also called: Adaptive Ray Casting, Boundary cell projection, Fast Ray Casting Algorithm, Octtree Ray Casting

## Overview
Optimized Ray Casting is a volume rendering algorithm that accelerates image-order rendering by combining hierarchical data structures (such as octrees) with adaptive sampling and early ray termination [S1, S2, unofficial]. It solves the problem of high computational cost in dense volumetric datasets by skipping transparent regions and reducing the number of ray samples where visual detail is low [S1, S2, unofficial]. Unlike sibling methods that focus on parallel distribution or specific hardware constraints, Optimized Ray Casting focuses on algorithmic efficiency through spatial coherence and opacity thresholds, building on the [Traversal and Data Access](13739-traversal-and-data-access.md) principles of path parameterization and coordinate mapping.

## How it works
The method integrates boundary cell projection, adaptive image sampling, and octree-based traversal to minimize unnecessary computation.

**Inputs and Outputs**
*   **Input:** A 3D scalar field (volume data), transfer functions (mapping scalar values to color and opacity), and camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$, image resolution).
*   **Output:** A 2D image where each pixel contains the accumulated color and opacity along the corresponding ray.

**Data Structures**
*   **Octree:** A hierarchical structure representing the volume. Each node represents a macro-block (e.g., a $4 \times 4 \times 4$ or larger block of voxels). Nodes are tagged to indicate if they contain only transparent voxels [S2, unofficial].
*   **Backstore/Backing Store:** Memory region holding loaded macros (blocks of voxels) for the current rendering sector [S2, unofficial].

**Algorithm Steps**

1.  **Preprocessing (Offline):**
    *   Construct the octree from the volume data.
    *   Tag macros (leaf nodes or internal nodes representing blocks) that contain *only* transparent voxels. This allows the traversal to skip these regions entirely [S2, unofficial].

2.  **Ray Initialization:**
    *   For each pixel in the image, define the ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ [S1, unofficial][S2, unofficial].
    *   If a cut plane is defined, start the ray traversal at the intersection with the cut plane rather than the dataset boundary. This adds no runtime cost and can speed up rendering by reducing the traversal distance [S2, unofficial].

3.  **Adaptive Ray Casting (Coarse to Fine):**
    *   **Coarse Pass:** Cast rays on a coarse grid (e.g., skipping pixels or using lower resolution sampling) to estimate the scene content [S2, unofficial].
    *   **Adaptive Refinement:** Compare adjacent sampled values. If the difference in color or density exceeds a threshold, cast additional rays in that region to capture detail [S2, unofficial].
        *   *Color Difference Thresholds:* 10 (electric field), 40 (neghip), 30 (brain) [S1, unofficial].
        *   *Density Difference Thresholds:* 30 (electric field), 80 (neghip), 5 (brain) [S1, unofficial].
    *   **Interpolation:** The final image is formed by bilinear interpolation of the ray-cast pixels from the adaptive sampling [S2, unofficial].

4.  **Hierarchical Traversal (Octree Skip):**
    *   Traverse the octree along the ray.
    *   If a node is tagged as "completely transparent," skip the entire subtree. This avoids trilinear interpolation and compositing for empty space [S2, unofficial].
    *   This optimization is effective because typically 2/3 of macros are completely transparent [S2, unofficial].

5.  **Ray Termination (Early Exit):**
    *   Accumulate opacity $\alpha$ along the ray.
    *   If $\alpha$ exceeds a threshold (alpha cutoff), terminate the ray. Further processing yields negligible color change [S2, unofficial].
    *   *Opacity Thresholds:* 92% (electric field), 98% (neghip), 98% (brain) [S1, unofficial].

**Pseudocode**

```python
def optimized_ray_casting(volume_data, camera, transfer_function, octree):
    """
    Renders a volume using optimized ray casting with adaptive sampling and octree skipping.
    """
    image_width = camera.width
    image_height = camera.height
    image = empty_array(image_height, image_width, 4) # RGBA

    # Pre-compute thresholds from configuration
    color_thresholds = get_color_thresholds() # e.g., [10, 40, 30]
    density_thresholds = get_density_thresholds() # e.g., [30, 80, 5]
    alpha_cutoff = get_alpha_cutoff() # e.g., 0.98

    # 1. Adaptive Sampling: Determine which pixels need full ray casting
    # Cast a coarse grid first
    coarse_step = 2 # Example: skip every other pixel
    coarse_samples = []
    for y in range(0, image_height, coarse_step):
        for x in range(0, image_width, coarse_step):
            ray = camera.get_ray(x, y)
            color, alpha = cast_ray_coarse(ray, volume_data, transfer_function, octree)
            coarse_samples.append((x, y, color, alpha))

    # 2. Refine based on differences
    refined_pixels = set()
    for i, (x1, y1, c1, a1) in enumerate(coarse_samples):
        # Check neighbors in coarse grid
        neighbors = get_coarse_neighbors(x1, y1, coarse_step, image_width, image_height)
        for x2, y2, c2, a2 in neighbors:
            # Check color difference
            if abs(c1 - c2) > color_thresholds:
                # Mark all pixels in the bounding box of these coarse samples for refinement
                mark_region_for_refinement(x1, y1, x2, y2, refined_pixels)
            # Check density difference (requires sampling density along ray)
            if abs(a1 - a2) > density_thresholds: # Approximation using alpha as proxy for density integration
                mark_region_for_refinement(x1, y1, x2, y2, refined_pixels)

    # 3. Full Ray Casting for refined pixels
    for y in range(image_height):
        for x in range(image_width):
            if (x, y) in refined_pixels:
                ray = camera.get_ray(x, y)
                final_color, final_alpha = cast_ray_fine(ray, volume_data, transfer_function, octree, alpha_cutoff)
                image[y, x] = final_color
            else:
                # Interpolate from coarse samples
                image[y, x] = bilinear_interpolate_coarse(x, y, coarse_samples)

    return image

def cast_ray_fine(ray, volume_data, transfer_function, octree, alpha_cutoff):
    """
    Casts a single ray using octree traversal and early termination.
    """
    accumulated_color = (0.0, 0.0, 0.0, 0.0)
    accumulated_opacity = 0.0
    
    # Determine entry and exit t values for the volume
    t_min, t_max = ray.intersect_volume_bounds()
    
    # Traverse octree
    nodes_to_visit = octree.get_nodes_intersecting_ray(ray, t_min, t_max)
    
    for node in nodes_to_visit:
        # Optimization: Skip transparent macros
        if node.is_tagged_transparent():
            continue
            
        # Get voxel samples within this node
        samples = node.get_voxel_samples(ray)
        
        for sample in samples:
            # Sample value and compute color/opacity
            value = volume_data.get_value(sample.position)
            color, opacity = transfer_function.apply(value)
            
            # Composite
            # C_out = C_in + (1 - A_in) * C_sample * A_sample
            # A_out = A_in + (1 - A_in) * A_sample
            
            weight = (1.0 - accumulated_opacity) * opacity
            accumulated_color += weight * color
            accumulated_opacity += weight
            
            # Early termination
            if accumulated_opacity >= alpha_cutoff:
                break
                
    return accumulated_color, accumulated_opacity
```

**Parameters**
*   **Sample Region Size:** For adaptive image sampling, the square sample region size is typically $3 \times 3$ pixels [S1, unofficial].
*   **Alpha Cutoff:** Thresholds vary by dataset: 92% (electric field), 98% (neghip), 98% (brain) [S1, unofficial].
*   **Cut Planes:** Implemented by starting rays at the plane equation $ax + by + cz + d = 0$ instead of the dataset boundary [S5].

**Edge Cases and Pitfalls**
*   **Precision:** Adaptive sampling relies on threshold comparisons. If thresholds are too low, performance degrades to full ray casting; if too high, visual artifacts (blockiness) appear [S1, unofficial].
*   **Boundary Conditions:** Cut planes must be correctly intersected with the ray to avoid starting inside the volume or missing the volume entirely [S5].
*   **Memory:** The octree and backing store require additional memory. If the volume is sparse, the octree overhead is justified; if dense, the skipping benefit diminishes [S2, unofficial].

## Subtopics

### [Light Ray Extinction Optimization](15221-light-ray-extinction-optimization.md)
Accelerates direct illumination computation in Monte Carlo volume rendering by optimizing extinction estimates along light rays. Distinct from camera-ray optimization as it handles stochastic scattering paths.

### [Parallel Volume Rendering for Computational Flow Imaging](16105-parallel-volume-rendering-for-computational-flow-imaging.md)
Optimizes ray casting for CFD data by converting curilinear grids to rectilinear multi-block voxel fields for parallel processing. Addresses integral errors from overlapping grids.

### [STiles (Sorted Tiles)](16374-stiles-sorted-tiles.md)
A progressive technique that sorts screen-space tiles by cost and renders them in batches. Designed for interactive rendering on mobile/low-performance devices to avoid frame stalls.

### Nishita and Nakamae Water Rendering
A specific application of optimized ray casting principles for water rendering [S3]. It considers optical effects like caustics, shafts of light, and water color. The water is modeled as a uniform particle density medium, eliminating the need for numerical integration of densities along the ray. Intensity is calculated as an analytical function of the distance between particles and the viewpoint. Unlike standard ray casting, it uses a scanline Z-buffer and accumulation buffer instead of ray-tracing [S3].

### Pre-calculated Gradient Storage
An optimization that replaces real-time gradient calculation with a pre-computed 3D texture lookup [S4]. Gradients (direction and magnitude) are stored in a 3D RGBA texture. During raycasting, the gradient texture is sampled instead of computing gradients on the fly, saving 6 extra texture fetches per sample [S4]. This trades memory for computation speed, advantageous for VR hardware like HTC Vive [S4].

### Reslicing via Ray Casting
A modification to the ray-cast algorithm to reslice a volume along an arbitrary plane $ax + by + cz + d = 0$ [S5]. The ray-cast is performed by either starting the search for the first voxel at the z-coordinate determined by the plane equation or continuing until the x-coordinate value is reached. This effectively removes voxels where $ax + by + cz + d < 0$ or $ax + by + cz + d > 0$, allowing for interactive slicing without global re-display [S5].

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume and the effectiveness of the octree skipping. In the worst case (fully opaque), it approaches $O(N)$ where $N$ is the number of voxels along the ray. In sparse volumes, it is significantly faster due to octree traversal skipping empty space [S2, unofficial].
*   **Memory Complexity:** $O(V)$ for the volume data plus $O(M)$ for the octree structure, where $M$ is the number of macros/nodes. The backing store adds temporary memory pressure [S2, unofficial].
*   **Measured Performance:**
    *   On an SGI Power Challenge with 16 processors: Electric field ($50^3$) 0.04s, Neghip ($68^3$) 0.15s, Brain ($256 \times 256 \times 124$) 0.09s [S1, unofficial].
    *   On 4 processors: Electric field 0.39s, Neghip 1.02s, Brain 0.17s [S1, unofficial].
    *   On 8 processors: Electric field 0.11s, Neghip 0.93s, Brain 0.12s [S1, unofficial].
    *   On 12 processors: Electric field 0.06s, Neghip 0.28s, Brain 0.11s [S1, unofficial].
    *   More than 10 frames per second achieved for all three datasets at highest resolution on 16 processors [S1, unofficial].
    *   On a slave GPU: 100-240 ms to render a $128 \times 128$ image tile for a $128^3$ dataset with coarse refinement [S2, unofficial].
*   **Strengths:** High performance on sparse or semi-transparent volumes; interactive frame rates achievable on older hardware; adaptive sampling reduces aliasing without full supersampling cost.
*   **Limitations:** Performance degrades on dense, fully opaque volumes where octree skipping is ineffective; adaptive sampling introduces complexity in threshold tuning; requires preprocessing to build the octree [S1, S2, unofficial].
*   **When to Use:** Interactive visualization of large, sparse volumetric datasets (e.g., medical CT/MRI, scientific simulations) where real-time feedback is required.
*   **When Not to Use:** Dense, fully opaque volumes where the overhead of octree traversal outweighs the benefit; scenes requiring precise, non-adaptive sampling for scientific accuracy.

## Background
Optimized Ray Casting was developed in the late 1980s and early 1990s as a response to the computational demands of direct volume rendering. Key contributors include Marc Levoy, who introduced the concept of early ray termination and alpha cutoffs [S2, unofficial], and researchers at SGI and NASA who implemented fast ray casting algorithms on parallel architectures [S1, unofficial]. The method integrates boundary cell projection and octree traversal to optimize the ray casting process, achieving real-time performance on datasets that were previously too large for interactive visualization [S1, S2, unofficial]. It has been widely used in medical imaging and scientific visualization for its balance of speed and visual quality.
