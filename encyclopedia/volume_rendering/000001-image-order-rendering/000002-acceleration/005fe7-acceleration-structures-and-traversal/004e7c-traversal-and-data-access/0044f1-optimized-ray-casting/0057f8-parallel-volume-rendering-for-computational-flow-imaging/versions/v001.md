# Parallel Volume Rendering for Computational Flow Imaging

Also called: CFI Parallel Volume Rendering, Preprocessed Raytracing for CFI

## Overview
Parallel Volume Rendering for Computational Flow Imaging (CFI) is a method that translates curvilinear, multiple overlapping grids from Computational Fluid Dynamics (CFD) simulations into rectilinear multi-block data fields to eliminate integral errors caused by intersected or overlapped grid parts [S1, unofficial]. It solves the problem of efficiently rendering optical simulations (shadowgraph, schlieren, interferometry) from complex, adaptive CFD meshes by voxelizing the geometry and distributing the resulting voxels across a distributed-memory architecture [S1, unofficial]. Unlike cell projection, which causes errors by repeatedly calculating overlapped segments, and unlike simple resampling, which requires excessive storage and sampling rates, this method uses preprocessing and region division to increase searching speed and efficiency [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Curvilinear, multiple overlapping CFD grids representing a 3D flow field.
*   **Output:** Rendered images simulating shadowgraph, schlieren, or interferometric observations.

**Data Structures:**
*   **Voxel:** A discrete unit representing a portion of the flow field. The source does not specify the exact bit-packing or field layout of the voxel data structure, only that voxels are distributed by x and y coordinates [S1, unofficial].
*   **Region:** A regular sub-volume of the flow field, created by equally dividing the whole field along x and y coordinates.
*   **Block:** A collection of voxels assigned to a specific processor in the distributed system.

**Parameters:**
*   **Integration Method:** Trapezoidal rule for line-of-sight integration [S1, unofficial].
*   **Communication:** MPI message passing [S1, unofficial].
*   **Implementation:** C++ [S1, unofficial].

**Steps:**
1.  **Voxelization:** Convert the continuous geometric representation of the CFD grids into a set of voxels [S1, unofficial].
2.  **Region Division:** Divide the whole flow field into new regular regions by equally dividing it along the x and y coordinates [S1, unofficial].
3.  **Load Balancing:** Distribute voxels into these regions such that each region contains approximately the same number of voxels. This reduces load imbalances caused by the varying sizes and shapes of voxels (which can differ by several orders of magnitude due to adaptive meshing) [S1, unofficial].
4.  **Distribution:** Distribute the voxels in different regions into different parts of the parallel distributed-memory supercomputer (e.g., Beowulf cluster) [S1, unofficial].
5.  **Rendering:** Perform ray-casting and field reconstruction on the distributed data. Each line integral process searches through all voxels in its assigned block [S1, unofficial].

**Formulas:**
The optical intensity is calculated based on the type of CFI technique. If the light path length is divided into $n$ segments, the integrand values are calculated at specific points, and integration is performed using the trapezoidal rule [S1, unofficial].

For **shadowgraph** systems, which respond to the second derivative of flow density, the optical intensity $I$ is proportional to:
$$ I \propto \sum_{i=1}^{n} \left( \frac{\partial^2 \rho}{\partial x^2} + \frac{\partial^2 \rho}{\partial y^2} \right)_i \Delta s_i $$
*(Note: The source text contains garbled characters for the formula, but describes it as the second derivative of flow density summed along the path [S1, unofficial].)*

For **schlieren** systems, which respond to the first derivative:
*   Vertical knife-edge/filter:
    $$ I \propto \sum_{i=1}^{n} \frac{\partial \rho}{\partial x}_i \Delta s_i $$
*   Horizontal knife-edge/filter:
    $$ I \propto \sum_{i=1}^{n} \frac{\partial \rho}{\partial y}_i \Delta s_i $$

For **interferometric** systems (Mach-Zehnder or holographic), the light intensity is proportional to the fringe shift [S1, unofficial].

    # Aggregate results from all processors

**Edge Cases and Pitfalls:**
*   **Load Imbalance:** Voxels from adaptive CFD meshes can vary in size by several orders of magnitude, leading to uneven computational loads. This is mitigated by balancing the *number* of voxels per region, not their volume [S1, unofficial].
*   **Integral Errors:** Using cell projection on intersecting/overlapping grids causes repeated calculation of overlapped segments. This method avoids that by voxelizing first [S1, unofficial].
*   **Storage Limits:** Simple resampling to a regular grid requires high sampling rates, making the volume too large for storage. This method avoids full resampling by using voxelization and region division [S1, unofficial].

## Subtopics

### Preprocessing for CFI
*   **What it is:** The conversion of curvilinear CFD grids into rectilinear multi-block voxel fields.
*   **Differentiation:** Eliminates integral errors from overlapping grids that affect cell projection, and avoids the storage bloat of full regular grid resampling.
*   **When to choose:** When rendering CFD data with complex, adaptive, overlapping meshes for CFI applications.
*   **Link:** [Preprocessing for CFI](52-preprocessing-cfi.md)

### Distributed Ray Casting for CFI
*   **What it is:** The parallel execution of ray casting where each processor searches its assigned block of voxels.
*   **Differentiation:** Optimizes search speed by reducing the number of voxels per block, trading off distribution cost for faster per-ray traversal.
*   **When to choose:** On distributed-memory supercomputers (e.g., Beowulf) where memory bandwidth and parallel processing power are available.
*   **Link:** [Distributed Ray Casting for CFI](52-distributed-ray-casting-cfi.md)

## Operating characteristics
*   **Time Complexity:** Searching speed is improved by creating more blocks with fewer voxels in each block, despite the overhead of the voxel distribution process [S1, unofficial].
*   **Memory Complexity:** Depends on the number of voxels generated from the CFD grids. The method avoids the excessive memory usage of high-resolution regular grid resampling [S1, unofficial].
*   **Measured Performance:** Tested on a Beowulf parallel computing system with 9 nodes (800 MHz Pentium III, 100 Mb/s Ethernet switch) using datasets of ~0.5 million hexahedral cells [S1, unofficial].
*   **Strengths:** Eliminates integral errors from overlapping grids; improves searching speed via block division; scalable with the number of CPUs and total memory [S1, unofficial].
*   **Limitations:** Load imbalances are unavoidable due to varying voxel sizes/shapes, though mitigated by balancing voxel counts; communication overhead via MPI [S1, unofficial].
*   **When to use:** For parallel volume rendering of Computational Flow Imaging (shadowgraph, schlieren, interferometry) on distributed-memory architectures.
*   **When not:** When the CFD grid is simple and non-overlapping (cell projection might suffice), or when memory is extremely constrained and voxelization overhead is prohibitive [S1, unofficial].

## Background
*   **Origin:** Developed for Computational Flow Imaging (CFI), a technique that simulates optical wave interaction with flow fields to generate digital pictures simulating shadowgraph, schlieren, and interferometric observations [S1, unofficial].
*   **History:** The method was implemented on a Linux-based Beowulf parallel computing system. Initial tests used datasets representing shock waves over bodies in a channel bend and hypersonic dynamics of a ball in a ballistic range [S1, unofficial].
*   **Usage:** Used in aerodynamic flow visualization research, specifically for validating CFD simulations against experimental optical data [S1, unofficial].
