# Traversal and Data Access
## Overview
Traversal and Data Access covers the algorithmic strategies for moving a ray through a volume dataset and retrieving scalar values for compositing [G]. It solves the problem of mapping continuous ray paths to discrete data structures (uniform grids, unstructured meshes, or hierarchical bricks) while managing memory bandwidth [G]. It sets itself apart from sibling methods like [GL-NeRF](803-gl-nerf.md) and [Space Skipping and Empty Volume Culling](10063-space-skipping-and-empty-volume-culling.md) by focusing on the topology of the data access path and memory availability [G].

## Shared principles
The core mechanism shared by all children is the determination of the sequence of data elements (voxels, cells, or bricks) intersected by a ray, and the retrieval of values from those elements [G]. This involves:
1. **Path Parameterization:** Representing the ray as $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ and computing intersection intervals $[t_{entry}, t_{exit}]$ with data boundaries [G].
2. **Coordinate Mapping:** Transforming the continuous ray parameter $t$ into discrete data indices (e.g., voxel coordinates, cell IDs, or brick IDs) [G].
3. **Data Retrieval:** Fetching the value at the mapped index from the appropriate memory structure (texture, buffer, or mesh) [G].
Mathematically, for a uniform grid, this is often a Digital Differential Analyzer (DDA) step [G]. For irregular grids, it involves explicit boundary intersection tests [G]. For hierarchical data, it involves Level of Detail (LoD) selection and cache residency checks [G]. Traversal control modifies the step size $\Delta t$ based on ray direction $\mathbf{d}$, grid spacing, local data variance, or accumulated opacity to balance accuracy and performance [G].

```python
def traverse_ray(ray_origin, ray_direction, volume_bounds, data_access_fn):
    t_min, t_max = compute_intersection(ray_origin, ray_direction, volume_bounds)
    t = t_min
    accumulated_color = (0.0, 0.0, 0.0, 0.0)
    accumulated_opacity = 0.0
    
    while t < t_max:
        indices = map_to_indices(ray_origin, ray_direction, t)
        value = data_access_fn(indices)
        color, opacity = apply_transfer_function(value)
        weight = (1.0 - accumulated_opacity) * opacity
        accumulated_color += weight * color
        accumulated_opacity += weight
        t += compute_step_size(ray_direction, indices, accumulated_opacity)
        if accumulated_opacity >= 0.98:
            break
    return accumulated_color
```

## Subtopics

### [Lazy Sweep Ray Casting](1649-lazy-sweep-ray-casting.md)
A traversal method for irregular, unstructured grids that uses a sweep-plane paradigm to determine visibility order. It is chosen when rendering complex, non-convex, or disconnected topologies where fixed-step traversal fails. It differs from DDA by relying on explicit cell indexing and sorting rather than analytical grid stepping.

### [Ray-guided volume rendering with missing brick reporting](2815-ray-guided-volume-rendering-with-missing-brick-reporting.md)
An out-of-core data access technique for large-scale volume rendering using hierarchical bricks. It dynamically determines the working set during rendering and reports missing bricks to a subsystem for paging. It is chosen when memory bandwidth is the bottleneck and the volume exceeds GPU memory. It differs from static caching by handling data unavailability explicitly via a lock-free hash table.

### [Adaptive Depth Sampling with Voxel Layer Alignment](11257-adaptive-depth-sampling-with-voxel-layer-alignment.md)
An acceleration technique that reduces interpolation cost by aligning sample points with voxel layers to enable bilinear interpolation, while skipping intermediate samples. It is chosen when trilinear interpolation dominates the rendering time. It differs from standard traversal by exploiting ray direction to maximize samples on grid planes.

### [Optimized Ray Casting](11373-optimized-ray-casting.md)
A rendering algorithm that accelerates image-order rendering by combining hierarchical data structures (octrees) with adaptive sampling and early ray termination. It is chosen for dense volumetric datasets to skip transparent regions and reduce samples where visual detail is low. It differs from sibling methods by focusing on algorithmic efficiency through spatial coherence and opacity thresholds.

### [Prediction Buffer Voxel Traversal](13167-prediction-buffer-voxel-traversal.md)
A GPU-accelerated dataset traversal technique that exploits frame-to-frame coherence during camera rotation to accelerate isosurface volume rendering. It is chosen for interactive rendering of static or slowly moving volumes. It differs from C-buffer techniques by storing depth distances in a prediction buffer for high-performance GPU parallelism.

## Background
The concept of ray casting traversal originated with the development of volume rendering in the 1980s, with early methods relying on uniform grid traversal [G]. The introduction of unstructured grids required new traversal algorithms, leading to methods like Lazy Sweep Ray Casting [S1, unofficial]. Out-of-core techniques for large-scale volumes were later developed to handle memory bottlenecks [G].
