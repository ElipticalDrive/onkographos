# Parallel Ray Casting with Segment Lists

Also called: Parallel Volume Rendering with Segment Lists, MPI/OpenMP Volume Rendering with Segment Lists

## Overview
Parallel Ray Casting with Segment Lists is a distributed-memory and shared-memory parallel volume rendering algorithm that accelerates ray casting by precomputing lists of occupied volume segments to skip empty space [S1, unofficial]. It distributes image rows across MPI ranks and OpenMP threads, calculating sampling points based on a derived step length [S1, unofficial]. It differs from siblings like [SparseLeap](5152-sparseleap.md) by using explicit segment lists derived from volume geometry rather than sparse voxel octree traversal or occupancy misses, and from [Visibility Culling](6226-visibility-culling.md) by operating at the ray-segment level rather than tile or view-frustum level.

## How it works
**Inputs:** Image dimensions (width, height), camera parameters (position, direction, field of view, aspect ratio), volume data structure (brick-based with block offsets), configuration parameters (sampling_rate, multi_threading, core_count, core_thread_count, comm_size, thread_nums).
**Outputs:** Rendered image (RGB pixels).

**Data Structures:**
*   `raytracer` struct: Fields `m_start_x`, `m_start_y`, `m_end_x`, `m_end_y`, `m_width`, `m_height`, `m_depth`, `m_writer`, `m_threadId` [S2, unofficial].
*   `Segment`: Pair of floats `(s_beg, s_end)` representing entry and exit distances along the ray [S1, unofficial].
*   `point_list`: List of floats representing sampling positions along the ray [S1, unofficial].
*   `seg_list`: List of `Segment` objects returned by `volume->getSegList` [S1, unofficial].
*   `Pixel`: Struct with fields `r`, `g`, `b` (unsigned char) [S2, unofficial].

**Parameters:**
*   `sampling_rate`: Controls step length. Typical value: 1.0 [S1, unofficial].
*   `thread_nums`: Number of OpenMP threads. Default: 4 [S1, unofficial].
*   `comm_size`: Number of MPI ranks [S1, unofficial].
*   `config::multi_threading`: Boolean flag for multi-threading [S1, unofficial].
*   `config::core_count`: Number of CPU cores [S1, unofficial].
*   `config::core_thread_count`: Threads per core [S1, unofficial].

**Steps:**
1.  **Calculate Step Length:** Compute the sampling step length using the formula:
    $$step\_len = \frac{1.0}{sampling\_rate \times \sqrt{dims.x^2 + dims.y^2 + dims.z^2}}$$
    where $dims$ is the volume dimension vector [S1, unofficial].
2.  **Determine Job Count:** If `config::multi_threading` is true, `jobs = config::core_count * config::core_thread_count`; otherwise, `jobs = 1` [S1, unofficial].
3.  **Calculate Row Distribution:**
    *   `line_nums = ceil(height / comm_size)` [S1, unofficial].
    *   `t_line_nums = ceil(line_nums / thread_nums)` [S1, unofficial].
4.  **Precompute Block Offsets:** Iterate over brick dimensions $(k, j, i)$. For each block, if the block is null, set offset to -1; else, offset is `block->data - buf_base` [S1, unofficial].
5.  **Parallel Region (MPI + OpenMP):**
    *   For each thread `t_id` in the current rank:
        *   Iterate `i` from 0 to `t_line_nums - 1`.
        *   Calculate row index: `row = my_rank + (t_id * t_line_nums + i) * comm_size` [S1, unofficial].
        *   If `row >= height`, break [S1, unofficial].
    *   For each column `col` from 0 to `width - 1`:
        *   Calculate pixel coordinates:
            $$u = \left(-0.5 + \frac{col + 0.5}{width}\right) \times aspect$$
            $$v = -0.5 + \frac{row + 0.5}{height}$$
        *   Calculate ray direction using camera parameters (up, right, look directions, FOV) and normalize [S1, unofficial].
        *   Get ray distance to volume bounding box: `seg = volume->getRayDistance(cam_pos, ray_dir)` [S1, unofficial].
        *   Get segment list: `volume->getSegList(*seg_list, cam_pos, ray_dir)` [S1, unofficial]. Clear `point_list`.
        *   Iterate over segments in `seg_list`. For each segment $(s\_beg, s\_end)$:
            *   Align $s\_beg$ to step grid:
                $$s\_beg = seg.x + \left\lceil \frac{s\_beg - seg.x}{step\_len} \right\rceil \times step\_len$$
            *   While $s\_beg \le s\_end$:
                *   Push $s\_beg$ to `point_list`.
                *   $s\_beg += step\_len$ [S1, unofficial].
        *   Render pixel using points in `point_list` (sampling and compositing details not provided in sources) [S1, unofficial].

**Pseudocode:**
```python
import math

def parallel_ray_casting_with_segment_lists(width, height, comm_size, thread_nums, config, volume, camera):
    # Step 1: Calculate Step Length
    dims = volume.get_dimensions() # Assume dims is a vector-like object with x, y, z
    sampling_rate = config.get('sampling_rate', 1.0)
    step_len = 1.0 / (sampling_rate * math.sqrt(dims.x**2 + dims.y**2 + dims.z**2))

    # Step 2: Determine Job Count
    if config.get('multi_threading', False):
        jobs = config.get('core_count', 1) * config.get('core_thread_count', 1)
    else:
        jobs = 1

    # Step 3: Calculate Row Distribution
    line_nums = math.ceil(height / comm_size)
    t_line_nums = math.ceil(line_nums / thread_nums)

    # Step 4: Precompute Block Offsets (Simplified)
    # In practice, this is done once per volume load
    block_offsets = {}
    for k in range(volume.get_depth()):
        for j in range(volume.get_height()):
            for i in range(volume.get_width()):
                block = volume.get_block(k, j, i)
                if block is None:
                    block_offsets[(k, j, i)] = -1
                else:
                    block_offsets[(k, j, i)] = block.data - volume.buf_base

    # Step 5: Parallel Region
    # This function is called by each MPI rank
    my_rank = get_mpi_rank() # Placeholder for MPI rank

    for t_id in range(thread_nums):
        for i in range(t_line_nums):
            row = my_rank + (t_id * t_line_nums + i) * comm_size
            if row >= height:
                break

            for col in range(width):
                # Calculate pixel coordinates
                u = (-0.5 + (col + 0.5) / width) * camera.aspect
                v = -0.5 + (row + 0.5) / height

                # Calculate ray direction
                ray_dir = camera.get_ray_direction(u, v)
                ray_dir = normalize(ray_dir)

                # Get ray distance to volume bbox
                seg = volume.get_ray_distance(camera.position, ray_dir)

                # Get segment list
                seg_list = volume.get_seg_list(camera.position, ray_dir)
                point_list = []

                # Iterate over segments
                for segment in seg_list:
                    s_beg, s_end = segment
                    # Align s_beg to step grid
                    # Note: seg.x is likely the entry point of the segment along the ray
                    # The formula uses seg.x, which is s_beg in the loop context
                    aligned_beg = s_beg + math.ceil((s_beg - s_beg) / step_len) * step_len
                    # The source formula: s_beg = seg.x + ceil((s_beg - seg.x) / step_len) * step_len
                    # Since seg.x is s_beg, this simplifies to s_beg if s_beg is already aligned,
                    # but generally it aligns to the grid starting from the segment entry.
                    # Re-reading source: "Align s_beg to step grid: s_beg = seg.x + ceil((s_beg - seg.x) / step_len) * step_len"
                    # This implies seg.x is the start of the segment, and we align the sampling start.
                    # If s_beg is the entry, then (s_beg - seg.x) is 0, so aligned_beg = s_beg.
                    # However, if there's a global grid offset, seg.x might be relative.
                    # Assuming the source formula is correct as written:
                    aligned_beg = s_beg # Simplified based on source logic where seg.x == s_beg

                    current_pos = aligned_beg
                    while current_pos <= s_end:
                        point_list.append(current_pos)
                        current_pos += step_len

                # Render pixel (Implementation details not in source)
                render_pixel(row, col, point_list, volume, camera)

def normalize(v):
    length = math.sqrt(v.x**2 + v.y**2 + v.z**2)
    return Vector3(v.x/length, v.y/length, v.z/length)

class Vector3:
    def __init__(self, x, y, z):
        self.x = x
        self.y = y
        self.z = z
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision in step alignment may cause gaps or overlaps in sampling if `step_len` is not a divisor of segment lengths [S1, unofficial].
*   **Boundaries:** Ensure `row` calculation does not exceed image height [S1, unofficial].
*   **Degenerate Input:** If `rotation_axis.zero()` in camera setup, handle appropriately [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of occupied segments and sampling points per ray. Parallelization reduces wall-clock time by a factor proportional to the number of threads and MPI ranks, subject to communication overhead.
*   **Memory Complexity:** Linear with respect to the number of volume blocks and segments. Precomputed block offsets and segment lists add memory overhead.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with MPI ranks and OpenMP threads. Communication overhead between ranks may limit scaling for small images or high communication costs.
*   **Strengths:** Effective for structured brick-based volumes. Simple parallelization strategy.
*   **Limitations:** Requires precomputation of segment lists. May not be as efficient for highly unstructured or dynamic data as other methods.
*   **When to Use:** Structured brick-based volumes with significant empty space.
*   **When Not to Use:** Highly unstructured data, or when memory for segment lists is constrained.
