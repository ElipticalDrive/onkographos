# Resumable Ray Marching Iterator

Also called: OptiX7 Adaptive Ray Marching, Resumable Ray Marching

## Overview
The Resumable Ray Marching Iterator is a GPU-accelerated ray marching algorithm that enables the interruption and subsequent resumption of ray traversal within a single frame or across frames. It solves the problem of limited GPU memory bandwidth and compute time by allowing the ray marcher to pause at a specific spatial coordinate, transfer control to the CPU for data loading or structure adaptation, and resume exactly where it left off [S1, unofficial][S2, unofficial]. It sets itself apart from sibling methods by explicitly exposing the traversal state (macrocell coordinates and ray parameter $t$) for external interruption, rather than relying solely on pre-loaded hierarchical structures or probabilistic culling [S1, unofficial][S2, unofficial].

## How it works
The method extends [Adaptive Ray Marching with Macrocell DDA](1500-adaptive-ray-marching-with-macrocell-dda.md) by maintaining state variables that allow the traversal loop to be paused and resumed. It supports two modes: adaptive sampling (using macrocell DDA) and non-adaptive linear stepping.

### Inputs and Outputs
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized).
- Ray bounds $t_{min}$ and $t_{max}$.
- Volume dimensions $\mathbf{dims} = (D_x, D_y, D_z)$.
- Macrocell spacing parameters (implicit in `macrocell_spacings_rcp`).
- `ADAPTIVE_SAMPLING`: A preprocessor macro flag. If defined, adaptive logic is used; otherwise, linear stepping is used [S2, unofficial].

**Outputs:**
- Radiance and opacity accumulated via the `body(t)` callback.
- State payload (`SampleStreamingPayload`) containing the current traversal position for resumption.

### Data Structures
The traversal state is stored in `SampleStreamingPayload` [S1, unofficial].

**`SampleStreamingPayload` Layout:**
- `pixel_index`: Integer index of the current pixel.
- `jitter`: Floating-point jitter value.
- `alpha`: Accumulated opacity (float).
- `color`: Accumulated color (vec3f).
- If `ADAPTIVE_SAMPLING` is defined:
  - `iter.cell`: Current macrocell coordinates (vec3i or similar).
  - `iter.t_next`: Next ray parameter $t$ for the start of the next segment.
- Always present:
  - `iter.next_cell_begin`: Offset from $t_{min}$ to the next cell boundary. This is the key variable for resumption [S1, unofficial].

**`RadiancePayload` Layout:**
- `alpha`: float, initialized to 0.f.
- `color`: vec3f, initialized to 0.f.
- `rng`: void pointer, initialized to nullptr [S2, unofficial].

**`ShadowPayload` Layout:**
- `alpha`: float, initialized to 0.f.
- `rng`: void pointer, initialized to nullptr [S2, unofficial].

### Algorithm Steps

#### 1. Initialization
If `ADAPTIVE_SAMPLING` is defined, initialize the Digital Differential Analyzer (DDA) iterator with the ray origin, direction, bounds, and volume dimensions [S1, unofficial]:
```python
dda_iter.init(m_org, m_dir, t_min, t_max, dims)
```
Where `m_org` and `m_dir` are computed as:
$$
\mathbf{m}_{org} = \mathbf{o} \cdot \mathbf{s}_{rcp}, \quad \mathbf{m}_{dir} = \mathbf{d} \cdot \mathbf{s}_{rcp}
$$
Here $\mathbf{s}_{rcp}$ is the reciprocal of the macrocell spacing [S2, unofficial].

If `ADAPTIVE_SAMPLING` is not defined, initialize the linear step tracker:
$$
t.x = \max(t_{min} + \text{next\_cell\_begin}, t_{min})
$$
$$
t.y = \min(t.x + \text{step}, t_{max})
$$
[S1, unofficial]

#### 2. Traversal Loop (Adaptive Mode)
The core loop iterates over macrocells using the DDA. For each macrocell interval $[t_0, t_1]$:

1.  **Opacity Upper Bound Check:** Calculate the opacity upper bound $r$ for the current macrocell [S2, unofficial].
    $$
    r = \text{opacityUpperBound}(\text{self}, \text{cell})
    $$
2.  **Empty Space Skipping:** If $|r| \le \epsilon$ (where $\epsilon$ is `float_epsilon`), the macrocell is considered empty. Return `true` to continue the DDA to the next cell [S2, unofficial].
3.  **Step Size Calculation:** Calculate the adaptive step size $ss$ [S2, unofficial]:
    $$
    ss = \text{adaptiveSamplingRate}(\text{step}, r)
    $$
    The effective step size within the interval is normalized by `sample_size_scaler`:
    $$
    N = \lfloor (t_1 - t_0) / ss \rfloor + 1
    $$
    $$
    \text{effective\_step} = (t_1 - t_0) / N
    $$
    [S2, unofficial]
4.  **Inner Loop:** Initialize $t = (t_0, \min(t_1, t_0 + ss))$. While $t.y > t.x$:
    - Set `next_cell_begin` = $t.y - t_{min}$ [S1, unofficial].
    - Call `body(t)` to accumulate radiance/opacity for the segment $[t.x, t.y]$ [S1, unofficial].
    - Update $t.x = t.y$ and $t.y = \min(t.x + ss, t_1)$ [S1, unofficial].

The outer loop continues while `DDAIter::next(..., lambda)` returns true [S1, unofficial].

#### 3. Traversal Loop (Non-Adaptive Mode)
If `ADAPTIVE_SAMPLING` is not defined, iterate linearly from $t_{min}$ to $t_{max}$ with a fixed `step` [S2, unofficial]:

1.  While $t.y > t.x$:
    - Set `next_cell_begin` = $t.y - t_{min}$ [S1, unofficial].
    - Call `body(t)` [S1, unofficial].
    - Update $t.x = t.y$ and $t.y = \min(t.x + \text{step}, t_{max})$ [S1, unofficial].
2.  After the loop, set `next_cell_begin` = `float_large` and return [S1, unofficial].

#### 4. Resumption Check
To determine if the ray marcher can be resumed later, the method checks the remaining distance to $t_{max}$ [S1, unofficial]:

- If `ADAPTIVE_SAMPLING` is defined:
  $$
  \text{resumable} = \text{DDAIter::resumable}(\mathbf{m}_{dir}, t_{min}, t_{max}, \mathbf{dims})
  $$
  [S1, unofficial]
- If `ADAPTIVE_SAMPLING` is not defined:
  $$
  \text{resumable} = (t_{min} + \text{next\_cell\_begin} < t_{max})
  $$
  [S1, unofficial]

If resumable, the current state (specifically `next_cell_begin`, and `iter.cell`/`iter.t_next` in adaptive mode) is saved to the payload. The CPU can then load missing data. Upon resumption, the iterator is re-initialized or continued using the saved `next_cell_begin` value [S1, unofficial].

#### 5. Shadow Ray Tracing (Optional)
For shadow rays, a `ShadowPayload` is created with a random number generator pointer packed into `u0` and `u1` [S2, unofficial]. The ray is traced using `optixTrace` with specific flags (`OPTIX_RAY_FLAG_DISABLE_ANYHIT`) and types (`SHADOW_RAY_TYPE`) [S2, unofficial]. The transmittance is returned as $1.0 - \text{shadow.alpha}$ [S2, unofficial].

### Pseudocode
```python
def resumable_ray_marching_iterator(o, d, t_min, t_max, dims, macrocell_spacings_rcp, step, body, adaptive_sampling):
    """
    Executes a resumable ray march.
    Returns (payload, is_resumable).
    """
    payload = SampleStreamingPayload()
    payload.alpha = 0.0
    payload.color = vec3f(0.0, 0.0, 0.0)
    
    # State for resumption
    next_cell_begin = 0.0
    
    if adaptive_sampling:
        # Initialize DDA for macrocells
        m_org = o * macrocell_spacings_rcp
        m_dir = d * macrocell_spacings_rcp
        dda_iter = DDAIter()
        dda_iter.init(m_org, m_dir, t_min, t_max, dims)
        
        def process_cell(cell, t0, t1):
            nonlocal next_cell_begin
            # Calculate opacity upper bound
            r = opacity_upper_bound(cell)
            
            # Skip empty cells
            if abs(r) <= float_epsilon:
                return True # Continue DDA
            
            # Calculate adaptive step
            ss = adaptive_sampling_rate(step, r)
            
            # Normalize step to fit integer number of steps in interval
            n_steps = floor((t1 - t0) / ss) + 1
            effective_step = (t1 - t0) / n_steps
            
            t_curr = vec2f(t0, min(t1, t0 + effective_step))
            
            while t_curr.y > t_curr.x:
                next_cell_begin = t_curr.y - t_min
                body(t_curr)
                t_curr.x = t_curr.y
                t_curr.y = min(t_curr.x + effective_step, t1)
            
            return True # Continue DDA
        
        # DDA Loop
        while dda_iter.next(process_cell):
            pass
            
        # Check resumability
        is_resumable = dda_iter.resumable(m_dir, t_min, t_max, dims)
        
        # Save state
        payload.iter.cell = dda_iter.current_cell
        payload.iter.t_next = dda_iter.current_t
        payload.iter.next_cell_begin = next_cell_begin
        
    else:
        # Non-adaptive linear stepping
        t_curr = vec2f(max(t_min + next_cell_begin, t_min), min(t_min + next_cell_begin + step, t_max))
        
        while t_curr.y > t_curr.x:
            next_cell_begin = t_curr.y - t_min
            body(t_curr)
            t_curr.x = t_curr.y
            t_curr.y = min(t_curr.x + step, t_max)
            
        next_cell_begin = float_large
        is_resumable = (t_min + next_cell_begin < t_max)
        
        payload.iter.next_cell_begin = next_cell_begin
        
    return payload, is_resumable
```

### Edge Cases and Pitfalls
- **Precision:** The check `fabsf(r) <= float_epsilon` requires careful selection of `float_epsilon` to avoid skipping valid low-opacity regions or processing empty ones due to floating-point noise [S2, unofficial].
- **Resumption State:** The `next_cell_begin` variable must be correctly preserved and restored. If the ray is resumed, the initial $t$ calculation must use the saved `next_cell_begin` to avoid re-processing segments [S1, unofficial].
- **Macrocell Boundaries:** In adaptive mode, the step size normalization ensures that the last segment in a macrocell does not exceed $t_1$, preventing out-of-bounds access or double-counting at boundaries [S2, unofficial].
- **ADAPTIVE_SAMPLING Flag:** If `ADAPTIVE_SAMPLING` is not defined, the code path for macrocell DDA is excluded, and the compiler may error if adaptive-specific members are accessed [S2, unofficial].

## Subtopics

### [Ray-Guided Streaming with Interrupt/Resume](2600-ray-guided-streaming-with-interrupt-resume.md)
Handles missing GPU memory data by stopping ray tracing, communicating to the CPU for loading, and resuming the algorithm at the last ray position, requiring multiple passes per frame. It sets itself apart from sibling methods by explicitly pausing the GPU ray marcher to allow CPU-driven data structure adaptation, rather than relying solely on pre-loaded hierarchical structures or probabilistic culling.

### [Woodcock Collision Estimation (Standard)](3331-woodcock-collision-estimation-standard.md)
A ray marching technique for volume rendering that uses Woodcock collision estimation (delta tracking) to skip empty space, avoiding the need for spatial acceleration structures for sampling but requiring a global maximum density estimate. It differs from sibling methods like [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md) by avoiding the need for spatial acceleration structures for sampling, instead relying on probabilistic step sizing based on a global maximum density estimate.

### [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md)
Adaptive Ray Marching with Voxel Skipping is a visibility culling technique for direct volume rendering that accelerates ray marching by dynamically adjusting the step size based on local density. It solves the problem of excessive sampling in large empty volumes by using a low-precision traversal algorithm for empty regions and switching to a high-precision algorithm when approaching data. It differs from standard empty-space skipping by dynamically adjusting precision based on proximity to data, rather than using a static skip distance or hierarchical structure like [Adaptive Ray Marching with Macrocell DDA](3869-adaptive-ray-marching-with-macrocell-dda.md).

### [Voxel Bricks](5794-voxel-bricks.md)
Voxel Bricks is a space-skipping acceleration structure for voxel ray marching that groups voxels into fixed-size $8 \times 8 \times 8$ blocks (bricks) and maintains a sparse index (brickgrid) to reference only non-empty bricks. It solves the problem of excessive memory bandwidth and traversal overhead in dense or sparse voxel volumes by skipping entire empty regions without visiting individual voxels. Unlike [Adaptive Ray Marching with Voxel Skipping](3870-adaptive-ray-marching-with-voxel-skipping.md) which may use variable-sized blocks or different culling criteria, Voxel Bricks relies on a strict two-level hierarchy: a sparse grid of pointers/references and fixed $8^3$ bricks, offering minimal structural overhead suitable for interactive, dynamic voxel worlds.

### [Block Predicate Filtering](9106-block-predicate-filtering.md)
Block Predicate Filtering is a culling technique that evaluates a user-defined predicate on each grid block using affine arithmetic to determine if the block's domain can possibly contain a zero of the scalar field, skipping blocks that cannot before scalar evaluation. Compared to naive block mask extraction, it filters blocks before scalar evaluation, reducing computation. It builds on [Resumable Ray Marching Iterator](1505-resumable-ray-marching-iterator.md) by providing a coarse-grained filtering mechanism that reduces the number of expensive scalar field evaluations required during ray marching [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of samples, but effectively reduced by empty space skipping. In adaptive mode, the number of samples is proportional to the opacity variation within macrocells [S2, unofficial].
- **Memory Complexity:** $O(1)$ per ray for the iterator state, plus the memory for the volume data and acceleration structures (macrocells) [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales with the number of rays (pixels) and the complexity of the volume. Adaptive sampling reduces samples in empty regions, improving performance for sparse volumes [S2, unofficial].
- **Strengths:** Enables handling of large volumes that do not fit in GPU memory by allowing CPU-GPU data streaming [S1, unofficial][S2, unofficial]. Reduces unnecessary computation in empty space [S2, unofficial].
- **Limitations:** Requires careful state management for resumption. Overhead of DDA and macrocell traversal may be significant for very small volumes or dense volumes with little empty space [S1, unofficial][S2, unofficial].
- **When to use:** When rendering large volumes that exceed GPU memory capacity or when real-time performance requires dynamic data loading [S1, unofficial][S2, unofficial].
- **When not to use:** For small, fully resident volumes where the overhead of state management and resumption logic outweighs the benefits of streaming [G].

## Background
The Resumable Ray Marching Iterator is part of the Open Volume Renderer (OVR) project, developed by VIDILabs [S1, unofficial][S2, unofficial]. It is designed for integration with NVIDIA OptiX 7, leveraging its ray tracing capabilities for efficient traversal and shading [S2, unofficial]. The method addresses the limitations of traditional ray marching by introducing resumability, which is crucial for interactive and large-scale volume rendering applications [S1, unofficial][S2, unofficial].
