# Visibility Culling


## Overview
Visibility Culling is a family of acceleration techniques that reduce the computational cost of volume rendering by identifying and excluding primitives, voxels, or ray segments that do not contribute to the final image [G]. It sets itself apart from sibling methods like [Bounding Volume Empty-Space Culling](17140-bounding-volume-empty-space-culling.md) by focusing on optical or geometric occlusion rather than purely geometric emptiness, and from [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md) by often operating on broader spatial or temporal scopes (e.g., frame-to-frame feedback or precomputed masks) rather than just per-ray state.

## Shared principles
The core mechanism shared by all methods in this family is the reduction of work units (samples, voxels, or pixels) processed per frame while maintaining acceptable visual fidelity [G]. This is achieved through three primary strategies:
1. **Culling/Skipping:** Identifying regions of the volume or ray path that do not contribute to the final image (e.g., empty space, occluded voxels) and bypassing their evaluation.
2. **Termination:** Halting the integration loop when the accumulated contribution becomes negligible (e.g., high opacity, low transmittance) [S1, unofficial].
3. **Adaptation:** Varying the computational effort based on local scene complexity or global performance budgets [S1, unofficial].

Mathematically, these methods modify the standard front-to-back compositing loop:
$$ C_{acc} = C_{acc} + C_{sample} \cdot \alpha_{sample} \cdot (1 - \alpha_{acc}) $$
$$ \alpha_{acc} = \alpha_{acc} + \alpha_{sample} \cdot (1 - \alpha_{acc}) $$
by introducing conditions that break the loop early, skip iterations, or reduce the number of $C_{sample}$ queries.

## Subtopics

### [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md)
Early Termination and Probabilistic Path Control are acceleration techniques that reduce the computational cost of volume rendering by halting the ray-marching integration loop when the remaining contribution to the pixel is deemed negligible. Unlike [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md) which culls based on pre-computed opacity maps, or [Empty-space skipping](1002-empty-space-skipping.md) which skips geometrically empty regions, these methods operate on the accumulated state of the ray during traversal. They set themselves apart from [Bounding Volume Culling](1239-bounding-volume-culling.md) by relying on optical properties (opacity/transmittance) rather than geometric bounds, and from [Adaptive Multi-Step Empty Voxel Skipping](6289-adaptive-multi-step-empty-voxel-skipping.md) by focusing on the termination of the integration path rather than the step size.

### [Probabilistic Culling](2833-probabilistic-culling.md)
Probabilistic Culling is a rendering optimization that intentionally allows false-negatives in intersection tests to reduce duplicated fragments and rendering time, particularly in virtual reality (VR) and high-resolution contexts. It sets itself apart from conservative culling methods (like [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md)) by trading strict geometric accuracy for performance, relying on the fact that the resulting visual artifacts are often imperceptible to the human eye.

### [Visibility Feedback with Screen Space Subdivision](3439-visibility-feedback-with-screen-space-subdivision.md)
Visibility Feedback with Screen Space Subdivision is an out-of-core volume rendering optimization that uses visibility information gathered during the current frame to prevent the loading and refinement of occluded data in subsequent frames. Unlike standard early ray termination, which only skips computation after data has already been loaded into the GPU working set, this method feeds visibility results back to the loader to reduce GPU memory usage and bandwidth. It distinguishes itself from sibling methods by combining occlusion queries with a screen-space subdivision strategy to interleave query processing with rasterization, thereby hiding the latency inherent in asynchronous occlusion query results.

### [Adaptive Multi-Step Empty Voxel Skipping](6289-adaptive-multi-step-empty-voxel-skipping.md)
Adaptive Multi-Step Empty Voxel Skipping is an acceleration technique for direct volume rendering that combines space leaping (empty voxel skipping) with adaptive variable step-size sampling. It solves the problem of redundant computation in large datasets containing significant empty space, such as medical CT scans, by bypassing empty regions entirely and adjusting sampling density based on local voxel occupancy. Unlike traditional equidistant ray casting, this method reduces computational overhead without altering the input data structure, distinguishing itself from siblings like [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md) by operating directly on the ray traversal logic rather than pre-computed opacity maps.

### [24-Region View-Dependent Visibility Preprocessing](6608-24-region-view-dependent-visibility-preprocessing.md)
A preprocessing technique that decomposes the domain of viewing directions into 24 regions on a directional cube to extract a lower number of potentially visible voxels compared to the standard 6-region decomposition, improving extraction rate and rendering speed. It sets itself apart from [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md) by using directional decomposition rather than orthogonal projections, and from [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md) by performing static visibility culling rather than dynamic ray termination.

### [Frustum Culling](8463-frustum-culling.md)
Frustum culling is a visibility culling technique that reduces rendering load by identifying and excluding volume chunks, segments, or primitives that lie outside the camera's viewing frustum. It solves the problem of unnecessary computation for geometry that does not contribute to the final image by performing a conservative intersection test between bounding volumes and the six planes defining the view frustum. Unlike [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md) which handles depth-based occlusion, or [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md) which handles transmittance, frustum culling operates on spatial extent relative to the camera orientation and projection.

### [Interactive Render Quality Estimation & Cancellation](8895-interactive-render-quality-estimation-cancellation.md)
This method prevents infinite rendering loops in interactive volume visualization by detecting when the rendering pipeline cannot keep up with the frame budget and forcing a quality reduction on the subsequent frame. It acts as a safety mechanism within the traversal loop, distinct from standard early termination which stops a single ray based on opacity [1791-early-termination-and-probabilistic-path-control.md]. Unlike [Occlusion Clipping with Orthogonal Opacity Map](990-occlusion-clipping-with-orthogonal-opacity-map.md) which culls based on precomputed depth, this method reacts to runtime performance failures by lowering the sampling density or resolution.

### [Visible Zone Algorithm](9086-visible-zone-algorithm.md)
The Visible Zone Algorithm is a conservative visibility computation method that determines which primitives (typically points or voxels) are potentially visible from a set of viewpoints by projecting them into screen space and retaining only those within a specified depth thickness. It solves the problem of efficiently culling occluded geometry in volume rendering and point cloud visualization by precomputing a visibility mask, allowing for significant reduction in rendering work without sacrificing visual correctness. It sets itself apart from its siblings by providing a strict worst-case correctness guarantee for visibility, unlike approximate methods that trade accuracy for speed.

### [Occlusion-Aware Visibility Filter](17171-occlusion-aware-visibility-filter.md)
The Occlusion-Aware Visibility Filter replaces the standard view-frustum test in 3D Gaussian Splatting densification with a rendering-based signal that restricts statistical updates to Gaussians that actually contribute to the final image. Unlike sibling methods that rely on binary flags or pixel counts, this method uses the sum of blending weights to determine visibility, ensuring that occluded Gaussians do not accumulate densification statistics.

### Screen Regions
#### definition
- [S1, unofficial] An optimization dividing image space into equal-sized squares of n x n pixels to reduce overhead from per-pixel visibility testing. If a screen region is full, rasterization skips to the next boundary.
#### number
- [S1, unofficial] Screen regions save another 3 percent of overall rendering time on average.

### Visibility Culling via Scalar Range Lookup Table
#### definition
- [S2] A GPU-based visibility test using a 2*D* Boolean lookup table to cull cells that do not intersect the transfer function's opacity range, reducing load on the rendering stage.
#### step
- [S2] Geometry shader computes the minimum and maximum of the 8 cell corner values. These two values are used as table lookup indices to fetch a visibility value. If the cell is deemed visible, the geometry shader instantiates its 6 faces.
#### parameter
- [S2] Visibility Lookup Table: A 2*D* table where D is the number of scalar value bins. For each pair of values s1 and s2, the table holds 1 if there exists at least an opacity which is non-zero for scalar values in [s1, s2], otherwise 0.
#### number
- [S2] On a PC with two Xeon E5345 processors, 4GB memory, GeForce 8800 GTX (768MB), using the 'meteorite' dataset (2,377,878 cells), removing the look-up table drops performance to <1 fps (specifically 0.76 fps). Adding the look-up table increases framerate to ~3.48 fps.
- [S2] Adding the hybrid CPU-GPU mesh traversal mechanism to the look-up table optimization increases the framerate to 3.62 fps.

## Background
Visibility culling in volume rendering has evolved from simple geometric checks to complex, feedback-driven systems. Early methods focused on reducing the overhead of per-pixel visibility tests by grouping pixels into screen regions [S1, unofficial]. As datasets grew, preprocessing techniques like view-dependent visibility masks were introduced to statically cull invisible voxels based on viewing direction [S1, unofficial]. Modern approaches, particularly in interactive and neural rendering contexts, utilize dynamic feedback (e.g., screen-space subdivision) and probabilistic approximations to balance performance and visual fidelity [S1, unofficial][S2].
