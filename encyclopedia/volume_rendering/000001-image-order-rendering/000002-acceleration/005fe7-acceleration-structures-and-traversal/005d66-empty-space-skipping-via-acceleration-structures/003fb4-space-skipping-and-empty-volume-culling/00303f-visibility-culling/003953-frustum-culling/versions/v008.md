# Frustum Culling

Also called: View Frustum Culling, markVisible

## Overview
Frustum culling is a visibility culling technique that reduces rendering load by filtering out faces, chunks, or primitives that lie outside the camera's viewing frustum [S3, unofficial][S5, unofficial][S8, unofficial]. It solves the problem of unnecessary computation for geometry that does not contribute to the final image by performing a conservative intersection test between bounding volumes and the six planes defining the view frustum [S3, unofficial][S8, unofficial]. It operates on spatial extent relative to the camera orientation and projection, distinguishing it from depth-based occlusion or transmittance-termination methods [G].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Spatial entities (chunks, blocks, segments, or points) defined by bounding volumes (spheres or axis-aligned boxes) [S3, unofficial][S5, unofficial][S7, unofficial]. Camera parameters: view matrix ($V$), projection matrix ($P$), near plane distance ($n$), and far plane distance ($f$) [S4, unofficial].
*   **Outputs:** A boolean tensor or mask indicating which entities are visible within the frustum [S1, unofficial][S4, unofficial].

**Data Structures:**
*   **Bounding Sphere:** Defined by center $c_k = (x_k, y_k, z_k)$ and radius $r_k$ [S10, unofficial].
*   **Axis-Aligned Bounding Box (AABB):** Defined by minimum and maximum corner vectors $bmin = (bmin[0], bmin[1], bmin[2])$ and $bmax = (bmax[0], bmax[1], bmax[2])$ [S7, unofficial].
*   **Frustum Planes:** Six planes derived from the combined projection-view matrix $M = P \cdot V$, each represented by coefficients $(a, b, c, d)$ for the plane equation $ax + by + cz + d = 0$ [S7, unofficial].

**Numbered Steps:**
1.  Extract the six frustum planes from the combined matrix $M = P \cdot V$ [G].
2.  For each entity, compute its signed distance to every frustum plane [G].
3.  Apply the sphere or AABB intersection test against all six planes [G].
4.  If the entity fails any single plane test, mark it as culled; otherwise, mark it as visible [S3, unofficial][S7, unofficial][S10, unofficial].
5.  For hierarchical structures, test the node's bounding volume first; if the node is fully outside, discard the entire subtree; if fully inside, accept all descendants; if intersecting, recurse into children [S3, unofficial][S8, unofficial].

**Formulas:**
*   **Sphere Frustum Test:** For a plane with coefficients $(a, b, c, d)$ and sphere center $(x_k, y_k, z_k)$, the signed distance is $dist = a x_k + b y_k + c z_k + d$. The sphere is culled if $dist < -r_k$ for any plane [S10, unofficial].
*   **AABB Frustum Test (Positive-Vertex Test):** For each plane $(a, b, c, d)$, select the box corner farthest along the plane's normal: $px = bmax[0]$ if $a \ge 0$ else $bmin[0]$, $py = bmax[1]$ if $b \ge 0$ else $bmin[1]$, $pz = bmax[2]$ if $c \ge 0$ else $bmin[2]$ [S7, unofficial]. Evaluate $val = a \cdot px + b \cdot py + c \cdot pz + d$ [S7, unofficial]. If $val < 0$ for any plane, the box is culled [S7, unofficial].
*   **Active Block Set (Two-Level Variant):** $\mathcal{K}_t = \bigcup_{c \in \mathcal{B}_t} \{k \mid \text{visible}(k, c)\}$, where $\mathcal{B}_t$ is the camera batch and $k$ is a block [S10, unofficial].

**Parameters:**
*   **Camera Configuration:** Typical helper implementations use FOV 20°, aspect ratio 1.77, near plane 0.5, and far plane 5 [S11, unofficial].
*   **Depth Tolerance:** When combined with depth-based visibility, a relative tolerance $\epsilon = 0.15$ is used to account for Gaussian mean positions and depth smoothing [S12, unofficial].

**Edge Cases and Pitfalls:**
*   **Chunk Center Accuracy:** Incorrect calculation of chunk centers during map loading can cause valid chunks to disappear erroneously [S5, unofficial].
*   **Boundary Definitions:** Using spherical boundaries for frustum culling alongside Euclidean distance for proximity culling can produce visible artifacts or inconsistencies [S5, unofficial].
*   **Mutual Exclusivity:** Some implementations cannot run frustum and proximity culling simultaneously due to conflicting state management [S5, unofficial].
*   **Conservatism:** The positive-vertex AABB test is conservative; it never hides a point that should be shown, but may retain nodes that are mostly outside the frustum yet have a corner inside [S7, unofficial].

**Pseudocode:**
```python
import math

def multiply_matrices(A, B):
    """Multiplies two 4x4 matrices (row-major layout)."""
    C = [[0.0]*4 for _ in range(4)]
    for i in range(4):
        for j in range(4):
            for k in range(4):
                C[i][j] += A[i][k] * B[k][j]
    return C

def normalize_plane(plane):
    """Normalizes plane coefficients (a,b,c,d) so the normal vector has unit length."""
    a, b, c, d = plane
    length = math.sqrt(a*a + b*b + c*c)
    if length == 0:
        return (0.0, 0.0, 0.0, 0.0)
    return (a/length, b/length, c/length, d/length)

def extract_frustum_planes(view_matrix, proj_matrix):
    """Extracts 6 planes from the combined projection-view matrix M = P * V."""
    M = multiply_matrices(proj_matrix, view_matrix)
    planes = []
    # M is stored as row-major list of rows. Standard OpenGL extraction uses columns:
    # Left: M[3] + M[0], Right: M[3] - M[0], Bottom: M[3] + M[1], Top: M[3] - M[1], Near: M[3] + M[2], Far: M[3] - M[2]
    planes.append(normalize_plane((M[0][3] + M[0][0], M[1][3] + M[1][0], M[2][3] + M[2][0], M[3][3] + M[3][0]))) # Left
    planes.append(normalize_plane((M[0][3] - M[0][0], M[1][3] - M[1][0], M[2][3] - M[2][0], M[3][3] - M[3][0]))) # Right
    planes.append(normalize_plane((M[0][3] + M[0][1], M[1][3] + M[1][1], M[2][3] + M[2][1], M[3][3] + M[3][1]))) # Bottom
    planes.append(normalize_plane((M[0][3] - M[0][1], M[1][3] - M[1][1], M[2][3] - M[2][1], M[3][3] - M[3][1]))) # Top
    planes.append(normalize_plane((M[0][3] + M[0][2], M[1][3] + M[1][2], M[2][3] + M[2][2], M[3][3] + M[2][3]))) # Near
    planes.append(normalize_plane((M[0][3] - M[0][2], M[1][3] - M[1][2], M[2][3] - M[2][2], M[3][3] - M[2][3]))) # Far
    return planes

def sphere_frustum_test(center, radius, planes):
    """Tests if a sphere intersects the frustum. Returns True if visible."""
    for a, b, c, d in planes:
        dist = a*center[0] + b*center[1] + c*center[2] + d
        if dist < -radius:
            return False
    return True

def aabb_frustum_test(bmin, bmax, planes):
    """Tests if an AABB intersects the frustum using the positive-vertex test."""
    for a, b, c, d in planes:
        px = bmax[0] if a >= 0 else bmin[0]
        py = bmax[1] if b >= 0 else bmin[1]
        pz = bmax[2] if c >= 0 else bmin[2]
        if a*px + b*py + c*pz + d < 0:
            return False
    return True

def frustum_cull_entities(entities, view_matrix, proj_matrix):
    """
    entities: List of dicts with 'type' ('sphere' or 'aabb'), 'center', 'radius', 'bmin', 'bmax'.
    Returns a boolean list indicating visibility.
    """
    planes = extract_frustum_planes(view_matrix, proj_matrix)
    visible_mask = []
    for entity in entities:
        if entity["type"] == "sphere":
            visible_mask.append(sphere_frustum_test(entity["center"], entity["radius"], planes))
        elif entity["type"] == "aabb":
            visible_mask.append(aabb_frustum_test(entity["bmin"], entity["bmax"], planes))
        else:
            # Not given in the sources.
            visible_mask.append(False)
    return visible_mask
```

## Subtopics

### View Frustum Culling for Segments
An optimization technique specifically for segment-based tetrahedral meshing [S9]. It rejects segments lying outside the view frustum early in the rendering pipeline to counteract over-refinement caused by Directed Acyclic Graph (DAG) dependencies, thereby reducing mesh size and computational load [S9].

### Two-Level Visibility Culling
A hierarchical approach used in out-of-core 3D Gaussian Splatting (TideGS) [S10, unofficial]. Level 1 (CPU) computes an active block set $\mathcal{K}_t = \bigcup_{c \in \mathcal{B}_t} \{k \mid \text{visible}(k, c)\}$ for a camera batch $\mathcal{B}_t$ using coarse bounding spheres with center $c_k$ and radius $r_k$ [S10, unofficial]. It applies a 6-plane frustum test and culls a sphere if its signed distance to any plane satisfies $d < -r_k$ [S10, unofficial]. Level 2 (GPU) materializes selected resident blocks $R_t$ in VRAM, runs the standard 3DGS projection/rasterization pipeline, determines the final contributing set $I_t$, and restricts the forward/backward pass to only Gaussians in $I_t$ [S10, unofficial]. Level 1 is conservative and may admit extra blocks, while Level 2 applies exact pipeline semantics [S10, unofficial].

### Frustum Culling Helper
A helper class implementation that uses a camera's frustum to cull an octree and visualizes intersecting octants with an `InstancedMesh` [S11, unofficial]. It constructs a `PerspectiveCamera` with FOV 20°, aspect 1.77, near 0.5, and far 5, and initializes camera position using spherical coordinates (radius 5, phi $\pi/3$, theta $\pi \cdot 1.75$) [S11, unofficial]. It computes the frustum from `projectionMatrix * matrixWorldInverse`, iterates through octree nodes, and updates an `InstancedMesh` (BoxGeometry 1,1,1, capacity 2500) with the center and dimensions of intersecting octants [S11, unofficial].

### Depth-based Visibility Culling
A selection method for error feature aggregation that combines frustum and depth tests to ensure only views observing a token's surface are used [S12, unofficial]. The frustum test transforms the token mean position $p_j$ into the camera frame to obtain depth $d_{jn}$, projects it to pixel $u_{jn}$, and passes the view if $d_{jn} > 0$ and $0 \le u < W, 0 \le v < H$ [S12, unofficial]. The depth test samples the expected depth $D_n$ at $u_{jn}$ and keeps the view if $d_{jn} \le (1 + \epsilon) D_n(u_{jn})$ with $\epsilon = 0.15$ [S12, unofficial]. The tolerance handles Gaussian mean offsets and depth smoothing at discontinuities [S12, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ for flat entity lists, where $N$ is the number of bounding volumes [S3, unofficial][S7, unofficial]. $O(\log N)$ or better for balanced hierarchical structures, as entire subtrees are discarded with a single box test [S3, unofficial][S7, unofficial].
*   **Memory Complexity:** $O(N)$ to store bounding volumes and visibility masks [S1, unofficial][S5, unofficial].
*   **Performance:** Significantly reduces GPU and PCIe/SSD transfer costs by filtering blocks before data movement [S10, unofficial]. Prevents performance bottlenecks from over-refined meshes outside the view in segment-based rendering [S9].
*   **Strengths:** Simple to implement, highly effective for large sparse scenes, and conservative (never hides visible geometry) [S7, unofficial][S8, unofficial].
*   **Limitations:** Conservative bounding volumes may admit extra geometry; accuracy depends on precise bounding volume generation; some implementations cannot combine it with proximity culling [S5, unofficial][S7, unofficial].

## Background
Frustum culling is a fundamental computer graphics optimization technique originally developed to avoid processing geometry outside the camera's field of view [S3, unofficial][S8, unofficial]. Møller and Haines discuss several algorithms for volume/frustum intersection [S8, unofficial]. It is widely applied in out-of-core visualization, voxel rendering, and modern 3D Gaussian Splatting pipelines to manage memory and processing loads [S3, unofficial][S5, unofficial][S10, unofficial].
