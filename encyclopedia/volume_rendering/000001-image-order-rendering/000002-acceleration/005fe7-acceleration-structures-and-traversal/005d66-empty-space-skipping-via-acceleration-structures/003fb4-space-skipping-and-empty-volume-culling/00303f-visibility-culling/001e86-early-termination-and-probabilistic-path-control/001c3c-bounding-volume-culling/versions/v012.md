# Bounding Volume Culling

Also called: Distance-based Culling, Ray Termination by Distance

## Overview
Bounding Volume Culling is an optimization that limits raymarching to a specific geometric boundary, dropping rays that exceed a certain distance from the eye or miss the volume entirely to speed up rendering [S1, unofficial][S3, unofficial][S4]. It differs from its parent, [Early Termination and Probabilistic Path Control](1791-early-termination-and-probabilistic-path-control.md), which relies on accumulated opacity or transmittance to stop integration, by using hard geometric constraints to discard rays before or during traversal [S1, unofficial][S2]. Unlike [Empty-space skipping](1002-empty-space-skipping.md), which skips empty voxels within a defined volume, Bounding Volume Culling often rejects the entire ray if it does not intersect the volume's outer bounds [S3, unofficial].

## How it works
The method varies by the type of bounding volume used (scalar distance limit, axis-aligned box, or heap-managed collection) [S1, unofficial][S3, unofficial][S2]. The core principle is to compute a distance or intersection test against the bounding geometry before or during the sampling loop [S1, unofficial][S3, unofficial][S2].

### Inputs and Outputs
*   **Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, bounding volume definition (e.g., max distance $D_{max}$, AABB min/max, or list of bounding volumes), and the volume data structure [G].
*   **Outputs:** A color value (or background) if the ray is culled or fully processed; otherwise, the result of the raymarching loop [G].

### Data Structures
1.  **Scalar Limit:** A single floating-point value $D_{max}$ representing the maximum travel distance [S1, unofficial].
2.  **AABB:** Two 3D vectors $\mathbf{min}$ and $\mathbf{max}$ defining the box extents [S3, unofficial][S4].
3.  **Heap (for Sphere Tracing):** A priority queue (min-heap) storing pairs of $(d_{bv}, \text{object\_id})$, where $d_{bv}$ is the distance to the bounding volume [S2].

### Algorithm: Scalar Distance Culling
This variant tracks the total distance traveled by the ray and terminates if it exceeds a predefined limit [S1, unofficial].

```python
def scalar_distance_culling(o, d, D_max, dt):
    t = 0.0
    C_acc = (0.0, 0.0, 0.0)
    alpha_acc = 0.0
    while t < D_max:
        C_sample = sample_volume(o + t * d)  # Standard volume query [G]
        alpha_sample = C_sample[3]
        C_acc = C_acc + C_sample[:3] * alpha_sample * (1.0 - alpha_acc)
        alpha_acc = alpha_acc + alpha_sample * (1.0 - alpha_acc)
        t += dt
    return C_acc  # Returns accumulated color or background if loop finishes [S1, unofficial]
```

### Algorithm: AABB Culling
This variant uses the six planar faces of a rectangular grid volume to reject rays that do not intersect the volume [S3, unofficial][S4]. The intersection interval $[t_{enter}, t_{exit}]$ is computed as:
$$ t_{min} = \max_{i \in \{x,y,z\}} \left( \frac{\min_i - o_i}{d_i} \right), \quad t_{max} = \min_{i \in \{x,y,z\}} \left( \frac{\max_i - o_i}{d_i} \right) $$
Division by zero for $d_i = 0$ is handled by treating the term as $-\infty$ or $+\infty$ appropriately [G].

```python
def aabb_culling(o, d, min_box, max_box, dt):
    t_min = max((min_box[i] - o[i]) / d[i] if d[i] != 0 else float('-inf') for i in range(3))
    t_max = min((max_box[i] - o[i]) / d[i] if d[i] != 0 else float('inf') for i in range(3))
    if t_max < 0 or t_min > t_max:
        return background_color  # Ray misses volume [S3, unofficial][S4]
    t_start = max(t_min, 0.0)    # Clamp start to near plane [G]
    t_end = t_max                # End at far intersection [G]
    C_acc = (0.0, 0.0, 0.0)
    alpha_acc = 0.0
    t = t_start
    while t < t_end:
        C_sample = sample_volume(o + t * d)  # Standard volume query [G]
        alpha_sample = C_sample[3]
        C_acc = C_acc + C_sample[:3] * alpha_sample * (1.0 - alpha_acc)
        alpha_acc = alpha_acc + alpha_sample * (1.0 - alpha_acc)
        t += dt
    return C_acc
```

### Algorithm: Heap-based Bounding Volume Culling (Sphere Tracing)
This variant finds the closest object in a collection by maintaining a heap of bounding volume distances, culling based on the smallest bounding volume distance [S2].

```python
def heap_bv_culling(bounding_volumes):
    heap = min_heap([(distance_to_bv(bv), bv) for bv in bounding_volumes])  # Compute distances and build heap [G]
    d_min = float('inf')
    while heap:
        d_top, bv = heap[0]  # Peek top [G]
        d_content = min(d_min, distance_to_contents(bv))  # Step 4 [S2]
        d_min = d_content
        heap.pop()  # Step 5 [S2]
        if not heap:
            return d_content  # Step 7: heap empty [S2]
        d_next_bv = heap[0][0]  # Step 6 [S2]
        if d_content < d_next_bv:
            return d_content  # Step 7: d_content < d_bv [S2]
    return d_content
```

### Parameters
*   $D_{max}$: Maximum ray travel distance. Not given in the sources.
*   $d_{bv}$: Distance to the bounding volume currently at the top of the heap [S2].

### Edge Cases and Pitfalls
*   **Perspective Degradation:** In perspective projection, bounding volume enhancements can degrade performance for typical implicit surfaces if the overhead of distance computation outweighs the culling benefit [S2].
*   **Precision:** Ray-AABB intersection requires careful handling of parallel rays (direction component zero) to avoid division by zero or incorrect interval calculations [G].
*   **Frustum Culling:** Bounding boxes can also be used to avoid iterations over objects outside the camera view frustum [S4].

## Subtopics

### [Bounding Spheres Optimization](1567-bounding-spheres-optimization.md)
Bounding Spheres Optimization reduces the computational cost of sphere tracing by grouping scene objects into larger enclosing spheres, thereby eliminating unnecessary distance calculations during ray traversal. It differs from its parent, [Bounding Volume Culling](1239-bounding-volume-culling.md), which typically discards rays entirely based on geometric bounds, by deferring the evaluation of individual object distances until the ray actually penetrates the enclosing volume. Unlike [Orthogonal Culling Optimization](4034-orthogonal-culling-optimization.md), which pre-computes object visibility via orthogonal projection to reduce per-step evaluations, Bounding Spheres Optimization dynamically manages the active set of distance fields based on ray proximity.

### Heap-based Bounding Volume Culling for Sphere Tracing
An algorithm to find the closest object in a collection by maintaining a heap of bounding volume distances [S2]. It computes distances to bounding volumes first, then contents, culling based on the smallest bounding volume distance [S2]. It is used when the scene consists of a union of implicit objects and sphere tracing is employed [S2]. It differs from simple scalar culling by managing a collection of objects rather than a single distance limit [S2].

### Axis-Aligned Bounding Box (AABB) Culling
A spatial acceleration technique that uses the outer boundaries of the data volume to quickly reject rays that do not intersect the volume, avoiding unnecessary computation [S3, unofficial]. It is used for grid-based volumes where the extent is known [S3, unofficial]. It differs from heap-based methods by using a single static box rather than a dynamic hierarchy of objects [S3, unofficial].

### Scene Delimitation with Bounding Boxes
Using bounding boxes to delimit cloud volumes and Smits' algorithm to limit ray-marching to the volume inside the cloud's boundaries, discarding rays that never hit the boundaries [S4]. It is used in real-time GPU volumetric cloud rendering [S4]. It differs from other methods by integrating with Smits' algorithm to calculate the specific segment of the Euclidean straight line for rendering and allowing separate voxel grids per cloud [S4].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for scalar and AABB culling per ray (intersection test). $O(N \log N)$ or $O(N)$ for heap-based culling depending on the number of bounding volumes $N$ and heap operations [S2].
*   **Memory Complexity:** $O(1)$ for scalar/AABB. $O(N)$ for heap-based culling to store the heap [S2].
*   **Performance:** AABB culling provides a rapid determination of a pixel's color when the data volume's projection does not affect it, reducing CPU/GPU time spent on ray location and object intersection [S3, unofficial]. Scene delimitation with bounding boxes increases FPS by discarding rays that never hit the boundaries and avoiding iterations over spheres outside the camera view frustum [S4].
*   **Limitations:** In perspective cases, bounding volume enhancements can degrade performance for typical implicit surfaces if the overhead is high [S2].
*   **When to use:** When the volume has a well-defined, limited extent (e.g., fog, clouds, specific objects) and rays frequently miss the volume or travel long distances through empty space [S1, unofficial][S3, unofficial][S4].

## Background
Bounding volume culling is a technique in computer graphics for accelerating ray tracing and ray marching by limiting the search space [S3, unofficial]. The concept of using bounding parallelepipeds for implicit surfaces was explored by Kay & Kajiya in 1986 [S2]. In the context of ray marching, limiting rays to a bounding volume is a common optimization to speed up rendering by dropping rays that exceed a certain distance [S1, unofficial]. Modern implementations often use GPU fragment shaders for bounding box delimitation with reduced linear cost [S4].
