# Depth Prediction for Early Stopping (DPES)
Also called: Early Stopping Depth Prediction

## Overview
Depth Prediction for Early Stopping (DPES) predicts the early stopping position for each tile in a target frame by leveraging truncated depth information from a reference frame [S1]. It solves the problem of redundant computation and load imbalance during viewpoint changes by allowing the renderer to exclude Gaussians that are guaranteed to be occluded or beyond the visible depth range in the new view [S1]. Unlike standard early termination which relies on per-pixel opacity thresholds during rendering, DPES pre-computes a tile-level depth bound to prune the Gaussian sorting stage entirely [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Reference frame color buffer $F_{ref}$, reference scene depth map $D_{ref}$, reference truncated depth max map $D_{ref}^{max}$, reference viewpoint $V_{ref}$, target viewpoint $V_{tgt}$, and a rerendering threshold $N_0$ [S1].
*   **Outputs:** Target frame color buffer $F_{tgt}$, a group of tiles $T$, and a tile-level truncated depth map $D_T^{max}$ [S1].

**Data Structures:**
*   $F_{ref}, F_{tgt}$: 2D arrays of pixel colors [S1].
*   $D_{ref}, D_{ref}^{max}$: 2D arrays of depth values [S1]. $D_{ref}$ stores the depth of the last traversed Gaussian or the early stopping depth [S1]. $D_{ref}^{max}$ stores the truncated depth bound [S1].
*   $D_T^{max}$: 2D array where each element corresponds to a tile and stores the maximum valid reprojected depth within that tile [S1].
*   $T$: Grid of tile coordinates covering the target frame [S1].

**Steps:**
1.  **Initialize:** Allocate output buffers $F_{tgt}$ and $D_T^{max}$ [S1].
2.  **Project to 3D:** Convert 2D pixel coordinates and depth values from the reference frame into 3D world coordinates using $V_{ref}$ [S1]. This yields 3D points $P_{ref}$ and truncated depth bounds $P_{ref}^{max}$ [S1].
3.  **View Transfer:** Transform the 3D points $P_{ref}$ and $P_{ref}^{max}$ from the reference viewpoint $V_{ref}$ to the target viewpoint $V_{tgt}$ [S1]. This yields transformed points $P_{tgt}$ and $P_{tgt}^{max}$ [S1].
4.  **Reproject to Target Frame:** Project the transformed 3D points $P_{tgt}$ and $P_{tgt}^{max}$ back onto the 2D image plane of $V_{tgt}$ [S1]. This produces the target frame color buffer $F_{tgt}$ and the target depth map $D_{tgt}$ [S1].
5.  **Tile-Level Processing:** Iterate through each tile $t \in T$ [S1]:
    *   Count the number of valid pixels $N$ within tile $t$ in $F_{tgt}$ [S1].
    *   If $N > N_0$: Interpolate missing pixel values for the tile [S1].
    *   If $N \le N_0$: Calculate the early stopping depth for the tile as the maximum depth of all valid reprojected pixels within that tile: $D_T^{max}(t) = \max_{p \in t} D_{tgt}(p)$ [S1]. Use this depth to re-render the tile, excluding any Gaussians with depth beyond $D_T^{max}(t)$ from the sorting stage [S1].

**Parameters:**
*   $N_0$: Rerendering threshold [S1]. Exact numerical values are not given in the sources [S1].

**Edge Cases and Pitfalls:**
*   **Sparse Valid Pixels:** If the number of valid reprojected pixels $N$ is low ($N \le N_0$), the method triggers re-rendering with depth pruning [S1]. If $N$ is too low, the depth estimate $D_T^{max}$ may be noisy or incomplete, potentially leading to incorrect Gaussian culling if the max depth is underestimated [S1].
*   **Occlusion Changes:** The method assumes that the depth from the reference frame is a valid upper bound for the target frame [S1].

## Operating characteristics
*   **Time Complexity:** The method adds an overhead of projecting and reprojecting depths for the reference frame [S1]. It reduces the sorting complexity for tiles that are re-rendered by excluding Gaussians beyond the predicted depth [S1].
*   **Memory Complexity:** Requires storing the reference depth maps $D_{ref}$ and $D_{ref}^{max}$ and the target depth map $D_{tgt}$ [S1].
*   **Strengths:** Enables balanced workload distribution across rasterization units by predicting expected load per tile [S1]. Reduces redundant computation by pruning Gaussians early [S1].
*   **Limitations:** Relies on the accuracy of the reference depth map [S1].
*   **When to use:** Real-time streaming 3D Gaussian Splatting where viewpoint changes are frequent and computational resources are limited [S1].
