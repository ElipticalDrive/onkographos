# Brick Tree (THC Tree)
Also called: THC tree, Tetra hexacon tree

## Overview
The Brick Tree is a hierarchical acceleration structure for voxel ray marching that reduces GPU memory bandwidth pressure by minimizing memory reads during traversal [S1, unofficial]. It differs from standard octrees by subdividing each parent node into 64 children (4×4×4 per axis) and using a single 64-bit bitmask to track occupancy, allowing rays to skip empty regions without repeated memory accesses [S1, unofficial].

## How it works
**Inputs:** Ray origin, ray direction, voxel grid data organized in a Brick Tree, and a maximum traversal depth [G].
**Outputs:** Intersection point, surface normal, and color [G].

**Data Structures:**
*   **Node:** Contains a 64-bit integer bitmask [S1, unofficial]. Each bit $i$ (where $0 \le i < 64$) corresponds to one of the 64 child nodes [S1, unofficial]. If bit $i$ is set (1), the child node contains non-empty voxels and is subdivided [S1, unofficial]. If bit $i$ is unset (0), the child node is empty and can be skipped [S1, unofficial].
*   **Tree Hierarchy:** The root node covers the entire voxel volume [G]. Each node is subdivided into a 4×4×4 grid of children [S1, unofficial]. This structure builds on [Voxel Bricks](5794-voxel-bricks.md), which groups voxels into 8×8×8 bricks; the Brick Tree operates on these bricks or similar macro-cells [S1, unofficial].

**Algorithm:**
1.  **Initialization:** Load the root node's bitmask into a register [S1, unofficial]. Determine the initial bounding box of the root [G].
2.  **Traversal Loop:** While the ray has not hit a surface and has not exited the volume:
    a.  Calculate the current child index $c$ corresponding to the ray's position within the current node's bounding box. The index is derived from the ray's integer cell coordinates relative to the node's origin, mapped to the 4×4×4 grid [G].
    b.  Check the $c$-th bit of the current bitmask using bitwise operations: `is_empty = (mask >> c) & 1` [S1, unofficial].
    c.  **If `is_empty` is 0:** The child is empty [S1, unofficial]. Skip this child entirely. Advance the ray's entry point to the exit point of the current child's bounding box along the ray direction and continue to the next step in the ray marcher without reading new memory [S1, unofficial].
    d.  **If `is_empty` is 1:** The child is occupied [S1, unofficial].
        i.  If the child is a leaf node (contains actual voxel data), perform ray-voxel intersection tests against the voxels in this child. If an intersection is found, return the result [G].
        ii. If the child is not a leaf, load the child's bitmask from memory into a register. Update the ray's entry point to the child's bounding box entry. Continue the loop with the new bitmask [S1, unofficial].
3.  **Termination:** If the ray exits the volume or hits a surface, return the result [G].

**Parameters:**
*   **Subdivision Factor:** 4 per axis, resulting in 64 children per node [S1, unofficial].
*   **Bitmask Size:** 64 bits [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors in ray-node intersection calculations may cause the ray to miss a child node or select the wrong one. Robust ray-box intersection tests are required [G].
*   **Boundary Conditions:** Rays starting exactly on a node boundary must be handled to avoid ambiguity in child selection [G].
*   **Empty Regions:** The bitmask must accurately reflect empty regions. The structure relies on the bitmask to skip children without memory reads [S1, unofficial].

**Pseudocode:**
```python
def ray_march_brick_tree(ray_origin, ray_direction, bitmasks, root_bbox, brick_size, max_steps):
    """
    Ray marcher using Brick Tree acceleration.
    bitmasks: list of ints, where bitmasks[node_id] is the 64-bit occupancy mask.
    root_bbox: tuple of ((min_x, min_y, min_z), (max_x, max_y, max_z))
    brick_size: float, side length of a 4x4x4 macrocell.
    """
    # Guard against zero direction components [G]
    inv_dir = tuple(1.0 / d if d != 0.0 else float('inf') for d in ray_direction)
    t_min = max((root_bbox[0][0] - ray_origin[0]) * inv_dir[0],
                (root_bbox[0][1] - ray_origin[1]) * inv_dir[1],
                (root_bbox[0][2] - ray_origin[2]) * inv_dir[2])
    t_max = min((root_bbox[1][0] - ray_origin[0]) * inv_dir[0],
                (root_bbox[1][1] - ray_origin[1]) * inv_dir[1],
                (root_bbox[1][2] - ray_origin[2]) * inv_dir[2])
    
    if t_max < 0 or t_min > t_max:
        return None  # Ray misses bounding box
    
    current_mask = bitmasks[0]  # Root bitmask
    current_node_origin = root_bbox[0]
    current_step = 0
    
    while current_step < max_steps and t_min <= t_max:
        # 1. Determine which of the 64 children the ray is currently in
        ray_pos = (ray_origin[0] + t_min * ray_direction[0],
                   ray_origin[1] + t_min * ray_direction[1],
                   ray_origin[2] + t_min * ray_direction[2])
        dx = int((ray_pos[0] - current_node_origin[0]) / brick_size)
        dy = int((ray_pos[1] - current_node_origin[1]) / brick_size)
        dz = int((ray_pos[2] - current_node_origin[2]) / brick_size)
        
        # Clamp to valid range [0, 3]
        dx = max(0, min(3, dx))
        dy = max(0, min(3, dy))
        dz = max(0, min(3, dz))
        
        # Map 3D index to 0-63 child index
        child_idx = dx + (dy * 4) + (dz * 16)
        
        # 2. Check occupancy via bitmask
        is_empty = (current_mask >> child_idx) & 1
        
        if is_empty == 0:
            # Child is empty. Skip it.
            # Advance ray to the exit of this child's bounding box
            child_min = (current_node_origin[0] + dx * brick_size,
                         current_node_origin[1] + dy * brick_size,
                         current_node_origin[2] + dz * brick_size)
            child_max = (child_min[0] + brick_size,
                         child_min[1] + brick_size,
                         child_min[2] + brick_size)
            
            t_exit = min((child_max[0] - ray_origin[0]) * inv_dir[0],
                         (child_max[1] - ray_origin[1]) * inv_dir[1],
                         (child_max[2] - ray_origin[2]) * inv_dir[2])
            t_min = max(t_min, t_exit)
            current_step += 1
        else:
            # Child is occupied
            # Sources do not specify leaf detection mechanism; typically a separate flag or depth limit [G].
            # If leaf:
            # Sources do not provide the leaf voxel intersection routine; standard ray-marching over 4x4x4 cells is required [G].
            # hit = intersect_voxels(...)
            # if hit: return hit
            # else: continue
            
            # Internal node: descend
            current_mask = bitmasks[child_idx]
            current_node_origin = (current_node_origin[0] + dx * brick_size,
                                   current_node_origin[1] + dy * brick_size,
                                   current_node_origin[2] + dz * brick_size)
            # Update ray entry to child's entry point
            t_min = max(t_min, (current_node_origin[0] - ray_origin[0]) * inv_dir[0])
            t_min = max(t_min, (current_node_origin[1] - ray_origin[1]) * inv_dir[1])
            t_min = max(t_min, (current_node_origin[2] - ray_origin[2]) * inv_dir[2])
            current_step += 1
            
    return None
```

## Operating characteristics
*   **Time Complexity:** Traversal time is proportional to the number of occupied nodes visited [S1, unofficial]. Empty regions are skipped without additional memory reads [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** On a GTX 1660 Ti, rendering a castle scene from a Tear Down map with primary and shadow rays at 7 milliseconds per frame [S1, unofficial]. The structure reduces memory reads compared to octrees, allowing up to 10 ray steps without additional memory reads by keeping the bitmask in registers [S1, unofficial].
*   **Strengths:** Minimal memory reads, efficient empty space skipping, leverages GPU register architecture [S1, unofficial].
*   **Limitations:** Fixed 4×4×4 subdivision may not be optimal for all scenes [S1, unofficial]. Requires careful handling of ray-node intersections [S1, unofficial].

## Background
The Brick Tree was developed by a game engine developer for use in a voxel-based game engine to optimize voxel ray marching performance [S1, unofficial]. It was created to address the high memory bandwidth costs of GPU memory reads during ray marching, which were a bottleneck in previous octree-based implementations [S1, unofficial]. The term "THC tree" or "Tetra hexacon tree" is a self-coined name by the developer, as no official name existed for this 4×4×4 subdivision structure [S1, unofficial].
