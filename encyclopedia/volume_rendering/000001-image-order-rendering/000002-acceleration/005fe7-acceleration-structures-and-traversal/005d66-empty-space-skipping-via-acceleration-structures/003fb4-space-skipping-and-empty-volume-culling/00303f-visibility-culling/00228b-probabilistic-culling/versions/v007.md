# Probabilistic Culling

Also called: Approximate Intersection Culling, Approximate Tile-Wise Culling, Ibrahim et al, Probabilistic Culling for Particle Rendering

## Overview
Probabilistic Culling is a rendering optimization that intentionally allows false-negatives in intersection tests to reduce duplicated fragments and rendering time, particularly in virtual reality (VR) and high-resolution contexts [S2]. It sets itself apart from conservative culling methods by trading strict geometric accuracy for performance, relying on the fact that resulting visual artifacts are imperceptible [S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of view-dependent primitives (e.g., splats or tiles) and their bounding volumes [S2].
*   **Output:** A subset of primitives passed to the rasterization stage, with some occluded primitives incorrectly classified as visible (false-negatives) [S2].

**Data Structures:**
The method operates on tile-wise or primitive-level bounding boxes [S2].

**Steps:**
1.  **Bounding:** Compute tight bounding boxes for each tile or primitive group [S2].
2.  **Approximate Intersection Test:** Perform an intersection test between the view frustum (or camera ray) and the bounding box; unlike conservative culling, this test may return visible even if the primitive is occluded, justifying false-negatives to reduce duplicated fragments [S2].
3.  **Fragment Generation:** Pass the visible primitives to the rasterizer; approximate culling reduces the amount of staged fragments compared to tight bounding boxes [S2].
4.  **Rendering:** Render the fragments; image difference metrics confirm the visual impact is negligible [S2].

**Formulas:**
The method modifies the culling condition rather than compositing. Conservative culling ensures $V = \text{true} \implies \text{primitive is visible}$. Probabilistic culling allows $V = \text{true} \implies \text{primitive is processed, potentially introducing false-negatives}$ [S2].

**Parameters:**
*   **Bounding Box Tightness:** Controls the trade-off between culling overhead and fragment reduction [S2].
*   **Framebuffer Resolution:** The benefit increases with resolution and is especially prominent in VR [S2].

**Edge Cases and Pitfalls:**
*   **Low Resolution:** At default framebuffer sizes (e.g., 1920×1080), performance gains are minimal because the reduction in sorting/rasterization workload is offset by a slight increase in fragment creation duration [S2].

**Pseudocode:**
```python
def probabilistic_cull(primitives, frustum_bounds):
    """
    Cull primitives using approximate intersection tests.
    frustum_bounds: dict with keys 'min_x', 'max_x', 'min_y', 'max_y', 'min_z', 'max_z'
    """
    visible_primitives = []
    for prim in primitives:
        # Compute tight bounding box for the primitive
        bbox_min = [min(v[i] for v in prim.vertices) for i in range(3)]
        bbox_max = [max(v[i] for v in prim.vertices) for i in range(3)]
        
        # Perform approximate intersection test
        # Standard AABB vs view frustum check [G]
        is_visible = True
        if bbox_max[0] < frustum_bounds['min_x'] or bbox_min[0] > frustum_bounds['max_x']:
            is_visible = False
        elif bbox_max[1] < frustum_bounds['min_y'] or bbox_min[1] > frustum_bounds['max_y']:
            is_visible = False
        elif bbox_max[2] < frustum_bounds['min_z'] or bbox_min[2] > frustum_bounds['max_z']:
            is_visible = False
            
        # Probabilistic culling allows false-negatives by skipping strict occlusion checks
        if is_visible:
            visible_primitives.append(prim)
            
    return visible_primitives
```

### [Parameter Range Culling](5071-parameter-range-culling.md)
A runtime optimization that isolates particle subsets by culling particles whose simulation property values do not overlap a user-defined valid range. It sets itself apart by allowing interactive range changes, unlike static culling.

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** The culling step is $O(N)$ where $N$ is the number of primitives/tiles, reducing the workload for sorting and rasterization [S2, G].
*   **Memory:** Not given in the sources.

**Measured Performance:**
*   **Berlin Scene (Desktop):** Fragments reduced from 6.3M to 5.9M; rendering time from 2.7ms to 2.6ms [S2].
*   **Berlin Scene (VR):** Fragments reduced from 12.8M to 9.8M; rendering time from 5.6ms to 5.2ms [S2].
*   **Visual Quality:** Image difference metrics show renderings are virtually indistinguishable (Berlin PSNR 41.83 dB, SSIM 0.9996, FLIP 0.0010, LPIPS 0.0021) [S2].

**Scaling:**
*   The impact increases with framebuffer size and is especially prominent in VR rendering, where the pixel count is significantly higher (e.g., 4.36 times more pixels in VR vs. desktop) [S2].

**Strengths and Limitations:**
*   **Strengths:** Significant performance gains in VR and high-resolution rendering; imperceptible visual quality loss [S2].
*   **Limitations:** Little impact at low resolutions; potential for a slight increase in fragment creation duration [S2].

## Background
Probabilistic Culling, also known as Approximate Tile-Wise Culling, was proposed by Ibrahim et al. [IRR*22] for efficient particle rendering using task and mesh shader pipelines [S1, S2]. It is used in contexts where real-time performance is critical, such as VR, and where the visual cost of false-negatives is acceptable [S2].
