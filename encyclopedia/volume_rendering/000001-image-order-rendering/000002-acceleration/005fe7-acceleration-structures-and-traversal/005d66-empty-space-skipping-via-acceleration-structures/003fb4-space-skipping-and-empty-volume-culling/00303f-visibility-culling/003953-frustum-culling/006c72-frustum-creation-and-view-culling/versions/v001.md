# Frustum Creation and View Culling

Also called: CheckFrustomView, FrustumFromCamera

## Overview
This method constructs the six planes of a perspective view frustum from camera parameters and performs a strict containment test to determine if an object is visible. It serves as the foundational geometric step for view culling in volume rendering, ensuring that only objects intersecting the view volume are processed for ray casting or traversal. It differs from hierarchical culling methods by operating on individual object bounding volumes without acceleration structures.

## How it works
**Inputs:**
- Camera position ($P$) as a 3D vector.
- Camera orientation vectors: front ($\mathbf{f}$), right ($\mathbf{r}$), and up ($\mathbf{u}$), assumed to be orthonormal unit vectors.
- Near plane distance ($d_{near}$).
- Far plane distance ($d_{far}$).
- Vertical field of view ($\theta$) in radians or degrees.
- Aspect ratio ($a$).
- Object bounding volume (typically an Axis-Aligned Bounding Box or Sphere) defined by its center ($C$) and extent ($E$).

**Outputs:**
- Boolean: `true` if the object is strictly inside the frustum, `false` otherwise.

**Data Structures:**
- **Plane:** Defined by a point $Q$ and a normal vector $\mathbf{n}$. The plane equation is $(X - Q) \cdot \mathbf{n} = 0$. For culling, the normal points inward.

**Steps:**

1.  **Calculate Frustum Extents at Far Plane:**
    Compute the half-height and half-width of the frustum at the far plane distance.
    $$ h_{far} = d_{far} \cdot \tan\left(\frac{\theta}{2}\right) $$
    $$ w_{far} = h_{far} \cdot a $$

2.  **Construct the Six Planes:**
    The frustum is defined by six planes. The normals are oriented to point into the frustum (inward).

    -   **Near Plane:**
        Point $Q_{near} = P + d_{near} \cdot \mathbf{f}$
        Normal $\mathbf{n}_{near} = \mathbf{f}$

    -   **Far Plane:**
        Point $Q_{far} = P + d_{far} \cdot \mathbf{f}$
        Normal $\mathbf{n}_{far} = -\mathbf{f}$

    -   **Right Plane:**
        The right plane passes through the camera position $P$. Its normal is perpendicular to the vector from the camera to the right edge of the far plane.
        Vector to right edge of far plane: $\mathbf{v}_{right} = d_{far} \cdot \mathbf{f} - w_{far} \cdot \mathbf{r}$
        Normal $\mathbf{n}_{right} = \text{normalize}(\mathbf{v}_{right} \times \mathbf{u})$
        *Note: The cross product order ensures the normal points inward (left of the view direction).*

    -   **Left Plane:**
        Vector to left edge of far plane: $\mathbf{v}_{left} = d_{far} \cdot \mathbf{f} + w_{far} \cdot \mathbf{r}$
        Normal $\mathbf{n}_{left} = \text{normalize}(\mathbf{u} \times \mathbf{v}_{left})$

    -   **Top Plane:**
        Vector to top edge of far plane: $\mathbf{v}_{top} = d_{far} \cdot \mathbf{f} - h_{far} \cdot \mathbf{u}$
        Normal $\mathbf{n}_{top} = \text{normalize}(\mathbf{r} \times \mathbf{v}_{top})$

    -   **Bottom Plane:**
        Vector to bottom edge of far plane: $\mathbf{v}_{bot} = d_{far} \cdot \mathbf{f} + h_{far} \cdot \mathbf{u}$
        Normal $\mathbf{n}_{bot} = \text{normalize}(\mathbf{v}_{bot} \times \mathbf{r})$

3.  **Perform Containment Test:**
    For each plane $i \in \{near, far, right, left, top, bottom\}$, calculate the signed distance from the object's center $C$ to the plane.
    $$ d_i = (C - Q_i) \cdot \mathbf{n}_i $$
    
    The object is strictly inside the frustum if and only if:
    $$ d_i > 0 \quad \forall i $$
    
    If the object is a bounding box, this test is typically performed against the 8 corners of the box, or by expanding the plane distance by the box's radius/extent along the normal. The source notes imply a point-center check or a simplified AABB check where the object's translation is used directly. For a general AABB with center $C$ and half-extents $e_x, e_y, e_z$, the condition becomes $d_i > -(\mathbf{n}_i \cdot \mathbf{e})$, where $\mathbf{e}$ is the projection of the box extents onto the plane normal. However, the provided source [S1, unofficial] specifies a strict dot product check on `objectTranslation`, implying a point or sphere test, or a simplified AABB where the extents are pre-subtracted. We follow the source's strict inequality for point-like objects or pre-culled volumes.

**Pseudocode:**

```python
import math
from typing import Tuple, List

class Vector3:
    def __init__(self, x, y, z):
        self.x = x
        self.y = y
        self.z = z

    def add(self, other):
        return Vector3(self.x + other.x, self.y + other.y, self.z + other.z)

    def sub(self, other):
        return Vector3(self.x - other.x, self.y - other.y, self.z - other.z)

    def scale(self, s):
        return Vector3(self.x * s, self.y * s, self.z * s)

    def dot(self, other):
        return self.x * other.x + self.y * other.y + self.z * other.z

    def cross(self, other):
        return Vector3(
            self.y * other.z - self.z * other.y,
            self.z * other.x - self.x * other.z,
            self.x * other.y - self.y * other.x
        )

    def normalize(self):
        mag = math.sqrt(self.x**2 + self.y**2 + self.z**2)
        if mag == 0:
            return Vector3(0, 0, 0)
        return Vector3(self.x / mag, self.y / mag, self.z / mag)

class Plane:
    def __init__(self, point: Vector3, normal: Vector3):
        self.point = point
        self.normal = normal.normalize()

    def distance_from_point(self, p: Vector3) -> float:
        return (p.sub(self.point)).dot(self.normal)

def create_frustum_planes(position: Vector3, front: Vector3, right: Vector3, up: Vector3, 
                          near: float, far: float, fov_deg: float, aspect: float) -> List[Plane]:
    # Convert FOV to radians
    fov_rad = math.radians(fov_deg)
    
    # 1. Calculate half vertical and horizontal side lengths at far plane
    half_v_side = far * math.tan(fov_rad / 2.0)
    half_h_side = half_v_side * aspect
    
    # 2. Define planes
    planes = []
    
    # Near face
    near_point = position.add(front.scale(near))
    planes.append(Plane(near_point, front))
    
    # Far face
    far_point = position.add(front.scale(far))
    planes.append(Plane(far_point, front.scale(-1)))
    
    # Right face
    # Normal = Cross(front * far - right * half_h_side, up)
    # Note: Source [S1, unofficial] uses Cross(frontMultFar - _right * halfHSide, _up)
    vec_right_far = front.scale(far).sub(right.scale(half_h_side))
    right_normal = vec_right_far.cross(up).normalize()
    planes.append(Plane(position, right_normal))
    
    # Left face
    # Normal = Cross(up, front * far + right * half_h_side)
    vec_left_far = front.scale(far).add(right.scale(half_h_side))
    left_normal = up.cross(vec_left_far).normalize()
    planes.append(Plane(position, left_normal))
    
    # Top face
    # Normal = Cross(right, front * far - up * half_v_side)
    vec_top_far = front.scale(far).sub(up.scale(half_v_side))
    top_normal = right.cross(vec_top_far).normalize()
    planes.append(Plane(position, top_normal))
    
    # Bottom face
    # Normal = Cross(front * far + up * half_v_side, right)
    vec_bot_far = front.scale(far).add(up.scale(half_v_side))
    bot_normal = vec_bot_far.cross(right).normalize()
    planes.append(Plane(position, bot_normal))
    
    return planes

def is_object_in_frustum(planes: List[Plane], object_center: Vector3) -> bool:
    for plane in planes:
        # Strictly greater than 0 as per source [S1, unofficial]
        if plane.distance_from_point(object_center) <= 0:
            return False
    return True
```

**Parameters:**
- `fov_deg`: Vertical field of view. Default 60 degrees [S1, unofficial].
- `aspect`: Aspect ratio (width/height). Default 1.77 [S1, unofficial].
- `near`: Near plane distance. Default 0.1 [S1, unofficial].
- `far`: Far plane distance. Default 200 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Degenerate Camera:** If `front`, `right`, or `up` are not orthonormal, the frustum geometry will be skewed. The source assumes valid camera basis vectors [S1, unofficial].
- **Precision:** Floating-point errors may cause objects exactly on the boundary to be culled if the inequality is not handled consistently (e.g., `>=` vs `>`). The source uses strict `> 0` [S1, unofficial].
- **Zero FOV:** If FOV is 0, `tan(0)` is 0, resulting in a degenerate frustum with no volume.

## Subtopics

### Frustum Geometry Construction
This variant focuses specifically on the derivation of the plane equations from the camera matrix or basis vectors. It sets itself apart by emphasizing the geometric derivation of the normals via cross products of the view direction and the far-plane edges, rather than extracting planes from a projection matrix. It is chosen when explicit control over plane orientation is required for custom culling logic or when the projection matrix is not readily available. It links to [Frustum Culling](8463-frustum-culling.md).

## Operating characteristics
- **Time Complexity:** $O(1)$ per object. The number of operations is constant (6 planes, 6 dot products).
- **Memory Complexity:** $O(1)$ auxiliary space for plane storage.
- **Performance:** Extremely fast, suitable for per-object culling in real-time engines. The cost is dominated by the trigonometric function (`tan`) if FOV is not precomputed, but this is typically done once per frame.
- **Strengths:** Simple to implement, no preprocessing required, works with any bounding volume type (with appropriate distance calculation).
- **Limitations:** Does not account for occlusion. It only checks visibility against the view volume. It may cull too aggressively if the bounding volume is loose.
- **When to use:** As a first-pass culling step before more expensive visibility checks.
- **When not to use:** When occlusion is significant and needs to be resolved, or when dealing with highly dynamic scenes where hierarchical culling might be more efficient.

## Background
This method is derived from standard computer graphics techniques for view frustum culling. The specific implementation details, including the plane construction via cross products and the strict inequality check, are documented in the VoxelCoreEngine source code [S1, unofficial]. It is a fundamental technique used in virtually all 3D rendering pipelines, including those for volume rendering, to reduce the number of objects processed by the GPU.
