# Russian Roulette

Also called: Monte Carlo termination, Probabilistic Path Termination, RR termination, Russian Roulette Termination, Russian Roulette for Ray Marching Termination, Russian Roulette for Ray Termination, Russian Roulette for Volumetric Paths

## Overview
Russian Roulette is a randomized early-out technique used in Monte Carlo volume rendering to remove the statistical bias introduced by deterministic early termination (such as breaking a ray-marching loop when transmittance drops below a fixed threshold) [S1, unofficial][S2, unofficial][S3, unofficial]. It probabilistically terminates rays with low contribution weights while scaling up the weights of surviving paths to maintain an unbiased expectation of the final pixel color [S4, unofficial][S5, unofficial]. Unlike deterministic cutoffs which simply discard remaining contributions, Russian Roulette ensures that the expected value of the rendered image remains correct, albeit at the cost of increased variance (noise) [S3, unofficial][S5, unofficial].

## How it works
Russian Roulette is applied when the accumulated transmittance (or path throughput) becomes sufficiently small, indicating that the remaining contribution to the pixel is negligible but non-zero. The method replaces a hard cutoff with a probabilistic decision.

### Inputs and Outputs
*   **Inputs:**
    *   Current accumulated transmittance/throughput $T$ (or weight $W$).
    *   Termination probability parameter $p_{rr}$ (or compensation factor $D$).
    *   Random number generator state.
*   **Outputs:**
    *   Boolean: `continue` or `terminate`.
    *   Updated transmittance/weight $T'$ or $W'$.

### Data Structures
No specific complex data structures are required beyond standard scalar variables for transmittance/weight and a random number generator.

### Parameters
*   **Threshold ($T_{thresh}$):** The minimum transmittance value below which Russian Roulette is considered. Common values are $10^{-3}$ [S5, unofficial].
*   **Termination Probability ($p_{rr}$):** The probability of terminating the path. In path tracing, this is often derived from the maximum color channel of the throughput [S4, unofficial]. In ray marching, it is often a constant (e.g., 0.5) or derived from a compensation factor $D$ [S5, unofficial].
*   **Compensation Factor ($D$):** A value $> 1$ used in some formulations where $p_{rr} = 1 - 1/D$ [S1, unofficial][S5, unofficial].

### Algorithm Steps
1.  **Check Threshold:** If the current accumulated transmittance $T$ (or weight $W$) is greater than or equal to the threshold $T_{thresh}$, continue marching/tracing normally.
2.  **Generate Random Number:** Sample a uniform random number $\xi$ from $[0, 1]$.
3.  **Determine Termination Probability:**
    *   *Formulation A (Constant/Heuristic):* Set $p_{rr}$ to a constant (e.g., 0.5) or a function of the transmittance [S5, unofficial][S6].
    *   *Formulation B (Compensation Factor):* Set $p_{rr} = 1 - 1/D$ where $D > 1$ [S1, unofficial][S5, unofficial].
    *   *Formulation C (Path Tracing):* Set $p_{rr}$ to the maximum component value of the current throughput vector $\beta$ (or a scaled version thereof) [S6].
4.  **Probabilistic Decision:**
    *   If $\xi < p_{rr}$ (or $\xi > 1/D$ in Formulation B), terminate the path. Set $T' = 0$ (or $W' = 0$).
    *   If $\xi \geq p_{rr}$ (or $\xi \leq 1/D$ in Formulation B), continue the path.
5.  **Weight Compensation:**
    *   If continuing, scale the transmittance/weight to compensate for the probability of termination:
        *   $T' = T / (1 - p_{rr})$ [S6].
        *   $W' = W / p_{rr}$ [S4, unofficial] (Note: S4 defines $p_{rr}$ as the probability of *continuation* in the formula context, but text says "probability of termination".         *   *Clarification from S5:* "If random number is lower than $1/d$ you kill... Otherwise... multiply transparency by $d$." Here $1/d$ is the termination probability. $D$ is the compensation factor. $p_{cont} = 1 - 1/D$. $T' = T \cdot D = T / (1 - p_{term})$.

        If terminating: $T' = 0$.

### Pseudocode
The following pseudocode implements the standard Russian Roulette for volume ray marching, combining the threshold check and probabilistic termination [S5, unofficial][S6].

```python
def russian_roulette(transmittance, threshold=1e-3, max_channel_prob=None):
    """
    Applies Russian Roulette to the current transmittance.
    
    Args:
        transmittance: Current accumulated transmittance (Spectrum or float).
        threshold: Minimum transmittance to trigger RR.
        max_channel_prob: If provided, used as the probability of continuation 
                          (e.g., max component of throughput). Overrides constant prob.
    
    Returns:
        (continue_marching: bool, new_transmittance: float)
    """
    # 1. Check if we are below the threshold
    if transmittance >= threshold:
        return True, transmittance

    # 2. Determine probability of continuation (p_cont)
    if max_channel_prob is not None:
        # Path tracing style: use the max channel of the throughput as continuation prob
        # Ensure it is within [0, 1]
        p_cont = min(max_channel_prob, 1.0)
    else:
        # Ray marching style: constant probability or derived from D
        # Using D=2 as a common example from sources [S5, unofficial]
        # p_cont = 1/D = 0.5
        p_cont = 0.5

    # 3. Generate random number
    r = random_uniform(0.0, 1.0)

    # 4. Decision
    if r < p_cont:
        # Survive: scale transmittance
        # Avoid division by zero
        if p_cont > 1e-6:
            new_transmittance = transmittance / p_cont
        else:
            new_transmittance = 0.0
        return True, new_transmittance
    else:
        # Die: terminate
        return False, 0.0
```

### Edge Cases and Pitfalls
*   **Bias from Simple Cutoff:** Simply breaking the loop when `transmittance < threshold` without compensation introduces significant bias by discarding the remaining volume contribution [S5, unofficial].
*   **Variance Increase:** While unbiased, Russian Roulette increases the variance (noise) of the image because it introduces binary outcomes (0 or scaled value) for paths that would have contributed small, deterministic amounts [S3, unofficial][S5, unofficial].
*   **Division by Zero:** Ensure the continuation probability is not zero to avoid division by zero when scaling the weight [G].
*   **Threshold Selection:** A threshold that is too high increases noise; too low provides little performance gain [S5, unofficial].

## Subtopics

### [Russian Roulette Early Ray Termination](13726-russian-roulette-early-ray-termination.md)
A sophisticated variant that probabilistically terminates rays based on accumulated opacity, replacing deterministic threshold-based cutoffs. It differs from standard early termination by allowing rays to continue with scaled weights even when opacity is high, thereby reducing computation while maintaining unbiased expectations through variance masking.

## Operating characteristics
*   **Time Complexity:** Reduces the average number of samples per ray by terminating low-contribution paths early. In path tracing, this allows for deeper paths without hitting max-depth limits, or reduces the cost of deep paths [S4, unofficial].
*   **Memory Complexity:** No additional memory overhead beyond standard scalar variables.
*   **Performance:** Significant speedup in scenes with high variance or deep paths. For example, rendering with Russian Roulette took 161s compared to 2556s without it (biased, max depth 200) in a cloud example [S4, unofficial].
*   **Strengths:** Unbiased results; effective for reducing computation in transparent or deep volumes.
*   **Limitations:** Increases noise (variance); requires careful tuning of termination probabilities to balance speed and quality [S3, unofficial].
*   **When to Use:** When using Monte Carlo integration for volume rendering, especially with path tracing or when deterministic early termination causes visible bias.
*   **When Not to Use:** When deterministic bias is acceptable for speed, or when the volume is very dense and transmittance drops to zero quickly anyway.

## Background
Russian Roulette originated in Monte Carlo particle-tracing methods to avoid simulating particles with low weights without biasing the results [S2, unofficial]. It was adapted for volume rendering to correct the bias introduced by early ray termination (cutoff) [S2, unofficial][S3, unofficial]. The technique is named after the dangerous game of chance, reflecting the probabilistic nature of path survival [S1, unofficial]. It is a standard component of unbiased path tracers and volume integrators [S6].
