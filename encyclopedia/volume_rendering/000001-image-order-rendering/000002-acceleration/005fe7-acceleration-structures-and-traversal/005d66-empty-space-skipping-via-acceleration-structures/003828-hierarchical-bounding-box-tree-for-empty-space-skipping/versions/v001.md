# Hierarchical Bounding Box Tree for Empty-Space Skipping

Also called: Accelerated Ray Casting with BVH and Early Termination, Large-Scale Aerosols Visualization via Accelerated Ray Casting, Large-scale Aerosols Visualization Method, Ray Casting Acceleration Algorithm

## Overview
This method accelerates traditional ray casting for large-scale aerosol visualization (smoke, fog, dust) by combining a Hierarchical Bounding Box Tree (BVH) for empty voxel skipping, early termination of light compositing, and grouped linear interpolation [S1]. It sets itself apart from sibling methods like [SparseLeap](5152-sparseleap.md) and [Efficient Space Skipping & Adaptive Sampling of Unstructured Volumes Using H.W. Accel. Ray Tracing](8217-efficient-space-skipping-adaptive-sampling-of-unstructured-v.md) by explicitly using a BVH constructed from an octree traversal to avoid recording empty nodes, thereby reducing computational complexity compared to pure octree-based skipping, while offering dynamic update capabilities superior to K-D trees [S1].

## How it works
**Inputs:** 3D scalar volume data (aerosol density/opacity field).
**Outputs:** 2D rendered image with color and opacity.

### Data Structures

**1. Volume Data Block (Leaf Node Input)**
*   Represents a sub-block of the original volume data.
*   **Fields:**
    *   `min_val`: Minimum scalar value in the block.
    *   `max_val`: Maximum scalar value in the block.
    *   `data`: Array of scalar values.
    *   `expanded`: Boolean flag indicating if the block is expanded by one voxel boundary.

**2. BVH Node**
*   The BVH is a binary tree [S1].
*   **Fields:**
    *   `bbox`: Axis-Aligned Bounding Box (AABB) defined by 6 values ($x_{min}, x_{max}, y_{min}, y_{max}, z_{min}, z_{max}$) parallel to the xy, xz, and yz planes [S1].
    *   `left_child`: Reference to left child node (or null).
    *   `right_child`: Reference to right child node (or null).
    *   `attribute`: Enum {EMPTY, NON_EMPTY, UNKNOWN}.
    *   `is_leaf`: Boolean. If true, points to a `Volume Data Block`.

**3. Ray State**
*   **Fields:**
    *   `origin`: 3D vector $(o_x, o_y, o_z)$.
    *   `direction`: 3D normalized vector $(d_x, d_y, d_z)$.
    *   `t_min`: Entry distance into the volume bounding box.
    *   `t_max`: Exit distance from the volume bounding box.
    *   `current_t`: Current distance along the ray.
    *   `cumulative_opacity`: Scalar $a$, initialized to 0.
    *   `accumulated_color`: 3D vector (RGB), initialized to $(0,0,0)$.
    *   `sampling_interval`: Scalar, dynamically adjusted.

### Construction Algorithm

1.  **Preprocessing (Expansion):**
    *   Divide the volume data into sub-blocks.
    *   For each sub-block, expand the data by one voxel in all directions to avoid boundary interpolation errors [S1]. This ensures interpolated values do not exceed the original block's min/max bounds [S1].
    *   Compute `min_val` and `max_val` for each expanded sub-block.

2.  **Octree Generation:**
    *   Recursively divide each data block into eight parts (children) to form an octree [S1].
    *   For each leaf node of the octree, determine its attribute:
        *   If all voxels are empty (e.g., density < threshold), attribute = `EMPTY`.
        *   If all voxels are non-empty, attribute = `NON_EMPTY`.
        *   Otherwise, attribute = `UNKNOWN`.

3.  **Attribute Propagation:**
    *   For each non-leaf node in the octree:
        *   Count the proportion of child nodes with attributes `EMPTY`, `NON_EMPTY`, and `UNKNOWN`.
        *   Assign the node's attribute to the child attribute with the highest proportion [S1].

4.  **BVH Construction (BFS):**
    *   Perform a breadth-first search (BFS) on the octree [S1].
    *   Identify volume data blocks (octree nodes) whose attribute differs from their parent node's attribute.
    *   Construct a bounding box for these identified blocks.
    *   Build the BVH as a binary tree where the root represents the largest bounding box, and each node splits into two sub-bounding boxes [S1].
    *   *Note:* The sources describe constructing the BVH from the octree attributes but do not specify the exact binary splitting heuristic (e.g., SAH, median split) used to form the binary tree from the octree nodes. [G] A standard implementation would recursively split the set of bounding boxes identified in step 4 into two subsets, creating a left and right child node for each split, until leaf nodes are reached.

### Rendering Algorithm

1.  **Initialization:**
    *   For each pixel, generate a ray with `origin` and `direction`.
    *   Intersect ray with the global volume bounding box to get `t_min` and `t_max`.
    *   Initialize `cumulative_opacity` $a = 0$.
    *   Initialize `accumulated_color` $C = (0,0,0)$.
    *   Set initial `sampling_interval` $s$ (base step size).

2.  **Ray Traversal (Empty-Space Skipping):**
    *   Traverse the BVH from the root.
    *   For each node, check if the ray intersects the node's AABB.
    *   If no intersection, skip the subtree.
    *   If intersection:
        *   If node is `EMPTY`, skip the subtree.
        *   If node is `NON_EMPTY`, process the leaf data.
        *   If node is `UNKNOWN`, recurse to children.
    *   Merge and delete bounding boxes according to specific rules to determine the valid sampling range [S1]. *Note:* The sources do not detail the "merge and delete" rules, but imply that overlapping or redundant bounding boxes are consolidated to define the continuous sampling interval along the ray.

3.  **Sampling and Compositing (with Adaptive Interval):**
    *   Iterate along the ray from `t_min` to `t_max` with step `sampling_interval`.
    *   For each sample point $P$:
        *   Sample the volume data at $P$ to get density $\rho$ and opacity $\alpha$.
        *   **Adaptive Sampling:**
            *   If the sample point is invalid (empty/noise), increase `sampling_interval` (e.g., $s \leftarrow s \times k, k > 1$) to reduce resampling frequency [S1].
            *   If a valid sampling point is encountered, restore `sampling_interval` to the base value [S1].
        *   **Grouped Linear Interpolation:**
            *   Divide resampling points into 3 levels based on distance from the viewpoint:
                *   Level 1: Closest (highest interpolation precision).
                *   Level 2: Middle.
                *   Level 3: Farthest (lowest interpolation precision) [S1].
            *   Apply different linear interpolation methods for each level, gradually decreasing the amount of interpolation calculation from Level 1 to Level 3 [S1]. *Note:* The specific interpolation formulas for each level are not provided in the sources. [G] Typically, this implies using trilinear interpolation for Level 1, bilinear or nearest-neighbor for Level 3, or reducing the number of texture lookups.
        *   **Compositing:**
            *   Update `accumulated_color` using front-to-back compositing:
                $$ C_{new} = C_{old} + \alpha \cdot c \cdot (1 - a) $$
                where $c$ is the color of the sample.
            *   Update `cumulative_opacity`:
                $$ a_{new} = a_{old} + \alpha \cdot (1 - a_{old}) $$

4.  **Early Termination:**
    *   After each compositing step, check if `cumulative_opacity` $a$ exceeds a threshold $T$ [S1].
    *   If $a > T$, terminate the ray calculation for this pixel. The sources state "exceeds 1" in one place and "a threshold can be set" in another [S1]. The threshold $T$ is typically close to 1 (e.g., 0.99) to avoid unnecessary computation when the pixel is saturated [S1].

5.  **Final Color:**
    *   If the ray completes traversal without early termination, the final pixel color is `accumulated_color`.

### Parameters
*   **Early Termination Threshold ($T$):** A value for cumulative opacity $a$ above which the ray is terminated. The exact numerical value is not specified in the sources, but it is set to a value close to 1 [S1].
*   **Sampling Interval ($s$):** Base step size. Not given in the sources.
*   **Adaptive Multiplier ($k$):** Factor by which to increase the sampling interval when encountering invalid points. Not given in the sources.

### Edge Cases and Pitfalls
*   **Boundary Interpolation Errors:** Without expanding sub-data blocks by one voxel, interpolated values may exceed the min/max of the original block, causing artifacts [S1].
*   **Precision:** The sources note that traditional interpolation is computationally expensive. The grouped interpolation method reduces this load but may introduce visual artifacts if the level transitions are not smooth. [G] Implementers should ensure smooth blending between interpolation levels to avoid visible seams.
*   **Dynamic Data:** The BVH is noted to be dynamically updatable if the dataset changes frequently, unlike K-D trees [S1]. However, the specific update algorithm is not detailed. [G] A standard approach is to rebuild the BVH or use a dynamic BVH structure (e.g., with refitting).

## Operating characteristics
*   **Time Complexity:** The BVH construction is $O(N \log N)$ or $O(N)$ depending on the splitting heuristic, where $N$ is the number of leaf nodes. Ray traversal is $O(\log N)$ for empty space skipping, but the actual sampling cost depends on the density of non-empty voxels and the adaptive sampling strategy.
*   **Memory Complexity:** The BVH stores bounding boxes for each node. The memory overhead is proportional to the number of nodes in the BVH. The sources state that the BVH avoids recording many empty nodes compared to octrees, reducing memory and computational complexity [S1].
*   **Measured Performance:** Experiments were conducted on an AMD Ryzen 5 5600H with Radeon Graphics 3.30 GHz, 16GB RAM, using Unity3D and HLSL [S1]. The method reduces hardware load and improves rendering speed, meeting real-time requirements for large-scale aerosols [S2].
*   **Strengths:**
    *   Avoids recording empty nodes, reducing complexity compared to octree-based methods [S1].
    *   Dynamically updatable, suitable for frequently changing datasets [S1].
    *   Early termination and adaptive sampling significantly reduce computation for transparent or empty regions.
*   **Limitations:**
    *   The specific interpolation details for the 3 levels are not provided, which may require implementation guesswork [G].
    *   The "merge and delete" rules for bounding boxes are not specified [S1].
    *   Performance is dependent on the efficiency of the BVH construction and traversal implementation.

## Background
This method was proposed to address the low efficiency, slow speed, and large resource consumption of traditional ray casting algorithms when rendering large-scale aerosol data (smoke, fog, dust) [S1, S2]. It builds on the core acceleration mechanisms defined in [Acceleration](18-acceleration.md), which reduce work units through culling/skipping, termination, and adaptation [G]. The method combines a BVH for empty-space skipping with early termination and grouped linear interpolation to enhance rendering speed and color quality [S1]. It is particularly suited for large-scale aerosol visualization where real-time rendering is required [S2].
