# K-D Tree-Guided Voxels

Also called: K-D Voxels, K-D tree-guided density-adaptive voxels

## Overview
K-D Tree-Guided Voxels is a density-adaptive rendering method that constructs multi-scale voxels from a K-D tree built on 3D points, allowing the skipping of empty spaces and guiding sampling based on point density as an approximation of volume density [S1]. Unlike conventional NeRFs that require explicit empty-space skipping, K-D voxels naturally stick to object surfaces described by the point cloud, automatically focusing rendering on the shape [S1]. It sets itself apart from sibling acceleration methods by deriving voxel geometry directly from the spatial partitioning of points rather than a fixed grid or octree, ensuring that voxels in the same tree layer contain the same number of points and thus uniform density [S1].

## How it works
**Inputs:** A 3D point cloud describing the scene geometry; a querying ray $r(t) = o + t \cdot d$ for each pixel.
**Outputs:** Color and opacity for the pixel.

**Data Structures:**
*   **K-D Tree:** A binary tree where each node represents a subset of points.
    *   **Node Layout:**
        *   `bbox`: Axis-aligned bounding box (min_x, max_x, min_y, max_y, min_z, max_z) with padding margins.
        *   `points`: List of 3D points in the subtree.
        *   `left_child`, `right_child`: References to child nodes.
        *   `depth`: Integer indicating the level in the tree.
    *   **Properties:**
        *   Nodes at the same depth have mutually exclusive bounding boxes.
        *   Upper-level nodes contain more points (larger voxels); lower-level nodes contain fewer points (smaller voxels).
        *   All voxels (bounding boxes) at the same K-D tree layer contain the same number of points, implying uniform density within that layer [S1].

**Numbered Steps:**
1.  **K-D Tree Construction:**
    *   Build a K-D tree on the input 3D points ($K=3$).
    *   For each node, compute its bounding box by taking the minimum and maximum x, y, z coordinates of all points in its subtree, applying proper padding margins [S1].
    *   Divide points in a top-down manner along one of the x, y, or z axes. Ensure that points are split such that voxels in the same K-D tree layer contain the same number of points [S1].
2.  **Ray Traversal and Minimal Voxel Identification:**
    *   For a querying ray, start from the root node.
    *   Recursively traverse the tree. A node is "intersected" if the ray intersects its bounding box.
    *   Identify "minimal" intersected voxels. A voxel is minimal if the ray intersects the node's bounding box but does not intersect any of its sub-node's bounding boxes [S1].
    *   This recursive procedure naturally locates voxels deep enough in the tree that tightly cover the surface [S1].
3.  **Segmentation:**
    *   The identified minimal voxels divide the querying ray into segments.
    *   Segments covered by a voxel are considered close to the surface and used for rendering.
    *   Segments not covered by any minimal voxel are considered empty spaces and skipped [S1].
4.  **Deterministic Spline Integration:**
    *   For each intersected voxel $i$ in ray passing order, define the segment interval $[l_i, r_i]$ along the ray [S1].
    *   Since points are not necessarily at voxel vertices, trilinear interpolation is not feasible. Instead, use deterministic spline integration [S1].
    *   Uniformly select points within the segment $[l_i, r_i]$.
    *   Calculate the average feature $f_i$ of the segment:
        $$ f_i = \frac {1}{r_i-l_i} \int _{l_i}^{r_i} \textbf {feature}(o+t\cdot d) \mathrm {d}t $$
        where $\textbf{feature}$ is obtained from the underlying point cloud (e.g., via KNN-based point features) [S1].
5.  **Color and Density Modeling:**
    *   For the representative point $p_i$ in the $i$-th voxel, obtain volume density $\sigma_i$ and color $c_i$ [S1].
    *   Use the Phong reflection model to model color, utilizing normal vectors estimated from the point cloud's shape [S1].
    *   Composite the results using standard front-to-back compositing over the segments defined by the minimal voxels [S1].

**Parameters:**
*   **Pre-set node depth:** The maximum depth to which the recursive procedure searches for minimal voxels. This controls the granularity of the rendering [S1].
*   **Padding margins:** Applied to bounding boxes during construction to ensure coverage [S1].

**Edge Cases and Pitfalls:**
*   **Empty Spaces:** Conventional methods require explicit skipping. K-D voxels avoid this because they stick to object surfaces; only space inside a voxel is considered, and deeper voxels are closer to the surface [S1].
*   **Point Distribution:** The method assumes the point cloud accurately describes the shape. Noisy or imprecise point clouds may lead to inaccurate voxel placement [S1].
*   **Integration Feasibility:** Trilinear interpolation cannot be used directly because points are not at voxel vertices; spline integration is required [S1].

**Pseudocode:**

```python
def build_kd_tree(points, depth=0):
    """
    Recursively builds a K-D tree.
    Ensures that nodes at the same depth have the same number of points.
    """
    if not points:
        return None
    
    # Compute bounding box for current node
    min_coords = min(points, key=lambda p: p.xyz)
    max_coords = max(points, key=lambda p: p.xyz)
    bbox = BoundingBox(min_coords.xyz, max_coords.xyz, padding=MARGIN)
    
    # Split points if not leaf
    if depth < MAX_DEPTH:
        # Choose split axis (e.g., based on variance or round-robin)
        axis = depth % 3
        # Split points into two equal-sized parts
        mid = len(points) // 2
        sorted_points = sorted(points, key=lambda p: p.xyz[axis])
        left_points = sorted_points[:mid]
        right_points = sorted_points[mid:]
        
        left_child = build_kd_tree(left_points, depth + 1)
        right_child = build_kd_tree(right_points, depth + 1)
        
        return Node(bbox=bbox, left=left_child, right=right_child, depth=depth)
    else:
        return Node(bbox=bbox, left=None, right=None, depth=depth)

def find_minimal_voxels(node, ray, minimal_voxels):
    """
    Recursively finds minimal intersected voxels.
    A voxel is minimal if the ray intersects the node's bbox
    but does not intersect any sub-node's bbox.
    """
    if node is None:
        return

    # Check if ray intersects current node's bounding box
    if not ray_intersects_bbox(ray, node.bbox):
        return

    # Check children
    left_intersected = node.left and ray_intersects_bbox(ray, node.left.bbox)
    right_intersected = node.right and ray_intersects_bbox(ray, node.right.bbox)

    if not left_intersected and not right_intersected:
        # No sub-nodes intersected, so this node's voxel is minimal
        # Record the intersection interval [l, r]
        l, r = ray_bbox_intersection(ray, node.bbox)
        minimal_voxels.append((node, l, r))
    else:
        # Recurse into intersected children
        if left_intersected:
            find_minimal_voxels(node.left, ray, minimal_voxels)
        if right_intersected:
            find_minimal_voxels(node.right, ray, minimal_voxels)

def integrate_segment(ray, l, r, point_cloud):
    """
    Performs deterministic spline integration over segment [l, r].
    """
    # Uniformly sample points along the segment
    num_samples = SAMPLES_PER_SEGMENT
    features = []
    for t in linspace(l, r, num_samples):
        point_pos = ray.origin + t * ray.direction
        # Get feature from point cloud (e.g., via KNN)
        feature = get_point_cloud_feature(point_pos, point_cloud)
        features.append(feature)
    
    # Average feature
    avg_feature = sum(features) / len(features)
    return avg_feature

def render_ray(ray, kd_tree_root, point_cloud):
    """
    Renders a single ray using K-D tree-guided voxels.
    """
    minimal_voxels = []
    find_minimal_voxels(kd_tree_root, ray, minimal_voxels)
    
    # Sort voxels by distance (l value)
    minimal_voxels.sort(key=lambda x: x[1])
    
    acc_color = Color(0, 0, 0)
    acc_alpha = 0.0
    
    for node, l, r in minimal_voxels:
        # Integrate segment
        feature = integrate_segment(ray, l, r, point_cloud)
        
        # Get density and color from representative point
        # Using Phong reflection with normal vectors from point cloud
        sigma, c = get_phong_color_and_density(node.representative_point, point_cloud)
        
        # Front-to-back compositing
        alpha = 1.0 - exp(-sigma * (r - l))
        weight = alpha * (1.0 - acc_alpha)
        acc_color += c * weight
        acc_alpha += weight
        
        if acc_alpha > 1.0 - EPSILON:
            break
            
    return acc_color
```

## Subtopics

### Deterministic Spline Integration
A deterministic integration method for obtaining segment features within each voxel, used because trilinear interpolation is not feasible when points are not at voxel vertices [S1]. It uniformly selects points in the segment defined by interval $[l_i, r_i]$ and integrates their features to obtain the average feature $f_i$ [S1]. Choose this when the point cloud does not align with voxel vertices, avoiding the artifacts of stochastic integration [S1].

### Balanced kd-tree Acceleration
Data structures built to accelerate queries of samples for indexing and brushing-and-linking, set up for each layer of parallel coordinates [S2]. It constructs one kd-tree for parallel coordinates lines representing original data values (using data domain dimensionality $k=m$) and 2D kd-trees for continuous indexed points (using downsampled indexed points data from the volume) [S2]. Choose this for multivariate volume visualization in parallel coordinates views, where it accelerates sample queries [S2].

## Operating characteristics
*   **Time Complexity:** Construction is $O(N \log N)$ for the K-D tree, where $N$ is the number of points. Rendering traversal is proportional to the number of minimal voxels intersected by the ray, which is typically much smaller than the total number of voxels in a dense grid.
*   **Memory Complexity:** Depends on the number of points and the K-D tree structure. Each node stores a bounding box and references to children.
*   **Measured Performance:** Not given in the sources for K-D voxels specifically. However, related kd-tree acceleration in parallel coordinates shows significant preprocessing time reductions (38% to 73%) for simulation data and MRI scans, but is not advantageous for noisy CT data where per-voxel computation is recommended [S2].
*   **Strengths:** Naturally skips empty spaces without explicit culling logic; density-adaptive sampling is inherent in the tree structure; multi-scale representation allows coarse-to-fine rendering [S1].
*   **Limitations:** Requires a high-quality point cloud; noisy point clouds may degrade performance; trilinear interpolation is not directly applicable, requiring spline integration [S1].
*   **When to use:** When rendering point-cloud-guided NeRFs or scenes where the geometry is well-described by a point cloud and empty-space skipping is desired without explicit culling [S1].
*   **When not to use:** When the point cloud is noisy or imprecise, as this affects voxel placement and rendering accuracy [S1].

## Background
K-D Tree-Guided Voxels were proposed in the context of NeuralEditor, a point cloud-guided NeRF model for novel-view synthesis and shape editing [S1]. The method leverages K-D trees to construct density-adaptive voxels, enabling natural and efficient rendering by sticking to object surfaces [S1]. It builds on the principles of acceleration structures and traversal  and early ray termination and culling , but derives the voxel structure from the point cloud rather than a fixed grid.
