# Reprojection with Temporal Accumulation

Also called: Temporal Anti-Aliasing (TAA) via reprojection

## Overview
Reprojection with Temporal Accumulation stabilizes voxel rendering over time by blending the current frame's color with the accumulated color from the previous frame, using camera motion vectors to align pixels [S1, unofficial]. It differs from sibling methods like [Inter-Ray Coherency](1030-inter-ray-coherency.md) or [Exploiting Temporal Coherence (C-Buffer)](5560-exploiting-temporal-coherence-c-buffer.md), which track state changes in volume data or buffers, by operating in image space to amortize rendering costs and reduce noise/aliasing through temporal history [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Current frame color (`colour_attachment`), current frame world position (`position_attachment`), previous frame accumulation buffer (`accumulation_attachment`), camera matrices (`trace_uniforms.last_camera`), and parameters `reprojection_factor` and `indirect_lighting`.
*   **Outputs:** Final output color.

**Data Structures:**
*   `colour_attachment`: `texture_2d<f32>`, binding 3.
*   `position_attachment`: `texture_storage_2d<rgba32float, read_write>`, binding 3.
*   `accumulation_attachment`: `texture_storage_2d<rgba16float, read_write>`, binding 1.

**Steps:**
1.  Load the current frame's color $C_{curr}$ from `colour_attachment` at `sample_pos`.
2.  Load the current frame's world position $P_{curr}$ from `position_attachment` at `sample_pos`.
3.  If `indirect_lighting` is non-zero AND `reprojection_factor` > 0.0, proceed with reprojection; otherwise, output $C_{curr}$ directly [S1, unofficial].
4.  Compute local color bounds to detect edges:
    *   Sample the current color at `sample_pos` and its 8 neighbors ($S_0$ to $S_8$).
    *   Calculate `min_col` as the average of the 'plus' bounds (cross pattern: center, up, down, left, right).
    *   Calculate `max_col` as the average of the 'square' bounds (3x3 pattern: all 9 samples).
    *   These bounds define the acceptable range for the accumulated color to prevent bleeding [S1, unofficial].
5.  Transform $P_{curr}$ to the previous frame's clip space using `trace_uniforms.last_camera`.
6.  Convert clip space coordinates to Normalized Device Coordinates (NDC) and then to texture coordinates `last_texture` for the accumulation buffer.
7.  Check validity: If the projected previous position is outside the NDC range $[-1, 1]$, the pixel is invalid (e.g., newly visible or occluded). In this case, skip blending and output $C_{curr}$ [S1, unofficial].
8.  Load the accumulated color $C_{prev}$ from `accumulation_attachment` at `last_texture`.
9.  Blend the colors:
    $$ C_{mixed} = C_{curr} \times (1.0 - \text{reprojection\_factor}) + C_{prev} \times \text{reprojection\_factor} $$
10. Clamp $C_{mixed}$ to the local bounds [`min_col`, `max_col`] to prevent ghosting and bleeding across edges [S1, unofficial].
11. Return the clamped $C_{mixed}$ as the final output.

**Accumulation Shader:**
A separate pass simply stores the current frame's color into `accumulation_attachment` for use in the next frame [S1, unofficial].

**Pseudocode:**
```python
def reprojection_pass(sample_pos, colour_attachment, position_attachment, accumulation_attachment, last_camera, reprojection_factor, indirect_lighting):
    # 1. Load current data
    colour = colour_attachment.sample(sample_pos)
    world_pos = position_attachment.sample(sample_pos)
    
    # 3. Check if reprojection is enabled
    if indirect_lighting == 0 or reprojection_factor <= 0.0:
        return colour
    
    # 4. Compute local bounds for clamping
    # Sample 3x3 neighborhood
    samples = [colour_attachment.sample(sample_pos + offset) for offset in [-1, 0, 1] in both x and y]
    
    # Plus pattern (center, up, down, left, right)
    plus_indices = [4, 1, 7, 3, 5] # Assuming row-major 3x3: 012, 345, 678
    min_col = min(samples[i] for i in plus_indices)
    max_col = max(samples[i] for i in plus_indices)
    
    # Square pattern (all 9)
    min_col_sq = min(samples)
    max_col_sq = max(samples)
    
    # Average of plus and square bounds as per source description
    # Note: Source says "average of the 'plus' bounds ... and 'square' bounds"
    # This likely means averaging the min/max values or the sets. 
    # Interpreting as averaging the bounds themselves for robustness:
    final_min = (min_col + min_col_sq) / 2.0
    final_max = (max_col + max_col_sq) / 2.0

    # 5. Transform to previous frame
    clip_pos = last_camera.transform(world_pos)
    
    # 6. Convert to NDC and texture coordinates
    ndc = clip_pos / clip_pos.w
    last_texture = ndc.xy * 0.5 + 0.5 # Standard NDC to UV conversion
    
    # 7. Check validity
    if not (-1.0 <= ndc.x <= 1.0 and -1.0 <= ndc.y <= 1.0):
        return colour
        
    # 8. Load previous accumulation
    prev_colour = accumulation_attachment.sample(last_texture)
    
    # 9. Blend
    mix_amount = reprojection_factor
    mixed = colour * (1.0 - mix_amount) + prev_colour * mix_amount
    
    # 10. Clamp to local bounds
    # Assuming component-wise clamp
    output = clamp(mixed, final_min, final_max)
    
    return output
```

**Parameters:**
*   `reprojection_factor`: Float uniform controlling blend weight. Typical values are not specified, but it must be $> 0.0$ for reprojection to occur [S1, unofficial].
*   `indirect_lighting`: Uint uniform. Reprojection is skipped if this is 0 [S1, unofficial].

## Subtopics

### Alpha-Max Quasi-Depth Motion Vector
A method to compute screen-space motion vectors for direct volume rendering (DVR) by using the 3D position of the point with maximum alpha along the ray as a proxy for depth, enabling temporal reprojection despite the lack of a single surface depth value [S2]. It is chosen when standard depth buffers are unavailable or unreliable for volumetric data. The step involves: for each pixel $(u, v)$, identifying the world space point $p$ where alpha is maximum along the ray; reprojecting $p$ to the previous frame's coordinates $(u', v')$ using previous camera matrices; and calculating the motion vector as $(u - u', v - v')$ [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per pixel for the reprojection pass, assuming constant-time texture sampling and arithmetic.
*   **Memory Complexity:** Requires storage for the accumulation buffer (`rgba16float`) and position buffer (`rgba32float`) in addition to the color buffer.
*   **Performance:** Reduces noise and aliasing by leveraging temporal coherence, effectively amortizing the cost of high-quality rendering over multiple frames [S1, unofficial].
*   **Strengths:** Effective at stabilizing images during camera movement; reduces flickering in noisy renders.
*   **Limitations:** Prone to ghosting artifacts if disocclusion is not handled (mitigated by clamping to local bounds) [S2]. Requires accurate motion vectors or position buffers.
*   **When to use:** When rendering dynamic volumes with camera movement and noise reduction is desired.
*   **When not to use:** When `indirect_lighting` is zero or `reprojection_factor` is $\le 0.0$, or when strict per-frame accuracy is required without temporal history.

## Background
The technique is implemented in the `bevy-voxel-engine` project, an unofficial voxel engine for the Bevy game engine [S1, unofficial]. It is also discussed in the context of medical volume visualization, where it is used to stabilize Direct Volume Rendering (DVR) by incorporating temporal anti-aliasing via a post-processing pass using history color buffers and motion vectors [S2].
