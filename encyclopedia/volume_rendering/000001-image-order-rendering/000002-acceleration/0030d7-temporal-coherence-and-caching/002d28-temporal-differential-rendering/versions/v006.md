# Temporal Differential Rendering

Also called: Dirty-brick partial re-render, Dirty-row flush

## Overview
Temporal differential rendering reduces computational load by skipping the rendering of screen regions that have not changed since the previous frame, leveraging temporal coherence. It differs from full reprojection methods by explicitly tracking "dirty" regions (bricks or rows) on the CPU and using hardware acceleration (compute shaders or canvas buffers) to bypass processing for clean areas, rather than relying on geometric warping or accumulation [S1, S2, unofficial].

## How it works
The method operates on two primary granularities: screen tiles (for GPU-based volume rendering) and rows (for CPU/Canvas-based rendering). Both variants share the core logic of hashing current frame content, comparing it against a previous frame's hash, and conditionally executing rendering or buffer updates.

### Inputs and Outputs
*   **Inputs:**
    *   Current frame data: Volume state (bricks), camera parameters, or canvas content (characters/colors).
    *   Previous frame data: Dirty region mask, previous hashes, or previous buffers.
*   **Outputs:**
    *   Rendered image (only for dirty regions).
    *   Updated dirty region mask/hash for the next frame.

### Data Structures

#### 1. Tile-Based (GPU/Compute Shader) [S1, unofficial]
*   **Dirty Brick List:** A list of world-space bricks marked as modified by physics or user edits.
*   **Tile Grid:** The screen is divided into $8 \times 8$ pixel tiles.
*   **Hit Distance Texture:** A `r32float` texture storing the first-hit distance for each tile, computed at $1/8$ resolution (one ray per tile).
*   **Safety Margin:** A constant value (e.g., 16 voxels) used to prevent z-fighting or gaps when fast-forwarding rays.

#### 2. Row-Based (Canvas/ANSI) [S2, unofficial]
*   **Canvas Buffer:** A 2D array `char[_H, _W]` storing character data.
*   **Color Buffer:** A 2D array `string?[_H, _W]` storing color codes.
*   **Row Hash Array:** An array `uint[_H]` storing the FNV hash for each row of the previous frame.
*   **FNV Constants:**
    *   `FNV_OFFSET = 2166136261u`
    *   `FNV_PRIME = 16777619u`

### Algorithm Steps

#### Variant A: Dirty-Brick Tile Culling [S1, unofficial]
1.  **Identify Dirty Bricks:** On the CPU, collect bricks modified by physics simulations or edits.
2.  **Project to Tiles:** Project these dirty bricks onto the screen to determine which $8 \times 8$ tiles are affected. Mark these tiles as "dirty."
3.  **Pre-Pass (Hit Distance):** For dirty tiles, launch a ray at $1/8$ resolution. Compute the first-hit distance and write it to the `r32float` texture. Clean tiles skip this pass.
4.  **Main Pass (Raymarching):**
    *   For each tile, read the hit distance from the texture.
    *   If the tile is clean, the compute shader early-outs (skips rendering).
    *   If dirty, fast-forward the ray to `hit_distance - safety_margin` (e.g., 16 voxels) and continue raymarching.
5.  **Skip Check:** If no tiles are dirty, both compute passes are skipped entirely.

#### Variant B: Dirty-Row Flush with Hashing [S2, unofficial]
1.  **Initialize Hash:** For each row $y$, initialize hash $h = \text{FNV\_OFFSET}$.
2.  **Compute Row Hash:**
    *   Loop $x$ from $0$ to $W-1$:
        *   Get character $ch = \text{canvas}[y, x]$.
        *   Update hash: $h = (h \oplus ch) \times \text{FNV\_PRIME}$.
        *   Get color $col = \text{colors}[y, x]$.
        *   Get color ID: $colId = \text{col} \text{ is null} ? 0 : \text{GetHashCode}(col)$.
        *   Update hash: $h = (h \oplus colId) \times \text{FNV\_PRIME}$.
    *   Store $h$ as `currentRowHash[y]`.
3.  **Compare and Update:**
    *   If `currentRowHash[y] == prevRowHash[y]`, the row is clean. Continue to next row.
    *   If changed:
        *   Copy `canvas[y, :]` to `prevCanvas[y, :]`.
        *   Copy `colors[y, :]` to `prevColors[y, :]`.
        *   Update `prevRowHash[y] = currentRowHash[y]`.
        *   Mark row as written.
4.  **Flush Output:**
    *   For each dirty row $y$:
        *   Generate ANSI cursor move sequence: `\x1b[{y+1};1H`.
        *   Loop $x$ from $0$ to $W-1$:
            *   If color changed from previous column, append color code or reset.
            *   Append character (replace `\0` with space).
    *   Write accumulated string to console.

### Pseudocode (Row-Based Hashing)
```python
# Constants
FNV_OFFSET = 2166136261
FNV_PRIME = 16777619

def compute_row_hash(canvas_row, colors_row):
    h = FNV_OFFSET
    for x in range(len(canvas_row)):
        ch = canvas_row[x]
        h = (h ^ ch) * FNV_PRIME
        
        col = colors_row[x]
        col_id = 0 if col is None else get_hash_code(col)
        h = (h ^ col_id) * FNV_PRIME
    return h

def update_frame(canvas, colors, prev_canvas, prev_colors, prev_row_hashes):
    current_row_hashes = []
    dirty_rows = []
    
    H, W = canvas.shape
    
    # Check dimension mismatch
    if prev_canvas.shape != canvas.shape:
        reinit_prev_buffers(prev_canvas, prev_colors, prev_row_hashes, H, W)
        
    for y in range(H):
        row_hash = compute_row_hash(canvas[y, :], colors[y, :])
        current_row_hashes.append(row_hash)
        
        if row_hash != prev_row_hashes[y]:
            dirty_rows.append(y)
            # Update previous buffers for next frame
            prev_canvas[y, :] = canvas[y, :]
            prev_colors[y, :] = colors[y, :]
            prev_row_hashes[y] = row_hash
            
    return dirty_rows, current_row_hashes

def flush_dirty_rows(dirty_rows, canvas, colors, H, W):
    output_buffer = ""
    any_writes = False
    
    for y in dirty_rows:
        any_writes = True
        # ANSI escape sequence to move cursor to row y, column 1
        output_buffer += f"\x1b[{y+1};1H"
        
        last_color = None
        for x in range(W):
            col = colors[y, x]
            if col != last_color:
                if col is None:
                    output_buffer += "\x1b[0m" # Reset
                else:
                    output_buffer += col
                last_color = col
            
            ch = canvas[y, x]
            output_buffer += ch if ch != '\0' else ' '
            
    if any_writes:
        print(output_buffer, end="")
```

### Parameters
*   **Tile Size:** $8 \times 8$ pixels [S1, unofficial].
*   **Safety Margin:** 16 voxels (distance to subtract from hit distance) [S1, unofficial].
*   **FNV Constants:** Offset 2166136261, Prime 16777619 [S2, unofficial].
*   **Resolution Scale:** Can be scaled (e.g., `RENDER_SCALE`), with bilinear upscale [S1, unofficial].

### Edge Cases and Pitfalls
*   **Dimension Mismatch:** If the canvas or volume resolution changes, previous buffers must be reinitialized to match current dimensions [S2, unofficial].
*   **Precision:** Hash collisions are theoretically possible but rare with FNV-1a; however, exact buffer copy is required for dirty rows to ensure consistency [S2, unofficial].
*   **Empty Regions:** Rows with no changes should be skipped entirely to save I/O or shader dispatch time [S1, S2, unofficial].

## Subtopics

### Partial Volume Rendering Update
A variant where a partial volume rendering pass is performed between visibility detection passes to update occluding data with newly loaded bricks. The frequency of total scene rendering must be chosen carefully due to high cost. Future work suggests storing ray state (position, direction, hierarchy position, DDA stack) in image-space buffers for progressive rendering resumption [S3, unofficial].

### Anti-flicker via Freezing
A heuristic used in differentiable rendering (e.g., DiffBMP) to prevent flicker in static regions. It computes an inter-frame difference mask $D$. Primitives $i$ with bounding boxes $B_i$ that do not intersect the support of $D$ ($B_i \cap \text{support}(D) = \emptyset$) are frozen ($freeze_i = 1$). Only non-frozen primitives are updated during optimization, preventing spurious edits and cascading flicker in static areas [S4, unofficial].

### Dirty-Row Flush with Hashing
The specific implementation using per-row FNV hashing to detect changes in text/ANSI canvas rendering. It avoids full buffer copies by only flushing rows where the hash differs, using ANSI escape sequences to update the terminal efficiently [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of dirty regions (tiles or rows), not the total frame size. In static scenes, complexity approaches $O(1)$ or $O(\text{changes})$.
*   **Memory Complexity:** Requires storing previous frame state (hashes, buffers, or hit distances). For tile-based, an additional `r32float` texture for hit distances is needed [S1, unofficial].
*   **Strengths:** Significant performance gains in static or slowly changing scenes; avoids expensive full-frame rasterization or raymarching.
*   **Limitations:** Requires explicit tracking of changes (dirty flags); overhead of hashing and comparison must be less than the cost of rendering the region. Not suitable for highly dynamic scenes where most pixels change every frame.
*   **Hardware:** GPU variant relies on compute shaders for early-out logic [S1, unofficial]. CPU variant relies on efficient hashing and I/O buffering [S2, unofficial].

## Background
Temporal differential rendering is a technique rooted in the exploitation of temporal coherence in rendering pipelines. The tile-based variant is exemplified in voxel rendering engines like `voxelG`, where dirty bricks from physics are projected to screen tiles to cull raymarching work [S1, unofficial]. The row-based hashing variant appears in terminal/console rendering optimizations, such as `csRaymarching`, to minimize ANSI output overhead [S2, unofficial]. The concept of partial updates and freezing static regions to prevent flicker is also applied in differentiable rendering frameworks like DiffBMP [S4, unofficial] and procedural volume exploration algorithms [S3, unofficial].
