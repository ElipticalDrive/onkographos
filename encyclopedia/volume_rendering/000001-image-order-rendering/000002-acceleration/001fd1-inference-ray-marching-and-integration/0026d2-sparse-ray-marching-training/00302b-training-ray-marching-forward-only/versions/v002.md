# Training Ray Marching (Forward Only)


## Overview
A training-specific ray marching function that estimates the maximum number of points to allocate based on mean count from previous epochs, enabling faster training by avoiding over-allocation, while supporting force-all-rays mode for stability [S1, unofficial]. It sets itself apart from its sibling [CUDA Ray Marching (IDDR-NGP Backend)](5788-cuda-ray-marching-iddr-ngp-backend.md) by explicitly managing memory allocation heuristics via `mean_count` and `step_counter` to optimize throughput during the training loop, rather than just executing the raw marching logic.

## How it works
**Inputs:**
- `rays_o`: Origin tensor, shape $[N, 3]$.
- `rays_d`: Direction tensor, shape $[N, 3]$.
- `density_grid`: Density grid tensor, shape $[H, H, H]$.
- `mean_density`: Float, mean density value.
- `iter_density`: Float, density value for the current iteration.
- `bound`: Float, spatial boundary (default $10^{-4}$).
- `mean_count`: Int, estimated max points number from previous epoch.
- `perturb`: Bool, enable perturbation.
- `force_all_rays`: Bool, if true, ignores `mean_count` and processes all rays.
- `step_counter`: Int array $[2]$, optional counter for points and rays; defaults to zeros if `None`.
- `align`: Int, alignment padding value (default 0).

**Outputs:**
- `xyzs`: Tensor of sampled positions, shape $[m, 3]$.
- `dirs`: Tensor of sampled directions, shape $[m, 3]$.
- `deltas`: Tensor of step sizes, shape $[m]$.
- `rays`: Int array $[N, 3]$, ray metadata.

**Data Structures:**
- `rays`: Int array of shape $[N, 3]$.
  - Column 0: Ray ID.
  - Column 1: Offset into the `xyzs`, `dirs`, `deltas` arrays.
  - Column 2: Number of steps for that ray.

**Steps:**
1. Reshape `rays_o` and `rays_d` to contiguous views of shape $[-1, 3]$.
2. Get $N$ (num rays) from `rays_o.shape[0]` and $H$ (grid resolution) from `density_grid.shape[0]`.
3. Initialize $M$ (max points) to $N \times 1024$ as a hardcoded default.
4. If `force_all_rays` is false and `mean_count` > 0, set $M = \text{mean\_count}$.
5. If `align` > 0, pad $M$ to the next multiple of `align`.
6. Initialize output tensors `xyzs`, `dirs`, `deltas` with zeros of shape $[M, 3]$, $[M, 3]$, $[M]$ respectively.
7. Initialize `rays` tensor of shape $[N, 3]$ with dtype int32.
8. If `step_counter` is `None`, initialize it as a zero tensor of shape $[2]$ with dtype int32.
9. Call the CUDA backend kernel `_backend.march_rays_train` with all parameters.
10. If `force_all_rays` is true or `mean_count` <= 0:
    a. Retrieve the actual number of points $m$ from `step_counter[0].item()`.
    b. Pad $m$ to the next multiple of `align` if `align` > 0.
    c. Slice `xyzs`, `dirs`, and `deltas` to size $m$.

**Pseudocode:**
```python
def march_rays_train(
    rays_o: torch.Tensor,
    rays_d: torch.Tensor,
    density_grid: torch.Tensor,
    mean_density: float,
    iter_density: float,
    bound: float = 1e-4,
    mean_count: int = 0,
    perturb: bool = False,
    force_all_rays: bool = False,
    step_counter: torch.Tensor = None,
    align: int = 0,
    _backend=None  # Placeholder for the actual CUDA backend module
) -> tuple:
    # 1. Reshape inputs to contiguous views
    rays_o = rays_o.contiguous().view(-1, 3)
    rays_d = rays_d.contiguous().view(-1, 3)
    
    # 2. Get dimensions
    N = rays_o.shape[0]
    H = density_grid.shape[0]
    
    # 3. Initialize M (max points)
    M = N * 1024
    
    # 4. Adjust M based on mean_count and force_all_rays
    if not force_all_rays and mean_count > 0:
        M = mean_count
        
    # 5. Align M
    if align > 0:
        M = ((M + align - 1) // align) * align
        
    # 6. Initialize output tensors
    xyzs = torch.zeros((M, 3), dtype=torch.float32, device=rays_o.device)
    dirs = torch.zeros((M, 3), dtype=torch.float32, device=rays_o.device)
    deltas = torch.zeros((M,), dtype=torch.float32, device=rays_o.device)
    
    # 7. Initialize rays metadata
    rays = torch.zeros((N, 3), dtype=torch.int32, device=rays_o.device)
    
    # 8. Initialize step_counter if None
    if step_counter is None:
        step_counter = torch.zeros((2,), dtype=torch.int32, device=rays_o.device)
        
    # 9. Call CUDA backend
    # Note: The exact signature of _backend.march_rays_train is assumed to match
    # the parameters described in the source.
    _backend.march_rays_train(
        rays_o, rays_d, density_grid,
        mean_density, iter_density, bound,
        xyzs, dirs, deltas, rays,
        step_counter, perturb, force_all_rays
    )
    
    # 10. Post-processing if force_all_rays or mean_count <= 0
    if force_all_rays or mean_count <= 0:
        m = step_counter[0].item()
        
        # Pad m to align
        if align > 0:
            m = ((m + align - 1) // align) * align
            
        # Slice outputs
        xyzs = xyzs[:m]
        dirs = dirs[:m]
        deltas = deltas[:m]
        
    return xyzs, dirs, deltas, rays, step_counter
```

**Parameters:**
- `bound`: Float, spatial boundary.
- `density_grid`: Float array $[H, H, H]$, density grid.
- `mean_density`: Float, mean density value.
- `iter_density`: Float, density value for the current iteration.
- `step_counter`: Int array $[2]$, optional counter for points and rays.
- `mean_count`: Int, estimated max points number from previous epoch.
- `perturb`: Bool, enable perturbation.
- `force_all_rays`: Bool, if true, ignores `mean_count` and processes all rays.

**Edge Cases and Pitfalls:**
- If `mean_count` underestimates the required points, rays may be randomly ignored unless `force_all_rays` is enabled [S1, unofficial].
- Precision issues may arise if `step_counter` is not properly initialized or if the CUDA kernel writes beyond the allocated buffer when `force_all_rays` is false and `mean_count` is too small.

## Subtopics

## Operating characteristics
**Time and Memory Complexity:**
- Memory allocation is $O(N \times 1024)$ by default, but can be reduced to $O(\text{mean\_count})$ if `mean_count` is provided and `force_all_rays` is false.
- Time complexity is dominated by the CUDA kernel execution, which is $O(N \times S)$ where $S$ is the average number of steps per ray.

**Measured Performance:**
- Not given in the sources.

**Scaling:**
- Scaling with $N$ is linear.
- Scaling with $H$ affects the density grid lookup cost.

**Strengths and Limitations:**
- Strengths: Reduces memory allocation overhead during training by reusing estimates from previous epochs.
- Limitations: Risk of under-estimation leading to ray loss if `mean_count` is inaccurate.

**When to Use:**
- Use during training when memory bandwidth is a bottleneck and previous epoch statistics are reliable.
- Use `force_all_rays=True` during debugging or when `mean_count` is unreliable.

## Background
Origin: Part of the neural point rendering pipeline, specifically designed for efficient training of sparse 3D point clouds with learned features.
History: Developed as part of the NeuralPoints framework to optimize the ray marching step for training.
Usage: Used in training loops for neural point rendering to aggregate sampled neural point features and blend them along rays.
