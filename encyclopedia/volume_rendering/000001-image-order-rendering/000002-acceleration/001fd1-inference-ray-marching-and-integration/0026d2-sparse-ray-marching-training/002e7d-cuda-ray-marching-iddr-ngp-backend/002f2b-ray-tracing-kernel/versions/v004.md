# Ray Tracing Kernel


## Overview
The Ray Tracing Kernel is a GPU-accelerated compute shader that performs volumetric tracing and lighting by stepping through a 3D grid, dynamically adjusting step size and cascade resolution based on distance from the center, and accumulating transmittance (alpha) [S1, S2, unofficial]. It serves as the core inference engine for sparse ray marching, supporting both forward rendering (image generation) and backward pass (gradient computation) for training [S2, unofficial]. It distinguishes itself from standard ray marching by using a hierarchical cascade structure where the sampling resolution expands exponentially as the ray moves away from the grid center, optimizing performance for large volumes [S1, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
*   `id`: Thread ID (uint3), representing the output voxel or ray index.
*   `GridResolution`: The base resolution of the 3D grid (uint).
*   `GridHalfResolution`: Half of `GridResolution` (uint).
*   `GridCascadeBase`: A uint2 specifying the base cascade index (`x`) and the maximum cascade index limit (`y`) [S1, unofficial].
*   `grid`: Sparse density grid data structure [S2, unofficial].
*   `ray_spec`: Ray specifications including origin and direction [S2, unofficial].
*   `opt`: Tracing options [S2, unofficial].
*   `sphfunc_val`: Spherical harmonic coefficients/values for SH evaluation [S2, unofficial].
*   `grad_output`: Gradient of the output loss with respect to the ray color/transmittance (for backward kernel) [S2, unofficial].
*   `color_cache`, `log_transmit_in`, `beta_loss`, `sparsity_loss`: Additional inputs for backward pass regularization and gradient accumulation [S2, unofficial].

**Outputs:**
*   `LightTex3d` / `CVCT_tex3d`: Output texture storing the accumulated alpha/transmittance or final color [S1, unofficial].
*   `grads`: Gradients with respect to grid densities and other parameters (for backward kernel) [S2, unofficial].

### Data Structures
*   **Shared Memory `sphfunc_val`**: Array of size `TRACE_RAY_CUDA_RAYS_PER_BLOCK` by 9 floats. Stores spherical harmonic function values for rays in the block [S2, unofficial].
*   **Shared Memory `ray_spec`**: Array of size `TRACE_RAY_CUDA_RAYS_PER_BLOCK`. Stores ray specifications (origin, direction) for rays in the block [S2, unofficial].
*   **Shared Memory `temp_storage`**: Array of size `TRACE_RAY_CUDA_RAYS_PER_BLOCK`. Temporary storage for warp reduction operations [S2, unofficial].

### Parameters
*   `SAMPLE_STEP_BASE`: Base step size for tracing, typically 0.45 [S1, unofficial].
*   `EXPAND_STEP`: Multiplier for expansion factor per step, typically 1.21 [S1, unofficial].
*   `sh_data_dim`: Dimension limit for SH evaluation per warp lane [S2, unofficial].
*   Warp size: 32 threads. `lane_id = threadIdx.x & 0x1F` [S2, unofficial].

### Algorithm Steps

1.  **Initialization**:
    *   Calculate the position relative to the grid center: `pos = id - (GridHalfResolution - 0.5)` [S1, unofficial].
    *   Calculate the central distance: `central_pos = abs(pos)`, `central_distance = max(central_pos.x, max(central_pos.y, central_pos.z))` [S1, unofficial].
    *   Normalize distance and compute expansion factor: `max_distance = GridHalfResolution - 0.5`, `central_distance /= max_distance`, `expand = max(log2(central_distance) + 2, 1)` [S1, unofficial].
    *   Initialize alpha: `alpha = 1` [S1, unofficial].
    *   Initialize cascade base: `grid_cascade_base = GridCascadeBase.x` [S1, unofficial].

2.  **Forward Kernel Specifics (S2, unofficial)**:
    *   Calculate spherical harmonic function values: `calc_sphfunc(grid, lane_id, ray_id, ray_spec[ray_blk_id].dir, sphfunc_val[ray_blk_id])` [S2, unofficial].
    *   Find ray bounds within the grid: `ray_find_bounds(ray_spec[ray_blk_id], grid, opt, ray_id)` [S2, unofficial].
    *   Synchronize warps: `__syncwarp((1U << grid.sh_data_dim) - 1)` [S2, unofficial].
    *   If `lane_id >= grid.sh_data_dim`, the thread returns early [S2, unofficial].

3.  **Main Tracing Loop**:
    *   While `true`:
        *   **Cascade Check**: If `expand >= 2.0`:
            *   If `grid_cascade_base >= GridCascadeBase.y`, break loop [S1, unofficial].
            *   Increment cascade: `grid_cascade_base += GridResolution` [S1, unofficial].
            *   Halve expansion: `expand *= 0.5` [S1, unofficial].
            *   Halve position: `pos *= 0.5` [S1, unofficial].
        *   **Sample Low**: Calculate sample position `p = pos + (GridHalfResolution - 0.5)`, `p.y += grid_cascade_base`. Sample grid: `a_low = SampleGV(p)` [S1, unofficial].
        *   **Sample High**:
            *   If `grid_cascade_base >= GridCascadeBase.y`, `a_high = 1` [S1, unofficial].
            *   Else, calculate `q = pos * 0.5 + (GridHalfResolution - 0.5)`, `q.y += grid_cascade_base + GridResolution`. Sample grid: `a_high = SampleGV(q)` [S1, unofficial].
        *   **Interpolate Alpha**: `a = lerp(a_low, a_high, expand - 1)` [S1, unofficial].
        *   **Update Step and Accumulate**:
            *   `sample_step = SAMPLE_STEP_BASE * expand` [S1, unofficial].
            *   `alpha *= pow(a, sample_step)` [S1, unofficial].
            *   `pos.z -= sample_step` [S1, unofficial].
            *   `expand *= EXPAND_STEP` [S1, unofficial].

4.  **Backward Kernel Specifics (S2, unofficial)**:
    *   Takes `grad_output`, `color_cache`, `log_transmit_in`, `beta_loss`, `sparsity_loss`, and `grads` as inputs [S2, unofficial].
    *   Sets up ray spec and calls `trace_ray_cuvol` (likely handling backward logic internally or calling a specific backward trace function) [S2, unofficial].

5.  **Output**:
    *   Adjust ID: `id.y += GridCascadeBase.x` [S1, unofficial].
    *   Write result: `LightTex3d[id] = alpha` (or equivalent output texture) [S1, unofficial].

### Edge Cases and Pitfalls
*   **Infinite Loop Prevention**: The loop breaks when `expand >= 2.0` and `grid_cascade_base` reaches `GridCascadeBase.y`. If the cascade base is already at the limit, it breaks immediately on the first check [S1, unofficial].
*   **SH Data Dimension Check**: If `lane_id >= grid.sh_data_dim`, the thread returns early. This implies SH evaluation is done per lane within a warp, limited by `sh_data_dim` [S2, unofficial].
*   **Precision**: The use of `log2` and floating-point arithmetic for `expand` and `sample_step` may introduce precision errors, especially for large grids or extreme distances.
*   **Boundary Conditions**: The calculation of `central_distance` and `expand` assumes the ray starts within or near the grid center. Rays starting far outside may have undefined behavior if not clamped or handled by `ray_find_bounds` [S2, unofficial].

## Operating characteristics

*   **Time Complexity**: The number of steps in the loop depends on the initial `expand` value and the `EXPAND_STEP`. Since `expand` grows exponentially, the number of steps is logarithmic with respect to the distance from the center. However, the cascade switching adds a constant overhead. Overall, it is efficient for large volumes due to adaptive resolution.
*   **Memory Complexity**: Uses shared memory for `sphfunc_val`, `ray_spec`, and `temp_storage`, sized by `TRACE_RAY_CUDA_RAYS_PER_BLOCK`. This limits the number of rays processed per block but reduces global memory bandwidth.
*   **Measured Performance**: Not given in the sources.
*   **Scaling**: Scales well with GPU parallelism, as each thread handles a ray or voxel independently. The cascade structure allows for efficient rendering of large volumes by coarsening resolution at a distance.
*   **Strengths**: Adaptive resolution reduces computation for distant parts of the volume. SH evaluation is optimized for lighting.
*   **Limitations**: Complexity of implementation due to cascade logic and backward pass. Precision issues may arise with extreme values.
*   **When to Use**: Ideal for large-scale volumetric rendering where adaptive resolution is beneficial, such as in neural radiance fields (NeRF) or volumetric light scattering.
*   **When Not to Use**: For small volumes where fixed-step marching is simpler and faster, or when high precision is required at all distances.

## Background

*   **Origin**: The method is derived from the CascatedVoxelConeTracing (CVCT) technique [S1, unofficial] and integrated into the svox2 framework for training sparse voxel radiance fields [S2, unofficial].
*   **History**: CVCT was developed to accelerate volumetric rendering by using a cascade of voxel grids with varying resolutions. svox2 adapted this for differentiable rendering and training.
*   **Usage**: Used in neural rendering pipelines for training and inference of 3D scenes represented as sparse voxel grids.
