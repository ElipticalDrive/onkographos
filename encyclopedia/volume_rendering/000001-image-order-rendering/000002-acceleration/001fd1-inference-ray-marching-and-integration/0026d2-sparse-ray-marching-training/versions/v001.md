# Sparse Ray Marching (Training)


## Overview
Sparse Ray Marching (Training) is a GPU-accelerated kernel designed to sample points along rays for the training phase of neural volume rendering, specifically within the Instant Neural Graphics Primitives (NGP) framework. It solves the problem of efficiently traversing a sparse, hashed density grid to identify occupied regions while minimizing global memory traffic. It distinguishes itself from inference marchers by supporting adaptive step sizes and perturbation for gradient-based optimization, and from static allocators by dynamically managing sample buffers based on occupancy thresholds [S1, unofficial].

## How it works
**Inputs:**
- `rays_alive`: Array of active ray indices.
- `rays_t`: Current distance along each ray.
- `ox, oy, oz`: Ray origins.
- `dx, dy, dz`: Ray directions.
- `grid`: Hashed density grid (resolution $H \times H \times H$).
- `density_thresh`: Threshold for occupancy.
- `bound`: Spatial extent of the grid.
- `perturb`: Boolean flag for jittering.
- `dt_min, dt_max`: Step size bounds.
- `dt_gamma`: Step size scaling factor.
- `n_step`: Maximum steps per ray.
- `n_alive`: Number of active rays.
- `N_THREAD`: Threads per CUDA block (typically 256) [S1, unofficial].

**Outputs:**
- `xyz`: Sampled coordinates.
- `dir`: Ray directions at samples.
- `delta`: Step sizes and cumulative distances.

**Data Structures:**
- The density grid is stored as a 1D array of size $H^3$ (or hashed equivalent, but accessed via clamped indices in this specific implementation variant).
- Ray state is maintained in parallel arrays.

**Steps:**
1. Initialize thread index $n$. If $n \ge n\_alive$, return.
2. Load ray index from `rays_alive[n]` and current distance $t$ from `rays_t[n]`.
3. If `perturb` is true, initialize a PCG32 random number generator with seed $(n, \text{perturb})$ and add $dt\_min \times \text{rng.next\_float()}$ to $t$ [S1, unofficial].
4. Loop while $t < \text{far}$ and step count $< n\_step$:
   a. Calculate current point $(x,y,z)$ by clamping $ox + t \cdot dx$, $oy + t \cdot dy$, $oz + t \cdot dz$ to $[-\text{bound}, \text{bound}]$ [S1, unofficial].
   b. Map $(x,y,z)$ to grid indices $(nx, ny, nz)$ by clamping $0.5 \cdot (\text{coord} \cdot rbound + 1) \cdot H$ to $[0, H-1]$, where $rbound = 1/\text{bound}$ [S1, unofficial].
   c. Query grid density at index $nx \cdot H^2 + ny \cdot H + nz$ [S1, unofficial].
   d. If density $> \text{density\_thresh}$:
      i. Write $xyz$, `dir`, and `delta` to output buffers.
      ii. Calculate $dt = \text{clamp}(t \cdot dt\_gamma, dt\_min, dt\_max)$ [S1, unofficial].
      iii. Update $t \leftarrow t + dt$.
      iv. Record `delta[0] = dt` and `delta[1] = t - last_t`.
      v. Update `last_t = t`.
      vi. Increment step and pointers.
   e. Else (empty space):
      i. Calculate distance to next voxel boundary in $x, y, z$ using $\text{signf}(dx), \text{signf}(dy), \text{signf}(dz)$ [S1, unofficial].
      ii. Compute $tt = t + \max(0, \min(tx, ty, tz))$ [S1, unofficial].
      iii. Advance $t$ in a do-while loop until $t \ge tt$, using the same $dt$ calculation as occupied space [S1, unofficial].

**Pseudocode:**
```python
def sparse_ray_marching_train(rays_alive, rays_t, ox, oy, oz, dx, dy, dz, grid, H, bound, density_thresh, perturb, dt_min, dt_max, dt_gamma, n_step, n_alive, N_THREAD):
    rbound = 1.0 / bound
    for n in range(N_THREAD):
        if n >= n_alive:
            break
        
        ray_idx = rays_alive[n]
        t = rays_t[n]
        last_t = t
        
        if perturb:
            rng = PCG32(seed=(n, perturb))
            t += dt_min * rng.next_float()
            
        step = 0
        while t < far and step < n_step:
            # Clamp point to bound
            x = clamp(ox[ray_idx] + t * dx[ray_idx], -bound, bound)
            y = clamp(oy[ray_idx] + t * dy[ray_idx], -bound, bound)
            z = clamp(oz[ray_idx] + t * dz[ray_idx], -bound, bound)
            
            # Map to grid indices
            nx = clamp(int(0.5 * (x * rbound + 1) * H), 0, H - 1)
            ny = clamp(int(0.5 * (y * rbound + 1) * H), 0, H - 1)
            nz = clamp(int(0.5 * (z * rbound + 1) * H), 0, H - 1)
            
            # Query density
            density = grid[nx * H * H + ny * H + nz]
            
            if density > density_thresh:
                # Write outputs
                write_xyz(x, y, z)
                write_dir(dx[ray_idx], dy[ray_idx], dz[ray_idx])
                
                # Calculate step
                dt = clamp(t * dt_gamma, dt_min, dt_max)
                t += dt
                
                # Record deltas
                delta_0 = dt
                delta_1 = t - last_t
                write_delta(delta_0, delta_1)
                
                last_t = t
                step += 1
            else:
                # Empty space traversal
                # Calculate distances to next voxel boundaries
                # Note: signf returns -1, 0, or 1
                tx = (signf(dx[ray_idx]) * bound - (ox[ray_idx] + t * dx[ray_idx])) / dx[ray_idx] if dx[ray_idx] != 0 else float('inf')
                ty = (signf(dy[ray_idx]) * bound - (oy[ray_idx] + t * dy[ray_idx])) / dy[ray_idx] if dy[ray_idx] != 0 else float('inf')
                tz = (signf(dz[ray_idx]) * bound - (oz[ray_idx] + t * dz[ray_idx])) / dz[ray_idx] if dz[ray_idx] != 0 else float('inf')
                
                # This logic assumes standard AABB traversal; simplified based on notes
                # The notes specify: tt = t + max(0, min(tx, ty, tz))
                # However, tx, ty, tz here are likely relative distances to boundaries
                # Re-reading notes: "Calculate distance to next voxel boundary... Compute tt = t + max(0, min(tx, ty, tz))"
                # We assume tx, ty, tz are pre-calculated relative distances to the next grid plane intersection
                
                # Placeholder for exact boundary calculation logic not fully detailed in notes
                # Typically involves DDA (Digital Differential Analyzer) steps
                tt = t + max(0, min(tx, ty, tz))
                
                while t < tt:
                    dt = clamp(t * dt_gamma, dt_min, dt_max)
                    t += dt
```

**Parameters:**
- `N_THREAD`: 256 [S1, unofficial].
- `perturb`: Boolean, enables jittering [S1, unofficial].
- `bound`: Spatial extent, inverse is `rbound` [S1, unofficial].
- `H`: Grid resolution [S1, unofficial].
- `mean_density`: Fallback threshold if specific function returns lower value [S1, unofficial].

**Edge Cases:**
- Precision issues in boundary calculations for empty space traversal [S1, unofficial].
- Degenerate rays (zero direction) require handling to avoid division by zero in boundary calculations [G].

## Subtopics

### [CUDA Ray Marching (IDDR-NGP Backend)](5788-cuda-ray-marching-iddr-ngp-backend.md)
A GPU-accelerated ray marching kernel that samples points along rays using a hashed density grid, supporting adaptive step sizes and perturbation. It serves as the core computational unit for the IDDR-NGP backend, enabling differentiable rendering by computing gradients alongside radiance accumulation. It distinguishes itself by organizing computation per-warp for spherical harmonic (SH) evaluation and using shared memory for ray specification caching to minimize global memory traffic.

### [Training Ray Marching (Forward Only)](6205-training-ray-marching-forward-only.md)
Training Ray Marching is a specialized ray marching function designed to optimize the training phase of neural volume rendering by dynamically allocating memory for ray samples. It estimates the maximum number of points to allocate based on the mean sample count from previous training epochs, thereby avoiding the computational overhead of over-allocating memory while supporting a "force-all-rays" mode to ensure stability when estimates are insufficient. It differs from inference-only marchers by maintaining state (step counters) across iterations to adaptively tune memory usage, and from static allocation methods by using historical data to predict resource needs.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of active rays and the number of steps per ray. Empty space traversal is accelerated by skipping to the next voxel boundary.
- **Memory Complexity:** Depends on the number of samples generated. The kernel itself uses minimal shared memory for ray specification caching [S1, unofficial].
- **Performance:** Optimized for GPU execution with 256 threads per block [S1, unofficial].
- **Strengths:** Efficient handling of sparse data, reduced memory traffic via shared memory, adaptive step sizes.
- **Limitations:** Requires careful tuning of `density_thresh` and `dt_gamma`. Perturbation adds computational overhead.
- **When to use:** Training phase of neural volume rendering where gradients are needed and data is sparse.
- **When not to use:** Inference where deterministic output is preferred without jitter, or when memory allocation overhead is prohibitive.

## Background
Originating from the Instant Neural Graphics Primitives (NGP) framework by NVIDIA, this method was developed to enable fast training of neural radiance fields. It builds on [Inference Ray Marching and Integration](2148-inference-ray-marching-and-integration.md) by adding training-specific features like perturbation and adaptive memory management. It is used in modern neural rendering pipelines for real-time training of high-quality 3D scenes.
