# Object Space Ray Tracing for Remote Volume Rendering

Also called: Object space ray tracing phase, Ray tracing technique rendering object space samples as spheres

## Overview
This method replaces the 2.5D point rasterization phase of the original Zellmann et al. remote volume rendering algorithm with an object space ray tracing phase to eliminate rendering artifacts in volumetric and transparent regions [S1, unofficial]. It transmits compacted object space samples (position and radius) and color data from a server to a client, where a software CUDA ray tracer renders them as spheres instead of fixed-size OpenGL points [S1, unofficial].

## How it works
**Inputs:**
*   Server-side volume rendering output: A set of object space samples, each containing position and radius data [S1, unofficial].
*   Network connection: Used to transmit compacted samples to the client [S1, unofficial].

**Outputs:**
*   Client-side rendered image: A 2D image generated by ray tracing the received object space samples [S1, unofficial].

**Data Structures:**
*   **Object Space Sample:** A structure containing position and radius [S1, unofficial].
    *   Size: 64 bits per sample [S1, unofficial].
    *   Layout: The source does not specify the exact bit-packing layout of the position and radius fields within the 64 bits [S1, unofficial].
*   **Color Data:** Transmitted alongside samples [S1, unofficial].
    *   Size: 32 bits per color value [S1, unofficial].

**Steps:**
1.  **Server-Side Rendering:** Perform volume rendering to generate object space samples [S1, unofficial].
2.  **Server-Side Compaction:** Compact the generated object space samples to reduce data size before transmission [S1, unofficial].
3.  **Transmission:** Transmit the compacted object space samples and color data to the client over the network [S1, unofficial].
4.  **Client-Side Ray Tracing:** Use a software ray tracing implementation based on NVIDIA CUDA to render the received samples [S1, unofficial].
5.  **Sphere Rendering:** Render the object space samples as spheres (object space splats) instead of OpenGL points with fixed pixel size [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The overall pipeline is currently bound by compaction performance on the server side [S1, unofficial].
*   **Memory Complexity:** Depends on the number of compacted samples. For 1024 × 1024 pixel images, compaction results in 623,584 individual object space samples [S1, unofficial].
*   **Measured Performance:** Measured on an NVIDIA RTX 2080 GPU [S1, unofficial]. The source does not provide specific frame rates but notes that rendering performance is "very high" even without RT Cores [S1, unofficial].
*   **Strengths:** Significantly improves visual quality in volumetric and transparent regions compared to OpenGL point rasterization, even with slight camera movement [S1, unofficial].
*   **Limitations:** Bound by server-side compaction performance. Network bandwidth and latency are not reported as they depend on the individual connection [S1, unofficial].
*   **When to Use:** Not given in the sources. [S1, unofficial]
*   **When Not to Use:** Not given in the sources. [S1, unofficial]

## Background
This technique is an extension of the algorithm by Zellmann et al. [ZAL12] titled 'Image-Based Remote Real-Time Volume Rendering - Decoupling Rendering from View Point Updates' (2012) [S1, unofficial]. It was proposed to address the rendering artifacts inherent in the original method's use of 2.5D point rendering [S1, unofficial]. The implementation uses NVIDIA CUDA for ray tracing and C++ Boost Asio for network communication [S1, unofficial].
