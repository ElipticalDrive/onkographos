# Inference Ray Marching and Integration

Also called: Inference Ray Marching, Ray Marching for Inference, CUDA Ray Marching (Inference), Sparse Ray Marching (Inference), Ray Marching (CUDA Kernel)

## Overview
Inference Ray Marching and Integration is a GPU-accelerated method for real-time volume rendering inference, specifically designed to generate sample points, directions, and integration deltas for active rays by marching through a pre-computed density grid [S1, S2, S4, unofficial]. It solves the performance bottleneck of evaluating volumetric neural fields (such as NeRFs) at inference time by utilizing occupancy grids for empty-space skipping and adaptive step sizing [S3, unofficial]. Unlike training-time marching, which maintains state for backpropagation, this method focuses on throughput, often processing rays in batches with strict early-termination logic to maximize frame rates [S2, S3, unofficial]. It builds on the acceleration principles of [Acceleration](18-acceleration.md) by combining culling (via density bitfields) and termination (via transmittance thresholds) [S1, S3, unofficial].

## How it works
The method typically operates as a CUDA kernel or a Python-wrapped backend call that outputs three primary tensors: sampled 3D coordinates (`xyzs`), view directions (`dirs`), and step sizes (`deltas`) [S2, S4, unofficial]. These outputs are subsequently used by a neural network (e.g., a color/density MLP) and an integration routine to produce the final pixel color and depth [S2, S3, unofficial].

### Inputs and Outputs
**Inputs:**
*   `rays_o`: Float array `[N, 3]`, ray origins for $N$ rays [S2, S4, unofficial].
*   `rays_d`: Float array `[N, 3]`, ray directions for $N$ rays [S2, S4, unofficial].
*   `near`: Float array `[N]`, near plane distances [S2, S4, unofficial].
*   `far`: Float array `[N]`, far plane distances [S2, S4, unofficial].
*   `density_bitfield`: Uint8 array `[CHHH // 8]`, a hashed grid (e.g., Instant-NGP style) used for fast occupancy queries [S1, S4, unofficial].
*   `density_grid`: Float array `[H, H, H]`, a pre-computed 3D density grid used for sampling and step estimation [S2, unofficial].
*   `mean_density`: Float, average density in the grid, used for step size estimation [S2, unofficial].
*   `bound`: Float, spatial boundary limit (scene bounding box size) [S1, S2, unofficial].
*   `n_alive`: Int, number of currently active rays [S1, S2, S4, unofficial].
*   `rays_alive`: Int array `[N]`, IDs of alive rays (only the first `n_alive` are processed) [S1, S2, S4, unofficial].
*   `rays_t`: Float array `[N]`, current traversal position ($t$) along each ray [S1, S2, S4, unofficial].
*   `n_step`: Int, maximum number of steps per ray [S1, S2, S4, unofficial].
*   `perturb`: Bool/Int, enables jittering of sample positions for anti-aliasing [S1, S2, unofficial].
*   `dt_gamma`: Float, cone angle for adaptive ray marching acceleration [S1, S4, unofficial].
*   `max_steps`: Int, global maximum sampled points per ray [S1, S4, unofficial].
*   `align`: Int, padding value to align output tensor size [S1, S2, unofficial].

**Outputs:**
*   `xyzs`: Float array `[M, 3]`, 3D coordinates of sampled points [S2, S4, unofficial].
*   `dirs`: Float array `[M, 3]`, view directions for each sample [S2, S4, unofficial].
*   `deltas`: Float array `[M, 2]`, two delta values per point: one for RGB contribution, one for depth [S2, S4, unofficial].
    *   $M$ is the total output size, calculated as $n\_alive \times n\_step$, padded to the next multiple of `align` if `align > 0` [S1, S2, unofficial].

### Data Structures
The core data structure is the **Density Bitfield** (or Hash Grid), a compressed representation of the volume occupancy. It allows $O(1)$ lookup to determine if a ray segment is empty, enabling the skipping of expensive neural network evaluations [S1, S4, unofficial].

### Algorithm Steps
The inference process generally follows a batched loop structure to manage GPU memory and handle ray termination dynamically [S3, unofficial].

1.  **Initialization**:
    *   Ensure `rays_o` and `rays_d` are contiguous on the CUDA device [S1, S2, unofficial].
    *   Initialize output tensors `xyzs`, `dirs`, `deltas` with zeros of shape `[M, 3]`, `[M, 3]`, and `[M, 2]` respectively [S2, unofficial].
    *   If perturbation is enabled, generate random noise for the first step [S1, unofficial].
    *   Initialize ray state: `rays_alive` contains indices $0 \dots n\_alive-1$, and `rays_t` is set to `near` distances [S2, unofficial].

2.  **Marching Loop**:
    *   Loop while `n_alive > 0` and step count $< max\_steps$ (typically up to 1024 steps) [S2, unofficial].
    *   **Step Size Calculation**: Determine `n_step` for the current batch. A common heuristic is $n\_step = \max(\min(B \cdot N // n\_alive, 8), 1)$, where $B$ is a batch constant and $N$ is total pixels, ensuring balanced work distribution [S2, unofficial].
    *   **CUDA Kernel Execution**: Call the backend kernel (e.g., `_backend.march_rays`) with parameters `n_alive`, `n_step`, `rays_alive`, `rays_t`, `rays_o`, `rays_d`, `bound`, `density_bitfield`, `C`, `H`, `near`, `far`, `align`, `perturb`, `dt_gamma`, `max_steps` [S1, S4, unofficial].
        *   Inside the kernel, for each alive ray:
            *   Query the `density_bitfield` or `density_grid` at the current $t$.
            *   If the voxel is empty (density below threshold), skip to the next occupied voxel or terminate if far plane is reached [S2, S4, unofficial].
            *   If occupied, compute the step size $\Delta t$. Adaptive marching uses $dt\_gamma$ to accelerate steps in empty space or where density is low [S1, S4, unofficial].
            *   Sample the new position $t_{new} = t + \Delta t$.
            *   Store $xyz$, $dir$, and $\Delta t$ in the output buffers [S2, unofficial].
            *   Update `rays_t` for the next iteration [S2, unofficial].
    *   **Compaction**: After the kernel returns, compact the list of `rays_alive` to remove rays that have terminated (reached `far` or accumulated high opacity) [S2, unofficial]. This reduces `n_alive` for the next iteration.

3.  **Integration (Separate Step)**:
    *   The outputs `xyzs`, `dirs`, `deltas` are passed to a neural network to query density ($\sigma$) and color ($C$) [S2, unofficial].
    *   An integration routine (e.g., `integrate_rays_inference`) updates ray colors, transmittance, and termination status using front-to-back compositing [S3, unofficial].
    *   Rays are terminated if transmittance drops below a threshold or opacity accumulates sufficiently [S3, unofficial].

    """
    Python wrapper for Inference Ray Marching.
    """
    # 1. Ensure inputs are contiguous on CUDA
    rays_o = rays_o.contiguous()
    rays_d = rays_d.contiguous()
    
    # 2. Calculate output size M
    M = n_alive * n_step
    if align > 0:
        M += align - (M % align)
        
    # 3. Initialize output buffers
    xyzs = torch.zeros((M, 3), dtype=torch.float32, device=rays_o.device)
    dirs = torch.zeros((M, 3), dtype=torch.float32, device=rays_o.device)
    deltas = torch.zeros((M, 2), dtype=torch.float32, device=rays_o.device)
    
    # 4. Call CUDA Backend Kernel
    # The kernel populates xyzs, dirs, deltas and updates rays_t/rays_alive state internally or returns new state
    # Note: In many implementations (like instant-ngp), the kernel returns the updated rays_t and the filled buffers
    xyzs, dirs, deltas, rays_t = _backend.march_rays(
        n_alive=n_alive,
        n_step=n_step,
        rays_alive=rays_alive,
        rays_t=rays_t,
        rays_o=rays_o,
        rays_d=rays_d,
        bound=bound,
        density_bitfield=density_bitfield,
        C=density_bitfield.shape[0] * 8 // (density_grid.shape[0]**3) if density_bitfield.numel() > 0 else 0, # Placeholder for hash grid params
        H=density_grid.shape[0],
        near=near,
        far=far,
        align=align,
        perturb=perturb,
        dt_gamma=dt_gamma,
        max_steps=max_steps
    )
    
    return xyzs, dirs, deltas, rays_t

### Parameters and Typical Values
*   `dt_gamma`: Default $1/256$. Set to 0 to disable adaptive marching [S1, unofficial].
*   `density_thresh`: Default 10. Threshold for density grid occupancy [S1, unofficial].
*   `max_steps`: Default 1024 [S1, S4, unofficial].
*   `perturb`: Default True (or seed value) [S1, S3, unofficial].
*   `align`: Default -1 (disabled) [S1, S2, unofficial].

### Edge Cases and Pitfalls
*   **Precision**: Floating-point errors in $t$ accumulation can cause rays to miss voxels or re-enter them. Using double precision for $t$ or robust voxel boundary checks is recommended [G].
*   **Empty Space**: If `density_bitfield` is not properly synchronized with `density_grid`, rays may march into empty space unnecessarily or terminate prematurely [S2, unofficial].
*   **Boundary Conditions**: Rays starting outside the `bound` box must be handled to avoid invalid memory accesses in the hash grid [S1, S4, unofficial].

## Subtopics

### Gradient Magnitude Threshold Acceleration
Discards voxels or ray samples with gradient magnitude below a threshold, assuming they do not lie on object surfaces [S5, unofficial]. This is advantageous because gradient estimation and interpolation are expensive operations, and discarding low-gradient samples reduces computational load without significant quality loss for surface-focused rendering [S5, unofficial].

### Inference Acceleration Strategies
A set of strategies to boost inference efficiency with minimal quality drop, including combining threads, using larger steps, early termination, and prefetching neighbors [S6]. These strategies can significantly reduce test time (e.g., from 41.8 ms to 5.5 ms for 800x800 images) with minimal PSNR degradation [S6].

## Operating characteristics
*   **Time Complexity**: $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of steps per ray. Adaptive marching reduces $S$ in empty regions [S1, S4, unofficial].
*   **Memory Complexity**: $O(M)$ for output buffers, where $M$ is the total number of samples generated. The density bitfield requires $O(H^3)$ space [S2, unofficial].
*   **Performance**: Capable of real-time rendering (e.g., >60 FPS) for moderate resolutions on modern GPUs [S3, unofficial]. Performance scales with the sparsity of the volume; denser volumes require more steps and network evaluations [S2, unofficial].
*   **Strengths**: High throughput due to CUDA acceleration and occupancy culling; suitable for real-time applications [S3, unofficial].
*   **Limitations**: Quality may degrade if `dt_gamma` is too high or if perturbation is disabled in complex geometry [S1, unofficial]. Memory usage can be high for very large volumes if not chunked [S2, unofficial].

## Background
Inference Ray Marching is a core component of modern neural radiance field (NeRF) rendering pipelines, particularly those based on Instant-NGP [S3, unofficial]. It was developed to address the high computational cost of evaluating dense neural networks along every ray during inference. By leveraging sparse data structures (hash grids) and GPU parallelism, it enables real-time visualization of trained NeRF models [S1, S3, unofficial]. It is widely used in applications requiring interactive exploration of 3D scenes, such as VR/AR and remote volume rendering [S1, S3, unofficial].
