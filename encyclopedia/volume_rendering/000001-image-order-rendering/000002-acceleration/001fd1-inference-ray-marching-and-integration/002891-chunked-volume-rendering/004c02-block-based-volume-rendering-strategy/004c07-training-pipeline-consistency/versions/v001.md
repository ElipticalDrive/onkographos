# Training Pipeline Consistency

Also called: Simulated finite grid approach, Training-time block rendering

## Overview
Training Pipeline Consistency is a strategy to minimize the discrepancy between the training and inference phases of block-based volume rendering by enforcing the identical rendering pipeline during both stages [S1]. It solves the problem where training with a continuous, global coordinate system leads to artifacts or quality degradation when the model is deployed in a constrained, block-based rendering environment [S1]. It sets itself apart from standard neural rendering methods by explicitly simulating the discrete, hardware-bound constraints of the target rendering hardware (such as texture unit limits and quantization) during the optimization process [S1].

## How it works
The method ensures that the data flow, sampling logic, and integration order during training are identical to those used in the final web-based rendering stage [S1].

**Inputs and Outputs:**
*   **Input:** Camera ray $\boldsymbol{r}(t)$, scene bounding box, block partitioning parameters, proposal MLPs $\psi^k$, and attribute MLPs $f^k$ for each block $k$.
*   **Output:** Final rendered color and opacity for the ray.

**Data Structures:**
*   **Blocks ($B_k$):** The scene is partitioned into spatial blocks. Each block $k$ has an associated proposal MLP $\psi^k$ and attribute MLP $f^k$ [S1].
*   **Ray Samples:** Points sampled along the ray $\boldsymbol{r}(t)$ between near and far boundaries [S1].

**Numbered Steps:**
1.  **Uniform Sampling:** For a given ray $\boldsymbol{r}(t)$, uniformly sample points between the near and far boundaries defined by the scene’s bounding box [S1].
2.  **Block Determination:** For each sample point, determine which block $B_k$ it resides in. This is calculated using the xy-coordinate projection of the point, referred to as Eq. (4) in the source [S1].
    *   *Note:* The exact formula for Eq. (4) is not provided in the source text, but it maps spatial coordinates to a block index $k$ [S1].
3.  **Proposal Sampling:** Query the proposal MLP $\psi^k$ corresponding to the determined block $B_k$ to sample probability distributions along the ray [S1]. This step identifies important regions within the block for further sampling or integration.
4.  **Attribute Querying:** Query the attribute MLP $f^k$ corresponding to block $B_k$ to obtain the rendering attributes (e.g., color, density) for the sample points [S1].
5.  **Sequential Rendering:** Render each block sequentially. For each block $B_k$, compute the color and opacity contribution of the ray segment within that block [S1].
6.  **Final Composition:** Combine the results from all blocks using the volume rendering equation, referred to as Eq. (5) in the source, to derive the final pixel color and opacity [S1].
    *   *Note:* The exact formula for Eq. (5) is not provided in the source text, but it represents the standard front-to-back volume rendering integration [S1].

## Subtopics

### MERF Rendering Pipeline
A memory-optimized rendering pipeline that combines a low-resolution sparse voxel representation with high-resolution 2D triplanes, bridging training and rendering by simulating grid and quantization constraints during training [S1]. It reduces memory requirements compared to SNeRG by replacing the dense 3D voxel grid with a hybrid sparse voxel and 2D triplane representation [S1]. During training, it simulates a finite grid approach by querying MLPs at virtual grid corners instead of continuous coordinates, and simulates quantization to closely mimic the discrete texture lookup behavior of the actual rendering pipeline [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** The MERF variant reduces memory requirements compared to SNeRG by using a hybrid sparse voxel and 2D triplane representation [S1].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Minimizes the gap between training and rendering quality by ensuring pipeline consistency [S1]. The MERF variant offers significant memory reduction [S1].
*   **Limitations:** The block-based approach is constrained by web texture unit limits, requiring sequential rendering [Parent]. The simulation of quantization and finite grids adds complexity to the training process [S1].
*   **When to use:** When deploying neural radiance fields on web platforms with strict hardware constraints (texture unit limits) and where training-inference consistency is critical for quality [S1, Parent].
*   **When not:** When memory is not a constraint and real-time rendering on high-end GPUs with sufficient texture units is possible, allowing for more flexible training pipelines.

## Background
The method originates from the "City-on-Web" project, which focuses on real-time neural rendering of large-scale scenes on the web [S1]. It was developed to address the limitations of existing methods like SNeRG, which demand substantial memory and do not account for the specific constraints of web-based rendering [S1]. The approach was introduced in the paper "City-on-Web: Real-Time Neural Rendering of Large-Scale Scenes on the Web" [S1].
