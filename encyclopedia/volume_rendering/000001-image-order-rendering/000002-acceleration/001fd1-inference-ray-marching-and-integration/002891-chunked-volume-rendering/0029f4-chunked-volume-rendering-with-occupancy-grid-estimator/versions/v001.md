# Chunked Volume Rendering with Occupancy Grid Estimator

Also called: OccGridEstimator Rendering

## Overview
This method accelerates volume rendering by combining chunked ray batching with an occupancy grid estimator to skip empty space. It solves the performance bottleneck of uniform ray marching in sparse or large scenes by only sampling regions where the radiance field has non-zero density. It differs from its parent [Chunked Volume Rendering](4310-chunked-volume-rendering.md) by integrating a specific hierarchical occupancy grid for adaptive sampling, and from its sibling [Block-based Volume Rendering Strategy](13140-block-based-volume-rendering-strategy.md) by using a continuous grid-based estimator rather than discrete block structures.

## How it works
**Inputs:**
- Ray origins: Tensor of shape $(H, W, 3)$ or $(N, 3)$.
- View directions: Tensor of shape $(H, W, 3)$ or $(N, 3)$.
- Radiance field: Object with `query_density(positions)` method returning density $\sigma$.
- OccGridEstimator: Object with `sampling(...)` method.
- Parameters: `near_plane`, `far_plane`, `render_step_size`, `alpha_thre`, `cone_angle`, `test_chunk_size`.

**Outputs:**
- RGB image: Shape $(H, W, 3)$.
- Depth image: Shape $(H, W)$.
- Opacity image: Shape $(H, W)$.
- Extras: Additional per-sample data.

**Data Structures:**
- `RaySamples`: Contains `vals` (flattened sample data), `ray_indices` (mapping samples to rays), and `packed_info` (chunk boundaries).
- `OccGrid`: Hierarchical grid storing occupancy probabilities.

**Steps:**
1. **Reshape Rays:** If ray origins and directions are 3D tensors of shape $(H, W, 3)$, reshape them to 2D tensors of shape $(N, 3)$ where $N = H \times W$. Store the original shape for final reshaping.
2. **Chunking:** Divide the $N$ rays into chunks of size `test_chunk_size`. If in training mode, use `max(int32)` to process all rays at once.
3. **Define Density Function:** For each chunk, define a function `sigma_fn(t_starts, t_ends, ray_indices)` that:
   - Calculates sample midpoints: $pos = origins[ray\_indices] + dirs[ray\_indices] \times \frac{t\_starts + t\_ends}{2.0}$.
   - Queries the radiance field for density: $\sigma = radiance\_field.query\_density(pos)$.
   - If temporal scenes are supported, pass timestamps to the query.
4. **Sampling:** Call `estimator.sampling(sigma_fn, near_plane, far_plane, render_step_size, stratified, cone_angle, alpha_thre)`. This returns:
   - `ray_indices`: Indices of rays associated with each sample.
   - `t_starts`: Start distances of samples along rays.
   - `t_ends`: End distances of samples along rays.
5. **Rendering:** Call the rendering composite function with `t_starts`, `t_ends`, `ray_indices`, `n_rays`, and a combined function `rgb_sigma_fn` (which queries both color and density). This returns `rgb`, `opacity`, `depth`, and `extras` for the chunk.
6. **Concatenation:** Concatenate results from all chunks along dimension 0.
7. **Reshape:** Reshape the concatenated results back to the original image dimensions $(H, W, 3)$ for RGB, $(H, W)$ for depth/opacity.

**Pseudocode:**
```python
import torch

def render_image_with_occgrid_test(
    radiance_field,
    estimator,
    origins,
    viewdirs,
    near_plane=0.0,
    far_plane=1e10,
    render_step_size=1e-3,
    alpha_thre=0.0,
    cone_angle=0.0,
    test_chunk_size=8192,
    is_training=False
):
    # 1. Reshape rays
    if origins.dim() == 3:
        rays_shape = origins.shape[:-1]
        origins = origins.view(-1, 3)
        viewdirs = viewdirs.view(-1, 3)
    else:
        rays_shape = (origins.shape[0],)
        origins = origins.view(-1, 3)
        viewdirs = viewdirs.view(-1, 3)

    n_rays = origins.shape[0]
    
    # 2. Chunking
    if is_training:
        chunk_size = 2**31 - 1 # max int32
    else:
        chunk_size = test_chunk_size

    all_rgb = []
    all_depth = []
    all_opacity = []
    all_extras = []

    for i in range(0, n_rays, chunk_size):
        chunk_end = min(i + chunk_size, n_rays)
        chunk_origins = origins[i:chunk_end]
        chunk_dirs = viewdirs[i:chunk_end]
        chunk_ray_indices = torch.arange(i, chunk_end, device=origins.device)

        # 3. Define sigma_fn for this chunk
        def sigma_fn(t_starts, t_ends, ray_indices):
            # ray_indices are relative to the chunk in some implementations, 
            # but usually estimator handles global or chunk-local indexing.
            # Assuming ray_indices passed to sigma_fn are indices into chunk_origins
            midpoints = chunk_origins[ray_indices] + chunk_dirs[ray_indices] * (t_starts + t_ends) / 2.0
            densities = radiance_field.query_density(midpoints)
            return densities

        # 4. Sampling
        # estimator.sampling returns t_starts, t_ends, ray_indices (global or chunk-relative)
        # Note: The exact signature of estimator.sampling may vary, but typically:
        ray_indices, t_starts, t_ends = estimator.sampling(
            sigma_fn=sigma_fn,
            near_plane=near_plane,
            far_plane=far_plane,
            render_step_size=render_step_size,
            stratified=True, # or False depending on training/eval
            cone_angle=cone_angle,
            alpha_thre=alpha_thre
        )

        # 5. Rendering
        # Define rgb_sigma_fn to return both color and density
        def rgb_sigma_fn(t_starts, t_ends, ray_indices):
            midpoints = chunk_origins[ray_indices] + chunk_dirs[ray_indices] * (t_starts + t_ends) / 2.0
            densities = radiance_field.query_density(midpoints)
            colors = radiance_field.query_color(midpoints)
            return colors, densities

        rgb, opacity, depth, extras = render(
            t_starts=t_starts,
            t_ends=t_ends,
            ray_indices=ray_indices,
            n_rays=chunk_end - i,
            rgb_sigma_fn=rgb_sigma_fn
        )

        all_rgb.append(rgb)
        all_depth.append(depth)
        all_opacity.append(opacity)
        all_extras.append(extras)

    # 6. Concatenation
    final_rgb = torch.cat(all_rgb, dim=0)
    final_depth = torch.cat(all_depth, dim=0)
    final_opacity = torch.cat(all_opacity, dim=0)

    # 7. Reshape
    final_rgb = final_rgb.view(*rays_shape, 3)
    final_depth = final_depth.view(*rays_shape)
    final_opacity = final_opacity.view(*rays_shape)

    return final_rgb, final_depth, final_opacity, all_extras
```

**Parameters:**
- `near_plane`: Float, default 0.0. Minimum distance for ray marching.
- `far_plane`: Float, default 1e10. Maximum distance for ray marching.
- `render_step_size`: Float, default 1e-3. Base step size for sampling.
- `alpha_thre`: Float, default 0.0. Alpha threshold for filtering samples.
- `cone_angle`: Float, default 0.0. Cone angle for adaptive sampling.
- `test_chunk_size`: Int, default 8192. Number of rays per chunk during inference.

**Edge Cases:**
- If `alpha_thre` is 0.0, no samples are filtered by alpha, potentially increasing memory usage.
- If `cone_angle` is 0.0, cone-based adaptive sampling is disabled.
- Precision issues may arise if `far_plane` is extremely large and `near_plane` is 0.0, leading to small relative step sizes.

## Operating characteristics
- **Time Complexity:** Depends on the sparsity of the scene and the efficiency of the occupancy grid. In dense regions, it approaches uniform sampling cost. In sparse regions, it is significantly faster due to skipped empty space.
- **Memory Complexity:** Proportional to the number of occupied cells in the occupancy grid plus the memory for ray samples in the current chunk. Chunking keeps peak memory low.
- **Performance:** On synthetic scenes (e.g., NERF synthetic), it provides significant speedups over uniform marching. The default `test_chunk_size` of 8192 balances memory usage and kernel launch overhead.
- **Strengths:** Efficient for large, sparse scenes. Adaptive sampling reduces unnecessary computations.
- **Limitations:** Requires maintaining and updating the occupancy grid. Overhead of grid queries may dominate in very dense scenes.
- **When to use:** Large scenes with significant empty space, real-time or near-real-time rendering requirements.
- **When not to use:** Very dense scenes where most rays hit objects, or when the overhead of grid updates is prohibitive.

## Background
The method originates from the NGP (Neural Graphics Primitives) framework and its derivatives, such as Instant-NGP and subsequent implementations like `faster-occgrid` and `taylor-nerf`. It leverages hierarchical occupancy grids to accelerate ray marching in neural radiance fields. The specific implementation details are found in unofficial repositories [S1, unofficial] and [S2, unofficial].
