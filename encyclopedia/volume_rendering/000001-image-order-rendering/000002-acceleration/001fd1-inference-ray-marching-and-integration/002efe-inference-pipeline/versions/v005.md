# Inference Pipeline

Also called: Inference Module

## Overview
The Inference Pipeline renders images from a trained dense point cloud and new camera poses without requiring further optimization [S1, unofficial]. It executes a fixed forward flow through a rasterizer to produce the output image [S1, unofficial].

## How it works
**Inputs:**
1. `DensePointCloudWithExtraFeatures`: The trained set of 3D primitives to be rendered [S1, unofficial].
2. `NewCameraPose`: The extrinsic and intrinsic parameters for the target view [S1, unofficial].

**Outputs:**
1. `Image`: The rendered output image [S1, unofficial].

**Data Structures:**
* `DensePointCloudWithExtraFeatures`: Stores a collection of 3D primitives. Fields include mean position $\mu$, covariance matrix $\Sigma$, opacity $\alpha$, and color coefficients [S1, unofficial][G].
* `NewCameraPose`: Stores the view matrix $V$ and projection matrix $P$ [G].

**Steps:**
1. **Rasterization:** Project the primitives from the point cloud onto the 2D image plane using the camera pose. This involves transforming the mean position to camera space and projecting the covariance to screen space [S1, unofficial][G].
2. **Compositing:** Sort the projected primitives by depth. Iterate through the sorted list and accumulate color and opacity using alpha compositing to produce the final pixel color [G].

**Pseudocode:**
```python
def inference_pipeline(point_cloud, camera_pose):
    screen_primitives = []
    for prim in point_cloud:
        cam_mean = camera_pose.view_matrix @ numpy.append(prim.mean, 1.0)
        J = camera_pose.projection_matrix @ camera_pose.view_matrix
        screen_cov = J @ prim.cov @ J.T
        screen_primitives.append({
            'mean': cam_mean[:2],
            'cov': screen_cov[:2, :2],
            'opacity': prim.opacity,
            'color': prim.color,
            'depth': cam_mean[2]
        })

    screen_primitives.sort(key=lambda p: p['depth'])

    image = numpy.zeros((camera_pose.height, camera_pose.width, 3))
    alpha_accum = numpy.zeros((camera_pose.height, camera_pose.width))

    for prim in screen_primitives:
        cov_inv = numpy.linalg.inv(prim['cov'])
        det = numpy.linalg.det(prim['cov'])
        bbox = compute_bounding_box(prim['mean'], prim['cov'])
        for y in range(bbox[0], bbox[2]):
            for x in range(bbox[1], bbox[3]):
                diff = numpy.array([x - prim['mean'][0], y - prim['mean'][1]])
                dist = diff @ cov_inv @ diff
                pdf = numpy.exp(-0.5 * dist) / (2 * numpy.pi * numpy.sqrt(max(det, 1e-8)))
                alpha = prim['opacity'] * pdf
                if alpha_accum[y, x] + alpha >= 1.0:
                    continue
                color_blend = prim['color'] * alpha * (1.0 - alpha_accum[y, x])
                image[y, x] += color_blend
                alpha_accum[y, x] += alpha * (1.0 - alpha_accum[y, x])
    return image

def compute_bounding_box(mean, cov):
    # [G] Standard 2-sigma axis-aligned bounding box for 2D Gaussian
    eigenvalues = numpy.linalg.eigvalsh(cov)
    sigma_x = 2.0 * numpy.sqrt(eigenvalues[0])
    sigma_y = 2.0 * numpy.sqrt(eigenvalues[1])
    return int(mean[0] - sigma_x), int(mean[1] - sigma_y), int(mean[0] + sigma_x), int(mean[1] + sigma_y)
```

## Subtopics

### [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md)
Renders views from a trained dense point cloud using a rasterizer. It distinguishes itself by explicitly handling the near-camera artifact problem through point pruning before rendering, ensuring depth values are physically meaningful for downstream tasks like video generation or multi-view consistency checks. Choose it when visualization outputs including color images, depth maps, and colored depth maps are required.

### Runtime Inference with Control Encoding
After training, only the forward flow is used to render images [S2]. A control encoding passed to MLPs determines the object to be rendered at runtime [S2]. MLPs are invoked only when the encoding changes [S2]. The color MLP is re-evaluated whenever the viewing angle shifts to account for view-dependent colors [S2]. All other MLPs predict $k$ parameters for each anchor point instead of being inferred for every viewing direction [S2].
