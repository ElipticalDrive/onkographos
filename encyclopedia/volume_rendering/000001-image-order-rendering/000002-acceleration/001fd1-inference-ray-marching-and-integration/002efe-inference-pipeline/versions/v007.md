# Inference Pipeline

Also called: Inference Module

## Overview
The Inference Pipeline renders images from a trained dense point cloud (specifically Gaussian Splatting models) and new camera poses without requiring further optimization [S1, unofficial]. It differs from its sibling [Inference Ray Compositing](3790-inference-ray-compositing.md) by executing the full evaluation loop including rasterization, FPS calculation, and video generation, whereas the sibling focuses specifically on the ray-compositing math [S1, unofficial]. It is distinct from [Sparse Ray Marching (Training)](3890-sparse-ray-marching-training.md) as it operates on a fully trained, dense representation rather than a sparse, evolving one [S1, unofficial].

## How it works
**Inputs:**
1. `DensePointCloudWithExtraFeatures`: The trained set of 3D Gaussians, including position, covariance, opacity, and color coefficients.
2. `NewCameraPose`: The extrinsic and intrinsic parameters for the target view.

**Outputs:**
1. `Image`: The rendered RGB image.
2. (Optional) Depth maps and colored depth maps, depending on the specific variant invoked [S1, unofficial].

**Data Structures:**
*   **Gaussian Point**: Defined by position $\mathbf{p}$, a $3 \times 3$ covariance matrix $\Sigma$ (or its Cholesky factor), opacity $\alpha$, and spherical harmonic coefficients for view-dependent color.
*   **Camera Pose**: A $4 \times 4$ transformation matrix $T_{world \to camera}$ and intrinsic matrix $K$.

**Steps:**
1.  **Initialization**: Load the trained `DensePointCloudWithExtraFeatures` and the `NewCameraPose` into the Inference Module [S1, unofficial].
2.  **Rasterization**: Pass the point cloud and camera pose to a rasterizer. The rasterizer projects the 3D Gaussians onto the 2D image plane, handling visibility and overlap [S1, unofficial].
3.  **Compositing**: The rasterizer outputs the final `Image` by compositing the projected Gaussians according to their depth and opacity [S1, unofficial].
4.  **Post-Processing (Variant Dependent)**:
    *   If rendering for visualization, prune points occluded by or too close to the camera [S1, unofficial].
    *   Save rendered images, depth maps, and colored depth maps [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Pruning**: Points that are occluded or too close to the camera must be explicitly pruned to avoid artifacts or invalid depth data [S1, unofficial].
*   **View-Dependent Color**: The color MLP must be re-evaluated whenever the viewing angle shifts to account for scene colors changing with viewing direction [S2].

## Subtopics

### [Depth Map Rendering and Visualization](8160-depth-map-rendering-and-visualization.md)
Renders a set of views from a trained dense point cloud, prunes points occluded by or too close to the camera, and saves rendered images, depth maps, and colored depth maps. It differs from the parent [Inference Pipeline](5924-inference-pipeline.md) by focusing specifically on the extraction and visualization of depth data and the pruning of invalid geometry, rather than the full evaluation loop including FPS calculation and video generation.

### Runtime Inference with Control Encoding
After training, uses only the forward flow to render images [S2]. Passes a control encoding to the MLPs to determine the object to be rendered at runtime [S2]. Invokes the MLPs whenever a change in the encoding is necessary [S2]. Re-evaluates the color MLP whenever the viewing angle shifts to account for scene colors changing with viewing direction [S2]. For other MLPs, predicts $k$ parameters for each anchor point instead of inferring for every viewing direction [S2].

## Operating characteristics
*   **Time Complexity**: Depends on the number of Gaussians and the rasterizer efficiency. The color MLP must be re-evaluated per viewing direction, while other MLPs predict $k$ parameters per anchor point, reducing per-pixel computation [S2].
*   **Memory Complexity**: Stores the full dense point cloud and MLP weights.
*   **Strengths**: Real-time rendering capability; supports context translation (e.g., style changes) via control encoding without retraining [S2].
*   **Limitations**: Requires a trained dense point cloud; control encoding changes may require MLP re-evaluation [S2].
*   **When to use**: When real-time rendering of trained Gaussian Splatting models is required, especially with dynamic context or style changes [S2].
*   **When not to use**: When optimization during inference is needed, or when the scene is not represented as a dense point cloud [S1, unofficial].

## Background
The Inference Pipeline is a component of Gaussian Splatting rendering systems, enabling real-time visualization of trained models. It was developed to allow efficient rendering without the computational overhead of training or optimization [S1, unofficial]. The concept of using control encodings for runtime context translation was introduced in "Shape-Shifting Splats: Realtime Context Translation for Gaussian Splatting in VR" [S2].
