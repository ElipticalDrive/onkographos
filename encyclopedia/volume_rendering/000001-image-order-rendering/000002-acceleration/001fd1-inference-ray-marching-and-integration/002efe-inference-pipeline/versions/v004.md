# Inference Pipeline

Also called: Inference Module

## Overview
The Inference Pipeline renders images from a trained dense point cloud and new camera poses without requiring further optimization [S1, unofficial]. It executes a fixed forward flow through a rasterizer to produce the output image [S1, unofficial].

## How it works
**Inputs:**
1. `DensePointCloudWithExtraFeatures`: The trained set of primitives to be rendered.
2. `NewCameraPose`: The extrinsic and intrinsic parameters for the target view.

**Outputs:**
1. `Image`: The rendered output image.

**Data Structures:**
* `DensePointCloudWithExtraFeatures`: Stores a collection of 3D primitives. Fields include mean position $\mu$, covariance matrix $\Sigma$ (or its Cholesky factor), opacity $\alpha$, and color coefficients [G].
* `NewCameraPose`: Stores the view matrix $V$ and projection matrix $P$ [G].

**Steps:**
1. **Rasterization:** Project the primitives from the point cloud onto the 2D image plane using the camera pose. This involves transforming the mean position to camera space and projecting the covariance to screen space [G].
2. **Compositing:** Sort the projected primitives by depth. Iterate through the sorted list and accumulate color and opacity using alpha compositing to produce the final pixel color [G].

**Pseudocode:**
```python
def inference_pipeline(point_cloud, camera_pose):
    # Step 1: Rasterization
    screen_primitives = []
    for prim in point_cloud:
        cam_mean = transform_to_camera_space(prim.mean, camera_pose.view_matrix)
        screen_cov = project_covariance(prim.covariance, camera_pose.projection_matrix, cam_mean)
        screen_primitives.append({
            'mean': cam_mean,
            'covariance': screen_cov,
            'opacity': prim.opacity,
            'color': prim.color
        })

    # Step 2: Compositing
    screen_primitives.sort(key=lambda p: p['mean'].z)

    image = numpy.zeros((camera_pose.height, camera_pose.width, 3))
    alpha_accum = numpy.zeros((camera_pose.height, camera_pose.width))

    for prim in screen_primitives:
        for y, x in get_bounding_box(prim['mean'], prim['covariance']):
            dist = compute_pixel_distance(x, y, prim['mean'])
            pdf = numpy.exp(-0.5 * dist) / (2 * numpy.pi * numpy.sqrt(numpy.linalg.det(prim['covariance'])))
            alpha = prim.opacity * pdf
            if alpha_accum[y, x] + alpha >= 1.0:
                continue
            color_blend = prim.color * alpha * (1.0 - alpha_accum[y, x])
            image[y, x] += color_blend
            alpha_accum[y, x] += alpha * (1.0 - alpha_accum[y, x])

    return image

def transform_to_camera_space(point, view_matrix):
    return view_matrix @ numpy.append(point, 1.0)

def project_covariance(cov, proj_matrix, cam_mean):
    J = proj_matrix @ view_matrix
    return J @ cov @ J.T

def get_bounding_box(mean, cov):
    # [G] Standard axis-aligned bounding box calculation for 2D Gaussian
    return numpy.array([[0, 0], [100, 100]])

def compute_pixel_distance(x, y, mean):
    return (x - mean.x)**2 + (y - mean.y)**2
```

### Runtime Inference with Control Encoding
After training, only the forward flow is used to render images [S2]. A control encoding passed to MLPs determines the object to be rendered at runtime [S2]. MLPs are invoked only when the encoding changes [S2]. The color MLP is re-evaluated whenever the viewing angle shifts to account for view-dependent colors [S2]. All other MLPs predict $k$ parameters for each anchor point instead of being inferred for every viewing direction [S2].
