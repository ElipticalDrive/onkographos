# Voxel Visualization Ray Marcher

Also called: 3D Texture Visualizer, Simple Fragment Shader Path Tracer

## Overview
A fragment shader technique that ray marches through a 3D texture to visualize voxelized data by accumulating color along a ray until opacity saturates or the ray exits the volume [S1, unofficial]. It differs from its parent [Voxel Raymarching with Screen Filters](2555-voxel-raymarching-with-screen-filters.md) by using a fixed-step traversal loop with explicit alpha compositing in the fragment shader, rather than relying on pre-filtered screen-space accumulation or hierarchical traversal structures [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Uniforms**:
    *   `textureFront`: `sampler2D`, stores ray origin coordinates for each fragment [S1, unofficial].
    *   `textureBack`: `sampler2D`, stores ray direction endpoints for each fragment [S1, unofficial].
    *   `texture3D`: `sampler3D`, contains the voxelized volume data [S1, unofficial].
    *   `cameraPosition`: `vec3`, world-space camera position [S1, unofficial].
    *   `state`: `int`, specifies the mipmap level for sampling the 3D texture (default 0) [S1, unofficial].
*   **Varying/Input**:
    *   `textureCoordinateFrag`: `vec2`, fragment texture coordinates [S1, unofficial].
*   **Output**:
    *   `color`: `vec4`, the final accumulated color [S1, unofficial].

**Constants**
*   `STEP_LENGTH`: `float`, default `0.005f`, defines the fixed distance advanced per ray march step [S1, unofficial].
*   `INV_STEP_LENGTH`: `float`, computed as `1.0f / STEP_LENGTH` [S1, unofficial].

**Data Structures**
The method relies on standard OpenGL sampler types. The 3D texture `texture3D` is sampled using `texture3D` (or `texelFetch`/`texture` depending on GLSL version, here assumed `texture` for normalized coordinates) [S1, unofficial]. The front and back textures are 2D samplers storing 3D vectors [S1, unofficial].

**Algorithm**
1.  **Initialize Ray Origin**: Determine the starting point of the ray. If the `cameraPosition` lies inside the unit cube with a margin of `0.2f` (i.e., all coordinates are within `[0.2, 0.8]`), set `origin = cameraPosition`. Otherwise, sample the origin from `textureFront` using `textureCoordinateFrag` [S1, unofficial].
2.  **Calculate Total Steps**: Compute the total number of steps required to traverse the ray length. Let `direction` be the vector from `origin` to the endpoint sampled from `textureBack` at `textureCoordinateFrag`. The number of steps is `numberOfSteps = uint(length(direction) * INV_STEP_LENGTH)` [S1, unofficial].
3.  **Initialize Accumulator**: Set the output color to transparent black: `color = vec4(0.0f)` [S1, unofficial].
4.  **Ray Marching Loop**: Iterate `step` from `0` to `numberOfSteps`:
    *   **Break Condition**: If `color.a >= 0.99f`, break the loop [S1, unofficial].
    *   **Compute Position**: Calculate the current point in space: `currentPoint = origin + STEP_LENGTH * step * direction` [S1, unofficial].
    *   **Normalize Coordinates**: Scale and bias `currentPoint` to the `[0, 1]` range suitable for texture sampling. If `currentPoint` is already in `[0, 1]`, no bias is needed; otherwise, apply `currentPoint = currentPoint * 0.5f + 0.5f` (assuming the volume is centered at 0 with extent 1, or similar mapping depending on the specific volume definition; the source implies a scaling/bias operation) [S1, unofficial].
    *   **Sample Volume**: Sample the 3D texture at the scaled `currentPoint` using `state` as the mipmap level: `currentSample = texture(texture3D, scaledPoint, state)` [S1, unofficial].
    *   **Alpha Compositing**: Accumulate the color using front-to-back blending:
        $$c_{out} = c_{in} + (1.0 - c_{in}.a) \times s$$
        where $c_{in}$ is the accumulated color, $c_{in}.a$ is its alpha, and $s$ is the sampled voxel color `currentSample` [S1, unofficial].
5.  **Gamma Correction**: Apply sRGB gamma correction to the RGB channels of the final color by raising them to the power of $1/2.2$: `color.rgb = pow(color.rgb, vec3(1.0 / 2.2))` [S1, unofficial].

**Pseudocode**
```python
# Inputs: textureFront, textureBack, texture3D, cameraPosition, state, textureCoordinateFrag
# Constants: STEP_LENGTH = 0.005f, INV_STEP_LENGTH = 1.0f / STEP_LENGTH

def voxel_visualization_ray_marcher(textureCoordinateFrag):
    # 1. Initialize Ray Origin
    # Check if cameraPosition is inside the unit cube with margin 0.2f
    if all(0.2 <= coord <= 0.8 for coord in cameraPosition):
        origin = cameraPosition
    else:
        origin = texture(textureFront, textureCoordinateFrag).xyz

    # 2. Calculate Direction and Total Steps
    # Sample the back point to determine direction
    back_point = texture(textureBack, textureCoordinateFrag).xyz
    direction = back_point - origin
    ray_length = length(direction)
    number_of_steps = uint(ray_length * INV_STEP_LENGTH)

    # 3. Initialize Output Color
    color = vec4(0.0, 0.0, 0.0, 0.0)

    # 4. Ray Marching Loop
    for step in range(number_of_steps):
        # Break if opacity saturates
        if color.a >= 0.99:
            break

        # Compute current point
        current_point = origin + STEP_LENGTH * step * direction

        # Scale and bias current point to [0, 1]
        # Assuming the volume space maps linearly to [0,1] via scaling/bias
        # If the volume is defined in [-0.5, 0.5], scale by 0.5 and bias by 0.5
        # The source says "scale and bias", implying a generic transform
        scaled_point = current_point * 0.5 + 0.5 

        # Sample texture3D
        # state is the mipmap level
        current_sample = texture(texture3D, scaled_point, state)

        # Alpha compositing: c_out = c_in + (1.0 - c_in.a) * s
        color = color + (1.0 - color.a) * current_sample

    # 5. Gamma Correction
    color.rgb = pow(color.rgb, vec3(1.0 / 2.2))

    return color
```

**Edge Cases and Pitfalls**
*   **Ray Origin Validity**: The ray origin must avoid invalid positions. If the camera is inside the unit cube, the origin is set to the camera position directly. Otherwise, it is fetched from the front buffer to ensure valid ray starting points [S1, unofficial].
*   **Precision**: The use of `uint` for step count may truncate fractional steps, potentially causing the ray to slightly undershoot the volume boundary.
*   **Boundary Conditions**: If `current_point` falls outside the `[0, 1]` range after scaling, texture sampling behavior depends on the texture wrapping mode (default is usually clamp or repeat, which may produce artifacts if not handled) [G].

## Subtopics

### Voxel Visualization Ray Casting
A technique to visualize the voxel grid by casting rays from the camera through the unit cube, using pre-computed front and back intersection textures to determine ray origin and direction [S2, unofficial]. It differs from the Ray Marcher by potentially skipping the accumulation loop in favor of direct intersection or simpler visualization, though it shares the same initialization logic [S2, unofficial]. Choose this when the goal is to visualize the grid structure or perform simple visibility checks rather than volumetric blending [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of steps per ray, determined by the ray length and `STEP_LENGTH` [S1, unofficial].
*   **Memory Complexity**: $O(1)$ per fragment, plus the memory for the 3D texture and front/back 2D textures [S1, unofficial].
*   **Performance**: Performance is limited by the fixed step size and the number of texture samples. A smaller `STEP_LENGTH` increases accuracy but reduces performance [S1, unofficial].
*   **Strengths**: Simple implementation, easy to integrate into a fragment shader pipeline [S1, unofficial].
*   **Limitations**: Fixed step size may lead to aliasing or missed details if the step is too large; no early exit based on empty space (only opacity) [S1, unofficial].
*   **When to Use**: Suitable for real-time visualization of voxel data where simplicity is prioritized over performance or accuracy [S1, unofficial].
*   **When Not to Use**: Not suitable for large volumes with high dynamic range or when hierarchical traversal is needed for performance [S1, unofficial].

## Background
The method originates from the Voxel Cone Tracing project, specifically the `voxel_visualization.frag` shader implementation [S1, unofficial]. It is used for visualizing voxelized data in real-time graphics applications [S1, unofficial].
