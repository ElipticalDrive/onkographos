# Ray Marching Optimization


## Overview
Ray marching optimization refers to techniques that accelerate volume rendering by replacing fixed-distance sampling steps with analytical traversal of voxel boundaries or by using auxiliary data structures to skip empty space [S1, S2, unofficial]. Unlike standard fixed-step ray marching, which samples at uniform intervals regardless of scene content, optimized methods advance the ray analytically from one cell boundary to the next, minimizing floating-point operations and redundant samples [S5, S7, unofficial]. This family builds on [Ray-grid traversal](17-ray-grid-traversal.md) by focusing on the efficiency of the traversal loop and the integration of sampling strategies.

## Shared principles
All methods in this family share the core mechanism of advancing analytically from one cell boundary to the next, avoiding fixed-distance sampling steps [S5][S7, unofficial]. The algorithm determines the next cell by comparing the distances to the upcoming boundaries on the x, y, and z axes, selecting the minimum distance to advance [S2, unofficial][S3, unofficial][S5].

### Mathematical Foundation
Let the ray be defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized or unnormalized) [G]. The grid is defined by cell boundaries. For a uniform grid with voxel size $v$ and dimensions $N_x, N_y, N_z$, the traversal relies on three key precomputed values per axis $i \in \{x, y, z\}$ [S2, unofficial][S3, unofficial][S5]:

1.  **Step Direction ($\text{step}_i$):** Determines the index increment direction [S4, unofficial].
    $$
    \text{step}_i = \begin{cases} 
    +1 & \text{if } d_i > 0 \\
    -1 & \text{if } d_i < 0 \\
    0 & \text{if } d_i = 0 
    \end{cases}
    $$
    If $d_i = 0$, the ray never crosses a boundary in that dimension, and the corresponding distance is treated as infinity [S5].

2.  **Time/Distance Delta ($\Delta t_i$ or $s_{\Delta i}$):** The distance along the ray to traverse one voxel width [S2, unofficial][S5].
    $$
    \Delta t_i = \frac{v_i}{|d_i|} \cdot \text{step}_i \quad \text{or} \quad s_{\Delta i} = \frac{\Delta x_i}{|\widehat{d}_i|}
    $$
    where $v_i$ is the voxel size and $\widehat{d}_i$ is the unit direction component [S2, unofficial][S5].

3.  **Time/Distance to Next Boundary ($t_{max, i}$ or $s_{max, i}$):** The distance from the ray origin to the first boundary crossed in axis $i$ [S2, unofficial][S3, unofficial][S5].
    $$
    t_{max, i} = \frac{\text{boundary}_i - o_i}{d_i}
    $$
    The initial boundary is determined by the starting voxel index [S3, unofficial]. If the ray starts inside the grid, the initial boundary is the next one in the direction of travel [S2, unofficial][S3, unofficial][S5].

### Traversal Loop
The core loop iterates while the ray remains within the grid bounds [S5]:
1.  Identify the axis $k$ with the minimum boundary distance: $t_{min} = \min(t_{max, x}, t_{max, y}, t_{max, z})$ [S2, unofficial][S3, unofficial][S5].
2.  Record the current cell and the interval $[t_{entry}, t_{min}]$ [S1][S5].
3.  Advance the index in axis $k$: $\text{index}_k \leftarrow \text{index}_k + \text{step}_k$ [S2, unofficial][S3, unofficial][S5].
4.  Update the boundary distance for axis $k$: $t_{max, k} \leftarrow t_{max, k} + \Delta t_k$ [S2, unofficial][S3, unofficial][S5].
5.  Update $t_{entry} \leftarrow t_{min}$ [S5].

### Pseudocode
```python
def dda_traversal(ray_origin, ray_direction, voxel_size, grid_bounds):
    # Initialize current voxel index
    current_voxel = floor(ray_origin / voxel_size)
    current_voxel = clamp(current_voxel, grid_bounds.min, grid_bounds.max)
    
    # Step direction per axis
    step = sign(ray_direction)
    
    # Distance to next boundary
    next_boundary = (current_voxel + step) * voxel_size
    t_max = (next_boundary - ray_origin) / ray_direction
    t_max = where(ray_direction == 0, INF, t_max)
    
    # Distance to traverse one voxel
    t_delta = voxel_size / abs(ray_direction)
    t_delta = where(ray_direction == 0, INF, t_delta)
    
    visited = []
    while current_voxel inside grid_bounds:
        visited.append(current_voxel)
        axis = argmin(t_max)
        current_voxel[axis] += step[axis]
        t_max[axis] += t_delta[axis]
    return visited
```

### Edge and Corner Handling
When the ray crosses an edge or corner (i.e., two or three $t_{max}$ values are equal), the traversal must advance all corresponding axes to maintain 4-connectivity (or 6/8-connectivity in 2D/3D) and avoid zero-length segments [S5]. The implementation uses independent `if` checks for ties rather than `if/elif` chains [S5]. A tie tolerance $\varepsilon_{\mathrm{DDA}}$ is used to handle floating-point drift, typically defined as $64 \varepsilon_{\mathrm{machine}} \max(1 \text{ cm}, L_{\mathrm{grid}})$ [S5].

### Non-Uniform Grids
For non-uniform grids defined by arbitrary 1D edge arrays (walls) $W_i$, the traversal time to the next wall is computed using the inverse velocity [S1]:
$$
t_{hit} = (W_{next} - o) \cdot \frac{1}{d}
$$
The traversal state maintains `hittimes` for each dimension, updated by precomputed `voxel_traversal_times` which depend on the wall spacing and ray velocity [S1].

## Subtopics

### [Voxel Ray Marching with Traversal Order Optimization](1251-voxel-ray-marching-with-traversal-order-optimization.md)
Renders a 3D voxel texture by marching rays from the camera through the volume, compositing samples with front-to-back alpha blending to visualize the volume. It differs from standard fixed-step ray marching by optimizing the traversal order of voxel boundaries using precomputed time deltas ($t_{\Delta}$) and maximum boundary times ($t_{max}$), minimizing floating-point operations per step. The algorithm advances analytically from one cell boundary to the next, avoiding fixed-distance sampling steps.

### [Tiled Ray Marching with Grid Sampling](2586-tiled-ray-marching-with-grid-sampling.md)
Renders a single view of a 3D volume by generating rays, sampling density via grid sampling, and accumulating attenuation. It supports tiling to manage memory usage for large images. It differs from [Voxel Ray Marching with Traversal Order Optimization](1251-voxel-ray-marching-with-traversal-order-optimization.md) by using dense grid sampling (e.g., `grid_sample`) rather than sparse voxel traversal, and by explicitly tiling the image plane to bound peak memory usage.

### Indicator Grid Ray Marching
**Definition**
A binary map cached and updated during training to signify empty areas, allowing for early termination of ray marching based on transmittance, thereby optimizing ray marching efficiency [S1].

**Step**
1. Initialize the indicator grid as fully occupied, assuming all space is dense [S1].
2. Sample a small batch of spatiotemporal points and pass them through the tiny MLP $\theta$ to obtain density [S1].
3. Update the indicator grid based on the obtained density distribution [S1].

**Comparison**
Compared to the original Lerplane [51] which uses a sample-net requiring extensive sampling, this method reduces unnecessary point sampling, enabling approximately 5 times faster inference (1.73 fps vs. 0.38 fps) [S1].

## Background
Originating from the need to accelerate volume rendering in medical imaging and real-time applications, ray marching optimization evolved from basic Digital Differential Analyzer (DDA) traversal [S5, S7, unofficial]. The integration of indicator grids for early termination was introduced in the context of efficient deformable tissue reconstruction, specifically in the Lerplane framework [S1]. This approach was developed to address the high computational cost of surface-focused sampling in dynamic scenes, leveraging the observation that empty space can be identified and skipped during training and inference [S1].
