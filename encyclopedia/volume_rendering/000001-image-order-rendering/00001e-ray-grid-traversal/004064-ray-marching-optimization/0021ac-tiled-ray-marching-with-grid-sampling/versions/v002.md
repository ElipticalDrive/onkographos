# Tiled Ray Marching with Grid Sampling

Also called: Python-loop renderer, Tiled rendering

## Overview
Renders a single view of a 3D volume by generating rays, sampling density via `grid_sample`, and accumulating attenuation [S1, unofficial]. It supports tiling to manage memory usage for large images [S1, unofficial]. Unlike [Fixed Step Ray Marching](3136-fixed-step-ray-marching.md) which may iterate sequentially, this method leverages batched tensor operations for sampling while using tiling to handle memory constraints that would otherwise cause out-of-memory errors in dense volume rendering [S1, unofficial].

## How it works
**Inputs:**
- `volume`: 3D density tensor of shape $(D, H, W)$ or $(C, D, H, W)$ [S1, unofficial].
- `camera_matrix`: $4 \times 4$ matrix defining camera pose [S1, unofficial].
- `ijk2ras`: $4 \times 4$ transformation matrix from volume grid (IJK) to physical space (RAS) [S1, unofficial].
- `ray_samples`: Number of samples per ray [S1, unofficial].
- `tile_h`, `tile_w`: Tile dimensions used to bound peak memory [S1, unofficial].
- `use_beer_lambert`: Boolean flag for attenuation model [S1, unofficial].
- `density_factor`: Scaling factor for non-Beer-Lambert mode [S1, unofficial].
- `margin`: Safety margin for near/far clipping [S1, unofficial].

**Outputs:**
- Rendered image tensor [S1, unofficial].
- Optional transmittance or optical depth (`tau`) [S1, unofficial].

**Data Structures:**
- `dirs_cam`: Buffer of shape $(H, W, 3)$ storing normalized camera-space view directions [S1, unofficial].
- `dirs_world`: Tensor of shape $(H, W, 3)$ storing world-space view directions [S1, unofficial].
- `origin_ijk`: Tensor of shape $(3,)$ storing the camera origin in IJK space [S1, unofficial].
- `dirs_ijk`: Tensor of shape $(H, W, 3)$ storing ray directions in IJK space [S1, unofficial].
- `ijk`: Tensor of shape $(ray\_samples, H, W, 3)$ (noted as $(D, H, W, 3)$ in the source) storing sample coordinates in IJK space [S1, unofficial].
- `density_b`: Tensor of shape $(1, C, W, H, D)$ prepared for `grid_sample` [S1, unofficial].

**Steps:**

1. **Initialize Camera Directions:** Compute the vertical field of view (FOV) to populate `dirs_cam` [S1, unofficial]. Generate a grid of directions in camera space, normalize them, and store in `dirs_cam` [S1, unofficial].
2. **Extract Camera Pose:** Extract the camera-to-world rotation (`cam2world`) and position (`cam_pos`) from the `camera_matrix` [S1, unofficial]. If the matrix represents world-to-camera (indicated by small translation norm), invert it to get camera-to-world [S1, unofficial].
3. **Transform Directions to World Space:** Transform camera-space directions to world space:
   $$ \text{dirs\_world} = \text{einsum}('ij,hwj->hwi', \text{cam2world}, \text{dirs\_cam}) $$
   This results in shape $(H, W, 3)$ [S1, unofficial].
4. **Extract Volume Transformation:** Extract the RAS-to-IJK rotation ($R$) and translation ($t$) from `ijk2ras` [S1, unofficial]. Compute the scale factor:
   $$ s = \frac{2.0}{\text{vol\_shape} - 1} $$
   where `vol_shape` is $(D, H, W)$ [S1, unofficial].
5. **Transform to IJK Space:** Transform world-space directions to IJK space:
   $$ \text{dirs\_ijk} = \text{dirs\_world} @ R^T $$
   Transform camera position to IJK space:
   $$ \text{origin\_ijk} = \text{cam\_pos} @ R^T + t $$
   Resulting shapes: `dirs_ijk` is $(H, W, 3)$, `origin_ijk` is $(3,)$ [S1, unofficial].
6. **Compute Near and Far Clipping:** Calculate near and far clipping distances by projecting the 8 corners of the volume bounding box (in IJK space, transformed to RAS) onto the view direction from the camera position [S1, unofficial]. Add the `margin` to expand the range [S1, unofficial].
7. **Generate Sample Depths:** Compute sample depths along the ray:
   $$ \text{depths} = \text{near} + (\text{far} - \text{near}) \times \text{linspace}(0, 1, \text{ray\_samples}) $$
   Shape: $(ray\_samples,)$ [S1, unofficial].
8. **Compute IJK Coordinates:** Compute IJK coordinates for all samples:
   $$ \text{ijk} = s \times (\text{origin\_ijk} + \text{dirs\_ijk} \times \text{depths}[:, \text{None}, \text{None}, \text{None}]) - 1 $$
   This results in shape $(ray\_samples, H, W, 3)$ (noted as $(D, H, W, 3)$ in the source) [S1, unofficial].
9. **Prepare Density Tensor:** Prepare the density tensor for `grid_sample` by unsqueezing to shape $(1, C, W, H, D)$ [S1, unofficial].
10. **Render Tile:** Define a function `render_tile` that:
    - Samples density using `F.grid_sample(density_b, coords_tile, align_corners=False)` [S1, unofficial].
    - If `use_beer_lambert` is True:
      - Compute optical depth: $\tau = \sum (\text{dens\_tile} \times \text{step\_size}, \text{dim}=2)$ [S1, unofficial].
      - If `return_tau` is True, apply Poisson noise to $\tau$ [S1, unofficial].
      - Otherwise, apply Poisson noise to $\exp(-\tau)$ and return $1 - \text{noisy\_transmission}$ [S1, unofficial].
    - If `use_beer_lambert` is False:
      - Compute $d = \text{density\_factor} \times \text{dens\_tile} / \text{ray\_samples}$ [S1, unofficial].
      - Compute transmission: $\text{transmission} = \text{cumprod}(1.0 - d, \text{dim}=2)$ [S1, unofficial].
      - Compute weight: $\text{weight} = d \times \text{transmission}$ [S1, unofficial].
      - Compute alpha: $\alpha = 1 - \prod (1.0 - d, \text{dim}=2)$ [S1, unofficial].
      - Return $(\text{weight.sum(dim=2)} / (w\_sum + 10^{-6})) \times \alpha$ [S1, unofficial].
11. **Tiling Execution:**
    - If the image is smaller than $2 \times \text{tile\_h} \times 2 \times \text{tile\_w}$, call `render_tile` with the full grid [S1, unofficial].
    - Otherwise, iterate over $H$ and $W$ in steps of `tile_h` and `tile_w` [S1, unofficial]. For each tile, extract the corresponding grid coordinates, call `render_tile`, and collect outputs [S1, unofficial]. Concatenate outputs along $W$ and $H$ axes [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def tiled_ray_marching(volume, camera_matrix, ijk2ras, ray_samples, 
                       tile_h=256, tile_w=256, use_beer_lambert=True, 
                       density_factor=1.0, margin=30.0):
    """
    Renders a volume using tiled ray marching with grid sampling.
    """
    # 1. Initialize Camera Directions
    h, w = volume.shape[-2], volume.shape[-1]
    # Generate normalized camera-space view directions (placeholder for FOV logic)
    dirs_cam = torch.empty(h, w, 3)
    # ... (populate dirs_cam based on FOV, normalized) ...
    
    # 2. Extract Camera Pose
    cam_matrix = torch.as_tensor(camera_matrix, dtype=torch.float32)
    ijk2ras_tensor = torch.as_tensor(ijk2ras, dtype=torch.float32)
    
    # Handle batched or single matrix
    if cam_matrix.ndim == 3:
        cam_to_world_all = torch.inverse(cam_matrix)
    else:
        cam_to_world_all = torch.inverse(cam_matrix.unsqueeze(0)).squeeze(0)
        
    # Determine if inversion was needed based on translation norm
    test_pos = cam_matrix[:, :3, 3] if cam_matrix.ndim == 3 else cam_matrix[:3, 3]
    translation_norm = torch.norm(test_pos, dim=-1)
    needs_invert = translation_norm < 1.0
    
    cam_pos_ras = torch.where(needs_invert, cam_to_world_all[:, :3, 3], cam_matrix[:, :3, 3])
    view_dir = torch.where(needs_invert, cam_to_world_all[:, :3, 2], cam_matrix[:, :3, 2])
    view_dir = view_dir / torch.norm(view_dir, dim=-1, keepdim=True)
    
    # 3. Transform Directions to World Space
    cam2world = cam_to_world_all[:3, :3]
    dirs_world = torch.einsum('ij,hwj->hwi', cam2world, dirs_cam)
    
    # 4. Extract Volume Transformation
    R = ijk2ras_tensor[:3, :3]
    t = ijk2ras_tensor[:3, 3]
    vol_shape = volume.shape
    scale = 2.0 / (torch.tensor(vol_shape, dtype=torch.float32) - 1)
    
    # 5. Transform to IJK Space
    dirs_ijk = dirs_world @ R.T
    origin_ijk = cam_pos_ras @ R.T + t
    
    # 6. Compute Near and Far Clipping
    I, J, K = vol_shape
    corners_ijk = torch.tensor([
        [0, 0, 0], [I-1, 0, 0], [0, J-1, 0], [I-1, J-1, 0],
        [0, 0, K-1], [I-1, 0, K-1], [0, J-1, K-1], [I-1, J-1, K-1]
    ], dtype=torch.float32)
    corners_homog = torch.cat([corners_ijk, torch.ones(8, 1)], dim=1)
    corners_ras = (ijk2ras_tensor @ corners_homog.T).T[:, :3]
    
    to_corners = corners_ras.unsqueeze(0) - origin_ijk.unsqueeze(1)
    distances = torch.sum(to_corners * view_dir.unsqueeze(1), dim=2)
    near = torch.min(distances, dim=1).values - margin
    far = torch.max(distances, dim=1).values + margin
    near = torch.clamp(near, min=0.1)
    
    # 7. Generate Sample Depths
    step_size = 0.1 * (far - near) / ray_samples
    depths = near + (far - near) * torch.linspace(0, 1, ray_samples)
    
    # 8. Compute IJK Coordinates
    ijk = scale * (origin_ijk.unsqueeze(1).unsqueeze(1) + 
                   dirs_ijk.unsqueeze(0) * depths[:, None, None, None]) - 1
    
    # 9. Prepare Density Tensor
    density_b = volume.unsqueeze(0).unsqueeze(0) # Shape (1, 1, W, H, D)
    
    # 10. Render Tile Function
    def render_tile(coords_tile):
        dens_tile = F.grid_sample(density_b, coords_tile, align_corners=False)
        if use_beer_lambert:
            tau = torch.sum(dens_tile * step_size, dim=2)
            # Poisson noise application would go here
            transmission = torch.exp(-tau)
            return 1.0 - transmission
        else:
            d = density_factor * dens_tile / ray_samples
            transmission = torch.cumprod(1.0 - d, dim=2)
            weight = d * transmission
            alpha = 1.0 - torch.prod(1.0 - d, dim=2)
            w_sum = torch.sum(weight, dim=2)
            return (w_sum / (w_sum + 1e-6)) * alpha
            
    # 11. Tiling Execution
    if h < 2 * tile_h and w < 2 * tile_w:
        return render_tile(ijk)
    else:
        outputs = []
        for i in range(0, h, tile_h):
            for j in range(0, w, tile_w):
                tile_coords = ijk[:, i:i+tile_h, j:j+tile_w, :]
                out = render_tile(tile_coords)
                outputs.append(out)
        # Reconstruct full image by concatenating along H and W axes
        full_h = ((h + tile_h - 1) // tile_h) * tile_h
        full_w = ((w + tile_w - 1) // tile_w) * tile_w
        full_image = torch.zeros(full_h, full_w, device=outputs[0].device)
        idx = 0
        for i in range(0, full_h, tile_h):
            for j in range(0, full_w, tile_w):
                if idx < len(outputs):
                    full_image[i:i+tile_h, j:j+tile_w] = outputs[idx]
                    idx += 1
        return full_image[:h, :w]
```

**Parameters:**
- `tile_h`, `tile_w`: Tile dimensions used to bound peak memory [S1, unofficial]. Default 256x256 [S1, unofficial]. Ignored if image is smaller than $2 \times \text{tile\_h} \times 2 \times \text{tile\_w}$ [S1, unofficial].
- `use_checkpointing`: Boolean flag [S1, unofficial]. If True and training, use `torch.utils.checkpoint.checkpoint` to save memory during backprop [S1, unofficial].
- `use_beer_lambert`: Boolean flag [S1, unofficial]. If True, use Beer-Lambert law (exponential attenuation) [S1, unofficial]. If False, use a different accumulation model (cumulative product of $(1-d)$) [S1, unofficial].
- `scatter`: Optional scatter function [S1, unofficial]. If present, scatter channels are processed separately and concatenated with non-scatter channels [S1, unofficial].
- `density_factor`: Scaling factor applied to density in the non-Beer-Lambert mode [S1, unofficial].

**Edge Cases and Pitfalls:**
- Precision issues may arise when computing `ijk` coordinates if the volume is very large or the camera is very close [S1, unofficial].
- Boundary conditions: `grid_sample` with `align_corners=False` handles out-of-bounds coordinates by returning zero or padding values, which may affect edge pixels [S1, unofficial].
- Degenerate input: If `near` equals `far`, step size becomes zero, leading to division by zero or no sampling [S1, unofficial]. The code clamps `near` to a minimum of 0.1 [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot H \cdot W \cdot \text{ray\_samples})$ where $N$ is the number of tiles [S1, unofficial]. Tiling does not change the total number of samples but may introduce overhead from tile management [S1, unofficial].
- **Memory Complexity:** $O(\text{tile\_h} \cdot \text{tile\_w} \cdot \text{ray\_samples})$ for the intermediate tensors during rendering [S1, unofficial]. This allows rendering of large images that would otherwise exceed GPU memory [S1, unofficial].
- **Measured Performance:** Not given in the sources.
- **Scaling:** Scales well with image resolution due to tiling [S1, unofficial]. Performance is limited by memory bandwidth and tensor operation efficiency [S1, unofficial].
- **Strengths:** Memory efficient for large images [S1, unofficial]. Leverages GPU-accelerated `grid_sample` for fast density lookup [S1, unofficial].
- **Limitations:** Tiling introduces overhead [S1, unofficial]. May not be optimal for very small images where full-grid rendering is faster [S1, unofficial].
- **When to use:** When rendering high-resolution volumes that exceed available GPU memory [S1, unofficial].
- **When not to use:** For small images or when memory is not a constraint, full-grid rendering may be simpler and faster [S1, unofficial].

Originated in the context of deep learning-based volume rendering, specifically in the `flashdrr` repository [S1, unofficial]. It is designed to integrate with PyTorch's automatic differentiation and GPU acceleration capabilities [S1, unofficial].
