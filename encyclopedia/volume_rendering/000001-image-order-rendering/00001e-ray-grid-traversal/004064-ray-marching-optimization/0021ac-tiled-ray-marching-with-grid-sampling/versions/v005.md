# Tiled Ray Marching with Grid Sampling

Also called: Python-loop renderer, Tiled rendering

## Overview
Tiled Ray Marching with Grid Sampling renders a 3D volume by generating rays per pixel, sampling density via grid-based interpolation, and accumulating attenuation [S1, unofficial]. It solves the memory bottleneck of large-volume rendering by processing the image in tiles, allowing the renderer to manage peak memory usage independently of image resolution [S1, unofficial]. It differs from its sibling [Voxel Ray Marching with Traversal Order Optimization](1251-voxel-ray-marching-with-traversal-order-optimization.md) by using fixed-step sampling with grid interpolation rather than analytic cell-boundary traversal [S1, unofficial].

## How it works
**Inputs:**
- Camera view matrix (camera-to-world or world-to-camera) [S1, unofficial].
- Volume density tensor in IJK space [S1, unofficial].
- Image dimensions $H \times W$ [S1, unofficial].
- Tiling parameters $tile_h, tile_w$ [S1, unofficial].
- Rendering mode flags: `use_beer_lambert`, `use_checkpointing` [S1, unofficial].

**Outputs:**
- Rendered image (color/alpha) [S1, unofficial].
- Optional optical depth $\tau$ [S1, unofficial].

**Data Structures:**
- `dirs_cam`: Tensor of shape $(H, W, 3)$ containing normalized camera-space view directions [S1, unofficial].
- `ijk`: Tensor of shape $(D, H, W, 3)$ containing sample coordinates in IJK space, where $D$ is the number of ray samples [S1, unofficial].
- `density_b`: Density tensor unsqueezed to $(1, C, W, H, D)$ for `grid_sample` compatibility [S1, unofficial].

**Parameters:**
- `ray_samples`: Number of samples per ray [S1, unofficial].
- `density_factor`: Scaling factor for density in non-Beer-Lambert mode [S1, unofficial].
- `tile_h, tile_w`: Tile dimensions (default 256x256) [S1, unofficial].
- `margin`: Safety margin for near/far clipping (default 30.0 mm) [S1, unofficial].

**Steps:**

1.  **Camera Setup:**
    Extract camera position $\mathbf{cam\_pos}$ and view direction $\mathbf{view\_dir}$ from the view matrix. If the matrix translation norm is $< 1.0$, invert the matrix to obtain camera-to-world transform [S1, unofficial]. Normalize $\mathbf{view\_dir}$ [S1, unofficial].

2.  **Clipping Bounds:**
    Compute the 8 corners of the volume bounding box in IJK space. Transform corners to RAS space using the `ijk2ras` matrix [S1, unofficial]. Project vectors from $\mathbf{cam\_pos}$ to corners onto $\mathbf{view\_dir}$ to find min/max distances. Set near/far bounds with margin:
    $$
    \text{near} = \min(\text{distances}) - \text{margin}, \quad \text{far} = \max(\text{distances}) + \text{margin}
    $$
    Clamp near to $\ge 0.1$ [S1, unofficial].

3.  **Ray Direction Transformation:**
    Extract RAS-to-IJK rotation $R$ and translation $t$ from `ras2ijk`. Compute scale factor $s = 2.0 / (\text{vol\_shape} - 1)$ [S1, unofficial]. Transform world-space directions to IJK space:
    $$
    \mathbf{dirs\_ijk} = \mathbf{dirs\_world} R^T
    $$
    Transform camera position to IJK space:
    $$
    \mathbf{origin\_ijk} = \mathbf{cam\_pos} R^T + t
    $$
    [S1, unofficial].

4.  **Sample Depth Generation:**
    Generate sample depths along the ray:
    $$
    \text{depths} = \text{near} + (\text{far} - \text{near}) \times \text{linspace}(0, 1, \text{ray\_samples})
    $$
    [S1, unofficial].

5.  **Coordinate Computation:**
    Compute IJK coordinates for all samples. For each pixel $(h, w)$ and sample $d$:
    $$
    \mathbf{ijk}_{d,h,w} = s \times (\mathbf{origin\_ijk} + \mathbf{dirs\_ijk}_{h,w} \times \text{depths}_d) - 1
    $$
    Resulting tensor shape: $(D, H, W, 3)$ [S1, unofficial].

6.  **Tiled Rendering:**
    If image dimensions $< 2 \times tile_h \times 2 \times tile_w$, render the full grid. Otherwise, iterate over tiles $(ty, tx)$ with step sizes $tile_h, tile_w$ [S1, unofficial]. For each tile:
    a. Extract corresponding grid coordinates from `ijk` [S1, unofficial].
    b. Sample density using `F.grid_sample(density_b, coords_tile, align_corners=False)` [S1, unofficial].
    c. Accumulate results [S1, unofficial].

7.  **Accumulation:**
    - **Beer-Lambert Mode (`use_beer_lambert=True`):**
      Compute step size $\Delta t = 0.1 \times (\text{far} - \text{near}) / \text{ray\_samples}$ [S1, unofficial].
      Compute optical depth:
      $$
      \tau = \sum (\text{density} \times \Delta t)
      $$
      Apply Poisson noise to $\tau$ if requested, or to transmission $e^{-\tau}$ [S1, unofficial]. Return $1 - \text{noisy\_transmission}$ [S1, unofficial].
    - **Non-Beer-Lambert Mode (`use_beer_lambert=False`):**
      Compute density contribution:
      $$
      d = \text{density\_factor} \times \text{density} / \text{ray\_samples}
      $$
      Compute transmission via cumulative product:
      $$
      T = \text{cumprod}(1.0 - d, \text{dim}=2)
      $$
      Compute weight:
      $$
      w = d \times T
      $$
      Compute alpha:
      $$
      \alpha = 1 - \prod (1.0 - d)
      $$
      Return weighted sum normalized by $w\_sum + 10^{-6}$ multiplied by $\alpha$ [S1, unofficial].

## Subtopics

### [Opt-in GPU Sampling for tifxyz Rendering](7397-opt-in-gpu-sampling-for-tifxyz-rendering.md)
Accelerates the sampling step of `vc_render_tifxyz` surface rendering by offloading trilinear sampling and pyramid generation to a CUDA or ROCm GPU, while maintaining byte-identical output to the CPU reference implementation. It differs from native integration by using `LD_PRELOAD` interposition to intercept the CPU sampling function, allowing the existing C++ renderer to remain unchanged.

### [Naive PyTorch Baseline Renderer](13676-naive-pytorch-baseline-renderer.md)
A reference implementation for differentiable rendering that processes all primitives for every pixel sequentially using standard PyTorch tensor operations. It serves as a performance baseline to demonstrate the efficiency gains of optimized CUDA implementations, which utilize tile-based culling, per-pixel parallelism, and FP16 optimization. Unlike its siblings, it lacks spatial optimization, tile-based binning, or specialized kernels, resulting in significant memory and computational overhead.

### Image-Space Ray Casting on Multicomputers
Iterates over each tile, then each ray through the tile, then each ray step. If step neighbors are not located on the local node, it fetches required macros from other nodes. If step neighbors have not been shaded, it shades them [S2, unofficial].

## Operating characteristics
- **Memory:** Peak memory is bounded by tile size ($tile_h \times tile_w$) rather than full image resolution, enabling rendering of large images on limited VRAM [S1, unofficial].
- **Performance:** Tiling introduces overhead for small images; if image size $< 2 \times tile_h \times 2 \times tile_w$, tiling is skipped [S1, unofficial].
- **Accuracy:** Uses fixed-step sampling with grid interpolation, which may introduce aliasing compared to adaptive traversal methods [S1, unofficial].
- **Scalability:** Scales with image resolution via tiling; scales with volume size via grid sampling efficiency [S1, unofficial].

## Background
Originated in the context of deep learning-based volume rendering frameworks, specifically `flashdrr` [S1, unofficial]. It leverages PyTorch's `grid_sample` for efficient density retrieval and supports both Beer-Lambert and alternative accumulation models [S1, unofficial].
