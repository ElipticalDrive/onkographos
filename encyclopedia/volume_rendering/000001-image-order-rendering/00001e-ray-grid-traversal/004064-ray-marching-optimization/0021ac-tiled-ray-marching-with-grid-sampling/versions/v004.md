# Tiled Ray Marching with Grid Sampling

Also called: Python-loop renderer, Tiled rendering

## Overview
This method renders a single view of a 3D volume by generating per-pixel rays, sampling density via grid-based interpolation, and accumulating attenuation to produce an image [S1, unofficial]. It addresses the memory constraints of large-volume rendering by processing the image in tiles, allowing the renderer to manage peak memory usage independently of the output resolution [S1, unofficial]. Unlike fixed-step ray marching, this approach computes sample depths along the ray and uses coordinate transformation to map them directly to the volume grid for batched sampling [S1, unofficial].

## How it works
**Inputs:**
*   Volume density tensor $V \in \mathbb{R}^{D \times H \times W}$ (or $C$ channels).
*   Camera parameters: View matrix (camera-to-world or world-to-camera), RAS-to-IJK transformation matrix, vertical Field of View (FOV).
*   Rendering parameters: `ray_samples` (number of samples per ray), `tile_h`, `tile_w`, `use_beer_lambert` (boolean), `density_factor`, `margin` (clipping safety margin).

**Outputs:**
*   Rendered image tensor (RGB or multi-channel).
*   Optional: Optical depth $\tau$ or transmission.

**Data Structures:**
*   `dirs_cam`: Precomputed camera-space view directions tensor of shape $(H_{img}, W_{img}, 3)$, normalized [S1, unofficial].
*   `ijk`: Sample coordinates tensor of shape $(ray\_samples, H_{img}, W_{img}, 3)$ in IJK space [S1, unofficial].
*   `density_b`: Density tensor padded to $(1, C, W, H, D)$ for `grid_sample` compatibility [S1, unofficial].

**Steps:**

1.  **Camera Setup:**
    *   Extract camera position $\mathbf{p}_{ras}$ and view direction $\mathbf{v}_{ras}$ from the view matrix. If the matrix represents world-to-camera (small translation norm), invert it to get camera-to-world [S1, unofficial].
    *   Normalize $\mathbf{v}_{ras}$ [S1, unofficial].
    *   Compute near and far clipping distances by projecting the 8 corners of the volume bounding box (transformed from IJK to RAS) onto $\mathbf{v}_{ras}$. Near is $\min(\text{distances}) - \text{margin}$, Far is $\max(\text{distances}) + \text{margin}$ [S1, unofficial]. Clamp near to $\ge 0.1$ [S1, unofficial].

2.  **Ray Generation:**
    *   Transform camera-space directions to world space: $\mathbf{d}_{world} = \mathbf{R}_{cam2world} \mathbf{d}_{cam}$ [S1, unofficial].
    *   Transform world-space directions to IJK space: $\mathbf{d}_{ijk} = \mathbf{d}_{world} \mathbf{R}_{ras2ijk}^T$ [S1, unofficial].
    *   Transform camera position to IJK space: $\mathbf{o}_{ijk} = \mathbf{p}_{ras} \mathbf{R}_{ras2ijk}^T + \mathbf{t}_{ras2ijk}$ [S1, unofficial].
    *   Generate sample depths: $t_n = \text{near} + (\text{far} - \text{near}) \frac{n}{N-1}$ for $n \in [0, N-1]$, where $N = \text{ray\_samples}$ [S1, unofficial].

3.  **Coordinate Transformation:**
    *   Compute IJK coordinates for all samples:
        $$ \mathbf{ijk}_{n,h,w} = \text{scale} \cdot (\mathbf{o}_{ijk} + \mathbf{d}_{ijk} \cdot t_n) - 1 $$
        where $\text{scale} = \frac{2.0}{\max(D, H, W) - 1}$ [S1, unofficial]. Note: The source uses `vol_shape - 1` in the denominator for scale, implying normalization to $[-1, 1]$ range typical for `grid_sample` [S1, unofficial].
    *   Resulting tensor shape: $(N, H_{img}, W_{img}, 3)$ [S1, unofficial].

4.  **Tiling Loop:**
    *   If image dimensions $(H_{img}, W_{img})$ are smaller than $2 \cdot \text{tile\_h} \times 2 \cdot \text{tile\_w}$, process the full image as a single tile [S1, unofficial].
    *   Otherwise, iterate over $h \in [0, H_{img})$ with step $\text{tile\_h}$ and $w \in [0, W_{img})$ with step $\text{tile\_w}$ [S1, unofficial].
    *   For each tile, extract the corresponding slice of `ijk` coordinates [S1, unofficial].

5.  **Sampling and Accumulation (per tile):**
    *   Sample density using bilinear/trilinear interpolation: $\mathbf{dens}_{tile} = \text{grid\_sample}(\mathbf{density\_b}, \mathbf{ijk}_{tile}, \text{align\_corners}=\text{False})$ [S1, unofficial].
    *   Compute step size: $\Delta t = \frac{\text{far} - \text{near}}{\text{ray\_samples}}$ [S1, unofficial].
    *   **Mode A: Beer-Lambert Law** (`use_beer_lambert=True`):
        *   Compute optical depth: $\tau = \sum_{n=0}^{N-1} \mathbf{dens}_{tile}[n] \cdot \Delta t$ [S1, unofficial].
        *   If `return_tau` is True, apply Poisson noise to $\tau$. Otherwise, apply Poisson noise to transmission $T = e^{-\tau}$ and return $1 - T_{noisy}$ [S1, unofficial].
    *   **Mode B: Cumulative Product** (`use_beer_lambert=False`):
        *   Compute per-sample absorption: $d_n = \text{density\_factor} \cdot \frac{\mathbf{dens}_{tile}[n]}{N}$ [S1, unofficial].
        *   Compute transmission: $T_n = \prod_{k=0}^{n-1} (1 - d_k)$ (with $T_0 = 1$) [S1, unofficial].
        *   Compute weight: $w_n = d_n \cdot T_n$ [S1, unofficial].
        *   Compute alpha: $\alpha = 1 - \prod_{n=0}^{N-1} (1 - d_n)$ [S1, unofficial].
        *   Return color: $\mathbf{C} = \frac{\sum_{n=0}^{N-1} w_n \cdot \mathbf{C}_{sample}}{\sum w_n + \epsilon}$ (Note: Source formula divides by `w_sum`, implying weighted average of colors, though density is the primary value sampled. The source explicitly states: `(weight.sum(dim=2) / (w_sum + 1e-6)) * alpha` which seems to be a specific normalization for the density output rather than color, or assumes density acts as color. We follow the source formula exactly) [S1, unofficial].

**Pseudocode:**

```python
import torch
import torch.nn.functional as F

def tiled_ray_marching(volume, camera_matrix, ijk2ras, fov, ray_samples, 
                       tile_h=256, tile_w=256, use_beer_lambert=True, 
                       density_factor=1.0, margin=30.0):
    """
    Renders volume using tiled ray marching with grid sampling.
    """
    # 1. Camera Setup
    # Determine if matrix is world-to-camera or camera-to-world
    cam_mat = camera_matrix.to(torch.float32)
    ijk2ras_mat = ijk2ras.to(torch.float32)
    
    # Check translation norm to decide inversion
    test_pos = cam_mat[:, :3, 3] if cam_mat.ndim == 3 else cam_mat[:3, 3]
    # Simplified for single camera
    if cam_mat.ndim == 2:
        cam_mat = cam_mat.unsqueeze(0)
        ijk2ras_mat = ijk2ras_mat.unsqueeze(0)
        
    needs_invert = torch.norm(cam_mat[:, :3, 3], dim=1) < 1.0
    
    cam_to_world = torch.inverse(cam_mat)
    cam_pos_ras = torch.where(needs_invert.view(-1, 1, 1), 
                              cam_to_world[:, :3, 3].unsqueeze(1), 
                              cam_mat[:, :3, 3].unsqueeze(1)).squeeze(1)
    view_dir = torch.where(needs_invert.view(-1, 1, 1), 
                           cam_to_world[:, :3, 2].unsqueeze(1), 
                           cam_mat[:, :3, 2].unsqueeze(1)).squeeze(1)
    view_dir = view_dir / torch.norm(view_dir, dim=1, keepdim=True)
    
    # 2. Clipping
    # Get volume shape from density tensor
    D, H_vol, W_vol = volume.shape[0], volume.shape[1], volume.shape[2]
    corners_ijk = torch.tensor([
        [0, 0, 0], [D-1, 0, 0], [0, H_vol-1, 0], [D-1, H_vol-1, 0],
        [0, 0, W_vol-1], [D-1, 0, W_vol-1], [0, H_vol-1, W_vol-1], [D-1, H_vol-1, W_vol-1]
    ], dtype=torch.float32, device=volume.device)
    
    corners_homog = torch.cat([corners_ijk, torch.ones(8, 1, device=volume.device)], dim=1)
    corners_ras = (ijk2ras_mat[0] @ corners_homog.T).T[:, :3]
    
    to_corners = corners_ras.unsqueeze(0) - cam_pos_ras.unsqueeze(1)
    distances = torch.sum(to_corners * view_dir.unsqueeze(1), dim=2)
    
    near = torch.min(distances, dim=1).values - margin
    far = torch.max(distances, dim=1).values + margin
    near = torch.clamp(near, min=0.1)
    
    # 3. Ray Generation
    # Assume dirs_cam is precomputed and normalized in camera space
    # dirs_cam shape: (H_img, W_img, 3)
    # Extract rotation from cam_to_world
    R_cam2world = cam_to_world[0, :3, :3]
    dirs_world = torch.einsum('ij,hwj->hwi', R_cam2world, dirs_cam)
    
    # Transform to IJK
    R_ras2ijk = ijk2ras_mat[0, :3, :3]
    t_ras2ijk = ijk2ras_mat[0, :3, 3]
    
    dirs_ijk = dirs_world @ R_ras2ijk.T
    origin_ijk = cam_pos_ras @ R_ras2ijk.T + t_ras2ijk
    
    # 4. Coordinate Transformation
    # Scale factor
    scale = 2.0 / (max(D, H_vol, W_vol) - 1)
    
    # Generate depths
    t_vals = torch.linspace(0, 1, ray_samples, device=volume.device)
    depths = near + (far - near) * t_vals.unsqueeze(1).unsqueeze(2) # (N, 1, 1)
    
    # Broadcast origin and dirs to (N, H, W, 3)
    origin_ijk_exp = origin_ijk.unsqueeze(0).unsqueeze(0).unsqueeze(0) # (1, 1, 1, 3)
    dirs_ijk_exp = dirs_ijk.unsqueeze(0).unsqueeze(0) # (1, H, W, 3)
    
    ijk = scale * (origin_ijk_exp + dirs_ijk_exp * depths.unsqueeze(3)) - 1.0
    
    # 5. Tiling
    H_img, W_img = dirs_cam.shape[0], dirs_cam.shape[1]
    
    # Prepare density for grid_sample: (1, C, D, H, W) -> (1, 1, D, H, W) if single channel
    # Note: grid_sample expects (N, C, H, W) or (N, C, D, H, W) for 3D
    density_b = volume.unsqueeze(0).unsqueeze(0) # (1, 1, D, H, W)
    
    step_size = (far - near) / ray_samples
    
    # Determine tile bounds
    if H_img < 2 * tile_h and W_img < 2 * tile_w:
        tiles_h, tiles_w = 1, 1
        tile_hs = [0]
        tile_ws = [0]
    else:
        tile_hs = list(range(0, H_img, tile_h))
        tile_ws = list(range(0, W_img, tile_w))
        tiles_h = len(tile_hs)
        tiles_w = len(tile_ws)
        
    results = []
    
    for th in tile_hs:
        row_results = []
        for tw in tile_ws:
            h_end = min(th + tile_h, H_img)
            w_end = min(tw + tile_w, W_img)
            
            # Extract tile coordinates
            ijk_tile = ijk[:, th:h_end, tw:w_end, :] # (N, h_end-th, w_end-tw, 3)
            
            # Sample density
            # grid_sample expects normalized coordinates in [-1, 1]
            # ijk is already scaled to [-1, 1]
            dens_tile = F.grid_sample(density_b, ijk_tile, align_corners=False) # (1, 1, h, w)
            
            # Accumulation
            if use_beer_lambert:
                tau = torch.sum(dens_tile * step_size, dim=0) # (1, h, w)
                # Poisson noise application omitted for brevity as per source [S1, unofficial]
                transmission = torch.exp(-tau)
                # Return 1 - noisy_transmission
                out = 1.0 - transmission
            else:
                d = density_factor * dens_tile / ray_samples
                # Cumprod of (1-d)
                one_minus_d = 1.0 - d
                transmission = torch.cumprod(one_minus_d, dim=0)
                # Shift transmission so T_0 = 1
                transmission = torch.cat([torch.ones_like(transmission[0:1]), transmission[:-1]], dim=0)
                
                weight = d * transmission
                alpha = 1.0 - torch.prod(one_minus_d, dim=0)
                
                # Weighted sum / sum of weights * alpha
                # Note: Source formula: (weight.sum(dim=2) / (w_sum + 1e-6)) * alpha
                # Assuming weight contains color/density values
                w_sum = torch.sum(weight, dim=0)
                out = (w_sum / (w_sum + 1e-6)) * alpha
            
            row_results.append(out)
        results.append(torch.cat(row_results, dim=2))
        
    return torch.cat(results, dim=1)
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point drift in coordinate transformation can cause sampling artifacts. The source does not specify a tolerance for `grid_sample` but relies on `align_corners=False` [S1, unofficial].
*   **Boundary Conditions:** The `grid_sample` function handles out-of-bounds coordinates by returning 0 (or padding value) if not handled explicitly. The clipping calculation ensures rays start inside the volume, but samples may fall outside if the volume is smaller than the bounding box defined by `near`/`far` [S1, unofficial].
*   **Memory:** Tiling is essential for large images. The default tile size is 256x256 [S1, unofficial]. If `use_checkpointing` is True, memory during backprop is reduced at the cost of recomputation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot H \cdot W)$, where $N$ is `ray_samples`, and $H, W$ are image dimensions. Tiling does not change asymptotic complexity but affects cache locality and memory bandwidth.
*   **Memory Complexity:** $O(N \cdot \text{tile\_h} \cdot \text{tile\_w})$ for the coordinate and density tensors per tile. Peak memory is bounded by tile size, not image size [S1, unofficial].
*   **Performance:** The method is implemented in PyTorch, leveraging GPU acceleration for `grid_sample` and tensor operations. Performance scales with GPU memory bandwidth and compute capability.
*   **Strengths:** Simple implementation, flexible accumulation models (Beer-Lambert or cumulative product), memory-efficient for large images via tiling [S1, unofficial].
*   **Limitations:** Fixed-step sampling along the ray may miss thin structures if `ray_samples` is low. Coordinate transformation overhead is non-trivial. Not a true grid traversal method (like DDA) but rather a fixed-depth sampling method [S1, unofficial].

## Background
This method is derived from the `flashdrr` repository, a Python-based volume renderer for medical imaging (DICOM) [S1, unofficial]. It was developed to provide a fast, differentiable volume rendering pipeline compatible with PyTorch, enabling integration into deep learning workflows for tasks like segmentation or registration [S1, unofficial]. The tiling strategy is a common technique in image processing to handle memory constraints on GPUs [S1, unofficial].
