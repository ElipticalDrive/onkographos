# Point Location
Also called: Frisken and Perry style hashing, Integer coordinate point location, Octree Hashing (Point Location), Octree Hashing with Precomputed Bit Masks, Octree Point Location, Octree Point Location with Precomputed Masks, top-down search, voxel lookup

## Overview
Point location maps a continuous 3D coordinate vector to a specific leaf node (or voxel) within a canonical octree. It solves the problem of efficiently retrieving data associated with a spatial position by traversing the tree from a given starting node to the target leaf. What sets this method apart from generic tree traversal is its reliance on precomputed bit masks to determine child indices using constant-time bitwise operations, avoiding the computational cost of arbitrary bit shifts. It builds on [Octree Child Index Computation](1807-octree-child-index-computation.md) to derive the 0-7 octant offset.

## How it works
**Inputs and Outputs:**
*   **Input:** `dest`: A 3D integer coordinate vector $(x, y, z)$ representing the target location. `depth`: The current depth level in the octree (starting from root or an intermediate node). `index`: The index of the current node in the flat node array. `max_depth`: The maximum depth of the octree.
*   **Output:** The scalar value stored in the leaf node containing `dest`.

**Data Structures:**
The method assumes the following data structures, typically stored in an `OctreeData` container:
*   `nodes`: A 2D array `nodes[depth][index]` of type `OctNode`.
*   `caps`: An array `caps[index]` of type `OctCap`, used for leaf voxels at the deepest level.
*   `child_bit_depth`: A precomputed 1D array `child_bit_depth[max_depth]`.
*   `OctNode` layout:
    *   `child_scalars[8]`: Array of scalar values for leaf children.
    *   `child_start`: Unsigned integer base pointer/index to the children of this node.
    *   `child_offset[8]`: Array of 8 signed chars (or integers) representing the offset from `child_start` to the child node. A value of `-1` indicates the child is a leaf (scalar).
*   `OctCap` layout:
    *   `child_scalars[8]`: Array of scalar values for the 8 voxels in the cap.

**Precomputation:**
Before traversal, the `child_bit_depth` array is computed for each depth level $d$ from $0$ to `max_depth`:
$$ \text{child\_bit\_depth}[d] = 1 \ll (\text{max\_depth} - d - 1) $$
This precomputation avoids expensive arbitrary left-shift operations during traversal [S1, S2, S3].

**Algorithm Steps:**
1.  **Initialize:** Start with the given `depth` and `index`.
2.  **Retrieve Node:** Access the current node: `node = nodes[depth][index]`.
3.  **Get Mask:** Retrieve the precomputed bit mask for the current depth: `child_bit = child_bit_depth[depth]`.
4.  **Compute Child Index:** Determine the 0-7 octant index of the child containing `dest`. This is done by testing the bits of `dest.x`, `dest.y`, and `dest.z` against `child_bit`, shifting the results, and combining them:
    $$ \text{child} = ((\text{dest}.x \ \& \ \text{child\_bit}) \neq 0) \ll 2 \ | \ ((\text{dest}.y \ \& \ \text{child\_bit}) \neq 0) \ll 1 \ | \ ((\text{dest}.z \ \& \ \text{child\_bit}) \neq 0) $$
    Note: The sources use `||` in the pseudocode for logical OR, but bitwise combination requires `|` or arithmetic addition. The logic is: if the bit is set, it contributes $4$, $2$, or $1$ to the index [S2, S3].
5.  **Check for Leaf in Interior Node:** If `node.child_offset[child] == -1`, the child is a scalar leaf. Return `node.child_scalars[child]` [S1, S2, S3].
6.  **Check for Cap Node (Deepest Level):** If `depth == max_depth - 2`, the node is a cap node containing voxels.
    *   Calculate the final child index using the lowest bit (bit 0) of the coordinates:
        $$ \text{child} = (\text{dest}.x \ \& \ 1) \ll 2 \ | \ (\text{dest}.y \ \& \ 1) \ll 1 \ | \ (\text{dest}.z \ \& \ 1) $$
    *   Return `caps[index].child_scalars[child]` [S2, S3].
7.  **Traverse Down:** If not a leaf and not a cap:
    *   Update `index` to point to the child's start location: `index = node.child_start + node.child_offset[child]`.
    *   Increment `depth`: `depth++`.
    *   Repeat from Step 2.

**Pseudocode:**
```python
def point_locate(dest: Vec3i, depth: int, index: int, max_depth: int, 
                 nodes: List[List[OctNode]], caps: List[OctCap], 
                 child_bit_depth: List[int]) -> T:
    while True:
        node = nodes[depth][index]
        child_bit = child_bit_depth[depth]
        
        # Compute child index (0-7) based on bits in dest coordinates
        # Using bitwise AND to test if the bit is set, then shifting
        child = ((dest.x & child_bit) != 0) << 2 | \
                ((dest.y & child_bit) != 0) << 1 | \
                ((dest.z & child_bit) != 0)
        
        # Check if child is a scalar leaf in an interior node
        if node.child_offset[child] == -1:
            return node.child_scalars[child]
        
        # Check if we are at the cap level (max_depth - 2)
        elif depth == max_depth - 2:
            # Use the lowest bit for cap nodes
            child = (dest.x & 1) << 2 | (dest.y & 1) << 1 | (dest.z & 1)
            return caps[index].child_scalars[child]
        
        # Traverse to the child node
        index = node.child_start + node.child_offset[child]
        depth += 1
        
    return 0  # Default return, though loop should always return
```

**Edge Cases and Pitfalls:**
*   **Coordinate Range:** Coordinates must be within the canonical interval $[0, 2^{\text{max\_depth}}]$. Components are cast to integers [S1, S2].
*   **Cap Nodes:** The algorithm explicitly handles the deepest level (`max_depth - 2`) as a special case using the lowest bit. This implies the octree structure uses "caps" for the finest resolution [S2, S3].
*   **Parent Pointers:** Parent pointers are omitted to save memory. Neighbor finding (which may call point location) relies on a separate `parent_trace` array provided by the ray traversal algorithm [S2, S3].

## Subtopics

### Recursive Octree Insertion with Bitstream
An algorithm to traverse and insert a voxel into an Octree using a pre-computed bitstream to determine child indices [S4].
*   **Definition:** It uses a bitstream `b` encoding the voxel's position to guide insertion [S4].
*   **Steps:**
    1.  If `depth d` is 0, return a new node containing the voxel `v` [S4].
    2.  Extract the child index from the bitstream `b` using `group(b, d, 3)` and get the corresponding child `n'` from node `n` [S4].
    3.  If child `n'` is null, create a new empty node [S4].
    4.  Recursively insert the voxel into the child node with `depth d-1`, and set the result as the child at the index derived from the bitstream [S4].
*   **Parameters:** `b`: The bitstream encoding the voxel's position [S4].
*   **When to choose:** Used for dynamic insertion into an octree where a bitstream representation of coordinates is available [S4].

## Operating characteristics
*   **Time Complexity:** $O(d)$, where $d$ is the depth of the octree. Each step performs constant-time bitwise operations and array lookups [S1, S2, S3].
*   **Memory Complexity:** $O(\text{max\_depth})$ for the precomputed `child_bit_depth` array. The node structure itself is compact, using `child_offset` as signed chars to save space [S2, S3].
*   **Performance:** Precomputing bit masks avoids expensive arbitrary left-shift operations, providing noticeably better performance than the original Frisken and Perry method [S1, S2, S3].
*   **Strengths:** Fast lookup, low memory overhead (no parent pointers), simple bitwise logic.
*   **Limitations:** Requires canonical coordinate system $[0, 2^{\text{max\_depth}}]$. Neighbor finding requires additional infrastructure (`parent_trace`) [S2, S3].

## Background
Originating from the work of Frisken and Perry, this method was adapted for interactive isosurface ray tracing of large octree volumes [S1, S2, S3]. The original proposal involved creating a single-bit mask corresponding to the current depth and applying it to coordinates. The optimized version, caching `child_bit_depth` to avoid arbitrary shifts, was introduced in subsequent implementations for performance [S1, S2, S3]. It is widely used in volume rendering and ray tracing applications requiring fast voxel lookup [S1, S2, S3].
