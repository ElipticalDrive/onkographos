# Back-Face Culling for Ray Casting

Also called: Back-face culling for entry/exit determination, Back-face depth culling raycasting, Backface Raycasting, Raycasting with depth pre-pass, Two-Pass Raycasting with Back-Face Depth Buffering, Two-Pass Raycasting with Backface Entry/Exit Points

## Overview
Back-face culling for ray casting is an optimization technique that determines the entry and exit points of a ray into a volume by rendering the back faces of the bounding cube to a texture, thereby avoiding the need to compute ray-cube intersections analytically [S1]. It is a two-pass rendering technique: the first pass renders the backface of the bounding box to a framebuffer to record entry depths, and the second pass performs raycasting using those points to drive ray marching, ensuring sampling begins inside the volume and terminates at the exit point [S2, S3]. This method sets itself apart from analytical intersection methods by leveraging the graphics pipeline's rasterization and depth testing to implicitly solve for ray bounds, and from 3D texture-based entry/exit lookups by using a 2D texture derived from the backface projection [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A volume bounding box (typically a cube defined by 8 vertices and 36 triangle indices), a 3D texture containing volume data (`uVolData`), a 2D texture for back-face coordinates (`uBackCoord` or `ExitPoints`), and camera matrices (Model-View `uMVMatrix`, Projection `uPMatrix`).
*   **Outputs:** A final color buffer with the composited volume rendering.

**Data Structures:**
1.  **Frame Buffer (`frameBuffer`):**
    *   **Depth Buffer:** A renderbuffer of type `DEPTH_COMPONENT16` with dimensions `width x height` [S3].
    *   **Color Texture (`texture`):** A 2D texture of type `RGBA`, `UNSIGNED_BYTE`, dimensions `width x height`. Initialized with zeros (`Uint8Array(4 * width * height)`) [S3]. Filters: `LINEAR` for `MIN`/`MAG`, `CLAMP_TO_EDGE` for `S`/`T` [S3].
2.  **Volume Data Texture (`uVolData`):** 3D texture containing scalar field data. Requires floating-point support (e.g., `OES_texture_float` in WebGL) [S3].
3.  **Back-Face Texture (`uBackCoord`):** 2D texture storing the 3D entry points (or exit points depending on pass definition) derived from the back-face render [S2, S3].

**Parameters:**
*   `StepSize`: Controls the step length in ray marching. Used in direction scaling and alpha modulation [S2].
*   `ScreenSize`: Resolution of the screen (`width`, `height`), used to normalize fragment coordinates for texture lookup [S2].
*   `uBackCoord`: Sampler uniform for the back-face depth/coordinate texture [S3].
*   `uVolData`: Sampler uniform for the volume data texture [S3].

**Numbered Steps:**

1.  **Initialization:**
    *   Create the frame buffer, depth renderbuffer, and color texture as described above [S3].
    *   Load volume data into `uVolData` [S3].
    *   Ensure the vertex winding order is Counterclockwise (CCW) so that front faces have outward normals and back faces have inward normals, allowing standard back-face culling logic to identify back faces when front faces are culled [S1].

2.  **Pass 1: Back-Face Depth/Coordinate Capture:**
    *   Bind the custom frame buffer [S3].
    *   Set the depth function to `GEQUAL` [S3]. This ensures that for a given pixel, the depth value written corresponds to the *farthest* (back-most) surface hit along the view ray, which represents the entry point into the volume from the camera's perspective (assuming the camera is outside) [S3]. *Note: In some implementations, this pass captures the exit point if the camera is inside or if the logic is inverted, but standard usage for external cameras captures the entry depth via back-face culling of the bounding box* [S1, S3].
    *   Enable front-face culling (or disable back-face culling and explicitly cull front faces) to render only the back-facing polygons of the bounding box [S1, S2].
    *   Execute the **Back-Face Vertex Shader**:
        *   Input: `VerPos` (vec3, object space), `VerClr` (vec3, object space coordinates).
        *   Output: `EntryPoint` (vec3, passed as `VerClr`), `ExitPointCoord` (vec4, `gl_Position`) [S2].
        *   Transformation: `gl_Position = uPMatrix * uMVMatrix * vec4(VerPos, 1.0)` [S3].
    *   Execute the **Back-Face Fragment Shader**:
        *   Input: `EntryPoint` (interpolated from `VerClr`) [S2].
        *   Output: `FragColor` = `vec4(EntryPoint, 1.0)` [S2].
    *   The result is a 2D texture where each pixel contains the 3D object-space coordinates of the back-face intersection (entry point) [S2].

3.  **Pass 2: Raycasting:**
    *   Bind the default framebuffer (screen) [S3].
    *   Set the depth function to `LEQUAL` [S3].
    *   Bind `uBackCoord` (the texture from Pass 1) to texture unit 0 [S3].
    *   Bind `uVolData` to texture unit 1 [S3].
    *   Execute the **Raycast Vertex Shader**:
        *   Input: `VerPos` (vec3), `VerClr` (vec3, object space coordinates).
        *   Output: `EntryPoint` (vec3, interpolated from `VerClr`), `ExitPointCoord` (vec4, `gl_Position`) [S2].
        *   Transformation: `gl_Position = uPMatrix * uMVMatrix * vec4(VerPos, 1.0)` [S3].
    *   Execute the **Raycast Fragment Shader**:
        *   Input: `EntryPoint` (interpolated front-face vertex color/position), `ExitPointCoord` (interpolated clip-space position) [S2].
        *   **Retrieve Exit Point:** Sample the back-face texture using screen coordinates normalized by `ScreenSize`:
            $$ \text{exitPoint} = \text{texture}(uBackCoord, \frac{\text{gl\_FragCoord.st}}{\text{ScreenSize}}).xyz $$
            *   *Pitfall:* `ExitPointCoord` is in clip-space. Do not perform perspective division manually. Use `gl_FragCoord` directly as it corresponds to the rasterized position [S2].
        *   **Check Validity:** If `EntryPoint == exitPoint` (or if the back-face texture lookup returns invalid/no-hit data), discard the fragment and render the background color (e.g., white with alpha 0) [S2].
        *   **Compute Ray Direction:**
            $$ \text{dir} = \text{exitPoint} - \text{EntryPoint} $$
            $$ \text{len} = \|\text{dir}\| $$
            $$ \text{deltaDir} = \text{normalize}(\text{dir}) \times \text{StepSize} $$
        *   **Ray Marching Loop:**
            Initialize `voxelCoord = EntryPoint`, `colorAcum = vec4(0.0)`, `alphaAcum = 0.0`, `lengthAcum = 0.0` [S2].
            For `i` from 0 to `MaxIterations` (e.g., 1600):
            1.  Sample volume: `intensity = texture(uVolData, voxelCoord).x` [S2].
            2.  Apply transfer function to get `colorSample` and `alphaSample` [S2].
            3.  Composite:
                $$ \text{colorAcum} += \text{colorSample} \times (1.0 - \text{alphaAcum}) $$
                $$ \text{alphaAcum} += \text{alphaSample} \times (1.0 - \text{alphaAcum}) $$
            4.  Update position: `voxelCoord += deltaDir` [S2].
            5.  Update length: `lengthAcum += length(deltaDir)` [S2].
            6.  **Termination Conditions:**
                *   If `lengthAcum >= len`, break [S2].
                *   If `alphaAcum >= 1.0`, clamp `alphaAcum` to 1.0 and break [S2].
        *   Output `FragColor = colorAcum` [S2].

**Pseudocode:**

```python
# Pass 1: Back-Face Capture
def pass1_backface_capture(gl, frame_buffer, cube, back_face_shader, mv_matrix, p_matrix):
    gl.bind_framebuffer(gl.FRAMEBUFFER, frame_buffer)
    gl.clear_color(0.0, 0.0, 0.0, 0.0)
    gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT)
    
    gl.enable(gl.DEPTH_TEST)
    gl.depth_func(gl.GEQUAL) # Capture farthest (back) face
    
    gl.use_program(back_face_shader)
    back_face_shader.set_uniform("uMVMatrix", mv_matrix)
    back_face_shader.set_uniform("uPMatrix", p_matrix)
    
    # Cull front faces to render only back faces
    gl.cull_face(gl.FRONT) 
    gl.enable(gl.CULL_FACE)
    
    gl.draw_elements(gl.TRIANGLES, cube.index_count, gl.UNSIGNED_SHORT, 0)
    
    gl.disable(gl.CULL_FACE)
    gl.bind_framebuffer(gl.FRAMEBUFFER, None)

# Pass 2: Raycasting
def pass2_ray_casting(gl, screen_buffer, cube, raycast_shader, mv_matrix, p_matrix, 
                      back_face_texture, volume_texture, step_size, screen_size):
    gl.bind_framebuffer(gl.FRAMEBUFFER, screen_buffer)
    gl.clear_color(1.0, 1.0, 1.0, 0.0) # White background
    gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT)
    
    gl.enable(gl.DEPTH_TEST)
    gl.depth_func(gl.LEQUAL)
    
    gl.use_program(raycast_shader)
    raycast_shader.set_uniform("uMVMatrix", mv_matrix)
    raycast_shader.set_uniform("uPMatrix", p_matrix)
    raycast_shader.set_uniform("StepSize", step_size)
    raycast_shader.set_uniform("ScreenSize", screen_size)
    
    # Bind textures
    gl.active_texture(gl.TEXTURE0)
    gl.bind_texture(gl.TEXTURE_2D, back_face_texture)
    raycast_shader.set_sampler("uBackCoord", 0)
    
    gl.active_texture(gl.TEXTURE1)
    gl.bind_texture(gl.TEXTURE_3D, volume_texture)
    raycast_shader.set_sampler("uVolData", 1)
    
    # Render front faces (default cull back faces)
    gl.cull_face(gl.BACK)
    gl.enable(gl.CULL_FACE)
    
    gl.draw_elements(gl.TRIANGLES, cube.index_count, gl.UNSIGNED_SHORT, 0)
    
    gl.disable(gl.CULL_FACE)
```

**Vertex Shader (Back-Face Pass):**
```glsl
#version 400
layout(location = 0) in vec3 VerPos;
layout(location = 1) in vec3 VerClr; // Object space coordinates

uniform mat4 uMVMatrix;
uniform mat4 uPMatrix;

out vec3 EntryPoint;
out vec4 ExitPointCoord;

void main() {
    EntryPoint = VerClr; // Pass object space position as color
    ExitPointCoord = uPMatrix * uMVMatrix * vec4(VerPos, 1.0);
    gl_Position = ExitPointCoord;
}
```

**Fragment Shader (Back-Face Pass):**
```glsl
#version 400
in vec3 EntryPoint;
out vec4 FragColor;

void main() {
    FragColor = vec4(EntryPoint, 1.0);
}
```

```glsl
#version 400

uniform mat4 uMVMatrix;
uniform mat4 uPMatrix;

out vec3 EntryPoint;
```

**Fragment Shader (Raycast Pass):**
```glsl
#version 400
in vec3 EntryPoint;
in vec4 ExitPointCoord;

uniform sampler2D uBackCoord;
uniform sampler3D uVolData;
uniform vec2 ScreenSize;
uniform float StepSize;

out vec4 FragColor;

void main() {
    // Retrieve exit point from back-face texture
    // Note: gl_FragCoord is in window coordinates, normalize by ScreenSize
    vec3 exitPoint = texture(uBackCoord, gl_FragCoord.xy / ScreenSize).xyz;
    
    // If entry and exit are the same, the ray missed the volume or hit an edge
    if (EntryPoint == exitPoint) {
        discard;
    }
    
    vec3 dir = exitPoint - EntryPoint;
    float len = length(dir);
    vec3 deltaDir = normalize(dir) * StepSize;
    
    vec3 voxelCoord = EntryPoint;
    vec4 colorAcum = vec4(0.0);
    float alphaAcum = 0.0;
    float lengthAcum = 0.0;
    
    // Max iterations to prevent infinite loops
    const int MaxIterations = 1600;
    
    for (int i = 0; i < MaxIterations; i++) {
        float intensity = texture(uVolData, voxelCoord).x;
        
        // Apply transfer function (simplified)
        vec4 colorSample = vec4(intensity, intensity, intensity, intensity);
        float alphaSample = intensity;
        
        // Alpha blending
        colorAcum += colorSample * (1.0 - alphaAcum);
        alphaAcum += alphaSample * (1.0 - alphaAcum);
        
        voxelCoord += deltaDir;
        lengthAcum += length(deltaDir);
        
        // Termination conditions
        if (lengthAcum >= len) break;
        if (alphaAcum >= 1.0) {
            alphaAcum = 1.0;
            break;
        }
    }
    
    FragColor = colorAcum;
}
```

## Subtopics

### [Volume Raycasting with MRT Endpoints](1584-volume-raycasting-with-mrt-endpoints.md)
A technique to obtain ray start and stop positions for volume raycasting by rendering a cube into two floating-point RGB surfaces using a fragment shader that writes object-space coordinates. Front faces go into one attachment, back faces into the other [1584-volume-raycasting-with-mrt-endpoints.md]. This variant uses Multiple Render Targets (MRT) to capture both entry and exit points simultaneously in a single pass, whereas the standard back-face culling method uses two passes (or a depth buffer trick) to derive one point from the back-face and the other from the front-face interpolation. Choose this when single-pass initialization is required and MRT support is available.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels, plus the cost of ray marching proportional to the number of samples per ray. The method adds a constant overhead of two draw calls (Pass 1 and Pass 2) compared to analytical intersection which is $O(1)$ per ray but requires CPU-side calculation or complex shader math.
*   **Memory Complexity:** $O(W \times H)$ for the 2D back-face texture, where $W$ and $H$ are screen dimensions. The volume data texture is $O(V)$ where $V$ is the volume resolution.
*   **Measured Performance:** Performance depends heavily on the efficiency of the depth buffer write in Pass 1 and the texture lookup in Pass 2. On hardware with fast depth testing and texture sampling, this method can be faster than analytical ray-cube intersection if the intersection logic is complex or if the ray marching loop is short. However, it requires two full-screen passes.
*   **Strengths:**
    *   Avoids analytical ray-cube intersection calculations in the fragment shader [S1].
    *   Naturally handles perspective projection without manual division [S2].
    *   Simple to implement using standard OpenGL/Direct3D pipelines [S3].
*   **Limitations:**
    *   Requires two passes, doubling the draw call overhead for bounding box rendering [S2].
    *   Precision issues may arise if the depth buffer resolution is insufficient for thin volumes or distant objects [S3].
    *   Coordinate system mismatches (clip-space vs NDC) can lead to incorrect exit point retrieval if not handled carefully [S2].
    *   Requires floating-point texture support for volume data in some environments (e.g., WebGL) [S3].
*   **When to use:** Suitable for real-time volume rendering where the bounding box is convex (e.g., a cube) and the camera is outside the volume. It is less suitable for non-convex volumes or when the camera is inside the volume, as the back-face culling logic for entry/exit may need inversion or additional handling.
*   **When not to use:** For non-convex volumes where analytical or hierarchical traversal is more appropriate, or when single-pass initialization is strictly required and MRT is not available.

## Background
The method originated as an optimization in GPU-based volume rendering to replace CPU-side or complex shader-side ray-cube intersection calculations with hardware-accelerated rasterization and depth testing. It leverages the fact that rendering the back faces of a bounding box to a depth buffer (with `GEQUAL` depth function) effectively records the entry depth of rays into the volume. The technique is documented in various unofficial repositories and tutorials focusing on WebGL and GLSL volume rendering [S1, S2, S3]. It is a variant of hierarchical traversal methods that use coarse meshes, specifically simplifying the entry/exit determination for a cubic bounding box [987-coarse-mesh-traversal-with-dual-ray-culling.md].
