# 3D Bresenham Voxel Traversal

Also called: Bresenham Line Drawing, Bresenham's Line Algorithm for Voxel Traversal, HDDA Voxel Stepping, HDDA::step, Half-Vector DDA step, ligneVoxels1, ligneVoxels2

## Overview

3D Bresenham Voxel Traversal is a discrete line algorithm used to determine the sequence of integer voxel coordinates intersected by a line segment in a 3D grid [S4, unofficial]. It iterates along the dominant axis and updates the other two axes based on accumulated error terms [S4, unofficial]. Unlike continuous DDA methods that guarantee every voxel the ray physically passes through is visited, Bresenham-based traversal may skip blocks where the ray does not get close enough to the block center, making it faster but potentially incomplete for volume rendering [S1, unofficial]. It is implemented as a stepping logic within DDA structures [S3, unofficial].

## How it works

### Inputs and Outputs

**Inputs:**
*   Ray origin $(x_i, y_i, z_i)$ and end point $(x_f, y_f, z_f)$ in continuous space, or equivalently, a starting voxel index and a direction vector [S4, unofficial].
*   Grid parameters: voxel size and grid offset [S1, unofficial].
*   Maximum traversal time or cell limit (optional, for bounded traversal) [S1, unofficial].

**Outputs:**
*   A sequence of integer voxel coordinates $(x, y, z)$ representing the voxels intersected by the line [S4, unofficial].
*   In DDA implementations, the updated state (current time $t$, next intersection times, voxel indices) after each step [S3, unofficial].

### Data Structures

The method can be implemented using two primary approaches: the classic error-accumulator loop [S4, unofficial] or the distance-based stepping state [S1, unofficial][S3, unofficial].

**1. Classic Error-Accumulator State [S4, unofficial]:**
*   `x, y, z`: Current integer voxel coordinates.
*   `dx, dy, dz`: Absolute differences in coordinates ($|x_f - x_i|$, etc.).
*   `xinc, yinc, zinc`: Step directions ($1$ if $x_f > x_i$, else $-1$).
*   `c1, c2`: Error accumulators for the non-dominant axes.

**2. DDA Stepping State [S1, unofficial][S3, unofficial]:**
*   `index` (`Vec3i`): Current voxel coordinates.
*   `pos` (`Vec3f`): Ray origin.
*   `dir` (`Vec3f`): Normalized ray direction.
*   `size` (`Vec3f`): Voxel dimensions.
*   `off` (`Vec3f`): Grid offset.
*   `delta` (`Vec3f`): Distance to next grid boundary per axis, computed as `size / dir`.
*   `sign` (`Vec3i`): Direction of traversal per axis ($1, -1, 0$).
*   `max` (`Vec3f`): Distance to next grid boundary from current position.
*   `mT0` (`RealT`): Current time parameter along the ray.
*   `mT1` (`RealT`): Maximum time parameter (ray end).
*   `mNext` (`Vec3T`): Array storing the time parameters for the next intersection along each axis.
*   `mDelta` (`Vec3T`): Array storing the time step between consecutive voxel intersections along each axis.
*   `mStep` (`CoordT`): Array storing the voxel index increment ($+1$ or $-1$) along each axis.
*   `plotted` (`int`): Count of plotted cells.
*   `limit` (`int`): Max cells to plot.

### Numbered Steps

The algorithm proceeds differently depending on the implementation variant.

#### Variant A: Dominant Axis Error Accumulation [S4, unofficial]

1.  **Initialize:** Set current voxel $(x, y, z) = (x_i, y_i, z_i)$ [S4, unofficial]. Compute differences $dx = |x_f - x_i|$, $dy = |y_f - y_i|$, $dz = |z_f - z_i|$ [S4, unofficial]. Determine step directions: $xinc = 1$ if $x_f > x_i$ else $-1$, similarly for $yinc, zinc$ [S4, unofficial].
2.  **Process Start:** Render or process the starting voxel $(x, y, z)$ [S4, unofficial].
3.  **Determine Dominant Axis:** Identify the maximum of $dx, dy, dz$ [S4, unofficial].
4.  **Iterate along Dominant Axis:**
    *   **If $dx$ is max:** Initialize $c1 = dx/2, c2 = dx/2$ [S4, unofficial]. Loop $i$ from $1$ to $dx$:
        *   Increment $x$ by $xinc$ [S4, unofficial].
        *   Add $dy$ to $c1$. If $c1 \ge dx$, subtract $dx$ from $c1$ and increment $y$ by $yinc$ [S4, unofficial].
        *   Add $dz$ to $c2$. If $c2 \ge dx$, subtract $dx$ from $c2$ and increment $z$ by $zinc$ [S4, unofficial].
        *   Process voxel $(x, y, z)$ [S4, unofficial].
    *   **If $dy$ is max:** Initialize $c1 = dy/2, c2 = dy/2$ [S4, unofficial]. Loop $i$ from $1$ to $dy$:
        *   Increment $y$ by $yinc$ [S4, unofficial].
        *   Add $dx$ to $c1$. If $c1 \ge dy$, subtract $dy$ from $c1$ and increment $x$ by $xinc$ [S4, unofficial].
        *   Add $dz$ to $c2$. If $c2 \ge dy$, subtract $dy$ from $c2$ and increment $z$ by $zinc$ [S4, unofficial].
        *   Process voxel $(x, y, z)$ [S4, unofficial].
    *   **If $dz$ is max:** Initialize $c1 = dz/2, c2 = dz/2$ [S4, unofficial]. Loop $i$ from $1$ to $dz$:
        *   Increment $z$ by $zinc$ [S4, unofficial].
        *   Add $dy$ to $c1$. If $c1 \ge dz$, subtract $dz$ from $c1$ and increment $y$ by $yinc$ [S4, unofficial].
        *   Add $dx$ to $c2$. If $c2 \ge dz$, subtract $dz$ from $c2$ and increment $x$ by $xinc$ [S4, unofficial].
        *   Process voxel $(x, y, z)$ [S4, unofficial].

#### Variant B: DDA Distance-Based Stepping [S1, unofficial][S3, unofficial]

1.  **Initialization (`plot`/`init`):**
    *   Set `limit` (max cells) and `pos` (ray origin) [S1, unofficial].
    *   Normalize `dir` (ray direction) [S1, unofficial].
    *   Compute `delta` = `size` / `dir` (element-wise) [S1, unofficial].
    *   Compute `sign`: $1$ if `dir > 0`, $-1$ if `dir < 0`, $0$ otherwise [S1, unofficial].
    *   Compute initial `index`: $\lfloor (pos - off) / size \rfloor$ for each axis [S1, unofficial].
    *   Compute initial `max`:
        *   If `sign > 0`: `max` = $(index \times size + off + size - pos)$ [S1, unofficial].
        *   If `sign < 0`: `max` = $(pos - (index \times size + off))$ [S1, unofficial].
        *   Divide `max` by `dir` to get time distances [S1, unofficial].
    *   Initialize `mT0` to the ray start time, `mT1` to ray end time [S3, unofficial].
    *   Initialize `mNext` with the initial `max` values [S3, unofficial].
    *   Initialize `mDelta` with `delta` values [S3, unofficial].
    *   Initialize `mStep` with `sign` values [S3, unofficial].
    *   Set `plotted = 0` [S1, unofficial].
2.  **Stepping (`step`/`next`):**
    *   Find the axis with the minimum `mNext` value: `axis = MinIndex(mNext)` [S3, unofficial].
    *   **Precision Correction (Optional):** If `ENFORCE_FORWARD_STEPPING` is active and `mNext[axis] <= mT0`, apply correction:
        $$mNext[axis] += mT0 - 0.999999f \times mNext[axis] + 1.0e-6f$$ [S3, unofficial].
    *   **Update State:**
        *   $mT0 = mNext[axis]$ [S3, unofficial].
        *   $mNext[axis] += mDelta[axis]$ [S3, unofficial].
        *   $mVoxel[axis] += mStep[axis]$ [S3, unofficial].
    *   **Check Bounds:** Return true if $mT0 \le mT1$ [S3, unofficial].
    *   **Alternative Logic [S1, unofficial]:** If `plotted > 0`, compare `mx = sign.x * max.x`, `my = sign.y * max.y`, `mz = sign.z * max.z`. Increment the index corresponding to the smallest value and add the corresponding `delta` to that axis's `max` [S1, unofficial].

### Formulas

*   **Delta Calculation:** $\Delta_i = \frac{size_i}{dir_i}$ for $i \in \{x, y, z\}$ [S1, unofficial].
*   **Initial Boundary Distance:**
    $$max_i = \begin{cases} (index_i \cdot size_i + off_i + size_i - pos_i) / dir_i & \text{if } dir_i > 0 \\ (pos_i - (index_i \cdot size_i + off_i)) / dir_i & \text{if } dir_i < 0 \end{cases}$$ [S1, unofficial].
*   **Precision Correction:**
    $$mNext[axis] += mT0 - 0.999999f \cdot mNext[axis] + 1.0e-6f$$ [S3, unofficial].
*   **Error Accumulator Update (Variant A):**
    If $c_k \ge D_{dom}$, then $c_k \leftarrow c_k - D_{dom}$ and increment the corresponding axis [S4, unofficial].

### Parameters

*   **ENFORCE_FORWARD_STEPPING:** A preprocessor flag (default often 1 in DDA) that enables precision correction logic to prevent infinite loops or incorrect stepping when $mNext[axis] \le mT0$ [S3, unofficial].
*   **Voxel Size:** Typically 1.0 in normalized coordinates, but can be arbitrary [S1, unofficial].
*   **Grid Offset:** Typically 0.0 [S1, unofficial].

### Edge Cases and Pitfalls

*   **Missing Voxels:** Bresenham's algorithm does not consider every block the ray passes through; it skips blocks where the ray does not get close enough to the block center [S1, unofficial]. For example, a block barely grazed by the ray may be missed [S1, unofficial]. This makes it unsuitable for applications requiring strict topological connectivity of visited voxels [S1, unofficial].
*   **Precision Issues:** Floating-point inaccuracies can cause $mNext[axis]$ to be less than or equal to $mT0$, leading to infinite loops or incorrect stepping [S3, unofficial]. The `ENFORCE_FORWARD_STEPPING` correction handles this [S3, unofficial].
*   **Zero Direction Components:** If a direction component is 0, the sign is 0, and the corresponding axis does not change [S1, unofficial]. The delta calculation involves division by zero, requiring special handling (e.g., setting delta to infinity or skipping that axis in comparisons) [G].

```python
def bresenham_3d(xi, yi, zi, xf, yf, zf):
    x, y, z = xi, yi, zi
    dx = abs(xf - xi)
    dy = abs(yf - yi)
    dz = abs(zf - zi)
    
    xinc = 1 if xf > xi else -1
    yinc = 1 if yf > yi else -1
    zinc = 1 if zf > zi else -1
    
    process_voxel(x, y, z)
    
    if dx >= dy and dx >= dz:
        c1 = c2 = dx / 2
        for _ in range(dx):
            x += xinc
            c1 += dy
            if c1 >= dx:
                c1 -= dx
                y += yinc
            c2 += dz
            if c2 >= dx:
                c2 -= dx
                z += zinc
            process_voxel(x, y, z)
    elif dy >= dx and dy >= dz:
        c1 = c2 = dy / 2
        for _ in range(dy):
            y += yinc
            c1 += dx
            if c1 >= dy:
                c1 -= dy
                x += xinc
            c2 += dz
            if c2 >= dy:
                c2 -= dy
                z += zinc
            process_voxel(x, y, z)
    else:
        c1 = c2 = dz / 2
        for _ in range(dz):
            z += zinc
            c1 += dy
            if c1 >= dz:
                c1 -= dz
                y += yinc
            c2 += dx
            if c2 >= dz:
                c2 -= dz
                x += xinc
            process_voxel(x, y, z)

# Variant B: DDA Stepping [S1, unofficial][S3, unofficial]
class DDA:
    def __init__(self, pos, dir, size, off):
        self.pos = pos
        self.dir = norm(dir)
        self.size = size
        self.off = off
        self.delta = [s / d for s, d in zip(size, self.dir)]
        self.sign = [1 if d > 0 else (-1 if d < 0 else 0) for d in self.dir]
        self.index = [math.floor((p - o) / s) for p, o, s in zip(pos, off, size)]
        self.max = [0.0, 0.0, 0.0]
        self.plotted = 0
        self.limit = float('inf')
        self.init_max()
        
    def init_max(self):
        for i in range(3):
            if self.sign[i] > 0:
                self.max[i] = (self.index[i] * self.size[i] + self.off[i] + self.size[i] - self.pos[i]) / self.dir[i]
            else:
                self.max[i] = (self.pos[i] - (self.index[i] * self.size[i] + self.off[i])) / self.dir[i]
                
    def step(self, t0, t1):
        axis = argmin(self.max)
        
        if self.max[axis] <= t0:
            self.max[axis] += t0 - 0.999999 * self.max[axis] + 1.0e-6
            
        t0 = self.max[axis]
        self.max[axis] += self.delta[axis]
        self.index[axis] += self.sign[axis]
        
        self.plotted += 1
        return t0 <= t1 and self.plotted <= self.limit
```

## Operating characteristics

*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels visited [S4, unofficial]. The number of steps is proportional to the length of the ray in voxel units, specifically $\max(|dx|, |dy|, |dz|)$ in the classic implementation [S4, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space for the classic implementation [S4, unofficial]. The DDA state requires a small fixed-size array for each axis [S1, unofficial].
*   **Performance:** Generally faster than continuous DDA due to integer arithmetic (in the classic variant) or simpler comparisons (in DDA) [S4, unofficial]. However, it may visit fewer voxels, which can be a benefit or a drawback depending on the application [S1, unofficial].
*   **Strengths:** Simple implementation, low memory overhead, fast execution [S4, unofficial].
*   **Limitations:** May miss voxels that the ray barely intersects, making it unsuitable for applications requiring strict ray-voxel intersection guarantees [S1, unofficial]. Precision issues require careful handling [S3, unofficial].
*   **When to use:** When performance is critical and missing a few boundary voxels is acceptable (e.g., simple collision detection in voxel games) [S1, unofficial].
*   **When not to use:** When strict topological connectivity of visited voxels is required (e.g., accurate volume rendering, medical imaging) [S1, unofficial].

## Background

The algorithm originates from Bresenham's line drawing algorithm, adapted for 3D voxel traversal [S4, unofficial]. It is used in voxel-based games for block selection and raycasting [S1, unofficial]. The DDA implementation is part of the OpenVDB/nanovdb library, used for efficient traversal of sparse volumetric data [S3, unofficial]. The 3D extension with error accumulators is described in various computer graphics tutorials [S4, unofficial].
