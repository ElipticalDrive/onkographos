# Bundle Parallelisation

Also called: GPU Integration Optimization, Ray Compaction and Sorting Optimization

## Overview
Bundle parallelisation distributes the processing of ray bundles across multiple processing elements to accelerate coherent grid traversal. It solves the performance bottleneck of serial ray integration by exploiting the spatial coherence of rays within a bundle. Unlike slice parallelisation, which requires complex index tables to map bundles to slices, bundle parallelisation processes bundles directly, though it may result in redundant block fetches from neighbouring bundles [S1, unofficial].

## How it works
**Inputs:** A set of ray bundles, each containing a group of rays sharing a common traversal path or depth range.
**Outputs:** Rendered image pixels with accumulated color and opacity.

**Data Structures:**
*   **Bundle:** A collection of rays.
*   **Shadow Map:** Depth buffer used for visibility prefiltering.
*   **Partial Sum Tree:** Stores accumulated transmittance and color for a slice. Stored in global memory due to size constraints [S2].
*   **Thread Blocks:** Allocated per slice.

**Steps:**
1.  **Rectification:** Perform a data-parallel operation on the depth and shadow maps. This prepares the data for visibility queries. One thread is assigned per output pixel [S2].
2.  **Sorting and Prefiltering:** Combine visibility prefiltering and sorting into a single kernel. This step coalesces groups of 4 rays based on their depth information from the shadow map. A modified GPU radix sort is used to coalesce rays with similar depths as it walks over the input shadow map [S2].
3.  **Integration:**
    *   Allocate one thread block of 32 threads per slice [S2].
    *   Assign one thread per slice for the integration phase because partial sum trees are too large to fit into shared memory [S2].
    *   Store the partial sum trees in global memory [S2].
    *   Execute the inner loop using the `while-if-if` strategy (UPDATE-TREE and QUERY-TREE) to minimize instruction divergence. This ensures that at least half the threads in a warp perform useful work [S2].

**Pseudocode:**
```python
def bundle_parallelisation(bundles, shadow_map, image_width, image_height):
    # Step 1: Rectification
    # Data-parallel operation on depth and shadow maps
    # One thread per output pixel
    rectified_shadow_map = rectify_shadow_map(shadow_map, image_width, image_height)

    # Step 2: Sorting and Prefiltering
    # Combine visibility prefiltering and sorting
    # Coalesce groups of 4 rays
    sorted_bundles = sort_and_prefilter(bundles, rectified_shadow_map)

    # Step 3: Integration
    # Allocate one block of 32 threads per slice
    # Assign one thread per slice
    # Store trees in global memory
    for slice_index in range(num_slices):
        # Use while-if-if strategy to reduce divergence
        # UPDATE-TREE and QUERY-TREE operations
        integrate_slice(slice_index, sorted_bundles, global_memory_trees)

    return rendered_image

def rectify_shadow_map(shadow_map, width, height):
    # Straightforward data-parallel operation
    # One thread per output pixel
    result = empty_array(width, height)
    for y in range(height):
        for x in range(width):
            result[y, x] = process_shadow(shadow_map[y, x])
    return result

def sort_and_prefilter(bundles, shadow_map):
    # Combine visibility prefiltering and sorting
    # Coalesce groups of 4 rays
    # Modified GPU radix sort
    sorted_bundles = []
    for bundle in bundles:
        # Coalesce rays with similar depths
        coalesced_bundle = coalesce_rays(bundle, shadow_map)
        sorted_bundles.append(coalesced_bundle)
    return sorted_bundles

def integrate_slice(slice_index, bundles, global_trees):
    # One thread per slice
    # Partial sum trees in global memory
    tree = global_trees[slice_index]
    for bundle in bundles:
        # while-if-if strategy
        while bundle.has_rays():
            if bundle.can_update_tree():
                update_tree(tree, bundle)
            if bundle.can_query_tree():
                query_tree(tree, bundle)
```

**Parameters:**
*   **Block Size:** 32 threads per slice [S2].
*   **Ray Grouping:** Groups of 4 rays coalesced during sorting [S2].

**Edge Cases and Pitfalls:**
*   **Redundant Fetches:** Some blocks may be fetched multiple times from neighbouring bundles [S1, unofficial].
*   **Memory Constraints:** Partial sum trees are too large for shared memory on current hardware, necessitating global memory storage [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Global memory usage for partial sum trees due to size constraints [S2].
*   **Performance:** The method is described as "trivial" to implement on CPU with OpenMP (1 line of code) [S1, unofficial]. On GPU, it uses specific optimizations like the `while-if-if` strategy to ensure at least half the threads in a warp do useful work [S2].
*   **Strengths:** Efficient parallelisation of ray bundles; reduced instruction divergence in integration [S2].
*   **Limitations:** Potential for redundant block fetches from neighbouring bundles [S1, unofficial].

## Background
Bundle parallelisation is a technique used in coherent grid traversal for volume rendering. It was implemented as part of a hierarchical volumetric shadow algorithm for single scattering [S2]. The approach was also noted in presentations on coherent grid traversal algorithms [S1, unofficial].
