# Binary Grid Ray Traversal (Single Voxel Step)

Also called: AABB traversal step

## Overview
This method advances a ray through a single voxel in a binary occupancy grid by determining the exit axis, updating the voxel index, and checking for grid boundary overflow. It is the core iterative step of the Binary Grid Ray Traversal algorithm, following initialization. Unlike continuous volume rendering which samples density, this method operates on discrete binary occupancy, making it suitable for sparse or binary voxel representations where only presence/absence matters. It differs from parent methods by performing the actual index update and boundary check rather than just setting up initial parameters.

## How it works
**Inputs and Outputs:**
*   `current_index`: A 3D vector `(x, y, z)` representing the current voxel coordinates.
*   `tdist`: A 3D vector `(x, y, z)` representing the distance from the ray origin to the next voxel boundary along each axis.
*   `delta`: A 3D vector `(x, y, z)` representing the distance between adjacent voxel boundaries along each axis (pre-computed by initialization).
*   `step_index`: A 3D vector `(x, y, z)` containing `+1` or `-1` indicating the traversal direction along each axis.
*   `overflow_index`: A 3D vector `(x, y, z)` representing the grid dimensions (or boundary indices) where traversal must stop.
*   **Output:** A boolean indicating whether the ray remains within the valid grid bounds (`true`) or has exited (`false`).

**Data Structures:**
The algorithm assumes `current_index`, `tdist`, `delta`, `step_index`, and `overflow_index` are 3-component vectors (e.g., `vec3` in GLSL or `numpy.array` in Python). No specific bit-packing is required for the traversal step itself, as it operates on floating-point distances and integer indices.

**Steps:**
1.  **Determine Exit Axis:** Compare `tdist.x`, `tdist.y`, and `tdist.z` to find the minimum distance to the next boundary.
    *   If `tdist.x < tdist.y` and `tdist.x < tdist.z`, the ray exits through the X-axis.
    *   Else, if `tdist.y < tdist.z`, the ray exits through the Y-axis.
    *   Else, the ray exits through the Z-axis.
2.  **Update Index and Distance:** Based on the selected axis, update the `current_index` and `tdist`.
    *   **X-axis:**
        *   `current_index.x += step_index.x`
        *   `tdist.x += delta.x`
    *   **Y-axis:**
        *   `current_index.y += step_index.y`
        *   `tdist.y += delta.y`
    *   **Z-axis:**
        *   `current_index.z += step_index.z`
        *   `tdist.z += delta.z`
3.  **Check Overflow:** Verify if the updated index has exceeded the grid boundaries.
    *   If the updated index component equals the corresponding `overflow_index` component, the ray has exited the valid grid. Return `false`.
    *   Otherwise, return `true`.

**Pseudocode:**
```python
def single_voxel_step(current_index, tdist, delta, step_index, overflow_index):
    """
    Advances ray through one voxel in a binary grid.
    
    Args:
        current_index: vec3, current voxel coordinates
        tdist: vec3, distance to next boundary on each axis
        delta: vec3, distance between adjacent boundaries on each axis
        step_index: vec3, direction (+1 or -1) for each axis
        overflow_index: vec3, grid boundary indices
        
    Returns:
        bool: True if ray is still within grid, False if out of bounds
    """
    # Determine which axis has the minimum distance to the next boundary
    if tdist.x < tdist.y and tdist.x < tdist.z:
        # Exit through X-axis
        current_index.x += step_index.x
        tdist.x += delta.x
        if current_index.x == overflow_index.x:
            return False
    elif tdist.y < tdist.z:
        # Exit through Y-axis
        current_index.y += step_index.y
        tdist.y += delta.y
        if current_index.y == overflow_index.y:
            return False
    else:
        # Exit through Z-axis
        current_index.z += step_index.z
        tdist.z += delta.z
        if current_index.z == overflow_index.z:
            return False
            
    return True
```

**Parameters and Edge Cases:**
*   **Precision:** Floating-point comparisons (`<`) are used. If `tdist` values are equal, the order of checks (X, then Y, then Z) determines the axis. This is a deterministic tie-breaking rule.
*   **Parallel Rays:** The parent initialization step handles rays parallel to axes by setting `delta` to 0 and `tdist` to `tmax`. This step assumes valid non-zero `delta` for the active axis, or that the ray has already terminated. If `delta` is 0 for the selected axis, `tdist` will not increase, potentially causing an infinite loop if not handled by the caller. However, the parent initialization ensures that for parallel rays, the traversal logic is adjusted or terminated.
*   **Overflow:** The check `current_index == overflow_index` assumes `overflow_index` represents the exclusive upper bound (or lower bound for negative directions). The exact meaning of `overflow_index` depends on the initialization step, but typically it is the grid dimension size for positive traversal.

## Operating characteristics
*   **Time Complexity:** O(1) per voxel step. The comparison and update operations are constant time.
*   **Memory Complexity:** O(1) auxiliary space. No additional data structures are allocated.
*   **Strengths:** Extremely fast per-voxel update. Minimal branching compared to more complex traversal methods. Suitable for binary occupancy grids where density integration is not required.
*   **Limitations:** Only advances one voxel at a time. Requires careful handling of parallel rays and boundary conditions, which are delegated to the initialization step. Not suitable for continuous volume rendering without additional sampling logic.
*   **When to Use:** When rendering binary occupancy grids (e.g., sparse voxel octrees converted to uniform grids, or simple binary masks) where only the presence of geometry matters.
*   **When Not to Use:** For continuous volume rendering requiring density integration, or for non-uniform grids where `delta` varies per voxel.

## Background
This method is part of the Digital Differential Analyzer (DDA) ray traversal technique adapted for binary grids. It is commonly used in GPU-based volume rendering and ray marching for binary occupancy data. The specific implementation details are derived from the CNC (Compressed Neural Fields) project, which uses binary voxel representations for efficient storage and traversal [S1, unofficial].
