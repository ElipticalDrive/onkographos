# Voxel Polygon Rendering
## Overview
Voxel Polygon Rendering is a real-time technique that projects a 2D voxel height map onto the screen as vertical bars, solving the problem of rendering high-detail terrain at constant speed without traditional 6DOF polygon operations [S1, unofficial]. It differs from its sibling [Voxel Raycasting with DDA and Vertical Stripe Rendering](2206-voxel-raycasting-with-dda-and-vertical-stripe-rendering.md) by using "voxel polygons" for local detail variation and an s-buffer (vertical c-buffer) to handle floating geometry, whereas the sibling relies on a simpler per-column depth buffer for stacking [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A voxel map (2D array storing height and color per location), camera parameters (limited to Y-axis rotation and small X-axis tilt), and a set of voxel polygons defining local geometry variations [S1, unofficial].
- **Output:** A rasterized screen image composed of vertical bars representing terrain heights, smoothed via bilinear filtering [S1, unofficial].

**Data Structures:**
1. **Voxel Map:** A 2D array where each cell stores a height value and a color value [S1, unofficial].
2. **Column Height Array (S-Buffer):** An array indexed by screen column, storing the current maximum height of the drawn bar in that column to clip subsequent bars and prevent overdraw [S1, unofficial].
3. **Voxel Polygon:** A data structure representing a "more or less" horizontal surface, storing a base height, a local height offset, and a depth value for floating polygons (top and bottom sides) [S1, unofficial].

**Steps:**
1. **Map Pixels to Voxel Space:** For each screen pixel, determine its corresponding location on the voxel map based on the camera's Y-axis rotation and distance [S1, unofficial].
2. **Determine Height:** Retrieve the height from the voxel map at the mapped location and apply perspective correction so distant "mountains" appear smaller [S1, unofficial].
3. **Bilinear Filtering (Height):** Retrieve four adjacent voxels (texels) from the map and calculate the height of the single pixel-wide span by taking a weighted average of their heights [S1, unofficial].
4. **Bilinear Filtering (Color):** Average the colors of the four fetched voxels to smooth the terrain appearance [S1, unofficial].
5. **Render Close to Far:** Draw the screen from the bottom line (closest) up to the horizon (approximately halfway the screen) [S1, unofficial].
6. **Clip and Draw:** For each span, compare the calculated height against the value stored in the Column Height Array for that screen column; if the span is lower, clip it; if visible, draw the vertical bar and update the Column Height Array with the new height [S1, unofficial].
7. **Handle Floating Polygons:** For polygons not starting at the bottom screen line, use the s-buffer (vertical c-buffer) to manage their top and bottom boundaries, preventing overdraw and correctly stacking floating bars [S1, unofficial].
8. **Fill Horizon:** Fill the screen space above the horizon with a backdrop [S1, unofficial].
9. **Voxel Polygon Integration:** Cover the map with a blanket of polygons for the ground, add extra polygons for details (hills, structures), add the local polygon height to the base voxel height to reuse details at different elevations, and interpolate polygon heights fluently (similar to Gouraud shading) to construct smooth shapes like round hills with few polygons [S1, unofficial].

**Pseudocode:**
```python
def render_voxel_polygons(voxel_map, screen_width, screen_height, camera_y_rotation, camera_x_tilt, backdrop_color):
    # Initialize the vertical c-buffer (s-buffer) with minimum height
    # Screen coordinates: y=0 is bottom, y=screen_height is top
    column_heights = [0.0] * screen_width
    
    # Define horizon line (approx halfway)
    horizon_y = screen_height // 2
    
    # Iterate from bottom (close) to horizon (far)
    for y in range(screen_height - 1, horizon_y - 1, -1):
        for x in range(screen_width):
            # 1. Map screen pixel to voxel map location
            # [Comment] Standard inverse perspective projection for Y-rotation and small X-tilt
            # Returns floating-point coordinates (vx, vy) in the voxel map space
            vx, vy = map_screen_to_voxel(x, y, camera_y_rotation, camera_x_tilt)
            
            # 2. Retrieve 4 adjacent voxels for bilinear filtering
            # Clamp coordinates to map bounds
            vx0, vx1 = int(vx), min(int(vx) + 1, voxel_map.width - 1)
            vy0, vy1 = int(vy), min(int(vy) + 1, voxel_map.height - 1)
            
            h00, c00 = voxel_map.get(vx0, vy0)
            h10, c10 = voxel_map.get(vx1, vy0)
            h01, c01 = voxel_map.get(vx0, vy1)
            h11, c11 = voxel_map.get(vx1, vy1)
            
            # 3. Bilinear filter height
            fx = vx - vx0
            fy = vy - vy0
            
            height = lerp(lerp(h00, h10, fx), lerp(h01, h11, fx), fy)
            
            # 4. Perspective correction: scale height by distance so far mountains look smaller
            distance_factor = (screen_height - y) / screen_height
            perspective_height = height * distance_factor
            
            # 5. Bilinear filter color
            color = lerp(lerp(c00, c10, fx), lerp(c01, c11, fx), fy)
            
            # 6. Clip against column height
            current_col_height = column_heights[x]
            
            # If the new height is lower than what's already drawn, skip
            if perspective_height <= current_col_height:
                continue
            
            # 7. Draw the vertical bar (span)
            # [Comment] Standard rasterization step to write color to the frame buffer at (x, span_y)
            for span_y in range(int(current_col_height), int(perspective_height) + 1):
                draw_pixel(x, span_y, color)
            
            # Update column height buffer
            column_heights[x] = perspective_height

    # 8. Fill horizon with backdrop
    for y in range(horizon_y - 1, -1, -1):
        for x in range(screen_width):
            draw_pixel(x, y, backdrop_color)

def lerp(a, b, t):
    return a + t * (b - a)

# [Comment] The sources do not provide the exact projection or rasterization routines.
# map_screen_to_voxel(x, y, rot_y, tilt_x) computes (vx, vy) in voxel space.
# draw_pixel(x, y, color) writes the color to the frame buffer.
```

**Parameters:**
- **Rotation Constraint:** Y-axis rotation is allowed [S1, unofficial]. X-axis (up/down) tilt is limited to approximately 10 degrees; looking down by 45 degrees is not supported as voxel bars must remain perfectly vertical [S1, unofficial].
- **Tiling:** Pre-built tiles of voxels can be used to reduce memory usage, though square tiles may not be ideal for all terrain types [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Flat Floor Performance:** The worst-case performance occurs on a completely flat floor, where every column's height increases with each processed line, leading to significant clipping and update overhead per pixel [S1, unofficial].
- **Blockiness:** Without bilinear filtering, voxels appear blocky. Small details may flicker during camera movement [S1, unofficial].
- **Single Height Limitation:** Standard voxel maps store only one height per location [S1, unofficial]. Voxel polygons are required to handle floating geometry and multiple heights at the same map location [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Virtually constant speed regardless of scene detail, as it processes each screen pixel once [S1, unofficial]. However, worst-case performance degrades on flat surfaces due to frequent clipping and buffer updates [S1, unofficial].
- **Memory Complexity:** High memory usage for the voxel map [S1, unofficial]. Tiling can mitigate this, but large maps require significant RAM (e.g., 4MB for early implementations) [S1, unofficial].
- **Strengths:** Constant rendering speed, no need for 6DOF rotation matrices or clipping, high detail potential, smooth appearance via bilinear filtering [S1, unofficial].
- **Limitations:** Limited to Y-axis rotation (small X-axis tilt only), blocky appearance without filtering, flickering details, high memory requirements, difficulty handling floating geometry without an s-buffer [S1, unofficial].
- **When to Use:** Real-time terrain rendering where constant speed is critical and camera movement is restricted to horizontal rotation [S1, unofficial].
- **When Not to Use:** Scenes requiring full 6DOF camera movement, significant vertical viewing angles, or complex floating structures without the overhead of an s-buffer [S1, unofficial].

## Background
Voxel Polygon Rendering was introduced by Jacco Bikker (a.k.a. "THE PHANTOM") in a 1999 article on Flipcode [S1, unofficial]. It was developed as part of the "Focus engine" to allow for high-detail graphics with a natural look, leveraging voxel techniques to avoid traditional 3D polygon operations [S1, unofficial]. The technique addresses issues like blockiness and memory usage through bilinear filtering and tiling/polygons [S1, unofficial].
