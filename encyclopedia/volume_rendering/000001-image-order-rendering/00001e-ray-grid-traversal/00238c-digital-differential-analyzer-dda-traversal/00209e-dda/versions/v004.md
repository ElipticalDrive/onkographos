# DDA

Also called: DDA Algorithm, DDA Raycasting Algorithm, Delta Calculation Helper, Digital Differential Analyzer

## Overview

The Digital Differential Analyzer (DDA) is a grid traversal algorithm that determines the sequence of cells (voxels or tiles) intersected by a ray in a uniform, axis-aligned grid [S4, unofficial][S5, unofficial]. It solves the problem of efficiently stepping through a discrete spatial structure without performing expensive intersection tests or fixed-step ray marching, by calculating the parameterized distance ($t$) to the next grid boundary in each dimension and advancing along the axis with the smallest $t$ [S7, unofficial][S5, unofficial]. It sets itself apart from naive fixed-step marching by using boundary-crossing logic to guarantee no voxels are missed, and from hierarchical methods by operating directly on a flat uniform grid [S1, unofficial][S3, unofficial].

## How it works

**Inputs and Outputs**
*   **Input:** Ray origin $\mathbf{o}$ (vec3), ray direction $\mathbf{d}$ (vec3, not necessarily normalized), grid resolution/resolution bounds, and optionally a maximum traversal time/distance [S11, unofficial][S4, unofficial].
*   **Output:** A sequence of voxel indices $(i, j, k)$ visited by the ray, or a boolean hit status with hit coordinates [S3, unofficial][S6].

**Data Structures**
The core state for a 3D DDA traversal typically maintains the following fields [S3, unofficial][S8, unofficial]:
*   `pos`: Integer coordinates of the current voxel $(i, j, k)$ [S3, unofficial].
*   `step_dir`: Integer vector $(\pm 1, \pm 1, \pm 1)$ indicating the direction of movement along each axis [S3, unofficial].
*   `delta_dist`: Vector of absolute inverse direction components $|1/d_x|, |1/d_y|, |1/d_z|$ [S3, unofficial].
*   `side_dist`: Vector representing the remaining parameterized distance to the next grid boundary in each axis [S3, unofficial].

**Numbered Steps**

1.  **Initialization**:
    *   Compute the initial voxel index by flooring the ray origin: $\mathbf{pos} = \lfloor \mathbf{o} \rfloor$ [S3, unofficial][S4, unofficial].
    *   Determine the step direction for each axis: $\mathbf{step\_dir} = \text{sign}(\mathbf{d})$ [S3, unofficial].
    *   Compute the distance between grid lines along the ray for each axis (inverse direction magnitude): $\mathbf{delta\_dist} = |1/\mathbf{d}|$ [S3, unofficial].
    *   Calculate the initial distance to the next grid boundary for each axis. For axis $n$, if $d_n > 0$, the boundary is at $\mathbf{pos}_n + 1$; if $d_n < 0$, it is at $\mathbf{pos}_n$. The fractional distance is derived from the ray's position within the current cell [S4, unofficial][S7, unofficial].
        *   Formula: $\mathbf{side\_dist}_n = (\mathbf{step\_dir}_n \cdot (\mathbf{pos}_n - \mathbf{o}_n) + 0.5) \cdot \mathbf{delta\_dist}_n + 0.5 \cdot \mathbf{delta\_dist}_n$ [S3, unofficial].
        *   *Note*: Some implementations simplify this to $\mathbf{side\_dist}_n = \mathbf{delta\_dist}_n \cdot (\mathbf{step\_dir}_n \cdot (\mathbf{pos}_n - \mathbf{o}_n) + 0.5) + 0.5 \cdot \mathbf{delta\_dist}_n$ [S3, unofficial].
    *   Handle zero-direction components: If $d_n = 0$, set $\mathbf{side\_dist}_n = \infty$ and $\mathbf{step\_dir}_n = 0$ to prevent division by zero and infinite loops [S11, unofficial][S8, unofficial].

2.  **Stepping Loop**:
    *   While the ray is within bounds and has not hit a target:
        *   Identify the axis to step: Find the index $axis$ such that $\mathbf{side\_dist}_{axis}$ is the minimum among the three axes [S3, unofficial][S8, unofficial].
        *   Update the state for the selected axis:
            *   Increment the voxel coordinate: $\mathbf{pos}_{axis} \leftarrow \mathbf{pos}_{axis} + \mathbf{step\_dir}_{axis}$ [S3, unofficial].
            *   Advance the distance to the next boundary: $\mathbf{side\_dist}_{axis} \leftarrow \mathbf{side\_dist}_{axis} + \mathbf{delta\_dist}_{axis}$ [S3, unofficial].
        *   Query the grid at $\mathbf{pos}$ for occupancy or color [S3, unofficial].
        *   Check termination condition (e.g., hit detected, max distance exceeded) [S5, unofficial].

**Pseudocode**

```python
def dda_traverse(ray_origin, ray_direction, grid_bounds, callback):
    # 1. Initialization
    # Handle zero-direction components to avoid division by zero
    # If direction component is 0, set inverse to infinity
    inv_dir = vec3(
        1.0 / ray_direction.x if abs(ray_direction.x) > 1e-8 else float('inf'),
        1.0 / ray_direction.y if abs(ray_direction.y) > 1e-8 else float('inf'),
        1.0 / ray_direction.z if abs(ray_direction.z) > 1e-8 else float('inf')
    )
    
    # Step direction: 1 if moving positive, -1 if moving negative, 0 if static
    step_dir = vec3(
        1 if ray_direction.x >= 0 else -1,
        1 if ray_direction.y >= 0 else -1,
        1 if ray_direction.z >= 0 else -1
    )
    
    # Current voxel index (floor of origin)
    pos = vec3(floor(ray_origin.x), floor(ray_origin.y), floor(ray_origin.z))
    
    # Distance to next grid boundary
    # Formula: (step_dir * (pos - origin) + 0.5) * delta_dist + 0.5 * delta_dist
    # Simplified: (step_dir * (pos - origin) + 1.0) * delta_dist for positive direction logic
    # Using the specific formula from [S3, unofficial]:
    side_dist = (step_dir * (vec3(pos) - ray_origin) + (step_dir * 0.5) + 0.5) * abs(inv_dir)
    
    # Absolute inverse direction (delta_dist)
    delta_dist = abs(inv_dir)
    
    # 2. Stepping Loop
    while is_within_bounds(pos, grid_bounds):
        # Invoke callback for current voxel
        hit = callback(pos)
        if hit:
            return pos, hit
            
        # Find axis with minimum side_dist
        # mask[i] is true if side_dist[i] is the minimum (cyclic comparison)
        # x vs y,z; y vs z,x; z vs x,y
        mask = vec3(
            side_dist.x <= min(side_dist.y, side_dist.z),
            side_dist.y <= min(side_dist.z, side_dist.x),
            side_dist.z <= min(side_dist.x, side_dist.y)
        )
        
        # Update side_dist for the stepped axis/axes
        side_dist += mask * delta_dist
        
        # Update position for the stepped axis/axes
        pos += mask * step_dir
        
    return None, None
```

**Parameters**
*   `ray_origin`: 3D vector, the starting point of the ray [S4, unofficial].
*   `ray_direction`: 3D vector, the direction of the ray. Does not need to be normalized for the basic DDA logic, but normalization is often used for distance calculations [S11, unofficial][S4, unofficial].
*   `grid_bounds`: Defines the extent of the voxel grid [S11, unofficial].

**Edge Cases and Pitfalls**
*   **Zero Direction**: Rays aligned with a grid axis ($d_n = 0$) cause division by zero in inverse direction calculations. These must be handled by setting the corresponding `side_dist` to infinity and `step_dir` to 0 [S11, unofficial][S8, unofficial].
*   **Boundary Alignment**: If the ray origin lies exactly on a grid boundary, floating-point precision errors may cause the ray to miss a voxel or double-count a cell. Guarding against `dt=0` or using epsilon offsets is recommended [S11, unofficial][S7, unofficial].
*   **Negative Directions**: The initial distance calculation must account for the direction of travel. If $d_n < 0$, the next boundary is at $\lfloor o_n \rfloor$ rather than $\lfloor o_n \rfloor + 1$ [S4, unofficial].

## Subtopics

### [TRFRay3 (DDA Ray Representation)](2104-trfray3-dda-ray-representation.md)
TRFRay3 is a CPU-side DDA ray representation and traversal engine designed for picking and raycasting in voxel worlds, specifically engineered to match the toroidal GPU storage layout exactly. It solves the problem of efficiently finding the first solid voxel hit along a ray in a sparse or dense voxel grid while handling edge cases like zero-direction vectors and toroidal wrapping. It differs from the Amanatides–Woo Voxel Traversal by explicitly providing a C++ class structure (`TRFRay3`) that pre-computes inverse directions and origin-inverse direction (OOD) terms for SIMD-friendly, division-free traversal loops, and from the Differentiable DDA Loop by being a non-differentiable, integer-step traversal method.

### [Differentiable DDA Loop](2474-differentiable-dda-loop.md)
A differentiable Digital Differential Analyzer (DDA) loop that traverses a grid along a ray, invoking a callback function for each visited cell. It sets itself apart from standard DDA implementations by maintaining differentiability through the traversal state, allowing gradients to flow back through the ray marching steps.

### [Amanatides-Woo Voxel Traversal](3132-amanatides-woo-voxel-traversal.md)
The Amanatides and Woo algorithm is a 3D Digital Differential Analyzer (DDA) method for traversing a uniform voxel grid along a ray, visiting every intersected voxel in order of increasing distance from the ray origin. It solves the problem of efficiently determining the sequence of grid cells a ray passes through without expensive division operations in the main loop, guaranteeing that the ray stops and tests a voxel index at exactly one of the x, y, or z dividing planes. It sets itself apart from naive fixed-step ray marching by using boundary-crossing logic to ensure no voxels are missed, and from hierarchical methods by operating directly on a flat uniform grid.

### [3D Bresenham Voxel Traversal](3951-3d-bresenham-voxel-traversal.md)
3D Bresenham Voxel Traversal is a discrete line algorithm used to determine the sequence of integer voxel coordinates intersected by a line segment in a 3D grid. It iterates along the dominant axis and updates the other two axes based on accumulated error terms, effectively rasterizing the ray path through the voxel space. Unlike continuous DDA methods that guarantee every voxel the ray physically passes through is visited, Bresenham-based traversal may skip blocks where the ray does not get close enough to the block center, making it faster but potentially incomplete for volume rendering. It is often implemented as the stepping logic within Half-Vector DDA (HDDA) structures.

### [Multi-level DDA with Adaptive Mip Selection](4086-multi-level-dda-with-adaptive-mip-selection.md)
This method is a ray traversal and sampling algorithm for volume rendering that combines Digital Differential Analyzer (DDA) stepping with adaptive mip-level selection to optimize the trade-off between step size and sampling accuracy. It solves the problem of inefficient traversal in sparse or heterogeneous volumes by using a majorant texture at multiple resolutions to skip empty space, while dynamically adjusting the granularity of the search to locate collision points precisely. It sets itself apart from standard DDA approaches by avoiding execution divergence on GPUs through a branchless, iterative mip-level adjustment heuristic, and from pure delta tracking by providing deterministic spatial bounds for step sizes.

### [Amanatides–Woo grid traversal](5003-amanatides-woo-grid-traversal.md)
The Amanatides–Woo grid traversal algorithm determines the sequence of grid cells intersected by a line segment defined by two endpoints, invoking a visitor function for each cell. It distinguishes itself from its siblings by using a floating-point implementation that computes `t-max` values to determine the next cell boundary intersection, offering a straightforward approach for uniform grids where high-precision fixed-point arithmetic is not strictly required.

### Safe Inverse for DDA
A safe inverse function for ray direction components to handle near-axis-aligned rays in DDA, preventing division by zero or infinity while maintaining correct stepping behavior [S12, unofficial]. If `abs(x) < 1e-8`, return `select(-1e20, 1e20, x >= 0.0)`. Otherwise, return `1.0 / x` [S12, unofficial].

### Multi-Ray Field of View Casting
Sweeps a full field of view by casting one ray per screen column, evenly distributed across the angular range [S13, unofficial]. Iterate $i$ from 0 to `rayCount`-1. Calculate the angle for each ray using $\theta_i = \text{facing} - \text{FOV}/2 + i \cdot (\text{FOV}/(\text{rayCount} - 1))$ [S13, unofficial]. Cast each ray using the DDA algorithm with the calculated angle and store the result (angle, distance, side, hit coordinates) [S13, unofficial].

### Forward Stepping Enforcement
A macro definition, likely used to enforce forward stepping behavior in the DDA/HDDA implementations [S9].

## Operating characteristics

*   **Time Complexity**: $O(N)$, where $N$ is the number of voxels intersected by the ray. The number of steps is proportional to the length of the ray within the grid, significantly fewer than fixed-step marching [S5, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary space for the traversal state [S3, unofficial].
*   **Performance**: On GPUs, branchless implementations (using masks instead of `if` statements) are preferred to avoid execution divergence [S3, unofficial][S7, unofficial].
*   **Strengths**: Exact boundary detection, no missed voxels, efficient for uniform grids [S5, unofficial].
*   **Limitations**: Performance degrades if the ray direction is very shallow relative to the grid (many steps per unit distance) [S5, unofficial]. Not suitable for hierarchical or non-uniform grids without modification [S1, unofficial].

## Background

The DDA algorithm originated as a line-drawing algorithm in computer graphics, adapted for raycasting in grid-based environments [S6][S7, unofficial]. It is widely used in voxel raycasting, collision detection, and real-time rendering on limited hardware [S6][S7, unofficial]. The Amanatides–Woo variant is a standard implementation for 3D voxel traversal [S5, unofficial].
