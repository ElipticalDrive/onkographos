# VolumeHDDA

Also called: Hierarchical Digital Differential Analyzer for Volume, Volume Hierarchical DDA (VolumeHDDA), VolumeHDDA (Hierarchical DDA for Volumes), VolumeHDDA< TreeT, RayT, 0 >, ChildLevel>, ChildNodeLevel>

## Overview
VolumeHDDA is a specialized Hierarchical Digital Differential Analyzer for traversing volume trees to find ray intersections with active tiles or leaf nodes [S1, unofficial][S2, unofficial]. It solves the problem of efficiently identifying contiguous active segments along a ray in a sparse hierarchical volume structure, returning either the first valid segment or all valid segments [S1, unofficial][S2, unofficial]. It sets itself apart from its parent [DDA](2323-dda.md) by supporting recursive hierarchical traversal down to a specified node level, and from its sibling [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by being specialized for generic volume trees with active/inactive tile states rather than implicit functions or level sets [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A ray object (`RayT`) containing time parameters ($t_0, t_1$) and direction; an accessor object (`AccessorT`) providing tree access; a template parameter `ChildNodeLevel` specifying the entry level for hierarchical marching.
- **Output:** A `TimeSpanT` object (for `march`) containing the start ($t_0$) and end ($t_1$) of the first active segment, or a list of `TimeSpanT` objects (for `hits`) containing all active segments.

**Data Structures:**
The class `VolumeHDDA<TreeT, RayT, int ChildNodeLevel>` contains:
- `math::DDA<RayT, NodeT::TOTAL> mDDA`: A DDA instance for traversing nodes of size $2^{\text{NodeT::TOTAL}}$.
- `VolumeHDDA<TreeT, RayT, ChildNodeLevel-1> mHDDA`: A recursive instance for the next lower level.

Type definitions:
- `NodeT`: `typename ChainT::template Get<ChildNodeLevel>`, where `ChainT` is `typename TreeT::RootNodeType::NodeChainType`.
- `LeafT`: `typename TreeT::LeafNodeType` (only in specialization `ChildNodeLevel=0`).
- `TimeSpanT`: `typename RayT::TimeSpan`.

**Parameters:**
- `ChildNodeLevel`: Integer template argument. The traversal starts at this node level and recurses down to level 0 (leaf level) [S1, unofficial][S2, unofficial].

**Algorithm Steps:**
The algorithm consists of a recursive structure. The general case (`ChildNodeLevel > 0`) and the base case (`ChildNodeLevel == 0`) share similar logic but differ in node probing.

1. **Initialization:** Initialize `mDDA` with the ray. Create a `TimeSpanT t` initialized to $(-1, -1)$.
2. **Loop:** While `mDDA.step()` returns true:
   a. **Child Node Check:** If `acc.probeConstNode<NodeT>(mDDA.voxel())` (or `LeafT` in base case) is not null:
      - Set ray times: `ray.setTimes(mDDA.time(), mDDA.next())`.
      - Recursively call `mHDDA.march` (or `hits`).
      - If recursive call returns true (for `march`) or collects a segment (for `hits`), handle termination/collection and continue or return.
   b. **Active Tile Check:** Else if `acc.isValueOn(mDDA.voxel())` is true:
      - If `t.t0 < 0`: Set `t.t0 = mDDA.time()`.
   c. **Inactive Tile Check (Segment Closure):** Else if `t.t0 >= 0` (an active segment was started but current tile is inactive):
      - Set `t.t1 = mDDA.time()`.
      - If `t.valid()` (both $t_0$ and $t_1$ are set):
        - For `march`: Return `true`.
        - For `hits`: Push `t` to `times`.
      - Reset `t.set(-1, -1)`.
3. **Finalization:** After the loop, if `t.t0 >= 0` (ray ended inside an active segment):
   - Set `t.t1 = mDDA.maxTime()`.
   - For `march`: Return `false` (no complete segment found yet, or segment extends to end).
   - For `hits`: The segment is implicitly closed by the max time, but the code structure in sources suggests the loop finishes and the function returns without pushing the final segment if it wasn't closed by an inactive tile. *Correction based on source logic:* The sources show `if (t.t0>=0) t.t1 = mDDA.maxTime();` at the end of `hits` but do not explicitly push it. However, `march` returns `false`. The `hits` function signature in [S1, unofficial] does not return the list, it modifies it in place. The final segment is added to `times` only if `t.valid()` was triggered inside the loop. If the ray ends in an active tile, `t.t1` is set to `maxTime`, but `t` is not pushed. This implies `hits` might miss the final segment if it extends to the ray end, or the caller handles it. *Re-reading [S1, unofficial] lines 262-263:* `if (t.t0>=0) t.t1 = mDDA.maxTime();` is the last line. There is no push. This is a potential pitfall.

**Pseudocode:**

```python
class VolumeHDDA:
    def __init__(self, ChildNodeLevel):
        self.ChildNodeLevel = ChildNodeLevel
        self.mDDA = DDA(RayT, NodeT.TOTAL)
        if ChildNodeLevel > 0:
            self.mHDDA = VolumeHDDA(ChildNodeLevel - 1)

    def march(self, ray, acc):
        t = TimeSpanT(-1, -1)
        if not ray.valid():
            return t
        self._march_recursive(ray, acc, t)
        return t

    def _march_recursive(self, ray, acc, t):
        self.mDDA.init(ray)
        while self.mDDA.step():
            voxel = self.mDDA.voxel()
            time = self.mDDA.time()
            next_time = self.mDDA.next()
            
            # Check for child node
            child_node = acc.probeConstNode(self.NodeType, voxel)
            if child_node is not None:
                ray.setTimes(time, next_time)
                if self.mHDDA._march_recursive(ray, acc, t):
                    return True
            
            # Check for active tile
            elif acc.isValueOn(voxel):
                if t.t0 < 0:
                    t.t0 = time
            # Check for inactive tile after active
            elif t.t0 >= 0:
                t.t1 = time
                if t.valid():
                    return True
                t.set(-1, -1)
        
        if t.t0 >= 0:
            t.t1 = self.mDDA.maxTime()
        return False

    def hits(self, ray, acc, times):
        t = TimeSpanT(-1, -1)
        self._hits_recursive(ray, acc, times, t)

    def _hits_recursive(self, ray, acc, times, t):
        self.mDDA.init(ray)
        while self.mDDA.step():
            voxel = self.mDDA.voxel()
            time = self.mDDA.time()
            next_time = self.mDDA.next()
            
            child_node = acc.probeConstNode(self.NodeType, voxel)
            if child_node is not None:
                ray.setTimes(time, next_time)
                self.mHDDA._hits_recursive(ray, acc, times, t)
            elif acc.isValueOn(voxel):
                if t.t0 < 0:
                    t.t0 = time
            elif t.t0 >= 0:
                t.t1 = time
                if t.valid():
                    times.push_back(t)
                t.set(-1, -1)
        
        if t.t0 >= 0:
            t.t1 = self.mDDA.maxTime()
        # Note: Final segment not pushed if it extends to maxTime
```

**Edge Cases and Pitfalls:**
- **Time Span Management:** The `TimeSpanT` object `t` tracks active segments. It is initialized to $(-1, -1)$. $t.t_0$ marks the start of an active segment. $t.t_1$ marks the end. If an inactive tile is hit after an active segment, the segment is closed. If the ray ends while still in an active segment ($t.t_0 \ge 0$ after loop), $t.t_1$ is set to `maxTime`. However, in the `hits` method, this final segment is not pushed to the list if it is not closed by an inactive tile [S1, unofficial][S2, unofficial].
- **Ray Validity:** The public `march` method checks `ray.valid()` before calling the internal recursive method.
- **Base Case Specialization:** When `ChildNodeLevel == 0`, the class specializes to check `LeafT` nodes. The logic remains the same, but `probeConstNode<LeafT>` is used instead of `NodeT`.

## Subtopics

### [HDDA Iterator Reorganization](5239-hdda-iterator-reorganization.md)
A reorganization of Hierarchical Data-Driven Approach (HDDA) iterators that separates the traversal of all active values from the traversal of only leaf voxels, enabling tile-skipping for leaf-specific operations. It sets itself apart from its parent [VolumeHDDA](2353-volumehdda.md) by providing a specialized leaf-only traversal path that avoids processing active coarse tiles, addressing the latent mis-indexing bugs that occurred when callers assumed the previous single iterator yielded only leaf voxels.

## Operating characteristics
- **Time Complexity:** Proportional to the number of nodes visited along the ray path, including recursive descent into child nodes. In sparse volumes, this is significantly faster than linear voxel traversal.
- **Memory Complexity:** $O(L)$ where $L$ is the depth of the tree (recursion stack depth).
- **Strengths:** Efficiently skips inactive regions in sparse volumes. Hierarchical structure allows large jumps over empty space.
- **Limitations:** Requires a hierarchical tree structure. Overhead of recursive calls and node probing. The `hits` method may miss the final segment if it extends to the ray end [S1, unofficial].
- **When to use:** When traversing sparse volume trees for active tiles or leaf nodes.
- **When not to use:** For dense volumes where linear traversal might be more cache-friendly, or if the final segment at the ray end is critical and not handled by the caller.

## Background
VolumeHDDA is part of the OpenVDB library, developed by DreamWorks Animation for visual effects production [S1, unofficial][S2, unofficial]. It is designed to work with the OpenVDB data structure, which uses a hierarchical tree of nodes to store sparse voxel data. The class is templated to support different tree types and ray representations, making it flexible for various volume rendering and simulation applications.
