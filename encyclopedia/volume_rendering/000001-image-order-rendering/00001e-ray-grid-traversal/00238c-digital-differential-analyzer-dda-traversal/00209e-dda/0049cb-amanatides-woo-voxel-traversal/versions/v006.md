# Amanatides-Woo Voxel Traversal

Also called: Amanatides-Woo, Amanatides and Woo, AW87, A Fast Voxel Traversal Algorithm for Ray Tracing

## Overview
Amanatides-Woo is a fast, branch-minimal algorithm for traversing a uniform 3D voxel grid along a ray, visiting only the voxels intersected by the ray in $O(n_x + n_y + n_z)$ time [S11, S13, S42, unofficial]. It solves the problem of efficiently locating geometry in a dense grid without performing expensive per-voxel intersection tests or suffering from the precision errors and missed voxels inherent in naive fixed-step ray marching [S34, S45, unofficial]. It sets itself apart from its siblings by using floating-point parametric distances ($t$-values) to determine the next voxel boundary crossing based on the minimum time to cross any axis boundary, guaranteeing that the ray stops and tests a voxel index at exactly one of the x, y, or z dividing planes [S5, S13, S42, unofficial].

## How it works
The algorithm operates in two phases: initialization and incremental traversal. It assumes a uniform grid where voxels are unit cubes (or scaled by a constant `voxel_size`) aligned with the world axes.

### Inputs and Outputs
*   **Inputs**:
    *   `ray_origin`: `vec3` $(o_x, o_y, o_z)$, the starting point of the ray in world space.
    *   `ray_direction`: `vec3` $(d_x, d_y, d_z)$, the direction vector. It is typically normalized, but the algorithm works with any non-zero direction.
    *   `grid_min`, `grid_max`: `vec3` defining the axis-aligned bounding box (AABB) of the voxel grid in world space.
    *   `voxel_size`: `float` (optional, default 1.0). The side length of a voxel. If the grid is defined by integer indices $[0, N_x) \times [0, N_y) \times [0, N_z)$, `voxel_size` maps world coordinates to voxel indices.
*   **Outputs**:
    *   A sequence of voxel indices $(i, j, k)$ visited by the ray, in order of increasing distance from the origin.
    *   Optionally, the parametric distance $t$ or world position at which each voxel is entered/exited.

### Data Structures
The algorithm maintains the following state variables, typically stored as 3-component vectors or arrays:
1.  `current_voxel`: `ivec3` $(i, j, k)$, the integer coordinates of the voxel currently being traversed.
2.  `step`: `ivec3` $(s_x, s_y, s_z)$, where $s_i \in \{-1, 1\}$ indicates the direction of traversal along axis $i$.
3.  `t_max`: `vec3` $(t_{max,x}, t_{max,y}, t_{max,z})$, the parametric distance $t$ along the ray where the ray crosses the *next* voxel boundary along each axis.
4.  `t_delta`: `vec3` $(t_{\Delta,x}, t_{\Delta,y}, t_{\Delta,z})$, the parametric distance required to traverse one full voxel width along each axis.

### Numbered Steps

#### 1. Precomputation
Compute the inverse direction and signs. Handle degenerate cases where a direction component is zero to avoid division by zero [S44, S71, unofficial].
$$
\text{inv\_dir} = \left( \frac{1}{d_x}, \frac{1}{d_y}, \frac{1}{d_z} \right)
$$
$$
\text{step}_i = \begin{cases} 1 & \text{if } d_i \ge 0 \\ -1 & \text{if } d_i < 0 \end{cases}
$$
$$
\text{t\_delta}_i = \frac{1}{|d_i|} \quad \text{(or } \frac{\text{voxel\_size}}{|d_i|} \text{ if scaled)}
$$
If $d_i = 0$, set $\text{inv\_dir}_i = 0$, $\text{step}_i = 1$ (arbitrary), and $\text{t\_delta}_i = \infty$ [S34, S44, unofficial].

#### 2. Initial Voxel and Entry Point
Determine the voxel containing the ray origin. If the origin is outside the grid, compute the entry point into the grid AABB using slab intersection [S1, S26, S55, unofficial].
$$
\text{current\_voxel}_i = \lfloor \frac{o_i - \text{grid\_min}_i}{\text{voxel\_size}} \rfloor
$$
Calculate the world position of the entry point $p_{entry}$ if the origin is outside. If the origin is inside, $p_{entry} = o$ [S36, S69, unofficial].

#### 3. Initialize `t_max`
Calculate the parametric distance to the first voxel boundary along each axis. This is the distance from the entry point (or origin) to the nearest grid plane in the direction of `step` [S13, S49, unofficial].
Let $p_{start}$ be the entry point (or origin if inside).
$$
\text{boundary}_i = (\text{current\_voxel}_i + \text{step}_i) \times \text{voxel\_size} + \text{grid\_min}_i
$$
$$
\text{t\_max}_i = \frac{\text{boundary}_i - p_{start,i}}{d_i}
$$
Note: If $d_i = 0$, $\text{t\_max}_i = \infty$ [S34, unofficial].

#### 4. Traversal Loop
Repeat until the ray exits the grid or a hit is found:
1.  **Visit**: Process the voxel at `current_voxel`.
2.  **Select Axis**: Find the axis $a$ with the minimum `t_max` value:
    $$
    a = \arg \min_{i \in \{x,y,z\}} (\text{t\_max}_i)
    $$
3.  **Step**: Increment `current_voxel` along axis $a$:
    $$
    \text{current\_voxel}_a \leftarrow \text{current\_voxel}_a + \text{step}_a
    $$
4.  **Update `t_max`**: Advance the boundary crossing for axis $a$ by one voxel width:
    $$
    \text{t\_max}_a \leftarrow \text{t\_max}_a + \text{t\_delta}_a
    $$
5.  **Check Bounds**: If `current_voxel` is outside the grid bounds, terminate.

### Pseudocode
```python
def amanatides_woo_traversal(ray_origin, ray_direction, grid_min, grid_max, voxel_size=1.0):
    # 1. Precomputation
    # Handle zero direction components to avoid division by zero
    safe_dir = ray_direction
    for i in range(3):
        if abs(safe_dir[i]) < 1e-10:
            safe_dir[i] = 1e-10 * sign(ray_direction[i]) if ray_direction[i] != 0 else 1e-10
            
    inv_dir = 1.0 / safe_dir
    step = [1 if d >= 0 else -1 for d in safe_dir]
    t_delta = [abs(inv_dir[i]) * voxel_size for i in range(3)]
    
    # 2. Initial Voxel and Entry Point
    # Determine voxel containing origin
    current_voxel = [int((ray_origin[i] - grid_min[i]) / voxel_size) for i in range(3)]
    
    # Check if origin is inside grid
    inside = all(grid_min[i] <= ray_origin[i] < grid_max[i] for i in range(3))
    
    if not inside:
        # Ray-AABB intersection to find entry point
        t_min = 0.0
        t_max_dist = float('inf')
        for i in range(3):
            t1 = (grid_min[i] - ray_origin[i]) * inv_dir[i]
            t2 = (grid_max[i] - ray_origin[i]) * inv_dir[i]
            t_entry = min(t1, t2)
            t_exit = max(t1, t2)
            t_min = max(t_min, t_entry)
            t_max_dist = min(t_max_dist, t_exit)
        
        if t_min > t_max_dist:
            return [] # Ray misses grid
            
        # Nudge entry point slightly inside to avoid boundary precision issues
        entry_pos = [ray_origin[i] + (t_min + 1e-9) * safe_dir[i] for i in range(3)]
        # Recalculate current_voxel based on entry point
        current_voxel = [int((entry_pos[i] - grid_min[i]) / voxel_size) for i in range(3)]
        p_start = entry_pos
    else:
        p_start = ray_origin
        
    # 3. Initialize t_max
    t_max = []
    for i in range(3):
        # Next boundary coordinate
        next_boundary = (current_voxel[i] + step[i]) * voxel_size + grid_min[i]
        t_max.append((next_boundary - p_start[i]) * inv_dir[i])
        
    # 4. Traversal Loop
    visited = []
    grid_dims = [(grid_max[i] - grid_min[i]) / voxel_size for i in range(3)]
    
    while all(0 <= current_voxel[i] < grid_dims[i] for i in range(3)):
        visited.append(tuple(current_voxel))
        
        # Find axis with minimum t_max
        min_t = t_max[0]
        axis = 0
        for i in range(1, 3):
            if t_max[i] < min_t:
                min_t = t_max[i]
                axis = i
                
        # Step
        current_voxel[axis] += step[axis]
        t_max[axis] += t_delta[axis]
        
    return visited
```

### Parameters and Edge Cases
*   **Zero Direction**: If $d_i = 0$, the ray is parallel to the grid planes of that axis. It never crosses a boundary in that direction. Set $\text{t\_delta}_i = \infty$ and $\text{t\_max}_i = \infty$ so that axis is never selected for stepping [S34, S44, unofficial].
*   **Origin on Boundary**: If the ray origin lies exactly on a voxel boundary, floating-point errors may cause the ray to visit the same voxel twice or skip one. A common fix is to nudge the origin slightly in the direction of the ray if it is on the boundary [S1, S69, unofficial].
*   **Grid Bounds**: The algorithm must check if `current_voxel` is within $[0, N_x) \times [0, N_y) \times [0, N_z)$ after each step. If the ray originates outside, the initial `t_max` calculation must use the grid entry point, not the origin [S36, S69, unofficial].

## Subtopics

### Worst-Case Iteration Analysis
The worst-case scenario for the Amanatides-Woo algorithm occurs when the ray travels along the diagonal of the grid through exclusively empty voxels. In this case, the number of iterations is proportional to the sum of the grid dimensions in each axis ($N_x + N_y + N_z$), which is $O(n)$ for a grid of size $n^3$ [S85, unofficial]. This makes the algorithm susceptible to false positives (visiting many empty voxels) in sparse grids, motivating the use of hierarchical structures like Octrees or Sparse Voxel Octrees (SVO) [S85, unofficial].

### Vectorized Amanatides and Woo Variant
A vectorized variant simplifies the code by avoiding explicit branching for axis selection using vector operations and operator overloading. It computes `steps` (distance to next boundary in terms of number of steps) and uses `argmin` to find the axis. This approach works for arbitrary dimensions but is practically used in 2D and 3D. It reduces the number of comparisons and branches, potentially improving performance on SIMD hardware [S23, unofficial].

### DDA with Root Voxel Check
A variant that checks for a specific 'root' voxel (e.g., $(0,0,0)$) during traversal to potentially terminate early or signal a specific state. This is useful for debugging or specific game logic where the origin of the world is a significant landmark [S2, unofficial].

### Shadow Casting
The Amanatides-Woo traversal is used to generate single-sample hard shadows by re-tracing a voxel ray from the hit point towards the light source. If a non-empty block is hit during this shadow ray traversal, the point is in shadow. This leverages the same efficient traversal logic for shadow calculations [S41, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(n_x + n_y + n_z)$ per ray, where $n_i$ is the number of voxels traversed along axis $i$. This is optimal for uniform grids as it visits each intersected voxel exactly once [S11, S13, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary space. The algorithm only requires a few scalar/vector variables for state [S42, unofficial].
*   **Performance**: The algorithm is extremely fast due to minimal floating-point operations per step (one comparison, one addition, one increment) [S42, unofficial][S25]. It is widely used in real-time voxel rendering, ray tracing, and shadow casting [S1, S3, S41, unofficial].
*   **Strengths**: Correctness (no missed voxels), efficiency (no per-voxel intersection tests), simplicity.
*   **Limitations**: Performance degrades in sparse grids due to traversal of empty space. Not suitable for non-uniform grids without modification (e.g., using hierarchical structures) [S85, unofficial].

## Background
The algorithm was introduced by Amanatides and Woo in their 1987 paper "A Fast Voxel Traversal Algorithm for Ray Tracing" [S13, S40, unofficial]. It is an extension of the 2D DDA (Digital Differential Analyzer) line drawing algorithm (Bresenham's algorithm) to 3D. It has become a standard technique in voxel-based rendering, game development, and scientific visualization [S1, S3, unofficial][S12].
