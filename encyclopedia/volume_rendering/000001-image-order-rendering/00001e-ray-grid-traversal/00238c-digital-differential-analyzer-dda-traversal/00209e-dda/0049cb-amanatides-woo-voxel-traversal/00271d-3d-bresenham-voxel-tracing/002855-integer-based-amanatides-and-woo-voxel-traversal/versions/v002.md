# Integer-based Amanatides and Woo Voxel Traversal

Also called: Exact integer grid traversal, Integer-based Fast Grid Traversal, Integer-based ray marching

## Overview
This method implements the Amanatides and Woo voxel traversal algorithm using scaled integer arithmetic to determine the sequence of grid cells intersected by a ray, ensuring exactness and stability by avoiding floating-point operations [S1, unofficial]. It serves as the core traversal loop for image-order volume rendering or ray casting [S1, unofficial].

## How it works
**Inputs:**
- `startX, startY, startZ`: Integer grid coordinates of the starting voxel [S1, unofficial].
- `originX, originY, originZ`: Ray origin in world space [S1, unofficial].
- `vx, vy, vz`: Ray direction vector components, scaled to integers [S1, unofficial].
- `cellSize`: Width of a single voxel in world units [S1, unofficial].
- `justOutX, justOutY, justOutZ`: Predefined boundary values indicating the grid exit for each axis [S1, unofficial].

**Outputs:**
- The first object hit in the voxel grid, or `None` if the ray exits the grid without hitting an object [S1, unofficial].

**Data Structures:**
- `X, Y, Z`: Current voxel coordinates (32-bit signed integers) [S1, unofficial].
- `stepX, stepY, stepZ`: Direction indicators (+1 or -1) for each axis [S1, unofficial].
- `iDeltaX, iDeltaY, iDeltaZ`: Scaled delta distances to the next boundary crossing for each axis (64-bit signed integers, `long long`) [S1, unofficial].
- `iMaxX, iMaxY, iMaxZ`: Scaled distances to the *first* boundary crossing for each axis (64-bit signed integers, `long long`) [S1, unofficial].

**Parameters:**
- Typical values for `cellSize` depend on the scene scale [S1, unofficial].
- `vx, vy, vz` must be scaled consistently with `origin` and `cellSize` [S1, unofficial].
- The scaling factor $S$ is implicitly $|v_x v_y v_z|$ [S1, unofficial].
- The algorithm avoids division by multiplying the standard floating-point $t_{max}$ formula by this factor [S1, unofficial].

**Steps:**

1.  **Initialization Phase:**
    1.  Set current voxel coordinates: $X = startX$, $Y = startY$, $Z = startZ$ [S1, unofficial].
    2.  Determine step directions:
        $$ stepX = \begin{cases} 1 & \text{if } v_x \ge 0 \\ -1 & \text{otherwise} \end{cases} $$
        (Repeat for $stepY$ and $stepZ$) [S1, unofficial].
    3.  Calculate the world-space coordinate of the next grid boundary for each axis:
        $$ nextBoundaryX = \begin{cases} (X + 1) \cdot cellSize & \text{if } stepX > 0 \\ X \cdot cellSize & \text{if } stepX \le 0 \end{cases} $$
        (Repeat for $Y$ and $Z$) [S1, unofficial].
    4.  Compute scaled delta distances ($iDelta$) for each axis. These represent the change in scaled distance when crossing one voxel:
        $$ iDeltaX = cellSize \cdot |v_y \cdot v_z| $$
        $$ iDeltaY = cellSize \cdot |v_x \cdot v_z| $$
        $$ iDeltaZ = cellSize \cdot |v_x \cdot v_y| $$
        Use 64-bit integers (`long long`) to prevent overflow during multiplication [S1, unofficial].
    5.  Initialize scaled max distances ($iMax$) to the first boundary crossing. The standard floating-point formula $t_{max} = \frac{boundary - origin}{v}$ is scaled by multiplying by $|v_x v_y v_z|$ [S1, unofficial].
        $$ iMaxX = (nextBoundaryX - originX) \cdot v_y \cdot v_z $$
        If $v_x < 0$, negate $iMaxX$ to correct for the direction of division [S1, unofficial].
        If $v_x = 0$, set $iMaxX = LLONG\_MAX$ (parallel ray) [S1, unofficial].
        (Repeat for $iMaxY$ and $iMaxZ$) [S1, unofficial].

2.  **Incremental Phase:**
    1.  Enter a loop. Compare $iMaxX$, $iMaxY$, and $iMaxZ$ to find the smallest value, indicating the next axis to cross [S1, unofficial].
    2.  If $iMaxX$ is the smallest:
        - Increment $X$ by $stepX$.
        - If $X == justOutX$, return `None` (ray exited grid) [S1, unofficial].
        - Update $iMaxX = iMaxX + iDeltaX$ [S1, unofficial].
    3.  Else if $iMaxY$ is the smallest:
        - Increment $Y$ by $stepY$.
        - If $Y == justOutY$, return `None` [S1, unofficial].
        - Update $iMaxY = iMaxY + iDeltaY$ [S1, unofficial].
    4.  Else ($iMaxZ$ is the smallest):
        - Increment $Z$ by $stepZ$.
        - If $Z == justOutZ$, return `None` [S1, unofficial].
        - Update $iMaxZ = iMaxZ + iDeltaZ$ [S1, unofficial].
    5.  Check the voxel list at the current $(X, Y, Z)$ coordinates for an object hit [S1, unofficial].
    6.  If an object is hit, return it. Otherwise, continue the loop [S1, unofficial].

**Pseudocode:**

```python
def integer_amanatides_woo_traversal(startX, startY, startZ, originX, originY, originZ, vx, vy, vz, cellSize, justOutX, justOutY, justOutZ):
    # 1. Initialization Phase
    X, Y, Z = startX, startY, startZ

    stepX = 1 if vx >= 0 else -1
    stepY = 1 if vy >= 0 else -1
    stepZ = 1 if vz >= 0 else -1

    nextBoundaryX = (X + 1) * cellSize if stepX > 0 else X * cellSize
    nextBoundaryY = (Y + 1) * cellSize if stepY > 0 else Y * cellSize
    nextBoundaryZ = (Z + 1) * cellSize if stepZ > 0 else Z * cellSize

    # Compute scale factors (Absolute values of cross-products)
    # Use 64-bit integers to prevent overflow
    iDeltaX = cellSize * abs(vy * vz)
    iDeltaY = cellSize * abs(vx * vz)
    iDeltaZ = cellSize * abs(vx * vy)

    # Initialize iMax (Scaled t to next boundary)
    # Logic: (nextBoundary - origin) * (product of other two velocity components)
    # Correct sign for negative velocity components
    INF = 2**63 - 1  # LLONG_MAX

    iMaxX = (nextBoundaryX - originX) * vy * vz
    if vx < 0:
        iMaxX = -iMaxX
    if vx == 0:
        iMaxX = INF

    iMaxY = (nextBoundaryY - originY) * vx * vz
    if vy < 0:
        iMaxY = -iMaxY
    if vy == 0:
        iMaxY = INF

    iMaxZ = (nextBoundaryZ - originZ) * vx * vy
    if vz < 0:
        iMaxZ = -iMaxZ
    if vz == 0:
        iMaxZ = INF

    # Check starting voxel before traversal [G]
    hit = None  # Placeholder for external voxel list lookup [S1, unofficial]
    if hit is not None:
        return hit

    # 2. Incremental Phase
    while True:
        if iMaxX < iMaxY:
            if iMaxX < iMaxZ:
                # X is smallest
                X += stepX
                if X == justOutX:
                    return None
                iMaxX += iDeltaX
            else:
                # Z is smallest
                Z += stepZ
                if Z == justOutZ:
                    return None
                iMaxZ += iDeltaZ
        else:
            if iMaxY < iMaxZ:
                # Y is smallest
                Y += stepY
                if Y == justOutY:
                    return None
                iMaxY += iDeltaY
            else:
                # Z is smallest
                Z += stepZ
                if Z == justOutZ:
                    return None
                iMaxZ += iDeltaZ

        # Check voxel list at current (X, Y, Z) for an object hit [S1, unofficial]
        hit = None  # Placeholder for external voxel list lookup
        if hit is not None:
            return hit
```

**Edge Cases and Pitfalls:**
- **Parallel Rays:** If a velocity component is 0 (e.g., $v_x = 0$), the corresponding $iMax$ is set to `LLONG_MAX`, effectively removing that axis from the minimum comparison [S1, unofficial].
- **Integer Overflow:** The intermediate calculations for $iDelta$ and $iMax$ involve products of velocity components and coordinates [S1, unofficial]. Using 64-bit integers (`long long`) is necessary to prevent overflow for large grids or high-precision direction vectors [S1, unofficial].
- **Grid Exit:** The loop terminates when the incremented coordinate equals the predefined `justOut` boundary for that axis [S1, unofficial].

## Subtopics

### [Fixed-point Amanatides–Woo Grid Traversal](5005-fixed-point-amanatides-woo-grid-traversal.md)
This method implements the Amanatides–Woo voxel traversal algorithm using 16-bit signed fixed-point arithmetic (Q8.8 format) to avoid floating-point operations entirely. It solves the problem of efficiently determining which grid cells a line segment intersects in 2D space, serving as the core traversal loop for image-order volume rendering or ray casting. It sets itself apart from its parent [Integer-based Amanatides and Woo Voxel Traversal](4246-integer-based-amanatides-and-woo-voxel-traversal.md) by using fractional bits to represent sub-cell distances, allowing for exact intersection calculations without the accumulation of rounding errors inherent in pure integer DDA, while maintaining the speed benefits of integer arithmetic.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels traversed [S1, unofficial]. Each iteration performs a constant number of integer comparisons and additions [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space [S1, unofficial].
- **Performance:** Significantly faster than floating-point Amanatides-Woo on hardware lacking efficient FPUs or where integer arithmetic is preferred for determinism [S1, unofficial]. It avoids the cost of division and floating-point conversion [S1, unofficial].
- **Strengths:** Exactness (no rounding errors in traversal order), stability, and speed [S1, unofficial]. Ideal for fixed-grid environments like voxel games or exact collision detection [S1, unofficial].
- **Limitations:** Requires careful scaling of input values to fit within 64-bit integer limits [S1, unofficial]. Not suitable for dynamic grids where cell sizes vary per axis unless adapted [S1, unofficial]. Precision is limited by the integer range; very small steps or very large grids may require higher precision types or fixed-point variants [S1, unofficial].

## Background
The original Amanatides and Woo algorithm (1987) is a standard method for voxel traversal using floating-point arithmetic [S1, unofficial]. This integer-based variant was proposed in an unofficial GitHub issue discussion to provide a fast, exact, and stable alternative for applications like bullet hit detection in games, where floating-point precision issues could cause rays to pass through voxels incorrectly [S1, unofficial]. It mirrors the logic of the original paper but replaces floating-point operations with scaled integer arithmetic [S1, unofficial].
