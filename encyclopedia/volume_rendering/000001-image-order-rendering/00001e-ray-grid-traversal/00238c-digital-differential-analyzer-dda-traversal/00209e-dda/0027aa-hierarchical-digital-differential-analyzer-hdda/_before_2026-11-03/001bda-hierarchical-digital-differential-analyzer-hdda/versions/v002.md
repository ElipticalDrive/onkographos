# Hierarchical Digital Differential Analyzer (HDDA)
Also called: Hierarchical DDA

## Overview
The Hierarchical Digital Differential Analyzer (HDDA) is a specialized ray-traversal algorithm for sparse voxel grids that performs multi-resolution leapfrogging to efficiently determine voxels or tiles intersected by a ray [S1, unofficial][S2]. It leverages the compile-time fixed tree configuration of the underlying data structure to inline and collapse the hierarchical traversal, reducing the overhead of vertical tree navigation [S1, unofficial][S2].

## How it works
### Inputs and Outputs
**Inputs:**
- A ray $R(t) = O + tD$, where $O$ is the origin, $D$ is the direction, and $t \in [t_{min}, t_{max}]$ [G].
- A hierarchical sparse voxel grid (e.g., VDB) with a fixed tree configuration [S1, unofficial][S2].
- An accessor providing node probing and tile activity checks [G].

**Outputs:**
- A list of `TimeSpan` intervals $[t_0, t_1]$ representing active segments along the ray in front-to-back order, or a boolean indicating intersection [S2].

### Data Structures
The algorithm maintains DDA state per node level to step through children [S1, unofficial][S2]. Template meta-programming is used to unroll the recursion at compile-time, eliminating function call overhead for vertical navigation [S1, unofficial][S2]. Each level manages its own DDA instance to leapfrog to the next child node or tile [S1, unofficial][S2].

### Algorithm Steps
1. Initialize a DDA instance for the current node level using the ray parameters [G].
2. While the DDA steps to the next voxel:
   a. If a child node exists at the current voxel, update the ray's $t$ range to the child's bounds and recursively process the child level (or unrolled equivalent) [S1, unofficial][S2].
   b. If the current tile is active (value is on), record the start of an active segment if not already recording [S2].
   c. If the current tile is inactive and an active segment is being recorded, close the segment at the current DDA time, store it, and reset the segment state [S2].
3. After the loop, if an active segment is still open, close it at the ray's maximum $t$ value [S2].
4. Return the accumulated segments or intersection status [S2].

### Pseudocode
```python
class DDA:
    def __init__(self, origin, direction, t_min, t_max, child_count):
        self.origin = origin
        self.direction = direction
        self.t_min = t_min
        self.t_max = t_max
        self.child_count = child_count
        self.current_voxel = [0, 0, 0]
        self.t = t_min
        self.next_t = t_min + 1.0 / max(abs(direction[0]), abs(direction[1]), abs(direction[2]))
    
    def step(self):
        if self.t > self.t_max:
            return False
        self.current_voxel = [int((self.origin[i] + self.t * self.direction[i]) / self.child_count) for i in range(3)]
        self.t = self.next_t
        self.next_t += 1.0 / max(abs(self.direction[0]), abs(self.direction[1]), abs(self.direction[2]))
        return True
    
    def time(self):
        return self.t_min
    
    def next(self):
        return self.t

class TimeSpan:
    def __init__(self):
        self.t0 = -1.0
        self.t1 = -1.0
    
    def valid(self):
        return self.t0 >= 0
    
    def reset(self):
        self.t0 = -1.0
        self.t1 = -1.0

def hdda_traverse(ray_origin, ray_direction, ray_t_min, ray_t_max, grid_accessor, node_type, time_span):
    # Initialize DDA for the current node level
    dda = DDA(ray_origin, ray_direction, ray_t_min, ray_t_max, node_type.child_count)
    
    while dda.step():
        voxel = dda.current_voxel()
        
        # Check for child node
        child_node = grid_accessor.probe_const_node(voxel)
        if child_node is not None:
            # Update ray bounds for child and recurse
            child_t_min = dda.time()
            child_t_max = dda.next()
            child_time_span = TimeSpan()
            hdda_traverse(ray_origin, ray_direction, child_t_min, child_t_max, grid_accessor, child_node.type, child_time_span)
            if child_time_span.valid():
                time_span.t0 = child_time_span.t0
                time_span.t1 = child_time_span.t1
        
        # Check active tile
        elif grid_accessor.is_value_on(voxel):
            if time_span.t0 < 0:
                time_span.t0 = dda.time()
            else:
                time_span.t1 = dda.time()
                if time_span.valid():
                    return True
                time_span.reset()
    
    if time_span.t0 >= 0:
        time_span.t1 = ray_t_max
    return time_span.valid()
```

### Parameters and Edge Cases
- **Linear Transforms:** Directly applicable when rays are linear in both world and index space [S1, unofficial][S2].
- **Non-linear Transforms:** Rays warped to a camera frustum do not march along straight lines in index space, preventing direct HDDA use [S1, unofficial].
- **Auxiliary Grid Solution:** For non-linear transforms, construct an auxiliary VDB with a linear transform to act as a mask for active values [S1, unofficial]. This binary grid is generated via concurrent resampling of the density grid with a frustum transform, uses lower voxel resolution and single-bit encoding for compactness, and undergoes fast bit-wise topological dilation to account for the interpolation kernel size [S1, unofficial][S2].
- **Time Span Management:** Segments are tracked as $[t_0, t_1]$ [S2]. Inactive tiles terminate active segments [S2]. Open segments at ray exit are closed at $t_{max}$ [S2].

## Subtopics

### [NanoVolumeHDDA](3125-nanovolumehdda.md)
A span-merging hierarchical DDA iterator over a NanoGrid that yields TimeSpan structs representing merged active regions along a ray in front-to-back order. It merges adjacent active leaves and tiles to eliminate seam artifacts at 8-voxel tile edges.

## Operating characteristics
- **Time Complexity:** Not given in the sources. The algorithm is described as highly efficient for sparse volumes with linear transformations due to multi-resolution leapfrogging and compile-time inlining [S1, unofficial][S2].
- **Memory Complexity:** Not given in the sources. The fixed tree configuration and template unrolling minimize auxiliary memory overhead [S1, unofficial][S2].
- **Strengths:** Optimized for sparse volumes with linear transformations; minimizes costly high-order voxel interpolation for level-set surfaces [S1, unofficial][S2].
- **Limitations:** Requires compile-time fixed tree configuration; requires auxiliary grid construction for non-linear transforms [S1, unofficial][S2].
- **When to Use:** Volume rendering of densities (e.g., clouds) and ray-tracing of narrow-band level set surfaces [S1, unofficial][S2].

## Background
The HDDA was developed by Ken Museth for the VDB (Volume Database) system, initially presented in 2013 [S1, unofficial][S2]. It was designed to take full advantage of the hierarchical structure of VDB, which uses a B+tree with fixed node sizes [S1, unofficial][S2]. The algorithm was implemented in OpenVDB v2 and has since been used for various graphics applications, including volume rendering and level-set intersection [S1, unofficial][S2].
