# OpenVDB DDA

Also called: Digital Differential Analyzer for OpenVDB, Digital Differential Analyzer specialized for OpenVDB grids, HDDA (Hierarchical Digital Differential Analyzer), VDB DDA

## Overview
The OpenVDB Digital Differential Analyzer (DDA) is a fixed-step ray traversal algorithm designed to efficiently iterate through the hierarchical node and voxel structure of OpenVDB grids [S1][S6, unofficial][S7]. It solves the problem of determining which grid elements (tiles, internal nodes, or voxels) intersect a given ray by adapting Bresenham’s line algorithm to 3D ray-space [S6, unofficial][S7]. Unlike its sibling Hierarchical Digital Differential Analyzer (HDDA), which uses variable step sizes to leapfrog across tree levels, OpenVDB DDA uses a fixed step size defined by the template parameter `Log2Dim` (or `Dim` in NanoVDB), making it suitable for uniform traversal of specific tree levels or leaf voxels [S1][S3, unofficial]. It is primarily used as the core traversal kernel within the broader HDDA framework to handle leaf-level or specific internal-node-level intersections [S3, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A ray object (`RayT`) providing position, direction, inverse direction, and time bounds ($t_0, t_1$); a template parameter `Log2Dim` (integer) defining the traversal granularity [S3, S6, unofficial].
- **Output:** A sequence of grid coordinates (`Coord`) and parameterized times ($t$) representing the entry points into each intersected node or voxel [S3, S6, unofficial].

**Data Structures:**
The DDA state is maintained in a class with the following private members [S3, S6, unofficial]:
- `mT0` (`RealT`): Current parameterized time along the ray.
- `mT1` (`RealT`): Maximum parameterized time (ray far plane).
- `mVoxel` (`Coord`): 3D integer coordinates of the current node/voxel origin.
- `mStep` (`Coord`): Step direction (+1 or -1) for each axis, scaled by `DIM`.
- `mDelta` (`Vec3T`): Time increment per step for each axis.
- `mNext` (`Vec3T`): Parameterized time of the next intersection along each axis.

**Parameters:**
- `Log2Dim`: Integer template parameter. Default is 0. `Log2Dim = 0` corresponds to a single voxel. `Log2Dim > 0` corresponds to a tree node (tile) of size $2^{\text{Log2Dim}}$ [S3, S6, unofficial][S7].
- `DIM`: Computed as $2^{\text{Log2Dim}}$ [S3, S6, unofficial].

**Algorithm Steps:**

1. **Initialization (`init`):**
   Given a ray, start time $t_{start}$, and max time $t_{max}$:
   a. Set $mT_0 = t_{start}$ and $mT_1 = t_{max}$ [S3, S6, unofficial].
   b. Compute $DIM = 1 \ll \text{Log2Dim}$ [S3, S6, unofficial].
   c. Get ray position $pos = \text{ray}(mT_0)$, direction $dir$, and inverse direction $inv$ [S3, S6, unofficial].
   d. Compute initial voxel coordinate: $mVoxel = \lfloor pos \rfloor \ \& \ \sim(DIM - 1)$ [S3, S6, unofficial]. This aligns the starting voxel to the grid boundary of size $DIM$ [S3, S6, unofficial].
   e. For each axis $i \in \{0, 1, 2\}$:
      - If $dir[i] == 0$ (including $\pm 0$):
        - $mStep[i] = 0$
        - $mNext[i] = \infty$ (disabled)
        - $mDelta[i] = \infty$
      - Else if $inv[i] > 0$ (ray moving in positive direction):
        - $mStep[i] = DIM$
        - $mNext[i] = mT_0 + (mVoxel[i] + DIM - pos[i]) \cdot inv[i]$
        - $mDelta[i] = mStep[i] \cdot inv[i]$
      - Else ($inv[i] < 0$, ray moving in negative direction):
        - $mStep[i] = -DIM$
        - $mNext[i] = mT_0 + (mVoxel[i] - pos[i]) \cdot inv[i]$
        - $mDelta[i] = mStep[i] \cdot inv[i]$ [S3, S6, unofficial].

2. **Query Current State:**
   - `time()`: Returns $mT_0$, the time of the first hit of the current node/voxel [S3, S6, unofficial].
   - `voxel()`: Returns $mVoxel$. If `Log2Dim == 0`, this is the signed coordinate of the voxel. If `Log2Dim > 0`, this is the origin of the VDB tree node/tile [S3, S6, unofficial].

3. **Stepping (`step`):**
   a. Find the axis with the minimum next hit time: $stepAxis = \text{argmin}(mNext[0], mNext[1], mNext[2])$ [S3, S6, unofficial].
   b. Update current time: $mT_0 = mNext[stepAxis]$ [S3, S6, unofficial].
   c. Advance the next hit time for that axis: $mNext[stepAxis] += mDelta[stepAxis]$ [S3, S6, unofficial].
   d. Advance the voxel coordinate for that axis: $mVoxel[stepAxis] += mStep[stepAxis]$ [S3, S6, unofficial].
   e. Return `true` if $mT_0 \le mT_1$, else `false` [S3, S6, unofficial].

4. **Query Next Hit (Optional):**
   - `next()`: Computes and returns the time of the *second* hit (the next intersection after the current one). This incurs a small computational overhead compared to `time()` and `voxel()` [S1, S4]. It is used to define the traversal interval for testing node existence [S3, unofficial].

**Pseudocode:**

```python
import math
import numpy as np

class OpenVDBDDA:
    def __init__(self, ray, log2_dim=0, start_time=None, max_time=None):
        """
        ray: object with methods .pos(t), .dir(), .invDir(), .t0(), .t1()
        log2_dim: integer, 0 for voxels, >0 for nodes of size 2^log2_dim
        """
        self.log2_dim = log2_dim
        self.dim = 1 << log2_dim
        self.init(ray, start_time, max_time)

    def init(self, ray, start_time=None, max_time=None):
        if start_time is None:
            start_time = ray.t0()
        if max_time is None:
            max_time = ray.t1()
        
        assert start_time <= max_time
        
        self.t0 = start_time
        self.t1 = max_time
        
        pos = ray.pos(self.t0)
        dir_vec = ray.dir()
        inv_dir = ray.invDir()
        
        # Align voxel to grid boundary
        # floor(pos) & ~(dim - 1)
        self.voxel = np.floor(pos).astype(int) & (~self.dim + 1)
        
        self.next_hit = np.full(3, np.inf)
        self.step_dir = np.zeros(3, dtype=int)
        self.delta = np.full(3, np.inf)
        
        for axis in range(3):
            if math.isclose(dir_vec[axis], 0.0, abs_tol=1e-9):
                # Axis is parallel to ray, disable
                self.step_dir[axis] = 0
                self.next_hit[axis] = np.inf
                self.delta[axis] = np.inf
            elif inv_dir[axis] > 0:
                # Moving in positive direction
                self.step_dir[axis] = self.dim
                self.next_hit[axis] = self.t0 + (self.voxel[axis] + self.dim - pos[axis]) * inv_dir[axis]
                self.delta[axis] = self.step_dir[axis] * inv_dir[axis]
            else:
                # Moving in negative direction
                self.step_dir[axis] = -self.dim
                self.next_hit[axis] = self.t0 + (self.voxel[axis] - pos[axis]) * inv_dir[axis]
                self.delta[axis] = self.step_dir[axis] * inv_dir[axis]

    def step(self):
        if self.t0 > self.t1:
            return False
        
        # Find axis with minimum next hit time
        step_axis = np.argmin(self.next_hit)
        
        # Update state
        self.t0 = self.next_hit[step_axis]
        self.next_hit[step_axis] += self.delta[step_axis]
        self.voxel[step_axis] += self.step_dir[step_axis]
        
        return self.t0 <= self.t1

    def time(self):
        return self.t0

    def voxel(self):
        return self.voxel

    def next_hit_time(self):
        """Computes the time of the next intersection. Incurs overhead."""
        # Re-implement logic to find the *next* hit after current t0
        # This is a simplified approximation for demonstration; 
        # actual implementation may cache or compute differently.
        # For correctness, we simulate the step without updating state permanently
        # or use the internal 'next' logic if available.
        # Here we just return the min of next_hit that is > t0
        candidates = self.next_hit[self.next_hit > self.t0]
        if len(candidates) == 0:
            return np.inf
        return np.min(candidates)
```

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of grid elements (voxels/nodes) intersected by the ray. Each step is $O(1)$ [S3, S6, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory for the DDA state [S3, S6, unofficial].
- **Performance:** The `time()` and `voxel()` methods incur no computational overhead, making them efficient for tight loops. The `next()` method incurs a small overhead [S1, S4]. Zero-direction handling prevents infinite loops but adds a branch check [S3, S6, unofficial].
- **Strengths:** Simple, robust, fixed-step traversal suitable for leaf-level or uniform node-level access. Integrates seamlessly with OpenVDB's tree structure via `hasNode` checks [S3, unofficial].
- **Limitations:** Fixed step size means it cannot skip empty internal nodes as efficiently as variable-step HDDA for sparse grids. Not suitable for non-linear coordinate spaces without modification [S1][S3, unofficial].
- **When to use:** When traversing leaf voxels (`Log2Dim=0`) or specific internal node levels (`Log2Dim>0`) within a hierarchical traversal framework. When simplicity and predictability are preferred over aggressive skipping.
- **When not to use:** For highly sparse grids where large empty regions should be skipped entirely (use HDDA). For non-linear grids (use Frustum DDA).

## Background
The OpenVDB DDA was introduced as part of the OpenVDB library, a C++ library for the management and manipulation of sparse volumetric data [S3, S6, unofficial]. It is conceptually based on Bresenham's line algorithm, adapted for 3D ray traversal [S6, unofficial][S7]. The algorithm is a core component of the Hierarchical Digital Differential Analyzer (HDDA) system, which uses DDA for leaf-level or specific node-level traversal while HDDA handles the hierarchical leapfrogging [S3, unofficial]. The implementation is found in `openvdb/math/DDA.h` and `nanovdb/math/HDDA.h` [S1][S3, S6, unofficial]. It has been used in various volume rendering and simulation contexts, including neural radiance fields (NeRF) with occupancy grids [S5, unofficial].
