# Integer Bresenham Voxelization with 6-Connectivity

Also called: 6-Connected Bresenham Algorithm Modification, 6-connected Bresenham, Discrete Ray Traversal, Modified Bresenham

## Overview
This method generates a 6-connected sequence of integer voxel coordinates intersected by a line segment, ensuring that every consecutive pair of voxels shares a face. It solves the connectivity gap in standard Bresenham algorithms, which may skip voxels or produce 18/26-connected lines, making it essential for applications requiring strict topological continuity such as interior filling of triangles in scanline voxelization [S1, unofficial]. It differs from its parent [3D Bresenham Voxel Traversal](3951-3d-bresenham-voxel-traversal.md) by explicitly handling multiple voxel outputs per iteration step to maintain 6-connectivity, and from [26-connected traversal](3951-3d-bresenham-voxel-traversal.md#subtopics) by being slower but more accurate for small features [S2, book].

## How it works
**Inputs:** Start voxel $(X_0, Y_0, Z_0)$, end voxel $(X_1, Y_1, Z_1)$, and a callback or iterator interface `SetVoxel(voxel)`.
**Outputs:** A sequence of voxels visited along the line.

**Data Structures:**
*   `dx, dy, dz`: Absolute differences $|X_1 - X_0|$, $|Y_1 - Y_0|$, $|Z_1 - Z_0|$.
*   `sx, sy, sz`: Step directions ($1$ or $-1$) for each axis.
*   `A`: Index of the dominant axis ($0$ for X, $1$ for Y, $2$ for Z).
*   `i1, i2`: Indices of the secondary axes, calculated as $(A + 1) \pmod 3$ and $(A + 2) \pmod 3$.
*   `e1, e2`: Error accumulators for the secondary axes.
*   `last_returned_index`: Integer tracking the number of voxels returned in the current iteration to handle multiple outputs per step [S1, unofficial].

**Parameters:**
*   Typical values are derived directly from input coordinates. No fixed constants are used other than $2$ and $3$ in modulo arithmetic.

**Steps:**
1.  **Initialization:**
    *   Calculate absolute differences: $\Delta X = |X_1 - X_0|$, $\Delta Y = |Y_1 - Y_0|$, $\Delta Z = |Z_1 - Z_0|$.
    *   Determine step signs: $sx = \text{sign}(X_1 - X_0)$, $sy = \text{sign}(Y_1 - Y_0)$, $sz = \text{sign}(Z_1 - Z_0)$. If difference is 0, sign is 0.
    *   Determine dominant axis $A$:
        $$
        A = \begin{cases} 
        0 & \text{if } \Delta X \ge \Delta Y \text{ and } \Delta X \ge \Delta Z \\
        1 & \text{if } \Delta Y > \Delta X \text{ and } \Delta Y \ge \Delta Z \\
        2 & \text{if } \Delta Z > \Delta X \text{ and } \Delta Z > \Delta Y
        \end{cases}
        $$
    *   Calculate secondary indices: $i1 = (A + 1) \pmod 3$, $i2 = (A + 2) \pmod 3$.
    *   Map $\Delta X, \Delta Y, \Delta Z$ to arrays or variables indexed by $0,1,2$ for uniform access: let $D[0]=\Delta X, D[1]=\Delta Y, D[2]=\Delta Z$. Similarly for steps $S[0]=sx, S[1]=sy, S[2]=sz$ and coordinates $C[0]=X_0, C[1]=Y_0, C[2]=Z_0$.

    dy = abs(y1 - y0)

**Edge Cases and Pitfalls:**
*   **Last Voxel:** The loop condition `C[A] != X1` excludes the final voxel. It must be explicitly appended after the loop [S1, unofficial].
*   **Multiple Voxels:** The algorithm can generate up to three voxels per dominant axis iteration. This conflicts with algorithms expecting a single next voxel. Implementers must use an iterator or buffer to handle this [S1, unofficial].
*   **Negative Directions:** Handled by absolute differences and sign variables [S1, unofficial].
*   **Zero Difference:** If a difference is zero, the step is 0, and the axis does not change. The error term logic still applies but will not trigger steps if the dominant axis is not that axis.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the length of the line in the dominant axis. Each iteration performs constant work, but may emit up to 3 voxels.
*   **Memory Complexity:** $O(1)$ if implemented as an iterator/generator. $O(V)$ if storing all voxels, where $V$ is the number of voxels (up to $3N$).
*   **Performance:** Slower than 26-connected traversal due to stricter connectivity checks and potential multiple emissions per step [S2, book].
*   **Strengths:** Guarantees 6-connectivity, ensuring no gaps in voxelized lines. Essential for filling interiors of triangles [S1, unofficial].
*   **Limitations:** More complex to implement than standard Bresenham. Requires handling multiple outputs per step.

## Background
The algorithm originates from a thesis on optimal scanline voxelization algorithms [S1, unofficial]. It was developed to address the lack of 6-connectivity in standard 3D Bresenham algorithms, which are insufficient for filling triangle interiors in integer-based voxelization. The modification adapts the classic Bresenham line algorithm to 3D and enforces face-sharing connectivity between consecutive voxels.
