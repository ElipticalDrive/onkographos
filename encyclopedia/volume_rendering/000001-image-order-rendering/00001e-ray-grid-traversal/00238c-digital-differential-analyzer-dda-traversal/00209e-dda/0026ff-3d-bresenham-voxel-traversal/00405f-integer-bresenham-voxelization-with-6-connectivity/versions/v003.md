# Integer Bresenham Voxelization with 6-Connectivity

Also called: 6-Connected Bresenham Algorithm Modification, 6-connected Bresenham, Discrete Ray Traversal, Modified Bresenham

## Overview
This method generates a 6-connected sequence of integer voxel coordinates intersected by a line segment, ensuring that every consecutive pair of voxels shares a face [S1, unofficial]. It solves the connectivity gap in standard Bresenham algorithms, which may skip voxels or produce 18/26-connected lines, making it essential for applications requiring strict topological continuity such as interior filling of triangles in scanline voxelization [S1, unofficial]. It differs from 26-connected traversal by being slower but more accurate for small features [S2, book].

## How it works
**Inputs:** Start voxel $(X_0, Y_0, Z_0)$, end voxel $(X_1, Y_1, Z_1)$, and a callback or iterator interface `SetVoxel(voxel)` [S1, unofficial].
**Outputs:** A sequence of voxels visited along the line [S1, unofficial].

**Data Structures:**
*   `dx, dy, dz`: Absolute differences $|X_1 - X_0|$, $|Y_1 - Y_0|$, $|Z_1 - Z_0|$ [S1, unofficial].
*   `sx, sy, sz`: Step directions ($1$ or $-1$) for each axis; $0$ if the difference is zero [S1, unofficial].
*   `A`: Index of the dominant axis ($0$ for X, $1$ for Y, $2$ for Z) [S1, unofficial].
*   `i1, i2`: Indices of the secondary axes, calculated as $(A + 1) \pmod 3$ and $(A + 2) \pmod 3$ [S1, unofficial].
*   `e1, e2`: Error accumulators for the secondary axes [S1, unofficial].
*   `C`: Array of current voxel coordinates $[x, y, z]$ [S1, unofficial].
*   `D`: Array of absolute differences $[dx, dy, dz]$ [S1, unofficial].
*   `S`: Array of step signs $[sx, sy, sz]$ [S1, unofficial].

**Parameters:**
*   Typical values are derived directly from input coordinates [S1, unofficial].
*   No fixed constants are used other than $2$ and $3$ in modulo arithmetic [S1, unofficial].

**Steps:**
1.  **Initialization:**
    *   Calculate absolute differences: $\Delta X = |X_1 - X_0|$, $\Delta Y = |Y_1 - Y_0|$, $\Delta Z = |Z_1 - Z_0|$ [S1, unofficial].
    *   Determine step signs: $sx = \text{sign}(X_1 - X_0)$, $sy = \text{sign}(Y_1 - Y_0)$, $sz = \text{sign}(Z_1 - Z_0)$ [S1, unofficial].
    *   Determine dominant axis $A$:
        $$
        A = \begin{cases} 
        0 & \text{if } \Delta X \ge \Delta Y \text{ and } \Delta X \ge \Delta Z \\
        1 & \text{if } \Delta Y > \Delta X \text{ and } \Delta Y \ge \Delta Z \\
        2 & \text{if } \Delta Z > \Delta X \text{ and } \Delta Z > \Delta Y
        \end{cases}
        $$
        [S1, unofficial]
    *   Calculate secondary indices: $i1 = (A + 1) \pmod 3$, $i2 = (A + 2) \pmod 3$ [S1, unofficial].
    *   Map values to arrays for uniform access: $D = [\Delta X, \Delta Y, \Delta Z]$, $S = [sx, sy, sz]$, $C = [X_0, Y_0, Z_0]$ [S1, unofficial].
    *   Initialize error terms for secondary axes using standard 2D Bresenham logic adapted for 3D: $e1 = 2 D[i1] - D[A]$, $e2 = 2 D[i2] - D[A]$ [S1, unofficial].
    *   Set current coordinates $C[0]=X_0, C[1]=Y_0, C[2]=Z_0$ [S1, unofficial].

2.  **Iteration:**
    *   Yield the starting voxel $(X_0, Y_0, Z_0)$ [S1, unofficial].
    *   Iterate along the dominant axis $A$ until the current coordinate equals the target coordinate [S1, unofficial].
    *   In each iteration, increment the dominant axis coordinate by its step sign [S1, unofficial].
    *   Check the error condition for the first secondary axis $i1$:
        *   If $e1 \ge 0$:
            *   If $e1 \ge D[i1]$, yield the voxel with the secondary axis $i1$ incremented: $(C[0], C[1], C[2])$ with $C[i1] + S[i1]$ [S1, unofficial].
            *   Otherwise, yield the current voxel $(C[0], C[1], C[2])$ [S1, unofficial].
            *   Increment the secondary axis coordinate $C[i1] += S[i1]$ [S1, unofficial].
            *   Update error: $e1 = e1 + 2(D[i1] - D[A])$ [S1, unofficial].
        *   Else:
            *   Update error: $e1 = e1 + 2 D[i1]$ [S1, unofficial].
    *   Check the error condition for the second secondary axis $i2$ using the same logic as for $i1$ [S1, unofficial].
    *   The algorithm may generate up to three voxels per dominant axis iteration, requiring an iterator or buffer to handle multiple outputs per step [S1, unofficial].

3.  **Termination:**
    *   After the loop, explicitly yield the final voxel at $(X_1, Y_1, Z_1)$ to resolve the pitfall where the loop condition misses the last voxel [S1, unofficial].

**Pseudocode:**
```python
def integer_bresenham_6_connected(x0, y0, z0, x1, y1, z1):
    dx = abs(x1 - x0)
    dy = abs(y1 - y0)
    dz = abs(z1 - z0)
    
    sx = 1 if x1 > x0 else (-1 if x1 < x0 else 0)
    sy = 1 if y1 > y0 else (-1 if y1 < y0 else 0)
    sz = 1 if z1 > z0 else (-1 if z1 < z0 else 0)
    
    if dx >= dy and dx >= dz:
        A = 0
    elif dy >= dx and dy >= dz:
        A = 1
    else:
        A = 2
        
    i1 = (A + 1) % 3
    i2 = (A + 2) % 3
    
    D = [dx, dy, dz]
    S = [sx, sy, sz]
    C = [x0, y0, z0]
    
    e1 = 2 * D[i1] - D[A]
    e2 = 2 * D[i2] - D[A]
    
    target = [x1, y1, z1][A]
    
    yield tuple(C)
    
    while C[A] != target:
        C[A] += S[A]
        
        if e1 >= 0:
            if e1 >= D[i1]:
                voxel = list(C)
                voxel[i1] += S[i1]
                yield tuple(voxel)
                C[i1] += S[i1]
                e1 += 2 * (D[i1] - D[A])
            else:
                yield tuple(C)
                C[i1] += S[i1]
                e1 += 2 * (D[i1] - D[A])
        else:
            e1 += 2 * D[i1]
            
        if e2 >= 0:
            if e2 >= D[i2]:
                voxel = list(C)
                voxel[i2] += S[i2]
                yield tuple(voxel)
                C[i2] += S[i2]
                e2 += 2 * (D[i2] - D[A])
            else:
                yield tuple(C)
                C[i2] += S[i2]
                e2 += 2 * (D[i2] - D[A])
        else:
            e2 += 2 * D[i2]
            
    yield tuple(C)
```

**Edge Cases and Pitfalls:**
*   **Last Voxel:** The loop condition `C[A] != target` excludes the final voxel. It must be explicitly appended after the loop [S1, unofficial].
*   **Multiple Voxels:** The algorithm can generate up to three voxels per dominant axis iteration. This conflicts with algorithms expecting a single next voxel. Implementers must use an iterator or buffer to handle this [S1, unofficial].
*   **Negative Directions:** Handled by absolute differences and sign variables [S1, unofficial].
*   **Zero Difference:** If a difference is zero, the step is $0$, and the axis does not change. The error term logic still applies but will not trigger steps if the dominant axis is not that axis [G].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the length of the line in the dominant axis. Each iteration performs constant work, but may emit up to 3 voxels [S1, unofficial].
*   **Memory Complexity:** $O(1)$ if implemented as an iterator/generator. $O(V)$ if storing all voxels, where $V$ is the number of voxels (up to $3N$) [S1, unofficial].
*   **Performance:** Slower than 26-connected traversal due to stricter connectivity checks and potential multiple emissions per step [S2, book].
*   **Strengths:** Guarantees 6-connectivity, ensuring no gaps in voxelized lines. Essential for filling interiors of triangles [S1, unofficial].
*   **Limitations:** More complex to implement than standard Bresenham. Requires handling multiple outputs per step [S1, unofficial].

## Background
The algorithm originates from a thesis on optimal scanline voxelization algorithms [S1, unofficial]. It was developed to address the lack of 6-connectivity in standard 3D Bresenham algorithms, which are insufficient for filling triangle interiors in integer-based voxelization [S1, unofficial]. The modification adapts the classic Bresenham line algorithm to 3D and enforces face-sharing connectivity between consecutive voxels [S1, unofficial].
