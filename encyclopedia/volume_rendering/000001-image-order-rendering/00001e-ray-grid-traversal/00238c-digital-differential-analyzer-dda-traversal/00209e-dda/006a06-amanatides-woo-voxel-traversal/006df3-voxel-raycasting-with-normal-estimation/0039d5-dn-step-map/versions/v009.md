# DN_step_map

Also called: Amanatides-Woo Algorithm, Amanatides and Woo algorithm, Voxel DDA, DDA Voxel Traversal

## Overview
DN_step_map is a voxel traversal algorithm that determines the sequence of voxels intersected by a ray in a regular grid without performing explicit intersection tests with voxel faces [S1, unofficial][S2][S6, unofficial]. It solves the problem of efficiently querying sparse or dense voxel structures for collision, occlusion, or surface detection by stepping through the grid along the ray direction [S16, unofficial]. It differs from fixed-step raymarching by using precomputed distance-to-boundary parameters (`tMax`) to jump directly to the next voxel boundary, ensuring exactly one voxel is processed per step and eliminating redundant checks [S6, unofficial]. It builds on [Voxel Raycasting with Normal Estimation](3901-voxel-raycasting-with-normal-estimation.md) by providing the core traversal mechanism that identifies the hit voxel and entry face, which are then used for normal estimation [S6, S7, unofficial].

## How it works
**Inputs:**
*   `rayPos`: Ray origin $(p_x, p_y, p_z)$ in world or volume coordinates [S1, S7, unofficial].
*   `rayDir`: Ray direction vector $(d_x, d_y, d_z)$ [S1, S7, unofficial]. Must be non-zero [S4, S6, unofficial].
*   `tmax`: Maximum traversal distance (parameter $t$) [S1, unofficial].
*   `voxSize`: Voxel side length (explicit scalar, typically 1.0 for unit grids) [S6, unofficial].
*   `maxSteps`: Optional integer limit to prevent infinite loops in degenerate cases (e.g., origin inside solid) [S3, S6, unofficial]. Default 1024 [S6, unofficial].

**Outputs:**
*   `hitVoxel`: Coordinates $(i, j, k)$ of the first occupied voxel [S6, S7, unofficial].
*   `hitFace`: The face entered (e.g., `neg-x`, `pos-y`) [S6, unofficial].
*   `prevEmptyVoxel`: The voxel coordinate immediately preceding the hit, useful for block placement [S6, unofficial].
*   `hitPos`: Intersection point in world coordinates [S3, unofficial].
*   `hitNormal`: Surface normal at the hit location [S3, unofficial].
*   Boolean success flag [S3, S6, unofficial].

**Data Structures:**
*   `current`: Integer tuple $(X, Y, Z)$ representing the current voxel index [S1, S6, unofficial].
*   `step`: Integer tuple $(step_x, step_y, step_z)$ indicating direction of increment ($1, -1, 0$) [S1, S6, unofficial].
*   `tMax`: Float tuple $(tMax_x, tMax_y, tMax_z)$ representing the ray parameter $t$ at which the ray crosses the next voxel boundary along each axis [S1, S6, unofficial].
*   `tDelta`: Float tuple $(tDelta_x, tDelta_y, tDelta_z)$ representing the distance between consecutive voxel boundaries along each axis [S6, unofficial].

**Steps:**

1.  **Validate Direction:**
    Calculate direction length $L = \sqrt{d_x^2 + d_y^2 + d_z^2}$. If $L < \epsilon$ (e.g., $10^{-5}$), return failure [S16, unofficial]. Normalize direction: $d_x \leftarrow d_x/L, d_y \leftarrow d_y/L, d_z \leftarrow d_z/L$ [S4, S7, unofficial].

2.  **Initialize Voxel Index:**
    Compute starting voxel indices:
    $$ X = \lfloor p_x / C \rfloor, \quad Y = \lfloor p_y / C \rfloor, \quad Z = \lfloor p_z / C \rfloor $$
    where $C$ is the voxel size [S1, S4, S7, unofficial]. Note: If the grid has an origin offset $O$, adjust: $X = \lfloor (p_x - O_x)/C \rfloor$ [S2][S6, unofficial].

3.  **Compute Step Directions:**
    For each axis $a \in \{x, y, z\}$:
    $$ step_a = \begin{cases} 1 & \text{if } d_a > 0 \\ -1 & \text{if } d_a < 0 \\ 0 & \text{if } d_a = 0 \end{cases} $$
    [S6, S7, unofficial].

4.  **Compute Delta and Initial tMax:**
    For each axis $a$:
    *   If $d_a \neq 0$:
        $$ tDelta_a = \frac{C}{|d_a|} $$
        [S6, S7, unofficial].
        Determine the next boundary coordinate $B_a$:
        $$ B_a = \begin{cases} (X + 1) \cdot C & \text{if } step_a = 1 \\ X \cdot C & \text{if } step_a = -1 \end{cases} $$
        [S6, unofficial].
        Calculate initial distance to boundary:
        $$ tMax_a = \frac{B_a - p_a}{d_a} $$
        [S6, S7, unofficial]. Note: If $d_a < 0$, the formula effectively becomes $\frac{(p_a - X \cdot C)}{|d_a|}$ [S7, unofficial].
    *   If $d_a = 0$:
        $$ tDelta_a = \infty, \quad tMax_a = \infty $$
        [S1, unofficial][S2][S7, unofficial]. This prevents division by zero and excludes the axis from traversal decisions [S1, S7, unofficial].

5.  **Traverse Loop:**
    Loop while `steps < maxSteps`:
    
    a.  **Check Current Voxel:**
        Query voxel occupancy at $(X, Y, Z)$. If occupied, return hit data:
        *   `hitVoxel` = $(X, Y, Z)$
        *   `hitPos` = $rayPos + rayDir \cdot tMax_{axis}$
        *   `hitNormal` = $(-step_x, -step_y, -step_z)$ (inward facing normal of the entry face) [S7, unofficial].
        *   `prevEmptyVoxel` = $(X - step_x, Y - step_y, Z - step_z)$ [S6, unofficial].
        *   Return success.
        
        *Pitfall:* If the ray origin is already inside an occupied voxel, the check in step 5a must occur *before* stepping, or the algorithm must handle the "inside" case explicitly to return the starting voxel as the hit [S6, S7, unofficial]. Standard DDA assumes entry from outside; if inside, the first step moves to a neighbor, potentially missing the start voxel if not checked pre-loop [S6, unofficial].

    b.  **Find Next Boundary:**
        Identify the axis with the minimum `tMax`:
        $$ axis = \arg\min_{a \in \{x,y,z\}} tMax_a $$
        [S6, S7, unofficial].
        If $tMax_{axis} > tmax$, break loop (ray exits volume) [S6, unofficial].

    c.  **Advance Ray:**
        Update current voxel index:
        $$ current_{axis} += step_{axis} $$
        [S6, S7, unofficial].
        Update `tMax_{axis}`:
        $$ tMax_{axis} += tDelta_{axis} $$
        [S6, S7, unofficial].
        Record `hitFace` based on `axis` and `step_{axis}` (e.g., if $axis=x, step_x=1$, face is `neg-x`) [S6, unofficial].

6.  **Termination:**
    If loop completes without hit, return failure [S3, S6, unofficial].

**Pseudocode:**

```python
def dn_step_map(ray_pos, ray_dir, tmax, vox_size=1.0, max_steps=1024):
    # 1. Validate and normalize direction
    dir_len = math.sqrt(ray_dir.x**2 + ray_dir.y**2 + ray_dir.z**2)
    if dir_len < 1e-5:
        return None
    
    dx = ray_dir.x / dir_len
    dy = ray_dir.y / dir_len
    dz = ray_dir.z / dir_len
    
    # 2. Initialize voxel indices
    cx = math.floor(ray_pos.x / vox_size)
    cy = math.floor(ray_pos.y / vox_size)
    cz = math.floor(ray_pos.z / vox_size)
    
    # 3. Compute step directions
    step_x = 1 if dx > 0 else (-1 if dx < 0 else 0)
    step_y = 1 if dy > 0 else (-1 if dy < 0 else 0)
    step_z = 1 if dz > 0 else (-1 if dz < 0 else 0)
    
    # 4. Compute tDelta and tMax
    if dx != 0:
        t_delta_x = vox_size / abs(dx)
        next_bnd_x = (cx + (1 if step_x > 0 else 0)) * vox_size
        t_max_x = (next_bnd_x - ray_pos.x) / dx
    else:
        t_delta_x = float('inf')
        t_max_x = float('inf')
        
    if dy != 0:
        t_delta_y = vox_size / abs(dy)
        next_bnd_y = (cy + (1 if step_y > 0 else 0)) * vox_size
        t_max_y = (next_bnd_y - ray_pos.y) / dy
    else:
        t_delta_y = float('inf')
        t_max_y = float('inf')
        
    if dz != 0:
        t_delta_z = vox_size / abs(dz)
        next_bnd_z = (cz + (1 if step_z > 0 else 0)) * vox_size
        t_max_z = (next_bnd_z - ray_pos.z) / dz
    else:
        t_delta_z = float('inf')
        t_max_z = float('inf')
        
    # 5. Traverse
    for _ in range(max_steps):
        # Query voxel occupancy at (cx, cy, cz) [G]
        is_occupied = False # Placeholder for grid lookup [G]
        if is_occupied:
            # Find min tMax for hit position
            if t_max_x <= t_max_y and t_max_x <= t_max_z:
                t_hit = t_max_x
            elif t_max_y <= t_max_z:
                t_hit = t_max_y
            else:
                t_hit = t_max_z
                
            hit_pos = (ray_pos.x + dx * t_hit, ray_pos.y + dy * t_hit, ray_pos.z + dz * t_hit)
            hit_normal = (-step_x, -step_y, -step_z)
            prev_voxel = (cx - step_x, cy - step_y, cz - step_z)
            return {
                'hitVoxel': (cx, cy, cz),
                'hitPos': hit_pos,
                'hitNormal': hit_normal,
                'prevEmptyVoxel': prev_voxel
            }
            
        # Find minimum tMax
        if t_max_x <= t_max_y and t_max_x <= t_max_z:
            axis = 'x'
            t_max = t_max_x
        elif t_max_y <= t_max_z:
            axis = 'y'
            t_max = t_max_y
        else:
            axis = 'z'
            t_max = t_max_z
            
        if t_max > tmax:
            break
            
        # Advance
        if axis == 'x':
            cx += step_x
            t_max_x += t_delta_x
            hit_face = 'neg-x' if step_x < 0 else 'pos-x'
        elif axis == 'y':
            cy += step_y
            t_max_y += t_delta_y
            hit_face = 'neg-y' if step_y < 0 else 'pos-y'
        else:
            cz += step_z
            t_max_z += t_delta_z
            hit_face = 'neg-z' if step_z < 0 else 'pos-z'
            
    return None
```

## Subtopics

### [Voxel Raycast (Nonzero/Color Channel)](12412-voxel-raycast-nonzero-color-channel.md)
This method performs hidden surface elimination by casting a ray through a binary voxel volume to locate the first voxel where a specific data channel is non-zero. It differs from standard DDA traversal by optimizing for sparse or binary data: it processes voxels in groups of eight packed into a single byte, advancing the ray by whole bytes when the group is empty, thereby skipping large empty regions efficiently. This approach is distinct from sibling methods that use adaptive edge smoothing or neighbor-averaged interpolation, as it relies on strict bitwise presence checks rather than continuous field evaluation.

### [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md)
This method extends standard DDA raymarching by sampling corner and edge voxel occupancy to adaptively compute volume content, eliminating stepping artifacts and spikes caused by uniform voxel traversal. Unlike standard DDA which steps uniformly through fixed voxels, this technique smooths terrain surfaces without increasing the step count or requiring geometry subdivision. It builds on [DN_step_map](8596-dn-step-map.md) by refining the surface normal and volume estimation at the hit voxel.

### [Corner-based Voxel Volume Calculation](14665-corner-based-voxel-volume-calculation.md)
A technique to compute voxel volume values at corners for smooth terrain rendering, replacing side-based volume storage with corner-based values to better represent surface geometry during raymarching. It sets apart from sibling methods by explicitly handling diagonal neighbors (NW, NE, SW, SE) and applying "surface block maxing" to clamp volumes at surface boundaries, whereas siblings like [Midpoint UV Calculation](14669-midpoint-uv-calculation.md) focus on interpolation precision or [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md) focus on edge artifacts without the specific corner-maxing logic.

### [Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation](14668-voxel-dda-raymarching-with-neighbor-averaged-entry-interpola.md)
A voxel raymarching technique that calculates smooth surface entry heights by averaging adjacent voxel volume/height values and interpolating based on the ray's entry position within the cube. It improves upon simple linear interpolation between two voxels by using neighbor-averaged face heights, though it initially ignores the center voxel's influence, leading to sharp edges.

### [Midpoint UV Calculation](14669-midpoint-uv-calculation.md)
Midpoint UV Calculation computes the UV coordinates of the midpoint plane within a voxel traversal step to determine height and lighting variations for surface rendering. It sets apart from sibling methods by explicitly calculating a geometric midpoint between entry and exit UV states to drive height maps, whereas siblings like [Corner-based Voxel Volume Calculation](14665-corner-based-voxel-volume-calculation.md) rely on corner interpolation and [Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation](14668-voxel-dda-raymarching-with-neighbor-averaged-entry-interpola.md) focus on entry-point smoothing.

### [Bresenham Voxel Traversal](16523-bresenham-voxel-traversal.md)
Bresenham Voxel Traversal is a discrete voxel traversal algorithm that uses an integral error-accumulation method to step through voxels along the dominant axis of a ray. It serves as an alternative to floating-point DDA methods by relying on integer arithmetic for axis increments, which can offer performance benefits in specific hardware or software contexts. It differs from its parent [DN_step_map](8596-dn-step-map.md) by generating a full sequence of visited voxel coordinates rather than just the first hit, and from siblings like [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md) by using a strict integer-based decision logic rather than floating-point distance comparisons.

### [Voxel Grid Ray Marching](16938-voxel-grid-ray-marching.md)
Voxel Grid Ray Marching is an algorithm to traverse a 3D voxel grid along a ray, returning the IDs of all visited cells. It handles rays starting outside the grid by computing the entry point intersection with the bounding box. It builds on [DN_step_map](8596-dn-step-map.md), which casts a ray into the voxel volume to find the first intersecting voxel, returning hit position, voxel data, and surface normal.

### Neighbor Voxel Volume Sampling
Reads adjacent voxel volumes at ray entry and exit positions to adjust traversal behavior, preventing artifacts such as floating voxels, flat edges, and incorrect slope rendering [S21, unofficial]. When exiting a voxel, it calculates the exit voxel's grid position by adding the current position, the step direction mask, and an offset derived from the mask [S21, unofficial]. When entering a voxel, it calculates the entry voxel's grid position using the same mask-based offset logic, ensuring the offset is negative or adjusted for entry direction [S21, unofficial]. It samples the volume value from the calculated adjacent voxel and uses it to modify the ray's exit behavior or skip logic [S21, unofficial]. Pitfall: Reading adjacent voxels can impact performance, though the author notes it may not significantly affect frame rate on small maps [S21, unofficial].

### [Voxel DDA Face Entry/Exit UV Mapping](14681-voxel-dda-face-entry-exit-uv-mapping.md)
Checks the entry mask to determine which face (X, Y, or Z) the ray enters the voxel. If entering from the left/back, it sets the start UV to the back face and interpolates toward the center. If entering from the right/front, it sets the start UV to the front face and interpolates toward the right/center. Pitfall: Using integer division for UV coordinate calculations causes terrain vertices to fail to connect across voxel edges; all coordinate math must use floating-point types.

### Thickness Computation
An algorithm to compute the thickness of a ray traversal through an object by counting boundary voxels and accumulating thickness based on the angle of traversal [S22, unofficial]. It uses parameters $\theta$ (the angle between the view and the slice index increasing direction) and `thickness` (the thickness of each slice) [S22, unofficial]. The logic initializes `ThickSum = 0`, `SurfaceCount = 0`, and `Inside = false`, then iterates through slices: if a voxel is a boundary voxel, it toggles `Inside` and increments `SurfaceCount`; if `Inside` is true, it adds `thickness/cos(\theta)` to `ThickSum` [S22, unofficial]. If `SurfaceCount >= 2` and is even, it returns `ThickSum` as the thickness and marks the pixel as OK; otherwise, it marks the pixel as questionable [S22, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(k)$, where $k$ is the number of voxels traversed along the ray. Each step involves constant-time comparisons and updates [S1, S6, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space, excluding the voxel grid storage itself [S1, unofficial].
*   **Strengths:** Deterministic traversal order; efficient handling of axis-aligned grids; robust handling of parallel rays (via infinity handling) [S1, S7, unofficial].
*   **Limitations:** Does not handle non-axis-aligned voxel grids (e.g., rotated or skewed) without modification [S1, unofficial]. Precision issues may arise with very large coordinates or very small voxel sizes due to floating-point accumulation in `tMax` [G]. Requires careful handling of ray origins inside occupied voxels [S6, unofficial].
*   **When to use:** Collision detection, occlusion culling, and surface picking in voxel-based worlds [S6, S7, unofficial].
*   **When not to use:** When smooth, continuous field evaluation is required without discrete stepping (use [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md) instead) [S1, unofficial].

## Background
The algorithm is based on the Amanatides & Woo method, originally published in 1986 for ray tracing through voxel grids [S1, unofficial][S2]. It is widely implemented in voxel engines for efficient raycasting [S6, S7, unofficial]. Variants are used in game development for terrain interaction and in scientific visualization for volume rendering [S3, unofficial][S5, unofficial].
