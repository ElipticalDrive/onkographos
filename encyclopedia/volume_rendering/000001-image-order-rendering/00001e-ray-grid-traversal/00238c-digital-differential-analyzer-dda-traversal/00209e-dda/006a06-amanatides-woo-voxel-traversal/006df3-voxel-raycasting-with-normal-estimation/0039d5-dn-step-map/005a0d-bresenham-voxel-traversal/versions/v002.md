# Bresenham Voxel Traversal

Also called: Bresenham-like Voxel Traversal, MarchRayVoxelBresenham, Ray-Voxel Grid Intersection (Bresenham)

## Overview
Bresenham Voxel Traversal is a discrete voxel traversal algorithm that uses an integral error-accumulation method to step through voxels along the dominant axis of a ray [S1, unofficial]. It generates a full sequence of visited voxel coordinates rather than just the first hit, and differs from floating-point DDA variants by relying on integer-like error accumulation for axis increments [S1, unofficial].

## How it works
**Inputs:** Ray origin $O$, ray direction $D$ (normalized), voxel grid dimensions $(W, H, Z)$, and a ray-cube intersection function `RayCubeSlabsIntersection` that returns the entry parameter $t_{entry}$ and exit parameter $t_{exit}$ of the ray with the bounding box of the grid [S1, unofficial].
**Outputs:** A list of 3D integer coordinates $(i, j, k)$ representing the sequence of voxels visited by the ray [S1, unofficial].

**Data Structures:**
- `vec3`: A 3D vector type with components $x, y, z$.
- `vector<vec3>`: A dynamic array of 3D vectors.
- Integers: `ii, jj, kk` for voxel indices; `dx, dy, dz` for ray deltas; `err_1, err_2` for error terms.

**Parameters:**
- `EPSILON`: A small positive constant to handle precision issues and boundary conditions [S1, unofficial].
- `quality`: A switch case value determining the rendering mode (0-4), though the traversal logic itself is independent of this switch in the source code [S1, unofficial].

**Steps:**

1.  **Ray-Grid Intersection:**
    Compute the intersection of the ray with the grid's bounding box using `RayCubeSlabsIntersection`. Let the result be $t_{entry}$ and $t_{exit}$ [S1, unofficial].
    If $t_{entry} < \text{EPSILON}$, the ray does not intersect the grid (or starts inside but exits immediately in a degenerate case) [S1, unofficial]. Push $(-1, -1, -1)$ to the output list and return [S1, unofficial].

2.  **Determine Start and End Points:**
    Calculate the start point $P_{start}$ and end point $P_{end}$ of the ray segment within the grid [S1, unofficial].
    - If the ray origin $O$ is outside the grid, $P_{start} = O + (t_{entry} + \text{EPSILON}) \cdot D$ [S1, unofficial].
    - If the ray origin $O$ is inside the grid, $P_{start} = O$ [S1, unofficial].
    - $P_{end}$ is computed similarly using $t_{exit}$ [S1, unofficial].

3.  **Calculate Deltas and Increments:**
    Calculate deltas $dx, dy, dz$ as the difference in world coordinates between $P_{end}$ and $P_{start}$ [S1, unofficial].
    - $dx = P_{end}.x - P_{start}.x$
    - $dy = P_{end}.y - P_{start}.y$
    - $dz = P_{end}.z - P_{start}.z$
    
    Calculate lengths along each axis. The source code uses `x_length`, `y_length`, `z_length` [S1, unofficial]. These are the absolute values of the deltas, representing the number of steps along each axis [S1, unofficial]. Let $L_x = |dx|$, $L_y = |dy|$, $L_z = |dz|$.
    
    Determine increments:
    - $x_{inc} = \text{sign}(dx)$
    - $y_{inc} = \text{sign}(dy)$
    - $z_{inc} = \text{sign}(dz)$
    
    Multiply deltas by 2 for integer arithmetic simulation:
    - $dx2 = 2 \cdot dx$
    - $dy2 = 2 \cdot dy$
    - $dz2 = 2 \cdot dz$
    
    [G] The source code uses `x_length`, `y_length`, `z_length` in the loop condition and error initialization. These are the integer step counts along each axis. We compute $N_x = \lceil L_x \rceil$, $N_y = \lceil L_y \rceil$, $N_z = \lceil L_z \rceil$. If any length is 0, it is set to 1 to avoid degenerate loops.

4.  **Determine Dominant Axis:**
    Identify the axis with the maximum absolute delta (or length). Let this be the dominant axis [S1, unofficial].
    - If $|dx| \ge |dy|$ and $|dx| \ge |dz|$, X is dominant.
    - If $|dy| \ge |dx|$ and $|dy| \ge |dz|$, Y is dominant.
    - If $|dz| \ge |dx|$ and $|dz| \ge |dy|$, Z is dominant.

5.  **Traverse Voxels:**
    Initialize the current voxel position $(i, j, k)$ to the voxel containing $P_{start}$ [S1, unofficial].
    [G] The source code initializes `point` implicitly or via the loop. We assume $(i, j, k)$ is the integer voxel index of $P_{start}$, computed as $\lfloor P_{start}.x \rfloor, \lfloor P_{start}.y \rfloor, \lfloor P_{start}.z \rfloor$.

    **Case 1: X is dominant**
    - Initialize error terms:
      - $err_1 = dy2 - x_{length}$
      - $err_2 = dz2 - x_{length}$
    - Loop `ii` from 0 to `x_length` (exclusive):
      - Push current point $(i, j, k)$ to output.
      - If $err_1 > 0$:
        - $j += y_{inc}$
        - $err_1 -= dx2$
      - If $err_2 > 0$:
        - $k += z_{inc}$
        - $err_2 -= dx2$
      - $err_1 += dy2$
      - $err_2 += dz2$
      - $i += x_{inc}$
    - Push final point $(i, j, k)$ after the loop [S1, unofficial].

    **Case 2: Y is dominant**
    - Initialize error terms:
      - $err_1 = dx2 - y_{length}$
      - $err_2 = dz2 - y_{length}$
    - Loop `ii` from 0 to `y_length` (exclusive):
      - Push current point $(i, j, k)$ to output.
      - If $err_1 > 0$:
        - $i += x_{inc}$
        - $err_1 -= dy2$
      - If $err_2 > 0$:
        - $k += z_{inc}$
        - $err_2 -= dy2$
      - $err_1 += dx2$
      - $err_2 += dz2$
      - $j += y_{inc}$
    - Push final point $(i, j, k)$ after the loop [S1, unofficial].

    **Case 3: Z is dominant**
    - Initialize error terms:
      - $err_1 = dy2 - z_{length}$
      - $err_2 = dx2 - z_{length}$
    - Loop `ii` from 0 to `z_length` (exclusive):
      - Push current point $(i, j, k)$ to output.
      - If $err_1 > 0$:
        - $j += y_{inc}$
        - $err_1 -= dz2$
      - If $err_2 > 0$:
        - $i += x_{inc}$
        - $err_2 -= dz2$
      - $err_1 += dy2$
      - $err_2 += dx2$
      - $k += z_{inc}$
    - Push final point $(i, j, k)$ after the loop [S1, unofficial].

**Pseudocode:**

```python
def bresenham_voxel_traversal(origin, direction, grid_width, grid_height, grid_depth, ray_cube_intersection):
    """
    Traverses a voxel grid using Bresenham-like integer arithmetic.
    
    Args:
        origin: vec3, ray origin
        direction: vec3, normalized ray direction
        grid_width: int, number of voxels in X
        grid_height: int, number of voxels in Y
        grid_depth: int, number of voxels in Z
        ray_cube_intersection: function, returns (t_entry, t_exit) for ray and grid bounding box
        
    Returns:
        list of vec3, voxel coordinates visited
    """
    # 1. Ray-Grid Intersection
    t_entry, t_exit = ray_cube_intersection(origin, direction, grid_width, grid_height, grid_depth)
    
    EPSILON = 1e-6
    if t_entry < EPSILON:
        return [vec3(-1, -1, -1)]
    
    # 2. Determine Start and End Points
    # Check if origin is inside grid
    ox, oy, oz = origin
    inside_x = 0 <= ox < grid_width
    inside_y = 0 <= oy < grid_height
    inside_z = 0 <= oz < grid_depth
    
    if not (inside_x and inside_y and inside_z):
        start_point = origin + (t_entry + EPSILON) * direction
    else:
        start_point = origin
        
    end_point = origin + t_exit * direction
    
    # 3. Calculate Deltas and Increments
    dx = end_point.x - start_point.x
    dy = end_point.y - start_point.y
    dz = end_point.z - start_point.z
    
    # Convert to voxel steps (absolute lengths)
    x_length = max(1, int(abs(dx)))
    y_length = max(1, int(abs(dy)))
    z_length = max(1, int(abs(dz)))
    
    dx2 = 2 * dx
    dy2 = 2 * dy
    dz2 = 2 * dz
    
    x_inc = 1 if dx > 0 else (-1 if dx < 0 else 0)
    y_inc = 1 if dy > 0 else (-1 if dy < 0 else 0)
    z_inc = 1 if dz > 0 else (-1 if dz < 0 else 0)
    
    # 4. Determine Dominant Axis
    abs_dx = abs(dx)
    abs_dy = abs(dy)
    abs_dz = abs(dz)
    
    # 5. Traverse Voxels
    # Initialize current voxel position
    i = int(start_point.x)
    j = int(start_point.y)
    k = int(start_point.z)
    
    # Clamp to grid bounds
    i = max(0, min(i, grid_width - 1))
    j = max(0, min(j, grid_height - 1))
    k = max(0, min(k, grid_depth - 1))
    
    points = []
    
    if abs_dx >= abs_dy and abs_dx >= abs_dz:
        # X is dominant
        err_1 = dy2 - x_length
        err_2 = dz2 - x_length
        
        for _ in range(x_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                j += y_inc
                err_1 -= dx2
            if err_2 > 0:
                k += z_inc
                err_2 -= dx2
                
            err_1 += dy2
            err_2 += dz2
            i += x_inc
            
        points.append(vec3(i, j, k))
        
    elif abs_dy >= abs_dx and abs_dy >= abs_dz:
        # Y is dominant
        err_1 = dx2 - y_length
        err_2 = dz2 - y_length
        
        for _ in range(y_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                i += x_inc
                err_1 -= dy2
            if err_2 > 0:
                k += z_inc
                err_2 -= dy2
                
            err_1 += dx2
            err_2 += dz2
            j += y_inc
            
        points.append(vec3(i, j, k))
        
    else:
        # Z is dominant
        err_1 = dy2 - z_length
        err_2 = dx2 - z_length
        
        for _ in range(z_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                j += y_inc
                err_1 -= dz2
            if err_2 > 0:
                i += x_inc
                err_2 -= dz2
                
            err_1 += dy2
            err_2 += dx2
            k += z_inc
            
        points.append(vec3(i, j, k))
        
    return points
```

**Edge Cases and Pitfalls:**
- **Precision:** The use of integer arithmetic avoids floating-point accumulation errors but may suffer from quantization errors if the ray direction is not well-aligned with the grid [S1, unofficial].
- **Boundaries:** The source code does not explicitly show boundary checks within the loop. It is assumed that the ray-cube intersection ensures the start and end points are within the grid, and the increments keep the voxel indices within bounds [S1, unofficial]. If the ray starts exactly on a boundary, care must be taken to avoid double-counting or missing voxels.
- **Degenerate Input:** If the ray direction is zero or the ray does not intersect the grid, the algorithm handles it by returning $(-1, -1, -1)$ [S1, unofficial]. If the ray is parallel to an axis, the dominant axis logic still holds, but the error terms for the non-dominant axes will be zero, resulting in no increments along those axes.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels intersected by the ray. The number of steps is proportional to the length of the ray segment within the grid.
- **Memory Complexity:** $O(N)$ to store the list of visited voxels.
- **Performance:** Integer arithmetic is generally faster than floating-point arithmetic on many hardware platforms, making this method potentially faster than DDA-based methods in software implementations. However, the lack of early-out optimizations (like stopping when a certain density threshold is reached) may lead to unnecessary computations in sparse volumes.
- **Strengths:** Simple implementation, no floating-point accumulation errors, deterministic behavior.
- **Limitations:** Less flexible than DDA methods for adaptive stepping or non-uniform voxel sizes. May visit more voxels than necessary if the ray passes through empty space.

## Background
The Bresenham Voxel Traversal algorithm is used in the `MarchRayVoxel` function to generate a sequence of voxel coordinates for light transmittance calculations [S1, unofficial]. The method is applied within volumetric rendering pipelines to step through voxel grids along ray paths.
