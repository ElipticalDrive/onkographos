# DN_step_map

Also called: Amanatides & Woo Ray Traversal, Digital Differential Analyzer raycast, Voxel Grid Raycasting (DDA), Voxel Raycasting / 3D DDA Block Traversal

## Overview
DN_step_map is a voxel grid traversal algorithm that determines the sequence of voxels intersected by a ray without performing explicit intersection tests with voxel faces [S1, S2, S6, S7, unofficial]. It solves the problem of efficiently querying sparse or dense voxel structures for collision, occlusion, or surface detection by stepping through the grid cell-by-cell along the ray direction [S6, S7, unofficial]. It differs from fixed-step raymarching by using precomputed distance-to-boundary parameters (`tMax`) to jump directly to the next voxel boundary, ensuring exactly one voxel is processed per step and eliminating redundant checks [S6, S7, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $P = (p_x, p_y, p_z)$, ray direction $D = (d_x, d_y, d_z)$, maximum traversal distance $t_{max}$ (or max step count), and voxel grid dimensions/bounds.
*   **Output:** The index/coordinates of the first occupied voxel, the entry face normal, and optionally the previous empty voxel [S3, S6, S7, unofficial].

**Data Structures:**
The algorithm maintains state variables for each axis $A \in \{x, y, z\}$:
*   `current_index[A]`: Integer voxel coordinate (e.g., $X, Y, Z$).
*   `step[A]`: Integer direction of increment ($1, -1, 0$).
*   `t_max[A]`: Floating-point distance along the ray to the next voxel boundary on axis $A$.
*   `t_adv[A]` (or `t_delta[A]`): Floating-point distance along the ray to traverse one full voxel cell on axis $A$.

**Numbered Steps:**

1.  **Validation:** If the direction vector magnitude is zero (or below a threshold like $10^{-5}$ or `EPSILON`), return null/no hit [S4, S7, unofficial].
2.  **Initialization:**
    *   Compute initial voxel indices: $X = \lfloor p_x \rfloor$, $Y = \lfloor p_y \rfloor$, $Z = \lfloor p_z \rfloor$ [S1, S7, unofficial].
    *   Normalize direction $D$ if not already unit length [S4, S7, unofficial].
    *   Compute inverse direction components: $inv_x = 1.0 / |d_x|$ (or $\infty$ if $d_x=0$), similarly for $y, z$ [S7, unofficial].
    *   Determine step directions: $step_x = \text{sign}(d_x)$, $step_y = \text{sign}(d_y)$, $step_z = \text{sign}(d_z)$ [S7, unofficial]. If $d_x=0$, $step_x=0$ [S1, unofficial].
    *   Compute initial distances to the next boundary:
        *   If $d_x > 0$: $t_{max\_x} = (X + 1 - p_x) \cdot inv_x$ [S1, S7, unofficial].
        *   If $d_x < 0$: $t_{max\_x} = (X - p_x) \cdot inv_x$ [S1, S7, unofficial].
        *   If $d_x = 0$: $t_{max\_x} = \infty$ [S1, S7, unofficial].
        *   Repeat for $y$ and $z$ [S1, unofficial].
    *   Compute advance distances: $t_{adv\_x} = |inv_x|$ (or $\infty$ if $d_x=0$) [S1, S6, unofficial].
3.  **Start Check (Optional but Recommended):** Check if the starting voxel $(X, Y, Z)$ is occupied. If the origin is inside an occupied voxel, return it immediately with a specific "inside" face or zero normal [S6, S7, G, unofficial]. *Note: Some implementations skip this and rely on the loop, but this causes errors if the camera starts inside a solid block [S6, unofficial].*
4.  **Traversal Loop:**
    *   Iterate while $t < t_{max}$ and step count $< HARD\_STEP\_CAP$ (e.g., 1024) [S1, S6, S7, unofficial].
    *   Find the axis with the minimum $t_{max}$: $axis = \arg\min(t_{max\_x}, t_{max\_y}, t_{max\_z})$ [S6, S7, unofficial].
    *   If the minimum $t_{max}$ exceeds $t_{max}$, terminate (ray exited volume) [S6, S7, unofficial].
    *   **Step:**
        *   Advance ray parameter: $t = \min(t, t_{max}[axis])$ [S1, S7, unofficial].
        *   Update voxel index: $current\_index[axis] += step[axis]$ [S1, S6, S7, unofficial].
        *   Update boundary distance: $t_{max}[axis] += t_{adv}[axis]$ [S1, S6, S7, unofficial].
    *   **Check Occupancy:** Query the voxel at $(current\_index_x, current\_index_y, current\_index_z)$ [S4, S6, S7, unofficial].
    *   If occupied, return hit data (position, face normal, voxel data) [S3, S6, S7, unofficial].
    *   Determine entry face normal based on which axis was stepped and the step direction (e.g., if $x$ stepped by $+1$, normal is $(-1, 0, 0)$) [S6, S7, unofficial].

**Pseudocode:**

```python
def dn_step_map(origin, direction, max_dist, is_occupied_func):
    # 1. Validation
    dir_len = math.sqrt(direction.x**2 + direction.y**2 + direction.z**2)
    if dir_len < 1e-5:
        return None
    
    # Normalize direction
    dir_x = direction.x / dir_len
    dir_y = direction.y / dir_len
    dir_z = direction.z / dir_len
    
    # 2. Initialization
    # Initial voxel indices
    curr_x = math.floor(origin.x)
    curr_y = math.floor(origin.y)
    curr_z = math.floor(origin.z)
    
    # Step directions
    step_x = 1 if dir_x > 0 else (-1 if dir_x < 0 else 0)
    step_y = 1 if dir_y > 0 else (-1 if dir_y < 0 else 0)
    step_z = 1 if dir_z > 0 else (-1 if dir_z < 0 else 0)
    
    # Inverse direction magnitudes
    inv_x = 1.0 / abs(dir_x) if abs(dir_x) > 1e-9 else float('inf')
    inv_y = 1.0 / abs(dir_y) if abs(dir_y) > 1e-9 else float('inf')
    inv_z = 1.0 / abs(dir_z) if abs(dir_z) > 1e-9 else float('inf')
    
    # Initial t_max (distance to next boundary)
    if dir_x > 0:
        t_max_x = (curr_x + 1 - origin.x) * inv_x
    elif dir_x < 0:
        t_max_x = (curr_x - origin.x) * inv_x
    else:
        t_max_x = float('inf')
        
    if dir_y > 0:
        t_max_y = (curr_y + 1 - origin.y) * inv_y
    elif dir_y < 0:
        t_max_y = (curr_y - origin.y) * inv_y
    else:
        t_max_y = float('inf')
        
    if dir_z > 0:
        t_max_z = (curr_z + 1 - origin.z) * inv_z
    elif dir_z < 0:
        t_max_z = (curr_z - origin.z) * inv_z
    else:
        t_max_z = float('inf')
        
    # Advance distances (t_delta)
    t_adv_x = inv_x
    t_adv_y = inv_y
    t_adv_z = inv_z
    
    # Max traversal parameter
    max_t = max_dist / dir_len # If direction was not normalized, use max_dist directly if dir is unit
    
    # 3. Start Check (Handle origin inside occupied voxel)
    if is_occupied_func(curr_x, curr_y, curr_z):
        return {
            "hitVoxel": {"i": curr_x, "j": curr_y, "k": curr_z},
            "hitFace": "inside",
            "prevEmptyVoxel": {"i": curr_x, "j": curr_y, "k": curr_z}
        }

    # 4. Traversal Loop
    for _ in range(1024): # HARD_STEP_CAP
        # Find minimum t_max
        if t_max_x <= t_max_y and t_max_x <= t_max_z:
            axis = 'x'
            t_max = t_max_x
        elif t_max_y <= t_max_z:
            axis = 'y'
            t_max = t_max_y
        else:
            axis = 'z'
            t_max = t_max_z
            
        if t_max > max_t:
            return None # Ray exceeded max reach
            
        # Step
        if axis == 'x':
            curr_x += step_x
            t_max_x += t_adv_x
            face = "neg-x" if step_x > 0 else "pos-x"
        elif axis == 'y':
            curr_y += step_y
            t_max_y += t_adv_y
            face = "neg-y" if step_y > 0 else "pos-y"
        else:
            curr_z += step_z
            t_max_z += t_adv_z
            face = "neg-z" if step_z > 0 else "pos-z"
            
        # Check occupancy
        if is_occupied_func(curr_x, curr_y, curr_z):
            # Calculate previous empty voxel for placement logic
            prev_x, prev_y, prev_z = curr_x, curr_y, curr_z
            if axis == 'x': prev_x -= step_x
            elif axis == 'y': prev_y -= step_y
            else: prev_z -= step_z
            
            return {
                "hitVoxel": {"i": curr_x, "j": curr_y, "k": curr_z},
                "hitFace": face,
                "prevEmptyVoxel": {"i": prev_x, "j": prev_y, "k": prev_z}
            }
            
    return None
```

## Subtopics

### [Voxel Raycast (Nonzero/Color Channel)](12412-voxel-raycast-nonzero-color-channel.md)
This method performs hidden surface elimination by casting a ray through a binary voxel volume to locate the first voxel where a specific data channel is non-zero. It differs from standard DDA traversal by optimizing for sparse or binary data: it processes voxels in groups of eight packed into a single byte, advancing the ray by whole bytes when the group is empty, thereby skipping large empty regions efficiently. This approach is distinct from sibling methods that use adaptive edge smoothing or neighbor-averaged interpolation, as it relies on strict bitwise presence checks rather than continuous field evaluation.

### [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md)
This method extends standard DDA raymarching by sampling corner and edge voxel occupancy to adaptively compute volume content, eliminating stepping artifacts and spikes caused by uniform voxel traversal. Unlike standard DDA which steps uniformly through fixed voxels, this technique smooths terrain surfaces without increasing the step count or requiring geometry subdivision. It builds on DN_step_map by refining the surface normal and volume estimation at the hit voxel.

### [Corner-based Voxel Volume Calculation](14665-corner-based-voxel-volume-calculation.md)
A technique to compute voxel volume values at corners for smooth terrain rendering, replacing side-based volume storage with corner-based values to better represent surface geometry during raymarching. It sets apart from sibling methods by explicitly handling diagonal neighbors (NW, NE, SW, SE) and applying "surface block maxing" to clamp volumes at surface boundaries, whereas siblings like Midpoint UV Calculation focus on interpolation precision or Voxel DDA Raymarching with Adaptive Edge Smoothing focus on edge artifacts without the specific corner-maxing logic.

### [Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation](14668-voxel-dda-raymarching-with-neighbor-averaged-entry-interpola.md)
A voxel raymarching technique that calculates smooth surface entry heights by averaging adjacent voxel volume/height values and interpolating based on the ray's entry position within the cube. It improves upon simple linear interpolation between two voxels by using neighbor-averaged face heights, though it initially ignores the center voxel's influence, leading to sharp edges.

### [Midpoint UV Calculation](14669-midpoint-uv-calculation.md)
Midpoint UV Calculation computes the UV coordinates of the midpoint plane within a voxel traversal step to determine height and lighting variations for surface rendering. It sets apart from sibling methods by explicitly calculating a geometric midpoint between entry and exit UV states to drive height maps, whereas siblings like Corner-based Voxel Volume Calculation rely on corner interpolation and Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation focus on entry-point smoothing.

### [Bresenham Voxel Traversal](16523-bresenham-voxel-traversal.md)
Bresenham Voxel Traversal is a discrete voxel traversal algorithm that uses an integral error-accumulation method to step through voxels along the dominant axis of a ray. It serves as an alternative to floating-point DDA methods by relying on integer arithmetic for axis increments, which can offer performance benefits in specific hardware or software contexts. It differs from its parent DN_step_map by generating a full sequence of visited voxel coordinates rather than just the first hit, and from siblings like Voxel DDA Raymarching with Adaptive Edge Smoothing by using a strict integer-based decision logic rather than floating-point distance comparisons.

### Neighbor Voxel Volume Sampling
Reads adjacent voxel volumes at ray entry and exit positions to adjust traversal behavior, preventing artifacts such as floating voxels, flat edges, and incorrect slope rendering [S8, unofficial]. When exiting a voxel, it calculates the exit voxel's grid position by adding the current position, the step direction mask, and an offset derived from the mask. When entering a voxel, it calculates the entry voxel's grid position using the same mask-based offset logic, ensuring the offset is negative or adjusted for entry direction. It samples the volume value from the calculated adjacent voxel and uses it to modify the ray's exit behavior or skip logic [S8, unofficial]. Pitfall: Reading adjacent voxels can impact performance, though the author notes it may not significantly affect frame rate on small maps [S8, unofficial].

### Voxel DDA Face Entry/Exit UV Mapping
Checks the entry mask to determine which face (X, Y, or Z) the ray enters the voxel. If entering from the left/back, it sets the start UV to the back face and interpolates toward the center. If entering from the right/front, it sets the start UV to the front face and interpolates toward the right/center [S8, unofficial]. Pitfall: Using integer division for UV coordinate calculations causes terrain vertices to fail to connect across voxel edges. All coordinate math must use floating-point types [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(k)$, where $k$ is the number of voxels traversed along the ray. Each step involves constant-time comparisons and updates [S1, S6, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space, excluding the voxel grid storage itself [S1, S6, unofficial].
*   **Performance:** Significantly faster than fixed-step raymarching for sparse or large grids because it skips empty space by jumping directly to boundaries [S6, unofficial]. It avoids expensive trigonometric or intersection calculations per voxel [S1, unofficial].
*   **Strengths:** Deterministic, robust, handles degenerate rays (parallel to axes) gracefully by setting `t_max` to infinity [S1, S7, unofficial]. Efficient for collision detection and occlusion queries [S6, unofficial].
*   **Limitations:** Does not provide sub-voxel precision for the hit position without additional interpolation [S6, unofficial]. Requires careful handling of the starting voxel if the ray origin is inside an occupied cell [S6, unofficial].
*   **When to use:** Collision detection, occlusion culling, and finding the first surface in voxel-based games or simulations [S6, S7, unofficial].
*   **When not to use:** When sub-voxel accuracy is required without post-processing, or when the ray needs to sample continuous values throughout the volume (use raymarching instead) [S6, unofficial].

## Background
The algorithm is based on the Amanatides & Woo method, originally published in 1987 for ray tracing through voxel grids [S1, S2, unofficial]. It is widely implemented in voxel engines, game development tools (e.g., Godot Voxel Tools, Splatcarve), and custom rendering engines (e.g., DoonEngine, NV2 Engine) for efficient spatial queries [S3, unofficial][S5][S6, S7, unofficial]. The method is a staple in computer graphics for its simplicity and efficiency in discrete grid traversal [S1, S2, unofficial].
