# Bresenham Voxel Traversal

Also called: Bresenham-like Voxel Traversal, MarchRayVoxelBresenham, Ray-Voxel Grid Intersection (Bresenham)

## Overview
Bresenham Voxel Traversal is a discrete voxel traversal algorithm that uses an integral error-accumulation method to step through voxels along the dominant axis of a ray [S1, unofficial]. It serves as an alternative to floating-point DDA methods by relying on integer arithmetic for axis increments, which can offer performance benefits in specific hardware or software contexts [S1, unofficial]. It differs from its parent [DN_step_map](8596-dn-step-map.md) by generating a full sequence of visited voxel coordinates rather than just the first hit, and from siblings like [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md) by using a strict integer-based decision logic rather than floating-point distance comparisons.

## How it works
**Inputs:** Ray origin $O$, ray direction $D$ (normalized), voxel grid dimensions $(W, H, D)$, voxel size $s$ (assumed uniform), and a ray-cube intersection function `RayCubeSlabsIntersection` that returns the entry parameter $t_{entry}$ and exit parameter $t_{exit}$ of the ray with the bounding box of the grid.
**Outputs:** A list of 3D integer coordinates $(i, j, k)$ representing the sequence of voxels visited by the ray.

**Data Structures:**
- `vec3`: A 3D vector type with components $x, y, z$.
- `vector<vec3>`: A dynamic array of 3D vectors.
- Integers: `ii, jj, kk` for voxel indices; `dx, dy, dz` for ray deltas; `err_1, err_2` for error terms.

**Parameters:**
- `EPSILON`: A small positive constant to handle precision issues and boundary conditions. Typical value: $10^{-6}$ or similar, depending on coordinate scale.
- `quality`: A switch case value determining the rendering mode (0-4), though the traversal logic itself is independent of this switch in the source code [S1, unofficial].

**Pseudocode:**

```python
def bresenham_voxel_traversal(origin, direction, grid_width, grid_height, grid_depth, voxel_size, ray_cube_intersection):
    """
    Traverses a voxel grid using Bresenham-like integer arithmetic.
    
    Args:
        origin: vec3, ray origin
        direction: vec3, normalized ray direction
        grid_width: int, number of voxels in X
        grid_height: int, number of voxels in Y
        grid_depth: int, number of voxels in Z
        voxel_size: float, size of each voxel (assumed uniform)
        ray_cube_intersection: function, returns (t_entry, t_exit) for ray and grid bounding box
        
    Returns:
        list of vec3, voxel coordinates visited
    """
    # 1. Ray-Grid Intersection
    t_entry, t_exit = ray_cube_intersection(origin, direction, grid_width, grid_height, grid_depth, voxel_size)
    
    EPSILON = 1e-6
    if t_entry < EPSILON:
        return [vec3(-1, -1, -1)]
    
    # 2. Determine Start and End Points
    # Check if origin is inside grid
    ox, oy, oz = origin
    # Simple check: is origin within [0, grid_width*voxel_size] etc?
    # Assuming grid starts at 0,0,0
    inside_x = 0 <= ox < grid_width * voxel_size
    inside_y = 0 <= oy < grid_height * voxel_size
    inside_z = 0 <= oz < grid_depth * voxel_size
    
    if not (inside_x and inside_y and inside_z):
        start_point = origin + (t_entry + EPSILON) * direction
    else:
        start_point = origin
        
    end_point = origin + t_exit * direction
    
    # 3. Calculate Deltas and Increments
    dx = end_point.x - start_point.x
    dy = end_point.y - start_point.y
    dz = end_point.z - start_point.z
    
    # Convert to voxel steps
    # Note: Source code uses x_length, y_length, z_length directly from deltas?
    # It seems to use absolute values and possibly rounding.
    # Let's assume integer steps based on length / voxel_size
    x_length = int(abs(dx) / voxel_size)
    y_length = int(abs(dy) / voxel_size)
    z_length = int(abs(dz) / voxel_size)
    
    # Handle zero length cases to avoid division by zero or degenerate loops
    if x_length == 0: x_length = 1
    if y_length == 0: y_length = 1
    if z_length == 0: z_length = 1
    
    dx2 = 2 * dx
    dy2 = 2 * dy
    dz2 = 2 * dz
    
    x_inc = 1 if dx > 0 else (-1 if dx < 0 else 0)
    y_inc = 1 if dy > 0 else (-1 if dy < 0 else 0)
    z_inc = 1 if dz > 0 else (-1 if dz < 0 else 0)
    
    # 4. Determine Dominant Axis
    # Use absolute values for comparison
    abs_dx = abs(dx)
    abs_dy = abs(dy)
    abs_dz = abs(dz)
    
    # 5. Traverse Voxels
    # Initialize current voxel position
    # Convert start_point to voxel index
    i = int(start_point.x / voxel_size)
    j = int(start_point.y / voxel_size)
    k = int(start_point.z / voxel_size)
    
    # Clamp to grid bounds
    i = max(0, min(i, grid_width - 1))
    j = max(0, min(j, grid_height - 1))
    k = max(0, min(k, grid_depth - 1))
    
    points = []
    
    if abs_dx >= abs_dy and abs_dx >= abs_dz:
        # X is dominant
        err_1 = dy2 - x_length
        err_2 = dz2 - x_length
        
        for _ in range(x_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                j += y_inc
                err_1 -= dx2
            if err_2 > 0:
                k += z_inc
                err_2 -= dx2
                
            err_1 += dy2
            err_2 += dz2
            i += x_inc
            
        points.append(vec3(i, j, k))
        
    elif abs_dy >= abs_dx and abs_dy >= abs_dz:
        # Y is dominant
        err_1 = dx2 - y_length
        err_2 = dz2 - y_length
        
        for _ in range(y_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                i += x_inc
                err_1 -= dy2
            if err_2 > 0:
                k += z_inc
                err_2 -= dy2
                
            err_1 += dx2
            err_2 += dz2
            j += y_inc
            
        points.append(vec3(i, j, k))
        
    else:
        # Z is dominant
        err_1 = dy2 - z_length
        err_2 = dx2 - z_length
        
        for _ in range(z_length):
            points.append(vec3(i, j, k))
            
            if err_1 > 0:
                j += y_inc
                err_1 -= dz2
            if err_2 > 0:
                i += x_inc
                err_2 -= dz2
                
            err_1 += dy2
            err_2 += dx2
            k += z_inc
            
        points.append(vec3(i, j, k))
        
    return points
```

**Edge Cases and Pitfalls:**
- **Precision:** The use of integer arithmetic avoids floating-point accumulation errors but may suffer from quantization errors if the voxel size is not uniform or if the ray direction is not well-aligned with the grid.
- **Boundaries:** The source code does not explicitly show boundary checks within the loop. It is assumed that the ray-cube intersection ensures the start and end points are within the grid, and the increments keep the voxel indices within bounds. However, if the ray starts exactly on a boundary, care must be taken to avoid double-counting or missing voxels.
- **Degenerate Input:** If the ray direction is zero or the ray does not intersect the grid, the algorithm handles it by returning $(-1, -1, -1)$. If the ray is parallel to an axis, the dominant axis logic still holds, but the error terms for the non-dominant axes will be zero, resulting in no increments along those axes.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of voxels intersected by the ray. The number of steps is proportional to the length of the ray segment within the grid.
- **Memory Complexity:** $O(N)$ to store the list of visited voxels.
- **Performance:** Integer arithmetic is generally faster than floating-point arithmetic on many hardware platforms, making this method potentially faster than DDA-based methods in software implementations. However, the lack of early-out optimizations (like stopping when a certain density threshold is reached) may lead to unnecessary computations in sparse volumes.
- **Strengths:** Simple implementation, no floating-point accumulation errors, deterministic behavior.
- **Limitations:** Less flexible than DDA methods for adaptive stepping or non-uniform voxel sizes. May visit more voxels than necessary if the ray passes through empty space.

## Background
The Bresenham Voxel Traversal algorithm is derived from Bresenham's line algorithm, which is a classic computer graphics algorithm for rasterizing lines using integer arithmetic [S1, unofficial]. It was adapted for voxel traversal in the context of volumetric rendering, specifically in the `VolumetricClouds` project by dotcamdev [S1, unofficial]. The method is used in the `MarchRayVoxel` function to generate a sequence of voxel coordinates for light transmittance calculations.
