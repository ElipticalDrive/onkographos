# DN_step_map

Also called: Amanatides & Woo Ray Traversal, Digital Differential Analyzer raycast, Voxel Grid Raycasting (DDA), Voxel Raycasting / 3D DDA Block Traversal

## Overview
DN_step_map is a ray-traversal algorithm for regular voxel grids that determines the sequence of voxels intersected by a ray without performing explicit geometric intersection tests with voxel faces [S1, S2, S6, unofficial]. It solves the problem of efficiently querying sparse or dense voxel structures for collision, occlusion, or surface detection by stepping through the grid cell-by-cell along the ray direction [S6, S7, unofficial]. Unlike fixed-step raymarching, it advances the ray only to the next voxel boundary, skipping empty regions in constant time per voxel [S6, unofficial]. It differs from sibling methods like [Voxel Raycast (Nonzero/Color Channel)](12412-voxel-raycast-nonzero-color-channel.md) by using strict bitwise presence checks on packed data, and from [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md) by relying on discrete boundary crossings rather than continuous field evaluation [S1, S2, unofficial].

## How it works
**Inputs:**
*   `rayPos`: Ray origin $(p_x, p_y, p_z)$ in world or voxel coordinates [S1, S7, unofficial].
*   `rayDir`: Ray direction vector $(d_x, d_y, d_z)$ [S1, S3, unofficial]. Must be normalized or its magnitude used for scaling [S4, S6, unofficial].
*   `tmax`: Maximum traversal parameter (distance) [S1, unofficial].
*   `voxSize`: Voxel grid cell size (assumed uniform) [S6, unofficial].
*   `gridOrigin`: World-space origin of the voxel grid $(o_x, o_y, o_z)$ [S6, unofficial].
*   `isOccupied`: Function returning boolean for a given voxel index [S6, unofficial].

**Outputs:**
*   `hitVoxel`: Index $(i, j, k)$ of the first occupied voxel [S6, unofficial].
*   `hitFace`: Entry face identifier (e.g., `'neg-x'`, `'pos-y'`) [S6, unofficial].
*   `prevEmptyVoxel`: Index of the last empty voxel before the hit [S6, unofficial].
*   Boolean success flag [S3, unofficial].

**Data Structures:**
*   `current`: Tuple $(X, Y, Z)$ of integer voxel indices [S1, S6, unofficial].
*   `step`: Tuple $(step_x, step_y, step_z)$ of integers $\{-1, 0, 1\}$ indicating direction of increment [S1, S6, unofficial].
*   `tMax`: Tuple $(tMax_x, tMax_y, tMax_z)$ of floats representing the ray parameter $t$ at which the ray crosses the next voxel boundary along each axis [S1, S6, unofficial].
*   `tDelta`: Tuple $(tDelta_x, tDelta_y, tDelta_z)$ of floats representing the distance between consecutive voxel boundaries along each axis [S6, unofficial].

**Algorithm Steps:**

1.  **Validation:** If $|rayDir| < \epsilon$ (e.g., $10^{-5}$), return failure [S4, S6, unofficial].
2.  **Initialization:**
    *   Calculate initial voxel indices: $X = \lfloor (rayPos_x - o_x) / voxSize \rfloor$, $Y = \lfloor (rayPos_y - o_y) / voxSize \rfloor$, $Z = \lfloor (rayPos_z - o_z) / voxSize \rfloor$ [S1, S6, unofficial].
    *   Calculate step directions:
        $$step_x = \begin{cases} 1 & \text{if } d_x > 0 \\ -1 & \text{if } d_x < 0 \\ 0 & \text{if } d_x = 0 \end{cases}$$
        (Same for $step_y, step_z$) [S6, unofficial].
    *   Calculate boundary deltas:
        $$tDelta_x = \begin{cases} voxSize / |d_x| & \text{if } d_x \neq 0 \\ \infty & \text{if } d_x = 0 \end{cases}$$
        (Same for $tDelta_y, tDelta_z$) [S6, unofficial].
    *   Calculate initial boundary crossings $tMax$:
        For axis $A \in \{x, y, z\}$:
        $$nextBoundary_A = \begin{cases} (X + 1) \cdot voxSize + o_A & \text{if } step_A = 1 \\ X \cdot voxSize + o_A & \text{if } step_A = -1 \end{cases}$$
        $$tMax_A = \begin{cases} (nextBoundary_A - rayPos_A) / d_A & \text{if } d_A \neq 0 \\ \infty & \text{if } d_A = 0 \end{cases}$$
        [S6, unofficial].
    *   Handle starting inside occupied voxel: If `isOccupied(current)` is true, return `current` as hit with `hitFace='inside'` and `prevEmptyVoxel=current` [S6, G, unofficial].
3.  **Traversal Loop:**
    *   While $t < tmax$ and steps $< HARD\_STEP\_CAP$ (1024) [S1, S6, unofficial]:
    *   Find axis $A$ with minimum $tMax_A$.
    *   If $tMax_A > tmax$, break (ray exits volume) [S6, unofficial].
    *   Advance ray parameter: $t = tMax_A$ [S1, unofficial].
    *   Update voxel index: $current_A += step_A$ [S6, unofficial].
    *   Update boundary crossing: $tMax_A += tDelta_A$ [S6, unofficial].
    *   Check occupancy: If `isOccupied(current)` is true:
        *   Determine `hitFace` based on $A$ and $step_A$ (e.g., if $A=x, step_x=1$, face is `'neg-x'` because we entered from the negative X side of the new voxel) [S6, unofficial].
        *   Calculate `prevEmptyVoxel` by reversing the step on the hit axis from `current` [S6, unofficial].
        *   Return success with `hitVoxel=current`, `hitFace`, `prevEmptyVoxel` [S6, unofficial].
4.  **Termination:** If loop completes without hit, return failure [S2, unofficial].

**Pseudocode:**

```python
def dn_step_map(rayPos, rayDir, voxSize, gridOrigin, isOccupied, tmax, hard_step_cap=1024):
    # 1. Validation
    dir_len = math.sqrt(rayDir.x**2 + rayDir.y**2 + rayDir.z**2)
    if dir_len < 1e-5:
        return None
    
    # Normalize direction for consistent step logic, though tMax calculation uses raw dir
    # Note: Some implementations use normalized dir for tMax, others use raw. 
    # S6 implies using raw dir in division, so tMax is in ray parameter space.
    # We will use raw dir for tMax calculations as per S6 formula.
    
    # 2. Initialization
    # Initial voxel indices
    X = math.floor((rayPos.x - gridOrigin.x) / voxSize)
    Y = math.floor((rayPos.y - gridOrigin.y) / voxSize)
    Z = math.floor((rayPos.z - gridOrigin.z) / voxSize)
    
    current = (X, Y, Z)
    
    # Step directions
    step_x = 1 if rayDir.x > 0 else (-1 if rayDir.x < 0 else 0)
    step_y = 1 if rayDir.y > 0 else (-1 if rayDir.y < 0 else 0)
    step_z = 1 if rayDir.z > 0 else (-1 if rayDir.z < 0 else 0)
    
    # Boundary deltas
    tDelta_x = voxSize / abs(rayDir.x) if rayDir.x != 0 else float('inf')
    tDelta_y = voxSize / abs(rayDir.y) if rayDir.y != 0 else float('inf')
    tDelta_z = voxSize / abs(rayDir.z) if rayDir.z != 0 else float('inf')
    
    # Initial boundary crossings
    # Next boundary positions in world space
    next_x = (X + 1) * voxSize + gridOrigin.x if step_x == 1 else X * voxSize + gridOrigin.x
    next_y = (Y + 1) * voxSize + gridOrigin.y if step_y == 1 else Y * voxSize + gridOrigin.y
    next_z = (Z + 1) * voxSize + gridOrigin.z if step_z == 1 else Z * voxSize + gridOrigin.z
    
    tMax_x = (next_x - rayPos.x) / rayDir.x if rayDir.x != 0 else float('inf')
    tMax_y = (next_y - rayPos.y) / rayDir.y if rayDir.y != 0 else float('inf')
    tMax_z = (next_z - rayPos.z) / rayDir.z if rayDir.z != 0 else float('inf')
    
    # Check if starting voxel is occupied
    if isOccupied(current[0], current[1], current[2]):
        return {
            "hitVoxel": current,
            "hitFace": "inside",
            "prevEmptyVoxel": current
        }
        
    steps = 0
    t = 0.0 # Current ray parameter
    
    # 3. Traversal Loop
    while t < tmax and steps < hard_step_cap:
        steps += 1
        
        # Find minimum tMax
        if tMax_x <= tMax_y and tMax_x <= tMax_z:
            axis = 'x'
            tMax = tMax_x
        elif tMax_y <= tMax_z:
            axis = 'y'
            tMax = tMax_y
        else:
            axis = 'z'
            tMax = tMax_z
            
        if tMax > tmax:
            break
            
        t = tMax
        
        # Advance voxel
        if axis == 'x':
            X += step_x
            tMax_x += tDelta_x
        elif axis == 'y':
            Y += step_y
            tMax_y += tDelta_y
        else:
            Z += step_z
            tMax_z += tDelta_z
            
        current = (X, Y, Z)
        
        # Check occupancy
        if isOccupied(X, Y, Z):
            # Determine hit face
            if axis == 'x':
                hitFace = 'neg-x' if step_x == 1 else 'pos-x'
            elif axis == 'y':
                hitFace = 'neg-y' if step_y == 1 else 'pos-y'
            else:
                hitFace = 'neg-z' if step_z == 1 else 'pos-z'
                
            # Calculate previous empty voxel
            prev = list(current)
            if axis == 'x': prev[0] -= step_x
            elif axis == 'y': prev[1] -= step_y
            else: prev[2] -= step_z
            prevEmptyVoxel = tuple(prev)
            
            return {
                "hitVoxel": current,
                "hitFace": hitFace,
                "prevEmptyVoxel": prevEmptyVoxel
            }
            
    return None
```

**Parameters:**
*   `HARD_STEP_CAP`: 1024 steps [S6, unofficial].
*   `voxSize`: Grid cell size [S6, unofficial].
*   `tmax`: Maximum traversal distance [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Direction Components:** If $d_x=0$, $step_x=0$ and $tDelta_x, tMax_x = \infty$, effectively ignoring that axis in traversal decisions [S1, S2, unofficial].
*   **Ray Inside Occupied Voxel:** The algorithm must check the starting voxel before the loop. If the origin is inside an occupied voxel, it should return immediately with `hitFace='inside'` [S6, G, unofficial].
*   **Precision:** Floating-point errors in $tMax$ accumulation can cause jitter or missed voxels. Using exact arithmetic or re-evaluating $tMax$ from the current position periodically can mitigate this [G].
*   **Bounds Checking:** The algorithm does not perform internal bounds checking; the caller must ensure the ray and voxel indices remain within the grid volume [S3, unofficial].

## Subtopics

### [Voxel Raycast (Nonzero/Color Channel)](12412-voxel-raycast-nonzero-color-channel.md)
This method performs hidden surface elimination by casting a ray through a binary voxel volume to locate the first voxel where a specific data channel is non-zero. It differs from standard DDA traversal by optimizing for sparse or binary data: it processes voxels in groups of eight packed into a single byte, advancing the ray by whole bytes when the group is empty, thereby skipping large empty regions efficiently. This approach is distinct from sibling methods that use adaptive edge smoothing or neighbor-averaged interpolation, as it relies on strict bitwise presence checks rather than continuous field evaluation.

### [Voxel DDA Raymarching with Adaptive Edge Smoothing](14664-voxel-dda-raymarching-with-adaptive-edge-smoothing.md)
This method extends standard DDA raymarching by sampling corner and edge voxel occupancy to adaptively compute volume content, eliminating stepping artifacts and spikes caused by uniform voxel traversal. Unlike standard DDA which steps uniformly through fixed voxels, this technique smooths terrain surfaces without increasing the step count or requiring geometry subdivision. It builds on DN_step_map by refining the surface normal and volume estimation at the hit voxel.

### [Corner-based Voxel Volume Calculation](14665-corner-based-voxel-volume-calculation.md)
A technique to compute voxel volume values at corners for smooth terrain rendering, replacing side-based volume storage with corner-based values to better represent surface geometry during raymarching. It sets apart from sibling methods by explicitly handling diagonal neighbors (NW, NE, SW, SE) and applying "surface block maxing" to clamp volumes at surface boundaries, whereas siblings like Midpoint UV Calculation focus on interpolation precision or Voxel DDA Raymarching with Adaptive Edge Smoothing focus on edge artifacts without the specific corner-maxing logic.

### [Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation](14668-voxel-dda-raymarching-with-neighbor-averaged-entry-interpola.md)
A voxel raymarching technique that calculates smooth surface entry heights by averaging adjacent voxel volume/height values and interpolating based on the ray's entry position within the cube. It improves upon simple linear interpolation between two voxels by using neighbor-averaged face heights, though it initially ignores the center voxel's influence, leading to sharp edges.

### [Midpoint UV Calculation](14669-midpoint-uv-calculation.md)
Midpoint UV Calculation computes the UV coordinates of the midpoint plane within a voxel traversal step to determine height and lighting variations for surface rendering. It sets apart from sibling methods by explicitly calculating a geometric midpoint between entry and exit UV states to drive height maps, whereas siblings like Corner-based Voxel Volume Calculation rely on corner interpolation and Voxel DDA Raymarching with Neighbor-Averaged Entry Interpolation focus on entry-point smoothing.

### Neighbor Voxel Volume Sampling
Reads adjacent voxel volumes at ray entry and exit positions to adjust traversal behavior, preventing artifacts such as floating voxels, flat edges, and incorrect slope rendering [S8, unofficial]. When exiting a voxel, it calculates the exit voxel's grid position by adding the current position, the step direction mask, and an offset derived from the mask. When entering a voxel, it calculates the entry voxel's grid position using the same mask-based offset logic, ensuring the offset is negative or adjusted for entry direction. It samples the volume value from the calculated adjacent voxel and uses it to modify the ray's exit behavior or skip logic. Reading adjacent voxels can impact performance, though the author notes it may not significantly affect frame rate on small maps [S8, unofficial].

### Voxel DDA Face Entry/Exit UV Mapping
Checks the entry mask to determine which face (X, Y, or Z) the ray enters the voxel. If entering from the left/back, it sets the start UV to the back face and interpolates toward the center. If entering from the right/front, it sets the start UV to the front face and interpolates toward the right/center. Using integer division for UV coordinate calculations causes terrain vertices to fail to connect across voxel edges; all coordinate math must use floating-point types [S8, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels traversed. Each step involves constant-time arithmetic and a single occupancy check.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** Significantly faster than fixed-step raymarching for sparse volumes as it skips empty space. Performance degrades in dense volumes where every voxel must be checked [S6, unofficial].
*   **Strengths:** Exact boundary crossing, no sampling artifacts, efficient for sparse data.
*   **Limitations:** Discrete steps can cause aliasing on smooth surfaces; requires explicit handling of degenerate cases (zero direction, starting inside voxel) [S1, S6, unofficial].
*   **When to Use:** Collision detection, occlusion culling, sparse voxel traversal.
*   **When Not to Use:** Smooth volume rendering requiring sub-voxel precision, dense volumes where fixed-step might be more cache-friendly.

## Background
The algorithm is based on the Amanatides & Woo method for ray traversal in voxel grids, introduced in "A Fast Voxel Traversal Algorithm for Ray Tracing" (1988) [S1, S2, S6, unofficial]. It has been widely adopted in voxel engines and games for efficient raycasting [S4, unofficial][S5][S7, unofficial]. Variants are used in tools like Godot's VoxelTool for blocky terrain raycasting [S5] and in custom voxel engines for collision and picking [S6, S7, unofficial].
