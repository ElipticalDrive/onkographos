# Liu Extension of Bresenham

Also called: Bresenham Extension, LZY04, Liu Extension, Liu et al. Algorithm

## Overview
The Liu Extension of Bresenham is a voxel traversal algorithm that extends the classic 2D Bresenham line algorithm to 3D grid traversal by detecting and visiting diagonal neighbors when the ray intersects a cell corner [S1][S2, unofficial]. Unlike standard Bresenham which visits only one neighbor per step, this method checks if the error exceeds a specific threshold to decide whether to visit both $(x+1, y)$ and $(x+1, y+1)$ in 2D, or the corresponding diagonal paths in 3D [S1][S2, unofficial]. It is distinguished from its siblings by its reliance on a geometric intersection check against a derived threshold rather than simple integer error accumulation, offering performance advantages even on modern hardware where floating-point operations are efficient [S1][S2, unofficial].

## How it works
**Inputs:** Ray origin $(x_0, y_0, z_0)$, ray direction $(dx, dy, dz)$, and the starting voxel $(x, y, z)$ [G].
**Outputs:** A sequence of voxel coordinates visited by the ray [G].

**Data Structures:**
*   Current voxel coordinates: $(x, y, z)$ (integers) [G].
*   Error accumulator: $e$ (floating-point or fixed-point) [G].
*   Slope: $k = dx/dy$ (for 2D) or analogous slopes for 3D axes [G].

**Steps:**
1. Determine the intersection point of the line with the two walls of the current cell [S1].
2. Compute the error $e$, defined as the difference between the chosen integer cell boundary and the real coordinate of the line intersection [S1].
3. Compare $e$ against a threshold. Source [S1] defines the threshold as $\frac{1}{2} - \frac{dy}{2dx}$, while Source [S2, unofficial] contains garbled text that has been interpreted as $\frac{1}{2} - \frac{1}{2dx \times dy}$ or $2^{1/2} dx dy$, which are likely transcription errors [S1][S2, unofficial].
4. If $e > \text{threshold}$, visit both $(x+1, y)$ and $(x+1, y+1)$ [S1][S2, unofficial]. Otherwise, proceed with the standard single-step traversal [G].
5. Thereafter, follow the standard Bresenham approach, adjusting the algorithm to integer arithmetic by accumulating the slope $k = dx/dy$ and subtracting $1$ when the error exceeds the threshold [S1].
6. In the three-dimensional case, identify two possible paths from cell $(x, y, z)$ to $(x+1, y+1, z+1)$ [S1][S2, unofficial]. The specific logic for selecting between these paths is not fully detailed in the provided text [G].

**Pseudocode:**
```python
def liu_bresenham_2d(x0, y0, x1, y1):
    """Liu Extension of Bresenham for 2D grid traversal. Assumes dx > 0, dy > 0."""
    dx = x1 - x0
    dy = y1 - y0
    k = dx / dy
    threshold = 0.5 - (dy / (2.0 * dx))  # Formula from [S1]
    
    x, y = x0, y0
    yield (x, y)
    e = 0.0  # Initialization [G]
    
    for _ in range(dx):
        e += k  # Cumulative slope accumulation [S1]
        if e > threshold:
            yield (x + 1, y)
            yield (x + 1, y + 1)
            e -= 1.0  # Integer adjustment [S1]
        else:
            yield (x + 1, y)
        x += 1
```

**Edge Cases and Pitfalls:**
*   **Threshold Formula Disagreement:** Sources [S1] and [S2, unofficial] provide conflicting or garbled formulas for the threshold. Implementers should verify the correct threshold against the original [LZY04] paper [S1][S2, unofficial].
*   **Negative Directions:** The algorithm assumes positive direction components. Handling negative $dx, dy, dz$ requires mirroring the coordinate system or adjusting the neighbor selection logic [G].
*   **3D Complexity:** The 3D extension is described vaguely as identifying two possible paths. Implementers must derive the specific 3D diagonal traversal logic, likely involving checks against multiple thresholds for the three axes [G].

## Operating characteristics
*   **Performance:** The Liu algorithm is reported to be faster than Zalik et al.'s code-based approach and even faster than standard Bresenham on modern processors, where floating-point arithmetic is nearly as efficient as integer arithmetic [S1][S2, unofficial].
*   **Complexity:** Time complexity is linear with respect to the number of voxels traversed, and memory complexity is constant, storing only current coordinates and error terms [G].
*   **Strengths:** Efficient diagonal traversal without complex branching; leverages floating-point precision for threshold checks [G].
*   **Limitations:** Ambiguity in the 3D extension details; potential precision issues if the threshold formula is misinterpreted [G].

## Background
The Liu Extension of Bresenham was proposed by Liu et al. in [LZY04] [S1][S2, unofficial]. It is an efficient extension of Bresenham's algorithm designed for ray tracing and grid traversal [S1]. It addresses the limitation of standard Bresenham by explicitly handling diagonal cell visits when the ray intersects a cell corner, improving traversal accuracy and efficiency in certain scenarios [S1][S2, unofficial].
