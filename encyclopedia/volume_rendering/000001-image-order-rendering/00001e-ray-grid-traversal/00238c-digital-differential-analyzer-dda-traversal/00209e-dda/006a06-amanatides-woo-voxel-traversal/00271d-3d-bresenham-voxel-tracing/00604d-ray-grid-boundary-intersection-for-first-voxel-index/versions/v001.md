# Ray-Grid Boundary Intersection for First Voxel Index

Also called: Exact Ray-Grid Entry Point Calculation

## Overview
This method computes the initial voxel index for ray traversal by determining the exact point where a ray enters a uniform axis-aligned grid and converting that point to grid coordinates. It differs from its siblings, such as [Integer-based Amanatides and Woo Voxel Traversal](4246-integer-based-amanatides-and-woo-voxel-traversal.md) and [3D Bresenham Voxel Tracing](3949-3d-bresenham-voxel-tracing.md), by explicitly solving for the entry intersection using parametric line equations rather than relying on incremental stepping or integer arithmetic approximations. This approach is chosen when an exact geometric entry point is required before initiating a traversal algorithm, particularly for handling arbitrary ray orientations without special-casing vertical or horizontal components early in the pipeline.

## How it works
**Inputs:**
*   Ray origin vector $\mathbf{u} = (u.x, u.y, u.z)$.
*   Ray direction vector $\mathbf{v} = (v.x, v.y, v.z)$.
*   Grid boundary definitions (parametric lines representing the grid faces).
*   Cell size (physical length of one voxel along an axis), typically $1$ [S1, unofficial].

**Outputs:**
*   The voxel index $(i, j, k)$ corresponding to the first voxel intersected by the ray.

**Data Structures:**
*   Ray represented as $r(t) = \mathbf{u} + t\mathbf{v}$.
*   Grid boundaries represented as parametric lines $r_2(t_2) = \mathbf{u}_2 + t_2\mathbf{v}_2$.

**Steps:**
1.  Define the ray as $r(t) = \mathbf{u} + t\mathbf{v}$, where $\mathbf{u}$ is the origin and $\mathbf{v}$ is the direction [S1, unofficial].
2.  Define each grid boundary as a parametric line $r_2(t_2) = \mathbf{u}_2 + t_2\mathbf{v}_2$, where $\mathbf{u}_2$ is a point on the boundary and $\mathbf{v}_2$ is the direction vector of the boundary line [S1, unofficial].
3.  Equate the ray and boundary equations: $\mathbf{u} + t\mathbf{v} = \mathbf{u}_2 + t_2\mathbf{v}_2$ [S1, unofficial].
4.  Solve the resulting system of linear equations for the scalar parameters $t$ and $t_2$. For a 2D projection (or specific axis alignment), the solution for $t$ is derived as:
    $$ t = \frac{u.x \cdot v2.y - u.y \cdot v2.x - u2.x \cdot v2.y + u2.y \cdot v2.x}{v.y \cdot v2.x - v.x \cdot v2.y} $$
    where $\mathbf{u}, \mathbf{v}$ are the ray origin/direction, and $\mathbf{u}_2, \mathbf{v}_2$ are the boundary origin/direction [S1, unofficial].
5.  Evaluate $t$ for all grid boundaries defining the entry surface of the grid [S1, unofficial].
6.  Select the smallest positive $t$ (denoted $t_{Min}$) among all calculated boundary intersections. Intersections with $t < 0$ are behind the ray origin and must be discarded [S1, unofficial].
7.  Calculate the entry point $\mathbf{p} = r(t_{Min})$ [S1, unofficial].
8.  Compute the voxel index by flooring the coordinates of $\mathbf{p}$ divided by the cell size. For a cell size of $1$, this is equivalent to $\lfloor \mathbf{p} \rfloor$ [S1, unofficial].

**Pseudocode:**
```python
def compute_first_voxel_index(ray_origin, ray_direction, grid_boundaries, cell_size=1.0):
    """
    ray_origin: tuple (ux, uy, uz)
    ray_direction: tuple (vx, vy, vz)
    grid_boundaries: list of tuples (u2x, u2y, u2z, v2x, v2y, v2z)
                     representing parametric lines r2(t2) = u2 + t2*v2
    cell_size: float, physical length of one voxel
    """
    ux, uy, uz = ray_origin
    vx, vy, vz = ray_direction
    
    t_min = float('inf')
    entry_point = None
    
    for boundary in grid_boundaries:
        u2x, u2y, u2z, v2x, v2y, v2z = boundary
        
        # Denominator of the intersection formula
        denom = vy * v2x - vx * v2y
        
        # Avoid division by zero; if denom is 0, lines are parallel
        if abs(denom) < 1e-9:
            continue
            
        # Numerator of the intersection formula
        # Derived from equating u + t*v = u2 + t2*v2 and solving for t
        num = (ux * v2y - uy * v2x - u2x * v2y + u2y * v2x)
        
        t = num / denom
        
        # Discard intersections behind the ray origin
        if t <= 0:
            continue
            
        if t < t_min:
            t_min = t
            # Calculate entry point p = u + t*v
            # Note: In 3D, we must verify the point lies on the boundary segment
            # or plane defined by the boundary. The source notes focus on 2D
            # boundary lines. For a general 3D grid, boundaries are planes.
            # The source formula is explicitly 2D (x,y components).
            # [G] Assuming the boundary definition handles the 3D context
            # or this is a 2D slice. For strict 3D, boundary vectors v2
            # would define a plane normal, not a line direction in the same way.
            # Based on source [S1, unofficial], we proceed with the 2D-derived logic
            # applied to the relevant axis or projection.
            entry_point = (ux + t * vx, uy + t * vy, uz + t * vz)
            
    if entry_point is None:
        return None # Ray does not intersect grid
        
    # Compute voxel index
    ix = int(entry_point[0] // cell_size)
    iy = int(entry_point[1] // cell_size)
    iz = int(entry_point[2] // cell_size)
    
    return (ix, iy, iz)
```

**Parameters:**
*   `cell_size`: Physical length of one voxel along an axis. Typical value is $1$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Vertical/Parallel Rays:** If the ray direction component is zero (e.g., $v.x = 0$), the simplified slope-intercept form fails. The general parametric formula must be used to avoid division by zero or incorrect slopes [S1, unofficial].
*   **Negative t:** Intersections with $t < 0$ are behind the ray origin and must be strictly discarded [S1, unofficial].
*   **Precision:** Floating-point precision issues may arise when $t$ is very close to zero or when boundaries are nearly parallel to the ray.

## Operating characteristics
*   **Time Complexity:** $O(B)$ where $B$ is the number of grid boundaries checked. For a 3D axis-aligned bounding box, this is a constant number of boundaries (typically 6 faces, though the source describes 2D line boundaries).
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Strengths:** Provides an exact geometric entry point without iterative approximation. Handles arbitrary ray directions robustly via the parametric form.
*   **Limitations:** The source derivation is explicitly 2D. Extending to 3D requires careful definition of "boundaries" as planes rather than lines, and the specific formula provided in [S1, unofficial] is for 2D intersection. Using it directly in 3D without modification may yield incorrect results for non-aligned boundaries.
*   **When to use:** When an exact entry point is needed for initialization, or when implementing a custom traversal that starts from a precise geometric intersection rather than a coarse grid cell.

## Background
This method originates from a discussion on Game Development Stack Exchange regarding the determination of the first voxel a ray intersects. It was proposed by user "datta" in January 2021 [S1, unofficial]. The approach is based on solving the parametric equations of the ray and the grid boundary lines to find the intersection parameter $t$. It serves as a foundational step for more complex voxel traversal algorithms by providing the starting coordinates.
