# Voxel Raymarching with DDA and Bounding Box Culling

Also called: Voxel Raymarching, Voxel Raymarching with DDA

## Overview
Voxel Raymarching with DDA and Bounding Box Culling is an image-order rendering technique for sparse, segmented voxel models [S1, unofficial]. It solves the problem of efficiently rendering large voxel volumes by treating the model as a bounding-box mesh where the fragment shader ignores the geometry and instead casts a ray from the eye through the pixel [S1, unofficial]. The ray intersects the box analytically to find the entry point, then steps through the voxel grid using Digital Differential Analyzer (DDA) traversal until it finds a non-empty voxel or leaves the box [S1, unofficial]. It sets itself apart from sibling methods by explicitly decoupling the ray origin from the box surface intersection to avoid floating-point boundary errors, and by using a segment directory to manage sparse 3D texture arrays [S1, unofficial].

## How it works
### Inputs and Outputs
Inputs include a sparse voxel model split into 128×128×128 voxel segments stored as R8 3D textures, a 2D segment directory listing active segments, a 256×1 RGBA8 palette, camera state matrices, bounding box uniforms, and a light position [S1, unofficial]. Outputs are the lit albedo color of the first hit voxel and its depth in clip space [S1, unofficial].

### Data Structures
The segment brick textures are an array of 128³ R8 `Texture3D` objects ordered to match directory entries [S1, unofficial]. The segment directory is a 2D texture where each texel stores segment grid coordinates and a texture slot index as floats [S1, unofficial]. The palette texture stores colors as 0xRRGGBBAA integers reversed to 0xAABBGGRR for little-endian RGBA8 byte order, read as sRGB [S1, unofficial]. The bounding box uniforms `box_center` and `box_size` define the volume in voxel space [S1, unofficial].

### Steps
1. **Compute Per-Eye Ray Origin and Direction:** Transform `EYE_OFFSET` to world space, unproject `SCREEN_UV` to view space, normalize the direction, transform it to world space, then transform both origin and direction to voxel space using the inverse model matrix and add `box_center` [S1, unofficial].
2. **March Through the Box:** Perform a ray-AABB slab test to find the entry point, then start DDA traversal from that point [S1, unofficial]. For each voxel visited, sample the corresponding 3D texture from the `segment_voxels` array using the segment directory to find the correct texture index [S1, unofficial]. If a non-empty voxel (palette index > 0) is found, record the hit position, normal, and material ID; if the ray exits the box without finding one, discard the pixel [S1, unofficial].
3. **Compute Lighting:** Calculate point light lighting with 30% ambient and 70% diffuse, clamping back-facing normals to 0 [S1, unofficial].
4. **Output Albedo:** Multiply the palette color retrieved by the material index by the lighting factor [S1, unofficial].
5. **Write Depth:** Transform `hit_pos` from voxel space to mesh-local, then to world, then to clip space, and write normalized depth [S1, unofficial].

### Pseudocode
```python
def fragment_shader(SCREEN_UV, EYE_OFFSET, INV_PROJECTION_MATRIX, INV_VIEW_MATRIX,
                    MODEL_MATRIX, INV_MODEL_MATRIX, PROJECTION_MATRIX, VIEW_MATRIX,
                    box_center, box_size, segment_directory, segment_voxels, palette,
                    light_position, active_segment_count):
    # 1. Compute Per-Eye Ray Origin and Direction
    camera_world = (INV_VIEW_MATRIX * vec4(EYE_OFFSET, 1.0)).xyz
    view_frag = INV_PROJECTION_MATRIX * vec4(SCREEN_UV * 2.0 - 1.0, 0.0, 1.0)
    view_frag = view_frag / view_frag.w
    ray_dir_view = normalize(view_frag.xyz - EYE_OFFSET)
    ray_world_dir = normalize((INV_VIEW_MATRIX * vec4(ray_dir_view, 0.0)).xyz)

    camera_voxel = (INV_MODEL_MATRIX * vec4(camera_world, 1.0)).xyz + box_center
    ray_dir = normalize((INV_MODEL_MATRIX * vec4(ray_world_dir, 0.0)).xyz)

    box_min = box_center - box_size * 0.5
    box_max = box_center + box_size * 0.5

    # 2. March Through the Box
    t_entry, t_exit, normal, hit_pos, material_id = march_box(camera_voxel, ray_dir, box_min, box_max,
                                                              segment_directory, segment_voxels, active_segment_count)

    if material_id == 0:
        discard

    # 3. Compute Lighting
    to_light = normalize(light_position - hit_pos)
    lighting = max(dot(normal, to_light), 0.0) * 0.7 + 0.3

    # 4. Output Albedo
    albedo = palette[material_id] * lighting

    # 5. Write Depth
    hit_clip = PROJECTION_MATRIX * VIEW_MATRIX * MODEL_MATRIX * vec4(hit_pos - box_center, 1.0)
    depth = hit_clip.z / hit_clip.w

    return albedo, depth

def march_box(origin, ray_dir, box_min, box_max, segment_directory, segment_voxels, active_segment_count):
    inv_ray_dir = 1.0 / ray_dir
    t0 = (box_min - origin) * inv_ray_dir
    t1 = (box_max - origin) * inv_ray_dir
    t_near = max(min(t0.x, t1.x), min(t0.y, t1.y), min(t0.z, t1.z))
    t_far = min(max(t0.x, t1.x), max(t0.y, t1.y), max(t0.z, t1.z))

    if t_near > t_far or t_far < 0:
        return 0, 0, vec3(0), vec3(0), 0

    current_pos = origin + ray_dir * t_near
    current_voxel = floor(current_pos)
    step_x = sign(ray_dir.x)
    step_y = sign(ray_dir.y)
    step_z = sign(ray_dir.z)

    # Amanatides-Woo initialization
    t_max_x = ((current_voxel.x + 1.0 if step_x > 0 else current_voxel.x) - origin.x) / ray_dir.x
    t_max_y = ((current_voxel.y + 1.0 if step_y > 0 else current_voxel.y) - origin.y) / ray_dir.y
    t_max_z = ((current_voxel.z + 1.0 if step_z > 0 else current_voxel.z) - origin.z) / ray_dir.z

    t_delta_x = abs(1.0 / ray_dir.x)
    t_delta_y = abs(1.0 / ray_dir.y)
    t_delta_z = abs(1.0 / ray_dir.z)

    while t_near <= t_far:
        segment_id = get_segment_id(current_voxel)
        texture_index = get_texture_index(segment_id, segment_directory, active_segment_count)

        if texture_index != -1:
            voxel_data = texelFetch(segment_voxels[texture_index], current_voxel % 128).r
            if voxel_data > 0:
                hit_pos = origin + ray_dir * t_near
                normal = compute_normal(current_voxel, hit_pos, ray_dir)
                return t_near, t_far, normal, hit_pos, voxel_data

        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                current_voxel.x += step_x
                t_near = t_max_x
                t_max_x += t_delta_x
            else:
                current_voxel.z += step_z
                t_near = t_max_z
                t_max_z += t_delta_z
        else:
            if t_max_y < t_max_z:
                current_voxel.y += step_y
                t_near = t_max_y
                t_max_y += t_delta_y
            else:
                current_voxel.z += step_z
                t_near = t_max_z
                t_max_z += t_delta_z

        if not inside_box(current_voxel, box_min, box_max):
            break

    return 0, 0, vec3(0), vec3(0), 0

def get_segment_id(voxel):
    X = voxel.x >> 7
    Y = voxel.y >> 7
    Z = voxel.z >> 7
    return (X << 18) | (Y << 9) | Z

def get_texture_index(segment_id, segment_directory, active_segment_count):
    for i in range(active_segment_count):
        entry = texelFetch(segment_directory, vec2(i, 0))
        segX, segY, segZ = entry.xyz
        if (segX << 18) | (segY << 9) | segZ == segment_id:
            return int(entry.w)
    return -1

def compute_normal(voxel, hit_pos, ray_dir):
    # Normal approximation based on entry face [G]
    if ray_dir.x > 0: return vec3(-1, 0, 0)
    if ray_dir.x < 0: return vec3(1, 0, 0)
    if ray_dir.y > 0: return vec3(0, -1, 0)
    if ray_dir.y < 0: return vec3(0, 1, 0)
    if ray_dir.z > 0: return vec3(0, 0, -1)
    return vec3(0, 0, 1)

def inside_box(voxel, box_min, box_max):
    return (voxel.x >= box_min.x and voxel.y >= box_min.y and voxel.z >= box_min.z and
            voxel.x <= box_max.x and voxel.y <= box_max.y and voxel.z <= box_max.z)
```

### Parameters
Segment size is 128×128×128 voxels per segment [S1, unofficial]. The camera is positioned at a distance of 2.5 times the model's largest dimension from the model center [S1, unofficial]. The default light position is `vec3(50.0, 50.0, 25.0)` in voxel space [S1, unofficial]. The inverse model matrix is precomputed on the CPU every frame [S1, unofficial].

### Edge Cases and Pitfalls
When model bounds change, the bounding box mesh size and position must be updated, and shader uniforms `box_center` and `box_size` must be refreshed to prevent rays from starting in the wrong place [S1, unofficial]. Starting the ray at the interpolated box-surface position causes fuzzy faces, wrong first-hit lighting, and vanishing faces for faces at coordinate 0 due to `floor()` boundary float errors; this is solved by intersecting the ray with the box analytically and clamping the origin just inside it [S1, unofficial]. Without writing depth at the hit voxel surface, the depth buffer holds the depth of the box's back face, causing other geometry to intersect the model as if it were a solid box and warping a flat box as a plane in VR reprojection [S1, unofficial]. Voxel data uses Z-up (MagicaVoxel) while Godot uses Y-up, requiring coordinate conversion `(x, y, z)_zup` to `(x, z, y)_yup` in C# and back in the shader [S1, unofficial].

## Operating characteristics
Time complexity is linear with respect to the number of voxels traversed along the ray, as DDA skips empty space efficiently [S1, unofficial]. Memory complexity is proportional to the number of active segments, with each segment being a 128³ R8 texture (2 MB) and a small directory texture [S1, unofficial]. Measured performance is not given in the sources. Strengths include efficiency for sparse voxel models, avoidance of floating-point boundary errors via analytical ray-box intersection, and correct depth writing for VR [S1, unofficial]. Limitations include the requirement for a precomputed inverse model matrix and performance dependence on voxel model density [S1, unofficial]. It is recommended for sparse voxel models with large empty spaces and VR applications requiring correct depth for reprojection [S1, unofficial]. It is not recommended for dense voxel models where ray traversal becomes expensive or models with frequent dynamic changes requiring frequent bound updates [S1, unofficial].

## Background
This method is implemented in the `Voxel2Pixel` graphics library by Ben McLean [S1, unofficial]. It is designed for use in Godot Engine for rendering voxel models in VR and desktop environments [S1, unofficial]. The method builds on the Amanatides-Woo Voxel Traversal algorithm for efficient ray traversal through voxel grids [S1, unofficial].
