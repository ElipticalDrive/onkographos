# Triangle Strip Voxel Projection

Also called: Hardware Accelerated Voxel Rendering, Structure Rendering Algorithm

## Overview
Triangle Strip Voxel Projection is a hardware-accelerated rendering method for voxel landscapes that replaces software span rendering with triangle strips [S1, unofficial]. It projects voxels onto the screen in columns and constructs geometry based on the visibility of adjacent columns to minimize polygon count and utilize hardware interpolation [S1, unofficial]. Unlike software span rendering which draws spans immediately, this method buffers column projections to construct triangle strips, reducing draw calls and leveraging hardware interpolation for texture coordinates, lightmap colors, and heights [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A voxel map representing a landscape; a camera view; a scan step size (default 32 pixels) [S1, unofficial].
*   **Output:** A sequence of OpenGL draw calls (triangle strips) rendering the visible surface of the voxel landscape [S1, unofficial].

**Data Structures**
The method does not define a complex persistent data structure but relies on temporary storage for two adjacent columns of projected screen-space coordinates:
*   `Column A`: The projected vertices (screen Y, depth Z, texture coordinates) of the previously scanned column.
*   `Column B`: The projected vertices of the currently scanned column.
*   `Strip State`: A boolean flag indicating if a triangle strip is currently active.

**Numbered Steps**
1.  **Scan Columns:** Iterate through the landscape depth lines (columns) from front to back. Instead of processing every single ray, project the voxels onto the screen for every $S$ pixels (where $S$ is the step size, default 32) [S1, unofficial].
2.  **Project Current Column:** Calculate the screen-space Y-coordinates and other attributes for the visible voxels in the current column (Column B) [S1, unofficial].
3.  **Evaluate Visibility Cases:** Compare the visibility of Column A (previous) and Column B (current) to determine the action:
    *   **Case 1 (A not visible, B visible):** Start a new triangle strip. Send vertices of Column A (as a degenerate or start marker) then Column B to the graphics library [S1, unofficial].
    *   **Case 2 (A visible, B visible):** Continue the currently active triangle strip. Send only the vertices of Column B to the graphics library [S1, unofficial].
    *   **Case 3 (A visible, B not visible):** Send the coordinates of Column B to the graphics library (to close the strip) and stop the current triangle strip [S1, unofficial].
    *   **Case 4 (A not visible, B not visible):** Usually do nothing. However, check for hole closure (see Pitfalls) [S1, unofficial].
4.  **Update State:** Set Column A = Column B for the next iteration.

**Formulas**
*   **Hole Closure Condition:** In Case 4, if a triangle strip was started or finished at the previous point, a single triangle must be drawn to close the gap. Let $Y_1, Y_2$ be the screen Y-coordinates of the current column's endpoints and $pY_1, pY_2$ be the screen Y-coordinates of the previous column's endpoints. The triangle is drawn if:
    $$ (Y_1 > pY_1) \land (Y_2 > pY_2) $$
    This condition may draw triangles that are not strictly visible, but it is more efficient than performing line intersections [S1, unofficial].

**Parameters**
*   **Step Size:** The distance between scanned columns in screen pixels. Default is 32 pixels. Smaller steps generate more polygons and higher fidelity but increase draw call overhead [S1, unofficial].

**Pitfalls and Edge Cases**
*   **Holes:** In Case 4, if a triangle strip was started or finished at the previous point during the prior pass, a single triangle must be drawn to close the gap between the non-visible columns [S1, unofficial].
*   **Mesh Density:** The triangle mesh can become too dense at the bottom of valleys. A span reduction technique is ideally needed to mitigate this, though not detailed in the primary source [S1, unofficial].
*   **Invisible Triangles:** The hole-closure formula may draw triangles that are not quite visible. This is accepted as a trade-off for efficiency over precise line intersection tests [S1, unofficial].

**Pseudocode**
```python
def render_voxel_landscape(voxel_map, camera, step_size=32):
    """
    Renders a voxel landscape using triangle strips.
    Assumes a function project_column(voxel_map, camera, col_index) returns
    a list of vertices with attributes (y, z, tex_coords) for the visible voxels
    in the given column index, sorted by screen Y.
    """
    width = camera.screen_width
    num_columns = width // step_size
    
    prev_col = None  # Column A
    strip_active = False
    
    for i in range(num_columns):
        curr_col = project_column(voxol_map, camera, i * step_size) # Column B
        if curr_col is None or len(curr_col) == 0:
            curr_col = []
            
        if prev_col is None:
            prev_col = curr_col
            continue
            
        # Determine visibility of previous and current columns
        # A column is "visible" if it has vertices
        a_visible = len(prev_col) > 0
        b_visible = len(curr_col) > 0
        
        if a_visible and b_visible:
            # Case 2: Continue active strip
            if not strip_active:
                # Should not happen if logic is correct, but start if needed
                gl_begin(GL_TRIANGLE_STRIP)
                strip_active = True
            gl_send_vertices(curr_col)
            
        elif not a_visible and b_visible:
            # Case 1: Start new strip
            if strip_active:
                gl_end()
                strip_active = False
            gl_begin(GL_TRIANGLE_STRIP)
            # Send prev_col (A) then curr_col (B)
            # Note: Source says "send vertices of columns A then B"
            # Since A is not visible, it might be empty or degenerate.
            # We send what we have for A, then B.
            gl_send_vertices(prev_col)
            gl_send_vertices(curr_col)
            strip_active = True
            
        elif a_visible and not b_visible:
            # Case 3: Stop strip
            if strip_active:
                # Send B (empty or degenerate) to close strip
                gl_send_vertices(curr_col)
                gl_end()
                strip_active = False
            else:
                # Strip was already inactive, just update prev
                pass
                
        elif not a_visible and not b_visible:
            # Case 4: Both not visible
            # Check for hole closure
            if strip_active:
                # Check hole condition
                # pY1, pY2 are prev_col endpoints, Y1, Y2 are curr_col endpoints
                # If curr_col is empty, we might use the last known bounds or skip
                # Source implies checking against previous column's bounds
                if len(prev_col) >= 2 and len(curr_col) >= 2:
                    pY1 = prev_col[0].y
                    pY2 = prev_col[-1].y
                    Y1 = curr_col[0].y
                    Y2 = curr_col[-1].y
                    
                    if (Y1 > pY1) and (Y2 > pY2):
                        # Draw closing triangle
                        # The source implies a single triangle. 
                        # Typically this connects the bottom of the gap.
                        # Implementation detail: [G]
                        gl_begin(GL_TRIANGLE_STRIP)
                        gl_send_vertices(prev_col) # Or specific vertices forming the gap
                        gl_send_vertices(curr_col)
                        gl_end()
                        # Note: This might temporarily activate a strip or draw a fan
                        # The source says "draw a single triangle", so GL_TRIANGLE_STRIP
                        # with 3 vertices is appropriate.
                        # However, the source logic is slightly ambiguous on whether
                        # this happens inside an active strip context or as an isolated draw.
                        # We assume it's an isolated draw or part of the strip closure.
                        # Given "started or finished at this point", it likely closes a gap.
                        pass
            prev_col = curr_col
            continue
            
        prev_col = curr_col
        
    if strip_active:
        gl_end()
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of scanned columns ($W/S$) and the number of visible voxels per column. The overhead of triangle strip construction is low compared to software span rendering.
*   **Memory Complexity:** Low. Only requires storage for two columns of projected vertices at a time.
*   **Measured Performance:** In the terraVoxGL demo, the method rendered 8664 triangles (across 4 passes) in 925 strips [S1, unofficial].
*   **Strengths:** Extremely efficient due to heavy use of triangle strips; leverages hardware interpolation for texture coordinates, lightmap colors, and heights; reduces draw calls compared to immediate span rendering [S1, unofficial].
*   **Limitations:** Mesh density can become excessive at the bottom of valleys; the hole-closure heuristic may render slightly invisible triangles; texturing scheme described (4 passes with alpha coefficients) is noted as inefficient [S1, unofficial].
*   **When to use:** When rendering voxel landscapes on hardware that supports efficient triangle strip processing and when performance is critical.
*   **When not to use:** When precise visibility culling is required without any overdraw, or when the landscape geometry is too dense to benefit from the fixed step size without significant visual artifacts.

## Background
The method was introduced by an anonymous author in the article "Realtime Voxel Landscape Engines - Part 6 - Hardware Acceleration" published on Flipcode on February 21, 2000 [S1, unofficial]. It was developed as part of the terraVoxGL demo to accelerate voxel landscape rendering by replacing software span rendering with hardware-accelerated triangle strips. The author noted that the code was written as a test and was not released, but the algorithm description was provided to allow others to implement it [S1, unofficial].
