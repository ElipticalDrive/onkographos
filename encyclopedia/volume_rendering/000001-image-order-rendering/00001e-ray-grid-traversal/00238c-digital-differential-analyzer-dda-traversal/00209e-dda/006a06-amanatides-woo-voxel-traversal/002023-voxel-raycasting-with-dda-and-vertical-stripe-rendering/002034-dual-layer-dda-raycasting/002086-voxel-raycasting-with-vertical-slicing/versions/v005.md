# Voxel Raycasting with Vertical Slicing

Also called: 12-layer vertical raycasting, voxel4.cpp raycaster

## Overview
A raycasting technique that renders a 3D voxel grid by treating each voxel column as 12 distinct vertical layers, drawing them as stacked horizontal stripes centered around the ray's intersection point [S1, unofficial]. Unlike standard 2D raycasting which draws a single vertical line per hit, this method visualizes voxel thickness and internal structure by iterating through all 12 vertical indices of a hit voxel [S1, unofficial]. It builds on [Dual-Layer DDA Raycasting](2212-dual-layer-dda-raycasting.md) by extending the binary floor/ceiling distinction into a continuous 12-layer vertical stack [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: 2D camera position $(posX, posY)$, direction vectors $(dirX, dirY)$, camera plane vector $(planeX, planeY)$, screen width $w$, screen height $h$, and a 3D voxel map `worldMap[mapWidth][mapHeight][12]` [S1, unofficial].
- Output: A 2D screen buffer where each column $x$ contains up to 12 vertical stripes representing the voxel layers [S1, unofficial].

**Data Structures:**
- `worldMap`: A 3D integer array of size `mapWidth` $\times$ `mapHeight` $\times$ 12. Dimensions are typically $96 \times 96$ [S1, unofficial]. The third dimension (size 12) represents the vertical layers [S1, unofficial]. Values 0-5 have specific color mappings; 6-11 default to Yellow [S1, unofficial].
- `depth`: An integer array of size $w$ (384 in the reference implementation), initialized to 100000 [S1, unofficial]. It is reset per ray and used to handle occlusion between vertical slices [S1, unofficial].

**Parameters:**
- `pitch`: A double constant representing the vertical tilt offset for the voxel stack. Default value is 200 [S1, unofficial].
- `cameraPlaneY`: The vertical component of the camera plane vector, determining the Field of View (FOV). Value is 0.66 [S1, unofficial].
- `planeX`: The horizontal component of the camera plane vector. Value is 0 [S1, unofficial].

**Steps:**
1. **Initialize Ray:** For each screen column $x$ from 0 to $w-1$, calculate `cameraX = 2 * x / w - 1` [S1, unofficial]. Calculate `rayDirX = dirX + planeX * cameraX` and `rayDirY = dirY + planeY * cameraX` [S1, unofficial]. Set `rayPosX = posX` and `rayPosY = posY` [S1, unofficial].
2. **Initialize DDA State:** Determine `mapX = int(rayPosX)` and `mapY = int(rayPosY)` [S1, unofficial]. Calculate `deltaDistX = sqrt(1 + (rayDirY * rayDirY) / (rayDirX * rayDirX))` and `deltaDistY = sqrt(1 + (rayDirX * rayDirX) / (rayDirY * rayDirY))` [S1, unofficial]. Determine `stepX` and `stepY` based on ray direction signs [S1, unofficial]. If `rayDirX < 0`, set `stepX = -1` and `sideDistX = (rayPosX - mapX) * deltaDistX`; else set `stepX = 1` and `sideDistX = (mapX + 1.0 - rayPosX) * deltaDistX` [S1, unofficial]. Apply the same logic for `stepY` and `sideDistY` using `rayDirY`, `rayPosY`, and `mapY` [S1, unofficial].
3. **Perform DDA Loop:** Initialize `hit = 0` [S1, unofficial]. While `hit < 100` and map coordinates are within bounds, if `sideDistX < sideDistY`, add `deltaDistX` to `sideDistX`, increment `mapX` by `stepX`, and set `side = 0`; else add `deltaDistY` to `sideDistY`, increment `mapY` by `stepY`, and set `side = 1` [S1, unofficial]. Clamp `mapX` to $[0, mapWidth-1]$ and `mapY` to $[0, mapHeight-1]$ [S1, unofficial]. If `worldMap[mapX][mapY][0]` is not empty, set `hit = 1` and break the loop [S1, unofficial].
4. **Calculate Perpendicular Distance and Line Height:** If `side == 0`, calculate `perpWallDist = (mapX - rayPosX + (1 - stepX) / 2) / rayDirX`; else calculate `perpWallDist = (mapY - rayPosY + (1 - stepY) / 2) / rayDirY` [S1, unofficial]. Calculate `lineHeight = int(h / perpWallDist)` [S1, unofficial].
5. **Render Voxel Layers:** Initialize `depth` array of size $w$ to 100000 [S1, unofficial]. Loop `b` from 0 to 11: calculate `drawStart = (lineHeight * (b - 6)) + pitch` and clamp to $[0, h-1]$ [S1, unofficial]. Calculate `drawEnd = lineHeight + (lineHeight * (b - 6)) + pitch` and clamp to $[0, h-1]$ [S1, unofficial]. Retrieve `color = worldMap[mapX][mapY][b]` [S1, unofficial]. If `side == 1`, divide `color` brightness by 2 [S1, unofficial]. If `color` is not Black, call `verLineDepth(x, drawStart, drawEnd, color, depth, w, &count)` [S1, unofficial].

**Pseudocode:**
```python
import math

def voxel_raycasting_vertical_slicing(posX, posY, dirX, dirY, planeX, planeY, w, h, mapWidth, mapHeight, worldMap, pitch=200.0):
    screen = [[0 for _ in range(h)] for _ in range(w)]
    
    for x in range(w):
        cameraX = 2 * x / w - 1
        rayDirX = dirX + planeX * cameraX
        rayDirY = dirY + planeY * cameraX
        
        rayPosX = posX
        rayPosY = posY
        
        mapX = int(rayPosX)
        mapY = int(rayPosY)
        
        deltaDistX = math.sqrt(1 + (rayDirY * rayDirY) / (rayDirX * rayDirX))
        deltaDistY = math.sqrt(1 + (rayDirX * rayDirX) / (rayDirY * rayDirY))
        
        if rayDirX < 0:
            stepX = -1
            sideDistX = (rayPosX - mapX) * deltaDistX
        else:
            stepX = 1
            sideDistX = (mapX + 1.0 - rayPosX) * deltaDistX
            
        if rayDirY < 0:
            stepY = -1
            sideDistY = (rayPosY - mapY) * deltaDistY
        else:
            stepY = 1
            sideDistY = (mapY + 1.0 - rayPosY) * deltaDistY
            
        hit = 0
        side = 0
        
        while hit < 100:
            if sideDistX < sideDistY:
                sideDistX += deltaDistX
                mapX += stepX
                side = 0
            else:
                sideDistY += deltaDistY
                mapY += stepY
                side = 1
            
            # Clamp map coordinates to grid bounds
            if mapX < 0: mapX = 0
            if mapX >= mapWidth: mapX = mapWidth - 1
            if mapY < 0: mapY = 0
            if mapY >= mapHeight: mapY = mapHeight - 1
            
            # Hit condition from source [S1, unofficial]
            if worldMap[mapX][mapY][0] != 0:
                hit = 1
                break
        
        if hit == 0:
            continue
            
        if side == 0:
            perpWallDist = (mapX - rayPosX + (1 - stepX) / 2) / rayDirX
        else:
            perpWallDist = (mapY - rayPosY + (1 - stepY) / 2) / rayDirY
            
        lineHeight = int(h / perpWallDist)
        
        # Depth buffer for occlusion within the column, reset per ray [S1, unofficial]
        depth = [100000] * w
        
        for b in range(12):
            drawStart = (lineHeight * (b - 6)) + pitch
            drawEnd = lineHeight + (lineHeight * (b - 6)) + pitch
            
            # Clamp to screen bounds [S1, unofficial]
            if drawStart < 0: drawStart = 0
            if drawStart >= h: drawStart = h - 1
            if drawEnd < 0: drawEnd = 0
            if drawEnd >= h: drawEnd = h - 1
            
            color = worldMap[mapX][mapY][b]
            
            if side == 1:
                color = color // 2 # Darken if side hit [S1, unofficial]
            
            if color != 0: # Assuming 0 is Black/Empty
                # verLineDepth is an implementation-specific helper for drawing vertical lines with depth testing [G]
                # verLineDepth(x, drawStart, drawEnd, color, depth, w, &count)
                pass
```

**Edge Cases and Pitfalls:**
- The reference implementation notes uncertainty about voxel aspect ratio, using `h / perpWallDist` without dividing by 2 to correct for non-square voxels, which may cause visual distortion [S1, unofficial].
- Division by zero in `deltaDistX` or `deltaDistY` occurs if `rayDirX` or `rayDirY` is exactly 0; standard DDA guards or epsilon checks are required [G].

## Subtopics

### [VoxlapGL](18154-voxlapgl.md)
Renders a 3D voxel grid by exploiting vertical ray coherence to cut space with multiple planes, determining visible voxel segments in software and projecting them as rectangles onto the screen using an OpenGL stencil buffer. Unlike Voxel Raycasting with Vertical Slicing, which renders and combines lines, VoxlapGL projects rectangles and contains no quadrant distinctions in its traversal code.

## Operating characteristics
- **Time Complexity:** $O(w \cdot h)$ for rendering, where $w$ is screen width and $h$ is screen height. The DDA traversal is $O(\text{distance})$ per ray, and the vertical slicing adds a constant factor of 12 iterations per hit.
- **Memory Complexity:** $O(\text{mapWidth} \cdot \text{mapHeight} \cdot 12)$ for the voxel map, plus $O(w)$ for the depth buffer [S1, unofficial].
- **Strengths:** Visualizes voxel thickness and internal structure, providing a more 3D-aware appearance than standard raycasting [S1, unofficial].
- **Limitations:** The aspect ratio of voxels may be distorted if not adjusted (source notes uncertainty about dividing by 2 for square voxels) [S1, unofficial]. The fixed 12-layer structure limits flexibility in voxel depth representation.

## Background
This technique is an unofficial implementation of a 12-layer vertical raycasting method [S1, unofficial]. It extends the concept of dual-layer raycasting to a more granular vertical representation, allowing for the visualization of voxel depth in a 2D screen space [S1, unofficial].
