# Voxel Polygon Rendering
## Overview
Voxel Polygon Rendering is a hybrid rendering technique that fills the screen with vertical bars representing heights from a voxel map, effectively projecting a 2D area of the map onto the screen as a flat landscape [S1, unofficial]. It solves the problem of rendering high-detail terrain at constant speed by avoiding traditional 6DOF polygon operations such as rotation matrix calculations and clipping [S1, unofficial]. Unlike its sibling [Voxel Raycasting with DDA and Vertical Stripe Rendering](2206-voxel-raycasting-with-dda-and-vertical-stripe-rendering.md), which casts rays per screen column to find the first occupied voxel, Voxel Polygon Rendering maps screen pixels directly to map locations and draws spans from close to far, using an s-buffer (vertical c-buffer) to handle floating bars and prevent overdraw [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A voxel map (array of height and color per location), screen resolution, camera position, and camera yaw (y-axis rotation) [S1, unofficial].
- Output: A rendered image with vertical bars representing terrain height [S1, unofficial].

**Data Structures:**
- `VoxelMap`: A 2D array where each cell stores `height` and `color` [S1, unofficial].
- `ColumnHeights`: An array of size `screen_width`, storing the current drawn height for each screen column to enable clipping [S1, unofficial].
- `S-Buffer` (Vertical C-Buffer): A data structure managing floating voxel bars that do not start at the bottom of the screen, storing depth and height values to handle occlusion for bars with both top and bottom sides [S1, unofficial].

**Steps:**
1. **Map Pixels to Voxel Space:** For each pixel on the screen, determine its corresponding location on the voxel map based on the camera's y-axis rotation and position [S1, unofficial]. Calculate the distance of the pixel from the camera to apply perspective correction, ensuring distant "mountains" appear smaller [S1, unofficial].
2. **Retrieve Voxel Data:** Fetch the height and color data from the voxel map [S1, unofficial]. To reduce blockiness, apply bilinear filtering by retrieving four adjacent voxels (texels) [S1, unofficial].
3. **Calculate Span Height and Color:** Compute the weighted average of the heights of the four fetched texels to determine the height of the single one-pixel wide span [S1, unofficial]. Compute the weighted average of the colors of the four fetched texels to determine the span's color [S1, unofficial].
4. **Clip Against Column Height:** Compare the calculated span height against the current height stored in `ColumnHeights` for that column [S1, unofficial]. If the span is behind the existing bar, clip it [S1, unofficial]. If it is in front, update `ColumnHeights` with the new height [S1, unofficial].
5. **Draw Span:** Draw the vertical bar (span) for the pixel [S1, unofficial]. If the bar is floating (not starting at the bottom), use the `S-Buffer` to manage its visibility and occlusion against other floating bars [S1, unofficial].
6. **Repeat for All Columns:** Process all screen columns from the bottom of the screen up to the horizon (approximately halfway up the screen) [S1, unofficial].
7. **Fill Backdrop:** Fill the screen space above the horizon with a backdrop image [S1, unofficial].

**Formulas:**
- **Bilinear Height Interpolation:**
  $$ H_{span} = \frac{H_1 + H_2 + H_3 + H_4}{4} $$
  Where $H_1, H_2, H_3, H_4$ are the heights of the four adjacent voxels [S1, unofficial].
- **Bilinear Color Interpolation:**
  $$ C_{span} = \frac{C_1 + C_2 + C_3 + C_4}{4} $$
  Where $C_1, C_2, C_3, C_4$ are the colors of the four adjacent voxels [S1, unofficial].

**Parameters:**
- **Rotation Constraint:** The scene can only be rotated around the y-axis [S1, unofficial]. Looking up/down (x-axis) is limited to about 10 degrees; looking down by 45 degrees wastes the picture because voxel bars must be perfectly vertical [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Flat Floor Performance:** Worst-case performance occurs on a completely flat floor [S1, unofficial]. Every column of the screen becomes one higher every time a new line is processed [S1, unofficial]. For the single pixel drawn, significant work is done: comparing to current column height, clipping, drawing, and updating column height [S1, unofficial]. This is likely more expensive than drawing a single perspective-correct texture map [S1, unofficial].
- **Floating Bars:** The usual voxel algorithm assumes bars start at the bottom screen line [S1, unofficial]. Floating bars (e.g., bridges, ceilings) require an s-buffer (vertical c-buffer) to handle correctly, as they have both a top and bottom side [S1, unofficial].
- **Blockiness:** Without bilinear filtering, voxels look blocky [S1, unofficial]. Small details tend to flicker when the camera moves [S1, unofficial].

**Pseudocode:**
```python
def render_voxel_polygon_screen(voxel_map, screen_width, screen_height, camera_yaw, camera_pos):
    NEG_INF = -float('inf')
    column_heights = [NEG_INF] * screen_width
    horizon_y = screen_height // 2

    for y in range(screen_height - 1, horizon_y - 1, -1):
        for x in range(screen_width):
            # 1. Map pixel to voxel map location
            # Standard perspective projection logic not detailed in source
            voxel_x, voxel_y = map_pixel_to_voxel(x, y, camera_yaw, camera_pos)

            # 2. Retrieve four adjacent voxels for bilinear filtering
            h1, c1 = get_voxel(voxel_map, voxel_x, voxel_y)
            h2, c2 = get_voxel(voxel_map, voxel_x + 1, voxel_y)
            h3, c3 = get_voxel(voxel_map, voxel_x, voxel_y + 1)
            h4, c4 = get_voxel(voxel_map, voxel_x + 1, voxel_y + 1)

            # 3. Calculate weighted average height and color
            span_height = (h1 + h2 + h3 + h4) / 4.0
            span_color = (c1 + c2 + c3 + c4) / 4.0

            # 4. Clip against column height
            current_col_height = column_heights[x]
            if span_height <= current_col_height:
                continue

            # 5. Draw span
            bar_top = span_height
            bar_bottom = current_col_height
            for py in range(int(bar_bottom), int(bar_top) + 1):
                framebuffer[y][x] = span_color

            # Update column height
            column_heights[x] = bar_top

    # Fill backdrop above horizon
    for y in range(0, horizon_y):
        for x in range(screen_width):
            framebuffer[y][x] = backdrop_color

def map_pixel_to_voxel(x, y, camera_yaw, camera_pos):
    # Standard perspective projection logic not detailed in source
    return 0, 0

def get_voxel(voxel_map, x, y):
    # Standard bounds-checked array access not detailed in source
    x = max(0, min(x, len(voxel_map[0]) - 1))
    y = max(0, min(y, len(voxel_map) - 1))
    return voxel_map[y][x].height, voxel_map[y][x].color
```
## Subtopics

### [Triangle Strip Voxel Projection](15933-triangle-strip-voxel-projection.md)
A hardware-accelerated rendering method for voxel landscapes that replaces software span rendering with triangle strips. It projects voxels onto the screen in columns and constructs geometry based on the visibility of adjacent columns to minimize polygon count and utilize hardware interpolation. Unlike software span rendering which draws spans immediately, this method buffers column projections to construct triangle strips, reducing draw calls and leveraging hardware interpolation for texture coordinates, lightmap colors, and heights.

## Operating characteristics
- **Time Complexity:** Virtually constant speed regardless of scene detail, as it processes each screen pixel once [S1, unofficial]. However, worst-case performance occurs on a completely flat floor, where every column's height is updated for every line, leading to significant clipping and drawing overhead per pixel [S1, unofficial].
- **Memory Complexity:** Requires a large voxel map [S1, unofficial]. Memory usage can be mitigated by tiling pre-built tiles of voxels [S1, unofficial].
- **Strengths:** Constant rendering speed; no 6DOF rotation matrix calculations or clipping required; allows for high detail; bilinear filtering reduces blockiness; supports floating structures via s-buffer [S1, unofficial].
- **Limitations:** Limited to y-axis rotation (approx. 10 degrees up/down); cannot handle significant x-axis rotation; blockiness without filtering; flickering of small details; worst-case performance on flat terrain [S1, unofficial].
- **When to Use:** Rendering high-detail terrain at constant speed where y-axis rotation is sufficient [S1, unofficial].
- **When Not to Use:** When full 6DOF rotation is required; when performance on flat terrain is critical; when memory is severely constrained without tiling support [S1, unofficial].
## Background
Voxel Polygon Rendering was introduced by Jacco Bikker (a.k.a. "THE PHANTOM") in 1999 on Flipcode [S1, unofficial]. It was developed as an alternative to traditional 6DOF polygon engines, aiming to provide high-detail graphics with constant speed [S1, unofficial]. The technique was considered for inclusion in the "Focus" engine [S1, unofficial].
