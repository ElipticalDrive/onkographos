# 2.5D Grid Traversal with Z-interpolation


## Overview
A method to traverse a 2D grid where each cell has a min/max height range, by extending a 2D DDA algorithm to calculate the Z-coordinate at each cell entry/exit to check for overlap with the cell's height range [S1, unofficial]. It solves the problem of efficiently culling cells in a 2.5D terrain or height-field representation during ray traversal, avoiding the cell-skipping errors of Bresenham's algorithm when the ray has a significant Z-component [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $(start.x, start.y, start.z)$ and end $(end.x, end.y, end.z)$ [S1, unofficial].
- Grid resolution $m\_gridresolution$ [S1, unofficial].
- Step direction $(step.x, step.y)$, where each component is $+1$ or $-1$ indicating the traversal direction in that axis [S1, unofficial].
- Cell height bounds: for each grid cell $(i, j)$, a minimum height $min\_z_{i,j}$ and maximum height $max\_z_{i,j}$ [S1, unofficial].

**Outputs:**
- Sequence of grid cells $(i, j)$ intersected by the ray segment that overlap with their respective height ranges [S1, unofficial].

**Data Structures:**
- `deltaZ`: A 2D vector storing the change in Z per unit distance in X and Y respectively [S1, unofficial].
- `currentOffset`: A 2D vector storing the accumulated distance along X and Y from the ray origin to the current grid boundary being crossed [S1, unofficial].

**Formulas:**
1.  **Z-offset per unit distance:**
    $$fzoffset = end.z - start.z$$
    $$deltaZ.x = \frac{fzoffset}{|end.x - start.x|}$$
    $$deltaZ.y = \frac{fzoffset}{|end.y - start.y|}$$
    [S1, unofficial]

2.  **Initial Z-offsets at starting grid boundaries:**
    $$currentOffset.x = \begin{cases} start.x \cdot m\_gridresolution - start.x & \text{if } step.x > 0 \\ (start.x + 1) \cdot m\_gridresolution - start.x & \text{if } step.x \le 0 \end{cases}$$
    $$currentOffset.y = \begin{cases} start.y \cdot m\_gridresolution - start.y & \text{if } step.y > 0 \\ (start.y + 1) \cdot m\_gridresolution - start.y & \text{if } step.y \le 0 \end{cases}$$
    [S1, unofficial]

3.  **Z-value at cell entry/exit:**
    When stepping in the X axis:
    $$z = currentOffset.x \cdot deltaZ.x + start.z$$
    [S1, unofficial]
    When stepping in the Y axis:
    $$z = currentOffset.y \cdot deltaZ.y + start.z$$
    [S1, unofficial]

**Algorithm Steps:**
1.  Calculate `fzoffset`, `deltaZ`, and `currentOffset` using the formulas above [S1, unofficial].
2.  Initialize the current grid cell $(cx, cy)$ to the cell containing $(start.x, start.y)$ [S1, unofficial].
3.  Enter the traversal loop, which continues until the ray exits the grid or the end point is reached:
    a.  Determine which axis boundary is next based on comparing the accumulated distances to the next X and Y grid lines [G].
    b.  If stepping in the X axis: increment `currentOffset.x` by `m_gridresolution`, calculate $z = currentOffset.x \cdot deltaZ.x + start.z$, and update $cx$ by adding $step.x$ [S1, unofficial].
    c.  If stepping in the Y axis: increment `currentOffset.y` by `m_gridresolution`, calculate $z = currentOffset.y \cdot deltaZ.y + start.z$, and update $cy$ by adding $step.y$ [S1, unofficial].
    d.  Check if the calculated $z$ value at the cell boundary overlaps with the height range of the current cell $(cx, cy)$ [S1, unofficial].
    e.  If the cell overlaps, process it [S1, unofficial].

**Pseudocode:**
```python
def traverse_25d_grid(start, end, grid_resolution, step_x, step_y, get_cell_heights):
    """
    Traverses a 2.5D grid, checking Z-overlap for each cell.
    start: (x, y, z) tuple
    end: (x, y, z) tuple
    grid_resolution: float, size of one grid cell
    step_x: int, +1 or -1
    step_y: int, +1 or -1
    get_cell_heights: function that returns (min_z, max_z) for a given (cx, cy)
    """
    fzoffset = end[2] - start[2]
    dx = abs(end[0] - start[0])
    dy = abs(end[1] - start[1])
    delta_z_x = fzoffset / dx if dx != 0 else 0.0
    delta_z_y = fzoffset / dy if dy != 0 else 0.0

    # [G] Standard Amanatides-Woo initialization for distance to next grid line
    current_offset_x = (start[0] if step_x > 0 else start[0] + 1) * grid_resolution - start[0]
    current_offset_y = (start[1] if step_y > 0 else start[1] + 1) * grid_resolution - start[1]

    cx = int(start[0])
    cy = int(start[1])

    t_max_x = current_offset_x / dx if dx != 0 else float('inf')
    t_delta_x = step_x / dx if dx != 0 else float('inf')
    t_max_y = current_offset_y / dy if dy != 0 else float('inf')
    t_delta_y = step_y / dy if dy != 0 else float('inf')

    cells = []
    while True:
        if t_max_x < t_max_y:
            current_offset_x += grid_resolution
            z = current_offset_x * delta_z_x + start[2]
            cx += step_x
            t_max_x += t_delta_x
        else:
            current_offset_y += grid_resolution
            z = current_offset_y * delta_z_y + start[2]
            cy += step_y
            t_max_y += t_delta_y

        t = min(t_max_x, t_max_y)
        if t > 1.0:
            break

        min_z, max_z = get_cell_heights(cx, cy)
        if min_z <= z <= max_z:
            cells.append((cx, cy))
    return cells
```

**Edge Cases and Pitfalls:**
- **Bresenham Inadequacy:** Bresenham's algorithm is insufficient because it only finds one cell in the non-primary axis for each step of the primary axis, skipping cells that are intersected by the line (e.g., cell (3,4) in the example sequence (2,3), (3,3), (3,4), (4,4)) [S1, unofficial].
- **Division by Zero:** If the ray is parallel to the X or Y axis, the corresponding `deltaZ` component involves division by zero [S1, unofficial]. The implementation guards against this by setting `delta_z` to `0.0` and `t_delta` to `inf` when the axis distance is zero [G].
- **Boundary Conditions:** The initialization of `currentOffset` assumes the starting point is not exactly on a grid line [S1, unofficial]. Floating-point precision near grid boundaries may cause repeated cell visits or skips, which is a known limitation of DDA methods [G].
