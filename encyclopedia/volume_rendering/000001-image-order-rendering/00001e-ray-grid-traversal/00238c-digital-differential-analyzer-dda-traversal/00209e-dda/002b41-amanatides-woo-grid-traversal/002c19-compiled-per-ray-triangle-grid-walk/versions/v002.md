# Compiled Per-Ray Triangle Grid Walk

Also called: Numba grid walk, compiled triangle-grid walk

## Overview
A ray traversal method that walks a triangle grid using a compiled loop (Numba) with one iteration per ray, replacing the previous array-based approach that used whole-array numpy passes over every ray still in flight [S1, unofficial]. Unlike the array walk, this method forms no (ray, triangle) pair arrays, so `blocks` takes no `work_limit` parameter [S1, unofficial]. It builds on [Amanatides–Woo grid traversal](5003-amanatides-woo-grid-traversal.md) by compiling the per-ray traversal logic into a tight loop, eliminating the overhead of managing global ray state arrays between voxel steps [S1, unofficial].

## How it works
**Inputs:**
- Ray origins and directions [S1, unofficial].
- Triangle grid definition (vertices, faces) [S1, unofficial].
- Grid bounds and resolution [S1, unofficial].

**Outputs:**
- For each ray: the first triangle hit (or null if no hit), or the traversal end point [S1, unofficial].
- Visited voxel sequence (implicit in the walk) [S1, unofficial].

**Data Structures:**
- No global (ray, triangle) pair arrays are formed [S1, unofficial].
- Per-ray state: current voxel coordinates, step sizes, and traversal parameters (axis permutation, shear) [S1, unofficial].

**Steps:**
1. **Initialization:** Compile the traversal loop using `numba.njit(parallel=True)` [S1, unofficial].
2. **Ray Iteration:** Iterate over rays using `prange` such that each ray is processed in its own iteration [S1, unofficial].
3. **Per-Ray Setup:** For each ray, form the axis permutation and shear parameters once per ray, not per triangle [S1, unofficial].
4. **Voxel Walk:** Walk the ray through the voxels of the triangle grid to its first hit or its end, visiting the same voxels in the same order as the array walk [S1, unofficial].
5. **Triangle Test:** For each voxel visited, test for intersection with triangles within that voxel [S1, unofficial]. Use the same watertight test (Woop, Benthin & Wald), including the averaged, exactly antisymmetric edge function, implemented as `grid_walk._cuts` [S1, unofficial].
6. **Tie Rule and Step Cap:** Apply the same tie rule and step cap as the original array walk [S1, unofficial].
7. **Termination:** Stop when a hit is found or the ray exits the grid bounds [S1, unofficial].

**Pseudocode:**
```python
import numba
import numpy as np

@numba.njit(parallel=True)
def compiled_per_ray_walk(ray_origins, ray_directions, grid_bounds, grid_resolution, voxel_triangles):
    """
    Walks a triangle grid for each ray using a compiled loop.
    
    Args:
        ray_origins: (R, 3) float32 array of ray origins.
        ray_directions: (R, 3) float32 array of ray directions.
        grid_bounds: (6) float32 array defining the grid AABB.
        grid_resolution: (3) int32 array defining the grid dimensions.
        voxel_triangles: (nx, ny, nz) int32 array of triangle indices per voxel.
        
    Returns:
        hits: (R,) int32 array of hit triangle indices (-1 if no hit).
        hit_t: (R,) float32 array of hit distances.
    """
    R = ray_origins.shape[0]
    hits = np.full(R, -1, dtype=np.int32)
    hit_t = np.full(R, np.inf, dtype=np.float32)
    
    min_x, min_y, min_z, max_x, max_y, max_z = grid_bounds
    nx, ny, nz = grid_resolution
    
    for r in numba.prange(R):
        ox, oy, oz = ray_origins[r]
        dx, dy, dz = ray_directions[r]
        
        # [G] Standard Amanatides-Woo initialization
        inv_dx, inv_dy, inv_dz = 1.0 / dx, 1.0 / dy, 1.0 / dz
        step_x = 1 if dx > 0 else -1
        step_y = 1 if dy > 0 else -1
        step_z = 1 if dz > 0 else -1
        
        # Compute initial voxel coordinates
        voxel_x = int((ox - min_x) * nx / (max_x - min_x))
        voxel_y = int((oy - min_y) * ny / (max_y - min_y))
        voxel_z = int((oz - min_z) * nz / (max_z - min_z))
        
        # Clamp to grid bounds
        voxel_x = max(0, min(voxel_x, nx - 1))
        voxel_y = max(0, min(voxel_y, ny - 1))
        voxel_z = max(0, min(voxel_z, nz - 1))
        
        # Compute t_max and t_delta for each axis
        t_max_x = ((voxel_x + (1 if step_x > 0 else 0)) * (max_x - min_x) / nx + min_x - ox) * inv_dx
        t_max_y = ((voxel_y + (1 if step_y > 0 else 0)) * (max_y - min_y) / ny + min_y - oy) * inv_dy
        t_max_z = ((voxel_z + (1 if step_z > 0 else 0)) * (max_z - min_z) / nz + min_z - oz) * inv_dz
        t_delta_x = abs((max_x - min_x) / nx * inv_dx)
        t_delta_y = abs((max_y - min_y) / ny * inv_dy)
        t_delta_z = abs((max_z - min_z) / nz * inv_dz)
        
        # Walk loop
        while True:
            # Check bounds
            if not (0 <= voxel_x < nx and 0 <= voxel_y < ny and 0 <= voxel_z < nz):
                break
            
            # Test triangles in current voxel
            tri_list = voxel_triangles[voxel_x, voxel_y, voxel_z]
            for tri_idx in tri_list:
                # [G] Standard Amanatides-Woo triangle intersection test
                # [S1, unofficial] Uses grid_walk._cuts: averaged, exactly antisymmetric edge function
                # If hit found and t < hit_t[r], update hits[r] and hit_t[r]
                pass # Implementation of grid_walk._cuts logic per source contract
            
            # Advance to next voxel
            if t_max_x < t_max_y:
                if t_max_x < t_max_z:
                    voxel_x += step_x
                    t_max_x += t_delta_x
                else:
                    voxel_z += step_z
                    t_max_z += t_delta_z
            else:
                if t_max_y < t_max_z:
                    voxel_y += step_y
                    t_max_y += t_delta_y
                else:
                    voxel_z += step_z
                    t_max_z += t_delta_z
            
            # [G] Apply tie rule and step cap as in original array walk
            # Termination if hit found
            if hit_t[r] < np.inf:
                break
    
    return hits, hit_t
```

**Parameters:**
- Numba version: `numba>=0.61` (required for Python 3.13 wheels) [S1, unofficial].
- Thread control: `NUMBA_NUM_THREADS=1` is set to prevent xdist workers from starting a machine-sized pool [S1, unofficial].

**Edge Cases and Pitfalls:**
- The intersection test exists twice: `grid_walk._cuts` for the Numba loop and `_watertight_hit` + `_counts_as_hit` for the traced dense path, because a Numba loop cannot call a traced function [S1, unofficial].
- They must be kept equal by contract tests [S1, unofficial].
- The first call of a process compiles the loop, taking approximately 2 seconds [S1, unofficial].
- The inclusive far end: a segment ending in a triangle's plane is blocked [S1, unofficial].
- The exclusive near margin: a hit exactly at the margin doesn't count (axis-aligned) [S1, unofficial].

## Operating characteristics
- **Measured Performance:** On a 4-core Linux container CPU, RayCastOcclusion on a 4,992-facet annular reactor: 54.47 s (main) vs 2.49 s (PR), a 21.9x speed-up [S1, unofficial]. TriangleBody wall (51,328 triangles, 18.4M pairs): 211.9 s (main) vs 15.4 s (PR), a 13.8x speed-up [S1, unofficial]. TriangleBody wall with default ShaftCulling(): 43.8 s (main) vs 2.3 s (PR), a 19.0x speed-up [S1, unofficial]. Walk alone measured against array walk on 200,000 rays: 16.9-37.3x speed-up across two scenes and three resolutions [S1, unofficial].
- **Strengths:** Significant speed-up over array-based walks, especially for large numbers of rays and complex grids [S1, unofficial]. Eliminates the overhead of managing global ray state arrays [S1, unofficial].
- **Limitations:** Initial compilation time (~2 seconds) [S1, unofficial]. Requires Numba as a dependency [S1, unofficial]. The intersection test must be duplicated for Numba and traced paths, increasing maintenance burden [S1, unofficial].
- **When to Use:** When performance is critical and the number of rays is large [S1, unofficial].
- **When Not to Use:** When Numba is not available or acceptable as a dependency [S1, unofficial].

## Background
- **Origin:** Introduced by ctdegroot in Pull Request #571 to the DeGrootResearchGroup/aquaflux repository, dated Sep 26, 2026 [S1, unofficial].
- **History:** The method was developed to address the performance bottleneck of the previous array-based walk, which spent significant time on bookkeeping per ray per voxel step [S1, unofficial]. The inspiration came from observing how production ray tracers like Embree achieve speed through compiled per-ray traversal [S1, unofficial].
- **Usage:** Used in the aquaflux repository for radiation simulations, specifically for computing ray masks and triangle body interactions [S1, unofficial].
