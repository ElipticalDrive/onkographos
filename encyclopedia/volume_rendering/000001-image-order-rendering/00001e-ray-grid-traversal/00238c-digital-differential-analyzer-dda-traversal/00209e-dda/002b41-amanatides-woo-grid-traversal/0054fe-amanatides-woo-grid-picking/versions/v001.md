# Amanatides-Woo Grid Picking

Also called: Amanatides-Woo DDA for Grid Picking, DDA over the level map, pure Amanatides-Woo DDA

## Overview
A method to pick grid cells by traversing a 2D grid using a Digital Differential Analyzer (DDA) ray traversal algorithm, replacing expensive raycasting against terrain meshes [S1, unofficial]. It determines the cell and face ('top' or 'side') hit by a ray, handling voids and raised terrain [S1, unofficial]. It builds on [Amanatides–Woo grid traversal](5003-amanatides-woo-grid-traversal.md) but applies the traversal logic specifically to a height-map-based level map rather than a generic voxel or triangle grid [S1, unofficial]. Unlike siblings that may use fixed-point arithmetic or 2.5D interpolation, this method operates on a logical grid independent of the visual ground mesh detail, ensuring picks remain exact and cheap [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `grid`: A 2D logical grid structure defining cell boundaries in the X-Z plane.
    *   `heightAt(cell)`: A function returning the floor Y for a given cell. It returns the drawn floorY from continued levels, `CHASM_DEPTH` for void cells, or `min(level, cutLevel)` if a cut is applied [S1, unofficial].
    *   `origin`: The ray origin $(x_0, y_0, z_0)$.
    *   `dir`: The ray direction vector $(d_x, d_y, d_z)$.
    *   `cutLevel`: A parameter limiting the maximum height considered for hits (default $\infty$) [S1, unofficial].
*   **Outputs:**
    *   A result object containing:
        *   `cell`: The grid cell index $(x, z)$ hit, or `null` if no cell is hit.
        *   `point`: The 3D hit point $(x, y, z)$.
        *   `face`: `'top'` or `'side'`, indicating which face of the cell was intersected [S1, unofficial].
    *   If `cell` is `null`, `point` is still provided as the ray's intersection with the $y=0$ plane (or `null` if it never meets it) to support edge snapping [S1, unofficial].

**Data Structures:**
*   The grid is treated as a logical 2D array or hash map of cells. Each cell has an associated height value retrieved via `heightAt`.
*   The ray is defined by origin and direction.
*   DDA state variables: `tMaxX`, `tMaxZ` (distance to next grid boundary crossing), `tDeltaX`, `tDeltaZ` (distance between grid boundaries along the ray) [S1, unofficial].

**Algorithm Steps:**

1.  **Clip the Ray:**
    Restrict the ray to the grid's bounding box.
    *   Restrict $x$ and $z$ to the grid bounds.
    *   Restrict $y$ from the chasm depth (void level) to the highest top level [S1, unofficial].
    *   If the ray does not intersect this bounding box, return `null` [S1, unofficial].

2.  **Initialize DDA Variables:**
    Calculate the initial step distances for the X and Z axes using the standard Amanatides-Woo DDA initialization [S1, unofficial]:
    $$ tDeltaX = \frac{1}{|d_x|} $$
    $$ tDeltaZ = \frac{1}{|d_z|} $$
    $$ tMaxX = \frac{x_{next\_boundary} - x_0}{d_x} $$
    $$ tMaxZ = \frac{z_{next\_boundary} - z_0}{d_z} $$
    Determine the initial step direction (`stepX`, `stepZ`) based on the sign of $d_x$ and $d_z$ [S1, unofficial].

3.  **Traverse Cells:**
    Iterate through cells in the grid, stepping through columns (X or Z) based on which `tMax` is smaller [S1, unofficial].
    *   At each step, determine the current cell $(x, z)$ [S1, unofficial].
    *   Get the cell's top surface height: $h = heightAt(cell)$ [S1, unofficial].
    *   Calculate the ray's Y position at the current cell's entry point (or the point where it enters the column) [S1, unofficial].
    *   **Check for Hit:** If the ray drops below the current cell's top surface height ($y_{ray} < h$) before leaving the current column:
        *   A hit occurs [S1, unofficial].
        *   Determine the hit face:
            *   If the ray entered the cell above the top surface ($y_{entry} > h$), the hit is on the **'top'** face at the crossing point [S1, unofficial].
            *   Otherwise, the hit is on the **'side'** face at the entry point [S1, unofficial]. Side hits return the raised cell [S1, unofficial].
        *   Return `{ cell, point, face }` [S1, unofficial].
    *   If the ray does not drop below the top surface, update `tMaxX` or `tMaxZ` and step to the next cell [S1, unofficial].

4.  **Handle Voids:**
    If the ray enters a hole (void cell), apply specific void rules: return the void cell or the owner of the wall it meets, based on the implementation's void handling logic [S1, unofficial].

5.  **Handle No Hit:**
    If the traversal completes without finding a hit (e.g., ray exits the grid bounds or passes above all terrain):
    *   Return `{ cell: null, point }` where `point` is the ray's intersection with the $y=0$ plane [S1, unofficial].
    *   If the ray never meets $y=0$, return `null` for the point [S1, unofficial].

6.  **Snapping Data:**
    Compute snapping data (corner, edge, edgeDistance) from the final hit point using the same logic as the previous system (`worldToCorner`, `worldToEdge`) [S1, unofficial]. If no cell is hit, use the ray's intersection with the $y=0$ plane for this computation [S1, unofficial].

**Pseudocode:**

```python
def pick_cell(grid, height_at, origin, dir, cut_level=float('inf')):
    """
    Pick a grid cell using Amanatides-Woo DDA over a level map.
    
    Args:
        grid: 2D grid structure with bounds and cell access.
        height_at: Function(cell) -> float, returns floor Y.
        origin: (x, y, z) ray origin.
        dir: (dx, dy, dz) ray direction.
        cut_level: Maximum height for hits.
        
    Returns:
        dict with 'cell', 'point', 'face' or 'cell': None, 'point': (x, y, z)
    """
    # 1. Clip Ray to Grid Bounding Box
    # Grid bounds: x_min, x_max, z_min, z_max
    # Y bounds: chasm_depth to max_top_level
    # If ray does not intersect box, return None
    
    # 2. Initialize DDA Variables
    # Calculate tDelta and tMax for X and Z axes
    # Standard Amanatides-Woo initialization
    # tDeltaX = 1.0 / abs(dir.dx)
    # tDeltaZ = 1.0 / abs(dir.dz)
    # tMaxX = (next_x_boundary - origin.x) / dir.dx
    # tMaxZ = (next_z_boundary - origin.z) / dir.dz
    # stepX = 1 if dir.dx > 0 else -1
    # stepZ = 1 if dir.dz > 0 else -1
    
    # 3. Traverse Cells
    # Current cell (cx, cz) = initial cell containing origin
    # Current t = 0
    
    while True:
        # Get current cell height
        cell = grid.get_cell(cx, cz)
        if cell is None:
            # Out of bounds, no hit
            # Return null cell and y=0 intersection if applicable
            return { 'cell': None, 'point': ray_intersect_y0(origin, dir) }
        
        # Get effective height
        h = height_at(cell)
        if h > cut_level:
            h = cut_level
            
        # Calculate ray Y at current cell entry
        # This requires tracking the ray's position at the start of the current cell
        # For simplicity, assume we have ray_pos at cell entry
        ray_y_at_entry = origin.y + dir.y * t_current
        
        # Check if ray drops below top surface before leaving column
        # Determine distance to next X or Z boundary
        if tMaxX < tMaxZ:
            t_next = tMaxX
            next_cell_x = cx + stepX
            next_cell_z = cz
        else:
            t_next = tMaxZ
            next_cell_x = cx
            next_cell_z = cz + stepZ
            
        # Ray Y at next boundary
        ray_y_at_boundary = origin.y + dir.y * t_next
        
        # Check for top hit: ray crosses below top surface within this cell
        # If ray_y_at_entry > h AND ray_y_at_boundary < h, then top hit
        # Or if ray_y_at_entry < h, it might be a side hit? 
        # Clarification from notes: "if the ray drops below the current cell's top surface height before leaving the current column: a hit occurs."
        # "if the ray entered the cell above the top surface, the hit is on the 'top' face... Otherwise, the hit is on the 'side' face"
        
        if ray_y_at_entry > h and ray_y_at_boundary < h:
            # Top hit
            # Calculate exact hit point
            t_hit = (h - origin.y) / dir.y
            point = (origin.x + dir.x * t_hit, h, origin.z + dir.z * t_hit)
            return { 'cell': cell, 'point': point, 'face': 'top' }
        elif ray_y_at_entry < h:
            # Side hit (ray entered below top, so it hits the side wall of the raised cell)
            # Hit point is the entry point to the cell
            point = (origin.x + dir.x * t_current, origin.y + dir.y * t_current, origin.z + dir.z * t_current)
            return { 'cell': cell, 'point': point, 'face': 'side' }
            
        # Handle void cells
        if cell.is_void:
            # Apply void rules: return void cell or owner of wall
            # Implementation specific
            pass
            
        # Step to next cell
        if tMaxX < tMaxZ:
            tMaxX += tDeltaX
            cx += stepX
        else:
            tMaxZ += tDeltaZ
            cz += stepZ
            
        # Check if out of bounds
        if not grid.contains(cx, cz):
            return { 'cell': None, 'point': ray_intersect_y0(origin, dir) }

def ray_intersect_y0(origin, dir):
    if dir.y == 0:
        return None
    t = -origin.y / dir.y
    if t < 0:
        return None
    return (origin.x + dir.x * t, 0, origin.z + dir.z * t)
```

**Parameters:**
*   `cutLevel`: Default $\infty$. Limits the maximum height considered for hits [S1, unofficial].
*   `heightAt(cell)`: Returns drawn floorY, `CHASM_DEPTH` for void, or `min(level, cutLevel)` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Rounded Corners:** Rounded corners in the visual mesh differ from logical columns by at most ~0.1 cell near grid corners. The DDA picks stay logical by design, ignoring visual rounding [S1, unofficial].
*   **Pick Layer:** The raycaster must be restricted to a specific layer (`PICK_LAYER`) to ensure decorative meshes (ground chunks, cliffs, backdrop, dice, effects) do not interfere with picking, while tokens, props, walls, and lights remain pickable [S1, unofficial].
*   **No Hit:** If no cell is hit, the method still provides the ray's intersection with the $y=0$ plane for edge snapping [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of cells crossed by the ray [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:** Under 0.05 ms per pick on a 100x100 grid [S1, unofficial]. This is significantly faster than brute-force raycasting (10.6 ms for 205k triangles) [S1, unofficial].
*   **Scaling:** Linear with the number of cells crossed. No GPU cost; identical on every backend and tier [S1, unofficial].
*   **Strengths:** Exact, cheap, testable, ignores decorative geometry, handles voids and raised terrain [S1, unofficial].
*   **Limitations:** Logical grid only; does not account for visual mesh details like rounded corners [S1, unofficial].
*   **When to Use:** When picking cells in a 3D grid-based game environment where performance is critical and visual mesh detail should not affect picking [S1, unofficial].
*   **When Not to Use:** When precise visual mesh intersection is required (e.g., for visual effects or non-grid-based interactions) [S1, unofficial].

## Background
*   **Origin:** Developed for the 'Node' project (Thirdfold/client) to replace `TerrainLayer` and `WorldGround`'s play-area plane [S1, unofficial].
*   **History:** Introduced in issue #246 of the Thirdfold/client repository [S1, unofficial]. It was created because the previous method of raycasting terrain boxes or a table plane at $y=0$ was expensive and no longer viable as boxes were removed and organic ground became more complex [S1, unofficial].
*   **Usage:** Used in the 'Node' project for cell picking in a 3D grid-based game environment [S1, unofficial].
