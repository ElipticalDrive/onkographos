# Hierarchical DDA

Also called: 3-level bit pyramid traversal, Multilevel DDA Raycasting

## Overview
Hierarchical DDA accelerates ray traversal in sparse voxel grids by skipping empty regions using a multi-level occupancy hierarchy, avoiding the $O(N)$ voxel visits of standard DDA [S2, unofficial]. It sets itself apart from standard DDA by descending the hierarchy only upon hitting occupied nodes, allowing large open spaces to be skipped at coarse granularities [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$ (normalized), and a 3-level occupancy hierarchy.
- Output: The first intersection point or distance along the ray.

**Data Structures:**
The hierarchy is a 3-level bit pyramid [S1, unofficial]:
1.  **Chunk Level:** The world is divided into $64^3$ voxel chunks. Each chunk contains a bitfield representing $16^3$ tiles.
2.  **Tile Level:** Each tile contains a bitfield representing $4^3$ bricks.
3.  **Brick Level:** Each brick contains a 64-bit occupancy mask representing individual voxels (or sub-voxel details, depending on implementation).

**Steps:**
1.  **Top-Level Traversal:** Cast the ray against the top-level hierarchy (chunks). Determine the entry and exit points of the ray within the current chunk.
2.  **Empty Space Skipping:** If the current chunk is empty (all bits zero), skip to the next chunk boundary. This is done using exact cell-boundary snapping via a `skip_to_cell` function [S1, unofficial].
3.  **Descent:** If the current chunk is occupied, descend to the tile level. Repeat the traversal and skipping logic for tiles within the chunk.
4.  **Base Level:** Once at the brick level, perform standard DDA traversal within the occupied brick to find the exact voxel intersection.
5.  **Termination:** Return the intersection point. If the ray exits the world bounds without hitting geometry, terminate.

**Parameters:**
- Chunk size: $64^3$ voxels [S1, unofficial].
- Tile size: $16^3$ voxels [S1, unofficial].
- Brick size: $4^3$ voxels [S1, unofficial].
- Safety margin: A 16-voxel safety margin may be used when fast-forwarding rays based on pre-pass data [S1, unofficial].

**Pseudocode:**
```python
def hierarchical_dda(ray_origin, ray_direction, hierarchy):
    # Start at the top level (chunks)
    current_level = hierarchy.top_level
    
    while current_level is not None:
        # Determine the segment of the ray within the current hierarchical node
        entry_t, exit_t = ray_segment(ray_origin, ray_direction, current_level.bounds)
        
        # Check if the node is empty
        if not current_level.is_occupied:
            # Skip to the next occupied node or boundary
            # This uses exact cell-boundary snapping
            next_node = skip_to_cell(ray_origin, ray_direction, entry_t, current_level)
            if next_node is None:
                return None  # Ray exited world
            current_level = next_node
            continue
            
        # If occupied, check if we are at the base level
        if current_level.is_base_level:
            # Perform standard DDA within this occupied node
            intersection = dda_traverse(ray_origin, ray_direction, current_level)
            return intersection
        else:
            # Descend to the next level
            # Find the child node that the ray enters
            child_node = get_child_node(current_level, ray_origin, ray_direction, entry_t)
            if child_node is None:
                return None  # Ray passed through empty space in this node
            current_level = child_node
            
    return None
```

**Edge Cases and Pitfalls:**
- Precision issues may arise when snapping to cell boundaries; use exact arithmetic or robust geometric predicates [S1, unofficial].
- Degenerate input (ray parallel to grid axes) should be handled by standard DDA edge cases [S1, unofficial].

## Subtopics

### [Hierarchical DDA with Chunk Stepping](8591-hierarchical-dda-with-chunk-stepping.md)
Traces a ray through a hierarchical voxel map by stepping through chunks using a 3D DDA algorithm. It treats the lowest hierarchy level as solid $8 \times 8 \times 8$ blocks, allowing the ray to skip empty regions in $O(1)$ time per chunk boundary. Choose this when chunk-level skipping is sufficient and finer granularity is not needed.

## Operating characteristics
- **Time Complexity:** $O(\log N)$ in the best case (sparse scenes), where $N$ is the number of voxels. In dense scenes, it degrades to $O(N)$ similar to standard DDA.
- **Memory Complexity:** $O(N)$ for the hierarchy, with a small constant factor overhead for the bitfields.
- **Performance:** Significantly faster than standard DDA in open space due to large skips [S2, unofficial]. Performance depends on the sparsity of the scene.
- **Strengths:** Efficiently handles large empty spaces; reduces memory bandwidth by skipping empty voxels.
- **Limitations:** Overhead of hierarchy traversal; less effective in dense scenes.
- **When to Use:** Sparse voxel grids with large empty regions.
- **When Not to Use:** Dense scenes or when memory overhead is a constraint.

## Background
Hierarchical DDA was developed to address the inefficiency of standard DDA in sparse voxel grids [S2, unofficial]. It builds on the concept of multi-level raycasting, where large open spaces are skipped by casting rays on a top-level hierarchy and descending to the base level only upon hitting geometry [S2, unofficial]. The method was initially implemented on the CPU before being ported to the GPU [S2, unofficial]. It is used in real-time voxel rendering engines, such as voxelG, to optimize ray marching performance [S1, unofficial].
