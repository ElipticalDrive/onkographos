# TRFRay3 (DDA Ray Representation)

Also called: Digital Differential Analyzer Traversal, DDA Ray Marching, Ray Marching with DDA, Digital Differential Analyzer raymarching, DDA Raycasting with zero-direction handling

## Overview
TRFRay3 is a specific data structure and traversal algorithm for performing Digital Differential Analyzer (DDA) ray marching through a voxel grid [S4, unofficial]. It solves the problem of efficiently determining which voxels a ray intersects by stepping through adjacent grid cells without division inside the main loop [S2, unofficial]. It sets itself apart from standard Amanatides-Woo implementations by precomputing an Origin-Inverse Direction (OOD) value and storing ray state in a contiguous, SIMD-friendly layout, enabling integer-step traversal logic [S4, unofficial]. Unlike Hierarchical DDA, it operates on a flat grid level, though it can be combined with hierarchical structures for skipping [S1, S5, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{O}$, ray direction $\mathbf{D}$, and voxel grid dimensions.
**Outputs:** Sequence of visited voxel coordinates $(x, y, z)$ and traversal distance $t$.

**Data Structures:**
The core structure `TRFRay3<T>` contains five 3-component vectors (`TRFVector3<T>`), laid out contiguously in memory to support SIMD vectorization [S4, unofficial]:
1.  `kOrigin`: The ray origin $\mathbf{O}$.
2.  `kDirection`: The ray direction $\mathbf{D}$.
3.  `kInvDirection`: Component-wise reciprocal of direction, $1/\mathbf{D}$.
4.  `kOod`: Origin-Inverse Direction, computed as $\mathbf{O} \odot (1/\mathbf{D})$ [S4, unofficial].
5.  `kSigns`: Component-wise sign of direction, $\text{sign}(\mathbf{D})$ [S4, unofficial].

**Initialization:**
1.  **Validation:** If any component of $\mathbf{D}$ is zero or near-zero, the ray is invalid for standard DDA because the sign function returns 0, preventing voxel advancement [S1, S2, unofficial]. The implementation requires floating-point types and assumes non-zero direction components to avoid division by zero in `kInvDirection` [S4, unofficial].
2.  **Precomputation:**
    *   $kInvDirection_i = 1 / D_i$ for $i \in \{x, y, z\}$ [S4, unofficial].
    *   $kOod_i = O_i \times kInvDirection_i$ [S4, unofficial].
    *   $kSigns_i = \text{sign}(D_i)$ [S4, unofficial].
3.  **Boundary Check:** Compute entry ($t_{enter}$) and exit ($t_{exit}$) distances for the world window. If $t_{enter} \ge t_{exit}$ or $t_{exit} < 0$, the ray misses the world [S1, unofficial].

**Traversal Loop:**
The traversal advances the ray through the voxel grid. Two common implementations exist in the sources: one using explicit $t_{max}$ and $t_{delta}$ (Amanatides-Woo style) [S1, S2, unofficial], and one using the OOD/`sideDist` method [S3, unofficial]. The TRFRay3 structure specifically supports the OOD-based logic found in [S3, unofficial] and [S4, unofficial].

1.  **Initial Voxel:** Calculate the starting voxel index $\mathbf{pos} = \lfloor \mathbf{O} \rfloor$ [S3, unofficial].
2.  **Distance Vectors:**
    *   $\mathbf{deltaDist} = |1/\mathbf{D}|$ [S3, unofficial].
    *   $\mathbf{rayStep} = \text{sign}(\mathbf{D})$ [S3, unofficial].
    *   $\mathbf{sideDist}$ represents the distance to the next voxel boundary along each axis. It is initialized using the OOD value:
        $$ \mathbf{sideDist}_i = (\text{sign}(D_i) \times (\lfloor O_i \rfloor - O_i) + 0.5 + 0.5) \times \Delta_i $$
        *Note: Source [S3, unofficial] formula is complex; a standard equivalent using OOD is often derived as $\mathbf{sideDist} = (\mathbf{pos} - \mathbf{O} + 0.5 \times \mathbf{rayStep} + 0.5) \odot \mathbf{deltaDist}$ or similar variations depending on coordinate system alignment [S3, unofficial].*
3.  **Iteration:**
    *   Determine which axis is closest to the next boundary. Create a mask $\mathbf{m}$ where $m_i = 1$ if $\mathbf{sideDist}_i$ is the minimum among $\mathbf{sideDist}_x, \mathbf{sideDist}_y, \mathbf{sideDist}_z$, else 0.
        $$ \mathbf{m} = \text{lessThanEqual}(\mathbf{sideDist}, \min(\mathbf{sideDist}_{yzx}, \mathbf{sideDist}_{zxy})) $$
    *   Update distances and position:
        $$ \mathbf{sideDist} \leftarrow \mathbf{sideDist} + \mathbf{m} \odot \mathbf{deltaDist} $$
        $$ \mathbf{pos} \leftarrow \mathbf{pos} + \mathbf{m} \odot \mathbf{rayStep} $$
    *   Compute the normal of the face crossed:
        $$ \mathbf{normal} = \mathbf{m} \odot (-\mathbf{rayStep}) $$
    *   Check for termination conditions (e.g., max steps, leaving world, hitting target) [S1, unofficial].

**Pitfalls:**
*   **Zero Direction Components:** If $D_i = 0$, $\text{sign}(D_i) = 0$. The voxel coordinate does not change, but $t_{max}$ may still advance, causing infinite loops or incorrect normals [S2, unofficial]. Fix: Set $t_{delta} = \infty$ and $t_{max} = \infty$ for zero-direction axes so they never win the minimum comparison [S2, unofficial].
*   **Precision:** Floating-point errors in $t_{max}$ or `sideDist` can cause the ray to skip voxels or revisit them. Using integer arithmetic for voxel indices and fixed-point for distances is recommended where possible [S4, unofficial].
*   **Toroidal Wrapping:** In some implementations (e.g., voxelG), voxel coordinates are wrapped using modulo arithmetic for toroidal worlds [S1, unofficial].

**Pseudocode:**
```python
def traverse_dda_trfray3(ray_origin, ray_direction, world_bounds, max_steps):
    # 1. Validation
    if any(abs(d) < 1e-9 for d in ray_direction):
        return [] # Invalid ray, zero direction component

    # 2. Precomputation (TRFRay3 structure fields)
    inv_dir = 1.0 / ray_direction
    ood = ray_origin * inv_dir
    signs = [1 if d > 0 else -1 for d in ray_direction]
    delta_dist = abs(inv_dir)
    
    # 3. Initial Voxel
    pos = floor(ray_origin)
    
    # 4. Initial Side Distances
    # Formula from [S3, unofficial]: sideDist_i = (sign(D_i) * (floor(O_i) - O_i) + 0.5 + 0.5) * deltaDist_i
    # Note: The "+ 0.5 + 0.5" simplifies to +1.0 in some interpretations, but we follow [S3, unofficial] literally.
    side_dist = [0.0, 0.0, 0.0]
    for i in range(3):
        side_dist[i] = (signs[i] * (pos[i] - ray_origin[i]) + 1.0) * delta_dist[i]

    visited = []
    
    for step in range(max_steps):
        # Add current voxel to visited list
        visited.append(pos)
        
        # 5. Determine axis to advance
        # Find index of minimum side_dist
        min_idx = 0
        min_val = side_dist[0]
        for i in range(1, 3):
            if side_dist[i] < min_val:
                min_val = side_dist[i]
                min_idx = i
        
        # 6. Update state
        side_dist[min_idx] += delta_dist[min_idx]
        pos[min_idx] += signs[min_idx]
        
        # 7. Boundary Check (World Bounds)
        if not is_within_world(pos, world_bounds):
            break
            
    return visited

def is_within_world(pos, world_bounds):
    # Example check for non-toroidal world
    return (world_bounds.min.x <= pos.x <= world_bounds.max.x and
            world_bounds.min.y <= pos.y <= world_bounds.max.y and
            world_bounds.min.z <= pos.z <= world_bounds.max.z)
```

## Subtopics

### [Hierarchical DDA](12757-hierarchical-dda.md)
A variant where the DDA traversal is performed on a top-level hierarchy (e.g., an octree or grid hierarchy) to skip large empty spaces. The ray is cast on the coarse level, and only when a hit is detected does it descend to the base level for detailed DDA traversal. This reduces the number of steps in open scenes compared to flat DDA.

### DDA Raycasting Lighting
A post-processing or shading step applied after the GPU raycaster has determined the voxel hits. It involves experimenting with lighting effects (e.g., shadows, ambient occlusion) based on the traversal results [S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of voxels intersected by the ray. The cost per step is constant and very low (comparisons and additions) [S2, S4, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space for the traversal state (TRFRay3 structure) [S4, unofficial].
*   **Performance:** Highly efficient for dense grids and short rays. Performance degrades in highly transparent scenes where the ray traverses many empty voxels [S5, unofficial].
*   **Strengths:** Simple implementation, no recursion, cache-friendly data layout (contiguous vectors) [S4, unofficial], suitable for GPU vectorization [S4, unofficial].
*   **Limitations:** Cannot skip empty space inherently (unlike Hierarchical DDA or SVO traversal) [S5, unofficial]. Sensitive to zero-direction rays [S2, unofficial].

## Background
TRFRay3 is a specific implementation of DDA ray marching, often associated with the Voxelizer project and similar voxel rendering engines [S4, unofficial]. The DDA algorithm itself was originally described by Amanatides and Woo (1987) for ray tracing through voxel grids [S1, S3, unofficial]. The TRFRay3 structure optimizes this by precomputing inverse directions and OOD values to avoid division in the loop [S4, unofficial]. It has been used in experimental graphics engines like voxelG for hardware ray tracing integration and in educational projects for voxel rendering [S1, S5, unofficial].
