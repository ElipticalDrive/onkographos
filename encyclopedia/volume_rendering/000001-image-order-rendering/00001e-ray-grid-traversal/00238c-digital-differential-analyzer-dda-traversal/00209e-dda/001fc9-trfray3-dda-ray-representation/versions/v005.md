# TRFRay3 (DDA Ray Representation)

Also called: Digital Differential Analyzer Traversal, DDA Ray Marching, Ray Marching with DDA, Digital Differential Analyzer raymarching, DDA Raycasting with zero-direction handling

## Overview
TRFRay3 is a data structure and traversal algorithm for performing Digital Differential Analyzer (DDA) ray marching through a voxel grid [S4, unofficial]. It solves the problem of efficiently determining which voxels a ray intersects by stepping through adjacent grid cells based on the ray's direction [S2, unofficial]. It sets itself apart from its siblings by encapsulating the ray state (origin, direction, inverse direction, and signs) into a contiguous, SIMD-friendly structure that precomputes division-heavy terms to avoid runtime division [S4, unofficial]. Unlike [Amanatides-Woo Voxel Traversal](3132-amanatides-woo-voxel-traversal.md) which explicitly tracks `tMax` and `tDelta` per axis, TRFRay3 often utilizes an Origin-Inverse Direction (OOD) formulation or similar precomputed offsets to drive the integer-step traversal [S4, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{O}$, ray direction $\mathbf{D}$, and voxel grid/world bounds [G].
**Outputs:** Sequence of visited voxel coordinates $(x, y, z)$ and traversal parameters [G].

### Data Structures
The core structure `TRFRay3<T>` contains five 3-component vectors, laid out contiguously in memory to support SIMD vectorization [S4, unofficial]:
1.  `kOrigin`: The ray origin $\mathbf{O}$.
2.  `kDirection`: The ray direction $\mathbf{D}$.
3.  `kInvDirection`: The component-wise reciprocal of the direction, $1/\mathbf{D}$.
4.  `kOod`: The Origin-Inverse Direction product, $\mathbf{O} \odot (1/\mathbf{D})$.
5.  `kSigns`: The component-wise sign of the direction, $\text{sign}(\mathbf{D})$.

The data layout allows `Data()` to return a pointer to `kOrigin`, ensuring all five fields are contiguous [S4, unofficial].

### Formulas
The traversal relies on precomputed values to avoid division inside the loop [S4, unofficial]:

1.  **Inverse Direction:**
    $$ \text{kInvDirection}_i = \frac{1}{\text{kDirection}_i} \quad \text{for } i \in \{x, y, z\} $$
2.  **Signs:**
    $$ \text{kSigns}_i = \begin{cases} -1 & \text{if } \text{kDirection}_i < 0 \\ 1 & \text{otherwise} \end{cases} $$
3.  **Origin-Inverse Direction (OOD):**
    $$ \text{kOod}_i = \text{kOrigin}_i \times \text{kInvDirection}_i $$
4.  **Side Distance Initialization:**
    $$ \text{sideDist} = (\text{sign}(\mathbf{D}) \times (\lfloor \mathbf{P} \rfloor - \mathbf{O}) + (\text{sign}(\mathbf{D}) \times 0.5) + 0.5) \times \text{deltaDist} $$
    where $\mathbf{P}$ is the current voxel position and $\text{deltaDist} = |\text{kInvDirection}|$ [S3, unofficial].

### Algorithm Steps
1.  **Initialization:** Compute `kInvDirection`, `kSigns`, and `kOod` [S4, unofficial]. Initialize `pos` as the floor of `rayPos`, `deltaDist` as the absolute value of `invRayDir`, and `sideDist` using the formula above [S3, unofficial]. Compute window bounds (`win_min`, `win_max`) from `world_origin` and `WORLD_VOXELS_*`, calculate `t_enter` and `t_exit`, and return early if `t_enter >= t_exit` or `t_exit < 0.0` [S1, unofficial].
2.  **Iteration:** Create a `mask` using `lessThanEqual(sideDist.xyz, min(sideDist.yzx, sideDist.zxy))` [S3, unofficial]. Add `vec3(mask) * deltaDist` to `sideDist` [S3, unofficial]. Add `ivec3(mask) * rayStep` to `mapPos` [S3, unofficial]. Set `normal` to `vec3(mask) * -rayStep` [S3, unofficial].
3.  **Advancement:** Advance the ray along the axis with the smallest `t_max` (or minimum `sideDist`), updating the voxel coordinate and `t_max`/`sideDist` accordingly, and return -1 if no valid axis exists [S1, unofficial].
4.  **Boundary & Occupancy Checks:** Check if a voxel is within the world window using modulo arithmetic for toroidal wrapping [S1, unofficial]. Check if a voxel is solid by computing the brick index, checking the occupancy bit, and excluding `MAT_LEAF_FRINGE` [S1, unofficial].
5.  **Phases:** Phase 1 skips past any solid voxels the camera is standing inside. Phase 2 returns the first solid voxel hit as the visible surface [S1, unofficial].
6.  **Termination:** Stop if the ray exits the world bounds or a maximum step count is reached [S1, unofficial].

### Pseudocode
```python
def traverse_dda(ray_origin, ray_direction, world_bounds, max_steps):
    # Guard against zero direction components to prevent infinite loops [S2, unofficial]
    if any(d == 0.0 for d in ray_direction):
        inv_dir = vec3(1.0 / d if d != 0.0 else float('inf') for d in ray_direction)
        signs = vec3(1.0 if d > 0 else (-1.0 if d < 0 else 0.0) for d in ray_direction)
        delta_dist = abs(inv_dir)
    else:
        inv_dir = 1.0 / ray_direction
        signs = vec3(1.0 if d > 0 else -1.0 for d in ray_direction)
        delta_dist = abs(inv_dir)

    # Initialize voxel position and side distances [S3, unofficial]
    current_voxel = floor(ray_origin)
    side_dist = (signs * (current_voxel - ray_origin) + (signs * 0.5) + 0.5) * delta_dist

    visited_voxels = []

    for step in range(max_steps):
        # Identify axis with minimum distance to next boundary [S3, unofficial]
        min_val = min(side_dist.x, side_dist.y, side_dist.z)
        if side_dist.x == min_val:
            axis = 0
        elif side_dist.y == min_val:
            axis = 1
        else:
            axis = 2

        # Update voxel coordinate and side distance for the winning axis [S3, unofficial]
        if axis == 0:
            current_voxel.x += signs.x
            side_dist.x += delta_dist.x
        elif axis == 1:
            current_voxel.y += signs.y
            side_dist.y += delta_dist.y
        else:
            current_voxel.z += signs.z
            side_dist.z += delta_dist.z

        # Check bounds using modulo arithmetic for toroidal wrapping [S1, unofficial]
        if current_voxel.x < 0 or current_voxel.x >= world_bounds.x or \
           current_voxel.y < 0 or current_voxel.y >= world_bounds.y or \
           current_voxel.z < 0 or current_voxel.z >= world_bounds.z:
            break
        visited_voxels.append(current_voxel)

    return visited_voxels
```

### Parameters
*   `MAX_STEPS`: Maximum number of DDA steps allowed per raycast call to prevent infinite loops in degenerate cases [S1, unofficial]. Typical value depends on world size; often set to the total number of voxels along the longest diagonal or a fixed large integer [G].

### Edge Cases and Pitfalls
*   **Zero Direction Components:** If any component of $\mathbf{D}$ is 0, `sign()` returns 0, and `inv_dir` is undefined (division by zero) [S4, unofficial]. In the traversal loop, a zero step means the voxel coordinate never changes for that axis. If `tDelta`/`sideDist` is finite, this axis might still be selected as the "minimum," causing the ray to advance in time/parameter without moving in grid space, leading to infinite loops or incorrect normals [S2, unofficial].
    *   *Fix:* Set `inv_dir` component to `Infinity`, `sign` to 0, and `delta_dist` to `Infinity`. This ensures the axis never wins the `min` comparison [S2, unofficial].
*   **Precision:** The method requires floating-point types for `inv_dir` and `side_dist` [S4, unofficial]. Integer arithmetic alone is insufficient for the distance calculations unless fixed-point approximations are used [G].
*   **Toroidal Wrapping:** In some implementations (e.g., voxelG), world bounds are handled via modulo arithmetic for toroidal wrapping [S1, unofficial].

## Subtopics

### [Hierarchical DDA](12757-hierarchical-dda.md)
Hierarchical DDA accelerates ray traversal in sparse voxel grids by skipping empty regions using a multi-level occupancy hierarchy, avoiding the $O(N)$ voxel visits of standard DDA. It sets itself apart from standard DDA by descending the hierarchy only upon hitting occupied nodes, allowing large open spaces to be skipped at coarse granularities.

## Operating characteristics
*   **Time Complexity:** $O(K)$, where $K$ is the number of voxels visited [G]. In dense scenes, $K$ is proportional to the ray length [G]. In sparse scenes with standard DDA, $K$ can be large; Hierarchical DDA reduces this significantly [S5, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary memory for the traversal state (TRFRay3 structure) [G]. The voxel grid itself is external.
*   **Performance:** The precomputation of `inv_dir`, `signs`, and `ood` moves division operations out of the inner loop, making it efficient on modern CPUs and GPUs [S4, unofficial]. The contiguous memory layout of `TRFRay3` facilitates SIMD vectorization [S4, unofficial].
*   **Strengths:** Simple to implement, robust for dense grids, low memory overhead.
*   **Limitations:** Inefficient for sparse grids with large empty regions compared to hierarchical methods. Sensitive to zero-direction rays if not handled explicitly [S2, unofficial].

## Background
TRFRay3 is a specific implementation of the DDA ray traversal algorithm, often found in custom C++ math libraries (e.g., RFMath) [S4, unofficial]. It is used in applications requiring efficient voxel raycasting, such as hardware-accelerated ray tracing in voxel engines (e.g., voxelG) where it serves as the software fallback or the in-brick resolution step for hardware RT cores [S1, unofficial]. The OOD (Origin-Inverse Direction) formulation is a common optimization in DDA implementations to reduce computational cost per step [S4, unofficial].
