# Amanatides and Woo Voxel Traversal

Also called: Amanatides and Woo, Amanatides-Woo 3D DDA, Amanatides and Woo 3D-DDA Ray Traversal, Amanatides and Woo Voxel Ray Traversal, Amanatides-Woo voxel traversal algorithm, Amanatides and Woo traversal, A Fast Voxel Traversal Algorithm for Ray Tracing, 3D DDA, 3D Digital Differential Analyzer, DDA Voxel Traversal, Voxel Traversal (DDA), Voxel traversal using DDA, Amanatides and Woo 1987

## Overview

The Amanatides and Woo algorithm is a 3D Digital Differential Analyzer (DDA) method for traversing a uniform voxel grid along a ray, visiting every intersected voxel in order of increasing distance from the ray origin [S5, unofficial]. It solves the problem of efficiently determining the sequence of grid cells a ray passes through without expensive division operations in the main loop, guaranteeing that the ray stops and tests a voxel index at exactly one of the x, y, or z dividing planes [S2, unofficial]. It sets itself apart from naive fixed-step ray marching by using boundary-crossing logic to ensure no voxels are missed, and from hierarchical methods by operating directly on a flat uniform grid [S1, unofficial].

## How it works

**Inputs and Outputs**
*   **Input:** Ray origin $u = (u_x, u_y, u_z)$, ray direction $v = (v_x, v_y, v_z)$, grid bounds (min/max coordinates or dimensions), and voxel size (typically unit size 1.0, or explicit `bin_size`) [S1, unofficial][S5, unofficial].
*   **Output:** A sequence of voxel indices $(i, j, k)$ visited by the ray, optionally with parametric distances $t$ or step lengths [S1, unofficial][S3, unofficial].

**Data Structures**
The algorithm maintains three arrays of size 3 for each axis $a \in \{x, y, z\}$:
1.  `coord[a]`: Integer voxel index (current cell) [S2, unofficial].
2.  `step[a]`: Integer step direction ($+1$ or $-1$) [S2, unofficial].
3.  `t_max[a]`: Parametric distance $t$ to the next voxel boundary along axis $a$ [S5, unofficial].
4.  `t_delta[a]`: Parametric distance to traverse one full voxel width along axis $a$ [S5, unofficial].

**Numbered Steps**

1.  **Initialization Phase:**
    a.  Determine the starting voxel index containing the ray origin:
        $$ \text{coord}[a] = \lfloor \frac{u_a - \text{min}_a}{\text{voxel\_size}} \rfloor $$
        If the origin is outside the grid, compute the entry point $t_{entry}$ and adjust `coord` to the first intersected voxel [S18, unofficial][S28, unofficial].
    b.  Determine step direction for each axis:
        $$ \text{step}[a] = \begin{cases} 1 & \text{if } v_a \ge 0 \\ -1 & \text{if } v_a < 0 \end{cases} $$
        Handle zero direction components by setting `step[a]` to 1 (or -1) and `t_delta[a]` to $\infty$ to avoid division by zero [S20, unofficial][S24, unofficial].
    c.  Calculate the parametric distance to the first boundary crossing for each axis. Let $frac0(x) = x - \lfloor x \rfloor$ and $frac1(x) = 1 - frac0(x)$ be the fractional distance to the previous and next integer, respectively [S12, unofficial].
        $$ t_{\delta}[a] = \frac{\text{voxel\_size}}{|v_a|} \quad \text{if } v_a \neq 0, \text{ else } \infty $$
        $$ t_{\max}[a] = \begin{cases} t_{\delta}[a] \cdot frac1(\frac{u_a - \text{min}_a}{\text{voxel\_size}}) & \text{if } v_a \ge 0 \\ t_{\delta}[a] \cdot frac0(\frac{u_a - \text{min}_a}{\text{voxel\_size}}) & \text{if } v_a < 0 \end{cases} $$
        If the ray starts outside the grid, add the entry $t$ value to `t_max` [S14].
    d.  Initialize current parametric position $t_{curr} = 0$ (or $t_{entry}$) [S24, unofficial].

2.  **Traversal Loop:**
    a.  Find the axis $axis$ with the minimum `t_max`:
        $$ axis = \arg \min_{a \in \{x,y,z\}} (t_{\max}[a]) $$
    b.  Advance the ray to this boundary:
        $$ t_{curr} = t_{\max}[axis] $$
    c.  Increment the voxel index along the crossing axis:
        $$ \text{coord}[axis] \leftarrow \text{coord}[axis] + \text{step}[axis] $$
    d.  Update the time to the *next* boundary for that axis:
        $$ t_{\max}[axis] \leftarrow t_{\max}[axis] + t_{\delta}[axis] $$
    e.  Test the new voxel at `coord`. If occupied or if a specific condition is met, process it. If the new `coord` is out of grid bounds, terminate [S28, unofficial].
    f.  Repeat until the ray exits the grid or reaches a maximum distance/step count [S1, unofficial].

**Pseudocode**

```python
import math

def amanatides_woo_traversal(origin, direction, grid_min, grid_max, voxel_size):
    """
    Traverses a uniform voxel grid along a ray.
    
    Args:
        origin: (float, float, float) Ray origin (u_x, u_y, u_z).
        direction: (float, float, float) Ray direction (v_x, v_y, v_z).
        grid_min: (float, float, float) Minimum bounds of the grid.
        grid_max: (float, float, float) Maximum bounds of the grid.
        voxel_size: float Side length of a voxel.
        
    Yields:
        (int, int, int) Voxel indices visited by the ray.
    """
    # 1. Initialization
    
    # Calculate inverse direction and handle zero components
    inv_dir = [1.0 / d if d != 0 else float('inf') for d in direction]
    
    # Determine step direction (+1 or -1)
    step = [1 if d >= 0 else -1 for d in direction]
    
    # Calculate t_delta: distance to cross one voxel
    t_delta = [abs(voxel_size * inv_dir[i]) if inv_dir[i] != float('inf') else float('inf') for i in range(3)]
    
    # Calculate initial voxel coordinates
    # Using floor of (origin - min) / voxel_size
    coord = [int(math.floor((origin[i] - grid_min[i]) / voxel_size)) for i in range(3)]
    
    # Calculate t_max: distance to the next boundary
    # frac0(x) = x - floor(x), frac1(x) = 1 - frac0(x)
    # We need the fractional distance to the next integer boundary relative to the grid
    # The boundary coordinate is (coord[i] + 1) * voxel_size + grid_min[i] if step > 0
    # or coord[i] * voxel_size + grid_min[i] if step < 0
    
    t_max = [0.0, 0.0, 0.0]
    for i in range(3):
        if inv_dir[i] == float('inf'):
            t_max[i] = float('inf')
        else:
            # Distance to the next grid plane
            if step[i] > 0:
                # Next plane is at coord + 1
                dist_to_plane = ((coord[i] + 1) * voxel_size + grid_min[i]) - origin[i]
            else:
                # Next plane is at coord
                dist_to_plane = (coord[i] * voxel_size + grid_min[i]) - origin[i]
            
            t_max[i] = dist_to_plane * inv_dir[i]
            
    # Current parametric t
    t_curr = 0.0
    
    # 2. Traversal Loop
    while True:
        # Check bounds
        if not (0 <= coord[0] < (grid_max[0] - grid_min[0]) / voxel_size and
                0 <= coord[1] < (grid_max[1] - grid_min[1]) / voxel_size and
                0 <= coord[2] < (grid_max[2] - grid_min[2]) / voxel_size):
            break
            
        # Yield current voxel
        yield tuple(coord)
        
        # Find axis with minimum t_max
        # In a tight loop, this can be unrolled or optimized
        min_t = t_max[0]
        axis = 0
        if t_max[1] < min_t:
            min_t = t_max[1]
            axis = 1
        if t_max[2] < min_t:
            min_t = t_max[2]
            axis = 2
            
        # Advance to the next boundary
        t_curr = min_t
        coord[axis] += step[axis]
        t_max[axis] += t_delta[axis]

# Example Usage
# origin = (0.5, 0.5, 0.5)
# direction = (1.0, 1.0, 1.0)
# grid_min = (0.0, 0.0, 0.0)
# grid_max = (10.0, 10.0, 10.0)
# voxel_size = 1.0
# for v in amanatides_woo_traversal(origin, direction, grid_min, grid_max, voxel_size):
#     print(v)
```

**Edge Cases and Pitfalls**
*   **Zero Direction Components:** If $v_a = 0$, the ray is parallel to the grid planes of axis $a$. `t_delta[a]` and `t_max[a]` must be set to $\infty$ to prevent the ray from ever crossing that axis, effectively locking the coordinate on that axis [S20, unofficial][S24, unofficial].
*   **Origin Outside Grid:** If the ray origin is outside the bounding box, the initial `t_max` values must be adjusted to reflect the distance to the entry point into the grid volume, not just the first local voxel boundary [S18, unofficial][S28, unofficial].
*   **Precision Errors:** Floating-point accumulation in `t_max` can lead to precision drift over long traversals. Using a relative $t$ or re-normalizing can mitigate this, though standard implementations often rely on the fact that `t_max` is only used for comparison [S29, unofficial].
*   **Z-fighting/Self-Intersection:** When sampling the voxel at the boundary, slight offsets may be needed to avoid sampling the same voxel twice or missing it due to precision [S1, unofficial].

## Subtopics

### [Voxel Raycasting with Normal Estimation](3901-voxel-raycasting-with-normal-estimation.md)
Voxel Raycasting with Normal Estimation is a brute-force raycasting algorithm for voxel grids that steps along a ray at fixed intervals to find the first solid voxel, then estimates the surface normal based on the direction of travel relative to the voxel grid axes. It differs from [Amanatides and Woo Voxel Traversal](3132-amanatides-and-woo-voxel-traversal.md) by using fixed-step sampling rather than boundary-crossing logic, making it simpler to implement but less efficient for sparse or large-scale scenes.

### [3D Bresenham Voxel Tracing](3949-3d-bresenham-voxel-tracing.md)
3D Bresenham Voxel Tracing is a discrete ray traversal algorithm for uniform 3D voxel grids that steps through adjacent voxels along the ray's path using integer arithmetic and error accumulation, rather than floating-point slab intersections. Unlike [Amanatides and Woo Voxel Traversal](3132-amanatides-and-woo-voxel-traversal.md), which uses floating-point $t$-values to determine the next voxel boundary, this method maintains a fixed-step iteration on the dominant axis and updates secondary axes based on accumulated error terms, making it computationally cheaper and immune to floating-point precision errors. It is primarily used for sparse particle systems or dense uniform grids where hierarchical acceleration structures are absent.

### [Restartable DDA for Voxel Traversal](5187-restartable-dda-for-voxel-traversal.md)
Restartable DDA for Voxel Traversal is a Digital Differential Analyzer (DDA) algorithm designed to traverse a 3D voxel grid while allowing the ray direction to be modified mid-walk, such as during refraction events. It solves the problem of maintaining traversal state consistency when a ray changes direction, enabling efficient volume transmission calculations without restarting the entire traversal from the original origin. It is distinct from standard Amanatides and Woo traversal by its explicit support for re-initializing the state structure with a new origin and direction while preserving the grid geometry context, and it differs from [3D Bresenham Voxel Tracing](3949-3d-bresenham-voxel-tracing.md) by using floating-point distance calculations rather than integer arithmetic.

### [Naive Voxel Ray Traversal](5192-naive-voxel-ray-traversal.md)
Naive voxel ray traversal is a method for determining which voxels a ray intersects by stepping forward from the ray origin in small, fixed increments of the ray direction. It solves the problem of identifying the sequence of voxels along a ray path but is characterized by its inability to guarantee intersection with all voxels the ray passes through. It is distinct from its parent, Amanatides and Woo Voxel Traversal, which advances to the nearest voxel boundary to guarantee no voxels are missed, whereas the naive method uses arbitrary step sizes that can skip voxels entirely.

## Operating characteristics

*   **Time Complexity:** $O(N)$, where $N$ is the number of voxels intersected by the ray. The algorithm performs one iteration per voxel visited [S8, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary space per ray, requiring only a few scalar variables for state (`t_max`, `t_delta`, `coord`, `step`) [S5, unofficial].
*   **Measured Performance:** On modern GPUs, the algorithm is highly parallelizable. Implementations using CUDA/Numba have demonstrated efficient processing of tens of thousands of rays simultaneously for LiDAR and volumetric analysis [S3, unofficial]. The core loop involves only two comparisons and one addition per step, making it extremely fast on SIMD architectures [S18, unofficial].
*   **Strengths:** Guaranteed visitation of all intersected voxels; no division in the main loop; simple integer/floating-point arithmetic; easy to implement [S5, unofficial].
*   **Limitations:** Inefficient for sparse grids where most voxels are empty (compared to hierarchical methods like [Hierarchical DDA with Super-brick Skipping](5197-hierarchical-dda-with-super-brick-skipping.md)); performance degrades with very long rays in large grids if not bounded [S1, unofficial].
*   **When to Use:** Uniform voxel grids, dense volumes, or when simplicity and correctness of traversal order are prioritized over sparse optimization [S1, unofficial].
*   **When Not to Use:** Sparse voxel octrees (use [OpenVDB DDA](2149-openvdb-dda.md) or hierarchical variants); scenes requiring massive skipping of empty space [S1, unofficial].

## Background

The algorithm was introduced by Jan Amanatides and Andrew Woo in their 1987 paper "A Fast Voxel Traversal Algorithm for Ray Tracing" [S5, unofficial]. It is an extension of the 2D DDA/Bresenham line drawing algorithm to 3D space [S21, unofficial]. It is widely used in voxel rendering, shadow casting, and LiDAR processing [S3, unofficial][S17, unofficial].
