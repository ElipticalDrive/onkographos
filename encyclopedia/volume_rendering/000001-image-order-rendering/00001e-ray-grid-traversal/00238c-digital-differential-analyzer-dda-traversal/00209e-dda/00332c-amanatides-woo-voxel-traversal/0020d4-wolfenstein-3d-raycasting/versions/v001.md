# Wolfenstein 3D Raycasting

Also called: 2.5D Raycasting, DDA Grid-Traversal Ray Cast, DDA Ray Casting, Digital Differential Analyzer, Digital Differential Analyzer Ray Casting, Lodev-style DDA, Raycasting Engine, Raycasting with Fisheye Correction, Wolfenstein 3D technique, Wolfenstein-style rendering

## Overview
Wolfenstein 3D Raycasting is a rendering technique for first-person corridors on hardware without GPUs or z-buffers, where the world is a flat 2D grid, the camera is confined to the grid plane, and one ray is cast per screen column to reconstruct a textured 3D scene [S1, unofficial]. It sets itself apart from general voxel traversal methods by operating on a strictly 2D grid map with a fixed-height camera, using the perpendicular distance to the camera plane to correct fisheye distortion and determine wall height, rather than computing full 3D intersections [S1, unofficial][S3, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 2D grid map (e.g., `Uint8Array` or `number[][]`), player state (position `pos`, direction vector `dir`, camera plane vector `plane`), screen dimensions (`FB_W`, `FB_H`), and field of view (defined by `plane` length).
- **Output:** A framebuffer image with vertical wall strips and billboard sprites.

**Data Structures:**
- **Map:** A 1D or 2D array representing the grid. Values: `0` (empty), `1-4` (wall types), `5` (sliding door) [S1, unofficial][S5, unofficial].
- **Player:** Object with `x`, `y` (position), `dirX`, `dirY` (unit direction vector), `planeX`, `planeY` (camera plane vector perpendicular to `dir`) [S1, unofficial][S3, unofficial].
- **Textures:** Procedurally generated or loaded into a `Uint32Array` (e.g., 64x64 pixels) [S1, unofficial].
- **Z-Buffer:** A 1D array of size `FB_W` storing the perpendicular distance to the nearest wall for each screen column, used for sprite occlusion [S1, unofficial].

**Parameters:**
- **FOV:** Determined by the length of the plane vector relative to the direction vector. A ratio of `|plane|/|dir| = 0.66` yields a horizontal FOV of ~66.8 degrees [S1, unofficial].
- **Wall Height:** Real-world height of a wall tile, typically 1 unit [S2, unofficial].

**Steps:**

1. **Initialize Camera Vectors:**
   For each screen column `x` from `0` to `FB_W - 1`:
   - Calculate `cameraX = 2 * x / FB_W - 1` (ranges from -1 to 1) [S1, unofficial].
   - Calculate ray direction:
     $$ \vec{r} = \vec{d} + cameraX \cdot \vec{p} $$
     $$ rayDirX = dirX + planeX \cdot cameraX $$
     $$ rayDirY = dirY + planeY \cdot cameraX $$
     [S1, unofficial][S3, unofficial]

2. **DDA Grid Traversal:**
   - Initialize current grid cell: `mapX = floor(posX)`, `mapY = floor(posY)` [S3, unofficial].
   - Calculate step distances:
     $$ \Delta_x = \left| \frac{1}{rayDirX} \right|, \quad \Delta_y = \left| \frac{1}{rayDirY} \right| $$
     Handle `rayDirX == 0` or `rayDirY == 0` by setting $\Delta$ to a large value (e.g., `1e30`) [S2, unofficial][S3, unofficial].
   - Determine step directions and initial side distances:
     - If `rayDirX < 0`: `stepX = -1`, `sideDistX = (posX - mapX) * \Delta_x`
     - Else: `stepX = 1`, `sideDistX = (mapX + 1 - posX) * \Delta_x`
     - If `rayDirY < 0`: `stepY = -1`, `sideDistY = (posY - mapY) * \Delta_y`
     - Else: `stepY = 1`, `sideDistY = (mapY + 1 - posY) * \Delta_y`
     [S1, unofficial][S3, unofficial]
   - Loop until a wall is hit:
     - If `sideDistX < sideDistY`:
       - `sideDistX += \Delta_x`
       - `mapX += stepX`
       - `side = 0` (hit vertical grid line)
     - Else:
       - `sideDistY += \Delta_y`
       - `mapY += stepY`
       - `side = 1` (hit horizontal grid line)
     - Check if `map[mapY][mapX]` is a wall (non-zero). If so, break [S1, unofficial][S3, unofficial].
     - *Edge Case (Sliding Doors):* If the hit tile is a door (`5`), check if the ray passes through the open gap. If the ray exits the cell before reaching the midline or hits the closed part, continue traversal [S1, unofficial].

3. **Calculate Perpendicular Distance:**
   - Compute the fisheye-corrected distance:
     $$ dist = side === 0 ? sideDistX - \Delta_x : sideDistY - \Delta_y $$
     This value represents the distance perpendicular to the camera plane, correcting for the bowing effect of raw ray length [S1, unofficial][S5, unofficial].

4. **Render Wall Strip:**
   - Calculate line height:
     $$ lineHeight = \frac{FB_H}{dist} $$
     [S1, unofficial]
   - Calculate draw range:
     $$ drawStart = \max(0, \lfloor (FB_H - lineHeight) / 2 \rfloor) $$
     $$ drawEnd = \min(FB_H - 1, \lfloor (FB_H + lineHeight) / 2 \rfloor) $$
     [S1, unofficial]
   - Calculate texture coordinate `wallX`:
     - If `side == 0`: `wallX = posY + dist * rayDirY - floor(posY + dist * rayDirY)`
     - Else: `wallX = posX + dist * rayDirX - floor(posX + dist * rayDirX)`
     [S1, unofficial][S5, unofficial]
   - Mirror texture X if necessary to prevent backward textures:
     - If `(side == 0 && rayDirX > 0) || (side == 1 && rayDirY < 0)`: `wallX = 1 - wallX` [S1, unofficial].
   - Draw vertical line from `drawStart` to `drawEnd` using `wallX` for texture sampling. Shade based on `side` for depth cues [S1, unofficial][S2, unofficial].
   - Store `dist` in `zbuffer[x]` for sprite occlusion [S1, unofficial].

5. **Render Sprites (Billboards):**
   - Sort sprites by squared distance to player (far to near) [S1, unofficial].
   - For each sprite:
     - Transform sprite position `(sx, sy)` to camera space:
       $$ invDet = \frac{1}{planeX \cdot dirY - dirX \cdot planeY} $$
       $$ transformX = invDet \cdot (dirY \cdot (sx - posX) - dirX \cdot (sy - posY)) $$
       $$ transformY = invDet \cdot (-planeY \cdot (sx - posX) + planeX \cdot (sy - posY)) $$
       [S1, unofficial]
     - If `transformY <= 0.05`, skip (behind camera) [S1, unofficial].
     - Calculate screen X: `screenX = floor((FB_W / 2) * (1 + transformX / transformY))` [S1, unofficial].
     - Calculate sprite size: `size = floor(FB_H / transformY)` [S1, unofficial].
     - For each column `x` in sprite range:
       - If `transformY >= zbuffer[x]`, skip (occluded by wall) [S1, unofficial].
       - Sample texture and draw, handling transparency [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(W \cdot N)$ where $W$ is screen width and $N$ is the average number of grid cells traversed per ray. DDA ensures $N$ is proportional to the distance to the wall, not the step size.
- **Memory Complexity:** $O(W + H_{map} \cdot W_{map})$ for the z-buffer and map storage.
- **Performance:** Highly efficient on CPU-only hardware. The original Wolfenstein 3D ran on 286/386 processors. Optimizations like drawing every 2nd column can double FPS with negligible visual loss on low-res displays [S5, unofficial].
- **Strengths:** Simple implementation, low memory footprint, no need for complex 3D math or polygon rasterization.
- **Limitations:** Cannot render non-rectangular geometry, slopes, or true 3D objects. Limited to a 2D grid map. Fisheye distortion must be corrected.
- **When to use:** Retro-style FPS games, educational demonstrations of raycasting, hardware with limited resources.
- **When not to use:** Modern 3D games requiring complex geometry, lighting, or shadows.

## Background
Wolfenstein 3D (id Software, 1992) was one of the first first-person shooters, rendered on 286/386-class hardware without GPUs or z-buffers [S1, unofficial]. The technique was popularized by this game and later refined by the community (e.g., Lodev's tutorial) [S1, unofficial]. It is a specific application of the Digital Differential Analyzer (DDA) algorithm for grid traversal [S1, unofficial][S3, unofficial].
