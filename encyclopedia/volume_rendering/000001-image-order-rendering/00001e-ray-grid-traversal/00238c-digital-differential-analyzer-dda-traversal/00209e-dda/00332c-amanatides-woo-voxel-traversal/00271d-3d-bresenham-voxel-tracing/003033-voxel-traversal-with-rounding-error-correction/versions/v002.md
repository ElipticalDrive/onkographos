# Voxel Traversal with Rounding Error Correction

Also called: Rounding Error Corrected Voxel Traversal

## Overview
Voxel Traversal with Rounding Error Correction is a method for stepping a ray through a voxel grid that explicitly compensates for floating-point precision errors in position calculations [S1, unofficial]. It builds on [3D Bresenham Voxel Tracing](3949-3d-bresenham-voxel-tracing.md) by adding a correction step to ensure the ray enters the correct adjacent voxel, preventing misses or incorrect entries caused by rounding artifacts [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Current voxel integer position `intPosition3` (3 integers), current float position `floatPosition3` (3 floats), ray direction signs `pstvDirComps` and `ngtvDirComps` (3 booleans indicating positive/negative direction components), rounding status flags `rightRnddComps` (3 booleans indicating correctly rounded components), and `sideMax` (3 floats specifying the exit side of the current voxel, corresponding to `tMax`) [S1, unofficial].
- Output: Updated `intPosition3` reflecting the next voxel index [S1, unofficial].

**Data Structures:**
- `intPosition3`: A 3-component integer vector representing the current voxel coordinates $(i, j, k)$ [S1, unofficial].
- `floatPosition3`: A 3-component float vector representing the ray's position in voxel space [S1, unofficial].
- `pstvDirComps`: A 3-component boolean vector where $P_x=1$ if $d_x > 0$, else $0$ [S1, unofficial].
- `ngtvDirComps`: A 3-component boolean vector where $N_x=1$ if $d_x < 0$, else $0$ [S1, unofficial].
- `rightRnddComps`: A 3-component boolean vector where $R_x=1$ if the component of `floatPosition3` was correctly rounded relative to the expected voxel boundary, else $0$ [S1, unofficial].
- `wrongRnddComps`: The logical NOT of `rightRnddComps` ($W_x = \neg R_x$) [S1, unofficial].
- `sideMax`: A 3-component float vector indicating the side of the current voxel where the ray exits. The sign indicates the exit direction (e.g., $(1, 0, 0)$ means exit on the right side, $+x$) [S1, unofficial].

**Steps:**
1. Calculate Correction Vector Components: Determine which components require a shift by combining direction signs and rounding error flags [S1, unofficial]. For positive direction components, a shift is needed if rounding was wrong: $C_x = P_x \land W_x$ [S1, unofficial]. For negative direction components, a shift is needed if rounding was correct, as this represents the same stepping problem: $C_x = N_x \land R_x$ [S1, unofficial]. Combine these using logical OR: $C = (P \land W) \lor (N \land R)$ [S1, unofficial].
2. Determine Shift Direction and Magnitude: The sign of the shift is determined by `sideMax` [S1, unofficial]. If `sideMax` indicates an exit on the $+x$ side, the shift in $x$ is positive, moving to the higher index voxel [S1, unofficial]. The `sideMax` vector's sign corresponds to the direction of travel for the exiting component [S1, unofficial].
3. Apply Shift: Update `intPosition3` by adding the correction vector scaled by the shift direction [S1, unofficial]. For each component $c \in \{x, y, z\}$, if $C_c$ is true, increment or decrement `intPosition3[c]` by $1$ based on the sign of `sideMax[c]` [S1, unofficial].

**Formula:**
The correction vector $C$ is calculated as:
$$ C = (pstvDirComps \land wrongRnddComps) \lor (ngtvDirComps \land rightRnddComps) $$
Where:
- $pstvDirComps$: Boolean vector indicating positive direction components [S1, unofficial].
- $ngtvDirComps$: Boolean vector indicating negative direction components [S1, unofficial].
- $wrongRnddComps$: Boolean vector indicating components with rounding errors [S1, unofficial].
- $rightRnddComps$: Boolean vector indicating correctly rounded components [S1, unofficial].
- $\land$: Logical AND [S1, unofficial].
- $\lor$: Logical OR [S1, unofficial].

The update to `intPosition3` is:
$$ intPosition3_{new} = intPosition3_{old} + \text{sign}(sideMax) \cdot C $$
Where $\text{sign}(sideMax)$ returns $+1$ or $-1$ for each component based on the sign of `sideMax` [S1, unofficial].

**Parameters:**
- `sideMax`: A vector specifying the side of the current voxel where the next voxel is adjacent. Its sign specifies the exit point side (e.g., $(1, 0, 0)$ means exit on the right side) [S1, unofficial]. Typical values are not given in the sources.

**Edge Cases and Pitfalls:**
- Rounding errors in float position calculations can cause the ray to miss the correct voxel or enter the wrong one [S1, unofficial].
- The case where the direction is negative and no rounding error occurred ($ngtvDirComps \land rightRnddComps$) presents the same stepping problem as described in reference [6] [S1, unofficial].

**Pseudocode:**
```python
def correct_voxel_traversal(int_position, side_max, pstv_dir, ngtv_dir, right_rndd):
    """
    Corrects voxel position for rounding errors.
    
    Args:
        int_position: List[int, int, int] - Current voxel indices [i, j, k]
        side_max: List[float, float, float] - Exit side indicators (signs)
        pstv_dir: List[bool, bool, bool] - True if direction component is positive
        ngtv_dir: List[bool, bool, bool] - True if direction component is negative
        right_rndd: List[bool, bool, bool] - True if rounding was correct
        
    Returns:
        List[int, int, int] - Corrected voxel indices
    """
    # Calculate wrong rounding flags
    wrong_rndd = [not r for r in right_rndd]
    
    # Calculate correction vector components
    # C = (pstv_dir AND wrong_rndd) OR (ngtv_dir AND right_rndd)
    correction = []
    for c in range(3):
        term1 = pstv_dir[c] and wrong_rndd[c]
        term2 = ngtv_dir[c] and right_rndd[c]
        correction.append(term1 or term2)
        
    # Apply correction
    new_position = list(int_position)
    for c in range(3):
        if correction[c]:
            # Determine shift direction from side_max sign
            # side_max sign indicates the exit side, which aligns with the travel direction
            shift = 1 if side_max[c] > 0 else -1
            new_position[c] += shift
            
    return new_position
```

The base method that this correction augments. Choose for general ray-voxel intersection.

## Operating characteristics
- Time Complexity: $O(1)$ per voxel step, as the correction involves a constant number of logical operations and additions [S1, unofficial].
- Memory Complexity: $O(1)$ additional memory for flags and temporary vectors [S1, unofficial].
- Strengths: Corrects for floating-point inaccuracies that can lead to incorrect voxel stepping, ensuring robustness in ray traversal [S1, unofficial].
- Limitations: Requires tracking rounding status for each component, adding complexity to the traversal loop [S1, unofficial].
- When to use: When using floating-point position calculations in voxel traversal and precision errors are observed or suspected [S1, unofficial].

## Background
The method is described in a thesis on raycasting-based voxel rendering [S1, unofficial]. It addresses issues found in standard Bresenham-based traversal when implemented with floating-point arithmetic [S1, unofficial].
