# Multi-level DDA with Adaptive Mip Selection

Also called: DDA-based volume sampling routine, Multi-level traversal scheme

## Overview
This method is a ray traversal and sampling algorithm for volume rendering that combines Digital Differential Analyzer (DDA) stepping with adaptive mip-level selection to optimize the trade-off between step size and sampling accuracy. It solves the problem of inefficient traversal in sparse or heterogeneous volumes by using a majorant texture at multiple resolutions to skip empty space, while dynamically adjusting the granularity of the search to locate collision points precisely. It sets itself apart from standard DDA approaches by avoiding execution divergence on GPUs through a branchless, iterative mip-level adjustment heuristic, and from pure delta tracking by providing deterministic spatial bounds for step sizes [S1, book].

## How it works
The algorithm performs a stochastic distance sampling loop using a majorant density texture. It maintains a target optical thickness (`tauToGo`) and steps through the volume using a DDA that intersects against "dilated" brick boundaries. The core innovation is the dynamic selection of the mip level for the majorant lookup at every step, allowing the algorithm to start coarse (large steps) and refine (smaller steps) based on proximity to a potential collision, without using conditional branches that would cause divergence on SIMT hardware.

### Inputs and Outputs
*   **Inputs:**
    *   `rayOrigin`: The starting position of the ray.
    *   `rayDir`: The direction of the ray (assumed normalized or handled via inverse direction).
    *   `majorantTexture`: A multi-mipmap texture storing the maximum density (majorant) for bricks. The source uses 4 mip levels (0 to 3).
    *   `densityTexture`: The high-resolution density texture used for final sampling.
    *   `random()`: A function returning a uniform random number in $[0, 1)$.
*   **Outputs:**
    *   The algorithm returns the result of the collision handling (e.g., color contribution, new path vertex) or continues the path if a null collision occurs.

### Data Structures
*   **Majorant Texture:** A 3D texture array or volume texture organized into mip levels. The source specifies a brick size of $8 \times 2^{\text{mip}}$ voxels. The texture stores the majorant density value for each brick.
*   **DDA State:**
    *   `t`: Current distance along the ray.
    *   `tauToGo`: Remaining optical thickness to accumulate before a collision.
    *   `mip`: Current floating-point mip level index (range $[0.0, 3.0]$).

### Formulas and Parameters
*   **Target Optical Thickness:**
    $$ \tau_{\text{target}} = -\ln(1 - r) $$
    where $r$ is a uniform random number. This defines the distance to the next interaction in optical space.
*   **Brick Dimension:**
    $$ \text{dim} = 8 \ll \text{mip} $$
    where $\text{mip}$ is the integer part of the current mip level. The base brick size is 8 voxels.
*   **DDA Step Distance (`nextt`):**
    The distance to the next brick boundary intersection, calculated using dilated boundaries.
    $$ \text{ofs} = \mathbf{ri} \odot \left( \left( \mathbf{ri} \ge 0 \right) ? (\text{dim} + 0.5) : (-0.5) - \mathbf{ro} \right) $$
    $$ \mathbf{tmax} = \lfloor \mathbf{pos} \odot (1.0 / \text{dim}) \rfloor \odot \text{dim} \odot \mathbf{ri} + \text{ofs} $$
    $$ \text{nextt} = \min(\mathbf{tmax}_x, \min(\mathbf{tmax}_y, \mathbf{tmax}_z)) $$
    Where:
    *   $\mathbf{ri} = 1.0 / \mathbf{rayDir}$ (inverse ray direction).
    *   $\mathbf{ro}$ is the ray origin offset relative to the brick grid (often 0 or derived from `rayOrigin`).
    *   $\mathbf{pos}$ is the current ray position.
    *   $\odot$ denotes component-wise multiplication.
    *   The dilation of $0.5$ voxels ensures the ray oversteps into the brick, avoiding numerical instability at exact boundaries [S1, book].
*   **Optical Thickness Traversed:**
    $$ \Delta \tau = \rho_{\text{majorant}} \cdot \Delta t $$
    where $\rho_{\text{majorant}}$ is the sampled majorant density and $\Delta t = \text{nextt} - t$.

### Parameters
*   **Initial Mip Level:** 3.0 (coarsest resolution, largest steps).
*   **Mip Increment:** 0.33 per iteration.
*   **Mip Decrement on Collision:** 2.0.
*   **Mip Bounds:** Clamped to $[0.0, 3.0]$.
*   **Brick Dilation:** 0.5 voxels.

### Pseudocode
The following Python-like pseudocode implements the core loop described in the source. It assumes helper functions `lookupMajorant`, `lookup`, and `random` are available.

```python
def multi_level_dda_sampling(ray_origin, ray_dir, majorant_texture, density_texture):
    """
    Performs volume sampling using Multi-level DDA with Adaptive Mip Selection.
    
    Args:
        ray_origin (float3): Start of the ray.
        ray_dir (float3): Direction of the ray.
        majorant_texture: Multi-mip texture for majorant density.
        density_texture: High-res texture for actual density.
        
    Returns:
        The result of the collision handling (e.g., color, throughput update).
    """
    # 1. Initialize target optical thickness and mip level
    r = random()
    tau_to_go = -math.log(1.0 - r)
    mip = 3.0
    
    # Precompute inverse ray direction
    inv_ray_dir = 1.0 / ray_dir
    
    # Current distance along ray
    t = 0.0
    
    while True:
        # 2. Calculate current position
        pos = ray_origin + t * ray_dir
        
        # 3. Lookup majorant density at current mip level
        # Round mip to nearest integer for texture lookup
        mip_int = round(mip)
        majorant = lookup_majorant(pos, mip_int, majorant_texture)
        
        # 4. Compute next DDA step distance using dilated boundaries
        next_t = step_dda_dilated(ray_origin, inv_ray_dir, pos, mip_int)
        
        # 5. Adaptive Mip Selection: Increment mip level
        # Move towards finer resolution gradually
        mip = min(3.0, mip + 0.33)
        
        # 6. Calculate step metrics
        dt = next_t - t
        dtau = majorant * dt
        
        # Update current distance
        t = next_t
        
        # 7. Check if target optical thickness is exceeded
        tau_to_go -= dtau
        
        if tau_to_go > 0:
            # No collision yet, continue to next brick
            continue
            
        # Collision detected (tau_to_go <= 0)
        
        # 8. Refine Mip Level: Decrement to find exact collision point
        mip = max(0.0, mip - 2.0)
        
        # 9. Backstep to exact collision point using linear interpolation
        # The collision occurred within the last step dt
        t += dt * (tau_to_go / dtau)
        
        # 10. Lookup actual density at the collision point
        collision_pos = ray_origin + t * ray_dir
        density = lookup_density(collision_pos, density_texture)
        
        # 11. Russian Roulette: Real vs. Null Collision
        # Probability of real collision is density / majorant
        if random() * majorant < density:
            # Real collision
            # Handle scattering, shading, etc.
            return handle_real_collision(collision_pos, density, ray_dir)
        else:
            # Null collision: The ray passed through without interacting
            # Restart the traversal with a new target
            r = random()
            tau_to_go = -math.log(1.0 - r)
            # Continue loop to search for next interaction

def step_dda_dilated(ray_origin, inv_ray_dir, pos, mip):
    """
    Computes the distance to the next brick boundary intersection.
    Uses dilated boundaries (0.5 voxel dilation) for numerical stability.
    """
    # Brick dimension: 8 * 2^mip
    dim = 8 << mip
    
    # Calculate offset for dilation
    # If ray component is positive, dilate by +0.5; if negative, by -0.5
    # This effectively expands the brick by 0.5 voxels in the direction of travel
    dilated_ro = ray_origin # Assuming ray_origin is the reference point for dilation calculation
    
    # Component-wise calculation for ofs
    # ofs = ri * ( ((ri >= 0) ? dim + 0.5 : -0.5) - ro )
    # Note: In the source, 'ro' in the formula refers to the ray origin component relative to the grid
    # or an offset. Here we assume standard DDA logic where we intersect against grid lines.
    
    # Reconstructing the specific HLSL logic from Listing 43-2:
    # const float3 ofs = ri * (((ri >= 0.f) ? dim + 0.5f : -0.5f ) - ro);
    # Here 'ro' is likely the ray origin's coordinate, but in DDA, we usually intersect
    # against the grid defined by 'pos'. The source formula uses 'ro' (ray origin) 
    # and 'pos' (current position). Let's follow the source exactly.
    
    # Component-wise operations
    x_val = (dim + 0.5) if inv_ray_dir.x >= 0 else -0.5
    y_val = (dim + 0.5) if inv_ray_dir.y >= 0 else -0.5
    z_val = (dim + 0.5) if inv_ray_dir.z >= 0 else -0.5
    
    # ofs calculation
    ofs_x = inv_ray_dir.x * (x_val - ray_origin.x)
    ofs_y = inv_ray_dir.y * (y_val - ray_origin.y)
    ofs_z = inv_ray_dir.z * (z_val - ray_origin.z)
    
    # tmax calculation
    # floor(pos * (1.0 / dim)) * dim * ri + ofs
    tmax_x = math.floor(pos.x * (1.0 / dim)) * dim * inv_ray_dir.x + ofs_x
    tmax_y = math.floor(pos.y * (1.0 / dim)) * dim * inv_ray_dir.y + ofs_y
    tmax_z = math.floor(pos.z * (1.0 / dim)) * dim * inv_ray_dir.z + ofs_z
    
    # Return the minimum positive t (assuming ray direction is consistent)
    # The source returns min(tmax.x, min(tmax.y, tmax.z))
    return min(tmax_x, min(tmax_y, tmax_z))
```

### Edge Cases and Pitfalls
*   **Numerical Instability at Boundaries:** Standard DDA can fail or produce jitter when a ray intersection falls exactly on a brick boundary. The algorithm mitigates this by dilating brick boundaries by 0.5 voxels in the direction of travel. This ensures the ray always "oversteps" into the brick, avoiding exact boundary hits [S1, book].
*   **Execution Divergence:** Implementing separate loops for each mip level causes significant divergence on GPUs (SIMT). The adaptive mip selection heuristic (incrementing/decrementing a float variable) allows all threads to execute the same loop body, minimizing divergence [S1, book].
*   **Null Collisions:** If a collision is detected in the majorant but not in the actual density (null collision), the traversal must restart with a new random target. This can lead to inefficiency if the majorant is a poor approximation of the density. The multi-level approach helps by allowing finer steps when close to a collision, improving the majorant's accuracy [S1, book].
*   **Mip Level Bounds:** The mip level is clamped between 0.0 and 3.0. Starting at 3.0 ensures large initial steps. Decrementing by 2.0 on collision ensures a significant refinement to locate the exact point.

## Operating characteristics
*   **Time Complexity:** The number of steps is reduced compared to a regular DDA with global majorants. The source reports an average of 3 steps per path on the Moana cloud scene, compared to 5 steps for a regular DDA [S1, book]. The adaptive mip selection reduces texture lookups in empty space regions [S1, book].
*   **Memory Complexity:** The method requires storing a multi-mipmap majorant texture. The source uses 4 mip levels. The memory usage for the Moana cloud scene was 86.7 MB (using BC4 compression) [S1, book].
*   **Measured Performance:** On an NVIDIA RTX 3090, rendering one sample per pixel at 1920x1080 with 3 bounces, the method achieved 3.9 ms for the Moana cloud scene [S1, book].
*   **Strengths:**
    *   Reduces the number of volume lookups and DDA steps, especially in empty space.
    *   Branchless mip selection avoids GPU execution divergence.
    *   Dilated boundaries improve numerical stability.
*   **Limitations:**
    *   Requires a multi-mipmap majorant texture, increasing memory usage.
    *   Performance depends on the quality of the majorant; a poor majorant leads to more null collisions and restarts.
    *   The heuristic for mip selection (0.33 increment, 2.0 decrement) is empirical and may not be optimal for all scenes.

## Background
The method was introduced in the book *Efficient Unbiased Volume Path Tracing on the GPU* [S1, book]. It builds upon the concept of delta tracking and ratio tracking for volume rendering, adapting them to a DDA-based traversal framework. The key contribution is the integration of adaptive mip-level selection into the DDA loop to balance step size and accuracy without branching. The technique was evaluated against a baseline path tracer using NanoVDB and delta tracking, demonstrating significant speedups (up to 2.58x) and memory savings (using BC4 compression) on complex cloud scenes [S1, book].
