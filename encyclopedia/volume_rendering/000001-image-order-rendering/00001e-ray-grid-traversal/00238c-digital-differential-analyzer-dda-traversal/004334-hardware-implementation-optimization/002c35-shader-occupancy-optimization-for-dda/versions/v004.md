# Shader Occupancy Optimization for DDA

Also called: DDA Shader Register Optimization, Optimizing 2-Level DDA Shader, Shader Occupancy Optimization

## Overview
This method optimizes the Digital Differential Analyzer (DDA) ray traversal shader to increase GPU occupancy by reducing register allocation and minimizing state carried across loops [S1, unofficial]. It addresses the performance degradation caused by high register pressure in complex traversal logic, which limits the number of concurrent warps and leads to memory stalls [S1, unofficial]. It sets itself apart from general execution configuration tuning by focusing on the internal variable management and instruction deduplication within the shader code itself, rather than block/grid sizing [S2, unofficial].

## How it works
The method modifies the 2-level DDA shader implementation to reduce the number of live variables and eliminate redundant calculations.

**Inputs and Outputs:**
- Input: Unoptimized DDA shader source code (typically containing nested loops for brick and voxel traversal).
- Output: Optimized shader source code with reduced register footprint.

**Data Structures:**
- `local_cell`: A single `int3` variable replacing separate `min_cell` and `max_cell` variables.
- `VX_BRICK_EXT`: A constant defining the brick dimensions (e.g., 8 or 16).
- `voxel_mask`: An array or buffer storing voxel occupancy bits.

**Steps:**
1.  **Variable Consolidation:** Replace the pair of variables `min_cell` and `max_cell` with a single `local_cell` variable. This variable tracks the current position within the brick.
2.  **Bounds Checking:** Implement bounds checking using the single `local_cell` variable. The check verifies if any component of `local_cell` exceeds the brick extent.
    -   Formula: `if (any((uint3)local_cell >= (uint)VX_BRICK_EXT))`
    -   This replaces the previous logic: `if (any(cell < min_cell) || any(cell > max_cell))` [S1, unofficial].
3.  **Deduplication:** Identify and remove duplicate calculations of `tdelta` (time delta for ray traversal) and other unnecessary intermediate states carried across loop iterations [S1, unofficial].
4.  **State Minimization:** Ensure that fewer variables are carried over the loops. This reduces the register pressure on the GPU execution units [S1, unofficial].

**Pseudocode:**
```python
# Optimized 2-level DDA bounds check
# local_cell is an int3 representing the current voxel index within the brick
# VX_BRICK_EXT is the constant dimension of the brick (e.g., 8)

def check_brick_bounds(local_cell: int3, VX_BRICK_EXT: int) -> bool:
    """
    Returns True if local_cell is out of bounds.
    Uses uint casting to handle signed/unsigned comparison correctly.
    """
    # Cast to uint to ensure unsigned comparison for >= check
    local_cell_uint = uint3(local_cell.x, local_cell.y, local_cell.z)
    brick_ext_uint = uint(VX_BRICK_EXT)
    
    # Check if any component is >= brick extent
    if any(local_cell_uint >= brick_ext_uint):
        return True
    return False

# Example usage in traversal loop
def traverse_brick(local_cell: int3, voxel_mask, brick_min: int3, voxels):
    if check_brick_bounds(local_cell, 8): # Assuming 8x8x8 brick
        return 0.0 # Out of bounds, return sentinel or terminate
    
    # Calculate linear index
    # Note: VX_BRICK_EXT is assumed to be 8 for this example
    brick_size = 8
    voxel_idx = local_cell.x + local_cell.y * brick_size + local_cell.z * brick_size * brick_size
    
    # Check voxel mask
    word = voxel_mask[voxel_idx >> 5]
    bit = 1 << (voxel_idx & 31)
    
    if (word & bit) != 0:
        # Load voxel value
        # brick_min is the origin of the brick in world space
        # local_cell is the offset within the brick
        return voxels.Load(int4(brick_min + local_cell, 0)).r
    else:
        return 0.0
```

**Parameters:**
- `VX_BRICK_EXT`: Typically 8 or 16, depending on the brick size.
- Register Allocation Target: Reduce from ~92 to ~72 registers per thread [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Ensure that the cast from `int3` to `uint3` is handled correctly to avoid signed/unsigned comparison errors [S1, unofficial].
- **Boundary Conditions:** The check `any((uint3)local_cell >= (uint)VX_BRICK_EXT)` must correctly handle the upper bound of the brick. If `local_cell` equals `VX_BRICK_EXT`, it is out of bounds.
- **Register Pressure:** Failure to deduplicate `tdelta` calculations can negate the benefits of variable consolidation [S1, unofficial].

## Subtopics

### [CUDA Execution Configuration Optimization](15104-cuda-execution-configuration-optimization.md)
This variant focuses on selecting block size, grid size, and shared memory size to maximize GPU occupancy. Occupancy is defined as the number of warps being executed divided by the number of warps allowed per multiprocessor. Benchmarked block sizes include 4x4, 4x8, 4x16, 4x32, 8x8, 8x16, 8x32, and 16x16. On an NVIDIA GTX280, block sizes of 4x16, 4x32, 8x8, 8x16, and 8x32 yielded higher performance (e.g., 31 FPS on Engine dataset) compared to 16x16 (21 FPS). This approach complements shader-level optimizations by ensuring the hardware resources are utilized efficiently.

## Operating characteristics
**Time and Memory Complexity:**
- The optimization reduces register allocation, which does not change the asymptotic time complexity of the DDA traversal but reduces the constant factor by improving cache utilization and reducing memory stalls [S1, unofficial].
- Memory complexity is reduced by fewer live variables in registers [S1, unofficial].

**Measured Performance:**
- On a Macbook Air (M2) at 3840x1600 resolution:
    - **monu2-1 (128³):** FPS increased from 143.20 to 144.00 (+0.56%); Walltime decreased from 6.58 ms to 5.37 ms (-18.32%) [S1, unofficial].
    - **sponza-256-1 (256³):** FPS increased from 59.78 to 72.83 (+21.83%); Walltime decreased from 28.39 ms to 22.51 ms (-20.71%) [S1, unofficial].
    - **sponza-256-2 (256³):** FPS increased from 109.53 to 143.94 (+31.42%); Walltime decreased from 13.40 ms to 7.32 ms (-45.33%) [S1, unofficial].
- Occupancy increased from 35.43% to 42.37% [S1, unofficial].
- Register allocation decreased from 92 to 72 [S1, unofficial].

**Scaling:**
- The benefits are more pronounced in complex scenes with higher voxel density and longer traversal paths (e.g., sponza-256-2) [S1, unofficial].
- Simpler scenes (monu2-1) show modest improvements [S1, unofficial].

**Strengths and Limitations:**
- **Strengths:** Significant reduction in walltime for complex scenes; improved occupancy leads to better hardware utilization [S1, unofficial].
- **Limitations:** The optimization is specific to the 2-level DDA shader structure; it may not apply directly to other traversal algorithms [S1, unofficial].
- **When to Use:** When the DDA shader is the bottleneck and register allocation is high [S1, unofficial].
- **When Not to Use:** When the bottleneck is memory bandwidth or other parts of the rendering pipeline [S1, unofficial].

## Background
The method originates from development logs of a voxel raytracer, specifically addressing performance issues in the 2-level DDA shader [S1, unofficial]. The low occupancy (35.43%) and high register allocation (92) in the unoptimized shader were identified as causes for memory stalls, despite high ALU usage [S1, unofficial]. The optimization was implemented through a series of commits that consolidated variables and deduplicated calculations [S1, unofficial]. The concept of occupancy is further supported by CUDA execution configuration optimization principles, which emphasize the importance of maximizing the number of concurrent warps per multiprocessor [S2, unofficial].
