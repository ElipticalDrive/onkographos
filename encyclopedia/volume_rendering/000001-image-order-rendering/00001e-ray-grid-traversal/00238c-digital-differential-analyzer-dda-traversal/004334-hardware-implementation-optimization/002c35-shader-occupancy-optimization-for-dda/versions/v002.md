# Shader Occupancy Optimization for DDA

Also called: DDA Shader Register Optimization, Optimizing 2-Level DDA Shader, Shader Occupancy Optimization

## Overview
This method increases GPU shader occupancy for Digital Differential Analyzer (DDA) volume rendering by reducing register pressure and minimizing state carried across nested loops [S1, unofficial]. It addresses the performance degradation caused by low occupancy (e.g., 35.43%) and high register allocation (e.g., 92 registers) in unoptimized 2-level DDA shaders, which leads to memory stalls despite high ALU usage [S1, unofficial]. It sets itself apart from general occupancy tuning by specifically targeting the variable explosion inherent in the nested loop structure of 2-level DDA traversal [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An unoptimized 2-level DDA shader implementation containing separate `min_cell` and `max_cell` variables and redundant `tdelta` calculations.
*   **Output:** An optimized shader with reduced register allocation and higher occupancy.

**Data Structures:**
*   `local_cell`: A single `int3` variable replacing the pair `min_cell` and `max_cell`.
*   `VX_BRICK_EXT`: A constant defining the brick extent (dimension size).
*   `voxel_mask`: An array of `uint` values used for sparse voxel access.

**Numbered Steps:**
1.  **Variable Consolidation:** Replace the separate `min_cell` and `max_cell` variables with a single `local_cell` variable within the nested loops. This reduces the number of live variables carried across loop iterations.
2.  **Bounds Checking:** Implement bounds checking using the consolidated `local_cell` and a cast to `uint` to handle signed/unsigned comparison correctly. The check is: `if (any((uint3)local_cell >= (uint)VX_BRICK_EXT))`.
3.  **Deduplication:** Remove redundant `tdelta` calculations and unnecessary work identified in intermediate commits to further reduce register pressure.
4.  **Voxel Access:** Use the `local_cell` to compute the voxel index and access the voxel data.

**Pseudocode:**
```python
# Optimized 2-level DDA loop structure
def optimized_dda_loop():
    # Initialize local_cell instead of min_cell/max_cell
    local_cell = int3(0, 0, 0)
    
    # Nested loops for 2-level DDA
    for level1 in range(num_level1):
        for level2 in range(num_level2):
            # Bounds check using single variable and uint cast
            if any((uint3)local_cell >= (uint)VX_BRICK_EXT):
                break # Or handle out-of-bounds appropriately
            
            # Compute voxel index
            voxel_idx = local_cell.x + local_cell.y * VX_BRICK_EXT + local_cell.z * VX_BRICK_EXT * VX_BRICK_EXT
            
            # Access voxel mask
            word = voxel_mask[voxel_idx >> 5u]
            bit = 1u << (voxel_idx & 31u)
            
            if (word & bit) != 0u:
                # Load voxel data
                return voxels.Load(int4(brick_min + local_cell, 0)).r
            
            # Update local_cell (DDA step)
            local_cell = update_local_cell(local_cell, tdelta) # [G] update_local_cell is a placeholder for the specific DDA step logic
    
    return 0 # Default return value
```

**Parameters:**
*   `VX_BRICK_EXT`: Brick extent size. Typical value: Not given in the sources.
*   `num_level1`, `num_level2`: Loop counts for the 2-level DDA. Typical value: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Signed/Unsigned Comparison:** Using `uint` cast for bounds checking is critical to avoid incorrect comparisons with negative indices.
*   **Register Pressure:** High register allocation (>90) can lead to low occupancy and memory stalls.
*   **Redundant Calculations:** Unnecessary work in loops increases register usage and reduces performance.

## Subtopics

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Reduced register usage leads to lower register pressure.
*   **Measured Performance:**
    *   **monu2-1 (128³ resolution, 3840x1600, 144Hz monitor):** FPS increased from 143.20 to 144.00 (+0.56%); Walltime decreased from 6.58 ms to 5.37 ms (-18.32%) [S1, unofficial].
    *   **sponza-256-1:** FPS increased from 59.78 to 72.83 (+21.83%); Walltime decreased from 28.39 ms to 22.51 ms (-20.71%) [S1, unofficial].
    *   **sponza-256-2:** FPS increased from 109.53 to 143.94 (+31.42%); Walltime decreased from 13.40 ms to 7.32 ms (-45.33%) [S1, unofficial].
*   **Scaling:** Performance improvements vary by scene complexity and view. Nearby voxels in complex scenes (e.g., sponza-256-1) remain expensive to render [S1, unofficial].
*   **Strengths:** Significant reduction in register allocation (92 to 72) and increase in occupancy (35.43% to 42.37%) [S1, unofficial].
*   **Limitations:** Modest occupancy bump; performance gains are scene-dependent [S1, unofficial].
*   **When to Use:** When implementing 2-level DDA for volume rendering on GPUs, especially when register pressure is high.
*   **When Not to Use:** When register pressure is already low, or when using different traversal algorithms.

## Background
This optimization was developed as part of a voxel raytracer development log, specifically targeting the 2-level DDA shader [S1, unofficial]. The work was documented in commits between July and August 2026 [S1, unofficial]. The author noted that the DDA shader became larger due to nested loops, carrying more state in registers, which negatively impacted occupancy compared to the previous Naive DDA implementation (71.39% occupancy, 42 registers) [S1, unofficial]. The optimization was inspired by general principles of shader occupancy and register allocation [S1, unofficial].
