# Shader Occupancy Optimization for DDA

Also called: DDA Shader Register Optimization, Optimizing 2-Level DDA Shader, Shader Occupancy Optimization

## Overview
This method increases GPU shader occupancy for Digital Differential Analyzer (DDA) ray-grid traversal by reducing register pressure and minimizing state carried across nested loops [S1, unofficial]. It addresses the performance degradation caused by low occupancy (e.g., 35.43%) and high register allocation (e.g., 92 registers) in unoptimized 2-level DDA shaders, which leads to memory stalls despite high ALU usage [S1, unofficial]. It specifically targets the register bloat caused by carrying separate `min_cell` and `max_cell` variables across nested loops [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An unoptimized 2-level DDA shader implementation containing separate `min_cell` and `max_cell` variables and redundant `tdelta` calculations [S1, unofficial].
*   **Output:** An optimized shader with reduced register allocation and higher occupancy [S1, unofficial].

**Data Structures:**
*   `local_cell`: A single `int3` variable representing the current voxel coordinates [S1, unofficial].
*   `VX_BRICK_EXT`: A constant defining the brick dimensions (e.g., 8 or 16) [S1, unofficial].
*   `voxel_mask`: An array of `uint` values used for sparse voxel access [S1, unofficial].

**Steps:**
1.  **Variable Consolidation:** Replace the pair of variables `min_cell` and `max_cell` with a single local variable `local_cell` [S1, unofficial].
2.  **Bounds Checking:** Implement bounds checking using a unified comparison against the brick extent [S1, unofficial]:
    ```python
    if any(local_cell[i] >= VX_BRICK_EXT for i in range(3)):
    ```
3.  **Deduplication:** Remove redundant `tdelta` calculations and unnecessary work within the nested loops [S1, unofficial].
4.  **Loop State Reduction:** Ensure that fewer variables are carried over the loops into registers [S1, unofficial].

**Pseudocode:**
```python
def optimized_dda_loop(ray_origin, ray_direction, brick_min, brick_max, brick_size, voxel_mask, voxels):
    # Initialize DDA state variables to prevent UnboundLocalError
    t_max = [0.0, 0.0, 0.0]
    t_delta = [0.0, 0.0, 0.0]
    step = [0, 0, 0]
    local_cell = [0, 0, 0]

    # Standard DDA initialization
    for i in range(3):
        if ray_direction[i] > 0:
            step[i] = 1
            t_max[i] = (brick_min[i] - ray_origin[i]) / ray_direction[i]
        elif ray_direction[i] < 0:
            step[i] = -1
            t_max[i] = (brick_max[i] - ray_origin[i]) / ray_direction[i]
        else:
            step[i] = 0
            t_max[i] = float('inf')
        t_delta[i] = step[i] / ray_direction[i] if ray_direction[i] != 0 else 0.0

    # Compute initial cell
    for i in range(3):
        local_cell[i] = int((ray_origin[i] - brick_min[i]) / brick_size)

    while True:
        # Bounds check using single variable and brick extent
        if any(local_cell[i] >= VX_BRICK_EXT for i in range(3)):
            break

        # Compute voxel index
        voxel_idx = local_cell[0] + local_cell[1] * VX_BRICK_EXT + local_cell[2] * VX_BRICK_EXT * VX_BRICK_EXT

        # Sparse voxel access
        word = voxel_mask[voxel_idx >> 5]
        bit = 1 << (voxel_idx & 31)

        if (word & bit) != 0:
            # Load voxel data
            return voxels.Load((brick_min[0] + local_cell[0], brick_min[1] + local_cell[1], brick_min[2] + local_cell[2], 0))[0]

        # Advance ray using standard DDA step
        if t_max[0] < t_max[1]:
            if t_max[0] < t_max[2]:
                axis = 0
            else:
                axis = 2
        else:
            if t_max[1] < t_max[2]:
                axis = 1
            else:
                axis = 2

        local_cell[axis] += step[axis]
        t_max[axis] += t_delta[axis]

        # Check for brick exit
        if any(local_cell[i] < 0 or local_cell[i] >= VX_BRICK_EXT for i in range(3)):
            break
```

**Parameters:**
*   `VX_BRICK_EXT`: Brick dimension. Typical values are 8 or 16. Not given in the sources.
*   Target Register Allocation: < 72 registers (achieved 72 vs 92) [S1, unofficial].
*   Target Occupancy: > 40% (achieved 42.37% vs 35.43%) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Low Occupancy:** Unoptimized shaders may have occupancy as low as 35.43% with 92 registers, causing memory stalls [S1, unofficial].
*   **Register Pressure:** Carrying excessive state across nested loops increases register allocation, reducing the number of concurrent warps [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Memory:** Reduced register usage (from 92 to 72 registers) [S1, unofficial].
*   **Time:** Performance improvements vary by scene complexity [S1, unofficial].

**Measured Performance:**
*   **monu2-1 (128³):** FPS 143.20 -> 144.00 (+0.56%), Walltime 6.58 ms -> 5.37 ms (-18.32%) [S1, unofficial].
*   **sponza-256-1:** FPS 59.78 -> 72.83 (+21.83%), Walltime 28.39 ms -> 22.51 ms (-20.71%) [S1, unofficial].
*   **sponza-256-2:** FPS 109.53 -> 143.94 (+31.42%), Walltime 13.40 ms -> 7.32 ms (-45.33%) [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Significant walltime reduction in complex scenes (up to 45.33% faster) [S1, unofficial].
*   **Limitations:** Modest FPS gains in simpler scenes (0.56%) [S1, unofficial].

**When to Use:**
*   Use when DDA shader occupancy is low (<40%) and register allocation is high (>80 registers) [S1, unofficial].

## Background
Originated from development logs of a voxel raytracer, addressing the performance drop in 2-level DDA shaders compared to naive DDA by reducing register pressure [S1, unofficial]. The unoptimized 2-level DDA shader had an occupancy of 35.43% and 92 registers, compared to 71.39% and 42 registers for the naive DDA [S1, unofficial].
