# Parallel 3D-DDA
Also called: SIMD Ray Marching, 并行化改造方案
## Overview
Parallel 3D-DDA is a GPU-optimized implementation of the 3D Digital Differential Analyzer traversal algorithm, designed to process large batches of rays simultaneously using Single Instruction, Multiple Data (SIMD) parallelism [S1, unofficial]. It solves the performance bottleneck of naive ray marching by leveraging modern GPU architectures to achieve high throughput, processing approximately 28 million rays per second on an NVIDIA A100 [S1, unofficial]. Unlike its parent [Hardware/Implementation Optimization](10943-hardware-implementation-optimization.md) which outlines general principles, this method specifically details the warp-level parallelization and mixed-precision strategies required to maintain efficiency in volume rendering [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ rays, each defined by origin $\mathbf{o}$, direction $\mathbf{d}$, and nominal step size $\Delta s$; a 3D voxel grid [S1, unofficial].
*   **Output:** Computed color and opacity for each ray, or traversal termination status [S1, unofficial].

**Data Structures:**
*   **Ray Data:** Stored in a Structure of Arrays (SoA) layout to ensure coalesced global memory access [G]. Each ray requires fields for current position, step size, and remaining distance [G].
*   **Voxel Data:** Cached in shared memory to reduce global memory access latency [S1, unofficial].

**Algorithm Steps:**
1.  **Warp Partitioning:** Divide the set of $N$ rays into groups of 32 (one warp per GPU thread block or subgroup); each thread processes exactly one ray [S1, unofficial].
2.  **Initialization:** For each ray, calculate the initial intersection with the volume bounding box to determine the entry voxel and the traversal direction signs [G].
3.  **Shared Memory Loading:** Cache the relevant voxel data into shared memory for the warp to reduce global memory access latency [S1, unofficial].
4.  **Traversal Loop:**
    a.  Sample the voxel at the current ray position [G].
    b.  Update ray position by advancing to the next voxel boundary along the ray direction [G].
    c.  Check for termination (exit volume or opacity threshold reached) [G].
    d.  If not terminated, update voxel indices based on direction signs [G].
5.  **Termination:** Write results to global memory [S1, unofficial].

**Mixed Precision Strategy:**
To balance precision and performance, the algorithm employs a two-stage precision approach [S1, unofficial]:
1.  **Initial Stage:** Use 32-bit floating-point numbers (FP32) for the first few steps to ensure accurate entry point calculation and initial sampling [S1, unofficial].
2.  **Deep Penetration Stage:** Switch to 16-bit floating-point numbers (FP16) as the ray penetrates deeper into the medium to accelerate calculation [S1, unofficial].

**Parameters:**
*   **Step Size:** Typically set to 0.5 voxel spacing to balance detail and performance [S1, unofficial].
*   **Warp Size:** 32 threads (standard NVIDIA GPU warp size) [G].

**Edge Cases and Pitfalls:**
*   **Precision Loss:** Using FP16 for initial entry calculations can cause jitter or incorrect voxel hits; the switch to FP16 should only occur after the ray is firmly inside the volume [S1, unofficial].
*   **Memory Coalescing:** Non-coalesced access patterns in global memory can severely degrade performance; SoA layout is critical [G].
*   **Occupancy:** High register pressure from carrying per-ray state can reduce occupancy; state should be minimized or stored in registers efficiently [G].

**Pseudocode:**
```python
def parallel_3d_dda_ray(origin, direction, step_size, bounds_min, bounds_max, max_steps):
    # 1. Initialization: Calculate entry/exit distances and voxel crossing parameters
    t_min = 0.0
    t_max = 0.0
    for i in range(3):
        if direction[i] == 0:
            t_min = max(t_min, 1e9)
            t_max = max(t_max, 1e9)
        else:
            t1 = (bounds_min[i] - origin[i]) / direction[i]
            t2 = (bounds_max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = max(t_max, max(t1, t2))
            
    if t_min > t_max or t_max < 0:
        return [0.0, 0.0, 0.0], 0.0, 0  # Ray misses volume
        
    # Step distances per axis
    t_delta = [step_size / abs(direction[i]) if direction[i] != 0 else 1e9 for i in range(3)]
    # Distance to next voxel boundary
    t_max_voxel = [t_min + t_delta[i] if direction[i] > 0 else t_min - t_delta[i] for i in range(3)]
    
    # Initial voxel index
    voxel_idx = [int((origin[i] - bounds_min[i]) / step_size) for i in range(3)]
    step_sign = [1 if direction[i] > 0 else -1 for i in range(3)]
    
    accumulated_opacity = 0.0
    accumulated_color = [0.0, 0.0, 0.0]
    current_t = t_min
    precision = 'FP32'
    switch_threshold = 5  # Steps before switching to FP16
    
    # 2. Traversal Loop
    for step in range(max_steps):
        if current_t > t_max:
            break  # Exited volume
            
        # a. Sample the voxel at the current ray position [G]
        voxel_val = texture_fetch(voxel_idx) # Standard texture lookup [G]
        alpha = voxel_val
        
        # Compositing update
        if precision == 'FP32':
            accumulated_color = [accumulated_color[i] + (1.0 - accumulated_opacity) * alpha * 1.0 for i in range(3)]
            accumulated_opacity += (1.0 - accumulated_opacity) * alpha
        else:
            accumulated_color = [accumulated_color[i] + (1.0 - accumulated_opacity) * alpha * 1.0 for i in range(3)]
            accumulated_opacity += (1.0 - accumulated_opacity) * alpha
            
        # c. Check for termination
        if accumulated_opacity >= 0.99:
            break
            
        # d. Update voxel indices based on direction signs
        min_t = 1e9
        min_idx = -1
        for i in range(3):
            if t_max_voxel[i] < min_t:
                min_t = t_max_voxel[i]
                min_idx = i
        if min_idx != -1:
            voxel_idx[min_idx] += step_sign[min_idx]
            t_max_voxel[min_idx] += t_delta[min_idx]
            current_t = min_t  # b. Update ray position to next boundary
            
        # Precision switch
        if step == switch_threshold:
            precision = 'FP16'
            
    return accumulated_color, accumulated_opacity, step
```
## Subtopics

### Mixed Precision Optimization
A variant that dynamically switches from FP32 to FP16 during traversal [S1, unofficial]. It uses FP32 for initial steps to ensure precision and FP16 for deeper penetration to accelerate calculation [S1, unofficial]. This strategy increased computational throughput by 40% in game engine practice while maintaining visual effects [S1, unofficial].

### [Per-pixel 3D-DDA Renderer](12466-per-pixel-3d-dda-renderer.md)
A CPU-based method that performs strict per-pixel traversal order over a brickmap. It serves as a clean-room alternative to column-coherent raycasting, enabling correct compositing of transparent voxels without depth sorting or Order-Independent Transparency (OIT) schemes. Unlike the parallel GPU method, it focuses on traversal order correctness on CPU architectures.
