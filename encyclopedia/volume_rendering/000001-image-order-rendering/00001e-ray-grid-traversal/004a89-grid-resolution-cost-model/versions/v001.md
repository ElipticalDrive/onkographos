# Grid Resolution Cost Model

Also called: Cost-based grid resolution model, ISP07 cost model, Ize et al. cost model

## Overview
The Grid Resolution Cost Model determines the optimal uniform grid subdivision factor $m$ that minimizes the average ray traversal time $T$ for a given scene [S1]. Unlike hierarchical methods that evaluate split planes (e.g., SAH), this model evaluates the cost of a global grid resolution weighted by the average number of primitives per cell [S1]. It distinguishes itself by providing closed-form asymptotic solutions for $m$ based on whether the scene is point-based or line-based [S1].

## How it works
**Inputs and Outputs:**
- Input: Scene primitive count $N$, subdivision factor $m$, traversal time components ($T_{setup}, T_{step}, T_{inter}$), and scene model type (point-based or line-based) [S1].
- Output: Optimal subdivision factor $M$ [S1].

**Data Structures:**
No complex data structures are required for the calculation itself; it relies on scalar parameters [S1].

**Formulas and Parameters:**
The average traversal time $T$ is modeled as [S1][S2, unofficial]:
$$
T = T_{setup} + m T_{step} + \mu T_{inter}
$$
Where:
- $T_{setup}$: Time for initial intersection with the main voxel bounding box and traversal setup [S1][S2, unofficial].
- $T_{step}$: Time to advance from one cell to a neighbor (excluding intersection checks) [S1][S2, unofficial].
- $T_{inter}$: Time required to check a ray-primitive intersection [S1][S2, unofficial].
- $\mu$: Average number of primitives contained (or partially contained) in the $m$ cells reached by a ray [S1][S2, unofficial].
- $N_m$: Total number of intersections between primitives and grid cells for subdivision $m$ [S1].
- $\mu = N_m / m^2$ [S1].

**Algorithm to find M:**
1.  Identify scene model (point-based or line-based) [S1].
2.  Calculate $T_{setup}, T_{step}, T_{inter}$ [S1][S2, unofficial].
3.  Compute $M$ using the appropriate formula [S1].

**Pseudocode:**
```python
def calculate_optimal_grid_resolution(N, T_setup, T_step, T_inter, model_type):
    """
    Calculates the optimal grid subdivision factor M.
    
    Args:
        N: Number of primitives.
        T_setup: Time for initial setup.
        T_step: Time to advance to neighbor.
        T_inter: Time for ray-primitive intersection.
        model_type: 'point' or 'line'.
        
    Returns:
        M: Optimal subdivision factor.
    """
    if model_type == 'point':
        # Point-based: each primitive in exactly one cell
        # Formula from [S1]: M = sqrt(2 * T_inter / T_step) * N
        # Note: Source [S1] claims O(N) complexity for this formula.
        M = (2 * T_inter / T_step)**0.5 * N
    elif model_type == 'line':
        # Line-based: each primitive in m cells
        # Formula from [S1]: M = cbrt((2 * T_inter / T_step)**2) * N**1.5
        # Note: Source [S1] claims O(N^1.5) complexity.
        M = ((2 * T_inter / T_step)**2)**(1/3) * (N**1.5)
    else:
        raise ValueError("Model type must be 'point' or 'line'")
        
    return M
```

**Edge Cases:**
-   If $T_{step} = 0$, the model breaks down (division by zero) [S1].
-   The model assumes $T_{setup}, T_{step}, T_{inter}$ are constant [S1].
-   Real-world models often behave between the two extremes [S1].

## Subtopics

### [Guess and Check Building Algorithm](12809-guess-and-check-building-algorithm.md)
An algorithm that samples the cost function over a bounded interval of $m$ values to find the resolution that minimizes cost, achieving linear overall building time. It uses the theoretical bounds derived from the cost model (e.g., $m \in ((10N)^{1/3}, 5N^{1/2})$) to limit the search space.

### Cost model for hierarchical grid building
A cost model that suggests a way to build hierarchical grids and determine a termination criteria to stop recursion [S1]. Recursion is beneficial if $T_{setup} + m T_{step} + \mu T_{inter} > N T_{inter}$ [S1]. Deep recursion requires efficient indexing strategies (e.g., hash tables) [S1].

## Operating characteristics
-   **Time Complexity:** The calculation of $M$ is $O(1)$ given the parameters [S1]. The "Guess and Check" building algorithm has linear overall building time $O(N)$ [S1].
-   **Memory Complexity:** Not given in the sources.
-   **Strengths:** Simple, clear, and provides theoretical bounds for grid resolution [S1]. Allows for linear-time grid building via sampling [S1].
-   **Limitations:** Requires knowledge of the scene model type (point vs. line) to apply the correct formula [S1]. Assumes constant traversal and intersection times [S1]. Does not account for spatial coherence or mailboxing optimizations in the base formula (though mailboxing can redefine $N_m$) [S1].
-   **When to use:** When a uniform grid is desired and scene statistics (primitive count and type) are known [S1].
-   **When not:** For highly adaptive scenes where uniform grids are inefficient, or when hierarchical structures are preferred [S1].

## Background
The cost model was introduced by Ize et al. [ISP07] as a clear and simple method for determining grid resolution [S1][S2, unofficial]. It builds on earlier work by Cohen and Werman [CW88] [S1]. It is discussed in surveys on exploiting grids for ray tracing [S1][S2, unofficial].
