# Indirect Mapping

Also called: Indirect thread mapping, Tile-based indirect mapping

## Overview
Indirect mapping is a thread-to-data mapping strategy used in GPU-based ray tracing to balance spatial coherence with SIMD (Single Instruction, Multiple Data) utilization [S1]. It addresses the conflict between sorting geometry into small tiles for efficient culling and the need for large thread blocks to saturate GPU hardware [S1]. Unlike standard direct mapping where thread indices align strictly with sorting tiles, indirect mapping decouples the sorting granularity from the ray-tracing granularity, allowing a larger number of threads to process a coarser area while maintaining coherence within sub-tiles [S1].

## How it works
**Inputs:**
- Triangle mesh data.
- Image dimensions (width $W$, height $H$).
- Sorting tile dimensions ($kN \times kN$ pixels).
- Ray-tracing tile dimensions ($N \times N$ pixels).
- GPU hardware parameters (SIMD width, shared memory size).

**Outputs:**
- Rendered image with reduced triangle intersection overhead.

**Data Structures:**
- **Sorting Tiles:** The image is divided into $kN \times kN$ pixel tiles. Triangles are sorted into these tiles.
- **Ray-Tracing Tiles:** The image is divided into $N \times N$ pixel tiles. Each ray-tracing tile contains a $k \times k$ group of sorting tiles.
- **Shared Memory:** Partitioned equally among the sorting tiles within a ray-tracing tile.

**Parameters:**
- $k$: The factor by which sorting tiles are finer than ray-tracing tiles. The source specifies that a $2 \times 2$ configuration (i.e., $k=2$) provides the best results on current GPU hardware [S1].
- $N$: Base dimension of the ray-tracing tile.

**Steps:**
1. **Sort Triangles:** Sort all triangles into $kN \times kN$ sorting tiles in image space. This creates a finer-grained spatial partition than the final ray-tracing tiles [S1].
2. **Initialize Ray-Tracing Tile:** Launch a work group (thread block) for each $N \times N$ ray-tracing tile. This work group contains more threads than a standard direct-mapping block to cover the larger area and utilize SIMD units [S1].
3. **Partition Shared Memory:** Divide the available shared memory for the work group into $k \times k$ regions, one for each sorting tile contained within the current ray-tracing tile [S1].
4. **Load Geometry:** For each sorting tile within the current ray-tracing tile, load its associated triangles into the corresponding region of shared memory [S1].
5. **Ray Tracing:** Threads within the work group trace rays corresponding to the pixels in the $N \times N$ ray-tracing tile. When a thread needs to intersect a ray with triangles, it accesses the shared memory region corresponding to the sorting tile that contains the relevant triangles [S1].
6. **Intersection:** Perform ray-triangle intersection tests using the triangles loaded in shared memory. The indirect mapping ensures that while threads cover a larger area, they only check triangles from the specific sorting tiles relevant to their ray's path, reducing the maximum number of triangles checked [S1].

**Pseudocode:**

```python
    # and are intersected with the rays corresponding to the sorting tiles."
    # This implies the threads might be organized or the access pattern is such that
    # they check the specific shared memory block for the sorting tile containing the ray's origin/intersection.
    
    # More accurately based on source:
    # The work group has more threads. The shared memory is partitioned.
    # Triangles from each sorting tile are in their respective shared memory area.
    # Rays are intersected with triangles.

    min_t = infinity
    
    # Iterate over the k*k sorting tiles in shared memory
    for st_x in range(k):
        for st_y in range(k):
            # Access triangles in shared memory
            tri_list = shared_mem[st_x][st_y]
            
            # Intersect ray with triangles in this sorting tile
            for tri in tri_list:
                t = intersect(ray, tri)
                if t is not None and t < min_t:
                    min_t = t
                    closest_hit = tri
                    
    return closest_hit
```
*Note: The pseudocode above simplifies the thread-to-pixel mapping. The key insight is that the shared memory holds triangles for the finer $kN \times kN$ tiles, and the larger thread block processes the $N \times N$ area, accessing the appropriate shared memory partition based on spatial locality.*

**Edge Cases and Pitfalls:**
- **Shared Memory Limits:** The number of triangles loaded into shared memory must fit within the available shared memory per work group. If a sorting tile contains too many triangles, the method may fail or require fallback strategies [S1].
- **SIMD Utilization:** If the number of threads is too low relative to the SIMD width, computing resources are wasted. Indirect mapping helps balance this by allowing larger thread blocks [S1].
- **Precision:** Standard ray-triangle intersection precision issues apply.

## Subtopics

### View-coherent Remapping
A technique to resolve uncoalesced memory access in subpixel-level rasterization by reordering GPU thread assignment to subpixels based on viewpoint indices [S2]. It ensures that warp threads process subpixels from the same or nearby viewpoints, restoring viewpoint monotonicity and enabling coalesced memory access [S2]. It is chosen when rendering light field displays or multi-view images where subpixel-level rasterization causes memory access inefficiencies due to scattered viewpoint indices [S2]. It differs from standard indirect mapping by operating on subpixel coordinates and viewpoint indices rather than triangle tiles and primary rays [S2].

## Operating characteristics
- **Performance:** On the Happy Buddha benchmark, indirect mapping provided a 10-30 percent speedup [S1].
- **Efficiency:** The maximum number of triangles checked dropped by more than half due to the finer sorting [S1].
- **Hardware Suitability:** Best results are observed with a $2 \times 2$ sorting tile configuration on current GPU hardware [S1].
- **Complexity:** The method adds overhead for sorting triangles into finer tiles and managing shared memory partitions, but reduces the computational cost of ray-triangle intersections [S1].
- **Limitations:** Requires sufficient shared memory to hold triangles for multiple sorting tiles. Performance is sensitive to the SIMD width and the distribution of triangles across tiles [S1].

## Background
Indirect mapping was introduced in the context of raytracing dynamic scenes on the GPU [S1]. It was developed to address the trade-off between spatial coherence (achieved by sorting geometry into tiles) and hardware utilization (achieved by using large thread blocks) [S1]. The method is particularly relevant for GPU architectures where shared memory and SIMD units are critical performance factors [S1].
