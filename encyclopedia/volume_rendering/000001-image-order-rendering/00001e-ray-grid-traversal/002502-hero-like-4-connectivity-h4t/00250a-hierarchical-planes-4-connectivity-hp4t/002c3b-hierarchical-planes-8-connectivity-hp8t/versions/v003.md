# Hierarchical Planes 8-Connectivity (HP8T)
## Overview
Hierarchical Planes 8-Connectivity (HP8T) is a ray traversal algorithm for hierarchical grids that simplifies the update logic of Hierarchical Planes 4-Connectivity (HP4T)[S1, unofficial]. While HP4T enforces strict 4-connectivity by clamping the non-hit axis, HP8T removes this clamping to allow 8-connectivity, permitting diagonal jumps between cells[S1, unofficial]. This simplification reduces computational overhead but requires flooring fractional grid positions before data access and introduces ambiguities in surface normal calculation when using simple comparison variables[S1, unofficial].

## How it works
HP8T builds on [Hierarchical Planes 4-Connectivity (HP4T)](3444-hierarchical-planes-4-connectivity-hp4t.md) by modifying the update step for the axis that is not currently being hit by the ray plane intersection[S1, unofficial].

### Inputs and Outputs
*   **Inputs**:
    *   `ray_position`: The starting position of the ray in world space[S1, unofficial].
    *   `ray_dir`: The normalized direction vector of the ray[S1, unofficial].
    *   `inv_dir`: The reciprocal of `ray_dir` ($1.0 / ray\_dir$)[S1, unofficial].
    *   `cellsize`: The side length of the uniform grid cells[S1, unofficial].
    *   `is_dir_pos`: A vector indicating the positive direction of traversal for each axis (typically 1.0 if `ray_dir` > 0, else 0.0)[S1, unofficial].
    *   `is_ray_neg`: A vector indicating the negative direction (typically -1.0 if `ray_dir` < 0, else 0.0), used to adjust the plane position[S1, unofficial].
    *   `grid_width`, `grid_height`: The dimensions of the 2D grid slice being traversed[S1, unofficial].
    *   `grid_position`: The current continuous position of the ray within the grid[S1, unofficial].
*   **Outputs**:
    *   Updated `grid_position` for each step[S1, unofficial].
    *   `t`: The distance to the next plane intersection[S1, unofficial].

### Steps
1.  **Calculate Planes**: Determine the world coordinates of the next grid planes for the X and Y axes based on the current `grid_position`[S1, unofficial].
    $$ planes = (\lfloor grid\_position / cellsize \rfloor + is\_dir\_pos) \times cellsize $$
2.  **Calculate Total T**: Compute the distance along the ray to reach these planes[S1, unofficial].
    $$ total\_t = (planes - ray\_position) \times inv\_dir $$
3.  **Determine Hit Axis**: Compare `total_t.x` and `total_t.y`[S1, unofficial].
    *   If `total_t.x <= total_t.y`: The ray hits the X plane first[S1, unofficial].
    *   Else: The ray hits the Y plane first[S1, unofficial].
4.  **Update Position**:
    *   **If X is hit**: Update X coordinate to the plane position: `grid_position.x = planes.x - is_ray_neg.x`. Update Y coordinate by adding the delta corresponding to the travel time `total_t.x`: `grid_position.y += ray_dir.y * max(0.0, total_t.x - (grid_position.y - ray_position.y) * inv_dir.y)`. Set `t = total_t.x`[S1, unofficial].
    *   **If Y is hit**: Update Y coordinate to the plane position: `grid_position.y = planes.y - is_ray_neg.y`. Update X coordinate by adding the delta corresponding to the travel time `total_t.y`: `grid_position.x += ray_dir.x * max(0.0, total_t.y - (grid_position.x - ray_position.x) * inv_dir.x)`. Set `t = total_t.y`[S1, unofficial].
5.  **Access Grid**: Before reading the grid data at the new position, floor the `grid_position` components to obtain integer indices[S1, unofficial].

### Pseudocode
```python
import math

def traverse_hp8t(ray_position, ray_dir, inv_dir, cellsize, is_dir_pos, is_ray_neg, grid_width, grid_height, grid_position):
    while 0 <= grid_position[0] < grid_width and 0 <= grid_position[1] < grid_height:
        planes_x = (math.floor(grid_position[0] / cellsize) + is_dir_pos[0]) * cellsize
        planes_y = (math.floor(grid_position[1] / cellsize) + is_dir_pos[1]) * cellsize
        total_t_x = (planes_x - ray_position[0]) * inv_dir[0]
        total_t_y = (planes_y - ray_position[1]) * inv_dir[1]
        
        if total_t_x <= total_t_y:
            grid_position[0] = planes_x - is_ray_neg[0]
            grid_position[1] += ray_dir[1] * max(0.0, total_t_x - (grid_position[1] - ray_position[1]) * inv_dir[1])
            t = total_t_x
        else:
            grid_position[1] = planes_y - is_ray_neg[1]
            grid_position[0] += ray_dir[0] * max(0.0, total_t_y - (grid_position[0] - ray_position[0]) * inv_dir[0])
            t = total_t_y
```

### Parameters
*   `cellsize`: The resolution of the underlying uniform grid[S1, unofficial].
*   `is_dir_pos`, `is_ray_neg`: Derived from `ray_dir`. `is_dir_pos` is 1.0 where `ray_dir > 0`, else 0.0. `is_ray_neg` is -1.0 where `ray_dir < 0`, else 0.0[S1, unofficial].

### Edge Cases and Pitfalls
*   **Fractional Positions**: Unlike HP4T, `grid_position` retains fractional values and must be floored before accessing grid data to avoid reading incorrect cells or causing memory errors[S1, unofficial].
*   **Surface Normal Ambiguity**: HP8T allows diagonal jumps[S1, unofficial]. If surface normals are calculated using a simple `compare` variable, the calculation will be incorrect for diagonal transitions because the `compare` value cannot distinguish between entering a cell from the side versus entering from a corner[S1, unofficial]. A post-processing step analyzing surrounding cells is required to determine the correct normal[S1, unofficial].
*   **Boundary Checks**: The loop condition checks `grid_position` against `grid_width` and `grid_height`[S1, unofficial].

## Operating characteristics
*   **Accuracy**: In randomized testing (100,000,000 cases), HP8T achieved a 99.99% chance of correct position and 99.99% chance of correct normal[S1, unofficial]. This is slightly lower than the 100% accuracy of Hero-like 4-Connectivity (H4T)[S1, unofficial].
*   **Strengths**: Simpler calculation for the non-hit axis compared to HP4T, as it avoids the complex clamping logic[S1, unofficial].
*   **Limitations**: 8-connectivity introduces potential errors in surface normal determination if not handled with additional logic[S1, unofficial]. The lack of clamping means the ray can "jump" diagonally, which may be undesirable for algorithms requiring strict 4-connectivity[S1, unofficial].

## Background
HP8T is described in a thesis [S1, unofficial]. It is presented as a variant of HP4T, designed to simplify the traversal logic by removing the clamping step for the non-hit axis[S1, unofficial]. The method was evaluated against HP4T and H4T using randomized and specific test cases[S1, unofficial].
