# GPU Octree Volume Rasterization with Shadow Mapping

Also called: asvo renderer, voxel-based octree traversal

## Overview
This method renders volumetric data stored in a Sparse Voxel Octree (SVO) by decoupling the hierarchical traversal from the raycasting loop, using rasterization to cull empty space and shadow mapping for occlusion [S1, unofficial]. It solves the performance bottleneck of branch-intensive octree traversal on GPUs by rasterizing proxy geometry of a view-dependent cut of octree nodes to identify occupied bricks, then casting rays only through the resulting tight segments [S2, abstract only, unofficial]. Unlike sibling methods that traverse the tree per-ray, this approach uses a rasterization pass to generate per-pixel lists of bricks, enabling two levels of empty space skipping (brick and macrocell) and achieving 2 to 4 times faster rendering than state-of-the-art algorithms on large out-of-core datasets [S2, abstract only, unofficial].

## How it works
The renderer operates in two main phases: a traversal/rasterization phase to identify visible volume segments, and a raycasting/shadow phase to compute color and depth.

**Inputs and Outputs:**
*   **Inputs:** Octree data structure (composed of bricks and macrocells), camera parameters, light position, frame dimensions ($m\_frameWidth, m\_frameHeight$).
*   **Outputs:** Color buffer (RGBA), Shadow map (depth buffer).

**Data Structures:**
*   **Octree:** Hierarchical structure where each node represents a brick. Bricks are further split into regular macrocells [S2, abstract only, unofficial].
*   **Per-pixel List:** Captures all bricks penetrated by the ray in front-to-back order during the rasterization pass [S2, abstract only, unofficial].
*   **Shadow Map:** 2D texture storing depth values. Initialized with `minDepth = INT_MAX` [S1, unofficial].
*   **Traversal Queue:** Dynamic queue managed by `dTravQueuePtr`. Initialized with `hStartIndex = 0` and `hEndIndex = obj.data()->jobs().size()` [S1, unofficial].

**Parameters:**
*   $m\_frameWidth, m\_frameHeight$: Frame dimensions in pixels.
*   $octreeLevel$: Current traversal depth, incremented each iteration [S1, unofficial].
*   $shadowPass$: Boolean flag determining whether to launch the shadow map kernel or the draw kernel [S1, unofficial].

**Steps:**

1.  **Initialization:**
    *   Set $hStartIndex = 0$.
    *   Set $hEndIndex = \text{size of job queue}$.
    *   Initialize $dTravQueuePtr[0] = hEndIndex$ [S1, unofficial].
    *   Set $octreeLevel = 0$ [S1, unofficial].

2.  **Traversal Loop:**
    *   While $hEndIndex - hStartIndex > 0$:
        *   Launch the **traverse kernel** with job range $[hStartIndex, hEndIndex)$ and current $octreeLevel$ [S1, unofficial].
        *   Update $hStartIndex = hEndIndex$.
        *   Update $hEndIndex = dTravQueuePtr[0]$ (read from GPU) [S1, unofficial].
        *   Increment $octreeLevel$ by 1 [S1, unofficial].
    *   *Pitfall:* If $dTravQueuePtr[0]$ is not updated correctly by the kernel, the loop may infinite loop or terminate prematurely [S1, unofficial].

3.  **Rasterization (Implicit in Traversal):**
    *   Rasterize proxy geometry of a view-dependent cut of octree nodes [S2, abstract only, unofficial].
    *   Capture all bricks that the ray penetrates in a per-pixel list [S2, abstract only, unofficial].
    *   Ensure the per-pixel list is captured in front-to-back order [S2, abstract only, unofficial].
    *   This achieves two levels of empty space skipping: brick level and macrocell level [S2, abstract only, unofficial].

4.  **Shadow Map Pass (if $shadowPass$ is true):**
    *   Launch **drawShadowMap kernel** [S1, unofficial].
    *   For each voxel, compute depth.
    *   *Pitfall:* If no voxels are found, $minDepth$ remains $INT\_MAX$ and $shadowMap[index]$ is not written [S1, unofficial].

5.  **Raycasting/Draw Pass (if $shadowPass$ is false):**
    *   Launch **draw kernel** [S1, unofficial].
    *   Cast rays only inside the tighter ray segments identified by the per-pixel list [S2, abstract only, unofficial].
    *   Use texture descriptor $depthBufferTexDesc$ with:
        *   $addressMode[0] = cudaAddressModeClamp$
        *   $filterMode = cudaFilterModePoint$
        *   $normalizedCoords = false$
        *   $readMode = cudaReadModeElementType$ [S1, unofficial].

**Pseudocode:**

```python
def render_pipeline(model, camera, light, frame_width, frame_height):
    # 1. Initialization
    h_start_index = 0
    h_end_index = len(model.data.jobs)
    d_trav_queue_ptr = [h_end_index]  # Simulated GPU pointer
    octree_level = 0
    
    # 2. Traversal Loop
    while h_end_index - h_start_index > 0:
        # Launch traverse kernel with job range [h_start_index, h_end_index)
        # and current octree_level
        traverse_kernel(
            jobs=model.data.jobs[h_start_index:h_end_index],
            octree_level=octree_level,
            output_queue=d_trav_queue_ptr
        )
        
        # Update indices
        h_start_index = h_end_index
        h_end_index = d_trav_queue_ptr[0]
        octree_level += 1
        
        # Pitfall check: if queue pointer not updated, loop may fail
        if h_end_index < h_start_index:
            break

    # 3. Shadow Map Pass
    shadow_pass = True  # Example flag
    if shadow_pass:
        draw_shadow_map_kernel(
            model=model,
            camera=camera,
            light=light,
            min_depth=INT_MAX  # Pitfall: remains INT_MAX if no voxels found
        )
    else:
        # 4. Raycasting/Draw Pass
        depth_buffer_tex_desc = {
            "addressMode": [cudaAddressModeClamp],
            "filterMode": cudaFilterModePoint,
            "normalizedCoords": False,
            "readMode": cudaReadModeElementType
        }
        draw_kernel(
            model=model,
            camera=camera,
            light=light,
            depth_buffer_tex_desc=depth_buffer_tex_desc,
            per_pixel_lists=get_per_pixel_lists()  # From rasterization pass
        )
```

## Subtopics

### Octree Rasterization for Volume Rendering
A GPU-based high-quality volume rendering approach for large out-of-core volume data that reduces rendering time by moving branch-intensive accelerating structure traversal out of the GPU raycasting loop and introducing efficient empty-space culling via rasterization [S2, abstract only, unofficial]. It stores the volume in an octree composed of bricks, further splitting every brick into regular macrocells [S2, abstract only, unofficial]. The method rasterizes the proxy geometry of a view-dependent cut of the octree nodes to capture all bricks that the ray penetrates in a per-pixel list, ensuring front-to-back order [S2, abstract only, unofficial]. This allows the raycasting pass to cast rays only inside tighter ray segments, achieving two levels of empty space skipping (brick and macrocell) [S2, abstract only, unofficial]. It achieved 2 to 4 times faster rendering speed than current state-of-the-art algorithms across a variety of data sets [S2, abstract only, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduced compared to traditional per-ray traversal due to rasterization-based culling. The traversal is parallelized across jobs and octree levels [S1, unofficial].
*   **Memory Complexity:** Requires storage for the octree (bricks and macrocells), per-pixel lists, and shadow maps [S2, abstract only, unofficial].
*   **Measured Performance:** Achieved 2 to 4 times faster rendering speed than state-of-the-art algorithms across various datasets [S2, abstract only, unofficial].
*   **Strengths:** Efficient empty-space culling via rasterization; handles large out-of-core data; reduces branch divergence in GPU raycasting [S2, abstract only, unofficial].
*   **Limitations:** Requires additional memory for per-pixel lists; complex synchronization between traversal and rasterization passes; potential for infinite loops if queue pointers are not managed correctly [S1, unofficial].
*   **When to Use:** Large out-of-core volumetric datasets where traditional raycasting is too slow due to branch divergence and empty space traversal [S2, abstract only, unofficial].
*   **When Not to Use:** Small datasets where the overhead of rasterization and per-pixel list management outweighs the benefits; scenes with high transparency where shadow mapping is less effective.

## Background
The method originates from the "asvo@cuda" project, an unofficial implementation of GPU-based volume rendering using CUDA and OpenGL [S1, unofficial]. It builds upon the principles of Sparse Voxel Octree (SVO) traversal and integrates rasterization techniques for acceleration [S1, unofficial]. The underlying theoretical framework for octree rasterization in volume rendering was presented in research focused on high-quality out-of-core GPU volume rendering, which demonstrated significant performance improvements by decoupling traversal from raycasting [S2, abstract only, unofficial].
