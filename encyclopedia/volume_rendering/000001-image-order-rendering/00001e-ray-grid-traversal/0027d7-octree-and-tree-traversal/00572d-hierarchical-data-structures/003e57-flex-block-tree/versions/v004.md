# Flex-block tree

Also called: Cell-tree, Flex-block partition

## Overview
The flex-block tree is a hierarchical data structure derived from a kd-tree, designed to distribute massive volume data across distributed rendering nodes while ensuring load balancing and deterministic view-dependent ordering [S1, unofficial]. It solves the problem of efficient data distribution and ray-task scheduling in distributed ray casting and ray tracing by partitioning space into "flex-blocks" that tightly crop empty space [S1, unofficial]. Unlike traditional space subdivision methods that alternate axis cuts, the flex-block partition allows flexible cut orientations to accommodate scenes with disproportionate dimensions, and it provides a dependency graph for image composition in ray casting and traversal acceleration in ray tracing [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A massive volume dataset, potentially with a pre-computed mask volume indicating regions of interest [S1, unofficial].
*   **Output:** A flex-block tree structure (dependency graph), cropped volume slices, and a look-up table representing image priority orders for eight quantized view directions [S1, unofficial].

**Data Structures:**
1.  **Flex-block Tree Node:** A binary tree node containing a cut plane definition and pointers to child nodes, identical to a traditional kd-tree node structure [S1, unofficial].
2.  **Flex-block:** A leaf node in the tree. It represents a cell containing a tightly cropped subvolume. The subvolume does not necessarily occupy the entire geometric cell [S1, unofficial].
3.  **Ray Queue:** A data structure holding pending rays for a specific cell during ray tracing [S1, unofficial].

**Algorithm Steps:**
The construction and usage involve a preprocessing pipeline and runtime traversal:

1.  **Preprocessing - Data Reduction:**
    *   Read raw data slices one at a time [S1, unofficial].
    *   Perform out-of-core region growing to create a mask for each slice, or use a provided mask volume [S1, unofficial].
    *   Crop slices to bounding rectangles of regions of interest using the mask [S1, unofficial].
    *   Align a tight axis-aligned bounding box (AABB) around cohesive non-empty areas of the volume to crop empty space [S1, unofficial].

2.  **Partitioning - Moving Walls:**
    *   Apply a "moving walls" algorithm to partition the scene [S1, unofficial].
    *   Move partition walls to simultaneously accommodate non-empty subvolume boundaries and render-node requirements for load balancing [S1, unofficial].

3.  **Tree Construction - KD-Tree Extraction:**
    *   Extract a kd-tree from the output of the moving walls procedure [S1, unofficial].
    *   The leaf nodes of this kd-tree become the flex-blocks [S1, unofficial].
    *   Unlike standard kd-trees, the flex-block partition does not restrict partition cuts to alternate between axes [S1, unofficial].

4.  **Dependency Graph Generation:**
    *   Use dynamic programming to create flex-blocks within the kd-tree-like partition, optimizing for load balancing (solving the Load Balanced Network Distribution problem) [S1, unofficial].
    *   Extract the image priority order for eight quantized view directions from the kd-tree [S1, unofficial].
    *   Store these orders in a look-up table, which serves as the dependency graph of flex-blocks [S1, unofficial].

5.  **Distribution:**
    *   Distribute flex-block parameters (including the dependency graph) and cropped slices (or pre-created volume blocks) across the cluster [S1, unofficial].

**Runtime Usage:**

*   **For Ray Casting (Image Order Rendering):**
    1.  Traverse the flex-block tree to determine the deterministic depth order of flex-blocks for the current view direction [S1, unofficial].
    2.  Use this order to schedule bricks (subvolumes sized for rendering hardware) within each render-node [S1, unofficial].
    3.  Composite images into a final image using alpha blending, respecting the relative depth determined by the tree [S1, unofficial].

*   **For Ray Tracing (Object Order/Traversal):**
    1.  Distribute data using the flex-block partition [S1, unofficial].
    2.  Update ray-task scheduling dynamically within the local partition of each render-node [S1, unofficial].
    3.  **Space Skipping:** Automate space skipping within each cell by advancing the ray forward according to the data extents of the flex-block [S1, unofficial].
    4.  **Ray Queue Processing:**
        *   Maintain a ray queue for each cell [S1, unofficial].
        *   When a cell is in main memory, trace each ray in the corresponding queue through that cell [S1, unofficial].
        *   When a spawned ray exits the current cell, place it on the queue of the next cell it intersects [S1, unofficial].
    5.  Use the cell-tree (compact representation of ray dependencies between cells) to accelerate traversal by indicating potential neighbors a ray may enter [S1, unofficial].

**Parameters:**
*   **View Directions:** Eight quantized view directions are used to extract image priority orders [S1, unofficial].
*   **Brick Size:** Subvolumes (bricks) are sized for the rendering hardware [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **NP-Completeness:** Determining the optimum order for caching cells in ray tracing is NP-Complete; therefore, optimizations are required for scheduling [S1, unofficial].
*   **Single Fetch Limitation:** It is not generally possible to create a schedule that fetches each cell only once for ray tracing algorithms [S1, unofficial].
*   **Disproportionate Scenes:** The flexibility of cut axes is critical for scenes with disproportionate lengths on each side [S1, unofficial].

## Operating characteristics
*   **Load Balancing:** The method is specifically designed to solve the Load Balanced Network Distribution (LBND) problem, minimizing end-to-end rendering time which is a function of the slowest render-node, image composition time, and network communication time [S1, unofficial].
*   **Data Reduction:** By cropping empty space early in the pipeline, it reduces run-time for preprocessing, processing, and network data movement [S1, unofficial].
*   **Memory Efficiency:** The cell-tree (dependency graph) is several orders of magnitude smaller than the full number of dependencies it represents [S1, unofficial].
*   **Determinism:** Provides a deterministic depth order for any given view direction, which is essential for correct alpha blending in distributed ray casting [S1, unofficial].
*   **Hardware Support:** Supports both software ray tracing and hardware ray casting [S1, unofficial].

## Background
The flex-block tree and partition method were introduced in the context of massive data management for distributed volume visualization [S1, unofficial]. The work addresses the limitations of static data distribution and traditional space subdivision methods which do not adequately handle load balancing in distributed rendering environments [S1, unofficial]. It builds upon concepts from kd-trees and dynamic programming for multipass partition problems [S1, unofficial].
