# Brick-of-Bricks Decomposition
Also called: Flat hierarchy of bricks

## Overview
Brick-of-Bricks Decomposition is a storage format for volume rendering where the volume is stored as a flat hierarchy of bricks of size $n^3$ to improve cache-coherence in volume traversal [S1, unofficial][S2, book]. It arises from not fully expanding an octree into single-voxel leaf nodes [S2, book]. It sets itself apart from fully expanded octrees by reducing pointer overhead and improving spatial locality, and from flat grids by maintaining hierarchical traversal capabilities for large sparse volumes.

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset and an octree structure that is not fully expanded to single-voxel leaves.
*   **Output:** A linear memory layout containing bricks, enabling efficient ray traversal and trilinear interpolation.

**Data Structures:**
The structure consists of a hierarchy of "bricks." Each brick is a cubic block of voxels with side length $n$. The hierarchy is stored in a flat array (linear memory). The exact bit-packing of the hierarchy pointers or indices is not given in the sources. The leaf nodes of the octree are bricks of size $n^3$ rather than single voxels.

**Steps:**
1.  **Construction:** The volume is decomposed into an octree. Unlike a standard fully expanded octree, the recursion stops at bricks of size $n^3$ rather than single voxels [S1, unofficial][S2, book].
2.  **Flattening:** The hierarchical structure is flattened into a linear array of bricks [S1, unofficial][S2, book].
3.  **Traversal:** During raycasting, the ray traverses the hierarchy. When a ray enters a brick, it samples the $n^3$ voxels within that brick [S1, unofficial][S2, book].
4.  **Interpolation Indexing:** An efficient indexing scheme is used to quickly find the memory address of voxels located in the 8-neighborhood required for trilinear interpolation [S1, unofficial][S2, book].

**Formulas:**
Let $n$ be the side length of a brick. The number of voxels in a brick is $n^3$.
The indexing scheme allows finding the 8-neighborhood for trilinear interpolation. The specific formula for the indexing scheme is not given in the sources.

**Parameters:**
*   $n$: The side length of the bricks. Typical values are not given in the sources.

**Edge Cases and Pitfalls:**

## Background
**Origin:**
The concept is derived from fully expanded octrees but modifies the leaf node size [S1, unofficial][S2, book]. It was utilized by Parker et al. for raycasting of very large volumes [S1, unofficial][S2, book].

**History:**
The technique is discussed in the context of octree variations where nodes are not fully expanded into single-voxel leaf nodes [S1, unofficial][S2, book].

**Usage:**
Used in volume rendering, specifically for raycasting large volumes [S1, unofficial][S2, book].
