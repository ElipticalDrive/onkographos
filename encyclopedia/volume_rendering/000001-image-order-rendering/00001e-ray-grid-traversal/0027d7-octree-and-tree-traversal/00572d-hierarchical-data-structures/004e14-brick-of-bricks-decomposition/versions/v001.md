# Brick-of-Bricks Decomposition

Also called: Flat hierarchy of bricks

## Overview
Brick-of-Bricks Decomposition is a storage format for volume data where the volume is stored as a flat hierarchy of bricks of size $n^3$ to improve cache-coherence in volume traversal [S1, unofficial][S2, book]. It arises from not fully expanding an octree into single-voxel leaf nodes [S2, book]. It sets itself apart from fully expanded octrees by maintaining a hierarchical structure of larger blocks rather than individual voxels, and from flat grids by providing spatial locality through block-based indexing [S1, unofficial][S2, book].

## How it works
**Inputs and Outputs:**
*   **Input:** An octree representation of a volume where non-leaf nodes are not expanded to single voxels.
*   **Output:** A flat memory layout consisting of a hierarchy of bricks, each of size $n^3$ voxels.

**Data Structures:**
The structure is a "flat hierarchy of bricks" [S1, unofficial][S2, book].
*   **Brick:** A cubic block of voxels with side length $n$. The total number of voxels in a brick is $n^3$.
*   **Hierarchy:** The bricks are arranged in a hierarchy derived from the octree structure. The specific layout of the hierarchy (e.g., how parent bricks relate to child bricks) is not explicitly detailed in the sources beyond the term "flat hierarchy" [S1, unofficial][S2, book].
*   **Indexing:** An efficient indexing scheme is used to map logical voxel coordinates to physical memory addresses [S1, unofficial][S2, book]. This scheme is critical for finding the memory address of voxels located in the 8-neighborhood required for trilinear interpolation [S1, unofficial][S2, book].

**Steps:**
1.  Construct an octree for the volume data.
2.  Do not fully expand the octree to single-voxel leaf nodes [S2, book].
3.  Organize the resulting nodes into a flat hierarchy of bricks, where each brick contains $n^3$ voxels [S1, unofficial][S2, book].
4.  Implement an efficient indexing scheme to calculate memory addresses for voxels based on their logical coordinates [S1, unofficial][S2, book].
5.  Use this indexing scheme during raycasting to access the 8-neighborhood of a voxel for trilinear interpolation [S1, unofficial][S2, book].

**Formulas:**
*   Brick size: $n^3$ voxels [S1, unofficial][S2, book].
*   Trilinear interpolation requires access to 8 neighboring voxels [S1, unofficial][S2, book].

**Parameters:**
*   $n$: The side length of a brick in voxels. The sources do not specify a typical value for $n$.

**Edge Cases and Pitfalls:**
*   **Precision:** Not given in the sources.
*   **Boundaries:** Not given in the sources.
*   **Degenerate Input:** Not given in the sources.

*   **What it is:** An acceleration structure based on silhouette images and mip pyramids.

*   **When to choose:** When image-space techniques and mipmaps are suitable for the rendering pipeline.
*   **Link:** [Silhouette Image Space Acceleration Structure (Mip Pyramid)](3731-silhouette-image-space-acceleration-structure-mip-pyramid.md)
