# Hierarchical Spatial Enumeration Optimization

Also called: Complete octree representation, Heirarchical Spatial Enumeration, Hierarchical Spatial Enumeration (Octree Pyramid), Pyramid Enumeration, Pyramid of binary volumes

## Overview
Hierarchical Spatial Enumeration Optimization is an acceleration technique for image-order volume rendering that encodes spatial coherence (empty regions) using a pyramid of binary volumes [S1][S2, S3, unofficial]. It solves the problem of inefficiently traversing sparse volumetric data by allowing rays to skip large empty regions in logarithmic time relative to the ray length [S2, S3, unofficial]. Unlike condensed octree representations that store pointers or variable-length codes, this method uses a complete octree structure mapped to fixed-size binary volumes, which simplifies memory access patterns and avoids pointer chasing [S1].

## How it works
**Inputs:** A volumetric dataset of size $N \times N \times N$ voxels, where $N = 2^M + 1$ for some integer $M \ge 0$. The dataset consists of scalar opacity values $\alpha(\mathbf{v})$ for each voxel $\mathbf{v}$.
**Outputs:** A pyramid of $M+1$ binary volumes $V_m$, where $V_m(\mathbf{i}) \in \{0, 1\}$ indicates whether the region covered by cell $\mathbf{i}$ at level $m$ contains any non-zero opacity.

### Data Structures
The core data structure is a pyramid of $M+1$ 3D arrays (binary volumes).
- **Level $m$ Volume ($V_m$):** A 3D array of size $C_m \times C_m \times C_m$, where $C_m = (N-1)/2^m$.
- **Indexing:** Cells are indexed by $\mathbf{i} = (i, j, k)$ where $1 \le i, j, k \le C_m$.
- **Value:** $V_m(\mathbf{i}) = 1$ if the cell is occupied (contains at least one non-zero opacity voxel); $V_m(\mathbf{i}) = 0$ if the cell is empty (all constituent voxels have zero opacity).
- **Memory Layout:** The volumes are stored as contiguous arrays. The total memory is $\sum_{m=0}^{M} ((N-1)/2^m)^3$ bits (or bytes, depending on implementation).

### Construction Algorithm
The pyramid is constructed bottom-up from the base volume $V_0$ to the top volume $V_M$.

1.  **Base Volume ($V_0$) Construction:**
    For each cell $\mathbf{i} = (i, j, k)$ in $V_0$ (where $1 \le i, j, k \le N-1$):
    -   The cell $\mathbf{i}$ in $V_0$ corresponds to the space between voxels $\mathbf{i}$ and $\mathbf{i} + (1,1,1)$.
    -   Specifically, cell $\mathbf{i}$ encloses the 8 voxels at its vertices: $\{\mathbf{i} + \Delta\mathbf{i} \mid \Delta\mathbf{i} \in \{0, 1\}^3\}$.
    -   Set $V_0(\mathbf{i}) = 1$ if $\alpha(\mathbf{v}) > 0$ for any $\mathbf{v}$ in the set of 8 vertices.
    -   Set $V_0(\mathbf{i}) = 0$ if $\alpha(\mathbf{v}) = 0$ for all 8 vertices.
    -   Formula:
        $$
        V_0(\mathbf{i}) = \max_{\Delta\mathbf{i} \in \{0,1\}^3} \alpha(\mathbf{i} + \Delta\mathbf{i}) > 0
        $$

2.  **Recursive Construction ($m > 0$):**
    For each level $m$ from $1$ to $M$:
    -   For each cell $\mathbf{i} = (i, j, k)$ in $V_m$ (where $1 \le i, j, k \le C_m$):
    -   The cell $\mathbf{i}$ in $V_m$ is the parent of 8 cells in $V_{m-1}$. These 8 children correspond to the octants of the current cell.
    -   The indices of the 8 children in $V_{m-1}$ are determined by expanding the current index. Let $\mathbf{c}_{m-1}$ be the base index of the children in $V_{m-1}$. The children are $\mathbf{c}_{m-1} + \Delta\mathbf{i}$ for $\Delta\mathbf{i} \in \{0, 1\}^3$, where $\mathbf{c}_{m-1} = 2 \cdot (\mathbf{i} - 1) + 1$.
    -   Set $V_m(\mathbf{i}) = 1$ if $V_{m-1}(\mathbf{child}) = 1$ for any child.
    -   Set $V_m(\mathbf{i}) = 0$ if $V_{m-1}(\mathbf{child}) = 0$ for all 8 children.
    -   Formula:
        $$
        V_m(\mathbf{i}) = \max_{\Delta\mathbf{i} \in \{0,1\}^3} V_{m-1}(2(\mathbf{i}-1) + 1 + \Delta\mathbf{i}) > 0
        $$

### Traversal Algorithm
For each pixel in the image, a viewing ray is cast. The ray is parameterized by $t$, starting from the near plane.

1.  **Initialization:**
    -   Compute the entry point of the ray into the top-level cell $V_M$. Since $V_M$ is a single cell, the ray starts at the beginning of the dataset.
    -   Set current level $m = M$.
    -   Set current cell index $\mathbf{i}_M = (1, 1, 1)$.

2.  **Pyramid Traversal Loop:**
    While $m \ge 0$:
    -   **Check Occupancy:**
        -   If $V_m(\mathbf{i}_m) == 0$:
            -   The current cell is empty.
            -   Advance the ray to the exit of the current cell.
            -   Determine the next cell $\mathbf{i}'_m$ on the same level $m$ that the ray enters.
            -   If the parent of $\mathbf{i}'_m$ is different from the parent of $\mathbf{i}_m$:
                -   Move up to the parent level: $m \leftarrow m - 1$.
                -   Set $\mathbf{i}_m$ to the parent of $\mathbf{i}'_m$.
                -   Repeat the check for the new parent.
            -   Else:
                -   Set $\mathbf{i}_m \leftarrow \mathbf{i}'_m$.
                -   Continue loop.
        -   If $V_m(\mathbf{i}_m) == 1$:
            -   The current cell is occupied.
            -   If $m == 0$:
                -   **Leaf Handling:** The ray is within a base cell containing non-zero opacity.
                -   Draw samples at evenly spaced locations along the ray segment within this cell.
                -   Resample the volume data at these locations (e.g., trilinear interpolation).
                -   Composite color and opacity into the ray state (front-to-back compositing).
                -   Advance the ray to the exit of the cell.
                -   Determine the next cell $\mathbf{i}'_0$.
                -   If the parent of $\mathbf{i}'_0$ differs from the parent of $\mathbf{i}_0$:
                    -   Move up to parent: $m \leftarrow m - 1$.
                    -   Set $\mathbf{i}_m$ to the parent of $\mathbf{i}'_0$.
                -   Else:
                    -   Set $\mathbf{i}_0 \leftarrow \mathbf{i}'_0$.
            -   Else ($m > 0$):
                -   Move down one level: $m \leftarrow m - 1$.
                -   Determine the child cell $\mathbf{i}_{m}$ in $V_m$ that encloses the current ray position.
                -   Set $\mathbf{i}_m$ to this child index.
                -   Continue loop.

3.  **Termination:**
    -   The ray traversal ends when the ray exits the dataset or when an adaptive termination criterion is met (e.g., accumulated opacity exceeds a threshold).

### Parameters
-   $M$: Integer such that dataset side length $N = 2^M + 1$.
-   Cell Size: The size of cells on level $m$ is $2^m$ times the spacing between voxels.
-   Opacity Threshold: For adaptive termination, a threshold $\epsilon$ for accumulated opacity.

### Edge Cases and Pitfalls
-   **Coordinate Alignment:** Voxel $(1,1,1)$ is placed at the front-lower-right corner of cell $(1,1,1)$ on level 0. Cell $(1,1,1)$ on level 0 encloses the space between voxels $(1,1,1)$ and $(2,2,2)$. Care must be taken to map ray coordinates to cell indices correctly [S1].
-   **Dataset Size:** The method requires $N = 2^M + 1$. If the dataset size does not fit this form, padding or cropping may be necessary [S1].
-   **Precision:** Floating-point precision in ray-cell intersection calculations can lead to errors in cell selection, especially at boundaries. Robust geometric predicates should be used [G].

## Subtopics

### [Hierarchical Volume Traversal with Adaptive Termination](1682-hierarchical-volume-traversal-with-adaptive-termination.md)
Hierarchical Volume Traversal with Adaptive Termination is a ray tracing algorithm that uses a pyramidal data structure of binary volumes to skip empty regions and an adaptive termination criterion to stop tracing when accumulated opacity exceeds a threshold. Unlike geometric ray tracing, which uses bounding volumes or spatial subdivision with lists of primitives, this method uses a hierarchical binary volume structure, which is more efficient for volume data because volume datasets have tens of millions of spatially ordered cells with single samples, whereas geometric scenes have hundreds of cells with many primitives.

### Hierarchical Opacity Enumeration
An optimization that uses a binary octree to avoid unnecessary resampling of voxels in transparent regions of the volume [S4].

### Flat Pyramid
A hierarchical spatial data structure (quadtree recursively subdivided down to pixel size) where empty space uniformity information is stored in the empty voxels of the 3D volume grid [S5, unofficial]. The structure is a quadtree recursively subdivided down until pixel size. Gray squares denote voxels with volume data; white squares denote empty voxels storing the octree level [S5, unofficial].

## Operating characteristics
-   **Time Complexity:** The cost of ray tracing grows linearly with the size of the image, logarithmically with the length of each ray, and linearly with the depth complexity of the data [S2, unofficial].
-   **Memory Complexity:** The pyramid requires $O(N^3)$ bits, specifically $\sum_{m=0}^{M} ((N-1)/2^m)^3$ bits. This is slightly more than the raw voxel data but allows for fast traversal without pointer chasing.
-   **Strengths:** Efficiently skips large empty regions, leading to significant speedups for sparse data. The fixed-size binary volumes simplify memory access and can be optimized for cache performance.
-   **Limitations:** Requires the dataset size to be of the form $2^M + 1$. The construction of the pyramid takes $O(N^3)$ time, which may be a bottleneck for very large datasets if not done efficiently.
-   **When to Use:** Ideal for sparse volumetric data with large empty regions, such as medical imaging or molecular graphics [S1].
-   **When Not to Use:** For dense volumetric data where most voxels are occupied, the overhead of traversal may not justify the benefits.

## Background
The method was introduced by Marc Levoy in 1990 in the paper "Efficient ray tracing of volume data" [S1]. It is based on the observation that many volumetric datasets contain coherent regions of uninteresting voxels (opacity zero) [S2, unofficial]. The technique was developed to improve the performance of image-order volume rendering algorithms, which were previously limited by the linear growth of rendering time with dataset size [S1]. The method has been used in applications such as medical imaging and molecular graphics [S1].
