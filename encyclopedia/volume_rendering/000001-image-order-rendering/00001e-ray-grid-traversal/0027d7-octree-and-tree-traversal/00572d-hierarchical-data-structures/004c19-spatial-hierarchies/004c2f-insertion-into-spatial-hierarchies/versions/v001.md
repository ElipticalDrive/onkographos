# Insertion into Spatial Hierarchies

Also called: Incremental Insertion, Dynamic Insertion

## Overview
Insertion into spatial hierarchies refers to the algorithmic process of adding primitives (such as triangles or voxels) into an existing or growing hierarchical data structure, such as an octree or bounding volume hierarchy (BVH). It solves the problem of maintaining spatial coherence and query efficiency in dynamic scenes or when building structures from unsorted data. Unlike static build methods that analyze the entire scene at once, insertion methods process primitives one by one, allowing for incremental updates. The primary distinction from sibling methods like Median-Cut or Surface Area Heuristic (SAH) builds is that insertion does not require a full re-sorting or re-partitioning of the dataset, making it suitable for dynamic environments, though it is highly sensitive to the order of insertion [S1, S2, unofficial].

## How it works
The method varies significantly depending on the specific insertion strategy (e.g., recursive subdivision vs. iterative sifting). Below are the two primary approaches documented in the sources.

### Recursive Subdivision (Octree-style)
This approach is typical for octrees where nodes are subdivided based on a primitive count threshold.

**Inputs and Outputs:**
- Input: A node in the hierarchy, a primitive (e.g., bounding box or triangle).
- Output: The modified hierarchy with the primitive added.

**Data Structures:**
- `node`: Contains a bounding volume (`bound`), a list of primitives (`prims`), a count of primitives (`nprims`), a depth level (`depth`), and child pointers.
- `leaf(node)`: A boolean check returning true if the node has no children.

**Parameters:**
- `MAXDEPTH`: The maximum allowed depth of the tree. Typical value: 16 [S1, unofficial].
- `MAXPRIMS`: The maximum number of primitives allowed in a leaf before subdivision. Typical range: 2 to 8 [S1, unofficial].

**Steps:**
1. Check if the primitive overlaps with the current node's bounding volume. If not, terminate.
2. If the node is a leaf:
   - If `nprims` exceeds `MAXPRIMS` AND `depth` is less than `MAXDEPTH`:
     - Subdivide the node into children.
     - Recursively insert the primitive into all children that overlap it.
   - Else:
     - Append the primitive to the node's primitive list.
3. If the node is not a leaf:
   - Recursively insert the primitive into all children that overlap it.

**Pseudocode:**
```python
def insert_recursive(node, primitive):
    # Check overlap between primitive and node bounding volume
    if not overlap(node.bound, primitive):
        return

    if is_leaf(node):
        # Leaf node logic
        if node.nprims > MAXPRIMS and node.depth < MAXDEPTH:
            # Subdivide if capacity exceeded and depth limit not reached
            subdivide(node)
            for child in node.children:
                insert_recursive(child, primitive)
        else:
            # Add to leaf list
            node.prims.append(primitive)
            node.nprims += 1
    else:
        # Internal node logic
        for child in node.children:
            insert_recursive(child, primitive)
```

### Iterative Insert (Goldsmith-Salmon BVH)
This method builds a BVH by sifting primitives down to leaves, potentially restructuring the tree dynamically.

**Inputs and Outputs:**
- Input: An existing BVH (initially an empty root), a new primitive.
- Output: The updated BVH.

**Steps:**
1. Start with an empty root node.
2. For each new primitive:
   - Let the primitive "sift" from the root towards the leaves.
   - At each internal node, decide whether to:
     - Attach the primitive to the current internal node's list.
     - Pass the primitive to the left or right child subtree.
   - If the primitive arrives at a leaf node:
     - Replace the leaf with an internal node.
     - Attach the existing primitive (from the leaf) and the new primitive as children of this new internal node.
   - During sifting, update the bounding volumes of intermediate nodes to encompass the new primitive if necessary.

**Pitfalls:**
- The order of insertion has a very large influence on the quality of the resulting tree [S2, unofficial]. Poor ordering can lead to unbalanced trees with poor traversal performance.

## Subtopics

### Iterative Insert
A dynamic insertion method introduced by Goldsmith and Salmon in 1987 [S2, unofficial]. It differs from static builds by inserting primitives one by one, sifting them to the bottom of the BVH. If a leaf is reached, it is split into an internal node with the old and new primitives as children. It is chosen for incremental scene updates or when the dataset is not available all at once. Its main limitation is sensitivity to insertion order, which affects tree balance and quality [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Insertion of a single primitive is $O(D)$ where $D$ is the depth of the tree, assuming constant-time overlap tests. However, frequent subdivisions and bounding volume updates can add overhead.
- **Memory Complexity:** Depends on the number of primitives and the tree depth. Dynamic splitting increases node count.
- **Performance:** Performance is highly dependent on the insertion order. Experiments show that sorted insertion or specific shuffling can significantly reduce the number of intersection tests per ray compared to random or model-load order [S2, unofficial].
- **Strengths:** Supports dynamic scenes; no need to rebuild the entire tree for new objects.
- **Limitations:** Tree quality degrades with poor insertion order; may require periodic rebalancing or rebuilding for optimal performance.

## Background
The concept of inserting primitives into spatial hierarchies is fundamental to dynamic ray tracing and collision detection. The recursive subdivision approach is common in octree implementations for volume rendering and voxel data [S1, unofficial]. The Iterative Insert method was specifically introduced by Goldsmith and Salmon in 1987 for building BVHs incrementally [S2, unofficial]. It was designed to handle scenes where objects are added or removed over time, avoiding the cost of full rebuilds.
