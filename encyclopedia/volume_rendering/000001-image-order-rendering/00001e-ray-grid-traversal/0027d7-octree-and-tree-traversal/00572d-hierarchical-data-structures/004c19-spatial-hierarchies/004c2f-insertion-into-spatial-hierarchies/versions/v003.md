# Insertion into Spatial Hierarchies
## Overview
Insertion into spatial hierarchies incrementally adds primitives to a hierarchical data structure, processing them one by one rather than analyzing the full scene at once [S1, unofficial]. This approach supports dynamic updates and unsorted data ingestion but produces tree quality that depends heavily on the insertion order [S2, unofficial]. It differs from static partitioning methods like Median-Cut or Surface Area Heuristic (SAH) by avoiding full dataset re-sorting [S1, unofficial].

## How it works
**Inputs and Outputs:** Input is a hierarchy node and a primitive (e.g., triangle or bounding box) [S1, unofficial]. Output is the modified hierarchy with the primitive integrated [S1, unofficial].

**Data Structures:** Each `node` stores a bounding volume (`bound`), a list of primitives (`prims`), a primitive count (`nprims`), a depth level (`depth`), and child pointers (`children`) [S1, unofficial]. A node is a leaf if `children` is empty [G].

**Parameters:** `MAXDEPTH` limits tree depth, typically 16 [S1, unofficial]. `MAXPRIMS` caps primitives per leaf before subdivision, typically 2 to 8 [S1, unofficial].

**Steps:**
1. Test primitive overlap with `node.bound`. If no overlap, terminate [S1, unofficial].
2. If `node` is a leaf:
   - If `nprims > MAXPRIMS` and `depth < MAXDEPTH`: subdivide `node`, then recursively insert the primitive into all children [S1, unofficial].
   - Otherwise: append the primitive to `node.prims` and increment `nprims` [S1, unofficial].
3. If `node` is internal: recursively insert the primitive into all children [S1, unofficial].

**Pseudocode:**
```python
class Node:
    def __init__(self):
        self.bound = AABB()
        self.prims = []
        self.nprims = 0
        self.depth = 0
        self.children = []

def insert(node, primitive):
    if not overlap(node.bound, primitive):
        return
    if is_leaf(node):
        if node.nprims > MAXPRIMS and node.depth < MAXDEPTH:
            subdivide(node)
            for child in node.children:
                insert(child, primitive)
        else:
            node.prims.append(primitive)
            node.nprims += 1
    else:
        for child in node.children:
            insert(child, primitive)

def is_leaf(node):
    return len(node.children) == 0

def overlap(a, b):
    return a.min.x <= b.max.x and a.max.x >= b.min.x and \
           a.min.y <= b.max.y and a.max.y >= b.min.y and \
           a.min.z <= b.max.z and a.max.z >= b.min.z

def subdivide(node):
    node.children = [Node() for _ in range(8)]  # Octree split [G]
```

**Edge cases and pitfalls:** Zero-size primitives or degenerate bounds require explicit overlap checks to avoid false negatives [G]. Depth limits prevent infinite recursion on tightly packed scenes [S1, unofficial].

## Subtopics

### Iterative Insert
Initialize an empty root node [S2, unofficial]. Iteratively insert one triangle after another into the BVH, possibly extending it [S2, unofficial]. Let the triangle sift to the bottom of the BVH, potentially enlarging the BV of intermediate nodes [S2, unofficial]. If the triangle arrives at a leaf, replace the leaf with an internal node and attach the new and old triangles as its children [S2, unofficial]. If at an internal node, decide to attach the triangle to the current internal node, or let it sift into the left/right subtree [S2, unofficial]. The order in which objects are inserted has a very large influence on the quality of the tree [S2, unofficial].

### BSP Tree Construction
A spatial partitioning structure built from a mesh to enable fast point queries or collision detection [S3, unofficial]. It visualizes splitting disks at each node and uses a configurable depth parameter, typically set to 14 [S3, unofficial]. Input requires mesh vertices and triangles, with optional `diskMaterial`, `visitedDiskMaterial`, and `drawNaiveClosestPoint` for debug visualization [S3, unofficial]. Construction initializes `binarySpacePartition = new BSP(mesh, 14)` and computes splitting disk matrices using the average position, plane rotation, and scaled radius [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(D)$ per insertion, where $D$ is tree depth, assuming constant-time overlap tests [G]. Frequent subdivisions and bounding volume updates add overhead [G].
- **Memory Complexity:** $O(N + C)$, where $N$ is primitive count and $C$ is node count from dynamic splitting [G].
- **Performance:** Highly dependent on insertion order. Sorted or shuffled insertion orders significantly reduce intersection tests per ray compared to model-load order [S2, unofficial].
- **Strengths:** Supports dynamic scenes without full rebuilds; handles unsorted data naturally [S1, unofficial].
- **Limitations:** Tree quality degrades with poor ordering; may require periodic rebalancing [S2, unofficial].

## Background
The recursive subdivision approach is standard in octree implementations for spatial partitioning [S1, unofficial]. The Iterative Insert method was introduced by Goldsmith and Salmon in 1987 for incremental BVH construction [S2, unofficial]. BSP tree construction provides an alternative mesh-based partitioning strategy for collision detection and point queries [S3, unofficial].
