# Octree with Neighbor Pointers

Also called: Neighbour Pointers (Ropes), Octree Construction with X-Neighbor Pointers, Octree with neighbors structure, Rope Trees, Ropes, Spatial index with neighbor information

## Overview
A spatial index structure that augments a branch-on-need octree with links to allow direct traversal to adjacent nodes, used to accelerate ray traversal in volume rendering [S2]. It differs from full 26-neighbor structures by maintaining only x-neighbor pointers, reducing memory overhead while enabling efficient skipping of empty space and boundary crossing [S1, unofficial].

## How it works
**Inputs:** A view-dependent branch-on-need octree [S2].
**Outputs:** A 3D texture acting as a spatial index, encoded with tagged pointers and neighbor links [S2].

**Data Structures:**
The structure is encoded into an 8-bit RGBA 3D texture [S2]. Each octree node is encoded in 8 consecutive texels arranged in the x-direction [S2]. The layout uses a tagged pointer scheme where the Alpha (A) component determines the node kind:
*   $A=1.0$: Inner node.
*   $A=0.5$: Data node (leaf with data).
*   $A=0.0$: Empty node [S2].

**Inner Node Layout:**
The RGB components point to the first of 8 children, which are arranged consecutively in the x-direction [S2].

**Leaf Node Layout:**
The RGB components point to leaf info, consisting of:
1.  A data pointer (if not empty).
2.  6 consecutive texels storing neighbor pointers for the 6 faces [S2].
The last leaf data texel contains a `None` pointer [S2]. Neighbor pointers use their A value to encode the octree level of the neighbor [S2].

**Construction Steps:**
1.  **Top-Level Initialization:** Create all nodes at the top level $n$ (typically two levels below the root to speed up traversal) and establish x-neighbor pointers for all adjacent nodes at this level [S1, unofficial].
2.  **Pointer Propagation:** Propagate x-neighbor pointers from nodes in level $i$ to their child nodes in level $i-1$. Specifically, link adjacent level-$(i-1)$ nodes that have different parent nodes [S1, unofficial].
3.  **Texture Encoding:** Encode the resulting structure into a 3D texture [S2].

**Edge Cases:**
*   **Boundary Nodes:** Neighbor pointers link to the smallest node enclosing all adjacent nodes if there are multiple ones [S2].
*   **Depth Limit:** Traversal stops before reaching a single root node at the top level to optimize performance [S1, unofficial].

## Subtopics

### Tree Graph Gp and Neighbor Graph G3
A variant that replaces explicit neighbor pointers with a primal tree graph $G_p$ and a neighbor graph $G_3$ to accelerate ray traversal. $G_p$ stores only parent and first-child indices per cell, relying on consecutive child numbering, while $G_3$ precomputes three immediate neighbors per cell to avoid expensive tree traversals. It sets itself apart by reducing memory overhead compared to full neighbor storage, making it suitable for high-depth trees where neighbor distance in $G_p$ alone can exceed 48 steps. Choose this structure when memory bandwidth is constrained and tree depth is high. See [Tree Graph Gp and Neighbor Graph G3](11339-tree-graph-gp-and-neighbor-graph-g3.md).

## Operating characteristics
*   **Memory:** Memory requirement increases by ~6x [S1, unofficial]. The structure uses a 3D texture with 8-bit RGBA components where each node occupies 8 texels, potentially addressing $16 \times M$ nodes [S2].
*   **Performance:** Traversal complexity drops to ~ O(log_x(n)) [S1, unofficial]. Enables direct jumps to object space neighbours without backtrack or parent pointers [S1, unofficial]. On-the-fly construction at each frame allows for view-dependent optimization [S2].
*   **Strengths and Limitations:** Accelerates ray casting by providing direct access to adjacent nodes, avoiding backtracking [S2]. Differs from Zhou et al. [2010] by storing different payload (mesh vs point cloud) and maintaining only x-neighbor pointers instead of pointers to all 26 neighbors [S1, unofficial].
*   **When to use:** Use when accelerating ray traversal in volume rendering and memory overhead must be balanced against traversal speed [S2]. Avoid when full 26-neighbor connectivity is strictly required or when on-the-fly texture updates are too costly for the target hardware [S2].

## Background
Introduced by Popov (2007) and Gobbetti et al. (2008) in the context of GPU-based volume rendering and voxelization [S1, unofficial][S2]. The structure is based on rope trees [HBZ98] and shares similarities with bottom-up breadth-first construction using Morton ordering [S1, unofficial]. It is used to accelerate ray casting by providing direct access to adjacent nodes, avoiding backtracking [S2].
