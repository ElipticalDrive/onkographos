# Octree with Neighbor Pointers

Also called: Octree Construction with X-Neighbor Pointers, Octree with neighbors structure

## Overview
This method augments a branch-on-need octree with explicit links to adjacent nodes, enabling direct traversal to neighboring spatial regions without ascending the parent hierarchy [S2]. It solves the latency penalty of recursive ascent in sparse octrees by allowing rays to jump horizontally across node boundaries [S1]. Unlike structures that maintain full 26-neighbor connectivity, this variant restricts pointers to the X-axis, distinguishing it from comprehensive adjacency graphs [S1].

## How it works
The method constructs a spatial index on-the-fly from a view-dependent octree and encodes it into a 3D texture for GPU traversal [S2].

### Inputs and Outputs
*   **Input:** A view-dependent branch-on-need octree representing the volume or surface data [S2].
*   **Output:** A 3D RGBA texture acting as the spatial index, where each node is encoded in 8 consecutive texels arranged in the X direction [S2].

### Data Structures
The spatial index is a 3D texture with 8-bit RGBA components [S2]. Each octree node occupies 8 consecutive texels along the X-axis [S2].

**Tagged Pointer Layout (per texel):**
*   **RGB:** Pointer information [S2].
*   **A (Alpha):** Node kind tag [S2].
    *   $A = 1.0$: Inner node (non-leaf) [S2].
    *   $A = 0.5$: Data node (leaf with data) [S2].
    *   $A = 0.0$: Empty node [S2].

**Inner Node Encoding:**
*   The RGB components of the first texel point to the first of 8 children, which are arranged consecutively in the X direction [S2].

**Leaf Node Encoding:**
*   The RGB components point to leaf info: a data pointer (if not empty) and 6 consecutive texels storing neighbor pointers for the 6 faces [S2].
*   The last leaf data texel contains a NULL pointer [S2].
*   Neighbor pointers use the A component to encode the octree level of the neighbor [S2].

### Construction Algorithm
The construction proceeds bottom-up in a breadth-first fashion [S1].

1.  Create all nodes at the top level $n$ (typically two levels below the root to speed up traversal) [S1].
2.  Establish X-neighbor pointers for all adjacent nodes at the top level $n$ [S1].
3.  Propagate X-neighbor pointers from nodes in level $i$ to their child nodes in level $i-1$ [S1].
    *   Specifically, link adjacent level-$(i-1)$ nodes that have different parent nodes [S1].
4.  Encode the resulting structure into a 3D texture [S2].
    *   Update the GPU texture using `glTexSubImage` [S2].

### Parameters
*   Top level $n$: Typically two levels below the root [S1].
*   Texture dimension $M$: Determines addressable capacity [S2].

### Edge Cases and Pitfalls
*   Boundary nodes require identifying the "smallest node enclosing all adjacent nodes" when a face spans multiple child nodes of a parent [S2].
*   The encoding supports addressing $16 \times M$ nodes or data blocks, where $M$ is the texture dimension [S2].
*   Maintaining only X-neighbor pointers reduces memory but may require fallback mechanisms for Y/Z traversal if not fully implemented for all axes [S1].

## Operating characteristics
*   **Time Complexity:** Construction is performed on-the-fly per frame directly from the view-dependent octree [S2]. Traversal is accelerated by direct neighbor jumps [S2].
*   **Memory Complexity:** The structure supports addressing $16 \times M$ nodes or data blocks, where $M$ is the texture dimension [S2].

## Background
The concept of augmenting octrees with neighbor pointers was introduced to accelerate ray traversal in volume rendering [S2]. The specific construction method using X-neighbor pointers and bottom-up propagation was detailed by Schwarz et al. in the context of fast parallel surface and solid voxelization [S1]. This approach differs from Zhou et al. [2010] by storing different payloads (mesh vs. point cloud) and maintaining only X-neighbor pointers instead of all 26 neighbors [S1].
