# Compositing Tree Rendering

Also called: Incremental Compositing, Modified subtree rendering, Partial image compositing, Selective Subtree Rendering

## Overview
Compositing Tree Rendering is a time-domain optimization for volume rendering that avoids re-rendering unchanged data by retaining and reusing partial images from previous frames [S1, S2, unofficial]. It solves the high computational cost of rendering time-varying volume data by identifying modified subtrees in a compressed octree and composing their new partial images with the retained partial images of unmodified subtrees to form the final image [S1, S2, unofficial]. Unlike sibling methods that may use entropy metrics to guide traversal, this method relies on structural change detection to splice new branches into a persistent compositing tree, making it distinct from [Octree-based Entropy Rendering](13580-octree-based-entropy-rendering.md) [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of compressed octree structures representing time-varying volume data [S1, S2, unofficial]. The first tree is rendered completely; subsequent inputs are trees where modified regions are identified [S1, S2, unofficial].
*   **Output:** A final composite image for the current time step [S1, S2, unofficial].

**Data Structures:**
*   **Compositing Tree:** A pointer-based octree that mirrors the structure of the compressed octree [S1, S2, unofficial].
    *   **Leaves:** Each leaf node contains a partial image (color and opacity buffer) rendered directly from the corresponding leaf in the compressed tree [S1, S2, unofficial].
    *   **Interior Nodes:** Each interior node contains a partial image which is the result of compositing the images of all its children [S1, S2, unofficial].
    *   **Root:** The image at the root of the compositing tree represents the complete final image [S1, S2, unofficial].

**Algorithm Steps:**
1.  **Initial Render:** Render the first compressed octree completely [S1, S2, unofficial]. Populate the Compositing Tree with partial images at all levels, starting from the leaves up to the root [S1, S2, unofficial].
2.  **Change Detection:** For subsequent time steps, identify the modified subtrees within the new compressed octree [S1, S2, unofficial].
3.  **Branch Creation:** Create a new compositing branch representing the modified data [S1, S2, unofficial]. This involves rendering the modified leaves and compositing them up to the new branch's root [S1, S2, unofficial].
4.  **Splicing:** Splice the new compositing branch into the existing Compositing Tree, replacing the old branch corresponding to the modified region [S1, S2, unofficial].
5.  **Recomposition:** Composite the image at the top of the new branch with its siblings [S1, S2, unofficial]. Recomposite all ancestors of the splice point up to the root to reflect the changes [S1, S2, unofficial].
6.  **Final Image:** The image at the root of the Compositing Tree is the complete image for the current time step [S1, S2, unofficial].

**Optimizations for Constant Subvolumes:**
When an octant (leaf) represents a subvolume with constant values, rendering is optimized by avoiding sample coordinate calculation and trilinear interpolation [S1, S2, unofficial].
*   **General Discretized Integral:** The accumulated color $C$ up to $n$ sample points is generally:
    $$ C = \sum_{i=1}^{n} C_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    where $C_i$ is the color and $\alpha_i$ is the opacity at sample $i$ [S1, S2, unofficial].
*   **Constant Subvolume Formula:** If all sample points have identical color $C$ and opacity $a$, the formula simplifies to a geometric series:
    $$ C_{total} = C \frac{1-(1-a)^n}{1-(1-a)} $$
    [S2, unofficial]. Both imply that only the number of samples $n$ is required [S1, S2, unofficial].

class ImageBuffer:
    def __init__(self, color, opacity):
        self.color = color
        self.opacity = opacity

class CompositingNode:
    def __init__(self):
        self.children = [None] * 8
        self.partial_image = None
        self.is_leaf = False
        self.compressed_data = None

class CompositingTreeRenderer:
    def __init__(self, compressed_tree_root):
        self.root = self._build_compositing_tree(compressed_tree_root)

    def _build_compositing_tree(self, node):
        comp_node = CompositingNode()
        if node.is_leaf:
            comp_node.is_leaf = True
            comp_node.compressed_data = node
        else:
            for i in range(8):
                if node.children[i] is not None:
                    comp_node.children[i] = self._build_compositing_tree(node.children[i])
        return comp_node

    def render_initial(self):
        self._render_node(self.root)

    def _render_node(self, comp_node):
        if comp_node.is_leaf:
            comp_node.partial_image = self._render_leaf(comp_node)
        else:
            for i in range(8):
                if comp_node.children[i] is not None:
                    self._render_node(comp_node.children[i])
            comp_node.partial_image = self._composite_children(comp_node)

    def _render_leaf(self, comp_node):
        n = comp_node.compressed_data.sample_count
        C = comp_node.compressed_data.constant_color
        a = comp_node.compressed_data.constant_opacity
        transmittance = (1 - a) ** n
        color = C * (1 - transmittance)
        opacity = 1 - transmittance
        return ImageBuffer(color, opacity)

    def _composite_children(self, node):
        result = ImageBuffer(0.0, 0.0)
        for child in node.children:
            if child is not None and child.partial_image is not None:
                result = self._blend(result, child.partial_image)
        return result

    def _blend(self, base, source):
        alpha_out = base.opacity + source.opacity * (1 - base.opacity)
        color_out = base.color + source.color * source.opacity * (1 - base.opacity)
        return ImageBuffer(color_out, alpha_out)

    def update(self, new_compressed_tree_root):

            parent = self._find_parent(node)

                self._recomposite_ancestors(parent)

**Edge Cases and Pitfalls:**
*   **Boundary Rendering:** Octree leaves represent uniform blocks, but boundaries between blocks must be rendered carefully [S1, S2, unofficial]. To avoid traversal overhead for boundary values, the original data is kept uncompressed, and the octree serves as a map into this volume data [S1, S2, unofficial].
*   **Viewing Position:** The optimization assumes a fixed viewing position [S1, S2, unofficial]. Changing the view requires rerendering the entire tree and creating a new compositing tree [S1, S2, unofficial].
*   **Temporal Navigation:** To allow random navigation through the temporal domain, complete trees must be saved at regular intervals [S1, S2, unofficial].
*   **Back Subtree Approximation:** Due to opacity accumulation obscuring back details in front-to-back rendering, subtrees representing the back portion of the data may not be completely sampled [S1, S2, unofficial]. As an approximation, unchanged subtrees are not re-rendered [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the amount of *modified* data rather than the total volume [S1, S2, unofficial]. Savings are significant when changes between time steps are localized [S1, S2, unofficial].
*   **Memory Complexity:** Requires storing the Compositing Tree, which holds partial images for all nodes [S1, S2, unofficial]. This is additional memory overhead compared to direct rendering [S1, S2, unofficial].
*   **Performance:** Rendering from the tree structure incurs overhead compared to direct volume data rendering [S1, S2, unofficial]. This is offset by optimizations like front-to-back rendering, caching ray coordinates in object space, and skipping transparent space [S1, S2, unofficial].
*   **Strengths:** Large savings in the time domain by rendering only modified data [S1, S2, unofficial]. Reduced data read time proportional to compression rate [S1, S2, unofficial].
*   **Limitations:** Fixed viewing position requirement [S1, S2, unofficial]. High memory usage for storing partial images [S1, S2, unofficial]. Overhead from tree traversal [S1, S2, unofficial].
*   **When to Use:** Time-varying volume data with localized changes and fixed viewpoints [G].
*   **When Not to Use:** Dynamic viewpoints or data with global changes [G].

## Background
Compositing Tree Rendering was introduced in the late 1990s as part of research into efficient encoding and rendering of time-varying volume data [S1, S2, unofficial]. It was applied to datasets such as Turbulent Vortex Flow, Thermal Convection, and Heart Modeling, demonstrating significant storage and rendering time savings [S1, S2, unofficial].
