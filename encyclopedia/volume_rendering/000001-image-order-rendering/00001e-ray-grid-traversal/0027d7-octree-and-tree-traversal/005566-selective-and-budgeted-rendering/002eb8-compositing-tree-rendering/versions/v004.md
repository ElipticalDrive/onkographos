# Compositing Tree Rendering

Also called: Incremental Compositing, Modified subtree rendering, Partial image compositing, Selective Subtree Rendering

## Overview
Compositing Tree Rendering is a time-varying volume rendering strategy that avoids re-rendering unmodified data by retaining partial images of static subtrees and incrementally compositing them with newly rendered partial images from modified regions [S1, S2, unofficial]. It differs from standard incremental rendering by maintaining a persistent pointer-based octree structure (the compositing tree) that mirrors the data compression structure, allowing for efficient splicing of new branches and recomposition of ancestors, whereas methods like [Octree-based Entropy Rendering](13580-octree-based-entropy-rendering.md) focus on spatial resolution adaptation rather than temporal delta-compositing.

## How it works
**Inputs and Outputs:**
*   **Input:** A sequence of compressed octrees representing time-varying volume data. The first tree is the initial state; subsequent trees represent changes (deltas) or full states where modifications are identified.
*   **Output:** A final image for each time step, constructed from the root of the compositing tree.

**Data Structures:**
1.  **Compositing Tree:** A pointer-based octree with the exact same hierarchical structure as the compressed data octree [S1, S2, unofficial].
    *   **Interior Nodes:** Contain a "partial image" which is the result of compositing the images of all its children.
    *   **Leaves:** Contain a "partial image" rendered directly from the volume data represented by the corresponding leaf in the compressed octree.
2.  **Partial Image:** A 2D image buffer (typically RGBA) corresponding to the pixel coverage of the subtree's bounding box projected onto the image plane.

**Algorithm Steps:**

1.  **Initialization (Time Step 0):**
    *   Render the first compressed octree completely using ray casting.
    *   Populate the Compositing Tree:
        *   For each leaf in the compressed octree, render the corresponding subvolume and store the result in the leaf's partial image.
        *   For each interior node, composite the partial images of its children (using front-to-back compositing) and store the result in the node's partial image.
    *   The image at the root of the Compositing Tree is the final image for Time Step 0.

2.  **Update (Time Step $t > 0$):**
    *   **Identify Modifications:** Compare the current compressed octree with the previous one to identify modified subtrees. [S1, S2, unofficial]
    *   **Create New Branch:** For each modified subtree, create a new branch in the Compositing Tree. This involves rendering the modified data.
        *   Render the leaves of the modified subtrees.
        *   Composite the results up to the root of the new branch.
    *   **Splice:** Replace the old branch in the Compositing Tree with the new branch.
    *   **Recompose Ancestors:** Starting from the parent of the spliced branch, recompute the partial image for each ancestor node by compositing its children's partial images (including the new branch and unchanged siblings).
    *   **Final Image:** The image at the root of the Compositing Tree is the final image for Time Step $t$.

**Optimizations for Constant Subvolumes:**
When an octree leaf represents a uniform block (constant value), rendering is optimized by avoiding sample coordinate calculation and trilinear interpolation [S1, S2, unofficial].

*   **General Discretized Volume Rendering Integral:**
    The accumulated color $C$ up to $n$ sample points is:
    $$ C = \sum_{i=1}^{n} C_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
    Where $C_i$ is the color and $\alpha_i$ is the opacity at sample $i$ [S1, S2, unofficial].

*   **Simplified Formula for Constant Subvolume:**
    If all samples have identical color $C$ and opacity $\alpha$ (or $a$), the sum simplifies to a geometric series:
    $$ C_{total} = C \alpha \frac{1 - (1 - \alpha)^{n-1}}{1 - (1 - \alpha)} = C \frac{1 - (1 - \alpha)^n}{1 - (1 - \alpha)} $$
    *(Note: Sources [S1, unofficial] and [S2, unofficial] provide slightly different notations for the exponent, but both derive from the geometric series sum for $n$ samples. [S1, unofficial] uses $n-1$ in the exponent for the term $(1-\alpha)$, while [S2, unofficial] uses $n$. Given the standard front-to-back accumulation for $n$ samples with constant $\alpha$, the transmittance after $n$ samples is $(1-\alpha)^n$. The accumulated color is $C \sum_{i=1}^n \alpha (1-\alpha)^{i-1} = C \frac{1-(1-\alpha)^n}{1-(1-\alpha)}$. We use the form consistent with $n$ samples.)*
    
    Only the number of samples $n$ along the ray is required.

**Pseudocode:**

```python
def render_time_step(compositing_tree, compressed_tree, time_step):
    """
    Renders a time step by updating the compositing tree.
    """
    if time_step == 0:
        # Initial full render
        render_subtree(compositing_tree.root, compressed_tree.root)
        return compositing_tree.root.image

    # Identify modified subtrees
    modified_nodes = identify_modifications(compositing_tree, compressed_tree)
    
    # Create new branches for modified subtrees
    for node in modified_nodes:
        new_branch = create_new_branch(compositing_tree, node)
        render_subtree(new_branch, node)
        splice_into_tree(compositing_tree, node, new_branch)
        
    # Recompose ancestors
    recompute_ancestors(compositing_tree, modified_nodes)
    
    return compositing_tree.root.image

def render_subtree(compositing_node, compressed_node):
    """
    Renders a subtree. If leaf, render data. If interior, render children then composite.
    """
    if compressed_node.is_leaf():
        # Check if constant subvolume
        if compressed_node.is_constant():
            # Optimization: Use simplified formula
            n = compressed_node.sample_count
            C = compressed_node.constant_color
            alpha = compressed_node.constant_opacity
            compositing_node.image = constant_composite(C, alpha, n)
        else:
            # Standard ray casting for this leaf's region
            compositing_node.image = ray_cast(compressed_node)
    else:
        # Render children
        for i in range(8):
            if compressed_node.children[i] is not None:
                render_subtree(compositing_node.children[i], compressed_node.children[i])
        
        # Composite children images
        compositing_node.image = composite_children(compositing_node.children)

def constant_composite(C, alpha, n):
    """
    Computes color for a constant subvolume with n samples.
    Formula: C * (1 - (1-alpha)^n) / alpha
    """
    if alpha == 0:
        return (0, 0, 0, 0)
    transmittance = (1 - alpha) ** n
    accumulated_color = C * (1 - transmittance) / alpha
    return accumulated_color

def composite_children(children):
    """
    Front-to-back compositing of 8 child images.
    Assumes children are ordered back-to-front or are composited in correct order.
    """
    result = (0, 0, 0, 0) # Clear color
    transmittance = 1.0
    
    # Note: Order of children depends on octree convention and view direction.
    # Standard front-to-back requires processing from front to back.
    for child in children_ordered_front_to_back(children):
        if child.image is not None:
            c, a = child.image.color, child.image.opacity
            result = result + c * a * transmittance
            transmittance *= (1 - a)
            
    return result

def recompute_ancestors(compositing_tree, modified_nodes):
    """
    Recomputes partial images for all ancestors of modified nodes.
    """
    ancestors = set()
    for node in modified_nodes:
        current = node.parent
        while current is not None:
            ancestors.add(current)
            current = current.parent
            
    # Process in topological order (children before parents)
    for ancestor in sorted_ancestors_by_depth(ancestors):
        ancestor.image = composite_children(ancestor.children)
```

**Edge Cases and Pitfalls:**
*   **Boundary Rendering:** Octree leaves represent uniform blocks, but boundaries between blocks must be rendered carefully. To avoid traversal overhead for boundary values, the original data is kept uncompressed, and the octree serves as a map into this volume data [S1, S2, unofficial].
*   **Viewing Position:** The optimization assumes a fixed viewing position. Changing the view requires rerendering the entire tree and creating a new compositing tree [S1, S2, unofficial].
*   **Temporal Navigation:** To allow random temporal navigation, complete trees must be saved at regular intervals [S1, S2, unofficial].
*   **Back Subtree Approximation:** Due to opacity accumulation obscuring back details, subtrees representing the back portion of the data may not be completely sampled. As an approximation, unchanged subtrees are not re-rendered [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the amount of *modified* data, not the total volume. Savings are significant when changes between time steps are small [S1, S2, unofficial].
*   **Memory Complexity:** Requires storing the Compositing Tree, which holds partial images for all nodes. This is roughly equivalent to storing the full image for the entire volume at each time step if no changes occur, but allows reuse of static parts.
*   **Performance:** Rendering from the tree structure incurs overhead compared to direct volume data rendering. This is offset by optimizations like front-to-back rendering (early ray termination), caching ray coordinates in object space, and skipping transparent space [S1, S2, unofficial].
*   **Strengths:** Efficient for time-varying data with localized changes; reduces I/O by leveraging compression [S1, S2, unofficial].
*   **Limitations:** Inefficient for global view changes; requires significant memory to store partial images for the compositing tree; approximation errors may occur for obscured back regions [S1, S2, unofficial].

## Background
Compositing Tree Rendering was introduced in the context of efficient encoding and rendering of time-varying volume data. It leverages octree-based compression to identify modified regions and uses a compositing tree to incrementally update the rendered image. The method was implemented in the `tvvd-renderer` and tested on datasets such as Turbulent Vortex Flow, Thermal Convection, and Heart Modeling [S1, S2, unofficial].
