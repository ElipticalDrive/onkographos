# Tree Marcher

Also called: Tree Marcher for Generic Grids

## Overview
The Tree Marcher is a hierarchical ray traversal algorithm that steps a ray through a generic adaptive grid structure (such as an OpenVDB tree) to identify intersections with active nodes [S1, S2]. It solves the problem of efficiently locating the first or subsequent node boundaries along a ray without visiting every leaf cell, leveraging the tree's hierarchy to skip empty or inactive subtrees. It differs from its siblings, [Hermite Data Computation via Bisection](822-hermite-data-computation-via-bisection.md) and [Tetrahedralization of Octree Cells](9049-tetrahedralization-of-octree-cells.md), by operating at the node-boundary level rather than computing dual vertices or tetrahedral intersections directly; it provides the geometric intervals ($t_0, t_1$) and node pointers required for subsequent isosurface extraction or volume sampling [S1].

## How it works
The method implements a Digital Differential Analyzer (DDA) specialized for hierarchical data structures. It relies on the parent's empty-space skipping logic to traverse only relevant parts of the tree [Parent](15494-octree-based-isosurface-and-geometry-extraction.md).

### Inputs and Outputs
*   **Input:** An accessor object (`AccT`) providing access to the grid data; a ray definition (`RayT`) in index space.
*   **Output:** A pointer to the intersected node (`NodeT**`), and the parametric start (`t0`) and end (`t1`) of the intersection interval along the ray.

### Data Structures
The `TreeMarcher` is a class template with the following layout [S1]:
*   **Template Parameters:**
    *   `NodeT`: The node type being traversed.
    *   `RayT`: The ray type, containing position, direction, and inverse direction.
    *   `AccT`: The accessor type used for grid access.
    *   `CoordT`: The coordinate type (default `Coord`).
*   **Internal Typedefs:**
    *   `ChildT`: `typename NodeT::ChildNodeType`
    *   `RealType`: `typename RayT::RealType`
    *   `RealT`: Alias for `RealType`
    *   `CoordType`: Alias for `CoordT`

### Algorithm Steps
The traversal is controlled by two primary functions: `init` and `step` [S1].

1.  **Initialization:**
    *   Construct the `TreeMarcher` with the grid accessor: `TreeMarcher(AccT &acc)`.
    *   Call `init(const RayT &indexRay)` to initialize the internal state with the index-space ray. This sets up the DDA state for stepping through the grid coordinates [S1].

2.  **Stepping:**
    *   Call `step(const NodeT **node, float &t0, float &t1)`.
    *   The algorithm advances the ray through the tree hierarchy.
    *   If the ray intersects a node of type `NodeT`:
        *   Populate `*node` with a pointer to the intersected node.
        *   Populate `t0` with the start parameter of the intersection interval.
        *   Populate `t1` with the end parameter of the intersection interval.
        *   Return `true`.
    *   If the ray does not hit a node of type `NodeT` (e.g., it passes through empty space or hits a different node type):
        *   Return `false`.
    *   Repeat `step` until the ray exits the grid or a specific condition is met [S1].

### Parameters and Edge Cases
*   **Ray Type (`RayT`):** Must be defined in index space. The coordinates correspond to the grid's voxel corners or nodes, not world space [S1].
*   **Precision:** The method uses `float` for `t0` and `t1` [S1]. Precision issues may arise in deep trees or with very small intersection intervals.
*   **Empty Space:** The method relies on the underlying HDDA (Hierarchical DDA) to skip empty subtrees. If the grid has no active nodes along the ray, `step` will return `false` [S2].
*   **Node Type Matching:** The `step` function only returns `true` for nodes of the specific template type `NodeT`. If the ray passes through nodes of other types, it continues stepping [S1].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of active nodes intersected by the ray, logarithmic in the depth of the tree for traversal overhead. It skips empty regions, making it significantly faster than linear traversal for sparse data [S1, S2].
*   **Memory Complexity:** $O(1)$ auxiliary memory per ray, as the traversal state is contained within the `TreeMarcher` object and the ray structure [S1].
*   **Strengths:** Generic applicability to any grid type supported by the accessor; efficient empty-space skipping; low memory footprint.
*   **Limitations:** Requires the ray to be in index space; does not compute geometric primitives (vertices/edges) directly, only node intervals [S1].
*   **When to use:** When you need to traverse a hierarchical grid to find active regions or sample data at node boundaries, particularly in sparse volumes [S1].

## Background
The `TreeMarcher` class is part of the OpenVDB library, specifically within the `nanovdb` namespace, which provides a compact, cache-friendly representation of VDB grids for GPU and CPU rendering [S1, S2]. It was developed to support efficient ray tracing and volume rendering on adaptive grids by providing a generic interface for hierarchical traversal [S1]. The implementation relies on the `HDDA` (Hierarchical Digital Differential Analyzer) for the underlying stepping logic [S2].
