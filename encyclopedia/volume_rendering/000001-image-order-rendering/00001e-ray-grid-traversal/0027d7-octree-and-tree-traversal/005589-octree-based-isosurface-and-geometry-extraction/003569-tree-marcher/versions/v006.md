# Tree Marcher

Also called: Tree Marcher for Generic Grids

## Overview
The Tree Marcher is a hierarchical ray traversal algorithm that steps a ray through a sparse, hierarchical grid structure (such as an OpenVDB tree) to identify intersections with active nodes [S1, S2]. It differs from its siblings by operating directly on the tree topology using a Digital Differential Analyzer (DDA) to skip empty space, rather than converting the grid to a mesh or tetrahedral volume [S1, S2]. It serves as the core traversal engine for [Hermite Data Computation via Bisection](822-hermite-data-computation-via-bisection.md) and [Tetrahedralization of Octree Cells](9049-tetrahedralization-of-octree-cells.md).

## How it works
The Tree Marcher uses a hierarchical DDA (HDDA) to traverse the tree. It does not compute voxel-level intersections directly; instead, it identifies which nodes in the hierarchy the ray intersects and provides the parametric interval $[t_0, t_1]$ of that intersection [S1, S2].

**Inputs and Outputs:**
*   **Input:** An accessor (`AccT`) providing access to the grid data, and a ray (`RayT`) defined in index space.
*   **Output:** A pointer to the intersected node (`NodeT**`), and the intersection interval start (`t0`) and end (`t1`) in ray parameter space.

**Data Structures:**
The class is a template with the following parameters [S1]:
*   `NodeT`: The node type being traversed.
*   `RayT`: The ray type, containing direction, origin, and inverse direction components.
*   `AccT`: The accessor type for grid access.
*   `CoordT`: The coordinate type (default `Coord`).

Internal typedefs include `ChildT` (derived from `NodeT::ChildNodeType`), `RealType` (derived from `RayT::RealType`), and `CoordType` [S1].

**Algorithm Steps:**
1.  **Construction:** Initialize the `TreeMarcher` with a reference to the grid accessor `acc`. This binds the traverser to the specific grid structure [S1].
2.  **Initialization:** Call `init(indexRay)` with the ray in index space. This sets up the internal DDA state for the ray [S1].
3.  **Stepping:** Repeatedly call `step(&node, t0, t1)`.
    *   The method advances the ray through the hierarchy.
    *   If an active node of type `NodeT` is intersected, it returns `true`, populates `node` with the pointer to that node, and sets `t0` and `t1` to the entry and exit parameters of the node along the ray [S1].
    *   If the ray exits the grid or hits no more active nodes, it returns `false` [S1].

**Edge Cases and Pitfalls:**
*   **Coordinate Systems:** The ray is defined in index space. For point grids, a mismatch exists between bucketed data (centered on voxels) and DDA operations (coincident with voxel corners). This is handled by specialized variants like `PointTreeMarcher` [S2].
*   **Empty Space:** The HDDA efficiently skips empty regions. If the grid is entirely empty, `step` will return `false` immediately after initialization [S1].
*   **Precision:** Floating-point precision in `t0` and `t1` depends on the `RealType` of the ray. Degenerate rays (zero length or direction) are not explicitly handled in the provided interface [S1].

## Subtopics

### [PointTreeMarcher](7535-pointtreemarcher.md)
A specialized tree traversal algorithm for point grids. It differs from the generic `TreeMarcher` by handling the coordinate system mismatch inherent in point grids, where data is bucketed into grid cells centered on voxels, while the underlying DDA operates on grid nodes coincident with voxel corners. Choose this when working with point-based volume representations in OpenVDB.

## Operating characteristics
*   **Time Complexity:** Proportional to the number of nodes traversed. The HDDA allows skipping empty space, making it efficient for sparse grids. The exact complexity depends on the tree depth and sparsity.
*   **Memory Complexity:** Low. The `TreeMarcher` itself holds minimal state (ray and DDA state). It does not allocate memory for the grid structure, which is managed by the accessor [S1].
*   **Strengths:** Efficient traversal of sparse hierarchical data; generic interface supporting various node types; integrates with OpenVDB's accessor model.
*   **Limitations:** Requires the grid to be accessible via an `AccT` interface; does not compute voxel-level values directly (requires further processing like bisection or tetrahedralization); specific to OpenVDB's tree structure.
*   **When to Use:** When traversing sparse volumetric data stored in an OpenVDB tree to find node intersections for further processing (e.g., isosurface extraction).
*   **When Not to Use:** For dense grids where linear traversal might be simpler; for non-OpenVDB hierarchical structures; when voxel-level values are needed directly without further processing.

## Background
The `TreeMarcher` class is part of the `nanovdb` library within OpenVDB, developed by the Academy Software Foundation [S1, S2]. It was designed to provide a generic, efficient ray traversal mechanism for hierarchical grid data structures, leveraging the Hierarchical Digital Differential Analyzer (HDDA) for space skipping [S2]. It is a core component for advanced volume rendering and geometry extraction techniques in OpenVDB.
