# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal

## Overview
Hierarchical Grid Traversal is a ray-grid traversal algorithm that iterates through levels of a grid mipmap to efficiently march a ray through sparse volume data [S1, S2, unofficial]. It starts at the root (level 0) and recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB), using lookup tables to map parent indices to child indices [S1, unofficial]. Unlike standard voxel DDA which checks every voxel, this method leverages the hierarchical tree structure to skip empty space by jumping between grid nodes of different resolutions [S1, S2, unofficial]. It is distinct from [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) in its specific implementation for VDB structures using compile-time template meta-programming, and from [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on traversal efficiency rather than shading interpolation [S1, S5, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ (clipped to the grid bounding box), a hierarchical grid access structure `mAcc`, and a precomputed list of lookup tables `tables_list` where each table corresponds to a mipmap level.
*   **Output:** A list of voxel positions (`cube_ori_list`) at the maximum level (leaf level) that are intersected by the ray.

**Data Structures:**
*   **Lookup Table (`tables_list`):** A list of arrays, one per level. Each row corresponds to a coarse voxel at that level.
    *   Columns 0-7: Indices of the 8 child voxels in the next finer level. If a child is empty/invalid, the value is -1 [S1, unofficial].
    *   Columns -3 to -1 (or 8-10 in 0-indexed layout): The 3D grid coordinates $(x, y, z)$ of the coarse voxel [S1, unofficial].
*   **TreeMarcher State (S2):**
    *   `mAcc`: Reference to the grid access structure.
    *   `mRay`: The ray being traversed.
    *   `mHdda`: A Hierarchical DDA instance for precise boundary crossing.
    *   `mT0`: Current traversal start time.
    *   `mTmax`: Current traversal end time (clipped to ray far plane).

**Parameters:**
*   `max_level`: The maximum depth of the mipmap hierarchy. The loop runs from level 0 to `max_level` inclusive [S1, unofficial].
*   `cube_size`: The physical size of a voxel at the current level. For a base grid resolution of 256 units, `cube_size = 256 / (2 ** level)` [S1, unofficial].
*   `Eps`: Intersection tolerance, typically $10^{-6}$ [S2, unofficial].
*   `Delta`: Small offset for next-step estimation, typically $0.01$ [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize `cube_touched_idx` with `[0]` (the root voxel index) and `new_list` as empty [S1, unofficial].
    *   Clip `mRay` to the root bounding box. If no intersection, return false [S2, unofficial].
    *   Set `t0 = mRay.t0() + Eps` and `t1 = mRay.t1() - Eps`. If `t0 > t1`, return false [S2, unofficial].
    *   Determine the initial voxel index `ijk` by rounding down the ray position at `t0`: `ijk = RoundDown(mRay(t0))` [S2, unofficial].
    *   Get the dimension of the node at `ijk`: `dim = mAcc.getDim(ijk, mRay)` [S2, unofficial].
    *   Initialize the HDDA: `mHdda.init(mRay, t0, t1, max(dim, NodeT::dim()))` [S2, unofficial].
    *   Set `mT0` to `mHdda.time()` if `dim <= ChildT::dim()`, else -1 [S2, unofficial].
    *   Set `mTmax = t1` [S2, unofficial].

2.  **Hierarchical Iteration:**
    Iterate through each level `l` from 0 to `max_level`:
    *   Retrieve the table for the current level: `table = tables_list[l]` [S1, unofficial].
    *   For each voxel index `i` in `cube_touched_idx`:
        *   Retrieve the voxel's origin and end coordinates from the table:
            `cube_ori = table[i, -3:] * cube_size`
            `cube_end = cube_ori + cube_size` [S1, unofficial].
        *   Compute ray-AABB intersection: `intersect_ray_aabb(ray_ori, ray_inv_dir, cube_ori, cube_end)`, returning near time `tn` and far time `tf` [S1, unofficial].
        *   **Intersection Check:** If `tn <= tf` (ray intersects the parent voxel):
            *   If `l == max_level`:
                *   Append the voxel's position `table[i, -3:]` to `cube_ori_list` (final hit list) [S1, unofficial].
            *   Else (not at max level):
                *   Extract child indices from columns 0-7 of the table row [S1, unofficial].
                *   Filter out invalid children (marked as -1): `mask = table[i, :8] != -1` [S1, unofficial].
                *   Convert valid indices to integers and add them to `new_list` [S1, unofficial].
    *   Update `cube_touched_idx` to `new_list` and reset `new_list` to empty for the next level [S1, unofficial].

3.  **Refinement with HDDA (S2):**
    *   Inside the loop, after updating `cube_touched_idx`, the algorithm may refine the traversal using `mHdda` [S2, unofficial].
    *   Set `t0 = mT0` [S2, unofficial].
    *   Get `currentNode = mAcc.getNode<NodeT>()` [S2, unofficial].
    *   Call `hddaIsValid = mHdda.step()` [S2, unofficial].
    *   Estimate the next voxel: `nextIjk = RoundDown(mRay(mHdda.time() + Delta))` where `Delta = 0.01f` [S2, unofficial].
    *   Get the dimension of the next node: `nextDim = mAcc.getDim(nextIjk, mRay)` [S2, unofficial].
    *   Update HDDA: `mHdda.update(mRay, max(nextDim, NodeT::dim()))` [S2, unofficial].
    *   Update `mT0`: If `nextDim <= ChildT::dim()`, set `mT0 = mHdda.time()`, else -1 [S2, unofficial].
    *   If `t0 >= 0`:
        *   Set `t1 = min(mTmax, mHdda.time())` [S2, unofficial].
        *   If `t0 >= t1` or `currentNode == nullptr`, continue to next iteration [S2, unofficial].
        *   Set `*node = currentNode` and return true [S2, unofficial].
    *   If the loop ends without finding a valid node, return false [S2, unofficial].

**Pseudocode:**

```python
def hierarchical_grid_traversal(ray_origin, ray_direction, tables_list, max_level, cube_size_func):
    """
    Traverses a hierarchical grid mipmap to find leaf voxels intersected by a ray.
    
    Args:
        ray_origin: (3,) array, ray origin.
        ray_direction: (3,) array, ray direction (normalized).
        tables_list: List of arrays, one per level. Shape (N, 11). 
                     Cols 0-7: child indices (-1 if empty). Cols 8-10: coarse coords.
        max_level: int, maximum depth of the hierarchy.
        cube_size_func: function(level) -> float, returns physical voxel size at level.
        
    Returns:
        list of (3,) arrays, coordinates of intersected leaf voxels.
    """
    # 1. Initialization
    cube_touched_idx = [0]  # Start with root index
    cube_ori_list = []
    
    # Clip ray to root bbox (simplified assumption: root is always valid for this example)
    # In practice, check ray-bbox intersection first.
    
    # 2. Iterate through levels
    for level in range(max_level + 1):
        table = tables_list[level]
        current_cube_size = cube_size_func(level)
        new_list = []
        
        for i in cube_touched_idx:
            # Retrieve voxel bounds from table
            # Cols -3 to -1 are x, y, z coordinates
            coarse_coords = table[i, -3:]
            cube_ori = coarse_coords * current_cube_size
            cube_end = cube_ori + current_cube_size
            
            # Ray-AABB Intersection
            # Standard slab method
            inv_dir = 1.0 / ray_direction
            t_min = (cube_ori - ray_origin) * inv_dir
            t_max = (cube_end - ray_origin) * inv_dir
            
            # Swap if necessary
            t_min = np.minimum(t_min, t_max)
            t_max = np.maximum(t_min, t_max)
            
            tn = np.max(t_min)
            tf = np.min(t_max)
            
            # Check intersection
            if tn <= tf:
                if level == max_level:
                    # Reached leaf level, record position
                    cube_ori_list.append(coarse_coords)
                else:
                    # Not leaf level, get children
                    # Cols 0-7 are child indices
                    child_indices = table[i, :8]
                    # Filter out invalid children (-1)
                    valid_mask = child_indices != -1
                    valid_children = child_indices[valid_mask]
                    new_list.extend(valid_children)
        
        cube_touched_idx = new_list
        if not cube_touched_idx:
            break
            
    return cube_ori_list
```

**Edge Cases and Pitfalls:**
*   **Floating-point Precision:** If the `Delta` offset used for estimating the next voxel is too large, it may clip corners of nodes visibly. If too small, it may fail due to floating-point rounding errors when far from the grid. A value of $0.01$ is typically used [S2, unofficial].
*   **Tiny Intersections:** Tweaking the intersection span with `Eps` ($10^{-6}$) may clip tiny corner intersections [S2, unofficial].
*   **Vectorization:** The vectorized version `ray_mipmap_intersect_vectorized` processes all rays in `cube_touched_idx` simultaneously. It uses `np.zeros_like` for `tn` and `tf` and iterates over `len(cube_touched_idx)` to call `intersect_ray_aabb` for each ray individually, then masks out non-intersecting rays: `mask = tn <= tf` [S1, unofficial].

## Subtopics

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
The Hierarchical Digital Differential Analyzer (HDDA) is a ray traversal algorithm that performs multi-resolution leapfrogging through sparse volume data structures, specifically OpenVDB and NanoVDB grids. It adapts the Digital Differential Analyzer (DDA) to step through nodes or voxels of varying power-of-two dimensions, skipping empty space by jumping between grid nodes of different resolutions. Unlike standard voxel DDA which checks every voxel, HDDA leverages the hierarchical tree structure (B+tree) to traverse coarse tiles first and only descend into occupied children, significantly accelerating ray-marching for sparse volumes. It is distinct from [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) in its specific implementation for VDB structures using compile-time template meta-programming to inline the hierarchy, and from [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on traversal efficiency rather than shading interpolation.

### [OpenVDB DDA](2149-openvdb-dda.md)
OpenVDB DDA is a Digital Differential Analyzer traversal algorithm specialized for OpenVDB grids, conceptually similar to Bresenham's line algorithm applied to a 3D ray intersecting OpenVDB nodes or voxels. It iterates through grid elements intersected by a ray using a fixed step-size defined by the template parameter `Log2Dim`. Unlike Hierarchical DDA (HDDA) which uses variable step-sizes to skip empty space, OpenVDB DDA marches through every node or voxel boundary along the ray path.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
Hierarchical Voxel Traversal is a recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### [XBrickMap](3116-xbrickmap.md)
XBrickMap is a space-skipping ray traversal algorithm for 3-level hierarchical voxel grids that uses 4³ occupancy bitmasks to perform hierarchical skips (4³, 2³, 1³ cuboids) via bitwise tests. It improves upon standard skipping by using tiled bitmasks to identify empty voxel sections and left-packs these bitmasks to omit empty bricks within sectors, saving memory. It is distinguished from siblings like [MultiDDA](2204-hierarchical-voxel-traversal.md) by its specific 3-level sector/brick/voxel hierarchy and bitmask-based compression, and from [Tree64](6354-multi-level-grid-structures.md) by its fixed grid topology and lack of dynamic tree rebalancing.

### [Spherical Volume Voxel Traversal](3877-spherical-volume-voxel-traversal.md)
Spherical Volume Voxel Traversal is a ray-marching algorithm that traverses a ray through a voxel grid structured in spherical coordinates (radial, polar, azimuthal), returning the sequence of voxels intersected by the ray. It solves the problem of efficiently sampling volumetric data defined on a spherical domain, such as planetary atmospheres or star models, where Cartesian grids introduce significant distortion or wasted space near the center. Unlike Cartesian hierarchical traversal which relies on axis-aligned bounding boxes, this method computes intersections with spherical shells, polar cones, and azimuthal wedges directly, handling the singularity at the origin by starting traversal at the first non-zero radial shell. It builds on [Hierarchical Grid Traversal](8384-hierarchical-grid-traversal.md) by specializing the traversal logic for spherical topology rather than octree or uniform grid structures.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
First Active Voxel Detection determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
Hierarchical and Block-Based Data Structures provide a spatial subdivision framework for volume rendering, enabling efficient traversal and culling of empty or inactive regions during ray marching. Unlike flat voxel grids, these structures organize data into a tree where internal nodes store aggregate properties (e.g., occupancy, scalar ranges) derived from their children, allowing rays to skip large inactive subtrees [4133-hierarchical-data-structures]. This family encompasses methods that vary in their spatial representation (octrees, pyramids, image-space mipmaps) and traversal order (image-order, object-order, or hybrid). It sets itself apart from sibling methods by focusing on the *data organization* strategy (hierarchical blocks/trees) rather than the specific traversal algorithm (e.g., HDDA) or hardware acceleration mechanism (e.g., RTX BVH) used to navigate it.

### [Hierarchical DDA with Super-brick Skipping](5197-hierarchical-dda-with-super-brick-skipping.md)
This method accelerates ray tracing through sparse volumetric data by introducing a two-level occupancy hierarchy (super-bricks and bricks) to skip large empty regions, while maintaining pixel-identical output to the fine per-voxel DDA. It solves the performance bottleneck of traversing empty space by verifying emptiness at a coarser granularity and using an axis-aligned bounding box (AABB) for early termination, ensuring exactness by only skipping verified empty blocks and terminating only when the ray definitively passes the occupied volume.

### [DDA Tree Traversal with Mini-Stack](5244-dda-tree-traversal-with-mini-stack.md)
This method extends the Digital Differential Analyzer (DDA) algorithm for regular grids to N-ary trees, enabling efficient ray traversal of hierarchical sparse voxel structures on GPU shaders. It solves the problem of navigating deep tree hierarchies by maintaining a small stack of DDA states, allowing the ray to descend to the entry leaf, process nodes horizontally, and ascend back up the tree without expensive recursive function calls or large memory allocations. It is distinguished from its siblings by its specific implementation using dynamically indexed local arrays in Shader Model 4.0, optimizing for fixed-depth hierarchies where stack size is known at compile time.

### [Octree-based traversal](5348-octree-based-traversal.md)
Octree-based traversal accelerates volume rendering and ray tracing by navigating a hierarchical spatial decomposition (typically an octree) to skip empty space and reduce the number of ray-casting or distance-evaluation steps. It solves the performance bottleneck of non-hierarchical traversal, where every voxel along a ray must be visited, by allowing the ray to leap over large empty regions. Unlike sibling methods that may use fixed-resolution grids or brick maps, this family operates on a recursive tree structure where each parent node divides into eight equal sub-blocks ($2 \times 2 \times 2$ subdivision), enabling larger steps through empty space.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty Space Skipping via Data Structures accelerates volume rendering by using secondary data structures to identify inactive regions, allowing rays to skip sampling points in empty space. It differs from [Space Leaping](5863-space-leaping.md) by relying on explicit spatial metadata rather than image-plane coherence, and from [Distance Map Acceleration](972-distance-map-acceleration.md) by using binary or bounded occupancy flags rather than distance-to-nearest-occupied-voxel metrics. It sets itself apart from sibling methods like [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) by focusing specifically on the *culling* of inactive regions via metadata queries, whereas hierarchical traversal focuses on the *navigation* of the grid hierarchy itself.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
Multi-level Grid Structures are a family of hierarchical acceleration techniques for ray-grid traversal that organize scene data into a hierarchy of grid levels to skip empty space and reduce intersection tests [G]. This family builds on [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by providing specific implementations for constructing and traversing these hierarchical grids [G].

### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. Scalar values within a certain range are grouped together to define sub-volume properties. A kd-tree is used to render the partitioned volume with correct visibility order, where each node is associated with a sub-volume. Each sub-volume is culled and clipped against an opacity map [S3, unofficial]. 10 fps was reported for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].

### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial]. Occupied voxels in the fine grid are identified and assigned unique indices. The 8 sub-grid regions corresponding to the 8 children of a coarse voxel are obtained by striding the fine grid indices. These sub-grids are flattened and filtered using the coarse grid mask to select only children belonging to occupied coarse voxels. The table is initialized with shape `[num_coarse_voxels, 11]` (8 child indices + 3 coordinates), filled with -1. Columns 0-7 are populated with filtered child indices, and columns 8-10 with coarse voxel coordinates [S1, unofficial].

### VIPER Ray-Traversal and Surface Intersection Algorithm
The algorithm's time and space complexities are both dependent upon the size of the data volume (in terms of voxel dimensions) to be rendered [S4, unofficial]. If one disregards the process of reading in the data volume, VIPER operates with an efficiency of $O(p \cdot r)$, where $p$ is the number of pixels through which rays are being cast and $r$ is the volume's largest dimension (in terms of voxels per edge) [S4, unofficial]. The relative distance is calculated as $(target - value1) / (value2 - value1)$ [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** The complexity depends on the sparsity of the volume and the depth of the hierarchy. In the worst case (fully occupied), it approaches $O(N)$ where $N$ is the number of leaf voxels, but typically skips large empty regions, offering significant speedups over flat DDA [S1, S4, unofficial]. The VIPER variant specifically notes $O(p \cdot r)$ where $p$ is pixels and $r$ is the largest dimension [S4, unofficial].
*   **Memory Complexity:** Dependent on the size of the data volume and the storage of the lookup tables. The tables store child indices and coordinates for each coarse voxel, adding overhead proportional to the number of nodes in the hierarchy [S1, S4, unofficial].
*   **Performance:** Reported performance of 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter for KD-Tree partitioned variants [S3, unofficial].
*   **Strengths:** Efficiently skips empty space in sparse volumes; leverages precomputed lookup tables for fast index mapping; suitable for hierarchical data structures like OpenVDB.
*   **Limitations:** Requires precomputation of mipmap tables; precision issues with small `Delta` or `Eps` values can lead to missed intersections or clipping; vectorized implementations may have overhead for small ray batches.

## Background
Hierarchical Grid Traversal is a method for accelerating volume rendering by utilizing multi-resolution grid structures (mipmaps) to skip empty space during ray marching. It builds on the principles of ray-grid traversal, specifically the Digital Differential Analyzer (DDA) algorithm, but extends it to hierarchical data structures. The method is closely associated with implementations in libraries like OpenVDB and NanoVDB, where it is often referred to as Hierarchical DDA (HDDA) or specialized DDA for VDB structures [S1, S2, S5, unofficial]. The approach allows for efficient traversal of sparse volumetric data by stepping through nodes of varying resolutions, only descending into occupied children [S1, S2, S6, unofficial].
