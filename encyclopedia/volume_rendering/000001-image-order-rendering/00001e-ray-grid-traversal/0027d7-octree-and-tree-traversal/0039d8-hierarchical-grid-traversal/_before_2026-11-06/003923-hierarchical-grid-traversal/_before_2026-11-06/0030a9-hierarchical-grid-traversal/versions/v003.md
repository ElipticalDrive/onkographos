# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal, TreeMarcher

## Overview
Hierarchical Grid Traversal accelerates ray-grid traversal by stepping through a multi-resolution grid hierarchy (mipmap) rather than a single flat grid. It starts at the root level and recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB) [S1, S2, unofficial]. This method differs from flat DDA [3061-digital-differential-analyzer-dda-traversal.md] by skipping large empty regions via coarse-level checks, and from pure tree structures like Octrees [5348-octree-based-traversal.md] by maintaining a grid-based indexing scheme at each level, which simplifies traversal logic on GPUs [6354-multi-level-grid-structures.md].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, ray near/far bounds $t_{min}, t_{max}$, hierarchical grid data structure (mipmap), and lookup tables mapping parent voxel indices to child voxel indices.
**Outputs:** List of voxel positions (or indices) at the maximum resolution level intersected by the ray.

**Data Structures:**
1.  **Grid Table (`g_table`):** A 2D array where each row corresponds to a coarse voxel.
    *   Columns 0–7: Indices of the 8 child voxels (or -1 if empty/invalid).
    *   Columns -3 to -1: The 3D grid coordinates $(x, y, z)$ of the coarse voxel.
2.  **K-Table (`k_table`):** A list of active rays during traversal. Each row contains:
    *   Columns 0–2: Ray origin $\mathbf{o}$.
    *   Columns 3–5: Ray inverse direction $\mathbf{r}_{inv} = 1/\mathbf{d}$.
    *   Columns 6–8: Current voxel origin $\mathbf{v}_{ori}$.
    *   Columns 9–11: Current voxel end $\mathbf{v}_{end}$.
    *   Column -2: Ray ID.
    *   Column -1: Voxel ID (row index in `g_table`).
3.  **TreeMarcher Class (C++ Implementation):** Contains `AccT& mAcc` (accessor), `RayT mRay`, `HDDA<RayT, Coord> mHdda` (Hierarchical DDA helper), `float mT0`, and `float mTmax` [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Set `cube_touched_idx` to `[0]` (root voxel index) [S1, unofficial].
    *   Initialize `new_list` as empty [S1, unofficial].
    *   Alternatively, using the C++ `TreeMarcher` approach:
        *   Clip ray to root bounding box; if no intersection, return false [S2, unofficial].
        *   Set epsilon $Eps = 10^{-6}$ [S2, unofficial].
        *   Set $t_0 = \max(t_{min} + Eps, \text{ray near})$ and $t_1 = \min(t_{max} - Eps, \text{ray far})$ [S2, unofficial].
        *   If $t_0 > t_1$, return false [S2, unofficial].
        *   Compute initial voxel index `ijk` by rounding down the ray position at $t_0$ [S2, unofficial].
        *   Initialize HDDA with ray, $t_0, t_1$, and node dimension [S2, unofficial].

2.  **Hierarchical Loop (Level-by-Level):**
    *   Iterate through levels $L$ from 0 to `max_level` [S1, unofficial].
    *   For each voxel index $i$ in `cube_touched_idx`:
        *   Retrieve voxel origin $\mathbf{v}_{ori}$ and end $\mathbf{v}_{end}$ from `g_table[i]` [S1, unofficial].
        *   Compute ray-AABB intersection with $\mathbf{v}_{ori}$ and $\mathbf{v}_{end}$ [S1, unofficial].
        *   Let $t_n$ (near) and $t_f$ (far) be the intersection distances.
        *   If $t_n \le t_f$ (intersection exists):
            *   If $L == \text{max\_level}$: Add voxel position to final hit list `cube_ori_list` [S1, unofficial].
            *   Else: Extract child indices from `g_table[i, 0:8]`. Filter out invalid children (value -1). Add valid child indices to `new_list` [S1, unofficial].
    *   Update `cube_touched_idx` to `new_list` and reset `new_list` [S1, unofficial].

3.  **K-Table Propagation (Alternative Vectorized Approach):**
    *   Initialize `k_table` with ray properties and root voxel bounds [S1, unofficial].
    *   For each level:
        *   For each row in `k_table`, get current voxel ID and position [S1, unofficial].
        *   Calculate voxel size $s = 256 / 2^L$ and sub-voxel size $s/2$ [S1, unofficial].
        *   Identify alive sub-voxels (children) from `g_table[voxel_id, 0:8] != -1` [S1, unofficial].
        *   Compute new origins for alive sub-voxels: $\mathbf{v}_{new} = \mathbf{v}_{current} + \text{shift} \times (s/2)$ [S1, unofficial].
        *   Create new `k_table` rows for each alive sub-voxel, copying ray properties and updating voxel bounds/ID [S1, unofficial].
        *   Concatenate new rows into `k_table` for the next level [S1, unofficial].

**Pseudocode (Python-like, Vectorized):**

```python
def hierarchical_grid_traversal(ray_origin, ray_direction, g_table, max_level):
    """
    Traverses a hierarchical grid using AABB intersection checks.
    
    Args:
        ray_origin: (3,) array, ray origin.
        ray_direction: (3,) array, ray direction.
        g_table: (N, 11) array, grid lookup table.
                 Columns 0-7: child indices (-1 if empty).
                 Columns 8-10: voxel coordinates (x, y, z).
        max_level: int, maximum depth of hierarchy.
        
    Returns:
        List of voxel coordinates at max_level intersected by ray.
    """
    # Initialize with root voxel index (0)
    cube_touched_idx = [0]
    cube_ori_list = []
    
    # Precompute ray inverse for AABB intersection
    ray_inv_dir = 1.0 / ray_direction
    
    for level in range(max_level + 1):
        new_list = []
        
        # Calculate voxel size for current level
        # Assuming base resolution 256 as per source [S1, unofficial]
        voxel_size = 256.0 / (2 ** level)
        
        for i in cube_touched_idx:
            # Get voxel bounds from table
            # Columns -3 to -1 are x, y, z coordinates
            voxel_coords = g_table[i, -3:]
            
            # Calculate origin and end in world space
            # Note: Source implies voxel_size is the step, 
            # but coordinates in table might be grid indices.
            # Assuming table stores grid indices, convert to world space if needed.
            # Based on S1: cube_ori = table[i, -3:] * cube_size is NOT explicitly stated 
            # for the table lookup, but rather for the shift calculation in K-table.
            # However, S1 says: "retrieve its origin: cube_ori = table[i, -3:] * cube_size"
            # Let's assume table stores grid indices.
            cube_ori = voxel_coords * voxel_size
            cube_end = cube_ori + voxel_size
            
            # Ray-AABB Intersection
            tn, tf = intersect_ray_aabb(ray_origin, ray_inv_dir, cube_ori, cube_end)
            
            if tn <= tf:
                if level == max_level:
                    cube_ori_list.append(voxel_coords)
                else:
                    # Get child indices (columns 0-7)
                    children = g_table[i, :8]
                    # Filter valid children (not -1)
                    mask = children != -1
                    valid_children = children[mask]
                    new_list.extend(valid_children)
        
        cube_touched_idx = new_list
        if not cube_touched_idx:
            break
            
    return cube_ori_list

def intersect_ray_aabb(ray_o, ray_inv_d, box_min, box_max):
    """
    Standard slab method for ray-AABB intersection.
    Returns (tn, tf) or (inf, -inf) if no intersection.
    """
    t_min = (box_min - ray_o) * ray_inv_d
    t_max = (box_max - ray_o) * ray_inv_d
    
    t1 = np.minimum(t_min, t_max)
    t2 = np.maximum(t_min, t_max)
    
    tn = np.max(t1)
    tf = np.min(t2)
    
    return tn, tf
```

**Parameters:**
*   `max_level`: Maximum depth of the mipmap hierarchy [S1, unofficial].
*   `cube_size`: Physical size of a voxel at level $L$, calculated as $256 / 2^L$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Floating-Point Drift:** Using the formula $\mathbf{o} + t\mathbf{d}$ to switch levels does not guarantee the ray crosses the plane due to floating-point issues, leading to outliers in depth and normal buffers [S4, unofficial].
*   **Corner Traversal:** Allowing rays to traverse through corners can cause problems with surface normals [S4, unofficial].
*   **Delta Tuning:** In C++ implementations, if the delta step is too large, it clips corners of nodes visibly; if too small, it fails due to FP32 rounding when far from the grid. A value of $0.01$ is used [S2, unofficial].
*   **Epsilon Clipping:** Tweaking intersection span with epsilon ($10^{-6}$) may clip tiny corner intersections [S2, unofficial].

## Subtopics

### [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md)
A method that accelerates ray casting by traversing a multi-dimensional hierarchy (mdh) and adaptively selecting resolution based on error tolerance [851-hierarchical-trilinear-ray-casting.md]. It uses least-squares trilinear basis functions to model data regions, deciding whether to refine or evaluate directly based on approximation error, unlike methods relying on simple homogeneity.

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
A ray traversal algorithm that performs multi-resolution leapfrogging through sparse volume data structures like OpenVDB [1122-hierarchical-digital-differential-analyzer-hdda.md]. It adapts DDA to step through nodes of varying power-of-two dimensions, skipping empty space by jumping between grid nodes of different resolutions. It is distinct from Hierarchical Grid Traversal in its specific implementation for VDB structures using compile-time template meta-programming.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
A recursive raycasting algorithm designed to traverse nested voxel structures (chunks containing subvoxels) [2204-hierarchical-voxel-traversal.md]. It transforms rays into local subvoxel space when entering a detail voxel, allowing efficient handling of nested voxel data.

### [XBrickMap](3116-xbrickmap.md)
A space-skipping ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to perform hierarchical skips via bitwise tests [3116-xbrickmap.md]. It improves upon standard skipping by using tiled bitmasks to identify empty voxel sections and left-packs these bitmasks to omit empty bricks within sectors.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
Determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile [4196-first-active-voxel-detection.md]. It leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
Organizes volume data into spatial subdivisions (blocks, bricks, or octrees) to enable efficient ray traversal, empty space skipping, and multiresolution access [4392-hierarchical-and-block-based-data-structures.md]. It stores aggregate properties (e.g., occupancy, min/max ranges) in internal nodes, allowing rays to skip inactive subtrees [Parent].

### [Octree-based traversal](5348-octree-based-traversal.md)
Accelerates volume rendering by navigating a hierarchical spatial decomposition (typically an octree) to skip empty space [5348-octree-based-traversal.md]. Each parent node divides into eight equal sub-blocks ($2 \times 2 \times 2$), enabling larger steps through empty space.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Accelerates volume rendering by using secondary data structures to identify inactive regions, allowing rays to skip sampling points in empty space [5619-empty-space-skipping-via-data-structures.md]. It differs from Space Leaping by relying on explicit spatial metadata rather than image-plane coherence.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
A family of hierarchical acceleration techniques that organize scene data into a hierarchy of grid levels (mipmaps) to skip empty space [6354-multi-level-grid-structures.md]. They differ from uniform grids by adapting resolution to local density and from pure tree structures by maintaining a grid-based indexing scheme at each level.

### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. It uses a kd-tree to render the partitioned volume with correct visibility order, where each node is associated with a sub-volume, and culls/clips each sub-volume against an opacity map [S3, unofficial]. Reported performance: 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].

### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal, mapping coarse grid voxels to their fine grid children [S1, unofficial]. It identifies occupied voxels in the fine grid, extracts 8 sub-grid regions for each coarse voxel, filters them using the coarse grid mask, and populates a table with child indices and coarse voxel coordinates [S1, unofficial].

### K-Table Initialization and Propagation
Manages a list of active rays ('k-table') during traversal, storing ray properties and the current voxel they are in, propagating to child voxels [S1, unofficial]. It initializes with ray origins, inverse directions, and root voxel bounds, then creates new rows for each alive sub-voxel at each level [S1, unofficial].

### Teardown Hierarchical Traversal
A hierarchical traversal method that uses DDA within a level and switches levels by rescaling the grid so the new level becomes a level 0 grid, restarting the DDA algorithm [S4, unofficial]. It calculates ray position at any level using $pos = \lfloor (O + t \cdot D) / 2^{level} \rfloor$ [S4, unofficial]. Pitfalls include floating-point issues leading to outliers in depth/normal buffers and problems with surface normals when traversing corners [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume. In dense volumes, it approaches flat DDA performance. In sparse volumes, it significantly reduces the number of visited voxels by skipping empty coarse regions [S1, S3, unofficial].
*   **Memory Complexity:** Requires additional memory for the hierarchy (mipmap levels) and lookup tables (`g_table`, `k_table`) [S1, S2, unofficial].
*   **Performance:** The vectorized version `ray_mipmap_intersect_vectorized` processes all rays in `cube_touched_idx` simultaneously, improving throughput on GPUs [S1, unofficial].
*   **Strengths:** Efficient empty space skipping, suitable for sparse volumes, simplifies traversal logic on GPUs compared to pure trees [6354-multi-level-grid-structures.md].
*   **Limitations:** Floating-point precision issues when switching levels can cause artifacts (outliers in depth/normal buffers) [S4, unofficial]. Requires careful tuning of epsilon and delta parameters [S2, unofficial].

## Background
Hierarchical Grid Traversal is a method for accelerating volume rendering by leveraging multi-resolution data structures. It builds on the principles of Ray-grid traversal [17-ray-grid-traversal.md], specifically DDA [3061-digital-differential-analyzer-dda-traversal.md], by adding a hierarchical layer to skip empty space. The method is implemented in various forms, including the `TreeMarcher` class in HNanoSolver [S2, unofficial] and the Jax-based volumetric renderer [S1, unofficial]. The Teardown game engine also uses a variant of this method, rescaling the grid at each level to restart DDA [S4, unofficial].
