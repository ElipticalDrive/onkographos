# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal, TreeMarcher

## Overview
Hierarchical Grid Traversal is a ray-grid traversal method that accelerates volume rendering by stepping through a multi-resolution grid hierarchy (mipmap) rather than a single flat grid. It starts at the root level and recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB), effectively skipping empty space at coarse levels before refining the search at finer levels [S1, unofficial]. Unlike flat [Digital Differential Analyzer (DDA) Traversal](3061-digital-differential-analyzer-dda-traversal.md) which samples every voxel along the ray path, this method reduces sample evaluations by leveraging the hierarchical structure to jump over inactive regions [S1, unofficial]. It differs from [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by typically using a fixed grid topology with pre-computed lookup tables rather than dynamic tree structures [S1, unofficial].

## How it works
**Inputs:** A ray defined by origin $O$ and direction $D$ (or inverse direction $I = 1/D$); a hierarchical grid structure defined by multiple resolution levels; a lookup table (or set of tables) mapping parent voxel indices to child voxel indices and coordinates.
**Outputs:** A list of voxel positions (or indices) at the maximum resolution level that the ray intersects.

**Data Structures:**
1.  **Grid Table (`g_table`):** A 2D array where each row corresponds to a voxel at a specific level.
    *   Columns 0-7: Indices of the 8 child voxels in the next finer level. If a child is empty or invalid, the value is $-1$.
    *   Columns -3 to -1 (or 8-10): The 3D grid coordinates $(x, y, z)$ of the current voxel.
    *   *Note:* In some implementations (like `ray_mipmap_intersect_vectorized`), the table is constructed dynamically or accessed via a list of tables per level [S1, unofficial].
2.  **K-Table (`k_table`):** (Optional, for ray-based traversal) Stores active ray state.
    *   Columns 0-2: Ray origin $(r_{ori})$.
    *   Columns 3-5: Ray inverse direction $(r_{inv})$.
    *   Columns 6-8: Current voxel origin $(cube_{ori})$.
    *   Columns 9-11: Current voxel end $(cube_{end})$.
    *   Column -2: Ray ID $(r_{id})$.
    *   Column -1: Voxel ID/Row ID in the grid table.
3.  **HDDA State:** (In C++ implementations like HNanoSolver) A Hierarchical Digital Differential Analyzer state tracking the current position, time $t$, and step direction within the current node [S2, unofficial].

**Parameters:**
*   `max_level`: The maximum depth of the mipmap hierarchy. The traversal iterates from level 0 to `max_level` inclusive [S1, unofficial].
*   `cube_size`: The physical size of a voxel at level $L$, calculated as $256 / 2^L$ (assuming a base resolution of 256 units) [S1, unofficial].
*   `Eps`: A small epsilon value (e.g., $0.000001$) added to the ray start time $t_0$ to avoid self-intersection or precision issues at the entry point [S2, unofficial].
*   `Delta`: A small offset (e.g., $0.01$) used to probe the next voxel position to determine if the ray has exited the current node [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Initialize `cube_touched_idx` with `[0]` (the root voxel index) [S1, unofficial].
    *   Initialize `cube_ori_list` as empty (to store final hits) [S1, unofficial].
    *   If using HDDA (C++ style):
        *   Set `mRay` to the input ray.
        *   Clip `mRay` to the root bounding box. If no intersection, return false [S2, unofficial].
        *   Set $t_0 = mRay.t_0() + Eps$ and $t_1 = mRay.t_1() - Eps$. If $t_0 > t_1$, return false [S2, unofficial].
        *   Initialize HDDA with $t_0, t_1$ and the root dimension [S2, unofficial].

2.  **Traversal Loop (Level by Level):**
    *   For each level $L$ from 0 to `max_level`:
        *   Retrieve the lookup table for level $L$: `table = tables_list[L]` [S1, unofficial].
        *   Initialize `new_list` as empty [S1, unofficial].
        *   For each voxel index `i` in `cube_touched_idx`:
            *   Retrieve the voxel's grid coordinates: `xyz = table[i, -3:]` [S1, unofficial].
            *   Calculate the voxel's physical origin and end:
                *   $cube_{ori} = xyz \times cube\_size$
                *   $cube_{end} = cube_{ori} + cube\_size$
            *   Compute ray-AABB intersection with $[cube_{ori}, cube_{end}]$:
                *   Use standard ray-AABB intersection formula to get near time $t_n$ and far time $t_f$ [S1, unofficial].
                *   *Vectorized Note:* In `ray_mipmap_intersect_vectorized`, this is done for all rays in `cube_touched_idx` simultaneously, masking out non-intersecting rays ($t_n \le t_f$) [S1, unofficial].
            *   If intersection exists ($t_n \le t_f$):
                *   If $L == max\_level$:
                    *   Append `xyz` to `cube_ori_list` [S1, unofficial].
                *   Else:
                    *   Extract child indices from `table[i, 0:8]` [S1, unofficial].
                    *   Filter out invalid children (where index $\ne -1$) using a mask [S1, unofficial].
                    *   Convert valid indices to integers and add them to `new_list` [S1, unofficial].
        *   Update `cube_touched_idx = new_list` [S1, unofficial].
        *   If `cube_touched_idx` is empty, break loop [S1, unofficial].

3.  **Return:**
    *   Return `cube_ori_list` containing the positions of voxels touched at the maximum level [S1, unofficial].

**Alternative C++ HDDA-based Step Logic (from HNanoSolver):**
1.  `step(node, t0, t1)`:
    *   Set $t_0 = mT_0$.
    *   Get `currentNode` from acceleration structure [S2, unofficial].
    *   Call `mHdda.step()`. If invalid, continue [S2, unofficial].
    *   Calculate `nextIjk` by rounding down the ray position at $mHdda.time() + Delta$ [S2, unofficial].
    *   Get `nextDim` for `nextIjk` [S2, unofficial].
    *   Update HDDA with `nextDim` [S2, unofficial].
    *   Set $mT_0$ based on whether `nextDim` is a leaf level [S2, unofficial].
    *   If $t_0 \ge 0$:
        *   Set $t_1 = \min(mT_{max}, mHdda.time())$ [S2, unofficial].
        *   If $t_0 \ge t_1$ or `currentNode` is null, continue [S2, unofficial].
        *   Set `*node = currentNode` and return true [S2, unofficial].
    *   If loop ends, return false [S2, unofficial].

**Pseudocode (Python-like, Table-based):**

```python
def hierarchical_grid_traversal(ray_origin, ray_direction, tables_list, max_level):
    """
    Traverses a hierarchical grid using lookup tables.
    
    Args:
        ray_origin: (3,) array, ray origin O.
        ray_direction: (3,) array, ray direction D.
        tables_list: List of arrays, where tables_list[L] is the grid table for level L.
                     Each row has shape (11,): [child0..child7, x, y, z].
        max_level: int, the maximum level index.
        
    Returns:
        cube_ori_list: List of (3,) arrays, coordinates of voxels at max_level intersected by the ray.
    """
    # Initialize with root voxel index 0
    cube_touched_idx = [0]
    cube_ori_list = []
    
    # Precompute inverse direction for ray-AABB intersection
    ray_inv_dir = 1.0 / ray_direction
    
    for level in range(max_level + 1):
        table = tables_list[level]
        new_list = []
        
        # Determine voxel size for this level (assuming base resolution 256)
        cube_size = 256.0 / (2 ** level)
        
        for i in cube_touched_idx:
            # Get voxel coordinates from table (columns -3, -2, -1)
            xyz = table[i, -3:]
            
            # Calculate physical bounds
            cube_ori = xyz * cube_size
            cube_end = cube_ori + cube_size
            
            # Ray-AABB Intersection
            tn, tf = intersect_ray_aabb(ray_origin, ray_inv_dir, cube_ori, cube_end)
            
            if tn <= tf:
                if level == max_level:
                    # Reached the finest level, record the voxel
                    cube_ori_list.append(xyz)
                else:
                    # Get child indices (columns 0-7)
                    children = table[i, :8]
                    
                    # Filter valid children (index != -1)
                    mask = children != -1
                    valid_children = children[mask]
                    
                    # Add valid children to the next level's list
                    new_list.extend(valid_children.tolist())
        
        cube_touched_idx = new_list
        if not cube_touched_idx:
            break
            
    return cube_ori_list

def intersect_ray_aabb(origin, inv_dir, min_corner, max_corner):
    """
    Standard ray-AABB intersection.
    Returns (tn, tf) near and far intersection times.
    Returns (inf, -inf) if no intersection.
    """
    t_min = (min_corner - origin) * inv_dir
    t_max = (max_corner - origin) * inv_dir
    
    t1 = np.minimum(t_min, t_max)
    t2 = np.maximum(t_min, t_max)
    
    tn = np.max(t1)
    tf = np.min(t2)
    
    if tn > tf:
        return float('inf'), float('-inf')
        
    return tn, tf
```

## Subtopics

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
A recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### [XBrickMap](3116-xbrickmap.md)
XBrickMap is a space-skipping ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to perform hierarchical skips ($4^3, 2^3, 1^3$ cuboids) via bitwise tests. It improves upon standard skipping by using tiled bitmasks to identify empty voxel sections and left-packs these bitmasks to omit empty bricks within sectors, saving memory. It is distinguished from siblings like [MultiDDA](2204-hierarchical-voxel-traversal.md) by its specific 3-level sector/brick/voxel hierarchy and bitmask-based compression, and from [Tree64](6354-multi-level-grid-structures.md) by its fixed grid topology and lack of dynamic tree rebalancing.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
First Active Voxel Detection determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
This family provides acceleration structures for image-order volume rendering by organizing volumetric data into multi-resolution trees or blocks to skip empty or inactive regions during ray traversal. It serves as the foundational acceleration mechanism for sibling methods such as [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md) and [ExaBricks Rendering with RTX BVH](2577-exabricks-rendering-with-rtx-bvh.md). Unlike flat grid traversal, these structures enable rays to jump over large empty spaces or identify active cells for rendering, significantly reducing computational cost.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty space skipping accelerates volume rendering by identifying and bypassing regions of the volume that do not contribute to the final image, thereby reducing the number of sample evaluations and shading calculations. It differs from its siblings by focusing on the identification of "active" or "significant" volume data using various data structures (bounding geometry, 2D slices, BVHs, or HistoPyramids) to define ray entry and exit bounds, whereas [Hierarchical Grid Traversal](6306-hierarchical-grid-traversal.md) focuses on the traversal logic of the grid itself. It sets itself apart from [Adaptive Multi-Step Empty Voxel Skipping](6289-adaptive-multi-step-empty-voxel-skipping.md) by typically using pre-computed or coarse structural bounds rather than adaptive step sizes based on local density gradients.

#### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. It groups scalar values within a certain range together based on the transfer function to define sub-volume properties, uses a kd-tree to render the partitioned volume with correct visibility order (where each node is associated with a sub-volume), and culls/clips each sub-volume against an opacity map [S3, unofficial]. Reported performance: 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].

#### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial]. It identifies occupied voxels in the fine grid, assigns unique indices, extracts the 8 sub-grid regions corresponding to the 8 children of a coarse voxel (via striding), flattens and filters them using the coarse grid mask, initializes the table with shape `[num_coarse_voxels, 11]` (8 child indices + 3 coordinates) filled with -1, populates columns 0-7 with filtered child indices, and columns 8-10 with coarse voxel coordinates [S1, unofficial].

#### K-Table Initialization and Propagation
Manages a list of active rays ('k-table') during traversal. It stores ray properties and the current voxel they are in, propagating to child voxels [S1, unofficial]. It initializes `k_table` with ray origins, inverse directions, ray IDs, and the root voxel's origin/end. In `next_k_table`, for each row, it gets the current voxel ID and position, calculates voxel/sub-voxel sizes, identifies alive sub-voxels (children) from the grid table, computes their origins, creates new `k_table` rows for each alive sub-voxel, and concatenates them into a single `k_table` for the next level [S1, unofficial].

#### Teardown Hierarchical Traversal
A hierarchical traversal method that uses DDA within a level and switches levels by rescaling the grid so the new level becomes a level 0 grid, restarting the DDA algorithm [S4, unofficial]. It calculates the ray position in the grid at any level using the formula: $pos = \lfloor (O + t \cdot D) / 2^{level} \rfloor$ [S4, unofficial]. Pitfalls include: using the formula $O + tD$ to switch levels does not guarantee that the ray crosses the plane due to floating-point issues, leading to outliers in depth and normal buffers; and the method allows rays to traverse through corners, which can cause problems with surface normals [S4, unofficial].

## Operating characteristics
**Time Complexity:** Depends on the sparsity of the volume and the depth of the hierarchy. In the worst case (fully dense volume), it visits all voxels at the finest level, similar to flat traversal, but with overhead for hierarchy management. In sparse volumes, it skips large empty regions at coarse levels, offering significant speedups.
**Memory Complexity:** Requires storage for the hierarchical grid data and the lookup tables. The lookup tables add memory overhead proportional to the number of voxels at each level.
**Measured Performance:** Specific performance metrics for the general method are not given in the sources. However, a related method, KD-Tree Partitioned Volume Rendering, reported 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].
**Strengths:** Efficiently skips empty space in sparse volumes; leverages pre-computed lookup tables for fast child index retrieval; suitable for GPU implementation via vectorized operations [S1, unofficial].
**Limitations:** Requires pre-computation of lookup tables; floating-point precision issues can cause outliers in depth/normal buffers when switching levels (e.g., Teardown method) [S4, unofficial]; corner traversal can lead to incorrect surface normals [S4, unofficial].
**When to use:** Sparse hierarchical volume data where empty space skipping is beneficial.
**When not to use:** Dense volumes where the overhead of hierarchy traversal outweighs the benefits; when high precision at level boundaries is critical and floating-point errors are unacceptable.

## Background
Hierarchical Grid Traversal is a technique used in image-order volume rendering to accelerate ray traversal through multi-resolution grid structures. It builds on the concept of ray-grid traversal [17-ray-grid-traversal.md] and utilizes lookup tables to map parent voxels to children, enabling efficient skipping of empty regions. The method is implemented in various forms, such as the table-based approach in `Jax-Volumetric-Renderer` [S1, unofficial] and the HDDA-based `TreeMarcher` in `HNanoSolver` [S2, unofficial]. The Teardown game engine also employs a variant of this method, using DDA within levels and rescaling for level transitions [S4, unofficial].
