# Multi-level Grid Structures

Also called: Hierarchical Grids, Two-Level Grids, Macrocell Grids, Multi-Level Array Grids

## Overview
Multi-level Grid Structures are a family of hierarchical acceleration techniques for ray-grid traversal that use nested uniform grids to skip empty space or coarse regions, reducing the number of intersection tests. They differ from sibling methods like [Octree-based traversal](5348-octree-based-traversal.md) by maintaining fixed-depth or fixed-structure grid layouts (often rectangular blocks) rather than arbitrary tree topologies, and from [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by often relying on simpler boolean flags or dense array mappings rather than complex DDA state machines for level transitions.

## Shared principles
All methods in this family share the core mechanism of superimposing a coarse grid over a finer underlying data structure to enable block-wise skipping. The traversal algorithm typically operates in two phases:
1.  **Coarse Traversal:** The ray is stepped through the coarse grid. If a coarse cell (macrocell, top-level cell, or block) is marked as empty, the ray advances by the size of that block, skipping all internal fine cells.
2.  **Fine Traversal:** If a coarse cell is marked as occupied, the ray enters the sub-grid or fine grid region and performs standard traversal (e.g., DDA) within that local coordinate space.

Mathematically, if the coarse grid has resolution $N_c$ and the fine grid has resolution $N_f$, the skipping factor is roughly $N_f / N_c$. The data structure must map a ray's position in the coarse grid to the corresponding sub-grid or offset in the fine grid. Common implementations use:
*   **Boolean Flags:** A single bit per coarse cell indicating occupancy [S1, S2, unofficial].
*   **Pointer Arrays:** An array of pointers to sub-grids, where `null` indicates an empty block [S1, S2, unofficial].
*   **Index Arrays:** A flat array storing start/end indices into a primitive list for each leaf cell [S1, unofficial].

## Subtopics

### [Multi-Level Array Grid](3329-multi-level-array-grid.md)
A dense, recursive grid structure that subdivides the scene bounding box based on item density using a deterministic heuristic. It differs from siblings by using a fixed heuristic for grid dimensions ($M_i$) and explicit null pointers for empty cells, ensuring a predictable memory layout. It is chosen when a simple, array-based baseline is needed, though it may suffer from fragmentation in sparse scenes.

### [Two-Level Grids for Ray Tracing on GPUs](4245-two-level-grids-for-ray-tracing-on-gpus.md)
A fixed-depth hierarchical structure designed for GPUs, consisting of a sparse top-level grid where each cell contains a sub-grid (leaf grid) of arbitrary resolution. It solves the "teapot in a stadium problem" by allowing variable resolution sub-grids. It differs from [Macrocell Grid Traversal](5207-macrocell-grid-traversal.md) by explicitly constructing distinct leaf-level uniform grids for each top-level cell, enabling SIMD-friendly traversal with minimal code divergence.

### [Macrocell Grid Traversal](5207-macrocell-grid-traversal.md)
A lightweight optimization that superimposes a coarse grid of boolean flags over a base uniform fine grid. It differs from other hierarchical methods by using a simple boolean flag per macrocell, making it trivial to build and suitable for medium-size animated scenes. It allows the ray to jump over blocks of empty fine cells in a single step.

#### Hierarchical Grid (hgridf) Renderer
*   **Definition:** A renderer for hierarchical grids that combines primitive generation and rendering in a single pass, updating only 'dirty' cells to support interactive editing [S1, unofficial].
*   **Step:** Traverse the top-level grid and visit each grid-cell unless it is empty. Check if the current grid-cell is 'dirty' (voxels have changed since the last visit). If dirty, use the associated point or polygon engine to regenerate the local isosurface representation for that cell. Mark the cell as 'clean' after regeneration [S1, unofficial].
*   **Parameter:** The hierarchical grid uses a top-level $N \times N \times N$ grid and sub-grids of size $M \times M \times M$, where $M=16$ [S1, unofficial].

## Background
The concept of hierarchical grids originated in the early 1990s as a way to save space and accelerate rendering for synthetic volumes representing solids of homogeneous material, which contain large regions of uniformly inside or outside voxels [S1, unofficial]. The "hgrid" (hierarchical grid) was introduced as an $N \times N \times N$ top-level grid where each cell is either empty or an $M \times M \times N$ sub-grid [S1, unofficial]. This approach offered simplicity and constant-time access compared to the logarithmic time of octrees [S1, unofficial]. Later developments, such as the hgridf renderer, extended this to support interactive editing by tracking "dirty" cells for partial updates [S1, unofficial]. In the context of GPU ray tracing, two-level grids were developed to handle non-uniform primitive distributions efficiently, leveraging sort-based construction and SIMD-friendly traversal [S1, unofficial][S2, unofficial].
