# MERF Real-Time Rendering

Also called: MERF viewer, Three.js MERF renderer

## Overview
MERF Real-Time Rendering is a WebGL-based implementation for synthesizing views from Memory-Efficient Radiance Fields (MERF) using a multi-resolution occupancy grid hierarchy for empty space skipping [S1]. It differs from CUDA-based accelerators like Instant-NGP by prioritizing browser portability and memory efficiency, achieving real-time frame rates on consumer hardware by combining coarse-to-fine grid queries with deferred appearance sampling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** MERF scene representation (split into density texture and appearance texture containing diffuse RGB and feature vectors), camera parameters, and a multi-resolution occupancy grid hierarchy.
*   **Output:** Final image color per pixel.

**Data Structures:**
1.  **Occupancy Grid Hierarchy:** A set of binary textures representing spatial occupancy.
    *   **Construction:** Generated by max-pooling a full-resolution binary mask $A$ with filter sizes $F \in \{16, 32, 128\}$ [S1].
    *   **Resolution:** If the base resolution is $R$, the hierarchy levels have resolutions $R/16$, $R/32$, and $R/128$ [S1].
    *   **Storage:** Textures are encoded as PNGs to reduce video memory usage [S1].
2.  **Scene Textures:**
    *   **Density Texture:** Stores volume density $\sigma$.
    *   **Appearance Texture:** Stores diffuse RGB colors and feature vectors.
    *   **Layout:** Split into separate components to allow deferred access [S1].

**Algorithm Steps:**
1.  **Ray Initialization:** For each pixel, generate a ray origin $\mathbf{o}$ and direction $\mathbf{d}$ [S1].
2.  **Termination Check:** Initialize transmittance $T = 1.0$. If $T < 2 \times 10^{-4}$, terminate the ray [S1].
3.  **Coarse-to-Fine Query:**
    *   Iterate through the occupancy grid hierarchy from coarsest to finest level [S1].
    *   For the current sample position $\mathbf{x}$, compute grid indices for the current level.
    *   Query the occupancy grid at these indices.
    *   **Skip Logic:** If any level in the hierarchy indicates the voxel is empty (0), calculate the exit point of the empty block using ray-AABB intersection. Advance the ray sample position $\mathbf{x}$ to this exit point and restart the hierarchy query from the coarsest level [S1].
4.  **Scene Access:**
    *   If all levels in the hierarchy indicate the voxel is occupied (1), access the MERF scene representation [S1].
    *   **Deferred Sampling:**
        1.  Query the **Density Texture** at $\mathbf{x}$ to obtain $\sigma$ [S1].
        2.  Compute voxel opacity contribution. If $\sigma$ results in non-zero opacity, query the **Appearance Texture** at $\mathbf{x}$ to obtain color $\mathbf{c}$ and features [S1].
        3.  If $\sigma$ is zero (or effectively zero), skip reading the Appearance Texture [S1].
5.  **Volume Rendering:**
    *   Compute color contribution $C_{sample}$ and update transmittance $T$ using standard volume rendering integration (Eq. 1 in [S1]).
    *   Update sample position $\mathbf{x} \leftarrow \mathbf{x} + \Delta t \cdot \mathbf{d}$ [S1].
6.  **Loop:** Repeat steps 2–5 until $T < 2 \times 10^{-4}$ or the ray exits the scene bounds [S1].

```python
def render_ray(ray_origin, ray_direction, occupancy_grids, density_tex, appearance_tex):
    # Constants
    T_THRESHOLD = 2e-4
    FILTER_SIZES = [128, 32, 16] # Coarsest to finest
    
    t = 0.0
    T = 1.0
    accumulated_color = vec3(0.0)
    
    # Ray bounds could be scene-specific; assuming infinite or large bounds for skipping logic
    # In practice, ray-AABB intersection handles the skip boundaries
    
    while T > T_THRESHOLD:
        # 1. Query Occupancy Hierarchy
        current_pos = ray_origin + t * ray_direction
        skip = False
        
        # Check from coarsest to finest
        for level_idx in range(len(FILTER_SIZES)):
            filter_size = FILTER_SIZES[level_idx]
            # Map world position to grid index
            grid_idx = world_to_grid(current_pos, filter_size)
            
            # Query binary occupancy
            is_occupied = texture_lookup(occupancy_grids[level_idx], grid_idx)
            
            if is_occupied == 0:
                # Empty space detected: skip to the end of this block
                # Calculate intersection with the AABB of the empty block
                block_exit_t = ray_aabb_intersection(ray_origin, ray_direction, current_pos, filter_size)
                
                if block_exit_t is not None:
                    t = block_exit_t
                    skip = True
                    break # Restart hierarchy check from coarsest level at new position
        
        if skip:
            continue
            
        # 2. Access Scene Representation (All levels occupied)
        # Deferred sampling: check density first
        sigma = texture_lookup(density_tex, current_pos)
        
        if sigma > 0.0: # Non-zero opacity condition
            # Only read appearance if density is non-zero
            color, features = texture_lookup(appearance_tex, current_pos)
            
            # Volume rendering step (Eq. 1 from [S1])
            # alpha = 1 - exp(-sigma * delta_t)
            # accumulated_color += T * alpha * color
            # T *= 1 - alpha
            
            # Note: delta_t depends on sampling strategy; standard fixed step assumed if not specified
            delta_t = 0.01 # Placeholder for specific step size; [S1] uses Eq 1
            alpha = 1.0 - exp(-sigma * delta_t)
            
            accumulated_color += T * alpha * color
            T *= (1.0 - alpha)
            
        # Advance ray
        t += delta_t
        
    return accumulated_color
```

**Parameters:**
*   **Transmittance Termination Threshold:** $2 \times 10^{-4}$ [S1].
*   **Occupancy Grid Filter Sizes:** 16, 32, and 128 [S1].
*   **Base Resolution:** Example given as 4096, resulting in grid sizes 256, 128, and 32 [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** Ray-AABB intersection must be robust to avoid jittering at block boundaries [S1].
*   **Memory Layout:** The MLP optimization relies on linear memory access patterns; improper texture layout can negate speed gains [S1].
*   **Empty Space:** Skipping logic must correctly handle the transition between grid levels to avoid missing thin occupied structures [S1].

## Operating characteristics
*   **Performance:** On an RTX 3090 GPU at 1920x1080 resolution, MERF renders at frame rates well above 100 FPS [S1]. In contrast, Instant-NGP achieves 4 FPS on the same hardware at the same resolution [S1].
*   **Memory:** MERF consumes approximately one-fifth of the video memory of SNeRG++ [S1].
*   **Hardware:** Implemented as a WebGL application (Three.js), making it portable across devices including mobile browsers, though performance varies by GPU [S1].
*   **Optimizations:**
    *   Loop unrolling of the deferred rendering MLP.
    *   Memory layout modifications for linear access.
    *   Exploitation of fast `mat4` multiplication.
    *   These optimizations provide an additional 4× speed-up [S1].
*   **Limitations:** Quality reduction compared to non-real-time methods is evident in background regions (e.g., 1.24 dB PSNR reduction compared to MobileNeRF on Macbook, though MobileNeRF uses 2x memory) [S1].

## Background
*   **Origin:** MERF (Memory-Efficient Radiance Fields) was introduced by [S1] to enable real-time view synthesis in unbounded scenes with limited memory.
*   **Implementation:** The real-time viewer is implemented as a Javascript 3D (Three.js) web application, orchestrated by a single GLSL fragment shader [S1].
*   **Context:** It builds upon SNeRG's implementation and uses the view-dependence model introduced by Hedman et al. [S1]. It is designed to be more portable than CUDA-based solutions like Instant-NGP [S1].
