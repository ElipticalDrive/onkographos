# Space Leaping

Also called: Space Leaping using Ray Coherence, Vikon Space Leaping System

## Overview
Space Leaping is an acceleration technique for direct volume rendering that exploits ray coherence to skip empty regions between the image plane and the first visible object. It solves the problem of wasted computation on transparent voxels in front of surfaces by using a lightweight buffer to determine skip distances. It differs from sibling methods like [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) and [Occupancy Grid and Map-Based Empty Space Skipping](3852-occupancy-grid-and-map-based-empty-space-skipping.md) by avoiding complex hierarchical data structures, instead relying on a single $N \times N$ buffer and a fixed leap pattern.

## How it works
Space Leaping operates by casting "space leap rays" at a lower frequency than the primary "detector rays" to probe the volume for the first non-empty voxel. The results are stored in a leap buffer, which is then used to accelerate the rendering of the remaining detector rays.

### Inputs and Outputs
*   **Input**: Volume dataset $V$, camera parameters (position, orientation, field of view), image resolution $N \times N$, sampling distance $d_s$.
*   **Output**: Rendered image with accelerated ray marching.

### Data Structures
*   **Leap Buffer**: A 2D array of size $N \times N$. Each element `leap_buffer[x][y]` stores an integer representing the number of samples the corresponding detector ray must traverse to reach the first non-empty cell.
    *   **Layout**: Contiguous memory block of $N^2$ integers.
    *   **Initialization**: All values initialized to 0 or a maximum skip value depending on implementation specifics, though typically computed from scratch per frame or view.

### Algorithm Steps

1.  **Leap Buffer Construction**:
    *   Cast space leap rays at a reduced rate. The source specifies leaping "one out of every 4 rays." This implies a strided or subsampled pattern across the image plane.
    *   For each space leap ray, march through the volume starting from the image plane.
    *   Identify the first sample point that lies inside a non-empty cell (a cell with non-zero density or opacity).
    *   Calculate the number of samples from the image plane to this first non-empty cell.
    *   Store this count in the `leap_buffer` at the corresponding pixel coordinates.
    *   **Boundary Condition Handling**: If the `leap_buffer` value is 0, it indicates that the space leap ray should not be leaped at all (the object is immediately adjacent or the ray hits the first sample). [G] In practice, a value of 0 usually means "no skip" or "skip 0 samples."

2.  **Ray Backtracking for Leap Rays**:
    *   If the first sample point of a space leap ray is found inside a non-empty cell, the ray is backtracked until the sample point is inside an empty cell.
    *   **Constraint**: The backtracking must not exceed the value stored in the `leap_buffer` for that ray's position, to prevent the ray from moving behind the image plane.
    *   The number of samples to backtrack depends on the sampling distance $d_s$. The upper limit for backtracking samples is calculated by dividing the cell size by $d_s$.

3.  **Detector Ray Rendering**:
    *   For each pixel $(x, y)$, cast a detector ray.
    *   Retrieve the skip count $S$ from `leap_buffer[x][y]`.
    *   Skip the first $S$ samples along the ray.
    *   Begin volume integration (compositing) from sample $S+1$ until the ray exits the volume or transmittance becomes negligible.

### Formulas
*   **Skip Distance**: The physical distance skipped is $S \times d_s$, where $S$ is the value in the leap buffer and $d_s$ is the sampling distance.
*   **Backtracking Limit**: The maximum number of samples to backtrack is $\lceil \frac{\text{cell\_size}}{d_s} \rceil$.

### Parameters
*   **Leap Stride**: The source specifies leaping one out of every 4 rays. This specific ratio yields 75% of the possible acceleration compared to optimal skipping.
*   **Sampling Distance ($d_s$)**: Determines the granularity of the leap.

### Edge Cases and Pitfalls
*   **Zero Leap Buffer Value**: If `leap_buffer[x][y] == 0`, the ray must not be leaped. The rendering should start from the first sample. [S1]
*   **Empty Space Beyond First Hit**: Space leaping is only possible between the image plane and the first object hit. Empty space beyond the first hit cannot be leaped using this method. [S1]
*   **Boundary Accuracy**: Objects projecting exclusively onto the edges of the image buffer must be handled carefully to avoid erroneous skipping. This is often addressed by a [Boundary Pixel Detector Ray Casting](5870-boundary-pixel-detector-ray-casting.md) mechanism, treating boundary pixels as mandatory detectors. [S1]

## Subtopics

### Leap Buffer Boundary Condition Handling
This is a specific procedural detail within Space Leaping. The leap buffer stores the number of samples to reach a non-empty cell. The sample immediately preceding this non-empty cell is the last sample in an empty cell. A critical pitfall is that if the leap buffer value is zero, the space leap ray should not be leaped at all. Additionally, if the first sample of a leap ray is in a non-empty cell, the ray is backtracked to an empty cell, but this backtracking must not exceed the leap buffer value to avoid moving behind the image plane. [S1]

## Operating characteristics
*   **Time Complexity**: $O(N^2)$, where $N$ is the image dimension. The primary cost is filling the leap buffer, which scans the buffer once. [S1]
*   **Memory Complexity**: $O(N^2)$. Requires a single buffer of size $N \times N$ integers. For a 256x256 image, this is 256x256 bytes (assuming 1-byte integers or similar compact storage). [S1]
*   **Performance**: Achieved speedups of up to 165% over non-space leap ray casting on a Pentium-IV, 2.6GHz PC with 1GB RAM. [S1]
*   **Strengths**: Low memory overhead, suitable for systems with limited resources (e.g., virtual endoscopy). Simple to implement.
*   **Limitations**: Cannot achieve as much empty space skipping as techniques using detailed data structures (like occupancy grids) because it only leaps one out of every 4 rays, capturing only 75% of possible acceleration. [S1]
*   **Usage Context**: Ideal for virtual endoscopy (e.g., Virtual Colonoscopy) and applications where the camera is close to the object surface, ensuring objects project over many pixels. Also suitable for high-resolution volume rendering with orthographic and perspective projections. [S1]

## Background
Space Leaping was incorporated into the **Vikon** system, a perspective direct volume rendering system designed for interactive navigation in 3D datasets, particularly for endoscopy applications like Virtual Colonoscopy. The technique was developed to address the need for interactive rendering speeds while minimizing memory overhead, which is critical for physics-based navigation systems using potential fields. The method leverages the fact that in endoscopic views, there is often significant empty space in front of the camera, making ray coherence a viable optimization target. [S1]
