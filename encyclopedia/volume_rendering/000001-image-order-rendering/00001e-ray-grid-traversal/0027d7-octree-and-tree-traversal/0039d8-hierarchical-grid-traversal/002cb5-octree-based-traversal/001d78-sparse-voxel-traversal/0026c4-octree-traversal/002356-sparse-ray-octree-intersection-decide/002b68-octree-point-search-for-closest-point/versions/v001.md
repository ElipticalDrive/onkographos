# Octree Point Search for Closest Point

Also called: PinholeRayTracer::evaluate (Octree)

## Overview
This method efficiently identifies the closest point to a ray origin among all points intersected by a set of rays, filtering by a maximum range. It differs from sibling methods like [Sparse Ray-Octree Intersection (DECIDE)](3006-sparse-ray-octree-intersection-decide.md) by operating on discrete point clouds indexed by an octree rather than continuous occupancy grids, and from [Octree Voxel-Triangle Intersection Test](3316-octree-voxel-triangle-intersection-test.md) by returning point indices rather than geometric intersection primitives. It is primarily used in Next-Best-View (NBV) planning to simulate sensor observations of a point cloud environment [S1, unofficial].

## How it works
**Inputs:**
- `viewpoint_`: An `Eigen::Affine3f` defining the camera position and orientation. The origin `rayo` is extracted via `viewpoint_.translation()` [S1, unofficial].
- `octree_search`: An instance of `pcl::octree::OctreePointCloudSearch<PointT>` providing spatial indexing for the input point cloud `cloud` [S1, unofficial].
- `rangeMax_`: A float representing the maximum sensor range. Default is `100000.0f` [S1, unofficial].
- `hsize_`, `vsize_`: Half-width and half-height of the image grid in pixels [S1, unofficial].
- `res_`: The resolution (size of the box) or pixel scale [S1, unofficial].
- `hfov_`, `vfov_`: Horizontal and vertical field of view in radians [S1, unofficial].

**Outputs:**
- `indices`: A `pcl::PointIndices` object containing the indices of the closest valid points for each ray [S1, unofficial].

**Data Structures:**
- `rayds`: `std::vector<Eigen::Vector3f>` storing ray directions.
- `viewed`: `std::set<int>` tracking processed point indices to avoid duplicates.
- `points_idx`: `std::vector<int>` accumulating point indices from intersected voxels.
- `voxels`: Temporary storage for voxel centers intersected by the ray.

**Steps:**
1. **Initialize Ray Origin:** Extract `rayo` from `viewpoint_.translation()` [S1, unofficial].
2. **Generate Rays:** Call `castRays(rayds)` to populate the ray direction vector. This function generates rays based on `hfov_`, `vfov_`, `hsize_`, and `vsize_` [S1, unofficial].
3. **Initialize Tracking:** Create an empty set `viewed` to store processed point indices [S1, unofficial].
4. **Iterate Rays:** Loop over each ray direction `rayds[i]` for `i` from `0` to `rayds.size() - 1`.
5. **Find Intersected Voxels:** Call `octree_search.getIntersectedVoxelCenters(rayo, rayds[i], voxels)` to retrieve the centers of all voxels intersected by the current ray [S1, unofficial].
6. **Collect Point Indices:** For each intersected voxel in `voxels`:
   - Call `octree_search.voxelSearch(voxels[h], points_idx_temp)` to get indices of points within that voxel.
   - Append `points_idx_temp` to `points_idx` [S1, unofficial].
7. **Find Closest Point:**
   - Initialize `idxmin = -1` and `distMin = 1e+6` [S1, unofficial].
   - Loop over each point index `idx` in `points_idx`:
     - Retrieve point `pt` from the cloud using `points_idx[idx]`.
     - Convert `pt` to `Eigen::Vector3f ept` [S1, unofficial].
     - Calculate distance `dist = (ept - rayo).norm()` [S1, unofficial].
     - If `dist < rangeMax_` AND `dist < distMin`:
       - Update `idxmin = points_idx[idx]`.
       - Update `distMin = dist` [S1, unofficial].
8. **Record Result:** If `idxmin >= 0` and `idxmin` is not in `viewed`:
   - Add `idxmin` to `indices.indices`.
   - Insert `idxmin` into `viewed` [S1, unofficial].

**Pseudocode:**
```python
def evaluate_octree_point_search(viewpoint, octree_search, cloud, range_max, hfov, vfov, hsize, vsize):
    rayo = viewpoint.translation()
    rayds = cast_rays(hfov, vfov, hsize, vsize)
    viewed = set()
    indices = []

    for ray_dir in rayds:
        voxels = octree_search.get_intersected_voxel_centers(rayo, ray_dir)
        points_idx = []
        
        for voxel_center in voxels:
            points_idx_temp = octree_search.voxel_search(voxel_center)
            points_idx.extend(points_idx_temp)
        
        idxmin = -1
        dist_min = 1e6
        
        for idx in points_idx:
            pt = cloud[idx]
            ept = Eigen.Vector3f(pt.x, pt.y, pt.z)
            dist = (ept - rayo).norm()
            
            if dist < range_max and dist < dist_min:
                idxmin = idx
                dist_min = dist
        
        if idxmin >= 0 and idxmin not in viewed:
            indices.append(idxmin)
            viewed.add(idxmin)
            
    return indices
```

**Parameters:**
- `rangeMax_`: Default `100000.0f` [S1, unofficial].
- `RES`: Default `0.02f` (box resolution) [S1, unofficial].
- `HFOV`, `VFOV`: Default `M_PI * 160.0f / 180.0f` (approx 2.79 rad) [S1, unofficial].
- `HSIZE`, `VSIZE`: Default `6` and `4` in the example, but commented out values suggest `320` and `240` are typical [S1, unofficial].

**Edge Cases:**
- If no points are within `rangeMax_` or intersected by the ray, `idxmin` remains `-1` and no index is added [S1, unofficial].
- Duplicate points across voxels are handled by the `viewed` set, ensuring each point is only recorded once per ray traversal session [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Dominated by voxel traversal and point retrieval. For each ray, the cost is proportional to the number of intersected voxels times the average number of points per voxel. In dense regions, this can be high.
- **Memory Complexity:** Requires storage for the octree, the point cloud, and temporary vectors for voxel centers and point indices per ray.
- **Strengths:** Efficiently filters points by spatial proximity and range. Simple to implement using existing PCL octree search primitives.
- **Limitations:** Not a true ray-triangle intersection; it finds the closest *point* in the cloud, which may not lie exactly on the ray path (nearest neighbor in 3D space within the ray's voxel footprint). Performance degrades with high point density in voxels.
- **When to use:** When simulating a range sensor on a sparse or moderately dense point cloud where exact geometric intersection is less critical than finding the nearest observed surface point.
- **When not to use:** For precise ray-triangle intersection or when the point cloud is extremely dense, leading to excessive point checks per voxel.

## Background
This method originates from the `basic_next_best_view` project by R. Monica, implemented in C++ using the Point Cloud Library (PCL) [S1, unofficial]. It is part of a pipeline for autonomous exploration, where the robot simulates views to determine the next best viewpoint. The `PinholeRayTracer` class encapsulates this logic, treating the point cloud as an occupancy map [S1, unofficial].
