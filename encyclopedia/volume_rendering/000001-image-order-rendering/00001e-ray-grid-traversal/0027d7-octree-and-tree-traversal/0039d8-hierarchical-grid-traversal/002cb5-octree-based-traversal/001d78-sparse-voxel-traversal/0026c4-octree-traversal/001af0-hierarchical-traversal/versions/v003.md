# Hierarchical Traversal

Also called: Kay & Kajiya Hierarchy Traversal, Kay-Kajiya traversal, Octree Hierarchical Traversal, Octree Navigation, Octree Node Activity Check

## Overview
Hierarchical Traversal is a ray-intersection method that accelerates volume rendering by traversing a spatial hierarchy (such as an Octree, Sparse Voxel Octree, or BVH) to skip empty space and coarsely approximate occupied regions [S1, S4, unofficial]. It solves the performance bottleneck of single-resolution discrete ray-tracing by allowing larger steps through empty areas [S1, unofficial]. Unlike sibling methods like [Sparse Voxel Octree Ray Traversal](933-sparse-voxel-octree-ray-traversal.md) which target specific sparse voxel layouts, this method provides a general framework for any hierarchical grid structure [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $O$, direction $D$, a hierarchical data structure (Octree, SVO, or BVH), and a maximum traversal distance $t_{max}$ (typically 10000.0) [S2, unofficial].
*   **Output:** A sequence of visited nodes/voxels in front-to-back order, or a boolean indicating if an intersection exists within $t_{max}$ [S2, unofficial].

**Data Structures:**
The layout depends on the hierarchy type:
1.  **Octree/SVO:** Nodes store pointers to 8 children or an activity flag [S1, S5, unofficial]. Level $k$ cells cover a $2^k \times 2^k$ area of level 0 [S1, unofficial].
2.  **BVH:** Nodes are stored in a buffer. A `BVHNode` struct contains `center` (`f32[4]`), `radius` (`f32`), `left_child` (`u32`), and `right_child` (`u32`), packed in 16-byte alignment [S2, unofficial]. Leaf nodes are identified by setting the high bit (`0x80000000`) of the child indices; if a leaf is the last element and has no sibling, `right_child` is set to `0` [S2, unofficial].

**Algorithm Steps:**
The traversal uses a stack-based descent [S2, unofficial]. At each node, the ray is tested against the bounding volume [S2, S4, unofficial]. If it intersects, the algorithm checks if the node is a leaf [S2, unofficial]. If not, it computes intersection distances to both children, pushes the farther child onto the stack first, and descends into the closer child [S2, unofficial].

```python
def traverse_hierarchy(ray_origin, ray_direction, hierarchy, max_t=10000.0):
    stack = [0]
    visited = []
    
    while stack:
        node_idx = stack.pop()
        node = hierarchy.nodes[node_idx]
        
        # Compute bounding box from center and radius
        center = node.center[:3]
        radius = node.radius
        bv_min = [center[i] - radius for i in range(3)]
        bv_max = [center[i] + radius for i in range(3)]
        
        t_min = ray_box_intersect(bv_min, bv_max, ray_origin, ray_direction, max_t)
        if t_min == float('inf'):
            continue
            
        if node.is_leaf:
            visited.append(node_idx)
            continue
            
        # Mask out high bit to get actual child indices
        left_idx = node.left_child & 0x7FFFFFFF
        right_idx = node.right_child & 0x7FFFFFFF
        
        left_node = hierarchy.nodes[left_idx]
        right_node = hierarchy.nodes[right_idx]
        
        left_center = left_node.center[:3]
        right_center = right_node.center[:3]
        left_radius = left_node.radius
        right_radius = right_node.radius
        
        left_t = ray_box_intersect(
            [left_center[i] - left_radius for i in range(3)],
            [left_center[i] + left_radius for i in range(3)],
            ray_origin, ray_direction, max_t
        )
        right_t = ray_box_intersect(
            [right_center[i] - right_radius for i in range(3)],
            [right_center[i] + right_radius for i in range(3)],
            ray_origin, ray_direction, max_t
        )
        
        if left_t < max_t and right_t < max_t:
            # Push farther child, descend into closer child
            if left_t < right_t:
                stack.append(right_idx)
                node_idx = left_idx
            else:
                stack.append(left_idx)
                node_idx = right_idx
            continue
        elif left_t < max_t:
            node_idx = left_idx
            continue
        elif right_t < max_t:
            node_idx = right_idx
            continue
        # If neither intersects, loop continues (node already popped)
            
    return visited

def ray_box_intersect(bv_min, bv_max, ray_origin, ray_direction, max_t):
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if ray_direction[i] == 0.0:
            if ray_origin[i] < bv_min[i] or ray_origin[i] > bv_max[i]:
                return float('inf')
        else:
            t1 = (bv_min[i] - ray_origin[i]) / ray_direction[i]
            t2 = (bv_max[i] - ray_origin[i]) / ray_direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    return t_min if t_min < max_t and t_max > 0.0 else float('inf')
```

**Parameters:**
*   **Stopping Depth:** In two-pass hierarchy traversal, the first step stops at a specific depth relative to the leaves (e.g., depth=3) [S8].

**Edge Cases and Pitfalls:**
*   **Precision:** Zero direction components require an epsilon guard to avoid division by zero [G].
*   **Leaf Identification:** Leaf nodes are identified by the high bit (`0x80000000`) of child indices [S2, unofficial].
*   **Boundary Voxels:** When a ray exits the grid bounds, `step_mask` logic must be applied to clamp traversal or return false [S2, unofficial].

## Subtopics

### [Leaf Collection](899-leaf-collection.md)
Leaf Collection extracts terminal nodes from a hierarchical spatial structure into a linear list for batch processing [G]. It decouples traversal from ray-casting, differing from methods like [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) that integrate traversal into rasterization [G].

### [Point Plane Test Traversal](982-point-plane-test-traversal.md)
A traversal algorithm for TET-AMR refinement trees that identifies the child tetrahedron containing a sample point by performing plane tests against the midpoints of the parent tetrahedron's edges [G].

### [Mesh BVH](1062-mesh-bvh.md)
Mesh BVH is a GPU-accelerated bounding volume hierarchy designed for triangle meshes to perform efficient distance queries, serving as the geometric backend for signed distance field (SDF) representations in volume rendering pipelines. It enables fast evaluation of point-to-mesh distance, closest point location, and topological properties (sign, winding number) required for ray-marching or grid-based rendering. Unlike hierarchical voxel traversals that operate on implicit grid structures, this method operates directly on explicit triangle geometry, making it suitable for high-frequency surface details that would be prohibitive to store in a dense or even sparse voxel grid.

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
The Hierarchical Digital Differential Analyzer (HDDA) is a specialized ray-traversal algorithm for sparse voxel grids that performs multi-resolution leapfrogging to efficiently determine voxels or tiles intersected by a ray. It leverages the compile-time fixed tree configuration of the underlying data structure to inline and collapse the hierarchical traversal, reducing the overhead of vertical tree navigation.

### [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md)
A rendering technique using k-d tree nodes to store approximations of data (nodal models) with associated error terms. If the error is below a user-specified threshold, the nodal region is drawn using the approximation; otherwise, traversal continues [G].

### [VolumeHDDA](2353-volumehdda.md)
A class for volume traversal using a hierarchical DDA approach, specialized for leaf nodes [G].

### [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md)
Uses a BVH built over a coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point, allowing skipping of non-sampled elements.

### [Node Omission in Ray-Tree Traversal](3305-node-omission-in-ray-tree-traversal.md)
An optimization that prevents adding nodes to the traversal stack if it is known they will not intersect the ray, reducing the number of intersection tests [G].

### [Adaptive Out-of-Core Single-Pass GPU Raycasting](3440-adaptive-out-of-core-single-pass-gpu-raycasting.md)
An adaptive out-of-core technique for rendering massive scalar volumes employing single pass GPU raycasting. It decomposes a volumetric dataset into small cubical bricks organized into an octree structure maintained out-of-core. The octree contains original data at leaves and filtered representations of children at inner nodes. An adaptive loader on the CPU updates a view- and transfer function-dependent working set of bricks on GPU memory by asynchronously fetching data. A compact indexing structure spatially organizes the working set into an octree hierarchy encoded in a small texture, exploited by a stackless raycasting algorithm [G].

### [Octree Traversal](3859-octree-traversal.md)
The base hierarchical indexing mechanism using 2x2x2 subdivisions [G].

### Surface Descendant Check
A recursive function to determine if a node or any of its descendants are marked as active or contain a surface [S3, unofficial]. If the cell is a Leaf, it returns whether it has a sign change [S3, unofficial]. If it is a Branch, it recursively checks if any of its children have a surface descendant [S3, unofficial]. If it is Empty or Full, it returns false [S3, unofficial].

### Coarse Mesh Traversal via BVH
Uses a Bounding Volume Hierarchy (BVH) built over the coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point [S6, unofficial]. The BVH is built by inserting four triangular faces facing outside for every coarse element [S6, unofficial]. Rays are traced using hit/miss functions; the hit function returns the hit point and coarse tetrahedron ID [S6, unofficial]. Unlike element marching, this allows skipping coarse elements and varying refinement levels [S6, unofficial].

### Perspective-Correct AMR Patch Traversal
A hybrid CPU-GPU strategy where the CPU traverses a KD-tree of AMR patches back-to-front, and the GPU traverses cells within a patch [S7]. Sub-patches are generated to ensure perspective-correct sorting of cells relative to the observer [S7]. The vertex shader modifies indices based on the observer position to ensure proper cell ordering [S7].

### Two-Pass Hierarchy Traversal
An optimization that splits traversal into two steps with a stopping depth in the first step [S8]. Step 1 traverses down to a specific depth relative to the leaves (e.g., depth=3) [S8]. Step 2 traverses the remaining lower part for nodes identified in Step 1 [S8]. At optimal stopping depth (3), it reduces time by 15% alone, and up to 30% with tile sharing [S8]. If stopping depth is 0, performance equals the direct implementation [S8].

## Operating characteristics
*   **Time Complexity:** Generally $O(\log N)$ for balanced hierarchies, where $N$ is the number of voxels/objects, compared to $O(N)$ for linear traversal [G].
*   **Memory Complexity:** Depends on the hierarchy; Octrees require storing node pointers, while SVOs store only non-empty nodes, reducing memory usage significantly for sparse data [S1, unofficial].
*   **Performance:** Hierarchical SVO traversal took 5 steps to intersect an occupied voxel compared to 11 steps for non-hierarchical traversal in example grids [S1, unofficial].
*   **Strengths:** Efficiently skips empty space and supports multi-resolution rendering [S1, unofficial].
*   **Limitations:** Traversal overhead for very dense or small scenes may negate benefits [G].

## Background
Hierarchical traversal was introduced by Kay and Kajiya in 1986 as a method for speeding up ray-object intersection calculations using a hierarchy of extents [S4, unofficial]. It has since been adapted for volume rendering, particularly with Sparse Voxel Octrees (SVO) and Octrees, to take larger steps through empty space and speed up the process [S1, unofficial].
