# Neighbor Finding

Also called: Octree Hashing (Neighbor-Finding)

## Overview
Neighbor finding locates the octree node containing a destination coordinate (`dest`) starting from a known origin node (`start`) and its depth [S1]. It solves the problem of traversing between arbitrary nodes in a sparse voxel octree without storing explicit parent pointers, by backtracing up the hierarchy to find a common ancestor and then descending to the target [S3, unofficial]. It differs from sibling methods like [Morton Key Vertex Neighbor Iteration](3318-morton-key-vertex-neighbor-iteration.md) by operating on coordinate bits directly rather than Morton keys, and by supporting arbitrary (non-adjacent) neighbor lookups through a two-phase ascent-descent process [S4].

## How it works
**Inputs and Outputs:**
*   `start`: The 3D integer coordinates of the origin node [S1].
*   `dest`: The 3D integer coordinates of the destination node [S1].
*   `depth`: The depth level of the `start` node in the octree [S1].
*   `parent_trace`: An array of node indices (or pointers) representing the path from the root to the `start` node, filled by the ray traversal algorithm [S3, unofficial].
*   **Output**: The index (or pointer) of the node containing `dest` [S1].

**Data Structures:**
*   `child_bit_depth`: A precomputed array where `child_bit_depth[d]` is a bitmask isolating the bits of the coordinate at depth `d` [S1].
*   `parent_trace`: An array of size `max_depth + 1` containing the indices of all parent nodes for the current cap [S3, unofficial].

**Algorithm Steps:**
1.  Iterate from the current `depth` down to 0 [S2, unofficial].
2.  Retrieve the bitmask for the current level: `child_bit = child_bit_depth[up]` [S1].
3.  Check if `start` and `dest` share the same parent at this level by masking both coordinates with `child_bit` and performing integer equality [S3, unofficial].
4.  If the condition is true, `start` and `dest` are in the same child of the node at level `up + 1` [S2, unofficial].
5.  The common ancestor is `parent_trace[up]` [S1].
6.  Call `point_locate(dest, up, parent_trace[up])` to descend from the common ancestor to the leaf node containing `dest` [S1].
7.  If the loop completes without returning, the nodes are in different subtrees of the root [S1].
8.  Check if they are in the same child of the root using the mask from the last iteration (`up=0`) [S2, unofficial].
9.  If they match at the root level, call `point_locate(dest, 0, 0)` assuming the root index is 0 [S1].
10. If they do not match, the destination is outside the octree bounds [S1].

**Pseudocode:**
```python
def neighbor_find(start: Vec3i, dest: Vec3i, depth: int, parent_trace: List[int], child_bit_depth: List[int]) -> int:
    """
    Finds the node index for 'dest' starting from 'start' at 'depth'.
    Uses parent_trace to ascend without explicit parent pointers.
    """
    child_bit = 0  # Initialize to prevent undefined value after loop exit
    for up in range(depth, -1, -1):
        child_bit = child_bit_depth[up]
        if ((dest.x & child_bit) == (start.x & child_bit) and
            (dest.y & child_bit) == (start.y & child_bit) and
            (dest.z & child_bit) == (start.z & child_bit)):
            return point_locate(dest, up, parent_trace[up])
    # Root node check
    if ((dest.x & child_bit) == (start.x & child_bit) and
        (dest.y & child_bit) == (start.y & child_bit) and
        (dest.z & child_bit) == (start.z & child_bit)):
        return point_locate(dest, 0, 0)
    return 0

def point_locate(dest: Vec3i, start_depth: int, node_idx: int) -> int:
    """
    Standard octree descent from start_depth to 0 using dest coordinates.
    Assumes child_bit_depth masks are powers of two and children are contiguous. [G]
    """
    for d in range(start_depth, 0, -1):
        cb = child_bit_depth[d]
        cx = (dest.x & cb) >> (cb.bit_length() - 1)
        cy = (dest.y & cb) >> (cb.bit_length() - 1)
        cz = (dest.z & cb) >> (cb.bit_length() - 1)
        child_idx = (cx << 2) | (cy << 1) | cz
        node_idx = parent_trace[d] + child_idx
    return node_idx
```

**Parameters:**
*   `child_bit_depth`: Typically precomputed for the coordinate bit-width and octree depth [S1].

**Edge Cases and Pitfalls:**
*   **Parent Pointers**: Parent pointers are omitted from the octree nodes to minimize memory footprint [S3, unofficial].
*   **Non-Adjacent Neighbors**: This algorithm finds the node containing `dest`, which may not be an immediate neighbor of `start` [S4].
*   **Root Handling**: The root node is typically at index 0 in the `parent_trace` array [S1].

## Subtopics

### Octree Neighbor Finding without Parent Pointers
Neighbor finding locates the voxel at a coordinate direction relative to an origin node by recursing up the octree to find a common parent containing both nodes, then using point location to find the destination leaf [S4]. Parent pointers are omitted to minimize memory footprint, and recursion up the tree requires knowledge of parent indices which are provided by the ray traversal algorithm filling an `index trace[]` array containing indices of all parent nodes for a given cap [S4]. Unlike Frisken and Perry's method using exclusive OR with depth masks, this implementation uses &-masking both source and destination coordinates and performing integer equality to find common parents, as it is not more expensive [S4].

## Operating characteristics
*   **Time Complexity**: The ascent phase is $O(D)$ where $D$ is the depth of the octree, and the descent phase (`point_locate`) is also $O(D)$, yielding a total time of $O(D)$ [S3, unofficial].
*   **Memory Complexity**: $O(1)$ additional memory beyond the `parent_trace` array, which requires $O(D)$ space, and no parent pointers are stored in the node structure itself [S3, unofficial].
*   **Strengths**: Memory efficient due to lack of parent pointers, uses simple bitwise operations for ascent, and supports arbitrary neighbor lookups [S4].
*   **Limitations**: Requires the `parent_trace` array to be maintained by the traversal algorithm, and is not faster than XOR-based methods for immediate neighbor lookups [S4].
*   **When to Use**: When memory is constrained and parent pointers are undesirable, or when the traversal algorithm already maintains a path trace [S3, unofficial].
*   **When Not to Use**: When immediate neighbor lookups are frequent and an XOR-based method is preferred for that specific case [S4].

## Background
The method originates from interactive isosurface ray tracing of large octree volumes [S1]. It was developed to optimize memory usage in sparse voxel octrees by removing explicit parent pointers and relying instead on the traversal context to provide parent indices [S3, unofficial].
