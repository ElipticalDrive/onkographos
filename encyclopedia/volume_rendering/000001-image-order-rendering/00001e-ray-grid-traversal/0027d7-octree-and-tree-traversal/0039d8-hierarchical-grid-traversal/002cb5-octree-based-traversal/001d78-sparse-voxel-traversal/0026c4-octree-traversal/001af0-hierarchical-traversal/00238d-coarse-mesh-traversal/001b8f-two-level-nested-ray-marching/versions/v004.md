# Two-level Nested Ray Marching

Also called: Front-to-back ray marching on AMR, Ray Marching with Coarse Mesh and Refinement Tree

## Overview
Two-level nested ray marching is a volume rendering technique that performs front-to-back compositing using a constant adjustable step size within a hierarchical data structure [S1, unofficial]. It solves the problem of efficiently rendering adaptive mesh refinement (AMR) or tetrahedral data by decoupling the traversal of the global scene into a coarse mesh (BVH) and the local sampling into a refinement tree [S1, unofficial]. Unlike uniform grid resampling which causes $(2^{l_{max}})^3$ memory blow-up, this method steps by the local cell size, keeping computational cost proportional to the actual simulation data rather than the bounding box [S2, unofficial]. It sets itself apart from its sibling [Coarse Mesh Traversal with Dual-Ray Culling](987-coarse-mesh-traversal-with-dual-ray-culling.md) by relying on a fixed step size rather than adaptive or dual-ray boundary handling for the inner loop, and from [Varying Refinement Levels of Coarse Elements](1055-varying-refinement-levels-of-coarse-elements.md) by using a single refinement level per coarse element [S1, S2, unofficial].

## How it works
The method consists of an outer loop that traverses a coarse mesh to identify active regions and an inner loop that marches through the descendant elements within the refinement tree bounded by the coarse element's entry and exit distances [S1, S2, unofficial].

**Inputs:**
*   `ray`: Origin `org`, direction `dir`, current distance `t`.
*   `macrocellValues`: Array of maximum density values for each coarse element (macrocell).
*   `stepSize`: Constant adjustable step size for the inner march [S1, unofficial].
*   `tf`: Transfer function with methods `inRange(scalar)` and `getColor(scalar)` returning `{color, opacity}` [S1, unofficial].
*   `bgColor`: Background color [S1, unofficial].
*   `data`: Simulation data (e.g., gas density) accessible via `sampleData` [S1, S2, unofficial].

**Outputs:**
*   Final accumulated color.

**Data Structures:**
*   **Coarse Mesh:** A BVH where leaves are macrocells. Each macrocell has a precomputed `max_density` stored in `macrocellValues` [S1, unofficial].
*   **Refinement Tree:** A hierarchy of tetrahedra (or AMR leaves) associated with each coarse element. Each node/leaf stores vertex coordinates and scalar values [S1, S2, unofficial].
*   **AMR Volume Object:** Stores per-level hashes of leaves for direct access without resampling [S2, unofficial].

**Parameters:**
*   **Opacity Threshold:** 0.99. The ray marching loop continues while accumulated alpha is less than this value [S1, unofficial].
*   **Step Size:** Constant. No adaptive adjustments are implemented [S1, unofficial].

**Algorithm Steps:**

1.  Initialize `color` to $\{0,0,0\}$ and $\alpha$ to 0 [S1, unofficial].
2.  Loop while $\alpha < 0.99$:
    a.  Call `TraverseCoarseMesh(ray)` to get `coarseID`, `tBack` (entry distance into coarse element), and `tNextFace` (exit distance from coarse element) [S1, unofficial].
    b.  If `coarseID` is -1, break the loop [S1, unofficial].
    c.  Check if `macrocellValues[coarseID] <= 0`. If true, set `skipElement` to true; otherwise false [S1, unofficial].
    d.  If `!skipElement`, call `MarchElement(ray, color, alpha, tBack, coarseID, stepSize, tf)` [S1, unofficial].
    e.  Update `ray.t` to $\max(tNextFace, ray.t)$ to advance to the next coarse element [S1, unofficial].
3.  Return final color: $(1 - \alpha) \times bgColor + color$ [S1, unofficial].

**Inner Loop (`MarchElement`):**
1.  Initialize `tExit` to 0, `sampleTetID` to 0, and `tetVertices` to empty set [S1, unofficial].
2.  Loop while `ray.t < tMax` (where `tMax` is `tBack` or the exit of the coarse element) [S1, unofficial]:
    a.  Calculate `samplePoint` = `ray.org` + `ray.t` $\times$ `ray.dir` [S1, unofficial].
    b.  If `ray.t > tExit`:
        i.  Call `traverse(samplePoint, coarseTetID)` to get `sampleTetID` and `tetVertices` [S1, unofficial].
        ii. Calculate `tExit` by intersecting the ray with the faces of the current tetrahedron/element using `intersectFaces` [S1, unofficial].
    c.  Sample scalar value at `samplePoint` using `sampleData(samplePoint, sampleTetID, tetVertices)` [S1, unofficial].
    d.  Advance `ray.t` by `stepSize` [S1, unofficial].
    e.  If `!tf.inRange(scalar)`, continue to next iteration [S1, unofficial].
    f.  Get `tfColor` from `tf.getColor(scalar)` [S1, unofficial].
    g.  Compute effective opacity: `tfColor.opacity` = `tfColor.opacity` $\times$ `tf.opacity` [S1, unofficial].
    h.  Accumulate color and alpha using front-to-back compositing:
        $$color = color + (1 - \alpha) \times tfColor.opacity \times tfColor.color$$
        $$\alpha = \alpha + tfColor.opacity \times (1 - \alpha)$$
    i.  Note: The source pseudocode lists `tfColor` as a color value in the accumulation step but `tfColor.opacity` separately. Standard compositing requires the color component [S1, unofficial].
3.  Return `color` and $\alpha$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The method uses a constant step size, which can lead to aliasing or missed features if the step size is too large relative to the finest details [S1, unofficial].
*   **Boundary Handling:** The transition between coarse elements relies on `tNextFace`. Robust handling of the ray position update `ray.t = max(tNextFace, ray.t)` is required to prevent gaps or overlaps between coarse elements [S1, unofficial].
*   **Degenerate Input:** If `macrocellValues` are all zero, the algorithm skips all processing efficiently [S1, unofficial].

```python
def ray_march_coarse(ray, macrocell_values, step_size, tf, bg_color):
    color = [0.0, 0.0, 0.0]
    alpha = 0.0
    while alpha < 0.99:
        coarse_id, t_back, t_next_face = traverse_coarse_mesh(ray)
        if coarse_id == -1:
            break
        skip_element = macrocell_values[coarse_id] <= 0
        if not skip_element:
            color, alpha = march_element(ray, color, alpha, t_back, coarse_id, step_size, tf)
        ray.t = max(t_next_face, ray.t)
    return (1 - alpha) * bg_color + color

def march_element(ray, color, alpha, t_max, coarse_tet_id, step_size, tf):
    t_exit = 0
    sample_tet_id = 0
    tet_vertices = []
    while ray.t < t_max:
        sample_point = ray.org + ray.t * ray.dir
        if ray.t > t_exit:
            sample_tet_id, tet_vertices = traverse(sample_point, coarse_tet_id)
            t_exit = intersect_faces(ray.t, sample_point, ray.direction, tet_vertices)
        scalar = sample_data(sample_point, sample_tet_id, tet_vertices)
        ray.t = ray.t + step_size
        if not tf.in_range(scalar):
            continue
        tf_color = tf.get_color(scalar)
        effective_opacity = tf_color.opacity * tf.opacity
        color = color + (1 - alpha) * effective_opacity * tf_color.color
        alpha = alpha + effective_opacity * (1 - alpha)
    return color, alpha
```

## Subtopics

### AMR Volume Ray-Casting
A variant that ray-marches Adaptive Mesh Refinement (AMR) octrees directly without resampling to a uniform grid [S2, unofficial]. It avoids the $(2^{l_{max}})^3$ memory blow-up by storing each leaf once in a per-level hash and stepping by the local cell size of the current leaf node [S2, unofficial]. This ensures computational cost scales with the simulation data rather than the bounding box [S2, unofficial]. It differs from the standard two-level nested approach by explicitly managing per-level hashes and local cell sizes for stepping, often incorporating cross-level trilinear reconstruction to reduce blockiness from nearest-leaf sampling [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of samples taken, which depends on the step size and the density of the volume. The coarse mesh traversal culls empty regions, reducing the number of inner loop executions [S1, unofficial].
*   **Memory Complexity:** Scales with the actual simulation data (number of leaves/tetrahedra) rather than the bounding box volume, avoiding the exponential blow-up of uniform grids [S2, unofficial].
*   **Performance:** The constant step size simplifies the inner loop but may require smaller steps for high-quality results, impacting performance [S1, unofficial]. The coarse mesh culling provides significant speedup for sparse volumes [S1, unofficial].
*   **Strengths:** Efficient for sparse AMR data; avoids resampling artifacts and memory overhead; simple implementation [S1, S2, unofficial].
*   **Limitations:** Constant step size may lead to aliasing; requires robust coarse mesh construction and traversal; potential for self-intersection artifacts at coarse element boundaries if not handled carefully [S1, unofficial].

## Background
The method originates from research on direct volume rendering of tree-based tetrahedral adaptive mesh refinement data [S1, unofficial]. It was developed to address the challenges of rendering AMR data without the memory costs associated with uniform grid resampling [S1, S2, unofficial]. The approach builds on the shared principles of hierarchical grid traversal, specifically utilizing a coarse mesh BVH for culling and a refinement tree for detailed sampling [S1, S2, unofficial].
