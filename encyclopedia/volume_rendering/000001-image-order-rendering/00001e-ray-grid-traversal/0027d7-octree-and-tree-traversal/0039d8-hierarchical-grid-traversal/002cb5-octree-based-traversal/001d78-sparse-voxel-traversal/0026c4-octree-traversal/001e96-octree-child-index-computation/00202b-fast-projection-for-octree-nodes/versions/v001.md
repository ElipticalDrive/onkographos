# Fast Projection for Octree Nodes

Also called: Projected Center Translation, Hierarchical Occlusion Map Projection

## Overview
Fast Projection for Octree Nodes accelerates the mapping of 3D octree nodes to 2D screen space during sparse voxel octree rendering. It solves the problem of efficiently determining which pixels are affected by a node's projection without per-pixel ray casting for every node. It sets itself apart from sibling methods by using a hierarchical 2D node map to terminate redundant thread execution, achieving a speedup of > 2x compared to naive per-pixel launching [S1].

## How it works
**Inputs and Outputs:**
- Input: Parent node's projected center $(cx_p, cy_p)$, octree level $L$, and precomputed translation vectors.
- Output: Child node's projected center $(cx_c, cy_c)$, subdivision indices, and affected pixel ranges.

**Data Structures:**
- **Translation Vectors:** For each octree level $L$, eight 2D integer vectors $\vec{T}_{L, i}$ where $i \in \{0, \dots, 7\}$ corresponds to the octant index. These are preprocessed constants.
- **Occlusion Map (HOM):** A 2D array of 32-bit integers. Values indicate occlusion status (e.g., opaque areas marked with specific constants like 16, or depth cues).

**Steps:**
1. **Preprocessing:** Compute and store eight 2D translation vectors $\vec{T}_{L, i}$ for each relevant octree level $L$. These vectors represent the offset from the parent's projected center to each of the eight children's projected centers in screen space.
2. **Child Projection:** For a parent node at level $L-1$ with projected center $(cx_p, cy_p)$, compute the projected center of child $i$ at level $L$ using:
   $$
   \begin{bmatrix} cx_c \\ cy_c \end{bmatrix} = \begin{bmatrix} cx_p \\ cy_p \end{bmatrix} + \vec{T}_{L, i}
   $$
   This uses simple 2D integer translation.
3. **Subdivision and Pixel Assignment:** Use 32-bit integer arithmetic to determine the bounding box of the projected child node. Calculate the range of pixels $[x_{min}, x_{max}] \times [y_{min}, y_{max}]$ covered by the node.
4. **Occlusion Map Update:** Recursively update the Hierarchical Occlusion Map (HOM). If a child node is occluded or fully opaque, mark the corresponding region in the HOM. This allows subsequent threads targeting the same common ancestor to be terminated early.
5. **Depth Cueing:** Compute the depth component for fast depth cueing using the same projection logic, ensuring consistent depth values for shading.

**Parameters:**
- **Arithmetic:** 32-bit integer arithmetic is used for all subdivision determination, pixel assignment, and HOM updates [S1].
- **Translation Vectors:** Precomputed per level. The exact values depend on the camera projection matrix and octree geometry.

**Edge Cases and Pitfalls:**
- **Precision:** Using 32-bit integers may lead to overflow or precision loss at very high resolutions or deep octree levels. Ensure the translation vectors and coordinates fit within 32-bit signed integer limits.
- **Boundary Conditions:** Handle nodes that project partially outside the screen bounds. Clip the pixel ranges to the viewport dimensions.
- **Degenerate Input:** If a node projects to a single pixel or zero area, ensure the HOM update logic handles this correctly to avoid infinite recursion or incorrect occlusion flags.

**Pseudocode:**
```python
# Precomputed translation vectors for each level
# T[level][octant_index] = (dx, dy)
T = precompute_translation_vectors()

def project_octree_node(parent_center, level, octant_index):
    """
    Compute the projected center of an octree child node.
    
    Args:
        parent_center: Tuple (cx_p, cy_p) of the parent's projected center.
        level: The octree level of the child node.
        octant_index: Integer 0-7 indicating the child's octant.
        
    Returns:
        Tuple (cx_c, cy_c) of the child's projected center.
    """
    dx, dy = T[level][octant_index]
    cx_c = parent_center[0] + dx
    cy_c = parent_center[1] + dy
    return (cx_c, cy_c)

def update_hierarchical_occlusion_map(node_center, node_size, hom):
    """
    Update the Hierarchical Occlusion Map with the current node's projection.
    
    Args:
        node_center: Tuple (cx, cy) of the node's projected center.
        node_size: Integer size of the node in screen pixels (radius or half-width).
        hom: 2D array representing the occlusion map.
    """
    # Calculate bounding box
    x_min = max(0, int(node_center[0] - node_size))
    x_max = min(hom.shape[1], int(node_center[0] + node_size))
    y_min = max(0, int(node_center[1] - node_size))
    y_max = min(hom.shape[0], int(node_center[1] + node_size))
    
    # Update HOM with occlusion flag (e.g., mark as opaque)
    # Specific flag value depends on implementation (e.g., 16 for opaque)
    for y in range(y_min, y_max):
        for x in range(x_min, x_max):
            hom[y][x] = 16  # Mark as opaque/occluded

def render_octree_node(node, hom):
    """
    Render a single octree node using fast projection.
    
    Args:
        node: Object containing parent_center, level, octant_index, and geometry.
        hom: 2D array representing the occlusion map.
    """
    # Check if node is already occluded in HOM
    # This check is performed before launching threads for children
    if is_occluded(node.center, node.size, hom):
        return

    # Project children
    for i in range(8):
        child_center = project_octree_node(node.center, node.level + 1, i)
        child_size = node.size / 2  # Assuming uniform subdivision
        
        # Recursively process or launch thread
        # If using thread-based approach, check HOM before launching
        if not is_occluded(child_center, child_size, hom):
            # Launch thread or process directly
            render_octree_node(Node(child_center, node.level + 1, i, child_size), hom)
            # Update HOM after processing
            update_hierarchical_occlusion_map(child_center, child_size, hom)
```

This method reduces the number of threads launched during sparse voxel octree filtering by using a hierarchical 2D node map to detect and terminate redundant thread execution. It sets itself apart from naive per-pixel thread launching by terminating threads that target the same common ancestor node, achieving a speedup of > 2x.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of visible nodes. The projection step is $O(1)$ per node due to precomputed translations. HOM updates are proportional to the projected area.
- **Memory Complexity:** $O(W \times H)$ for the HOM, where $W$ and $H$ are screen dimensions. Precomputed translation vectors require $O(L \times 8)$ space, where $L$ is the max octree depth.
- **Measured Performance:** Achieves a speedup of > 2x compared to naive per-pixel thread launching [S1].
- **Strengths:** Efficient occlusion culling via HOM; fast projection using integer arithmetic.
- **Limitations:** Requires precomputation of translation vectors; 32-bit integer arithmetic may limit precision at high resolutions.
- **When to Use:** Sparse voxel octree rendering with significant occlusion.
- **When Not to Use:** Dense volumes where occlusion culling is ineffective; very high resolutions where 32-bit integer precision is insufficient.

## Background
Originated in the context of object-order ray-casting algorithms for sparse voxel octrees. The method leverages hierarchical occlusion maps (HOMs) to optimize thread execution in GPU-based rendering. It is particularly useful in scenarios where many threads target the same common ancestor node, allowing for early termination.
