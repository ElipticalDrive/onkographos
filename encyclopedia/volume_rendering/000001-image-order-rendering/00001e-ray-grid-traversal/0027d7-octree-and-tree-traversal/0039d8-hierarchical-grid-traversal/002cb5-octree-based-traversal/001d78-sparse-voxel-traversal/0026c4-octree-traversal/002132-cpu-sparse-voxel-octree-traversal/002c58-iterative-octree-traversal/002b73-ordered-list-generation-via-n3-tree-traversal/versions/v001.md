# Ordered List Generation via N3-Tree Traversal

Also called: Depth-first ordered traversal, View-dependent tree traversal

## Overview
This method generates a list of spatial bricks (or nodes) ordered from closest to furthest relative to the viewpoint. It solves the problem of unnecessary data loading by ensuring that visibility tests are performed on blocks in an order where any previously reached node cannot be occluded by a subsequently reached node [S1, unofficial]. Unlike sibling methods that may rely on fixed traversal orders or distance sorting after generation, this approach integrates view-dependent axis prioritization directly into the depth-first traversal of the N3-tree structure [S1, unofficial].

## How it works
**Inputs:**
- The root of the N3-tree.
- The viewpoint direction vector $\vec{V} = (V_x, V_y, V_z)$.
- $N$, the number of subdivisions (children) per node in the hierarchy [S1, unofficial].

**Outputs:**
- A list of nodes ordered by occlusion (closest to furthest) [S1, unofficial].

**Data Structures:**
- **N3-tree:** A hierarchical structure where each node represents a grid of $N \times N \times N$ bricks (or children) [S1, unofficial].
- **Traversal Stack:** Used to manage the depth-first search state [S1, unofficial].

**Algorithm Steps:**
1.  **Initialize:** Start the traversal at the root of the N3-tree [S1, unofficial].
2.  **Depth-First Traversal:** Recursively or iteratively traverse the tree in depth-first order [S1, unofficial].
3.  **View-Dependent Axis Ordering:** At each node, determine the order in which to visit its child grids. The traversal prioritizes the axis with the smallest absolute component in the viewpoint direction vector $\vec{V}$ [S1, unofficial].
    -   Let the sorted axes be $A_1, A_2, A_3$ such that $|V_{A_1}| \le |V_{A_2}| \le |V_{A_3}|$ [S1, unofficial].
    -   The traversal proceeds primarily along $A_1$, then $A_2$, then $A_3$ [S1, unofficial].
4.  **Start Element Calculation:** For each grid traversal at a given level, determine the starting element index $(E_x, E_y, E_z)$ based on the viewpoint components [S1, unofficial].
5.  **Grid Traversal:** Iterate through the children of the current node in the order determined by the axes and the start element [S1, unofficial].
6.  **Recursion:** For each child, repeat steps 3-5 until leaf nodes are reached [S1, unofficial].

**Formulas:**
The starting element $E_{xyz}$ for each axis component is calculated as [S1, unofficial]:

$$
E_{xyz} = \text{step}(0, V_{xyz}) \times (N - 1)
$$

Where $\text{step}(0, V_{xyz})$ is defined as [S1, unofficial]:

$$
\text{step}(0, V_{xyz}) = 
\begin{cases} 
0 & \text{if } V_{xyz} < 0 \\
1 & \text{otherwise}
\end{cases}
$$

Here, $V_{xyz}$ represents the component of the viewpoint direction vector along the respective axis, and $N$ is the number of subdivisions of the nodes [S1, unofficial].

**Parameters:**
-   $N$: Number of subdivisions of the nodes in the hierarchy [S1, unofficial].
-   $\vec{V}$: Viewpoint direction vector components $V_x, V_y, V_z$ [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **View Vector Alignment:** If a component of the view vector is zero, the tie-breaking for axis order is not specified in the sources [S1, unofficial]. [G] A deterministic tie-breaker (e.g., fixed axis priority x < y < z) should be used.
-   **Precision:** Floating-point comparisons for $V_{xyz} < 0$ should handle near-zero values carefully to avoid jitter in traversal order [S1, unofficial].
-   **Boundary Conditions:** The formula assumes $N \ge 1$. If $N=1$, the start index is always 0 [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of nodes in the tree, $O(M)$, where $M$ is the total number of nodes, as each node is visited once [S1, unofficial].
-   **Memory Complexity:** $O(D)$, where $D$ is the depth of the tree, due to the recursion stack or explicit stack for depth-first traversal [S1, unofficial].
-   **Performance:** The method avoids unnecessary loading of occluded blocks by ensuring that visibility tests are performed in occlusion order [S1, unofficial].
-   **Strengths:** Easy traversal in occlusion order; any node already reached cannot be occluded by a node reached later [S1, unofficial].
-   **Limitations:** The traversal order is based on occlusion, not strictly on distance from the viewpoint. While it provides a visibility order, it does not guarantee a distance-sorted list, which might be useful for prioritizing the loading of the closest bricks [S1, unofficial].

## Background
The method originates from the work on interactive exploration of procedural volumes, specifically using the N3-tree structure [S1, unofficial]. It was developed to optimize visibility detection by providing a list of bricks ordered from closest to furthest, thereby minimizing the loading of occluded blocks [S1, unofficial]. The N3-tree structure facilitates this by allowing easy traversal in occlusion order [S1, unofficial].
