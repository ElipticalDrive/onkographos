# Parametric Quadtree Traversal
Also called: Parametric Quadtree Ray Traversal, parametric algorithm for octree traversal (2D variant), quadtree-raycast
## Overview
Parametric quadtree traversal is a top-down ray-quadtree intersection algorithm that uses parametric ray coordinates to determine the entry and exit points of a ray within a node and its children. It solves the problem of efficiently traversing non-uniform depth quadtrees without branching on ray direction signs for every step, by normalizing coordinates via flipping. It sets itself apart from sibling methods by operating on 2D spatial hierarchies (quadtrees) rather than 3D volumes (octrees), while sharing the same parametric coordinate logic as [Parametric Octree Traversal](2361-parametric-octree-traversal.md).
## How it works
### Inputs and Outputs
- **Inputs**: Ray origin $(start_x, start_y)$, ray direction $(dir_x, dir_y)$, quadtree root node, and the spatial bounds of the root node $(quad\_pos_x, quad\_pos_y, size)$.
- **Outputs**: A list of leaf nodes (or nodes with no children) intersected by the ray, in traversal order.

### Data Structures
- **Quadtree Node**: Contains a boolean or pointer indicating if it has children (`children.is_none()` implies leaf). If it has children, it contains an array of 4 child nodes indexed 0-3.
- **Indexing**: Children are indexed as: 0 (bottom-left), 1 (bottom-right), 2 (top-left), 3 (top-right). This is the standard raster order.

### Parameters
- **EXIT**: The integer constant `4`, used to signal that no further children should be visited.
- **Mask**: A 2-bit integer (0-3) tracking coordinate flips. Bit 0 corresponds to X, Bit 1 to Y.

### Steps
1. **Coordinate Flipping (Normalization)**:
   To handle arbitrary ray directions without conditional branching inside the loop, flip the ray origin if the direction component is negative.
   - If $dir_x < 0$:
     - $start_x \leftarrow 2 \cdot quad\_pos_x + size - start_x$
     - $mask \leftarrow mask \ | \ 1$
   - If $dir_y < 0$:
     - $start_y \leftarrow 2 \cdot quad\_pos_y + size - start_y$
     - $mask \leftarrow mask \ | \ 2$
   - Note: The direction vector components are used as absolute values $|dir_x|$ and $|dir_y|$ for all subsequent parametric calculations.

2. **Parametric Bounds Calculation**:
   Compute the parametric distances $t$ along the ray to the entry and exit planes of the current node.
   - $tx0 = \frac{quad\_pos_x - start_x}{|dir_x|}$
   - $tx1 = \frac{quad\_pos_x + size - start_x}{|dir_x|}$
   - $ty0 = \frac{quad\_pos_y - start_y}{|dir_y|}$
   - $ty1 = \frac{quad\_pos_y + size - start_y}{|dir_y|}$

3. **Node Intersection Test**:
   - $t_{min} = \max(tx0, ty0)$
   - $t_{max} = \min(tx1, ty1)$
   - If $t_{min} \ge t_{max}$, the ray does not intersect the node. Return empty list.

4. **Leaf Check**:
   - If the current node has no children, return a list containing the current node.

5. **Midpoint Calculation**:
   - $txm = \frac{tx0 + tx1}{2}$
   - $tym = \frac{ty0 + ty1}{2}$

6. **Initial Child Selection**:
   Determine the first child to visit based on the entry point $(tx0, ty0)$ relative to the midpoints $(txm, tym)$.
   - If $tx0 > ty0$:
     - If $tx0 < tym$, $curr\_node = 0$
     - Else, $curr\_node = 2$
   - Else ($tx0 \le ty0$):
     - If $ty0 < txm$, $curr\_node = 0$
     - Else, $curr\_node = 1$

7. **Traversal Loop**:
   While $curr\_node \neq EXIT$:
   - **Access Child**:
     - The actual child index in memory is $idx = curr\_node \oplus mask$.
     - Let $child$ be the node at `node.children[idx]`.
   - **Process Child**:
     - Recursively call the traversal function on $child$ with updated parametric bounds.
     - The bounds for the child depend on its quadrant index $curr\_node$:
       - If $curr\_node = 0$: bounds are $(tx0, ty0, txm, tym)$
       - If $curr\_node = 1$: bounds are $(txm, ty0, tx1, tym)$
       - If $curr\_node = 2$: bounds are $(tx0, tym, txm, ty1)$
       - If $curr\_node = 3$: bounds are $(txm, tym, tx1, ty1)$
     - Append results from the child to the output list.
   - **Next Node Selection**:
     - Use the lookup table $L$ to find the next node to visit.
     - $L = \begin{bmatrix} 1 & 2 \\ 4 & 3 \\ 3 & 4 \\ 4 & 4 \end{bmatrix}$
     - If $txm \le tym$, $next\_node = L[curr\_node][0]$
     - Else, $next\_node = L[curr\_node][1]$
     - $curr\_node = next\_node$

8. **Return**:
   - Return the accumulated list of leaf nodes.

### Pseudocode

```python
def parametric_quadtree_traversal(ray_origin, ray_dir, node, quad_pos, size):
    """
    ray_origin: (x, y)
    ray_dir: (x, y)
    node: QuadtreeNode object
    quad_pos: (x, y) position of the current node's bottom-left corner
    size: float, side length of the current node
    """
    start_x, start_y = ray_origin
    dir_x, dir_y = ray_dir
    
    # 1. Coordinate Flipping
    mask = 0
    abs_dir_x = abs(dir_x)
    abs_dir_y = abs(dir_y)
    
    # Handle division by zero if direction is exactly 0? 
    # In practice, rays with 0 direction components are degenerate. 
    # Assuming non-zero directions for parametric calculation.
    if abs_dir_x == 0: abs_dir_x = 1e-9
    if abs_dir_y == 0: abs_dir_y = 1e-9

    if dir_x < 0:
        start_x = 2 * quad_pos[0] + size - start_x
        mask |= 1
    if dir_y < 0:
        start_y = 2 * quad_pos[1] + size - start_y
        mask |= 2

    # 2. Parametric Bounds
    tx0 = (quad_pos[0] - start_x) / abs_dir_x
    tx1 = (quad_pos[0] + size - start_x) / abs_dir_x
    ty0 = (quad_pos[1] - start_y) / abs_dir_y
    ty1 = (quad_pos[1] + size - start_y) / abs_dir_y

    # 3. Intersection Test
    t_min = max(tx0, ty0)
    t_max = min(tx1, ty1)
    
    if t_min >= t_max:
        return []

    # 4. Leaf Check
    if node.children is None:
        return [node]

    # 5. Midpoints
    txm = (tx0 + tx1) / 2
    tym = (ty0 + ty1) / 2

    # 6. Initial Child Selection
    if tx0 > ty0:
        if tx0 < tym:
            curr_node = 0
        else:
            curr_node = 2
    else:
        if ty0 < txm:
            curr_node = 0
        else:
            curr_node = 1

    results = []
    EXIT = 4
    
    # Lookup table for next node
    # L[curr_node][0] if txm <= tym else L[curr_node][1]
    next_lookup = [
        [1, 2], # curr_node 0
        [4, 3], # curr_node 1
        [3, 4], # curr_node 2
        [4, 4]  # curr_node 3
    ]

    # 7. Traversal Loop
    while curr_node != EXIT:
        # Access child with mask flip
        idx = curr_node ^ mask
        child = node.children[idx]
        
        # Determine bounds for child
        if curr_node == 0:
            c_tx0, c_ty0, c_tx1, c_ty1 = tx0, ty0, txm, tym
        elif curr_node == 1:
            c_tx0, c_ty0, c_tx1, c_ty1 = txm, ty0, tx1, tym
        elif curr_node == 2:
            c_tx0, c_ty0, c_tx1, c_ty1 = tx0, tym, txm, ty1
        elif curr_node == 3:
            c_tx0, c_ty0, c_tx1, c_ty1 = txm, tym, tx1, ty1
            
        # Recursive call
        # Note: The child's quad_pos and size must be calculated based on curr_node
        # However, the parametric bounds (tx0, ty0, etc.) are relative to the 
        # current node's coordinate system. The recursive call needs the child's 
        # spatial position to compute its own local parametrics if we were to 
        # recompute from scratch. But this algorithm passes parametric bounds 
        # down. The child's spatial bounds are implicit in the parametric bounds 
        # passed to it? 
        # Actually, the standard implementation passes the parametric bounds 
        # directly to the next level, but the next level needs to know its 
        # own spatial position to compute tx0/tx1 from scratch? 
        # No, the parametric values tx0, tx1 etc. ARE the t-values along the 
        # ray. The child's spatial bounds are defined by the midpoints.
        # The recursive function signature usually takes the parametric bounds 
        # directly or recomputes them. 
        # Based on the source, the bounds are passed as (tx0, ty0, tx1, ty1) 
        # to the next level? 
        # Let's look at the source logic: "Process the child recursively with 
        # updated parametric bounds". 
        # The child's spatial position is needed to compute the *next* level's 
        # parametrics? No, the parametrics are global t-values. 
        # The child's spatial bounds are just the sub-rectangle. 
        # The recursive call needs: ray_origin, ray_dir, child_node, 
        # child_quad_pos, child_size.
        # We must compute child_quad_pos and child_size.
        
        child_size = size / 2
        if curr_node == 0: # Bottom-Left
            child_pos = (quad_pos[0], quad_pos[1])
        elif curr_node == 1: # Bottom-Right
            child_pos = (quad_pos[0] + child_size, quad_pos[1])
        elif curr_node == 2: # Top-Left
            child_pos = (quad_pos[0], quad_pos[1] + child_size)
        elif curr_node == 3: # Top-Right
            child_pos = (quad_pos[0] + child_size, quad_pos[1] + child_size)
            
        results.extend(parametric_quadtree_traversal(
            ray_origin, ray_dir, child, child_pos, child_size
        ))
        
        # Next Node
        if txm <= tym:
            curr_node = next_lookup[curr_node][0]
        else:
            curr_node = next_lookup[curr_node][1]
            
    return results
```

### Edge Cases and Pitfalls
- **Zero Direction Components**: If $dir_x = 0$ or $dir_y = 0$, division by zero occurs. The implementation should handle this by treating the ray as parallel to the axis, effectively ignoring the parametric constraint for that axis or using a large epsilon. [G]
- **Degenerate Nodes**: Nodes with zero size should not exist in a valid quadtree.
- **Mask Logic**: The XOR with mask correctly maps the logical quadrant index to the physical child index in memory when coordinates are flipped. Forgetting to flip the mask or the origin leads to visiting the wrong child.
- **Precision**: Floating-point precision errors in $txm$ and $tym$ comparisons can lead to incorrect child selection at boundaries. [G] Using a small epsilon for comparisons might be necessary.

## Operating characteristics
- **Time Complexity**: $O(k)$ where $k$ is the number of nodes visited. In the worst case (ray passes through many empty nodes), it can be $O(N)$ where $N$ is the number of nodes. However, it skips empty subtrees efficiently.
- **Memory Complexity**: $O(D)$ where $D$ is the depth of the quadtree, due to recursion stack.
- **Performance**: The parametric approach avoids branching on ray direction signs for every node, making it cache-friendly and suitable for GPU implementation. It is generally faster than naive traversal for sparse quadtrees. [S1, unofficial]
- **Strengths**: Handles arbitrary ray directions without complex branching; simple logic for child selection; efficient for sparse data.
- **Limitations**: Requires floating-point arithmetic; precision issues at node boundaries; not directly applicable to 3D octrees without modification (though the 3D variant exists).

## Background
The algorithm is based on "An Efficient Parametric Algorithm for Octree Traversal" [S1, unofficial]. It is a 2D adaptation of the parametric octree traversal method. The implementation in [S1, unofficial] is a Rust port of the algorithm, visualized using minifb. It is used in computer graphics for ray tracing against 2D spatial hierarchies, such as in image processing or 2D collision detection.
