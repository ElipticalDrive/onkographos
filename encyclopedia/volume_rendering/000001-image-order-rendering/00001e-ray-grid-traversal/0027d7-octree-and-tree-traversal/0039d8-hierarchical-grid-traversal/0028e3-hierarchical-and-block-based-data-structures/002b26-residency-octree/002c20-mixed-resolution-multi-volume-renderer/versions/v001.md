# Mixed-Resolution Multi-Volume Renderer

Also called: MR-MVR

## Overview
A ray-guided renderer that accesses metadata and cached volume data through the [Residency Octree](4950-residency-octree.md), enabling efficient mixing of resolutions across different channels in multi-volume datasets. It differs from per-channel sampling approaches by evaluating all visible channels at each sample along a ray, using a global step size determined by the highest-resolution channel to reduce shader divergence.

## How it works
**Inputs and Outputs:**
- **Input:** Ray origin, ray direction, current node index in the full octree, channel mapping, and user-defined parameters.
- **Output:** Computed color and opacity for the ray segment, updated ray position, and potential data streaming requests.

**Data Structures:**
- **Residency Octree:** Provides metadata (for empty-space skipping) and cached volume data (bricks). Nodes are accessed via index in a full octree layout.
- **Channel Mapping:** Maps dataset channels to the $m$ visible channels. This mapping can change at runtime.
- **Visibility Buffer:** Tracks the $m$ visible channels ($m \le n$, where $n$ is total channels).

**Parameters:**
- $m$: Maximum visible channels, user-defined at initialization.
- $stepScale$: User-defined scaling factor for sampling rate.
- Channel Importance: Determined by user-defined resolution ranges via UI sliders. A channel with a higher upper bound in its resolution range is considered more important.

**Step Size Calculation:**
The sampling rate is determined globally for all channels based on the channel requiring the highest sampling rate (highest resolution). The step size $dt_{step}$ is computed as follows:

1. Calculate the step size component for each dimension $i \in [0, 1, 2]$:
   $$ dt_i = \frac{1}{v_i \cdot s_i \cdot d_i} $$
   Where:
   - $v_i$ is the volume extent in dimension $i$.
   - $s_i$ is the voxel spacing in dimension $i$.
   - $d_i$ is the ray direction in dimension $i$.

2. Compute the global step size:
   $$ dt_{step} = \min(dt_0, dt_1, dt_2) \cdot stepScale $$

**Algorithm Steps:**
1. **Initialization:** Set the maximum visible channels $m$ and channel mapping. Initialize ray parameters.
2. **Traversal Start:** Start tree traversal at a user-defined subdivision level or the parent level of the previous termination level. Access nodes directly via their index in the full octree.
3. **Data Check:** For the current node, check if metadata and cached volume data are available.
   - If missing, generate a request for the missing data to be streamed from the server.
4. **Empty-Space Skipping:** Use metadata to skip empty nodes.
5. **Sampling:** For each sample along the ray:
   - Compute the global step size $dt_{step}$ based on the highest-resolution visible channel.
   - Evaluate all $m$ visible channels at the current sample position. This reduces diverging branches in the shader.
   - Accumulate color and opacity.
6. **Termination:** Stop when the ray exits the volume or opacity threshold is reached.
7. **Loop:** Repeat steps 2-6 for subsequent rays or frames.

**Pseudocode:**
```python
def render_ray(ray_origin, ray_direction, current_node_index, channel_mapping, step_scale):
    # Determine global step size based on highest resolution channel
    # Assume get_highest_res_channel_params returns (v, s) for the relevant channel
    v, s = get_highest_res_channel_params(channel_mapping)
    
    dt_components = []
    for i in range(3):
        # Avoid division by zero if ray direction component is zero
        if ray_direction[i] == 0:
            dt_components.append(float('inf'))
        else:
            dt_i = 1.0 / (v[i] * s[i] * ray_direction[i])
            dt_components.append(dt_i)
            
    dt_step = min(dt_components) * step_scale
    
    # Start traversal at optimized level
    node_idx = current_node_index
    
    while node_idx is not None:
        # Check data availability
        if not has_metadata(node_idx) or not has_cached_data(node_idx):
            request_streaming(node_idx)
            # Wait for data or handle pending request
            wait_for_data(node_idx)
            
        # Empty-space skipping using metadata
        if is_empty(node_idx):
            node_idx = get_next_node(node_idx)
            continue
            
        # Sample along ray segment covered by this node
        # Evaluate all visible channels at each sample
        for sample_pos in sample_along_ray(ray_origin, ray_direction, dt_step, node_bounds):
            color = vec3(0.0)
            opacity = 0.0
            for ch in channel_mapping:
                val = sample_volume(ch, sample_pos)
                color += transfer_function(ch, val) * val
                opacity += alpha(ch, val) * (1.0 - opacity)
            ray_origin += ray_direction * dt_step
            
        node_idx = get_next_node(node_idx)
        
    return color
```

**Edge Cases and Pitfalls:**
- **Ray Direction Zero:** If a ray direction component is zero, $dt_i$ becomes infinite. Handle this by taking the minimum of non-infinite components or using a large finite value.
- **Missing Data:** Streaming requests may stall rendering. Implement asynchronous handling or fallbacks.
- **Channel Mapping Changes:** Ensure smooth transitions when channel mapping changes at runtime.

## Operating characteristics
- **Time Complexity:** Depends on the number of samples per ray, which is determined by $dt_{step}$. Evaluating all $m$ channels at each sample adds a factor of $m$.
- **Memory Complexity:** Depends on the number of cached bricks in the residency octree.
- **Performance:** Reduces shader divergence by evaluating all channels at each sample. Global step size simplifies sampling logic.
- **Strengths:** Efficient handling of multi-resolution data, reduced divergence, ray-guided data streaming.
- **Limitations:** Potential over-sampling if lower-resolution channels are evaluated at high resolution. Requires careful tuning of $stepScale$ and channel importance.

## Background
The mixed-resolution multi-volume renderer is part of a system for scalable web-based volume rendering of large biomedical datasets. It leverages the residency octree for data management and is implemented as a WebGPU compute shader. The approach addresses the challenges of rendering multi-volume data with varying resolutions efficiently on the GPU.
