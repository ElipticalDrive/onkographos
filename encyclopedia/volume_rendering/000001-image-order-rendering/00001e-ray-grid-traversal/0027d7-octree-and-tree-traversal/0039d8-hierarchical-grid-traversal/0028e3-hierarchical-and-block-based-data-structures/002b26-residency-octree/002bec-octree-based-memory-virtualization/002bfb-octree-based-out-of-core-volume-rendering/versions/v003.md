# Octree-based out-of-core volume rendering

Also called: Octree approach, Octree reference implementation, Octree-based Out-of-Core LOD

## Overview
An out-of-core rendering approach based on an octree structure, extending the single-channel method of Crassin et al. to support multiple visible channels by storing pointers and culling metadata in each node [S1, unofficial]. It solves the problem of managing brick residency and performing address translation for out-of-core volume rendering by using a hierarchical tree structure [S1, unofficial]. Unlike its sibling [Residency Octree](5269-residency-octree.md), which uses a more compact representation, this method enforces that the whole subtree is resident in the cache for high-resolution rendering, leading to a higher memory footprint [S1, unofficial]. It achieves comparable or better performance for single-channel data due to similar empty-space skipping, but performs worse for multiple channels because the octree must be traversed for each channel to ensure subtree residency [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Multi-channel volume dataset with $m$ visible channels, brick size $B$, cache size $C$, and ray origin/direction [S1, unofficial][G].
- Output: Rendered image pixels [G].

**Data Structures:**
- **Octree Node:** Contains $m$ pointers to bricks (one per visible channel) and culling metadata (minimum and maximum scalar values for each of the $m$ channels) [S1, unofficial].
- **Brick:** A 3D block of voxels. The brick size is approximately equal to the leaf-node size [S1, unofficial].
- **Mapping:** One-to-one mapping of bricks and octree nodes [S1, unofficial].

**Parameters:**
- Cache size: 4 GB [S1, unofficial].
- Brick size (and approximate leaf-node size): $32^3$ voxels [S1, unofficial].
- Traversal start level: Third subdivision level counting from the root node [S1, unofficial].

**Steps:**
1. **Initialization:** Start the residency octree and octree traversal at the third subdivision level counting from the root node [S1, unofficial].
2. **Ray Sample Processing:** For each ray sample:
   a. Determine the current node in the octree. Access the correct node for a ray sample in each subdivision level directly using a full octree implementation [S1, unofficial].
   b. **Culling:** Use the stored minimum and maximum scalar values for each channel to cull empty or transparent regions [S1, unofficial]. Bricks containing at least one non-zero value are not considered EMPTY and must be kept in memory, even if transparent under current viewing conditions [S1, unofficial].
   c. **Residency Enforcement:** To ensure high-resolution rendering, the whole subtree must be resident in the cache [S1, unofficial]. Restart the tree traversal for each visible channel when evaluating a ray sample [S1, unofficial].
   d. **Fallback:** In case of a missing brick in the desired resolution, render the next lower resolution instead [S1, unofficial].
   e. **Optimization:** Do not start tree traversal at the root level for each sample, but from the parent node’s subdivision level in the tree structure of the last node visited for the last sample [S1, unofficial].
3. **Rendering:** Render the voxel data from the resident bricks using the appropriate transfer function [G].

**Pseudocode:**
```python
def render_octree_out_of_core(volume_data, ray_origin, ray_direction, cache, brick_size=32, num_channels=1, start_level=3):
    ray_pos = list(ray_origin)
    ray_dir = list(ray_direction)
    step_size = brick_size / 2.0
    accumulated_color = [0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    last_visited_node = None
    last_visited_level = 0

    while accumulated_opacity < 1.0:
        if last_visited_node is not None:
            current_level = last_visited_level
            current_node = last_visited_node.parent
        else:
            current_level = 0
            current_node = volume_data.root

        while current_level < start_level:
            current_node = current_node.children[compute_octree_index(ray_pos, current_level)]
            current_level += 1
            if current_node is None:
                return accumulated_color

        cull = False
        for c in range(num_channels):
            if not (current_node.min_values[c] <= current_node.sample(ray_pos) <= current_node.max_values[c]):
                cull = True
                break

        if cull:
            ray_pos = [ray_pos[i] + ray_dir[i] * step_size for i in range(3)]
            continue

        for c in range(num_channels):
            brick = current_node.bricks[c]
            if brick is not None:
                cache.load(brick)
            else:
                lower_brick = current_node.lower_res_bricks[c]
                if lower_brick:
                    cache.load(lower_brick)

        color = [0.0, 0.0, 0.0]
        opacity = 0.0
        for c in range(num_channels):
            brick = cache.get_brick(current_node.bricks[c])
            if brick is None:
                brick = cache.get_brick(current_node.lower_res_bricks[c])
            if brick is not None:
                voxel_value = brick.sample(ray_pos)
                channel_color = [voxel_value, voxel_value, voxel_value]
                channel_opacity = voxel_value / 255.0
                alpha = channel_opacity
                color = [color[i] + channel_color[i] * alpha * (1.0 - accumulated_opacity) for i in range(3)]
                accumulated_opacity += alpha * (1.0 - accumulated_opacity)

        accumulated_color = [accumulated_color[i] + color[i] for i in range(3)]
        ray_pos = [ray_pos[i] + ray_dir[i] * step_size for i in range(3)]
        last_visited_node = current_node
        last_visited_level = current_level

    return accumulated_color
```

## Subtopics

## Operating characteristics
- **Time Complexity:** Depends on the tree traversal depth and the number of visible channels [G]. For multiple channels, the octree has to be traversed for each channel to ensure that all subtrees are resident in the cache, leading to worse performance compared to single-channel rendering [S1, unofficial].
- **Memory Complexity:** Higher memory footprint in terms of the number of bricks in the working set compared to the residency octree because whole subtrees have to be resident in the cache for rendering the volume in high resolution [S1, unofficial].
- **Measured Performance:**
  - CyCIF Small (16 channels): 122.8 ms/frame [S1, unofficial].
  - CyCIF Medium (15 channels): 155.1 ms/frame [S1, unofficial].
  - CyCIF Large (4 channels): 123.5 ms/frame [S1, unofficial].
  - Kingsnake (1 channel): 11.6 ms/frame [S1, unofficial].
  - Bonsai (1 channel): 4.5 ms/frame [S1, unofficial].
  - Aneurism (1 channel): 4.8 ms/frame [S1, unofficial].
- **Strengths:** Comparable performance to other methods for single-channel data due to similar empty-space skipping strategy [S1, unofficial].
- **Limitations:** Performs worse than the author's method for multiple channels due to the need to restart tree traversal for each channel [S1, unofficial]. Bricks with non-zero values are not considered EMPTY and must be kept in memory even if transparent, which can lead to unnecessary memory usage [S1, unofficial].

## Background
The method is based on the out-of-core renderer presented by Crassin et al. [CNLE09] and is similar to the octree-based method discussed by Brix et al. [BPH14] [S1, unofficial]. It was extended by the author to support multiple visible channels [S1, unofficial].
