# Parallel cache management with LRU

Also called: GPU-based cache management, Sarton et al. LRU cache management

## Overview
A method by Sarton et al. [SCRL20] that generalizes page-table hierarchies for non-rendering purposes and processes cache misses on the GPU itself using CUDA shared memory to minimize memory transfers between CPU and GPU [S1, unofficial]. It uses a global usage buffer and an LRU buffer to keep frequently used bricks in the cache [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A brick cache with $N$ entries, a multi-channel page-table hierarchy, and a current timestamp $t$ (e.g., frame number) [S1, unofficial].
*   **Output:** Updated LRU buffer order, and a list of missing brick IDs for the current timestamp [S1, unofficial].

**Data Structures:**
1.  **Global Brick-Usage Buffer:** An array comprising one timestamp per cache entry, storing the last timestamp at which the corresponding cache entry was accessed [S1, unofficial].
2.  **LRU Buffer:** An array storing linear indices into the brick cache, sorted by their most recent usage times [S1, unofficial].
3.  **Global Request Buffer:** A 3D buffer with one entry per page in the multi-channel page-table hierarchy, storing the last request timestamp for that page [S1, unofficial].
4.  **Request List:** A dynamic list of brick IDs for pages requested at a specific timestamp $t$, compiled from the request buffer [S1, unofficial].

**Algorithm Steps:**

1.  **Record Usage:** When a brick-cache entry is accessed, write the current timestamp $t$ to the corresponding location in the Global Brick-Usage Buffer [S1, unofficial].
2.  **Update LRU Buffer:** Generate a boolean mask of brick-cache entries used at the current timestamp from the timestamps in the usage buffer [S1, unofficial]. Use this mask to rearrange the previous LRU buffer such that the most recently used entries are moved to the front, preserving their relative order [S1, unofficial].
3.  **Handle Cache Misses:** On GPU access to a non-resident, non-empty brick page, write the current timestamp to the page's location in the Global Request Buffer [S1, unofficial].
4.  **Retrieve Misses:** To retrieve misses for timestamp $t$, read all pages from the Request Buffer with value $t$ [S1, unofficial].
5.  **Compile Requests:** Use a single stream compaction operation to compile a list of all brick IDs reported missing at timestamp $t$ [S1, unofficial].
6.  **Stream Bricks:** Read back the Request List to the CPU, which streams the missing bricks from the server [S1, unofficial].

**Parameters:**
*   **Max Bricks per Timestamp:** A limit on the number of requested bricks per timestamp to control traffic between client and server. Can be a constant or variable (e.g., decreased during user interactions like viewport changes) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Traffic Control:** Excessive traffic may occur during temporally incoherent working sets if the limit is not enforced [S1, unofficial].
*   **Empty Bricks:** The method distinguishes between non-resident bricks and those known to be empty; only non-empty non-resident bricks trigger requests [S1, unofficial].

**Pseudocode:**

```python
# Global state
usage_buffer = [0] * N  # Stores last access timestamp for each cache entry
lru_buffer = list(range(N))  # Indices into cache, sorted by recency
request_buffer = [0] * P  # Stores last request timestamp for each page
request_limit = 100  # Max bricks per timestamp
cache_resident = [True] * N  # Tracks residency of each cache entry
cache_empty = [False] * N     # Tracks emptiness of each cache entry
page_to_brick_id = [0] * P    # Maps page ID to brick ID

def update_lru(timestamp):
    # Step 1: Generate mask for entries used at current timestamp
    mask = [usage_buffer[i] == timestamp for i in range(N)]
    # Step 2: Rearrange LRU buffer
    # Most recently used (mask is True) go to front, preserving relative order
    new_lru_front = [idx for idx in lru_buffer if mask[idx]]
    # Least recently used (mask is False) go to back, preserving relative order
    new_lru_back = [idx for idx in lru_buffer if not mask[idx]]
    lru_buffer[:] = new_lru_front + new_lru_back

def handle_access(cache_entry_index, page_id, brick_id, timestamp):
    # Record usage in global buffer
    usage_buffer[cache_entry_index] = timestamp
    # Check residency and emptiness using standard cache state arrays
    if not cache_resident[cache_entry_index] and not cache_empty[brick_id]:
        request_buffer[page_id] = timestamp

def process_misses(timestamp):
    # Find all pages requested at this timestamp
    requested_pages = [pid for pid, ts in enumerate(request_buffer) if ts == timestamp]
    # Limit traffic
    if len(requested_pages) > request_limit:
        requested_pages = requested_pages[:request_limit]
    # Compile brick IDs (stream compaction)
    brick_ids = [page_to_brick_id[pid] for pid in requested_pages]
    # Transfer list to CPU for streaming
    host_transfer(brick_ids)
    # Clear request buffer for this timestamp
    for pid in requested_pages:
        request_buffer[pid] = 0
```

## Subtopics

### Brick Request Processing
An algorithm to process cache misses on the GPU and transmit brick requests to the CPU for streaming from the server [S1, unofficial]. It uses a 3D Request Buffer storing the last request timestamp for each page and a Request List compiled via stream compaction for a specific timestamp [S1, unofficial]. It allows limiting the number of requested bricks per timestamp to control traffic, which can be adjusted dynamically during user interactions [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Requires additional global buffers: Usage Buffer ($N$ integers), LRU Buffer ($N$ integers), and Request Buffer ($P$ integers) [S1, unofficial].
*   **Performance:** Minimizes CPU-GPU memory transfers by processing misses on the GPU using CUDA shared memory [S1, unofficial].
*   **Strengths:** Efficient GPU-side miss processing; scalable to exascale volumes [S1, unofficial].
*   **Limitations:** Requires synchronization between GPU and CPU for brick streaming; traffic control is necessary to prevent overload [S1, unofficial].

## Background
Originated with Sarton et al. [SCRL20], who generalized page-table hierarchies for volumetric datasets for non-rendering purposes [S1, unofficial]. The approach builds on earlier work by Fogal et al. [FSK13] who used a global hash table for reporting cache misses, but improves efficiency by processing misses on the GPU [S1, unofficial]. It is used in scalable web-based volume rendering of large biomedical datasets [S1, unofficial].
