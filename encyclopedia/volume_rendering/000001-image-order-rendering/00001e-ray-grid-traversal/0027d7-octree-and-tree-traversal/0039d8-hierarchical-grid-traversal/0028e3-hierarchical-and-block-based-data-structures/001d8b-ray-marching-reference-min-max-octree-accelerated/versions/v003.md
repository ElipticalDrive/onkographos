# Ray-marching reference (min-max octree accelerated)

Also called: Empty Space Skipping with Min/Max Cells, Interactive Isosurface Ray Tracing of Large Octree Volumes, Min-Max Octree Ray Casting, Min-Max Octree Ray-Marching, Min-Max Octree Ray-Marching Reference, Octree-accelerated ray-marching

## Overview
This method is an accelerated direct isosurface visualization technique that uses a min-max octree to facilitate empty space skipping during ray marching [S1][S3, unofficial][S2]. It serves as a performance baseline for general volumes, offering negligible memory overhead for the input volume and low auxiliary data requirements (1–4 MB for octree depth $\ge$ 7) [S3, unofficial][S2]. Unlike Sphere Tracing, which requires signed distance functions, or Segment Tracing, which is limited to hierarchical skeletal implicit surfaces, this approach is applicable to a wide range of scalar volumes [S2][S3, unofficial]. It guarantees continuous isosurfaces that locally interpolate the input data, avoiding the topological artifacts of mesh extraction techniques like marching cubes [S4, unofficial].

## How it works
The method consists of constructing a min-max octree from the volume data and using it to accelerate ray traversal by skipping empty regions. The isosurface intersection is refined using binary search, and shading is applied using computed normals.

### Inputs and Outputs
*   **Input:** A 3D scalar volume (structured grid).
*   **Output:** A rendered image of the isosurface defined by a specific isovalue.

### Data Structures
The core data structure is a **min-max octree**.
*   **Construction Source:** The octree is constructed from a min-max texture. In some implementations, this texture is derived from a MIP texture used to determine block occupancy [S1][S3, unofficial]. In others, the scalar data is converted into a lossless-compression octree representation where the acceleration tree and scalar data are embedded in a single structure [S4, unofficial].
*   **Node Content:** Each node in the octree stores the minimum and maximum scalar values of the voxels contained within its bounding box.
*   **Geometry:** The octree is constructed on a base level with equal size along all three cardinal axes. Volume dimensions are padded to the nearest power of two for straightforward implementation [S1][S3, unofficial].
*   **Indexing:** Optimized octree hash schemes are employed for point location and neighbor-finding [S4, unofficial]. For non-Cartesian datasets (e.g., FCC), the data may be stored as an embedded one-channel 3D texture [S5].

### Algorithm Steps

1.  **Octree Construction:**
    *   Compute the min and max scalar values for each cell in the volume.
    *   Build the octree hierarchy bottom-up. Internal nodes store the aggregate min/max of their children [S1][S3, S4, unofficial].
    *   *Note:* Some implementations use a fixed number of min/max cells (e.g., $32^3$) to define the coarsest level of the hierarchy [S5].

2.  **Entry and Exit Point Computation (GPU Rasterization Approach):**
    *   To find the entry and exit points of the ray within the active volume, render cubes corresponding to one level of the min/max octree [S5].
    *   All vertices of a cube share the same 2D texture coordinates containing the min/max values of that octree cell.
    *   **Exit Position:** Render the cubes with front-face culling (`glCullFace(GL FRONT)`) and depth function `GL_LESS`. A fragment shader discards fragments if the cube is empty or does not contain the isosurface level.
    *   **Entry Position:** Render the cubes again with back-face culling (`glCullFace(GL BACK)`) and depth function `GL_GREATER`.
    *   *Alternative (CPU/Hash Approach):* Trace rays through the octree using the min/max hierarchy inside interior nodes for acceleration, utilizing hash schemes for traversal [S4, unofficial].

3.  **Ray Marching:**
    *   March rays from the entry point to the exit point through the volume [S3, unofficial].
    *   Use the min-max octree to skip empty space. If a node's min and max values do not bracket the isovalue, the entire subtree is skipped [S1][S3, unofficial].
    *   **Step Size:** The ray marching step size is set to $0.5 \times$ the cell edge length [S1][S3, unofficial].

4.  **Isosurface Refinement:**
    *   Upon finding a voxel containing the isosurface, refine the intersection position using exactly **3 iterations** of a binary search algorithm [S1][S3, unofficial].

5.  **Normal Computation:**
    *   Compute surface normals on the fly using the central difference method at the intersection point [S1][S3, unofficial].

6.  **Shading:**
    *   Apply Gooch shading using the computed vertex normals [S1][S3, unofficial].

### Pseudocode

```python
def ray_march_min_max_octree(ray_origin, ray_direction, isovalue, octree, volume_data):
    """
    Performs ray marching through a volume using a min-max octree for acceleration.
    
    Args:
        ray_origin: vec3, origin of the ray.
        ray_direction: vec3, normalized direction of the ray.
        isovalue: float, the scalar value defining the isosurface.
        octree: Object, the min-max octree structure.
        volume_data: Array, the scalar volume data.
        
    Returns:
        vec3, the 3D intersection point on the isosurface, or None if no intersection.
    """
    
    # Step 1: Determine Entry and Exit Points
    # Method A: GPU Rasterization (as described in [S5])
    # entry_point, exit_point = compute_entry_exit_rasterization(ray_origin, ray_direction, octree)
    
    # Method B: Direct Traversal (as described in [S4, unofficial])
    entry_point = octree.get_entry_point(ray_origin, ray_direction)
    exit_point = octree.get_exit_point(ray_origin, ray_direction)
    
    if entry_point is None or exit_point is None:
        return None

    # Step 2: Ray Marching with Empty Space Skipping
    step_size = 0.5 * octree.get_cell_edge_length() # [S1][S3, unofficial]
    current_pos = entry_point
    
    while distance(current_pos, exit_point) > step_size:
        # Check if current position is within an active octree node
        node = octree.get_node_containing(current_pos)
        
        if node is None:
            break
            
        # Empty Space Skipping: Check min/max bounds
        if not (node.min_value <= isovalue <= node.max_value):
            # Skip this node's subtree
            current_pos = current_pos + ray_direction * node.bounding_box_depth
            continue
            
        # Sample volume data at current position
        scalar_value = sample_volume(volume_data, current_pos)
        
        # Check for isosurface intersection
        # Note: Simple step check; refinement happens after finding a bracketing step
        if scalar_value >= isovalue: # Assuming isovalue crossing condition
            # Found a potential intersection, refine it
            intersection = refine_intersection(current_pos, ray_direction, isovalue, octree, volume_data)
            return intersection
            
        current_pos = current_pos + ray_direction * step_size

    return None

def refine_intersection(start_pos, ray_direction, isovalue, octree, volume_data):
    """
    Refines the isosurface intersection using binary search.
    """
    iterations = 3 # [S1][S3, unofficial]
    low = start_pos
    high = start_pos + ray_direction * octree.get_cell_edge_length() # Approximate next step
    
    for i in range(iterations):
        mid = low + (high - low) / 2.0
        val_low = sample_volume(volume_data, low)
        val_mid = sample_volume(volume_data, mid)
        
        if val_low <= isovalue <= val_mid:
            high = mid
        else:
            low = mid
            
    return low

def sample_volume(volume_data, position):
    """
    Samples the scalar value at the given 3D position.
    Uses trilinear interpolation if position is not on a grid center.
    """

    # [G] Standard trilinear interpolation is assumed for continuous sampling.
    return interpolate_trilinear(volume_data, position)
```

### Parameters
*   **Binary Search Iterations:** 3 [S1][S3, unofficial].
*   **Ray Step Size:** $0.5 \times$ cell edge length [S1][S3, unofficial].
*   **Number of Min/Max Cells:** Experiments showed that $32^3$ cells resulted in the best performance [S5].

### Edge Cases and Pitfalls
*   **Cell Size Trade-off:** A large number of small cells induces a tight bound of the isosurface but comes with large overhead due to primitives. A small number of large cells reduces overhead but bounds the isosurface loosely [S5].
*   **Precision:** The method relies on accurate min/max aggregation. Degenerate input (e.g., constant regions) may lead to unnecessary traversal if not handled by occupancy flags, though the min/max check generally handles empty space effectively [S1][S3, unofficial].
*   **Resolution Dependence:** Unlike rasterization-based approaches, this method works largely in volume space and is hardly influenced by rendering resolution [S3, unofficial].

## Subtopics

### [Object-Order Iso-Surface Rendering with Macro-Cells](1757-object-order-iso-surface-rendering-with-macro-cells.md)
An iso-surface rendering algorithm based on object-order ray casting that subdivides data into macro-cells to build a min/max octree, reducing traversal steps by rasterizing hexagonal footprints. It builds on [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md) by replacing per-pixel octree traversal with macro-cell rasterization to reuse traversal paths for multiple pixels.

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume and the depth of the octree. Empty space skipping significantly reduces the number of samples taken.
*   **Memory Complexity:** Auxiliary octree data memory requirement is 1 to 4 megabytes for octrees with a depth of 7 or more [S3, unofficial][S2]. The lossless compression into an octree volume occupies less than one quarter the size of the original 3D array [S4, unofficial].
*   **Measured Performance:**
    *   On an Intel Core Duo 2.16 GHz laptop with 2 GB RAM, frame rates were 2.4, 1.3, and 3.3 fps for three test scenes (LLNL Richtmyer-Meshkov, Utah CSAFE heptane, and a closer view) [S4, unofficial].
    *   On a 16-node NUMA 2.4 GHz Opteron workstation, frame rates were 17.9, 9.8, and 22.0 fps for the same three test scenes [S4, unofficial].
    *   Performance gain up to $\approx 4.95$-fold using fine-grained min/max cells for efficient empty space skipping [S5].
*   **Strengths:**
    *   Applicable to a wide range of volumes [S2][S3, unofficial].
    *   Guarantees continuous isosurfaces that locally interpolate the input data [S4, unofficial].
    *   Low auxiliary memory overhead [S3, unofficial][S2].
    *   Hardly influenced by rendering resolution [S3, unofficial].
*   **Limitations:**
    *   Outperformed by raster occlusion culling approaches at high resolutions (e.g., 3840×2160) [S1].
    *   Less efficient than optimized mesh extraction (e.g., marching cubes) for dense isosurfaces, as mesh extraction can be 1.6–2.1 times faster [S1][S3, unofficial].
    *   A large number of small cells increases primitive overhead [S5].
*   **When to Use:** Suitable for general volumes where direct visualization is required, especially when the volume is sparse or when topological correctness is critical. It serves as a baseline for comparing more complex rasterization techniques [S3, unofficial].

## Background
The technique originated as a reference method for evaluating direct isosurface rendering pipelines. It was introduced in works such as "Efficient Direct Isosurface Rasterization of Scalar Volumes" [S1, S2][S3, unofficial] and "Interactive Isosurface Ray Tracing of Large Octree Volumes" [S4, S4, unofficial]. It was designed to provide a fair comparison against novel rasterization-based approaches by using a well-understood, GPU-friendly acceleration structure (min-max octree) that avoids the preprocessing requirements of Sphere Tracing or the limitations of Segment Tracing [S2][S3, unofficial]. The method leverages the duality between voxels and cells, mapping each voxel to the lower-left corner of a cell to facilitate ray tracing [S4, unofficial].
