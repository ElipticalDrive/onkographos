# ExaBricks Rendering with RTX BVH

Also called: Ray tracing structured AMR data using ExaBricks

## Overview
ExaBricks Rendering with RTX BVH is a hardware-accelerated volume rendering method for Adaptive Block-Refined (ABR) data that utilizes an RTX Bounding Volume Hierarchy (BVH) to traverse regions, perform volume integration, and skip empty space [S1]. It distinguishes itself from software-based k-d tree approaches (e.g., Kähler et al. [17]) by leveraging GPU hardware ray tracing to avoid non-trivial control flow and per-thread stacks in shaders, while supporting interactive transfer function editing and adaptive sampling [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Adaptive Block-Refined (ABR) data structure containing regions derived from AMR bricks; a transfer function defining scalar-to-opacity mapping; a maximum ray distance $t_{max}$.
*   **Output:** Final color and opacity for each pixel.

**Data Structures:**
*   **ABR Regions:** The spatial subdivision consists of regions. Each region has a precomputed scalar range $[min, max]$ and a bounding box.
*   **RTX BVH:** An acceleration structure built over the ABR regions. It contains one primitive per region.
    *   **Primitive Layout:** If a region is potentially visible (max opacity > 0), the primitive is the region's bounding box. If a region is fully transparent (max opacity = 0), the primitive is an empty box (discarded from traversal) [S1].

**Algorithm Steps:**
1.  **BVH Construction:**
    *   For each ABR region, determine its precomputed scalar range $[min, max]$.
    *   Evaluate the transfer function $TF$ over this range to find the maximum opacity: $opacity_{max} = \max_{s \in [min, max]} TF(s)$ [S1].
    *   If $opacity_{max} == 0$, return an empty box for the BVH primitive (effectively removing the region from the hierarchy) [S1].
    *   If $opacity_{max} > 0$, return the region's bounding box as the BVH primitive [S1].

2.  **Ray Traversal Loop:**
    *   Initialize a ray with origin $O$, direction $D$, and search interval $[0, t_{max})$ [S1].
    *   Perform hardware-accelerated ray traversal against the RTX BVH [S1].
    *   **Case 1: No Intersection.** If the BVH traversal returns no hit, the ray terminates [S1].
    *   **Case 2: Intersection.** If a region is intersected:
        1.  Compute the overlap interval $[t_{in}, t_{out}]$ between the ray and the intersected region's bounding box [S1].
        2.  Volume-integrate the samples within $[t_{in}, t_{out}]$ over the region using the ABR reconstruction filter [S1].
        3.  Check for early ray termination (if accumulated opacity is sufficiently high) [S1].
        4.  If the ray is not terminated, initiate a new ray traversal starting from $t_{out} + \epsilon$ to find the next ABR region [S1].
        5.  Repeat until the ray becomes opaque or no subsequent region is found [S1].

**Pseudocode:**
```python
def render_ray(origin, direction, t_max, bvh, transfer_function):
    """
    Renders a single ray using ExaBricks RTX BVH traversal.
    """
    t_current = 0.0
    accumulated_color = (0.0, 0.0, 0.0)
    accumulated_opacity = 0.0
    
    while t_current < t_max:
        # Hardware-accelerated BVH traversal
        # Returns the closest region hit and its intersection parameter t_hit
        hit_region, t_hit = bvh.traverse(origin, direction, t_start=t_current, t_end=t_max)
        
        if hit_region is None:
            # No more regions found
            break
            
        # Compute overlap interval [tin, tout] with the region
        # Note: The BVH primitive is the region's bounding box
        tin = t_hit
        # Calculate the exit point from the region's bounding box
        tout = compute_exit_t(origin, direction, hit_region.bounding_box, t_start=tin)
        
        # Volume integrate within the region
        region_color, region_opacity = volume_integrate(
            origin, direction, tin, tout, hit_region
        )
        
        # Composite the result
        # Standard front-to-back compositing
        alpha = 1.0 - accumulated_opacity
        accumulated_color += region_color * region_opacity * alpha
        accumulated_opacity += region_opacity * alpha
        
        if accumulated_opacity >= 0.99: # Early termination threshold
            break
            
        # Advance ray start to just after the current region
        # epsilon is a small value to prevent self-intersection
        t_current = tout + epsilon
        
    return accumulated_color, accumulated_opacity

def build_bvh(regions, transfer_function):
    """
    Constructs the RTX BVH, pruning fully transparent regions.
    """
    primitives = []
    for region in regions:
        # Get precomputed scalar range for the region
        min_val, max_val = region.scalar_range
        
        # Compute max opacity in this range
        max_opacity = 0.0
        # Evaluate transfer function over the range [min_val, max_val]
        # In practice, this might be a lookup or analytical max
        for s in sample_range(min_val, max_val):
            opacity = transfer_function(s)
            if opacity > max_opacity:
                max_opacity = opacity
                
        if max_opacity == 0:
            # Discard region: return empty box
            primitives.append(EmptyBox())
        else:
            # Keep region: return bounding box
            primitives.append(region.bounding_box)
            
    return BVH_build(primitives)
```

**Parameters:**
*   $\epsilon$: Small offset to prevent re-intersecting the current region. Value not given in the sources [G].
*   Early termination threshold: Typically around 0.99 or 1.0. Value not given in the sources [G].

**Edge Cases and Pitfalls:**
*   **BVH Rebuild Cost:** The BVH must be rebuilt whenever the transfer function or iso-value changes. On the Exajet dataset (656M cells), a full rebuild takes approximately 300ms on a Titan RTX or RTX 8000 GPU [S1]. Refitting the BVH is suggested as a potential optimization [S1].
*   **Empty Space:** Truly empty space (outside the AMR mesh) is automatically skipped as it generates no bricks or regions [S1].
*   **Transparent Regions:** Regions covered by cells with zero opacity under the current transfer function are excluded from the BVH during construction, avoiding traversal checks during rendering [S1].

## Subtopics

### [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md)
Adaptive Sampling with Region Delimiters is a sampling strategy for Adaptive Block-Refined (ABR) volume data that adapts the sampling rate to the finest cell size within each region, using sample positions as delimiters to handle boundary artifacts. Unlike Ljung [23], which defines a global set of finest level samples skipped by coarseness, this method defines independent sampling intervals for each region. It solves the problem of boundary artifacts caused by successive regions sampled at different rates, where the distance between the last sample of one region and the first of the next can be smaller or larger than either region's sampling rate.

## Operating characteristics
*   **Time Complexity:** The method performs multiple hardware ray traversals per volume ray (one per region intersected). However, hardware support makes these traversals cheap, and the cost is amortized over multiple samples taken within each region [S1].
*   **Memory Complexity:** Depends on the number of ABR regions. The BVH stores one primitive per region [S1].
*   **Measured Performance:**
    *   **Hardware:** Titan RTX, RTX 8000 [S1].
    *   **Data Sets:**
        *   Wind: 411M cells, 24.6K regions, 689K bricks, 2.78x speedup, 1.72x memory reduction [S1].
        *   Gear: 262M cells, 26K regions, 792K bricks, 2.97x speedup, 1.20x memory reduction [S1].
        *   Exajet: 656M cells, 3.1M regions, 55.8M bricks, 3.18x speedup, 1.25x memory reduction [S1] [S1].
*   **Strengths:** Hardware-accelerated traversal avoids complex shader control flow; supports interactive transfer function editing; adaptive sampling keeps total sample counts tractable while adapting to finest cell sizes [S1].
*   **Limitations:** BVH rebuild cost on transfer function change (~300ms for Exajet) [S1].
*   **When to use:** Interactive direct volume rendering of large AMR datasets where hardware ray tracing is available and transfer functions change frequently [S1].
*   **When not to use:** If the hardware does not support RTX ray tracing or if the transfer function is static and BVH rebuild cost is prohibitive compared to refitting [S1].

## Background
The method was introduced in the paper "Ray Tracing Structured AMR Data Using ExaBricks" [S1]. It builds on the ExaBricks data structure, which uses a reconstruction filter to store which bricks influence each region, enabling fast basis reconstruction during rendering [S1]. The approach was developed to support interactive high-quality direct volume rendering with smooth AMR reconstruction filters, gradient-based volume shading, and surface shading from implicit isosurfaces [S1]. It replaces software k-d tree traversal (as used by Kähler et al. [17]) with hardware-accelerated RTX BVH traversal to improve performance and simplify shader code [S1].
