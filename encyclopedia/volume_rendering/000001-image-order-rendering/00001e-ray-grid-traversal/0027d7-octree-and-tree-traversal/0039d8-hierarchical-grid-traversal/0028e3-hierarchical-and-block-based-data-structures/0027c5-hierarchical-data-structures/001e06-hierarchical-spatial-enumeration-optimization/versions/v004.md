# Hierarchical Spatial Enumeration Optimization

Also called: Complete octree representation, Heirarchical Spatial Enumeration, Hierarchical Spatial Enumeration (Octree Pyramid), Pyramid Enumeration, Pyramid of binary volumes

## Overview
Hierarchical Spatial Enumeration Optimization is a ray-tracing acceleration technique for volume rendering that encodes spatial coherence (empty regions) using a pyramid of binary volumes, also known as a complete octree representation [S1][S3, unofficial]. It solves the problem of efficiently skipping large empty regions in volumetric datasets during image-order rendering [S2, unofficial]. Unlike geometric ray tracing which uses bounding volumes or spatial subdivision with lists of primitives, this method uses a hierarchical binary volume structure, which is more efficient for volume data because volume datasets have tens of millions of spatially ordered cells with single samples, whereas geometric scenes have hundreds of cells with many primitives [S1]. It differs from [Jiang et al. Acceleration Structure](1673-jiang-et-al-acceleration-structure.md) by using a pyramid of binary volumes/complete octree rather than a condensed representation [S1].

## How it works
**Inputs:** A volumetric dataset of size $N \times N \times N$ voxels, where $N = 2^M + 1$ for some integer $M$ [S1]. Each voxel has an associated opacity $\alpha$ [S1].
**Outputs:** A pyramid of $M+1$ binary volumes $V_m$ for $m=0, \dots, M$, and the rendered image [S1].

**Data Structures:**
The pyramid consists of $M+1$ volumes $V_m$ [S1].
- **Level $m$ Volume ($V_m$):** A 3D array of binary values [S1].
- **Size:** $V_m$ has dimensions $\frac{N-1}{2^m} \times \frac{N-1}{2^m} \times \frac{N-1}{2^m}$ cells [S1].
- **Indexing:** Cells are indexed by level $m$ and vector $\mathbf{i} = (i, j, k)$ where $i, j, k \in \{1, \dots, \frac{N-1}{2^m}\}$ [S1].
- **Value:** $V_m(\mathbf{i}) \in \{0, 1\}$. $0$ indicates an empty region (all constituent voxels have zero opacity), $1$ indicates an occupied region [S3, unofficial].
- **Cell Size:** The physical size of a cell on level $m$ is $2^m$ times the spacing between voxels [S1]. Voxels are treated as point samples; cells fill the space between them [S1]. Each volume is one cell larger in each direction than the underlying dataset [S1].
- **Coordinate Alignment:** Voxel $(1,1,1)$ is placed at the front-lower-right corner of cell $(1,1,1)$ on level $0$ [S1]. Cell $(1,1,1)$ on level $0$ encloses the space between voxels $(1,1,1)$ and $(2,2,2)$ [S1].

**Construction Algorithm:**
The pyramid is constructed bottom-up [S1].
1. **Base Level ($V_0$):**
   For each cell $\mathbf{i} \in \{1, \dots, N-1\}^3$:
   $$V_0(\mathbf{i}) = \begin{cases} 1 & \text{if } \alpha(\mathbf{i} + \Delta\mathbf{i}) > 0 \text{ for any } \Delta\mathbf{i} \in \{0, 1\}^3 \\ 0 & \text{otherwise} \end{cases}$$
   Cell $\mathbf{i}$ in $V_0$ is $1$ if any of the 8 voxels at its vertices has non-zero opacity [S1][S3, unofficial].
2. **Recursive Levels ($m > 0$):**
   For each cell $\mathbf{i}$ in volume $V_m$:
   $$V_m(\mathbf{i}) = \begin{cases} 0 & \text{if } V_{m-1}(\mathbf{j}) = 0 \text{ for all 8 children } \mathbf{j} \text{ forming the octant of } \mathbf{i} \\ 1 & \text{otherwise} \end{cases}$$
   Cell $\mathbf{i}$ in $V_m$ is $0$ if all 8 cells on level $m-1$ that form its octants contain zeros [S1][S3, unofficial].

**Ray Traversal Algorithm:**
For each pixel, a viewing ray is traced from the observer position through the data [S1].
```python
def traverse_ray(ray_origin, ray_direction, pyramid, voxel_data, M):
    m = M
    # Compute entry point into the single cell at the top level
    t = compute_entry_t(ray_origin, ray_direction)
    while m >= 0:
        c = get_cell_index(m, ray_origin + t * ray_direction)
        if pyramid[m][c] == 0:
            # Advance to next cell on same level
            t += ray_direction.step_length(cell_size(m))
            c_new = get_cell_index(m, ray_origin + t * ray_direction)
            # If parent changed, move up to parent of new cell
            if parent_index(m, c) != parent_index(m, c_new):
                m += 1
        else:
            if m > 0:
                # Move down one level to enclosing child
                m -= 1
            else:
                # Leaf level: sample within this cell
                cell_start = ray_origin + t * ray_direction
                cell_end = cell_start + ray_direction * cell_size(m)
                num_samples = compute_even_samples(cell_start, cell_end)
                for i in range(num_samples):
                    sample_pos = interpolate_linear(cell_start, cell_end, i, num_samples)
                    color, opacity = resample_trilinear(voxel_data, sample_pos)
                    composite_front_to_back(color, opacity)
                # Advance to next cell on level 0
                t += ray_direction.step_length(cell_size(0))
```
*Note: Helper functions (`compute_entry_t`, `get_cell_index`, `parent_index`, `step_length`, `compute_even_samples`, `interpolate_linear`, `resample_trilinear`, `composite_front_to_back`) implement standard ray-cell intersection, grid indexing, trilinear resampling, and front-to-back compositing [S1][S3, unofficial].*

**Parameters:**
- $M$: Integer such that dataset side length $N = 2^M + 1$. The pyramid has levels $m = 0, \dots, M$ [S1].
- Opacity Threshold: Voxels with opacity $\alpha = 0$ are considered empty [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Coordinate Alignment:** Voxel $(1,1,1)$ must be placed at the front-lower-right corner of cell $(1,1,1)$ on level $0$ to ensure correct empty/occupied classification [S1].
- **Dataset Size:** The method requires $N = 2^M + 1$ [S1].

## Subtopics

### [Hierarchical Volume Traversal with Adaptive Termination](1682-hierarchical-volume-traversal-with-adaptive-termination.md)
Combines this pyramid structure with an adaptive termination criterion to stop tracing when opacity changes become negligible. Chosen when opacity accumulates quickly or objects are opaque, reducing dependence on depth complexity.

## Operating characteristics
- **Time Complexity:** Grows linearly with the size of the image, logarithmically with the length of each ray, and linearly with the depth complexity of the data [S2, unofficial].
- **Memory Complexity:** Requires storage for $M+1$ binary volumes [S1]. The total number of cells is $\sum_{m=0}^{M} (\frac{N-1}{2^m})^3$, which for large $N$ is dominated by the base level $V_0$ with $(N-1)^3$ cells [S1].
- **Performance:** Speedups of an order of magnitude have been observed for datasets of useful size and complexity [S1]. Saves time by quickly advancing across empty regions of space [S3, unofficial].
- **Strengths:** Efficiently skips large empty regions; suitable for image-order rendering of dense volumetric data [S1][S3, unofficial].
- **Limitations:** Requires $N = 2^M + 1$; construction cost is non-trivial; not suitable for geometric scenes with sparse primitives [S1].
- **When to Use:** Dense volumetric datasets with significant empty regions (e.g., medical imaging, molecular graphics) [S1][S2, unofficial].
- **When Not to Use:** Geometric scenes with few primitives; datasets where $N$ cannot be easily adjusted to $2^M + 1$ without excessive padding [S1].

## Background
Originated in the late 1980s by Marc Levoy [S1]. The technique was introduced in "Efficient ray tracing of volume data" (1988) [S1] and further detailed in "Rendering Mixtures of Geometric and Volumetric Data" (1989) [S2, unofficial]. It was developed to address the high computational cost of ray casting for large volumetric datasets by exploiting spatial coherence [S1][S2, unofficial]. It is used in medical imaging and molecular graphics applications [S1].
