# PBRTv4 BVH Layout

Also called: Decoupled BVH Layout, LinearBVH, LinearBVHNode, Original PBRTv4 layout, PBRTv4 layout, Scion BVH layout

## Overview
The PBRTv4 BVH Layout is a memory-efficient, cache-friendly representation of a Bounding Volume Hierarchy (BVH) used in the PBRTv4 rendering system [S1]. It solves the problem of pointer-chasing overhead and memory fragmentation inherent in traditional pointer-based BVHs by storing nodes in a contiguous array and primitives in a separate array [S1]. It sets itself apart from its parent [Pointer Chasing BVH Traversal](19488-pointer-chasing-bvh-traversal.md) by replacing explicit child pointers with implicit indexing and unified node structures, enabling more predictable memory access patterns during traversal [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A logical BVH tree (abstract data type) consisting of `Interior` and `Leaf` nodes, where `Interior` contains bounds and two child BVHs, and `Leaf` contains bounds, a primitive count, and an array of triangles [S1].
*   **Output:** A `LinearBVH` struct containing two contiguous arrays: `nodes` (BVH nodes) and `primitives` (triangles) [S1].

**Data Structures:**
The layout uses two primary C++ structs [S1]:

1.  `LinearBVH`: The container for the entire BVH.
    *   `uint32_t P`: Total number of primitives.
    *   `uint32_t N`: Total number of nodes.
    *   `Triangle* primitives`: Pointer to the contiguous array of triangles.
    *   `LinearBVHNode* nodes`: Pointer to the contiguous array of nodes.

2.  `LinearBVHNode`: The node structure, aligned to 32 bytes.
    *   `AABB bounds`: Axis-Aligned Bounding Box, containing `low` (float3) and `high` (float3) [S1].
    *   `uint16_t nprims`: Discriminator. Value `0` indicates an Interior node; value `> 0` indicates a Leaf node [S1].
    *   `uint8_t S[4]`: A 4-byte union field.
        *   If `nprims > 0` (Leaf): Interpreted as `uint32_t p_o`, the offset into the `primitives` array [S1].
        *   If `nprims == 0` (Interior): Interpreted as `uint32_t c_o`, the offset to the right child relative to the current node index [S1].

**Logical to Physical Mapping:**
*   **Left Child:** Implicitly located at `current_index + 1` [S1].
*   **Right Child:** Located at `current_index + c_o` [S1].
*   **Primitives:** Located at `primitives + p_o` for `nprims` elements [S1].

**Build Process:**
The build process consists of two recursive passes: counting and building [S1].

1.  **Counting (`rec_count`):** Traverses the logical BVH to determine the total number of nodes (`N`) and primitives (`P`) [S1].
2.  **Allocation:** Allocates memory for `primitives` (size `P * sizeof(Triangle)`) and `nodes` (size `N * sizeof(Nodes)`, aligned to 32 bytes) [S1].
3.  **Building (`rec_build`):** Traverses the logical BVH again, filling the physical arrays [S1].
    *   **Interior Node:**
        *   Store bounds.
        *   Set `nprims = 0`.
        *   Recursively build left child.
        *   Recursively build right child.
        *   Calculate `c_o = right_index - this_index`.
        *   Store `c_o` in `S` [S1].
    *   **Leaf Node:**
        *   Store bounds.
        *   Set `nprims` to the number of primitives.
        *   Store current `primitives_index` as `p_o` in `S`.
        *   Copy primitives from logical node to physical `primitives` array.
        *   Increment `primitives_index` by `nprims`.
        *   Return `this_index` [S1].

**Pseudocode:**
```python
# Data Structures
class AABB:
    low: Vector3  # float3
    high: Vector3 # float3

class Triangle:
    p0: Vector3
    p1: Vector3
    p2: Vector3

    bounds: AABB
    nprims: uint16  # 0 for Interior, >0 for Leaf
    S: uint8[4]     # Union: p_o (Leaf) or c_o (Interior)

class LinearBVH:
    P: uint32       # Primitive count
    N: uint32       # Node count
    primitives: List[Triangle]
    nodes: List[LinearBVHNode]

# Build Phase 1: Count Nodes and Primitives
def rec_count(logical_node, bvh):
    if logical_node is Interior:
        rec_count(logical_node.left, bvh)
        rec_count(logical_node.right, bvh)
        bvh.N += 1
    elif logical_node is Leaf:
        bvh.P += logical_node.nprims

# Build Phase 2: Construct Physical Layout
def rec_build(logical_node, bvh, nodes_index, primitives_index):
    this_index = nodes_index[0]
    nodes_index[0] += 1
    
    if logical_node is Interior:
        # Store bounds
        bvh.nodes[this_index].bounds = logical_node.bounds
        bvh.nodes[this_index].nprims = 0
        
        # Recurse Left (Implicitly this_index + 1)
        rec_build(logical_node.left, bvh, nodes_index, primitives_index)
        
        # Recurse Right
        right_index = rec_build(logical_node.right, bvh, nodes_index, primitives_index)
        
        # Store offset to right child
        bvh.nodes[this_index].S = right_index - this_index
        
        return this_index
        
    elif logical_node is Leaf:
        # Store bounds
        bvh.nodes[this_index].bounds = logical_node.bounds
        bvh.nodes[this_index].nprims = logical_node.nprims
        
        # Store primitive offset
        bvh.nodes[this_index].S = primitives_index[0]
        
        # Copy primitives
        for i in range(logical_node.nprims):
            bvh.primitives[primitives_index[0] + i] = logical_node.data[i]
            
        # Update primitive index
        primitives_index[0] += logical_node.nprims
        
        return this_index

def build_bvh(logical_bvh):
    bvh = LinearBVH()
    bvh.P = 0
    bvh.N = 0
    
    # Count
    rec_count(logical_bvh, bvh)
    
    # Allocate
    bvh.primitives = [Triangle() for _ in range(bvh.P)]
    bvh.nodes = [LinearBVHNode() for _ in range(bvh.N)]
    
    # Build
    nodes_index = [0]
    primitives_index = [0]
    rec_build(logical_bvh, bvh, nodes_index, primitives_index)
    
    return bvh

# Traversal Phase: Closest Hit
def closest_hit(ray, bvh, best):
    # best is a tuple (distance, triangle)
    # Initialize best with infinity if no hit found yet
    if best[0] == float('inf'):
        best = (float('inf'), None)
        
    stack = [0] # Start at root node index 0
    
    while stack:
        i = stack.pop()
        node = bvh.nodes[i]
        
        # Check intersection with node bounds
        if intersects_ray_aabb(ray, node.bounds):
            # Check if closer than current best
            if distmin_ray_aabb(ray, node.bounds) < best[0]:
                if node.nprims > 0:
                    # Leaf Node
                    start_prim_idx = node.S # p_o
                    for k in range(node.nprims):
                        prim = bvh.primitives[start_prim_idx + k]
                        if intersects_ray_triangle(ray, prim):
                            dist = distmin_ray_triangle(ray, prim)
                            if dist < best[0]:
                                best = (dist, prim)
                else:
                    # Interior Node
                    # Left child is implicit: i + 1
                    # Right child is i + c_o
                    left_child = i + 1
                    right_child = i + node.S # c_o
                    
                    # Push children to stack. Order depends on traversal strategy.
                    # For closest hit, order matters for early termination.
                    # Standard approach: push right then left to process left first (LIFO)
                    # Or use distance heuristic to order.
                    # Here we simply push both.
                    stack.append(right_child)
                    stack.append(left_child)
```

**Parameters:**
*   Node alignment: 32 bytes [S1].
*   Primitive storage: Separate contiguous array [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** The `S` field is 4 bytes. For interior nodes, `c_o` is an offset. If the tree is very deep or unbalanced, offsets must fit in `uint32_t`. [S1] does not specify limits, but `uint32_t` implies a max node count of $2^{32}-1$.
*   **Boundary Conditions:** The left child is always `i+1`. If `i` is the last node, `i+1` is out of bounds. This implies the tree structure must be valid (no dangling left children). [S1] assumes a valid BVH structure.
*   **Degenerate Input:** Empty BVHs or BVHs with no primitives are not explicitly handled in the pseudocode, but `P=0` and `N=0` would result in empty arrays. [S1]

## Subtopics

### Compressed-Leaf BVH
A variant that quantizes leaf bounds to save space. The PBRTv4 layout described here is the "Original" or "Uncompressed" version [S1].

### Pointer Chasing BVH Traversal
The parent method that uses explicit pointers. The PBRTv4 layout replaces this with implicit indexing to improve cache performance [S1].

## Operating characteristics
*   **Time Complexity:** Build time is $O(N)$ where $N$ is the number of nodes, as it requires two passes over the logical tree [S1]. Traversal time is $O(K)$ where $K$ is the number of visited nodes, same as pointer-chasing, but with better cache locality [S1].
*   **Memory Complexity:** $O(N + P)$ where $N$ is node count and $P$ is primitive count. Nodes are 32 bytes each. Primitives are stored separately [S1].
*   **Strengths:**
    *   Cache-friendly due to contiguous node array [S1].
    *   Reduced memory overhead by eliminating explicit child pointers and using implicit indexing [S1].
    *   Unified node structure simplifies memory management [S1].
*   **Limitations:**
    *   Less flexible than pointer-based structures for dynamic updates (insertions/deletions) due to contiguous layout [S1].
    *   Requires two-pass build process (count then build) [S1].
*   **When to use:** Static scenes where ray tracing performance is critical and memory bandwidth is a bottleneck [S1].
*   **When not to use:** Dynamic scenes requiring frequent BVH updates [S1].

## Background
The PBRTv4 BVH Layout was introduced in the PBRTv4 rendering system [S1]. It is described in the paper "Decoupling Data Layouts from Bounding Volume Hierarchies" (2026) by Christophe Gyurgyik et al. [S1]. The layout is designed to combine the clarity of Abstract Data Types (ADTs) with the performance of specialized memory layouts [S1]. It is implemented in C++ and is also described using the Scion declarative layout language [S1].
