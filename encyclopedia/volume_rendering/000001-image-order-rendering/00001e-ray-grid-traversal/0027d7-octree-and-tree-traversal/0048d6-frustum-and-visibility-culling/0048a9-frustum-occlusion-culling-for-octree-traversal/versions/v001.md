# Frustum-Occlusion Culling for Octree Traversal

Also called: Frustum-octant traversal, Voxel LOD selection, Voxel LOD selection via Frustum Culling, Voxel Rasterization via Frustum Culling and Instancing

## Overview
This method identifies visible voxels in an octree by traversing the hierarchy against the camera's view frustum, automatically selecting the Level of Detail (LOD) based on screen projection size [S1, unofficial]. It differs from ray-casting methods by treating the volume as a set of discrete, rasterizable cubes rather than a continuous scalar field, relying on hardware instancing for final rendering [S1, unofficial].

## How it works
**Inputs:** Camera view frustum parameters, octree structure (implicit or explicit), bounding box of the entire octree.
**Outputs:** A buffer of voxel instances (position and size) ready for rasterization.

**Data Structures:**
*   **Octree:** Stored in breadth-first order. Each node uses a single 8-bit mask to indicate occupied children [S1, unofficial].
*   **Voxel Instance Buffer:** A dynamic array storing tuples of $(\mathbf{p}, s)$, where $\mathbf{p}$ is the voxel center and $s$ is the half-extent (size).
*   **Canonical Voxel Template:** A unit cube defined by extreme vertices $\mathbf{c}_{min} = (-1, -1, -1)$ and $\mathbf{c}_{max} = (1, 1, 1)$ [S1, unofficial].

**Algorithm:**
1.  **Initialization:** Start traversal at the root octant. Calculate the bounding box of the current node based on the global AABB and the node's depth/position in the hierarchy.
2.  **Frustum Intersection Test:** Determine if the current octant intersects the view frustum. To optimize, approximate the octant as a sphere with diameter equal to the octant's diagonal [S1, unofficial].
3.  **Traversal Decision:**
    *   If the octant does **not** intersect the frustum, prune this branch.
    *   If the octant **does** intersect, check termination conditions:
        a.  **Leaf Node:** No further subdivisions exist.
        b.  **Screen Size Threshold:** The projected area of the octant on the screen is less than the area of a single pixel.
    *   If either termination condition is met, record the voxel's position and size in the instance buffer and stop descending this branch [S1, unofficial].
    *   If neither condition is met, descend to the children indicated by the 8-bit occupancy mask.
4.  **Buffer Population:** For every halted node (leaf or screen-sized), compute its world-space position and size implicitly from the traversal state and append to the buffer [S1, unofficial].
5.  **Rasterization:** Pass the instance buffer to a hardware instancing pipeline (e.g., Geometry Shader, Uniform Buffer, or Vertex Buffer) to render the voxels using the canonical template [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Numeric Precision:** At extreme subdivision levels, numeric precision issues may arise. However, LOD traversal typically halts at coarser levels based on screen size before precision becomes critical [S1, unofficial].
*   **Over-subdivision:** Allocating nodes for extremely deep levels is inefficient if they are never rendered due to the screen-size criterion. The traversal should respect a maximum depth limit to avoid unnecessary memory allocation [S1, unofficial].
*   **Empty Space:** The 8-bit mask efficiently skips empty branches, but the frustum test must be applied before checking the mask to ensure correct culling [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of visible voxels and the depth of the octree. The frustum-sphere intersection is $O(1)$ per node.
*   **Memory Complexity:** $O(N)$ where $N$ is the number of visible voxels, for the instance buffer. The octree storage is compact (1 byte per node in breadth-first order) [S1, unofficial].
*   **Performance:** Profiled on Intel Core i5-2540M and NVIDIA Quadro 3000M at 1920x1280 resolution. Voxel rendering times for the 'basketball' dataset (depth 10) were:
    *   Geometry Shader: 3.454 ms
    *   Uniform Buffer: 2.549 ms (Fastest)
    *   Hardware Texture Buffer: 2.773 ms
    *   Instancing Vertex Buffer: 5.599 ms (Slowest) [S1, unofficial]
*   **Strengths:** Automatic LOD selection; efficient culling of non-visible regions; compact octree storage.
*   **Limitations:** Rasterization overhead depends on the chosen instancing method; Geometry Shaders are slower for voxels than for surfels due to geometric complexity [S1, unofficial].

## Background
This method was introduced in the context of hardware-accelerated rendering of scanned 4D media, combining octree-based LOD selection with geometry instancing [S1, unofficial]. It addresses the need for efficient visualization of large, sparse volumetric datasets by treating voxels as discrete geometric primitives rather than continuous data.
