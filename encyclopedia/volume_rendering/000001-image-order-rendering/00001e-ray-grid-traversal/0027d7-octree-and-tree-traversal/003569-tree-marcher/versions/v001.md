# Tree Marcher

Also called: Tree Marcher for Generic Grids

## Overview
The Tree Marcher is a ray traversal algorithm for generic hierarchical grids, specifically designed to integrate with the OpenVDB data structure. It solves the problem of efficiently stepping through sparse voxel data by combining hierarchical empty-space skipping with Digital Differential Analyzer (DDA) logic at the leaf level. Unlike sibling methods that may rely on geometric intersection tests for child selection, Tree Marcher utilizes a hierarchical DDA (HDDA) approach to determine traversal order, making it distinct from [Octree Path Computation](897-octree-path-computation.md) and [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md).

## How it works
The algorithm operates on a hierarchical grid structure where nodes represent volumes of varying sizes. It uses a template-based design to support different ray types, coordinate types, and accessor interfaces.

**Inputs and Outputs:**
*   **Input:** A ray defined by origin and direction, a grid accessor providing access to node data, and the root node of the hierarchical grid.
*   **Output:** A sequence of voxel coordinates ($ijk$) and values ($v$) encountered along the ray, along with the intersection time ($t$) if a zero-crossing is detected.

**Data Structures:**
The implementation relies on the `NodeT` template parameter, which defines the node layout. The `AccT` accessor provides methods to retrieve voxel values and determine node occupancy. The `RayT` structure contains the ray origin, direction, and inverse direction. The `CoordT` type represents integer coordinates.

**Algorithm Steps:**
1.  **Initialization:** Initialize the ray parameters and the current node pointer to the grid root.
2.  **Hierarchical Descent:** Use the HDDA mechanism to traverse the tree. The HDDA maintains the entry and exit parameters ($t_{min}, t_{max}$) for the current node's bounding box relative to the ray.
3.  **Empty Space Skipping:** If the current node is marked as empty or uniform, skip directly to the next potentially occupied node. This is achieved by advancing the ray parameter $t$ to the exit of the current node or using neighbor pointers if available [G].
4.  **Leaf Traversal:** Upon reaching a leaf node, switch to a fixed-step DDA. The DDA uses a step size defined by the template parameter `Dim` (typically the voxel size of the leaf) to step through the voxels along the ray [S1].
5.  **Zero-Crossing Detection:** For each voxel visited, check for zero-crossings in the scalar field. The `ZeroCrossing` function updates the voxel index $ijk$, the value $v$, and the intersection time $t$ if a crossing is found [S1].
6.  **Termination:** Continue traversal until the ray exits the grid or a maximum depth/step count is reached.

**Pseudocode:**
```python
def TreeMarcher(RayT ray, AccT acc, NodeT root):
    # Initialize HDDA state for the root node
    hdda = HDDA(ray, root.bounding_box)
    
    while hdda.is_valid():
        node = hdda.current_node()
        
        if node.is_empty():
            # Skip empty node by advancing HDDA
            hdda.advance_to_next_node()
            continue
            
        if node.is_leaf():
            # Switch to leaf-level DDA
            leaf_dda = DDA(ray, node, Dim=node.voxel_size)
            while leaf_dda.is_valid():
                voxel = leaf_dda.current_voxel()
                v = acc.get_value(voxel)
                
                # Check for zero-crossing
                if ZeroCrossing(ray, acc, voxel.ijk, v, t):
                    yield (voxel.ijk, v, t)
                    
                leaf_dda.step()
        else:
            # Descend into children using HDDA logic
            hdda.descend()
```

**Parameters:**
*   `NodeT`: The node type template parameter [S1].
*   `RayT`: The ray type template parameter [S1].
*   `AccT`: The accessor type template parameter [S1].
*   `CoordT`: The coordinate type template parameter [S1].
*   `Dim`: The fixed step size for the DDA at leaf nodes [S1].

**Edge Cases:**
*   **Precision:** Floating-point precision issues may arise when computing ray-node intersections, especially for long rays or small voxels.
*   **Boundaries:** Ensure the ray origin is correctly handled if it lies exactly on a node boundary.
*   **Degenerate Input:** Empty grids or rays that do not intersect the grid should be handled gracefully by returning no results.

## Subtopics

### PointTreeMarcher
A specialized Tree Marcher for Point Grids. It differs from the generic Tree Marcher by operating on point-based data structures rather than volumetric grids. It is chosen when the underlying data is a set of points rather than a scalar field. Parameters include `AccT`, `RayT`, and `CoordT` [S1].

## Operating characteristics
The Tree Marcher provides efficient traversal for sparse grids by skipping empty space at multiple levels of the hierarchy. Its performance depends on the sparsity of the grid and the distribution of the ray. In dense regions, it behaves similarly to a standard DDA, while in sparse regions, it offers significant speedups due to empty space skipping. Memory usage is proportional to the depth of the tree and the number of active nodes visited.

## Background
The Tree Marcher is part of the OpenVDB library, developed by DreamWorks Animation for visual effects production. It is designed to work with the Hierarchical Digital Differential Analyzer (HDDA) for efficient ray traversal in large-scale volumetric data. The method is documented in the OpenVDB header file `HDDA.h` [S1].
