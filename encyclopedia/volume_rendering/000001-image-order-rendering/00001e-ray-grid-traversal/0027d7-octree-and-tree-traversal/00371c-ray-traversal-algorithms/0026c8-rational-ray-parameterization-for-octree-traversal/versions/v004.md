# Rational Ray Parameterization for Octree Traversal

Also called: Integer Ray Tracing, Rational Arithmetic Ray Tracing

## Overview
Rational Ray Parameterization for Octree Traversal is a method for tracing rays through an octree using exact rational arithmetic to avoid floating-point precision errors during cell boundary crossing and neighbor finding [S1]. It solves the problem of determining the next cell intersected by a ray when the ray parameters are not integers, which typically occurs when the viewplane is in an arbitrary position in space [S1]. Unlike sibling methods that rely on floating-point comparisons or pre-computed structures, this method guarantees robustness by representing ray parameters as rational numbers (numerator/denominator pairs) and using integer arithmetic for all comparisons and boundary tests [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray defined by viewpoint $B = (b_x, b_y, b_z)$ with integer coordinates, and direction coefficients $m_x, m_y, m_z$ which are rational numbers [S1]. Octree root pointer. Scene width $W_{scene}$ (assumed power of 2) [S1].
*   **Output:** Sequence of octree nodes visited by the ray, or intersection points with objects within those nodes.

**Data Structures:**
*   **Rational Number:** Represented as a pair $(num, den)$ where $den > 0$ [S1]. Comparisons are performed via cross-multiplication: $\frac{a}{b} < \frac{c}{d} \iff a \cdot d < c \cdot b$ [S1].
*   **Cell Record:** Contains 6 fields [S1]:
    *   `T_IN`: Rational number, entry parameter $t$.
    *   `T_OUT`: Rational number, exit parameter $t$.
    *   `SIZ`: Integer, cell width $W$.
    *   `PTR`: Pointer to the octree node.
    *   `CORNER`: Array of 3 integers, coordinates of the furthest corner from the origin $(c_x, c_y, c_z)$ [S1].
    *   `DIRECT`: Enum/Direction code for the next cell relative to the current one (e.g., 'L', 'R', 'U', 'D', 'F', 'B', or combinations like 'LUB') [S1].

**Algorithm Steps:**

1.  **Rational Parameterization:**
    Convert the ray direction coefficients $m_x, m_y, m_z$ to integers by finding the lowest common denominator $c$ of the three rational coefficients [S1]. Define a new parameter $t' = t/c$. The parametric equations become [S1]:
    $$
    x = m'_x \cdot t' + b_x
    $$
    $$
    y = m'_y \cdot t' + b_y
    $$
    $$
    z = m'_z \cdot t' + b_z
    $$
    where $m'_x, m'_y, m'_z$ are integers (numerators) and $b_x, b_y, b_z$ are integers (viewpoint coordinates) [S1]. In the remainder of the algorithm, we use $m_i$ and $t$ to refer to these integer numerators and the scaled parameter $t'$ respectively [S1].

2.  **Initial Entry Point (FIRST_POINT):**
    Determine the entry point of the ray into the entire scene (bounding box of width $W_{scene}$ starting at origin) [S1].
    *   Clip the ray against the scene boundaries [S1].
    *   Compute $t^{in}$ and $t^{out}$ for each coordinate axis $i \in \{x, y, z\}$ against the planes $0$ and $W_{scene}$ [S1].
    *   If $m_i < 0$, $t^{in}$ corresponds to the plane at $W_{scene}$ and $t^{out}$ to $0$. If $m_i > 0$, $t^{in}$ corresponds to $0$ and $t^{out}$ to $W_{scene}$ [S1].
    *   The valid range for $t$ inside the scene is $[\max(t^{in}_i), \min(t^{out}_i)]$ over all $i$ [S1].
    *   If $\max(t^{in}_i) > \min(t^{out}_i)$, the ray misses the scene; terminate [S1].
    *   Identify the exit point $P$ of the ray from the scene boundary to determine the initial direction of traversal relative to the first cell [S1].

3.  **Locate First Cell (FIND_3D_BLOCK):**
    Use a point location algorithm (descend from root) to find the octree node containing the entry point $P$ [S1]. Create the initial `Cell` record with `T_IN`, `T_OUT`, `SIZ`, `PTR`, `CORNER`, and `DIRECT` [S1].

4.  **Main Traversal Loop:**
    For each current cell $C$:
    a.  **Process Cell:** Intersect the ray with objects in $C$ using `RAY_INTERSECTS_OBJECT_IN_CELL` [S1]. If an intersection is found, handle reflection/refraction or return the hit [S1].
    b.  **Determine Exit:** The ray exits $C$ at parameter $t^{out} = \min(t^{out}_x, t^{out}_y, t^{out}_z)$ [S1]. Let $P = (P_x, P_y, P_z)$ be the 3D coordinates of the exit point [S1].
    c.  **Classify Exit Point:** Determine the type of exit point $P$ on the boundary of $C$ [S1]:
        *   **Vertex:** $t^{out}$ is equal for all three coordinates.
        *   **Edge:** $t^{out}$ is equal for exactly two coordinates.
        *   **Face:** $t^{out}$ is different for all three coordinates.
    d.  **Determine Direction $L$:** Calculate the direction vector $L = (l_x, l_y, l_z)$ to the next cell $C'$ based on the exit type and which boundaries were crossed [S1].
    e.  **Find Neighbor:** Call `OT_GTEQ_NEIGHBOR` to find the neighbor $N$ of $C$ in direction $L$ such that $width(N) \ge width(C)$ [S1].
        *   If no such neighbor exists, the ray has exited the scene; terminate [S1].
        *   If $N$ is a leaf (not gray), set $C' = N$ [S1].
        *   If $N$ is gray, calculate a point $Q$ guaranteed to be inside $C'$ (see below) and use point location to find the specific descendant $C'$ of $N$ [S1].
    f.  **Update State:** Create a new `Cell` record for $C'$ with updated `T_IN`, `T_OUT`, etc., and repeat [S1].

5.  **Point $Q$ Calculation (for Gray Neighbors):**
    To locate $C'$ when the neighbor $N$ is gray, compute a point $Q$ strictly inside $C'$ [S1].
    *   Let $P = (P_x, P_y, P_z)$ be the exit point from $C$ [S1].
    *   Let $L = (l_x, l_y, l_z)$ be the direction to $C'$ [S1].
    *   Convention: Left, Down, and Back faces are closed. If a point lies on these faces, it is considered inside the cell bounded by them [S1].
    *   For each coordinate $j$ where $l_j$ is negative (decreasing direction), subtract a small integer value $A$ from $P_j$ to ensure $Q$ is inside $C'$ [S1].
    *   $A$ must be $> 1$ (width of smallest cell) and compatible with integer arithmetic [S1]. The text suggests $A=1$ is sufficient if coordinates are integers, but notes $A$ must be small enough not to jump over cells [S1].
    *   Example: If $L = \text{'LUB'}$ (Left, Up, Back), $l_x < 0$ and $l_z < 0$. Then $Q = (P_x - 1, P_y, P_z - 1)$ [S1].
    *   Example: If $L = \text{'RD'}$ (Right, Down), $l_y < 0$. Then $Q = (P_x, P_y - 1, P_z)$ [S1]. Note that $P_x$ and $P_z$ are already integers because $P$ lies on an edge or vertex [S1].

6.  **Neighbor Finding Implementation:**
    *   **Pointer-based:** Use `FATHER` links in the octree to traverse up and down to find the neighbor [S1].
    *   **Pointer-less (Locational Codes):** Represent nodes by locational codes (depth + concatenated base-8 digits). Manipulate bits of the code based on direction $L$ to find the neighbor's code, then search for it [S1].

**Pseudocode:**

```python
def rational_ray_tracer(ray_viewpoint, ray_direction_rational, octree_root, scene_width):
    # 1. Rational Parameterization
    c = lcm(ray_direction_rational.x.denom, ray_direction_rational.y.denom, ray_direction_rational.z.denom)
    m_x = ray_direction_rational.x.num * (c // ray_direction_rational.x.denom)
    m_y = ray_direction_rational.y.num * (c // ray_direction_rational.y.denom)
    m_z = ray_direction_rational.z.num * (c // ray_direction_rational.z.denom)
    
    b_x, b_y, b_z = ray_viewpoint.x, ray_viewpoint.y, ray_viewpoint.z
    
    # 2. Initial Entry
    t_min, t_max, exit_point, exit_type = clip_ray_against_box(
        b_x, b_y, b_z, m_x, m_y, m_z, 0, scene_width
    )
    
    if t_min > t_max:
        return []
    
    # 3. Locate First Cell
    current_cell = find_3d_block(octree_root, exit_point, scene_width)
    
    results = []
    
    while current_cell is not None:
        hit = ray_intersects_object_in_cell(current_cell, b_x, b_y, b_z, m_x, m_y, m_z, t_min, t_max)
        if hit:
            results.append(hit)
            break
            
        t_exit = current_cell.t_out
        
        p_x = m_x * t_exit + b_x
        p_y = m_y * t_exit + b_y
        p_z = m_z * t_exit + b_z
        
        t_out_x = rational_div(current_cell.corner.x - b_x, m_x) if m_x != 0 else None
        t_out_y = rational_div(current_cell.corner.y - b_y, m_y) if m_y != 0 else None
        t_out_z = rational_div(current_cell.corner.z - b_z, m_z) if m_z != 0 else None
        
        exit_type = classify_exit_point(t_out_x, t_out_y, t_out_z)
        l = determine_direction(exit_type, p_x, p_y, p_z, current_cell)
        
        neighbor_ptr = ot_gteq_neighbor(current_cell.ptr, l)
        
        if neighbor_ptr is None:
            break
            
        if is_leaf(neighbor_ptr):
            next_cell_ptr = neighbor_ptr
            next_cell_size = get_leaf_size(neighbor_ptr)
        else:
            q = calculate_point_q(p_x, p_y, p_z, l)
            next_cell_ptr = find_3d_block(octree_root, q, scene_width)
            next_cell_size = get_node_size(next_cell_ptr)
            
        current_cell = create_cell_record(next_cell_ptr, next_cell_size, t_exit)
        
    return results

# Helper definitions
def lcm(a, b):
    return (a * b) // gcd(a, b)

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def rational_div(num, den):
    return (num, den)

def rational_lt(r1, r2):
    return r1[0] * r2[1] < r2[0] * r1[1]

def rational_eq(r1, r2):
    return r1[0] * r2[1] == r2[0] * r1[1]

def clip_ray_against_box(bx, by, bz, mx, my, mz, min_val, max_val):
    t_candidates = []
    for m, b, p_min, p_max in [(mx, bx, min_val, max_val), (my, by, min_val, max_val), (mz, bz, min_val, max_val)]:
        if m != 0:
            t1 = rational_div(p_min - b, m)
            t2 = rational_div(p_max - b, m)
            if m > 0:
                t_candidates.append((t1, 'in'))
                t_candidates.append((t2, 'out'))
            else:
                t_candidates.append((t2, 'in'))
                t_candidates.append((t1, 'out'))
    
    t_in = t_candidates[0][0]
    t_out = t_candidates[0][0]
    for t, type in t_candidates:
        if type == 'in' and not rational_lt(t_in, t): t_in = t
        if type == 'out' and not rational_lt(t, t_out): t_out = t
    return t_in, t_out, None, None

def classify_exit_point(t_out_x, t_out_y, t_out_z):
    if t_out_x is None or t_out_y is None or t_out_z is None:
        return 'face'
    if rational_eq(t_out_x, t_out_y) and rational_eq(t_out_y, t_out_z):
        return 'vertex'
    elif rational_eq(t_out_x, t_out_y) or rational_eq(t_out_x, t_out_z) or rational_eq(t_out_y, t_out_z):
        return 'edge'
    else:
        return 'face'

def calculate_point_q(px, py, pz, l):
    qx = px - 1 if l.x < 0 else px
    qy = py - 1 if l.y < 0 else py
    qz = pz - 1 if l.z < 0 else pz
```

## Subtopics

### [Arbitrary 3D Resolution Discrete Ray Traversal](4081-arbitrary-3d-resolution-discrete-ray-traversal.md)
Arbitrary 3D Resolution Discrete Ray Traversal is a method for tracing rays through implicit surfaces by voxelizing both the scene and the rays using interval arithmetic within a recursive octree subdivision. It eliminates explicit intersection calculations by ensuring the discrete ray matches the continuous ray down to the resolution of floating-point numbers, guaranteeing robustness against rounding errors. Unlike sibling methods that calculate explicit intersections or rely on pre-computed structures, this method performs on-the-fly subdivision and uses BSP ordering to determine traversal sequence without geometric intersection tests.

### [Single-Ray Octree Traversal](5477-single-ray-octree-traversal.md)
Single-ray octree traversal is a method for rendering implicit surfaces by ray tracing an octree-encapsulated volume directly, using the octree as an acceleration structure to locate cell primitives. It solves the problem of efficiently finding the intersection between a ray and a piecewise $C^0$ isosurface defined by trilinear interpolant patches within octree cells. Unlike coherent traversal techniques that process packets of rays or frustums, this method processes one ray at a time, prioritizing optimized single-ray performance over the modest speedups gained from coherence in highly variant scenes.

## Operating characteristics
*   **Time Complexity:** The traversal time depends on the number of nodes visited. Neighbor finding is cheaper than point location from the root, but still requires tree traversal. The use of exact arithmetic (rational numbers) increases the cost of basic operations (addition, multiplication, comparison) compared to floating-point arithmetic [S1].
*   **Memory Complexity:** Requires storage for the octree and the rational number representations (two integers per parameter). The cell record structure is small (6 fields) [S1].
*   **Performance:** Exact arithmetic avoids precision errors but is computationally expensive. The method is robust but slower than floating-point counterparts due to the overhead of rational arithmetic and neighbor finding [S1].
*   **Strengths:** Guaranteed robustness against floating-point errors in boundary crossing and neighbor finding. No tolerance parameters needed for equality tests [S1].
*   **Limitations:** High computational cost of rational arithmetic. Assumes integer viewpoints and power-of-2 scene widths. The described implementation does not support rational viewpoints, though the solution can be modified to permit them [S1].
*   **When to Use:** When exact geometric predicates are critical and floating-point errors lead to incorrect traversal or missed intersections [S1].
*   **When Not to Use:** For real-time applications where performance is paramount and approximate floating-point methods are sufficient.

## Background
The method was introduced by Wyvill and Kunii in 1989 [S1]. It addresses the limitations of floating-point arithmetic in ray tracing through octrees, particularly in neighbor finding and boundary crossing. The approach is based on the Cyrus-Beck clipping algorithm and builds on earlier work by Glassner and Wyvill and Kunii [S1]. It is used in contexts requiring high precision in ray-triangle or ray-object intersection tests within hierarchical structures.
