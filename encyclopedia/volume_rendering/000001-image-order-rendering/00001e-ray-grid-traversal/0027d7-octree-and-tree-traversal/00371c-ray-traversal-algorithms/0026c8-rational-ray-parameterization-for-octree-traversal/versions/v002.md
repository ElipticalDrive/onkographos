# Rational Ray Parameterization for Octree Traversal

Also called: Integer Ray Tracing, Rational Arithmetic Ray Tracing

## Overview
Rational Ray Parameterization is a method for tracing rays through an octree using exact rational arithmetic to avoid floating-point precision errors during cell boundary crossing and neighbor finding [S1]. It solves the problem of determining the next cell intersected by a ray when the ray parameters are not integers, ensuring robust traversal without tolerance-based comparisons [S1]. Unlike sibling methods that calculate explicit geometric intersections or rely on pre-computed structures, this method uses integer-based neighbor finding and rational parameter comparisons to guarantee correctness [S1]. It builds on [Octree and Tree Traversal](4134-octree-and-tree-traversal.md) by providing a specific, exact mechanism for child selection and boundary crossing.

## How it works
**Inputs and Outputs:**
*   **Input:** Ray defined by viewpoint $B = (b_x, b_y, b_z)$ with integer coordinates, and direction coefficients $m_x, m_y, m_z$ which may be rational. Octree root pointer. Scene width $W_{scene}$ (assumed power of 2).
*   **Output:** Sequence of octree nodes (cells) intersected by the ray, with entry and exit parameters $t_{in}, t_{out}$.

**Data Structures:**
*   **Cell Record:** Contains 6 fields [S1]:
    *   `T_IN`: Rational number, $t$ value at entry.
    *   `T_OUT`: Rational number, $t$ value at exit.
    *   `SIZ`: Integer, width of the cell.
    *   `PTR`: Pointer to the octree node.
    *   `CORNER`: Array of 3 integers, coordinates of the furthest corner from the origin $(0,0,0)$.
    *   `DIRECT`: Direction code to the next cell (e.g., 'L', 'R', 'U', 'D', 'F', 'B').
*   **Rational Number:** Represented as an ordered pair $(numerator, denominator)$ [S1]. Comparisons are performed via cross-multiplication to maintain exactness [S1].

**Parameters:**
*   **Scene Width:** Assumed to be a power of 2 [S1].
*   **Smallest Cell Width:** 1 [S1].
*   **Viewpoint:** Must have integer coordinates [S1].
*   **Ray Direction:** Converted to integers by finding the lowest common denominator $c$ of the rational coefficients $m_x, m_y, m_z$. The parametric equation becomes $x = m'_x t' + b_x$, where $t' = t/c$ and $m'_x$ are the integer numerators [S1].

**Steps:**

1.  **Ray Parameterization:**
    Given rational direction coefficients $m_x, m_y, m_z$, compute $c = \text{lcm}(\text{denom}(m_x), \text{denom}(m_y), \text{denom}(m_z))$. Define $t' = t/c$ and $m'_i = m_i \cdot c$. The ray is now $P(t') = B + M' t'$, where $M' = (m'_x, m'_y, m'_z)$ are integers [S1].

2.  **Initial Entry:**
    Call `FIRST_POINT` to find the entry $t$ and direction relative to the scene boundary. If the ray starts outside the scene, terminate [S1].
    Call `FIND_3D_BLOCK` to locate the initial cell $C$ containing the entry point using point location (descending from root) [S1].

3.  **Cell Clipping (Entry/Exit Calculation):**
    For the current cell $C$ of width $W$, bounded by $[x_0, x_0+W]$, $[y_0, y_0+W]$, $[z_0, z_0+W]$:
    *   For each coordinate $i \in \{x, y, z\}$, compute the $t$ values where the ray intersects the bounding planes $i_0$ and $i_0+W$ [S1]:
        $$ t = \frac{i_{bound} - b_i}{m'_i} $$
    *   Determine $t^{in}_i$ and $t^{out}_i$ based on the sign of $m'_i$ [S1]:
        *   If $m'_i < 0$: $t^{in}_i$ corresponds to $i_0 + W$, $t^{out}_i$ corresponds to $i_0$.
        *   If $m'_i > 0$: $t^{in}_i$ corresponds to $i_0$, $t^{out}_i$ corresponds to $i_0 + W$.
    *   The valid range for $t$ inside the cell is $[t_{max\_in}, t_{min\_out}]$ where:
        $$ t_{max\_in} = \max(t^{in}_x, t^{in}_y, t^{in}_z) $$
        $$ t_{min\_out} = \min(t^{out}_x, t^{out}_y, t^{out}_z) $$
    *   Store these as `T_IN` and `T_OUT` for cell $C$ [S1].

4.  **Exit Point Classification:**
    Determine the exit point $P$ of the ray from cell $C$ by comparing $t^{out}_x, t^{out}_y, t^{out}_z$ using exact rational comparison (cross-multiplication) [S1]:
    *   **Vertex:** All three $t^{out}$ values are equal.
    *   **Edge:** Exactly two $t^{out}$ values are equal.
    *   **Face:** All three $t^{out}$ values are distinct.

5.  **Next Cell Direction Determination:**
    Calculate the direction $L = (l_x, l_y, l_z)$ of the next cell $C'$ relative to $C$ based on the position of $P$ [S1]:
    *   If $P$ is on a face (e.g., $t^{out}_x$ is the minimum), the direction is along the normal of that face (e.g., Left or Right).
    *   If $P$ is on an edge, the direction is along the edge vector.
    *   If $P$ is on a vertex, the direction is along the vertex diagonal.

6.  **Neighbor Finding:**
    Find the neighbor $N$ of $C$ in direction $L$ such that $\text{width}(N) \ge \text{width}(C)$ [S1].
    *   If no such neighbor exists, the ray has exited the scene. Terminate.
    *   If $N$ is a leaf (not gray), then $C' = N$.
    *   If $N$ is gray, calculate a point $Q$ guaranteed to be inside $C'$ and use point location to find $C'$ [S1].

7.  **Point Q Calculation (for Gray Neighbors):**
    Let $P = (P_x, P_y, P_z)$ be the exit point. Let $L = (l_x, l_y, l_z)$ be the direction.
    *   Convention: Left, Down, Back faces are closed.
    *   If $l_j < 0$ (decreasing direction), subtract a small value $A$ from $P_j$.
    *   $A$ must be $> 1$ (width of smallest cell) and $> 1$ for integer arithmetic. Conventionally, $A=1$ is used in the integer logic context described, but the text specifies $A$ must be larger than the smallest cell width (1) to ensure $Q$ is strictly inside if using floating point, but for integer arithmetic, the text implies using integer parts and subtracting 1 to handle the "closed face" convention [S1].
    *   Example: If $L = \text{'LUB'}$ (Left, Up, Back), $l_x < 0, l_z < 0$. $Q = (P_x - 1, P_y, P_z - 1)$.
    *   Example: If $L = \text{'RD'}$ (Right, Down), $l_y < 0$. $Q = (P_x, P_y - 1, P_z)$ [S1].

8.  **Point Location (if needed):**
    If $C'$ is not directly found via neighbor pointers (e.g., pointer-less octree), locate $C'$ by finding the cell containing $Q$ using a point location algorithm (descending from root) [S1].

**Pseudocode:**

```python
def rational_ray_tracer(ray_viewpoint, ray_direction_coeffs, octree_root, scene_width):
    """
    ray_viewpoint: tuple (bx, by, bz) - integers
    ray_direction_coeffs: tuple (mx, my, mz) - rationals (num, den)
    octree_root: pointer to root node
    scene_width: int, power of 2
    """
    # 1. Parameterization
    # Convert rational direction coefficients to integers
    # Find LCM of denominators
    c = lcm(ray_direction_coeffs[0].den, ray_direction_coeffs[1].den, ray_direction_coeffs[2].den)
    m_prime = (ray_direction_coeffs[0].num * c // ray_direction_coeffs[0].den,
               ray_direction_coeffs[1].num * c // ray_direction_coeffs[1].den,
               ray_direction_coeffs[2].num * c // ray_direction_coeffs[2].den)
    b = ray_viewpoint
    
    # 2. Initial Entry
    # Determine if ray enters scene and find initial cell
    # FIRST_POINT logic: clip ray against scene bounds [0, scene_width]^3
    # This is a simplification of Cyrus-Beck
    t_scene_in, t_scene_out = clip_ray_against_box(b, m_prime, 0, scene_width)
    
    if t_scene_in is None:
        return [] # Ray misses scene
        
    # Find the cell containing the entry point
    # Use point location from root
    current_cell = find_3d_block(octree_root, b, m_prime, t_scene_in, scene_width)
    
    if current_cell is None:
        return []
        
    cells = []
    
    while current_cell is not None:
        # 3. Cell Clipping
        # Calculate t_in and t_out for current cell
        t_in, t_out = compute_cell_bounds(current_cell, b, m_prime)
        
        # Store cell info
        cell_record = {
            'T_IN': t_in,
            'T_OUT': t_out,
            'SIZ': current_cell.width,
            'PTR': current_cell,
            'CORNER': current_cell.furthest_corner,
            'DIRECT': None
        }
        cells.append(cell_record)
        
        # 4. Exit Point Classification
        # Determine if exit is on face, edge, or vertex
        # Compare t_out_x, t_out_y, t_out_z exactly
        exit_type = classify_exit_point(t_out)
        
        # 5. Next Cell Direction
        direction = get_direction_from_exit(exit_type, t_out)
        cell_record['DIRECT'] = direction
        
        # 6. Neighbor Finding
        # Find neighbor N in direction with width >= current_cell.width
        neighbor = find_neighbor(current_cell, direction)
        
        if neighbor is None:
            break # Exited scene
            
        if neighbor.is_leaf():
            current_cell = neighbor
        else:
            # 7. Point Q Calculation
            # P is the exit point from current_cell
            P = compute_exit_point(current_cell, t_out)
            Q = calculate_point_Q(P, direction)
            
            # 8. Point Location
            current_cell = find_3d_block(octree_root, Q, m_prime, t_out, scene_width)
            
    return cells

def clip_ray_against_box(b, m, min_val, max_val):
    """
    Clips ray against axis-aligned box [min_val, max_val]^3.
    Returns (t_in, t_out) as rationals or None if miss.
    """
    t_min = Rational(-float('inf'))
    t_max = Rational(float('inf'))
    
    for i in range(3):
        if m[i] == 0:
            if b[i] < min_val or b[i] > max_val:
                return None # Parallel and outside
            else:
                continue # Parallel and inside
                
        # Intersection with min plane
        t1 = Rational(min_val - b[i], m[i])
        # Intersection with max plane
        t2 = Rational(max_val - b[i], m[i])
        
        if m[i] > 0:
            t_in_i = t1
            t_out_i = t2
        else:
            t_in_i = t2
            t_out_i = t1
            
        if t_in_i > t_min:
            t_min = t_in_i
        if t_out_i < t_max:
            t_max = t_out_i
            
    if t_min > t_max:
        return None
        
    return (t_min, t_max)

def compute_cell_bounds(cell, b, m_prime):
    """
    Computes t_in and t_out for a specific cell.
    """
    x0, y0, z0 = cell.min_corner
    W = cell.width
    
    t_in_vals = []
    t_out_vals = []
    
    for i, coord in enumerate([x0, y0, z0]):
        # Planes at coord and coord + W
        # Intersection t = (plane - b) / m
        t_plane1 = Rational(coord - b[i], m_prime[i])
        t_plane2 = Rational(coord + W - b[i], m_prime[i])
        
        if m_prime[i] > 0:
            t_in_vals.append(t_plane1)
            t_out_vals.append(t_plane2)
        else:
            t_in_vals.append(t_plane2)
            t_out_vals.append(t_plane1)
            
    t_in = max(t_in_vals)
    t_out = min(t_out_vals)
    
    return (t_in, t_out)

def classify_exit_point(t_out):
    """
    Classifies exit point based on equality of t_out components.
    """
    tx, ty, tz = t_out
    if tx == ty == tz:
        return 'vertex'
    elif tx == ty or tx == tz or ty == tz:
        return 'edge'
    else:
        return 'face'
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point arithmetic must not be used for comparisons. All $t$ values are rational. Equality tests must be exact (cross-multiplication) [S1].
*   **Boundary Conventions:** The convention that Left, Down, and Back faces are closed must be consistently applied to determine which cell contains a point on the boundary [S1].
*   **Point Q Calculation:** The value $A$ subtracted from $P$ must be chosen carefully. The text states $A$ must be $> 1$ (width of smallest cell) for the logic to hold, but uses 1 in examples. This implies $A$ should be slightly larger than the smallest cell width if using floating point, but for integer arithmetic, the integer part logic is used [S1].
*   **Pointer-less Octree:** If using locational codes, neighbor finding involves bit manipulation and search, which is more expensive than pointer-based neighbor finding [S1].

## Subtopics

### [Arbitrary 3D Resolution Discrete Ray Traversal](4081-arbitrary-3d-resolution-discrete-ray-traversal.md)
Arbitrary 3D Resolution Discrete Ray Traversal is a method for tracing rays through implicit surfaces by voxelizing both the scene and the rays using interval arithmetic within a recursive octree subdivision. It eliminates explicit intersection calculations by ensuring the discrete ray matches the continuous ray down to the resolution of floating-point numbers, guaranteeing robustness against rounding errors. Unlike sibling methods that calculate explicit intersections or rely on pre-computed structures, this method performs on-the-fly subdivision and uses BSP ordering to determine traversal sequence without geometric intersection tests.

### [Single-Ray Octree Traversal](5477-single-ray-octree-traversal.md)
Single-ray octree traversal is a method for rendering implicit surfaces by ray tracing an octree-encapsulated volume directly, using the octree as an acceleration structure to locate cell primitives. It solves the problem of efficiently finding the intersection between a ray and a piecewise $C^0$ isosurface defined by trilinear interpolant patches within octree cells. Unlike coherent traversal techniques that process packets of rays or frustums, this method processes one ray at a time, prioritizing optimized single-ray performance over the modest speedups gained from coherence in highly variant scenes.

## Operating characteristics
*   **Time Complexity:** The traversal visits each cell intersected by the ray. Neighbor finding is $O(1)$ with pointers, but $O(\log N)$ or worse with locational codes and search [S1]. Point location is $O(\log N)$ where $N$ is the number of nodes [S1].
*   **Memory Complexity:** Depends on the octree representation. Pointer-based requires storing pointers. Pointer-less requires storing locational codes [S1].
*   **Measured Performance:** Not given in the sources.
*   **Strengths:** Exact arithmetic avoids precision errors and robust traversal. Neighbor finding is efficient with pointers.
*   **Limitations:** Rational arithmetic is more expensive than integer or floating-point arithmetic. Requires integer viewpoint.
*   **When to Use:** When exact traversal is required, and floating-point precision errors are unacceptable.
*   **When Not to Use:** When performance is critical and approximate traversal is acceptable. When viewpoint is not integer.

## Background
The method was introduced by Wyvill and Kunii in 1989 [S1]. It is based on the work of Glassner and others on ray tracing with octrees. The method uses a simplification of the Cyrus-Beck clipping algorithm [S1].
