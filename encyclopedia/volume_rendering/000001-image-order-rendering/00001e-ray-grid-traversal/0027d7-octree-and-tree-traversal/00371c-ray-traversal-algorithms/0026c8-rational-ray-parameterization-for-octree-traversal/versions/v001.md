# Rational Ray Parameterization for Octree Traversal

Also called: Integer Ray Tracing, Rational Arithmetic Ray Tracing

## Overview
Rational Ray Parameterization is a method for tracing rays through an octree using exact rational arithmetic to eliminate floating-point precision errors during cell boundary crossing and neighbor finding [S1]. It solves the problem of robustly determining the next cell intersected by a ray when ray parameters are not integers, ensuring that equality tests for intersection distances are exact [S1]. Unlike standard floating-point traversal methods, this approach guarantees robustness by representing ray parameters as rational numbers (numerator/denominator pairs) and using integer arithmetic for neighbor location [S1]. It builds on [Octree and Tree Traversal](4134-octree-and-tree-traversal.md) by replacing approximate geometric tests with exact arithmetic operations.

## How it works
**Inputs and Outputs:**
*   **Input:** Ray defined by viewpoint $B = (b_x, b_y, b_z)$ with integer coordinates, and direction coefficients $m_x, m_y, m_z$ which may be rational. Octree root pointer. Scene width $W_{scene}$ (assumed power of 2).
*   **Output:** Sequence of octree cells intersected by the ray, with entry/exit $t$ values.

**Data Structures:**
*   **Rational Number:** Represented as a pair $(num, den)$ where $den > 0$. Comparison of $r_1 = (n_1, d_1)$ and $r_2 = (n_2, d_2)$ is done via cross-multiplication: $r_1 < r_2 \iff n_1 d_2 < n_2 d_1$ [S1].
*   **Cell Record:** Contains 6 fields [S1]:
    *   `T_IN`: Rational $t$ value for ray entry.
    *   `T_OUT`: Rational $t$ value for ray exit.
    *   `SIZ`: Integer width of the cell.
    *   `PTR`: Pointer to the octree node.
    *   `CORNER`: Array of 3 integers, coordinates of the furthest corner from the origin.
    *   `DIRECT`: Direction code to the next cell (e.g., 'L', 'R', 'U', 'D', 'F', 'B').

**Algorithm Steps:**

1.  **Rational Parameterization:**
    Convert ray direction coefficients $m_x, m_y, m_z$ to integers by finding the lowest common denominator $c$ of the three coefficients [S1]. Define $t' = t/c$ and $m'_i = m_i \cdot c$ (numerators) [S1]. The parametric equations become:
    $$ x = m'_x t' + b_x $$
    $$ y = m'_y t' + b_y $$
    $$ z = m'_z t' + b_z $$
    where $b_x, b_y, b_z$ are integers [S1].

2.  **Initial Entry Point (`FIRST_POINT`):**
    Determine the entry point of the ray into the entire scene (bounding box of width $W_{scene}$) [S1].
    *   Clip the ray against the scene boundaries.
    *   If the ray does not intersect the scene, terminate.
    *   Compute the entry $t_{entry}$ and the direction type (face, edge, or vertex) relative to the entry point [S1].

3.  **Locate Initial Cell (`FIND_3D_BLOCK`):**
    Use point location (descend from root) to find the octree node containing the entry point [S1].
    *   Compute the cell record for this initial cell, including `T_IN`, `T_OUT`, `SIZ`, `PTR`, `CORNER`, and `DIRECT` [S1].

4.  **Process Current Cell:**
    *   Intersect the ray with objects in the current cell [S1].
    *   If an intersection is found, handle reflection/refraction (trace new ray) [S1].
    *   If no intersection, proceed to find the next cell.

5.  **Determine Exit Point:**
    For the current cell $C$ of width $W$, bounded by $[x_0, x_0+W]$, etc., compute $t^{in}_i$ and $t^{out}_i$ for each coordinate $i \in \{x, y, z\}$ [S1]:
    *   If $m_i < 0$: $t^{in}_i$ corresponds to $x_0 + W$, $t^{out}_i$ corresponds to $x_0$.
    *   If $m_i > 0$: $t^{in}_i$ corresponds to $x_0$, $t^{out}_i$ corresponds to $x_0 + W$.
    *   The valid range for $t$ inside the cell is $[\max_i(t^{in}_i), \min_i(t^{out}_i)]$ [S1].
    *   The exit point $P = (P_x, P_y, P_z)$ is determined by the coordinate(s) achieving $\min_i(t^{out}_i)$ [S1].
        *   If all three $t^{out}$ are equal, $P$ is on a vertex.
        *   If two $t^{out}$ are equal, $P$ is on an edge.
        *   If all three are different, $P$ is on a face [S1].

6.  **Determine Next Cell Direction (`DIRECT`):**
    The direction $L = (l_x, l_y, l_z)$ to the next cell is determined by the position of $P$ [S1].
    *   If $P$ is on a face perpendicular to axis $i$, $l_i$ is the sign of $m_i$, others 0.
    *   If $P$ is on an edge, $l_i$ and $l_j$ are signs of $m_i, m_j$.
    *   If $P$ is on a vertex, $l_i$ are signs of all $m_i$ [S1].

7.  **Neighbor Finding (`OT_GTEQ_NEIGHBOR`):**
    Find the neighbor $N$ of $C$ in direction $L$ such that $width(N) \ge width(C)$ [S1].
    *   If no such neighbor exists, the ray has exited the scene [S1].
    *   If $N$ is a leaf (not gray), set $C' = N$ [S1].
    *   If $N$ is gray, calculate a point $Q$ guaranteed to be inside $C'$ (see below) and use point location to find $C'$ [S1].

8.  **Calculate Point $Q$ inside $C'$:**
    Let $P = (P_x, P_y, P_z)$ be the exit point from $C$. Let $L = (l_x, l_y, l_z)$ be the direction to $C'$ [S1].
    *   Convention: Left, Down, Back faces are closed [S1].
    *   For each coordinate $j$, if $l_j < 0$ (decreasing direction), subtract a small value $A$ from $P_j$ to ensure $Q$ is strictly inside $C'$ [S1].
    *   $A$ must be $> 1$ (width of smallest cell) and $> 1$ for integer arithmetic. Conventionally, $A=1$ is used in the integer implementation [S1].
    *   If $l_j \ge 0$, $Q_j = \lfloor P_j \rfloor$ (integer part) [S1].
    *   Example: If $L = 'LUB'$ (Left, Up, Back), $l_x < 0, l_y > 0, l_z < 0$. Then $Q = (P_x - 1, \lfloor P_y \rfloor, P_z - 1)$ [S1].
    *   Example: If $L = 'RD'$ (Right, Down), $l_x > 0, l_y < 0, l_z = 0$. Then $Q = (\lfloor P_x \rfloor, P_y - 1, \lfloor P_z \rfloor)$ [S1]. Note: $P_y$ is already integer if on edge [S1].

9.  **Point Location (if $N$ is gray):**
    Descend from the root of the octree to find the leaf cell containing $Q$ [S1].

**Pseudocode:**

```python
def rational_ray_tracer(ray_viewpoint, ray_direction_coeffs, octree_root, scene_width):
    # 1. Rational Parameterization
    # ray_direction_coeffs: (mx, my, mz) as floats or rationals
    # Convert to integers by finding LCM of denominators
    c = lcm(denominator(mx), denominator(my), denominator(mz))
    mx_int = mx * c
    my_int = my * c
    mz_int = mz * c
    # Viewpoint must be integer
    bx, by, bz = ray_viewpoint
    
    # 2. Initial Entry
    t_entry, entry_dir = first_point(bx, by, bz, mx_int, my_int, mz_int, scene_width)
    if t_entry is None:
        return [] # Ray misses scene
    
    # 3. Locate Initial Cell
    current_cell = find_3d_block(bx + mx_int * t_entry, by + my_int * t_entry, bz + mz_int * t_entry, octree_root, scene_width)
    
    cells = []
    while current_cell is not None:
        # 4. Process Cell
        # Intersect with objects in current_cell
        hit = ray_intersects_object_in_cell(current_cell, bx, by, bz, mx_int, my_int, mz_int)
        if hit:
            # Handle reflection/refraction (not implemented here)
            pass
        
        # 5. Determine Exit Point
        t_in, t_out, siz, ptr, corner, direct = current_cell
        # Compute t_out for each face
        t_out_x = (corner[0] - bx) / mx_int if mx_int > 0 else (corner[0] - siz - bx) / mx_int # Simplified logic
        # ... (Exact rational arithmetic for t_out_x, t_out_y, t_out_z)
        
        # Determine exit point P and direction L
        P, L = determine_exit_point_and_direction(t_out_x, t_out_y, t_out_z, mx_int, my_int, mz_int)
        
        # 6. Neighbor Finding
        neighbor_ptr = ot_gteq_neighbor(ptr, L, octree_root)
        
        if neighbor_ptr is None:
            break # Exited scene
            
        next_node = deref(neighbor_ptr)
        
        if not is_gray(next_node):
            # Neighbor is leaf
            next_cell = create_cell_record(next_node, P, L, t_out)
        else:
            # Neighbor is gray, need point location
            Q = calculate_point_Q(P, L)
            next_cell = find_3d_block(Q.x, Q.y, Q.z, octree_root, scene_width)
            
        cells.append(next_cell)
        current_cell = next_cell
        
    return cells

def calculate_point_Q(P, L):
    # P is exit point (rational)
    # L is direction (signs: -1, 0, 1)
    Q = [0, 0, 0]
    for i in range(3):
        if L[i] < 0:
            # Subtract 1 (A=1) from P[i]
            Q[i] = floor(P[i]) - 1
        else:
            # Use integer part
            Q[i] = floor(P[i])
    return Point(Q[0], Q[1], Q[2])
```

## Subtopics

### [Arbitrary 3D Resolution Discrete Ray Traversal](4081-arbitrary-3d-resolution-discrete-ray-traversal.md)
Eliminates explicit intersection calculations by voxelizing rays and scene using interval arithmetic. Guarantees robustness by traversing down to floating-point resolution. Choose when absolute robustness against precision errors is required and performance allows for discrete traversal.

### [Single-Ray Octree Traversal](5477-single-ray-octree-traversal.md)
Traces ray directly through octree-encapsulated volume using trilinear interpolant patches. Choose when the volume is defined by implicit surfaces within cells rather than discrete objects.

## Operating characteristics
*   **Time Complexity:** Neighbor finding is cheaper than point location from the root [S1]. However, rational arithmetic operations (multiplication, division) are more expensive than floating-point operations [S1].
*   **Memory Complexity:** Requires storage for rational numbers (two integers per value) and cell records [S1].
*   **Strengths:** Exact arithmetic eliminates precision errors in boundary crossing and neighbor finding [S1]. Robust for arbitrary viewplanes [S1].
*   **Limitations:** Slower due to rational arithmetic overhead [S1]. Requires integer viewpoints (or modified implementation) [S1]. Neighbor finding in pointer-less octrees requires bit manipulation and search [S1].
*   **When to use:** When robustness is critical and precision errors in standard floating-point traversal cause artifacts or infinite loops.
*   **When not to use:** When performance is paramount and floating-point precision is sufficient.

## Background
Originated in the late 1980s, this method was proposed to address the limitations of floating-point arithmetic in ray tracing through octrees [S1]. It builds on earlier work by Wyvill and Kunii [S1] and Glassner [S1], adapting their clipping algorithms to use exact rational arithmetic. The method is particularly relevant for applications requiring high precision, such as scientific visualization or CAD [S1].
