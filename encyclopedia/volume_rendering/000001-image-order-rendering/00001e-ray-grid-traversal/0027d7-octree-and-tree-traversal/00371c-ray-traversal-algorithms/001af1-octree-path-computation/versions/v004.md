# Octree Path Computation

Also called: Octree Path Encoding, Octree Path Decoding, Octree Traversal Path

## Overview
Octree Path Computation refers to the algorithmic process of encoding a ray's trajectory through an octree hierarchy into a compact bitstream (path) and decoding that path to retrieve spatial coordinates. It solves the problem of efficiently tracking which octants a ray intersects during hierarchical traversal without maintaining explicit stack frames for every node. It sets itself apart from sibling methods like [Tree Marcher](7534-tree-marcher.md) by focusing on the *representation* of the traversal state (the path bits) rather than the geometric sampling or mesh extraction, and differs from [Octree Neighbor Search](7782-octree-neighbor-search.md) by computing the descent sequence rather than lateral adjacency.

## How it works
The method consists of two complementary operations: **Encoding** (computing the path during traversal) and **Decoding** (recovering voxel coordinates from the path).

### Inputs and Outputs
- **Encoding Input:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, octree bounding box $[\mathbf{b}_{min}, \mathbf{b}_{max}]$, max depth $D$.
- **Encoding Output:** A bitstream (integer or array) representing the sequence of child indices chosen at each level.
- **Decoding Input:** The path bitstream, current level $lv$, scene extent.
- **Decoding Output:** Voxel coordinates $(i, j, k)$ or node center.

### Data Structures
- **Path Variable:** An integer or bit-array storing the child index (3 bits) for each level. For a max depth of 16, this requires 48 bits.
- **Scale Variable:** An integer representing the half-extent of the current node's grid cell, initialized to $2^{D-1}$.

### Encoding Steps (Path Computation)
1.  **Initialization:** Initialize an empty path vector $P$ and a scale variable $s = 2^{D-1}$ [S1, unofficial].
2.  **Iterative Descent:** For each depth level $l$ from $0$ to $D-1$:
    a. Determine the current ray position $\mathbf{p}$ within the current node's local coordinate system (or global, adjusted by offset).
    b. Compare $\mathbf{p}$ against the node center $\mathbf{c}$ to determine the octant index $k \in \{0, \dots, 7\}$ using the formula from the parent article:
       $$
       k = 4 \cdot \mathbb{I}(p_x \ge c_x) + 2 \cdot \mathbb{I}(p_y \ge c_y) + 1 \cdot \mathbb{I}(p_z \ge c_z)
       $$
    c. Append $k$ to $P$ (typically by shifting and OR-ing).
    d. Update the scale: $s \leftarrow s / 2$ (or right-shift by 1) [S1, unofficial].
    e. If the node is empty, skip the subtree (advance $t$) and backtrack [G].

### Decoding Steps (Voxel Coordinate Calculation)
1.  **Initialization:** Let $lv$ be the target level (depth). Let $MAX\_NUM\_LEVELS$ be the maximum supported depth (e.g., 16) [S3, unofficial].
2.  **Bit Extraction:** Iterate $l$ from $0$ to $lv-1$:
    a. Shift the octpath right by $3 \times (MAX\_NUM\_LEVELS - lv)$ to align the relevant bits? *Note: Source [S3, unofficial] specifies shifting right by $3 \times (MAX\_NUM\_LEVELS - lv)$ to remove irrelevant higher-level bits, then extracting lowest 3 bits.*
    b. Extract the lowest 3 bits of the current path state.
    c. Decode these bits into local coordinates $(i, j, k)$ using bit masks:
       $$
       i = (path \gg 2) \& 1, \quad j = (path \gg 1) \& 1, \quad k = path \& 1
       $$
    d. Shift the path right by 3 bits to process the next level [S3, unofficial].
3.  **Coordinate Scaling:** Compute the voxel size $s$ at level $lv$:
    $$
    s = \text{scene\_extent} \times 2^{-lv}
    $$
    The absolute voxel coordinates are derived from the accumulated path bits [S3, unofficial].

### Parameters
- **MAX_NUM_LEVELS:** 16 (typical maximum depth for bit shifting operations) [S3, unofficial].
- **Scale:** Initialized to $2^{D-1}$ [S1, unofficial].

### Edge Cases and Pitfalls
- **Precision:** Bit shifting on large integers may overflow if `MAX_NUM_LEVELS` exceeds the integer width (e.g., 64-bit integers support up to 21 levels).
- **Boundary Conditions:** Ray positions exactly on node boundaries ($p_x = c_x$) must be handled consistently with the indicator function $\mathbb{I}(p_x \ge c_x)$ to avoid ambiguity [S1, unofficial].
- **Empty Nodes:** If a node is empty, the path computation must skip the subtree, which may involve backtracking and updating the ray parameter $t$ [G].

## Subtopics

### Mapping Macrocells to Octree Nodes
A method to map implicit macrocell coordinates to the deepest corresponding octree child node to perform isovalue culling using the parent's min/max pair [S2, unofficial]. It differs from standard traversal by focusing on mapping coarse implicit grid cells to fine octree nodes for culling. It is chosen when using implicit macrocells for frustum culling. Key steps: store the path from root to current node along the u,v-minimal ray to avoid costly lookups, use neighbor-finding to traverse from one node to the next, and hierarchically recurse from parent to child with a single lookup step [S2, unofficial].

### Octree Path Decoding & Voxel Coordinate Calculation
A method to decode an octree path into voxel coordinates. It differs from encoding by reversing the bit operations. It is chosen when spatial coordinates are needed from a stored path. Key steps: shift the octpath right by $3 \times (MAX\_NUM\_LEVELS - lv)$ to remove higher-level bits, iterate to extract 3-bit chunks, decode into $i, j, k$, and compute voxel size $s = \text{scene\_extent} \times 2^{-lv}$ [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Encoding is $O(D)$ where $D$ is the depth, as it processes one level per iteration. Decoding is also $O(D)$.
- **Memory Complexity:** $O(D)$ bits to store the path.
- **Strengths:** Compact representation of traversal state; efficient bit manipulation; avoids explicit stack management for path storage.
- **Limitations:** Requires careful bit management; decoding requires knowledge of `MAX_NUM_LEVELS` and `scene_extent`.

## Background
Originating from efficient ray tracing and volume rendering algorithms, octree path computation is a fundamental technique for managing hierarchical spatial data. It is widely used in [SVO Pathfinder](7910-svo-pathfinder-with-lazy-theta-and-los-recovery.md) and implicit surface rendering [S2, unofficial].
