# Octree Neighbor Search

Also called: Get Neighbour Algorithm

## Overview
An algorithm to find the adjacent cell $a$ sharing a specific face $f$ with a given cell $c$ in a generalized octree, handling cases where the neighbor might be at a different subdivision level [S1].

## How it works
**Inputs:** A cell $c$ and a face $f$ for which the neighbor is sought [S1].
**Outputs:** The adjacent cell $a$ sharing face $f$ with $c$, or null if no valid neighbor exists [S1].

**Data Structures:**
*   **Cell Representation:** Defined by spatial coordinates and a Morton code (Z-order curve) [S1].
*   **Level:** The subdivision depth of the cell [S1].
*   **Offset:** An integer variable tracking the search depth relative to the cell's level [S1].

**Steps:**
1. Determine the level of cell $c$, denoted as $L_c$ [S1].
2. Identify the coincident face $f'$ corresponding to the input face $f$ [S1].
3. Initialize an offset variable $k = 1$ [S1].
4. Loop while $k \le L_c$:
   a. Compute the candidate neighbor using `GetAdjacentCellByFace(c, f, k)` [S1].
   b. Check if the candidate cell $a$ exists in the octree structure [S1].
   c. If $a$ exists:
      i. Retrieve the geometric limit of cell $c$ in the direction of face $f$, denoted $Limit_c$ [S1].
      ii. Retrieve the geometric limit of cell $a$ in the direction of the coincident face $f'$, denoted $Limit_a$ [S1].
      iii. If $Limit_c == Limit_a$, the cells share the exact same boundary plane [S1]. Return $a$ [S1].
      iv. Else, the limits do not match. Increment $k$ by 1 and continue the loop [S1].
   d. If $a$ does not exist, increment $k$ by 1 and continue the loop [S1].
5. If the loop completes without returning a cell, no valid neighbor exists [S1].

**Pseudocode:**
```python
def GetNeighbor(c, f, storage):
    level = c.level
    coincidentFace = (f + 3) % 6  # Opposite face mapping [G]
    offset = 1
    
    while offset <= level:
        candidate_morton = GetAdjacentCellByFace(c, f, offset, storage)
        if candidate_morton is not None:
            a = storage.get(candidate_morton)
            if a is not None:
                cellLimitC = GetCellLimitByFace(c, f)
                cellLimitA = GetCellLimitByFace(a, coincidentFace)
                if cellLimitC == cellLimitA:
                    return a
        offset += 1
            
    return None

def GetAdjacentCellByFace(cell, face, offset, storage):
    # Obtain spatial coordinates, add offset in direction, convert to Morton code [G]
    coords = list(cell.coords)
    if face == 0: coords[0] += offset
    elif face == 1: coords[0] -= offset
    elif face == 2: coords[1] += offset
    elif face == 3: coords[1] -= offset
    elif face == 4: coords[2] += offset
    elif face == 5: coords[2] -= offset
    morton = coords_to_morton(coords)
    
    # If no neighbouring cell exists, look at parent by shifting 3 LSBs [S1]
    if morton not in storage:
        morton = cell.morton >> 3
    return morton

def GetCellLimitByFace(cell, face):
    # Return boundary coordinate along face axis [G]
    if face < 2: return cell.coords[0]
    if face < 4: return cell.coords[1]
    return cell.coords[2]

def coords_to_morton(coords):
    # Standard Morton/Z-order encoding [G]
    x, y, z = coords
    return (x << 2) | (y << 1) | z
```

**Parameters:**
*   `offset`: Starts at 1. The maximum value is bounded by the depth of the octree, as anisotropic subdivision usually occurs at the deepest levels [S1].

**Edge Cases and Pitfalls:**
*   **Anisotropic Subdivision:** The algorithm is designed for generalized octrees where cells may have different sizes. The offset loop handles cases where the neighbor is at a different subdivision level [S1].
*   **Precision:** Geometric limit comparison must use exact equality. Floating-point errors in limit calculation could cause false negatives [S1].
*   **Boundary Conditions:** If the cell is on the boundary of the domain, `Exists` will return false for external neighbors, and the loop will terminate correctly [S1].

## Subtopics

### [Indirect Neighbor Search](14139-indirect-neighbor-search.md)
Indirect Neighbor Search computes the set of neighbors for the three faces of a cell $c$ that are not covered by direct neighbors. These neighbors are separated from $c$ by splitting planes located deeper in the octree hierarchy. While Direct Neighbor Search handles the immediate vicinity resulting from the last three splitting steps, Indirect Neighbor Search handles the remaining faces by traversing the tree structure to find cells or planes on the opposite side of bounding splitting planes. It is the second phase of the complete neighborhood computation in generalized octrees.

### Hong Implicit Neighbor Octree
Generates fragments corresponding to rays intersecting the cell [S2, unofficial]. This approach is used for efficient classification of cells in volume rendering contexts, where sub-volumes are projected onto the image plane and fragments are generated for rays intersecting the cell [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources [S1].
*   **Memory Complexity:** Not given in the sources [S1].
*   **Strengths:** Handles generalized (anisotropic) octrees efficiently without requiring regular grid structures [S1].
*   **Limitations:** Performance degrades if the octree has very deep levels and neighbors are sparse, requiring many offset increments [S1].

## Background
The algorithm was introduced by Ricardo Uribe Lobello, Florence Denis, and Florent Dupont in their work on adaptive surface extraction from anisotropic volumetric data using generalized octrees [S1]. It addresses the need for efficient neighbor access in non-uniform octrees where standard bitwise neighbor calculations fail due to varying cell sizes [S1].
