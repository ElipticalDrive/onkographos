# Octree Neighbor Search

Also called: Get Neighbour Algorithm

## Overview
Octree Neighbor Search computes the adjacent cells (neighbors) of a given cell $c$ in a generalized (anisotropic) octree, specifically handling cases where neighbors reside at different subdivision levels. It solves the problem of spatial adjacency in irregular grids where standard grid-based indexing fails. It is distinguished from sibling methods like [SVO Pathfinder with Lazy Theta* and LOS Recovery](7910-svo-pathfinder-with-lazy-theta-and-los-recovery.md) and [Access Path Predictor](11650-access-path-predictor.md) by its focus on exact geometric adjacency verification via coordinate limits rather than pathfinding or prediction.

## How it works
The method consists of two phases: finding **direct neighbors** (sharing a face at the same or adjacent level) and **indirect neighbors** (separated by splitting planes deeper in the tree).

### Inputs and Outputs
*   **Input**: Cell $c$ (defined by its binary index $b_d$ or Morton code), face $f$ (direction of search).
*   **Output**: Set of neighbor cells $N(c)$.

### Data Structures
*   **Cell Index**: Binary representation $b_d$ or Morton code.
*   **Splitting Planes**: Represented by their binary indices.
*   **Limits**: Geometric bounds (min/max coordinates) for each cell face.

### Step 1: Direct Neighbors
Direct neighbors are found by checking immediate spatial adjacency. The algorithm [S2] proceeds as follows:

1.  Get the level of cell $c$: $L \leftarrow \text{GetLevel}(c)$.
2.  Determine the coincident face $f'$ of the search face $f$ on the neighbor side.
3.  Initialize offset $o \leftarrow 1$.
4.  Loop while $o \le L$:
    a.  Compute candidate cell $a$ by moving offset $o$ in direction $f$ from $c$. This is done by obtaining spatial coordinates of $c$, adding offset in direction $f$, and converting back to a Morton code [S2].
    b.  If cell $a$ exists:
        i.  Get the geometric limit of $c$ on face $f$: $L_c \leftarrow \text{GetCellLimitByFace}(c, f)$.
        ii. Get the geometric limit of $a$ on face $f'$: $L_a \leftarrow \text{GetCellLimitByFace}(a, f')$.
        iii. If $L_c == L_a$, return $a$ as the neighbor [S2].
        iv. Else, increment $o \leftarrow o + 1$.

### Step 2: Indirect Neighbors
Indirect neighbors are separated by splitting planes deeper in the tree. The algorithm [S1] computes these for the three faces not covered by direct neighbors.

1.  **Find Splitting Planes**: For each dimension $d \in \{x, y, z\}$, scan the binary index $b_d$ from back to front, considering every third bit. Find the first bit swap (0 to 1). If the swap occurs at bit $j$, the splitting plane index is $b_{d_j}$ (the value of $b_d$ right-shifted by $j$) [S1].
2.  **Recursive Search**: For each found plane $p$, recursively search the subtree starting from $p$ to find cells/planes on the opposite side of $p$ relative to $c$.
    *   Recursion logic [S1]:
        ```python
        def search(current_plane, c, p):
            if current_plane splits in same dimension as p:
                continue with subtree of current node next to c
            else:
                if current_plane has a common point with c:
                    add current_plane to N(c)
                    continue with both subtrees of current node
                else:
                    continue with subtree of current node next to c
        ```
    *   The recursion stops in leaf nodes representing cells belonging to $N(c)$ [S1].

### Pseudocode
The following combines the logic from [S1] and [S2] into a single implementation flow.

```python
def get_neighbors(cell_c, face_f):
    neighbors = set()
    
    # Phase 1: Direct Neighbors [S2]
    level = get_level(cell_c)
    coincident_face = get_coincident_face(face_f)
    offset = 1
    
    while offset <= level:
        # Get spatial coords, add offset, convert to Morton code
        candidate_morton = get_adjacent_cell_by_face(cell_c, face_f, offset)
        
        if exists(candidate_morton):
            limit_c = get_cell_limit_by_face(cell_c, face_f)
            limit_a = get_cell_limit_by_face(candidate_morton, coincident_face)
            
            if limit_c == limit_a:
                neighbors.add(candidate_morton)
                break # Found the immediate neighbor
        offset += 1

    # Phase 2: Indirect Neighbors [S1]
    # Find splitting planes for the other 3 faces
    for dim in [x, y, z]:
        if dim == face_f.dimension: continue
        
        # Scan bits of cell_c in dim from back to front, every 3rd bit
        plane_index = find_first_bit_swap(cell_c, dim)
        
        if plane_index is not None:
            # Recursively search subtree from plane_index
            search_subtree(plane_index, cell_c, plane_index, neighbors)
            
    return neighbors

def search_subtree(current_plane, c, p, neighbors):
    # Check if current_plane is a leaf cell
    if is_leaf(current_plane):
        # Verify if it is an indirect neighbor
        # Logic from [S1]: if it has common point with c, add it
        if has_common_point(current_plane, c):
            neighbors.add(current_plane)
        return

    # Recursive step [S1]
    if splits_in_same_dimension(current_plane, p):
        # Continue with subtree next to c
        next_node = get_subtree_next_to_c(current_plane, c)
        search_subtree(next_node, c, p, neighbors)
    else:
        if has_common_point(current_plane, c):
            neighbors.add(current_plane)
            # Continue with both subtrees
            search_subtree(get_left_subtree(current_plane), c, p, neighbors)
            search_subtree(get_right_subtree(current_plane), c, p, neighbors)
        else:
            # Continue with subtree next to c
            next_node = get_subtree_next_to_c(current_plane, c)
            search_subtree(next_node, c, p, neighbors)
```

### Parameters and Edge Cases
*   **Offset Limit**: The offset in direct neighbor search does not exceed the current depth of the octree [S2].
*   **Coordinate Usage**: Only the test for which side of a plane cell $c$ lies uses coordinates. All other operations use binary representation for speed [S1].
*   **Degenerate Input**: If no neighbor exists at any offset, the method returns nothing for that face [S2].

## Subtopics

### Hong Implicit Neighbor Octree
Generates fragments corresponding to rays intersecting the cell. This variant is used for efficient classification of cells in footprint tables, implicitly given by the min-max octree [S3, unofficial].

## Operating characteristics
*   **Complexity**: In 3D, the average case has up to 9 neighbors per face, leading to 27 indirect neighbors per cell. The worst-case complexity is $O(\sqrt[3]{n})$ [S1].
*   **Performance**: Similar to nearest-neighbor search in kd-trees due to heavy use of binary operations [S1].
*   **Strengths**: Handles anisotropic subdivision and irregular grids effectively [S2].
*   **Limitations**: Indirect neighbor count is not constant and can be high in worst-case scenarios [S1].

## Background
The method originates from work on direct isosurface extraction from scattered volume data [S1] and adaptive surface extraction from anisotropic volumetric data [S2]. It is used in interactive volume rendering techniques [S3, unofficial].
