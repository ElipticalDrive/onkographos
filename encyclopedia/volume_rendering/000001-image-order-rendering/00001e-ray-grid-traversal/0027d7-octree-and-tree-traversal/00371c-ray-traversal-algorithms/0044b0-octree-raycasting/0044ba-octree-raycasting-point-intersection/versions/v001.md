# Octree Raycasting (Point Intersection)

Also called: PointOctant

## Overview
This method finds specific points within a pointer-based octree that intersect with a given ray by iterating through all octants intersected by the ray and testing the points contained within those octants [S1, unofficial]. It differs from sibling methods by focusing on discrete point data rather than continuous volume density or boundary surfaces, serving as the intersection logic for `PointOctree` structures [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A raycaster (defining origin and direction) and a `PointOctree` instance.
- Output: A list of `RayPointIntersection` objects, sorted by distance from the ray origin.

**Data Structures:**
- `PointOctree<T>`: Extends `Octree<PointOctant<T>>`.
  - Fields:
    - `bias`: Number. Octant boundary bias. If $> 0$, the octree is "loose" [S1, unofficial].
    - `maxPoints`: Number. Maximum distinct points per leaf octant before a split occurs. Default: 8 [S1, unofficial].
    - `maxDepth`: Number. Maximum tree depth level (starting at 0). Default: 8 [S1, unofficial].
- `PointOctant<T>`: Represents a node in the octree.
  - Field: `pointData`. Contains the points stored in this octant. Can be `null` if empty or not yet populated [S1, unofficial].
- `RayPointIntersection`: The result object returned for each hit point.

**Parameters:**
- `bias`: Default 0.0. Must be $\ge 0$ [S1, unofficial].
- `maxPoints`: Default 8. Must be $\ge 1$ [S1, unofficial].
- `maxDepth`: Default 8. Must be $\ge 0$ [S1, unofficial].

**Steps:**
1. Initialize an empty list `result` of type `RayPointIntersection`.
2. Retrieve the list of octants intersecting the ray by calling the parent method `super.getIntersectingNodes(raycaster)` [S1, unofficial].
3. If the list of intersecting octants is not empty:
   a. Iterate through each octant in the list.
   b. Check if the octant has point data (`pointData !== null`) [S1, unofficial].
   c. If point data exists, call `pointData.testPoints(raycaster, result)` to identify specific points within the octant that intersect the ray and add them to `result` [S1, unofficial].
4. Return the `result` list.

**Pseudocode:**
```python
def point_octree_raycast(raycaster, octree):
    # 1. Initialize result list
    result = []
    
    # 2. Get intersecting octants from parent traversal logic
    # super.getIntersectingNodes(raycaster) returns a list of PointOctant objects
    intersecting_octants = super.getIntersectingNodes(raycaster)
    
    # 3. Iterate through octants
    if intersecting_octants is not empty:
        for octant in intersecting_octants:
            # 4. Check for point data
            if octant.pointData is not null:
                # 5. Test points within this octant against the ray
                # This modifies the result list in place or returns new intersections
                octant.pointData.testPoints(raycaster, result)
                
    # 6. Return results
    return result
```

**Edge Cases and Pitfalls:**
- **Infinity Depth:** Allowing `maxDepth` to be infinite can result in poor performance due to infinitely small octants [S1, unofficial].
- **Bias:** The bias parameter must be non-negative. It affects the "looseness" of the octree boundaries [S1, unofficial].
- **Empty Octants:** Octants without `pointData` are skipped, optimizing traversal for sparse data [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the number of intersecting octants and the number of points per octant. The traversal is efficient due to the octree structure, but point testing is linear with respect to points in the leaf octants.
- **Memory Complexity:** Proportional to the number of points stored in the octree.
- **Strengths:** Efficient for sparse point data; avoids testing points in non-intersecting octants.
- **Limitations:** Performance degrades if `maxDepth` is too high or if octants contain excessive points. Not suitable for continuous volume rendering without modification.

## Background
This method is part of the `sparse-octree` module, which implements a pointer-based octree for storing and querying points in 3D space [S1, unofficial]. It is designed to work with the `PointOctant` class to provide efficient raycasting against discrete point sets.
