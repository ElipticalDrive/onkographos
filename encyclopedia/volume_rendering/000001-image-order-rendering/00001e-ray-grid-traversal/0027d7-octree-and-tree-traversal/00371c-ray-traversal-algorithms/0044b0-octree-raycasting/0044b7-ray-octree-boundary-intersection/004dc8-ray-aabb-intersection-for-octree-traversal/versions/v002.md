# Ray-AABB Intersection for Octree Traversal

Also called: Ray-Parameter Function, Revelles, Urena and Lastra Octree Traversal

## Overview
This algorithm determines whether a ray intersects an axis-aligned bounding box (AABB) representing an octree node and prepares parameters for traversing its subtrees [S1, unofficial]. It distinguishes itself by normalizing the ray direction to be strictly positive through coordinate flipping, which simplifies the subsequent intersection logic and traversal order determination [S1, unofficial].

## How it works
**Inputs:** Ray origin $o$ and direction $d$ (3D vectors) [S1, unofficial]. Octree node bounds: minimum corner $\_min$, maximum corner $\_max$, and node size $\_size$ [S1, unofficial].

**Outputs:** Boolean indicating intersection [S1, unofficial]. If intersecting, calls `processSubtree` with entry/exit distances and a bitmask [S1, unofficial].

**Data Structures:** `a`: Unsigned integer bitmask (3 bits) indicating which axes were flipped [S1, unofficial]. `t0`: Vector of entry distances per axis [S1, unofficial]. `t1`: Vector of exit distances per axis [S1, unofficial]. `t`: Scalar tracking the maximum entry distance (closest entry point) [S1, unofficial].

**Steps:**
1. Initialize bitmask $a = 0$ [S1, unofficial].
2. Copy ray origin $o$ and direction $d$ [S1, unofficial].
3. For each axis $i \in \{0, 1, 2\}$: If $d[i] < 0$: Flip origin: $o[i] = \_size[i] - o[i]$ [S1, unofficial]. Negate direction: $d[i] = -d[i]$ [S1, unofficial]. Set bit $i$ in $a$: $a \ |= \ (1 \ll (2-i))$ [S1, unofficial]. Specifically: bit 2 (value 4) for axis 0, bit 1 (value 2) for axis 1, bit 0 (value 1) for axis 2 [S1, unofficial].
4. Compute entry distances: $t0 = (\_min - o) / d$ [S1, unofficial].
5. Compute exit distances: $t1 = (\_max - o) / d$ [S1, unofficial].
6. Initialize $t = \infty$ (maximum double value) [S1, unofficial].
7. Check intersection: If $\max(t0) < \min(t1)$, the ray intersects the box [S1, unofficial]. Call `processSubtree(t0, t1, r, t, sd, a)` [S1, unofficial]. Otherwise, return false [S1, unofficial].

**Formulas:**
- Origin flip: $o[i] = \_size[i] - o[i]$ [S1, unofficial].
- Entry distance: $t0[i] = (\_min[i] - o[i]) / d[i]$ [S1, unofficial].
- Exit distance: $t1[i] = (\_max[i] - o[i]) / d[i]$ [S1, unofficial].
- Intersection condition: $\max(t0) < \min(t1)$ [S1, unofficial].

**Parameters:** Not given in the sources.

**Edge cases and pitfalls:** Incorrect traversal logic or misinterpretation of $\_size$ can cause rendering artifacts, such as only the upper-right part of the image being rendered while the rest is rejected [S1, unofficial]. The formula $o[i] = \_size[i] - o[i]$ is specific to the implementation cited [S1, unofficial]. Standard implementations often use $o[i] = \_max[i] - o[i]$ or similar depending on coordinate space [G]. Sources indicate ambiguity in $\_size$: it is either $\_size = \_max - \_min$ or $\_size = (\_max - \_min) / 2$ [S1, unofficial]. Implementers must verify the definition of $\_size$ in their specific octree structure [S1, unofficial].

**Pseudocode:**
```python
def ray_aabb_intersect(oct_node, ray):
    # Inputs: oct_node with attributes _min, _max, _size
    # ray with attributes origin (o), direction (d)
    
    a = 0
    o = [ray.origin[0], ray.origin[1], ray.origin[2]]
    d = [ray.direction[0], ray.direction[1], ray.direction[2]]
    
    # Normalize ray direction to be positive
    if d[0] < 0:
        o[0] = oct_node._size[0] - o[0]
        d[0] = -d[0]
        a |= 4  # Bit 2
    
    if d[1] < 0:
        o[1] = oct_node._size[1] - o[1]
        d[1] = -d[1]
        a |= 2  # Bit 1
        
    if d[2] < 0:
        o[2] = oct_node._size[2] - o[2]
        d[2] = -d[2]
        a |= 1  # Bit 0
        
    # Compute intersection distances
    t0 = [(oct_node._min[i] - o[i]) / d[i] for i in range(3)]
    t1 = [(oct_node._max[i] - o[i]) / d[i] for i in range(3)]
    
    t = float('inf')
    
    # Check for intersection
    if max(t0) < min(t1):
        # process_subtree(t0, t1, ray, t, sd, a) is not defined in the sources; 
        # it handles child traversal using bitmask a and distance t [G].
        return True
    else:
        return False
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per node visit [S1, unofficial]. The intersection test involves a constant number of arithmetic operations and comparisons [S1, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space [S1, unofficial].
- **Strengths:** Simplifies traversal logic by ensuring positive ray directions, allowing consistent ordering of child node visits based on the bitmask [S1, unofficial].
- **Limitations:** Relies on correct interpretation of node size and bounds. Incorrect implementation can lead to significant rendering errors (e.g., missing image regions) [S1, unofficial].
- **When to use:** When traversing an octree where node bounds are axis-aligned and the traversal order needs to be determined by the ray's entry/exit points relative to the node's children [S1, unofficial].

## Background
This method is based on the "Efficient Parametric Algorithm for Octree Traversal" by Revelles, Urena, and Lastra [S1, unofficial]. The specific implementation details and pitfalls discussed in the sources stem from a community discussion on Stack Overflow regarding an implementation of this algorithm [S1, unofficial]. The algorithm is a standard technique in volume rendering and ray tracing for efficient spatial subdivision traversal [G].
