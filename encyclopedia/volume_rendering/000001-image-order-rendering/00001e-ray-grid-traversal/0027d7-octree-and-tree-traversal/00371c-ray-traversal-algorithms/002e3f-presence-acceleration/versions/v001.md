# Presence Acceleration

Also called: Binary Pyramid Ray Traversal, Binary pyramid traversal, Hierarchical Spatial Enumeration, Levoy's octree acceleration

## Overview
Presence Acceleration is a ray traversal acceleration technique for volume rendering that uses a binary pyramid to skip empty regions by identifying cells containing at least one opaque voxel [S1, S2, S3, unofficial]. It solves the problem of inefficiently traversing large transparent volumes by allowing the ray to jump over empty space hierarchically [S3, unofficial]. It sets itself apart from siblings like [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by using a fixed, pointerless complete octree structure (the pyramid) rather than a sparse linked structure, and from [Homogeneity Acceleration](822-hermite-data-computation-via-bisection.md) by using binary occupancy flags rather than value ranges for skipping [S1, S2, unofficial].

## How it works
**Inputs:**
*   Volume data of resolution $N \times N \times N$, where $N = 2^M + 1$ for some integer $M$ [S1, S2, unofficial].
*   Ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [S1, S2, unofficial].

**Outputs:**
*   A sequence of elementary cells (voxels) containing at least one opaque voxel, along with the ray segment within each, for compositing [S1, S2, unofficial].

**Data Structures:**
The method uses a **Binary Pyramid**, a set of $M + 1$ volumes indexed by level $m = 0, \dots, M$ [S1, S2, unofficial].
*   **Level $V_0$**: Measures $(N - 1) \times (N - 1) \times (N - 1)$ cells [S1, S2, unofficial]. Each cell represents the rectangular region between eight neighboring voxels in the original data [S1, S2, unofficial].
*   **Level $V_m$**: Measures $(N - 1)/2^m$ cells on a side [S1, S2, unofficial].
*   **Level $V_M$**: A single cell [S1, S2, unofficial].
*   **Cell Value**:
    *   For $V_0$: A cell value is $0$ if all eight corner voxels have opacity equal to zero; otherwise, it is $1$ [S1, S2, unofficial].
    *   For $V_m$ ($m > 0$): A cell value is $0$ if all four corner cells at level $V_{m-1}$ are $0$; otherwise, it is $1$ [S1, S2, unofficial].
    *   *Note:* The sources describe the pyramid as "binary" and "pointerless" [S1, S2, unofficial]. The layout implies a dense array storage for each level, though exact bit-packing is not specified [S1, S2, unofficial].

**Algorithm Steps:**

1.  **Pyramid Construction:**
    *   Compute $V_0$ by checking the opacity of the $2 \times 2 \times 2$ voxel blocks in the original volume [S1, S2, unofficial].
    *   Compute higher levels $V_m$ recursively: a cell is $0$ if all its corner cells at level $V_{m-1}$ are $0$ [S1, S2, unofficial].
    *   *Pitfall:* The volume resolution must satisfy $N = 2^M + 1$ for the pyramid to reduce to a single cell at level $M$ [S1, S2, unofficial]. If the volume does not meet this, padding or a different structure is required [G].

2.  **Ray Initialization:**
    *   Calculate the entry point of the ray into the single cell at the top level $V_M$ [S1, S2, unofficial]. This is effectively the entry into the entire volume bounding box [S1, S2, unofficial].

3.  **Traversal Loop:**
    *   Let the current cell be $C$ at level $m$ with entry parameter $t_{entry}$ [S1, S2, unofficial].
    *   **Check Cell Value:**
        *   If $C$ is empty (value $0$):
            *   Calculate the exit point of the ray from cell $C$, determining the next cell $C_{next}$ at the same level $m$ [S1, S2, unofficial].
            *   Update $t_{entry}$ to the intersection with $C_{next}$ [S1, S2, unofficial].
            *   Check if the parent of $C_{next}$ differs from the parent of $C$ [S1, S2, unofficial].
            *   If the parent differs, move up to the parent cell at level $m+1$ [S1, S2, unofficial].
            *   If the parent cell is empty, skip it and continue iterating up or across until a non-empty cell is found [S1, S2, unofficial].
            *   If the parent is non-empty, descend to the child of the parent that contains the ray [S1, S2, unofficial].
        *   If $C$ is non-empty (value $1$):
            *   If $m > 0$, move down the hierarchy to the child cell at level $m-1$ that encloses the current ray position [S1, S2, unofficial].
            *   Repeat the check for the new child.
            *   If $m = 0$, the cell is an elementary cell (representing a region of voxels) [S1, S2, unofficial].

4.  **Sampling and Compositing:**
    *   Once an elementary cell (leaf of the pyramid, corresponding to a region in $V_0$) is reached, take samples at evenly spaced locations along the ray within that cell [S1, S2, unofficial].
    *   Perform volume compositing (e.g., front-to-back alpha blending) using the original volume data for the voxels in that region [S1, S2, unofficial].

**Parameters:**
*   $N$: Volume resolution, must be $2^M + 1$ [S1, S2, unofficial].
*   $M$: Pyramid depth [S1, S2, unofficial].
*   Number of samples per elementary cell: Not given in the sources [S1, S2, unofficial].

**Edge Cases:**
*   **Volume Resolution:** If $N \neq 2^M + 1$, the pyramid does not reduce to a single cell at level $M$ [S1, S2, unofficial]. Padding or a different hierarchical structure is needed [G].
*   **Empty Volume:** If all voxels are transparent, the top cell is $0$, and the ray skips the entire volume [S1, S2, unofficial].
*   **Precision:** Floating-point precision in ray-cell intersection calculations can cause jitter or missed cells if not handled carefully [G].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal to the first opaque region, then $O(L)$ for sampling within opaque regions, where $L$ is the number of opaque cells hit [S1, S2, unofficial].
*   **Memory Complexity:** $O(N^3)$ for the pyramid, as it stores a dense binary volume for each level [S1, S2, unofficial]. The total memory is $\sum_{m=0}^M ((N-1)/2^m)^3 \approx \frac{N^3}{7}$ [G].
*   **Strengths:** Simple to implement, pointerless structure, efficient for skipping large empty regions [S1, S2, unofficial].
*   **Limitations:** High memory usage for large volumes due to dense pyramid storage [S1, S2, unofficial]. Not suitable for sparse volumes where most space is empty [S1, S2, unofficial]. Requires volume resolution to be of the form $2^M + 1$ [S1, S2, unofficial].
*   **When to use:** Dense volumes with large empty regions, where memory is not a constraint [S1, S2, unofficial].
*   **When not to use:** Sparse volumes, or when memory bandwidth is a bottleneck [S1, S2, unofficial].

## Background
Presence Acceleration was introduced by Marc Levoy in 1991 [S1, S2, S3, unofficial]. It is also known as Hierarchical Spatial Enumeration [S3, unofficial]. The method was later improved by Denskin and Hanrahan in 1992 with Homogeneity Acceleration, which used range pyramids instead of binary pyramids [S1, S2, unofficial]. It is a foundational technique for empty space skipping in volume rendering [S3, unofficial].
