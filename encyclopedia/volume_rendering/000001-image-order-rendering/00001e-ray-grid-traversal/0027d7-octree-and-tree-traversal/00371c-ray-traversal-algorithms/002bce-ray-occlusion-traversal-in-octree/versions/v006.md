# Ray-Occlusion Traversal in Octree

Also called: Octree Ray Traversal, Ray-Octree Traversal

## Overview
Ray-Occlusion Traversal in Octree is a method for intersecting rays with an octree-represented scene by recursively descending the hierarchy to find the first material leaf or surface, handling rays that start inside or outside the root voxel [S1, unofficial]. It solves the problem of efficiently stepping through empty space in hierarchical voxel structures by using ray-AABB intersection to cull internal nodes and their children, returning true on the first intersection [S3, S4, unofficial]. Unlike its sibling [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md), which often uses iterative slab-based stepping for unstructured SVOs, this method explicitly manages the hierarchical descent and leaf detection logic, and differs from [Bottom-up Neighbor-Finding Ray Traversal](5610-bottom-up-neighbor-finding-ray-traversal.md) by relying on top-down recursive descent rather than lateral neighbor lookups [S1, S3, S4, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A ray defined by origin $\mathbf{r}_o$ and direction $\mathbf{r}_d$ (normalized), and an octree data structure.
- **Output:** A boolean indicating intersection, or the color/shadow factor of the first hit material leaf.

**Data Structures:**
The octree is stored in a flat array `octreeArray` of `OctreeNode` structs, bound as a storage buffer (SSBO) [S1, unofficial].
- `OctreeNode`: Contains 8 integer child pointers `p0` through `p7` [S1, unofficial].
  - Indices $\ge 0$ point to child nodes in `octreeArray`.
  - Indices $< 0$ (specifically $-1$) indicate no child or leaf status [S1, unofficial].
- Nodes are stored in reverse depth order (deepest layers first) [S1, unofficial].
- Pointers are adjusted by a `pointerOffset` to be relative to the start of the flat array [S1, unofficial].
- Auxiliary arrays (from [S1, unofficial]): `nodes[depth][node_index]`, `child_bit_depth[depth]`, `child_mins[child]`, `child_maxs[child]`, `child_offset` [S1, unofficial][S2].

**Parameters:**
- `MAX_TRAVERSALS`: Maximum outer loop iterations, typically 300 [S1, unofficial].
- `MAX_DEPTH`: Maximum octree depth, typically 100 [S1, unofficial].
- `INF`: Large constant for infinity [S1, unofficial].
- Epsilon values: `0.001` for collision point offset, `0.01` for position updates to prevent re-entry [S1, unofficial].
- Shadow attenuation multiplier: `0.3` [S1, unofficial].

**Algorithm Steps:**

1. **Initialization and Root Entry:**
   - If the ray origin is outside the root voxel's bounding box, calculate intersection distances ($t_x, t_y, t_z$) with the six planes of the root voxel [S1, unofficial].
   - Use `intersectRayPlane` for each axis, selecting the near or far plane based on ray direction signs [S1, unofficial].
   - Clamp negative distances to `INF` [S1, unofficial].
   - Compute candidate collision points: $\mathbf{p}_x = \mathbf{r}_o + t_x \mathbf{r}_d$, etc. [S1, unofficial].
   - Validate points lie within root bounds using `voxelInParent`. Add epsilon `0.001 * \mathbf{r}_d` to the collision point along the intersecting axis to avoid self-intersection [S1, unofficial].
   - Select minimum valid distance `minDist`. If `minDist` is `INF`, return miss [S1, unofficial].
   - Determine entry voxel index (0-5) based on axis and direction sign [S1, unofficial].
   - Initialize traversal state: `curDepth = 0`, `nodeIndices[0] = initialIndex`, `parentVoxels[0] = parentVoxel`, `voxelSize = parentVoxelSize / 2` [S1, unofficial].

2. **Outer Loop (Max Iterations):**
   - Iterate `i` from 0 to `MAX_TRAVERSALS - 1` [S1, unofficial].

3. **Inner Loop (Descent):**
   - While `subNodeValue >= 0` and `curDepth < MAX_DEPTH`:
     - Calculate `parentVoxels[curDepth] = scaleVoxel(curVoxel, parentVoxelSize)` and `curVoxelScaled = scaleVoxel(curVoxel, voxelSize)` [S1, unofficial].
     - Determine child index `p0`-`p7` by comparing `curVoxelScaled` components against `parentVoxels[curDepth]` (equality checks for x, y, z) [S1, unofficial].
     - Update `subNodeValue = octree.octreeArray[nodeIndices[curDepth]].pN` [S1, unofficial].
     - **Leaf Handling:**
       - If `subNodeValue < -1` (material leaf): Compute shadow factor. If shadow ray hits, `shadowFactor *= 0.3`. Else `shadowFactor *= normals[collType]`. Return `(shadowFactor) * determineRayColor(ivec2(subNodeValue, collType))` [S1, unofficial].
       - If `subNodeValue == -1` (empty leaf): Break descent loop to proceed to traversal step [S1, unofficial].
       - If `curDepth + 1 == MAX_DEPTH` (max depth leaf): Check `subNodeValue`. If `< -1`, compute shadow/color. If `>= -1`, increment `curDepth`, halve sizes, break descent [S1, unofficial].
     - **Internal Node Descent:**
       - If `subNodeValue > -1`, set `nodeIndices[curDepth + 1] = subNodeValue`, increment `curDepth`, halve `parentVoxelSize` and `voxelSize` [S1, unofficial].

4. **Voxel Stepping (if empty leaf or max depth reached):**
   - If leaf is empty (`subNodeValue == -1`), calculate deltas to next voxel boundaries using `getDelta` for x, y, z axes with current `voxelSize` [S1, unofficial].
   - Advance ray position: $\mathbf{r}_o \leftarrow \mathbf{r}_o + \text{minDelta} \cdot \mathbf{r}_d$ [S1, unofficial].
   - Update current voxel index by rounding new position with epsilon `0.01 * \mathbf{r}_d` [S1, unofficial].
   - Determine `collType` (0-5) based on direction sign [S1, unofficial].
   - **Parent Boundary Check:** While `!voxelInParent(curPosi, parentVoxels[curDepth], curParentEnds)` and `curDepth >= 0`:
     - Decrement `curDepth`, double `parentVoxelSize` and `voxelSize`, update `curParentEnds` [S1, unofficial].
     - If `curDepth < 0`, return miss/false [S1, unofficial].
   - Re-enter Inner Loop (Descent) from current `curDepth` and `curVoxel`.

5. **Termination:**
   - If `curDepth + 1 == MAX_DEPTH` and leaf is empty, break.
   - If `subNodeValue == -1` and not at max depth, break to step 4.
   - If `subNodeValue < -1`, return hit result [S1, unofficial].
   - If outer loop limit reached, return miss/black color [S1, unofficial].

## Subtopics

### [Bottom-up Neighbor-Finding Ray Traversal](5610-bottom-up-neighbor-finding-ray-traversal.md)
Bottom-up neighbor-finding ray traversal is a method for intersecting rays with an octree-represented scene by determining the sequence of cells the ray passes through via neighbor lookups rather than hierarchical descent. It solves the problem of efficiently stepping from one occupied or relevant cell to the next along a ray path, avoiding the overhead of traversing empty space from the root. Unlike top-down traversal methods that descend from the root for every step, this approach starts at the first intersected cell and moves laterally or vertically through the tree structure to find the subsequent cell, offering a trade-off between implementation complexity and traversal speed depending on the density of the scene.

### [Octree-based Raycasting](5707-octree-based-raycasting.md)
Octree-based Raycasting is a volume rendering technique that accelerates ray traversal by skipping empty space regions using an octree data structure. It solves the performance bottleneck of naive voxel raycasting, which has $O(n)$ complexity relative to the number of voxels, by reducing traversal cost to depend only on occupied space. It differs from its parent [Ray-Occlusion Traversal in Octree](5121-ray-occlusion-traversal-in-octree.md) by explicitly managing dynamic voxel updates and concurrency, and from [Bottom-up Neighbor-Finding Ray Traversal](5610-bottom-up-neighbor-finding-ray-traversal.md) by relying on hierarchical empty-space skipping rather than neighbor-based stepping.

### Octree Traversal via Voxel Grid
Octree Traversal via Voxel Grid is a method to traverse an octree by mapping ray origin/direction to chunk coordinates and checking if the ray stays within the current chunk bounds, using a loop condition based on distance from center [S1, unofficial]. It defines the voxel center as `voxelCenter = vec3(octreeSize / 2, octreeSize / 2, octreeSize / 2)` and computes the current voxel position as `curVoxel = octreeSize * floor(rayOrigin / octreeSize)` [S1, unofficial]. It checks if the current voxel is within valid bounds `[0, octreeSize)` and loops while the squared distance from center to ray origin is greater than the squared distance from center to ray end: `dot(rayOrigin - voxelCenter, rayOrigin - voxelCenter) > dot(rayOrigin + rayDir - voxelCenter, rayOrigin + rayDir - voxelCenter)` [S1, unofficial]. If the loop exits, it returns failure [S1, unofficial].

### Hero-like Octree Traversal
Hero-like Octree Traversal is a depth-first search approach for ray-tracing octrees that uses a 2x2x2 voxel test to determine the order of cell hits and descend into occupied nodes [S5, unofficial]. It starts from the root of the octree and performs a 2x2 test to find which cells the ray hits and their order [S5, unofficial]. It uses intersection values for middle planes ($t_{mx}, t_{my}$) and exit planes ($t_{ex}, t_{ey}$) to determine the ray's position and path within the 2x2 area [S5, unofficial]. If any top cells in the 2x2 area are occupied, it descends into the tree by calculating new plane positions based on the cell position [S5, unofficial].

## Operating characteristics
- **Time Complexity:** Depends on the depth of the octree and the number of occupied nodes traversed. In the worst case (dense scene), it approaches $O(N)$ where $N$ is the number of voxels, but typically scales with the number of leaf nodes intersected [S1, S3, unofficial].
- **Memory Complexity:** $O(N)$ for the octree storage, where $N$ is the number of nodes. The flat array storage is efficient for cache locality [S1, unofficial].
- **Performance:** The method is efficient for sparse scenes due to early culling of empty nodes [S3, unofficial]. Performance can be improved with a low-resolution depth pass to start rays closer to collision points [S1, unofficial].
- **Strengths:** Handles rays starting inside or outside the root; explicit leaf detection; efficient culling of empty space [S1, S3, unofficial].
- **Limitations:** Recursive implementation may cause stack overflow in deep trees; requires careful handling of precision at voxel boundaries [S1, unofficial].
- **When to use:** Suitable for static or semi-static octree volumes where ray origins are distributed [S1, unofficial].
- **When not to use:** Not suitable for highly dynamic scenes requiring frequent tree rebuilds without careful management [S1, unofficial].

## Background
Ray-Occlusion Traversal in Octree is a fundamental technique in volume rendering and ray tracing for hierarchical voxel data. It is based on the recursive traversal of octree structures to find ray intersections [S3, S4, unofficial]. The method is widely used in real-time rendering engines, such as those implemented in Vulkan, to accelerate raymarching through voxelized terrain or volumetric data [S1, unofficial]. The approach of using ray-AABB intersection to cull internal nodes is a standard optimization in ray tracing algorithms [S3, unofficial].
