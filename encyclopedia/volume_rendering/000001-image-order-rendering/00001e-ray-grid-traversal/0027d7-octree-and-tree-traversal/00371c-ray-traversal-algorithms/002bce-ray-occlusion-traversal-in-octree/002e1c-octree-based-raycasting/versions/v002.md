# Octree-based Raycasting

Also called: Raycasting mit Octree-Beschleunigungsstruktur, Voxel-Raycasting mit Octree

## Overview
Octree-based raycasting is a volume rendering technique that accelerates ray traversal by utilizing an octree structure to skip empty space regions [S1, unofficial]. It solves the performance bottleneck of naive raycasting, which scales linearly with the number of voxels $O(n)$, by culling large volumes of empty space [S1, unofficial]. It differs from its parent [Ray-Occlusion Traversal in Octree](5121-ray-occlusion-traversal-in-octree.md) by explicitly maintaining voxel counts per node to support dynamic updates, and from [Bottom-up Neighbor-Finding Ray Traversal](5610-bottom-up-neighbor-finding-ray-traversal.md) by relying on top-down parametric analysis rather than neighbor-finding for traversal.

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, octree root node, voxel data buffer.
**Outputs:** Intersection points, accumulated color/opacity.

**Data Structures:**
*   **Octree Node:** Contains a boolean `exists` flag and an integer `voxel_count` [S1, unofficial].
*   **Voxel Buffer:** Stores density/color values for active voxels.
*   **StructuredBuffer:** GPU buffer holding node data, declared `globallycoherent` for atomic operations [S1, unofficial].

**Steps:**
1.  **Initialization:** Start traversal at the root node. If the ray originates inside the root, compute entry point; otherwise, intersect ray with root bounding box planes [Parent].
2.  **Node Evaluation:** For the current node, check `exists`. If false, terminate traversal for this branch [S1, unofficial].
3.  **Voxel Count Check:** Read `voxel_count` [S1, unofficial]. If `voxel_count` is 0, deactivate the node (set `exists` to false) and terminate traversal for this branch [S1, unofficial].
4.  **Leaf/Interior Decision:**
    *   If leaf: Sample voxel data at intersection point.
    *   If interior: Compute child bounding boxes. Determine which children intersect the ray.
5.  **Recursive Traversal:** For each intersecting child, recursively call the raycasting function.
6.  **Dynamic Update (On Modification):** When a voxel is deleted, decrement `voxel_count` of all ancestor nodes [S1, unofficial]. If `voxel_count` reaches 0, mark the node as inactive [S1, unofficial].

**Pseudocode:**
```python
def raycast_octree(ray_origin, ray_direction, node, depth):
    # Check if node exists
    if not node.exists:
        return None

    # Check if node contains voxels
    if node.voxel_count == 0:
        node.exists = False
        return None

    # Base case: Leaf node
    if depth == MAX_DEPTH:
        return sample_voxel(ray_origin, ray_direction, node.voxel_data)

    # Recursive case: Interior node
    # Compute intersection with child bounding boxes
    children_to_visit = []
    for i in range(8):
        child_bbox = get_child_bbox(node, i)
        if ray_intersects_bbox(ray_origin, ray_direction, child_bbox):
            children_to_visit.append(i)

    # Traverse children
    closest_hit = None
    for child_idx in children_to_visit:
        child_node = node.children[child_idx]
        hit = raycast_octree(ray_origin, ray_direction, child_node, depth + 1)
        if hit is not None:
            if closest_hit is None or hit.distance < closest_hit.distance:
                closest_hit = hit

    return closest_hit

def update_voxel_count(node, voxel_deleted):
    """
    Updates the voxel count for a node and its ancestors.
    Called when a voxel is modified/deleted.
    """
    if voxel_deleted:
        node.voxel_count -= 1
        if node.voxel_count == 0:
            node.exists = False
    # Recursively update parent [S1, unofficial]
    if node.parent is not None:
        update_voxel_count(node.parent, voxel_deleted)
```

**Parameters:**
*   `MAX_DEPTH`: Depth of the octree. Typical value $D=5$ for large datasets [S2].
*   `voxel_count`: Integer field in node structure [S1, unofficial].

**Edge Cases:**
*   **Empty Root:** If the root has `voxel_count` 0, no traversal occurs [S1, unofficial].
*   **Dynamic Updates:** Concurrent writes to `voxel_count` require atomic operations to prevent data races [S1, unofficial].

## Subtopics

### Atomic Octree Update
A technique to prevent data races during concurrent writes to `voxel_count` in the octree nodes [S1, unofficial]. It uses HLSL intrinsics `InterlockedAdd` for atomic addition/subtraction on the `voxel_count` variable [S1, unofficial]. The `StructuredBuffer` must be declared with the `globallycoherent` qualifier to ensure visibility across warps [S1, unofficial]. This is necessary because multiple voxels in the same node may be deleted simultaneously, leading to inconsistent data if not synchronized [S1, unofficial].

### Hybrid Raycasting with Voxel Traversal
A top-down parametric raycasting technique that combines a voxel traversal algorithm with octree traversal [S2]. It uses a 3D supercover DDA line algorithm to iterate over octants in the highest LOD grid along the ray's 3D line [S2]. For each octant identified, it performs recursive top-down parametric raycasting to find entry and exit planes, using child existence masks to accelerate search [S2].
*   **Pitfall:** The highest LOD grid has no coarser parent, so no meta information exists. A hash map must be queried for every octant in this grid, and empty space cannot be skipped on this level [S2].
*   **Performance:** Raycasting 1,048,576 spheres takes >65ms with a naive approach, but <0.5ms with the octree approach (tree depth $D=5$) [S2].

## Operating characteristics
*   **Time Complexity:** $O(\log n)$ for traversal in sparse volumes, compared to $O(n)$ for naive raycasting [S1, unofficial].
*   **Memory Complexity:** $O(n)$ for storing voxel data plus overhead for octree nodes [S1, unofficial].
*   **Measured Performance:** Raycasting 1,048,576 spheres takes <0.5ms with octree (depth $D=5$) vs >65ms naive [S2].
*   **Strengths:** Significant speedup for sparse volumes; supports dynamic updates with atomic operations [S1, unofficial][S2].
*   **Limitations:** Overhead for maintaining `voxel_count` and atomic operations; highest LOD grid requires hash map queries, preventing empty space skipping [S2].
*   **When to Use:** Dynamic volumes with frequent modifications; sparse data sets.
*   **When Not to Use:** Dense volumes where traversal overhead outweighs culling benefits; static volumes where simpler acceleration structures may suffice.

## Background
Originated in the context of raycasting-based voxel rendering, where acceleration structures are necessary due to the $O(n)$ complexity of naive raycasting [S1, unofficial]. The approach was developed to handle dynamic volume modifications, requiring the octree to track voxel counts per node [S1, unofficial]. Atomic operations using HLSL intrinsics were introduced to handle concurrent updates [S1, unofficial]. The hybrid approach with voxel traversal was proposed to handle the highest LOD grid where meta-information is unavailable [S2].
