# Octree-based Raycasting

Also called: Raycasting mit Octree-Beschleunigungsstruktur, Voxel-Raycasting mit Octree

## Overview
Octree-based raycasting is a volume rendering technique that accelerates ray traversal by utilizing an octree structure to skip empty space regions [S1, unofficial]. It solves the performance bottleneck of naive raycasting, which scales linearly with the number of voxels $O(n)$, by culling large volumes of empty space [S1, unofficial]. It differs from its parent [Ray-Occlusion Traversal in Octree](5121-ray-occlusion-traversal-in-octree.md) by explicitly maintaining voxel counts per node to support dynamic updates [S1, unofficial], and from [Bottom-up Neighbor-Finding Ray Traversal](5610-bottom-up-neighbor-finding-ray-traversal.md) by relying on top-down parametric analysis rather than neighbor-finding for traversal [S2].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, octree root node, voxel data buffer [G].
**Outputs:** Intersection points, accumulated color/opacity [G].

**Data Structures:**
*   **Octree Node:** Contains a boolean `exists` flag and an integer `voxel_count` [S1, unofficial].
*   **Voxel Buffer:** Stores density/color values for active voxels [G].
*   **StructuredBuffer:** GPU buffer holding node data, declared `globallycoherent` for atomic operations [S1, unofficial].

**Steps:**
1.  **Initialization:** Start traversal at the root node [G]. If the ray originates inside the root, compute entry point; otherwise, intersect ray with root bounding box planes [Parent].
2.  **Node Evaluation:** For the current node, check `exists` [S1, unofficial]. If false, terminate traversal for this branch.
3.  **Voxel Count Check:** Read `voxel_count` [S1, unofficial]. If `voxel_count` is 0, deactivate the node (set `exists` to false) [S1, unofficial].
4.  **Ray-Node Intersection:** Compute parametric intersection of the ray with the current node's bounding box [G]. If the ray misses or the intersection distance exceeds the current closest hit `t_max`, terminate this branch [G].
5.  **Leaf/Interior Decision:**
    *   If leaf: Sample voxel data at the intersection point [G].
    *   If interior: Compute child bounding boxes [G]. Determine which children intersect the ray within `t_max` [G].
6.  **Recursive Traversal:** For each intersecting child, recursively call the raycasting function with the child's exit distance as the new `t_max` [G]. Return the closest hit found.
7.  **Dynamic Update (On Modification):** When a voxel is deleted, decrement `voxel_count` of all ancestor nodes [S1, unofficial]. If `voxel_count` reaches 0, mark the node as inactive [S1, unofficial].

**Pseudocode:**
```python
MAX_DEPTH = 5  # Typical tree depth [S2]

def raycast_octree(ray_origin, ray_direction, node, depth, t_max):
    # Check if node exists
    if not node.exists:
        return None

    # Check if node contains voxels
    if node.voxel_count == 0:
        node.exists = False
        return None

    # Ray-AABB intersection for current node
    hit, t_min, t_exit_node = ray_aabb_intersect(ray_origin, ray_direction, node.bbox_min, node.bbox_max)
    if not hit:
        return None
    if t_min < 0:
        t_min = 0.0  # Handle ray origin inside node
    if t_min >= t_max:
        return None

    # Base case: Leaf node
    if depth == MAX_DEPTH:
        return sample_voxel(ray_origin, ray_direction, node.voxel_data, t_min)

    # Recursive case: Interior node
    children_to_visit = []
    for i in range(8):
        child_min, child_max = get_child_bbox(node.bbox_min, node.bbox_max, i)
        child_hit, child_t_min, child_t_exit = ray_aabb_intersect(ray_origin, ray_direction, child_min, child_max)
        if child_hit and child_t_min < t_max:
            children_to_visit.append((i, child_t_min, child_t_exit))

    # Sort by t_min for early exit optimization
    children_to_visit.sort(key=lambda x: x[1])

    closest_hit = None
    for child_idx, child_t_min, child_t_exit in children_to_visit:
        child_node = node.children[child_idx]
        hit = raycast_octree(ray_origin, ray_direction, child_node, depth + 1, child_t_exit)
        if hit is not None:
            if closest_hit is None or hit.distance < closest_hit.distance:
                closest_hit = hit
            if closest_hit.distance <= child_t_min:
                break  # Early exit: closer hit found

    return closest_hit

def ray_aabb_intersect(origin, direction, bbox_min, bbox_max):
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if direction[i] == 0.0:
            if origin[i] < bbox_min[i] or origin[i] > bbox_max[i]:
                return False, 0.0, 0.0
        else:
            inv_d = 1.0 / direction[i]
            t1 = (bbox_min[i] - origin[i]) * inv_d
            t2 = (bbox_max[i] - origin[i]) * inv_d
            if t1 > t2:
                t1, t2 = t2, t1
            if t1 > t_min:
                t_min = t1
            if t2 < t_max:
                t_max = t2
            if t_min > t_max:
                return False, 0.0, 0.0
    return True, t_min, t_max

def get_child_bbox(parent_min, parent_max, child_idx):
    child_min = [0.0, 0.0, 0.0]
    child_max = [0.0, 0.0, 0.0]
    for i in range(3):
        half = (parent_max[i] - parent_min[i]) / 2.0
        if (child_idx >> i) & 1:
            child_min[i] = parent_min[i] + half
            child_max[i] = parent_max[i]
        else:
            child_min[i] = parent_min[i]
            child_max[i] = parent_min[i] + half
    return child_min, child_max

def sample_voxel(ray_origin, ray_direction, voxel_data, t_hit):
    # Standard texture lookup at parametric distance t_hit [G]
    return {"distance": t_hit, "density": 0.0, "color": [0.0, 0.0, 0.0]}
```

**Parameters:**
*   `MAX_DEPTH`: Depth of the octree. Typical value $D=5$ for large datasets [S2].
*   `voxel_count`: Integer field in node structure [S1, unofficial].
*   `t_max`: Tracks the current branch exit distance along the ray to prune further traversal [G].

**Edge Cases:**
*   **Empty Root:** If the root has `voxel_count` 0, no traversal occurs [S1, unofficial].
*   **Dynamic Updates:** Concurrent writes to `voxel_count` require atomic operations to prevent data races [S1, unofficial].
*   **Zero Direction Components:** Handled by checking ray origin against axis bounds before division [G].

## Subtopics

### Atomic Octree Update
A technique to prevent data races during concurrent writes to `voxel_count` in the octree nodes [S1, unofficial]. It uses HLSL intrinsics `InterlockedAdd` for atomic addition/subtraction on the `voxel_count` variable [S1, unofficial]. The `StructuredBuffer` must be declared with the `globallycoherent` qualifier to ensure visibility across warps [S1, unofficial]. This is necessary because multiple voxels in the same node may be deleted simultaneously, leading to inconsistent data if not synchronized [S1, unofficial].

### Hybrid Raycasting with Voxel Traversal
A top-down parametric raycasting technique that combines a voxel traversal algorithm with octree traversal [S2]. It uses a 3D supercover DDA line algorithm to iterate over octants in the highest LOD grid along the ray's 3D line [S2]. For each octant identified, it performs recursive top-down parametric raycasting to find entry and exit planes, using child existence masks to accelerate search [S2].
*   **Pitfall:** The highest LOD grid has no coarser parent, so no meta information exists. A hash map must be queried for every octant in this grid, and empty space cannot be skipped on this level [S2].
*   **Performance:** Raycasting 1,048,576 spheres takes >65ms with a naive approach, but <0.5ms with the octree approach (tree depth $D=5$) [S2].

## Operating characteristics
*   **Time Complexity:** Naive raycasting scales as $O(n)$ [S1, unofficial]. Octree traversal complexity is Not given in the sources. [G]
*   **Memory Complexity:** $O(n)$ for storing voxel data plus overhead for octree nodes [S1, unofficial].
*   **Measured Performance:** Raycasting 1,048,576 spheres takes <0.5ms with octree (depth $D=5$) vs >65ms naive [S2].
*   **Strengths:** Significant speedup for sparse volumes; supports dynamic updates with atomic operations [S1, unofficial][S2].
*   **Limitations:** Overhead for maintaining `voxel_count` and atomic operations; highest LOD grid requires hash map queries, preventing empty space skipping [S2].

## Background
Originated in the context of raycasting-based voxel rendering, where acceleration structures are necessary due to the $O(n)$ complexity of naive raycasting [S1, unofficial]. The approach was developed to handle dynamic volume modifications, requiring the octree to track voxel counts per node [S1, unofficial]. Atomic operations using HLSL intrinsics were introduced to handle concurrent updates [S1, unofficial]. The hybrid approach with voxel traversal was proposed to handle the highest LOD grid where meta-information is unavailable [S2].
