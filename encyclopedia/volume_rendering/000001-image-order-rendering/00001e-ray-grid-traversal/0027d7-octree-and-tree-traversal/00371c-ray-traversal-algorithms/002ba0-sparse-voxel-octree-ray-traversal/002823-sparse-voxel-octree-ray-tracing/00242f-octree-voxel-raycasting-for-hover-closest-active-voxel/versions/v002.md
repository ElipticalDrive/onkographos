# Octree Voxel Raycasting for Hover (Closest Active Voxel)

Also called: Octree Closest Hit Tracing

## Overview
This method traces rays against a GPU-accessible octree to find the closest intersections with active voxels [S1, unofficial]. It tracks both the nearest active leaf node and the nearest empty space node to support hover interactions [S2, unofficial]. It differs from standard SVO ray tracing [2989-sparse-voxel-octree-ray-tracing.md] by prioritizing closest-hit detection and empty-space fallback for interaction rather than full volume integration [G].

## How it works
**Inputs:** `rays` (GPU buffer of `Ray` structs, size `resolution * resolution`), `octree` (GPU-accessible sparse voxel octree), `resolution` (grid width and height) [S1, unofficial].
**Outputs:** `hits` (GPU buffer of `Hit` structs, size `resolution * resolution`), `host_hits` (host `std::vector<Hit>` of size `resolution * resolution` for downloaded results) [S1, unofficial].

**Data Structures:**
- `Ray`: Origin and direction vectors [G].
- `Hit`: Intersection results including distance, position, and normal [G].
- `OctreeNode`: `isLeaf` (bool), `isActive` (bool), `position` (vec3), `size` (vec3), `color` (vec3), `children` (array of 8 pointers) [S2, unofficial].

**Pseudocode:**
```python
def trace_closest_kernel(rays, hits, octree, resolution, current_depth):
    for idx in range(resolution * resolution):
        ray = rays[idx]
        closest_hit_distance = float('inf')
        closest_empty_distance = float('inf')
        found_active_voxel = False
        hover_info = {"has_hit": False, "node": None, "distance": float('inf'), "position": None, "normal": None}

        node = octree.root
        depth = 0
        while node is not None:
            hit_distance, hit_position, hit_normal = compute_intersection(ray, node)
            if hit_distance < float('inf'):
                if node.isActive and node.isLeaf:
                    if hit_distance < closest_hit_distance:
                        closest_hit_distance = hit_distance
                        found_active_voxel = True
                        hits[idx].distance = closest_hit_distance
                        hits[idx].position = hit_position
                        hits[idx].normal = hit_normal
                elif not found_active_voxel and depth >= current_depth and hit_distance < closest_empty_distance:
                    closest_empty_distance = hit_distance
                    hover_info["has_hit"] = True
                    hover_info["node"] = node
                    hover_info["distance"] = closest_empty_distance
                    hover_info["position"] = hit_position
                    hover_info["normal"] = hit_normal
            # Advance traversal logic [G]
            node = get_next_node(node, ray, depth)
            depth += 1

        hits[idx].hover_info = hover_info
```

**Algorithm Steps:**
1. **Initialization:** Reset `closestHitDistance` to infinity, `closestEmptyDistance` to infinity, and `foundActiveVoxel` to false when `depth == 1` [S2, unofficial]. Reset `hoverInfo.hasHit` to false [S2, unofficial].
2. **Dispatch:** Call `octree->trace_closest(rays->data(), hits->data(), resolution, resolution)` on the GPU [S1, unofficial].
3. **Traversal:** For each ray, traverse the octree. If an active leaf is intersected, update `closestHitDistance` and record the hit [G]. If an empty/internal node is intersected and `!foundActiveVoxel` and `depth >= currentDepth` and `hitDistance < closestEmptyDistance`, compute position and normal, update `hoverInfo` to point to the empty space node, set `closestEmptyDistance = hitDistance`, and set `hoverInfo.hasHit = true` [S2, unofficial].
4. **Download:** Transfer `hits` to host memory via `hits->download(host_hits.data())` [S1, unofficial].

**Parameters:**
- `resolution`: Width and height of the ray grid [S1, unofficial].
- `currentDepth`: Maximum traversal depth limit [S2, unofficial].

**Edge Cases:**
- **No Hit:** If no active voxel is intersected, `foundActiveVoxel` remains false and `hoverInfo.hasHit` indicates empty-space fallback [S2, unofficial].
- **Precision:** Floating-point comparisons for distance thresholds may require epsilon guards [G].
- **Boundaries:** Ray origins exactly on node boundaries require consistent half-open interval handling [G].

## Operating characteristics
- **Time Complexity:** $O(N \cdot D)$, where $N$ is the number of rays ($W \times H$) and $D$ is the average octree traversal depth [G].
- **Memory Complexity:** $O(W \times H)$ for the `rays` and `hits` GPU buffers [S1, unofficial].
- **Strengths:** Parallel GPU execution efficiently resolves closest-hit queries for interaction [G].
- **Limitations:** Requires host-device synchronization for result downloads and GPU memory allocation [S1, unofficial].
- **When to Use:** Hover interactions, picking, or closest-hit queries in SVO-based renderers [G].
- **When Not to Use:** Full volume integration, ray marching with accumulation, or CPU-only pipelines [G].

## Background
The method originates from GPU-based voxelization pipelines that dispatch ray tracing tasks via a stream and thread pool architecture [S1, unofficial]. It builds on [Sparse Voxel Octree Ray Tracing](2989-sparse-voxel-octree-ray-tracing.md) by specializing the traversal for closest active voxel detection and empty-space hover feedback [S2, unofficial].
