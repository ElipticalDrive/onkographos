# Octree Ray Marching with Brick Interpolation and Early Termination

Also called: Brick-based SVO Ray Marching, GigaVoxels Ray Marching

## Overview
This method performs volume rendering by traversing a Sparse Voxel Octree (SVO) using a hybrid approach that combines coarse space-skipping via precomputed "bricks" (sub-cubes of voxels) with fine-grained interpolation within those bricks [S1, unofficial]. It reduces the number of node fetches and memory accesses required to traverse empty or uniform regions [S1, unofficial]. It sets itself apart from [SVO Ray Marching with Stack-Based Navigation](2454-svo-ray-marching-with-stack-based-navigation.md) by utilizing brick interpolation to handle view-dependent sampling rates more efficiently [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin ($O$) and direction ($D$) in world space; Sparse Voxel Octree structure; Brick textures (scalar values and optionally gradients); Transfer function; Camera projection parameters [S1, unofficial].
*   **Output:** Color ($C$) and accumulated opacity ($\alpha$) for the pixel [G].

**Data Structures:**
*   **Octree Node:** Contains a pointer to child nodes (or null for leaves) and metadata including brick dimensions and offsets [S1, unofficial].
*   **Brick:** A fixed-size sub-cube of voxels stored in a texture. Bricks are stored as unmodified scalar values to allow dynamic transfer function application in the fragment shader without texture regeneration [S1, unofficial].
*   **Node Usage List:** A list tracking recently traversed nodes to optimize memory management and brick loading [S1, unofficial].

**Parameters:**
*   `projVoxelSize`: Projected voxel size in world coordinates, used to determine interpolation ratios [S1, unofficial].
*   `parentVoxelSize`: Voxel size at the parent octree level, used in the interpolation denominator [S1, unofficial].
*   `k_ChildNodeSizeScalar`: Scalar multiplier applied to `nodeSize` and `voxelHalfSize` on each descent step [S1, unofficial].
*   `MaxNodesToPushThisFrame`: Maximum number of nodes allowed to be pushed to the usage list per frame [S1, unofficial].
*   `maxNodesPerPixelBlock`: Threshold for `nodeListTraversalCount` before it resets to 0 [S1, unofficial].
*   `startPushingNodes`, `stopPushingNodes`: Range for pushing nodes to the usage list [S1, unofficial].

**Steps:**

1.  **Initialization:**
    *   Reset traversal state: Set `octTreeNode` to `rootOctTreeNode`, `extents` to `VolExtentMin`/`VolExtentMax`, `nodeSize` to $1.0f$, and `voxelHalfSize` to `RootVoxelHalfSize` [S1, unofficial].
    *   Compute ray containment test:
        $$ test1 = \text{sign}(O - \text{VolExtentMin}) $$
        $$ test2 = \text{sign}(\text{VolExtentMax} - O) $$
        $$ inside = \text{dot}(test1, test2) $$
        If $inside < 3$, the ray does not intersect the volume extent [S1, unofficial].

2.  **Traversal Loop:**
    *   Increment counters: `++traversalCount`, `++nodeListTraversalCount`. If `nodeListTraversalCount >= maxNodesPerPixelBlock`, reset `nodeListTraversalCount` to 0 [S1, unofficial].
    *   **Node Management:** If `nodeListTraversalCount` is within `[startPushingNodes, stopPushingNodes)` and `pushedNodeCount < MaxNodesToPushThisFrame`, increment `pushedNodeCount` and call `AddToNodeUsageList(octTreeNode)` [S1, unofficial].
    *   **Interpolation Decision:**
        *   Compute interpolation factor based on `projVoxelSize` and `parentVoxelSize`.
        *   Clamp interpolation factor to $[0.0f, 1.0f]$ and threshold at $0.001f$ to avoid division by zero or negligible interpolation steps [S1, unofficial].
        *   Check conditions: If `projVoxelSize > parentVoxelSize`, `curDepth != 0`, and `interpolation factor > 0.001f`, proceed to **Brick Interpolation** step. Otherwise, proceed to **Brick Traversal** step [S1, unofficial].
        *   *Pitfall:* Interpolation is disabled at the root node (`curDepth == 0`) to prevent invalid ratios when `parentVoxelSize` equals `projVoxelSize` [S1, unofficial].

    *   **Brick Interpolation Step:**
        *   Compute `prevBrickRayPos` based on previous step position [G].
        *   Sample the brick texture with interpolation using `TraverseBrickInterp` [S1, unofficial].
        *   Update accumulated color and opacity using front-to-back compositing [G].

    *   **Brick Traversal Step:**
        *   Sample the brick texture without interpolation (nearest neighbor or simple fetch) using `TraverseBrick` [S1, unofficial].
        *   Update accumulated color and opacity [G].

    *   **Descent Logic (if node is not a leaf or brick is not fully traversed):**
        *   Compute `brickOffset = rayBrickPosition * k_TreeN` [S1, unofficial].
        *   Clamp to `childOffset = clamp(uvec3(brickOffset), 0u, 1u)` [S1, unofficial].
        *   Update `rayBrickPosition = brickOffset - vec3(childOffset)` [S1, unofficial].
        *   Update extents:
            $$ nodeExtentMin += (vec3(childOffset) * nodeSize) $$
            $$ nodeExtentMax -= ((vec3(1.0f) - vec3(childOffset)) * nodeSize) $$
        *   Fetch next octree node: `octTreeNode = texelFetch(OctTreeSampler, octTreeNodePtr, 0)` [S1, unofficial].
        *   Update `nodeSize *= k_ChildNodeSizeScalar` and `voxelHalfSize *= k_ChildNodeSizeScalar` [S1, unofficial].
        *   Increment `curDepth` [S1, unofficial].

    *   **Early Termination:**
        *   If accumulated opacity $> 0.995$ AND the current step actually traversed a brick or constant value, terminate the ray march [S1, unofficial].
        *   *Pitfall:* Early termination only triggers if the current step traversed a brick/constant value, preventing premature cutoff during initialization or empty space [S1, unofficial].

**Pseudocode:**

```python
def octree_ray_marching_brick_interpolation(ray_origin, ray_direction, octree, brick_textures, transfer_function):
    # Initialization [S1, unofficial]
    oct_tree_node = octree.root
    extents_min = octree.vol_extent_min
    extents_max = octree.vol_extent_max
    node_size = 1.0
    voxel_half_size = octree.root_voxel_half_size
    cur_depth = 0
    traversal_count = 0
    node_list_traversal_count = 0
    pushed_node_count = 0
    
    # Ray advancement and brick position [G]
    ray_position = ray_origin
    ray_brick_position = floor(ray_position / octree.brick_size)
    prev_brick_ray_pos = ray_brick_position
    step_traversed_brick = False
    
    accumulated_color = vec3(0.0)
    accumulated_opacity = 0.0

    # Ray containment test [S1, unofficial]
    test1 = sign(ray_position - extents_min)
    test2 = sign(extents_max - ray_position)
    inside = dot(test1, test2)
    if inside < 3:
        return vec3(0.0), 0.0

    max_steps = 1000 # [G]
    for _ in range(max_steps):
        # Early termination [S1, unofficial]
        if accumulated_opacity > 0.995 and step_traversed_brick:
            break

        # Increment counters [S1, unofficial]
        traversal_count += 1
        node_list_traversal_count += 1
        if node_list_traversal_count >= octree.max_nodes_per_pixel_block:
            node_list_traversal_count = 0

        # Node management [S1, unofficial]
        if octree.start_pushing_nodes <= node_list_traversal_count < octree.stop_pushing_nodes:
            if pushed_node_count < octree.max_nodes_to_push_this_frame:
                pushed_node_count += 1
                octree.add_to_node_usage_list(oct_tree_node)

        # Interpolation decision [S1, unofficial]
        proj_voxel_size = octree.compute_projected_voxel_size(ray_position, ray_direction, cur_depth) # [G]
        parent_voxel_size = octree.compute_parent_voxel_size(cur_depth) # [G]
        interpolation_factor = clamp(proj_voxel_size / parent_voxel_size, 0.0, 1.0) # [G]

        # Pitfall: Disable interpolation at root [S1, unofficial]
        if cur_depth == 0:
            interpolation_factor = 0.0

        if proj_voxel_size > parent_voxel_size and cur_depth != 0 and interpolation_factor > 0.001:
            # Brick Interpolation [S1, unofficial]
            accumulated_color, accumulated_opacity = traverse_brick_interpolation(
                ray_brick_position, prev_brick_ray_pos, oct_tree_node, brick_textures, 
                transfer_function, node_size, accumulated_color, accumulated_opacity
            )
            step_traversed_brick = True
        else:
            # Brick Traversal [S1, unofficial]
            accumulated_color, accumulated_opacity = traverse_brick(
                ray_brick_position, oct_tree_node, brick_textures, 
                transfer_function, node_size, accumulated_color, accumulated_opacity
            )
            step_traversed_brick = True

        prev_brick_ray_pos = ray_brick_position

        # Descent logic [S1, unofficial]
        if not octree.is_leaf(oct_tree_node):
            brick_offset = ray_brick_position * octree.k_tree_n
            child_offset = clamp(uvec3(brick_offset), 0, 1)
            ray_brick_position = brick_offset - vec3(child_offset)
            
            extents_min += vec3(child_offset) * node_size
            extents_max -= (vec3(1.0) - vec3(child_offset)) * node_size
            
            oct_tree_node = texel_fetch(octree.oct_tree_sampler, oct_tree_node.ptr, 0)
            node_size *= octree.k_child_node_size_scalar
            voxel_half_size *= octree.k_child_node_size_scalar
            cur_depth += 1
        else:
            # Ascent/Backtracking not detailed in sources [G]
            break

        # Advance ray along direction [G]
        ray_position += ray_direction * node_size

    return accumulated_color, accumulated_opacity

def traverse_brick_interpolation(ray_brick_pos, prev_brick_pos, node, textures, tf, node_size, acc_color, acc_alpha):
    # Sample brick texture with interpolation [S1, unofficial]
    sample_value = texture_interpolate(textures.brick, ray_brick_pos)
    # Apply transfer function [G]
    C_s, alpha_s = tf(sample_value)
    # Front-to-back compositing [G]
    acc_alpha = acc_alpha + (1.0 - acc_alpha) * alpha_s
    acc_color = acc_color + (1.0 - acc_alpha) * C_s * alpha_s
    return acc_color, acc_alpha

def traverse_brick(ray_brick_pos, node, textures, tf, node_size, acc_color, acc_alpha):
    # Sample brick texture without interpolation [S1, unofficial]
    sample_value = texture_fetch(textures.brick, ray_brick_pos)
    # Apply transfer function [G]
    C_s, alpha_s = tf(sample_value)
    # Front-to-back compositing [G]
    acc_alpha = acc_alpha + (1.0 - acc_alpha) * alpha_s
    acc_color = acc_color + (1.0 - acc_alpha) * C_s * alpha_s
    return acc_color, acc_alpha
```

## Subtopics

### [Two-staged Space-Skipping with Bricking and Octrees](5210-two-staged-space-skipping-with-bricking-and-octrees.md)
This method balances GPU bottlenecks by dividing space-skipping into two stages: coarse division using bricking to address bus and texture cache limitations, and fine division using octrees within bricks to address the rasterization bottleneck. It differs from Tong et al.'s bricking technique by storing unmodified scalar values in textures and using a fragment shader for post-interpolative RGB$\alpha$ lookup, avoiding time-consuming texture regeneration when the transfer function changes.

### [Stackless GPU Raycasting with Octree Traversal](5222-stackless-gpu-raycasting-with-octree-traversal.md)
This method performs volume rendering by traversing a Sparse Voxel Octree (SVO) on the GPU without using a stack, computing the volume rendering integral in front-to-back order. It solves the problem of efficient memory access and traversal overhead in sparse volumetric data by combining space-skipping (via empty node detection) with adaptive sampling density. It sets itself apart from sibling methods like [Two-staged Space-Skipping with Bricking and Octrees](5210-two-staged-space-skipping-with-octrees.md) by performing neighbor lookups implicitly on-the-fly using the octree's regular structure, rather than relying on precomputed neighbor pointers or a two-stage bricking pipeline. It builds on the concepts of [Octree Ray Marching with Brick Interpolation and Early Termination](4147-octree-ray-marching-with-brick-interpolation-and-early-termi.md) but replaces explicit brick interpolation with adaptive sampling based on leaf resolution.

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume and the depth of the octree [G].
*   **Memory Complexity:** Requires storage for the octree nodes and brick textures [G].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales with resolution due to the adaptive nature of the octree and brick interpolation [G].
*   **Strengths:** Reduces memory bandwidth usage by fetching multiple voxels per texture access; handles view-dependent sampling rates efficiently via interpolation; early termination speeds up rendering of opaque objects [G].
*   **Limitations:** Interpolation artifacts may occur if the brick size is too large or the transfer function is highly non-linear [G].
*   **When to use:** Suitable for real-time volume rendering of large, sparse datasets where memory bandwidth is a bottleneck [G].
*   **When not to use:** Not suitable for volumes with very fine, high-frequency details that require per-voxel accuracy without interpolation [G].

## Background
This method is based on the GigaVoxels framework, which was developed to enable real-time exploration of large volumetric datasets. The specific implementation details, including brick interpolation and early termination, are derived from the VoxViz project and associated thesis [S1, unofficial]. The approach addresses the limitations of traditional ray casting on sparse voxel grids by leveraging the hierarchical structure of the octree and the spatial coherence of volumetric data [S1, unofficial].
