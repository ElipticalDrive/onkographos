# Quaternary Tree Volume Traversal

Also called: CPU-GPU Split Volume Rendering, Tile-based Ray Casting

## Overview
Quaternary Tree Volume Traversal is a hybrid rendering technique that offloads coarse spatial partitioning to the CPU and fine-grained ray-object intersection to the GPU [S1]. It solves the problem of inefficient memory access and load balancing in volume rendering by dividing the rendering pipeline into two distinct stages: geometric culling on the CPU and ray casting on the GPU [S1]. Unlike pure GPU ray tracers, this method leverages the CPU's flexibility to build a quaternary tree for early space-skipping, reducing the number of rays processed by the GPU [S1].

## How it works
The method operates on a functionally defined object (implicit surface) represented by a height map or scalar field. The core algorithm divides the 3D space into tiles using a quaternary tree on the CPU, then performs ray casting along the Z-axis on the GPU.

**Inputs:**
- A scalar field or height map defining the object surface [S1].
- Camera parameters (view direction, assumed to be along the Z-axis for the GPU stage) [S1].
- Tile size parameter (resolution of the final fragments) [S1].

**Outputs:**
- A rendered image with smooth shading and lighting [S1].
- Z-coordinates and surface normals for each pixel [S1].

**Data Structures:**
- **Quaternary Tree:** A tree structure where each node represents a square region in the XY plane. Each node has up to four children, corresponding to the four quadrants of the parent region [S1].
- **Fragment List:** A list of geometric primitives (tiles) generated by the CPU, containing intersection data for tiles that contain part of the object [S1].

**Algorithm Steps:**

1.  **CPU: Quaternary Tree Construction**
    1.  Start with the entire object space (a cube or bounding box).
    2.  Divide the current region into four equal parts in the XY plane [S1].
    3.  Test each of the four parts for intersection with the object. The intersection test checks if the scalar field or height map values within the region indicate the presence of the object [S1].
    4.  If a part does not intersect the object, neglect it (do not create children) [S1].
    5.  If a part intersects the object, recursively apply steps 2-4 to that part [S1].
    6.  Stop recursion when the current part corresponds to a tile of a predefined size (the target fragment resolution) [S1].
    7.  Generate a list of fragments. Each fragment represents a tile where the object intersects the volume [S1].

2.  **GPU: Ray Casting and Shading**
    1.  Feed the list of fragments from the CPU to the GPU [S1].
    2.  For each pixel in the target image, cast a ray directed along the Z-axis [S1].
    3.  Determine which fragment(s) the ray passes through based on the fragment list [S1].
    4.  Perform a binary search along the ray to find the nearest intersection point with the object surface [S1].
        -   The goal is to find the first point where the implicit function vanishes (i.e., $f(x,y,z) = 0$) [S1].
    5.  Determine the Z-coordinate of the intersection point for each pixel [S1].
    6.  Calculate the surface normal at the intersection point [S1].
    7.  Apply a local lighting model using the position and normal to compute the final pixel color [S1].

**Pseudocode:**

```python
# CPU Side
def build_quaternary_tree(region, tile_size):
    """
    Recursively divide the region in XY plane and test for intersection.
    region: Bounding box (x_min, x_max, y_min, y_max, z_min, z_max)
    tile_size: Minimum size for a fragment tile
    Returns: List of fragments (tiles) that intersect the object
    """
    fragments = []
    
    # Check if region is smaller than tile size
    if (region.x_max - region.x_min < tile_size and 
        region.y_max - region.y_min < tile_size):
        # Base case: if it intersects, add as fragment
        if intersects_object(region):
            fragments.append(Fragment(region))
        return fragments

    # Divide into four parts in XY plane
    mid_x = (region.x_min + region.x_max) / 2
    mid_y = (region.y_min + region.y_max) / 2
    
    # Define four quadrants
    quadrants = [
        Region(region.x_min, mid_x, region.y_min, mid_y, region.z_min, region.z_max),
        Region(mid_x, region.x_max, region.y_min, mid_y, region.z_min, region.z_max),
        Region(region.x_min, mid_x, mid_y, region.y_max, region.z_min, region.z_max),
        Region(mid_x, region.x_max, mid_y, region.y_max, region.z_min, region.z_max)
    ]
    
    for quad in quadrants:
        if intersects_object(quad):
            # Recursively subdivide
            fragments.extend(build_quaternary_tree(quad, tile_size))
            
    return fragments

def intersects_object(region):
    """
    Check if the object exists within the region.
    Implementation depends on the specific scalar field/height map.
    [G] Placeholder for specific intersection test logic.
    """
    # Example: Check if max height in region > 0
    return get_max_height_in_region(region) > 0

# GPU Side
def render_fragments(fragments, image_width, image_height):
    """
    Process fragments on GPU to render the image.
    """
    for y in range(image_height):
        for x in range(image_width):
            # Ray directed along Z-axis
            ray_origin = Vector3(x, y, 0)
            ray_direction = Vector3(0, 0, 1)
            
            # Find relevant fragment for this pixel
            relevant_fragment = find_fragment_at_pixel(fragments, x, y)
            
            if relevant_fragment is not None:
                # Binary search for intersection
                z_intersect = binary_search_intersection(ray_origin, ray_direction, relevant_fragment)
                
                if z_intersect is not None:
                    # Calculate normal
                    normal = calculate_normal(z_intersect)
                    
                    # Apply lighting
                    color = apply_lighting(ray_origin, z_intersect, normal)
                    image[x, y] = color
                else:
                    image[x, y] = background_color
            else:
                image[x, y] = background_color

def binary_search_intersection(origin, direction, fragment):
    """
    Find the first point where the function vanishes along the ray.
    """
    # [G] Standard binary search implementation for root finding
    # Lower bound z_min, upper bound z_max from fragment
    z_low = fragment.z_min
    z_high = fragment.z_max
    
    for _ in range(max_iterations):
        z_mid = (z_low + z_high) / 2
        point = origin + direction * z_mid
        value = evaluate_scalar_field(point)
        
        if abs(value) < epsilon:
            return z_mid
        
        if value > 0: # Assuming function vanishes at 0 and we look for first crossing
            z_high = z_mid
        else:
            z_low = z_mid
            
    return None
```

**Parameters:**
- **Tile Size:** The size of the fragments generated by the CPU. Smaller tiles increase precision but increase the number of fragments. [S1]
- **Ray Direction:** Assumed to be along the Z-axis for the GPU stage. [S1]

**Pitfalls:**
- **Memory Optimization:** Registers should be used to a maximum degree, and memory should be used jointly to avoid performance penalties from general GPU memory access. [S1]
- **Intersection Test Accuracy:** The intersection test on the CPU must be robust to avoid missing parts of the object or including empty space, which affects the fragment list quality. [S1]

## Operating characteristics
- **Time Complexity:** The CPU stage complexity depends on the tree depth and the number of fragments. The GPU stage complexity is linear with respect to the number of pixels and the cost of binary search per pixel. [S1]
- **Memory Complexity:** Depends on the number of fragments generated. Memory is optimized by using registers and joint memory access. [S1]
- **Performance:** Tested on Intel Core2 CPU E8400 3.0 GHz and NVIDIA GeForce GTX 470 GPU. The method reduces visualization time by effective use of computational resources. [S1]
- **Strengths:** Early neglect of large parts of the cube that do not contain the object, reducing the workload on the GPU. [S1]
- **Limitations:** Requires a two-stage pipeline with CPU-GPU communication. The method is specific to functionally defined objects and Z-axis rays. [S1]

## Background
The method was proposed in the paper "GPU-based volume-oriented rendering of functionally defined objects" [S1]. It was implemented using NVIDIA CUDA architecture and DirectX API. The testing was conducted on an Intel Core2 CPU E8400 3.0 GHz and an NVIDIA GeForce GTX 470 GPU. The research focuses on optimizing volume-oriented rendering by splitting the rasterization process between the CPU and GPU. [S1]
