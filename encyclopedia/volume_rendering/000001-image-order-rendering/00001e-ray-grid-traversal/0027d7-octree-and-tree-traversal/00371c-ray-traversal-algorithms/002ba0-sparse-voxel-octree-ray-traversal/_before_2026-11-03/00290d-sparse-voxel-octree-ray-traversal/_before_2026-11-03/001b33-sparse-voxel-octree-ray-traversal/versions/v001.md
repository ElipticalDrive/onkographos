# Sparse Voxel Octree Ray Traversal

Also called: Laine and Karras SVO Renderer, SVO Traversal, Sparse Voxel Octree (SVO) Raytracing, Sparse Voxel Octree Traversal

## Overview
Sparse Voxel Octree (SVO) Ray Traversal is a hierarchical raycasting method that renders 3D voxel data by traversing a tree structure where empty space nodes are omitted, ensuring sparsity [S1, unofficial]. It solves the problem of efficiently rendering large, high-resolution volumetric datasets by providing an implicit Level-of-Detail (LOD) mechanism; traversal depth is controlled by viewer distance or resolution requirements, skipping empty regions entirely [S1, unofficial][S3]. Unlike standard SVO methods that may store pre-computed normals or use contouring, this approach renders voxels as cubes with normals calculated on the fly based on the ray exit face, avoiding contouring artifacts [S2, unofficial]. It builds on [Octree Traversal](1587-octree-traversal.md) by using an iterative, stack-based traversal algorithm optimized for GPU execution, avoiding recursion which is unsupported in shading languages like HLSL [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $o$ and direction $d$; a Sparse Voxel Octree stored in a flat array (`SvoBuffer`); initial root size $s$; minimum voxel size $\epsilon$; octant vector array $P$ mapping indices 0–7 to 3D offsets.
*   **Output:** Hit distance $t$, hit position, surface normal, and voxel color. Returns `false` if no hit is found within the tree bounds.

**Data Structures:**
The SVO is stored as a contiguous array of 32-bit unsigned integers (`uint`). Two layout variants exist in the sources:

1.  **Laine & Karras / Hergül Layout [S1, unofficial]:**
    *   `struct OctreeEntry { int childrenStartIndex; int data; }`
    *   `childrenStartIndex`: Index of the first child in the array.
    *   `data`: Bitfield. First bit indicates if the node holds voxel data; remaining 31 bits are arbitrary (e.g., color or flags).
    *   Children are stored sequentially in memory starting at `childrenStartIndex`.

2.  **mxbrt/svo Layout [S2, unofficial]:**
    *   `SVONode` consists of two `uint` values per node: `node[0]` and `node[1]`.
    *   `node[0]` (Flags & Child Index):
        *   Bit 31: Empty flag (1 = empty, 0 = occupied).
        *   Bit 30: Leaf flag (1 = leaf, 0 = internal).
        *   Bits 0–29: Child index (offset into the `SvoBuffer`).
    *   `node[1]`: Color data (RGB, typically packed).
    *   Access: `child_idx = (cur_node & 0x3fffffff) * 2 + (idx ^ oct_mask) * 2`.

**Parameters:**
*   $s$: Initial size of the root node [S1, unofficial].
*   $\epsilon$: Minimum size of a voxel (termination condition) [S1, unofficial].
*   $P$: Array of octant vectors, e.g., $P[0]=(0,0,0)$, $P[1]=(1,0,0)$, $P[2]=(1,0,1)$ [S1, unofficial].
*   $S_{MAX}$: Maximum scale, typically 23 (corresponding to float mantissa bits) [S2, unofficial].
*   $EPSILON$: Small value ($10^{-4}$) to prevent division by zero for ray direction components [S2, unofficial].
*   $STACK\_SIZE$: Maximum depth of the traversal stack, typically 23 [S2, unofficial].

**Algorithm Steps:**
The traversal is iterative to support GPU shaders. It uses a "t-span" approach to determine which octants to visit.

1.  **Initialization:**
    *   Shift ray origin $o$ by $+1.0$ in x, y, z [S2, unofficial].
    *   Clamp ray direction components $d.x, d.y, d.z$ to $EPSILON$ if $|d| < EPSILON$ [S2, unofficial].
    *   Precompute coefficients:
        $$ t_{coef} = \frac{1.0}{-|d|} $$
        $$ t_{bias} = t_{coef} \cdot o $$
    *   Determine `oct_mask` and adjust biases based on ray direction signs:
        *   If $d.x > 0$: `oct_mask ^= 1`, $t_{bias}.x = 3.0 \cdot t_{coef}.x - t_{bias}.x$.
        *   If $d.y > 0$: `oct_mask ^= 2`, $t_{bias}.y = 3.0 \cdot t_{coef}.y - t_{bias}.y$.
        *   If $d.z > 0$: `oct_mask ^= 4`, $t_{bias}.z = 3.0 \cdot t_{coef}.z - t_{bias}.z$.
    *   Initialize active t-span:
        $$ t_{min} = \max(2.0 \cdot t_{coef}.x - t_{bias}.x, \ 2.0 \cdot t_{coef}.y - t_{bias}.y, \ 2.0 \cdot t_{coef}.z - t_{bias}.z) $$
        $$ t_{max} = \min(t_{coef}.x - t_{bias}.x, \ t_{coef}.y - t_{bias}.y, \ t_{coef}.z - t_{bias}.z) $$
        Clamp $t_{min} = \max(0.0, t_{min})$.
    *   Initialize traversal state:
        *   `parent_idx = 0`, `cur = 0`.
        *   `cur_node = svo_data[0]` (Root).
        *   `pos = (1.0, 1.0, 1.0)`.
        *   `idx = 0`.
        *   `scale = STACK_SIZE - 1`.
        *   `scale_exp2 = 0.5`.
        *   Determine initial `idx` based on $t_{min}$:
            *   If $1.5 \cdot t_{coef}.x - t_{bias}.x > t_{min}$: `idx ^= 1`, `pos.x = 1.5`.
            *   If $1.5 \cdot t_{coef}.y - t_{bias}.y > t_{min}$: `idx ^= 2`, `pos.y = 1.5`.
            *   If $1.5 \cdot t_{coef}.z - t_{bias}.z > t_{min}$: `idx ^= 4`, `pos.z = 1.5`.

2.  **Main Loop:**
    While `scale < STACK_SIZE`:
    *   **Fetch Node:** If `cur == 0`, `cur_node = svo_data[parent_idx]`.
    *   **Calculate Corner T:**
        $$ t_{corner} = pos \cdot t_{coef} - t_{bias} $$
        $$ t_{c\_max} = \min(t_{corner}.x, t_{corner}.y, t_{corner}.z) $$
    *   **Check Child Existence:**
        Calculate `child_idx` using the layout formula.
        Check if child exists (`child & 0x80000000 == 0`) AND $t_{min} \le t_{max}$.
    *   **Intersect/Descend:**
        If the child exists and the span is valid:
        *   $t_{v\_max} = \min(t_{max}, t_{c\_max})$.
        *   $half = scale\_exp2 \cdot 0.5$.
        *   $t_{center} = half \cdot t_{coef} + t_{corner}$.
        *   If $t_{min} \le t_{v\_max}$:
            *   **Leaf Check:** If `(child & 0x40000000) != 0` (Leaf flag set):
                *   Extract color from `svo_data[child_idx + 1]`.
                *   Break loop.
            *   **Push to Stack:**
                *   If $t_{c\_max} < h$ (where $h$ tracks the minimum exit distance of ancestors), push `(parent_idx, t_max)` to `stack[scale]`.
                *   Update $h = t_{c\_max}$.
                *   `parent_idx = child_idx`.
                *   `idx = 0`.
                *   `scale -= 1`.
                *   `scale_exp2 = half`.
                *   Update `pos` and `idx` based on $t_{center}$:
                    *   If $t_{center}.x > t_{min}$: `idx ^= 1`, `pos.x += scale_exp2`.
                    *   If $t_{center}.y > t_{min}$: `idx ^= 2`, `pos.y += scale_exp2`.
                    *   If $t_{center}.z > t_{min}$: `idx ^= 4`, `pos.z += scale_exp2`.
                *   `cur = 0`.
                *   $t_{max} = t_{v\_max}$.
                *   `continue`.
    *   **Advance:**
        If not descending:
        *   `step_mask = 0`.
        *   If $t_{corner}.x \le t_{c\_max}$: `step_mask ^= 1`, `pos.x -= scale_exp2`.
        *   If $t_{corner}.y \le t_{c\_max}$: `step_mask ^= 2`, `pos.y -= scale_exp2`.
        *   If $t_{corner}.z \le t_{c\_max}$: `step_mask ^= 4`, `pos.z -= scale_exp2`.
        *   $t_{min} = t_{c\_max}$.
        *   `idx ^= step_mask`.
        *   If $t_{min} \ge bvh\_t_{min}$ (BVH culling threshold), return `false`.
    *   **Pop:**
        If `(idx & step_mask) != 0`:
        *   Find highest differing bit between `pos` and `pos + scale_exp2` for x, y, z components to determine `differing_bits`.
        *   `scale = 31 - leading_zeros(differing_bits)`.
        *   `scale_exp2 = exp2f(scale - S_MAX)`.
        *   Restore `parent_idx` and `t_max` from `stack[scale]`.
        *   Round `pos` to current scale by shifting bits:
            *   `shx = floatBitsToUint(pos.x) >> scale`.
            *   `pos.x = uintBitsToFloat(shx << scale)`.
            *   (Repeat for y, z).
        *   Extract new `idx` from rounded `pos` bits.
        *   `cur = 0`.

3.  **Normal Calculation:**
    *   Determine face based on `oct_mask` and `step_mask`.
    *   If `(oct_mask & 1) == 0` and `(step_mask & 1) != 0`: Face 3 (Left, Normal $(-1, 0, 0)$).
    *   If `(oct_mask & 2) == 0` and `(step_mask & 2) != 0`: Face 5 (Bottom, Normal $(0, -1, 0)$).
    *   If `(oct_mask & 4) == 0` and `(step_mask & 4) != 0`: Face 6 (Front, Normal $(0, 0, -1)$).
    *   Else: Face = `step_mask`.
    *   Map face to normal: $1 \to (1,0,0)$, $2 \to (0,1,0)$, $3 \to (-1,0,0)$, $4 \to (0,0,1)$, $5 \to (0,-1,0)$, $6 \to (0,0,-1)$.

4.  **Return:**
    *   Set $t = t_{min}$.
    *   Return `true` if hit, `false` if `scale >= STACK_SIZE`.

**Edge Cases and Pitfalls:**
*   **Recursion:** HLSL does not support recursion. The algorithm must be iterative [S1, unofficial].
*   **Boundary Voxels:** If `step_mask == 0` after the loop, check if $2.0 \cdot t_{coef} - t_{bias} \ge t_{min}$ to handle rays exiting the octree or hitting boundaries [S2, unofficial].
*   **Dynamic Updates:** Dynamic updates to voxel data are inefficient; worst-case requires regenerating the entire Octree every frame [S1, unofficial].
*   **Precision:** Use `EPSILON` ($10^{-4}$) to avoid division by zero for small ray direction components [S2, unofficial].

## Subtopics

### [Sparse Voxel DAG Construction with Subtree Caching](1289-sparse-voxel-dag-construction-with-subtree-caching.md)
Compresses the SVO into a Directed Acyclic Graph (DAG) by merging identical subtrees, significantly reducing node count and memory usage compared to standard SVOs. Choose this when memory constraints are critical for high-resolution scenes.

### [GigaVoxels](3057-gigavoxels.md)
A dynamic sparse octree approach that adapts resolution based on the view and occlusion, streaming data to achieve real-time rates for billions of voxels. Choose this when rendering extremely large scenes with smooth temporal transitions and inherent anti-aliasing are required.

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal, where $N$ is the number of voxels, due to the hierarchical structure [S1, unofficial].
*   **Memory Complexity:** Sparse; only occupied nodes are stored. However, at high resolutions, memory constraints can still be significant, often limiting SVOs to effects like rough reflections or ambient occlusion where lower resolution is acceptable [S3].
*   **Performance:** The mxbrt/svo implementation renders a scene with over 1 billion voxels (512 tori at $128^3$) at 20 FPS at 720p on an AMD 5700 [S2, unofficial].
*   **Strengths:** Implicit LOD, efficient empty space skipping, no contouring artifacts, suitable for large static scenes.
*   **Limitations:** Inefficient for dynamic updates (requires full regeneration), memory intensive at very high resolutions without DAG compression [S1, unofficial][S3].

## Background
The Sparse Voxel Octree (SVO) was introduced by Laine and Karras as an efficient data structure for ray tracing [S1, S2, unofficial]. It allows for Level-of-Detail rendering by controlling traversal depth based on viewer distance [S1, unofficial]. The method is used as a baseline for comparison with DAG-based methods and is employed in real-time rendering for effects like reflections and ambient occlusion [S3]. The iterative traversal algorithm described here is adapted from the original Laine and Karras paper to support GPU execution without recursion [S2, unofficial].
