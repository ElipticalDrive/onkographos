# SVO Ray Tracing
Also called: Sparse Voxel Octree Ray Tracing, SVO Traversal

## Overview
SVO Ray Tracing is a hierarchical ray traversal method that accelerates volume rendering by traversing a Sparse Voxel Octree (SVO) rather than a uniform grid. It builds on [Ray-grid traversal](17-ray-grid-traversal.md) by using the tree structure to skip empty space, visiting only occupied nodes. It differs from [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by specifically referring to implementations that construct the SVO from a voxel grid (often via morton codes) and traverse it using a stackless or explicit stack approach, as seen in specific GPU raytracing implementations.

## How it works
**Inputs:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; an SVO constructed from a voxel grid.
**Outputs:** A color/value for the ray, determined by integrating density or shading along the ray.

**Data Structures:**
The SVO is stored in flat buffers for GPU access [S1, unofficial]:
1.  **SVO Node Buffer:** Contains internal nodes. Each node has:
    *   `center`: `[f32; 4]` (x, y, z, w).
    *   `radius`: `f32`.
    *   `left_child`: `u32` (index into node/leaf buffer, MSB set to 1 to distinguish from leaves).
    *   `right_child`: `u32` (index into node/leaf buffer, MSB set to 1).
2.  **SVO Leaf Buffer:** Contains leaf nodes. Each leaf has:
    *   `model_address`: `u32` (index to object data).
    *   `inv_model`: `[f32; 4]` (part of inverse transformation matrix).
3.  **Uniform Buffer:** Contains camera parameters:
    *   `camera_rotation`: `[[f32; 4]; 4]`.
    *   `camera_origin`: `[f32; 4]`.
    *   `width`, `height`: `u32`.
    *   `aspect_ratio`: `f32`.
    *   `fov`: `f32` (stored as $\tan(\text{fov}/2)$).
    *   `bvh_root`: `u32` (index of the root node).

**Construction (Preprocessing):**
1.  Load voxel grid from CSV [S1, unofficial].
2.  Encode voxel positions into 3D Morton codes [S1, unofficial].
3.  Sort leaves by Morton code.
4.  Build BVH/SVO structure by pairing adjacent leaves and nodes, computing bounding spheres (center and radius) for each parent node [S1, unofficial].
5.  Store nodes and leaves in flat buffers. Max leaves: $2^{16}$, Max nodes: $2 \cdot 2^{16} - 1$ [S1, unofficial].

**Traversal Algorithm:**
The traversal uses a stack (or explicit queue) to manage the traversal order. The specific implementation described uses a queue-based approach for building, but traversal typically follows a depth-first or breadth-first pattern depending on the callback mechanism [S1, unofficial]. For a single ray:

1.  Initialize traversal stack/queue with the root node index.
2.  While stack/queue is not empty:
    a.  Pop node index $n$.
    b.  If $n$ is a leaf (check MSB of index):
        i.  Intersect ray with the leaf's bounding volume or object.
        ii. If hit, compute shading/radiance and update ray color.
    c.  If $n$ is an internal node:
        i.  Compute distance to node's bounding sphere.
        ii. If ray intersects sphere:
            1.  Push `right_child` to stack/queue.
            2.  Push `left_child` to stack/queue.
            (Note: Order depends on traversal strategy; SVO Walk visits based on eye position [S1, unofficial]).
3.  Return accumulated color.

**Pseudocode:**
```python
def traverse_svo_ray(o, d, root_idx, nodes, leaves):
    stack = [root_idx]
    color = [0.0, 0.0, 0.0]
    
    while stack:
        idx = stack.pop()
        
        # Check if leaf (MSB set)
        if idx & 0x80000000:
            leaf_idx = idx & 0x7FFFFFFF
            leaf = leaves[leaf_idx]
            # Intersect with object defined by leaf
            hit = intersect_ray_with_object(o, d, leaf)
            if hit:
                color = shade(hit, leaf)
        else:
            node = nodes[idx]
            # Check intersection with node bounding sphere
            if ray_sphere_intersect(o, d, node.center[:3], node.radius):
                # Push children
                # Note: right_child and left_child indices already have MSB set
                stack.append(node.right_child)
                stack.append(node.left_child)
                
    return color
```

**Edge Cases:**
*   **Empty Space:** The tree structure inherently skips empty regions, but rays may pass through large empty volumes if the tree is not deep enough.
*   **Precision:** Floating-point errors in ray-sphere intersection tests can cause missed nodes or false positives. Use epsilon tolerance [S5, S3436].
*   **Stack Overflow:** Deep trees may require a large stack. Stackless traversal variants exist [5202-stackless-traversal.md].

## Subtopics

### [SVO Walk (Traversal)](5188-svo-walk-traversal.md)
Traverses the SVO tree from the root, visiting nodes in a specific order based on eye position, and calling a callback for each node.

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal in balanced trees, where $N$ is the number of voxels. In practice, depends on tree depth and occupancy.
*   **Memory Complexity:** $O(N)$ for storing the SVO nodes and leaves.
*   **Performance:** Faster than uniform grid traversal for sparse volumes. Slower than highly optimized grid traversal for dense volumes due to tree traversal overhead.
*   **Strengths:** Efficient for sparse data; supports adaptive resolution.
*   **Limitations:** Construction time can be high; memory overhead for tree structure.

## Background
SVO Ray Tracing is used in real-time raytracing applications, particularly in Vulkan-based renderers. The specific implementation described in [S1, unofficial] uses a BVH-like structure built from Morton codes for efficient spatial sorting.
