# SVO Walk (Traversal) — fast_walk

Also called: BVH Traversal with SVO Leaves, BVH-SVO Hybrid Traversal

## Overview
`fast_walk` is a hybrid ray traversal algorithm that combines a Bounding Volume Hierarchy (BVH) for coarse culling with Sparse Voxel Octree (SVO) structures for fine-grained density evaluation. It solves the problem of efficiently rendering large, sparse volumetric datasets by delegating leaf-node processing to an SVO ray marcher while using BVH ray-sphere intersection to skip empty regions of the scene. It differs from pure SVO traversal by reducing the number of visited nodes through hierarchical culling, and from pure BVH traversal by maintaining the memory efficiency and adaptive resolution of the SVO at the leaves.

## How it works
**Inputs:**
- Ray origin $O$ and direction $D$.
- BVH node buffer (`BVHNodes`).
- BVH leaf buffer (`BVHLeafs`).
- SVO data structures (accessed via leaf `address`).
- Output accumulators: `min_t` (initialized to $\infty$), `o_t`, `o_color`, `o_normal`.

**Data Structures:**
- `BVHNode`: Struct containing:
  - `center`: `vec4` (x, y, z coordinates of the bounding sphere center; w is unused or padding).
  - `radius`: `float` (radius of the bounding sphere).
  - `left_child`: `uint` (index of left child; if bit 31 is set, it is a leaf index).
  - `right_child`: `uint` (index of right child; if bit 31 is set, it is a leaf index).
- `BVHLeaf`: Struct containing:
  - `inv_model`: `mat4` (inverse model matrix for the leaf's coordinate space).
  - `address`: `uint` (pointer/index to the root of the SVO structure for this leaf).

**Parameters:**
- `BVH_STACK_SIZE`: Maximum depth of the traversal stack, set to 64 [S1, unofficial].
- `MAX_T`: Termination threshold, set to 10000.0 [S1, unofficial].

**Algorithm Steps:**
1. Initialize a stack `S` of size `BVH_STACK_SIZE`. Push the root node index onto `S`.
2. While `S` is not empty:
   a. Pop the current node index `idx` from `S`.
   b. Load `node = BVHNodes[idx]`.
   c. Check if `node.left_child` is a leaf: `is_leaf = (node.left_child & 0x80000000) != 0`.
   d. If `is_leaf`:
      i. Call `bvh_trace_leaf` for the left child. The actual leaf index is `node.left_child ^ 0x80000000`.
      ii. Call `bvh_trace_leaf` for the right child. The actual leaf index is `node.right_child ^ 0x80000000`.
      iii. If a hit is found in either leaf, update `min_t`, `o_t`, `o_color`, and `o_normal` with the closest hit.
   e. If not `is_leaf`:
      i. Load `left_node = BVHNodes[node.left_child]` and `right_node = BVHNodes[node.right_child]`.
      ii. Perform ray-sphere intersection for the ray $(O, D)$ against `left_node.center` and `left_node.radius`. Set `left_descend` to true if the ray intersects the sphere within `min_t`.
      iii. Perform ray-sphere intersection for the ray $(O, D)$ against `right_node.center` and `right_node.radius`. Set `right_descend` to true if the ray intersects the sphere within `min_t`.
      iv. If neither `left_descend` nor `right_descend` is true:
         - Continue to next iteration (pop next from stack).
      v. If only one child is descended into:
         - Push the non-descended child's index onto `S` (if stack is not full).
         - Set current node to the descended child.
      vi. If both children are descended into:
         - Determine which child is farther from the ray origin.
         - Push the farther child's index onto `S` (if stack is not full).
         - Set current node to the nearer child.
3. After the loop, set `o_t = min_t`.
4. Return `true` if `min_t < MAX_T`, else `false`.

**Pseudocode:**

```python
def fast_walk(ray_origin, ray_direction, bvh_nodes, bvh_leaves, svo_data, max_t=10000.0):
    stack = []
    stack.append(0)  # Assume root is index 0
    min_t = float('inf')
    o_t = 0.0
    o_color = (0.0, 0.0, 0.0, 0.0)
    o_normal = (0.0, 0.0, 0.0)

    while stack:
        if not stack:
            break
        
        idx = stack.pop()
        node = bvh_nodes[idx]
        
        # Check if left child is a leaf
        is_leaf = (node.left_child & 0x80000000) != 0
        
        if is_leaf:
            # Process left leaf
            left_leaf_idx = node.left_child ^ 0x80000000
            hit_t, hit_color, hit_normal = bvh_trace_leaf(
                ray_origin, ray_direction, 
                bvh_leaves[left_leaf_idx], svo_data, min_t
            )
            if hit_t < min_t:
                min_t = hit_t
                o_t = hit_t
                o_color = hit_color
                o_normal = hit_normal
            
            # Process right leaf
            right_leaf_idx = node.right_child ^ 0x80000000
            hit_t, hit_color, hit_normal = bvh_trace_leaf(
                ray_origin, ray_direction, 
                bvh_leaves[right_leaf_idx], svo_data, min_t
            )
            if hit_t < min_t:
                min_t = hit_t
                o_t = hit_t
                o_color = hit_color
                o_normal = hit_normal
        else:

                        stack.append(node.right_child)
                    idx = node.left_child

def bvh_trace_leaf(ray_origin, ray_direction, leaf, svo_data, min_t):
    # Transform ray to leaf's local space using inv_model
    inv_model = leaf.inv_model
    # Apply inverse model matrix to ray origin and direction
    # This is a simplified representation; actual matrix multiplication required
    local_origin = transform_point(inv_model, ray_origin)
    local_direction = transform_vector(inv_model, ray_direction)
    
    # Call SVO ray marcher
    hit_t, hit_color, hit_normal = svo_ray_march(local_origin, local_direction, svo_data, leaf.address, min_t)
    return hit_t, hit_color, hit_normal

def ray_sphere_intersect(ray_origin, ray_direction, sphere_center, radius, min_t):
    # Standard ray-sphere intersection
    oc = ray_origin - sphere_center
    a = dot(ray_direction, ray_direction)
    b = 2.0 * dot(oc, ray_direction)
    c = dot(oc, oc) - radius * radius
    discriminant = b * b - 4 * a * c
    
    if discriminant < 0:
        return False
    
    sqrt_disc = sqrt(discriminant)
    t1 = (-b - sqrt_disc) / (2 * a)
    t2 = (-b + sqrt_disc) / (2 * a)
    
    t = t1 if t1 > 0 else t2
    return t < min_t

def ray_sphere_distance(ray_origin, sphere_center):
    # Distance from ray origin to sphere center
    return length(sphere_center - ray_origin)

def transform_point(matrix, point):
    # Homogeneous transformation
    w = matrix[3][0]*point.x + matrix[3][1]*point.y + matrix[3][2]*point.z + matrix[3][3]
    x = (matrix[0][0]*point.x + matrix[0][1]*point.y + matrix[0][2]*point.z + matrix[0][3]) / w
    y = (matrix[1][0]*point.x + matrix[1][1]*point.y + matrix[1][2]*point.z + matrix[1][3]) / w
    z = (matrix[2][0]*point.x + matrix[2][1]*point.y + matrix[2][2]*point.z + matrix[2][3]) / w
    return (x, y, z)

def transform_vector(matrix, vector):
    # Linear transformation (no translation)
    x = matrix[0][0]*vector.x + matrix[0][1]*vector.y + matrix[0][2]*vector.z
    y = matrix[1][0]*vector.x + matrix[1][1]*vector.y + matrix[1][2]*vector.z
    z = matrix[2][0]*vector.x + matrix[2][1]*vector.y + matrix[2][2]*vector.z
    return (x, y, z)
```

**Edge Cases and Pitfalls:**
- Stack overflow: `BVH_STACK_SIZE` is fixed at 64. Deep BVHs may cause stack overflow if not handled [S1, unofficial].
- Precision: Ray-sphere intersection precision can affect culling accuracy.
- Leaf Index Masking: The leaf index is stored with the MSB set. It must be XORed with `0x80000000` to get the actual index [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(\log N)$ for BVH traversal, where $N$ is the number of BVH nodes. SVO traversal is proportional to the number of occupied voxels along the ray.
- **Memory Complexity:** $O(N)$ for BVH nodes and $O(M)$ for SVO nodes, where $M$ is the number of SVO nodes. Stack space is $O(D)$, where $D$ is the BVH depth, capped at 64 [S1, unofficial].
- **Performance:** Faster than pure SVO traversal for sparse scenes due to BVH culling. Slower than pure BVH for dense scenes due to SVO overhead.
- **Strengths:** Efficient for large, sparse datasets. Good balance between memory usage and traversal speed.
- **Limitations:** Stack size limitation. Complexity of implementation due to hybrid nature.

## Background
The `fast_walk` algorithm is described in the unofficial source [S1, unofficial]. It is part of the `mxbrt/svo` project. The approach combines BVH and SVO techniques, which are common in volume rendering.
