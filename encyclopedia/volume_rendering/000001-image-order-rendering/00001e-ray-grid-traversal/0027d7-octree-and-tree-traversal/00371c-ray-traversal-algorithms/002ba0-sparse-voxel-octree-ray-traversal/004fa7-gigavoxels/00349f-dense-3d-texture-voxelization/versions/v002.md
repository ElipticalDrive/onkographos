# Dense 3D Texture Voxelization

Also called: Dense 3D Texture, Mip-mapped 3D Texture Volume

## Overview
Dense 3D Texture Voxelization is an alternative to GigaVoxels [GigaVoxels](3057-gigavoxels.md) where the entire scene, including empty space, is encoded into a very large mip-mapped 3D texture [S1, unofficial]. It solves the problem of sparse data management by replacing the explicit octree structure with an implicit one derived from the texture's mipmap levels. Unlike GigaVoxels, which uses a dynamic sparse octree to stream only necessary data, this method relies on direct world-space indexing and automatic hardware filtering, trading memory efficiency for implementation simplicity [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (density and color/opacity) defined in world space.
*   **Output:** A mip-mapped 3D texture resource suitable for GPU sampling.

**Data Structures:**
*   **3D Texture:** A dense, multi-level 3D texture array. The resolution decreases by a factor of 2 at each mipmap level.
*   **Implicit Octree:** The hierarchy of the octree is not stored as nodes but is implicit in the mipmap chain. Level $L$ of the mipmap corresponds to the $L$-th level of the octree.

**Steps:**
1.  **Texture Generation:** Create a 3D texture with sufficient resolution to cover the scene bounds. Generate mipmap levels using standard downsampling (e.g., averaging or max-pooling) across the 3D volume.
2.  **Ray Initialization:** For each pixel, compute the ray origin and direction in world space.
3.  **Mipmap Traversal:** Instead of traversing an octree, the ray traverses the mipmap chain. The ray starts at the highest resolution level (level 0) or a level determined by the ray's distance to the camera (LOD selection).
4.  **Direct Indexing:** Because the texture is a world-space representation, the ray's world position can be directly mapped to texture coordinates. No inverse transformation or octree node lookup is required to find the voxel data.
5.  **Sampling:** Use hardware texture sampling functions (e.g., `texture()` in GLSL/HLSL) to fetch values. The hardware automatically performs quadrilinear interpolation across the 3D voxel grid and handles mipmap LOD selection [S1, unofficial].
6.  **Compositing:** Accumulate color and opacity along the ray using standard volume rendering integration (e.g., front-to-back or back-to-front compositing).

**Formulas:**
*   **Texture Coordinate Mapping:** Given a ray position $\mathbf{p}$ in world space, and texture bounds $[\mathbf{b}_{min}, \mathbf{b}_{max}]$, the normalized texture coordinate $\mathbf{u}$ is:
    $$ \mathbf{u} = \frac{\mathbf{p} - \mathbf{b}_{min}}{\mathbf{b}_{max} - \mathbf{b}_{min}} $$
*   **LOD Selection:** The mipmap level $L$ is typically determined by the derivative of the texture coordinate with respect to screen space, or by the distance of the ray origin from the camera, ensuring that distant rays sample lower-resolution levels [S1, unofficial].

**Parameters:**
*   **Texture Resolution:** Must be large enough to cover the scene. Typical values depend on scene size and required detail, but often require power-of-two dimensions (e.g., $1024^3$, $2048^3$).
*   **Mipmap Levels:** $\lfloor \log_2(\max(\text{width}, \text{height}, \text{depth})) \rfloor + 1$.

**Edge Cases and Pitfalls:**
*   **Memory Consumption:** The primary pitfall is the immense memory required to store the entire volume, including empty space, in physical memory [S1, unofficial].
*   **Boundary Conditions:** Rays outside the texture bounds must be handled (e.g., treated as empty or clamped).
*   **Precision:** Floating-point precision in world-space to texture-coordinate conversion may cause artifacts at very large scales.

## Subtopics

### Solid Texturing
Solid texturing in this context refers to the generation of procedural textures or noise directly within the 3D texture space, rather than sampling from a pre-computed density field. This allows for infinite resolution detail without increasing memory usage, as the texture is generated on-the-fly or baked into the dense structure. It is chosen when procedural detail is preferred over sampled data, but still suffers from the memory overhead of the dense 3D texture structure [S1, unofficial].

### Sparse Textures
Sparse Textures are a variant that addresses the memory impracticality of dense 3D textures. By using partially-resident textures (e.g., via the `AMD_sparse_texture` OpenGL extension), regions of the texture corresponding to empty or constant space are marked as non-resident and do not consume physical memory [S1, unofficial]. This allows the system to maintain the simplicity of dense texture indexing while achieving memory efficiency comparable to sparse octree approaches. It is chosen when memory bandwidth and capacity are critical constraints, but the scene has large uniform or empty regions.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per voxel access due to direct indexing. Mipmap LOD selection is handled by hardware.
*   **Memory Complexity:** $O(N)$ where $N$ is the total number of voxels in the bounding box, including empty space. This is significantly higher than sparse methods for sparse scenes.
*   **Measured Performance:** Performance is limited by memory bandwidth and capacity. On modern GPUs, dense 3D textures can achieve high throughput for dense volumes but fail for large, sparse scenes due to out-of-memory errors [S1, unofficial].
*   **Strengths:** Simple implementation; no explicit octree traversal logic; automatic quadrilinear interpolation; no need to store redundant neighbor voxels; straightforward mipmap generation.
*   **Limitations:** High memory consumption; impractical for large sparse scenes; no inherent anti-aliasing beyond mipmap filtering (which may blur details); fixed resolution.
*   **When to Use:** Dense volumes where memory is not a constraint; scenes with minimal empty space; when implementation simplicity is prioritized over memory efficiency.
*   **When Not to Use:** Large sparse scenes; scenes with limited GPU memory; when dynamic resolution adaptation is required.

## Background
Dense 3D Texture Voxelization was presented as an alternative to the GigaVoxels system in the context of real-time voxel rendering. It was discussed in blog posts analyzing GigaVoxels and sparse texture techniques, highlighting the trade-offs between explicit sparse data structures and implicit dense texture representations [S1, unofficial]. The approach leverages existing GPU hardware features for 3D texture sampling and mipmap generation, which have been standard since the early 2000s.
