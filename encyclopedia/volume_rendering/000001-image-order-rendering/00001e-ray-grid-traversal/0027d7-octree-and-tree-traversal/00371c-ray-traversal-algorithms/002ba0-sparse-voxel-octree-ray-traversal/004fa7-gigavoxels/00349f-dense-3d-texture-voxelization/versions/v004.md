# Dense 3D Texture Voxelization

Also called: Implicit Octree via Mipmaps, Mipmapped 3D Texture Volume Rendering

## Overview
Dense 3D Texture Voxelization is an alternative to GigaVoxels where the entire scene, including empty space, is encoded into a very large mip-mapped 3D texture [S1, unofficial]. It solves the problem of managing sparse voxel data structures by replacing the explicit octree with an implicit one defined by the mipmap levels of the 3D texture. Unlike GigaVoxels, which requires a separate octree data structure and complex neighbor handling, this method allows rays to traverse the mipmap chain directly and index into voxel data using world-space coordinates [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (or procedural definition) representing the scene geometry and material properties.
*   **Output:** A mip-mapped 3D texture resource resident in GPU memory.

**Data Structures:**
The core data structure is a standard 3D texture array with multiple mip levels.
*   **Layout:** The texture is organized in world space. Level 0 contains the highest resolution voxels. Each subsequent level $L$ contains a downsampled version of the previous level, typically by a factor of 2 in each dimension.
*   **Implicit Octree:** The hierarchy of the octree is implicit in the mipmap chain. Level $L$ corresponds to the nodes at depth $L$ of the conceptual octree.
*   **No Neighbor Padding:** Unlike brick-based approaches, bricks are spatially aligned in the scene. Redundant neighbor voxels are not stored because the texture coordinates provide immediate access to adjacent cells [S1, unofficial].

**Algorithm Steps:**
1.  **Voxelization/Generation:** The scene is voxelized into a dense 3D grid. For each voxel $(x, y, z)$, the density and color values are computed.
    *   If using procedural texturing (Solid Texturing), the value is assigned by evaluating a procedural function $f(x, y, z)$ at the voxel center [S2, book].
2.  **Mipmap Generation:** Generate the mipmap chain. Since the data is dense and aligned, filtering is straightforward. Each level $L+1$ is generated by downsampling level $L$, typically using box filtering or trilinear interpolation [S1, unofficial].
3.  **Ray Traversal:** For each pixel, cast a ray into the scene.
    *   Start at the highest resolution level (Level 0).
    *   Determine the intersection of the ray with the current voxel at the current mip level.
    *   If the ray exits the current voxel or the current voxel is empty/transparent, advance to the next mip level (coarser resolution).
    *   Continue until the ray exits the volume or a non-empty voxel is found.
4.  **Sampling:** Sample the 3D texture at the ray's position.
    *   Use hardware texture sampling (e.g., `texture()` call).
    *   The hardware automatically performs quadrilinear interpolation (trilinear in space + mipmap LOD selection) based on the ray's derivative or explicit LOD calculation [S1, unofficial].
5.  **Compositing:** Accumulate color and opacity along the ray using standard volume rendering integration (e.g., front-to-back or back-to-front compositing) [S1, unofficial].

**Formulas:**
*   **Mipmap Level Selection:** The LOD $l$ for a ray at position $\mathbf{p}$ with direction $\mathbf{d}$ can be estimated by the screen-space derivative or the distance to the camera. A common approximation is:
    $$ l = \log_2 \left( \frac{\text{voxel\_size}}{\text{pixel\_size}} \right) $$
    where $\text{pixel\_size}$ is the size of the pixel footprint on the voxel grid at the current depth.
*   **Quadrilinear Interpolation:** The value $V$ at position $\mathbf{p}$ is computed by interpolating the 8 surrounding voxels in the selected mip level, weighted by the distance to each corner [S1, unofficial].

**Parameters:**
*   **Resolution:** The base resolution of the 3D texture. Must be a power of 2.
*   **Mipmap Levels:** Determined by the base resolution. Typically $\log_2(\text{base\_resolution}) + 1$ levels.

**Edge Cases and Pitfalls:**
*   **Memory Consumption:** The primary pitfall is the immense memory required to store the entire scene, including empty space. Most scenes are sparse, making dense textures impractical for large volumes [S1, unofficial].
*   **Empty Space:** Empty space must still be backed by physical memory in a standard dense texture, leading to significant waste [S1, unofficial].
*   **Boundary Conditions:** Ensure texture coordinates are clamped or wrapped correctly to avoid sampling artifacts at the volume boundaries.

## Subtopics

### Solid Texturing
Solid texturing is a technique where a procedural function or 3D map models the color of objects in 3D space [S2, book]. It assigns values to voxels during voxelization or evaluates the function during rendering at ray sampling locations to enrich volume datasets without increasing stored resolution [S2, book].
*   **Voxelization Phase:** Each voxel belonging to the objects is assigned a value by the texturing function or 3D map, which is stored as part of the voxel information [S2, book].
*   **Rendering Phase:** The texturing function is evaluated at ray sampling locations to add detail without increasing the stored resolution of the dataset [S2, book].
*   **Basis Functions:** Common functions include noise (e.g., Perlin noise), turbulence, and n-th closest distance [S2, book].

## Operating characteristics
*   **Time Complexity:** Ray traversal is $O(\log N)$ where $N$ is the number of voxels along the ray, due to the mipmap hierarchy. Sampling is $O(1)$ per step.
*   **Memory Complexity:** $O(N)$ where $N$ is the total number of voxels in the dense grid. This includes empty space, making it inefficient for sparse scenes.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Does not scale well with scene size due to memory constraints.
*   **Strengths:** Simplifies implementation by removing the need for an explicit octree and neighbor management. Hardware-accelerated interpolation and LOD selection.
*   **Limitations:** High memory usage. Impractical for large, sparse scenes.
*   **When to Use:** Small, dense volumes where memory is not a constraint and implementation simplicity is prioritized.
*   **When Not to Use:** Large, sparse scenes. Use GigaVoxels or Sparse Textures instead.

## Background
Dense 3D Texture Voxelization was proposed as an alternative to the GigaVoxels system to simplify the rendering pipeline by removing the explicit octree data structure [S1, unofficial]. It leverages existing GPU hardware features for 3D texture sampling and mipmap generation. The concept of solid texturing, often used in conjunction with such voxelization, has roots in procedural modeling and volume graphics, with basis functions like Perlin noise being well-established [S2, book].
