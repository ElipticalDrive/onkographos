# Sparse Voxel Octree Ray Traversal

Also called: Sparse Voxel Octree Traversal, SVO Traversal, Sparse Voxel Octree Raycasting, Sparse Voxel Octree Tracing

## Overview
Sparse Voxel Octree (SVO) Ray Traversal is a hierarchical ray-casting technique that renders 3D voxel data stored in a sparse octree structure by traversing the tree along ray paths to find occupied cells [S2, S4, S6, unofficial]. It solves the problem of efficiently rendering large, complex voxel scenes by skipping empty space using axis-aligned slab intersection logic, avoiding the need to sample every voxel [S1, S6, S8, unofficial]. Unlike standard rasterization which requires mesh generation and draw calls per chunk, SVO ray tracing renders the entire scene with a single draw call (e.g., a fullscreen triangle) and no vertex buffers [S6, S8, unofficial]. It differs from its siblings, such as [Hermite Data Computation via Bisection](822-hermite-data-computation-via-bisection.md) or [Octree Path Computation](897-octree-path-computation.md), by explicitly managing hierarchical descent and backtracking to handle the sparse nature of the data, often using parallel arrays or explicit stacks to simulate recursion on the GPU [S4, S6, S8, unofficial].

## How it works
The method traverses a Sparse Voxel Octree to find the first intersection with a solid voxel. The octree is stored as a linear array of nodes, where internal nodes point to children and leaf nodes contain voxel data (color/density). The traversal uses a stack to manage backtracking when the ray exits a subtree [S6, S8, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Ray: Origin $O$, Direction $D$ (normalized).
    *   SVO Data: A linear array of nodes (uints or structs).
    *   Camera Parameters: View matrix, projection matrix, viewport dimensions.
*   **Outputs:**
    *   Hit position, normal, and color/density of the first occupied leaf node intersected by the ray.
    *   Background color if no hit is found.

### Data Structures
The SVO is typically stored in a single buffer (e.g., `std430` in GLSL or `Buffer` in Vulkan) [S4, S6, S8, unofficial].

**Node Layout (Variant 1: Bit-packed uint, [S6, S8, unofficial]):**
Each node is a 32-bit unsigned integer (`uint`).
*   **Bit 31 (MSB):** Internal Node Flag. If 1, the node is internal; if 0, it is a leaf.
*   **Bits 0-30:** Child Index.
    *   If Internal: Points to the index of the first child in the linear array.
    *   If Leaf: Points to the index of the color data (or is a direct color value in some variants [S8, unofficial]).
*   **Color Data:** Stored in a separate buffer or interleaved. In [S6, unofficial], a second `uint` per node stores the color (RGBA). In [S8, unofficial], leaf nodes may store color directly in the lower bits if the MSB is 0.

**Node Layout (Variant 2: Struct, [S3, unofficial]):**
*   `childrenStartIndex`: `int` (index of first child in array).
*   `data`: `int` (bitfield: bit 0 = has data, bits 1-31 = arbitrary/child pointer).

**Stack Structure (for backtracking, [S8, unofficial]):**
```python
struct StackEntry:
    node_address: uint
    frontal_mask: uint  # Tracks which axes have been stepped
    t_min: float      # Current entry distance
    t_corner: vec3    # Exit distances for current node
```

### Pseudocode
The following implementation combines the slab intersection logic from [S1, S6, S8, unofficial] with the iterative stack-based traversal from [S6, S8, unofficial]. It handles empty space skipping and backtracking.

```python
import math

# Constants
EPS = 1e-4
MAX_DEPTH = 32

def sign(x):
    return 1.0 if x >= 0.0 else -1.0

def abs(x):
    return x if x >= 0.0 else -x

def min(a, b):
    return a if a < b else b

def max(a, b):
    return a if a > b else b

def ray_traverse_svo(ray_origin, ray_direction, svo_buffer, svo_color_buffer, viewport_size, camera_matrix):
    """
    ray_origin: vec3
    ray_direction: vec3 (normalized)
    svo_buffer: array of uint (nodes)
    svo_color_buffer: array of vec4 (colors)
    viewport_size: vec2 (width, height)
    camera_matrix: mat4 (inverse view-projection for ray gen)
    """
    
    # 1. Ray Generation (if not provided)
    # Assuming ray_origin and ray_direction are passed. 
    # If generating from pixel:
    # uv = (gl_FragCoord.xy * 2. / viewport_size.y) - vec2(1.)
    # direction = normalize(camera_matrix * vec4(uv * fov, 1.0, 1.0))
    
    # 2. Precompute Ray Coefficients (Slab Method)
    # Avoid division by zero by clamping small components
    d = ray_direction
    if abs(d.x) < EPS: d.x = sign(d.x) * EPS
    if abs(d.y) < EPS: d.y = sign(d.y) * EPS
    if abs(d.z) < EPS: d.z = sign(d.z) * EPS
    
    inv_d = 1.0 / d
    tx_coef = -inv_d.x
    ty_coef = -inv_d.y
    tz_coef = -inv_d.z
    
    tx_bias = tx_coef * ray_origin.x
    ty_bias = ty_coef * ray_origin.y
    tz_bias = tz_coef * ray_origin.z
    
    # Determine direction masks for octant selection
    # Bit 0: X, Bit 1: Y, Bit 2: Z
    dir_mask = 0
    if d.x > 0: dir_mask ^= 1
    if d.y > 0: dir_mask ^= 2
    if d.z > 0: dir_mask ^= 4
    
    # 3. Initialization
    # Start at root (index 0). Root bounds are typically [-1, 1]^3 or similar.
    # For this generic implementation, we assume the root covers the world space
    # and we compute initial t_min/t_max against the root box.
    # Let's assume root box is [-1, 1]^3 for simplicity, or passed as param.
    root_min = vec3(-1.0)
    root_max = vec3(1.0)
    
    # Compute t_min and t_max for root box
    t_min = max(max((root_min.x - ray_origin.x) * inv_d.x, 
                    (root_min.y - ray_origin.y) * inv_d.y), 
                (root_min.z - ray_origin.z) * inv_d.z)
    t_max = min(min((root_max.x - ray_origin.x) * inv_d.x, 
                    (root_max.y - ray_origin.y) * inv_d.y), 
                (root_max.z - ray_origin.z) * inv_d.z)
    
    if t_min > t_max or t_max < 0.0:
        return vec4(0.0) # No hit
    
    # Stack for backtracking
    stack = []
    depth = 0
    
    # Current state
    node_idx = 0
    scale = 2.0 # Initial size of root (assuming root is 2x2x2 centered at 0)
    step = scale * 0.5
    center = vec3(0.0) # Center of root
    
    # Initial corner position relative to ray
    # Determine which octant the ray enters
    # t_center is time to reach center
    t_center = (center - ray_origin) * inv_d
    
    # Frontal mask: bits set for axes where t_center > t_min (ray hasn't passed center yet? 
    # Actually, frontal_mask usually tracks which boundaries we are "in front of")
    # Let's use the logic from [S8, unofficial]: frontal_mask bits indicate if we are in the "positive" half of the split
    frontal_mask = 0
    if t_center.x > t_min: frontal_mask ^= 1
    if t_center.y > t_min: frontal_mask ^= 2
    if t_center.z > t_min: frontal_mask ^= 4
    
    # Corner position (entry point into the current node's sub-box)
    corner = center
    if not (frontal_mask & 1): corner.x -= step
    if not (frontal_mask & 2): corner.y -= step
    if not (frontal_mask & 4): corner.z -= step
    
    # Compute t values for the corner (exit times from the current node's perspective)
    t_corner = (corner - ray_origin) * inv_d
    
    # 4. Traversal Loop
    while True:
        # Load Node
        value = svo_buffer[node_idx]
        
        # Check if Leaf
        if (value & 0x80000000) == 0:
            # Leaf Node
            # Fetch color
            # In [S6, unofficial], color is in a separate buffer at index 'value'
            # In [S8, unofficial], value might be the color index or direct color
            color = svo_color_buffer[value] 
            return color # First hit found
            
        # Internal Node
        # Push state to stack for backtracking
        if depth >= MAX_DEPTH:
            return vec4(0.0) # Stack overflow
            
        stack.append({
            'node_idx': node_idx,
            'frontal_mask': frontal_mask,
            't_min': t_min,
            't_corner': t_corner,
            'scale': scale,
            'step': step
        })
        depth += 1
        
        # Descend to child
        # Child index is determined by frontal_mask and dir_mask
        # The child we enter is the one corresponding to the current octant
        child_idx = (value & 0x7FFFFFFF) + (frontal_mask ^ dir_mask)
        node_idx = child_idx
        
        # Update scale and step
        scale *= 0.5
        step = scale * 0.5
        
        # Update center of the new child node
        # The new center is the old corner
        new_center = corner
        
        # Update t_min to the exit time of the current node (which is the entry to the child)
        # Actually, t_min should be updated to the max of the current t_min and the t values of the boundaries we crossed.
        # In the slab method, t_min is the entry into the current node.
        # When we descend, the new t_min is the t value of the face we entered.
        # This is implicitly handled by t_corner updates in the "Advance" phase, 
        # but for descent, we need to ensure t_min is valid for the new node.
        # The new node's entry is the old node's exit in the direction of travel.
        # However, standard SVO traversal [S6, S8, unofficial] updates t_min by advancing the corner.
        
        # Reset frontal_mask for the new node
        new_frontal_mask = 0
        
        # Determine new corner and frontal_mask based on t_center relative to new t_min
        # Note: t_min for the child is the t value of the face we just crossed.
        # We need to recompute t_center for the new center.
        t_center = (new_center - ray_origin) * inv_d
        
        # Check if t_center is beyond t_min? 
        # Actually, the new node's "center" is the old corner.
        # The new t_min is the t value of the boundary we entered.
        # Let's use the logic from [S8, unofficial]:
        # t_min is updated in the "Advance" loop. For descent, we just set up the next iteration.
        
        # Compute new corner based on new frontal_mask
        # But we don't know the new frontal_mask yet.
        # The new frontal_mask is determined by whether t_center > t_min (for the new node's bounds).
        # But t_min for the new node is the t value of the entry face.
        
        # Let's simplify: The new node's bounds are defined by the new center and new step.
        # The ray enters the new node at t_min (which is the t value of the entry face of the parent).
        # We need to find which octant of the new node the ray is in.
        # This is determined by the position of the ray at t_min relative to the new center.
        
        # Position at t_min
        pos_at_tmin = ray_origin + ray_direction * t_min
        
        # Determine octant relative to new_center
        new_frontal_mask = 0
        if pos_at_tmin.x > new_center.x: new_frontal_mask ^= 1
        if pos_at_tmin.y > new_center.y: new_frontal_mask ^= 2
        if pos_at_tmin.z > new_center.z: new_frontal_mask ^= 4
        
        # Update corner to be the entry corner of the new node
        new_corner = new_center
        if not (new_frontal_mask & 1): new_corner.x -= step
        if not (new_frontal_mask & 2): new_corner.y -= step
        if not (new_frontal_mask & 4): new_corner.z -= step
        
        # Update t_corner for the new node
        t_corner = (new_corner - ray_origin) * inv_d
        
        # Update t_min? 
        # The new t_min is the t value of the entry face.
        # This is already in t_min from the previous step? 
        # No, t_min was the entry into the PARENT.
        # The entry into the CHILD is the same point, so t_min is still valid as the entry time.
        # However, we need to ensure t_min is <= t_max of the child.
        
        # Continue loop
        continue
        
    # Backtracking logic is handled in the "Advance" phase or if we hit a boundary.
    # The above descent logic assumes we always descend. 
    # We need an "Advance" phase to skip empty space.
    
    # Re-structure: The loop should check if the current node is empty or if we need to advance.
    # The standard algorithm [S8, unofficial] has an inner loop for "Advance" (empty space skipping).
    
    # Let's rewrite the loop to include Advance and Pop.
    
    # ... (See detailed steps below)
```

**Detailed Step-by-Step Algorithm (Based on [S6, S8, unofficial]):**

1.  **Initialize:**
    *   Compute `tx_coef`, `ty_coef`, `tz_coef` and `tx_bias`, `ty_bias`, `tz_bias` from ray origin and direction.
    *   Compute `dir_mask` from ray direction signs.
    *   Set `node_idx = 0` (root).
    *   Set `scale = 2.0` (root size), `step = 1.0`.
    *   Set `center = (0,0,0)`.
    *   Compute `t_min` and `t_max` for the root box. If `t_min > t_max`, return background.
    *   Compute `t_center = (center - origin) * inv_dir`.
    *   Compute `frontal_mask`: bit $i$ is 1 if `t_center[i] > t_min`.
    *   Compute `corner`: start at `center`, subtract `step` in axes where `frontal_mask` bit is 0.
    *   Compute `t_corner = (corner - origin) * inv_dir`.

2.  **Traversal Loop:**
    *   **Load Node:** `value = svo_buffer[node_idx]`.
    *   **Check Leaf:** If `value & 0x80000000 == 0`, it is a leaf. Return color from `svo_color_buffer[value]`.
    *   **Internal Node:**
        *   **Push:** Save current state (`node_idx`, `frontal_mask`, `t_min`, `t_corner`, `scale`, `step`) to stack. Increment `depth`.
        *   **Descend:**
            *   `child_idx = (value & 0x7FFFFFFF) + (frontal_mask ^ dir_mask)`.
            *   `node_idx = child_idx`.
            *   `scale *= 0.5`, `step = scale * 0.5`.
            *   `center = corner`.
            *   Recompute `t_center = (center - origin) * inv_dir`.
            *   Recompute `frontal_mask`: bit $i$ is 1 if `t_center[i] > t_min`.
            *   Recompute `corner`: start at `center`, subtract `step` in axes where `frontal_mask` bit is 0.
            *   Recompute `t_corner = (corner - origin) * inv_dir`.
            *   Continue to next iteration.

3.  **Empty Space Skipping (Advance):**
    *   This phase is triggered when we are at a node but need to skip to the next potentially occupied node. In the [S8, unofficial] algorithm, this is integrated into the loop. If the current node is empty (or we are just traversing), we advance `t_min` to `t_corner_max = min(t_corner.x, t_corner.y, t_corner.z)`.
    *   Determine `step_mask`: bits set for axes where `t_corner[i] <= t_corner_max`.
    *   Update `t_min = t_corner_max`.
    *   Update `t_corner`: for axes in `step_mask`, add `sign(dir[i]) * step / dir[i]` to `t_corner[i]`.
    *   Update `frontal_mask`: `frontal_mask ^= step_mask`.
    *   If `(frontal_mask & step_mask) == 0`, break inner loop (backtrack needed).

4.  **Backtracking (Pop):**
    *   If the inner loop breaks (no more axes to step in current direction), decrement `depth`.
    *   If `depth < 0`, return background (no hit).
    *   Restore state from `stack[depth]`.
    *   Continue outer loop.

### Parameters
*   `mRootRadius`: Radius of the root bounding box [S1, unofficial].
*   `HRDWTREE_MAX_DEPTH`: Maximum traversal depth, typically 16 [S2, unofficial].
*   `S_MAX`: Maximum scale, typically 23 (float mantissa bits) [S6, unofficial].
*   `EPS`: Epsilon for ray direction clamping, typically $10^{-4}$ [S6, S8, unofficial].
*   `MAX_DEPTH`: Stack size, typically 32 [S8, unofficial].

### Edge Cases and Pitfalls
*   **Boundary Precision:** If the ray position lies exactly on a boundary, child index selection can be ambiguous. Add a small epsilon (`0.1 * dir`) to break ties [S1, unofficial].
*   **Zero Direction Components:** Ray directions with zero components cause division by zero. Clamp components to `EPS` or `-EPS` based on sign [S8, unofficial].
*   **Stack Overflow:** The traversal uses a fixed-size stack. If the octree depth exceeds the stack size, backtracking fails. Ensure `MAX_DEPTH` is sufficient for the scene [S8, unofficial].
*   **Texture Repeat Artifacts:** If using texture lookup for SVO, ensure the lookup point is within the unit cube to avoid wrapping. Intersect with unit box and advance if outside [S2, unofficial].
*   **Z-Fighting:** When stepping past a boundary, multiply the intersection distance by `1.0001` to avoid gaps or z-fighting [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal to the first hit, where $N$ is the number of voxels, due to the hierarchical nature of the octree. However, in the worst case (dense scene), it can approach $O(N)$.
*   **Memory Complexity:** $O(N)$ for storing the octree nodes, but significantly less than a dense voxel grid due to sparsity. The DAG variant reduces this further [S7].
*   **Measured Performance:** Renders scenes like Stanford Dragon (512^3) and 512 tori (128^3 each, >1 billion voxels) at 20 FPS at 720p on AMD 5700 [S6, unofficial].
*   **Strengths:** Efficient empty space skipping, implicit LOD, single draw call rendering, no mesh generation required.
*   **Limitations:** Dynamic updates are inefficient, often requiring full octree regeneration [S3, unofficial]. Memory constraints at high resolutions can limit applicability [S7].
*   **When to Use:** Large, static voxel scenes, real-time rendering on GPU, scenes with significant empty space.
*   **When Not to Use:** Highly dynamic scenes requiring frequent updates, scenes with very high density where the octree overhead outweighs benefits.

## Background
Sparse Voxel Octrees were introduced as a hierarchical data structure for raycasting, allowing for Level-of-Detail rendering by controlling traversal depth based on viewer distance [S3, unofficial]. The technique is based on the work of Laine and Karras (2011) [S6, unofficial]. It is used in various real-time rendering engines and research projects, such as the mxbrt/svo repository [S6, unofficial] and the zazen engine [S4, unofficial]. The method is particularly useful for rendering large-scale voxel environments, such as those found in games like Minecraft, but with higher fidelity and dynamic lighting capabilities.
