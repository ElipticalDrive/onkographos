# Compositing Tree Rendering

Also called: Incremental Compositing, Modified subtree rendering, Partial image compositing, Selective Subtree Rendering

## Overview
Compositing Tree Rendering is a time-domain optimization strategy for volume rendering that avoids re-rendering unmodified data by retaining and reusing partial images from previous frames. It solves the high computational cost of rendering time-varying volume data by identifying modified subtrees in a compressed octree and composing them with cached partial images of unchanged regions to form the final image [S1, S2, unofficial]. Unlike standard ray casting which re-evaluates the entire volume for every frame, this method leverages spatial coherence in time, significantly reducing rendering time when only small portions of the volume change between timesteps [S1, S2, unofficial].

## How it works
The method operates on a sequence of compressed octrees representing time-varying volume data. It maintains a parallel "compositing tree" structure that mirrors the compressed octree but stores rendered image data instead of volume values.

### Inputs and Outputs
*   **Input:** A sequence of compressed octrees $T_t$ for time steps $t=0, 1, \dots$. Each node in the octree contains metadata indicating whether the subvolume is constant (uniform) or variable, and pointers to children.
*   **Output:** A final composite image for each time step $t$.

### Data Structures
**Compositing Tree Structure:**
A pointer-based octree with the same topology as the compressed octree [S1, S2, unofficial].
*   **Leaf Node:** Contains a partial image (color and opacity buffer) rendered directly from the corresponding leaf in the compressed octree.
*   **Interior Node:** Contains a partial image which is the result of compositing the images of all its children.
*   **Root Node:** Contains the complete image for the current time step.

### Algorithm Steps
1.  **Initial Render ($t=0$):** Render the first tree $T_0$ completely using standard ray casting. Populate the compositing tree $C_0$ such that every leaf contains the rendered partial image for its subvolume, and every interior node contains the composite of its children. The root of $C_0$ is the final image for $t=0$ [S1, S2, unofficial].

2.  **Identify Changes ($t > 0$):** Compare the current compressed octree $T_t$ with the previous one $T_{t-1}$ (or the structure of the compositing tree). Identify the set of modified subtrees. A subtree is modified if its leaf data has changed or if the structure of constant/uniform blocks has changed [S1, S2, unofficial].

3.  **Render Modified Subtrees:** For each identified modified subtree:
    *   Traverse the subtree.
    *   At the leaves of the modified subtree, render the partial images using the current volume data.
    *   **Optimization for Constant Subvolumes:** If a leaf represents a uniform block with constant color $C$ and constant opacity $a$, do not perform ray casting or trilinear interpolation. Calculate the accumulated color directly using the number of samples $n$ along the ray through that block [S1, S2, unofficial].
    *   Composite the results up the new branch to form the partial image for the root of the modified subtree [S1, S2, unofficial].

4.  **Splice and Recomposite:**
    *   Create a new branch in the compositing tree representing the modified data.
    *   Splice this new branch into the compositing tree, replacing the old branch corresponding to the modified region [S1, S2, unofficial].
    *   The leaves in the unchanged parts of the tree retain their cached partial images.
    *   Recomposite the ancestors of the spliced branch. For each interior node in the path from the modified leaves to the root, compute its new partial image by compositing its children's images (some new, some cached) [S1, S2, unofficial].

5.  **Final Image:** The image stored at the root of the compositing tree is the final rendered image for time step $t$ [S1, S2, unofficial].

### Formulas
**General Volume Rendering Integral:**
The accumulated color $C$ up to $n$ sample points on a ray is given by the front-to-back compositing equation [S1, S2, unofficial]:
$$ C = \sum_{i=1}^{n} C_i \alpha_i \prod_{j=1}^{i-1} (1 - \alpha_j) $$
Where:
*   $C_i$ is the color at sample $i$.
*   $\alpha_i$ is the opacity at sample $i$.
*   The term $\prod_{j=1}^{i-1} (1 - \alpha_j)$ represents the transmittance from the eye to sample $i$.

**Simplified Formula for Constant Subvolumes:**
If a subvolume has constant color $C$ and constant opacity $a$ for all $n$ samples, the summation simplifies to a geometric series [S1, S2, unofficial]:
$$ C_{total} = C \cdot a \cdot \frac{1 - (1-a)^n}{1 - (1-a)} = C \cdot a \cdot \frac{1 - (1-a)^n}{a} = C (1 - (1-a)^n) $$
*Note: Source [S1, unofficial] presents a garbled formula $C \cdot a (1 - a^{n-1}) / (1-a)$ which is inconsistent with standard compositing. Source [S2, unofficial] presents $C \frac{1-(1-a)^n}{1-(1-a)}$. The standard derivation for constant opacity $a$ yields $C(1-(1-a)^n)$. The sources agree that $n$ (number of samples) is the only required parameter, avoiding coordinate calculation and interpolation [S1, S2, unofficial].*

### Pseudocode
```python
def render_time_step(compressed_octree_t, compositing_tree_t_minus_1):
    """
    Renders the volume for time step t using incremental compositing.
    
    Args:
        compressed_octree_t: The compressed octree for the current time step.
        compositing_tree_t_minus_1: The compositing tree from the previous time step.
        
    Returns:
        The final composite image (root image of the new compositing tree).
    """
    # Initialize new compositing tree structure identical to compressed_octree_t
    new_compositing_tree = copy_structure(compressed_octree_t)
    
    # Identify modified subtrees by comparing compressed_octree_t with the 
    # structure/data of compositing_tree_t_minus_1
    modified_subtrees = identify_modified_subtrees(compressed_octree_t, compositing_tree_t_minus_1)
    
    # Cache unchanged leaves from previous frame
    cache_unchanged_leaves(compressed_octree_t, compositing_tree_t_minus_1, new_compositing_tree)
    
    # Render and composite modified subtrees
    for subtree_root in modified_subtrees:
        render_subtree(subtree_root, compressed_octree_t, new_compositing_tree)
        
    # Recomposite ancestors of modified subtrees up to the root
    recomposite_ancestors(modified_subtrees, new_compositing_tree)
    
    return new_compositing_tree.root.image

def render_subtree(node, compressed_octree, compositing_tree):
    """
    Recursively renders a modified subtree.
    """
    if node.is_leaf():
        # Render leaf
        if node.is_constant():
            # Optimization: Use closed-form solution for constant subvolume
            n = get_sample_count(node)
            C = node.constant_color
            a = node.constant_opacity
            # Formula: C * (1 - (1-a)^n)
            partial_image = compute_constant_color(C, a, n)
        else:
            # Standard ray casting for variable data
            partial_image = ray_cast_leaf(node, compressed_octree)
        
        compositing_tree[node.id].image = partial_image
    else:
        # Recursively render children
        for child in node.children:
            render_subtree(child, compressed_octree, compositing_tree)
        
        # Composite children images
        children_images = [compositing_tree[child.id].image for child in node.children]
        compositing_tree[node.id].image = composite_images(children_images)

def cache_unchanged_leaves(compressed_octree, old_compositing_tree, new_compositing_tree):
    """
    Copies partial images from the old compositing tree to the new one
    for leaves that have not changed.
    """
    for leaf in compressed_octree.leaves:
        if not is_modified(leaf, old_compositing_tree):
            new_compositing_tree[leaf.id].image = old_compositing_tree[leaf.id].image

def recomposite_ancestors(modified_subtrees, compositing_tree):
    """
    Recomposites the images up the tree from the modified leaves to the root.
    """
    # Collect all nodes that need recompositing (ancestors of modified leaves)
    nodes_to_recomposite = set()
    for subtree_root in modified_subtrees:
        current = subtree_root
        while current is not None:
            nodes_to_recomposite.add(current)
            current = current.parent
            
    # Sort nodes by depth (leaves first, then parents)
    sorted_nodes = sort_by_depth(nodes_to_recomposite)
    
    for node in sorted_nodes:
        if node.is_leaf():
            continue # Already rendered
        children_images = [compositing_tree[child.id].image for child in node.children]
        compositing_tree[node.id].image = composite_images(children_images)
```

### Parameters and Edge Cases
*   **Viewing Position:** The optimization assumes a fixed viewing position. If the camera moves, the ray paths change, invalidating the cached partial images. In this case, the entire tree must be rerendered and a new compositing tree created [S1, S2, unofficial].
*   **Temporal Navigation:** To support random access to different time steps, complete compositing trees must be saved at regular intervals. The cost of saving these trees must be balanced against the rendering savings [S1, S2, unofficial].
*   **Boundary Rendering:** Octree leaves represent uniform blocks, but boundaries between blocks may have discontinuities. To avoid traversal overhead for boundary values, the original volume data is kept uncompressed, and the octree serves as a map into this data for boundary regions [S1, S2, unofficial].
*   **Back Subtree Approximation:** Due to opacity accumulation, front details may obscure back details. In front-to-back rendering, back subtrees may not be fully sampled. As an approximation, unchanged subtrees in the back are not re-rendered, which may introduce minor visual artifacts if the front opacity changes significantly [S1, S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of modified voxels/subtrees rather than the total volume size. Significant savings are achieved when temporal coherence is high (small changes between timesteps) [S1, S2, unofficial].
*   **Memory Complexity:** Requires storing the compositing tree, which holds partial images for all leaves. This increases memory usage compared to standard ray casting, as the entire volume's image data must be cached in the tree structure [S1, S2, unofficial].
*   **Performance:** Tests on datasets like "Turbulent Vortex Flow" (128^3, 100 timesteps) showed significant rendering time reductions due to tree merging and compression [S1, S2, unofficial].
*   **Strengths:** Drastic reduction in rendering time for time-varying data with high spatial and temporal coherence. Efficient handling of constant subvolumes.
*   **Limitations:** High memory overhead for caching images. Inefficient for dynamic camera views (requires full rerender). Overhead from tree traversal compared to direct volume rendering, offset by optimizations like early ray termination and constant subvolume formulas [S1, S2, unofficial].

## Background
Compositing Tree Rendering was introduced in the context of efficient encoding and rendering of time-varying volume data. It builds on compressed octree representations where data is grouped into uniform blocks. The method was developed to address the computational bottleneck of rendering large time-varying datasets, leveraging the fact that most of the volume remains unchanged between timesteps [S1, S2, unofficial].
