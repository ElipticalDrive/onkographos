# kD-Tree Traversal
Also called: K-d Tree Spatial Partitioning, Kd Backtrack Algorithm, Multi-dimensional binary search tree

## Overview
kD-Tree Traversal is a ray traversal algorithm for binary spatial partitioning structures where nodes split space using arbitrary axis-aligned planes, offering more flexible geometry adaptation than fixed-center octrees [S1, unofficial]. It solves the problem of efficiently intersecting rays with complex, non-uniform geometry distributions by recursively descending a binary tree, determining which child node (near or far) the ray intersects relative to the splitting plane, and performing early termination upon finding the first hit [S1, unofficial].

## How it works
**Inputs:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized), and a root node of the kD-tree [S2, unofficial].
**Outputs:** The distance $t_{hit}$ to the closest intersection with a primitive in the scene, or $\infty$ if no intersection is found [S2, unofficial].

**Data Structures:**
The kD-tree is a binary tree. Each node contains:
1.  **Splitting Plane:** Defined by an axis index $axis \in \{0, 1, 2\}$ (representing x, y, or z) and a split position $s$ along that axis [S2, unofficial].
2.  **Children:** Pointers to two child nodes (left and right) [S3, unofficial].
3.  **Primitives:** A list of geometry primitives (e.g., triangles) stored only in leaf nodes [S2, unofficial].
4.  **Bounding Box:** Implicitly defined by the path from the root. The root encloses the entire scene. Each child's bounding box is the parent's box clipped by the splitting plane [S2, unofficial].

**Construction:**
1.  Given a cell (axis-aligned BBox) and a list of primitives, choose an axis-aligned splitting plane perpendicular to one coordinate axis [S2, unofficial].
2.  Distribute geometry among the two children. Polygons straddling the plane must be assigned to both children [S2, unofficial].
3.  Recurse until a stopping criterion is met (e.g., max depth, number of objects, or cost function threshold) [S2, unofficial].
4.  **Splitting Plane Selection:** To minimize traversal cost, use the Surface-Area-Heuristic (SAH). Try all 3 axes. For each axis, evaluate the cost function at finite points (borders of bounding boxes of primitives) using a plane sweep. Choose the axis and split position with the minimum cost [S2, unofficial].
    *   **SAH Cost Function:**
        $$ C(B) = Area(B_1) \cdot N(B_1) + Area(B_2) \cdot N(B_2) $$
        where $Area(B_i)$ is the surface area of child box $i$ and $N(B_i)$ is the number of triangles in child box $i$. This assumes rays have a far-away origin and hit the root bounding volume [S2, unofficial].
    *   **Cost Ratio:** The ratio of time for one ray-primitive test ($t_i$) to one ray-splitting-plane intersection test ($t_t$) is typically $80:1$ [S2, unofficial].
    *   **Approximation:** For large scenes (>500,000 polygons), sort polygons into buckets and evaluate SAH only at bucket borders [S2, unofficial].

**Traversal Algorithm (Recursive):**
The traversal determines the intersection of the ray with the splitting plane to identify the "near" child (containing the ray origin) and the "far" child [S2, unofficial].

1.  **Leaf Check:** If the current node is a leaf, intersect the ray with each primitive in the node's object list. Discard intersections with $t > t_{max}$. Return the closest intersection $t_{hit}$ if found, otherwise return $\infty$ [S2, unofficial].
2.  **Splitting Plane Intersection:** Calculate $t_{split}$, the signed distance along the ray to the splitting plane of the current node.
    $$ t_{split} = \frac{s - o_{axis}}{d_{axis}} $$
    where $s$ is the split position, $o_{axis}$ is the ray origin component along the split axis, and $d_{axis}$ is the ray direction component along the split axis [S2, unofficial]. If $d_{axis} = 0$, the ray is parallel to the plane; handle as a special case by traversing only the child containing the origin [G].
3.  **Child Determination:** Let $near$ be the child containing the origin, and $far$ be the other child. The child index is determined by comparing $o_{axis}$ to $s$ and the sign of $d_{axis}$ [G].
4.  **Traversal Logic:**
    *   If $t_{split} > t_{max}$: The splitting plane is beyond the current search range. Traverse only the $near$ child with $t_{min}, t_{max}$ [S2, unofficial].
    *   If $t_{split} < t_{min}$: The splitting plane is before the current search range. Traverse only the $far$ child with $t_{min}, t_{max}$ [S2, unofficial].
    *   Otherwise ($t_{min} \le t_{split} \le t_{max}$): The ray intersects the splitting plane within the range. Recursively traverse the $near$ child with $t_{min}, t_{split}$. If the result $t_{hit} < t_{split}$, return $t_{hit}$ (early termination). Else, traverse the $far$ child with $t_{split}, t_{max}$ [S2, unofficial].

**Pseudocode:**
```python
def traverse_kd_tree(ray_origin, ray_direction, node, t_min, t_max):
    # 1. Leaf Handling
    if node.is_leaf:
        closest_t = float('inf')
        for primitive in node.primitives:
            t = intersect_ray_primitive(ray_origin, ray_direction, primitive)
            if t_min <= t < closest_t:
                closest_t = t
        return closest_t

    # 2. Splitting Plane Intersection
    axis = node.axis
    split_pos = node.split_position
    o_axis = ray_origin[axis]
    d_axis = ray_direction[axis]

    # Handle parallel ray case
    if d_axis == 0.0:
        # Ray is parallel to splitting plane; it never crosses it.
        # Traverse only the child containing the ray origin.
        if o_axis < split_pos:
            near_child = node.left
        else:
            near_child = node.right
        return traverse_kd_tree(ray_origin, ray_direction, near_child, t_min, t_max)

    t_split = (split_pos - o_axis) / d_axis

    # 3. Child Determination
    # Determine which child contains the ray origin
    if d_axis > 0:
        near_child = node.left if o_axis < split_pos else node.right
        far_child = node.right if o_axis < split_pos else node.left
    else: # d_axis < 0
        near_child = node.right if o_axis < split_pos else node.left
        far_child = node.left if o_axis < split_pos else node.right

    # 4. Traversal Logic
    if t_split > t_max:
        return traverse_kd_tree(ray_origin, ray_direction, near_child, t_min, t_max)
    elif t_split < t_min:
        return traverse_kd_tree(ray_origin, ray_direction, far_child, t_min, t_max)
    else:
        t_hit_near = traverse_kd_tree(ray_origin, ray_direction, near_child, t_min, t_split)
        if t_hit_near < t_split:
            return t_hit_near
        return traverse_kd_tree(ray_origin, ray_direction, far_child, t_split, t_max)
```

**Oversized Object Handling:**
If objects are very large (e.g., in architectural models), they can hinder the finding of good splitting planes [S2, unofficial].
1.  Before each splitting, filter out "oversized objects" [S2, unofficial].
2.  If many oversized objects exist, build a separate kD-tree for them [S2, unofficial].
3.  Otherwise, store them in a simple list attached to the node or scene [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Straddling Polygons:** In regular kD-trees, polygons straddling the splitting plane must be stored in both subtrees, leading to 2-3 times more pointers to triangles than triangles exist [S2, unofficial]. This increases memory usage and traversal time [S2, unofficial].
*   **Precision:** Floating-point precision issues can arise when calculating $t_{split}$, especially when the ray is nearly parallel to the splitting plane ($d_{axis} \approx 0$) [G].
*   **Boundary Conditions:** Ensure correct handling of ray origins exactly on the splitting plane by using consistent half-open interval logic or epsilon offsets [G].

## Subtopics

### [Hybrid Kd Tree Traversal](20234-hybrid-kd-tree-traversal.md)
Hybrid Kd Tree Traversal is a method for efficiently accessing heterogeneous volume data by organizing distinct brick types (e.g., dense grids, octrees, voxel lists) into a hierarchical Kd tree structure. It solves the problem of sparse or mixed-format volumes where a single uniform data structure would waste memory or require complex type-checking during ray traversal. Unlike its sibling Adaptive Kd Tree, which adapts subdivision based on data density, this method groups bricks by their storage format to enable specialized, type-specific access routines at the leaves.

### [Adaptive Kd Tree](20471-adaptive-kd-tree.md)
The Adaptive Kd Tree is a hierarchical acceleration structure for volume rendering that stores data values exclusively in the leaves of the tree. It addresses the problem of efficient ray traversal through sparse volumetric data by allowing subdivision in all directions, offering more flexibility than octrees which are restricted to center-based subdivisions. It is distinguished from its sibling, the Hybrid Kd Tree, by its specific leaf-only storage strategy and construction method.

### Spatial KD-Tree (SKD-Tree)
A variant of the kD-tree using 2 parallel splitting planes per node (also known as BoxTree or Bounding Interval Hierarchy, BIH) [S2, unofficial]. It solves the straddling polygon problem by ensuring that polygons are not stored in both subtrees; instead, the space between the two planes is shared [S2, unofficial]. However, because the child boxes overlap, traversal cannot stop as soon as a hit is found in the 'near' subtree; the 'far' subtree must also be checked if the hit is within the overlap region [S2, unofficial].

### Oversized Object Handling
A construction-time optimization strategy for scenes with extreme size variance in primitives. It filters out oversized objects before each split to prevent them from degrading split-plane quality. If numerous, they are isolated in a separate kD-tree; otherwise, they are stored in a simple list attached to the node [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Average case $O(\log N)$ for balanced trees, but can degrade to $O(N)$ for poorly constructed trees or specific ray directions [S2, unofficial]. Traversal cost is dominated by the number of nodes visited [S2, unofficial].
*   **Memory Complexity:** $O(N)$ for $N$ primitives, but with a constant factor overhead due to storing straddling polygons in multiple nodes (2-3x pointers) [S2, unofficial]. SKD-Trees reduce this overhead but increase node size (2 planes vs 1) [S2, unofficial].
*   **Performance:** Very fast ray traversal due to simple node structure (8 bytes per node: axis + split position) [S2, unofficial]. Construction uses plane sweep optimization for SAH evaluation, with bucket approximation for scenes exceeding 500,000 polygons [S2, unofficial].
*   **Strengths:** Adaptive subdivision, compact nodes, simple and fast traversal, good for static scenes [S2, unofficial].
*   **Limitations:** Memory intensive due to straddling polygons, construction can be slow for large scenes, not ideal for dynamic scenes due to frequent rebuilds [S2, unofficial].
*   **When to use:** Static scenes with complex geometry distribution where adaptive subdivision is beneficial [S2, unofficial].
*   **When not to use:** Dynamic scenes requiring frequent updates, or when memory is extremely constrained [S2, unofficial].

## Background
kD-trees were introduced as an acceleration structure for ray tracing to address the inflexibility of octrees, which always subdivide at the center of cells [S1, unofficial]. The multi-dimensional binary search tree was introduced by Bentley [S3, unofficial], and spatial partitioning techniques alternating splits along coordinate axes were developed by Kaplan [S4]. The "best known method" for static scenes was highlighted in a Siggraph Course in 2006 [S2, unofficial]. The Spatial KD-Tree (SKD-Tree) or BIH variant was proposed in 1987, 2002, and 2006 to mitigate the straddling polygon issue [S2, unofficial].
