# Stack Culling (Parent Node Re-intersection)
Also called: Short Stack Culling
## Overview
Stack culling is a technique for stackless or short-stack ray traversal that reduces expensive ray-primitive intersection tests by deferring the processing of multiple intersecting children. Instead of pushing all intersecting children onto the stack, the algorithm pushes the parent node itself when more than two children intersect and at least one is a leaf [S1, unofficial]. The parent is re-intersected later to cull children with hit distances greater than the current closest hit [S1, unofficial]. It sets itself apart from standard short-stack traversal by trading a small increase in traversal steps (1–10%) for a reduction in primitive intersections (2–14%), using only 1 bit of extra storage per stack entry instead of storing hit distances for every entry [S1, unofficial].
## How it works
**Inputs and Outputs:**
*   Input: Ray, N-wide BVH, short stack, restart trail.
*   Output: Closest hit distance (for closest-hit) or all hits (for any-hit).

**Data Structures:**
*   **Short Stack:** Stores node references. Each entry includes a flag bit to mark if the node is a "parent node" [S1, unofficial].
*   **Restart Trail:** An array of counters, one per hierarchy level, tracking how many children at each level have been processed [S1, unofficial].
*   **Current Depth:** Tracks the current level in the tree [S1, unofficial].

**Steps:**
1.  **Intersection Check:** For an internal N-wide node, compute intersections between the N child bounding boxes and the ray to find a list $H$ of intersecting children [S1, unofficial].
2.  **Sorting:** Sort $H$ based on increasing hit distance to obtain a sorted list $S$ [S1, unofficial].
3.  **Restart Handling:** If traversal restarts from the root, remove the first $k$ nodes from $S$ (where $k$ is the count value at the current level in the restart trail) to avoid re-traversing previously processed children [S1, unofficial].
4.  **Stack Culling Decision:**
    *   If more than two children intersect and at least one is a leaf:
        *   Push the **parent node** onto the short stack, tagged as a "parent node" [S1, unofficial].
        *   Continue traversal with the closest child (first in $S$) [S1, unofficial].
    *   Otherwise:
        *   Push the remaining intersecting children onto the short stack in back-to-front order [S1, unofficial].
        *   Tag the last child pushed to update the restart trail correctly [S1, unofficial].
5.  **Stack Pop (Re-intersection):**
    *   When popping from the stack, find the `parentLevel` to increment the restart trail and reset lower levels [S1, unofficial].
    *   If the node is tagged as a "parent node":
        *   Set the current depth to `parentLevel` [S1, unofficial].
        *   Re-intersect the parent node's children against the ray [S1, unofficial].
        *   Use the restart trail to skip children that were already traversed [S1, unofficial].
        *   Cull any child whose hit distance is greater than the current closest hit distance found so far [S1, unofficial].
    *   If the node is not a parent node:
        *   Set the current level to `parentLevel + 1` [S1, unofficial].

**Pseudocode:**

```python
def traverse_ray(ray, bvh, short_stack, restart_trail, max_level):
    current_node = bvh.root
    current_level = 0
    current_hit = float('inf')

    while True:
        # 1. Intersect children
        children = current_node.children
        intersections = []
        for child in children:
            hit = ray_intersect_box(ray, child.bbox)
            if hit is not None:
                intersections.append((hit, child))
        intersections.sort(key=lambda x: x[0])  # Front-to-back order [G]

        # 2. Apply restart trail to skip previously processed children
        k = restart_trail[current_level]
        valid = intersections[k:]

        if not valid:
            # No new children; pop from stack
            if not short_stack:
                return current_hit

            node, is_last, is_parent = short_stack.pop()

            # Find parent level to increment trail counter [G]
            parent_level = find_parent_level(restart_trail, current_level)
            if parent_level < 0:
                return current_hit

            restart_trail[parent_level] += 1
            reset_trail(restart_trail, parent_level + 1, max_level)

            if is_last:
                restart_trail[parent_level] = len(children) - 1

            if is_parent:
                current_level = parent_level
            else:
                current_level = parent_level + 1

            current_node = node
            continue

        # 3. Stack Culling Decision
        # Condition: more than two children intersect and at least one is a leaf
        if len(valid) > 2 and any(child.is_leaf for _, child in valid):
            # Push parent instead of children
            short_stack.append((current_node, is_last=False, is_parent=True))
            # Continue with closest child
            current_node = valid[0][1]
            current_level += 1
        else:
            # Push remaining children back-to-front
            for i in range(len(valid) - 1, 0, -1):
                hit, child = valid[i]
                is_last = (i == len(valid) - 1)
                short_stack.append((child, is_last=is_last, is_parent=False))

            # Continue with closest child
            current_node = valid[0][1]
            current_level += 1

            # If closest is last child, set trail to max
            if current_node is valid[-1][1]:
                restart_trail[current_level] = len(children) - 1

def find_parent_level(trail, current_level):
    # Find highest level with count < N-1 to determine which level to increment [G]
    for i in range(current_level, -1, -1):
        if trail[i] < N - 1:
            return i
    return -1

def reset_trail(trail, start_level, max_level):
    for i in range(start_level, max_level + 1):
        trail[i] = 0
```

**Parameters:**
*   Short stack size: Typically 5 entries [S1, unofficial].
*   Additional storage: 1 bit per stack entry [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Front-to-back ordering:** Strictly required for closest-hit searches to ensure culling logic remains consistent with restart trail counters [S1, unofficial]. Not required for any-hit searches [S1, unofficial].
*   **Precision:** Re-intersection may introduce slight numerical differences, but the culling logic relies on distance comparisons [S1, unofficial].
*   **Degenerate Input:** If more than two children intersect but none are leaves, the culling condition does not trigger, falling back to standard behavior [S1, unofficial].

## Subtopics

### Stack Culling Extension
An extension that culls leaf node entries on the stack when a closer intersection has been found, skipping expensive primitive intersection tests for further nodes [S1, unofficial]. During traversal, the current hit distance is updated every time a ray intersects a leaf node [S1, unofficial]. Subsequent child node intersections at a distance greater than the current hit distance are culled [S1, unofficial]. When an internal node is re-visited after a restart, children that previously intersected the ray but are now further than the current hit are also culled [S1, unofficial]. Front-to-back ordering is strictly required for closest-hit searches to ensure culling logic remains consistent with restart trail counters [S1, unofficial]. It is not required for any-hit searches [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   Memory: Approximately 3× less than a full stack. With a short stack of 5 entries, storage is less than 44 bytes (root 64 bits, current node 32 bits, restart trail 3×32 bits, current depth 5 bits, stack entries 5×32 bits) [S1, unofficial]. A full stack with max depth 32 requires 136 bytes [S1, unofficial].
*   Time: Overhead in traversal steps is 1–10% for closest-hit queries and 0–5% for any-hit queries with a short stack of 5 entries [S1, unofficial]. Quad intersections are reduced by 2–14% [S1, unofficial].

**Measured Performance:**
*   Evaluated with different path traced scenes [S1, unofficial].
*   Restart overhead is at most 10% with a short stack of 5 entries [S1, unofficial].

**Strengths and Limitations:**
*   Strengths: Significant memory reduction, reduced primitive intersections.
*   Limitations: Slight increase in traversal steps, requires front-to-back ordering for closest-hit [S1, unofficial].

**When to Use:**
*   Use when memory is constrained and primitive intersection cost is high.
*   Not recommended when traversal step overhead is unacceptable or when any-hit queries are the primary use case (though it still works, the benefit is less pronounced) [S1, unofficial].

## Background
Originated in the paper "Wide BVH Traversal with a Short Stack" [S1, unofficial]. The technique leverages the generalized restart trail mechanism to cull leaf node entries on the stack for closest-hit searches [S1, unofficial]. It addresses the trade-off between memory usage and traversal efficiency in BVH ray casting [S1, unofficial].
