# Restart Trail

Also called: Generalized Restart Trail, Restart Trail for Wide BVHs, Short Stack BVH Traversal, Short stack traversal with restart trail, Wide BVH Traversal with Short Stack, Wide BVH Traversal with a Short Stack

## Overview
Restart Trail is a stackless or short-stack traversal algorithm for Bounding Volume Hierarchies (BVHs) that enables traversal restarts from the root by storing one bit of data per hierarchy level to track which parts of the tree have been processed [S2, unofficial]. It sets itself apart from standard short-stack traversal by allowing the stack to be completely exhausted without losing traversal state, using a compact bit-array (the "trail") to resume from the correct point, whereas methods like [Stack Culling](9874-stack-culling-parent-node-re-intersection.md) trade a small increase in traversal steps for reduced primitive intersections using only 1 bit of extra storage per stack entry [S1, unofficial]. It solves the problem of memory-constrained traversal (e.g., in hardware or GPUs) where a full stack is too large, by replacing the stack with a fixed-size short stack and a restart mechanism that avoids re-entering already processed subtrees [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A ray, an N-wide BVH (where $N$ is the number of children per internal node), and a short stack of fixed size (typically 5 entries) [S1, unofficial].
- Output: The closest intersection (for closest-hit) or all intersections (for any-hit), traversing the BVH [S1, unofficial][S2, unofficial].

**Data Structures:**
1.  **Restart Trail (`trail`):** An array of bits (for binary BVHs) or counters (for N-wide BVHs) with one entry per hierarchy level [S1, unofficial][S2, unofficial].
    -   For binary BVHs: `trail` is a single register (`trailReg`) of 32 or 64 bits. `trail[0]` is a sentinel. `trail[i]` corresponds to the node at level $i$ [S2, unofficial].
    -   For N-wide BVHs: `trail[i]` is a counter ranging from $0$ to $N-1$. `trail[i]` stores the number of children at level $i$ already processed. $N-1$ indicates the current subtree is the last child at that level [S1, unofficial].
2.  **Level Register (`levelReg`):** A register with exactly one bit set, corresponding to the bit position in `trailReg` pointing to the parent of the current node. Initialized to `10000...` (1 followed by zeros) for the sentinel [S2, unofficial].
3.  **Short Stack:** A fixed-size array of node references. Each entry may include a reserved bit to mark if the entry corresponds to the last child of its parent node [S1, unofficial].
4.  **Pop Level (`popLevel`):** An integer tracking the level where the last stack pop would have taken the traversal. Initialized to NONE [S2, unofficial].

**Parameters:**
-   $N$: The width of the BVH (number of children per internal node) [S1, unofficial].
-   Short Stack Size: A small fixed number of entries (e.g., 5) stored in on-chip memory [S1, unofficial].

**Steps:**

1.  **Initialization:**
    -   Set `node` to `ROOT` [S1, unofficial][S2, unofficial].
    -   Set `trail` to all zeros (or counters to 0) [S1, unofficial][S2, unofficial].
    -   Set `level` to 0 [S1, unofficial][S2, unofficial].
    -   Set `shortstack` to empty [S1, unofficial][S2, unofficial].
    -   Set `popLevel` to NONE [S2, unofficial].

2.  **Traversal Loop:**
    While the current `node` is not a leaf:
    a.  **Intersect Children:** Intersect the ray against all children of `node`. Let $H$ be the list of intersecting children [S2, unofficial].
    b.  **Sort:** Sort $H$ by increasing hit distance to obtain sorted list $S$ [S1, unofficial].
    c.  **Handle Multiple Hits (Binary BVH Logic [S2, unofficial]):**
        -   If both children are intersected:
            -   Identify `near` child (smaller $t_{min}$) and `far` child (greater $t_{min}$).
            -   Increment `level` (shift `levelReg` right by 1) [S2, unofficial].
            -   If `trail[level]` is 1 (bit set): Set `node` to `far`. (The near child has been fully processed or skipped) [S2, unofficial].
            -   Else: Set `node` to `near`. Push `far` onto the short stack [S2, unofficial].
        -   If only one child is intersected:
            -   Increment `level` [S2, unofficial].
            -   If `level` $\neq$ `popLevel`: Set `trail[level]` to 1. Set `node` to the intersected child [S2, unofficial].
            -   Else (`level` == `popLevel`): Invoke `POP()`. This handles the case where the far child was culled during the processing of the near child [S2, unofficial].
        -   If no children are intersected:
            -   Invoke `POP()` [S2, unofficial].
    d.  **Handle Multiple Hits (N-wide BVH Logic [S1, unofficial]):**
        -   Let $k = \text{trail}[\text{level}]$ [S1, unofficial].
        -   If $k = N-1$: Remove all but the last entry in $S$ to form $Q$. (Current subtree is the last one) [S1, unofficial].
        -   Else: Remove the first $k$ entries in $S$ to form $Q$. (Skip already processed children) [S1, unofficial].
        -   If $Q$ is empty: Call `POP(trail, level)` [S1, unofficial].
        -   Else:
            -   Set `node` to the first entry in $Q$ [S1, unofficial].
            -   Remove the first entry from $Q$ [S1, unofficial].
            -   If $Q$ is empty: Set `trail[level]` to $N-1$ [S1, unofficial].
            -   Else: Mark the last entry in $Q$ as the "last child" and push remaining entries in $Q$ onto the short stack (back-to-front order) [S1, unofficial].

3.  **Leaf Processing:**
    -   Intersect the ray against primitives in the leaf `node` [S2, unofficial].
    -   If a closer primitive is found, shorten the ray at the end [S2, unofficial].
    -   Invoke `POP()` [S1, unofficial][S2, unofficial].

4.  **POP() Operation:**
    -   **Find Parent Level:** Scan the restart trail upwards from the current `level`. Skip levels with the max count value ($N-1$ for wide BVHs, or bit=1 for binary BVHs where it indicates completion). Find the largest $i \le \text{level}$ such that `trail[i]` is 0 (binary) or $< N-1$ (wide). If no such level exists (all scanned levels are maxed), the stack is empty and traversal is complete [S1, unofficial][S2, unofficial].
    -   **Update Trail:**
        -   Increment `trail[parentLevel]` (wide BVH) or set `trail[parentLevel]` to 1 (binary BVH) [S1, unofficial][S2, unofficial].
        -   Clear all counters/bits below `parentLevel` to 0 [S1, unofficial][S2, unofficial].
    -   **Update State:**
        -   If short stack is empty: Set `node` to `ROOT`, `level` to 0. Restart traversal [S1, unofficial][S2, unofficial].
        -   Else: Pop from short stack.
            -   If popped node is tagged as "last child": Set `trail[parentLevel]` to $N-1$ (wide BVH) [S1, unofficial].
            -   If popped node is tagged as "parent node" (Stack Culling extension): Set `level` to `parentLevel` [S1, unofficial].
            -   Else: Set `level` to `parentLevel` + 1 [S1, unofficial].
    -   **Save Pop Level:** If a node's near child is marked as fully processed (bit set in trail for binary, or counter incremented for wide), save the level of that node into `popLevel` [S2, unofficial].

**Pseudocode (N-wide BVH, generalizing [S1, unofficial]):**

```python
def restart_trail_traverse(ray, root, bvh_width, max_depth, short_stack_size=5):
    # Initialization
    trail = [0] * max_depth
    level = 0
    node = root
    short_stack = []
    
    while True:
        # Traverse down
        while not node.is_leaf():
            # Intersect children
            hits = []
            for child in node.children:
                t = ray.intersect(child.bvh_node)
                if t is not None:
                    hits.append((t, child))
            
            # Sort by hit distance
            hits.sort(key=lambda x: x[0])
            
            # Skip already processed children
            k = trail[level]
            if k == bvh_width - 1:
                # Current subtree is the last one, keep only the last child
                q = hits[-1:] if hits else []
            else:
                # Skip first k children
                q = hits[k:]
                
            if not q:
                # Stack underflow, pop
                node, level, short_stack, done = pop(trail, level, short_stack, bvh_width, root)
                if done:
                    return None
                continue
                
            # Proceed to next node
            node = q[0][1]
            q.pop(0)
            
            if not q:
                trail[level] = bvh_width - 1
            else:
                # Mark last child and push to stack
                q[-1][1].is_last_child = True
                # Push back-to-front
                for child_node, _ in reversed(q):
                    if len(short_stack) < short_stack_size:
                        short_stack.append(child_node)
                    
        # Leaf processing
        t_leaf, primitive = ray.intersect_leaf(node)
        if t_leaf is not None and t_leaf < ray.t_max:
            ray.t_max = t_leaf
            
        # Pop after leaf
        node, level, short_stack, done = pop(trail, level, short_stack, bvh_width, root)
        if done:
            return None
            
        # Check if we restarted to root and finished
        if level == 0 and node == root and trail[0] == bvh_width - 1:
            break

def pop(trail, level, short_stack, bvh_width, root):
    # Find parent level: scan upwards from level-1, skip levels with max count
    parent_level = -1
    for i in range(level - 1, -1, -1):
        if trail[i] < bvh_width - 1:
            parent_level = i
            break
            
    if parent_level < 0:
        return root, 0, [], True # Stack empty, traversal complete
        
    # Increment counter at parent level
    trail[parent_level] += 1
    # Clear counters below parent level
    for i in range(parent_level + 1, len(trail)):
        trail[i] = 0
        
    if not short_stack:
        # Restart from root
        return root, 0, [], False
    else:
        node = short_stack.pop()
        if node.is_last_child:
            trail[parent_level] = bvh_width - 1
        level = parent_level + 1
        return node, level, short_stack, False
```

**Edge Cases and Pitfalls:**
-   **Traversal Order:** Must be front-to-back (closest first) for closest-hit searches. If a child is culled because a closer hit was found, it must not be counted as 'processed' in the restart trail counter, otherwise the restart will skip it incorrectly [S1, unofficial].
-   **Culled Far Child:** When a node has two intersecting children, but the far child becomes culled during the processing of the near child (due to ray shortening), the algorithm must detect this via `popLevel` to avoid re-entering the near branch. If `level` equals `popLevel` in the single-child branch, it indicates the far child was culled, and `POP()` must be invoked [S2, unofficial].
-   **Precision:** Care must be taken to ensure that equal $t$ values after a restart do not cause re-entering already processed branches, leading to infinite loops [S2, unofficial].

## Subtopics

### [Stack Culling (Parent Node Re-intersection)](9874-stack-culling-parent-node-re-intersection.md)
A technique that pushes the parent node onto the stack instead of multiple children when multiple children intersect and at least one is a leaf. The parent is re-intersected later to cull children with hit distances greater than the current closest hit. It sets itself apart from standard short-stack traversal by trading a small increase in traversal steps (1-7%) for a reduction in primitive intersections (2-14%), using only 1 bit of extra storage per stack entry instead of storing hit distances for every entry.

## Operating characteristics
-   **Time Complexity:** Traversal steps increase by 1-10% for closest-hit queries and 0-5% for any-hit queries compared to a full stack [S1, unofficial]. Stackless traversal (no short stack) visits approximately 2.2–2.4 times as many nodes as ordinary traversal with a full stack [S2, unofficial]. A short stack with just one entry reduces this multiplier to 1.3–1.4 [S2, unofficial].
-   **Memory Complexity:** Uses ~3x less memory than a full stack. For a short stack of 5 entries, storage is < 44 bytes (Root: 64 bits, Current Node: 32 bits, Restart Trail: 3x32 bits, Current Depth: 5 bits, Short Stack: 5x32 bits). A full stack for a max depth of 32 requires 136 bytes [S1, unofficial].
-   **Performance:** Preliminary tests on NVIDIA G80 and GT200 hardware indicate that memory bandwidth benefits of short stacks may not outweigh costs of restarts, SIMD divergence, and extra instructions [S2, unofficial]. However, it is well-suited for hardware hierarchy traversal units where registers are limited [S2, unofficial].
-   **Strengths:** Compact memory footprint, no need for parent pointers or hash lookups in BVH nodes, simpler implementation than stackless backtracking methods [S1, unofficial].
-   **Limitations:** Restart overhead increases with smaller stack sizes. Slightly higher extraneous node visits compared to kd-trees due to BVH child overlap causing more stack pushes [S2, unofficial].

## Background
Restart Trail was introduced by Tero Laine in 2010 [S2, unofficial]. It generalizes the restart trail algorithm for binary BVHs to BVHs of arbitrary widths, as proposed by Scheuermann et al. [S1, unofficial]. It is used in real-time ray tracing, particularly in hardware acceleration units and GPU ray cast kernels where memory bandwidth and on-chip storage are critical constraints [S1, unofficial][S2, unofficial].
