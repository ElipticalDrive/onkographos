# Stackless Traversal

Also called: Algorithme sans pile, Parcours sans pile, Parent-link traversal, Stack-less Tree Traversal

## Overview
Stackless Traversal is a ray traversal algorithm for hierarchical volume structures (such as N3-trees or octrees) that eliminates the need for an explicit stack data structure by recalculating Digital Differential Analyzer (DDA) parameters at every descent and ascent step [S1, unofficial]. It solves the memory and register pressure issues associated with stack-based traversal on GPUs, where dynamic array indexing can force data into slow local memory [S1, unofficial]. It sets itself apart from [DDA Tree Traversal with Mini-Stack](5244-dda-tree-traversal-with-mini-stack.md) by trading computational cost (repeated DDA calculations) for reduced memory footprint and avoidance of stack overflow or complex stack management logic [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a hierarchical tree structure where each node stores a pointer to its parent and its spatial bounds; leaf nodes containing either voxel data or pre-integrated average color/density values [S1, unofficial].
*   **Output:** A compositing result (color and opacity) for the ray, or a termination flag if the ray exits the volume or reaches maximum depth [S1, unofficial].

**Data Structures:**
*   **Node:** Contains bounding box information, a pointer to the parent node, and a flag indicating if the node is empty or a leaf [S1, unofficial].
*   **Parent Pointer:** A direct reference to the parent node, specifically allowing extraction of the current cell's position within the parent's grid without recalculation [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Calculate initial DDA parameters ($t_{min}, t_{max}, \Delta t_x, \Delta t_y, \Delta t_z, x_{step}, y_{step}, z_{step}$) for the root node's bounding box using the ray $\mathbf{o}, \mathbf{d}$ [S1, unofficial].
2.  **Descent:**
    *   Determine the child octant intersected by the ray using the method from [Octree and Tree Traversal](4134-octree-and-tree-traversal.md) [S1, unofficial].
    *   If the child is empty, skip the subtree. This is handled by advancing the ray parameter $t$ to the exit of the current node or using neighbor pointers (if available) [S1, unofficial][G].
    *   If the child is not empty, descend into it.
3.  **Ascent (Backtracking):**
    *   When a ray exits a subtree or encounters a leaf, it must return to the parent to explore other branches or exit the volume.
    *   Instead of popping a stack, use the **parent pointer** stored in the current node to move directly to the parent node [S1, unofficial].
    *   Extract the current cell's index within the parent's grid from the parent pointer information, avoiding the need to recalculate the cell's position relative to the parent's center [S1, unofficial].
4.  **Re-calculation:**
    *   Upon moving to a new node (either via descent or ascent), **recalculate all DDA parameters** for the new node's bounding box based on the current ray state and the new node's bounds [S1, unofficial]. This is the core computational trade-off of the method [S1, unofficial].
5.  **Leaf Processing:**
    *   If the current node is a leaf with available voxel data, perform regular ray-marching (fixed-step traversal) within the leaf's voxel grid [S1, unofficial].
    *   If the leaf is a "brick" with pre-integrated data (or if dynamic loading fails), use the stored average color and density. Accumulate the contribution based on the distance traversed by the ray within that brick [S1, unofficial].
    *   If the leaf is empty, ignore it and proceed to ascent [S1, unofficial].
6.  **Termination:**
    *   Stop if the ray exits the root node's bounding box or if the accumulated opacity reaches 1.0 (or a threshold) [S1, unofficial].

*   **Register Limit:** Limit the number of registers used to allow multiprocessors to handle more parallel threads, better covering texture access latency [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **GPU Local Memory Penalty:** On older GPUs like the G80, dynamically indexed arrays are placed in 'local' memory (device memory) by the shader compiler, which is uncached and up to 50x slower than registers [S1, unofficial]. This negatively impacts performance compared to register-based stack access [S1, unofficial].
*   **Recalculation Cost:** The repeated DDA calculations can be computationally expensive, but this is offset by the avoidance of stack memory overhead [S1, unofficial].

## Subtopics

### [Restart Trail](9459-restart-trail.md)
A stackless or short-stack traversal algorithm designed to enable restarts from the root without a full stack. It differs from Stackless Traversal by storing one bit of data per hierarchy level to track visited status, allowing traversal to resume after a short stack overflow. It sets itself apart from skip-node pointers by allowing processing of the nearer node before the farther node, adapting to ray direction.

## Operating characteristics
*   **Time Complexity:** Higher per-node computational cost due to repeated DDA parameter recalculation at every descent and ascent step [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary stack space, as no explicit stack is used. Memory usage is dominated by the tree structure itself [S1, unofficial].
*   **Measured Performance:** On the NVIDIA G80 GPU, the stackless algorithm was approximately 50% faster than the mini-stack algorithm in tested scenarios [S1, unofficial].
*   **Strengths:** Avoids stack overflow issues; reduces register pressure and memory bandwidth usage associated with stack storage; simpler control flow on hardware with limited dynamic indexing capabilities [S1, unofficial].
*   **Limitations:** Higher computational cost per step; performance heavily dependent on the efficiency of DDA recalculation; on modern GPUs with fast local memory or shared memory, the advantage may diminish compared to optimized stack-based approaches [S1, unofficial].
*   **When to Use:** When memory bandwidth or register pressure is a bottleneck, or when implementing on hardware with poor support for dynamic array indexing into large structures [S1, unofficial].
*   **When Not to Use:** When the tree is very deep and DDA recalculation is prohibitively expensive, or when the hardware provides efficient stack management (e.g., via shared memory) [S1, unofficial].

## Background
*   **Origin:** The algorithm was developed and tested as part of research on interactive exploration of procedural volume data, specifically for N3-trees [S1, unofficial].
*   **History:** It was proposed as an alternative to stack-based methods (like mini-stacks) to overcome limitations in GPU shader compilers regarding dynamic array indexing and memory access patterns [S1, unofficial].
*   **Usage:** Used in GPU-based volume rendering implementations where minimizing memory footprint and avoiding stack overflow are critical [S1, unofficial].
