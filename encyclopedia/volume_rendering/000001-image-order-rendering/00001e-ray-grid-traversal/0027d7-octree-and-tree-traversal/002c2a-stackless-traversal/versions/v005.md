# Stackless Traversal

Also called: Algorithme sans pile, Parcours sans pile, Parent-link traversal, Stack-less Tree Traversal

## Overview
Stackless Traversal is a ray-traversal algorithm for hierarchical volume structures (such as N3-trees or octrees) that eliminates the need for an explicit stack data structure by recalculating Digital Differential Analyzer (DDA) parameters at every descent and ascent step [S1, unofficial]. It sets itself apart from sibling methods like [DDA Tree Traversal with Mini-Stack](5244-dda-tree-traversal-with-mini-stack.md) by trading increased computational cost for reduced memory footprint, making it particularly suitable for hardware or GPU architectures where stack storage is limited or expensive [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a hierarchical tree structure where each node stores a pointer to its parent and its spatial bounds.
*   **Output:** A sequence of visited nodes and accumulated volume samples (color/opacity) along the ray.

**Data Structures:**
*   **Tree Node:** Contains bounding box information, a pointer to the parent node, and data flags (empty/occupied). The parent pointer points directly to the specific child index within the parent's grid, allowing extraction of current cell information without recalculation [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Compute initial DDA parameters for the ray at the root node.
2.  **Descent:** Determine the child node intersected by the ray using the standard child selection logic (comparing ray position to node center) [Parent].
3.  **Empty Check:** If the selected child is marked as empty, skip the subtree. This is achieved by advancing the ray parameter $t$ to the exit of the current node or using neighbor pointers if available [Parent].
4.  **Leaf Handling:** If the current node is a leaf:
    *   If data is available, perform regular ray-marching within the leaf's voxel grid [S1, unofficial].
    *   If data is unavailable (e.g., dynamic loading failure), use the stored average color and accumulate it based on the distance traversed by the ray in that brick (pre-integration) [S1, unofficial].
5.  **Ascent:** If the ray exits the current subtree or a branch is fully processed, move to the parent node using the stored parent pointer [S1, unofficial].
6.  **Re-calculation:** Upon moving to the parent (either during ascent or subsequent descent), recalculate **all** DDA parameters for the new context [S1, unofficial]. This avoids storing state but increases computational cost.
7.  **Iteration:** Repeat steps 2-6 until the ray exits the volume or the maximum depth is reached.

**Formulas:**
*   **Child Selection:** For a node with center $\mathbf{c}$ and half-extent $s$, the ray position $\mathbf{p}$ determines the child index $k \in \{0, \dots, 7\}$:
    $$
    k = 4 \cdot \mathbb{I}(p_x \ge c_x) + 2 \cdot \mathbb{I}(p_y \ge c_y) + 1 \cdot \mathbb{I}(p_z \ge c_z)
    $$
    where $\mathbb{I}(\cdot)$ is the indicator function [Parent].
*   **DDA Recalculation:** All DDA parameters (step sizes, direction signs, initial $t$ values) are recomputed from scratch for the new node's bounding box and the global ray definition [S1, unofficial].

**Parameters:**
*   **Conditional Block Size:** Limited to reduce divergent threads on GPU multiprocessors [S1, unofficial].
*   **Register Usage:** Limited to allow multiprocessors to handle more parallel threads, better covering texture access latency [S1, unofficial].

**Pitfalls:**
*   **GPU Memory Latency:** On older architectures like the G80, dynamically indexed arrays are placed in "local" memory (device memory) by the shader compiler. This memory is uncached and up to 50x slower than registers, which can negate the benefits of stackless traversal if not managed carefully [S1, unofficial].
*   **Computational Overhead:** Recalculating DDA parameters at every step is more expensive than maintaining a stack, so this method is best suited for scenarios where memory is the primary constraint [S1, unofficial].

## Subtopics

### [Restart Trail](9459-restart-trail.md)
A stackless or short-stack traversal algorithm for Bounding Volume Hierarchies (BVHs) that enables traversal restarts from the root by storing one bit of data per hierarchy level. It sets itself apart from standard short-stack traversal by allowing the stack to be completely exhausted without losing traversal state, using a compact bit-array (the "trail") to resume from the correct point. It is chosen when memory is extremely constrained and full stack exhaustion is possible.

## Operating characteristics
*   **Time Complexity:** Higher per-step computational cost due to DDA parameter recalculation at every descent and ascent [S1, unofficial].
*   **Memory Complexity:** $O(1)$ auxiliary stack space, as no explicit stack is maintained [S1, unofficial].
*   **Measured Performance:** On the G80 GPU, the stackless algorithm was approximately 50% faster than the mini-stack algorithm in tested scenarios [S1, unofficial].
*   **Strengths:** Eliminates stack overflow risks; reduces memory footprint; suitable for hardware with limited register/stack space [S1, unofficial].
*   **Limitations:** Higher computational overhead; performance sensitive to GPU memory latency (e.g., local memory on G80) [S1, unofficial].
*   **When to Use:** When memory is the primary bottleneck, or on hardware where stack operations are expensive or limited [S1, unofficial].
*   **When Not to Use:** When computational resources are abundant but memory is not constrained, or when DDA recalculation is too costly for the target hardware [S1, unofficial].

## Background
The method was developed and tested as part of research into interactive exploration of procedural volume data, specifically for N3-trees [S1, unofficial]. It was designed to address the limitations of stack-based approaches on early GPU architectures (like the G80) where dynamic array indexing led to slow local memory access [S1, unofficial]. The algorithm trades memory usage for computational cost, recalculating DDA parameters at each step to avoid stack storage [S1, unofficial].
