# Octree and Tree Traversal

Also called: Hierarchical Grid Traversal, Sparse Voxel Octree Traversal

## Overview
Octree and Tree Traversal methods accelerate volume rendering and ray tracing by skipping empty or uniform regions of space using a hierarchical spatial index. Unlike fixed-grid methods that sample every voxel, these techniques descend the tree to locate only the occupied leaves intersected by the ray. This family sets itself apart from [Ray-grid traversal](17-ray-grid-traversal.md) siblings by replacing uniform stepping with pointer-based or coordinate-based descent, allowing for non-uniform resolution and significant speedups in sparse scenes.

## Shared principles
All methods in this family share the mechanism of hierarchical descent. The ray is tested against the bounding volume of the current node. If the ray misses, the node is skipped. If it hits, the algorithm determines which child node (octant) contains the ray's entry point or next intersection. This process repeats until a leaf node is reached or a termination condition (e.g., max depth, empty leaf) is met.

Key shared concepts include:
1.  **Bounding Box Intersection:** Testing the ray against the node's AABB to cull empty subtrees.
2.  **Child Selection:** Determining the index of the child node to visit next. This can be done via:
    *   **Geometric Intersection:** Computing the exact entry/exit points of the ray with the child boundaries (e.g., [Rational Ray Parameterization](3875-rational-ray-parameterization-for-octree-traversal.md)).
    *   **Coordinate Comparison:** Comparing the ray's position relative to the node's center or grid coordinates to determine the octant (e.g., [Octree Path Computation](897-octree-path-computation.md)).
3.  **Empty Space Skipping:** If a node is marked as empty (or uniform), the traversal can skip directly to the next potentially occupied node, often using neighbor pointers or by advancing the ray parameter $t$ to the exit of the current node.

## Subtopics

### [Hermite Data Computation via Bisection](822-hermite-data-computation-via-bisection.md)
A method to find all edge crossings in an adaptive octree for an implicit function and compute Hermite data (intersection points and normals) using bisection. It refines linear interpolation guesses with bisection to achieve higher precision than standard Marching Cubes, which is essential for dual contouring methods that rely on accurate vertex placement via Quadratic Error Functions (QEF). Unlike [Octree Path Computation](897-octree-path-computation.md) which focuses on traversal efficiency, this method focuses on geometric accuracy of the isosurface intersection. The method outputs Hermite data structures; mesh generation is a downstream step.

### [Octree Path Computation](897-octree-path-computation.md)
Octree Path Computation is the method of encoding the spatial location of a node within an octree hierarchy into a compact bit-vector (path) based on the ray's traversal coordinates. It solves the problem of efficiently identifying which child node a ray enters at each depth level without performing repeated geometric intersection tests against child bounding boxes. It sets itself apart from [Hermite Data Computation via Bisection](822-hermite-data-computation-via-bisection.md) by using direct coordinate comparison rather than iterative refinement, and from [Rational Ray Parameterization for Octree Traversal](3875-rational-ray-parameterization-for-octree-traversal.md) by operating in grid-space rather than ray-parameter space.

### [Rational Ray Parameterization for Octree Traversal](3875-rational-ray-parameterization-for-octree-traversal.md)
Rational Ray Parameterization is a method for tracing rays through an octree using exact rational arithmetic to eliminate floating-point precision errors during cell boundary crossing and neighbor finding. It solves the problem of robustly determining the next cell intersected by a ray when ray parameters are not integers, ensuring that equality tests for intersection distances are exact. Unlike standard floating-point traversal methods, this approach guarantees robustness by representing ray parameters as rational numbers (numerator/denominator pairs) and using integer arithmetic for neighbor location. It builds on [Octree and Tree Traversal](4134-octree-and-tree-traversal.md) by replacing approximate geometric tests with exact arithmetic operations.

### [Ray-Occlusion Traversal in Octree](5121-ray-occlusion-traversal-in-octree.md)
Ray-Occlusion Traversal in Octree is a method for determining shadow ray intersections within a hierarchical voxel (octree) structure by traversing the tree to find the first non-empty leaf or surface. It handles rays starting inside or outside the root voxel by computing entry points via bounding box intersection and stepping through empty space or descending into child nodes. It sets itself apart from its siblings by explicitly managing shadow ray occlusion logic, including specific attenuation factors and boundary precision handling, whereas [Octree Path Computation](897-octree-path-computation.md) focuses on path generation and [Compositing Tree Rendering](5860-compositing-tree-rendering.md) handles alpha blending.

### [Presence Acceleration](5753-presence-acceleration.md)
A hierarchical ray traversal technique using a binary pyramid to skip empty regions in a volume, finding the first intersection with opaque voxels.

### [Compositing Tree Rendering](5860-compositing-tree-rendering.md)
A rendering strategy where only modified data subtrees are rendered. Partial images of unmodified data are retained and composited with new partial images from modified data to form the final image.

### Photon Splatting for Direct Illumination
- **Definition:** Store incoming radiance from a light source in the octree leaves by rendering the scene from the light's view using standard rasterization to output a world position map (light-view map), where each pixel represents a photon [S1].
- **Steps:**
    - Splat photons using a fragment shader with one thread per light-view-map pixel, storing them as a direction distribution and energy proportional to the subtended solid angle of the pixel as seen from the light [S1].
    - Assume light-view map resolution is higher than the lowest level of the voxel grid to splat photons directly into leaf nodes without gaps [S1].
    - Store photons at the finest level of the voxel structure because they are stored at the surface [S1].
    - Use atomic add to handle multiple photons ending up in the same voxel [S1].
- **Pitfalls:**
    - Atomic add operations are currently only available for integer textures. Use a 16-bit normalized texture format, denormalized when accessing the value later [S1].
    - Voxels are repeated for adjacent bricks for fast hardware-supported filtering. Copying photons directly to all required locations in adjacent bricks leads to many thread collisions and bandwidth issues [S1].

### Octree with Neighbor Pointers
- **Definition:** A spatial index structure that augments a branch-on-need octree with links to allow direct traversal to adjacent nodes, used to accelerate ray traversal in volume rendering [S2].
- **Steps:**
    - Construction: Create the structure on-the-fly at each frame directly from the view-dependent octree. Encode it into a 3D texture acting as a spatial index. Update the GPU texture using a glTexSubImage call [S2].
- **Layout:**
    - Encoded into a 3D texture. Each octree node is encoded in 8 consecutive texels arranged in the x direction. The layout uses an 8-bit RGBA texture. The A component of the tagged pointer determines node kind: A=1.0 for inner nodes, A=0.5 for data nodes, A=0.0 for empty nodes. Inner nodes use RGB to point to the first of 8 children arranged consecutively in x. Leaf nodes use RGB to point to leaf info: a data pointer (if not empty) and 6 consecutive texels storing neighbor pointers. The last leaf data texel contains a NULL pointer. Neighbor pointers use their A value to encode the octree level of the neighbor [S2].

### Selective Rendering with Tree Representation
- **Definition:** A rendering strategy that uses the tree representation to perform selective rendering efficiently, reducing I/O costs and enabling distribution of data and calculations to multiple workstations [S3, unofficial].
- **Steps:**
    - Examine the encoded data to identify partial images built from subtrees which have not changed [S3, unofficial].
    - Reuse the identified unchanged partial images in the following time steps [S3, unofficial].

## Background
Octrees were introduced as a spatial partitioning data structure in the 1970s and have been widely used in computer graphics for collision detection, ray tracing, and volume rendering. In the context of volume rendering, sparse voxel octrees (SVOs) allow for the efficient representation of large, sparse volumetric datasets by only storing non-empty voxels. The traversal algorithms evolved from simple recursive descent to optimized stackless and GPU-friendly variants to handle the high memory bandwidth requirements of modern rendering. Key developments include the use of neighbor pointers for efficient empty-space skipping [S2], rational arithmetic for robust traversal [S1], and hierarchical compression techniques for time-varying data [S3, unofficial].
