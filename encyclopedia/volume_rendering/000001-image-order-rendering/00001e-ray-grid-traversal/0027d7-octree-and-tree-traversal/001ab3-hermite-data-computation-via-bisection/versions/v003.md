# Hermite Data Computation via Bisection

Also called: Bisection-based Hermite Data Computation, Edge Crossing Detection with Bisection

## Overview
This method computes precise intersection points and surface normals (Hermite data) for an implicit function on the edges of an adaptive octree's leaf cells [S1, unofficial]. It solves the problem of geometric inaccuracy in surface extraction (such as Dual Contouring) where linear interpolation between cell corners introduces visible jaggedness on curved or sharp features [S1, unofficial]. Unlike [Octree Path Computation](897-octree-and-tree-traversal.md) which focuses on traversal efficiency, or [Rational Ray Parameterization for Octree Traversal](3875-rational-ray-parameterization-for-octree-traversal.md) which handles ray-cube intersections, this method refines the geometric location of the isosurface crossing within each leaf cell to sub-cell accuracy [S1, unofficial].

## How it works
The algorithm identifies edges in leaf cells where the implicit function changes sign relative to an iso-value, then refines the crossing point on these edges using bisection. It subsequently computes normals either from direct gradient evaluation or finite differences.

### Inputs and Outputs
*   **Inputs**:
    *   `octree`: An adaptive octree structure containing leaf cells. Each leaf has bounds, depth, and corner values of the implicit function.
    *   `func`: An implicit function evaluator capable of batch evaluation of positions and optionally gradients.
    *   `iso_value`: The scalar threshold defining the isosurface.
*   **Outputs**:
    *   `hermite_data`: A collection of `HermitePoint` structures, each containing the refined 3D position, the surface normal, and the parameter $t$ along the edge.

### Data Structures
The method uses the following structures to manage edge crossings and results:

**`EdgeCrossing`** (Intermediate representation of a sign-change edge):
*   `p0`: `[f64; 3]` — 3D coordinates of the first endpoint of the edge.
*   `p1`: `[f64; 3]` — 3D coordinates of the second endpoint of the edge.
*   `v0`: `f64` — Signed function value at `p0` (i.e., $f(p_0) - \text{iso\_value}$).
*   `v1`: `f64` — Signed function value at `p1` (i.e., $f(p_1) - \text{iso\_value}$).
*   `leaf_idx`: `usize` — Index of the leaf cell containing this edge.
*   `edge`: `u8` — Index of the edge within the cell (0–11).
*   `comp_id`: `u8` — Component ID for multi-component cells (used in Dual Contouring).

**`HermitePoint`** (Final output):
*   `pos`: `[f64; 3]` — Refined 3D intersection point.
*   `normal`: `[f64; 3]` — Normalized surface normal at `pos`.
*   `t`: `f64` — Barycentric parameter along the edge $[0.0, 1.0]$.

### Algorithm Steps

1.  **Initialization**:
    *   Retrieve `iso_value` from `octree.iso_value`.
    *   Retrieve `max_depth` from `octree.max_depth`.
    *   Calculate `cell_size_at_max` as `octree.bounds.size / (1u32 << max_depth)` [S1, unofficial].

2.  **Edge Collection**:
    *   Iterate over all leaf cells in the octree.
    *   For each leaf, iterate over its 12 edges.
    *   For each edge, retrieve the corner indices $(c_0, c_1)$ and compute signed values $v_0 = f(p_0) - \text{iso\_value}$ and $v_1 = f(p_1) - \text{iso\_value}$.
    *   If a sign change is detected ($v_0 < 0.0 \neq v_1 < 0.0$), create an `EdgeCrossing` struct with `p0`, `p1`, `v0`, `v1`, `leaf_idx`, `edge`, and `comp_id` (derived from connected component analysis of the cell's corner mask) [S1, unofficial].
    *   Collect all such edges into a flat list `all_edges`.

3.  **Bisection Refinement**:
    *   Initialize arrays `lo_t` and `hi_t` of size `num_crossings` to $[0.0, 1.0]$.
    *   Initialize `lo_val` with the `v0` values from `all_edges`.
    *   Perform a fixed number of bisection iterations (typically 8–10) [S1, unofficial]:
        *   Compute midpoints $t_i = (lo\_t[i] + hi\_t[i]) \times 0.5$.
        *   Compute 3D positions $pos_i = \text{lerp}(p0_i, p1_i, t_i)$.
        *   Batch evaluate the implicit function at all $pos_i$ to get values $val_i$.
        *   Compute signed mid-values $mid\_val_i = val_i - \text{iso\_value}$.
        *   Update intervals: If $mid\_val_i$ and $lo\_val[i]$ have the same sign, set $lo\_t[i] = t_i$ and $lo\_val[i] = mid\_val_i$; otherwise, set $hi\_t[i] = t_i$.
    *   After iterations, compute final $t_i = (lo\_t[i] + hi\_t[i]) \times 0.5$ and final positions $pos_i$ [S1, unofficial].

4.  **Normal Computation**:
    *   Evaluate gradients at all final $pos_i$ in a batch.
    *   If gradients are available, normalize them: if $\|g\| > 10^{-12}$, $n = g / \|g\|$; else $n = [0.0, 0.0, 1.0]$ [S1, unofficial].
    *   If gradients are not available, estimate them using finite differences with step size $h = \text{cell\_size\_at\_max} \times 0.01$. Normalize the estimated gradients using the same logic [S1, unofficial].

5.  **Storage**:
    *   Store `HermitePoint` (pos, normal, t) in `octree.hermite_data`, associated with the corresponding leaf and edge index [S1, unofficial].

### Pseudocode

```python
def compute_hermite_data(octree, func, iso_value):
    """
    Computes Hermite data (position, normal, t) for edge crossings in an adaptive octree.
    """
    max_depth = octree.max_depth
    bounds_size = octree.bounds.size
    cell_size_at_max = bounds_size / (1 << max_depth)
    
    # Step 1: Collect sign-change edges
    all_edges = []
    for leaf_idx, leaf in enumerate(octree.leaves):
        # Get connected components for this leaf to handle multi-component cells
        components = get_cell_components(leaf.corner_mask)
        
        for edge_idx in range(12):
            c0, c1 = CubicBounds.edge_corners(edge_idx)
            p0 = leaf.bounds.corner(c0)
            p1 = leaf.bounds.corner(c1)
            
            # Evaluate function at corners (assumed pre-computed or cached in leaf)
            v0 = leaf.corner_values[c0] - iso_value
            v1 = leaf.corner_values[c1] - iso_value
            
            # Check for sign change
            if (v0 < 0.0) != (v1 < 0.0):
                comp_id = edge_component(components, leaf.corner_mask, edge_idx)
                all_edges.append({
                    'p0': p0, 'p1': p1,
                    'v0': v0, 'v1': v1,
                    'leaf_idx': leaf_idx,
                    'edge': edge_idx,
                    'comp_id': comp_id
                })
    
    num_crossings = len(all_edges)
    if num_crossings == 0:
        return []

    # Step 2: Bisection Refinement
    lo_t = [0.0] * num_crossings
    hi_t = [1.0] * num_crossings
    lo_val = [edge['v0'] for edge in all_edges]
    
    # 10 iterations for ~1/1024 cell accuracy
    for _ in range(10):
        if num_crossings == 0:
            break
            
        # Compute midpoints
        mid_points = []
        for i in range(num_crossings):
            t = (lo_t[i] + hi_t[i]) * 0.5
            mid_points.append(lerp3(all_edges[i]['p0'], all_edges[i]['p1'], t))
        
        # Batch evaluate implicit function
        results = func.batch_evaluate(mid_points)
        
        for i in range(num_crossings):
            mid_val = results.values[i] - iso_value
            mid_t = (lo_t[i] + hi_t[i]) * 0.5
            
            # Update interval based on sign
            if (mid_val < 0.0) == (lo_val[i] < 0.0):
                lo_t[i] = mid_t
                lo_val[i] = mid_val
            else:
                hi_t[i] = mid_t

    # Step 3: Compute Final Positions and Normals
    hermite_points = []
    final_positions = []
    
    for i in range(num_crossings):
        t = (lo_t[i] + hi_t[i]) * 0.5
        pos = lerp3(all_edges[i]['p0'], all_edges[i]['p1'], t)
        final_positions.append(pos)
        
        # Compute Normal
        if results.gradients is not None:
            grad = results.gradients[i]
            norm_len = length3(grad)
            if norm_len > 1e-12:
                normal = normalize3(grad)
            else:
                normal = [0.0, 0.0, 1.0]
        else:
            # Finite difference estimation if gradients not available
            fd_grads = func.estimate_gradients_fd(final_positions, cell_size_at_max * 0.01)
            grad = fd_grads[i]
            norm_len = length3(grad)
            if norm_len > 1e-12:
                normal = normalize3(grad)
            else:
                normal = [0.0, 0.0, 1.0]
        
        hermite_points.append({
            'pos': pos,
            'normal': normal,
            't': t,
            'leaf_idx': all_edges[i]['leaf_idx'],
            'edge': all_edges[i]['edge']
        })
        
    return hermite_points

def lerp3(p0, p1, t):
    return [p0[j] + t * (p1[j] - p0[j]) for j in range(3)]

def length3(v):
    return (v[0]**2 + v[1]**2 + v[2]**2)**0.5

def normalize3(v):
    l = length3(v)
    return [v[j] / l for j in range(3)]
```

### Parameters and Typical Values
*   `bisection_iters`: Number of bisection iterations. Value: 10. Context: Provides ~1/1024 cell accuracy [S1, unofficial].
*   `iso_value`: The scalar value defining the isosurface [S1, unofficial].
*   `cell_size_at_max`: The physical size of a cell at the maximum octree depth. Used for finite difference step size [S1, unofficial].
*   Finite difference step size: `cell_size_at_max * 0.01` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Division by Zero in Linear Interpolation**: If $|v_1 - v_0| < 10^{-15}$, the denominator in linear interpolation is near zero. The method handles this by defaulting $t$ to $0.5$ [S1, unofficial].
*   **Zero-Length Gradient**: If the gradient magnitude is $< 10^{-12}$, normalization fails. The method defaults the normal to $[0.0, 0.0, 1.0]$ [S1, unofficial].
*   **No Sign Change**: If no sign change exists on an edge, no Hermite data is computed for that edge [S1, unofficial].
*   **Multi-Component Cells**: Cells with complex topology (e.g., checkerboard patterns) may have multiple disconnected isosurface components. The method uses connected component analysis to assign a `comp_id` to each edge crossing, ensuring correct vertex placement in Dual Contouring [S1, unofficial].

## Subtopics

### [Edge Completeness Enforcement](825-edge-completeness-enforcement.md)
A post-processing step that ensures topological consistency by enforcing complete 4-cell neighborhoods at depth boundaries. It differs from Hermite Data Computation by focusing on grid structure consistency rather than precise intersection point computation.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of leaf cells and edges with sign changes. The bisection step adds a constant factor of $O(k)$ where $k$ is the number of bisection iterations (typically 8–10). Batch evaluation allows for efficient GPU or multi-core CPU utilization.
*   **Memory Complexity**: Linear with respect to the number of sign-change edges. Requires storage for `EdgeCrossing` lists and `HermitePoint` results.
*   **Accuracy**: Provides sub-cell accuracy (e.g., ~1/256 to 1/1024 of cell size) compared to linear interpolation, significantly reducing jaggedness on curved surfaces [S1, unofficial].
*   **Strengths**: High geometric accuracy for Dual Contouring; handles adaptive octrees efficiently by only processing leaf cells; batched operations optimize performance.
*   **Limitations**: Requires evaluation of the implicit function multiple times per edge (once per bisection iteration); relies on the availability of an implicit function evaluator; may be slower than simple linear interpolation if high precision is not required.
*   **When to Use**: When generating meshes for Dual Contouring where vertex placement accuracy is critical, especially for curved or sharp features.
*   **When Not to Use**: When only vertex positions are needed (e.g., standard Marching Cubes) or when performance is prioritized over geometric precision.

## Background
The method originates from implementations of Dual Contouring on adaptive octrees, specifically within the `isomesh` project [S1, unofficial]. It addresses the limitations of standard Marching Cubes, which only computes vertex positions, by providing the Hermite data (position and normal) necessary for solving Quadratic Error Functions (QEF) in Dual Contouring [S1, unofficial]. The use of bisection refinement was introduced to mitigate the jaggedness caused by linear interpolation on curved surfaces, a common issue in adaptive mesh generation [S1, unofficial].
