# Hermite Data Computation via Bisection

Also called: Bisection-based Hermite Data Computation, Edge Crossing Detection with Bisection

## Overview
A method to find all edge crossings in an adaptive octree for an implicit function and compute Hermite data (intersection points and normals) using bisection [S1, unofficial]. It refines linear interpolation guesses with bisection to achieve higher precision than standard Marching Cubes, which is essential for dual contouring methods that rely on accurate vertex placement via Quadratic Error Functions (QEF) [S1, unofficial]. Unlike [Octree Path Computation](897-octree-path-computation.md) which focuses on traversal efficiency, this method focuses on geometric accuracy of the isosurface intersection [S1, unofficial]. The method outputs Hermite data structures; mesh generation is a downstream step [S1, unofficial].

## How it works
**Inputs:**
- `octree`: An adaptive octree structure containing leaf cells. Each leaf cell has `bounds` (spatial extent), `corner_values` (8 scalar values at corners), `corner_mask` (bitmask of inside corners), and `depth` [S1, unofficial].
- `iso_value`: The scalar value defining the isosurface, extracted from `octree.iso_value` [S1, unofficial].
- `func`: A function evaluator capable of batch evaluation of the implicit function and its gradients at a list of 3D points [S1, unofficial].

**Outputs:**
- `hermite_data`: A collection of `HermitePoint` structs, one for each detected edge crossing [S1, unofficial].

**Data Structures:**
- `EdgeCrossing`: A temporary struct used during collection.
  - `p0: [f64; 3]`: Start point of the edge.
  - `p1: [f64; 3]`: End point of the edge.
  - `v0: f64`: Signed function value at `p0` (i.e., `value - iso_value`).
  - `v1: f64`: Signed function value at `p1` [S1, unofficial].
- `HermitePoint`: The final output struct.
  - `pos: [f64; 3]`: The computed intersection point.
  - `normal: [f64; 3]`: The normalized gradient at the intersection point.
  - `t: f64`: The parameter along the edge $[0, 1]$ where the intersection occurs [S1, unofficial].

**Steps:**

1. **Initialization:**
   - Extract `iso_value` from `octree.iso_value` [S1, unofficial].
   - Extract `max_depth` from `octree.max_depth` [S1, unofficial].
   - Calculate `cell_size_at_max` as `octree.bounds.size / (1u32 << max_depth)` [S1, unofficial].

2. **Collect Sign-Change Edges:**
   - Iterate over all leaf cells in the octree [S1, unofficial].
   - For each leaf cell, iterate over its 12 edges [S1, unofficial].
   - For each edge, identify the two corner vertices `c0` and `c1` [S1, unofficial].
   - Compute signed values: `v0 = corner_values[c0] - iso_value` and `v1 = corner_values[c1] - iso_value` [S1, unofficial].
   - If `(v0 < 0.0) != (v1 < 0.0)`, a sign change exists [S1, unofficial].
   - Record the edge endpoints `p0 = bounds.corner(c0)`, `p1 = bounds.corner(c1)`, `v0`, `v1`, `leaf_idx`, `edge`, and `comp_id` (derived from connected component analysis of the cell's corner mask) in a list of `EdgeCrossing` structs [S1, unofficial].

3. **Bisection Refinement:**
   - Initialize arrays `lo_t` and `hi_t` of size `num_crossings` to `[0.0, 1.0]` [S1, unofficial].
   - Initialize `lo_val` with the `v0` values from the collected edges [S1, unofficial].
   - Perform 10 bisection iterations (or 8 as per some implementations, see [Operating characteristics]) [S1, unofficial]:
     - For each crossing `i`:
       - Compute midpoint parameter: `mid_t = (lo_t[i] + hi_t[i]) * 0.5` [S1, unofficial].
       - Compute 3D position: `pos = p0 + mid_t * (p1 - p0)` [S1, unofficial].
     - Batch evaluate the implicit function at all `pos` points [S1, unofficial].
     - For each crossing `i`:
       - Compute `mid_val = result.values[i] - iso_value` [S1, unofficial].
       - If `(mid_val < 0.0) == (lo_val[i] < 0.0)`:
         - `lo_t[i] = mid_t`
         - `lo_val[i] = mid_val`
       - Else:
         - `hi_t[i] = mid_t` [S1, unofficial].

4. **Compute Final Intersection Points:**
   - For each crossing `i`:
     - `t = (lo_t[i] + hi_t[i]) * 0.5` [S1, unofficial].
     - `pos = p0 + t * (p1 - p0)` [S1, unofficial].

5. **Compute Normals:**
   - Batch evaluate the implicit function at all final `pos` points to obtain gradients [S1, unofficial].
   - If gradients are available:
     - For each gradient `g`:
       - If `len(g) > 1e-12`: `normal = g / len(g)` [S1, unofficial].
       - Else: `normal = [0.0, 0.0, 1.0]` [G] (Guard against zero-length gradients).
   - If gradients are not available:
     - Estimate gradients using finite differences with step size `cell_size_at_max * 0.01` [S1, unofficial].
     - Normalize estimated gradients using the same logic [S1, unofficial].

6. **Store Hermite Data:**
   - Create `HermitePoint` structs with `pos`, `normal`, and `t` [S1, unofficial].
   - Store in `octree.hermite_data` associated with the leaf and edge index [S1, unofficial].

**Pseudocode:**

```python
# Standard edge corner indices for a cube (0-7)
EDGE_CORNERS = [
    (0,1), (2,3), (4,5), (6,7),  # x-edges
    (0,2), (1,3), (4,6), (5,7),  # y-edges
    (0,4), (1,5), (2,6), (3,7)   # z-edges
]

def compute_hermite_data(octree, iso_value, func):
    max_depth = octree.max_depth
    cell_size_at_max = octree.bounds.size / (1 << max_depth)
    
    # Step 2: Collect sign-change edges
    all_edges = []
    for leaf_idx, leaf in enumerate(octree.leaves):
        for edge in range(12):
            c0, c1 = EDGE_CORNERS[edge]
            v0 = leaf.corner_values[c0] - iso_value
            v1 = leaf.corner_values[c1] - iso_value
            
            if (v0 < 0.0) != (v1 < 0.0):
                p0 = leaf.bounds.corner(c0)
                p1 = leaf.bounds.corner(c1)
                # Initial guess via linear interpolation
                denom = v1 - v0
                if abs(denom) < 1e-15:
                    t = 0.5
                else:
                    t = -v0 / denom
                t = max(0.0, min(1.0, t))
                all_edges.append({'p0': p0, 'p1': p1, 'v0': v0, 'v1': v1, 't': t})
    
    num_crossings = len(all_edges)
    if num_crossings == 0:
        return []
    
    # Step 3: Bisection Refinement
    lo_t = [0.0] * num_crossings
    hi_t = [1.0] * num_crossings
    lo_val = [edge['v0'] for edge in all_edges]
    
    # 10 iterations for ~1/1024 cell accuracy
    for _ in range(10):
        mid_points = []
        for i in range(num_crossings):
            mid_t = (lo_t[i] + hi_t[i]) * 0.5
            mid_points.append(lerp3(all_edges[i]['p0'], all_edges[i]['p1'], mid_t))
        
        result = func.batch_evaluate(mid_points)
        
        for i in range(num_crossings):
            mid_val = result.values[i] - iso_value
            mid_t = (lo_t[i] + hi_t[i]) * 0.5
            if (mid_val < 0.0) == (lo_val[i] < 0.0):
                lo_t[i] = mid_t
                lo_val[i] = mid_val
            else:
                hi_t[i] = mid_t
    
    # Step 4: Final Points
    crossing_points = []
    for i in range(num_crossings):
        t = (lo_t[i] + hi_t[i]) * 0.5
        crossing_points.append(lerp3(all_edges[i]['p0'], all_edges[i]['p1'], t))
    
    # Step 5: Normals
    if crossing_points:
        result = func.batch_evaluate(crossing_points)
        if result.gradients:
            normals = [normalize3(g) for g in result.gradients]
        else:
            fd_grads = func.estimate_gradients_fd(crossing_points, cell_size_at_max * 0.01)
            normals = [normalize3(g) for g in fd_grads]
    else:
        normals = []
    
    # Step 6: Store Hermite Data
    hermite_data = []
    for i in range(num_crossings):
        t = (lo_t[i] + hi_t[i]) * 0.5
        hermite_data.append({
            'pos': crossing_points[i],
            'normal': normals[i],
            't': t,
            'leaf_idx': all_edges[i]['leaf_idx'],
            'edge': all_edges[i]['edge']
        })
    
    return hermite_data

def lerp3(p0, p1, t):
    return [p0[j] + t * (p1[j] - p0[j]) for j in range(3)]

def normalize3(v):
    len_v = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    if len_v > 1e-12:
        return [v[j] / len_v for j in range(3)]
    return [0.0, 0.0, 1.0]
```

**Parameters:**
- `iso_value`: The scalar value defining the isosurface [S1, unofficial].
- `max_depth`: The maximum depth of the octree [S1, unofficial].
- `bisection_iters`: Number of bisection iterations. Value: 10. Context: Provides ~1/1024 cell accuracy, though the reference implementation uses 8 iterations for ~1/256 accuracy [S1, unofficial].
- `cell_size_at_max`: The physical size of a cell at the maximum octree depth. Used for finite difference step size [S1, unofficial].

**Edge Cases and Pitfalls:**
- **No Sign Change:** If no sign change exists on an edge, no Hermite data is computed for that edge [S1, unofficial].
- **Division by Zero:** In linear interpolation (if used as initial guess), if `|v1 - v0| < 1e-15`, the denominator is near zero. Handled by defaulting `t` to 0.5 [S1, unofficial].
- **Zero-Length Gradient:** If the gradient magnitude is `< 1e-12`, normalization fails. Handled by defaulting the normal to `[0.0, 0.0, 1.0]` [S1, unofficial].

## Subtopics

### [Edge Completeness Enforcement](825-edge-completeness-enforcement.md)
Edge Completeness Enforcement is a post-processing step in adaptive octree surface extraction that ensures all edges with sign changes possess complete 4-cell neighborhoods at the same depth, thereby eliminating geometric gaps at depth boundaries. It differs from its parent, Hermite Data Computation via Bisection, by focusing on topological consistency of the grid structure rather than the precise computation of intersection points and normals.

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of leaf cells and edges. Bisection adds a constant factor (10 iterations) per edge crossing [S1, unofficial].
- **Memory Complexity:** Linear with respect to the number of edge crossings [S1, unofficial].
- **Measured Performance:** 8 bisection iterations provide ~1/256 cell accuracy, which is sufficient for many cases, but 10 iterations are recommended for curved sharp edges (cylinders, chamfers) to avoid visible jaggedness [S1, unofficial].
- **Strengths:** High precision intersection points, essential for dual contouring and QEF-based vertex placement. Handles adaptive octrees effectively [S1, unofficial].
- **Limitations:** Requires batch evaluation of the implicit function. Finite difference gradient estimation adds overhead if analytical gradients are not available [S1, unofficial].
- **When to Use:** When high-precision isosurface extraction is required, particularly for dual contouring [S1, unofficial].
- **When Not to Use:** When performance is critical and lower precision is acceptable (e.g., simple Marching Cubes) [S1, unofficial].

## Background
Originated in the context of adaptive octree surface extraction for implicit functions, specifically for dual contouring methods [S1, unofficial]. The method was developed to address the limitations of linear interpolation in finding edge crossings, which can introduce visible artifacts on curved surfaces [S1, unofficial].
