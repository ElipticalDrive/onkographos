# Bounding-Sphere Tree Traversal with Frame-Rate Control

Also called: Adaptive Tree Traversal with Frame-Rate Control, Visibility Culling Tests

## Overview
This method renders hierarchical Shell and Solid tree structures by traversing bounding-sphere nodes and projecting them as splats, using adaptive refinement to maintain real-time performance [S1, unofficial]. It distinguishes itself from standard octree traversal by decoupling geometric precision from rendering cost through dynamic pixel-size thresholds ($\delta_r, \delta_b$) and employing specific culling tests (view-frustum, back-face, occlusion) optimized for point-based primitives rather than ray-marching [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Root node of a hierarchical tree (Shell or Solid), camera parameters (view frustum), current frame rate.
*   **Output:** Rendered splats on the screen.

**Data Structures:**
*   **Tree Nodes:** Stored breath-first in physical memory to allow fast recursive refinements and progressive loading [S1, unofficial].
*   **Node Attributes:** Bounding sphere radius, type (Leaf, Regular, Boundary, Shell, Solid), and for Shell nodes, hierarchically encoded normal vectors and bounding normal cones [S1, unofficial].
*   **Parameters:**
    *   $\delta_r$: Global minimum regular splat size in pixels [S1, unofficial].
    *   $\delta_b$: Global minimum boundary splat size in pixels [S1, unofficial].

**Steps:**
1.  **Frame-Rate Feedback:** Check the current frame rate. If it is too low, increase $\delta_r$ and $\delta_b$ smoothly. If the frame rate is too high (after a completed traversal), $\delta_r$ and $\delta_b$ are allowed to decrease [S1, unofficial]. Note: In the described implementation, these parameters are only allowed to *decrease* after a fully completed tree traversal has resulted in too high frame rates [S1, unofficial].
2.  **TraverseTree(Node):**
    *   For each child of the input node:
        *   **Attribute Decompression:** Perform fast on-the-fly table lookups to decompress the bounding sphere attributes of the child [S1, unofficial].
        *   **Culling Tests:** Apply visibility culling tests. If the child fails any test, ignore it and its descendants [S1, unofficial].
        *   **Screen Size Calculation:** Compute $S$, the screen size of the child's bounding sphere in pixels.
        *   **Leaf Node:** If the child is a leaf, render it as a splat of size $S$ pixels [S1, unofficial].
        *   **Regular Node:** If the child is a regular node and $S < \delta_r$, render it as a splat of size $\delta_r$ pixels [S1, unofficial].
        *   **Boundary Node:** If the child is a boundary node and $S < \delta_b$, render it as a splat of size $\delta_b$ pixels [S1, unofficial].
        *   **Recurse:** Otherwise, call `TraverseTree(child)` [S1, unofficial].

**Culling Tests:**
*   **View-Frustum Culling:**
    *   If the bounding sphere is completely outside the viewing frustum, ignore the node and all its children [S1, unofficial].
    *   If the bounding sphere intersects any plane of the view frustum, traverse to its children [S1, unofficial].
    *   If the bounding sphere is completely inside the view frustum, disable this culling test for all its children [S1, unofficial].
*   **Back-Face Culling:**
    *   **Shell:** Uses hierarchically encoded normal vectors and bounding normal cones to eliminate branches where all nodes point entirely away from the camera [S1, unofficial].
    *   **Solid:** Does not perform hierarchical back-face culling during traversal because normal information depends on the CSG probe. Instead, back-face culling is performed before rendering individual Solid splats using normals derived from the CSG probe [S1, unofficial].
*   **Occlusion Culling:** Hierarchical occlusion culling is considered hard for point-based primitives. Instead, the z-buffer algorithm in graphics hardware is enabled for occlusion culling [S1, unofficial].

**Pseudocode:**
```python
def traverse_tree(node, delta_r, delta_b, camera):
    """
    Recursively traverse the bounding-sphere tree.
    
    Args:
        node: The current tree node.
        delta_r: Minimum regular splat size in pixels.
        delta_b: Minimum boundary splat size in pixels.
        camera: Object containing view frustum planes and frame rate status.
    """
    for child in node.children:
        # 1. Attribute Decompression
        # Fast on-the-fly table lookups to decompress bounding sphere attributes
        sphere = decompress_attributes(child)
        
        # 2. Visibility Culling Tests
        if not passes_culling_tests(child, sphere, camera):
            continue
            
        # 3. Screen Size Calculation
        s = calculate_screen_size(sphere, camera)
        
        # 4. Rendering or Recursion
        if child.is_leaf:
            render_splat(child, s)
        elif child.is_regular and s < delta_r:
            render_splat(child, delta_r)
        elif child.is_boundary and s < delta_b:
            render_splat(child, delta_b)
        else:
            traverse_tree(child, delta_r, delta_b, camera)

def passes_culling_tests(child, sphere, camera):
    """
    Applies view-frustum, back-face, and other culling tests.
    Returns True if the node should be traversed/rendered.
    """
    # View-Frustum Culling
    if is_completely_outside_frustum(sphere, camera.frustum):
        return False
    
    if is_completely_inside_frustum(sphere, camera.frustum):
        # Disable frustum culling for children
        camera.disable_frustum_culling_for_children = True
    else:
        # Intersects plane, traverse to children
        pass
        
    # Back-Face Culling (Shell specific)
    if child.type == "Shell":
        if is_back_faced(sphere, child.normals, camera.position):
            return False
            
    # Note: Solid back-face culling is handled at splat rendering time
    # Occlusion culling is handled by hardware z-buffer
    
    return True

def adjust_frame_rate_parameters(delta_r, delta_b, current_frame_rate, target_frame_rate):
    """
    Adjusts delta parameters based on frame rate feedback.
    Note: Decrease only allowed after fully completed traversal.
    """
    if current_frame_rate < target_frame_rate:
        # Increase splat sizes to reduce load
        delta_r = smooth_increase(delta_r)
        delta_b = smooth_increase(delta_b)
```

## Operating characteristics
*   **Time Complexity:** Depends on tree depth and culling efficiency. Breath-first storage aids cache locality [S1, unofficial].
*   **Memory:** Progressive loading of data structures reduces physical memory usage by only loading parts of the data structure actually rendered [S1, unofficial].
*   **Performance:** Designed for real-time rendering of large volumetric datasets [S1, unofficial].
*   **Strengths:** Adaptive frame-rate control ensures consistent performance; efficient culling tests reduce unnecessary traversal [S1, unofficial].
*   **Limitations:** Occlusion culling is not hierarchical, relying on hardware z-buffer [S1, unofficial]. Solid nodes lack hierarchical back-face culling [S1, unofficial].

## Background
The method was introduced by Museth and Lombeyna in 2004 for the "TetSplat" system, which renders and clips large volumetric datasets in real-time [S1, unofficial]. It addresses the challenge of rendering complex Shell and Solid structures while allowing dynamic volumetric clipping via CSG probes [S1, unofficial].
