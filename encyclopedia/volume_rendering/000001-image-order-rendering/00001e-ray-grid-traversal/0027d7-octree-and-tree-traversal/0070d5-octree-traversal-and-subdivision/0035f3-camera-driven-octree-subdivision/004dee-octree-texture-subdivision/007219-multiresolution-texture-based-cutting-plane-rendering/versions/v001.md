# Multiresolution Texture-Based Cutting Plane Rendering

Also called: Adaptive Octree Cutting Plane Rendering, High/Low Texture Tile Blending

## Overview
Multiresolution Texture-Based Cutting Plane Rendering is an adaptive scheme for rendering arbitrarily oriented cutting planes through large volumetric data sets at varying resolutions [S1]. It solves the problem of interactive visualization of massive datasets by rendering high-resolution detail near a point-of-interest and lower-resolution data in distant or low-importance regions, blending between levels to reduce artifacts [S1]. Unlike prior algorithms that assume data is uniformly complex or uniformly important, this method treats quality as a tunable parameter based on visual importance, such as distance from the viewer [S1]. It builds on [Octree Texture Subdivision](13613-octree-texture-subdivision.md) by introducing a specific high/low tile blending mechanism to smooth transitions between the octree levels during cutting plane extraction.

## How it works
### Inputs and Outputs
**Inputs:**
*   A volumetric data set.
*   A cutting plane defined by its position and orientation.
*   A point-of-interest (or viewer location) to determine visual importance [S1].

**Outputs:**
*   A blended 2D image of the cutting plane intersection with the volume [S1].

### Data Structures
The core data structure is an octree decomposing texture space [S1].
*   **Octree Nodes:** Each node contains two texture tiles:
    *   **High Tile:** Stores the node's copy of the data at its specific resolution level [S1].
    *   **Low Tile:** Stores the portion of the *parent's* high tile that covers the same area as the current node [S1].
*   **Tile Sizes:** The size relationship between the high and low tiles is defined by the formula:
    $$ |high| = |low| * 2 - 1 $$
    where $|high|$ is the size (number of elements) of the high tile and $|low|$ is the size of the low tile [S1]. This implies one tile must have an odd size. If power-of-two sizes are required for hardware compatibility, the low tile is set to a power-of-two size, and the high tile size is calculated accordingly, incurring memory overhead [S1].
*   **Selected Node Tree:** An incomplete octree formed during traversal, containing only nodes selected for rendering [S1].

### Algorithm Steps

1.  **Construct the Texture Hierarchy:**
    *   Decompose texture space into an octree [S1].
    *   Each level of the octree corresponds to a resolution level, where each level is half the resolution of the next finer level [S1].
    *   Leaf nodes are associated with the original data resolution [S1].
    *   The root node is associated with the coarsest resolution [S1].
    *   Interior nodes are created by subsampling the eight child nodes [S1].
    *   For each node, generate the **High Tile** (the node's own data) and the **Low Tile** (the subset of the parent's High Tile covering the node's area) [S1].

2.  **Traverse and Select Nodes:**
    *   Traverse the octree and apply a selection filter to each node based on visual importance (e.g., distance from point-of-interest) [S1].
    *   Build a 'selected node tree'. For each node, one of three outcomes occurs:
        1.  The node and its children are skipped entirely.
        2.  The node is skipped, but its children are visited.
        3.  The node is rendered, and its children are skipped [S1].

3.  **Balance the Selected Node Tree:**
    *   Ensure that all adjacent nodes in the selected tree differ by no more than one level of resolution in the octree [S1].
    *   *Pitfall:* Blending is only possible between nodes differing by exactly one level of resolution. Nodes differing by two or more levels do not share textures and cannot be blended directly [S1]. This balancing step is necessary to ensure valid blending pairs exist [S1].

4.  **Determine Corner Blend Ratios:**
    *   Examine the neighbors of all selected nodes [S1].
    *   For each corner of a given selected node, check the seven adjacent nodes (across faces, edges, and corners) [S1].
    *   If any adjacent node exists and has a *lower* resolution than the current node, set the corner's blend ratio to **1** (selecting the low tile) [S1].
    *   Otherwise, set the corner's blend ratio to **0** (selecting the high tile) [S1].

5.  **Calculate Edge Blend Ratios:**
    *   For each edge of the selected node, calculate the blend ratio for points along the edge [S1].
    *   The value is a linear combination of the ratios at the ends of that edge, proportional to the position of the point along the edge [S1].

6.  **Render First Weighted Image (Low Tile):**
    *   Download the **Low** texture tile for the selected node [S1].
    *   For each vertex of the clipped cutting plane polygon intersecting the node, define the RGB color value to be equal to the calculated blend ratio at that vertex [S1].
    *   Draw the polygon. The hardware interpolates the color values across the polygon, effectively multiplying the texture by the blend ratio [S1]. This produces the first weighted image [S1].

7.  **Render Second Weighted Image (High Tile):**
    *   Download the **High** texture tile for the selected node [S1].
    *   For each vertex of the clipped cutting plane polygon, define the RGB color value to be **1 minus the blend ratio** [S1].
    *   Draw the polygon. This produces the second weighted image [S1].

8.  **Produce Final Blended Result:**
    *   Add the first weighted image and the second weighted image together [S1].

    octree = build_octree(volume_data)
    for node in octree.all_nodes:
        node.high_tile = node.generate_high_tile()
        node.low_tile = node.parent.high_tile.get_subset(node.bounding_box)
        
    # Step 2: Traverse and Select Nodes
    selected_nodes = []

        importance = calculate_importance(node, point_of_interest)
        if importance < threshold:
            # Case 1: Skip node and children
            return
        elif importance < high_threshold:
            # Case 2: Skip node, visit children
            for child in node.children:
                traverse_and_select(child)
        else:
            # Case 3: Render node, skip children
            selected_nodes.append(node)
            
    traverse_and_select(octree.root)
    
    # Step 3: Balance Selected Node Tree
    # Ensure adjacent selected nodes differ by at most 1 level
    balance_tree(selected_nodes)
    
    # Step 4 & 5: Determine Blend Ratios
    # Pre-calculate corner ratios for all selected nodes
    for node in selected_nodes:
        for corner in node.corners:
            adjacent_nodes = get_26_neighbors(node, corner)
            # Check if any adjacent node has lower resolution
            has_lower_neighbor = any(
                n in selected_nodes and n.resolution_level > node.resolution_level 
                for n in adjacent_nodes
            )
            corner.ratio = 1.0 if has_lower_neighbor else 0.0
            
        # Calculate edge ratios based on corner ratios
        for edge in node.edges:
            edge.ratio = linear_interpolate(edge.start.ratio, edge.end.ratio, edge.position)
            
    # Step 6, 7, 8: Render Blended Image
    final_image = zeros_like(cutting_plane_screen_coords)

        # Clip cutting plane to node's bounding box
        clipped_polygon = clip_polygon_to_node(cutting_plane, node)

        # Get blend ratios for clipped polygon vertices

## Operating characteristics
*   **Time Complexity:** Rendering time is significantly reduced compared to fixed-resolution rendering. On an SGI Onyx2 with a 195MHz R10K processor, rendering the 'Visible Female' data set ($256^3$ RGB) reduced rendering time from 12.0 seconds (fixed resolution) to 0.37 seconds (multiresolution) [S1].
*   **Memory/Transfer Complexity:** The method reduces the amount of data accessed and transmitted. For the 'Visible Female' data set, bytes transmitted were reduced from 56MB to 7MB [S1]. The number of rendered nodes dropped from 443 (fixed) to 50 (multiresolution) [S1].
*   **Strengths:**
    *   Allows adaptive rendering where quality is a tunable parameter based on visual importance [S1].
    *   Reduces artifacts introduced by resolution changes through blending [S1].
    *   Suitable for data mining or visual steering applications where the point-of-interest is unknown or changes frequently [S1].
*   **Limitations:**
    *   Requires balancing the octree to ensure adjacent nodes differ by at most one level, adding preprocessing complexity [S1].
    *   If power-of-two tile sizes are required, the high tile size calculation incurs memory overhead [S1].
    *   Blending is limited to adjacent nodes differing by exactly one resolution level; larger gaps cannot be blended directly [S1].
*   **When to use:** When rendering large volumetric datasets interactively, especially when the viewer's focus or point-of-interest varies, or when bandwidth/memory is constrained [S1].
*   **When not to use:** When uniform high resolution is required across the entire volume, or when the hardware does not support the required texture blending operations [S1].

## Background
*   **Origin:** The method was presented by researchers from Lawrence Livermore National Laboratory and the University of California, Davis [S1].
*   **Paper:** "Multiresolution Techniques for Interactive Texture-Based Rendering of Arbitrarily Oriented Cutting Planes" [S1].
*   **History:** The technique was developed to address the limitations of prior algorithms that assumed data was "uniformly complex" or "uniformly important" [S1]. It was designed for immersive environments where data closer to the viewer has more visual importance [S1].
*   **Applications:** Data mining, visual steering, and progressive visualization where data sets are too large for a single system and portions are distributed across a network [S1].
