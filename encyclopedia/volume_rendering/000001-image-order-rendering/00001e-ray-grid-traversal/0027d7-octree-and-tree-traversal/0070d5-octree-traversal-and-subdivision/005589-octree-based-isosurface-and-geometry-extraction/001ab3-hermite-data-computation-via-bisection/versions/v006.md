# Hermite Data Computation via Bisection

Also called: Bisection-based Hermite Data Computation, Edge Crossing Detection with Bisection

## Overview
Hermite Data Computation via Bisection is a method for finding all edge crossings in an adaptive octree for an implicit function and computing Hermite data (intersection points and normals) by refining linear interpolation guesses with bisection [S1, unofficial]. It differs from its sibling [Tree Marcher](7534-tree-marcher.md) by providing high-precision intersection locations necessary for dual contouring, whereas Tree Marcher typically focuses on marching through the grid to generate triangles directly. It differs from [Tetrahedralization of Octree Cells](9049-tetrahedralization-of-octree-cells.md) by operating on the octree's edge structure rather than subdividing cells into tetrahedra, allowing it to handle adaptive depth boundaries without geometric artifacts [S1, unofficial].

## How it works
**Inputs:**
- An adaptive octree containing leaf cells, each with corner values of an implicit function $f(x)$ and bounds.
- The `iso_value` defining the isosurface.
- The `max_depth` of the octree.
- The implicit function evaluator (and optionally its gradient).

**Outputs:**
- A list of `HermitePoint` structures, each containing the 3D position of the intersection, the surface normal, and the parameter $t$ along the edge.

**Data Structures:**
- `EdgeCrossing`: A struct representing a detected sign change on an edge.
  - `p0: [f64; 3]`: World coordinates of the first corner of the edge.
  - `p1: [f64; 3]`: World coordinates of the second corner of the edge.
  - `v0: f64`: Signed function value at `p0` ($f(p0) - \text{iso\_value}$).
  - `v1: f64`: Signed function value at `p1` ($f(p1) - \text{iso\_value}$).
  - `leaf_idx: usize`: Index of the leaf cell containing this edge.
  - `edge: u8`: Index of the edge within the cell (0–11).
  - `comp_id: u8`: Component ID for multi-component cells (derived from connected component analysis).
- `HermitePoint`: The final output structure.
  - `pos: [f64; 3]`: Computed intersection position.
  - `normal: [f64; 3]`: Normalized gradient at `pos`.
  - `t: f64`: Parameter along the edge, in $[0.0, 1.0]$.

**Steps:**

1. **Initialization:**
   - Retrieve `iso_value` and `max_depth` from the octree.
   - Calculate `cell_size_at_max` as:
     $$ \text{cell\_size\_at\_max} = \frac{\text{octree.bounds.size}}{2^{\text{max\_depth}}} $$
   - Initialize lists for bisection intervals and values.

2. **Edge Crossing Detection:**
   - Iterate over all leaf cells in the octree.
   - For each leaf cell, iterate over its 12 edges.
   - For each edge, identify the two corner vertices ($c_0, c_1$).
   - Compute signed values:
     $$ v_0 = f(p_0) - \text{iso\_value} $$
     $$ v_1 = f(p_1) - \text{iso\_value} $$
   - If a sign change is detected ($v_0 < 0.0 \neq v_1 < 0.0$), create an `EdgeCrossing` record with `p0`, `p1`, `v0`, `v1`, `leaf_idx`, `edge`, and `comp_id`. The `comp_id` is determined by a connected component analysis of the cell's corner mask [S1, unofficial].
   - Collect all such edges into a global list `all_edges`.

3. **Bisection Refinement:**
   - Initialize bisection intervals for each crossing:
     - $lo = 0.0$, $hi = 1.0$
     - $lo\_val = v_0$, $hi\_val = v_1$
   - Compute an initial guess for $t$ using linear interpolation:
     $$ t = \frac{-v_0}{v_1 - v_0} $$
     If $|v_1 - v_0| < 10^{-15}$, set $t = 0.5$ [S1, unofficial].
   - Clamp $t$ to $[0.0, 1.0]$.
   - Perform 10 bisection iterations (or 8 in some implementations [S1, unofficial]):
     1. Compute midpoint parameter:
        $$ t_{mid} = \frac{lo + hi}{2} $$
     2. Compute 3D position:
        $$ pos = p_0 + t_{mid} \times (p_1 - p_0) $$
     3. Batch evaluate the implicit function at all midpoints to get $f(pos)$.
     4. Compute signed midpoint value:
        $$ mid\_val = f(pos) - \text{iso\_value} $$
     5. Update interval:
        - If $mid\_val$ and $lo\_val$ have the same sign:
          $$ lo = t_{mid}, \quad lo\_val = mid\_val $$
        - Else:
          $$ hi = t_{mid}, \quad hi\_val = mid\_val $$

4. **Final Intersection Computation:**
   - After bisection, compute the final $t$:
     $$ t_{final} = \frac{lo + hi}{2} $$
   - Compute the final position:
     $$ pos = p_0 + t_{final} \times (p_1 - p_0) $$

5. **Normal Computation:**
   - If gradients are available from the batch evaluation, normalize them:
     $$ \text{normal} = \frac{\nabla f(pos)}{\|\nabla f(pos)\|} $$
     If $\|\nabla f(pos)\| < 10^{-12}$, default normal to $[0.0, 0.0, 1.0]$ [S1, unofficial].
   - If gradients are not available, estimate them using finite differences with step size $h = \text{cell\_size\_at\_max} \times 0.01$. Normalize the estimated gradients using the same logic.

6. **Storage:**
   - Store the `HermitePoint` (pos, normal, t) in the octree's `hermite_data` structure, associated with the leaf and edge index.

**Pseudocode:**

```python
def compute_hermite_data(octree, iso_value, max_depth, func_evaluator):
    """
    Computes Hermite data (intersection points and normals) for all edge crossings
    in an adaptive octree using bisection refinement.
    """
    # Step 1: Initialization
    cell_size_at_max = octree.bounds.size / (1 << max_depth)
    all_edges = []
    
    # Step 2: Edge Crossing Detection
    for leaf_idx, leaf in enumerate(octree.leaves):
        # Perform connected component analysis to get comp_id for each edge
        components = get_cell_components(leaf.corner_mask)
        
        for edge_idx in range(12):
            c0, c1 = CubicBounds.edge_corners(edge_idx)
            p0 = leaf.bounds.corner(c0)
            p1 = leaf.bounds.corner(c1)
            
            v0 = leaf.corner_values[c0] - iso_value
            v1 = leaf.corner_values[c1] - iso_value
            
            # Check for sign change
            if (v0 < 0.0) != (v1 < 0.0):
                comp_id = edge_component(components, leaf.corner_mask, edge_idx)
                all_edges.append({
                    'p0': p0,
                    'p1': p1,
                    'v0': v0,
                    'v1': v1,
                    'leaf_idx': leaf_idx,
                    'edge': edge_idx,
                    'comp_id': comp_id
                })
    
    num_crossings = len(all_edges)
    if num_crossings == 0:
        return []
    
    # Step 3: Bisection Refinement
    lo_t = [0.0] * num_crossings
    hi_t = [1.0] * num_crossings
    lo_val = [edge['v0'] for edge in all_edges]
    
    # 10 iterations for high precision
    for _ in range(10):
        mid_points = []
        for i in range(num_crossings):
            t = (lo_t[i] + hi_t[i]) * 0.5
            pos = lerp3(all_edges[i]['p0'], all_edges[i]['p1'], t)
            mid_points.append(pos)
        
        # Batch evaluate implicit function
        results = func_evaluator.batch_evaluate(mid_points)
        
        for i in range(num_crossings):
            mid_val = results.values[i] - iso_value
            mid_t = (lo_t[i] + hi_t[i]) * 0.5
            
            if (mid_val < 0.0) == (lo_val[i] < 0.0):
                lo_t[i] = mid_t
                lo_val[i] = mid_val
            else:
                hi_t[i] = mid_t
    
    # Step 4: Final Intersection Computation
    crossing_points = []
    for i in range(num_crossings):
        t = (lo_t[i] + hi_t[i]) * 0.5
        pos = lerp3(all_edges[i]['p0'], all_edges[i]['p1'], t)
        crossing_points.append(pos)
    
    # Step 5: Normal Computation
    if crossing_points:
        # Try to get gradients from evaluator
        results = func_evaluator.batch_evaluate(crossing_points)
        if results.gradients:
            normals = [normalize3(g) for g in results.gradients]
        else:
            # Estimate gradients using finite differences
            fd_step = cell_size_at_max * 0.01
            fd_grads = func_evaluator.estimate_gradients_fd(crossing_points, fd_step)
            normals = [normalize3(g) for g in fd_grads]
    else:
        normals = []
    
    # Step 6: Store Hermite Data
    hermite_data = []
    for i in range(num_crossings):
        t = (lo_t[i] + hi_t[i]) * 0.5
        normal = normals[i] if normals else [0.0, 0.0, 1.0]
        hermite_data.append({
            'pos': crossing_points[i],
            'normal': normal,
            't': t,
            'leaf_idx': all_edges[i]['leaf_idx'],
            'edge': all_edges[i]['edge'],
            'comp_id': all_edges[i]['comp_id']
        })
    
    return hermite_data

def lerp3(p0, p1, t):
    return [p0[j] + t * (p1[j] - p0[j]) for j in range(3)]

def normalize3(v):
    length = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    if length < 1e-12:
        return [0.0, 0.0, 1.0]
    return [v[j] / length for j in range(3)]
```

**Parameters:**
- `iso_value`: The scalar value defining the isosurface.
- `max_depth`: The maximum depth of the octree.
- `bisection_iters`: Number of bisection iterations. Value: 10. Context: Provides ~1/1024 cell accuracy [S1, unofficial].
- `cell_size_at_max`: The physical size of a cell at the maximum octree depth. Used for finite difference step size.

**Edge Cases and Pitfalls:**
- **No Sign Change:** If no sign change exists on an edge, no Hermite data is computed for that edge [S1, unofficial].
- **Division by Zero:** In linear interpolation, if $|v_1 - v_0| < 10^{-15}$, the denominator is near zero. Handled by defaulting $t$ to 0.5 [S1, unofficial].
- **Zero-Length Gradient:** If the gradient magnitude is $< 10^{-12}$, normalization fails. Handled by defaulting the normal to $[0.0, 0.0, 1.0]$ [S1, unofficial].

## Subtopics

### [Edge Completeness Enforcement](825-edge-completeness-enforcement.md)
Edge Completeness Enforcement is a post-processing step in adaptive octree surface extraction that ensures all edges with sign changes possess complete 4-cell neighborhoods at the same depth, thereby eliminating geometric gaps at depth boundaries. It differs from its parent, Hermite Data Computation via Bisection, by focusing on topological consistency of the grid structure rather than the precise computation of intersection points and normals.

## Operating characteristics
- **Time Complexity:** $O(E \times I)$, where $E$ is the number of edge crossings and $I$ is the number of bisection iterations. The batch evaluation of the implicit function is the dominant cost.
- **Memory Complexity:** $O(E)$ to store the edge crossings and Hermite data.
- **Measured Performance:** 8 bisection iterations provide ~1/256 cell accuracy, which is essential for curved sharp edges (cylinders, chamfers) where linear interpolation from corner values introduces visible jaggedness [S1, unofficial]. 10 iterations provide ~1/1024 cell accuracy.
- **Strengths:** High precision intersection points suitable for dual contouring and QEF vertex placement. Handles adaptive octrees efficiently by only processing leaf cells.
- **Limitations:** Requires batch evaluation of the implicit function, which may be costly for complex functions. Relies on sign changes, so it may miss features if the iso_value is not carefully chosen or if the sampling is too coarse.
- **When to Use:** When high-quality isosurfaces are required, especially for dual contouring, and the implicit function is expensive to evaluate (benefiting from batching).
- **When Not to Use:** When real-time performance is critical and lower precision is acceptable, or when the implicit function cannot be batched efficiently.

## Background
Hermite Data Computation via Bisection is used in adaptive octree surface extraction, particularly in the context of dual contouring. It was implemented in the `isomesh` library by narnia-ai-mason [S1, unofficial]. The method addresses the need for precise intersection points and normals to construct accurate meshes from implicit functions represented in an adaptive octree.
