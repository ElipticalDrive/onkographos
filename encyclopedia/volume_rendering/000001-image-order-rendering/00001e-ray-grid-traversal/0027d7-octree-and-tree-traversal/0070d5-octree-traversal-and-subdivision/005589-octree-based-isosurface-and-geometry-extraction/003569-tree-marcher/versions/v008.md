# Tree Marcher

Also called: Tree Marcher for Generic Grids

## Overview
The Tree Marcher is a hierarchical ray traversal algorithm used to step a ray through an adaptive octree structure (specifically within the OpenVDB/nanovdb framework) to identify intersections with active nodes. It solves the problem of efficiently locating the entry and exit intervals of a ray within non-empty regions of a sparse volume representation, serving as the foundational traversal engine for higher-level operations like zero-crossing detection and geometry extraction. It differs from its siblings, such as [PointTreeMarcher](7535-pointtreemarcher.md), by operating on a generic grid coordinate system without special handling for the coordinate mismatch inherent in point-based grids.

## How it works
The Tree Marcher implements a Digital Differential Analyzer (DDA) specialized for hierarchical data structures. It relies on the parent's empty-space skipping logic to bypass inactive subtrees, focusing computation only on active nodes [Parent](15494-octree-based-isosurface-and-geometry-extraction.md).

### Inputs and Outputs
*   **Input:** An accessor object (`AccT`) providing access to the grid data, and a ray definition (`RayT`) in index space.
*   **Output:** A pointer to the intersected node (`NodeT**`), and the parametric interval of the intersection along the ray (`t0`, `t1`).

### Data Structures and Layout
The class is a template with the following parameters and internal typedefs [S1]:
*   `NodeT`: The type of node being traversed.
*   `RayT`: The ray type, containing ray origin, direction, and inverse direction.
*   `AccT`: The accessor type used for grid access.
*   `CoordT`: The coordinate type (defaults to `Coord`).
*   `ChildT`: Defined as `typename NodeT::ChildNodeType`.
*   `RealType`: Defined as `typename RayT::RealType`.
*   `RealT`: Alias for `RealType`.
*   `CoordType`: Alias for `CoordT`.

### Algorithm Steps
The traversal is controlled by two primary methods: `init` and `step`.

1.  **Initialization:** The `TreeMarcher` is constructed with a reference to the grid accessor. The `init` method is called with an `indexRay`. This prepares the internal state for traversal in index space [S1].
2.  **Stepping:** The `step` method is called repeatedly. It advances the ray through the tree hierarchy.
    *   It uses an underlying Hierarchical DDA (HDDA) to perform empty-space skipping at all levels of the tree [S2].
    *   If the ray intersects a node of type `NodeT`, the method returns `true`.
    *   Upon success, it populates:
        *   `node`: The pointer to the intersected node.
        *   `t0`: The start of the intersection interval.
        *   `t1`: The end of the intersection interval.
    *   If no node of the specified type is intersected (e.g., the ray passes through empty space or hits a different node type), it returns `false` [S1].

The following pseudocode demonstrates the usage pattern of the `TreeMarcher` class as defined in the OpenVDB nanovdb library. It assumes the existence of the `RayT`, `AccT`, and `NodeT` types and the `ZeroCrossing` helper function mentioned in the sources.

    def __init__(self, accessor: AccT):
        """
        Initialize the Tree Marcher with a grid accessor.
        """
        self.marcher = TreeMarcher[NodeT, RayT, AccT, CoordT](accessor)
        self.node_ptr = None
        self.t0 = 0.0
        self.t1 = 0.0

    def process_ray(self, index_ray: RayT):
        """
        Traverse the tree for a given index-space ray.
        """
        # 1. Initialize the marcher with the ray
        if not self.marcher.init(index_ray):
            return False

        # 2. Step through the tree to find intersections
        while True:
            # Attempt to step to the next active node
            hit = self.marcher.step(self.node_ptr, self.t0, self.t1)
            
            if not hit:
                # No more nodes of type NodeT are intersected
                break
            
            # At this point:
            # self.node_ptr points to the intersected node
            # self.t0 is the start of the interval
            # self.t1 is the end of the interval
            
            # Perform further processing, e.g., zero-crossing detection
            # Note: ZeroCrossing is a helper function found in HDDA.h
            # It updates ijk and v if a zero-crossing is detected at the voxel level
            ijk = Coord()
            v = typename AccT::ValueType()
            
            # Check for zero-crossing within the interval [t0, t1]
            # This is a logical extension based on [S2] describing ZeroCrossing
            # The actual implementation of ZeroCrossing logic is not fully detailed
            # in the provided snippets, but it operates on the ray and accessor.
            has_zero_crossing = ZeroCrossing(self.marcher.ray(), accessor, ijk, v, self.t0)
            
            if has_zero_crossing:

### Parameters and Edge Cases
*   **Coordinate System:** The algorithm operates in index space. The ray is defined in index coordinates [S1].
*   **Empty Space:** The underlying HDDA handles empty-space skipping. If a ray passes entirely through empty space, `step` will return `false` [S2].
*   **Node Type Matching:** The `step` function specifically looks for nodes of type `NodeT`. If the ray intersects a node of a different type (e.g., a leaf node when searching for an internal node), it may return `false` or continue stepping depending on the hierarchy [S1].
*   **Precision:** The use of `float` for `t0` and `t1` suggests single-precision parametric intervals. Care must be taken with precision near boundaries [S1].

## Subtopics

### [PointTreeMarcher](7535-pointtreemarcher.md)
A specialized variant for point grids that handles the coordinate system mismatch between bucketed grid cells and voxel corners. Choose this when working with point-based volume representations in OpenVDB.

## Operating characteristics
*   **Time Complexity:** The traversal time is proportional to the number of active nodes intersected by the ray. Empty subtrees are skipped, making it efficient for sparse data. The exact complexity depends on the tree depth and the distribution of active nodes.
*   **Memory Complexity:** The algorithm requires minimal additional memory, primarily storing the current node pointer and interval parameters. The tree structure itself is stored in the grid.
*   **Strengths:** Efficient handling of sparse data via hierarchical traversal; generic interface allowing reuse across different node types; integrated with OpenVDB's accessor model.
*   **Limitations:** Limited to the specific data structures and types supported by OpenVDB/nanovdb; requires understanding of the node hierarchy to interpret results correctly.
*   **When to Use:** Use when you need to traverse an OpenVDB grid to find active nodes along a ray, particularly as a precursor to more detailed sampling or geometry extraction.
*   **When Not to Use:** Do not use for point grids; use [PointTreeMarcher](7535-pointtreemarcher.md) instead. Do not use if you need direct voxel-level zero-crossing detection without further processing; use `ZeroCrossing` helper in conjunction with this or similar methods.

## Background
The Tree Marcher is part of the OpenVDB library, specifically within the `nanovdb` namespace, which provides a compact, GPU-friendly representation of VDB grids. It was developed to support efficient ray traversal for volume rendering and geometry extraction on sparse, adaptive grids. The class is documented in the OpenVDB API reference [S1]. The underlying traversal logic relies on the Hierarchical Digital Differential Analyzer (HDDA) [S2].
