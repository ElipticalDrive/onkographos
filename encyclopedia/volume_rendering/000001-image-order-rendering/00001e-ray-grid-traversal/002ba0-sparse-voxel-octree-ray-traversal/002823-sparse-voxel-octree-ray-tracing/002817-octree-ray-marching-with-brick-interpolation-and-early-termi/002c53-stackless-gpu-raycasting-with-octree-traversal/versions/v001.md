# Stackless GPU Raycasting with Octree Traversal

Also called: Stackless octree traversal on the GPU

## Overview
This method performs volume rendering by traversing a Sparse Voxel Octree (SVO) on the GPU without using a stack, computing the volume rendering integral in front-to-back order. It solves the problem of efficient memory access and traversal overhead in sparse volumetric data by combining space-skipping (via empty node detection) with adaptive sampling density. It sets itself apart from sibling methods like [Two-staged Space-Skipping with Bricking and Octrees](5210-two-staged-space-skipping-with-bricking-and-octrees.md) by performing neighbor lookups implicitly on-the-fly using the octree's regular structure, rather than relying on precomputed neighbor pointers or a two-stage bricking pipeline. It builds on the concepts of [Octree Ray Marching with Brick Interpolation and Early Termination](4147-octree-ray-marching-with-brick-interpolation-and-early-termi.md) but replaces explicit brick interpolation with adaptive sampling based on leaf resolution.

## How it works
The algorithm maintains the state of the current ray segment (entry point $t_{min}$, current node pointer, current bounding box, and octree level) in registers. It traverses the octree from the root to the leaf containing the current sampling point, accumulates color/opacity if the leaf is non-empty, and moves to the next leaf via implicit neighbor calculation when the ray exits the current box.

### Inputs and Outputs
*   **Inputs:**
    *   Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (in texture coordinates, normalized to $[0,1]^3$).
    *   Spatial Index Texture: A 3D texture storing the octree structure. Each texel is a `float4` (or `vec4`).
    *   Leaf Data Texture: A 3D texture storing the actual volume data (density/color) for non-empty leaves.
    *   Transfer Function: A 2D texture mapping density and octree level to color and opacity.
*   **Outputs:**
    *   `fragment.color`: Accumulated RGBA color.
    *   `fragment.depth`: Depth of the first opaque surface encountered (or far plane).

### Data Structures
**Spatial Index Texture Texel Layout (`float4`):**
*   `xyz`: Pointer to the first child node (for inner nodes) or to the leaf data (for leaf nodes). Stored as a 3D coordinate offset in the texture.
*   `w`: Tag/Status.
    *   If `w` indicates an **Inner Node**: The `xyz` components point to children. The children are stored consecutively in the texture. The offset to the $i$-th child (where $i \in [0,7]$) is calculated as `dot3(s, float3(1, 2, 4)) * texel_sz`, where `s` is the child index vector.
    *   If `w` indicates a **Leaf Node**: The `xyz` components point to the leaf data in the Leaf Data Texture. The `w` component encodes the octree level of the neighbor (see Neighbor Traversal).
    *   **Empty Node**: A specific marker (e.g., `w=0` or null pointer) indicating no children or data.
    *   **Null Pointer**: Used to terminate traversal.

**Neighbor Pointers:**
*   Neighbor pointers are not stored explicitly in the index texel for all 6 neighbors in the primary traversal path described in the code snippet, but the text notes that leaf nodes use RGB components to point to leaf information and 6 consecutive texels store pointers to neighbors. However, the *stackless traversal logic* described relies on **implicit** neighbor calculation for the exit face to avoid extra texture fetches. The text states: "computing neighbor information on-the-fly... exploiting the regular structure of the octree."
*   The `w` component of a leaf node's index texel stores the **octree level** of the neighbor in the direction of the exit face. This allows the shader to compute the neighbor's bounding box without fetching the neighbor's index texel first.

### Parameters
*   **Early Termination Threshold:** Opacity $\alpha_{thresh} = 0.99$. If accumulated opacity exceeds this, the ray terminates.
*   **Box Normalization:** All computations are done in texture coordinates. The octree subdivides the unit cube $[0,1]^3$.
*   **Sampling:** Adaptive. Step size is determined by the resolution of the current leaf (box dimension).

### Edge Cases and Pitfalls
*   **Null Pointers:** The last leaf data texel always contains a NULL pointer. This is used to simplify handling of rays that do not exit from the current box (e.g., terminate due to opacity threshold). If traversal reaches a null pointer, the loop terminates.
*   **Coarser Neighbors:** When moving to a neighbor with a coarser octree level, the current box must be coarsened. This is done by updating `box_dim` to $2^{-\text{neighbor\_level}}$ and snapping `box_min` to the neighbor's grid: $\lfloor \text{box\_min} / \text{box\_dim} \rfloor \cdot \text{box\_dim}$.
*   **Precision:** All computations are in texture coordinates (unit cube). Floating-point precision issues may arise at deep octree levels.
*   **Termination:** Rays that terminate due to the opacity threshold (0.99) must not continue to neighbors. The null pointer check and the opacity check inside the loop handle this.

## Operating characteristics
*   **Time Complexity:** $O(k)$ per ray, where $k$ is the number of non-empty leaves traversed. The traversal is stackless, reducing memory overhead and instruction count compared to stack-based methods.
*   **Memory Complexity:** $O(N)$ for the octree structure, where $N$ is the number of nodes. The spatial index is stored in a 3D texture.
*   **Performance:** The method is efficient for sparse data because it skips empty space. Adaptive sampling reduces the number of texture fetches for large empty or uniform regions. The on-the-fly neighbor calculation reduces texture memory bandwidth usage compared to methods storing explicit neighbor pointers for all nodes.
*   **Strengths:** No stack required; efficient memory access; adaptive sampling; early termination.
*   **Limitations:** Requires a well-constructed octree; implicit neighbor calculation assumes regular octree structure; may have branch divergence on GPU if rays traverse different paths.

## Background
The method was introduced in "A single-pass GPU ray casting framework for interactive out-of-core volume rendering" (2008) by [S1]. It extends stackless ray traversal techniques previously used for kd-trees [7,16] to octrees. The key innovation is the implicit computation of neighbor bounding boxes using the octree's regular structure, avoiding the need for explicit neighbor pointers in the index structure for all nodes, thus saving memory and texture fetches. It is used in interactive volume rendering systems where out-of-core data handling and high performance are required.
