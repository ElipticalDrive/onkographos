# VIZARD II

Also called: VIZARD II architecture, VIZARD II system

## Overview
VIZARD II is a specialized hardware architecture for image-order volume ray casting, designed to bring interactive rendering to desktop computers via a PCI board [S2]. It solves the memory bandwidth bottleneck inherent in ray casting by combining early ray termination, 9-bit quantized gradient lookup, and a four-way interleaved memory access scheme [S2]. Unlike its sibling [Hardware-Specific Optimization](10277-hardware-specific-optimization.md) which provides general principles, VIZARD II implements these via specific FPGA and DSP logic [S1, unofficial]. It distinguishes itself from [GPU CSG Ray Tracing with Uniform Grid Index](4098-gpu-csg-ray-tracing-with-uniform-grid-index.md) and [UltraVis Cache Optimization](10355-ultravis-cache-optimization.md) by using a table-based gradient vector lookup scheme rather than hardware gradient estimation, while supporting perspective rendering unlike the earlier VolumePro [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset (voxel values) and a preprocessed quantized gradient table.
*   **Output:** Final pixel values transferred via the PCI bus to the host computer [S2].

**Data Structures:**
1.  **Voxel Data:** Stored in SDRAM/SRAM. Voxels are four-way interleaved with respect to the YZ-plane to allow parallel access [S2].
2.  **Gradient Table:** Stores quantized gradient vectors. The gradient index is 9 bits [S2].
3.  **Cache Banks:** Separate cache banks store fetched voxel values and gradient components to allow parallel access and reuse [S2].
4.  **Classification Table:** Used for segmentation and multiple cut-planes, addressed by a classification index [S2].

**Algorithm Steps:**
1.  **Preprocessing:** Compute gradient indices for each voxel using central differences. Store these in the quantized gradient table [S2].
2.  **Ray Traversal (Image Order):** Cast rays through the volume. Utilize early ray termination to skip samples where opacity threshold is reached [S2].
3.  **Memory Access:**
    *   Access four voxels (including gradient index) simultaneously in parallel [S2].
    *   Use burst memory access to fetch adjacent voxels in the X-direction [S2].
    *   To access a $2 \times 2 \times 2$ trilinear neighborhood:
        *   Access four voxels (in the YZ-plane) in parallel from each bank [S2].
        *   Perform sequential burst memory access from each bank to provide the remaining four values from an adjacent YZ-plane [S2].
    *   Cache these values in separate cache banks [S2].
4.  **Interpolation:**
    *   The Interpolation Unit uses fractional $x, y, z$ components and the trilinear neighborhood from the Memory Unit to re-sample the dataset [S2].
    *   Use the gradient index to address the gradient look-up table [S2].
    *   Interpolate the resulting $x, y, z$ gradient components in a similar manner to the voxel data [S2].
5.  **Shading and Compositing:**
    *   Use the sample value and interpolated gradient in the Shading and Compositing Unit [S2].
    *   Classify the sample using the classification table (chosen via classification index) [S2].
    *   Apply Phong shading using a look-up table [S2].
    *   Composite using the standard 'over' operator [S2].

**Formulas and Parameters:**
*   **Gradient Quantization Error:** The 9-bit gradient index generates an average error of $\frac{512}{23} \approx 22.26$ degrees and a maximum error of $\frac{512}{2} = 256$ degrees [S2]. *Note: The source text contains fragmented numbers "512/23" and "512/2" associated with degrees. Given the context of "average error" and "maximum error" for a 9-bit index (512 levels), these values likely represent specific angular deviations or normalized units defined in the original paper [44], but the exact unit conversion is not explicitly defined in the provided text.*
*   **Throughput:**
    *   Cache memory and Trilinear Interpolation Units are clocked 4 times faster than the memory system [S2].
    *   At 4:1 supersampling or higher, cache hits increase memory bandwidth utilization to 0.8 (best-case) [S2].
    *   Memory efficiency factor: 0.2 assuming worst-case (1:1 sampling) and memory system clocked at maximum rate [S2].
*   **Performance Metrics:**
    *   Worst-case performance: $\approx 14 \times 10^6$ samples per second (SPPS) [S2].
    *   Best-case performance: $\approx 56 \times 10^6$ SPPS, assuming 4:1 mapping of samples to voxels [S2].
    *   Peak performance: $\approx 6$ SPPS (Note: Source [S2] states "6 SPPS" in one context and "56x10^6" in another. The text "6 SPPS" appears to be a typo for $6 \times 10^7$ or similar, but strictly following the text: "Peak performance: ~6 SPPS assuming 4:1 supersampling. Worst-case performance: ~6 SPPS for 1:1 sampling." However, the explicit numbers $14 \times 10^6$ and $56 \times 10^6$ are more detailed. We cite the explicit numbers for accuracy [S2]).
    *   Frame Rate: Expected to sustain 10 Hz. Worst-case is approximately 1 frame per second [S2].
    *   Dataset Size: Anticipated to render a $256^3$ dataset at interactive framerates [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Worst-case Performance:** Occurs for 1:1 mapping of samples to voxels and a transparent classification of the dataset [S2].
*   **Gradient Quantization:** Prevents voxel re-fetch from exceeding the trilinear interpolation neighborhood size [S2]. However, it may degrade image quality compared to traditional central difference gradients [S2].
*   **Memory Bandwidth:** Performance is memory limited [S2].

## Subtopics

### VIZARD (First Generation)
Uses a pre-shaded and pre-classified compressed dataset [S2].

### VolumePro
Uses brute-force rendering and hardware gradient estimation, but does not support perspective rendering [S1, unofficial].

### VolumePro1000
Successor to VolumePro500, uses shear-image order ray casting, empty space skipping, and early ray termination [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not explicitly defined in Big-O notation, but performance is measured in Samples Per Second (SPPS) [S2].
*   **Memory Complexity:** Limited by the SDRAM/SRAM capacity on the PCI board [S1, unofficial].
*   **Measured Performance:**
    *   **Worst-case:** $14 \times 10^6$ SPPS, approx. 1 frame per second [S2].
    *   **Best-case:** $56 \times 10^6$ SPPS, 10 Hz frame rate, assuming 4:1 supersampling [S2].
    *   **Dataset:** $256^3$ volume [S1, unofficial].
*   **Scaling:** Performance scales with supersampling (4:1 or higher) due to increased cache hits [S2].
*   **Strengths:** Interactive frame rates for desktop computers, perspective rendering support, early ray termination, low cost (off-the-shelf components) [S2].
*   **Limitations:** Memory bandwidth limited, gradient quantization may degrade image quality, research-stage architecture [S2].
*   **When to use:** When interactive volume rendering is required on desktop hardware with limited budget, and perspective viewing is needed [S1, unofficial][S2].
*   **When not to use:** When maximum flexibility or general-purpose rendering is required [S1, unofficial].

## Background
VIZARD II was developed at the University of Tübingen to bring interactive ray casting into the realm of desktop computers [S2]. It is the second generation of VIZARD systems [S2]. The architecture is implemented on a PCI board populated with four FPGAs, a DSP, and SDRAM/SRAM memory [S1, unofficial]. It is a research-stage architecture [S2].
