# GPU CSG Ray Tracing with Uniform Grid Index

Also called: GPU CSG Renderer Features, GPU CSG tracer, GpuPlot

## Overview
A GPU-based ray tracer for Constructive Solid Geometry (CSG) that accelerates traversal by replacing unindexed full-scans of the root universe with a uniform grid index over the root universe's cells [S1, unofficial]. It renders Solid, Wireframe, and Slice views using a WGSL shader that is an $f32$ transcription of the CPU plotter's logic [S1, unofficial]. It sets itself apart from the unindexed GPU approach by eliminating the cost of rays outside the model stepping through infinite surface extensions, and from the CPU path by leveraging SIMD-like parallelism on the GPU while correcting specific parity bugs in complement handling [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A CSG scene defined by surfaces, regions (RPN), universes, lattices, and translations.
*   **Output:** Rendered images (Solid, Wireframe, Slice) or ray-tracing data.

**Data Structures:**
1.  **Flat Geometry Buffer (`outram_blender::csg::gpu::flat`):** A single `u32` buffer containing:
    *   Surfaces.
    *   RPN regions.
    *   Universes.
    *   Rect/Hex lattices (with maps and outer definitions).
    *   Translations.
    *   Static crossing hints (OpenMC-style neighbor lists).
    *   Universe graph (used to skip subtrees with no drawn material) [S1, unofficial].
2.  **Uniform Grid Index:** A voxel grid over the root universe's bounding box. Each voxel contains a list of cells that intersect it. Each cell's region expression is constant-folded to the specific surfaces passing through that voxel [S1, unofficial].
3.  **GpuPlot Struct:** Contains variants `Solid`, `Wireframe`, `Slice`, matching the CPU plotter's structs [S1, unofficial].

**Parameters:**
*   **Grid Resolution:** Varies by scene. Example: HTR-10 root universe uses a $30 \times 30 \times 47$ voxel grid [S1, unofficial].
*   **Indexing Budget:** Index universes with token counts above 512, within a 16 MB memory budget [S1, unofficial].
*   **Buffer Limit:** The geometry buffer must not exceed the device's 128 MiB binding limit [S1, unofficial].

**Algorithm Steps:**

1.  **Build the Uniform Grid:**
    *   Create a voxel grid over the root universe's bounding box.
    *   For each voxel, identify the cells that intersect it.
    *   Constant-fold each cell's region expression to determine the specific surfaces that pass through that voxel [S1, unofficial].

2.  **Close the Grid:**
    *   Ensure no root cell lies outside the grid bounds.
    *   For unbounded OpenMC boxes (e.g., absorber-sphere channels, core cell conus), perform vertex enumeration over plane half-spaces.
    *   Apply a bound on the cone radius to create tight bounding boxes for these unbounded regions [S1, unofficial].

3.  **Ray Traversal (Shader Execution):**
    *   **Outside Model:** If a ray is outside the model, it jumps directly to the grid index.
    *   **Inside Grid:** The ray steps through voxels. Voxel faces act as "silent steps" (no surface intersection test is required for the voxel boundary itself) [S1, unofficial].
    *   **Intersection Test:** Upon entering a voxel, test the ray against the pre-computed surfaces for the candidate cells.
    *   **Complex Region Handling:** Sign complex regions from the surface normal. This corrects a CPU parity bug where complements were not handled via De Morgan's laws [S1, unofficial].
    *   **Post-Step Correction:** After a silent voxel step, reset the token. This ensures the ray can exit a bore/cell correctly. Previously, the tracer retained the token of the last-crossed surface, trapping the ray [S1, unofficial].

4.  **Rendering:**
    *   **Phong Solid View:** Render solid geometry with lighting.
    *   **Slice View:** Render section planes with cut faces. Supports per-material visibility and x-ray attenuation with outlines [S1, unofficial].

**Pseudocode:**

```python
# Simplified representation of the GPU traversal logic
# Assumes access to the flat geometry buffer and uniform grid

def trace_ray(ray_origin, ray_direction, grid, geometry_buffer):
    # 1. Check if ray is outside the root universe bounding box
    if not is_inside_root_bbox(ray_origin, ray_direction, grid.bbox):
        # Jump directly to the grid index
        voxel = grid.find_voxel(ray_origin, ray_direction)
        if voxel is None:
            return BACKGROUND_COLOR
        
        # 2. Traverse voxels
        current_voxel = voxel
        token = INITIAL_TOKEN # Reset token to allow exit from bores
        
        while current_voxel is not None:
            # Silent step: moving between voxel faces requires no intersection test
            # Get candidate cells and pre-computed surfaces for this voxel
            candidates = current_voxel.candidate_cells
            surfaces = current_voxel.precomputed_surfaces
            
            # 3. Intersection Test
            # Test ray against surfaces of candidate cells
            hit_surface, hit_dist, hit_normal = find_nearest_intersection(
                ray_origin, ray_direction, surfaces
            )
            
            if hit_surface is not None:
                # 4. Complex Region Handling
                # Sign complex regions from the surface normal
                region_token = hit_surface.get_region_token(hit_normal)
                
                # Update ray origin to hit point
                ray_origin = ray_origin + ray_direction * hit_dist
                token = region_token
                
                # Move to next voxel
                current_voxel = grid.get_next_voxel(ray_origin, ray_direction)
            else:
                # No intersection in this voxel, move to next
                # Post-Step Correction: Reset token if needed?
                # The source notes that token retention was a bug.
                # Here, we assume the token is updated only on actual surface crossing.
                # However, the "reset token" fix implies that after a silent step,
                # the state should be clean for the next voxel's evaluation.
                # In this simplified model, we just proceed.
                current_voxel = grid.get_next_voxel(ray_origin, ray_direction)
                
        return BACKGROUND_COLOR
    else:
        # Ray starts inside or intersects root bbox
        # Similar traversal logic starting from the first intersected voxel
        pass

def find_nearest_intersection(origin, direction, surfaces):
    min_dist = INFINITY
    best_surface = None
    best_normal = None
    
    for surface in surfaces:
        dist, normal = surface.intersect(origin, direction)
        if dist > 0 and dist < min_dist:
            min_dist = dist
            best_surface = surface
            best_normal = normal
            
    return best_surface, min_dist, best_normal
```

**Edge Cases and Pitfalls:**
*   **Complement Handling:** The CPU port did not remove complements by De Morgan's laws or sign complex regions from the surface normal. This caused rays entering a reflector core (written as `box & ~core`) to be re-located incorrectly. The fix signs complex regions from the normal [S1, unofficial].
*   **Silent Step Token Retention:** After stepping through a voxel face (silent step), the tracer retained the token of the last-crossed surface. This prevented rays inside a bore from exiting. The fix resets the token [S1, unofficial].
*   **ClipPlane Shadow Bug:** In the CPU SolidRayTracePlot with a ClipPlane, the shadow ray was blocked by the cut-away half. The fix ensures the ray is lit once it passes into that half. This changes the shade of 2.5% of pixels but no pixel changes material [S1, unofficial].
*   **Buffer Limit:** If the geometry buffer exceeds the device's 128 MiB binding limit, `set_geometry` returns an error (CPU fallback) instead of panicking [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The cost per crossing is approximately 90 ns [S1, unofficial]. This is partly due to reflector cells holding up to 124 region tokens [S1, unofficial].
*   **Memory Complexity:** Indexing is limited by a 16 MB budget for universes with token counts above 512 [S1, unofficial]. The total geometry buffer is limited to 128 MiB [S1, unofficial].
*   **Measured Performance:**
    *   **Şeker bed, half-section (900x560):** GPU indexed time 24-60 ms (best 17 ms). GPU unindexed time 0.36-0.39 s. CPU time 6.95 s (from earlier test) [S1, unofficial].
    *   **Şeker reflector, half-section:** GPU indexed time 19-21 ms. GPU unindexed time 0.36 s [S1, unofficial].
    *   **X-y slice, mid-bed:** GPU indexed time 2 ms. GPU unindexed time 17 ms [S1, unofficial].
    *   **DEM bed, half-section:** GPU indexed time 33 ms. GPU unindexed time 0.39 s [S1, unofficial].
    *   **DEM reflector, half-section:** GPU indexed time 20 ms. GPU unindexed time 0.35 s [S1, unofficial] [S1, unofficial].
*   **Scaling:** Indexing reduces frame time significantly compared to unindexed GPU rendering (e.g., from ~0.36s to 24-60ms for the Şeker bed half-section) [S1, unofficial]. Unindexed rays performed ~10 full scans of the 128-cell root universe because rays outside the model stepped through infinite extensions (planes, cones) crossing all 1,675 tokens [S1, unofficial].
*   **Strengths:** Significant speedup over unindexed GPU and CPU methods for large scenes. Handles complex CSG operations.
*   **Limitations:** Grid indexing adds complexity and memory overhead. Unbounded cells require special handling (vertex enumeration). Buffer size limits may force CPU fallback.
*   **When to use:** When rendering large CSG scenes on a GPU with sufficient memory and compute resources, and when the performance gain from indexing outweighs the setup cost.
*   **When not to use:** When the scene is small enough that unindexed traversal is fast enough, or when memory constraints prevent building the index. Also not suitable for scenes with tori (refused) [S1, unofficial].

## Background
The method was developed as part of the `outram-blender` project, specifically in the `outram_blender::csg::gpu` module, to provide GPU-accelerated rendering for 3D and 2D views in a workbench application [S1, unofficial]. It was implemented as a WGSL shader, transcribed from the CPU plotter's logic, to support Solid, Wireframe, and Slice views [S1, unofficial]. The development addressed specific performance bottlenecks in the unindexed GPU approach, where rays outside the model caused excessive surface crossings [S1, unofficial]. The implementation includes corrections for parity bugs in complement handling and token retention issues [S1, unofficial]. It was verified against the CPU plotter using Vulkan on an NVIDIA RTX A5000 [S1, unofficial].
