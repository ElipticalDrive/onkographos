# ASCII Rendering with Dithering

Also called: ASCII Ray Tracing, ASCII Tracing with Ordered Dithering, Terminal Ray Tracing, Terminal Raymarching, VT100 Rendering

## Overview
ASCII Rendering with Dithering renders 3D scenes to a text-based terminal buffer by casting rays, computing lighting, and mapping the resulting continuous-tone color to a limited set of ASCII characters (typically `#` and space) using ANSI escape codes [S1, unofficial]. It differs from standard terminal rendering by employing ordered dithering via a Bayer matrix to simulate grayscale intensity and color depth within the constraints of a fixed 80x24 character grid, effectively acting as a low-resolution, text-based raymarcher [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Scene defined by Signed Distance Functions (SDFs) for primitives (e.g., planes, tori, spheres) [S1, unofficial].
*   Camera position (`campos`) and orientation [S1, unofficial].
*   Light position (`lightpos`) and color (`lcol`) [S1, unofficial].
*   Material properties: diffuse color (`mcol`) and shininess (`mshiny`) for each material index [S1, unofficial].
*   Resolution: Fixed at 80 columns (x) and 24 rows (y) [S1, unofficial].

**Outputs:**
*   A terminal buffer containing ANSI escape sequences for foreground/background colors and ASCII characters (`#` or space) [S1, unofficial].

### Data Structures
*   **Bayer Matrix:** A 4x4 integer array used for ordered dithering offsets, stored in row-major order [S1, unofficial]: `{1, 9, 3, 11, 13, 5, 15, 7, 4, 12, 2, 10, 16, 8, 14, 6}`.
*   **Color Lookup Table (LUT):** A precomputed table `color_LUT[16*16*16]` mapping quantized RGB indices (0-15 per channel) to a packed integer representing foreground and background ANSI color indices [S1, unofficial].
*   **Material Arrays:** `mcol` (diffuse colors) and `mshiny` (shininess exponents) [S1, unofficial].
*   **Light Color:** `lcol = {0.7, 0.5, 0.5}` [S1, unofficial].

### Steps
1.  **Initialization:** Call `render_init()` to populate the `color_LUT` [S1, unofficial]. This iterates over all 16^3 possible quantized RGB combinations, finds the nearest ANSI foreground/background pair using a brute-force search over 17 palette entries (indices 0-16) with an error metric based on squared Euclidean distance in RGB space, and stores the result [S1, unofficial].
2.  **Loop:** Iterate through each frame.
3.  **Camera Setup:** Define camera position `campos` and view direction `camz = normalize(campos * -1)` [S1, unofficial]. Compute camera basis vectors: `camx = normalize(cross(camz, vec3(0, 1, 0)))` and `camy = normalize(cross(camx, camz))` [S1, unofficial]. The cross product assumes the camera is not looking exactly up or down (parallel to the Y-axis) [G].
4.  **Pixel Loop:** For each pixel `(x, y)` where `x ∈ [0, 79]` and `y ∈ [0, 23]`:
    5.  **Accumulate Color:** Initialize `color = vec3(0, 0, 0)` [S1, unofficial].
    6.  **Multi-sampling (AA):** Perform 8 samples per pixel to reduce aliasing [S1, unofficial].
        *   Iterate `xx` in `{-0.25, 0.25}` (2 samples) [S1, unofficial].
        *   Iterate `yy` in `{-0.75, -0.25, 0.25, 0.75}` (4 samples) [S1, unofficial].
        *   Construct ray direction `dir` in screen space: $dir_{screen} = \text{normalize}(v3(x - 40.0 + xx, 25.0 - 2.0 \cdot y + yy, 40.0))$ [S1, unofficial].
        *   Transform `dir` to camera space: $dir = camx \cdot dir.x + camy \cdot dir.y + camz \cdot dir.z$ [S1, unofficial].
        *   **Ray Marching:**
            *   Initialize `t = 0`, `m = -1` (no material) [S1, unofficial].
            *   Loop up to 64 iterations or until `t > 1e6`:
                *   Compute point `p = dir * t + campos` [S1, unofficial].
                *   Compute distance `d = dist(p, &m)` using SDFs [S1, unofficial].
                *   If `d < 0.001`, a hit occurred. Compute lighting `L = lighting(p, m, lightpos)` and add to accumulator: `color = color + L` [S1, unofficial]. Break loop.
                *   Else, `t += d`. If the ray step `t` accumulates floating-point errors, the ray might miss the surface or jitter, but the fixed threshold and iteration limit mitigate this [S1, unofficial].
        7.  **Scale:** Multiply accumulated color by `0.125` (divide by 8) to average the 8 samples [S1, unofficial].
        8.  **Dithering and Color Mapping:**
            *   Compute dithering offset `o` using the Bayer matrix `B`. The source code implements $o = B[(x \bmod 4) + (y \bmod 4) \cdot 4] \cdot \frac{1}{8}$ [S1, unofficial]. (The notes mention an alternative formula $o = -48 + 4 \cdot B[(x \bmod 4) + (y \bmod 4) \cdot 4]$, but the code implementation is as stated) [S1, unofficial].
            *   Quantize RGB channels to 0-15 range with offset: $r = \text{clamp}(\lfloor c.x \cdot 15.0 - o \rfloor, 0, 15)$, $g = \text{clamp}(\lfloor c.y \cdot 15.0 - o \rfloor, 0, 15)$, $b = \text{clamp}(\lfloor c.z \cdot 15.0 - o \rfloor, 0, 15)$ [S1, unofficial].
            *   Lookup ANSI codes in `color_LUT[r + g*16 + b*256]` to get `fg` and `bg` [S1, unofficial].
        9.  **Render Character:**
            *   If `fg` is valid (>=0), print `#` with ANSI foreground color `30 + (fg & 7)` and bold flag `!!(fg & 8)` [S1, unofficial].
            *   If `fg` is invalid (-1), print space [S1, unofficial].
            *   The `render_color` function tracks previous `cur_fg` and `cur_bg` to avoid printing escape sequences when attributes are identical to the previous pixel [S1, unofficial].
        10. **End of Row:** After `x` loop, print newline `\n` and reset attributes `\x1b[0m` [S1, unofficial].
        11. **Frame Update:** Flush stdout, sleep 20ms, increment frame counter, and move cursor up 24 lines (`\x1b[24A`) to redraw [S1, unofficial].

### Pseudocode
```python
def render_init():
    color_LUT = [0] * (16 * 16 * 16)
    for r in range(16):
        for g in range(16):
            for b in range(16):
                c = vec3(r / 15.0, g / 15.0, b / 15.0)
                fg, bg = nearest_color(c)
                color_LUT[r + g * 16 + b * 256] = (bg << 5) | fg
    return color_LUT

def nearest_color(c):
    min_err = float('inf')
    best_fg, best_bg = 0, 0
    # Brute-force search over 17 palette entries (indices 0-16) [S1, unofficial]
    for i in range(17):
        # Palette entry generation from standard ANSI/VGA approximation [G]
        pal_c = vec3((i & 7) / 7.0, ((i >> 3) & 1) / 1.0, ((i >> 3) & 2) / 2.0)
        # Error metric based on squared Euclidean distance in RGB space after adding an offset [S1, unofficial]
        err = (c.x - pal_c.x)**2 + (c.y - pal_c.y)**2 + (c.z - pal_c.z)**2
        if err < min_err:
            min_err = err
            best_fg = i
            best_bg = 0
    return best_fg, best_bg

def dist(p, m_out):
    d_plane = p.y + 50.0
    m_out[0] = ((int(p.x * 0.01) & 1) ^ (int(p.z * 0.01) & 1))
    d = d_plane
    # Torus SDF from source [S1, unofficial]
    q = rotate_x(rotate_y(p, -frame * 0.07), frame * 0.025)
    dtorus = length(vec3(length(vec3(q.x, q.y, 0)) - 50.0, q.z, 0)) - 20.0
    if dtorus < d:
        d = dtorus
        m_out[0] = 2
    return d

def lighting(p, m, lightpos):
    lightdir = normalize(lightpos - p)
    eps = 0.1
    m_temp = [-1]
    diffuse = max(0.0, 10.0 * dist(p + lightdir * eps, m_temp))
    s = shadow(p, lightdir, 0.01, length(lightpos - p))
    l = max(0.1, diffuse * s)
    return MCOL[m] * l + LCOL * pow(l, MSHINY[m])

def shadow(ro, rd, mint, maxt):
    res = 1.0
    t = mint
    while t < maxt:
        m_temp = [-1]
        h = dist(ro + rd * t, m_temp)
        if h < 0.001:
            return 0.0
        res = min(res, 10.0 * h / t)
        t += h
    return res

def render_frame(frame):
    global MCOL, LCOL, MSHINY
    # Material properties from source [S1, unofficial]
    MCOL = [vec3(1.5, 1.5, 1.5), vec3(0.6, 0.6, 0.6), vec3(0.0, 0.4, 1.0)]
    LCOL = vec3(0.7, 0.5, 0.5)
    MSHINY = [100, 10, 10]
    
    campos = vec3(120 * sin(frame * 0.01), 40 + 30 * sin(frame * 0.03), -120 * cos(frame * 0.01))
    camz = normalize(campos * -1)
    camx = normalize(cross(camz, vec3(0, 1, 0)))
    camy = normalize(cross(camx, camz))
    
    cur_fg = 7
    cur_bg = 0
    color_LUT = render_init()
    
    for y in range(24):
        for x in range(80):
            color = vec3(0, 0, 0)
            for xx in [-0.25, 0.25]:
                for yy in [-0.75, -0.25, 0.25, 0.75]:
                    dir_screen = normalize(vec3(x - 40.0 + xx, 25.0 - 2.0 * y + yy, 40.0))
                    dir = camx * dir_screen.x + camy * dir_screen.y + camz * dir_screen.z
                    t = 0.0
                    m = [-1]
                    for _ in range(64):
                        if t > 1e6:
                            break
                        p = dir * t + campos
                        d = dist(p, m)
                        if d < 0.001:
                            color = color + lighting(p, m[0], vec3(0, 40, 0))
                            break
                        t += d
            
            color = color * 0.125
            bayer_val = BAYER_MATRIX[(x & 3) + ((y & 3) * 4)]
            o = bayer_val * (1.0 / 8.0)
            
            r = clamp(int(color.x * 15.0 - o), 0, 15)
            g = clamp(int(color.y * 15.0 - o), 0, 15)
            b = clamp(int(color.z * 15.0 - o), 0, 15)
            
            entry = color_LUT[r + g * 16 + b * 256]
            fg = entry & 31
            bg = entry >> 5
            
            if fg >= 0:
                if bg == cur_bg:
                    if fg != cur_fg:
                        print(f"\x1b[3{fg&7};1m#", end="")
                        cur_fg = fg
                    else:
                        print("#", end="")
                else:
                    print(f"\x1b[4{bg};3{fg&7};1m#", end="")
                    cur_fg, cur_bg = fg, bg
            else:
                if bg != cur_bg:
                    print(f"\x1b[4{bg}m ", end="")
                    cur_bg = bg
                else:
                    print(" ", end="")
        print("\n")
        print("\x1b[0m")
    print("\x1b[24A")
    flush()
    sleep(0.02)
```

### Parameters
*   **Resolution:** 80x24 characters [S1, unofficial].
*   **Samples per Pixel:** 8 (2 in x, 4 in y) [S1, unofficial].
*   **Gamma Correction:** Not explicitly applied in the provided code, but standard gamma is 2.2 [S1, unofficial].
*   **Color Scaling:** 0.125 for AA averaging [S1, unofficial].
*   **Light Color:** `{0.7, 0.5, 0.5}` [S1, unofficial].
*   **Shininess:** The notes specify `{10, 10, 10}` for materials 0, 1, 2, but the source code uses `{100, 10, 10}` [S1, unofficial].
*   **Material Colors:** The notes specify `mcol[0]={0.0,1.6,0.0}`, `mcol[1]={0.0,0.0,0.0}`, `mcol[2]={1.0,0.0,0.0}`, but the source code uses `mcol[0]={1.5, 1.5, 1.5}`, `mcol[1]={0.6, 0.6, 0.6}`, `mcol[2]={0.0, 0.4, 1.0}` [S1, unofficial].

### Edge Cases and Pitfalls
*   **Precision:** The distance field check uses a threshold of `0.001`. If the ray step `t` accumulates floating-point errors, the ray might miss the surface or jitter. The source uses a fixed iteration limit (64) and a max distance (`1e6` or `6000`) to prevent infinite loops [S1, unofficial].
*   **Color Mapping:** The nearest color function uses a brute-force search over 17 palette entries. If no close match is found, it returns -1, resulting in a space character (background) [S1, unofficial].
*   **ANSI State:** Failing to track `cur_fg` and `cur_bg` correctly will result in excessive escape sequence emission, slowing down rendering [S1, unofficial].
*   **Camera Basis:** The camera basis calculation `camx = normalize(cross(camz, vec3(0,1,0)))` assumes the camera is not looking exactly up or down (parallel to the Y-axis). If `camz` is parallel to `(0,1,0)`, the cross product is zero, causing a division by zero in normalization [G].

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot S \cdot I)$, where $W=80$, $H=24$, $S=8$ (samples), and $I=64$ (max ray march iterations) [S1, unofficial]. The complexity is dominated by the ray marching loop [S1, unofficial].
*   **Memory Complexity:** $O(1)$ for the scene (SDFs are procedural), plus $O(1)$ for the LUT ($16^3$ entries) [S1, unofficial].
*   **Performance:** Described as "pretty slow and unoptimized" [S1, unofficial]. The use of Python-like pseudocode suggests it is intended for clarity rather than speed, but the original C implementation runs in real-time on modern CPUs for simple scenes [S1, unofficial].
*   **Strengths:** Simple implementation, no external assets, portable to any terminal [S1, unofficial].
*   **Limitations:** Low resolution (80x24), limited color palette, no transparency/reflections (only diffuse/specular), fixed camera movement [S1, unofficial].

## Background
ASCII Rendering with Dithering is a technique popularized by obfuscated C programming contests and terminal art enthusiasts. The specific implementation described here is from the `a1k0n/asciitracing` repository, which demonstrates raymarching in a terminal using ANSI escape codes [S1, unofficial]. It builds on the principles of raymarching (as seen in Shadertoy) but adapts the output to a text-based medium using ordered dithering to simulate grayscale [S1, unofficial].
