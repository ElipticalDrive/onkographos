# Image-order Rendering Loop

Also called: Main Rendering Loop, Octree Rendering Loop

## Overview
The Image-order Rendering Loop is the top-level control structure that iterates over pixels to generate rays and invoke the raymarcher or path tracer for shading [S1, unofficial]. It serves as the entry point for the rendering pipeline, managing the mapping from screen coordinates to world-space rays and aggregating results [S1, unofficial]. Unlike sibling methods that focus on traversal optimization or specific shading models, this loop handles the global orchestration of sampling, projection, and output composition [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera parameters (position, direction, projection mode), scene data (octree, lights), rendering configuration (shading mode, sample count), and image dimensions ($v_{width}, v_{height}$).
*   **Outputs:** A rendered image buffer (e.g., RGB values).

**Data Structures:**
*   **Renderer Configuration:**
    *   `maxDepth`: Integer, maximum recursion depth for ray tracing. Default: 100 [S2, unofficial].
    *   `samplesPerPixel`: Integer, number of samples per pixel for anti-aliasing. Default: 500 [S2, unofficial].
    *   `background`: RGB color, default `{0, 0, 0}` [S2, unofficial].
*   **Shading Mode Enum:** Determines the shading behavior. Values include `TRACE`, `DEPTH`, `DEPTH_HIT`, `DIFFUSE`, `NORMAL`, `INDEX` [S1, unofficial].
*   **Projection Mode Enum:** Determines ray generation. Values include `PERSPECTIVE`, `ORTHOGRAHIC` [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Set `CompletedSamples = 0` [S1, unofficial]. Calculate light bounds $p_0, p_1$ [S1, unofficial]. Apply rotation to camera position and direction [S1, unofficial].
2.  **Sample Loop:** Iterate $s$ from $0$ to `NumSamples` - 1. If `ShadingMode == Shade::TRACE`, proceed to pixel loop; otherwise, skip to single-pass shading [S1, unofficial].
3.  **Pixel Loop:** Iterate $y$ from $0$ to $v_{height}-1$ and $x$ from $0$ to $v_{width}-1$ [S1, unofficial].
4.  **Ray Generation:**
    *   Calculate normalized pixel coordinates $rx, ry$ [S1, unofficial].
    *   Transform position `pos` based on projection mode [S1, unofficial].
    *   **Perspective:** `rayOrigin` = `cameraPos`, `rayDirection` = `cameraDir` + `pos` [S1, unofficial].
    *   **Orthographic:** `rayOrigin` = `cameraPos` + `pos`, `rayDirection` = `cameraDir` [S1, unofficial].
5.  **Shading:**
    *   Calculate pixel index: `index` = $x + y \times v_{width}$ [S1, unofficial].
    *   If `ShadingMode == Shade::TRACE`:
        *   Call `ShadePathTrace(rayOrigin, rayDirection, hit, normal, depth)` [S1, unofficial].
        *   Accumulate the returned color by averaging with previous samples [S1, unofficial].
    *   Else (Single-pass modes):
        *   Call `Raymarch(rayOrigin, rayDirection, hit, normal, ...)` [S1, unofficial].
        *   If hit: Shade based on `ShadingMode`:
            *   `DEPTH`: `result.g *= depth / 2.0f` [S1, unofficial].
            *   `DEPTH_HIT`: `result.g *= distance(cameraPos, hit) / 2.0f` [S1, unofficial].
            *   `NORMAL`: `result.x = (normal.x != 0)`, `result.y = (normal.y != 0)`, `result.z = (normal.z != 0)` [S1, unofficial].
            *   `DIFFUSE`: Compute ambient and diffuse lighting using light direction and color [S1, unofficial].
            *   `INDEX`: (Implementation details not fully specified in source, assumed similar to diffuse or index-based coloring) [S1, unofficial].
        *   If no hit but ray intersects light AABB: Write light color [S1, unofficial].
        *   Else: Write dark color `(25, 25, 25)` [S1, unofficial].

**Pseudocode:**
```python
def render(scene, camera, image):
    # Configuration
    max_depth = 100
    samples_per_pixel = 500
    background = (0, 0, 0)
    shading_mode = "TRACE" # TRACE, DEPTH, DEPTH_HIT, DIFFUSE, NORMAL, INDEX
    projection_mode = "PERSPECTIVE" # PERSPECTIVE, ORTHOGRAPHIC
    
    v_width = image.width
    v_height = image.height
    
    # Pre-calculate light bounds
    p0, p1 = calculate_light_bounds(scene)
    
    # Rotate camera
    camera_pos = rotate(camera.position)
    camera_dir = rotate(camera.direction)
    
    for s in range(samples_per_pixel):
        for y in range(v_height):
            for x in range(v_width):
                # Normalize pixel coordinates
                rx = (2.0 * (x + 0.5) / v_width) - 1.0
                ry = 1.0 - (2.0 * (y + 0.5) / v_height)
                
                # Transform position based on projection
                if projection_mode == "PERSPECTIVE":
                    # Assuming camera setup maps rx,ry to direction offset
                    pos = transform_position(rx, ry)
                    ray_origin = camera_pos
                    ray_direction = normalize(camera_dir + pos)
                else: # ORTHOGRAPHIC
                    pos = transform_position(rx, ry)
                    ray_origin = camera_pos + pos
                    ray_direction = camera_dir
                
                # Shade
                if shading_mode == "TRACE":
                    hit = vec3(0,0,0)
                    normal = vec3(0,0,0)
                    color = shade_path_trace(ray_origin, ray_direction, hit, normal, max_depth)
                    image.set_pixel(x, y, accumulate_color(color))
                else:
                    hit = vec3(0,0,0)
                    normal = vec3(0,0,0)
                    if raymarch(ray_origin, ray_direction, hit, normal):
                        if shading_mode == "DEPTH":
                            depth = length(hit - ray_origin)
                            color = vec3(0, depth / 2.0, 0)
                        elif shading_mode == "DEPTH_HIT":
                            depth = length(hit - ray_origin)
                            color = vec3(0, depth / 2.0, 0)
                        elif shading_mode == "NORMAL":
                            color = vec3(
                                1.0 if normal.x != 0 else 0.0,
                                1.0 if normal.y != 0 else 0.0,
                                1.0 if normal.z != 0 else 0.0
                            )
                        elif shading_mode == "DIFFUSE":
                            # Simplified diffuse shading
                            light_dir = normalize(vec3(1,1,1)) # Placeholder for actual light dir
                            ambient = vec3(0.1, 0.1, 0.1)
                            diff = max(dot(normal, light_dir), 0.0)
                            light_color = vec3(1,1,1)
                            color = (ambient + diff * light_color) * scene.object_color
                        else:
                            color = vec3(0,0,0) # INDEX or default
                    else:
                        # Check light intersection
                        if ray_aabb(p0, p1, ray_origin, ray_direction):
                            color = scene.light_color
                        else:
                            color = vec3(25, 25, 25) # Dark color
                    
                    image.set_pixel(x, y, color)
```

## Subtopics

### [Terminal Rendering Pipeline](3434-terminal-rendering-pipeline.md)
Renders the scene to a terminal buffer by iterating over pixels, mapping them to NDC, casting rays, and applying ASCII/ANSI styling based on depth and lighting [3434-terminal-rendering-pipeline.md]. It differs from standard image-order loops by outputting character codes instead of RGB values, adapting the loop for text-based displays.

### [Diffuse Octree Rendering](4989-diffuse-octree-rendering.md)
Traverses an octree to find the first leaf node with data for each pixel, then computes lighting using a diffuse and Phong model with distance attenuation [4989-diffuse-octree-rendering.md]. It specializes the shading step of the image-order loop for octree structures with specific lighting models.

## Operating characteristics
*   **Time Complexity:** $O(N_{pixels} \times N_{samples} \times N_{traversal})$, where $N_{traversal}$ is the cost of the raymarcher/traversal method.
*   **Memory Complexity:** $O(N_{pixels})$ for the image buffer, plus scene data.
*   **Strengths:** Simple control flow, easy to parallelize per-pixel or per-sample, supports various shading modes.
*   **Limitations:** Performance is bound by the number of samples and traversal depth; naive implementation may suffer from aliasing without sufficient sampling.
*   **When to use:** General-purpose rendering where flexibility in shading modes is required.
*   **When not to use:** When hardware-accelerated ray tracing or specific traversal optimizations (like those in siblings) are needed for performance.

## Background
The image-order rendering loop is a fundamental concept in ray tracing and volume rendering, originating from early ray tracers like those by Whitted [S1, S2, unofficial]. It is widely used in educational ray tracers and production renderers as the main driver for pixel processing. The specific implementation details cited here are derived from open-source sparse voxel octree and volumetric path tracing projects [S1, S2, unofficial].
