# Opt-in GPU Sampling for tifxyz Rendering

Also called: vc_render_tifxyz GPU sampling

## Overview
This method accelerates the sampling step of `vc_render_tifxyz` surface rendering by offloading trilinear sampling and pyramid generation to a CUDA or ROCm GPU, while maintaining byte-identical output to the CPU reference implementation [S1, unofficial]. It differs from native integration by using `LD_PRELOAD` interposition to intercept the CPU sampling function, allowing the existing C++ renderer to remain unchanged [S1, unofficial].

## How it works
The method consists of two phases: a CPU dump phase and a GPU sampling phase.

**Inputs and Outputs:**
*   **Input:** A surface directory, a volume path (OME-Zarr format), and environment variables controlling execution.
*   **Output:** A Zarr directory containing pyramid levels L0–L5, byte-identical to the CPU-only render.

**Data Structures:**
The shim intercepts specific C++ symbols to extract rendering geometry. The intercepted data consists of tile sample positions, defined as base points and step directions for each tile [S1, unofficial]. These are dumped to a directory specified by `RENDER_SHIM_DIR` [S1, unofficial].

**Parameters:**
*   `RENDER_GPU`: Environment variable. Set to `1` to enable the GPU path; otherwise, the normal CPU render runs [S1, unofficial].
*   `RENDER_SHIM_DIR`: Environment variable specifying the directory where the shim dumps tile sample positions [S1, unofficial].
*   `PyTorch`: Required dependency for `render_gpu.py`, must be built with CUDA or ROCm support [S1, unofficial].

**Steps:**

1.  **CPU Dump Phase:**
    The CPU renderer (`vc_render_tifxyz`) is executed with `LD_PRELOAD` pointing to `render_shim.so` [S1, unofficial]. The shim intercepts the `sampleTileSlices` function (specifically the `u8` specialization) and `VcDataset::writeChunkSkipEmpty` by mangled name [S1, unofficial]. Instead of performing actual sampling, it dumps the tile sample positions (base points and step directions) to the directory specified by `RENDER_SHIM_DIR` [S1, unofficial]. The `vc_core` library must be a shared library to allow this interposition [S1, unofficial].

2.  **GPU Sampling Phase:**
    The Python script `render_gpu.py` reads the dumped sample positions and the volume data [S1, unofficial].
    *   **Memory Management:** Volume chunks are kept in GPU memory across surfaces to optimize I/O [S1, unofficial].
    *   **Computation:** The GPU performs trilinear sampling and pyramid generation using fp32 arithmetic to reproduce the CPU sampler's output exactly [S1, unofficial].
    *   **Output:** The GPU-generated pyramid levels (L0–L5) are written into the zarr directory structure created by the initial C++ run [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Symbol Signature Changes:** If the signatures of the intercepted symbols (`sampleTileSlices<u8>` and `VcDataset::writeChunkSkipEmpty`) change, the dump output will be empty, and `render_gpu.py` will stop with an error. It does not produce a wrong render [S1, unofficial].
*   **Shared Library Requirement:** The shim requires `vc_core` to be a shared library (the default) to allow `LD_PRELOAD` interposition [S1, unofficial].
*   **Precision:** The GPU uses fp32 arithmetic to ensure byte-identical output with the CPU sampler [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Most GPU time is spent reading volume chunks from disk; sampling and pyramid generation take about 5 seconds for 10 wraps [S1, unofficial].
*   **Memory Complexity:** Volume chunks are kept in GPU memory across surfaces to optimize I/O [S1, unofficial].
*   **Measured Performance:**
    *   **Radeon AI PRO R9700:** Rendering 10 PHerc0800 wraps took 28–47 seconds with the GPU tool compared to 64–82 seconds with the stock CPU render [S1, unofficial].
    *   **AMD Instinct MI50:** The median time for 20 rounds of 10 wraps was 49.5 seconds (range 35.9–70.0) for the GPU path versus 64.2 seconds (range 48.3–104.5) for the CPU path [S1, unofficial].
    *   **RTX 3080:** Rendering wraps 030-035 took 8.7/6.3/5.8 seconds across three rounds compared to 14.1/12.1/13.9 seconds for CPU [S1, unofficial].
*   **Accuracy:** Parity checks confirmed byte-identical output at all six pyramid levels (L0–L5) for 20 of 20 PHerc0800 wraps on an AMD Instinct MI50 [S1, unofficial]. On an RTX 3080, 150 tiles of wrap w030 were byte-identical to the CPU render at L0 [S1, unofficial].
*   **Strengths:** Significant speedup on GPU hardware; byte-identical output to CPU reference.
*   **Limitations:** Relies on `LD_PRELOAD` interposition, which is a workaround that may break if symbol signatures change [S1, unofficial]. Requires PyTorch with CUDA or ROCm support [S1, unofficial].

## Background
This method was developed by phippsrtyler and submitted as a pull request to the Vesuvius Challenge monorepo (ScrollPrize/villa) in October 2026 [S1, unofficial].
