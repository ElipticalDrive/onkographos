# Sphere-Center Method
Also called: enlarged frustum traversal for particles
## Overview
The Sphere-Center Method is an optimization for glyph-based particle visualization within the Coherent Grid Traversal (CGT) framework [S1]. It solves the problem of redundant storage and intersection testing for spherical primitives that overlap multiple grid cells by storing each sphere in exactly one cell—specifically, the cell containing its center [S1]. Unlike traditional grid traversal which requires mailboxes or data duplication to handle overlapping primitives, this method eliminates indirection overhead by traversing an enlarged frustum [S1]. It is distinct from [Macrocell Hierarchical CGT](5464-macrocell-hierarchical-cgt.md) and [Bundle Parallelisation](6293-bundle-parallelisation.md) by relying on geometric expansion of the traversal volume rather than hierarchical skipping or packet-level parallelism to achieve efficiency [S1].

## How it works
The method exploits the properties of particle-based simulation datasets where radii are uniform or fall within a well-defined range, and particles are uniformly distributed or densely packed with large empty regions [S1]. It uses a grid as the acceleration structure, constructed on-the-fly for time-varying data [S1].

**Inputs and Outputs:**
*   **Input:** A set of particles, each defined by a center position $C_i$ and radius $r_i$, and a ray packet bounding frustum $F$ [S1].
*   **Output:** A list of sphere intersections for the ray packet [S1].

**Data Structures:**
*   **Grid:** A 3D grid where each cell stores a list of sphere indices [S1].
*   **Storage Layout:** Each sphere is stored in exactly one cell: the cell $(x, y, z)$ such that the sphere's center $C_i$ lies within that cell's bounds [S1]. No duplicate entries are created for spheres that geometrically overlap adjacent cells [S1].

**Parameters:**
*   $r_{max}$: The maximum radius across all particles in the dataset [S1].

**Algorithm Steps:**

1.  **Determine Maximum Radius:** Compute $r_{max} = \max_i(r_i)$ [S1].
2.  **Compute Enlarged Frustum:** Construct an enlarged frustum $F_r$ from the original ray packet frustum $F$ [S1].
    *   For each bounding plane of $F$ with normal direction vector $dU$, shift the plane outward by distance $s$ [S1].
    *   The shift distance $s$ is calculated as:
        $$s = r_{max} \sqrt{1 + dU^2}$$
        where $dU$ is the direction vector of the given plane's normal [S1].
    *   Shift the near and far planes of the frustum by $r_{max}$ [S1].
3.  **Grid Construction:** Build the grid on-the-fly [S1]. For each particle $i$ with center $C_i$, determine the grid cell index $(cx, cy, cz)$ containing $C_i$ and append the sphere index $i$ to the list of objects in that cell [S1].
4.  **Traversal:** Traverse the grid using the enlarged frustum $F_r$ [S1]. Identify all grid cells that intersect $F_r$, retrieve the list of spheres stored in each intersected cell, and perform ray-sphere intersection tests for all rays in the packet against all spheres in the cell [S1].
5.  **Early Termination Adjustment:** Adjust early ray termination criteria to accommodate potentially intersecting spheres whose centers lie in the next slice [S1].

**Pseudocode:**

```python
import math

class Plane:
    def __init__(self, normal, distance):
        self.normal = normal  # vec3
        self.distance = distance  # float

class Ray:
    def __init__(self, origin, direction):
        self.origin = origin  # vec3
        self.direction = direction  # vec3

class RayPacket:
    def __init__(self, frustum, rays):
        self.frustum = frustum  # list of Plane
        self.rays = rays  # list of Ray

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def get_cell_index(center, origin, cell_size):
    # Standard grid indexing: floor((center - origin) / cell_size)
    return (
        math.floor((center[0] - origin[0]) / cell_size),
        math.floor((center[1] - origin[1]) / cell_size),
        math.floor((center[2] - origin[2]) / cell_size)
    )

def plane_box_intersect(plane, cell_min, cell_max):
    # Check if a plane intersects an axis-aligned bounding box
    n = plane.normal
    d = plane.distance
    # Find the point in the box that minimizes n.x + d
    min_val = 0.0
    for i in range(3):
        if n[i] > 0:
            min_val += n[i] * cell_min[i]
        else:
            min_val += n[i] * cell_max[i]
    min_val += d
    return min_val <= 0.0  # Box intersects or is on the positive side

def get_cells_intersecting_frustum(grid, frustum_planes, grid_origin, grid_cell_size, grid_dims):
    # Iterates all cells and checks against frustum planes.
    # In practice, CGT traversal is used for efficiency [G].
    cells = []
    for x in range(grid_dims[0]):
        for y in range(grid_dims[1]):
            for z in range(grid_dims[2]):
                cell_min = (grid_origin[0] + x*grid_cell_size, grid_origin[1] + y*grid_cell_size, grid_origin[2] + z*grid_cell_size)
                cell_max = (cell_min[0] + grid_cell_size, cell_min[1] + grid_cell_size, cell_min[2] + grid_cell_size)
                intersects = True
                for plane in frustum_planes:
                    if not plane_box_intersect(plane, cell_min, cell_max):
                        intersects = False
                        break
                if intersects:
                    cells.append((x, y, z))
    return cells

def intersect_ray_sphere(ray_origin, ray_dir, sphere_center, radius):
    # Standard ray-sphere intersection
    oc = (ray_origin[0]-sphere_center[0], ray_origin[1]-sphere_center[1], ray_origin[2]-sphere_center[2])
    a = dot(ray_dir, ray_dir)
    b = 2.0 * dot(oc, ray_dir)
    c = dot(oc, oc) - radius * radius
    discriminant = b*b - 4*a*c
    if discriminant < 0:
        return None
    t = (-b - math.sqrt(discriminant)) / (2.0 * a)
    if t < 0:
        return None
    return t

def sphere_center_method(particles, ray_packet, grid_origin, grid_cell_size, grid_dims):
    # Step 1: Determine maximum radius
    r_max = 0.0
    for p in particles:
        if p.radius > r_max:
            r_max = p.radius

    # Step 2: Compute enlarged frustum
    enlarged_planes = []
    for i, plane in enumerate(ray_packet.frustum):
        n = plane.normal
        d = plane.distance
        # dU is the direction vector of the plane's normal
        du_sq = dot(n, n)
        s = r_max * math.sqrt(1.0 + du_sq)
        
        # Shift plane outward: for n.x + d = 0, shifting along n by s changes d to d - s
        # The source specifies near/far planes are shifted by r_max instead of s
        shift = r_max if i < 2 else s  # Assumes first two planes are near/far
        enlarged_planes.append(Plane(n, d - shift))

    # Step 3: Grid Construction
    grid = {}
    for i, p in enumerate(particles):
        cell = get_cell_index(p.center, grid_origin, grid_cell_size)
        if cell not in grid:
            grid[cell] = []
        grid[cell].append(i)

    # Step 4: Traversal
    intersections = []
    cells_to_visit = get_cells_intersecting_frustum(grid, enlarged_planes, grid_origin, grid_cell_size, grid_dims)

    for cell in cells_to_visit:
        sphere_indices = grid.get(cell, [])
        for ray in ray_packet.rays:
            for idx in sphere_indices:
                p = particles[idx]
                hit = intersect_ray_sphere(ray.origin, ray.direction, p.center, p.radius)
                if hit is not None:
                    intersections.append(hit)

    # Step 5: Early Termination Adjustment
    # The enlarged frustum includes cells adjacent to the original boundary.
    # Early ray termination must be extended to account for spheres in these adjacent cells.
    # This is handled implicitly by traversing the enlarged frustum cells.

    return intersections
```

**Edge Cases and Pitfalls:**
*   **Precision:** The shift calculation involves a square root. Ensure floating-point precision is sufficient for large $r_{max}$ or small grid cells [G].
*   **Boundary Conditions:** The enlargement means spheres whose centers are outside the original ray packet's frustum but whose bodies intersect it will be tested. This is correct behavior but increases the number of intersection tests compared to a tight fit [S1].
*   **Degenerate Input:** If $r_{max} = 0$, the enlarged frustum equals the original frustum. The method degrades to standard point-in-cell storage [G].

## Subtopics

### Macrocell Hierarchical CGT
Uses a hierarchical grid structure to skip empty space faster than a flat grid. Choose when the scene has large empty regions and the overhead of hierarchy traversal is justified. See [Macrocell Hierarchical CGT](5464-macrocell-hierarchical-cgt.md).

### Bundle Parallelisation
Parallelizes the ray-sphere intersection tests across multiple rays in a packet using SIMD or GPU threads. Choose when hardware supports wide vector operations. See [Bundle Parallelisation](6293-bundle-parallelisation.md).

## Operating characteristics
*   **Time Complexity:** Grid construction is $O(N)$ where $N$ is the number of particles [S1]. Traversal is proportional to the number of cells intersecting the enlarged frustum [S1]. Intersection testing is proportional to the number of spheres stored in those cells [S1].
*   **Memory Complexity:** $O(N)$ for storing particle indices in the grid [S1]. No duplicate storage for overlapping spheres [S1].
*   **Performance:** The method reduces storage requirements and avoids the overhead of mailboxes and data reordering [S1]. It performs well for uniformly sized primitives [S1]. For time-varying data, on-the-fly grid construction is required, which adds CPU/GPU overhead [S1].
*   **Strengths:** Eliminates redundant computation and storage [S1]. Simple implementation [G]. Good locality of reference for spatially local primitives [S1].
*   **Limitations:** Requires knowledge of $r_{max}$ beforehand [S1]. The enlarged frustum may include more cells than necessary if $r_{max}$ is much larger than typical radii [S1]. Not suitable for highly variable radii where $r_{max}$ is an outlier [S1].
*   **When to use:** Particle visualization with uniform or narrowly distributed radii [S1]. Interactive ray tracing [S1].
*   **When not to use:** Scenes with highly variable particle sizes where $r_{max}$ is significantly larger than the median radius, leading to excessive frustum enlargement [S1].

## Background
The Sphere-Center Method was introduced in the context of interactive ray tracing for visualizing large particle datasets, such as those from material point method simulations [S1]. It builds on the Coherent Grid Traversal (CGT) algorithm [S1]. The approach is motivated by observations similar to offset surfaces used in collision detection [S1]. It addresses the limitations of traditional grids where primitives overlap multiple cells, requiring mailboxes or reordering [S1]. The method was demonstrated using results from structural mechanics simulations [S1].
