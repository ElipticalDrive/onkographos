# Adaptive Volume Ray Casting

Also called: volume ray casting technique

## Overview
Adaptive Volume Ray Casting is a volume rendering technique where one ray is shot through the volume for each pixel, traversing an octree to accumulate physical values along the ray path [S1, unofficial]. It builds on [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by using the octree structure to determine traversal depth based on camera-defined resolution limits [S1, unofficial]. It produces better image quality than splatting by avoiding splatting artifacts, but is more computationally intensive [S1, unofficial].

## How it works
**Inputs:**
*   Ray origin and direction for each pixel [S1, unofficial].
*   Octree data structure representing the volume [S1, unofficial].
*   Camera parameters defining the maximum resolution level [S1, unofficial].

**Outputs:**
*   Accumulated pixel value for each ray [S1, unofficial].

**Data Structures:**
*   **Octree:** Hierarchical structure where nodes represent spatial subdivisions [S1, unofficial].
*   **Leaf Definition:** Every cell ranked with the maximum level of resolution defined by the camera is considered as a leaf [S1, unofficial]. Highest level of resolution cells are discarded when these cells are too small compared to the image pixel size [S1, unofficial]. The maximum octree depth level read is therefore defined by the camera [S1, unofficial].

**Steps:**
1.  **Find Intersections:** Determine the intersections between the grid and the ray [S1, unofficial]. Using basic 3D geometry calculation, compute the coordinates $(x,y,z)$ of the entry and exit points of the ray in the cell faces [S1, unofficial].
2.  **Traverse Octree:** Start from the root of the octree and traverse down the tree [S1, unofficial]. This top-down traversal of the tree stops when a leaf cell is found [S1, unofficial].
3.  **Accumulate Contribution:** Multiply the cell's observed physical value by the length between the entry and exit points into the cell faces [S1, unofficial]. Add every contribution along the ray to the resulting pixel value, without taking into account any ordering [S1, unofficial].
4.  **Post-Processing (Optional):** Apply an adaptive Gaussian blur filter as an image post-processing option to avoid aliasing in coarse mesh regions by adjusting filter size to local image resolution [S1, unofficial].

**Pseudocode:**
```python
import math

def adaptive_volume_ray_casting(ray_origin, ray_direction, octree_root, camera_max_level):
    """
    Renders a single pixel by traversing an octree and accumulating physical values.
    
    Args:
        ray_origin: tuple (x, y, z), origin of the ray.
        ray_direction: tuple (dx, dy, dz), direction of the ray.
        octree_root: dict, root node of the octree with keys: 'bbox', 'value', 'children', 'level'.
        camera_max_level: int, maximum octree depth level defined by camera.
        
    Returns:
        float, accumulated pixel value.
    """
    # Step 1 & 2: Traverse octree and accumulate contributions
    # The sources describe a top-down traversal that stops at leaf cells.
    # We implement a recursive traversal that computes per-cell entry/exit distances.
    return _traverse_node(octree_root, ray_origin, ray_direction, 0.0, float('inf'), camera_max_level)

def _traverse_node(node, ray_origin, ray_direction, t_min, t_max, camera_max_level):
    """Recursively traverse octree nodes along the ray."""
    # Compute intersection of ray with current node bounding box
    # The exact 3D geometry calculation is not detailed in the sources [G].
    t_entry, t_exit = _ray_box_intersection(ray_origin, ray_direction, node['bbox'])
    
    # If ray misses node or intersection is behind current traversal point, return 0
    if t_entry is None or t_exit <= t_min:
        return 0.0
    
    # Clamp t_max to the exit point of this node
    t_exit = min(t_exit, t_max)
    
    # Step 2 & 3: Stop traversal at leaf cell (or max camera level)
    if node['level'] >= camera_max_level or node['children'] is None:
        # Step 3: Multiply cell's observed physical value by the length between
        # entry and exit points into this cell faces.
        cell_length = t_exit - t_min
        contribution = node['value'] * cell_length
        # Add every contribution along the ray to the resulting pixel value,
        # without taking into account any ordering.
        return contribution
    
    # Recurse into children that intersect the ray
    total_contribution = 0.0
    for child in node['children']:
        total_contribution += _traverse_node(child, ray_origin, ray_direction, t_min, t_exit, camera_max_level)
        
    return total_contribution

def _ray_box_intersection(origin, direction, bbox):
    """
    Compute entry and exit distances (t) of a ray intersecting an axis-aligned bounding box.
    bbox: tuple (min_x, min_y, min_z, max_x, max_y, max_z)
    Returns (t_entry, t_exit) or (None, None) if no intersection.
    Standard ray-AABB intersection logic [G].
    """
    t_min = -float('inf')
    t_max = float('inf')
    
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < bbox[i] or origin[i] > bbox[i + 3]:
                return None, None
        else:
            t1 = (bbox[i] - origin[i]) / direction[i]
            t2 = (bbox[i + 3] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
            
    if t_min > t_max:
        return None, None
    return t_min, t_max
```

**Parameters:**
*   **Camera Max Level:** The maximum octree depth level read is defined by the camera [S1, unofficial]. Cells smaller than the image pixel size at this level are discarded [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Aliasing:** Aliasing can be seen on coarse mesh resolution areas because low simulation resolution leads to big pixels [S1, unofficial]. An adaptive Gaussian blur filter can be used to mitigate this [S1, unofficial].
*   **Ordering:** Contributions are added without taking into account any ordering, which may affect transparency/opacity calculations if not handled by the physical value definition [S1, unofficial].
*   **Precision:** Ray-box intersection calculations may suffer from floating-point precision issues near cell boundaries; standard epsilon guards are recommended [G].

## Operating characteristics
*   **Time Complexity:** Not explicitly given, but described as "more computationally intensive" than splatting [S1, unofficial].
*   **Memory Complexity:** Not explicitly given [S1, unofficial].
*   **Performance:** The software implementation is not interactive on large datasets (e.g., Milky Way simulation with ~200 million AMR cells) [S1, unofficial].
*   **Strengths:** Produces better image quality than splatting (no splatting artifacts) [S1, unofficial]. Convenient to process large datasets as the algorithm is embarrassingly parallel [S1, unofficial].
*   **Limitations:** More computationally intensive than splatting [S1, unofficial]. Aliasing in coarse mesh regions [S1, unofficial].
*   **When to use:** When image quality is prioritized over interactive performance and splatting artifacts are unacceptable [S1, unofficial].
*   **When not to use:** When interactive performance on large datasets is required [S1, unofficial].

## Background
*   **Origin:** Based on volume ray casting explained by Levoy (1990) [S1, unofficial].
*   **History:** Described in the context of AMR (Adaptive Mesh Refinement) simulations, specifically for visualizing large datasets like Milky Way simulations [S1, unofficial].
*   **Usage:** Used in PyMSES software for volume rendering of AMR simulations [S1, unofficial].
