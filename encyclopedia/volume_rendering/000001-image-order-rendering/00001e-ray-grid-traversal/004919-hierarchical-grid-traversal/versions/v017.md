# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal

## Overview
Hierarchical Grid Traversal is a ray-grid traversal method that accelerates volume rendering by marching a ray through a multi-resolution grid hierarchy (mipmap) rather than a single flat grid [S1, unofficial][S2, unofficial]. It solves the performance bottleneck of traversing large, sparse, or multi-resolution volumes by skipping empty or homogeneous regions at coarse levels and only refining the search when the ray intersects active nodes [S1, unofficial][S2, unofficial]. Unlike flat DDA traversal which samples every voxel along the ray path, this method recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB), significantly reducing the number of texture lookups and compositing operations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ (or inverse direction $\mathbf{d}^{-1}$); a hierarchical grid structure (mipmap) with $L$ levels; lookup tables mapping coarse voxel indices to fine voxel children; grid bounds.
*   **Output:** A list of voxel indices (or positions) at the finest level (leaf level) intersected by the ray.

**Data Structures:**
1.  **Lookup Table (`tables_list`):** A list of arrays, one per level. Each row corresponds to a coarse voxel at that level.
    *   Columns 0-7: Indices of the 8 child voxels in the next finer level. If a child is empty or invalid, the value is $-1$ [S1, unofficial].
    *   Columns -3 to -1 (or 8-10 in 0-indexed layout): The 3D grid coordinates $(x, y, z)$ of the coarse voxel [S1, unofficial].
2.  **Ray State:** Current time $t$, current voxel index `ijk`, and boundary distances.
3.  **Hierarchical DDA (HDDA):** A helper structure that manages the ray's position and boundary crossing logic within the current node's coordinate space [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Set the ray's near and far clip distances $t_0$ and $t_1$. Apply a small epsilon $\epsilon$ to avoid precision errors at the origin: $t_0 \leftarrow t_0 + \epsilon$, $t_1 \leftarrow t_1 - \epsilon$ [S2, unofficial]. If $t_0 > t_1$, the ray is invalid.
    *   Determine the starting voxel index `ijk` at the root level (level 0) by flooring the ray origin coordinates: $\text{ijk} = \lfloor \mathbf{o} / \text{voxel\_size}_0 \rfloor$ [S2, unofficial].
    *   Initialize the list of active voxel indices for the current level: `cube_touched_idx` = [`ijk`] [S1, unofficial].
    *   Initialize an empty list `new_list` for the next level [S1, unofficial].

2.  **Hierarchical Traversal Loop:**
    Iterate through each level $l$ from $0$ to $L-1$ (where $L$ is the maximum level):
    *   Retrieve the lookup table for level $l$: $T = \text{tables\_list}[l]$ [S1, unofficial].
    *   For each voxel index $i$ in `cube_touched_idx`:
        *   Retrieve the voxel's physical bounds. Let $\mathbf{c}$ be the coordinates from $T[i, -3:]$ and $s_l$ be the voxel size at level $l$.
        *   $\mathbf{min\_corner} = \mathbf{c} \cdot s_l$
        *   $\mathbf{max\_corner} = \mathbf{c} \cdot s_l + s_l$
        *   Perform Ray-AABB intersection test using the ray $(\mathbf{o}, \mathbf{d})$ and bounds $[\mathbf{min\_corner}, \mathbf{max\_corner}]$ [S1, unofficial].
        *   Compute intersection times $t_n$ (near) and $t_f$ (far). If the ray does not intersect the AABB ($t_n > t_f$), skip this voxel [S1, unofficial].
        *   If the ray intersects:
            *   If $l < L-1$ (not at the leaf level):
                *   Extract the 8 child indices from $T[i, 0:7]$ [S1, unofficial].
                *   Filter out invalid children (where value $\neq -1$) [S1, unofficial].
                *   Append valid child indices to `new_list` [S1, unofficial].
            *   If $l = L-1$ (leaf level):
                *   Append the voxel's position/coordinates to the final result list `cube_ori_list` [S1, unofficial].
    *   Update `cube_touched_idx` = `new_list`.
    *   Reset `new_list` to empty for the next iteration [S1, unofficial].

3.  **Alternative Implementation (HDDA-based):**
    Some implementations use a Hierarchical DDA (HDDA) to manage traversal within nodes [S2, unofficial].
    *   Initialize HDDA with the ray and the root node's bounds [S2, unofficial].
    *   In each step, advance the ray to the next boundary using the DDA logic (min $t_{max}$ among axes) [S2, unofficial].
    *   Check if the current node is a leaf or if it needs refinement. If refinement is needed, compute the child node's bounds and update the HDDA context [S2, unofficial].
    *   Use a small delta $\Delta$ (e.g., $0.01$) to project the ray forward and determine the dimension of the next node to avoid precision issues [S2, unofficial].

**Pseudocode:**

```python
def hierarchical_grid_traversal(ray_origin, ray_direction, tables_list, max_level, voxel_sizes):
    """
    Traverses a hierarchical grid using lookup tables.
    
    Args:
        ray_origin: (3,) array, ray origin.
        ray_direction: (3,) array, ray direction.
        tables_list: List of arrays, where tables_list[l] is the lookup table for level l.
                     Shape: (num_voxels_at_level, 11). Columns 0-7 are child indices, 8-10 are coords.
        max_level: Integer, the maximum depth of the hierarchy (exclusive upper bound for loop).
        voxel_sizes: List of floats, voxel size at each level.
        
    Returns:
        List of (x, y, z) coordinates of leaf voxels intersected by the ray.
    """
    # 1. Initialization
    # Clip ray to valid range if necessary, here we assume ray is valid
    # Determine starting voxel at root level (level 0)
    # Note: In a full implementation, one would use the root AABB to find the initial voxel
    # For this simplified version, we assume the traversal starts with a known root or 
    # the first level's table contains the root. 
    # Based on [S1, unofficial], we start with a list of touched indices. 
    # If we don't have an initial index, we might iterate all roots or use a spatial query.
    # Here we assume `initial_indices` are provided or derived from the root node's bbox intersection.
    # For the sake of the algorithm described in [S1, unofficial], we start with a list.
    # Let's assume we start with the root voxel index 0 for a single root, 
    # or a list of roots if the grid is not a single tree.
    
    cube_touched_idx = [0] # Example: Start with root index 0
    cube_ori_list = []
    
    # 2. Iterate through levels
    for level in range(max_level):
        table = tables_list[level]
        voxel_size = voxel_sizes[level]
        new_list = []
        
        # 3. Process each touched voxel at this level
        for i in cube_touched_idx:
            # Retrieve voxel data from table
            # Columns 0-7: children, Columns 8-10: coords (x, y, z)
            child_indices = table[i, 0:8]
            coords = table[i, 8:11]
            
            # Compute AABB
            # coords are grid indices, multiply by voxel size to get world coordinates
            cube_min = coords * voxel_size
            cube_max = cube_min + voxel_size
            
            # Ray-AABB Intersection
            # Using standard slab method
            inv_dir = 1.0 / ray_direction
            t_min = (cube_min - ray_origin) * inv_dir
            t_max = (cube_max - ray_origin) * inv_dir
            
            # Swap if necessary
            t_min = np.minimum(t_min, t_max)
            t_max = np.maximum(t_min, t_max)
            
            # Find the largest t_min and smallest t_max
            tn = np.max(t_min)
            tf = np.min(t_max)
            
            # Check intersection
            if tn <= tf:
                # Ray intersects this voxel
                if level == max_level - 1:
                    # Leaf level: add to result
                    cube_ori_list.append(coords)
                else:
                    # Internal level: add valid children to next list
                    # Filter out -1 (invalid/empty children)
                    valid_mask = child_indices != -1
                    valid_children = child_indices[valid_mask]
                    new_list.extend(valid_children)
        
        # Update touched indices for next level
        cube_touched_idx = new_list
        
        # Optimization: If no voxels are touched, break early
        if not cube_touched_idx:
            break
            
    return cube_ori_list
```

**Parameters:**
*   `max_level`: The maximum depth of the mipmap hierarchy. The loop runs from $0$ to `max_level` inclusive (or exclusive depending on implementation, typically exclusive upper bound for the number of levels) [S1, unofficial].
*   `epsilon` ($\epsilon$): A small value (e.g., $10^{-6}$) added to $t_0$ to prevent self-intersection or precision errors at the ray origin [S2, unofficial].
*   `Delta`: A small offset (e.g., $0.01$) used in HDDA-based implementations to project the ray forward and determine the next node's dimension, avoiding floating-point rounding errors when far from the grid [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision Errors:** If `Delta` is too large, the ray may clip corners of nodes visibly. If too small, it may fail due to FP32 rounding errors when the ray is far from the grid origin [S2, unofficial].
*   **Epsilon Clipping:** Tweaking the intersection span with `Eps` may clip tiny corner intersections, potentially missing valid voxels [S2, unofficial].
*   **Empty Voxels:** The lookup table must correctly mark empty children with $-1$ to avoid traversing non-existent nodes [S1, unofficial].
*   **Ray Direction Zero:** If a ray direction component is zero, the inverse direction is infinite. The ray never crosses a boundary in that dimension, and the corresponding distance should be treated as infinity [S5].

## Subtopics

### [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md)
A technique that accelerates ray casting by traversing a multi-dimensional hierarchy (mdh) to adaptively choose the resolution level for evaluating volume data. It solves the problem of expensive ray traversal in large volumes by approximating homogeneous regions with least-squares trilinear coefficients, allowing the renderer to skip fine-grained sampling in unimportant or smooth areas. Unlike sibling methods that rely on simple opacity thresholds or constant-value homogeneity, this method uses a user-defined error tolerance and data importance weighting to control refinement, providing a balance between image quality and performance.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
A recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### VolumeHDDA
A specialized Hierarchical Digital Differential Analyzer for traversing volume trees, templated on the tree type, ray type, and the starting node level for traversal [S1, unofficial][S2, unofficial]. It builds on [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by implementing a recursive ray-marching approach that enters child nodes when present and processes active or inactive tiles at leaf levels [S2, unofficial]. It sets itself apart from siblings like [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on discrete tile/voxel intersection detection and time-span management rather than continuous sampling, and from [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) by explicitly handling the hierarchical node structure via template recursion [S1, unofficial][S2, unofficial].

### [XBrickMap](3116-xbrickmap.md)
A space-partitioning ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to skip empty regions via bitwise tests. It improves upon simpler skipping methods by using tiled bitmasks to perform hierarchical skips of $4^3$, $2^3$, and $1^3$ cuboids, while left-packing empty bricks within sectors to save memory. It is distinguished from its sibling [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by its specific use of compacted bitmasks for random access and its support for arbitrary in-place edits within bricks.

### [Spherical Volume Voxel Traversal](3877-spherical-volume-voxel-traversal.md)
A ray-marching algorithm that traverses a ray through a voxel grid structured in spherical coordinates (radial, polar, azimuthal), returning the sequence of voxels intersected by the ray. It solves the problem of efficiently sampling volumetric data defined on a spherical domain, such as planetary atmospheres or star models, where Cartesian grids introduce significant distortion or wasted space near the center. Unlike Cartesian hierarchical traversal which relies on axis-aligned bounding boxes, this method computes intersections with spherical shells, polar cones, and azimuthal wedges directly, handling the singularity at the origin by starting traversal at the first non-zero radial shell. It builds on [Hierarchical Grid Traversal](8384-hierarchical-grid-traversal.md) by specializing the traversal logic for spherical topology rather than octree or uniform grid structures.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
Determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
This family of methods accelerates volume rendering by organizing voxel data into a spatial subdivision hierarchy (e.g., octrees, bricked grids, BVHs) where internal nodes store aggregate information derived from their children or leaf voxels [4133-hierarchical-data-structures]. This structure enables the renderer to prune empty or inactive regions during ray traversal, significantly reducing the number of samples required to generate an image [4133-hierarchical-data-structures]. Unlike flat grid traversal methods, hierarchical approaches adaptively skip large volumes of empty space, making them particularly effective for sparse or multi-resolution datasets [4133-hierarchical-data-structures].

### [Hierarchical DDA with Super-brick Skipping](5197-hierarchical-dda-with-super-brick-skipping.md)
This method accelerates ray tracing through sparse volumetric data by introducing a two-level occupancy hierarchy (super-bricks and bricks) to skip large empty regions, while maintaining pixel-identical output to the fine per-voxel DDA. It solves the performance bottleneck of traversing empty space by verifying emptiness at a coarser granularity and using an axis-aligned bounding box (AABB) for early termination, ensuring exactness by only skipping verified empty blocks and terminating only when the ray definitively passes the occupied volume.

### [Octree-based traversal](5348-octree-based-traversal.md)
Octree-based traversal accelerates volume rendering and implicit surface rendering by recursively navigating a hierarchical spatial subdivision (typically an octree) to skip empty space or cull nodes that do not intersect the ray. It differs from flat grid traversal by using a tree structure to bypass large volumes of empty space, and from Empty-Space Skipping which uses primitive hulls, by employing hierarchical spatial subdivision to locate non-empty space faster. It sets itself apart from its siblings, such as [Octree Partitioning for Sphere Tracing](1541-octree-partitioning-for-sphere-tracing.md), by using explicit bounds tracking and entry/exit side tracking with a callback for leaf processing rather than fixed-step iteration.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty Space Skipping via Data Structures is a family of volume rendering optimization techniques that reduce computational cost by identifying and bypassing inactive (transparent or empty) regions of a volume dataset before or during ray sampling. Unlike methods that rely on hardware occlusion culling or ray coherence, this family uses explicit secondary data structures—such as min-max blocks, occupancy grids, BVHs, or hybrid trees—to store metadata about the spatial distribution of active data [G]. This allows rays to determine entry and exit points of active regions analytically or via coarse traversal, skipping large intervals of empty space that would otherwise require expensive texture lookups and compositing operations.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
Multi-level Grid Structures are a family of hierarchical acceleration algorithms that recursively subdivide a spatial domain into nested grids of varying resolution to optimize ray traversal. They solve the problem of inefficient traversal in non-uniform scenes by replacing pointer-chasing tree structures with contiguous array-based grids, thereby improving memory locality and reducing ray-primitive intersection counts. Unlike flat grids, they adapt resolution based on object density, and unlike tree structures, they use fixed-size grid arrays at each level, allowing for faster traversal via integer arithmetic.

### [Quadtree Raycasting](8208-quadtree-raycasting.md)
Quadtree Raycasting is a recursive ray-quadtree intersection algorithm that traverses a 2D quadtree to find the first hit node. It solves the problem of efficiently locating the first occupied voxel in a hierarchical 2D grid by handling ray direction flipping via a mask to ensure consistent traversal order regardless of ray direction. It sets itself apart from non-hierarchical methods like DDA by leveraging the spatial coherence of the quadtree structure to skip empty regions, and differs from standard AABB traversal by operating on a tree of variable-sized nodes rather than a uniform grid.

### [Hierarchical Tree Node Traversal](12213-hierarchical-tree-node-traversal.md)
Hierarchical Tree Node Traversal is a ray-intersection method that accelerates volume rendering by traversing a boolean tree structure representing the active regions of a volume grid. It solves the problem of efficiently skipping empty space and coarse structures during ray marching. Unlike sibling methods that may traverse uniform grids or specific brick layouts, this approach operates on a generic hierarchical tree (typically an octree or similar sparse structure) where nodes represent tiles or voxels, allowing for variable-resolution traversal. It is implemented in OpenVDB as the `VolumeRayIntersector` class.

### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. It groups scalar values within a certain range together based on the transfer function to define sub-volume properties, uses a kd-tree to render the partitioned volume with correct visibility order, and culls and clips each sub-volume against an opacity map [S3, unofficial]. Reported performance was 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].

### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial]. It identifies occupied voxels in the fine grid, assigns unique indices, extracts the 8 sub-grid regions corresponding to the 8 children of a coarse voxel, flattens these sub-grids, filters them using the coarse grid mask, and populates the table with child indices (columns 0-7) and coarse voxel coordinates (columns 8-10) [S1, unofficial].

### VIPER Ray-Traversal and Surface Intersection Algorithm
A ray-traversal algorithm with time complexity $O(p \cdot r)$, where $p$ is the number of pixels and $r$ is the volume's largest dimension in voxels [S4, unofficial]. It uses a relative distance formula: $\text{relative distance} = (\text{target} - \text{value1}) / (\text{value2} - \text{value1})$ [S4, unofficial].

### Hierarchical Data Structure Traversal
A parallel ray-casting approach where each processor performs cell connectivity pre-steps, excludes cells outside the camera view, and applies ray-casting to its data [S5]. Each ray enters the volume from an exterior face and uses connectivity information to determine the next cell, exiting when it intersects a second exterior face [S5]. Image pixels are assigned to different processors, and a Hierarchical Data Structure (HDS) is used to exchange rays, which are then composited to produce the final image [S5].

### World-Space Voxel Raycast with Transform
Performs raycasting in world space by transforming the ray to local voxel space, calling the generic raycast, and transforming results back [S6, unofficial]. It computes the ray end in world space, transforms the origin and end to local space, calculates the local direction and distance, and calls the generic raycast [S6, unofficial]. It scales the distance and normal back to world space if enabled, and handles zero-length rays by returning an empty result [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** The traversal time depends on the number of active voxels and the depth of the hierarchy. In the worst case (fully occupied volume), it approaches the complexity of flat DDA, but with overhead for hierarchy management. In sparse volumes, it is significantly faster, proportional to the number of leaf voxels intersected [S1, unofficial][S4, unofficial].
*   **Memory Complexity:** Requires storage for the hierarchical grid data and the lookup tables. The lookup tables add memory overhead proportional to the number of voxels at each level, but allow for fast, cache-friendly traversal [S1, unofficial].
*   **Performance:** Reported performance varies by implementation and hardware. For example, KD-Tree partitioned variants reported 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].
*   **Strengths:** Efficiently handles sparse and multi-resolution data; reduces texture fetches; suitable for large volumes where most space is empty or homogeneous.
*   **Limitations:** Requires preprocessing to build the hierarchy and lookup tables; overhead for small volumes or fully occupied grids may negate benefits; precision issues can arise if epsilon/delta parameters are not tuned correctly [S2, unofficial].

## Background
Hierarchical Grid Traversal is a method within the broader field of volume rendering, specifically under image-order rendering and ray-grid traversal. It builds on the principles of DDA traversal [17-ray-grid-traversal.md] but introduces a multi-resolution structure to optimize the search process. The method is closely related to hierarchical data structures like octrees and bricked grids, which allow for adaptive resolution and empty-space skipping [4133-hierarchical-data-structures]. Variants such as VolumeHDDA and XBrickMap extend the core concept to specific data layouts and traversal optimizations.
