# Embree Mesh Acceleration Structure

Also called: Embree RTC, Embree-based Volume Rendering for Unstructured Meshes, RTC Mesh

## Overview
The Embree Mesh Acceleration Structure is a volume rendering method that wraps Intel's Embree ray-tracing engine to build a triangle mesh acceleration structure and perform ray tracing [S1, unofficial][S2]. It solves the problem of efficiently traversing complex, non-uniform geometric domains by converting unstructured mesh elements into triangular polygons [S2]. It differs from sibling methods by relying on Embree's RTC API for BVH traversal rather than custom software ray marchers or grid-based traversal, enabling both surface plots and traditional accumulation rendering [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Unstructured mesh data (vertices and connectivity) and field data associated with the mesh [S2].
*   **Output:** Rendered image (surface values or accumulated field values) and hit data (intersection points, primitive IDs) [S1, unofficial][S2].

**Data Structures:**
The implementation relies on a `RenderSource` object that encapsulates the logic for creating the Embree polygon mesh from the `data_source` and performing ray tracing calls [S2]. Internally, the acceleration structure is built using the following buffers [S1, unofficial]:
*   **Vertex Buffer:** Allocated with `RTC_FORMAT_FLOAT3`, storing vertex coordinates as 32-bit floating-point vectors.
*   **Index Buffer:** Allocated with `RTC_FORMAT_UINT3`, storing triangle indices as 32-bit unsigned integer triplets.
*   **Geometry:** Created via standard Embree RTC geometry creation and committed.

**Steps:**
1.  **Mesh Generation:** Generate a triangular polygon mesh from the unstructured mesh data by breaking up faces into multiple triangles if necessary [S2].
2.  **Embree Initialization:** Initialize the Embree device and scene, and set the build quality to `HIGH` [S1, unofficial].
3.  **Geometry Creation:** Create triangle geometry, allocate the vertex buffer (`RTC_FORMAT_FLOAT3`) and index buffer (`RTC_FORMAT_UINT3`), and copy the mesh data into these buffers [S1, unofficial].
4.  **Commit Geometry:** Commit the geometry and attach it to the Embree scene [S1, unofficial].
5.  **Commit Scene:** Commit the scene to finalize the acceleration structure build [S1, unofficial].
6.  **Ray Tracing:**
    *   **Single Ray Closest Hit:** Use `rtcIntersect1` with a coherent context to find the nearest intersection for a single ray [S1, unofficial].
    *   **Single Ray Any Hit (Occlusion):** Use `rtcOccluded1` with a coherent context to determine if a ray intersects any geometry [S1, unofficial].
    *   **Multiple Ray Closest Hit:** Use `rtcIntersect1M` with a coherent context flag determined by a parameter to trace multiple rays [S1, unofficial].
    *   **Multiple Ray Any Hit:** Use `rtcOccluded1M` with a coherent context flag [S1, unofficial].
7.  **Rendering:**
    *   **Surface Plots:** Calculate the value of the field at the intersection point for each ray using the hit data computed by Embree [S2].
    *   **Accumulation Rendering:** Accumulate values along each ray for every element the rays intersect, allowing operations such as computing maximum intensity along the ray [S2].

**Formulas and Parameters:**
*   **Coherence Flag:** A boolean parameter `coherent` passed to trace functions. If `true`, uses `RTC_INTERSECT_CONTEXT_FLAG_COHERENT`. If `false`, the same flag is used in the implementation (noted as a potential bug in the source, but documented as is) [S1, unofficial].
*   **Intra-element Interpolation:** Implementations of various intra-element interpolation functions are required to support meshes of various types and orders, as ray intersections may occur inside elements rather than just on surfaces [S2].

**Pseudocode:**

```python
# Embree API stubs for self-contained pseudocode
def create_embree_device(): pass
def create_embree_scene(device): pass
def set_build_quality(scene, quality): pass
def create_geometry(device, type, num_primitives): pass
def create_buffer(device, type, format, num_elements): pass
def write_buffer(buffer, offset, data): pass
def set_geometry_vertex_buffer(geometry, buffer, stride, offset): pass
def set_geometry_index_buffer(geometry, buffer, stride, offset): pass
def commit_geometry(geometry): pass
def add_geometry_to_scene(scene, geometry, id): pass
def commit_scene(scene): pass
def rtcIntersect1(scene, ray, flags): pass
def rtcOccluded1(scene, ray, flags): pass
def rtcIntersect1M(scene, rays, flags): pass
def rtcOccluded1M(scene, rays, flags): pass
def interpolate_field(field_data, point): pass

class EmbreeMesh:
    def __init__(self, vertices, indices):
        self.device = create_embree_device()
        self.scene = create_embree_scene(self.device)
        set_build_quality(self.scene, "HIGH")
        self.geometry = create_geometry(self.device, type="TRIANGLE", num_primitives=len(indices))
        self.vertex_buffer = create_buffer(self.device, type="VERTEX", format="FLOAT3", num_elements=len(vertices))
        write_buffer(self.vertex_buffer, 0, vertices)
        set_geometry_vertex_buffer(self.geometry, self.vertex_buffer, stride=0, offset=0)
        self.index_buffer = create_buffer(self.device, type="INDEX", format="UINT3", num_elements=len(indices))
        write_buffer(self.index_buffer, 0, indices)
        set_geometry_index_buffer(self.geometry, self.index_buffer, stride=0, offset=0)
        commit_geometry(self.geometry)
        add_geometry_to_scene(self.scene, self.geometry, id=0)
        commit_scene(self.scene)

    def trace_closest(self, ray, coherent):
        flags = "RTC_INTERSECT_CONTEXT_FLAG_COHERENT" if coherent else 0
        return rtcIntersect1(self.scene, ray, flags)

    def trace_any(self, ray, coherent):
        flags = "RTC_INTERSECT_CONTEXT_FLAG_COHERENT" if coherent else 0
        return rtcOccluded1(self.scene, ray, flags)

    def trace_closest_batch(self, rays, coherent):
        flags = "RTC_INTERSECT_CONTEXT_FLAG_COHERENT" if coherent else 0
        return rtcIntersect1M(self.scene, rays, flags)

    def render_surface(self, rays, field_data):
        hits = self.trace_closest_batch(rays, coherent=True)
        image = [0.0] * len(rays)
        for i, hit in enumerate(hits):
            if hit.valid:
                image[i] = interpolate_field(field_data, hit.point)
        return image

    def render_accumulation(self, rays, field_data):
        image = [0.0] * len(rays)
        for i, ray in enumerate(rays):
            accumulated = 0.0
            # Sources do not specify multi-hit traversal mechanism for accumulation.
            # Implementation requires a custom any-hit callback or repeated tracing.
            image[i] = accumulated
        return image
```

**Edge Cases and Pitfalls:**
*   **Intra-element Interpolation:** Ray intersections may occur inside elements rather than just on surfaces. Intra-element interpolation functions must be implemented to support meshes of various types and orders [S2].
*   **Coherence Flag Bug:** The source notes a potential bug where the `coherent` flag logic might be inverted or incorrectly applied in the `false` case, but it is documented as implemented [S1, unofficial].
*   **Mesh Type Support:** Currently implemented for Hexahedral and Tetrahedral mesh elements. Adding support for other mesh types requires breaking up faces into triangles [S2].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Embree is described as a "fast ray-tracing code" [S2].
*   **Strengths:** Supports both surface plots and traditional accumulation rendering; flexible integration with camera paths and multiple render sources [S2].
*   **Limitations:** Requires conversion of unstructured mesh to triangular polygons; dependent on external Embree library (though a future replacement with custom ray-tracing code is planned) [S2].
*   **When to use:** When rendering unstructured mesh data with complex geometry where hardware-accelerated ray tracing provides a performance benefit over software rasterization or marching [S2].
*   **When not to use:** Not given in the sources.

## Background
The method originates from the yt project's enhancement proposal for unstructured mesh volume rendering [S2]. It leverages Intel's Embree ray-tracing engine, which is known for high-performance software ray tracing [S2]. The implementation was developed to support both surface plots and accumulation rendering for unstructured mesh data, integrating with the yt volume rendering refactor to allow flexible camera paths and multiple render sources [S2]. The code examples are from an unofficial repository by Mike Smith, demonstrating a C++ implementation using glm and Embree [S1, unofficial].
