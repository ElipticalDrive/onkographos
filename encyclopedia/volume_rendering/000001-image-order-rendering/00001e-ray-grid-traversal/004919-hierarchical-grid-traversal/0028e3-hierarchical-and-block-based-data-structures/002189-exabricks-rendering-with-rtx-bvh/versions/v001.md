# ExaBricks Rendering with RTX BVH

Also called: Ray tracing structured AMR data using ExaBricks

## Overview
ExaBricks Rendering with RTX BVH is a hardware-accelerated volume rendering method for Adaptive Block-Refined (ABR) data that utilizes an RTX Bounding Volume Hierarchy (BVH) to traverse spatial regions, perform volume integration, and skip empty space [S1]. It distinguishes itself from software-based k-d tree approaches (e.g., Kähler et al. [17]) by leveraging GPU hardware ray tracing to avoid non-trivial control flow and per-thread stacks in shaders, while supporting interactive transfer function editing and adaptive sampling [S1].

## How it works
**Inputs:**
*   A set of Adaptive Block-Refined (ABR) regions derived from AMR data.
*   A transfer function mapping scalar values to color and opacity.
*   A ray origin and direction for each pixel/sample.
*   $t_{max}$, the maximum traversal distance.

**Outputs:**
*   Computed color and opacity for each ray.

**Data Structures:**
*   **ABR Region:** Defined by its spatial bounding box and a precomputed scalar range $[min\_val, max\_val]$ of the data contained within it [S1].
*   **RTX BVH:** An acceleration structure built over the ABR regions. It contains one primitive per ABR region. The BVH is constructed using NVIDIA RTX hardware acceleration APIs [S1].

**Algorithm Steps:**

1.  **BVH Construction (Offline/Update Phase):**
    For each ABR region $R_i$:
    1.  Retrieve the precomputed scalar range $[min\_val_i, max\_val_i]$ for the region.
    2.  Compute the maximum possible opacity $\alpha_{max}$ using the transfer function $TF$ over the range $[min\_val_i, max\_val_i]$.
        $$ \alpha_{max} = \max_{v \in [min\_val_i, max\_val_i]} TF(v).opacity $$
    3.  If $\alpha_{max} == 0$, the region is fully transparent. Return an empty bounding box (or exclude the primitive) for this region in the BVH.
    4.  If $\alpha_{max} > 0$, return the region's actual spatial bounding box as the primitive for the BVH [S1].

2.  **Ray Traversal (Per-Frame/Per-Ray):**
    For each ray $r$ with origin $O$ and direction $D$:
    1.  Initialize the search interval $[t_{start}, t_{end}] = [0, t_{max})$ [S1].
    2.  Perform hardware-accelerated ray traversal against the RTX BVH using the current interval.
    3.  If no region is intersected, terminate the ray [S1].
    4.  If a region $R$ is intersected at distance $t_{hit}$:
        a.  Compute the overlap interval $[t_{in}, t_{out}]$ between the ray and the region $R$.
            *   $t_{in} = \max(t_{start}, t_{hit\_entry})$
            *   $t_{out} = \min(t_{end}, t_{hit\_exit})$
        b.  Volume-integrate the samples within $[t_{in}, t_{out}]$ over region $R$. This involves sampling the ABR data structure (using the adaptive sampling strategy defined in [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md)) and accumulating color/opacity [S1].
        c.  Check for early ray termination (if accumulated opacity $\ge 1.0$). If terminated, stop.
        d.  Update the search interval: $t_{start} = t_{out} + \epsilon$, where $\epsilon$ is a small epsilon to prevent self-intersection or re-traversal of the same region boundary.
        e.  Repeat from step 2 with the new interval.

**Parameters:**
*   $\epsilon$: A small positive value to offset the next ray start. Value not given in the sources [G].
*   $t_{max}$: Maximum ray length. Typical values depend on scene scale [G].

**Edge Cases and Pitfalls:**
*   **Transfer Function Changes:** The BVH must be rebuilt when the transfer function or iso-value changes because the opacity pruning depends on the current transfer function [S1].
*   **Empty Space:** Truly empty space (outside the AMR mesh) is automatically skipped as it generates no bricks or regions [S1].
*   **Performance Cost:** BVH rebuilds are expensive. On the Exajet dataset (656M cells), a full rebuild takes ~300ms on a Titan RTX or RTX 8000 [S1].

## Subtopics

### [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md)
Adaptive Sampling with Region Delimiters is a sampling strategy for ABR data that adapts the sampling rate to the finest cell size within each region, using sample positions as delimiters to handle boundary artifacts. Unlike Ljung [23], which defines a global set of finest level samples skipped by coarseness, this method defines independent sampling intervals for each region. It solves the problem of boundary artifacts caused by successive regions sampled at different rates, where the distance between the last sample of one region and the first of the next can be smaller or larger than either region's sampling rate.

### RTX BVH Ray Tracing
Using an RTX BVH built over regions for hardware-accelerated ray marching, space skipping, and adaptive sampling, supporting interactive transfer function and iso-surface editing [S1]. This variant emphasizes the use of hardware ray tracing cores to amortize the cost of multiple ray traversals over multiple samples taken within the next region [S1].

### BVH Pruning for Space Skipping
A technique to skip empty space and fully transparent regions during ray traversal by excluding them from the BVH during construction [S1]. During BVH construction, each ABR's precomputed scalar range is used to compute the maximum opacity of the transfer function within that range. If the maximum opacity is 0, the region is discarded by returning an empty box for its primitive in the BVH. If the maximum opacity is not 0, the region's bounding box is returned. This requires a BVH rebuild on transfer function or iso-value change but avoids checking region validity during traversal [S1].

## Operating characteristics
*   **Time Complexity:** The traversal cost is amortized over multiple samples within each region due to hardware acceleration [S1]. However, each ray may perform several hardware ray traversals (one per region intersected) [S1].
*   **Memory Complexity:** Depends on the number of ABR regions. The BVH stores one primitive per region [S1].
*   **Measured Performance:** On the Exajet dataset (656M cells, 55.8M regions), the BVH rebuild takes ~300ms on a Titan RTX or RTX 8000 [S1].
*   **Strengths:** Hardware-accelerated traversal avoids non-trivial control flow in shaders. Supports interactive transfer function editing. Adaptive sampling ensures tractable sample counts for AMR data.
*   **Limitations:** BVH rebuilds are required when the transfer function changes, which can be costly (~300ms for large datasets). Refitting the BVH could improve this time [S1].
*   **When to use:** Interactive direct volume rendering of large AMR datasets where transfer function editing is required.
*   **When not to use:** Static scenes with fixed transfer functions where software k-d tree traversal might be more memory-efficient or where BVH rebuild costs are prohibitive.

## Background
The method was introduced in the paper "Ray Tracing Structured AMR Data Using ExaBricks" [S1]. It builds on the ExaBricks data structure, which uses a convolution filter to store which bricks can influence each region, enabling fast basis reconstruction without costly cell location kernels [S1]. The approach was developed to support interactive high-quality direct volume rendering with smooth AMR reconstruction filters and gradient-based volume shading, combined with surface shading from implicit isosurfaces [S1]. It addresses the limitations of previous software-based k-d tree traversals (e.g., Kähler et al. [17]) by leveraging new RTX hardware available on GPUs [S1].
