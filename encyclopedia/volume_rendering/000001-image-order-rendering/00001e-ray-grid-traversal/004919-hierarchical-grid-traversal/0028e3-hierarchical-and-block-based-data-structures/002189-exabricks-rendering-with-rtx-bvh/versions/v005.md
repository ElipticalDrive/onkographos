# ExaBricks Rendering with RTX BVH

Also called: Ray tracing structured AMR data using ExaBricks

## Overview
ExaBricks Rendering with RTX BVH is a method for rendering Adaptive Block-Refined (ABR) volume data that utilizes hardware-accelerated RTX Bounding Volume Hierarchy (BVH) traversal to iterate through spatial regions, performing volume integration within each region while skipping empty space [S1]. It distinguishes itself from sibling methods like [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md) and [Hierarchical Data Structures](4133-hierarchical-data-structures.md) by replacing software-based k-d tree or octree traversal with dedicated hardware RT Cores, thereby avoiding complex control flow and per-thread stacks in shaders [S1]. This approach enables interactive editing of transfer functions and iso-surfaces, provided the acceleration structure is updated accordingly [S1].

## How it works
**Inputs:**
*   Adaptive Block-Refined (ABR) dataset: A collection of regions, where each region corresponds to a set of AMR cells [S1].
*   Transfer function: Defines the opacity and color mapping for scalar values [S1].
*   Ray parameters: Origin, direction, and maximum traversal distance $t_{max}$ [S1].

**Outputs:**
*   Final color and opacity for each pixel [S1].

**Data Structures:**
*   **RTX BVH:** A Bounding Volume Hierarchy constructed over the ABR regions [S1].
    *   **Primitives:** Each primitive corresponds to one ABR region [S1].
    *   **Bounding Box:** For each primitive, the bounding box is the spatial extent of the region [S1].
    *   **Empty Box Handling:** If a region is fully transparent (maximum opacity 0 for the current transfer function), its primitive is assigned an empty bounding box or discarded from the BVH construction entirely, making it invisible to traversal [S1].
    *   **Visibility Box:** If a region has non-zero maximum opacity, its primitive is assigned its full spatial bounding box [S1].

**Algorithm Steps:**
1.  **BVH Construction:** For each ABR region, compute the precomputed scalar range (min/max values) of the cells within that region. Evaluate the transfer function over this scalar range to determine the maximum possible opacity. If the maximum opacity is 0, mark the region as fully transparent and return an empty box for its primitive. If the maximum opacity is greater than 0, return the region's spatial bounding box for its primitive [S1].
2.  **Ray Initialization:** For each primary ray, initialize a search interval $[0, t_{max})$ [S1].
3.  **Hardware Traversal:** Trace the ray through the RTX BVH using hardware acceleration. If no region is intersected, the ray terminates and the remaining interval is considered empty space [S1].
4.  **Region Intersection and Integration:** If a region is intersected, compute the overlap interval $[t_{in}, t_{out}]$ between the ray and the region's bounding box. Perform volume integration over the samples within $[t_{in}, t_{out}]$ for the specific ABR region, which involves sampling the scalar field, applying the transfer function, and accumulating color and opacity [S1].
5.  **Next Region Search:** If the ray is not terminated, initiate a new ray traversal starting from $t_{out} + \epsilon$ (where $\epsilon$ is a small constant to avoid precision gaps) [S1]. Repeat steps 3-5 until no subsequent region is found or the ray becomes opaque [S1].

**Pseudocode:**
```python
def render_exabricks_ray(ray_origin, ray_direction, t_max, transfer_function, bvh):
    """
    Renders a single ray using ExaBricks with RTX BVH.
    
    Args:
        ray_origin: list[float], origin of the ray.
        ray_direction: list[float], normalized direction of the ray.
        t_max: float, maximum distance to trace.
        transfer_function: callable, maps scalar value to (color, opacity).
        bvh: BVH structure, supports hardware ray intersection.
        
    Returns:
        list[float], final color and opacity (RGBA).
    """
    accumulated_color = [0.0, 0.0, 0.0, 0.0]
    accumulated_opacity = 0.0
    current_t = 0.0
    epsilon = 1e-6  # Small value to prevent self-intersection [G]

    while current_t < t_max:
        # Hardware-accelerated BVH traversal
        hit = bvh.intersect(ray_origin, ray_direction, current_t, t_max)
        
        if hit is None:
            break
            
        t_hit = hit.distance
        region = hit.primitive
        bbox = region.bounding_box

        # Compute overlap interval [t_in, t_out] with the region's bounding box
        t_in, t_out = ray_box_intersection(ray_origin, ray_direction, bbox)

        # Clamp to valid range and current traversal state
        t_in = max(current_t, t_in)
        t_out = min(t_max, t_out)

        if t_in >= t_out:
            current_t = t_out + epsilon
            continue

        # Volume integration over [t_in, t_out]
        color, opacity = volume_integrate(ray_origin, ray_direction, t_in, t_out, region.data, transfer_function)

        # Composite
        accumulated_color[0] += color[0] * (1.0 - accumulated_opacity)
        accumulated_color[1] += color[1] * (1.0 - accumulated_opacity)
        accumulated_color[2] += color[2] * (1.0 - accumulated_opacity)
        accumulated_opacity += opacity * (1.0 - accumulated_opacity)

        if accumulated_opacity >= 1.0:
            break

        current_t = t_out + epsilon

    return accumulated_color, accumulated_opacity

def ray_box_intersection(origin, direction, bbox):
    """Standard slab method for ray-AABB intersection."""
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if direction[i] == 0:
            if origin[i] < bbox.min[i] or origin[i] > bbox.max[i]:
                return -1.0, -1.0
        else:
            t1 = (bbox.min[i] - origin[i]) / direction[i]
            t2 = (bbox.max[i] - origin[i]) / direction[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    return t_min, t_max

def volume_integrate(origin, direction, t_in, t_out, region_data, transfer_function):
    """Performs volume integration over a specific region."""
    step = region_data.step_size  # Depends on region resolution [G]
    color = [0.0, 0.0, 0.0]
    opacity = 0.0
    t = t_in
    while t < t_out:
        scalar = region_data.sample(origin[0] + direction[0] * t, 
                                    origin[1] + direction[1] * t, 
                                    origin[2] + direction[2] * t)
        c, o = transfer_function(scalar)
        alpha = o * step
        color[0] += c[0] * alpha * (1.0 - opacity)
        color[1] += c[1] * alpha * (1.0 - opacity)
        color[2] += c[2] * alpha * (1.0 - opacity)
        opacity += alpha
        t += step
    return color, opacity
```

**Parameters:**
*   $\epsilon$: Small constant to prevent precision gaps when starting the next ray traversal. Value not specified in sources [G].
*   $t_{max}$: Maximum traversal distance. Typical values depend on scene scale [G].

**Edge Cases and Pitfalls:**
*   **BVH Rebuild Cost:** The BVH must be rebuilt whenever the transfer function or iso-value changes, as the visibility of regions depends on the maximum opacity within their scalar ranges. On the Exajet dataset, a full rebuild takes approximately 300ms on a Titan RTX or RTX 8000 GPU [S1].
*   **Transfer Function Changes:** Unlike methods that check region validity during traversal, this method excludes fully transparent regions from the BVH entirely. This avoids traversal checks but necessitates BVH updates for any transfer function change [S1].
*   **Precision:** Using a new ray traversal for each iteration step means multiple hardware ray traversals per volume ray. Precision issues at region boundaries ($t_{out} + \epsilon$) must be handled to avoid gaps or overlaps [S1].

## Subtopics

### [RTX BVH Ray Tracing](2957-rtx-bvh-ray-tracing.md)
RTX BVH Ray Tracing is a rendering method for Adaptive Block-Refined (ABR) data that uses hardware-accelerated RTX BVH traversal to iterate through regions, performing volume integration within each region and skipping empty space. It sets itself apart from sibling methods like [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md) by leveraging dedicated hardware ray-tracing cores (RT Cores) for acceleration structure traversal, enabling interactive transfer function and iso-surface editing.

### [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md)
Adaptive Sampling with Region Delimiters is a sampling strategy for Adaptive Block-Refined (ABR) volume data that adapts the sampling rate to the finest cell size within each region, using sample positions as delimiters to handle boundary artifacts. Unlike Ljung [23], which defines a global set of finest level samples skipped by coarseness, this method defines independent sampling intervals for each region. It solves the problem of boundary artifacts caused by successive regions sampled at different rates, where the distance between the last sample of one region and the first of the next can be smaller or larger than either region's sampling rate.

### [Sparse Brick Set Rendering](9909-sparse-brick-set-rendering.md)
Sparse Brick Set Rendering is a method for rendering Signed Distance Fields (SDFs) using hardware-accelerated raytracing against a Bounding Volume Hierarchy (BVH) of leaf bricks, where each brick contains SDF data and is intersected via software shaders and sphere-tracing. It differs from its parent [ExaBricks Rendering with RTX BVH](2577-exabricks-rendering-with-rtx-bvh.md) by specifically utilizing SDF sphere-tracing within leaf nodes rather than general volume integration, and from [RTX BVH Ray Tracing](2957-rtx-bvh-ray-tracing.md) by relying on software intersection shaders for the SDF geometry rather than hardware-native triangle or primitive intersection.

### BVH Pruning for Space Skipping
A technique to skip empty space and fully transparent regions during ray traversal by excluding them from the BVH during construction [S1]. During BVH construction, each ABR's precomputed scalar range is used to compute the maximum opacity of the transfer function within that range. If the maximum opacity for the range is 0, the region is discarded by returning an empty box for its primitive in the BVH. If the maximum opacity is not 0, the region's bounding box is returned. This requires a BVH rebuild on transfer function or iso-value changes, but avoids checking region validity during traversal [S1].

## Operating characteristics
*   **Time Complexity:** The traversal cost is amortized over multiple samples taken within each region due to hardware acceleration [S1]. However, each region intersection requires a new ray traversal, leading to multiple hardware traversals per volume ray [S1].
*   **Memory Complexity:** The BVH stores one primitive per ABR region. The size depends on the number of regions and the depth of the BVH [S1].
*   **Measured Performance:** On the Exajet dataset (656M cells, 3.1M regions, 55.8M bricks), the method achieves interactive frame rates, though specific FPS values are not provided in the sources [S1]. BVH rebuild time is approximately 300ms on a Titan RTX or RTX 8000 for the Exajet dataset [S1].
*   **Strengths:** Hardware-accelerated traversal avoids non-trivial control flow in shaders compared to software k-d tree traversal [S1]. Space skipping is efficient as fully transparent regions are excluded from the BVH [S1].
*   **Limitations:** BVH rebuild is required for every transfer function or iso-value change, which can be costly for large datasets [S1]. Multiple ray traversals per volume ray may introduce overhead if regions are small or numerous [S1].
*   **When to Use:** Suitable for interactive volume rendering of AMR data where transfer function editing is required and hardware RTX support is available [S1].
*   **When Not to Use:** Not suitable for static scenes with fixed transfer functions where BVH rebuild cost is prohibitive, or on hardware without RTX support [S1].

## Background
The method was introduced in the paper "Ray Tracing Structured AMR Data Using ExaBricks" [S1]. It builds upon the ExaBricks data structure, which organizes AMR data into Adaptive Block-Refined (ABR) regions. The approach contrasts with earlier software-based methods like those by Kähler et al. [17], which used software k-d tree traversal with per-thread stacks [S1]. The use of RTX hardware acceleration represents a shift towards leveraging dedicated GPU hardware for acceleration structure traversal in volume rendering [S1].
