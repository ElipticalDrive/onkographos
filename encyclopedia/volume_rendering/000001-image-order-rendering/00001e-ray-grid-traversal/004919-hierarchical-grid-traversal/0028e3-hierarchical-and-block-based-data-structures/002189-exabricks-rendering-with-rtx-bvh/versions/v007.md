# ExaBricks Rendering with RTX BVH

Also called: Ray tracing structured AMR data using ExaBricks

## Overview
ExaBricks Rendering with RTX BVH is a method for rendering Adaptive Block-Refined (ABR) volume data that leverages hardware-accelerated Bounding Volume Hierarchy (BVH) traversal to iterate through data regions, performing volume integration within each region while skipping empty space [S1]. It is distinguished from sibling methods by its reliance on NVIDIA RTX hardware acceleration for both traversal and shading, enabling interactive transfer function and iso-surface editing alongside adaptive sampling [S1]. Unlike [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md) which may use software-based logic for region boundaries, or [Sparse Brick Set Rendering](9909-sparse-brick-set-rendering.md) which focuses on sparse data structures, this method explicitly leverages the RTX ray tracing cores for efficient space skipping and adaptive sample density control [S1].

## How it works
**Inputs:**
*   A set of Adaptive Block-Refined (ABR) regions derived from structured AMR data.
*   A transfer function mapping scalar values to color and opacity.
*   Ray origins and directions for the image.
*   Maximum ray distance $t_{max}$.

**Outputs:**
*   Final color and opacity for each pixel.

**Data Structures:**
*   **ABR Region:** A spatial region containing a set of bricks. Each region has a precomputed scalar range $[min, max]$ of the data it contains and a geometric bounding box.
*   **RTX BVH:** A Bounding Volume Hierarchy constructed over the ABR regions. The BVH is built using NVIDIA RTX user geometry primitives. Each primitive corresponds to one ABR region.
    *   **Primitive Layout:** If a region is fully transparent (max opacity 0), its primitive is an empty box (discarded). Otherwise, the primitive is the region's bounding box.

**Algorithm Steps:**

1.  **BVH Construction:**
    *   For each ABR region, compute the maximum opacity $\alpha_{max}$ of the transfer function over the region's scalar range $[min, max]$.
    *   If $\alpha_{max} == 0$, assign an empty bounding box to the region's BVH primitive (effectively removing it from the hierarchy).
    *   If $\alpha_{max} > 0$, assign the region's geometric bounding box to the BVH primitive.
    *   Build the RTX BVH over these primitives [S1].

2.  **Ray Initialization:**
    *   For each pixel, initialize a ray with origin $O$, direction $D$, and search interval $[0, t_{max})$ [S1].

3.  **Hardware Traversal:**
    *   Trace the ray through the RTX BVH in hardware.
    *   If no region is intersected, the ray terminates. The pixel color is set to the background color [S1].

4.  **Region Intersection and Integration:**
    *   If a region is intersected, compute the overlap interval $[t_{in}, t_{out}]$ between the ray and the region's bounding box.
    *   Perform volume integration over the interval $[t_{in}, t_{out}]$ using the samples within the ABR region. The integration updates the accumulated color and opacity.
    *   Check for early ray termination (if accumulated opacity reaches 1.0). If terminated, stop processing this ray [S1].

5.  **Next Region Search:**
    *   If the ray is not yet opaque, trace a new ray starting from $t_{out} + \epsilon$ (where $\epsilon$ is a small bias to avoid self-intersection) to find the next ABR region.
    *   Repeat steps 3-5 until the ray becomes opaque or no subsequent region is found [S1].

**Pseudocode:**

```python

    """
    Renders a single ray using ExaBricks data structure and RTX BVH.
    
    Args:
        ray_origin: vec3, origin of the ray.
        ray_direction: vec3, normalized direction of the ray.
        t_max: float, maximum distance to trace.
        bvh: RTX BVH object, containing ABR region primitives.
        transfer_function: function, maps scalar value to (color, opacity).
        
    Returns:
        vec4, final color and opacity (RGBA).
    """
    accumulated_color = vec3(0.0)
    accumulated_opacity = 0.0
    t_current = 0.0
    
    while t_current < t_max and accumulated_opacity < 1.0:
        # Step 3: Hardware Traversal
        # Trace ray from t_current to t_max
        hit = bvh.trace(ray_origin, ray_direction, t_current, t_max)
        
        if hit is None:
            # No region found, ray terminates
            break
            
        # Step 4: Region Intersection and Integration
        # Compute overlap interval [t_in, t_out]
        t_in = max(t_current, hit.t_hit) # hit.t_hit is the entry point into the region
        t_out = min(t_max, hit.t_exit)   # hit.t_exit is the exit point from the region
        
        # Volume integrate over [t_in, t_out]
        # Note: The actual sampling and integration logic depends on the specific
        # ABR implementation, but it uses the samples within the intersected region.
        region_color, region_opacity = volume_integrate(
            ray_origin, ray_direction, t_in, t_out, hit.region
        )
        
        # Update accumulated color and opacity
        # Standard front-to-back compositing
        weight = region_opacity * (1.0 - accumulated_opacity)
        accumulated_color += weight * region_color
        accumulated_opacity += weight
        
        # Step 5: Next Region Search
        # Start next ray from t_out + epsilon
        t_current = t_out + 1e-6
        
    return vec4(accumulated_color, accumulated_opacity)
```

*   $\epsilon$: Small bias to avoid self-intersection. Value not specified in sources [G].

**Edge Cases and Pitfalls:**
*   **BVH Rebuild Cost:** The BVH must be rebuilt when the transfer function or iso-value changes. On the Exajet dataset, a full rebuild takes ~300ms on a Titan RTX or RTX 8000 [S1].
*   **Transfer Function Changes:** Unlike methods that check region validity during traversal, this method requires a full BVH rebuild for any change in transfer function or iso-value, as regions are pruned based on precomputed opacity ranges [S1].

## Subtopics

### [RTX BVH Ray Tracing](2957-rtx-bvh-ray-tracing.md)
RTX BVH Ray Tracing is a method for volume rendering that utilizes hardware-accelerated Bounding Volume Hierarchy (BVH) traversal to iterate through data regions, performing volume integration within each region while skipping empty space. It is distinguished from sibling methods by its reliance on NVIDIA RTX hardware acceleration for both traversal and shading, enabling interactive transfer function and iso-surface editing alongside adaptive sampling. Unlike [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md) which may use software-based logic for region boundaries, or [Sparse Brick Set Rendering](9909-sparse-brick-set-rendering.md) which focuses on sparse data structures, this method explicitly leverages the RTX ray tracing cores for efficient space skipping and adaptive sample density control.

### [Adaptive Sampling with Region Delimiters](3421-adaptive-sampling-with-region-delimiters.md)
Adaptive Sampling with Region Delimiters is a sampling strategy for Adaptive Block-Refined (ABR) volume data that adapts the sampling rate to the finest cell size within each region, using sample positions as delimiters to handle boundary artifacts. Unlike Ljung [23], which defines a global set of finest level samples skipped by coarseness, this method defines independent sampling intervals for each region. It solves the problem of boundary artifacts caused by successive regions sampled at different rates, where the distance between the last sample of one region and the first of the next can be smaller or larger than either region's sampling rate.

### [Sparse Brick Set Rendering](9909-sparse-brick-set-rendering.md)
Sparse Brick Set Rendering is a method for rendering Signed Distance Fields (SDFs) using hardware-accelerated raytracing against a Bounding Volume Hierarchy (BVH) of leaf bricks, where each brick contains SDF data and is intersected via software shaders and sphere-tracing. It differs from its parent [ExaBricks Rendering with RTX BVH](2577-exabricks-rendering-with-rtx-bvh.md) by specifically utilizing SDF sphere-tracing within leaf nodes rather than general volume integration, and from [RTX BVH Ray Tracing](2957-rtx-bvh-ray-tracing.md) by relying on software intersection shaders for the SDF geometry rather than hardware-native triangle or primitive intersection.

## Operating characteristics
*   **Time Complexity:** The traversal cost is amortized over multiple samples taken within each region due to hardware acceleration [S1]. The cost of BVH traversal is low compared to software-based k-d tree traversal [S1].
*   **Memory Complexity:** Depends on the number of ABR regions. The BVH stores one primitive per region.
*   **Measured Performance:** On the Exajet dataset (656M cells, 3.1M regions, 55.8M bricks), the method achieves interactive frame rates. Specific frame rates are not provided in the sources, but the BVH rebuild time is ~300ms on a Titan RTX or RTX 8000 [S1].
*   **Strengths:** Hardware-accelerated traversal avoids non-trivial control flow in shaders [S1]. Space skipping is efficient as transparent regions are excluded from the BVH during construction [S1].
*   **Limitations:** BVH rebuild is required for transfer function or iso-value changes, which can be costly (~300ms for large datasets) [S1].
*   **When to Use:** When rendering structured AMR data with hardware-accelerated GPUs (NVIDIA RTX) and when interactive transfer function editing is required.
*   **When Not to Use:** When the transfer function changes frequently and BVH rebuild cost is prohibitive, or when hardware RTX acceleration is not available.

## Background
The method was introduced by Wald et al. in 2020 in the paper "Ray Tracing Structured AMR Data Using ExaBricks" [S1]. It was developed to address the limitations of software-based k-d tree traversal for AMR data, which required per-thread stacks and non-trivial control flow in shaders [S1]. The method leverages the new RTX hardware available on GPUs to enable hardware-accelerated traversal of regions, discarding the k-d tree produced by the region builder and storing only the final regions [S1].
