# BVH Pruning for Space Skipping
Also called: Space Skipping via BVH Pruning

## Overview
BVH Pruning for Space Skipping is a technique that accelerates volume rendering by excluding fully transparent regions from the Bounding Volume Hierarchy (BVH) during construction, thereby allowing hardware ray traversal to skip empty space and non-visible data without runtime checks [S1].

## How it works
**Inputs:**
*   A set of Adaptive Block-Refined (ABR) regions [S1].
*   Precomputed scalar ranges for each ABR [S1].
*   A transfer function mapping scalar values to opacity [S1].

**Outputs:**
*   A BVH containing only regions with non-zero maximum opacity [S1].

**Data Structures:**
*   **BVH Primitive:** Each leaf node represents an ABR [S1]. The primitive is defined by its bounding box [S1]. If the region is pruned, the bounding box is effectively empty (or the node is removed from the hierarchy) [S1].

**Steps:**
1.  **Compute Maximum Opacity:** For each ABR, retrieve its precomputed scalar range $[min\_val, max\_val]$ [S1]. Evaluate the transfer function $T(v)$ over this range to find the maximum opacity:
    $$
    \alpha_{max} = \max_{v \in [min\_val, max\_val]} T(v)
    $$
    [S1]
2.  **Prune Decision:**
    *   If $\alpha_{max} = 0$, the region is fully transparent [S1]. Discard the region from the BVH construction by returning an empty box for its primitive [S1].
    *   If $\alpha_{max} > 0$, the region may contain visible data [S1]. Return the region's standard bounding box for its primitive [S1].
3.  **BVH Construction:** Build the BVH using the resulting set of primitives (valid boxes and empty boxes) [S1].

**Pitfalls:**
*   **Transfer Function Changes:** The BVH is static with respect to the transfer function [S1]. Any change to the transfer function or iso-value requires a full BVH rebuild to ensure correct pruning [S1].
*   **No Runtime Checks:** Because inactive regions are excluded from the BVH, no validity checks are needed during traversal, but this also means the BVH does not adapt to dynamic data changes without rebuild [S1].

**Pseudocode:**
```python
def build_pruned_bvh(abr_regions, transfer_function):
    """
    Builds a BVH where fully transparent ABRs are excluded.
    
    Args:
        abr_regions: List of ABR objects, each having:
            - scalar_range: tuple (min_val, max_val)
            - bounding_box: the spatial bounds of the region
        transfer_function: A function T(v) returning opacity for scalar v.
        
    Returns:
        BVH: A Bounding Volume Hierarchy containing only non-transparent regions.
    """
    primitives = []
    
    for region in abr_regions:
        min_val, max_val = region.scalar_range
        
        # Compute maximum opacity in the scalar range
        # In practice, this might use a precomputed histogram or texture lookup [G]
        alpha_max = 0.0
        for v in range(min_val, max_val + 1):
            opacity = transfer_function(v)
            if opacity > alpha_max:
                alpha_max = opacity
        
        # Prune if fully transparent
        if alpha_max == 0:
            # Return empty box or skip adding to primitives list
            # The source specifies "returning an empty box", which effectively
            # removes it from traversal if the BVH builder handles empty bounds.
            primitives.append(EmptyBox())
        else:
            primitives.append(region.bounding_box)
            
    # Construct BVH from the filtered primitives
    # The source does not specify the exact BVH construction algorithm; standard methods (e.g., SAH) are used [G]
    return standard_bvh_build(primitives)
```

## Subtopics

### [Region Clustered BVH Volume Rendering](17973-region-clustered-bvh-volume-rendering.md)
A GPU-based Empty Space Skipping (ESS) technique that uses a Bounding Volume Hierarchy (BVH) built from clustered active regions of a volume, traced via NVIDIA OptiX, to skip empty space during direct volume rendering.

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Hardware ray traversal is cheap and amortized over multiple samples [S1]. Space skipping is achieved without runtime overhead [S1]. A full BVH rebuild on large datasets (e.g., Exajet) takes approximately 300ms on a Titan RTX or RTX 8000 GPU [S1].
*   **Strengths:** No additional structures needed for space skipping; no runtime validity checks; leverages hardware acceleration efficiently [S1].
*   **Limitations:** Requires BVH rebuild on transfer function or iso-value changes [S1].

## Background
This method is part of the ExaBricks rendering framework for Adaptive Block-Refined (ABR) data, which uses hardware-accelerated RTX BVH traversal [S1]. It was introduced to handle visibility-dependent regions more efficiently than static sparsity masks, avoiding the need for additional structures like those used by Morrical et al. [S1].
