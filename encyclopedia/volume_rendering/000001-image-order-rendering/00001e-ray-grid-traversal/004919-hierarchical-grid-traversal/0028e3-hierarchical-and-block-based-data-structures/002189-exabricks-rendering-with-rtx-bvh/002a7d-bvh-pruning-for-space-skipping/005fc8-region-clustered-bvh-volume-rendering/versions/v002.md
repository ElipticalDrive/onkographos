# Region Clustered BVH Volume Rendering
Also called: GPU BVH ESS, OptiX DVR

## Overview
Region Clustered BVH Volume Rendering is a GPU-based Empty Space Skipping (ESS) technique that accelerates direct volume rendering by constructing a Bounding Volume Hierarchy (BVH) from clustered active regions of a volume, which is then traced via NVIDIA OptiX to skip empty space [S1]. Unlike traditional GPU DVR methods that rely on octrees or rasterization-based occupancy geometry (such as Sparseleap), this method leverages BVHs to represent sparse or thin strands of data with fewer nodes, avoiding the need for rasterization when the camera moves [S1].

## How it works
The method partitions the volume into fixed-size regions, determines their activity status relative to a transfer function, clusters contiguous active regions into larger cubes using a 3D Summed Area Table, and passes the resulting bounding boxes to OptiX for ray tracing [S1].

### Inputs and Outputs
*   **Input:** A volumetric dataset divided into fixed-size regions (bricks); a transfer function (TF) defining opacity thresholds [S1].
*   **Output:** A BVH structure containing Axis-Aligned Bounding Boxes (AABBs) for clustered active regions, ready for ray tracing [S1].

### Data Structures
1.  **Region Flags Array:** A 3D array (or bit-string) where each element corresponds to a region in the volume [S1]. The value is `1` if the region is active (contains opacity > 0 according to the TF) and `0` otherwise [S1].
2.  **3D Summed Area Table (3DSAT):** A precomputed 3D array derived from the Region Flags Array [S1]. It allows $O(1)$ queries (8 lookups) to determine the number of active regions within any rectangular sub-volume [S1].
3.  **Clustered AABBs:** A list of bounding boxes representing the spatial extent of each identified cluster of active regions [S1].

### Algorithm Steps

1.  **Region Partitioning:** Divide the volume into fixed-size regions (bricks) [S1]. For each region, store the minimum and maximum voxel values [S1].
2.  **Activity Testing:** When the transfer function updates, test all regions in parallel to determine if they are active [S1]. A region is active if its min/max values indicate the presence of opacity > 0 [S1]. Store the result as a 3D bit-string `ActiveFlags` [S1].
3.  **3DSAT Construction:** Compute the 3D Summed Area Table from `ActiveFlags` [S1]. For any sub-volume defined by corners $(x_1, y_1, z_1)$ and $(x_2, y_2, z_2)$, the number of active regions $N$ is calculated using 8 lookups into the 3DSAT [S1].
4.  **Clustering:** Identify contiguous groups of active regions to form larger cube-shaped blocks (e.g., $2\times2\times2$, $3\times3\times3$, $4\times4\times4$) to reduce the total node count in the BVH [S1].
    *   Maintain a `ClusteredFlags` bit-string to track regions already assigned to a cluster [S1].
    *   Sweep through the volume in descending order of cluster size (e.g., checking for $64^3$, then $63^3$, etc.) [S1].
    *   For each candidate cluster size $S$, iterate through all possible positions [S1]. If a candidate block of size $S$ consists entirely of active regions (verified via 3DSAT) and no region in the block is marked in `ClusteredFlags`, mark the block as a cluster and update `ClusteredFlags` [S1].
5.  **AABB Generation:** Calculate the spatial bounds (AABBs) for each identified cluster [S1].
6.  **BVH Construction and Traversal:** Pass the list of AABBs to NVIDIA OptiX [S1]. OptiX constructs the BVH and initiates ray tracing for the volume rendering pipeline [S1].

### Pseudocode

```python
def build_region_clustered_bvh(volume_data, transfer_function, region_size):
    """
    Constructs a BVH for empty space skipping using region clustering.
    volume_data: 3D numpy array of voxel values
    transfer_function: callable returning opacity for a voxel value
    region_size: integer size of each brick along one axis
    """
    # 1. Determine active regions
    active_flags = compute_active_flags(volume_data, transfer_function, region_size)
    
    # 2. Build 3D Summed Area Table for O(1) region counting
    sat = build_3d_summed_area_table(active_flags)
    
    # 3. Cluster active regions
    max_cluster_dim = 64
    clustered_flags = [[[False for _ in range(volume_data.shape[2])] 
                        for _ in range(volume_data.shape[1])] 
                       for _ in range(volume_data.shape[0])]
    clusters = []
    
    # Sweep in descending order of cluster size
    for size in range(max_cluster_dim, 1, -1):
        # Iterate over all possible top-left corners for a cube of 'size'
        for x in range(volume_data.shape[0] - size + 1):
            for y in range(volume_data.shape[1] - size + 1):
                for z in range(volume_data.shape[2] - size + 1):
                    # Check if this block is fully active using 3DSAT
                    count = query_3dsat(sat, x, y, z, x + size - 1, y + size - 1, z + size - 1)
                    expected_count = size * size * size
                    
                    if count == expected_count:
                        # Check if any region in this block is already clustered
                        if not is_any_region_clustered(clustered_flags, x, y, z, size):
                            # Mark this block as a cluster
                            mark_regions_as_clustered(clustered_flags, x, y, z, size)
                            
                            # Calculate AABB for this cluster
                            aabb = compute_aabb_from_region_coords(x, y, z, size, region_size)
                            clusters.append(aabb)
                            
    # 4. Pass AABBs to OptiX for BVH construction and traversal
    # bvh = optix_build_bvh(clusters)
    return clusters

def compute_active_flags(volume, tf, region_size):
    """
    Returns a 3D boolean array where True indicates an active region.
    """
    flags = [[[False for _ in range(volume.shape[2])] 
              for _ in range(volume.shape[1])] 
             for _ in range(volume.shape[0])]
    for z in range(0, volume.shape[2], region_size):
        for y in range(0, volume.shape[1], region_size):
            for x in range(0, volume.shape[0], region_size):
                min_val = float('inf')
                max_val = float('-inf')
                for dz in range(region_size):
                    for dy in range(region_size):
                        for dx in range(region_size):
                            val = volume[x+dx, y+dy, z+dz]
                            if val < min_val: min_val = val
                            if val > max_val: max_val = val
                if tf(min_val) > 0 or tf(max_val) > 0:
                    flags[x // region_size][y // region_size][z // region_size] = True
    return flags

def build_3d_summed_area_table(flags):
    """
    Computes a 3D SAT from a 3D boolean array.
    Returns a padded 3D array for safe 1-based indexing in queries.
    """
    h, w, d = len(flags), len(flags[0]), len(flags[0][0])
    sat = [[[0] * (d + 1) for _ in range(w + 1)] for _ in range(h + 1)]
    for i in range(1, h + 1):
        for j in range(1, w + 1):
            for k in range(1, d + 1):
                sat[i][j][k] = (1 if flags[i-1][j-1][k-1] else 0) \
                             + sat[i-1][j][k] + sat[i][j-1][k] + sat[i][j][k-1] \
                             - sat[i-1][j-1][k] - sat[i-1][j][k-1] - sat[i][j-1][k-1] \
                             + sat[i-1][j-1][k-1]
    return sat

def query_3dsat(sat, x1, y1, z1, x2, y2, z2):
    """
    Returns the sum of active flags in the box defined by corners.
    Uses 8 lookups into the 3D SAT.
    """
    return (sat[x2+1][y2+1][z2+1]
            - sat[x1][y2+1][z2+1] - sat[x2+1][y1][z2+1] - sat[x2+1][y2+1][z1]
            + sat[x1][y1][z2+1] + sat[x1][y2+1][z1] + sat[x2+1][y1][z1]
            - sat[x1][y1][z1])

def is_any_region_clustered(clustered_flags, x, y, z, size):
    for i in range(x, x + size):
        for j in range(y, y + size):
            for k in range(z, z + size):
                if clustered_flags[i][j][k]:
                    return True
    return False

def mark_regions_as_clustered(clustered_flags, x, y, z, size):
    for i in range(x, x + size):
        for j in range(y, y + size):
            for k in range(z, z + size):
                clustered_flags[i][j][k] = True

def compute_aabb_from_region_coords(x, y, z, size, region_size):
    min_x, min_y, min_z = x * region_size, y * region_size, z * region_size
    max_x, max_y, max_z = (x + size) * region_size, (y + size) * region_size, (z + size) * region_size
    return ((min_x, min_y, min_z), (max_x, max_y, max_z))
```

### Parameters and Edge Cases
*   **Cluster Shapes:** The method prefers cube-shaped clusters ($2\times2\times2$, $3\times3\times3$, etc.) [S1]. Future work suggests investigating non-cubed shapes (e.g., $2\times2\times8$) [S1].
*   **Degenerate Input:** If the volume is entirely empty, the BVH will be empty, and no rays will be traced [S1]. If the volume is entirely active, the clustering may result in a single large block or a few large blocks, depending on the sweep order [S1].

## Operating characteristics
*   **Time Complexity:** The clustering step involves a sweep over the volume dimensions [S1]. For a volume of size $N$ and max cluster size $K$, the complexity is roughly $O(N \cdot K^3)$ in the worst case if not optimized, but the 3DSAT allows fast validation [S1]. The BVH build time is noted as not a hindering factor [S1].
*   **Memory Complexity:** Requires storage for the volume data, the active flags bit-string, the 3DSAT (same dimensions as active flags), and the BVH nodes [S1].
*   **Performance:** Tested on an Intel Xeon E5-1620 v2 CPU and NVIDIA RTX2080 GPU [S1]. The method shows performance benefits over non-clustered BVHs and avoids the rasterization overhead of Sparseleap [S1].
*   **Strengths:** Efficiently handles sparse data and thin strands with fewer BVH nodes than octrees; avoids rasterization overhead on camera move [S1].
*   **Limitations:** Build time on CPU; clustering heuristic is limited to fully active cubes in the basic implementation [S1].

## Background
*   **Origin:** The method was presented in the context of re-evaluating BVHs for GPU-based ESS for Direct Volume Rendering, leveraging NVIDIA OptiX and RTX RTCore hardware [S1].
*   **History:** BVHs were traditionally used on CPUs for full-resolution DVR (Knoll et al. 2011) but were not standard on GPUs due to build times and traversal logic [S1]. This method adapts them for GPU ESS using hardware-accelerated ray tracing [S1].
*   **Comparison:** It differs from Sparseleap (Hadwiger et al. 2018), which uses octrees to generate occupancy geometry that must be rasterized on camera move [S1]. It also differs from traditional GPU DVR octrees, which can become deep and expensive for sparse data [S1].
