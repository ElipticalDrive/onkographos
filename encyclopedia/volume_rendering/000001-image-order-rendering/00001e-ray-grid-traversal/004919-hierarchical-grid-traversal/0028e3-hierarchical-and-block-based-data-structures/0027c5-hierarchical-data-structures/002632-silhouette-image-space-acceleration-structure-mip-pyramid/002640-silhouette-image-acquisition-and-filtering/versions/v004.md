# Silhouette Image Acquisition and Filtering

Also called: Chroma-keyed silhouette generation, Gaussian-filtered silhouette images

## Overview
This method acquires and preprocesses silhouette images from raw camera data to create smooth, calibrated binary masks used for visual hull approximation. It solves the problem of converting raw, distorted Bayer-pattern sensor data into high-quality silhouette inputs for hierarchical acceleration structures. It is distinguished from sibling methods by its unified compute kernel approach that simultaneously handles lens distortion, demosaicing, and chroma-keying, followed by separable Gaussian filtering to control surface smoothness [S1].

## How it works
**Inputs:** Raw Bayer pattern image data from a camera; camera intrinsic parameters (for distortion correction); chroma key color range.
**Outputs:** Calibrated silhouette images (2D arrays of 0s and 1s); filtered silhouette images.

**Data Structures:**
*   **Input Texture:** 2D texture array storing raw Bayer data (8 bits per pixel).
*   **Output Texture:** 2D texture array storing silhouette values (float or integer, 0 or 1).
*   **Filter Kernel:** Separable Gaussian kernel with unit integral.

**Steps:**
1.  **Upload Data:** Upload raw Bayer pattern data to the GPU as a 2D texture array. This reduces camera bus and CPU/GPU bandwidth usage compared to higher-bit formats [S1].
2.  **Compute Kernel Launch:** Launch a single GPU compute kernel. Each thread or thread block processes a portion of the image.
3.  **Distortion Correction:** Remove radial lens distortion from the pixel coordinates. This requires inverse mapping using camera calibration parameters [S1].
4.  **Demosaicing:** Convert the Bayer pattern data to full RGB or luminance values.
5.  **Chroma Keying:** Segment foreground and background pixels.
    *   Foreground pixels are assigned a value of $0$.
    *   Background pixels are assigned a value of $1$.
    *   This creates the initial binary silhouette image $\mathcal{I}_i$ [S1].
6.  **Filtering:** Apply a separable Gaussian filter to the binary silhouette images.
    *   The filter has a unit integral.
    *   The kernel width is a parameter. Increasing the width increases blur, resulting in a smoother visual hull surface $S(\mathbf{p})$ [S1].
    *   Implementation uses a thread block per row/column strategy to fit the entire image row or column in shared memory, leveraging separability for performance [S1].

**Pseudocode:**
```python
# Pseudocode for the single compute kernel processing a pixel (x, y)
def process_pixel(x, y, bayer_data, camera_intrinsics, chroma_range):
    # 1. Get raw Bayer value
    raw_val = bayer_data[x, y]
    
    # 2. Correct radial lens distortion
    # Map pixel (x, y) to undistorted coordinates (u, v)
    u, v = correct_radial_distortion(x, y, camera_intrinsics)
    
    # 3. Demosaic
    # Interpolate RGB values from surrounding Bayer pixels at (u, v)
    r, g, b = demosaic_bayer(u, v, bayer_data)
    
    # 4. Chroma Keying
    # Check if color is within the foreground range
    if is_in_chroma_range(r, g, b, chroma_range):
        silhouette_value = 0.0  # Foreground
    else:
        silhouette_value = 1.0  # Background
        
    return silhouette_value

def apply_gaussian_filter(silhouette_image, kernel_width):
    # Create separable Gaussian kernel with unit integral
    kernel_1d = create_gaussian_1d(kernel_width)
    
    # Apply horizontal pass
    # Use thread block per row, load row into shared memory
    temp_image = apply_1d_filter_horizontal(silhouette_image, kernel_1d)
    
    # Apply vertical pass
    # Use thread block per column, load column into shared memory
    filtered_image = apply_1d_filter_vertical(temp_image, kernel_1d)
    
    return filtered_image
```

**Parameters:**
*   **Kernel Width:** Controls the amount of blur. Larger values produce smoother surfaces $S(\mathbf{p})$ [S1]. Not given in the sources.
*   **Chroma Range:** The color threshold for segmentation. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** Using 8-bit Bayer data reduces bandwidth but may limit color precision for chroma keying.
*   **Boundaries:** Shared memory usage requires careful handling of image boundaries during the separable filter passes [S1].
*   **Degenerate Input:** If the chroma key range is too narrow or wide, foreground/background segmentation may fail, leading to incorrect silhouette values [S1].

## Subtopics

### Slab Silhouette Maps with Early Depth Test
A technique that exploits slab silhouette maps and an early depth test to skip empty spaces along the direction normal to the texture slice. It is used to optimize volume rendering by avoiding computation in non-transparent regions. It is distinguished by its specific application of early depth testing in conjunction with slab-based silhouette data for empty space skipping [S2].

## Operating characteristics
*   **Time Complexity:** The compute kernel runs in $O(N)$ time for $N$ pixels, with the filtering step also being $O(N)$ due to separability.
*   **Memory Complexity:** Requires storage for the input Bayer texture array and output silhouette textures. Shared memory is used for filter rows/columns, reducing global memory bandwidth [S1].
*   **Performance:** The single compute kernel approach and shared memory usage for filtering provide high performance on GPUs [S1].
*   **Strengths:** Reduces data bandwidth; produces smooth surfaces suitable for visual hull approximation; efficient GPU implementation [S1].
*   **Limitations:** Requires camera calibration for distortion correction; chroma keying may fail under poor lighting or color variation [S1].
*   **When to use:** When real-time or high-resolution silhouette acquisition from raw camera data is needed for visual hull-based volume rendering [S1].
*   **When not to use:** When high-precision color segmentation is required beyond chroma keying capabilities, or when camera calibration is unavailable [S1].

## Background
This method is described in the context of real-time high-resolution sparse voxelization and image-based modeling. It was introduced by the authors of the source paper to efficiently generate silhouette inputs for visual hull oracle kernels [S1]. The use of chroma keying and Gaussian filtering for silhouette smoothing is a standard technique in image-based modeling to create smooth visual hull surfaces [S1]. The concept of using slab silhouette maps for empty space skipping was explored by Keleş et al. [S2].
