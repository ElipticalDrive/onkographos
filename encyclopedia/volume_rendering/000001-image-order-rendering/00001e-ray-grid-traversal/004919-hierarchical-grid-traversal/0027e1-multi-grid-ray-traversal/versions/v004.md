# Multi-Grid Ray Traversal

Also called: Grid Traversal (Multi-Grid), Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal traverses rays through multiple binary occupancy grids to generate ray intervals, sample positions, and termination planes [S1, S2, unofficial]. It solves the problem of efficiently sampling dense volumetric data by pre-computing ray-AABB intersections to determine which grids are hit, sorting these entry/exit points, and then performing voxel traversal only within the valid intervals [S1, S2, unofficial]. Unlike single-grid traversal, it handles multiple distinct spatial partitions (e.g., different resolution levels or separate scene objects) in a unified pass, merging their intersection intervals [S1, unofficial]. It differs from [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by operating on a flat list of grids with pre-computed intersections rather than recursively descending a mipmap hierarchy using lookup tables [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `rays_o`: Ray origins, shape `[n_rays, 3]` [S2, unofficial].
    *   `rays_d`: Ray directions, shape `[n_rays, 3]` [S2, unofficial].
    *   `binaries`: Binary occupancy grids, shape `[n_grids, resx, resy, resz]` [S2, unofficial]. All grids share the same resolution [S1, unofficial].
    *   `aabbs`: Axis-aligned bounding boxes for each grid, shape `[n_grids, 6]` (min/max x, y, z) [S1, S2, unofficial].
    *   `rays_mask`: Optional boolean mask, shape `[n_rays]`, to skip specific rays [S1, S2, unofficial].
    *   `near_planes`: Optional per-ray near plane distances, shape `[n_rays]` [S1, S2, unofficial].
    *   `far_planes`: Optional per-ray far plane distances, shape `[n_rays]` [S1, S2, unofficial].
    *   `t_sorted`: Optional pre-computed sorted intersection times, shape `[n_rays, n_grids * 2]` [S1, S2, unofficial].
    *   `t_indices`: Optional pre-computed sorted grid indices, shape `[n_rays, n_grids * 2]` [S1, S2, unofficial].
    *   `hits`: Optional pre-computed hit flags, shape `[n_rays, n_grids]` [S1, S2, unofficial].
    *   `step_size`: Fixed step size for marching. Default `1e-3` [S1, S2, unofficial].
    *   `cone_angle`: Cone angle for linearly-increased step size. `0.0` means constant step size. Default `0.0` [S1, S2, unofficial].
    *   `traverse_steps_limit`: Maximum number of traversal steps per ray. Default `-1` (unlimited) [S1, S2, unofficial].
    *   `over_allocate`: Whether to over-allocate memory for outputs. If `True`, `traverse_steps_limit` must be set [S2, unofficial].
    *   `compute_intervals`, `compute_samples`, `compute_terminate_planes`: Flags to enable specific outputs [S2, unofficial].

*   **Outputs:**
    *   `intervals`: Ray segment intervals (start/end t values) [S1, S2, unofficial].
    *   `samples`: Sample positions within each interval [S1, S2, unofficial].
    *   `terminated_t`: Termination planes (t values) for each ray, shape `[n_rays]` [S1, S2, unofficial].

**Data Structures:**
*   `t_sorted`: Float array of shape `[n_rays, n_grids * 2]` containing sorted intersection distances [S1, unofficial].
*   `t_indices`: Integer array of shape `[n_rays, n_grids * 2]` mapping each intersection to its grid ID (0-indexed) [S1, unofficial].
*   `hits`: Boolean array of shape `[n_rays, n_grids]` indicating whether each ray hits each grid [S1, unofficial].
*   `intervals` and `samples`: Packed structures supporting chunked memory layouts via `chunk_cnts` and `chunk_starts` [S1, unofficial].

**Steps:**
1.  **Initialization:**
    *   Initialize `rays_mask` to all-ones boolean tensor of shape `[n_rays]` if `None` [S2, unofficial].
    *   Initialize `near_planes` to zeros of shape `[n_rays]` if `None` [S1, S2, unofficial].
    *   Initialize `far_planes` to infinity of shape `[n_rays]` if `None` [S1, S2, unofficial].
    *   Set `traverse_steps_limit` to `-1` if `None` [S2, unofficial].
    *   If `t_sorted`, `t_indices`, or `hits` are `None`, compute ray-AABB intersections using `ray_aabb_intersect(rays_o, rays_d, aabbs)` to get `t_mins`, `t_maxs`, and `hits` [S2, unofficial].
    *   Concatenate `t_mins` and `t_maxs` along the last dimension and sort them to get `t_sorted` and `t_indices` [S1, S2, unofficial].

2.  **Parallel Execution Setup:**
    *   Parallelize over rays using grid/block indices: `tid = blockIdx.x * blockDim.x + threadIdx.x` [S1, unofficial].
    *   Skip rays where `rays_mask[tid]` is false [S1, unofficial].
    *   On non-first passes, skip rays where `chunk_cnts[tid] == 0` if `first_pass` is false [S1, unofficial].

3.  **Interval Processing:**
    *   For each ray, loop over intersections `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1` [S1, unofficial].
    *   Determine `is_entering = t_indices[i] < n_grids` and `level = t_indices[i] % n_grids` [S1, unofficial].
    *   Compute interval bounds:
        $$ this\_tmin = \max(t\_sorted[i], near\_planes[tid]) $$
        $$ this\_tmax = \min(t\_sorted[i + 1], far\_planes[tid]) $$
    *   Skip if `this_tmin >= this_tmax` (invalid/degenerate interval) [S1, S2, unofficial].

4.  **Step Size Adjustment (Discontinuous Traversal):**
    *   If `continuous` is false, adjust `t_last` (previous step position) to align with `this_tmin` [S1, unofficial].
    *   If `step_size <= 0.0`, set `t_last = this_tmin` [S1, unofficial].
    *   If `step_size > 0.0`, march forward using `dt = _calc_dt(t_last, cone_angle, step_size, 1e10f)` until `t_last + dt * 0.5f >= this_tmin` [S1, unofficial].

5.  **Voxel Traversal:**
    *   Setup traversal for the current AABB using `setup_traversal(ray, this_tmin, this_tmax, eps, aabb, resolution, delta, tdist, step_index, current_index, final_index)` with `eps = 1e-6f` [S1, unofficial].
    *   Perform voxel traversal within the interval, generating samples and intervals [S1, S2, unofficial].
    *   Enforce `traverse_steps_limit` to enable early termination [S1, S2, unofficial].

6.  **Output Generation:**
    *   If `compute_intervals` is true, store traversal intervals [S2, unofficial].
    *   If `compute_samples` is true, store sample positions [S2, unofficial].
    *   If `compute_terminate_planes` is true, store termination planes [S2, unofficial].

## Subtopics

### [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md)
A hybrid technique using a low-resolution grid for culling and a high-resolution grid for precise hit testing. It skips large empty regions by querying the coarser grid first, switching to high-resolution traversal only when occupied cells are detected.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of rays and the number of grids intersected. The sorting step is $O(N \log N)$ where $N$ is the number of grids per ray. Voxel traversal is proportional to the number of occupied voxels along the ray.
*   **Memory Complexity:** $O(N \cdot G)$ for storing sorted intersections, where $N$ is the number of rays and $G$ is the number of grids. Output memory depends on the number of samples, which can be large.
*   **Performance:** Efficient for scenes with multiple distinct occupancy grids (e.g., dynamic NeRFs, multi-resolution volumes). Pre-computing intersections reduces per-ray overhead.
*   **Strengths:** Handles multiple grids uniformly; supports adaptive step sizes; efficient culling of empty space via binary grids.
*   **Limitations:** Not differentiable to any inputs [S2, unofficial]. Overlapping grids require careful ordering as the first grid's occupancy status overwrites the second's [S1, unofficial]. Discontinuous traversal requires careful alignment of `t_last` to avoid misaligned samples [S1, unofficial].
*   **When to use:** When rendering scenes with multiple distinct volumetric grids or when using occupancy grids for acceleration in NeRFs.
*   **When not to use:** When differentiability is required for training [S2, unofficial]. When grids are highly overlapping and order-dependent logic is not desired [S1, unofficial].

## Background
Multi-Grid Ray Traversal is a core component of the NerfAcc library, designed to accelerate NeRF rendering by efficiently sampling occupancy grids [S1, unofficial]. It was introduced in the NerfAcc paper by Li et al. (2023) as part of a general NeRF acceleration toolbox [S1, unofficial]. The method is used in various NeRF variants, including TensoRF, K-Planes, and TiNeuVox, for dynamic and camera-optimized NeRFs [S1, unofficial]. It is implemented in CUDA for high performance on GPUs [S1, S2, unofficial].
