# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal

## Overview
Hierarchical Grid Traversal accelerates volume rendering by marching a ray through a multi-resolution grid hierarchy (mipmap) rather than a single flat grid. It starts at the root level and recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB), using lookup tables to map coarse indices to fine indices [S1, unofficial]. Unlike flat grid traversal methods that step at fixed intervals or use simple homogeneity checks, this method adapts the resolution level based on the ray's position, allowing large steps over empty or homogeneous regions while maintaining high fidelity in critical areas [S2, unofficial]. It sets itself apart from its siblings by explicitly managing the hierarchy via lookup tables or node pointers to skip empty space, rather than relying solely on continuous sampling or fixed-step iteration.

## How it works
The method traverses a hierarchical grid structure, typically organized as a mipmap where each level $l$ has a resolution scaled by $2^l$ relative to the base. The traversal can be implemented via explicit lookup tables (for sparse or tiled grids) or via a recursive node structure (for dense octrees or bricked grids).

### Inputs and Outputs
*   **Input:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, hierarchical grid data structure (mipmap levels or tree nodes), maximum traversal level $L_{max}$.
*   **Output:** A list of voxel indices or spans $(t_{entry}, t_{exit})$ at the finest level intersected by the ray.

### Data Structures

#### 1. Lookup Table Structure (Sparse/Tiled Variant)
Used in implementations like `ray_mipmap_intersect` [S1, unofficial].
*   **Table Layout:** A 2D array where each row corresponds to a coarse voxel at level $l$.
    *   Columns 0–7: Indices of the 8 child voxels at level $l+1$. Value `-1` indicates an empty child.
    *   Columns -3 to -1 (or 8–10): The 3D grid coordinates $(x, y, z)$ of the coarse voxel.
*   **Tables List:** A list of these tables, one for each level from $0$ to $L_{max}-1$.

#### 2. Tree Marcher Class Structure (Node-Based Variant)
Used in implementations like `HNanoSolver` [S2, unofficial].
*   **Class `TreeMarcher`:**
    *   `AccT& mAcc`: Reference to the acceleration structure (grid/tree).
    *   `RayT mRay`: The ray being traversed.
    *   `HDDA<RayT, Coord> mHdda`: Hierarchical Digital Differential Analyzer instance.
    *   `float mT0`: Current entry time into the current node span.
    *   `float mTmax`: Global exit time (clipped to ray far plane).

### Numbered Steps

#### Variant A: Lookup Table Iteration (Explicit Hierarchy)
This variant iterates through levels, maintaining a list of active voxel indices.

1.  **Initialization:**
    *   Set `cube_touched_idx` to `[0]` (the root voxel index) [S1, unofficial].
    *   Initialize `cube_ori_list` as empty [S1, unofficial].
    *   Define `cube_size` for level $l$ as $S_0 / 2^l$, where $S_0$ is the base grid size (e.g., 256 units) [S1, unofficial].

2.  **Level Loop:** Iterate $l$ from $0$ to $L_{max}$:
    *   Retrieve `table` from `tables_list[l]` [S1, unofficial].
    *   Initialize `new_list` as empty [S1, unofficial].
    *   For each voxel index `i` in `cube_touched_idx`:
        *   Retrieve voxel coordinates: `cube_ori = table[i, -3:] * cube_size` and `cube_end = cube_ori + cube_size` [S1, unofficial].
        *   Compute ray-AABB intersection: `tn, tf = intersect_ray_aabb(ray_origin, ray_inverse_direction, cube_ori, cube_end)` [S1, unofficial].
        *   **Intersection Check:** If `tn <= tf` (ray intersects the voxel):
            *   If $l == L_{max}$:
                *   Append `table[i, -3:]` to `cube_ori_list` [S1, unofficial].
            *   Else ($l < L_{max}$):
                *   Extract child indices: `children = table[i, 0:8]` [S1, unofficial].
                *   Filter valid children: `mask = children != -1` [S1, unofficial].
                *   Add valid child indices to `new_list` [S1, unofficial].
    *   Update `cube_touched_idx = new_list` [S1, unofficial].
    *   If `cube_touched_idx` is empty, break loop [S1, unofficial].

3.  **Return:** `cube_ori_list` containing the positions of voxels touched at the maximum level [S1, unofficial].

#### Variant B: Node-Based Recursive Traversal (Implicit Hierarchy)
This variant uses a Hierarchical DDA (HDDA) to step through nodes [S2, unofficial].

1.  **Initialization (`init`):**
    *   Set `mRay` to the input ray [S2, unofficial].
    *   Clip `mRay` to the root bounding box; if no intersection, return `false` [S2, unofficial].
    *   Set epsilon `Eps = 0.000001f` [S2, unofficial].
    *   Set `t0 = mRay.t0() + Eps`, `t1 = mRay.t1() - Eps` [S2, unofficial].
    *   If `t0 > t1`, return `false` [S2, unofficial].
    *   Compute initial voxel index: `ijk = RoundDown<Coord>(mRay(t0))` [S2, unofficial].
    *   Get node dimension: `dim = mAcc.getDim(ijk, mRay)` [S2, unofficial].
    *   Initialize HDDA: `mHdda.init(mRay, t0, t1, nanovdb::math::Max(dim, NodeT::dim()))` [S2, unofficial].
    *   Set `mT0 = (dim <= ChildT::dim()) ? mHdda.time() : -1` [S2, unofficial].
    *   Set `mTmax = t1` [S2, unofficial].
    *   Return `true` [S2, unofficial].

2.  **Traversal Step (`step`):**
    *   Set `t0 = mT0` [S2, unofficial].
    *   Get `currentNode = mAcc.template getNode<NodeT>()` [S2, unofficial].
    *   Advance HDDA: `hddaIsValid = mHdda.step()` [S2, unofficial].
    *   Compute next voxel position: `nextIjk = RoundDown<Coord>(mRay(mHdda.time() + Delta))` where `Delta = 0.01f` [S2, unofficial].
    *   Get next node dimension: `nextDim = mAcc.getDim(nextIjk, mRay)` [S2, unofficial].
    *   Update HDDA: `mHdda.update(mRay, Max(nextDim, NodeT::dim()))` [S2, unofficial].
    *   Update `mT0 = (nextDim <= ChildT::dim()) ? mHdda.time() : -1` [S2, unofficial].
    *   If `t0 >= 0`:
        *   Set `t1 = Min(mTmax, mHdda.time())` [S2, unofficial].
        *   If `t0 >= t1` or `currentNode == nullptr`, continue to next iteration [S2, unofficial].
        *   Set `*node = currentNode` [S2, unofficial].
        *   Return `true` [S2, unofficial].
    *   If loop ends, return `false` [S2, unofficial].

### Pseudocode

```python
def hierarchical_grid_traversal_lookup_table(ray_origin, ray_direction, tables_list, max_level, base_size=256):
    """
    Variant A: Explicit Lookup Table Traversal.
    """
    # Precompute inverse direction for AABB intersection
    ray_inv_dir = 1.0 / ray_direction
    ray_inv_dir = np.where(ray_direction == 0, 1e30, ray_inv_dir) # Handle zero components

    cube_touched_idx = [0] # Start with root
    cube_ori_list = []

    for level in range(max_level + 1):
        table = tables_list[level]
        new_list = []
        
        # Calculate voxel size for this level
        cube_size = base_size / (2 ** level)

        for i in cube_touched_idx:
            # Get voxel bounds
            # Columns -3 to -1 are x, y, z coordinates
            coords = table[i, -3:]
            cube_ori = coords * cube_size
            cube_end = cube_ori + cube_size

            # Ray-AABB Intersection (Slab Method)
            # t_min = max((box_min - o) / d)
            # t_max = min((box_max - o) / d)
            t_min = np.maximum((cube_ori - ray_origin) * ray_inv_dir)
            t_max = np.minimum((cube_end - ray_origin) * ray_inv_dir)
            
            tn = t_min
            tf = t_max

            # Check intersection
            if tn <= tf:
                if level == max_level:
                    # Leaf level: record voxel
                    cube_ori_list.append(coords)
                else:
                    # Internal level: find children
                    # Columns 0-7 are child indices
                    children = table[i, :8]
                    mask = children != -1
                    valid_children = children[mask]
                    new_list.extend(valid_children)

        cube_touched_idx = new_list
        if not cube_touched_idx:
            break

    return cube_ori_list

def hierarchical_grid_traversal_node_based(ray_origin, ray_direction, acc_structure, epsilon=1e-6, delta=0.01):
    """
    Variant B: Node-Based Traversal (Pseudocode representation of HNanoSolver logic).
    """
    # 1. Initialization
    ray = Ray(ray_origin, ray_direction)
    
    # Clip to root bbox
    if not ray.clip_to_bbox(acc_structure.root_bbox):
        return []

    t0 = ray.t0 + epsilon
    t1 = ray.t1 - epsilon
    
    if t0 > t1:
        return []

    # Initial voxel
    ijk = floor(ray(t0) / voxel_size)
    dim = acc_structure.get_dim(ijk, ray)
    
    # Init HDDA
    hdda = HDDA(ray, t0, t1, max(dim, NODE_DIM))
    
    # Determine if we are at leaf level immediately
    if dim <= CHILD_DIM:
        mT0 = hdda.time()
    else:
        mT0 = -1
        
    t_max_global = t1
    
    visited_nodes = []
    
    # 2. Step Loop
    while True:
        t_entry = mT0
        current_node = acc_structure.get_node(ijk) # Simplified node access
        
        # Advance HDDA
        hdda.step()
        
        # Predict next voxel for dimension check
        next_time = hdda.time() + delta
        next_ijk = floor(ray(next_time) / voxel_size)
        next_dim = acc_structure.get_dim(next_ijk, ray)
        
        # Update HDDA with new dimension info
        hdda.update(ray, max(next_dim, NODE_DIM))
        
        # Update mT0 for next iteration
        if next_dim <= CHILD_DIM:
            mT0 = hdda.time()
        else:
            mT0 = -1
            
        if t_entry >= 0:
            t_exit = min(t_max_global, hdda.time())
            
            if t_entry >= t_exit or current_node is None:
                continue
                
            visited_nodes.append(current_node)
            
            # Check if we should continue or if ray is done
            if hdda.time() >= t1:
                break
                
    return visited_nodes
```

### Parameters
*   **max_level:** The maximum depth of the mipmap hierarchy. The loop runs from $0$ to `max_level` inclusive [S1, unofficial].
*   **cube_size:** The physical size of a voxel at level $l$, calculated as $S_0 / 2^l$, where $S_0$ is the base grid resolution (e.g., 256 units) [S1, unofficial].
*   **Epsilon:** Small offset to avoid precision errors at boundaries. Typical value: $0.000001f$ [S2, unofficial].
*   **Delta:** Small offset for predicting next voxel dimension. Typical value: $0.01f$ [S2, unofficial].

### Edge Cases and Pitfalls
*   **Precision Clipping:** If `Delta` is too large, it may clip corners of nodes visibly. If too small, it may fail due to floating-point rounding errors when the ray is far from the grid origin [S2, unofficial].
*   **Tiny Intersections:** Tweaking the intersection span with `Eps` may clip tiny corner intersections [S2, unofficial].
*   **Empty Regions:** The vectorized version must mask out non-intersecting rays (`tn <= tf`) to avoid processing invalid children [S1, unofficial].
*   **Zero Direction:** Ray direction components equal to zero must be handled in inverse direction calculations to avoid division by zero (treated as infinity) [S5, unofficial].

## Subtopics

### [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md)
Accelerates volume rendering by traversing a multi-dimensional hierarchy (mdh) to adaptively select the resolution level for evaluating volume data, based on a user-defined error tolerance and data importance weighting. Unlike standard ray-grid traversal methods that step at fixed intervals or use simple homogeneity checks, this method approximates data regions using least-squares trilinear coefficients to decide whether to refine the ray traversal or evaluate the data directly. It generalizes the concept of homogeneity from nearly constant values to least-squares fits with a set of basis functions, specifically trilinear functions, allowing for large steps over homogeneous regions while maintaining high fidelity in critical areas.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
A recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### [VolumeHDDA](2353-volumehdda.md)
A specialized Hierarchical Digital Differential Analyzer for traversing volume trees, templated on the tree type, ray type, and the starting node level for traversal. It builds on [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by implementing a recursive ray-marching approach that enters child nodes when present and processes active or inactive tiles at leaf levels. It sets itself apart from siblings like [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on discrete tile/voxel intersection detection and time-span management rather than continuous sampling, and from [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) by explicitly handling the hierarchical node structure via template recursion.

### [XBrickMap](3116-xbrickmap.md)
A space-partitioning ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to skip empty regions via bitwise tests. It improves upon simpler skipping methods by using tiled bitmasks to perform hierarchical skips of $4^3$, $2^3$, and $1^3$ cuboids, while left-packing empty bricks within sectors to save memory. It is distinguished from its sibling [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by its specific use of compacted bitmasks for random access and its support for arbitrary in-place edits within bricks.

### [Spherical Volume Voxel Traversal](3877-spherical-volume-voxel-traversal.md)
A ray-marching algorithm that traverses a ray through a voxel grid structured in spherical coordinates (radial, polar, azimuthal), returning the sequence of voxels intersected by the ray. It solves the problem of efficiently sampling volumetric data defined on a spherical domain, such as planetary atmospheres or star models, where Cartesian grids introduce significant distortion or wasted space near the center. Unlike Cartesian hierarchical traversal which relies on axis-aligned bounding boxes, this method computes intersections with spherical shells, polar cones, and azimuthal wedges directly, handling the singularity at the origin by starting traversal at the first non-zero radial shell. It builds on [Hierarchical Grid Traversal](8384-hierarchical-grid-traversal.md) by specializing the traversal logic for spherical topology rather than octree or uniform grid structures.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
Determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
This family of methods accelerates volume rendering by organizing voxel data into a spatial subdivision hierarchy (e.g., octrees, bricked grids, BVHs) where internal nodes store aggregate information derived from their children or leaf voxels [4133-hierarchical-data-structures]. This structure enables the renderer to prune empty or inactive regions during ray traversal, significantly reducing the number of samples required to generate an image [4133-hierarchical-data-structures]. Unlike flat grid traversal methods, hierarchical approaches adaptively skip large volumes of empty space, making them particularly effective for sparse or multi-resolution datasets [4133-hierarchical-data-structures].

### [Hierarchical DDA with Super-brick Skipping](5197-hierarchical-dda-with-super-brick-skipping.md)
This method accelerates ray tracing through sparse volumetric data by introducing a two-level occupancy hierarchy (super-bricks and bricks) to skip large empty regions, while maintaining pixel-identical output to the fine per-voxel DDA. It solves the performance bottleneck of traversing empty space by verifying emptiness at a coarser granularity and using an axis-aligned bounding box (AABB) for early termination, ensuring exactness by only skipping verified empty blocks and terminating only when the ray definitively passes the occupied volume.

### [Octree-based traversal](5348-octree-based-traversal.md)
Accelerates volume rendering and implicit surface rendering by recursively navigating a hierarchical spatial subdivision (typically an octree) to skip empty space or cull nodes that do not intersect the ray. It differs from flat grid traversal by using a tree structure to bypass large volumes of empty space, and from Empty-Space Skipping which uses primitive hulls, by employing hierarchical spatial subdivision to locate non-empty space faster. It sets itself apart from its siblings, such as [Octree Partitioning for Sphere Tracing](1541-octree-partitioning-for-sphere-tracing.md), by using explicit bounds tracking and entry/exit side tracking with a callback for leaf processing rather than fixed-step iteration.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty Space Skipping via Data Structures is a family of volume rendering optimization techniques that reduce computational cost by identifying and bypassing inactive (transparent or irrelevant) regions of a volume before or during ray sampling. It solves the problem of wasted samples in large, sparse, or complex volumes where significant portions of the ray path contribute nothing to the final image. What sets this family apart from sibling methods like [Space Leaping](5863-space-leaping.md) (which relies on ray coherence and image-plane buffers) or [Early Shader Termination](969-early-shader-termination.md) (which stops rays dynamically during compositing) is the use of explicit, precomputed or dynamically maintained data structures (e.g., min-max blocks, occupancy grids, BVHs, or hash maps) to define spatial bounds of active data. Unlike [Rasterizing Bounding Geometry for Empty Space Skipping](5141-rasterizing-bounding-geometry-for-empty-space-skipping.md), which uses polygonal approximations, these methods typically rely on scalar block statistics or hierarchical tree structures.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
Multi-level Grid Structures are a family of hierarchical acceleration algorithms that recursively subdivide a spatial domain into nested grids of varying resolution to optimize ray traversal. They solve the problem of inefficient traversal in non-uniform scenes by replacing pointer-chasing tree structures with contiguous array-based grids, thereby improving memory locality and reducing ray-primitive intersection counts. Unlike flat grids, they adapt resolution based on object density, and unlike tree structures, they use fixed-size grid arrays at each level, allowing for faster traversal via integer arithmetic.

### [Grid Sphere Traversal](9649-grid-sphere-traversal.md)
Grid Sphere Traversal (GST) is a ray-grid traversal method that performs sphere tracing through a dense grid of Signed Distance Function (SDF) values. It solves the problem of efficiently traversing empty regions in SDF-based rendering by using a hierarchy of SDF grids where lower-resolution levels encode larger SDF values to accelerate step sizes. It is distinguished from its siblings by performing the entire traversal in shader code using dense grids, whereas alternatives like [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) or [XBrickMap](3116-xbrickmap.md) often rely on sparse structures or hardware-accelerated BVH traversal.

### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. It groups scalar values within a certain range together based on the transfer function to define sub-volume properties, uses a kd-tree to render the partitioned volume with correct visibility order (where each node is associated with a sub-volume), and culls/clips each sub-volume against an opacity map [S3, unofficial]. Reported performance: 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].(Note: No dedicated article exists, linked to sibling for context)

### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial]. Steps: 1. Identify occupied voxels in the fine grid and assign unique indices. 2. Extract the 8 sub-grid regions corresponding to the 8 children of a coarse voxel by striding the fine grid indices. 3. Flatten these sub-grids and filter them using the coarse grid mask to select only children belonging to occupied coarse voxels. 4. Initialize the table with shape `[num_coarse_voxels, 11]` (8 child indices + 3 coordinates), filled with -1. 5. Populate columns 0-7 with the filtered child indices. 6. Populate columns 8-10 with the coarse voxel coordinates [S1, unofficial].(Note: No dedicated article exists, linked to sibling for context)

### Hierarchical Data Structure Traversal
Each processor performs the cell connectivity pre-step. Cells that are outside the camera view are excluded. Each processor applies the ray-casting algorithm to its data. Each ray enters the volume from an exterior face and uses the connectivity information to determine the next cell. When a ray intersects a second exterior face, it exits the volume. Image pixels are assigned to different processors and HDS is used to exchange rays. Rays are composited to produce the final image [S4].(Note: No dedicated article exists, linked to sibling for context)

## Operating characteristics
*   **Time Complexity:** $O(N)$ in the number of voxels visited, but significantly reduced compared to flat traversal due to skipping empty regions. The cost is dominated by the hierarchy traversal overhead and AABB intersection tests.
*   **Memory Complexity:** $O(V)$ where $V$ is the total number of voxels in the hierarchy. Lookup table variants require additional memory for the tables themselves.
*   **Measured Performance:** Specific benchmarks for the lookup table variant are not provided in the sources. However, related hierarchical methods (KD-Tree partitioned) reported 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].
*   **Scaling:** Scales well with sparse data. Performance degrades if the volume is dense and fully occupied, as the overhead of hierarchy traversal may exceed flat DDA.
*   **Strengths:** Efficiently skips large empty regions; adapts resolution to data importance; suitable for sparse and multi-resolution data.
*   **Limitations:** Requires pre-computation of hierarchy (mipmap or tree); lookup table construction can be memory-intensive for very large grids; precision issues with epsilon/delta parameters [S2, unofficial].
*   **When to Use:** Sparse volumes, multi-resolution data, scenes with large empty spaces.
*   **When Not to Use:** Dense, fully occupied volumes where flat DDA might be faster due to lower overhead; hardware with limited memory for large lookup tables.

## Background
Hierarchical Grid Traversal is a method for accelerating volume rendering by utilizing multi-resolution data structures. It builds on the principles of ray-grid traversal [17-ray-grid-traversal.md] and hierarchical data structures [4392-hierarchical-and-block-based-data-structures.md]. The specific lookup table implementation is documented in unofficial sources [S1, unofficial], while the node-based HDDA approach is found in [S2, unofficial]. The concept of partitioning volumes for visibility-based rendering using hierarchical structures like kd-trees was explored by Li et al. [S3, unofficial].
