# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal

## Overview
Hierarchical Grid Traversal is a ray-grid traversal algorithm that iterates through levels of a grid mipmap (hierarchical grid tree) to accelerate volume rendering [S1, S2, unofficial]. It starts at the root (level 0) and recursively visits child voxels only if the ray intersects the parent voxel's axis-aligned bounding box (AABB), using lookup tables to map parent indices to child indices [S1, S2, unofficial]. Unlike flat traversal methods, it skips empty space by leveraging the hierarchy, and unlike pure tree structures, it maintains a grid-based indexing scheme at each level to simplify traversal logic on GPUs [S1, unofficial][S2, unofficial]. It sets itself apart from siblings like [Multi-level Grid Structures](6354-multi-level-grid-structures.md) by providing specific implementations for constructing and traversing these hierarchical grids using mipmap tables [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$, a hierarchical grid structure (mipmap) with $L$ levels, and a lookup table `tables_list` where `tables_list[level]` maps coarse voxels to their fine children.
*   **Output:** A list of voxel positions (or indices) at the maximum level (`max_level`) that are intersected by the ray [S1, unofficial].

**Data Structures:**
*   **Mipmap Table (`tables_list`):** A list of arrays, one per level. Each row corresponds to a coarse voxel at that level.
    *   Columns 0-7: Indices of the 8 child voxels in the next finer level. If a child is empty or invalid, the value is $-1$ [S1, unofficial].
    *   Columns 8-10 (or -3 to -1): The 3D grid coordinates $(x, y, z)$ of the coarse voxel [S1, unofficial].
    *   Layout: Shape `[num_coarse_voxels, 11]` [S1, unofficial].
*   **Ray Structure:** Defined by origin $\mathbf{o}$, direction $\mathbf{d}$, and near/far clip distances $t_{min}, t_{max}$ [S2, unofficial].
*   **HDDA State:** An internal Hierarchical Digital Differential Analyzer (HDDA) instance tracks the ray's position and time within the current node [S2, unofficial].

**Parameters:**
*   `max_level`: The maximum depth of the mipmap hierarchy. The loop runs from level 0 to `max_level` inclusive [S1, unofficial].
*   `cube_size`: The physical size of a voxel at the current level. For a base grid resolution of 256 units, `cube_size = 256 / (2 ** level)` [S1, unofficial].
*   `Eps`: A small epsilon for clipping, typically $10^{-6}$ [S2, unofficial].
*   `Delta`: A small offset for advancing the ray to the next node, typically $0.01$ [S2, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    *   Set `cube_touched_idx` to `[0]` (the root voxel index) [S1, unofficial].
    *   Initialize `new_list` as an empty list [S1, unofficial].
    *   Clip the ray to the root bounding box. If the ray does not intersect, return empty [S2, unofficial].
    *   Set $t_0 = \mathbf{r}.t_{min} + \text{Eps}$ and $t_1 = \mathbf{r}.t_{max} - \text{Eps}$ [S2, unofficial].
    *   If $t_0 > t_1$, return empty [S2, unofficial].
    *   Initialize the HDDA state with the ray, $t_0$, $t_1$, and the root node's dimension [S2, unofficial].

2.  **Hierarchical Iteration:**
    Iterate through each level $l$ from 0 to `max_level`:
    *   Retrieve the table for the current level: `table = tables_list[l]` [S1, unofficial].
    *   For each voxel index $i$ in `cube_touched_idx`:
        *   Retrieve the voxel's 3D coordinates $(x, y, z)$ from the table [S1, unofficial].
        *   Compute the voxel's physical origin $\mathbf{p}_{ori}$ and end $\mathbf{p}_{end}$ using `cube_size` [S1, unofficial].
        *   Perform a ray-AABB intersection test between the ray and the voxel's bounding box $[\mathbf{p}_{ori}, \mathbf{p}_{end}]$ [S1, unofficial].
        *   Let $t_n$ be the near intersection time and $t_f$ be the far intersection time [S1, unofficial].
        *   If $t_n \le t_f$ (intersection exists):
            *   If $l == \text{max\_level}$:
                *   Append the voxel's grid coordinates $(x, y, z)$ to `cube_ori_list` (the final hit list) [S1, unofficial].
            *   Else:
                *   Extract the 8 child indices from columns 0-7 of the table row $i$ [S1, unofficial].
                *   Filter out invalid children (where index $== -1$) using a mask [S1, unofficial].
                *   Convert valid indices to integers and add them to `new_list` [S1, unofficial].
    *   Update `cube_touched_idx` to `new_list` and reset `new_list` to empty for the next level [S1, unofficial].

3.  **Return:**
    *   Return `cube_ori_list` containing the positions of voxels touched at the maximum level [S1, unofficial].

**Pseudocode:**

```python
def hierarchical_grid_traversal(ray, tables_list, max_level, cube_size_func):
    """
    ray: object with .origin, .direction, .t_min, .t_max
    tables_list: list of numpy arrays, shape [N_l, 11]
    max_level: int
    cube_size_func: function(level) -> float
    """
    # 1. Initialization
    cube_touched_idx = [0]  # Start with root
    cube_ori_list = []
    
    # Clip ray to root bbox (simplified check)
    # In practice, use a robust AABB intersection test for the root
    if not ray_intersects_bbox(ray, [0,0,0], cube_size_func(0)):
        return []

    t0 = ray.t_min + 1e-6
    t1 = ray.t_max - 1e-6
    if t0 > t1:
        return []

    # 2. Iterate through levels
    for level in range(max_level + 1):
        table = tables_list[level]
        current_cube_size = cube_size_func(level)
        new_list = []
        
        # Process all currently touched voxels
        for i in cube_touched_idx:
            row = table[i]
            # Columns -3 to -1 are coordinates (x, y, z)
            coords = row[-3:]
            
            # Compute physical bounds
            # Assuming voxel size is uniform per level and origin is coords * size
            p_ori = coords * current_cube_size
            p_end = p_ori + current_cube_size
            
            # Ray-AABB Intersection
            tn, tf = intersect_ray_aabb(ray.origin, ray.direction, p_ori, p_end)
            
            if tn <= tf:
                if level == max_level:
                    # Reached leaf level, record hit
                    cube_ori_list.append(coords)
                else:
                    # Extract child indices (columns 0-7)
                    child_indices = row[:8]
                    # Filter out invalid children (-1)
                    valid_mask = child_indices != -1
                    valid_children = child_indices[valid_mask]
                    
                    # Add valid children to the next level's list
                    new_list.extend(valid_children)
        
        cube_touched_idx = new_list
        if not cube_touched_idx:
            break
            
    return cube_ori_list

def intersect_ray_aabb(ray_o, ray_d, box_min, box_max):
    """
    Standard ray-AABB intersection.
    Returns (tn, tf) or (None, None) if no intersection.
    """
    tn = -float('inf')
    tf = float('inf')
    
    for i in range(3):
        if ray_d[i] == 0:
            if ray_o[i] < box_min[i] or ray_o[i] > box_max[i]:
                return None, None
        else:
            t1 = (box_min[i] - ray_o[i]) / ray_d[i]
            t2 = (box_max[i] - ray_o[i]) / ray_d[i]
            if t1 > t2:
                t1, t2 = t2, t1
            tn = max(tn, t1)
            tf = min(tf, t2)
            
    if tn > tf:
        return None, None
    return tn, tf
```

**Edge Cases and Pitfalls:**
*   **Floating Point Precision:** If the `Delta` offset used in internal HDDA steps is too large, it may clip corners of nodes visibly. If too small, it may fail due to FP32 rounding errors when far from the grid. A value of $0.01$ is recommended [S2, unofficial].
*   **Tiny Intersections:** Tweaking the intersection span with `Eps` ($10^{-6}$) may clip tiny corner intersections [S2, unofficial].
*   **Empty Voxels:** Child indices marked as $-1$ must be filtered out to prevent traversal into non-existent nodes [S1, unofficial].
*   **Vectorization:** In vectorized implementations (e.g., `ray_mipmap_intersect_vectorized`), rays are processed simultaneously. Non-intersecting rays are masked out using `tn <= tf` [S1, unofficial].

## Subtopics

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
The Hierarchical Digital Differential Analyzer (HDDA) is a ray traversal algorithm that performs multi-resolution leapfrogging through sparse volume data structures, specifically OpenVDB and NanoVDB grids. It adapts the Digital Differential Analyzer (DDA) to step through nodes or voxels of varying power-of-two dimensions, skipping empty space by jumping between grid nodes of different resolutions. Unlike standard voxel DDA which checks every voxel, HDDA leverages the hierarchical tree structure (B+tree) to traverse coarse tiles first and only descend into occupied children, significantly accelerating ray-marching for sparse volumes. It is distinct from [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) in its specific implementation for VDB structures using compile-time template meta-programming to inline the hierarchy, and from [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on traversal efficiency rather than shading interpolation.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
Hierarchical Voxel Traversal is a recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### [XBrickMap](3116-xbrickmap.md)
XBrickMap is a space-skipping ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to perform hierarchical skips ($4^3, 2^3, 1^3$ cuboids) via bitwise tests. It improves upon standard skipping by using tiled bitmasks to identify empty voxel sections and left-packs these bitmasks to omit empty bricks within sectors, saving memory. It is distinguished from siblings like [MultiDDA](2204-hierarchical-voxel-traversal.md) by its specific 3-level sector/brick/voxel hierarchy and bitmask-based compression, and from [Tree64](6354-multi-level-grid-structures.md) by its fixed grid topology and lack of dynamic tree rebalancing.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
First Active Voxel Detection determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
Hierarchical and Block-Based Data Structures provide a spatial subdivision framework for volume rendering, enabling efficient traversal and culling of empty or inactive regions during ray marching. Unlike flat voxel grids, these structures organize data into a tree where internal nodes store aggregate properties (e.g., occupancy, scalar ranges) derived from their children, allowing rays to skip large inactive subtrees [4133-hierarchical-data-structures]. This family encompasses methods that vary in their spatial representation (octrees, pyramids, image-space mipmaps) and traversal order (image-order, object-order, or hybrid). It sets itself apart from sibling methods by focusing on the *data organization* strategy (hierarchical blocks/trees) rather than the specific traversal algorithm (e.g., HDDA) or hardware acceleration mechanism (e.g., RTX BVH) used to navigate it.

### [Octree-based traversal](5348-octree-based-traversal.md)
Octree-based traversal accelerates volume rendering and ray tracing by navigating a hierarchical spatial decomposition (typically an octree) to skip empty space and reduce the number of ray-casting or distance-evaluation steps. It solves the performance bottleneck of non-hierarchical traversal, where every voxel along a ray must be visited, by allowing the ray to leap over large empty regions. Unlike sibling methods that may use fixed-resolution grids or brick maps, this family operates on a recursive tree structure where each parent node divides into eight equal sub-blocks ($2 \times 2 \times 2$ subdivision), enabling larger steps through empty space.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty Space Skipping via Data Structures accelerates volume rendering by using secondary data structures to identify inactive regions, allowing rays to skip sampling points in empty space. It differs from [Space Leaping](5863-space-leaping.md) by relying on explicit spatial metadata rather than image-plane coherence, and from [Distance Map Acceleration](972-distance-map-acceleration.md) by using binary or bounded occupancy flags rather than distance-to-nearest-occupied-voxel metrics. It sets itself apart from sibling methods like [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) by focusing specifically on the *culling* of inactive regions via metadata queries, whereas hierarchical traversal focuses on the *navigation* of the grid hierarchy itself.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
Multi-level Grid Structures are a family of hierarchical acceleration techniques for ray-grid traversal that organize scene data into a hierarchy of grid levels (mipmaps) to skip empty space and reduce intersection tests. They differ from uniform grids by adapting resolution to local density and from pure tree structures (like Octrees) by maintaining a grid-based indexing scheme at each level, which simplifies traversal logic on GPUs. This family builds on [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by providing specific implementations for constructing and traversing these hierarchical grids.

#### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. Scalar values within a certain range are grouped together to define sub-volume properties. A kd-tree is used to render the partitioned volume with correct visibility order, where each node is associated with a sub-volume. Each sub-volume is culled and clipped against an opacity map [S3, unofficial]. Reported performance: 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].

#### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial].
1.  Identify occupied voxels in the fine grid: $x, y, z = \text{np.where}(\text{grid\_fine})$. Assign a unique index to each occupied voxel: $\text{tmp}[\text{grid}] = \text{idx}$ where $\text{idx} = \text{jnp.arange}(0, \text{grid.sum}())$ [S1, unofficial].
2.  Extract the 8 sub-grid regions corresponding to the 8 children of a coarse voxel. These are obtained by striding the fine grid indices: $\text{grid}_{000} = \text{grid}[0::2, 0::2, 0::2]$, etc. [S1, unofficial].
3.  Flatten these sub-grids and filter them using the coarse grid mask: $f_{000} = f_{000}[\text{mask\_coarse}]$. This selects only the children that belong to occupied coarse voxels [S1, unofficial].
4.  Initialize the table with shape `[num_coarse_voxels, 11]` (8 child indices + 3 coordinates), filled with $-1$ [S1, unofficial].
5.  Populate columns 0-7 with the filtered child indices ($f_{000}$ to $f_{111}$) [S1, unofficial].
6.  Populate columns 8-10 with the coarse voxel coordinates $(x, y, z)$ [S1, unofficial].
Table layout: Rows correspond to coarse voxels. Columns 0-7 are child voxel indices (or -1). Columns 8-10 are coarse voxel coordinates (x, y, z) [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume and the depth of the hierarchy. In the worst case (fully dense), it is proportional to the number of voxels at the leaf level. In sparse cases, it skips empty regions, reducing the number of intersection tests significantly compared to flat DDA [S1, S2, unofficial].
*   **Memory Complexity:** Requires storage for the mipmap tables. The table size is proportional to the number of voxels at each level. For a base resolution $N$, the total table size is roughly $\sum_{l=0}^{L} N_l$, where $N_l$ is the number of voxels at level $l$ [S1, unofficial].
*   **Measured Performance:** Specific performance metrics for the general Hierarchical Grid Traversal method are not given in the sources. However, related methods like KD-Tree Partitioned Volume Rendering reported 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].
*   **Strengths:** Efficiently skips empty space in sparse volumes; leverages grid-based indexing for GPU friendliness; reduces intersection tests compared to flat traversal [S1, S2, unofficial].
*   **Limitations:** Requires pre-computation of mipmap tables; performance degrades if the volume is dense; precision issues with small `Delta` or `Eps` values [S1, S2, unofficial].
*   **When to Use:** Sparse volume data with significant empty space; when GPU acceleration is desired and grid-based indexing is preferred over tree structures [S1, S2, unofficial].
*   **When Not to Use:** Dense volumes where the overhead of hierarchy traversal outweighs the benefits; when dynamic updates to the volume structure are frequent and table reconstruction is costly [S1, S2, unofficial].

## Background
Hierarchical Grid Traversal is a method for accelerating volume rendering by using hierarchical data structures to skip empty space. It builds on the principles of ray-grid traversal [17-ray-grid-traversal.md] and multi-level grid structures [6354-multi-level-grid-structures.md]. The specific implementation using mipmap tables and lookup tables is described in unofficial sources [S1, S2, unofficial]. The concept of partitioning volumes and using hierarchical structures for visibility culling has been explored in interactive volume ray tracing [S3, unofficial].
