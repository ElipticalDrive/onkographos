# LightGaussian Pruning Scoring

Also called: Projection-based primitive scoring

## Overview
LightGaussian Pruning Scoring is a 2D projection-based method for ranking 3D Gaussian primitives to determine which ones to prune, based on accumulated ray contributions across multiple synthesized views [S1, unofficial]. It differs from volume-based scoring methods by operating in image space rather than volumetric space, making it less accurate for volumetric data where intensity integration and anisotropy weighting are critical [S1, unofficial].

## How it works
**Inputs:** A trained 3D Gaussian Splatting model (or similar primitive-based representation) and a set of uniformly sampled camera views [G].
**Outputs:** A scalar importance score for each primitive and a binary mask indicating which primitives to retain or prune [G].

**Data Structures:**
*   `Primitive`: Contains position, covariance, opacity, and color attributes [G].
*   `View`: Defined by camera pose (extrinsics) and intrinsics [G].
*   `Score`: A float value associated with each primitive [G].

**Steps:**
1.  **View Generation:** Generate $N$ uniformly sampled views on a sphere surrounding the scene [S1, unofficial]. The source specifies $N=360$ for experimental settings [S1, unofficial].
2.  **Rendering:** Render the scene from each generated view using the current primitive parameters [S1, unofficial].
3.  **Feature Extraction:** For each primitive, extract view-dependent features from the rendered views [S1, unofficial]. Key features include ray hits (whether the primitive contributes to the pixel color along the ray) and transmittance (the accumulated transmittance along the ray up to the primitive) [S1, unofficial].
4.  **Accumulation:** Accumulate the ray contributions (e.g., color difference, opacity contribution) for each primitive across all $N$ views [S1, unofficial].
5.  **Scoring:** Compute a final importance score for each primitive based on the accumulated contributions [S1, unofficial]. Primitives with lower scores are considered less important [G].
6.  **Pruning:** Remove primitives below a certain score threshold or keep the top $K$ primitives [G].

**Pseudocode:**
```python
import math

def lightgaussian_pruning_scoring(primitives, num_views=360):
    # Step 1: Generate uniformly sampled views on a sphere
    views = []
    golden_angle = math.pi * (3.0 - math.sqrt(5.0))
    for i in range(num_views):
        y = 1.0 - (i / (num_views - 1)) * 2.0
        radius = math.sqrt(max(0.0, 1.0 - y * y))
        theta = golden_angle * i
        cam_pos = (math.cos(theta) * radius, y, math.sin(theta) * radius)
        views.append(cam_pos)

    scores = {p.id: 0.0 for p in primitives}

    # Step 2 & 3: Render views and extract view-dependent features
    for cam_pos in views:
        for p in primitives:
            # [G] The exact contribution computation (ray hits, transmittance, opacity)
            # is implementation-dependent and not specified in the sources.
            # It typically involves projecting the primitive onto the image plane,
            # computing coverage, and accumulating its weight along the ray.
            contrib = 1.0  # Placeholder for actual rasterization output
            scores[p.id] += contrib

    return scores
```

**Parameters:**
*   `num_views`: Typically 360 [S1, unofficial].
*   `threshold`: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Volumetric Accuracy:** Projection-based scoring yields lower accuracy in volumetric settings compared to volume-based scoring [S1, unofficial]. It fails to account for voxel intensities and fractional anisotropy, leading to unreliable ranking for complex volumetric data [S1, unofficial].
*   **View Sampling:** Uniform sampling on a sphere may not capture all relevant viewing angles if the scene has strong directional dependencies, though 360 views is a standard baseline [S1, unofficial].

## Subtopics

### FA-based Pruning
Uses Fisher Information to estimate parameter sensitivity [G]. More computationally expensive but provides a first-order approximation of importance [G]. [Link](3236-fa-based-pruning.md)

### Importance-Driven Volume Rendering
Integrates voxel intensities and anisotropy for scoring [S1, unofficial]. More accurate for volumetric data than projection-based methods [S1, unofficial]. [Link](7632-importance-driven-volume-rendering.md)

### Death Criterion
Primitives are removed if: (i) opacity $o < \tau_o$, (ii) maximum blending weight $\max_j (\alpha_{i,j} T_{i,j})$ over all pixels $j$ across recent views falls below $\tau_I$, or (iii) primitive is observed in fewer than $V_{\min}$ frames [S3]. Newly created primitives are protected by a one-epoch grace period [S3].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of views and $P$ is the number of primitives [G]. Rendering $N$ views is the dominant cost [G].
*   **Memory Complexity:** $O(P)$ to store scores [G]. Rendering requires temporary memory for intermediate buffers [G].
*   **Performance:** The source notes that LightGaussian achieves comparable or smaller number of primitives with higher PSNR/SSIM in general 3D-GS settings, but lower accuracy in volumetric settings [S1, unofficial].
*   **Strengths:** Simple to implement; leverages existing rendering pipelines; view-dependent features capture occlusion and visibility well [G].
*   **Limitations:** Lower accuracy for volumetric data; does not account for volumetric properties like anisotropy; requires multiple renders [S1, unofficial].

## Background
LightGaussian was introduced as a pruning baseline for 3D Gaussian Splatting [S1, unofficial]. It was compared against other pruning methods like RAP and PUP 3D-GS [S2, unofficial]. The method was found to be less effective for volumetric data compared to volume-based scoring methods that integrate voxel intensities [S1, unofficial].
