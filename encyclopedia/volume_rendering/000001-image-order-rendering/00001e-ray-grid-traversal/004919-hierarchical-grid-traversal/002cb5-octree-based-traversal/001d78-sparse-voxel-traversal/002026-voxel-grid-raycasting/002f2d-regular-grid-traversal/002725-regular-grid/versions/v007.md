# Regular Grid

Also called: Grid Data Structure, Grilles régulières, Regular Grid Spatial Subdivision, Uniform Grids, Uniform Spatial Subdivision

## Overview
A Regular Grid is a spatial acceleration structure that partitions the scene's Axis-Aligned Bounding Box (AABB) into a fixed-size 3D grid of uniform cells (voxels) [S1, unofficial][S2][S4, unofficial]. It solves the problem of testing every object for every ray by storing primitives in the cells they overlap, allowing rays to skip empty cells and only test primitives within intersected cells [S3, S4, unofficial]. Unlike hierarchical structures like BVH or Octrees, it uses a uniform spatial subdivision where primitives can belong to multiple disjoint sub-blocks, offering constant-time access and high data locality [S2][S4, S6, unofficial].

## How it works
**Inputs:** Scene primitives (e.g., triangles), scene bounding box (AABB), grid resolution ($N_x, N_y, N_z$ or $N^3$).
**Outputs:** A grid data structure mapping cells to primitive lists; for a given ray, the list of intersected cells and their primitives.

**Data Structures:**
1.  **Grid Array:** A 1D array of pointers to object lists, sized $N_x \times N_y \times N_z$ [S1, unofficial].
    *   Index calculation: $idx = x + y \cdot N_x + z \cdot N_x \cdot N_y$ [S1, unofficial].
    *   Each element is a pointer to a linked list (`ObjectList`) containing pointers to primitives [S1, unofficial].
2.  **Cell Dimensions:** Precomputed width, height, depth ($dx, dy, dz$) and their reciprocals ($dx_{reci}, dy_{reci}, dz_{reci}$) [S1, unofficial].

**Algorithm Steps:**

1.  **Grid Construction (Build):**
    1.  Determine the scene bounding box defined by minimum corner $p_1$ and maximum corner $p_2$ [S1, S5, unofficial].
    2.  Calculate cell dimensions:
        $$dx = \frac{p_2.x - p_1.x}{N_x}, \quad dy = \frac{p_2.y - p_1.y}{N_y}, \quad dz = \frac{p_2.z - p_1.z}{N_z}$$
        Compute reciprocals: $dx_{reci} = 1/dx$, etc. [S1, unofficial].
    3.  Initialize the grid array with NULL pointers [S1, unofficial].
    4.  For each primitive $p$ in the scene:
        a.  Get the primitive's AABB: $[bv_1, bv_2]$ where $bv_1$ is min and $bv_2$ is max [S1, unofficial].
        b.  Calculate the range of grid cells intersected by this AABB:
            $$x_1 = \lfloor (bv_1.x - p_1.x) \cdot dx_{reci} \rfloor, \quad x_2 = \lfloor (bv_2.x - p_1.x) \cdot dx_{reci} \rfloor + 1$$
            (Similarly for $y_1, y_2$ and $z_1, z_2$) [S1, unofficial].
        c.  Clamp indices to grid bounds: $x_1 = \max(0, x_1)$, $x_2 = \min(N_x - 1, x_2)$, etc. [S1, unofficial].
        d.  For each cell $(x, y, z)$ in the range $[x_1, x_2] \times [y_1, y_2] \times [z_1, z_2]$:
            i.  Calculate index $idx = x + y \cdot N_x + z \cdot N_x \cdot N_y$ [S1, unofficial].
            ii. Add primitive $p$ to the object list at `m_Grid[idx]` [S1, unofficial].

2.  **Ray Traversal Setup:**
    1.  Given a ray $r(t) = o + t \cdot d$, determine the starting cell $(X, Y, Z)$ [S1, S4, unofficial].
        *   If the ray origin $o$ is inside the grid AABB:
            $$X = \lfloor \frac{o.x - p_1.x}{dx} \rfloor, \quad Y = \lfloor \frac{o.y - p_1.y}{dy} \rfloor, \quad Z = \lfloor \frac{o.z - p_1.z}{dz} \rfloor$$
        *   If the ray origin is outside, compute the intersection with the grid AABB. If it misses, terminate. If it hits, use the hit point to determine $(X, Y, Z)$ [S1, unofficial].
    2.  Calculate step directions:
        $$stepX = \begin{cases} 1 & \text{if } d.x > 0 \\ -1 & \text{if } d.x \le 0 \end{cases}$$
        (Similarly for $stepY, stepZ$) [S1, unofficial].
    3.  Calculate $tMax$ (distance to the first cell boundary) and $tDelta$ (distance to cross one cell) for each axis [S1, S4, unofficial]:
        *   Let $t_{start}$ be the parameter where the ray enters the current cell (or 0 if inside).
        *   Boundary coordinates: $B_x = p_1.x + (X + 0.5 \cdot (1 - stepX)) \cdot dx$? No, simpler: The boundary between cell $X$ and $X+stepX$ is at $p_1.x + (X + 1) \cdot dx$ if $stepX=1$, or $p_1.x + X \cdot dx$ if $stepX=-1$.
        *   General formula for $tMaxX$:
            $$tMaxX = \frac{(p_1.x + (X + 1) \cdot dx) - o.x}{d.x} \quad \text{if } d.x > 0$$
            $$tMaxX = \frac{(p_1.x + X \cdot dx) - o.x}{d.x} \quad \text{if } d.x < 0$$
            (Handle $d.x=0$ by setting $tMaxX = \infty$) [S1, S4, unofficial].
        *   $tDeltaX = \frac{dx}{|d.x|}$ (if $d.x \neq 0$, else $\infty$) [S1, S4, unofficial].
        *   Repeat for $Y, Z$ [S1, unofficial].

3.  **Grid Traversal Loop (3D-DDA):**
    1.  While the current cell $(X, Y, Z)$ is within bounds:
        a.  **Process Cell:** If `m_Grid[X, Y, Z]` is not NULL, iterate through the primitive list.
            *   For each primitive, perform intersection test.
            *   **Deduplication:** Use a "mailbox" system. Assign each ray a unique ID. Store `(rayID, primitiveID)` in a cache. Skip intersection tests if the primitive has already been tested by this ray ID [S3, S5, unofficial].
            *   **Correctness Check:** If an intersection is found, verify the intersection point lies within the current cell's bounds (or is the closest hit found so far). If the intersection point is outside the current cell (e.g., in a subsequent cell), continue traversal to find the valid intersection or a closer one [S1, S5, unofficial].
        b.  **Advance Ray:** Compare $tMaxX, tMaxY, tMaxZ$.
            *   If $tMaxX < tMaxY$ and $tMaxX < tMaxZ$:
                $$tMaxX \leftarrow tMaxX + tDeltaX$$
                $$X \leftarrow X + stepX$$
            *   Else if $tMaxY < tMaxZ$:
                $$tMaxY \leftarrow tMaxY + tDeltaY$$
                $$Y \leftarrow Y + stepY$$
            *   Else:
                $$tMaxZ \leftarrow tMaxZ + tDeltaZ$$
                $$Z \leftarrow Z + stepZ$$
            *   If any coordinate goes out of bounds, terminate [S1, S4, unofficial].

**Parameters:**
*   $N_x, N_y, N_z$: Number of cells per dimension. Typical simple implementation uses $5 \times 5 \times 5$ [S3, unofficial]. For general scenes, $m$ (where $N_x=N_y=N_z=m$) is chosen to balance build time and traversal time [S2].
*   GRIDSIZE: Total cells per axis [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Intersection Outside Cell:** A primitive stored in cell $F$ may be intersected by a ray while traversing $F$, but the intersection point lies in cell $G$. Testing only $F$ misses the hit or requires redundant checks in $G$. Solution: Continue traversal until the intersection point is within the current cell or a closer intersection is found [S1, S5, unofficial].
*   **Redundant Tests:** Primitives overlapping multiple cells cause repeated intersection tests. Solution: Mailbox system (ray ID caching) [S3, S5, unofficial].
*   **Precision:** Floating-point errors in DDA can cause missed cells or infinite loops. Using robust 3D-DDA with careful boundary handling is required [S4, unofficial].
*   **Sparse Scenes:** High memory usage due to uniform subdivision; many empty voxels [S4, unofficial].

## Subtopics

### [Regular-Grid Mesh Intersection](15512-regular-grid-mesh-intersection.md)
Computes intersections between a ray and a regular-grid mesh of size $P \times P \times P$ with $O(P)$ complexity. Sets itself apart by exploiting structured topology to limit search space, enabling efficient quadrature for neural field rendering. Choose when rendering neural fields or structured meshes.

## Operating characteristics
*   **Time Complexity:**
    *   Build: $O(N^3 + P \cdot K)$, where $N$ is grid resolution, $P$ is number of primitives, and $K$ is average number of cells a primitive overlaps [S2][S5, unofficial]. The naive build is $O(N^3 \cdot P)$, but optimized build using primitive AABBs is $O(P \cdot K + N^3)$ [S1, unofficial][S2].
    *   Traversal: $O(C)$, where $C$ is the number of cells traversed by the ray [S2].
*   **Memory Complexity:** $O(N^3 + P \cdot K)$ for storing grid pointers and primitive lists [S1, unofficial][S2].
*   **Performance:** On GPU, regular grids are optimal for scenes with uniform data distribution due to high probability of cached texture accesses (up to 100x faster than unstructured access) [S6, unofficial]. Build time is linear, allowing interactive updates for dynamic scenes [S2].
*   **Strengths:** Simple implementation, fast build time, good for dynamic scenes, excellent GPU cache locality [S2][S6, unofficial].
*   **Limitations:** High memory usage for sparse scenes, no adaptivity to primitive density, redundant intersection tests for large primitives [S4, S5, unofficial].
*   **When to use:** Uniform scenes, dynamic scenes requiring frequent rebuilds, GPU rendering with texture cache optimization [S2][S6, unofficial].
*   **When not to use:** Highly sparse or clustered scenes, scenes with large primitives causing excessive overlap [S4, unofficial].

## Background
Regular grids were introduced as one of the earliest spatial acceleration structures for ray tracing [S2][S5, unofficial]. Gla84 is cited as the origin of grid data structures in the context of dividing scene-space into uniform voxels [S2]. They have been widely used in software ray tracers and are often recommended as a starting point for homework assignments in computer graphics courses [S3, unofficial]. Nvidia OptiX uses BVH internally, but the grid concept remains foundational [S3, unofficial]. They are also popular in particle-based simulations and computational fluid dynamics [S2].
