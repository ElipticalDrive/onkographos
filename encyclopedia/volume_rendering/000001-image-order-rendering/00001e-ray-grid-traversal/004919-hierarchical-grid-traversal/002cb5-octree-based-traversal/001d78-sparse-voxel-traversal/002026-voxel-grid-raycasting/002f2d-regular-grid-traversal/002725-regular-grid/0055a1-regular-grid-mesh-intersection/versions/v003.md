# Regular-Grid Mesh Intersection

Also called: Ray-Mesh Quadrature

## Overview
Regular-Grid Mesh Intersection computes intersections between a ray and a regular-grid mesh $M$ of size $P \times P \times P$ with $O(P)$ complexity [S1]. It differs from general ray-mesh intersection algorithms by exploiting the structured topology of the regular grid to restrict the search space to a linear number of voxels and faces, enabling efficient quadrature for neural field rendering [S1].

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ [S1].
- Regular-grid mesh $M$ defined on a grid of size $P \times P \times P$ [S1].
- Acceleration grid $G \in \mathbb{R}^{P \times P \times P}$, where each element $G_{i,j,k}$ is a real number indicating geometry likelihood [S1].
- Training progress $t \in [0, 1]$ to determine pruning aggressiveness [S1].
- Scene type flag (e.g., unbounded 360°) [S1].

**Outputs:**
- A set of quadrature points (intersection points) between the ray and the mesh faces [S1].

**Data Structures:**
- **Acceleration Grid $G$**: A 3D array of size $P \times P \times P$ [S1]. Each element $G_{i,j,k}$ is a real number [S1]. The sources do not specify exact bit-packing or normalization range, but it functions as a threshold filter [S1].
- **Mesh $M$**: Implicitly defined by the regular grid vertices, consisting of faces incident to voxel vertices [S1].

**Numbered Steps:**
1. **Compute Intersected Voxels:** Solve $3P$ ray-plane intersections to determine the set of voxels intersected by the ray [S1]. Using these intersection points, identify at most $3P$ intersected voxels [S1].
2. **Prune Empty Voxels (Conditional):** Use the acceleration grid $G$ to prune voxels unlikely to contain geometry based on threshold $\tau_G = 0.1$ [S1].
   - **Training Stage 1 (First Quarter, $t < 0.25$):** Do not use $G$ for pruning [S1]. Keep all $3P$ intersected voxels and all $3P$ intersection points [S1].
   - **Training Stage 2 (Second Quarter, $0.25 \le t < 0.5$):** Use $G$ to remove empty voxels [S1]. Keep at most $3P/2$ non-empty voxels and the $3P/2$ intersection points closest to the camera [S1].
   - **Training Stage 3 (Rest of Training, $t \ge 0.5$):** Use $G$ to remove empty voxels [S1]. Keep at most $3P/4$ intersection points [S1].
   - **Batch Size Adjustment:** Double the training batch size each time the number of intersections is halved [S1].
3. **Compute Quadrature Points:** For each kept voxel, compute intersections between the ray and the faces of $M$ that are incident to the voxel’s vertex [S1]. This yields the final set of quadrature points [S1].
4. **Special Case for Unbounded 360° Scenes:** For concentric boxes in unbounded 360° scenes, compute their intersections and keep all of them, bypassing the pruning steps above [S1].

**Formulas:**
- Ray-plane intersection parameter: $t = \frac{c - \mathbf{o}_i}{\mathbf{d}_i}$, where $c$ is the grid plane coordinate along axis $i \in \{x, y, z\}$, $\mathbf{o}_i$ and $\mathbf{d}_i$ are the ray origin and direction components along axis $i$, and $t > 0$ ensures forward intersection [S1].
- Voxel index from intersection point: $v_i = \lfloor (\mathbf{o}_i + t \mathbf{d}_i) P \rfloor$ [S1].
- Distance to camera for sorting: $D(\mathbf{p}) = \|\mathbf{p} - \mathbf{o}\|$ [S1].

**Parameters:**
- $\tau_G = 0.1$: Threshold for pruning voxels in the acceleration grid [S1].
- $P$: Grid resolution (dimension of the regular grid) [S1].

**Edge Cases and Pitfalls:**
- **Precision:** Division by zero occurs when $\mathbf{d}_i = 0$; a small epsilon guard ($10^{-8}$) is required [G].
- **Boundaries:** Intersection points must be clamped to voxel face bounds to avoid duplicate or out-of-mesh quadrature points [G].
- **Degenerate Input:** Unbounded 360° scenes with concentric boxes require bypassing pruning to retain all intersections [S1].

**Pseudocode:**
```python
def regular_grid_mesh_intersection(ray_origin, ray_direction, accel_grid, P, training_progress, is_unbounded_360):
    """
    Compute intersections between a ray and a regular-grid mesh.
    
    Args:
        ray_origin: 3D vector, origin of the ray.
        ray_direction: 3D vector, direction of the ray.
        accel_grid: 3D array of size P x P x P, values indicate geometry likelihood.
        P: Integer, grid resolution.
        training_progress: Float in [0, 1], normalized training progress.
        is_unbounded_360: Boolean, true for unbounded 360 degree scenes.
        
    Returns:
        list of intersection points (quadrature points).
    """
    EPS = 1e-8
    intersected_voxels = []
    
    # Step 1: Solve 3P ray-plane intersections to find intersected voxels
    for axis in range(3):
        for i in range(P):
            plane_coord = i / P
            denom = ray_direction[axis]
            if abs(denom) > EPS:
                t = (plane_coord - ray_origin[axis]) / denom
                if t > 0:
                    point = ray_origin + t * ray_direction
                    # Clamp voxel index to valid range [0, P-1]
                    voxel_idx = tuple(min(int(point[d] * P), P - 1) for d in range(3))
                    if voxel_idx not in intersected_voxels:
                        intersected_voxels.append(voxel_idx)
                        
    kept_voxels = []
    if is_unbounded_360 or training_progress < 0.25:
        kept_voxels = intersected_voxels
    else:
        # Filter by acceleration grid threshold
        filtered = [v for v in intersected_voxels if accel_grid[v] >= 0.1]
        # Sort by distance to camera to keep closest points
        filtered.sort(key=lambda v: sum((ray_origin[d] - v[d] / P) ** 2 for d in range(3)))
        # Limit based on training stage
        limit = int(1.5 * P) if training_progress < 0.5 else int(0.75 * P)
        kept_voxels = filtered[:limit]
        
    # Step 3: Compute quadrature points by intersecting ray with voxel faces
    quadrature_points = []
    for voxel in kept_voxels:
        for axis in range(3):
            for boundary in (0, 1):
                plane_coord = boundary / P
                denom = ray_direction[axis]
                if abs(denom) > EPS:
                    t = (plane_coord - ray_origin[axis]) / denom
                    if t > 0:
                        point = ray_origin + t * ray_direction
                        # Check if point lies within voxel bounds on other axes
                        valid = True
                        for d in range(3):
                            if d != axis:
                                if not (voxel[d] / P <= point[d] <= (voxel[d] + 1) / P):
                                    valid = False
                                    break
                        if valid:
                            quadrature_points.append(point)
    return quadrature_points
```

## Operating characteristics
- **Time Complexity:** $O(P)$ for computing intersections [S1].
- **Memory Complexity:** Requires storage for the acceleration grid $G \in \mathbb{R}^{P \times P \times P}$ [S1].
- **Performance:** The method reduces the number of intersection tests, enabling efficient neural field rendering [S1].
- **Strengths:** Linear complexity with respect to grid resolution $P$; efficient pruning via acceleration grid [S1].
- **Limitations:** Accuracy of the acceleration grid $G$ is low in the first quarter of training, necessitating full voxel retention initially [S1].

## Background
The method is described in the context of MobileNeRF, which exploits the polygon rasterization pipeline for efficient neural field rendering [S1]. It was introduced to address the computational cost of ray-mesh intersections in neural rendering [S1].
