# Voxel Grid Accelerated Ray-Point Intersection

Also called: GPU voxel grid for ray casting, Pointersect voxel structure

## Overview
This method accelerates the identification of the $k$ nearest points within a cylinder of radius $\delta$ around a query ray in a point cloud, specifically optimized for parallel GPU execution and dynamic scenes where the point cloud changes frequently [S1]. Unlike static acceleration structures such as octrees, which require $O(n \log n)$ construction time, this voxel grid approach achieves $O(n)$ construction, making it superior for inverse rendering and dynamic scenarios where the structure must be rebuilt every iteration [S1].

## How it works
**Inputs:**
- Point cloud $P$ containing $n$ points.
- Query ray $r = (r_o, r_d)$, where $r_o$ is the origin and $r_d$ is the direction.
- Parameters:
  - $k$: Number of nearest points to retrieve [S1].
  - $\delta$: Radius of the cylinder around the query ray [S1].
  - $g$: Number of grid cells per dimension in the voxel grid [S1].

**Outputs:**
- A list of $k$ points from $P$ that are closest to the ray $r$ in terms of perpendicular distance, restricted to those within distance $\delta$ [S1].

**Data Structures:**
- **Voxel Grid:** A uniform 3D grid with $g^3$ cells. Each cell stores a list (or linked list) of point indices belonging to that voxel.
- **Point Table:** An array of size $n$ storing the 3D coordinates of each point in $P$.

**Steps:**
1. **Grid Construction:** Divide the 3D space containing $P$ into a uniform voxel grid with $g$ cells per dimension. Iterate through all $n$ points in $P$ and assign each point to its corresponding voxel in the grid table. This step takes $O(n)$ operations [S1].
2. **Ray Traversal:** For each query ray, trace it through the voxel grid to identify candidate voxels intersected by the ray. Compute grid-ray intersection in $O(g)$ time per ray. This computation is parallelized across multiple GPU threads [S1].
3. **Candidate Collection:** Collect all points located in the intersected voxels. Filter these points to keep only those within perpendicular distance $\delta$ from the ray, resulting in $q$ candidate points [S1].
4. **Sorting and Selection:** Sort the $q$ candidate points by their perpendicular distance to the ray and select the $k$ nearest ones [S1].

**Formulas:**
- **Time Complexity:** The overall time complexity for finding $k$ nearest points within a surrounding cylinder of radius $\delta$ is:
  $$ O(n + mg + mq \log(q)) $$
  where $n$ is the total number of points, $m$ is the number of rays, $g$ is the grid cells per dimension, and $q$ is the number of points lying within the cylinder [S1].
- **Expected Candidates:** For uniformly distributed points, the expected number of points in the cylinder is:
  $$ q = n/g^3 $$
  [S1]

**Pseudocode:**
```python
def build_voxel_grid(points, grid_size, bounds_min, bounds_max):
    """
    Builds a uniform voxel grid for a point cloud.
    points: List of 3D coordinates (n, 3)
    grid_size: Integer g, number of cells per dimension
    bounds_min: 3D vector, minimum corner of the grid
    bounds_max: 3D vector, maximum corner of the grid
    Returns: A 3D array of lists (grid_size, grid_size, grid_size)
    """
    # Calculate voxel dimensions
    voxel_size = (bounds_max - bounds_min) / grid_size
    
    # Initialize empty grid
    grid = [[[] for _ in range(grid_size)] for _ in range(grid_size)]
    for z in range(grid_size):
        for y in range(grid_size):
            for x in range(grid_size):
                grid[z][y][x] = []

    # Assign points to voxels
    for point in points:
        # Calculate voxel coordinates
        x = int((point[0] - bounds_min[0]) / voxel_size[0])
        y = int((point[1] - bounds_min[1]) / voxel_size[1])
        z = int((point[2] - bounds_min[2]) / voxel_size[2])
        
        # Clamp to grid boundaries
        x = max(0, min(x, grid_size - 1))
        y = max(0, min(y, grid_size - 1))
        z = max(0, min(z, grid_size - 1))
        
        grid[z][y][x].append(point)
        
    return grid

def ray_voxel_intersection(ray_origin, ray_direction, grid_size, bounds_min, bounds_max):
    """
    Traces a ray through a uniform voxel grid to find intersected voxels.
    Uses a 3D DDA (Digital Differential Analyzer) approach.
    """
    # Calculate voxel size
    voxel_size = (bounds_max - bounds_min) / grid_size
    
    # Initialize traversal variables
    # Current voxel coordinates
    x, y, z = int((ray_origin[0] - bounds_min[0]) / voxel_size[0]), \
              int((ray_origin[1] - bounds_min[1]) / voxel_size[1]), \
              int((ray_origin[2] - bounds_min[2]) / voxel_size[2])
              
    # Step directions
    step_x = 1 if ray_direction[0] > 0 else -1
    step_y = 1 if ray_direction[1] > 0 else -1
    step_z = 1 if ray_direction[2] > 0 else -1
    
    # Distance to next voxel boundary
    t_max_x = ((x + (1 if step_x > 0 else 0)) * voxel_size[0] + bounds_min[0] - ray_origin[0]) / ray_direction[0]
    t_max_y = ((y + (1 if step_y > 0 else 0)) * voxel_size[1] + bounds_min[1] - ray_origin[1]) / ray_direction[1]
    t_max_z = ((z + (1 if step_z > 0 else 0)) * voxel_size[2] + bounds_min[2] - ray_origin[2]) / ray_direction[2]
    
    # Delta distances between voxel boundaries
    delta_x = voxel_size[0] / abs(ray_direction[0])
    delta_y = voxel_size[1] / abs(ray_direction[1])
    delta_z = voxel_size[2] / abs(ray_direction[2])
    
    intersected_voxels = []
    
    # Traverse until out of bounds
    while 0 <= x < grid_size and 0 <= y < grid_size and 0 <= z < grid_size:
        intersected_voxels.append((x, y, z))
        
        # Advance to next voxel
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                x += step_x
                t_max_x += delta_x
            else:
                z += step_z
                t_max_z += delta_z
        else:
            if t_max_y < t_max_z:
                y += step_y
                t_max_y += delta_y
            else:
                z += step_z
                t_max_z += delta_z
                
    return intersected_voxels

def perpendicular_distance(point, ray_origin, ray_direction):
    """
    Calculates the perpendicular distance from a point to a ray.
    """
    # Vector from ray origin to point
    v = point - ray_origin
    # Project v onto ray direction
    proj_length = dot(v, ray_direction)
    # Projection vector
    proj = proj_length * ray_direction
    # Perpendicular vector
    perp = v - proj
    return length(perp)

def find_k_nearest_points(points, ray_origin, ray_direction, k, delta):
    """
    Finds k nearest points to a ray within distance delta.
    """
    candidates = []
    for point in points:
        dist = perpendicular_distance(point, ray_origin, ray_direction)
        if dist <= delta:
            candidates.append((dist, point))
            
    # Sort by distance
    candidates.sort(key=lambda x: x[0])
    
    # Return k nearest
    return [p for _, p in candidates[:k]]

def voxel_grid_ray_point_intersection(points, rays, grid_size, bounds_min, bounds_max, k, delta):
    """
    Main function combining voxel grid construction and ray-point intersection.
    """
    # Build voxel grid
    grid = build_voxel_grid(points, grid_size, bounds_min, bounds_max)
    
    results = []
    for ray in rays:
        # Get intersected voxels
        voxels = ray_voxel_intersection(ray.origin, ray.direction, grid_size, bounds_min, bounds_max)
        
        # Collect candidates from voxels
        candidates = []
        for (x, y, z) in voxels:
            for point in grid[z][y][x]:
                dist = perpendicular_distance(point, ray.origin, ray.direction)
                if dist <= delta:
                    candidates.append((dist, point))
        
        # Sort and select k nearest
        candidates.sort(key=lambda x: x[0])
        results.append([p for _, p in candidates[:k]])
        
    return results
```

**Edge Cases and Pitfalls:**
- The implementation described in the source is not optimized; specifically, retrieving unordered $k$ nearest points from $q$ points can be done in $O(q)$, but the current implementation sorts them, resulting in $O(q \log q)$ [S1].
- For uniformly distributed points, the expected number of points in the cylinder is $q = n/g^3$ [S1].
- The method is slower than octrees for static scenes but faster to construct, making it suitable for dynamic scenes or inverse rendering where the tree must be rebuilt every iteration [S1].

## Operating characteristics
- **Time Complexity:** $O(n + mg + mq \log(q))$, where $n$ is total points, $m$ is number of rays, $g$ is grid cells per dimension, and $q$ is points within the cylinder [S1].
- **Construction Time:** $O(n)$, which is faster than octree construction ($O(n \log n)$) [S1].
- **Query Time:** $O(g + q \log q)$ per ray, where $g$ is the cost of grid-ray intersection and $q \log q$ is the cost of sorting candidates [S1].
- **Strengths:** Fast construction makes it superior for dynamic scenes or inverse rendering where the point cloud changes frequently and the structure must be rebuilt every iteration [S1]. Parallelizable on GPU [S1].
- **Limitations:** Slower query performance for static scenes compared to octrees ($n \log(n) + m \log(n) + mq$) [S1]. The sorting step is not optimized; using a selection algorithm could reduce the sorting cost to $O(q)$ [S1].
- **When to Use:** Dynamic scenes, inverse rendering, or scenarios requiring frequent updates to the point cloud structure [S1].
- **When Not to Use:** Static scenes where an octree can be built once and reused, as octrees offer faster query performance in that context [S1].

## Background
The method was introduced in the context of "Pointersect: Neural Rendering with Cloud-Ray Intersection" [S1]. It was designed to address the inefficiency of rebuilding octrees in dynamic scenes or inverse rendering applications, where many points in the point cloud can change at every iteration [S1]. The approach leverages the simplicity and parallelizability of uniform voxel grids to achieve faster construction times compared to hierarchical structures like octrees [S1].
