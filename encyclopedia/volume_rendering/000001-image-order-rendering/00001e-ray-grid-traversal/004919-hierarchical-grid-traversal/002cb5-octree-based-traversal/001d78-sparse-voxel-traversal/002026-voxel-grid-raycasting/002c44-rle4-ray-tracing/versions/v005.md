# RLE4 Ray Tracing

Also called: Map4 Traversal

## Overview
RLE4 Ray Tracing is a ray-marching or voxel-intersection algorithm that traverses an RLE4-compressed volume structure (Map4) to locate the first occupied voxel along a ray or to colorize a voxel based on its position [S1, unofficial]. It uses slab-based RLE encoding to skip empty space efficiently [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A float position `pos` (x, y, z), volume dimensions `vx, vy, vz`, and a pre-compressed RLE4 structure `map4` containing a slab pointer array `map`, a slab data array `slabs`, and the X-dimension size `sx` [S1, unofficial].
*   **Output:** A packed 16-bit RGB value stored in the texture array if the voxel is found, or a skip indicator if not [S1, unofficial].

**Data Structures:**
The Map4 structure uses `map4.map` indexed by `x + z * map4.sx` to point into `map4.slabs` [S1, unofficial]. Each slab entry is a 16-bit integer where bits 0–9 store a Y-coordinate increment and bits 10–15 store the Y-range length [S1, unofficial].

**Algorithm Steps:**

1.  **Coordinate Conversion:** Convert the float position `pos` to integer voxel coordinates `x, y, z` by scaling with volume dimensions `vx, vy, vz` [S1, unofficial].
2.  **Bounds Check:** Verify `x` and `z` are within bounds [S1, unofficial].
3.  **Slab Access:** Access the slab pointer for the current XZ coordinate [S1, unofficial].
4.  **Read Segment Lengths:** Read the lengths of the first and second slab segments to skip header data [S1, unofficial].
5.  **Initialize State:** Set `y1=0, y2=0`. Set pointer `pt` to `p+len1`. Initialize `texture=0` [S1, unofficial].
6.  **Iterate Slabs:** Loop `s` from `0` to `len1-1` [S1, unofficial]:
    a.  **Read Slab Entry:** `slab = p[0]; p += 1` [S1, unofficial].
    b.  **Decode Y-Range:** `y1 += slab & 1023; y2 = y1 + (slab >> 10)` [S1, unofficial].
    c.  **Check Intersection:** Check if the target Y coordinate `y` falls within the current slab range `[y1, y2)` [S1, unofficial].
    d.  **Advance:** If not found, advance the texture pointer and Y1: `texture += y2 - y1; y1 = y2` [S1, unofficial].

```python
def rle4_traverse(pos, vx, vy, vz, map4):
    # 1. Coordinate conversion
    x = int(pos[0] * vx)
    y = int(pos[1] * vy)
    z = int(pos[2] * vz)

    # 2. Bounds check
    if x < 0 or x >= vx or z < 0 or z >= vz:
        return None

    # 3. Slab access (pointer arithmetic simulated via index offset)
    p = map4.slabs + map4.map[x + z * map4.sx]

    # 4. Read segment lengths
    len1 = p[0]; p += 1
    len2 = p[0]; p += 1

    # 5. Initialize state
    y1 = 0
    y2 = 0
    pt = p + len1
    texture = 0

    # 6. Iterate slabs
    for s in range(len1):
        slab = p[0]; p += 1
        y1 += slab & 1023
        y2 = y1 + (slab >> 10)

        # 6c. Check intersection
        if y >= y1 and y < y2:
            col = read_color_from_texture(pt, texture + y - y1)
            r_ = clamp(col[0] * 15 + 16, 0, 31)
            g_ = clamp(col[1] * 15 + 16, 0, 31)
            b_ = clamp(col[2] * 15 + 16, 0, 31)
            packed = int(r_ + (g_ << 5) + (b_ << 10))
            pt[texture + y - y1] = packed
            return packed

        # 6d. Advance
        texture += y2 - y1
        y1 = y2

    return None

def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))

def read_color_from_texture(texture_array, offset):
    # Standard texture/array lookup [G]
    return texture_array[offset]
```

**Parameters:**
*   Color quantization: 5 bits per channel (0–31 range) [S1, unofficial].
*   Y-range decoding: 10 bits for Y-increment, 6 bits for Y-length [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Bounds:** The algorithm assumes the target Y coordinate is within the volume bounds checked at the start; if the ray passes through multiple slabs, it iterates until the Y range is found [S1, unofficial].
*   **Precision:** The color quantization uses 5 bits per channel, which may introduce visible banding in high-dynamic-range scenes [S1, unofficial].
*   **Empty Regions:** If the Y coordinate is not found in any slab, the algorithm returns without writing, effectively skipping the voxel [S1, unofficial].

## Subtopics

### [RL-compressed GPU Ray Casting with Texture-Based Lookup](10793-rl-compressed-gpu-ray-casting-with-texture-based-lookup.md)
This method performs GPU-based ray casting on volume data compressed using run-length encoding (RLE), storing the compressed structure in 2D textures to facilitate efficient random access. It distinguishes itself from sibling methods by avoiding full decompression; instead, it uses a texture-based lookup system to determine if a sample point lies in an uncompressed surface region, an "inside" region, or an "outside" region, returning special markers for the latter two. This approach is particularly suited for scenarios where the volume geometry is sparse or has large uniform interior/exterior regions, allowing the renderer to skip volumetric integration in those areas.

## Operating characteristics
*   **Time Complexity:** $O(k)$ where $k$ is the number of Y-slabs traversed along the ray [G].
*   **Memory Complexity:** $O(N)$ for the compressed RLE4 structure, where $N$ is the number of occupied Y-ranges [G].
*   **Performance:** Efficient for sparse volumes with large uniform regions, as it avoids full decompression and skips empty space [S1, unofficial].
*   **Strengths:** Low memory footprint for sparse data; fast traversal of empty space; GPU-friendly texture lookups [S1, unofficial].
*   **Limitations:** Color quantization limits visual fidelity to 5 bits per channel; requires pre-compression of volume data; not suitable for dense volumes where compression ratio is low [S1, unofficial].

## Background
The method is documented in the OpenGL-Voxel-Splatting repository [S1, unofficial]. It is used for efficient ray casting in sparse volumetric data, leveraging RLE compression to skip empty space [S1, unofficial].
