# Regular-Grid Mesh Intersection

Also called: Ray-Mesh Quadrature

## Overview
Regular-Grid Mesh Intersection is a method to compute intersections between a ray and a regular-grid mesh $M$ of size $P \times P \times P$ with $O(P)$ complexity [S1]. It sets itself apart from general ray-mesh intersection algorithms by exploiting the structured topology of the regular grid to limit the search space to a linear number of voxels and faces, enabling efficient quadrature for neural field rendering [S1].

## How it works
**Inputs:**
- Ray origin $\mathbf{o}$ and direction $\mathbf{d}$.
- Regular-grid mesh $M$ defined on a grid of size $P \times P \times P$.
- Acceleration grid $G \in \mathbb{R}^{P \times P \times P}$, where each cell stores a value indicating the likelihood of containing geometry [S1].
- Training stage indicator $t$ (normalized to $[0,1]$) to determine pruning aggressiveness [S1].
- Scene type flag (e.g., unbounded 360°) [S1].

**Outputs:**
- A set of quadrature points (intersection points) between the ray and the mesh faces [S1].

**Data Structures:**
- **Acceleration Grid $G$**: A 3D array of size $P \times P \times P$. Each element $G_{i,j,k}$ is a real number. The sources do not specify the exact bit-packing or normalization range, but it is used as a threshold filter [S1].
- **Mesh $M$**: Implicitly defined by the regular grid vertices. The mesh consists of faces incident to the voxel vertices [S1].

**Parameters:**
- $\tau_G = 0.1$: Threshold for pruning voxels in the acceleration grid [S1].
- $P$: Grid resolution (dimension of the regular grid) [S1].

**Steps:**

1. **Compute Intersected Voxels:**
   Solve $3P$ ray-plane intersections to determine the set of voxels intersected by the ray. Using the intersection points, identify at most $3P$ intersected voxels [S1].

2. **Prune Empty Voxels (Conditional):**
   Use the acceleration grid $G$ to prune voxels unlikely to contain geometry. A voxel is kept if its corresponding value in $G$ exceeds $\tau_G = 0.1$ [S1].
   - **Training Stage 1 (First Quarter):** Do not use $G$ for pruning. Keep all $3P$ intersected voxels and all $3P$ intersection points [S1].
   - **Training Stage 2 (Second Quarter):** Use $G$ to remove empty voxels. Keep at most $3P/2$ non-empty voxels and the $3P/2$ intersection points closest to the camera [S1].
   - **Training Stage 3 (Rest of Training):** Use $G$ to remove empty voxels. Keep at most $3P/4$ intersection points [S1].
   - **Batch Size Adjustment:** Double the training batch size each time the number of intersections is halved [S1].

3. **Compute Quadrature Points:**
   For each kept voxel, compute intersections between the ray and the faces of $M$ that are incident to the voxel’s vertex. This yields the final set of quadrature points [S1].

4. **Special Case for Unbounded 360° Scenes:**
   For concentric boxes in unbounded 360° scenes, compute their intersections and keep all of them, regardless of the pruning steps above [S1].

**Pseudocode:**

```python
def regular_grid_mesh_intersection(ray_origin, ray_direction, mesh, accel_grid, P, training_stage, is_unbounded_360):
    """
    Compute intersections between a ray and a regular-grid mesh.
    
    Args:
        ray_origin: 3D vector, origin of the ray.
        ray_direction: 3D vector, direction of the ray.
        mesh: Regular-grid mesh of size P x P x P.
        accel_grid: 3D array of size P x P x P, values indicate geometry likelihood.
        P: Integer, grid resolution.
        training_stage: Float in [0, 1], normalized training progress.
        is_unbounded_360: Boolean, true for unbounded 360 degree scenes.
        
    Returns:
        list of intersection points (quadrature points).
    """
    
    # Step 1: Compute intersected voxels
    # Solve 3P ray-plane intersections to find intersected voxels
    intersected_voxels = solve_ray_plane_intersections(ray_origin, ray_direction, P)
    # At most 3P voxels
    num_voxels = len(intersected_voxels)
    
    # Step 2: Pruning based on training stage
    if is_unbounded_360:
        # Special case: keep all intersections for concentric boxes
        kept_voxels = intersected_voxels
    else:
        if training_stage < 0.25:
            # First quarter: no pruning, keep all
            kept_voxels = intersected_voxels
        elif training_stage < 0.5:
            # Second quarter: prune using G, keep at most 3P/2
            kept_voxels = prune_voxels(intersected_voxels, accel_grid, threshold=0.1)
            # Keep closest 3P/2 to camera
            kept_voxels = keep_closest(kept_voxels, ray_origin, limit=3*P/2)
        else:
            # Rest of training: prune using G, keep at most 3P/4
            kept_voxels = prune_voxels(intersected_voxels, accel_grid, threshold=0.1)
            # Keep closest 3P/4 to camera
            kept_voxels = keep_closest(kept_voxels, ray_origin, limit=3*P/4)
            
    # Step 3: Compute quadrature points
    quadrature_points = []
    for voxel in kept_voxels:
        # Compute intersections between ray and faces incident to voxel's vertex
        points = compute_face_intersections(ray_origin, ray_direction, mesh, voxel)
        quadrature_points.extend(points)
        
    return quadrature_points
```

## Operating characteristics
- **Time Complexity:** $O(P)$ for computing intersections [S1].
- **Memory Complexity:** Requires storage for the acceleration grid $G \in \mathbb{R}^{P \times P \times P}$ [S1].
- **Performance:** The method enables efficient neural field rendering on mobile architectures by reducing the number of intersection tests [S1].
- **Strengths:** Linear complexity with respect to grid resolution $P$; efficient pruning via acceleration grid [S1].
- **Limitations:** Accuracy of the acceleration grid $G$ is low in the first quarter of training, necessitating full voxel retention initially [S1].

## Background
The method is described in the context of MobileNeRF, which exploits the polygon rasterization pipeline for efficient neural field rendering on mobile architectures [S1]. It was introduced to address the computational cost of ray-mesh intersections in neural rendering [S1].
