# Regular Grid

Also called: Grid Data Structure, Grilles régulières, Regular Grid Spatial Subdivision, Uniform Grids, Uniform Spatial Subdivision

## Overview
A Regular Grid is a spatial acceleration structure that partitions the scene's Axis-Aligned Bounding Box (AABB) into a fixed-size 3D grid of uniform cells (voxels) [S1, unofficial][S3][S5, unofficial]. It solves the problem of $O(N)$ ray-primitive intersection tests by allowing rays to skip empty cells, testing only primitives stored in intersected voxels [S4, S5, unofficial]. Unlike hierarchical structures (e.g., BVH, Octree) that partition primitives into disjoint sets, the Regular Grid partitions space into disjoint sub-blocks, meaning a single primitive can belong to multiple cells [S5, unofficial]. It is distinguished by its constant-time cell access, simple traversal logic, and suitability for dynamic scenes due to its linear build time, though it suffers from high memory overhead in sparse scenes [S3][S5, unofficial].

## How it works
**Inputs:**
- Ray $r(t) = o + t \cdot d$, where $o$ is the origin and $d$ is the direction vector.
- Scene bounding box defined by minimum corner $p_1$ and maximum corner $p_2$.
- Grid resolution $(N_x, N_y, N_z)$, the number of cells along each axis [S3].

**Outputs:**
- A list of primitives intersected by the ray, or the nearest intersection point.

**Data Structures:**
- **Grid Array:** A 1D array of size $N_x \times N_y \times N_z$ [S1, unofficial]. Each element is a pointer to a linked list of primitives (ObjectList) [S1, unofficial].
- **Indexing:** Cell $(x, y, z)$ is accessed via `idx = x + y * N_x + z * N_x * N_y` [S1, unofficial].
- **Primitive List:** Each node in the linked list contains a pointer to a primitive and a pointer to the next node [S1, unofficial].

**Algorithm Steps:**

1.  **Grid Construction (Preprocessing):**
    a.  Determine the scene bounding box $[p_1, p_2]$ [S6, unofficial].
    b.  Calculate cell dimensions:
        $$dx = \frac{p_2.x - p_1.x}{N_x}, \quad dy = \frac{p_2.y - p_1.y}{N_y}, \quad dz = \frac{p_2.z - p_1.z}{N_z}$$
        [S1, unofficial][S3]
    c.  Initialize the grid array to NULL [S1, unofficial].
    d.  For each primitive $P$ in the scene:
        i.  Compute its AABB $[b_{min}, b_{max}]$ [S1, unofficial].
        ii. Determine the range of grid cells that overlap this AABB. Calculate the cell indices for the minimum and maximum corners:
            $$x_1 = \max(0, \lfloor \frac{b_{min}.x - p_1.x}{dx} \rfloor), \quad x_2 = \min(N_x - 1, \lfloor \frac{b_{max}.x - p_1.x}{dx} \rfloor + 1)$$
            (Similarly for $y_1, y_2$ and $z_1, z_2$) [S1, unofficial].
        iii. For each cell $(x, y, z)$ in the range $[x_1, x_2] \times [y_1, y_2] \times [z_1, z_2]$:
            - Add primitive $P$ to the object list of cell $(x, y, z)$ [S1, S5, unofficial].
            - *Note:* This mapping must be conservative; it may include more primitives than strictly necessary but never fewer [S5, unofficial].

2.  **Ray Traversal Setup:**
    a.  Intersect the ray with the grid's bounding box $[p_1, p_2]$ to find the entry parameter $t_{enter}$ and exit parameter $t_{exit}$ [S1, S5, unofficial].
    b.  If $t_{exit} < 0$ or $t_{enter} > t_{exit}$, the ray misses the grid entirely [S1, unofficial].
    c.  Calculate the starting point on the ray: $start\_point = o + d \cdot \max(t_{enter}, 0.0)$ [S1, S5, unofficial].
    d.  Determine the starting cell $(X, Y, Z)$:
        $$X = \lfloor \frac{start\_point.x - p_1.x}{dx} \rfloor, \quad Y = \lfloor \frac{start\_point.y - p_1.y}{dy} \rfloor, \quad Z = \lfloor \frac{start\_point.z - p_1.z}{dz} \rfloor$$
        [S1, S5, unofficial]
    e.  Determine step directions:
        $$stepX = \begin{cases} 1 & \text{if } d.x > 0 \\ -1 & \text{if } d.x < 0 \\ 0 & \text{if } d.x = 0 \end{cases}$$
        (Similarly for $stepY, stepZ$) [S1, unofficial].
    f.  Calculate initial distances to the next cell boundary ($tMax$):
        If $d.x > 0$: $tMaxX = \frac{(X + 1) \cdot dx + p_1.x - start\_point.x}{d.x}$
        If $d.x < 0$: $tMaxX = \frac{X \cdot dx + p_1.x - start\_point.x}{d.x}$
        If $d.x = 0$: $tMaxX = \infty$
        (Similarly for $tMaxY, tMaxZ$) [S1, unofficial].
    g.  Calculate distances to cross one full cell ($tDelta$):
        $$tDeltaX = \frac{dx}{|d.x|} \text{ if } d.x \neq 0 \text{ else } \infty$$
        (Similarly for $tDeltaY, tDeltaZ$) [S1, unofficial].

3.  **Traversal Loop:**
    While $0 \le X < N_x$ and $0 \le Y < N_y$ and $0 \le Z < N_z$:
    a.  **Process Cell:** Retrieve the object list for cell $(X, Y, Z)$. If the list is not NULL, test the ray against all primitives in the list [S1, unofficial].
        - *Intersection Handling:* If an intersection is found, verify if the intersection point lies within the current cell's bounds along the ray's path. If the intersection is outside the current cell (e.g., the primitive spans into the next cell), continue traversal to subsequent cells to find the true closest intersection or to avoid redundant tests [S1, S6, unofficial].
        - *Deduplication:* To avoid testing the same primitive multiple times if it spans multiple cells, use a "Mailbox" system: assign each ray a unique ID. Store the ray ID and intersection data in the primitive. Skip the test if the primitive's cache already contains a valid intersection for the current ray ID [S6, unofficial].
    b.  **Advance Ray:** Compare $tMaxX, tMaxY, tMaxZ$. Advance to the nearest boundary:
        - If $tMaxX < tMaxY$ and $tMaxX < tMaxZ$:
          $X += stepX$
          $tMaxX += tDeltaX$
        - Else if $tMaxY < tMaxZ$:
          $Y += stepY$
          $tMaxY += tDeltaY$
        - Else:
          $Z += stepZ$
          $tMaxZ += tDeltaZ$
    c.  If a hit is found and verified, return it. If the loop terminates (ray exits grid), return no hit [S1, unofficial].

**Pseudocode:**

```python
def regular_grid_traverse(ray_origin, ray_direction, grid_min, grid_max, grid_res, grid_array):
    Nx, Ny, Nz = grid_res
    
    # 1. Grid Dimensions
    dx = (grid_max.x - grid_min.x) / Nx
    dy = (grid_max.y - grid_min.y) / Ny
    dz = (grid_max.z - grid_min.z) / Nz
    
    # 2. Ray-Grid AABB Intersection
    # Compute t_min and t_max for the ray intersecting the grid bounds
    # If ray_direction.x == 0, handle division by zero by setting t_min/max appropriately
    # Standard slab method:
    t_min = -float('inf')
    t_max = float('inf')
    
    for axis in ['x', 'y', 'z']:
        p1 = getattr(grid_min, axis)
        p2 = getattr(grid_max, axis)
        d = getattr(ray_direction, axis)
        o = getattr(ray_origin, axis)
        
        if d == 0:
            if o < p1 or o > p2:
                return None # Ray misses grid
        else:
            t1 = (p1 - o) / d
            t2 = (p2 - o) / d
            if t1 > t2: t1, t2 = t2, t1
            t_min = max(t_min, t1)
            t_max = min(t_max, t2)
            
    if t_max < 0 or t_min > t_max:
        return None # Ray misses grid
        
    # Start point inside grid
    t_start = max(t_min, 0.0)
    start_point = ray_origin + ray_direction * t_start
    
    # 3. Initial Cell and Steps
    X = int((start_point.x - grid_min.x) / dx)
    Y = int((start_point.y - grid_min.y) / dy)
    Z = int((start_point.z - grid_min.z) / dz)
    
    # Clamp to grid bounds (should be guaranteed by t_start logic, but safe guard)
    X = max(0, min(Nx - 1, X))
    Y = max(0, min(Ny - 1, Y))
    Z = max(0, min(Nz - 1, Z))
    
    stepX = 1 if ray_direction.x > 0 else (-1 if ray_direction.x < 0 else 0)
    stepY = 1 if ray_direction.y > 0 else (-1 if ray_direction.y < 0 else 0)
    stepZ = 1 if ray_direction.z > 0 else (-1 if ray_direction.z < 0 else 0)
    
    # 4. Initial tMax and tDelta
    if ray_direction.x != 0:
        if ray_direction.x > 0:
            tMaxX = ((X + 1) * dx + grid_min.x - start_point.x) / ray_direction.x
        else:
            tMaxX = (X * dx + grid_min.x - start_point.x) / ray_direction.x
        tDeltaX = dx / abs(ray_direction.x)
    else:
        tMaxX = float('inf')
        tDeltaX = float('inf')
        
    if ray_direction.y != 0:
        if ray_direction.y > 0:
            tMaxY = ((Y + 1) * dy + grid_min.y - start_point.y) / ray_direction.y
        else:
            tMaxY = (Y * dy + grid_min.y - start_point.y) / ray_direction.y
        tDeltaY = dy / abs(ray_direction.y)
    else:
        tMaxY = float('inf')
        tDeltaY = float('inf')
        
    if ray_direction.z != 0:
        if ray_direction.z > 0:
            tMaxZ = ((Z + 1) * dz + grid_min.z - start_point.z) / ray_direction.z
        else:
            tMaxZ = (Z * dz + grid_min.z - start_point.z) / ray_direction.z
        tDeltaZ = dz / abs(ray_direction.z)
    else:
        tMaxZ = float('inf')
        tDeltaZ = float('inf')
        
    # 5. Traversal Loop
    while 0 <= X < Nx and 0 <= Y < Ny and 0 <= Z < Nz:
        # Process primitives in current cell
        cell_idx = X + Y * Nx + Z * Nx * Ny
        primitives = grid_array[cell_idx]
        
        if primitives is not None:
            for prim in primitives:
                # Check if prim already tested for this ray (Mailbox optimization)
                if not prim.is_tested_for(ray_id):
                    hit = prim.intersect(ray_origin, ray_direction)
                    if hit is not None:
                        # Verify hit is within current cell extent along ray?
                        # Simplified: return first hit found, or track closest
                        # For correctness with spanning primitives, one might need to 
                        # continue if hit.t > tMax of current cell boundary?
                        # Standard implementation often returns first valid hit or 
                        # continues to find closest.
                        prim.mark_tested_for(ray_id)
                        return hit
        
        # Advance to next cell
        if tMaxX < tMaxY:
            if tMaxX < tMaxZ:
                X += stepX
                tMaxX += tDeltaX
            else:
                Z += stepZ
                tMaxZ += tDeltaZ
        else:
            if tMaxY < tMaxZ:
                Y += stepY
                tMaxY += tDeltaY
            else:
                Z += stepZ
                tMaxZ += tDeltaZ
                
    return None
```

**Parameters:**
- **Grid Resolution ($N_x, N_y, N_z$):** Determines the number of cells. A common heuristic is to set the number of voxels proportional to the number of objects, but with a high density for performance [S2, unofficial].
- **Voxel Density ($D$):** Ratio of voxels to objects. $D=1.0$ (1 voxel per object) is generally inefficient [S2, unofficial]. "Uniform Grid Customary" uses $D=20.0$ [S2, unofficial].
- **Cubic Voxels:** To optimize for uniform ray directions, voxels should be as cubic as possible. If the scene bounding box is not cubic, use different $N_x, N_y, N_z$ such that $dx \approx dy \approx dz$ [S2, unofficial][S3].

**Edge Cases and Pitfalls:**
- **Primitives Spanning Multiple Cells:** A primitive may be stored in multiple cells. Testing it in every cell it touches leads to redundant intersection tests [S4, S5, unofficial]. Use a "Mailbox" system (ray ID caching) to skip already-tested primitives [S6, unofficial].
- **Intersection Outside Current Cell:** A ray may intersect a primitive stored in cell $F$ at a point that lies in cell $G$. Testing only cell $F$ might miss the hit or return a false positive if not checked against cell bounds [S1, S6, unofficial]. The algorithm must ensure the intersection point is valid relative to the traversal order or continue to subsequent cells [S1, unofficial].
- **Ray Origin Outside Grid:** The ray must be clipped to the grid's AABB before traversal begins. If the ray misses the grid entirely, traversal terminates immediately [S1, S5, unofficial].
- **Zero Direction Component:** If a ray direction component is zero, $tDelta$ and $tMax$ for that axis become infinite, and the step direction is 0, effectively freezing traversal along that axis [S1, unofficial].

## Subtopics

### [Regular-Grid Mesh Intersection](15512-regular-grid-mesh-intersection.md)
Computes intersections between a ray and a regular-grid mesh of size $P \times P \times P$ with $O(P)$ complexity. It exploits the structured topology to limit the search space, enabling efficient quadrature for neural field rendering.

## Operating characteristics
- **Time Complexity:**
    - **Build:** $O(N + V)$, where $N$ is the number of primitives and $V$ is the number of voxels ($N_x N_y N_z$). Building is linear with respect to primitives and grid size, allowing interactive updates for dynamic scenes [S3].
    - **Traversal:** $O(K)$, where $K$ is the number of cells traversed by the ray. In the worst case (ray passes through all cells), it is $O(N_x + N_y + N_z)$.
- **Memory Complexity:** $O(N_x N_y N_z + N)$. Memory usage is high for sparse scenes because the grid is uniform and cannot adapt to primitive density. Many voxels may be empty, wasting memory [S5, unofficial].
- **Measured Performance:** On a Pentium II 350 MHz, for the 'tree' scene (513x513 resolution, depth 4):
    - Uniform Grid ($D=1.0$): Build 0.22s, Trace 1517.0s [S2, unofficial].
    - Uniform Grid Customary ($D=20.0$): Build 0.33s, Trace 781.3s [S2, unofficial].
    - Uniform Grid Customary outperforms hierarchical grids for some scenes but uses more memory [S2, unofficial].
- **Strengths:**
    - Simple implementation [S5, unofficial].
    - Excellent data locality (successively accessed elements are spatially close) [S7, unofficial].
    - Optimal on GPU for scenes with uniform data distribution due to cached texture accesses (up to 100x faster) [S7, unofficial].
    - Fast build time suitable for dynamic scenes [S3].
- **Limitations:**
    - Poor performance in sparse scenes due to memory overhead and traversal of empty cells [S5, unofficial].
    - Not suitable for highly dynamic scenes if using acceleration structures that require pre-calculated distance info (like Proximity Clouds) [S7, unofficial].
    - Redundant intersection tests for primitives spanning multiple cells if not optimized [S4, S6, unofficial].
- **When to Use:** Scenes with uniform primitive distribution, dynamic scenes requiring frequent rebuilds, or GPU implementations where memory coalescing is critical [S2, S7, unofficial].
- **When Not to Use:** Sparse scenes, scenes with highly clustered primitives, or when memory is constrained [S5, unofficial].

## Background
The Regular Grid was introduced as a spatial subdivision technique for ray tracing [S3]. It is one of the earliest and simplest acceleration structures, often recommended for educational purposes in computer graphics courses [S4, unofficial]. The traversal algorithm is heavily based on the 3D-DDA algorithm described by Amanatides and Woo [S1, unofficial]. It has been widely used in software ray tracers and remains a foundational concept in spatial acceleration, referenced in contexts like Nvidia OptiX (though BVH is preferred there) [S4, unofficial]. Variations like "Uniform Grid Customary" were analyzed in the 1990s (e.g., Woo's GI'92 article) to optimize voxel density and shape [S2, unofficial].
