# N3-Tree

Also called: N-ary Octree, Octree / N3-Tree

## Overview
The N3-Tree is a sparse pointer octree data structure designed for GPU-based traversal, originally introduced for surface texture encoding and later adapted for volume rendering. It distinguishes itself by enforcing a strict binary state for every node: a node is either a leaf containing data values or an internal node containing pointers to exactly $N^3$ children (typically $N=2$, resulting in 8 children). This regular subdivision simplifies memory layout and reduces indirections compared to general sparse octrees, making it suitable for storing regular data bricks [S1, S2, unofficial].

## How it works
The N3-Tree represents a hierarchical grid where each internal node has exactly 8 children (for $N=2$), and leaf nodes store volumetric data. The structure is optimized for GPU fragment shader traversal using 3D textures.

### Inputs and Outputs
*   **Input:** A volumetric dataset represented as a sparse octree.
*   **Output:** Traversal state (current node, ray position) or rendered color/opacity values.

### Data Structures
The tree is stored in **RGBA 3D textures** [S1, unofficial].
*   **Internal Nodes:** The RGB channels encode pointers to child nodes. The Alpha channel is a flag indicating the node type.
*   **Leaf Nodes:** The RGB channels encode data values (e.g., density, color). The Alpha channel is a flag indicating the node type.
*   **Flag Convention:** The Alpha channel distinguishes between internal nodes and leaf nodes. Specific bit values for the flag are not detailed in the sources [S1, unofficial].

### Traversal Algorithm
Traversal is performed in a **fragment shader** [S1, unofficial]. The algorithm follows the ray through the tree, resolving pointers from internal nodes until a leaf node is reached.

1.  **Initialize:** Start at the root node. Determine the initial ray origin and direction.
2.  **Sample Node:** Read the RGBA value of the current node from the 3D texture.
3.  **Check Type:** Inspect the Alpha channel.
    *   If Alpha indicates **Leaf**:
        *   Sample the volumetric data from the RGB channels.
        *   Perform shading/compositing.
        *   Terminate traversal for this ray segment.
    *   If Alpha indicates **Internal**:
        *   Decode the child pointer from the RGB channels.
        *   Determine which of the 8 children the ray intersects.
        *   Update the current node to the child node.
        *   Update the ray's local coordinates or bounding box relative to the child.
        *   Repeat from Step 2.
4.  **Boundary Check:** If the ray exits the tree bounds, terminate.

    current_ray_local = map_ray_to_node(ray_origin, ray_direction, current_node_pos)
    
    for depth in range(max_depth):
        # Sample the current node from the 3D texture
        # RGB = pointer (internal) or value (leaf)
        # A = flag (internal vs leaf)
        node_data = texture_lookup(current_node_pos)

        if is_leaf(alpha):
            # Leaf node: extract data values from RGB
            density = node_data.rgb
            return compute_shading(density, current_ray_local)
        else:
            # Internal node: extract pointer from RGB
            # The pointer likely encodes the offset to the child node pool
            child_pointer = node_data.rgb
            
            # Determine which of the 8 children to visit
            # This requires mapping the ray's position within the current node
            # to one of the 8 sub-cubes (octants)
            child_index = get_octant_index(current_ray_local)
            
            # Calculate the position of the child node

            # in the sources [S1, unofficial]. [G] Assuming a standard linear offset or

            next_node_pos = dereference_pointer(child_pointer, child_index)

### Parameters and Edge Cases
*   **N:** The number of subdivisions per axis. Typically $N=2$ (octree). $N$ is an arbitrary integer [S1, unofficial].
*   **Precision:** Pointer encoding in RGB channels may limit the maximum tree depth or addressable memory space.
*   **Empty Space:** The structure distinguishes between internal nodes (pointers) and leaves (values). Empty space handling is not explicitly detailed, but the binary nature suggests that missing children might be represented by null pointers or specific flag values [S1, unofficial].

## Operating characteristics
*   **Memory:** Compact storage due to the regular structure. Internal nodes store only one pointer (to the first child) if children are stored successively, or 8 pointers if not. The sources note that storing 8 pointers per internal node requires the same memory as storing the first node marked as empty [S1, unofficial].
*   **Performance:** Traversal in fragment shaders benefits from deep pipelining and identical processing of fragments [S2, unofficial]. Reduced indirections improve memory locality [S2, unofficial].
*   **Limitations:** The structure is considered a special case of Kd-Trees, and specific algorithms to exploit its regularity for ray traversal acceleration are not widely proposed in the literature [S2, unofficial].

## Background
The N3-Tree was introduced by Lefebvre et al. for surface texture encoding [S1, unofficial]. It was later used by Crassin et al. for volume rendering, where internal nodes are stored in a node pool and leaf nodes in a brick pool [S1, unofficial]. Octrees and N3-trees are considered a special case of Kd-Trees, offering regular subdivision and compact storage [S2, unofficial].
