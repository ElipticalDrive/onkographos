# Hierarchical Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal accelerates volume rendering by navigating a multi-resolution grid structure (such as an Octree or Sparse Voxel Octree) where higher-level cells cover larger spatial areas (e.g., $2^k \times 2^k \times 2^k$) than lower-level cells [S1, unofficial]. This allows the renderer to take larger steps through empty space, significantly reducing the total number of intersection tests compared to non-hierarchical grid walks [S1, unofficial]. It differs from [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) and [CPU Sparse Voxel Octree Traversal](2455-cpu-sparse-voxel-octree-traversal.md) by focusing on the general algorithmic principle of hierarchical stepping rather than specific implementation details for CPU or GPU architectures, though it shares the core mechanism of [Stack-based traversal](23146-stack-based-traversal.md) [S1, S6, unofficial].

## How it works
**Inputs:**
*   Ray: Origin $o$, direction $d$ (normalized), near/far bounds $t_{min}, t_{max}$.
*   Hierarchical Grid: Root node of the tree (Octree or SVO).
*   Node Structure: Each node contains bounding box information (AABB) and child pointers/indices.

**Outputs:**
*   Sequence of leaf nodes (or active voxels) intersected by the ray, ordered by distance from the ray origin.

**Data Structures:**
*   **Stack:** Stores traversal states. Each state typically contains the node index/pointer and the ray's entry/exit distances ($t_{min}, t_{max}$) relative to the current node's bounding volume [S1, S6, unofficial].
*   **Node Layout:**
    *   **Octree/SVO Node:** Contains a bounding box and an array of 8 child indices. In SVO implementations, children may be stored in a flat array with indices, where the high bit indicates a leaf or null child [S3, unofficial].
    *   **Bounding Box:** Defined by $boxMin$ and $boxMax$ in world or local coordinates.

**Algorithm Steps:**

1.  **Initialization:**
    *   Compute the intersection of the ray with the root node's bounding box using the slab method.
    *   If no intersection, terminate.
    *   Push the root node and its intersection interval $[t_{enter}, t_{exit}]$ onto the stack.

2.  **Traversal Loop:**
    *   While the stack is not empty:
        1.  Pop the top state $(node, t_{min}, t_{max})$ from the stack.
        2.  **Ray-Node Intersection:** Verify the ray intersects the node's bounding box within $[t_{min}, t_{max}]$. If not, continue to the next state.
        3.  **Leaf Check:** If the node is a leaf:
            *   Process the leaf (e.g., sample volume data, shade, or collect for rendering).
            *   Do not push children.
        4.  **Internal Node Expansion:** If the node is internal:
            *   Identify which of the 8 children are intersected by the ray.
            *   For each intersected child, compute the new intersection interval $[t'_{min}, t'_{max}]$ clipped to the child's bounding box and the parent's interval.
            *   If a child's interval is valid (i.e., $t'_{min} < t'_{max}$ and within global bounds):
                *   Calculate the distance to the child's entry point ($t'_{min}$).
                *   Push the child node and its interval onto the stack.
            *   **Sorting:** To ensure the closest child is processed first (critical for early termination and correct compositing), children should be pushed in reverse order of their distance from the ray origin (farthest first) [S1, S6, unofficial]. Alternatively, use a priority queue if strict ordering is required, though a stack with reverse pushing is common for depth-first traversal [S3, S6, unofficial].

3.  **Backtracking:**
    *   Implicitly handled by the stack. When a subtree is exhausted, the algorithm naturally returns to the parent state stored in the stack [S1, unofficial].

**Pseudocode:**

```python
def hierarchical_traverse(ray, root_node):
    # Stack stores tuples: (node, t_min, t_max)
    stack = []
    
    # 1. Initialization
    t_enter, t_exit = slab_intersection(ray, root_node.bbox)
    if t_enter > t_exit or t_exit < ray.t_min or t_enter > ray.t_max:
        return []
    
    stack.append((root_node, max(t_enter, ray.t_min), min(t_exit, ray.t_max)))
    visited_leaves = []
    
    while stack:
        # 2. Pop state
        node, t_min, t_max = stack.pop()
        
        # 3. Leaf Check
        if node.is_leaf():
            visited_leaves.append((node, t_min, t_max))
            continue
        
        # 4. Internal Node Expansion
        children = node.children # List of 8 child nodes or indices
        
        # Identify intersected children and their intervals
        children_to_push = []
        for child in children:
            if child is None:
                continue
            
            # Compute intersection with child's bbox
            c_t_enter, c_t_exit = slab_intersection(ray, child.bbox)
            
            # Clip to parent's interval and global bounds
            c_t_min = max(c_t_enter, t_min, ray.t_min)
            c_t_max = min(c_t_exit, t_max, ray.t_max)
            
            if c_t_min < c_t_max:
                children_to_push.append((child, c_t_min, c_t_max))
        
        # Sort by entry distance (descending) to push farthest first
        # This ensures closest child is popped next
        children_to_push.sort(key=lambda x: x[1], reverse=True)
        
        for child, c_t_min, c_t_max in children_to_push:
            stack.append((child, c_t_min, c_t_max))
            
    return visited_leaves

def slab_intersection(ray, bbox):
    # Standard slab method for AABB intersection
    # Returns (t_min, t_max) of intersection interval
    # Handle zero direction components by clamping or using infinity
    t_min = -float('inf')
    t_max = float('inf')
    
    for i in range(3):
        if ray.d[i] == 0:
            if ray.o[i] < bbox.min[i] or ray.o[i] > bbox.max[i]:
                return (float('inf'), -float('inf')) # No intersection
        else:
            t1 = (bbox.min[i] - ray.o[i]) / ray.d[i]
            t2 = (bbox.max[i] - ray.o[i]) / ray.d[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
            
    return (t_min, t_max)
```

**Parameters:**
*   **Stack Size:** Depends on tree depth. For deep octrees, a fixed-size stack or linked-list based stack may be needed to prevent overflow [S6, unofficial].
*   **Termination:** Traversal can be terminated early if a specific condition is met (e.g., maximum opacity reached, or a specific object found) [S2, S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Direction Components:** The slab intersection test must handle rays parallel to axes by checking if the origin is within the slab bounds [S1, unofficial].
*   **Precision:** Floating-point errors in intersection calculations can cause gaps or overlaps between nodes. Using epsilon values or robust geometric predicates is recommended [S3, unofficial].
*   **Empty Space:** Hierarchical traversal excels at skipping empty space. If the tree is not well-constructed (e.g., many empty leaves), performance may degrade [S1, unofficial].
*   **Stack Overflow:** Deep trees can exhaust the stack. GPU implementations often use "ropes" or limited stack sizes with restart mechanisms [S6, unofficial].

### Surface Descendant Check
A method to determine if a node or its descendants contain a surface (sign change) without traversing all leaves. If the cell is a Leaf, it returns whether it has a sign change. If it is a Branch, it recursively checks if any of its children have a surface descendant. If it is Empty or Full, it returns false [S4, unofficial].

### Warp-Level Intersection Caching
An optimization for GPU traversal where intersection tests are delayed until enough threads in a warp have stored an intersection child node. When an intersection is found, the current voxel data is stored. At the start of each step, the warp checks if enough threads have stored intersections; if so, they proceed with the test. Otherwise, the warp continues traversal together. Threads that find a new intersection while already holding one stop until the next test [S8, unofficial].

### Packet Ray Traversal / Ray Coherence Optimization
Configures CUDA grids and blocks as 2D to map neighboring threads (rays) to be spatially coherent. This causes neighboring rays to traverse the octree in similar ways, improving cache hit rates. A pitfall is thread divergence in deep octree subdivisions, where neighboring rays diverge significantly, causing SIMD stalls [S9, unofficial].

### Octree Traversal with Texture Memory Access
Binds octree node data to a CUDA texture object and accesses it using `tex1Dfetch()`. Texture memory is preferred over constant memory because it supports random access patterns and has larger capacity, whereas constant memory is limited and optimized for broadcast reads [S9, unofficial].

### Bookkeeping Method
An octree traversal method inspired by Frisken & Perry (2002) that avoids starting the search from the root node for every wall passage. It maintains state to continue traversal from the last known position, reducing overhead compared to top-down methods [S10].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for sparse data, where $N$ is the number of voxels in the finest grid. In the worst case (dense data), it approaches $O(N)$, but typically performs significantly better than linear grid walks [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for the tree structure, but with a smaller constant factor for sparse data due to the SVO representation [S1, unofficial].
*   **Performance:** Hierarchical traversal can reduce the number of steps by more than half compared to non-hierarchical traversal in sparse scenes (e.g., 5 steps vs. 11 steps in an example) [S1, unofficial]. It is several times faster than other published algorithms for ray-object intersection in hierarchical structures [S5, unofficial].
*   **Strengths:** Efficiently skips empty space; adapts to data density; suitable for large, sparse datasets.
*   **Limitations:** Stack depth can be an issue for deep trees; requires careful handling of precision and boundary conditions; GPU implementations may suffer from thread divergence [S6, S9, unofficial].
*   **When to Use:** Large, sparse volume datasets; scenes with significant empty space; when memory bandwidth is a bottleneck.
*   **When Not to Use:** Dense, uniform volumes where a simple grid walk might be faster due to lower overhead; scenes with highly irregular geometry that does not fit well into a hierarchical grid.

## Background
Hierarchical traversal originated with the development of ray tracing algorithms for complex scenes. Tim Kay and James T. Kajiya introduced a hierarchy traversal algorithm in 1986 that used extents to bound objects tightly and query them in an efficient order [S5, unofficial]. The concept was later applied to volume rendering, where Octrees and Sparse Voxel Octrees (SVOs) were used to represent volumetric data at multiple resolutions [S1, unofficial]. The method is closely related to tree traversal in ray tracing and has been adapted for GPU architectures using techniques like ropes, kd-restart, and texture memory access [S6, S9, unofficial]. It is also used in scientific visualization for large-scale datasets [S6, unofficial] and in Monte Carlo radiative transfer simulations [S10].
