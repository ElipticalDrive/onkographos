# Hierarchical Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal accelerates volume rendering by navigating a multi-resolution spatial data structure (such as an Octree or Sparse Voxel Octree) instead of a uniform grid [S1, unofficial]. It solves the problem of excessive memory bandwidth and computation spent traversing empty space by allowing the ray to take larger steps at coarser levels of the hierarchy [S1, unofficial]. Unlike non-hierarchical grid walks that step voxel-by-voxel, hierarchical traversal reduces the total number of intersection tests and memory accesses by skipping large empty regions [S1, unofficial]. It builds on [Stack-based traversal](23146-stack-based-traversal.md) by using a stack to manage the tree descent, but differs from [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) in that it specifically refers to the general algorithmic approach of hierarchical stepping, often implemented via SVOs [S1, unofficial].

## How it works
**Inputs:** Ray origin $O$, ray direction $D$, and a hierarchical data structure (e.g., SVO or Octree) where each node has a bounding volume and a flag indicating if it contains active data.
**Outputs:** A sequence of leaf nodes (or active voxels) intersected by the ray, ready for sampling.

**Data Structures:**
The structure is typically a Sparse Voxel Octree (SVO) [S1, unofficial].
*   **Node Layout:** Nodes are stored in a flat array (node pool). A node contains:
    *   `is_leaf`: Boolean flag.
    *   `is_empty`: Boolean flag (if true, no children exist and no data is present).
    *   `children_offset`: Index of the first child in the node pool (if not a leaf and not empty).
    *   `data`: Pointer or index to volumetric data (if leaf) [S3, unofficial].
*   **Bounding Volumes:** Each node implicitly or explicitly defines an Axis-Aligned Bounding Box (AABB). For an SVO, the AABB of a node at level $L$ covers a spatial extent of $2^L \times 2^L \times 2^L$ voxels relative to the root [S1, unofficial].
*   **Stack:** Stores traversal states. Each state contains the node index and the ray's entry/exit distances ($t_{min}, t_{max}$) relative to the current node's bounding box [S1, 23146-stack-based-traversal.md, unofficial].

**Algorithm Steps:**
1.  **Initialization:**
    *   Compute the intersection of the ray with the root node's bounding box.
    *   If no intersection, terminate.
    *   Push the root node index and the computed $t_{min}, t_{max}$ onto the stack.

2.  **Traversal Loop:**
    *   While the stack is not empty:
        *   Pop the top state $(node\_idx, t_{min}, t_{max})$.
        *   Retrieve the node from the node pool.
        *   **Empty Check:** If the node is marked empty, continue to the next iteration (skip subtree) [S1, unofficial].
        *   **Leaf Check:** If the node is a leaf:
            *   Perform ray marching or sampling within the leaf's voxel data using $t_{min}$ and $t_{max}$ [S1, unofficial].
            *   (Optional) If early termination criteria are met (e.g., opacity threshold), stop traversal.
            *   Continue to next iteration.
        *   **Internal Node:** If the node is internal and not empty:
            *   Compute the intersection distances to the 8 children.
            *   The children's bounding boxes are sub-regions of the parent. The ray's $t_{min}$ and $t_{max}$ for each child are derived from the parent's $t$ values and the child's position within the parent [S1, unofficial].
            *   Filter children: Only consider children that intersect the ray (i.e., $t_{child\_min} < t_{child\_max}$ and $t_{child\_max} > 0$).
            *   Sort the valid children by their entry distance $t_{child\_min}$ (ascending).
            *   Push the children onto the stack in **reverse order** (farthest first) so that the closest child is popped next [23146-stack-based-traversal.md].

3.  **Termination:**
    *   The loop ends when the stack is empty or an early termination condition is met.

**Pseudocode:**
```python
def hierarchical_traversal(ray_origin, ray_direction, root_node_idx, node_pool):
    # Stack stores tuples: (node_index, t_min, t_max)
    stack = [(root_node_idx, ray_origin, ray_direction)]
    
    # Helper: Get bounding box of a node
    # For SVO, bbox is implicit based on level and position, 
    # or stored explicitly. Here we assume a function that returns bbox.
    def get_bbox(node_idx):
        return node_pool[node_idx].bbox

    # Helper: Ray-AABB intersection
    # Returns (t_min, t_max) or None if no intersection
    def ray_aabb_intersect(origin, direction, bbox):
        t_min = -float('inf')
        t_max = float('inf')
        
        for i in range(3):
            if direction[i] == 0:
                if origin[i] < bbox.min[i] or origin[i] > bbox.max[i]:
                    return None
            else:
                t1 = (bbox.min[i] - origin[i]) / direction[i]
                t2 = (bbox.max[i] - origin[i]) / direction[i]
                t_min = max(t_min, min(t1, t2))
                t_max = min(t_max, max(t1, t2))
        
        if t_min > t_max or t_max < 0:
            return None
        return (t_min, t_max)

    while stack:
        node_idx, t_min, t_max = stack.pop()
        node = node_pool[node_idx]

        # 1. Check if node is empty
        if node.is_empty:
            continue

        # 2. Check if node is leaf
        if node.is_leaf:
            # Process leaf: sample volume data
            # The actual ray segment is from t_min to t_max
            sample_volume(node.data, t_min, t_max)
            continue

        # 3. Internal node: traverse children
        children = node.get_children_indices()
        children_to_push = []

        for child_idx in children:
            child_bbox = get_bbox(child_idx)
            # Compute intersection of ray with child bbox
            # Note: t_min/t_max passed here are relative to parent, 
            # but ray_aabb_intersect expects global ray params.
            # We use the original ray origin/direction and the child's global bbox.
            # However, to optimize, we can clip t_min/t_max.
            # For simplicity, we use global ray params and filter by t_max.
            
            inter = ray_aabb_intersect(ray_origin, ray_direction, child_bbox)
            
            if inter is not None:
                c_t_min, c_t_max = inter
                # Only push if it intersects within the current ray segment
                if c_t_max > t_min:
                    children_to_push.append((child_idx, c_t_min, c_t_max))

        # Sort children by entry distance (ascending)
        children_to_push.sort(key=lambda x: x[1])

        # Push in reverse order (farthest first)
        for child in reversed(children_to_push):
            stack.append(child)
```

**Parameters:**
*   **Stack Size:** Depends on tree depth. For an SVO, depth is logarithmic with resolution [S1, unofficial].
*   **Termination Threshold:** User-defined opacity or distance limit to stop traversal early [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Ray-box intersection tests must handle zero direction components carefully to avoid division by zero [23146-stack-based-traversal.md].
*   **Boundary Conditions:** Rays passing exactly through node boundaries may cause double-counting or missed nodes if not handled consistently [S3, unofficial].
*   **Empty Nodes:** Efficiently skipping empty nodes is the primary performance gain. Failure to mark empty nodes correctly leads to unnecessary traversal [S1, unofficial].

### Surface Descendant Check
A method to determine if a node or its descendants contain a surface (sign change) without traversing all leaves [S4, unofficial].
*   **Step:** If the cell is a Leaf, return whether it has a sign change. If it is a Branch, recursively check if any of its children have a surface descendant. If it is Empty or Full, return false [S4, unofficial].

### Warp-Level Intersection Caching
An optimization for GPU traversal to delay intersection tests until warp coherence is achieved [S8, unofficial].
*   **Definition:** Delays intersection tests until enough threads in a warp have stored an intersection child node [S8, unofficial].
*   **Step:** When an intersection is found, store the current voxel intersection data. At the start of every traversal step, check if enough threads have a stored intersection. If so, proceed by doing an intersection test. Otherwise, continue traversal with the complete warp. If threads find the next intersection test while already having an intersection stored, stop traversing until the next intersection test is performed [S8, unofficial].

### Packet Ray Traversal / Ray Coherence Optimization
Optimizes GPU traversal by grouping spatially coherent rays [S9, unofficial].
*   **Step:** Configure the CUDA grid and block dimensions as 2D. Map threads such that neighboring threads (rays) are spatially coherent (similar direction), causing them to traverse the octree in similar ways, improving cache hit rates [S9, unofficial].
*   **Pitfall:** Thread Divergence: In volumetric ray tracing or deep octree subdivisions, neighboring rays may diverge significantly in their traversal paths, causing SIMD stalls [S9, unofficial].

### Octree Traversal with Texture Memory Access
Uses texture memory for random access patterns in octree traversal [S9, unofficial].
*   **Step:** Bind the octree node data to a CUDA texture object. Access node data using the `tex1Dfetch()` function, which utilizes the texture cache for random access patterns typical in tree traversal [S9, unofficial].
*   **Comparison:** Texture memory is preferred over constant memory for octree nodes because constant memory is limited in size and optimized for broadcast reads, whereas octree traversal involves random access patterns across different nodes [S9, unofficial].

### Bookkeeping Method
An octree traversal method inspired by Frisken & Perry (2002) to avoid restarting from the root [S10].
*   **Definition:** An octree traversal method designed to avoid starting the search from the root node for every wall passage [S10].
*   **Comparison:** Unlike the top-down method, it does not require starting the search from the root node for every passage through a wall [S10].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal in a balanced tree, where $N$ is the number of voxels. In practice, it is significantly faster than $O(N)$ grid walks for sparse data [S1, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the tree structure, but with a smaller constant factor for sparse data due to the SVO representation [S1, unofficial].
*   **Measured Performance:** In a comparative example, non-hierarchical traversal took 11 steps to intersect an occupied voxel, while hierarchical SVO traversal took 5 steps [S1, unofficial]. Techniques using this traversal are several times faster than non-hierarchical algorithms [S5, unofficial].
*   **Strengths:** Efficiently skips empty space; adapts to data density; reduces memory bandwidth usage.
*   **Limitations:** Requires building and maintaining the tree structure; potential for thread divergence on GPUs if rays diverge significantly [S9, unofficial].
*   **When to Use:** Sparse volumetric data; large datasets where empty space dominates; interactive rendering requirements.
*   **When Not to Use:** Dense, fully occupied volumes where the overhead of tree traversal outweighs the benefits; simple uniform grids may be faster due to lower overhead.

## Background
Hierarchical traversal originated with the development of ray tracing acceleration structures. The concept of using a hierarchy to speed up ray-object intersection was introduced by Kay and Kajiya in 1986 [S5, unofficial]. In volume rendering, it was adapted to traverse octrees and sparse voxel octrees (SVOs) to handle large, sparse datasets efficiently [S1, unofficial]. The SVO specifically stores only the highest level initially and subdivides on demand, enabling sparse storage and traversal [S1, unofficial]. The method is widely used in modern volume rendering engines and scientific visualization tools [S6, unofficial].
