# Dense 3D Texture Voxelization

Also called: Implicit Octree via Mipmaps, Dense Mipmapped 3D Texture

## Overview
Dense 3D Texture Voxelization is an alternative to GigaVoxels [S1, unofficial] where the entire scene, including empty space, is encoded into a very large mip-mapped 3D texture. It solves the problem of explicit tree traversal by making the octree implicit in the mipmap levels of the 3D texture, allowing rays to traverse the mipmap chain and index voxel data directly via world-space coordinates. Unlike GigaVoxels [3057-gigavoxels.md], which maintains a sparse octree to skip empty space, this method simplifies the design by removing the need for a separate octree structure and redundant neighbor storage, but it is generally impractical for large scenes due to the massive memory consumption of backing physical memory for empty space.

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scene defined by a volume dataset.
*   **Output:** A mip-mapped 3D texture containing the voxel data.

**Data Structures:**
*   **Mip-mapped 3D Texture:** A hierarchical set of 3D textures where each level $L$ has dimensions $(W/2^L, H/2^L, D/2^L)$. The top level represents the finest resolution, and subsequent levels represent downsampled versions. The octree structure is implicit: level $L$ corresponds to the nodes at depth $L$ of an octree covering the world space.

**Steps:**
1.  **Voxelization:** The scene is voxelized into a dense 3D grid. Every voxel in the world space, including empty regions, is assigned a value (color/density) [S1, unofficial].
2.  **Mipmap Generation:** Generate the mipmap chain. Since bricks are spatially aligned and there are no redundant neighbor voxels (unlike the amorphous memory pool of GigaVoxels), the filtering stage is straightforward [S1, unofficial]. Each mipmap level is generated by downsampling the previous level.
3.  **Ray Traversal:** For each ray, determine the starting mipmap level based on the ray's distance or the desired sampling frequency.
4.  **Sampling:** Use hardware texture sampling functions (e.g., `texture()`) to access the voxel data. The hardware automatically handles the traversal of the mipmap chain, effectively performing the octree traversal [S1, unofficial].
5.  **Interpolation:** Quadrilinear interpolation is automatically achieved by the texture hardware due to the mipmap chain and 3D texture filtering capabilities [S1, unofficial].
6.  **Indexing:** Rays index into the voxel data directly because the 3D texture serves as a world-space representation of the scene [S1, unofficial].

**Pitfalls:**
*   **Memory Consumption:** Dense 3D textures are impractical for large scenes because they consume excessive memory. The primary issue is that empty space must be backed by physical memory, which is inefficient given that most scenes are sparse [S1, unofficial].

## Subtopics

### Solid Texturing
Solid Texturing is a method for modeling various solid types where a procedural function or a 3D map models the color of objects in 3D [S2, book]. It assigns values to voxels during voxelization or evaluates the function during rendering at ray sampling locations to enrich volume datasets without increasing stored resolution [S2, book].
*   **Voxelization Phase:** Each voxel belonging to the objects is assigned a value by the texturing function or 3D map, which is then stored as part of the voxel information [S2, book].
*   **Rendering Phase:** If used to enrich a volume dataset without increasing stored resolution, the texturing function is evaluated during rendering time at the ray sampling locations [S2, book].
*   **Basis Functions:** Common functions include noise (e.g., Perlin's noise), turbulence, and n-th closest [S2, book].

## Operating characteristics
*   **Memory Complexity:** $O(N)$ where $N$ is the total number of voxels in the world space, including empty space. This is significantly higher than sparse methods like GigaVoxels [3057-gigavoxels.md] because empty space consumes physical memory [S1, unofficial].
*   **Time Complexity:** Traversal time is determined by the mipmap chain depth and sampling rate. Hardware-accelerated texture sampling and filtering provide efficient traversal and interpolation [S1, unofficial].
*   **Strengths:** Simplifies the rendering pipeline by removing the need for an explicit octree data structure and complex neighbor lookups. Quadrilinear interpolation is handled automatically by hardware [S1, unofficial].
*   **Limitations:** High memory usage makes it impractical for large, sparse scenes. It does not inherently support adaptive resolution based on scene content density, unlike sparse voxel approaches [S1, unofficial].
*   **When to use:** Suitable for small, dense scenes where memory is not a constraint and simplicity of implementation is prioritized.
*   **When not to use:** Unsuitable for large-scale, sparse scenes where memory efficiency is critical.

## Background
Dense 3D Texture Voxelization was proposed as an alternative to the GigaVoxels system [S1, unofficial]. It leverages the capabilities of modern GPUs to handle mip-mapped 3D textures and hardware filtering. The concept is discussed in the context of real-time voxel rendering, highlighting the trade-offs between explicit sparse structures and dense hardware-accelerated textures [S1, unofficial]. Solid Texturing, a related concept often used in conjunction with voxelization, has a longer history in volume graphics, with basis functions like Perlin's noise being well-established [S2, book].
