# Hierarchical Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal accelerates volume rendering by navigating a multi-resolution spatial hierarchy (such as an Octree or Sparse Voxel Octree) where each cell at a higher level covers a $2 \times 2$ area of the level below [S1, unofficial]. This allows the renderer to take larger steps at higher levels, reducing the total number of steps compared to non-hierarchical traversal [S1, unofficial]. It sets itself apart from flat grid traversal by using a resolution hierarchy, and from [BVH Traversal](18487-bounding-volume-hierarchy-bvh-traversal.md) by maintaining a strict resolution hierarchy coupled to the data structure rather than arbitrary bounding volumes [S6, unofficial].

## How it works
Hierarchical traversal builds on the stack-based principles of [Stack-based traversal](23146-stack-based-traversal.md), applying them to nodes with variable spatial extents [G].

### Inputs and Outputs
*   **Input**: A ray defined by origin $O$ and direction $D$; a hierarchical data structure (Octree/SVO) where each node has a bounding box and child pointers [S6, unofficial].
*   **Output**: A sequence of leaf nodes intersected by the ray, processed for shading or compositing [G].

### Data Structures
The hierarchy is typically stored as a linear array of nodes [S3, unofficial]. A common layout for a Sparse Voxel Octree (SVO) node packs metadata and child indices, often using bit-masking to distinguish leaves from internal nodes [S3, unofficial]. Cell naming conventions refer to the area covered at Level 0: Level 0 cells are $1\times1$, Level 1 are $2\times2$, Level 2 are $4\times4$ [S1, unofficial].

### Algorithm Steps
1.  **Initialization**: Push the root node index and the ray's entry/exit distances $[t_{min}, t_{max}]$ onto the traversal stack [G].
2.  **Loop**: While the stack is not empty:
    *   Pop the top state $(node\_idx, t_{min}, t_{max}, depth)$ [G].
    *   Retrieve the node from the data structure [G].
    *   If $depth \ge max\_depth$ or the node is a leaf, record the intersection interval and continue [G].
    *   If the node is empty, continue [G].
    *   Compute intersection intervals $[t_{child\_min}, t_{child\_max}]$ for each child using the slab method [G].
    *   Filter children where $t_{child\_max} < t_{min}$ or $t_{child\_min} > t_{max}$ [G].
    *   Sort remaining children by $t_{child\_min}$ (ascending) [G].
    *   Push children onto the stack in **reverse order** (farthest first) so the closest child is popped next [G].
3.  **Termination**: Stop when the stack is empty or a termination condition (e.g., opacity threshold) is met [S2, unofficial].

### Formulas
The ray-node intersection uses the slab method for axis-aligned bounding boxes:
$$ t_{min} = \max_i \left( \frac{boxMin_i - o_i}{d_i} \right), \quad t_{max} = \min_i \left( \frac{boxMax_i - o_i}{d_i} \right) $$
where $o$ is the ray origin, $d$ is the ray direction, and $boxMin/boxMax$ define the node's bounds [S1, S6, unofficial]. Zero direction components must be handled by checking if the ray origin lies outside the slab bounds, returning an empty intersection if so [G].

### Parameters and Edge Cases
*   **Termination**: A termination object (e.g., max depth, opacity threshold) stops traversal early [S2, unofficial]. The termination object must be convex [S2, unofficial].
*   **Precision**: Zero direction components in ray-box intersection require explicit handling to avoid division by zero; if $d_i = 0$, the ray is parallel to the slab, and intersection fails if $o_i$ falls outside $[boxMin_i, boxMax_i]$ [G].
*   **Stack Depth**: Deep hierarchies can cause large stack usage; GPU implementations often use ropes or short-stack techniques to limit memory [S6, unofficial].

### Pseudocode
```python
def intersect_aabb(o, d, box_min, box_max):
    t_min = -float('inf')
    t_max = float('inf')
    for i in range(3):
        if d[i] == 0.0:
            if o[i] < box_min[i] or o[i] > box_max[i]:
                return float('inf'), -float('inf')
        else:
            t1 = (box_min[i] - o[i]) / d[i]
            t2 = (box_max[i] - o[i]) / d[i]
            t_min = max(t_min, min(t1, t2))
            t_max = min(t_max, max(t1, t2))
    return t_min, t_max

def hierarchical_traverse(ray_origin, ray_dir, root_node, max_depth, t_max):
    stack = [(root_node.index, 0.0, t_max, 0)]
    visited = []

    while stack:
        node_idx, t_min, t_max, depth = stack.pop()
        node = root_node.children[node_idx]

        if depth >= max_depth or node.is_leaf:
            visited.append((node_idx, t_min, t_max))
            continue

        if node.is_empty:
            continue

        children_to_push = []
        for child_idx in node.children_indices:
            child = root_node.children[child_idx]
            t_child_min, t_child_max = intersect_aabb(ray_origin, ray_dir, child.bbox_min, child.bbox_max)

            if t_child_max > t_min and t_child_min < t_max:
                children_to_push.append((child.index, t_child_min, t_child_max))

        children_to_push.sort(key=lambda x: x[1])

        for child_idx, c_t_min, c_t_max in reversed(children_to_push):
            stack.append((child_idx, c_t_min, c_t_max, depth + 1))

    return visited
```

### Surface Descendant Check
An optimization for isosurface extraction where the traversal checks if a node or its descendants contain a sign change in the scalar field [S4, unofficial]. If the cell is a leaf, it returns whether it has a sign change [S4, unofficial]. If it is a branch, it recursively checks if any of its children have a surface descendant [S4, unofficial]. If it is empty or full, it returns false, allowing the traversal to skip the entire subtree [S4, unofficial].

### Warp-Level Intersection Caching
A GPU optimization that delays intersection tests until enough threads in a warp have stored an intersection child node [S8, unofficial]. When an intersection is found, the voxel intersection data is stored [S8, unofficial]. At the start of every traversal step, the warp checks if enough threads have a stored intersection; if so, they proceed with the test [S8, unofficial]. Otherwise, the warp continues traversing together [S8, unofficial]. Threads that find the next intersection test while already having an intersection stored stop traversing until the next intersection test is performed [S8, unofficial].

### Packet Ray Traversal / Ray Coherence Optimization
Configures CUDA grids and block dimensions as 2D to map threads such that neighboring threads (rays) are spatially coherent (similar direction), causing them to traverse the octree in similar ways and improving cache hit rates [S9, unofficial]. A known pitfall is thread divergence in deep octree subdivisions, causing SIMD stalls on GPU architecture [S9, unofficial].

### Octree Traversal with Texture Memory Access
Binds octree node data to a CUDA texture object and accesses node data using the `tex1Dfetch()` function, which utilizes the texture cache for random access patterns typical in tree traversal [S9, unofficial]. Texture memory is preferred over constant memory because constant memory is limited in size and optimized for broadcast reads, whereas octree traversal involves random access patterns across different nodes [S9, unofficial].

### Bookkeeping Method
An octree traversal method inspired by Frisken & Perry (2002), designed to avoid starting the search from the root node for every wall passage [S10]. Unlike the top-down method, it does not require starting the search from the root node for every passage through a wall, reducing computational overhead [S10].

## Operating characteristics
*   **Time Complexity**: $O(\log N)$ for sparse data, where $N$ is the number of voxels, compared to $O(N)$ for dense grids [G]. The number of steps is significantly reduced; e.g., 5 steps for SVO vs. 11 for non-hierarchical in comparable examples [S1, unofficial].
*   **Memory Complexity**: Depends on the structure [G]. SVOs store only occupied nodes, offering significant space savings for sparse data [S1, unofficial]. However, pointer overhead exists.
*   **Performance**: Several times faster than non-hierarchical algorithms [S5, unofficial].
*   **Strengths**: Efficient for sparse volumes; adaptive resolution; reduces overdraw.
*   **Limitations**: Stack depth can be large for deep trees; pointer chasing can cause cache misses on CPU; thread divergence on GPU [S9, unofficial].
*   **When to use**: Sparse volumetric data, multi-resolution datasets, isosurface extraction [G].
*   **When not to use**: Dense, fully occupied volumes where grid traversal is simpler and faster; hardware with limited stack size (requires stackless variants) [G].

## Background
Hierarchical traversal originated with the development of ray tracing acceleration structures [S5, unofficial]. Kay and Kajiya (1986) introduced a hierarchy traversal algorithm for ray-object intersection, demonstrating significant speedups [S5, unofficial]. In volume rendering, the concept was adapted to Octrees and Sparse Voxel Octrees (SVOs) to handle large, sparse datasets efficiently [S1, unofficial]. The technique is used for volume rendering octrees or kd-trees, similar to tree traversal in ray tracing [S6, unofficial].
