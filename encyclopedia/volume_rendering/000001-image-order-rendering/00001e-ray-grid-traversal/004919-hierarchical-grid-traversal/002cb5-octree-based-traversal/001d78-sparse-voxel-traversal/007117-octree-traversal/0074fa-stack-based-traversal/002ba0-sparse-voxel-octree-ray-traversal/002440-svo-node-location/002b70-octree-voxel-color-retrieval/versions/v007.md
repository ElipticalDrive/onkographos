# Octree Voxel Color Retrieval

Also called: Color Lookup with Shading, Voxel Lighting and Color Retrieval, lookupColor

## Overview
Octree Voxel Color Retrieval computes the final color of a voxel hit by a ray by retrieving stored color and normal data from a Sparse Voxel Octree (SVO) and applying a directional lighting model. It builds on [SVO Node Location](3249-svo-node-location.md) to locate the leaf node, then navigates the tree structure to fetch the associated color and normal vectors. It differs from [Octree Node Lookup by Voxel](5120-octree-node-lookup-by-voxel.md) by explicitly integrating lighting calculations (ambient and diffuse) into the retrieval process rather than just returning raw voxel data.

## How it works
The method retrieves the color of a voxel from the octree data structure, applying lighting if the renderer is not in shadeless mode. It navigates the tree to find the leaf node containing the color and normal data, then computes the final pixel color.

### Inputs and Outputs
- **Inputs**:
  - Ray origin and direction (3D or 4D depending on implementation).
  - SVO data structure (array of integers/floats representing nodes and leaf data).
  - Light parameters: direction vector, ambient strength, light color.
  - Camera/Render context: resolution ($n_x, n_y$), frustum width, pixel radius.
  - Flags: `shadeless` (boolean/int), `max_level` (integer).
- **Outputs**:
  - Final color (RGB) and alpha (1.0) for the pixel.
  - Stored in a texture array or buffer.

### Data Structures
1. **Octree Data Array**: A contiguous array of integers (`uint` or `int`) storing node headers, block info, and leaf data.
   - **Node Header**: Contains pointers to child nodes or leaf data offsets.
   - **Block Info**: Metadata for memory management or attachment.
   - **Leaf Data**: Stores color (RGB) and normal (XYZ) components.
2. **Traversal State**:
   - `node`: Current node index in the octree data array.
   - `level`: Current depth in the octree.
   - `cidx`: Child index within the current node.
   - `pageHeader`, `blockInfo`, `attachData`: Intermediate pointers/offsets for memory access.
3. **Color/Normal Storage**:
   - **Color**: Stored as 8-bit integers (RGB) or normalized floats.
   - **Normal**: Stored as 8-bit integers (signed, range -128 to 127) or normalized floats.

### Steps
1. **Initialize Traversal State**:
   - Convert 3D ray to 4D ray if using 4D SVO: `Ray4D::convertRayTo4D(ray3D, time_point, 0.0)`.
   - Initialize traverser: `Tree4DTraverserDifferentSides` with tree and 4D ray.
   - Get initial hit information from [SVO Node Location](3249-svo-node-location.md):
     - `px = floatBitsToInt(castRes.pos.x)`
     - `node = castRes.node`
     - `cidx = castRes.childIdx`
     - `level = castRes.scale`

2. **Calculate Memory Offsets**:
   - `pageHeader = node & 0xFFFFF800`
   - `blockInfo = pageHeader + octree.data[pageHeader]`
   - `attachData = int(blockInfo) + ubo.blockInfoEnd`
   - `paletteNode = octree.data[attachData + int(node) - renderList.offsets[index] / 4 - 1]`

3. **Traverse to Leaf with Data**:
   - Loop while traversal is not terminated AND no data leaf found AND node is not too small AND max level not reached:
     ```python
     while not terminated and not data_leaf_found and not node_too_small and not reached_max_level:
         # Check if current node is a leaf with data
         if tree_traverser.get_current_node().is_leaf() and tree_traverser.get_current_node().has_data():
             data_leaf_found = True
             break
         
         # If node has no color (internal node), navigate to child
         while (int(palette_node >> cidx) & 1) != 1:
             level += 1
             # Check bounds, update node, cidx, pageHeader, blockInfo, attachData, paletteNode
             # Specific update logic depends on SVO layout (e.g., bit-shifting, pointer arithmetic)
             pass
         
         # Check termination conditions
         if tree_traverser.stack_TraversalInfo_about_Node4Ds.size() >= max_level:
             reached_max_level = True
         
         projected_size = tree_traverser.get_projected_size_of_current_node(t_pixel)
         if projected_size <= pixel_size:
             node_too_small = True
         
         if not data_leaf_found and not reached_max_level and not node_too_small:
             tree_traverser.step()
     ```

4. **Retrieve Voxel Data**:
   - If `data_leaf_found`:
     - Calculate attach offset: `attachOffset = attachData + int(paletteNode >> 8) + bitCount(paletteNode & (1 << cidx) - 1)`
     - Get color component: `c = int(octree.data[attachOffset])`
     - Extract RGB: `r = (c >> 16) & 0xFF`, `g = (c >> 8) & 0xFF`, `b = c & 0xFF`
     - Normalize color: `octreeColor = vec3(r / 255.0, g / 255.0, b / 255.0)`
     - Retrieve normal: `normal = tree->data_ptrs[tree_traverser.get_current_node().data]->normal`
     - Normalize normal: `normal = normalize(normal)`

5. **Apply Lighting**:
   - If `shadeless` is true:
     - Return `vec4(octreeColor, 1.0)`
   - Else:
     - Load transformation matrix to convert normal to world space:
       - `offset = int(renderList.offsets[index] + ubo.pageBytes) / 4 - ubo.transformCount * 4`
       - Read 16 floats into `v[]`, construct `mat4 octreeToWorld`
       - `hitNormalWorld = normalize(octreeToWorld * vec4(castRes.normal, 0.0))`
     - Calculate lighting:
       - `ambient = ubo.ambientStrength * vec3(ubo.lightColor)`
       - `lightDir = normalize(vec3(ubo.lightPos))`
       - `diffuse = max(dot(hitNormalWorld, lightDir), 0.0) * vec3(ubo.lightColor)`
       - `finalColor = (ambient + diffuse) * octreeColor`

6. **Store Result**:
   - Store RGB values and alpha=1 into texture array:
     - `texture_array[index] = (unsigned char)r`
     - `texture_array[index+1] = (unsigned char)g`
     - `texture_array[index+2] = (unsigned char)b`
     - `texture_array[index+3] = (unsigned char)1`

### Formulas
- **Brightness/Lighting**:
  $$ \text{brightness} = \frac{\arccos\left( \frac{N_x}{128.0} L_x + \frac{N_y}{128.0} L_y + \frac{N_z}{128.0} L_z \right)}{\pi} $$
  Where $N$ is the voxel normal (stored as 8-bit integers divided by 128) and $L$ is the light direction [S1, unofficial].

- **Normal to Color Conversion (for storage)**:
  $$ R = 255 \times \frac{\text{normal}[0] + 1.0f}{2.0f} $$
  $$ G = 255 \times \frac{\text{normal}[1] + 1.0f}{2.0f} $$
  $$ B = 255 \times \frac{\text{normal}[2] + 1.0f}{2.0f} $$
  Maps normal components from $[-1, 1]$ to $[0, 255]$ for RGB storage [S3, unofficial].

### Parameters
- **Light Direction**: Example: `{-0.039030f, -0.866792f, 0.497139f}` [S1, unofficial].
- **Pixel Size**: Threshold for node projected size. Calculated as `pixel_radius * pixel_radius` where `pixel_radius = 0.5 * (frustum_width / rc.n_x)` [S3, unofficial].
- **Max Level**: Maximum depth of the tree to traverse. Static member variable `LODColorTree4DRenderer::max_level` [S3, unofficial].
- **Max Stack Size**: Maximum possible stack depth, calculated as `log(size) / log(2) + 1` where `size = max(tree->gridsize_T, tree->gridsize_S)` [S3, unofficial].

### Edge Cases and Pitfalls
- **Precision**: Normal storage as 8-bit integers introduces quantization error. Division by 128.0 in lighting calculation must be precise.
- **Boundaries**: Ensure `cidx` and `level` updates in the traversal loop do not exceed array bounds or tree depth.
- **Degenerate Input**: Empty octrees or rays missing the volume entirely must be handled by the traversal termination condition.
- **Shadeless Mode**: If `shadeless` is true, lighting calculations are skipped, and raw color is returned.

## Subtopics

### Hierarchical Octree Voxel Coloring
A variant that starts with a low-resolution voxel structure and refines it to higher resolutions. This approach speeds up reconstruction by processing coarse data first. It requires approximately 15 seconds to generate a reconstruction with 3,256 voxels [S4, unofficial]. Unlike uniform resolution methods, it introduces a perceptual saliency component to represent information hierarchically [S4, unofficial].

## Operating characteristics
- **Time Complexity**: Depends on tree depth and traversal path. Hierarchical variants reduce time by processing coarse levels first [S4, unofficial].
- **Memory Complexity**: Proportional to the number of nodes in the SVO. Leaf data storage (color/normal) adds overhead.
- **Performance**: Hierarchical method takes ~15s for 3,256 voxels [S4, unofficial].
- **Strengths**: Efficient for large sparse volumes; integrates lighting directly into retrieval.
- **Limitations**: Quantization error in normal storage; dependency on SVO layout for efficient traversal.
- **When to Use**: Real-time rendering of sparse voxel volumes with lighting requirements.
- **When Not to Use**: When high-precision normals are required without post-processing; when uniform resolution is sufficient and simpler.

## Background
The method originates from implementations of Sparse Voxel Octree renderers, such as those found in [S1, S2, S3, unofficial]. The hierarchical variant was proposed by Prock and Dyer [S4, unofficial] to speed up voxel coloring by refining resolutions incrementally. It is used in real-time volume rendering applications where lighting and shading are required for visual fidelity.
