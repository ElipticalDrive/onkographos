# Iterative Up-Down Tree Traversal

Also called: Iterative ascent-descent traversal, Up-Down method

## Overview
Iterative Up-Down Tree Traversal is a hierarchical ray traversal algorithm for octrees that determines the next node by locally analyzing the current node's position relative to its parent, avoiding the overhead of restarting the search from the root for every step [S1]. It distinguishes itself from the [Two-Pass Hierarchy Traversal](3339-two-pass-hierarchy-traversal.md) by maintaining a single continuous traversal state that dynamically ascends and descends the tree based on whether a ray exit constitutes an "internal transition" (exiting a child but remaining within the parent) or an "external transition" (exiting the parent) [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A ray $R(t) = O + tD$; the root of an octree $\mathcal{T}$; the current node $N$ (initially the root or the first leaf entered); the current entry parameter $t_{entry}$ and exit parameter $t_{exit}$ for the current node's bounding volume.
- **Output:** The next leaf node $L$ to be processed, and updated $t_{entry}, t_{exit}$ for $L$.

**Data Structures:**
- **Octree Node:** Contains a bounding box (AABB), a flag indicating if it is a leaf, and pointers to up to 8 children.
- **Ray-Node Intersection:** A function `intersect(ray, node)` returning the smallest $t > 0$ where the ray enters the node's AABB, or $\infty$ if no intersection.

**Algorithm Steps:**
1. **Calculate Exit:** Determine the exit parameter $t_{exit}$ of the current ray within the current node $N$'s bounding box.
2. **Identify Next Cell Wall:** Determine which face of the current node's bounding box the ray exits through. Let this be face $F$.
3. **Check Internal Transition:** Determine if the adjacent cell sharing face $F$ is a sibling of $N$ or a child of $N$'s parent.
    - An **Internal Transition** occurs if the ray exits $N$ but remains within the bounding volume of $N$'s parent $P$. This happens if $N$ is not the root and the ray does not exit $P$'s bounds at the same time it exits $N$'s bounds, or more precisely, if the next cell is a sibling or a child of a sibling.
    - Specifically, if $N$ has a sibling $S$ across face $F$, and $S$ is not a leaf, the next node is $S$ (or its children). If $S$ is a leaf, the next node is $S$.
    - If the transition is **not internal** (i.e., the ray exits the parent $P$'s bounds), the algorithm must ascend.
4. **Ascent Phase:**
    - While the transition is not internal:
        - Move to the parent of the current node $N \leftarrow \text{parent}(N)$.
        - Recalculate the exit face relative to the new current node.
        - If the current node is the root and the ray still exits, terminate traversal (ray has left the volume).
5. **Descent Phase:**
    - Once an internal transition is identified (the ray exits the current node but remains within its parent's bounds, or we are at a node where the next cell is a sibling/child):
        - Identify the target sibling or child across the exit face.
        - If the target is a leaf, set it as the next node.
        - If the target is an internal node, descend iteratively:
            - From the target node, determine which child the ray enters next.
            - Repeat until a leaf node is reached.
6. **Update State:** Set the current node to the found leaf. Update $t_{entry}$ to the previous $t_{exit}$ (clamped to 0 if negative due to precision) and calculate the new $t_{exit}$ for the leaf.

**Pseudocode:**
```python
def iterative_up_down_traversal(ray, current_node, t_entry, t_exit):
    """
    Traverses an octree using the iterative up-down method.
    Returns the next leaf node and its exit parameter.
    """
    node = current_node
    
    while True:
        # 1. Determine exit face and parameter for current node
        t_exit_local, exit_face = ray_exit_info(ray, node)
        
        # If ray exits the current node's bounds
        if t_exit_local <= t_entry:
            # Precision guard: if t_exit is very close to t_entry, 
            # it might be the same cell or a degenerate case.
            # In practice, we proceed to find the next cell.
            pass
        
        # 2. Check if the transition is internal
        # Internal means: the ray exits 'node' but stays within 'node.parent'
        # Or, more generally, the next cell is a sibling or child of the current hierarchy level.
        
        is_internal = False
        next_node_candidate = None
        
        # Case A: Current node has a sibling across the exit face
        if node.parent is not None:
            sibling = get_sibling(node, exit_face)
            if sibling is not None:
                # The next cell is the sibling
                next_node_candidate = sibling
                # Is it internal? Yes, because sibling is within parent's bounds
                is_internal = True
            else:
                # No sibling (boundary of parent), must ascend
                is_internal = False
        else:
            # Root node has no parent. If we exit, we are done or need to check global bounds.
            # Assuming the root covers the entire volume of interest.
            return None, float('inf') # Ray left the volume

        if is_internal:
            # 3. Descent Phase
            # We have identified the next node (sibling or child).
            # If it is a leaf, we are done.
            if next_node_candidate.is_leaf:
                current_node = next_node_candidate
                t_entry = t_exit_local
                t_exit = calculate_exit_for_node(ray, current_node)
                return current_node, t_exit
            
            # If it is not a leaf, we must descend to the next leaf
            current_node = next_node_candidate
            while not current_node.is_leaf:
                # Find which child the ray enters
                child_index = get_child_index(ray, current_node)
                current_node = current_node.children[child_index]
            
            t_entry = t_exit_local
            t_exit = calculate_exit_for_node(ray, current_node)
            return current_node, t_exit
        
        else:
            # 4. Ascent Phase
            # The transition is not internal. Move up.
            if node.parent is None:
                return None, float('inf') # Left the root
            
            node = node.parent
            # Note: t_entry for the parent is effectively the old t_entry,
            # but we are looking for the *next* leaf after the current exit.
            # The ascent logic relies on the fact that we are now looking for
            # a node that is a sibling of an ancestor or higher up.
            # We do not update t_entry here; we keep the original exit point
            # as the reference for the next intersection test in the new context.
            # However, strictly speaking, the ray has passed the exit point.
            # The next intersection will be > t_exit_local.
```

**Parameters and Edge Cases:**
- **Implementation Complexity:** High. It requires maintaining parent pointers and carefully distinguishing between internal and external transitions [S1].
- **Memory Overhead:** None. It uses no additional memory structures beyond the tree itself [S1].
- **Precision:** Care must be taken when $t_{exit}$ is very close to $t_{entry}$ to avoid infinite loops or skipping cells [G].
- **Degenerate Input:** If the ray grazes a face, the exit face determination must be robust.

## Operating characteristics
- **Time Complexity:** Average case is $O(1)$ per voxel transition, similar to standard grid traversal, but with higher constant factors due to parent pointer dereferencing and ascent/descent logic. Worst case is $O(D)$ where $D$ is the depth of the tree, if the ray traverses a path requiring frequent ascents and descents.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Strengths:** No memory overhead; avoids the $O(D)$ cost of restarting from the root for every step, which is beneficial for sparse octrees where many transitions are between siblings [S1].
- **Limitations:** Higher implementation complexity compared to simple top-down or two-pass methods [S1].

## Background
This method was proposed in the context of Monte Carlo radiative transfer simulations using hierarchical octrees [S1]. It was introduced as an alternative to the standard top-down method (which restarts from the root) and the two-pass method, aiming to balance performance and implementation simplicity [S1]. It is applicable to both regular and barycentric octree grids [S1].
