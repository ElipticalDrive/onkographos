# Ray Tracing with BVH and Möller–Trumbore

Also called: Pure ray tracing, Wald BVH Traversal (Occlusion/Shadow), occluded

## Overview
A rendering method using a PackedBVH over triangles, traversed with ray-box slab tests for pruning, and Möller–Trumbore tests for triangle intersections [S1, unofficial]. It is used to determine if a ray is occluded by any triangle (shadow ray), returning true on the first hit [S2, unofficial]. It sets itself apart from sphere tracing by providing exact sharp CSG surfaces and from hybrid methods by relying entirely on ray-primitive intersection rather than marching [S1, unofficial].

## How it works
**Inputs:** Ray origin $O$, ray direction $D$, BVH root node, current maximum intersection distance $t_{max}$ (often initialized to infinity or a scene bound).
**Outputs:** Boolean indicating occlusion (true if hit found), or intersection distance/normal if extended.

**Data Structures:**
*   **PackedBVH:** A binary tree stored in a linear array. Internal nodes contain an AABB (Axis-Aligned Bounding Box) and indices/offsets to children. Leaves contain an array of triangles (`TriangleSoA`).
*   **AABB:** Defined by min and max vectors ($b_{min}, b_{max}$).
*   **TriangleSoA:** Structure of Arrays for triangles, storing vertex positions $v_0, v_1, v_2$ and potentially normals.
*   **Stack:** A fixed-size array or dynamic list used for iterative traversal.

**Steps:**
1.  **Initialization:** Compute the reciprocal ray direction $r_{dir} = 1/D$. Initialize the traversal stack with the BVH root node. Set the current node to the root.
2.  **Traversal Loop:** While the stack is not empty:
    a.  Pop the top node from the stack.
    b.  **Pruning:** Perform a ray-box slab intersection test against the current node's AABB. If the ray does not intersect the box within $[0, t_{max}]$, prune this branch (continue to next stack item).
    c.  **Leaf Check:** If the node is a leaf:
        i.  If it is a triangle leaf, iterate through all triangles in the leaf.
        ii. For each triangle, perform the Möller–Trumbore ray-triangle intersection test.
        iii. If an intersection is found at distance $t < t_{max}$, update $t_{max} = t$ and return true (for occlusion queries) or store the hit data.
    d.  **Internal Node:** If the node is internal:
        i.  Identify the near and far children based on the ray's entry/exit distances into the children's AABBs.
        ii. Push the far child to the stack.
        iii. Set the current node to the near child and continue the loop (process near child immediately).
3.  **Termination:** If the stack is empty and no hit was found, return false.

**Möller–Trumbore Formula:**
For a ray $R(t) = O + tD$ and a triangle with vertices $v_0, v_1, v_2$:
Let $E_1 = v_1 - v_0$, $E_2 = v_2 - v_0$, $H = D \times E_2$, $S = O - v_0$.
Compute determinant $det = E_1 \cdot H$.
If $det$ is close to zero, the ray is parallel to the triangle.
Otherwise, compute $t = (S \cdot H) / det$.
If $t < 0$ or $t > t_{max}$, no valid intersection.
Compute $u = (S \times E_1) \cdot D / det$.
If $u < 0$ or $u > 1$, no valid intersection.
Compute $v = (O \cdot E_2) / det$ [G]. (Note: Standard derivation uses $v = (E_2 \cdot (S \times E_1)) / det$ or similar; source [S1, unofficial] mentions "Möller–Trumbore" but does not provide the explicit formula. The standard formula is provided here as [G] to ensure implementability, as the source implies standard usage).
If $v < 0$ or $u + v > 1$, no valid intersection.
Otherwise, intersection at $t$.

**Parameters:**
*   $t_{max}$: Typically scene bounding box diagonal or infinity for primary rays.
*   Stack size: Depends on BVH depth. Not given in the sources.

**Edge Cases:**
*   **Parallel Rays:** If $det \approx 0$, the ray is parallel to the triangle plane. Handle by skipping or using a epsilon threshold.
*   **Degenerate Triangles:** Triangles with zero area may cause division by zero or incorrect barycentric coordinates. [G] Check for degenerate triangles or rely on BVH culling.
*   **Precision:** Slab tests and Möller–Trumbore are sensitive to floating-point precision. Use epsilon for comparisons.

**Pseudocode:**
```python
def ray_triangle_intersection(O, D, v0, v1, v2, t_max):
    E1 = v1 - v0
    E2 = v2 - v0
    H = cross(D, E2)
    S = O - v0
    det = dot(E1, H)
    
    if abs(det) < 1e-8:
        return None  # Parallel
    
    inv_det = 1.0 / det
    t = dot(S, H) * inv_det
    
    if t < 0.0 or t > t_max:
        return None
    
    u = dot(S, cross(E1, D)) * inv_det
    if u < 0.0 or u > 1.0:
        return None
    
    v = dot(D, cross(E2, S)) * inv_det  # [G] Standard formula
    if v < 0.0 or u + v > 1.0:
        return None
    
    return t

def slab_intersect(ray_origin, ray_dir_recip, box_min, box_max, t_max):
    tmin = (box_min - ray_origin) * ray_dir_recip
    tmax = (box_max - ray_origin) * ray_dir_recip
    t1 = min(tmin, tmax)
    t2 = max(tmin, tmax)
    t_near = max(t1)
    t_far = min(t2)
    
    if t_near > t_far or t_far < 0.0 or t_near > t_max:
        return False
    return True

def traverse_bvh(ray_origin, ray_dir, bvh_root, t_max):
    r_dir_recip = 1.0 / ray_dir
    stack = [bvh_root]
    
    while stack:
        node = stack.pop()
        
        if not slab_intersect(ray_origin, r_dir_recip, node.box_min, node.box_max, t_max):
            continue
            
        if node.is_leaf():
            for tri in node.triangles:
                t_hit = ray_triangle_intersection(ray_origin, ray_dir, tri.v0, tri.v1, tri.v2, t_max)
                if t_hit is not None:
                    return True  # Occlusion found
        else:
            # Push far child, process near child
            # Determine near/far based on slab test results or precomputed order
            # For simplicity, assume children are ordered [near, far]
            far_child = node.children[1]
            near_child = node.children[0]
            
            stack.append(far_child)
            stack.append(near_child)
            
    return False
```

## Subtopics

### Mesh BVH
Optimized for mesh data, potentially using different leaf structures or traversal strategies. Choose when dealing with large static meshes. [Link](1062-mesh-bvh.md)

### Initial Upper Bound Estimation
Uses a coarse bound to quickly reject rays. Choose when scene has large empty spaces. [Link](15442-initial-upper-bound-estimation.md)

### Ray Packet BVH Traversal
Processes multiple rays simultaneously for SIMD efficiency. Choose for GPU or SIMD-heavy CPU implementations. [Link](21088-ray-packet-bvh-traversal.md)

## Operating characteristics
*   **Time Complexity:** $O(N \log M)$ on average, where $N$ is the number of rays and $M$ is the number of triangles. Worst case $O(N \cdot M)$ for degenerate BVHs.
*   **Memory Complexity:** $O(M)$ for the BVH structure.
*   **Performance:** Pure ray tracing achieves ~1.1 billion primary rays/s and ~1.3 billion rays/s with shadows/AO on RTX 3080 Ti [S1, unofficial].
*   **Strengths:** Exact intersections, sharp CSG support, no marching errors.
*   **Limitations:** Slower than sphere tracing for smooth SDFs, sensitive to BVH quality.
*   **When to use:** When exact geometry is required, or for shadow rays.
*   **When not to use:** For smooth SDFs where sphere tracing is faster, or for very large scenes with poor BVH construction.

## Background
Originated from the need for exact ray-triangle intersection in software ray tracers. The method is described in the context of "EBGeometry" and "Visualization: sphere-traced rendering of shapes and tapes" [S1, unofficial]. It is used in interactive viewers for sharp CSG rendering.
