# Sequential Access via Bit Mask Iteration

Also called: Bit Mask Iterator, Compact Mask Traversal

## Overview
Sequential Access via Bit Mask Iteration is an access pattern that iterates over active voxels or nodes by scanning the compact `mChildMask` and `mValueMask` bitmasks embedded in each node, outperforming random access for algorithms invariant to voxel sequence [S1, unofficial]. It sets itself apart from sibling methods like [Flat Rank](10397-flat-rank.md) by leveraging the physical memory layout of the bitmasks themselves to achieve cache-friendly traversal, whereas flat rank focuses on constant-time rank queries on bit vectors. Unlike [DT-Grid](../dt-grid.md) or [H-RLE](../h-rle.md) which offer $O(1)$ sequential access but $O(\log[\text{topology}])$ random lookup, this method provides $O(1)$ complexity for both random and sequential access [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A node containing two 32-bit bitmasks, `mChildMask` and `mValueMask`, and a starting bit `offset` (global or local index).
*   **Output:** The linear offset (bit index) of the next set bit in the mask starting from `offset`.

**Data Structures:**
*   `mChildMask`: A 32-bit integer where each bit represents the existence of a child node in the corresponding octree child slot.
*   `mValueMask`: A 32-bit integer where each bit represents the presence of an active value (e.g., density, color) in the corresponding leaf voxel slot.
*   `DeBruijn`: A static lookup table with 32 entries mapping unique upper five bits of a power-of-two result to its bit position.

**Algorithm Steps:**
1.  **Locate the next active value or child node** by iterating over the `mChildMask` and `mValueMask` bitmasks in each node [S1, unofficial].
2.  **Compute the linear offset** to the next set bit in a mask `mMask` starting from `offset` using the following logic:
    *   Determine the 32-bit word index `n` and the bit position `m` within that word:
        $$ n = \text{offset} \gg 5 $$
        $$ m = \text{offset} \& 31 $$
    *   Load the word `b` from the mask at index `n`:
        $$ b = \text{mMask}[n] $$
    *   **Trivial Case:** If the bit at `m` is already set, return `offset`.
    *   **Mask Lower Bits:** Clear all bits in `b` at positions less than `m` to ignore previously visited bits in the current word:
        $$ b = b \ \& \ (0\text{xFFFFFFFF} \ll m) $$
    *   **Find Next Non-Zero Word:** If `b` is zero, increment `n` and load the next word until a non-zero word is found.
    *   **Isolate Lowest Set Bit:** Use the expression `b & -b` to isolate the lowest set bit in `b`.
    *   **De Bruijn Lookup:** Multiply the isolated bit by the de Bruijn constant `0x077CB531U`. Shift the result right by 27 bits to extract the unique upper five bits. Use these bits to index the `DeBruijn` table to find the bit position relative to the start of the word.
    *   **Calculate Final Offset:** Combine the word index `n` and the bit position from the lookup to return the final linear offset.

**Pseudocode:**
```python
# DeBruijn is a static list of 32 integers mapping bit positions
# Constant for de Bruijn sequence multiplication
DEBRUIJN_CONSTANT = 0x077CB531

def next_set_bit(mMask: list[int], offset: int) -> int:
    """
    Computes the linear offset to the next set bit in mMask starting from offset.
    mMask is a list of 32-bit integers representing the bit vector.
    """
    # 1. Determine word index and bit position within the word
    n = offset >> 5
    m = offset & 31
    
    # 2. Load the current 32-bit word
    b = mMask[n]
    
    # 3. Trivial case: if the current bit is set, return it
    if b & (1 << m):
        return offset
        
    # 4. Mask out lower bits (bits < m) in the current word
    # 0xFFFFFFFF is 32 ones. Shifting left by m clears bits 0..m-1
    b = b & (0xFFFFFFFF << m)
    
    # 5. Find the next non-zero 32-bit word
    while b == 0:
        n += 1
        b = mMask[n]
        
    # 6. Isolate the lowest set bit using two's complement trick
    # b & -b leaves only the lowest 1-bit set
    lowest_bit = b & -b
    
    # 7. De Bruijn multiplication to map the power of two to a unique index
    # Multiplication by 0x077CB531U makes the upper 5 bits unique for each power of 2
    # >> 27 isolates these upper 5 bits
    index = (lowest_bit * DEBRUIJN_CONSTANT) >> 27
    
    # 8. Lookup the bit position from the static table
    bit_pos = DeBruijn[index]
    
    # 9. Calculate final linear offset
    return (n << 5) + bit_pos
```

**Parameters:**
*   `DeBruijn`: A static table with 32 entries. The exact values are not provided in the sources, but the table maps the unique upper five bits of a power-of-two result to its bit position [S1, unofficial].
*   `0x077CB531U`: The hex representation of the 32-bit de Bruijn sequence [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Branching:** The De Bruijn lookup computes the lowest bit position without branching (conditionals), which is critical for performance on modern CPUs [S1, unofficial].
*   **Boundary Conditions:** The algorithm assumes `mMask` has sufficient words allocated. If `offset` points beyond the allocated mask, the `while` loop may access out-of-bounds memory. [G] In practice, a check for `n` exceeding the mask size should be added.
*   **Zero Mask:** If the entire mask is zero, the `while` loop will eventually access invalid memory. [G] A check for `b == 0` after the loop should return an error or sentinel value.

## Subtopics

### Direct Access Bit Masks
Bit masks embedded in nodes providing fast, compact direct access to binary topology. Used for: (1) hierarchical topology encoding, (2) fast sequential iterators, (3) lossless compression, (4) boolean operations, (5) topology dilation [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for both sequential and random access [S1, unofficial].
*   **Memory Complexity:** The bitmasks are compact (32 bits per node level), making them cache-friendly compared to larger direct access tables like `mInternalDAT` and `mLeafDAT` [S1, unofficial].
*   **Performance:** Outperforms random access for algorithms invariant to voxel sequence, such as time-dependent simulations (level set propagation, fluid advection) [S1, unofficial].
*   **Strengths:** Cache-friendly, branchless bit position calculation, supports multiple levels of iteration (voxels, tiles, leaf nodes) [S1, unofficial].
*   **Limitations:** Requires the data structure to embed bitmasks in every node. Not suitable for algorithms that require specific ordering other than the physical memory layout.
*   **Comparison:** VDB achieves $O(1)$ for both random and sequential access. DT-Grid/H-RLE achieve $O(1)$ for sequential but $O(\log[\text{topology}])$ for random lookup [S1, unofficial].

## Background
Originated in the VDB (Voxel Database) system, developed by Ken Museth et al. at DreamWorks Animation. The method was introduced in the paper "VDB: High-Resolution Sparse Volumes with Dynamic Topology" (TOG 2013, Academy Award Winner) [S1, unofficial]. It was designed to support dynamic sparse data structures for fluids, narrow-band level sets, and volumetric modeling, where fast sequential access is critical for performance [S1, unofficial].
