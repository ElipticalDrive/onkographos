# Bounding Volume Hierarchy (BVH) Traversal

Also called: BVH for Triangle Traversal, Bounding Volume Hierarchy, GPU BVH Traversal, Iterative BVH Traversal

## Overview
Bounding Volume Hierarchy (BVH) traversal accelerates ray-scene intersection and distance queries by traversing a binary tree of bounding volumes to skip empty space by construction [S1, unofficial]. It is distinguished from hierarchical grid methods (like Octree Traversal) by operating directly on unstructured geometry (e.g., triangle meshes) rather than voxelized volumes, and from software-only BVHs by leveraging hardware acceleration (e.g., NVIDIA OptiX) for ray-triangle intersections [S3, unofficial][S4, unofficial].

## How it works
**Inputs and outputs:** Ray origin $O$, ray direction $D$, flattened BVH node array, primitive array, and maximum traversal distance $t_{max}$ [G]. The method outputs the closest intersection distance $t_{hit}$ and the corresponding primitive ID [G].

**Data structures:** A flat array of nodes where each node stores bounding box extents (min/max vectors), child indices for internal nodes, or primitive counts and indices for leaves [S2, unofficial][S5]. Primitives are stored in a contiguous buffer [S2, unofficial].

**Numbered steps:**
1. Initialize an explicit stack in thread-local memory with the root node index [S2, unofficial].
2. While the stack is non-empty, pop the top node index [S2, unofficial].
3. Perform a ray-AABB intersection test against the node's bounding box [S1, unofficial].
4. If the ray misses the box or the intersection distance exceeds $t_{hit}$, prune the node and continue to the next iteration [S1, unofficial].
5. If the node is a leaf, compute exact primitive intersections using slab or Möller–Trumbore tests, updating $t_{hit}$ if a closer hit is found [S1, unofficial][G].
6. If the node is internal, compute distances to both children, push them onto the stack in order of increasing distance, and repeat [S2, unofficial].

**Formulas:** Ray-AABB slab intersection for axis $i$: $t_{1,i} = \frac{\min_i - O_i}{D_i}$, $t_{2,i} = \frac{\max_i - O_i}{D_i}$, $t_{min} = \max_i(\min(t_{1,i}, t_{2,i}))$, $t_{max} = \min_i(\max(t_{1,i}, t_{2,i}))$ [G]. The node is pruned if $t_{max} < 0$ or $t_{min} > t_{hit}$ [S1, unofficial].

**Parameters:** $t_{max}$ is typically set to the scene bounding sphere radius; thread-local stack capacity is usually 64–128 entries to prevent overflow [G].

**Edge cases and pitfalls:** Degenerate rays with zero direction components require component-wise handling to avoid division by zero [G]. Empty BVHs return immediately. The iterative stack design explicitly avoids GPU call-stack overflows and recursion overhead [S2, unofficial].

```python
def traverse_bvh(ray_origin, ray_direction, bvh_nodes, primitives, max_t):
    stack = [0]
    closest_t = max_t
    hit_id = -1
    while stack:
        node_idx = stack.pop()
        node = bvh_nodes[node_idx]
        # Ray-AABB slab test [G]
        inv_dir = 1.0 / ray_direction
        t1 = (node.min - ray_origin) * inv_dir
        t2 = (node.max - ray_origin) * inv_dir
        t_min = max(min(t1, t2))
        t_max = min(max(t1, t2))
        if t_max < 0 or t_min > closest_t:
            continue
        if node.is_leaf:
            for prim_idx in node.primitive_indices:
                t = ray_triangle_intersect(ray_origin, ray_direction, primitives[prim_idx])
                if 0 < t < closest_t:
                    closest_t = t
                    hit_id = prim_idx
        else:
            left = bvh_nodes[node.left_idx]
            right = bvh_nodes[node.right_idx]
            inv_dir_l = 1.0 / ray_direction
            t1_l = (left.min - ray_origin) * inv_dir_l
            t2_l = (left.max - ray_origin) * inv_dir_l
            t_min_l = max(min(t1_l, t2_l))
            inv_dir_r = 1.0 / ray_direction
            t1_r = (right.min - ray_origin) * inv_dir_r
            t2_r = (right.max - ray_origin) * inv_dir_r
            t_min_r = max(min(t1_r, t2_r))
            if t_min_l < t_min_r:
                stack.append(node.right_idx)
                stack.append(node.left_idx)
            else:
                stack.append(node.left_idx)
                stack.append(node.right_idx)
    return closest_t, hit_id
```

## Subtopics

### [Mesh BVH](1062-mesh-bvh.md)
Mesh BVH is a GPU-accelerated BVH designed for triangle meshes to support efficient distance queries, signed distance field (SDF) computation, and ray intersection tests. It is distinguished from hierarchical grid methods by operating on unstructured triangle geometry and from software-only BVHs by leveraging NVIDIA OptiX hardware acceleration. Choose this for SDF computation or collision detection on complex meshes.

### [IRIS Ray-Geometry Intersection](3250-iris-ray-geometry-intersection.md)
IRIS Ray-Geometry Intersection is an intersection-aware ray-based sampling method for implicit editable scenes that determines samples as the maximum response points of Gaussians intersected by each ray. It sets itself apart from standard BVH traversal by using OptiX Any-hit shaders to directly compute intersection parameters for Gaussian primitives represented as affine-transformed icosahedrons, accumulating results in a bounded hit buffer. Choose this for implicit editable scenes with Gaussian primitives.

### [Multi-Hit BVH Traversal](12728-multi-hit-bvh-traversal.md)
Multi-Hit BVH Traversal is a technique to determine the $N$ closest intersections of a viewing ray with compound clip objects to construct clip intervals for volume rendering. It sets itself apart from all-hit queries by using a preallocated static array to avoid costly dynamic memory reallocation, which is essential for real-time implementation. Choose this when constructing clip intervals without multiple rendering passes.

### [Initial Upper Bound Estimation](15442-initial-upper-bound-estimation.md)
Initial Upper Bound Estimation computes a tight initial upper bound to prune BVH-tree traversal during distance field computation for isosurface approximation. It differs from standard hierarchical traversal by proactively sampling the approximated surface to establish a pruning threshold before traversal begins, rather than waiting for the first leaf encounter. Choose this when traversing BVHs for isosurface distance fields to reduce node visits.

### [Ray Tracing with BVH and Möller–Trumbore](19369-ray-tracing-with-bvh-and-m-ller-trumbore.md)
A rendering method using a PackedBVH over triangles, traversed with ray-box slab tests for pruning, and Möller–Trumbore tests for triangle intersections. It is used to determine if a ray is occluded by any triangle (shadow ray), returning true on the first hit. It sets itself apart from sphere tracing by providing exact sharp CSG surfaces and from hybrid methods by relying entirely on ray-primitive intersection rather than marching. Choose this for exact shadow ray occlusion testing.

### [BVH Traversal for Closest Point](19482-bvh-traversal-for-closest-point.md)
This method performs a recursive traversal of a Bounding Volume Hierarchy (BVH) to find the triangle closest to a specific query point. It differs from ray-based traversal methods by computing Euclidean distance rather than ray intersection, and from Mesh BVH by focusing on point-to-primitive distance rather than mesh-level collision detection. Choose this for point-to-mesh distance queries.

### [Ray Packet BVH Traversal](21088-ray-packet-bvh-traversal.md)
Ray Packet BVH Traversal traverses a Wald-ordered Bounding Volume Hierarchy (BVH) for a packet of rays to find the closest intersection for each active ray in the packet. It differs from single-ray traversal by processing multiple rays simultaneously, allowing for batched culling and intersection tests, which improves throughput on SIMD architectures. Choose this for high-throughput primary or shadow ray batches.

### Coarse Mesh Traversal via BVH
Uses a BVH built over a coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point [S3, unofficial]. Build a triangle BVH over the coarse mesh by inserting four triangular faces facing outside for every coarse element [S3, unofficial]. Trace rays into the BVH using OptiX Wrapper Library (OWL) hit and miss functions [S3, unofficial]. The hit function returns the hit point and the coarse tetrahedron ID [S3, unofficial]. The miss function reports no intersection with BVH faces [S3, unofficial]. Trace two rays: one with front-face culling and one with back-face culling [S3, unofficial]. If the front-culling ray misses, the point is outside the coarse mesh [S3, unofficial]. If the back-culling ray misses, the point is inside the last intersected element [S3, unofficial]. Unlike element marching which uses connectivity, point location querying skips coarse elements not being sampled and allows varying refinement levels in the coarse mesh [S3, unofficial].

### BVH-based UDF evaluation with analytic gradient
Computes the unsigned distance from query points to a triangle mesh using a BVH, and provides an analytic gradient for backpropagation [S4, unofficial]. Flatten input $x$ to $[N, 3]$. Query BVH for distance $udf$, triangle ID $tri\_id$, and barycentric coordinates $uvw$ [S4, unofficial]. Clamp $uvw$ to $[1e-9, 1-1e-9]$. Interpolate nearest point on triangle using $uvw$ and triangle vertices [S4, unofficial]. Return $udf$ reshaped to input shape [S4, unofficial]. In backward pass, retrieve saved $x$ and nearest points [S4, unofficial]. Compute $diff = x - nearest\_points$. Compute $norm = diff.norm(dim=-1, keepdim=True) + 1e-8$ [S4, unofficial]. Gradient is $grad\_output$ scaled by $diff/norm$ [S4, unofficial]. Formula: $\nabla_x \text{UDF}(x) = \frac{x - p_{\text{nearest}}}{\|x - p_{\text{nearest}}\|}$ where $p_{\text{nearest}}$ is the closest point on the mesh [S4, unofficial]. Input $x$ shape $[N, 3]$. Output $udf$ shape $[N, 1]$. Saved tensors: $x\_flat$, $nearest\_points$ [S4, unofficial]. Pitfall: $uvw$ is clamped to $[1e-9, 1-1e-9]$ to avoid invalid barycentric coordinates at triangle edges/corners [S4, unofficial].

### DOP-14 Separated Layout
A layout optimization for Discrete Oriented Polytopes (DOP-14) where the 14 bounding planes are split into two separate arrays to improve traversal performance by enabling independent memory access patterns [S5]. First check the AABB planes of the bounding volume (planes 0-2) during traversal [S5]. Only test planes 3–6 if warranted by the result of the initial AABB plane check [S5]. The BVHd type defines an Interior node with two children and a Leaf node with primitive count and data [S5]. The layout groups fields $lo1$, $hi1$, $c0$, $c1$ (planes 0-2) in one array, and $lo2$, $hi2$ (planes 3-6) in a separate array [S5]. Separates the logical bounding volume specification (which planes comprise a DOP-14) from the physical organization (which planes are co-located in memory), facilitating exploration of alternative representations [S5].

## Operating characteristics
Time complexity averages $O(N \log M)$ for $N$ rays and $M$ primitives, degrading to $O(N \cdot M)$ in worst-case degenerate scenes [G]. Memory footprint is dominated by the flat node and primitive arrays, which enables coalesced memory access and avoids pointer-chasing overhead on GPUs [S2, unofficial]. Strengths include skipping empty space by construction, hardware acceleration support via OptiX, and iterative stack traversal that prevents GPU call-stack overflows [S1, unofficial][S2, unofficial]. Limitations include the loss of flat CSR layouts, build-time overhead for tree construction, and per-thread stack management costs [S1, unofficial][S2, unofficial]. Use this method when scene geometry is unstructured or triangle-based; avoid it when a pre-existing hierarchical grid or stride-based walk is already optimal for the data layout [S1, unofficial].

## Background
BVH traversal for point location and distance queries in volume rendering contexts has been applied to tetrahedral adaptive mesh refinement (TET-AMR) data to locate coarse elements efficiently [S3, unofficial]. The approach allows renderers to skip elements not being sampled and supports varying refinement levels in the coarse mesh [S3, unofficial]. Implementation often utilizes NVIDIA OptiX for hardware-accelerated ray-triangle intersection tests [S3, unofficial]. The method has also been adapted for unsigned distance field (UDF) computation and analytic gradient backpropagation on triangle meshes [S4, unofficial].
