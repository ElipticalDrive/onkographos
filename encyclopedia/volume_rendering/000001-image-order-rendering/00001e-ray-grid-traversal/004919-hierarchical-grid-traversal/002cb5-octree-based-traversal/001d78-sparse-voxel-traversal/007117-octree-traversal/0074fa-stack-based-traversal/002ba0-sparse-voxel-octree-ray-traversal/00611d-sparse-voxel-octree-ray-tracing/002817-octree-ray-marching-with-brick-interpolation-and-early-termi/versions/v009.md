# Octree Ray Marching with Brick Interpolation and Early Termination

Also called: Brick-based SVO Ray Marching, GigaVoxels-style Ray Traversal

## Overview
This method performs volume rendering on a Sparse Voxel Octree (SVO) by traversing the tree structure and sampling data stored in "bricks" (small, fixed-size blocks of voxels) rather than individual leaf voxels [S1, unofficial]. It solves the problem of inefficient memory access and cache thrashing in large-volume rendering by grouping data into bricks, which improves texture cache utilization and reduces traversal overhead compared to single-voxel stepping [S1, unofficial]. It sets itself apart from sibling methods like [SVO Ray Marching with Stack-Based Navigation](2454-svo-ray-marching-with-stack-based-navigation.md) by explicitly handling interpolation between bricks of different resolutions and using early termination based on accumulated opacity to skip empty space, whereas [Octree Voxel Raycasting for Hover (Closest Active Voxel)](3219-octree-voxel-raycasting-for-hover-closest-active-voxel.md) focuses on finding the nearest surface rather than full volume integration [G].

## How it works
**Inputs:**
- Ray origin $O$ and direction $D$ in world coordinates [G].
- SVO root node pointer [S1, unofficial].
- Volume bounding box extents $V_{min}$ and $V_{max}$ [S1, unofficial].
- Projected voxel size $projVoxelSize$ [S1, unofficial].
- Parent voxel size $parentVoxelSize$ [S1, unofficial].
- Brick dimensions and border sizes [S1, unofficial].
- Maximum nodes to push per frame $MaxNodesToPushThisFrame$ and reset threshold $maxNodesPerPixelBlock$ [S1, unofficial].

**Outputs:**
- Final color $C$ and opacity $\alpha$ for the pixel [G].
- Updated node usage statistics for asynchronous brick loading [S1, unofficial].

**Data Structures:**
- **Octree Node:** Contains a pointer to the next node in the hierarchy, a pointer to the brick data (if leaf), and metadata (depth, size) [G].
- **Brick Data:** A 3D texture or buffer containing color and optionally gradient values for a block of voxels [S1, unofficial].
- **Node Usage List:** A queue of recently traversed nodes used to trigger asynchronous GPU upload of their brick data [S1, unofficial].

**Parameters:**
- $projVoxelSize$: Projected voxel size in world units. Used for interpolation ratio [S1, unofficial].
- $parentVoxelSize$: Voxel size at the parent octree level. Used in interpolation denominator [S1, unofficial].
- $k_{ChildNodeSizeScalar}$: Scalar multiplier applied to $nodeSize$ and $voxelHalfSize$ on each descent step (typically 0.5 for octrees) [S1, unofficial].
- $MaxNodesToPushThisFrame$: Maximum number of nodes allowed to be pushed to the usage list per frame [S1, unofficial].
- $maxNodesPerPixelBlock$: Threshold for $nodeListTraversalCount$ before it resets to 0 [S1, unofficial].
- $startPushingNodes$, $stopPushingNodes$: Implementation-specific thresholds defining the window for node list management [G].

**Algorithm Steps:**

1.  **Initialization:**
    - Set current node $N$ to root.
    - Set current extents $E_{min} = V_{min}$, $E_{max} = V_{max}$ [S1, unofficial].
    - Set current node size $S = 1.0$ [S1, unofficial].
    - Set voxel half-size $h = RootVoxelHalfSize$ [S1, unofficial].
    - Reset traversal counters: $traversalCount = 0$, $nodeListTraversalCount = 0$ [G].
    - Initialize accumulated color $C = (0,0,0,0)$ and transmittance $T = 1.0$ [G].

2.  **Ray-Volume Intersection Test:**
    - Compute containment:
      $$ test1 = \text{sign}(O - V_{min}) $$
      $$ test2 = \text{sign}(V_{max} - O) $$
      $$ inside = \text{dot}(test1, test2) $$
    - If $inside < 3$, the ray origin is outside the volume bounding box [S1, unofficial]. Handle entry point calculation or terminate if the ray does not intersect the bounding box [G].

3.  **Traversal Loop:**
    While $T > \epsilon$ and $N$ is valid:
    
    a. **Increment Counters:**
       $$ traversalCount \leftarrow traversalCount + 1 $$
       $$ nodeListTraversalCount \leftarrow nodeListTraversalCount + 1 $$
       If $nodeListTraversalCount \ge maxNodesPerPixelBlock$, reset $nodeListTraversalCount = 0$ [S1, unofficial].

    b. **Node Management (Asynchronous Loading):**
       If $nodeListTraversalCount$ is within $[startPushingNodes, stopPushingNodes)$ and $pushedNodeCount < MaxNodesToPushThisFrame$:
       - Increment $pushedNodeCount$.
       - Call $AddToNodeUsageList(N)$. This schedules the brick data associated with $N$ for asynchronous GPU upload if not already present [S1, unofficial].

    c. **Interpolation Decision:**
       Check if interpolation is enabled:
       - Condition: $projVoxelSize > parentVoxelSize$, $curDepth \neq 0$, and interpolation factor $> 0.001$ [S1, unofficial].
       - If true, compute previous brick ray position and call **TraverseBrickInterp** [S1, unofficial].
       - Otherwise, call **TraverseBrick** [S1, unofficial].
       - *Note:* Interpolation is disabled at the root node ($curDepth == 0$) to prevent invalid ratios when $parentVoxelSize$ equals $projVoxelSize$ [S1, unofficial].

    d. **Descent (if moving to child):**
       - Compute brick offset: $brickOffset = rayBrickPosition \times k_{TreeN}$ (where $k_{TreeN}$ is the number of children, typically 8) [S1, unofficial].
       - Clamp to child index: $childOffset = \text{clamp}(\text{uvec3}(brickOffset), 0, 1)$ [S1, unofficial].
       - Update ray position within brick: $rayBrickPosition = brickOffset - vec3(childOffset)$ [S1, unofficial].
       - Update extents:
         $$ E_{min} += (vec3(childOffset) \times S) $$
         $$ E_{max} -= ((vec3(1.0) - vec3(childOffset)) \times S) $$
       - Fetch next node: $N = \text{texelFetch}(OctTreeSampler, N.ptr, 0)$ [S1, unofficial].

    e. **Brick Traversal (TraverseBrick):**
       - Sample the brick data at the current ray position [G].
       - Compute density/color $\rho, c$ [G].
       - Update transmittance: $T \leftarrow T \times (1 - \rho \cdot \Delta s)$ [G].
       - Update color: $C \leftarrow C + T \cdot c \cdot \rho \cdot \Delta s$ [G].
       - Advance ray by step size $\Delta s$ [G].

    f. **Brick Interpolation (TraverseBrickInterp):**
       - Sample surrounding bricks or interpolate within the brick based on the interpolation factor derived from $projVoxelSize$ and $parentVoxelSize$ [S1, unofficial].
       - Apply the same color/opacity accumulation as above [G].
       - *Pitfall:* Interpolation factor is clamped to $[0.0, 1.0]$ and thresholded at $0.001$ to avoid division by zero [S1, unofficial].

    g. **Early Termination:**
       - If accumulated opacity $> 0.995$ AND the current step actually traversed a brick or constant value (not empty space):
         - Terminate loop.
       - This prevents premature cutoff during initialization or in empty space [S1, unofficial].

4.  **Reset State:**
    - After ray completion, reset $N$ to root, extents, and sizes for the next ray [S1, unofficial].

**Pseudocode:**

               proj_voxel_size, parent_voxel_size, max_nodes_per_block, 
               max_nodes_per_frame, start_pushing_nodes, stop_pushing_nodes,
               k_child_node_size_scalar=0.5, k_tree_n=8):
    # Initialization [S1, unofficial]
    oct_tree_node = root_node
    extents_min = vol_min
    extents_max = vol_max
    node_size = 1.0
    voxel_half_size = 0.5  # RootVoxelHalfSize [G]
    cur_depth = 0
    ray_brick_pos = ray_origin
    ray_pos = ray_origin
    ray_dir = ray_dir / np.linalg.norm(ray_dir)
    accumulated_color = np.array([0.0, 0.0, 0.0, 0.0])
    transmittance = 1.0
    traversal_count = 0
    node_list_traversal_count = 0
    pushed_node_count = 0
    step = node_size * 0.1  # Fixed step size for brick marching [G]

    # Ray-Volume Intersection Test [S1, unofficial]
    test1 = np.sign(ray_pos - extents_min)
    test2 = np.sign(extents_max - ray_pos)
    inside = np.dot(test1, test2)
    if inside < 3.0:
        # Ray origin outside volume; compute entry point or skip [G]
        pass

    while transmittance > 0.005 and oct_tree_node is not None:
        # Increment Counters [S1, unofficial]
        traversal_count += 1
        node_list_traversal_count += 1
        if node_list_traversal_count >= max_nodes_per_block:
            node_list_traversal_count = 0

        # Node Management [S1, unofficial]
        if start_pushing_nodes <= node_list_traversal_count < stop_pushing_nodes and \
           pushed_node_count < max_nodes_per_frame:
            pushed_node_count += 1
            # AddToNodeUsageList(oct_tree_node) [G]

        # Interpolation Decision [S1, unofficial]
        interp_factor = min(max((proj_voxel_size / parent_voxel_size) - 1.0, 0.0), 1.0)
        enable_interp = (proj_voxel_size > parent_voxel_size) and (cur_depth != 0) and (interp_factor > 0.001)

        if enable_interp:
            prev_brick_ray_pos = ray_pos - ray_dir * step
            # TraverseBrickInterp logic [S1, unofficial]
            # Sample surrounding bricks or interpolate within the brick [S1, unofficial]
            density = 0.1  # Sample brick data [G]
            color = np.array([0.5, 0.5, 0.5, 1.0])  # Sample color [G]
            alpha = density * step
            transmittance *= (1.0 - alpha)
            accumulated_color += transmittance * color
            ray_pos += ray_dir * step
        else:
            # TraverseBrick logic [S1, unofficial]
            density = 0.1  # Sample brick data [G]
            color = np.array([0.5, 0.5, 0.5, 1.0])  # Sample color [G]
            alpha = density * step
            transmittance *= (1.0 - alpha)
            accumulated_color += transmittance * color
            ray_pos += ray_dir * step

        # Early Termination [S1, unofficial]
        if transmittance < 0.005 and alpha > 0.0:
            break

        # Descent Logic [S1, unofficial]
        brick_offset = ray_brick_pos * k_tree_n
        child_offset = np.clip(brick_offset.astype(int), 0, 1)
        ray_brick_pos = brick_offset - child_offset
        extents_min += child_offset * node_size
        extents_max -= (1.0 - child_offset) * node_size
        oct_tree_node = fetch_next_node(oct_tree_node, child_offset)
        node_size *= k_child_node_size_scalar
        cur_depth += 1

    return accumulated_color

## Subtopics

### Sparse Octree Raytracing Acceleration
This variant accelerates rendering by using sparse octrees to store caches, enabling raytracing to skip empty space and terminate rays missing the object [S2, unofficial]. It converts the density cache to a signed distance function (SDF) by thresholding at 0.0, optionally downsamples the SDF, and generates a collision mesh using marching cubes [S2, unofficial]. Rays are traced against the BVH of this mesh to find occupied voxels, skipping empty space efficiently [S2, unofficial]. For rays hitting occupied voxels, volume integration uses cached components [S2, unofficial]. It uses BVH/ray-triangle intersection instead of hierarchical DDA to leverage hardware acceleration, allow easy mesh deformation/downsampling, and enable compositing of fake shadows/bouncelight [S2, unofficial]. Cache resolutions are typically $1024^3$ (8 components) for NeRF Synthetic 360 scenes (except ship: $768^3$) and $768^3$ (6 components) for LLFF [S2, unofficial].

### Multi-resolution Ray-casting Rendering
This method performs volume rendering via ray-casting that traverses the octree hierarchy to skip empty space and march rays near the surface [S3]. It uses multi-resolution interpolation to handle variable resolution blocks at boundaries, avoiding complex synchronization issues [S3]. The hierarchy is traversed to skip empty space and advance the ray as close as possible to the surface [S3]. In the proximity of the surface, the ray is marched in steps proportional to the distance from the zero-crossing [S3]. At each step, the SDF field is sampled via tri-linear interpolation [S3]. The accurate 3D position of the surface is computed when the ray transitions from positive to negative space [S3].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** Improves cache coherency by accessing brick-sized blocks rather than scattered leaf voxels [S1, unofficial].
- **Strengths:** Efficient handling of large, sparse volumes; reduced memory bandwidth usage; supports dynamic transfer functions without texture regeneration (unlike some bricking techniques) [S1, unofficial].
- **Limitations:** Interpolation artifacts at brick boundaries if not handled carefully; complexity in managing asynchronous loading and node usage lists; early termination may cause visual artifacts if not tuned properly [S1, unofficial].
- **When to use:** Large-scale volume rendering where memory bandwidth is a bottleneck and the volume is sparse [S1, unofficial].
- **When not to use:** Dense volumes where brick overhead outweighs benefits, or when exact surface reconstruction is required without post-processing [G].

## Background
The method originates from the GigaVoxels project, which introduced bricking as a technique to optimize volume rendering on GPUs by grouping voxels into bricks to improve cache performance [S1, unofficial]. The specific combination of octree traversal, brick interpolation, and early termination is detailed in the VoxViz thesis, which describes the implementation of GigaVoxels in a real-time rendering context [S1, unofficial]. The technique addresses the limitations of traditional ray marching on dense textures and the overhead of pure octree traversal on leaf nodes [S1, unofficial].
