# Stackless BVH Ray Traversal for Occlusion

Also called: IntersectScene, Scene Intersection for Occlusion, IntersectSceneOcclusion, Scene Intersection with Occlusion Culling

## Overview
This method performs global scene intersection by iterating over all entities in a scene to find the first entity hit by a ray, effectively serving as an occlusion culling primitive. Unlike standard closest-hit algorithms that search for the minimum distance across all geometry, this approach returns immediately upon finding any valid intersection with an entity's BVH, prioritizing speed for visibility checks over precise depth sorting. It builds on [Stackless BVH Traversal](22227-stackless-bvh-traversal.md) by wrapping its traversal logic in a linear entity loop.

## How it works
**Inputs:**
- `RayOrigin`: The starting point of the ray.
- `RayDirection`: The normalized direction vector of the ray.
- `u_EntityCount`: The total number of entities in the scene.
- `BVHEntities`: An array or list of entity descriptors, each containing:
  - `NodeOffset`: The starting index of the BVH node array for this entity.
  - `NodeCount`: The number of nodes in the BVH for this entity.
  - `InverseMatrix`: The inverse transformation matrix for the entity's local-to-world space.
- `TMax`: The maximum search distance (default `1000000.0f`).

**Outputs:**
- `T`: The distance to the first hit along the ray. Returns `-1.0f` if no entity is hit.

**Data Structures:**
The `BVHEntities` array stores metadata for each entity. The actual BVH nodes are assumed to be stored in a contiguous global array or per-entity arrays, accessed via `NodeOffset`. The `InverseMatrix` is a $4 \times 4$ matrix used to transform the ray into the entity's local space for traversal.

**Steps:**
1. Initialize `TMax` to a large value (e.g., `1000000.0f`).
2. Iterate `i` from `0` to `u_EntityCount - 1`:
   a. Retrieve the entity descriptor `E = BVHEntities[i]`.
   b. Call the stackless BVH traversal function `IntersectBVHStacklessOcclusion` (or `IntersectBVHStackless`) with:
      - `RayOrigin`
      - `RayDirection`
      - `E.NodeOffset`
      - `E.NodeCount`
      - `E.InverseMatrix`
      - `TMax`
   c. Let `Traversal` be the result.
   d. If `Traversal > 0.0f`, return `Traversal` immediately. This is the first hit found.
3. If the loop completes without a hit, return `-1.0f`.

**Pseudocode:**
```python
def IntersectSceneOcclusion(RayOrigin, RayDirection, BVHEntities, u_EntityCount, TMax=1000000.0f):
    """
    Iterates over all entities to find the first hit for occlusion culling.
    
    Args:
        RayOrigin: vec3, origin of the ray.
        RayDirection: vec3, normalized direction of the ray.
        BVHEntities: list of dicts, each with 'NodeOffset', 'NodeCount', 'InverseMatrix'.
        u_EntityCount: int, number of entities.
        TMax: float, maximum intersection distance.
        
    Returns:
        float: Distance to first hit, or -1.0f if no hit.
    """
    for i in range(u_EntityCount):
        entity = BVHEntities[i]
        
        # Call the underlying stackless BVH traversal for this specific entity
        # Note: IntersectBVHStacklessOcclusion is assumed to be defined in the parent article
        # or available as a primitive. It returns the distance to the closest hit within
        # the entity's BVH, or -1.0f if no hit.
        hit_distance = IntersectBVHStacklessOcclusion(
            RayOrigin,
            RayDirection,
            entity['NodeOffset'],
            entity['NodeCount'],
            entity['InverseMatrix'],
            TMax
        )
        
        # If any entity is hit, return immediately (first hit wins)
        if hit_distance > 0.0f:
            return hit_distance
            
    # No entity was hit
    return -1.0f
```

**Parameters:**
- `TMax`: Default `1000000.0f`. Controls the maximum distance for intersection tests.

**Edge Cases and Pitfalls:**
- **Order Dependency:** The result depends on the order of entities in `BVHEntities`. The first entity in the list that intersects the ray will be returned, regardless of whether a later entity is closer. This is intentional for occlusion culling but incorrect for shading.
- **No Hit:** Returns `-1.0f` if no entity is hit. Callers must check for this value.
- **Precision:** Standard floating-point precision applies. Degenerate rays (zero length) should be handled by the caller or the underlying BVH traversal.

## Subtopics

### Stackless BVH Traversal
The core traversal algorithm used for each entity. It uses a linear pointer-based approach to avoid stack allocation, making it suitable for GPU execution. [Stackless BVH Traversal](22227-stackless-bvh-traversal.md)

### BVH Traversal for Closest Point
A variant that finds the absolute closest hit across all geometry, not just the first entity hit. [BVH Traversal for Closest Point](22228-bvh-traversal-for-closest-point.md)

### BVH Ray Traversal with Stack
The traditional recursive traversal method that uses an explicit stack. Less suitable for GPU due to stack depth limits. [BVH Ray Traversal with Stack](22229-bvh-ray-traversal-with-stack.md)

## Operating characteristics
- **Time Complexity:** $O(N \cdot H)$, where $N$ is the number of entities and $H$ is the average height of the BVH for each entity. In the worst case, it traverses the entire BVH of every entity until a hit is found.
- **Memory Complexity:** $O(1)$ auxiliary space, as it relies on the stackless traversal of the parent method.
- **Strengths:** Extremely fast for occlusion culling when the first entity hit is likely to be the occluder. No need to sort hits by distance.
- **Limitations:** Not suitable for shading or accurate depth testing, as it does not guarantee the closest hit. Performance degrades if the first entity in the list is not hit and many entities must be checked.
- **When to Use:** Visibility checks, frustum culling, or any scenario where determining if *any* geometry blocks a ray is sufficient.
- **When Not to Use:** Shading, shadow ray tracing, or any application requiring the precise closest intersection point.

## Background
This method is derived from the `IntersectSceneOcclusion` function found in the `VolumetricDisplay` project by swr06. It is designed for real-time rendering applications where occlusion culling is needed to reduce overdraw or skip expensive shading calculations for hidden surfaces. The approach leverages the efficiency of stackless BVH traversal to minimize overhead per entity.
