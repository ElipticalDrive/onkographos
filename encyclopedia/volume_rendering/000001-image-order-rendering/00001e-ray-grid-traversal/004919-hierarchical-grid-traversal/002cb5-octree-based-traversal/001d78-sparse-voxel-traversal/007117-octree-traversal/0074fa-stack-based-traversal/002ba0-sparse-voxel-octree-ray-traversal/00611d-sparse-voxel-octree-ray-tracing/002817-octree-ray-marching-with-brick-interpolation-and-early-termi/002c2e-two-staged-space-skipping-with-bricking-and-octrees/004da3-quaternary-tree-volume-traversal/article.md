# Quaternary Tree Volume Traversal

Also called: CPU-GPU Split Volume Rendering, Tile-based Ray Casting

## Overview
Quaternary Tree Volume Traversal is a two-stage rasterization process distributed between a central processor and a graphics processing unit [S1]. The CPU divides object space using a quaternary tree to find intersections, and the GPU performs ray casting and shading [S1].

## How it works
**Inputs:**
- An implicit function defining the object surface [S1].
- Camera parameters, with the GPU ray direction fixed along the Z-axis [S1].
- A target tile size parameter that terminates the CPU subdivision [S1].

**Outputs:**
- A rendered image with smooth shading and lighting [S1].
- Z-coordinates and surface normals for each pixel [S1].

**Data Structures:**
- **Quaternary Tree:** Each node represents a square region in the XY plane and branches into four children corresponding to the quadrants of the parent region [S1].
- **Fragment List:** A list of geometric primitives generated by the CPU, containing the bounding boxes of tiles where the object intersects the volume [S1].

**Algorithm Steps:**
1. CPU: Divide the current cube region into four equal parts in the XY plane [S1].
2. CPU: Test each part for intersection with the object [S1].
3. CPU: If a part does not intersect the object, neglect it; if it intersects, repeat the division procedure on that part [S1].
4. CPU: Stop recursion when the current part corresponds to a tile of the predefined size [S1].
5. CPU: Generate a list of fragments representing the geometric objects intersecting with the tiles [S1].
6. GPU: Feed the fragment list to the GPU input [S1].
7. GPU: For each pixel, test the relevant fragment for intersection with a ray directed along the Z-axis [S1].
8. GPU: Perform a binary search along the ray to find the nearest intersection point, defined as the first point where the object function vanishes [S1].
9. GPU: Determine the z-coordinate and surface normal for each pixel [S1].
10. GPU: Apply a local lighting model using the coordinates and normals to compute the final pixel color [S1].

```python
class Region:
    def __init__(self, x_min, x_max, y_min, y_max, z_min, z_max):
        self.x_min, self.x_max = x_min, x_max
        self.y_min, self.y_max = y_min, y_max
        self.z_min, self.z_max = z_min, z_max

class Fragment:
    def __init__(self, region):
        self.region = region

def intersects_object(region):
    # [G] The source does not specify the exact intersection test; 
    # this implements a standard axis-aligned bounding box check against a fixed object bounds.
    obj_min, obj_max = 0.0, 1.0
    return (region.x_min < obj_max and region.x_max > obj_min and
            region.y_min < obj_max and region.y_max > obj_min and
            region.z_min < obj_max and region.z_max > obj_min)

def build_quaternary_tree(region, tile_size):
    fragments = []
    if (region.x_max - region.x_min < tile_size and 
        region.y_max - region.y_min < tile_size):
        if intersects_object(region):
            fragments.append(Fragment(region))
        return fragments
    mid_x = (region.x_min + region.x_max) / 2
    mid_y = (region.y_min + region.y_max) / 2
    quadrants = [
        Region(region.x_min, mid_x, region.y_min, mid_y, region.z_min, region.z_max),
        Region(mid_x, region.x_max, region.y_min, mid_y, region.z_min, region.z_max),
        Region(region.x_min, mid_x, mid_y, region.y_max, region.z_min, region.z_max),
        Region(mid_x, region.x_max, mid_y, region.y_max, region.z_min, region.z_max)
    ]
    for quad in quadrants:
        if intersects_object(quad):
            fragments.extend(build_quaternary_tree(quad, tile_size))
    return fragments

def evaluate_scalar_field(point):
    # [G] Placeholder for the implicit surface function f(x,y,z)
    return point.z - 0.5

def binary_search_intersection(origin, direction, fragment):
    z_low = fragment.region.z_min
    z_high = fragment.region.z_max
    max_iterations = 32
    epsilon = 1e-4
    for _ in range(max_iterations):
        z_mid = (z_low + z_high) / 2
        point = (origin[0] + direction[0] * z_mid,
                 origin[1] + direction[1] * z_mid,
                 z_mid)
        value = evaluate_scalar_field(point)
        if abs(value) < epsilon:
            return z_mid
        if value > 0:
            z_high = z_mid
        else:
            z_low = z_mid
    return None

def calculate_normal(point):
    # [G] Approximate normal using central finite differences
    h = 1e-5
    dx = evaluate_scalar_field((point[0]+h, point[1], point[2])) - evaluate_scalar_field((point[0]-h, point[1], point[2]))
    dy = evaluate_scalar_field((point[0], point[1]+h, point[2])) - evaluate_scalar_field((point[0], point[1]-h, point[2]))
    dz = evaluate_scalar_field((point[0], point[1], point[2]+h)) - evaluate_scalar_field((point[0], point[1], point[2]-h))
    length = (dx*dx + dy*dy + dz*dz)**0.5
    return (dx/length, dy/length, dz/length)

def apply_lighting(point, normal):
    # [G] Simple diffuse lighting model
    return (0.5 + 0.5 * max(0, normal[2]))

def render_fragments(fragments, image_width, image_height, tile_size):
    image = [[0.0] * image_width for _ in range(image_height)]
    for y in range(image_height):
        for x in range(image_width):
            origin = (float(x), float(y), 0.0)
            direction = (0.0, 0.0, 1.0)
            relevant_fragment = None
            for frag in fragments:
                if (frag.region.x_min <= x < frag.region.x_max and
                    frag.region.y_min <= y < frag.region.y_max):
                    relevant_fragment = frag
                    break
            if relevant_fragment is not None:
                z_intersect = binary_search_intersection(origin, direction, relevant_fragment)
                if z_intersect is not None:
                    point = (origin[0], origin[1], z_intersect)
                    normal = calculate_normal(point)
                    image[y][x] = apply_lighting(point, normal)
    return image
```

**Parameters:**
- **Tile Size:** The size of the fragments generated by the CPU [S1].
- **Ray Direction:** Assumed to be along the Z-axis for the GPU stage [S1].

**Pitfalls:**
- **Memory Optimization:** Registers should be used to a maximum degree, and memory should be used jointly to avoid performance penalties from general GPU memory access [S1].
- **Intersection Test Accuracy:** The source does not specify the exact intersection test method, so implementers must choose a robust test appropriate for their implicit function representation [G].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Depends on the number of fragments generated, and memory is optimized by using registers and joint memory access [S1].
- **Performance:** Tested on Intel Core2 CPU E8400 3.0 GHz and NVIDIA GeForce GTX 470 GPU, and the method reduces visualization time by effective use of computational resources [S1].
- **Strengths:** At an early stage, larger parts of the cube that do not contain the object can be neglected, reducing the workload on the GPU [S1].
- **Limitations:** Requires a two-stage pipeline with CPU-GPU communication, and the method is specific to functionally defined objects and assumes rays directed along the Z-axis [S1].

## Background
The method was proposed in the paper "GPU-based volume-oriented rendering of functionally defined objects" [S1]. It was implemented using NVIDIA CUDA architecture and DirectX API [S1]. The testing was conducted on an Intel Core2 CPU E8400 3.0 GHz and an NVIDIA GeForce GTX 470 GPU [S1]. The research focuses on optimizing volume-oriented rendering by splitting the rasterization process between the CPU and GPU [S1].
