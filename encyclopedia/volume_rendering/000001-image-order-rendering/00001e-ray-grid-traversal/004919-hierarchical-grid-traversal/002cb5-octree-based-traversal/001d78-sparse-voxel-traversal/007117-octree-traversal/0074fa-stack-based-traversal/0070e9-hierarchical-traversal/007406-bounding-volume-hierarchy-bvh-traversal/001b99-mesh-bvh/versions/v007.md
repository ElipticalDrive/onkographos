# Mesh BVH

Also called: GPU BVH for Triangle Mesh, MeshBVH, TriangleMeshSDF BVH

## Overview
Mesh BVH is a GPU-accelerated bounding volume hierarchy designed for triangle meshes to support efficient distance queries, signed distance field (SDF) computation, and ray intersection tests [S1, unofficial][S4]. It serves as the acceleration structure for `isoext.sdf.TriangleMeshSDF`, enabling fast evaluation of geometric attributes for points in 3D space [S1, unofficial]. Unlike general-purpose CPU BVHs, this implementation is optimized for CUDA execution, providing batched operations for closest-point, sign, and winding number queries [S1, unofficial]. It distinguishes itself from sibling methods like [Leaf Collection](899-leaf-collection.md) by focusing on dense triangle mesh queries rather than sparse voxel or point cloud data, and from [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md) by using a binary hierarchy of AABBs rather than a k-d tree for spatial partitioning.

## How it works
**Inputs and Outputs:**
The primary constructor takes two CUDA tensors: vertices $V$ of shape $(N_v, 3)$ with `float32` data type, and faces $F$ of shape $(N_f, 3)$ with `int32` data type, where each row contains indices into $V$ [S1, unofficial].
The structure exposes three query methods, each accepting a point tensor $P$ of shape $(N_p, 3)$ with `float32` data type:
1.  `closest(P)`: Returns distances $D$ of shape $(N_p,)$, closest points $C$ of shape $(N_p, 3)$, and face IDs $I$ of shape $(N_p,)$ [S1, unofficial].
2.  `sign(P)`: Returns a sign tensor $S$ of shape $(N_p,)$ with `float32` values: $+1$ for outside, $-1$ for inside [S1, unofficial].
3.  `winding_number(P)`: Returns a winding number tensor $W$ of shape $(N_p,)$ with `float32` values: $1$ inside a closed mesh, $0$ outside [S1, unofficial].

**Data Structures:**
The hierarchy is a binary tree where each node contains an Axis-Aligned Bounding Box (AABB) [S1, unofficial]. The AABB is defined by minimum and maximum coordinates $(min_x, min_y, min_z)$ and $(max_x, max_y, max_z)$ [S1, unofficial]. Internal nodes store the union of their children's AABBs. Leaf nodes store references to individual triangles [S1, unofficial]. The implementation uses CUDA tensors for storage, managed via a custom `NDArray` wrapper that handles device memory allocation and deallocation using Thrust [S1, unofficial].

**Algorithm Steps:**

1.  **Construction:**
    *   Input: $V \in \mathbb{R}^{N_v \times 3}$, $F \in \mathbb{Z}^{N_f \times 3}$.
    *   Compute the bounding box of all vertices.
    *   Recursively subdivide the set of triangles. The splitting criterion is not explicitly detailed in the provided sources, but standard BVH construction typically uses SAH (Surface Area Heuristic) or median splitting [G].
    *   For each node, compute the AABB enclosing all triangles in its subtree. The AABB intersection test for a point $p$ and box $b$ is:
        $$
        \text{inside} = (p.x \ge b.min.x) \land (p.x \le b.max.x) \land (p.y \ge b.min.y) \land (p.y \le b.max.y) \land (p.z \ge b.min.z) \land (p.z \le b.max.z)
        $$
        In CUDA C++, this is implemented using `fminf` and `fmaxf` for clamping checks [S1, unofficial].

2.  **Closest Point Query (`closest`):**
    *   Input: $P \in \mathbb{R}^{N_p \times 3}$.
    *   For each point $p_i \in P$:
        *   Traverse the BVH to find the closest triangle.
        *   For each candidate triangle with vertices $a, b, c$, compute the closest point on the triangle to $p_i$.
        *   The closest point calculation follows the Voronoi region method [S1, unofficial]:
            $$
            ab = b - a, \quad ac = c - a, \quad ap = p_i - a
            $$
            $$
            d_1 = ab \cdot ap, \quad d_2 = ac \cdot ap
            $$
            If $d_1 \le 0$ and $d_2 \le 0$, the closest point is $a$.
            $$
            bp = p_i - b
            $$
            $$
            d_3 = ab \cdot bp, \quad d_4 = ac \cdot bp
            $$
            If $d_3 \ge 0$ and $d_4 \le d_3$, the closest point is $b$.
            $$
            vc = d_1 d_4 - d_3 d_2
            $$
            If $vc \le 0$ and $d_1 \ge 0$ and $d_3 \le 0$, the closest point is on edge $ab$:
            $$
            a + ab \frac{d_1}{d_1 - d_3}
            $$
            $$
            cp = p_i - c
            $$
            $$
            d_5 = ab \cdot cp, \quad d_6 = ac \cdot cp
            $$
            If $d_6 \ge 0$ and $d_5 \le d_6$, the closest point is $c$.
            $$
            vb = d_5 d_2 - d_1 d_6
            $$
            If $vb \le 0$ and $d_2 \ge 0$ and $d_6 \le 0$, the closest point is on edge $ac$:
            $$
            a + ac \frac{d_2}{d_2 - d_6}
            $$
            Otherwise, the closest point is inside the triangle:
            $$
            a + ab \frac{d_1 d_6 - d_2 d_5}{vb} + ac \frac{d_2 d_5 - d_1 d_6}{vb} \quad \text{(Note: Source [S1, unofficial] cuts off here, standard barycentric formula applies)}
            $$
            *   [G] The standard barycentric calculation for the interior case is $a + \frac{d_1 d_6 - d_2 d_5}{vb} ab + \frac{d_2 d_5 - d_1 d_6}{vb} ac$ is incorrect; the correct formula uses the computed $vc$ and $vb$. The source implies the standard Ericson implementation [S1, unofficial].
        *   Track the minimum distance and corresponding face ID.
    *   Output: $D, C, I$.

3.  **Sign Query (`sign`):**
    *   Input: $P \in \mathbb{R}^{N_p \times 3}$.
    *   For each point $p_i$:
        *   Trace 32 "stab rays" distributed uniformly over the sphere using a Fibonacci lattice [S4].
        *   The lattice is pseudorandomly and independently offset for every training position [S4].
        *   If any ray reaches infinity (no intersection), mark $p_i$ as outside ($+1$) [S4].
        *   Otherwise, mark $p_i$ as inside ($-1$) [S4].
        *   [G] Ray-triangle intersection is performed using NVIDIA OptiX 7 hardware acceleration [S4].
    *   Output: $S$.

4.  **Winding Number Query (`winding_number`):**
    *   Input: $P \in \mathbb{R}^{N_p \times 3}$.
    *   For each point $p_i$:
        *   Compute the winding number by summing the solid angles subtended by each triangle, or by ray casting [S1, unofficial].
        *   The source specifies the output is $1$ inside and $0$ outside for closed meshes [S1, unofficial].
    *   Output: $W$.

**Parameters:**
*   Number of stab rays for sign determination: 32 [S4].
*   Hardware: NVIDIA RTX 3090 GPU (for OptiX acceleration) [S4].

**Edge Cases and Pitfalls:**
*   **Watertightness:** Signing distance based on the normal of the closest triangle is cheaper but is disabled by default due to incompatibility with non-watertight meshes [S4].
*   **Precision:** The BVH construction and traversal rely on `float32` precision [S1, unofficial].
*   **Memory:** The `NDArray` wrapper manages CUDA memory; failure to call `free()` may lead to leaks [S1, unofficial].

## Subtopics

### [Position-Normal Tree](4222-position-normal-tree.md)
A binary tree hierarchy over a triangle mesh where leaves are triangles and internal nodes contain a 3D axis-aligned bounding box (AABB) over positions and a bounding cone over shading normals for all descendants. It stores position and normal information for boundary triangles to enable hierarchical pruning of refractive path searches. It is distinguished from interval-based refinement by prioritizing speed over guaranteed convergence, typically running 2 to 5 times faster while producing visually equivalent results.

### [Voxel Mesh Ray Intersection via BVH](6900-voxel-mesh-ray-intersection-via-bvh.md)
Voxel Mesh Ray Intersection via BVH is a raycasting method for voxel meshes that traverses a grid of oriented sub-cubes to find intersections with voxel geometry using Binary Volume Hierarchy (BVH) triangle intersection tests. It handles multiple meshes by first checking bounding boxes and then delegating to the specific mesh's BVH. This method builds on [Mesh BVH](1062-mesh-bvh.md) by providing the specific traversal logic and data structures required to query triangle meshes stored within a voxelized world structure.

### [GPU BVH Construction via Cluster Merging](16461-gpu-bvh-construction-via-cluster-merging.md)
A method to construct a Binary Volume Hierarchy (BVH) on the GPU by iteratively merging clusters of triangles. It uses a neighbor-finding step followed by cluster merging, prefix scans for position calculation, and reallocation to compact the cluster array until a single root cluster remains.

#### BVH-based Geometric Attribute Correction
Uses a BVH to compute the unsigned distance and barycentric coordinates from interpolated UV-space positions back to the original high-resolution mesh, correcting geometric errors from simplification/remeshing [S2, unofficial].
1.  Query BVH: `_, face_id, uvw = bvh.unsigned_distance(valid_pos, return_uvw=True)` [S2, unofficial].
2.  Fetch original triangle vertices: `orig_tri_verts = vertices[faces[face_id.long()]]` [S2, unofficial].
3.  Reconstruct corrected position via barycentric interpolation: `valid_pos = (orig_tri_verts * uvw.unsqueeze(-1)).sum(dim=1)` [S2, unofficial].

#### BVH for Blending
A bounding volume hierarchy adapted for the management of the blending operation, used for efficient evaluation of field functions on large skeletons [S3].

#### Efficient Signed Distance to Triangle Mesh
A method to compute the signed distance from a 3D point to a triangle mesh efficiently using a BVH for unsigned distance and ray casting for sign determination [S4].
1.  Construct a triangle BVH for efficient unsigned distance queries, achieving $O(\log N_{triangles})$ average complexity [S4].
2.  Trace 32 'stab rays' distributed uniformly over the sphere using a Fibonacci lattice, pseudorandomly and independently offset for every training position [S4].
3.  If any ray reaches infinity, mark the position as 'outside' and the distance as positive. Otherwise, mark it as negative [S4].
4.  Use NVIDIA ray tracing hardware via the OptiX 7 framework for ray-triangle intersections to maximize efficiency [S4].
*   Parameter: Number of stab rays: 32 [S4].
*   Pitfall: For watertight meshes, signing distance based on the normal of the closest triangle is cheaper, but this is disabled by default due to incompatibility with typical non-watertight meshes found in the wild [S4].
*   Comparison: Using OptiX 7 is over an order of magnitude faster than using a software triangle BVH for ray-shape intersections on an RTX 3090 GPU [S4].

## Operating characteristics
*   **Time Complexity:** Unsigned distance queries achieve $O(\log N_{triangles})$ average complexity [S4].
*   **Performance:** Using OptiX 7 for ray-triangle intersections is over an order of magnitude faster than software triangle BVH on an RTX 3090 GPU [S4].
*   **Memory:** The structure stores vertices, faces, and BVH nodes in CUDA tensors [S1, unofficial].
*   **Strengths:** Fast distance queries, support for signed distance fields, hardware acceleration via OptiX [S1, unofficial][S4].
*   **Limitations:** Default sign determination is slower due to ray casting; normal-based signing is disabled for non-watertight meshes [S4].
*   **When to use:** When efficient SDF computation or closest-point queries on triangle meshes are required on GPU [S1, unofficial][S4].
*   **When not to use:** For non-watertight meshes where normal-based signing is desired and performance is critical [S4].

## Background
Mesh BVH was introduced as part of the `isoext` library by Guangyan Cai [S1, unofficial]. It is used by `isoext.sdf.TriangleMeshSDF` for distance queries [S1, unofficial]. The method for efficient signed distance computation using BVH and stab rays was described in the "Instant Neural Graphics Primitives" paper by Mueller et al. [S4]. The use of BVH for blending operations in large skeletons was discussed in "Fast Ray Tracing of Scale-Invariant Integral Surfaces" [S3]. BVH-based geometric attribute correction was described in the `o-voxel-gpu` repository [S2, unofficial].
