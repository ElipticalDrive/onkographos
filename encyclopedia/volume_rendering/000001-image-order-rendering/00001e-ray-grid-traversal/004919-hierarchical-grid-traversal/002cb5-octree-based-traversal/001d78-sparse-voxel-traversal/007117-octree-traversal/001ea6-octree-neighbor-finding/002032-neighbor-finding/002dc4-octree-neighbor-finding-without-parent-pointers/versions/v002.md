# Octree Neighbor Finding without Parent Pointers

Also called: Mask-based Neighbor Finding, Neighbor Finding without Parent Pointers

## Overview
This method locates the voxel at a coordinate direction relative to an origin node by traversing up the octree hierarchy to find a common parent, then using point location to find the destination leaf [S1]. It is distinguished from parent-pointer-based approaches by omitting explicit parent pointers to minimize memory footprint, instead relying on an `index trace[]` array populated during ray traversal to provide parent indices [S1]. Unlike Frisken and Perry’s method which uses exclusive OR with depth masks, this implementation uses bitwise AND masking on both source and destination coordinates followed by integer equality checks to identify common parents, as it is not more expensive [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** Origin node index, origin coordinate, destination coordinate, and the `index trace[]` array containing indices of all parent nodes for the current cap [S1].
*   **Output:** Index of the destination leaf node [S1].

**Data Structures:**
*   `index trace[]`: An array storing the indices of parent nodes encountered during the ray traversal up to the current cap [S1].
*   Coordinates: Spatial coordinates for the origin and destination nodes.

**Steps:**
1.  **Masking:** Apply a bitwise AND mask to both the source (origin) and destination coordinates [S1].
2.  **Comparison:** Perform integer equality comparison on the masked source and destination values [S1].
3.  **Recursion:** If the masked values are not equal, move up the tree using the `index trace[]` array to access the parent node indices [S1]. Repeat the masking and comparison at the parent level [S1].
4.  **Common Parent:** Continue until a common parent is found where the masked coordinates are equal [S1].
5.  **Point Location:** Once the common parent is identified, perform point location from this ancestor to find the specific leaf node at the destination coordinate [S1].

**Pseudocode:**
```python
def mask_coords(coords, depth):
    # Masks out bits finer than the current depth level.
    # Assumes depth 0 is the finest level (leaf).
    return coords & ~((1 << depth) - 1)

def find_neighbor(origin_index, origin_coord, dest_coord, index_trace, current_depth):
    # Mask both coordinates at the current depth
    masked_origin = mask_coords(origin_coord, current_depth)
    masked_dest = mask_coords(dest_coord, current_depth)
    
    # Check for equality to find common parent
    if masked_origin == masked_dest:
        # Common parent found; perform point location from this ancestor
        return point_location(index_trace, current_depth, dest_coord)
    else:
        # Move up to the parent using the trace array
        parent_index = index_trace[current_depth - 1]
        # Recurse to the parent level
        return find_neighbor(parent_index, origin_coord, dest_coord, index_trace, current_depth - 1)

def point_location(trace, start_depth, target_coord):
    # Traverse down from the common ancestor to find the leaf at target_coord
    current_index = trace[start_depth]
    for depth in range(start_depth, -1, -1):
        # Extract octant bits for the current depth level
        octant = (target_coord >> (3 * depth)) & 7
        # Compute child index using standard hash-based octree layout
        child_index = (current_index << 3) | octant
        # [G] Standard hash-table lookup for child existence
        if child_index not in hash_table:
            return None
        current_index = child_index
    return current_index
```

**Parameters:**
*   `current_depth`: The depth level in the octree where the comparison is performed.

**Edge Cases and Pitfalls:**
*   **Precision:** Integer coordinates must be handled carefully to ensure correct masking [G].
*   **Boundaries:** If the destination coordinate is outside the octree bounds, point location should handle this gracefully [G].
*   **Degenerate Input:** If the origin and destination are the same, the algorithm should return the origin index immediately [G].

## Subtopics

### Neighbor Finding via Reflection
An algorithm to find adjacent nodes in an octree without using locational codes, utilizing case decomposition for edges/vertices and bitwise operations for optimization [S2, unofficial]. It computes the 'reflection' function for the adjacent neighbor by performing a binary exclusive OR (XOR) of the current location and the direction vector in which the neighbor is sought [S2, unofficial]. It then recursively traverses up the tree to find the deepest common ancestor between the current node and the reflected location [S2, unofficial]. Finally, it performs point location from the deepest common ancestor to find the target neighbor node [S2, unofficial]. The average cost to find an adjacent neighbor at the same depth is O(1) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The average cost to find an adjacent neighbor at the same depth is O(1) [S2, unofficial]. The general neighbor finding algorithm involves recursion up the tree, which depends on the depth of the octree [S1].
*   **Memory Complexity:** The `index trace[]` array requires O(D) memory where D is the depth of the octree [S1]. O(1) additional memory is required per traversal step if the array is reused [G].
*   **Strengths:** Minimizes memory footprint by omitting parent pointers [S1]. Efficient for non-adjacent neighbors [S1].
*   **Limitations:** Requires the `index trace[]` array to be maintained during ray traversal [S1].
*   **When to Use:** When memory is constrained and parent pointers are undesirable [S1].
*   **When Not to Use:** When random access to parent pointers is needed without maintaining a trace array [G].

## Background
Neighbor finding was addressed early on in octree research [S2, unofficial]. Gargantini [Gar82] provided a concise algorithm for finding adjacent nodes in the linear quadtree using Morton’s [Mor66] array-based locational code [S2, unofficial]. Samet [Sam82] proposed a more general scheme for adjacent neighbor-finding using only an original node and a desired direction, with no knowledge of a locational code [S2, unofficial]. The algorithm was later applied to accelerating ray tracing using a pointer octree [Sam89] [S2, unofficial]. Samet [Sam90] conducted rigorous analysis of the neighbor finding technique, decomposing the algorithm into cases for edge, vertex, and aligned neighbors [S2, unofficial]. Frisken and Perry noted that the “reflection” function for adjacent neighbors, implemented by Samet via a switch statement, can be accomplished by a binary exclusive “or” of the current location and the direction in which we seek a neighbor [S2, unofficial]. The method described here, using masking and equality checks, was proposed in [S1] as an alternative to Frisken and Perry’s method.
