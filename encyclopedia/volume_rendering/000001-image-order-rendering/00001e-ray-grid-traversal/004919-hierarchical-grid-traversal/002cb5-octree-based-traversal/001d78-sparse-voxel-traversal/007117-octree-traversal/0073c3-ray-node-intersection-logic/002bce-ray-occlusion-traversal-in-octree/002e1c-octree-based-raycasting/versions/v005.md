# Octree-based Raycasting

Also called: Raycasting mit Octree-Beschleunigungsstruktur, Raycasting with Octree Traversal, Voxel-Raycasting mit Octree

## Overview
Octree-based raycasting is a technique for rendering sparse volumetric data or geometric primitives by casting rays from a camera through screen pixels and traversing an octree structure to skip empty space [S1, S2, unofficial]. It accelerates rendering by avoiding intersection tests with non-existent voxels, reducing complexity from linear in the number of voxels to proportional to the number of occupied nodes [S2, unofficial][S3]. Unlike uniform grid traversal, it adapts to data sparsity, making it suitable for large scenes with varying density [S3].

## How it works
**Inputs:** Camera parameters (position, view matrix, screen dimensions), octree structure (nodes with child masks and voxel counts), and scene data (voxel values or primitive definitions).
**Outputs:** Color or scalar value for each pixel.

**Data Structures:**
*   **Octree Node:** Contains an 8-bit child existence mask (indicating which of the 8 sub-cubes have children) and a voxel count integer. The voxel count tracks the number of leaf voxels in the subtree to support dynamic updates [S2, unofficial].
*   **Ray:** Defined by origin $(O_x, O_y, O_z)$ and direction $(D_x, D_y, D_z)$.

**Steps:**
1.  **Coordinate Transformation:** Transform the ray from world space to the local space of the current octree node (or root bounding box).
    *   Compute the inverse world-view matrix $M_{inv}$ [S1, unofficial].
    *   Transform ray origin: $O' = M_{inv} \cdot O$.
    *   Transform ray direction: $D' = M_{inv} \cdot D$. Note: Direction vectors must be transformed using the normal matrix (upper 3x3 of inverse model-view) to avoid translation artifacts [S1, G, unofficial].
    *   Normalize $D'$ [S1, unofficial].
2.  **Direction Flipping:** To simplify intersection logic, flip the ray direction and adjust the origin if components are negative, mapping the ray into the first octant relative to the box [S1, unofficial].
    *   If $D'_x < 0$: $O'_x = \text{boxSize} - O'_x$, $D'_x = -D'_x$.
    *   If $D'_y < 0$: $O'_y = \text{boxSize} - O'_y$, $D'_y = -D'_y$.
    *   If $D'_z < 0$: $O'_z = \text{boxSize} - O'_z$, $D'_z = -D'_z$.
3.  **Box Intersection Test:** Calculate entry and exit times for the axis-aligned bounding box (AABB) of the current node.
    *   $t_{x0} = (0 - O'_x) / D'_x$, $t_{x1} = (\text{boxSize} - O'_x) / D'_x$.
    *   $t_{y0} = (0 - O'_y) / D'_y$, $t_{y1} = (\text{boxSize} - O'_y) / D'_y$.
    *   $t_{z0} = (0 - O'_z) / D'_z$, $t_{z1} = (\text{boxSize} - O'_z) / D'_z$.
    *   Let $t_{enter} = \max(t_{x0}, t_{y0}, t_{z0})$ and $t_{exit} = \min(t_{x1}, t_{y1}, t_{z1})$.
    *   If $t_{enter} > t_{exit}$, the ray misses the box; return no hit [S1, unofficial].
4.  **Traversal:**
    *   If the node is a leaf, compute the volume rendering integral or surface intersection using the stored voxel data [S1, unofficial].
    *   If the node is internal, use the child existence mask to identify which sub-cubes to traverse. Recursively apply steps 1-3 for each active child, using the sub-cube's local bounds (typically half the parent size) [S1, unofficial][S3].
    *   For hybrid approaches, use a 3D supercover DDA algorithm to iterate over octants in the highest LOD grid, then recursively raycast those octants as subtrees [S3].

**Pseudocode:**
```python
def cast_ray(camera, octree_root, screen_x, screen_y, width, height):
    # 1. Create ray in world space
    cam_pos = camera.position
    cam_dir = map_2d_to_3d(screen_x, screen_y, width, height, camera.coord_system) - cam_pos
    ray_origin = cam_pos
    ray_dir = normalize(cam_dir)

    # 2. Transform to local space of root
    # Note: Use inverse view matrix for direction to avoid translation [S1, G, unofficial]
    inv_view = inverse(camera.view_matrix)
    local_origin = transform_vector(inv_view, ray_origin)
    local_dir = transform_vector(inv_view, ray_dir) # TransformNormal equivalent [S1, G, unofficial]
    local_dir = normalize(local_dir)

    # 3. Traverse
    return traverse_node(local_origin, local_dir, octree_root, box_size=64.0)

def traverse_node(origin, direction, node, box_size):
    # 4. Flip direction to positive octant for simpler intersection math [S1, unofficial]
    if direction.x < 0:
        origin.x = box_size - origin.x
        direction.x = -direction.x
    if direction.y < 0:
        origin.y = box_size - origin.y
        direction.y = -direction.y
    if direction.z < 0:
        origin.z = box_size - origin.z
        direction.z = -direction.z

    # 5. AABB Intersection Test [S1, unofficial]
    tx0 = (0.0 - origin.x) / direction.x
    tx1 = (box_size - origin.x) / direction.x
    ty0 = (0.0 - origin.y) / direction.y
    ty1 = (box_size - origin.y) / direction.y
    tz0 = (0.0 - origin.z) / direction.z
    tz1 = (box_size - origin.z) / direction.z

    t_enter = max(tx0, ty0, tz0)
    t_exit = min(tx1, ty1, tz1)

    if t_enter > t_exit:
        return -1.0 # No hit

    # 6. Check if leaf or internal
    if node.is_leaf:
        return compute_voxel_value(origin, direction, node.data)
    
    # 7. Recurse into children based on mask [S3]
    child_size = box_size / 2.0
    hit_value = -1.0
    for i in 0..7:
        if node.child_mask & (1 << i):
            # Calculate child's local origin offset
            child_origin = origin + get_child_offset(i, child_size)
            # Transform child origin back to parent's flipped coordinate system if needed,
            # or adjust logic to handle local space. 
            # Simplified: pass child's local bounds relative to parent's flipped space.
            # Note: The flip logic in [S1, unofficial] assumes the box is [0, boxSize].
            # Children are sub-boxes. The intersection test must be adapted for sub-boxes.
            # For a child at index i, its bounds in the flipped space are complex.
            # A robust implementation transforms the ray into the child's local space.
            
            # Alternative: Use standard octree traversal (e.g., Amanatides & Woo) 
            # which handles negative directions natively. The flip method [S1, unofficial] is specific 
            # to the cited example and may not generalize easily to arbitrary children 
            # without coordinate remapping.
            
            # For the purpose of this article, we assume a recursive call with 
            # adjusted bounds or a standard traversal algorithm is used for children.
            val = traverse_node(child_origin, direction, node.children[i], child_size)
            if val != -1.0:
                hit_value = val
                break # Return first hit
    
    return hit_value
```

**Parameters:**
*   `boxSize`: Size of the bounding box for the current node. For the root, typically 64.0; for children, halved recursively [S1, unofficial].
*   `child_mask`: 8-bit integer where bit $i$ is set if child $i$ exists [S3].

**Edge Cases and Pitfalls:**
*   **Direction Transformation:** Using `TransformCoordinate` (which includes translation) on direction vectors instead of `TransformNormal` causes gaps between cubes when the camera moves [S1, unofficial].
*   **Zero Direction Components:** Division by zero occurs if a ray direction component is exactly 0. Handle by treating $t_{min}$ as $-\infty$ and $t_{max}$ as $+\infty$ for that axis [G].
*   **Precision:** Floating-point errors in $t_{enter}$ and $t_{exit}$ comparisons can cause missed hits or double hits. Use a small epsilon for comparisons [G].
*   **Dynamic Updates:** When voxels are deleted, the voxel count in the node must be decremented atomically to avoid data races [S2, unofficial]. If the count reaches 0, the node is deactivated [S2, unofficial].

## Subtopics

### Atomic Octree Update
A technique to prevent data races during concurrent writes to octree node voxel counts in real-time modifications. It uses HLSL intrinsics `InterlockedAdd` for atomic addition/subtraction on the voxel count variable. The `StructuredBuffer` storing the octree must be declared with the `globallycoherent` qualifier to ensure visibility across warps [S2, unofficial].

### Hybrid Raycasting with Voxel Traversal
A top-down parametric raycasting technique that uses a 3D supercover DDA line algorithm to iterate over octants in the highest LOD grid, then recursively raycasts those octants as subtrees. This approach is chosen when the octree has a limited number of LOD levels and the highest grid is sparse. It avoids querying a hash map for every octant in coarser levels but requires hash map queries for every octant in the highest LOD grid, as no meta-information exists to skip empty space there [S3]. Performance: Raycasting 1,048,576 spheres takes >65ms with a naive approach, but <0.5ms with the octree approach (tree depth D=5) [S3].

## Operating characteristics
*   **Time Complexity:** $O(k)$, where $k$ is the number of occupied nodes intersected by the ray, rather than $O(n)$ where $n$ is the total number of voxels [S2, unofficial].
*   **Memory Complexity:** $O(N)$, where $N$ is the number of nodes in the octree. The structure requires storing child masks and voxel counts for each node [S2, unofficial].
*   **Performance:** Scales well with larger amounts of data. For a point cloud of 1,048,576 spheres, the octree approach reduces rendering time from >65ms to <0.5ms (D=5) [S3].
*   **Strengths:** Efficient culling of empty space; suitable for dynamic scenes with voxel modifications [S2, unofficial].
*   **Limitations:** Requires complex data structure management for dynamic updates (atomic operations) [S2, unofficial]. Highest LOD grid traversal can be inefficient if sparse, as empty space cannot be skipped without a hash map query [S3].
*   **When to use:** Sparse volumetric data, dynamic voxel environments, large scenes with varying density.
*   **When not to use:** Dense, uniform volumes where a regular grid traversal might be simpler and faster due to lower overhead.

## Background
Octree-based raycasting originated as a method to accelerate rendering of complex scenes by exploiting spatial coherence. The technique leverages the hierarchical nature of octrees to skip empty regions. The specific implementation details cited, such as the flip-and-test method and atomic updates, stem from practical implementations in real-time graphics and voxel-based games [S1, S2, unofficial]. The hybrid approach combining voxel traversal with octree raycasting was developed to handle limited LOD grids in WebGL-based volumetric terrain rendering [S3].
