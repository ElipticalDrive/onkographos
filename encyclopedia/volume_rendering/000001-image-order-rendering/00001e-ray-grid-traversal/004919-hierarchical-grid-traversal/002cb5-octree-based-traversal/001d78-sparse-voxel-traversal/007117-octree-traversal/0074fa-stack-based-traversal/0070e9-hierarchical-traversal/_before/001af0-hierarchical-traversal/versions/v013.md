# Hierarchical Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal is a method for accelerating ray-object intersection and volume rendering by utilizing a hierarchy of grids where each higher-level cell covers a $2 \times 2$ area of the level below [S1, unofficial]. It solves the problem of inefficiently stepping through large empty spaces in sparse volumetric data by allowing the ray to take larger steps at coarser levels of the hierarchy [S1, unofficial]. Unlike non-hierarchical traversal which requires a step for every voxel, hierarchical traversal reduces the total number of steps by skipping over empty regions represented by higher-level nodes [S1, unofficial]. It builds on [Octree Traversal](1587-octree-traversal.md) by applying specific traversal logic to sparse voxel structures.

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, and a hierarchical data structure (e.g., Sparse Voxel Octree or BVH) where nodes represent spatial extents.
*   **Output:** A sequence of active nodes or leaves intersected by the ray, or a boolean indicating intersection within a distance threshold.

**Data Structures:**
The structure depends on the specific variant (Octree vs. BVH), but generally follows these layouts:
*   **Octree/SVO Node:** Contains pointers or indices to children. In SVO implementations, only the highest level is stored initially, and nodes are subdivided on demand to represent the grid [S1, unofficial].
*   **BVH Node:** As defined in [S2, unofficial], a `BVHNode` struct contains:
    *   `center`: `[f32; 4]` (center coordinates)
    *   `radius`: `f32`
    *   `left_child`: `u32`
    *   `right_child`: `u32`
    *   Packed in 16-byte alignment.
    *   **Leaf Identification:** Leaf nodes are identified by setting the high bit (`0x80000000`) of the child indices [S2, unofficial]. If a leaf is the last element and has no sibling, its `right_child` is set to `empty_node_idx` (0) [S2, unofficial].

**Algorithm Steps:**
The traversal generally follows a stack-based or recursive descent, prioritizing closer nodes.

1.  **Initialization:**
    *   Initialize a stack with the root node.
    *   Compute ray-box intersection parameters ($t_{min}, t_{max}$) for the root bounding volume [S2, unofficial].

2.  **Traversal Loop:**
    While the stack is not empty:
    1.  Pop the top node index from the stack.
    2.  Retrieve the node data.
    3.  **Intersection Test:** Check if the ray intersects the current node's bounding volume. If not, continue to the next iteration [S2, unofficial].
    4.  **Leaf Check:** If the node is a leaf (identified by the high bit in child indices for BVH, or specific type flag for Octree):
        *   Process the leaf (e.g., check for surface descendant, sample volume, or return intersection) [S3, unofficial][S6, unofficial].
        *   Return true if the minimum intersection distance $t$ is less than a threshold (e.g., 10000.0) [S2, unofficial].
    5.  **Internal Node Descent:**
        *   Identify children (left and right for BVH; 8 for Octree).
        *   If both children need descending (intersect the ray):
            *   Push the child with the smaller intersection distance onto the stack first, then descend into the closer child immediately [S2, unofficial].
            *   Formula for ordering: `if left_t < right_t: push right, descend left`.
        *   If only one child intersects, descend into that child.
        *   If neither intersects, pop from stack (handled by the loop condition or explicit check).

3.  **Octree-Specific Path Traversal:**
    For SVO/Octree variants, traversal may follow a precomputed path or octant mask:
    *   Iterate through path octants.
    *   If the current cell is a Branch, retrieve its children index, access the specific child in the children vector, and update the current pointer [S3, unofficial].
    *   If it is not a Branch (Leaf), return the current cell [S3, unofficial].

**Parameters:**
*   **Max Depth:** Limits the recursion depth to prevent infinite loops in degenerate cases [S2, unofficial].
*   **Threshold:** Distance cutoff for early termination (e.g., 10000.0) [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Empty Siblings:** In BVH leaf handling, if a leaf is the last element and has no sibling, `right_child` is set to 0 [S2, unofficial].
*   **Zero Direction Components:** Ray direction components must be handled to avoid division by zero during slab intersection tests (e.g., clamping small values to epsilon) [S2, unofficial].
*   **Boundary Voxels:** Special handling is required for rays intersecting boundary voxels where standard step masks might be zero [S2, unofficial].

**Pseudocode (BVH Variant):**
```python
def traverse_bvh(ray_origin, ray_direction, bvh_nodes, max_depth=100):
    # Stack stores (node_index, t_min, t_max)
    stack = [(0, 0.0, 10000.0)] 
    
    while stack:
        node_idx, t_min, t_max = stack.pop()
        
        # Check bounds
        if node_idx >= len(bvh_nodes):
            continue
            
        node = bvh_nodes[node_idx]
        
        # Check if leaf (high bit set in left_child)
        is_leaf = (node.left_child & 0x80000000) != 0
        
        if is_leaf:
            # Process leaf intersection
            # Return true if intersection found within t_max
            if check_leaf_intersection(node, ray_origin, ray_direction, t_max):
                return True
            continue
            
        # Internal node: get children
        left_child = node.left_child & 0x7FFFFFFF
        right_child = node.right_child & 0x7FFFFFFF
        
        # Calculate intersection distances for children
        # Assuming children have bounding boxes defined by center/radius
        left_t_min, left_t_max = compute_box_intersection(node.center, node.radius, left_child, ray_origin, ray_direction)
        right_t_min, right_t_max = compute_box_intersection(node.center, node.radius, right_child, ray_origin, ray_direction)
        
        # Push children in order of distance (closer first)
        # Only push if they intersect the current ray segment [t_min, t_max]
        if left_t_max >= t_min and right_t_max >= t_min:
            if left_t_min < right_t_min:
                if right_t_max >= t_min:
                    stack.append((right_child, right_t_min, right_t_max))
                stack.append((left_child, left_t_min, left_t_max))
            else:
                if left_t_max >= t_min:
                    stack.append((left_child, left_t_min, left_t_max))
                stack.append((right_child, right_t_min, right_t_max))
        elif left_t_max >= t_min:
            stack.append((left_child, left_t_min, left_t_max))
        elif right_t_max >= t_min:
            stack.append((right_child, right_t_min, right_t_max))
            
    return False
```

## Subtopics

### [Leaf Collection](899-leaf-collection.md)
Leaf Collection identifies and gathers all terminal nodes (leaves) intersected by a ray grid during hierarchical traversal, converting a sparse traversal path into a contiguous list of active volumetric blocks for subsequent ray marching or shading. It separates node identification from radiance computation to enable efficient memory compaction and parallel processing [899-leaf-collection.md].

### [Point Plane Test Traversal](982-point-plane-test-traversal.md)
Point Plane Test Traversal is a method for locating the specific child tetrahedron within a TET-AMR refinement tree that contains a given query point. It solves the in-element lookup problem by traversing from the coarse root to the leaf using geometric half-space tests against planes defined by edge midpoints, avoiding the redundancy of checking all eight children individually [982-point-plane-test-traversal.md].

### [Mesh BVH](1062-mesh-bvh.md)
Mesh BVH is a GPU-accelerated bounding volume hierarchy designed for triangle meshes to support efficient distance queries, signed distance field (SDF) computation, and ray intersection tests. It serves as the acceleration structure for `isoext.sdf.TriangleMeshSDF`, enabling fast evaluation of geometric attributes for points in 3D space. Unlike general-purpose CPU BVHs, this implementation is optimized for CUDA execution, providing batched operations for closest-point, sign, and winding number queries [1062-mesh-bvh.md].

### [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md)
Multi-resolution rendering with K-D Tree is a hierarchical volume rendering technique that accelerates image-order ray casting by storing approximations of the underlying data within K-D tree nodes. It solves the performance bottleneck of rendering large, high-resolution datasets by allowing the renderer to skip detailed traversal when the data within a spatial region can be represented by a simple model within a user-specified error threshold. Unlike wavelet-based methods which store only detail coefficients, this method stores a complete model for each region, enabling fast "preview" images and adaptive detail [1942-multi-resolution-rendering-with-k-d-tree.md].

### [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md)
Coarse Mesh Traversal is a hierarchical rendering technique that accelerates volume rendering by decoupling the global search for active data regions from the local sampling of fine-grained geometry. It solves the problem of inefficiently traversing large, sparse, or multi-resolution datasets by first identifying which coarse elements (macrocells) a ray intersects, and then performing detailed rendering only within those specific regions. What sets it apart from its siblings is the explicit construction of a coarse mesh (typically a BVH) from the underlying adaptive or hierarchical data structure, allowing the renderer to skip empty or irrelevant volumes entirely before entering the fine-level traversal loop [3062-coarse-mesh-traversal.md].

### [Node Omission in Ray-Tree Traversal](3305-node-omission-in-ray-tree-traversal.md)
Node omission is an optimization for hierarchical ray-tree traversal that prevents adding child nodes to the traversal stack if it is known they will not intersect the current ray, reducing the number of intersection tests. It sets itself apart from sibling methods by operating on the spatial relationship between the ray's entry/exit parameters and the node's bounding box midpoints, rather than relying on leaf-level data structures or plane-based splitting planes [3305-node-omission-in-ray-tree-traversal.md].

### [Two-Pass Hierarchy Traversal](3339-two-pass-hierarchy-traversal.md)
Two-Pass Hierarchy Traversal is a spatial hierarchy traversal optimization that reduces computational cost by splitting the descent into a coarse initial pass and a fine subsequent pass. It sets itself apart from single-pass methods by explicitly decoupling the identification of relevant subtrees from the detailed node evaluation, allowing for significant reuse across pixel blocks [3339-two-pass-hierarchy-traversal.md].

### [Adaptive Out-of-Core Single-Pass GPU Raycasting](3440-adaptive-out-of-core-single-pass-gpu-raycasting.md)
This method enables interactive rendering of multi-gigabyte scalar volumes on desktop hardware by combining an out-of-core octree data structure with a single-pass, stackless GPU raycasting algorithm. It solves the memory capacity and bandwidth bottlenecks of in-core rendering by maintaining a view- and transfer-function-dependent working set of volumetric bricks in GPU memory, while the rest of the dataset remains on disk. Unlike separate block rendering techniques that suffer from boundary artifacts and cannot support refractive or global illumination models, this approach performs the entire volume traversal and compositing in a single fragment shader pass, adapting sampling density to the local brick resolution [3440-adaptive-out-of-core-single-pass-gpu-raycasting.md].

### [Initial Upper Bound Estimation](15442-initial-upper-bound-estimation.md)
Initial Upper Bound Estimation computes a tight initial upper bound to prune BVH-tree traversal during distance field computation for isosurface approximation. It differs from standard hierarchical traversal by proactively sampling the approximated surface to establish a pruning threshold before traversal begins, rather than waiting for the first leaf encounter. This allows for more aggressive pruning at the beginning of the traversal, reducing the total number of nodes visited [15442-initial-upper-bound-estimation.md].

### Surface Descendant Check
If the cell is a Leaf, return whether it has a sign change. If it is a Branch, recursively check if any of its children have a surface descendant. If it is Empty or Full, return false [S3, unofficial].

### Coarse Mesh Traversal via BVH
Uses a Bounding Volume Hierarchy (BVH) built over the coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point. Build a triangle BVH over the coarse mesh by inserting four triangular faces facing outside for every coarse element. Trace rays into the BVH using OptiX Wrapper Library (OWL) hit and miss functions. The hit function returns the hit point and the coarse tetrahedron ID. The miss function reports no intersection with BVH faces. Unlike element marching which uses connectivity, point location querying skips coarse elements not being sampled and allows varying refinement levels in the coarse mesh [S7, unofficial].

### Warp-Level Intersection Caching
Optimization to delay intersection tests until enough threads in a warp have stored an intersection child node. When an intersection is found, store the current voxel intersection data. At the start of every traversal step, check if enough threads have a stored intersection. If so, proceed by doing an intersection test. Otherwise, continue traversal with the complete warp. If threads find the next intersection test while already having an intersection stored, stop traversing until the next intersection test is performed [S8, unofficial].

### BFS Hierarchy Cut Algorithm
An algorithm to cut a binary tree hierarchy along a certain condition using a breadth-first search (BFS) queue [S9, unofficial].

### Packet Ray Traversal / Ray Coherence Optimization
Configure the CUDA grid and block dimensions as 2D. Map threads such that neighboring threads (rays) are spatially coherent (similar direction), causing them to traverse the octree in similar ways, improving cache hit rates. Thread Divergence: In volumetric ray tracing or deep octree subdivisions, neighboring rays may diverge significantly in their traversal paths, causing SIMD stalls. This is a known limitation of GPU architecture for high-quality volume rendering [S10, unofficial].

### Octree Traversal with Texture Memory Access
Bind the octree node data to a CUDA texture object. Access node data using the `tex1Dfetch()` function, which utilizes the texture cache for random access patterns typical in tree traversal. Texture memory is preferred over constant memory for octree nodes because constant memory is limited in size and optimized for broadcast reads, whereas octree traversal involves random access patterns across different nodes [S10, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for balanced trees in the average case, where $N$ is the number of nodes, compared to $O(N)$ for linear traversal. The number of steps is significantly reduced; for example, in a hierarchical SVO example, traversal took 5 steps compared to 11 steps for non-hierarchical traversal [S1, unofficial].
*   **Memory Complexity:** Depends on the structure. SVO stores only the highest level initially and subdivides on demand, enabling sparse storage [S1, unofficial]. BVH nodes are packed tightly (e.g., 16-byte alignment) [S2, unofficial].
*   **Performance:** Results demonstrate that the technique is several times faster than other published algorithms [S4, unofficial].
*   **Strengths:** Efficiently skips empty space; reduces memory bandwidth usage by accessing only relevant nodes; supports out-of-core rendering via hierarchical paging [S5, unofficial].
*   **Limitations:** Stack depth can be an issue on GPUs; thread divergence in packet traversal can cause SIMD stalls [S10, unofficial].

## Background
Hierarchical traversal originated from the need to accelerate ray tracing and volume rendering for large datasets. Early work by Kay and Kajiya (1986) introduced a new hierarchy traversal algorithm for ray-object intersection, demonstrating it was several times faster than previous methods [S4, unofficial]. The concept of using octrees and SVOs for volume rendering was further developed to handle sparse data, where the tree acts as a 'page table' coupled to the resolution hierarchy [S5, unofficial]. Modern implementations leverage GPU-specific optimizations like texture memory access and warp-level caching [S10, unofficial][S8, unofficial].
