# Iterative Octree Traversal

Also called: BaseOctreeRenderer, Non-recursive Octree Ray Tracing, Ray-Tree Traversal for Color Rendering, Ray-Tree Traversal for Depth Visualization, Rekursionsfreie Traversierung eines Octree, Stack-based Octree Traversal, WorkOctreeRenderer

## Overview
Iterative Octree Traversal is a method for raycasting sparse voxel octrees on hardware that prohibits recursion, such as GPUs or specific CPU shader models, by replacing the call stack with an explicit data structure [S2, S4, unofficial]. It solves the problem of stack overflow and execution context limits by using a greedy approach that tracks the closest potential intersection, backtracking to parent nodes when a "false positive" (a parent hit but no child hit) occurs [S2, unofficial]. It differs from [Recursive Octree Traversal](2632-recursive-octree-traversal.md) by managing traversal state explicitly, and from [Parametric Octree Traversal](2361-parametric-octree-traversal.md) by relying on slab-based distance comparisons rather than parametric coordinate mapping [S2, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray $r$ defined by origin $o$ and direction $d$, and a Sparse Voxel Octree (SVO) stored in a linear block structure [S4, unofficial].
*   **Output:** The distance $t$ to the closest intersected voxel, or $-1$ if no intersection is found [S4, unofficial].

**Data Structures:**
The algorithm simulates recursion using fixed-size arrays to track depth, parent indices, and positions [S2, unofficial].
*   `skipListPerDepth[4]`: Integer array storing a bitmask of visited children for each depth level. Size 4 is sufficient for typical depth limits (e.g., $512^3$ tree with $32^3$ leaves) [S2, unofficial].
*   `parentListPerDepth[4]`: Integer array storing the index of the parent node at each depth level [S2, unofficial].
*   `positionListPerDepth[4]`: Array of `float3` storing the position of the parent node at each depth level [S2, unofficial].
*   `stack_item_t` (Alternative Implementation): A struct containing slab boundaries (`tx0, ty0, tz0, tx1, ty1, tz1`), node address (`adr`), and child index (`idx`) [S5, unofficial].

**Steps:**
1.  **Initialization:**
    *   Initialize `skipListPerDepth`, `parentListPerDepth`, and `positionListPerDepth` to zero/null [S2, unofficial].
    *   Set `currentDepth = 0` [S2, unofficial].
    *   Handle ray direction components: if any component is zero, add a small epsilon (e.g., 0.001) to avoid division by zero. If a component is negative, negate the ray origin and direction for that axis, and set a corresponding bit in `dir_mask` (x=4, y=2, z=1) [S5, unofficial].
    *   Compute initial slab boundaries for the root octree bounds $[min_x, max_x] \times [min_y, max_y] \times [min_z, max_z]$:
        $$tx_0 = \frac{min_x - o_x}{d_x}, \quad tx_1 = \frac{max_x - o_x}{d_x}$$
        $$ty_0 = \frac{min_y - o_y}{d_y}, \quad ty_1 = \frac{max_y - o_y}{d_y}$$
        $$tz_0 = \frac{min_z - o_z}{d_z}, \quad tz_1 = \frac{max_z - o_z}{d_z}$$
        [S5, unofficial]
    *   Scale slab boundaries by a fixed-point factor (e.g., `tnum_scale = 10000`) to convert to integer coordinates if using integer arithmetic [S5, unofficial].
    *   Initialize `minDistToNode` to infinity [S2, unofficial].

2.  **Traversal Loop:**
    *   Iterate for a maximum number of steps (`maxIterations`) [S2, unofficial].
    *   Identify the current node to process. In the greedy approach, this is the child of the current parent that has the smallest entry slab distance $t_{min}$ [S2, unofficial].
    *   **Check for False Positives/Backtracking:**
        *   If the current node is a leaf (e.g., size $\le 32$) and intersects the ray, perform voxel-level raycasting. If a hit is found at distance $t_{hit}$, update `minDistToNode` if $t_{hit} < minDistToNode$ [S2, unofficial].
        *   If the current node is an internal node, compute its 8 children's slab boundaries. The midpoint slab boundaries are calculated as:
            $$tx_m = \frac{tx_0 + tx_1}{2}, \quad ty_m = \frac{ty_0 + ty_1}{2}, \quad tz_m = \frac{tz_0 + tz_1}{2}$$
            [S4, unofficial]
        *   For each child $i$, determine its slab boundaries based on its octant index bits. Cull children whose exit distance is less than or equal to the current traversal start distance, or whose entry distance is greater than the current best hit [S4, unofficial].
        *   If a child intersects and is closer than `minDistToNode`, push the current state (parent index, position, visited mask) to the depth arrays, increment `currentDepth`, and move to the child [S2, unofficial].
        *   **Backtracking:** If no valid child is found (false positive) or all children are processed:
            *   Decrement `currentDepth`.
            *   If `currentDepth < 0`, terminate (no hit).
            *   Retrieve the parent from `parentListPerDepth` and `positionListPerDepth`.
            *   Mark the current child as visited in `skipListPerDepth` using bit manipulation: `skipListPerDepth[currentDepth] |= (1 << usedIndex)` [S2, unofficial].
            *   Proceed to the next unvisited child of the parent.

3.  **Termination:**
    *   If `minDistToNode` remains infinity after traversal, return $-1$ [S4, unofficial].
    *   Otherwise, return `minDistToNode` [S4, unofficial].

**Pseudocode:**
```python
def iterative_octree_traversal(ray_o, ray_d, octree_root, max_iterations):
    # Handle zero/negative directions
    dir_mask = 0
    d = list(ray_d)
    o = list(ray_o)
    for i in range(3):
        if d[i] == 0: d[i] = 0.001
        if d[i] < 0:
            o[i] = -o[i]
            d[i] = -d[i]
            dir_mask |= (1 << i)
            
    # Initial slab boundaries for root
    tx0 = (octree_root.min_x - o[0]) / d[0]
    tx1 = (octree_root.max_x - o[0]) / d[0]
    ty0 = (octree_root.min_y - o[1]) / d[1]
    ty1 = (octree_root.max_y - o[1]) / d[1]
    tz0 = (octree_root.min_z - o[2]) / d[2]
    tz1 = (octree_root.max_z - o[2]) / d[2]
    
    # State
    current_node = octree_root
    current_size = octree_root.size
    current_pos = octree_root.pos
    current_tx0, current_ty0, current_tz0 = tx0, ty0, tz0
    current_tx1, current_ty1, current_tz1 = tx1, ty1, tz1
    
    skip_list = [0] * 4
    parent_list = [0] * 4
    position_list = [(0.0, 0.0, 0.0)] * 4
    slab_list = [((0,0,0),(0,0,0))] * 4
    current_depth = 0
    min_dist = float('inf')
    
    for _ in range(max_iterations):
        # Leaf check
        if current_size <= 32:
            # Inline voxel raycast logic (AABB test)
            hit, t_hit = ray_aabb_intersect(o, d, current_pos, current_size)
            if hit and t_hit < min_dist:
                min_dist = t_hit
            break # Greedy approach assumes first valid leaf is closest
            
        # Internal node
        tm_x = (current_tx0 + current_tx1) / 2
        tm_y = (current_ty0 + current_ty1) / 2
        tm_z = (current_tz0 + current_tz1) / 2
        
        best_idx = -1
        best_dist = float('inf')
        best_slabs = None
        
        for i in range(8):
            if (skip_list[current_depth] >> i) & 1: continue
            
            # Compute child slabs based on octant i and dir_mask
            c_tx0, c_tx1 = current_tx0, tm_x
            c_ty0, c_ty1 = current_ty0, tm_y
            c_tz0, c_tz1 = current_tz0, tm_z
            
            if dir_mask & 1: c_tx0, c_tx1 = tm_x, current_tx1
            if dir_mask & 2: c_ty0, c_ty1 = tm_y, current_ty1
            if dir_mask & 4: c_tz0, c_tz1 = tm_z, current_tz1
            
            # Cull if exit <= current start or entry > min_dist
            child_exit = min(c_tx1, c_ty1, c_tz1)
            child_entry = max(c_tx0, c_ty0, c_tz0)
            if child_exit <= 0 or child_entry > min_dist: continue
            
            if child_entry < best_dist:
                best_dist = child_entry
                best_idx = i
                best_slabs = (c_tx0, c_ty0, c_tz0, c_tx1, c_ty1, c_tz1)
                
        if best_idx == -1:
            # Backtrack
            if current_depth == 0: break
            current_depth -= 1
            # Restore parent
            current_node = octree_root.children[parent_list[current_depth]]
            current_pos = position_list[current_depth]
            current_size = octree_root.size >> current_depth
            current_tx0, current_ty0, current_tz0 = slab_list[current_depth][0]
            current_tx1, current_ty1, current_tz1 = slab_list[current_depth][1]
            continue
            
        # Move to child
        position_list[current_depth] = current_pos
        parent_list[current_depth] = current_node.index
        skip_list[current_depth] |= (1 << best_idx)
        slab_list[current_depth] = ((current_tx0, current_ty0, current_tz0), (current_tx1, current_ty1, current_tz1))
        
        current_depth += 1
        current_node = octree_root.children[parent_list[current_depth-1] + best_idx]
        current_size /= 2
        current_pos = [current_pos[j] + (0 if not (best_idx & (1<<j)) else current_size) for j in range(3)]
        current_tx0, current_ty0, current_tz0 = best_slabs[0], best_slabs[1], best_slabs[2]
        current_tx1, current_ty1, current_tz1 = best_slabs[3], best_slabs[4], best_slabs[5]
        
    return min_dist if min_dist < float('inf') else -1

def ray_aabb_intersect(o, d, pos, size):
    t0 = [(pos[i] - o[i]) / d[i] for i in range(3)]
    t1 = [(pos[i] + size - o[i]) / d[i] for i in range(3)]
    t_enter = max(min(t0[i], t1[i]) for i in range(3))
    t_exit = min(max(t0[i], t1[i]) for i in range(3))
    if t_enter <= t_exit and t_exit > 0:
        return True, t_enter
    return False, float('inf')
```

## Subtopics

### [Octree Traversal with Fixed-Size Leaf Volumes](3900-octree-traversal-with-fixed-size-leaf-volumes.md)
This method accelerates sparse voxel octree (SVO) raycasting by enforcing a uniform leaf node size, thereby decoupling traversal depth from data sparsity and ensuring predictable memory access patterns. Unlike [Iterative Octree Traversal](2618-iterative-octree-traversal.md), which may vary leaf granularity, this approach fixes the leaf volume to 32x32x32 voxels, optimizing for hardware cache efficiency and reducing branch divergence in GPU warps, albeit at the cost of increased false-positive checks in noisy or dense regions.

### [Octree Traversal with LOD & Constant Nodes](4181-octree-traversal-with-lod-constant-nodes.md)
This method renders a Sparse Voxel Octree (SVO) on the CPU by traversing the hierarchy to project voxels into a color buffer, using depth-sorted traversal and hierarchical culling based on projected size. It distinguishes itself from sibling methods by supporting Level of Detail (LOD) switching between constant-value nodes and textured bricks. It builds on [Iterative Octree Traversal](2618-iterative-octree-traversal.md) by adding specific logic for constant node handling and brick texture sampling.

### [Ordered List Generation via N3-Tree Traversal](5023-ordered-list-generation-via-n3-tree-traversal.md)
This method generates a list of spatial bricks ordered from closest to furthest relative to the viewpoint to avoid testing blocks behind untested unloaded blocks. It solves the problem of unnecessary data loading by ensuring that visibility tests are performed in an order where any previously reached node cannot be occluded by a subsequently reached node. It sets itself apart from sibling methods by integrating view-dependent axis prioritization directly into a depth-first traversal of the N3-tree structure, followed by a lightweight distance sort.

### [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md)
Hierarchical Ray Marching is a sparse voxel traversal technique that dynamically switches between octree levels and voxel levels to optimize ray-marching performance. It differs from sibling methods by adjusting the traversal granularity up or down based on hit/miss status, allowing rapid skipping of empty regions at coarse levels and precise sampling at fine levels.

### [Ray-Direction Child Ordering](5462-ray-direction-child-ordering.md)
Ray-Direction Child Ordering is an iterative traversal optimization for sparse voxel octrees that processes child nodes in a sequence determined by the ray's direction, ensuring nodes closer to the ray origin are visited first. It solves the inefficiency of standard recursive traversal, which examines all eight children and performs redundant intersection tests for non-intersected subtrees, by using a deterministic neighbor-linking strategy to skip empty or non-intersected branches. Unlike its siblings, it avoids recursion entirely within a node's children by maintaining a `currNode` state and computing the next neighbor based on exit plane t-values, thereby reducing the number of intersection tests and improving performance on sparse structures.

### [Octree Iteration with Culling](11319-octree-iteration-with-culling.md)
Octree Iteration with Culling is a traversal method that visits only the leaf nodes of a sparse voxel octree that intersect a specified spatial region, typically an axis-aligned bounding box (AABB). It solves the problem of efficiently identifying relevant geometry for rendering or raycasting by skipping empty or non-intersecting subtrees, thereby reducing the number of nodes processed compared to a full tree traversal. It differs from sibling methods like [Octree Traversal with Fixed-Size Leaf Volumes](3900-octree-traversal-with-fixed-size-leaf-volumes.md) by supporting arbitrary leaf sizes and dynamic culling regions, and from [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md) by focusing on node enumeration rather than direct volume integration.

### [Single-kernel Octree Traversal](15600-single-kernel-octree-traversal.md)
Single-kernel octree traversal is a technique for traversing an octree for ray tracing by performing the entire traversal logic, including recursion simulation, within a single CUDA kernel execution per ray, rather than using multiple kernel launches for each recursion depth. It is preferred over multi-kernel recursion because kernel invocation overhead is high. Although single-kernel traversal may cause thread divergence due to the SIMD nature of GPUs, coherent rays in a warp traverse similarly, mitigating this issue.

### [ESVO (Efficient Sparse Voxel Octrees)](3089-esvo-efficient-sparse-voxel-octrees.md)
ESVO is a GPU-based ray casting algorithm that uses a Sparse Voxel Octree (SVO) to reduce voxel storage costs and enable real-time rendering of large scenes. It sets itself apart from sibling methods by using a compact 4-byte node encoding with a depth-first (z-curve) memory layout, which optimizes for localized memory access patterns on the GPU. Unlike [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md) which may use larger leaf nodes or different traversal strategies, ESVO relies on a near 1:1 port of the original implementation with specific pointer encoding changes to facilitate buffer-less tree construction.

### Non-Intersectable Node Omission
Optimization to avoid adding children to the stack if they cannot possibly intersect the ray closer than the current best intersection $t$ [S4, unofficial]. It uses precomputed slab boundaries of children [S4, unofficial]. If a child's minimum slab boundary $t_{i1}$ (for $i \in \{x,y,z\}$) is less than the current best intersection $t_{min}$, the child is guaranteed not to intersect closer than $t_{min}$ and is skipped [S4, unofficial]. Similarly, if a child's maximum slab boundary $t_{i0}$ is greater than $t_{max}$, the child is skipped [S4, unofficial]. Factors separating children of a node are defined as $((tx_0, ty_0, tz_0) + (tx_1, ty_1, tz_1)) \times 0.5$ [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** O(log s) in the ideal case, where s is the initial size of the Octree. The leaf raycasting is O(1) as it always processes a fixed 32x32x32 volume [S2, unofficial]. In the worst case (e.g., diagonal traversal through dense regions), it can approach O(s · log s) [S2, unofficial].
*   **Memory Complexity:** The stack simulation uses fixed-size arrays (e.g., depth 4), resulting in O(1) auxiliary memory for the traversal state itself, independent of tree depth [S2, unofficial].
*   **Strengths:** Eliminates recursion limits; greedy approach reduces unnecessary node visits; fixed-size leaves optimize cache usage [S2, S4, unofficial].
*   **Limitations:** False positives require backtracking, which can be costly; fixed leaf size may waste memory in sparse regions [S2, unofficial].
*   **When to use:** When targeting hardware without recursion support (GPUs, HLSL) or when stack depth is unpredictable [S2, S4, unofficial].
*   **When not to use:** When memory bandwidth is the primary bottleneck and node size is large, or when the scene is extremely dense with no empty space to skip [S2, unofficial].

## Background
Iterative Octree Traversal originated as a solution to the recursion limitations in HLSL (High-Level Shading Language) and GPU architectures, which do not support general method recursion [S2, S4, unofficial]. It was developed to enable real-time raycasting of sparse voxel octrees on GPUs by simulating the call stack explicitly [S2, unofficial]. The method is closely related to the ESVO (Efficient Sparse Voxel Octrees) algorithm, which popularized the use of small, localized node structures for fast traversal [S1, unofficial].
