# Two-Pass Hierarchy Traversal

Also called: Two-Step Hierarchy Traversal, Two-pass traversal

## Overview
Two-Pass Hierarchy Traversal is a spatial hierarchy traversal optimization that reduces computational cost by splitting the traversal process into two distinct phases: a coarse extraction of a subtree followed by a detailed traversal of that subtree. It solves the problem of high traversal overhead in participating media rendering by avoiding redundant checks for nodes that do not contribute to the final image. It differs from [Iterative Up-Down Tree Traversal](21243-iterative-up-down-tree-traversal.md) by explicitly decoupling the hierarchy exploration into a fixed-depth pre-pass and a variable-depth post-pass, rather than using a single unified state machine for descent and ascent.

## How it works
The method operates on a spatial hierarchy $\mathcal{H}$ (typically an octree) and a set of rays. The core mechanism involves determining the next node to process based on the ray's current position and the hierarchy's structure, but executed in two sequential stages.

### Inputs and Outputs
- **Input:**
  - The spatial hierarchy $\mathcal{H}$ (rooted tree).
  - A set of rays $R$ (primary or secondary).
  - A stopping depth parameter $d_{stop}$, defined as the number of levels above the leaves where the first traversal stops.
- **Output:**
  - A set of leaf nodes (or nodes satisfying the accuracy criterion) that the rays intersect, ready for shading/scattering computation.
  - A performance metric showing reduced traversal time compared to naive traversal.

### Data Structures
- **Hierarchy $\mathcal{H}$:** A tree where each node has a bounding volume (AABB) and up to 8 children (for octrees).
- **Subtree Buffer:** A temporary data structure storing the nodes identified in Step 1. This buffer contains the roots of the coarse subtrees that will be traversed in Step 2.
- **Ray State:** For each ray, the current intersection point and direction.

### Steps
1. **Step 1: Coarse Subtree Extraction**
   - Traverse the hierarchy $\mathcal{H}$ from the root for each ray.
   - Descend through the tree until the current node's depth relative to the leaves equals $d_{stop}$.
   - Record all nodes at this depth that are intersected by the ray. These nodes form the roots of the coarse subtrees.
   - If $d_{stop} = 0$, the traversal continues to the leaves, and Step 2 is skipped (performance equals naive traversal).

2. **Step 2: Detailed Traversal**
   - For each ray, restart the traversal starting from the nodes identified in Step 1.
   - Continue descending through the hierarchy until the accuracy criterion is met (typically reaching leaf nodes or nodes where scattering contributions are negligible).
   - Compute scattering contributions for the intersected leaf nodes.

### Parameters
- **Stopping Depth ($d_{stop}$):** The depth relative to the leaves where the first traversal stops.
  - Typical value: $d_{stop} = 3$. This produces a set of trees of depth 3, offering optimal performance.
  - Edge case: $d_{stop} = 0$ results in no performance gain, as the second step cost is null.

### Formulas
- **Performance Gain:** The method reduces traversal time by approximately 15% for the two-pass method alone at $d_{stop}=3$, and up to 30% when combined with tile sharing [S1].
- **Accuracy Criterion:** Traversal stops when the node satisfies the accuracy criterion, which is typically related to the scattering contribution becoming negligible (e.g., after one mean-free-path for single scattering) [S1].

### Pseudocode
```python
def two_pass_hierarchy_traversal(hierarchy, rays, stopping_depth):
    """
    Perform two-pass hierarchy traversal.
    
    Args:
        hierarchy: The root node of the spatial hierarchy.
        rays: List of rays to traverse.
        stopping_depth: Depth relative to leaves where first pass stops.
        
    Returns:
        List of intersected leaf nodes with scattering contributions.
    """
    all_results = []
    
    # Step 1: Extract coarse subtrees
    coarse_subtree_roots = []
    for ray in rays:
        current_node = hierarchy
        depth_from_leaves = get_depth_from_leaves(current_node)
        
        # Traverse down to stopping_depth
        while depth_from_leaves > stopping_depth:
            if ray_intersects_node(ray, current_node):
                # Check children and descend
                children = get_children(current_node)
                next_node = find_intersecting_child(ray, children)
                if next_node is None:
                    break
                current_node = next_node
                depth_from_leaves -= 1
            else:
                break
        
        # Record the node at stopping_depth
        if ray_intersects_node(ray, current_node):
            coarse_subtree_roots.append((ray, current_node))
            
    # Step 2: Traverse from coarse subtrees to leaves
    for ray, subtree_root in coarse_subtree_roots:
        current_node = subtree_root
        while not is_leaf(current_node):
            if ray_intersects_node(ray, current_node):
                children = get_children(current_node)
                next_node = find_intersecting_child(ray, children)
                if next_node is None:
                    break
                current_node = next_node
            else:
                break
        
        # Compute scattering contribution for the leaf node
        contribution = compute_scattering(ray, current_node)
        all_results.append((ray, current_node, contribution))
        
    return all_results

def get_depth_from_leaves(node):
    """Calculate the depth of a node relative to the leaves."""
    # Implementation depends on hierarchy structure.
    # Assumes each node stores its depth or height.
    return node.height

def ray_intersects_node(ray, node):
    """Check if a ray intersects a node's bounding volume."""
    return ray_aabb_intersection(ray, node.bounding_box)

def find_intersecting_child(ray, children):
    """Find the child node intersected by the ray."""
    for child in children:
        if ray_intersects_node(ray, child):
            return child
    return None

def compute_scattering(ray, leaf_node):
    """Compute scattering contribution for a leaf node."""
```

### Edge Cases and Pitfalls
- **Stopping Depth 0:** If $d_{stop} = 0$, the first traversal descends through the entire hierarchy, and the second step cost is null. Performance equals the direct implementation [S1].
- **Secondary Rays:** Do not apply the savings of tile sharing to secondary rays (rays that have bounced at least once) [S1].
- **Material Edges:** Do not apply tile sharing when the 2x2 pixels block covers an edge of the material [S1].
- **Precision:** Ensure that the depth calculation is accurate to avoid stopping at the wrong level.

## Subtopics

### Rendering Pipeline
In the context of the point-based rendering algorithm for participating media, the two-pass hierarchy traversal is integrated into a broader two-step rendering pipeline.
- **Step 1:** Trace rays from the camera through the scene. Each time a ray encounters translucent material, store it, along with its starting and end points, in an auxiliary buffer. This buffer contains all paths through the material, including primary rays and secondary rays (rays that reach the material after one or several bounces) [S1].
- **Step 2:** Treat all rays from this buffer, compute their single, double, and multiple scattering contributions, and add these to the corresponding pixel value. For each ray from the camera, after each bounce, compute the attenuation caused by material absorption and BRDF reflectance, and stop tracing when the attenuation is above a certain threshold. For single scattering, gather contributions only over a material layer of thickness $\ell$ (one mean-free-path), as it becomes negligible compared to multiple scattering after roughly one mean-free-path. For multiple scattering, group neighbouring rays together using 4x4 downsampling and interpolation [S1].

## Operating characteristics
- **Time Complexity:** The method reduces traversal time by approximately 15% for the two-pass method alone at optimal stopping depth ($d_{stop}=3$), and up to 30% when combined with tile sharing [S1].
- **Memory Complexity:** Requires additional memory for the auxiliary buffer storing rays and the coarse subtree buffer. The size of the auxiliary buffer depends on the number of rays per pixel, which varies with scene thickness (thinner regions require more rays) [S1].
- **Measured Performance:** In the GPU implementation of the point-based rendering algorithm for participating media, the method provides a 20% performance improvement over naive hierarchy traversal [S1].
- **Scaling:** Performance gain depends on the stopping depth. Best performance is achieved when the first step produces a set of trees of depth 3 [S1].
- **Strengths:** Reduces computational cost by discarding a large subset of the hierarchy before the second pass. Efficient for single scattering computations.
- **Limitations:** Not applicable to secondary rays or when material edges are involved in tile sharing. Performance gain diminishes if $d_{stop}$ is not optimized.

## Background
The Two-Pass Hierarchy Traversal method was introduced in the context of point-based rendering for homogeneous participating media with refractive boundaries. It was developed to address the high computational cost of traversing spatial hierarchies in participating media rendering, particularly for single and multiple scattering computations. The method was presented in the paper "Point-Based Rendering for Homogeneous Participating Media with Refractive Boundaries" [S1].
