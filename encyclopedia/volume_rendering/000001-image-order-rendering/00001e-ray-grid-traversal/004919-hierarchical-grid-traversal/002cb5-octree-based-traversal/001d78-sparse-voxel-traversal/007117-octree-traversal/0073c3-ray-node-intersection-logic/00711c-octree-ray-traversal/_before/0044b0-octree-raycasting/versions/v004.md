# Octree Raycasting

Also called: Ray-Octant Intersection

## Overview
An algorithm to find all octants in a pointer-based octree that intersect with a given ray, returning them sorted by distance (closest first) [S1, unofficial]. It uses parametric ray representation ($t$-values) to traverse the octree structure efficiently [S1, unofficial]. It distinguishes itself from [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by focusing on discrete octant traversal logic for pointer-based structures rather than dense voxel sampling, and from [Ray-Octree Boundary Intersection](11318-ray-octree-boundary-intersection.md) by operating on the internal hierarchy rather than just the root bounding box [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a pointer-based octree node; pre-computed entry/exit $t$-values for the current node's bounding box ($tx_0, ty_0, tz_0$ for entry; $tx_1, ty_1, tz_1$ for exit).
*   **Output:** A list of intersected octants sorted by distance from the ray origin.

**Data Structures:**
*   **Octree Node:** Contains a pointer to children (array of 8 nodes or null) and a bitmask/flag `RaycastingFlags` to handle child reordering or symmetry [S1, unofficial].
*   **RaycastingFlags:** A static constant holding a single value `value` used as a bitmask or index modifier for child array access [S1, unofficial].

**Steps:**
1.  **Intersection Check:** Verify if the ray intersects the current octant. Calculate the mean $t$-values for the center of the current octant:
    $$
    tx_m = 0.5 \cdot (tx_0 + tx_1), \quad ty_m = 0.5 \cdot (ty_0 + ty_1), \quad tz_m = 0.5 \cdot (tz_0 + tz_1)
    $$
    Check if the ray is behind the current octant or does not intersect it by verifying if $tx_1 < 0.0$, $ty_1 < 0.0$, or $tz_1 < 0.0$. If any are negative, return immediately [S1, unofficial].

2.  **Entry Octant Determination:** Determine the index of the first octant the ray enters within the current node using `findEntryOctant(tx_0, ty_0, tz_0, tx_m, ty_m, tz_m)`. This function maps ray-parametric intersections to discrete octant indices using axis-aligned comparisons [S1, unofficial].

3.  **Traversal Loop:** Loop through octants starting from `currentOctant` (the entry index) while `currentOctant < 8`.
    *   For each octant, recursively call `raycastOctant` with the appropriate $t$-value bounds for that child octant.
    *   Update `currentOctant` to the next intersected octant using `findNextOctant(currentOctant, tx_m, ty_m, tz_m)`.

4.  **Child Access:** Access the child node using the `RaycastingFlags` mask. For octants $i \in \{1, \dots, 7\}$, the child index is `children[f ^ i]`, where `f` is the flag value. Octant 0 uses `children[f]` [S1, unofficial].

5.  **Termination:** Octant 7 (far top right) is the last possible octant reachable from the entry point in this traversal order. After processing octant 7, the loop terminates by setting `currentOctant = 8` [S1, unofficial].

**Pseudocode:**
```python
def raycast_octant(node, tx0, ty0, tz0, tx1, ty1, tz1, result):
    # Check if ray is behind or misses the current octant
    if tx1 < 0.0 or ty1 < 0.0 or tz1 < 0.0:
        return

    # Calculate mean t-values for the center of the current octant
    tx_m = 0.5 * (tx0 + tx1)
    ty_m = 0.5 * (ty0 + ty1)
    tz_m = 0.5 * (tz0 + tz1)

    # Determine the entry octant index (0-7)
    current_octant = find_entry_octant(tx0, ty0, tz0, tx_m, ty_m, tz_m)

    # Loop through octants starting from the entry point
    while current_octant < 8:
        # Determine child index based on RaycastingFlags
        # f is a static constant bitmask for symmetry/reordering
        child_idx = children[f ^ current_octant] if current_octant > 0 else children[f]
        
        # Recursively process the child octant
        # Note: t-bounds for the child are derived from tx0/tx1 and the octant's spatial position
        # For octant 0 (closest), bounds are (tx0, ty0, tz0) to (tx_m, ty_m, tz_m)
        # For octant 7 (farthest), bounds are (tx_m, ty_m, tz_m) to (tx1, ty1, tz1)
        # Intermediate octants use mixed bounds based on their axis alignment
        if child_idx is not None:
            raycast_octant(child_idx, child_tx0, child_ty0, child_tz0, child_tx1, child_ty1, child_tz1, result)

        # Move to the next intersected octant
        if current_octant == 7:
            current_octant = 8  # Termination condition
        else:
            current_octant = find_next_octant(current_octant, tx_m, ty_m, tz_m)
```

**Parameters:**
*   $tx_0, ty_0, tz_0$: The ray projection parameters ($t$-values) at the entry point of the current octant for the x, y, and z axes respectively [S1, unofficial].
*   $tx_1, ty_1, tz_1$: The ray projection parameters ($t$-values) at the exit point of the current octant for the x, y, and z axes respectively [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Octant 7 Termination:** Octant 7 is the last possible octant reachable from the entry point. The loop must explicitly terminate after processing it by setting `currentOctant = 8` [S1, unofficial].
*   **Child Reordering:** The `RaycastingFlags` mask must be applied correctly to handle potential child reordering or symmetry in the octree structure [S1, unofficial].
*   **Zero Direction Components:** If the ray direction has zero components, division by zero may occur in intersection logic. This is typically handled by normalizing the ray direction to be strictly positive or using epsilon comparisons [S1, unofficial].

## Subtopics

### [Ray-Octree Boundary Intersection](11318-ray-octree-boundary-intersection.md)
Calculates the entry and exit distances of a ray relative to the bounding box of an octree root node. It serves as the core intersection test within the broader Octree Raycasting framework, determining if a ray intersects the octree's spatial bounds before initiating traversal.

### [Ray-Octant Traversal (Entry)](11321-ray-octant-traversal-entry.md)
Determines the index of the first octant a ray enters within a local 2×2×2 block of an octree, and the index of the subsequent octant the ray traverses. It maps ray-parametric intersections to discrete octant indices using axis-aligned comparisons.

### [Octree Raycasting (Point Intersection)](11324-octree-raycasting-point-intersection.md)
Finds specific points within a pointer-based octree that intersect with a given ray by iterating through all octants intersected by the ray and testing the points contained within those octants. It differs from sibling methods by focusing on discrete point data rather than continuous volume density or boundary surfaces.

## Operating characteristics
*   **Time Complexity:** Proportional to the number of intersected octants. In the worst case (ray passing through all occupied nodes), it is $O(N)$ where $N$ is the number of nodes. However, empty space skipping reduces this significantly for sparse data.
*   **Memory Complexity:** $O(D)$ where $D$ is the depth of the octree, due to recursion stack. On GPU, an explicit stack is required [G].
*   **Strengths:** Efficient for sparse data; avoids sampling empty space; returns intersected octants in sorted order (closest first) [S1, unofficial].
*   **Limitations:** Requires pointer-based octree structure; recursion depth can be an issue on hardware with limited stack size; not optimized for dense volume rendering without additional leaf-level sampling strategies.
*   **When to Use:** When discrete octant intersection is required (e.g., for point clouds, boundary detection, or as a pre-pass for volume rendering).
*   **When Not to Use:** For dense volume rendering where voxel-level sampling is needed; consider [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) instead.

## Background
Originated from the `sparse-octree` module by vanruesc [S1, unofficial]. The method is designed for efficient ray intersection with pointer-based octrees, commonly used in computer graphics for spatial partitioning of sparse data.
