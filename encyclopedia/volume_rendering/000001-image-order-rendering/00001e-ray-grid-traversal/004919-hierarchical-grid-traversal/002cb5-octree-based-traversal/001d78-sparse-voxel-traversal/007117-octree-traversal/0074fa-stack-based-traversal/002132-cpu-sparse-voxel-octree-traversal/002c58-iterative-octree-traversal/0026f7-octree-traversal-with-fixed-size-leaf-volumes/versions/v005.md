# Octree Traversal with Fixed-Size Leaf Volumes


## Overview
This method accelerates sparse voxel octree (SVO) raycasting by enforcing a uniform leaf node size, decoupling traversal depth from data sparsity and ensuring predictable memory access patterns [S1, unofficial]. Unlike [Iterative Octree Traversal](2618-iterative-octree-traversal.md), which may vary leaf granularity, this approach fixes the leaf volume to 32×32×32 voxels, optimizing for hardware cache efficiency and reducing branch divergence in GPU warps, at the cost of increased false-positive checks in noisy or dense regions [S1, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized), octree root node, volume side length $s$ (cubic $s \times s \times s$), fixed leaf size $L = 32$ voxels [G].
**Outputs:** Intersection point or null if no leaf is hit [G].
**Data Structures:**
- **Skip List (`skipListPerDepth`):** Array of bitmasks, one per depth level. Each bit $i$ indicates the $i$-th child of a node at that depth has been visited or determined empty for the current ray, preventing redundant checks [S1, unofficial].
- **Node State:** Indicates if a node is a leaf or internal [G].
- **Current Depth Variable (`currentDepthVariable`):** Tracks the depth of the current node in the traversal [S1, unofficial].
**Steps:**
1. **Initialization:** Set `currentDepthVariable` to 0. Initialize `skipListPerDepth` for all possible depths to 0 [G]. Start traversal at the root node [G].
2. **Traversal Loop:** While the current node is not a leaf:
   - Determine the child index $i$ (0–7) that the ray enters next, typically calculated using the ray's direction and the node's bounding box [G].
   - Check if bit $i$ is set in `skipListPerDepth[currentDepthVariable]`. If set, the child has been processed; skip to the next sibling or backtrack [G].
   - If not set, proceed to the child. Mark the current child as visited by setting bit $i$ in the skip list: `skipListPerDepth[currentDepthVariable] |= (1 << i)` [S1, unofficial].
   - Save the index and position of the current parent node, then increment `currentDepthVariable` to traverse one level deeper into the tree [S1, unofficial].
   - Move to the selected child node [G].
3. **Leaf Processing:** Once a leaf node is reached, examine the 32×32×32 voxel volume contained within it [S1, unofficial]. Perform ray-voxel intersection tests within this fixed-size block to find the first occupied voxel [G]. If an intersection is found, return the result [G]. If no intersection is found in this leaf, backtrack to the parent and continue searching other siblings [G].
**Formulas:**
- **Diagonal Leaf Count:** The number of leaf nodes along the main diagonal of the volume is derived from the Pythagorean theorem: $tcountNodes = \frac{s}{64} \cdot 3 \cdot \left(\frac{s}{32}\right)^2$ [S1, unofficial].
- **Worst-Case Complexity:** Total steps: $tTotalCount = tcountNodes \cdot \log s + 3 \cdot 32^2$ [S1, unofficial]. Asymptotically, this simplifies to $O(s \cdot \log s)$ [S1, unofficial].
Symbols: $s$ is volume side length, $tcountNodes$ is diagonal leaf count, $tTotalCount$ is total worst-case steps.
**Parameters:** Leaf size $L = 32$ voxels [S1, unofficial]. Volume side $s$ [G].
**Edge Cases and Pitfalls:**
- Noise in volume data significantly reduces efficiency by causing false positives along the ray direction, forcing examination of unnecessary leaf nodes [S1, unofficial].
- Unpredictable precision errors may cause rays to miss voxels or return incorrect results, often requiring post-processing (e.g., median filtering) [S1, unofficial].
**Pseudocode:**
```python
def traverse_octree_fixed_leaf(root, ray_origin, ray_direction, volume_side_s):
    current_depth = 0
    # Initialize skip list for all possible depths. Not given in the sources. [G]
    skip_list_per_depth = [0] * 64
    stack = [(root, 0)]
    node, current_depth = stack.pop()
    while not node.is_leaf():
        # Determine child index 0-7 based on ray direction and node bounding box. Not given in the sources. [G]
        child_index = (ray_direction.x > 0) | ((ray_direction.y > 0) << 1) | ((ray_direction.z > 0) << 2)
        if (skip_list_per_depth[current_depth] >> child_index) & 1:
            # Child already visited; backtrack to parent. Not given in the sources. [G]
            if stack:
                node, current_depth = stack.pop()
            else:
                return None
            continue
        # Mark child as visited: shift 1 left by child_index and bitwise OR with current value [S1, unofficial]
        skip_list_per_depth[current_depth] |= (1 << child_index)
        # Save index and position of current parent node, then increment depth to traverse deeper [S1, unofficial]
        stack.append((node, current_depth))
        current_depth += 1
        node = node.children[child_index]
    # Leaf reached: examine the 32x32x32 voxel volume contained within it [S1, unofficial]
    # Perform ray-voxel intersection within the fixed block. Not given in the sources. [G]
    return examine_fixed_leaf_volume(node, ray_origin, ray_direction)
```

## Subtopics

### Iterative Octree Traversal (BFS)
This variant traverses an octree using Breadth-First Search (BFS) to extract plane parameters from leaf nodes into a `Planes` structure for each voxel [S2, unofficial]. It is distinct in its explicit plane parameter extraction and queue-based traversal, suitable for Gaussian Splatting applications where per-voxel plane data is required [S2, unofficial]. Choose it when BFS ordering and explicit plane attribute extraction are needed rather than standard depth-first raycasting [S2, unofficial]. See [Iterative Octree Traversal](2618-iterative-octree-traversal.md) [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Best-case is $O(\log s)$ per voxel, where $s$ is the volume side length, occurring when the ray hits a leaf quickly [S1, unofficial]. Worst-case is $O(s \cdot \log s)$, occurring when every 32×32×32 leaf node along the diagonal through the volume center must be examined [S1, unofficial].
- **Memory Complexity:** Depends on the octree structure, with smaller leaf sizes increasing memory usage and larger leaf sizes improving efficiency for sparse data [S1, unofficial].
- **Measured Performance:** Measured performance on specific hardware, resolution, and scene: Not given in the sources. [G]
- **Scaling:** Larger leaf sizes improve efficiency for sparse data but increase false positives; smaller leaf sizes reduce false positives but increase octree memory usage [S1, unofficial].
- **Strengths:** Predictable performance, reduced branch divergence, optimized for fixed-size hardware caches [S1, unofficial].
- **Limitations:** Sensitive to noise, potential for false positives in dense regions, fixed leaf size may not be optimal for all data distributions [S1, unofficial].
- **When to use/not:** Use for sparse voxel data where cache efficiency and low warp divergence are prioritized [S1, unofficial]. Avoid for highly noisy or uniformly dense volumes where false-positive overhead dominates [S1, unofficial].
