# Iterative Up-Down Tree Traversal

Also called: Iterative ascent-descent traversal, Up-Down method

## Overview
Iterative Up-Down Tree Traversal is a hierarchical grid traversal algorithm for octrees that avoids restarting the search from the root node when transitioning between cells [S1]. It leverages the current node's position awareness to determine if the next cell is a sibling or child, and if not, it ascends the tree until an internal transition is found, then descends to the leaf [S1]. Unlike the standard top-down method which starts the search from the root node for every transition, this method uses local tree structure knowledge to minimize traversal distance, avoiding the overhead of root-to-leaf searches for non-internal transitions [S1].

## How it works
**Inputs:**
*   Ray $R(t) = \mathbf{o} + t\mathbf{d}$.
*   Hierarchical octree $\mathcal{H}$ where each node $N$ has a bounding volume (AABB), pointers to children (if internal), and a pointer to its parent.
*   Current node $N_{curr}$ (initially the root or the leaf node from the previous ray step).
*   Current entry distance $t_{entry}$ and exit distance $t_{exit}$ for $N_{curr}$.

**Outputs:**
*   The leaf node $N_{leaf}$ intersected by the ray following the transition from $N_{curr}$.
*   Updated $t_{entry}$ and $t_{exit}$ for $N_{leaf}$.

**Data Structures:**
*   Node structure: Contains AABB bounds, boolean `is_leaf`, array of 8 child pointers (null if leaf), and parent pointer.
*   Ray parameters: Origin $\mathbf{o}$, direction $\mathbf{d}$, current interval $[t_{entry}, t_{exit}]$.

**Definitions:**
*   **Internal Transition:** A transition through a cell wall that does not leave the parent cell's bounds [S1].
*   **External Transition:** A transition through a cell wall that leaves the parent cell's bounds [S1].

**Algorithm Steps:**

1.  **Check Transition Type:** Determine if the transition from $N_{curr}$ to the next cell is an internal transition. This is done by checking if the ray exits $N_{curr}$ through a face that is shared with a sibling node (i.e., the exit point is still within the parent's AABB) [S1].
2.  **Handle Internal Transition:** If the transition is internal:
    *   Identify the next cell as one of the current node's siblings [S1].
    *   If the sibling is not a leaf node, descend into its children to find the next leaf [S1].
    *   Update $N_{curr}$ to this new leaf node.
3.  **Handle External Transition:** If the transition is not internal (i.e., the ray leaves the parent's bounds):
    *   **Ascent:** Iteratively move up the tree starting from $N_{curr}$ (i.e., set $N_{curr} = N_{curr}.parent$) until the transition becomes an internal transition relative to the new current node [S1]. This means finding the lowest ancestor where the ray exit from the previous node was an internal transition relative to that ancestor.
    *   **Descent:** Once an internal transition is identified during the ascent, iteratively descend the tree from that node until a leaf node is reached [S1].
    *   Update $N_{curr}$ to this new leaf node.
4.  **Process Leaf:** Shade or scatter at the identified leaf node.

**Parameters:**
*   Implementation complexity: High. Described as the most complex of the three presented methods in terms of implementation [S1].
*   Memory overhead: None [S1].
*   Additional computations: None [S1].

**Edge Cases and Pitfalls:**
*   **Root Handling:** The source does not specify behavior if the ascent reaches the root without finding an internal transition. [G] In practice, this may require restarting the traversal from the root or treating the root's exit as a special case.
*   **Precision:** Floating-point precision errors in `point_in_aabb` checks may lead to incorrect classification of internal vs. external transitions. [G] Epsilon comparisons should be used.
*   **Degenerate Input:** Rays tangent to cell walls may cause ambiguous transition classifications. [G] Robust intersection tests are required.

## Operating characteristics
*   **Time Complexity:** Depends on the tree depth and the number of ascents/descents. In the best case (internal transitions), it is $O(1)$ per step (sibling lookup). In the worst case, it may require $O(D)$ ascents and $O(D)$ descents, where $D$ is the tree depth.
*   **Memory Complexity:** $O(1)$ additional memory, as it uses the existing tree structure and pointers [S1].
*   **Strengths:** No memory overhead, no additional computations, applicable to regular and barycentric octree grids [S1]. Avoids the overhead of root-to-leaf searches for non-internal transitions [S1].
*   **Limitations:** High implementation complexity [S1].
*   **When to use:** When memory is constrained and implementation complexity is acceptable. Suitable for regular and barycentric octree grids [S1].
*   **When not to use:** When implementation simplicity is prioritized over traversal efficiency.

## Background

*   **History:** It is presented as an alternative to the standard top-down method and a two-pass hierarchy traversal method [S1].
