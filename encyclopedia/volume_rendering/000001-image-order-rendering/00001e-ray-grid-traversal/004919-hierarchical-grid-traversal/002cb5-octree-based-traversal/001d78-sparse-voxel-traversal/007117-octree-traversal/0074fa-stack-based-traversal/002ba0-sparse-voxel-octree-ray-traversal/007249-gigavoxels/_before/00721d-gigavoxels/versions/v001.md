# GigaVoxels

Also called: GigaVoxels rendering engine

## Overview
GigaVoxels is a real-time rendering engine for large, detailed scenes that uses a pre-filtered volumetric geometry representation and voxel-based approximate cone tracing, implemented in CUDA on GPU [S1, unofficial]. It solves the problem of rendering massive volumetric datasets by exploiting the fact that details are concentrated on interfaces, using a Sparse Voxel Octree (SVO) to serve as a rendering primitive [S1, unofficial]. Unlike its siblings which may focus on static storage or different traversal strategies, GigaVoxels is defined by its adaptive hierarchical data representation dependent on the current view, coupled with a GPU cache mechanism for video memory paging and a producer/renderer pipeline [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** User-defined Producer (procedural generation or file streaming) and Shader (visualization logic). The system ingests spatial positions of nodes and voxels.
*   **Outputs:** Rendered image with high-quality filtering, transparency handling, and automatic Level of Detail (LOD) adjustment [S1, unofficial].

**Data Structures:**
The data structure unifies geometry and texture [S1, unofficial]. It consists of:
1.  **Spatial Accelerator:** An $N^3$ Tree, typically an Octree ($N=2$) [S1, unofficial].
2.  **User Voxels:** Stored in **voxel bricks** [S1, unofficial].
3.  **Node Tiles:** Nodes are grouped into node tiles [S1, unofficial].
4.  **Configuration:** The user defines the tree dimension ($N=2$) and the brick size (e.g., $8 \times 8 \times 8$) [S1, unofficial].
5.  **Voxel Content:** Defined by a list of types (e.g., `uchar4`, `float4`, `float`) [S1, unofficial].
6.  **Storage Format:** Each data type (color, normal, density, etc.) is stored as a 3D texture accessible for read/write to benefit from hardware interpolation during sampling [S1, unofficial].

**Pipeline Components:**
1.  **Cache System:** A generic GPU-implemented LRU (Least Recently Used) mechanism to recycle least recently used data [S1, unofficial].
2.  **Producer:** Responds to cache requests to subdivide a spatial structure node or produce/load a voxel brick [S1, unofficial].
3.  **Renderer:** Traverses the spatial structure during ray casting and emits requests for subdivision or voxel production based on node content [S1, unofficial].
4.  **Shader:** Samples the 3D texture at the current spatial position along the ray and performs shading (e.g., Blinn/Phong) [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Define the $N^3$ Tree dimension ($N=2$) and voxel brick size (e.g., $8 \times 8 \times 8$) [S1, unofficial]. Define the list of voxel data types [S1, unofficial].
2.  **Ray Casting Traversal:** The Renderer traverses the spatial structure [S1, unofficial].
3.  **Request Emission:** Based on node content, the Renderer emits requests for:
    *   Spatial subdivision (refinement) of a node [S1, unofficial].
    *   Production/loading of a voxel brick [S1, unofficial].
4.  **Producer Response:**
    *   *For Subdivision:* The Producer determines if a region is empty or contains data based on provided spatial positions of nodes and voxels [S1, unofficial].
    *   *For Voxel Brick:* The Producer either procedurally generates values for each data type in a voxel or reads/loads the associated data file [S1, unofficial].
5.  **Caching:** Produced/loaded data is stored in the GPU cache (3D textures) [S1, unofficial].
6.  **Shading:** The Shader uses the current spatial position along the ray to sample the 3D texture containing the data [S1, unofficial].
7.  **Rendering:** The Shader performs shading (e.g., Blinn/Phong). Normals can be stored in the voxel data or calculated in the shader using a gradient [S1, unofficial].

**Procedural Generation Example (Mandelbulb):**
For procedural generation of fractal objects like the Mandelbulb, the following formulas are used [S1, unofficial]:
$$
\begin{aligned}
r &= \sqrt{x^2 + y^2 + z^2} \\
\theta &= \arctan(y/x) \\
\phi &= \arctan(z/\sqrt{x^2 + y^2}) = \arcsin(z/r) \\
x', y', z' &= r^n \begin{pmatrix} \cos(n\theta)\cos(n\phi) \\ \sin(n\theta)\cos(n\phi) \\ \sin(n\phi) \end{pmatrix}
\end{aligned}
$$
where $n$ is the power parameter [S1, unofficial].

**Dynamic Loading Modes:**
*   Load the highest resolution level directly [S1, unofficial].
*   Load successive LOD levels from lowest to highest resolution [S1, unofficial].

**Pseudocode:**
```python
# GigaVoxels Pipeline Implementation
# Note: This is a high-level representation of the pipeline described in [S1, unofficial].
# Actual implementation requires CUDA kernels for the cache, renderer, and producer.

class GigaVoxelsEngine:
    def __init__(self, tree_dim=2, brick_size=(8, 8, 8), data_types=['float4', 'float']):
        self.tree_dim = tree_dim
        self.brick_size = brick_size
        self.data_types = data_types
        self.cache = GPUCacheLRU()
        self.svo = SparseVoxelOctree(dim=tree_dim)
        self.producer = None
        self.shader = None

    def set_producer(self, producer):
        """User defines the Producer."""
        self.producer = producer

    def set_shader(self, shader):
        """User defines the Shader."""
        self.shader = shader

    def render_ray(self, ray_origin, ray_direction):
        """
        Renderer traverses the SVO and emits requests.
        """
        current_node = self.svo.root
        t = 0.0
        
        while current_node is not None:
            # Check node content to decide action
            if current_node.is_leaf():
                # Request voxel brick if not in cache
                brick_key = current_node.get_brick_key()
                if not self.cache.has(brick_key):
                    self.producer.load_or_generate_brick(brick_key, self.brick_size, self.data_types)
                    self.cache.put(brick_key)
                
                # Sample voxel data
                voxel_data = self.cache.sample(brick_key, ray_origin + t * ray_direction)
                
                # Perform shading
                color = self.shader.shade(voxel_data, ray_origin + t * ray_direction)
                return color
            else:
                # Request subdivision if needed
                if not self.svo.is_subdivided(current_node):
                    # Producer determines if region is empty or has data
                    has_data = self.producer.check_region_content(current_node.spatial_position)
                    if has_data:
                        self.svo.subdivide(current_node)
                    else:
                        # Region is empty, skip
                        return background_color
                
                # Traverse to child node
                current_node = self.svo.get_child(current_node, ray_direction)
                t += self.svo.get_step_size(current_node)

        return background_color

    def procedural_mandelbulb(self, x, y, z, n=8):
        """
        Procedural generation example for Mandelbulb [S1, unofficial].
        """
        r = math.sqrt(x**2 + y**2 + z**2)
        theta = math.atan2(y, x)
        phi = math.asin(z / r) if r > 0 else 0
        
        new_r = r ** n
        new_x = new_r * math.cos(n * theta) * math.cos(n * phi)
        new_y = new_r * math.sin(n * theta) * math.cos(n * phi)
        new_z = new_r * math.sin(n * phi)
        
        return new_x, new_y, new_z
```

## Background
GigaVoxels was developed to allow real-time exploration and visually realistic rendering of immense detailed scenes [S1, unofficial]. It is based on the performance and features of massively parallel graphics processors (GPUs) [S1, unofficial]. The system was illustrated with applications such as the Mandelbulb fractal, aneurysm models, and foot models imported from RAW files [S1, unofficial]. The approach leverages the fact that in CG scenes, details are often concentrated on their interface [S1, unofficial].
