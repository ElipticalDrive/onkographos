# Stackless BVH Traversal

Also called: GPU BVH traversal without stack, Linear pointer-based BVH traversal

## Overview
Stackless BVH Traversal is a ray traversal algorithm for Axis-Aligned Bounding Box (AABB) hierarchies that avoids explicit stack allocation by using a linear pointer-based approach, suitable for GPU execution where stack depth is limited or unavailable [S1, unofficial]. It differs from stack-based BVH traversal [BVH Ray Traversal with Stack](22168-bvh-ray-traversal-with-stack.md) by eliminating the need for dynamic memory allocation or fixed-size stack buffers, relying instead on a pre-ordered linear array of nodes where traversal order is encoded in the node structure itself.

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $O$ and direction $D$, a linear array of BVH nodes `BVHNodes`, a linear array of triangle data `BVHTris`, a starting index `NodeStartIndex` (typically 0), and a maximum traversal distance $T_{max}$ (initially $\infty$).
*   **Output:** The closest intersection distance $t$, the triangle index, and the mesh identifier.

**Data Structures:**
Each node in `BVHNodes` is 32 bytes, packed into two `vec4` structures (`Min` and `Max`).
*   `Min` (vec4):
    *   `x, y, z`: AABB minimum coordinates.
    *   `w`: Packed integer.
        *   If the node is a **leaf**: Lower 4 bits (`& 0xF`) store the triangle count (`Length`). Upper bits (`>> 4`) store the starting index into the `BVHTris` array.
        *   If the node is **internal**: This field is not used for traversal logic in this specific implementation.
*   `Max` (vec4):
    *   `x, y, z`: AABB maximum coordinates.
    *   `w`: Packed integer.
        *   If the node is a **leaf**: This field is not used for traversal logic.
        *   If the node is **internal**: Stores the index of the next node to visit in the linear array. A value of -1 indicates the end of traversal for that branch.

**Algorithm Steps:**
1.  Initialize `Pointer` to `NodeStartIndex`.
2.  Initialize `ClosestTraversal` to -1.0f and `TMax` to the initial maximum distance.
3.  Initialize `Iterations` to 0.
4.  Loop while `Pointer >= 0` and `Iterations < MaxIterations` (1024):
    a.  Fetch `CurrentNode = BVHNodes[Pointer]`.
    b.  Compute `BoxTraversal` (intersection of ray with AABB defined by `CurrentNode.Min.xyz` and `CurrentNode.Max.xyz`).
    c.  If `BoxTraversal > 0.0f` and `BoxTraversal < TMax`:
        i.  Check if `CurrentNode` is a leaf: `IsLeaf = (floatBitsToInt(CurrentNode.Min.w) != -1)`.
        ii. If `IsLeaf`:
            1.  Extract `StartIndex = CurrentNode.Min.w >> 4`.
            2.  Extract `Length = CurrentNode.Min.w & 0xF`.
            3.  Iterate `i` from `StartIndex` to `StartIndex + Length - 1`:
                *   Compute ray-triangle intersection for triangle `BVHTris[i]`.
                *   If hit distance $t < TMax$:
                    *   Update `TMax = t`.
                    *   Update `ClosestTraversal = t`.
                    *   Store mesh and triangle index.
            4.  Set `Pointer = floatBitsToInt(CurrentNode.Max.w)`.
        iii. If not `IsLeaf`:
            1.  Increment `Pointer` by 1 (`Pointer++`).
    d.  Else (node did not intersect or intersection is beyond $T_{max}$):
        i.  Set `Pointer = floatBitsToInt(CurrentNode.Max.w)`.
    e.  If `Pointer < 0`, break loop.
    f.  Else, `Pointer += NodeStartIndex` (if `NodeStartIndex` is non-zero, otherwise this is a no-op).
    g.  Increment `Iterations`.

**Pseudocode:**
```python
def stackless_bvh_traverse(ray_origin, ray_dir, bvh_nodes, bvh_tris, node_start_index=0, t_max=float('inf'), t_min=0.0001f, max_iterations=1024):
    pointer = node_start_index
    closest_t = -1.0
    current_t_max = t_max
    
    for iteration in range(max_iterations):
        if pointer < 0:
            break
            
        current_node = bvh_nodes[pointer]
        
        # Compute AABB intersection
        box_t_min = ray_bounds(ray_origin, ray_dir, current_node.min.xyz, current_node.max.xyz, t_min, current_t_max)
        
        if box_t_min > 0.0 and box_t_min < current_t_max:
            # Check if leaf: Min.w != -1 indicates leaf in this specific packing
            is_leaf = (float_bits_to_int(current_node.min.w) != -1)
            
            if is_leaf:
                # Leaf processing
                packed_min_w = current_node.min.w
                start_index = packed_min_w >> 4
                length = packed_min_w & 0xF
                
                for i in range(start_index, start_index + length):
                    tri = bvh_tris[i]
                    hit_t = ray_triangle_intersect(ray_origin, ray_dir, tri)
                    
                    if hit_t is not None and hit_t < current_t_max:
                        current_t_max = hit_t
                        closest_t = hit_t
                        # Store mesh/triangle index here
                        pass
                
                # Move to next node specified in Max.w
                pointer = float_bits_to_int(current_node.max.w)
            else:
                # Internal node: advance to next sequential node
                pointer += 1
        else:
            # Node did not intersect or was too far; move to next node specified in Max.w
            pointer = float_bits_to_int(current_node.max.w)
            
        if pointer < 0:
            break
            
        # Adjust pointer if start index is non-zero (implementation detail from source)
        if node_start_index != 0:
            pointer += node_start_index
            
    return closest_t
```

**Parameters:**
*   `MaxIterations`: 1024. Prevents infinite loops in malformed BVHs [S1, unofficial].
*   `TMin`: 0.0001f. Used in `RayBounds` to avoid self-intersection or precision errors at the ray origin [S1, unofficial].

**Edge Cases and Pitfalls:**
*   The traversal assumes a linearized BVH where children are stored sequentially. Non-leaf nodes simply advance to the next index (`Pointer++`), implying the BVH is built in a specific depth-first or breadth-first order that allows linear traversal without explicit left/right child pointers for internal nodes [S1, unofficial].
*   Malformed BVHs with cycles or incorrect `Max.w` pointers can cause infinite loops; `MaxIterations` acts as a safeguard.
*   Precision errors near `TMin` are mitigated by the clamping value.

## Operating characteristics
*   **Time Complexity:** $O(N)$ in the worst case for traversal, where $N$ is the number of nodes visited. The linear scan avoids stack push/pop overhead but may visit nodes in a less optimal order than a stack-based approach if the BVH is not built for linear traversal.
*   **Memory Complexity:** $O(1)$ auxiliary memory. No stack allocation is required, making it ideal for GPU shaders with limited stack space.
*   **Strengths:** No stack overflow risk; simple implementation; low memory footprint.
*   **Limitations:** Relies on a specific BVH build order (linearization); potentially less efficient culling if the linear order does not align with spatial locality as well as a stack-based DFS/BFS.
*   **When to use:** GPU ray tracing where stack size is constrained or dynamic allocation is prohibited.
*   **When not to use:** CPU ray tracing where stack allocation is cheap and BVHs are not pre-linearized for this specific traversal pattern.

This method is derived from implementations found in unofficial graphics repositories, specifically designed for GPU-based rendering where traditional stack-based recursion is impractical [S1, unofficial]. It represents a variation of linear BVH traversal techniques adapted for specific node packing schemes.
