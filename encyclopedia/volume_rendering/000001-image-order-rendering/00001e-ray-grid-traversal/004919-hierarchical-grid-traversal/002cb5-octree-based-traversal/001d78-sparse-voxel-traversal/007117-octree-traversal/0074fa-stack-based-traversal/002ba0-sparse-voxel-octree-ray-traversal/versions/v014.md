# Sparse Voxel Octree Ray Traversal

Also called: OctreeSimple Shader, SVO Traversal, Sparse Voxel Octree (SVO) Traversal, Sparse Voxel Octree Tracing

## Overview
Sparse Voxel Octree (SVO) Ray Traversal is a hierarchical raycasting technique that renders volumetric data stored in a 3D sparse octree by traversing the tree along ray paths to find occupied leaf nodes (voxels) [S2, S4, S6, unofficial]. It solves the problem of efficiently rendering large, sparse 3D datasets without the memory overhead of dense voxel grids by skipping empty space via axis-aligned slab intersection logic [S3, S4, unofficial]. It differs from [GigaVoxels](3057-gigavoxels.md) by not relying on a fixed-resolution texture-based cache, and from [Sparse Voxel Octree Ray Traversal (State Machine)](3299-sparse-voxel-octree-ray-traversal-state-machine.md) by explicitly managing a stack to control visitation order based on eye position [S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (in world or octree space), the SVO data structure (flat array of nodes), camera parameters (FOV, viewport size) [S5, S6, S9, unofficial].
*   **Outputs:** Hit position, surface normal, and color of the first occupied voxel intersected by the ray [S4, S6, unofficial].

**Data Structures:**
The SVO is stored as a flat array of integers or structs [S7, unofficial]. Common layouts include:
1.  **Node Struct:** Contains `childrenStartIndex` (pointer to first child) and `data` (bitfield indicating if the node holds voxel data or is empty) [S3, unofficial].
2.  **Integer Encoding:** A 32-bit integer where bit 31 indicates type (0=Pointer to children, 1=Voxel/Leaf) and bits 0-30 store the pointer to child nodes or attribute data [S4, unofficial].
3.  **Stack:** An explicit stack (on GPU) or recursion (on CPU) to handle backtracking when a ray exits a subtree [S4, S6, unofficial][S8]. The stack stores node addresses, traversal state (e.g., `t_min`, `frontal_mask`), and depth [S9, unofficial].

**Numbered Steps:**
1.  **Ray Initialization:** Generate ray origin $\mathbf{o}$ and direction $\mathbf{d}$ for each pixel from the camera [S5, S6, S9, unofficial]. Transform $\mathbf{o}$ and $\mathbf{d}$ into octree space if necessary (e.g., shifting origin by +1.0 to handle boundary conditions) [S4, S7, unofficial]. Clamp small direction components to $\epsilon$ (e.g., $10^{-4}$) to prevent division by zero during slab intersection calculations [S7, S9, unofficial].
2.  **Root Intersection:** Compute the intersection of the ray with the root bounding box (AABB) using the slab method [S1, S9, unofficial]. For each axis $k \in \{x, y, z\}$:
    $$ t_{min_k} = \frac{boxMin_k - o_k}{d_k}, \quad t_{max_k} = \frac{boxMax_k - o_k}{d_k} $$
    Swap $t_{min_k}$ and $t_{max_k}$ if $t_{min_k} > t_{max_k}$ [S1, S9, unofficial]. Calculate entry $t_{entry} = \max(t_{min_x}, t_{min_y}, t_{min_z})$ and exit $t_{exit} = \min(t_{max_x}, t_{max_y}, t_{max_z})$ [S1, S9, unofficial]. If $t_{entry} > t_{exit}$ or $t_{exit} < 0$, the ray misses the octree; return background color [S1, S9, unofficial].
3.  **Traversal Loop:** Initialize traversal state: `node_address` = root index, `depth` = 0, `scale` = root size, `t_min` = $t_{entry}$ [S9, unofficial]. Determine `dir_mask` based on ray direction signs [S9, unofficial]. Loop while `depth` < `MAX_DEPTH`:
    a.  **Fetch Node:** Load node value from `SVO[node_address]` [S9, unofficial].
    b.  **Check Type:**
        *   If **Internal Node** (bit 31 set): Push current `node_address`, `t_min`, and `frontal_mask` to the stack [S9, unofficial]. Halve `scale`. Update `node_address` to the child address extracted from the node value (`value & 0x7FFFFFFF`) [S9, unofficial]. Update `t_min` and `t_corner` based on the new child's boundaries [S9, unofficial].
        *   If **Leaf Node** (value > 0 and bit 31 clear): The ray has hit a voxel [S9, unofficial]. Break traversal loop [S9, unofficial].
        *   If **Empty Node** (value == 0): Advance `t_min` to `t_corner_max` [S9, unofficial]. Step `t_corner` along axes where `t_corner <= t_corner_max` [S9, unofficial]. Update `frontal_mask` by XORing with `step_mask` [S9, unofficial]. If no axes remain to step, pop the stack to backtrack [S9, unofficial].
4.  **Backtracking:** Pop the stack to restore `node_address`, `t_min`, `scale`, and `depth` [S9, unofficial]. Determine the next child to visit using the updated `frontal_mask` and `dir_mask` [S9, unofficial].
5.  **Leaf Handling:** Upon reaching a leaf, sample the voxel data (color, normal) [S1, S4, S6, unofficial]. Compute the normal from the ray-AABB intersection face if not stored [S1, S7, unofficial]. Return the hit color and position [S4, S6, unofficial].

**Pseudocode:**
```python
def traverse_svo(ray_origin, ray_direction, svo_data, root_min, root_max, max_depth=32):
    # 1. Ray Initialization
    eps = 1e-4
    dir = ray_direction.copy()
    for i in range(3):
        if abs(dir[i]) < eps:
            dir[i] = eps if dir[i] >= 0 else -eps
    inv_dir = 1.0 / dir
    
    # 2. Root Intersection (Slab Method)
    t1 = [(root_min[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    t2 = [(root_max[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    t_min = max(t1)
    t_max = min(t2)
    if t_min > t_max or t_max < 0:
        return None, None, None
        
    # 3. Traversal State
    node_address = 0
    depth = 0
    scale = 0.5
    size = root_max[0] - root_min[0]
    step = scale * size
    center = [(root_min[i] + root_max[i]) / 2.0 for i in range(3)]
    
    # dir_mask: bit 0 for X, 1 for Y, 2 for Z. Set if dir component > 0
    dir_mask = 0
    if dir[0] > 0: dir_mask |= 1
    if dir[1] > 0: dir_mask |= 2
    if dir[2] > 0: dir_mask |= 4
    
    frontal_mask = 0
    t_center = [(center[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    for i in range(3):
        if t_center[i] > t_min: frontal_mask |= (1 << i)
        
    corner = center.copy()
    for i in range(3):
        if not (frontal_mask & (1 << i)):
            corner[i] += step if dir[i] > 0 else -step
    t_corner = [(corner[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
    
    stack = []
    
    while depth < max_depth:
        value = svo_data[node_address]
        if value == 0:
            value = svo_data[node_address + (frontal_mask ^ dir_mask)]
            
        if value & (1 << 31): # Internal node
            stack.append((node_address, frontal_mask, t_min, t_corner))
            depth += 1
            scale *= 0.5
            step *= 0.5
            node_address = value & 0x7FFFFFFF
            # Update center to the corner of the new child
            center = corner.copy()
            t_center = [(center[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
            frontal_mask = 0
            for i in range(3):
                if t_center[i] > t_min: frontal_mask |= (1 << i)
            corner = center.copy()
            for i in range(3):
                if not (frontal_mask & (1 << i)):
                    corner[i] += step if dir[i] > 0 else -step
            t_corner = [(corner[i] - ray_origin[i]) * inv_dir[i] for i in range(3)]
            continue
            
        if value > 0: # Leaf node
            break
            
        # Empty node: advance
        t_corner_max = min(t_corner)
        t_min = t_corner_max
        step_mask = 0
        for i in range(3):
            if t_corner[i] <= t_corner_max: step_mask |= (1 << i)
        for i in range(3):
            if step_mask & (1 << i):
                corner[i] += step if dir[i] > 0 else -step
        frontal_mask ^= step_mask
        if (frontal_mask & step_mask) == 0:
            if not stack: return None, None, None
            node_address, frontal_mask, t_min, t_corner = stack.pop()
            depth -= 1
            scale *= 2.0
            step *= 2.0
            continue
            
    if depth >= max_depth: return None, None, None
    return ray_origin + dir * t_min, svo_data[node_address], None
```

**Parameters:**
*   `MAX_DEPTH`: Maximum traversal depth, typically 16-32 [S2, S9, unofficial].
*   `EPS`: Epsilon for direction clamping, typically $10^{-4}$ [S7, S9, unofficial].
*   `mRootRadius`: Radius of the root bounding box [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Precision:** If the ray position lies exactly on a node boundary, tie-breaking logic (e.g., adding a small epsilon to the position) is required to avoid ambiguity in child selection [S1, unofficial].
*   **Zero Direction Components:** Ray directions with zero components cause division by zero [S9, unofficial]. Clamp direction components to $\pm \epsilon$ based on sign [S9, unofficial].
*   **Stack Overflow:** Fixed-size stacks (e.g., 32 elements) can overflow if the octree depth exceeds the limit [S9, unofficial].
*   **Texture Repeat Artifacts:** In texture-based SVOs, ensure lookup points are within the unit cube to avoid wrapping artifacts [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for traversal to the first hit, where $N$ is the number of voxels, due to the hierarchical nature of the octree [S3, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the octree nodes, but significantly less than dense grids for sparse scenes [S8].
*   **Performance:** Can render large scenes (e.g., >1 billion voxels) at real-time frame rates (e.g., 20 FPS at 720p) on modern GPUs [S7, unofficial].
*   **Strengths:** Efficient empty space skipping, implicit LOD, and low memory usage for sparse data [S3, unofficial][S8].
*   **Limitations:** Dynamic updates can be expensive, potentially requiring full octree regeneration [S3, unofficial]. Memory constraints at high resolutions may limit applicability [S8].
*   **When to Use:** Real-time rendering of large, sparse volumetric scenes, reflections, and ambient occlusion [S7, unofficial][S8].
*   **When Not to Use:** Dense volumetric data where ray marching through a 3D texture is more efficient, or scenes with frequent dynamic updates [S3, unofficial].

## Background
Sparse Voxel Octrees were introduced as a hierarchical data structure for raycasting, allowing for efficient rendering of sparse 3D data [S3, unofficial]. The technique builds on the concept of octrees, where empty space is not stored, making the structure sparse [S3, unofficial]. It is widely used in real-time graphics for rendering complex voxel-based scenes, such as the Stanford Dragon and large tori clusters [S7, unofficial]. The method has been adapted for various platforms, including GPU shaders (GLSL, HLSL) and Vulkan [S2, S4, S6, unofficial].
