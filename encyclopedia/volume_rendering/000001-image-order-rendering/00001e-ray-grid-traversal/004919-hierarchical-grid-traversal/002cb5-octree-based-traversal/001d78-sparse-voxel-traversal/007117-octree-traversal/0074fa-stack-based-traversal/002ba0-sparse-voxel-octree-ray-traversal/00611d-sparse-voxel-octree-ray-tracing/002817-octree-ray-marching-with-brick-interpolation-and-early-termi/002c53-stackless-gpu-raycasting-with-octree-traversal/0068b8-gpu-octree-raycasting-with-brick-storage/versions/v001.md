# GPU Octree Raycasting with Brick Storage

Also called: Goxels Raycasting, Octree Voxel Rendering

## Overview
A raycasting method that traverses an octree structure stored in a GPU buffer to render voxels, handling both solid nodes and leaf nodes containing 8x8x8 voxel bricks using a 3D texture for brick data storage [S1, unofficial]. It differs from standard sparse voxel octree traversal by packing leaf node data into a 3D texture and encoding brick coordinates within the node's color data, allowing for efficient brick-level raymarching [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Ray origin $O$, ray direction $D$ (normalized), world bounds, octree node buffer, 3D texture `voxelBlocks` containing 8x8x8 voxel bricks.
*   **Output:** Accumulated color and opacity for the pixel.

**Data Structures**
The octree is stored as a flat array of `octreeNode` structs in a GPU buffer [S1, unofficial].

```glsl
struct octreeNode {
    uint childData; // Encodes leaf/solid flags and child offset
    uint colorData; // Encodes color for solids or brick coordinates for leaves
};
```

**Bit Packing in `childData`**
*   `LEAF_MASK` (0x80000000): Indicates leaf node.
*   `SOLID_MASK` (0x40000000): Indicates solid node.
*   `FINAL_MASK` (0xA0000000): `LEAF_MASK | SOLID_MASK`. If `(childData & FINAL_MASK) == FINAL_MASK`, the node is a leaf or solid.
*   `CHILD_MASK` (0x3FFFFFFF): Stores the index of the first child node if not a leaf.

**Bit Packing in `colorData` (Leaf Nodes)**
For leaf nodes, `colorData` stores the brick coordinates packed as a `uint` [S1, unofficial].
*   `COORD_MASK` (0x000003FF): Extracts 10-bit coordinates.
*   Brick X: Bits 20-29. Calculated as `(loc >> 20) & COORD_MASK`.
*   Brick Y: Bits 10-19. Calculated as `(loc >> 10) & COORD_MASK`.
*   Brick Z: Bits 0-9. Calculated as `loc & COORD_MASK`.

**Voxel Data Storage**
Voxel data is stored in a uniform 3D texture `voxelBlocks` (sampler3D). Each voxel is a `vec4` (RGBA) [S1, unofficial].

**Parameters**
*   `MAX_DEPTH`: Maximum octree depth allowed, set to 10. If depth exceeds this, treat as leaf/solid [S1, unofficial].
*   `BRICK_SIZE`: Size of voxel bricks, defined as 8 [S1, unofficial].
*   `MAX_STEPS`: Maximum traversal steps, set to 200 [S1, unofficial].

**Algorithm Steps**

1.  **Initialize Ray Traversal:**
    *   Normalize direction $D$.
    *   Compute inverse direction $D_{inv} = 1/D$.
    *   Compute delta $T = |D_{inv}|$.
    *   Determine entry/exit parameters $s_{min}, s_{max}$ based on world bounds and ray origin.

2.  **Traverse Octree:**
    *   Initialize current node index to root (0), depth to 0, and bounds ($x_{min}, dim$) to world bounds.
    *   Loop with `maxSteps = 200`.
    *   Check if current node is leaf/solid: `if ((nodes[node].childData & FINAL_MASK) == FINAL_MASK)`.
        *   If true, process leaf/solid logic (Step 3).
        *   If false, descend to child node (Step 4).

3.  **Leaf/Solid Processing:**
    *   **Solid Node:** If `SOLID_MASK` is set, the node is solid. Add its color to the accumulated color with alpha blending.
    *   **Leaf Node:**
        *   Extract brick location from `colorData`:
            ```python
            brick_x = (nodes[node].colorData >> 20) & COORD_MASK
            brick_y = (nodes[node].colorData >> 10) & COORD_MASK
            brick_z = nodes[node].colorData & COORD_MASK
            ```
        *   Compute line position in brick coordinates.
        *   Raymarch through the 8x8x8 brick using DDA-like stepping.
        *   Loop through voxels in the brick using `stepTmax` comparisons to determine which axis to step next.
        *   Check voxel alpha; if non-zero, blend color and accumulate alpha.
        *   Break if line position goes out of $[0, 8)$ bounds.

4.  **Node Descent:**
    *   If not leaf/solid, compute sub-node location:
        ```python
        subNodeLoc = ivec3(floor((pos - xMin) / dim))
        ```
    *   **Edge Case:** If `subNodeLoc` is out of $[0, 1]$, the ray has exited the current node's domain.
        *   If `depth == 0`, return accumulated color.
        *   Otherwise, reset traversal to root.
    *   Compute next node index:
        ```python
        nextNode = (nodes[node].childData & CHILD_MASK) + (subNodeLoc.x << 2) + (subNodeLoc.y << 1) + subNodeLoc.z
        ```
    *   Increment depth, halve `dim`, update `xMin`.

## Operating characteristics
*   **Time Complexity:** Depends on the depth of the octree and the number of non-empty bricks traversed. The traversal is stackless, reducing overhead.
*   **Memory Complexity:** The octree is stored in a flat array, and voxel data is in a 3D texture. The memory usage is proportional to the number of nodes and the size of the voxel texture.
*   **Strengths:** Efficient traversal without a stack, efficient storage of leaf node data in a 3D texture.
*   **Limitations:** The method relies on a specific bit-packing scheme and assumes a fixed brick size. The handling of solid nodes and color extraction is not fully detailed in the sources.
