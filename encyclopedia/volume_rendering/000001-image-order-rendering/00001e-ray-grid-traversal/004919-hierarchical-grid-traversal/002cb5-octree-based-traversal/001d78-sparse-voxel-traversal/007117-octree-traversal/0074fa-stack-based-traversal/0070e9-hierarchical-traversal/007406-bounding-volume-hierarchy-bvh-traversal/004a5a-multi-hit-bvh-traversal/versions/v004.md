# Multi-Hit BVH Traversal

Also called: Multi-Hit BVH Traversal for Volume Clipping, Multi-hit intersection, Multi-hit query, Ray Traced Volume Clipping Using Multi-Hit BVH Traversal

## Overview
Multi-Hit BVH Traversal is a technique to determine the $N$ closest intersections of a viewing ray with compound clip objects (geometric primitives organized in a Bounding Volume Hierarchy) to construct clip intervals for volume rendering [S1]. It sets itself apart from all-hit queries by using a preallocated static array to avoid costly dynamic memory reallocation, which is essential for real-time implementation [S1]. Unlike texture-based approaches that require multiple rendering passes or depth peeling, this method calculates intervals directly in on-chip GPU memory [S1].

## How it works
**Inputs and Outputs**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a set of clip primitives (planes, spheres, triangle meshes) organized in a BVH; an integer $N$ representing the maximum number of intersections to retrieve [S1].
*   **Output:** An array of $N$ intersection distances (or hit records) sorted by proximity to the ray origin, used to construct clip intervals [S1].

**Data Structures**
*   **Clip Primitives:** Stored as Plain Old Data (POD) objects in a C array to avoid virtual inheritance and vtable lookups, reducing indirection overhead [S1].
*   **BVH:** Manages triangle meshes. The BVH is rebuilt completely if the triangle mesh changes, as dynamic updates are not supported in this implementation [S1].
*   **Result Array:** A static memory array of size $N$. The size $N$ must be decided a priori [S1].

**Parameters**
*   $N$: The maximum number of intersections to retrieve. This value determines the size of the static result array [S1].

**Algorithm Steps**
1.  **Preallocation:** Allocate a static array of size $N$ to store the intersection results. This avoids dynamic memory allocation during the traversal loop [S1].
2.  **Traversal:** Execute the multi-hit query on the BVH. The traversal visits nodes and primitives, collecting hit distances [S1].
3.  **Sorting/Selection:** The implementation ensures the $N$ closest hits are returned [S1].
4.  **Interval Construction:** Use the resulting hit distances to define clip intervals (e.g., $[t_1, t_2], [t_3, t_4]$) for the volume rendering pass [S1].

**Pseudocode**
The following pseudocode illustrates the usage pattern, assuming a generic ray-tracing library interface (like Visionaray) that supports multi-hit queries with a fixed-size buffer [S1].

```python
def multi_hit_bvh_traversal(ray_origin, ray_direction, bvh_root, max_hits):
    # Preallocate a static array of size N to store the intersection results [S1]
    hits = [None] * max_hits
    hit_count = 0
    max_hit_t = float('inf')

    # Standard BVH traversal stack
    stack = [bvh_root]

    while stack:
        node = stack.pop()

        # Check bounding box intersection using the slab method
        t_min = (node.bbox.min - ray_origin) / ray_direction
        t_max = (node.bbox.max - ray_origin) / ray_direction
        t_enter = max(min(t_min), min(t_max))
        t_exit = min(max(t_min), max(t_max))
        if t_enter > t_exit:
            continue

        if node.is_leaf():
            # Intersect primitives in leaf
            # Avoid dynamic branching in the innermost loop by using generic routines
            # that call specific intersect() functions for POD objects [S1]
            for primitive in node.primitives:
                t = intersect_primitive(primitive, ray_origin, ray_direction)
                if t is not None and t < max_hit_t:
                    # Insert into sorted static buffer
                    hits = insert_sorted(hits, t, hit_count, max_hits)
                    hit_count = min(hit_count + 1, max_hits)
                    if hit_count == max_hits:
                        max_hit_t = hits[max_hits - 1]
        else:
            # Push children to stack
            stack.append(node.left)
            stack.append(node.right)

    return hits[:hit_count]

def intersect_primitive(primitive, origin, direction):
    # Dispatch to specific intersect() based on primitive type (plane, sphere, triangle)
    # In practice, this is implemented via template specialization or function pointers
    # to avoid dynamic branching in compiled assembly [S1]
    if primitive.type == PLANE:
        return intersect_plane(primitive, origin, direction)
    elif primitive.type == SPHERE:
        return intersect_sphere(primitive, origin, direction)
    elif primitive.type == TRIANGLE:
        return intersect_triangle(primitive, origin, direction)
    return None

def insert_sorted(hits, t, count, max_hits):
    # Insert t into hits maintaining ascending order
    if count < max_hits:
        hits[count] = t
        # Bubble sort insertion for small count
        i = count
        while i > 0 and hits[i] < hits[i-1]:
            hits[i], hits[i-1] = hits[i-1], hits[i]
            i -= 1
    else:
        # Replace if t is smaller than the largest stored hit
        if t < hits[max_hits - 1]:
            hits[max_hits - 1] = t
            # Bubble down to correct position
            i = max_hits - 1
            while i > 0 and hits[i] < hits[i-1]:
                hits[i], hits[i-1] = hits[i-1], hits[i]
                i -= 1
    return hits
```

**Edge Cases and Pitfalls**
*   **Dynamic Branching:** Switching over primitive types in the innermost traversal loop causes performance degradation. The implementation avoids this by using generic routines that call specific `intersect()` functions for POD objects [S1].
*   **Register Pressure:** Storing clip intervals in on-chip GPU memory increases register demand per thread on the shading multi-processor (SM), which may impact kernel performance [S1].
*   **Static Geometry:** Triangle meshes must be static. Changing them requires a complete BVH rebuild [S1].
*   **Precision:** The method avoids the need for a tiny epsilon $\Delta$ that varies per query, which can cause artifacts and unnecessary BVH traversals in other methods [S1].

## Operating characteristics
*   **Time Complexity:** Depends on the BVH traversal depth and the number of primitives. The multi-hit query is generally more efficient than an all-hit query for large scenes because it stops after finding $N$ hits [S1]. The asymptotic behavior is reduced to average logarithmic in the number of geometric primitives due to the BVH [S1].
*   **Memory Complexity:** $O(N)$ for the result array, where $N$ is the maximum number of hits. The BVH structure itself is $O(P)$ where $P$ is the number of primitives [S1].
*   **Performance:** Evaluated on a 1024x1024 resolution MRI dataset (MNI152, 0.5mm³ voxel size, 364x436x364 voxels) clipped with Utah teapot models [S1].
    *   Level 1: 2,464 triangles, 1,559 BVH nodes [S1].
    *   Level 2: 14,784 triangles, 9,771 BVH nodes [S1].
    *   Level 3: 59,136 triangles, 39,063 BVH nodes [S1].
    *   Level 4: 236,544 triangles, 151,637 BVH nodes [S1].
*   **Strengths:** Real-time capable; avoids dynamic memory allocation; no multiple rendering passes or depth peeling required; on-chip memory access is faster than DDR3 [S1].
*   **Limitations:** Requires a priori knowledge of the maximum number of intersections $N$; increased register pressure on GPU; triangle meshes must be static (BVH rebuild required on change) [S1].

## Background
The method was proposed in the context of real-time volume rendering for neurosurgical applications [S1]. It builds on the Visionaray ray tracing template library [S1] and the BVH construction scheme from [31] (cited in S1). It is conceptually aligned with the approach by Weiskopf et al. [34] (cited in S1), but differs by using a multi-hit query instead of hardware depth buffers and multiple render passes [S1].
