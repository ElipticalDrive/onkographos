# Iterative Octree Traversal

Also called: BaseOctreeRenderer, Non-recursive Octree Ray Tracing, Ray-Tree Traversal for Color Rendering, Ray-Tree Traversal for Depth Visualization, Rekursionsfreie Traversierung eines Octree, Stack-based Octree Traversal, WorkOctreeRenderer

## Overview
Iterative Octree Traversal is a method for raycasting against a Sparse Voxel Octree (SVO) that replaces recursive function calls with an explicit stack-based data structure, primarily to comply with hardware constraints such as the lack of recursion support in HLSL [S2, S4, unofficial]. It differs from [Recursive Octree Traversal](2632-recursive-octree-traversal.md) by managing traversal state (depth, parent pointers, visited children) in fixed-size arrays, and from [Parametric Octree Traversal](2361-parametric-octree-traversal.md) by using a greedy, distance-based child selection strategy that backtracks on false positives rather than following a strict parametric order [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An octree structure (root node, internal nodes, leaf voxels), a ray defined by origin $O$ and direction $D$, and a maximum iteration count `maxIterations`.
*   **Output:** The color and depth of the closest voxel intersected by the ray, or a default value if no intersection is found.

**Data Structures:**
The algorithm simulates the call stack using fixed-size arrays to track traversal state per depth level [S2, unofficial]:
*   `skipListPerDepth[4]`: An integer array where each bit $i$ indicates if child $i$ of the node at `currentDepth` has already been visited [S2, unofficial].
*   `parentListPerDepth[4]`: Stores the index of the parent node at each depth level to facilitate backtracking [S2, unofficial].
*   `positionListPerDepth[4]`: Stores the 3D position (`float3`) of the parent node at each depth level [S2, unofficial].
*   `stack_item_t` (Alternative Implementation): A struct containing slab boundaries (`tnum tx0, ty0, tz0, tx1, ty1, tz1`), node address (`int adr`), and child index (`char idx`) [S5, unofficial].
*   `Container`: Represents a node, containing `childStartIndex`, `hasData`, `currentSize`, and `currentPosition` [S2, unofficial].

**Steps:**

1.  **Ray Preprocessing:**
    *   If any component of the ray direction $D$ is zero, add a small epsilon (e.g., $0.001$) to avoid division by zero [S5, unofficial].
    *   If a component of $D$ is negative, negate the corresponding component of the ray origin $O$ and direction $D$, and set a bit in `dir_mask` (x=4, y=2, z=1) to track the flip [S5, unofficial].
    *   Compute slab entry and exit distances for the octree bounds:
        $$tx_0 = \frac{min_x - o_x}{d_x}, \quad tx_1 = \frac{max_x - o_x}{d_x}$$
        $$ty_0 = \frac{min_y - o_y}{d_y}, \quad ty_1 = \frac{max_y - o_y}{d_y}$$
        $$tz_0 = \frac{min_z - o_z}{d_z}, \quad tz_1 = \frac{max_z - o_z}{d_z}$$
        where $(min_x, min_y, min_z)$ and $(max_x, max_y, max_z)$ are the octree bounds [S5, unofficial].
    *   Scale slab boundaries by a fixed-point factor (e.g., `tnum_scale = 10000`) to convert them to integer coordinates for traversal [S5, unofficial].

2.  **Initialization:**
    *   Initialize `skipListPerDepth`, `parentListPerDepth`, and `positionListPerDepth` to zero/empty states [S2, unofficial].
    *   Set `currentDepth = 0` [S2, unofficial].
    *   Get the root node entry and decode child validity/leaf status into arrays `c_leaf[8]`, `c_valid[8]`, `c_offset[8]` [S5, unofficial].
    *   Initialize `minDistToNode` to infinity [S2, unofficial].

3.  **Main Traversal Loop:**
    Iterate for `maxIterations` times [S2, unofficial]:
    *   **Child Selection:**
        *   Get `childStartIndex` from the current parent node [S2, unofficial].
        *   Iterate through children $i$ from 0 to 7:
            *   Check if child $i$ was already visited: `if (((skipListPerDepth[currentDepth] >> i) & 1)) continue;` [S2, unofficial].
            *   Retrieve the child container. If it has no data, skip [S2, unofficial].
            *   Update child properties:
                $$child.currentSize = parent.currentSize \times 0.5$$
                $$child.currentPosition = parent.currentPosition + octantVectors[i] \times child.currentSize$$
            *   Perform Ray-AABB intersection test between the ray and the child's bounding box to get $t'$ [S4, unofficial].
            *   **Non-Intersectable Node Omission:** If the child's minimum slab boundary $t_{i1}$ is less than the current best intersection $t_{min}$, or if $t_{i0}$ is greater than $t_{max}$, skip the child [S4, unofficial].
            *   If the intersection is valid ($t' \in (0, t_{min})$):
                *   If the child is a leaf (e.g., size $\le 32$):
                    *   Perform raycasting on the leaf volume [S2, unofficial].
                    *   If a voxel is found and $t_{minVoxel} < minDistToVoxel$, update `minDistToVoxel` and set `voxelFound = true` [S2, unofficial].
                    *   If no voxel is found, reset `minDistToNode` to infinity to allow other nodes to be checked [S2, unofficial].
                *   If the child is an internal node:
                    *   Store the current parent's index and position in `parentListPerDepth` and `positionListPerDepth` [S2, unofficial].
                    *   Mark child $i$ as visited: `skipListPerDepth[currentDepth] |= (1 << i)` [S2, unofficial].
                    *   Set `nextParent = child`, `usedIndex = i`, `nextIndex = childStartIndex + i` [S2, unofficial].
                    *   Break the child loop to descend [S2, unofficial].

    *   **Backtracking or Descending:**
        *   If `voxelFound` is true, break the main loop [S2, unofficial].
        *   If `nextParent.isNull` is true (all children visited or no valid child found):
            *   Reset `skipListPerDepth[currentDepth]` to 0 [S2, unofficial].
            *   Decrement `currentDepth`. If `currentDepth < 0`, terminate [S2, unofficial].
            *   Retrieve the parent from `parentListPerDepth[currentDepth]` and restore its size and position [S2, unofficial].
        *   Else (forward traversal):
            *   Increment `currentDepth` [S2, unofficial].
            *   Update `parent = nextParent` and `currentIndex = nextIndex` [S2, unofficial].

4.  **Result Extraction:**
    *   If a voxel was found, extract the color from the leaf node data and write it to the output buffer with alpha = 1 [S2, unofficial].
    *   If no voxel was found, return a default value (e.g., background color or depth -1) [S4, unofficial].

**Pseudocode:**

```python
def iterative_octree_traversal(ray, octree, max_iterations):
    # Preprocessing
    dir_mask = 0
    if ray.d.x == 0: ray.d.x += 0.001
    if ray.d.x < 0: ray.o.x = -ray.o.x; ray.d.x = -ray.d.x; dir_mask |= 4
    if ray.d.y == 0: ray.d.y += 0.001
    if ray.d.y < 0: ray.o.y = -ray.o.y; ray.d.y = -ray.d.y; dir_mask |= 2
    if ray.d.z == 0: ray.d.z += 0.001
    if ray.d.z < 0: ray.o.z = -ray.o.z; ray.d.z = -ray.d.z; dir_mask |= 1

    # Slab calculation
    tx0 = (octree.min_x - ray.o.x) / ray.d.x
    tx1 = (octree.max_x - ray.o.x) / ray.d.x
    ty0 = (octree.min_y - ray.o.y) / ray.d.y
    ty1 = (octree.max_y - ray.o.y) / ray.d.y
    tz0 = (octree.min_z - ray.o.z) / ray.d.z
    tz1 = (octree.max_z - ray.o.z) / ray.d.z
    
    # Fixed-point scaling
    tnum_scale = 10000
    tx0 *= tnum_scale; tx1 *= tnum_scale
    ty0 *= tnum_scale; ty1 *= tnum_scale
    tz0 *= tnum_scale; tz1 *= tnum_scale

    # State initialization
    skip_list = [0] * 4
    parent_list = [0] * 4
    position_list = [0.0, 0.0, 0.0] * 4
    current_depth = 0
    min_dist_to_node = float('inf')
    min_dist_to_voxel = float('inf')
    voxel_found = False
    
    parent = octree.root
    current_index = 0
    
    for _ in range(max_iterations):
        child_start_index = parent.entry.child_start_index
        found_next = False
        
        for i in range(8):
            # Check if already visited
            if (skip_list[current_depth] >> i) & 1:
                continue
            
            child = get_container(child_start_index + i)
            if not child.has_data:
                continue
                
            # Update child properties
            child.current_size = parent.current_size * 0.5
            child.current_position = parent.current_position + octant_vectors[i] * child.current_size
            
            # Ray-AABB intersection
            t_prime = ray_aabb_intersect(ray, child.bounding_box)
            
            # Non-intersectable node omission
            # Calculate child slab boundaries tm
            tm = 0.5 * (t0 + t1) # Simplified logic for tm
            if t_prime < min_dist_to_node:
                if child.is_leaf:
                    # Raycast leaf volume
                    t_voxel = raycast_leaf(ray, child.voxel_data)
                    if t_voxel < min_dist_to_voxel:
                        min_dist_to_voxel = t_voxel
                        voxel_found = True
                        break
                else:
                    # Store parent state for backtracking
                    parent_list[current_depth] = current_index
                    position_list[current_depth] = parent.current_position
                    skip_list[current_depth] |= (1 << i)
                    
                    next_parent = child
                    used_index = i
                    next_index = child_start_index + i
                    found_next = True
                    break
        
        if voxel_found:
            break
            
        if not found_next:
            # Backtrack
            skip_list[current_depth] = 0
            current_depth -= 1
            if current_depth < 0:
                break
            current_index = parent_list[current_depth]
            parent = get_container(current_index)
            parent.current_size = octree.initial_size >> current_depth
            parent.current_position = position_list[current_depth]
        else:
            # Descend
            current_depth += 1
            parent = next_parent
            current_index = next_index
            
    if voxel_found:
        return extract_color(min_dist_to_voxel)
    else:
        return -1
```

## Subtopics

### [ESVO (Efficient Sparse Voxel Octrees)](3089-esvo-efficient-sparse-voxel-octrees.md)
ESVO is a GPU-based ray casting algorithm that uses a Sparse Voxel Octree (SVO) to reduce voxel storage costs and enable real-time rendering of large scenes. It sets itself apart from sibling methods by using a compact 4-byte node encoding with a depth-first (z-curve) memory layout, which optimizes for localized memory access patterns on the GPU. Unlike [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md) which may use larger leaf nodes or different traversal strategies, ESVO relies on a near 1:1 port of the original implementation with specific pointer encoding changes to facilitate buffer-less tree construction.

### [Octree Traversal with Fixed-Size Leaf Volumes](3900-octree-traversal-with-fixed-size-leaf-volumes.md)
This method accelerates sparse voxel octree (SVO) raycasting by enforcing a uniform leaf node size, decoupling traversal depth from data sparsity and ensuring predictable memory access patterns. Unlike [Iterative Octree Traversal](2618-iterative-octree-traversal.md), which may vary leaf granularity, this approach fixes the leaf volume to 32×32×32 voxels, optimizing for hardware cache efficiency and reducing branch divergence in GPU warps, at the cost of increased false-positive checks in noisy or dense regions.

### [Octree Traversal with LOD & Constant Nodes](4181-octree-traversal-with-lod-constant-nodes.md)
This method renders a Sparse Voxel Octree (SVO) on the CPU by traversing the hierarchy to project voxels into a color buffer, using depth-sorted traversal and hierarchical culling based on projected size. It distinguishes itself from sibling methods by supporting Level of Detail (LOD) switching between constant-value nodes and textured bricks. It builds on [Iterative Octree Traversal](2618-iterative-octree-traversal.md) by adding specific logic for constant node handling and brick texture sampling.

### [Ordered List Generation via N3-Tree Traversal](5023-ordered-list-generation-via-n3-tree-traversal.md)
This method generates a list of spatial bricks ordered from closest to furthest relative to the viewpoint to avoid testing blocks behind untested unloaded blocks. It solves the problem of unnecessary data loading by ensuring that visibility tests are performed in an order where any previously reached node cannot be occluded by a subsequently reached node. It sets itself apart from sibling methods by integrating view-dependent axis prioritization directly into a depth-first traversal of the N3-tree structure, followed by a lightweight distance sort.

### [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md)
Hierarchical Ray Marching is a sparse voxel traversal technique that dynamically switches between octree levels and voxel levels to optimize ray-marching performance. It differs from sibling methods by adjusting the traversal granularity up or down based on hit/miss status, allowing rapid skipping of empty regions at coarse levels and precise sampling at fine levels.

### [Ray-Direction Child Ordering](5462-ray-direction-child-ordering.md)
Ray-Direction Child Ordering is an iterative traversal optimization for sparse voxel octrees that processes child nodes in a sequence determined by the ray's direction, ensuring nodes closer to the ray origin are visited first. It solves the inefficiency of standard recursive traversal, which examines all eight children and performs redundant intersection tests for non-intersected subtrees, by using a deterministic neighbor-linking strategy to skip empty or non-intersected branches. Unlike its siblings, it avoids recursion entirely within a node's children by maintaining a `currNode` state and computing the next neighbor based on exit plane t-values, thereby reducing the number of intersection tests and improving performance on sparse structures.

### [Octree Iteration with Culling](11319-octree-iteration-with-culling.md)
This method performs a depth-first traversal of a Sparse Voxel Octree (SVO) to collect leaf nodes that intersect a specified spatial region, typically a bounding box or ray volume. It solves the problem of efficiently identifying relevant geometry for rendering or physics without visiting every node in the tree. It sets itself apart from sibling methods by explicitly integrating a `BoxIntersector` check at every node visit, allowing early termination of branches that lie outside the region of interest, whereas siblings like [ESVO](3089-esvo-efficient-sparse-voxel-octrees.md) or [Hierarchical Ray Marching](5238-hierarchical-ray-marching.md) may focus on different traversal optimizations or data layouts.

### [Single-kernel Octree Traversal](15600-single-kernel-octree-traversal.md)
Single-kernel octree traversal is a technique for traversing an octree for ray tracing by performing the entire traversal logic, including recursion simulation, within a single CUDA kernel execution per ray, rather than using multiple kernel launches for each recursion depth. It is preferred over multi-kernel recursion because kernel invocation overhead is high. Although single-kernel traversal may cause thread divergence due to the SIMD nature of GPUs, coherent rays in a warp traverse similarly, mitigating this issue.

## Operating characteristics
*   **Time Complexity:** In the ideal case, the time complexity is $O(\log s)$, where $s$ is the initial size of the Octree [S2, unofficial]. The leaf raycasting is $O(1)$ as it always processes a fixed 32x32x32 volume [S2, unofficial]. In the worst case (e.g., traversing along a diagonal where every leaf node must be checked), the complexity is $O(s \cdot \log s)$ [S2, unofficial].
*   **Memory Complexity:** The algorithm uses fixed-size arrays for the stack simulation (`skipListPerDepth`, `parentListPerDepth`, `positionListPerDepth`), typically of length 4, making the auxiliary memory usage constant and independent of the octree depth [S2, unofficial].
*   **Strengths:** Eliminates recursion overhead and complies with GPU constraints (HLSL) [S2, S4, unofficial]. The greedy approach with backtracking efficiently handles false positives by revisiting parent nodes [S2, unofficial].
*   **Limitations:** The greedy strategy may lead to redundant checks if many false positives occur [S2, unofficial]. The fixed-size stack limits the maximum traversal depth [S5, unofficial].
*   **When to use:** When targeting hardware that does not support recursion (e.g., older GPUs, HLSL) or when stack overflow is a concern [S2, S4, unofficial].
*   **When not to use:** When the octree depth exceeds the fixed stack size limit [S5, unofficial].

## Background
Iterative Octree Traversal originated as a solution to the limitations of recursive raycasting in shader languages like HLSL, which do not support general method recursion [S2, unofficial]. It was developed to enable efficient raycasting of large voxel spaces on GPUs by replacing the call stack with explicit data structures [S2, S4, unofficial]. The method is a key component in various sparse voxel rendering pipelines, including those described in theses on voxel rendering and GPU-based ray tracing [S2, S4, unofficial].
