# SVO Ray Tracing

Also called: Full-screen SVO Raycasting, SVO Walk (Traversal)

## Overview
SVO Ray Tracing is a method for rendering 3D scenes represented by a Sparse Voxel Octree (SVO) or a BVH-structured SVO by casting rays from each screen pixel directly into the tree structure. It solves the problem of efficiently rendering large, sparse volumetric datasets without the memory overhead of dense voxel grids. It differs from [GigaVoxels](3057-gigavoxels.md) by not relying on a fixed-resolution texture-based cache, and from [Sparse Voxel Octree Ray Traversal (State Machine)](3299-sparse-voxel-octree-ray-traversal-state-machine.md) by explicitly managing a stack to control visitation order based on eye position, operating directly on the octree structure without an intermediate bounding volume hierarchy in its pure form [S1, unofficial].

## How it works
The method consists of two primary phases: the construction of the spatial acceleration structure (SVO/BVH) and the ray-casting traversal for rendering.

### Inputs and Outputs
*   **Inputs**: A voxel grid (e.g., from CSV), camera parameters (origin, rotation, FOV, aspect ratio, resolution), and object transforms.
*   **Outputs**: A rendered image (color buffer) and optionally debug visualization of visited nodes/leaves.

### Data Structures
The implementation uses parallel arrays to simulate a stack and store tree nodes.

**Uniform Buffer (`RaytracerShaderUniforms`)** [S1, unofficial]:
*   `camera_rotation`: `[[f32; 4]; 4]` (4x4 matrix)
*   `camera_origin`: `[f32; 4]`
*   `width`: `u32`
*   `height`: `u32`
*   `aspect_ratio`: `f32`
*   `fov`: `f32` (stored as $\tan(\text{fov}_{rad}/2)$)
*   `bvh_root`: `u32` (index of the root node)

**BVH Node Buffer** [S1, unofficial]:
*   `center`: `[f32; 4]` (x, y, z, w)
*   `radius`: `f32`
*   `left_child`: `u32` (index, with MSB set to 1 if it points to a leaf)
*   `right_child`: `u32` (index, with MSB set to 1 if it points to a leaf)

**BVH Leaf Buffer** [S1, unofficial]:
*   `model_address`: `u32`
*   `inv_model`: `mat4` (inverse transformation matrix)

**SVO Buffer**:
*   Stores the node pool and leaf data. Max sizes are typically defined as 16,384 leaves and 32,767 nodes in specific implementations, though theoretical limits are higher [S1, unofficial].

### Construction Steps
1.  **Voxelization**: Load the voxel grid from source data (e.g., CSV) [S1, unofficial].
2.  **Leaf Generation**: For each object, compute its position, scale, and rotation. Encode the position into a Morton code. Create a `BVHLeaf` containing the model address and inverse model matrix [S1, unofficial].
3.  **Sorting**: Sort the leaves by their Morton code [S1, unofficial].
4.  **Tree Building**:
    *   Initialize a `nodes` vector with a dummy empty node at index 0.
    *   Iterate through sorted leaves in pairs.
    *   For each pair (or single remaining leaf), compute the bounding sphere (`center`, `radius`) encompassing the objects [S1, unofficial].
    *   Create a `BVHNode` with the computed center, radius, and child indices.
    *   If a child is a leaf, set the MSB of the child index to `1` (e.g., `i | 0x80000000`) to distinguish it from internal nodes [S1, unofficial].
    *   Push the new node index to a `node_queue` [S1, unofficial].
    *   While `node_queue` has more than one element, pop two front elements (left and right children), compute their combined bounding sphere, create a parent node, and push the parent back to the queue.
    *   The final element in the queue is the root [S1, unofficial].

### Ray Traversal Steps (Full-screen SVO Raycasting)
1.  **Initialization**: Clear the `raycastingLeafs` list [S2, unofficial].
2.  **Pixel Loop**: For each pixel $(x, y)$ in the screen resolution:
    *   **Unproject**: Calculate the ray origin and direction in world space.
        *   $origin = \text{unproject}(x, y, 0.0)$
        *   $end = \text{unproject}(x, y, 1.0)$
        *   $direction = \text{normalize}(end - origin)$ [S2, unofficial]
    *   **Cast Ray**: Call `octree_raycast(origin, direction, false)`. This function traverses the SVO/BVH structure.
        *   *Note*: The specific traversal logic for `octree_raycast` is not detailed in the provided snippets, but it implies a depth-first or stack-based visitation that identifies intersecting leaves [S2, unofficial].
3.  **Result Processing**:
    *   Iterate over `raycastingLeafs` (stored as `glm::vec4` where $x,y,z$ are position and $w$ is size) [S2, unofficial].
    *   **Color Assignment**:
        *   If $y < 10$: Color = Green
        *   If $10 \le y < 27$: Color = Grey
        *   Otherwise: Color = White [S2, unofficial]
    *   **Rendering**: Draw a square at $v.xyz$ with size $v.w$ and the assigned color [S2, unofficial].
4.  **Debug Visualization (Optional)**:
    *   Iterate over `octreeBoxes` (stored as `glm::vec4`) [S2, unofficial].
    *   Set polygon mode to `line`.
    *   Calculate color intensity: $C = \frac{2^{\text{octreeScale}} - v.w}{2^{\text{octreeScale}}}$
    *   Set color to $(C, 0, 0, 1)$ [S2, unofficial].
    *   Draw the box outline.
    *   Reset polygon mode to `fill` [S2, unofficial].

### Pseudocode

```python
# Data Structures
struct BVHNode:
    center: Vector4  # x, y, z, w
    radius: float
    left_child: uint # MSB set if leaf
    right_child: uint # MSB set if leaf

struct BVHLeaf:
    model_address: uint
    inv_model: Matrix4

# Construction
function build_bvh(morton_leafs: List[Tuple[MortonCode, BVHLeaf, Transform, Scale]]):
    nodes = [BVHNode(center=[0,0,0,0], radius=0, left_child=0, right_child=0)] # Empty node at 0
    leafs = []
    node_queue = Queue()
    
    # Sort leaves by Morton code
    morton_leafs.sort_by_key(lambda x: x[0])
    
    i = 0
    while i < len(morton_leafs):
        # Process pair or single
        if i == len(morton_leafs) - 1:
            # Single leaf
            leaf = morton_leafs[i][1]
            leafs.append(leaf)
            center, radius = compute_center_and_radius(morton_leafs[i][2])
            left_idx = i
            right_idx = 0 # Empty node
        else:
            # Pair of leaves
            leaf1 = morton_leafs[i][1]
            leaf2 = morton_leafs[i+1][1]
            leafs.append(leaf1)
            leafs.append(leaf2)
            
            c1, r1 = compute_center_and_radius(morton_leafs[i][2])
            c2, r2 = compute_center_and_radius(morton_leafs[i+1][2])
            center, radius = compute_bounding_sphere([c1, c2])
            
            left_idx = i
            right_idx = i + 1
            
        # Create node, mark leaves with MSB
        node = BVHNode(
            center=center,
            radius=radius,
            left_child=left_idx | 0x80000000,
            right_child=right_idx | 0x80000000
        )
        nodes.append(node)
        node_queue.push(len(nodes) - 1)
        i += 2
        
    # Build internal nodes
    while len(node_queue) > 1:
        left_child_idx = node_queue.pop_front()
        right_child_idx = node_queue.pop_front()
        
        # Get children's bounding spheres
        left_node = nodes[left_child_idx]
        right_node = nodes[right_child_idx]
        
        center, radius = compute_bounding_sphere([left_node.center, right_node.center])
        
        parent_node = BVHNode(
            center=center,
            radius=radius,
            left_child=left_child_idx,
            right_child=right_child_idx
        )
        nodes.append(parent_node)
        node_queue.push(len(nodes) - 1)
        
    root_idx = node_queue.pop_front()
    return nodes, leafs, root_idx

# Rendering
function render_svo(width, height, camera, nodes, leafs, root_idx):
    raycasting_leafs = []
    
    for y in range(height):
        for x in range(width):
            # Unproject to get ray
            origin = unproject(x, y, 0.0, camera.view, camera.projection)
            end = unproject(x, y, 1.0, camera.view, camera.projection)
            direction = normalize(end - origin)
            
            # Cast ray
            hits = octree_raycast(origin, direction, nodes, leafs, root_idx)
            for hit in hits:
                raycasting_leafs.append(hit)
                
    # Render results
    for leaf in raycasting_leafs:
        color = get_color_by_y(leaf.position.y)
        draw_square(leaf.position, leaf.size, color)
        
    # Debug: Render octree boxes
    set_polygon_mode(LINE)
    for box in octree_boxes:
        intensity = (exp2(octree_scale) - box.size) / exp2(octree_scale)
        color = (intensity, 0, 0, 1)
        draw_box_outline(box.position, box.size, color)
    set_polygon_mode(FILL)
```

## Subtopics

### [SVO Walk (Traversal)](5188-svo-walk-traversal.md)
SVO Walk is a depth-first traversal algorithm for Sparse Voxel Octrees that visits nodes in an order determined by the eye position, invoking a callback for each visited node. It differs from pure SVO traversal by explicitly managing a stack to control visitation order based on eye position, and from BVH-based approaches by operating directly on the octree structure without an intermediate bounding volume hierarchy.

### Full-screen SVO Raycasting
This variant refers to the specific implementation where rays are cast for every pixel on the screen, processing the results to render colored squares for hits and wireframe boxes for debug visualization. It uses a specific color-coding scheme based on the Y-coordinate of the hit leaf (Green for $y<10$, Grey for $10 \le y < 27$, White otherwise) [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: Depends on the depth of the tree and the number of nodes visited per ray. In the worst case (dense scene), it is proportional to the number of voxels; in sparse scenes, it is logarithmic with respect to the resolution.
*   **Memory Complexity**: Linear with respect to the number of nodes and leaves in the SVO/BVH. The implementation uses parallel arrays, requiring storage for `center`, `radius`, `left_child`, `right_child` per node, and `model_address`, `inv_model` per leaf [S1, unofficial].
*   **Performance**: The provided implementation uses a CPU-side construction phase (sorting, queue-based tree building) and a GPU-side or CPU-side rendering phase. The specific hardware performance is not given, but the use of parallel arrays suggests cache-friendly traversal if implemented in a shader [S1, unofficial].
*   **Strengths**: Efficient for sparse data; no need for dense texture memory; flexible resolution.
*   **Limitations**: Construction can be slow for very large datasets if not optimized; stack depth can be an issue for deep trees if not managed carefully [S1, unofficial].

## Background
The method originates from unofficial implementations of SVO rendering, specifically the `mxbrt/svo` repository and `Dean904/Senior-Project-Volumetric-Rendering` [S1, S2, unofficial]. It builds on the principles of Sparse Voxel Octrees and BVH construction, adapting them for real-time or near-real-time raycasting.
