# LCTS Improvements

Also called: LCTS Optimizations

## Overview
LCTS Improvements are a set of optimizations for the Longest Common Traversal Sequence (LCTS) method [S1, unofficial]. They address structural complexity and traversal termination in sparse voxel grids. Unification of empty leaves simplifies the traversal sequence structure, while a common termination object allows early exit [S1, unofficial]. An initial leaf sequence enables HLCTS to match new ray histories against existing common sequences [S1, unofficial].

## How it works
The method modifies the LCTS data structure and traversal logic.

**Inputs:**
- LCTS structure (sequence of leaf nodes).
- Ray traversal history.

**Outputs:**
- Optimized traversal sequence.
- Termination status.

**Data Structures:**
- **LCTS Sequence:** A list of leaf nodes representing the common traversal path.
- **Termination Object:** A convex geometric primitive defining the end of the traversal volume [S1, unofficial].

**Steps:**
1. **Unify Empty Leaves:** Traverse the LCTS sequence and merge consecutive empty leaf nodes into a single entry or remove them to simplify the structure [S1, unofficial].
2. **Apply Termination Object:** During traversal, check if the ray has exited the convex termination object. If so, stop traversal early [S1, unofficial].
3. **Initialize HLCTS Sequence (for HLCTS only):** When constructing a new HLCTS from an existing one and a new ray, copy the initial leaf nodes of the existing HLCTS without matching them against the new ray's history. These copied nodes form the initial leaf sequence [S1, unofficial].

**Pseudocode:**
```python
def unify_empty_leaves(lcts_sequence):
    """Remove or merge consecutive empty leaves in the LCTS sequence."""
    new_sequence = []
    for leaf in lcts_sequence:
        if leaf.is_empty():
            # Unify empty leaves: either skip or merge with previous
            if new_sequence and new_sequence[-1].is_empty():
                # Merge logic: update size or count
                pass
            else:
                new_sequence.append(leaf)
        else:
            new_sequence.append(leaf)
    return new_sequence

def check_termination(ray, termination_object):
    """Check if ray has exited the convex termination object."""
    # Assuming termination_object is convex
    return not termination_object.contains(ray.current_position())

def initialize_hlcts_sequence(existing_hlcts, new_ray_history):
    """Copy initial leaves of existing HLCTS without matching."""
    # Initial leaf nodes are copied, not matched
    initial_leaves = existing_hlcts.initial_leaves.copy()
    return initial_leaves
```

**Parameters:**
- **Termination Object:** Must be convex [S1, unofficial].

**Edge Cases:**
- **Non-convex Termination Object:** The optimization assumes convexity; non-convex objects may cause incorrect early termination [S1, unofficial].
- **Empty Leaf Unification:** Ensure that unifying empty leaves does not lose necessary spatial information for subsequent rays [S1, unofficial].

## Subtopics

### [Hierarchical Longest Common Traversal Sequence](21519-hierarchical-longest-common-traversal-sequence.md)
HLCTS is a hierarchical extension of the Single Longest Common Traversal Sequence (SLCTS) method. It matches traversal histories to create a common traversal history for multiple rays, allowing the incremental construction of common sequences. It sets itself apart from SLCTS by supporting the accumulation of coherence across more than two rays, enabling the reuse of traversal state for a growing group of rays rather than just a pair.

## Operating characteristics
- **Time Complexity:** Unifying empty leaves reduces the number of nodes to traverse, potentially improving performance. Early termination reduces traversal depth.
- **Memory Complexity:** Unification reduces the size of the LCTS sequence.
- **Strengths:** Simplifies structure, enables early exit, supports incremental coherence in HLCTS.
- **Limitations:** Requires convex termination object. Unification may not be beneficial if empty leaves are sparse.

## Background
The LCTS method was introduced by Vlastimil Havran and Jiri Bittner [S1, unofficial]. These improvements were proposed to enhance the efficiency and applicability of LCTS, particularly for HLCTS [S1, unofficial].
