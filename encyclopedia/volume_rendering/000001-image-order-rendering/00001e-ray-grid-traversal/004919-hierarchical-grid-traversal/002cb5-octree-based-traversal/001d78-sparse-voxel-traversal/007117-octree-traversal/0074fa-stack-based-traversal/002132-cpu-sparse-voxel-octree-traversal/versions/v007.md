# CPU Sparse Voxel Octree Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Ray Tracing with Stack-Based Traversal, Sparse Voxel Octree Tracing, Stack-based Sparse Voxel Octree Traversal

## Overview
CPU Sparse Voxel Octree Traversal is a real-time ray traversal algorithm for 3D sparse voxel octrees (SVO) that uses a stack-based approach to navigate from the root to leaf voxels, calculating intersections with node boundaries to determine the next octant [S1, S2, S3, unofficial]. It solves the problem of efficiently locating and sampling occupied voxels in a hierarchical spatial structure without relying on recursive function calls, thereby avoiding stack overflow risks and satisfying hardware constraints [S2, unofficial]. It sets itself apart from its siblings by using a linear block structure and explicit stack management to handle valid internal nodes, leaf nodes, and empty space, often optimizing for CPU cache locality and avoiding the sorting of children by distance required by other hierarchical methods [S1, S2, S3, unofficial].

## How it works
The method traverses an SVO stored in a linear block structure. The core mechanism involves maintaining a stack of traversal states, where each state contains the node index or pointer, and intersection parameters relative to the ray [Parent].

### Inputs and Outputs
*   **Inputs**:
    *   Ray: Origin $O$, Direction $D$ (normalized).
    *   SVO: Root node, containing a hierarchy of `Voxel` and `Leaf` structures.
    *   Camera parameters: Screen width $W$, height $H$, field of view $fov$ [S3, unofficial].
*   **Outputs**:
    *   Pixel color (e.g., RGB or RGBA) for the ray's corresponding screen coordinate.
    *   Default color (e.g., background) if the ray misses all occupied voxels [S2, S3, unofficial].

### Data Structures
The SVO nodes are stored in a linear array (block). The specific layout varies by implementation, but common fields include:

**Node Structure (`vx_node` or `Voxel`)** [S2, S3, unofficial]:
*   `valid_masks` (uint32_t): Bitmask of 8 bits indicating which children exist (are non-empty).
*   `leaf_mask` (uint32_t): Bitmask of 8 bits indicating which children are leaf voxels.
*   `child_pointers` (uint32_t[8]): Indices into the root array for children.
*   `is_leaf` (bool): Indicates if the current node is a leaf.
*   `is_valid` (bool): Indicates if the node contains data.

**Stack Entry Structure** [S2, S3, unofficial]:
*   `voxel`: Pointer or index to the current node in the linear block.
*   `box`: Bounding box (AABB) of the current node, defined by `min` and `max` coordinates.
*   `half_size`: Half the side length of the current node's bounding box.
*   `octant`: The octant index (0-7) of the child being traversed.
*   `planes`: Intersection planes or distances for the current node boundaries.

### Numbered Steps

1.  **Initialization**:
    *   Compute ray direction for each pixel $(i, j)$:
        $$ screen\_x = \frac{i \cdot fov}{W} - 0.5 $$
        $$ screen\_y = \frac{j \cdot fov}{H} - 0.5 $$
        $$ direction = (screen\_x \cdot scale.x, -scale.y, screen\_y \cdot scale.z) $$ [S3, unofficial]
    *   Initialize the stack with the root node and the ray's entry/exit distances for the root bounding volume. The root bounding box is typically the axis-aligned bounding box (AABB) of the entire scene [S1, S3, unofficial].
    *   Set `stack_pos = 0` [S2, unofficial].

2.  **Traversal Loop**:
    *   While `stack_pos >= 0`:
        *   Pop the top state from the stack (implicitly by decrementing `stack_pos` after processing or managing it via index) [S2, S3, unofficial].
        *   **Check Validity**: Check if the current node has the target child (octant) using `valid_masks`:
            ```python
            if not (node.valid_masks & (1 << octant)):
                # Child does not exist, skip to next stack item
                continue
            ``` [S2, unofficial]
        *   **Check Leaf**: If the child is a leaf voxel:
            ```python
            if node.leaf_mask & (1 << octant):
                # Retrieve voxel struct
                voxel = octree.root[child_ptr]
                # Compute lighting/color
                color = compute_lighting(voxel, ray)
                return color
            ``` [S2, unofficial]
        *   **Traverse Internal Node**:
            *   Compute intersection distances for the children. This is often done by determining the first intersecting plane of the current node's boundaries [S2, S3, unofficial].
            *   Calculate $t$ values for the planes:
                $$ t = \frac{planes - ray\_origin}{ray\_direction} $$ [S2, unofficial]
            *   Determine the first intersecting plane:
                $$ intersection\_plane = \arg\min(t[0], t[1], t[2]) $$ [S2, unofficial]
            *   Identify the octant of the child the ray enters.
            *   Push the child node onto the stack in reverse order of distance (farthest first) to ensure the closest child is popped next. In many SVO implementations, this is handled by pushing only the relevant children (up to 4) based on grid traversal order, avoiding full sorting [S1, S2, unofficial].
            *   Update the bounding box and half-size for the child:
                $$ box_{child} = box_{parent} + \text{IfThenElseZero}(octant, half\_size) $$
                $$ half\_size_{child} = half\_size_{parent} \times 0.5 $$ [S2, unofficial]
            *   Increment `stack_pos` and update the octant and planes for the new level [S2, unofficial].

3.  **Backtracking**:
    *   If the ray exits a node (i.e., $t > t_{max}$ for the current node's bounds), pop the stack.
    *   When popping, update the parent's state:
        $$ half\_size_{parent} *= 2.0 $$
        $$ box_{parent} -= \text{IfThenElseZero}(octant, half\_size_{parent}) $$
        $$ octant_{parent} \oplus= hit\_face $$ [S2, S3, unofficial]
    *   Continue to the next item on the stack.

4.  **Termination**:
    *   If the stack is empty and no leaf was hit, return the default background color (e.g., opaque red `0xFF000000` or a specific blue channel value) [S2, S3, unofficial].

### Pseudocode
```python
def traverse_svo(ray, octree, width, height, fov):
    # Initialize screen coordinates
    screen_x = (ray.pixel_i * fov) / width - 0.5
    screen_y = (ray.pixel_j * fov) / height - 0.5
    direction = Vector(screen_x * scale.x, -scale.y, screen_y * scale.z)
    
    # Initialize stack
    stack = []
    stack.push(RootNode, ray.origin, direction, root_box)
    
    while stack is not empty:
        node, origin, dir, box = stack.pop()
        
        # Check if node is valid and has children
        if not node.is_valid:
            continue
            
        # Determine octant
        octant = get_octant(origin, dir, box)
        
        # Check if child exists
        if not (node.valid_masks & (1 << octant)):
            continue
            
        # Check if child is a leaf
        if node.leaf_mask & (1 << octant):
            child_ptr = node.child_pointers[octant]
            leaf = octree.get_leaf(child_ptr)
            return compute_color(leaf, origin, dir)
        
        # Internal node: compute children intersections
        # Calculate intersection t values for planes
        t = (planes - origin) / dir
        hit_plane = argmin(t)
        
        # Identify next octant and push children
        # Only push up to 4 children to avoid sorting
        for child_octant in get_relevant_children(octant, hit_plane):
            if node.valid_masks & (1 << child_octant):
                child_box = update_box(box, child_octant)
                child_half_size = box.half_size * 0.5
                stack.push(node.child_pointers[child_octant], origin, dir, child_box)
                
    return default_color
```

### Parameters
*   **MAX_DETAIL_LEVEL**: Maximum recursion depth for the octree traversal, typically set to 20 [S2, unofficial].
*   **SVO Resolution**: The base resolution of the voxel grid, e.g., 256 [S1, unofficial].
*   **Screen Dimensions**: Width and Height in pixels, e.g., 1280x720 [S3, unofficial].
*   **Field of View (fov)**: Factor where 1.0 corresponds to 90 degrees, default 1.2 [S3, unofficial].

### Edge Cases and Pitfalls
*   **Empty Stack**: If the stack becomes empty before a leaf is hit, the ray has exited the scene. Return a default color [S2, S3, unofficial].
*   **Invalid Nodes**: Skip nodes where `valid_masks` does not include the current octant [S2, unofficial].
*   **Precision**: Handle zero direction components in ray-box intersection tests by clamping $d_i$ to $\epsilon$ or using infinity for $t$ calculations to avoid division by zero [Parent].
*   **Stack Overflow**: Using an explicit stack prevents stack overflow issues associated with recursive traversal [S2, unofficial].

## Subtopics

### [Parametric Octree Traversal](2361-parametric-octree-traversal.md)
Parametric Octree Traversal is a top-down algorithm for finding the subset of voxels in an octree intersected by a straight line (ray). It computes parameter values at which the ray intersects voxel boundary planes incrementally using additions and divisions by two, and selects child sub-voxels via comparisons on these parameter values to avoid neighbor finding. It sets itself apart from its siblings and nearest alternatives by using simple comparisons on ray parameters to determine the first sub-voxel and subsequent transitions, thereby avoiding the neighbor-finding overhead of bottom-up methods like Samet and the sorting of potentially visited sub-voxels required by the HERO algorithm.

### [Iterative Octree Traversal](2618-iterative-octree-traversal.md)
Iterative Octree Traversal is a method for raycasting against a Sparse Voxel Octree (SVO) that replaces recursive function calls with an explicit stack-based data structure, primarily to satisfy hardware constraints such as HLSL recursion limits or CPU stack size restrictions. It solves the problem of traversing hierarchical spatial data without risking stack overflow or violating shader model restrictions, using a greedy approach that prioritizes the closest node and backtracks on false positives. Unlike [Recursive Octree Traversal](2632-recursive-octree-traversal.md), which relies on the call stack, this method explicitly manages traversal state and parent pointers to navigate the tree hierarchy.

### [Recursive Octree Traversal](2632-recursive-octree-traversal.md)
Recursive octree traversal is a standard algorithm for ray casting against a 3D sparse voxel octree, where the traversal logic is implemented via a recursive function that visits nodes in depth-first order. It solves the problem of efficiently locating and sampling leaf nodes (or specific depth levels) along a ray by recursively descending into child nodes only when the ray intersects their axis-aligned bounding boxes (AABBs). It differs from its siblings by relying on the call stack for state management rather than an explicit stack or parametric surface equations.

### [Compact Voxel Octree Raycasting](2980-compact-voxel-octree-raycasting.md)
Compact Voxel Octree Raycasting is a CPU-based ray traversal algorithm for Sparse Voxel Octrees that optimizes memory layout and traversal logic by compacting active ray-voxel interactions and decoding node masks on-the-fly. It solves the problem of inefficient traversal in sparse structures by using an explicit stack to manage non-sequential memory layouts and a parallel "COMPACTIFY" step to filter out non-intersecting rays, ensuring that only valid ray-voxel pairs are processed in subsequent levels. Unlike recursive or parametric approaches, it relies on a linear block structure with explicit state management, making it suitable for high-performance CPU implementations where memory bandwidth and cache locality are critical. It builds on [CPU Sparse Voxel Octree Traversal](2455-cpu-sparse-voxel-octree-traversal.md) and differs from [Parametric Octree Traversal](2361-parametric-octree-traversal.md), [Iterative Octree Traversal](2618-iterative-octree-traversal.md), [Recursive Octree Traversal](2632-recursive-voxel-octree-traversal.md), and [Sparse Voxel Octree Path Tracing](2988-sparse-voxel-octree-path-tracing.md) by explicitly managing traversal state and compacting active ray lists between levels.

### [Sparse Voxel Octree Path Tracing](2988-sparse-voxel-octree-path-tracing.md)
Sparse Voxel Octree (SVO) Path Tracing is a CPU-based rendering technique that traverses a sparse voxel octree (or DAG) structure to compute physically based lighting via recursive path tracing. It solves the problem of rendering complex, high-resolution voxel-based scenes efficiently by skipping empty space and only processing occupied nodes, writing the accumulated radiance to a texture for display. Unlike its siblings which focus on specific traversal optimizations (e.g., parametric or iterative steps), this method integrates the traversal directly into a Monte Carlo path tracer with Russian roulette termination, diffuse/specular bounces, and material properties (metalness, roughness, emission) stored in the leaf nodes.

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of nodes visited along the ray path. In practice, this is much less than the total number of voxels due to the sparsity of the octree.
*   **Memory Complexity**: $O(D)$ where $D$ is the depth of the octree, for the stack. The SVO itself requires $O(V)$ memory where $V$ is the number of voxels.
*   **Measured Performance**: A 256 resolution SVO of the Sponza scene renders at 200 ms per frame on a GTX 1070 [S1, unofficial].
*   **Strengths**:
    *   Avoids sorting children by distance, unlike methods that check all 8 children [S1, unofficial].
    *   Explicit stack management prevents stack overflow [S2, unofficial].
    *   Efficient for sparse scenes by skipping empty space [S1, S2, unofficial].
*   **Limitations**:
    *   Performance can degrade if the scene is dense or the ray passes through many small nodes.
    *   Requires careful handling of precision and boundary conditions [Parent].
*   **When to Use**: Suitable for real-time rendering of large, sparse voxel-based scenes on CPU or GPU where memory bandwidth and cache locality are critical [S2, unofficial].
*   **When Not to Use**: Not ideal for dense, uniform voxel grids where a simple 3D texture lookup might be faster [S1, unofficial].

## Background
CPU Sparse Voxel Octree Traversal originated from the need to render high-resolution, complex 3D scenes efficiently. The method is inspired by the work of Euclideon and has been implemented in various open-source projects such as `voxl` and `zazen` [S2, S3, unofficial]. The use of a stack-based approach allows for efficient traversal without the overhead of recursion, making it suitable for both CPU and GPU implementations [S2, unofficial]. The algorithm has been optimized for real-time performance, with techniques such as limiting the number of children checked per voxel and avoiding sorting [S1, unofficial].
