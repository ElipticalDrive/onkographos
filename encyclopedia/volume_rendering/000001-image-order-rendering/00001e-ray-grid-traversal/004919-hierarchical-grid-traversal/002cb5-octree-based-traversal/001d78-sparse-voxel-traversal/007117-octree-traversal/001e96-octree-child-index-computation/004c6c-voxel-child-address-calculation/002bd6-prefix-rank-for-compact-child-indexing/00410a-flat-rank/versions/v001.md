# Flat Rank

Also called: Flat Rank for Compact Child Indexing

## Overview
Flat Rank is a space-efficient data structure for answering rank queries on bit vectors in constant time [S1]. It solves the problem of efficiently counting the number of set bits (1-bits) preceding a given index in a bitmask, which is critical for mapping child indices to compact payload indices in sparse octrees [S1]. It sets itself apart from its siblings by achieving this with minimal additional space overhead (3.51%) compared to other constant-time rank approaches [S1].

## How it works
**Inputs and Outputs:**
- Input: A bit vector $W$ of length $n$, and an index $i$ ($0 \le i < n$).
- Output: The rank value $r = \text{rank}_1(i)$, defined as the number of 1-bits in $W$ at indices $j < i$ [S1].

**Data Structures:**
The structure consists of the original bit vector $W$ and an auxiliary array $A$.
- $W$: The bit vector itself.
- $A$: An array of size $\lceil n / b \rceil$, where $b$ is the block size. $A[k]$ stores the cumulative count of 1-bits in $W$ from index $0$ up to the end of block $k-1$. Specifically, $A[k] = \sum_{j=0}^{k \cdot b - 1} W[j]$ [S1].

**Parameters:**
- Block size $b$: Not explicitly given in the sources. [G] Typical values in literature are powers of 2 (e.g., 64 or 128) to align with word sizes, but the source does not specify.
- Space overhead: 3.51% of the original bit vector size [S1].

**Steps:**
1. **Partitioning:** Divide the bit vector $W$ into contiguous blocks of size $b$.
2. **Precomputation:** Compute the prefix sums of 1-bit counts for each block. Store these cumulative counts in array $A$. Let $A[0] = 0$. For $k > 0$, $A[k]$ is the total number of 1-bits in $W[0 \dots k \cdot b - 1]$.
3. **Query Execution:** To compute $\text{rank}_1(i)$:
   a. Determine the block index $k = \lfloor i / b \rfloor$.
   b. Retrieve the base count from $A[k]$.
   c. Count the number of 1-bits in the remaining partial block $W[k \cdot b \dots i - 1]$. Let this count be $c$.
   d. The result is $A[k] + c$.

**Pseudocode:**
```python
def flat_rank(W, A, b, i):
    """
    W: bit vector (list of integers 0/1 or bitset)
    A: auxiliary array of cumulative block counts
    b: block size
    i: query index
    Returns: number of 1-bits in W[0...i-1]
    """
    # Step 1: Get base count from precomputed array
    k = i // b
    base_count = A[k]
    
    # Step 2: Count bits in the partial block
    start_idx = k * b
    end_idx = i
    
    # Count 1-bits in W[start_idx:end_idx]
    # Note: In practice, this uses bit manipulation instructions (e.g., popcount)
    partial_count = 0
    for j in range(start_idx, end_idx):
        if W[j] == 1:
            partial_count += 1
            
    return base_count + partial_count
```

**Edge Cases and Pitfalls:**
- If $i=0$, the rank is 0.
- If $i=n$, the rank is the total number of 1-bits in $W$.
- Precision issues are not applicable as the operation is integer-based.
- Boundary conditions for block alignment must be handled correctly in the partial block counting step.

## Operating characteristics
- **Time Complexity:** $O(1)$ for rank queries [S1]. The block lookup is $O(1)$, and the partial block count is bounded by $b$, which is constant.
- **Space Complexity:** $O(n)$ for the bit vector plus $O(n/b)$ for the auxiliary array. The total space overhead is 3.51% [S1].
- **Measured Performance:** The source cites it as the "currently most space-efficient approach maintaining reasonable query performance" [S1].
- **Strengths:** Minimal space overhead, constant-time queries.
- **Limitations:** Requires precomputation of the auxiliary array. Performance depends on block size choice for the partial block scan.
- **When to use:** When space is constrained and constant-time rank queries are needed on bit vectors, such as in sparse voxel octrees.
- **When not to use:** When dynamic updates to the bit vector are frequent, as the auxiliary array would need updates.

## Background
Flat Rank was introduced by Kurth in 2022 [S1]. It is based on the general idea of partitioning bit vectors into blocks and storing cumulative counts, a technique previously explored in [Jac89] for constant-time rank queries on bit vectors [S1]. It is used in the context of wavelet trees and compressible index data structures for applications like text indexing and computational geometry [S1].
