# Hierarchical Traversal

Also called: SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal is a method for accelerating ray-object intersection and volume rendering by utilizing a hierarchy of grids where each higher-level cell covers a $2 \times 2$ area of the level below [S1, unofficial]. It solves the problem of inefficiently traversing large, sparse datasets by allowing the ray to take larger steps through empty space at coarser levels, reducing the total number of traversal steps compared to non-hierarchical methods [S1, unofficial]. Unlike flat grid traversal, it dynamically subdivides the highest stored level on demand to represent the grid, enabling sparse storage and traversal [S1, unofficial].

## How it works
**Inputs:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, and a hierarchical data structure (e.g., Sparse Voxel Octree or BVH) where nodes represent spatial extents.
**Outputs:** A sequence of active nodes or leaves intersected by the ray, or a boolean indicating intersection.

**Data Structures:**
The structure depends on the specific implementation variant (e.g., SVO vs. BVH).
*   **SVO Node:** Typically contains flags for occupancy/active status and indices to children. In some implementations, leaf nodes are identified by setting the high bit (0x80000000) of the child indices [S2, unofficial].
*   **BVH Node:** A common layout includes a center `[f32; 4]`, radius `f32`, and left/right child indices `u32`, packed in 16-byte alignment [S2, unofficial]. Leaf nodes may be stored separately with inverse model matrices and model addresses [S2, unofficial].
*   **Cell Naming:** In grid-based hierarchies, Level 0 cells are $1 \times 1$, Level 1 are $2 \times 2$, and Level 2 are $4 \times 4$, with coordinates defined by the area they occupy in Level 0 [S1, unofficial].

**Steps:**
1.  **Initialization:** Initialize a traversal stack. For BVH, push the root node index. For SVO, start at the root cell [S2, unofficial][S3, unofficial].
2.  **Traversal Loop:** While the stack is not empty:
    *   Pop the current node index from the stack.
    *   Retrieve the node data.
    *   **Intersection Test:** Determine if the ray intersects the current node's bounding volume.
    *   **Descend:**
        *   If the node is a leaf, process it (e.g., return true if active, or collect for rendering) [S6, unofficial].
        *   If the node is a branch/internal node:
            *   Identify which children (up to 8 for octree, 2 for BVH) intersect the ray.
            *   If both children need descending, push the child with the smaller intersection distance ($t_{min}$) onto the stack, then descend into the closer child [S2, unofficial].
            *   If only one child intersects, descend into that child.
            *   If neither, pop from stack (continue to next item).
3.  **Termination:** Return the result (e.g., intersection distance, active leaf list, or boolean) [S2, unofficial].

    stack_ptr = 0

        stack_ptr -= 1
        
        node = bvh_nodes[node_idx]
        
        # Check intersection with node bounding box
        t_min, t_max = intersect_box(ray_origin, ray_direction, node.center, node.radius)
        
        if t_max < 0 or t_min > 10000.0:  # Arbitrary far plane cutoff
            continue
            
        # Check if leaf
        is_leaf = (node.left_child & 0x80000000) != 0
        
        if is_leaf:
            # Process leaf (e.g., return true or store intersection)
            return true
            
        # Determine children to visit
        left_child_idx = node.left_child & 0x7FFFFFFF
        right_child_idx = node.right_child & 0x7FFFFFFF
        
        # Handle case where leaf is last element and has no sibling
        if right_child_idx == 0:
            right_child_idx = left_child_idx # Or handle as single child
            
        # Calculate intersection distances for children
        left_t_min, left_t_max = intersect_box(ray_origin, ray_direction, 
                                               bvh_nodes[left_child_idx].center, 
                                               bvh_nodes[left_child_idx].radius)
        right_t_min, right_t_max = intersect_box(ray_origin, ray_direction, 
                                                 bvh_nodes[right_child_idx].center, 
                                                 bvh_nodes[right_child_idx].radius)
        
        # Decide order based on closest intersection
        if left_t_max > 0 and left_t_min < right_t_min:
            # Left is closer, push right then descend left
            if stack_ptr < stack_capacity - 1:
                stack_ptr += 1
                stack[stack_ptr] = right_child_idx
            # Descend left
            node_idx = left_child_idx
            # Loop continues with new node_idx
        elif right_t_max > 0:
            # Right is closer or only valid

                stack_ptr += 1

            node_idx = right_child_idx

            # Neither intersects (should have been caught by initial test, but for safety)

**Pseudocode (SVO/Recursive Variant):**
```python
def traverse_svo(ray, current_cell, path):
    if path is empty:
        return current_cell
        
    octant = path.pop(0)
    
    if current_cell is Branch:
        children = current_cell.get_children()
        next_cell = children[octant]
        return traverse_svo(ray, next_cell, path)
    else:
        return current_cell
```

**Parameters:**
*   **Stack Size:** Depends on tree depth. For SVO, typically logarithmic with respect to resolution [S1, unofficial].
*   **Far Plane:** Arbitrary cutoff (e.g., 10000.0) to terminate traversal [S2, unofficial].

**Edge Cases:**
*   **Boundary Voxels:** Special handling may be required for rays hitting the boundary of the volume, where step masks might be zero [S2, unofficial].
*   **Empty Siblings:** If a leaf is the last element and has no sibling, its right child index may be set to an empty node index (0) [S2, unofficial].
*   **Precision:** Small ray direction components should be clamped to avoid division by zero during slab intersection calculations [S2, unofficial].

## Subtopics

### [Leaf Collection](899-leaf-collection.md)
Leaf Collection identifies and gathers all terminal nodes (leaves) intersected by a ray grid during hierarchical traversal, converting a sparse traversal path into a contiguous list of active volumetric blocks for subsequent ray marching or shading. It separates node identification from radiance computation to enable efficient memory compaction and parallel processing. [899-leaf-collection.md]

### [Point Plane Test Traversal](982-point-plane-test-traversal.md)
Point Plane Test Traversal is a method for locating the specific child tetrahedron within a TET-AMR refinement tree that contains a given query point. It solves the in-element lookup problem by traversing from the coarse root to the leaf using geometric half-space tests against planes defined by edge midpoints, avoiding the redundancy of checking all eight children individually. It is distinguished from Leaf Collection by its on-the-fly vertex computation and from VolumeHDDA by its reliance on explicit geometric plane tests rather than incremental rasterization logic. [982-point-plane-test-traversal.md]

### [Mesh BVH](1062-mesh-bvh.md)
Mesh BVH is a GPU-accelerated bounding volume hierarchy designed for triangle meshes to support efficient distance queries and ray intersection tests. It provides spatial indexing for unsigned distance calculation and topological signing. Unlike leaf collection or point-plane tests which may handle specific traversal optimizations, Mesh BVH provides the foundational spatial indexing for both unsigned distance calculation and topological signing. [1062-mesh-bvh.md]

### [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md)
Multi-resolution rendering with K-D Tree is a hierarchical volume rendering technique that accelerates image-order ray casting by storing approximations of the underlying data within K-D tree nodes. It solves the performance bottleneck of rendering large, high-resolution datasets by allowing the renderer to skip detailed traversal when the data within a spatial region can be represented by a simple model within a user-specified error threshold. Unlike wavelet-based methods which store only detail coefficients, this method stores a complete model for each region, enabling fast "preview" images and adaptive detail. It builds on Hierarchical Traversal. [1942-multi-resolution-rendering-with-k-d-tree.md]

### [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md)
Coarse Mesh Traversal is a hierarchical rendering technique that accelerates volume rendering by decoupling the global search for active data regions from the local sampling of fine-grained geometry. It solves the problem of inefficiently traversing large, sparse, or multi-resolution datasets by first identifying which coarse elements (macrocells) a ray intersects, and then performing detailed rendering only within those specific regions. What sets it apart from its siblings is the explicit construction of a coarse mesh (typically a BVH) from the underlying adaptive or hierarchical data structure, allowing the renderer to skip empty or irrelevant volumes entirely before entering the fine-level traversal loop. [3062-coarse-mesh-traversal.md]

### [Node Omission in Ray-Tree Traversal](3305-node-omission-in-ray-tree-traversal.md)
Node omission is an optimization for hierarchical ray-tree traversal that prevents adding child nodes to the traversal stack if it is known they will not intersect the current ray, reducing the number of intersection tests. It sets itself apart from sibling methods like Leaf Collection and Point Plane Test Traversal by operating on the spatial relationship between the ray's entry/exit parameters and the node's bounding box midpoints, rather than relying on leaf-level data structures or plane-based splitting planes. [3305-node-omission-in-ray-tree-traversal.md]

### [Two-Pass Hierarchy Traversal](3339-two-pass-hierarchy-traversal.md)
Two-Pass Hierarchy Traversal is a spatial hierarchy traversal optimization that reduces computational cost by splitting the descent into a coarse initial pass and a fine subsequent pass. It sets itself apart from single-pass methods like Leaf Collection or Point Plane Test Traversal by explicitly decoupling the identification of relevant subtrees from the detailed node evaluation, allowing for significant reuse across pixel blocks. [3339-two-pass-hierarchy-traversal.md]

### [Adaptive Out-of-Core Single-Pass GPU Raycasting](3440-adaptive-out-of-core-single-pass-gpu-raycasting.md)
This method enables interactive rendering of multi-gigabyte scalar volumes on desktop hardware by combining an out-of-core octree data structure with a single-pass, stackless GPU raycasting algorithm. It solves the memory capacity and bandwidth bottlenecks of in-core rendering by maintaining a view- and transfer-function-dependent working set of volumetric bricks in GPU memory, while the rest of the dataset remains on disk. Unlike separate block rendering techniques that suffer from boundary artifacts and cannot support refractive or global illumination models, this approach performs the entire volume traversal and compositing in a single fragment shader pass, adapting sampling density to the local brick resolution. [3440-adaptive-out-of-core-single-pass-gpu-raycasting.md]

### [Initial Upper Bound Estimation](15442-initial-upper-bound-estimation.md)
Initial Upper Bound Estimation is a heuristic sampling process that computes a tight initial upper bound to prune BVH-tree traversal during distance field computation. It reduces the number of nodes visited by providing a conservative estimate of the distance to the isosurface before the full traversal begins. Unlike methods that rely on fixed grid resolutions or complex hierarchical structures for early exit, this method uses a small, fixed set of sample points to establish a global constraint that guides the search. [15442-initial-upper-bound-estimation.md]

#### Surface Descendant Check
If the cell is a Leaf, return whether it has a sign change. If it is a Branch, recursively check if any of its children have a surface descendant. If it is Empty or Full, return false. [S3, unofficial]

#### Coarse Mesh Traversal via BVH
Uses a Bounding Volume Hierarchy (BVH) built over the coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point. Build a triangle BVH over the coarse mesh by inserting four triangular faces facing outside for every coarse element. Trace rays into the BVH using OptiX Wrapper Library (OWL) hit and miss functions. The hit function returns the hit point and the coarse tetrahedron ID. The miss function reports no intersection with BVH faces. Unlike element marching which uses connectivity, point location querying skips coarse elements not being sampled and allows varying refinement levels in the coarse mesh. [S7, unofficial]

#### Warp-Level Intersection Caching
Optimization to delay intersection tests until enough threads in a warp have stored an intersection child node. When an intersection is found, store the current voxel intersection data. At the start of every traversal step, check if enough threads have a stored intersection. If so, proceed by doing an intersection test. Otherwise, continue traversal with the complete warp. If threads find the next intersection test while already having an intersection stored, stop traversing until the next intersection test is performed. [S8, unofficial]

#### BFS Hierarchy Cut Algorithm
An algorithm to cut a binary tree hierarchy along a certain condition using a breadth-first search (BFS) queue. [S9, unofficial]

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for balanced trees, where $N$ is the number of voxels/objects, assuming uniform distribution. In practice, it reduces the number of steps significantly compared to linear traversal. For example, hierarchical SVO traversal took 5 steps to intersect an occupied voxel, while non-hierarchical traversal took 11 steps in a comparable example [S1, unofficial].
*   **Memory Complexity:** Depends on the sparsity. SVO stores only occupied nodes, leading to significant space savings for sparse data compared to full octrees or grids [S1, unofficial]. BVH memory is proportional to the number of primitives and tree depth.
*   **Performance:** The technique is several times faster than other published algorithms for ray/object intersection [S4, unofficial].
*   **Strengths:** Efficient empty space skipping, adaptive resolution, reduced memory footprint for sparse data.
*   **Limitations:** Overhead of tree traversal logic, potential for stack overflow in deep trees (mitigated by stackless techniques or ropes [S5, unofficial]), complexity of implementation.
*   **When to Use:** Large, sparse volumetric datasets or complex scenes with many objects where empty space is prevalent.
*   **When Not to Use:** Dense, fully occupied grids where the overhead of traversal outweighs the benefit of skipping, or when hardware supports efficient linear texture sampling.

## Background
Hierarchical traversal originated from the need to accelerate ray tracing and volume rendering. Early work by Kay and Kajiya (1986) introduced a new hierarchy traversal algorithm for speeding up ray-object intersection calculations, demonstrating that objects could be placed into a hierarchy and queried in an efficient order, resulting in scenes with hundreds of thousands of objects being traceable [S4, unofficial]. The concept of using octrees and SVOs for volume rendering builds on the idea that a hierarchy of grids, where higher-level cells cover $2 \times 2$ areas of the level below, allows for larger steps through empty space [S1, unofficial]. GPU implementations have evolved to use techniques like "ropes" and kd-restart to manage stack usage [S5, unofficial].
