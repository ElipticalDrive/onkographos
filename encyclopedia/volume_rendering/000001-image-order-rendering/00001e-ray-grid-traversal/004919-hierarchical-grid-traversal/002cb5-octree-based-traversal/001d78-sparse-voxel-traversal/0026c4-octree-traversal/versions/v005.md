# Octree Traversal

Also called: Hierarchical Octree Traversal, Octree Space Subdivision

## Overview
Octree Traversal is a hierarchical ray-intersection method that accelerates volume rendering by recursively subdividing 3D space into eight equal blocks (octants) to skip empty regions [S1, S2, S3, unofficial]. It solves the problem of excessive sampling in large, sparse volumetric datasets by allowing rays to bypass non-occupied nodes, reducing the number of intersection tests compared to flat grid traversal [S1, S5, unofficial]. Unlike [Voxel Grid Raycasting](2218-voxel-grid-raycasting.md) which checks every voxel, or [Sparse Voxel Ray Marching with AABB Exit Planes](3252-sparse-voxel-ray-marching-with-aabb-exit-planes.md) which uses axis-aligned bounding boxes for irregular cells, Octree Traversal relies on strict 2x2x2 regular subdivision and mid-plane sorting to determine traversal order [S1, S5, unofficial].

## How it works
**Inputs:**
*   Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized).
*   Octree root node covering the bounding box $[x_{min}, x_{max}] \times [y_{min}, y_{max}] \times [z_{min}, z_{max}]$.
*   Node type metadata (Interior, Cap, Scalar Leaf, Empty).

**Outputs:**
*   List of occupied leaf nodes (or voxels) intersected by the ray, sorted by distance from $\mathbf{o}$ [S1, unofficial].

**Data Structures:**
*   **Node:** Contains type identifier, bounding box coordinates (or derived from level/position), and child pointers/indices.
    *   *Interior Node:* 8 child pointers (or indices into a linear array). May store min/max scalar values for culling [S4].
    *   *Cap Node:* Contains 8 finest-level voxels. Maps to a cell via reconstruction [S4].
    *   *Scalar Leaf:* Contains coarser-resolution scalar data. Embedded in parent [S4].
    *   *Empty Node:* No children; traversal terminates or skips [S1, unofficial].
*   **Stack:** Explicit stack required for GPU implementation to manage traversal state (current node, $t_{enter}$, $t_{exit}$) because recursion is not supported [S1, S2, unofficial].

**Steps:**
1.  **Initialization:** Push the root node and the ray's entry/exit parameters ($t_{enter}=0, t_{exit}=\infty$) onto the stack [S4].
2.  **Traversal Loop:** While the stack is not empty:
    a. Pop the current node and ray parameters.
    b. **Culling:** If the node is Empty or if the ray's $t$-range does not intersect the node's bounding box, discard and continue [S1, unofficial].
    c. **Leaf Check:** If the node is a Leaf (Scalar or Cap):
        i. Sample the voxel data.
        ii. Perform shading/compositing.
        iii. Record the hit position and depth.
        iv. Continue (do not recurse) [S4].
    d. **Interior Node Processing:**
        i. Compute the mid-planes of the current node: $x_{mid}, y_{mid}, z_{mid}$ [S4].
        ii. Compute intersection distances of the ray with these mid-planes:
            $$ t_{midX} = \frac{x_{mid} - o_x}{d_x} $$
            $$ t_{midY} = \frac{y_{mid} - o_y}{d_y} $$
            $$ t_{midZ} = \frac{z_{mid} - o_z}{d_z} $$
            [S4]
        iii. Sort $t_{midX}, t_{midY}, t_{midZ}$ to determine the order in which the ray crosses the octant boundaries [S4][S5, unofficial].
        iv. Determine the 0–7 octant index for each child based on the ray's position relative to the mid-planes using bitwise operations or geometric comparison [S1, unofficial][S4].
        v. Identify which of the 8 children are intersected by the ray within the current $t$-range. Note that a ray intersects at most 4 octants of a single node [S4].
        vi. Push the intersected children onto the stack, sorted by their intersection distance (front-to-back) [S4][S5, unofficial].
3.  **Termination:** The algorithm terminates when the stack is empty. All found voxels are written to an output array in sorted order [S1, unofficial].

**Pseudocode:**
```python
def traverse_octree(ray_origin, ray_dir, root_node):
    # Stack stores tuples: (node, t_enter, t_exit)
    stack = [(root_node, 0.0, float('inf'))]
    hits = []

    while stack:
        node, t_enter, t_exit = stack.pop()

        # 1. Culling: Check if node is empty or out of ray range
        if node.is_empty:
            continue
        if not ray_intersects_node(ray_origin, ray_dir, node.bounds, t_enter, t_exit):
            continue

        # 2. Leaf Processing
        if node.is_leaf:
            # Sample data and composite
            hit_pos = ray_origin + ray_dir * t_enter
            color = sample_volume(node, hit_pos)
            hits.append((t_enter, color))
            continue

        # 3. Interior Node Processing
        # Compute mid-planes
        mid_x = (node.bounds.min_x + node.bounds.max_x) / 2.0
        mid_y = (node.bounds.min_y + node.bounds.max_y) / 2.0
        mid_z = (node.bounds.min_z + node.bounds.max_z) / 2.0

        # Compute intersection distances with mid-planes
        # Handle division by zero if ray is parallel to plane
        t_mid_x = (mid_x - ray_origin.x) / ray_dir.x if ray_dir.x != 0 else float('inf')
        t_mid_y = (mid_y - ray_origin.y) / ray_dir.y if ray_dir.y != 0 else float('inf')
        t_mid_z = (mid_z - ray_origin.z) / ray_dir.z if ray_dir.z != 0 else float('inf')

        # Sort mid-plane intersections to determine traversal order
        # This determines the sequence of octants visited
        mid_distances = sorted([(t_mid_x, 'x'), (t_mid_y, 'y'), (t_mid_z, 'z')])

        # Determine which children are intersected
        # A ray intersects at most 4 octants
        intersected_children = []
        
        # Iterate through potential children based on ray direction and mid-plane crossings
        # For each child, compute its specific t_enter and t_exit relative to the parent's range
        for child_idx in range(8):
            child_bounds = get_child_bounds(node, child_idx)
            
            # Calculate intersection of ray with child bounds
            t_child_enter, t_child_exit = ray_box_intersection(ray_origin, ray_dir, child_bounds)
            
            # Check if intersection is within the valid range and not behind the current entry
            if t_child_exit > t_enter and t_child_enter < t_exit:
                intersected_children.append((t_child_enter, node.children[child_idx]))

        # Sort children by entry distance (front-to-back)
        intersected_children.sort(key=lambda x: x[0])

        # Push children to stack
        for t_enter_child, child in intersected_children:
            stack.append((child, t_enter_child, t_exit))

    # Sort final hits by depth
    hits.sort(key=lambda x: x[0])
    return hits
```

**Parameters:**
*   **Minimum Block Size:** Typically the size of a single voxel or a small brick (e.g., $2^3$ voxels) [S1, unofficial][S4].
*   **Stack Size:** Must be sufficient to hold the maximum depth of the octree plus branching factor overhead [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **GPU Recursion:** GPUs do not support recursive function calls; an explicit stack must be implemented, increasing memory usage and complexity [S1, unofficial].
*   **Irregular Geometry:** Octrees conform poorly to irregular geometry or meshes, leading to expensive traversal strategies compared to hierarchical grids [S5, unofficial].
*   **Node Types:** Separate traversal routines are required for Interior nodes (recursive descent), Scalar Leaves (constant scalar), and Cap nodes (voxel reconstruction) [S4].
*   **Precision:** Floating-point precision errors in mid-plane intersection calculations can lead to incorrect traversal order or missed nodes [G].

## Subtopics

### [Hierarchical Traversal](896-hierarchical-traversal.md)
Accelerates ray-object intersection by navigating a spatial hierarchy (Octree/SVO), skipping entire subtrees when inactive. Chosen for large datasets to reduce intersection tests.

### [Octree-based Volume Rendering](1131-octree-based-volume-rendering.md)
Baseline method using one-to-one brick-to-node mapping for spatial subdivision and empty-space culling. Distinguished by strict mapping and per-channel traversal.

### [Octree Child Index Computation](1807-octree-child-index-computation.md)
Determines the 0–7 octant offset using precomputed bit masks and constant-time bitwise operations. Sets itself apart by avoiding arbitrary bit shifts.

### [Octree Neighbor Finding](1821-octree-neighbor-finding.md)
Locates adjacent leaf nodes in six cardinal directions by finding the nearest shared ancestor. Solves traversal between non-contiguous nodes.

### [Ray Traversal of Octree Nodes](1841-ray-traversal-of-octree-nodes.md)
Determines exact sequential order of child octants by sorting ray intersection distances with X, Y, Z mid-planes. Effective for empty space skipping without pointer chasing.

### [CPU Sparse Voxel Octree Traversal](2455-cpu-sparse-voxel-octree-traversal.md)
CPU-based algorithm using a stack and linear block structure. Sets itself apart by performing all calculations on the host processor.

### [Sparse Ray-Octree Intersection (DECIDE)](3006-sparse-ray-octree-intersection-decide.md)
GPU-based iterative algorithm with explicit stack management and bit-manipulation optimizations. Suitable for high-performance parallel execution.

### [Residency Octree Traversal](3073-residency-octree-traversal.md)
Ray-guided method integrating residency metadata to decide whether to skip a node, use aggregate values, or request data. Optimizes memory bandwidth.

### [PND3D Octree Rendering](3433-pnd3d-octree-rendering.md)
Uses 8-way octree with child/solid masks, visited front-to-back. Splits screen into tiles for multithreaded occlusion culling.

### [GigaVoxels Ray Traversal and Rendering](4144-gigavoxels-ray-traversal-and-rendering.md)
GPU-based technique decoupling geometric hierarchy from data storage in a global brick pool. Enables efficient residency management.

### [Sparse Voxel Grid Raycasting with Occupancy Grid](4152-sparse-voxel-grid-raycasting-with-occupancy-grid.md)
Uses hierarchical sparse voxel grid (VDB/NanoVDB) to skip empty space. Differs from Octree Traversal by using fixed-resolution sparse grid with hierarchical levels.

### [HashDAG Ray Traversal](6745-hashdag-ray-traversal.md)
GPU kernel traversing a HashDAG structure, storing the sequence of child indices.

### N3-Tree
N3-trees are a generalization of octrees where each node is subdivided into $N$ parts (typically $N=8$ for octrees) [S6, unofficial]. They are considered a special case of Kd-Trees [S6, unofficial]. While octrees offer regular subdivision with identical node sizes at each level (useful for regular data bricks) and compact storage with fewer indirections, no specific algorithm in available literature proposes exploiting the unique structure of octrees/N3-trees to accelerate ray traversal beyond standard methods [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(\log N)$ for empty space skipping in sparse volumes, where $N$ is the number of voxels. In dense volumes, it approaches $O(N)$ but with higher constant overhead due to tree traversal [S5, unofficial].
*   **Memory Complexity:** $O(N)$ for storing the tree structure. The footprint includes pointers/metadata for internal nodes. Min/max trees add ~22% footprint on top of raw voxel data [S4].
*   **Performance:** Dramatic speedups in sparse datasets due to empty space skipping [S1, S5, unofficial]. Performance degrades in dense or irregular geometry where the tree is fully populated or poorly aligned [S5, unofficial].
*   **Strengths:** Theoretical optimality for fewest traversal steps for regularly spaced geometry [S5, unofficial]. Compact storage with reduced indirections compared to linked lists [S6, unofficial].
*   **Limitations:** Difficult to implement on GPUs due to lack of native recursion support [S1, unofficial]. Poor conformity to irregular geometry [S5, unofficial].
*   **When to Use:** Regular voxel geometry, sparse datasets, when a single structure can serve for both traversal and scalar storage [S5, unofficial].
*   **When Not to Use:** Irregular meshes, dense volumes where overhead outweighs benefits, or when hardware supports efficient recursive traversal (e.g., some CPU architectures) [S5, unofficial].

## Background
*   **Origin:** The concept of octrees for spatial subdivision was proposed by Glassner, who suggested top-down point location testing along successive octree nodes hit by the ray [S5, unofficial].
*   **Development:** Samet modified the marching procedure to incorporate neighbor-finding algorithms, delivering dramatic speedups [S5, unofficial]. Sung proposed a DDA traversal similar to a hierarchical grid [S5, unofficial]. Gargantini and Atkinson implemented a traversal similar to a kd-tree where ray intersection with each octant midplane is ordered [S5, unofficial].
*   **Usage:** Commonly employed in 3D graphics for occlusion culling and volumetric rendering applications to perform empty space skipping [S2, S3, unofficial].
