# Voxel Child Address Calculation

Also called: Voxel Index Calculation (getIdx), Voxel address_of, getIdx

## Overview
Voxel Child Address Calculation determines the storage index of a child voxel within a parent's child array, given a query point and the parent's spatial bounds [S1, unofficial]. It solves the problem of mapping a 3D geometric position to a specific slot in a potentially sparse or compacted child payload array [S2, unofficial]. Unlike [Point Location](2076-point-location.md), which finds the leaf node containing a point, this method operates at the internal node level to identify which of the 8 octants contains the sample point [S1, unofficial]. It differs from [Ordered Child Traversal](3008-ordered-child-traversal.md) by focusing on the arithmetic mapping of coordinates to indices rather than the traversal sequence [S1, unofficial].

## How it works
The method computes a logical octant index from the query point's coordinates, remaps it to a traversal-friendly order, and finally converts it to a compact storage offset using a validity bitmask [S1, unofficial][S2, unofficial].

### Inputs and Outputs
- **Inputs**:
  - `point`: A 3D vector $(x, y, z)$ representing the query location [S1, unofficial].
  - `parent_pos`: A 3D vector representing the minimum corner (origin) of the parent voxel [S1, unofficial].
  - `parent_size`: A scalar representing the side length of the parent voxel [S1, unofficial].
  - `valid_mask`: An 8-bit integer bitmask where bit $k$ is set if child octant $k$ exists [S2, unofficial].
  - `child`: An integer base index pointing to the start of the child payload array [S2, unofficial].
- **Outputs**:
  - `final_index`: The integer index into the child payload array [S2, unofficial]. Returns $-1$ if the point is outside the parent voxel [S1, unofficial].

### Data Structures
- **`convertIndex`**: A lookup table of 8 integers mapping the internal bit-based octant index to the traversal order index [S1, unofficial].
  - Layout: `convertIndex = [0, 1, 3, 2, 4, 5, 7, 6]` [S1, unofficial].
- **`valid_mask`**: An 8-bit unsigned integer where bit $k$ corresponds to octant $k$ [S2, unofficial].

### Steps
1. **Boundary Check**: Verify the point lies within the parent voxel's half-open bounds $[parent\_pos, parent\_pos + parent\_size)$ [G]. If outside, return $-1$ [S1, unofficial].
2. **Logical Octant Index**: Initialize `idx = 0`. Determine which half of the voxel the point occupies along each axis. The source uses the conditional `if (pos->axis + size - point.axis) < 0` to detect the high half, adding axis-specific weights to `idx` and advancing `pos` by the subdivision length [S1, unofficial]. Here, the subdivision length equals `parent_size / 2`. The weights are X=2, Y=4, Z=1 [S1, unofficial].
3. **Traversal Mapping**: Apply the `convertIndex` lookup table to remap the logical bit-index to the target traversal order index [S1, unofficial].
4. **Compact Address Calculation**: Create a bitmask isolating all octants preceding the target index using `mask = ~(0xFF << traversal_idx)` [S2, unofficial]. Compute the final storage offset by counting the number of valid children preceding the target octant: `final_index = child + popcount(mask & valid_mask)` [S2, unofficial].

### Pseudocode
```python
def voxel_child_address_calculation(point, parent_pos, parent_size, valid_mask, child):
    """
    Calculates the storage index of the child voxel containing the query point.
    
    Args:
        point: tuple (x, y, z)
        parent_pos: tuple (x, y, z) minimum corner of parent voxel
        parent_size: float side length of parent voxel
        valid_mask: int 8-bit mask of valid children
        child: int base index in the compacted child payload array
        
    Returns:
        int: Index in the child payload array, or -1 if point is outside.
    """
    # 1. Boundary Check
    min_x, min_y, min_z = parent_pos
    max_x = min_x + parent_size
    max_y = min_y + parent_size
    max_z = min_z + parent_size
    
    if not (min_x <= point[0] < max_x and 
            min_y <= point[1] < max_y and 
            min_z <= point[2] < max_z):
        return -1

    # 2. Logical Octant Index Calculation
    # Source uses `pos->axis + size - point.axis < 0` to detect the high half [S1, unofficial].
    # `size` in the source corresponds to the half-side length for the first traversal step.
    step = parent_size / 2.0
    pos_x, pos_y, pos_z = min_x, min_y, min_z
    idx = 0
    
    if (pos_x + step - point[0]) < 0:
        idx += 2
        pos_x += step
    if (pos_y + step - point[1]) < 0:
        idx += 4
        pos_y += step
    if (pos_z + step - point[2]) < 0:
        idx += 1
        pos_z += step
        
    # 3. Map to Traversal Order
    convertIndex = [0, 1, 3, 2, 4, 5, 7, 6]
    traversal_idx = convertIndex[idx]
    
    # 4. Compact Address Calculation
    # Source mask: `~(0xff << octant)` isolates bits below the target octant [S2, unofficial].
    # Equivalent to `(1 << traversal_idx) - 1` for the lower 8 bits.
    preceding_mask = (1 << traversal_idx) - 1
    
    # Count valid children preceding the target octant [S2, unofficial].
    preceding_valid_count = bin(valid_mask & preceding_mask).count("1")
    
    return child + preceding_valid_count
```

### Parameters
- `convertIndex`: Fixed array `[0, 1, 3, 2, 4, 5, 7, 6]` [S1, unofficial].

### Edge Cases and Pitfalls
- **Boundary Precision**: Floating-point comparisons at voxel boundaries can cause inconsistent parent/child assignments; consistent half-open intervals $[min, max)$ are required [G].
- **Invalid Mask**: If `valid_mask` does not have the bit at `traversal_idx` set, the point does not lie in a valid child and the method should return $-1$ [G].
- **Coordinate System Assumptions**: The bit weights (Z=1, X=2, Y=4) and the `convertIndex` permutation are specific to the source implementation [S1, unofficial]. Other systems may use standard Morton ordering or different permutations.

## Subtopics

### [Prefix Rank for Compact Child Indexing](5129-prefix-rank-for-compact-child-indexing.md)
Maps a child's logical index to its compact position in a payload array by counting active children preceding it in a bitmask. Chosen when storage must be compacted to skip empty octants without allocating storage for them.

## Operating characteristics
- **Time Complexity**: $O(1)$ arithmetic operations and bitwise logic [S1, unofficial][S2, unofficial].
- **Memory Complexity**: $O(1)$ auxiliary space [S2, unofficial].
- **Strengths**: Fast, branch-minimized when implemented with bitwise operations, and directly supports compacted sparse storage layouts [S2, unofficial].
- **Limitations**: Requires knowledge of the specific `convertIndex` mapping and bit-weighting scheme used by the parent node [S1, unofficial]. Assumes children are stored in octant order before compaction [S2, unofficial].

## Background
The method originates from implementations of sparse voxel octrees in real-time volumetric rendering, specifically those optimizing for GPU traversal and compact memory layouts [S1, unofficial]. The specific indexing scheme and `convertIndex` table are documented in implementations focusing on efficient child address computation [S1, unofficial]. The compact address calculation using popcount is a standard technique in sparse data structures for rank queries [S2, unofficial].
