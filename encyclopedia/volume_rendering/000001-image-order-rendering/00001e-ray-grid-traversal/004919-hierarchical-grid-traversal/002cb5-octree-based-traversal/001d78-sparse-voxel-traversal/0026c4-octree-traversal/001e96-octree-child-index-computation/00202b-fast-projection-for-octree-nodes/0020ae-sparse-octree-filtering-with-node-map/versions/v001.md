# Sparse Octree Filtering with Node Map

Also called: Light-view Map Node Map, Node Map MIP-map Filtering

## Overview
This method accelerates the filtering of sparse voxel octrees by reducing redundant thread execution during MIP-map generation. It solves the problem of launching threads for empty nodes or multiple threads computing the same ancestor node in high-level octree structures. It sets itself apart from naive per-pixel thread launching by using a hierarchical 2D node map to detect and terminate redundant threads, achieving a speedup of > 2x [S1].

## How it works
The method constructs a 2D node map derived from the light-view map to guide thread execution during octree filtering. It uses a MIP-map pyramid structure to manage thread coordination and termination.

### Data Structures
**Node Map**: A 2D array with multiple levels (MIP-map pyramid).
- **Lowest Level (Highest Resolution)**: Each pixel stores the index of the 3D leaf node in the sparse octree that contains the corresponding photon from the light-view map.
- **Higher Levels (Lower Resolution)**: Each pixel stores the index of the lowest common ancestor (LCA) node for the nodes referenced by the corresponding pixels in the previous (higher resolution) level.

### Algorithm Steps
1. **Initialization**: Construct the node map from the light-view map. For the lowest level, map each photon to its containing leaf node index. For higher levels, compute the LCA for groups of nodes from the level below.
2. **Thread Launch**: Launch one thread per pixel of the lowest node map level for each MIP-mapping pass.
3. **Node Lookup and Redundancy Check**:
   - Each thread traverses the octree to find the specific node it must compute the filtered value for.
   - Before performing computation, the thread checks the current level of the node map to see if another thread is targeting the same node (a common ancestor).
   - If a common ancestor is detected, all threads identifying this node are terminated except the "upper left" one (based on pixel coordinates).
   - The surviving thread computes the remaining filtered values for that node.
4. **Filtering Passes**: To balance computational load across threads, the filtering is performed in three separate passes, moving from lower to higher octree levels:
   - **Pass 1 (Center)**: Compute the center voxel using 27 voxel values from the lower level.
   - **Pass 2 (Face Centers)**: Compute half of the filtered response for voxels at the center of the node's faces. This involves 18 voxel values.
   - **Pass 3 (Corners)**: Launch threads for corner voxels to compute partial filtering from a single octant.
5. **Value Transfer**: After the three passes, octree vertices may contain partial results. Apply the "Value Transfer to Neighboring Bricks" step to sum values across bricks and finalize the filtering [S1].

### Parameters and Edge Cases
- **Thread Termination Heuristic**: The "upper left" rule ensures deterministic termination. If multiple threads target the same node, only one computes the result.
- **Unbalanced Scheduling**: The three-pass approach ensures threads have roughly the same cost, mitigating the imbalance caused by varying voxel counts (27, 18, 1) [S1].
- **Sparse Octrees**: The method specifically avoids filtering zero values for empty nodes, which is crucial for scenes with sparse direct light [S1].

## Operating characteristics
- **Speedup**: Achieves a speedup of > 2x compared to not using the heuristic to terminate redundant threads [S1].
- **Complexity**: Reduces the number of threads launched by terminating redundant threads that target the same common ancestor node.
- **Strengths**: Efficiently handles sparse octrees by avoiding computation on empty nodes; balances thread workload through the three-pass approach.
- **Limitations**: Requires construction of the 2D node map; relies on the "upper left" heuristic for thread termination, which may have edge cases in highly irregular distributions.

## Background
This method is part of the "Interactive Indirect Illumination Using Voxel Cone Tracing" technique developed by NVIDIA researchers. It addresses the computational cost of filtering sparse voxel octrees for real-time global illumination. The node map structure is derived from the light-view map, which is a key component in voxel cone tracing pipelines [S1].
