# Sparse Octree Filtering with Node Map

Also called: Light-view Map Node Map, Node Map Heuristic, Node Map MIP-map Filtering, Thread Termination for Sparse Filtering

## Overview
Sparse Octree Filtering with Node Map is a thread-scheduling heuristic that reduces redundant computation during MIP-map generation for sparse voxel octrees by terminating duplicate threads [S1, S2]. It solves the problem of multiple threads performing identical filtering work on the same octree node, which occurs frequently at higher MIP-map levels [S1, S2]. It differs from standard parallel MIP-map generation by using a 2D node map derived from the light-view map to detect common ancestors among threads before computation begins [S1, S2].

## How it works
**Inputs and Outputs**
*   **Input:** Sparse voxel octree structure, light-view map (2D array of photon indices), and target MIP-map level for the current pass [S1, S2].
*   **Output:** Updated MIP-map level data for the octree nodes, with redundant threads terminated [S1, S2].

**Data Structures**
1.  **Light-View Map:** A 2D array where each pixel stores the index of a 3D leaf node in the sparse voxel octree that contains the corresponding photon [S1, S2].
2.  **Node Map:** A 2D MIP-map pyramid derived from the light-view map [S1, S2].
    *   **Lowest Level:** Pixels store the indices of the 3D leaf nodes containing the corresponding photons, identical to the light-view map [S1, S2].
    *   **Higher Levels:** Each pixel stores the index of the lowest common ancestor (LCA) node in the octree for the set of nodes referenced by the corresponding pixels in the previous (lower) level [S1, S2].

**Algorithm Steps**
1.  **Launch Threads:** Launch one thread per pixel of the lowest level of the node map for the current MIP-mapping pass [S1, S2].
2.  **Node Lookup:** For each thread, determine the target octree node for the current MIP-map level by traversing from the leaf node indicated in the light-view map up to the required level [S1, S2].
3.  **Common Ancestor Detection:** Before computing the filtered value, the thread checks the current level of the node map to verify whether another thread has already detected or is computing the same common ancestor node [S1, S2].
4.  **Termination Heuristic:** If a common ancestor is detected among multiple threads, terminate all threads detecting this common ancestor except for the thread corresponding to the "upper left" pixel in the node map [S1, S2]. The surviving "upper left" thread is responsible for computing the remaining filtered values [S1, S2].
5.  **Computation:** The surviving threads compute the MIP-mapped values for their respective octree nodes [S1, S2].

**Pseudocode**
```python
import threading

# Shared state for synchronization across threads
node_owner = {}  # Maps octree node index to (x, y) of the winning thread
lock = threading.Lock()

def filter_thread(x, y, node_map, octree, light_view_map, mip_level):
    # 1. Get leaf node index from light-view map for this pixel
    leaf_node_idx = light_view_map[y, x]
    
    # 2. Traverse octree to find target node at the specified MIP-map level
    # [G] Standard octree parent traversal from leaf to target depth
    target_node = octree.get_node_at_level(leaf_node_idx, mip_level)
    
    # 3. Check node map for common ancestor detection
    # The node map at mip_level stores LCAs for the previous level
    # We verify if another thread has already claimed this target_node
    with lock:
        if target_node not in node_owner:
            node_owner[target_node] = (x, y)
            is_upper_left = True
        else:
            owner_x, owner_y = node_owner[target_node]
            # "upper left" tie-breaking: smallest y, then smallest x
            is_upper_left = (y, x) < (owner_y, owner_x)
            
    # 4. Termination heuristic
    if not is_upper_left:
        return  # Thread terminates early
        
    # 5. Compute filtered values for the target node
    # [G] Standard MIP-filtering computation for the target node at mip_level
    filtered_value = octree.compute_mip_value(target_node, mip_level)
    octree.set_mip_value(target_node, mip_level, filtered_value)

# Parallel execution setup
width, height = light_view_map.shape
threads = []
for y in range(height):
    for x in range(width):
        t = threading.Thread(target=filter_thread, args=(x, y, node_map, octree, light_view_map, mip_level))
        threads.append(t)
        t.start()
for t in threads:
    t.join()
```

**Parameters**
*   **MIP Level:** The current level of the MIP-map being generated. Typical values depend on the octree depth. Not given in the sources.
*   **Node Map Levels:** The number of levels in the node map pyramid corresponds to the number of MIP-map levels. Not given in the sources.

**Edge Cases and Pitfalls**
*   **Precision:** Not given in the sources.
*   **Boundaries:** The "upper left" tie-breaking rule must be consistently defined to avoid race conditions or missed computations [S1, S2].
*   **Degenerate Input:** Not given in the sources.

## Subtopics

### [Anisotropic Voxel Filtering for Mipmap Generation](2996-anisotropic-voxel-filtering-for-mipmap-generation.md)
This method filters lighting data at the leaf nodes of an octree anisotropically along the positive and negative XYZ directions to prepare for cone tracing. It stores six directional values per voxel to preserve directional information.

### [Distribution over Levels (MIP-mapping)](3045-distribution-over-levels-mip-mapping.md)
Distribution over Levels (MIP-mapping) filters radiance values from the lowest level of a sparse voxel octree and stores the results in higher levels to form a MIP-map hierarchy. It differs from regular grid MIP-mapping by explicitly handling the boundary sharing of 3x3x3 voxel bricks in an octree structure, requiring weighted averaging to account for overlapping voxels.

## Operating characteristics
*   **Time Complexity:** The method reduces the number of threads launched, leading to a speedup of > 2x compared to not using the heuristic [S1, S2]. The complexity per thread remains similar, but the total work is reduced [S1, S2].
*   **Memory Complexity:** Requires additional memory for the 2D node map, which is a MIP-map pyramid derived from the light-view map [S1, S2].
*   **Measured Performance:** Yields > 2x speedup compared to not using the heuristic to terminate threads [S1, S2].
*   **Strengths:** Significantly reduces redundant computation in parallel MIP-map generation for sparse octrees [S1, S2].
*   **Limitations:** Requires the construction and maintenance of the 2D node map [S1, S2].
*   **When to Use:** Not given in the sources.
*   **When Not to Use:** Not given in the sources.

## Background
The method is described in [S1, S2] as an optimization for the MIP-map generation step in voxel cone tracing [S1, S2]. The node map heuristic was developed to reduce thread launch overhead and prevent identical filtering work on the same octree nodes [S1, S2].
