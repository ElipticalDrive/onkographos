# Volume Raycasting with MRT Endpoints

Also called: MRT Ray Start/Stop Determination, Two-pass raycasting

## Overview
Volume Raycasting with MRT Endpoints is a technique to determine the entry and exit points of rays into a volume by rendering the volume's bounding box to two separate color attachments in a single GPU pass, avoiding analytical ray-cube intersection calculations. It sets itself apart from analytical intersection methods by leveraging the graphics pipeline's face culling and multiple render target (MRT) capabilities to store object-space coordinates directly, building on the back-face culling logic of [Back-Face Culling for Ray Casting](1236-back-face-culling-for-ray-casting.md).

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture, a bounding box geometry (typically a two-unit cube centered at the origin), and a viewport.
*   **Output:** Two textures (RayStart, RayStop) containing the entry and exit points for each pixel, and a final 2D image with the composited volume.

**Data Structures:**
*   **Bounding Box:** A cube with vertices in object space ranging from $[-1, 1]$ on all axes.
*   **Frame Buffer Objects (FBO):** Must support two color attachments (e.g., `GL_COLOR_ATTACHMENT0` and `GL_COLOR_ATTACHMENT1`).
*   **Textures:** Two 2D floating-point RGB textures (e.g., `GL_RGBA32F`) to store the 3D coordinates. Initialized to black (zero).

**Steps:**

1.  **Pass 1: Compute Endpoints**
    1.  Bind an FBO with two color attachments.
    2.  Enable blending with additive mode: `glBlendFunc(GL_ONE, GL_ONE)`.
    3.  Set draw buffers to both attachments: `glDrawBuffers(2, {GL_COLOR_ATTACHMENT0, GL_COLOR_ATTACHMENT1})`.
    4.  Render the bounding box cube.
    5.  The vertex shader transforms vertices to clip space using the Model-View-Projection matrix but passes the original object-space position to the fragment shader.
    6.  The fragment shader writes the object-space position to one attachment if the face is front-facing, and to the other if back-facing.
    7.  Convert coordinates from $[-1, 1]$ to $[0, 1]$ range: $coord = 0.5 \times (position + 1.0)$.

2.  **Pass 2: Raycasting and Compositing**
    1.  Bind the RayStart and RayStop textures to texture units.
    2.  Render a full-screen quad.
    3.  For each fragment, sample the entry point $P_{start}$ from RayStart and exit point $P_{stop}$ from RayStop using screen coordinates.
    4.  If $P_{start} == P_{stop}$, discard the fragment (no intersection).
    5.  Compute ray vector $\vec{R} = P_{stop} - P_{start}$ and length $L = \|\vec{R}\|$.
    6.  Compute step vector $\vec{S} = \text{StepLength} \times \frac{\vec{R}}{L}$.
    7.  Apply stochastic jitter to $P_{start}$ using a jitter texture to reduce aliasing: $P_{start} \leftarrow P_{start} + \vec{S} \times \text{jitter}$.
    8.  Initialize current position $P = P_{start}$ and destination color $C_{dst} = (0, 0, 0, 0)$.
    9.  Loop while $L > 0$ and $C_{dst}.a < 1.0$:
        *   Sample volume density $d = \text{texture}(\text{Volume}, P).r$.
        *   Create source color $C_{src} = (d, d, d, d)$ (assuming grayscale density maps to RGB).
        *   Apply front-to-back blending: $C_{dst} = (1.0 - C_{dst}.a) \times C_{src} + C_{dst}$.
        *   Advance position: $P \leftarrow P + \vec{S}$.
        *   Decrease remaining length: $L \leftarrow L - \text{StepLength}$.
    10. Output $C_{dst}$ as the fragment color.

**Pseudocode:**

```python
# Pass 1: Vertex Shader
def vertex_shader(position: vec3, mvp_matrix: mat4) -> (vec4, vec3):
    gl_Position = mvp_matrix * vec4(position, 1.0)
    return gl_Position, position

# Pass 1: Fragment Shader
def fragment_shader(position: vec3, is_front_facing: bool) -> vec3:
    # Convert from [-1, 1] to [0, 1]
    coord = 0.5 * (position + 1.0)
    if is_front_facing:
        return coord  # Written to Attachment 0 (RayStart)
    else:
        return vec3(0.0)  # Written to Attachment 0 (RayStart)

def fragment_shader_back(position: vec3, is_front_facing: bool) -> vec3:
    coord = 0.5 * (position + 1.0)
    if is_front_facing:
        return vec3(0.0)  # Written to Attachment 1 (RayStop)
    else:
        return coord  # Written to Attachment 1 (RayStop)

# Pass 2: Fragment Shader
def raycasting_fragment_shader(screen_uv: vec2, 
                               ray_start_tex: sampler2D, 
                               ray_stop_tex: sampler2D, 
                               volume_tex: sampler3D, 
                               jitter_tex: sampler2D, 
                               step_length: float) -> vec4:
    
    # Sample endpoints
    ray_start = texture(ray_start_tex, screen_uv).xyz
    ray_stop = texture(ray_stop_tex, screen_uv).xyz
    
    # Discard if no intersection
    if ray_start == ray_stop:
        discard()
        
    # Compute ray properties
    ray_vec = ray_stop - ray_start
    ray_length = length(ray_vec)
    step_vec = step_length * (ray_vec / ray_length)
    
    # Apply jitter
    jitter_val = texture(jitter_tex, screen_uv).r
    current_pos = ray_start + step_vec * jitter_val
    
    # Initialize compositing
    dst_color = vec4(0.0)
    
    # Raymarching loop
    while ray_length > 0.0 and dst_color.a < 1.0:
        # Sample volume
        density = texture(volume_tex, current_pos).r
        
        # Create source color (assuming density maps to intensity)
        src_color = vec4(density, density, density, density)
        
        # Front-to-back blending
        dst_color = (1.0 - dst_color.a) * src_color + dst_color
        
        # Advance
        current_pos += step_vec
        ray_length -= step_length
        
    return dst_color
```

**Parameters:**
*   `step_length`: Distance between samples. Typical value: 0.01 [S2, unofficial]. Smaller values increase quality but cost; larger values increase speed but reduce quality [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-intersecting rays:** Handled by checking if `ray_start == ray_stop`. If the ray misses the volume, both textures return zero (or the cleared value), resulting in a zero vector.
*   **Precision:** Using floating-point textures for endpoints is critical to avoid quantization errors in start/stop positions, which would cause gaps or overlaps in the raymarching.
*   **Jitter Texture:** Requires a pre-generated texture of random values on the CPU to be passed to the GPU. Without jitter, regular sampling can cause moiré patterns or "wood grain" artifacts [S1, unofficial].

## Subtopics

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is the number of samples per ray. The first pass is $O(1)$ relative to resolution (fixed cube rendering).
*   **Memory Complexity:** $O(N)$ for the two endpoint textures (2 floats per pixel) plus the volume texture.
*   **Strengths:** Simple to implement; leverages standard GPU rasterization; avoids complex analytical intersection math in shaders.
*   **Limitations:** Requires two rendering passes; requires additional memory for endpoint textures; less efficient than hierarchical traversal methods for large sparse volumes because it samples every voxel along the ray regardless of emptiness.
*   **When to use:** Small to medium volumes; educational purposes; simple implementations where hierarchical structures are too complex.
*   **When not to use:** Large sparse volumes (use [Sparse Voxel Traversal](link) or [Octree Traversal](link)); real-time applications requiring high performance on large datasets.

## Background
The technique is described in blog posts and unofficial guides on GPU-accelerated volumetric raycasting. It is attributed to Martin Opilia [S1, unofficial] and Prideout [S2, unofficial]. It represents a basic, brute-force approach to volume rendering that predates more advanced hierarchical methods.
