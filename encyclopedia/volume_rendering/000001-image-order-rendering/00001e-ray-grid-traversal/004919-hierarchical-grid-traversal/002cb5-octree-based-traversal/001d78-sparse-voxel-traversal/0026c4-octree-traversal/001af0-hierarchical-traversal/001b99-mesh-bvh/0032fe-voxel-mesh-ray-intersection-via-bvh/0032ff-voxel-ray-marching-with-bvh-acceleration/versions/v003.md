# Voxel Ray Marching with BVH Acceleration

Also called: VoxelMeshQuery, VoxelRayRender

## Overview
Voxel Ray Marching with BVH Acceleration is a compute-shader-based ray tracing technique for voxel data that uses a Binary Volume Hierarchy (BVH) to accelerate ray-mesh intersection tests for sun lighting and ambient occlusion calculations [S1, unofficial]. It operates on a per-pixel basis in a compute shader, utilizing position and normal textures as input buffers [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method requires input textures `position_texture` (`texture_2d<f32>`) storing world positions and `normal_texture` (`texture_2d<f32>`) storing surface normals [S1, unofficial]. It writes results to output storage textures `light_texture` (`texture_storage_2d<rgba32float, write>`) and `ao_texture` (`texture_storage_2d<rgba16float, write>`) [S1, unofficial]. Mesh data is stored in buffers: `vertices` (`array<VoxelMeshVertex>`), `indices` (`array<u32>`), `voxel_meshes` (`array<VoxelMesh>`), `voxel_bvh` (`array<AABB>`), and `voxel_indice` (`array<vec2u>`) [S1, unofficial].

**Data Structures:**
The `VoxelMeshVertex` struct contains fields `position` (`vec3f`), `normal` (`vec3f`), `textureIndex` (`vec3f`), `uv` (`vec2f`), `colors` (`vec3f`), `voxelData` (`f32`), and `_padding` (`vec4f`) [S1, unofficial].

**Parameters:**
The sun ray max distance is $300.0$ [S1, unofficial]. The AO ray max distance is $0.99$ [S1, unofficial]. The epsilon offset for shadow/occlusion ray origins is $0.01$ [S1, unofficial]. The AO sample count is $4$ [S1, unofficial].

**Formulas:**
Normal conversion from $[0, 1]$ to $[-1, 1]$ range: $\mathbf{n} = 2 \cdot \mathbf{n}_{\text{color}} - 1$ [S1, unofficial].
Occlusion factor: $\text{occlusion} = 1.0 - \frac{\text{hit}}{4}$ [S1, unofficial].
Ray direction in camera space: $\mathbf{d} = \text{normalize}(\text{screenCoord}.x \cdot (-\text{camera.right}) \cdot \tan(\text{halfFov}) \cdot \text{camera.settings}.y + \text{screenCoord}.y \cdot \text{camera.up} \cdot \tan(\text{halfFov}) + \text{camera.forward})$ [S1, unofficial].

**Steps:**
1. **Initialization:** Calculate screen coordinates from the global invocation ID multiplied by $2$ [S1, unofficial]. Load the world position from `position_texture` at these coordinates [S1, unofficial]. If the position's alpha component is $\le 0$, store $1.0$ in the light and AO output textures and return [S1, unofficial].
2. **Normal Processing:** Extract the world position and normal [S1, unofficial]. Convert the normal from the $[0, 1]$ range to the $[-1, 1]$ range using $\mathbf{n} = 2 \cdot \mathbf{n}_{\text{color}} - 1$ [S1, unofficial]. Set `hitPosition` to the position's RGB components [S1, unofficial].
3. **Sun Lighting Calculation:** Offset the hit position along the normal by epsilon ($\epsilon = 0.01$) to get `newHitPosition` to prevent self-intersection [S1, unofficial]. Calculate the sun direction vector from `newHitPosition` to `scene_props.sunPosition` [S1, unofficial]. Construct an orthonormal basis for the sun direction [S1, unofficial]. Call `voxelMeshQuery` with a max distance of $300.0$ [S1, unofficial]. If a hit is found, set the light value to dark gray ($0.25$) [S1, unofficial]. If an error occurs, set the light value to red ($1, 0, 0$) [S1, unofficial].
4. **Ambient Occlusion Calculation:** Build an orthonormal basis from the surface normal using `buildOrthonormalBasis` [S1, unofficial]. Initialize a `hit` counter to $0$ [S1, unofficial]. Loop $4$ times for sampling [S1, unofficial]. Generate random numbers using `getTwoRandomNumbers` with a seed based on fragment coordinates and time [S1, unofficial]. Sample a hemisphere direction using `cosineWeightedHemisphereSample` [S1, unofficial]. Transform the local sample to world space using `hemisphereToWorld` [S1, unofficial]. Construct an orthonormal basis for the sample direction [S1, unofficial]. Call `voxelMeshQuery` with a max distance of $0.99$ [S1, unofficial]. If a hit is found, increment the `hit` counter [S1, unofficial]. Calculate the occlusion factor as $\text{occlusion} = 1.0 - \frac{\text{hit}}{4}$ [S1, unofficial]. Apply this factor to the AO color channels [S1, unofficial].

import math

def vec3(x, y, z): return (x, y, z)
def vec4(x, y, z, w): return (x, y, z, w)
def normalize(v):
    l = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/l, v[1]/l, v[2]/l)
def cross(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])
def select(cond, a, b): return a if cond else b

def build_orthonormal_basis(N):
    up = select(abs(N[2]) < 0.999, vec3(0.0, 1.0, 0.0), vec3(0.0, 0.0, 1.0))
    T = normalize(cross(up, N))
    B = normalize(cross(N, T))
    return (T, B, N)

    screen_coord = (global_invocation_id[0] * 2, global_invocation_id[1] * 2)
    pos_tex = position_texture[screen_coord]
    if pos_tex[3] <= 0.0:
        light_texture[screen_coord] = vec4(1.0, 1.0, 1.0, 1.0)
        ao_texture[screen_coord] = vec4(1.0, 1.0, 1.0, 1.0)

    # 2. Normal Processing
    world_pos = (pos_tex[0], pos_tex[1], pos_tex[2])
    normal_color = normal_texture[screen_coord]
    normal = (2.0 * normal_color[0] - 1.0, 2.0 * normal_color[1] - 1.0, 2.0 * normal_color[2] - 1.0)
    hit_position = world_pos

    # 3. Sun Lighting Calculation
    new_hit_position = (hit_position[0] + normal[0] * 0.01,
                        hit_position[1] + normal[1] * 0.01,
                        hit_position[2] + normal[2] * 0.01)
    sun_dir = normalize((scene_props.sun_position[0] - new_hit_position[0],
                         scene_props.sun_position[1] - new_hit_position[1],
                         scene_props.sun_position[2] - new_hit_position[2]))
    sun_basis = build_orthonormal_basis(sun_dir)
    sun_hit = voxel_mesh_query(new_hit_position, sun_dir, max_distance=300.0)

    if sun_hit.found:
        light_color = vec4(0.25, 0.25, 0.25, 1.0)
    elif sun_hit.error:
        light_color = vec4(1.0, 0.0, 0.0, 1.0)
    else:
        light_color = vec4(1.0, 1.0, 1.0, 1.0)
    light_texture[screen_coord] = light_color

    # 4. Ambient Occlusion Calculation
    surf_basis = build_orthonormal_basis(normal)
    hit_count = 0

    for i in range(4):
        u, v = get_two_random_numbers(screen_coord, time)
        local_sample = cosine_weighted_hemisphere_sample(u, v)
        world_sample = hemisphere_to_world(local_sample, surf_basis)
        sample_basis = build_orthonormal_basis(world_sample)
        ao_hit = voxel_mesh_query(new_hit_position, world_sample, max_distance=0.99)
        if ao_hit.found:
            hit_count += 1

    occlusion_factor = 1.0 - (hit_count / 4.0)
    ao_color = vec4(occlusion_factor, occlusion_factor, occlusion_factor, 1.0)
    ao_texture[screen_coord] = ao_color

**Pitfalls:**
The ray origin for sun and AO queries is offset from the surface position along the normal by a small epsilon ($0.01$) to prevent self-intersection and shadow acne [S1, unofficial]. The `buildOrthonormalBasis` function selects the 'up' vector based on the Z component of the normal to avoid cross-product degeneracy when the normal is parallel to the default up vector [S1, unofficial].

## Subtopics

### [Sparse Voxel Set (SVS)](9654-sparse-voxel-set-svs.md)
Sparse Voxel Set (SVS) is a ray-tracing acceleration method for Signed Distance Function (SDF) grids that constructs a Bounding Volume Hierarchy (BVH) from Axis-Aligned Bounding Boxes (AABBs) representing individual surface-intersecting voxels. It differs from software-based traversal methods (like Grid Sphere Tracing or Sparse Brick Set) by offloading the primary traversal logic to dedicated GPU ray-tracing hardware (DXR), thereby reducing the computational burden of the custom intersection shader.

## Operating characteristics
Time complexity is not given in the sources. Memory complexity is not given in the sources. Measured performance is not given in the sources. Strengths include offloading complex ray-mesh intersection logic to a BVH structure, which is efficient for sparse voxel data, and using compute shaders for parallel per-pixel processing [S1, unofficial]. Limitations include the requirement for pre-computed position and normal textures and reliance on a specific `voxelMeshQuery` implementation [S1, unofficial]. The method is used when performing screen-space lighting (sun and AO) on voxel meshes where hardware ray tracing is not available or a software compute shader approach is preferred [S1, unofficial]. It is not used when full global illumination is required beyond simple shadowing and AO, or when hardware ray tracing (DXR) is available and preferred for SDF grids [S1, unofficial].
