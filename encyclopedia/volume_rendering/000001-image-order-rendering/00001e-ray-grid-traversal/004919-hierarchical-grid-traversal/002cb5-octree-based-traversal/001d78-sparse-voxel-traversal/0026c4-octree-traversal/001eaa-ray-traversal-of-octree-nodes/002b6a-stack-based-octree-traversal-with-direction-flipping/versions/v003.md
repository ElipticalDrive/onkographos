# Stack-based Octree Traversal with Direction Flipping

Also called: Octree Ray Traversal with Direction Flipping, Stack-based Octree Traversal, TreeTraverser

## Overview
A stack-based algorithm for traversing an octree structure along a ray, handling arbitrary ray directions by flipping the coordinate system and ray parameters to ensure positive traversal direction [S1, S2, unofficial]. It uses a stack to store parent context for backtracking when a ray exits a voxel or skips empty space, allowing it to resume traversal at a higher level [S2, unofficial]. It differs from [Ray-Octree Traversal (Gargantini and Atkinson variant)](1890-ray-octree-traversal-gargantini-and-atkinson-variant.md) by explicitly managing a traversal stack for arbitrary depth and direction, and from [IEEE-754 Bit Manipulation Octree Traversal](3907-ieee-754-bit-manipulation-octree-traversal.md) by using floating-point t-values and explicit direction flipping rather than bit-level integer arithmetic for traversal order.

## How it works
**Inputs:** An octree structure (`Octree`), a ray (`Ray`) defined by origin and direction, and the octree bounding box defined by `min` and `max` vectors.
**Outputs:** A sequence of leaf voxels intersected by the ray, or a termination signal when the ray exits the octree.

**Data Structures:**
1.  `TraversalNodeInfo_` struct [S1, unofficial]:
    *   `const Node* node`: Pointer to the current octree node.
    *   `vec3 t0`: Entry t-values for the current voxel bounds (x, y, z components).
    *   `vec3 t1`: Exit t-values for the current voxel bounds (x, y, z components).
    *   `vec3 tm`: Midpoint t-values for the current voxel bounds.
    *   `int nextchild`: Index of the next child to visit. `-1` indicates unvisited, `0-7` indicates a specific child index, `8` indicates all children visited.
2.  `TreeTraverser` class fields [S1, unofficial]:
    *   `unsigned char a`: Direction flip mask (bits 0, 1, 2 correspond to z, y, x axes respectively).
    *   `Octree const* octree`: Pointer to the octree.
    *   `Ray ray`: Modified ray with flipped coordinates if necessary.
    *   `Ray original_ray`: Original ray for final position calculation.
    *   `std::vector<TraversalNodeInfo_> stack`: Stack of traversal nodes.
    *   `int stepcount`: Counter for traversal steps.
3.  `parentStack` (alternative implementation in [S2, unofficial]): Array of tuples `(Voxel*, float, glm::ivec3)` of size `s_max + 1`. Stores parent pointer, `t_max` value, and `lastPos` for backtracking.

**Initialization (`initTraversal`):**
1.  Set `stepcount = 0`, `a = 0`. Store the original ray.
2.  For each axis `i` (0 for x, 1 for y, 2 for z):
    *   If `ray.direction[i] < 0` (Note: [S1, unofficial] notes a specific non-standard logic where z might be checked for `> 0`, but standard flipping applies to negative directions; the code snippet implies checking `ray.direction[i] < 0` for x and y, and potentially z depending on implementation [S1, unofficial]):
        *   Flip `ray.origin[i] = octree->size[i] - ray.origin[i]`.
        *   Flip `ray.direction[i] = -ray.direction[i]`.
        *   Set bit `i` in `a` (bit 0 for z, bit 1 for y, bit 2 for x) [S1, unofficial].
3.  Clamp ray direction components to avoid division by zero: if `fabsf(dir.x) < epsilon`, set `dir.x = copysignf(epsilon, dir.x)`. Repeat for y and z [S2, unofficial]. The value of `epsilon` is $2^{-s_{max}}$ (e.g., 0.015625 for $s_{max}=6$) [S2, unofficial].
4.  Calculate entry/exit t values for the octree bounding box [S1, unofficial]:
    *   $tx_0 = (octree->min[0] - ray.origin[0]) \times (1.0f / ray.direction[0])$
    *   $tx_1 = (octree->max[0] - ray.origin[0]) \times (1.0f / ray.direction[0])$
    *   Similarly for $ty_0, ty_1$ (y-axis) and $tz_0, tz_1$ (z-axis).
5.  Check if ray intersects octree: if $\max(\max(tx_0, ty_0), tz_0) < \min(\min(tx_1, ty_1), tz_1)$, push root node onto stack with $t_0=(tx_0, ty_0, tz_0)$ and $t_1=(tx_1, ty_1, tz_1)$. Else, stack remains empty [S1, unofficial].
    *   *Alternative Initialization ([S2, unofficial]):* Calculate initial $t_{min}$ and $t_{max}$ for the entire octree bounding box using `findMinMax`. If $t_{min} \neq 9999$, move origin to nearest face: $origin += t_{min} \times dir$, $t_{max} -= t_{min}$, $t_{min} = 0$. Initialize `scale = s_max - 1`, `size = CHUNK_NUM * Chunk::CHUNK_SIZE / 2`. Get initial `idx` and `pos` using `getIdx(origin, &pos, size)` [S2, unofficial].

**Traversal Loop:**
The traversal proceeds by processing the top of the stack. The algorithm alternates between visiting nodes and backtracking.

1.  **POP Step:** If stack is empty, return. If `stack.back().nextchild == 8` (all children visited) or `stack.back().node->isLeaf()`, pop stack and return (or continue to next ray/exit) [S1, unofficial].
2.  **PUSH Step (First Visit):** If `stack.back().nextchild == -1` (first visit to this node):
    *   Calculate $tm = 0.5f \times (t_0 + t_1)$ [S1, unofficial].
    *   Determine the first child to visit using `firstNode(t0, tm)` [S1, unofficial].
    *   Set `stack.back().nextchild` to that result [S1, unofficial].
    *   *Alternative ([S2, unofficial]):* Calculate `c_min` and `c_max` for current voxel using `findMinMax`. Update $t_{min} = \max(t_{min}, c_{min})$ and $t_{c\_max} = \min(c_{max}, t_{max})$. If voxel not valid or $t_{min} > t_{c\_max}$, backtrack: Convert `idx` using `convertIndex` array. Adjust `pos` based on index bits. Pop from stack if necessary [S2, unofficial].
3.  **ADVANCE Step:** Switch on `stack.back().nextchild` (0-7).
    *   Calculate the next child index: `child_index = current_case ^ a` [S1, unofficial]. This XOR operation maps the logical child index to the physical child index based on ray direction.
    *   Check if the corresponding child exists using `stack.back().node->hasChild(child_index ^ a)` [S1, unofficial].
    *   If it exists, build new `TraversalNodeInfo` with appropriate $t_0/t_1$ bounds for the child voxel and push onto stack.
    *   Set `stack.back().nextchild` to the next child to visit after this one [S1, unofficial].
    *   *Alternative ([S2, unofficial]):* Core loop condition: `while (scale < s_max)`. If `parent->validMask & (int)exp2(idx)` and $t_{min} \le t_{c\_max}$:
        *   If `parent->leafMask & (int)exp2(idx)`, break (leaf reached).
        *   If $c_{max} < h$, save state: `parentStack[scale] = std::make_tuple(parent, t_max, lastPos)`.
        *   Update `lastPos = pos`, $h = c_{max}$, $t_{max} = c_{max}$.
        *   `size /= 2`, `scale--`.
        *   Calculate `pointerIndex` by counting valid children up to `idx`.
        *   `parent = parent->childPointers[pointerIndex]`.
        *   `point = origin + (c_min + 0.00001f) * dir`.
        *   `idx = getIdx(point, &pos, size)`.
        *   `continue` [S2, unofficial].

**First Child Selection (`firstNode`):**
Given $t_0$ and $t_m$ (midpoint t-values) [S1, unofficial]:
*   If $tx_0 > ty_0$ and $tx_0 > tz_0$ (entering via YZ plane):
    *   Check if $ty_m < tx_0$ (set bit 1) and $tz_m < tx_0$ (set bit 0).
*   If $ty_0 > tz_0$ (entering via XZ plane):
    *   Check if $tx_m < ty_0$ (set bit 2) and $tz_m < ty_0$ (set bit 0).
*   Otherwise (entering via XY plane):
    *   Check if $tx_m < tz_0$ (set bit 2) and $ty_m < tz_0$ (set bit 1) [S1, unofficial].

**Position Calculation:**
To get the world position of the current node, use `original_ray.getRayPoint(t)` where $t = \max(stack.back().t_0)$. Negate the z-coordinate if the z-axis was flipped: `answer[2] = -answer[2]` [S1, unofficial].

**Pitfalls:**
*   Ray direction handling: The code assumes specific sign checks for each axis (negative for x and y, positive for z) to determine flipping. This is non-standard and must be replicated exactly [S1, unofficial].
*   Division by zero in ray-box intersection if ray direction component is zero. Handled by clamping small components to epsilon with correct sign [S2, unofficial].
*   Position calculation requires compensating for z-flip if applied [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Proportional to the number of nodes visited. In the worst case, it visits all nodes along the ray path. The direction flipping ensures consistent traversal logic regardless of ray direction.
*   **Memory Complexity:** $O(D)$ where $D$ is the depth of the octree, due to the stack storage.
*   **Strengths:** Handles arbitrary ray directions robustly via coordinate flipping. Stack-based approach allows for efficient backtracking and handling of sparse data.
*   **Limitations:** Stack operations may introduce overhead compared to iterative pointer-chasing methods. The specific direction flipping logic must be carefully implemented to match the source's non-standard checks [S1, unofficial].
*   **When to use:** When rendering with arbitrary ray directions and an octree structure that requires explicit backtracking or handling of non-uniform traversal orders.
*   **When not to use:** If performance is critical and rays are mostly axis-aligned, simpler traversal methods might be faster. If memory is extremely constrained, the stack overhead might be significant.

## Background
This method is derived from implementations found in CPU-based voxel raycasters [S1, S2, unofficial]. It represents a practical approach to octree traversal that prioritizes correctness across all ray directions by normalizing the traversal space. The specific implementation details, including the direction flipping mask and stack structure, are characteristic of the `cpu_voxel_raycaster` project [S1, unofficial] and related academic projects [S2, unofficial].
