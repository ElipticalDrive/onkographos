# Prefix Rank for Compact Child Indexing

Also called: Popcount-based Child Index Mapping, Prefix Rank

## Overview
Prefix Rank maps a child's logical index within an octree node to its compact position in a payload array by counting the number of active children preceding it in a bitmask [S1, unofficial]. It solves the dense indexing problem in sparse voxel grids by enabling traversal to skip empty octants without allocating storage for them [S1, unofficial]. Unlike [Voxel Child Address Calculation](2495-voxel-child-address-calculation.md), which handles general address arithmetic, this method specifically implements the rank query on a bit vector to determine the offset [S1, unofficial].

## How it works
**Inputs:**
- `mask`: Bitmask representing occupied children (1 bit per child) [S1, unofficial].
- `child_index`: Target child index ($0 \dots 7$ for 8-way, $0 \dots 63$ for wide) [S1, unofficial].

**Outputs:**
- `rank`: The number of active children with indices strictly less than `child_index` [S1, unofficial].

**Data Structures:**
- No auxiliary structures are required for the basic implementation [S1, unofficial]. The operation is stateless and relies on bitwise operations [G].

**Steps:**
1. If `child_index <= 0`, return 0 [S1, unofficial].
2. Create `lower_mask = (1 << child_index) - 1` [S1, unofficial].
3. Return `popcount(mask & lower_mask)` [S1, unofficial].

**Formula:**
$$ \text{rank} = \text{popcount}(\text{mask} \ \& \ ((1 \ll \text{child\_index}) - 1)) $$

Where:
- $\text{popcount}(x)$ returns the number of 1-bits in $x$ [G].
- $\&$ is the bitwise AND operator [G].
- $\ll$ is the bitwise left shift operator [G].

**Parameters:**
- `mask`: 8-bit unsigned integer for standard octrees, or wider for wide variants [S1, unofficial].
- `child_index`: Integer $0 \dots 7$ for 8-way, $0 \dots 63$ for wide [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `child_index <= 0`, the function returns 0 immediately [S1, unofficial].
- For 8-way octrees, `child_index` ranges from 0 to 7; for wide octrees, it ranges from 0 to 63 [S1, unofficial].
- The shift operation `(1 << child_index)` is well-defined for these ranges within standard integer types [G].
- Precision issues are minimal as the operation is purely integer-based [G].

**Pseudocode:**
```python
def prefix_rank(mask: int, child_index: int) -> int:
    """
    Calculates the rank of a child index in a bitmask.
    
    Args:
        mask: Bitmask of active children (1 bit per child).
        child_index: Target child index (0-7 for 8-way, 0-63 for wide).
        
    Returns:
        The number of active children with index < child_index.
    """
    if child_index <= 0:
        return 0
    
    # Create a mask with bits 0 to child_index-1 set to 1
    lower_mask = (1 << child_index) - 1
    
    # Isolate active children preceding the target and count them
    return bin(mask & lower_mask).count('1')
```

## Subtopics

### Flat Rank
A space-efficient approach for answering access and rank queries on bit vectors in constant time [S2]. It partitions the bit vector into blocks and stores the cumulative count of 1-bits up to each block in an auxiliary array [S2]. This method requires approximately 3.51% additional space overhead compared to the raw bit vector [S2].

## Background
The method is derived from implementations in sparse voxel octree rendering, specifically cited from the `sparse-voxels` repository [S1, unofficial]. Rank queries on bit vectors can be answered in constant time [S2, Jac89]. Flat Rank, a variant for larger vectors, was detailed in recent research on segmentation volume compression [S2, Kur22].
