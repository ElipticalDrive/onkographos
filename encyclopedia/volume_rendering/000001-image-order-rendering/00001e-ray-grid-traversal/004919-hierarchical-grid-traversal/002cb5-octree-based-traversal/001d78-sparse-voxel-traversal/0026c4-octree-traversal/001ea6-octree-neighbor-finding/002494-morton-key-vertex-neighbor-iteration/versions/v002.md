# Morton Key Vertex Neighbor Iteration

Also called: Vertex Neighbor Iteration via Morton Keys

## Overview
Morton Key Vertex Neighbor Iteration identifies and processes the eight corner vertices of leaf nodes in a sparse voxel octree by leveraging the spatial locality of Morton (Z-order) keys [S1, unofficial]. It solves the dual-grid traversal problem, ensuring each shared vertex is processed exactly once across up to eight adjacent leaf nodes [S1, unofficial]. It differs from standard recursive neighbor finding by operating on a pre-computed list of vertex keys and using bitwise arithmetic to resolve adjacency and level mismatches without recursive tree traversal [S1, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: A sparse voxel octree implementation providing `node_exists(key)`, `is_subdivided(key)`, and `parent()` operations [S1, unofficial]. An array of `vertex_keys` containing `MortonKey` values for the eight vertices of a leaf node, with invalid vertices marked as `MortonKey::none()` [S1, unofficial]. The target level of the leaf node (`vertex_lv`) [S1, unofficial].
- **Outputs**: An array of eight resolved neighbor keys for the valid vertices of the leaf, where each entry is either a valid `MortonKey` of an existing node at the same level (or an ancestor if the direct neighbor is missing) or `MortonKey::none()` [S1, unofficial].

### Data Structures
- **MortonKey**: A struct wrapping a `u64` integer that represents a single node in a hashed octree [S1, unofficial]. Its internal representation starts with `1` for the root node and appends three bits per level for the child index along the X, Y, and Z axes [S1, unofficial]. `MortonKey::none()` returns `Self(0)` and `MortonKey::root()` returns `Self(1)` [S1, unofficial].
- **HashedOctree**: A concurrent hash map-based storage for the octree values [S1, unofficial]. Defined as `pub struct HashedOctree<T: Copy> { values: DashMap<MortonKey, T, RandomState>, }` [S1, unofficial].
- **OctreeIndex**: Bitflags for child indices where `RIGHT = 1 << 0`, `TOP = 1 << 1`, and `FOREMOST = 1 << 2` [S1, unofficial].

### Constants
The method relies on three 64-bit dilation constants to perform bitwise arithmetic on Morton keys [S1, unofficial]. These constants have bits set at positions corresponding to the X, Y, and Z axes in the Morton interleaving [S1, unofficial].
- `DIL_X = 0b001001001001001001001001001001001001001001001001001001001001001u64` [S1, unofficial].
- `DIL_Y = 0b010010010010010010010010010010010010010010010010010010010010010u64` [S1, unofficial].
- `DIL_Z = 0b100100100100100100100100100100100100100100100100100100100100100u64` [S1, unofficial].

### Formulas
The core of the method uses dilated integer addition and dilated integer subtraction to move along grid axes in Morton space using standard integer arithmetic masked by the dilation constants [S1, unofficial].
1. **Dilated Integer Addition** (computes vertex keys from a leaf key):
$$vertex\_key = \left( (key.0 \mid \neg DIL\_X) + (vertex\_i \ \& \ DIL\_X) \right) \ \& \ DIL\_X \ \mid \ \left( (key.0 \mid \neg DIL\_Y) + (vertex\_i \ \& \ DIL\_Y) \right) \ \& \ DIL\_Y \ \mid \ \left( (key.0 \mid \neg DIL\_Z) + (vertex\_i \ \& \ DIL\_Z) \right) \ \& \ DIL\_Z$$
Where $key.0$ is the Morton key of the leaf node, $vertex\_i$ is the vertex index (0–7), $\mid$ is bitwise OR, $\neg$ is bitwise NOT, $\&$ is bitwise AND, and $+$ is integer addition [S1, unofficial].
2. **Dilated Integer Subtraction** (computes neighbor leaf keys from a vertex key):
$$key_{node\_i} = \left( (dc \ \& \ DIL\_X) - (node\_i \ \& \ DIL\_X) \right) \ \& \ DIL\_X \ \mid \ \left( (dc \ \& \ DIL\_Y) - (node\_i \ \& \ DIL\_Y) \right) \ \& \ DIL\_Y \ \mid \ \left( (dc \ \& \ DIL\_Z) - (node\_i \ \& \ DIL\_Z) \right) \ \& \ DIL\_Z$$
Where $dc$ is the dilated coordinate of the vertex computed as $vertex\_k.0 \ll (vertex\_lv - vertex\_k.level()) \times 3$, and $node\_i$ is the neighbor index (0–7) [S1, unofficial].

### Algorithm Steps
The method processes a list of vertex keys to find unique neighbors [S1, unofficial].
1. **Iterate Vertices**: Enumerate over the `vertex_keys` array and stop when `vertex_k` equals `MortonKey::none()` [S1, unofficial]. Let the current index be `vertex_i` and the key be `vertex_k` [S1, unofficial].
2. **Compute Neighbor Candidates**: Call `vert2leaf(vertex_k, vertex_lv)` to obtain an array `neighbours` of eight candidate `MortonKey` values for the adjacent nodes [S1, unofficial].
3. **Filter Neighbors**: For each neighbor index `neighbour_i` from 0 to 7: skip if `neighbour_i == vertex_i` (the node itself) [S1, unofficial]. Let `neighbour_k = neighbours[neighbour_i]` [S1, unofficial]. If `!octree.node_exists(neighbour_k)`, continue to the next neighbor [S1, unofficial]. If `octree.is_subdivided(neighbour_k)` (the neighbor is deeper than the current leaf), mark the entire vertex as skipped because the deeper node will process the shared vertex [S1, unofficial]. If `neighbour_i < vertex_i`, mark the entire vertex as skipped to ensure shared vertices between same-level nodes are processed exactly once based on fixed indices rather than iteration order [S1, unofficial].
4. **Resolve Keys**: If the vertex passes the filter, initialize an array `keys: [MortonKey; 8]` [S1, unofficial]. For each `neighbour_i` from 0 to 7, let `neighbour_k = neighbours[neighbour_i]` [S1, unofficial]. While `neighbour_k != MortonKey::none()` AND `!octree.node_exists(neighbour_k)`, set `neighbour_k = neighbour_k.parent()` [S1, unofficial]. Store the resolved `neighbour_k` in `keys[neighbour_i]` [S1, unofficial]. Return `keys` [S1, unofficial].

### Pseudocode
```python
# Dilation constants
DIL_X = 0b001001001001001001001001001001001001001001001001001001001001001
DIL_Y = 0b010010010010010010010010010010010010010010010010010010010010010
DIL_Z = 0b100100100100100100100100100100100100100100100100100100100100100

class MortonKey:
    def __init__(self, val: int):
        self.0 = val
    @staticmethod
    def none():
        return MortonKey(0)
    @staticmethod
    def root():
        return MortonKey(1)
    def level(self) -> int:
        if self.0 == 0:
            raise ValueError("Cannot get level of none key")
        return (63 - self.0.bit_length() + 1) // 3
    def parent(self) -> 'MortonKey':
        return MortonKey(self.0 >> 3)

def leaf2vert(key: MortonKey) -> tuple[int, list[MortonKey]]:
    level = key.level()
    level_key = 1 << (3 * level)
    keys = [None] * 8
    for vertex_i in range(8):
        vertex_key = (
            ((key.0 | ~DIL_X) + (vertex_i & DIL_X)) & DIL_X |
            ((key.0 | ~DIL_Y) + (vertex_i & DIL_Y)) & DIL_Y |
            ((key.0 | ~DIL_Z) + (vertex_i & DIL_Z)) & DIL_Z
        )
        if (vertex_key >= (level_key << 1)) or \
           ((vertex_key - level_key) & DIL_X) == 0 or \
           ((vertex_key - level_key) & DIL_Y) == 0 or \
           ((vertex_key - level_key) & DIL_Z) == 0:
            keys[vertex_i] = MortonKey.none()
        else:
            keys[vertex_i] = MortonKey(vertex_key)
    return level, keys

def vert2leaf(vertex_k: MortonKey, vertex_lv: int) -> list[MortonKey]:
    dc = vertex_k.0 << ((vertex_lv - vertex_k.level()) * 3)
    keys = [None] * 8
    for node_i in range(8):
        keys[node_i] = MortonKey(
            ((dc & DIL_X) - (node_i & DIL_X)) & DIL_X |
            ((dc & DIL_Y) - (node_i & DIL_Y)) & DIL_Y |
            ((dc & DIL_Z) - (node_i & DIL_Z)) & DIL_Z
        )
    return keys

def process_vertex_neighbors(vertex_keys: list[MortonKey], octree) -> list[list[MortonKey]]:
    results = []
    for vertex_i, vertex_k in enumerate(vertex_keys):
        if vertex_k == MortonKey.none():
            break
        neighbours = vert2leaf(vertex_k, vertex_k.level())
        should_process = True
        for neighbour_i in range(8):
            if neighbour_i == vertex_i:
                continue
            neighbour_k = neighbours[neighbour_i]
            if not octree.node_exists(neighbour_k):
                continue
            if octree.is_subdivided(neighbour_k):
                should_process = False
                break
            if neighbour_i < vertex_i:
                should_process = False
                break
        if not should_process:
            continue
        keys = [None] * 8
        for neighbour_i in range(8):
            neighbour_k = neighbours[neighbour_i]
            while neighbour_k != MortonKey.none() and not octree.node_exists(neighbour_k):
                neighbour_k = neighbour_k.parent()
            keys[neighbour_i] = neighbour_k
        results.append(keys)
    return results
```

### Edge Cases and Pitfalls
- **Invalid Vertex Keys**: A vertex key is invalid if it falls outside the level's range (`vertex_key >= level_key << 1`) or if any dilated axis difference is zero [S1, unofficial]. These invalid cases return `MortonKey::none()` [S1, unofficial].
- **Concurrency**: When using `HashedOctree` (backed by `DashMap`), concurrent access may deadlock if a mutable reference is held while calling `value()` [S1, unofficial].
- **Tie-Breaking**: The condition `neighbour_i < vertex_i` ensures that shared vertices between nodes of the same level are processed only once, relying on fixed neighbor and vertex indices rather than iteration order [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(V)$ where $V$ is the number of valid vertices, with constant-time bitwise operations per vertex and a bounded parent-traversal loop [S1, unofficial].
- **Memory Complexity**: $O(1)$ auxiliary space per vertex for storing eight keys, with external octree storage [S1, unofficial].
- **Strengths**: Avoids recursive tree traversal for neighbor finding and uses fast bitwise arithmetic, making it efficient for sparse grids where many neighbors are missing [S1, unofficial].
- **Limitations**: Requires pre-computed or easily derivable vertex keys and relies on the octree implementation providing efficient `node_exists` and `is_subdivided` checks [S1, unofficial].

## Background
The method is described in the `dmc` (Dense Marching Cuber) project by aleokdev [S1, unofficial]. It is used for dual-grid traversal in volume rendering, specifically for extracting isosurfaces from sparse voxel octrees [S1, unofficial]. The approach leverages the properties of Morton keys to map spatial adjacency to arithmetic operations [S1, unofficial].
