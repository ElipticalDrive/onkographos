# Single-kernel Octree Traversal

Also called: Iterative Octree Traversal in CUDA, Stack-based Ray Traversal

## Overview
Single-kernel octree traversal is a technique for traversing an octree for ray tracing by performing the entire traversal logic, including recursion simulation, within a single CUDA kernel execution per ray, rather than using multiple kernel launches for each recursion depth [S1, unofficial]. It is preferred over multi-kernel recursion because kernel invocation overhead is high [S1, unofficial]. Although single-kernel traversal may cause thread divergence due to the SIMD nature of GPUs, coherent rays in a warp traverse similarly, mitigating this issue [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin, ray direction, octree node data (typically bound as a texture for random access), and a maximum stack size parameter.
*   **Output:** Traversal results (e.g., hit distance, node indices) stored in local or shared memory structures.

**Data Structures:**
*   **Traversal Stack:** A fixed-size array stored in local or shared memory. The size is manually defined because dynamic sizing is not possible in local/shared memory [S1, unofficial].
    *   **Fields:** Node indices (or pointers) to be visited.
    *   **Size:** Determined by the `stack_size` parameter. If too small, overflow occurs; if too large, memory is wasted [S1, unofficial].

**Steps:**
1.  **Kernel Launch:** Launch a single CUDA kernel where each thread (or block) represents a single ray [S1, unofficial]. A 2D grid and 2D block configuration is recommended to help with cache hits [S1, unofficial].
2.  **Initialization:** Initialize the traversal stack with the root node index [G].
3.  **Traversal Loop:** While the stack is not empty:
    a.  Pop the top node index from the stack.
    b.  If the node is a leaf, perform the leaf operation (e.g., ray-march or intersection test) [G].
    c.  If the node is internal, compute the child node indices intersected by the ray.
    d.  Push the child node indices onto the stack in reverse order of traversal preference (to ensure correct processing order upon popping) [G].
4.  **Termination:** The kernel completes when all rays have finished their traversal or hit a termination condition.

**Parameters:**
*   **Stack Size:** A manually defined maximum value for the traversal stack size [S1, unofficial]. Typical values depend on the octree depth and scene complexity, but must be chosen to balance memory waste and overflow risk [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Register Spilling:** If the kernel uses too many registers, the compiler spills variables to local memory (which is physically global memory), causing a significant performance penalty [S1, unofficial]. This is determined at compile time, not runtime [S1, unofficial].
*   **Silent Failure:** Exceeding register limits or program size limits can cause the kernel to fail silently without error messages, making debugging difficult [S1, unofficial].
*   **Memory Waste:** Using a fixed-size stack for all threads can lead to significant memory waste if the actual traversal depth varies greatly among rays [S1, unofficial].

**Pseudocode:**
```python
# Pseudocode for Single-kernel Octree Traversal in CUDA
# Each thread handles one ray

def single_kernel_octree_traversal(ray_origin, ray_direction, octree_texture, max_stack_size):
    # Local memory stack
    stack = [0] * max_stack_size
    stack_top = 0
    
    # Push root node
    stack[stack_top] = 0  # Assuming root is index 0
    stack_top += 1
    
    while stack_top > 0:
        # Pop node
        stack_top -= 1
        current_node_idx = stack[stack_top]
        
        # Fetch node data from texture
        # Note: tex1Dfetch is recommended for random access
        node_data = tex1Dfetch(octree_texture, current_node_idx)
        
        if node_data.is_leaf:
            # Perform leaf operation (e.g., ray-march)
            result = ray_march(ray_origin, ray_direction, node_data)
            # Store result

        else:
            # Compute intersected children
            children = get_intersected_children(ray_origin, ray_direction, node_data)
            
            # Push children in reverse order
            for child_idx in reversed(children):
                if stack_top < max_stack_size:
                    stack[stack_top] = child_idx
                    stack_top += 1
```

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of nodes visited per ray. The overhead of kernel invocation is eliminated compared to multi-kernel approaches [S1, unofficial].
*   **Memory Complexity:** O(D) per ray, where D is the maximum stack depth, stored in local or shared memory [S1, unofficial].
*   **Performance:** Kernel invocation overhead is high, making single-kernel traversal more efficient than multi-kernel recursion [S1, unofficial]. Thread divergence may occur, but coherent rays mitigate this [S1, unofficial].
*   **Strengths:** Reduced kernel launch overhead, better cache utilization with coherent rays [S1, unofficial].
*   **Limitations:** Risk of register spilling and silent failure if register limits are exceeded [S1, unofficial]. Fixed stack size can lead to memory waste or overflow [S1, unofficial].
*   **When to Use:** When kernel invocation overhead is a bottleneck and rays are coherent [S1, unofficial].
*   **When Not to Use:** When register pressure is high and cannot be managed, or when stack depth is highly variable and unpredictable [S1, unofficial].
