# Leaf Offset Computation

Also called: IndexGridBuilder::computeLeafs

## Overview
Leaf Offset Computation calculates the linear memory offsets for each leaf node in an OpenVDB tree to facilitate parallel processing and data copying [S1, unofficial]. It serves as a prerequisite for [Leaf Processing](5189-leaf-processing.md), which uses these offsets to copy precomputed voxel data from a contiguous source buffer into leaf node buffers [S1, unofficial].

## How it works
**Inputs:** An OpenVDB tree retrieved from a domain grid (`m_domainGrid->tree()`) [S1, unofficial].
**Outputs:** A vector `m_leafOffsets` containing cumulative offsets, and an integer `m_totalVoxels` [S1, unofficial].

**Data Structures:**
- `m_leafOffsets`: A `std::vector<size_t>` of size $N+1$, where $N$ is the number of leaves [S1, unofficial].
- `m_totalVoxels`: A `size_t` representing the total number of voxels in all leaves [S1, unofficial].
- `LeafNodeType::SIZE`: The constant number of voxels per leaf node [S1, unofficial].

**Steps:**
1. Retrieve the tree from the domain grid.
2. Create a `LeafManager` instance wrapping the tree to facilitate leaf counting.
3. Store the leaf count in `m_numLeaves`.
4. Resize `m_leafOffsets` to hold $N+1$ elements.
5. Calculate `m_totalVoxels` as $N \times \text{LeafNodeType::SIZE}$.
6. Generate a sequence of indices from $0$ to $N-1$.
7. Compute offsets in parallel: for each index $i$, set `m_leafOffsets[i] = i * LeafNodeType::SIZE`.
8. Set the final offset `m_leafOffsets[N]` to `m_totalVoxels`. This final element acts as a boundary marker for parallel iteration ranges [G].

## Subtopics

### [Leaf Processing](5189-leaf-processing.md)
Copies precomputed voxel data from a contiguous source buffer into the leaf node buffers of an OpenVDB tree in parallel. It executes the actual memory copy operations using offsets generated by [Leaf Offset Computation](5185-leaf-offset-computation.md).

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of leaves [G]. The parallel transform scales with available cores [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the offset vector [S1, unofficial].
- **Strengths:** Simple, deterministic, and highly parallelizable [G]. Provides a clean boundary marker for subsequent parallel loops [G].
- **Limitations:** Assumes uniform leaf size [G]. Does not handle variable-sized leaves or sparse leaf distributions differently than dense ones (it counts active leaves) [G].
- **When to use:** When preparing for bulk data transfer into OpenVDB leaf nodes [G].
- **When not to use:** If leaf sizes vary or if a different memory layout is required [G].
