# Octree MIP-mapping

Also called: Octree MIP-map Generation, Voxel Hierarchy Filtering, Writing and Mipmapping Values

## Overview
Octree MIP-mapping propagates and filters voxel data from the leaf nodes of a sparse voxel octree up to the interior nodes to create a multi-resolution hierarchy for efficient ray-grid traversal [S1][S2, unofficial]. It differs from regular grid MIP-mapping by explicitly handling the boundary sharing of 3x3x3 voxel bricks in an octree structure, requiring weighted averaging to account for overlapping voxels [S1][S2, unofficial].

## How it works
**Inputs:**
*   An octree structure with $n$ levels, where level 0 is the root and level $n-1$ contains the leaves [S1][S2, unofficial].
*   Leaf node values, written in a prior step ("Write Leaf Values") [S2, unofficial].
*   Voxel values stored as `RGBA32F` in a buffer object in global memory [S2, unofficial].

**Outputs:**
*   Filtered values for all interior nodes (levels $0$ to $n-2$) [S1][S2, unofficial].

**Data Structures:**
*   **Octree Nodes:** Each node at level $l$ contains a 3x3x3 brick of voxels [S1].
*   **Sub-nodes:** Each node has 8 child nodes (sub-nodes) at level $l+1$ [S2, unofficial].
*   **Voxel Multiplicity:** Due to the 3x3x3 brick layout, boundary voxels are shared between neighboring bricks, meaning a voxel on the boundary of a brick appears in multiple adjacent bricks [S1].

**Parameters:**
*   $n$: Total number of levels in the octree [S1][S2, unofficial].
*   Weighting Kernel: 3x3x3 Gaussian weighting kernel [S1]. This is considered an optimal reconstruction filter [S1][FP02].

**Steps:**
1.  **Write Leaf Values:** Launch one thread per entry in the voxel-fragment list. Each thread splats and merges voxel-fragment values into the leaf nodes of the octree, using a scheme similar to the regular grid method [S2, unofficial].
2.  **Mipmap Interior Nodes:** Process levels from bottom (level $n-2$) to top (level 0) in $n-1$ steps [S1][S2, unofficial].
    *   At each step, launch one thread per non-empty node of the current level [S2, unofficial].
    *   Each thread computes the filtered value for the current node by averaging the values contained in its eight sub-nodes (children) from the previous level [S1][S2, unofficial].
    *   **Weighting:** Because each node contains a 3x3x3 voxel brick, boundary voxels reappear in neighboring bricks. To prevent double-counting, each voxel must be weighted by the inverse of its multiplicity (the number of bricks it is shared by) [S1].
    *   This weighting results in a 3x3x3 Gaussian weighting kernel [S1].

**Pseudocode:**
```python
def octree_mipmap(octree, n_levels):
    # Process levels from bottom (n-2) to top (0) in n-1 steps [S1][S2, unofficial]
    for level in range(n_levels - 2, -1, -1):
        # Retrieve non-empty nodes at the current level [S2, unofficial]
        current_nodes = get_nodes_at_level(octree, level)
        
        for node in current_nodes:
            # Get the 8 sub-nodes (children) at level + 1 [S2, unofficial]
            children = get_children(node)
            parent_brick = [[None]*3 for _ in range(3)]
            
            # Iterate over the 3x3x3 voxels of the parent node
            for x in range(3):
                for y in range(3):
                    for z in range(3):
                        weighted_sum = 0.0
                        weight_total = 0.0
                        
                        for child in children:
                            # Each child is a 3x3x3 brick [S1]
                            # Apply inverse multiplicity weighting, resulting in a 3x3x3 Gaussian kernel [S1]
                            # The exact Gaussian coefficients are not provided in the sources [G]
                            w = 1.0  # Placeholder for Gaussian weight calculation
                            v = child.brick[x][y][z]
                            weighted_sum += v * w
                            weight_total += w
                        
                        parent_brick[x][y][z] = weighted_sum / weight_total if weight_total > 0 else 0.0
                            
            node.brick = parent_brick

def get_nodes_at_level(octree, level):
    # Returns a list of node references allocated at the given level [S2, unofficial]
    return octree.nodes_by_level[level]

def get_children(node):
    # Returns the 8 child node references for the given node
    return node.children
```

**Edge Cases and Pitfalls:**
*   **Boundary Sharing:** Failure to weight voxels by the inverse of their multiplicity will result in incorrect values at node boundaries due to double-counting [S1].
*   **Precision:** Using `RGBA32F` helps maintain precision during accumulation [S2, unofficial].
*   **Empty Nodes:** Only non-empty nodes need to be processed at each level [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of non-empty nodes in the octree, processed over $n-1$ passes [S1][S2, unofficial].
*   **Memory Complexity:** Requires storage for the octree structure and the voxel values, with no significant additional memory required for the MIP-mapping step itself [S1][S2, unofficial].
*   **Performance:** On a Kepler-based NVIDIA GTX680 with a maximum voxelization resolution of $512^3$ (9 octree levels), the MIP-mapping step is relatively fast compared to octree construction [S2, unofficial].
*   **Strengths:** Efficiently creates a multi-resolution hierarchy for ray-grid traversal and handles sparse data well [S1][S2, unofficial].
*   **Limitations:** Requires careful handling of boundary voxels to avoid double-counting, and performance scales with the number of non-empty nodes [S1][S2, unofficial].
