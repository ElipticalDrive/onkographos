# XBrickMap
Also called: eXtendedBrickMap
## Overview
XBrickMap is a space-partitioning ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to skip empty regions via bitwise tests [S1, unofficial]. It improves upon simpler skipping methods by using tiled bitmasks to perform hierarchical skips of $4^3$, $2^3$, and $1^3$ cuboids, while left-packing empty bricks within sectors to save memory [S1, unofficial]. It is distinguished from its sibling [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by its specific use of compacted bitmasks for random access and its support for arbitrary in-place edits within bricks [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a hierarchical voxel grid consisting of sectors, bricks, and voxels [S1, unofficial].
- Output: The intersection point and material properties of the first non-transparent voxel hit by the ray [S1, unofficial].

**Data Structures:**
The hierarchy consists of three levels [S1, unofficial]:
1.  **Sector:** The top-level container holding a list of bricks [S1, unofficial]. Empty bricks are omitted via left-packing [S1, unofficial]. Sector metadata maps indices [S1, unofficial].
2.  **Brick:** Contains a $4^3$ (64-bit) occupancy bitmask and $8^3$ voxel data [S1, unofficial]. The bitmask tracks $4^3$ sub-cuboids for hierarchical skipping ($4^3, 2^3, 1^3$) [S1, unofficial].
3.  **Voxel:** 8-bit value (0 is transparent) [S1, unofficial].
-   **Memory Layout:** 8³ bits per brick + 12 bytes per sector [S1, unofficial].

**Numbered Steps:**
1.  **Initialize Ray Marching:** Start at the ray origin [S1, unofficial].
2.  **Sector Traversal:** Determine which sector the ray is currently in [S1, unofficial].
3.  **Brick Skipping (Hierarchical):** Query the sector's data structure to find the bricks in the current path [S1, unofficial]. Use the $4^3$ occupancy bitmask of each brick [S1, unofficial]. Perform bitwise tests on the bitmask to identify empty sub-cuboids ($4^3, 2^3, 1^3$) [S1, unofficial]. If a sub-cuboid is empty, skip it entirely [S1, unofficial]. Use `popcnt` (population count) instructions to count preceding entries for random access to the next non-empty brick or voxel [S1, unofficial].
4.  **Voxel Traversal:** Once a non-empty brick/sub-region is identified, march through the $8^3$ voxels [S1, unofficial]. Intersect the ray with the three front-facing cube planes of the current voxel to compute the step size [S1, unofficial]. Query the voxel data. If non-zero, return the hit.
5.  **Iteration:** Repeat steps 2-4 until the ray exits the grid or hits a surface [S1, unofficial].

**Formulas:**
- Ray position at step $t$: $\mathbf{p}(t) = \mathbf{o} + t \cdot \mathbf{d}$ [S1, unofficial].
- DDA step size along axes: $\Delta t_x = \frac{V}{|d_x|}$, $\Delta t_y = \frac{V}{|d_y|}$, $\Delta t_z = \frac{V}{|d_z|}$, where $V$ is voxel size and $d_i$ are direction components [G].
- Sub-cuboid bitmask index: $idx = (z_{local} \cdot 4 + \lfloor y_{local} / 2 \rfloor) \cdot 4 + \lfloor x_{local} / 2 \rfloor$ [G].
- Random access offset via population count: $offset = \text{popcnt}(mask \ \& \ (2^{idx} - 1))$ [S1, unofficial].

**Parameters:**
-   Sector size: Not explicitly given in units, but contains $4^3$ bricks [S1, unofficial].
-   Brick size: $8^3$ voxels [S1, unofficial].
-   Bitmask size: $4^3$ bits per brick [S1, unofficial].

**Edge Cases and Pitfalls:**
-   **Floating-point precision:** Can cause infinite backtracking [S1, unofficial]. Workaround: Bias intersection distances [S1, unofficial].
-   **Dynamic Edits:** Supports arbitrary edits within a brick [S1, unofficial]. However, insertions and deletions may require reallocations at the sector level to make space for new bricks [S1, unofficial].
-   **Memory Layout:** Left-packing of empty bricks requires careful index mapping using `popcnt` [S1, unofficial].
-   **Voxel Storage:** Each voxel in a brick is 8-bit [S1, unofficial]. 0 is transparent [S1, unofficial].

**Pseudocode:**
```python
def traverse_xbrickmap(ray_origin, ray_direction, grid):
    # Bias intersection distances to avoid floating-point infinite backtracking [S1, unofficial]
    t = 1e-6
    
    # Precompute inverse direction components for DDA step calculation [G]
    inv_dir = [1.0 / d if d != 0 else float('inf') for d in ray_direction]
    voxel_size = grid.voxel_size
    
    # Determine initial sector index from ray origin [G]
    sector_idx = int(ray_origin.x // grid.sector_size)
    sector = grid.sectors[sector_idx]
    
    while t < grid.max_distance:
        # Compute current voxel position by intersecting with ray [S1, unofficial]
        voxel_pos = ray_origin + ray_direction * t
        
        # Determine current brick index within the sector [G]
        brick_idx = int((voxel_pos.x - sector.origin.x) // grid.brick_size)
        
        # Check bounds and sector/brick emptiness [G]
        if brick_idx < 0 or brick_idx >= len(sector.bricks):
            # Skip to next sector or exit [G]
            t += (sector.origin.x + (sector_idx + 1) * grid.sector_size - ray_origin.x) * inv_dir[0]
            sector_idx += 1
            if sector_idx < len(grid.sectors):
                sector = grid.sectors[sector_idx]
            else:
                return None
            continue
            
        brick = sector.bricks[brick_idx]
        
        # Map voxel position to local brick coordinates and bitmask index [G]
        local_x = int((voxel_pos.x - brick.origin.x) // voxel_size)
        local_y = int((voxel_pos.y - brick.origin.y) // voxel_size)
        local_z = int((voxel_pos.z - brick.origin.z) // voxel_size)
        mask_idx = (local_z * 4 + local_y // 2) * 4 + local_x // 2
        
        # Check occupancy mask for sub-cuboids [S1, unofficial]
        if (brick.occupancy_mask >> mask_idx) & 1 == 0:
            # Sub-cuboid empty; skip using bitmask logic [S1, unofficial]
            # Advance t to exit current sub-cuboid [G]
            t += 2.0 * voxel_size * inv_dir[0]
            continue
            
        # Traverse voxels within the brick [S1, unofficial]
        # Intersect ray with three front-facing cube planes to compute step size [S1, unofficial]
        dx = voxel_size * inv_dir[0]
        dy = voxel_size * inv_dir[1]
        dz = voxel_size * inv_dir[2]
        step = min(dx, dy, dz)
        
        # Query voxel data [S1, unofficial]
        voxel_val = brick.voxels[local_z * 64 + local_y * 8 + local_x]
        
        if voxel_val == 0:
            t += step
        else:
            return {"t": t, "position": ray_origin + ray_direction * t, "value": voxel_val}
            
    return None
```

This method tracks which finest-level brick cells have been visited by rays to enable selective streaming and refinement, preventing redundant data transfers when multiple rays share a cell. It differs from XBrickMap by adding a runtime occupancy buffer that complements the static hierarchical skipping with dynamic visitation history.

### Two-Level Voxel Grid with Solid Color Optimization
A data structure storing voxels in a two-level hierarchy to optimize ray traversal and memory usage [S2, unofficial]. It consists of a coarse $128^3$ top-level grid pointing to $8^3$ voxel bricks, resulting in a total world resolution of $1024^3$ [S2, unofficial].
-   **Layout:** Top-level grid cell is a 32-bit value [S2, unofficial]. Bit 0 determines type: 0 indicates solid color (bits 1-31 store color), 1 indicates pointer to brick (bits 1-31 store brick index) [S2, unofficial]. Value 0 represents transparent solid color [S2, unofficial].
-   **Voxel Storage:** Each voxel in a brick is 8-bit [S2, unofficial]. 0 is transparent [S2, unofficial]. Non-zero is 3-3-2 RGB triplet [S2, unofficial].
-   **Memory:** Top-level grid is 8MB ($128^3 \times 4$ bytes) [S2, unofficial]. Max brick memory is 1GB ($128^3$ unique bricks $\times 8^3$ voxels $\times 1$ byte) [S2, unofficial].
-   **Pitfall:** Initializing the world to empty/transparent is done via `memset(0)` because 0 is a valid transparent solid color [S2, unofficial].

## Operating characteristics
-   **Time Complexity:** Approximately $O(1)$ per step, though dependent on the density of non-empty regions [S1, unofficial].
-   **Memory Complexity:** 8³ bits per brick + 12 bytes per sector [S1, unofficial].
-   **Performance:** On the Sponza 2k scene, XBrickMap achieves 165.6 Mrays/s for primary rays and 125.1 Mrays/s for primary + 1 diffuse bounce [S1, unofficial].
-   **Strengths:** Good performance relative to simplicity; supports arbitrary edits within bricks; efficient space skipping via bitwise operations [S1, unofficial].
-   **Limitations:** Insertions/deletions may require sector-level reallocations; floating-point precision issues require biasing; performance on incoherent rays is ~30-50% worse than coherent rays but still worse than other space-partitioning methods [S1, unofficial].
-   **When to use:** When random access and in-place editing of voxel data are required, and the scene has significant empty space to skip [S1, unofficial].
-   **When not to use:** When the scene is highly dense with no empty space, or when dynamic topology changes are frequent and costly reallocations are unacceptable [S1, unofficial].

## Background
XBrickMap was developed as part of the VoxelRT project by Thijs van Wingerden and Stijn Herfst [S1, unofficial]. It is described in the thesis "VoxelRT: Visualization and Editing of Large Voxel Scenes" [S1, unofficial]. The method builds on earlier brick map concepts and aims to provide a high-performance realtime CUDA voxel path tracer [S1, unofficial]. It is designed to handle large voxel scenes with efficient space skipping and dynamic editing capabilities [S1, unofficial].
