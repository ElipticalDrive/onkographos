# Dual-grid Parallel Framework

Also called: raytheia dual-grid, source-contribution grid

## Overview
The dual-grid parallel framework is a distributed-memory method for evaluating direction-dependent integrals by decoupling ray emission locations from the spatial domain used for accumulation [S1, unofficial]. It improves computational efficiency and methodological generality by allowing the source grid to retain native simulation discretizations (e.g., unstructured or meshless) while using a recursively refined contribution grid for ray walking [S1, unofficial]. Unlike monolithic grid approaches, it enables independent decomposition of source and contribution domains to optimize load balance during parallel execution [S1, unofficial].

## How it works
**Inputs and Outputs**
- **Inputs**: A source grid defining ray emission centers (structured, unstructured, or particles); a direction vector for integration; a contribution grid built from the source grid; domain decomposition parameters.
- **Outputs**: The total direction-dependent integral value.

**Data Structures**
- **Source Grid**: Stores emission locations. Layout depends on the underlying simulation (e.g., Lagrangian particles or unstructured mesh nodes) [S1, unofficial].
- **Contribution Grid**: A uniform or refined mesh used for ray traversal. Built via recursive refinement of the source grid based on problem-specific criteria [S1, unofficial].
- **Chunks**: The computational domain is partitioned into distinct spatial chunks, each assigned to an MPI rank [S1, unofficial]. Each rank stores only data for its local subdomain [S1, unofficial].

**Algorithm Steps**
1. **Grid Construction**: Build the contribution grid from the source grid using recursive refinement [S1, unofficial].
2. **Domain Decomposition**: Partition the contribution grid into $N_{\text{ranks}}$ chunks, one per MPI rank [S1, unofficial].
3. **Parallel Loop (Chunk-to-Chunk)**: For each contribution chunk $c$ from $0$ to $N_{\text{ranks}}-1$:
    a. **Broadcast**: Send the data (spatial boundaries and integration variables) of chunk $c$ to all MPI ranks [S1, unofficial].
    b. **Local Ray Walking**: For each source element $i$ local to the current rank:
        i. Emit a ray from the source element's center along the given direction.
        ii. Walk the ray through the received chunk $c$ to find intersected cells.
        iii. For each intersected cell $j$, compute the local contribution $C_{i,j}$ as the product of the cell quantity $Q_j$ and the path length $L_{i,j}$ within that cell:
        $$ C_{i,j} = Q_j \times L_{i,j} $$
        iv. Accumulate the local contribution for this chunk:
        $$ I_{\text{local}, c} = \sum_{j \in \text{intersected}} C_{i,j} $$
    c. **Accumulation**: Add $I_{\text{local}, c}$ to the rank's total integral accumulator [S1, unofficial].
    d. **Buffer Reuse**: The same communication buffer is reused to receive the next chunk's data, updating the local data after accumulation [S1, unofficial].
4. **Final Result**: The total integral is the sum of contributions from all traversed chunks [S1, unofficial].

**Pseudocode**
```python
# Global variables
# N_ranks: Total number of MPI ranks
# source_elements: List of local source elements (center positions)
# direction: Unit vector for ray direction
# total_integral: Accumulator for the final result, initialized to 0.0

# Step 1: Partition contribution grid into chunks (done once, known to all ranks)
# chunks: List of N_ranks contribution chunks, each containing spatial boundaries and cell data

# Step 2: Chunk-to-Chunk Parallel Loop
for c in range(N_ranks):
    # (i) Sequential broadcast of chunk c data to all ranks
    # chunk_data contains: spatial boundaries (min/max coords) and integration variables (cell quantities)
    chunk_data = receive_chunk_data(c)
    
    # (ii) Compute local contribution for this chunk
    local_chunk_contribution = 0.0
    
    for source in source_elements:
        # Emit ray from source center along direction
        ray_origin = source.center
        ray_direction = direction
        
        # Ray-walk through chunk_data to find intersected cells
        intersected_cells = ray_walk(ray_origin, ray_direction, chunk_data)
        
        # Accumulate contributions from intersected cells
        for cell in intersected_cells:
            # Cell quantity Q and path length L
            Q = cell.quantity
            L = cell.path_length_in_chunk
            
            # Local contribution: product of cell quantity and path length
            contribution = Q * L
            local_chunk_contribution += contribution
            
    # (iii) Accumulate into total integral
    total_integral += local_chunk_contribution
    
    # (iv) Buffer reuse: chunk_data is overwritten in next iteration
```

**Parameters and Edge Cases**
- **Refinement Criteria**: Problem-specific criteria determine the contribution grid's resolution [S1, unofficial].
- **Memory**: The chunk-to-chunk strategy ensures only one chunk is stored in memory at a time, reducing memory requirements [S1, unofficial].
- **Load Balance**: Independent decomposition of source and contribution grids allows for better load balancing [S1, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of source elements and the number of intersected cells per ray. The chunk-to-chunk strategy adds a sequential communication overhead proportional to $N_{\text{ranks}}$.
- **Memory Complexity**: $O(1)$ per rank for the contribution grid data, as only one chunk is held in memory at a time [S1, unofficial].
- **Scalability**: Excellent scalability due to coarse-grained, regular communication patterns and reduced memory footprint [S1, unofficial].
- **Strengths**: High efficiency for direction-dependent integrals; supports arbitrary source grid discretizations; flexible load balancing.
- **Limitations**: Sequential broadcast of chunks may become a bottleneck if $N_{\text{ranks}}$ is very large or if chunk data is large.

## Background
The framework is implemented in RAYTHEIA, a high-performance ray-tracing algorithm for three-dimensional direction-dependent equations in astronomical simulations [S1, unofficial]. It was developed to handle complex source distributions (e.g., Lagrangian particles) and improve upon traditional grid-based methods by decoupling emission and accumulation domains [S1, unofficial].
