# Particle Rendering via Grid Bucketing

Also called: Grid Bucketing Particle Rendering, Particle Visualization, Sphere Rendering

## Overview
Particle Rendering via Grid Bucketing renders particles as spheres by mapping them to a spatial grid to accelerate ray-sphere intersection tests [S1]. It differs from [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md) by explicitly iterating over particle lists stored in grid buckets rather than marching through a voxel grid to find hits, and from [2D Projection 1D Lookup Particle Cache](8958-2d-projection-1d-lookup-particle-cache.md) by relying on 3D spatial hashing rather than 2D screen-space caching [G].

## How it works
**Inputs:** Ray origin $\mathbf{o}$ and direction $\mathbf{d}$; particle data (positions $\mathbf{x}_j$, radii $r_j$, colors); spatial grid structure mapping cell indices to particle lists; current cell bounds $[\mathbf{c}_{min}, \mathbf{c}_{max}]$ and index $\mathbf{c}$ [S1].
**Outputs:** Intersection distance $\lambda_j$, intersection point $\mathbf{x}_i$, normal $\mathbf{n}_i$, and color [S1].

**Data Structures:**
The grid maps integer cell indices to lists of particle IDs [S1]. Each particle $j$ is assigned to a cell based on its center position $\mathbf{x}_j$ [G]. The grid must support retrieval of particles in a cell $c$ and its immediate neighbors [S1].

**Steps:**
1.  **Ray-Cell Intersection:** Calculate the intersection of the current ray with the current grid cell $c$ [S1]. This yields the entry distance $\lambda_{min\_c}$ and exit distance $\lambda_{max\_c}$ [S1].
2.  **Neighbor Iteration:** Identify all particles that can potentially overlap cell $c$ [S1]. This includes all particles contained within cell $c$ and its neighboring cells [S1].
3.  **Ray-Sphere Intersection:** For each candidate particle $j$:
    *   Calculate the ray-sphere intersection distance $\lambda_j$ [S1]. If an intersection exists, $\lambda_j$ is the distance from the ray origin to the intersection point [S1].
    *   Check if $\lambda_j \in [\lambda_{min\_c}, \lambda_{max\_c}]$ [S1].
    *   If the condition is met and $\lambda_j$ is smaller than the current closest intersection distance, store $j$ and $\lambda_j$ as the new closest hit [S1].
4.  **Result Computation:** If a particle intersection was found:
    *   Compute the intersection point: $\mathbf{x}_i = \mathbf{o} + \lambda_j \mathbf{d}$ [S1].
    *   Compute the normal: $\mathbf{n}_i = \mathbf{x}_i - \mathbf{x}_j$ [S1].
    *   Determine the color using a color mapping of a quantity associated with particle $j$ [S1].

**Pseudocode:**
```python
def render_particle_grid_bucketing(ray_o, ray_d, grid, particles, cell_idx, cell_min, cell_max):
    # 1. Ray-Cell Intersection (Slab method)
    t_min = []
    t_max = []
    for i in range(3):
        if ray_d[i] == 0.0:
            t_min.append(-float('inf'))
            t_max.append(float('inf'))
        else:
            t_min.append((cell_min[i] - ray_o[i]) / ray_d[i])
            t_max.append((cell_max[i] - ray_o[i]) / ray_d[i])
    t_enter = max(min(t_min), min(t_max))
    t_exit = min(max(t_min), max(t_max))
    lambda_min_c, lambda_max_c = t_enter, t_exit
    
    closest_lambda = float('inf')
    closest_particle_id = -1
    
    # 2. Neighbor Iteration
    neighbor_cells = []
    for dx in (-1, 0, 1):
        for dy in (-1, 0, 1):
            for dz in (-1, 0, 1):
                neighbor_cells.append((cell_idx[0] + dx, cell_idx[1] + dy, cell_idx[2] + dz))
                
    candidate_particles = []
    for n_idx in neighbor_cells:
        if n_idx in grid:
            candidate_particles.extend(grid[n_idx])
            
    # 3. Ray-Sphere Intersection tests
    for j in candidate_particles:
        particle = particles[j]
        center = particle.position
        radius = particle.radius
        
        # Ray: P(t) = O + t*D
        # Sphere: |P(t) - C|^2 = r^2
        # Quadratic: a*t^2 + b*t + c = 0
        L = [ray_o[k] - center[k] for k in range(3)]
        a = sum(ray_d[k] * ray_d[k] for k in range(3))
        b = 2.0 * sum(ray_d[k] * L[k] for k in range(3))
        c_val = sum(L[k] * L[k] for k in range(3)) - radius * radius
        
        discriminant = b * b - 4 * a * c_val
        
        if discriminant >= 0:
            sqrt_disc = discriminant ** 0.5
            t1 = (-b - sqrt_disc) / (2 * a)
            t2 = (-b + sqrt_disc) / (2 * a)
            
            # Select closest positive intersection
            if t1 > 0:
                lambda_j = t1
            elif t2 > 0:
                lambda_j = t2
            else:
                continue
                
            # Check if intersection is within the cell bounds
            if lambda_min_c <= lambda_j <= lambda_max_c:
                if lambda_j < closest_lambda:
                    closest_lambda = lambda_j
                    closest_particle_id = j
                    
    # 4. Result Computation
    if closest_particle_id != -1:
        particle = particles[closest_particle_id]
        x_i = [ray_o[k] + closest_lambda * ray_d[k] for k in range(3)]
        n_i = [x_i[k] - particle.position[k] for k in range(3)]
        color = particle.color
        return closest_lambda, x_i, n_i, color
    else:
        return float('inf'), None, None, None
```

**Parameters:**
*   Grid resolution: Not given in the sources [S1].
*   Particle radius: Defined per particle [S1].

**Edge Cases:**
*   **Precision:** Ray-sphere intersection discriminant calculation may suffer from precision issues for grazing angles or very small radii [G].
*   **Boundaries:** The check $\lambda_j \in [\lambda_{min\_c}, \lambda_{max\_c}]$ ensures the intersection is within the current cell's depth range, preventing false positives from particles in the same cell but at different depths if the grid is not perfectly aligned or if particles span multiple cells [G].
*   **Degenerate Input:** Particles with zero radius will have no intersection unless the ray origin is exactly at the center [G].

### Grid Resolution Selection
Determines the trade-off between culling efficiency and neighbor list size [G]. Smaller cells reduce neighbor lists but increase grid memory and traversal overhead [G]. Larger cells increase neighbor lists but reduce grid overhead [G]. Not given in the sources.

### Particle Data Structure
How particle positions, radii, and colors are stored and accessed [G]. Typically a Struct of Arrays (SoA) or Array of Structs (AoS) [G]. Not given in the sources.

## Operating characteristics
*   **Time Complexity:** $O(N)$ in the worst case if all particles are in the same cell or neighbors, but typically $O(1)$ per ray if the grid is well-balanced and particles are uniformly distributed, as only a small constant number of neighbors are checked [G].
*   **Memory Complexity:** $O(N + G)$, where $N$ is the number of particles and $G$ is the number of grid cells [G].
*   **Strengths:** Efficient culling of non-overlapping particles; simple implementation; supports arbitrary particle shapes (spheres) and sizes [G].
*   **Limitations:** Performance degrades with highly clustered particles; requires spatial hashing or grid management overhead [G].
*   **When to use:** When rendering large numbers of spherical particles where spatial coherence exists [G].
*   **When not to use:** When particles are extremely dense and clustered, leading to large neighbor lists; when non-spherical particles are used without modification [G].

## Background
The method is described in the context of Smoothed Particle Hydrodynamics (SPH) simulation and rendering [S1]. It was published by The Authors in *Computer Graphics Forum* published by Eurographics - The European Association for Computer Graphics in 2020 [S1]. The work is titled *Multi‐Level Memory Structures for Simulating and Rendering Smoothed Particle Hydrodynamics* [S1].
