# Multi-Grid Ray Traversal

Also called: Grid Traversal (Multi-Grid), Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal traverses rays through multiple binary occupancy grids to generate ray intervals, sample positions, and termination planes. It solves the problem of efficiently sampling dense volumetric data by combining pre-computed ray-AABB intersections with voxel-level traversal. Unlike single-grid traversal, it handles disjoint or overlapping spatial partitions by sorting intersection times and managing chunked memory layouts for variable-length output segments [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `rays_o`: Ray origins, shape `[n_rays, 3]` (float).
    *   `rays_d`: Ray directions, shape `[n_rays, 3]` (normalized float).
    *   `binaries`: Binary occupancy grids, shape `[n_grids, resx, resy, resz]` (boolean). All grids share the same resolution [S1, unofficial][S2, unofficial].
    *   `aabbs`: Axis-Aligned Bounding Boxes for each grid, shape `[n_grids, 6]` (float), storing min/max x, y, z [S1, unofficial][S2, unofficial].
    *   `rays_mask`: Optional boolean mask, shape `[n_rays]`, to skip specific rays [S1, unofficial][S2, unofficial].
    *   `near_planes`: Optional per-ray near plane distances, shape `[n_rays]`. Defaults to zeros [S1, unofficial][S2, unofficial].
    *   `far_planes`: Optional per-ray far plane distances, shape `[n_rays]`. Defaults to infinity [S1, unofficial][S2, unofficial].
    *   `t_sorted`: Optional pre-computed sorted intersection times, shape `[n_rays, n_grids * 2]` (float) [S1, unofficial][S2, unofficial].
    *   `t_indices`: Optional pre-computed sorted grid indices, shape `[n_rays, n_grids * 2]` (int64) [S1, unofficial][S2, unofficial].
    *   `hits`: Optional pre-computed hit flags, shape `[n_rays, n_grids]` (boolean) [S1, unofficial][S2, unofficial].
    *   `step_size`: Fixed step size for marching. Default `1e-3`. If `<= 0.0`, records steps per voxel cell; if `> 0.0`, uses uniform or cone-based marching [S1, unofficial][S2, unofficial].
    *   `cone_angle`: Controls linear step size increase with distance. Default `0.0` (constant step size). Must be `>= 0.0` [S1, unofficial][S2, unofficial].
    *   `traverse_steps_limit`: Maximum number of traversal steps per ray. Default `-1` (unlimited) [S1, unofficial][S2, unofficial].
    *   `over_allocate`: If `True`, over-allocates memory for outputs. Requires `traverse_steps_limit > 0` [S1, unofficial][S2, unofficial].
    *   `compute_intervals`, `compute_samples`, `compute_terminate_planes`: Boolean flags to enable specific outputs [S2, unofficial].

*   **Outputs:**
    *   `intervals`: `PackedRaySegmentsSpec` structure storing traversal intervals per ray, supporting chunked memory layouts via `chunk_cnts` (counts) and `chunk_starts` (offsets) [S1, unofficial].
    *   `samples`: `RaySamples` object containing sample positions within each interval [S1, unofficial].
    *   `terminated_t`: Tensor of shape `[n_rays]` containing terminated t values [S1, unofficial].

**Data Structures:**
*   **PackedRaySegmentsSpec**: A structure that packs variable-length segments into contiguous memory. It uses `chunk_cnts` (array of segment counts per ray) and `chunk_starts` (cumulative offsets) to map ray/segment indices to flat arrays of interval bounds and sample data [S1, unofficial].
*   **Binary Grid**: A 4D boolean tensor `[n_grids, resx, resy, resz]` representing voxel occupancy. Empty voxels are `False`, occupied are `True` [S1, unofficial][S2, unofficial].

**Algorithm Steps:**

1.  **Initialization**:
    *   Initialize `rays_mask` to all-ones boolean tensor `[n_rays]` if `None` [S2, unofficial].
    *   Initialize `near_planes` to zeros `[n_rays]` if `None` [S1, unofficial][S2, unofficial].
    *   Initialize `far_planes` to infinity `[n_rays]` if `None` [S1, unofficial][S2, unofficial].
    *   If `t_sorted`, `t_indices`, or `hits` are `None`, compute ray-AABB intersections using `ray_aabb_intersect(rays_o, rays_d, aabbs)` to get `t_mins`, `t_maxs`, and `hits` [S2, unofficial].
    *   Concatenate `t_mins` and `t_maxs` along the last dimension and sort them to get `t_sorted` and `t_indices` [S1, unofficial][S2, unofficial].

2.  **Parallel Setup**:
    *   Compute thread ID: `tid = blockIdx.x * blockDim.x + threadIdx.x` [S1, unofficial].
    *   If `first_pass` is `False` and `chunk_cnts[tid] == 0`, skip processing for this ray [S1, unofficial].
    *   Set base indices for intersections: `base_hits = tid * n_grids`, `base_t_sorted = tid * n_grids * 2` [S1, unofficial].

3.  **Interval Generation**:
    *   Loop over intersections `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1` [S1, unofficial].
    *   Determine `is_entering = t_indices[i] < n_grids` and `level = t_indices[i] % n_grids` [S1, unofficial].
    *   Compute interval bounds:
        $$this\_tmin = \max(t\_sorted[i], near\_plane)$$
        $$this\_tmax = \min(t\_sorted[i + 1], far\_plane)$$
    *   If `this_tmin >= this_tmax`, skip this interval (degenerate) [S1, unofficial].

4.  **Voxel Traversal Setup**:
    *   Setup traversal for the current AABB using `setup_traversal(ray, this_tmin, this_tmax, eps, aabb, resolution, delta, tdist, step_index, current_index, final_index)` with `eps = 1e-6f` [S1, unofficial].
    *   Handle discontinuous traversal: If `!continuous`, adjust `t_last`:
        *   If `step_size <= 0.0f`, set `t_last = this_tmin` [S1, unofficial].
        *   Else, march forward using `dt = _calc_dt(t_last, cone_angle, step_size, 1e10f)` until `t_last + dt * 0.5f >= this_tmin` [S1, unofficial].

5.  **Sampling and Termination**:
    *   Perform voxel traversal within `[this_tmin, this_tmax]` using the calculated step size and cone angle.
    *   If `traverse_steps_limit` is reached, terminate early [S1, unofficial][S2, unofficial].
    *   Store intervals, samples, and termination planes based on flags [S2, unofficial].

    rays_d: torch.Tensor,
    binaries: torch.Tensor,

    far_planes: torch.Tensor = None,

    t_indices: torch.Tensor = None,
    hits: torch.Tensor = None,

    cone_angle: float = 0.0,
    traverse_steps_limit: int = -1,

    compute_intervals: bool = True,
    compute_samples: bool = True,
    compute_terminate_planes: bool = True
):
    """
    Traverses rays through multiple binary grids.
    Note: This is a simplified Python representation of the CUDA kernel logic.
    Actual implementation requires CUDA kernels for ray_aabb_intersect and voxel traversal.
    """
    n_rays = rays_o.shape[0]
    n_grids = binaries.shape[0]
    resx, resy, resz = binaries.shape[1], binaries.shape[2], binaries.shape[3]
    
    # 1. Initialization
    if rays_mask is None:
        rays_mask = torch.ones(n_rays, dtype=torch.bool, device=rays_o.device)
    if near_planes is None:
        near_planes = torch.zeros(n_rays, device=rays_o.device)
    if far_planes is None:
        far_planes = torch.full((n_rays,), float('inf'), device=rays_o.device)
        
    # 2. Pre-compute intersections if not provided
    if t_sorted is None or t_indices is None or hits is None:
        # Placeholder for ray_aabb_intersect CUDA call

        # For demonstration, assume dummy values
        t_mins = torch.zeros(n_rays, n_grids, device=rays_o.device)
        t_maxs = torch.ones(n_rays, n_grids, device=rays_o.device)
        hits = torch.ones(n_rays, n_grids, dtype=torch.bool, device=rays_o.device)
        
        # Concatenate and sort
        # t_mins shape: [n_rays, n_grids], t_maxs shape: [n_rays, n_grids]
        # Concatenate along last dim: [n_rays, n_grids * 2]
        t_combined = torch.cat([t_mins, t_maxs], dim=-1)

        # This is a simplified representation
        t_sorted, t_indices = torch.sort(t_combined, dim=-1)
        # t_indices values need to be mapped to grid IDs. 
        # In reality, t_indices stores the original index (0 to n_grids*2-1)
        # We need to map these back to grid IDs (0 to n_grids-1)
        # If index < n_grids, it's an entry (min), else exit (max)
        # The actual grid ID is index % n_grids
        grid_ids = t_indices % n_grids
        is_entering = t_indices < n_grids
        # Reconstruct t_indices to store grid IDs and entry/exit flag if needed
        # For simplicity, we assume t_indices stores the grid ID and we derive entry/exit from sorted order
        # In the source, t_indices maps each intersection to its grid ID.
        # The sorting is done on t values.
        
    # 3. Parallel Processing (Simulated for single ray for clarity)
    intervals = []
    samples = []
    terminated_t = torch.zeros(n_rays, device=rays_o.device)
    
    for r in range(n_rays):
        if not rays_mask[r]:
            continue
            
        # Get sorted intersections for this ray
        ray_t_sorted = t_sorted[r] # Shape [n_grids * 2]
        ray_t_indices = t_indices[r] # Shape [n_grids * 2]
        ray_near = near_planes[r]
        ray_far = far_planes[r]
        
        t_last = 0.0
        step_count = 0
        
        for i in range(0, len(ray_t_sorted), 2):
            if i + 1 >= len(ray_t_sorted):
                break
                
            t_min = ray_t_sorted[i]
            t_max = ray_t_sorted[i+1]
            
            # Compute interval bounds
            this_tmin = max(t_min, ray_near)
            this_tmax = min(t_max, ray_far)
            
            if this_tmin >= this_tmax:
                continue
                
            # Determine grid ID for this interval
            # The source says t_indices[i] maps to grid ID.
            # Assuming t_indices is sorted alongside t_sorted
            grid_id = ray_t_indices[i] % n_grids
            
            # Setup traversal
            # eps = 1e-6
            # aabb = aabbs[grid_id]
            # resolution = (resx, resy, resz)

                t_last = this_tmin

                # dt = _calc_dt(t_last, cone_angle, step_size, 1e10)

                    step_count += 1

## Subtopics

### [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md)
A hybrid technique using a low-resolution grid for culling and a high-resolution grid for precise hit testing in dense particle systems. It skips large empty regions by querying a coarser occupancy grid first.

## Operating characteristics
*   **Time Complexity**: Dominated by ray-AABB intersection tests ($O(n\_rays \times n\_grids)$) and voxel traversal within occupied intervals. Voxel traversal is proportional to the number of occupied voxels intersected by rays.
*   **Memory Complexity**: Requires storage for `binaries` ($O(n\_grids \times resx \times resy \times resz)$), `aabbs` ($O(n\_grids)$), and output structures (`intervals`, `samples`) which scale with the number of samples per ray. `over_allocate` can increase peak memory usage to avoid dynamic resizing [S1, unofficial][S2, unofficial].
*   **Performance**: Efficient for sparse volumes where large empty regions can be skipped via AABB culling. Performance degrades if rays intersect many small occupied grids or if the volume is dense.
*   **Strengths**: Handles multiple disjoint grids efficiently; supports adaptive step sizes via `cone_angle`; chunked memory layout handles variable-length outputs.
*   **Limitations**: Not differentiable to any inputs [S2, unofficial]. Overlapping grids require careful ordering as the first grid's occupancy overwrites the second's [S1, unofficial]. Discontinuous traversal requires careful alignment of `t_last` to avoid misaligned samples [S1, unofficial].

## Background
Multi-Grid Ray Traversal is a core component of the NerfAcc library, designed to accelerate NeRF rendering by efficiently sampling occupancy grids. It was introduced in the NerfAcc paper (Li et al., 2023) as part of a general NeRF acceleration toolbox [S1, unofficial]. It is widely used in modern NeRF implementations such as nerfstudio, SDFStudio, and threestudio [S1, unofficial].
