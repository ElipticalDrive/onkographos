# Multi-Grid Ray Traversal

Also called: Grid Traversal (Multi-Grid), Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal traverses rays through multiple binary occupancy grids (typically arranged as mipmaps or hierarchical levels) to generate ray intervals, sample positions, and termination planes [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the problem of efficiently sampling dense volumetric scenes by combining pre-computed ray-AABB intersections with voxel-level traversal, allowing rays to skip empty regions across multiple grid resolutions [S2, unofficial]. Unlike single-grid traversal, this method handles overlapping grids by prioritizing the first intersected grid and supports adaptive step sizing based on cone angles [S2, unofficial]. It builds on [Multi-level Grid Structures](6354-multi-level-grid-structures.md) by explicitly managing multiple grid levels and their intersection events [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `rays_o`: Ray origins, shape `[n_rays, 3]`, float [S2, unofficial][S3, unofficial].
    *   `rays_d`: Ray directions, shape `[n_rays, 3]`, normalized float [S2, unofficial][S3, unofficial].
    *   `binaries`: Binary occupancy grids, shape `[n_grids, resx, resy, resz]`, boolean [S2, unofficial][S3, unofficial]. All grids share the same resolution [S2, unofficial].
    *   `aabbs`: Axis-aligned bounding boxes for each grid, shape `[n_grids, 6]`, float, storing `{xmin, ymin, zmin, xmax, ymax, zmax}` [S1, unofficial][S3, unofficial].
    *   `rays_mask`: Optional boolean mask, shape `[n_rays]`, to skip specific rays [S2, unofficial][S3, unofficial].
    *   `near_planes`: Optional float tensor, shape `[n_rays]`, per-ray near plane distances [S3, unofficial].
    *   `far_planes`: Optional float tensor, shape `[n_rays]`, per-ray far plane distances [S3, unofficial].
    *   `t_sorted`: Optional float tensor, shape `[n_rays, n_grids * 2]`, pre-computed sorted intersection distances [S2, unofficial][S3, unofficial].
    *   `t_indices`: Optional int64 tensor, shape `[n_rays, n_grids * 2]`, pre-computed sorted grid indices for each intersection [S2, unofficial][S3, unofficial].
    *   `hits`: Optional boolean tensor, shape `[n_rays, n_grids]`, pre-computed hit flags [S2, unofficial][S3, unofficial].
    *   `step_size`: Optional float, default `1e-3` [S1, unofficial][S2, unofficial][S3, unofficial].
    *   `cone_angle`: Optional float, default `0.0` [S1, unofficial][S2, unofficial][S3, unofficial].
    *   `traverse_steps_limit`: Optional int, default `-1` (unlimited) [S1, unofficial][S2, unofficial][S3, unofficial].
    *   `over_allocate`: Optional bool, default `False` [S1, unofficial][S2, unofficial][S3, unofficial].
    *   `eps`: Epsilon for traversal setup, default `1e-6f` [S2, unofficial].
*   **Outputs:**
    *   `intervals`: Ray traversal intervals [S2, unofficial].
    *   `samples`: Sample positions within intervals [S2, unofficial].
    *   `terminated_t`: Termination plane distances, shape `[n_rays]` [S2, unofficial][S3, unofficial].

**Data Structures:**
*   **RaySpec:** Contains origins, directions, and near/far planes.
*   **PackedRaySegmentsSpec:** Stores traversal intervals and sample positions per ray, supporting chunked memory layouts via `chunk_cnts` (counts per chunk) and `chunk_starts` (start indices) [S2, unofficial].
*   **Intersection Data:** `t_sorted` and `t_indices` are concatenated from `t_mins` and `t_maxs` of ray-AABB intersections, then sorted [S2, unofficial][S3, unofficial].

**Parameters:**
*   `step_size`: Fixed step size for marching. If `<= 0.0`, records steps per voxel cell. If `> 0.0`, uses uniform or cone-based marching [S2, unofficial].
*   `cone_angle`: Controls linear step size increase with distance. `0.0` means uniform marching with `step_size` [S2, unofficial].
*   `traverse_steps_limit`: Maximum number of traversal steps per ray. Enables early termination [S2, unofficial].
*   `over_allocate`: If `True`, `traverse_steps_limit` must be set and `> 0` [S1, unofficial][S3, unofficial].

**Steps:**
1.  **Initialization:**
    *   Initialize `rays_mask` to all-ones boolean tensor `[n_rays]` if `None` [S3, unofficial].
    *   Initialize `near_planes` to zeros `[n_rays]` if `None` [S3, unofficial].
    *   Initialize `far_planes` to infinity `[n_rays]` if `None` [S3, unofficial].
    *   If `t_sorted`, `t_indices`, or `hits` are `None`, compute ray-AABB intersections using `ray_aabb_intersect(rays_o, rays_d, aabbs)` to get `t_mins`, `t_maxs`, and `hits` [S3, unofficial].
    *   Concatenate `t_mins` and `t_maxs` along the last dimension and sort them to get `t_sorted` and `t_indices` [S2, unofficial][S3, unofficial].
    *   Set `traverse_steps_limit` to `-1` if `None` [S3, unofficial].

2.  **Parallel Execution Setup:**
    *   Parallelize over rays using grid/block indices: `tid = blockIdx.x * blockDim.x + threadIdx.x` [S2, unofficial].
    *   Skip rays where `rays_mask[tid]` is false or `chunk_cnts[tid] == 0` on non-first passes [S2, unofficial].

3.  **Interval Processing:**
    *   For each ray `tid`, initialize ray spec with origins, directions, near/far planes [S2, unofficial].
    *   Set base indices for intersections: `base_hits = tid * n_grids`, `base_t_sorted = tid * n_grids * 2` [S2, unofficial].
    *   Loop over intersections `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1`:
        *   Determine `is_entering = t_indices[i] < n_grids` [S2, unofficial].
        *   Determine `level = t_indices[i] % n_grids` [S2, unofficial].
        *   Compute interval bounds: `this_tmin = fmaxf(t_sorted[i], near_plane[tid])` and `this_tmax = fminf(t_sorted[i + 1], far_plane[tid])` [S2, unofficial].
        *   Skip if `this_tmin >= this_tmax` (invalid/degenerate interval) [S2, unofficial].

4.  **Step Alignment (Discontinuous Traversal):**
    *   If `!continuous`, adjust `t_last`:
        *   If `step_size <= 0.0f`, set `t_last = this_tmin` [S2, unofficial].
        *   Else, march forward using `dt = _calc_dt(t_last, cone_angle, step_size, 1e10f)` until `t_last + dt * 0.5f >= this_tmin` [S2, unofficial].

5.  **Voxel Traversal Setup:**
    *   Setup traversal for the current AABB using `setup_traversal(ray, this_tmin, this_tmax, eps, aabb, resolution, delta, tdist, step_index, current_index, final_index)` [S2, unofficial].
    *   `aabb` is the bounding box for the grid identified by `level` [S2, unofficial].

6.  **Ray Marching:**
    *   Traverse the voxel grid from `this_tmin` to `this_tmax` using the configured step size and cone angle [S2, unofficial].
    *   Record samples and intervals.
    *   Terminate if `traverse_steps_limit` is reached [S2, unofficial].

7.  **Output Generation:**
    *   Call the C++ kernel `traverse_grids` with prepared inputs, setting `compute_intervals`, `compute_samples`, and `compute_terminate_planes` to `True` [S3, unofficial].
    *   Return `RayIntervals`, `RaySamples`, and termination planes [S2, unofficial].

## Subtopics

### [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md)
A hybrid technique using a low-resolution grid for culling and a high-resolution grid for precise hit testing in particle systems. It skips empty regions by querying a coarser occupancy grid first, switching to high-resolution traversal only when occupied cells are detected.

### [Multi-Grid Ray Traversal with Adaptive Step Size](14341-multi-grid-ray-traversal-with-adaptive-step-size.md)
A CUDA kernel that traverses rays through multiple AABB voxel grids, handling overlapping grids by priority and outputting traversal intervals with adaptive step sizing based on cone angle. It explicitly manages multiple hierarchical grid levels with sorted intersection events, ensuring the first grid's occupancy status takes precedence in overlapping regions.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of rays and the number of grid levels intersected. Sorting intersections is $O(N \log N)$ where $N$ is the number of grids per ray [S2, unofficial].
*   **Memory Complexity:** Proportional to the number of rays and grids. Over-allocation can increase memory usage but avoids dynamic resizing [S1, unofficial][S3, unofficial].
*   **Measured Performance:** Used in NeRF training pipelines (e.g., TensoRF, K-Planes) to accelerate sampling on NeRF-Synthetic and Tanks&Temple datasets [S2, unofficial].
*   **Strengths:** Efficiently handles multiple grid resolutions; skips empty space; supports adaptive step sizes; parallelizable on GPU [S2, unofficial].
*   **Limitations:** Not differentiable to inputs [S3, unofficial]; overlapping grids require careful ordering (first grid takes precedence) [S2, unofficial]; degenerate intervals must be handled [S2, unofficial].
*   **When to use:** Dense volumetric scenes with hierarchical occupancy data; NeRF training acceleration [S2, unofficial].
*   **When not to use:** Scenes with few grid levels; when differentiability is required [S3, unofficial].

## Background
Multi-Grid Ray Traversal is part of the NerfAcc library, developed by Ruilong Li, Hang Gao, Matthew Tancik, and Angjoo Kanazawa [S2, unofficial]. It was introduced in the paper "NerfAcc: Efficient Sampling Accelerates NeRFs" (arXiv:2305.04966, 2023) [S2, unofficial]. The method is used in various NeRF implementations, including TensoRF, K-Planes, and BARF, to accelerate training by reducing the number of samples needed [S2, unofficial].
