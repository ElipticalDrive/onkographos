# Multi-Grid Ray Traversal

Also called: Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal extends single-grid traversal by processing rays against a collection of disjoint or overlapping binary occupancy grids to generate valid sampling intervals and sample positions. It solves the problem of efficiently determining where a ray intersects a complex, potentially fragmented scene represented by multiple separate voxel structures, such as those used in dynamic NeRFs or hierarchical occupancy estimators. Unlike single-grid methods, it pre-computes ray-AABB intersections to sort entry and exit points across all grids, handling overlapping regions by prioritizing the first grid's occupancy status [S1, unofficial].

## How it works
The method operates in two phases: pre-computation of grid intersections and parallel traversal of rays through the sorted intervals. It relies on the parent [Ray-grid traversal](17-ray-grid-traversal.md) for the actual voxel stepping logic within each grid's AABB.

### Inputs and Outputs
**Inputs:**
*   `rays_o`: `[n_rays, 3]` float array of ray origins.
*   `rays_d`: `[n_rays, 3]` float array of normalized ray directions.
*   `binaries`: `[n_grids, resx, resy, resz]` boolean array representing voxel occupancy. All grids share the same resolution.
*   `aabbs`: `[n_grids, 6]` float array storing axis-aligned bounding boxes per grid (min/max x, y, z).
*   `near_plane`: Optional float or tensor. Default is 0.0.
*   `far_plane`: Optional float or tensor. Default is infinity.
*   `step_size`: Optional float. Default is $10^{-3}$. Controls the marching step size.
*   `cone_angle`: Optional float. Default is 0.0. Controls linear step size increase with distance.
*   `traverse_steps_limit`: Optional int. Default is -1 (unlimited). Maximum number of traversal steps per ray.
*   `rays_mask`: Optional BoolTensor of shape `[n_rays]`. Default is all ones. Skips specific rays.
*   `t_sorted`: Optional Tensor of shape `[n_rays, n_grids * 2]`. Pre-computed sorted t values.
*   `t_indices`: Optional Tensor of shape `[n_rays, n_grids * 2]`. Pre-computed sorted t indices mapping to grid IDs.
*   `hits`: Optional Tensor of shape `[n_rays, n_grids]`. Pre-computed hit flags.

**Outputs:**
*   `intervals`: `RayIntervals` object containing traversal intervals per ray.
*   `samples`: `RaySamples` object containing sample positions within each interval.
*   `terminated_t`: Tensor of shape `[n_rays]` containing terminated t values.

### Data Structures
The core data structure for managing multiple grids is the sorted intersection list. For each ray, intersections with all $N$ grids are collected, sorted by distance $t$, and paired with the grid index.

*   `t_sorted`: `[n_rays, 2 * n_grids]` float array. Stores the sorted intersection distances $t$.
*   `t_indices`: `[n_rays, 2 * n_grids]` int64 array. Stores the grid ID corresponding to each entry/exit point.
*   `chunk_cnts`: `[n_rays]` int array. Stores the number of valid intervals per ray, used for packed memory layout.
*   `chunk_starts`: `[n_rays]` int array. Stores the starting index in the packed interval buffer for each ray.

### Algorithm Steps

1.  **Pre-compute Intersections (Optional/External):**
    If `t_sorted` and `t_indices` are not provided, compute ray-AABB intersections for each grid. For each ray $r$ and grid $g$, determine entry $t_{entry}$ and exit $t_{exit}$. Collect all valid intervals where $t_{entry} < t_{exit}$. Sort these intervals by $t_{entry}$ to populate `t_sorted` and `t_indices`.
    *   *Note:* If grids overlap, the ordering matters. The implementation assumes the first grid's occupancy overwrites subsequent ones in overlapping regions [S1, unofficial].

2.  **Parallel Initialization:**
    Launch a CUDA kernel with thread ID `tid = blockIdx.x * blockDim.x + threadIdx.x`.
    *   If `rays_mask[tid]` is false, skip.
    *   If `first_pass` is false and `chunk_cnts[tid] == 0`, skip (optimization for subsequent passes).
    *   Initialize `base_hits = tid * n_grids` and `base_t_sorted = tid * n_grids * 2`.
    *   Initialize `t_last = near_plane` (or 0.0 if not provided).

3.  **Interval Processing Loop:**
    Iterate through the sorted intersections for the current ray. The loop processes pairs of entry/exit points.
    *   Let `n_intersections = n_grids * 2`.
    *   For `i` from `0` to `n_intersections - 1` (stepping by 2 for pairs, or processing sequentially if using a state machine):
        *   Determine if the current intersection is an entry or exit: `is_entering = (t_indices[base_t_sorted + i] < n_grids)`. *Note: The source implies a specific encoding where indices $< n_grids$ are entries and $\ge n_grids$ are exits, or similar logic based on `t_indices` values. A more robust interpretation from the source snippet `is_entering = t_indices[i] < n_grids` suggests the index itself encodes the type.*
        *   Actually, the source snippet says: `is_entering = t_indices[i] < n_grids`. This implies `t_indices` stores the grid ID, and perhaps a separate flag or the parity of the loop index determines entry/exit. However, standard ray-AABB intersection yields pairs. Let's follow the source's explicit logic:
        *   `level = t_indices[base_t_sorted + i] % n_grids`.
        *   Compute interval bounds:
            $$
            \text{this\_tmin} = \max(\text{t\_sorted}[base\_t\_sorted + i], \text{near\_plane})
            $$
            $$
            \text{this\_tmax} = \min(\text{t\_sorted}[base\_t\_sorted + i + 1], \text{far\_plane})
            $$
            *   *Correction:* The source snippet iterates `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1`. It calculates `this_tmin` and `this_tmax` using `i` and `i+1`. This implies `t_sorted` contains interleaved or paired entries. If `t_sorted` is fully sorted, we must pair them correctly. The source logic `this_tmin = fmaxf(t_sorted[i], near_plane)` and `this_tmax = fminf(t_sorted[i+1], far_plane)` suggests processing adjacent pairs in the sorted list.
        *   Skip if `this_tmin >= this_tmax` (degenerate interval) [S1, unofficial].

4.  **Discontinuity Handling (Marching Alignment):**
    If `continuous` is false (or based on `step_size` logic):
    *   If `step_size <= 0.0`, set `t_last = this_tmin`.
    *   If `step_size > 0.0`, march forward from `t_last` using `dt = _calc_dt(t_last, cone_angle, step_size, 1e10f)` until `t_last + dt * 0.5f >= this_tmin`.
    *   This ensures samples are aligned with the grid traversal start point [S1, unofficial].

5.  **Voxel Traversal:**
    Call `setup_traversal` for the current grid `level` within the interval `[this_tmin, this_tmax]`.
    *   Parameters: `ray`, `this_tmin`, `this_tmax`, `eps` ($10^{-6}$), `aabb[level]`, `resolution`, `delta`, `tdist`, `step_index`, `current_index`, `final_index`.
    *   This step uses the parent [Ray-grid traversal](17-ray-grid-traversal.md) algorithm to step through voxels.
    *   Record samples and intervals.

6.  **Termination:**
    *   If `traverse_steps_limit` is set and the number of steps exceeds it, terminate the ray.
    *   Return `terminated_t` for the ray.

### Pseudocode

```python
import math

def traverse_grids_kernel(rays_o, rays_d, binaries, aabbs, t_sorted, t_indices, 
                          n_grids, near_plane, far_plane, step_size, cone_angle, 
                          traverse_steps_limit, rays_mask, first_pass, eps):
    """
    Parallel kernel for multi-grid ray traversal.
    Assumes CUDA-like parallel execution with global thread ID `tid`.
    """
    tid = get_global_thread_id()
    
    # Skip masked rays
    if not rays_mask[tid]:
        return

    # Skip rays with no chunks in non-first passes
    if not first_pass and chunk_cnts[tid] == 0:
        return

    base_t_sorted = tid * n_grids * 2
    t_last = near_plane
    
    # Initialize output buffers for this ray
    intervals = []
    samples = []
    step_count = 0
    
    # Process sorted intersections
    # Note: t_sorted and t_indices are assumed to be pre-sorted per ray
    # The source implies processing pairs (i, i+1) from the sorted list
    for i in range(0, n_grids * 2, 2):
        idx = base_t_sorted + i
        
        # Determine grid ID
        grid_id = t_indices[idx]
        
        # Calculate interval bounds
        t_min = max(t_sorted[idx], near_plane)
        t_max = min(t_sorted[idx + 1], far_plane)
        
        # Skip degenerate intervals
        if t_min >= t_max:
            continue
            
        # Handle discontinuity/marching alignment
        if step_size <= 0.0:
            t_last = t_min
        else:
            # March forward to align with t_min
            while t_last + calc_dt(t_last, cone_angle, step_size, 1e10) * 0.5 < t_min:
                t_last += calc_dt(t_last, cone_angle, step_size, 1e10)
        
        # Setup traversal for the specific grid
        aabb = aabbs[grid_id]
        resolution = binaries.shape[1:] # Assuming uniform resolution
        
        # Perform voxel traversal within [t_min, t_max] for grid_id
        # This calls the parent Ray-grid traversal logic
        voxel_traversal_result = setup_traversal(
            ray_o=rays_o[tid],
            ray_d=rays_d[tid],
            t_min=t_min,
            t_max=t_max,
            eps=eps,
            aabb=aabb,
            resolution=resolution,
            step_size=step_size,
            cone_angle=cone_angle,
            t_last=t_last
        )
        
        # Append results
        intervals.append(voxel_traversal_result.intervals)
        samples.append(voxel_traversal_result.samples)
        step_count += voxel_traversal_result.num_steps
        
        # Update t_last for next interval if needed
        t_last = t_max
        
        # Check termination
        if traverse_steps_limit > 0 and step_count >= traverse_steps_limit:
            break
            
    # Store results in packed memory
    store_intervals(tid, intervals)
    store_samples(tid, samples)
    chunk_cnts[tid] = len(intervals)
```

### Edge Cases and Pitfalls
*   **Overlapping Grids:** The ordering of grids in `t_sorted` determines precedence. If two grids overlap, the first one encountered in the sorted list is used, and subsequent overlaps are ignored or overwritten [S1, unofficial].
*   **Degenerate Intervals:** If `this_tmin >= this_tmax`, the interval is skipped. This can happen if a ray is tangent to a grid or if near/far planes clip the intersection to a point [S1, unofficial].
*   **Discontinuous Traversal:** When entering a new grid interval, `t_last` must be reset or advanced to `this_tmin` to ensure sample alignment. Failure to do so results in misaligned samples [S1, unofficial].
*   **Precision:** An epsilon `eps = 1e-6` is used in traversal setup to handle floating-point inaccuracies at boundaries [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N_{rays} \cdot N_{grids} \log N_{grids})$ for sorting intersections, plus $O(N_{rays} \cdot N_{voxels\_hit})$ for traversal. The sorting step is dominant if $N_{grids}$ is large.
*   **Memory Complexity:** $O(N_{rays} \cdot N_{grids})$ for storing sorted intersections and hit flags.
*   **Performance:** Highly parallelizable on GPU. Performance scales with the number of rays and grids. Efficient for scenes with many small, disjoint objects represented as separate grids.
*   **Strengths:** Handles complex, fragmented scenes efficiently. Pre-computation of intersections allows for flexible grid management.
*   **Limitations:** Overlapping grids require careful ordering. Memory usage increases linearly with the number of grids.

## Background
Multi-Grid Ray Traversal is a technique used in modern NeRF acceleration libraries like NerfAcc to handle dynamic scenes and hierarchical occupancy grids. It was popularized in the context of efficient sampling for Neural Radiance Fields, allowing for the management of multiple occupancy grids that represent different parts of a scene or different time steps in dynamic NeRFs [S1, unofficial].
