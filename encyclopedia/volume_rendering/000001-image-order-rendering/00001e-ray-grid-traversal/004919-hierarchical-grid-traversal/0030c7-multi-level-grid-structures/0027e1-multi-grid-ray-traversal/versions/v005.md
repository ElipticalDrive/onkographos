# Multi-Grid Ray Traversal

Also called: Grid Traversal (Multi-Grid), Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal traverses rays through multiple binary occupancy grids to generate ray intervals, sample positions, and termination planes [S1, S2, unofficial]. It solves the problem of efficiently sampling dense volumetric data by using pre-computed ray-AABB intersections to determine which grids are hit, sorting these entry/exit points, and then performing voxel traversal within the valid intervals [S1, S2, unofficial]. It sets itself apart from single-grid traversal by handling disjoint or hierarchical sets of grids in a unified pass, and from pointer-based hierarchical structures by relying on flat, contiguous binary tensors [S1, S2, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   `rays_o`: Ray origins, shape `[n_rays, 3]` [S2, unofficial].
    *   `rays_d`: Ray directions, shape `[n_rays, 3]` [S2, unofficial].
    *   `binaries`: Binary occupancy grids, shape `[n_grids, resx, resy, resz]` [S1, S2, unofficial]. All grids share the same resolution [S1, unofficial].
    *   `aabbs`: Axis-aligned bounding boxes for the grids, shape `[n_grids, 6]` (min/max x, y, z) [S1, S2, unofficial].
    *   `rays_mask`: Optional boolean mask, shape `[n_rays]`, to skip specific rays [S1, S2, unofficial].
    *   `near_planes`: Optional per-ray near plane distances, shape `[n_rays]` [S1, S2, unofficial].
    *   `far_planes`: Optional per-ray far plane distances, shape `[n_rays]` [S1, S2, unofficial].
    *   `t_sorted`: Optional pre-computed sorted intersection times, shape `[n_rays, n_grids * 2]` [S1, S2, unofficial].
    *   `t_indices`: Optional pre-computed sorted grid indices, shape `[n_rays, n_grids * 2]` [S1, S2, unofficial].
    *   `hits`: Optional pre-computed hit flags, shape `[n_rays, n_grids]` [S1, S2, unofficial].
    *   `step_size`: Fixed step size for sampling. Default `1e-3` [S1, S2, unofficial].
    *   `cone_angle`: Cone angle for linearly-increased step size. `0.0` means constant step size. Default `0.0` [S1, S2, unofficial].
    *   `traverse_steps_limit`: Maximum number of traversal steps per ray. Default `-1` (unlimited) [S1, S2, unofficial].
    *   `over_allocate`: Whether to over-allocate memory for outputs. If `True`, `traverse_steps_limit` must be set > 0 [S1, S2, unofficial].
    *   `compute_intervals`, `compute_samples`, `compute_terminate_planes`: Flags to enable output generation [S2, unofficial].
*   **Outputs**:
    *   `intervals`: Ray segment intervals [S1, S2, unofficial].
    *   `samples`: Sample positions within intervals [S1, S2, unofficial].
    *   `terminated_t`: Termination planes per ray, shape `[n_rays]` [S1, S2, unofficial].

**Data Structures**
*   `t_sorted`: Float array `[n_rays, n_grids * 2]` storing sorted ray-grid intersection distances [S1, unofficial].
*   `t_indices`: Integer array `[n_rays, n_grids * 2]` mapping each intersection to its grid ID (0-indexed) [S1, unofficial].
*   `hits`: Boolean array `[n_rays, n_grids]` indicating whether each ray hits each grid [S1, unofficial].
*   `binaries`: Boolean tensor `[n_grids, resx, resy, resz]` representing voxel occupancy [S1, S2, unofficial].

**Algorithm Steps**
1.  **Initialization**:
    *   Initialize `rays_mask` to all-ones if `None` [S2, unofficial].
    *   Initialize `near_planes` to zeros and `far_planes` to infinity if `None` [S1, S2, unofficial].
    *   Initialize `traverse_steps_limit` to `-1` if `None` [S2, unofficial].
    *   If `t_sorted`, `t_indices`, or `hits` are `None`, compute ray-AABB intersections using `ray_aabb_intersect(rays_o, rays_d, aabbs)` to get `t_mins`, `t_maxs`, and `hits` [S2, unofficial].
    *   Concatenate `t_mins` and `t_maxs` along the last dimension and sort them to get `t_sorted` and `t_indices` [S1, S2, unofficial].

2.  **Parallel Execution Setup**:
    *   Parallelize over rays using grid/block indices: `tid = blockIdx.x * blockDim.x + threadIdx.x` [S1, unofficial].
    *   Skip rays where `rays_mask` is false or `chunk_cnts[tid] == 0` on non-first passes [S1, unofficial].

3.  **Interval Processing**:
    *   Loop over intersections `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1`, where `base_t_sorted = tid * n_grids * 2` [S1, unofficial].
    *   Determine `is_entering = t_indices[i] < n_grids` and `level = t_indices[i] % n_grids` [S1, unofficial].
    *   Compute interval bounds: `this_tmin = fmaxf(t_sorted[i], near_plane)` and `this_tmax = fminf(t_sorted[i + 1], far_plane)` [S1, unofficial].
    *   Skip if `this_tmin >= this_tmax` to prevent degenerate marching [S1, unofficial].

4.  **Discontinuous Traversal Handling**:
    *   If `!continuous`, adjust `t_last`:
        *   If `step_size <= 0.0f`, set `t_last = this_tmin` [S1, unofficial].
        *   Else, march forward using `dt = _calc_dt(t_last, cone_angle, step_size, 1e10f)` until `t_last + dt * 0.5f >= this_tmin` [S1, unofficial].

5.  **Voxel Traversal Setup**:
    *   Setup traversal for the current AABB using `setup_traversal(ray, this_tmin, this_tmax, eps, aabb, resolution, delta, tdist, step_index, current_index, final_index)` with `eps = 1e-6f` [S1, unofficial].
    *   Perform voxel traversal within the grid defined by `binaries` using the calculated step size and cone angle [S1, S2, unofficial].
    *   Record samples and intervals. Stop if `traverse_steps_limit` is reached [S1, S2, unofficial].

6.  **Output Generation**:
    *   Return `RayIntervals`, `RaySamples`, and termination planes based on the computed flags [S1, S2, unofficial].

    if t_sorted is None or t_indices is None or hits is None:

    # 3. Process Intervals

    t_last = 0.0 # Assume initialized from previous pass or 0

## Subtopics

### [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md)
A hybrid technique using a low-resolution grid for culling and a high-resolution grid for precise hit testing in particle systems. It skips large empty regions by querying the coarser grid first.

## Operating characteristics
*   **Time Complexity**: Linear with respect to the number of rays and the number of grids intersected. Sorting intersections is $O(N \log N)$ per ray where $N$ is the number of grids. Voxel traversal is proportional to the number of occupied voxels along the ray.
*   **Memory Complexity**: $O(N_{rays} \cdot N_{grids})$ for storing intersection data (`t_sorted`, `t_indices`, `hits`). Output memory depends on `traverse_steps_limit` and `over_allocate`.
*   **Performance**: Highly efficient on GPUs due to parallelization over rays and contiguous memory access for binary grids [S1, S2, unofficial].
*   **Strengths**: Handles multiple disjoint grids efficiently; avoids pointer chasing; supports adaptive step sizes via `cone_angle` [S1, S2, unofficial].
*   **Limitations**: Not differentiable to any inputs [S2, unofficial]. Overlapping grids require careful ordering as the first grid's occupancy overwrites the second's [S1, unofficial].
*   **When to use**: When rendering scenes with multiple distinct volumetric regions or hierarchical grids stored as flat binary tensors.
*   **When not to use**: When differentiability is required for training [S2, unofficial].

## Background
Multi-Grid Ray Traversal is implemented in the `nerfacc` library, an efficient sampling acceleration toolbox for NeRFs [S1, unofficial]. It was developed by Ruilong Li, Hang Gao, Matthew Tancik, and Angjoo Kanazawa and published in 2023 [S1, unofficial]. It is used in various NeRF acceleration pipelines, including TensoRF, K-Planes, and TiNeuVox, often in conjunction with occupancy grid estimators [S1, unofficial].
