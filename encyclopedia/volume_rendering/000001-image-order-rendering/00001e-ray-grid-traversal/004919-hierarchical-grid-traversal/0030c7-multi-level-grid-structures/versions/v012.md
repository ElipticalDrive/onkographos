# Multi-level Grid Structures


## Overview
Multi-level Grid Structures organize spatial data into a hierarchy of uniform grids to efficiently skip empty regions and adapt resolution to local density, solving the memory and traversal overhead problems of flat uniform grids in sparse scenes [G]. It sets itself apart from sibling methods like [KD-Tree Partitioned Volume Rendering](1966-kd-tree-partitioned-volume-rendering.md) by maintaining the regular memory access patterns of grid structures while providing hierarchical empty-space skipping [G].

## Shared principles
All methods in this family share the following mechanism:
1. **Hierarchical Uniform Subdivision:** The spatial domain is divided into a coarse grid (Level 0). Occupied cells in the coarse grid point to finer sub-grids (Level 1, Level 2, etc.). Empty cells point to null or are skipped entirely [G].
2. **Ray-Grid Intersection:** Rays are tested against the Axis-Aligned Bounding Boxes (AABBs) of the grid cells at each level. If a ray does not intersect a coarse cell, the entire sub-grid is skipped [G].
3. **Traversal Continuity:** Traversal typically reuses decision variables (DDA steps) between levels to maintain coherence, or computes new intervals based on sorted intersection events [G].
4. **Memory Layout:** Data is often stored in flat arrays or linked lists of cells, with occupancy flags or pointers indicating the presence of child grids [S1, unofficial].

## Subtopics

### [Multi-Level Array Grid](3329-multi-level-array-grid.md)
A fixed-depth hierarchical spatial acceleration structure that recursively subdivides the scene bounding box into uniform grids based on item density. It is distinguished from siblings like the Multi-Level Hashed Grid by its use of dense array indexing for child nodes rather than hash tables, making it memory-conservative. Choose it when memory efficiency is prioritized over handling extreme sparsity.

### [Multi-Grid Ray Traversal](4142-multi-grid-ray-traversal.md)
Traverses rays through multiple binary occupancy grids to generate ray intervals, sample positions, and termination planes. It explicitly manages intersection events across distinct grid instances rather than hierarchical pointers, handling overlapping bounding boxes where the first grid's occupancy status takes precedence. Choose it for efficiently sampling hierarchical or overlapping volumetric structures.

### [Two-Level Grids for Ray Tracing on GPUs](4245-two-level-grids-for-ray-tracing-on-gpus.md)
A fixed-depth hierarchical acceleration structure designed to handle non-uniform primitive distributions in dynamic scenes on GPUs. It uses a sparse top-level grid where each occupied cell points to a finer sub-grid of arbitrary resolution. Choose it for GPU-accelerated ray tracing of triangle meshes with sparse regions, avoiding the "teapot in a stadium" problem.

### [Macrocell Grid Traversal](5207-macrocell-grid-traversal.md)
A hierarchical acceleration technique that superimposes a coarse grid over a base uniform fine grid to skip empty regions. It uses a fixed, regular downsampling factor to create a simple boolean occupancy map, allowing trivial build times and efficient reuse of frustum setup calculations. Choose it for large, sparse uniform grids where traversal overhead is a concern.

### [Multi-resolution grids](12782-multi-resolution-grids.md)
A recursive hierarchical subdivision algorithm that integrates regular and adaptive spatial subdivision methods. It uses a top-down build strategy where internal voxels maintain their own local sub-grids, enabling efficient traversal through deep recursion when paired with a hash-table indexing strategy. Choose it for scenes containing both large, regularly distributed objects and small, dense clusters.

### [Sparse Multi-Scale Grid](21086-sparse-multi-scale-grid.md)
A volume rendering and projection algorithm for SPH data that assigns particles to a hierarchy of grid levels based on their kernel smoothing length, deposits onto coarser grids, and collapses the hierarchy coarse-to-fine via upsampling to bound per-particle cost. Choose it for SPH data visualization.

### [Hypertree Grid Construction](21914-hypertree-grid-construction.md)
A preprocessing step to convert unstructured or structured mesh data into a native hypertree grid format for efficient visualization. Choose it when preparing non-grid mesh data for hierarchical traversal.

### Hierarchical Grid (hgridf) Renderer
#### definition
- [S1, unofficial] A renderer for hierarchical grids (hgridf) that combines primitive generation and rendering in a single pass, updating only 'dirty' cells to support interactive editing.
#### step
- [S1, unofficial] Traverse the top-level grid and visit each grid-cell unless it is empty.
- [S1, unofficial] Check if the current grid-cell is 'dirty' (voxels have changed since the last visit).
- [S1, unofficial] If dirty, use the associated point or polygon engine to regenerate the local isosurface representation for that cell.
- [S1, unofficial] Mark the cell as 'clean' after regeneration.
#### parameter
- [S1, unofficial] The hierarchical grid uses a top-level N×N×N grid and sub-grids of size M×M×M, where M=16.

## Background
The concept of hierarchical grids for volume rendering and ray tracing originated in the early 1990s to address the memory and performance limitations of uniform grids for large datasets [G]. The "hgridf" renderer, described in *Hardware Accelerated Point Rendering of Isosurfaces* (2003), popularized the use of a top-level N×N×N grid with M×M×M sub-grids (typically M=16) to save space and provide constant-time access compared to octrees [S1, unofficial]. The term "hgrid" refers to this specific two-level structure where empty top-level cells are null, and occupied cells contain sub-grids [S1, unofficial].
