# Multi-resolution grids

Also called: Hierarchical voxel grids, JW89, Jevans and Wyvill method

## Overview
Multi-resolution grids is a recursive hierarchical subdivision algorithm for grids proposed by Jevans and Wyvill [S1][S2, unofficial] that integrates regular and adaptive spatial subdivision methods. It solves the problem of efficiently ray tracing scenes containing both large, regularly distributed objects and small, dense objects by allowing variable resolution across the spatial domain [S1][S2, unofficial]. It sets itself apart from siblings like [Multi-Level Array Grid](3329-multi-level-array-grid.md) by using a top-down build approach with hash-table indexed internal nodes rather than fixed-array bricks, and differs from [Multi-Grid Ray Traversal](4142-multi-grid-ray-traversal.md) by its specific adaptive voxel resolution strategies [S1][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of geometric primitives (e.g., polygons) and a bounding box covering the scene.
*   **Output:** A hierarchical grid structure (tree) where leaf nodes contain primitive lists and internal nodes contain child grids.

**Data Structures:**
The structure consists of two kinds of voxels [S1][S2, unofficial]:
1.  **Leaf Voxel:** Contains a list of objects (primitives) inside that voxel.
2.  **Internal Voxel:** Maintains a voxel grid subdivision. To support deep recursion, non-empty internal voxels are maintained using a hash table [S1][S2, unofficial]. This indexing strategy is critical; without it, deep levels of recursion are not feasible due to memory overhead [S1][S2, unofficial].

**Build Methods:**
The build approach is top-down [S1][S2, unofficial]. All primitives are initially inserted into a single root voxel. The algorithm then recursively subdivides internal voxels based on one of the following criteria [S1][S2, unofficial]:
1.  **Octree-like:** Setting the size of voxel grids to $2 \times 2 \times 2$ on a side.
2.  **Maximum Depth:** Setting a maximum depth of the subdivision tree.
3.  **Constant Resolution:** Fixing the resolution of the voxel subgrids to a constant value.
4.  **Variable (Adaptive) Resolution:** Adjusting resolution based on local density.

**Parameters:**
Parameters controlling the coarseness of the voxel grid, depth of adaptive subdivision trees, and maximum number of polygons per voxel are tailored to the scene [S1][S2, unofficial].

**Subtopics:**
*   **Octree-like Subdivision:** Uses $2 \times 2 \times 2$ child grids. Best for uniform density. Link to [Multi-Level Array Grid](3329-multi-level-array-grid.md) for comparison on fixed-size blocks.

## Operating characteristics
*   **Time Complexity:** Build time is higher than bottom-up strategies due to the top-down recursive nature and hash table management [S1][S2, unofficial]. Traversal time is efficient for mixed-scale scenes.
*   **Memory Complexity:** The use of hash tables for internal nodes allows sparse storage, but deep recursion requires careful indexing to avoid excessive overhead [S1][S2, unofficial].
*   **Strengths:** Efficiently handles scenes with both large regular objects and small dense clusters [S1][S2, unofficial]. Reduces memory accesses by skipping empty subtrees.
*   **Limitations:** High build cost. Traversal algorithm is unsuited for GPU computation due to branching and irregular memory access patterns; CPUs are more suitable [S2, unofficial].
*   **When to use:** CPU-based ray tracing of complex scenes with varying object density.
*   **When not to use:** GPU ray tracing or scenes requiring very fast build times.

## Background
The method was proposed by Jevans and Wyvill in 1989 [JW89]. It integrates regular and adaptive spatial subdivision methods to allow efficient ray tracing of images consisting of large regularly distributed objects and small dense objects [S1][S2, unofficial]. The survey notes that this approach has a greater build cost against general bottom-up strategies [S1][S2, unofficial].
