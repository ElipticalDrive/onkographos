# Dynamic MLP Maps with Empty Space Skipping

Also called: Dynamic MLP Maps

## Overview
Dynamic MLP Maps with Empty Space Skipping is a rendering technique for volumetric videos that combines multi-level hash tables with 2D CNN-generated MLP maps to achieve real-time performance [S1, unofficial]. It solves the problem of efficiently rendering dynamic volumetric content by using an occupancy volume to skip empty space during ray traversal [S1, unofficial]. Unlike [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) which relies on per-frame models, this method shares parameters across frames via CNN-predicted maps, significantly reducing storage and training time [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera rays $\mathbf{r}$, scene bounds, pre-computed occupancy volume, multi-level hash tables, and a 2D CNN decoder [S1, unofficial].
*   **Outputs:** Final predicted color $\tilde{C}(\mathbf{r})$ for each pixel [S1, unofficial].

**Data Structures:**
1.  **Occupancy Volume:** A 3D grid with resolution $24 \times 24 \times 48$ per video frame [S1, unofficial]. Each cell indicates if a region is occupied [S1, unofficial].
2.  **Multi-level Hash Tables:** Stores high-dimensional feature vectors for query points [S1, unofficial].
3.  **MLP Maps:** 2D parameter maps predicted by a 2D CNN decoder, representing three axis-aligned orthogonal projections of the volume [S1, unofficial].

**Numbered Steps:**

1.  **Occupancy Volume Construction (Pre-computation):**
    *   Divide the volume into cells.
    *   For each cell, create a $5 \times 5 \times 5$ subgrid [S1, unofficial].
    *   Calculate the density $\sigma$ for each subgrid point [S1, unofficial].
    *   Mark the volume cell as occupied if any subgrid point has density above threshold $\tau_1 = 5$ [S1, unofficial].

2.  **Training Sampling:**
    *   Uniformly sample 64 query locations along each camera ray within the scene bound [S1, unofficial].
    *   Do not use hierarchical sampling [S1, unofficial].

3.  **Feature Embedding:**
    *   For each query point, embed it into a high-dimensional feature vector using the multi-level hash tables [S1, unofficial].

4.  **Parameter Retrieval:**
    *   Project the query point onto three axis-aligned orthogonal MLP maps predicted by the 2D CNN decoder [S1, unofficial].
    *   Retrieve the corresponding MLP parameters from these maps [S1, unofficial].

5.  **MLP Evaluation:**
    *   Feed the embedded feature vector into an MLP network using the retrieved parameters to predict color $\mathbf{c}_i$ and density $\sigma_i$ [S1, unofficial].
    *   Evaluate multiple MLP networks efficiently using a custom PyTorch layer based on MAGMA, following KiloNeRF [S1, unofficial].

6.  **Result Combination:**
    *   Combine predictions from each of the three MLP maps via elementwise summation [S1, unofficial].

7.  **Inference Sampling (Empty Space Skipping):**
    *   Set sampling step size $\delta_i$ to $1/256$th of the diagonal distance of the scene bound [S1, unofficial].
    *   Sample points only in occupied voxels from the pre-computed occupancy volume [S1, unofficial].

8.  **Inference Filtering:**
    *   Compute density $\sigma_i$, accumulated transmittance $T_i$, and composition weight $\omega_i$ [S1, unofficial].
    *   Filter sampling points for color evaluation if $\omega_i < \tau_2$, where $\tau_2 = 10^{-3}$ [S1, unofficial].

9.  **Inference Rendering:**
    *   Predict colors and densities as in training [S1, unofficial].
    *   Compute final predicted color via volume rendering using Eq. 1 [S1, unofficial].

**Formulas:**

Differentiable volume rendering equation [S1, unofficial]:
$$
\tilde{C}(\mathbf{r}) = \sum_{i=1}^M \omega_i \mathbf{c}_i
$$
where
$$
\omega_i = T_i(1 - \exp(-\sigma_i \delta_i))
$$
and
$$
T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j)
$$
Here $\mathbf{c}_i$ is color, $\sigma_i$ is density, $T_i$ is accumulated transmittance, $\omega_i$ is composition weight, and $\delta_i$ is ray step size [S1, unofficial].

Total loss function [S1, unofficial]:
$$
L = L_c + \lambda_{KL} L_{KL}
$$
where $L_c$ is MSE between rendered color $\tilde{C}(\mathbf{r})$ and observed color $C(\mathbf{r})$, and $L_{KL}$ is Kullback-Leibler divergence loss [S1, unofficial].

Color loss [S1, unofficial]:
$$
L_c = \sum_{\mathbf{r} \in \mathcal{R}} \|\tilde{C}(\mathbf{r}) - C(\mathbf{r})\|_2^2
$$
where $\mathcal{R}$ is the set of camera rays [S1, unofficial].

Optional mask loss (if foreground only) [S1, unofficial]:
$$
M_m = \sum_{\mathbf{r} \in \mathcal{R}} \|\tilde{M}(\mathbf{r}) - M(\mathbf{r})\|_2^2
$$
with weight 0.1 [S1, unofficial].

**Parameters:**
*   Occupancy volume resolution: $24 \times 24 \times 48$ per video frame [S1, unofficial].
*   Occupancy threshold $\tau_1$: 5 [S1, unofficial].
*   Weight threshold $\tau_2$: $10^{-3}$ [S1, unofficial].
*   KL loss weight $\lambda_{KL}$: $10^{-6}$ [S1, unofficial].
*   Training samples per ray: 64 [S1, unofficial].
*   Inference step size: $1/256$th of scene diagonal [S1, unofficial].

**Pitfalls:**
*   The method struggles to render very detailed content, such as text and fingers [S1, unofficial].
*   Using feature maps instead of MLP maps requires a larger MLP for high quality, slowing down rendering, and does not perform better than hash tables [S1, unofficial].

## Subtopics

### Dynamic MLP Maps
A representation using 2D CNN-generated MLP maps and hash tables for volumetric videos [S1, unofficial]. Sets apart by sharing parameters across frames via CNN, reducing storage/training time compared to per-frame models [S1, unofficial]. Choose when real-time volumetric video rendering with low storage is needed [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering is accelerated by empty space skipping and efficient MLP evaluation via MAGMA-based custom layer [S1, unofficial].
*   **Memory Complexity:** Storage is significantly reduced compared to per-frame KiloNeRF. For a 300-frame video, it requires 240 MB vs 9 GB for per-frame KiloNeRF [S1, unofficial].
*   **Measured Performance:** On NHR dataset (sport1): PSNR 32.92, SSIM 0.959, LPIPS 0.067 [S1, unofficial]. On ZJU-MoCap dataset (scene 313): PSNR 32.15, SSIM 0.976, LPIPS 0.049 [S1, unofficial].
*   **Scaling:** Training time and storage scale linearly with the number of frames for per-frame methods, but this method maintains constant storage and low training time (16 hours for 300 frames vs 6000 hours for per-frame KiloNeRF) [S1, unofficial].
*   **Strengths:** Real-time performance, low storage, efficient rendering via MLP maps and hash tables [S1, unofficial].
*   **Limitations:** Struggles with very detailed content (text, fingers) [S1, unofficial].
*   **When to use:** Real-time volumetric video rendering where storage and training efficiency are critical [S1, unofficial].
*   **When not to use:** Scenes with very fine details like text or thin structures [S1, unofficial].

## Background
Originated by Sida Peng, Yunzhi Yan, Qing Shuai, Hujun Bao, and Xiaowei Zhou from Zhejiang University [S1, unofficial]. The method was introduced in the supplementary material for "Representing Volumetric Videos as Dynamic MLP Maps" [S1, unofficial]. It addresses the limitations of per-frame KiloNeRF models, which require excessive storage and training time for volumetric videos [S1, unofficial]. The approach combines hash tables for feature embedding and CNN-generated MLP maps for efficient parameter retrieval, enabling real-time rendering [S1, unofficial].
