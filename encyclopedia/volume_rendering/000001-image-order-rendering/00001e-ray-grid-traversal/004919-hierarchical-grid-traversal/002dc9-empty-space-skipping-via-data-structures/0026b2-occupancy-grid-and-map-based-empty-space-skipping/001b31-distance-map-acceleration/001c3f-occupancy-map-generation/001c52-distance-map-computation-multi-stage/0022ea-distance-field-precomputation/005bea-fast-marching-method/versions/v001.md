# Fast Marching Method

Also called: Fast Marching SDF

## Overview
The Fast Marching Method (FMM) is a computationally efficient numerical scheme for computing the propagation of an active contour, implicitly handling topological changes [S1]. It solves the Eikonal equation to determine the arrival time of a front expanding in the normal direction from a given boundary condition [S2]. Unlike standard region growing, FMM respects causality by always expanding outwards (where the speed function $F > 0$), ensuring that the solution at any grid point depends only on points with earlier arrival times [S1].

## How it works
**Inputs:**
- A 3D grid of voxels.
- A speed function $F(\mathbf{x}) > 0$ defined over the grid [S1].
- A set of boundary voxels (seeds) with known initial arrival times, typically $T=0$ [S2].

**Outputs:**
- An arrival time function $T(\mathbf{x})$ for all voxels in the grid [S1].

**Data Structures:**
1.  **Grid $T$**: Stores the arrival time for each voxel. Initialized to $\infty$ for non-boundary voxels and $0$ (or specified values) for boundary voxels.
2.  **Heap $H$**: A min-heap storing voxels in the "Narrow" band (candidates for update), ordered by their current $T$ value.
3.  **Status Map**: Tracks voxel states:
    -   **Far**: $T = \infty$, not in heap.
    -   **Narrow**: $T < \infty$, in heap.
    -   **Trial**: $T < \infty$, in heap (often merged with Narrow in efficient implementations).
    -   **Accepted**: $T$ is final, removed from heap.

**Algorithm Steps:**
1.  **Initialization**:
    -   Set $T(\mathbf{x}) = \infty$ for all $\mathbf{x}$.
    -   Set $T(\mathbf{x}) = 0$ for all boundary voxels $\mathbf{x}_b$.
    -   Insert all boundary voxels into the min-heap $H$.
    -   Mark boundary voxels as "Accepted" or "Narrow" depending on implementation specifics [S1, S2].

2.  **Main Loop**:
    -   While $H$ is not empty:
        1.  Extract the voxel $\mathbf{x}_{min}$ with the smallest $T$ value from $H$.
        2.  Mark $\mathbf{x}_{min}$ as "Accepted".
        3.  For each neighbor $\mathbf{x}_n$ of $\mathbf{x}_{min}$:
            -   If $\mathbf{x}_n$ is not "Accepted":
                -   Compute the new arrival time $T_{new}(\mathbf{x}_n)$ by solving the discretized Eikonal equation.
                -   If $T_{new}(\mathbf{x}_n) < T(\mathbf{x}_n)$:
                    -   Update $T(\mathbf{x}_n) = T_{new}(\mathbf{x}_n)$.
                    -   If $\mathbf{x}_n$ is not in $H$, insert it into $H$.
                    -   Else, update its priority in $H$.

**Formula:**
The core equation is the Eikonal equation:
$$ \|\nabla T\| F = 1 $$
where $T(\mathbf{x})$ is the arrival function and $F > 0$ is the speed function [S1].

In 3D, the discretized solution for $T(\mathbf{x})$ at a voxel $\mathbf{x}$ uses the minimum of the solutions from its 6 neighbors (in 3D, 26 neighbors can be considered, but 6 is standard for monotonicity):
$$ T(\mathbf{x}) = \min_{\mathbf{x}_n \in \text{Neighbors}} \left( T(\mathbf{x}_n) + \frac{1}{F(\mathbf{x})} \|\mathbf{x} - \mathbf{x}_n\| \right) $$
More precisely, using upwind differences for the gradient $\nabla T$:
$$ \max(0, \partial_x T)^2 + \max(0, \partial_y T)^2 + \max(0, \partial_z T)^2 = \frac{1}{F(\mathbf{x})^2} $$
The solution for $T(\mathbf{x})$ is derived by taking the minimum over all combinations of upwind neighbors. For a neighbor $\mathbf{x}_n$ along the x-axis:
$$ T(\mathbf{x}) = T(\mathbf{x}_n) + \frac{\Delta x}{F(\mathbf{x})} $$
If multiple neighbors contribute, the quadratic solution is used:
$$ T(\mathbf{x}) = \frac{A - \sqrt{A^2 - B}}{C} $$
where $A, B, C$ are derived from the neighbor values and grid spacing [S1, S2].

**Parameters:**
-   $F(\mathbf{x})$: Speed function. Must be $> 0$ [S1].
-   Boundary conditions: Seeds defining the start of the front [S2].

**Edge Cases:**
-   $F=0$: Causes division by zero. The speed function must be strictly positive [S1].
-   Disconnected components: FMM propagates from seeds. If the domain is not fully connected to seeds, some voxels remain $\infty$ [S1].

**Pseudocode:**
```python
def fast_marching_method(grid_shape, speed_function, boundary_voxels):
    # Initialize T with infinity
    T = np.full(grid_shape, np.inf)
    
    # Min-heap for narrow band
    heap = []
    
    # Initialize boundary voxels
    for voxel in boundary_voxels:
        T[voxel] = 0.0
        heapq.heappush(heap, (0.0, voxel))
        
    # Status map: 0=Far, 1=Narrow, 2=Accepted
    status = np.zeros(grid_shape, dtype=int)
    for voxel in boundary_voxels:
        status[voxel] = 1 # Narrow
        
    while heap:
        t_min, current_voxel = heapq.heappop(heap)
        
        # If already accepted, skip
        if status[current_voxel] == 2:
            continue
            
        status[current_voxel] = 2 # Accepted
        
        # Get neighbors
        neighbors = get_neighbors(current_voxel, grid_shape)
        
        for neighbor in neighbors:
            if status[neighbor] == 2:
                continue
                
            # Calculate new T for neighbor
            # This involves solving the discretized Eikonal equation
            # using the accepted neighbors of the neighbor
            new_t = compute_eikonal_solution(neighbor, T, speed_function)
            
            if new_t < T[neighbor]:
                T[neighbor] = new_t
                if status[neighbor] == 0: # Far -> Narrow
                    status[neighbor] = 1
                    heapq.heappush(heap, (new_t, neighbor))
                else: # Narrow -> Update priority
                    # In Python heapq, we push a new entry and handle duplicates
                    heapq.heappush(heap, (new_t, neighbor))
                    
    return T
```

## Operating characteristics
-   **Time Complexity**: $O(N \log N)$, where $N$ is the number of voxels, due to heap operations [S1].
-   **Memory Complexity**: $O(N)$ for storing $T$, heap, and status map.
-   **Strengths**: Handles topological changes implicitly; efficient for large grids; monotonic propagation ensures causality [S1].
-   **Limitations**: Requires a well-defined speed function $F > 0$; sensitive to boundary conditions; not suitable for non-monotonic fronts [S1].
-   **When to use**: When computing distance fields or propagation times in a grid where the front expands monotonically [S2].
-   **When not to use**: When the speed function can be zero or negative; when non-causal propagation is required.

## Background
The Fast Marching Method was proposed first by Tsitsiklis and then by Sethian [S2]. It is based on solving the Eikonal equation to compute the arrival time of a front expanding in the normal direction [S2]. It is advantageous because it implicitly handles topological changes and is computationally efficient when implemented using heap sort algorithms [S1]. It has been used for heart segmentation, where the pericardial cavity acts as a boundary restricting propagation [S1].
