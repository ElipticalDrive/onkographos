# Distance Map Computation (Multi-Stage)

Also called: Compute Distance Map, Distance Field Compute, Multi-Stage Distance Map Computation, Occupancy Distance Map

## Overview
Distance Map Computation (Multi-Stage) is a GPU compute shader dispatch routine that computes a distance map from an occupancy map, using a swap buffer for iterative or multi-pass distance calculation [S1, unofficial]. It follows [Occupancy Map Generation](1197-occupancy-map-generation.md) and transforms occupancy data into distance fields to enable empty space skipping during ray traversal [S1, unofficial]. Unlike [Occupancy Mipmap Generation](2700-occupancy-mipmap-generation.md), which builds hierarchical mipmaps, this method computes explicit distance values in a flat 3D volume [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** `textureOccupancyMap`, a 3D texture bound to image unit 1 with `GL_R8UI` format and `GL_READ_WRITE` access [S1, unofficial].
*   **Output:** `textureDistanceMap`, a 3D texture bound to image unit 0 with `GL_R8UI` format and `GL_READ_WRITE` access [S1, unofficial].
*   **Uniforms:** A Uniform Buffer Object (UBO) of 4 bytes bound to binding point 0, containing a single integer indicating the current computation stage [S1, unofficial].
*   **Swap Buffer:** `textureSwap`, a temporary 3D texture bound to image unit 1 during intermediate passes [S1, unofficial].

**Data Structures:**
*   **UBO:** 4 bytes total, containing `uint stage` [S1, unofficial].
*   **Textures:** 3D textures with `GL_R8UI` format (8-bit unsigned integer per channel) [S1, unofficial]. The occupancy map stores binary occupancy values [S1, unofficial]. The distance map stores quantized distance values [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** Bind `textureDistanceMap` to image unit 0 and `textureOccupancyMap` to image unit 1, both with `GL_R8UI` format and `GL_READ_WRITE` access [S1, unofficial]. Create a Uniform Buffer Object (UBO) of size 4 bytes, bind it to binding point 0, and map the entire buffer using `glBindBufferRange` [S1, unofficial]. Calculate the number of work groups for the 3D grid by dividing `sizeOccupancyMap` dimensions by 8 and applying ceiling division [S1, unofficial].
2.  **Stage 1 (X-axis propagation):** Set UBO stage value to 0 [S1, unofficial]. Dispatch compute shader with dimensions `(numWorkGroups[1], numWorkGroups[2], 1)` [S1, unofficial]. Issue a memory barrier [S1, unofficial].
3.  **Stage 2 (Y-axis propagation):** Bind `textureSwap` to image unit 1 [S1, unofficial]. Set UBO stage value to 1 [S1, unofficial]. Dispatch compute shader with dimensions `(numWorkGroups[0], numWorkGroups[2], 1)` [S1, unofficial]. Issue a memory barrier [S1, unofficial].
4.  **Stage 3 (Z-axis propagation):** Set UBO stage value to 2 [S1, unofficial]. Dispatch compute shader with dimensions `(numWorkGroups[0], numWorkGroups[1], 1)` [S1, unofficial]. Issue a memory barrier [S1, unofficial].
5.  **Cleanup:** Unbind the UBO and delete the buffer object [S1, unofficial].

**Formulas:**
*   Work group count per axis: $N_i = \lceil \text{sizeOccupancyMap}[i] / 8 \rceil$ for $i \in \{0, 1, 2\}$ [S1, unofficial].
*   Dispatch dimensions: Stage 1 $(N_1, N_2, 1)$, Stage 2 $(N_0, N_2, 1)$, Stage 3 $(N_0, N_1, 1)$ [S1, unofficial].

**Parameters:**
*   **Workgroup Size:** 8 (implied by division by 8 in work group calculation) [S1, unofficial].
*   **Texture Format:** `GL_R8UI` [S1, unofficial].
*   **UBO Size:** 4 bytes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Neighbors outside the volume bounds must be handled to avoid out-of-bounds access [G].
*   **Precision:** The use of 8-bit unsigned integers limits the maximum representable distance to 255 [G].
*   **Synchronization:** Memory barriers are required between stages to ensure that the output of one stage is visible to the next [S1, unofficial].

**Pseudocode:**
```python
def compute_distance_map_multi_stage(occupancy_map, distance_map, swap_buffer, volume_size, workgroup_size=8):
    # Calculate work groups using ceiling division
    num_work_groups = [
        (volume_size[0] + workgroup_size - 1) // workgroup_size,
        (volume_size[1] + workgroup_size - 1) // workgroup_size,
        (volume_size[2] + workgroup_size - 1) // workgroup_size
    ]

    # Stage 1: X-axis propagation
    bind_texture(distance_map, image_unit=0, access="GL_READ_WRITE")
    bind_texture(occupancy_map, image_unit=1, access="GL_READ_WRITE")
    create_ubo(size=4)
    bind_ubo(binding=0)
    map_ubo(binding=0, stage=0)
    dispatch_compute(num_work_groups[1], num_work_groups[2], 1)
    memory_barrier()

    # Stage 2: Y-axis propagation
    bind_texture(swap_buffer, image_unit=1, access="GL_READ_WRITE")
    map_ubo(binding=0, stage=1)
    dispatch_compute(num_work_groups[0], num_work_groups[2], 1)
    memory_barrier()

    # Stage 3: Z-axis propagation
    map_ubo(binding=0, stage=2)
    dispatch_compute(num_work_groups[0], num_work_groups[1], 1)
    memory_barrier()

    # Cleanup
    unbind_ubo(binding=0)
    delete_buffer_object()
```

## Subtopics

### [Empty Space Map Generation](1771-empty-space-map-generation.md)
Empty Space Map Generation is a preprocessing technique that creates a boolean map indicating which voxels in a scalar field contain no visible geometry, allowing ray marching to skip empty regions. It reduces the number of density samples and transfer function evaluations by jumping over contiguous blocks of empty space. Unlike [Distance Map Computation (Multi-Stage)](1205-distance-map-computation-multi-stage.md), which computes distances to occupied blocks, this method uses a binary occupancy check based on a transfer function threshold.

### [Distance Transformation (Proximity Clouds)](5720-distance-transformation-proximity-clouds.md)
Distance Transformation, also known as Proximity Clouds, is a method to accelerate ray traversal in a regular grid filled with empty zones by pre-calculating distance information to the nearest full element in the grid. It differs from hierarchical structures by storing distance data in a flat 3D volume aligned with the original voxel indices, allowing for $O(1)$ lookup during traversal without tree navigation overhead.

### Distance Field Precomputation
Precomputing distance fields for the scalar fields involved in the fiber surface definition to facilitate fast intersection detection via the rule of signs [S2]. The precomputation time is fixed and depends only on the distance field dimensions [S2]. In tests, a 64x64 array is accurate enough, taking around 1-2 milliseconds to compute the distance field for 4 FSCP with 4 segments for each polygon [S2].

### AADF Exit Plane Calculation
Calculates the exit plane of an empty region defined by an Axis-Aligned Distance Field (AADF) [S3, unofficial]. The AADF stores distances to the nearest occupied voxel in each of the 6 directions [S3, unofficial]. The shift for each axis is determined by the ray direction: if `ray_dir.x < 0`, use shift 0 (-X), else use shift 5 (+X); similarly for Y (10/15) and Z (20/25) [S3, unofficial]. The bounds (distances) for each axis are extracted from the packed uint, with each distance being 5 bits [S3, unofficial]. The lower and upper bounds of the empty region in voxel coordinates are calculated as `coord - bounds` (clamped to 0) and `coord + 1 + bounds` (clamped to grid_ext), respectively [S3, unofficial]. The exit plane coordinate is returned based on the ray direction: if `ray_dir` is negative, return the lower bound, else return the upper bound [S3, unofficial]. The `cell_ext` parameter defines the size of the cell in voxel units: for chunks, `VX_BRICK_EXT * VX_CHUNK_EXT`; for bricks, `VX_BRICK_EXT`; for voxels, 1 [S3, unofficial].

## Background
Distance Map Computation (Multi-Stage) is implemented in the DVR_ESS_PDM repository [S1, unofficial]. It builds on the concept of occupancy maps and distance fields to accelerate ray marching [S1, unofficial]. The multi-stage approach processes the volume across three separate compute shader dispatches, each handling propagation along one axis [S1, unofficial].
