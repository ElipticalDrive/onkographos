# Occupancy Grid Update

Also called: Density-Based Grid Update, Grid Density Thresholding, Occupancy Grid Update from Density

## Overview
Occupancy Grid Update is a method to periodically refresh a 3D occupancy grid by querying a Neural Radiance Field (NeRF) model for density at grid voxel centers and marking voxels as occupied if the density exceeds a specified threshold [S1, unofficial]. It solves the problem of stale spatial caching in on-the-fly NeRF training, where the geometry learned by the network evolves over time [S1, unofficial]. Unlike static caching, this method dynamically adapts the grid to the current network state, ensuring that empty space skipping remains accurate throughout training [S1, unofficial]. It differs from [Occupancy Map Generation via Ray Casting](8136-occupancy-map-generation-via-ray-casting.md) by using direct voxel-center density queries rather than ray-casting to determine occupancy [S1, unofficial].

## How it works
**Inputs:**
- `model`: A NeRF model capable of returning density values. It may implement a `forward_with_density_only` interface or a standard `forward` interface requiring dummy directions [S1, unofficial].
- `grid_resolution` ($N$): Integer resolution of the 3D grid (default 128) [S1, unofficial].
- `aabb_min`, `aabb_max`: 3D vectors defining the axis-aligned bounding box of the scene [S1, unofficial].
- `density_threshold` ($\tau$): Float threshold for occupancy (default 0.01) [S1, unofficial].
- `update_grid_every` ($K$): Integer iteration interval for updates [S1, unofficial].

**Outputs:**
- `self.grid`: A 3D boolean tensor of shape $(N, N, N)$ where `True` indicates occupied voxels [S1, unofficial].

**Data Structures:**
- `grid_coords`: A tensor of shape $(N^3, 3)$ containing integer grid indices $(x, y, z)$ for all voxels [S1, unofficial].
- `world_positions`: A tensor of shape $(N^3, 3)$ containing the world-space coordinates of voxel centers [S1, unofficial].
- `densities`: A tensor of shape $(N^3)$ containing the queried density values [S1, unofficial].

**Formulas:**
- Voxel size: $\text{voxel\_size} = (\text{aabb\_max} - \text{aabb\_min}) / \text{resolution}$ [S1, unofficial].
- Grid-to-world conversion: $\text{positions} = \text{aabb\_min} + \left( \frac{\text{grid\_indices}.\text{float}() + 0.5}{\text{resolution}} \right) \times (\text{aabb\_max} - \text{aabb\_min})$ [S1, unofficial].
- World-to-grid conversion: $\text{grid\_indices} = \text{clamp}\left( \frac{\text{positions} - \text{aabb\_min}}{\text{aabb\_max} - \text{aabb\_min}} \times \text{resolution}, 0, \text{resolution}-1 \right).\text{long}()$ [S1, unofficial].

**Steps:**
1. **Generate Grid Coordinates**: Create integer coordinates for the grid. $x, y, z = \text{linspace}(0, N-1, N)$; $\text{grid\_coords} = \text{meshgrid}(x, y, z, \text{indexing}='ij').\text{reshape}(-1, 3)$ [S1, unofficial].
2. **Convert to World Positions**: Map grid indices to world space using the center of each voxel. $\text{positions} = \text{aabb\_min} + \left( \frac{\text{grid\_indices}.\text{float}() + 0.5}{N} \right) \times (\text{aabb\_max} - \text{aabb\_min})$ [S1, unofficial].
3. **Query Densities**: Evaluate the NeRF model at `world_positions`. If `model` has `forward_with_density_only`, call it directly. Otherwise, call `model(batch, dummy_dirs)` and extract density [S1, unofficial].
4. **Update Grid**: Apply thresholding and reshape. $\text{occupied} = \text{densities} > \tau$; $\text{self.grid} = \text{occupied}.\text{reshape}(N, N, N)$ [S1, unofficial].

**Pseudocode:**
```python
def update_occupancy_grid(model, aabb_min, aabb_max, resolution=128, threshold=0.01):
    # Step 1: Generate grid coordinates
    x = [float(i) for i in range(resolution)]
    y = [float(i) for i in range(resolution)]
    z = [float(i) for i in range(resolution)]
    grid_coords = [[xi, yi, zi] for xi in x for yi in y for zi in z]
    
    # Step 2: Convert to world positions
    positions = []
    for coord in grid_coords:
        pos = [
            aabb_min[d] + ((coord[d] + 0.5) / resolution) * (aabb_max[d] - aabb_min[d])
            for d in range(3)
        ]
        positions.append(pos)
        
    # Step 3: Query densities
    if hasattr(model, 'forward_with_density_only'):
        densities = model(positions)
    else:
        dummy_dirs = [[1.0, 0.0, 0.0] for _ in positions] # [G] Dummy directions must be valid vectors.
        output = model(positions, dummy_dirs)
        densities = output[..., 0] # [G] Extract density; assumes standard NeRF output structure.
        
    # Step 4: Update grid
    occupied = [d > threshold for d in densities]
    grid = [[[occupied[i * resolution**2 + j * resolution + k] for k in range(resolution)] for j in range(resolution)] for i in range(resolution)]
    
    return grid
```

**Parameters:**
- `resolution`: int, default 128. The 3D resolution of the occupancy grid [S1, unofficial].
- `density_threshold`: float, default 0.01. The density value above which a voxel is considered occupied [S1, unofficial].
- `update_grid_every`: int. Iteration interval for grid updates [S1, unofficial].
- `occupancy_threshold`: float. Alias for `density_threshold` [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision**: Grid-to-world conversion uses floating-point arithmetic; ensure `aabb_min` and `aabb_max` are consistent with the model's coordinate space [S1, unofficial].
- **Model Interface**: If the model does not support density-only queries, dummy directions must be generated [S1, unofficial].
- **Batching**: For large resolutions, querying all $N^3$ points at once may exceed memory limits. Batching should be implemented if $N^3$ is large [S1, unofficial].

## Subtopics

### [Density Grid Update with EMA](3884-density-grid-update-with-ema.md)
This method periodically refreshes a 3D hierarchical density grid using an Exponential Moving Average (EMA) of newly queried densities to stabilize training and refine the representation of occupied space. It builds on [Occupancy Grid Update](2916-occupancy-grid-update.md) by maintaining a continuous density value per voxel rather than just binary occupancy, allowing for smoother transitions and better gradient flow during neural radiance field optimization. It sets itself apart from sibling methods like [MERF Baking](10179-merf-baking.md) by performing online, step-wise updates during training rather than offline baking, and from [Occupancy Grid Transition and Update](7522-occupancy-grid-transition-and-update.md) by using EMA smoothing instead of hard thresholding or transition maps.

### [Occupancy Grid Transition and Update](7522-occupancy-grid-transition-and-update.md)
This method adapts the occupancy grid for efficient point sampling in dynamic Neural Radiance Fields (NeRFs) by treating voxel occupancy as a time-varying probability rather than a static binary state. It solves the problem of maintaining sampling efficiency in on-the-fly training where scene geometry changes, by applying a transition function to predict motion and a Bayesian update to incorporate new density observations. Unlike static NeRFs that cache grids or 4D space-time grids that fail to accelerate per-frame training, this method transitions the 3D grid between frames to preserve occupancy information relevant to the current time step.

### [MERF Baking](10179-merf-baking.md)
MERF Baking is a post-training procedure that converts a trained neural field representation into a block-sparse, texture-based format optimized for real-time web rendering. It solves the problem of storing and transmitting large-scale neural scenes by evaluating the MLP outputs on discrete grids and using a binary occupancy grid to cull empty or occluded voxels. It sets itself apart from its siblings, such as [Density Grid Update with EMA](3884-density-grid-update-with-ema.md) and [Occupancy Grid Transition and Update](7522-occupancy-grid-transition-and-update.md), by explicitly targeting web-based delivery through texture compression and block-sparse storage, trading higher frame rates for neural field reconstruction capabilities compared to mesh rasterization methods. Unlike existing baking pipelines that do not consider the proposal-MLP and use uniformly-spaced sample points (causing fog-like artifacts and floating blobs), this method uses proposal-MLP sampling and real-time renderer step sizes for visibility culling, resulting in a lossless pipeline.

#### Proposal Network Baking
**Step:** Render all training rays to bake the proposal network into a $1024^3$ binary occupancy grid [S3]. Mark a voxel as occupied if there exists at least one sampled point $x_i$ such that $\max(w_i, \sigma_i) > 0.005$ [S3].
**Parameter:** The threshold for marking a voxel as occupied is 0.005 [S3].
**Layout:** The baked proposal network is stored in a $1024^3$ binary occupancy grid [S3].

## Operating characteristics
- **Performance**: Updates are performed periodically (e.g., every 500 iterations) to balance accuracy and training speed [S1, unofficial].
- **Strengths**: Simple to implement; effectively skips empty space during training; adapts to changing geometry [S1, unofficial].
- **Limitations**: Requires full grid queries; may be slow for very high resolutions [S1, unofficial].
- **When to Use**: Static or slowly changing scenes where periodic updates are sufficient [S1, unofficial].
- **When Not to Use**: Highly dynamic scenes requiring per-frame updates (use [Occupancy Grid Transition and Update](7522-occupancy-grid-transition-and-update.md)) or when smooth density gradients are needed (use [Density Grid Update with EMA](3884-density-grid-update-with-ema.md)) [S1, unofficial].

## Background
This method is implemented in frameworks such as FLASH [S1, unofficial] and integrated into estimators like `nerfacc` to periodically refresh occupancy grids during training [S2, unofficial]. It ensures that the occupancy grid accurately reflects the current state of the learned scene geometry [S1, unofficial].
