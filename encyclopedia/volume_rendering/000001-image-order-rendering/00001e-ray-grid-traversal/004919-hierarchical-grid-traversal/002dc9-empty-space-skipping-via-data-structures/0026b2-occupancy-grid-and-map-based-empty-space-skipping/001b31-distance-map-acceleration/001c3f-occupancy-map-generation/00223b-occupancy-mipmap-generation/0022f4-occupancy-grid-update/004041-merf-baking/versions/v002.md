# MERF Baking

Also called: Baking to Discrete Grids, Proposal-MLP-aware baking pipeline

## Overview
MERF Baking is a post-training procedure that converts a trained neural radiance field (specifically the Multi-resolution Encoding Radiance Field) into a discrete, block-sparse grid representation for real-time rendering [S2]. It solves the problem of high memory consumption and slow inference associated with on-the-fly MLP evaluation by storing pre-computed attributes in 2D planes and 3D voxels [S1]. Unlike generic baking pipelines that use uniform sampling, this method is Proposal-MLP-aware, using the proposal network's sampling distribution and the real-time renderer's step sizes to aggressively cull empty or occluded voxels, resulting in a lossless compression of the neural field [S2].

## How it works

### Inputs and Outputs
**Inputs:**
*   A trained MERF model, including the Proposal MLP and the attribute MLPs [S2].
*   The set of training rays $\mathcal{R}$ used during training [S2].
*   Rendering parameters: voxel resolution per block ($N_v = 512$), triplane resolution per block ($N_t = 2048$), and occupancy threshold ($\tau = 0.005$) [S1, S2].

**Outputs:**
*   A block-sparse 3D occupancy grid hierarchy (mipmaps) for empty space skipping [S2].
*   Baked attribute data: high-resolution 2D triplanes and low-resolution 3D voxel grids per block, stored as PNG textures [S1, S2].

### Data Structures

**1. Binary Occupancy Grid ($A$)**
*   **Type:** 3D boolean array.
*   **Resolution:** Matches the voxel grid resolution of the block ($512^3$) [S1].
*   **Content:** $A[x, y, z] = \text{true}$ if the voxel is occupied, $\text{false}$ otherwise.

**2. Block-Sparse Voxel Grid**
*   **Structure:** A collection of data blocks. Each block corresponds to a $512^3$ region in the local coordinate space.
*   **Storage:** Only blocks where at least one voxel in $A$ is $\text{true}$ are stored [S2].
*   **Content:** For each occupied voxel, stores the attribute values (density, color, etc.) derived from the baked planes/voxels [S1].

**3. Triplanes**
*   **Structure:** Three 2D textures (XY, YZ, XZ planes).
*   **Resolution:** $2048 \times 2048$ per plane [S1].
*   **Content:** Attribute values baked from the MLP outputs [S1].

**4. Occupancy Mipmaps**
*   **Structure:** A hierarchy of downsampled binary occupancy grids.
*   **Generation:** Created via max-pooling on $A$ with filter sizes 16, 32, and 128 [S2].
*   **Purpose:** Accelerates ray marching by skipping empty space at multiple scales [S2].

### Steps

1.  **Render Training Rays:**
    Render all training rays $\mathcal{R}$ using the trained Proposal MLP to collect ray samples [S2]. The Proposal MLP samples points clustered around surfaces [S2].

2.  **Extract Weighted Points:**
    For each ray, extract a set of weighted points $\{(x_i, w_i)\}$ [S2].
    *   $x_i$: The 3D position of the $i$-th sample.
    *   $w_i$: The volume rendering weight associated with the sample, computed as:
        $$ w_i = \alpha_i \prod_{j < i} (1 - \alpha_j) $$
        where $\alpha_j$ is the opacity at sample $j$ [S2]. Note: $\alpha_j$ depends on the density at $x_j$ and the step size used by the *real-time renderer* (small uniform step size in contracted space), not necessarily the Proposal MLP's step size [S2].

3.  **Mark Occupied Voxels:**
    Initialize the binary occupancy grid $A$ to all false. For each weighted point $(x_i, w_i)$:
    *   Compute the opacity $\alpha_i$ at $x_i$ using the real-time renderer's step size [S2].
    *   If $w_i > \tau$ AND $\alpha_i > \tau$ (where $\tau = 0.005$):
        *   Identify the 8 voxels surrounding $x_i$ in the $512^3$ grid.
        *   Set these 8 voxels to $\text{true}$ in $A$ [S2].
    *   *Note:* Using both $w_i$ and $\alpha_i$ ensures that voxels contributing to visibility (accounting for occlusion via $w_i$) and significant local density (via $\alpha_i$) are preserved [S2].

4.  **Generate Occupancy Mipmaps:**
    Create lower-resolution versions of $A$ using max-pooling with filter sizes 16, 32, and 128 [S2]. These form the hierarchy for empty space skipping during rendering [S2].

5.  **Bake Attributes:**
    Evaluate the trained MLP to generate the attribute function $f_{k,l}$ for each block [S1].
    *   Bake high-resolution 2D triplanes ($2048^2$) [S1].
    *   Bake a low-resolution 3D voxel grid ($512^3$) within each block [S1].
    *   Store only the data blocks corresponding to occupied voxels in $A$ using a block-sparse format [S2].

6.  **Compress and Store:**
    Encode the resulting textures (triplanes and voxel grids) into PNG format to reduce storage footprint [S1, S2].

### Pseudocode

```python
def merf_baking(training_rays, proposal_mlp, real_time_renderer_params, voxel_res=512, triplane_res=2048, threshold=0.005):
    """
    Bakes a trained MERF model into discrete grids.
    
    Args:
        training_rays: List of rays used during training.
        proposal_mlp: The trained proposal network for sampling.
        real_time_renderer_params: Parameters for the real-time renderer (e.g., step size, contraction).
        voxel_res: Resolution of the voxel grid per block (default 512).
        triplane_res: Resolution of the triplanes per block (default 2048).
        threshold: Occupancy threshold for weight and opacity (default 0.005).
        
    Returns:
        occupancy_mipmaps: List of downsampled binary occupancy grids.
        baked_data: Dictionary containing triplanes and block-sparse voxel data.
    """
    
    # Step 1 & 2: Render training rays and extract weighted points
    weighted_points = []
    for ray in training_rays:
        # Sample points using Proposal MLP (clusters around surfaces)
        samples = proposal_mlp.sample(ray)
        
        for i, sample in enumerate(samples):
            x_i = sample.position
            # Compute opacity alpha_i based on real-time renderer's step size
            # This ensures culling matches the real-time rendering behavior
            alpha_i = compute_opacity(sample.density, real_time_renderer_params.step_size)
            
            # Compute volume rendering weight w_i
            # w_i = alpha_i * product(1 - alpha_j) for j < i
            # Note: The product term accounts for occlusion along the ray
            w_i = compute_volume_rendering_weight(samples[:i], alpha_i)
            
            if w_i > threshold and alpha_i > threshold:
                weighted_points.append((x_i, w_i, alpha_i))

    # Step 3: Mark occupied voxels
    # Initialize binary occupancy grid A
    A = zeros((voxel_res, voxel_res, voxel_res), dtype=bool)
    
    for (x_i, w_i, alpha_i) in weighted_points:
        # Map continuous position x_i to grid indices
        # Assuming contracted space mapping is handled by the renderer/MLP
        grid_coords = continuous_to_grid(x_i, voxel_res)
        
        # Mark the 8 surrounding voxels as occupied
        for dx in [-1, 0]:
            for dy in [-1, 0]:
                for dz in [-1, 0]:
                    idx = grid_coords + [dx, dy, dz]
                    if is_valid_index(idx, voxel_res):
                        A[idx] = True

    # Step 4: Generate Occupancy Mipmaps
    occupancy_mipmaps = [A]
    current_grid = A
    for filter_size in [16, 32, 128]:
        # Max-pooling to downsample
        next_grid = max_pool(current_grid, filter_size)
        occupancy_mipmaps.append(next_grid)
        current_grid = next_grid

    # Step 5: Bake Attributes
    # Evaluate MLP to get attribute function f_k,l
    # This involves baking triplanes and voxel grids
    triplanes = bake_triplanes(proposal_mlp, triplane_res)
    voxel_blocks = bake_voxel_blocks(proposal_mlp, A, voxel_res)
    
    # Step 6: Compress
    baked_data = {
        'triplanes': compress_to_png(triplanes),
        'voxel_blocks': voxel_blocks # Stored in block-sparse format
    }
    
    return occupancy_mipmaps, baked_data

def compute_volume_rendering_weight(samples, current_alpha):
    """
    Computes the volume rendering weight for the current sample.
    w_i = alpha_i * product_{j < i} (1 - alpha_j)
    """
    transmittance = 1.0
    for sample in samples:
        alpha_j = compute_opacity(sample.density, real_time_renderer_params.step_size)
        transmittance *= (1.0 - alpha_j)
    return current_alpha * transmittance

def compute_opacity(density, step_size):
    """
    Computes opacity from density and step size.
    alpha = 1 - exp(-density * step_size)
    """
    return 1.0 - exp(-density * step_size)
```

### Parameters and Edge Cases
*   **Threshold ($\tau$):** Set to 0.005 for both volume rendering weight and opacity [S2]. This value balances aggressive culling with the guarantee that voxels with significant opacity are not culled [S2].
*   **Voxel Resolution:** $512^3$ per block [S1].
*   **Triplane Resolution:** $2048^2$ per block [S1].
*   **Edge Case - Occlusion:** The use of volume rendering weight $w_i$ (which includes the transmittance product) is critical. It ensures that voxels occluded by closer geometry are not marked as occupied, even if their local density/opacity is high [S2].
*   **Edge Case - Step Size Mismatch:** The opacity $\alpha_i$ must be computed using the *real-time renderer's* step size, not the Proposal MLP's step size. The Proposal MLP may suggest larger steps, which would overestimate opacity if used for culling, leading to incorrect occupancy [S2].

## Operating characteristics

*   **Time Complexity:** The baking process is $O(N_r \cdot N_s)$, where $N_r$ is the number of training rays and $N_s$ is the number of samples per ray. This is a one-time offline cost [S2].
*   **Memory Complexity:** The memory footprint is determined by the number of occupied voxels and the size of the triplanes. The block-sparse format and PNG compression significantly reduce storage compared to a dense grid [S1, S2].
*   **Performance:** Real-time rendering frame rates are lower than mesh rasterization-based methods due to the use of volume rendering, but higher than on-the-fly neural field evaluation [S1].
*   **Quality:** The method is almost lossless compared to the pre-baking quality because it uses Proposal-MLP-aware sampling and visibility culling, avoiding the fog-like artifacts and floating blobs common in uniform-sampling baking pipelines [S2].
*   **When to Use:** Suitable for real-time neural rendering of unbounded scenes where memory efficiency and fast inference are required, and the scene has been captured with a Proposal MLP [S2].
*   **When Not to Use:** If mesh rasterization is preferred for higher frame rates, or if the scene does not benefit from neural field reconstruction (e.g., simple geometric scenes) [S1].

## Background

MERF (Memory-Efficient Radiance Fields) was introduced by [S2] for real-time view synthesis in unbounded scenes. The baking pipeline is a key component of MERF, designed to convert the trained neural representation into a discrete format for efficient rendering. It builds on the idea of block-sparse grids (as seen in SNeRG) and enhances it with Proposal-MLP-aware culling [S2]. The method was developed to address the limitations of existing baking pipelines that ignore the proposal network's sampling distribution, leading to artifacts [S2].
