# Distance Map Computation (Multi-Stage)

Also called: Compute Distance Map, Distance Field Compute, Multi-Stage Distance Map Computation, Occupancy Distance Map

## Overview
Distance Map Computation (Multi-Stage) is a GPU compute shader dispatch routine that generates a distance map from an occupancy map, using a swap buffer for iterative or multi-pass distance calculation [S1, unofficial]. It enables ray marching to skip empty regions by providing distances to the nearest occupied blocks, reducing the number of density samples and transfer function evaluations [S1, unofficial]. Unlike sibling methods that may generate mipmaps or recompute bricks independently, this method computes a global distance field across the occupancy grid using a structured multi-stage reduction approach [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `textureOccupancyMap`, a 3D texture containing binary occupancy data (1 if occupied, 0 if empty).
- Output: `textureDistanceMap`, a 3D texture storing the distance to the nearest occupied voxel/block for each location.
- Auxiliary: `textureSwap`, a temporary buffer used for intermediate stages of the distance computation.

**Data Structures:**
- `textureOccupancyMap`: Bound to image unit 1. Format: `GL_R8UI` (8-bit unsigned integer, single channel). Access: `GL_READ_WRITE`.
- `textureDistanceMap`: Bound to image unit 0. Format: `GL_R8UI`. Access: `GL_READ_WRITE`.
- `textureSwap`: Bound to image unit 1 during stages 2 and 3. Format: `GL_R8UI`. Access: `GL_READ_WRITE`.
- Uniform Buffer Object (UBO): Bound to binding point 0. Size: 4 bytes. Contains a single `uint` value representing the current computation stage (0, 1, or 2).

**Parameters:**
- `sizeOccupancyMap`: The dimensions (width, height, depth) of the occupancy map.
- `blockSize`: The workgroup size is fixed at 8x8x1 for the dispatch dimensions calculation.

**Algorithm Steps:**
1. **Initialization:** Bind `textureDistanceMap` to image unit 0 and `textureOccupancyMap` to image unit 1. Create and bind a 4-byte UBO to binding point 0.
2. **Work Group Calculation:** Calculate the number of work groups required for the 3D grid. The dimensions are derived by dividing `sizeOccupancyMap` by 8, using ceiling division. Let $N_x, N_y, N_z$ be the dimensions of the occupancy map. The number of work groups is:
   $$
   \text{numWorkGroups}_x = \lceil N_x / 8 \rceil, \quad \text{numWorkGroups}_y = \lceil N_y / 8 \rceil, \quad \text{numWorkGroups}_z = \lceil N_z / 8 \rceil
   $$
3. **Stage 1 (X-Axis Reduction):**
   - Set the UBO stage value to 0.
   - Dispatch compute shader with dimensions `(numWorkGroups_x, numWorkGroups_y, 1)`.
   - Issue a memory barrier to ensure completion.
4. **Stage 2 (Y-Axis Reduction):**
   - Bind `textureSwap` to image unit 1.
   - Set the UBO stage value to 1.
   - Dispatch compute shader with dimensions `(numWorkGroups_x, numWorkGroups_z, 1)`.
   - Issue a memory barrier.
5. **Stage 3 (Z-Axis Reduction):**
   - Set the UBO stage value to 2.
   - Dispatch compute shader with dimensions `(numWorkGroups_x, numWorkGroups_y, 1)`.
   - Issue a memory barrier.
6. **Cleanup:** Unbind the UBO and delete the buffer object.

**Pseudocode:**
```python
def compute_distance_map_multi_stage(occupancy_map, size_occupancy_map):
    """
    Simulates the multi-stage GPU compute dispatch for distance map generation.
    Note: This pseudocode describes the host-side dispatch logic.
    The actual distance calculation logic within the compute shader is not fully detailed in the source [S1, unofficial].
    """
    # 1. Setup Textures and Buffers
    texture_distance_map = create_texture_3d(size_occupancy_map, format="GL_R8UI", access="GL_READ_WRITE")
    texture_occupancy_map = occupancy_map # Already created
    texture_swap = create_texture_3d(size_occupancy_map, format="GL_R8UI", access="GL_READ_WRITE")
    
    ubo = create_uniform_buffer(size=4) # 4 bytes for stage index
    
    # 2. Calculate Work Groups
    # Ceiling division: ceil(a / b) = (a + b - 1) // b
    num_work_groups_x = (size_occupancy_map[0] + 7) // 8
    num_work_groups_y = (size_occupancy_map[1] + 7) // 8
    num_work_groups_z = (size_occupancy_map[2] + 7) // 8
    
    # 3. Stage 1: X-Axis (and Y-slice processing)
    bind_image_unit(0, texture_distance_map)
    bind_image_unit(1, texture_occupancy_map)
    bind_ubo(0, ubo)
    set_ubo_value(ubo, 0) # Stage 0
    dispatch_compute(num_work_groups_x, num_work_groups_y, 1)
    memory_barrier()
    
    # 4. Stage 2: Y-Axis (using Swap buffer)
    bind_image_unit(0, texture_distance_map) # Output remains distance map
    bind_image_unit(1, texture_swap)         # Input from swap
    set_ubo_value(ubo, 1) # Stage 1
    dispatch_compute(num_work_groups_x, num_work_groups_z, 1)
    memory_barrier()
    
    # 5. Stage 3: Z-Axis (final reduction)
    bind_image_unit(0, texture_distance_map)
    bind_image_unit(1, texture_swap) # Input from swap
    set_ubo_value(ubo, 2) # Stage 2
    dispatch_compute(num_work_groups_x, num_work_groups_y, 1)
    memory_barrier()
    
    # 6. Cleanup
    unbind_ubo(0)
    delete_buffer(ubo)
    
    return texture_distance_map
```

**Edge Cases and Pitfalls:**
- **Precision:** The distance map uses `GL_R8UI`, limiting distances to 0-255. If the occupancy map dimensions exceed 255 units, distances will saturate [S1, unofficial].
- **Boundaries:** The source does not specify boundary handling (e.g., clamping, wrapping) for the distance calculation within the compute shader [S1, unofficial].
- **Synchronization:** Memory barriers are critical between stages to ensure the output of one stage is visible as input to the next [S1, unofficial].

## Subtopics

### [Empty Space Map Generation](1771-empty-space-map-generation.md)
Empty Space Map Generation is a preprocessing technique that creates a boolean map indicating which voxels in a scalar field contain no visible geometry, allowing ray marching to skip empty regions. It reduces the number of density samples and transfer function evaluations by jumping over contiguous blocks of empty space. Unlike Distance Map Computation (Multi-Stage), which computes distances to occupied blocks, this method uses a binary occupancy check based on a transfer function threshold.

### [Distance Field Precomputation](2861-distance-field-precomputation.md)
Distance Field Precomputation calculates distance fields for scalar fields defining fiber surfaces to enable fast intersection detection via the rule of signs. It builds on Distance Map Computation (Multi-Stage) [G]. Unlike Empty Space Map Generation which tracks occupancy, or Distance Transformation (Proximity Clouds) which uses proximity clouds, this method targets geometric boundaries of fiber surfaces for ray-tracing acceleration.

### [Distance Transformation (Proximity Clouds)](5720-distance-transformation-proximity-clouds.md)
Distance Transformation, also known as Proximity Clouds, accelerates ray traversal in regular grids filled with empty zones by pre-calculating distance information to the nearest full element in the grid. It differs from hierarchical structures by storing distance data in a flat 3D volume aligned with the original voxel indices, allowing for $O(1)$ lookup during traversal without tree navigation overhead.

### AADF Exit Plane Calculation
AADF Exit Plane Calculation calculates the exit plane of an empty region defined by an Axis-Aligned Distance Field (AADF). The AADF stores distances to the nearest occupied voxel in each of the 6 directions [S2, unofficial].
- **Steps:**
  1. Determine the shift for each axis based on the ray direction. If `ray_dir.x < 0`, use shift 0 (-X), else use shift 5 (+X). Similarly for Y (10/15) and Z (20/25).
  2. Extract the bounds (distances) for each axis from the packed uint. Each distance is 5 bits.
  3. Calculate the lower and upper bounds of the empty region in voxel coordinates. The lower bound is `coord - bounds`, clamped to 0. The upper bound is `coord + 1 + bounds`, clamped to `grid_ext`.
  4. Return the exit plane coordinate. For each axis, if `ray_dir` is negative, return the lower bound, else return the upper bound.
- **Parameters:**
  - `cell_ext`: The size of the cell in voxel units. For chunks, this is `VX_BRICK_EXT * VX_CHUNK_EXT`. For bricks, `VX_BRICK_EXT`. For voxels, 1 [S2, unofficial].

## Operating characteristics
- **Time Complexity:** The multi-stage approach suggests a reduction complexity proportional to the number of dimensions (3 stages) plus the grid size, $O(N)$ where $N$ is the number of voxels, assuming constant-time distance updates per voxel per stage.
- **Memory Complexity:** Requires storage for the occupancy map, distance map, and a swap buffer, totaling $3 \times N$ bytes (assuming 8-bit unsigned integers).
- **Performance:** The method is designed for GPU acceleration using compute shaders, leveraging parallel processing for distance calculation [S1, unofficial].
- **Strengths:** Efficiently skips empty space during ray marching, reducing sample count and transfer function evaluations [S1, unofficial].
- **Limitations:** Limited to distances representable in 8-bit unsigned integers (0-255) [S1, unofficial]. Requires multiple dispatches and memory barriers, introducing overhead [S1, unofficial].

## Background
Distance Map Computation (Multi-Stage) is part of the DVR_ESS_PDM project, an unofficial implementation of volume rendering techniques [S1, unofficial]. It is used in conjunction with other occupancy map generation techniques to accelerate ray traversal in volume rendering [S1, unofficial]. The method is implemented using OpenGL compute shaders [S1, unofficial].
