# Chebyshev Distance Map Empty Space Skipping

Also called: Chebychev distance maps for empty-space skipping, Isotropic Chebyshev distance map

## Overview
Chebyshev distance map empty space skipping is a ray-traversal acceleration technique that uses a pre-computed distance map to skip multiple empty voxels in any dimension along a ray [S1]. It builds on [Empty Space Map Generation](1771-empty-space-map-generation.md) by replacing the binary occupancy check with a metric that quantifies the distance to the nearest occupied block, allowing the ray to jump directly to the next potential intersection [S1]. Unlike the occupancy map method, which resumes sampling after a fixed number of empty voxels, this method dynamically calculates the skip distance based on the local geometry, achieving an average speed-up of 5.3 times the baseline frame rate [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** An occupancy map (boolean grid indicating visible geometry based on a transfer function threshold) [S1].
*   **Output:** A Chebyshev distance map texture where each voxel stores the Chebyshev distance to the nearest occupied block [S1].

**Data Structures:**
*   **Distance Map Texture:** A 3D image texture (`uimage3D`) with an unsigned 8-bit integer channel (`r8ui`) [S1].
    *   **Layout:** 3D grid of `uint8` values.
    *   **Constraint:** Distances are limited to a maximum of 255 due to the 8-bit storage [S1].
    *   **Occupancy Map Integration:** The distance map can overwrite the occupancy map texture to save memory, but a separate "swap image" of identical dimensions is required during generation [S1].

**Algorithm: Distance Map Generation**
The transformation from an occupancy map to a Chebyshev distance map is decomposed into three 1D passes that are trivially parallelized on a GPU [S1]. The passes operate on rows (x-axis), columns (y-axis), and slices (z-axis) independently [S1].

1.  **First Transformation (X-axis):**
    *   For each column and slice, perform a forward pass and a backward pass along the x-dimension.
    *   **Forward Pass:** Initialize $D_1$ from the occupancy map at $x=0$. Iterate $x$ from 1 to $dim.x-1$. Update $D = \min(D_1 + 1, \text{occ}(x))$. Store $D$ in the distance map. Update $D_1 = D$.
    *   **Backward Pass:** Iterate $x$ from $dim.x-2$ down to 0. Update $D = \min(D_1 + 1, \text{dist}(x))$. Store $D$ in the distance map. Update $D_1 = D$.
    *   *Note:* This pass can read from and write to the same texture if it is the occupancy map [S1].

2.  **Second Transformation (Y-axis):**
    *   For each row and slice, perform a single-pass zig-zag search along the y-dimension.
    *   Read the current distance $D$ from the output of the first transformation.
    *   Iterate $n$ from 1 to $D-1$.
        *   If $y \ge n$, read $D_n = \text{dist}(x, y-n, z)$. Update $D = \min(D, \max(n, D_n))$.
        *   If $y+n < dim.y$ and $n < D$, read $D_n = \text{dist}(x, y+n, z)$. Update $D = \min(D, \max(n, D_n))$.
    *   Store the final $D$ in the **swap image** [S1].

3.  **Third Transformation (Z-axis):**
    *   For each row and column, perform a single-pass zig-zag search along the z-dimension.
    *   Read from the **swap image** (output of the second transformation).
    *   Perform the same zig-zag logic as the second transformation but on the z-axis.
    *   Store the final Chebyshev distance in the **distance map** [S1].

**Pseudocode for Generation (GLSL-style):**

```glsl
// Globals
uniform uimage3D dist; // Distance map (output)
uniform uimage3D occ;  // Occupancy map (input)
uniform uimage3D swap; // Swap image (intermediate storage)
uniform ivec3 dim;     // Dimensions of the volume

// Algorithm 2: First Transformation (X-axis)
// Invoked for all columns (y) and slices (z)
void firstTransformation(ivec3 pos) {
    // pos is (0, gl_GlobalInvocationID.y, gl_GlobalInvocationID.z)
    uint D1 = imageLoad(occ, pos).x;
    
    // Forward pass
    for (int x = 1; x < dim.x; ++x) {
        ivec3 currentPos = ivec3(x, pos.y, pos.z);
        uint occVal = imageLoad(occ, currentPos).x;
        uint D = min(D1 + 1, occVal);
        imageStore(dist, currentPos, uvec4(D));
        D1 = D;
    }
    
    // Backward pass
    for (int x = dim.x - 2; x >= 0; --x) {
        ivec3 currentPos = ivec3(x, pos.y, pos.z);
        uint distVal = imageLoad(dist, currentPos).x;
        uint D = min(D1 + 1, distVal);
        imageStore(dist, currentPos, uvec4(D));
        D1 = D;
    }
}

// Algorithm 3: Second Transformation (Y-axis)
// Invoked for all rows (x) and slices (z)
void secondTransformation(ivec3 pos) {
    // pos is (gl_GlobalInvocationID.x, 0, gl_GlobalInvocationID.z)
    uint D = imageLoad(dist, pos).x;
    
    // Zig-zag search
    for (int n = 1; n < D; ++n) {
        // Check negative y direction
        if (pos.y >= n) {
            ivec3 negPos = ivec3(pos.x, pos.y - n, pos.z);
            uint Dn = imageLoad(dist, negPos).x;
            D = min(D, max(n, Dn));
        }
        // Check positive y direction
        if ((pos.y + n) < dim.y && n < D) {
            ivec3 posPos = ivec3(pos.x, pos.y + n, pos.z);
            uint Dn = imageLoad(dist, posPos).x;
            D = min(D, max(n, Dn));
        }
    }
    imageStore(swap, pos, uvec4(D));
}

// Algorithm 3 (Variant): Third Transformation (Z-axis)
// Invoked for all rows (x) and columns (y)
void thirdTransformation(ivec3 pos) {
    // pos is (gl_GlobalInvocationID.x, gl_GlobalInvocationID.y, 0)
    uint D = imageLoad(swap, pos).x;
    
    // Zig-zag search on Z axis
    for (int n = 1; n < D; ++n) {
        // Check negative z direction
        if (pos.z >= n) {
            ivec3 negPos = ivec3(pos.x, pos.y, pos.z - n);
            uint Dn = imageLoad(swap, negPos).x;
            D = min(D, max(n, Dn));
        }
        // Check positive z direction
        if ((pos.z + n) < dim.z && n < D) {
            ivec3 posPos = ivec3(pos.x, pos.y, pos.z + n);
            uint Dn = imageLoad(swap, posPos).x;
            D = min(D, max(n, Dn));
        }
    }
    imageStore(dist, pos, uvec4(D));
}
```

**Ray Traversal Step Calculation:**
During rendering, the distance $D$ is sampled from the distance map at the current ray position. The number of steps to the next sampling point is calculated to skip $D$ blocks [S1].

*   **Chebyshev Distance Definition:**
    $$D_{\text{Chebyshev}}(\mathbf{p}_1, \mathbf{p}_2) = \max(|\mathbf{p}_1 - \mathbf{p}_2|)$$
    where $\mathbf{p}_1$ and $\mathbf{p}_2$ are two points [S1].

*   **Step Calculation:**
    The number of steps $\Delta_{ij}$ to the next sampling point $D$ blocks away on dimension $j \in \{x, y, z\}$ is:
    $$
    \Delta_{ij} = 
    \begin{cases} 
    \lceil (D + \lfloor \mathbf{u}_j \rfloor - \mathbf{u}_j) / \Delta \mathbf{u}_j \rceil, & \text{if } \Delta \mathbf{u}_j > 0 \\
    \lceil (1 - D + \lfloor \mathbf{u}_j \rfloor - \mathbf{u}_j) / \Delta \mathbf{u}_j \rceil, & \text{otherwise}
    \end{cases}
    $$
    where $\mathbf{u}$ is the current ray position in block coordinates, and $\Delta \mathbf{u}$ is the ray direction in block coordinates [S1].

*   **Vectorized Form:**
    $$
    \Delta \mathbf{i} = \lceil (\text{step}(-\Delta \mathbf{u}) + \text{sgn}(\Delta \mathbf{u}) \cdot D + \lfloor \mathbf{u} \rfloor - \mathbf{u}) / \Delta \mathbf{u} \rceil
    $$
    This vectorized equation allows skipping multiple blocks with a single sample of the distance map [S1].

**Edge Cases and Pitfalls:**
*   **Memory Overhead:** The generation process requires a swap image, doubling the memory requirements compared to using only an occupancy map [S1].
*   **Distance Limit:** The use of 8-bit integers limits the maximum skip distance to 255 blocks [S1].
*   **Transfer Function Dependency:** The distance map is dependent on the transfer function. It must be regenerated whenever the transfer function changes [S2, unofficial].
*   **Initial Skip Size:** When exiting an occupied region, the initial skip distance $D$ is small. This can be suboptimal if the next occupied region is far away [S1].

## Subtopics

### Anisotropic Chebyshev Distance Map
A variant that uses separate distance maps for each of the 8 directional octants (defined by the sign of the x, y, and z components) to optimize skipping when exiting occupied regions [S1]. It is generated by modifying the isotropic transformations to scan in single directions only, requiring a total of 24 transformations (2 for the first pass, 4 for the second, reusing intermediate maps) [S1]. During traversal, the octant index is computed once based on the fixed ray direction, and the corresponding anisotropic distance map is indexed [S1]. Compared to the Extended Anisotropic Chebyshev Distance (Es and Işler [8]), which requires 24x the memory of the isotropic map, this isotropic approach uses significantly less memory while providing sufficient performance gains [S1].

## Operating characteristics
*   **Time Complexity:** The generation of the distance map involves three 1D passes. The first pass is $O(N)$ where $N$ is the number of voxels. The second and third passes involve a zig-zag search that depends on the current distance value, potentially making them slower than a simple linear pass, but still parallelizable [S1].
*   **Memory Complexity:** Requires storage for the distance map (1 byte per voxel) and a swap image (1 byte per voxel) during generation. Total 2 bytes per voxel for the acceleration structure [S1].
*   **Performance:** Achieves an average speed-up of 5.3 times the baseline frame rate [S2, unofficial].
*   **Strengths:** Allows skipping multiple blocks in any dimension, not constrained by the block size $B$ as in the occupancy map method [S1]. Efficiently parallelized on GPU [S1].
*   **Limitations:** Memory overhead due to the swap image. Limited to 255 block skips due to 8-bit storage. Requires regeneration on transfer function changes [S1][S2, unofficial].
*   **When to Use:** When the volume has large empty regions and the transfer function is static or changes infrequently. When memory bandwidth is a bottleneck and the 255-block skip limit is sufficient.
*   **When Not to Use:** When the transfer function changes frequently, as the regeneration cost may outweigh the rendering benefits. When memory is extremely constrained and the 2x overhead is unacceptable.

## Background
The technique was introduced by Deakin and Knackstedt [S1][S2, unofficial]. It builds on the work of Saito and Toriwaki [12] for transforming occupancy maps to distance maps, adapted for Chebyshev distance and GPU parallelization [S1]. The method was developed to address the limitations of the original occupancy map approach, which resumed sampling after a fixed length of empty voxels, by allowing dynamic skip distances [S1]. Deakin and Knackstedt [DK20] further improved the approach by resuming empty-space skipping after a single empty voxel instead of a fixed set length [S2, unofficial].
