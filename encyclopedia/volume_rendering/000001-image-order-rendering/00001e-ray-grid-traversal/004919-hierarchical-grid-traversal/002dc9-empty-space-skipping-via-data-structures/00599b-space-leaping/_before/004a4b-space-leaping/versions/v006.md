# Space Leaping

Also called: Fast Traversal, Skip Traversal, Space Leaping using Ray Coherence, Vikon Space Leaping System

## Overview
Space leaping is an acceleration technique for volume rendering that rapidly skips over empty or homogeneous regions of a volume to speed up rendering [S1, S3, S6, unofficial]. It solves the problem of excessive computation in large volumes where significant portions of the ray path contribute no visible information [S10, book]. Unlike sibling methods that rely on hierarchical structures like octrees or occupancy grids to define active regions, space leaping often utilizes pre-computed distance information or ray coherence to determine safe skip distances [S4, unofficial][S8]. It is particularly effective in applications like virtual endoscopy where the camera is close to the object surface, leaving large empty spaces in front of the first hit [S8].

## How it works
Space leaping avoids processing regions of a volume that will not contribute to the final image by using pre-computed data structures or coherence properties to determine how far a ray can advance without sampling [S6, unofficial][S10, book]. The method generally involves two main variants: geometry-based leaping using distance transforms (proximity clouds) and coherence-based leaping using a leap buffer [S6, unofficial][S8].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset $V$ with dimensions $D_x \times D_y \times D_z$.
    *   Transfer function $T(v)$ mapping scalar values to color and opacity.
    *   Ray parameters: origin $\mathbf{o}$ and direction $\mathbf{d}$.
    *   Pre-computed acceleration data: either a distance transform volume $D$ (for proximity clouds) or a leap buffer $L$ (for ray coherence) [S7, unofficial][S8].
*   **Outputs:**
    *   Final pixel color and accumulated opacity.

### Data Structures

#### 1. Proximity Cloud (Distance Transform)
A 3D volume $D$ of the same resolution as $V$, where each cell stores the Euclidean or Manhattan distance to the nearest "opaque" or "active" voxel.
*   **Layout:** Array of floats or integers.
*   **Value:** $D[i,j,k] = \min_{(i',j',k') \in \text{Active}} \text{dist}((i,j,k), (i',j',k'))$ [S7, unofficial].
*   **Active Voxel:** A voxel where $T(V[i,j,k]) > \epsilon$ [G].

#### 2. Leap Buffer
A 2D buffer $L$ of size $N_x \times N_y$ (image plane resolution), storing the number of samples a detector ray took to reach the first non-empty cell [S8].
*   **Layout:** Array of integers.
*   **Value:** $L[u,v]$ = count of empty samples between image plane and first hit for pixel $(u,v)$ [S8].

### Algorithm Steps

#### Variant A: Proximity Cloud / Distance Transform
This method uses a pre-computed distance field to skip empty space [S7, unofficial].

1.  **Preprocessing:** Compute the distance transform $D$ for the volume. For every empty voxel, calculate the distance to the nearest active voxel [S7, unofficial].
2.  **Ray Initialization:** Start ray at $\mathbf{p} = \mathbf{o}$.
3.  **Sampling Loop:**
    a. Sample volume value $v = V(\mathbf{p})$.
    b. If $v$ is active (opacity $> \epsilon$), proceed with standard ray casting integration [S1, unofficial].
    c. If $v$ is empty:
        i. Retrieve skip distance $s = D(\mathbf{p})$ [S7, unofficial].
        ii. Advance ray: $\mathbf{p} \leftarrow \mathbf{p} + s \cdot \mathbf{d}$ [S7, unofficial].
        iii. Clamp $\mathbf{p}$ to volume bounds.
4.  **Termination:** Stop when ray exits volume or accumulated opacity exceeds threshold [S1, unofficial].

#### Variant B: Ray Coherence (Leap Buffer)
This method, used in the Vikon system, exploits temporal coherence and ray coherence to skip empty space [S8].

1.  **Leap Buffer Construction (Per Frame/View):**
    a. Cast a sparse set of "space leap rays" (e.g., one out of every 4 rays) from the image plane into the volume [S8].
    b. For each leap ray, find the first sample point inside an active cell [S8].
    c. Store the number of empty samples traversed in the leap buffer $L$ at the corresponding pixel coordinates [S8].
    d. **Boundary Condition:** If the leap buffer value is zero, do not leap; the ray hits an active cell immediately [S8].
2.  **Rendering Loop (Per Pixel):**
    a. Retrieve skip count $k = L[u,v]$ for pixel $(u,v)$ [S8].
    b. If $k > 0$:
        i. Advance ray by $k$ samples: $\mathbf{p} \leftarrow \mathbf{p} + k \cdot \Delta \mathbf{d}$ [S8].
        ii. **Backtracking Check:** If the new position $\mathbf{p}$ is inside a non-empty cell, backtrack the ray until it is inside an empty cell, ensuring not to go beyond the leap buffer value (which would place the ray behind the image plane) [S8].
    c. Perform standard ray casting from $\mathbf{p}$ until the ray exits the volume or opacity threshold is reached [S8].

### Parameters
*   **Opacity Threshold ($\epsilon$):** Minimum opacity to consider a voxel active. Typical values: $0.01$ to $0.05$ [G].
*   **Leap Ray Density:** In the Vikon system, one out of every 4 rays is used for leap buffer construction, achieving 75% of possible acceleration [S8].

### Edge Cases and Pitfalls
*   **Transfer Function Changes:** Content-based space leaping (using proximity clouds) requires extensive re-computation of the distance transform whenever the transfer function changes [S6, S7, unofficial].
*   **High-Frequency Data:** Techniques break down on datasets with high-frequency information (e.g., ultrasound) where most voxels are relevant, causing rendering times to increase rather than decrease [S9][S10, book].
*   **Boundary Misses:** Standard space leaping may miss objects projecting only on boundary pixels. This is addressed by the Boundary Pixel Detector Ray Casting variant, which treats all boundary pixels as mandatory detector pixels [S2, 5870-boundary-pixel-detector-ray-casting.md, unofficial].
*   **Leap Buffer Zero:** If the leap buffer value is zero, the space leap ray should not be leaped at all [S8].
*   **Post-Object Space:** Space leaping is only possible between the image plane and the first object hit; empty space beyond the first hit cannot be leaped in the coherence-based method [S8].

## Subtopics

### [Boundary Pixel Detector Ray Casting](5870-boundary-pixel-detector-ray-casting.md)
Boundary Pixel Detector Ray Casting is a safety mechanism within Space Leaping that ensures objects projecting only on boundary pixels are not missed by considering all boundary pixels as detector pixels. It distinguishes itself from standard space leaping by treating all image boundary pixels as mandatory detector pixels, preventing the algorithm from leaping over objects located at the periphery of the view frustum.

## Operating characteristics
*   **Time Complexity:**
    *   Base volume rendering complexity is $O(n^3)$ where $n$ is the volume dimension [S10, book].
    *   Leap Buffer Construction: $O(N^2)$ where $N \times N$ is the image plane size, as it scans the buffer once [S8].
    *   Rendering: Depends on the density of active voxels. In sparse volumes, speedups are significant; in dense volumes, performance may degrade due to overhead [S9][S10, book].
*   **Memory Complexity:**
    *   Proximity Cloud: $O(n^3)$ for the distance volume [S10, book].
    *   Leap Buffer: $O(N^2)$ for the 2D buffer [S8].
*   **Measured Performance:**
    *   Speedups of up to 165% over non-space leap ray casting were achieved on a Pentium-IV, 2.6GHz PC with 1GB RAM and Linux OS [S8].
    *   Memory usage for leap buffer was 256x256 bytes for tested datasets [S8].
*   **Strengths:**
    *   Ideal for virtual endoscopy and applications requiring camera placement close to object surface [S8].
    *   Low memory overhead for the leap buffer variant ($O(N^2)$) [S8].
*   **Limitations:**
    *   Cannot achieve as much empty space skipping as techniques using data structures for empty/non-empty voxel info (e.g., octrees) because it only leaps one out of every 4 rays in the coherence variant, getting 75% of possible acceleration [S8].
    *   Performance is classification dependent; changes to opacity transfer function require lengthy re-computation for content-based methods [S6, S7, unofficial].
    *   Ineffective for volumes with high percentage of relevant voxels (e.g., shockwave dataset) [S9].

## Background
Space leaping was introduced as a method to efficiently traverse or skip empty space in volume rendering [S5, unofficial]. The original approach utilized hierarchical spatial data structures like octrees or flat pyramids [S1, S5, unofficial]. The concept of using proximity clouds (distance transforms) was also explored early on [S5, unofficial]. The Vikon system incorporated a specific space leaping acceleration technique using ray coherence (leap buffers) for perspective direct volume rendering, specifically for endoscopy applications like Virtual Colonoscopy [S8]. The technique is listed as a powerful method for raycasting alongside bounding volumes and multi-resolution grid traversal [S9].
