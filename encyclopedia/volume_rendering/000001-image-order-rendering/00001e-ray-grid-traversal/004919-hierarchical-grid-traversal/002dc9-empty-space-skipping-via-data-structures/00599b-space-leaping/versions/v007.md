# Space Leaping


## Overview
Space leaping is an acceleration technique for volume rendering that rapidly skips over empty or homogeneous regions of a volume to speed up rendering [S1][S6, unofficial]. It solves the problem of excessive computation in large volumes where significant portions of the ray path contribute no visible information [S10]. Unlike sibling methods that rely on hierarchical structures like octrees or occupancy grids to define active regions, space leaping often utilizes pre-computed distance information or ray coherence to determine safe skip distances [S4, unofficial][S8, unofficial]. It is particularly effective in applications like virtual endoscopy where the camera is close to the object surface, leaving large empty spaces in front of the first hit [S8, unofficial].

## How it works
Space leaping avoids processing regions of a volume that will not contribute to the final image by using pre-computed data structures or coherence properties to determine how far a ray can advance without sampling [S6, unofficial][S10]. The technique implements distance-based skipping for empty cells or coherence-based skipping using a per-pixel leap buffer [S7, unofficial][S8, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Volume dataset $V$ with dimensions $D_x \times D_y \times D_z$ [G].
    *   Transfer function $T(v)$ mapping scalar values to color and opacity [G].
    *   Ray parameters: origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].
    *   Pre-computed acceleration data: either a distance transform volume $D$ (for proximity clouds) or a leap buffer $L$ (for ray coherence) [S7, unofficial][S8, unofficial].
*   **Outputs:**
    *   Final pixel color and accumulated opacity [G].

### Data Structures

#### 1. Proximity Cloud (Distance Transform)
A 3D volume $D$ of the same resolution as $V$, where each empty cell stores the distance to the nearest opaque cell [S7, unofficial][S8, unofficial].
*   **Layout:** Array of floats or integers matching the volume grid.
*   **Value:** $D[i,j,k]$ encodes the distance that can be safely skipped along any ray sampling the empty cell at $(i,j,k)$ [S8, unofficial].
*   **Opaque Cell:** A voxel where $T(V[i,j,k]) > \epsilon$ [G].

#### 2. Leap Buffer
A 2D buffer $L$ of size $N_x \times N_y$ (image plane resolution), storing the number of samples a detector ray took to reach the first non-empty cell [S8, unofficial].
*   **Layout:** Array of integers.
*   **Value:** $L[u,v]$ = count of empty samples between image plane and first hit for pixel $(u,v)$ [S8, unofficial].

### Algorithm Steps

1.  **Preprocessing:** Compute the distance transform $D$ for the volume. For every empty voxel, calculate the distance to the nearest active voxel [S1][S7, unofficial].
2.  **Leap Buffer Construction (Per Frame/View):** Cast a sparse set of space leap rays (e.g., one out of every 4 rays) from the image plane into the volume [S8, unofficial]. For each leap ray, find the first sample point inside an active cell and store the number of empty samples traversed in $L$ at the corresponding pixel coordinates [S8, unofficial].
3.  **Ray Initialization:** Start ray at $\mathbf{p} = \mathbf{o}$ [G].
4.  **Sampling Loop:**
    a. Sample volume value $v = V(\mathbf{p})$.
    b. If $v$ is active (opacity $> \epsilon$), proceed with standard ray casting integration [S1].
    c. If $v$ is empty:
        i. Retrieve skip distance $s = D(\mathbf{p})$ [S7, unofficial].
        ii. Advance ray: $\mathbf{p} \leftarrow \mathbf{p} + s \cdot \mathbf{d}$ [S7, unofficial].
        iii. Clamp $\mathbf{p}$ to volume bounds.
5.  **Termination:** Stop when ray exits volume or accumulated opacity exceeds threshold [G].

### Pseudocode
```python
def space_leap_render(volume, acceleration_data, ray_origin, ray_direction, image_plane, opacity_threshold):
    # acceleration_data: dict containing 'distance_transform' or 'leap_buffer'
    ray_step = 1.0  # Normalized step size per voxel
    max_t = compute_max_t(ray_origin, ray_direction, volume.bounds)

    for u, v in image_plane:
        accumulated_opacity = 0.0
        pixel_color = (0.0, 0.0, 0.0)
        t = 0.0

        # Leap Buffer Initialization (Variant B)
        if 'leap_buffer' in acceleration_data:
            skip_count = acceleration_data['leap_buffer'][u, v]
            if skip_count > 0:
                t = skip_count * ray_step
                # Backtrack if initial leap lands inside non-empty cell
                while t > 0 and volume.is_occupied(ray_origin + t * ray_direction):
                    t -= ray_step
                # Do not backtrack beyond original skip count to stay in front of image plane
                if t < 0:
                    t = 0.0
            else:
                t = 0.0

        # Main Traversal Loop
        while t < max_t and accumulated_opacity < opacity_threshold:
            p = ray_origin + t * ray_direction
            cell_idx = volume.world_to_index(p)

            if not volume.is_occupied(cell_idx):
                # Variant A: Proximity Cloud / Distance Transform
                if 'distance_transform' in acceleration_data:
                    skip_dist = acceleration_data['distance_transform'][cell_idx]
                    t += skip_dist
                else:
                    t += ray_step
            else:
                # Standard sampling and front-to-back compositing
                val = volume.read(cell_idx)
                op = transfer_function(val).opacity
                col = transfer_function(val).color
                pixel_color = pixel_color + col * op * (1.0 - accumulated_opacity)
                accumulated_opacity += op * (1.0 - accumulated_opacity)
                t += ray_step

        image_plane[u, v].color = pixel_color
        image_plane[u, v].opacity = accumulated_opacity
```

### Parameters
*   **Opacity Threshold ($\epsilon$):** Minimum opacity to consider a voxel active. Typical values: $0.01$ to $0.05$ [G].
*   **Leap Ray Density:** In the Vikon system, one out of every 4 rays is used for leap buffer construction, achieving 75% of possible acceleration [S8, unofficial].

### Edge Cases and Pitfalls
*   **Transfer Function Changes:** Content-based space leaping (using proximity clouds) requires extensive re-computation of the distance transform whenever the transfer function changes [S6, S7, unofficial].
*   **High-Frequency Data:** Techniques break down on datasets with high-frequency information (e.g., ultrasound) where most voxels are relevant, causing rendering times to increase rather than decrease [S9][S10].
*   **Boundary Misses:** Standard space leaping may miss objects projecting only on boundary pixels. This is addressed by the Boundary Pixel Detector Ray Casting variant, which treats all boundary pixels as mandatory detector pixels [S1][S2, unofficial].
*   **Leap Buffer Zero:** If the leap buffer value is zero, the space leap ray should not be leaped at all [S8, unofficial].
*   **Post-Object Space:** Space leaping is only possible between the image plane and the first object hit; empty space beyond the first hit cannot be leaped in the coherence-based method [S8, unofficial].

## Subtopics

### [Boundary Pixel Detector Ray Casting](5870-boundary-pixel-detector-ray-casting.md)
Boundary Pixel Detector Ray Casting is a safety mechanism within Space Leaping that ensures objects projecting only on boundary pixels are not missed by considering all boundary pixels as detector pixels. It distinguishes itself from standard space leaping by treating all image boundary pixels as mandatory detector pixels, preventing the algorithm from leaping over objects located at the periphery of the view frustum.

### Leap Buffer Boundary Condition Handling
The leap buffer stores the number of samples the detector ray took to reach a non-empty cell, where the sample before that is the last sample in an empty cell [S8, unofficial]. If the leap buffer value is zero, the space leap ray should not be leaped at all [S8, unofficial].

### Hierarchical Box Space Leaping
The simplest form of space leaping for empty space, facilitated by enclosing the object into a set of boxes, possibly hierarchical [S13, book]. The algorithm quickly determines and tests the rays' intersection with each of the boxes before engaging in more time-consuming volumetric traversal of the material within only if the ray intersects the box [S13, book].

## Operating characteristics
*   **Time Complexity:**
    *   Base volume rendering complexity is $O(n^3)$ where $n$ is the volume dimension [S10].
    *   Leap Buffer Construction: $O(N^2)$ where $N \times N$ is the image plane size, as it scans the buffer once [S8, unofficial].
    *   Rendering: Depends on the density of active voxels. In sparse volumes, speedups are significant; in dense volumes, performance may degrade due to overhead [S9][S10].
*   **Memory Complexity:**
    *   Proximity Cloud: $O(n^3)$ for the distance volume [S10].
    *   Leap Buffer: $O(N^2)$ for the 2D buffer [S8, unofficial].
*   **Measured Performance:**
    *   Speedups of up to 165% over non-space leap ray casting were achieved on a Pentium-IV, 2.6GHz PC with 1GB RAM and Linux OS [S8, unofficial].
    *   Memory usage for leap buffer was 256x256 bytes for tested datasets [S8, unofficial].
*   **Strengths:**
    *   Ideal for virtual endoscopy and applications requiring camera placement close to object surface [S8, unofficial].
    *   Low memory overhead for the leap buffer variant ($O(N^2)$) [S8, unofficial].
*   **Limitations:**
    *   Cannot achieve as much empty space skipping as techniques using data structures for empty/non-empty voxel info (e.g., octrees) because it only leaps one out of every 4 rays in the coherence variant, getting 75% of possible acceleration [S8, unofficial].
    *   Performance is classification dependent; changes to opacity transfer function require lengthy re-computation for content-based methods [S6, S7, unofficial].
    *   Ineffective for volumes with high percentage of relevant voxels (e.g., shockwave dataset) [S9].

## Background
Space leaping was introduced as a method to efficiently traverse or skip empty space in volume rendering [S5, unofficial]. The original approach utilized hierarchical spatial data structures like octrees or flat pyramids [S1][S5, unofficial]. The concept of using proximity clouds (distance transforms) was also explored early on [S5, unofficial]. The Vikon system incorporated a specific space leaping acceleration technique using ray coherence (leap buffers) for perspective direct volume rendering, specifically for endoscopy applications like Virtual Colonoscopy [S8, unofficial]. The technique is listed as a powerful method for raycasting alongside bounding volumes and multi-resolution grid traversal [S9].
