# Boundary Pixel Detector Ray Casting

Also called: Boundary Pixel Detection

## Overview
Boundary Pixel Detector Ray Casting is a safety mechanism within Space Leaping [5863-space-leaping.md] that ensures volumetric objects projecting exclusively onto the edges of the image buffer are not erroneously skipped. It distinguishes itself from standard space leaping by treating all image boundary pixels as mandatory "detector pixels," preventing the algorithm from leaping over objects located at the periphery of the view frustum.

## How it works
**Inputs and Outputs:**
*   **Input:** The image buffer dimensions (width $W$, height $H$), the current state of the leap buffer (tracking which pixels have been processed or leaped over), and the ray generation logic for space leaping.
*   **Output:** A set of detector rays originating from boundary pixels that are guaranteed to intersect any volumetric data present at the image edges, ensuring no cell groups are missed.

**Data Structures:**
*   **Leap Buffer:** A 2D array of size $W \times H$. Each entry corresponds to a pixel in the image buffer. The specific bit-packing or data type is not defined in the sources, but it serves to track the status of space leap rays (e.g., whether a ray has been shot, whether an object was found, or if the ray has leaped past a cell group).

**Steps:**
1.  **Identify Boundary Pixels:** Determine all pixels $(x, y)$ in the image buffer where $x = 0$, $x = W-1$, $y = 0$, or $y = H-1$.
2.  **Mark as Detector Pixels:** Explicitly designate all identified boundary pixels as "detector pixels." These pixels are excluded from the standard space-leaping logic that might skip them if they are occluded by foreground objects.
3.  **Shoot Detector Rays:** For every pixel identified in Step 1, generate and shoot a detector ray into the volume.
4.  **Populate Leap Buffer:** Record the results of these detector rays in the leap buffer. This ensures that any object intersecting the boundary pixels is registered as "found" or "processed," preventing the algorithm from leaping over the cell group containing that object.

**Pseudocode:**

**Edge Cases and Pitfalls:**
*   **Missing Boundary Objects:** If detector rays are *not* shot from boundary pixels, a cell group projecting only onto the boundary may be leaped over and missed if the detector rays around its projection intersect another cell group further away [S1].
*   **First Sample Rule:** While not specific to boundary pixels alone, the general space leaping technique requires that the first sample of a space leap ray be in an empty cell to avoid missing non-transparent sample points [S1, S2]. Boundary detector rays must adhere to this to ensure correctness.

## Subtopics

### Backtracking Space Leap Rays
*   **What it is:** A rule applied to space leap rays to ensure they do not leap beyond an object boundary inside a cell group.
*   **Distinction:** It focuses on intra-cell-group accuracy rather than inter-cell-group skipping.
*   **When to choose:** When ensuring that no non-transparent sample points are missed within a single cell group during the leap process.
*   **Link:** [Backtracking Space Leap Rays](5863-backtracking-space-leap-rays.md)

## Operating characteristics
*   **Time Complexity:** Adds $O(W + H)$ ray shoots per frame, where $W$ and $H$ are image dimensions. This is negligible compared to the total $W \times H$ rays.
*   **Memory Complexity:** No additional memory beyond the existing leap buffer.
*   **Strengths:** Guarantees visual correctness at image boundaries, preventing artifacts where objects disappear at the screen edges.
*   **Limitations:** Slightly increases ray count; however, the cost is minimal.
*   **When to use:** Always, when using Space Leaping techniques that rely on skipping empty space, to prevent boundary artifacts.

## Background
*   **Origin:** Introduced in "Light Weight Space Leaping using Ray Coherence" by Lakare et al. (2004) [S1, S2].
*   **History:** Developed to address a specific flaw in early space leaping implementations where objects at the periphery of the view were incorrectly skipped due to the coherence-based skipping logic.
*   **Usage:** Used in high-performance volume rendering systems that employ ray coherence and space leaping to optimize rendering speed.
