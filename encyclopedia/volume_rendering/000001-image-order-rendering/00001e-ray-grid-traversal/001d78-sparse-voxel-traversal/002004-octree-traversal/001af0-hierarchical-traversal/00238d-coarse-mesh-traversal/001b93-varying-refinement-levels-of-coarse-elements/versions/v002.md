# Varying Refinement Levels of Coarse Elements

Also called: Coarse mesh refinement level variation, Inserting refinement levels into coarse mesh

## Overview
This method optimizes hierarchical volume rendering by controlling the granularity of the coarse mesh used for bounding volume hierarchy (BVH) construction and macrocell-based optimizations [S1]. It solves the trade-off between BVH traversal efficiency and the overhead of traversing the underlying refinement tree (e.g., TET-AMR) by selecting which level of the refinement hierarchy is promoted to the coarse mesh [S1]. Unlike sibling methods such as [Leaf Collection](899-leaf-collection.md), [Point Plane Test Traversal](982-point-plane-test-traversal.md), [Coarse Mesh Traversal with Dual-Ray Culling](987-coarse-mesh-traversal-with-dual-ray-culling.md), [Two-level Nested Ray Marching](1045-two-level-nested-ray-marching.md), [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md), [Octree-based Volume Rendering](1131-octree-based-volume-rendering.md), [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md), and [CPU Sparse Voxel Octree Traversal](2455-cpu-sparse-voxel-octree-traversal.md), this approach explicitly varies the refinement level inserted into the coarse mesh to balance macrocell tightness against BVH node count [S1].

## How it works
**Inputs:**
*   A hierarchical dataset with a refinement tree (e.g., TET-AMR) where elements exist at multiple refinement levels (0 to $L_{max}$) [S1].
*   A target refinement level $k$ for the coarse mesh [S1].
*   A renderer configuration (e.g., Ray Marcher, Woodcock tracking) with optional macrocell optimizations [S1].

**Outputs:**
*   A coarse mesh containing elements from refinement level $k$ (or leaves if they are finer than $k$) [S1].
*   A BVH built over this coarse mesh [S1].
*   Rendering performance metrics [S1].

**Data Structures:**
*   **Coarse Mesh:** A collection of geometric primitives (tetrahedra or faces) representing the bounding volumes for BVH nodes [S1]. The size of this mesh is determined by the number of elements at level $k$ in the refinement tree [S1].
*   **BVH:** A bounding volume hierarchy built over the coarse mesh elements [S1]. The source specifies using 4 faces per element in the BVH construction [S1].

**Algorithm:**
1.  **Traverse Refinement Tree:** For each root or relevant parent in the refinement tree, traverse its children [S1].
2.  **Select Element:** Continue traversing down the tree until an element is reached that is either at the desired refinement level $k$ or a leaf element [S1].
3.  **Add to Coarse Mesh:** Insert the selected element into the coarse mesh structure [S1].
4.  **Build BVH:** Construct the BVH using the elements in the coarse mesh [S1]. The source notes the use of 4 faces per element for BVH construction [S1].
5.  **Render:** Perform volume rendering using the selected renderer (Ray Marcher or Woodcock) with or without macrocell optimizations [S1].

**Parameters:**
*   **Refinement Level ($k$):** The level of the refinement tree to insert into the coarse mesh [S1]. Typical values tested are integers $0$ to $5$ [S1].
*   **Macrocell Optimization:** A boolean flag enabling or disabling macrocell-based culling/optimizations [S1].

**Edge Cases and Pitfalls:**
*   **BVH Efficiency:** Increasing the number of elements in the coarse mesh (higher $k$) decreases BVH efficiency and reduces the maximum traversal depth in the TET-AMR traversal process [S1]. This can negatively impact performance if the BVH overhead outweighs the benefits of reduced refinement tree traversal [S1].
*   **Leaf Handling:** The algorithm must correctly handle leaf nodes [G]. If a leaf is at a level finer than $k$, it is still added to the coarse mesh, potentially increasing the coarse mesh size more than expected [S1].

**Pseudocode:**
```python
def build_coarse_mesh(refinement_tree, target_level):
    """
    Builds a coarse mesh by traversing the refinement tree and selecting
    elements at the target refinement level or leaf nodes.
    
    Args:
        refinement_tree: The root of the refinement tree structure.
        target_level: The integer refinement level to target.
        
    Returns:
        coarse_mesh: A list of geometric elements (faces/tetrahedra)
                     suitable for BVH construction.
    """
    coarse_mesh = []
    
    def traverse(node, current_level):
        # If the node is a leaf, add it to the coarse mesh
        if node.is_leaf():
            coarse_mesh.append(node.element)
            return
        
        # If the current level matches the target level, add this element
        if current_level == target_level:
            coarse_mesh.append(node.element)
            return
        
        # If the current level is finer than target, continue to children
        if current_level < target_level:
            for child in node.children:
                traverse(child, current_level + 1)
        # If current_level > target_level, stop (should not happen in standard traversal)
        
    # Start traversal from root
    traverse(refinement_tree, 0)
    
    return coarse_mesh
```

## Operating characteristics
**Time and Memory Complexity:**
*   The number of elements in the coarse mesh (and thus the BVH) grows exponentially with the refinement level $k$ [S1]. For the Uniform Engine dataset, the number of elements increases from 6 at level 0 to 196,608 at level 5 [S1]. For the Engine dataset, it increases from 5,177 at level 0 to 14,402,140 at level 5 [S1].
*   BVH construction and traversal time increase with the number of elements, but the efficiency of the BVH decreases as the number of elements increases [S1].

**Measured Performance:**
*   **Engine Dataset:**
    *   Ray Marcher with macrocell: Level 0 (41.47 ms), Level 1 (45.72 ms), Level 2 (50 ms), Level 3 (53.31 ms), Level 4 (62.45 ms), Level 5 (87.77 ms) [S1].
    *   Ray Marcher without macrocell: Level 0 (41.12 ms), Level 1 (45.53 ms), Level 2 (50.43 ms), Level 3 (54.69 ms), Level 4 (54.69 ms), Level 5 (84.02 ms) [S1].
    *   Woodcock with macrocell: Level 0 (7.14 ms), Level 1 (11.07 ms), Level 2 (18.46 ms), Level 3 (33.18 ms), Level 4 (56.65 ms), Level 5 (94.97 ms) [S1].
    *   Woodcock without macrocell: Level 0 (14.70 ms), Level 1 (16.11 ms), Level 2 (16.11 ms), Level 3 (18.52 ms), Level 4 (21.00 ms), Level 5 (21.00 ms) [S1].
*   **Uniform Engine Dataset:**
    *   Ray Marcher with macrocell: Level 0 (78.58 ms), Level 1 (75.8 ms), Level 2 (80.7 ms), Level 3 (93.18 ms), Level 4 (101.84 ms), Level 5 (99.81 ms) [S1].
    *   Ray Marcher without macrocell: Level 0 (77.61 ms), Level 1 (75 ms), Level 2 (79.69 ms), Level 3 (91.93 ms), Level 4 (101.16 ms), Level 5 (100.96 ms) [S1].
    *   Woodcock with macrocell: Level 0 (10.72 ms), Level 1 (9.57 ms), Level 2 (9.56 ms), Level 3 (12.80 ms), Level 4 (22.04 ms), Level 5 (43.80 ms) [S1].
    *   Woodcock without macrocell: Level 0 (24.99 ms), Level 1 (26.66 ms), Level 2 (30.91 ms), Level 3 (33.09 ms), Level 4 (32.13 ms), Level 5 (29.30 ms) [S1].

**Strengths and Limitations:**
*   **Strengths:** Can improve performance for specific datasets (e.g., Uniform Engine at level 1) by reducing refinement tree traversal depth, even if BVH overhead increases [S1]. Macrocell optimizations can significantly improve Woodcock tracker performance at levels 1 and 2 for Uniform Engine due to tighter majorants [S1].
*   **Limitations:** Increasing coarse mesh elements generally decreases BVH efficiency and can hurt performance (e.g., Engine dataset) [S1]. The optimal level depends heavily on the dataset structure and renderer type [S1].

**When to Use:**
*   Use when the refinement tree has a large depth and reducing traversal depth is beneficial (e.g., Uniform Engine at level 1) [S1].
*   Use with Woodcock tracking and macrocell optimizations when smaller macrocells can provide tighter majorants (e.g., Uniform Engine at levels 1 and 2) [S1].

**When Not to Use:**
*   Avoid for datasets where BVH efficiency is critical and increasing coarse mesh elements leads to significant performance degradation (e.g., Engine dataset) [S1].

## Background
This method was proposed in the context of direct volume rendering of tree-based tetrahedral adaptive mesh refinement (TET-AMR) data [S1]. The research explores how different levels of the refinement hierarchy can be used to construct a coarse mesh for BVH-based acceleration, balancing the costs of BVH traversal against refinement tree traversal [S1]. The work is part of a broader effort to optimize volume rendering for complex, multi-resolution scientific data [S1].
