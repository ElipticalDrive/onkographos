# Parametric Octree Traversal

Also called: An efficient parametric algorithm for octree traversal, Revelles 2000, Revelles Octree Traversal, Revelles' algorithm

## Overview
Parametric Octree Traversal is a top-down ray-octree traversal algorithm that uses parametric interval arithmetic to determine which child nodes of an octree node are intersected by a ray, handling non-uniform octree depths [S1, S2]. It sets itself apart from bottom-up approaches (like DDA traversal) by performing a depth-first search that computes entry and exit parametric times ($t$) for the bounding box, allowing it to skip empty subtrees without requiring a fixed tree depth or explicit stack management for the traversal order itself [S1, S2].

## How it works
### Inputs and Outputs
**Inputs:**
*   `octree`: A Sparse Voxel Octree structure containing:
    *   `min[3]`: The minimum coordinates of the octree's bounding box [S1, S2].
    *   `max[3]`: The maximum coordinates of the octree's bounding box [S1, S2].
    *   `center[3]`: The center coordinates of the octree's bounding box, used for mirroring ray origins [S1, S2].
    *   `root`: A pointer to the root `Node` [S1, S2].
*   `ray`: A ray defined by:
    *   `origin[3]`: The starting point of the ray [S1, S2].
    *   `direction[3]`: The direction vector of the ray [S1, S2].

**Outputs:**
*   Traversal of all nodes intersected by the ray, processing leaf nodes as defined by the application (e.g., volume sampling) [S1, S2].

### Data Structures
**Node Structure:**
*   `terminal` (bool): Indicates if the node is a leaf [S1, S2].
*   `debug_ID` (int): Identifier for debugging (optional, not required for traversal logic) [S1, S2].
*   `children` (array of 8 `Node*` pointers): Pointers to the 8 child nodes, indexed 0–7 [S1, S2]. If a child does not exist, the pointer is `nullptr` (or handled as empty) [S1].

### Parameters
*   `a` (unsigned char, 8 bits): A bitmask used to track coordinate system transformations for rays with negative direction components [S1, S2]. Bit 0 corresponds to Z-axis inversion, bit 1 to Y-axis inversion, and bit 2 to X-axis inversion [S1, S2].

### Steps

1.  **Initialize and Normalize Ray Direction:**
    Initialize `a = 0`. For each axis $i \in \{0, 1, 2\}$ (X, Y, Z):
    *   If `ray.direction[i] < 0`:
        *   Mirror the origin: `ray.origin[i] = octree.center[i] * 2 - ray.origin[i]` [S1, S2].
        *   Negate the direction: `ray.direction[i] = -ray.direction[i]` [S1, S2].
        *   Set the corresponding bit in `a`:
            *   Axis 0 (X): `a |= 4` [S1, S2].
            *   Axis 1 (Y): `a |= 2` [S1, S2].
            *   Axis 2 (Z): `a |= 1` [S1, S2].

2.  **Compute Inverse Directions:**
    Calculate inverse direction components for stability:
    $$
    \begin{aligned}
    divx &= 1 / ray.direction[0] \\
    divy &= 1 / ray.direction[1] \\
    divz &= 1 / ray.direction[2]
    \end{aligned}
    $$
    Division by zero or near-zero direction components relies on IEEE floating-point behavior (producing infinity/NaN) [S1]. Robust implementations may require explicit checks or clamping [S1, S2].

3.  **Compute Parametric Bounds for Octree:**
    Calculate the parametric entry ($t_0$) and exit ($t_1$) times for the octree's bounding box along each axis:
    $$
    \begin{aligned}
    tx0 &= (octree.min[0] - ray.origin[0]) \times divx \\
    tx1 &= (octree.max[0] - ray.origin[0]) \times divx \\
    ty0 &= (octree.min[1] - ray.origin[1]) \times divy \\
    ty1 &= (octree.max[1] - ray.origin[1]) \times divy \\
    tz0 &= (octree.min[2] - ray.origin[2]) \times divz \\
    tz1 &= (octree.max[2] - ray.origin[2]) \times divz
    \end{aligned}
    $$
    [S1, S2]

4.  **Check Intersection with Octree:**
    Determine if the ray intersects the octree bounding box:
    $$
    \max(\max(tx0, ty0), tz0) < \min(\min(tx1, ty1), tz1)
    $$
    [S2] If false, the ray misses the octree entirely; terminate [S2]. If true, call `proc_subtree(tx0, ty0, tz0, tx1, ty1, tz1, octree.root)` [S1].

5.  **Recursive Traversal (`proc_subtree`):**
    The function `proc_subtree(tx0, ty0, tz0, tx1, ty1, tz1, node)` traverses the subtree rooted at `node` within the parametric bounds $[tx0, tx1] \times [ty0, ty1] \times [tz0, tz1]$ [S1, S2].

    **Step 5.1: Termination Conditions**
    *   If `tx1 < 0` or `ty1 < 0` or `tz1 < 0`, return (the ray has exited the volume behind the origin) [S1, S2].
    *   If `node` is `terminal` (leaf), process the leaf (e.g., sample volume) and return [S1, S2].

    **Step 5.2: Compute Midpoints**
    Calculate the parametric midpoints for the current node's bounds:
    $$
    \begin{aligned}
    txm &= 0.5 \times (tx0 + tx1) \\
    tym &= 0.5 \times (ty0 + ty1) \\
    tzm &= 0.5 \times (tz0 + tz1)
    \end{aligned}
    $$
    [S1, S2]

    **Step 5.3: Determine First Child**
    Call `first_node(tx0, ty0, tz0, txm, tym, tzm)` to determine the index of the first child to visit [S2]. This function selects the entry plane (YZ, XZ, or XY) based on which entry time ($tx0, ty0, tz0$) is largest and sets bits based on whether the midpoints are less than the entry times [S1, S2].

    **Step 5.4: Iterate Through Children**
    Use a `do-while` loop to visit all intersected children [S1]. Let `currNode` be the index returned by `first_node` [S1].
    $$
    \text{do } \{ \dots \} \text{ while } (currNode < 8)
    $$
    Inside the loop, switch on `currNode` to recurse into the appropriate child and update `currNode` for the next iteration using `new_node` [S1, S2]. The child index is accessed as `node->children[child_idx ^ a]` to account for axis inversions [S1, S2]. The bounds passed to the recursive call are determined by the child's position relative to the midpoints ($txm, tym, tzm$) [S1].

    *   **Case 0 (YZ plane entry):**
        *   Recurse: `proc_subtree(tx0, ty0, tz0, txm, tym, tzm, node->children[a])`
        *   Next: `currNode = new_node(txm, 4, tym, 2, tzm, 1)`
    *   **Case 1 (YZ plane entry):**
        *   Recurse: `proc_subtree(tx0, ty0, tzm, txm, tym, tz1, node->children[1^a])`
        *   Next: `currNode = new_node(txm, 5, tym, 3, tz1, 8)`
    *   **Case 2 (XZ plane entry):**
        *   Recurse: `proc_subtree(tx0, tym, tz0, txm, ty1, tzm, node->children[2^a])`
        *   Next: `currNode = new_node(txm, 6, ty1, 8, tzm, 3)`
    *   **Case 3 (XZ plane entry):**
        *   Recurse: `proc_subtree(tx0, tym, tzm, txm, ty1, tz1, node->children[3^a])`
        *   Next: `currNode = new_node(txm, 7, ty1, 8, tz1, 8)`
    *   **Case 4 (XY plane entry):**
        *   Recurse: `proc_subtree(txm, ty0, tz0, tx1, tym, tzm, node->children[4^a])`
        *   Next: `currNode = new_node(tx1, 8, tym, 6, tzm, 5)`
    *   **Case 5 (XY plane entry):**
        *   Recurse: `proc_subtree(txm, ty0, tzm, tx1, tym, tz1, node->children[5^a])`
        *   Next: `currNode = new_node(tx1, 8, tym, 7, tz1, 8)`
    *   **Case 6 (XY plane entry):**
        *   Recurse: `proc_subtree(txm, tym, tz0, tx1, ty1, tzm, node->children[6^a])`
        *   Next: `currNode = new_node(tx1, 8, ty1, 8, tzm, 7)`
    *   **Case 7 (XY plane entry):**
        *   Recurse: `proc_subtree(txm, tym, tzm, tx1, ty1, tz1, node->children[7^a])`
        *   Next: `currNode = 8` (terminates loop)

    **Helper Functions:**
    *   `first_node(tx0, ty0, tz0, txm, tym, tzm)`:
        *   Initialize `answer = 0`.
        *   If `tx0 > ty0`:
            *   If `tx0 > tz0` (YZ plane):
                *   If `tym < tx0`, `answer |= 2`.
                *   If `tzm < tx0`, `answer |= 1`.
                *   Return `answer`.
            *   Else (XZ plane, since `ty0 > tz0` is checked in the else branch):
                *   If `txm < ty0`, `answer |= 4`.
                *   If `tzm < ty0`, `answer |= 1`.
                *   Return `answer`.
        *   Else (XY plane, since `tz0` is the maximum entry time):
            *   If `txm < tz0`, `answer |= 4`.
            *   If `tym < tz0`, `answer |= 2`.
            *   Return `answer`.
    *   `new_node(txm, x, tym, y, tzm, z)`:
        *   If `txm < tym`:
            *   If `txm < tzm`, return `x`.
            *   Else, return `z`.
        *   Else:
            *   If `tym < tzm`, return `y`.
            *   Else, return `z`.
        *   This selects the child adjacent to the plane with the smallest midpoint parametric time [S1].

### Pseudocode

```python
def parametric_octree_traversal(octree, ray):
    # 1. Normalize Ray Direction
    a = 0
    if ray.direction[0] < 0:
        ray.origin[0] = octree.center[0] * 2 - ray.origin[0]
        ray.direction[0] = -ray.direction[0]
        a |= 4
    if ray.direction[1] < 0:
        ray.origin[1] = octree.center[1] * 2 - ray.origin[1]
        ray.direction[1] = -ray.direction[1]
        a |= 2
    if ray.direction[2] < 0:
        ray.origin[2] = octree.center[2] * 2 - ray.origin[2]
        ray.direction[2] = -ray.direction[2]
        a |= 1

    # 2. Compute Inverse Directions
    divx = 1.0 / ray.direction[0]
    divy = 1.0 / ray.direction[1]
    divz = 1.0 / ray.direction[2]

    # 3. Compute Parametric Bounds
    tx0 = (octree.min[0] - ray.origin[0]) * divx
    tx1 = (octree.max[0] - ray.origin[0]) * divx
    ty0 = (octree.min[1] - ray.origin[1]) * divy
    ty1 = (octree.max[1] - ray.origin[1]) * divy
    tz0 = (octree.min[2] - ray.origin[2]) * divz
    tz1 = (octree.max[2] - ray.origin[2]) * divz

    # 4. Check Intersection
    if max(tx0, max(ty0, tz0)) < min(tx1, min(ty1, tz1)):
        proc_subtree(tx0, ty0, tz0, tx1, ty1, tz1, octree.root, a)

def proc_subtree(tx0, ty0, tz0, tx1, ty1, tz1, node, a):
    # 5.1 Termination
    if tx1 < 0 or ty1 < 0 or tz1 < 0:
        return
    if node.terminal:
        process_leaf(node)
        return

    # 5.2 Midpoints
    txm = 0.5 * (tx0 + tx1)
    tym = 0.5 * (ty0 + ty1)
    tzm = 0.5 * (tz0 + tz1)

    # 5.3 First Child
    currNode = first_node(tx0, ty0, tz0, txm, tym, tzm)

    # 5.4 Iterate
    while currNode < 8:
        if currNode == 0:
            proc_subtree(tx0, ty0, tz0, txm, tym, tzm, node.children[0 ^ a], a)
            currNode = new_node(txm, 4, tym, 2, tzm, 1)
        elif currNode == 1:
            proc_subtree(tx0, ty0, tzm, txm, tym, tz1, node.children[1 ^ a], a)
            currNode = new_node(txm, 5, tym, 3, tz1, 8)
        elif currNode == 2:
            proc_subtree(tx0, tym, tz0, txm, ty1, tzm, node.children[2 ^ a], a)
            currNode = new_node(txm, 6, ty1, 8, tzm, 3)
        elif currNode == 3:
            proc_subtree(tx0, tym, tzm, txm, ty1, tz1, node.children[3 ^ a], a)
            currNode = new_node(txm, 7, ty1, 8, tz1, 8)
        elif currNode == 4:
            proc_subtree(txm, ty0, tz0, tx1, tym, tzm, node.children[4 ^ a], a)
            currNode = new_node(tx1, 8, tym, 6, tzm, 5)
        elif currNode == 5:
            proc_subtree(txm, ty0, tzm, tx1, tym, tz1, node.children[5 ^ a], a)
            currNode = new_node(tx1, 8, tym, 7, tz1, 8)
        elif currNode == 6:
            proc_subtree(txm, tym, tz0, tx1, ty1, tzm, node.children[6 ^ a], a)
            currNode = new_node(tx1, 8, ty1, 8, tzm, 7)
        elif currNode == 7:
            proc_subtree(txm, tym, tzm, tx1, ty1, tz1, node.children[7 ^ a], a)
            currNode = 8

def first_node(tx0, ty0, tz0, txm, tym, tzm):
    answer = 0
    if tx0 > ty0:
        if tx0 > tz0: # YZ Plane
            if tym < tx0:
                answer |= 2
            if tzm < tx0:
                answer |= 1
            return answer
    else:
        if ty0 > tz0: # XZ Plane
            if txm < ty0:
                answer |= 4
            if tzm < ty0:
                answer |= 1
            return answer
    
    # XY Plane
    if txm < tz0:
        answer |= 4
    if tym < tz0:
        answer |= 2
    return answer

def new_node(txm, x, tym, y, tzm, z):
    if txm < tym:
        if txm < tzm:
            return x
        else:
            return z
    else:
        if tym < tzm:
            return y
        else:
            return z
```

### Edge Cases and Pitfalls
*   **Zero Direction Components:** Division by zero in `divx`, `divy`, or `divz` occurs if the ray direction component is zero [S1, S2]. The source code relies on IEEE floating-point behavior (resulting in infinity/NaN) which may propagate incorrectly through comparisons [S1]. Robust implementations should explicitly check for zero direction components and handle them (e.g., by clamping or special-case logic) [S1, S2].
*   **Negative Directions:** Rays with negative direction components must be mirrored [S1, S2]. Failure to do so results in incorrect parametric intervals and traversal order [S1, S2].
*   **Non-Uniform Depth:** The algorithm handles non-uniform octree depths by using pointers to children, unlike DDA algorithms that often assume fixed depth [S1].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Handles non-uniform octree depths efficiently; top-down approach is intuitive; bitwise operations for child selection are fast [S1, S2].
*   **Limitations:** Recursion depth can be large for deep octrees; division by zero requires handling; relies on IEEE floating-point behavior for stability [S1, S2].
*   **When to Use:** When traversing sparse voxel octrees with non-uniform depth on CPU, as it handles null pointers for empty subtrees without requiring fixed-depth assumptions [S1].
*   **When Not to Use:** When ray directions are guaranteed to be positive (simplification possible); when robustness to zero-direction rays is critical without IEEE guarantees [S1, S2].

## Background
Parametric Octree Traversal was introduced by Revelles in 2000 in the paper "An efficient parametric algorithm for octree traversal" [S1, S2]. It is a top-down algorithm designed to overcome limitations of bottom-up DDA algorithms (like Sung's 1991 algorithm) which often require fixed-depth octrees [S1, S2]. It is particularly relevant for Sparse Voxel Octrees (SVOs) where empty subtrees are represented by null pointers [S1, S2].
