# Pixel-Weighted Line Integration

Also called: Line Integral Weight Calculation (Bresenham-like), Sinogram generation via pixel-weighted line integration

## Overview
Pixel-Weighted Line Integration is a forward projection technique that computes a sinogram by approximating line integrals over a 2D image using pixel weights [S1, unofficial]. It determines which pixels a line passes through and their intersection lengths using a Bresenham-like rasterization approach [S1, unofficial]. It differs from matrix-based forward projection by computing the transformation manually to avoid constructing and inverting a large matrix [S1, unofficial].

## How it works
**Inputs:**
- `Image`: struct containing `width: usize`, `height: usize`, and `data: Vec<f64>` [S1, unofficial].
- `angles`: Number of projection angles over a 180-degree range ($>0$) [S1, unofficial].
- `rays`: Number of parallel rays spread over the object ($>1$) [S1, unofficial].

**Outputs:**
- `Scan`: struct containing `angles: usize`, `rays: usize`, and `data: Vec<f64>` (flattened array, outer loop angles, inner loop rays) [S1, unofficial].

**Data Structures:**
The method returns weights as `Vec<(usize, usize, f64)>`, where each tuple is `(x_pixel_index, y_pixel_index, weight)` [S1, unofficial].

**Parameters:**
- `dy_dx`: The slope of the line ($dy/dx$). The algorithm assumes $|dy\_dx| \le 1.0$ for the inner loop; steeper lines are handled by axis swapping [S1, unofficial].
- `base_weight`: A scaling factor derived from pixel dimensions and slope, ensuring that crossing the whole pixel area is 1 unit [S1, unofficial].

**Steps:**

1. **Coordinate Transformation:** Transform scan space coordinates (range $-1..1$) to pixel space (range $0..w, 0..h$) [S1, unofficial]. For endpoints $(x_1, y_1)$ and $(x_2, y_2)$ in scan space:
   $$ x_{1p} = (x_1 + 1.0) \times \frac{w}{2.0} $$
   $$ y_{1p} = (y_1 + 1.0) \times \frac{h}{2.0} $$
   $$ x_{2p} = (x_2 + 1.0) \times \frac{w}{2.0} $$
   $$ y_{2p} = (y_2 + 1.0) \times \frac{h}{2.0} $$
   where $w$ and $h$ are image width and height [S1, unofficial].

2. **Ray Grid Generation:** Iterate over angle index `idx` in `0..angles` and ray index `idx` in `0..rays` [S1, unofficial].
   - Compute angle step: `angle_step = PI / angles` [S1, unofficial].
   - Compute ray offset: `ray_offset = sqrt(2)` [S1, unofficial].
   - Compute ray step: `ray_step = 2.0 * ray_offset / (rays - 1)` [S1, unofficial].
   - For each `idx` in `0..angles`:
     - `angle = idx * angle_step` [S1, unofficial].
     - `axis_start = (cos(angle), sin(angle))` [S1, unofficial].
     - `axis_end = (-axis_start.0, -axis_start.1)` [S1, unofficial].
   - For each `idx` in `0..rays`:
     - `ray = idx * ray_step - ray_offset` [S1, unofficial].
     - `parallel_offset = (ray * -axis_start.1, ray * axis_start.0)` [S1, unofficial].
     - `ray_start = (axis_start.0 + parallel_offset.0, axis_start.1 + parallel_offset.1)` [S1, unofficial].
     - `ray_end = (axis_end.0 + parallel_offset.0, axis_end.1 + parallel_offset.1)` [S1, unofficial].
   - Transform `ray_start` and `ray_end` from scan space to pixel grid coordinates using the formula in Step 1 [S1, unofficial].

3. **Pixel Weight Calculation:** Compute pixel weights for the transformed ray segment [S1, unofficial].
   - Let $w$ be image width, $h$ be image height [S1, unofficial].
   - Calculate base weight:
     $$ wf64 = w \text{ as } f64 $$
     $$ hf64 = h \text{ as } f64 $$
     $$ y\_scale = \frac{1.0}{hf64 \times hf64} $$
     $$ x\_scale = \frac{1.0}{wf64 \times wf64} $$
     $$ base\_weight = \sqrt{x\_scale + dy\_dx \times dy\_dx \times y\_scale} $$
     [S1, unofficial].
   - Initialize Bresenham state:
     $$ y\_round = \lfloor y_0 \rfloor $$
     $$ y\_int = y\_round \text{ as } isize $$
     $$ y\_fract = y_0 - y\_round $$
     [S1, unofficial].
   - Iterate $x$ from $0$ to $w$:
     - $y\_fract += dy\_dx$ [S1, unofficial].
     - If $y\_fract \ge 1.0$:
       - $rhs = y\_fract / dy\_dx$ [S1, unofficial].
       - $lhs = 1.0 - rhs$ [S1, unofficial].
       - `add_pixel(x, y_int, lhs * base_weight)` [S1, unofficial].
       - $y\_int += 1$ [S1, unofficial].
       - `add_pixel(x, y_int, rhs * base_weight)` [S1, unofficial].
     - Else if $y\_fract < 0.0$:
       - $rhs = y\_fract / dy\_dx$ [S1, unofficial].
       - $lhs = 1.0 - rhs$ [S1, unofficial].
       - $y\_fract += 1.0$ [S1, unofficial].
       - `add_pixel(x, y_int, lhs * base_weight)` [S1, unofficial].
       - $y\_int -= 1$ [S1, unofficial].
       - `add_pixel(x, y_int, rhs * base_weight)` [S1, unofficial].
     - Else:
       - `add_pixel(x, y_int, base_weight)` [S1, unofficial].
   - Handle steep lines ($|dy/dx| > 1$) by swapping $x$ and $y$ coordinates, calling the horizontal weight calculator with swapped dimensions, then swapping the resulting pixel coordinates back [S1, unofficial].

4. **Integral Computation:**
   - `integral = sum(weight * pixel_value)` for each weight-pixel pair [S1, unofficial].
   - Append `integral` to output data array [S1, unofficial].

**Pseudocode:**

```python
import math

def pixel_weighted_line_integration(image: Image, angles: int, rays: int) -> Scan:
    """
    image: struct with width, height, data (Vec<f64>)
    angles: int > 0
    rays: int > 1
    returns: Scan struct with angles, rays, data (Vec<f64>)
    """
    w = image.width
    h = image.height
    scan_data = [0.0] * (angles * rays)
    
    angle_step = math.pi / angles
    ray_offset = math.sqrt(2.0)
    ray_step = 2.0 * ray_offset / (rays - 1)
    
    for idx_a in range(angles):
        angle = idx_a * angle_step
        axis_start_x = math.cos(angle)
        axis_start_y = math.sin(angle)
        axis_end_x = -axis_start_x
        axis_end_y = -axis_start_y
        
        for idx_r in range(rays):
            ray = idx_r * ray_step - ray_offset
            parallel_offset_x = ray * -axis_start_y
            parallel_offset_y = ray * axis_start_x
            
            ray_start_x = axis_start_x + parallel_offset_x
            ray_start_y = axis_start_y + parallel_offset_y
            ray_end_x = axis_end_x + parallel_offset_x
            ray_end_y = axis_end_y + parallel_offset_y
            
            # Transform scan space (-1..1) to pixel space (0..w, 0..h)
            x1p = (ray_start_x + 1.0) * (w / 2.0)
            y1p = (ray_start_y + 1.0) * (h / 2.0)
            x2p = (ray_end_x + 1.0) * (w / 2.0)
            y2p = (ray_end_y + 1.0) * (h / 2.0)
            
            # Calculate weights
            weights = calculate_weights(x1p, y1p, x2p, y2p, w, h)
            
            # Compute integral
            integral = 0.0
            for (px, py, weight) in weights:
                # Access pixel value from image data
                # Assuming image.data is flattened row-major
                pixel_value = image.data[py * w + px]
                integral += weight * pixel_value
            
            scan_data[idx_a * rays + idx_r] = integral
            
    return Scan(angles=angles, rays=rays, data=scan_data)

def calculate_weights(x1: float, y1: float, x2: float, y2: float, w: int, h: int) -> list:
    """
    Returns list of (x_pixel_index, y_pixel_index, weight)
    """
    dx = x2 - x1
    dy = y2 - y1
    
    # Handle steep lines
    if abs(dy) > abs(dx):
        # Swap x and y
        weights_swapped = calculate_weights(y1, x1, y2, x2, h, w)
        # Swap coordinates back
        return [(py, px, weight) for (px, py, weight) in weights_swapped]
    
    # Assume |dy/dx| <= 1
    dy_dx = dy / dx if dx != 0 else 0.0
    
    wf64 = float(w)
    hf64 = float(h)
    y_scale = 1.0 / (hf64 * hf64)
    x_scale = 1.0 / (wf64 * wf64)
    base_weight = math.sqrt(x_scale + dy_dx * dy_dx * y_scale)
    
    y_round = math.floor(y1)
    y_int = int(y_round)
    y_fract = y1 - y_round
    
    weights = []
    
    # Iterate x from 0 to w
    # Note: The source iterates x from 0 to w. 
    # We assume the line segment covers this range or we clamp/iterate appropriately.
    # Based on source: "Iterate x from 0 to w"
    for x in range(w + 1): # Include w if endpoint is at w
        # Check if x is within segment bounds? 
        # Source implies iterating full width for the projection logic.
        # However, standard Bresenham iterates along the major axis.
        # Here x is major axis.
        
        y_fract += dy_dx
        
        if y_fract >= 1.0:
            rhs = y_fract / dy_dx
            lhs = 1.0 - rhs
            weights.append((x, y_int, lhs * base_weight))
            y_int += 1
            weights.append((x, y_int, rhs * base_weight))
        elif y_fract < 0.0:
            rhs = y_fract / dy_dx
            lhs = 1.0 - rhs
            y_fract += 1.0
            weights.append((x, y_int, lhs * base_weight))
            y_int -= 1
            weights.append((x, y_int, rhs * base_weight))
        else:
            weights.append((x, y_int, base_weight))
            
    return weights
```

**Edge Cases and Pitfalls:**
- Steep lines where $|dy/dx| > 1$ cause numerical instability or incorrect traversal in the primary loop; handled by swapping $x$ and $y$ axes, processing as horizontal, then swapping results back [S1, unofficial].
- Reconstruction error does not asymptotically approach zero; persists due to normalization steps or deconvolution filter inaccuracies [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Measured Performance:** For a 32x32 image, 80 rays and 80 angles minimizes reconstruction error on the tested sparse cases [S1, unofficial].
- **Strengths:** Avoids constructing and inverting a large matrix by computing the transformation manually [S1, unofficial].
- **Limitations:** Reconstruction error does not asymptotically approach zero [S1, unofficial].

## Background
The method is part of the `rediscovering-tomography` project by Simon Frankau [S1, unofficial]. It is used for generating sinograms and performing forward projections in tomographic reconstruction contexts [S1, unofficial].
