# Voronoi Diagram Traversal with Local Adjacency
Also called: Voronoi Traversal via Local Adjacency
## Overview
This method accelerates ray traversal in 3D Voronoi tessellations by replacing global bounding volume hierarchy (BVH) intersection queries with local cell adjacency lookups [S1, unofficial]. It solves the performance bottleneck of repeated global searches by leveraging the spatial coherence of neighboring cells, significantly reducing the number of cells visited per ray and improving memory coherence across neighboring rays on the GPU [S1, unofficial]. It is distinct from global BVH approaches by relying on precomputed topological connectivity rather than geometric bounding volumes [S1, unofficial].
## How it works
**Inputs:**
- A set of Voronoi sites (points) $S = \{s_1, s_2, \dots, s_N\}$ in 3D space.
- For each site $s_i$, its associated physical properties (e.g., density, temperature) and geometric bounds.
- A set of rays $R$ defined by origin $o$ and direction $d$.

**Data Structures:**
1. **Site List:** Array of site coordinates and properties.
2. **Adjacency Map:** A sparse structure mapping each cell index $i$ to a list of neighbor indices $\mathcal{N}(i)$. This replaces the BVH tree.
3. **Morton Order Array:** An array of cell indices sorted by their 3D Morton (Z-order) code to improve spatial locality.
4. **Ray Tile Buffer:** A buffer storing rays grouped into compact screen-space tiles.

**Steps:**
1. **Preprocessing (Offline):**
   - Compute the Voronoi diagram to determine the adjacency graph where two cells are neighbors if they share a facet.
   - Store the adjacency list for each cell.
   - Compute the 3D Morton code for each site's centroid.
   - Sort the cell indices based on their Morton codes to create a spatially coherent layout [S1, unofficial].

2. **Ray Scheduling (Per Frame):**
   - Project ray origins and directions onto the screen.
   - Group rays into compact 2D tiles (e.g., $8 \times 8$ or $16 \times 16$ pixels) to maximize GPU warp coherence [S1, unofficial].

3. **Traversal (Per Ray):**
   - **Initialization:** Use the parent method [Point location in Voronoi grid](22962-point-location-in-voronoi-grid.md) to find the initial cell $c_{start}$ containing the ray origin $o$.
   - **Loop:** While the ray is within the domain and has not terminated:
     - Let current cell be $c$.
     - **Culling:** Calculate the maximum possible contribution of cell $c$ to the ray (based on opacity, density, and path length). If this value is below a fixed threshold $\tau$, skip appearance evaluation and jump to the next cell using adjacency [S1, unofficial].
     - **Appearance Evaluation:** If not skipped, compute the radiative transfer contribution of cell $c$ along the ray segment inside it.
     - **Exit Point:** Compute the exit point $p_{exit}$ of the ray from cell $c$.
     - **Next Cell:** Identify the neighbor cell $c_{next}$ that shares the facet containing $p_{exit}$. This is done by checking the adjacency list $\mathcal{N}(c)$ and selecting the cell whose centroid or bounding box best aligns with the ray direction at $p_{exit}$, or by storing facet-to-neighbor mappings explicitly [G].
     - Update current cell $c \leftarrow c_{next}$.

**Parameters:**
- $\tau$: Threshold for skipping appearance evaluation. Value depends on scene opacity and desired precision. Not given in the sources.

**Edge Cases:**
- **Degenerate Cells:** If a cell has no neighbors (isolated), traversal stops.
- **Precision Errors:** Floating-point inaccuracies at facet boundaries may cause the ray to miss the correct neighbor. Robust geometric predicates or epsilon offsets are required [G].
- **Empty Space:** If the ray exits the domain of sites, traversal terminates.

**Pseudocode:**
```python
def traverse_voronoi_ray(ray, sites, adjacency, morton_sorted_indices, threshold):
    # 1. Initial Point Location (from parent method)
    current_cell_idx = point_location(ray.origin, sites)
    
    # 2. Ray Parameters
    t_min = 0.0
    t_max = ray.max_distance
    
    # 3. Traverse
    while t_min < t_max and current_cell_idx is not None:
        cell = sites[current_cell_idx]
        
        # 4. Culling
        max_contribution = estimate_max_contribution(cell, ray, t_min, t_max)
        if max_contribution < threshold:
            # Skip appearance, find next cell
            next_cell_idx = find_next_cell_via_adjacency(current_cell_idx, ray, t_min)
            if next_cell_idx is None:
                break
            current_cell_idx = next_cell_idx
            continue
            
        # 5. Appearance Evaluation
        t_exit = compute_exit_point(ray, cell)
        if t_exit > t_max:
            t_exit = t_max
            
        contribution = evaluate_radiative_transfer(cell, ray, t_min, t_exit)
        accumulate_result(contribution)
        
        # 6. Advance
        t_min = t_exit
        next_cell_idx = find_next_cell_via_adjacency(current_cell_idx, ray, t_min)
        if next_cell_idx is None:
            break
        current_cell_idx = next_cell_idx
        
    return result

def find_next_cell_via_adjacency(current_idx, ray, t_at_exit):
    # Find the neighbor cell that contains the exit point
    # This requires checking the adjacency list and determining which neighbor
    # the ray enters. A robust implementation checks the facet normal or
    # uses a point-in-cell test for neighbors.
    neighbors = adjacency[current_idx]
    for n_idx in neighbors:
        if is_point_in_cell(ray.origin + ray.direction * t_at_exit, sites[n_idx]):
            return n_idx
    return None
```

## Subtopics

### [Voronoi Grid Radiative Transfer](23840-voronoi-grid-radiative-transfer.md)
A Monte Carlo method for astrophysical radiative transfer using Voronoi tessellations. It is uncoupled from the input model's internal code, requiring only site coordinates and physical properties. Choose this when simulating photon transport in non-uniform density fields like SPH particles.

## Operating characteristics
- **Time Complexity:** Traversal is proportional to the number of cells visited per ray. Local adjacency reduces the cost of finding the next cell from $O(\log N)$ (BVH) to $O(1)$ (adjacency lookup), but requires precomputing the adjacency graph.
- **Memory Complexity:** Requires storing the adjacency graph, which can be large for complex Voronoi diagrams. Morton ordering improves cache coherence.
- **Performance:** Improves GPU throughput by enhancing memory coherence across neighboring rays and reducing traversal overhead [S1, unofficial].
- **Strengths:** Faster traversal than global BVH for dense Voronoi grids; better cache locality due to Morton ordering and tile scheduling.
- **Limitations:** Requires precomputed adjacency; culling threshold $\tau$ must be tuned; precision issues at cell boundaries.
- **When to use:** When rendering large-scale Voronoi tessellations (e.g., astrophysical simulations) where traversal cost dominates.
- **When not to use:** For sparse or dynamic Voronoi diagrams where adjacency computation is too costly.
## Background
This method was introduced in the context of differentiable Voronoi ray tracing, building on the Radiant Foam renderer [S1, unofficial]. It addresses the limitations of global BVH intersection queries for Voronoi diagrams, which are inefficient due to the irregular shape of cells. The approach was demonstrated to support interactive rendering on mobile devices and advanced camera effects like fisheye projection and motion blur [S1, unofficial].
