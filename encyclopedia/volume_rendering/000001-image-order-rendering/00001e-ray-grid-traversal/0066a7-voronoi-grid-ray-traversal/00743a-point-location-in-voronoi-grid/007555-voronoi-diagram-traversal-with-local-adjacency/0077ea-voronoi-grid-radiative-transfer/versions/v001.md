# Voronoi Grid Radiative Transfer

Also called: 3D Voronoi grid RT, Voronoi tessellation radiative transfer

## Overview
Voronoi Grid Radiative Transfer is a Monte Carlo method for computing radiative transfer in astrophysical environments using a 3D Voronoi tessellation as the spatial discretization grid [S1]. It solves the problem of efficiently tracing photon packages through complex, non-uniform density fields (such as SPH particles or MHD meshes) by adapting cell boundaries to underlying density gradients [S1]. Unlike methods that require tight coupling with the input model's internal code (e.g., Sunrise RT invoking Arepo), this approach remains uncoupled, requiring only site coordinates and cell physical properties [S1]. It is implemented in the SKIRT code [S1].

## How it works

### Inputs and Outputs
**Inputs:**
1.  **Voronoi Sites:** Coordinates of the generating points (sites) defining the grid [S1].
2.  **Physical Properties:** Scalar values (e.g., mass density, opacity) associated with the cell surrounding each site [S1].
3.  **Light Source Definition:** Position and spectral distribution of the emitter [S1].

**Outputs:**
1.  **Radiation Field:** Discretized quantities (e.g., flux density, dust absorption) on the same grid as the dust density [S1].
2.  **Spectral Energy Distribution (SED):** Integrated flux at observer locations [S1].

### Data Structures
The method relies on data structures built during initialization using a public Voronoi library (e.g., Voro++) [S1]. For path calculation, the algorithm requires no information about the Voronoi cell geometry other than:
1.  **Bounding Box:** The axis-aligned bounding box of the current cell [S1].
2.  **Site Location:** The 3D coordinates of the cell's own generating site [S1].
3.  **Neighbor Locations:** The 3D coordinates of all neighboring sites [S1].

*Note: The specific internal layout of the neighbor list or bounding box structure is not detailed in the sources, but the library (Voro++) handles the geometric construction [S1].*

### Algorithm Steps

1.  **Initialization:**
    *   Construct the Voronoi tessellation from the input sites using a library like Voro++ [S1].
    *   Build the required data structures: bounding boxes and neighbor lists for each cell [S1].
    *   Assign physical properties (density/opacity) to each cell based on the input model [S1].

2.  **Photon Shooting (Monte Carlo Loop):**
    *   Emit photon packages from the light source [S1].
        *   For **panchromatic** simulations: Emit packages for multiple wavelength bins on a logarithmic grid (e.g., 100 bins) [S1].
        *   For **monochromatic** simulations: Emit packages at a fixed wavelength [S1].
    *   For each photon package:
        *   Determine the starting cell containing the photon's position [S1].
        *   **Cell Traversal:** Calculate the straight-line path from the current position to the next cell boundary [S1].
            *   Use the cell's bounding box and neighbor site locations to determine the exit point [S1].
            *   *Pitfall:* Computational inaccuracies may occasionally cause the algorithm to fail to find an exit point. This occurs at most once per 50 million cell crossings [S1].
        *   **Interaction:** Calculate absorption and scattering within the traversed cell segment using the cell's physical properties [S1].
        *   **Scattering:** If a scattering event occurs, create a new photon package with a new direction and wavelength (if applicable) [S1].
        *   Repeat traversal until the photon escapes the domain or is absorbed.

### Pseudocode

```python
def voronoi_rt(sites, properties, light_source, num_photons, wavelength_bins):
    """
    Perform radiative transfer on a 3D Voronoi grid.
    
    Args:
        sites: List of 3D coordinates for Voronoi generating points.
        properties: Dictionary mapping site index to physical property (e.g., density).
        light_source: Object defining position and spectral emission.
        num_photons: Total number of photon packages to emit.
        wavelength_bins: Logarithmic array of wavelengths for panchromatic simulation.
    
    Returns:
        radiation_field: Discretized radiation field on the grid.
    """
    # 1. Initialization
    # Build Voronoi tessellation and extract necessary data structures
    # Requires external library (e.g., Voro++)
    voronoi_grid = build_voronoi_grid(sites)
    
    # Extract bounding boxes and neighbor site locations for each cell
    # The library provides the topology; we store only what is needed for traversal
    cell_data = {}
    for cell_id in voronoi_grid.cells:
        cell_data[cell_id] = {
            'bbox': voronoi_grid.get_bounding_box(cell_id),
            'own_site': sites[cell_id],
            'neighbor_sites': [sites[n] for n in voronoi_grid.get_neighbors(cell_id)]
        }
    
    # Initialize radiation field accumulator
    radiation_field = initialize_field(voronoi_grid)
    
    # 2. Photon Shooting
    for i in range(num_photons):
        # Determine wavelength for this photon
        if wavelength_bins is not None:
            wavelength = sample_wavelength(wavelength_bins)
        else:
            wavelength = light_source.fixed_wavelength
            
        # Emit photon package
        photon = light_source.emit(wavelength)
        
        # Traverse through the grid
        current_cell_id = find_cell_containing_point(sites, photon.position)
        
        while photon.is_alive():
            # Get cell data for path calculation
            data = cell_data[current_cell_id]
            
            # Calculate exit point from current cell
            # Uses bounding box and neighbor sites to determine intersection
            exit_point, next_cell_id = calculate_exit_point(
                photon.position, 
                photon.direction, 
                data['bbox'], 
                data['neighbor_sites']
            )
            
            # Handle potential failure to find exit point (rare, ~1 in 50M)
            if exit_point is None:
                # Fallback or skip; sources indicate this is negligible
                break 
            
            # Calculate interaction in the segment [photon.position, exit_point]
            segment_length = distance(photon.position, exit_point)
            cell_property = properties[current_cell_id]
            
            # Compute absorption and scattering
            # This step depends on the specific radiative transfer physics model
            # For simplicity, we assume a standard Monte Carlo interaction
            absorption, scattering = compute_interaction(
                segment_length, 
                cell_property, 
                wavelength
            )
            
            # Update radiation field
            update_field(radiation_field, current_cell_id, absorption, scattering)
            
            # Move photon to exit point
            photon.position = exit_point
            
            # Handle scattering
            if scattering:
                # Create new photon package with new direction/wavelength
                photon = create_scattered_photon(photon, cell_property)
                # Find the new cell containing the scattered photon's position
                current_cell_id = find_cell_containing_point(sites, photon.position)
            else:
                # Move to next cell
                current_cell_id = next_cell_id
                
                # Check if photon has left the domain
                if current_cell_id is None:
                    photon.is_alive = False
```

### Parameters
*   **Wavelength Bins:** For panchromatic simulations, a logarithmic grid is used. Typical values: 100 bins [S1].
*   **Photon Count:** 
    *   Torus model (panchromatic): $10^5$ photons per bin [S1].
    *   Pascucci benchmark (panchromatic): $10^5$ photons per bin [S1].
    *   Monochromatic simulations: $10^7$ photons [S1].
*   **Cell Resolution:** 
    *   Pascucci benchmark: 1 million cells, randomly placed according to a $1/r$ distribution [S1].

### Edge Cases and Pitfalls
*   **Cell Crossing Failure:** The algorithm may occasionally fail to find an exit point due to computational inaccuracies. In tests, this occurred at most once per 50 million cell crossings, so it does not significantly affect performance [S1].
*   **Precision:** The method relies on accurate geometric intersection calculations. The use of bounding boxes and neighbor sites simplifies this but requires robust floating-point handling [S1].

## Operating characteristics

### Time and Memory Complexity
*   **Time Complexity:** The time per cell crossing is higher for Voronoi grids than for octree grids due to geometric complexity. 
    *   Torus model (panchromatic): Voronoi 1006 ns vs. Octree 400 ns (ratio 2.5) [S1].
    *   Torus model (monochromatic): Voronoi 693 ns vs. Octree 219 ns (ratio 3.2) [S1].
    *   Spiral model (panchromatic): Voronoi 1095 ns vs. Octree 442 ns (ratio 2.5) [S1].
    *   Spiral model (monochromatic): Voronoi 903 ns vs. Octree 309 ns (ratio 2.9) [S1] [S1].
*   **Memory Complexity:** Depends on the number of sites and the storage of neighbor lists. The sources do not provide explicit memory usage figures, but note that the interface is thin and data structures are built from input data [S1].

### Measured Performance
*   **Hardware:** Tests performed on a typical desktop computer using a single core [S1].
*   **Scaling:** The method allows for flexible discretization, potentially requiring fewer cells than octree grids to represent certain density fields, which can balance performance [S1].

### Strengths and Limitations
*   **Strengths:**
    *   Flexible discretization: Cell size and distribution can be fine-tuned by placing sites in appropriate locations (e.g., high-gradient areas) [S1].
    *   Uncoupled interface: Does not require access to the input model's source code, unlike methods that invoke non-public codes (e.g., Arepo) [S1].
    *   Supports various input models: SPH particles, MHD Voronoi meshes, or random points from analytical fields [S1].
*   **Limitations:**
    *   Higher per-cell-crossing time compared to octree grids (2.5x to 3.2x slower) [S1].
    *   Potential for rare geometric failures in cell crossing [S1].

### When to Use
*   Use when the input data is naturally particle-based (SPH) or already in a Voronoi mesh (MHD) [S1].
*   Use when the density field has large dynamic ranges and requires adaptive resolution that can be achieved by placing sites according to density/opacity fields [S1].
*   Use when the input model's source code is not available [S1].

### When Not to Use
*   Use when maximum performance per cell crossing is critical and the density field is well-represented by an octree [S1].
*   Use when the input model is a regular grid and does not benefit from adaptive Voronoi discretization [S1].

## Background

### Origin
The method was introduced in the paper "Using 3D Voronoi grids in radiative transfer simulations" [S1]. It is implemented in the SKIRT code [S1].

### History and Development
The method was developed to address the need for flexible discretization in radiative transfer simulations, particularly for astrophysical environments with complex density structures [S1]. It was validated against the Pascucci benchmark [S1].

### Usage
*   Implemented in the SKIRT code [S1].
*   Used for Pascucci benchmark simulations with optical depths $\tau = 0.1, 1, 10$ [S1].
*   Input models can be SPH particles, MHD Voronoi meshes, or random points from analytical density/opacity fields [S1].
