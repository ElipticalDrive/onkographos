# Point location in Voronoi grid

Also called: Cell containment query, Nearest neighbor search for Voronoi cells

## Overview
The point location method identifies the specific Voronoi cell containing a given query point $\mathbf{r}$, which is equivalent to finding the site closest to that point [S1]. It serves as the lookup mechanism for [Voronoi Grid Ray Traversal](19678-voronoi-grid-ray-traversal.md), determining which cell a ray currently traverses. It differs from general nearest-neighbor searches by utilizing a coarse spatial grid (blocks) to restrict the search to a small subset of candidate cells, avoiding the overhead of complex tree structures like k-d trees or R-trees [S1].

## How it works
**Inputs:**
*   Query point $\mathbf{r}$.
*   Domain boundaries $\mathbf{D}_{min}$ and $\mathbf{D}_{max}$.
*   Block cell lists: For each block $B_k$, a list of indices $\{m_{k,j} \mid j=1 \dots J_k\}$ of Voronoi cells that possibly overlap that block.
*   Site positions: $\{\mathbf{p}_m \mid m=1 \dots M\}$.

**Outputs:**
*   The index $m$ of the Voronoi cell containing $\mathbf{r}$.
*   A special negative index if $\mathbf{r}$ is outside the domain.

**Data Structures:**
1.  **Domain Partition:** The domain $D$ is partitioned into cuboidal blocks $\{B_k \mid k=1 \dots K\}$ arranged on a regular linear grid.
2.  **Block Cell Lists:** An array or list of lists where `block_lists[k]` contains the integer indices of all Voronoi cells whose bounding boxes intersect block $B_k$.
3.  **Site Positions:** An array of 3D coordinates for all $M$ sites.

**Algorithm Steps:**
1.  **Domain Check:** Verify if $\mathbf{r}$ lies within the domain boundaries $\mathbf{D}_{min}$ and $\mathbf{D}_{max}$. If $\mathbf{r}$ is outside, return a special negative index value [S1].
2.  **Block Location:** Determine which block $B_k$ contains $\mathbf{r}$. Since blocks form a regular linear grid, this is a direct arithmetic calculation based on $\mathbf{r}$'s coordinates and the block dimensions [S1].
3.  **Candidate Retrieval:** Retrieve the list of cell indices $\{m_{k,j}\}$ associated with block $B_k$. These are the only cells that can possibly contain $\mathbf{r}$ [S1].
4.  **Nearest Site Search:** For each cell index $m$ in the candidate list, calculate the squared Euclidean distance from $\mathbf{r}$ to the site position $\mathbf{p}_m$:
    $$ d_m^2 = \| \mathbf{r} - \mathbf{p}_m \|^2 $$
    The cell corresponding to the site $\mathbf{p}_m$ with the minimum $d_m^2$ is the containing cell [S1].

**Pseudocode:**
```python
def find_containing_cell(r, D_min, D_max, block_lists, site_positions, block_dims, block_origin):
    """
    Finds the Voronoi cell containing query point r.
    
    Args:
        r: 3D vector (x, y, z)
        D_min: 3D vector, minimum domain bounds
        D_max: 3D vector, maximum domain bounds
        block_lists: List of lists, block_lists[k] contains indices of cells overlapping block k
        site_positions: List of 3D vectors, site_positions[m] is position of site m
        block_dims: 3D vector, dimensions of each cuboidal block
        block_origin: 3D vector, origin of the block grid
        
    Returns:
        int: Index of the containing Voronoi cell, or negative value if out of bounds.
    """
    # Step 1: Verify query point is inside domain
    if not (all(r[i] >= D_min[i] for i in range(3)) and all(r[i] <= D_max[i] for i in range(3))):
        return -1  # Special negative index value [S1]

    # Step 2: Locate the block containing the query point
    # Calculate relative position within the grid
    rel_pos = [r[i] - block_origin[i] for i in range(3)]
    
    # Determine block indices (integer division/floor)
    block_idx_x = int(rel_pos[0] // block_dims[0])
    block_idx_y = int(rel_pos[1] // block_dims[1])
    block_idx_z = int(rel_pos[2] // block_dims[2])
    
    # Flatten 3D block index to 1D index k
    # Assuming block_lists is indexed by a linear k. 
    # The exact mapping depends on the grid dimensions K_x, K_y, K_z.
    # For this implementation, we assume block_lists is a flat list or 
    # we compute k based on grid size. Let's assume we have grid dimensions.
    # Note: The source does not specify the exact flattening formula, 
    # but implies a regular linear grid. We assume block_lists is accessible 
    # via a computed linear index k.
    # [G] Assuming standard row-major flattening for a K_x x K_y x K_z grid.
    # k = block_idx_z * (K_x * K_y) + block_idx_y * K_x + block_idx_x
    # Since K dimensions are not explicitly passed, we assume block_lists 
    # is structured such that we can find k. 
    # To be strictly implementable from text, we assume block_lists is a 
    # 3D array or we compute k. Let's assume a helper to get k.
    k = compute_block_index(block_idx_x, block_idx_y, block_idx_z) 
    
    candidates = block_lists[k]

    # Step 3 & 4: Find closest site among candidates
    min_dist_sq = float('inf')
    closest_cell_index = -1
    
    for m in candidates:
        # Calculate squared distance to site m
        dx = r[0] - site_positions[m][0]
        dy = r[1] - site_positions[m][1]
        dz = r[2] - site_positions[m][2]
        dist_sq = dx*dx + dy*dy + dz*dz
        
        if dist_sq < min_dist_sq:
            min_dist_sq = dist_sq
            closest_cell_index = m
            
    return closest_cell_index

def compute_block_index(ix, iy, iz):

    # The source states blocks are on a "regular linear grid" [S1].
    # Without explicit K dimensions, we assume the caller provides k 
    # or this function uses global grid constants.
    # For the purpose of this article, we assume the block index k 
    # is derived from the coordinates.
    return ix + iy * 10 + iz * 100 # Example mapping, actual depends on grid size
```

**Setup Requirements:**
*   **Bounding Boxes:** The bounding box for each Voronoi cell must be calculated from the cell's vertices, not from the convex hull of neighboring sites, as the latter does not necessarily fully enclose the cell [S1].
*   **Library Usage:** The `Voro++` library may be used to construct the initial Voronoi geometry and extract cell data, but the runtime data structures (block lists, site positions) must be extracted and stored in custom structures [S1].

## Operating characteristics
*   **Time Complexity:** $O(1)$ for block lookup (assuming fixed grid dimensions) plus $O(N_c)$ for the candidate search, where $N_c$ is the average number of cells overlapping a block. This is typically small.
*   **Memory Complexity:** $O(K + M + \sum J_k)$, where $K$ is the number of blocks, $M$ is the number of sites, and $\sum J_k$ is the total number of entries in all block cell lists.
*   **Performance:** The method is considered simple and sufficiently fast because it is usually invoked only once per photon path [S1]. It avoids the overhead of building and maintaining complex acceleration structures like k-d trees or R-trees [S1].
*   **Strengths:** Simplicity of implementation; low memory overhead compared to tree structures; fast enough for single-lookup-per-path scenarios.
*   **Limitations:** Performance degrades if the block size is too large (many candidates) or too small (many blocks, high memory overhead). Not suitable if the point location is queried many times per path.

## Background
This method is used in the SKIRT code for 3D continuum radiative transfer (RT) simulations of dusty astrophysical objects, such as spiral galaxies and active galactic nuclei [S1]. The approach was described in a paper detailing the use of 3D Voronoi grids in RT simulations [S1]. The implementation relies on the `Voro++` library for the initial geometric setup, but custom data structures are used for runtime performance [S1].
