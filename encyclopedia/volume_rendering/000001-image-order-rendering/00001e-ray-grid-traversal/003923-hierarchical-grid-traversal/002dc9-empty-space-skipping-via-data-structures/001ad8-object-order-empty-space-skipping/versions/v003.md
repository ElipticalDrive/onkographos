# Object-Order Empty Space Skipping

Also called: Block min-max culling, Front-to-back ray-casting with bounding box culling, GPU-based Ray-Casting with Object-Order Empty Space Skipping

## Overview
Object-Order Empty Space Skipping is a volume rendering optimization technique that reduces the ray marching domain by rasterizing a bounding geometry of active volume blocks to determine per-pixel entry and exit depths [S1][S2, unofficial]. It sets itself apart from image-order methods (like [Space Leaping](5863-space-leaping.md)) by computing the skip bounds via hardware rasterization of geometry rather than per-sample data structure lookups, thereby reducing overhead for large empty regions [S1]. It differs from [Semi-transparent Empty-Space Skipping](1911-semi-transparent-empty-space-skipping.md) by relying on explicit bounding geometry of active blocks rather than opacity thresholds alone [S2, unofficial].

## How it works
**Inputs:**
*   Volume data $V$ (e.g., 3D texture).
*   Camera parameters: position $\mathbf{c}$, screen coordinates $(x, y)$.
*   Isovalue threshold $\tau$ (for active block determination).
*   Block subdivision size $B$ (e.g., $4^3$ or $8^3$ voxels) [S1].

**Outputs:**
*   Rendered image with rays marching only within active regions $[t_{start}, t_{exit}]$.

**Data Structures:**
1.  **Volume Texture:** Stores voxel values.
2.  **Block Min-Max Structure:** A regular subdivision of the volume into blocks of size $B \times B \times B$. For each block, store the minimum and maximum voxel values (or maximum iso-value for thresholding) [S1].
3.  **Bounding Geometry:** A triangle mesh representing the faces of active blocks that are adjacent to inactive blocks. This geometry is generated based on the min-max values and the threshold $\tau$ [S1][S2, unofficial].

**Steps:**

1.  **Initialization (Pre-computation):**
    *   Subdivide the volume into blocks of size $B^3$ [S1].
    *   Compute the min-max value for each block. For thresholding, determine if a block is "active" (contains values $>\tau$) using the max value [S1][S2, unofficial].
    *   Generate the bounding geometry: For each pair of neighboring blocks, if one is active and the other is inactive, generate a quad (or triangle mesh) representing the shared face [S2, unofficial]. This geometry represents the boundary of the active volume [S1][S2, unofficial].

2.  **Per-Frame Ray Depth Computation (First Pass):**
    *   Compute ray direction $\mathbf{d}(x, y)$ for each pixel from camera position $\mathbf{c}$ and screen coordinates $(x, y)$:
        $$ \mathbf{p}(t, x, y) = \mathbf{c} + t \mathbf{d}(x, y) $$
    *   Rasterize the **front faces** of the bounding geometry to an off-screen buffer (or depth buffer) using a depth test that keeps the closest hit (e.g., `GL_LESS`). This yields $t_{start}(x, y)$, the entry depth into the active volume [S1][S2, unofficial].
    *   Rasterize the **back faces** of the bounding geometry using a depth test that keeps the farthest hit (e.g., `GL_GREATER`). This yields $t_{exit}(x, y)$, the exit depth from the active volume [S1].

3.  **Ray Casting (Second Pass):**
    *   For each pixel, initialize ray origin $\mathbf{o} = \mathbf{c}$ and direction $\mathbf{d}$.
    *   Set ray start parameter $t = t_{start}(x, y)$ and end parameter $t_{max} = t_{exit}(x, y)$ [S1][S2, unofficial].
    *   If $t \ge t_{max}$, discard the pixel (render as background) [S2, unofficial].
    *   March the ray from $t$ to $t_{max}$ in front-to-back order [S1].
    *   **Per-Sample Check:** If the ray passes through inactive blocks enclosed by active blocks (a pitfall noted in [S1]), samples within these blocks are skipped on a per-sample basis early in the ray-casting loop using the block min-max values [S1].

**Pseudocode:**

```python
# Pre-computation (once or when isovalue changes)
def generate_bounding_geometry(volume, block_size, threshold):
    """
    Generates a mesh of quads representing the boundary between active and inactive blocks.
    volume: 3D array of voxel values.
    block_size: int, dimension of a block (e.g., 8).
    threshold: float, iso-value threshold.
    Returns: list of quads (each quad is 4 vertices in world space).
    """
    blocks = []
    # Determine active status for each block
    for z in range(0, volume.shape[0], block_size):
        for y in range(0, volume.shape[1], block_size):
            for x in range(0, volume.shape[2], block_size):
                # Extract block data
                block_data = volume[z:z+block_size, y:y+block_size, x:x+block_size]
                max_val = max(block_data.flatten())
                is_active = max_val > threshold
                blocks.append({
                    'min': (x, y, z),
                    'max': (x+block_size, y+block_size, z+block_size),
                    'active': is_active
                })
    
    quads = []
    # Iterate over all blocks to find active-inactive boundaries
    for i, block in enumerate(blocks):
        if not block['active']:
            continue
        # Check neighbors (simplified for 6 directions)
        # In practice, check all 6 neighbors and generate quad if neighbor is inactive
        # This part depends on specific neighbor indexing logic
        # For brevity, assume a function get_neighbors returns adjacent blocks
        neighbors = get_neighbors(block, blocks)
        for neighbor in neighbors:
            if not neighbor['active']:
                # Generate quad for the shared face
                quad = generate_quad(block, neighbor)
                quads.append(quad)
    return quads

def render_depth_pass(bounding_geometry, camera, screen_width, screen_height):
    """
    First pass: Rasterize bounding geometry to get t_start and t_exit.
    """
    # Initialize depth buffers
    t_start_buffer = np.full((screen_height, screen_width), np.inf)
    t_exit_buffer = np.full((screen_height, screen_width), -np.inf)
    
    # Rasterize front faces (keep min depth)
    for quad in bounding_geometry.front_faces:
        for pixel in quad.rasterize(camera, screen_width, screen_height):
            t = quad.depth_at_pixel(pixel)
            if t < t_start_buffer[pixel.y, pixel.x]:
                t_start_buffer[pixel.y, pixel.x] = t
                
    # Rasterize back faces (keep max depth)
    for quad in bounding_geometry.back_faces:
        for pixel in quad.rasterize(camera, screen_width, screen_height):
            t = quad.depth_at_pixel(pixel)
            if t > t_exit_buffer[pixel.y, pixel.x]:
                t_exit_buffer[pixel.y, pixel.x] = t
                
    return t_start_buffer, t_exit_buffer

def ray_casting_loop(t_start, t_exit, volume, camera, block_min_max):
    """
    Second pass: Cast rays within the computed bounds.
    """
    image = np.zeros((camera.height, camera.width, 3))
    
    for y in range(camera.height):
        for x in range(camera.width):
            t_min = t_start[y, x]
            t_max = t_exit[y, x]
            
            if t_min >= t_max:
                continue # Pixel is in empty space
                
            ray_origin = camera.position
            ray_direction = camera.get_ray_direction(x, y)
            
            # Initialize accumulation variables
            color = (0.0, 0.0, 0.0)
            transmittance = 1.0
            
            # March ray
            t = t_min
            while t < t_max:
                # Sample volume at current t
                # Note: Adaptive sampling or step size adjustment may be used
                sample_pos = ray_origin + t * ray_direction
                voxel_value = volume.sample(sample_pos)
                
                # Check if sample is in active region using block min-max
                # If not active, skip this sample (and potentially advance t)
                if not is_active_block(sample_pos, block_min_max):
                    t += step_size
                    continue
                    
                # Compute color and opacity from transfer function
                alpha, rgb = transfer_function(voxel_value)
                
                # Front-to-back compositing
                color += rgb * alpha * transmittance
                transmittance *= (1.0 - alpha)
                
                if transmittance < epsilon:
                    break # Ray is fully opaque
                    
                t += step_size
                
            image[y, x] = color
            
    return image
```

**Parameters:**
*   **Block Size:** Regular subdivision of volume into small blocks, e.g., $4^3$ or $8^3$ voxels per block [S1].
*   **Isovalue Threshold:** Determines active blocks [S1][S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Enclosed Inactive Blocks:** The bounding geometry approach does not exclude inactive blocks from the search range if they are enclosed by active blocks with respect to the viewing direction. Samples in these blocks are skipped on a per-sample basis early in the ray-casting loop [S1].
*   **Isovalue Changes:** The bounding geometry must be regenerated whenever the isovalue changes, as active blocks may change [S1][S2, unofficial].

## Subtopics

### [Early Shader Termination](969-early-shader-termination.md)
Early Shader Termination is an optimization technique that discards the execution of complex decoding shaders for fragments likely to represent empty space by using an early z-test in a two-pass rendering approach. It builds on [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) by adding a lightweight pre-check to avoid expensive shader execution in empty regions [G]. Compared to rendering uncompressed data, this approach initially perceives a loss in performance of a factor of 2-3 due to complex shaders and texture indirections; however, in empty regions, it results in a considerable speed-up because only one texture fetch is needed to check the mean.

### [Rasterizing Bounding Geometry for Empty Space Skipping](5141-rasterizing-bounding-geometry-for-empty-space-skipping.md)
This method exploits hardware-accelerated rasterization to skip over empty space in volume rendering, avoiding the overhead of explicit tree traversal on the GPU. It sets itself apart from sibling methods like [Early Shader Termination](969-early-shader-termination.md) by using the fragment positions of rasterized bounding geometry faces as the start and end points for ray casting, which can lead to fewer look-ups into the empty-space skipping data structure compared to traditional octree structures.

### Overlapped Min-Max Block
A data structure for empty-space skipping in pre-integrated volume rendering. It modifies the region covered by each block so that each block covers some region of which thickness is at least the sampling distance. By overlapping the region of each block, a line segment formed by two sampling points can be tested for transparency using only one block, avoiding the overhead of determining which of multiple intersecting blocks are transparent [S3]. Unlike previous methods where a line segment may intersect at most three blocks and requires testing all intersecting blocks (creating overhead to determine cases like Fig. 1a vs 1b), this method tests only one block due to the overlapping region design [S3].

## Operating characteristics
*   **Time Complexity:** The bounding geometry generation is $O(N)$ where $N$ is the number of blocks. The rasterization pass is $O(P)$ where $P$ is the number of pixels. The ray casting loop is proportional to the number of active samples, which is significantly reduced compared to full volume traversal.
*   **Memory Complexity:** Requires storage for the volume texture, the block min-max structure ($O(N)$), and the bounding geometry mesh.
*   **Strengths:** Efficiently skips large empty regions using hardware rasterization. Reduces per-sample overhead compared to image-order skipping for large empty spaces [S1].
*   **Limitations:** Does not handle enclosed inactive blocks efficiently (requires per-sample checks). Geometry regeneration is needed for isovalue changes [S1][S2, unofficial].
*   **When to Use:** Suitable for real-time ray-casting on GPUs where large empty spaces are common and isovalue changes are infrequent [S1].

## Background
Object-Order Empty Space Skipping was introduced in the context of GPU-based ray-casting for real-time volume rendering [S1]. It was developed to overcome limitations of earlier approaches that used multiple passes or had high per-sample overhead for empty space skipping [S1]. The technique leverages the graphics pipeline's rasterization capabilities to compute ray bounds, a concept further explored in implementations using OpenGL [S2, unofficial]. It is often used in conjunction with adaptive sampling and iterative bisection for intersection refinement [S1].
