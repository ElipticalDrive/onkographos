# Distance Map Acceleration

Also called: Accelerated Volume Rendering with Chebyshev Distance Maps, Chebyshev Distance Maps, Chebyshev distance map ray traversal, Distance Field Ray Marching Acceleration, Empty space skipping using distance maps, Ray Traversal with Distance Map Skipping

## Overview
Distance Map Acceleration is a ray traversal technique that uses a precomputed Chebyshev distance map alongside an occupancy map to skip sampling points in empty regions of a volumetric image, thereby reducing texture memory bandwidth and improving frame rates for volume and isosurface rendering [S1]. It differs from its sibling [Two-stage Ray Marching with Empty-Space Skipping](2985-two-stage-ray-marching-with-empty-space-skipping.md) by using a global distance field to determine skip distances rather than a two-stage hierarchical traversal, and from [Hierarchical Sampling with Occupancy Grid](3035-hierarchical-sampling-with-occupancy-grid.md) by computing exact Chebyshev distances to the nearest occupied block rather than relying solely on binary occupancy flags for coarse skipping [S1].

## How it works
The method accelerates ray casting by precomputing a distance map that encodes the Chebyshev distance from each voxel in the occupancy grid to the nearest occupied region. During rendering, this distance map allows the ray caster to leap over large empty segments in a single step.

### Inputs and Outputs
**Inputs:**
*   High-resolution volume data (scalar field).
*   Transfer function (TF) parameters defining opacity and gradient thresholds [S1][S2, unofficial].
*   Ray origin and direction for each pixel.
*   Camera parameters (view/projection matrices) [S2, unofficial].

**Outputs:**
*   Rendered 2D image with compositing.
*   (Preprocessing) Occupancy map and Chebyshev distance map [S1][S2, unofficial].

### Data Structures
1.  **Volume Texture:** 3D texture storing scalar voxel values. Resolution $d_{\text{vol}} = (d_x, d_y, d_z)$ [S1].
2.  **Occupancy Map:** 3D texture/grid with resolution $d_{\text{occ}} = (d_x/B, d_y/B, d_z/B)$, where $B$ is the block size [S1]. Each voxel stores a binary flag: 1 if the block contains non-empty data, 0 otherwise [S1].
3.  **Distance Map:** 3D texture with resolution $d_{\text{occ}}$. Each voxel stores the Chebyshev distance (in blocks) to the nearest occupied block [S1].
4.  **Gradient Map (Optional):** 3D texture storing precomputed gradient magnitudes for each voxel, computed via the tetrahedron method [S1].

### Preprocessing Steps
Before ray traversal, the acceleration structures must be generated:

1.  **Gradient Map Generation (Optional):** If `use_precomputed_gradient` is true, dispatch a compute shader to compute gradient magnitudes for all voxels using the tetrahedron method [S2, unofficial]. The gradient magnitude $g$ at position $pos$ is calculated as:
    $$
    g(pos) = \left\| 0.25 \cdot \left( k_{xyy} \cdot V(pos + k_{xyy}) + k_{yyx} \cdot V(pos + k_{yyx}) + k_{yxy} \cdot V(pos + k_{yxy}) + k_{xxx} \cdot V(pos + k_{xxx}) \right) \right\|
    $$
    where $V$ is the volume texture, and $k$ is a set of 4 offset vectors derived from the tetrahedron decomposition [S1].
2.  **Occupancy Map Generation:** Dispatch a compute shader to generate the occupancy map. For volume rendering, a block is occupied if it contains any voxels with non-zero alpha as determined by the transfer function [S1]. For isosurface rendering, a block is occupied if the isosurface threshold lies between the minimum and maximum voxel values within the block, including a single-voxel halo around the region [S1].
3.  **Distance Map Computation:** Convert the occupancy map to a Chebyshev distance map. This is typically done using a multi-stage algorithm (e.g., partitioned distance map combination) to compute the distance from every empty block to the nearest occupied block [S1][S2, unofficial]. The Chebyshev distance between two points $(x_1, y_1, z_1)$ and $(x_2, y_2, z_2)$ is $\max(|x_1-x_2|, |y_1-y_2|, |z_1-z_2|)$ [S1].

### Ray Traversal Algorithm
For each ray, the renderer determines the entry and exit points $t_{\text{entry}}$ and $t_{\text{exit}}$ in normalized texture coordinates $[0, 1]$ [S1].

1.  **Calculate Sampling Parameters:**
    Compute the number of equidistant sampling points $n$ required to ensure at least one sample per voxel on average:
    $$
    n = \lceil \max \vec{x}(\mathbf{d}) \cdot \| \mathbf{t}_{\text{exit}} - \mathbf{t}_{\text{entry}} \| \cdot f \rceil
    $$
    where $\mathbf{d}$ is the ray direction in texture coordinate space, $\max \vec{x}$ is the maximum component operator, and $f \ge 1$ is a sampling factor for quality adjustment [S1].
    Compute the step size in normalized coordinates:
    $$
    \Delta t = \frac{t_{\text{exit}} - t_{\text{entry}}}{n - 1}
    $$
    The $i$-th sampling point is $\mathbf{t}_i = \mathbf{t}_{\text{entry}} + i \cdot \Delta t$ for $i = 0 \dots n-1$ [S1].

2.  **Ray Marching with Distance Map Skipping:**
    Initialize current position $t = t_{\text{entry}}$.
    While $t < t_{\text{exit}}$:
    a. Map current normalized coordinate $t$ to occupancy map coordinate $u_{\text{occ}}$:
       $$
       u_{\text{occ}} = \frac{d_{\text{vol}}}{B} \cdot t
       $$
       (Note: Exact mapping accounts for non-even division of $d_{\text{vol}}$ by $B$ [S1]).
    b. Sample the distance map at $u_{\text{occ}}$. Let $D$ be the stored Chebyshev distance value.
    c. **Skip Logic:**
       If the block is occupied (or if $D=0$), proceed to standard sampling.
       If the block is empty ($D > 0$), calculate the skip distance. The distance map stores the distance in *blocks*. The number of steps $\Delta i$ to reach the next occupied region is derived from $D$. Specifically, the ray can skip $\Delta i$ samples such that the new position is at least $D$ blocks away from the current empty region boundary.
       *Implementation Note:* The exact step count $\Delta i$ to reach the next occupied block boundary for dimension $j$ is calculated as [S1]:
       $$
       \Delta i_j = \begin{cases} \lceil (1 + \lfloor u_{\text{occ},j} \rfloor - u_{\text{occ},j}) / \Delta u_j \rceil & \text{if } \Delta u_j > 0 \\ \lceil (\lfloor u_{\text{occ},j} \rfloor - u_{\text{occ},j}) / \Delta u_j \rceil & \text{otherwise} \end{cases}
       $$
       However, with a distance map, the skip is often simplified: the ray advances by a distance corresponding to $D$ blocks. The step count in samples is $\Delta i = \lceil D \cdot B \cdot \Delta t \cdot \text{scale} \rceil$ (where scale accounts for ray direction normalization). The sources specify that the distance map is used to "efficiently leap rays past empty regions" [S1]. The precise leap is determined by the Chebyshev distance value $D$ read from the map.
    d. **Sampling:**
       If not skipped, sample the volume at $t$. If a gradient map is used, sample it as well. Apply the transfer function to compute color and opacity. Perform front-to-back compositing.
    e. **Termination:**
       Check for early ray termination (if enabled). If opacity threshold is reached, break.
    f. **Advance:**
       $t = t + \Delta t$ (or $t + \Delta t \cdot \Delta i$ if skipping).

### Parameters
*   $B$: Block size. Default 4 ($4^3$ blocks) [S2, unofficial]. A block size of $B=4^3$ reduces occupancy map memory to 1/64th of the volume [S1].
*   $f$: Sampling factor. $f \ge 1$ [S1].
*   `imin`, `imax`: Intensity thresholds for transfer function. Default 0.1, 1.0 [S2, unofficial].
*   `gmin`, `gmax`: Gradient thresholds. Default 0.0, 0.2 [S2, unofficial].
*   `clip_distance`: Distance from camera for volume clipping. Default 1.0f in benchmark mode [S2, unofficial].
*   `skipmode`: Strategy for empty space skipping. Default `Distance` [S2, unofficial].

### Edge Cases and Pitfalls
*   **Boundary Conditions:** The mapping between volume coordinates and occupancy map coordinates must handle cases where $d_{\text{vol}}$ is not evenly divisible by $B$. The volume block extents are defined as $u_{\text{vol}}^{\min} = B \cdot u_{\text{occ}}$ and $u_{\text{vol}}^{\max} = \min(u_{\text{vol}}^{\min} + B, d_{\text{vol}}) - 1$ [S1].
*   **Isosurface Halo:** For isosurface rendering, the occupancy map generation must include a single-voxel halo around each region to ensure isosurfaces at block boundaries are not missed [S1].
*   **Precision:** Floating-point precision in texture lookups for the distance map can affect skip accuracy. High-precision textures may be required for large volumes [G].
*   **Camera Inside Volume:** The renderer supports the viewpoint entering the volume by clipping the volume at a specified distance and computing box-plane intersection vertices in a vertex shader [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(d_{\text{vol}})$ for gradient/occupancy/distance map generation. Ray traversal is $O(N_{\text{samples}})$ in the worst case (fully occupied), but significantly faster in sparse volumes due to skipping. The number of texture samples is reduced proportionally to the amount of empty space skipped [S1].
*   **Memory Complexity:** Occupancy map requires $1/B^3$ of the volume memory. Distance map requires similar memory to the occupancy map (storing integer distances) [S1]. Gradient map requires additional $O(d_{\text{vol}})$ memory if precomputed [S1].
*   **Performance:** The method improves frame rates by reducing unnecessary texture samples in empty regions [S1]. Performance depends heavily on the sparsity of the volume and the accuracy of the distance map [S1].
*   **Strengths:** Efficient empty space skipping; supports both volume and isosurface rendering; precomputed gradients reduce per-sample cost [S1][S2, unofficial].
*   **Limitations:** Requires preprocessing time and memory for distance maps; distance map computation can be complex for large volumes (hence partitioned approaches) [S1].

## Background
The method was introduced by Lachlan Deakin and Mark Knackstedt in 2019 as "Accelerated Volume Rendering with Chebyshev Distance Maps" [S2, unofficial]. It builds upon earlier work on occupancy maps and empty space skipping [S1]. The implementation is available in the open-source Vulkan renderer `VkVolume` [S2, unofficial].
