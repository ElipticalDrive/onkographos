# Voxel Grid Raycasting

Also called: DDA Ray Tracing, Ray Marching through Voxel Grid, Uniform Grid Raycasting, Voxel Ray Marching, Voxel Ray Tracing with Voxel Marching, Voxel-Volume-Raycasting, Voxelization Raycasting

## Overview
Voxel Grid Raycasting is a rendering technique that stores scene geometry in a 3D voxel grid and traces rays through the grid by stepping from voxel to voxel, checking for occupied voxels to determine intersections and surface normals [S1, unofficial]. It solves the problem of efficiently determining ray-voxel intersections without explicit geometric intersection tests [S2, unofficial]. It is distinct from [Sparse Voxel Traversal](1525-sparse-voxel-traversal.md) by assuming a dense, regular grid layout rather than a sparse octree or brick-based structure [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** Ray origin $O$, ray direction $D$ (normalized), voxel grid dimensions, voxel size (bin size), and the voxel data buffer [S1, S2, S4, unofficial].
- **Output:** Intersection distance, hit position, surface normal, and optionally accumulated color [S1, S2, unofficial].

**Data Structures:**
The voxel grid is stored in a single storage buffer or array [S1, unofficial].
- **Format 1 (S1):** `array<u32>` where each `u32` represents a single voxel [S1, unofficial]. A value of `0u` indicates an empty voxel; non-zero values indicate occupied voxels, where the value encodes color via `unpack4x8unorm` [S1, unofficial].
- **Format 2 (S2):** `int` array of size $16 \times 16 \times 16$ (4096 elements), bound to `layout(std430, binding = 0)` [S2, unofficial].
- **Indexing:**
  - For Format 1: $index = x + y \cdot W + z \cdot (W \cdot H)$, where $x,y,z$ are grid coordinates, $W$ is chunk width, and $H$ is chunk height [S1, unofficial].
  - For Format 2: $index = (x \cdot 16 + z) \cdot 16 + y$ [S2, unofficial].

**Algorithm Steps:**
1. **Initialization:**
   - Normalize ray direction: $ray = \text{normalize}(ray\_end - ray\_start)$ [S2, unofficial].
   - Calculate initial grid position: $grid\_pos = \lfloor (start\_pos - min\_pos) \cdot inv\_voxel\_size \rfloor$ [S1, unofficial].
   - Determine direction indicators: $ray\_dir\_i = \text{sign}(ray\_dir)$ (1 if $>0$, -1 otherwise) [S1, unofficial].
   - Calculate step deltas: $dt = |voxel\_size / ray\_dir|$ [S1, unofficial].
   - Calculate initial time to next voxel boundary $t_{max}$ based on the fractional part of the start position within the voxel [S1, unofficial].
   - *Edge Case:* If a ray component is 0, set corresponding $t_{max}$ and $dt$ to `FLT_MIN` to avoid division by zero, effectively removing that axis from the traversal comparison logic [S2, unofficial].
   - *Edge Case:* If the ray starts in a voxel different from the last voxel and moves in a negative direction, decrement the corresponding voxel coordinate to ensure correct traversal start [S2, unofficial].

2. **Traversal Loop:**
   - Find the axis with the minimum $t_{max}$ value: $last\_axis = \text{argmin}(t_{max})$ [S1, unofficial].
   - Increment the grid position on that axis by $ray\_dir\_i[last\_axis]$ [S1, unofficial].
   - Update the distance traveled to $t_{max}[last\_axis]$ [S1, unofficial].
   - Increment $t_{max}[last\_axis]$ by $dt[last\_axis]$ to move to the next boundary on that axis [S1, unofficial].
   - Check for hit: Load voxel data at $grid\_pos$ [S1, unofficial]. If occupied, calculate the surface normal using $axis\_dir\_normal(last\_axis, ray\_dir)$ and terminate [S1, unofficial].

3. **Ray Bouncing (Optional):**
   - If stochastic reflection is enabled, spawn a new ray from $start\_pos + dist \cdot ray\_dir + \epsilon \cdot normal$ [S1, unofficial].
   - $\epsilon$ is a small offset (e.g., $voxel\_size \cdot 0.01$) to prevent self-intersection [S1, unofficial].
   - Attenuate color and repeat traversal up to a max depth (e.g., 3 bounces) [S1, unofficial].

**Formulas:**
- Grid Index: $index = x + y \cdot W + z \cdot (W \cdot H)$ [S1, unofficial].
- Ray-Voxel Step Delta: $dt = \frac{voxel\_size}{|ray\_dir|}$ [S1, unofficial].
- Time to Next Boundary: $t_{max} = \frac{left}{ray\_dir}$, where $left$ is the distance to the next voxel boundary in the direction of travel [S1, unofficial].
- Distance to Next Grid Intersection: $t = \frac{target - position}{direction}$, where $target$ is $reference$ if $direction < 0.0$, otherwise $reference + 1$ [S5, unofficial].

**Parameters:**
- `voxel_size`: $0.1$ world units [S1, unofficial].
- `_bin_size`: $1.0$ world units (hardcoded in some implementations) [S2, unofficial].
- `epsilon`: $voxel\_size \cdot 0.01$ [S1, unofficial].
- `max_dist`: $16.0$ world units [S1, unofficial].

**Pseudocode:**
```python
def voxel_grid_raycast(origin, direction, voxel_size, grid_min, grid_max, is_occupied):
    # 1. Initialization
    ray = [d / sum(d*d for d in direction)**0.5 for d in direction]
    inv_ray = [1.0 / d if d != 0.0 else 0.0 for d in ray]
    
    # Initial voxel coordinate
    current_voxel = [int((origin[i] - grid_min[i]) // voxel_size) for i in range(3)]
    
    # Step direction per axis
    step = [1 if ray[i] >= 0 else -1 for i in range(3)]
    
    # Distance to next boundary
    next_boundary = [(current_voxel[i] + step[i]) * voxel_size + grid_min[i] for i in range(3)]
    
    # tMax: distance along ray to next boundary
    t_max = [(next_boundary[i] - origin[i]) * inv_ray[i] if ray[i] != 0 else float('inf') for i in range(3)]
    
    # tDelta: distance along ray to traverse one voxel width
    t_delta = [voxel_size * inv_ray[i] * step[i] if ray[i] != 0 else float('inf') for i in range(3)]
    
    MAX_ITERATIONS = 512
    max_dist = 16.0
    
    # 2. Traversal Loop
    for _ in range(MAX_ITERATIONS):
        # Check bounds
        if not all(grid_min[i] <= current_voxel[i] * voxel_size + grid_min[i] < grid_max[i] for i in range(3)):
            return None
            
        # Check occupancy
        if is_occupied(current_voxel):
            # Determine normal based on which axis had the minimum t_max before stepping
            last_axis = t_max.index(min(t_max))
            normal = [0.0, 0.0, 0.0]
            normal[last_axis] = -step[last_axis]
            return {'hit': True, 'voxel': current_voxel, 'normal': normal}
            
        # Find axis with minimum t_max
        last_axis = t_max.index(min(t_max))
        
        # Step on that axis
        current_voxel[last_axis] += step[last_axis]
        
        # Update t_max for that axis
        t_max[last_axis] += t_delta[last_axis]
        
    return None
```

## Subtopics

### [Voxel-Cell Duality Mapping](2240-voxel-cell-duality-mapping.md)
Voxel-Cell Duality Mapping is a technique for ray tracing isosurfaces defined within cells of 8 voxels using an octree that stores scalar values at voxel centers. It establishes a dual relationship between voxels and cells by logically shifting scalar positions backward by half a voxel width, allowing the ray tracer to intersect 8-voxel cell primitives defined by the stored leaf values. Unlike methods that expand storage to hold complete cell data, this method retrieves forward neighbors at intersection time, maintaining single scalar storage per leaf.

### [Spherical Volume Ray Walking](3865-spherical-volume-ray-walking.md)
Spherical Volume Ray Walking is a fast voxel traversal algorithm for rendering volumetric data defined on a spherical coordinate grid. It extends the cartesian fast voxel traversal method by Amanatides and Woo to non-cartesian grids, iterating through radial, polar, and azimuthal voxel boundaries to determine the sequence of voxels intersected by a ray. Unlike [Voxel Grid Raycasting](2218-voxel-grid-raycasting.md) which assumes axis-aligned bounding boxes, this method handles the curved boundaries of spherical sectors, using line-sphere intersection for radial steps and 2D segment intersection for angular boundaries.

### [Plane Marching](3959-plane-marching.md)
Plane Marching is a raymarching technique for voxel grids that advances a ray by stepping to the nearest intersection with the integer grid planes separating voxel layers. It solves the problem of traversing a dense voxel volume to find the first solid voxel by checking occupancy at each plane boundary. Unlike shape-assisted siblings such as [Sphere Assisted Raymarching](3865-sphere-assisted-raymarching.md) or [Optimised Voxel Ray Marching](4240-optimised-voxel-ray-marching.md), it does not store auxiliary distance fields or shape metadata, relying solely on the geometric structure of the grid. This makes it simple to implement but fragile in empty space, as it never skips more than one voxel per step.

### [RLE4 Ray Tracing](5228-rle4-ray-tracing.md)
RLE4 Ray Tracing is a ray-marching and voxel-intersection algorithm that traverses an RLE4 (Run-Length Encoded 4D) compressed volume structure, also known as Map4, to locate the first occupied voxel along a ray or to colorize a voxel based on its position. It distinguishes itself from standard voxel grid traversal by using slab-based RLE encoding to skip empty space efficiently, reducing the number of memory accesses required to find occupied regions.

### [Sparse Shadow Volume Raycast](5632-sparse-shadow-volume-raycast.md)
A hierarchical raycasting algorithm that traverses a sparse shadow volume texture to find the first intersection with a shadow-casting volume. It differs from fixed-step hierarchical variants by dynamically adjusting its traversal step size and level of detail (LOD) based on occupancy bits, allowing it to skip empty space efficiently in sparse representations.

### [Regular Grid Traversal](5939-regular-grid-traversal.md)
Regular Grid Traversal accelerates ray-scene intersection by stepping through a uniform 3D grid of cells, skipping empty space without primitive tests. It differs from hierarchical methods (e.g., [Sparse Voxel Traversal](5228-sparse-voxel-tracing.md)) by using a fixed-size array, offering high cache efficiency on GPUs for uniform data but requiring $O(N^3)$ memory.

### [Voxel Raytracer](6403-voxel-raytracer.md)
A voxel raytracer renders 3D voxel models by marching rays through a 3D grid of voxels, supporting multiple bounces for diffuse reflection and a ground plane. It differs from standard voxel grid raycasting by implementing a full path-tracing loop with diffuse scattering and anti-aliasing, rather than simple direct illumination or single-pass raymarching.

### [DirectVoxGO Volume Rendering](6412-directvoxgo-volume-rendering.md)
DirectVoxGO is a volume rendering method that accelerates neural radiance field (NeRF) training and inference by sampling points directly on a structured voxel grid rather than uniformly along rays. It solves the problem of inefficient ray marching in sparse scenes by using a mask cache to skip free space and a direct lookup of density and color features from the voxel grid. It sets itself apart from standard NeRF by replacing uniform sampling with grid-based point selection and from other sparse voxel methods by using a dense voxel grid with a binary mask cache for acceleration.

### Voxel Resolve Search
A search algorithm used by voxel resolve and GI update to find the pixel's voxel again in the brick named by the visibility buffer [S6, unofficial]. It finds the cell holding the ray's point at the stored depth, then the two cells along each axis whose centers lie nearest that point, stopping at the first cell whose hit gives the stored depth again, bit for bit [S6, unofficial]. A voxel's test depends only on the ray and the voxel, ensuring every pass meets it at the same $t$ [S6, unofficial].

### Narrow Band Voxelization
A narrow band strategy that does not use any solver [S7]. When the algorithm reaches a narrow band voxel, it immediately returns a hit, resulting in a voxelization of the scene [S7].

### Dense Octree Accelerated Raymarching
An acceleration structure using a dense octree stored in a 3D texture to skip empty space during ray traversal [S8, unofficial]. The raymarcher first traverses the octree texture; once it hits a leaf node (occupied octant), it switches to the fine-grained voxel texture for detailed collision detection [S8, unofficial]. The octree is stored as a 3D texture (`texture_3d<u32>`) with data for different levels interleaved in the Z dimension [S8, unofficial]. The implementation uses a 3D texture for the octree instead of a linear buffer with Morton curve ordering, which was found to be significantly faster for ray traversal because graphics hardware is optimized for spatially local texture access [S8, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources [S2, unofficial]. Standard DDA traversal steps through each intersected voxel once, making it proportional to the ray length divided by voxel size [G].
- **Memory Complexity:** Not given in the sources [S1, unofficial]. Requires $O(V)$ memory where $V$ is the total number of voxels in the grid [G].
- **Performance:** Highly efficient on GPUs due to regular memory access patterns and predictable branching [S1, S2, unofficial]. Performance degrades in dense scenes or when rays traverse many empty voxels without skipping them [S1, unofficial].
- **Strengths:** Simple implementation, no preprocessing overhead for hierarchy construction, excellent cache locality on uniform grids [S3, unofficial].
- **Limitations:** Memory usage scales with the cube of the grid resolution, making it unsuitable for very large scenes without sparsity techniques [S3, unofficial]. Precision issues can occur with large coordinates or small voxel sizes [S1, unofficial].

## Background
Voxel Grid Raycasting is a fundamental technique in volume rendering and voxel-based games [S1, unofficial]. It is often associated with the "DDA" (Digital Differential Analyzer) algorithm for grid traversal, originally described by Amanatides and Woo [S3, unofficial]. The method is a core component of many voxel engines and is frequently compared to or combined with sparse voxel octrees for larger scale scenes [S1, S2, unofficial].
