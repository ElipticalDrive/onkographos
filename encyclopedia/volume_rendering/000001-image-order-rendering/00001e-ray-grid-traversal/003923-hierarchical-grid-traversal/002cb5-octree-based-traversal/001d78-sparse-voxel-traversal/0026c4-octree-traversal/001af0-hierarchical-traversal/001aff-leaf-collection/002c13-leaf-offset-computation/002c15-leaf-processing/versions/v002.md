# Leaf Processing

Also called: IndexGridBuilder::foreach

## Overview
Leaf Processing is the final data copying stage in hierarchical sparse voxel traversal pipelines, responsible for transferring precomputed voxel data from a contiguous source buffer into the leaf node buffers of an OpenVDB tree. It differs from its parent [Leaf Offset Computation](5185-leaf-offset-computation.md) by executing the actual memory copy operations using the offsets generated by the parent, and from its child [IndexGridBuilder::build](5203-indexgridbuilder-build.md) by handling single-grid data transfer rather than aggregating multiple grids into a flat array.

## How it works
**Inputs and Outputs:**
- **Input:** A contiguous source buffer containing voxel values (`data`), an array of precomputed linear offsets for each leaf (`m_leafOffsets`), and a `LeafManager` instance iterating over the tree's leaf nodes.
- **Output:** The leaf node buffers (`leaf.buffer().data()`) are populated with the corresponding voxel data from the source buffer.

**Data Structures:**
- `m_leafOffsets`: An array of `size_t` where the index corresponds to the leaf node index (`leafIdx`) and the value is the starting byte offset in the source `data` buffer.
- `LeafT::SIZE`: The number of voxels in a leaf node (typically $8^3 = 512$ for standard OpenVDB leaves).
- `ValueT`: The data type of the voxel values (e.g., `float`, `Vec3f`).

**Steps:**
1. Initialize a parallel iterator over the leaf nodes using `LeafManager::foreach`.
2. Configure the parallel execution with a chunk size of 12 to balance overhead and parallelism [S1, unofficial].
3. For each leaf node processed in parallel:
   a. Retrieve the leaf's global index (`leafIdx`).
   b. Look up the base offset for this leaf from `m_leafOffsets`: `leafBaseOffset = m_leafOffsets[leafIdx]`.
   c. Get the pointer to the leaf's internal buffer: `leafData = leaf.buffer().data()`.
   d. Calculate the source pointer: `sourcePtr = data + leafBaseOffset`.
   e. Copy the leaf's data from the source to the leaf buffer using `std::memcpy`. The number of bytes to copy is `LeafT::SIZE * sizeof(ValueT)`.

**Pseudocode:**
```python
def leaf_processing(data: List[ValueT], m_leafOffsets: List[int], leaf_manager: LeafManager, ValueT: type, LeafT: type):
    """
    Copies voxel data from a flat source buffer into OpenVDB leaf nodes in parallel.
    
    Args:
        data: Contiguous source buffer of voxel values.
        m_leafOffsets: Array mapping leaf index to byte offset in data.
        leaf_manager: Iterator over leaf nodes.
        ValueT: Data type of voxels.
        LeafT: Leaf node type, providing SIZE constant.
    """
    chunk_size = 12
    
    # Parallel iteration over leaves
    # The lambda function is executed for each leaf in parallel chunks
    leaf_manager.foreach(
        lambda leaf: process_leaf(leaf, data, m_leafOffsets, ValueT, LeafT),
        parallel=True,
        chunk_size=chunk_size
    )

def process_leaf(leaf, data, m_leafOffsets, ValueT, LeafT):
    """
    Copies data for a single leaf node.
    """
    # Get the index of the current leaf node
    leaf_idx = leaf.index()
    
    # Retrieve the precomputed base offset for this leaf
    leaf_base_offset = m_leafOffsets[leaf_idx]
    
    # Get pointer to the leaf's internal buffer
    leaf_data = leaf.buffer().data()
    
    # Calculate source pointer in the flat data array
    # Note: In C++, this is pointer arithmetic. In Python-like pseudocode, we assume
    # data is a byte array or list of values where indexing aligns with offsets.
    # Since offsets are in bytes, we must account for sizeof(ValueT).
    value_size = sizeof(ValueT)
    source_offset_in_values = leaf_base_offset // value_size
    
    # Number of values to copy
    num_values = LeafT.SIZE
    
    # Copy data
    # In a real implementation, this is std::memcpy or equivalent
    for i in range(num_values):
        leaf_data[i] = data[source_offset_in_values + i]
```

**Parameters:**
- `chunk_size`: 12 [S1, unofficial]. This value balances thread synchronization overhead with the granularity of parallel work units.

**Edge Cases and Pitfalls:**
- **Offset Mismatch:** If `m_leafOffsets` is not correctly aligned with the leaf indices, data will be copied to the wrong leaf nodes. The offsets must be computed by [Leaf Offset Computation](5185-leaf-offset-computation.md) before this step.
- **Buffer Bounds:** Ensure the source `data` buffer is large enough to accommodate the sum of all leaf data sizes. The total size should be `sum(LeafT::SIZE for all leaves) * sizeof(ValueT)`.
- **Thread Safety:** The `leaf_manager.foreach` implementation must ensure that different threads do not process the same leaf node. The chunking mechanism handles this by partitioning the leaf index space.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of active leaves. The work is linear in the number of leaves, with constant-time memory copy per leaf.
- **Memory Complexity:** $O(1)$ auxiliary space per leaf, as the copy is in-place into the leaf buffers. The source buffer is provided externally.
- **Performance:** Parallel execution with a chunk size of 12 [S1, unofficial] provides good load balancing for typical scene complexities. The use of `std::memcpy` ensures optimized memory transfer.
- **Strengths:** Simple, efficient, and parallelizable. Decouples data collection from offset computation.
- **Limitations:** Requires precomputed offsets. Not suitable for dynamic trees where leaf structure changes frequently without recomputing offsets.

## Background
This method is part of the HNanoSolver project, an unofficial implementation of hierarchical volume rendering techniques [S1, unofficial]. It is designed to efficiently populate OpenVDB leaf nodes for rendering pipelines that use sparse voxel representations.
