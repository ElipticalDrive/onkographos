# Two-level Nested Ray Marching

Also called: Front-to-back ray marching on AMR, Ray Marching with Coarse Mesh and Refinement Tree

## Overview
Two-level nested ray marching is a volume rendering technique that renders Adaptive Mesh Refinement (AMR) data by performing a coarse mesh traversal to identify active regions, followed by a fine-level ray march within the descendant elements of each coarse element [S1, unofficial]. It solves the problem of efficiently visualizing sparse, multi-resolution simulation data without the memory blow-up of uniform grid resampling, ensuring computational cost scales with the actual simulation data rather than the bounding box [S1, unofficial]. Unlike uniform grid resampling, which incurs memory, time, and quality costs, this method maintains native resolution [S2, unofficial]. It builds on [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md) by using a constant adjustable step size for the inner loop rather than hierarchical traversal for the fine level.

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a coarse mesh BVH; macrocell density values $\text{macrocellValues}$; a transfer function $\text{tf}$; a constant step size $s$; a background color $\mathbf{c}_{bg}$.
*   **Output:** Final pixel color $\mathbf{c}_{out}$.

**Data Structures:**
*   **Coarse Mesh:** A BVH where leaves are macrocells. Each macrocell stores a maximum density value used for culling.
*   **Refinement Tree:** A tetrahedral hierarchy. Each node (tetrahedron) stores vertex positions.
*   **Transfer Function:** Maps scalar values to color $\mathbf{c}_{tf}$ and opacity $\alpha_{tf}$.

**Parameters:**
*   **Step Size ($s$):** A constant adjustable step size. No adaptive adjustments are implemented [S1, unofficial].
*   **Opacity Threshold:** The marching loop continues while accumulated alpha $\alpha < 0.99$ [S1, unofficial].

**Algorithm Steps:**
1.  Initialize output color $\mathbf{c} = \{0,0,0\}$ and accumulated alpha $\alpha = 0$.
2.  Loop while $\alpha < 0.99$:
    a.  Traverse the coarse mesh BVH with the ray to find the current coarse element ID ($\text{coarseID}$), the back distance of the element ($t_{back}$), and the distance to the next face ($t_{nextFace}$). If $\text{coarseID} = -1$, break the loop [S1, unofficial].
    b.  Check if $\text{macrocellValues}[\text{coarseID}] \le 0$. If true, the element is empty; skip processing [S1, unofficial].
    c.  If not empty, call the inner marching function `MarchElement` with the ray, current color/alpha, $t_{back}$, $\text{coarseID}$, $s$, and $\text{tf}$ [S1, unofficial].
    d.  Update the ray parameter $t \leftarrow \max(t_{nextFace}, t)$ to advance to the next coarse element [S1, unofficial].
3.  Return $\mathbf{c}_{out} = (1 - \alpha) \mathbf{c}_{bg} + \mathbf{c}$ [S1, unofficial].

**Inner Loop (`MarchElement`):**
1.  Initialize $t_{exit} = 0$, $\text{sampleTetID} = 0$, and $\text{tetVertices} = \{\}$ [S1, unofficial].
2.  Loop while $t < t_{max}$ (where $t_{max}$ is the exit distance of the coarse element):
    a.  Calculate sample point $\mathbf{p} = \mathbf{o} + t \mathbf{d}$ [S1, unofficial].
    b.  If $t > t_{exit}$:
        i.  Traverse the refinement tree starting from $\text{sampleTetID}$ to find the current tetrahedron ID and its vertices [S1, unofficial].
        ii. Calculate $t_{exit}$ by intersecting the ray with the faces of the current tetrahedron [S1, unofficial].
    c.  Sample the scalar value $v$ at $\mathbf{p}$ using the current tetrahedron [S1, unofficial].
    d.  Advance $t \leftarrow t + s$ [S1, unofficial].
    e.  If $v$ is not in the transfer function range, continue to the next iteration [S1, unofficial].
    f.  Get transfer function color $\mathbf{c}_{tf}$ and opacity $\alpha_{tf}$ for $v$ [S1, unofficial].
    g.  Adjust opacity: $\alpha_{tf} \leftarrow \alpha_{tf} \times \text{tf.opacity}$ [S1, unofficial].
    h.  Accumulate using front-to-back compositing:
        $$ \mathbf{c} \leftarrow \mathbf{c} + (1 - \alpha) \alpha_{tf} \mathbf{c}_{tf} $$
        $$ \alpha \leftarrow \alpha + \alpha_{tf} (1 - \alpha) $$
    i.  Continue to next iteration [S1, unofficial].
3.  Return $\mathbf{c}, \alpha$ [S1, unofficial].

**Pseudocode:**
```python
def ray_march_coarse(ray, macrocell_values, step_size, tf, bg_color):
    color = [0.0, 0.0, 0.0]
    alpha = 0.0
    while alpha < 0.99:
        coarse_id, t_back, t_next_face = traverse_coarse_mesh(ray)
        if coarse_id == -1:
            break
        if macrocell_values[coarse_id] <= 0:
            ray.t = max(t_next_face, ray.t)
            continue
        
        color, alpha = march_element(ray, color, alpha, t_back, coarse_id, step_size, tf)
        ray.t = max(t_next_face, ray.t)
    
    return (1.0 - alpha) * bg_color + color

def march_element(ray, color, alpha, t_max, coarse_tet_id, step_size, tf):
    t_exit = 0.0
    sample_tet_id = 0
    tet_vertices = []
    
    while ray.t < t_max:
        sample_point = ray.org + ray.t * ray.dir
        
        if ray.t > t_exit:
            sample_tet_id, tet_vertices = traverse_refinement_tree(sample_point, coarse_tet_id)
            t_exit = intersect_faces(ray.t, sample_point, ray.dir, tet_vertices)
        
        scalar = sample_data(sample_point, sample_tet_id, tet_vertices)
        ray.t = ray.t + step_size
        
        if not tf.in_range(scalar):
            continue
            
        tf_color = tf.get_color(scalar)
        tf_opacity = tf_color.opacity * tf.opacity
        
        color = color + (1.0 - alpha) * tf_opacity * tf_color.color
        alpha = alpha + tf_opacity * (1.0 - alpha)
        
    return color, alpha
```

**Edge Cases and Pitfalls:**
*   **Precision:** The use of a constant step size means that regions with very high frequency detail may be undersampled if the step size is too large, while sparse regions may be oversampled [S1, unofficial].
*   **Boundary Handling:** The transition between coarse elements relies on $t_{nextFace}$. If $t$ is not correctly advanced, rays may re-sample the same element or miss gaps [S1, unofficial].
*   **Empty Elements:** The check `macrocellValues[coarseID] <= 0` is critical for performance. If macrocell values are inaccurate, empty regions may be processed unnecessarily [S1, unofficial].

## Subtopics

### [AMR Volume Ray-Casting](4032-amr-volume-ray-casting.md)
AMR Volume Ray-Casting is a volume rendering technique that ray-marches Adaptive Mesh Refinement (AMR) octrees directly without resampling to a uniform grid, avoiding the $(2^{l_{max}})^3$ memory blow-up. It solves the problem of efficiently visualizing sparse, multi-resolution simulation data by storing each leaf once in a per-level hash and stepping by the local cell size, ensuring computational cost scales with the actual simulation data rather than the bounding box. Unlike uniform grid resampling, which incurs memory, time, and quality costs, this method maintains native resolution.

## Operating characteristics
*   **Time Complexity:** The coarse traversal is $O(\log N)$ for $N$ macrocells. The inner march is $O(L \cdot \frac{D}{s})$ where $L$ is the number of tetrahedra intersected, $D$ is the path length, and $s$ is the step size. The total cost is proportional to the number of samples taken within active coarse elements.
*   **Memory Complexity:** $O(N)$ for the coarse mesh and $O(M)$ for the refinement tree, where $M$ is the number of tetrahedra. No uniform grid storage is required [S1, unofficial].
*   **Performance:** Performance is highly dependent on the step size and the sparsity of the data. Smaller step sizes increase accuracy but reduce performance [S1, unofficial].
*   **Strengths:** Avoids memory blow-up of uniform grids; maintains native resolution; efficient culling of empty regions via macrocells [S1, unofficial].
*   **Limitations:** Constant step size may lead to aliasing or inefficiency; no adaptive step size is implemented [S1, unofficial].

## Background
The method was described in a thesis by a researcher at Bilkent University, focusing on direct volume rendering of tree-based tetrahedral AMR data [S1, unofficial]. It addresses the limitations of uniform grid rendering for sparse AMR data.
