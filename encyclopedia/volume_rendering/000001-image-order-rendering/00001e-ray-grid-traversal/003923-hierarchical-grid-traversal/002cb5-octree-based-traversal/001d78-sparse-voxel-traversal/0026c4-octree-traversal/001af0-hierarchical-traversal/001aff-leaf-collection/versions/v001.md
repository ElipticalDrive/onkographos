# Leaf Collection

Also called: Leaf Node Collection, Leaf Extraction

## Overview
Leaf Collection is a hierarchical traversal method that extracts the leaf nodes of a tree structure (typically an octree) into a linear list for subsequent processing, such as ray marching or shading. It solves the problem of efficiently identifying which spatial regions contain data without traversing the entire tree depth-first for every ray. It differs from sibling methods like [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by decoupling the traversal logic from the ray-casting logic, allowing for batched or parallel processing of leaf nodes, whereas HDDA integrates traversal into the rasterization pipeline.

## How it works
**Inputs:** A root node of a hierarchical structure (e.g., octree); a traversal callback or function.
**Outputs:** A vector/list of leaf node coordinates and their associated depth levels.

**Data Structures:**
*   **Result Vector:** A dynamic array storing tuples of `(x, y, z, depth)`.
*   **Node:** Each node contains a type indicator (Empty, Full, Branch, Leaf) and, if a Branch, pointers or indices to 8 children.

**Steps:**
1.  Initialize an empty result vector.
2.  Call the recursive collection function on the root node with initial coordinates `(0, 0, 0)` and depth `0`.
3.  **Recursive Function `Collect(node, cx, cy, cz, depth)`:**
    1.  Determine the type of `node`.
    2.  If `node` is **Empty**, **Full**, or **Leaf**:
        *   Append `(cx, cy, cz, depth)` to the result vector [S1, unofficial].
    3.  If `node` is a **Branch**:
        *   Iterate through its 8 children (octants 0 to 7).
        *   For each child `i` (where `i` is the octant index):
            *   Calculate child coordinates:
                $$cx_{child} = cx \times 2 + (i \& 1)$$
                $$cy_{child} = cy \times 2 + ((i >> 1) \& 1)$$
                $$cz_{child} = cz \times 2 + ((i >> 2) \& 1)$$
            *   Recursively call `Collect(child, cx_{child}, cy_{child}, cz_{child}, depth + 1)` [S1, unofficial].

**Pseudocode:**
```python
def collect_leaves(node, cx, cy, cz, depth, result):
    """
    Recursively collects leaf/terminal nodes from a hierarchical tree.
    
    Args:
        node: The current tree node object.
        cx, cy, cz: Integer coordinates of the current node's top-left corner.
        depth: Current depth level in the tree.
        result: List to append (cx, cy, cz, depth) tuples to.
    """
    # Determine node type
    node_type = node.get_type()
    
    if node_type in (NodeType.EMPTY, NodeType.FULL, NodeType.LEAF):
        # Terminal nodes are collected
        result.append((cx, cy, cz, depth))
    elif node_type == NodeType.BRANCH:
        # Iterate through 8 children
        for i in range(8):
            # Calculate octant bits
            bit_x = i & 1
            bit_y = (i >> 1) & 1
            bit_z = (i >> 2) & 1
            
            # Update coordinates
            new_cx = cx * 2 + bit_x
            new_cy = cy * 2 + bit_y
            new_cz = cz * 2 + bit_z
            
            # Get child node (implementation detail: access child by index i)
            child = node.children[i]
            
            # Recurse
            collect_leaves(child, new_cx, new_cy, new_cz, depth + 1, result)
    else:
        # Unknown node type, skip or error
        pass
```

**Parameters:**
*   **Depth Limit:** Not specified in sources. [G] Typically capped by memory or scene bounds.
*   **Coordinate System:** Integer grid coordinates.

**Edge Cases:**
*   **Empty Tree:** If the root is null or empty, the result vector remains empty.
*   **Degenerate Input:** If the tree structure is corrupted (e.g., branch pointing to null), the implementation must handle null checks [G].

## Subtopics

### Leaf Node Representation
A specific variant focusing on the data layout of leaf nodes in the [zazen](https://github.com/gabrielmuller/zazen) implementation.
*   **Structure:** Leaves are represented as 4-byte RGBA blocks.
*   **Validity:** A leaf is considered valid if `rgba[3] != 0x00` [S2, unofficial].
*   **Color Modification:** The `set_color(pixel, lightness)` function multiplies the RGB channels by `lightness` but leaves the alpha channel unchanged [S2, unofficial].
*   **Equality:** Comparison uses bitwise equality of the entire 4-byte block, not element-wise checks [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of nodes in the tree, as every node is visited exactly once.
*   **Memory Complexity:** $O(L)$ where $L$ is the number of leaf/terminal nodes, for the result vector.
*   **Strengths:** Simple to implement; decouples traversal from rendering; efficient for batch processing.
*   **Limitations:** Requires storing all leaf nodes in memory; not suitable for ray-by-ray rendering where early termination is critical.
*   **When to use:** When rendering requires all visible geometry (e.g., global illumination, shadow maps) or when parallelizing leaf processing.
*   **When not to use:** For standard ray marching where early exit on empty space is desired.

## Background
Leaf Collection is a fundamental technique in hierarchical volume rendering, often used as a preprocessing step. The specific implementation details cited here are derived from open-source repositories [isomesh](https://github.com/narnia-ai-mason/isomesh) and [zazen](https://github.com/gabrielmuller/zazen).
