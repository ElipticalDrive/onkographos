# Leaf Collection


## Overview
Leaf Collection is a recursive traversal method that identifies terminal nodes (Empty, Full, or Leaf) in a hierarchical grid and records their spatial coordinates and traversal depth [S1, unofficial]. It solves the problem of mapping visited regions of a sparse voxel octree to a compact list of node positions for downstream processing [S1, unofficial]. Unlike sibling methods that optimize traversal speed or memory residency, Leaf Collection specifically targets the extraction of node indices and their hierarchical context [S1, unofficial].

## How it works
**Inputs:** Current tree node, current integer coordinates $(cx, cy, cz)$, current depth $d$.
**Outputs:** A result vector storing tuples of $(cx, cy, cz, d)$ for each terminal node encountered.
**Data Structures:**
- Result vector: Dynamic array of 4-tuples $(cx, cy, cz, d)$.
- Node type flag: Indicates if the cell is Empty, Full, Leaf, or Branch.
**Steps:**
1. Evaluate the current node's type.
2. If the node is Empty, Full, or Leaf, append $(cx, cy, cz, d)$ to the result vector.
3. If the node is a Branch, iterate through its 8 children. For each child at octant index $o \in [0, 7]$, compute the new coordinates and recurse.
**Formulas:**
The child coordinates are computed using integer arithmetic to maintain exact hierarchical alignment [G]:
$$ cx_{new} = cx \times 2 + octant\_bit $$
$$ cy_{new} = cy \times 2 + octant\_bit $$
$$ cz_{new} = cz \times 2 + octant\_bit $$
where $octant\_bit$ is the child's index (0-7) [S1, unofficial]. The depth increments by one: $d_{new} = d + 1$ [S1, unofficial].
**Pseudocode:**
```python
def collect_leaf_nodes(node, cx, cy, cz, depth, result):
    """Recursively traverse the tree and collect terminal node coordinates and depth."""
    if node.is_empty() or node.is_full() or node.is_leaf():
        result.append((cx, cy, cz, depth))
    elif node.is_branch():
        for octant_bit in range(8):
            child = node.children[octant_bit]
            new_cx = cx * 2 + octant_bit
            new_cy = cy * 2 + octant_bit
            new_cz = cz * 2 + octant_bit
            collect_leaf_nodes(child, new_cx, new_cy, new_cz, depth + 1, result)
```
**Edge Cases and Pitfalls:**
- Zero direction component or degenerate input: The method assumes a valid tree structure; if the root is null, the result vector remains empty.
- Precision: Coordinate updates use bitwise operations on integers to avoid floating-point drift across recursion levels [G].
- Boundary conditions: The algorithm does not perform ray-cell intersection tests; it purely collects hierarchical indices based on node type [S1, unofficial].

## Subtopics

### Leaf Node Representation
Leaf nodes are stored as 4-byte RGBA blocks [S2, unofficial]. A leaf node is valid if `rgba[3] != 0x00` [S2, unofficial]. The `set_color(pixel, lightness)` function multiplies the RGB channels by lightness without modifying the alpha channel [S2, unofficial]. Equality checks between leaf nodes use bitwise comparison of the entire 4-byte RGBA block rather than element-wise comparison [S2, unofficial].
