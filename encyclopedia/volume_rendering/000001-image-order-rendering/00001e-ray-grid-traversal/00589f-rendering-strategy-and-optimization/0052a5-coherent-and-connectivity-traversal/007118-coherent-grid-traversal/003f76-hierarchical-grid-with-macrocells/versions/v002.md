# Hierarchical Grid with Macrocells

Also called: Macrocell hierarchy, Two-level hierarchy

## Overview
A hierarchical grid structure that divides densely populated regions of space more finely than empty regions by imposing a coarser grid over the previous level, where each macrocell corresponds to an $M \times M \times M$ block of cells in the underlying level [S1]. It sets itself apart from the original Coherent Grid Traversal (CGT) by replacing simple Boolean empty/non-empty flags with parameter range culling, storing minimum and maximum values for multiple particle properties to enable more aggressive early-out tests [S1].

## How it works
**Inputs:** Particle dataset (position, radius, up to four additional properties); macrocell resolution $M$; grid dimensions [S1].
**Outputs:** Hierarchical grid structure (macrocells containing bounds for underlying cells) [S1].

**Data Structures:**
1.  **Macrocell:** Stores minimum and maximum values for eight parameters: position $x, y, z$, radius, and up to four additional particle properties [S1]. This replaces the Boolean empty/non-empty flag used in the original CGT algorithm [S1].
2.  **Underlying Grid:** Standard CGT grid cells, organized into blocks of size $M \times M \times M$ corresponding to macrocells [S1].

**Construction Algorithm (Sort-Middle):**
1.  Distribute construction tasks for disjoint sections of the grid statically among all system threads [S1].
2.  Each thread performs a coarse parallel bucket sort of particles by their cell location, inserting them into its local set of buckets [S1].
3.  Regions for each bucket are disjoint, avoiding write conflicts and the need for mutexes [S1].
4.  Each thread inserts its particles into the appropriate grid cells within its assigned disjoint region [S1].
5.  Aggregate the grid data to form macrocells [S1]. For each macrocell, compute the min/max of the eight parameters across all particles contained in its underlying $M \times M \times M$ block of cells [S1].

**Pseudocode:**
```python
def build_hierarchical_grid(particles, M, grid_size, cell_size, num_threads):
    # 1. Static distribution of disjoint grid sections to threads
    section_len = grid_size // num_threads
    thread_ranges = [(i * section_len, (i + 1) * section_len) for i in range(num_threads)]

    # 2. Coarse parallel bucket sort by cell location
    # Each thread handles a disjoint spatial region, avoiding write conflicts
    thread_buckets = [[] for _ in range(num_threads)]
    for p in particles:
        cell_idx = int(p.pos[0] / cell_size)  # Dominant axis assumed x
        t_id = min(cell_idx // section_len, num_threads - 1)
        thread_buckets[t_id].append(p)

    # 3. Insert particles into grid cells within disjoint regions
    # Regions are disjoint, so no synchronization or mutexes are needed
    grid = [[[] for _ in range(grid_size)] for _ in range(grid_size)]
    for t in range(num_threads):
        for p in thread_buckets[t]:
            cell_idx = int(p.pos[0] / cell_size)
            grid[cell_idx].append(p)

    # 4. Aggregate grid data to form macrocells
    macrocells = []
    for i in range(0, grid_size, M):
        for j in range(0, grid_size, M):
            for k in range(0, grid_size, M):
                mc = {'min': [float('inf')] * 8, 'max': [float('-inf')] * 8}
                # Iterate over underlying M x M x M block of cells
                for di in range(M):
                    for dj in range(M):
                        for dk in range(M):
                            ci, cj, ck = i + di, j + dj, k + dk
                            if ci < grid_size and cj < grid_size and ck < grid_size:
                                for p in grid[ci][cj][ck]:
                                    # Extract 8 parameters: x, y, z, radius, 4 properties
                                    vals = [p.pos[0], p.pos[1], p.pos[2], p.radius] + p.props[:4]
                                    for idx in range(8):
                                        if vals[idx] < mc['min'][idx]: mc['min'][idx] = vals[idx]
                                        if vals[idx] > mc['max'][idx]: mc['max'][idx] = vals[idx]
                macrocells.append(mc)
    return macrocells, grid
```

**Parameters:**
*   **Macrocell resolution ($M$):** The size of the macrocell block in cells. Typical value: $6 \times 6 \times 6$ [S1].
*   **Lambda ($\lambda$):** A parameter affecting performance in modified algorithms. Value $\lambda = 1$ provides best performance for tested datasets [S1].

**Edge Cases and Pitfalls:**
*   **Write Conflicts:** Avoided by using disjoint regions for each thread during construction [S1].
*   **Parameter Tuning:** Performance varies widely with $\lambda$ for large particle counts; $\lambda=1$ is recommended [S1].
*   **Frustum Overlap:** Ray packet size impacts performance; larger packets overlap more cells, increasing intersection cost per step [S1].

## Subtopics

### [Loosely Nested Grids](12774-loosely-nested-grids.md)
A hierarchical grid building method proposed by Cazals et al. designed to handle very complex scenes by organizing primitives into a structure that allows for efficient traversal of empty spaces. Unlike top-down adaptive subdivision methods, LNG employs a bottom-up construction approach via filtering and clustering steps. This method builds upon the concept of hierarchical grids with macrocells by structuring the hierarchy through local grid clusters rather than a single global recursive subdivision. Choose it when scene complexity requires localized clustering instead of uniform global subdivision.

## Operating characteristics
*   **Time Complexity:** Construction is $O(N)$ with parallel bucket sort, where $N$ is the number of particles, due to disjoint thread regions [S1]. Traversal benefits from parameter range culling, potentially reducing intersection tests compared to Boolean flags [S1].
*   **Memory Complexity:** Higher than original CGT due to storing 8 min/max values per macrocell instead of a single Boolean flag [S1].
*   **Performance:** $\lambda = 1$ and $M = 6 \times 6 \times 6$ yield reasonable performance for tested datasets [S1]. Performance is sensitive to $\lambda$ for very large particle counts [S1].
*   **Strengths:** Efficient traversal via parameter range culling; parallel construction without synchronization [S1].
*   **Limitations:** Increased memory usage per macrocell due to storing eight min/max values instead of a single Boolean flag [S1]. Performance sensitivity to $\lambda$ for extremely large particle counts [S1].

## Background
Originated from the work of Parker et al. [17] and adapted for particle-based simulation data visualization by Ize et al. [9] and others [S1]. It builds on the original CGT algorithm but modifies the macrocell data structure to support more sophisticated culling [S1].
