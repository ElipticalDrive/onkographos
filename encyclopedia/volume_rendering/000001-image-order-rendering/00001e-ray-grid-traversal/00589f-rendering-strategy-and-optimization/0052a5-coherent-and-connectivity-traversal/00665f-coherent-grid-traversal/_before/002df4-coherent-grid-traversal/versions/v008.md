# Coherent Grid Traversal

Also called: CGT (Coherent Grid Traversal), CGT algorithm, Ize et al. traversal, Slice by slice algorithm

## Overview
Coherent Grid Traversal (CGT) is a ray tracing acceleration technique for uniform grids that traverses bundles (frustums) of coherent rays slice-by-slice along a dominant axis, abandoning cell-by-cell traversal to avoid expensive packet splitting and merging operations [S2, S4, S5]. It sets itself apart from its sibling [Hero-like 4-Connectivity (H4T)](3436-hero-like-4-connectivity-h4t.md) and standard 3DDDA by processing entire slices of cells as a coherent whole, allowing the grid to be rebuilt from scratch every frame for dynamic scenes while maintaining performance competitive with kd-trees [S3, unofficial][S4, S5].

## How it works
**Inputs and Outputs:**
*   **Input:** A packet of $N \times N$ coherent rays (spanning an angle $< \pi/2$) defined by origins $\mathbf{o}$ and directions $\mathbf{d}$ [S2, S4, S5]; a uniform grid of dimensions $N_x \times N_y \times N_z$ [S4, S5]; the grid's bounding box [S4, S5].
*   **Output:** A sequence of grid cells (or bricks) overlapped by the ray packet frustum, in traversal order along the major axis [S4, S5].

**Data Structures:**
*   **Canonical Grid Space:** Rays are transformed such that the grid maps to $[0, N_x) \times [0, N_y) \times [0, N_z)$ [S4, S5]. Cell coordinates are computed by truncating floating-point positions to integers [S4, S5].
*   **Frustum Representation:** Defined by four bounding planes in the minor axes ($\tilde{U}, \tilde{V}$) and near/far planes in the major axis ($\tilde{K}$) [S4, S5]. For primary rays, these are derived from the four corner rays of the packet [S4, S5].
*   **Overlap Box $B(i)$:** A 2D axis-aligned box in the $\tilde{U}, \tilde{V}$ plane representing the frustum's intersection with slice $i$ along $\tilde{K}$ [S4, S5]. Stored as four floats: $[u_{min}, v_{min}, u_{max}, v_{max}]$ [S4, S5].
*   **Bricked Volume (Optional):** For volume rendering, the volume is stored as "bricks" referenced by 3 maps (one per principal axis). Empty bricks are not stored for compression [S1, S9, unofficial].

**Parameters:**
*   **Packet Size:** Typically $4 \times 4$ or $8 \times 8$ rays [S6, S8].
*   **Major Axis $\tilde{K}$:** Determined by the dominant component ($\pm X, \pm Y, \pm Z$) of the first ray's direction [S4, S5]. All rays must have the same sign along $\tilde{K}$ to allow front-to-back traversal [S4, S5].
*   **Minor Axes $\tilde{U}, \tilde{V}$:** The remaining two dimensions [S4, S5].

**Steps:**
1.  **Transform:** Convert all rays in the packet to canonical grid space [S4, S5].
2.  **Select Major Axis:** Identify $\tilde{K}$ as the axis with the maximum absolute direction component of the first ray [S4, S5]. Verify all rays have the same sign along $\tilde{K}$ [S4, S5].
3.  **Compute Frustum Planes:** Calculate the slopes and offsets of the four bounding planes in $\tilde{U}$ and $\tilde{V}$ based on the extremal rays (or all rays for secondary packets) [S4, S5].
4.  **Clip to Grid:** Intersect the frustum with the grid's bounding box to determine the first slice index $k_{min}$ and last slice index $k_{max}$ along $\tilde{K}$ [S4, S5]. If the interval is empty, terminate [S4, S5].
5.  **Initialize Overlap Box:** Compute the initial overlap box $B(0)$ for slice $k_{min}$ by finding the min/max $\tilde{U}$ and $\tilde{V}$ coordinates of the frustum's entry and exit points at that slice [S4, S5].
6.  **Traverse Slices:** For each slice $k$ from $k_{min}$ to $k_{max}$:
    a.  **Convert to Cell IDs:** Truncate the min/max coordinates of $B(k)$ to integers to get the cell range $[i_0..i_1] \times [j_0..j_1]$ in the $\tilde{U}, \tilde{V}$ plane [S4, S5].
    b.  **Intersect:** Intersect all rays in the packet with all primitives (triangles or volume data) in the cells defined by the range [S4, S5].
    c.  **Increment Overlap Box:** Compute $B(k+1) = B(k) + \Delta B$, where $\Delta B = (du_{min}, du_{max}, dv_{min}, dv_{max})$ are the slopes of the bounding planes in grid space [S4, S5]. This requires four floating-point additions [S4, S5].
7.  **Early Termination:** If all rays have intersected their targets, stop traversal [S4, S5].

**Pseudocode:**
```python
def coherent_grid_traversal(rays, grid_dims, grid_bounds):
    # 1. Transform rays to canonical grid space (assumed pre-computed)
    # 2. Select major axis K
    first_ray = rays[0]
    abs_d = [abs(first_ray.d[i]) for i in range(3)]
    k_axis = abs_d.index(max(abs_d))
    u_axis = (k_axis + 1) % 3
    v_axis = (k_axis + 2) % 3
    
    # Check coherence: all rays must have same sign along K
    k_sign = 1 if first_ray.d[k_axis] > 0 else -1
    for ray in rays:
        if ray.d[k_axis] * k_sign <= 0:
            raise ValueError("Rays are not coherent along major axis K")
            
    # 3. Compute Frustum Planes (slopes and offsets in grid space)
    slopes = []
    offsets = []
    for ray in rays:
        if ray.d[k_axis] == 0:
            continue
        du = ray.d[u_axis] / ray.d[k_axis]
        dv = ray.d[v_axis] / ray.d[k_axis]
        slopes.append((du, dv))
        # U(K) = offset_u + K * du => offset_u = U(0) - 0 * du
        # Using ray origin projected to K=0 plane:
        offset_u = ray.o[u_axis] - ray.o[k_axis] * du
        offset_v = ray.o[v_axis] - ray.o[k_axis] * dv
        offsets.append((offset_u, offset_v))
        
    du_min = min(s[0] for s in slopes)
    du_max = max(s[0] for s in slopes)
    dv_min = min(s[1] for s in slopes)
    dv_max = max(s[1] for s in slopes)
    
    offset_u_min = min(o[0] for o in offsets)
    offset_u_max = max(o[0] for o in offsets)
    offset_v_min = min(o[1] for o in offsets)
    offset_v_max = max(o[1] for o in offsets)
    
    # 4. Clip to Grid to find k_min and k_max
    # Frustum K-extent is clipped to [0, grid_dims[k_axis])
    # Assuming frustum near/far in canonical space are known or derived from ray origins
    frustum_k_min = max(0.0, min(ray.o[k_axis] for ray in rays))
    frustum_k_max = max(ray.o[k_axis] + ray.d[k_axis] * 1000.0 for ray in rays) # Simplified far plane
    k_min = max(0, int(frustum_k_min))
    k_max = min(grid_dims[k_axis] - 1, int(frustum_k_max))
    if k_min > k_max:
        return
        
    # 5. Initialize Overlap Box B(0) for slice k_min
    b_u_min = offset_u_min + k_min * du_min
    b_u_max = offset_u_max + k_min * du_max
    b_v_min = offset_v_min + k_min * dv_min
    b_v_max = offset_v_max + k_min * dv_max
    
    delta_b = (du_min, du_max, dv_min, dv_max)
    
    # 6. Traverse Slices
    for k in range(k_min, k_max + 1):
        # Convert to cell IDs via truncation
        i0 = int(b_u_min)
        i1 = int(b_u_max)
        j0 = int(b_v_min)
        j1 = int(b_v_max)
        
        # Clamp to grid bounds
        i0 = max(0, min(i0, grid_dims[u_axis] - 1))
        i1 = max(0, min(i1, grid_dims[u_axis] - 1))
        j0 = max(0, min(j0, grid_dims[v_axis] - 1))
        j1 = max(0, min(j1, grid_dims[v_axis] - 1))
        
        # Yield cells in this slice
        for i in range(i0, i1 + 1):
            for j in range(j0, j1 + 1):
                yield (i, j, k)
                
        # Incremental update for next slice: B(k+1) = B(k) + ΔB
        b_u_min += delta_b[0]
        b_u_max += delta_b[1]
        b_v_min += delta_b[2]
        b_v_max += delta_b[3]
```

**Edge Cases and Pitfalls:**
*   **Ray Divergence:** If rays span an angle $> \pi/2$, they may have different signs along the traversal axis, violating the front-to-back assumption [S4]. Mitigation: Ensure packet coherence or split packets only when hit points are too distant (silhouettes), as general splitting deteriorates to single-ray traversal [S4, S5].
*   **Silhouette Hit Points:** If primary rays hit object silhouettes, hit points can be distant, creating a wide frustum where the method breaks down [S5]. Mitigation: Split the packet into subpackets if min/max hit distances are too large [S5].
*   **Roll Angle:** When the "roll" angle of the bundles to the volume angle is close to $\pi/4$, block fetches can double [S1, S9, unofficial].
*   **Redundant Intersections:** Grids do not conform tightly to geometry, and filling cells with bounding boxes exacerbates redundant triangle intersections [S4]. Mitigation: Use SIMD frustum culling and mailboxing [S4, S5].
*   **Straddling Triangles:** Large triangles or small triangles straddling boundaries may appear in multiple cells [S4]. Mitigation: Mailboxing [S4, S5].

## Subtopics

### [Sphere-Center Method](5200-sphere-center-method.md)
An optimization for glyph-based particle visualization that eliminates data duplication by storing each particle in exactly one grid cell, traversing an enlarged frustum to ensure containment. Choose it when visualizing large particle datasets to avoid redundant intersection tests and storage overhead.

### [Macrocell Hierarchical CGT](5464-macrocell-hierarchical-cgt.md)
Extends CGT to large volumes using a recursive hierarchy of macrocells ($2^3$ children) to amortize traversal costs, using an iterative stack. Choose it when flat CGT performance degrades on massive datasets, as it maintains slice-based traversal while managing spatial hierarchy.

### [Slice Parallelisation](6292-slice-parallelisation.md)
A parallelization scheme assigning processing elements to slices of the volume, requiring explicit data structures to map bundles to slices. Choose it when reducing redundant block fetches from neighboring bundles is prioritized over direct bundle processing.

### [Bundle Parallelisation](6293-bundle-parallelisation.md)
A parallelization scheme where bundles of rays are processed in parallel, distributing work across processing elements. Choose it for straightforward implementation on multi-core systems, accepting potential redundant block fetches from neighboring bundles.

### [SIMD Sphere/Frustum Culling](10012-simd-sphere-frustum-culling.md)
A culling technique for spheres that checks if the sphere center is contained within an enlarged bounding frustum, avoiding unnecessary intersection tests. Choose it for particle-based visualization where planar shaft culling is inapplicable.

### [Hierarchical Grid with Macrocells](10019-hierarchical-grid-with-macrocells.md)
A hierarchical grid structure that divides densely populated regions more finely, using parameter range culling for early-out tests. Choose it when aggressive early-out tests on particle properties are needed to replace simple empty/non-empty flags.

## Operating characteristics
*   **Time Complexity:** The traversal cost per step is independent of the number of rays in the packet, encouraging larger packets [S4]. The incremental update of the overlap box requires only four floating-point additions (one SIMD instruction) and one float-to-int conversion (one SIMD instruction) per slice [S4, S6].
*   **Memory Complexity:** The grid is uniform and simple to build, making it suitable for per-frame rebuilds in dynamic scenes [S3, unofficial][S4, S5]. For volume rendering, a "bricked" volume structure reduces memory overhead by not storing empty bricks [S1, S9, unofficial].
*   **Measured Performance:** On a dual 3.2 GHz Xeon, rendering a 174K triangle animated scene at 1024x1024 achieves 1.4 fps with shading/textures/shadows, and 3.4 fps excluding them [S4, S5]. CGT outperforms single-ray 3DDDA by a factor of 6.75 to 20.9x [S5]. It performs competitively with kd-trees (e.g., 1.0M vs 0.82M ray-triangle intersections in the 'toys' scene) [S4, S5].
*   **Scaling:** Sublinear scaling in screen resolution is observed because higher resolutions enable larger packets, amortizing traversal costs [S2, S6, S8].
*   **Strengths:** Simple grid construction allows for full per-frame rebuilds, ideal for dynamic/animated scenes [S3, unofficial][S4, S5]. Avoids expensive packet splitting and merging [S2, S5]. Cache-friendly for volume rendering [S1, S9, unofficial].
*   **Limitations:** Uniform grids are ill-suited for highly complex scenes with high variation in geometry size and density (e.g., Boeing 777) [S4, S5]. Performance degrades if the roll angle is close to $\pi/4$ [S1, S9, unofficial].

## Background
Coherent Grid Traversal was introduced in 2006 by Wald, Ize, Kensler, Knoll, and Parker in "Ray Tracing Animated Scenes using Coherent Grid Traversal" published in ACM Transactions on Graphics (SIGGRAPH) [S4, S5]. It was developed to address the limitations of packet-based kd-tree traversal for dynamic scenes, where rebuilding the kd-tree is expensive [S4, S5]. The algorithm abandons cell-by-cell traversal (3DDDA) in favor of slice-by-slice traversal to maintain coherence within ray packets [S2, S4, S5]. It has been used in systems for interactive visualization of large particle datasets [S8] and volume rendering [S1, S9, unofficial].
