# Hero-like 4-Connectivity (H4T)
## Overview
Hero-like 4-Connectivity (H4T) is a ray traversal algorithm for uniform grids that guarantees strict 4-connectivity by resolving boundary crossing ambiguities through a stable sort of candidate cell entries [S1, unofficial]. It differs from standard DDA and its sibling [Coherent Grid Traversal](2987-coherent-grid-traversal.md) by explicitly testing a 2x2 cell neighborhood and using axis-priority sorting to prevent diagonal jumps, ensuring that rays crossing grid lines do so one axis at a time [S1, unofficial].
## How it works
H4T determines the sequence of voxels visited by a ray by identifying the entry point into a 2x2 block of cells and then advancing through them while maintaining connectivity [S1, unofficial]. The method relies on a stable sorting mechanism to break ties between axis crossings [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, grid dimensions, voxel size $v$ [S1, unofficial].
*   **Output:** A sequence of voxel indices $(i, j, k)$ visited by the ray [S1, unofficial].

**Data Structures:**
*   **Candidate List:** A list of tuples containing $(t, \text{axis\_id})$, where $t$ is the distance to the next boundary and $\text{axis\_id}$ identifies the axis ($0$ for $x$, $1$ for $y$, $2$ for $z$) [S1, unofficial].

**Steps:**
1.  **2x2 Cell Test:** Identify the candidate cells the ray passes through in the current 2x2 block by computing the distance $t$ to the next boundary along each active axis [S1, unofficial].
2.  **Associate Axis IDs:** For each candidate boundary crossing distance $t$, associate it with an axis identifier ($0$ for $x$, $1$ for $y$) [S1, unofficial].
3.  **Stable Sort:** Sort the candidate list using a stable sorting algorithm. The sort key is primarily the axis identifier, and secondarily the $t$-value [S1, unofficial]. This ensures that if $t$-values for the $x$ and $y$ axes are equal, the $x$-axis ($0$) is processed before the $y$-axis ($1$), preserving 4-connectivity [S1, unofficial].
4.  **Advance:** Select the first entry in the sorted list as the next cell. Update the ray's position and repeat the process for the next block. The grid position must be floored before reading the grid data, as the method may produce fractional position values during intermediate calculations [S1, unofficial].

**Pseudocode:**
The source notes that the full C implementation is too long to include and describes the logic conceptually [S1, unofficial]. The following pseudocode implements the described stable sort logic for the 2x2 test resolution, adapted to 3D traversal [G].

```python
def h4t_traversal(ray_origin, ray_direction, voxel_size, grid_dims):
    # Initialize current voxel index (floor division handles negative coordinates correctly)
    current_voxel = [int(ray_origin[i] // voxel_size) for i in range(3)]
    
    # Step direction per axis
    step = [1 if ray_direction[i] > 0 else (-1 if ray_direction[i] < 0 else 0) for i in range(3)]
    
    # Distance to next boundary per axis
    next_boundary = [(current_voxel[i] + (1 if ray_direction[i] > 0 else 0)) * voxel_size for i in range(3)]
    t_max = [(next_boundary[i] - ray_origin[i]) / ray_direction[i] if ray_direction[i] != 0 else float('inf') for i in range(3)]
    
    # Distance delta per axis
    t_delta = [voxel_size / abs(ray_direction[i]) if ray_direction[i] != 0 else float('inf') for i in range(3)]
    
    t_entry = 0.0
    
    while 0 <= current_voxel[0] < grid_dims[0] and \
          0 <= current_voxel[1] < grid_dims[1] and \
          0 <= current_voxel[2] < grid_dims[2]:
        
        # H4T-specific step: pair t_max with axis_id and sort stably
        # Primary key: axis_id (0=x, 1=y, 2=z), Secondary key: t_max
        candidates = [(t_max[0], 0), (t_max[1], 1), (t_max[2], 2)]
        candidates.sort(key=lambda x: (x[1], x[0]))  # Python's sort is stable
        
        # Extract the axis with the smallest t_max (ties broken by axis_id)
        min_idx = candidates[0][1]
        t_exit = candidates[0][0]
        
        yield current_voxel, t_entry, t_exit
        
        current_voxel[min_idx] += step[min_idx]
        t_max[min_idx] += t_delta[min_idx]
        t_entry = t_exit
```

**Edge Cases and Pitfalls:**
*   **Ties:** The critical pitfall is the handling of equal $t$-values for different axes. Without stable sorting by axis ID, the traversal may jump diagonally, violating 4-connectivity [S1, unofficial].
*   **Fractional Positions:** The method may result in fractional grid positions during calculation. The grid must be accessed using floored coordinates [S1, unofficial].
*   **Code Length:** The source notes that the full implementation is complex and lengthy, suggesting careful handling of the candidate list management [S1, unofficial].
## Subtopics

### [Hierarchical Planes 4-Connectivity (HP4T)](3444-hierarchical-planes-4-connectivity-hp4t.md)
A ray traversal algorithm for hierarchical grids (Octrees/SVO) that ensures strict 4-connectivity by preventing diagonal jumps. It distinguishes itself from [Hierarchical Planes 8-Connectivity (HP8T)](5220-hierarchical-planes-8-connectivity-hp8t.md) by applying clamping logic to the non-hit axis to avoid surface normal ambiguities. Choose HP4T when traversing sparse hierarchical structures where strict 4-connectivity is required to maintain normal consistency.

## Operating characteristics
*   **Correctness:** H4T achieved 100% correctness for both position and normal in randomized testing (100,000,000 cases) and specific test cases (2,883,496 cases), outperforming HP4T and HP8T which had error rates of 99.99% and 97.66% respectively [S1, unofficial].
*   **Complexity:** Not given in the sources.
*   **Strengths:** Highest accuracy among tested methods; guarantees 4-connectivity [S1, unofficial].
*   **Limitations:** Implementation complexity is high; the source code was not published due to length [S1, unofficial].
## Background
H4T was developed as part of a project investigating ray traversal algorithms for hierarchical grids [S1, unofficial]. It was discovered late in the project and is described as working "very differently" from previous methods like HP4T and HP8T [S1, unofficial]. The method was tested using a C program compiled with GCC [S1, unofficial].
