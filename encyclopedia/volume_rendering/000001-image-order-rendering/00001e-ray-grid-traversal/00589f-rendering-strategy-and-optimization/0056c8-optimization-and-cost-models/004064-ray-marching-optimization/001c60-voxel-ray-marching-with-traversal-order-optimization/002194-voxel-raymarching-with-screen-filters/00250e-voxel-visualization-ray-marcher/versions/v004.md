# Voxel Visualization Ray Marcher

Also called: 3D Texture Visualizer, Simple Fragment Shader Path Tracer

## Overview
A fragment shader technique that ray marches through a 3D texture to visualize voxelized data by accumulating color along a ray until opacity saturates or the ray exits the volume [S1, unofficial]. It differs from its parent, [Voxel Raymarching with Screen Filters](2555-voxel-raymarching-with-screen-filters.md), by using a fixed-step march with pre-computed ray origins rather than screen-space filtering [S1, unofficial]. Unlike [Voxel Visualization Ray Casting](5081-voxel-visualization-ray-casting.md), which relies on pre-computed intersection textures for ray initialization, this method computes the ray direction dynamically from front and back intersection points [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**: `textureCoordinateFrag` (`in vec2`, fragment screen-space coordinates), `textureFront` (`sampler2D`, stores ray origin coordinates), `textureBack` (`sampler2D`, stores ray direction endpoints), `texture3D` (`sampler3D`, contains the voxelized volume data), `cameraPosition` (`vec3`, world-space camera position), and `state` (`int`, mipmap level, default 0) [S1, unofficial].
*   **Outputs**: `color` (`out vec4`, final accumulated color) [S1, unofficial].

**Data Structures**
*   **Uniforms**: `STEP_LENGTH` (`float`, fixed distance advanced per step, default 0.005), `INV_STEP_LENGTH` (`float`, computed as `1.0 / STEP_LENGTH`) [S1, unofficial].
*   **Textures**: `textureFront` and `textureBack` are 2D textures mapping screen fragments to 3D space points, and `texture3D` is a 3D texture containing voxel colors and alpha [S1, unofficial].

**Parameters**
*   `STEP_LENGTH`: 0.005 [S1, unofficial].
*   `INV_STEP_LENGTH`: 200.0 (derived) [S1, unofficial].
*   `state`: 0 [S1, unofficial].
*   `cameraPosition`: Provided by application [S1, unofficial].

**Algorithm**
1.  **Initialize Ray Origin**: Check if `cameraPosition` is inside the unit cube with a margin of 0.2f [S1, unofficial]. If inside, set `origin = cameraPosition` [S1, unofficial]. Otherwise, sample `origin` from `textureFront` using `textureCoordinateFrag` [S1, unofficial]. *Pitfall*: The origin must avoid invalid positions; using the front buffer ensures valid ray starting points when the camera is outside the volume [S1, unofficial].
2.  **Calculate Total Steps**: Sample `backPoint` from `textureBack` using `textureCoordinateFrag` [S1, unofficial]. Compute `direction = backPoint - origin` [G]. Normalize `direction` to ensure `STEP_LENGTH` represents a fixed world distance [G]. Compute `rayLength = length(direction)` [G]. Compute `numberOfSteps = uint(INV_STEP_LENGTH * rayLength)` [S1, unofficial].
3.  **Initialize Accumulator**: Set `color = vec4(0.0)` [S1, unofficial].
4.  **Ray Marching Loop**: Iterate `step` from 0 to `numberOfSteps` inclusive [S1, unofficial]. *Early Exit*: If `color.a >= 0.99`, break the loop [S1, unofficial]. *Compute Position*: `currentPoint = origin + STEP_LENGTH * float(step) * direction` [S1, unofficial]. *Sample Volume*: Scale and bias `currentPoint` to the [0, 1] range [S1, unofficial]. Sample `texture3D` at the scaled point using `state` as the mipmap level [S1, unofficial]. *Accumulate Color*: Apply alpha compositing $c_{out} = c_{in} + (1.0 - c_{in}.a) \times s$, where $c_{in}$ is the accumulated `color`, $c_{in}.a$ is its alpha, and $s$ is the sampled voxel color [S1, unofficial]. Update `color = color + (1.0 - color.a) * currentSample` [S1, unofficial].
5.  **Gamma Correction**: Apply sRGB gamma correction to the RGB channels by raising to the power of $1/2.2$ [S1, unofficial].

**Pseudocode**
```python
import math

def vec3(x, y, z): return (x, y, z)
def vec4(r, g, b, a): return (r, g, b, a)
def length(v): return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
def normalize(v):
    l = length(v)
    return (v[0]/l, v[1]/l, v[2]/l) if l > 0 else (0.0, 0.0, 0.0)
def sample_2d(tex, uv): return vec4(0.0)
def sample_3d(tex, uv, mip): return vec4(0.0)
def is_inside_unit_cube(pos, margin=0.2): return all(-margin <= c <= 1.0+margin for c in pos)

def voxel_ray_marcher(textureCoordinateFrag, textureFront, textureBack, texture3D, cameraPosition, state=0):
    STEP_LENGTH = 0.005
    INV_STEP_LENGTH = 1.0 / STEP_LENGTH

    # Step 1: Initialize Ray Origin
    if is_inside_unit_cube(cameraPosition, margin=0.2):
        origin = cameraPosition
    else:
        origin = sample_2d(textureFront, textureCoordinateFrag)[:3]

    # Step 2: Calculate Total Steps
    backPoint = sample_2d(textureBack, textureCoordinateFrag)[:3]
    raw_direction = (backPoint[0]-origin[0], backPoint[1]-origin[1], backPoint[2]-origin[2])
    direction = normalize(raw_direction)
    rayLength = length(raw_direction)
    numberOfSteps = int(INV_STEP_LENGTH * rayLength)

    # Step 3: Initialize Accumulator
    color = vec4(0.0, 0.0, 0.0, 0.0)

    # Step 4: Ray Marching Loop
    for step in range(numberOfSteps + 1):
        if color[3] >= 0.99:
            break
        currentPoint = (origin[0] + STEP_LENGTH * step * direction[0],
                        origin[1] + STEP_LENGTH * step * direction[1],
                        origin[2] + STEP_LENGTH * step * direction[2])
        # Scale and bias to [0, 1]
        currentPoint = (max(0.0, min(1.0, currentPoint[0])),
                        max(0.0, min(1.0, currentPoint[1])),
                        max(0.0, min(1.0, currentPoint[2])))
        currentSample = sample_3d(texture3D, currentPoint, state)
        color = (color[0] + (1.0 - color[3]) * currentSample[0],
                 color[1] + (1.0 - color[3]) * currentSample[1],
                 color[2] + (1.0 - color[3]) * currentSample[2],
                 color[3] + (1.0 - color[3]) * currentSample[3])

    # Step 5: Gamma Correction
    color = (pow(color[0], 1.0/2.2), pow(color[1], 1.0/2.2), pow(color[2], 1.0/2.2), color[3])
    return color
```

## Subtopics

### [Voxel Visualization Ray Casting](5081-voxel-visualization-ray-casting.md)
A fragment shader technique that visualizes a 3D voxel grid by casting rays from the camera through a unit cube, using pre-computed front and back intersection textures to determine the ray origin and direction. Unlike traditional mesh rendering which requires draw calls per object, this method holds geometric complexity in 3D voxel textures and renders the entire structure in a single draw call using only a few triangles. It differs from its parent, Voxel Visualization Ray Marcher, by explicitly utilizing pre-computed intersection textures for ray initialization rather than computing intersections or marching from a generic camera position.

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of steps per ray [S1, unofficial].
*   **Memory Complexity**: $O(1)$ per fragment for the shader state, plus storage for the 3D texture and front/back 2D textures [S1, unofficial].
*   **Performance**: Performance depends on `STEP_LENGTH` and ray length [S1, unofficial].
*   **Strengths**: Simple implementation, single draw call, works with any 3D texture [S1, unofficial].
*   **Limitations**: Fixed step size may lead to aliasing or missed details if `STEP_LENGTH` is too large [S1, unofficial].
*   **When to use**: Real-time visualization of voxel data where simplicity is preferred over optimization [S1, unofficial].
*   **When not to use**: Large volumes with sparse data [S1, unofficial].

## Background
Originating from unofficial implementations, this method provides a straightforward approach to rendering voxel data using fragment shaders [S1, unofficial]. It builds on the concept of ray marching through 3D textures, a common technique in volume rendering [S1, unofficial].
