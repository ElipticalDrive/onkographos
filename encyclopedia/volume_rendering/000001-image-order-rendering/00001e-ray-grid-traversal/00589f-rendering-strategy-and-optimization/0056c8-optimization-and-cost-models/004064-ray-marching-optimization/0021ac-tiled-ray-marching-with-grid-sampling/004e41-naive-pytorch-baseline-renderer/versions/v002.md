# Naive PyTorch Baseline Renderer
Also called: Sequential CPU loop, Standard tensor operations renderer

## Overview
The Naive PyTorch Baseline Renderer is a reference implementation for differentiable rendering that processes all primitives for every pixel sequentially using standard PyTorch tensor operations [S1, unofficial]. It serves as a performance baseline to demonstrate the efficiency gains of optimized CUDA implementations, which utilize tile-based culling, per-pixel parallelism, and FP16 optimization [S1, unofficial]. Unlike its siblings, it lacks spatial optimization, tile-based binning, or specialized kernels, resulting in significant memory and computational overhead [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes a set of $N$ primitives as input, where each primitive $i$ is defined by parameters $\{(x_i, y_i, s_i, \theta_i, \nu_i, c_i)\}_{i=1}^N$ [S1, unofficial]. Here, $(x_i, y_i)$ is the center, $s_i$ is the scale, $\theta_i$ is the rotation angle, $\nu_i$ is a density parameter, and $c_i$ is the base color [S1, unofficial]. A mask texture $M_i$ is associated with each primitive [S1, unofficial]. The method outputs a rendered image tensor $I$ of size $H_{canvas} \times W_{canvas}$ [S1, unofficial].

**Data Structures:**
The implementation uses two 2D tensors $X$ and $Y$ of shape $(H_{canvas}, W_{canvas})$ to represent the normalized coordinates of each pixel [S1, unofficial]. It maintains two accumulator tensors $I$ (image) and $T$ (transparency), both of shape $(H_{canvas}, W_{canvas})$, initialized to zeros and ones respectively [S1, unofficial]. During execution, full-canvas tensors are allocated for $\Delta x, \Delta y, u, v,$ and $mask$ for each primitive [S1, unofficial].

**Algorithm Steps:**
1. Generate coordinate grids $X, Y$ over the canvas dimensions $H_{canvas}, W_{canvas}$ using `torch.meshgrid` [S1, unofficial].
2. Initialize the output image $I$ to zeros and the transparency mask $T$ to ones [S1, unofficial].
3. Iterate through each primitive $i$ from $0$ to $N-1$ [S1, unofficial].
4. Compute displacement vectors: $\Delta x = X - x_i$ and $\Delta y = Y - y_i$ [S1, unofficial].
5. Transform coordinates to the primitive's local space by rotating and scaling $\Delta x, \Delta y$ by angle $\theta_i$ and scale $s_i$ to obtain local coordinates $u, v$ [S1, unofficial].
6. Sample the primitive's mask texture $M_i$ at $(u, v)$ using `torch.grid_sample` to get the mask value [S1, unofficial].
7. Compute opacity $\alpha_i$ and color $c_i$ using the defined formulas [S1, unofficial].
8. Update the image and transparency using alpha compositing: $I \leftarrow I + T \cdot \alpha_i \cdot c_i$ and $T \leftarrow T \cdot (1 - \alpha_i)$ [S1, unofficial].
9. Return the final image $I$ [S1, unofficial].

**Formulas:**
$$ \alpha_i = \alpha_{max} \cdot \sigma(\nu_i) \cdot \text{mask} $$
$$ c_i = \sigma(c_i) $$
where $\sigma$ denotes the sigmoid function, $\alpha_{max}$ is a maximum opacity constant, and $\text{mask}$ is the sampled texture value [S1, unofficial].

**Parameters:**
The parameter $\alpha_{max}$ controls the maximum opacity scaling [S1, unofficial]. Typical values for $\alpha_{max}$ are not given in the sources.

**Edge Cases and Pitfalls:**
The method allocates full-canvas tensors for every primitive in the loop, which causes massive memory allocation [S1, unofficial]. For 1000 primitives on a $512 \times 512$ canvas, this results in approximately 5 GB of memory allocation at FP32 precision due to intermediate tensors $\Delta x, \Delta y, u, v,$ and $mask$ [S1, unofficial]. Every primitive is evaluated at all $H \times W$ pixels, even if the primitive contributes nothing to the final image, yielding 262 million wasted evaluations for the 1000-primitive example [S1, unofficial]. The Python `for` loop prevents primitive-level parallelism and forces repeated kernel launches, significantly slowing down execution compared to GPU-optimized approaches [S1, unofficial].

**Pseudocode:**
```python
import torch
import torch.nn.functional as F

def naive_pytorch_renderer(primitives, H_canvas, W_canvas, alpha_max=1.0):
    # 1. Create meshgrid X, Y over canvas dimensions
    y, x = torch.meshgrid(
        torch.linspace(-1, 1, H_canvas, device=primitives[0]['x'].device),
        torch.linspace(-1, 1, W_canvas, device=primitives[0]['x'].device),
        indexing='ij'
    )
    # 2. Initialize output image I to zeros and transparency mask T to ones
    I = torch.zeros((H_canvas, W_canvas), device=primitives[0]['x'].device)
    T = torch.ones((H_canvas, W_canvas), device=primitives[0]['x'].device)
    N = len(primitives)
    # 3. Loop i from 0 to N-1
    for i in range(N):
        prim = primitives[i]
        xi, yi = prim['x'], prim['y']
        si, theta_i = prim['s'], prim['theta']
        nu_i, ci = prim['nu'], prim['c']
        Mi = prim['mask_texture']
        # 4. Compute deltas ∆x = X - xi, ∆y = Y - yi
        dx = x - xi
        dy = y - yi
        # 5. Rotate/scale deltas by primitive angle θi and scale si to get u, v
        cos_theta, sin_theta = torch.cos(theta_i), torch.sin(theta_i)
        u = (dx * cos_theta + dy * sin_theta) / si
        v = (-dx * sin_theta + dy * cos_theta) / si
        # 6. Sample mask from primitive's mask texture Mi at (u, v) using torch.grid_sample
        grid = torch.stack([u, v], dim=-1).unsqueeze(0)
        mask = F.grid_sample(Mi, grid, mode='bilinear', padding_mode='zeros', align_corners=True).squeeze()
        # 7. Compute opacity αi = αmax · σ(νi) · mask and color ci = σ(ci)
        alpha_i = alpha_max * torch.sigmoid(nu_i) * mask
        ci = torch.sigmoid(ci)
        # 8. Update image I = I + T · αi · ci and transparency T = T · (1 - αi)
        I = I + T * alpha_i * ci
        T = T * (1 - alpha_i)
    # 9. Return I
    return I
```

## Operating characteristics
The time complexity is $O(N \times H \times W)$ because every primitive is evaluated at all $H \times W$ pixels [S1, unofficial]. The memory complexity is $O(N \times H \times W)$ per iteration because each primitive creates full-canvas tensors for intermediate calculations [S1, unofficial]. The naive version is 30-50x slower than the optimized CUDA implementation [S1, unofficial]. Its strengths include a simple implementation using standard PyTorch operations and its role as a clear baseline for comparison [S1, unofficial]. Its limitations are massive memory allocation, sequential processing, lack of spatial culling, and generic interpolation operations [S1, unofficial]. It should only be used for small-scale testing or as a reference for correctness against optimized renderers [S1, unofficial]. It should not be used for large scenes, high-resolution images, or any performance-critical application [S1, unofficial].

## Background
The Naive PyTorch Baseline Renderer was introduced in the paper "DiffBMP: Differentiable Rendering with Bitmap Primitives" [S1, unofficial]. It was designed to demonstrate the efficiency of a custom CUDA implementation by comparing it against a straightforward PyTorch-based renderer that uses standard tensor operations without tile-based culling or specialized kernels [S1, unofficial]. The paper highlights the major bottlenecks of this approach, including no spatial culling, massive memory allocation, sequential loops, and generic operations [S1, unofficial].
