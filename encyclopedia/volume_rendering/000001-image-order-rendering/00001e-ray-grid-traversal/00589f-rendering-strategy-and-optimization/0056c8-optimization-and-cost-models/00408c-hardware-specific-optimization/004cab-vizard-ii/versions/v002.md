# VIZARD II

Also called: UVIZARD

## Overview
VIZARD II is a specialized hardware architecture for interactive volume rendering, designed to bring ray casting to desktop computers by minimizing memory bandwidth requirements [S2]. It implements early ray termination and uses quantized gradient look-up tables to accelerate shading and compositing [S1, unofficial][S2]. Unlike its sibling [VolumePro](10277-hardware-specific-optimization.md), which uses brute-force rendering, VIZARD II supports perspective viewing and segmentation, though it relies on a table-based gradient scheme rather than hardware gradient estimation [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A 3D scalar volume dataset.
- **Output:** A 2D image rendered on a PCI board, transferred to the host computer [S2].

**Data Structures:**
1.  **Volume Data:** Stored in SDRAM/SRAM. Four voxels are four-way interleaved with respect to the YZ-plane to allow parallel access [S2].
2.  **Gradient Table:** A look-up table storing quantized gradient vectors. The gradient index for each voxel is 9 bits [S2].
3.  **Cache Banks:** Separate cache banks store fetched voxel neighborhoods to allow parallel access and re-use [S2].

**Preprocessing:**
The dataset is preprocessed to compute gradient indices for each voxel using central differences. This step takes a few seconds and is performed once per dataset [S2].

**Algorithm Steps:**
1.  **Ray Traversal:** The system advances along rays in image order. Early ray termination is used to skip transparent regions [S2].
2.  **Memory Access:** To access a $2 \times 2 \times 2$ trilinear interpolation neighborhood:
    - Four voxels (including the gradient index) are accessed in parallel from the YZ-plane [S2].
    - A sequential burst memory access fetches the adjacent voxels in the X-direction from each bank [S2].
3.  **Caching:** The fetched values are cached in separate cache banks [S2].
4.  **Interpolation:**
    - The **Interpolation Unit** uses fractional $x, y, z$ components and the cached neighborhood to re-sample the dataset [S2].
    - The **Gradient Index** addresses the gradient look-up table. The resulting $x, y, z$ gradient components are interpolated similarly [S2].
5.  **Shading and Compositing:**
    - The sample value and interpolated gradient are passed to the **Shading and Compositing Unit** [S2].
    - **Classification:** A classification table is selected using a classification index. The architecture supports segmentation and multiple cut-planes [S2].
    - **Shading:** Phong shading is implemented using a look-up table [S2].
    - **Compositing:** The standard "over" operator is used [S2].
6.  **Output:** Final pixel values are transferred through the PCI bus [S2].

**Parameters:**
- **Gradient Table Size:** Default 9-bit index. Can be increased for higher accuracy [S2].
- **Supersampling:** 4:1 mapping of samples to voxels is assumed for best-case performance [S2].
- **Clock Ratio:** Cache memory and Trilinear Interpolation Units are clocked 4 times faster than the memory system [S2].

**Edge Cases and Pitfalls:**
- **Worst-case Performance:** Occurs with 1:1 mapping of samples to voxels and a transparent classification of the dataset [S2].
- **Gradient Quantization:** Prevents voxel re-fetch from exceeding the trilinear interpolation neighborhood size, but may degrade image quality compared to traditional central difference gradients [S2].
- **Memory Bandwidth:** Performance is memory-limited. Best-case memory bandwidth utilization is 0.8 with 4:1 supersampling [S2].

## Operating characteristics
- **Time Complexity:** Not explicitly defined in algorithmic terms, but performance is measured in Samples Processed Per Second (SPPS) [S2].
- **Memory Complexity:** Limited by the SDRAM/SRAM capacity on the PCI board. The architecture uses caching to reduce effective memory bandwidth [S2].
- **Performance:**
    - **Best-case:** $56 \times 10^6$ samples per second (SPPS) with 4:1 supersampling [S2].
    - **Worst-case:** $14 \times 10^6$ SPPS with 1:1 sampling [S2].
    - **Frame Rate:** Expected to sustain 10 Hz for a $256^3$ dataset. Worst-case is approximately 1 frame per second [S2].
    - **Peak Performance:** ~6 SPPS (Note: Source [S2] states "6 SPPS" in one context and "$56 \times 10^6$" in another; the $56 \times 10^6$ figure is explicitly linked to the hardware capability with 4:1 mapping, while "6 SPPS" appears in a summary sentence that may refer to a different metric or contain a typo in the source text. Given the explicit "$56 \times 10^6$" and "$14 \times 10^6$" figures, the latter are used for performance metrics. The "6 SPPS" claim is contradictory to the millions of samples per second and is likely a misinterpretation of "6" as a multiplier or a different unit in the source [S2]).
- **Strengths:** Interactive frame rates for desktop hardware; supports perspective rendering, segmentation, and multiple cut-planes [S1, unofficial][S2].
- **Limitations:** Memory bandwidth limited; quantized gradients may reduce image quality; research-stage architecture [S2].
- **When to use:** When interactive volume rendering is required on hardware with limited general-purpose GPU capabilities, specifically for datasets where early ray termination is effective [S2].

## Background
VIZARD II was developed at the University of Tübingen as the second generation of VIZARD systems [S2]. It was designed to bring interactive ray casting to desktop computers by reducing memory bandwidth requirements [S2]. It is a research-stage architecture implemented on a PCI board with four FPGAs, a DSP, and SDRAM/SRAM [S1, unofficial][S2]. It is a successor to the original VIZARD, which used pre-shaded and pre-classified compressed datasets, whereas VIZARD II uses quantized gradient look-up tables [S2].
