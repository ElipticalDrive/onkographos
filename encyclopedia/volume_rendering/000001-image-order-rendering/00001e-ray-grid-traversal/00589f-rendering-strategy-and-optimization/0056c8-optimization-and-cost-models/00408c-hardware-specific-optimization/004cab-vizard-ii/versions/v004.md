# VIZARD II

Also called: UVIZARD

## Overview
VIZARD II is a hardware-accelerated volume rendering architecture designed to bring interactive ray casting to desktop computers by minimizing memory bandwidth requirements through quantized gradients, caching, and early ray termination [S2]. Unlike its predecessor VIZARD which used pre-shaded data, VIZARD II computes gradients on-the-fly using a quantized lookup table, and unlike the VolumePro architecture, it supports perspective rendering while relying on a table-based gradient vector lookup scheme rather than hardware gradient estimation [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** A 3D scalar volume dataset (typically $256^3$ voxels) and a classification table.
*   **Output:** A 2D image rendered at interactive frame rates (target 10 Hz) [S2].

**Data Structures**
1.  **Volume Data:** Stored in memory banks. To support parallel access, voxels are **four-way interleaved** with respect to the YZ-plane [S2].
2.  **Gradient Table:** A lookup table storing quantized gradient vectors. The gradient index for each voxel is 9 bits (though the architecture is not limited to this size) [S2].
3.  **Cache Banks:** Separate cache banks store recently accessed voxel values and gradient components to allow parallel access and re-use [S2].

**Algorithm Steps**
1.  **Preprocessing:** The dataset is preprocessed to compute gradient indices for each voxel using central differences. This step is performed once per dataset [S2].
2.  **Memory Access (Trilinear Neighborhood):**
    *   To access a $2 \times 2 \times 2$ trilinear interpolation neighborhood, the system accesses four voxels (including their gradient indices) in parallel from the YZ-plane [S2].
    *   A burst memory access fetches adjacent voxels in the X-direction [S2].
    *   Specifically, four voxels in the YZ-plane are accessed in parallel from each memory bank, and a sequential burst memory access from each bank provides the remaining four values from an adjacent YZ-plane [S2].
    *   These values are cached in separate cache banks [S2].
3.  **Interpolation:**
    *   The **Interpolation Unit** uses the fractional $x, y, z$ components of the ray position and the trilinear neighborhood from the Memory Unit to re-sample the dataset value [S2].
    *   The 9-bit gradient index addresses the gradient lookup table to retrieve the $x, y, z$ gradient components. These components are interpolated in a similar trilinear manner [S2].
4.  **Shading and Compositing:**
    *   The sample value and interpolated gradient are passed to the **Shading and Compositing Unit** [S2].
    *   **Classification:** A classification index selects the appropriate classification table. The architecture supports segmentation and multiple cut-planes [S2].
    *   **Shading:** Phong shading is implemented using a look-up table [S2].
    *   **Compositing:** The standard "over" operator is used for alpha compositing [S2].
5.  **Early Ray Termination:** The compositing process utilizes early ray termination to stop ray casting when opacity thresholds are met, increasing frame rate [S2].

**Parameters and Formulas**
*   **Gradient Quantization Error:** A 9-bit gradient index generates an average error of $\frac{512}{23} \approx 22.26$ degrees and a maximum error of $\frac{512}{2} = 256$ degrees [S2]. Larger gradient tables can be used to enhance accuracy [S2].
*   **Memory Efficiency Factor:** $0.2$ assuming worst-case (1:1 sampling) and memory system clocked at maximum rate [S2].
*   **Algorithmic Speedup:** Assumed to be $3$ due to early ray termination [S2].
*   **Clock Rates:** Cache memory and Trilinear Interpolation Units are clocked four times faster than the memory system [S2].

**Edge Cases and Pitfalls**
*   **Worst-Case Performance:** Occurs for 1:1 mapping of samples to voxels and a transparent classification of the dataset, resulting in approximately 1 frame per second [S2].
*   **Gradient Quantization:** The use of quantized central difference gradients prevents voxel re-fetch from exceeding the trilinear interpolation neighborhood size, but may degrade image quality compared to traditional central difference gradients [S2].
*   **Memory Bandwidth:** Performance is memory-limited. Best-case performance assumes 4:1 supersampling, which increases cache hits [S2].

## Operating characteristics
*   **Performance:**
    *   **Target Frame Rate:** 10 Hz for a $256^3$ dataset [S2].
    *   **Worst-Case Frame Rate:** ~1 frame per second (1:1 sampling, transparent classification) [S2].
    *   **Samples Processed Per Second (SPPS):**
        *   Worst-case: $14 \times 10^6$ SPPS (1:1 sampling) [S2].
        *   Best-case: $56 \times 10^6$ SPPS (4:1 supersampling) [S2].
        *   Peak Performance: ~6 SPPS (Note: Source text contains conflicting units/values; "6 SPPS" likely refers to a normalized metric or contains a typo in the source, as $56 \times 10^6$ is explicitly stated as best-case SPPS. We cite the explicit $56 \times 10^6$ figure) [S2].
*   **Complexity:** The architecture is memory-limited. The memory efficiency factor is 0.2 in the worst case and 0.8 in the best case (4:1 supersampling) [S2].
*   **Strengths:**
    *   Supports perspective rendering, segmentation, and multiple cut-planes [S1, unofficial][S2].
    *   Reduces memory bandwidth requirements via caching and quantized gradients [S2].
    *   Good performance-to-cost ratio compared to ASICs [S2].
*   **Limitations:**
    *   Research-stage architecture; not a commercial product [S2].
    *   Gradient quantization may degrade image quality [S2].
    *   Performance is highly dependent on supersampling and classification transparency [S2].

## Background
VIZARD II was developed at the University of Tübingen as the second generation of the VIZARD systems (following VIZARD) [S2]. It was designed to run on a PCI board populated with four FPGAs, a DSP, and SDRAM/SRAM memory [S1, unofficial]. The architecture was simulated and was in the research stage as of 1999 [S2]. It was developed to bring interactive ray casting into the realm of desktop computers, addressing the memory bandwidth bottlenecks of previous architectures [S2].
