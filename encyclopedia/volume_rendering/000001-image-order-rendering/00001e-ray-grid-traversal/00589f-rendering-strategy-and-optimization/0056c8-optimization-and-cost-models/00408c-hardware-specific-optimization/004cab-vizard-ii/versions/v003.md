# VIZARD II

Also called: UVIZARD

## Overview
VIZARD II is a hardware-accelerated, image-order ray casting architecture designed to bring interactive volume rendering to desktop computers by minimizing memory bandwidth requirements [S2]. It distinguishes itself from sibling methods like [GPU CSG Ray Tracing with Uniform Grid Index](4098-gpu-csg-ray-tracing-with-uniform-grid-index.md) and [UltraVis Cache Optimization](10355-ultravis-cache-optimization.md) by relying on a specialized PCI board with FPGAs and a DSP, utilizing 9-bit quantized gradient look-up tables and four-way interleaved memory access rather than general-purpose GPU shaders or software-based cache management [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D scalar volume dataset $V$ of size $N_x \times N_y \times N_z$.
*   **Preprocessing:** A gradient table $G$ is generated from $V$ using quantized central differences.
*   **Output:** A 2D image frame.

**Data Structures:**
1.  **Volume Data ($V$):** Stored in SDRAM/SRAM. Voxels are four-way interleaved with respect to the YZ-plane to facilitate parallel access.
2.  **Gradient Table ($G$):** A look-up table where each entry corresponds to a 9-bit gradient index. The table stores pre-computed $(g_x, g_y, g_z)$ components.
3.  **Cache Banks:** Separate cache banks store recently accessed voxel neighborhoods and gradient values to allow parallel re-use.

**Algorithm Steps:**

1.  **Preprocessing (Offline):**
    *   For each voxel in $V$, compute the central difference gradient.
    *   Quantize the gradient vector to a 9-bit index.
    *   Store the index in the voxel data and the corresponding full gradient components in $G$ [S2].

2.  **Ray Initialization:**
    *   For each pixel in the image, initialize a ray origin and direction.
    *   Determine the entry and exit points into the volume bounding box [S2].

3.  **Ray Traversal and Sampling:**
    *   Advance the ray through the volume grid.
    *   **Memory Access:** To fetch a $2 \times 2 \times 2$ trilinear interpolation neighborhood:
        *   Access four voxels (including gradient index) in parallel from the YZ-plane.
        *   Perform a sequential burst memory access from each bank to fetch the adjacent YZ-plane values in the X-direction [S2].
    *   **Caching:** Store fetched values in separate cache banks for parallel access and re-use [S2].

4.  **Interpolation:**
    *   **Volume Value:** Use the fractional $(x, y, z)$ components and the cached voxel neighborhood in the Interpolation Unit to perform trilinear interpolation [S2].
    *   **Gradient:** Use the 9-bit gradient index to address $G$. Retrieve the $(g_x, g_y, g_z)$ components. Interpolate these gradient components in a similar manner to the volume values [S2].

5.  **Shading and Compositing:**
    *   Pass the interpolated sample value and gradient to the Shading and Compositing Unit.
    *   **Classification:** Use a classification index (derived from the sample value) to select a classification table. Support for segmentation and multiple cut-planes is handled here [S2].
    *   **Shading:** Implement Phong shading using a look-up table based on the interpolated gradient and light direction [S2].
    *   **Compositing:** Apply the standard 'over' operator to accumulate color and opacity along the ray [S2].

6.  **Early Ray Termination:**
    *   If the accumulated opacity exceeds a threshold, terminate the ray early to save computation [S2].

7.  **Output:**
    *   Transfer final pixel values through the PCI bus to the host computer [S2].

**Parameters:**
*   **Gradient Quantization:** 9-bit index [S2]. Larger tables can be used for greater accuracy [S2].
*   **Supersampling:** 4:1 mapping of samples to voxels is assumed for best-case performance [S2].
*   **Clock Rates:** Cache memory and Trilinear Interpolation Units are clocked four times faster than the memory system [S2].

**Edge Cases and Pitfalls:**
*   **Worst-Case Performance:** Occurs with 1:1 mapping of samples to voxels and a transparent classification of the dataset [S2].
*   **Gradient Quantization Error:** The 9-bit gradient index generates an average error of $\approx 2.3^\circ$ and a maximum error of $\approx 5.5^\circ$ [S2]. This may degrade image quality compared to traditional central difference gradients [S2].
*   **Voxel Re-fetch:** The quantized central difference gradient prevents voxel re-fetch from exceeding the trilinear interpolation neighborhood size [S2].

## Operating characteristics
*   **Performance:**
    *   **Best-Case:** $56 \times 10^6$ samples per second (SPPS) with 4:1 supersampling [S2].
    *   **Worst-Case:** $14 \times 10^6$ SPPS with 1:1 sampling [S2].
    *   **Frame Rate:** Expected to sustain 10 Hz for a $256^3$ dataset; worst-case is approximately 1 frame per second [S2].
    *   **Peak Performance:** $\sim 6$ SPPS is cited in one context, but $56 \times 10^6$ SPPS is the detailed hardware simulation result [S2]. The $6$ SPPS figure likely refers to a different metric or unit in the source text, but the $56 \times 10^6$ figure is explicitly linked to the hardware capabilities [S2].
*   **Memory Efficiency:**
    *   **Worst-Case:** Memory efficiency factor of 0.2 (assuming 1:1 sampling and max memory clock rate) [S2].
    *   **Best-Case:** Memory bandwidth utilization of 0.8 (assuming 4:1 supersampling) due to cache hits [S2].
*   **Algorithmic Speedup:** Assumed to be 3 due to early ray termination [S2].
*   **Strengths:**
    *   Supports perspective rendering, multiple cut planes, and segmentation [S1, unofficial][S2].
    *   Reduces memory bandwidth requirements through caching and quantized gradients [S2].
    *   Good performance-to-cost ratio compared to ASICs [S2].
*   **Limitations:**
    *   Memory bandwidth limited [S2].
    *   Gradient quantization may degrade image quality [S2].
    *   Research-stage architecture; not a commercial product [S2].
    *   Requires preprocessing of gradients [S2].

## Background
VIZARD II was developed at the University of Tübingen as the second generation of the VIZARD systems [S2]. It was designed to bring interactive ray casting to desktop computers using a PCI board populated with four FPGAs, a DSP, and SDRAM/SRAM memory [S1, unofficial][S2]. It is a research-stage architecture [S2]. It differs from its predecessor VIZARD, which used pre-shaded and pre-classified compressed datasets, by using quantized gradient look-up tables [S2]. It is compared to VolumePro, which uses brute-force rendering and shear-image order, whereas VIZARD II uses image-order with early ray termination [S1, unofficial].
