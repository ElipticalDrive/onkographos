# Hardware-Aware Hyperparameter Tuning

Also called: Hyperparameter Selection, XPR Hyperparameter Selection, automatic hyperparameter tuning

## Overview
Hardware-Aware Hyperparameter Tuning is an automatic process that determines optimal performance parameters (tile size, unroll factor, number of bins, batch divisor) for a specific scene and hardware configuration, ensuring correctness and performance without manual tuning [S1, unofficial]. It sets itself apart from manual configuration or static heuristics by profiling the specific target views to derive exact bounds and searching the parameter space sequentially to adapt to scene geometry and hardware characteristics [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs:** The set of target views to be rendered, the trained primitive parameters, and the target hardware device [S1, unofficial].
*   **Outputs:** A set of six hyperparameters: Tile Size, Unroll Factor ($U$), Number of Bins ($L$), Batch Divisor ($D$), and the derived Shader Batch Size ($b_l$), along with the data-aware assignment of tiles to bins [S1, unofficial].

**Data Structures**
The method relies on profiling data collected from the target views. For each view, it records:
*   $M$: The maximum number of primitives intersecting any tile in that view.
*   $I$: The maximum number of primitives intersecting any tile in that view (often synonymous with $M$ in the context of bounds, representing the intensity of intersection) [S1, unofficial].
*   Per-tile primitive counts for all tiles in all views [S1, unofficial].

**Parameters and Search Space**
The search space for the hyperparameters is defined as follows [S1, unofficial]:
*   **Tile Size:**
    *   GPU: $\{8 \times 8, 16 \times 16\}$
    *   TPU: $\{16 \times 16, 32 \times 32\}$
*   **Unroll Factor ($U$):** $\{1, 2, 4, 8, 16, 32\}$
*   **Number of Bins ($L$):** $\{2, 4, 6, 8\}$
*   **Batch Divisor ($D$):** $\{1, 2, 4, 8\}$
*   **$P_{max}$:** A global accuracy/speed tuning knob (values $\{4096, 8192\}$) shared by all methods, identical for all methods [S1, unofficial].

**Numbered Steps**
The selection operates in two main phases: Profiling and Search.

1.  **Profile Views:** Render every target view once using a forward-only pass (no gradients). Record $M$, $I$, and the number of primitives each tile intersects for each view [S1, unofficial].
2.  **Set Bounds:** Set the global bounds for $M$ and $I$ to the observed maxima across all views. This guarantees bounds are sufficient without safety margins [S1, unofficial].
    *   *Pitfall:* Any view whose $M$ or $I$ values exceed the chosen bounds can produce incorrect rendered images or a drop in accuracy. Profiling all target views is necessary [S1, unofficial].
3.  **Search Performance Parameters:** Search for optimal Tile Size, $U$, $L$, and $D$ in five sequential phases [S1, unofficial]:
    *   **Phase 1: Tile Size.** Search from two candidates. Each candidate must be profiled because different tile sizes change the tile grid structure [S1, unofficial].
    *   **Phase 2: Unroll Factor ($U$).** Search from six candidates, benchmarked exhaustively [S1, unofficial].
    *   **Phase 3: Number of Bins ($L$).** Search from four candidates, benchmarked exhaustively.
        *   *Tie-Breaker:* If candidates are tied within a 2% noise tolerance, re-benchmark the lowest and highest tied candidates with additional runs to break the tie [S1, unofficial].
    *   **Phase 4: Re-search $U$.** Search $U$ again at the chosen $L$ (six candidates). This is triggered whenever $L$ shifts the bin layout, because a larger unrolled scan body shifts the tradeoff between instruction-level parallelism and register pressure [S1, unofficial].
    *   **Phase 5: Batch Divisor ($D$).** Search from up to four candidates, preferring $D=4$ within noise tolerance [S1, unofficial].
4.  **Compute Data-Aware Assignment:** Determine the assignment of tiles to bins. This is computed from the worst-case cumulative counts of primitives across all views [S1, unofficial].
5.  **Derive Shader Batch Size ($b_l$):** For each bin $l$, compute the shader batch size $b_l$ from the bin trip count $P_l$ using the formula:
    $$ b_l = \lfloor P_l / D \rfloor $$
    The result is then rounded to a multiple of $U$ [S1, unofficial].

**Pseudocode**
```python
def hardware_aware_hyperparameter_tuning(target_views, primitives, hardware):
    """
    Automatically selects optimal hyperparameters for XPR rendering.
    """
    # Step 1: Profile Views
    # Render every target view once (forward-only, no gradients)
    max_M = 0
    max_I = 0
    tile_intersections = {} # Map: (view_id, tile_id) -> count

    for view in target_views:
        # Render view and collect stats
        view_stats = render_view_forward_only(view, primitives)
        
        # Record M, I, and per-tile counts
        current_M = view_stats.max_primitives_per_tile
        current_I = view_stats.max_primitives_per_tile # Context implies I tracks intersection intensity
        
        if current_M > max_M:
            max_M = current_M
        if current_I > max_I:
            max_I = current_I
            
        for tile_id, count in view_stats.tile_counts.items():
            tile_intersections[(view.id, tile_id)] = count

    # Step 2: Set Bounds
    # Bounds are guaranteed sufficient without safety margins
    global_M = max_M
    global_I = max_I

    # Step 3: Search Performance Parameters
    # Phase 1: Tile Size
    best_tile_size = None
    best_tile_perf = -1
    
    tile_candidates = {
        "GPU": [(8, 8), (16, 16)],
        "TPU": [(16, 16), (32, 32)]
    }
    
    for ts in tile_candidates[hardware]:
        perf = benchmark_tile_size(ts, target_views, primitives)
        if perf > best_tile_perf:
            best_tile_perf = perf
            best_tile_size = ts
            
    tile_size = best_tile_size

    # Phase 2: Unroll Factor U (Initial)
    best_U = None
    best_U_perf = -1
    U_candidates = [1, 2, 4, 8, 16, 32]
    
    for U in U_candidates:
        perf = benchmark_unroll(U, tile_size, target_views, primitives)
        if perf > best_U_perf:
            best_U_perf = perf
            best_U = U
            
    # We store the initial U, but it may be overridden in Phase 4
    initial_U = best_U

    # Phase 3: Number of Bins L
    best_L = None
    best_L_perf = -1
    L_candidates = [2, 4, 6, 8]
    tied_L_candidates = []
    
    for L in L_candidates:
        perf = benchmark_bins(L, tile_size, target_views, primitives)
        if perf > best_L_perf:
            best_L_perf = perf
            best_L = L
            tied_L_candidates = [L]
        elif abs(perf - best_L_perf) < 0.02 * best_L_perf: # 2% noise tolerance
            tied_L_candidates.append(L)
            
    # Tie-breaker
    if len(tied_L_candidates) > 1:
        # Re-benchmark lowest and highest tied candidates
        low_L = min(tied_L_candidates)
        high_L = max(tied_L_candidates)
        
        perf_low = benchmark_bins(low_L, tile_size, target_views, primitives, runs=10)
        perf_high = benchmark_bins(high_L, tile_size, target_views, primitives, runs=10)
        
        if perf_low > perf_high:
            best_L = low_L
        else:
            best_L = high_L
            
    L = best_L

    # Phase 4: Re-search U at chosen L
    # Triggered whenever L shifts the bin layout
    best_U_final = None
    best_U_final_perf = -1
    
    for U in U_candidates:
        perf = benchmark_unroll(U, tile_size, L, target_views, primitives)
        if perf > best_U_final_perf:
            best_U_final_perf = perf
            best_U_final = U
            
    U = best_U_final

    # Phase 5: Batch Divisor D
    best_D = None
    best_D_perf = -1
    D_candidates = [1, 2, 4, 8]
    
    # Prefer D=4 within noise tolerance
    for D in D_candidates:
        perf = benchmark_batch_divisor(D, tile_size, L, U, target_views, primitives)
        if D == 4 and abs(perf - best_D_perf) < 0.02 * best_D_perf:
            best_D = D
            best_D_perf = perf
            break # Found preferred D within tolerance
        elif perf > best_D_perf:
            best_D_perf = perf
            best_D = D
            
    D = best_D

    # Step 4: Compute Data-Aware Assignment
    # Compute worst-case cumulative counts across all views
    bin_assignment = compute_tile_to_bin_assignment(
        tile_intersections, 
        L, 
        global_M, 
        global_I
    )

    # Step 5: Derive Shader Batch Size
    # For each bin l, calculate b_l
    bin_batch_sizes = {}
    for bin_id, trip_count_P_l in bin_assignment.items():
        b_l = floor(trip_count_P_l / D)
        # Round to multiple of U
        b_l = round_to_multiple(b_l, U)
        bin_batch_sizes[bin_id] = b_l

    return {
        "tile_size": tile_size,
        "U": U,
        "L": L,
        "D": D,
        "bin_assignment": bin_assignment,
        "bin_batch_sizes": bin_batch_sizes,
        "bounds": {"M": global_M, "I": global_I}
    }

def round_to_multiple(value, multiple):
    return int(round(value / multiple)) * multiple
```

**Edge Cases and Pitfalls**
*   **Incorrect Bounds:** If any view's $M$ or $I$ values exceed the chosen bounds, it produces incorrect rendered images or a drop in accuracy [S1, unofficial].
*   **Noise in Benchmarking:** The 2% noise tolerance is critical for tie-breaking in bin selection; insufficient re-benchmarking runs may lead to suboptimal choices [S1, unofficial].
*   **Register Pressure:** Changing $L$ affects the tradeoff between instruction-level parallelism and register pressure, necessitating the re-search of $U$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The hyperparameter selection takes only a few minutes. It is a one-time cost that is negligible relative to the training time of the scene [S1, unofficial].
*   **Memory Complexity:** Not given in the sources.
*   **Measured Performance:**
    *   On an L40 GPU with the 360 dataset:
        *   Base XPR-4K: SSIM 0.87, LPIPS 0.182.
        *   XPR-8K: SSIM 0.87, LPIPS 0.182.
        *   LinPrim: SSIM 0.86, LPIPS 0.190.
        *   XPR-8K LinPrim: SSIM 0.83, LPIPS 0.195 [S1, unofficial].
*   **Scaling:** Increasing the number of bins initially increases FPS by reducing redundant computation. However, beyond an optimal count, FPS drops due to reduced SM occupancy and increased launch overhead [S1, unofficial].
*   **Strengths:** Adapts to scene geometry without manual tuning; guarantees correctness by profiling all target views; negligible setup cost [S1, unofficial].
*   **Limitations:** Requires forward-only profiling passes; performance is sensitive to hardware-specific factors like SM occupancy and cache behavior [S1, unofficial].

## Background
*   **Origin:** The method is part of the XPR (Extensible Cross-Platform Point-Based Differentiable Renderer) framework [S1, unofficial].
*   **History:** It was introduced to automate the configuration of XPR, allowing it to adapt to various hardware (GPU, TPU) and scene geometries without user intervention [S1, unofficial].
*   **Usage:** Used in XPR-3DGUT and XPR-LinPrim implementations [S1, unofficial].

## Subtopics

### Tile Size Selection
Determines the granularity of the rendering grid. Smaller tiles (8x8) may offer better culling but higher overhead, while larger tiles (16x16) may improve occupancy. Chosen from {8x8, 16x16} for GPU and {16x16, 32x32} for TPU [S1, unofficial].

### Unroll Factor ($U$)
Controls the XLA unroll factor for the inner loop over primitive entries. Affects the tradeoff between instruction-level parallelism and register pressure. Chosen from {1, 2, 4, 8, 16, 32} [S1, unofficial].

### Number of Bins ($L$)
Partitions tiles to reduce redundant computation. Too few bins cause redundant work; too many bins reduce SM occupancy. Chosen from {2, 4, 6, 8} [S1, unofficial].

### Batch Divisor ($D$)
Controls the granularity of early exit in the blend loop. Smaller $D$ checks exit conditions less frequently (lower overhead, more wasted work); larger $D$ enables tighter early termination (higher overhead). Chosen from {1, 2, 4, 8}, preferring 4 [S1, unofficial].
