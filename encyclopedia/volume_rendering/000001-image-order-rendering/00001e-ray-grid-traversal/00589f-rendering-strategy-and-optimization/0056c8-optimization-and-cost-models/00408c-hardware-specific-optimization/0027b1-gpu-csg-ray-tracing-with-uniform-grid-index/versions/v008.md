# GPU CSG Ray Tracing with Uniform Grid Index

Also called: GPU CSG Renderer Features, GPU CSG tracer, GpuPlot

## Overview
A GPU-based ray tracer for Constructive Solid Geometry (CSG) that accelerates traversal by replacing unindexed full-scan approaches with a uniform grid index over the root universe's cells [S1, unofficial]. It renders various plot types (Solid, Wireframe, Slice) using a WGSL shader that serves as an `f32` transcription of the CPU plotter's raytrace, slice, geometry, cell, and lattice logic [S1, unofficial]. Unlike its siblings, it specifically targets the cost of ray traversal in large, unbounded CSG models by pre-computing surface intersections per voxel, reducing frame times from hundreds of milliseconds to single-digit milliseconds for indexed scenes [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   CSG geometry defined by a root universe containing cells, surfaces, and regions.
*   Ray origin and direction for each pixel.
*   Plot type: `Solid` (Phong lighting), `Wireframe`, or `Slice` (section planes with cut faces, per-material visibility, x-ray attenuation) [S1, unofficial].

**Outputs:**
*   Rendered image buffer.
*   Status metrics (e.g., frame time) [S1, unofficial].

### Data Structures
**`outram_blender::csg::gpu::flat` Buffer:**
A single `u32` buffer containing the assembled geometry. It holds:
*   Surfaces.
*   RPN (Reverse Polish Notation) regions.
*   Universes.
*   Rect and hex lattices (with maps and outer definitions).
*   Translations.
*   Static crossing hints (OpenMC-style neighbour lists).
*   The universe graph (used to skip subtrees with no drawn material) [S1, unofficial].

**`GpuPlot` Struct:**
Contains variants `Solid`, `Wireframe`, and `Slice`, matching the CPU plotter's structs [S1, unofficial].

**Uniform Grid Index:**
*   A voxel grid over the root universe's bounding box.
*   Each voxel lists the cells that intersect it.
*   Each cell's region expression is constant-folded down to the specific surfaces that pass through that voxel [S1, unofficial].
*   Typical Resolution: 30x30x47 voxels for the HTR-10 root universe [S1, unofficial].

### Numbered Steps

1.  **Build the Uniform Grid:**
    *   Create a voxel grid over the root universe's bounding box.
    *   For each voxel, identify the cells that intersect it.
    *   Constant-fold each cell's region expression to determine the specific surfaces passing through that voxel [S1, unofficial].

2.  **Close the Grid:**
    *   Ensure no root cell lies outside the grid bounds.
    *   For unbounded OpenMC boxes (e.g., absorber-sphere channels, core cell conus), perform vertex enumeration over plane half-spaces.
    *   Apply a bound on the cone radius to create tight bounding boxes for these unbounded regions [S1, unofficial].

3.  **Indexing Budget:**
    *   Index universes with token counts above 512.
    *   Operate within a 16 MB memory budget for the index.
    *   If the geometry buffer exceeds the device's 128 MiB binding limit, return an error to trigger a CPU fallback instead of panicking [S1, unofficial].

4.  **Ray Traversal (Shader Execution):**
    *   **Outside Model:** If the ray is outside the model, it jumps directly to the grid.
    *   **Inside Grid:** The ray steps through voxels. Voxel faces act as "silent steps" (no surface intersection test required) [S1, unofficial].
    *   **Post-Step Correction:** After a silent voxel step, reset the token to ensure the ray can exit a bore/cell correctly. Previously, the tracer kept the token of the last-crossed surface, trapping the ray [S1, unofficial].

5.  **Intersection Test:**
    *   Upon entering a voxel, test against the pre-computed surfaces for the candidate cells.
    *   **Complement Handling:** Sign complex regions from the surface normal. This corrects a CPU parity bug where complements were not handled via De Morgan's laws. For example, a ray entering a reflector core written as `box & ~core` must be re-located correctly in the reflector [S1, unofficial].

6.  **Rendering:**
    *   **Phong Solid View:** Render solid geometry with lighting.
    *   **Slice View:** Render section planes with cut faces. Supports per-material visibility and x-ray attenuation with outlines.
    *   **ClipPlane Shadow Fix:** Ensure the ray is lit once it passes into the cut-away half of a ClipPlane. Previously, the shadow ray was blocked by the cut-away half. This changes the shade of ~2.5% of pixels but does not change material assignment [S1, unofficial].

### Pseudocode

```python
# Simplified WGSL-like logic for the ray traversal kernel
# Assumes flat buffer is bound and accessible

fn trace_ray(origin: vec3<f32>, direction: vec3<f32>, plot_type: PlotType) -> vec4<f32>:
    # 1. Check if ray is outside the closed grid bounds
    if not is_inside_grid_bounds(origin, direction):
        # Jump directly to grid entry point
        t_entry = compute_grid_entry_t(origin, direction)
        current_pos = origin + direction * t_entry
    else:
        current_pos = origin

    # 2. Traverse the uniform grid
    while current_pos is inside grid:
        voxel = get_voxel_at(current_pos)
        
        # Silent step: moving from voxel face to voxel face requires no surface test
        # Advance to next voxel boundary
        t_next = compute_next_voxel_boundary_t(current_pos, direction)
        prev_pos = current_pos
        current_pos = current_pos + direction * t_next
        
        # Post-Step Correction: Reset token after silent step to allow exit from bores
        # This prevents the tracer from retaining the token of the last-crossed surface
        reset_token() 
        
        # 3. Intersection Test within the voxel
        # Test against pre-computed surfaces for candidate cells in this voxel
        for surface in voxel.candidate_surfaces:
            t_hit = compute_surface_intersection(current_pos, direction, surface)
            if t_hit > 0:
                # Sign complex regions from the surface normal
                # Corrects complement handling (De Morgan's laws)
                normal = compute_surface_normal(surface, hit_point)
                region_token = sign_region_from_normal(surface.region, normal)
                
                # Handle ClipPlane shadow fix if applicable
                if plot_type == Solid and is_behind_clip_plane(hit_point):
                    ensure_lit(hit_point)
                
                return render_pixel(hit_point, region_token, plot_type)

    # Fallback or background color if ray escapes
    return background_color
```

### Parameters
*   **Grid Resolution:** 30x30x47 voxels for HTR-10 root universe [S1, unofficial].
*   **Indexing Threshold:** Universes with token counts > 512 are indexed [S1, unofficial].
*   **Memory Budget:** 16 MB for indexing [S1, unofficial].
*   **Buffer Limit:** 128 MiB binding limit per device [S1, unofficial].

### Edge Cases and Pitfalls
*   **Complement Handling:** The CPU port did not remove complements by De Morgan's laws or sign complex regions from the surface normal. This caused rays entering a reflector core (written as `box & ~core`) to be re-located incorrectly. The fix signs complex regions from the normal [S1, unofficial].
*   **Silent Step Token Retention:** After stepping through a voxel face (silent step), the tracer retained the token of the last-crossed surface. This prevented rays inside a bore from exiting. The fix resets the token [S1, unofficial].
*   **ClipPlane Shadow Bug:** In the CPU SolidRayTracePlot with a ClipPlane, the shadow ray was blocked by the cut-away half. The fix ensures the ray is lit once it passes into that half. This changes the shade of 2.5% of pixels but no pixel changes material [S1, unofficial].
*   **Unbounded Cells:** Root cells with unbounded OpenMC boxes (e.g., absorber-sphere channels, core cell conus) must be closed with tight bounding boxes to prevent rays from stepping through infinite extensions [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Cost per crossing is approximately 90 ns. This is largely due to reflector cells holding up to 124 region tokens [S1, unofficial].
*   **Measured Performance (Şeker bed, half-section, 900x560):**
    *   GPU Indexed: 24-60 ms (best 17 ms).
    *   GPU Unindexed: 0.36-0.39 s.
    *   CPU: 6.95 s (from earlier test) or 0.41 s (HTR-10 specific).
    *   Indexed GPU is ~15-30x faster than unindexed GPU [S1, unofficial].
*   **Scaling:** Indexing reduces frame time significantly. Unindexed rays performed ~10 full scans of the 128-cell root universe because rays outside the model stepped through infinite extensions (planes, cones) crossing all 1,675 tokens. Indexing avoids these full scans [S1, unofficial].
*   **Strengths:** Dramatic speedup for large CSG models; supports interactive 3D view at full resolution while camera moves (once frame time < 30 ms); supports various plot types (Solid, Wireframe, Slice) [S1, unofficial].
*   **Limitations:** Buffer limit of 128 MiB; shared GPU resources cause 2-4x variance in frame times; X-ray with every pebble shown is still slow (~0.64 s) due to walking every TRISO lattice; slice view does not do overlap checks, level or mesh lines [S1, unofficial].
*   **When to Use:** When rendering large CSG models on GPU with Vulkan support and sufficient memory budget.
*   **When Not to Use:** When buffer exceeds 128 MiB (falls back to CPU); when high precision overlap checks are needed for slices; when GPU is heavily shared with desktop.

## Background
Originated in the `outram-blender` crate, specifically in the `dhoby-ghaut` project, as a WGSL ray tracer over assembled geometry [S1, unofficial]. It was developed to replace the unindexed full-scan approach, which was too slow for interactive use. The implementation is an `f32` transcription of the CPU plotter's logic, ensuring parity. It was verified on NVIDIA RTX A5000 with Vulkan [S1, unofficial]. The project is associated with the `outram-park-backend` repository [S1, unofficial].
