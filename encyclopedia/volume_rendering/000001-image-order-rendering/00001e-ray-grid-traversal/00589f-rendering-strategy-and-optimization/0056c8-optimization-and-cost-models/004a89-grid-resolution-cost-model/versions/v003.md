# Grid Resolution Cost Model

Also called: Cost-based grid resolution model, ISP07 cost model, Ize et al. cost model

## Overview
The Grid Resolution Cost Model determines the optimal uniform grid subdivision factor $m$ for volume rendering by minimizing the average ray traversal time $T$ [S1]. It distinguishes itself from spatial acceleration structures like kd-trees by evaluating a single global resolution parameter rather than recursively splitting space, relying on theoretical scene models (point-based vs. line-based) to derive closed-form solutions for $m$ [S1].

## How it works
**Inputs:**
*   $N$: Total number of primitives (voxels or geometric elements) in the scene.
*   $T_{setup}$: Time for initial ray-bounding box intersection and traversal setup.
*   $T_{step}$: Time to advance from one cell to the next neighbor (without intersection checks).
*   $T_{inter}$: Time to perform a ray-primitive intersection test.
*   Scene Model Type: Point-based or Line-based.

**Outputs:**
*   Optimal subdivision factor $m$ (or $M$).

**Data Structures:**
*   The model assumes a flat uniform grid. No explicit data structure layout is defined for the grid itself in the cost derivation, only the traversal logic [S1].

**Formulas and Steps:**

1.  **Define Average Traversal Time ($T$):**
    The average time to traverse a ray through the grid is modeled as [S1]:
    $$ T = T_{setup} + m T_{step} + \mu T_{inter} $$
    Where:
    *   $m$ is the average number of cells a ray intersects.
    *   $\mu$ is the average number of primitives contained in the $m$ cells intersected by the ray.

2.  **Determine $\mu$ based on Scene Model:**
    Let $N_m$ be the total number of intersections between all primitives and all grid cells.
    *   **Point-based model:** Each primitive is contained in exactly one cell. Thus, $N_m = N$. The number of primitives per cell is $N/m^3$. The average number of primitives in the $m$ cells hit by a ray is [S1]:
        $$ \mu = \frac{N}{m^2} $$
    *   **Line-based model:** Each primitive spans approximately $m$ cells. Thus, $N_m = N \cdot m$. The average number of primitives in the $m$ cells hit by a ray is [S1]:
        $$ \mu = \frac{N}{m} $$

4.  **Sampling Interval (Guess and Check):**
    If exact scene model parameters are unknown, the optimal $m$ can be found by sampling the cost function within a theoretical bound [S1][S2, unofficial]:
    $$ m \in \left( (10N)^{1/3}, 5N^{1/2} \right) $$
    Using typical values $T_{setup} \approx 1.0$, $T_{step} \approx 0.1$, $T_{inter} \approx 0.5$, this interval is derived [S2, unofficial].

**Pseudocode:**

```python
def calculate_optimal_m(N, T_setup, T_step, T_inter, scene_model):
    """
    Calculates the optimal grid subdivision factor m.
    
    Args:
        N (int): Total number of primitives.
        T_setup (float): Initial setup time.
        T_step (float): Time to advance to neighbor cell.
        T_inter (float): Time for ray-primitive intersection.
        scene_model (str): 'point' or 'line'.
        
    Returns:
        float: Optimal subdivision factor m.
    """
    if scene_model == 'point':
        # Formula from Source [S1] Eq 1
        # Note: Source states M = sqrt(2*T_inter/T_step) * N
        # This implies linear scaling O(N) according to source text.
        m = (2 * T_inter / T_step) ** 0.5 * N
    elif scene_model == 'line':
        # Formula from Source [S1] Eq 2
        # M = cbrt((2*T_inter/T_step)^2) * N^1.5
        factor = (2 * T_inter / T_step) ** 2
        m = factor ** (1/3) * (N ** 1.5)
    else:
        raise ValueError("Scene model must be 'point' or 'line'")
        
    return m

def sample_optimal_m(N, T_setup, T_step, T_inter):
    """
    Samples the cost function within the theoretical bounds to find optimal m.
    Uses Guess and Check approach.
    """
    # Bounds from Source [S1][S2, unofficial]
    lower_bound = (10 * N) ** (1/3)
    upper_bound = 5 * (N ** 0.5)
    
    best_m = lower_bound
    min_time = float('inf')
    
    # Sample a constant number of points in the interval for linear build time
    # Source [S1] suggests sampling in a constant number of points.
    num_samples = 10 
    
    for i in range(num_samples + 1):
        m = lower_bound + (upper_bound - lower_bound) * (i / num_samples)
        
        # Calculate average number of primitives mu
        # Assuming point-based for sampling if model unknown, or average case
        # Source [S1] implies mu depends on model. 
        # If model is unknown, one might sample both or use a heuristic.
        # Here we assume point-based for the sample calculation as a baseline,
        # or we could calculate T for both and pick the best m that minimizes T.
        
        # Let's calculate T for point-based assumption
        mu_point = N / (m ** 2)
        T_point = T_setup + m * T_step + mu_point * T_inter
        
        # Let's calculate T for line-based assumption
        mu_line = N / m
        T_line = T_setup + m * T_step + mu_line * T_inter
        
        # Pick the minimum time for this m across models? 
        # Or just pick one. Source [S1] says "Commonly used models behave between".
        # For implementation, we pick the m that minimizes the worst-case or average.
        # Let's use the minimum of the two times for this m.
        T = min(T_point, T_line)
        
        if T < min_time:
            min_time = T
            best_m = m
            
    return best_m
```

## Subtopics

### Cost model for hierarchical grid building
A cost model extension that suggests a termination criteria for recursive grid subdivision [S1]. Recursion is beneficial if the cost of the hierarchical traversal is less than the cost of a flat grid traversal [S1]. The condition for recursion to introduce a benefit is [S1]:
$$ T_{setup} + m T_{step} + \mu T_{inter} > N T_{inter} $$
Where $N$ is the number of intersections without the grid. Deep recursion requires efficient indexing strategies (e.g., hash tables) to be viable [S1].

## Operating characteristics
*   **Complexity:** The closed-form solution for $m$ is $O(1)$ to compute given $N$ and timing constants. The sampling-based "Guess and Check" approach has linear overall building time relative to the number of samples, which is constant [S1].
*   **Performance:** The model assumes constant times $T_{step}$ and $T_{inter}$. Performance degrades if these assumptions fail (e.g., cache misses, variable primitive sizes).
*   **Strengths:** Simple to implement; provides theoretical bounds for search space; avoids expensive exhaustive search or SAH-like $O(N \log N)$ builds [S1].
*   **Limitations:** Requires knowledge of the scene model (point vs. line) for the closed-form solution; assumes uniform grid; does not account for spatial coherence or empty space skipping beyond the average case [S1].
*   **When to use:** When a uniform grid is required and scene statistics ($N$, primitive distribution type) are known or can be estimated.
*   **When not to use:** For highly non-uniform scenes where adaptive structures (octrees, kd-trees) are superior; when $T_{step}$ or $T_{inter}$ are not constant.

## Background
The cost model was introduced by Ize et al. in 2007 [ISP07], building on earlier work by Coveney and Witten (1988) [CW88] [S1]. It is described in surveys by Cosenza (2008) [S1] and others [S2, unofficial]. It is used in volume rendering and ray tracing to optimize grid resolution for interactive performance.
