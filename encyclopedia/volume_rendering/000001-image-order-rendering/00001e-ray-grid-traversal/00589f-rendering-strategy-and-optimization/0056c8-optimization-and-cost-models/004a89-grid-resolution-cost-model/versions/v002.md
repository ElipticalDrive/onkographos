# Grid Resolution Cost Model

Also called: Cost-based grid resolution model, ISP07 cost model, Ize et al. cost model

## Overview
The Grid Resolution Cost Model determines the optimal subdivision factor $m$ for a uniform grid in volume rendering or ray tracing by minimizing the average ray traversal time [S1][S2, unofficial]. It distinguishes itself from spatial split heuristics like the Surface Area Heuristic (SAH) used in kd-trees by evaluating the cost of a global grid resolution parameter rather than local split planes, leveraging theoretical bounds to restrict the search space for $m$ [S1].

## How it works
**Inputs:**
- $N$: Total number of primitives in the scene.
- $T_{setup}$: Time to perform the initial intersection with the main voxel bounding box and setup traversal.
- $T_{step}$: Time spent to advance from a cell to its neighbor (without checking intersection).
- $T_{inter}$: Time required to check a ray-primitive intersection.
- Scene model type: Point-based or Line-based.

**Outputs:**
- Optimal subdivision factor $M$ (or $m$).

**Data Structures:**
- No complex data structures are required for the calculation of $M$ itself; it is a scalar value derived from the parameters above.

**Method:**
The average traversal time $T$ for a ray in a flat grid is modeled as [S1][S2, unofficial]:

$$ T = T_{setup} + m T_{step} + \mu T_{inter} $$

where:
- $m$ is the average number of cells a ray traverses.
- $\mu$ is the average number of primitives contained (or partially contained) in those $m$ cells.
- $\mu = N_m / m^2$, where $N_m$ is the total number of intersections between primitives and cells for a given subdivision factor $m$ [S1][S2, unofficial].

The value of $N_m$ depends on the scene model [S1][S2, unofficial]:
1.  **Point-based model:** Each primitive is contained in exactly one cell ($N_m = N$). Consequently, $\mu = N / m^2$.
2.  **Line-based model:** Each primitive is partially contained in approximately $m$ cells ($N_m = N \cdot m$). Consequently, $\mu = N / m$ [S1][S2, unofficial].

To find the optimal $M$ that minimizes $T$, we differentiate $T$ with respect to $m$ and set the derivative to zero.

For **point-based models**:
$$ T = T_{setup} + m T_{step} + \frac{N}{m^2} T_{inter} $$
$$ \frac{dT}{dm} = T_{step} - \frac{2N T_{inter}}{m^3} = 0 \implies M = \sqrt[3]{\frac{2N T_{inter}}{T_{step}}} $$

**Parameters:**
- Typical example values: $T_{setup} \approx 1.0$, $T_{step} \approx 0.1$, $T_{inter} \approx 0.5$ [S2, unofficial].
- With these values, the search interval for $m$ is bounded by $(10N)^{1/3}$ and $5N^{1/2}$ [S2, unofficial].

**Pseudocode:**
```python
def calculate_optimal_m(N, T_setup, T_step, T_inter, model_type):
    """
    Calculates the optimal grid subdivision factor m.
    
    Args:
        N (int): Total number of primitives.
        T_setup (float): Initial setup time.
        T_step (float): Time to advance to neighbor cell.
        T_inter (float): Time for ray-primitive intersection.
        model_type (str): 'point' or 'line'.
        
    Returns:
        float: Optimal subdivision factor m.
    """
    if model_type == 'point':
        # Formula from [S1]: M = sqrt(2 * T_inter / T_step) * N
        # Note: Source [S1] explicitly provides this form.
        m = (2 * T_inter / T_step)**0.5 * N
    elif model_type == 'line':
        # Formula from [S1]: M = cbrt((2 * T_inter / T_step)^2) * N^1.5
        # Note: Source [S1] explicitly provides this form.
        ratio = 2 * T_inter / T_step
        m = (ratio**2)**(1/3) * (N**1.5)
    else:
        raise ValueError("Model type must be 'point' or 'line'")
        
    return m

def search_interval(N, T_setup, T_step, T_inter):
    """
    Returns the theoretical search interval for m based on example values 
    or general bounds if specific values are not used.
    Source [S2, unofficial] gives bounds (10N)^(1/3) to 5N^(1/2) for specific T values.
    General bounds are not explicitly defined in sources other than the optimal M itself.
    """
    # Using the specific example bounds from [S2, unofficial]
    lower = (10 * N)**(1/3)
    upper = 5 * (N**0.5)
    return lower, upper
```

**Edge Cases and Pitfalls:**
- The model assumes a flat grid. Hierarchical grids require different termination criteria [S1].
- The model requires knowledge of the scene model type (point vs. line) to select the correct formula [S1].
- Without a good indexing strategy (e.g., hash tables), deep recursion in hierarchical grids is not feasible [S1].
- The complexity of exact SAH build algorithms is $O(n \log n)$, which is considered too high for interactive purposes, motivating this cost model [S1].

## Subtopics

### [Guess and Check Building Algorithm](12809-guess-and-check-building-algorithm.md)
The Guess and Check Building Algorithm determines the optimal grid resolution parameter $m$ by sampling the cost function over a theoretically bounded interval to minimize average traversal time. It distinguishes itself from exhaustive search methods by guaranteeing linear overall building time while leveraging theoretical bounds to restrict the search space.

### Cost model for hierarchical grid building
A cost model that suggests a way to build hierarchical grids and determine a termination criteria to stop recursion [S1]. Recursion introduces a benefit in grid traversal time if $T_{setup} + m T_{step} + \mu T_{inter} > N T_{inter}$ [S1].

## Operating characteristics
- **Time Complexity:** The search for optimal $m$ using the guess-and-check approach over the bounded interval has linear overall building time $O(N)$ [S1].
- **Memory Complexity:** Not given in the sources.
- **Scaling:** For point-based models, optimal $m$ scales as $O(N)$ [S1]. For line-based models, optimal $m$ scales as $O(N^{1.5})$ [S1].
- **Strengths:** Simple to implement; provides theoretical bounds for search; faster than exact SAH ($O(n \log n)$) [S1].
- **Limitations:** Requires knowledge of the scene model type (point vs. line) [S1]; assumes uniform grid; less adaptive than hierarchical structures without additional indexing strategies [S1].
- **When to use:** When a flat grid is desired and interactive build times are required [S1].
- **When not to use:** When the scene has complex geometry distribution requiring adaptive subdivision, or when exact SAH performance is worth the build cost [S1].

## Background
The first complete cost model for grids was introduced in [CW88] [S1][S2, unofficial]. Ize et al. [ISP07] introduced a clear and simple cost model for grids, which is the primary reference for the formulas presented here [S1][S2, unofficial]. The model is used in the context of exploiting grids for ray tracing, particularly in volume rendering and general ray tracing acceleration structures [S1].
