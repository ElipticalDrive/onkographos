# 3D Siddon's Method for Intercept Matrix Calculation

Also called: Ray-Voxel Intersection Length Calculation, Siddon's Algorithm

## Overview
This method calculates the exact length of intersection between X-ray rays and voxels in a 3D grid to construct the intercept matrix $A$ for Cone Beam Computed Tomography (CBCT) reconstruction [S1, unofficial]. Unlike direct reconstruction algorithms like FDK, which bypass the explicit calculation of $A$, this approach computes $A$ to enable studies of its properties and the approximation of its inverse for volume reconstruction [S1, unofficial]. It is specifically designed for flat-panel detector cone beam geometry and relies on a parametric ray formulation to determine voxel boundaries [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `detector_plate_length` ($dl$): Number of detectors along one side of the square detector plate [S1, unofficial].
    *   `source_to_object` ($sod$): Distance from X-ray source to object center [S1, unofficial].
    *   `source_to_detector` ($sdd$): Distance from X-ray source to detector center [S1, unofficial].
    *   `pixel_size` ($ps$): Physical size of one pixel/voxel unit [S1, unofficial].
    *   `projections` ($p$): Total number of rotation angles [S1, unofficial].
    *   `resolution` ($n$): Grid resolution along all axes. The implementation assumes $n = dl$; mismatched values are not supported [S1, unofficial].
    *   `dtype`: Data type for calculations. `float32` is required; `float16` causes precision loss and distorted images [S1, unofficial].
    *   `k`: Batch size for processing X-ray rays to manage GPU memory (e.g., 100 for 16GB VRAM) [S1, unofficial].
*   **Outputs:**
    *   `intercept_lengths`: A tensor containing the intersection lengths for all rays and voxels, forming the rows of the sparse intercept matrix $A$ [S1, unofficial].

**Data Structures:**
*   **Voxel Grid:** A 3D meshgrid `X, Y, Z` of shape $(n, n, n)$, flattened into 1D tensors of shape $(1, n^3)$ [S1, unofficial]. The grid coordinates are generated from $(-n // 2) \cdot ps$ to $(n // 2) \cdot ps$ with step $ps$ [S1, unofficial].
*   **Ray Parameters:** Tensors for $\phi$ (rotation angle), $\alpha$ (detector y-coordinate index), and $\beta$ (detector x-coordinate index) [S1, unofficial]. These are stacked into `line_params_tensor` of shape $(3, \phi, \alpha, \beta)$ [S1, unofficial].
*   **Intercept Matrix:** Represented as a sparse COO tensor where indices correspond to flattened voxel coordinates and values are the calculated lengths [S1, unofficial].

**Formulas and Definitions:**
Let $\gamma = sdd$ and $\lambda = sod$. The ray is defined parametrically. The slopes and intercepts for the ray passing through a detector pixel $(\alpha, \beta)$ at rotation $\phi$ are:
$$
\begin{aligned}
\sin &= \sin(\phi) \\
\cos &= \cos(\phi) \\
m_x &= \gamma \sin - \alpha \cos \\
m_z &= \gamma \cos + \alpha \sin \\
\xi &= \lambda \sin \\
\zeta &= \lambda \cos
\end{aligned}
$$
A small epsilon ($\epsilon$) is added to denominators to prevent division by zero [S1, unofficial].

The parametric equations for the ray in terms of single variables are:
1.  $x(z) = \xi + m_x \frac{z - \zeta}{m_z + \epsilon}, \quad y(z) = -\beta \frac{z - \zeta}{m_z + \epsilon}$ [S1, unofficial].
2.  $y(x) = -\beta \frac{x - \xi}{m_x + \epsilon}, \quad z(x) = \zeta + m_z \frac{x - \xi}{m_x + \epsilon}$ [S1, unofficial].
3.  $z(y) = \zeta - m_z \frac{y}{\beta + \epsilon}, \quad x(y) = \xi - m_x \frac{y}{\beta + \epsilon}$ [S1, unofficial].

**Numbered Steps:**
1.  **Initialize Grid:** Create 1D array `a` from $(-n // 2) \cdot ps$ to $(n // 2) \cdot ps$ with step $ps$ [S1, unofficial]. Create 3D meshgrid `X, Y, Z` using `indexing='xy'` [S1, unofficial]. Flatten `X, Y, Z` into 1D tensors of shape $(1, n^3)$ [S1, unofficial].
2.  **Generate Rays:** Create detector coordinates `x` from $(-n + 1) \cdot ps$ to $n \cdot ps$ with step $2 \cdot ps$, divided by 2 [S1, unofficial]. Create meshgrid for `detector_coords` [S1, unofficial]. Stack `phis`, `alphas`, `betas` into `line_params_tensor` of shape $(3, \phi, \alpha, \beta)$ [S1, unofficial].
3.  **Compute Ray Parameters:** For each ray defined by $(\phi, \alpha, \beta)$, calculate $m_x, m_z, \xi, \zeta$ using the formulas above [S1, unofficial].
4.  **Calculate Intercepts at Voxel Boundaries:**
    *   Compute $C_1$: Absolute difference of $z$-plane intercepts at $Z$ and $Z+ps$ using `intercepts_z_plane` [S1, unofficial].
    *   Compute $C_2$: Absolute difference of $y$-plane intercepts at $Y$ and $Y+ps$ using `intercepts_y_plane` [S1, unofficial].
    *   Compute $C_3$: Absolute difference of $x$-plane intercepts at $X$ and $X+ps$ using `intercepts_x_plane` [S1, unofficial].
    *   *Note:* The implementation uses sparse masks to identify valid intersections, storing only True values to save memory [S1, unofficial].
5.  **Calculate Intercept Lengths:**
    *   Compute intermediate variable $ic = |\,|C_1 - C_2| - C_3\,|$ [S1, unofficial].
    *   Compute final lengths: $\text{intercept\_lengths} = \sqrt{ic_0^2 + ic_1^2 + ic_2^2}$ [S1, unofficial].
6.  **Memory Management:** Move results to CPU and clear GPU cache (`torch.cuda.empty_cache()`) to prevent Out-Of-Memory (OOM) errors [S1, unofficial]. Process rays in batches of size $k$ if necessary [S1, unofficial].

**Pseudocode:**
```python
import math

def calculate_intercept_lengths(dl, sod, sdd, ps, projections, resolution, k=100):
    """
    Calculates the intercept matrix rows for 3D Siddon's method.
    """
    eps = 1e-9
    n = resolution if resolution is not None else dl
    assert n == dl, "Resolution must equal detector plate length"
    assert n % 2 == 0, "Resolution must be even"
    
    # Scale parameters for precision
    lam = sod / 100.0
    gam = sdd / 100.0
    ps_val = ps / 100.0
    
    # Initialize Voxel Grid
    a = [(-n // 2) * ps_val + i * ps_val for i in range(n)]
    X_flat, Y_flat, Z_flat = [], [], []
    for x_val in a:
        for y_val in a:
            for z_val in a:
                X_flat.append(x_val)
                Y_flat.append(y_val)
                Z_flat.append(z_val)
    
    # Generate Ray Parameters
    phis = [2 * math.pi * i / projections for i in range(projections)]
    x_det = [((-n + 1) * ps_val + i * 2 * ps_val) / 2.0 for i in range(n)]
    alpha_flat, beta_flat = [], []
    for x_val in x_det:
        for y_val in x_det:
            alpha_flat.append(x_val)
            beta_flat.append(y_val)
    
    all_lengths = []
    num_rays = len(alpha_flat)
    
    # Process in batches to manage GPU memory
    for batch_start in range(0, num_rays, k):
        batch_end = min(batch_start + k, num_rays)
        batch_alphas = alpha_flat[batch_start:batch_end]
        batch_betas = beta_flat[batch_start:batch_end]
        
        for phi in phis:
            sin_p = math.sin(phi)
            cos_p = math.cos(phi)
            
            # Ray parameters for the current batch of rays at this phi
            mx = [gam * sin_p - a * cos_p for a in batch_alphas]
            mz = [gam * cos_p + a * sin_p for a in batch_alphas]
            xi = lam * sin_p
            zi = lam * cos_p
            
            # Define parametric functions
            def xy_from_z(z_vals):
                x_out = [xi + mx[i] * (z_vals[i] - zi) / (mz[i] + eps) for i in range(len(z_vals))]
                y_out = [-batch_betas[i] * (z_vals[i] - zi) / (mz[i] + eps) for i in range(len(z_vals))]
                return x_out, y_out

            def yz_from_x(x_vals):
                y_out = [-batch_betas[i] * (x_vals[i] - xi) / (mx[i] + eps) for i in range(len(x_vals))]
                z_out = [zi + mz[i] * (x_vals[i] - xi) / (mx[i] + eps) for i in range(len(x_vals))]
                return y_out, z_out

            def zx_from_y(y_vals):
                z_out = [zi - mz[i] * y_vals[i] / (batch_betas[i] + eps) for i in range(len(y_vals))]
                x_out = [xi - mx[i] * y_vals[i] / (batch_betas[i] + eps) for i in range(len(y_vals))]
                return z_out, x_out

            # Intercepts at boundaries
            # C1: absolute difference of z-plane intercepts at Z and Z+ps
            x_z1, y_z1 = xy_from_z(Z_flat)
            x_z2, y_z2 = xy_from_z([z + ps_val for z in Z_flat])
            C1 = [abs(x_z1[i] - x_z2[i]) for i in range(len(Z_flat))]
            
            # C2: absolute difference of y-plane intercepts at Y and Y+ps
            y_y1, z_y1 = yz_from_x(X_flat)
            y_y2, z_y2 = yz_from_x([x + ps_val for x in X_flat])
            C2 = [abs(y_y1[i] - y_y2[i]) for i in range(len(X_flat))]
            
            # C3: absolute difference of x-plane intercepts at X and X+ps
            z_x1, x_x1 = zx_from_y(Y_flat)
            z_x2, x_x2 = zx_from_y([y + ps_val for y in Y_flat])
            C3 = [abs(x_x1[i] - x_x2[i]) for i in range(len(Y_flat))]
            
            # Calculate Intercept Lengths
            # ic = abs(abs(C1 - C2) - C3)
            ic = [abs(abs(C1[i] - C2[i]) - C3[i]) for i in range(len(X_flat))]
            # intercept_lengths = sqrt(ic[0]^2 + ic[1]^2 + ic[2]^2)
            intercept_lengths = [math.sqrt(C1[i]**2 + C2[i]**2 + C3[i]**2) for i in range(len(X_flat))]
            
            all_lengths.extend(intercept_lengths)
            
        # Memory management: clear cache after batch
        # gc.collect() and torch.cuda.empty_cache() would go here in practice [S1, unofficial]
            
    return all_lengths
```

**Edge Cases and Pitfalls:**
*   **Precision:** `float16` must not be used; it results in bad precision and distorted images. `float32` is required [S1, unofficial].
*   **Memory:** The matrix is large and sparse. Processing all rays simultaneously can cause OOM errors. Rays must be processed in batches of size `k` (e.g., 100 for 16GB GPU) [S1, unofficial].
*   **Resolution Mismatch:** The code assumes `resolution` equals `detector_plate_length`. Different values are not supported and may cause errors [S1, unofficial].
*   **Division by Zero:** Epsilon ($\epsilon$) is added to denominators in parametric equations to handle rays parallel to coordinate planes [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The method is computationally intensive. Generating 50 rows of the matrix for a 200x200 resolution takes less than 7 hours on a single NVIDIA P100 GPU with 16 GB RAM [S1, unofficial].
*   **Memory Complexity:** High. The intercept matrix $A$ is sparse but large. Memory usage is managed by batching rays (parameter `k`) and clearing GPU cache [S1, unofficial].
*   **Strengths:** Explicitly calculates the intercept matrix $A$, allowing for analysis of its properties and approximation of its inverse ($A^{-1}d$) [S1, unofficial].
*   **Limitations:** Slow compared to direct methods like FDK. Requires significant GPU memory. Assumes square detector and equal resolution/detector length [S1, unofficial].
*   **When to use:** When the properties of the system matrix $A$ need to be studied or when using iterative reconstruction methods that require $A$ or $A^{-1}$ approximation [S1, unofficial].
*   **When not to use:** For real-time reconstruction or when direct methods like FDK are sufficient [S1, unofficial].

## Background
This method is based on Siddon's Algorithm, a classic technique for calculating ray-voxel intersections in computed tomography [S1, unofficial]. The specific implementation described is from an unofficial repository (`aakashks/CT-Reconstruction-3D`) aimed at Cone Beam CT reconstruction using a flat-panel detector [S1, unofficial]. It differs from the standard FDK algorithm by explicitly constructing the projection matrix $A$ rather than applying a filtered backprojection kernel directly [S1, unofficial].
