# Backward Projection

Also called: Backward Mapping, Backward and forward texture mapping algorithms, Backward texture mapping, Forward texture mapping, image-order algorithms

## Overview
Backward Projection (also known as Backward Mapping) is an image-order rendering technique that iterates over all pixels of the output image to determine the contributions of the volume integral to the current pixel [S2, unofficial]. It solves the problem of mapping 3D volume data to a 2D image by casting rays from the camera through each pixel into the volume, evaluating the radiative transfer equation along these paths. It is distinguished from forward mapping (object-order) algorithms, which iterate over volume primitives and project them onto the image plane, by ensuring that every output pixel is computed exactly once without requiring complex depth sorting or handling of overlapping projections [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D volume dataset $V$ (scalar or vector values), a camera model (origin $\mathbf{o}$, direction vectors $\mathmathbf{d}_{i,j}$ for each pixel $(i,j)$), and rendering parameters (step size $\Delta t$, transfer functions for opacity $\alpha$ and color $c$).
- Output: A 2D image buffer $I$ of dimensions $H \times W$.

**Data Structures:**
- Volume $V$: Stored as a 3D array or sparse structure. Access is typically via trilinear interpolation for continuous evaluation.
- Image Buffer $I$: A 2D array of size $H \times W \times C$ (where $C$ is channels, e.g., 3 for RGB).

**Steps:**
1. **Initialize Image Buffer:** Set all pixel values in $I$ to zero (or background color).
2. **Iterate Pixels:** For each pixel $(i, j)$ in the image grid:
    a. **Ray Generation:** Compute the ray origin $\mathbf{o}$ and direction $\mathbf{d}_{i,j}$ corresponding to pixel $(i, j)$ based on the camera projection matrix.
    b. **Ray Casting:** Traverse the volume along the ray. For each sample point $\mathbf{x}_k$ along the ray:
        i. **Sample Volume:** Evaluate the volume value $v_k = V(\mathbf{x}_k)$ using interpolation.
        ii. **Transfer Function:** Map $v_k$ to color $c_k$ and opacity $\alpha_k$.
        iii. **Accumulate:** Update the pixel color using front-to-back compositing:
        $$ C_{out} = C_{in} + c_k \cdot \alpha_k \cdot \prod_{m=0}^{k-1} (1 - \alpha_m) $$
        where $C_{in}$ is the accumulated color so far, and the product term represents the transmittance.
    c. **Early Termination:** If the accumulated transmittance $\prod (1 - \alpha_m)$ drops below a threshold $\epsilon$, stop sampling for this ray.
3. **Finalize:** Store the accumulated color $C_{out}$ in $I[i, j]$.

**Pseudocode:**
```python
def backward_projection(volume, camera, height, width, step_size, epsilon=1e-4):
    """
    Renders a volume using backward projection (ray casting).
    
    Args:
        volume: 3D array or callable returning interpolated values.
        camera: Object with method get_ray(i, j) returning (origin, direction).
        height: Image height.
        width: Image width.
        step_size: Distance between samples along the ray.
        epsilon: Transmittance threshold for early termination.
        
    Returns:
        image: 2D array of shape (height, width, 3) with RGB values.
    """
    image = np.zeros((height, width, 3))
    
    for i in range(height):
        for j in range(width):
            origin, direction = camera.get_ray(i, j)
            accumulated_color = np.array([0.0, 0.0, 0.0])
            transmittance = 1.0
            t = 0.0
            
            # Traverse ray until transmittance is negligible or ray exits volume
            while transmittance > epsilon:
                # Sample position
                pos = origin + t * direction
                
                # Check if pos is inside volume bounds (implementation specific)
                if not volume.is_inside(pos):
                    break
                
                # Sample volume value and apply transfer function
                # Note: volume.sample() returns (color, opacity)
                color, opacity = volume.sample(pos)
                
                # Front-to-back compositing
                weight = opacity * transmittance
                accumulated_color += color * weight
                transmittance *= (1.0 - opacity)
                
                t += step_size
                
            image[i, j] = accumulated_color
            
    return image
```

**Parameters:**
- `step_size`: Controls sampling density. Smaller values increase accuracy but reduce performance. Typical values depend on volume resolution and view distance.
- `epsilon`: Threshold for early termination. Typical value $10^{-4}$ to $10^{-6}$.

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision errors in ray traversal can cause gaps or overlaps in dense volumes.
- **Boundaries:** Ray intersection with volume bounds must be handled correctly to avoid out-of-bounds memory access.
- **Degenerate Input:** Empty volumes or volumes with zero opacity everywhere result in a black or background-colored image.

## Subtopics

### [GPU Backprojection](5843-gpu-backprojection.md)
GPU Backprojection is a rendering pass that visualizes detected scale-space blobs by generating small slices for each blob, computing weighted contributions, and blending them to form the final image, followed by normalization. It is distinct from standard ray-casting as it operates on a sparse abstraction of the volume (scale maxima) rather than the full voxel grid, decoupling the expensive scale-space computation from the frequent backprojection step. It builds on [Backward Projection](1491-backward-projection.md) [G].

### [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md)
Ray Segment Projection to Image computes the bounding segment of a ray (defined by origin and direction) that overlaps with a 2D image frame, returning the parameter range $[t_{min}, t_{max}]$ and the 2D coordinates at the entry and exit points. It solves the problem of determining which parts of a ray contribute to a specific image plane, which is a prerequisite for backward projection in volume rendering. It differs from [GPU Backprojection](5843-gpu-backprojection.md) by explicitly computing the geometric intersection bounds rather than relying on hardware rasterization or texture sampling, and from [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md) by operating in image space to define clipping bounds rather than projecting volume data onto the image.

### [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md)
Cone Beam Forward Projection with Trilinear Interpolation computes the projection of a 3D volume onto a 2D detector array for cone beam geometry by integrating voxel values along explicit source-to-detector segments. It differs from its parent [Backward Projection](1491-backward-projection.md) by performing the forward ray-cast operation, and from siblings like [GPU Backprojection](5843-gpu-backprojection.md) by accumulating values into the detector space rather than distributing them into the volume. It supports circular and helical trajectories, flat and curved detectors, and per-view source offsets.

### [Circular Integral Convolution](8507-circular-integral-convolution.md)
Circular Integral Convolution generates a blurred image from a scan by integrating ray values across all angles for each point, effectively filtering the true image with a $1/r$-weighted kernel. It serves as a pre-processing step for deconvolution-based reconstruction rather than a full reconstruction method itself.

#### Visibility Thresholding for Scale Backprojection
Visibility Thresholding for Scale Backprojection is a method to prevent scale information from being backprojected to voxels that do not correspond to the target feature (e.g., vessels), improving classification accuracy by using a visibility parameter [S4]. A voxel is determined to be not visible from the Laplacian of Gaussian (LoG) extrema if, at some point along the ray connecting the two positions, the intensity is below the threshold $\tau$. Alternatively, thresholding can be based on gradient magnitude [S4]. The parameter $\tau$ (tau) is a visibility parameter used to control the sensitivity of the visibility test, based on scalar value or gradient magnitude [S4]. This is a fast approximation; more accurate results can be obtained with a region growing approach added as a post-process based on the initial size-based classification [S4].

## Operating characteristics
Backward projection algorithms are generally memory-intensive due to the need to store the full volume dataset and the image buffer. The time complexity is proportional to the number of pixels in the output image multiplied by the average number of samples per ray, which depends on the volume depth and step size. Performance scales linearly with image resolution and volume density. Strengths include high visual quality and straightforward implementation of complex transfer functions. Limitations include high computational cost for large volumes and the inability to easily handle dynamic scenes without recomputing all rays. It is best used for static volume rendering where high fidelity is required.

## Background
Backward projection was introduced as part of early volume rendering techniques, with foundational work by Levoy (1988), Sabella (1988), and Danskin and Hanrahan (1992) [S2, unofficial]. It emerged as a standard approach for high-quality volume visualization, leveraging the efficiency of image-order processing to avoid the complexity of object-order sorting. The method has been widely adopted in medical imaging and scientific visualization.
