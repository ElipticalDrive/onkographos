# Backward Projection

Also called: Backward Mapping, Backward texture mapping, image-order algorithms

## Overview
Backward projection (also known as backward mapping or image-order rendering) is a volume rendering strategy that iterates over the output image pixels to determine their color and opacity contributions from the 3D volume data [S2, unofficial]. It solves the problem of mapping 3D volumetric information to a 2D image plane by casting rays from the camera through each pixel into the volume [S2, unofficial]. It is distinguished from forward projection methods by processing the image buffer directly, allowing for efficient early termination when a ray becomes fully opaque, a key advantage for standard absorption-based rendering [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D volume dataset $V$ (scalar or vector values), camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$ per pixel), and transfer functions for opacity $\alpha$ and color $c$.
- Output: A 2D image buffer $I$ with dimensions $H \times W$ and channels (e.g., RGB).

**Data Structures:**
- Volume $V$: Stored as a 3D array or grid. Access is typically via trilinear interpolation for non-integer coordinates.
- Image Buffer $I$: A 2D array of size $H \times W \times C$, where $C$ is the number of color channels.

**Steps:**
1. Initialize the image buffer $I$ to zero (or background color).
2. For each pixel $(i, j)$ in the image grid ($0 \le i < H, 0 \le j < W$):
    a. Compute the ray origin $\mathbf{o}_{i,j}$ and direction $\mathbf{d}_{i,j}$ based on camera projection matrices.
    b. Determine the entry and exit points of the ray with the volume bounding box. Let the parametric range be $[t_{start}, t_{end}]$.
    c. Initialize front-to-back accumulation variables: accumulated opacity $\alpha_{acc} = 0$, accumulated color $C_{acc} = (0, 0, 0)$.
    d. Sample the volume along the ray from $t_{start}$ to $t_{end}$ with step size $\Delta t$. For each sample point $\mathbf{x}(t)$:
        i. Retrieve the volume value $v = V(\mathbf{x}(t))$ using interpolation.
        ii. Compute opacity $\alpha = \alpha(v)$ and color $c = c(v)$ using transfer functions.
        iii. Update accumulation:
        $$ \beta = \alpha \cdot (1 - \alpha_{acc}) $$
        $$ C_{acc} = C_{acc} + c \cdot \beta $$
        $$ \alpha_{acc} = \alpha_{acc} + \beta $$
        iv. If $\alpha_{acc} \ge 1 - \epsilon$ (where $\epsilon$ is a small threshold, e.g., $10^{-4}$), terminate the ray early [S2, unofficial].
    e. Store the final accumulated color $C_{acc}$ in $I[i, j]$.

**Formulas:**
The standard front-to-back compositing equation for a ray is:
$$ I(\hat{x}) = \sum_{l=1}^{N} c(x_l) \alpha_l \prod_{j=1}^{l-1} (1 - \alpha_j) $$
where $c(x_l)$ is the color at sample $l$, $\alpha_l$ is the opacity at sample $l$, and $N$ is the number of samples [S2, unofficial].

**Parameters:**
- $\Delta t$: Step size along the ray. Typical values depend on volume resolution and desired quality (e.g., 1 voxel spacing or sub-voxel steps).
- $\epsilon$: Early termination threshold. Typical value: $10^{-4}$ to $10^{-2}$.

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision errors in ray marching can cause gaps or overlaps if step sizes are not aligned with voxel boundaries.
- **Boundaries:** Rays that do not intersect the volume must be handled to avoid out-of-bounds memory access.
- **Degenerate Input:** Empty volumes or volumes with zero opacity everywhere result in a black or background-colored image.

**Pseudocode:**
```python
def backward_projection(volume, camera, height, width, channels, transfer_func, step_size=1.0, epsilon=1e-4):
    """
    Perform backward projection volume rendering.
    
    Args:
        volume: 3D array of shape (D, H_v, W_v) containing scalar values.
        camera: Object with methods get_ray_origin(i, j) and get_ray_direction(i, j).
        height: Integer, height of the output image.
        width: Integer, width of the output image.
        channels: Integer, number of color channels (e.g., 3 for RGB).
        transfer_func: Function that takes a scalar value and returns (color, opacity).
        step_size: Float, step size along the ray in world units.
        epsilon: Float, threshold for early termination.
        
    Returns:
        image: 2D array of shape (height, width, channels).
    """
    image = np.zeros((height, width, channels), dtype=np.float32)
    
    for i in range(height):
        for j in range(width):
            # Get ray parameters for this pixel
            origin = camera.get_ray_origin(i, j)
            direction = camera.get_ray_direction(i, j)
            
            # Compute ray-volume intersection
            t_min, t_max = compute_ray_box_intersection(origin, direction, volume.bounds)
            
            if t_min > t_max:
                continue  # Ray does not intersect volume
            
            # Initialize accumulation
            acc_color = np.zeros(channels, dtype=np.float32)
            acc_opacity = 0.0
            
            # March along the ray
            t = t_min
            while t <= t_max:
                # Sample point in world coordinates
                point = origin + t * direction
                
                # Interpolate volume value at point
                # Note: Implementation of trilinear interpolation is assumed
                val = interpolate_volume(volume, point)
                
                # Get color and opacity from transfer function
                color, opacity = transfer_func(val)
                
                # Front-to-back compositing
                beta = opacity * (1.0 - acc_opacity)
                acc_color = acc_color + color * beta
                acc_opacity = acc_opacity + beta
                
                # Early termination
                if acc_opacity >= 1.0 - epsilon:
                    break
                
                t += step_size
            
            # Store result
            image[i, j, :] = acc_color
            
    return image
```

## Subtopics

### [GPU Backprojection](5843-gpu-backprojection.md)
GPU Backprojection is a rendering pass that visualizes detected scale-space blobs by mapping projection data back into a 3D reconstruction volume. It solves the problem of efficiently computing weighted contributions of scale-space features to image pixels by parallelizing the accumulation over the output space (voxels or pixels) on NVIDIA GPUs. It is distinguished from its siblings by its specific application to scale-space blob visualization and its implementation as a CUDA kernel that decouples the expensive scale-space computation from the frequent backprojection step, unlike [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md) which projects geometric primitives, or [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md) which performs the forward mapping.

### [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md)
This method computes the bounding segment of a ray (defined by origin and direction) that overlaps with a canonical image frame, returning the parametric $t$-range and the 2D $xy$ coordinates at the entry and exit points. It solves the problem of determining which parts of a 3D ray are visible within the 2D image plane boundaries, which is a prerequisite for subsequent rasterization or sampling in backward projection pipelines. It differs from [GPU Backprojection](5843-gpu-backprojection.md) by explicitly computing geometric bounds rather than relying on hardware rasterization, and from [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md) by operating on individual rays rather than volumetric integration.

### [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md)
Cone Beam Forward Projection computes the line integrals of a 3D volume along rays defined by a source and a 2D detector array, simulating the acquisition of projection data (sinograms) for cone-beam geometry. It differs from its sibling [GPU Backprojection](5843-gpu-backprojection.md) by integrating volume values along rays rather than distributing detector values into the volume, and from [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md) by explicitly handling the 3D-to-2D perspective projection geometry with trilinear interpolation. It is the primary forward operator for iterative reconstruction algorithms like [Differentiable Forward Projection (Mesh)](13343-differentiable-forward-projection-mesh.md) and [3D Siddon's Method for Intercept Matrix Calculation](14467-3d-siddon-s-method-for-intercept-matrix-calculation.md).

### [Circular Integral Convolution](8507-circular-integral-convolution.md)
Circular Integral Convolution generates a blurred image from a scan by integrating ray values across all angles for each point, effectively filtering the true image with a $1/r$-weighted kernel. It serves as a pre-processing step for deconvolution-based reconstruction rather than a full reconstruction method itself.

#### Visibility Thresholding for Scale Backprojection
Visibility Thresholding for Scale Backprojection is a method to prevent scale information from being backprojected to voxels that do not correspond to the target feature (e.g., vessels), improving classification accuracy by using a visibility parameter [S4]. A voxel is determined to be not visible from the Laplacian of Gaussian (LoG) extrema if, at some point along the ray connecting the two positions, the intensity is below the threshold $\tau$ [S4]. Alternatively, thresholding can be based on gradient magnitude [S4]. The parameter $\tau$ (tau) is a visibility parameter used to control the sensitivity of the visibility test, and it is a thresholding value based on scalar value or gradient magnitude [S4]. This is a fast approximation; more accurate results can be obtained with a region growing approach added as a post-process based on the initial size-based classification [S4].

## Operating characteristics
- **Time Complexity:** $O(H \cdot W \cdot N)$, where $H$ and $W$ are image dimensions and $N$ is the number of samples per ray. Early termination can reduce the average $N$.
- **Memory Complexity:** $O(H \cdot W \cdot C)$ for the image buffer, plus $O(V)$ for the volume data.
- **Measured Performance:** Performance depends heavily on the efficiency of ray-volume intersection and interpolation. Hardware-accelerated implementations (e.g., GPU) can achieve interactive frame rates for moderate resolutions [S1, unofficial].
- **Scaling:** Scales linearly with image resolution and volume depth. Parallelization is straightforward across pixels.
- **Strengths:** Simple implementation, efficient early termination for opaque regions, natural fit for hardware rasterization pipelines.
- **Limitations:** Can suffer from aliasing if step size is too large; requires careful handling of ray-volume intersections.
- **When to Use:** Standard volume rendering where visual accuracy and performance are balanced, especially when early termination is beneficial.
- **When Not to Use:** When forward projection is required (e.g., for reconstruction algorithms) or when specific geometric primitives need to be projected directly.

## Background
Backward projection, also known as backward mapping, was introduced as one of two algorithms for high-quality and efficient texture mapping featuring backward and forward processing orders [S1, unofficial]. It is based on the work of Levoy (1988), Sabella (1988), and Danskin and Hanrahan (1992) [S2, unofficial]. The method is widely used in volume rendering frameworks for its simplicity and effectiveness in producing visually accurate results [S2, unofficial].
