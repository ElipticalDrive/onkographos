# Backward Projection

Also called: Backward Mapping, Backward and forward texture mapping algorithms, Backward texture mapping, Forward texture mapping, image-order algorithms

## Overview
Backward Projection (also known as Backward Mapping or image-order algorithms) is a volume rendering strategy that iterates over all pixels of the output image and determines the contributions of the volume integral to the current pixel [S2, unofficial]. It solves the problem of mapping 3D volumetric data to a 2D image by casting rays from the camera through the volume for each pixel, yielding a simple and visually accurate mechanism for volume rendering [S2, unofficial]. It is distinguished from its siblings, such as [Front-to-Back Layer Traversal](1212-front-to-back-layer-traversal.md), by its explicit iteration over the image space (pixels) rather than the volume space (voxels) [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume dataset $V$ (scalar or vector values), a camera model (origin $\mathbf{o}$, direction $\mathbf{d}$ per pixel), and transfer functions mapping volume values to color $c$ and opacity $\alpha$ [G].
*   **Output:** A 2D image buffer $I$ with dimensions $H \times W \times C$ (where $C$ is channels, typically 3 for RGB) [G].

**Data Structures:**
*   **Volume $V$:** A 3D array of size $D_x \times D_y \times D_z$ [G]. Values are accessed via trilinear interpolation [G].
*   **Image Buffer $I$:** A 2D array of size $H \times W \times C$ [G].

**Numbered Steps:**
1.  Initialize the image buffer $I$ to zero [G].
2.  For each pixel $(i, j)$ in the image grid ($0 \le i < H, 0 \le j < W$):
    a. Compute the ray origin $\mathbf{o}_{i,j}$ and direction $\mathbf{d}_{i,j}$ from the camera model [G].
    b. Determine the entry and exit points of the ray with the volume bounding box [G]. Let the parametric range be $[t_{start}, t_{end}]$.
    c. Initialize the accumulated color $C_{acc} = (0,0,0)$ and accumulated opacity $\alpha_{acc} = 0$ [G].
    d. Iterate along the ray from $t_{start}$ to $t_{end}$ with step size $\Delta t$ (typically the voxel spacing or diagonal) [G]:
        i. Compute sample position $\mathbf{p} = \mathbf{o}_{i,j} + t \cdot \mathbf{d}_{i,j}$ [G].
        ii. Sample the volume value $v = V(\mathbf{p})$ using trilinear interpolation [G].
        iii. Map $v$ to color $c$ and opacity $\alpha$ using transfer functions [G].
        iv. Apply the front-to-back compositing equation:
            $$ C_{acc} = C_{acc} + c \cdot \alpha \cdot (1 - \alpha_{acc}) $$
            $$ \alpha_{acc} = \alpha_{acc} + \alpha \cdot (1 - \alpha_{acc}) $$
    e. Store $C_{acc}$ in $I[i, j]$ [G].

**Formulas:**
The volume rendering integral is approximated using a Riemann sum [S2, unofficial]. The compositing equation for each sample $l$ is:
$$ I(\hat{x}) = \sum_{l=1}^{L} c(x_l) \alpha_l \prod_{j=1}^{l-1} (1 - \alpha_j) $$
where $c(x_l)$ is the color and $\alpha_l$ is the opacity at sample position $x_l$ [S2, unofficial].

**Parameters:**
*   $\Delta t$: Step size. Typical value: distance between voxel centers or voxel diagonal [G].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating point precision errors in ray marching can cause gaps or overlaps if $\Delta t$ is not chosen carefully relative to voxel size [G].
*   **Boundaries:** Rays missing the volume entirely must be handled to avoid out-of-bounds memory access [G].
*   **Degenerate Input:** Empty volumes or volumes with zero opacity everywhere result in a black or background image [G].

**Pseudocode:**
```python
def backward_projection(volume, camera, height, width, channels, transfer_func, dt=1.0):
    """
    volume: 3D numpy array (Dx, Dy, Dz)
    camera: object with method get_ray(i, j) returning (origin, direction)
    height, width: int
    channels: int (e.g., 3 for RGB)
    transfer_func: function mapping scalar value to (color, alpha)
    dt: float, step size along the ray
    """
    image = np.zeros((height, width, channels), dtype=np.float32)
    Dx, Dy, Dz = volume.shape
    
    for i in range(height):
        for j in range(width):
            origin, direction = camera.get_ray(i, j)
            
            # Compute ray bounds with volume bounding box [0, Dx] x [0, Dy] x [0, Dz]
            t_min = -np.inf
            t_max = np.inf
            no_intersect = False
            for k in range(3):
                if direction[k] == 0:
                    if origin[k] < 0 or origin[k] > [Dx, Dy, Dz][k]:
                        no_intersect = True
                        break
                else:
                    t1 = (0.0 - origin[k]) / direction[k]
                    t2 = ([Dx, Dy, Dz][k] - origin[k]) / direction[k]
                    t_min = max(t_min, min(t1, t2))
                    t_max = min(t_max, max(t1, t2))
            
            if no_intersect or t_min > t_max:
                continue
                
            acc_color = np.zeros(channels)
            acc_alpha = 0.0
            t = t_min
            
            while t <= t_max:
                pos = origin + t * direction
                x, y, z = pos
                if 0 <= x < Dx and 0 <= y < Dy and 0 <= z < Dz:
                    # Trilinear interpolation
                    x0, y0, z0 = int(x), int(y), int(z)
                    x1, y1, z1 = x0 + 1, y0 + 1, z0 + 1
                    fx, fy, fz = x - x0, y - y0, z - z0
                    
                    def clamp(v, dim): return max(0, min(v, dim - 1))
                    v000 = volume[clamp(x0, Dx), clamp(y0, Dy), clamp(z0, Dz)]
                    v100 = volume[clamp(x1, Dx), clamp(y0, Dy), clamp(z0, Dz)]
                    v010 = volume[clamp(x0, Dx), clamp(y1, Dy), clamp(z0, Dz)]
                    v110 = volume[clamp(x1, Dx), clamp(y1, Dy), clamp(z0, Dz)]
                    v001 = volume[clamp(x0, Dx), clamp(y0, Dy), clamp(z1, Dz)]
                    v101 = volume[clamp(x1, Dx), clamp(y0, Dy), clamp(z1, Dz)]
                    v011 = volume[clamp(x0, Dx), clamp(y1, Dy), clamp(z1, Dz)]
                    v111 = volume[clamp(x1, Dx), clamp(y1, Dy), clamp(z1, Dz)]
                    
                    c00 = v000 * (1 - fx) + v100 * fx
                    c10 = v010 * (1 - fx) + v110 * fx
                    c01 = v001 * (1 - fx) + v101 * fx
                    c11 = v011 * (1 - fx) + v111 * fx
                    c0 = c00 * (1 - fy) + c10 * fy
                    c1 = c01 * (1 - fy) + c11 * fy
                    val = c0 * (1 - fz) + c1 * fz
                    
                    color, alpha = transfer_func(val)
                    weight = alpha * (1.0 - acc_alpha)
                    acc_color += color * weight
                    acc_alpha += weight
                
                t += dt
            
            image[i, j] = acc_color
            
    return image
```

## Subtopics

### [GPU Backprojection](5843-gpu-backprojection.md)
GPU Backprojection is a rendering pass that visualizes detected scale-space blobs by mapping projection data back into a 3D reconstruction volume. It solves the problem of efficiently computing weighted contributions of scale-space features to image pixels by parallelizing the accumulation over the output space (voxels or pixels) on NVIDIA GPUs. It is distinguished from its siblings by its specific application to scale-space blob visualization and its implementation as a CUDA kernel that decouples the expensive scale-space computation from the frequent backprojection step, unlike [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md) which projects geometric primitives, or [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md) which performs the forward mapping.

### [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md)
This method computes the bounding segment of a ray (defined by origin and direction) that overlaps with a canonical image frame, returning the parametric $t$-range and the 2D $xy$ coordinates at the entry and exit points. It solves the problem of determining which parts of a 3D ray are visible within the 2D image plane boundaries, which is a prerequisite for subsequent rasterization or sampling in backward projection pipelines. It differs from [GPU Backprojection](5843-gpu-backprojection.md) by explicitly computing geometric bounds rather than relying on hardware rasterization, and from [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md) by operating on individual rays rather than volumetric integration.

### [Cone Beam Forward Projection with Trilinear Interpolation](8247-cone-beam-forward-projection-with-trilinear-interpolation.md)
Cone Beam Forward Projection computes the line integrals of a 3D volume along rays defined by a source and a 2D detector array, simulating the acquisition of projection data (sinograms) for cone-beam geometry. It differs from its sibling [GPU Backprojection](5843-gpu-backprojection.md) by integrating volume values along rays rather than distributing detector values into the volume, and from [Ray Segment Projection to Image](7631-ray-segment-projection-to-image.md) by explicitly handling the 3D-to-2D perspective projection geometry with trilinear interpolation. It is the primary forward operator for iterative reconstruction algorithms like [Differentiable Forward Projection (Mesh)](13343-differentiable-forward-projection-mesh.md) and [3D Siddon's Method for Intercept Matrix Calculation](14467-3d-siddon-s-method-for-intercept-matrix-calculation.md).

### [Circular Integral Convolution](8507-circular-integral-convolution.md)
Circular Integral Convolution generates a blurred image from a scan by integrating ray values across all angles for each point, effectively filtering the true image with a $1/r$-weighted kernel. It serves as a pre-processing step for deconvolution-based reconstruction rather than a full reconstruction method itself.

### [Gaussian Texture Filtering via Jacobian Back-projection](16469-gaussian-texture-filtering-via-jacobian-back-projection.md)
Gaussian Texture Filtering via Jacobian Back-projection is a technique to compute the color of a screen pixel by integrating a texture signal against a Gaussian filter, where the filter is back-projected from screen space to texture space using the local affine approximation (Jacobian) of the texture mapping. It solves the problem of aliasing in texture mapping by ensuring that the frequency content of the projected texture is properly band-limited before sampling. Unlike sibling methods that may rely on pre-filtered mipmaps or simple box filters, this method explicitly models the pixel footprint as a Gaussian and adapts its shape in texture space based on the local distortion of the surface mapping.

#### Visibility Thresholding for Scale Backprojection
Visibility Thresholding for Scale Backprojection is a method to prevent scale information from being backprojected to voxels that correspond to vessels, giving a better classification of the brain [S4]. A voxel is determined to be not visible from the Laplacian of Gaussian (LoG) extrema if, at some point along the ray connecting the two positions, the intensity is below the threshold $\tau$ [S4]. Alternatively, thresholding can be based on gradient magnitude [S4]. The parameter $\tau$ (tau) is a visibility parameter used to control the sensitivity of the visibility test, based on scalar value or gradient magnitude [S4]. This is a fast approximation; more accurate results can be obtained with a region growing approach added as a post-process based on the initial size-based classification [S4].

## Operating characteristics
*   **Time Complexity:** $O(H \cdot W \cdot N)$, where $H, W$ are image dimensions and $N$ is the number of samples per ray [G].
*   **Memory Complexity:** $O(V)$ for the volume and $O(H \cdot W)$ for the image buffer [G].
*   **Measured Performance:** Performance depends heavily on the efficiency of the ray-volume intersection and interpolation [G]. The source framework achieved an average of a magnitude speedup over traditional volume rendering and obtained an interactive frame rate using shear transformations for hardware or parallel implementation [S1, unofficial].
*   **Scaling:** Scales linearly with image resolution and volume depth [G].
*   **Strengths:** Simple implementation, visually accurate [S2, unofficial].
*   **Limitations:** Can be slow for large volumes or high resolutions if not optimized. Memory bandwidth bound due to frequent volume sampling [G].
*   **When to use:** When visual accuracy is prioritized and computational resources allow for per-pixel ray casting [G].
*   **When not to use:** When real-time performance is critical for very large volumes without hardware acceleration [G].

## Background
Backward projection, also known as backward mapping, was introduced as one of the two main algorithms for high-quality and efficient texture mapping, featuring backward and forward processing orders [S1, unofficial]. It was further developed and popularized in the context of volume rendering by Levoy (1988), Sabella (1988), and Danskin and Hanrahan (1992) [S2, unofficial]. The method is fundamental to ray casting techniques in volume rendering [S2, unofficial].
