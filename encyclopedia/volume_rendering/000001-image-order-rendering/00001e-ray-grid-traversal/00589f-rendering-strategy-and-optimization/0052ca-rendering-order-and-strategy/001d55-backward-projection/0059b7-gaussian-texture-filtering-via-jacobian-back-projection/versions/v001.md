# Gaussian Texture Filtering via Jacobian Back-projection

Also called: Gaussian Back-projection, Jacobian Back-projection

## Overview
Gaussian Texture Filtering via Jacobian Back-projection is a technique to compute the color of a screen pixel by integrating a texture signal against a Gaussian filter, where the filter is back-projected from screen space to texture space using the local affine approximation (Jacobian) of the texture mapping [S1]. It solves the problem of aliasing in procedural textures and signals applied to surfaces by adapting the filter shape to the viewing condition [S1]. It sets itself apart from forward projection methods by operating in the frequency domain relationship, ensuring the filtered texture spectrum is the multiplication of the unfiltered spectrum and the filter spectrum [S1].

## How it works
**Inputs and Outputs:**
- Input: Texture coordinates $(u, v)$, screen coordinates $(x, y)$, Gaussian width $\sigma$.
- Output: Filtered texture value (or filter kernel parameters) for the pixel.

**Data Structures:**
- Jacobian Matrix $J$: A $2 \times 2$ matrix representing the local affine approximation of the mapping from image to texture coordinates [S1].
  $$
  J = \begin{bmatrix} \frac{du}{dx} & \frac{dv}{dx} \\ \frac{du}{dy} & \frac{dv}{dy} \end{bmatrix}
  $$
  [S1]

**Steps:**
1. Model each screen pixel as a small Gaussian filter in screen space [S1].
2. Estimate the local affine approximation (Jacobian) $J$ in every pixel using screen space derivatives of the texture coordinates (for rasterization) or ray differentials (for raytracing) [S1].
3. Back-project the filter in the texture domain through the view transformation and the mapping used to apply the texture onto the visible surface [S1].
4. Compute the color of the pixel as the integral of the back-projected filter multiplied by the visible portion of the texture, which evaluates the convolution between the filter and the projected texture at the pixel [S1].

**Formulas:**
The screen space Gaussian filter is defined as [S1]:
$$
f(x, y) = \frac{1}{\sigma \sqrt{2\pi}} e^{-\frac{1}{2\sigma^2}(x^2 + y^2)}
$$
where $\sigma$ is the width of the Gaussian in pixels [S1].

The corresponding filter in texture space is [S1]:
$$
f_{J^{-1}[u\ v]^T} = \frac{1}{\sigma \sqrt{2\pi}} e^{-\frac{1}{2\sigma^2} [u\ v] J^{-1} J^{-1} [u\ v]^T}
$$
where $J$ is the Jacobian of the mapping from image to texture coordinates [S1].

The frequency domain filter is [S1]:
$$
F_{J^T[f_u\ f_v]^T} = e^{-2\pi^2 \sigma^2 [f_u\ f_v] J J^T [f_u\ f_v]^T}
$$
where $[f_u\ f_v]^T$ represents the frequency vector in texture space [S1].

**Parameters:**
- $\sigma$: The width of the Gaussian filter in pixels. Typical value: 1.0 [S1].

**Edge Cases and Pitfalls:**
- The Jacobian $J$ must be invertible. If the mapping is degenerate (e.g., texture coordinates are constant across a pixel), $J$ may be singular, leading to undefined back-projection.
- Precision issues may arise when computing $J^{-1}$ for highly distorted mappings.

**Pseudocode:**
```python
def gaussian_jacobian_backprojection(u, v, du_dx, dv_dx, du_dy, dv_dy, sigma):
    """
    Computes the Gaussian filter parameters in texture space given screen-space derivatives.
    
    Args:
        u, v: Texture coordinates (relative to pixel center or similar).
        du_dx, dv_dx: Derivatives of texture coordinates with respect to x.
        du_dy, dv_dy: Derivatives of texture coordinates with respect to y.
        sigma: Width of the Gaussian filter in pixels.
        
    Returns:
        The exponent coefficient for the texture space Gaussian filter.
    """
    # Construct the Jacobian matrix J
    # J = [[du_dx, dv_dx],
    #      [du_dy, dv_dy]]
    
    # Compute the inverse of J
    det_J = du_dx * dv_dy - dv_dx * du_dy
    if abs(det_J) < 1e-9:
        # Handle degenerate case: Jacobian is singular
        # Return a default or handle as an error
        return 0.0 # Placeholder for degenerate handling
    
    inv_det_J = 1.0 / det_J
    J_inv = [
        [dv_dy * inv_det_J, -dv_dx * inv_det_J],
        [-du_dy * inv_det_J, du_dx * inv_det_J]
    ]
    
    # Compute J_inv * J_inv
    # Let A = J_inv
    # A = [[a00, a01],
    #      [a10, a11]]
    a00, a01 = J_inv[0][0], J_inv[0][1]
    a10, a11 = J_inv[1][0], J_inv[1][1]
    
    # J_inv * J_inv = [[a00*a00 + a01*a10, a00*a01 + a01*a11],
    #                  [a10*a00 + a11*a10, a10*a01 + a11*a11]]
    # We need [u v] * (J_inv * J_inv) * [u v]^T
    # Let M = J_inv * J_inv
    # M00 = a00*a00 + a01*a10
    # M01 = a00*a01 + a01*a11
    # M10 = a10*a00 + a11*a10
    # M11 = a10*a01 + a11*a11
    
    M00 = a00*a00 + a01*a10
    M01 = a00*a01 + a01*a11
    M10 = a10*a00 + a11*a10
    M11 = a10*a01 + a11*a11
    
    # Compute the quadratic form: [u v] M [u v]^T
    # = u * (M00*u + M01*v) + v * (M10*u + M11*v)
    # = M00*u^2 + (M01+M10)*u*v + M11*v^2
    
    quadratic_form = M00 * u * u + (M01 + M10) * u * v + M11 * v * v
    
    # The exponent in the texture space Gaussian is -1/(2*sigma^2) * quadratic_form
    exponent = -1.0 / (2.0 * sigma * sigma) * quadratic_form
    
    return exponent
```

## Operating characteristics
- Time Complexity: Not given in the sources.
- Memory Complexity: Not given in the sources.
- Measured Performance: Not given in the sources.
- Scaling: Not given in the sources.
- Strengths: Properly filtered textures have a spectrum that is the multiplication of the unfiltered spectrum and the filter spectrum, following the convolution theorem [S1].
- Limitations: Requires accurate estimation of the Jacobian, which can be complex for non-linear mappings [S1].
- When to use: When applying procedural textures or signals to surfaces where aliasing is a concern [S1].
- When not to use: When the texture mapping is highly degenerate or when computational resources are extremely limited [S1].

## Background
The technique was introduced in the context of procedural noise functions and texture filtering [S1]. It builds on the basics of texture filtering detailed in Heckbert [Hec89] [S1]. The method relates the filter to the spectrum of the texture, allowing for easy computation in the frequency domain [S1].
