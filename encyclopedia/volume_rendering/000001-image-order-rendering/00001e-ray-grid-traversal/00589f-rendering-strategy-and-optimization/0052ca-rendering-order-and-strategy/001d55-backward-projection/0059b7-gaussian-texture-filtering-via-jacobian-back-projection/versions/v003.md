# Gaussian Texture Filtering via Jacobian Back-projection

Also called: Back-projected Gaussian Texture Filtering, Gaussian Back-projection, Gaussian Filtering for Texture Mapping, Jacobian Back-projection

## Overview
Gaussian Texture Filtering via Jacobian Back-projection computes the color of a screen pixel by integrating a texture signal against a Gaussian filter, where the filter is back-projected from screen space to texture space using the local affine approximation (Jacobian) of the texture mapping [S1, S2]. It solves the problem of aliasing in texture mapping by explicitly modeling the pixel footprint as a Gaussian and adapting its shape in texture space based on the local distortion of the surface mapping [S1, S2]. Unlike sibling methods that rely on pre-filtered mipmaps or simple box filters, this method evaluates the convolution between the screen-space filter and the projected texture directly in the texture domain [S1, S2].

## How it works
### Inputs and Outputs
**Inputs:**
- Screen coordinates $(x, y)$ of the pixel center [S1, S2].
- Texture coordinates $(u, v)$ at the pixel center [S1, S2].
- Local derivatives of texture coordinates with respect to screen coordinates, forming the Jacobian matrix $J$ [S1, S2].
- Filter width parameter $\sigma$ in pixels [S1, S2].

**Outputs:**
- Filtered texture color value, computed as the integral of the texture signal against the back-projected Gaussian [S1, S2].

### Data Structures
The method relies on the following data structures:
1.  **Jacobian Matrix ($J$):** A $2 \times 2$ matrix representing the local affine approximation of the mapping from image coordinates to texture coordinates [S1, S2].
    $$
    J = \begin{bmatrix} \frac{du}{dx} & \frac{dv}{dx} \\ \frac{du}{dy} & \frac{dv}{dy} \end{bmatrix}
    $$
    -   $\frac{du}{dx}, \frac{dv}{dx}$: Derivatives of texture coordinates with respect to screen $x$ [S1, S2].
    -   $\frac{du}{dy}, \frac{dv}{dy}$: Derivatives of texture coordinates with respect to screen $y$ [S1, S2].
    -   In rasterization, these are computed using screen-space derivatives of texture coordinates [S1, S2].
    -   In raytracing, these are computed using ray differentials [S1, S2].

2.  **Gaussian Filter Parameters:**
    -   $\sigma$: Width of the Gaussian filter in pixels. Typical value: $\sigma = 1.0$ [S1, S2].

### Numbered Steps
1.  **Model Screen-Space Filter:** Define the Gaussian filter in screen space centered at the pixel $(x, y)$ [S1, S2]. The filter function $f(x, y)$ is defined as:
    $$
    f(x, y) = \frac{1}{2\pi\sigma^2} e^{-\frac{1}{2\sigma^2}(x^2 + y^2)}
    $$
    where $x$ and $y$ are screen coordinates relative to the pixel center, and $\sigma$ is the filter width in pixels [S1, S2]. The normalization factor is $\frac{1}{2\pi\sigma^2}$ (sources cite $\frac{1}{\sigma 2\pi}$ or $\frac{1}{\sigma^2 2\pi}$) [S1, S2].

2.  **Estimate Jacobian:** Compute the Jacobian matrix $J$ for the current pixel [S1, S2].
    -   For rasterization: Use screen-space derivatives of texture coordinates ($\frac{\partial u}{\partial x}, \frac{\partial v}{\partial x}, \frac{\partial u}{\partial y}, \frac{\partial v}{\partial y}$) [S1, S2].
    -   For raytracing: Use ray differentials to estimate the change in texture coordinates over the pixel footprint [S1, S2].

3.  **Back-Project Filter to Texture Space:** Transform the screen-space Gaussian filter into the texture domain, resulting in a distorted Gaussian [S1, S2]. The back-projected filter $f_{J^{-1}}[u, v]^T$ is defined as:
    $$
    f_{J^{-1}}[u, v]^T = \frac{1}{2\pi\sigma^2} e^{-\frac{1}{2\sigma^2} [u, v] J^{-1} J^{-1} [u, v]^T}
    $$
    where $[u, v]^T$ are texture coordinates relative to the center, and $J$ is the Jacobian of the mapping from image to texture coordinates [S1, S2]. The sources explicitly write $J^{-1} J^{-1}$ in the exponent [S1, S2].

4.  **Compute Pixel Color:** Evaluate the integral of the back-projected Gaussian filter multiplied by the visible portion of the texture [S1, S2]. This is equivalent to convolving the texture signal with the back-projected Gaussian filter [S1, S2].
    $$
    C = \int_{\text{texture}} \text{Texture}(u, v) \cdot f_{J^{-1}}[u, v]^T \, du \, dv
    $$
    In practice, this is approximated by sampling the texture at multiple points weighted by the Gaussian, or by using pre-filtered mipmaps where the mipmap level is determined by the determinant of the Jacobian [G].

5.  **Frequency Domain Alternative (Optional):** The filter can also be applied in the frequency domain [S1, S2]. The frequency domain filter is a Gaussian:
    $$
    F_{J^T}[f_u, f_v]^T = e^{-2\pi^2 \sigma^2 [f_u, f_v] J J^T [f_u, f_v]^T}
    $$
    where $[f_u, f_v]^T$ are frequency coordinates [S1, S2]. The spectrum of the properly filtered texture is the multiplication of the unfiltered spectrum and this filter spectrum [S1, S2].

### Pseudocode
```python
import math

def gaussian_texture_filtering(u, v, du_dx, dv_dx, du_dy, dv_dy, sigma):
    """
    Computes the back-projected Gaussian filter parameters for texture filtering.
    
    Args:
        u, v: Texture coordinates at the pixel center.
        du_dx, dv_dx: Derivatives of texture coordinates w.r.t screen x.
        du_dy, dv_dy: Derivatives of texture coordinates w.r.t screen y.
        sigma: Width of the Gaussian filter in pixels (typically 1.0).
        
    Returns:
        A function representing the back-projected Gaussian filter in texture space.
    """
    # Step 2: Estimate Jacobian J
    # J = [[du/dx, dv/dx],
    #      [du/dy, dv/dy]]
    a, b = du_dx, dv_dx
    c, d = du_dy, dv_dy
    det = a * d - b * c
    if det == 0.0:
        raise ValueError("Singular Jacobian")
    # J_inv = (1/det) * [[d, -b], [-c, a]]
    j_inv_00, j_inv_01 = d / det, -b / det
    j_inv_10, j_inv_11 = -c / det, a / det

    # Step 3: Back-project filter to texture space
    # M = J_inv * J_inv
    m00 = j_inv_00 * j_inv_00 + j_inv_01 * j_inv_10
    m01 = j_inv_00 * j_inv_01 + j_inv_01 * j_inv_11
    m10 = j_inv_10 * j_inv_00 + j_inv_11 * j_inv_10
    m11 = j_inv_10 * j_inv_01 + j_inv_11 * j_inv_11

    # Normalization factor
    norm_factor = 1.0 / (2.0 * math.pi * sigma * sigma)

    # Step 1 & 4: Define the filter function
    def back_projected_gaussian(u_rel, v_rel):
        # Quadratic form: [u_rel v_rel] * M * [u_rel v_rel]^T
        quadratic = (u_rel * (u_rel * m00 + v_rel * m10) +
                     v_rel * (u_rel * m01 + v_rel * m11))
        exponent = -0.5 * quadratic / (sigma * sigma)
        if exponent < -50.0:
            return 0.0
        return norm_factor * math.exp(exponent)

    return back_projected_gaussian
```

### Parameters
-   $\sigma$: The width of the Gaussian filter in pixels. Typical value: $\sigma = 1.0$ [S1, S2].

### Edge Cases and Pitfalls
-   **Singular Jacobian:** If the Jacobian matrix is singular (determinant is zero), the inverse does not exist [G]. This occurs when the texture is stretched infinitely or folded [G]. The implementation must handle this by falling back to a default filter or skipping filtering [G].
-   **Precision:** The computation of $J^{-1}$ and the quadratic form can suffer from precision issues if the Jacobian entries vary widely in magnitude [G]. Clamping the exponent is recommended to avoid underflow [G].
-   **Boundary Conditions:** The integral is over the visible portion of the texture [G]. If the texture is bounded, the filter must be truncated or the integration limits adjusted [G].

## Operating characteristics
-   **Time Complexity:** The cost depends on the number of samples taken to approximate the integral [G]. If a fixed number of samples are used, it is $O(1)$ per pixel [G]. If adaptive sampling is used, it depends on the complexity of the texture and the Jacobian [G].
-   **Memory Complexity:** $O(1)$ additional memory per pixel for storing the Jacobian and filter parameters [G].
-   **Measured Performance:** Not given in the sources.
-   **Scaling:** The method scales well with resolution if the Jacobian is computed efficiently [G]. However, accurate estimation of the Jacobian requires fine-grained derivatives [G].
-   **Strengths:** Provides high-quality anti-aliasing by explicitly modeling the pixel footprint [S1, S2]. Adapts to local distortion, reducing aliasing in stretched or compressed regions [S1, S2].
-   **Limitations:** Requires computation of derivatives (Jacobian), which can be expensive in raytracing [G]. The Gaussian approximation may not be optimal for all textures [G].
-   **When not to use:** When performance is critical and lower-quality filtering (e.g., bilinear filtering) is acceptable [G].

## Background
The method originates from the work of Heckbert [Hec89] and is discussed in detail in surveys of procedural noise functions and texture filtering [S1, S2]. It is based on the convolution theorem, which states that convolution in the spatial domain corresponds to multiplication in the frequency domain [S1, S2]. The technique is widely used in computer graphics for texture mapping to reduce aliasing artifacts [S1, S2].
