# CUDA Backprojection Implementation
Also called: CUDA Core Implementation, CUDA Parallelization Strategy
## Overview
This method implements the backprojection step of differentiable X-ray computed tomography on NVIDIA GPUs using CUDA [S1, unofficial][S2, unofficial]. It efficiently maps projection data into a 3D reconstruction volume by parallelizing computation over the output space (reconstruction voxels) [S1, unofficial][S2, unofficial]. It is distinguished from CPU implementations by its use of 3D thread blocks and 3D texture memory for input data access, and it supports both Siddon and SF projector models [S1, unofficial][S2, unofficial]. It builds on [GPU Backprojection](5843-gpu-backprojection.md).

## How it works
**Inputs and Outputs:**
*   **Input:** CT projection data stored as a contiguous 32-bit floating-point array [S1, unofficial][S2, unofficial].
*   **Output:** Reconstruction volume stored as a contiguous 32-bit floating-point array [S1, unofficial][S2, unofficial].
*   Users provide pointers to these arrays [S1, unofficial][S2, unofficial].

**Data Structures:**
*   **Projection Data:** Contiguous 1D array of `float32` values representing the 2D projection images [S1, unofficial][S2, unofficial].
*   **Reconstruction Volume:** Contiguous 1D array of `float32` values representing the 3D voxel grid [S1, unofficial][S2, unofficial].
*   **Texture Memory:** 3D texture memory is used for input data (CT projections for backprojection) [S1, unofficial][S2, unofficial].

**Parameters:**
*   **Geometry:** Three CT geometries are supported, though specific configurations are Not given in the sources [S1, unofficial][S2, unofficial].
*   **Projector Model:** Either "Siddon" or "SF" [S1, unofficial][S2, unofficial].
*   **Thread Configuration:** 3D thread blocks are used for parallelization [S1, unofficial][S2, unofficial].

**Algorithm Steps:**
1.  **Data Preparation:** If the input projection data is not already on the GPU, copy it from CPU memory to GPU global memory [S1, unofficial][S2, unofficial].
2.  **Texture Binding:** Bind the input projection data to 3D texture memory [S1, unofficial][S2, unofficial].
3.  **Kernel Launch:** Launch a CUDA kernel where computation is parallelized over the reconstruction voxels using 3D threads [S1, unofficial][S2, unofficial].
4.  **Voxel Processing:** Each thread processes its assigned voxel using the 3D texture memory for data access [S1, unofficial][S2, unofficial].
5.  **Result Retrieval:** If the output was computed on the GPU, copy the reconstruction volume back to CPU memory [S1, unofficial][S2, unofficial].

## Background
The CUDA backprojection implementation was developed as part of a differentiable forward projector for X-ray computed tomography [S1, unofficial][S2, unofficial]. It was introduced in a paper published in 2023 [S1, unofficial][S2, unofficial]. The implementation is part of a library that provides both CPU and GPU versions of forward and backprojection algorithms for three CT geometries using Siddon and SF projector models [S1, unofficial][S2, unofficial]. It integrates with PyTorch via a `Projector` class derived from `torch.nn.Module` to enable automatic differentiation [S1, unofficial].
