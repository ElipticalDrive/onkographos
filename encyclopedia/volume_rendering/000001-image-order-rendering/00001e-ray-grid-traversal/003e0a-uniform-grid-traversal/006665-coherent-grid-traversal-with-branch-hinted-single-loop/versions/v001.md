# Coherent Grid Traversal with Branch-Hinted Single Loop

Also called: Branch-Hinted Single Loop Traversal, Single-Loop Coherent Grid Traversal

## Overview
This method is a traversal algorithm for uniform grids optimized for the CELL SPU architecture, which replaces standard nested loops with a single loop to avoid branch misprediction penalties [S1, unofficial]. It differs from [Robust Grid Traversal](9923-robust-grid-traversal.md) by prioritizing branch hint compatibility over robustness, and from [Computational Space Traversal](10339-computational-space-traversal.md) by maintaining the logical slice-by-slice order of [Uniform Grid Traversal](9652-uniform-grid-traversal.md) while flattening the control flow [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A bounding frustum of rays, a uniform grid, and the axis most parallel to the frustum direction (primary axis).
*   **Output:** A sequence of grid cells intersecting the frustum, traversed outwardly from the camera.

**Data Structures:**
The grid is stored as a uniform structure. The traversal maintains state variables for the current cell coordinates $(x, y, z)$ and the boundaries of the frustum in grid space. Specific bit-packing or cell layout details are not given in the sources [S1, unofficial].

**Steps:**
1.  **Initialization:** Determine the primary axis (the axis most parallel to the frustum direction). Initialize the starting cell coordinates at the camera side of the frustum [S1, unofficial].
2.  **Single Loop Iteration:** Execute a single loop that iterates through grid cells in the same logical order as the standard 3-nested-loop structure: slice-by-slice along the primary axis, then square regions within each slice [S1, unofficial].
3.  **Branchless Condition Evaluation:** For every iteration, compute the solutions for all three potential `if/else` clauses that would normally determine the next step (e.g., moving to the next slice, moving to the next region, or terminating) [S1, unofficial].
4.  **Bitwise Selection:** Use bitwise operations to discard incorrect clause results. This avoids branching and allows the hardware to issue branch hints effectively [S1, unofficial].
5.  **Update State:** Apply the selected result to update the current cell coordinates [S1, unofficial].
6.  **Termination:** The loop continues until the final iteration is reached. The "always predicting branch" strategy is used, expecting misprediction only on the final iteration [S1, unofficial].

**Pseudocode:**
```python
def coherent_single_loop_traversal(frustum, grid, primary_axis):
    # Initialize state based on frustum and grid boundaries
    # Determine start cell (x, y, z) at the camera side
    x, y, z = get_start_cell(frustum, grid, primary_axis)
    
    # Determine loop bounds based on frustum extent
    # The loop runs for the total number of cells intersecting the frustum
    total_cells = count_intersecting_cells(frustum, grid, primary_axis)
    
    for i in range(total_cells):
        # Compute potential next states for all three logical branches
        # Branch 1: Move to next cell in current slice/region
        next_x_1, next_y_1, next_z_1 = compute_next_cell_in_region(x, y, z, primary_axis)
        
        # Branch 2: Move to next slice (if primary axis is x, this changes x)
        next_x_2, next_y_2, next_z_2 = compute_next_slice(x, y, z, primary_axis)
        
        # Branch 3: Termination condition check (returns current or sentinel)
        next_x_3, next_y_3, next_z_3 = compute_termination(x, y, z, frustum)
        
        # Determine which branch is valid for the current state
        # This logic replaces if/else with bitwise operations
        # mask_1, mask_2, mask_3 are 1 if the branch is valid, 0 otherwise
        mask_1 = is_valid_branch_1(x, y, z, primary_axis)
        mask_2 = is_valid_branch_2(x, y, z, primary_axis)
        mask_3 = is_valid_branch_3(x, y, z, frustum)
        
        # Select the correct next state using bitwise operations
        # Example: next_x = (next_x_1 & mask_1) | (next_x_2 & mask_2) | (next_x_3 & mask_3)
        # Note: The exact bitwise implementation depends on how masks are encoded
        # [G] Assuming masks are 0 or -1 (all bits set) for valid/invalid
        valid_mask_1 = mask_1 * -1
        valid_mask_2 = mask_2 * -1
        valid_mask_3 = mask_3 * -1
        
        x = (next_x_1 & valid_mask_1) | (next_x_2 & valid_mask_2) | (next_x_3 & valid_mask_3)
        y = (next_y_1 & valid_mask_1) | (next_y_2 & valid_mask_2) | (next_y_3 & valid_mask_3)
        z = (next_z_1 & valid_mask_1) | (next_z_2 & valid_mask_2) | (next_z_3 & valid_mask_3)
        
        # Process the current cell (x, y, z)
        process_cell(x, y, z, frustum, grid)
        
    return
```

**Parameters:**
*   **Branch Hint Strategy:** "Always predicting branch" [S1, unofficial].
*   **Typical Values:** Not given in the sources [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Branch Misprediction:** Standard nested loops cause pipeline stalls due to misprediction. The outer loop cannot be predicted because it calls inner loops, and the inner loop executes 1-3 iterations, making prediction strategies frequently mis-predict [S1, unofficial].
*   **Complexity:** The single-loop approach is more complex to code than nested loops [S1, unofficial].
*   **Performance:** The method is theorized to be faster on CELL architecture due to avoided misprediction, but was not tested or benchmarked in the source [S1, unofficial].

## Background
**Origin:** The algorithm was described in a paper by D. Chapman regarding high definition interactive animated ray tracing on the CELL processor [S1, unofficial].
**History:** It was developed to address the limitations of the CELL SPU's branch prediction unit, which struggled with the irregular control flow of standard nested grid traversal loops [S1, unofficial].
**Usage:** It is used in the context of efficient voxelization and ray tracing on the CELL processor [S1, unofficial].
