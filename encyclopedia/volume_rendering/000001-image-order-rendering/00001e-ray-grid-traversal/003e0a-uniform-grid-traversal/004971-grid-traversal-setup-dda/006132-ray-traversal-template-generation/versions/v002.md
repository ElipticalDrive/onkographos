# Ray Traversal Template Generation

Also called: Precomputed Ray Traversal Pattern, Ray Template Generation

## Overview
Precomputes a 3D ray traversal pattern (DDA-like) for light rays to avoid per-ray floating-point division during rendering [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Grid resolution (`edgeLen` or `_RES`), maximum traversal length (`maxlen`), and ray direction vector $(lx, ly, lz)$ [S1, unofficial].
- Output: `_rayTemplate`, a lookup table of integer voxel offsets [S1, unofficial].

**Data Structures:**
- `_rayTemplate[4096][3]`: Stores integer voxel offsets for up to 4096 steps [S1, unofficial].

**Parameters:**
- `maxlen`: Maximum number of steps, calculated as $3 \times edgeLen \times edgeLen$ [S1, unofficial].
- `epsilon`: Small value added to direction components to prevent division by zero [S1, unofficial].
- `ALMOST_EQUAL_THRESHOLD`: Threshold for float comparison, set to $0.00001f$ [S1, unofficial].

**Steps:**
1. Initialize ray direction components $lx, ly, lz$ by adding `epsilon` [S1, unofficial].
2. Determine increments $xinc, yinc, zinc$ based on the signs of the direction components [S1, unofficial].
3. Initialize the fractional position and initial distances to the next voxel boundary $t_x, t_y, t_z$. Not given in the sources.
4. Loop until `maxlen` is reached:
   a. Compute $t$ values to the next voxel boundary [S1, unofficial].
   b. Advance the coordinate along the axis with the smallest $t$ [S1, unofficial].
   c. Update the fractional position [S1, unofficial].
   d. Store the integer voxel coordinates in `_rayTemplate` [S1, unofficial].

**Pseudocode:**
```python
def generate_ray_template(edge_len, max_len, lx, ly, lz):
    epsilon = 1e-6
    lx += epsilon
    ly += epsilon
    lz += epsilon

    xinc = 1 if lx > 0 else -1
    yinc = 1 if ly > 0 else -1
    zinc = 1 if lz > 0 else -1

    # Not given in the sources: initialization of fractional position and initial t values.
    frac_x, frac_y, frac_z = 0.0, 0.0, 0.0
    inv_lx = 1.0 / lx
    inv_ly = 1.0 / ly
    inv_lz = 1.0 / lz

    t_x = (1.0 - frac_x) * inv_lx if xinc > 0 else (0.0 - frac_x) * inv_lx
    t_y = (1.0 - frac_y) * inv_ly if yinc > 0 else (0.0 - frac_y) * inv_ly
    t_z = (1.0 - frac_z) * inv_lz if zinc > 0 else (0.0 - frac_z) * inv_lz

    ray_template = [[0, 0, 0] for _ in range(max_len)]
    voxel_x, voxel_y, voxel_z = 0, 0, 0

    for i in range(max_len):
        # Compute t values to next voxel boundary (maintained incrementally)
        # Advance coordinate with smallest t
        if t_x <= t_y and t_x <= t_z:
            voxel_x += xinc
            t_x += inv_lx
            ray_template[i] = [xinc, 0, 0]
        elif t_y <= t_x and t_y <= t_z:
            voxel_y += yinc
            t_y += inv_ly
            ray_template[i] = [0, yinc, 0]
        else:
            voxel_z += zinc
            t_z += inv_lz
            ray_template[i] = [0, 0, zinc]

        # Update fractional position
        frac_x = frac_x + xinc
        frac_y = frac_y + yinc
        frac_z = frac_z + zinc

    return ray_template
```

**Edge Cases and Pitfalls:**
- The `ALMOST_EQUAL` macro uses a threshold of $0.00001f$ for float comparison, which may cause jitter or missed steps in degenerate cases [S1, unofficial].
- Adding `epsilon` to zero direction components prevents division by zero during traversal [S1, unofficial].

## Subtopics

### Light Ray Template Generation
Sets the light position, computes the light direction vector, and triggers ray template generation for volume ray casting [S1, unofficial]. It assigns the input position to `_lightPos`, computes `_lightDir` as the negation of `_lightPos`, and calls `GenerateRayTemplate` with the grid resolution `_RES` to prepare ray casting parameters [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(maxlen)$ for template generation, where $maxlen = 3 \times edgeLen \times edgeLen$ [S1, unofficial].
- **Memory Complexity:** $O(maxlen \times 3)$ integers for the template storage, capped at 4096 steps [S1, unofficial].
- **Performance:** Avoids per-ray floating-point division during rendering [S1, unofficial].
- **Limitations:** Fixed template size (4096 steps) may not be sufficient for very large grids or long rays [S1, unofficial]. Precision issues with the `ALMOST_EQUAL` threshold can lead to artifacts [S1, unofficial].
