# Cell-Local Ray Traversal

Also called: Accurate Ray Traversal

## Overview
Cell-Local Ray Traversal is a ray-grid traversal method that computes cell-exit points and traversal distances using a normalized coordinate system local to each cell, preventing numerical drift and angle errors that accumulate when using global or canvas coordinates [S1, unofficial]. It sets itself apart from Uniform Grid Traversal and Robust Grid Traversal by decoupling the precision of the intersection calculation from the global scale of the scene, allowing accurate traversal even with low-precision floating-point formats on mobile hardware [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray origin $p_{eye}$, ray direction $d$ (normalized), current cell-entry point $p_i$, current cell geometry (center, size, neighbor texture).
- Output: Next cell-entry point $p_{i+1}$, traversal distance $t_i$, neighbor cell index.

**Data Structures:**
- **Cell-Local Coordinate System:** Origin at cell center, cell size normalized to 1. Coordinates range from $[-0.5, 0.5]$ along each axis [S1, unofficial].
- **Neighbor Texture:** A lookup structure (e.g., 3D texture or array) mapping the exit face of the current cell to the index of the adjacent neighbor cell [S1, unofficial].

**Steps:**
1. **Transform to Local Coordinates:** Convert the global cell-entry point $p_i$ into the cell-local coordinate system. Let this be $p_i^{local} = (p_x, p_y, p_z)$ [S1, unofficial].
2. **Compute Traversal Distance:** Determine the distance $t_i$ to the nearest cell boundary in the direction of $d$. For a ray hitting the top surface (positive y-direction), the formula is:
   $$ t_i = \frac{0.5 - p_y}{d_y} $$
   where $p_y$ is the y-component of $p_i^{local}$ and $d_y$ is the y-component of $d$ [S1, unofficial]. Similar formulas apply for other faces based on the sign of $d_x, d_y, d_z$.
3. **Compute Exit Point:** Calculate the cell-exit point $p_i^0$ in the local system:
   $$ p_i^0 = p_i^{local} + t_i \cdot d $$
   Note: This addition occurs in the local coordinate space [S1, unofficial].
4. **Identify Exit Face:** Determine which face of the unit cell contains $p_i^0$. This is done by checking which coordinate of $p_i^0$ is closest to $\pm 0.5$ [S1, unofficial].
5. **Lookup Neighbor:** Use the identified exit face and the neighbor texture to find the index of the next cell $N$ (the $i+1$-th cell) [S1, unofficial].
6. **Transform to Next Cell's Local System:** Convert the global position of $p_i^0$ into the local coordinate system of the neighbor cell $N$. This involves scaling and shifting based on the neighbor's depth and location. Let the exact transformed point be $\tilde{p}_{i+1}$. The computed floating-point value is $p_{i+1} = f(\tilde{p}_{i+1})$ [S1, unofficial].
7. **Update and Repeat:** Set $p_i \leftarrow p_{i+1}$ and repeat from Step 2 until the ray accumulates full opacity or exits the canvas [S1, unofficial].

**Pseudocode:**
```python
def cell_local_traversal(ray_origin, ray_direction, current_cell, neighbor_texture):
    # Step 1: Transform entry point to local coordinates
    # Assuming current_cell provides center and size, and a function to_local(p)
    p_local = current_cell.to_local(ray_origin) # Returns vector in [-0.5, 0.5]
    
    # Step 2 & 3: Compute traversal distance and exit point
    # Determine which face is hit first
    # For simplicity, assuming we know the face or compute min t for all 6 faces
    # Here we show the top face (positive Y) example from source
    if ray_direction.y > 0:
        t = (0.5 - p_local.y) / ray_direction.y
    elif ray_direction.y < 0:
        t = (-0.5 - p_local.y) / ray_direction.y
    else:
        # Parallel to Y axis, handle X or Z next (omitted for brevity, logic is symmetric)
        t = float('inf')
        
    p_exit_local = p_local + t * ray_direction
    
    # Step 4: Identify exit face
    # Find which component is closest to +/- 0.5
    abs_x = abs(p_exit_local.x)
    abs_y = abs(p_exit_local.y)
    abs_z = abs(p_exit_local.z)
    
    max_abs = max(abs_x, abs_y, abs_z)
    
    if max_abs == abs_x:
        face = 'X' if p_exit_local.x > 0 else '-X'
    elif max_abs == abs_y:
        face = 'Y' if p_exit_local.y > 0 else '-Y'
    else:
        face = 'Z' if p_exit_local.z > 0 else '-Z'
        
    # Step 5: Lookup neighbor
    next_cell_index = neighbor_texture.lookup(current_cell.index, face)
    next_cell = get_cell_by_index(next_cell_index)
    
    # Step 6: Transform exit point to next cell's local system
    # Convert p_exit_local back to global, then to next_cell's local
    p_exit_global = current_cell.to_global(p_exit_local)
    p_next_local = next_cell.to_local(p_exit_global)
    
    # Step 7: Return next cell and entry point
    return next_cell, p_next_local
```

**Parameters:**
- Machine epsilon $\epsilon$: Depends on precision. For single precision, $\epsilon = 2^{-23}$ [S1, unofficial]. For half precision, $\epsilon = 1/1024$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Global Coordinates:** Using global coordinates for exit point calculation leads to high inaccuracy due to large variations in cell sizes and space coverage, causing ray drift [S1, unofficial].
- **Parallel Rays:** If a ray is parallel to a grid axis (e.g., $d_y = 0$), the division in the traversal distance formula becomes undefined. The algorithm must check for zero components and prioritize other axes [S1, unofficial].
- **Precision Limits:** While robust, extremely long rays may still accumulate small errors, though the angle error bound remains constant [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of cells traversed. Each step involves constant-time arithmetic and a texture lookup.
- **Memory Complexity:** $O(1)$ per ray, plus the storage for the neighbor texture and cell hierarchy.
- **Performance:** Enables ray-casting on mobile GPUs using half-precision floats ($\epsilon = 1/1024$) without significant visual artifacts [S1, unofficial].
- **Strengths:** Eliminates ray drift and large angle errors associated with global coordinates. Accuracy is independent of zoom level or global coordinate magnitude [S1, unofficial].
- **Limitations:** Requires transformation to and from local coordinates for each cell, adding computational overhead compared to simple DDA in uniform grids. Requires neighbor texture lookups.
- **When to Use:** Large volumetric scenes with varying cell sizes (e.g., octrees, deep trees) where global precision is insufficient or where mobile/low-precision hardware is used [S1, unofficial].
- **When Not to Use:** Simple uniform grids with small bounds where global coordinates fit within high-precision ranges without drift.

## Background
Cell-Local Ray Traversal was introduced in the CanvoX system for high-resolution VR painting in large volumetric canvases [S1, unofficial]. It addresses the limitations of standard ray traversal methods in deep octree structures where cell sizes vary significantly and global coordinates can span large ranges, leading to floating-point precision issues [S1, unofficial]. The method was demonstrated on an Nvidia GTX 980Ti GPU and HTC Vive, showing that accurate ray-casting is feasible even with half-precision floats on mobile GPUs [S1, unofficial].
