# Cell-Local Ray Traversal

Also called: Accurate Ray Traversal

## Overview
Cell-Local Ray Traversal is a ray-grid traversal method that computes cell-exit points and traversal distances using a normalized coordinate system local to each cell, preventing numerical drift and angle errors that accumulate when using global or canvas coordinates [S1, unofficial]. It sets itself apart from Uniform Grid Traversal and Robust Grid Traversal by decoupling the precision of the intersection calculation from the global scale of the scene, allowing accurate traversal even with low-precision floating-point formats on mobile hardware [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray direction $d$, current cell-entry point $p_i$ in global coordinates, current cell geometry (center, size), and a neighbor texture mapping exit faces to neighbor indices [S1, unofficial].
- Output: Next cell-entry point $p_{i+1}^0$ in the neighbor's local coordinate system, and the neighbor cell index [S1, unofficial].

**Data Structures:**
- **Cell-Local Coordinate System:** Origin at cell center, cell size normalized to 1, coordinates range from $[-0.5, 0.5]$ along each axis [S1, unofficial].
- **Neighbor Texture:** A lookup structure mapping the exit face of the current cell to the index of the adjacent neighbor cell [S1, unofficial].

**Steps:**
1. Transform the global cell-entry point $p_i$ into the cell-local coordinate system, yielding $p_i^{local} = (p_x, p_y, p_z)$ [S1, unofficial].
2. Compute the cell-traversal distance $t_i$ and the cell-exit point $p_i^0$ in local coordinates, and identify the neighboring cell $N$ containing $p_i^0$ [S1, unofficial].
3. Find the face containing $p_i^0$ with respect to the cell coordinate system [S1, unofficial].
4. Use the intersecting face and the neighbor texture to choose the neighbor cell (the $i+1$-th cell) to visit [S1, unofficial].
5. Update $p_i^0$ to $p_{i+1}^0$, the entry point for the next cell in its local coordinate system [S1, unofficial].
6. Repeat until the ray accumulates full opacity or exits the canvas [S1, unofficial].

**Formulas:**
- Cell-traversal distance for the top surface (positive y-direction): $t_i = (0.5 - p_y) / d_y$, where $p_y$ is the y-component of $p_i^{local}$ and $d_y$ is the y-component of $d$ [S1, unofficial].
- Floating-point representation error model: $f(x + y) = (x + y)(1 + \epsilon_+)$, with $\epsilon_+ \le \epsilon$ [S1, unofficial].
- Error in computed exit point: $f(p_i^0) = (p_i + t_i)(1 + 3\epsilon_p)$, for some $\epsilon_p \le \epsilon$ [S1, unofficial].
- Error in next cell entry point: $p_{i+1} = ((p_i + t_i)s + c)(1 + 5\epsilon_i)$, where $s$ and $c$ are scale and shift factors depending on depth and location, and $\epsilon_i \le \epsilon$ [S1, unofficial].
- Total error bound: $e_{total} \le e_0 + 7.5 \epsilon L$, where $e_0$ is the initial eye location error and $L$ is ray length [S1, unofficial].
- Ray angle error bound: $\sin^{-1}(\sqrt{2(e_0/L + 7.5\epsilon)})$, which does not increase as a function of $L$ [S1, unofficial].

**Pseudocode:**
```python
def cell_local_traversal(ray_direction, p_i_global, cell_center, cell_size, neighbor_texture):
    # Step 1: Transform to local coordinates (origin at center, size normalized to 1)
    p_local = (p_i_global - cell_center) / cell_size
    
    # Step 2 & 3: Compute traversal distance and exit point, identify exit face
    # Compute t for each axis, handle zero direction components
    t_x = (0.5 - p_local.x) / ray_direction.x if ray_direction.x != 0 else float('inf')
    t_x_neg = (-0.5 - p_local.x) / ray_direction.x if ray_direction.x != 0 else float('inf')
    t_y = (0.5 - p_local.y) / ray_direction.y if ray_direction.y != 0 else float('inf')
    t_y_neg = (-0.5 - p_local.y) / ray_direction.y if ray_direction.y != 0 else float('inf')
    t_z = (0.5 - p_local.z) / ray_direction.z if ray_direction.z != 0 else float('inf')
    t_z_neg = (-0.5 - p_local.z) / ray_direction.z if ray_direction.z != 0 else float('inf')
    
    # Find minimum positive t and corresponding face
    t_candidates = [
        (t_x, 'X'), (t_x_neg, '-X'),
        (t_y, 'Y'), (t_y_neg, '-Y'),
        (t_z, 'Z'), (t_z_neg, '-Z')
    ]
    t_i, face = min((t, f) for t, f in t_candidates if t >= 0)
    
    p_exit_local = p_local + t_i * ray_direction
    
    # Step 4: Lookup neighbor using face
    next_cell_index = neighbor_texture[face]
    
    # Step 5: Transform exit point to next cell's local system
    # Convert exit point to global, then to next cell's local coordinates
    p_exit_global = cell_center + cell_size * p_exit_local
    # Neighbor geometry (center, size) must be fetched from the hierarchy; 
    # exact scale/shift depends on depth and location [G]
    # p_next_local = (p_exit_global - neighbor_center) / neighbor_size
    # For self-contained pseudocode, we assume neighbor geometry is available:
    neighbor_center, neighbor_size = get_neighbor_geometry(next_cell_index)
    p_next_local = (p_exit_global - neighbor_center) / neighbor_size
    
    return next_cell_index, p_next_local
```

**Parameters:**
- Machine epsilon $\epsilon$: $2^{-23}$ for single precision, $1/1024$ for half precision [S1, unofficial].

**Edge Cases and Pitfalls:**
- Global coordinates cause high inaccuracy and ray drift due to large cell size variations and space coverage [S1, unofficial].
- Parallel rays ($d_x=0$, etc.) require skipping the division for that axis and checking other axes [G].
- Precision limits: The angle error bound remains constant regardless of ray length $L$, preventing cumulative drift [S1, unofficial].

## Operating characteristics
- Time complexity: Not given in the sources.
- Memory complexity: Not given in the sources.
- Measured performance: Maximum ray-angle error of $7.5 \times 10^{-9}$ degrees and position error of $2.5 \times 10^{-7}$ in L2 norm [S1, unofficial]. Enables ray-casting on mobile GPUs with half-precision floats ($\epsilon = 1/1024$) [S1, unofficial].
- Strengths: Eliminates ray drift and large angle errors from global coordinates; accuracy is independent of zoom level or global coordinate magnitude [S1, unofficial].
- Limitations: Requires coordinate transformations and neighbor texture lookups per cell [S1, unofficial].
- When to use: Large volumetric scenes with varying cell sizes (e.g., deep octrees) where global coordinates cause precision loss, or on mobile/low-precision hardware [S1, unofficial].
- When not to use: Not given in the sources.

## Background
Cell-Local Ray Traversal was introduced in the CanvoX system for high-resolution VR painting in large volumetric canvases [S1, unofficial]. It addresses floating-point precision issues in deep octree structures where cell sizes vary significantly and global coordinates span large ranges [S1, unofficial]. The method was demonstrated on an Nvidia GTX 980Ti GPU and HTC Vive, showing that accurate ray-casting is feasible even with half-precision floats on mobile GPUs [S1, unofficial].
