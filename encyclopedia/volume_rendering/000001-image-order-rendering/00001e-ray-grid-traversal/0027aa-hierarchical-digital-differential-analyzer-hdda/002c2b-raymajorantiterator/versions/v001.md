# RayMajorantIterator

Also called: HDDA-based ray traversal for volume majorant

## Overview
The `RayMajorantIterator` is an iterator that traverses a sparse volume grid using a Hybrid Digital Differential Analyzer (HDDA) to step through voxels or leaves, computing the maximum density (majorant) for each segment where the majorant remains constant [S1, unofficial]. It solves the problem of efficiently determining integration segments for volume path tracing by avoiding per-voxel sampling in empty or uniform regions [S1, unofficial]. It builds on [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by bundling consecutive steps with identical majorants into single segments, reducing overhead compared to standard voxel DDA which cannot skip inactive nodes or handle variable leaf sizes efficiently [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A ray (`RayT`), a grid accessor (`const GridT::AccessorType&`), and an optional debug buffer (`std::vector<DDAStep>*`).
- **Output:** A sequence of `Segment` structs, each containing start time `t0`, end time `t1`, and the constant majorant density `d_maj` for that segment.

**Data Structures:**
The iterator maintains the following state fields [S1, unofficial]:
- `float m_scale`: Inverse of the ray direction length in index space, calculated as `1 / ray.dir().length()`.
- `RayT m_ray`: The ray object (typically `nanovdb::math::Ray<float>`).
- `float m_majorant`: The current segment's majorant density, initialized to `std::numeric_limits<float>::signaling_NaN()`.
- `const GridT::AccessorType& m_acc`: Reference to the grid accessor for probing values.
- `nanovdb::math::HDDA<RayT> m_dda`: The HDDA instance managing the traversal step.
- `std::vector<DDAStep>* m_step_record_dst`: Pointer to a debug buffer for recording step details.

The `Segment` struct returned by the iterator contains [S1, unofficial]:
- `float t0`: Start time in voxel units.
- `float t1`: End time in voxel units.
- `float d_maj`: Majorant density value for the segment.

The `DDAStep` struct (used for debugging) contains [S1, unofficial]:
- `int dim`: HDDA dimension stepped.
- `float majorant`: Current majorant.
- `float t`: Current time.
- `Eigen::Vector3i voxel`: Current voxel coordinates.
- `Eigen::Vector3f hit`: World position.

**Algorithm Steps:**

1.  **Initialization:**
    - Calculate `m_scale = 1.0f / m_ray.dir().length()`.
    - Initialize `m_majorant` to `std::numeric_limits<float>::signaling_NaN()`.
    - Initialize `m_dda` with the ray and an initial dimension. The initial dimension is determined by `get_hdda_dim`, which returns `std::max<uint32_t>(8, acc.getDim(ijk, ray))`. This ensures a minimum step dimension of 8 to avoid skipping active leaves [S1, unofficial].

2.  **Iteration (`next()` method):**
    - **Termination Check:** If `m_dda.time() >= m_dda.maxTime()`, the ray has left the bounding box. Return `std::nullopt` (or equivalent end-of-sequence indicator) [S1, unofficial].
    - **Start Time:** Set `ans.t0 = m_dda.time()` [S1, unofficial].
    - **Majorant Update:** If `m_majorant` is `NaN`, call `update_current_majorant()` and `record_step()` [S1, unofficial].
    - **Dimension Update:** Calculate the new HDDA dimension for the next step. The coordinate used is `m_ray(m_dda.time() + 1.0001f).floor()`. The offset `1.0001f` ensures the coordinate is slightly ahead of the current step to get the correct dimension for the next step, preventing issues with pessimistic HDDA stepping in empty space [S1, unofficial]. Update `m_dda` with `m_dda.update(m_ray, new_dim)` [S1, unofficial].
    - **Loop for Constant Majorant:**
        - Call `update_current_majorant()` and `record_step()` [S1, unofficial].
        - If the new `m_majorant` equals `ans.d_maj` (the majorant of the current segment), continue the loop to bundle this step into the current segment.
        - If `m_majorant` differs, exit the loop.
    - **End Time:** Set `ans.t1 = m_dda.time()` [S1, unofficial].
    - **Return:** Return the `Segment` struct with `t0`, `t1`, and `d_maj` [S1, unofficial].

3.  **Majorant Calculation (`update_current_majorant()`):**
    - Determine the current voxel index `ijk` from the HDDA state.
    - If the current node is not a leaf, attempt to probe the value using `m_acc.probeValue(ijk, value)`.
    - If `probeValue` returns true, set `m_majorant = value` and return.
    - Otherwise, set `m_majorant = 0.0f` (empty space) [S1, unofficial].

**Pseudocode:**

```python
import math
import numpy as np
from typing import Optional, Tuple, List

class RayMajorantIterator:
    def __init__(self, ray, accessor, debug_buffer: Optional[List] = None):
        """
        Initialize the iterator.
        :param ray: Ray object with dir() and time(t) methods.
        :param accessor: Grid accessor with getDim(ijk, ray) and probeValue(ijk, value) methods.
        :param debug_buffer: Optional list to record DDAStep details.
        """
        self.m_ray = ray
        self.m_acc = accessor
        self.m_step_record_dst = debug_buffer
        
        # m_scale: inverse of ray direction length in index space
        self.m_scale = 1.0 / np.linalg.norm(ray.dir())
        
        # m_majorant: current segment majorant, initialized to NaN
        self.m_majorant = float('nan')
        
        # Initialize HDDA
        # Initial dimension calculation
        ijk_initial = ray.time(0).floor().astype(int)
        init_dim = self._get_hdda_dim(ijk_initial, ray, accessor)
        self.m_dda = HDDA(ray, init_dim)

    def _get_hdda_dim(self, ijk, ray, accessor):
        """
        Returns the HDDA dimension for the given voxel.
        Ensures minimum dimension of 8.
        """
        dim = accessor.getDim(ijk, ray)
        return max(8, dim)

    def _update_current_majorant(self):
        """
        Updates m_majorant based on the current voxel.
        """
        # Get current voxel from HDDA state
        ijk = self.m_dda.get_voxel_index()
        
        # Try to probe value
        value = 0.0
        is_leaf = True # Placeholder for actual leaf check logic
        if not is_leaf:
            # probeValue returns (success, value)
            success, value = self.m_acc.probeValue(ijk)
            if success:
                self.m_majorant = value
                return
        
        # If not a leaf or probe failed, set to 0
        self.m_majorant = 0.0

    def _record_step(self):
        """
        Records step details to debug buffer if enabled.
        """
        if self.m_step_record_dst is not None:
            step = DDAStep(
                dim=self.m_dda.get_dim(),
                majorant=self.m_majorant,
                t=self.m_dda.time(),
                voxel=self.m_dda.get_voxel_index(),
                hit=self.m_ray.time(self.m_dda.time())
            )
            self.m_step_record_dst.append(step)

    def next(self) -> Optional[Tuple[float, float, float]]:
        """
        Returns the next segment (t0, t1, d_maj) or None if ray is out of bounds.
        """
        # Check if ray has left the bounding box
        if self.m_dda.time() >= self.m_dda.max_time():
            return None

        ans_t0 = self.m_dda.time()
        
        # If majorant is NaN, initialize it
        if math.isnan(self.m_majorant):
            self._update_current_majorant()
            self._record_step()

        # Loop to bundle segments with the same majorant
        current_majorant = self.m_majorant
        
        while True:
            # Update HDDA dimension for the next step
            # Use time + 1.0001f to ensure coordinate is slightly ahead
            next_time_approx = self.m_dda.time() + 1.0001
            ijk_next = self.m_ray.time(next_time_approx).floor().astype(int)
            new_dim = self._get_hdda_dim(ijk_next, self.m_ray, self.m_acc)
            
            # Update HDDA
            self.m_dda.update(self.m_ray, new_dim)
            
            # Update majorant for the new position
            self._update_current_majorant()
            self._record_step()
            
            # If majorant changed, break the loop
            if self.m_majorant != current_majorant:
                break
            
            # If majorant is same, continue to next step
            # Check if we are still within bounds for the next step
            if self.m_dda.time() >= self.m_dda.max_time():
                break

        ans_t1 = self.m_dda.time()
        ans_d_maj = current_majorant
        
        return (ans_t0, ans_t1, ans_d_maj)

class HDDA:
    """
    Simplified HDDA implementation for pseudocode clarity.
    In reality, this is nanovdb::math::HDDA.
    """
    def __init__(self, ray, dim):
        self.ray = ray
        self.dim = dim
        self.current_time = 0.0
        self.max_time = 1000.0 # Placeholder for actual bounding box max time
        
    def time(self):
        return self.current_time
        
    def max_time(self):
        return self.max_time
        
    def update(self, ray, dim):
        # Advance ray by one step in the grid
        # The exact logic depends on the HDDA implementation
        # Here we simulate a step
        self.current_time += 1.0 / np.linalg.norm(ray.dir())
        self.dim = dim
        
    def get_voxel_index(self):
        # Return voxel index based on current time
        pos = self.ray.time(self.current_time)
        return pos.floor().astype(int)
        
    def get_dim(self):
        return self.dim

class DDAStep:
    def __init__(self, dim, majorant, t, voxel, hit):
        self.dim = dim
        self.majorant = majorant
        self.t = t
        self.voxel = voxel
        self.hit = hit
```

**Parameters and Typical Values:**
- **Minimum HDDA Dimension:** 8. This is hardcoded to avoid skipping active leaves in sparse grids [S1, unofficial].
- **Time Offset for Dimension Update:** `1.0001f`. This small epsilon ensures the coordinate used for dimension lookup is slightly ahead of the current step, handling pessimistic HDDA stepping in empty space [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Pessimistic HDDA Stepping:** HDDA stepping can be pessimistic in empty space, potentially stepping more frequently than necessary. The iterator mitigates this by bundling consecutive segments with the same majorant into one, reducing overhead [S1, unofficial].
- **Boundary Conditions:** The termination check `m_dda.time() >= m_dda.maxTime()` handles the case where the ray leaves the bounding box [S1, unofficial].
- **Precision:** The use of `1.0001f` offset is critical for correct dimension updates. Using `1.0f` might result in the same voxel being queried, leading to incorrect dimension updates or infinite loops in degenerate cases [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The iterator steps through the grid using HDDA, which allows skipping inactive nodes. The complexity is proportional to the number of distinct majorant segments along the ray, which is typically much less than the number of voxels intersected, especially in sparse or uniform regions [S1, unofficial].
- **Memory Complexity:** The iterator maintains a small constant amount of state per ray (HDDA state, current majorant, etc.). The debug buffer, if used, scales with the number of steps.
- **Strengths:** Efficiently handles sparse voxel grids by skipping empty space and variable leaf sizes. Bundling segments with the same majorant reduces the number of integration steps required for volume path tracing [S1, unofficial].
- **Limitations:** HDDA stepping can be pessimistic in empty space, although this is mitigated by segment bundling. The method relies on the underlying HDDA implementation's correctness and efficiency [S1, unofficial].
- **When to Use:** Ideal for volume path tracing in sparse voxel grids where empty space is common and majorant values are constant over large segments.
- **When Not to Use:** If the volume is dense and majorant values change frequently per voxel, the overhead of HDDA and segment bundling might not provide significant benefits over standard voxel DDA.

## Background
The `RayMajorantIterator` is part of the volume path tracer developed by Shibodd [S1, unofficial]. It leverages the NanoVDB library's HDDA implementation for efficient hierarchical traversal. The method was designed to optimize volume rendering by reducing the number of samples required for accurate integration, particularly in large, sparse scenes.
