# Hierarchical Digital Differential Analyzer (HDDA)

Also called: Hierarchical DDA, Multi-resolution leapfrogging

## Overview

Hierarchical Digital Differential Analyzer (HDDA) is a ray traversal algorithm specialized for sparse, hierarchical volume data structures, specifically the VDB (Volumetric Data Base) family [S1, unofficial][S5]. It extends the standard Digital Differential Analyzer (DDA) by performing "multi-resolution leapfrogging," allowing rays to skip empty space by jumping between grid nodes of varying resolutions (tiles, internal nodes, and leaves) rather than stepping voxel-by-voxel [S2, unofficial][S5]. Unlike standard DDA which uses a fixed step size, HDDA adapts its step size to the current tree level, leveraging the B+tree structure of VDB to minimize traversal overhead [S1, unofficial][S4]. It is primarily used for efficient empty-space ray marching in volume rendering and narrow-band level set intersection [S1, unofficial][S5].

## How it works

HDDA operates by maintaining a state machine that tracks the ray's progress through the hierarchical grid. The core mechanism is a DDA loop where the step size (`mDim`) corresponds to the dimension of the current node or voxel being traversed. When the ray exits the current node's bounds, the algorithm detects the change in resolution and updates the DDA state to the child level [S3, S7, unofficial].

### Inputs and Outputs

**Inputs:**
*   **Ray:** Defined by origin $\mathbf{o}$, direction $\mathbf{d}$, inverse direction $\mathbf{i} = 1/\mathbf{d}$, and time bounds $[t_{min}, t_{max}]$ [S3, unofficial].
*   **Grid:** A VDB structure with a fixed compile-time tree configuration (e.g., Root $\to$ InternalNode2 $\to$ InternalNode1 $\to$ Leaf) [S1, unofficial][S5].
*   **Dimension ($dim$):** The size of the current traversal unit (e.g., $2^{Log2Dim}$). For leaves, $dim=1$; for internal nodes, $dim > 1$ [S3, unofficial].

**Outputs:**
*   A sequence of intersected nodes/voxels in front-to-back order [S6, unofficial].
*   The time $t$ and index coordinates $\mathbf{ijk}$ of each intersection [S3, unofficial].

### Data Structures

The HDDA state is maintained in a class/struct with the following fields [S3, S7, unofficial]:

*   `mDim` (int32_t): The dimension size of the current node/voxel level.
*   `mT0` (RealT): The current ray parameter (time) at the entry of the current cell.
*   `mT1` (RealT): The maximum ray parameter (exit bound).
*   `mVoxel` (CoordT): The integer index coordinates of the current node/voxel origin.
*   `mStep` (CoordT): The step direction (+1, -1, or 0) for each axis.
*   `mDelta` (Vec3T): The time delta to traverse one `mDim` unit in each axis.
*   `mNext` (Vec3T): The time to the next boundary crossing for each axis.

### Initialization

The algorithm initializes the DDA state for a specific dimension `dim` [S3, S7, unofficial]:

1.  Set `mDim = dim`, `mT0 = startTime`, `mT1 = maxTime`.
2.  Compute the starting voxel index aligned to the grid level:
    $$ \mathbf{mVoxel} = \lfloor \mathbf{pos} \rfloor \ \& \ \sim(\mathbf{dim} - 1) $$
    where $\mathbf{pos} = \mathbf{o} + t_{min} \mathbf{d}$ is the ray origin in world space, and `&` / `~` are bitwise AND and NOT operations [S3, unofficial].
3.  For each axis $k \in \{x, y, z\}$:
    *   If $d_k = 0$:
        $$ mStep_k = 0, \quad mNext_k = \infty $$
    *   Else if $i_k > 0$ (ray moves in positive direction):
        $$ mStep_k = 1 $$
        $$ mNext_k = t_{min} + (mVoxel_k + dim - pos_k) \cdot i_k $$
        $$ mDelta_k = i_k $$
    *   Else ($i_k < 0$, ray moves in negative direction):
        $$ mStep_k = -1 $$
        $$ mNext_k = t_{min} + (mVoxel_k - pos_k) \cdot i_k $$
        $$ mDelta_k = -i_k $$

### Traversal Loop

The core loop advances the ray through the hierarchy [S3, S7, unofficial]:

1.  **Find Axis:** Identify the axis $k$ with the minimum next boundary time:
    $$ k = \arg\min(mNext_x, mNext_y, mNext_z) $$
2.  **Step:** Advance the ray to the next boundary [S3, unofficial]:
    *   **Round-off Correction:** If `ENFORCE_FORWARD_STEPPING` is enabled and $mNext_k \le mT0$, apply correction to prevent infinite loops due to floating-point drift:
        $$ mNext_k \leftarrow mNext_k + mT0 - 0.999999 \cdot mNext_k + 1.0 \times 10^{-6} $$
    *   Update time: $mT0 \leftarrow mNext_k$.
    *   Update boundary: $mNext_k \leftarrow mNext_k + mDim \cdot mDelta_k$.
    *   Update index: $mVoxel_k \leftarrow mVoxel_k + mDim \cdot mStep_k$.
3.  **Check Level Change:** If the current voxel index $\mathbf{mVoxel}$ has changed relative to the previous level's bounds, or if the ray has exited the current node, the algorithm must descend to the child level [S3, S7, unofficial].
    *   Compute the new child dimension (e.g., from 32 to 16).
    *   Call `update(ray, new_dim)`:
        *   Clamp `mVoxel` to the valid range of the parent node.
        *   Recompute `mNext` and `mDelta` for the new `mDim` based on the current `mT0` and position [S3, unofficial].
4.  **Query:** Check if the child node is active (non-empty) using the node's mask [S6, unofficial]. If active, process the node; if empty, skip to the next step.
5.  **Termination:** Stop if $mT0 > mT1$ or if a maximum step count is exceeded [S2, S8, unofficial].

### Pseudocode

```python
class HDDA:
    def __init__(self):
        self.mDim = 0
        self.mT0 = 0.0
        self.mT1 = 0.0
        self.mVoxel = [0, 0, 0]
        self.mStep = [0, 0, 0]
        self.mDelta = [0.0, 0.0, 0.0]
        self.mNext = [0.0, 0.0, 0.0]

    def init(self, ray_origin, ray_dir, ray_inv_dir, t_min, t_max, dim):
        self.mDim = dim
        self.mT0 = t_min
        self.mT1 = t_max
        
        # Current position in world space
        pos = ray_origin + t_min * ray_dir
        
        # Align voxel index to grid level
        # Bitwise AND with ~(dim - 1) floors to the nearest multiple of dim
        self.mVoxel = [floor(p) & ~(dim - 1) for p in pos]
        
        for axis in range(3):
            if ray_dir[axis] == 0:
                self.mStep[axis] = 0
                self.mNext[axis] = float('inf')
                self.mDelta[axis] = 0
            elif ray_inv_dir[axis] > 0:
                self.mStep[axis] = 1
                # Distance to next boundary in positive direction
                self.mNext[axis] = t_min + (self.mVoxel[axis] + dim - pos[axis]) * ray_inv_dir[axis]
                self.mDelta[axis] = ray_inv_dir[axis]
            else:
                self.mStep[axis] = -1
                # Distance to next boundary in negative direction
                self.mNext[axis] = t_min + (self.mVoxel[axis] - pos[axis]) * ray_inv_dir[axis]
                self.mDelta[axis] = -ray_inv_dir[axis]

    def step(self):
        # Find axis with minimum next time
        axis = argmin(self.mNext)
        
        # Round-off correction to prevent backward stepping
        if self.mNext[axis] <= self.mT0:
            self.mNext[axis] += self.mT0 - 0.999999 * self.mNext[axis] + 1.0e-6
        
        # Advance
        self.mT0 = self.mNext[axis]
        self.mNext[axis] += self.mDim * self.mDelta[axis]
        self.mVoxel[axis] += self.mDim * self.mStep[axis]
        
        return self.mT0 <= self.mT1

    def update(self, ray_origin, ray_dir, ray_inv_dir, dim):
        if self.mDim == dim:
            return False
        
        # Clamp voxel to parent bounds
        voxel_max = (self.mVoxel + (self.mDim - 1)) & ~(dim - 1)
        voxel_min = self.mVoxel & ~(dim - 1)
        
        self.mDim = dim
        pos = ray_origin + self.mT0 * ray_dir
        self.mVoxel = [floor(p) & ~(dim - 1) for p in pos]
        
        # Clamp to valid range
        for axis in range(3):
            self.mVoxel[axis] = max(voxel_min[axis], min(self.mVoxel[axis], voxel_max[axis]))
            
        for axis in range(3):
            if self.mStep[axis] == 0:
                continue
            self.mNext[axis] = self.mT0 + (self.mVoxel[axis] - pos[axis]) * ray_inv_dir[axis]
            if self.mStep[axis] > 0:
                self.mNext[axis] += dim * ray_inv_dir[axis]
                
        return True
```

### Edge Cases and Pitfalls

*   **Zero Direction Components:** If $d_k = 0$, the ray never crosses a boundary in that axis. The algorithm sets $mStep_k = 0$ and $mNext_k = \infty$ to disable traversal in that dimension [S7, unofficial].
*   **Floating-Point Precision:** Round-off errors can cause the ray to step backward or stall. The `ENFORCE_FORWARD_STEPPING` macro enables a correction term ($mNext_k \leftarrow mNext_k + mT0 - 0.999999 mNext_k + 10^{-6}$) to ensure forward progress [S3, S7, unofficial].
*   **Non-Linear Transforms:** HDDA assumes rays are linear in index space. For grids with non-linear transforms (e.g., camera frustum warping), rays are not straight in index space, breaking the DDA assumption. The solution is to construct an auxiliary VDB with a linear transform to act as a mask for active values [S1, unofficial][S5].
*   **Self-Intersection:** To prevent the ray from re-hitting the same voxel it just left, a small offset ($4 \times 10^{-4} \times \text{step} \times \text{mask}$) is added to the position after each step [S2, unofficial].
*   **Out of Bounds:** The algorithm checks if the absolute position exceeds the grid bounds (e.g., 4096 units) to handle rays escaping the volume [S2, unofficial].

## Subtopics

### [OpenVDB DDA](2149-openvdb-dda.md)
OpenVDB DDA is a Digital Differential Analyzer traversal algorithm specialized for OpenVDB grids, conceptually similar to Bresenham's line algorithm applied to a 3D ray intersecting OpenVDB nodes or voxels. It iterates through grid elements intersected by a ray using a fixed step-size defined by the template parameter `Log2Dim`. Unlike Hierarchical DDA (HDDA) which uses variable step-sizes to skip empty space, OpenVDB DDA marches through every node or voxel boundary along the ray path. It handles hierarchical traversal where `Log2Dim = 0` corresponds to a voxel and `Log2Dim > 0` corresponds to a tree node of size $2^{Log2Dim}$.

### NanoVolumeHDDA
NanoVolumeHDDA is an iterator that traverses a `NanoGrid` along a ray to yield merged active spans $(t_0, t_1)$ without heap allocations, using a callback interface [S1, unofficial]. It merges adjacent active leaves and tiles to eliminate seam artifacts at 8-voxel tile edges [S1, unofficial]. It builds on [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by operating specifically on the `NanoGrid` structure and optimizing for zero-allocation iteration [S1, unofficial].

### [RayMajorantIterator](5199-raymajorantiterator.md)
The `RayMajorantIterator` is an iterator that traverses a sparse volume grid using a Hybrid Digital Differential Analyzer (HDDA) to step through voxels or leaves, computing the maximum density (majorant) for each segment where the majorant remains constant. It solves the problem of efficiently determining integration segments for volume path tracing by avoiding per-voxel sampling in empty or uniform regions. It builds on [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) by bundling consecutive steps with identical majorants into single segments, reducing overhead compared to standard voxel DDA which cannot skip inactive nodes or handle variable leaf sizes efficiently.

### [HDDA Hybrid](5201-hdda-hybrid.md)
HDDA Hybrid is a ray traversal algorithm for sparse voxel grids that combines hierarchical skipping with fine-grained traversal. It uses Hierarchical Digital Differential Analyzer (HDDA) to skip empty tiles at resolutions coarser than the leaf level, and switches to standard Digital Differential Analyzer (DDA) to traverse occupied tiles voxel-by-voxel. This approach avoids per-voxel checks in empty space while maintaining sampling accuracy in dense regions. It builds on [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md).

### HDDA Branch
A ray traversal algorithm using HDDA that samples every tile/voxel, branching based on occupancy [S9, unofficial]. It initializes ray bounds and HDDA, then loops: if the current voxel is active, it records samples and advances; if not active, it skips time. It updates the HDDA state and dimension at each step [S9, unofficial].

### Teardown Hierarchical Traversal
A hierarchical traversal method that uses DDA within a level and switches levels by rescaling the grid so the new level becomes a level 0 grid, restarting the DDA algorithm [S10, unofficial]. It calculates ray position using $pos = \lfloor (O + t \cdot D) / 2^{level} \rfloor$. Pitfalls include floating-point issues causing outliers in depth/normal buffers and rays traversing corners, causing normal problems [S10, unofficial].

### Distance LOD
Reduces traversal granularity for distant objects to save performance while maintaining surface color [S11, unofficial]. Beyond 400 voxels, the DDA terminates at brick granularity, and shading uses the brick's topmost solid material [S11, unofficial].

## Operating characteristics

*   **Time Complexity:** $O(N_{active})$, where $N_{active}$ is the number of active nodes/voxels intersected by the ray. It is significantly faster than voxel-by-voxel DDA for sparse volumes because it skips empty space at multiple resolution levels [S1, unofficial][S5].
*   **Memory Complexity:** $O(1)$ per ray, as the state is maintained in a small struct. The VDB structure itself is stored in memory, but HDDA does not require additional large buffers [S3, S7, unofficial].
*   **Performance:** In Unity HDRP, HDDA rendered a WDAS cloud dataset at 1920x1080 in 6 ms on an RTX 3080 [S8, unofficial].
*   **Strengths:** Efficient empty-space skipping, minimal interpolation overhead, compile-time optimization via template meta-programming [S1, unofficial][S5].
*   **Limitations:** Requires VDB-compatible data structures. Non-linear transforms require auxiliary grids [S1, unofficial][S5]. Precision issues require careful handling of floating-point errors [S3, S7, unofficial].

## Background

HDDA was introduced by Ken Museth in the context of the VDB (Volumetric Data Base) data structure, initially presented in "VDB: High-resolution sparse volumes with dynamic topology" (ACM Trans. Graph. 2013) and further detailed in "Hierarchical Digital Differential Analyzer" (SIGGRAPH 2014) [S1, unofficial][S5]. It was developed to address the inefficiency of standard DDA in sparse, hierarchical volumes by leveraging the B+tree structure of VDB. The algorithm has been implemented in OpenVDB and NanoVDB, and is used in various graphics applications, including volume rendering, level set intersection, and real-time rendering in game engines like Unity [S1, unofficial][S5][S8, unofficial].
