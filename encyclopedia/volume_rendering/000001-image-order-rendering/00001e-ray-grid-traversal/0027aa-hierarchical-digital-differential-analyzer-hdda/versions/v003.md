# Hierarchical Digital Differential Analyzer (HDDA)

Also called: HDDA Tree Marcher, Hierarchical DDA, NanoVDB Ray Marching with HDDA Acceleration, Unity NanoVDB Volume Renderer

## Overview
The Hierarchical Digital Differential Analyzer (HDDA) is a specialized ray traversal algorithm for sparse voxel grids (specifically VDB structures) that performs multi-resolution leapfrogging to efficiently determine intersected voxels or tiles [S1, unofficial][S2]. It leverages the compile-time fixed tree configuration of VDB to inline and collapse the hierarchical navigation, minimizing vertical tree traversal overhead [S1, unofficial][S2]. Unlike standard DDA which steps voxel-by-voxel, HDDA leaps across empty space and traverses multiple resolution levels in a single pass, making it ideal for real-time volume rendering of large sparse datasets [S1, unofficial][S2]. It builds on [Hierarchical Traversal](896-hierarchical-traversal.md) by specializing the traversal logic for the B+tree topology of VDB.

## How it works
**Inputs:**
- A VDB grid (or NanoVDB buffer) containing sparse voxel data.
- A ray defined by origin $\mathbf{o}$, direction $\mathbf{d}$, near clip $t_{min}$, and far clip $t_{max}$.
- Grid transformation matrix (linear or non-linear).

**Outputs:**
- A sequence of hit distances and corresponding voxel values (density/scattering coefficient) along the ray, in front-to-back order.

**Data Structures:**
- **Ray:** Struct containing `origin` (float3), `direction` (float3), `tmin` (float), `tmax` (float) [S3, unofficial].
- **Grid Handle:** Reference to the root of the VDB tree [S3, unofficial].
- **Accessor:** Read accessor initialized with the root handle to access voxel values [S3, unofficial].
- **Auxiliary Binary Grid (for non-linear transforms):** A compact binary grid (1 bit per voxel) with linear transform, used as a mask for active values in frustum-warped volumes [S1, unofficial][S2].

**Algorithm Steps:**

1.  **Initialization:**
    - Read grid type from buffer offset `PNANOVDB_GRID_OFF_GRID_TYPE` [S3, unofficial].
    - Get tree handle from grid and root handle from tree [S3, unofficial].
    - Initialize read accessor with root [S3, unofficial].
    - If the grid has a non-linear transform (e.g., warped to camera frustum), construct an auxiliary VDB with a linear transform [S1, unofficial][S2]. This is done by concurrent resampling of the density grid with the frustum transform onto a binary grid with a linear transform [S1, unofficial][S2]. The auxiliary grid uses lower voxel resolution and single-bit encoding for compactness [S2]. Perform fast bit-wise topological dilation on this binary grid to account for interpolation kernel size [S1, unofficial][S2].

2.  **HDDA Hit Detection (Leapfrogging):**
    - Call `pnanovdb_hdda_tree_marcher` with grid type, buffer, accessor, ray origin, `tmin`, ray direction, and `tmax` [S3, unofficial].
    - The HDDA algorithm internally performs multi-resolution leapfrogging:
        - It determines the current resolution level based on the ray's position and the grid's hierarchy.
        - It calculates the step size in world space corresponding to the current tile/voxel size.
        - It advances the ray parameter $t$ by this step size, effectively "leaping" over empty space or entire tiles.
        - It checks for intersections at the new $t$. If an intersection is found, it returns the hit distance $t_{hit}$ and the value at that hit [S1, unofficial][S2].
    - Update `ray.tmin` to $t_{hit}$ if a hit is found. If no hit is found within `tmax`, the traversal ends for this ray segment [S3, unofficial].

3.  **Ray Marching Loop (for Volume Rendering):**
    - Initialize `transmittance = 1.0`, `acc_density = 0.0`, `direct_light = 0.0`, `ambient_light = 0.005` [S3, unofficial].
    - Loop while `step < _RayMarchSamples` (e.g., max steps) [S3, unofficial]:
        - **Termination Check:** If `ray.tmin >= ray.tmax`, break [S3, unofficial].
        - **Space Skipping (Dimension Check):**
            - Calculate sample position `pos` from `ray.tmin` [S3, unofficial].
            - Get dimension `dim` using `get_dim_coord` (likely checking if the sample is on a grid boundary or in empty space) [S3, unofficial].
            - If `dim > 1`, increment `step`, add `skip_step` (e.g., 15) to `ray.tmin`, set `skip = 15`, and continue [S3, unofficial].
        - **Space Skipping (Density Check):**
            - Sample density $\sigma_S$ at `pos` [S3, unofficial].
            - If $\sigma_S < MIN\_DENSITY$ (e.g., 0.01), increment `step`, add `skip_step` (e.g., 5) to `ray.tmin`, set `skip = 5`, and continue [S3, unofficial].
        - **Backtracking:**
            - If `skip > 0`, subtract `skip * 0.8` from `ray.tmin` to refine the position [S3, unofficial].
            - Recalculate `pos` [S3, unofficial].
            - Reset `skip = 0` [S3, unofficial].
        - **Accumulation:**
            - Add $\sigma_S$ to `acc_density` [S3, unofficial].
            - Calculate scattered light $S = \sigma_S \times phase\_function() \times volumetric\_shadow\_2(pos, acc, ray.direction)$ [S3, unofficial].
            - Calculate integrated scattering $S_{int} = \frac{S - S \cdot e^{-\sigma_E \cdot step\_size}}{\sigma_E}$ [S3, unofficial].
                - Note: $\sigma_E$ is the extinction coefficient. To prevent division by zero, ensure $\sigma_E \ge 0.000001$ via `max(0.000001, sigmaS)` [S3, unofficial].
            - Add `transmittance * S_int` to `direct_light` [S3, unofficial].
            - Update `transmittance *= exp(-\sigma_E * step_size)` [S3, unofficial].
        - **Step Increment:**
            - Increment `step` [S3, unofficial].
            - Add `step_size` (e.g., 0.57) to `ray.tmin` [S3, unofficial].

4.  **Final Color Calculation:**
    - If `_VisualizeSteps` is 1, return a blue-to-red gradient based on step count ratio [S3, unofficial].
    - Otherwise, `final_color = (direct_light + ambient_light) * acc_density` [S3, unofficial].
    - Apply gamma correction: `final_color = pow(final_color, 1.0 / 2.2)` [S3, unofficial].
    - Return `float4(final_color, acc_density)` [S3, unofficial].

**Shadow Ray Calculation (`volumetric_shadow_2`):**
- Initialize `shadow = 1.0`, `step_size = 1.0`, `jitter = 0` [S3, unofficial].
- Loop 10 times:
    - Calculate `sample_pos = pos + (jitter + step_size) * light_dir` [S3, unofficial].
    - Get $\sigma_E$ at `sample_pos` [S3, unofficial].
    - Multiply $\sigma_E$ by 0.3 [S3, unofficial].
    - Update `shadow *= exp(-\sigma_E * step_size)` [S3, unofficial].
    - Increment `step` [S3, unofficial].
    - Update `step_size *= (2 + random_float(sample_pos))` [S3, unofficial].
- Return `shadow` [S3, unofficial].

**Pseudocode:**

```python
def hdda_traverse(grid, ray):
    """
    Performs multi-resolution leapfrogging to find hit distance and value.
    Returns (t_hit, value) or (None, None) if no hit.
    """
    # Initialize accessor with grid root
    accessor = init_accessor(grid.root)
    
    # HDDA internal state
    current_t = ray.tmin
    current_level = grid.root_level
    
    while current_t < ray.tmax:
        # Determine step size based on current resolution level
        # In VDB, this corresponds to the tile/voxel size at the current level
        step_size = get_step_size_for_level(current_level)
        
        # Leapfrog: advance ray by step size
        next_t = current_t + step_size
        
        # Check if next_t is within bounds and if there is data at next_t
        # This involves checking the tree structure to see if the ray intersects
        # any active nodes at the current or child levels
        if is_active_at_t(grid, accessor, next_t):
            value = sample_value(grid, accessor, next_t)
            return next_t, value
        
        # If no active data, we might need to adjust level or continue leapfrogging
        # The HDDA algorithm optimizes this by skipping empty regions entirely
        # For simplicity, we assume the HDDA implementation handles the skipping
        # and returns the next hit or None
        current_t = next_t
        
    return None, None

def ray_march_volume(grid, ray, params):
    transmittance = 1.0
    acc_density = 0.0
    direct_light = 0.0
    ambient_light = 0.005
    step = 0
    skip = 0
    
    while step < params._RayMarchSamples:
        if ray.tmin >= ray.tmax:
            break
            
        # Space Skipping (Dimension Check)
        pos = ray.origin + ray.direction * ray.tmin
        dim = get_dim_coord(pos)
        if dim > 1:
            step += 1
            ray.tmin += 15
            skip = 15
            continue
            
        # Space Skipping (Density Check)
        sigma_S = sample_density(grid, pos)
        if sigma_S < params.MIN_DENSITY:
            step += 1
            ray.tmin += 5
            skip = 5
            continue
            
        # Backtracking
        if skip > 0:
            ray.tmin -= skip * 0.8
            pos = ray.origin + ray.direction * ray.tmin
            skip = 0
            
        # Accumulation
        acc_density += sigma_S
        sigma_E = max(0.000001, sigma_S) # Prevent division by zero
        S = sigma_S * phase_function() * volumetric_shadow_2(pos, acc_density, ray.direction)
        S_int = (S - S * exp(-sigma_E * params.step_size)) / sigma_E
        direct_light += transmittance * S_int
        transmittance *= exp(-sigma_E * params.step_size)
        
        # Step Increment
        step += 1
        ray.tmin += params.step_size
        
    final_color = (direct_light + ambient_light) * acc_density
    final_color = pow(final_color, 1.0 / 2.2)
    return float4(final_color, acc_density)

def volumetric_shadow_2(pos, acc_density, ray_direction):
    shadow = 1.0
    step_size = 1.0
    jitter = 0.0
    for _ in range(10):
        sample_pos = pos + (jitter + step_size) * light_dir
        sigma_E = sample_density(grid, sample_pos) * 0.3
        shadow *= exp(-sigma_E * step_size)
        step_size *= (2 + random_float(sample_pos))
    return shadow
```

## Subtopics

### [NanoVolumeHDDA](3125-nanovolumehdda.md)
A span-merging hierarchical DDA iterator over a NanoGrid that yields TimeSpan structs representing merged active regions along a ray in front-to-back order. It merges adjacent active leaves and tiles to eliminate seam artifacts at 8-voxel tile edges.

## Operating characteristics
- **Time Complexity:** The HDDA traversal is $O(k)$ where $k$ is the number of active tiles/voxels intersected by the ray, rather than $O(n)$ where $n$ is the total number of voxels. The leapfrogging skips empty space efficiently [S1, unofficial][S2].
- **Memory Complexity:** The VDB structure uses a B+tree, which is memory-efficient for sparse data. The auxiliary binary grid for non-linear transforms adds minimal overhead due to single-bit encoding [S1, unofficial][S2].
- **Measured Performance:** Tested on RTX 3080 rendering WDAS cloud dataset at 1920x1080 in 6 ms using Unity HDRP [S3, unofficial].
- **Strengths:**
    - Highly efficient for sparse volumes with large empty regions [S1, unofficial][S2].
    - Compile-time optimization reduces overhead [S1, unofficial][S2].
    - Handles non-linear transforms via auxiliary grids [S1, unofficial][S2].
- **Limitations:**
    - Requires VDB or compatible hierarchical structure [S1, unofficial][S2].
    - Non-linear transforms require additional preprocessing (auxiliary grid generation) [S1, unofficial][S2].
    - Shadow ray calculation can be expensive if not optimized [S3, unofficial].
- **When to Use:** Real-time volume rendering of large sparse datasets (e.g., clouds, smoke) where performance is critical [S3, unofficial].
- **When Not to Use:** Dense volumes where the overhead of tree traversal outweighs the benefits of leapfrogging [S1, unofficial].

## Background
The HDDA was introduced by Ken Museth in the context of the VDB (Volume Database) library, specifically in OpenVDB v2 [S1, unofficial][S2]. It was designed to address the inefficiencies of standard DDA ray marching for sparse voxel grids by leveraging the hierarchical structure of VDB [S1, unofficial][S2]. The algorithm was originally developed for rendering narrow-band level set surfaces and density volumes like clouds [S1, unofficial][S2]. It has since been adapted for use in real-time engines like Unity, particularly with the NanoVDB format [S3, unofficial].
