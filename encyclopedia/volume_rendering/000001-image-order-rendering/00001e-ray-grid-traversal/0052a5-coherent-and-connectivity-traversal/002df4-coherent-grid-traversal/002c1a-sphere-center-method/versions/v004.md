# Sphere-Center Method

Also called: Sphere-center grid

## Overview
The Sphere-Center Method is an optimization for glyph-based particle visualization within the Coherent Grid Traversal (CGT) framework that eliminates data duplication and redundant intersection tests by storing each particle in exactly one grid cell [S1, S2]. It achieves this by traversing an enlarged frustum that accounts for the maximum particle radius, ensuring that any sphere intersecting the original view volume has its center contained within the traversal bounds [S1, S2]. Unlike standard grid approaches that require mailboxes or reference lists to handle primitives overlapping multiple cells, this method guarantees single storage and single intersection per particle [S1, S2].

## How it works
The method exploits the property that particle radii are either uniform or fall within a well-defined range [S2]. By using the maximum radius across all particles, the algorithm constructs a frustum large enough to contain the centers of all potentially intersecting spheres, thereby allowing a simple "center-in-cell" storage scheme [S1, S2].

### Inputs and Outputs
*   **Inputs:**
    *   Particle dataset: A collection of spheres defined by center coordinates $(x, y, z)$ and radius $r$ [S2].
    *   Ray packet frustum $F$: Defined by bounding planes and near/far clipping planes [S1, S2].
    *   Grid resolution: Determines the cell size in world units [G].
*   **Outputs:**
    *   A grid structure where each sphere is stored in exactly one cell [S2].
    *   An enlarged frustum $F_r$ used for traversal [S1, S2].

### Data Structures
*   **Grid:** A multi-level grid structure (as defined in [Coherent Grid Traversal](2987-coherent-grid-traversal.md)).
*   **Cell Content:** Each cell stores a list of particle indices or direct particle data [S1]. Unlike standard grids, no duplicate entries or mailbox structures are required [S1, S2].
*   **Particle Storage:** Particles are stored directly in the finest level of the grid [S1]. The conversion from floating-point center coordinates to grid cell indices is performed via truncation [S1].

### Parameters
*   $r_{max}$: The maximum radius across all particles in the dataset. This value is determined once during initialization and cached for subsequent build and traversal steps [S1].
*   $dU$: The direction vector component of the normal to a bounding plane of the frustum [S2].

### Steps

1.  **Initialization:**
    *   Compute $r_{max}$ by iterating over all particles and finding the maximum radius [S1, S2].
    *   Cache $r_{max}$ for use in grid construction and traversal [S1].

2.  **Grid Construction:**
    *   For each particle with center $C = (x, y, z)$, compute its grid cell coordinates by truncating the floating-point values of its center in the grid coordinate space to integers [S1].
    *   Store the particle in the list of the identified cell [S1, S2].
    *   This process replaces expensive primitive/cell or bounding box/cell overlap tests with a single float-to-int truncation per particle [S1].

3.  **Frustum Enlargement:**
    *   Compute the shift distance $s$ for the side bounding planes of the frustum [S2]. The distance $s$ is calculated based on $r_{max}$ and the plane normal direction $dU$:
        $$s = r_{max} \sqrt{1 + dU^2}$$
    *   Derivation: The condition that a sphere of radius $r_{max}$ intersects a bounding plane defined by normal direction $dU$ is equivalent to the sphere's center being within distance $r_{max}$ of the plane [S1, S2]. Geometrically, this requires shifting the plane by $s$ such that the projection of the shift vector onto the normal equals $r_{max}$ [S1]. The scalar projection formula yields $r_{max} = \frac{\langle -dU, 1 \rangle \cdot \langle 0, s \rangle}{|\langle -dU, 1 \rangle|}$, which solves to $s = r_{max} \sqrt{1 + dU^2}$ [S1, S2].
    *   Adjust the bounding planes: Add $s$ to the $u_0$ parameter for the maximum bounding plane and subtract $s$ for the minimum bounding plane [S1, S2].
    *   Adjust the near and far planes: Shift the near plane by $r_{max}$ in the $-\mathbf{K}$ direction and the far plane by $r_{max}$ in the $+\mathbf{K}$ direction, where $\mathbf{K}$ is the viewing direction [S1, S2].
    *   The resulting structure is the enlarged frustum $F_r$ [S1, S2].

4.  **Traversal:**
    *   Traverse the grid using the enlarged frustum $F_r$ instead of the original frustum $F$ [S1, S2].
    *   For each cell visited, intersect the rays in the packet against all spheres stored in that cell [S1, S2].
    *   Because the frustum is enlarged by $r_{max}$, any sphere intersecting the original frustum $F$ is guaranteed to have its center inside $F_r$ [S1, S2]. Thus, intersecting only spheres whose centers are in the visited cells covers all potential intersections [S1, S2].

5.  **Early Ray Termination:**
    *   Adjust early ray termination criteria to account for spheres whose centers lie in the next slice but whose geometry extends into the current slice due to the enlarged frustum [S2].

### Pseudocode

```python
import math

def ray_sphere_intersect(ray_o, ray_d, sphere_c, radius):
    """Standard ray-sphere intersection check."""
    oc = [ray_o[i] - sphere_c[i] for i in range(3)]
    a = sum(ray_d[i] * ray_d[i] for i in range(3))
    b = sum(oc[i] * ray_d[i] for i in range(3))
    c = sum(oc[i] * oc[i] for i in range(3)) - radius * radius
    return b * b - a * c >= 0

def sphere_center_build(particles, frustum_planes, frustum_near, frustum_far, view_dir, cell_size):
    r_max = max(p.radius for p in particles)
    grid = {}
    for i, p in enumerate(particles):
        gx = int(p.center[0] / cell_size)
        gy = int(p.center[1] / cell_size)
        gz = int(p.center[2] / cell_size)
        grid.setdefault((gx, gy, gz), []).append(i)

    enlarged_planes = []
    for plane in frustum_planes:
        dU = plane['normal'][0]
        s = r_max * math.sqrt(1.0 + dU * dU)
        new_u0 = plane['u0'] + (s if plane['is_max'] else -s)
        enlarged_planes.append({'normal': plane['normal'], 'u0': new_u0, 'is_max': plane['is_max']})

    enlarged_near = frustum_near - r_max
    enlarged_far = frustum_far + r_max
    return grid, enlarged_planes, enlarged_near, enlarged_far, view_dir

def traverse(grid, planes, near, far, view_dir, particles, rays):
    for cell_key, indices in grid.items():
        cell_min = [c * 1.0 for c in cell_key]
        cell_max = [m + 1.0 for m in cell_min]
        if not box_intersects_frustum(cell_min, cell_max, planes, near, far, view_dir):
            continue
        for idx in indices:
            p = particles[idx]
            for ray in rays:
                if ray_sphere_intersect(ray.origin, ray.dir, p.center, p.radius):
                    pass

def box_intersects_frustum(box_min, box_max, planes, near, far, view_dir):
    """Checks if an axis-aligned box intersects the frustum planes."""
    for plane in planes:
        n = plane['normal']
        u0 = plane['u0']
        # Check if box is completely outside the plane
        if (box_min[0] * n[0] + box_min[1] * n[1] + box_min[2] * n[2] < u0 and
            box_max[0] * n[0] + box_max[1] * n[1] + box_max[2] * n[2] < u0):
            return False
    if box_min[2] < near or box_max[2] > far:
        return False
    return True
```

### Edge Cases and Pitfalls
*   **Wide Radius Range:** If particle radii span several orders of magnitude, using $r_{max}$ causes the enlarged frustum to be excessively large [S1]. This results in traversing many empty cells and intersecting many unnecessary spheres, potentially outweighing the benefits of single storage [S1]. Frustum culling is typically required to mitigate this performance loss [S1].
*   **Non-Uniform Radii:** The method assumes radii are uniform or within a small range [S2]. If this assumption is violated, the performance gain diminishes [S1, S2].
*   **Plane Normal Definition:** The calculation of $s$ depends on the definition of $dU$ [S1, S2]. The sources define $dU$ as the direction vector of the given plane's normal in a reduced 2D context where the normal is $\langle -dU, 1 \rangle$ [S1]. Implementers must ensure $dU$ is extracted correctly from the frustum plane definitions [S1, S2].

## Operating characteristics
*   **Time Complexity:** Grid construction is $O(N)$ where $N$ is the number of particles, due to the simple truncation operation [S1]. Traversal complexity depends on the number of cells visited by the enlarged frustum and the number of spheres per cell [G].
*   **Memory Complexity:** Memory footprint is reduced significantly because each particle is stored exactly once [S1]. For the BulletTorso dataset (35M particles), storage dropped from 3.11 GB (with references) to 1.04 GB [S1].
*   **Measured Performance:**
    *   Speed-up over standard grid: 1.02x to 1.27x on various datasets (Cylinder, JP8, Bullet, Thunder, Foam, BulletTorso) [S1].
    *   Grid construction time improvement: Up to 3.07x faster insertion phase (e.g., JP8 dataset: 797.71 ms to 260.13 ms) [S1]. Total construction time improved from 1407.27 ms to 510.96 ms (factor of 2.75) [S1].
*   **Strengths:**
    *   Eliminates data duplication and mailbox overhead [S1, S2].
    *   Improves locality of reference [S1].
    *   Simplifies grid construction by avoiding overlap tests [S1].
    *   Efficient frustum computation using SIMD (5 operations) [S1, S2].
*   **Limitations:**
    *   Performance degrades if particle radii vary widely [S1].
    *   Requires a priori knowledge of $r_{max}$ [S1].
    *   Enlarged frustum may traverse more cells than necessary if $r_{max}$ is large relative to particle density [S1].
*   **When to Use:** Ideal for particle-based simulation data with uniform or narrowly distributed radii, where interactive performance and low memory footprint are critical [S1, S2].
*   **When Not to Use:** When particle radii vary by several orders of magnitude, unless combined with effective frustum culling [S1].

## Background
The Sphere-Center Method was introduced in the context of interactive ray tracing for particle-based simulation data, specifically for visualizing material point method (MPM) simulations [S2]. It was presented as an optimization to the Coherent Grid Traversal (CGT) algorithm to address classic grid problems: duplicate data, lack of locality of reference, and redundant intersection tests [S1]. The method draws inspiration from offset surfaces used in collision detection [S2]. It was evaluated on datasets such as Cylinder, JP8, Bullet, Thunder, Foam, and BulletTorso, demonstrating improvements in both frame rate and memory usage [S1]. The approach is applicable to other primitive types, such as triangles, though primarily designed for spherical glyphs [S1].
