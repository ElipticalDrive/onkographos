# Hero-like 4-Connectivity (H4T)


## Overview
Hero-like 4-Connectivity (H4T) is a ray traversal algorithm for uniform grids that guarantees strict 4-connectivity by explicitly resolving boundary crossing ambiguities via stable sorting of intersection distances [S1, unofficial]. It solves the problem of diagonal jumps (8-connectivity errors) and associated normal inaccuracies that occur when a ray crosses an edge or corner in standard Digital Differential Analyzer (DDA) approaches [S1, unofficial]. Unlike its sibling [Hierarchical Planes 4-Connectivity (HP4T)](3444-hierarchical-planes-4-connectivity-hp4t.md), which uses plane intersections and clamping, H4T relies on a 2x2 cell test and stable sorting to determine the first cell entered, achieving 100% correctness in randomized testing [S1, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, grid bounds, and voxel size $v$ [S1, unofficial].
**Outputs:** Sequence of visited voxel indices $(i, j, k)$ and traversal intervals [G].

**Data Structures:**
*   `t_max`: Array of floating-point distances to the next boundary for each axis [G].
*   `axis_ids`: Array of integers mapping each `t_max` entry to its axis (0 for x, 1 for y) [S1, unofficial].
*   `grid_position`: Current voxel coordinates $(i, j, k)$ [S1, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Determine the starting voxel containing the ray origin [G]. Compute initial distances to the first boundary in the x and y axes (and z if applicable, though H4T emphasizes the 2D plane logic for connectivity resolution) [S1, unofficial]. Let $t_x$ and $t_y$ be the distances to the next x- and y-boundaries [G].
2.  **2x2 Cell Test:** Identify the candidate cells the ray passes through by evaluating the intersection distances [S1, unofficial]. This involves checking which of the four cells sharing the current edge/corner is entered first [G].
3.  **Association:** Associate each distance value $t$ with an axis identifier [S1, unofficial]. If the distance corresponds to an x-boundary, assign `axis_id = 0`; if y-boundary, assign `axis_id = 1` [S1, unofficial].
4.  **Stable Sorting:** Sort the pairs $(t, \text{axis\_id})$ using a stable sorting algorithm [S1, unofficial]. Primary key: `axis_id` (ascending); Secondary key: $t$ (ascending) [S1, unofficial]. A stable sort preserves the relative order of elements with equal keys [G]. By sorting first by axis, ties in $t$ between x and y boundaries are resolved by prioritizing the x-axis (axis 0) over the y-axis (axis 1) [S1, unofficial].
5.  **Traversal Update:** Select the first entry in the sorted list as the next boundary to cross [S1, unofficial]. Update the `grid_position` index for the selected axis [S1, unofficial]. Update the corresponding $t$ value for that axis by adding the step size $\Delta t$ [G]. The `grid_position` may contain fractional values during intermediate calculations and must be floored before reading the grid data [S1, unofficial].
6.  **Iteration:** Repeat steps 2-5 until the ray exits the grid bounds [G].

**Pseudocode:**
```python
def h4t_traverse(ray_origin, ray_direction, grid_bounds, voxel_size):
    # Initialize current voxel index [G]
    current_voxel = [int(floor(ray_origin[i] / voxel_size)) for i in range(3)]
    current_voxel = [max(grid_bounds.min[i], min(grid_bounds.max[i], current_voxel[i])) for i in range(3)]
    
    # Step direction and delta per axis [G]
    step = [1 if ray_direction[i] > 0 else (-1 if ray_direction[i] < 0 else 0) for i in range(3)]
    t_delta = [voxel_size / abs(ray_direction[i]) if ray_direction[i] != 0 else float('inf') for i in range(3)]
    
    # Initial distance to next boundary per axis [G]
    t_max = [0.0, 0.0, 0.0]
    for i in range(3):
        if ray_direction[i] != 0:
            boundary = (current_voxel[i] + step[i]) * voxel_size
            t_max[i] = (boundary - ray_origin[i]) / ray_direction[i]
        else:
            t_max[i] = float('inf')
            
    visited = []
    while all(grid_bounds.min[i] <= current_voxel[i] <= grid_bounds.max[i] for i in range(3)):
        visited.append(tuple(current_voxel))
        
        # H4T core: 2x2 cell test with stable sorting for x and y axes [S1, unofficial]
        # Associate each t-value with an axis identifier (0 for x, 1 for y) [S1, unofficial]
        candidates = [(t_max[0], 0), (t_max[1], 1)]
        # Stable sort: primary key axis_id, secondary key t_max [S1, unofficial]
        candidates.sort(key=lambda item: (item[1], item[0]))
        
        # Select the first entry as the next boundary to cross [S1, unofficial]
        next_t, next_axis = candidates[0]
        
        # Update grid_position index for the selected axis [S1, unofficial]
        current_voxel[next_axis] += step[next_axis]
        # Update the corresponding t value by adding the step size [G]
        t_max[next_axis] += t_delta[next_axis]
        
        # Note: For full 3D traversal, z-axis updates follow standard DDA logic [G]
        # The source emphasizes the 2D x/y tie-resolution as the defining H4T feature [S1, unofficial]
        
    return visited
```

**Edge Cases and Pitfalls:**
*   **Ties:** When $t_x = t_y$, standard DDA might arbitrarily pick one, leading to 8-connectivity. H4T forces x-first via sorting [S1, unofficial].
*   **Fractional Positions:** The method may produce fractional grid positions during traversal; these must be floored before texture/voxel lookup [S1, unofficial].
*   **Performance:** The sorting step adds computational overhead compared to simple comparisons. The source notes the C code was omitted due to length, implying complexity [S1, unofficial].

## Subtopics

### [Hierarchical Planes 4-Connectivity (HP4T)](3444-hierarchical-planes-4-connectivity-hp4t.md)
A hierarchical variant that replaces stable sorting with direct plane intersection and clamping. Chosen when hierarchical grid structures (like Octrees) are used and higher precision `total_t` calculation is needed, though it trades the 100% correctness of H4T for hierarchical efficiency.

## Operating characteristics
*   **Correctness:** Achieved 100% correctness for both position and normal in 100,000,000 randomized test cases and 2,883,496 exact test cases [S1, unofficial].
*   **Accuracy:** Outperforms HP4T (99.99% in randomized tests, 99.57%/99.78% in specific tests) and HP8T (99.99% in randomized tests, 97.66%/99.29% in specific tests) [S1, unofficial].
*   **Complexity:** The stable sorting step introduces overhead. The source does not provide explicit Big-O notation but notes the implementation complexity is high enough that the source code was not published [S1, unofficial].
*   **Use Case:** Best suited for applications where geometric correctness and normal accuracy are critical and performance overhead of sorting is acceptable [S1, unofficial].

## Background
H4T was developed as part of a project investigating ray traversal algorithms for hierarchical grids [S1, unofficial]. It was discovered late in the project cycle and designed to address the connectivity errors inherent in previous approaches like HP4T and HP8T [S1, unofficial]. The method's implementation complexity is high, as the original C code was omitted from the publication due to length [S1, unofficial].
