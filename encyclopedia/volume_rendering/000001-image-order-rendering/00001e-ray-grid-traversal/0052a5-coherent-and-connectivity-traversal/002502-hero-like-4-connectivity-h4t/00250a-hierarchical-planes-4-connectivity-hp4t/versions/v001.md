# Hierarchical Planes 4-Connectivity (HP4T)

## Overview
Hierarchical Planes 4-Connectivity (HP4T) is a ray traversal algorithm for hierarchical grids (such as Octrees or Sparse Voxel Octrees) that ensures strict 4-connectivity by using plane intersections to calculate new grid positions and applying specific clamping logic to prevent diagonal jumps [S1, unofficial]. It builds on [Hero-like 4-Connectivity (H4T)](3436-hero-like-4-connectivity-h4t.md) but replaces the stable sorting of t-values with a direct plane-intersection approach that calculates `total_t` with higher precision [S1, unofficial]. HP4T is distinguished from its sibling [Hierarchical Planes 8-Connectivity (HP8T)](5220-hierarchical-planes-8-connectivity-hp8t.md) by the inclusion of clamping operations that restrict movement to axis-aligned steps only, thereby avoiding the 8-connectivity errors (diagonal jumps) and associated surface normal inaccuracies found in naive implementations [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** `ray_position` (vec3), `ray_direction` (vec3), `inv_dir` (vec3, inverse of `ray_direction`), `grid_position` (vec2, current 2D grid coordinates), `cellsize` (float, size of the current hierarchical level), `grid_width` (int), `grid_height` (int).
*   **Outputs:** Updated `grid_position` for the next cell in the traversal path.

**Data Structures:**
*   `grid_position`: A 2D vector representing the current cell indices in the 2D slice of the hierarchical grid.
*   `planes`: A 2D vector representing the world-space coordinates of the grid planes intersected by the ray.
*   `total_t`: A 2D vector representing the parametric distance along the ray to each plane intersection.

**Definitions:**
*   $is_{pos}(x)$: Returns $1$ if $x \ge 0$, else $0$.
*   $is_{neg}(x)$: Returns $0$ if $x \ge 0$, else $1$.
*   $sign\_dir$: A vector where each component is $1$ if the corresponding `ray_direction` component is $\ge 0$, else $-1$. This is used for clamping logic.
*   $is\_ray\_neg$: A vector where each component is $is_{neg}(ray\_direction)$.
*   $is\_dir\_pos$: A vector where each component is $is_{pos}(ray\_direction)$.
*   $cellsize$: The current size of the cell in the hierarchy, calculated as $2^{level}$, where $level$ is the current hierarchy level (0, 1, 2...). At level 0, $cellsize=1$; at level 1, $cellsize=2$; at level 2, $cellsize=4$ [S1, unofficial].
*   $inv\_dir$: The element-wise inverse of `ray_direction` ($1.0 / ray\_direction$). Note that this is distinct from `abs_inv_dir` as it retains the sign of the direction [S1, unofficial].

**Algorithm Steps:**
The traversal loop continues while `grid_position` is within the grid bounds ($0 \le x < grid\_width$ and $0 \le y < grid\_height$).

1.  **Calculate Plane Positions:** Compute the world-space coordinates of the grid planes that bound the current cell in the direction of the ray. This is done using Hadamard (element-wise) multiplication:
    $$planes = (\lfloor grid\_position / cellsize \rfloor + is\_dir\_pos) \times cellsize$$
    Here, $\lfloor \cdot \rfloor$ denotes the floor function applied element-wise. The term $is\_dir\_pos$ offsets the plane to the next cell boundary in the direction of the ray [S1, unofficial].

2.  **Calculate Total T:** Compute the parametric distance to these planes:
    $$total\_t = (planes - ray\_position) \times inv\_dir$$
    This calculation uses the precise plane positions rather than incremental steps, improving numerical precision [S1, unofficial].

3.  **Determine Hit Axis:** Compare $total\_t.x$ and $total\_t.y$ to determine which plane is hit first.

    **Case A: X plane is hit first ($total\_t.x \le total\_t.y$)**
    *   Set the traversal step $t = total\_t.x$.
    *   Update the X grid position to the plane boundary:
        $$grid\_position.x = planes.x - is\_ray\_neg.x$$
    *   Store the old Y position:
        $$old\_grid\_pos\_y = grid\_position.y$$
    *   Calculate the candidate new Y position based on the ray intersection:
        $$grid\_position.y = \lfloor ray\_dir.y \times t + ray\_position.y \rfloor$$
    *   Apply 4-connectivity clamping to Y to prevent diagonal jumps. This involves two steps using $sign\_dir.y$:
        1.  Ensure the new Y is not behind the old Y in the direction of travel:
            $$grid\_position.y = sign\_dir.y \times \max(0.0f, sign\_dir.y \times (grid\_position.y - old\_grid\_pos\_y))$$
        2.  Ensure the new Y does not skip the next plane boundary:
            $$grid\_position.y = sign\_dir.y \times \min(sign\_dir.y \times (planes.y - is\_dir\_pos.y), sign\_dir.y \times (grid\_position.y + old\_grid\_pos\_y))$$

    **Case B: Y plane is hit first ($total\_t.x > total\_t.y$)**
    *   Set the traversal step $t = total\_t.y$.
    *   Update the Y grid position to the plane boundary:
        $$grid\_position.y = planes.y - is\_ray\_neg.y$$
    *   Update the X position using simplified clamping logic (equivalent to the X logic in Case A but optimized):
        $$grid\_position.x = sign\_dir.x \times \min(sign\_dir.x \times planes.x - is\_dir\_pos.x, \max(0.0f, sign\_dir.x \times (\lfloor ray\_dir.x \times t + ray\_position.x \rfloor - grid\_position.x)) + sign\_dir.x \times grid\_position.x)$$

**Pseudocode:**
```python
def hp4t_traverse(ray_position, ray_direction, inv_dir, grid_position, cellsize, grid_width, grid_height):
    # Precompute helper vectors
    is_dir_pos = [1.0 if d >= 0 else 0.0 for d in ray_direction[:2]]
    is_ray_neg = [0.0 if d >= 0 else 1.0 for d in ray_direction[:2]]
    sign_dir = [1.0 if d >= 0 else -1.0 for d in ray_direction[:2]]
    
    while 0 <= grid_position[0] < grid_width and 0 <= grid_position[1] < grid_height:
        # 1. Calculate plane positions
        # floor is applied element-wise
        planes = [(floor(grid_position[i] / cellsize) + is_dir_pos[i]) * cellsize for i in range(2)]
        
        # 2. Calculate total_t
        total_t = [(planes[i] - ray_position[i]) * inv_dir[i] for i in range(2)]
        
        if total_t[0] <= total_t[1]:
            # X plane hit first
            t = total_t[0]
            
            # 3. Update X position
            grid_position[0] = planes[0] - is_ray_neg[0]
            
            # 4. Store old Y
            old_grid_pos_y = grid_position[1]
            
            # 5. Calculate candidate Y
            grid_position[1] = floor(ray_direction[1] * t + ray_position[1])
            
            # 6. Clamp Y (part 1): Ensure forward movement
            grid_position[1] = sign_dir[1] * max(0.0, sign_dir[1] * (grid_position[1] - old_grid_pos_y))
            
            # 7. Clamp Y (part 2): Ensure no skipping of next plane
            grid_position[1] = sign_dir[1] * min(sign_dir[1] * (planes[1] - is_dir_pos[1]), sign_dir[1] * (grid_position[1] + old_grid_pos_y))
            
        else:
            # Y plane hit first
            t = total_t[1]
            
            # 8. Update Y position
            grid_position[1] = planes[1] - is_ray_neg[1]
            
            # 9. Update X position with clamping
            # Simplified formula from source
            candidate_x = floor(ray_direction[0] * t + ray_position[0])
            diff_x = candidate_x - grid_position[0]
            clamped_diff = max(0.0, sign_dir[0] * diff_x)
            grid_position[0] = sign_dir[0] * min(sign_dir[0] * planes[0] - is_dir_pos[0], clamped_diff + sign_dir[0] * grid_position[0])
```

## Subtopics

### [Hierarchical Planes 8-Connectivity (HP8T)](5220-hierarchical-planes-8-connectivity-hp8t.md)
A variant of HP4T that simplifies the calculation for the non-hit axis by removing clamping, resulting in 8-connectivity (allowing diagonal jumps). The resulting grid_position may contain fractional values and must be floored before grid access.

## Operating characteristics
*   **Time Complexity:** Per step, the algorithm performs a constant number of arithmetic operations, comparisons, and floor functions. It is $O(1)$ per cell visited.
*   **Memory Complexity:** $O(1)$ auxiliary space, requiring only a few temporary vectors (`planes`, `total_t`, `old_grid_pos_y`).
*   **Measured Performance:** In randomized testing with 100,000,000 cases, HP4T achieved a 99.99% chance of correct position and 99.99% chance of correct normal [S1, unofficial]. While slightly less accurate than H4T (which achieved 100% in the same tests), HP4T offers a robust balance between precision and implementation simplicity compared to naive DDA methods [S1, unofficial].
*   **Strengths:** Avoids the 8-connectivity errors (diagonal jumps) and incorrect surface normals associated with naive implementations using `compare` variables and `t + eps` [S1, unofficial]. Uses plane intersections for better precision in `total_t` calculation [S1, unofficial].
*   **Limitations:** Slightly lower accuracy than H4T in extreme edge cases (0.01% error rate in randomized tests) [S1, unofficial]. The clamping logic is complex and prone to implementation errors if not carefully followed [S1, unofficial].
*   **When to use:** When 4-connectivity is required to ensure correct surface normals and avoid diagonal jumps in hierarchical grid traversal, and when the implementation complexity of H4T's stable sorting is undesirable.
*   **When not to use:** When maximum numerical accuracy is critical and H4T can be implemented; when 8-connectivity is acceptable or desired (use HP8T).

## Background
HP4T was introduced in a thesis by versal, titled "versal algorithm for ray tracing Hur man gör en hierarkisk ..." [S1, unofficial]. The method is part of a family of hierarchical plane traversal algorithms, where "HP" stands for Hierarchical Planes and "4T" indicates 4-connectivity with total summation logic [S1, unofficial]. It was developed to address the surface normal errors and connectivity issues found in earlier methods like those used in the game Teardown, which relied on 8-connectivity and flawed comparison variables [S1, unofficial]. The algorithm draws inspiration from Scratchapixel's code for clamping logic [S1, unofficial].
