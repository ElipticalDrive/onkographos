# Hierarchical Grid Traversal

Also called: Hierarchical Grid Intersection, Ray-Mipmap Traversal

## Overview
Hierarchical Grid Traversal is a ray-grid traversal method that accelerates volume rendering by stepping through a multi-resolution grid hierarchy (mipmap) rather than a single flat grid. It solves the performance bottleneck of visiting empty or homogeneous regions by traversing coarse nodes first and only descending into child voxels when the ray intersects the parent's axis-aligned bounding box (AABB) [S1, S2, unofficial]. It sets itself apart from flat [Digital Differential Analyzer (DDA) Traversal](3061-digital-differential-analyzer-dda-traversal.md) by skipping large empty spaces via tree structure, and from pure [Octree and Tree Traversal](4134-octree-and-tree-traversal.md) by often relying on precomputed lookup tables or fixed grid strides rather than dynamic pointer-based node navigation [S1, S2, unofficial].

## How it works
The method iterates through levels of a grid mipmap, starting from the root (level 0). It maintains a list of active "touched" voxels at the current level and computes their children for the next level if the ray intersects the current voxel's spatial bounds [S1, S2, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Ray: Origin $\mathbf{o}$, direction $\mathbf{d}$ (or inverse direction $\mathbf{r}_{inv}$), and near/far clip distances $t_0, t_1$.
    *   Grid Hierarchy: A set of lookup tables (`tables_list`) where each table corresponds to a resolution level.
    *   Parameters: `max_level` (depth of hierarchy), `cube_size` (physical size of a voxel at the current level).
*   **Outputs:**
    *   `cube_ori_list`: A list of 3D coordinates (or indices) of the voxels at the maximum level (`max_level`) that the ray intersects.

### Data Structures
1.  **Lookup Table (`table`):** A 2D array where each row represents a coarse voxel.
    *   Columns 0–7: Indices of the 8 child voxels in the next finer level. Value `-1` indicates an empty/invalid child [S1, unofficial].
    *   Columns -3 to -1 (or 8–10): The 3D grid coordinates $(x, y, z)$ of the coarse voxel [S1, unofficial].
2.  **K-Table (Active Ray List):** A list of active rays and their current voxel context.
    *   Columns 0–2: Ray origin $\mathbf{o}$ [S1, unofficial].
    *   Columns 3–5: Ray inverse direction $\mathbf{r}_{inv}$ [S1, unofficial].
    *   Columns 6–8: Current voxel origin (AABB min) [S1, unofficial].
    *   Columns 9–11: Current voxel end (AABB max) [S1, unofficial].
    *   Column -2: Ray ID [S1, unofficial].
    *   Column -1: Voxel ID (row index in the grid table) [S1, unofficial].
3.  **TreeMarcher Class (C++ Implementation):**
    *   Members: `AccT& mAcc` (accessor), `RayT mRay`, `HDDA<RayT, Coord> mHdda` (Hierarchical DDA helper), `float mT0`, `float mTmax` [S2, unofficial].

### Algorithm Steps

#### 1. Initialization
1.  Initialize `cube_touched_idx` with `[0]` (the root voxel index) [S1, unofficial].
2.  Initialize `new_list` as empty [S1, unofficial].
3.  Clip the ray to the root bounding box. If no intersection, terminate [S2, unofficial].
4.  Set epsilon $Eps = 10^{-6}$ [S2, unofficial].
5.  Set $t_{entry} = t_0 + Eps$ and $t_{exit} = t_1 - Eps$. If $t_{entry} > t_{exit}$, terminate [S2, unofficial].
6.  Determine the initial voxel index `ijk` by flooring the ray position at $t_{entry}$ [S2, unofficial].
7.  Initialize the Hierarchical DDA (`mHdda`) with the ray, $t_{entry}$, $t_{exit}$, and the dimension of the current node [S2, unofficial].

#### 2. Hierarchical Iteration
Iterate through each level $L$ from $0$ to `max_level`:

1.  Retrieve the lookup table for level $L$: `table = tables_list[L]` [S1, unofficial].
2.  For each voxel index $i$ in `cube_touched_idx`:
    a.  **Retrieve Bounds:** Get the voxel's 3D coordinates $(x, y, z)$ from `table[i, -3:]`. Calculate the physical origin $\mathbf{v}_{ori}$ and end $\mathbf{v}_{end}$ using the voxel size for level $L$:
        $$ \mathbf{v}_{ori} = (x, y, z) \times \text{cube\_size}_L $$
        $$ \mathbf{v}_{end} = \mathbf{v}_{ori} + \text{cube\_size}_L $$
        where $\text{cube\_size}_L = \frac{256}{2^L}$ (assuming a base resolution of 256) [S1, unofficial].
    b.  **Ray-AABB Intersection:** Compute the intersection of the ray with the box $[\mathbf{v}_{ori}, \mathbf{v}_{end}]$. This yields near time $t_n$ and far time $t_f$ [S1, unofficial].
    c.  **Check Intersection:** If $t_n \le t_f$ (ray intersects the voxel):
        i.  **Leaf Check:** If $L == \text{max\_level}$, append the voxel's position/ID to `cube_ori_list` (the final hit list) [S1, unofficial].
        ii. **Descend:** If $L < \text{max\_level}$, extract the child indices from `table[i, 0:7]`. Filter out invalid children (where value is `-1`) using a mask. Convert valid indices to integers and add them to `new_list` [S1, unofficial].
    d.  **Non-Intersection:** If the ray does not intersect the voxel, skip to the next voxel in `cube_touched_idx` [S1, unofficial].

3.  **Update Active List:** Set `cube_touched_idx = new_list` and reset `new_list` to empty for the next level [S1, unofficial].

#### 3. Vectorized Variant (`ray_mipmap_intersect_vectorized`)
1.  Process all rays in `cube_touched_idx` simultaneously [S1, unofficial].
2.  Initialize arrays `tn` and `tf` with zeros [S1, unofficial].
3.  Iterate over each ray index in `cube_touched_idx`:
    a.  Compute $\mathbf{v}_{ori}$ and $\mathbf{v}_{end}$ for the current voxel [S1, unofficial].
    b.  Call `intersect_ray_aabb` with the ray's origin, inverse direction, and the voxel bounds to get $t_n$ and $t_f$ [S1, unofficial].
4.  Create a mask `mask = tn <= tf` [S1, unofficial].
5.  Use this mask to filter valid children from the table and update `new_list` [S1, unofficial].

#### 4. Teardown Variant (Rescaling)
An alternative implementation (e.g., in the game *Teardown*) switches levels by rescaling the grid so the new level becomes a level 0 grid, then restarting the DDA algorithm [S4, unofficial].
1.  Calculate the ray position in the grid at any level $L$:
    $$ \text{pos} = \left\lfloor \frac{\mathbf{o} + t \cdot \mathbf{d}}{2^L} \right\rfloor $$
2.  Restart the DDA algorithm in the new level [S4, unofficial].

### Parameters
*   `max_level`: The maximum depth of the mipmap hierarchy. The loop runs from $0$ to `max_level` inclusive [S1, unofficial].
*   `cube_size`: The physical size of a voxel at the current level. Typically calculated as $256 / 2^L$ for a base grid of 256 units [S1, unofficial].
*   `Delta`: A small offset used in the HDDA step to determine the next voxel index. Typical value: $0.01$ [S2, unofficial].
*   `Eps`: Epsilon for clipping. Typical value: $10^{-6}$ [S2, unofficial].

### Edge Cases and Pitfalls
1.  **Floating-Point Drift in Rescaling:** Using the formula $\mathbf{o} + t\mathbf{d}$ to switch levels does not guarantee that the ray crosses the plane due to floating-point issues, leading to outliers in depth and normal buffers [S4, unofficial].
2.  **Corner Traversal:** Allowing rays to traverse through corners can cause problems with surface normals [S4, unofficial].
3.  **Delta Sensitivity:** If `Delta` is too large, it clips corners of nodes visibly. If too small, it fails due to FP32 rounding when far from the grid [S2, unofficial].
4.  **Tiny Intersections:** Tweaking the intersection span with `Eps` may clip tiny corner intersections [S2, unofficial].
5.  **Empty Children:** Child indices in the lookup table are marked as `-1` if empty. These must be explicitly filtered out before adding to the next level's active list [S1, unofficial].

## Subtopics

### [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md)
Hierarchical Trilinear Ray Casting is a volume rendering method that accelerates ray casting by traversing a multi-dimensional hierarchy (mdh) and adaptively selecting the resolution level for data evaluation based on a user-defined error tolerance and data importance weighting. It differs from sibling methods like [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md) or [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by using least-squares trilinear basis functions to model data regions, allowing the algorithm to decide whether to refine traversal or evaluate the region directly based on the approximation error. Unlike methods that rely on simple homogeneity (constant values), this approach generalizes homogeneity to least-squares fits, providing a more robust metric for heterogeneous but smooth regions.

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
The Hierarchical Digital Differential Analyzer (HDDA) is a ray traversal algorithm that performs multi-resolution leapfrogging through sparse volume data structures, specifically OpenVDB and NanoVDB grids. It adapts the Digital Differential Analyzer (DDA) to step through nodes or voxels of varying power-of-two dimensions, skipping empty space by jumping between grid nodes of different resolutions. Unlike standard voxel DDA which checks every voxel, HDDA leverages the hierarchical tree structure (B+tree) to traverse coarse tiles first and only descend into occupied children, significantly accelerating ray-marching for sparse volumes. It is distinct from [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) in its specific implementation for VDB structures using compile-time template meta-programming to inline the hierarchy, and from [Hierarchical Trilinear Ray Casting](851-hierarchical-trilinear-ray-casting.md) by focusing on traversal efficiency rather than shading interpolation.

### [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md)
Hierarchical Voxel Traversal is a recursive raycasting algorithm designed to traverse nested voxel structures, such as chunks containing subvoxels, to find intersections. It distinguishes itself from flat traversal methods by transforming rays into local subvoxel space when entering a detail voxel, allowing for efficient handling of nested voxel data. Unlike [First Active Voxel Detection](4196-first-active-voxel-detection.md) which focuses on finding the first non-empty voxel, this method fully traverses the hierarchy to compute precise intersections within detail voxels.

### [XBrickMap](3116-xbrickmap.md)
XBrickMap is a space-skipping ray traversal algorithm for 3-level hierarchical voxel grids that uses $4^3$ occupancy bitmasks to perform hierarchical skips ($4^3, 2^3, 1^3$ cuboids) via bitwise tests. It improves upon standard skipping by using tiled bitmasks to identify empty voxel sections and left-packs these bitmasks to omit empty bricks within sectors, saving memory. It is distinguished from siblings like [MultiDDA](2204-hierarchical-voxel-traversal.md) by its specific 3-level sector/brick/voxel hierarchy and bitmask-based compression, and from [Tree64](6354-multi-level-grid-structures.md) by its fixed grid topology and lack of dynamic tree rebalancing.

### [First Active Voxel Detection](4196-first-active-voxel-detection.md)
First Active Voxel Detection determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA). Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit.

### [Hierarchical and Block-Based Data Structures](4392-hierarchical-and-block-based-data-structures.md)
Hierarchical and Block-Based Data Structures provide a spatial subdivision framework for volume rendering, enabling efficient traversal and culling of empty or inactive regions during ray marching. Unlike flat voxel grids, these structures organize data into a tree where internal nodes store aggregate properties (e.g., occupancy, scalar ranges) derived from their children, allowing rays to skip large inactive subtrees [4133-hierarchical-data-structures]. This family encompasses methods that vary in their spatial representation (octrees, pyramids, image-space mipmaps) and traversal order (image-order, object-order, or hybrid). It sets itself apart from sibling methods by focusing on the *data organization* strategy (hierarchical blocks/trees) rather than the specific traversal algorithm (e.g., HDDA) or hardware acceleration mechanism (e.g., RTX BVH) used to navigate it.

### [Octree-based traversal](5348-octree-based-traversal.md)
Octree-based traversal accelerates volume rendering and ray tracing by navigating a hierarchical spatial decomposition (typically an octree) to skip empty space and reduce the number of ray-casting or distance-evaluation steps. It solves the performance bottleneck of non-hierarchical traversal, where every voxel along a ray must be visited, by allowing the ray to leap over large empty regions. Unlike sibling methods that may use fixed-resolution grids or brick maps, this family operates on a recursive tree structure where each parent node divides into eight equal sub-blocks ($2 \times 2 \times 2$ subdivision), enabling larger steps through empty space.

### [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md)
Empty Space Skipping via Data Structures accelerates volume rendering by using secondary data structures to identify inactive regions, allowing rays to skip sampling points in empty space. It differs from [Space Leaping](5863-space-leaping.md) by relying on explicit spatial metadata rather than image-plane coherence, and from [Distance Map Acceleration](972-distance-map-acceleration.md) by using binary or bounded occupancy flags rather than distance-to-nearest-occupied-voxel metrics. It sets itself apart from sibling methods like [Hierarchical Voxel Traversal](2204-hierarchical-voxel-traversal.md) by focusing specifically on the *culling* of inactive regions via metadata queries, whereas hierarchical traversal focuses on the *navigation* of the grid hierarchy itself.

### [Multi-level Grid Structures](6354-multi-level-grid-structures.md)
Multi-level Grid Structures are a family of hierarchical acceleration techniques for ray-grid traversal that organize scene data into a hierarchy of grid levels (mipmaps) to skip empty space and reduce intersection tests. They differ from uniform grids by adapting resolution to local density and from pure tree structures (like Octrees) by maintaining a grid-based indexing scheme at each level, which simplifies traversal logic on GPUs. This family builds on [Hierarchical Grid Traversal](2560-hierarchical-grid-traversal.md) by providing specific implementations for constructing and traversing these hierarchical grids.

### KD-Tree Partitioned Volume Rendering
A method to avoid computing all scalar values regardless of visibility by partitioning the volume into smaller sub-volumes with similar properties based on the transfer function [S3, unofficial]. The opacity map corresponds to a region of the frame buffer and stores the minimum opacity of the frame buffer pixels found within that region [S3, unofficial]. It groups scalar values within a certain range together based on the transfer function to define sub-volume properties, uses a kd-tree to render the partitioned volume with correct visibility order (where each node is associated with a sub-volume), and culls/clips each sub-volume against an opacity map [S3, unofficial]. Reported performance: 10 fps for the Engine data set using a 2.5 GHz Pentium-IV and a nVidia GeForce4 graphics adapter [S3, unofficial].

### Mipmap Table Construction
Constructs a lookup table for hierarchical grid traversal. It maps coarse grid voxels to their fine grid children. The table is built from a fine grid and a coarse grid mask [S1, unofficial]. It identifies occupied voxels in the fine grid, assigns unique indices, extracts the 8 sub-grid regions corresponding to the 8 children of a coarse voxel (via striding), flattens these sub-grids, and filters them using the coarse grid mask. The table is initialized with shape `[num_coarse_voxels, 11]` (8 child indices + 3 coordinates), filled with -1. Columns 0-7 are populated with filtered child indices, and columns 8-10 with coarse voxel coordinates [S1, unofficial].

### K-Table Initialization and Propagation
Manages a list of active rays ('k-table') during traversal. It stores ray properties and the current voxel they are in, propagating to child voxels [S1, unofficial]. It initializes `k_table` with ray origins, inverse directions, ray IDs, and the root voxel's origin/end. In `next_k_table`, for each row, it gets the current voxel ID and position, calculates voxel size, identifies alive sub-voxels (children) from the grid table, computes their origins, creates new `k_table` rows for each alive sub-voxel, and concatenates them into a single `k_table` for the next level [S1, unofficial].

### Teardown Hierarchical Traversal
A hierarchical traversal method that uses DDA within a level and switches levels by rescaling the grid so the new level becomes a level 0 grid, restarting the DDA algorithm [S4, unofficial]. It calculates the ray position in the grid at any level using the formula: $pos = \lfloor (O + t \cdot D) / 2^{level} \rfloor$ [S4, unofficial]. Using the formula $O + tD$ to switch levels does not guarantee that the ray crosses the plane due to floating-point issues, leading to outliers in depth and normal buffers [S4, unofficial]. The method allows rays to traverse through corners, which can cause problems with surface normals [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the sparsity of the volume and the depth of the hierarchy. In the worst case (dense volume), it approaches $O(N)$ where $N$ is the number of voxels at the finest level, but with a higher constant factor due to tree traversal overhead. In sparse volumes, it is significantly faster than flat DDA, approaching $O(K)$ where $K$ is the number of active voxels.
*   **Memory Complexity:** Requires storage for the hierarchy. For a mipmap approach, this is $O(N)$ total voxels across all levels ($N + N/8 + N/64 + \dots \approx 1.14N$). The lookup tables add overhead but avoid pointer chasing.
*   **Measured Performance:** Specific hardware-dependent metrics are not provided in the general sources, but KD-Tree partitioned variants report 10 fps for the Engine data set on a 2.5 GHz Pentium-IV and nVidia GeForce4 [S3, unofficial].
*   **Strengths:** Efficiently skips large empty regions; suitable for sparse volumes; lookup tables can be cache-friendly on GPUs.
*   **Limitations:** Requires precomputation of the hierarchy/tables; floating-point precision issues can arise during level switching (rescaling); corner traversal can cause artifacts.
*   **When to use:** Sparse volumes, large datasets with significant empty space, GPU implementations where pointer chasing is expensive.
*   **When not to use:** Dense volumes where the overhead of tree traversal outweighs the benefit of skipping; dynamic volumes where hierarchy updates are frequent.

## Background
Hierarchical Grid Traversal builds on the principles of ray-grid traversal [17-ray-grid-traversal.md]. It was developed to address the inefficiency of flat grid traversal in sparse volumes. Variants like HDDA are associated with OpenVDB/NanoVDB structures [S1, S3, unofficial]. The "Teardown" variant is documented in a thesis analyzing the game *Teardown*'s rendering engine [S4, unofficial]. The lookup table approach is implemented in projects like Jax-Volumetric-Renderer [S1, unofficial] and HNanoSolver [S2, unofficial].
