# First Active Voxel Detection

Also called: firstActive

## Overview
First Active Voxel Detection determines if a ray intersects an active value at any level of a hierarchical grid and identifies the first such voxel or tile [S1]. It solves the problem of efficiently skipping empty space in sparse volume data structures by performing empty-space ray-marching at all tree levels using a Hierarchical DDA (HDDA) [S1][S3, unofficial]. Unlike standard linear traversal, it leverages the hierarchical structure to jump over inactive regions, setting the intersection time and index upon the first hit [S1].

## How it works
**Inputs:**
- `ray`: A ray object with properties `t0` (start time), `t1` (end time), `start` (origin), and a method to compute position at time $t$ [S3, unofficial].
- `acc`: An accessor object providing access to the grid hierarchy and voxel activity status [S1].
- `ijk` (output): A coordinate object updated to the index of the first active voxel/tile [S1].
- `t` (output): A float updated to the intersection time along the ray [S1].

**Data Structures:**
- `Coord`: A 3D integer coordinate type (e.g., `int32_t` or `CoordT`) [S1].
- `HDDA`: A Hierarchical DDA state machine that tracks ray progress through the grid hierarchy. It provides `step()` to advance to the next slab and `time()` to retrieve the current traversal time [S3, unofficial].

**Algorithm:**
1. **Clipping:** Clip the ray to the root bounding box of the accessor (`acc.root().bbox()`). If the ray's end time `t1` exceeds $10^{20}$, return `false` indicating no valid intersection range [S3, unofficial].
2. **Initialization:** Set a small delta constant $\Delta = 1.0001$ [S3, unofficial]. Initialize traversal time $t = \text{ray}.t0$ [S3, unofficial]. Initialize current coordinate $ijk = \lfloor \text{ray.start} \rfloor$ (floor of the ray origin) [S3, unofficial].
3. **Traversal Loop:** While the voxel at `ijk` is not active (`!acc.isActive(ijk)`): Call `hdda.step()` to advance the hierarchical traversal. If `hdda.step()` returns `false` (indicating the ray has exited the grid or hierarchy), return `false` [S3, unofficial]. Update time: $t = \text{hdda.time()} + \Delta$ [S3, unofficial]. Update coordinate: $ijk = \lfloor \text{ray}(t) \rfloor$ (floor of the ray position at time $t$) [S3, unofficial].
4. **Result:** Return `true`. The variables `ijk` and `t` now hold the index and time of the first active voxel/tile [S1][S3, unofficial].

**Pseudocode:**
```python
def firstActive(ray, acc):
    # 1. Clip ray to root bounding box
    bbox = acc.root().bbox()
    if not ray.clip_to_bbox(bbox):
        return False
    if ray.t1 > 1e20:
        return False

    # 2. Initialize
    Delta = 1.0001
    t = ray.t0
    ijk = floor(ray.start)

    # 3. Traverse empty space
    hdda = HDDA(ray, acc)
    while not acc.isActive(ijk):
        if not hdda.step():
            return False
        t = hdda.time() + Delta
        ijk = floor(ray.position_at(t))

    return True
```

**Edge Cases:**
- **Ray outside bounds:** If the ray does not intersect the root bounding box, the algorithm returns `false` immediately [S3, unofficial].
- **No active voxels:** If the ray traverses the entire grid without hitting an active voxel, `hdda.step()` will eventually return `false`, and the function returns `false` [S3, unofficial].
- **Precision:** The addition of $\Delta$ ensures the ray advances slightly past the current voxel boundary to avoid re-sampling the same inactive voxel due to floating-point inaccuracies [S3, unofficial].

## Subtopics

### Brick Active Check
Checks if a brick is currently active in the world tile occupancy mask to filter out stale or unloaded bricks in ray-tracing queries [S4, unofficial]. It calculates brick coordinates $(bx, by, bz)$ from a linear brick index $bi$ using modulo and division operations relative to `WORLD_BRICKS_X` and `WORLD_BRICKS_Y` [S4, unofficial]. It then maps these to a tile index $ti$ using chunking (`>> 2`) and a world tile index function [S4, unofficial]. Finally, it computes a linear offset `lin` within the tile using bitwise AND operations and returns the result of `tile_has_child(ti, lin)` [S4, unofficial]. This method is specific to world-space brick management rather than pure grid hierarchy traversal [S4, unofficial].
