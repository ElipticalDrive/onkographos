# Hierarchical Digital Differential Analyzer (HDDA)

Also called: HDDA Tree Marcher, Hierarchical DDA, NanoVDB Ray Marching with HDDA Acceleration, Unity NanoVDB Volume Renderer

## Overview
The Hierarchical Digital Differential Analyzer (HDDA) is a specialized ray traversal algorithm for sparse voxel grids (specifically VDB structures) that performs multi-resolution leapfrogging to efficiently determine intersected voxels or tiles [S1, unofficial][S2]. It solves the problem of slow ray traversal in deep, sparse hierarchies by leveraging the fixed compile-time tree configuration to inline and collapse vertical navigation overhead [S1, unofficial][S2]. Unlike standard DDA which steps voxel-by-voxel, HDDA leaps across empty space at multiple resolution levels, making it distinct from [Leaf Collection](899-leaf-collection.md) (which collects leaves first) and [Point Plane Test Traversal](982-point-plane-test-traversal.md) (which uses geometric tests per node) [S1, unofficial].

## How it works
**Inputs:** A sparse voxel grid (e.g., VDB or NanoVDB) with a hierarchical tree structure (B+tree), a ray defined by origin $\mathbf{o}$, direction $\mathbf{d}$, and interval $[t_{min}, t_{max}]$. For non-linear transforms, an auxiliary binary mask grid is required [S1, unofficial][S2].
**Outputs:** A sequence of active voxel/tile intervals $(t_0, t_1)$ along the ray, or hit distances and values for rendering [S1, S3, unofficial].

**Data Structures:**
*   **Grid:** Hierarchical structure with fixed depth/branching factor at compile time [S1, unofficial].
*   **Ray:** Struct containing `origin` (float3), `direction` (float3), `tmin` (float), `tmax` (float) [S3, unofficial].
*   **Auxiliary Mask (Non-linear only):** Binary grid (1 bit per voxel) with linear transform, lower resolution, generated by resampling the density grid with frustum transform [S1, unofficial][S2].

**Algorithm Steps:**

1.  **Initialization:**
    *   Read grid type and tree handle from the buffer [S3, unofficial].
    *   Initialize a read accessor with the root node [S3, unofficial].
    *   If the grid has a non-linear transform (e.g., warped to camera frustum), construct an auxiliary binary VDB with a linear transform [S1, unofficial][S2]. This is done by concurrent resampling of the density grid with the frustum transform onto a binary grid with a linear transform [S1, unofficial][S2].
    *   Perform fast bit-wise topological dilation on the auxiliary binary grid to account for interpolation kernel size [S1, unofficial][S2].

2.  **HDDA Hit Detection (Leapfrogging):**
    *   Call the HDDA tree marcher with the grid, accessor, ray, and bounds [S3, unofficial].
    *   The HDDA uses template meta-programming to inline the hierarchical traversal, avoiding virtual calls or stack-based vertical navigation [S1, unofficial][S2].
    *   It computes the next intersection point $t_{hit}$ and the value at that hit [S3, unofficial].
    *   If a hit is found within $[t_{min}, t_{max}]$, update $t_{min} \leftarrow t_{hit}$ [S3, unofficial]. If no hit, terminate.

3.  **Ray Marching Loop (Rendering Context):**
    *   Initialize `transmittance` = 1.0, `acc_density` = 0.0, `direct_light` = 0.0, `ambient_light` = 0.005 [S3, unofficial].
    *   Loop while `step` < `_RayMarchSamples` and `tmin` < `tmax` [S3, unofficial]:
        *   **Space Skipping (Dimension Check):** Calculate sample position `pos` from `tmin`. Get dimension `dim` using `get_dim_coord(pos)`. If `dim` > 1 (indicating empty space or boundary), increment `step`, add `skip_step` (e.g., 15) to `tmin`, set `skip` = `skip_step`, and continue [S3, unofficial].
        *   **Space Skipping (Density Check):** Evaluate scattering coefficient $\sigma_S$ at `pos`. If $\sigma_S < \text{MIN\_DENSITY}$ (e.g., 0.01), increment `step`, add `skip_step` (e.g., 5) to `tmin`, set `skip` = `skip_step`, and continue [S3, unofficial].
        *   **Backtracking:** If `skip` > 0, subtract `skip * 0.8` from `tmin` to re-enter the active region, recalculate `pos`, and reset `skip` = 0 [S3, unofficial].
        *   **Accumulation:**
            *   Add $\sigma_S$ to `acc_density`.
            *   Calculate scattered light $S = \sigma_S \times \text{phase\_function}() \times \text{volumetric\_shadow\_2}(pos, acc, \mathbf{d})$ [S3, unofficial].
            *   Calculate integrated scattering $S_{int} = \frac{S - S \cdot e^{-\sigma_E \cdot \text{step\_size}}}{\sigma_E}$ [S3, unofficial].
            *   Guard against division by zero: ensure $\sigma_E \ge 0.000001$ via $\sigma_E = \max(0.000001, \sigma_S)$ [S3, unofficial].
            *   Add `transmittance` $\times S_{int}$ to `direct_light` [S3, unofficial].
            *   Update `transmittance` $\leftarrow \text{transmittance} \times e^{-\sigma_E \cdot \text{step\_size}}$ [S3, unofficial].
        *   **Step Increment:** Increment `step`. Add `step_size` (e.g., 0.57) to `tmin` [S3, unofficial].

4.  **Final Color Calculation:**
    *   If visualizing steps, return gradient based on step count ratio [S3, unofficial].
    *   Otherwise, `final_color` = (`direct_light` + `ambient_light`) $\times$ `acc_density` [S3, unofficial].
    *   Apply gamma correction: `final_color` = $\text{pow}(\text{final\_color}, 1.0/2.2)$ [S3, unofficial].
    *   Return `float4(final_color, acc_density)` [S3, unofficial].

5.  **Shadow Ray Calculation (`volumetric_shadow_2`):**
    *   Initialize `shadow` = 1.0, `step_size` = 1.0, `jitter` = 0 [S3, unofficial].
    *   Loop 10 times:
        *   Calculate `sample_pos` = `pos` + (`jitter` + `step_size`) $\times$ `light_dir` [S3, unofficial].
        *   Get extinction coefficient $\sigma_E$ at `sample_pos` [S3, unofficial].
        *   Multiply $\sigma_E$ by 0.3 [S3, unofficial].
        *   Update `shadow` $\leftarrow \text{shadow} \times e^{-\sigma_E \cdot \text{step\_size}}$ [S3, unofficial].
        *   Increment `step`.
        *   Update `step_size` $\leftarrow \text{step\_size} \times (2 + \text{random\_float}(sample\_pos))$ [S3, unofficial].
    *   Return `shadow` [S3, unofficial].

**Pseudocode:**
```python
def hdda_march(grid, ray, auxiliary_mask=None):
    """
    Traverses a hierarchical grid using HDDA.
    Returns a list of (t_hit, value) tuples.
    """
    hits = []
    t_current = ray.tmin
    
    # Initialize accessor
    accessor = grid.get_root_accessor()
    
    while t_current < ray.tmax:
        # HDDA leapfrog step
        t_hit, value = hdda_next_hit(grid, accessor, ray, t_current)
        
        if t_hit is None or t_hit > ray.tmax:
            break
            
        # If auxiliary mask exists, check if hit is active
        if auxiliary_mask is not None:
            if not is_active_in_mask(auxiliary_mask, t_hit):
                t_current = t_hit + epsilon
                continue
                
        hits.append((t_hit, value))
        t_current = t_hit + epsilon
        
    return hits

def is_active_in_mask(mask, t_hit):
    """Check if a point is active in the binary auxiliary mask."""
    # Convert world pos to index space
    pos = mask.world_to_index(ray.origin + ray.direction * t_hit)
    # Check bit in binary grid
    return mask.get_bit(pos) == 1
```

## Operating characteristics
**Time Complexity:** Multi-resolution leapfrogging reduces traversal time from $O(N)$ (where $N$ is total voxels) to $O(K)$, where $K$ is the number of active tiles/voxels intersected [S1, unofficial][S2]. Template inlining reduces vertical navigation overhead [S1, unofficial][S2].
**Memory Complexity:** Low, as it traverses the tree without storing large intermediate lists (unlike Leaf Collection) [S1, unofficial]. Auxiliary mask adds $O(M)$ memory where $M$ is the number of voxels in the lower-resolution mask [S1, unofficial][S2].
**Performance:** Tested on RTX 3080 rendering WDAS cloud dataset at 1920x1080 in 6 ms [S3, unofficial].
**Strengths:** Efficient for sparse volumes; minimizes interpolation cost for level sets; handles non-linear transforms via auxiliary mask [S1, unofficial][S2].
**Limitations:** Requires compile-time fixed tree configuration for optimal inlining [S1, unofficial][S2]. Non-linear transforms require auxiliary grid generation [S1, unofficial][S2].

## Background
Originated by Ken Museth in OpenVDB v2, HDDA leverages the B+tree structure of VDB to perform multi-resolution leapfrogging [S1, unofficial][S2]. It was developed to accelerate ray-tracing of narrow-band level set surfaces and volume rendering (e.g., clouds) [S1, unofficial][S2]. The use of template meta-programming to collapse the hierarchical algorithm was a key innovation to reduce vertical navigation overhead [S1, unofficial][S2]. It is used in Unity HDRP for real-time volume rendering [S3, unofficial].
