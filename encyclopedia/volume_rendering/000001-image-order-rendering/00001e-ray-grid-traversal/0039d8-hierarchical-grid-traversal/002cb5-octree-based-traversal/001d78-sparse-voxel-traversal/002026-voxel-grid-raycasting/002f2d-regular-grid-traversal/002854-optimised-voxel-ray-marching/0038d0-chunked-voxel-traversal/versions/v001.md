# Chunked Voxel Traversal

Also called: Chunk-based Voxel Traversal, Fixed-step voxel ray marching

## Overview
Chunked Voxel Traversal is a hierarchical ray traversal method for sparse voxel grids that accelerates rendering by skipping empty space using a two-level 3D grid structure [S1, unofficial]. It combines the simplicity of a flat 3D grid with the efficiency of octrees by allowing large empty regions to be bypassed while maintaining fixed-step traversal within populated regions [S1, unofficial]. It is distinct from pure octree traversal by avoiding pointer chasing and dynamic node allocation, and from flat grid marching by reducing the number of visited cells in sparse scenes [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, chunk grid dimensions, chunk size $N \times N \times N$, voxel data buffer.
- Output: Hit voxel position, material properties, and accumulated color/transparency.

**Data Structures:**
1.  **Chunk Grid:** A 3D array of chunk headers. Each header indicates if the chunk is empty or contains data.
2.  **Voxel Data:** Compressed voxel information stored in a buffer. The source specifies compression to 8 bytes per voxel [S1, unofficial]. Material properties are stored separately from voxel geometry data [S1, unofficial].
3.  **Chunk Size:** Fixed at $8 \times 8 \times 8$ voxels per chunk [S1, unofficial].

**Algorithm Steps:**
1.  **Outer Traversal:** Use the Digital Differential Analyzer (DDA) algorithm to traverse the outer 3D grid of chunks along the ray [S1, unofficial].
2.  **Skip Empty Chunks:** If the current chunk is marked as empty, advance the DDA to the next chunk and repeat Step 1 [S1, unofficial].
3.  **Inner Traversal:** Upon finding a non-empty chunk, use the same DDA algorithm to traverse the voxels within that specific chunk [S1, unofficial].
4.  **Hit Detection:**
    - If a voxel is hit within the chunk, return the voxel information (position, material) to the outer loop and terminate the traversal [S1, unofficial].
    - If no voxel is hit in the chunk (e.g., the ray passes through empty space within the chunk or the chunk contains only transparent/empty voxels depending on implementation), continue the outer DDA loop to check the next chunk [S1, unofficial].
5.  **Transparency Handling:** For transparent voxels, a fraction of the transparent object's color is added to the color behind it. The traversal carries this transparent object information to the next voxel or chunk for final color determination [S1, unofficial].

**Pseudocode:**
```python
def chunked_voxel_traversal(ray_origin, ray_direction, chunk_grid, chunk_size=8):
    # Initialize DDA for outer chunk grid
    chunk_dda = DDA(ray_origin, ray_direction, chunk_grid.dimensions)
    
    while chunk_dda.has_next():
        chunk_pos = chunk_dda.current_chunk()
        
        # Check if chunk is empty
        if not chunk_grid.is_empty(chunk_pos):
            # Initialize DDA for inner voxel grid within the chunk
            # Note: Ray parameters must be adjusted to local chunk coordinates
            local_ray_origin = ray_origin - chunk_pos * chunk_size
            voxel_dda = DDA(local_ray_origin, ray_direction, chunk_size)
```

**Parameters:**
- Chunk dimensions: $8 \times 8 \times 8$ voxels [S1, unofficial].
- Voxel data size: 8 bytes per voxel [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Bitmask Application Order:** When compressing voxel data, applying bitmasks *after* shifting data results in zeroed-out data. The fix is to apply bitmasks *before* shifting [S1, unofficial].
- **Data Alignment:** Compressing data to 8 bytes requires careful handling of padding variables to maintain data alignment when transferring to the GPU [S1, unofficial].
- **Material Separation:** Material properties must be sent separately from voxel data to reduce transmission size [S1, unofficial].

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(K)$ where $K$ is the number of non-empty chunks and voxels visited. Significantly faster than flat grid traversal in sparse scenes due to skipping empty chunks.
- **Memory Complexity:** Depends on the number of non-empty chunks and the compressed voxel data size (8 bytes/voxel) [S1, unofficial].
- **Strengths:** Simple implementation, no pointer chasing, efficient for sparse data, easy to parallelize [S1, unofficial].
- **Limitations:** Fixed chunk size may lead to inefficiency if objects are smaller or larger than 8x8x8. Requires careful compression to fit data in VRAM [S1, unofficial].
- **When to use:** Sparse voxel worlds with large empty regions, real-time rendering on GPU where memory bandwidth is a constraint [S1, unofficial].
- **When not to use:** Dense voxel grids where flat traversal is sufficient, or scenes with highly variable object sizes where fixed chunks cause excessive fragmentation [S1, unofficial].

## Background
The method was described in an unofficial blog post by "ii-day-ii" in May 2023, as part of a voxel raytracer project [S1, unofficial]. The author sought a middle ground between 3D grid and octree approaches to skip empty space while limiting GPU data transmission [S1, unofficial]. The implementation faced challenges with GPU memory limits and data compression bugs, particularly related to bitmask application order [S1, unofficial].
