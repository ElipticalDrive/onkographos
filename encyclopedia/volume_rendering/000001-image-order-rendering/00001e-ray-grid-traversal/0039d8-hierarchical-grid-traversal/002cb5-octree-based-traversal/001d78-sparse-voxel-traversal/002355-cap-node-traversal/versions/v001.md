# Cap Node Traversal

Also called: Cap Node Traversal and Neighbor Finding, Cap intersection, Gargantini and Atkinson Octree Traversal (Cap Node Variant), Neighbor-finding with cap scalars

## Overview
Cap Node Traversal is a specialized ray traversal routine for "cap nodes" in sparse voxel octrees, which are leaf-like structures containing scalar data for a $2 \times 2 \times 2$ block of voxels [S1, S2][S3, unofficial]. It solves the problem of efficiently retrieving voxel values and performing isosurface intersection without the overhead of recursive descent into child nodes [S1, S2][S3, unofficial]. It differs from standard interior node traversal by replacing the isovalue range check and recursive child call with direct scalar retrieval and local neighbor finding [S1, S2][S3, unofficial]. It is distinct from [Scalar Leaves](1525-sparse-voxel-traversal.md) (which have homogeneous values) and [Sparse Voxel Traversal](1525-sparse-voxel-traversal.md) (which handles general sparse structures) by specifically optimizing the $2 \times 2 \times 2$ boundary case [S1, S2][S3, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o}$, ray direction $\mathbf{d}$, current cap node $C$, isovalue $I$.
**Outputs:** Isosurface intersection point (if any), or traversal continuation.

**Data Structures:**
*   **Cap Node ($C$):** Contains a scalar array `scalars` of size 8.
    *   `scalars[i]`: Scalar value for the $i$-th voxel in the $2 \times 2 \times 2$ block, where $i \in [0, 7]$.
    *   The index $i$ corresponds to the child octant index in the parent octree structure.

**Steps:**
1.  **Cap Intersection:** Perform the standard octree traversal step to determine which of the 8 voxels (octants) the ray intersects within the cap node [S1, S2][S3, unofficial]. Let the intersected child octant index be $child \in [0, 7]$ [S1, S2][S3, unofficial].
2.  **Voxel Value Retrieval:** Determine the scalar values of the 8 voxels composing the cell [S1, S2][S3, unofficial]. These are stored directly in $C$.scalars[0..7] [S1, S2][S3, unofficial].
3.  **Isosurface Check:** Check if the isovalue $I$ lies within the minimum and maximum of the 8 voxel values [S1, S2][S3, unofficial].
    *   Let $V_{min} = \min(C.\text{scalars}[0..7])$ and $V_{max} = \max(C.\text{scalars}[0..7])$ [S1, S2][S3, unofficial].
    *   If $I < V_{min}$ or $I > V_{max}$, no isosurface exists within this cap node. Return or continue traversal [S1, S2][S3, unofficial].
4.  **Neighbor Finding (if required):** If the isosurface check passes, determine the values of the 8 voxels for isosurface intersection [S1, S2][S3, unofficial]. For the intersected voxel $child$, identify neighbors within the same cap node [S1, S2][S3, unofficial].
    *   For a desired neighbor direction $dir \in [0, 7]$ from the child octant $child$:
        *   Check if $(child \ \& \ dir) == 0$ [S1, S2][S3, unofficial].
        *   If false (i.e., $(child \ \& \ dir) == 0$), the neighbor is simply $C.\text{scalars}[dir]$ [S1, S2][S3, unofficial].
        *   If true (i.e., $(child \ \& \ dir) \neq 0$), proceed with neighbor-finding to retrieve the value from outside the cap node [S1, S2][S3, unofficial].
5.  **Isosurface Intersection:** Perform isosurface intersection using the 8 voxel values as corners of the cell [S1, S2][S3, unofficial]. This involves solving a cubic polynomial for the ray intersection with the trilinearly interpolated surface [S2][S3, unofficial].

**Pseudocode:**
```python
def cap_node_traversal(ray_o, ray_d, cap_node, isovalue):
    # Step 1: Determine intersected child octant (standard octree traversal)
    # This assumes a standard octree traversal routine exists that returns the child index
    child = octree_traverse_step(ray_o, ray_d, cap_node.bounds)
    
    # Step 2: Retrieve scalar values
    scalars = cap_node.scalars  # Array of 8 floats
    
    # Step 3: Isosurface check
    min_val = min(scalars)
    max_val = max(scalars)
    
    if isovalue < min_val or isovalue > max_val:
        return None  # No intersection in this cap node
    
    # Step 4: Neighbor finding for the 8 voxels
    # We need the values of all 8 voxels for isosurface intersection
    # For the intersected voxel 'child', we need its neighbors
    # However, for full isosurface intersection, we need all 8 corner values
    # which are already in scalars. The neighbor finding is primarily for
    # determining if the surface crosses the boundary of the cap node
    # or for gradient calculation if needed.
    
    # For each of the 8 voxels, determine if its neighbors are within the cap
    voxel_values = []
    for i in range(8):
        # The value of voxel i is simply scalars[i]
        voxel_values.append(scalars[i])
        
    # Step 5: Isosurface intersection
    # Solve for intersection with trilinearly interpolated cell
    # This is a standard step after obtaining the 8 corner values
    hit = solve_cubic_isosurface(ray_o, ray_d, voxel_values, cap_node.bounds)
    
    return hit
```

**Parameters:**
*   **Isovalue:** The scalar value defining the isosurface. Typical values depend on the dataset [S1, S2][S3, unofficial].
*   **Cap Node Depth:** The depth at which cap nodes are defined. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Neighbor Finding:** Neighbor finding is only required when the neighbor lies outside the immediate local cap node structure defined by the bitwise check; otherwise, direct array access is used [S1, S2][S3, unofficial].
*   **Precision:** Standard floating-point precision issues may apply to isosurface intersection [S2][S3, unofficial].
*   **Degenerate Input:** If all 8 voxel values are identical, no isosurface is encountered [S3, unofficial].

## Subtopics

### Scalar Leaves
A leaf-like structure with homogeneous scalar values. Traversed recursively to the same depth as caps. If a neighborhood of identical voxels is encountered, no isosurface is present. Neighbor-finding is performed at borders. See [Scalar Leaves](1525-sparse-voxel-traversal.md).

### Interior Node Traversal
The standard octree traversal routine that cap node traversal modifies. It involves checking isovalue against min/max ranges and recursively calling child traversal [S1, S2][S3, unofficial]. See [Octree Traversal](1587-octree-traversal.md).

## Operating characteristics
*   **Time Complexity:** $O(1)$ for scalar retrieval and isosurface check within a cap node, assuming the child octant is determined. Neighbor finding may add overhead if neighbors are outside the cap [S1, S2][S3, unofficial].
*   **Memory Complexity:** $O(1)$ per cap node, storing 8 scalar values [S1, S2][S3, unofficial].
*   **Strengths:** Avoids recursive descent overhead for leaf-like structures. Efficient for datasets with many $2 \times 2 \times 2$ homogeneous or near-homogeneous regions [S1, S2][S3, unofficial].
*   **Limitations:** Requires specific data structure support for cap nodes. Neighbor finding logic adds complexity [S1, S2][S3, unofficial].
*   **When to Use:** When the octree contains many cap nodes (leaf-like structures with scalar data) and efficient isosurface intersection is required [S1, S2][S3, unofficial].
*   **When Not to Use:** When the dataset does not benefit from cap node optimization (e.g., fully sparse or fully dense) [S1, S2][S3, unofficial].

## Background
Cap Node Traversal was introduced in the context of interactive isosurface ray tracing of large octree volumes [S1, S2][S3, unofficial]. It is part of the Gargantini and Atkinson octree traversal method, specifically the cap node variant [S1, S2][S3, unofficial]. The method was developed to optimize ray traversal for sparse voxel octrees by handling leaf-like structures efficiently [S1, S2][S3, unofficial].
