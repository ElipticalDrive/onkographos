# Ordered List Generation via N3-Tree Traversal

Also called: Depth-first ordered traversal, View-dependent tree traversal

## Overview
This method generates a list of spatial bricks ordered from closest to furthest relative to the viewpoint to avoid testing blocks behind untested unloaded blocks [S1, unofficial]. It solves the problem of unnecessary data loading by ensuring that visibility tests are performed in an order where any previously reached node cannot be occluded by a subsequently reached node [S1, unofficial]. It sets itself apart from sibling methods by integrating view-dependent axis prioritization directly into a depth-first traversal of the N3-tree structure, followed by a lightweight distance sort [S1, unofficial].

## How it works
**Inputs:**
- The root of the N3-tree [S1, unofficial].
- The viewpoint direction vector $\vec{V} = (V_x, V_y, V_z)$ [S1, unofficial].
- $N$, the number of subdivisions per node in the hierarchy [S1, unofficial].
- The viewpoint position $\vec{P}$, required for the final distance sort [G].

**Outputs:**
- A list of bricks ordered by strict distance to the viewpoint [S1, unofficial].

**Data Structures:**
- **N3-tree:** A hierarchical structure where each node represents a grid of children with $N$ subdivisions along each axis [S1, unofficial].
- **Traversal List:** A dynamic array that accumulates visited nodes during the depth-first pass [S1, unofficial].

**Algorithm Steps:**
1. **Initialize:** Begin a depth-first traversal at the root node [S1, unofficial].
2. **View-Dependent Axis Ordering:** At each node, determine the child visitation order by sorting the three axes based on the absolute values of the viewpoint direction vector components [S1, unofficial].
3. **Start Element Calculation:** Compute the starting grid index for each axis using the step formula [S1, unofficial].
4. **Grid Traversal:** Iterate through the $N \times N \times N$ children of the current node, prioritizing the axis with the smallest view component as the outermost loop [S1, unofficial].
5. **Recursion:** For each child, repeat steps 2–4 until leaf nodes are reached [S1, unofficial].
6. **Distance Sorting:** Sort the accumulated list by Euclidean distance to the viewpoint to prioritize nearest bricks [S1, unofficial].

**Formulas:**
The starting element $E_{xyz}$ for each axis component is calculated as [S1, unofficial]:

$$
E_{xyz} = \text{step}(0, V_{xyz}) \times (N - 1)
$$

Where $\text{step}(0, V_{xyz})$ is defined as [S1, unofficial]:

$$
\text{step}(0, V_{xyz}) = 
\begin{cases} 
0 & \text{if } V_{xyz} < 0 \\
1 & \text{otherwise}
\end{cases}
$$

Here, $V_{xyz}$ represents the component of the viewpoint direction vector along the respective axis, and $N$ is the number of subdivisions of the nodes [S1, unofficial].

**Parameters:**
- $N$: Number of subdivisions of the nodes in the hierarchy [S1, unofficial].
- $\vec{V}$: Viewpoint direction vector components $V_x, V_y, V_z$ [S1, unofficial].

**Pseudocode:**

```python
import math

def generate_ordered_list(root_node, view_vector, N, viewpoint_pos):
    """
    Generates a list of bricks ordered from closest to furthest using N3-tree traversal.
    """
    ordered_list = []

    def get_axis_order(view_vec):
        axes = [0, 1, 2]
        axes.sort(key=lambda i: abs(view_vec[i]))
        return axes

    def get_start_index(axis_idx, view_vec, N):
        v_comp = view_vec[axis_idx]
        step_val = 0 if v_comp < 0 else 1
        return step_val * (N - 1)

    def traverse(node):
        if node.is_leaf():
            ordered_list.append(node)
            return

        sorted_axes = get_axis_order(view_vector)
        start_indices = [get_start_index(ax, view_vector, N) for ax in sorted_axes]

        # The source specifies the starting element and axis priority for child traversal,
        # but does not detail the exact iteration pattern for the full N^3 grid.
        # We iterate through all children, prioritizing the axes as outer loops.
        a, b, c = sorted_axes
        start_a, start_b, start_c = start_indices

        for i in range(N):
            for j in range(N):
                for k in range(N):
                    child = node.get_child(i, j, k)
                    traverse(child)

    traverse(root_node)

    # Sort the list by distance to the viewpoint to prioritize nearest bricks
    ordered_list.sort(key=lambda node: math.dist(node.center, viewpoint_pos))
    return ordered_list
```

**Edge Cases and Pitfalls:**
- **View Vector Alignment:** If a component of the view vector is zero, the tie-breaking for axis order is not specified in the sources [S1, unofficial]. [G] A deterministic tie-breaker (e.g., fixed axis priority $x < y < z$) should be used.
- **Boundary Conditions:** The formula assumes $N \ge 1$. If $N=1$, the start index is always $0$ [S1, unofficial].
- **Precision:** Floating-point comparisons for $V_{xyz} < 0$ should handle near-zero values carefully to avoid jitter in traversal order [G].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of nodes visited, $O(M)$, as the ordered traversal is not more expensive than an arbitrary traversal [S1, unofficial].
- **Memory Complexity:** Linear with respect to the number of nodes in the output list, $O(M)$, plus $O(D)$ for the recursion stack where $D$ is the tree depth [G].
- **Performance:** The method avoids unnecessary loading of occluded blocks by ensuring that visibility tests are performed in occlusion order [S1, unofficial].
- **Strengths:** The N3-tree structure allows easy traversal in occlusion order, ensuring that any node already reached cannot be occluded by a node reached later [S1, unofficial].
- **Limitations:** The initial traversal provides an occlusion order but not a strict distance order, requiring a sorting step to prioritize nearest bricks [S1, unofficial].

## Background
The method originates from research on interactive exploration of procedural volumes, specifically utilizing the N3-tree structure [S1, unofficial]. It was developed to optimize visibility detection by providing a list of bricks ordered from closest to furthest, thereby minimizing the loading of occluded blocks [S1, unofficial]. The N3-tree structure facilitates this by allowing easy traversal in occlusion order [S1, unofficial]. Sorting from a list already ordered by a close criterion allows rapid convergence of the sorting algorithm, greatly improving visibility algorithm efficiency without additional traversal cost [S1, unofficial].
