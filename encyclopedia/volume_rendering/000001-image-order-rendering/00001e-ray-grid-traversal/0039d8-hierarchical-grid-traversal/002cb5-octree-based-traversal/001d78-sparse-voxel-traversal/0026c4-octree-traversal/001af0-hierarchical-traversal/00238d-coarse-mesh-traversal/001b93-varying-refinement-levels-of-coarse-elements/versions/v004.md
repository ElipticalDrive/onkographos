# Varying Refinement Levels of Coarse Elements

Also called: Coarse mesh refinement level variation, Inserting refinement levels into coarse mesh

## Overview
This method optimizes hierarchical volume rendering by controlling the granularity of the coarse mesh (BVH) through the selective insertion of elements from specific refinement levels of the underlying adaptive mesh. It solves the trade-off between BVH traversal efficiency and fine-level sampling overhead by allowing the renderer to choose how deep into the refinement tree elements are collected to form macrocells [S1, unofficial]. It differs from fixed-level coarse meshing by dynamically adjusting the macrocell size to balance BVH node count against the depth of the subsequent fine-level traversal [S1, unofficial].

## How it works
The method extends the standard Coarse Mesh Traversal by modifying the macrocell construction phase. Instead of collecting all leaf elements or a fixed set of nodes, the algorithm traverses the refinement tree to a user-defined depth or level.

**Inputs:**
*   The adaptive mesh refinement (AMR) tree structure.
*   A target refinement level $L$ (integer $\ge 0$).
*   The ray origin $\mathbf{o}$ and direction $\mathbf{d}$.
*   Macrocell optimization flags (e.g., Woodcock majorants).

**Outputs:**
*   A coarse mesh (BVH) containing elements from the specified refinement level or their nearest ancestors if they are leaves.
*   Rendered image samples.

**Data Structures:**
*   **Refinement Tree Node:** Contains pointers to children and density/geometry data.
*   **Coarse Mesh Element:** Represents a macrocell. Stores bounding box, density statistics (for culling/majorants), and a reference to the fine-level subtree root for nested traversal.

**Steps:**
1.  **Tree Traversal:** For each root of a refinement tree (or the global root), traverse the children.
2.  **Level Check:** For each node, check its current refinement level.
3.  **Selection:**
    *   If the node's level is less than the target level $L$, continue traversing its children.
    *   If the node's level is equal to $L$, or if the node is a leaf (regardless of level), stop traversing this branch.
4.  **Insertion:** Add the selected node to the coarse mesh. This node becomes a macrocell.
5.  **BVH Construction:** Build or update the BVH using these macrocells as leaf nodes.
6.  **Rendering:** Perform standard hierarchical traversal. For each active macrocell, enter the nested fine-level traversal loop bounded by the macrocell's entry/exit distances [S1, unofficial].

**Pseudocode:**
```python
def build_coarse_mesh(refinement_tree, target_level):
    """
    Builds a coarse mesh by inserting elements from the refinement tree
    up to the specified target_level.
    """
    coarse_mesh_elements = []
    
    def traverse(node, current_level):
        # Base case: if we reached the target level or a leaf, add to coarse mesh
        if current_level == target_level or node.is_leaf():
            coarse_mesh_elements.append(node)
            return
        
        # Recursive step: traverse children
        for child in node.children:
            traverse(child, current_level + 1)

    # Start traversal from the root
    traverse(refinement_tree.root, 0)
    
    # Build BVH from the collected elements
    bvh = build_bvh(coarse_mesh_elements)
    return bvh
```

**Parameters:**
*   **Refinement Level ($L$):** The depth in the AMR tree where elements are harvested. $L=0$ typically means the root or very coarse elements; higher $L$ means finer, smaller macrocells.
*   **Faces per Element:** In the cited experiments, BVH elements had 4 faces [S1, unofficial].

**Edge Cases:**
*   **Leaf Premature Termination:** If a refinement tree is shallower than $L$, the algorithm stops at the leaf. This ensures all parts of the domain are covered, even if some macrocells are larger than others [S1, unofficial].
*   **Memory Blow-up:** High $L$ values can lead to a very large number of macrocells, increasing BVH memory usage and traversal overhead [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** BVH construction time increases with $L$ due to the larger number of leaf nodes. Ray traversal time depends on the balance between BVH traversal cost and fine-level sampling cost.
*   **Memory Complexity:** Memory usage for the coarse mesh scales linearly with the number of elements inserted. Higher $L$ leads to more elements and higher memory consumption [S1, unofficial].
*   **Performance:**
    *   **BVH Efficiency:** Increasing the number of elements (higher $L$) generally decreases BVH efficiency and maximum traversal depth [S1, unofficial].
    *   **Dataset Dependency:**
        *   **Engine Dataset:** Performance degraded with higher $L$ for both Ray Marcher and Woodcock methods, as the BVH overhead outweighed any benefits [S1, unofficial].
        *   **Uniform Engine Dataset:** Performance improved slightly at $L=1$ for the Ray Marcher because the reduction in refinement tree traversal depth compensated for BVH overhead. For Woodcock, $L=1$ and $L=2$ improved performance due to tighter majorants from smaller macrocells [S1, unofficial].
*   **Strengths:** Allows tuning for specific scene characteristics (e.g., uniform vs. adaptive density). Can improve Woodcock tracking by providing tighter bounding volumes.
*   **Limitations:** Not universally beneficial; can hurt performance if the BVH becomes too large or inefficient. Requires experimentation to find the optimal level [S1, unofficial].

## Background
This technique was explored in the context of direct volume rendering of tree-based tetrahedral adaptive mesh refinement (TET-AMR) data. The research investigated how varying the granularity of the coarse mesh affects the performance of nested ray traversal methods, specifically comparing Ray Marching and Woodcock tracking [S1, unofficial]. The study highlighted that while finer coarse meshes (higher refinement levels) reduce the depth of the fine-level traversal, they increase the cost of the coarse-level BVH traversal, leading to a non-linear performance trade-off that depends heavily on the data distribution [S1, unofficial].
