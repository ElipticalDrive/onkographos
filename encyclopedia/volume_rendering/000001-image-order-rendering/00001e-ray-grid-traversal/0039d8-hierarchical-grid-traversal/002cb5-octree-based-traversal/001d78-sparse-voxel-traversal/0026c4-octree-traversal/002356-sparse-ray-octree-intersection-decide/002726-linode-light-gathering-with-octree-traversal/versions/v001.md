# LiNode Light Gathering with Octree Traversal

Also called: LiNode::gather

## Overview
LiNode Light Gathering is a ray-surfel intersection method that traverses an octree of surfels to determine the closest hit color and distance for a given ray. It solves the problem of efficiently gathering lighting information from a sparse, hierarchical surfel representation. It differs from its siblings by operating on surfel primitives within octree leaves rather than triangles (Octree Voxel-Triangle Intersection Test), using deterministic traversal rather than stochastic estimation (Woodcock Collision Estimation with Octree Acceleration), or performing point queries (Octree Point Search for Closest Point).

## How it works
**Inputs and Outputs:**
- Input: A ray defined by origin and direction, and a root `LiNode` (octree node) containing surfels.
- Output: The closest hit color and the distance to the hit point (`t`).

**Data Structures:**
- `LiNode`: Inherits from `OctreeNode`. Contains `min` and `max` bounding box corners, `_surfelCount` (integer), and `_surfelData` (array of `shared_ptr<Surfel>`).
- `Surfel`: Contains position, normal, and color data. Accessible via methods like `normal()` and `position()`.
- `MAX_SURFEL_COUNT`: The maximum number of surfels a leaf node can hold before subdivision. Not given in the sources.

**Steps:**
1. Initialize `tmin` to infinity and `closest` to the background color configuration.
2. Test the ray intersection with the current octree node's bounding box using `OctreeNode::test_intersect`.
3. If no intersection is found, set `*t` to infinity and return the background color.
4. If the node has children:
   - Iterate through all 8 children.
   - Recursively call `gather` on each child.
   - Update `tmin` and `closest` if a child returns a hit with a smaller distance.
5. If the node is a leaf:
   - Check if the ray origin is inside the leaf's bounding box. If so, return the background color with `*t` set to infinity.
   - Iterate through all surfels in `_surfelData` (up to `_surfelCount`).
   - For each surfel:
     - Transform the ray into the surfel's local space.
     - Normalize the ray direction.
     - Perform backface culling: if `s->normal() * (ray.direction * -1) > 0`, skip the surfel.
     - Test for intersection between the ray and the surfel.
     - If an intersection is found and the distance is less than `tmin`, update `tmin` and `closest` with the surfel's color.
6. Set `*t` to `tmin` and return `closest`.

**Pseudocode:**
```python
def gather(ray, node):
    # Step 1: Initialize
    tmin = INFINITY
    closest = config.background

    # Step 2: Node intersection test
    if not node.test_intersect(ray):
        ray.t = INFINITY
        return config.background

    # Step 4: Internal node
    if node.has_children():
        for i in range(8):
            child_t, child_color = gather(ray, node.child(i))
            if child_t < tmin:
                tmin = child_t
                closest = child_color
        ray.t = tmin
        return closest

    # Step 5: Leaf node
    # Check if ray start is inside bounding box
    if node.is_inside(ray.origin):
        ray.t = INFINITY
        return config.background

    # Iterate surfels
    for i in range(node._surfelCount):
        surfel = node._surfelData[i]
        
        # Transform ray to surfel local space
        local_ray = transform_ray_to_local(ray, surfel)
        local_ray.direction = normalize(local_ray.direction)
        
        # Backface culling
        # s->normal() * (ray.direction * -1) > 0
        if dot(surfel.normal(), -local_ray.direction) > 0:
            continue
            
        # Test intersection
        hit_t, hit_color = test_surfel_intersection(local_ray, surfel)
        
        if hit_t is not None and hit_t < tmin:
            tmin = hit_t
            closest = hit_color

    ray.t = tmin
    return closest
```

**Parameters and Edge Cases:**
- `MAX_SURFEL_COUNT`: When a leaf node exceeds this count, it subdivides into 8 children and re-adds the surfels. Not given in the sources.
- Precision: Ray transformation to local space requires careful handling of floating-point precision to avoid false negatives in intersection tests.
- Degenerate Input: Rays originating inside a leaf node are handled by returning the background color, preventing self-intersection artifacts.

## Subtopics

### Surfel-based Spherical Harmonic Lighting
This variant processes lighting information from surfels in a leaf node by projecting them onto Spherical Harmonics. It is chosen when compact lighting representation is needed for global illumination or ambient occlusion. It differs from standard LiNode gathering by aggregating lighting data rather than finding a single closest hit.
- **Steps**:
  1. For each leaf node in the LiNode hierarchy, if `_surfelCount` is zero, return immediately.
  2. Collect all surfels from `_surfelData` into a vector of shared pointers named `surf_list`.
  3. Project the lighting onto Spherical Harmonics by calling `SHProject(surf_list, 2, sh_c)`.
- **Parameters**: `SHProject` order is hardcoded to 2, resulting in 9 coefficients.
- **Layout**: `sh_c` is an array of 9 Spherical Harmonic coefficients (indices 0-8).

## Operating characteristics
- **Time Complexity**: $O(N)$ in the worst case where $N$ is the number of surfels, but typically $O(\log N)$ due to octree pruning.
- **Memory Complexity**: $O(N)$ to store surfels and octree nodes.
- **Strengths**: Efficient culling of non-intersecting nodes and surfels. Simple implementation.
- **Limitations**: Performance degrades if the octree is unbalanced or if rays intersect many surfels. Backface culling is simple and may not handle complex geometry well.
- **When to use**: Real-time rendering with surfel-based representations.
- **When not to use**: Scenes with high-frequency lighting variations requiring higher-order SH or precise ray-triangle intersection.

## Background
LiNode Light Gathering is part of the Mr-Voxel project, an open-source voxel-based renderer. It was developed by cgibson as part of the broader effort to create a flexible volume and surfel rendering engine. The method leverages the hierarchical structure of the octree to accelerate ray-surfel intersection tests.
