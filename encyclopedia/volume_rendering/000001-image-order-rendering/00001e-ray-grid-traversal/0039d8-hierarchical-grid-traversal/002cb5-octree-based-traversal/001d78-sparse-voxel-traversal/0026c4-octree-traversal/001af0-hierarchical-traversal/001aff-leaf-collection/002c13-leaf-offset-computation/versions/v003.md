# Leaf Offset Computation

Also called: IndexGridBuilder::computeLeafs

## Overview
Leaf Offset Computation calculates the linear memory offsets for each leaf node in an OpenVDB tree to facilitate parallel processing and data copying [S1, unofficial]. It serves as a prerequisite for [Leaf Processing](5189-leaf-processing.md), which uses these offsets to copy precomputed voxel data from a contiguous source buffer into leaf node buffers [S1, unofficial]. Unlike [Leaf Node Representation](3000-leaf-node-representation.md), which defines the internal structure of a leaf, this method computes the external indexing required to map leaf nodes to a flat memory space.

## How it works
**Inputs:** An OpenVDB tree (`m_domainGrid->tree()`).
**Outputs:** A vector `m_leafOffsets` containing cumulative offsets, and an integer `m_totalVoxels`.

**Data Structures:**
- `m_leafOffsets`: A `std::vector<size_t>` of size $N+1$, where $N$ is the number of leaves.
- `m_totalVoxels`: A `size_t` representing the total number of voxels in all leaves.
- `LeafNodeType::SIZE`: The constant number of voxels per leaf node (typically $8^3 = 512$ for standard OpenVDB).

**Steps:**
1. Retrieve the tree from the domain grid.
2. Create a `LeafManager` instance wrapping the tree to facilitate leaf counting.
3. Store the leaf count in `m_numLeaves`.
4. Resize `m_leafOffsets` to hold $N+1$ elements.
5. Calculate `m_totalVoxels` as $N \times \text{LeafNodeType::SIZE}$.
6. Generate a sequence of indices from $0$ to $N-1$.
7. Compute offsets in parallel: for each index $i$, set `m_leafOffsets[i] = i * LeafNodeType::SIZE`.
8. Set the final offset `m_leafOffsets[N]` to `m_totalVoxels`. This final element acts as a boundary marker for parallel iteration ranges.

**Pseudocode:**
```python
def compute_leaf_offsets(tree):
    # Step 1: Retrieve tree
    # const auto& tree = m_domainGrid->tree();
    
    # Step 2: Create LeafManager
    # const openvdb::tree::LeafManager leafManager{tree};
    
    # Step 3: Store leaf count
    num_leaves = leafManager.leaf_count()
    
    # Step 4: Resize offset array
    # m_leafOffsets.resize(num_leaves + 1)
    leaf_offsets = [0] * (num_leaves + 1)
    
    # Step 5: Calculate total voxels
    # m_totalVoxels = m_numLeaves * LeafNodeType::SIZE
    leaf_size = 512  # Standard OpenVDB leaf size (8^3)
    total_voxels = num_leaves * leaf_size
    
    # Step 6: Generate indices
    # std::vector<size_t> indices(m_numLeaves); std::iota(indices.begin(), indices.end(), 0);
    indices = list(range(num_leaves))
    
    # Step 7: Compute offsets in parallel
    # std::transform(std::execution::par_unseq, indices.begin(), indices.end(), m_leafOffsets.begin(), 
    #                [](size_t i) { return i * LeafNodeType::SIZE; });
    for i in indices:
        leaf_offsets[i] = i * leaf_size
        
    # Step 8: Set final offset
    # m_leafOffsets[m_numLeaves] = m_totalVoxels
    leaf_offsets[num_leaves] = total_voxels
    
    return leaf_offsets, total_voxels
```

**Parameters:**
- `LeafNodeType::SIZE`: Typically 512 for 8x8x8 leaves. Not given in the sources for other configurations.

**Edge Cases:**
- If `num_leaves` is 0, the vector contains two zeros.
- Precision: Uses `size_t` (unsigned integer) to prevent overflow for large scenes.

## Subtopics

### [Leaf Processing](5189-leaf-processing.md)
Copies precomputed voxel data from a contiguous source buffer into the leaf node buffers of an OpenVDB tree in parallel. It executes the actual memory copy operations using offsets generated by Leaf Offset Computation. Choose this when you need to populate leaf nodes with data after computing offsets.

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of leaves. The parallel transform scales with available cores.
- **Memory Complexity:** $O(N)$ for the offset vector.
- **Strengths:** Simple, deterministic, and highly parallelizable. Provides a clean boundary marker for subsequent parallel loops.
- **Limitations:** Assumes uniform leaf size. Does not handle variable-sized leaves or sparse leaf distributions differently than dense ones (it counts active leaves).
- **When to use:** When preparing for bulk data transfer into OpenVDB leaf nodes.
- **When not to use:** If leaf sizes vary or if a different memory layout is required.

## Background
Originated in the HNanoSolver project [S1, unofficial]. It is part of the index building pipeline for efficient volume rendering on GPU/CPU hybrid architectures.
