# Back-Face Culling for Ray Casting

Also called: Backface Raycasting, Raycasting with depth buffers, Raycasting with depth pre-pass, Front/Backface Buffer Raycasting, Two-pass depth buffer raycasting, Back-face depth culling raycasting, Back-face culling for entry/exit determination, Two-Pass Raycasting with Back-Face Depth Buffering, Two-Pass Raycasting with Backface Entry/Exit Points

## Overview
Back-face culling for ray casting is an optimization technique that determines the entry and exit points of rays into a volume by rendering the back faces of the volume's bounding box to a texture, thereby avoiding the need to compute ray-cube intersections analytically in the raycasting shader [S1, S2, S3, S4, unofficial]. It builds on [Coarse Mesh Traversal with Dual-Ray Culling](987-coarse-mesh-traversal-with-dual-ray-culling.md) by applying the principle of using front/back face distinction to a simple bounding box primitive, offloading geometry processing to the GPU rasterizer [S1, S2, unofficial]. Unlike single-pass methods that compute intersections in the fragment shader, this approach uses a two-pass rendering pipeline: the first pass captures the back-face depth/position, and the second pass uses this data to initialize the ray march, skipping empty space outside the volume [S2, S4, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume density data (3D texture), transfer function (1D or 2D texture), camera view/projection matrices, bounding box geometry (cube).
*   **Outputs:** Final composited image (color buffer).

**Data Structures:**
1.  **Bounding Box Geometry:** A cube defined by 8 vertices and 12 triangles (36 vertices if unindexed). Each vertex has:
    *   `VerPos` (vec3): Position in object space.
    *   `VerClr` (vec3): Color, used to pass the 3D position of the vertex to the fragment shader [S2, unofficial].
2.  **Back-Face Texture (`g_bfTexObj` / `texBackFaces`):** A 2D texture (RGBA, UNSIGNED_BYTE or FLOAT depending on extension support) storing the 3D entry point coordinates for each pixel [S2, S4, unofficial].
    *   Dimensions: Width x Height (screen resolution) [S4, unofficial].
    *   Initialization: Zeros [S4, unofficial].
    *   Filters: LINEAR for MIN/MAG, CLAMP_TO_EDGE for S/T [S4, unofficial].
3.  **Volume Texture (`g_volTexObj` / `uVolData`):** A 3D texture (sampler3D) storing density values [S2, S3, S4, unofficial]. Requires `OES_texture_float` extension in WebGL for floating-point data [S4, unofficial].
4.  **Transfer Function Texture (`trfunc_texture`):** A 2D texture (sampler2D) mapping density to color [S3, unofficial].
5.  **Frame Buffer:** A framebuffer object containing:
    *   Depth Buffer: Renderbuffer of type `DEPTH_COMPONENT16` [S4, unofficial].
    *   Color Texture: 2D texture attached as color attachment [S4, unofficial].

**Numbered Steps:**

1.  **Pass 1: Back-Face Depth Capture**
    1.  Bind the auxiliary framebuffer.
    2.  Enable depth testing.
    3.  Set depth function to `GEQUAL` [S4, unofficial].
    4.  Enable front-face culling (cull front faces, render back faces) [S1, S3, unofficial]. Note: Assumes counter-clockwise (CCW) winding order where normals point out; back faces have negative dot product with view direction [S1, unofficial].
    5.  Use the "back" shader program.
    6.  Draw the bounding box cube.
        *   **Vertex Shader:** Transforms `VerPos` to clip space (`gl_Position`). Passes `VerClr` (vertex position) as `EntryPoint` to the fragment shader [S2, unofficial].
        *   **Fragment Shader:** Outputs `VerClr` (the 3D entry point) as `FragColor` [S2, unofficial].
    7.  Store the resulting color buffer into `g_bfTexObj` [S2, unofficial].

2.  **Pass 2: Raycasting**
    1.  Bind the default framebuffer.
    2.  Enable depth testing.
    3.  Set depth function to `LEQUAL` [S4, unofficial].
    4.  Enable back-face culling (cull back faces, render front faces) [S3, unofficial].
    5.  Bind `g_bfTexObj` to texture unit 0 (`uBackCoord`) [S4, unofficial].
    6.  Bind `uVolData` (volume texture) to texture unit 1 [S4, unofficial].
    7.  Use the "raycast" shader program.
    8.  Draw the bounding box cube again.
        *   **Vertex Shader:** Transforms `VerPos` to clip space. Passes `VerClr` as `EntryPoint` (front face position) [S2, unofficial].
        *   **Fragment Shader:**
            1.  Sample `uBackCoord` using screen coordinates (`gl_FragCoord.st / ScreenSize`) to retrieve the 3D exit point (`exitPoint`) [S2, unofficial].
                *   *Pitfall:* `gl_FragCoord` provides window-space coordinates. The texture was written with clip-space positions transformed by the rasterizer. Direct sampling using `gl_FragCoord` avoids manual perspective division errors [S2, unofficial].
            2.  If `EntryPoint` equals `exitPoint` (no back-face hit, e.g., background), discard the fragment [S2, unofficial].
            3.  Calculate ray direction: `dir = exitPoint - EntryPoint` [S3, unofficial].
            4.  Calculate ray length: `len = length(dir)` [S3, unofficial].
            5.  Calculate step vector: `deltaDir = normalize(dir) * StepSize` [S3, unofficial].
            6.  Initialize accumulators: `col_acc = vec4(0,0,0,0)`, `alpha_acc = 0.0`, `length_acc = 0.0`, `ray_pos = EntryPoint` [S3, unofficial].
            7.  Loop for `NUM_RAY_STEPS` (e.g., 512) iterations:
                1.  Sample density: `density = texture(uVolData, ray_pos).x` [S3, unofficial].
                2.  Map to color: `color_sample = texture(trfunc_texture, vec2(density, 0.5))` [S3, unofficial].
                3.  Calculate sample alpha: `alpha_sample = density * StepSize` [S3, unofficial].
                4.  Front-to-back blending: `col_acc += (1.0 - alpha_acc) * color_sample * alpha_sample * 40.0` [S3, unofficial].
                5.  Update alpha: `alpha_acc += alpha_sample` [S3, unofficial].
                6.  Update length: `length_acc += length(deltaDir)` [S3, unofficial].
                7.  Advance ray: `ray_pos += deltaDir` [S3, unofficial].
                8.  Termination Conditions:
                    *   If `length_acc >= len`, composite background (white, alpha 0) and break [S2, unofficial].
                    *   If `alpha_acc > 1.0`, clamp to 1.0 and break [S2, unofficial].
            8.  Output `col_acc` as fragment color [S3, unofficial].

**Pseudocode:**

```python
# Pass 1: Back-Face Capture
def pass1_backface_capture(framebuffer, cube, back_shader, view_proj_matrix):
    bind_framebuffer(framebuffer)
    enable_depth_test()
    set_depth_func(GEQUAL)
    enable_cull_face(FRONT) # Cull front faces, render back faces
    
    use_shader(back_shader)
    set_uniform("uMVMatrix", view_matrix)
    set_uniform("uPMatrix", proj_matrix)
    
    draw_cube(cube)
    
    # The back_shader vertex shader outputs gl_Position and passes VerClr (position)
    # The fragment shader outputs VerClr as color
    # Result is stored in framebuffer.texture (g_bfTexObj)

# Pass 2: Raycasting
def pass2_raycasting(default_framebuffer, cube, raycast_shader, back_texture, volume_texture, transfer_func, step_size, num_steps):
    bind_framebuffer(default_framebuffer)
    enable_depth_test()
    set_depth_func(LEQUAL)
    enable_cull_face(BACK) # Cull back faces, render front faces
    
    use_shader(raycast_shader)
    set_uniform("uMVMatrix", view_matrix)
    set_uniform("uPMatrix", proj_matrix)
    set_uniform("StepSize", step_size)
    set_uniform("NUM_RAY_STEPS", num_steps)
    
    bind_texture_unit(0, back_texture) # uBackCoord
    bind_texture_unit(1, volume_texture) # uVolData
    bind_texture_unit(2, transfer_func) # trfunc_texture
    
    draw_cube(cube)
    
    # Fragment Shader Logic (executed per pixel):
    # 1. Get screen coords: uv = gl_FragCoord.xy / ScreenSize
    # 2. Get exit point: exit_point = texture(uBackCoord, uv).xyz
    # 3. Get entry point: entry_point = EntryPoint (interpolated from vertex shader)
    # 4. If entry_point == exit_point: discard
    # 5. dir = exit_point - entry_point
    # 6. len = length(dir)
    # 7. delta_dir = normalize(dir) * StepSize
    # 8. col_acc = vec4(0,0,0,0), alpha_acc = 0.0, length_acc = 0.0, ray_pos = entry_point
    # 9. for i in 0..NUM_RAY_STEPS:
    #      density = texture(uVolData, ray_pos).x
    #      color_sample = texture(trfunc_texture, vec2(density, 0.5))
    #      alpha_sample = density * StepSize
    #      col_acc += (1.0 - alpha_acc) * color_sample * alpha_sample * 40.0
    #      alpha_acc += alpha_sample
    #      length_acc += length(delta_dir)
    #      ray_pos += delta_dir
    #      if length_acc >= len or alpha_acc > 1.0: break
    # 10. Output col_acc
```

**Parameters:**
*   `StepSize`: Controls the step length in ray marching. Typical values depend on volume resolution and view distance [S2, S3, unofficial].
*   `NUM_RAY_STEPS`: Maximum iterations per ray. Source [S3, unofficial] uses 512. Source [S2, unofficial] uses 1600.
*   `ScreenSize`: Resolution of the screen (width, height) [S2, unofficial].
*   `uBackCoord`: Sampler uniform for back-face texture [S4, unofficial].
*   `uVolData`: Sampler uniform for volume data [S4, unofficial].

**Edge Cases and Pitfalls:**
*   **Coordinate System Mismatch:** `ExitPointCoord` in the vertex shader is in clip-space. Sampling the texture using `gl_FragCoord` (window coordinates) works because the rasterizer maps clip-space to window-space, and the texture was written during rasterization. Manual perspective division is not required and can cause errors [S2, unofficial].
*   **AMD Debugging Issue:** The `VerClr` input variable must be used in the shader; otherwise, debugging may fail on AMD hardware [S2, unofficial].
*   **Floating-Point Textures:** WebGL implementations require the `OES_texture_float` extension to support floating-point textures for volume data. Without it, initialization fails [S4, unofficial].
*   **Winding Order:** The method assumes counter-clockwise (CCW) winding order for front faces. If the winding is clockwise, back-face culling logic must be inverted [S1, unofficial].

## Subtopics

### [Volume Raycasting with MRT Endpoints](1584-volume-raycasting-with-mrt-endpoints.md)
Volume Raycasting with MRT Endpoints is a two-pass GPU technique that determines ray entry and exit points by rendering the volume's bounding box to multiple render targets (MRT), explicitly separating front-face and back-face coordinates into distinct textures to avoid analytical ray-cube intersection calculations. It builds on [Back-Face Culling for Ray Casting](1236-back-face-culling-for-ray-casting.md) by using MRT to store both entry and exit points simultaneously in the first pass, rather than relying on depth buffering and a single pass for back-faces. Unlike single-pass methods that compute intersections in the fragment shader, this approach offloads geometry processing to the rasterizer, simplifying the raycasting shader at the cost of an additional rendering pass and texture lookups. It is chosen when precise entry/exit determination is critical and the GPU supports MRT, avoiding the potential precision issues of depth-buffer-based entry point retrieval.

## Operating characteristics
*   **Time Complexity:** O(N) where N is the number of pixels, plus O(M) where M is the number of ray steps per pixel. The two-pass overhead is constant relative to scene complexity.
*   **Memory Complexity:** O(W*H) for the back-face texture, where W and H are screen dimensions. O(V) for volume data.
*   **Measured Performance:** Performance depends heavily on `StepSize` and `NUM_RAY_STEPS`. Source [S3, unofficial] uses 512 steps, Source [S2, unofficial] uses 1600. Higher steps increase accuracy but reduce frame rate.
*   **Scaling:** Scales well with screen resolution due to rasterizer efficiency. Does not scale with volume density complexity, only with ray length and step count.
*   **Strengths:** Avoids expensive analytical ray-cube intersection tests in the fragment shader. Simple to implement on GPUs with standard rasterization capabilities.
*   **Limitations:** Requires two rendering passes. Precision of entry/exit points depends on rasterization precision and texture filtering. Not suitable for non-convex volumes without a bounding box approximation.
*   **When to use:** When rendering convex volumes with a bounding box and the GPU supports efficient framebuffer objects and texture sampling.
*   **When not to use:** For non-convex volumes where the bounding box is a poor approximation, or when memory bandwidth is a bottleneck due to large screen resolutions and multiple texture lookups.

## Background
Back-face culling for ray casting originated as a technique to optimize volume rendering by leveraging the GPU's rasterization pipeline to determine ray entry and exit points. It was popularized in early WebGL and OpenGL tutorials for volume rendering, such as those by Khizar Siddiqui [S1, unofficial], toolchainX [S2, unofficial], and others [S3, S4, unofficial]. The method is a practical application of depth buffering and face culling to avoid analytical geometry calculations in shaders. It is commonly used in educational contexts and simple real-time volume renderers where simplicity and GPU compatibility are prioritized over advanced traversal algorithms.
