# Woodcock Collision Estimation with Octree Acceleration

Also called: castRayWoodcockFast

## Overview
An optimized ray marching method that combines Woodcock collision estimation with an octree traversal to skip empty regions and nodes that do not intersect the ray's current segment, reducing the number of volume samples [S1, unofficial]. It sets itself apart from standard ray marching by using the octree structure to cull non-intersecting nodes and from the parent [Sparse Ray-Octree Intersection (DECIDE)](3006-sparse-ray-octree-intersection-decide.md) by specifically employing stochastic collision estimation within leaf nodes rather than deterministic traversal or triangle intersection.

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, with a valid interval $[ray.minT, ray.maxT]$. An octree data structure representing the volume. A random number generator `sampler`. Configuration `settings` containing `stepSize` and `densityScale`.
*   **Output:** Accumulated color and opacity along the ray segment.

**Data Structures:**
*   **State Struct:** A stack element containing:
    *   `Octree const* node`: Pointer to the current octree node.
    *   `float minT`: The entry distance of the ray into the node's bounding box, clamped to the ray's current valid range.
    *   `float maxT`: The exit distance of the ray from the node's bounding box, clamped to the ray's current valid range.
    *   `int nodesMask`: A bitmask (integer) tracking which of the 8 children of the current node have already been visited or checked for intersection.

**Steps:**
1.  **Initialization:**
    *   Create an empty stack `st`.
    *   Push the root octree node onto the stack.
    *   Compute the bounding box intersection range for the root node. If the ray does not intersect the root bounding box, terminate.
    *   Initialize `ray.minT` with a random offset to start the Woodcock sampling:
        $$ ray.minT \leftarrow ray.minT + (-\ln(\text{sampler.nextFloat()})) \times \text{settings.stepSize} $$
        [S1, unofficial]

2.  **Traversal Loop:**
    *   While the stack is not empty and `ray.minT <= ray.maxT`:
        1.  Get the top state from the stack. Extract `node`, `minT`, and `maxT`.
        2.  **Clamping:** Ensure `minT` and `maxT` are clamped to the node's bounding box intersection and the current `ray.minT`.
        3.  **Pitfall Check:** If `minT > maxT`, the ray has passed this node. Pop the stack and continue to the next iteration. [S1, unofficial]
        4.  **Non-Leaf Node:** If `node` is not a leaf:
            *   Determine the child ID to traverse first based on the ray's position relative to the node's center. Let $sideX, sideY, sideZ$ be signs indicating which half of the node the ray origin (or current position) lies in:
                $$ id = (sideX \ll 2) \mid (sideY \ll 1) \mid (sideZ) $$
                [S1, unofficial]
            *   Check if `id` is already in `nodesMask`. If yes, skip this child.
            *   Compute the bounding box intersection for the child node.
            *   If valid:
                *   Push the child node to the stack with its intersection range.
                *   Break the inner loop to process the child immediately (depth-first).
        5.  **Leaf Node:** If `node` is a leaf:
            *   Calculate `invMaxOpacity`: the inverse of the maximum opacity stored in the node. If not pre-computed, default to $1.0$.
            *   **Woodcock Sampling Loop:** While `minT <= maxT`:
                1.  Sample the volume density $\rho$ at the current position along the ray.
                2.  Evaluate the transfer function to get color $C$ and opacity $\alpha$.
                3.  **Collision Test:** Generate a random number $u = \text{sampler.nextFloat()}$. The collision probability condition is:
                    $$ u < (\alpha \times \text{settings.densityScale}) \times \text{invMaxOpacity} \times \text{settings.stepSize} $$
                    [S1, unofficial]
                    *   If the condition is met (collision):
                        *   Accumulate the color $C$ and opacity $\alpha$ into the ray's result.
                        *   Update `ray.minT` to the current `minT` (or advance past the collision point depending on implementation specifics, but the source implies updating `ray.minT` after the leaf loop). *Note: Standard Woodcock advances the ray. The source notes say "Advance minT" after the test. If collision occurs, we typically accumulate and then advance. If no collision, we skip.*
                        *   The source pseudocode structure implies: if collision, accumulate. Then advance.
                4.  **Advance Ray:** Regardless of collision, advance `minT` by a stochastic step:
                    $$ minT \leftarrow minT + (-\ln(\text{sampler.nextFloat()})) \times \text{invMaxOpacity} \times \text{settings.stepSize} $$
                    [S1, unofficial]
            *   After processing the leaf, update `ray.minT` to the final `minT` value from the loop.
            *   Pop the stack to process the next node in the traversal order.

**Parameters:**
*   `settings.stepSize`: Base step size for sampling. Typical value: Not given in the sources.
*   `settings.densityScale`: Scaling factor for density. Typical value: Not given in the sources.
*   `invMaxOpacity`: Inverse of maximum opacity in the node. Default: $1.0$.

**Edge Cases and Pitfalls:**
*   **Ray Passed Node:** If `minT > maxT` after clamping, the ray has exited the node's bounds. The algorithm must pop the stack and continue. [S1, unofficial]
*   **Precision:** Floating point precision in logarithmic calculations for step advancement.
*   **Empty Nodes:** The octree traversal naturally skips empty nodes if they are not pushed to the stack or if their intersection is invalid.

## Operating characteristics
*   **Time Complexity:** Depends on the density of the volume and the octree depth. Fewer samples are taken in empty regions due to octree culling.
*   **Memory Complexity:** Stack depth is proportional to the octree depth.
*   **Strengths:** Efficiently skips empty space. Reduces sampling rate in low-density regions via Woodcock estimation.
*   **Limitations:** Stochastic nature introduces noise. Requires careful tuning of `stepSize` and `densityScale`.
*   **When to use:** Sparse volumes with large empty regions.
*   **When not to use:** Dense volumes where deterministic marching might be more efficient or less noisy.

## Background
Originated from the implementation in the PathTracer repository by thewildnath [S1, unofficial]. It is an adaptation of Woodcock collision estimation (also known as the delta tracking method) for use with hierarchical voxel structures (octrees) to accelerate volume rendering.
