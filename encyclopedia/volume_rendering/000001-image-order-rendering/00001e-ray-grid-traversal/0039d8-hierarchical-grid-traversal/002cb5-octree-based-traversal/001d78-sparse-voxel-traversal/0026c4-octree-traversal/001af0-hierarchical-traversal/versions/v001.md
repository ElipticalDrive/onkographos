# Hierarchical Traversal

Also called: Kay & Kajiya Hierarchy Traversal, Kay-Kajiya traversal, Octree Hierarchical Traversal, Octree Navigation, Octree Node Activity Check

## Overview
Hierarchical Traversal is a ray-intersection method that accelerates volume rendering by traversing a spatial hierarchy (such as an Octree or Sparse Voxel Octree) to skip empty space and coarsely approximate occupied regions [S1, S2, unofficial]. It solves the memory and performance bottlenecks of single-resolution discrete ray-tracing by allowing larger steps through empty areas [S1, S2, unofficial]. Unlike single-step discrete ray-tracing which requires a high-resolution 3D grid limited by memory, this method uses a hierarchy to represent the scene at multiple resolutions, bypassing memory limits and optimizing traversal time [S2, unofficial]. It is distinct from sibling methods like [Sparse Voxel Octree Ray Traversal](933-sparse-voxel-octree-ray-traversal.md) in its general applicability to any hierarchical grid structure, whereas SVO traversal specifically targets the sparse voxel data layout.

## How it works
**Inputs and Outputs:**
*   **Input:** A ray defined by origin $O$ and direction $D$; a hierarchical data structure (e.g., Octree, BVH, SVO) representing the volume.
*   **Output:** A sequence of visited nodes/voxels in front-to-back order, or a boolean indicating if an intersection exists within a threshold.

**Data Structures:**
The specific layout depends on the hierarchy type:
1.  **Octree/SVO:** Nodes are typically stored in arrays. An Octree node contains pointers to 8 children [S2, unofficial]. In SVO implementations, nodes may be packed into 32-bit integers where the high bit indicates emptiness or leaf status [S3, unofficial].
2.  **BVH (Bounding Volume Hierarchy):** Nodes are stored in a buffer. A `BVHNode` struct contains:
    *   `center`: `vec4` (or `f32[4]`) representing the bounding volume center [S3, unofficial].
    *   `radius`: `f32` representing the bounding sphere radius [S3, unofficial].
    *   `left_child`: `u32` index to the left child [S3, unofficial].
    *   `right_child`: `u32` index to the right child [S3, unofficial].
    *   Alignment: Packed in 16-byte alignment [S3, unofficial].
    *   Leaf nodes are identified by setting the high bit (0x80000000) of the child indices [S3, unofficial]. If a leaf is the last element and has no sibling, `right_child` is set to an empty node index (0) [S3, unofficial].
    *   `BVHLeaf` struct contains:
        *   `inv_model`: `mat4` (inverse model matrix) [S3, unofficial].
        *   `address`: `u32` pointing to the root of the SVO or target data [S3, unofficial].

**Parameters:**
*   **Resolution:** In two-step methods, the first step uses a coarse resolution (upper octree levels) and the second step uses a finer resolution (lower levels) [S2, unofficial]. The transition is calculated in floating-point arithmetic, requiring high precision [S2, unofficial].
*   **Stopping Depth:** In two-pass hierarchy traversal, the first step stops at a specific depth relative to the leaves (e.g., depth=3) [S9].

**Edge Cases and Pitfalls:**
*   **Precision:** The transition between resolution levels in two-step methods is calculated in floating-point arithmetic, which requires high precision for correctness [S2, unofficial].
*   **Leaf Identification:** Leaf nodes are identified by the high bit (0x80000000) of child indices. If a leaf is the last element and has no sibling, `right_child` is set to 0 [S3, unofficial].
*   **Empty Nodes:** If a node is null, the activity check returns false [S6, unofficial].

## Subtopics

### [Leaf Collection](899-leaf-collection.md)
A feedback mechanism that collects indices of visited nodes to maintain data coherence between GPU and CPU, targeting streaming/caching decisions based on rendering status.

### [Point Plane Test Traversal](982-point-plane-test-traversal.md)
A traversal algorithm for TET-AMR refinement trees that identifies the child tetrahedron containing a sample point by performing plane tests against midpoints of parent edges.

### [Mesh BVH](1062-mesh-bvh.md)
A GPU-accelerated BVH for triangle meshes, serving as a geometric backend for SDFs, enabling fast distance queries for high-frequency surface details.

### [Hierarchical Digital Differential Analyzer (HDDA)](1122-hierarchical-digital-differential-analyzer-hdda.md)
A specialized traversal for Sparse Voxel Octrees (OpenVDB) that uses multi-resolution leapfrogging and DDA at each node level to skip non-intersected nodes.

### [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md)
Uses k-d tree nodes to store data approximations with error terms; draws if error is below threshold, otherwise continues traversal.

A class for volume traversal using a hierarchical DDA approach, specialized for leaf nodes.

### [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md)
Uses a BVH built over a coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point, allowing skipping of non-sampled elements.

### [Node Omission in Ray-Tree Traversal](3305-node-omission-in-ray-tree-traversal.md)
An optimization that prevents adding nodes to the traversal stack if they are known not to intersect the ray.

Decomposes volumes into cubical bricks in an octree; uses a compact indexing structure in a texture for stackless raycasting, with an adaptive CPU loader for out-of-core data.

### [Octree Traversal](3859-octree-traversal.md)
The base hierarchical indexing mechanism using 2x2x2 subdivisions.

### Surface Descendant Check
A recursive function to determine if a node or any of its descendants are marked as active or contain a surface. If the cell is a Leaf, it returns whether it has a sign change. If it is a Branch, it recursively checks if any of its children have a surface descendant. If it is Empty or Full, it returns false [S4, unofficial].

### Coarse Mesh Traversal via BVH
Uses a Bounding Volume Hierarchy (BVH) built over the coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point [S7, unofficial]. The BVH is built by inserting four triangular faces facing outside for every coarse element. Rays are traced using hit/miss functions; the hit function returns the hit point and coarse tetrahedron ID. Unlike element marching, this allows skipping coarse elements and varying refinement levels [S7, unofficial].

### Perspective-Correct AMR Patch Traversal
A hybrid CPU-GPU strategy where the CPU traverses a KD-tree of AMR patches back-to-front, and the GPU traverses cells within a patch. Sub-patches are generated to ensure perspective-correct sorting of cells relative to the observer. The vertex shader modifies indices based on the observer position to ensure proper cell ordering [S8].

### Two-Pass Hierarchy Traversal
An optimization that splits traversal into two steps with a stopping depth in the first step. Step 1 traverses down to a specific depth relative to the leaves (e.g., depth=3). Step 2 traverses the remaining lower part for nodes identified in Step 1. At optimal stopping depth (3), it reduces time by 15% alone, and up to 30% with tile sharing. If stopping depth is 0, performance equals the direct implementation [S9].

## Operating characteristics
*   **Time Complexity:** Generally $O(\log N)$ for balanced hierarchies, where $N$ is the number of voxels/objects, compared to $O(N)$ for linear traversal.
*   **Memory Complexity:** Depends on the hierarchy. Octrees require storing node pointers. SVOs store only non-empty nodes, reducing memory usage significantly for sparse data [S1, S2, unofficial].
*   **Performance:** Results show a five-fold reduction in time compared to single-step implementations [S2, unofficial]. Hierarchical SVO traversal took 5 steps to intersect an occupied voxel compared to 11 steps for non-hierarchical traversal in example grids [S1, unofficial].
*   **Strengths:** Efficiently skips empty space; handles large datasets that exceed memory limits for dense grids; supports multi-resolution rendering [S1, S2, unofficial].
*   **Limitations:** Requires high precision for floating-point transitions between resolution levels [S2, unofficial]; overhead of tree traversal for very dense or small scenes may negate benefits.

## Background
Hierarchical traversal was introduced by Kay and Kajiya in 1986 as a method for speeding up ray-object intersection calculations using a hierarchy of extents [S5, unofficial]. It has since been adapted for volume rendering, particularly with Sparse Voxel Octrees (SVO) and Octrees, to handle huge voxel spaces that would otherwise be impractical due to memory constraints [S1, S2, unofficial]. The two-step approach was developed to optimize performance by leveraging the octree's ability to represent scenes at multiple resolutions [S2, unofficial].
