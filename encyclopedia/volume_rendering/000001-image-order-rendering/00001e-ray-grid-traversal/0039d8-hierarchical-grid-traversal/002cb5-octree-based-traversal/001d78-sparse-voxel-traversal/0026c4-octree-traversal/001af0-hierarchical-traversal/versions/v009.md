# Hierarchical Traversal

Also called: Hierarchical Octree Traversal, Kay & Kajiya Hierarchy Traversal, Kay-Kajiya traversal, Octree Hierarchical Traversal, Octree Navigation, Octree Node Activity Check, SVO Traversal, Sparse Voxel Octree (SVO) Traversal

## Overview
Hierarchical traversal is a method for accelerating ray-object intersection and volume rendering by navigating a spatial hierarchy (such as an octree or bounding volume hierarchy) where higher-level nodes cover larger spatial extents than lower-level nodes [S1, unofficial][S4, unofficial]. It solves the performance bottleneck of non-hierarchical traversal by allowing the ray to take larger steps through empty space, significantly reducing the total number of intersection tests and node visits required to reach active data [S1, unofficial]. Unlike flat grid traversal which checks every voxel, hierarchical traversal skips entire subtrees that do not intersect the ray or are marked inactive, enabling efficient rendering of sparse or multi-resolution datasets [S1, unofficial].

## How it works
**Inputs:** A ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$, and a hierarchical data structure (e.g., Sparse Voxel Octree or BVH) where each node has a bounding volume and references to children.
**Outputs:** A sequence of active leaf nodes or intersection points along the ray.

**Data Structures:**
The hierarchy is typically stored as an array of nodes. For BVH implementations, a node struct may contain:
- `center`: 4-component vector (x, y, z, padding) representing the bounding box center [S2, unofficial].
- `radius`: Scalar representing the bounding radius [S2, unofficial].
- `left_child`: Index to the left child node [S2, unofficial].
- `right_child`: Index to the right child node [S2, unofficial].
Nodes are packed with 16-byte alignment [S2, unofficial]. Leaf nodes are often distinguished by setting the high bit (0x80000000) of the child indices [S2, unofficial]. If a leaf is the last element and has no sibling, its `right_child` is set to an empty node index (0) [S2, unofficial].

For Octree/SVO implementations, nodes may store:
- `is_active`: Boolean flag indicating if the node or any descendant contains data [S5, unofficial].
- `children`: Array of 8 child indices (for octrees) or a pointer to a child block [S1, unofficial].

**Algorithm Steps:**
1. **Initialization:** Compute ray-box intersection parameters ($t_{min}, t_{max}$) for the root node's bounding volume. Initialize a traversal stack with the root node index and its intersection distance [S2, unofficial].
2. **Traversal Loop:** While the stack is not empty:
   a. Pop the top node index and its associated $t$ value from the stack [S2, unofficial].
   b. Retrieve the node from the data structure.
   c. **Activity Check:** If the node is an internal node, check if it is active. A node is active if `node->is_active` is true, or if any of its 8 children exist and are active [S5, unofficial]. If not active, skip to step 2a.
   d. **Intersection Test:** Test if the ray intersects the current node's bounding volume. If the minimum intersection distance $t$ is greater than the ray's near plane or existing closest hit, skip to step 2a [S2, unofficial].
   e. **Leaf Check:** If the node is a leaf (identified by specific flags or index ranges), process the leaf (e.g., perform ray-marching or surface intersection) and record the hit. Skip to step 2a.
   f. **Descend:** If the node is an internal node and active:
      i. Retrieve the indices of the left and right children (or all 8 children for octrees).
      ii. For each child, compute the intersection distance with its bounding volume.
      iii. Push children that intersect the ray onto the stack, ordered by increasing intersection distance (closer child first) [S2, unofficial].
      iv. If only one child intersects, push only that one. If neither, do not push any.
3. **Termination:** Return when the stack is empty or the closest hit distance exceeds the ray's far plane.

**Pseudocode (BVH-style):**
```python
def traverse_bvh(ray_origin, ray_direction, bvh_nodes, stack_max_size):
    # Initialize stack
    stack = [None] * stack_max_size
    stack_ptr = 0
    
    # Push root
    root_idx = 0
    t_hit = intersect_box(ray_origin, ray_direction, bvh_nodes[root_idx].center, bvh_nodes[root_idx].radius)
    
    if t_hit is None:
        return [] # No intersection with root
    
    stack[stack_ptr] = (root_idx, t_hit)
    stack_ptr += 1
    
    hits = []
    
    while stack_ptr > 0:
        stack_ptr -= 1
        node_idx, t_node = stack[stack_ptr]
        node = bvh_nodes[node_idx]
        
        # Check if leaf
        if is_leaf(node):
            # Process leaf intersection
            hit = intersect_leaf(ray_origin, ray_direction, node)
            if hit is not None:
                hits.append(hit)
            continue
        
        # Get children
        left_idx = node.left_child & 0x7FFFFFFF # Clear high bit if set
        right_idx = node.right_child & 0x7FFFFFFF
        
        # Determine which children to visit
        # Assume intersect_box returns t_min or None
        t_left = intersect_box(ray_origin, ray_direction, bvh_nodes[left_idx].center, bvh_nodes[left_idx].radius)
        t_right = intersect_box(ray_origin, ray_direction, bvh_nodes[right_idx].center, bvh_nodes[right_idx].radius)
        
        # Push in order of increasing t
        if t_left is not None and t_right is not None:
            if t_left < t_right:
                stack[stack_ptr] = (left_idx, t_left)
                stack_ptr += 1
                stack[stack_ptr] = (right_idx, t_right)
                stack_ptr += 1
            else:
                stack[stack_ptr] = (right_idx, t_right)
                stack_ptr += 1
                stack[stack_ptr] = (left_idx, t_left)
                stack_ptr += 1
        elif t_left is not None:
            stack[stack_ptr] = (left_idx, t_left)
            stack_ptr += 1
        elif t_right is not None:
            stack[stack_ptr] = (right_idx, t_right)
            stack_ptr += 1
            
    return hits
```

**Pitfalls:**
- **Precision:** Division by zero can occur if ray direction components are zero; clamp small direction components to a small epsilon [S2, unofficial].
- **Boundary Conditions:** Leaf nodes at the end of the array may have invalid sibling indices; handle empty node indices explicitly [S2, unofficial].
- **Stack Overflow:** Ensure stack size is sufficient for the maximum depth of the hierarchy [S2, unofficial].

## Subtopics

### [Leaf Collection](899-leaf-collection.md)
Leaf Collection identifies and gathers all terminal nodes (leaves) intersected by a ray grid during hierarchical traversal, converting a sparse traversal path into a contiguous list of active volumetric blocks for subsequent ray marching or shading. It separates node identification from radiance computation to enable efficient memory compaction and parallel processing [899-leaf-collection.md].

### [Point Plane Test Traversal](982-point-plane-test-traversal.md)
Point Plane Test Traversal is a method for locating the specific child tetrahedron within a TET-AMR (Tetrahedral Adaptive Mesh Refinement) refinement tree that contains a given query point. It solves the in-element lookup problem by traversing from the coarse root to the leaf (or max depth) using geometric half-space tests against planes defined by edge midpoints, avoiding the redundancy of checking all eight children individually. It is distinguished from Leaf Collection by its on-the-fly vertex computation and from VolumeHDDA by its reliance on explicit geometric plane tests rather than incremental rasterization logic.

### [Mesh BVH](1062-mesh-bvh.md)
Mesh BVH is a GPU-accelerated bounding volume hierarchy designed for triangle meshes to support efficient distance queries and ray intersection tests. It serves as the primary acceleration structure for computing signed distances and performing ray-triangle intersections in large-scale triangle meshes, distinguishing itself from other hierarchical methods by its specific optimization for GPU hardware (such as OptiX) and its role in neural rendering pipelines. Unlike leaf collection or point-plane tests which may handle specific traversal optimizations, Mesh BVH provides the foundational spatial indexing for both unsigned distance calculation and topological signing.

### [Multi-Resolution Rendering with K-D Tree](1942-multi-resolution-rendering-with-k-d-tree.md)
Multi-resolution rendering with K-D Tree is a hierarchical volume rendering technique that accelerates image-order ray casting by storing approximations of the underlying data within K-D tree nodes. It solves the performance bottleneck of rendering large, high-resolution datasets by allowing the renderer to skip detailed traversal when the data within a spatial region can be represented by a simple model within a user-specified error threshold. Unlike wavelet-based methods which store only detail coefficients, this method stores a complete model for each region, enabling fast "preview" images and adaptive detail. It builds on Hierarchical Traversal.

### [Coarse Mesh Traversal](3062-coarse-mesh-traversal.md)
Coarse Mesh Traversal is a hierarchical rendering technique that accelerates volume rendering by decoupling the global search for active data regions from the local sampling of fine-grained geometry. It solves the problem of inefficiently traversing large, sparse, or multi-resolution datasets by first identifying which coarse elements (macrocells) a ray intersects, and then performing detailed rendering only within those specific regions. What sets it apart from its siblings is the explicit construction of a coarse mesh (typically a BVH) from the underlying adaptive or hierarchical data structure, allowing the renderer to skip empty or irrelevant volumes entirely before entering the fine-level traversal loop [3062-coarse-mesh-traversal.md].

### [Node Omission in Ray-Tree Traversal](3305-node-omission-in-ray-tree-traversal.md)
Node omission is an optimization for hierarchical ray-tree traversal that prevents adding child nodes to the traversal stack if it is known they will not intersect the current ray, reducing the number of intersection tests. It sets itself apart from sibling methods like Leaf Collection and Point Plane Test Traversal by operating on the spatial relationship between the ray's entry/exit parameters and the node's bounding box midpoints, rather than relying on leaf-level data structures or plane-based splitting planes.

### [Two-Pass Hierarchy Traversal](3339-two-pass-hierarchy-traversal.md)
Two-Pass Hierarchy Traversal is a spatial hierarchy traversal optimization that reduces computational cost by splitting the descent into a coarse initial pass and a fine subsequent pass. It sets itself apart from single-pass methods like Leaf Collection or Point Plane Test Traversal by explicitly decoupling the identification of relevant subtrees from the detailed node evaluation, allowing for significant reuse across pixel blocks.

### [Adaptive Out-of-Core Single-Pass GPU Raycasting](3440-adaptive-out-of-core-single-pass-gpu-raycasting.md)
This method enables interactive rendering of multi-gigabyte scalar volumes on desktop hardware by combining an out-of-core octree data structure with a single-pass, stackless GPU raycasting algorithm. It solves the memory capacity and bandwidth bottlenecks of in-core rendering by maintaining a view- and transfer-function-dependent working set of volumetric bricks in GPU memory, while the rest of the dataset remains on disk. Unlike separate block rendering techniques that suffer from boundary artifacts and cannot support refractive or global illumination models, this approach performs the entire volume traversal and compositing in a single fragment shader pass, adapting sampling density to the local brick resolution.

#### Surface Descendant Check
If the cell is a Leaf, return whether it has a sign change. If it is a Branch, recursively check if any of its children have a surface descendant. If it is Empty or Full, return false [S3, unofficial].

#### Coarse Mesh Traversal via BVH
Uses a Bounding Volume Hierarchy (BVH) built over the coarse tetrahedral mesh to efficiently locate the coarse element containing a sample point [S6, unofficial]. Build a triangle BVH over the coarse mesh by inserting four triangular faces facing outside for every coarse element. Trace rays into the BVH using OptiX Wrapper Library (OWL) hit and miss functions. The hit function returns the hit point and the coarse tetrahedron ID. The miss function reports no intersection with BVH faces. Unlike element marching which uses connectivity, point location querying skips coarse elements not being sampled and allows varying refinement levels in the coarse mesh [S6, unofficial].

#### Warp-Level Intersection Caching
Optimization to delay intersection tests until enough threads in a warp have stored an intersection child node, similar to [AL09] [S7, unofficial]. When an intersection is found, store the current voxel intersection data. At the start of every traversal step, check if enough threads have a stored intersection. If so, proceed by doing an intersection test. Otherwise, continue traversal with the complete warp. If threads find the next intersection test while already having an intersection stored, stop traversing until the next intersection test is performed [S7, unofficial].

## Operating characteristics
**Time Complexity:** $O(\log N)$ for balanced trees in the average case, where $N$ is the number of nodes, but can degrade to $O(N)$ in worst-case scenarios (e.g., highly unbalanced trees or rays passing through many active leaves) [S1, unofficial].
**Memory Complexity:** Depends on the sparsity of the data. SVOs store only active nodes, leading to significant memory savings compared to dense grids [S1, unofficial].
**Performance:** Hierarchical traversal can reduce the number of steps significantly. For example, in a specific SVO example, non-hierarchical traversal took 11 steps to intersect an occupied voxel, while hierarchical SVO traversal took only 5 steps [S1, unofficial]. Results demonstrate that the technique is several times faster than other published algorithms [S4, unofficial].
**Strengths:** Efficient skipping of empty space; scalable to large datasets; supports multi-resolution data.
**Limitations:** Overhead of tree traversal and stack management; performance sensitive to tree balance and data distribution.

## Background
Hierarchical traversal was introduced by Tim Kay and James T. Kajiya in 1986 in the paper "Ray Tracing Complex Scenes" [S4, unofficial]. They presented a new algorithm for speeding up ray-object intersection calculations using a hierarchy of bounding extents. The method allows objects to be bounded by extents that fit convex hulls tightly and placed into a hierarchy, enabling efficient querying of objects along the ray in an efficient order [S4, unofficial]. The technique has since become a foundational component in modern ray tracing and volume rendering systems, evolving into various forms such as BVHs for triangle meshes and Sparse Voxel Octrees (SVOs) for volumetric data [S1, unofficial][S4, unofficial].
