# Sparse Ray Marching with Nested Axis-Aligned Distance Fields (NAADF)
Also called: NAADF Ray Marching, Sparse Raymarching

## Overview
Sparse Ray Marching with Nested Axis-Aligned Distance Fields (NAADF) is a technique for traversing sparse voxel grids by skipping over empty space using precomputed distance fields, replacing traditional brick coordinate rasterization with a simpler pipeline suitable for g-buffer and path tracing [S1, unofficial]. It differs from its sibling [Hierarchical Brick-Map DDA](4105-hierarchical-brick-map-dda.md) by calculating the largest empty region along the ray's path via axis-aligned bounds, allowing it to step over multiple cells at once rather than advancing one cell boundary per iteration [S1, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: Ray origin (`ray_origin`), ray direction (`ray_dir`), maximum traversal distance (`t_max`), global grid extent (`grid_ext`), voxel occupancy masks (`voxel_masks`), and axis-aligned distance fields (`voxel_aadf`) [S1, unofficial].
- **Outputs**: Boolean indicating if a voxel was hit (`True`) or if the ray exited the grid/max distance (`False`) [S1, unofficial].

### Data Structures
The method relies on a three-level grid hierarchy [S1, unofficial]:
1. **Voxel Grid**: The bottom level containing individual voxels [S1, unofficial].
2. **Brick Grid**: Each brick contains $4^3$ voxels [S1, unofficial].
3. **Chunk Grid**: Each chunk contains $4^3$ bricks [S1, unofficial].

**Axis-Aligned Distance Field (AADF) Layout**: Each cell in the AADF stores six distances, representing the number of free (empty) cells along each axis in both positive and negative directions. These are packed into a single 32-bit unsigned integer (`uint`) [S1, unofficial]:
- Bits 0–4: Distance in $-X$ direction [S1, unofficial].
- Bits 5–9: Distance in $+X$ direction [S1, unofficial].
- Bits 10–14: Distance in $-Y$ direction [S1, unofficial].
- Bits 15–19: Distance in $+Y$ direction [S1, unofficial].
- Bits 20–24: Distance in $-Z$ direction [S1, unofficial].
- Bits 25–29: Distance in $+Z$ direction [S1, unofficial].

**Voxel Masks**: A sparse structure used to quickly identify occupied bricks. The index into the mask is calculated via `mask_linear_idx(ipos)`, which maps the 3D integer position to a linear index based on the brick dimensions (`VX_MASK_EXT`) [S1, unofficial].

### Algorithm Steps
1. **Initialize**: Compute inverse direction `inv_dir = 1.0 / (ray_dir + (ray_dir == 0.0) * 1e-30)` to guard against division by zero [S1, unofficial]. Set integer position `ipos = floor(ray_origin)` [S1, unofficial]. Set local position `local_pos = ray_origin - ipos` [S1, unofficial]. Set accumulated distance `distance = 0.0` [S1, unofficial].
2. **Loop**: Iterate `i` from 0 to `3 * grid_ext - 1` [S1, unofficial].
3. **Boundary Check**: If any component of `ipos` is greater than or equal to `grid_ext`, return `False` [S1, unofficial].
4. **Voxel Mask Check**: Load the voxel mask at `ipos // VX_MASK_EXT` [S1, unofficial]. Calculate the linear index `idx` using `mask_linear_idx(ipos)` [S1, unofficial]. If `(mask & (1 << idx)) != 0`, return `True` (a voxel was hit) [S1, unofficial].
5. **Load AADF**: Load the AADF value at `ipos` [S1, unofficial]. Determine shift values based on ray direction signs to extract the correct distance for the direction of travel [S1, unofficial]: `shift_x = 0` if `ray_dir.x < 0` else `5` [S1, unofficial]. `shift_y = 10` if `ray_dir.y < 0` else `15` [S1, unofficial]. `shift_z = 20` if `ray_dir.z < 0` else `25` [S1, unofficial].
6. **Extract Bounds**: Extract the number of free cells for each axis by shifting and masking with `31` (5 bits) [S1, unofficial]: `bounds.x = (aadf >> shift_x) & 31` [S1, unofficial]. `bounds.y = (aadf >> shift_y) & 31` [S1, unofficial]. `bounds.z = (aadf >> shift_z) & 31` [S1, unofficial].
7. **Calculate Empty Region**: Determine the minimum and maximum bounds of the empty region relative to the current cell [S1, unofficial]: `cell_min = max(ipos - bounds, 0)` [S1, unofficial]. `cell_max = min(ipos + 1 + bounds, grid_ext)` [S1, unofficial]. Determine the `exit_plane` coordinate for each axis: use `cell_min` if the ray direction is negative, otherwise use `cell_max` [S1, unofficial].
8. **Calculate Step Distance**: Calculate the distance to the exit plane in ray space: `side_dist = (exit_plane - ipos - local_pos) * inv_dir` [S1, unofficial]. Guard against zero ray direction components by setting the corresponding `side_dist` component to `3e+38` [S1, unofficial].
9. **Determine T**: Find the minimum distance to any exit plane: `t = min(side_dist.x, side_dist.y, side_dist.z)` [S1, unofficial]. Add `t` to `distance` [S1, unofficial]. If `distance > t_max`, return `False` [S1, unofficial].
10. **Update Position**: Determine which planes were crossed: `crossed = step(side_dist, t)` [S1, unofficial]. Update local position: `advanced = local_pos + t * ray_dir` [S1, unofficial]. Calculate integer cell delta: `cell_delta = floor(advanced + crossed * sign(ray_dir) * 0.5)` [S1, unofficial]. Update `ipos += cell_delta` and `local_pos = advanced - cell_delta` [S1, unofficial].

### Pseudocode
```python
import math

def sparse_ray_march(ray_origin, ray_dir, t_max, grid_ext, voxel_masks, voxel_aadf, VX_MASK_EXT):
    # Guard against division by zero
    inv_dir = tuple(1.0 / (d + (1e-30 if d == 0.0 else 0.0)) for d in ray_dir)
    
    # Initialize positions
    ipos = tuple(math.floor(p) for p in ray_origin)
    local_pos = tuple(ray_origin[j] - ipos[j] for j in range(3))
    distance = 0.0
    
    max_iter = 3 * grid_ext
    
    for i in range(max_iter):
        # Boundary check
        if any(p >= grid_ext for p in ipos):
            return False
            
        # Voxel mask check
        mask_idx = tuple(p // VX_MASK_EXT for p in ipos)
        mask = voxel_masks[mask_idx]
        idx = ipos[0] + ipos[1] * VX_MASK_EXT + ipos[2] * VX_MASK_EXT * VX_MASK_EXT
        if (mask >> idx) & 1:
            return True
            
        # Load AADF
        aadf = voxel_aadf[ipos]
        
        # Determine shifts based on ray direction
        shift_x = 0 if ray_dir[0] < 0.0 else 5
        shift_y = 10 if ray_dir[1] < 0.0 else 15
        shift_z = 20 if ray_dir[2] < 0.0 else 25
        
        # Extract bounds (5 bits each)
        bounds = (
            (aadf >> shift_x) & 31,
            (aadf >> shift_y) & 31,
            (aadf >> shift_z) & 31
        )
        
        # Calculate empty region boundaries
        cell_min = tuple(max(ipos[j] - bounds[j], 0) for j in range(3))
        cell_max = tuple(min(ipos[j] + 1 + bounds[j], grid_ext) for j in range(3))
        
        # Determine exit plane
        exit_plane = tuple(
            cell_min[j] if ray_dir[j] < 0.0 else cell_max[j] for j in range(3)
        )
        
        # Calculate step distance
        side_dist = tuple(
            (exit_plane[j] - ipos[j] - local_pos[j]) * inv_dir[j] for j in range(3)
        )
        
        # Guard against zero ray direction components
        side_dist = tuple(3e+38 if ray_dir[j] == 0.0 else side_dist[j] for j in range(3))
        
        # Determine t
        t = min(side_dist)
        distance += t
        
        if distance > t_max:
            return False
            
        # Update position
        crossed = tuple(1.0 if side_dist[j] < t else 0.0 for j in range(3))
        advanced = tuple(local_pos[j] + t * ray_dir[j] for j in range(3))
        
        sign_dir = tuple(1.0 if ray_dir[j] > 0.0 else (-1.0 if ray_dir[j] < 0.0 else 0.0) for j in range(3))
        cell_delta = tuple(math.floor(advanced[j] + crossed[j] * sign_dir[j] * 0.5) for j in range(3))
        
        ipos = tuple(ipos[j] + cell_delta[j] for j in range(3))
        local_pos = tuple(advanced[j] - cell_delta[j] for j in range(3))
        
    return False
```

### Parameters and Edge Cases
- **Grid Compression**: The implementation uses "naive" AADFs. The compression method described in the source paper is not implemented, leading to redundancy in empty space [S1, unofficial].
- **Zero Direction**: Ray direction components equal to zero are handled by adding `1e-30` to the denominator during inverse calculation and setting the corresponding `side_dist` to `3e+38` to prevent invalid steps [S1, unofficial].
- **Loop Limit**: The loop runs up to `3 * grid_ext` iterations [S1, unofficial].

## Operating characteristics
- **Time Complexity**: The method steps over the largest empty space calculated from the AADF, potentially reducing the number of iterations compared to standard DDA which steps one cell boundary at a time [S1, unofficial]. However, the overhead of AADF lookups and bit manipulation may offset gains in highly sparse but large grids [S1, unofficial].
- **Memory Complexity**: Naive AADFs consume significant memory. For a $1024^3$ voxel grid, the voxel AADF alone requires 4 GiB. For a $256^3$ grid, it requires 64 MiB [S1, unofficial]. This makes the method less scalable for very large grids without compression [S1, unofficial].
- **Performance**: On the `monu2` scene, FPS increased slightly from 144.00 to 144.05 (+0.03%), but average GPU walltime increased from 5.11 ms to 6.35 ms (+24.30%) [S1, unofficial]. On the `sponza-1024` scene (1 billion voxels), FPS decreased from 81.41 to 64.73 (-20.48%), and average GPU walltime increased from 20.72 ms to 26.28 ms (+26.86%) [S1, unofficial].
- **Strengths**: Simpler pipeline than brick coordinate rasterization; suitable for g-buffer and path tracing; effective at skipping empty space in sparse volumes [S1, unofficial].
- **Limitations**: High memory usage for large grids due to naive AADF storage; potential performance regression in complex scenes due to increased register allocation and reduced occupancy (e.g., occupancy dropped from 52.02% to 36.38% in RTAO shader tests) [S1, unofficial].

## Background
NAADF is inspired by the paper "Globally Illuminated Voxel Worlds Accelerated with Nested Axis‐Aligned Distance Fields" [S1, unofficial]. It was implemented in a voxel raytracer devlog to replace an existing DDA renderer, aiming to provide a promising method for both basic g-buffer + RTAO rendering and potential path tracing [S1, unofficial]. The three-level grid hierarchy (voxel, brick, chunk) was adopted from the source paper [S1, unofficial].
