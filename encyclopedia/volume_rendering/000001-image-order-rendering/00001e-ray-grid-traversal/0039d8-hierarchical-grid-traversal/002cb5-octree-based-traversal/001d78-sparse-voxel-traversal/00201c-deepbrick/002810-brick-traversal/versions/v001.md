# Brick Traversal

Also called: Ray Marching with Alpha Compositing & Sample Ratio Adjustment, TraverseBrick

## Overview
Brick Traversal is a ray-marching kernel that samples a volumetric brick texture, adjusts alpha and RGB values for variable step sizes, and composites the result into a destination color using front-to-back alpha blending [S1, unofficial]. It is specifically designed to handle the transition between hierarchical levels in sparse voxel structures, ensuring that the accumulated opacity and color correctly reflect the sampling density relative to the underlying voxel grid [S1, unofficial]. Unlike standard ray marching which assumes uniform step sizes, Brick Traversal accounts for the "sample ratio" ($r$) between the ray step and the brick's internal resolution, preventing over-sampling artifacts when traversing coarser levels of a hierarchy [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin ($\mathbf{O}$), ray direction ($\mathbf{D}$), brick bounds (min/max coordinates), brick texture data, current brick depth ($curDepth$), and global brick step size scalar ($k_{BrickStepSizeScalar}$).
*   **Output:** Composite color ($c_{dst}$) and accumulated alpha ($a_{dst}$).

**Data Structures:**
The method operates on a `BrickData` structure which typically contains:
*   `xOffset`, `yOffset`, `zOffset`: The brick's position in the global voxel grid.
*   `brickDimX`, `brickDimY`, `brickDimZ`: The dimensions of the brick in voxels.
*   `borderVoxels`: The number of border voxels surrounding the valid data.
*   `texData`: The 3D texture array or volume data associated with the brick.

**Parameters:**
*   $k_{BrickStepSizeScalar}$: A scalar factor controlling the base step size relative to the brick resolution.
*   $r$ (sampleRatio): The ratio of the ray step size to the brick's effective voxel size. It is computed as:
    $$ r = k_{BrickStepSizeScalar}^{OctTreeDepthMinusOne - curDepth} $$
    for constant nodes, or derived from $curBrickDepth$ for textured bricks [S1, unofficial].

**Steps:**
1.  **Compute Intersection:** Calculate the time to exit the brick bounds using a ray-box intersection algorithm (e.g., ComputeMinRayBoxIntersection) [S1, unofficial]. Let $t_{exit}$ be the exit time.
2.  **Calculate Steps:** Determine the ray step size in world space: $rayStepSize = RayStepSize \times r$. Calculate the number of steps: $numSteps = \lfloor t_{exit} / rayStepSize \rfloor + 1$ [S1, unofficial].
3.  **Initialize:** Set $curBrickRayPos$ to the entry point within the brick. Initialize $c_{dst} = (0,0,0,0)$ [G].
4.  **Loop:** For $i$ from $0$ to $numSteps - 1$:
    a.  **Advance Ray:** Update the world position: $rayWorldPosition += worldRayStep$. Update the brick-space position: $curBrickRayPos += brickRayStep$ [S1, unofficial].
    b.  **Fetch Texel:** Sample the brick texture at $curBrickRayPos$ to get source color $c_{src}$ and alpha $a_{src}$ [S1, unofficial].
    c.  **Adjust Values:** Compute adjusted alpha and color:
        $$ a_{adj} = 1 - (1 - a_{src})^r $$
        $$ c_{adj} = c_{src} \times r $$
        [S1, unofficial].
    d.  **Composite:** Update the destination using front-to-back blending:
        $$ c_{dst} = (1 - a_{dst}) \times c_{adj} + c_{dst} $$
        $$ a_{dst} = a_{dst} + a_{adj} \times (1 - a_{dst}) $$
        [S1, unofficial].
    e.  **Early Exit Check:** If $a_{dst} > 0.995$, subtract $(i+1)$ from $numSteps$, advance $rayWorldPosition$ by the remaining steps to the exit point, and return [S1, unofficial].

**Pseudocode:**
```python
def brick_traversal(ray_origin, ray_direction, brick_bounds, brick_texture, cur_depth, k_scalar):
    # 1. Compute intersection
    t_min, t_max = compute_ray_box_intersection(ray_origin, ray_direction, brick_bounds)
    if t_max < 0:
        return (0, 0, 0, 0) # No intersection
    
    t_exit = t_max
    ray_step_size = get_global_ray_step_size() # Assumed global parameter
    sample_ratio = k_scalar ** (oct_tree_depth - 1 - cur_depth) # Or from curBrickDepth
    
    num_steps = int(t_exit / (ray_step_size * sample_ratio)) + 1
    
    # 2. Initialize
    cur_brick_pos = ray_origin + ray_direction * t_min # Entry point in brick space
    brick_step = ray_direction * ray_step_size * sample_ratio
    world_step = ray_direction * ray_step_size
    
    dst_color = (0.0, 0.0, 0.0, 0.0)
    
    # 3. Loop
    for i in range(num_steps):
        # Advance
        cur_brick_pos += brick_step
        ray_world_pos = ray_origin + ray_direction * (t_min + (i + 1) * ray_step_size)
        
        # Fetch
        src_color, src_alpha = brick_texture.sample(cur_brick_pos)
        
        # Adjust
        adj_alpha = 1.0 - (1.0 - src_alpha) ** sample_ratio
        adj_color = src_color * sample_ratio
        
        # Composite
        dst_color = (
            (1.0 - dst_color[3]) * adj_color + dst_color,
            dst_color[3] + adj_alpha * (1.0 - dst_color[3])
        )
        
        # Early exit
        if dst_color[3] > 0.995:
            # Advance to exit to avoid artifacts
            remaining_steps = num_steps - (i + 1)
            ray_world_pos += world_step * remaining_steps
            break
            
    return dst_color
```

**Edge Cases and Pitfalls:**
*   **Early Exit Positioning:** When $a_{dst} > 0.995$, the loop breaks. It is critical to advance $rayWorldPosition$ to the exact exit point of the brick to prevent visual artifacts in subsequent rays or passes [S1, unofficial].
*   **Precision:** Floating-point precision errors in $curBrickRayPos$ accumulation can lead to sampling artifacts over many steps. Using a direct position calculation based on $i$ is often more robust than incremental addition [G].
*   **Boundary Conditions:** Ensure $curBrickRayPos$ is clamped to the valid texture region, accounting for border voxels if present [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of steps within the brick, proportional to the brick thickness and inversely proportional to the step size.
*   **Memory Complexity:** $O(1)$ auxiliary space, plus the memory for the loaded brick texture.
*   **Strengths:** Efficiently handles variable sampling rates in hierarchical volumes; reduces over-sampling at coarser levels.
*   **Limitations:** Requires careful management of the sample ratio; early exit logic adds branching complexity.
*   **When to Use:** When rendering sparse voxel octrees or hierarchical grids where bricks represent different levels of detail.
*   **When Not to Use:** For uniform, dense volumes where standard ray marching is sufficient and simpler.

## Background
Brick Traversal is a core component of the GigaVoxels rendering pipeline, introduced by Laptev et al. in the context of real-time rendering of large-scale volumetric data [S1, unofficial]. It addresses the challenge of efficiently traversing hierarchical voxel structures by adapting the sampling rate to the local detail level, ensuring visual consistency across different levels of the octree. The method is integral to systems like VoxViz, which utilize brick-based memory management and rendering [S1, unofficial].
