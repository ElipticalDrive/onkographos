# Dynamic MLP Maps with Empty Space Skipping
## Overview
Dynamic MLP Maps is a rendering technique for volumetric videos that combines multi-level hash tables with 2D CNN-generated MLP maps and uses an occupancy volume for empty space skipping to achieve real-time performance [S1, unofficial]. It differs from its siblings by using a hybrid representation where spatial features are stored in hash tables and network parameters are predicted by a CNN decoder onto orthogonal planes, allowing for efficient evaluation of multiple small MLPs [S1, unofficial]. Unlike [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) which operates on geometry, or [Space Leaping](5863-space-leaping.md) which uses fixed grid strides, this method dynamically skips empty space using a pre-computed per-frame occupancy volume [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A sequence of video frames (volumetric video), camera poses, and an optional foreground mask [S1, unofficial].
*   **Outputs:** Rendered color images and densities for each frame [S1, unofficial].

**Data Structures:**
1.  **Multi-level Hash Tables:** Stores high-dimensional feature vectors for spatial locations [S1, unofficial].
2.  **MLP Maps:** Three 2D maps (one for each axis-aligned plane: XY, YZ, XZ) predicted by a 2D CNN decoder. Each map stores parameters for a small MLP network [S1, unofficial].
3.  **Occupancy Volume:** A 3D grid representing the spatial extent of non-empty voxels for each video frame [S1, unofficial].
    *   **Layout:** A 3D array of booleans.
    *   **Resolution:** $24 \times 24 \times 48$ per video frame [S1, unofficial].
    *   **Construction:** Each volume cell is divided into a $5 \times 5 \times 5$ subgrid. Density is calculated for each subgrid point. A volume cell is marked as occupied if any subgrid point has density above threshold $\tau_1 = 5$ [S1, unofficial].

**Numbered Steps:**

1.  **Pre-computation (Training/Offline):**
    1.  Train the hash tables and CNN decoder to predict MLP maps using the training loss function [S1, unofficial].
    2.  For each video frame, compute the occupancy volume by sampling densities and applying the threshold $\tau_1$ [S1, unofficial].

2.  **Inference Sampling (Per Ray):**
    1.  Define the scene bound diagonal distance $D$ [S1, unofficial].
    2.  Set sampling step size $\delta = D / 256$ [S1, unofficial].
    3.  For a given camera ray $\mathbf{r}$, determine the intersection with the occupancy volume [S1, unofficial].
    4.  Identify the set of occupied voxels along the ray [S1, unofficial].
    5.  Sample query points $\mathbf{p}_i$ only within these occupied voxels, spaced by $\delta$ [S1, unofficial].

3.  **Feature Retrieval and MLP Evaluation:**
    1.  For each query point $\mathbf{p}_i$:
        a.  **Hash Embedding:** Embed $\mathbf{p}_i$ into a high-dimensional feature vector $\mathbf{f}_i$ using the multi-level hash tables [S1, unofficial].
        b.  **MLP Map Projection:** Project $\mathbf{p}_i$ onto the three axis-aligned orthogonal MLP maps (XY, YZ, XZ) to retrieve corresponding MLP parameters $\theta_{xy}, \theta_{yz}, \theta_{xz}$ [S1, unofficial].
        c.  **MLP Evaluation:** Evaluate three small MLP networks using $\mathbf{f}_i$ and each set of parameters $\theta$. This is done efficiently using a custom PyTorch layer based on MAGMA, following KiloNeRF [S1, unofficial].
        d.  **Result Combination:** Combine the predictions (color $\mathbf{c}_i$ and density $\sigma_i$) from each MLP map via elementwise summation [S1, unofficial].

4.  **Filtering and Rendering:**
    1.  Compute accumulated transmittance $T_i$ and composition weight $\omega_i$ for each sample:
        $$ \omega_i = T_i(1 - \exp(-\sigma_i \delta_i)) $$
        $$ T_i = \exp(-\sum_{j=1}^{i-1} \sigma_j \delta_j) $$
        where $\delta_i$ is the ray step size [S1, unofficial].
    2.  **Filtering:** If $\omega_i < \tau_2$ (where $\tau_2 = 10^{-3}$), ignore the query point for color evaluation [S1, unofficial].
    3.  **Composition:** Compute the final pixel color $\tilde{C}(\mathbf{r})$:
        $$ \tilde{C}(\mathbf{r}) = \sum_{i=1}^M \omega_i \mathbf{c}_i $$
        where $M$ is the number of valid samples [S1, unofficial].

**Pseudocode:**

```python
import torch

# Constants from sources
OCCUPANCY_RES = (24, 24, 48)
SUBGRID_SIZE = 5
THRESHOLD_DENSITY = 5.0
THRESHOLD_WEIGHT = 1e-3
STEP_DIVISOR = 256

def compute_occupancy_volume(scene_min, scene_max, density_fn, resolution=OCCUPANCY_RES):
    """Pre-compute occupancy volume for a frame."""
    occupied = torch.zeros(resolution, dtype=torch.bool)
    dx = (scene_max[0] - scene_min[0]) / resolution[0]
    dy = (scene_max[1] - scene_min[1]) / resolution[1]
    dz = (scene_max[2] - scene_min[2]) / resolution[2]
    
    for i in range(resolution[0]):
        for j in range(resolution[1]):
            for k in range(resolution[2]):
                cx, cy, cz = scene_min[0] + (i + 0.5) * dx, scene_min[1] + (j + 0.5) * dy, scene_min[2] + (k + 0.5) * dz
                is_occupied = False
                for sdx in range(SUBGRID_SIZE):
                    for sdy in range(SUBGRID_SIZE):
                        for sdz in range(SUBGRID_SIZE):
                            sub_pt = (cx + (sdx - 2) * dx / SUBGRID_SIZE,
                                      cy + (sdy - 2) * dy / SUBGRID_SIZE,
                                      cz + (sdz - 2) * dz / SUBGRID_SIZE)
                            if density_fn(sub_pt) > THRESHOLD_DENSITY:
                                is_occupied = True
                                break
                        if is_occupied: break
                    if is_occupied: break
                occupied[i, j, k] = is_occupied
    return occupied

def world_to_voxel_coords(point, scene_min, scene_max, resolution):
    """Map world point to voxel grid indices."""
    return [int((point[0] - scene_min[0]) / ((scene_max[0] - scene_min[0]) / resolution[0])),
            int((point[1] - scene_min[1]) / ((scene_max[1] - scene_min[1]) / resolution[1])),
            int((point[2] - scene_min[2]) / ((scene_max[2] - scene_min[2]) / resolution[2]))]

def is_in_bounds(coords, resolution):
    """Check if voxel coordinates are within grid bounds."""
    return all(0 <= c < r for c, r in zip(coords, resolution))

def interpolate_2d(map_2d, coords_2d):
    """Bilinear interpolation on a 2D map."""
    h, w, c = map_2d.shape
    x, y = coords_2d[:, 0], coords_2d[:, 1]
    x0, y0 = torch.floor(x).long(), torch.floor(y).long()
    x1, y1 = x0 + 1, y0 + 1
    x0 = torch.clamp(x0, 0, w - 1)
    y0 = torch.clamp(y0, 0, h - 1)
    x1 = torch.clamp(x1, 0, w - 1)
    y1 = torch.clamp(y1, 0, h - 1)
    wx = x - x0.float()
    wy = y - y0.float()
    val00 = map_2d[y0, x0, :]
    val01 = map_2d[y0, x1, :]
    val10 = map_2d[y1, x0, :]
    val11 = map_2d[y1, x1, :]
    return (val00 * (1 - wx) * (1 - wy) + val01 * wx * (1 - wy) +
            val10 * (1 - wx) * wy + val11 * wx * wy)

def apply_mlp(features, params):
    """Forward pass of a small MLP given features and parameters."""
    x = features
    for i in range(0, len(params), 2):
        W, b = params[i], params[i+1]
        x = torch.relu(x @ W.t() + b)
    return x[:, :3], x[:, 3:]

def render_ray(ray_origin, ray_direction, scene_min, scene_max, occupancy_volume, 
               hash_tables, mlp_maps, step_divisor=STEP_DIVISOR):
    """Render a single ray using Dynamic MLP Maps with Empty Space Skipping."""
    diagonal = torch.norm(torch.tensor(scene_max) - torch.tensor(scene_min))
    step_size = diagonal / step_divisor
    
    occupied_points = []
    t = 0.0
    max_t = diagonal
    
    while t < max_t:
        point = ray_origin + ray_direction * t
        coords = world_to_voxel_coords(point, scene_min, scene_max, occupancy_volume.shape)
        if is_in_bounds(coords, occupancy_volume.shape) and occupancy_volume[coords]:
            occupied_points.append(point)
        t += step_size
        
    if not occupied_points:
        return torch.zeros(3), 0.0
        
    points_tensor = torch.stack(occupied_points)
    
    # Hash embedding: standard multi-level hash grid lookup [G]
    features = torch.cat([level.lookup(points_tensor) for level in hash_tables], dim=-1)
    
    # MLP map projection
    params_xy = interpolate_2d(mlp_maps[0], points_tensor[:, [0, 1]])
    params_yz = interpolate_2d(mlp_maps[1], points_tensor[:, [1, 2]])
    params_xz = interpolate_2d(mlp_maps[2], points_tensor[:, [0, 2]])
    
    # Evaluate and sum
    c_xy, s_xy = apply_mlp(features, params_xy)
    c_yz, s_yz = apply_mlp(features, params_yz)
    c_xz, s_xz = apply_mlp(features, params_xz)
    
    colors = c_xy + c_yz + c_xz
    densities = s_xy + s_yz + s_xz
    
    # Volume rendering with filtering
    transmittance = 1.0
    accumulated_color = torch.zeros(3)
    
    for i in range(len(points_tensor)):
        sigma = densities[i]
        delta = step_size
        alpha = 1.0 - torch.exp(-sigma * delta)
        weight = transmittance * alpha
        
        if weight < THRESHOLD_WEIGHT:
            transmittance *= (1.0 - alpha)
            continue
            
        accumulated_color += weight * colors[i]
        transmittance *= (1.0 - alpha)
        
    return accumulated_color, 1.0 - transmittance
```

**Parameters:**
*   **Occupancy Volume Resolution:** $24 \times 24 \times 48$ per video frame [S1, unofficial].
*   **Density Threshold ($\tau_1$):** 5. Used to determine if a volume cell is occupied during occupancy volume construction [S1, unofficial].
*   **Weight Threshold ($\tau_2$):** $10^{-3}$. Sampling points with composition weight below this are ignored [S1, unofficial].
*   **Sampling Step Size:** $1/256$th of the diagonal distance of the scene bound [S1, unofficial].
*   **KL Loss Weight ($\lambda_{KL}$):** $10^{-6}$ [S1, unofficial].
*   **Mask Loss Weight:** 0.1 (optional, for foreground-only scenes) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Detailed Content:** The method struggles to render very detailed content, such as text and fingers [S1, unofficial].

## Subtopics

### Multi-level Hash Tables
Stores high-dimensional feature vectors for spatial locations using a hash grid [S1, unofficial]. Sets itself apart from dense feature grids by improving rendering quality and reducing memory overhead [S1, unofficial]. Choose when high-frequency detail is needed and memory is constrained [S1, unofficial]. See [Occupancy Grid and Map-Based Empty Space Skipping](3852-occupancy-grid-and-map-based-empty-space-skipping.md) for comparison on grid-based storage.

### CNN-Generated MLP Maps
Uses a 2D CNN to predict network parameters onto three axis-aligned 2D planes [S1, unofficial]. Sets itself apart from feature maps by enabling faster rendering with smaller MLPs, as feature maps require a large MLP for high quality which is slow [S1, unofficial]. Choose when rendering speed is critical and the scene has smooth variations [S1, unofficial]. See [Space Leaping](5863-space-leaping.md) for comparison on acceleration structures.

## Operating characteristics
*   **Time Complexity:** Rendering is accelerated by empty space skipping, reducing the number of samples per ray [S1, unofficial]. The evaluation of multiple small MLPs is faster than a single large MLP [S1, unofficial]. The method achieves real-time performance [S1, unofficial].
*   **Memory Complexity:** Storage is significantly reduced compared to per-frame models [S1, unofficial]. For a 300-frame video, it requires 240 MB, compared to 9 GB for per-frame KiloNeRF models [S1, unofficial].
*   **Measured Performance:**
    *   **NHR Dataset (sport1):** PSNR 32.92, SSIM 0.959, LPIPS 0.067 [S1, unofficial].
    *   **ZJU-MoCap Dataset (scene 313):** PSNR 32.15, SSIM 0.976, LPIPS 0.049 [S1, unofficial].
*   **Scaling:** Training time and storage scale linearly with the number of frames for per-frame methods, but this method maintains constant storage and low training time (16 hours for 300 frames) [S1, unofficial].
*   **Strengths:** Real-time rendering, low storage, high quality compared to baselines like Neural Volumes, C-NeRF, D-NeRF, and DyNeRF [S1, unofficial].
*   **Limitations:** Difficulty rendering very detailed content (text, fingers) [S1, unofficial].
*   **When to Use:** Real-time volumetric video playback where storage and training time are constraints [S1, unofficial].
*   **When Not to Use:** Scenes with extremely fine, high-frequency details that the hash table and MLP map resolution cannot capture [S1, unofficial].

## Background
Dynamic MLP Maps was introduced by Sida Peng, Yunzhi Yan, Qing Shuai, Hujun Bao, and Xiaowei Zhou from the State Key Lab of CAD&CG, Zhejiang University [S1, unofficial]. It is designed to represent volumetric videos efficiently, addressing the limitations of storing per-frame neural radiance fields [S1, unofficial]. The method builds on [Empty Space Skipping via Data Structures](5619-empty-space-skipping-via-data-structures.md) by using an occupancy volume to skip empty space, and on [Space Leaping](5863-space-leaping.md) by using a grid-based structure for acceleration [S1, unofficial]. It improves upon [Object-Order Empty Space Skipping](865-object-order-empty-space-skipping.md) by integrating the skipping directly into the neural rendering pipeline for dynamic content [S1, unofficial].
