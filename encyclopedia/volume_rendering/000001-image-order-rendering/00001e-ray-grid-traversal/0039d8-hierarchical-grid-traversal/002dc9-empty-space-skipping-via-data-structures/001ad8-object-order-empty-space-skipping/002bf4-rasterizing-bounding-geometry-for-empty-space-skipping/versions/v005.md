# Rasterizing Bounding Geometry for Empty Space Skipping

Also called: Bounding Geometry Rasterization, Raster-based Bounding Box Culling, Rasterizing Bounding Geometry

## Overview
A volume rendering optimization technique that rasterizes bounding geometry to compute start and end positions for ray marching, skipping empty space by discarding fragments that are not at the minimum depth value [S1, unofficial]. It exploits hardware-accelerated rasterization to skip over empty space by rasterizing bounding geometries, such as bounding boxes of leaf nodes of a tree structure [S2, unofficial]. Unlike standard octree empty space skipping, this method moves the major cost of empty space skipping into a rasterization stage that produces per-pixel lists of non-empty ray segments [S2, unofficial].

## How it works
**Inputs:**
*   Volume texture `gridTex` containing maximum iso values per voxel [S1, unofficial].
*   Threshold iso value for determining active voxels [S1, unofficial].
*   Coarse grid dimensions (e.g., $32 \times 32 \times 25$ for a $256 \times 256 \times 200$ volume with $8^3$ voxel cells) [S1, unofficial].

**Outputs:**
*   Ray start and end positions for each pixel [S1, unofficial].
*   Rendered volume image [S1, unofficial].

**Data Structures:**
*   `gridTex`: 3D texture where each voxel stores the maximum iso value of the underlying fine-grained volume region [S1, unofficial].
*   Bounding Geometry: A set of quads representing the boundaries between active and inactive regions in the coarse grid [S1, unofficial].

**Steps:**

1.  **Initialization:** Generate the volume texture `gridTex` [S1, unofficial]. For each voxel in the coarse grid, compute the maximum iso value from the underlying fine-grained volume data [S1, unofficial].
2.  **Generate Bounding Geometry:** Given a threshold iso value, determine active voxels [S1, unofficial]. A grid voxel is active if its value in `gridTex` is above the threshold [S1, unofficial]. For each pair of neighboring voxels in `gridTex`, generate a quad if one voxel is active and the other is inactive [S1, unofficial]. This process must be repeated whenever the iso value changes [S1, unofficial].
3.  **First Pass (Depth Buffering):** Render the bounding geometry to an offscreen buffer [S1, unofficial]. Store the minimum and maximum depth values for each fragment covered by the geometry [S1, unofficial].
4.  **Second Pass (Rendering):** Render the front faces of the bounding geometry again to the main buffer [S1, unofficial].
5.  **Fragment Discard:** In the fragment shader, discard fragments that are not at the minimum depth value [S1, unofficial]. This ensures that only the front-most entry point into a non-empty region is processed [S1, unofficial].
6.  **Ray Setup:** Compute the start and end positions for the ray using the minimum and maximum depth values obtained from the first pass [S1, unofficial]. The fragment positions of the front and back faces of the rasterized bounding geometry serve as these start and end points [S2, unofficial].
7.  **Ray Marching:** March the ray through the volume using the computed start and end positions [S1, unofficial].

**Pseudocode:**

```python
def generate_bounding_geometry(gridTex, threshold, dims):
    # dims = (W, H, D)
    # gridTex is a list of lists of lists: gridTex[x][y][z]
    active = [[[gridTex[x][y][z] > threshold for z in range(dims[2])] for y in range(dims[1])] for x in range(dims[0])]
    quads = []
    for x in range(dims[0]):
        for y in range(dims[1]):
            for z in range(dims[2]):
                if active[x][y][z]:
                    # Check +x neighbor
                    if x + 1 >= dims[0] or not active[x + 1][y][z]:
                        quads.append(((x, y, z), (x, y + 1, z), (x, y + 1, z + 1), (x, y, z + 1)))
                    # Check -x neighbor
                    if x - 1 < 0 or not active[x - 1][y][z]:
                        quads.append(((x + 1, y, z), (x + 1, y + 1, z), (x + 1, y + 1, z + 1), (x + 1, y, z + 1)))
                    # Check +y neighbor
                    if y + 1 >= dims[1] or not active[x][y + 1][z]:
                        quads.append(((x, y, z), (x + 1, y, z), (x + 1, y, z + 1), (x, y, z + 1)))
                    # Check -y neighbor
                    if y - 1 < 0 or not active[x][y - 1][z]:
                        quads.append(((x, y + 1, z), (x + 1, y + 1, z), (x + 1, y + 1, z + 1), (x, y + 1, z + 1)))
                    # Check +z neighbor
                    if z + 1 >= dims[2] or not active[x][y][z + 1]:
                        quads.append(((x, y, z), (x + 1, y, z), (x + 1, y + 1, z), (x, y + 1, z)))
                    # Check -z neighbor
                    if z - 1 < 0 or not active[x][y][z - 1]:
                        quads.append(((x, y + 1, z + 1), (x + 1, y + 1, z + 1), (x + 1, y, z + 1), (x, y, z + 1)))
    return quads
```

**Parameters:**
*   Threshold iso value: Determines which voxels are considered active [S1, unofficial].
*   Coarse grid size: Determines the resolution of the bounding geometry [S1, unofficial].

**Edge Cases:**
*   Changing iso values requires regenerating the bounding geometry [S1, unofficial].
*   Precision issues in depth buffering may affect the accuracy of start/end positions [G].

## Subtopics

### [SparseLeap Rasterization](5154-sparseleap-rasterization.md)
SparseLeap is a method for efficient empty space skipping in very large, sparse volume data, such as terabyte-sized microscopy volumes, by exploiting hardware-accelerated rasterization to avoid hierarchy traversal on the GPU. It solves the problem of fragmented space subdivisions making empty regions hard to skip and the infeasibility of pre-computing well-adapted space subdivisions due to frequent changes in active objects. Unlike standard octree empty space skipping, SparseLeap scales better to large, sparse data by moving the major cost of empty space skipping into a rasterization stage that produces per-pixel lists of non-empty ray segments. It is agnostic of the underlying data structure used for managing volume data, such as page-table hierarchies or octrees.

## Operating characteristics
*   **Time Complexity:** Depends on the number of active bounding geometry fragments [S2, unofficial]. Rasterization is hardware-accelerated, potentially faster than CPU/GPU tree traversal [S2, unofficial].
*   **Memory Complexity:** Requires storage for `gridTex` and the bounding geometry [S1, unofficial].
*   **Performance:** Can lead to fewer look-ups into the empty-space skipping data structure during rendering when compared to octree structures [S2, unofficial].
*   **Strengths:** Avoids hierarchy traversal on the GPU [S2, unofficial].
*   **Limitations:** Requires regenerating geometry when iso values change [S1, unofficial].

## Background
The technique was proposed by Liu et al. [LCDP13] and further utilized by Hadwiger et al. [HAAB+ 18] to avoid hierarchy traversal on the GPU [S2, unofficial]. It is part of the broader field of object-order empty space skipping [S2, unofficial].
