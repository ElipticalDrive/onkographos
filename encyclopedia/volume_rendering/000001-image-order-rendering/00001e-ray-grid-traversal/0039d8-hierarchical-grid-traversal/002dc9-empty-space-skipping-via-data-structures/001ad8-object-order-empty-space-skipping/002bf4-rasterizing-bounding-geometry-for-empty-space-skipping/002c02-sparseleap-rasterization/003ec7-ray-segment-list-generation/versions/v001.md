# Ray Segment List Generation

Also called: Rasterizing occupancy geometry for ray segments

## Overview
Ray Segment List Generation converts the rasterized occupancy geometry of a volume into singly-linked lists of ray events per pixel, defining ray segments (intervals between events) with associated occupancy classes [S1, unofficial]. It sets itself apart from hierarchical traversal methods by performing a sequential, non-hierarchical "traversal" where the occupancy class is embedded directly in the event types (entry/exit), eliminating the need for a stack to push and pop classes during parsing [S1, unofficial].

## How it works
**Inputs:**
*   Occupancy geometry array (bounding boxes with front/back face flags and occupancy classes).
*   Visibility order of the geometry.
*   Volume bounding box (for initialization).

**Outputs:**
*   For each pixel: a singly-linked list of ray events. Each event contains `Depth` (1D parameter), `EventType` (entry/exit), and `OccupancyClass` (empty/non-empty/unknown). The list defines ray segments between consecutive events.

**Data Structures:**
*   **Ray Event:** A structure containing:
    *   `depth`: float, the 1D parameter position of the intersection with a bounding box face.
    *   `type`: enum, `ENTRY` or `EXIT`.
    *   `class`: enum, `EMPTY`, `NON_EMPTY`, or `UNKNOWN`.
*   **Ray Segment List:** A singly-linked list of `Ray Event` nodes, initialized per pixel.

**Initialization:**
1.  For each pixel, initialize the ray segment list as a single segment with occupancy class `UNKNOWN`.
2.  This segment starts at the volume bounding box front face position and ends at the back face position.
3.  The list comprises two events:
    *   Event 1: `type=ENTRY`, `depth=front_face_position`, `class=UNKNOWN` (or derived from parent if applicable, but sources specify default unknown for the volume box).
    *   Event 2: `type=EXIT`, `depth=back_face_position`, `class=UNKNOWN` (or derived from parent).
    *   *Note:* The sources state the default segment is `UNKNOWN` spanning the volume bounding box [S1, unofficial].

**Rasterization Pass:**
1.  Rasterize the occupancy geometry array in a single rendering pass.
2.  For each fragment generated, invoke a fragment shader.
3.  Determine if the fragment resulted from a front face or back face rasterization to set the `EventType` (`ENTRY` or `EXIT`) [S1, unofficial].
4.  Create a new `Ray Event` for the fragment:
    *   `depth`: Intersection parameter.
    *   `type`: Determined in step 3.
    *   `class`:
        *   If `type == ENTRY`: Set to the occupancy class of the bounding box that generated the event.
        *   If `type == EXIT`: Set to the occupancy class of the box's parent [S1, unofficial].

**Incremental Event Processing (Merging and Deletion):**
For each incoming event $E_{new}$, access the tail of the current ray segment list. Let the last event in the list be $E_{last}$. If $E_{last}.depth \neq E_{new}.depth$, append $E_{new}$ to the list. If $E_{last}.depth == E_{new}.depth$, apply the following rules to $E_{last}$ and $E_{new}$ (and potentially preceding events):

1.  **Merge Same Type:** If $E_{last}.type == E_{new}.type$ (both ENTRY or both EXIT):
    *   Delete $E_{last}$.
    *   Replace $E_{last}$'s position in the list with $E_{new}$ (or append $E_{new}$ if $E_{last}$ was the only one, effectively overwriting).
    *   The surviving event is $E_{new}$, adopting its `class` [S1, unofficial].
2.  **Delete Exit-Entry Pair (Same Class):** If $E_{last}.type == EXIT$ and $E_{new}.type == ENTRY$:
    *   Let $E_{prev}$ be the event preceding $E_{last}$ in the list (if it exists).
    *   If $E_{new}.class == E_{prev}.class$ (indicating consecutive segments of the same occupancy class):
        *   Delete both $E_{last}$ and $E_{new}$.
        *   This merges the segment ending at $E_{last}$ and the segment starting at $E_{new}$ into one longer segment of class $E_{prev}.class$ [S1, unofficial].
3.  **Delete Entry-Exit Pair (Grazing):** If $E_{last}.type == ENTRY$ and $E_{new}.type == EXIT$:
    *   Delete both $E_{last}$ and $E_{new}$, regardless of occupancy class.
    *   This handles grazing rays hitting an edge or corner, generating two events at the same depth [S1, unofficial].
4.  **Remove Short Empty Segments:**
    *   Detect very short empty ray segments that cannot be merged because they precede a non-empty segment.
    *   Remove these segments to reduce depth complexity [S1, unofficial].

**Pseudocode:**

```python
def process_event(ray_segment_list, new_event):
    """
    Incrementally updates the ray segment list with a new event,
    applying merging and deletion rules for events at the same depth.
    """
    if not ray_segment_list:
        ray_segment_list.append(new_event)
        return

    last_event = ray_segment_list[-1]

    # If depths differ, simply append
    if last_event.depth != new_event.depth:
        ray_segment_list.append(new_event)
        return

    # Depths are equal, apply rules
    prev_event = ray_segment_list[-2] if len(ray_segment_list) > 2 else None

    # Rule 1: Merge same type
    if last_event.type == new_event.type:
        # Overwrite last_event with new_event
        ray_segment_list[-1] = new_event
        return

    # Rule 2: Exit followed by Entry (same class)
    if last_event.type == EXIT and new_event.type == ENTRY:
        # Check if previous event exists and has same class as new event
        if prev_event is not None and prev_event.class == new_event.class:
            # Delete both last_event and new_event
            ray_segment_list.pop() # Remove last_event
            # new_event is not added
            return
        else:
            # Cannot merge, append new_event
            ray_segment_list.append(new_event)
            return

    # Rule 3: Entry followed by Exit (grazing)
    if last_event.type == ENTRY and new_event.type == EXIT:
        # Delete both
        ray_segment_list.pop() # Remove last_event
        # new_event is not added
        return

    # Fallback: Append if no rule matched (should be covered by above, but for safety)
    ray_segment_list.append(new_event)

def generate_ray_segment_lists(occupancy_geometry, volume_bbox):
    """
    Main function to generate ray segment lists for all pixels.
    """
    # Initialize ray segment lists for all pixels
    ray_segment_lists = {}
    for pixel in all_pixels:
        # Default segment: UNKNOWN class, spanning volume bbox
        front_depth = volume_bbox.front_face_depth(pixel)
        back_depth = volume_bbox.back_face_depth(pixel)
        
        event_entry = RayEvent(depth=front_depth, type=ENTRY, class=UNKNOWN)
        event_exit = RayEvent(depth=back_depth, type=EXIT, class=UNKNOWN)
        
        ray_segment_lists[pixel] = [event_entry, event_exit]

    # Rasterize occupancy geometry
    for fragment in rasterize(occupancy_geometry):
        pixel = fragment.pixel
        ray_segment_list = ray_segment_lists[pixel]
        
        # Determine event type from face flag
        if fragment.is_front_face:
            event_type = ENTRY
        else:
            event_type = EXIT
            
        # Determine occupancy class
        if event_type == ENTRY:
            occ_class = fragment.bounding_box.occupancy_class
        else: # EXIT
            occ_class = fragment.bounding_box.parent.occupancy_class
            
        new_event = RayEvent(depth=fragment.depth, type=event_type, class=occ_class)
        
        # Process incrementally
        process_event(ray_segment_list, new_event)

    return ray_segment_lists
```

**Edge Cases and Pitfalls:**
*   **Grazing Rays:** Rays hitting box edges/corners generate Entry/Exit pairs at the same depth. These must be deleted to avoid spurious segments [S1, unofficial].
*   **Short Empty Segments:** Empty segments preceding non-empty segments that are too short to merge must be explicitly detected and removed to reduce depth complexity [S1, unofficial].
*   **Parent Class for Exit:** Correctly identifying the parent box's occupancy class for exit events is critical for the merging logic [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear in the number of fragments generated by the occupancy geometry rasterization, as each fragment triggers a constant-time update to the ray segment list tail [S1, unofficial].
*   **Memory Complexity:** Proportional to the number of ray events per pixel. Merging and deletion rules reduce the final list size, but worst-case depth complexity depends on the geometry density [S1, unofficial].
*   **Strengths:** Enables sequential, non-hierarchical traversal of the occupancy histogram tree without a stack, simplifying the ray-casting stage [S1, unofficial].
*   **Limitations:** Requires careful handling of merging rules to maintain consistency. Performance depends on the efficiency of the fragment shader and the depth complexity of the resulting lists [S1, unofficial].

## Background
Ray Segment List Generation is part of the SparseLeap algorithm for efficient empty space skipping in large-scale volume rendering [S1, unofficial]. It was introduced in the paper "SparseLeap: Efficient Empty Space Skipping for Large-Scale Volume Rendering" (2018) [S1, unofficial]. The method builds on the concept of lazy evaluation and occupancy histogram trees, where geometry is generated on-the-fly [S1, unofficial].
