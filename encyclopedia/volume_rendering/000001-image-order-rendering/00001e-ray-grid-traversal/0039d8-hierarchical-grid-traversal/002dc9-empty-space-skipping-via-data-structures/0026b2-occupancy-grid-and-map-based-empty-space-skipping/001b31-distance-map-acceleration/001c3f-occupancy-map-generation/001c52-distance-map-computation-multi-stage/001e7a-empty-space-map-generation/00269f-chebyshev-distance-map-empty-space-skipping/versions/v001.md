# Chebyshev Distance Map Empty Space Skipping

Also called: Isotropic Chebyshev distance map

## Overview
This method accelerates volume ray casting by pre-computing a Chebyshev distance map from an occupancy map, allowing rays to skip multiple empty blocks in any dimension [S1]. It improves upon standard occupancy map skipping by enabling larger, dimension-independent skips, though it requires more complex generation and higher memory overhead [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** An occupancy map where occupied voxels are marked (e.g., value 255) and empty voxels are 0.
*   **Output:** A distance map texture storing the Chebyshev distance to the nearest occupied block for every voxel.
*   **Auxiliary:** A swap image (texture) of the same dimensions as the distance map, required during generation [S1].

**Data Structures:**
*   **Distance Map:** A 3D texture (`uimage3D`) with `r8ui` format (unsigned 8-bit integer per channel). Distances are stored as unsigned 8-bit integers, limiting the maximum representable distance to 255 [S1].
*   **Swap Image:** A 3D texture with the same format and dimensions as the distance map, used to store intermediate results during the second transformation [S1].

**Chebyshev Distance Definition:**
The Chebyshev distance between two points $\mathbf{p}_1$ and $\mathbf{p}_2$ is defined as [S1]:
$$D_{\text{Chebyshev}}(\mathbf{p}_1, \mathbf{p}_2) = \max (|\mathbf{p}_1 - \mathbf{p}_2|)$$
where the maximum is taken over all dimensions [S1].

**Generation Algorithm:**
The distance map is generated from the occupancy map using three sequential 1D passes, adapted from Saito and Toriwaki [12] for GPU parallelization [S1]. Each pass operates independently on rows, columns, or slices [S1].

1.  **First Transformation (X-axis):** Processes rows. It performs a forward pass followed by a backward pass to compute distances along the x-axis. The occupancy map can be read directly and written to the distance map in this stage [S1].
2.  **Second Transformation (Y-axis):** Processes columns. It reads from the output of the first transformation and writes to the swap image. It uses a zig-zag search from each voxel to find the minimum distance [S1].
3.  **Third Transformation (Z-axis):** Processes slices. It is identical to the second transformation but operates on the z-axis. It reads from the swap image and writes the final Chebyshev distance to the distance map [S1].

**Ray Skipping Calculation:**
When a ray is at parameter $u$ and the current voxel has distance $D$, the number of steps $\Delta \mathbf{i}$ to the next sampling point $D$ blocks away is calculated per dimension $j \in \{x, y, z\}$ [S1]:

$$\Delta_{ij} = \begin{cases} \lceil (D + \lfloor \mathbf{u}_j \rfloor - \mathbf{u}_j) / \Delta \mathbf{u}_j \rceil, & \text{if } \Delta \mathbf{u}_j > 0 \\ \lceil (1 - D + \lfloor \mathbf{u}_j \rfloor - \mathbf{u}_j) / \Delta \mathbf{u}_j \rceil, & \text{otherwise} \end{cases} \quad (13)$$

This can be vectorized as [S1]:
$$\Delta \mathbf{i} = \lceil (\text{step}(-\Delta \mathbf{u}) + \text{sgn}(\Delta \mathbf{u}) \cdot D + \lfloor \mathbf{u} \rfloor - \mathbf{u}) / \Delta \mathbf{u} \rceil \quad (14)$$
where $\text{step}(x)$ is 0 if $x < 0$ and 1 otherwise, and $\text{sgn}(x)$ is the sign function [S1].

    Returns: dist, the Chebyshev distance map.

    # First Transformation: X-axis (Rows)
    # Forward pass
    for z in range(dim_z):
        for y in range(dim_y):
            D1 = occupancy[0][y][z]
            dist[0][y][z] = D1
            for x in range(1, dim_x):
                D = min(D1 + 1, occupancy[x][y][z])
                dist[x][y][z] = D
                D1 = D

                # Forward: D = min(D1 + 1, occ[pos]). Store in dist. D1 = D.
                # Backward: D = min(D1 + 1, dist[pos]). Store in dist. D1 = D.
                # This means the backward pass uses the value already in dist (from forward pass)

    dist = [[[[0 for _ in range(dim_z)] for _ in range(dim_y)] for _ in range(dim_x)]]
    
    # Forward pass
    for z in range(dim_z):
        for y in range(dim_y):
            D1 = occupancy[0][y][z]
            dist[0][y][z] = D1
            for x in range(1, dim_x):
                D = min(D1 + 1, occupancy[x][y][z])
                dist[x][y][z] = D
                D1 = D
                
    # Backward pass
    for z in range(dim_z):
        for y in range(dim_y):
            D1 = dist[dim_x - 1][y][z]
            for x in range(dim_x - 2, -1, -1):
                # Read current dist value (from forward pass)
                current_dist_val = dist[x][y][z]
                D = min(D1 + 1, current_dist_val)
                dist[x][y][z] = D
                D1 = D

    # Second Transformation: Y-axis (Columns)
    # Reads from dist, writes to swap
    for z in range(dim_z):
        for x in range(dim_x):
            for y in range(dim_y):
                D = dist[x][y][z]
                # Zig-zag search
                for n in range(1, D):

                        D_n = dist[x][y - n][z]
                        D = min(D, max(n, D_n))

    # Reads from swap, writes to dist

                # Zig-zag search on Z axis

                        D = min(D, max(n, D_n))

                        D_n = swap[x][y][z + n]
                        D = min(D, max(n, D_n))
                dist[x][y][z] = D
                
    return dist

**Edge Cases and Pitfalls:**
*   **Memory Overhead:** The generation process requires a swap image, doubling the memory requirements compared to using only an occupancy map [S1].
*   **Distance Limit:** Distances are stored as unsigned 8-bit integers, limiting the maximum distance to 255. If the distance to the nearest occupied block exceeds 255, the value will be clamped or overflow, potentially leading to incorrect skipping [S1].
*   **Transfer Function Changes:** The distance map must be regenerated every time the transfer function changes, as the occupancy map depends on the transfer function threshold [S1].

## Operating characteristics
*   **Time Complexity:** The generation of the distance map involves three passes over the volume. The first pass is $O(N)$ where $N$ is the number of voxels. The second and third passes involve a zig-zag search which, in the worst case, can be $O(N \cdot D)$ where $D$ is the maximum distance, but typically much faster due to early termination [S1]. The ray casting step itself is $O(1)$ per skip, allowing multiple blocks to be skipped with a single sample [S1].
*   **Memory Complexity:** Requires storage for the occupancy map, the distance map, and the swap image during generation. The distance map uses `r8ui`, so 1 byte per voxel [S1].
*   **Performance:** The method is faster than the original approach which resumed occupancy map sampling after a set length of empty voxels [S1]. The zig-zag search in the second and third transformations reduces the number of IO operations and is faster than the original algorithm [S1].
*   **Strengths:** Enables skipping multiple blocks in any dimension, not constrained by the block size $B$ as with the occupancy map method [S1].
*   **Limitations:** Computational complexity of generating the distance map, which must be done every time the transfer function changes [S1]. Memory overhead due to the swap image [S1]. Limited maximum distance of 255 [S1].

## Background
The method is based on the Chebyshev distance metric, which is the greatest difference between two points along any dimension [S1]. The algorithm for transforming an occupancy map into a Chebyshev distance map was adapted from Saito and Toriwaki [12] for efficient GPU parallelization [S1]. Previous papers using Chebyshev distance maps for ray casting acceleration noted the computational complexity of generating them [S1].
