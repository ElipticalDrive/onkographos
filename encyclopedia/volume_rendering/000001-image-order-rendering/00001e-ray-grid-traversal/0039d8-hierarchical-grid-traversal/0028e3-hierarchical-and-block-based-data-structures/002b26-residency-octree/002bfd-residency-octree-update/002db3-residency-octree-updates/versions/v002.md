# Residency-Octree Updates

## Overview
This method updates a residency octree to reflect changes in a brick cache during volume rendering [S1, unofficial]. It handles metadata reception, brick addition, and LRU cache eviction by marking leaf nodes as partially mapped and propagating bitmap updates up the tree [S1, unofficial].

## How it works
The method maintains a residency octree where each node stores per-channel metadata and a residency bitmap [S1, unofficial]. The core logic processes three events: metadata reception, brick addition, and LRU cache eviction [S1, unofficial].

### Inputs and Outputs
*   **Inputs**: New volume metadata, new brick data, brick cache state [G].
*   **Outputs**: Updated residency octree nodes (metadata and bitmaps), updated brick cache [G].

### Data Structures
*   **Residency Octree Node**:
    *   `metadata`: Channel-specific status (e.g., `VALID`, `INVALID`) [S1, unofficial].
    *   `residency_bitmap`: A bitfield where each bit corresponds to a resolution level; a bit is set if the node is partially mapped at that level [S1, unofficial].
    *   `children`: Pointers to child nodes for non-leaf nodes [G].
*   **Brick Cache**:
    *   Fixed-size array of slots [G].
    *   Each slot holds a brick identifier, its spatial extent, resolution level, and channel [G].
    *   LRU tracking for eviction [S1, unofficial].

### Numbered Steps

#### 1. Metadata Reception
When new metadata for a volume region is received:
1.  Check if a node exists for the region's spatial extent in the octree [G].
2.  **If new**: Create the node and add it to the octree [S1, unofficial]. Initialize `metadata` as `INVALID` for all channels except the received one [S1, unofficial]. Initialize `residency_bitmap` by checking if the node is partially mapped in each resolution level [S1, unofficial].
3.  **If exists**: Update the channel-specific `metadata` [S1, unofficial]. Initialize residency info for the new channel if the node already holds metadata for another channel (multi-channel case) [S1, unofficial].

#### 2. Brick Addition
When a new brick is received:
1.  Select an available slot in the brick cache [S1, unofficial]. If none is available, trigger LRU Eviction (see below) [S1, unofficial].
2.  Determine all residency-octree leaf nodes whose spatial extent overlaps the brick's spatial extent [S1, unofficial].
3.  Mark these leaf nodes as partially mapped in the brick's resolution level and channel by setting the corresponding bit in their `residency_bitmap` [S1, unofficial].
4.  Propagate the update up the tree to the root: for each non-leaf node on the path, update its `residency_bitmap` by computing the bit-wise OR of its children's bitmaps [S1, unofficial]. Terminate upward propagation as soon as a node's bitmap remains unchanged by this operation [S1, unofficial].

#### 3. LRU Cache Eviction
If no slot is available for a new brick:
1.  Evict the least recently accessed brick from the cache [S1, unofficial].
2.  Identify all leaf nodes whose spatial extent overlaps the evicted brick's spatial extent [S1, unofficial].
3.  For each such leaf node: check if any other brick in the same resolution level is resident in the cache [S1, unofficial]. If no other brick is resident, the node is no longer partially mapped in that resolution level; set the corresponding bit in the node's `residency_bitmap` to zero [S1, unofficial].
4.  Update non-leaf nodes by setting their bitmaps to the bit-wise OR of their child nodes' bitmaps, propagating up to the root [S1, unofficial].

### Pseudocode
```python
def update_residency_octree(new_brick, cache, octree_root):
    """Handles addition of a new brick and cache eviction if necessary."""
    slot = cache.find_available_slot()
    if slot is None:
        evicted_brick = cache.evict_lru()
        handle_eviction(evicted_brick, cache, octree_root)
        slot = cache.find_available_slot()
    cache.store(slot, new_brick)
    leaf_nodes = find_leaves_overlapping(octree_root, new_brick.spatial_extent)
    for node in leaf_nodes:
        node.residency_bitmap.set_bit(new_brick.resolution_level, new_brick.channel)
    propagate_update(leaf_nodes, octree_root)

def handle_eviction(evicted_brick, cache, octree_root):
    """Handles the removal of a brick due to LRU eviction."""
    leaf_nodes = find_leaves_overlapping(octree_root, evicted_brick.spatial_extent)
    for node in leaf_nodes:
        is_still_mapped = False
        for brick in cache.get_bricks_at_resolution(evicted_brick.resolution_level):
            if brick.overlaps(node.spatial_extent):
                is_still_mapped = True
                break
        if not is_still_mapped:
            node.residency_bitmap.clear_bit(evicted_brick.resolution_level, evicted_brick.channel)
    propagate_update(leaf_nodes, octree_root)

def propagate_update(affected_leaves, root):
    """Propagates bitmap updates up the tree, terminating early if unchanged."""
    paths = collect_unique_ancestors(affected_leaves)
    for path in paths:
        for node in path:
            if node.is_leaf:
                continue
            new_bitmap = 0
            for child in node.children:
                new_bitmap |= child.residency_bitmap
            if new_bitmap == node.residency_bitmap:
                break
            node.residency_bitmap = new_bitmap

def find_leaves_overlapping(root, extent):
    """Returns all leaf nodes whose spatial extent overlaps the given extent."""
    leaves = []
    if root.is_leaf:
        if root.spatial_extent.overlaps(extent):
            leaves.append(root)
        return leaves
    for child in root.children:
        if child.spatial_extent.overlaps(extent):
            leaves.extend(find_leaves_overlapping(child, extent))
    return leaves

def collect_unique_ancestors(leaves):
    """Collects unique upward paths from leaves to root."""
    paths = set()
    for leaf in leaves:
        current = leaf
        while current is not None:
            paths.add(current)
            current = current.parent
    return sorted(paths, key=lambda n: n.depth, reverse=True)
```

### Parameters and Edge Cases
*   **Bitmap Size**: The number of bits in `residency_bitmap` equals the number of resolution levels [S1, unofficial].
*   **Multi-channel Volumes**: Residency info is initialized per channel; adding metadata for a new channel requires re-evaluating residency for that channel [S1, unofficial].
*   **Precision**: Bit-wise operations are exact with no floating-point precision issues [G].
*   **Boundaries**: Leaf nodes must correctly handle spatial overlaps; bricks exactly on a boundary should be included in the overlap check [G].
*   **Degenerate Input**: Empty cache or empty octree should be handled gracefully as a no-op [G].

## Operating characteristics
*   **Time Complexity**: Not given in the sources.
*   **Memory Complexity**: Not given in the sources.
*   **Strengths**: Bitmap propagation minimizes redundant writes by terminating early when bitmaps are unchanged [S1, unofficial].
*   **Limitations**: Requires synchronization for parallel updates; LRU eviction may trigger cascading bitmap updates [G].
*   **When to use**: Dynamic streaming volumes with frequent cache changes [G].
*   **When not to use**: Static volumes with no cache updates [G].

## Background
This method is described in the context of scalable web-based volume rendering of large biomedical datasets [S1, unofficial]. It builds on earlier work using LRU cache eviction [SCRL20] cited in [S1, unofficial]. The approach is designed for GPU implementation to avoid CPU-GPU synchronization bottlenecks [G].
