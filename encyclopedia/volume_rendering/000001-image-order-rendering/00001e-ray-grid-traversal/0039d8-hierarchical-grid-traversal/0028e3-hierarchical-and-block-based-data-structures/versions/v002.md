# Hierarchical and Block-Based Data Structures

Also called: Hierarchical Grid Traversal, Block-Based Data Structures, Octree-based traversal, Multi-level Grid Structures, Empty Space Skipping via Data Structures, Brick Size and Octree Limit Tuning, Residency Octree, Ray-marching reference (min-max octree accelerated), ExaBricks Rendering with RTX BVH, Hierarchical Data Structures, Block-based GPU Volume Rendering with Acceleration, Multiresolution with Octree Bricking

## Overview
Hierarchical and Block-Based Data Structures organize volumetric data into tree or grid hierarchies where nodes represent spatial regions and store aggregate metadata (e.g., occupancy flags, min/max scalar values) to enable empty space skipping and adaptive resolution during ray traversal [Parent]. This family distinguishes itself from flat grid traversal by reducing the number of processed voxels per ray through subtree pruning, and from pure software k-d trees by leveraging hardware acceleration (e.g., RTX BVH) or specific GPU memory hierarchies (e.g., brick caching) [S1, unofficial].

## Shared principles
All methods in this family rely on a spatial subdivision hierarchy where internal nodes store aggregate information derived from their children or leaf voxels. The core mechanism is:
1.  **Aggregation:** Leaf nodes encode voxel properties. Internal nodes aggregate these properties (e.g., binary occupancy, min/max scalar ranges) from their children.
2.  **Pruning:** During ray traversal, if a node indicates an empty or inactive region (e.g., occupancy flag is 0, or min/max bounds are outside the transfer function's opacity range), the entire subtree is skipped.
3.  **Construction:** The hierarchy is typically constructed bottom-up. The depth is determined by data dimensions, often requiring padding to powers of two or specific size constraints to maintain regular subdivision [Parent].

## Subtopics

### [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md)
An accelerated direct isosurface visualization technique using a min-max octree to facilitate empty space skipping during ray marching. It serves as a performance baseline for general volumes, offering negligible memory overhead for the input volume and low auxiliary data requirements. Unlike Sphere Tracing, which requires precomputed signed distance functions, or Segment Tracing, which is limited to hierarchical skeletal implicit surfaces, this approach is applicable to a wide range of scalar volumes. It guarantees continuous isosurfaces that locally interpolate the input data, unlike mesh extraction techniques (e.g., marching cubes) which may produce topologically different piecewise linear meshes.

### [ExaBricks Rendering with RTX BVH](2577-exabricks-rendering-with-rtx-bvh.md)
A hardware-accelerated volume rendering method for Adaptive Block-Refined (ABR) data that utilizes an RTX Bounding Volume Hierarchy (BVH) to traverse spatial regions, perform volume integration, and skip empty space. It distinguishes itself from software-based k-d tree approaches (e.g., Kähler et al. [17]) by leveraging GPU hardware ray tracing to avoid non-trivial control flow and per-thread stacks in shaders, while supporting interactive transfer function editing and adaptive sampling.

### [Hierarchical Data Structures](4133-hierarchical-data-structures.md)
Acceleration techniques for image-order volume rendering that organize volumetric data into a tree where nodes represent spatial regions and store aggregate information (e.g., binary occupancy flags, min/max values) derived from child nodes or leaf voxels [Parent]. This structure allows traversal to skip entire subtrees if a node indicates an empty or inactive region, significantly reducing the number of voxels processed per ray [Parent]. Unlike sibling methods that may use condensed sparse structures (like [Residency Octree](4950-residency-octree.md)) or object-order traversal (like [Jiang et al. Acceleration Structure](1673-jiang-et-al-acceleration-structure.md)), this family encompasses various specific implementations such as complete octrees, mip pyramids, and unstructured spatial trees, each optimizing the trade-off between construction cost, memory footprint, and traversal speed [1663-hierarchical-spatial-enumeration-optimization.md][1673-jiang-et-al-acceleration-structure.md][3731-silhouette-image-space-acceleration-structure-mip-pyramid.md].

### [Brick Size and Octree Limit Tuning](4263-brick-size-and-octree-limit-tuning.md)
Optimizes GPU-based volume rendering by balancing texture memory constraints, rasterization overhead, and hardware-specific sampling penalties. It differs from sibling methods by treating brick size and octree depth as orthogonal variables that must be tuned specifically for the target graphics hardware's texture unit behavior and memory hierarchy, rather than relying solely on algorithmic space-skipping.

### [Residency Octree](4950-residency-octree.md)
A hybrid data structure for out-of-core direct volume rendering (DVR) of multi-volume datasets that decouples the cache residency of multi-resolution data from the spatial subdivision determined by the octree. Unlike standard octrees where each node maps to exactly one brick (one-to-one correspondence), each Residency Octree node represents a resolution-independent spatial region and references all resolution levels in a bricked volume hierarchy. This allows efficient mixing of channel resolutions, cache-miss compensation by substituting missing bricks with available resolutions, and fine-grained empty-space skipping independent of the underlying bricking granularity. It combines the flexible mixed-resolution access of page-table hierarchies with the efficient empty-space skipping of octrees.

## Background
The concept of using hierarchical structures for volume rendering acceleration originated with the need to handle large datasets efficiently. LaMar et al. [166] employed an octree to encode a hierarchical volume "bricking" for large dataset rendering, establishing the foundation for multiresolution octree-based approaches [S2]. Similar octree-based multiresolution methods were presented by Boada and colleagues [167]. Kähler and Hege [168, 169] extended these concepts to Adaptive Mesh Refinement (AMR) data using 3DTM, partitioning volumes into axis-aligned bricks of the same resolution level and extending the AMR tree-based 3DTM to render large and sparse datasets. Gao et al. [170] proposed parallel multiresolution techniques to accelerate large dataset visualization [S2].
