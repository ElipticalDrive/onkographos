# Two-Level Grid Ray Traversal

Also called: Modified DDA Traversal

## Overview
Two-Level Grid Ray Traversal is a hierarchical ray traversal algorithm designed for two-level grid structures, modifying the classic DDA algorithm to step through top-level cells and then treat each top cell as a uniform grid for leaf traversal [S1, unofficial]. It solves the problem of efficiently traversing sparse or complex volumetric data by leveraging coherence within top-level cells, offering a SIMD-friendly approach that minimizes code divergence except when rays disagree on the traversal level [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A ray $r$ with origin $O$ and direction $D$, a cell size $s$, and a two-level grid structure consisting of a top-level uniform grid where each active cell may contain a leaf-level uniform grid [S1, unofficial].
- Output: A sequence of leaf cells intersected by the ray, or a termination signal [S1, unofficial].

**Data Structures:**
- Top-level grid: Uniform grid partitioning the space [S1, unofficial].
- Leaf grid: Uniform grid stored within each active top-level cell [S1, unofficial].
- Decision variables: Standard DDA variables including $t_{max}$ (ray length limit), $t_{delta}$ (distance to next cell boundary per axis), $step$ (axis direction $\pm 1$), and $t_{next}$ (distance to next boundary along each axis) [G].

**Numbered Steps:**
1. Initialize top-level DDA traversal using the Amanatides and Woo algorithm [S1, unofficial].
2. For each top-level cell intersected by the ray:
   a. If the top-level cell contains leaf data, initialize leaf-level traversal [S1, unofficial].
   b. Reuse decision variables from the top-level traversal to spare computations when initializing the leaf-level decision variables [S1, S2, unofficial].
   c. Traverse the leaf-level uniform grid using the same DDA algorithm [S1, unofficial].
3. For each leaf cell intersected:
   a. Check if all rays in the warp have intersection candidates [S2, unofficial].
   b. If yes, proceed with standard ray-triangle intersection [S2, unofficial].
   c. If no, check if there are rays with high workload (at least 16 intersection candidates) [S2, unofficial].
   d. If high workload rays exceed 20, proceed with the standard intersection routine [S2, unofficial].

**Formulas:**
- DDA step advancement: $t_{next}[axis] \leftarrow t_{next}[axis] + t_{delta}[axis]$ [G].
- Cell index update: $cell[axis] \leftarrow cell[axis] + step[axis]$ [G].
- Coherence property: For rays starting in the same grid cell $o$, if cell $c$ is the $n$-th cell along ray $r$, it is the $n$-th cell along any ray $r_2$ from the same origin set that intersects $c$ [S1, unofficial]. This holds because $c$ is at distance $(x, y, z)$ from $o$ in cell units, and traversal advances one neighbor cell at a time, so $c$ is traversed at the $x + y + z = n$-th step [S1, unofficial].

**Parameters:**
- Workload threshold: 16 intersection candidates [S2, unofficial].
- Standard intersection routine threshold: More than 20 rays [S2, unofficial].
- Typical values: Not given in the sources. [G]

**Edge Cases and Pitfalls:**
- Code divergence occurs only when rays disagree on which level of structure they need to traverse [S1, unofficial].
- Zero direction components are handled by setting $t_{delta}$ and $t_{next}$ to infinity for that axis, preventing division by zero and skipping traversal on that axis [G].
- Precision issues with DDA variables are not explicitly discussed, but standard DDA pitfalls apply [G].

**Pseudocode:**
```python
def two_level_grid_ray_traversal(ray_origin, ray_direction, cell_size, top_grid, leaf_grids):
    # Initialize DDA variables [G]
    t_delta = abs(cell_size / ray_direction)
    step_dir = sign(ray_direction)
    t_max = 1e9
    t_next = (step_dir - 0.5 * ray_direction) * t_delta
    # Guard against zero direction components
    for i in range(3):
        if ray_direction[i] == 0:
            t_delta[i] = float('inf')
            t_next[i] = float('inf')
    current_cell = floor(ray_origin / cell_size)

    while min(t_next) < t_max:
        # Check if top-level cell contains leaf data [S1, unofficial]
        if leaf_grids[current_cell] is not None:
            # Reuse top-level decision variables for leaf traversal [S1, S2, unofficial]
            leaf_t_delta = t_delta
            leaf_step_dir = step_dir
            leaf_t_max = t_max
            leaf_t_next = t_next
            leaf_cell = current_cell

            while min(leaf_t_next) < leaf_t_max:
                yield leaf_cell
                # Advance leaf traversal
                axis = argmin(leaf_t_next)
                leaf_t_next[axis] += leaf_t_delta[axis]
                leaf_cell[axis] += leaf_step_dir[axis]

        # Advance top-level traversal
        axis = argmin(t_next)
        t_next[axis] += t_delta[axis]
        current_cell[axis] += step_dir[axis]
```

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of cells traversed, similar to uniform grid traversal [S1, unofficial].
- **Memory Complexity:** Not given in the sources. [G]
- **Measured Performance:** Not given in the sources. [G]
- **Scaling:** Favors coherent rays due to SIMD-friendly nature [S1, unofficial].
- **Strengths:** Inexpensive traversal, SIMD-friendly, reuses decision variables [S1, S2, unofficial].
- **Limitations:** Code divergence when rays disagree on traversal level [S1, unofficial].
- **When to Use:** Sparse or complex volumetric data with coherent rays [S1, unofficial].
- **When Not to Use:** Highly divergent rays or uniform data where simpler traversal suffices [S1, unofficial].

## Background
- **Origin:** Modified from the DDA algorithm by Amanatides and Woo [AW87] [S1, unofficial].
- **History:** Adapted for GPU architectures, with specific workload management routines mapping better to Fermi GPUs [S2, unofficial].
- **Usage:** Used in two-level grid structures for ray tracing on GPUs [S1, unofficial].
