# 2D Projective Grid Traversal

Also called: 2D grid walk over depth heightfield, DepthMesh.raycast() optimization

## Overview
2D Projective Grid Traversal is a raycasting optimization for depth meshes that replaces brute-force triangle intersection checks with a traversal of a 2D projective grid [S1, unofficial]. It exploits the property that vertices of a DepthMesh lie along perspective unprojection rays from the camera origin, causing 3D triangles in a grid cell to project strictly inside that 2D cell under central projection [S1, unofficial]. Unlike standard 3D grid traversal methods which step through volumetric cells, this method projects the ray segment into 2D grid coordinates and visits only the cells crossed by the projected line segment, reducing the number of intersection checks from thousands to approximately 20–40 [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A local-space ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a DepthMesh geometry with precomputed rectilinear grid metadata (segments, min/max depth, rectilinear flag); the truncated depth frustum planes ($z_{min}, z_{max}, r_{x,min}, r_{x,max}, r_{y,min}, r_{y,max}$).
*   **Output:** A list of intersection points, distances, face indices, and normals for triangles intersected by the ray.

**Data Structures:**
*   **Grid Metadata:** Per-geometry metadata tracked by `DepthGeometryUpdater` includes `segments` (grid dimensions, e.g., $39 \times 39$), `isRectilinear` (boolean), `minVertexDepth`, `maxVertexDepth`, and `hasDepthData` [S1, unofficial].
*   **Vertex Buffer:** Flat `Float32Array` containing vertex positions, accessed directly to avoid overhead [S1, unofficial].

**Algorithm Steps:**
1.  **Frustum Clipping:** Clip the local-space ray against the 6 planes of the truncated depth frustum ($z_{min}, z_{max}, r_{x,min}, r_{x,max}, r_{y,min}, r_{y,max}$) to determine the entry and exit points of the ray segment within the valid depth volume [S1, unofficial]. Let the clipped segment be defined by endpoints $\mathbf{p}_{entry}$ and $\mathbf{p}_{exit}$ [S1, unofficial].
2.  **2D Projection:** Project the clipped ray's entry and exit endpoints from 3D local space into 2D grid coordinates $(c, r)$ using the central projection formula [S1, unofficial]:
    $$
    c = \frac{x}{-z}, \quad r = \frac{y}{-z}
    $$
    where $(x, y, z)$ are the coordinates of the endpoint and $-z > 0$ [S1, unofficial]. This results in a 2D line segment in grid space.
3.  **2D Grid Traversal:** Traverse only the 2D grid cells crossed by the projected 2D line segment. The grid is typically uniform (e.g., $39 \times 39$ cells) [S1, unofficial]. The traversal visits approximately 20–40 cells instead of all 1,521 cells in the full grid [S1, unofficial].
4.  **Intersection Testing:** For each visited 2D grid cell, identify the 3D triangles contained within that cell. Read vertex positions directly from the flat `Float32Array` buffer into reusable scratch `THREE.Vector3` instances to avoid the overhead of repeated accessor calls [S1, unofficial]. Perform standard triangle-ray intersection tests for these triangles.
5.  **Fallback:** If depth data has not yet been populated (`hasDepthData` is false) or if the projection is non-rectilinear (`isRectilinear` is false), fallback to standard `Mesh.prototype.raycast()` which tests all triangles [S1, unofficial].

**Pseudocode:**
```python
def projective_grid_traversal(ray_origin, ray_direction, grid_metadata, frustum_planes):
    """
    ray_origin: Vector3
    ray_direction: Vector3
    grid_metadata: Object containing segments (Nx, Ny), isRectilinear, minVertexDepth, maxVertexDepth, hasDepthData
    frustum_planes: List of 6 planes (zMin, zMax, rxMin, rxMax, ryMin, ryMax)
    """
    # Fallback condition
    if not grid_metadata.hasDepthData or not grid_metadata.isRectilinear:
        return standard_mesh_raycast(ray_origin, ray_direction)

    # 1. Clip ray against frustum planes
    clipped_segment = clip_ray_to_frustum(ray_origin, ray_direction, frustum_planes)
    if clipped_segment is None:
        return []

    p_entry, p_exit = clipped_segment

    # 2. Project endpoints to 2D grid coordinates
    # Central projection: c = x / -z, r = y / -z
    c_entry = p_entry.x / -p_entry.z
    r_entry = p_entry.y / -p_entry.z
    c_exit = p_exit.x / -p_exit.z
    r_exit = p_exit.y / -p_exit.z

    # 3. Traverse 2D grid cells crossed by the line segment (c_entry, r_entry) -> (c_exit, r_exit)
    visited_cells = traverse_2d_grid(c_entry, r_entry, c_exit, r_exit, grid_metadata.segments)

    intersections = []
    vertex_buffer = grid_metadata.vertex_buffer # Flat Float32Array

    # 4. For each visited cell, test contained triangles
    for cell in visited_cells:
        triangles_in_cell = get_triangles_in_cell(cell, grid_metadata)
        for tri in triangles_in_cell:
            # Read vertices from buffer directly
            v0 = read_vertex(vertex_buffer, tri.v0)
            v1 = read_vertex(vertex_buffer, tri.v1)
            v2 = read_vertex(vertex_buffer, tri.v2)
            
            hit = ray_triangle_intersection(ray_origin, ray_direction, v0, v1, v2)
            if hit:
                intersections.append(hit)

    return intersections

def clip_ray_to_frustum(origin, direction, planes):
    """
    Clips a ray against 6 frustum planes.
    Returns (p_entry, p_exit) or None if no intersection.
    """
    # Standard Liang-Barsky or Cohen-Sutherland style clipping for a ray segment
    # against 6 planes.
    # For simplicity, assume a helper function exists or implement standard parametric clipping.
    # Here we outline the logic:
    t_min = 0.0
    t_max = 1.0
    
    for plane in planes:
        # Plane defined by normal n and point p_on_plane
        # Ray: O + t*D
        # Intersection: (P_on_plane - O) . n / (D . n)
        denom = dot(direction, plane.normal)
        if abs(denom) < 1e-8:
            # Ray parallel to plane
            if dot(plane.point - origin, plane.normal) < 0:
                return None # Ray is outside
        else:
            t = dot(plane.point - origin, plane.normal) / denom
            if denom < 0:
                t_min = max(t_min, t)
            else:
                t_max = min(t_max, t)
    
    if t_min > t_max:
        return None
    
    p_entry = origin + direction * t_min
    p_exit = origin + direction * t_max
    return (p_entry, p_exit)

def traverse_2d_grid(c1, r1, c2, r2, grid_size):
    """
    Traverses 2D grid cells crossed by a line segment.
    Uses a 2D DDA-like approach.
    """
    cells = []
    # Determine grid bounds
    min_c, max_c = 0, grid_size.x
    min_r, max_r = 0, grid_size.y
    
    # Current cell
    curr_c = int(c1)
    curr_r = int(r1)
    
    # Step directions
    step_c = 1 if c2 > c1 else -1
    step_r = 1 if r2 > r1 else -1
    
    # Distances to next boundary
    # Boundary coordinates are integers
    next_c_boundary = c1 if step_c < 0 else curr_c + 1
    next_r_boundary = r1 if step_r < 0 else curr_r + 1
    
    # Delta distances
    if c2 != c1:
        delta_c = abs(next_c_boundary - c1) / abs(c2 - c1)
    else:
        delta_c = float('inf')
        
    if r2 != r1:
        delta_r = abs(next_r_boundary - r1) / abs(r2 - r1)
    else:
        delta_r = float('inf')
        
    t_c = delta_c
    t_r = delta_r
    
    # Add first cell
    cells.append((curr_c, curr_r))
    
    # Traverse until we reach the end
    t = 0.0
    while t < 1.0:
        if t_c < t_r:
            curr_c += step_c
            t_c += delta_c
        else:
            curr_r += step_r
            t_r += delta_r
        
        # Check bounds
        if 0 <= curr_c < grid_size.x and 0 <= curr_r < grid_size.y:
            cells.append((curr_c, curr_r))
        else:
            break
            
    return cells

def read_vertex(buffer, index):
    """
    Reads a vertex from a flat Float32Array.
    Assumes interleaved x, y, z.
    """
    offset = index * 3
    x = buffer[offset]
    y = buffer[offset + 1]
    z = buffer[offset + 2]
    return Vector3(x, y, z)
```

## Operating characteristics
*   **Time Complexity:** The traversal visits approximately 20–40 grid cells per ray, compared to testing all triangles in the mesh (e.g., 3,042 triangles for a downsampled mesh) [S1, unofficial]. This significantly reduces the number of intersection checks.
*   **Measured Performance:** On Android XR Chrome Trace, `DepthMesh.raycast()` time decreased from 1.177 ms/frame to 0.072 ms/frame, a 93.9% reduction (16.3x faster) [S1, unofficial]. `collectIntersections` (Scene Raycast) time decreased from 1.292 ms/frame to 0.187 ms/frame, an 85.5% reduction (6.9x faster) [S1, unofficial].
*   **Strengths:** Drastic reduction in intersection tests for depth meshes with rectilinear projections. Efficient use of GPU/CPU by minimizing memory access overhead through direct buffer reading.
*   **Limitations:** Only applicable to DepthMesh geometries with rectilinear projections and populated depth data. Requires fallback to brute-force raycasting if these conditions are not met [S1, unofficial].

## Background
This method was introduced in the context of optimizing raycasting for DepthMesh in the `xrblocks` project [S1, unofficial]. It was implemented in `src/depth/DepthMeshRaycast.ts` and merged into the main branch in October 2026 [S1, unofficial]. The optimization addresses the performance bottleneck of testing thousands of triangles per frame for controller rays in XR applications.
