# Ray-marching reference (min-max octree accelerated)

Also called: Empty Space Skipping with Min/Max Cells, Interactive Isosurface Ray Tracing of Large Octree Volumes, Min-Max Octree Ray Casting, Min-Max Octree Ray-Marching, Min-Max Octree Ray-Marching Reference, Octree-accelerated ray-marching

## Overview
This method is an accelerated direct isosurface visualization technique that uses a min-max octree to facilitate empty space skipping during ray marching [S1, S2][S3, unofficial]. It serves as a performance baseline for general volumes, offering negligible memory overhead for the input volume and low auxiliary data requirements [S3, unofficial]. Unlike Sphere Tracing, which requires precomputed signed distance functions, or Segment Tracing, which is limited to hierarchical skeletal implicit surfaces, this approach is applicable to a wide range of scalar volumes [S2][S3, unofficial]. It guarantees continuous isosurfaces that locally interpolate the input data, unlike mesh extraction techniques (e.g., marching cubes) which may produce topologically different piecewise linear meshes [S4, unofficial].

## How it works
**Inputs:**
- A 3D scalar volume dataset.
- An isovalue threshold for isosurface extraction.
- Camera parameters (origin and direction for each pixel).

**Outputs:**
- A rendered image of the isosurface with shading.

**Data Structures:**
1.  **Min-Max Texture:** A texture where each texel stores the minimum and maximum scalar values of a corresponding block or cell in the volume. This is used to determine block occupancy [S1][S3, unofficial].
2.  **Min-Max Octree:** Constructed from the min-max texture. The octree is built on a base level with equal size along all three cardinal axes [S1][S3, unofficial]. Volume dimensions are padded to the nearest power of two for straightforward implementation [S1]. The octree nodes store min/max values to allow empty space skipping [S4, unofficial][S5].
3.  **Scalar Data:** The original volume data, potentially losslessly compressed into the octree representation [S4, unofficial].

**Steps:**

1.  **Construct the Min-Max Octree:**
    - Create an MIP texture from the min-max texture used for block occupancy determination [S1][S3, unofficial].
    - Build the octree on a base level with equal size along all three cardinal axes [S1][S3, unofficial].
    - Pad volume dimensions to the nearest power of two [S1].
    - [G] Ensure the octree is fully populated or indexed correctly for traversal.

2.  **Compute Entry and Exit Points:**
    - Instead of rendering one cube enclosing the whole volume, render cubes corresponding to one level of the min/max octree [S5].
    - All vertices of a cube have the same 2D texture coordinates containing the min/max values [S5].
    - **Exit Positions:** Render the cubes with `glCullFace(GL FRONT)` and `glDepthFunc(GL LESS)` [S5]. A fragment shader discards the fragment if the cube is empty or does not contain the isosurface level [S5].
    - **Entry Positions:** Render the cubes again with `glCullFace(GL BACK)` and `glDepthFunc(GL GREATER)` [S5]. The same fragment shader logic applies [S5].

3.  **Ray Marching:**
    - March rays through the volume using a step size of $0.5 \times \text{cell edge length}$ [S1][S3, unofficial].
    - Use the min-max octree to skip empty space [S3, S4, unofficial].
    - [G] Initialize ray origin and direction based on camera parameters.

4.  **Isosurface Refinement:**
    - Refine the isosurface intersection position using exactly three iterations of a binary search algorithm [S1][S3, unofficial].
    - [G] The binary search narrows down the interval where the scalar value crosses the isovalue.

5.  **Shading:**
    - Compute surface normals on the fly using the central difference method upon finding an isosurface intersection [S1][S3, unofficial].
    - Apply Gooch shading using the sampled/computed vertex normals [S1][S3, unofficial].

**Pseudocode:**

```python
def ray_march_min_max_octree(volume, isovalue, camera, octree):
    """
    Ray march through a volume using a min-max octree for acceleration.
    
    Args:
        volume: 3D array of scalar values.
        isovalue: Threshold for isosurface.
        camera: Object with origin and direction methods.
        octree: Min-max octree structure with min/max values per node.
        
    Returns:
        Image buffer with shaded isosurface.
    """
    image = create_empty_image()
    
    for pixel in image:
        ray_origin = camera.origin(pixel)
        ray_direction = camera.direction(pixel)
        
        # Step 2: Compute entry and exit points using octree cubes
        # This step is typically done via GPU rendering passes as described in [S5]
        # For the sake of this algorithmic description, we assume entry and exit
        # points are computed by querying the octree or rendering cubes.
        entry_point, exit_point = compute_entry_exit_points(ray_origin, ray_direction, octree)
        
        if entry_point is None or exit_point is None:
            continue
            
        # Step 3: Ray Marching
        step_size = 0.5 * get_cell_edge_length(octree)
        current_point = entry_point
        
        while distance(current_point, exit_point) > step_size:
            # Check if current point is inside an empty region using octree
            if is_empty(current_point, octree):
                # Skip to next non-empty region or exit
                current_point = skip_empty_region(current_point, ray_direction, octree)
                if current_point is None or distance(current_point, exit_point) <= 0:
                    break
                continue
                
            # Sample volume value
            value = sample_volume(volume, current_point)
            
            # Check for isosurface crossing
            if value >= isovalue: # Assuming isovalue is the threshold
                # Step 4: Isosurface Refinement
                intersection = binary_search_refinement(current_point, ray_direction, volume, isovalue)
                
                # Step 5: Shading
                normal = compute_normal(volume, intersection)
                color = apply_gooch_shading(normal)
                image[pixel] = color
                break
            
            current_point += ray_direction * step_size
            
    return image

def compute_entry_exit_points(ray_origin, ray_direction, octree):
    """
    Compute entry and exit points by rendering octree cubes.
    This is a conceptual representation of the GPU rendering passes described in [S5].
    """
    # In practice, this involves two rendering passes:
    # 1. Render cubes with glCullFace(GL FRONT) and glDepthFunc(GL LESS) to find exit.
    # 2. Render cubes with glCullFace(GL BACK) and glDepthFunc(GL GREATER) to find entry.
    # Here we assume a function that returns these points.
    exit_point = render_exit_pass(ray_origin, ray_direction, octree)
    entry_point = render_entry_pass(ray_origin, ray_direction, octree)
    return entry_point, exit_point

def is_empty(point, octree):
    """
    Check if a point is in an empty region using the min-max octree.
    """
    node = octree.find_node_containing(point)
    return node.min_value > isovalue or node.max_value < isovalue

def skip_empty_region(point, direction, octree):
    """
    Skip over empty regions using the octree.
    """
    # Move along the ray until a non-empty node is found
    # This is a simplified implementation; actual implementation would use octree traversal
    current = point
    while is_empty(current, octree):
        current += direction * get_cell_edge_length(octree)
    return current

def binary_search_refinement(point, direction, volume, isovalue):
    """
    Refine intersection using 3 iterations of binary search.
    """
    low = point
    high = point + direction * get_cell_edge_length(octree) # Approximate step
    
    for _ in range(3):
        mid = (low + high) / 2
        value = sample_volume(volume, mid)
        if value < isovalue:
            low = mid
        else:
            high = mid
            
    return (low + high) / 2

def compute_normal(volume, point):
    """
    Compute normal using central difference.
    """
    epsilon = get_cell_edge_length(volume) / 2.0
    dx = sample_volume(volume, point + vec3(epsilon, 0, 0)) - sample_volume(volume, point - vec3(epsilon, 0, 0))
    dy = sample_volume(volume, point + vec3(0, epsilon, 0)) - sample_volume(volume, point - vec3(0, epsilon, 0))
    dz = sample_volume(volume, point + vec3(0, 0, epsilon)) - sample_volume(volume, point - vec3(0, 0, epsilon))
    return normalize(vec3(dx, dy, dz))

def apply_gooch_shading(normal):
    """
    Apply Gooch shading.
    """
    # Simplified Gooch shading
    light_dir = normalize(vec3(1, 1, 1))
    diff = max(dot(normal, light_dir), 0.0)
    return vec3(0.5 + 0.5 * diff) # Example color mapping
```

**Parameters:**
- Binary search iterations for isosurface refinement: 3 [S1][S3, unofficial].
- Ray step size: $0.5 \times \text{cell edge length}$ [S1][S3, unofficial].
- Number of min/max cells: $32^3$ resulted in the best performance in experiments [S5].

**Edge Cases and Pitfalls:**
- A large number of small cells induces a tight bound of the isosurface but comes with a large overhead due to the primitives [S5].
- A small number of large cells reduces the overhead but bounds the isosurface loosely [S5].
- Precision issues may arise during binary search if the step size is too large relative to the volume gradient [G].
- Boundary conditions must be handled when sampling near the volume edges [G].

## Subtopics

### [Object-Order Iso-Surface Rendering with Macro-Cells](1757-object-order-iso-surface-rendering-with-macro-cells.md)
An iso-surface rendering algorithm based on object-order ray casting that subdivides data into macro-cells to build a min/max octree, reducing traversal steps by rasterizing hexagonal footprints. It differs from its parent method [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md) by processing visible volume cells directly rather than pixels, and from its sibling [Object-Order Ray Casting with Min/Max Octrees](1814-object-order-ray-casting-with-min-max-octrees.md) by relying on pre-computed hierarchical data structures to skip empty regions.

## Operating characteristics
- **Time Complexity:** Depends on the number of rays and the sparsity of the volume. Empty space skipping reduces the number of samples per ray.
- **Memory Complexity:** Auxiliary octree data memory requirement is 1 to 4 megabytes for octrees with a depth of 7 or more [S3, unofficial]. The lossless compression into an octree volume occupies less than one quarter the size of the original 3D array [S4, unofficial].
- **Measured Performance:**
    - On an Intel Core Duo 2.16 GHz laptop with 2 GB RAM, frame rates were 2.4, 1.3, and 3.3 fps for three test scenes (LLNL Richtmyer-Meshkov, Utah CSAFE heptane, and a closer view) [S4, unofficial].
    - On a 16-node NUMA 2.4 GHz Opteron workstation, frame rates were 17.9, 9.8, and 22.0 fps for the same three test scenes [S4, unofficial].
    - Performance gain up to ≈ 4.95-fold using fine-grained min/max cells for efficient empty space skipping [S5].
- **Scaling:** The method scales well to large data, particularly when scene complexity is high relative to the number of rays that must be cast to fill a frame [S4, unofficial].
- **Strengths:**
    - Applicable to a wide range of volumes [S2][S3, unofficial].
    - Low auxiliary data memory overhead [S3, unofficial].
    - Guarantees continuous isosurfaces [S4, unofficial].
- **Limitations:**
    - Outperformed by raster occlusion culling approaches at high resolutions (e.g., 3840×2160) [S1].
    - Less efficient than the proposed rasterization approach for most resolutions, except for sparse datasets like Chameleon at low-to-medium resolutions [S1][S3, unofficial].
    - Dependent on rendering resolution for the ray-marching part, unlike the proposed rasterization approach which works largely in volume space [S3, unofficial].
- **When to use:** Suitable for general accelerated direct isosurface rendering, especially when memory overhead must be minimized and the volume is sparse [S3, unofficial].
- **When not to use:** Not suitable for very high resolutions where raster occlusion culling is more efficient [S1]. Not suitable if signed distance functions are available and Sphere Tracing is preferred [S2].

## Background
- **Origin:** The method was introduced as a reference technique for evaluating direct isosurface rendering pipelines [S1, S2][S3, unofficial]. It is based on the concept of using min-max octrees for empty space skipping [S1, S2][S3, unofficial].
- **History:** The technique has been used as a baseline for comparing new rendering approaches [S3, unofficial]. It has been implemented in various research projects, including those involving large compressed structured volumes [S4, unofficial] and FCC datasets [S5].
- **Usage:** It is used as a baseline reference for direct isosurface visualization performance in evaluations [S3, unofficial].
