# Object-Order Iso-Surface Rendering with Macro-Cells
Also called: Neubauer macro-cell octree

## Overview
An iso-surface rendering algorithm based on object-order ray casting that subdivides data into macro-cells to build a min/max octree, reducing traversal steps by rasterizing hexagonal footprints [S1, unofficial]. It differs from its parent method [Ray-marching reference (min-max octree accelerated)](1554-ray-marching-reference-min-max-octree-accelerated.md) by processing visible volume cells directly rather than pixels, and from its sibling [Object-Order Ray Casting with Min/Max Octrees](1814-object-order-ray-casting-with-min-max-octrees.md) by relying on pre-computed hierarchical data structures to skip empty regions [S1, unofficial].

## How it works
**Inputs:**
- Scalar volume dataset $V$ of dimensions $D_x \times D_y \times D_z$.
- Iso-value threshold $T$.
- Camera parameters (view matrix, projection matrix, image plane resolution $W \times H$).
- Macro-cell size parameter $m$ (integer, typically $4 \le m \le 10$) [S1, unofficial].

**Outputs:**
- Final image buffer with color and depth values for each pixel.

**Data Structures:**
1. **Min/Max Octree:** A hierarchical tree structure where each node stores the minimum and maximum scalar values of all voxels in its corresponding sub-volume. Leaf nodes correspond to macro-cells of size $m^3$.
2. **Boundary Cell Flag:** A boolean flag associated with each node indicating if the iso-surface (defined by $T$) potentially intersects the sub-volume (i.e., $\min < T < \max$).

**Steps:**
1. **Preprocessing:**
   - Subdivide the entire dataset $V$ into non-overlapping macro-cells of size $m \times m \times m$. If the dataset dimensions are not divisible by $m$, pad or truncate appropriately [G].
   - Compute the min and max scalar values for each macro-cell.
   - Build the min/max octree recursively. For each node, compute its min/max from its children. Mark a node as a "boundary node" if its min $< T$ and max $> T$.

2. **Image-Plane Iteration:**
   - Initialize a set of unprocessed pixels $P_{unprocessed}$ containing all pixels $(u, v)$ in the image plane.
   - While $P_{unprocessed}$ is not empty:
     - Select an unprocessed pixel $(u, v)$.
     - Construct a ray $R$ from the camera through $(u, v)$.
     - Traverse the min/max octree using $R$:
       - Start at the root.
       - At each node, check if the ray intersects the node's bounding box.
       - If the node is marked as a boundary node, recurse into its children.
       - If the node is not a boundary node, skip it (empty space skipping).
       - If the node is a leaf node (macro-cell), proceed to Step 3.
     - Remove $(u, v)$ from $P_{unprocessed}$.

3. **Macro-Cell Rasterization (Hexagonal Footprint):**
   - At the leaf node (macro-cell), project the boundaries of the macro-cell onto the image plane.
   - The projection yields a hexagonal footprint $F$ on the image plane [S1, unofficial].
   - Identify all pixels $(u', v')$ within the bounding box of $F$ that are also inside the hexagon $F$.
   - For each such pixel $(u', v')$:
     - Construct a local ray $R'$ from the camera through $(u', v')$.
     - Traverse the macro-cell grid using the Amanatides and Woo algorithm [S1, unofficial].
     - For each voxel visited in the macro-cell:
       - Check if the voxel is a boundary voxel (min $< T <$ max).
       - If yes, perform an intersection test with the iso-surface (e.g., using linear interpolation or marching cubes within the voxel).
       - If an intersection is found, compute the normal and shading, then write the result to the image buffer for pixel $(u', v')$.
       - Mark pixel $(u', v')$ as processed.

**Parameters:**
- Macro-cell size $m$: Usually between 4 and 10 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** Floating-point precision errors in ray-triangle or ray-voxel intersection tests may cause missed intersections or double hits. Use epsilon offsets for boundary checks [G].
- **Degenerate Input:** If the iso-value $T$ equals the min or max of a macro-cell, the boundary flag logic must handle equality carefully to avoid missing surfaces or including empty space [G].
- **Hexagonal Projection:** The hexagonal footprint assumes a specific camera projection model (e.g., perspective). For orthogonal projection, the footprint may be rectangular or hexagonal depending on the view direction [G].

## Subtopics

## Operating characteristics
- **Time Complexity:** The octree traversal reduces the number of macro-cells visited. Within each macro-cell, the Amanatides and Woo traversal is efficient. However, the hexagonal footprint rasterization may process multiple pixels per macro-cell, leading to redundant ray casting if not optimized.
- **Memory Complexity:** The min/max octree requires $O(N)$ memory, where $N$ is the number of voxels, plus overhead for the tree structure.
- **Strengths:** Reduces traversal steps by rasterizing hexagonal footprints, reusing traversal paths for multiple pixels.
- **Limitations:** Hexagonal footprint calculation and rasterization add complexity. Performance may degrade if the iso-surface is highly complex or if the macro-cell size $m$ is not well-tuned.
- **When to Use:** Suitable for interactive visualization of large volume datasets where iso-surface extraction is required.
- **When Not to Use:** Not suitable for volume rendering (transparency) or when high-frequency details are present and $m$ is too large.

## Background
Proposed by Neubauer et al. [Neubauer02] as an alternative to image-order ray casting. It builds on the min/max octree concept introduced by Wilhelms et al. [Wilhelms92] and uses the Amanatides and Woo voxel traversal algorithm [Amanatides87].
