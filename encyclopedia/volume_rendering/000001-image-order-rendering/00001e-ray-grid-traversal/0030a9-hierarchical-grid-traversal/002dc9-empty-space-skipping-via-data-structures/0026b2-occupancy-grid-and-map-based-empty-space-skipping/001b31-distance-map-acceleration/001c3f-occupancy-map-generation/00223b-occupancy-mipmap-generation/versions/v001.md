# Occupancy Mipmap Generation

Also called: JAX Convolutional Occupancy Mipmap

## Overview
Occupancy Mipmap Generation computes a hierarchical occupancy map for a 3D grid using JAX convolutions to enable efficient empty-space skipping in volume rendering [S1, unofficial]. It differs from its parent, [Occupancy Map Generation](1197-occupancy-map-generation.md), by constructing a multi-resolution pyramid via convolutional downsampling rather than a single-resolution binary map, and from its sibling, [Distance Map Computation (Multi-Stage)](1205-distance-map-computation-multi-stage.md), by producing binary occupancy indicators rather than continuous distance fields [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `mat`, a 3D numpy array of shape `(xdim, ydim, zdim)` containing density or occupancy values.
- Output: `mipmap`, a list of JAX arrays representing the occupancy pyramid levels, plus a final scalar element.

**Data Structures:**
- `occupancy_mat`: A 3D array of shape `(xdim, ydim, zdim)` with `float32` values. Entries are `1.0` if `mat > 0`, else `0.0`.
- `data`: A 4D JAX array of shape `(1, xdim, ydim, zdim, 1)` used for convolution.
- `kernel`: A 5D JAX array of shape `(2^i, 2^i, 2^i, 1, 1)` for level `i`.
- `mipmap`: A list containing the downsampled occupancy arrays.

**Steps:**
1. Calculate the number of mipmap levels: $L = \lfloor \log_2(\text{xdim}) \rfloor$. Note: The source code adds 1 for the root node implicitly by iterating `range(levels)` and appending a final scalar, but the loop range is based on `log2(xdim)` [S1, unofficial].
2. Create the base occupancy mask: Initialize `occupancy_mat` with zeros. Set `occupancy_mat[x, y, z] = 1.0` if `mat[x, y, z] > 0`, otherwise `0.0`.
3. Convert to JAX array and reshape: Cast `occupancy_mat` to `float32` and add batch and channel dimensions to form `data` of shape `(1, xdim, ydim, zdim, 1)` [S1, unofficial].
4. Initialize `mipmap` as an empty list.
5. For each level $i$ from $0$ to $L-1$:
   a. Create a kernel of ones with shape $(2^i, 2^i, 2^i, 1, 1)$.
   b. Define convolution dimension numbers for input `(NHWDC)` and kernel `(HWDIO)` to output `(NHWDC)` [S1, unofficial].
   c. Apply `lax.conv_general_dilated` with stride $(2^i, 2^i, 2^i)$ and padding `'SAME'`.
   d. Remove batch and channel dimensions from the result.
   e. Append the resulting 3D array to `mipmap`.
6. Compute the total number of occupied points: $N = \sum \text{occupancy\_mat}$.
7. Append $N$ as a scalar tensor to `mipmap`.

**Pseudocode:**
```python
import jax.numpy as jnp
from jax.lax import conv_general_dilated, conv_dimension_numbers

def generate_occupancy_mipmap(mat):
    """
    Generate a hierarchical occupancy mipmap from a 3D density grid.
    
    Args:
        mat: numpy array of shape (xdim, ydim, zdim) with density values.
        
    Returns:
        mipmap: list of JAX arrays. Each element is a 3D occupancy grid at a 
                decreasing resolution, followed by a scalar count of total occupied voxels.
    """
    xdim, ydim, zdim = mat.shape
    
    # Step 1: Compute number of levels
    # Note: Source uses log2(xdim).astype(int). 
    # If xdim is not a power of 2, this truncates. 
    levels = int(jnp.log2(xdim))
    
    # Step 2: Create occupancy mask
    occupancy_mat = (mat > 0).astype(jnp.float32)
    
    # Step 3: Convert to JAX array and add dims
    data = jnp.array(occupancy_mat)
    data = data[None, :, :, :, None]  # Shape: (1, xdim, ydim, zdim, 1)
    
    mipmap = []
    
    # Step 5: Iterate through levels
    for i in range(levels):
        # Create kernel of ones
        kernel_size = 2**i
        kernel = jnp.ones((kernel_size, kernel_size, kernel_size, 1, 1))
        
        # Define dimension numbers
        # Input: (N, H, W, D, C) -> (1, xdim, ydim, zdim, 1)
        # Kernel: (H, W, D, I, O) -> (ks, ks, ks, 1, 1)
        # Output: (N, H, W, D, C)
        dn = conv_dimension_numbers(data.shape, kernel.shape, ('NHWDC', 'HWDIO', 'NHWDC'))
        
        # Apply convolution with stride and SAME padding
        strides = (kernel_size, kernel_size, kernel_size)
        padding = 'SAME'
        
        conv_out = conv_general_dilated(
            data, 
            kernel, 
            window_strides=strides, 
            padding=padding, 
            dimension_numbers=dn
        )
        
        # Remove batch and channel dimensions
        # conv_out shape: (1, new_x, new_y, new_z, 1)
        level_grid = conv_out[0, :, :, :, 0]
        
        mipmap.append(level_grid)
        
    # Step 6 & 7: Append total occupied count
    total_occupied = jnp.sum(occupancy_mat)
    mipmap.append(total_occupied)
    
    return mipmap
```

**Parameters:**
- `mat`: Input 3D grid array. Dimensions must be powers of 2 for consistent downsampling, though the code does not explicitly enforce this [S1, unofficial].
- `xdim, ydim, zdim`: Grid dimensions. The number of levels is determined by `xdim` [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `xdim` is not a power of 2, `jnp.log2(xdim).astype(int)` truncates, potentially ignoring valid levels or causing stride mismatches if the grid dimensions are not uniform [S1, unofficial].
- The kernel size grows exponentially ($2^i$). For large grids, early levels may have very large kernels, leading to high memory usage during convolution [S1, unofficial].
- The final scalar is appended as a JAX array, not a Python scalar, to maintain consistency in the list type [S1, unofficial].

## Subtopics

### [Occupancy Grid Update](2916-occupancy-grid-update.md)
Periodically refreshes a single-resolution 3D occupancy grid by querying a NeRF model for density values at voxel centers, marking voxels as occupied if density exceeds a threshold. It differs from this method by using direct thresholding on a single resolution rather than hierarchical convolutional smoothing.

### [Density Grid Update with EMA](3884-density-grid-update-with-ema.md)
Uses exponential moving averages to update continuous density values in a grid. It differs from this method by maintaining continuous values rather than binary occupancy states.

## Operating characteristics
- **Time Complexity:** $O(N \log N)$ where $N$ is the number of voxels, due to the hierarchical convolutional downsampling. Each level reduces the spatial dimensions by a factor of $2^i$, but the kernel size also grows, making the convolution cost per level non-trivial [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store the mipmap levels, as the sum of volumes across all levels is bounded by a constant factor of the original grid size (geometric series) [S1, unofficial].
- **Strengths:** Provides a multi-resolution structure for efficient empty-space skipping, allowing rays to skip large empty regions at coarse levels [S1, unofficial].
- **Limitations:** Requires the grid dimensions to be powers of 2 for consistent downsampling. The use of JAX convolutions may be less efficient on hardware without optimized JAX backends compared to native CUDA implementations [S1, unofficial].
- **When to Use:** When using JAX for volume rendering and a hierarchical acceleration structure is needed for empty-space skipping [S1, unofficial].
- **When Not to Use:** When grid dimensions are not powers of 2, or when a single-resolution grid is sufficient [S1, unofficial].

## Background
This method originates from the Jax-Volumetric-Renderer project by szat, which implements volume rendering using JAX [S1, unofficial]. It was designed to leverage JAX's automatic differentiation and compilation capabilities to generate occupancy mipmaps efficiently on GPUs [S1, unofficial].
