# Partitioned Distance Map Combination

Also called: PDM Combination, Iterative Distance Map Merging

## Overview
Partitioned Distance Map Combination is the runtime assembly phase of the Partitioned Distance Map (PDM) acceleration technique. It combines a subset of precomputed partitioned distance maps into a single global distance map to enable empty space skipping during ray casting. Unlike methods that recompute the distance transform from scratch when the transfer function changes, this method merges existing distance fields, trading higher memory usage and initialization cost for significantly faster transfer function update times [S1, unofficial]. It serves as the core combination logic for the [Partitioned Distance Map (PDM) Acceleration](1286-partitioned-distance-map-pdm-acceleration.md) variant.

## How it works
The method uses a ping-pong buffer strategy with two swap textures to iteratively merge multiple partitioned distance maps into a single output distance map. This allows combining more maps than can be bound simultaneously as shader inputs.

**Inputs and Outputs:**
*   **Input:** A set of precomputed partitioned distance maps (`texturePartitionedDistanceMaps`), a boolean array indicating which maps are active for the current transfer function (`partitionedDistanceMapsToUse`), and the occupancy map dimensions (`sizeOccupancyMap`).
*   **Output:** A single combined distance map stored in `textureIntermediateDistanceMapOutput`.

**Data Structures:**
*   `textureSwapArray`: An array of two 3D textures (or 2D slices if 3D volume is handled via layers) with format `GL_R8UI` (8-bit unsigned integer, single channel) and `GL_READ_WRITE` access. These act as ping-pong buffers.
*   `texturePartitionedDistanceMaps`: An array of 3D textures, each representing a distance map for a specific intensity partition. Format is typically `GL_R8UI` or similar, with `GL_READ_ONLY` access.
*   `partitionedDistanceMapsToUse`: A boolean array or bitmask indicating which partitioned maps are currently relevant.
*   `UBO` (Uniform Buffer Object): A small buffer (8 bytes) used to pass control flags to the compute shader.

**Parameters:**
*   `numMapsToCombinePerLaunch`: The maximum number of partitioned maps to combine in a single compute dispatch. The source specifies a constant value of 6 [S1, unofficial].
*   `useDistanceValueFromPreviousPass`: A flag (0 or 1) indicating whether the input distance map comes from the initial partitioned maps (0) or from the previous iteration's swap buffer (1).

**Algorithm Steps:**
1.  **Initialization:** Bind `textureSwapArray[0]` and `textureSwapArray[1]` to image units 0 and 1 respectively.
2.  **Count Active Maps:** Iterate through `partitionedDistanceMapsToUse` to calculate `numMapsToCombineTotal`, the total number of active partitioned maps.
3.  **Calculate Iterations:** Compute `numIterations` as $\lceil \text{numMapsToCombineTotal} / \text{numMapsToCombinePerLaunch} \rceil$.
4.  **Iterative Combination Loop:** For each iteration `j` from 0 to `numIterations - 1`:
    a.  **Bind Swap Buffers:** Bind `textureSwapArray[j % 2]` to image unit 0 (read/write) and `textureSwapArray[(j + 1) % 2]` to image unit 1 (read/write).
    b.  **Determine Maps to Combine:** Calculate `numMapsToUse` as $\min(\text{numMapsToCombinePerLaunch}, \text{numMapsToCombineTotal} - j \times \text{numMapsToCombinePerLaunch})$.
    c.  **Bind Partitioned Maps:** Loop through `i` from 0 to `numMapsToUse - 1`. Skip inactive maps in `partitionedDistanceMapsToUse` by incrementing an index counter `idxMapProcessed` until a `true` value is found. Bind the corresponding `texturePartitionedDistanceMaps[idxMapProcessed]` to image unit `2 + i` with `GL_READ_ONLY` access. Increment `idxMapProcessed`.
    d.  **Setup UBO:** Create an 8-byte UBO. Set the first 4 bytes to `useDistanceValueFromPreviousPass` (1 if `j > 0`, else 0). Set the next 4 bytes to `numMapsToUse`. Bind this UBO to binding point 0.
    e.  **Dispatch Compute:** Calculate work groups based on `sizeOccupancyMap` dimensions divided by 8 (e.g., `ceil(size / 8)`). Dispatch the compute shader with dimensions `(numWorkGroups[0], numWorkGroups[1], numWorkGroups[2])`. Issue a memory barrier to ensure completion.
5.  **Final Copy:** After the loop, copy the final result from `textureSwapArray[(numIterations - 1) % 2]` to `textureIntermediateDistanceMapOutput` using `glCopyImageSubData` with dimensions from `sizeOccupancyMap`.
6.  **Cleanup:** Delete the UBO.

**Pseudocode:**
```python
# Assume textureSwapArray[0] and textureSwapArray[1] are already bound to image units 0 and 1
# with GL_R8UI format and GL_READ_WRITE access.

numMapsToCombineTotal = 0
for is_active in partitionedDistanceMapsToUse:
    if is_active:
        numMapsToCombineTotal += 1

numIterations = ceil(numMapsToCombineTotal / numMapsToCombinePerLaunch)

for j in range(numIterations):
    # Bind swap buffers
    read_buffer_idx = j % 2
    write_buffer_idx = (j + 1) % 2
    
    bind_image(textureSwapArray[read_buffer_idx], image_unit=0, access=GL_READ_WRITE)
    bind_image(textureSwapArray[write_buffer_idx], image_unit=1, access=GL_READ_WRITE)
    
    # Calculate how many maps to combine in this iteration
    remaining_maps = numMapsToCombineTotal - j * numMapsToCombinePerLaunch
    numMapsToUse = min(numMapsToCombinePerLaunch, remaining_maps)
    
    # Bind partitioned maps
    idxMapProcessed = 0
    for i in range(numMapsToUse):
        # Skip inactive maps
        while not partitionedDistanceMapsToUse[idxMapProcessed]:
            idxMapProcessed += 1
        
        bind_image(texturePartitionedDistanceMaps[idxMapProcessed], image_unit=2 + i, access=GL_READ_ONLY)
        idxMapProcessed += 1
    
    # Setup UBO
    ubo_data = bytearray(8)
    # First 4 bytes: useDistanceValueFromPreviousPass
    if j > 0:
        ubo_data[0:4] = struct.pack('I', 1)
    else:
        ubo_data[0:4] = struct.pack('I', 0)
    # Next 4 bytes: numMapsToUse
    ubo_data[4:8] = struct.pack('I', numMapsToUse)
    
    bind_ubo(ubo_data, binding_point=0)
    
    # Calculate work groups
    # Assuming sizeOccupancyMap is a tuple (w, h, d)
    numWorkGroups = [ceil(sizeOccupancyMap[k] / 8) for k in range(3)]
    
    # Dispatch compute shader
    dispatch_compute(numWorkGroups[0], numWorkGroups[1], numWorkGroups[2])
    memory_barrier()

# Copy final result to output texture
final_buffer_idx = (numIterations - 1) % 2
copy_image_data(textureSwapArray[final_buffer_idx], textureIntermediateDistanceMapOutput, sizeOccupancyMap)

# Cleanup
delete_ubo()
```

**Edge Cases and Pitfalls:**
*   **Zero Active Maps:** If `numMapsToCombineTotal` is 0, `numIterations` is 0, and the loop is skipped. The output distance map may need to be initialized to a maximum value (infinity) to indicate no occupied space.
*   **Precision:** The use of `GL_R8UI` implies 8-bit unsigned integer distance values. This may lead to quantization errors or overflow if the distance values exceed 255. The source notes that support points for the transfer function must use `int` datatype, not `uchar8`, to avoid conversion issues, but the distance maps themselves are stored as `GL_R8UI` [S1, unofficial].
*   **Boundary Conditions:** The compute shader must handle boundary checks correctly when reading from partitioned maps and writing to the swap buffers.

## Subtopics

### [Partitioned Distance Map (PDM) Acceleration](1286-partitioned-distance-map-pdm-acceleration.md)
Direct Volume Rendering (DVR) with Partitioned Distance Maps (PDM) based Empty Space Skipping (ESS) is an acceleration technique for distance-field ray marching that subdivides the volume's intensity range into $n$ partitions to precompute individual distance maps. When a transfer function (TF) changes, only the relevant PDMs are merged to form the final distance map $D'$, avoiding a full recomputation of the distance transform. Unlike the base method [Partitioned Distance Map Combination](1191-partitioned-distance-map-combination.md) which recomputes the global distance map on every TF change, PDM-based ESS trades higher memory usage and one-time initialization cost for significantly faster TF update times, maintaining high frame rates during frequent TF adjustments.

## Operating characteristics
*   **Time Complexity:** The combination process is $O(N \cdot V)$, where $N$ is the number of active partitioned maps and $V$ is the number of voxels in the occupancy map. The number of iterations is proportional to $N / \text{numMapsToCombinePerLaunch}$.
*   **Memory Complexity:** Requires storing $n$ partitioned distance maps plus two swap buffers. The memory usage is $O(n \cdot V)$.
*   **Performance:** The method is designed for fast transfer function updates. The source indicates that it maintains high frame rates during frequent TF adjustments [S1, unofficial]. The constant `numMapsToCombinePerLaunch` is set to 6 [S1, unofficial].
*   **Strengths:** Fast TF updates, avoids full distance transform recomputation.
*   **Limitations:** Higher memory usage due to storing multiple partitioned maps. Initialization cost is higher. Precision limitations due to 8-bit distance maps.

## Background
The method is part of the DVR_ESS_PDM project, an unofficial implementation of Partitioned Distance Map based Empty Space Skipping for Direct Volume Rendering [S1, unofficial]. It builds on the principles of Distance Map Acceleration [972-distance-map-acceleration.md] and Occupancy Map Generation [1197-occupancy-map-generation.md].
