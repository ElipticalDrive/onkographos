# Sparse Voxel Octree CPU Rasterizer

Also called: Marceline Cramer SVO, SVO CPU

## Overview
A CPU-based rasterizer that traverses a Sparse Voxel Octree (SVO) to render voxels directly into a color buffer, utilizing depth-sorted traversal and hierarchical culling strategies that switch between rectangle and point primitives based on projected depth [S1, unofficial]. It distinguishes itself from GPU-based SVO renderers by performing the entire traversal and rasterization pipeline on the CPU, relying on a flat node array and explicit stack management for memory efficiency [S1, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   **SVO:** A Sparse Voxel Octree stored as a flat vector of `Node` structures.
*   **Camera:** Contains `eye` position (`Vec3A`) and projection matrix.
*   **Framebuffer:** A `ColorBuffer` with `width`, `height`, and pixel data.
*   **DrawConfig:** Parameters controlling rendering thresholds (`min_rect`, `max_rect`, `max_test`).

**Outputs:**
*   **Framebuffer:** Updated pixel colors with alpha blending.

### Data Structures
**Node Layout:**
Each `Node` is stored in a flat `Vec<Node>` and referenced by `NodeRef` (a `usize` index).
*   `occupancy`: `ChildMask` (u8). Bitmask where bit `i` indicates if child `i` exists. `occupancy == 0` denotes a leaf node.
*   `children`: `[NodeRef; 8]`. Array of indices into the flat `nodes` vector.
*   `data`: `Payload`. Contains `color: u32` in ABGR format (Alpha bits 24-31, Red 16-23, Green 8-15, Blue 0-7). Default is `0xff0000ff`.

**Traversal Order:**
*   **HILBERT_ORDER:** Static array defining the default child iteration order: `[(0, 0x01), (1, 0x02), (3, 0x08), (2, 0x04), (6, 0x40), (7, (0x80), (5, 0x20), (4, 0x10)]`.
*   **SORTED_ORDER_INDICES:** A static 2D array `[[ (ChildIndex, ChildMask); 8 ]; 48]`. Generated by `calc_child_orders()`, which combines 6 axis permutations with 8 flip variants each. Used for depth-sorted traversal.

**Frame Buffer:**
*   `width`, `height`: Dimensions.
*   `px`: `f32`, minimum of width/height.
*   `data`: `Vec<P>` (flat pixel array). Default resolution 1280x720.

### Algorithm Steps

1.  **Initialization:**
    *   Create a fixed-size stack `[(NodePtr, Vec3A, u32); 256]` to hold `(node_pointer, stem_position, depth)`.
    *   Push the root node onto the stack.

2.  **Traversal Loop (`fast_walk`):**
    *   While the stack is not empty, pop the top element `(node_ptr, stem, depth)`.
    *   Calculate the voxel center `voxel`:
        *   Compute `offset = depth_to_offset(depth)`.
        *   `voxel = stem.extend(offset * 1.73)` [S1, unofficial].
    *   Retrieve the node and check if it is a leaf (`node.is_leaf()`).
    *   **Callback:** Invoke `on_node(is_leaf, &node.data, voxel)`.
    *   **Culling/Recursion:** If the callback returns true and the node is **not** a leaf:
        *   Calculate the sorting order `order = Node::sorting_order(&eye, &stem)`.
        *   Iterate through children using `for_kids_ordered(order)`.
        *   For each occupied child, calculate its `origin` (stem + `index_offset(index, offset)`) and push `(child_ref, origin, depth + 1)` to the stack.

3.  **Voxel Rendering (`draw_voxel`):**
    *   **Projection:** Project the voxel center `voxel` to screen space.
        *   `vertex = voxel.extend(1.0)` (Vec4).
        *   `frag = projection_matrix * vertex`.
        *   `frag.z = -voxel.w` (adjust depth).
        *   `screen_pos = frag.xyz / frag.w` (Vec3A).
    *   **Primitive Selection:** Determine whether to draw a rectangle or a point based on `is_leaf` and projected Z depth `z`:
        *   **If NOT leaf:**
            *   If `z > max_rect`: Perform culling test (`test_rect`).
            *   Else if `z > min_rect`: Draw rectangle (`draw_rect`).
            *   Else: Draw point (`draw_point`).
        *   **If IS leaf:**
            *   If `z < min_rect`: Draw point (`draw_point`).
            *   Else: Draw rectangle (`draw_rect`).

4.  **Primitive Operations:**
    *   **`test_rect`:** Calculate projected bounds. If area `< max_test`, call `fb.test_rect(bounds)` to reserve space/cull. Returns true if culled.
    *   **`draw_rect`:** Calculate projected bounds and call `fb.draw_rect(bounds, color)`.
    *   **`draw_point`:** Get fragment XY coordinates via `fb.frag_xy(projected)` and call `fb.draw_point(xy, color)`.

5.  **Framebuffer Blending (`Target::draw`):**
    *   If destination pixel is 0, write new pixel.
    *   Else, extract destination alpha `dst_a`.
    *   If `dst_a < 255`, blend using `a = 256 - dst_a` [S1, unofficial].

### Pseudocode

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
# Data Structures
struct Node:
    occupancy: u8  # ChildMask
    children: [usize; 8]
    data: Payload

struct Payload:
    color: u32  # ABGR

struct DrawConfig:
    min_rect: f32
    max_rect: f32
    max_test: usize

# Helper Functions
def depth_to_offset(depth: u32) -> f32:
    # Implementation from source: bit manipulation for float representation
    # Note: Exact bit-packing logic from source uses unsafe transmute
    exp = 126 - depth
    f = exp << 23
    return bits_to_float(f)

def index_offset(index: u8, offset: f32) -> Vec3:
    offsets = [
        [-offset, -offset, -offset], [offset, -offset, -offset],
        [-offset, offset, -offset], [offset, offset, -offset],
        [-offset, -offset, offset], [offset, -offset, offset],
        [-offset, offset, offset], [offset, offset, offset]
    ]
    return offsets[index]

def sorting_order(eye: Vec3, stem: Vec3) -> u8:
    # Determine dominant axis and sign bits for depth sorting
    s = bitmask(eye >= stem)
    sx = s & 1
    sy = (s >> 1) & 1
    sz = (s >> 2) & 1
    a = abs(eye - stem)
    
    if a.x > a.y and a.x > a.z:
        if a.y > a.z:
            return (sx << 2) | (sy << 1) | sz
        else:
            return 8 + ((sx << 2) | (sz << 1) | sy)
    elif a.y > a.z:
        if a.x > a.z:
            return 16 + ((sy << 2) | (sx << 1) | sz)
        else:
            return 24 + ((sy << 2) | (sz << 1) | sx)
    else:
        if a.x > a.y:
            return 32 + ((sz << 2) | (sx << 1) | sy)
        else:
            return 40 + ((sz << 2) | (sy << 1) | sx)

# Main Traversal
def fast_walk(svo: SVO, eye: Vec3, on_node_callback):
    stack = [(svo.root_index, Vec3(0,0,0), 0)] * 256
    stack_ptr = 1
    
    while stack_ptr > 0:
        stack_ptr -= 1
        node_ref, stem, depth = stack[stack_ptr]
        node = svo.nodes[node_ref]
        
        offset = depth_to_offset(depth)
        voxel = stem.extend(offset * 1.73)
        
        is_leaf = (node.occupancy == 0)
        
        # Callback returns bool to control recursion
        should_recurse = on_node_callback(is_leaf, node.data, voxel)
        
        if should_recurse and not is_leaf:
            order = sorting_order(eye, stem)
            next_level = depth + 1
            
            # Iterate children in sorted order
            for index, mask in SORTED_ORDER_INDICES[order]:
                if (node.occupancy & mask) != 0:
                    child_ref = node.children[index]
                    origin = stem + index_offset(index, offset)
                    stack[stack_ptr] = (child_ref, origin, next_level)
                    stack_ptr += 1

# Rendering Logic
def draw_voxel(fb: Framebuffer, config: DrawConfig, is_leaf: bool, voxel: Vec3, color: u32):
    # Project voxel center
    vertex = voxel.extend(1.0)
    frag = proj_matrix * vertex
    frag.z = -voxel.w
    screen_pos = frag.xyz / frag.w
    z = screen_pos.z
    
    if not is_leaf:
        if z > config.max_rect:
            if test_rect(fb, screen_pos, config.max_test):
                return
        if z > config.min_rect:
            draw_rect(fb, screen_pos, color)
        else:
            draw_point(fb, screen_pos, color)
    else:
        if z < config.min_rect:
            draw_point(fb, screen_pos, color)
        else:
            draw_rect(fb, screen_pos, color)

def test_rect(fb: Framebuffer, screen_pos: Vec3, max_test: usize) -> bool:
    bounds = get_bounds(screen_pos)
    area = (bounds[2] - bounds[0]) * (bounds[3] - bounds[1])
    if area < max_test:
        fb.test_rect(bounds)
        return True
    return False

def draw_rect(fb: Framebuffer, screen_pos: Vec3, color: u32):
    bounds = get_bounds(screen_pos)
    fb.draw_rect(bounds, color)

def draw_point(fb: Framebuffer, screen_pos: Vec3, color: u32):
    xy = fb.frag_xy(screen_pos)
    fb.draw_point(xy, color)
```

### Parameters
*   `min_rect`: Minimum projected Z to draw as a rectangle. [S1, unofficial]
*   `max_rect`: Maximum projected Z to draw as a rectangle; beyond this, culling is tested. [S1, unofficial]
*   `max_test`: Maximum pixel area for the culling test. [S1, unofficial]
*   `MAX_DEPTH`: Constant set to 4 in procedural generation, controlling octree depth. [S1, unofficial]

### Edge Cases and Pitfalls
*   **Precision:** The `depth_to_offset` function uses bit manipulation (`transmute`) to generate float offsets, which may introduce precision artifacts if not handled carefully [S1, unofficial].
*   **Stack Overflow:** The stack size is fixed at 256 entries. Deeply nested or complex scenes may exceed this limit, causing traversal errors [S1, unofficial].
*   **Culling Logic:** The culling test (`test_rect`) reserves space in the framebuffer. If multiple overlapping rectangles pass the test, depth sorting ensures correct blending, but incorrect Z-ordering can lead to visual artifacts [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of visited nodes in the SVO. Depth sorting adds overhead proportional to the number of internal nodes traversed.
*   **Memory Complexity:** O(N) for the flat node array, where N is the number of nodes. The stack is fixed size (256 entries), making it memory-efficient for deep trees.
*   **Performance:** Performance is measured on CPU hardware. The use of SIMD operations for pixel format conversion (`pixel_to_simd`, `simd_to_pixel`) suggests optimization for vector processing [S1, unofficial].
*   **Strengths:** Efficient memory usage due to flat array and explicit stack; flexible traversal order based on camera position; hierarchical culling reduces overdraw.
*   **Limitations:** Fixed stack size limits depth; CPU-bound performance may lag behind GPU rasterizers for high-resolution scenes; precision issues in depth calculation.

## Background
The method originates from the `marceline-cramer/svo-cpu` repository, an unofficial implementation of a CPU-based Sparse Voxel Octree rasterizer [S1, unofficial]. It builds upon hierarchical grid traversal techniques and adapts them for CPU execution, emphasizing depth-sorted rendering and efficient node management.
