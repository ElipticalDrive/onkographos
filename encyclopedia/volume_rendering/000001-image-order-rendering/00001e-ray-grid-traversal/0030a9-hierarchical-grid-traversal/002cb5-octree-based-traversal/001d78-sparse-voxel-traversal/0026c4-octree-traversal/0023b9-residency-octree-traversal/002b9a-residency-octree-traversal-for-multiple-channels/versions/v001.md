# Residency-octree traversal for multiple channels

Also called: Multi-channel octree traversal

## Overview
This method extends residency-based octree traversal to handle multiple volume channels simultaneously within a single ray. It solves the problem of efficient empty-space and homogeneous-node skipping in multi-volume rendering by requiring that a node be empty or homogeneous for **all** active channels before it can be skipped [S1, unofficial]. Unlike single-channel traversal, which skips a node as soon as it is empty for that specific channel, this algorithm continues traversing deeper levels for non-empty channels until they also reach an empty or homogeneous state, ensuring no visible data is skipped [S1, unofficial].

## How it works
**Inputs:**
- `rootNode`: The root of the residency octree.
- `ray`: The current ray being evaluated.
- `stepSize(ray)`: The distance between ray samples.
- `numChannels`: The total number of volume channels to render.
- `noCullingInformation(node, channelIndex)`: A check for the availability of culling metadata (empty/homogeneous flags) for a specific node and channel.
- `isEmpty(node, channelIndex)`: Returns true if the node is empty for the given channel.
- `isPartiallyMapped(node, channelIndex)`: Returns true if the node contains data that requires further subdivision or detailed rendering.
- `depth(ray)`: The current depth of the ray in the tree.
- `next(node, ray)`: Returns the child node along the ray path.
- `chooseTraversalDepth(stepSize)`: Calculates the maximum traversal depth based on ray step size.
- `chooseResolutionLevel(depth, channelIndex)`: Determines the brick resolution level for a specific channel at a given depth.
- `skipNode(node, ray)`: Updates the ray origin to the far boundary of the node's spatial extent.

**Outputs:**
- Node requests for missing culling information or missing child nodes.
- Brick requests for rendering, including the chosen resolution level for each channel.

**Data Structures:**
- `traversalDepth`: Integer, the maximum depth to traverse.
- `node`: Reference to the current octree node.
- `channelIndex`: Integer, index of the current channel being processed (0 to `numChannels - 1`).
- `emptyChannels`: Integer, counter of channels found to be empty for the current node.
- `homogeneousChannels`: Integer, counter of channels found to be homogeneous for the current node (implied by text, though pseudocode omits explicit variable declaration for brevity, the logic mirrors `emptyChannels`).

**Parameters:**
- `traversalDepth`: Determined by `chooseTraversalDepth(stepSize(ray))`. Not given in the sources.

**Algorithm Steps:**
1. Initialize `traversalDepth` based on the ray step size.
2. Set `node` to `rootNode`, `channelIndex` to 0, and `emptyChannels` to 0.
3. Loop while `node.depth` is less than or equal to `traversalDepth` AND `channelIndex` is less than `numChannels`.
4. If no culling information is available for the current `node` and `channelIndex`, report a node request for that node and channel, increment `channelIndex`, and continue to the next iteration.
5. If the current `node` is empty for the current `channelIndex`:
   - Check if `emptyChannels` equals `numChannels - 1`.
   - If so, skip the node by updating the ray based on the node's spatial extent (using the extent of the last empty node encountered), break the loop, and stop traversal for this ray.
   - If not all channels are empty, increment `emptyChannels`, increment `channelIndex`, and continue to the next channel.
6. If the node is homogeneous for the current channel (logic mirrors empty nodes):
   - Check if `homogeneousChannels` equals `numChannels - 1`.
   - If so, skip the node using the spatial extent of the last homogeneous node encountered, break the loop, and stop traversal.
   - If not all channels are homogeneous, increment `homogeneousChannels`, increment `channelIndex`, and continue.
7. If the node is not partially mapped for the current channel (i.e., it is fully mapped or requires rendering):
   - Choose the resolution level for the current depth and channel.
   - Report a brick request with the chosen resolution level.
   - Increment `channelIndex` and break the loop to proceed to rendering.
8. If the loop continues past the depth check (implying end of traversal or specific condition), choose the resolution level for the current channel, and increment `channelIndex`.
9. If `node.depth` is less than `traversalDepth`:
   - Determine the next node along the ray.
   - If the next node is missing, report a node request for it.
   - Otherwise, update the current `node` to the next node and continue the loop.

**Pseudocode:**
```python
def residency_octree_traversal_multi_channel(rootNode, ray, numChannels):
    # 1. Initialize traversal depth
    traversalDepth = chooseTraversalDepth(stepSize(ray))
    
    # 2. Initialize state
    node = rootNode
    channelIndex = 0
    emptyChannels = 0
    homogeneousChannels = 0
    
    # 3. Main traversal loop
    while node.depth <= traversalDepth and channelIndex < numChannels:
        
        # 4. Check for culling information availability
        if noCullingInformation(node, channelIndex):
            reportNodeRequest(node, channelIndex)
            channelIndex += 1
            continue
            
        # 5. Handle empty nodes
        if isEmpty(node, channelIndex):
            if emptyChannels == numChannels - 1:
                # All channels are empty; skip this node
                ray = skipNode(node, ray)
                break
            else:
                # Only some channels are empty; continue to next channel
                emptyChannels += 1
                channelIndex += 1
                continue
        
        # 6. Handle homogeneous nodes (mirrors empty node logic)
        if isHomogeneous(node, channelIndex):
            if homogeneousChannels == numChannels - 1:
                # All channels are homogeneous; skip this node
                ray = skipNode(node, ray)
                break
            else:
                # Only some channels are homogeneous; continue to next channel
                homogeneousChannels += 1
                channelIndex += 1
                continue
                
        # 7. Handle partially mapped / renderable nodes
        if not isPartiallyMapped(node, channelIndex):
            # Node is fully mapped or requires rendering
            resolutionLevel = chooseResolutionLevel(depth(ray), channelIndex)
            reportBrickRequest(node, ray, resolutionLevel, channelIndex)
            channelIndex += 1
            break
            
        # 8. Move to next level if depth allows
        if node.depth < traversalDepth:
            nextNode = next(node, ray)
            if nextNode.missing:
                reportNodeRequest(nextNode)
            else:
                node = nextNode
                continue
        else:
            # End of traversal depth reached
            resolutionLevel = chooseResolutionLevel(depth(ray), channelIndex)
            reportBrickRequest(node, ray, resolutionLevel, channelIndex)
            channelIndex += 1
```

**Edge Cases and Pitfalls:**
- **Empty Node Skipping:** Empty nodes can only be skipped if **ALL** channels are empty for that node. If a node is empty for one channel but not others, traversal must continue for the non-empty channels to find the subdivision level where they are empty [S1, unofficial].
- **Skipped Distance:** The skipped distance is determined by the spatial extent of the **last** empty (or homogeneous) node encountered during traversal. Since spatial extents of nodes strictly decrease between tree traversal steps, this strategy ensures that non-empty space is not skipped [S1, unofficial].
- **Homogeneous Nodes:** Homogeneous nodes are handled similarly to empty nodes. They are only skipped if all channels are homogeneous for that node. The values of the last homogeneous node encountered are used for rendering the node for each channel [S1, unofficial].

## Operating characteristics
- **Time Complexity:** In multi-volume settings, empty-space skipping may require more traversal steps than single-channel settings because multiple channels must be checked for each node [S1, unofficial].
- **Memory Complexity:** Not given in the sources.
- **Scaling:** Not given in the sources.
- **Strengths:** Efficiently skips empty and homogeneous regions across multiple volumes without rendering unnecessary data.
- **Limitations:** Increased traversal overhead compared to single-channel rendering due to the need to check all channels before skipping.
- **When to use:** Multi-volume rendering where channels share spatial structure and empty/homogeneous regions are common.
- **When not to use:** Single-channel rendering where simpler traversal suffices.

## Background
This method is described in the context of scalable web-based volume rendering of large biomedical datasets [S1, unofficial]. It is part of a mixed-resolution multi-volume rendering framework that uses residency-based octrees to manage memory and traversal efficiently [S1, unofficial].
