# Top Level Octree Rendering

Also called: Depth-dependent Octree Traversal, Y-coordinate based Octree Cutoff

## Overview
Top Level Octree Rendering is a rendering technique that stops octree traversal at a specific depth level determined by the pixel's y-coordinate, then applies lighting [S1, unofficial]. It differs from standard recursive traversal by using the vertical screen position to limit the traversal depth, effectively culling deeper nodes based on their apparent height in the viewport.

## How it works
**Inputs and Outputs:**
*   **Input:** An octree structure (`tree`) with a known grid length, a ray configuration (`rc`) containing camera parameters, screen dimensions (`n_y`), and a list of lights.
*   **Output:** A texture array (`texture_array`) containing the final RGB color and alpha for each pixel.

**Data Structures:**
*   `tree`: Contains `gridlength`, which defines the spatial extent of the voxel grid.
*   `rc`: Contains `n_y` (screen height in pixels), `lights` (list of light sources), and `camera` (containing `e_`, the eye position).
*   `TreeTraverser`: A helper object initialized with the tree and a specific ray. It maintains a `stack` representing the current path in the octree.
*   `DataPoint`: Stored in leaf nodes, containing `normal` (vector) and color data.

**Parameters:**
*   `depth`: Calculated as $\log_2(\text{tree->gridlength}) + 2$ [S1, unofficial].
*   `step`: Calculated as $\text{rc.n\_y} / \text{depth}$ [S1, unofficial].

**Algorithm Steps:**
1.  Calculate `depth` and `step` using the formulas above.
2.  Initialize a parallel loop over the screen height $y$ from $0$ to $\text{rc.n\_y} - 1$ [S1, unofficial].
3.  For each $y$, iterate over the screen width $x$ from $0$ to $\text{rc.n\_x} - 1$ [S1, unofficial].
4.  Initialize a `TreeTraverser` instance `t` for the ray corresponding to pixel $(x, y)$ [S1, unofficial].
5.  Traverse the octree while the traverser is not terminated:
    *   Check if the current stack size is greater than or equal to the cutoff threshold: $\lfloor y / \text{step} \rfloor$ [S1, unofficial].
    *   If the condition is met, break the traversal loop [S1, unofficial].
    *   Otherwise, call `t.step()` to advance to the next node [S1, unofficial].
6.  After traversal, compute lighting for the current position `t.getCurrentPosition()` [S1, unofficial].
7.  For each active light $i$:
    *   Compute the light vector: $\vec{to\_light} = \text{lights}[i].\text{position} - \text{current\_position}$ [S1, unofficial].
    *   Compute the half vector for specular reflection: $\vec{s} = \text{normalize}(\vec{to\_light} + (\text{camera}.e\_ - \text{current\_position}))$ [S1, unofficial].
    *   Compute distance attenuation: $\text{distancecut} = \frac{1.0}{\text{CONSTANT\_ATTENUATION} + \text{LINEAR\_ATTENUATION} \cdot \|\vec{to\_light}\| + \text{QUADRATIC\_ATTENUATION} \cdot \|\vec{to\_light}\|^2}$ [S1, unofficial].
    *   Normalize the light vector: $\vec{to\_light} = \text{normalize}(\vec{to\_light})$ [S1, unofficial].
    *   Compute diffuse factor: $\text{diffuse\_factor} = \text{data}[\text{current\_node}.\text{data}].\text{normal} \cdot \vec{to\_light}$ [S1, unofficial].
    *   Accumulate diffuse color: $r += \max(0.0, \text{diffuse\_factor}) \cdot \text{distancecut} \cdot \text{lights}[i].\text{diffuse}[0]$ (similarly for $g, b$) [S1, unofficial].
    *   Compute Phong specular factor: $\text{phong\_factor} = \text{pow}(\vec{s} \cdot \text{data}[\text{current\_node}.\text{data}].\text{normal}, \text{lights}[i].\text{SHININESS})$ [S1, unofficial].
    *   Accumulate specular color: $r += \max(0.0, \text{phong\_factor}) \cdot \text{distancecut} \cdot \text{lights}[i].\text{specular}[0]$ (similarly for $g, b$) [S1, unofficial].
8.  Write the final color to the texture array: $\text{texture\_array}[\text{index}] = \text{clamp}(255 \cdot r, 0, 255)$ [S1, unofficial].
9.  Set alpha: $\text{texture\_array}[\text{index}+3] = 1$ [S1, unofficial].

**Pseudocode:**
```python
def top_level_octree_rendering(tree, rc, texture_array):
    # Calculate depth and step parameters
    depth = log2(tree.gridlength) + 2
    step = rc.n_y / depth
    
    # Parallelize pixel loop
    for y in range(rc.n_y):
        for x in range(rc.n_x):
            # Initialize ray traverser
            t = TreeTraverser(tree, rc.get_ray_for_pixel(x, y))
            
            # Traverse tree with depth cutoff
            while not t.is_terminated():
                if len(t.stack) >= (y / step):
                    break
                t.step()
            
            # Get current position and node data
            current_pos = t.get_current_position()
            current_node = t.get_current_node()
            data = current_node.data
            
            # Initialize color accumulators
            r, g, b = 0.0, 0.0, 0.0
            
            # Process each light
            for light in rc.lights:
                # Compute light vector
                to_light = light.position - current_pos
                
                # Compute half vector for specular
                view_dir = rc.camera.e_ - current_pos
                s = normalize(to_light + view_dir)
                
                # Compute distance attenuation
                dist = length(to_light)
                dist_sq = dist * dist
                distancecut = 1.0 / (light.CONSTANT_ATTENUATION + 
                                     light.LINEAR_ATTENUATION * dist + 
                                     light.QUADRATIC_ATTENUATION * dist_sq)
                
                # Normalize light vector
                to_light = normalize(to_light)
                
                # Compute diffuse factor
                normal = data.normal
                diffuse_factor = dot(normal, to_light)
                
                # Accumulate diffuse color
                r += max(0.0, diffuse_factor) * distancecut * light.diffuse[0]
                g += max(0.0, diffuse_factor) * distancecut * light.diffuse[1]
                b += max(0.0, diffuse_factor) * distancecut * light.diffuse[2]
                
                # Compute Phong specular factor
                phong_factor = pow(max(0.0, dot(s, normal)), light.SHININESS)
                
                # Accumulate specular color
                r += max(0.0, phong_factor) * distancecut * light.specular[0]
                g += max(0.0, phong_factor) * distancecut * light.specular[1]
                b += max(0.0, phong_factor) * distancecut * light.specular[2]
            
            # Write final color
            index = (y * rc.n_x + x) * 4
            texture_array[index] = clamp(255 * r, 0, 255)
            texture_array[index + 1] = clamp(255 * g, 0, 255)
            texture_array[index + 2] = clamp(255 * b, 0, 255)
            texture_array[index + 3] = 1
```

**Edge Cases and Pitfalls:**
*   **Division by Zero:** If `depth` is zero, `step` calculation will fail. This occurs if `tree.gridlength` is 1 or less, resulting in `log2(1) + 2 = 2` (safe) or `log2(0)` (undefined). Ensure `gridlength` is at least 1.
*   **Integer Division:** The cutoff condition `y / step` uses floating-point division in the source, but the comparison `stack.size() >= ...` compares an integer size to a float. Ensure consistent types to avoid precision issues.
*   **Boundary Conditions:** The loop bounds for $x$ and $y$ must match the screen resolution. The source code implies a rectangular screen but only explicitly loops $y$ in the parallel directive and mentions $x$ in the ray generation.

## Operating characteristics
*   **Time Complexity:** Depends on the octree depth and the cutoff threshold. The cutoff reduces the number of nodes visited for pixels with low $y$ values (assuming $y=0$ is top or bottom depending on coordinate system).
*   **Memory Complexity:** Requires storage for the octree and the texture array. The traverser stack depth is limited by the cutoff, reducing peak memory usage compared to full traversal.
*   **Strengths:** Reduces computation for parts of the image where deep traversal is not necessary (e.g., distant or less detailed regions if mapped to $y$).
*   **Limitations:** The quality of the result depends heavily on the mapping between $y$-coordinate and depth. If the scene geometry does not correlate with screen height, the cutoff may introduce artifacts or miss important details.
*   **When to Use:** When the scene has a strong correlation between vertical screen position and depth/detail requirements, or when performance is critical and some loss of detail is acceptable.
*   **When Not to Use:** When uniform rendering quality is required across the entire image.

## Background
This technique is described in the `cpu_voxel_raycaster` project by Forceflow [S1, unofficial]. It appears to be a custom optimization for CPU-based voxel raycasting, leveraging the parallelization capabilities of OpenMP. The method is not a standard academic algorithm but rather a practical implementation detail from a specific codebase.
