# Residency Octree Traversal

Also called: Ray-Guided Volume Rendering with Residency Octree, Single Channel Residency Traversal

## Overview
Residency Octree Traversal is a ray-guided method for sparse voxel volume rendering that determines which data bricks to load from a server into a local cache based on the current viewing ray [S1]. It solves the problem of efficient memory management and bandwidth reduction in large-scale volume visualization by skipping empty or homogeneous regions and only requesting bricks that are actually needed for rendering [S1]. It sets itself apart from standard octree traversal by integrating residency metadata directly into the traversal logic, allowing the renderer to decide whether to skip a node, use its aggregate value, or request specific voxel data based on cache status and resolution requirements [S1].

## How it works
The method traverses a residency octree for each pixel's viewing ray to determine the sampling strategy and data requirements. It relies on leaf node metadata to identify empty, homogeneous, or unmapped regions, and uses residency information to manage brick caching [S1].

**Inputs and Outputs:**
*   **Input:** Viewing ray (origin, direction), current pixel coordinates, current sampling step size, desired resolution level (determined by viewing parameters like distance to camera), maximum traversal depth (derived from step size to prevent skipping over samples smaller than the step) [S1].
*   **Output:** A decision for each ray sample: skip (empty), use node value (homogeneous), request brick (needed but not resident), or advance to next sample [S1].

**Data Structures:**
*   **Residency Octree:** A hierarchical structure where each node contains metadata [S1].
*   **Node Metadata:** Includes flags for empty, homogeneous, and partially mapped states, as well as residency status of child bricks [S1]. The metadata for newly added bricks is set by the bit-wise OR of their child nodes’ bitmasks [S1].
*   **Brick Cache:** Stores resident voxel data bricks [S1].

**Parameters:**
*   **Desired Resolution Level:** Chosen based on viewing parameters (e.g., distance to camera) [S1].
*   **Maximum Traversal Depth:** Chosen based on the current sampling step size to ensure the ray does not skip a distance smaller than the distance to the next ray sample [S1].

**Algorithm Steps:**
1.  **Initialize:** For each pixel, march along the viewing ray. Determine the desired resolution level and maximum traversal depth [S1].
2.  **Traverse:** Start at the root node (assumed to have metadata). Traverse the tree until the maximum traversal depth is reached or a terminal condition is met [S1].
3.  **Check Node State:** At the current node, check the metadata:
    *   **Empty:** If the node is empty, skip all samples along the ray that would fall into this node. Advance the ray to the next relevant node or sample [S1].
    *   **Homogeneous:** If the node is homogeneous (all voxels hold approximately the same value), use the node's value directly for rendering for all samples falling into the node. Advance the ray to the next node [S1].
    *   **Not Partially Mapped:** If the node is not even partially mapped, stop traversal for this ray segment and report a brick request [S1].
    *   **Refinement Needed:** If the current subtree is not deep enough to reach the target traversal depth AND culling information does not allow skipping the current node, refine the residency octree by requesting a new node [S1].
4.  **Retrieve Brick:** If the target traversal depth is reached and the current node is non-empty and inhomogeneous:
    *   Attempt to retrieve the brick of the chosen resolution level from the brick cache [S1].
    *   **Cache Miss:** If the brick is not resident, report a brick request. Try to load a brick from an alternative resolution level where the node is partially mapped [S1].
    *   **No Brick Found:** If no brick is found in alternative resolutions, advance the ray to the next sample [S1].
5.  **Adjust Sampling:** Depending on the resolution level of the retrieved brick, potentially increase the sampling distance along the ray [S1].

**Pseudocode:**
```python
def residency_octree_traversal(ray, pixel, max_depth, desired_resolution):
    """
    Traverses the residency octree for a single ray sample.
    Returns: action ('skip', 'use_value', 'request_brick', 'advance')
    """
    # Determine current node based on ray position and previous traversal state
    current_node = get_node_at_ray_position(ray)
    
    # Traverse until max depth or terminal condition
    depth = 0
    while depth < max_depth:
        # Check if node metadata is valid
        if not current_node.has_valid_metadata():
            # Refine octree if subtree not deep enough and cannot skip
            if not can_skip_node(current_node):
                request_new_node(current_node)
                current_node = get_refined_node(current_node)
            else:
                return 'skip'
        
        # Check node state
        if current_node.is_empty():
            return 'skip'
        
        if current_node.is_homogeneous():
            return 'use_value', current_node.value
        
        if not current_node.is_partially_mapped():
            return 'request_brick'
        
        # Move to child if not at max depth and not terminal
        if depth < max_depth - 1:
            current_node = get_child_node(current_node, ray)
            depth += 1
        else:
            break
            
    # At target depth, node is non-empty and inhomogeneous
    # Try to get brick from cache at desired resolution
    brick = brick_cache.get(desired_resolution, current_node.id)
    
    if brick is not None:
        # Adjust sampling distance based on resolution
        adjust_sampling_distance(brick.resolution)
        return 'use_brick', brick
    
    # Cache miss: request brick
    request_brick_from_server(desired_resolution, current_node.id)
    
    # Try alternative resolution levels
    for alt_res in alternative_resolutions(desired_resolution):
        alt_brick = brick_cache.get(alt_res, current_node.id)
        if alt_brick is not None:
            adjust_sampling_distance(alt_brick.resolution)
            return 'use_brick', alt_brick
            
    # No brick found
    return 'advance'
```

## Subtopics

### [Residency-octree traversal for multiple channels](5041-residency-octree-traversal-for-multiple-channels.md)
Extends the method to handle multiple volume channels simultaneously. It requires that a node be empty or homogeneous for **all** active channels before it can be skipped, ensuring no visible data is skipped for any channel.

## Operating characteristics
*   **Time Complexity:** Depends on the tree depth and the number of nodes visited per ray. The traversal stops early for empty or homogeneous nodes, reducing the number of cache lookups and server requests [S1].
*   **Memory Complexity:** Proportional to the number of resident bricks in the cache. The residency octree metadata is stored in memory [S1].
*   **Performance:** Efficient for large-scale volumes with significant empty or homogeneous regions, as it minimizes data transfer and processing for irrelevant data [S1]. Performance degrades if the cache misses are frequent or if the volume is dense and inhomogeneous [S1].
*   **Strengths:** Reduces bandwidth and memory usage by only loading necessary data. Supports mixed-resolution rendering for different channels [S1].
*   **Limitations:** Requires maintaining residency metadata. Complex to implement for multi-channel scenarios where traversal must continue until all channels are processed [S1].

## Background
The method was introduced in the paper "Residency Octree: A Hybrid Approach for Scalable Web Volume Rendering" [S1]. It is part of a broader effort to enable scalable volume rendering on the web, leveraging ray-guided techniques to manage data residency efficiently [S1].
