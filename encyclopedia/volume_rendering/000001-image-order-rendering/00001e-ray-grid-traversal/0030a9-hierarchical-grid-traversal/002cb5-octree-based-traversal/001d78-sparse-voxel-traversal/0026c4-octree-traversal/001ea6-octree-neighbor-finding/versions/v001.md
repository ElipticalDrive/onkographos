# Octree Neighbor Finding

Also called: GetNeighbors, Neighbor Retrieval

## Overview
Octree Neighbor Finding determines the adjacent leaf nodes in six cardinal directions (±X, ±Y, ±Z) for a given node in a Sparse Voxel Octree (SVO) [S1, unofficial][S2]. It solves the problem of traversing between non-contiguous or differently-sized nodes during ray casting or pathfinding by locating the nearest shared ancestor and performing point location to retrieve the neighbor [S1, unofficial][S2][S3, unofficial]. It differs from sibling methods like [Morton Key Vertex Neighbor Iteration](3318-morton-key-vertex-neighbor-iteration.md) by relying on explicit parent-pointer traversal (via a trace array) and coordinate bit-masking rather than Morton key arithmetic [S1, unofficial].

## How it works
**Inputs:**
- `current_node`: The index of the starting leaf node.
- `direction`: A vector specifying the target direction (e.g., `+X`, `-Y`).
- `parent_trace`: An array containing the indices of all parent nodes from the root to `current_node`, provided by the ray traversal algorithm [S3, unofficial].
- `depth`: The depth level of `current_node`.

**Outputs:**
- `neighbor_index`: The index of the adjacent leaf node, or a sentinel value (e.g., `INDEX_NONE`) if no neighbor exists in that direction.

**Data Structures:**
- **Node Struct**: Contains `depth` (7 bits), `is_leaf` (1 bit), `position` (3 floats), and `size` (1 float) [S1, unofficial].
- **Parent Trace Array**: `trace[]` stores the indices of parent nodes for the current ray cap, allowing upward traversal without storing explicit parent pointers in the node structure [S3, unofficial].

**Algorithm Steps:**
1. **Validation**: Verify `current_node` is a leaf. If not, return `INDEX_NONE` [S1, unofficial].
2. **Target Position Calculation**: Compute the position just outside the current node in the specified `direction`.
   - Let `pos` be the center of `current_node`.
   - Let `half_size` be half the width of `current_node`.
   - `target_pos = pos + direction * (half_size + epsilon)` [S1, unofficial].
3. **Upward Traversal (Find Common Ancestor)**:
   - Iterate up the tree using `parent_trace` from `depth` down to 0.
   - At each level `d`, check if the target position falls within the spatial bounds of the parent node `parent_trace[d]`.
   - The check uses bit-masking on the coordinates relative to the grid. For a node at depth `d` with size $2^{-d}$, the coordinate bits above $d$ must match the parent's bounds [S2][S3, unofficial].
   - Specifically, for each axis $a \in \{X, Y, Z\}$, verify:
     $$ (target\_pos[a] \gg (MAX\_DEPTH - d)) == (current\_node\_pos[a] \gg (MAX\_DEPTH - d)) $$
     This identifies the lowest common ancestor that contains both the current node and the target position [S3, unofficial].
4. **Point Location**:
   - Once the common ancestor is found, perform a standard point-location search (ray traversal or coordinate descent) from the root (or the common ancestor) to the `target_pos` [S3, unofficial].
   - This search descends the octree, selecting children based on the coordinate bits at each level [S1, unofficial].
5. **Neighbor Collection**:
   - If the search lands on a leaf node, return it.
   - If the search lands on an internal node, the neighbor is one of its children.
   - To find the specific child adjacent to the current node, use `AxisMask` and `AxisBit` [S1, unofficial].
     - `AxisMask`: A bitmask for the axis. X=001, Y=010, Z=100 (binary) [S1, unofficial].
     - `AxisBit`: Returns `AxisMask` if `direction` is negative (-1), else 0 [S1, unofficial].
     - The child index is filtered by checking if the child's position bit matches the `AxisBit` condition [S1, unofficial].
   - Limit the search depth to the current node's depth to ensure only adjacent leaves of equal or larger size are collected, avoiding all descendants [S1, unofficial].

**Pseudocode:**
```python
def get_neighbors(current_node_idx, direction, parent_trace, max_depth):
    # 1. Validate leaf
    if not is_leaf(current_node_idx):
        return INDEX_NONE

    current_pos = get_node_position(current_node_idx)
    current_size = get_node_size(current_node_idx)
    current_depth = get_node_depth(current_node_idx)
    
    # 2. Calculate target position outside the node
    # epsilon ensures we are strictly outside the current voxel
    target_pos = current_pos + direction * (current_size + 1e-6)
    
    # 3. Find common ancestor using parent_trace
    common_ancestor_idx = parent_trace[current_depth]
    
    # Traverse up to find the lowest common ancestor
    for d in range(current_depth, -1, -1):
        parent_idx = parent_trace[d]
        parent_pos = get_node_position(parent_idx)
        parent_size = get_node_size(parent_idx)
        
        # Check if target_pos is within parent bounds
        # A point is in a node if its coordinates, when shifted by the node's depth,
        # match the node's base coordinate bits.
        if is_point_in_node(target_pos, parent_pos, parent_size, d):
            common_ancestor_idx = parent_idx
            break
            
    # 4. Point location from common ancestor to target_pos
    # This is a standard descent from the common ancestor
    neighbor_idx = point_location(common_ancestor_idx, target_pos, max_depth)
    
    # 5. Handle internal node result (if neighbor is larger)
    if neighbor_idx != INDEX_NONE and not is_leaf(neighbor_idx):
        # If the found node is internal, we need the specific child adjacent to current
        # Use AxisMask/AxisBit logic to identify the correct child index
        axis_mask = get_axis_mask(direction)
        axis_bit = axis_mask if direction < 0 else 0
        
        # Determine child index based on relative position
        # This part depends on the specific child indexing scheme (e.g., Morton)
        child_idx = find_adjacent_child(neighbor_idx, current_pos, direction, axis_mask, axis_bit)
        return child_idx
        
    return neighbor_idx

def is_point_in_node(point, node_pos, node_size, depth):
    # Check if point is within [node_pos - node_size/2, node_pos + node_size/2]
    half = node_size / 2.0
    return (node_pos.x - half <= point.x < node_pos.x + half) and \
           (node_pos.y - half <= point.y < node_pos.y + half) and \
           (node_pos.z - half <= point.z < node_pos.z + half)
```

**Parameters:**
- `AxisMask`: Bit mask for axis direction. X returns `001`, Y returns `010`, Z returns `100` [S1, unofficial].
- `AxisBit`: Returns `AxisMask` if `Side` is -1, returns `0` if `Side` is +1 [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Non-Leaf Input**: The algorithm must validate that the input node is a leaf; otherwise, it returns immediately [S1, unofficial].
- **Depth Limiting**: The search must stop at a leaf or when the depth matches the current node's depth to avoid collecting all descendants of a neighbor [S1, unofficial].
- **Memory Footprint**: Parent pointers are omitted from nodes to save memory; the `parent_trace` array must be maintained by the caller (ray traversal) [S3, unofficial].
- **Optimization**: Use static polymorphism via templates for each X, Y, Z dimension to perform only one or two equality tests per iteration [S2].

## Subtopics

### [Neighbor Finding](2198-neighbor-finding.md)
Determines the next cell in a hierarchical spatial structure by backtracing from a start coordinate to the common ancestor with a destination coordinate, then performing point location. It differs from [Morton Key Vertex Neighbor Iteration](3318-morton-key-vertex-neighbor-iteration.md) by relying on explicit parent-pointer traversal and coordinate bit-masking rather than Morton key arithmetic.

### [Morton Key Vertex Neighbor Iteration](3318-morton-key-vertex-neighbor-iteration.md)
Identifies and processes the eight corner vertices of leaf nodes in a sparse voxel octree by leveraging the spatial locality of Morton (Z-order) keys. It solves the dual-grid traversal problem by operating on a pre-computed or iterated list of vertex keys, using bitwise arithmetic to resolve adjacency and handle level mismatches without tree traversal recursion.

## Operating characteristics
- **Time Complexity**: $O(D)$ where $D$ is the depth of the octree, due to the upward traversal and subsequent point location [S3, unofficial].
- **Memory Complexity**: $O(1)$ auxiliary space per neighbor query, assuming the `parent_trace` array is provided by the traversal context [S3, unofficial].
- **Strengths**: Efficient for sparse structures where explicit parent pointers are too costly; works with arbitrary node sizes [S3, unofficial].
- **Limitations**: Requires the `parent_trace` array to be maintained by the caller; slower than Morton-key based methods if keys are already available [S1, S3, unofficial].
- **When to Use**: When memory footprint is critical (no parent pointers in nodes) or when traversing non-contiguous nodes in an SVO [S3, unofficial].
- **When Not to Use**: When Morton keys are readily available and the overhead of bit arithmetic is lower than tree traversal [S1, unofficial].

## Background
The method originates from interactive isosurface ray tracing of large octree volumes [S3, unofficial]. The authors rejected Frisken and Perry's exclusive "or" method for immediate neighbors because it was no cheaper than &-masking both source and destination and performing integer equality on the results [S3, unofficial]. To minimize memory footprint, parent pointers were omitted from octree nodes, requiring the ray traversal algorithm to fill an index trace array containing the indices of all parent nodes for a given cap [S3, unofficial].
