# Octree Traversal with Fixed-Size Leaf Volumes

Also called: Hierarchical Ray Marching with Fixed Leaf Size, Adaptive Level Traversal

## Overview
This method is a hierarchical ray marching technique that switches between octree levels and voxel levels to optimize traversal [S1, unofficial]. It starts at the finest level (voxels, level -1) or a coarse octree level, and adjusts the level up or down based on hit/miss status to optimize traversal [S1, unofficial]. It sets itself apart from standard iterative octree traversal by fixing the leaf node size to a constant volume (e.g., 32x32x32 voxels) rather than using the smallest available octree nodes, which simplifies the inner loop and reduces memory overhead for sparse data at the cost of potential false positives [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin ($rayPos$), ray direction ($rayDir$), scene data containing `octantSize` (size of octants at level 0), `octreeHighestLevel` (maximum octree level index), and a 3D voxel texture where each 32-bit uint contains data for 4 voxels packed in a specific layout [S1, unofficial].
*   **Output:** A hit result containing position, normal, iterations, status, voxel data, and UV coordinates [S1, unofficial].

**Data Structures:**
*   **Voxel Texture:** A 3D texture where each texel is a 32-bit unsigned integer. The data for 4 voxels is packed into one texel. The packing layout for a voxel at integer coordinates $(x, y, z)$ is determined by the least significant bits of $x$ and $z$:
    *   Shift count: $shiftCount = (x \& 0x1) | ((z \& 0x1) << 1)$ [S1, unofficial].
    *   Mask: $mask = 255u << (shiftCount << 3u)$ [S1, unofficial].
    *   The texel is loaded at $(x >> 1, y, z >> 1)$ [S1, unofficial].
    *   The voxel value is extracted by applying the mask and shifting right by $shiftCount << 3u$ [S1, unofficial].
*   **Scene Data:** Contains `octantSize` (u32) and `octreeHighestLevel` (u32) [S1, unofficial].

**Parameters:**
*   `sceneData.octantSize`: The size of octants at level 0 [S1, unofficial].
*   `sceneData.octreeHighestLevel`: The maximum octree level index [S1, unofficial].
*   Leaf node size: Fixed at 32x32x32 voxels [S2, unofficial].
*   Max iterations per level: 1024 if level is the highest, else 4 [S1, unofficial].
*   Initial level: -1 (voxels) [S1, unofficial].

**Steps:**
1.  Initialize `level` to -1 (representing the finest voxel level) [S1, unofficial].
2.  Loop for a maximum number of iterations (implementation dependent, typically bounded by scene size or max depth) [S1, unofficial].
3.  If `level` is -1:
    *   Call `MarchThroughVoxels` with 4 iterations [S1, unofficial].
    *   This function samples the voxel texture directly at the current `rayPos` [S1, unofficial].
4.  If `level` >= 0:
    *   Calculate `unitSize` as `sceneData.octantSize << level` [S1, unofficial].
    *   Calculate `maxIterations` for this level: if `level` is `sceneData.octreeHighestLevel`, use 1024, else use 4 [S1, unofficial].
    *   Call `MarchThroughOctree` with `rayPos/unitSize`, `rayDir`, `level`, and `maxIterations` [S1, unofficial].
    *   `MarchThroughOctree` traverses the octree structure. It uses a skip list to avoid re-examining nodes. The skip list is updated by shifting 1 right by `usedIndex` (the index of the child node) and bitwise ORing it with the current value: `skipListPerDepth[currentDepth] |= (1 << usedIndex)` [S2, unofficial].
    *   It saves the index and position of the current parent node, then increments `currentDepthVariable` to traverse one level deeper [S2, unofficial].
5.  After the march function returns a `rayHit` result:
    *   Scale `rayHit.position` by `unitSize` [S1, unofficial].
    *   Add `rayHit.iterations` to total iterations [S1, unofficial].
    *   Update `rayPos` to `rayHit.position` [S1, unofficial].
6.  Check `rayHit.status`:
    *   If status is 0 (miss) and `level` < `sceneData.octreeHighestLevel`: increment `level` (move to coarser octree) and continue loop [S1, unofficial].
    *   If status is 1 (hit octree node but no leaf/voxel hit yet) and `level` > -1: decrement `level` (move to finer octree) and continue loop [S1, unofficial].
    *   If status is 2 (hit voxel): copy position, normal, iterations, status, voxelData, and uv to result and return [S1, unofficial].
    *   If status is 3 (out of bounds): copy position, status, iterations to result and return [S1, unofficial].

    total_iterations = 0
    
    # Max iterations for the entire traversal loop to prevent infinite loops
    max_total_iterations = 10000 
    
    for _ in range(max_total_iterations):
        if level == -1:
            # March through fine voxels
            # Assumes MarchThroughVoxels returns a hit structure

            else:
                max_iter = 4
            
            # Normalize ray for this level's coordinate system
            normalized_ray_pos = ray_pos / unit_size
            ray_hit = march_through_octree(normalized_ray_pos, ray_dir, level, max_iter)
        
        # Scale position back to world space
        ray_hit.position = ray_hit.position * unit_size
        total_iterations += ray_hit.iterations
        ray_pos = ray_hit.position
        
        if ray_hit.status == 2: # Hit voxel
            return {
                'position': ray_hit.position,
                'normal': ray_hit.normal,
                'iterations': total_iterations,
                'status': 2,
                'voxel_data': ray_hit.voxel_data,
                'uv': ray_hit.uv
            }
        elif ray_hit.status == 3: # Out of bounds
            return {
                'position': ray_hit.position,
                'status': 3,
                'iterations': total_iterations
            }
        elif ray_hit.status == 0: # Miss
            if level < scene_data.octree_highest_level:
                level += 1 # Go coarser
                continue
            else:
                # Missed at highest level, return miss
                return {
                    'position': ray_pos,
                    'status': 0,
                    'iterations': total_iterations
                }
        elif ray_hit.status == 1: # Hit octree node
            if level > -1:
                level -= 1 # Go finer
                continue
            else:
                # Should not happen if level -1 is handled, but fallback to miss
                return {
                    'position': ray_pos,
                    'status': 0,
                    'iterations': total_iterations
                }

**Edge Cases and Pitfalls:**
*   **Noise:** Noise in volume data significantly reduces efficiency by causing false positives along the ray direction, forcing the examination of unnecessary leaf nodes [S2, unofficial].
*   **Precision:** Precision errors can cause rays to miss or hit incorrectly [S2, unofficial].
*   **Boundary Conditions:** Out of bounds checks are required at each level [S1, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Best-case time complexity per voxel:** $O(\log s)$, where $s$ is the initial size of the Octree (side length of the volume) [S2, unofficial].
*   **Worst-case time complexity:** $O(s \cdot \log s)$ [S2, unofficial]. This occurs when every 32x32x32 leaf node along the diagonal (through the volume center) must be examined [S2, unofficial].
*   The number of leaf nodes to examine along the diagonal is calculated as: $tcountNodes = \frac{s}{64} \cdot 3 \cdot \left(\frac{s}{32}\right)^2$ (based on the Pythagorean theorem) [S2, unofficial].
*   Total steps for worst-case traversal: $tTotalCount = tcountNodes \cdot \log s + 3 \cdot 32^2$ [S2, unofficial].
*   **Memory:** Memory usage is lower than using the smallest octree nodes because the leaf size is fixed, but larger leaf sizes increase the probability of false positives [S2, unofficial].

**Measured Performance:**
*   Warp divergence is minimal because similar rays produce similar results within a warp [S2, unofficial].
*   Divergence is further mitigated because the number of iterations is relatively low for noise-free voxel data [S2, unofficial].

**Strengths and Limitations:**
*   **Strengths:** Efficient for sparse data due to fixed leaf size; reduced memory overhead; minimal warp divergence [S2, unofficial].
*   **Limitations:** Sensitive to noise; false positives can degrade performance; trade-off between leaf size and false positive rate [S2, unofficial].

**When to Use:**
*   Use when data is sparse and noise levels are low [S2, unofficial].
*   Use when memory efficiency is a priority [S2, unofficial].

**When Not to Use:**
*   Avoid when data is dense and noisy, as false positives will dominate traversal cost [S2, unofficial].
*   Avoid when exact leaf-level precision is required without post-processing [S2, unofficial].

## Background
This method is described in the context of raycasting-based voxel rendering, specifically in a thesis on recursive-free octree traversal [S2, unofficial]. It is also implemented in a WebGPU voxel raymarching project [S1, unofficial]. The approach leverages the Pythagorean theorem to estimate the number of leaf nodes along the diagonal for complexity analysis [S2, unofficial].
