# Voxel Child Address Calculation

Also called: Voxel address_of

## Overview
Calculates the linear index (address) of a specific child octant within a compact block of valid children, based on a validity bitmask. It solves the problem of mapping a logical octant index (0–7) to its physical position in a dense array that only stores active children. It differs from [Point Location](2076-point-location.md) by operating on a single node's children rather than traversing the tree, and from [Fast Projection for Octree Nodes](2178-fast-projection-for-octree-nodes.md) by focusing on index compression rather than geometric culling.

## How it works
**Inputs:**
- `valid`: A bitmask where bit $i$ is 1 if child $i$ is active, 0 otherwise.
- `octant`: The target child index (0–7).

**Outputs:**
- `address`: The 0-based index of the target child within the compact array of valid children.

**Data Structures:**
- `valid`: Integer type (e.g., `uint8_t`), 8 bits.

**Steps:**
1. Create a mask that isolates all bits lower than the target `octant`:
   $$ \text{mask} = \sim(0xFF \ll \text{octant}) $$
   Note: This assumes 8-bit unsigned arithmetic where `~` inverts all 8 bits. In wider types, ensure the shift and inversion are masked to 8 bits if necessary.
2. Compute the bitwise AND of `valid` and `mask` to isolate valid children preceding the target.
3. Count the number of set bits (population count) in the result.
   $$ \text{address} = \text{popcount}(\text{valid} \ \& \ \text{mask}) $$

**Parameters:**
- `octant`: Integer, 0–7.

**Edge Cases and Pitfalls:**
- The calculation assumes children are stored in order of their octant index.
- If `octant` is not valid (bit is 0 in `valid`), the result is the index where it *would* be if it were valid, or potentially an invalid index if the caller does not check validity first.
- Precision issues are minimal as this is integer arithmetic.
- Bitwise operations must be performed on unsigned types to avoid sign extension issues.

**Pseudocode:**
```python
def voxel_child_address(valid: int, octant: int) -> int:
    """
    Calculate the address of a child octant in a compact valid block.
    
    Args:
        valid: Bitmask of valid children (8 bits).
        octant: Target child index (0-7).
        
    Returns:
        The linear index of the child in the compact array.
    """
    # Create mask: isolate bits lower than octant
    # ~0xFF is -256 in two's complement, shifting left by octant
    # We need to ensure we only look at 8 bits
    mask = (~0xFF << octant) & 0xFF
    
    # Count valid children preceding the target
    return bin(valid & mask).count('1')
```

## Subtopics

### Prefix Rank for Compact Child Indexing
Counts the number of active children (bits set to 1) in a bitmask that precede a given `child_index`. Used to map a child index to a compact payload index in sparse octrees. It is a generalization of Voxel Child Address Calculation for wider nodes (e.g., 64-way). [S2, unofficial]
- **Definition:** Maps a logical child index to its rank among valid children.
- **Steps:** If `child_index <= 0`, return 0. Create `lower_mask = (1 << child_index) - 1`. Return `popcount(mask & lower_mask)`.
- **Parameters:** `mask`: Bitmask representing occupied children. `child_index`: Target child index (0–63 for wide nodes).
- **Pseudocode:**
```python
def prefix_rank(mask: int, child_index: int) -> int:
    if child_index <= 0:
        return 0
    lower_mask = (1 << child_index) - 1
    return bin(mask & lower_mask).count('1')
```

## Operating characteristics
- **Time Complexity:** $O(1)$ assuming fixed-width integers and hardware popcount.
- **Memory Complexity:** $O(1)$.
- **Strengths:** Extremely fast, branchless (if popcount is hardware-supported), essential for compact memory layouts.
- **Limitations:** Only works for direct child indexing within a single node. Does not handle tree traversal.
- **When to use:** When storing children in a compact array and needing to find the index of a specific child.
- **When not to use:** When traversing the tree or locating a node in the tree structure.

## Background
Originated in implementations of sparse voxel octrees for efficient memory storage and ray traversal. Popularized by libraries like [zazen](https://github.com/gabrielmuller/zazen) and [sparse-voxels](https://github.com/hectorpiteau/sparse-voxels) for GPU-based volume rendering.
