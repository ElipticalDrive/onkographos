# Recursive Octree Traversal

Also called: BuildOctree, ConstructOctreeNodes, ContourCellProc, Octree Construction & Traversal, Recursive Octree Rendering

## Overview
Recursive Octree Traversal is a depth-first algorithm for processing a 3D sparse voxel octree by visiting every node in the tree structure. It serves as the foundational traversal logic for both volume rendering (rendering active leaf nodes as cubes) and isosurface extraction (generating vertex buffers via contouring) [S1, S2, S3, S4, unofficial]. It differs from its siblings by explicitly using the call stack to manage recursion depth, whereas [Iterative Octree Traversal](2618-iterative-octree-traversal.md) uses an explicit stack, and [Parametric Octree Traversal](2361-parametric-octree-traversal.md) uses parametric ray-marching logic. It builds on [CPU Sparse Voxel Octree Traversal](2455-cpu-sparse-voxel-octree-traversal.md) by replacing the stack-based state machine with direct recursive function calls [S1, S3, unofficial].

## How it works
The method consists of two primary phases: tree construction (optional, depending on the source) and recursive traversal. The traversal visits nodes to either render them as geometry or process them for mesh generation.

### Inputs and Outputs
*   **Input:** A root octree node pointer, current depth (initially 0), and optional parameters such as `stop_at_lvl` (maximum depth to traverse) or `currentDepth` (depth threshold for rendering) [S1, S3, S4, unofficial].
*   **Output:**
    *   For rendering: OpenGL immediate mode draw calls or a vertex buffer [S2, S4, unofficial].
    *   For contouring: An index buffer containing triangle indices for the isosurface [S1, S2, unofficial].
    *   For construction: A constructed octree root node [S1, unofficial].

### Data Structures
*   **OctreeNode:** Contains `min` (3D offset), `size` (voxel dimension), `type` (Node_Internal or Node_Leaf), and an array of 8 child pointers [S1, S4, unofficial].
*   **Vertex Struct (for contouring):** Contains `glm::vec3 position`, `glm::vec3 color`, `glm::vec3 normal`, and 1 float of padding, totaling 40 bytes and aligned [S2, unofficial].
*   **Child Offsets:** `CHILD_MIN_OFFSETS` defines the 8 relative offsets for children (typically binary combinations of -1/0 or 0/1 depending on coordinate system) [S1, unofficial].

### Steps

#### 1. Construction (if applicable)
If the tree is not pre-built, `ConstructOctreeNodes` is called on the root [S1, unofficial]:
1.  If `size == 1`, call `ConstructLeaf(node)` to evaluate voxel density/material and return [S1, unofficial].
2.  Else, create 8 children with `size/2`.
3.  For each child `i` (0 to 7), set `min` offset by `CHILD_MIN_OFFSETS[i] * childSize` [S1, unofficial].
4.  Recursively call `ConstructOctreeNodes` on each child [S1, unofficial].
5.  If no children were created (all empty), delete the node and return `nullptr` [S1, unofficial].
6.  Return the node [S1, unofficial].

#### 2. Recursive Traversal
The core traversal function `traverse_r` (or similar) processes the tree [S3, unofficial]:

1.  **Base Case / Null Check:** If the current node is `NULL`, return [S1, S3, unofficial].
2.  **Leaf/Stop Condition:** If the node is a leaf OR the current `depth` equals `stop_at_lvl` (or `currentDepth` for rendering), invoke the leaf callback `on_leaf(morton, node_idx)` or render the node [S3, S4, unofficial].
    *   *Rendering Detail:* If rendering, check if `node->isLeaf && node->isActive` or `depth >= currentDepth` [S4, unofficial]. Draw 6 faces (Front, Back, Top, Bottom, Right, Left) with vertices in range [-1, 1] and appropriate normals [S4, unofficial]. Pop matrix and return [S4, unofficial].
3.  **Recursive Step:** If not a leaf and not at stop depth:
    *   Iterate `i` from 0 to 7 [S2, S3, S4, unofficial].
    *   Calculate Morton code: `parent_morton | (i << (3 * (depth - 1)))` [S3, unofficial].
    *   Read child at index `offset + i` [S3, unofficial].
    *   If child exists (is not null), recursively call `traverse_r` (or `GenerateVertexIndices`) with the child address and `depth + 1` [S2, S3, S4, unofficial].

#### 3. Contour Processing (Variant)
For isosurface extraction, `ContourCellProc` handles boundary resolution [S1, unofficial]:
1.  If `node == NULL`, return [S1, unofficial].
2.  If `node->type == Node_Internal`, recursively process 8 children [S1, unofficial].
3.  Process 12 faces using `cellProcFaceMask` and `ContourFaceProc` [S1, unofficial].
    *   Face pairs are defined as `{1,0}, {3,2}, {5,4}, {7,6}` for X, `{2,0}, {6,4}, {3,1}, {7,5}` for Y, etc. [S2, unofficial].
4.  Process 6 edges using `cellProcEdgeMask` and `ContourEdgeProc` [S1, unofficial].
    *   Edge pairs are defined for XY, XZ, and YZ planes [S2, unofficial].
5.  If all 4 nodes of an edge are leaves, call `ContourProcessEdge` [S1, unofficial].

### Pseudocode

```python
def traverse_r(node, depth, stop_at_lvl, on_leaf):
    """
    Recursive traversal of an octree.
    node: OctreeNode or None
    depth: Current depth level (0 for root)
    stop_at_lvl: Depth at which to stop recursion and invoke on_leaf
    on_leaf: Callback function(morton_code, node_index)
    """
    if node is None:
        return

    # Check if we should process this node as a leaf/stop node
    is_leaf = (node.type == Node_Leaf)
    is_stop_depth = (depth >= stop_at_lvl)

    if is_leaf or is_stop_depth:
        # Calculate Morton code if needed for the callback
        # morton_code = ... (calculated from parent path)
        on_leaf(node.morton_code, node.index)
        return

    # Recursive step: visit all 8 children
    child_size = node.size / 2
    for i in range(8):
        # Calculate child offset based on binary index i
        # CHILD_MIN_OFFSETS[i] is a vec3 with components -1 or 0 (or 0/1)
        child_min = node.min + (CHILD_MIN_OFFSETS[i] * child_size)
        
        # Access child pointer
        child = node.children[i]
        
        if child is not None:
            # Recurse
            traverse_r(child, depth + 1, stop_at_lvl, on_leaf)

def construct_octree_node(min_pos, size, density_func):
    """
    Constructs an octree node recursively.
    """
    if size == 1:
        return construct_leaf(min_pos, density_func)
    
    child_size = size / 2
    children = [None] * 8
    
    for i in range(8):
        child_min = min_pos + (CHILD_MIN_OFFSETS[i] * child_size)
        child = construct_octree_node(child_min, child_size, density_func)
        if child is not None:
            children[i] = child
            
    # If no children were created, this node is empty
    if all(c is None for c in children):
        return None
        
    return OctreeNode(min=min_pos, size=size, type=Node_Internal, children=children)

def construct_leaf(min_pos, density_func):
    """
    Evaluates a leaf voxel. Returns None if empty/full, else a leaf node.
    """
    corners = 0
    for i in range(8):
        corner_pos = min_pos + CHILD_MIN_OFFSETS[i]
        density = density_func(corner_pos)
        material = MATERIAL_SOLID if density < 0.0 else MATERIAL_AIR
        corners |= (material << i)
        
    # If all corners are same material, voxel is uniform
    if corners == 0 or corners == 255:
        return None
        
    # Voxel contains surface, create leaf with contour data
    return OctreeNode(min=min_pos, size=1, type=Node_Leaf, corners=corners)
```

### Parameters and Edge Cases
*   **Stop Level:** `stop_at_lvl` prevents infinite recursion in deep trees and controls mesh resolution [S3, unofficial].
*   **Empty Nodes:** Nodes with no active children are pruned during construction or skipped during traversal [S1, S3, unofficial].
*   **Precision:** Floating-point density calculations in `ConstructLeaf` may suffer from precision issues near the isosurface threshold [S1, unofficial].
*   **Recursion Depth:** Deep trees may cause stack overflow on systems with limited stack size [G].

Uses an explicit stack instead of recursion. Choose when stack depth limits are a concern or for integration into languages without deep recursion support.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of nodes in the octree, as every node is visited once [S1, S3, unofficial].
*   **Memory Complexity:** $O(D)$ where $D$ is the maximum depth of the tree, due to the recursion stack [G].
*   **Performance:** Fast for sparse data where empty branches are pruned [S1, unofficial]. Slower than iterative methods if stack overflow is a risk [G].
*   **Strengths:** Simple implementation, natural fit for hierarchical data, easy to parallelize at leaf nodes [G].
*   **Limitations:** Stack overflow on very deep trees, not cache-friendly compared to linearized traversal [G].
*   **When to use:** Small to medium depth trees, prototyping, or when recursion is preferred for clarity [S1, S3, unofficial].
*   **When not to use:** Extremely deep trees, embedded systems with small stacks, or when maximum performance is critical (consider iterative or GPU-based methods) [G].

## Background
Recursive octree traversal is a fundamental algorithm in computer graphics, originating from early 3D modeling and ray-tracing systems. It is widely used in voxel-based editors, Marching Cubes implementations, and sparse voxel octree renderers. The specific implementations cited here are from modern open-source projects demonstrating voxelization and contouring techniques [S1, S2, S3, S4, unofficial].
