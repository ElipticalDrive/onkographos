# Compact Voxel Octree Raycasting

Also called: Compact Octree Traversal, SVO Workbench Raycasting, Sparse Ray-Octree Intersection

## Overview
Compact Voxel Octree Raycasting is a CPU-based ray traversal algorithm for Sparse Voxel Octrees (SVO) that optimizes memory layout and traversal logic by compacting active ray-voxel interactions and decoding node masks on-the-fly [S2, unofficial]. It solves the problem of inefficient traversal in sparse structures by using an explicit stack to manage non-sequential memory layouts and a parallel "COMPACTIFY" step to filter out non-intersecting rays, ensuring that only valid ray-voxel pairs are processed in subsequent levels [S1][S2, unofficial]. Unlike recursive or parametric approaches, it relies on a linear block structure with explicit state management, making it suitable for high-performance CPU implementations where memory bandwidth and cache locality are critical [S2, unofficial].

## How it works
The method traverses a compacted voxel octree using an explicit stack to handle non-sequential memory layouts. It decodes node masks on-the-fly to determine traversal order and leaf status, utilizing a parallel reduction step to compact the list of active rays between octree levels.

### Inputs and Outputs
*   **Input:** A ray $r = (o, d)$, where $o$ is the origin and $d$ is the direction; a Sparse Voxel Octree $ot$; a framebuffer $fb$ for output; and a parameter $terminLevel$ defining the maximum traversal depth.
*   **Output:** A rendered pixel value in $fb$ at the corresponding screen coordinate, or a boolean indicating if a leaf was hit.

### Data Structures

**CNode (8 bytes, packed)**
The node structure stores metadata for children. It is a union of two layouts:
1.  **Standard Layout:**
    *   `valid_mask` (UInt8): Bit $i$ is 1 if child $i$ exists.
    *   `leaf_mask` (UInt8): Bit $i$ is 1 if child $i$ is a leaf node.
    *   `child_ptr` (UInt16): Relative offset to the first child or a far-pointer indicator.
2.  **Far Pointer Layout:**
    *   `far_ptr` (UInt32): Used if `child_ptr` indicates a far pointer. Contains the actual offset to the child data.

**Stack Item (`stack_item_t`)**
Stores the traversal state for backtracking:
*   `tx0, ty0, tz0` (tnum): Entry t-values for the current node bounds.
*   `tx1, ty1, tz1` (tnum): Exit t-values for the current node bounds.
*   `node_adr` (pointer/integer): Absolute address of the current node.
*   `idx` (integer): Current child index.

**Traversal State Variables**
*   `si`: Stack index (current top).
*   `sl`: Stack level (current depth).
*   `level`: Current octree depth.
*   `is_first_node`: Boolean flag indicating if the current node is the first visited at this level.
*   `t_start`: Initial entry t-value for the ray.

### Parameters
*   `terminLevel`: Integer. Maximum depth of the octree. Traversal stops here even if the node is not a leaf in the mask sense. Default: 10 [S2, unofficial].
*   `STACK_SIZE`: Integer. Maximum size of the traversal stack. Asserted against `si` before push [S2, unofficial].
*   `stack_level_max`: Integer. Maximum depth of the stack. `si` is only incremented if `sl < stack_level_max` [S2, unofficial].
*   `tnum_scale`: Fixed-point scaling factor (e.g., $2^{16}$) for t-values [S2, unofficial].

### Algorithm Steps

1.  **Ray Normalization and Initialization:**
    *   Handle negative ray directions by flipping the origin and direction, setting a `dir_mask` to track flips for index correction later.
    *   Handle zero components in the direction vector by adding a small epsilon ($10^{-10}$) to avoid division by zero [S2, unofficial].
    *   Calculate initial t-values ($tx0, ty0, tz0$ for entry, $tx1, ty1, tz1$ for exit) for the ray against the root bounding box.
    *   Initialize `t_start` to $\min(\min(tx1, ty1), tz1)$ if stack underflow occurs or on initial entry [S2, unofficial].

2.  **Traversal Loop:**
    *   Loop while the stack is not empty or the initial node is being processed.
    *   **Node Entry:**
        *   If `is_first_node` is true:
            *   Get the current `BlockEntry` using `node_adr`.
            *   Decode the node masks using `child_decode` (see below) to populate `c_valid`, `c_leaf`, and `c_offset` arrays.
            *   Determine the first child node index `i` using `first_node(tx0, ty0, tz0, txm, tym, tzm)` [S2, unofficial].
            *   Set `is_first_node = false`.
        *   Otherwise, determine the next child node index using `new_node(tx1, ty1, tz1, node_index)` [S2, unofficial].
    *   **Index Flipping:**
        *   Apply `dir_mask` to the calculated child index `idx` to correct for ray direction flips. Let `idx_flip` be the corrected index.
    *   **Exit Check:**
        *   If `exit_node` is true:
            *   If `level == 0`, the ray has exited the octree; return false.
            *   If `stack_underflow` (stack empty), reset `t_start` to `t_exit` and restart from initialization (treat as new ray entry) [S2, unofficial].
            *   Otherwise, pop the stack: decrement `level`, `si`, `sl`; restore `tx0..tz1`, `idx`, `node_adr` from `stack[si]`; get `BlockEntry`; decode child masks.
    *   **Leaf Hit Check:**
        *   If `c_leaf[idx_flip]` is true OR `level == terminLevel`:
            *   Call `procLeaf(r, t_enter_child, size)` to render the pixel.
            *   Return true.
    *   **Valid Child Check:**
        *   If `c_valid[idx_flip]` is true:
            *   Push current state to stack: create `stack_item_t` with current `tx0..tz1`, `node_adr`, `idx`. Assert `si < STACK_SIZE`.
            *   Increment `si`. If `sl < stack_level_max`, increment `sl`.
            *   Increment `level`.
            *   Update `tx0..tz1` to the child's bounds.
            *   Get the child `BlockEntry` using `ot->getRelativeEntry(node_adr, n->child_ptr)`.
            *   Update `node_adr` to `child_bep.adr + c_offset[idx_flip]`.
            *   Decode the new node's masks.

3.  **COMPACTIFY Step (Parallel Reduction):**
    *   After processing a level, if multiple rays are active, a parallel COMPACTIFY step may be invoked to remove non-intersecting rays and compact the list $N(l)$ into $N(l+1)$ [S1].
    *   For all $t \in \{0, \dots, |N(l)|-1\}$ in parallel:
        *   If $D_t = 1$ (ray $t$ hit a voxel):
            *   $k \leftarrow S_t$ (where $S_t$ is the result of an exclusive sum of hit flags).
            *   $N(l+1)_k \leftarrow N(l)_t$.
    *   This step ensures that only valid ray-voxel pairs are carried forward, reducing memory bandwidth and processing load for deeper levels [S1].

### Helper Functions

**`child_decode(Node *n, bool *c_leaf, bool *c_valid, int *c_offset)`**
```python
def child_decode(n, c_leaf, c_valid, c_offset):
    c = 0
    for i in range(8):
        valid = (n.valid_mask >> i) & 1
        leaf = (n.leaf_mask >> i) & 1
        c_valid[i] = valid
        c_leaf[i] = leaf
        if valid and not leaf:
            c_offset[i] = c
            c += 1
```

**`first_node(tx0, ty0, tz0, txm, tym, tzm)`**
Determines the first octant to visit based on the ray entry plane.
```python
def first_node(tx0, ty0, tz0, txm, tym, tzm):
    t_enter = max(tx0, max(ty0, tz0))
    i = 0
    if tzm < t_enter:
        i ^= 1
    if tym < t_enter:
        i ^= 2
    if txm < t_enter:
        i ^= 4
    return i
```

**`new_node(tx1, ty1, tz1, node_index)`**
Determines the next child node based on exit bounds and a specific traversal heuristic.
```python
def new_node(tx1, ty1, tz1, node_index):
    if tx1 < ty1 and tx1 < tz1:
        if node_index & 0b100:
            return 8
        return node_index ^ 0b100
    elif ty1 < tz1:
        if node_index & 0b010:
            return 8
        return node_index ^ 0b010
    else:
        if node_index & 0b001:
            return 8
        return node_index ^ 0b001
```

**`procLeaf(r, tmin, size)`**
Renders the pixel for a leaf hit.
```python
def procLeaf(r, tmin, size):
    # Example implementation from source: color based on tmin
    red = (tmin >> 8) % 256
    blu = 0
    fb.drawPixel(cur_x, cur_y, Pixel(red/256, 0, blu/256))
```

### Edge Cases and Pitfalls
*   **Far Pointers:** If `child_ptr` has bit 15 set (`child_ptr & (1<<15)`), the actual child pointer is stored in a separate 'far' entry at relative offset `child_ptr` from the current address. The far entry's `far_ptr` field contains the actual offset [S2, unofficial].
*   **Stack Underflow:** If the stack is empty and an exit is requested, the algorithm resets `t_start` to `t_exit` and restarts from initialization, effectively treating the ray as if it just entered the octree bounds [S2, unofficial].
*   **Ray Direction Zeroes:** Zero components in the ray direction must be handled by adding a small epsilon to avoid division by zero during t-value calculations [S2, unofficial].
*   **Precision:** T-values are stored in fixed-point format (`tnum`). Clipping is applied to prevent overflow (`tnum_max` and `tnum_min`) [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of rays, but optimized by the COMPACTIFY step which reduces the number of active rays as they traverse deeper into the octree. The traversal itself is proportional to the number of visited nodes.
*   **Memory Complexity:** $O(D)$ for the stack, where $D$ is the maximum depth of the octree. The COMPACTIFY step requires temporary storage for the active ray list.
*   **Performance:** The method is designed for CPU implementation, leveraging explicit stack management and parallel reduction for COMPACTIFY. It is efficient for sparse scenes where many rays do not intersect the octree.
*   **Strengths:** Explicit stack allows for non-recursive traversal, avoiding stack overflow issues. COMPACTIFY reduces memory bandwidth and processing load. On-the-fly mask decoding minimizes memory accesses.
*   **Limitations:** The heuristic for `new_node` may not be optimal for all ray directions. The fixed-point arithmetic may introduce precision errors for very large or very small scenes.
*   **When to use:** Suitable for CPU-based ray tracing of sparse voxel octrees where memory efficiency and explicit control over traversal are required.
*   **When not to use:** Not suitable for GPU implementations where recursive or parametric methods might be more natural. Not ideal for dense scenes where the overhead of stack management and COMPACTIFY may outweigh the benefits.

## Background
Compact Voxel Octree Raycasting is associated with the SVO Workbench project [S2, unofficial]. The COMPACTIFY technique, which is integral to this method, is described in the context of Neural Geometric Level of Detail (NGLOD) for real-time rendering with implicit 3D shapes [S1]. The SVO Workbench provides an implementation of this traversal algorithm for CPU-based ray tracing [S2, unofficial].
