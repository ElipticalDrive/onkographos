# Regular Grid

Also called: Grilles régulières, Regular Grid Spatial Subdivision

## Overview
A Regular Grid is a spatial acceleration structure that divides a scene's Axis-Aligned Bounding Box (AABB) into a fixed-size, uniform 3D grid of cells (voxels) [S1, S2, unofficial]. It accelerates ray tracing by allowing rays to step through empty cells without performing primitive intersection tests, reducing the number of expensive geometric queries [S1, S2, unofficial]. Unlike hierarchical structures like BVH or KD-trees, the Regular Grid partitions *space* into disjoint sub-blocks, meaning primitives can belong to multiple cells, whereas BVH partitions *primitives* into disjoint sets [S2, S3, unofficial]. It is particularly effective on GPUs for scenes with uniform data distribution due to high spatial locality and cache efficiency [S3, unofficial].

## How it works

### Inputs and Outputs
*   **Input:** A set of scene primitives, each with an associated AABB; the global scene bounding box defined by minimum corner $p_1$ and maximum corner $p_2$; and a grid resolution parameter $N$ (GRIDSIZE).
*   **Output:** A 1D array representing the grid, enabling efficient ray traversal and primitive intersection testing.

### Data Structures
The grid is stored as a 1D array `m_Grid` of size $N^3$ [S1, unofficial].
*   **Indexing:** A cell at integer coordinates $(x, y, z)$ is accessed via index:
    $$ idx = x + y \cdot N + z \cdot N^2 $$
*   **Cell Content:** Each entry in `m_Grid` is a pointer to an `ObjectList` [S1, unofficial].
*   **ObjectList:** A linked list structure where each node contains:
    *   A pointer to a primitive.
    *   A pointer to the next `ObjectList` node.
    *   (Optional implementation detail) A flag or ID to track if a primitive has already been tested by the current ray to avoid redundant calculations [S1, S2, unofficial].

### Grid Construction
The construction phase maps primitives to the cells they intersect. This mapping must be **conservative**: it may include more primitives than strictly necessary but must never exclude a primitive that intersects a cell [S2, unofficial].

1.  **Initialize Grid:** Allocate `m_Grid` of size $N^3$ and set all pointers to `NULL` [S1, unofficial].
2.  **Define Bounds:** Set the scene bounds $p_1$ (min) and $p_2$ (max) [S1, unofficial].
3.  **Calculate Cell Dimensions:** Compute the width, height, and depth of a single cell, and their reciprocals for fast coordinate conversion:
    $$ dx = \frac{p_{2x} - p_{1x}}{N}, \quad dx_{reci} = \frac{1}{dx} $$
    $$ dy = \frac{p_{2y} - p_{1y}}{N}, \quad dy_{reci} = \frac{1}{dy} $$
    $$ dz = \frac{p_{2z} - p_{1z}}{N}, \quad dz_{reci} = \frac{1}{dz} $$
4.  **Map Primitives:** For each primitive $p$:
    a. Retrieve its AABB bounds: $bv_1$ (min corner) and $bv_2$ (max corner) [S1, unofficial].
    b. Calculate the grid cell coordinates $(x_1, y_1, z_1)$ containing $bv_1$ and $(x_2, y_2, z_2)$ containing $bv_2$:
       $$ x_1 = \lfloor (bv_{1x} - p_{1x}) \cdot dx_{reci} \rfloor, \quad x_2 = \lfloor (bv_{2x} - p_{1x}) \cdot dx_{reci} \rfloor + 1 $$
       $$ y_1 = \lfloor (bv_{1y} - p_{1y}) \cdot dy_{reci} \rfloor, \quad y_2 = \lfloor (bv_{2y} - p_{1y}) \cdot dy_{reci} \rfloor + 1 $$
       $$ z_1 = \lfloor (bv_{1z} - p_{1z}) \cdot dz_{reci} \rfloor, \quad z_2 = \lfloor (bv_{2z} - p_{1z}) \cdot dz_{reci} \rfloor + 1 $$
    c. **Clamp Coordinates:** Clamp $x_1, y_1, z_1$ to a minimum of 0, and $x_2, y_2, z_2$ to a maximum of $N-1$ to handle primitives outside or on the boundary of the grid [S1, unofficial].
    d. **Iterate Candidate Cells:** Loop over $x$ from $x_1$ to $x_2-1$, $y$ from $y_1$ to $y_2-1$, and $z$ from $z_1$ to $z_2-1$:
       i. Calculate cell index $idx = x + y \cdot N + z \cdot N^2$.
       ii. Construct the AABB for the current cell:
           $$ cell\_min = p_1 + (x \cdot dx, y \cdot dy, z \cdot dz) $$
           $$ cell\_max = cell\_min + (dx, dy, dz) $$
       iii. If the primitive's AABB intersects the cell's AABB, add the primitive to the `ObjectList` at `m_Grid[idx]` [S1, unofficial].

### Ray Traversal (3D DDA)
Traversal uses a 3D Digital Differential Analyzer (3D-DDA) algorithm to step through cells [S1, S2, unofficial].

#### Setup
1.  **Determine Start Cell:** Find the initial cell $(X, Y, Z)$ containing the ray origin. If the origin is outside the grid, advance the ray to the first intersection with the grid's bounding box. If the ray misses the grid entirely, terminate [S1, unofficial].
2.  **Calculate Step Distances:** Compute the distance along the ray to cross one full cell in each axis ($tDelta$):
    $$ tDeltaX = \frac{dx}{|ray\_dir_x|}, \quad tDeltaY = \frac{dy}{|ray\_dir_y|}, \quad tDeltaZ = \frac{dz}{|ray\_dir_z|} $$
3.  **Calculate Initial Boundary Distances:** Compute the distance to the first cell boundary in each axis ($tMax$) from the ray origin (or the entry point into the grid) [S1, unofficial]:
    $$ tMaxX = \frac{(X + 0.5) \cdot dx - ray\_origin_x}{ray\_dir_x} \quad \text{(adjusted for sign)} $$
    *Note: Standard implementation calculates the distance to the next grid plane. If $ray\_dir_x > 0$, the next boundary is at $X+1$; if $ray\_dir_x < 0$, it is at $X$.*
    $$ tMaxX = \frac{(X + (ray\_dir_x > 0 ? 1 : 0)) \cdot dx - ray\_origin_x}{ray\_dir_x} $$
    $$ tMaxY = \frac{(Y + (ray\_dir_y > 0 ? 1 : 0)) \cdot dy - ray\_origin_y}{ray\_dir_y} $$
    $$ tMaxZ = \frac{(Z + (ray\_dir_z > 0 ? 1 : 0)) \cdot dz - ray\_origin_z}{ray\_dir_z} $$
4.  **Determine Steps:** Set step directions $stepX, stepY, stepZ$ to $1$ if the corresponding ray direction component is positive, and $-1$ otherwise [S1, unofficial].

#### Loop
Repeat until the ray exits the grid or a hit is found:
1.  **Process Current Cell:**
    a. Check if `m_Grid[X + Y*N + Z*N*N]` is `NULL`. If not, iterate through the `ObjectList`.
    b. For each primitive in the list, perform an intersection test.
    c. **Handling Out-of-Cell Intersections:** If an intersection is found, check if the intersection point lies within the current cell's bounds.
       *   If the intersection point is **outside** the current cell (e.g., the primitive spans multiple cells), advance the ray to the next cell(s) and continue testing. Do not return this hit yet, as a closer hit might exist in subsequent cells [S1, unofficial].
       *   To avoid redundant tests, mark primitives that have already been tested by the current ray (e.g., using a unique ray ID stored in the primitive) [S1, S2, unofficial].
    d. If the intersection point is **inside** the current cell, return the hit [S1, unofficial].
2.  **Advance Ray:** Compare $tMaxX, tMaxY, tMaxZ$. Advance the ray to the nearest cell boundary:
    *   If $tMaxX < tMaxY$ and $tMaxX < tMaxZ$:
        $$ tMaxX += tDeltaX $$
        $$ X += stepX $$
    *   Else if $tMaxY < tMaxZ$:
        $$ tMaxY += tDeltaY $$
        $$ Y += stepY $$
    *   Else:
        $$ tMaxZ += tDeltaZ $$
        $$ Z += stepZ $$
3.  **Boundary Check:** If any coordinate $(X, Y, Z)$ goes out of bounds $[0, N-1]$, terminate the ray [S2, unofficial].

### Pseudocode

```python
def build_regular_grid(primitives, p1, p2, N):
    # Initialize grid
    grid_size = N * N * N
    grid = [None] * grid_size
    
    # Calculate cell dimensions and reciprocals
    dx = (p2.x - p1.x) / N
    dy = (p2.y - p1.y) / N
    dz = (p2.z - p1.z) / N
    dx_reci = 1.0 / dx
    dy_reci = 1.0 / dy
    dz_reci = 1.0 / dz
    
    # Map primitives to cells
    for primitive in primitives:
        bound = primitive.get_aabb()
        bv1 = bound.min
        bv2 = bound.max
        
        # Calculate cell range
        x1 = int((bv1.x - p1.x) * dx_reci)
        x2 = int((bv2.x - p1.x) * dx_reci) + 1
        y1 = int((bv1.y - p1.y) * dy_reci)
        y2 = int((bv2.y - p1.y) * dy_reci) + 1
        z1 = int((bv1.z - p1.z) * dz_reci)
        z2 = int((bv2.z - p1.z) * dz_reci) + 1
        
        # Clamp to grid bounds
        x1 = max(0, x1)
        x2 = min(N - 1, x2)
        y1 = max(0, y1)
        y2 = min(N - 1, y2)
        z1 = max(0, z1)
        z2 = min(N - 1, z2)
        
        # Add primitive to intersecting cells
        for x in range(x1, x2 + 1):
            for y in range(y1, y2 + 1):
                for z in range(z1, z2 + 1):
                    idx = x + y * N + z * N * N
                    cell_min = Vector3(p1.x + x * dx, p1.y + y * dy, p1.z + z * dz)
                    cell_max = cell_min + Vector3(dx, dy, dz)
                    
                    if primitive.intersects_aabb(cell_min, cell_max):
                        add_to_list(grid[idx], primitive)
                        
    return grid

def trace_ray(ray, grid, p1, p2, N):
    # Determine start cell
    if ray.origin is outside(grid_bounds):
        t_hit = ray.intersect_aabb(grid_bounds.min, grid_bounds.max)
        if t_hit is None:
            return None
        current_pos = ray.origin + ray.direction * t_hit
    else:
        current_pos = ray.origin
        
    X = int((current_pos.x - p1.x) / ((p2.x - p1.x) / N))
    Y = int((current_pos.y - p1.y) / ((p2.y - p1.y) / N))
    Z = int((current_pos.z - p1.z) / ((p2.z - p1.z) / N))
    
    # Clamp start coordinates
    X = max(0, min(N - 1, X))
    Y = max(0, min(N - 1, Y))
    Z = max(0, min(N - 1, Z))
    
    # Calculate deltas and initial tMax
    dx = (p2.x - p1.x) / N
    dy = (p2.y - p1.y) / N
    dz = (p2.z - p1.z) / N
    
    t_delta_x = dx / abs(ray.direction.x)
    t_delta_y = dy / abs(ray.direction.y)
    t_delta_z = dz / abs(ray.direction.z)
    
    step_x = 1 if ray.direction.x > 0 else -1
    step_y = 1 if ray.direction.y > 0 else -1
    step_z = 1 if ray.direction.z > 0 else -1
    
    # Calculate tMax to first boundary
    # Note: Exact formula depends on whether origin is inside or outside.
    # Assuming origin is at entry point into grid for simplicity of DDA setup.
    # If origin is inside, tMax is distance to next boundary.
    if ray.direction.x > 0:
        t_max_x = (X + 1) * dx - (current_pos.x - p1.x)
    else:
        t_max_x = X * dx - (current_pos.x - p1.x)
        
    if ray.direction.y > 0:
        t_max_y = (Y + 1) * dy - (current_pos.y - p1.y)
    else:
        t_max_y = Y * dy - (current_pos.y - p1.y)
        
    if ray.direction.z > 0:
        t_max_z = (Z + 1) * dz - (current_pos.z - p1.z)
    else:
        t_max_z = Z * dz - (current_pos.z - p1.z)
        
    # Normalize tMax to be relative to ray origin if necessary, 
    # or keep relative to entry point. Here we assume relative to entry.
    # Add entry distance if ray.origin was outside.
    if ray.origin is outside(grid_bounds):
        t_max_x += t_hit
        t_max_y += t_hit
        t_max_z += t_hit
        
    while 0 <= X < N and 0 <= Y < N and 0 <= Z < N:
        idx = X + Y * N + Z * N * N
        cell_list = grid[idx]
        
        if cell_list is not None:
            for primitive in cell_list:
                # Check if primitive already tested by this ray
                if primitive.ray_id == ray.id:
                    continue
                    
                hit = primitive.intersect(ray)
                if hit is not None:
                    # Check if hit is within current cell
                    if hit.point is inside_cell(X, Y, Z, p1, dx, dy, dz):
                        primitive.ray_id = ray.id
                        return hit
                    else:
                        # Hit is outside current cell, continue traversal
                        # Mark as tested to avoid re-testing in next cell
                        primitive.ray_id = ray.id
                        
        # Advance to next cell
        if t_max_x < t_max_y:
            if t_max_x < t_max_z:
                t_max_x += t_delta_x
                X += step_x
            else:
                t_max_z += t_delta_z
                Z += step_z
        else:
            if t_max_y < t_max_z:
                t_max_y += t_delta_y
                Y += step_y
            else:
                t_max_z += t_delta_z
                Z += step_z
                
    return None
```

### Parameters
*   **GRIDSIZE ($N$):** The number of cells along each axis. The total number of cells is $N^3$ [S1, unofficial]. Typical values depend on scene complexity and memory constraints; higher $N$ increases precision but also memory usage and construction time [S1, unofficial].

### Edge Cases and Pitfalls
*   **Intersection Outside Cell:** A primitive stored in cell $F$ may be intersected by a ray while traversing cell $F$, but the intersection point lies outside cell $F$ (e.g., in cell $G$). Testing only the current cell misses this or requires redundant checks. The solution is to continue advancing the ray to subsequent cells until the intersection point is within the current cell or a closer intersection is found [S1, unofficial].
*   **Redundant Tests:** A single triangle may span multiple voxels. To avoid redundant intersection tests, mark primitives that have already been tested by the current ray (e.g., using a unique ray ID) [S1, S2, unofficial].
*   **Dynamic Scenes:** The Regular Grid is not suitable for dynamic scenes if using acceleration methods like Proximity Clouds, as pre-calculating distance information to the nearest full element is too costly [S3, unofficial].
*   **Boundary Handling:** Primitives outside or on the boundary of the grid must be clamped to the grid indices to avoid out-of-bounds access [S1, unofficial].

## Operating characteristics

### Time and Memory Complexity
*   **Memory:** Memory usage is $O(N^3)$, where $N$ is the grid resolution. This is high for sparse scenes because the grid is uniform and cannot adapt to primitive density. Many triangles may cluster in a small area but occupy many empty voxels [S2, unofficial].
*   **Construction:** $O(P \cdot N^3)$ in the naive implementation (checking all primitives for all cells), but optimized to $O(P \cdot k)$ where $k$ is the average number of cells a primitive intersects, by only iterating over candidate cells defined by the primitive's AABB [S1, unofficial].
*   **Traversal:** $O(C)$, where $C$ is the number of cells intersected by the ray. Intersection tests are performed only for primitives in visited cells.

### Measured Performance
*   On GPUs, the Regular Grid is considered optimal for scenes with uniform data distribution due to high probability of cached texture accesses, offering up to 100x faster performance compared to non-optimized structures [S3, unofficial].
*   GPU rasterization can find primary ray intersections by reading pixel colors, but it cannot handle secondary rays (reflections/refractions) effectively and has limits on primitive count and supersampling. The Regular Grid helps accelerate these secondary rays [S1, unofficial].

### Strengths and Limitations
*   **Strengths:** Simple implementation; constant-time access to elements and neighbors; good data locality (successively accessed elements are spatially close in memory); effective for uniform scenes on GPU [S1, S3, unofficial].
*   **Limitations:** High memory usage for sparse scenes; no adaptivity to primitive density; construction can be slow for large numbers of primitives if not optimized; stepping through the grid is not free, especially setup costs [S1, S2, unofficial].

### When to Use
*   Use for scenes with uniform data distribution, especially on GPU where cache locality is critical [S3, unofficial].
*   Use when simplicity of implementation is prioritized over memory efficiency [S2, unofficial].
*   Not suitable for highly sparse or highly dynamic scenes without additional acceleration structures like Proximity Clouds (which are costly for dynamic scenes) [S3, unofficial].

## Background

### Origin and History
The Regular Grid was one of the first spatial acceleration structures used in ray tracing, particularly in early GPU experiments [S3, unofficial]. The traversal algorithm (3D-DDA) is heavily based on the paper by Amanatides & Woo [S1, unofficial]. The structure has been widely used in various forms, including "Grilles régulières" in French literature [S3, unofficial].

### Development
Early implementations checked all primitives for all cells, which was slow. Optimizations involved mapping primitives to cells based on their AABBs, reducing the number of intersection tests during construction [S1, unofficial]. The handling of intersections outside the current cell was addressed by Amanatides & Woo, who proposed advancing the ray to subsequent cells and marking tested primitives to avoid redundancy [S1, unofficial].

### Usage
The Regular Grid is used in various ray tracing applications, particularly where uniform scene distribution allows for efficient caching on GPUs [S3, unofficial]. It serves as a baseline for more complex hierarchical structures like KD-trees and BVHs [S2, unofficial].
