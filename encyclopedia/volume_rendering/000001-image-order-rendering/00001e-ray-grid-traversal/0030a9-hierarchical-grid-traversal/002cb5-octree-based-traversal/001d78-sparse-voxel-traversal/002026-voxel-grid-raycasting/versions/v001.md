# Voxel Grid Raycasting

Also called: DDA Ray Tracing, Ray Marching through Voxel Grid, Regular Grid Traversal, Uniform Grid Raycasting, Voxel Ray Marching, Voxel Ray Tracing with Voxel Marching, Voxelization Raycasting

## Overview
Voxel Grid Raycasting is a rendering technique that stores scene geometry in a 3D voxel grid and traces rays through the grid by stepping from voxel to voxel to determine intersections and surface normals [S1, S2, unofficial]. It solves the problem of efficiently determining ray-voxel intersections without performing explicit geometric intersection tests against primitives [S2, unofficial]. Unlike hierarchical structures like BVH or KD-trees which partition primitives, this method partitions space into a fixed uniform grid, allowing rays to step through empty cells rapidly [S3, unofficial]. It is distinct from [Sparse Voxel Traversal](1525-sparse-voxel-traversal.md) by assuming a dense, regular grid layout rather than a sparse octree or brick-based structure.

## How it works
**Inputs and Outputs:**
- **Input:** Ray origin $O$, ray direction $D$ (normalized), voxel grid dimensions, voxel size (bin size), and the voxel data buffer.
- **Output:** Intersection distance, hit position, surface normal, and optionally accumulated color.

**Data Structures:**
The voxel grid is typically stored as a 1D array or storage buffer.
- **Format 1 (S1):** `array<u32>` where each `u32` represents a single voxel. A value of `0u` indicates an empty voxel; non-zero values indicate occupied voxels, encoding color via `unpack4x8unorm` [S1, unofficial].
- **Format 2 (S2):** `int` array of size $16 \times 16 \times 16$ (4096 elements), bound as a storage buffer [S2, unofficial].
- **Indexing:**
  - For Format 1: $index = x + y \cdot W + z \cdot (W \cdot H)$, where $W$ is chunk width and $H$ is chunk height [S1, unofficial].
  - For Format 2: $index = (x \cdot 16 + z) \cdot 16 + y$ [S2, unofficial].

**Algorithm Steps:**
1. **Initialization:**
   - Normalize ray direction: $ray = \text{normalize}(ray\_end - ray\_start)$ [S2, unofficial].
   - Calculate initial grid position: $grid\_pos = \lfloor (start\_pos - min\_pos) \cdot inv\_voxel\_size \rfloor$ [S1, unofficial].
   - Determine direction indicators: $ray\_dir\_i = \text{sign}(ray\_dir)$ (1 if $>0$, -1 if $\le 0$) [S1, unofficial].
   - Calculate step deltas: $dt = |voxel\_size / ray\_dir|$ [S1, unofficial].
   - Calculate initial time to next boundary $t_{max}$ based on the fractional part of the start position [S1, unofficial].
   - *Edge Case:* If a ray component is 0, set corresponding $t_{max}$ and $dt$ to `FLT_MIN` to avoid division by zero [S2, unofficial].

2. **Traversal Loop:**
   - Find the axis with the minimum $t_{max}$ value: $last\_axis = \text{argmin}(t_{max})$ [S1, unofficial].
   - Increment grid position on that axis: $grid\_pos[last\_axis] += ray\_dir\_i[last\_axis]$ [S1, unofficial].
   - Update distance traveled: $dist = t_{max}[last\_axis]$ [S1, unofficial].
   - Advance $t_{max}$ for the stepped axis: $t_{max}[last\_axis] += dt[last\_axis]$ [S1, unofficial].
   - Check for hit: Load voxel data at $grid\_pos$. If occupied, calculate normal and terminate [S1, unofficial].

3. **Intersection & Normal:**
   - If a hit occurs, the surface normal is derived from the axis of entry: $normal = \text{axis\_dir\_normal}(last\_axis, ray\_dir)$ [S1, unofficial].
   - If $last\_axis$ is the initial state (e.g., 3), retain previous normal or handle as primary hit [S1, unofficial].

4. **Ray Bouncing (Optional):**
   - If stochastic reflection is enabled, spawn a new ray from $start\_pos + dist \cdot ray\_dir + \epsilon \cdot normal$ [S1, unofficial].
   - $\epsilon$ is a small offset (e.g., $voxel\_size \cdot 0.01$) to prevent self-intersection [S1, unofficial].
   - Attenuate color and repeat traversal up to a max depth (e.g., 3 bounces) [S1, unofficial].

**Pseudocode:**
```python
def voxel_grid_raycast(origin, direction, voxel_grid, voxel_size, grid_dims):
    # 1. Initialization
    ray = normalize(direction)
    
    # Handle zero components to avoid division by zero
    inv_ray = 1.0 / ray
    inv_ray[ray == 0] = 0.0
    
    # Initial voxel coordinate
    current_voxel = floor(origin / voxel_size)
    
    # Step direction per axis
    step = vec3(1 if ray.x >= 0 else -1, 
                1 if ray.y >= 0 else -1, 
                1 if ray.z >= 0 else -1)
    
    # Distance to next boundary
    # Boundary position = (current_voxel + step) * voxel_size
    next_boundary = (current_voxel + step) * voxel_size
    
    # tMax: distance along ray to next boundary
    # If ray component is 0, tMax is effectively infinity (handled by FLT_MIN in C-like impls)
    t_max = vec3(
        (next_boundary.x - origin.x) * inv_ray.x if ray.x != 0 else float('inf'),
        (next_boundary.y - origin.y) * inv_ray.y if ray.y != 0 else float('inf'),
        (next_boundary.z - origin.z) * inv_ray.z if ray.z != 0 else float('inf')
    )
    
    # tDelta: distance along ray to traverse one voxel width
    t_delta = vec3(
        voxel_size * inv_ray.x * step.x if ray.x != 0 else float('inf'),
        voxel_size * inv_ray.y * step.y if ray.y != 0 else float('inf'),
        voxel_size * inv_ray.z * step.z if ray.z != 0 else float('inf')
    )
    
    # 2. Traversal Loop
    for i in range(MAX_ITERATIONS):
        # Check bounds
        if not is_inside_grid(current_voxel, grid_dims):
            return MISS
            
        # Check occupancy
        if is_occupied(voxel_grid, current_voxel):
            # Determine normal based on which axis we just crossed
            # The axis with the smallest t_max was the one we just stepped across
            # In this simplified loop, we assume we check occupancy AFTER stepping or 
            # use the t_max comparison to determine entry axis.
            # Standard DDA checks occupancy of the NEW voxel.
            normal = get_normal_from_t_max(t_max, step)
            return HIT(current_voxel, t_max, normal)
            
        # Find axis with minimum t_max
        axis = argmin(t_max)
        
        # Step on that axis
        current_voxel[axis] += step[axis]
        
        # Update t_max for that axis
        t_max[axis] += t_delta[axis]
        
    return MISS
```

## Subtopics

### [Voxel-Cell Duality Mapping](2240-voxel-cell-duality-mapping.md)
A technique for ray tracing isosurfaces defined within cells of 8 voxels using an octree that stores scalar values at voxel centers. It establishes a dual relationship between voxels and cells by logically shifting scalar positions backward by half a voxel width, allowing the ray tracer to intersect 8-voxel cell primitives defined by the stored leaf values. Unlike methods that expand storage to hold complete cell data, this method retrieves forward neighbors at intersection time, maintaining single scalar storage per leaf.

### [Spherical Volume Ray Walking](3865-spherical-volume-ray-walking.md)
A fast voxel traversal algorithm for rendering volumetric data defined on a spherical coordinate grid. It extends the cartesian fast voxel traversal method by Amanatides and Woo to non-cartesian grids, iterating through radial, polar, and azimuthal voxel boundaries to determine the sequence of voxels intersected by a ray. Unlike [Voxel Grid Raycasting](2218-voxel-grid-raycasting.md) which assumes axis-aligned bounding boxes, this method handles the curved boundaries of spherical sectors, using line-sphere intersection for radial steps and 2D segment intersection for angular boundaries.

### [Regular Grid](3950-regular-grid.md)
A spatial acceleration structure that divides a scene's Axis-Aligned Bounding Box (AABB) into a fixed-size, uniform 3D grid of cells (voxels). It accelerates ray tracing by allowing rays to step through empty cells without performing primitive intersection tests, reducing the number of expensive geometric queries. Unlike hierarchical structures like BVH or KD-trees, the Regular Grid partitions *space* into disjoint sub-blocks, meaning primitives can belong to multiple cells, whereas BVH partitions *primitives* into disjoint sets. It is particularly effective on GPUs for scenes with uniform data distribution due to high spatial locality and cache efficiency.

### [Plane Marching](3959-plane-marching.md)
A raymarching technique for voxel grids that advances a ray by stepping to the nearest intersection with the integer grid planes separating voxel layers. It solves the problem of traversing a dense voxel volume to find the first solid voxel by checking occupancy at each plane boundary. Unlike shape-assisted siblings such as [Sphere Assisted Raymarching](3865-sphere-assisted-raymarching.md) or [Optimised Voxel Ray Marching](4240-optimised-voxel-ray-marching.md), it does not store auxiliary distance fields or shape metadata, relying solely on the geometric structure of the grid. This makes it simple to implement but fragile in empty space, as it never skips more than one voxel per step.

### [Voxel-based Ray Tracing for GI and Specular Reflections](4091-voxel-based-ray-tracing-for-gi-and-specular-reflections.md)
A voxel-based ray tracing system using Digital Differential Analyzer (DDA) traversal through a 128³ block-occupancy grid to provide global illumination (GI) and specular reflection fallbacks. It serves as a drop-in replacement for Screen-Space Ray Tracing (SSRT) for GI and a fallback for Screen-Space Reflections (SSR) when coverage is incomplete, combining sky occlusion with Light Propagation Volume (LPV) colour bleeding.

### [Optimised Voxel Ray Marching](4240-optimised-voxel-ray-marching.md)
A fixed-step ray traversal algorithm for voxel-based scenes that minimizes computational overhead by keeping block lookups within the current working chunk. It builds on [Voxel Grid Raycasting](2218-voxel-grid-raycasting.md) by replacing global coordinate arithmetic with bitwise operations for chunk indexing, thereby reducing the number of bitshifts, masks, and multiplication operations required per step.

### [RLE4 Ray Tracing](5228-rle4-ray-tracing.md)
A ray-marching or voxel-intersection algorithm that traverses the RLE4 compressed volume structure (Map4) to find the first occupied voxel along a ray or to colorize a voxel based on its position. It uses the slab-based RLE encoding to skip empty space efficiently.

### Voxel Resolve Search
A search algorithm used by voxel resolve and GI update to find the pixel's voxel again in the brick named by the visibility buffer [S5, unofficial]. It finds the cell holding the ray's point at the stored depth, then the two cells along each axis whose centers lie nearest that point, stopping at the first cell whose hit gives the stored depth again, bit for bit [S5, unofficial]. A voxel's test depends only on the ray and the voxel, ensuring every pass meets it at the same t [S5, unofficial].

### Narrow Band Voxelization
A narrow band strategy that does not use any solver [S6]. When the algorithm reaches a narrow band voxel, it immediately returns a hit, resulting in a voxelization of the scene [S6].

### TLAS Instance Traversal
Manages transformed voxel objects by storing local acceleration structures and applying inverse rotations during ray queries [S7, unofficial]. Rays are transformed into instance local space via inverse rotation (transpose, since the matrix is orthogonal) [S7, unofficial]. The `VoxelInstance` contains a local `BrickPool` (BLAS), rotation matrix, and bounding sphere [S7, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels traversed along the ray. In empty space, this is proportional to the distance divided by voxel size.
- **Memory Complexity:** $O(V)$ where $V$ is the total number of voxels in the grid. The grid must be stored in memory, typically as a 1D array [S1, S2, unofficial].
- **Performance:** Highly efficient on GPUs due to regular memory access patterns and lack of branching in empty space [S3, unofficial]. However, performance degrades in dense scenes or when rays traverse many empty voxels without skipping them (unlike sparse methods).
- **Strengths:** Simple implementation, no preprocessing overhead for hierarchy construction, excellent cache locality on uniform grids [S3, unofficial].
- **Limitations:** Memory usage scales with the cube of the grid resolution, making it unsuitable for very large scenes without sparsity techniques [S3, unofficial]. Precision issues can occur with large coordinates or small voxel sizes [S1, unofficial].

## Background
Voxel Grid Raycasting is a fundamental technique in volume rendering and voxel-based games. It is often associated with the "DDA" (Digital Differential Analyzer) algorithm for grid traversal, originally described by Amanatides and Woo [S2, unofficial]. It has been widely used in real-time applications such as *Teardown* and various GPU-based ray tracing demos [S1, unofficial]. The method is a core component of many voxel engines and is frequently compared to or combined with sparse voxel octrees for larger scale scenes [S1, S2, unofficial].
