# kd-restart algorithm

Also called: CERA-TVR

## Overview
The kd-restart algorithm is a stackless traversal method for kd-trees that eliminates the need for an explicit recursion stack by restarting traversal from the root after each leaf is processed [S2, unofficial]. It trades increased runtime for reduced memory complexity, making it suitable for GPU implementations with limited stack space [S2, unofficial].

## How it works
**Inputs:** ray origin $\mathbf{o}$, direction $\mathbf{d}$, kd-tree root, grid bounds.
**Outputs:** sequence of leaf nodes visited with entry/exit distances.

**Data Structures:** Each internal node stores a split axis $a \in \{x, y, z\}$, split position $s$, and pointers to left and right children. Leaf nodes store references to voxel data or texture bricks.

**Steps:**
1. Initialize $t_{entry} = 0$ (or the ray's near plane). Set current node to root.
2. While current node is not null and the ray remains within grid bounds:
   a. If current node is a leaf, process its data for the interval $[t_{entry}, t_{exit}]$, then reset current node to root and continue.
   b. Determine split axis $a$ and position $s$.
   c. Compute distance to split plane: $t_{split} = \frac{s - o_a}{d_a}$. If $d_a = 0$, treat $t_{split}$ as $\infty$ and use the ray origin position relative to $s$ to choose the child.
   d. If $t_{split} < t_{entry}$, the ray has already passed the split plane; select the far child. Otherwise, select the near child.
   e. Advance to the selected child. Update $t_{entry} \leftarrow \max(t_{entry}, t_{split})$ for the next iteration.
3. Terminate when the ray exits the grid bounds.

**Formulas:**
* Split plane distance: $t_{split} = \frac{s - o_a}{d_a}$ [S3, unofficial].
* Step direction per axis: $\text{step}_i = \text{sign}(d_i)$, with $\text{step}_i = 0$ if $d_i = 0$ [G].
* Distance delta per axis: $\Delta t_i = \frac{v_i}{|d_i|}$, where $v_i$ is voxel size [S2, unofficial][S3, unofficial].

**Parameters:** Typical grid resolutions range from $64^3$ to $1024^3$ voxels; tree depth depends on data distribution [S1].

**Edge Cases and Pitfalls:**
* Ray parallel to split plane ($d_a = 0$): handled by treating $t_{split}$ as infinity and using origin position [G].
* Floating-point precision near split planes: use a small epsilon or robust geometric predicates to avoid oscillation [G].
* Infinite loops: ensure $t_{entry}$ advances or leaf processing resets context correctly; restart logic must not re-enter the same leaf without progress [G].

**Pseudocode:**
```python
def kd_restart_traversal(ray_origin, ray_direction, kd_tree_root, grid_bounds):
    current_node = kd_tree_root
    t_entry = 0.0
    
    while current_node is not None:
        # Check grid bounds
        if not (grid_bounds.min[0] <= current_node.voxel_idx[0] <= grid_bounds.max[0] and
                grid_bounds.min[1] <= current_node.voxel_idx[1] <= grid_bounds.max[1] and
                grid_bounds.min[2] <= current_node.voxel_idx[2] <= grid_bounds.max[2]):
            break
            
        # Leaf handling and restart
        if current_node.is_leaf:
            # Process leaf data for interval [t_entry, t_exit]
            # (Standard volume integration or sampling goes here)
            current_node = kd_tree_root  # Restart from root
            continue
            
        # Split plane check
        split_axis = current_node.split_axis
        split_pos = current_node.split_position
        d_axis = ray_direction[split_axis]
        
        if d_axis == 0.0:
            t_split = float('inf')
        else:
            t_split = (split_pos - ray_origin[split_axis]) / d_axis
            
        # Child selection
        if t_split < t_entry:
            # Ray passed split plane, go to far child
            next_node = current_node.right if ray_origin[split_axis] >= split_pos else current_node.left
        else:
            # Ray enters near child first
            next_node = current_node.left if ray_origin[split_axis] < split_pos else current_node.right
            
        # Advance
        t_entry = max(t_entry, t_split)
        current_node = next_node
```

## Subtopics

### Stackless KD-backtrack traversal
A variant that maintains a "restart point" pointer instead of always returning to the root [S3, unofficial]. At every descent, it checks if the ray crosses the split plane; if not, it marks the current node as a new restart point and stores a pointer [S3, unofficial]. When a neighbor must be found, it jumps back to the restart point instead of the root, reducing visited nodes in practice while keeping worst-case complexity at $O(n \log n)$ [S3, unofficial].

## Operating characteristics
* **Time Complexity:** $O(n \log n)$ average for balanced trees, but with a higher constant factor due to redundant root restarts [S2, unofficial][S3, unofficial].
* **Memory Complexity:** $O(1)$ auxiliary stack space, as no explicit stack is used [S2, unofficial].
* **Strengths:** Eliminates recursion stack overhead, simple implementation logic, fits GPU memory constraints.
* **Limitations:** Higher runtime from redundant root traversals, inefficient for very deep trees.
* **When to Use:** Memory-constrained environments (e.g., mobile GPUs) and moderate tree depths.
* **When Not to Use:** Deep kd-trees or performance-critical paths where stack space is available.

## Background
Proposed by Foley et al. for rendering triangle meshes on the GPU [S2, unofficial]. Later adopted for volume rendering, notably in the CERA-TVR system which targets scientific visualization with real-time dynamic transfer function updates [S1]. The method addresses early GPU architecture limitations regarding stack depth [S2, unofficial].
