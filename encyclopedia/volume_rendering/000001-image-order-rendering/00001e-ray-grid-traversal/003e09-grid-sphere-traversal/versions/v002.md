# Grid Sphere Traversal


## Overview
Grid Sphere Traversal (GST) is a ray-grid traversal method that performs sphere tracing through a dense grid of Signed Distance Function (SDF) values [S1, unofficial]. It solves the problem of efficiently traversing empty regions in SDF-based rendering by using a hierarchy of SDF grids where lower-resolution levels encode larger SDF values to accelerate step sizes [S1, unofficial]. It is distinguished from its siblings by performing the entire traversal in shader code using dense grids, whereas alternatives like [Sparse Voxel Set](3116-sparse-voxel-set.md) leverage DXR hardware acceleration for BVH traversal [S2, unofficial].

## How it works
**Inputs:** Ray origin, ray direction, SDF grid hierarchy (mipmap levels), grid resolution per level [S1, unofficial].
**Outputs:** Intersection distance or null [G].

**Data Structures:**
*   **SDF Grid:** A 3D texture or array storing SDF values [S1, unofficial].
*   **Value Encoding:** SDF values are clamped to $[-1, 1]$ [S1, unofficial]. A value of $1$ encodes a distance of $2.5$ interior voxel diagonals [S1, unofficial]. This allows storage as 8-bit signed normalized (snorm) integers [S1, unofficial].
*   **Hierarchy:** A set of grid levels $L_0, L_1, \dots, L_n$ [S1, unofficial]. Level $L_0$ is the highest resolution [S1, unofficial]. Lower-resolution levels (higher index) encode larger SDF values to represent empty space more coarsely [S1, unofficial].

**Steps:**
1.  **Initialize:** Start at the root level (lowest resolution, highest index) of the SDF hierarchy [S1, unofficial].
2.  **Traverse Hierarchy:** For the current ray, determine the position in the current grid level [S1, unofficial].
3.  **Sample SDF:** Sample the SDF value at the current ray position from the current grid level [S1, unofficial].
4.  **Adaptive Resolution Selection:** Use the sampled SDF value to determine if the ray is in empty space [S1, unofficial]. If the SDF value indicates sufficient empty space (larger distance), the algorithm may step forward by a larger amount or switch to a lower-resolution level to maximize step size safely [S1, unofficial]. If the ray is close to the surface (small SDF value), switch to a higher-resolution level to reduce step size and maintain precision [G].
5.  **Sphere Trace:** Perform sphere tracing steps [S1, unofficial]. The step size is determined by the SDF value at the current position, scaled appropriately for the grid resolution and encoding [S1, unofficial].
6.  **Intersection Check:** If the SDF value is below a threshold (surface hit), return the intersection distance [G]. If the ray exits the grid or exceeds max distance, return null [G].
7.  **Shader Execution:** The entire traversal logic is implemented in shader code (e.g., GLSL/HLSL) [S1, unofficial].

**Pseudocode:**
```python
def grid_sphere_traversal(ray_origin, ray_direction, sdf_grids, grid_bounds, max_steps, epsilon, level_switch_threshold):
    # sdf_grids: list of 3D textures/arrays, index 0 is lowest resolution (coarsest)
    # grid_bounds: (min_corner, max_corner) defining the world-space extent of the grids
    # level_switch_threshold: multiplier for voxel_size to decide when to change resolution
    
    t = 0.0
    current_level = 0
    pos = ray_origin
    
    for _ in range(max_steps):
        # Check if ray has exited the grid bounds
        if not is_inside_grid(pos, grid_bounds):
            return None
            
        # Compute physical voxel size for current level
        # Assuming cubic grids with side length L at level 0, scaled by 2^level
        level_scale = 2 ** current_level
        grid_side = grid_bounds[1][0] - grid_bounds[0][0]
        voxel_size = grid_side / (sdf_grids[0].shape[0] * level_scale)
        
        # Sample SDF value at current position
        # Coordinates normalized to [0, 1] for texture lookup
        uv = (pos - grid_bounds[0]) / (grid_bounds[1] - grid_bounds[0])
        uv = clamp(uv, 0.0, 1.0)
        sdf_snorm = texture_sample(sdf_grids[current_level], uv)
        
        # Decode 8-bit snorm to physical distance
        # snorm 1.0 -> 2.5 * sqrt(3) * voxel_size
        physical_dist = sdf_snorm * 2.5 * sqrt(3) * voxel_size
        
        # Surface intersection check
        if physical_dist < epsilon:
            return t
            
        # Sphere tracing step
        step = max(epsilon, physical_dist)
        t += step
        pos = ray_origin + ray_direction * t
        
        # Adaptive resolution selection
        # Large empty space (large SDF) -> coarser level (higher index)
        # Near surface (small SDF) -> finer level (lower index)
        if physical_dist > level_switch_threshold * voxel_size and current_level < len(sdf_grids) - 1:
            current_level += 1
        elif physical_dist < 0.5 * level_switch_threshold * voxel_size and current_level > 0:
            current_level -= 1
            
    return None

def is_inside_grid(point, bounds):
    return all(bounds[0][i] <= point[i] <= bounds[1][i] for i in range(3))

def clamp(v, min_val, max_val):
    return max(min_val, min(max_val, v))

def texture_sample(grid, uv):
    # Standard trilinear interpolation of 3D texture at normalized coordinates
    # Returns value in [-1, 1]
    return grid[uv]
```

**Parameters:**
*   **SDF Encoding:** 8-bit snorm, range $[-1, 1]$, mapping $1.0$ to $2.5$ interior voxel diagonals [S1, unofficial].
*   **Max Steps:** Not given in the sources [G].
*   **Epsilon:** Not given in the sources [G].
*   **Level Switch Threshold:** Not given in the sources [G].

**Edge Cases:**
*   **Precision:** Using 8-bit snorm may introduce quantization errors [S1, unofficial]. The mapping of $1.0$ to $2.5$ diagonals is a specific design choice to maximize the range of representable distances [S1, unofficial].
*   **Boundaries:** Ray must be clamped to the grid bounds [G].
*   **Degenerate Input:** Empty space far from surface may require many steps if the hierarchy is not deep enough or if the adaptive resolution selection is not optimal [G].

## Subtopics

### Grid Sphere-Tracing
A grid traversal algorithm used in Claybook (Aaltonen, 2018) where every voxel is uniquely associated with a raytracing bounding box [S2, unofficial]. It performed best in open and simple scenes compared to sparse brick set and sparse voxel octree [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Depends on the number of steps in sphere tracing and the depth of the hierarchy [S1, unofficial]. Adaptive resolution selection aims to reduce steps in empty space [S1, unofficial].
*   **Memory Complexity:** Dense grid storage [S1, unofficial]. All voxels are stored, including those without SDF surface [S1, unofficial].
*   **Performance:** Performed best in open and simple scenes [S2, unofficial]. Outperformed by sparse voxel set in general due to DXR hardware acceleration, but GST has better cache coherency due to compact data storage [S2, unofficial].
*   **Strengths:** Simple implementation in shader code, good cache coherency, effective in open scenes [S1, unofficial][S2, unofficial].
*   **Limitations:** Dense storage is memory-intensive [S1, unofficial]. Less effective in complex scenes compared to sparse methods [S2, unofficial].

## Background
Grid Sphere Traversal was evaluated in the context of ray tracing signed distance function grids [S1, unofficial]. It is similar to the technique used in Claybook by Aaltonen (2018) [S1, unofficial][S2, unofficial]. The method was compared against sparse voxel set, sparse brick set, and sparse voxel octree [S1, unofficial].
