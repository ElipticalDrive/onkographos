# Ray Marching with Octant Masking

Also called: Ray march, Ray struct

## Overview
Ray Marching with Octant Masking is a method for traversing a uniform voxel grid by advancing a ray in discrete steps and using an octant mask to determine visibility or traversal direction based on the ray's direction vector components. It solves the problem of efficiently stepping through dense volume data without hierarchical acceleration structures, relying instead on simple arithmetic and bitwise operations to manage the traversal state. It differs from hierarchical methods like [Sparse Voxel Octree Ray Traversal](2451-sparse-voxel-octree-ray-traversal.md) by avoiding tree traversal overhead, and from [Digital Differential Analyzer (DDA) Traversal](3061-digital-differential-analyzer-dda-traversal.md) by explicitly using an octant mask for state management rather than continuous coordinate comparison.

## How it works
**Inputs:** Ray origin, ray direction, voxel grid dimensions, voxel size (implicit or explicit), and a step size or march amount.
**Outputs:** Updated ray state (origin, direction) and traversal mask.

**Data Structures:**
The core data structure is the `Ray` struct, defined as follows:
- `origin`: `Vector` (3 floats). Current ray position.
- `direction`: `Vector` (3 floats). Ray direction vector.
- `negdir`: `Vector` (3 floats). Unused in the provided implementation.
- `init_origin`: `Vector` (3 floats, private). The starting position of the ray.

**Algorithm Steps:**
1. **Initialization:** Construct the ray. If any component of the direction vector has a magnitude less than a small epsilon ($\epsilon$), set that component to $\epsilon$ with the same sign to prevent division by zero or degenerate cases [S1, unofficial].
2. **Octant Masking:** Compute an octant mask to identify the current octant relative to the origin. The mask is a `uint8_t` where:
   - Bit 2 (value 4) is set if `direction.x >= 0`.
   - Bit 1 (value 2) is set if `direction.y >= 0`.
   - Bit 0 (value 1) is set if `direction.z >= 0` [S1, unofficial].
3. **Ray Marching:** Advance the ray origin by adding the product of the direction vector and a specified march amount (step size) to the current origin. The function returns the updated ray [S1, unofficial].
4. **Distance Tracking:** Calculate the squared Euclidean distance from `init_origin` to the current `origin` using `square_distance()` to track traversal progress or determine termination conditions [S1, unofficial].

**Pseudocode:**
```python
import math

class Ray:
    def __init__(self, origin, direction):
        self.origin = origin.copy()
        self.direction = direction.copy()
        self.negdir = [0.0, 0.0, 0.0]  # Unused
        self.init_origin = origin.copy()
        
        # Step 1: Handle degenerate directions
        epsilon = 1e-6
        for i in range(3):
            if abs(self.direction[i]) < epsilon:
                if self.direction[i] >= 0:
                    self.direction[i] = epsilon
                else:
                    self.direction[i] = -epsilon

    def octant_mask(self):
        """
        Step 2: Compute octant mask.
        Bit 2 (4) if dir.x >= 0
        Bit 1 (2) if dir.y >= 0
        Bit 0 (1) if dir.z >= 0
        """
        mask = 0
        if self.direction[0] >= 0:
            mask |= 4
        if self.direction[1] >= 0:
            mask |= 2
        if self.direction[2] >= 0:
            mask |= 1
        return mask

    def march(self, amount):
        """
        Step 3: Advance ray origin.
        origin = origin + direction * amount
        """
        self.origin[0] += self.direction[0] * amount
        self.origin[1] += self.direction[1] * amount
        self.origin[2] += self.direction[2] * amount
        return self

    def square_distance(self):
        """
        Step 4: Calculate squared distance from init_origin.
        """
        dx = self.origin[0] - self.init_origin[0]
        dy = self.origin[1] - self.init_origin[1]
        dz = self.origin[2] - self.init_origin[2]
        return dx*dx + dy*dy + dz*dz
```

**Parameters:**
- `epsilon`: Small value to avoid zero-direction components. Value not given in the sources [G].
- `amount`: Step size for marching. Value not given in the sources [G].

**Edge Cases:**
- **Zero Direction Components:** Handled by clamping to $\epsilon$ [S1, unofficial].
- **Boundary Conditions:** Not specified in the sources.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of march steps. Each step involves constant-time arithmetic and bitwise operations.
- **Memory Complexity:** $O(1)$ auxiliary memory for the ray struct.
- **Performance:** Efficient for dense, uniform grids where hierarchical overhead is not justified. Performance degrades in sparse volumes due to unnecessary marching through empty space.
- **Strengths:** Simple implementation, low memory footprint, no recursion or stack usage.
- **Limitations:** Inefficient for sparse data; no early termination for empty regions unless combined with external checks.
- **When to Use:** Dense voxel textures, simple uniform grids, or when hardware acceleration for hierarchical traversal is unavailable.
- **When Not to Use:** Sparse voxel octrees, large scenes with significant empty space, or when hierarchical culling is required.

## Background
The method is described in the unofficial source [S1, unofficial], which provides a C++ implementation using GLM for vector operations. It appears to be a component of a larger volume rendering or voxel visualization system.
