# Multi-Grid Ray Traversal

Also called: Ray traversal through multiple voxel grids

## Overview
Multi-Grid Ray Traversal traverses rays through multiple binary occupancy grids to generate ray intervals and samples, enabling efficient rendering in scenes with complex, disjoint, or hierarchical volumetric structures [S1, unofficial]. It solves the problem of efficiently locating samples in dense particle systems or multi-resolution NeRFs by pre-computing ray-AABB intersections to determine which grids are hit, sorting these entry/exit points, and then performing voxel-level traversal only within the active intervals [S1, unofficial]. Unlike single-grid traversal, it handles multiple disjoint volumes by merging intersection events, though it requires careful handling of overlapping grids where the first grid's occupancy status overwrites subsequent ones [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `rays_o`: `[n_rays, 3]` float array of ray origins [S1, unofficial].
    *   `rays_d`: `[n_rays, 3]` float array of normalized ray directions [S1, unofficial].
    *   `binaries`: `[n_grids, resx, resy, resz]` boolean array representing voxel occupancy. All grids share the same resolution [S1, unofficial].
    *   `aabbs`: `[n_grids, 6]` float array storing axis-aligned bounding boxes per grid (min/max x, y, z) [S1, unofficial].
    *   `t_sorted`: Optional `[n_rays, n_grids * 2]` float array of pre-computed, sorted ray-grid intersection distances [S1, unofficial].
    *   `t_indices`: Optional `[n_rays, n_grids * 2]` int64 array mapping each intersection to its grid ID (0-indexed) [S1, unofficial].
    *   `hits`: Optional `[n_rays, n_grids]` boolean array indicating whether each ray hits each grid [S1, unofficial].
    *   `step_size`: Optional float for the ray traversal step size. Default is $10^{-3}$ [S1, unofficial].
    *   `cone_angle`: Optional float for linearly-increased step size. $0.0$ means constant step size. Default is $0.0$ [S1, unofficial].
    *   `traverse_steps_limit`: Optional int for the maximum number of samples per ray. Default is $-1$ (unlimited) [S1, unofficial].
    *   `near_plane`: Optional float array. Default is $0.0$ [S1, unofficial].
    *   `far_plane`: Optional float array. Default is $\infty$ [S1, unofficial].
    *   `rays_mask`: Optional BoolTensor of shape `[n_rays]` to skip specific rays [S1, unofficial].
*   **Outputs:**
    *   `intervals`: `PackedRaySegmentsSpec` structure storing traversal intervals per ray, supporting chunked memory layouts via `chunk_cnts` and `chunk_starts` [S1, unofficial].
    *   `samples`: `PackedRaySegmentsSpec` structure storing sample positions within each interval [S1, unofficial].
    *   `terminated_t`: Tensor of shape `[n_rays]` containing terminated t values for each ray [S1, unofficial].

**Data Structures:**
The method relies on pre-computed intersection data to avoid per-ray AABB intersection tests during the main loop.
*   `t_sorted`: A flattened array of $2 \times n\_grids$ intersection distances per ray, sorted in ascending order.
*   `t_indices`: An integer array of the same shape as `t_sorted`, where each entry indicates which grid ID ($0 \dots n\_grids-1$) generated the corresponding intersection distance.
*   `binaries`: A 4D boolean tensor. The traversal accesses this to determine if a specific voxel $(x,y,z)$ in a specific grid $g$ is occupied.

**Algorithm Steps:**
1.  **Initialization:**
    *   Initialize `rays_mask` to all ones if not provided [S1, unofficial].
    *   Initialize `near_plane` to zeros and `far_plane` to infinity if not provided [S1, unofficial].
    *   Compute `t_sorted` and `t_indices` by concatenating `t_mins` and `t_maxs` for all grids and sorting them per ray [S1, unofficial]. If pre-computed, use them directly.
    *   Set base indices for the current ray `tid`: `base_hits = tid * n_grids`, `base_t_sorted = tid * n_grids * 2` [S1, unofficial].

2.  **Intersection Loop:**
    *   Iterate `i` from `base_t_sorted` to `base_t_sorted + n_grids * 2 - 1` [S1, unofficial].
    *   Determine if the current intersection is an entry or exit: `is_entering = t_indices[i] < n_grids` (assuming the sorting logic maps even indices to entries and odd to exits, or uses the index value to distinguish; the source implies `t_indices` stores the grid ID, and the sorting order determines entry/exit sequence) [S1, unofficial]. *Note: The source specifies `is_entering = t_indices[i] < n_grids` which seems to imply a specific encoding in `t_indices` or a misunderstanding of the standard even/odd pairing. However, standard AABB intersection yields pairs. We assume `t_sorted` contains pairs $(t_{entry}, t_{exit})$ for each grid, sorted globally.*
    *   Compute interval bounds:
        $$
        \text{this\_tmin} = \max(t\_sorted[i], \text{near\_plane}[tid])
        $$
        $$
        \text{this\_tmax} = \min(t\_sorted[i+1], \text{far\_plane}[tid])
        $$
        *Note: The source uses `t_sorted[i+1]` suggesting the loop processes pairs or the array is structured such that adjacent elements form intervals. Given `n_grids * 2` entries, we likely process pairs.*
    *   Skip if `this_tmin >= this_tmax` to prevent degenerate intervals [S1, unofficial].

3.  **Step Size Calculation (Marching Setup):**
    *   If `step_size <= 0.0`, record steps per voxel cell [S1, unofficial].
    *   If `step_size > 0.0`, use uniform or cone-based marching [S1, unofficial].
    *   If `cone_angle > 0.0`, the step size increases linearly with distance. The function `_calc_dt` computes the delta $dt$ based on `t_last`, `cone_angle`, `step_size`, and a large constant ($10^{10}$) [S1, unofficial].
    *   **Discontinuity Handling:** If `continuous` is false, adjust `t_last` to align with `this_tmin`. If `step_size <= 0.0`, set `t_last = this_tmin`. Else, march forward using `dt` until `t_last + dt * 0.5 >= this_tmin` [S1, unofficial].

4.  **Voxel Traversal:**
    *   Setup traversal for the current AABB using `setup_traversal(ray, this_tmin, this_tmax, eps, aabb, resolution, delta, tdist, step_index, current_index, final_index)` [S1, unofficial].
    *   `eps` is set to $10^{-6}$ [S1, unofficial].
    *   Perform the DDA-like traversal within the voxel grid defined by `binaries` for the current grid ID.
    *   Accumulate samples into the `samples` structure.

5.  **Parallelization:**
    *   Parallelize over rays using grid/block indices: `tid = blockIdx.x * blockDim.x + threadIdx.x` [S1, unofficial].
    *   Skip rays where `rays_mask` is false or `chunk_cnts[tid] == 0` on non-first passes [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Overlapping Grids:** The ordering of grids matters. If grids overlap, the first grid's occupancy status overwrites the second grid's if they overlap [S1, unofficial]. This means the traversal order (determined by `t_sorted`) dictates visibility.
*   **Invalid Intervals:** If `this_tmin >= this_tmax` (e.g., both 0.0), the interval is skipped to prevent degenerate marching [S1, unofficial].
*   **Discontinuous Traversal:** When entering a new grid interval, `t_last` must be advanced to align with `this_tmin` before starting voxel traversal, otherwise samples will be misaligned [S1, unofficial].
*   **Precision:** `eps` is set to $10^{-6}$ for traversal setup to handle boundary precision issues [S1, unofficial].

## Subtopics

### [Ray Marching Particle Grid Traversal](5182-ray-marching-particle-grid-traversal.md)
A hybrid technique that uses a low-resolution grid for culling and a high-resolution grid for precise hit testing. It skips large empty regions by querying a coarser occupancy grid first, switching to high-resolution traversal only when occupied cells are detected.

## Operating characteristics
*   **Time Complexity:** The complexity is dominated by the pre-computation of ray-AABB intersections ($O(n\_rays \times n\_grids)$) and the voxel traversal within active intervals. The traversal itself is proportional to the number of occupied voxels visited.
*   **Memory Complexity:** Requires storage for `t_sorted`, `t_indices`, `hits`, and the `binaries` grids. The `binaries` tensor is $O(n\_grids \times resx \times resy \times resz)$.
*   **Performance:** Efficient for scenes with many disjoint volumes or hierarchical structures, as it avoids traversing empty space outside the AABBs. Performance scales with the number of rays and the density of occupied voxels within the active intervals.
*   **Strengths:** Handles multiple grids efficiently; supports dynamic updates (e.g., occupancy grid estimation in NeRF training); supports cone-based step sizing for adaptive sampling.
*   **Limitations:** Overlapping grids require careful ordering; pre-computation of intersections adds overhead; discontinuous traversal requires state management for `t_last`.

## Background
Multi-Grid Ray Traversal is a core component of the NerfAcc library, designed to accelerate NeRF rendering by efficiently sampling occupancy grids [S1, unofficial]. It was introduced in the context of dynamic NeRFs and camera optimization NeRFs, where efficient sampling is crucial for training speed [S1, unofficial]. The method is used in various NeRF variants, including TensoRF, T-NeRF, K-Planes, and TiNeuVox, often in conjunction with occupancy grid estimators [S1, unofficial].
