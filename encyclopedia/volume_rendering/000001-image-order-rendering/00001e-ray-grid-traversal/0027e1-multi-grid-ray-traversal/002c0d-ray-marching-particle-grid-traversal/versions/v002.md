# Ray Marching Particle Grid Traversal

Also called: Hybrid Ray Marching Particle Grid Traversal, Low-Resolution Culling Particle Grid Traversal

## Overview
Ray Marching Particle Grid Traversal is a hybrid ray marching technique that traverses a voxel grid to find particle hits, using a low-resolution grid for culling and a high-resolution grid for precise hit testing [S1, unofficial]. It solves the problem of efficiently locating particles along a ray in a dense particle system by avoiding expensive per-particle distance checks in empty space. Unlike standard high-resolution grid traversal which checks every voxel, this method skips large empty regions by first querying a coarser occupancy grid, switching to high-resolution traversal only when occupied cells are detected [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $pos_0$ and direction $rayDirection$ (normalized).
- Particle position buffer $particlesPositionBuffer$ (array of $vec4f$, storing particle centers).
- Particle index buffer $particlesIndicesBuffer$ (array of $i32$, mapping voxel slots to particle IDs).
- Low-resolution occupancy grid $gridBuffer$ (array of $i32$, flags 1 or 0).
- Uniforms: $resolution$ (image dimensions), $INNER\_RADIUS$ (boundary threshold).

**Outputs:**
- Hit color, hit position, hit velocity, and boolean success flag.

**Data Structures:**
- $particlesPositionBuffer$: Stores particle centers as $vec4f$. The $rgb$ components hold the 3D position.
- $particlesIndicesBuffer$: Stores particle IDs. Each entry corresponds to a potential particle slot in a high-resolution voxel.
- $gridBuffer$: Stores occupancy flags for the low-resolution grid. Index calculated as $lowGrid.x + lowRes \cdot lowGrid.y + lowRes^2 \cdot lowGrid.z$.

**Parameters:**
- $MAX\_ITERATIONS$: 400 [S1, unofficial].
- $GRID\_RATIO$: 8 [S1, unofficial].
- $RADIUS$: 0.19 (squared radius for hit check) [S1, unofficial].
- $EPSILON$: $1.e-10$ [S1, unofficial].
- $acne$: 0.05 (offset for texture sampling) [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:**
    Calculate the initial step size $rayStep$ and the delta distance to the next voxel boundary $deltaDist$.
    Initialize side distances for slab crossing:
    $$sideDist = (rayStep \cdot (mapPos - pos + 0.5) + 0.5) \cdot deltaDist$$
    where $mapPos = floor(pos)$ is the initial voxel coordinate.

2.  **Ray Marching Loop:**
    Loop for $i$ from 0 to $MAX\_ITERATIONS$:

    a.  **Determine Step Direction:**
        Calculate the direction to the next voxel boundary along each axis.
        $$stepForward = step(sideDist.xyz, sideDist.yxy) \cdot step(sideDist.xyz, sideDist.zzx)$$
        Note: The source uses a specific component-wise comparison pattern `step(sideDist.xyz, sideDist.yxy)` which implies a specific ordering or axis permutation logic for determining the minimum slab crossing. In standard AABB traversal, this is typically `step(sideDist, max(sideDist))` or similar min-finding logic. The source code explicitly uses:
        `stepForward = step(sideDist.xyz, sideDist.yxy) * step(sideDist.xyz, sideDist.zzx)`
        This appears to be a compact way to find the minimum component's direction, assuming specific axis mappings. We follow the source exactly.

    b.  **Update State:**
        $$sideDist += stepForward \cdot deltaDist$$
        $$pos += stepForward \cdot rayStep$$
        $$mapPos = floor(pos)$$

    c.  **Calculate Time to Boundary:**
        $$t = min(sideDist.x, min(sideDist.y, sideDist.z))$$

    d.  **Border Check:**
        Check if the ray is near the image boundaries.
        $$borders = length(pos.yz / uniforms.resolution - vec2(0.5)) > INNER\_RADIUS$$
        Also check x-bound conditions (source mentions "x-bound checks" but does not specify the formula, likely similar to y/z).
        If borders are exceeded, `continue` (skip to next iteration). The source comments out a `return`, implying the ray continues or is handled elsewhere.

    e.  **Low-Resolution Grid Query:**
        Calculate the low-resolution grid index:
        $$lowGrid = mapPos / GRID\_RATIO \quad (\text{if highResolution else } mapPos)$$
        $$indexGrid = lowGrid.x + lowRes \cdot lowGrid.y + lowRes^2 \cdot lowGrid.z$$
        Check occupancy:
        $$resolution = gridBuffer[indexGrid] == 1$$
        (Note: Source code shows `resolution = gridBuffer[indexGrid] == 1 || true`, which always evaluates to true. This is likely a placeholder or bug in the source. We assume the logical intent is checking for occupancy, i.e., `gridBuffer[indexGrid] == 1`.)

    f.  **Mode Switching (Low to High):**
        If currently in high-resolution mode and $resolution$ is false (empty low-res cell):
        Switch to low-res mode.
        $$pos0\_l = (pos0\_h + t \cdot rayDirection) / GRID\_RATIO$$
        $$pos = pos0\_l$$
        $$mapPos = floor(pos)$$
        Recalculate $sideDist$ for the low-res grid.

    g.  **High-Resolution Hit Testing:**
        If currently in high-resolution mode and $resolution$ is true (occupied low-res cell):
        Check for particle hits in the current high-resolution voxel.
        $$index1D = mapPos.x + res \cdot mapPos.y + res^2 \cdot mapPos.z$$
        Loop $z$ from 0 to 7:
        $$particleId = 8 \cdot index1D + z$$
        $$voxelData = particlesIndicesBuffer[particleId]$$
        If $voxelData == 0$, break (no more particles in this voxel slot).
        $$center = particlesPositionBuffer[voxelData].rgb$$
        Check particle bounds:
        $$if \ center.x > 0.1 \cdot uniforms.resolution \ and \ checkHit(initPos, center, rayDirection) \ and \ l < d$$
        Update hit:
        $$index = voxelData$$
        $$d = l$$
        
        The `checkHit` function uses the squared radius to avoid square roots:
        $$l = length(center - initPos)$$
        $$d = l^2 - t_{CA} \cdot t_{CA}$$ (Source formula: `d = l*l - tCA*tCA`, where $t_{CA}$ is likely the distance along the ray to the closest approach or a specific threshold).

    h.  **Hit Return:**
        If a hit is found ($index > -1000$):
        Set $hitColor$, $hitPosition$, $hitVelocity$ from buffers and return true.

    i.  **Mode Switching (High to Low):**
        If in low-res mode and $resolution$ is true:
        Switch back to high-res mode.
        $$pos0\_h = GRID\_RATIO \cdot (pos0\_l + 0.9999 \cdot t \cdot rayDirection)$$
        $$pos = pos0\_h$$
        $$mapPos = floor(pos)$$
        Recalculate $sideDist$.

    j.  **Update Flag:**
        $$highResolution = resolution$$

**Pseudocode:**

```python
def ray_marching_particle_grid_traversal(ray_origin, ray_direction, particles_position_buffer, particles_indices_buffer, grid_buffer, resolution, inner_radius, max_iterations=400, grid_ratio=8, radius=0.19, epsilon=1e-10):
    # Initialize state
    pos = ray_origin
    map_pos = floor(pos)
    # Calculate initial side distances and delta dist based on ray step and voxel size
    # Note: Exact calculation of rayStep and deltaDist depends on voxel size and ray direction magnitude
    # Assuming unit voxel size for simplicity, or derived from context
    ray_step = 1.0 / length(ray_direction) # Simplified
    delta_dist = ray_step # Simplified
    
    side_dist = (ray_step * (map_pos - pos + 0.5) + 0.5) * delta_dist
    
    high_resolution = True
    pos0_h = pos
    pos0_l = pos
    
    for i in range(max_iterations):
        # Determine step direction
        # Source: stepForward = step(sideDist.xyz, sideDist.yxy) * step(sideDist.xyz, sideDist.zzx)
        # This is a non-standard way to find min. We implement it as written.
        step_forward = step(side_dist.xyz, side_dist.yxy) * step(side_dist.xyz, side_dist.zzx)
        
        # Update side distances and position
        side_dist += step_forward * delta_dist
        pos += step_forward * ray_step
        map_pos = floor(pos)
        
        # Calculate distance to next voxel boundary
        t = min(side_dist.x, min(side_dist.y, side_dist.z))
        
        # Check border conditions
        # Source: borders = length(pos.yz / uniforms.resolution - vec2f(0.5)) > INNER_RADIUS
        # Note: pos is in world/voxel space, resolution is in pixels. This comparison seems dimensionally inconsistent
        # unless pos is normalized or resolution is in voxel units. We follow the source logic.
        border_check_yz = length(pos.yz / resolution - vec2(0.5)) > inner_radius
        # x-bound checks are mentioned but not detailed. We assume similar logic or skip if not specified.
        if border_check_yz:
            continue
            
        # Determine low-res grid index
        if high_resolution:
            low_grid = map_pos / grid_ratio
        else:
            low_grid = map_pos
            
        low_res = resolution[0] / grid_ratio # Assuming cubic grid scaling
        index_grid = low_grid.x + low_res * low_grid.y + low_res * low_res * low_grid.z
        
        # Check occupancy in low-res grid
        # Source: resolution = gridBuffer[indexGrid] == 1 || true
        # We interpret this as checking for occupancy
        resolution_flag = grid_buffer[index_grid] == 1
        
        if high_resolution and not resolution_flag:
            # Switch to low-res mode
            pos0_l = (pos0_h + t * ray_direction) / grid_ratio
            pos = pos0_l
            map_pos = floor(pos)
            # Recalculate sideDist for low-res grid
            # This requires recalculating delta_dist for low-res voxel size
            delta_dist_low = ray_step / grid_ratio
            side_dist = (ray_step * (map_pos - pos + 0.5) + 0.5) * delta_dist_low
            high_resolution = False
            
        elif high_resolution and resolution_flag:
            # Check for particle hits in current high-res voxel
            res = resolution[0] # Assuming square resolution for index calculation
            index1d = map_pos.x + res * map_pos.y + res * res * map_pos.z
            
            hit_found = False
            best_index = -1000
            best_d = infinity
            
            for z in range(8):
                particle_id = 8 * index1d + z
                voxel_data = particles_indices_buffer[particle_id]
                if voxel_data == 0:
                    break
                    
                center = particles_position_buffer[voxel_data].rgb
                
                # Check particle bounds
                if center.x > 0.1 * resolution[0]:
                    # Check hit
                    # Source: checkHit(initPos, center, rayDirection)
                    # We assume this checks if the ray intersects the particle sphere
                    l = length(center - pos) # Distance from ray origin to particle center
                    # Source: d = l*l - tCA*tCA
                    # tCA is not defined in the source. We assume it's a threshold or distance along ray.
                    # For a simple sphere hit test, we might use standard ray-sphere intersection.
                    # However, we must follow the source. We will assume tCA is a pre-calculated value or 0 for this simplified version.
                    # Given the ambiguity, we implement a basic distance check.
                    if l * l < radius: # Using squared radius
                        hit_found = True
                        best_index = voxel_data
                        best_d = l
                        break
            
            if hit_found:
                return {
                    "hit": True,
                    "index": best_index,
                    "position": center,
                    "color": get_color(best_index),
                    "velocity": get_velocity(best_index)
                }
                
        elif not high_resolution and resolution_flag:
            # Switch back to high-res mode
            pos0_h = grid_ratio * (pos0_l + 0.9999 * t * ray_direction)
            pos = pos0_h
            map_pos = floor(pos)
            # Recalculate sideDist for high-res grid
            delta_dist_high = ray_step
            side_dist = (ray_step * (map_pos - pos + 0.5) + 0.5) * delta_dist_high
            high_resolution = True
            
        # Update highResolution flag
        high_resolution = resolution_flag
        
    return {"hit": False}
```

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of ray steps, but effectively reduced by the low-resolution culling. The cost per step is $O(1)$ for grid lookup and $O(1)$ for particle check (up to 8 particles per voxel).
- **Memory Complexity:** $O(V_{low} + V_{high} \cdot P)$ where $V$ is the number of voxels and $P$ is particles per voxel. The low-res grid is $1/GRID\_RATIO^3$ the size of the high-res grid.
- **Performance:** The method is efficient for sparse particle systems where large empty regions can be skipped. The low-resolution grid acts as a broad-phase culling mechanism.
- **Strengths:** Reduces the number of particle distance checks by skipping empty high-resolution voxels.
- **Limitations:** Requires maintaining two grid structures. The low-resolution grid may have false positives (occupied low-res cell but no particles in the high-res voxel), leading to unnecessary particle checks. The source code contains potential bugs (e.g., `|| true` in occupancy check, undefined `tCA`).

## Background
This method is described in an unofficial WebGPU Voxel Cone Tracing repository [S1, unofficial]. It is a hybrid approach combining ray marching with grid-based particle lookup.
