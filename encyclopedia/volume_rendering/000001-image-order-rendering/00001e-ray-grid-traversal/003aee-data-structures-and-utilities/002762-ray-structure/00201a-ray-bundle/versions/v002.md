# Ray Bundle

Also called: Ray Bundle Data Structure, Ray Bundle Generation

## Overview
A Ray Bundle groups ray origins, directions, and sampling parameters (sample points and lengths) into a single object, typically implemented as a collection of aligned tensors [S2, unofficial][S3, unofficial]. It manages batched ray data for volume rendering pipelines, enabling efficient vectorized operations and memory transfers [S2, unofficial]. It differs from a [RayBatch container](4187-raybatch-container.md) by explicitly bundling sampling metadata alongside geometric data, and from a [Hit Record Structure](4953-hit-record-structure.md) by focusing on input ray generation rather than output intersection results [S1, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: Tensors for ray origins, ray directions, sample points along rays, and distances of sample points from origins [S1, unofficial].
- **Outputs**: A structured object containing these tensors, supporting indexing, reshaping, and device transfer [S2, unofficial].

### Data Structures
The `RayBundle` class wraps four per-ray tensors [S2, unofficial][S3, unofficial]:
1. `origins`: Tensor of shape $(N, 3)$, storing 3D ray origin coordinates [S1, unofficial][S3, unofficial].
2. `directions`: Tensor of shape $(N, 3)$, storing normalized ray direction vectors [S1, unofficial][S3, unofficial].
3. `sample_points`: Tensor of shape $(N, n_{pts}, 3)$, storing 3D coordinates of sample points along each ray [S1, unofficial][S3, unofficial].
4. `sample_lengths`: Tensor of shape $(N, n_{pts}, 1)$, storing distances of sample points from the ray origin [S1, unofficial][S3, unofficial].

### Numbered Steps
1. **Initialization**: Instantiate `RayBundle` by passing the four tensors to the constructor [S1, unofficial].
2. **Indexing**: Call `__getitem__(idx)` to return a new `RayBundle` with sliced tensors for all fields at index `idx` [S3, unofficial].
3. **Reshaping**: Call `reshape(*args)` to change batch dimensions while preserving last dimensions: origins/directions to `(*args, 3)`, sample points to `(*args, n_{pts}, 3)`, and sample lengths to `(*args, n_{pts}, 1)` [S1, unofficial][S3, unofficial].
4. **Viewing**: Call `view(*args)` to return a new `RayBundle` with viewed tensors, preserving the same last dimension constraints [S3, unofficial].
5. **Replacement**: Call `_replace(**kwargs)` to update specific attributes and return the modified bundle [S3, unofficial].
6. **Device Transfer**: Call `to(device)` to move all tensors to a specified device [S2, unofficial].
7. **Property Access**: `shape` returns `origins.shape[:-1]` [S3, unofficial]; `sample_shape` returns `sample_points.shape[:-1]` [S3, unofficial]; `device` returns `sample_points.device` [S3, unofficial].

### Formulas
- **Camera-Space Directions**: For pixel coordinates $(i, j)$, image width $W$, height $H$, and focal length $f$:
  $$ x = \frac{i - W/2}{f} $$
  $$ y = -\frac{j - H/2}{f} $$
  $$ z = -1 $$
  [S4, unofficial]
- **World-Space Directions**: Transform camera-space directions to world space using rotation matrix $R$ from the camera-to-world transform, then normalize:
  $$ \mathbf{d}_{world} = \text{normalize}(R \cdot [x, y, z]^T) $$
  [S4, unofficial]
- **Ray Origins**: Set to the camera position extracted from the camera-to-world matrix [S4, unofficial].

### Parameters
- $N$: Number of rays. Not given in the sources.
- $n_{pts}$: Number of sample points per ray. Not given in the sources.
- $W, H$: Image width and height. Not given in the sources.
- $f$: Focal length. Not given in the sources.

### Edge Cases and Pitfalls
- **Boundaries**: `reshape` and `view` must preserve the last dimensions (3 for origins/directions/sample points, 1 for sample lengths); mismatched dimensions cause errors [S1, unofficial].
- **Degenerate Input**: Empty tensors or mismatched batch sizes between fields cause initialization or indexing failures [S3, unofficial].

### Pseudocode
```python
import torch

class RayBundle:
    def __init__(self, origins: torch.Tensor, directions: torch.Tensor, 
                 sample_points: torch.Tensor, sample_lengths: torch.Tensor):
        """
        Initialize a RayBundle with ray data.
        
        Args:
            origins: Tensor of shape (N, 3)
            directions: Tensor of shape (N, 3)
            sample_points: Tensor of shape (N, n_pts, 3)
            sample_lengths: Tensor of shape (N, n_pts, 1)
        """
        self.origins = origins
        self.directions = directions
        self.sample_points = sample_points
        self.sample_lengths = sample_lengths

    @property
    def shape(self):
        """Returns the batch dimensions."""
        return self.origins.shape[:-1]

    @property
    def sample_shape(self):
        """Returns the batch and sample dimensions."""
        return self.sample_points.shape[:-1]

    @property
    def device(self):
        """Returns the device of the sample_points tensor."""
        return self.sample_points.device

    def __getitem__(self, idx):
        """Returns a new RayBundle with sliced tensors."""
        return RayBundle(
            origins=self.origins[idx],
            directions=self.directions[idx],
            sample_points=self.sample_points[idx],
            sample_lengths=self.sample_lengths[idx]
        )

    def reshape(self, *args):
        """Reshapes tensors, preserving last dimensions."""
        new_origins = self.origins.reshape(*args, 3)
        new_directions = self.directions.reshape(*args, 3)
        new_sample_points = self.sample_points.reshape(*args, self.sample_points.shape[-2], 3)
        new_sample_lengths = self.sample_lengths.reshape(*args, self.sample_lengths.shape[-2], 1)
        return RayBundle(new_origins, new_directions, new_sample_points, new_sample_lengths)

    def view(self, *args):
        """Views tensors, preserving last dimensions."""
        new_origins = self.origins.view(*args, 3)
        new_directions = self.directions.view(*args, 3)
        new_sample_points = self.sample_points.view(*args, self.sample_points.shape[-2], 3)
        new_sample_lengths = self.sample_lengths.view(*args, self.sample_lengths.shape[-2], 1)
        return RayBundle(new_origins, new_directions, new_sample_points, new_sample_lengths)

    def _replace(self, **kwargs):
        """Updates attributes based on kwargs."""
        for key, value in kwargs.items():
            if hasattr(self, key):
                setattr(self, key, value)
        return self

    def to(self, device):
        """Moves all tensors to the specified device."""
        return RayBundle(
            origins=self.origins.to(device),
            directions=self.directions.to(device),
            sample_points=self.sample_points.to(device),
            sample_lengths=self.sample_lengths.to(device)
        )
```

## Subtopics

### 2D Skewed Buffer
A 2D temporary buffer storing slanted Projection Ray Planes (PRPs) for parallel horizontal beam storage and vertical viewing ray retrieval [S5]. Physically divided into $n$ modules and diagonally skewed to allow conflict-free writing of entire horizontal beams and conflict-free retrieval of entire vertical rays [S5]. The slanted PRP loads one beam at a time (closest to furthest), shifting each beam left or right to align viewing rays vertically [S5]. Retrieved vertical rays transfer to the Ray Projection Tree (RPT), shifting during transfer to position the closest voxel correctly [S5]. Pitfalls include neighborhood access (requiring multiple parallel 2DSBs and processing rays only after the succeeding slanted PRP loads) and pipeline overlap (using a fourth plane to load the next slanted PRP while three extract the 27-voxel cube) [S5].

## Operating characteristics
- **Time Complexity**: Not given in the sources.
- **Memory Complexity**: Linear in $N$ and $n_{pts}$, specifically $O(N \cdot n_{pts})$ for sample points and lengths, and $O(N)$ for origins and directions [S1, unofficial][S3, unofficial].
- **Measured Performance**: Not given in the sources.
- **Scaling**: Scales with batch size $N$ and sample count $n_{pts}$ [S1, unofficial][S3, unofficial].
- **Strengths**: Enables efficient vectorized operations, indexing, reshaping, and device transfer [S2, unofficial][S3, unofficial].
- **Limitations**: Requires strict dimension management during reshape/view operations [S1, unofficial].
- **When to Use**: Managing batched ray data for volume rendering or neural rendering pipelines [S1, unofficial][S3, unofficial].
- **When Not to Use**: When individual ray processing without batching is required, or when memory constraints are tight for large $N \cdot n_{pts}$ [G].

## Background
Used in VolSDF and NeRF frameworks [S1, unofficial][S3, unofficial]. Facilitates efficient ray data handling for differentiable rendering [S3, unofficial]. The 2D Skewed Buffer variant originates from hardware-based volume visualization systems for arbitrary parallel projection, designed to handle slanted projection ray planes efficiently [S5].
