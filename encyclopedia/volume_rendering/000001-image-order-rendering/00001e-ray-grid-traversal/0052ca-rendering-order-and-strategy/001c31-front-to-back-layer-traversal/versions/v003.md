# Front-to-Back Layer Traversal

Also called: Layer-based Front-to-Back Traversal

## Overview
Front-to-Back Layer Traversal is a rendering order strategy for Matryoshka-like hierarchical data structures that processes cells in front-to-back order along the viewing direction to handle occlusion correctly [S1, unofficial]. It sets itself apart from standard ray-grid traversal methods by operating on pre-defined "layers" composed of six planes, ensuring that outer cells occlude inner cells without requiring per-ray depth sorting [S1, unofficial]. It builds on [Ray-grid traversal](17-ray-grid-traversal.md) but applies a specific plane-grouping logic to manage the visibility of nested structures.

## How it works
**Inputs and Outputs:**
- Input: A Matryoshka layer $l_m$ defined by six planes ($X_{kx}, Y_{ky}, Z_{kz}$ and their opposites), a viewing direction (camera position), and an auxiliary buffer for marking drawable cells.
- Output: A sequence of cell processing instructions ordered front-to-back.

**Data Structures:**
- **Layer Definition:** A layer consists of six planes. The planes are classified into two groups based on the camera position:
    - **Closest Planes:** The three planes closest to the camera. Defined by binary indices $k_x, k_y, k_z \in \{0, 1\}$.
    - **Furthest Planes:** The three planes furthest from the camera. Defined by the opposite indices $k'_x, k'_y, k'_z$.
- **Auxiliary Buffer:** A memory structure used to mark cells as "drawable" during the first pass, allowing them to be processed in the correct order during the second pass.

**Parameters:**
- $k_x, k_y, k_z$: Binary values (0 or 1) determined by the viewing camera to define which planes are closest to the camera position [S1, unofficial].
- $k'_x, k'_y, k'_z$: The opposite values of $k_x, k_y, k_z$ (i.e., $1-k_x$, etc.), defining the furthest planes [S1, unofficial].

**Steps:**
1.  **Classify Planes:** Determine the values of $k_x, k_y, k_z$ based on the camera's viewing direction. These indices identify the planes closest to the viewer.
2.  **Process Closest Planes:**
    -   Identify the three planes closest to the camera: $X=X_{kx}$, $Y=Y_{ky}$, $Z=Z_{kz}$.
    -   **Intra-Plane Ordering:** Within this group, specific ordering rules apply to handle shared cells (edges/corners) correctly:
        -   Cells from plane $X=X_{kx}$ that also belong to plane $Y=Y_{ky}$ must be treated before any other cells from plane $Y=Y_{ky}$ [S1, unofficial].
        -   Plane $Z=Z_{kz}$ must be processed last among the three closest planes because cells from $X=X_{kx}$ and $Y=Y_{ky}$ may occlude cells in $Z=Z_{kz}$ [S1, unofficial].
    -   Use the auxiliary buffer to mark these cells as drawable.
3.  **Process Inner Layers:** If $l_m$ is not the last layer, recursively or iteratively process the next inner layer $l_{m+1}$ using the same logic [S1, unofficial].
4.  **Process Furthest Planes:**
    -   Identify the three planes furthest from the camera: $X=X_{k'x}$, $Y=Y_{k'y}$, $Z=Z_{k'z}$.
    -   **Intra-Plane Ordering:** Within this group, the ordering is inverted to maintain front-to-back consistency relative to the inner layers:
        -   Plane $Z=Z_{k'z}$ is processed first among the three furthest planes because it may occlude cells in $Y=Y_{k'y}$, which in turn may occlude cells in $X=X_{k'x}$ [S1, unofficial].
    -   Process the cells marked in the auxiliary buffer in this specific order.

**Edge Cases and Pitfalls:**
-   **Shared Cells:** Cells at the intersection of planes (edges/corners) must be handled carefully to avoid double processing or incorrect occlusion. The intra-plane ordering rules specifically address this [S1, unofficial].
-   **Camera Position:** The values of $k_x, k_y, k_z$ depend on the camera position. If the camera moves, these values may change, requiring a re-evaluation of the plane grouping [S1, unofficial].
-   **Auxiliary Buffer:** Requires sufficient memory to store the drawable cells for each layer.

## Subtopics

### Intra-Plane Rendering Order
A specific ordering rule for processing cells within the same plane group to handle shared cells (edges/corners) correctly, ensuring correct occlusion between planes [S1, unofficial]. It dictates that for closest planes, cells from $X=X_1$ belonging to $Y=Y_1$ are processed before $Y=Y_1$, and $Z=Z_1$ is last. For furthest planes, $Z=Z_0$ is first, occluding $Y=Y_0$, which occludes $X=X_0$ [S1, unofficial].

## Operating characteristics
-   **Time Complexity:** Linear with respect to the number of cells in the layer, plus the cost of marking and processing the auxiliary buffer. The intra-plane ordering adds a constant overhead per plane group.
-   **Memory Complexity:** Requires an auxiliary buffer proportional to the number of cells in the layer to mark drawable cells.
-   **Strengths:** Correctly handles occlusion for nested Matryoshka structures without per-ray depth sorting. Efficient for parallel projections where the viewing direction is fixed for a frame.
-   **Limitations:** Requires an auxiliary buffer. The ordering logic is specific to the Matryoshka structure and may not generalize to other hierarchical structures. Performance may degrade if the camera position changes frequently, requiring re-computation of plane groups.
-   **When to Use:** When rendering Matryoshka-like data structures with parallel projection and correct occlusion is required.
-   **When Not to Use:** For structures that do not fit the Matryoshka layer model, or when memory for the auxiliary buffer is constrained.

## Background
The method was introduced in the context of the Matryoshka algorithm for speeding up isosurfacing [S1, unofficial]. It addresses the challenge of visualizing active cells in a hierarchical data structure while maintaining correct front-to-back rendering order for occlusion. The approach leverages the geometric properties of the layer planes relative to the camera position.
