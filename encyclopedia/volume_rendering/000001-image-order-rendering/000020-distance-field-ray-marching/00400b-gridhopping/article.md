# Gridhopping

Also called: Ray Marching Polygonization, Sphere Tracing for Polygonization, fast algorithm, ray marching with SDB

## Overview
Gridhopping is an algorithm for transforming a Signed Distance Bound (SDB) into a polygon mesh by combining sphere tracing (ray marching) with traditional polygonization techniques like Marching Cubes [S1]. It efficiently isolates the $O(N^2)$ cells containing the surface of a shape within an $N^3$ grid, achieving $O(N^2 \log N)$ complexity [S1]. Unlike standard enumeration which checks every cell, gridhopping uses rays to "hop" over empty space, making it asymptotically faster for large $N$ [S1].

## How it works
Gridhopping operates on a unit cube domain $[-0.5, 0.5]^3$ discretized into an $N \times N \times N$ grid. It casts $N^2$ rays parallel to the z-axis to traverse the volume, identifying surface-intersecting cells and polygonizing them on the fly.

### Inputs and Outputs
*   **Input**:
    *   `eval_sdb`: A function evaluating the Signed Distance Bound $f_S(\mathbf{x})$ for a shape $S$. The SDB satisfies $|f_S(\mathbf{x})| \le \min_{\mathbf{y} \in f_S^{-1}(0)} \|\mathbf{x} - \mathbf{y}\|_2$ [S1].
    *   `N`: The grid resolution (integer).
    *   `lambda` ($\lambda$): A shrink factor for neural network SDBs to prevent missing surface parts due to overestimation. Typical value: $1.5$ [S1].
*   **Output**: A polygon mesh (triangle list) generated by applying a polygonization routine (e.g., Marching Cubes) to the identified cells [S1].

### Data Structures
*   **Grid**: Implicitly defined by the resolution $N$. Cell indices $(i, j, k)$ map to spatial coordinates.
*   **Ray State**: Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.

### Formulas
*   **Cell Centroids**: The spatial coordinates of the centroid for cell $(i, j, k)$ are:
    $$ x_i = -\frac{1}{2} + \frac{1}{2N} + \frac{i}{N} $$
    $$ y_j = -\frac{1}{2} + \frac{1}{2N} + \frac{j}{N} $$
    $$ z_k = -\frac{1}{2} + \frac{1}{2N} + \frac{k}{N} $$
    [S1]
*   **Surface Intersection Threshold**: A cell is considered to possibly intersect the surface if the absolute SDB value is less than or equal to the distance from the cell center to its farthest corner (half-diagonal):
    $$ \text{threshold} = \sqrt{ \left(\frac{1}{2N}\right)^2 + \left(\frac{1}{2N}\right)^2 + \left(\frac{1}{2N}\right)^2 } = \frac{\sqrt{6}}{2N} $$
    [S1]
*   **Max Distance**: The maximum distance a ray can travel in a single step is bounded to prevent overshooting the top of the unit cube ($z=0.5$):
    $$ t_{max} = 1.05 \times (0.5 - z) $$
    [S1]

### Pseudocode
The following pseudocode implements the core gridhopping loop. It assumes a helper function `trace_ray` which performs sphere tracing on the SDB and returns the distance $t$ to the surface or the max distance if no surface is found within the limit. It also assumes a `polygonize` function that takes cell indices and the SDB evaluator to generate triangles.

```python
function apply_grid_hopping(eval_sdb, N, lambda=1.5):
    # Initialize empty mesh
    mesh = EmptyMesh()

    # Iterate over all x, y grid positions
    for i from 0 to N - 1:
        for j from 0 to N - 1:
            # Initialize z index
            k = 0
            
            while true:
                # 1. Calculate ray origin at current cell centroid
                x = -0.5 + 1.0/(2.0*N) + i/N
                y = -0.5 + 1.0/(2.0*N) + j/N
                z = -0.5 + 1.0/(2.0*N) + k/N
                
                # 2. Define ray direction (+z)
                direction = [0.0, 0.0, 1.0]
                
                # 3. Calculate max travel distance to stay within volume boundary
                # The volume extends to z=0.5. We allow a 5% overshoot.
                max_dist = 1.05 * (0.5 - z)
                
                # 4. Required distance to trigger polygonization
                # This is the half-diagonal of the cell
                required_dist = sqrt(6.0) / (2.0 * N)
                
                # 5. Perform sphere tracing (ray marching)
                # The SDB evaluator is shrunk by lambda to handle neural network overestimation
                # trace_ray returns the distance 't' to the nearest surface or max_dist
                t = trace_ray(
                    origin=[x, y, z],
                    direction=direction,
                    sdb_func=lambda p: eval_sdb(p) / lambda,
                    max_distance=max_dist,
                    threshold=required_dist
                )
                
                # 6. Update position and cell index
                z_new = z + t
                # Calculate new k index based on new z position
                # Note: The formula maps z back to the grid index space
                k_new = floor(N * (z_new + 0.5 - 1.0/(2.0*N)))
                
                # 7. Check exit conditions
                # If we have moved beyond the last cell index or the volume boundary
                if k_new > N - 1 or z_new > 1.05/2.0:
                    break
                
                # 8. Polygonize the cell we just arrived at (or the cell where we stopped)
                # The algorithm polygonizes the cell (i, j, k_new) if the ray stopped
                # within the volume. If the ray hit the surface, k_new is the cell index
                # of the hit. If the ray escaped (t=max_dist), k_new is the next cell.
                # The source code polygonizes the cell corresponding to the new k.
                # [G] The source code calls polygonize on (i, j, k_new) inside the loop
                # before incrementing k. However, the logic implies polygonizing the cell
                # where the surface was found or the cell being traversed.
                # Based on the source: "Polygonize cell (i, j, k)" happens after update.
                # We polygonize the cell at the new position.
                mesh.add_triangles(polygonize(i, j, k_new, eval_sdb, lambda))
                
                # 9. Advance to next cell for the next iteration of the while loop
                k = k_new

    return mesh

function trace_ray(origin, direction, sdb_func, max_distance, threshold):
    """
    Standard sphere tracing loop.
    Returns the distance t to the surface if |f(p)| <= threshold.
    Returns max_distance if the ray escapes or exceeds max_distance.
    """
    t = 0.0
    while t < max_distance:
        p = origin + t * direction
        dist = sdb_func(p)
        
        # If the distance is small enough, we hit the surface
        if abs(dist) <= threshold:
            return t
        
        # Advance by the distance
        t = t + dist
        
        # Safety break if dist is non-positive (degenerate SDB)
        if dist <= 0:
            # [G] In standard SDFs, dist < 0 means inside. 
            # For SDBs, |f| <= dist_to_surface. 
            # If we are inside, we might need to handle differently, 
            # but gridhopping typically looks for surface crossings.
            # If the SDB underestimates, we might get stuck. 
            # The source uses |f| <= threshold, so negative values are treated 
            # as close to surface.
            break
            
    return max_distance
```

### Parameters
*   **N**: Grid resolution. Higher $N$ increases accuracy but also computational cost.
*   **lambda** ($\lambda$): Shrink factor for SDBs. Default $1.5$ [S1].
*   **Threshold**: $\frac{\sqrt{6}}{2N}$ [S1].

### Edge Cases and Pitfalls
*   **Neural Network Overestimation**: Neural network approximations of SDBs may overestimate the distance to the surface, causing the ray to skip over thin features. This is mitigated by shrinking the SDB value by a factor $\lambda$ (typically $1.5$) during evaluation [S1].
*   **Boundary Overshoot**: The max distance is set to $1.05 \times (0.5 - z)$ to ensure the ray does not overshoot the top of the unit cube significantly [S1].
*   **Degenerate SDBs**: If the SDB function returns non-positive distances in empty space (violating the SDB property), the ray might terminate incorrectly. The algorithm assumes $|f_S(\mathbf{x})|$ is a valid bound [S1].

## Subtopics

### Marching Cubes
The standard polygonization algorithm used to generate triangles from the SDB values at the vertices of each identified cell. It is chosen for its robustness and widespread support [S1].

### Signed Distance Bounds (SDB)
A generalization of SDFs where the function value is an upper bound on the true distance. Gridhopping is specifically designed to work with SDBs, which are common in neural shape representations [S1].

## Operating characteristics
*   **Time Complexity**: $O(N^2 \log N)$ for a grid with $N^3$ cells [S1]. This is asymptotically faster than enumeration ($O(N^3)$) and continuation methods for large $N$ [S1].
*   **Memory Complexity**: $O(N^3)$ to store the SDB grid if it is pre-computed, or $O(1)$ if the SDB is evaluated on-the-fly (e.g., via a neural network). The output mesh size is proportional to the surface area, $O(N^2)$ [S1].
*   **Performance**: On an Nvidia GeForce RTX 2060 Mobile GPU, batching neural network computations in chunks of $\approx 100,000$ yields significant speedups. Gridhopping is significantly faster than CPU-based enumeration [S1].
*   **Strengths**: High performance for large grids, simplicity of implementation, portability [S1].
*   **Limitations**: Requires the SDB to be a valid bound. The shrink factor $\lambda$ is a heuristic that may need tuning for different shapes [S1].

## Background
Gridhopping was introduced by Nenad Markus and Mirko Sužnjević in 2021 [S1]. The method was developed to address the need for efficient polygonization of Signed Distance Bounds, particularly those generated by deep learning models (neural SDBs) for 3D shape modeling. It combines the efficiency of ray marching with the geometric accuracy of Marching Cubes. The algorithm has been tested on primitive shapes, point cloud-derived SDBs, and neural network approximations [S1].
