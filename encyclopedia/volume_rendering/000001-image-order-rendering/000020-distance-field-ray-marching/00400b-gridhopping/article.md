# Gridhopping

Also called: Ray Marching Polygonization, Sphere Tracing for Polygonization, fast algorithm, ray marching with SDB

## Overview
Gridhopping is an algorithm for transforming a Signed Distance Bound (SDB) into a polygon mesh by combining sphere tracing (ray marching) with traditional polygonization techniques like Marching Cubes [S1]. It efficiently isolates the $O(N^2)$ cells containing the surface of a shape within an $N^3$ grid, achieving $O(N^2 \log N)$ complexity [S1]. Unlike standard enumeration which checks every cell, gridhopping uses rays to "hop" over empty space, making it asymptotically faster for large $N$ [S1].

## How it works
Gridhopping operates on a unit cube domain $[-0.5, 0.5]^3$ discretized into an $N \times N \times N$ grid [S1]. It casts $N^2$ rays parallel to the z-axis to traverse the volume, identifying surface-intersecting cells and polygonizing them on the fly [S1].

### Inputs and Outputs
*   **Input**:
    *   `eval_sdb`: A function evaluating the Signed Distance Bound $f_S(\mathbf{x})$ for a shape $S$. The SDB satisfies $|f_S(\mathbf{x})| \le \min_{\mathbf{y} \in f_S^{-1}(0)} \|\mathbf{x} - \mathbf{y}\|_2$ [S1].
    *   `N`: The grid resolution (integer) [S1].
    *   `lambda` ($\lambda$): A shrink factor for neural network SDBs to prevent missing surface parts due to overestimation. Typical value: $1.5$ [S1].
*   **Output**: A polygon mesh (triangle list) generated by applying a polygonization routine (e.g., Marching Cubes) to the identified cells [S1].

### Data Structures
*   **Grid**: Implicitly defined by the resolution $N$, where cell indices $(i, j, k)$ map to spatial coordinates via the centroid formulas [S1].
*   **Ray State**: Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$ [G].

### Formulas
*   **Cell Centroids**: The spatial coordinates of the centroid for cell $(i, j, k)$ are:
    $$ x_i = -\frac{1}{2} + \frac{1}{2N} + \frac{i}{N} $$
    $$ y_j = -\frac{1}{2} + \frac{1}{2N} + \frac{j}{N} $$
    $$ z_k = -\frac{1}{2} + \frac{1}{2N} + \frac{k}{N} $$
    [S1]
*   **Surface Intersection Threshold**: A cell is considered to possibly intersect the surface if the absolute SDB value is less than or equal to the distance from the cell center to its farthest corner (half-diagonal):
    $$ \text{threshold} = \sqrt{ \left(\frac{1}{2N}\right)^2 + \left(\frac{1}{2N}\right)^2 + \left(\frac{1}{2N}\right)^2 } = \frac{\sqrt{6}}{2N} $$
    [S1]
*   **Max Distance**: The maximum distance a ray can travel in a single step is bounded to prevent overshooting the top of the unit cube ($z=0.5$):
    $$ t_{max} = 1.05 \times (0.5 - z) $$
    [S1]

import math

def apply_grid_hopping(eval_sdb, N, lambda_val=1.5):
    mesh = []
    for i in range(N):
        for j in range(N):
            k = 0
            while True:
                # 1. Calculate ray origin at current cell centroid
                x = -0.5 + 1.0/(2.0*N) + i/N
                y = -0.5 + 1.0/(2.0*N) + j/N
                z = -0.5 + 1.0/(2.0*N) + k/N
                
                # 2. Define ray direction (+z)
                direction = [0.0, 0.0, 1.0]
                
                # 3. Calculate max travel distance to stay within volume boundary
                max_dist = 1.05 * (0.5 - z)
                
                # 4. Required distance to trigger polygonization (half-diagonal)
                required_dist = math.sqrt(6.0) / (2.0 * N)
                
                # 5. Perform sphere tracing (ray marching)
                t = trace_ray([x, y, z], direction, eval_sdb, max_dist, required_dist, lambda_val)
                
                # 6. Update position and cell index
                z = z + t
                k = math.floor(N * (z + 0.5 - 1.0/(2.0*N)))
                
                # 7. Check exit conditions
                if k > N - 1 or z > 1.05/2.0:
                    break
                
                # 8. Polygonize the cell where the ray stopped
                # [S1] Polygonize cell (i, j, k) using Marching Cubes on the SDB values at its vertices
                mesh.extend(polygonize_cell(i, j, k, eval_sdb, lambda_val))
                
                # 9. Advance to next cell for the next iteration
                k += 1
    return mesh

### Parameters
*   **N**: Grid resolution. Higher $N$ increases accuracy but also computational cost [S1].
*   **lambda** ($\lambda$): Shrink factor for SDBs. Default $1.5$ [S1].
*   **Threshold**: $\frac{\sqrt{6}}{2N}$ [S1].

### Edge Cases and Pitfalls
*   **Neural Network Overestimation**: Neural network approximations of SDBs may overestimate the distance to the surface, causing the ray to skip over thin features. This is mitigated by shrinking the SDB value by a factor $\lambda$ (typically $1.5$) during evaluation [S1].
*   **Boundary Overshoot**: The max distance is set to $1.05 \times (0.5 - z)$ to ensure the ray does not overshoot the top of the unit cube significantly [S1].
*   **Degenerate SDBs**: If the SDB function returns non-positive distances in empty space (violating the SDB property), the ray might terminate incorrectly. The algorithm assumes $|f_S(\mathbf{x})|$ correctly bounds the distance to the surface [S1].

## Subtopics

### Marching Cubes
A standard polygonization algorithm that generates triangles from scalar field values at grid vertices [S1]. It is chosen here because it reliably converts the SDB samples at identified cells into a watertight mesh [S1].

### Signed Distance Bounds (SDB)
A representation where $|f_S(\mathbf{x})| \le \min_{\mathbf{y} \in f_S^{-1}(0)} \|\mathbf{x} - \mathbf{y}\|_2$, meaning it underestimates the true distance to the surface but never overestimates it [S1]. It is preferred over exact SDFs for neural shape representations because it accommodates a broader class of learned approximations [S1].

## Operating characteristics
*   **Time Complexity**: $O(N^2 \log N)$ for a grid with $N^3$ cells [S1]. This is asymptotically faster than enumeration ($O(N^3)$) and continuation methods for large $N$ [S1].
*   **Memory Complexity**: $O(N^3)$ to store the SDB grid if it is pre-computed, or $O(1)$ if the SDB is evaluated on-the-fly (e.g., via a neural network) [S1]. The output mesh size is proportional to the surface area, $O(N^2)$ [S1].
*   **Performance**: On an Nvidia GeForce RTX 2060 Mobile GPU, batching neural network computations in chunks of $\approx 100,000$ yields significant speedups. Gridhopping is significantly faster than CPU-based enumeration [S1].
*   **Strengths**: High performance for large grids, simplicity of implementation, and portability [S1].
*   **Limitations**: Requires the SDB to be a valid bound. The shrink factor $\lambda$ must be tuned to balance mesh completeness and marching speed, with $\lambda=1.5$ empirically validated for tested shapes [S1].

## Background
Developed by Markus and Sužnjević [S1]. The method was developed to address the need for efficient polygonization of Signed Distance Bounds, particularly those generated by deep learning models (neural SDBs) for 3D shape modeling [S1]. It combines the efficiency of ray marching with the geometric accuracy of Marching Cubes [S1]. The algorithm has been tested on primitive shapes, point cloud-derived SDBs, and neural network approximations [S1].
