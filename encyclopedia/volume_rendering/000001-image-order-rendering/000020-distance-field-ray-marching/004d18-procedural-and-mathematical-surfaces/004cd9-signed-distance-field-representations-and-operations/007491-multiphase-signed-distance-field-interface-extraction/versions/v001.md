# Multiphase Signed Distance Field Interface Extraction

Also called: Multiphase Interface Extraction, Multiphase SDF evaluation, PhaseTree interface computation, Thin Volume Interface

## Overview
This method extracts the complete set of thin, non-manifold interfaces separating distinct material phases within a multiphase Signed Distance Field (SDF) model [S1]. It solves the problem of explicitly defining the boundaries between multiple coexisting phases, including complex junctions where three or more phases meet, which are often ambiguous or lost in monolithic SDF representations [S1]. Unlike solid-textured implicit surfaces where phases are indistinguishable, or object-space multiphase fields that lack Lipschitz guarantees, this method preserves the 1-Lipschitz property of individual phases to enable standard SDF algorithms like Sphere Tracing while providing explicit geometric handles for each phase [S1].

## How it works
The method computes a signed distance field representing the interface between two specific phases $i$ and $j$ by intersecting their "inflated" regions. This intersection creates a thin volume $\mathcal{S}$ that embeds the boundary $\partial\Omega_{ij}$ [S1]. The process relies on the PhaseTree construction, which maintains a 1-Lipschitz SDF for each phase $\mathcal{A}_k$ [S1].

### Inputs and Outputs
*   **Inputs**:
    *   $n$: The total number of phases in the model.
    *   $\phi_{\mathcal{A}_k}(\mathbf{p})$: The 1-Lipschitz signed distance field function for phase $k$, where $k \in [1, n]$.
    *   $\varepsilon$: A small positive offset value used to inflate the phases for intersection calculation. The specific numerical value is not provided in the sources [S1].
*   **Outputs**:
    *   $\Phi$: A vector of $n$ signed distance fields, where each entry $\phi_k$ represents the phase function for phase $k$ in the context of the extracted interfaces.
    *   $f_{ij}(\mathbf{p})$: The SDF of the thin interface volume between phases $i$ and $j$.

### Data Structures
The method operates on procedural functions. No explicit grid or voxel data structure is required; the SDFs are evaluated analytically or via neural networks (e.g., SIREN) or hierarchical trees (e.g., BlobTree) [S1]. The output $\Phi$ is a logical collection of $n$ scalar fields.

### Steps and Formulas

1.  **Ensure 1-Lipschitz Continuity**:
    Each phase's SDF $\phi_{\mathcal{A}_k}$ must satisfy the Lipschitz condition with constant 1, i.e., $|\phi_{\mathcal{A}_k}(\mathbf{p}_1) - \phi_{\mathcal{A}_k}(\mathbf{p}_2)| \le \|\mathbf{p}_1 - \mathbf{p}_2\|$ [G].
    *   For **BlobTree** models, convert the tree to a 1-Lipschitz SDF [S1].
    *   For **SIREN** (neural) models, compute the theoretical Lipschitz bound $\lambda$ or sample the maximum gradient magnitude $\lambda$. Define the normalized function as $f/\lambda$ to ensure 1-Lipschitz continuity. Restrict queries to the learned area using a proxy sphere [S1].

2.  **Compute Minimum Inter-Phase Distance ($f$)**:
    Calculate the global minimum distance between any pair of distinct phases, inflated by $\varepsilon$. This value $f$ serves as a lower bound for the interface thickness and ensures that interfaces do not overlap incorrectly.
    $$f = \min_{(i,j) \in [1, n]^2, i \neq j} \max(\phi_{\mathcal{A}_i}(\mathbf{p}) - \varepsilon, \phi_{\mathcal{A}_j}(\mathbf{p}) - \varepsilon)$$
    Here, $f$ is a scalar field (or a conservative lower bound scalar if precomputed) representing the tightest gap between any two phases minus the inflation radius [S1].

3.  **Compute Two-Phase Interface SDF ($f_{ij}$)**:
    For a specific pair of phases $i$ and $j$, the SDF of the thin interface volume $\mathcal{S}$ is computed by intersecting the inflated phases:
    $$f_{ij}(\mathbf{p}) = \max(\phi_{\mathcal{A}_i}(\mathbf{p}) - \varepsilon, \phi_{\mathcal{A}_j}(\mathbf{p}) - \varepsilon)$$
    The operator $I(\mathcal{A}_k, \varepsilon)$ denotes the inflation of phase $k$ by $\varepsilon$. The intersection is defined as $\mathcal{S} = I(\mathcal{A}_i, \varepsilon) \cap I(\mathcal{A}_j, \varepsilon)$ [S1].

4.  **Construct Complete Interface Set ($\Phi$)**:
    To extract the complete set of interfaces for all $n$ phases, update the phase functions $\phi_k$ in the output vector $\Phi$.
    
    For a **two-phase representation** (isolating interface between $i$ and $j$):
    $$\phi_k = \begin{cases} \max(f, \phi_{\mathcal{A}_k}) & \forall k \in \{i, j\} \\ \infty & \text{otherwise} \end{cases}$$
    
    For the **complete set of interfaces** (all phases):
    $$\Phi = (\phi_1, \phi_2, \dots, \phi_n)$$
    Where for each $k \in [1, n]$:
    $$\phi_k(\mathbf{p}) = \max(f(\mathbf{p}), \phi_{\mathcal{A}_k}(\mathbf{p}))$$
    
    Note: In the complete set formulation, $f$ is the field computed in Step 2 [S1]. The use of $\max(f, \phi_{\mathcal{A}_k})$ effectively clips the phase distance, ensuring that the phase boundary is defined relative to the nearest other phase's inflated boundary, thereby creating the thin interface volume [S1].

### Pseudocode

```python
def compute_multiphase_interfaces(phases, epsilon):
    """
    Computes the thin interface SDFs for a multiphase model.
    
    Args:
        phases: A list of n callable functions [phi_A_1, ..., phi_A_n].
                Each phi_A_k(p) returns the signed distance for phase k.
                It is assumed these are 1-Lipschitz.
        epsilon: Float, the inflation radius for interface extraction.
        
    Returns:
        phi_output: A list of n callable functions representing the 
                    multiphase interface SDFs.
        f_field: The scalar field representing the minimum inter-phase distance.
    """
    n = len(phases)
    
    # Step 1: Ensure 1-Lipschitz (Assumed pre-condition for inputs)
    # If using SIREN, inputs should already be normalized by lambda.
    
    # Step 2: Compute f_field = min_{i!=j} max(phi_A_i - eps, phi_A_j - eps)
    # We evaluate this field at query points. For implementation, we define
    # a function that computes f(p) on the fly.
    
    def f_field(p):
        min_val = infinity
        for i in range(n):
            for j in range(i + 1, n):
                # Compute inflated distances
                dist_i = phases[i](p) - epsilon
                dist_j = phases[j](p) - epsilon
                # Intersection of inflated phases
                interface_val = max(dist_i, dist_j)
                if interface_val < min_val:
                    min_val = interface_val
        return min_val

    # Step 3 & 4: Construct the output phase functions
    phi_output = []
    for k in range(n):
        def phi_k(p, k=k):
            # phi_k = max(f, phi_A_k)
            # Note: f is the field from Step 2. 
            # In a real renderer, f(p) might be precomputed or cached.
            # Here we compute it directly, which is O(n^2) per query.
            # Optimization: Precompute f_field if memory allows.
            f_val = f_field(p)
            return max(f_val, phases[k](p))
        phi_output.append(phi_k)
        
    return phi_output, f_field
```

### Parameters
*   $\varepsilon$: Inflation radius. Not given in the sources [S1].
*   $\lambda$: Lipschitz bound for SIREN models. Computed theoretically or via sampling [S1].

### Edge Cases and Pitfalls
*   **Sphere Tracing Performance**: Near interfaces between phases, the signed distance value may become locally smaller due to the $\max(f, \phi_{\mathcal{A}_k})$ operation. This causes Sphere Tracing to take shorter steps, increasing the number of iterations required for convergence [S1].
*   **Monolithic Merging**: Aggressively merging multiple phases into a single mono-phase SDF when the geometry contains many internal interfaces significantly degrades ray-object intersection performance [S1].
*   **Lipschitz Violation**: If the input phases are not 1-Lipschitz, Sphere Tracing may tunnel. SIREN models require normalization by $\lambda$ [S1].
*   **Boundary Queries**: For SIREN models, queries should be restricted to the learned area using a proxy sphere to avoid undefined behavior outside the training domain [S1].

## Operating characteristics
*   **Time Complexity**: The computation of the complete interface set $\Phi$ requires evaluating the minimum over all pairs of phases. For $n$ phases, this involves $O(n^2)$ comparisons per query point if $f$ is computed on-the-fly. This can be a bottleneck for scenes with many phases [S1].
*   **Memory Complexity**: The PhaseTree representation is highly compact, requiring only a few kilobytes of storage for the construction tree, compared to several megabytes for sampled vector volumes [S1].
*   **Strengths**:
    *   Fully resolution-independent and procedural [S1].
    *   Preserves 1-Lipschitz continuity, ensuring compatibility with Sphere Tracing and other SDF algorithms [S1].
    *   Explicitly encodes phase geometry, allowing individual phases to be manipulated as first-class primitives [S1].
    *   Can be compiled into GLSL for efficient GPU execution [S1].
*   **Limitations**:
    *   Performance degrades with an increasing number of phases due to the $O(n^2)$ pairwise comparisons for $f$ [S1].
    *   Requires careful handling of Lipschitz bounds for neural representations (SIREN) [S1].
    *   Current authoring workflow relies on scripting construction trees, which may be less intuitive than direct modeling [S1].

## Background
The method is part of the **PhaseTree** framework, which extends traditional SDFs with native multiphase capabilities [S1]. It builds on the principle that a scene can be defined by a scalar field where the zero-level set represents the surface [G].

*   **Origin**: The PhaseTree concept was introduced in the paper "The PhaseTree: Multiphase Signed Distance Fields" [S1].
*   **Related Models**:
    *   **SIREN**: Sinusoidal Implicit Neural Representations, introduced by Sitzmann et al. in 2020, are compatible with this method when normalized to be 1-Lipschitz [S1].
    *   **BlobTree**: Introduced by Wyvill et al. in 1999, BlobTrees can be converted to 1-Lipschitz SDFs and integrated into the PhaseTree framework [S1].
*   **Comparison to Alternatives**:
    *   Unlike **solid-textured implicit surfaces**, PhaseTree explicitly encodes phase geometry [S1].
    *   Unlike **multiscale vector volumes**, it uses compact trees instead of sampled fields, preserving resolution independence and Lipschitz guarantees [S1].
    *   Unlike **object-space multiphase implicit functions** (e.g., Yuan et al. 2012), it guarantees 1-Lipschitz continuity, enabling standard SDF algorithms without reinitialization [S1].
    *   Unlike **unsigned distance field reconstruction** methods, it partitions space into labeled regions with explicit phase information, ensuring consistent non-manifold interfaces [S1].
