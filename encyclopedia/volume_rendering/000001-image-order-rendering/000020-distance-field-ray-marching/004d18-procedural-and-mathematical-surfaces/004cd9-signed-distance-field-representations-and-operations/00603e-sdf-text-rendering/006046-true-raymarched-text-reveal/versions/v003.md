# True Raymarched Text Reveal

Also called: Raymarched SDF Heading, Text load-in v2, true raymarching

## Overview
True Raymarched Text Reveal is a technique that renders text animations by converting DOM glyphs into a 3D Signed Distance Field (SDF), marching rays through it, and revealing the text using smooth-min metaballs and SDF-gradient lighting [S1, unofficial]. It differs from its sibling [RayMarchedHeading](18123-sdf-text-rendering.md) by performing actual 3D raymarching through an extruded SDF rather than marching 2D blur taps along a smear line [S1, unofficial].

## How it works
**Inputs:** DOM heading glyphs at measured positions, scene parameters (`MAX_STEPS`, `SURFACE_DIST`, `smooth-min k`, `front softness`) [S1, unofficial].
**Outputs:** A rendered image of the text reveal, eventually crossfading to the selectable DOM heading [S1, unofficial].

**Data Structures:**
*   **SDF Texture:** A 3D texture representing the extruded SDF of the text [S1, unofficial].
*   **Ray State:** Per-pixel ray origin and direction [S1, unofficial].

**Steps:**
1.  **SDF Generation:** Rasterize DOM heading glyphs at their measured positions on a 2D grid [S1, unofficial]. Convert the rasterized glyphs into a real Signed Distance Field (SDF) using an exact Euclidean distance transform [S1, unofficial]. The implementation uses the Felzenszwalb–Huttenlocher algorithm with tiny-sdf style seeding to handle sub-pixel edges [S1, unofficial]. Extrude the 2D SDF into 3D space to create a volumetric representation of the text [S1, unofficial].
2.  **Ray Setup:** Set the ray origin and per-pixel ray direction [S1, unofficial]. Use CSS pixels as world units so that a ray passing through pixel coordinate $q$ in the viewport hits the text plane exactly at $q$, keeping the WebGL rendering aligned with the DOM layout [S1, unofficial].
3.  **Raymarching:** March rays through the 3D SDF [S1, unofficial]. In each step, evaluate the SDF distance $d$ at the current ray position [S1, unofficial]. Advance the ray by distance $d$ [S1, unofficial]. Repeat up to `MAX_STEPS` iterations [S1, unofficial]. Terminate if the distance $d$ is within `SURFACE_DIST` (indicating a hit) or if `MAX_STEPS` is reached [S1, unofficial].
4.  **Reveal Logic:** The text is revealed via a smooth-max intersection with a sweeping half-space [S1, unofficial]. Metaball droplets are placed on the front of the reveal sweep [S1, unofficial]. These droplets melt into the emerging glyphs using a smooth-min function controlled by the parameter `smooth-min k` [S1, unofficial]. The `front softness` parameter controls the softness of the reveal sweep [S1, unofficial].
5.  **Shading:** Compute normals at hit points using the SDF gradient [S1, unofficial]. The implementation uses Inigo Quilez's `getNormal` method [S1, unofficial]. Calculate lighting as ambient (based on `normal.y`) plus diffuse lighting [S1, unofficial]. Apply a Beer's-law exponential depth fade to the lighting [S1, unofficial].
6.  **Handoff:** As the animation progress settles, the shader converges onto analytically antialiased flat glyphs [S1, unofficial]. Crossfade from the raymarched shader to the selectable DOM heading [S1, unofficial].

**Formulas:**
*   Ray advancement: $P_{i+1} = P_i + d_i \cdot \vec{r}$, where $P_i$ is the current position, $d_i$ is the sampled SDF distance, and $\vec{r}$ is the normalized ray direction [S1, unofficial].
*   Beer's-law depth fade: $C_{final} = (C_{ambient} + C_{diffuse}) \cdot e^{-\alpha \cdot L}$, where $\alpha$ is the depth fade factor and $L = \|P_{hit} - P_{origin}\|$ is the ray length [S1, unofficial].
*   Smooth-min blending: $f_{smoothmin}(a, b, k) = -\frac{\ln(e^{-k a} + e^{-k b})}{k}$, where $k$ controls the blending sharpness [G].

**Parameters:**
*   `MAX_STEPS`: Maximum number of raymarch steps allowed per ray [S1, unofficial].
*   `SURFACE_DIST`: Distance threshold below which a ray is considered to have hit the surface [S1, unofficial].
*   `smooth-min k`: Smoothness parameter controlling the blending of the smooth-min function [S1, unofficial].
*   `front softness`: Controls the softness of the reveal sweep [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Sub-pixel edges require careful handling during SDF generation (Felzenszwalb–Huttenlocher with tiny-sdf seeding) to avoid aliasing artifacts [S1, unofficial].
*   **Alignment:** Using CSS pixels as world units is critical to keep WebGL and DOM aligned; deviation causes misalignment [S1, unofficial].
*   **Termination:** Rays must terminate at `MAX_STEPS` to prevent infinite loops on miss cases [G].

**Pseudocode:**
```python
def raymarch_text_reveal(ray_origin, ray_direction, sdf_texture, params):
    """
    Renders a single pixel of the raymarched text reveal.
    Args:
        ray_origin: vec3 origin of the ray.
        ray_direction: vec3 direction of the ray.
        sdf_texture: 3D texture containing the extruded SDF of the text.
        params: Object containing MAX_STEPS, SURFACE_DIST, smooth_min_k, 
                front_softness, sweep_offset, droplet_pos, depth_fade_factor.
    Returns:
        vec3: Final color of the pixel.
    """
    current_pos = ray_origin
    color = vec3(0.0)
    hit = False
    
    for i in range(params.MAX_STEPS):
        dist = sdf_texture.sample(current_pos)
        if dist < params.SURFACE_DIST:
            hit = True
            break
        current_pos += ray_direction * dist
        
    if hit:
        # Compute normals at hit points using the SDF gradient (Inigo Quilez's getNormal)
        eps = 0.001
        dx = sdf_texture.sample(current_pos + vec3(eps, 0, 0)) - sdf_texture.sample(current_pos - vec3(eps, 0, 0))
        dy = sdf_texture.sample(current_pos + vec3(0, eps, 0)) - sdf_texture.sample(current_pos - vec3(0, eps, 0))
        dz = sdf_texture.sample(current_pos + vec3(0, 0, eps)) - sdf_texture.sample(current_pos - vec3(0, 0, eps))
        normal = normalize(vec3(dx, dy, dz))
        
        # Lighting: ambient from normal.y plus diffuse
        ambient = vec3(0.5) * max(normal.y, 0.0) + vec3(0.5)
        diffuse = max(dot(normal, params.light_dir), 0.0) * params.light_color
        
        # Beer's-law exponential depth fade
        depth = length(current_pos - ray_origin)
        fade = exp(-params.depth_fade_factor * depth)
        color = (ambient + diffuse) * fade
        
        # Reveal: smooth-max intersection with a sweeping half-space
        half_space = dot(current_pos, vec3(0, 1, 0)) - params.sweep_offset
        # Metaball droplets on the front, melting via smooth-min
        droplet_dist = length(current_pos - params.droplet_pos)
        # smooth-max(a, b, k) = -smoothmin(-a, -b, k)
        reveal = -smoothmin_exp(-half_space, -droplet_dist, params.smooth_min_k)
        
        if reveal > 0.0:
            color *= smoothstep(0.0, params.front_softness, reveal)
        else:
            color = vec3(0.0)
            
    return color

def smoothmin_exp(a, b, k):
    """Exponential smooth-min function for metaball blending."""
    h = exp(-k * a)
    return -log(h + exp(-k * b)) / k
```

## Operating characteristics
*   **Strengths:** True 3D raymarching allows for complex lighting, shadows, and interactions (metaballs) that 2D techniques cannot achieve [S1, unofficial]. The alignment with DOM ensures crisp final output [S1, unofficial].
*   **Limitations:** Requires careful tuning of parameters to avoid artifacts [S1, unofficial].

## Background
The technique was developed by milesroxas and added to the Suits & Sandals website as part of an immersive demo section [S1, unofficial]. It is built from the techniques described in Maxime Heckel's "Painting with Math: A Gentle Study of Raymarching" [S1, unofficial]. It serves as an improved approach to the previous "RayMarchedHeading" attempt, which was not true raymarching [S1, unofficial].
