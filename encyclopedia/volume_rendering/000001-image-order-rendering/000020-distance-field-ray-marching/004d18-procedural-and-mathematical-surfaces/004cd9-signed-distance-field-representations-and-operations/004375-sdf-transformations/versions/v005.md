# SDF Transformations
Also called: SDF Composition, SDF Modifiers

## Overview
SDF Transformations modify the spatial domain of a Signed Distance Field (SDF) by applying geometric transformations to the query point $\mathbf{p}$ before evaluating the primitive's distance function [S1, unofficial]. This technique allows for the creation of complex procedural geometry, such as tiling, twisting, and dynamic animation, without altering the underlying primitive definitions or requiring mesh processing [S1, unofficial][S2]. Unlike static composition which combines primitives via Boolean operations, transformations map the world space into the local space of the primitive, enabling effects like repetition and deformation [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $\mathbf{p}$ (world space), transformation parameters (e.g., spacing, twist angle, time $t$), and the base SDF function $f_{\text{base}}$ [S1, unofficial].
*   **Output:** Transformed distance value $d = f_{\text{base}}(\mathbf{p}')$, where $\mathbf{p}'$ is the transformed point [S1, unofficial].

**Data Structures:**
No specific data structures are required beyond the transformation parameters and the base SDF function [S1, unofficial]. For dynamic operators, a Holistic Scene Dynamics (HSD) function may be used to generate transformation matrices based on time and object input data [S2].

**Steps:**
1.  **Identify Transformation Type:** Determine if the transformation is static (e.g., repetition, deformation) or dynamic (e.g., time-varying animation) [S1, unofficial][S2].
2.  **Compute Transformed Point $\mathbf{p}'$:** Apply the inverse of the desired geometric transformation to the query point $\mathbf{p}$ .
    *   For **Repetition (Tiling)**: Apply modular arithmetic to wrap the space [S1, unofficial].
        $$ \mathbf{p}' = \text{mod}(\mathbf{p}, \mathbf{s}) - \frac{\mathbf{s}}{2} $$
        where $\mathbf{s}$ is the spacing vector [S1, unofficial].
    *   For **Deformation**: Apply a non-linear function to the position [S1, unofficial].
        $$ \mathbf{p}' = \text{twist}(\mathbf{p}) $$
        where $\text{twist}$ rotates the point around an axis based on its height or distance [S1, unofficial].
    *   For **Dynamic Operators**: Calculate a dynamic variation using the Holistic Scene Dynamics Function $f_{\text{HSD}}(\mathbf{d}, t)$, where $\mathbf{d}$ is object input data (such as world space position or grid cell vector) and $t$ is simulation time [S2]. This generates a transformation matrix $M$ [S2].
3.  **Evaluate Base SDF:** Compute the distance using the transformed point [S1, unofficial].
    $$ d = f_{\text{base}}(\mathbf{p}') $$
4.  **Dynamic Ray Transformation (Optional):** In dynamic instancing pipelines, apply an additional transformation to the position on the ray from the camera to the SDF component at each iteration of the ray marching algorithm to preserve the correct form of the SDF during animation [S2].

**Pseudocode:**
```python
def sdf_transform(p, transform_type, params, f_base):
    """
    Apply a transformation to point p before evaluating f_base.
    
    Args:
        p: vec3, query point in world space
        transform_type: str, 'repetition', 'deformation', 'dynamic'
        params: dict, transformation parameters
        f_base: callable, base SDF function
        
    Returns:
        float, transformed distance
    """
    if transform_type == 'repetition':
        spacing = params['spacing']
        # p' = mod(p, spacing) - spacing/2 (component-wise)
        p_prime = p % spacing - spacing / 2.0
        return f_base(p_prime)
    
    elif transform_type == 'deformation':
        # Example: twist deformation around Y axis
        angle = params['angle']
        y = p[1]
        cos_a = cos(angle * y)
        sin_a = sin(angle * y)
        p_prime = vec3(p[0] * cos_a - p[2] * sin_a, y, p[0] * sin_a + p[2] * cos_a)
        return f_base(p_prime)
    
    elif transform_type == 'dynamic':
        object_data = params['object_data']
        time = params['time']
        # HSD function generates a transformation matrix from input data and time [G]
        # Sources do not provide the exact HSD algorithm; returns a transformation matrix [G]
        M = identity_matrix() # Compute HSD matrix here [G]
        p_prime = inverse(M) * p
        return f_base(p_prime)
    
    else:
        return f_base(p)
```

**Parameters:**
*   `spacing`: Vector defining the repetition interval [S1, unofficial].
*   `angle`: Float defining the twist intensity [S1, unofficial].
*   `time`: Float for dynamic variations [S2].
*   `object_data`: Object input data (e.g., world space position or grid cell vector) for dynamic operators [S2].

**Edge Cases and Pitfalls:**
*   **Lipschitz Condition:** Transformations must preserve the Lipschitz constant of 1 to ensure valid sphere tracing [G]. Non-linear transformations like twisting can violate this if not carefully implemented, leading to tunneling [G].
*   **Precision:** Modular arithmetic for repetition can suffer from precision issues at large scales [G].
*   **Dynamic Instancing:** Dynamic operators require calculating the grid cell vector independently from the Instancing operator to ensure correct transformation application [S2].

## Subtopics

### Dynamic Operators
Dynamic Operators extend the Global operators collection by applying unique affine transformations and material animations to 3D objects using the Holistic Scene Dynamics Function [S2]. Unlike original Global operators that used the Instancing operator's output (grid cell vector) as input, Dynamic Operators calculate the grid cell vector independently and transform the ray before applying the Instancing operator [S2]. This allows for time-varying effects such as wind sway or object translation based on simulation time and object input data [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per SDF evaluation, as transformations are simple arithmetic operations [G].
*   **Memory Complexity:** $O(1)$, as no additional data structures are needed beyond transformation parameters [G].
*   **Strengths:** Extremely low memory footprint; procedural geometry is defined by functions, not data structures [S1, unofficial]. Allows for complex effects like tiling and deformation without mesh processing [S1, unofficial].
*   **Limitations:** Transformations must preserve the Lipschitz condition to ensure valid sphere tracing [G]. Dynamic operators require additional processing passes and independent grid cell calculation [S2].
*   **When to Use:** When creating repetitive patterns, deformed shapes, or animated procedural scenes without increasing memory usage [S1, unofficial][S2].

## Background
SDF Transformations are a fundamental technique in procedural ray marching, allowing for the creation of complex scenes from simple primitives [S1, unofficial]. The concept of applying transformations to the query point before evaluation is standard in SDF rendering [S1, unofficial]. Dynamic Operators were introduced as an extension to the Holistic UOI rendering pipeline to enable dynamic variations of 3D objects using the Holistic Scene Dynamics Function [S2].
