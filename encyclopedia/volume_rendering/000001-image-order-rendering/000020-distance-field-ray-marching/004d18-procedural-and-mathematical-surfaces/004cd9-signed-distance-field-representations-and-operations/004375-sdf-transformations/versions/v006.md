# SDF Transformations

Also called: SDF Composition, SDF Modifiers

## Overview
SDF Transformations modify the spatial domain of a Signed Distance Field (SDF) primitive by applying geometric operations to the query point $\mathbf{p}$ before evaluation, enabling complex procedural geometry such as repetition, deformation, and dynamic animation without mesh processing [S1, unofficial][S2]. Unlike static primitives, this method allows for the composition of infinite or dynamically varying scenes with extremely low memory footprint, as the scene is defined by functions rather than data structures [S1, unofficial]. It sets itself apart from [SDF Primitive Definitions](1578-sdf-primitive-definitions.md) by focusing on the manipulation of the input coordinate space rather than the analytical distance formula itself.

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $\mathbf{p}$ (typically in world space), primitive parameters (e.g., spacing, twist angle), and optionally time $t$ for dynamic operators.
*   **Output:** Transformed point $\mathbf{p}'$ used to evaluate the base SDF, or the final distance value $d = SDF_{base}(\mathbf{p}')$.

**Data Structures:**
No persistent data structures are required. The transformation is computed on-the-fly per ray march step. For dynamic operators, a Holistic Scene Dynamics (HSD) function may store parameters per object instance [S2].

**Steps:**
1.  **Identify Transformation Type:** Determine if the operation is static (repetition, deformation) or dynamic (time-varying affine transformation) [S1, unofficial][S2].
2.  **Apply Coordinate Mapping:** Transform the query point $\mathbf{p}$ into the local or transformed space $\mathbf{p}'$ using the specific transformation function $T(\mathbf{p})$ [S1, unofficial][S2].
    *   For **Repetition (Tiling)**: Apply modular arithmetic to create a periodic grid [S1, unofficial].
    *   For **Deformation**: Apply a non-linear function to the coordinates [S1, unofficial].
    *   For **Dynamic Operators**: Calculate a transformation matrix or vector based on the HSD function, time $t$, and object ID, then apply it to the ray position [S2].
3.  **Evaluate Base SDF:** Compute the distance $d$ using the base primitive's SDF function with the transformed point: $d = SDF_{base}(\mathbf{p}')$ [S1, unofficial][S2].
4.  **Return Distance:** Return $d$ to the ray marching loop.

**Formulas:**
*   **Repetition (Tiling):**
    $$ \mathbf{p}' = \text{mod}(\mathbf{p}, \mathbf{s}) - \frac{\mathbf{s}}{2} $$
    Where $\mathbf{s}$ is the spacing vector (e.g., `vec3(1.0)`) [S1, unofficial].
*   **Deformation (Twist):**
    $$ \mathbf{p}' = \text{twist}(\mathbf{p}) $$
    Where `twist` is a custom function, typically rotating the $x$ and $y$ coordinates based on the $z$ height [S1, unofficial].
*   **Dynamic Transformation:**
    The position on the ray is transformed at each iteration. If $M(t, \mathbf{p})$ is the dynamic transformation matrix derived from the HSD function:
    $$ \mathbf{p}' = M(t, \mathbf{p}) \cdot \mathbf{p} $$
    The HSD function is defined as $f_{HSD}: D \times t \rightarrow V$, where $D$ is object input data, $t$ is simulation time, and $V$ is the dynamics variation (e.g., transformation matrix) [S2].

**Parameters:**
*   **Spacing ($\mathbf{s}$):** Vector defining the tile size. Typical value: `vec3(1.0)` for unit cubes [S1, unofficial].
*   **Twist Angle:** Scalar defining rotation per unit height. Typical value: `PI` for a full twist [S1, unofficial].
*   **Time ($t$):** Float for dynamic animations. Updates per frame [S2].

**Edge Cases and Pitfalls:**
*   **Lipschitz Condition:** Transformations must preserve the Lipschitz constant of 1 to ensure the distance value remains a safe lower bound for sphere tracing. Non-linear deformations like twisting can violate this if not carefully implemented, potentially causing tunneling [G].
*   **Boundary Precision:** In repetition, the `mod` operation can introduce precision errors at tile boundaries. Using `spacing/2` offset helps center the tiles [S1, unofficial].
*   **Dynamic Grid Calculation:** In Dynamic Operators, the grid cell vector must be calculated independently from the Instancing operator to ensure the transformation is applied correctly before instancing logic [S2].

**Pseudocode:**
```python
def sdf_transformations(p, primitive_func, transform_type, params):
    """
    Applies SDF transformations to a query point.
    
    Args:
        p: vec3, query point in world space.
        primitive_func: function, base SDF function (e.g., sphere, box).
        transform_type: str, 'repetition', 'deformation', or 'dynamic'.
        params: dict, transformation parameters.
        
    Returns:
        float, signed distance to the transformed surface.
    """
    p_prime = p
    
    if transform_type == 'repetition':
        spacing = params.get('spacing', vec3(1.0))
        # Apply tiling transformation
        p_prime = mod(p, spacing) - spacing / 2.0
        
    elif transform_type == 'deformation':
        twist_angle = params.get('twist_angle', 0.0)
        # Apply twist deformation
        # Example: rotate x,y based on z
        z = p.z
        angle = z * twist_angle
        c = cos(angle)
        s = sin(angle)
        x = p.x
        y = p.y
        p_prime = vec3(x * c - y * s, x * s + y * c, z)
        
    elif transform_type == 'dynamic':
        # Dynamic Operators require additional processing
        # 1. Calculate grid cell vector independently
        grid_cell = calculate_grid_cell(p, params.get('grid_size', 1.0))
        
        # 2. Apply HSD function to get transformation
        # HSD: f_HSD(D, t) -> V
        time = params.get('time', 0.0)
        object_id = params.get('object_id', 0)
        transformation_matrix = hsd_function(grid_cell, time, object_id)
        
        # 3. Apply transformation to ray position
        # Note: In a full ray marcher, this happens per step.
        # Here we assume p is the current step position.
        p_prime = transformation_matrix * p
        
    # Evaluate base primitive with transformed point
    distance = primitive_func(p_prime)
    
    return distance

def calculate_grid_cell(p, grid_size):
    """Helper to calculate grid cell for dynamic operators."""
    return floor(p / grid_size)

def hsd_function(grid_cell, time, object_id):
    """
    Placeholder for Holistic Scene Dynamics Function.
    Returns a transformation matrix based on noise or time.
    """
    # Example: Simple translation based on time and noise
    noise_val = noise(grid_cell + time)
    translation = vec3(noise_val, 0.0, 0.0)
    # Return identity matrix with translation
    return mat4(1.0) + translation_matrix(translation)
```

## Subtopics

### Dynamic Operators
An extension to the Global operators collection that applies unique affine transformations and material animations to 3D objects using the Holistic Scene Dynamics (HSD) function [S2]. Unlike original Global operators which used the Instancing operator's output (grid cell vector) as input, Dynamic Operators calculate the grid cell vector independently and transform the ray before applying the Instancing operator [S2]. This allows for dynamic variations per 3D object, such as wind effects on grass or flying objects, by applying an additional transformation to the position on the ray from the camera to the SDF component at each iteration of the ray marching algorithm [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray march step, as transformations are simple arithmetic or matrix operations.
*   **Memory Complexity:** $O(1)$, as no scene data structures are stored; only shader code and parameters [S1, unofficial].
*   **Performance:** Extremely efficient for complex procedural landscapes with hundreds of blended primitives, consuming effectively zero scene memory beyond the framebuffer [S1, unofficial].
*   **Strengths:** Infinite detail, low memory usage, natural integration with volumetrics, and ability to create complex geometry from simple functions [S1, unofficial].
*   **Limitations:** Transformations must preserve the Lipschitz condition to avoid tunneling; complex deformations may require smaller step sizes or adaptive marching [G]. Dynamic operators add overhead for HSD function evaluation and grid cell calculation [S2].

## Background
SDF Transformations are a core technique in procedural ray marching, popularized by shaders like those in "A Ray Marching Primer" and tutorials by Tektite [S1, unofficial]. The concept of using `mod` for repetition and coordinate manipulation for deformation is standard in GLSL shader programming [S1, unofficial]. Dynamic Operators were introduced in the context of the Holistic UOI rendering pipeline to address the need for dynamic, unlimited object instancing with unique variations [S2].
