# Smooth Intersection

Also called: Round Intersection, S-Intersection, Smooth SDF Operations

## Overview
Smooth Intersection is a Constructive SDF (CSDF) operator that blends the boolean intersection of two signed distance fields (SDFs) into a rounded feature with a specified radius $r$. Unlike standard boolean intersection which creates sharp edges, this operator produces a smooth fillet. It is distinguished from generic smooth minimums (like the standard smooth union) by its specific geometric construction aimed at preserving Lipschitz continuity under orthogonal gradient conditions, thereby reducing ray marching artifacts [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- $a$: Distance from the first SDF.
- $b$: Distance from the second SDF.
- $r$: Blending radius (must be significantly smaller than object sizes [S1, unofficial][S2, unofficial]).

**Output:**
- $d$: The resulting blended distance value.

**Data Structures:**
None required; scalar operations.

**Formulas:**
There are two primary formulations found in the sources. They are mathematically distinct and should be treated as alternative implementations or approximations.

1.  **Geometric/Vector Formulation (S-Intersection):**
    This method calculates the distance to a rounded corner formed by the intersection.
    Let $m = \max(a, b)$.
    If $-a < r$ and $-b < r$ (i.e., both points are inside the respective shapes within the blending radius):
    $$ f = \max\left(m, -\left(r - \sqrt{(r+a)^2 + (r+b)^2}\right)\right) $$
    Otherwise:
    $$ f = m $$
    [S3, unofficial]

2.  **Polynomial/Blending Formulation (Smooth Intersection):**
    This method uses a polynomial blend based on the difference between distances.
    Let $h = \max(k - |a - b|, 0.0)$, where $k$ is the smoothing parameter (equivalent to $r$).
    $$ d = \min(a, b) - \frac{h^2}{4k} $$
    [S4, unofficial]

    *Note: Source [S1, unofficial] and [S2, unofficial] describe a similar polynomial approach using a mixing factor $h$:*
    $$ h = \text{clamp}\left(0.5 - 0.5 \frac{b - a}{k}, 0.0, 1.0\right) $$
    $$ d = \text{mix}(b, a, h) + k \cdot h \cdot (1.0 - h) $$
    where $\text{mix}(x, y, t) = x(1-t) + yt$. [S1, unofficial][S2, unofficial]

**Pseudocode:**
The following implements the Geometric/Vector Formulation (S-Intersection) as it is more robust for preserving distance field properties in CSG contexts.

```python
import math

def smooth_intersection(a: float, b: float, r: float) -> float:
    """
    Computes the smooth intersection of two SDF values a and b with radius r.
    Uses the geometric formulation: max(m, -(r - sqrt((r+a)^2 + (r+b)^2)))
    """
    m = max(a, b)
    
    # Check if both points are within the blending radius of the interior
    # Condition: -a < r AND -b < r
    if (-a < r) and (-b < r):
        # Calculate the rounded corner distance
        # Note: (r+a) and (r+b) are positive because a > -r and b > -r
        dist_to_corner = math.sqrt((r + a)**2 + (r + b)**2)
        result = max(m, -(r - dist_to_corner))
        return result
    else:
        # Outside the blending region, standard max intersection applies
        return m
```

**Edge Cases and Pitfalls:**
- **Lipschitz Violation:** If the gradients of the two SDFs are not orthogonal (off by more than 30 degrees) or if the surfaces are parallel and close, the Lipschitz condition (gradient magnitude $\le 1$) may be violated, causing ray marching artifacts [S1, unofficial][S2, unofficial].
- **Radius Size:** The parameter $r$ must be significantly smaller than the size of the objects to maintain validity [S1, unofficial][S2, unofficial].
- **Precision:** When $a$ and $b$ are large negative numbers (deep inside the shapes), $(r+a)^2$ may suffer from precision loss if $r \ll |a|$. However, since the condition $-a < r$ fails in such cases, this branch is not taken.

## Operating characteristics
- **Time Complexity:** $O(1)$ per query. Involves basic arithmetic, `max`, and `sqrt`.
- **Memory Complexity:** $O(1)$.
- **Strengths:** Produces visually smooth, rounded intersections suitable for CSG modeling. Preserves distance field properties better than naive smoothing when gradients are orthogonal.
- **Limitations:** Computationally slightly more expensive than simple `max` due to `sqrt`. Artifacts occur if surface normals are not orthogonal.
- **When to use:** When creating rounded corners or fillets in CSG models using SDFs.
- **When not to use:** When sharp boolean edges are required, or when performance is critical and visual smoothness is not needed.

## Background
Smooth Intersection operators are part of the broader family of Constructive SDF Modeling (CSDF) techniques. They extend the boolean operations of CSG to continuous distance fields. The specific "S-Intersection" formulation is documented in unofficial repositories related to sphere tracing and PyTorch-based differentiable rendering [S1, unofficial][S2, unofficial][S3, unofficial]. The polynomial blending variant is also cited in similar contexts [S4, unofficial].
