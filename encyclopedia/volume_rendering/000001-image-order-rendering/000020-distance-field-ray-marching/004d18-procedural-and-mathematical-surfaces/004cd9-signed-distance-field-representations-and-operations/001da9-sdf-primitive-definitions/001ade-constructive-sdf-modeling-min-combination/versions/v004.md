# Constructive SDF Modeling (Min Combination)

Also called: SDF Scene Composition, SDF Union, Scene SDF Composition, Union of SDFs

## Overview
Constructive SDF Modeling (Min Combination) is a method for defining complex geometric scenes by combining multiple primitive Signed Distance Functions (SDFs) into a single composite field. It solves the problem of representing arbitrary collections of shapes (primitives) as a single continuous distance function suitable for ray marching, where the resulting distance at any point is the minimum of the distances to all individual primitives [S1, S2, S3, S5, S7, S8, unofficial]. Unlike [Smooth SDF Composition](2685-smooth-sdf-composition.md), which blends primitives to create organic transitions, or [Object Combination Operators](1801-object-combination-operators.md), which introduce rounded features, Min Combination produces sharp, non-differentiable boundaries characteristic of a standard boolean union [S1, S2, S8, unofficial]. It differs from [CSG Difference](1238-csg-difference.md) by using a simple minimum rather than a max-negation operation for subtraction.

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ primitive SDFs, where each primitive $i$ has a distance function $d_i(\mathbf{p})$ and associated parameters (e.g., center, radius, orientation).
*   **Output:** A composite scene SDF $D_{scene}(\mathbf{p})$ that returns the signed distance to the nearest surface in the scene, and optionally the material ID of the closest primitive.

**Data Structures:**
The scene is typically represented by a collection of primitive objects. A common layout, as seen in C++ implementations, stores primitives in separate vectors indexed by type [S4, unofficial]:
*   `world_spheres`: `std::vector<Sphere*>`
*   `world_boxes`: `std::vector<Box*>`
*   `world_mandelbulbs`: `std::vector<MandelBulb*>`
*   `world_toruses`: `std::vector<Torus*>`

Each primitive class implements a `pointDist(point)` method returning the signed distance.

**Formulas:**
The composite distance is defined as the minimum of all individual primitive distances [S2, S3, S4, S5, S7, S8, unofficial]:
$$ D_{scene}(\mathbf{p}) = \min_{i=0}^{N-1} (d_i(\mathbf{p})) $$

For a scene containing a plane and multiple spheres, this expands to [S1, unofficial]:
$$ D_{scene}(\mathbf{p}) = \min(d_{plane}(\mathbf{p}), \min_{i=0}^{numSpheres-1} (d_{sphere}(\mathbf{p}, \mathbf{c}_i, r_i))) $$

Where:
*   $d_{plane}(\mathbf{p}) = \mathbf{p}.y - \text{FLOOR\_HEIGHT}$ (for a horizontal plane) [S1, unofficial].
*   $d_{sphere}(\mathbf{p}, \mathbf{c}, r) = \|\mathbf{p} - \mathbf{c}\| - r$ [S1, unofficial].

**Parameters:**
*   `numSpheres`: Integer count of sphere primitives [S1, unofficial].
*   `sphereCenters`: Array of 3D vectors storing center coordinates $\mathbf{c}_i$ [S1, unofficial].
*   `sphereRadii`: Array of floats storing radii $r_i$ [S1, unofficial].
*   `FLOOR_HEIGHT`: Constant defining the base height of the ground plane (e.g., -4.0) [S1, unofficial].

**Numbered Steps:**
1.  Initialize `min_dist` to positive infinity (or a sufficiently large value like `std::numeric_limits<double>::max()`) [S4, S8, unofficial].
2.  Initialize `closest_id` to -1 (or null) [S6, G, unofficial].
3.  For each primitive $i$ in the scene:
    a.  Transform the query point $\mathbf{p}$ into the primitive's local coordinate space if necessary [S10, unofficial, G].
    b.  Evaluate the primitive's SDF: $d_i = \text{primitive}_i.\text{eval}(\mathbf{p}_{local})$ [S4, S8, unofficial].
    c.  If $d_i < \text{min\_dist}$:
        i.  Set $\text{min\_dist} = d_i$ [S4, unofficial].
        ii. Set $\text{closest\_id} = i$ [S6, G, unofficial].
4.  Return $\text{min\_dist}$ and $\text{closest\_id}$ [S6, S8, unofficial].

**Pseudocode:**
```python
def scene_sdf(p: vec3, primitives: list[Primitive]) -> tuple[float, int]:
    """
    Computes the minimum signed distance to a set of primitives.
    
    Args:
        p: Query point in world space.
        primitives: List of Primitive objects, each having an eval(p_local) method.
        
    Returns:
        (min_dist, closest_id): The minimum distance and the index of the closest primitive.
    """
    min_dist = float('inf')
    closest_id = -1
    
    for i, prim in enumerate(primitives):
        # Transform point to local space if the primitive has a transformation matrix
        # [G] Assuming prim.get_local_transform() returns the inverse matrix
        p_local = prim.transform_inverse(p)
        
        # Evaluate primitive distance
        d = prim.eval(p_local)
        
        # Check if this primitive is closer
        if d < min_dist:
            min_dist = d
            closest_id = i
            
    return min_dist, closest_id
```

**Edge Cases and Pitfalls:**
*   **Initialization:** Initializing `min_dist` to a hardcoded finite value (e.g., 999) is dangerous; if all objects are farther than this value, the function returns an incorrect distance. It must be initialized to infinity or the distance of the first object [S4, unofficial].
*   **Overshooting:** Using a distance larger than the minimum (e.g., from a far object) instead of the true minimum causes the ray marcher to step too far, potentially skipping over the nearer surface [S8, unofficial].
*   **Lipschitz Continuity:** The `min` operator preserves the Lipschitz continuity of the constituent SDFs, ensuring the distance estimate remains a valid lower bound for sphere tracing [S2, S8, unofficial]. However, the resulting field is not differentiable at the boundaries where two primitives are equidistant, which can affect normal estimation if not handled via finite differences or analytical normals from the closest primitive [S3, S8, unofficial].

## Subtopics

### [CSG Difference](1238-csg-difference.md)
Performs boolean subtraction using `max(-d_A, d_B)`. Choose when carving volume from a base object. Produces sharp boundaries.

### [Object Combination Operators](1801-object-combination-operators.md)
Merges SDFs with a radius parameter $k$ to create rounded edges. Choose when smooth, chamfered transitions are desired over sharp unions.

### [Smooth SDF Composition](2685-smooth-sdf-composition.md)
Blends SDFs using a smooth minimum operator. Choose for organic merging effects and continuous gradients, avoiding sharp creases.

## Operating characteristics
*   **Time Complexity:** $O(N)$ per query point, where $N$ is the number of primitives. Each primitive must be evaluated to find the minimum [S4, S8, unofficial].
*   **Memory Complexity:** $O(N)$ to store the primitive definitions and their parameters [S4, unofficial].
*   **Performance:** Performance scales linearly with the number of primitives. For large scenes, spatial partitioning (e.g., BVH) is required to accelerate the search, but standard Min Combination assumes a flat list [S4, S8, unofficial].
*   **Strengths:** Simple to implement; guarantees a valid lower bound for sphere tracing; supports arbitrary combinations of primitives [S2, S8, unofficial].
*   **Limitations:** Sharp, non-differentiable boundaries at intersections; performance degrades with high primitive counts without acceleration structures; does not support smooth blending natively [S1, S8, unofficial].
*   **When to use:** Ideal for hard-surface modeling, mechanical parts, and scenes requiring precise boolean unions with sharp edges [S8, unofficial].
*   **When not to use:** Unsuitable for organic, fluid-like merging of shapes where smooth transitions are required [S1, S8, unofficial].

## Background
Constructive SDF Modeling via Min Combination is based on the approach popularized by Iñigo Quilez in his "Distance Functions" tutorials [S8, unofficial]. It relies on the mathematical property that the union of two signed distance fields is the minimum of their distances, a principle derived from the definition of the distance to a set as the infimum of distances to its elements [S2, S8, unofficial]. This method is foundational in ray marching for implicit surfaces, allowing complex scenes to be rendered without explicit triangle meshes [S8, unofficial].
