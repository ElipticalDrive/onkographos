# Polynomial Smooth Minimum

Also called: Quilez smin, Quilez smooth min, Smooth Minimum (smin), smoothMin

## Overview
Polynomial Smooth Minimum is a blending function for combining two Signed Distance Function (SDF) values to create organic, metaball-like merges between primitives without branching or trigonometry [S1, S2, unofficial]. It sets itself apart from the standard `min` operator by providing a continuous, differentiable transition controlled by a smoothing radius parameter $k$, allowing for smooth union operations in Constructive SDF Modeling [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- Inputs: Two scalar SDF values $a$ and $b$, and a non-negative smoothing radius $k$.
- Output: A single scalar value representing the smooth minimum of $a$ and $b$.

**Data Structures:**
- No complex data structures; operates on scalar floating-point values.

**Algorithm:**
The method computes an intermediate blend factor $h$ based on the distance between $a$ and $b$ relative to $k$, then adjusts the minimum value by a quadratic term.

1.  **Edge Case Handling:** If $k$ is effectively zero (specifically $k \le 10^{-6}$), return the hard minimum $\min(a, b)$ to avoid division by zero or numerical instability [S2, unofficial].
2.  **Compute Blend Factor:** Calculate $h$ using the absolute difference between $a$ and $b$:
    $$ h = \frac{\max(k - |a - b|, 0.0)}{k} $$
    This value $h$ ranges from $0.0$ (when $|a - b| \ge k$) to $1.0$ (when $a = b$) [S2, unofficial].
    *Note: An equivalent formulation found in sources uses clamping:*
    $$ h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right) $$
    *Sources [S1, unofficial] and [S2, unofficial] provide slightly different derivations for $h$ that yield the same result for the final formula when combined with their respective adjustment terms. The implementation below uses the formulation from [S2, unofficial] as it is explicitly labeled "quadratic smooth minimum" and avoids the `mix` function call in favor of direct arithmetic.*
3.  **Compute Result:** Return the adjusted minimum:
    $$ \text{smin}(a, b, k) = \min(a, b) - h^2 \cdot k \cdot 0.25 $$
    *Note: The source [S1, unofficial] presents the result as $\text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h)$. These are mathematically equivalent under the respective definitions of $h$. The implementation below follows the [S2, unofficial] structure for consistency with the "Polynomial" descriptor.*

**Pseudocode:**
```python
def polynomial_smooth_minimum(a: float, b: float, k: float) -> float:
    # Edge case: fallback to hard union if smoothing radius is negligible
    if k <= 1e-6:
        return min(a, b)
    
    # Calculate blend factor h
    # Using the formulation from [S2, unofficial]: h = max(k - |a - b|, 0) / k
    diff = abs(a - b)
    h = max(k - diff, 0.0) / k
    
    # Calculate the smooth minimum
    # Result = min(a, b) - h^2 * k * 0.25
    min_val = min(a, b)
    result = min_val - (h * h * k * 0.25)
    
    return result
```

**Parameters:**
- $k$: Smoothing radius. Controls the width of the transition zone between the two primitives. Typical values are $0.2$ or $0.3$ [S2, unofficial]. Larger values create more "blobby" merges [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Precision:** When $a$ and $b$ are very close, $h$ approaches $1.0$. Ensure floating-point precision is sufficient to handle the subtraction $\min(a, b) - \text{adjustment}$ without losing significant digits, especially for large $k$ [G].
- **Boundaries:** If $|a - b| \ge k$, then $h = 0$, and the result is exactly $\min(a, b)$. This ensures the function behaves like a standard union outside the blending region [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per primitive pair. The computation involves basic arithmetic operations (subtraction, absolute value, max, multiplication).
- **Memory Complexity:** $O(1)$. No additional memory is required beyond the input values.
- **Strengths:** Branchless (except for the $k \le 10^{-6}$ check, which can be optimized), differentiable, and produces visually pleasing organic shapes. It is computationally cheap compared to trigonometric or exponential smoothing methods.
- **Limitations:** The transition is not as "soft" or gradual as exponential smooth minimum for very large $k$ values, as the polynomial decay is fixed. It may exhibit slight artifacts if $k$ is too large relative to the scene scale [G].
- **When to use:** Ideal for metaballs, organic terrain blending, and any scenario requiring smooth, continuous unions of SDF primitives.
- **When not to use:** When sharp, hard edges are required (use standard `min`), or when extreme smoothness over large distances is needed (consider exponential smooth minimum).

## Background
The method is attributed to Inigo Quilez, a prominent graphics programmer known for his work on ray marching and SDFs [S1, S2, unofficial]. It is widely known in the procedural geometry community as "Quilez smin" [S1, S2, unofficial]. The technique is a staple in real-time ray marching shaders for creating complex organic shapes from simple primitives.
