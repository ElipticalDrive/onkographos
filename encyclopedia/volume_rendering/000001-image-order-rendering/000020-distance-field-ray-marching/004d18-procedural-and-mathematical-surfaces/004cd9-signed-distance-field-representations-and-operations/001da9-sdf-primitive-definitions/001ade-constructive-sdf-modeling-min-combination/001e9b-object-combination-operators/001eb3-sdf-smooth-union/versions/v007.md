# SDF Smooth Union

Also called: LogSumExp SDF Union, S-Union, Smooth Minimum, Smooth Union, Smooth Union SDF Operator

## Overview
SDF Smooth Union combines two Signed Distance Functions (SDFs) into a single smooth SDF, avoiding sharp edges at primitive intersections [S2, unofficial][S3, unofficial]. It provides a smooth approximation of the boolean union operation controlled by a blending parameter $k$ [S1, unofficial]. Unlike the standard boolean union which creates sharp corners, this operator creates organic, metaball-like merges between primitives without branching or trigonometry [S5, unofficial]. It is distinguished from generic smooth minimums by its specific formulation (polynomial or LogSumExp) which aims to preserve Lipschitz continuity under orthogonal gradient conditions, preventing ray marching artifacts [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two scalar distance values $a$ and $b$ (the SDF values at a query point for two primitives), and a blending radius parameter $k$ (or $r$) [S1, unofficial][S2, unofficial].
*   **Outputs:** A single scalar distance value representing the smooth union.

**Data Structures:**
*   **SdResult:** A struct containing a float distance field (accessed via `.x`) and a `Material` struct. Constructed as `SdResult(distance, material)` [S5, unofficial].
*   **Material:** A struct containing diffuse, specular, shininess, reflectivity, transparency, absorption, refraction index, and emission properties [S5, unofficial].

**Numbered Steps:**
1.  Define individual SDF results with associated materials using `SdResult(distance, material)` [S5, unofficial].
2.  Apply transformations (translation, rotation, scaling) to the query point $p$ before SDF evaluation [S5, unofficial].
3.  Evaluate the SDF for each primitive at the transformed point $p$ to get distances $a$ and $b$ [S5, unofficial].
4.  Compute the interpolation weight $h$:
    $$h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right)$$
5.  Compute the blended distance:
    $$result = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h)$$
    Where $\text{mix}(b, a, h) = b + h(a - b)$ [S6, unofficial].
6.  Return the combined SDF result [S5, unofficial].

**Formulas:**
There are two primary formulations found in sources: the Polynomial Smooth Minimum [S6, unofficial] and the LogSumExp (Soft Minimum) approach [S3, unofficial].

1.  **Polynomial Smooth Minimum:**
    $$h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right)$$
    $$result = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h)$$
    Where $\text{mix}(b, a, h) = b + h(a - b)$ [S6, unofficial].
    Alternatively expressed as [S1, unofficial]:
    $$result = \text{mix}(d_2, d_1, h) - k \cdot h \cdot (1 - h)$$
    Where $h = \text{clamp}(0.5 + 0.5 \cdot \frac{d_2 - d_1}{k}, 0., 1.)$ and $\text{mix}(a, b, t) = a \cdot (1 - t) + b \cdot t$ [S1, unofficial].

2.  **LogSumExp (Soft Minimum):**
    $$S_{union}(p) = -\frac{1}{k} \ln \left( \sum_{i} e^{-k \cdot S_i(p)} \right) = \frac{1}{-k} \text{logsumexp}_{i}(-k \cdot S_i(p))$$
    Where $S_i(p)$ are the input SDF values and $k$ is the blend factor [S3, unofficial].

**Parameters:**
*   **$k$ (blend radius/smoothing factor):** Controls the width of the transition region between the two shapes. Higher values result in a smoother union [S2, unofficial]. Typical values are $1.0$ [S3, unofficial], $0.5$ for primitive blending, or $0.33$ for final scene blending [S5, unofficial]. Smaller values produce sharper transitions; larger values produce smoother, more organic merges [S5, unofficial].
*   **$n$:** Occasionally used in multi-primitive combinations, but not defined in the core binary operator notes.

**Edge Cases and Pitfalls:**
*   **Lipschitz Continuity:** Standard smooth minimums can violate the Lipschitz condition (gradient magnitude > 1) when combining SDFs, leading to ray marching artifacts [S1, unofficial][S2, unofficial]. These operators preserve Lipschitz continuity provided the gradients of the two SDFs are at right angles (orthogonal) [S1, unofficial][S2, unofficial].
*   **Gradient Misalignment:** If the gradients are off by more than 30 degrees, or if the surfaces are parallel and close to each other, the Lipschitz condition may no longer hold, causing artifacts [S1, unofficial][S2, unofficial].
*   **Parameter Scale:** The parameter $k$ (or $r$) must be significantly smaller than the size of the objects to maintain validity [S1, unofficial][S2, unofficial].
*   **Parallel Surfaces:** The operator assumes intersecting or adjacent surfaces with distinct normals. Parallel surfaces may produce incorrect distances [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
import math

def smooth_union_polynomial(a: float, b: float, k: float) -> float:
    """
    Computes the smooth union of two SDF values using the polynomial approximation.
    
    Args:
        a: Distance value of the first primitive.
        b: Distance value of the second primitive.
        k: Blending radius/smoothing factor. Must be > 0.
        
    Returns:
        The blended distance value.
    """
    # Clamp h to [0.0, 1.0]
    h = 0.5 + 0.5 * (b - a) / k
    if h < 0.0:
        h = 0.0
    elif h > 1.0:
        h = 1.0
        
    # Mix function: mix(b, a, h) = b + h * (a - b)
    mixed = b + h * (a - b)
    
    # Final result
    result = mixed - k * h * (1.0 - h)
    
    return result

def smooth_union_logsumexp(distances: list, k: float) -> float:
    """
    Computes the smooth union of multiple SDF values using the LogSumExp approximation.
    
    Args:
        distances: List of distance values from multiple primitives.
        k: Blending factor.
        
    Returns:
        The blended distance value.
    """
    # Compute -k * d for each distance
    neg_k_d = [-k * d for d in distances]
    
    # Find the maximum value for numerical stability
    max_val = max(neg_k_d)
    
    # Compute sum of exponentials
    sum_exp = sum(math.exp(val - max_val) for val in neg_k_d)
    
    # Compute logsumexp
    log_sum_exp = math.log(sum_exp) + max_val
    
    # Final result: -1/k * logsumexp
    result = -1.0 / k * log_sum_exp
    
    return result
```

## Subtopics

### Polynomial Smooth Minimum
A blending function for combining two SDF values to create organic, metaball-like merges between primitives without branching or trigonometry [S5, unofficial]. It uses the clamp-based interpolation formula $h = \text{clamp}(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0)$ and $result = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h)$ [S6, unofficial]. It is chosen for its computational efficiency and widespread use in real-time ray marching shaders [S3, unofficial][S5, unofficial].

### LogSumExp Smooth Union
A method using the LogSumExp function $S_{union}(p) = -\frac{1}{k} \ln \left( \sum_{i} e^{-k \cdot S_i(p)} \right)$ to combine SDFs [S3, unofficial]. It provides a mathematically smooth approximation that is differentiable everywhere, making it suitable for gradient-based optimization in differentiable rendering [S1, unofficial][S2, unofficial]. It is chosen when smoothness and differentiability are prioritized over the specific geometric properties of the polynomial blend [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation [G]. Combining $N$ primitives requires $N-1$ union operations [G].
*   **Memory Complexity:** $O(1)$ auxiliary memory per operation [G].
*   **Measured Performance:** Not given in the sources [G].
*   **Scaling:** Linear with the number of primitives [G].
*   **Strengths:** Creates organic, smooth transitions between shapes; avoids sharp edges; computationally inexpensive compared to implicit surface reconstruction [S5, unofficial][G].
*   **Limitations:** Does not preserve exact distance values (it is an approximation); Lipschitz continuity is not guaranteed for non-orthogonal gradients or parallel surfaces, leading to ray marching artifacts [S1, unofficial][S2, unofficial].
*   **When to use:** When organic blending of shapes is desired, and exact distance preservation is not critical [G].
*   **When not to use:** When exact boolean union distances are required, or when primitives are parallel and close together [G].

## Background
The concept of smooth unions in SDFs originated in the context of ray marching and procedural modeling [G]. The polynomial smooth minimum is widely used in real-time ray marching shaders, as seen in tutorials and implementations by Maxime Garcia [S3, unofficial] and others [S5, unofficial]. The method is a key component of Constructive SDF Modeling, allowing for the creation of complex scenes from simple primitives [S3, unofficial][S5, unofficial].
