# SDF Smooth Union

Also called: LogSumExp SDF Union, S-Union, Smooth Minimum, Smooth Union, Smooth Union SDF Operator

## Overview
SDF Smooth Union is a method for combining two Signed Distance Functions (SDFs) to create a blended transition between shapes, avoiding the sharp edges of standard boolean union operations [S1, unofficial][S2, unofficial][S3, unofficial][S4, unofficial][S5, unofficial]. It solves the problem of creating organic, metaball-like merges or rounded fillets in constructive solid geometry (CSG) modeling within ray marching [S3, unofficial][S6, unofficial]. It is distinguished from generic smooth minimum operators by its specific mathematical formulation (often cubic or logarithmic) which aims to preserve Lipschitz continuity under orthogonal gradient conditions, preventing ray marching artifacts caused by gradient magnitudes exceeding 1 [S1, unofficial][S2, unofficial].

## How it works
The method takes two scalar distance values, $a$ and $b$ (the distances from a query point to two primitives), and a smoothing parameter $k$ (or $r$), and returns a single scalar distance value [S1, unofficial][S2, unofficial]. The parameter $k$ controls the width of the transition region; it must be significantly smaller than the size of the objects to maintain validity [S1, unofficial][S2, unofficial].

There are two primary formulations found in the literature: the Polynomial (Cubic) Smooth Minimum and the LogSumExp (Logarithmic) Smooth Minimum.

### Inputs and Outputs
- **Inputs**:
  - $a$: Distance to the first primitive (float).
  - $b$: Distance to the second primitive (float).
  - $k$: Smoothing factor or blend radius (float, $k > 0$).
- **Output**:
  - $d$: The combined smooth distance (float).

### Data Structures
No complex data structures are required for the core operator. It operates on scalar floats. If material information is preserved (as in some implementations), a struct `SdResult` containing `distance` (float) and `material` (struct) is used, but the distance combination logic remains scalar [S5, unofficial].

### Formulas

#### 1. Polynomial (Cubic) Smooth Minimum
This is the most common implementation in real-time ray marching [S1, unofficial][S2, unofficial][S4, unofficial][S6, unofficial].

1. Calculate the interpolation weight $h$:
   $$ h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right) $$
2. Calculate the result:
   $$ d = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h) $$
   Where $\text{mix}(b, a, h) = b + h(a - b)$ [S6, unofficial].

*Note: Some sources define the mix order as $\text{mix}(d_2, d_1, h)$ where $d_1=a, d_2=b$ [S1, unofficial][S2, unofficial]. The formula above follows the consistent derivation from [S4, unofficial][S6, unofficial].*

#### 2. LogSumExp (Logarithmic) Smooth Minimum
This formulation is derived from the soft minimum approximation using the log-sum-exp function [S3, unofficial].

$$ d = -\frac{1}{k} \ln \left( e^{-k \cdot a} + e^{-k \cdot b} \right) $$

Or equivalently:
$$ d = \frac{1}{-k} \text{logsumexp}(-k \cdot a, -k \cdot b) $$

### Pseudocode

```python
import math

def smooth_union_polynomial(a: float, b: float, k: float) -> float:
    """
    Polynomial (Cubic) Smooth Union.
    Preserves Lipschitz continuity better than generic smooth min for orthogonal gradients.
    """
    if k <= 0.0:
        return min(a, b)
    
    # Calculate interpolation weight h
    # h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0)
    h = 0.5 + 0.5 * (b - a) / k
    if h < 0.0:
        h = 0.0
    elif h > 1.0:
        h = 1.0
        
    # mix(b, a, h) = b + h * (a - b)
    mixed = b + h * (a - b)
    
    # result = mix - k * h * (1 - h)
    result = mixed - k * h * (1.0 - h)
    
    return result

def smooth_union_logsumexp(a: float, b: float, k: float) -> float:
    """
    LogSumExp Smooth Union.
    Equivalent to soft minimum.
    """
    if k <= 0.0:
        return min(a, b)
    
    # d = -1/k * ln(exp(-k*a) + exp(-k*b))
    # To avoid overflow/underflow, use log-sum-exp trick if values are large,
    # but for typical SDF ranges, direct computation is stable.
    term1 = math.exp(-k * a)
    term2 = math.exp(-k * b)
    
    result = -math.log(term1 + term2) / k
    return result
```

### Parameters
- **$k$ (or $r$)**: The smoothing factor. Larger values create a smoother, wider blend between the shapes [S1, unofficial][S2, unofficial][S4, unofficial]. Typical values range from 0.1 to 1.0 depending on scene scale [S4, unofficial][S5, unofficial]. In multi-material blending, values like 0.5 and 0.33 are used for primitive and final scene blending respectively [S5, unofficial].

### Edge Cases and Pitfalls
- **Lipschitz Violation**: If the gradients of the two SDFs are not orthogonal (off by more than 30 degrees) or if the surfaces are parallel and close, the Lipschitz condition (gradient magnitude $\le 1$) may no longer hold, causing ray marching artifacts [S1, unofficial][S2, unofficial].
- **Zero Smoothing**: If $k=0$, the operator should degenerate to `min(a, b)` to avoid division by zero.
- **Precision**: For the LogSumExp variant, if $k \cdot a$ or $k \cdot b$ are very large negative numbers, `exp` may underflow to 0. If they are large positive numbers, `exp` may overflow. Standard log-sum-exp stabilization techniques can be applied if necessary, though typical SDF values in ray marching are small enough that direct computation is often safe [S3, unofficial].

## Subtopics

### Polynomial Smooth Minimum
A blending function for combining two SDF values to create organic, metaball-like merges between primitives without branching or trigonometry [S6, unofficial]. It uses the cubic formula described in the main method. It is preferred in real-time graphics for its computational efficiency and lack of transcendental functions (exp/log) [S6, unofficial]. The parameter $k$ (often exposed as `uBlendK`) controls the "blobbiness" [S6, unofficial].

### LogSumExp SDF Union
A smooth approximation of the CSG union operation using the logarithmic sum of exponentials [S3, unofficial]. It is mathematically equivalent to the soft minimum. It is often used in differentiable rendering pipelines (e.g., PyTorch) because it is smooth and differentiable everywhere, unlike the hard min [S3, unofficial].

## Operating characteristics
- **Time Complexity**: $O(1)$ per query. The polynomial version involves basic arithmetic operations (add, multiply, clamp). The LogSumExp version involves exponentials and logarithms, which are more expensive but still constant time.
- **Memory Complexity**: $O(1)$. No additional memory is required beyond the input scalars.
- **Strengths**: Creates visually pleasing, organic transitions between shapes; avoids sharp edges; preserves distance field properties (mostly) better than naive interpolation.
- **Limitations**: Does not strictly preserve the exact distance field property (the result is not a true SDF for all configurations, but a valid approximation); Lipschitz continuity is not guaranteed for non-orthogonal gradients, leading to potential ray marching errors (overshooting or undershooting) [S1, unofficial][S2, unofficial].
- **When to use**: When creating organic shapes, metaballs, or rounded fillets in CSG modeling.
- **When not to use**: When exact boolean operations are required, or when high precision distance values are critical for physics/collision detection without further correction.

## Background
SDF Smooth Union operators are a staple in the field of ray marching and implicit surface rendering. The polynomial smooth minimum was popularized by Inigo Quilez in his online articles on SDFs [S4, unofficial]. The LogSumExp variant is widely used in differentiable rendering and neural implicit surface representations due to its smoothness and differentiability [S3, unofficial]. The family of operators, including smooth union, intersection, and difference, is designed to provide a continuous transition between shapes, enabling the creation of complex scenes from simple primitives [S5, unofficial].
