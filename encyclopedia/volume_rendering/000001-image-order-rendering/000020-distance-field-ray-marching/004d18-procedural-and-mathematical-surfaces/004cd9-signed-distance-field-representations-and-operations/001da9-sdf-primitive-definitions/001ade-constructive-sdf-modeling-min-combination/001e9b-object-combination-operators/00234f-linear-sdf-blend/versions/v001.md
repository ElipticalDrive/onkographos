# Linear SDF Blend

Also called: Shape Blending, Linear Interpolation of SDFs

## Overview
Linear SDF Blend creates a morphing transition between two signed distance functions (SDFs) by interpolating their distance values. It solves the problem of creating smooth, continuous shape transitions (morphs) rather than boolean unions or intersections. Unlike [SDF Smooth Union](1817-sdf-smooth-union.md) which creates a rounded edge feature, Linear SDF Blend preserves the original geometry of both shapes within the blend region, simply averaging their distances. This method does not guarantee Lipschitz continuity (gradient magnitude $\le 1$) and can produce artifacts if the blend factor is not handled carefully or if the underlying shapes have significantly different curvatures [S1, unofficial][S2, unofficial].

## How it works
**Inputs:**
- $d_1$: Distance value of the first primitive at query point $p$.
- $d_2$: Distance value of the second primitive at query point $p$.
- $a$: Blend factor (alpha), a scalar in $[0, 1]$.

**Outputs:**
- $d_{blend}$: The blended distance value.

**Data Structures:**
- Scalars $d_1, d_2, a, d_{blend}$ are typically `float` or `vec1`.

**Formula:**
$$d_{blend} = a \cdot d_1 + (1 - a) \cdot d_2$$

**Steps:**
1. Evaluate the SDF for the first primitive at point $p$ to get $d_1$.
2. Evaluate the SDF for the second primitive at point $p$ to get $d_2$.
3. Determine the blend factor $a$. This can be a constant, a function of time, or a function of position.
4. Compute the linear interpolation using the formula above.

**Parameters:**
- $a$: The blend weight. $a=0$ yields $d_2$, $a=1$ yields $d_1$.

**Edge Cases and Pitfalls:**
- **Lipschitz Violation:** Because the gradient of the result is $\nabla d_{blend} = a \nabla d_1 + (1-a) \nabla d_2$, the magnitude $|\nabla d_{blend}|$ can exceed 1 if $\nabla d_1$ and $\nabla d_2$ are not orthogonal or if their magnitudes sum to more than 1. This violates the Lipschitz condition required for robust ray marching, potentially causing the ray to step too far and miss the surface [S1, unofficial][S2, unofficial].
- **Discontinuity:** If $a$ changes abruptly with position, the derivative of $d_{blend}$ with respect to position will be discontinuous, causing visual artifacts.
- **Sign Ambiguity:** If one shape is inside ($d < 0$) and the other is outside ($d > 0$), the blend may produce a distance value that does not correspond to a meaningful surface boundary between the two shapes.

**Pseudocode:**
```python
import math

def linear_sdf_blend(d1: float, d2: float, a: float) -> float:
    """
    Blends two SDF values linearly.
    
    Args:
        d1: Distance of the first primitive.
        d2: Distance of the second primitive.
        a: Blend factor in [0, 1].
        
    Returns:
        Blended distance value.
    """
    # Clamp alpha to [0, 1] to prevent extrapolation artifacts [G]
    a_clamped = max(0.0, min(1.0, a))
    
    # Linear interpolation formula
    return a_clamped * d1 + (1.0 - a_clamped) * d2

def example_sphere_cube_blend(p: tuple, time: float) -> float:
    """
    Example blending a sphere into a cube using time.
    Based on [S1, unofficial].
    """
    # Helper to compute sphere distance
    def sdf_sphere(point, center, radius):
        return math.sqrt(sum((point[i] - center[i])**2 for i in range(3))) - radius

    # Helper to compute box distance
    def sdf_box(point, center, size):
        # Assuming axis-aligned box centered at center with half-extents size
        dist = 0.0
        for i in range(3):
            diff = abs(point[i] - center[i]) - size[i]
            if diff > 0:
                dist += diff**2
        return math.sqrt(dist)

    # Define primitives
    sphere_d = sdf_sphere(p, (0,0,0), 1.0)
    box_d = sdf_box(p, (0,0,0), (1.0, 1.0, 1.0))
    
    # Blend factor oscillating between 0 and 1 over time
    # (_SinTime[3] + 1.) / 2. from [S1, unofficial]
    a = (math.sin(time) + 1.0) / 2.0
    
    return linear_sdf_blend(sphere_d, box_d, a)
```

## Subtopics

### Smoothstep SDF Blend
A technique to blend between two SDFs based on the distance of the query point from the origin, using a smooth interpolation factor. It uses `smoothstep` to create a spatially varying blend factor $s$ that transitions from 0 to 1 as the distance from the origin increases from 0.0 to 1.0. This creates a radial blend zone. The function returns a `vec2` containing the blended distance and a primitive identifier (typically 1) [S2, unofficial].

- **Definition:** Blends SDFs $a$ and $b$ using a spatially varying smoothstep factor.
- **Formula:**
  $$s = \text{smoothstep}(0.0, 1.0, \|p\|)$$
  $$d = (1 - s) \cdot a.x + s \cdot b.x$$
- **Parameters:** The smoothstep range is fixed between 0.0 and 1.0 [S2, unofficial].
- **Layout:** Returns `vec2(d, 1)` where `d` is the distance and `1` is the primitive ID [S2, unofficial].
- **Pseudocode:**
  ```python
  import math

  def smoothstep_sdf_blend(p: tuple, a: tuple, b: tuple) -> tuple:
      """
      Blends two SDFs (returned as (distance, id)) based on distance from origin.
      Based on [S2, unofficial].
      """
      # Calculate distance from origin
      dist_from_origin = math.sqrt(sum(p[i]**2 for i in range(3)))
      
      # Calculate smoothstep factor s
      # smoothstep(edge0, edge1, x)
      # t = max(0, min(1, (x - edge0) / (edge1 - edge0)))
      # result = t * t * (3 - 2 * t)
      t = max(0.0, min(1.0, (dist_from_origin - 0.0) / (1.0 - 0.0)))
      s = t * t * (3.0 - 2.0 * t)
      
      # Interpolate distances (x-component)
      d = (1.0 - s) * a[0] + s * b[0]
      
      # Return blended distance and primitive ID
      return (d, 1.0)
  ```

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, same as evaluating the underlying SDFs.
- **Memory Complexity:** $O(1)$, no additional data structures required.
- **Strengths:** Simple to implement; produces smooth morphing animations; preserves the individual geometry of both shapes within the blend region.
- **Limitations:** Does not preserve Lipschitz continuity, which can lead to ray marching artifacts (jittering, missed surfaces) if the gradients of the two shapes are not orthogonal or if the blend factor varies rapidly [S1, unofficial][S2, unofficial]. Not suitable for creating sharp or rounded edges like boolean operators; it creates a "ghosting" or "mixing" effect.
- **When to use:** For morphing animations between two shapes where the transition is temporal or spatially controlled by a smooth factor.
- **When not to use:** When a clean, artifact-free surface is required for ray marching with large step sizes, or when creating boolean-like features (unions, intersections) with rounded edges. Use [SDF Smooth Union](1817-sdf-smooth-union.md) or other combination operators instead.

## Background
Linear SDF blending is a technique popularized in the ray marching community for creating smooth transitions between shapes. It is analogous to alpha blending in image compositing. The method was described by Alan Zucconi in his tutorial on Signed Distance Functions [S1, unofficial] and further illustrated in the Geeks3D GLSL Hacker tutorial on primitive blending [S2, unofficial]. It is often used in conjunction with time-based animation to morph between primitives like spheres and cubes.
