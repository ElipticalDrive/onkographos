# Material Object Format

Also called: Material struct, Material object, Material descriptor

## Overview
The Material Object Format is a data structure used in distance-field ray marching to encapsulate surface shading properties and texture descriptors, enabling physically based rendering (PBR) within GPU-accelerated volume rendering pipelines [S1]. It distinguishes itself by providing a unified interface for both host and device code, separating geometric displacement (via `heightmapTex`) from shading calculations, and explicitly managing texture projection modes and normal deflection scaling [S1].

## How it works
The format defines a `Material` structure that stores physical material properties and references to texture maps. It is designed to be accessible from both CPU (host) and GPU (device) code, facilitating the transfer of material definitions into the ray marching loop [S1].

### Inputs and Outputs
*   **Input**: Material parameters (albedo, metalness, roughness, F0) and optional texture descriptors.
*   **Output**: A `Material` instance containing all shading and texture metadata required by the ray marcher to compute surface color and normals.

### Data Structures
The `Material` object consists of the following fields [S1]:

| Field | Type | Description |
| :--- | :--- | :--- |
| `albedo` | `vec3` (linear float) | Surface color in linear RGB. |
| `metalness` | `float` | Range $[0, 1]$. Controls specular vs. diffuse shading contribution. |
| `roughness` | `float` | Range $[0, 1]$. Controls smoothness of reflections and light scattering. |
| `F0` | `vec3` (linear float) | Base reflectivity when `metalness` is 0. Often corresponds to the specular term in PBR shaders. |
| `triplar` | `bool` | Texture projection mode. `false` for XZ planar mapping, `true` for triplanar mapping. |
| `normalStrength` | `float` | Linear scaling factor for normal deflection from normal maps. Useful for displacing surfaces at angles less steep than the normal map's design. |
| `albedoTex` | `int` | Texture descriptor for sRGB albedo map. Value $-1$ if unused. Multiplied with `albedo`. |
| `normalTex` | `int` | Texture descriptor for linear detail normal map. Value $-1$ if unused. |
| `roughnessTex` | `int` | Texture descriptor for linear roughness map. Value $-1$ if unused. Multiplied with `roughness`. |
| `metalnessTex` | `int` | Texture descriptor for linear metalness map. Value $-1$ if unused. Multiplied with `metalness`. |
| `heightmapTex` | `int` | Texture descriptor for linear displacement heightmap. Value $-1$ if unused. Used for geometric displacement by the object SDF, not for shading. |
| `ambietTex` | `int` | Texture descriptor for linear ambient occlusion map. Value $-1$ if unused. |

*Note: Texture descriptors are integers referencing texture objects or mipmap arrays. To read a texture from device code, only the `tex` variable (descriptor) needs to be known [S1].*

### Construction Logic
Two constructors are provided to initialize the `Material` object [S1]:

1.  **Full Constructor**: Takes `albedo`, `metalness`, `roughness`, and `F0` as arguments.
    *   Sets all texture descriptors (`albedoTex`, `normalTex`, etc.) to $-1$ (textureless).
    *   Sets `triplar` to `false` (planar mapping).
    *   Sets `normalStrength` to $1.0$.
2.  **Simplified Constructor**: Takes `albedo`, `roughness`, and `metalness`.
    *   Calls the Full Constructor with these values.
    *   Sets `F0` to the default value $[0.04, 0.04, 0.04]$, which is the standard base reflectance for most non-metal dielectrics (e.g., plastics, organic materials) [S1].

### Pseudocode
```python
class Material:
    def __init__(self, albedo, metalness, roughness, F0=None):
        """
        Constructor 2 (Simplified) if F0 is None, else Constructor 1.
        """
        if F0 is None:
            # Default F0 for non-metal dielectrics
            F0 = [0.04, 0.04, 0.04]
        
        self.albedo = albedo          # vec3, linear float RGB
        self.metalness = metalness    # float, [0, 1]
        self.roughness = roughness    # float, [0, 1]
        self.F0 = F0                # vec3, linear float RGB
        
        # Texture projection and normal scaling defaults
        self.triplar = False          # bool: False = XZ planar, True = triplanar
        self.normalStrength = 1.0     # float
        
        # Texture descriptors: -1 indicates unused/textureless
        self.albedoTex = -1
        self.normalTex = -1
        self.roughnessTex = -1
        self.metalnessTex = -1
        self.heightmapTex = -1
        self.ambietTex = -1

    def set_texture(self, albedoTex=-1, normalTex=-1, roughnessTex=-1, 
                    metalnessTex=-1, heightmapTex=-1, ambietTex=-1):
        """
        Updates texture descriptors. 
        Note: heightmapTex is for geometric displacement, not shading.
        """
        self.albedoTex = albedoTex
        self.normalTex = normalTex
        self.roughnessTex = roughnessTex
        self.metalnessTex = metalnessTex
        self.heightmapTex = heightmapTex
        self.ambietTex = ambietTex
```

### Edge Cases and Pitfalls
*   **Texture Descriptors**: All texture fields default to $-1$. If a texture is not used, it must remain $-1$ to prevent invalid memory access during device code execution [S1].
*   **Heightmap vs. Shading**: `heightmapTex` is explicitly excluded from shading calculations. It is used solely by the object SDF for geometric displacement. Using it for shading is incorrect [S1].
*   **Normal Strength**: `normalStrength` scales normal deflection. It is particularly useful when the surface displacement angle is less steep than what the normal map is designed for, preventing visual artifacts [S1].
*   **F0 Default**: The default `F0` of $[0.04, 0.04, 0.04]$ is specific to non-metal dielectrics. Metals require a different `F0` derived from their index of refraction, which must be set via the full constructor [S1].

## Operating characteristics
*   **Memory**: The `Material` structure is small, consisting of a few vectors, floats, and integers. It fits easily in registers or shared memory on the GPU.
*   **Performance**: Accessing material properties is $O(1)$. Texture lookups depend on the texture resolution and filtering mode, but the descriptor-based access is efficient.
*   **Compatibility**: Designed for CUDA environments, allowing seamless data sharing between host and device code [S1].
*   **Limitations**: The format assumes a specific PBR workflow. It does not include complex material models (e.g., subsurface scattering) beyond the basic albedo/metalness/roughness framework.

## Background
The Material Object Format was introduced in the context of CUDA-based ray marching of distance fields [S1]. It addresses the need for a standardized way to pass material information from the CPU to the GPU in real-time rendering applications, ensuring that shading parameters and texture references are correctly interpreted by the ray marcher. The format is part of a broader system that includes Light objects and SDF primitives, enabling complex scenes with physically based materials.
