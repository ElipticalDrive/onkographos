# SDF Intersection
Also called: CSG Intersection, Constructive SDF Modeling, Intersection of SDFs, Min/Max Combination, SDF Boolean Operations, SDF Composition, SDF Intersection via Max, SDF Max

## Overview
SDF Intersection is a boolean operation that computes the region common to two or more Signed Distance Field (SDF) primitives by returning the maximum distance value at any sampling point [S1, unofficial][S3, unofficial]. It effectively requires the ray to be inside both shapes simultaneously, allowing for the construction of complex geometries akin to Constructive Solid Geometry (CSG) [S1, unofficial]. Unlike the union operation (min), which combines shapes into a single volume, intersection creates sharp, non-smooth corners where the surfaces meet [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Two SDF functions, $S_1(p)$ and $S_2(p)$, and a query point $p$ in 3D space.
- Output: A single scalar value representing the signed distance to the intersection of the two shapes.

**Data Structures:**
No specific data structures are required beyond the scalar values returned by the primitive SDF evaluations [G]. The operation is point-wise and stateless [G].

**Steps:**
1. Evaluate the signed distance of the first shape at point $p$: $d_1 = S_1(p)$ [S3, unofficial].
2. Evaluate the signed distance of the second shape at point $p$: $d_2 = S_2(p)$ [S3, unofficial].
3. Return the maximum of the two distances: $d_{intersect} = \max(d_1, d_2)$ [S1, unofficial].

**Formulas:**
The intersection of two SDFs $A$ and $B$ at point $p$ is defined as:
$$ S_{intersect}(p) = \max(S_A(p), S_B(p)) $$

For a point to be inside the resulting intersection volume, it must satisfy $S_A(p) \le 0$ AND $S_B(p) \le 0$ [G].

**Parameters:**
- None. The operation is deterministic based on the input SDFs [G].

**Edge Cases and Pitfalls:**
- **Non-smooth derivatives:** Standard `max` produces non-smooth intersections with discontinuous derivatives at the boundary where $S_A(p) = S_B(p)$ [S1, unofficial].
- **Precision:** Near the intersection boundary, floating-point precision errors can cause jitter if the step size in ray marching is not sufficiently small [G].
- **Degenerate input:** If one SDF is always greater than the other in the region of interest, the result is simply the boundary of the "inner" shape [G].

**Pseudocode:**
```python
def sdf_intersection(p, sdf_a, sdf_b):
    """
    Computes the intersection of two SDFs at point p.
    
    Args:
        p: vec3, the query point in 3D space.
        sdf_a: function, returns signed distance for shape A.
        sdf_b: function, returns signed distance for shape B.
        
    Returns:
        float, the signed distance to the intersection of A and B.
    """
    d_a = sdf_a(p)
    d_b = sdf_b(p)
    return max(d_a, d_b)
```

## Subtopics

### Smooth SDF Composition
Uses smooth minimum/maximum functions (e.g., `smin`) to approximate intersections with continuous derivatives, avoiding the sharp corners of standard `max`. Choose when visual smoothness is prioritized over exact geometric intersection. [Smooth SDF Composition](4453-smooth-sdf-composition.md)

### Scene SDF Evaluation
The parent method that combines primitives using `min` (union). Intersection is a sibling operation used within scene evaluation to carve out holes or combine shapes. [Scene SDF Evaluation](4452-scene-sdf-evaluation.md)

## Operating characteristics
- **Time Complexity:** $O(1)$ per evaluation, requiring two primitive SDF evaluations and one `max` operation [G].
- **Memory Complexity:** $O(1)$, no additional memory required [G].
- **Performance:** Extremely fast per-ray cost. High per-ray evaluation counts are inherent to ray marching and depend on scene complexity, ray direction, step size strategy, and surface proximity, rather than the intersection operation itself [S2, unofficial].
- **Strengths:** Exact watertight surfaces; no mesh topology errors; trivial to implement; supports arbitrary combinations of primitives [S2, unofficial].
- **Limitations:** Discontinuous derivatives lead to non-smooth normals; does not support smooth blending by default [S1, unofficial].
- **When to use:** When exact boolean intersection is required and sharp edges are acceptable or desired [G].
- **When not to use:** When smooth transitions between shapes are needed (use Smooth SDF Composition) [G].

## Background
The concept of using `min` and `max` operators for SDF boolean operations was popularized by Inigo Quilez in his writings on raymarching and procedural geometry [S1, unofficial]. The technique allows for the creation of complex CSG-like models using simple mathematical functions, avoiding the need for mesh-based boolean operations which suffer from robustness issues [S2, unofficial]. It is a fundamental building block in procedural raymarching scenes, enabling the creation of intricate patterns and fractals [S1, unofficial].
