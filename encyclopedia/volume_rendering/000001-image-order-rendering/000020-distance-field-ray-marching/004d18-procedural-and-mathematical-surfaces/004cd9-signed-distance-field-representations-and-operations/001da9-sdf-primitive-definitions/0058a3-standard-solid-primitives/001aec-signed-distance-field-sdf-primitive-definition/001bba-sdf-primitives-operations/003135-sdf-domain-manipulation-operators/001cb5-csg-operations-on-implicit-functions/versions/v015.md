# CSG Operations on Implicit Functions

Also called: CSG Operations, Boolean SDF operators, SDF Boolean Operators, SDF Boolean Operations, CSG implicit surfaces, Constructive Solid Geometry with SDFs, CSG with SDFs, CSG SDF combination, CSG Operations for SDFs

## Overview
CSG Operations on Implicit Functions combine multiple Signed Distance Functions (SDFs) into a single implicit function using Boolean logic (Union, Intersection, Difference) to define complex composite shapes from simple primitives [S1][S2, S3, S7, unofficial]. Unlike sibling domain manipulation operators that transform the query position vector $\mathbf{p}$ to create periodic or mirrored structures [1730-sdf-domain-manipulation-operators.md], CSG operations act directly on the scalar distance values returned by child SDFs, reducing constructive solid geometry to arithmetic operations on scalar fields [S13, unofficial]. This method enables the rendering of complex geometries, such as near-tangent intersections, by evaluating the field functions of child objects and combining their density or distance values [S14, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Two or more SDF primitives (or composite SDFs), denoted as $f(\mathbf{p})$ and $g(\mathbf{p})$, which return the signed distance from a query point $\mathbf{p}$ to the surface. Negative values indicate the interior, positive values the exterior [S3, unofficial].
- **Outputs:** A new SDF $h(\mathbf{p})$ representing the Boolean combination of the inputs.

**Data Structures:**
The operations are typically implemented using a binary tree structure where leaf nodes contain primitive SDF functions and material identifiers, and internal nodes contain the operation type and pointers to child nodes [S2, S4, unofficial].

```python
# Simplified CSG Tree Node Structure
class CSGNode:
    def __init__(self, operation, left_child, right_child=None):
        self.operation = operation  # 'Union', 'Intersection', 'Difference'
        self.left = left_child      # CSGNode or Leaf
        self.right = right_child    # CSGNode or Leaf (None for unary ops)

class Leaf:
    def __init__(self, sdf_function, material_id):
        self.sdf = sdf_function     # Callable returning float
        self.material = material_id # Integer ID
```

**Numbered Steps:**
1. **Evaluate Children:** Recursively evaluate the left and right child nodes at the query point $\mathbf{p}$ to obtain distances $d_A$ and $d_B$ [S2, S4, unofficial].
2. **Apply Operator:** Combine $d_A$ and $d_B$ using the specific arithmetic operator defined by the node's operation type [S3, unofficial][S8].
3. **Return Result:** Return the combined distance value [S4, unofficial].

**Formulas:**
Let $f(\mathbf{p})$ and $g(\mathbf{p})$ be the signed distances of two shapes A and B at point $\mathbf{p}$.

- **Union ($A \cup B$):** The point is inside the union if it is inside either shape. The distance is the minimum of the two distances [S3, unofficial][S8][S10, S12, S13, unofficial].
  $$ h(\mathbf{p}) = \min(f(\mathbf{p}), g(\mathbf{p})) $$

- **Intersection ($A \cap B$):** The point is inside the intersection only if it is inside both shapes. The distance is bounded by the maximum of the two distances [S3, unofficial][S8][S9, S10, S12, S13, unofficial].
  $$ h(\mathbf{p}) = \max(f(\mathbf{p}), g(\mathbf{p})) $$

- **Difference ($A \setminus B$):** The point is inside A but outside B. This is equivalent to the intersection of A and the complement of B. The distance is the maximum of A's distance and the negation of B's distance [S3, unofficial][S8][S9, S10, S11, S13, unofficial].
  $$ h(\mathbf{p}) = \max(f(\mathbf{p}), -g(\mathbf{p})) $$

- **XOR:** The point is inside exactly one of the shapes.
  $$ h(\mathbf{p}) = \max(\min(f(\mathbf{p}), g(\mathbf{p})), -\max(f(\mathbf{p}), g(\mathbf{p}))) $$ [S10, unofficial]

**Parameters:**
- **k (Smoothness):** For smooth variants, a blending factor $k$ (typically $0.1$ to $1.0$) determines the radius of the fillet [S4, S11, unofficial].

**Edge Cases and Pitfalls:**
- **Scaling:** Scaling an SDF requires scaling the input coordinates by the inverse of the scale factor and scaling the output distance by the scale factor to maintain correct distance values for ray marching [S3, unofficial].
- **Subtraction Artifacts:** The difference operation $\max(-a, b)$ is exact only when the surface of A is entirely contained within B. If A pokes through the boundary of B, the resulting SDF is not Lipschitz-1, and sphere marching may skip surfaces. A small EPSILON correction or tightened step size is required in those regions [S12, unofficial].
- **DeMorgan’s Theorem:** DeMorgan’s theorem (intersection = complement of union of complements) does not work directly with min/max operators for distance bounds because the minimum operator is not complemented properly. Using max ensures the bound holds [S8].
- **Material Handling:** When using discrete voxel buffers or material grids, the polygonizer does not consider materials, leading to drastic color changes at CSG boundaries. Material changes must be treated as surface boundaries to separate colors [S14, unofficial].

**Pseudocode:**
```python
def evaluate_csg(node, p):
    """
    Recursively evaluates a CSG tree at point p.
    node: CSGNode or Leaf
    p: vec3 query point
    Returns: float signed distance
    """
    if isinstance(node, Leaf):
        return node.sdf(p)
    
    # Evaluate children
    dist_a = evaluate_csg(node.left, p)
    dist_b = evaluate_csg(node.right, p)
    
    # Apply operation
    if node.operation == 'Union':
        return min(dist_a, dist_b)
    elif node.operation == 'Intersection':
        return max(dist_a, dist_b)
    elif node.operation == 'Difference':
        return max(dist_a, -dist_b)
    else:
        raise ValueError(f"Unknown operation: {node.operation}")
```

## Subtopics

### [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md)
A method that combines multiple implicit functions (typically SDFs) into a single implicit function using Boolean operations. It differs from [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md) by focusing on the mathematical composition of scalar fields or classification maps rather than spatial transformation. It differs from [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md) by providing specific implementation strategies for discrete voxel buffers and classification look-up tables, often involving the generation and combination of Hermite data (material grids and edge data) rather than just scalar field evaluation [1627-constructive-solid-geometry-csg-on-level-sets.md].

### [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md)
An interactive editor that constructs SDFs from primitives and operations using a stack-based interface similar to Reverse Polish Notation (RPN). It implicitly represents a tree with postorder traversal, deferring structure resolution until compilation. This allows users to build complex scenes by pushing operations onto a linear stack where only the top item is visible until combined [1696-stack-based-sdf-editor.md].

### Smooth SDF Boolean Composition
A symbolic representation and evaluation method for constructing complex implicit surfaces by composing primitive SDFs using smooth approximations of Boolean operations. It uses a blend factor $k$ to create rounded fillets.
- **Smooth Union (OR):** $f_{or} = f_1 + f_2 + \sqrt{f_1^2 + f_2^2}$ [S15, unofficial]
- **Smooth Intersection (AND):** $f_{and} = f_1 + f_2 - \sqrt{f_1^2 + f_2^2}$ [S15, unofficial]
- **Smooth Subtraction:** $f_{sub} = f_{and}(f_1, -f_2)$ [S15, unofficial]
- **Parameter:** `inside_positive` flag indicates whether positive values represent the interior [S15, unofficial].

### Patch-wise Merge Loss
A loss term computed within merge cells to ensure the zero-level set of the merged implicit function accurately reproduces the target geometry via Boolean operations. It builds a CSG tree for connected components at non-empty leaf nodes of the merge grid and assigns a loss $L_{merge}^p$ to involved patches [S16].

## Operating characteristics
- **Time Complexity:** For discrete voxel-based implementations, material index generation and combination is $O(n^3)$, and edge generation is $O(3 \times n^3)$, where $n$ is the resolution [S1]. Tree-based evaluations are proportional to the depth of the CSG tree.
- **Memory Complexity:** Depends on the implementation. Tree-based approaches require memory proportional to the number of nodes. Voxel-based approaches require $O(n^3)$ for the material grid and edge arrays [S1].
- **Strengths:** Simple arithmetic implementation; allows for infinite complexity of shapes from simple primitives; efficient for ray marching as it avoids explicit mesh generation [S3, S7, unofficial].
- **Limitations:** Smooth operations are not exact SDFs (distance metric is distorted); subtraction can produce non-Lipschitz-1 surfaces if shapes intersect improperly; complex trees can be slow to evaluate if not optimized [S12, S4, unofficial].
- **When to use:** Ideal for ray-marched rendering of procedural geometry, CAD-like scenes, and real-time applications where mesh generation overhead is prohibitive [S7, unofficial].
- **When not to use:** When exact analytical normals are required for complex boolean intersections without approximation, or when the scene is static and a mesh representation is more efficient for rasterization.

## Background
CSG was originally defined by William Newman and Robert Sproull in 1973 and later formalized by Ian Bucklin and others. The application of CSG to Signed Distance Functions was popularized in the computer graphics community through the work of Inigo Quilez and others in the context of ray marching and shader programming [S3, S12, S13, unofficial]. The method leverages the property that the zero-level set of the min/max functions corresponds to the union/intersection of the zero-level sets of the operands [S8].
