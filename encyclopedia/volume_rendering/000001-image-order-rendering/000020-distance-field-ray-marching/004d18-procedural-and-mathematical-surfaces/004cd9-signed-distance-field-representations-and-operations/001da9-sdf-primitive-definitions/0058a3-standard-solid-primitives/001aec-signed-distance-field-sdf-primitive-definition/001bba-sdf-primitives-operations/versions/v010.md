# SDF Primitives & Operations

Also called: Implicit Shape Functions, Raycasting with SDFs, Raymarching with SDFs, Signed Distance Function (SDF) Primitives and Operators, Signed Distance Function Primitives

## Overview
SDF Primitives & Operations define the foundational analytical functions and boolean/combinatorial operators used to represent complex 3D geometry as implicit surfaces for distance-field ray marching [S11, unofficial]. They solve the problem of replacing explicit mesh topology with continuous scalar fields, enabling safe, large step sizes along rays by leveraging the property that the function value indicates the exact distance to the nearest surface [G]. What sets them apart from polygonal primitives is their reliance on closed-form algebraic solutions for standard shapes (spheres, boxes, tori) and their ability to combine via min/max operations to form complex CSG structures without topological maintenance [S11, unofficial]. Unlike [SDF Transformation](1086-sdf-transformation.md) which modifies the input coordinate space, or [SDF Rounding](1829-sdf-rounding.md) which modifies the output range, these primitives and operations define the core geometric definitions and their direct combinations [S1, S3, unofficial].

## How it works

### Inputs and Outputs
**Inputs:**
- Query point $\mathbf{p} \in \mathbb{R}^3$ (in local or world space).
- Primitive parameters: position $\mathbf{c}$, radius $r$, half-extents $\mathbf{b}$, normal $\mathbf{n}$, height $h$, etc.
- For operations: two SDF functions $f_A, f_B$ and their respective parameters.

**Outputs:**
- Scalar signed distance $d \in \mathbb{R}$.
- $d > 0$: point is outside the surface.
- $d = 0$: point is on the surface.
- $d < 0$: point is inside the surface.

### Data Structures
The implementation typically involves a struct or class hierarchy representing the SDF map.
- `Material`: Enum or struct containing color and physical properties (e.g., `Lambertian { color: Vec3 }`, `Specular { color: Vec3, specularity: f32, fuzziness: f32 }`) [S1, unofficial].
- `DistInfo`: Struct containing `distance: f32` and `material: Material` [S1, unofficial].
- `SdfMap`: Interface or base class with a method `ray_intersection(ray)` or `eval(p)` returning `DistInfo` [S1, unofficial].
- `Union`/`Intersection`: Composite structs holding references to two child SDFs (`sdf1`, `sdf2`) [S1, unofficial].

### Standard Solid Primitives

#### Sphere
Parametrized by center $\mathbf{c}$ and radius $r$.
Formula:
$$ d(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r $$
Implementation:
```python
def sphere(p, c, r):
    return length(p - c) - r
```

#### Box (AABB)
Parametrized by center $\mathbf{c}$ and half-extents $\mathbf{b} = (b_x, b_y, b_z)$.
Formula:
$$ d(\mathbf{p}) = \|\max(\mathbf{q}, \mathbf{0})\| + \min(\max(q_x, \max(q_y, q_z)), 0) $$
where $\mathbf{q} = |\mathbf{p} - \mathbf{c}| - \mathbf{b}$ [S3, unofficial].
Implementation:
```python
def box(p, c, b):
    q = abs(p - c) - b
    q_max = max(q, 0.0)
    return length(q_max) + min(max(q.x, max(q.y, q.z)), 0.0)
```

#### Torus
Parametrized by center $\mathbf{c}$, major radius $R$ (distance from center to tube center), and minor radius $r$ (tube radius).
Formula:
$$ d(\mathbf{p}) = \|\vec{2}(\|\mathbf{p}_{xy} - \mathbf{c}_{xy}\| - R, p_z - c_z)\| - r $$
where $\mathbf{p}_{xy}$ is the projection of $\mathbf{p}$ onto the XY plane [S1, unofficial].
Implementation:
```python
def torus(p, c, R, r):
    # Assuming torus lies in XY plane, centered at c
    dist_xy = length(p.xy - c.xy) - R
    return length(vec2(dist_xy, p.z - c.z)) - r
```

#### Plane
Parametrized by a point $\mathbf{p}_0$ on the plane and normal $\mathbf{n}$ (unit length).
Formula:
$$ d(\mathbf{p}) = (\mathbf{p} - \mathbf{p}_0) \cdot \mathbf{n} $$
If $\mathbf{p}_0$ is origin: $d(\mathbf{p}) = \mathbf{p} \cdot \mathbf{n}$ [S1, unofficial].

#### Cylinder
Parametrized by axis direction $\mathbf{a}$ (unit), center $\mathbf{c}$, height $h$, and radius $r$.
1. Project $\mathbf{p}$ onto axis: $t = (\mathbf{p} - \mathbf{c}) \cdot \mathbf{a}$.
2. Clamp $t$ to $[-h/2, h/2]$.
3. Compute radial distance from axis.
4. Combine radial and axial distances.

#### Round Box / Round Cylinder
Similar to Box/Cylinder, but edges are rounded by a radius $r_{round}$.
Formula (Round Box):
$$ d(\mathbf{p}) = \|\max(\mathbf{q} - r_{round}, \mathbf{0})\| + \min(\max(q_x - r_{round}, \max(q_y - r_{round}, q_z - r_{round})), 0) + r_{round} - \|\mathbf{q}\| \text{ (approx)} $$
More precisely, it subtracts $r_{round}$ from the edge calculations [S6, unofficial].

### CSG Operations

#### Union
Combines two shapes $A$ and $B$. The resulting SDF is the minimum of the two distances.
Formula:
$$ d_{union}(\mathbf{p}) = \min(f_A(\mathbf{p}), f_B(\mathbf{p})) $$
Implementation:
```python
def union(a, b, p):
    return min(a(p), b(p))
```

#### Intersection
Combines two shapes $A$ and $B$. The resulting SDF is the maximum of the two distances.
Formula:
$$ d_{intersect}(\mathbf{p}) = \max(f_A(\mathbf{p}), f_B(\mathbf{p})) $$
Implementation:
```python
def intersection(a, b, p):
    return max(a(p), b(p))
```

#### Difference (Subtraction)
Subtracts shape $B$ from shape $A$.
Formula:
$$ d_{diff}(\mathbf{p}) = \max(f_A(\mathbf{p}), -f_B(\mathbf{p})) $$
Implementation:
```python
def difference(a, b, p):
    return max(a(p), -b(p))
```

### Smooth Blending
Standard min/max operations create sharp discontinuities in the derivative. Smooth blending uses a smooth minimum function to interpolate between shapes.
Formula (Smooth Min, Quilez):
$$ \text{smoothmin}(a, b, k) = \frac{h}{h + k} \quad \text{where} \quad h = \max(-k, b - a) $$
Or equivalently:
$$ \text{smoothmin}(a, b, k) = \begin{cases} b & \text{if } a \ge b \\ a & \text{if } b \ge a \\ \frac{b + h - k \ln(1 + e^{(b-a)/k})}{1} & \dots \end{cases} $$
Common implementation:
```python
def smooth_min(a, b, k):
    h = max(k - abs(a - b), 0.0)
    return min(a, b) - h * h / (4.0 * k)
```
Note: This trades distance field accuracy for visual smoothness [S2, unofficial].

### Domain Manipulation (Transformations)
Transformations are applied to the input point $\mathbf{p}$ before evaluation.

#### Translation
Shift the point by offset $\mathbf{t}$.
$$ d(\mathbf{p}) = f(\mathbf{p} - \mathbf{t}) $$

#### Rotation
Rotate the point by inverse rotation matrix $R^{-1}$ or quaternion $q^{-1}$.
$$ d(\mathbf{p}) = f(R^{-1}(\mathbf{p} - \mathbf{c}) + \mathbf{c}) $$

#### Scaling
Scale the point by $1/s$ and divide the result by $s$.
$$ d(\mathbf{p}) = \frac{1}{s} f\left(\frac{\mathbf{p} - \mathbf{c}}{s} + \mathbf{c}\right) $$

#### Tiling (Modulo)
Repeat the primitive periodically.
$$ \mathbf{p}' = \mathbf{p} - \text{period} \cdot \text{floor}\left(\frac{\mathbf{p}}{\text{period}} + 0.5\right) $$
$$ d(\mathbf{p}) = f(\mathbf{p}') $$
Implementation:
```python
def repeat(p, period):
    return p - period * floor(p / period + 0.5)
```

### Ray Marching Loop
To render an SDF primitive, a ray is marched through space.
1. **Initialize**: $t = 0$, $\mathbf{p} = \mathbf{origin}$.
2. **Loop**:
   - Evaluate $d = f(\mathbf{p})$.
   - If $d < \epsilon$ (surface hit), break.
   - If $t > t_{max}$ (miss), break.
   - Advance: $t \leftarrow t + d \cdot \text{step\_scale}$ (where step_scale $\le 1.0$ for safety) [G].
   - $\mathbf{p} \leftarrow \mathbf{origin} + t \cdot \mathbf{direction}$.
3. **Output**: Hit point, normal (computed via gradient), material.

### Normal Computation
Normals are computed using central differences.
$$ \mathbf{n} = \text{normalize}\left( \begin{bmatrix} f(\mathbf{p} + \Delta_x) - f(\mathbf{p} - \Delta_x) \\ f(\mathbf{p} + \Delta_y) - f(\mathbf{p} - \Delta_y) \\ f(\mathbf{p} + \Delta_z) - f(\mathbf{p} - \Delta_z) \end{bmatrix} \right) $$
where $\Delta_x = (\epsilon, 0, 0)$, etc. [S3, unofficial].

### Pitfalls and Edge Cases
- **Division by Zero**: In fractals like Mandelbulb, $\text{atan}(w_x/w_z)$ fails if $w_z=0$, and $\text{acos}(w_y/r)$ fails if $r=0$ [S1, unofficial]. Guard against these.
- **Discontinuities**: Standard min/max operations break the interior distance field for complex shapes, potentially causing artifacts in effects like ambient occlusion or smooth blending [S8, unofficial].
- **Mirroring Artifacts**: Mirroring coordinates (e.g., `abs(p.y)`) creates concave edges that break the distance field accuracy because the SDF does not "know" about the new corner [S8, unofficial].
- **Rounding Size**: Rounding a shape by subtracting thickness makes the bounding box larger; the primitive's base size must be reduced by the thickness first [S8, unofficial].

## Subtopics

### [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md)
SDF Domain Manipulation Operators modify the input position vector $\mathbf{p}$ before it is passed to a base SDF primitive, effectively transforming the coordinate space to create periodic, mirrored, reflected, or stretched structures. They solve the problem of generating complex geometric patterns (such as grids, twists, or elongated shapes) from simple primitives without altering the primitive's internal distance calculation logic. They differ from [SDF Rounding](1829-sdf-rounding.md) and [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md) by operating on the input position vector $\mathbf{p}$ (domain transformation) rather than on the scalar distance output (range transformation).

### [Quadric SDF (First-Order Approximation)](2682-quadric-sdf-first-order-approximation.md)
Computes an approximate signed distance from a query point to a general quadric surface defined by a quadratic implicit equation, using a first-order Taylor approximation. It differs from exact SDF primitives (like spheres or boxes) by handling arbitrary second-order surfaces (ellipsoids, hyperboloids, paraboloids) at the cost of geometric accuracy, trading precision for the ability to model complex algebraic shapes without analytical distance formulas.

### [SDF Tiling via Modulo](4713-sdf-tiling-via-modulo.md)
Repeating SDF Geometry creates a periodic tiling of a base signed distance field by folding 3D coordinates into a fundamental domain centered at the origin. It segments space into infinite parallel regions of repeated distance by taking the modulus of a point’s position along one or more axes before computing the signed distance. This technique allows for the infinite repetition of geometry for no extra computational cost.

### [Basic Primitive Definitions](5346-basic-primitive-definitions.md)
Basic Primitive Definitions provide the foundational analytical functions that compute the exact Euclidean signed distance from a query point to standard geometric shapes, serving as the atomic building blocks for distance-field ray marching. They replace explicit mesh geometry with implicit mathematical definitions, enabling safe, large step sizes along rays by leveraging the continuous scalar field where the sign indicates interior ($d < 0$) or exterior ($d > 0$) status [G]. Unlike polygonal primitives or iterative approximations, these primitives rely on closed-form algebraic solutions for standard shapes like spheres, boxes, and tori.

### [Higher Order Algebraic Signed Distance Fields](8500-higher-order-algebraic-signed-distance-fields.md)
Higher Order Algebraic Signed Distance Fields (HOASDFs) generalize traditional signed distance fields by approximating the distance function over a larger area using local Taylor approximations or least squares fit polynomials.

### [Smooth Blending and CSG Operations](14568-smooth-blending-and-csg-operations.md)
This family defines the mathematical operators and coordinate transformations required to construct complex procedural geometry from primitive Signed Distance Fields (SDFs). It solves the problem of combining simple shapes into complex models and positioning them in world space. It is distinguished from exact Boolean operations by its support for smooth blending approximations, which allow for continuous gradients and organic transitions between shapes, at the cost of distance field accuracy.

### [Gradient-SDF](22971-gradient-sdf.md)
Gradient-SDF is a hybrid 3D geometry representation that augments a voxel-based implicit Signed Distance Field (SDF) with the SDF gradient vector field at each voxel, combining implicit topology handling with explicit surface feature access. It solves the problem of costly neighbor lookups required for gradient computation in sparse SDF storage (e.g., hash maps) by storing gradients directly, enabling efficient interpolation via first-order Taylor expansion without accessing multiple voxels. Unlike standard sparse SDFs which require accessing 8 voxels for interpolation or gradient computation, Gradient-SDF allows direct access to the gradient per voxel, facilitating direct SDF tracking from depth images and photometric bundle adjustment directly in the voxel representation.

## Operating characteristics

**Time Complexity:**
- Primitive evaluation: $O(1)$ per primitive.
- Ray marching: $O(N)$ where $N$ is the number of steps. $N$ depends on the scene complexity and the tightness of the SDF bounds. Smooth blending and complex CSG operations increase the constant factor per step.

**Memory Complexity:**
- Procedural SDFs: $O(1)$ memory, as geometry is defined by code.
- Voxel-based SDFs (e.g., Gradient-SDF): $O(V)$ where $V$ is the number of voxels.

**Performance:**
- SDFs allow for large step sizes compared to ray-triangle intersection, often resulting in fewer samples per ray for simple scenes [S8, unofficial].
- However, evaluating complex CSG trees or fractals (like Mandelbulb) can be computationally expensive per step [S1, unofficial].
- Backface Distance Fields (BDF) can improve convergence rates for sphere tracing by using relaxed distance estimates for backfacing surfaces, generally outperforming basic sphere tracing [S12, abstract only, unofficial].

**Strengths:**
- Intuitive shape construction and modification [S8, unofficial].
- No need for mesh generation or topological maintenance.
- Easy implementation of anti-aliasing, outlines, and soft shadows [S8, unofficial].
- Compact representation for procedural geometry.

**Limitations:**
- Sharp CSG operations (min/max) break the distance field accuracy, affecting effects like ambient occlusion and smooth blending [S8, unofficial].
- Mirroring and tiling can introduce artifacts if not handled carefully [S8, unofficial].
- Hard to represent non-manifold geometry or complex topology changes dynamically.

**When to use:**
- Procedural generation, fractals, and organic shapes.
- Real-time rendering where memory bandwidth is a constraint.
- Scenes with simple, repetitive geometry.

**When not to use:**
- Highly detailed, static meshes with complex topology.
- Applications requiring exact distance metrics for physics or precise collision detection (use exact primitives or meshes).

## Background

SDFs were popularized in computer graphics by Inigo Quilez in his articles on raymarching and distance fields [S13, unofficial]. The mathematical foundation relies on the work of Hart (1989) on implicit surfaces and CSG operations [S7, unofficial]. The technique allows for raycasting and physics simulations by treating geometry as implicit functions [S8, unofficial]. Variants like Backface Distance Fields (BDF) have been proposed to enhance sphere tracing convergence [S12, abstract only, unofficial]. Solid noise primitives combine SDFs with fractal noise for volumetric effects [S10, unofficial].
