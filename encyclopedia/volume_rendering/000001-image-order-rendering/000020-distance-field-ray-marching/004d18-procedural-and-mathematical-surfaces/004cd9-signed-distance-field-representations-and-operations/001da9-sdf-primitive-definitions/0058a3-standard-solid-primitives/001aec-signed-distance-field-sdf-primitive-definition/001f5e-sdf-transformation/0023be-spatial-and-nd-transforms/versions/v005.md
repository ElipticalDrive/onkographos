# Spatial and nD transforms

Also called: Transforming SDF Geometry, hierarchical transforms, inverse transform query

## Overview
Spatial and nD transforms allow the application of geometric transformations (rotation, translation, scaling, and permutation) to Signed Distance Field (SDF) primitives and discrete data structures by applying the inverse transformation to the query point rather than transforming the geometry itself [S1, unofficial][S2, unofficial]. This approach ensures that the underlying data structures remain unmodified, preserving local linearity and allowing constant-time affine queries per dimension [S1, unofficial]. It differs from direct geometry transformation by deferring the coordinate change to the evaluation step, which avoids distorting the stored data and supports non-uniform or spatially varying distortions [S2, unofficial].

## How it works
The method operates by mapping a world-space query point back to the local space of the primitive or data grid using the inverse of the desired transformation matrix [S1, unofficial][S2, unofficial]. This applies to both continuous SDFs and discrete multi-dimensional data structures [S1, unofficial][S2, unofficial].

### Inputs and Outputs
- **Input**: A query point $P_{world}$ in world coordinates [S1, unofficial][S2, unofficial].
- **Input**: A transformation matrix $T$ (or its components: scale, offset, permutation) defining the local-to-world mapping [S1, unofficial][S2, unofficial].
- **Output**: A transformed point $P_{local}$ (or transformed tolerance) suitable for evaluating the base distance function or accessing the data grid [S1, unofficial][S2, unofficial].

### Data Structures
For discrete multi-dimensional data (e.g., voxel grids or splatting indices), transforms are stored per node or dimension [S1, unofficial]:
- **Affine Transform**: Defined by a scale factor $s$ and an offset $o$ [S1, unofficial].
- **Permutation Transform**: Defined by a permutation array $perm$ mapping indices [S1, unofficial].
- **Composition**: Affine transforms compose as $s = s_p s_c$ and $o = s_p o_c + o_p$; permutations compose as $r[i] = perm_p[perm_c[i]]$ [S1, unofficial].

### Steps
1. **Construct Inverse Transform**: Determine the inverse of the local-to-world transformation $T$ [S2, unofficial]. For a composite transformation $T = S \cdot R \cdot T_{trans}$, compute $T^{-1}$ [S2, unofficial].
2. **Apply Inverse to Query Point**:
   - For **SDFs**: Transform the query point $P_{world}$ to $P_{local}$ using $T^{-1}$ [S2, unofficial].
   - For **Discrete Data**: Inverse-transform the slice query per dimension rather than per point to maintain constant work for affine transforms [S1, unofficial].
3. **Evaluate Base Function**: Use $P_{local}$ to evaluate the base distance function or access the data grid [S1, unofficial][S2, unofficial].

### Formulas
- **Affine Transform (Continuous/Discrete)**:
  Given a world position $P_{world}$ and tolerance $T_{world}$, and affine parameters scale $s$ and offset $o$:
  $$ P_{raw} = \frac{P_{world} - o}{s} $$
  $$ T_{raw} = \frac{T_{world}}{|s|} $$
  [S1, unofficial]
- **Permutation Transform (Discrete)**:
  Given a permutation array $perm$, the inverse mapping is:
  $$ inverse[perm[i]] = i $$
  [S1, unofficial]
- **Matrix Inverse (SDF)**:
  For a 4x4 transformation matrix $M$ (combining scale $S$, rotation $R$, and translation $T$), the transformed point $P_{local}$ is:
  $$ P_{local} = (P_{world} \cdot M^{-1}).xyz $$
  where $P_{world}$ is treated as a homogeneous vector $(x, y, z, 1)$ [S2, unofficial].

### Parameters
- **Scale ($s$)**: Non-uniform scaling factors [S1, unofficial]. A zero scale is accepted but triggers a validation warning, leaving the query untransformed [S1, unofficial].
- **Offset ($o$)**: Translation vector [S1, unofficial].
- **Permutation ($perm$)**: Array mapping discrete indices [S1, unofficial].
- **Norm**: In nD geometric transformation contexts, if `norm != 0`, the result is projected onto the $z=norm$ plane [S3, unofficial].

### Pseudocode
The following pseudocode demonstrates the application of an inverse transform to an SDF query point, combining translation, rotation, and scaling [S2, unofficial].

```python
def invert_matrix_4x4(m):
    """Computes the inverse of a 4x4 matrix using cofactor expansion [G]."""
    inv = [[0.0]*4 for _ in range(4)]
    inv[0][0] = m[1][1]*m[2][2]*m[3][3] - m[1][1]*m[2][3]*m[3][2] - m[1][2]*m[2][1]*m[3][3] + m[1][2]*m[2][3]*m[3][1] + m[1][3]*m[2][1]*m[3][2] - m[1][3]*m[2][2]*m[3][1]
    inv[0][1] = -m[0][1]*m[2][2]*m[3][3] + m[0][1]*m[2][3]*m[3][2] + m[0][2]*m[2][1]*m[3][3] - m[0][2]*m[2][3]*m[3][1] - m[0][3]*m[2][1]*m[3][2] + m[0][3]*m[2][2]*m[3][1]
    inv[0][2] = m[0][1]*m[1][2]*m[3][3] - m[0][1]*m[1][3]*m[3][2] - m[0][2]*m[1][1]*m[3][3] + m[0][2]*m[1][3]*m[3][1] + m[0][3]*m[1][1]*m[3][2] - m[0][3]*m[1][2]*m[3][1]
    inv[0][3] = -m[0][1]*m[1][2]*m[2][3] + m[0][1]*m[1][3]*m[2][2] + m[0][2]*m[1][1]*m[2][3] - m[0][2]*m[1][3]*m[2][1] - m[0][3]*m[1][1]*m[2][2] + m[0][3]*m[1][2]*m[2][1]
    inv[1][0] = -m[1][0]*m[2][2]*m[3][3] + m[1][0]*m[2][3]*m[3][2] + m[1][2]*m[2][1]*m[3][3] - m[1][2]*m[2][3]*m[3][1] - m[1][3]*m[2][1]*m[3][2] + m[1][3]*m[2][2]*m[3][1]
    inv[1][1] = m[0][0]*m[2][2]*m[3][3] - m[0][0]*m[2][3]*m[3][2] - m[0][2]*m[2][1]*m[3][3] + m[0][2]*m[2][3]*m[3][1] + m[0][3]*m[2][1]*m[3][2] - m[0][3]*m[2][2]*m[3][1]
    inv[1][2] = -m[0][0]*m[1][2]*m[3][3] + m[0][0]*m[1][3]*m[3][2] + m[0][2]*m[1][1]*m[3][3] - m[0][2]*m[1][3]*m[3][1] - m[0][3]*m[1][1]*m[3][2] + m[0][3]*m[1][2]*m[3][1]
    inv[1][3] = m[0][0]*m[1][2]*m[2][3] - m[0][0]*m[1][3]*m[2][2] - m[0][2]*m[1][1]*m[2][3] + m[0][2]*m[1][3]*m[2][1] + m[0][3]*m[1][1]*m[2][2] - m[0][3]*m[1][2]*m[2][1]
    inv[2][0] = m[1][0]*m[2][2]*m[3][3] - m[1][0]*m[2][3]*m[3][2] - m[1][2]*m[2][1]*m[3][3] + m[1][2]*m[2][3]*m[3][1] + m[1][3]*m[2][1]*m[3][2] - m[1][3]*m[2][2]*m[3][1]
    inv[2][1] = -m[0][0]*m[2][2]*m[3][3] + m[0][0]*m[2][3]*m[3][2] + m[0][2]*m[2][1]*m[3][3] - m[0][2]*m[2][3]*m[3][1] - m[0][3]*m[2][1]*m[3][2] + m[0][3]*m[2][2]*m[3][1]
    inv[2][2] = m[0][0]*m[1][2]*m[3][3] - m[0][0]*m[1][3]*m[3][2] - m[0][2]*m[1][1]*m[3][3] + m[0][2]*m[1][3]*m[3][1] + m[0][3]*m[1][1]*m[3][2] - m[0][3]*m[1][2]*m[3][1]
    inv[2][3] = -m[0][0]*m[1][2]*m[2][3] + m[0][0]*m[1][3]*m[2][2] + m[0][2]*m[1][1]*m[2][3] - m[0][2]*m[1][3]*m[2][1] - m[0][3]*m[1][1]*m[2][2] + m[0][3]*m[1][2]*m[2][1]
    inv[3][0] = -m[1][0]*m[2][1]*m[3][3] + m[1][0]*m[2][3]*m[3][1] + m[1][1]*m[2][2]*m[3][3] - m[1][1]*m[2][3]*m[3][2] - m[1][3]*m[2][1]*m[3][1] + m[1][3]*m[2][2]*m[3][1]
    inv[3][1] = m[0][0]*m[2][1]*m[3][3] - m[0][0]*m[2][3]*m[3][1] - m[0][1]*m[2][2]*m[3][3] + m[0][1]*m[2][3]*m[3][2] + m[0][3]*m[2][1]*m[3][1] - m[0][3]*m[2][2]*m[3][1]
    inv[3][2] = -m[0][0]*m[1][1]*m[3][3] + m[0][0]*m[1][3]*m[3][1] + m[0][1]*m[1][2]*m[3][3] - m[0][1]*m[1][3]*m[3][2] - m[0][3]*m[1][1]*m[3][1] + m[0][3]*m[1][2]*m[3][1]
    inv[3][3] = m[0][0]*m[1][1]*m[2][3] - m[0][0]*m[1][3]*m[2][1] - m[0][1]*m[1][2]*m[2][3] + m[0][1]*m[1][3]*m[2][1] + m[0][3]*m[1][1]*m[2][1] - m[0][3]*m[1][2]*m[2][1]
    det = m[0][0]*inv[0][0] + m[0][1]*inv[1][0] + m[0][2]*inv[2][0] + m[0][3]*inv[3][0]
    if det == 0:
        raise ValueError("Matrix is singular and cannot be inverted.")
    inv = [[inv[i][j]/det for j in range(4)] for i in range(4)]
    return inv

def inverse_transform_query(pt_world, transform_matrix):
    """
    Applies the inverse of a 4x4 transformation matrix to a 3D point [S2, unofficial].
    Args:
        pt_world: tuple of 3 floats, the query point in world space.
        transform_matrix: list of lists, 4x4 matrix representing the local-to-world transform.
    Returns:
        tuple of 3 floats, the transformed point in local space.
    """
    pt_homogeneous = (pt_world[0], pt_world[1], pt_world[2], 1.0)
    inv_matrix = invert_matrix_4x4(transform_matrix)
    pt_local_x = inv_matrix[0][0]*pt_homogeneous[0] + inv_matrix[0][1]*pt_homogeneous[1] + inv_matrix[0][2]*pt_homogeneous[2] + inv_matrix[0][3]*pt_homogeneous[3]
    pt_local_y = inv_matrix[1][0]*pt_homogeneous[0] + inv_matrix[1][1]*pt_homogeneous[1] + inv_matrix[1][2]*pt_homogeneous[2] + inv_matrix[1][3]*pt_homogeneous[3]
    pt_local_z = inv_matrix[2][0]*pt_homogeneous[0] + inv_matrix[2][1]*pt_homogeneous[1] + inv_matrix[2][2]*pt_homogeneous[2] + inv_matrix[2][3]*pt_homogeneous[3]
    return (pt_local_x, pt_local_y, pt_local_z)

def evaluate_transformed_sdf(pt_world, transform_matrix, base_sdf_func):
    """
    Evaluates an SDF after applying a spatial transform [S2, unofficial].
    Args:
        pt_world: tuple of 3 floats, query point.
        transform_matrix: list of lists, 4x4 matrix, local-to-world transform.
        base_sdf_func: function, the base distance function (e.g., sphere).
    Returns:
        float, the signed distance.
    """
    pt_local = inverse_transform_query(pt_world, transform_matrix)
    return base_sdf_func(pt_local)

def sphere(pt):
    return (pt[0]**2 + pt[1]**2 + pt[2]**2)**0.5 - 1.0

def f_translate(pt_world):
    # Translation by (0, 3, 0)
    # Inverse translation is (0, -3, 0)
    pt_local = (pt_world[0], pt_world[1] - 3.0, pt_world[2])
    return sphere(pt_local)
```

For discrete nD geometric transformations, the exact tensor operations are not given in the sources [G]. The method instead inverse-transforms the slice query per dimension to maintain constant work for affine transforms [S1, unofficial].

### Edge Cases and Pitfalls
- **Zero Scale**: A zero scale factor is accepted but triggers a validation warning. The query remains untransformed in this case [S1, unofficial].
- **Discrete Grid Alignment**: On a discrete axis, the world value is rounded onto the declared grid. If a value has no local preimage (i.e., it falls between grid points), it selects nothing [S1, unofficial].
- **Non-Uniform Distortion**: Non-uniform spatial distortion modifies 'all of space' with the same transform, so distance functions retain their local linearity. Spatially varying distortion can also be applied by making the transform a function of the point's position [S2, unofficial].
- **Precision**: Inverse transformation queries must handle floating-point precision carefully, especially when dealing with large translation offsets or small scale factors [G].

## Subtopics

### [SDF Rotation](5817-sdf-rotation.md)
SDF Rotation applies a rotational transformation to a signed distance field primitive by rotating the sampling point before evaluating the base distance function. It is chosen when an object needs to be oriented in world space without modifying its underlying SDF definition. It is a specific case of the general inverse transform method, focusing solely on the rotational component of the transformation matrix. See [SDF Rotation](5817-sdf-rotation.md).

## Operating characteristics
- **Time Complexity**: For affine transforms, the query time is constant per dimension, independent of the data size, as it involves simple arithmetic operations [S1, unofficial]. For permutations, it requires one pass over the category list [S1, unofficial].
- **Memory Complexity**: No additional memory is required for the transformation itself, as the inverse is applied on-the-fly to the query point [S1, unofficial][S2, unofficial].
- **Strengths**: Preserves the integrity of the underlying data structure; supports non-uniform and spatially varying distortions; efficient for discrete data by avoiding per-point transformation [S1, unofficial][S2, unofficial].
- **Limitations**: Requires computing the inverse transformation matrix, which can be computationally expensive if done per-query (though typically done once per frame/object) [S2, unofficial]. Zero scale leads to undefined behavior unless handled [S1, unofficial].
- **When to Use**: When transforming SDF primitives or discrete data structures for rendering or visualization, especially when the underlying data should remain unmodified [S1, unofficial][S2, unofficial].
- **When Not to Use**: When the transformation is simple enough to be baked into the data structure, or when the inverse transformation is not available or difficult to compute [G].

## Background
The concept of applying inverse transformations to query points in SDF rendering is a standard technique in ray marching, popularized by tutorials and resources such as those by Inigo Quilez [S2, unofficial]. The application of hierarchical and nD transforms to discrete scientific data (e.g., microscopy data) for scalable web visualization was detailed in the Luxar paper, which introduced per-node affine and permutation transforms for multi-dimensional data [S1, unofficial]. The geometric transformation application in nD spaces is supported by deep learning frameworks, though the exact tensor implementation details are not provided in the sources [G].
