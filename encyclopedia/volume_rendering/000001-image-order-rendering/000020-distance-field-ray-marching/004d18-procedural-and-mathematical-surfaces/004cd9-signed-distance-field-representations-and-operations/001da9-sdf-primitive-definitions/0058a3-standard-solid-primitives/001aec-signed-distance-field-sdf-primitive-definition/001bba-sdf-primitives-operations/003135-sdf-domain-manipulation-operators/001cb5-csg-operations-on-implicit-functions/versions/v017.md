# CSG Operations on Implicit Functions

Also called: CSG Operations, Boolean SDF operators, SDF Boolean Operators, SDF Boolean Operations, CSG implicit surfaces, Constructive Solid Geometry with SDFs, CSG with SDFs, CSG SDF combination, CSG Operations for SDFs

## Overview
CSG Operations on Implicit Functions combine multiple Signed Distance Functions (SDFs) into a single implicit function using Boolean logic (Union, Intersection, Difference) [S1][S2, S3, S7, unofficial]. This method solves the problem of defining complex composite shapes from simple primitives within a volumetric or ray-marched context [S1][S7, unofficial]. It differs from sibling methods like [SDF Rounding](1829-sdf-rounding.md) and [Elongation](2440-elongation.md) by operating on the scalar field values directly rather than modifying the input position vector $\mathbf{p}$ [S1][S3, S12, unofficial]. It differs from [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md) by providing specific implementation strategies for discrete voxel buffers and classification look-up tables, whereas this method focuses on the continuous arithmetic composition of scalar fields [S1][S7, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Two SDF values $f(\mathbf{p})$ and $g(\mathbf{p})$ at a query point $\mathbf{p} \in \mathbb{R}^3$, or a tree of SDF primitives.
*   **Output:** A combined SDF value $h(\mathbf{p})$ representing the Boolean result.

**Data Structures:**
The method can be implemented as a recursive tree structure or direct arithmetic composition.
*   **Tree Node:** Contains an `operation` enum (`Union`, `Intersection`, `Difference`) and pointers to two child nodes (left and right) [S2, S4, unofficial].
*   **Leaf Node:** Contains the base SDF function and an optional material ID [S2, unofficial].

**Formulas:**
The Boolean operations map directly to mathematical operators on the signed distance values [S1][S3, unofficial][S8][S10, S13, unofficial]:

1.  **Union ($A \cup B$):** The distance to the union is the minimum of the individual distances. A point is inside the union if it is inside either shape.
    $$ h(\mathbf{p}) = \min(f(\mathbf{p}), g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, unofficial]

2.  **Intersection ($A \cap B$):** The distance to the intersection is the maximum of the individual distances. A point is inside the intersection only if it is inside both shapes. Note that this yields a signed distance *bound*, not necessarily the exact distance, because the closest point in the intersection may not be the closest point in either individual shape [S8].
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, unofficial]

3.  **Difference ($A \setminus B$):** Also known as Subtraction. This is equivalent to intersecting $A$ with the complement of $B$. The complement of an SDF is obtained by negating its value.
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), -g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, S14, unofficial]

4.  **XOR:** Exclusive OR.
    $$ h(\mathbf{p}) = \max(\min(f(\mathbf{p}), g(\mathbf{p})), -\max(f(\mathbf{p}), g(\mathbf{p}))) $$
    [S10, unofficial]

**Pseudocode:**
The following Python-like pseudocode implements the recursive evaluation of a CSG tree.

```python
import math

class SDFNode:
    """Base class for CSG tree nodes."""
    def evaluate(self, p):
        raise NotImplementedError

class LeafNode(SDFNode):
    """Represents a primitive SDF."""
    def __init__(self, sdf_func):
        self.sdf = sdf_func

    def evaluate(self, p):
        return self.sdf(p)

class BinaryNode(SDFNode):
    """Represents a Boolean operation between two child nodes."""
    def __init__(self, left, right, operation):
        self.left = left
        self.right = right
        self.operation = operation

    def evaluate(self, p):
        a = self.left.evaluate(p)
        b = self.right.evaluate(p)
        
        if self.operation == 'Union':
            return min(a, b)
        elif self.operation == 'Intersection':
            return max(a, b)
        elif self.operation == 'Difference':
            return max(a, -b)
        else:
            raise ValueError(f"Unknown operation: {self.operation}")

def compute_csg_sdf(root_node, p):
    """
    Evaluates the CSG tree at point p.
    
    Args:
        root_node: The root SDFNode of the tree.
        p: A tuple or list (x, y, z) representing the query point.
        
    Returns:
        The signed distance value at p.
    """
    return root_node.evaluate(p)

# Example: Union of a Sphere and a Box
def sphere_sdf(p, center=(0,0,0), radius=1.0):
    return math.sqrt(sum((c - coord)**2 for coord, c in zip(p, center))) - radius

def box_sdf(p, half_size=(1,1,1)):
    dx = max(abs(p[0]) - half_size[0], 0.0)
    dy = max(abs(p[1]) - half_size[1], 0.0)
    dz = max(abs(p[2]) - half_size[2], 0.0)
    return math.sqrt(dx**2 + dy**2 + dz**2)

# Build tree: Union(Sphere, Box)
sphere = LeafNode(sphere_sdf)
box = LeafNode(box_sdf)
union_node = BinaryNode(sphere, box, 'Union')

# Evaluate
point = (0.5, 0.5, 0.5)
distance = compute_csg_sdf(union_node, point)
```

**Edge Cases and Pitfalls:**
*   **Scaling:** Scaling an SDF requires scaling the input coordinates by the inverse of the scale factor and scaling the output distance by the scale factor to maintain correct distance values [S3, unofficial].
*   **Subtraction Artefacts:** The formula $\max(-a, b)$ is exact only when the surface of $A$ is entirely contained within $B$. If $A$ pokes through the boundary of $B$, the resulting SDF is not Lipschitz-1, and sphere marching may skip surfaces. An EPSILON correction or tightened step size is required in those regions [S12, unofficial].
*   **DeMorgan’s Theorem:** DeMorgan’s theorem (intersection = complement of union of complements) does not work directly with min/max operators for distance bounds because the minimum operator is not complemented properly. Using `max` for intersection ensures the bound holds [S8].
*   **Material Boundaries:** Standard polygonizers do not consider materials, leading to drastic color changes between vertices at CSG boundaries. Material changes must be treated as surface boundaries (inside/outside changes) to separate colors correctly [S14, unofficial].

## Subtopics

### [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md)
Constructive Solid Geometry (CSG) on Level Sets combines multiple implicit functions (typically Signed Distance Fields, SDFs) into a single implicit function using Boolean operations (Union, Intersection, Difference). This method solves the problem of defining complex composite shapes from simple primitives within a volumetric or ray-marched context. It differs from sibling methods like the [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md) by focusing on the mathematical composition of scalar fields or classification maps rather than a procedural stack-based evaluation, and it differs from [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md) by providing specific implementation strategies for discrete voxel buffers and classification look-up tables.

### [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md)
An interactive editor that constructs Signed Distance Fields (SDFs) from primitives and operations using a stack-based interface similar to Reverse Polish Notation (RPN), implicitly representing a tree with postorder traversal. It differs from explicit tree editors by deferring structure resolution until compilation, allowing users to build complex scenes by pushing operations onto a linear stack where only the top item is visible until combined.

### Smooth SDF Boolean Composition
A symbolic representation and evaluation method for constructing complex implicit surfaces by composing primitive SDFs using smooth approximations of Boolean operations [S15, unofficial].
*   **Definition:** Uses smooth AND/OR functions to create rounded fillets between shapes, avoiding sharp creases [S15, unofficial].
*   **Formulas:**
    *   Smooth Intersection (AND): $f_{and} = f_1 + f_2 - \sqrt{f_1^2 + f_2^2}$
    *   Smooth Union (OR): $f_{or} = f_1 + f_2 + \sqrt{f_1^2 + f_2^2}$
    *   Subtraction: $f_{sub} = f_{and}(f_1, -f_2)$
*   **Parameters:** `inside_positive` (Boolean flag indicating if positive values represent the interior) [S15, unofficial].
*   **Usage:** Used to create organic blends between primitives, such as the `smin` function in GLSL shaders [S4, S5, S11, unofficial].

### Patch-wise Merge Loss
A loss term computed within merge cells to ensure the zero-level set of the merged implicit function accurately reproduces the target geometry via Boolean operations [S16].
*   **Definition:** Used in neural implicit surface representations to enforce geometric accuracy during training [S16].
*   **Formula:** $L_{merge}^p = \frac{1}{L} \sum_{l=1}^{L} \frac{1}{J} \sum_{j=1}^{J} L_{merge}^j$, where $L$ is the collection of cells in $S_p$ containing merge cells, and $J$ is the collection of merge cells in $F_{C_l}$ [S16].
*   **Usage:** Applied in differentiable rendering and neural implicit surface reconstruction [S16].

## Operating characteristics
*   **Time Complexity:** For discrete voxel-based implementations (e.g., terrain generation), material index generation and combination is $O(n^3)$, and edge generation is $O(3 \times n^3)$, where $n$ is the resolution [S1]. For ray-marched implementations, the complexity is dominated by the number of marching steps per ray, which depends on the scene's minimum distance and the smoothness of the resulting SDF.
*   **Memory Complexity:** Depends on the implementation. Tree-based structures require memory proportional to the number of nodes. Voxel-based structures require $O(n^3)$ for the material grid and edge arrays [S1].
*   **Strengths:** Simple to implement; computationally cheap for ray marching; allows for infinite detail and resolution independence; supports complex hierarchical scene construction [S3, S7, unofficial].
*   **Limitations:** The resulting SDF is only a bound for Intersection and Difference operations, which can cause artifacts in sphere tracing if not handled carefully (e.g., via EPSILON corrections) [S8][S12, unofficial]. Sharp creases from standard Boolean operations can be visually harsh; smooth variants require more complex calculations [S11, S15, unofficial].
*   **When to use:** Ideal for ray-marched rendering of complex geometric scenes composed of primitives [S7, unofficial].
*   **When not to use:** When exact distance bounds are critical for all operations (e.g., in physics simulations requiring precise collision normals) without additional correction steps [S8][S12, unofficial].

## Background
CSG Operations on Implicit Functions originated from the application of Constructive Solid Geometry (CSG) to implicit surfaces. Ricci [1974] established that minimum and maximum operations on functions result in union and intersection operations on their implicit surfaces [S8]. This technique became widely popularized in computer graphics through ray marching and signed distance field rendering, notably by artists and researchers like Iñigo Quilez and Jamie Wong, who demonstrated its efficiency for real-time rendering [S2, S3, S12, unofficial]. It is a fundamental technique in procedural modeling, ray marching shaders, and modern neural implicit surface representations [S7, S15, unofficial][S16].
