# SDF Tiling via Modulo

Also called: Tiled SDF, Tiling SDF, Modulo Tiling, Tiling via Modulo

## Overview
SDF Tiling via Modulo creates a periodic tiling of a base signed distance field by folding 3D coordinates into a fundamental domain centered at the origin [S1, S2, S3, S5, unofficial]. It segments space into infinite parallel regions of repeated distance by taking the modulus of a point’s position along one or more axes before computing the signed distance [S2, S3, S5, unofficial]. This allows for the infinite repetition of geometry for no extra computational cost in terms of scene complexity [S2, S3, S5, unofficial]. It differs from [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md) by specifically using arithmetic wrapping to create periodicity rather than general transformations, and from [Basic Primitive Definitions](5346-basic-primitive-definitions.md) by enabling complex, repeated structures from simple primitives.

## How it works
**Inputs:**
- `pt`: The 3D point in world space $(x, y, z)$ [S2, S3, S5, unofficial].
- `period`: The spacing between repetitions along each axis (f32) [S1, S3, S5, unofficial].
- `base_sdf`: A function that computes the signed distance for the fundamental tile [S1, S5, unofficial].

**Outputs:**
- The signed distance value at `pt` within the tiled scene [S2, S3, S5, unofficial].

**Data Structures:**
- No persistent data structures are required. The operation is stateless and computed per-point [S1, S2, S3, S5, unofficial].

**Parameters:**
- `period`: The size of the repeating unit. In the standard implementation, the period is 4.0, and the offset is 2.0 to center the tile [S3, S5, unofficial].
- `offset`: Half the period, used to center the fundamental domain at the origin. Typically `offset = period / 2.0` [S1, S4, S5, unofficial].

**Steps:**
1. For each coordinate $c$ in $\{x, y, z\}$, apply the modulo tiling transformation to fold the coordinate into the fundamental domain centered at 0 [S1, S4, S5, unofficial]:
   $$ c' = \text{mod}(c + \text{offset}, \text{period}) - \text{offset} $$
   Where $\text{mod}(a, b)$ is the floating-point modulo operation returning a value in $[0, b)$ [S2, S3, S5, unofficial].
2. Construct the transformed point $\mathbf{p}' = (x', y', z')$ [S1, S5, unofficial].
3. Pass $\mathbf{p}'$ to the `base_sdf` function to compute the distance [S1, S5, unofficial].

**Pseudocode:**
```python
def mod_tiling_sdf(pt: Vec3, period: float, base_sdf: Callable[[Vec3], float]) -> float:
    """
    Computes the signed distance of a point in a periodically tiled scene.
    
    Args:
        pt: The 3D point to evaluate.
        period: The spacing between repetitions.
        base_sdf: The SDF function for the single tile.
        
    Returns:
        The signed distance value.
    """
    offset = period / 2.0
    
    # Apply modulo tiling to x and z axes (y is often left un-tiled for floor/ceiling effects,
    # but can be tiled similarly if desired)
    x_tiled = mod(pt.x + offset, period) - offset
    y_tiled = pt.y  # Not tiled in standard example [S2, S3, S5, unofficial]
    z_tiled = mod(pt.z + offset, period) - offset
    
    transformed_pt = Vec3(x_tiled, y_tiled, z_tiled)
    
    return base_sdf(transformed_pt)

def mod(a: float, b: float) -> float:
    """
    Standard floating-point modulo.
    Returns a value in [0, b).
    """
    return a - b * floor(a / b)
```

**Edge Cases and Pitfalls:**
- **Symmetry:** Simple modulo tiling works seamlessly for symmetrical shapes (e.g., circles, squares) [S4, unofficial]. For irregular shapes that are not symmetrical along the tiling axis (e.g., stars not symmetrical vertically), the simple mod approach may produce artifacts at the boundaries [S4, unofficial].
- **Irregular Shapes Solution:** For irregular shapes, one must sample the distance field at multiple shifted positions (e.g., one unit above and below) and take the minimum to ensure seamless tiling [S4, unofficial].
- **Precision:** Floating-point precision issues may arise with very large coordinates or very small periods, potentially causing discontinuities in the gradient [G].

### Infinite Multiphase Layers
An infinite multiphase primitive defined as a set of parallel slices orthogonal to a prescribed direction $\mathbf{u}$ [S6]. It uses a similar fractional part calculation but defines a two-phase space-filling structure [S6]. Let $\mathbf{u} = \mathbf{p}\mathbf{u}$ (as per source notation [S6]), compute the fractional part $\mathbf{z} = \mathbf{u} - [\mathbf{u}]$ [S6]. The signed distance field is defined as $\phi_i = s \min(\mathbf{q}, 1 - \mathbf{q})$, where the sign $s$ is determined by $s = +1$ if $[\mathbf{u}]$ is even, and $-1$ otherwise [S6]. ## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ per point evaluation, independent of the number of repetitions [S2, S3, S5, unofficial].
- Memory: $O(1)$, as no geometry data is stored [S2, S3, S5, unofficial].

**Measured Performance:**
- Infinite repetition of geometry incurs no extra cost in terms of scene complexity or memory usage [S2, S3, S5, unofficial].

**Strengths and Limitations:**
- **Strengths:** Extremely efficient for creating complex, repetitive environments (e.g., floors, walls, grids) without increasing draw calls or memory footprint [S2, S3, S5, unofficial].
- **Limitations:** Limited to periodic, regular structures. Cannot easily represent non-periodic or irregular tiling without additional logic [S4, unofficial]. May produce visual artifacts at tile boundaries for non-symmetric primitives [S4, unofficial].

**When to Use:**
- Use for creating infinite floors, walls, grids, or any scene requiring regular, periodic repetition of a base shape [S2, S3, S5, unofficial].

**When Not to Use:**
- Do not use for irregular, non-periodic, or asymmetric tiling without the additional sampling techniques described in [S4, unofficial] [S4, unofficial].

## Background
The technique is widely popularized in the context of ray marching and signed distance fields, particularly through the work of Inigo Quilez and educational resources from the University of Cambridge [S2, S3, S5, unofficial]. It is a fundamental building block in procedural geometry generation, allowing for the creation of complex scenes from simple primitives [S2, S3, S5, unofficial]. The concept of using modulo for repetition is also related to fractal generation techniques described by John C. Hart [S2, S3, S5, unofficial].
