# SDF Value and Gradient Query

Also called: Live Cursor Measurement Caliper, ObjectFrameSDF query, Step Ruler Caliper, measureSdfRayCaliper

## Overview
SDF Value and Gradient Query is a method for inspecting Signed Distance Field (SDF) properties at specific 3D coordinates in real-time, primarily used for debugging, calibration, and interactive measurement. It outputs the signed distance value $d(\mathbf{p})$, the analytical gradient $\nabla d(\mathbf{p})$, and classification of the query point's spatial context (e.g., surface, free space, or sky) [S1, S2, unofficial]. Unlike [Batched SDF Inference](2329-batched-sdf-inference.md), which optimizes memory throughput for large datasets, this method focuses on low-latency, per-point inspection and verification of SDF correctness, such as normal unit-length validation [S1, unofficial].

## How it works
**Inputs:**
1.  A set of 3D query points $\mathbf{p}$ (typically in world or object frame coordinates) [S1, S2, unofficial].
2.  An SDF primitive or implicit surface definition capable of evaluating distance and gradient [S1, S2, unofficial].
3.  Optional flag `compute_grad`: Boolean indicating whether to calculate the gradient [S2, unofficial].

**Outputs:**
1.  Signed distance value $d(\mathbf{p})$ [S1, S2, unofficial].
2.  Gradient vector $\nabla d(\mathbf{p})$ (if requested) [S1, S2, unofficial].
3.  Hit target classification (e.g., COURSE SURFACE, GLASS MARBLE, ABYSS, SKY RAY) [S1, unofficial].
4.  Performance metrics (e.g., step counts, CSG latency) [S1, unofficial].

**Data Structures:**
*   **Query Points:** Array of shape $(N, 3)$ or $(B, N, 3)$ for batched queries [S2, unofficial].
*   **SDF Values:** Array of shape $(N)$ or $(B, N)$ [S2, unofficial].
*   **SDF Gradients:** Array of shape $(N, 3)$ or $(B, N, 3)$ [S2, unofficial].

**Steps:**
1.  **Coordinate Transformation:** If the SDF is defined in an object frame, transform query points $\mathbf{p}_{world}$ to $\mathbf{p}_{obj}$ using the inverse model matrix [S2, unofficial].
2.  **SDF Evaluation:**
    *   Call the SDF evaluation function `sdf(pts)` with the query points [S2, unofficial].
    *   If `compute_grad` is `True`, compute the gradient analytically or via finite differences (analytical is preferred for unit-length verification) [S1, S2, unofficial].
    *   If `compute_grad` is `False`, skip gradient computation to improve speed [S2, unofficial].
3.  **Gradient Verification:** Verify that the magnitude of the analytical normal is unity: $\|\nabla d(\mathbf{p})\| = 1.000$ [S1, unofficial].
4.  **Classification:** Classify the query point based on the distance value and context:
    *   **Surface:** $d(\mathbf{p}) \approx 0$ [S1, unofficial].
    *   **Free Space:** $d(\mathbf{p}) > 0$ (often with a probe offset, e.g., +1m) [S1, unofficial].
    *   **Inside/Obstacle:** $d(\mathbf{p}) < 0$ [S1, unofficial].
    *   **Sky/Abyss:** Points outside the bounding volume or raycast limits [S1, unofficial].
5.  **Performance Measurement:** Compare optimized raymarching steps (e.g., using `sdCourseBounds` and $\kappa$-March) against legacy steps to calculate percentage reduction [S1, unofficial]. Measure CSG (Constructive Solid Geometry) latency if boolean operations are involved [S1, unofficial].

**Pseudocode:**
```python
def query_sdf_value_and_gradient(sdf_model, points, compute_grad=True):
    """
    Queries SDF value and gradient for given points.
    
    Args:
        sdf_model: Object implementing __call__(pts, compute_grad)
        points: numpy array of shape (N, 3) or (B, N, 3)
        compute_grad: bool, whether to compute gradient
        
    Returns:
        sdf_val: array of distances
        sdf_grad: array of gradients (shape (N, 3) or (B, N, 3)) if compute_grad else None
        classification: list of strings describing hit target
    """
    # Step 1: Evaluate SDF
    # The sdf_model handles batching internally or expects batched input
    sdf_val, sdf_grad = sdf_model(points, compute_grad=compute_grad)
    
    # Step 2: Verify Gradient Unit Length (if computed)
    if compute_grad and sdf_grad is not None:
        grad_magnitude = np.linalg.norm(sdf_grad, axis=-1)
        # Assertion or warning if deviation from 1.0 is significant
        # ||∇d|| should be 1.000 [S1, unofficial]
        assert np.allclose(grad_magnitude, 1.0, atol=1e-3), "Gradient magnitude deviates from 1.0"
        
    # Step 3: Classification
    classification = []
    for i, d in enumerate(sdf_val):
        if d < -1e-3:
            classification.append("INSIDE")
        elif d < 1e-3:
            classification.append("SURFACE")
        elif d < 1.0: # Example threshold
            classification.append("FREE_SPACE")
        else:
            classification.append("SKY_RAY")
            
    return sdf_val, sdf_grad, classification
```

**Parameters:**
*   `compute_grad`: Boolean. If `False`, gradient computation is skipped for speed [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Ensure floating-point precision is sufficient for verifying $\|\nabla d\| = 1.0$ [S1, unofficial].
*   **Bounding Box:** Bounding box comparisons for out-of-bounds points may under-approximate SDF values but are empirically sufficient for many applications [S2, unofficial].
*   **CSG Latency:** Real-time CSG operations can introduce latency (e.g., 0.0018 ms) which should be monitored [S1, unofficial].

## Subtopics

### Cached SDF
Accelerates SDF queries by storing values in a voxel grid, falling back to a ground truth SDF for points outside the cache [S2, unofficial]. A variant, TSDF (Truncated SDF), uses a `truncation_distance` to create a smaller voxel grid covering only the near-surface region; out-of-bounds points return the truncation value [S2, unofficial].
*   **Parameters:** `resolution` (voxel cell size, e.g., 0.01), `range_per_dim` (grid dimensions, e.g., from bounding box with padding), `out_of_bounds_strategy` (default compares against bounding box; `pv.OutOfBoundsStrategy.LOOKUP_GT_SDF` uses ground truth), `truncation_distance` [S2, unofficial].
*   **Pitfalls:** Bounding box comparison under-approximates SDF values [S2, unofficial].
*   **Comparison:** Dramatically faster than ground truth SDF for out-of-bounds queries [S2, unofficial].

### SDF Snapping
Queries the VoxelGenerator at floating-point positions to approximate the surface, snapping instances closer to the surface [S3].
*   **Formula:** $P_{snapped} = P_{mesh} + \text{interpolation}(SDF(P_{mesh}), \text{samples})$. Uses at least 2 nearby SDF samples to interpolate [S3].
*   **Pitfalls:** Does not work if terrain is modified after initial generation (workaround: set instances as persistent) [S3]. Can cause instances to 'bury' or 'float' far away with low-resolution meshes [S3].
*   **Comparison:** Snapping improves positioning but is slower; preferably used when `lod_index > 0` [S3].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per point for analytical SDFs; $O(N)$ for batched queries [S2, unofficial]. Cached SDF reduces complexity for out-of-bounds queries [S2, unofficial].
*   **Memory Complexity:** $O(N)$ for storing query results [S2, unofficial]. Cached SDF requires $O(V)$ memory for the voxel grid, where $V$ is the number of voxels [S2, unofficial].
*   **Performance:** Real-time inspection (e.g., 60 FPS) is achievable with optimized raymarching (e.g., $\kappa$-March) [S1, unofficial]. CSG latency can be minimal (e.g., 0.0018 ms) [S1, unofficial].
*   **Strengths:** High precision for debugging; real-time feedback; unit-length gradient verification [S1, unofficial].
*   **Limitations:** Slower than non-snapping methods for large-scale instancing [S3]; caching requires additional memory [S2, unofficial].

## Background
The method originates from interactive SDF debugging tools, such as the "Live Cursor Measurement Caliper" and "Step Ruler" implemented in the Gemini 4 Argon SF Hackathon project [S1, unofficial]. It is also used in volumetric structure evaluation libraries like `pytorch_volumetric` for computing chamfer distances and closest points in object frames [S2, unofficial]. SDF snapping is documented in Voxel Tools for game engine instancing [S3].
