# Distance to Natural Quadrics

Also called: Natural Quadrics SDF, SDF for Natural Quadrics

## Overview
Distance to Natural Quadrics provides closed-form Signed Distance Functions (SDFs) for standard solid modeling primitives, including spheres, cylinders, cones, planes, and tori [S2]. These functions compute the exact Euclidean distance from a query point to the surface of the primitive, enabling efficient distance-field ray marching (sphere tracing) [S3, unofficial]. Unlike generic or approximate methods, these analytical solutions are computationally cheap and serve as the foundational building blocks for Constructive Solid Geometry (CSG) operations [S2]. They are distinct from [Superquadrics](1561-distance-to-superquadics.md) because they rely on the standard Euclidean $L_2$ norm rather than generalized $L_p$ norms, and from [Cylinder SDF](2739-cylinder-signed-distance-function.md) in that the natural quadric definitions often assume infinite extent or specific canonical orientations unless explicitly capped [S1, unofficial][S2].

## How it works
The method evaluates the scalar field $f(\mathbf{p})$ for a given query point $\mathbf{p}$ in 3D space. The output is a signed distance: positive outside the object, negative inside, and zero on the surface [S3, unofficial]. To use these primitives in a scene, the query point is transformed into the primitive's local coordinate space using the inverse of the primitive's world transformation matrix $M^{-1}$ [S3850].

### Data Structures
*   **Query Point**: $\mathbf{p} = (x, y, z)$, a 3D vector.
*   **Primitive Parameters**:
    *   Sphere: Center $\mathbf{c}$, radius $r$.
    *   Cylinder: Radius $r$, half-height $h$ (for capped), axis direction $\mathbf{a}$.
    *   Cone: Base radius $r$, height $h$, axis direction $\mathbf{a}$.
    *   Torus: Major radius $R$ (t[0]), minor radius $r$ (t[1]).
    *   Plane: Point $\mathbf{p}_0$ on plane, unit normal $\mathbf{n}$.

### Formulas and Steps

#### 1. Sphere
The distance is the distance to the center minus the radius [S2].
$$ d(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r $$
For a unit sphere at the origin: $d(\mathbf{p}) = \|\mathbf{p}\| - 1$ [S2].

#### 2. Plane
The distance is the dot product of the normal and the vector from a point on the plane to the query point [S2].
$$ d(\mathbf{p}) = \mathbf{n} \cdot (\mathbf{p} - \mathbf{p}_0) $$

#### 3. Cylinder (Infinite)
For a cylinder aligned with the Z-axis, the distance is the 2D distance to the unit circle in the XY plane minus the radius [S2].
$$ d(\mathbf{p}) = \text{dist}_{2D}((x, y), \text{circle}) - r $$
Specifically, if aligned with Z: $d(\mathbf{p}) = \sqrt{x^2 + y^2} - r$ [S3, unofficial].

#### 4. Cylinder (Capped)
A capped cylinder with radius $r$ and half-height $h$, aligned with the Y-axis, is computed by clamping the Y coordinate [S1, unofficial].
Let $d = (\sqrt{p_x^2 + p_z^2} - r, |p_y| - h)$.
$$ d_{\text{capped}} = \min(\max(d_x, d_y), 0) + \max(\|d\|, 0) $$
If the clamped Y differs from the original Y (point is outside height bounds), the distance to the nearest cap is added [S1, unofficial].

#### 5. Cone
For a cone centered at the origin oriented along the Z-axis with divergence angle $\theta$:
$$ d(\mathbf{p}) = \text{dist}_{2D}(p_{xz}, \text{cone profile}) $$
The derivation involves the angle of divergence $\theta$ from the Z-axis [S2]. A robust GLSL implementation uses the following logic [S1, unofficial]:
Let $c = (\cos \theta, \sin \theta)$ and $q = h \cdot (c_x/c_y, -1)$.
Let $w = (\sqrt{p_x^2 + p_z^2}, p_y)$.
Compute vectors $a$ and $b$ based on projections onto $q$.
$$ d(\mathbf{p}) = \text{sign}(s) \sqrt{\min(\|a\|^2, \|b\|^2)} $$
Where $s$ determines the sign based on the position relative to the cone surface [S1, unofficial].

#### 6. Torus
The torus is defined by a major radius $R$ (t[0]) and minor radius $r$ (t[1]) [S4, unofficial]. It is evaluated as the distance to a circle of radius $R$ in the XY plane, minus the minor radius $r$ [S2].
Let $q = (\sqrt{p_x^2 + p_z^2} - R, p_y)$.
$$ d(\mathbf{p}) = \|q\| - r $$
Typical values: $R=0.8, r=0.3$ [S4, unofficial].

### Pseudocode
```python
import math

def sdf_sphere(p, center, radius):
    """Distance to a sphere."""
    return math.sqrt(sum((p[i] - center[i])**2 for i in range(3))) - radius

def sdf_plane(p, point_on_plane, normal):
    """Distance to a plane."""
    # normal must be unit length
    return sum((p[i] - point_on_plane[i]) * normal[i] for i in range(3))

def sdf_cylinder_infinite(p, radius, axis_index=2):
    """Distance to an infinite cylinder aligned with axis_index (0=x, 1=y, 2=z)."""
    # Sum squares of the two axes perpendicular to the cylinder axis
    sq_dist = 0.0
    for i in range(3):
        if i != axis_index:
            sq_dist += p[i]**2
    return math.sqrt(sq_dist) - radius

def sdf_cylinder_capped(p, radius, half_height, axis_index=1):
    """Distance to a capped cylinder aligned with axis_index."""
    # Calculate radial distance in the plane perpendicular to the axis
    sq_radial = 0.0
    for i in range(3):
        if i != axis_index:
            sq_radial += p[i]**2
    radial = math.sqrt(sq_radial)
    
    # d represents distance to side wall and distance to caps
    # d_x is distance to side wall (radial - radius)
    # d_y is distance to caps (|p_axis| - half_height)
    d_x = radial - radius
    d_y = abs(p[axis_index]) - half_height
    
    # Core formula from [S1, unofficial]
    # min(max(d_x, d_y), 0) handles the "inside" case or the corner case
    # max(norm(d), 0) handles the "outside" case
    core = min(max(d_x, d_y), 0.0)
    outside = math.sqrt(max(d_x, 0.0)**2 + max(d_y, 0.0)**2)
    
    return core + outside

def sdf_torus(p, major_radius, minor_radius):
    """Distance to a torus aligned with Y-axis (major radius in XZ plane)."""
    # q = (sqrt(px^2 + pz^2) - R, py)
    q_x = math.sqrt(p[0]**2 + p[2]**2) - major_radius
    q_y = p[1]
    return math.sqrt(q_x**2 + q_y**2) - minor_radius

def sdf_cone(p, radius, height, axis_index=2):
    """
    Distance to a cone. 
    Assumes cone apex at origin, base at height along axis_index.
    c is sin/cos of divergence angle.
    """
    # Calculate divergence angle parameters
    # q is the point at the base in 2D profile
    # c_x = radius / sqrt(radius^2 + height^2) ? 
    # Using the GLSL logic from [S1, unofficial]:
    # c is sin/cos of angle. Let's derive c from radius and height.
    # The vector from apex to base edge is (radius, height) in local 2D.
    # Length of this vector is sqrt(r^2 + h^2).
    # cos(theta) = h / L, sin(theta) = r / L
    # In GLSL code: q = h * vec2(c.x/c.y, -1.0)
    # c.x/c.y = tan(theta) = r/h. So q = h * (r/h, -1) = (r, -h).
    
    r = radius
    h = height
    
    # Local 2D coordinates relative to cone axis
    # w is (radial_dist, p_axis)
    sq_radial = 0.0
    for i in range(3):
        if i != axis_index:
            sq_radial += p[i]**2
    radial = math.sqrt(sq_radial)
    
    w_x = radial
    w_y = p[axis_index]
    
    # q is the point at the base in 2D (from apex)
    # Based on [S1, unofficial] GLSL: q = h * vec2(c.x/c.y, -1.0) -> q = (r, -h)
    q_x = r
    q_y = -h
    
    # Vector from q to w
    # a = w - q * clamp(dot(w,q)/dot(q,q), 0, 1)
    dot_wq = w_x * q_x + w_y * q_y
    dot_qq = q_x**2 + q_y**2
    
    clamp_val = max(0.0, min(1.0, dot_wq / dot_qq))
    
    a_x = w_x - q_x * clamp_val
    a_y = w_y - q_y * clamp_val
    
    # b = w - q * vec2(clamp(w.x/q.x, 0, 1), 1)
    # Note: q.x is r. If r is 0, this is degenerate. Assuming r > 0.
    clamp_b_x = max(0.0, min(1.0, w_x / q_x))
    
    b_x = w_x - q_x * clamp_b_x
    b_y = w_y - q_y * 1.0
    
    # d = min(dot(a,a), dot(b,b))
    d_sq = min(a_x**2 + a_y**2, b_x**2 + b_y**2)
    
    # s = max(k*(w.x*q.y - w.y*q.x), k*(w.y - q.y))
    # k = sign(q.y). q.y is -h. So k = -1 (assuming h > 0).
    k = -1.0 if h > 0 else 1.0
    
    term1 = k * (w_x * q_y - w_y * q_x)
    term2 = k * (w_y - q_y)
    s = max(term1, term2)
    
    return math.sqrt(d_sq) * math.copysign(1.0, s)
```

### Edge Cases and Pitfalls
*   **Precision**: When the query point is very close to the surface, floating-point errors can cause jitter. A small epsilon threshold is used in ray marching to stop [S3, unofficial].
*   **Degenerate Cones**: If the cone radius is 0, the division by $q_x$ in the cone calculation becomes undefined [S1, unofficial].
*   **Lipschitz Condition**: All natural quadric SDFs must satisfy the Lipschitz condition with constant 1 to be valid for sphere tracing [S2, S5, 9643]. The closed-form solutions provided here guarantee this property.
*   **Transformations**: When transforming primitives, the inverse matrix must be applied to the point $\mathbf{p}$ before evaluation [S3850]. Rotations affect the axis alignment, requiring careful handling of the axis index in the formulas.

## Subtopics

### [Distance to Superquadrics](1561-distance-to-superquadrics.md)
Generalizes natural quadrics using $L_p$ norms to create shapes with rounded, square, or pinched cross-sections. Choose this when non-Euclidean metrics are needed for blending or specific aesthetic shapes.

### [Cylinder Signed Distance Function](2739-cylinder-signed-distance-function.md)
Computes the exact distance to a finite cylinder with end caps. Choose this for CSG operations involving capped cylinders, distinct from the infinite natural quadric cylinder.

### [Torus Signed Distance Function](2864-torus-signed-distance-function.md)
Specific implementation for tori, often treated as a natural quadric but distinguished by its closed-loop topology and specific algebraic form.

## Operating characteristics
*   **Time Complexity**: $O(1)$ per primitive evaluation. The operations involve basic arithmetic, square roots, and comparisons.
*   **Memory Complexity**: $O(1)$. No auxiliary data structures are required.
*   **Performance**: These closed-form solutions are significantly faster than iterative or mesh-based distance approximations [S2]. They are suitable for real-time ray marching on GPUs [S3, unofficial].
*   **Strengths**: Exact distances, no discretization error, efficient composition via CSG [S2].
*   **Limitations**: Limited to specific geometric shapes. Complex shapes require decomposition into these primitives or use of [Superquadrics](1561-distance-to-superquadics.md) [S2].

## Background
Signed Distance Functions for natural quadrics were formalized in the context of sphere tracing for antialiased ray tracing of implicit surfaces [S2]. The method leverages the geometric properties of standard solid modeling primitives to provide efficient distance queries. The torus SDF, for instance, is derived from the product of two circles [S2]. These functions are widely used in procedural geometry, ray marching tutorials, and real-time rendering engines [S3, S4, unofficial].
