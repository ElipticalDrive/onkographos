# Dodecahedron Modulo

Also called: Dodecahedron SDF, Dodecahedron Distance Field

## Overview
Computes the Euclidean signed distance from a query point $p$ to the surface of a regular dodecahedron centered at the origin with unit circumradius. It solves the problem of efficiently evaluating the distance field for a complex polyhedral primitive without explicit mesh intersection tests. It sets itself apart from sibling primitives like the [Octahedron Signed Distance Function](2339-octahedron-signed-distance-function.md) by using a sequence of rotations and reflections to fold 3D space into a fundamental domain (a wedge) where the closest feature is always a single face, rather than relying on simple coordinate absolute values or 2D extrusion compositions.

## How it works
**Inputs:** A 3D point $p = (x, y, z)$.
**Outputs:** A scalar signed distance $d$.

**Data Structures:**
The method operates in-place on the point coordinates using standard 3D vector operations. No auxiliary data structures are required.

**Constants:**
*   $\phi = \frac{1 + \sqrt{5}}{2}$ (Golden Ratio).
*   $\pi \approx 3.14159265$.

**Helper Functions:**
*   `normalize(v)`: Returns $\frac{v}{\|v\|}$.
*   `dot(a, b)`: Dot product of vectors $a$ and $b$.
*   `acos(x)`: Arc cosine of $x$.
*   `pR(axis, angle)`: Rotates point $p$ around the specified axis (`xy`, `yz`, or `zy`) by `angle` radians. Note: `pR(p.xy, angle)` rotates the $x$ and $y$ components in the $xy$-plane. `pR(p.zy, angle)` rotates the $z$ and $y$ components in the $zy$-plane (equivalent to rotating around the $x$-axis).
*   `pModPolar(v, sides)`: Converts the 2D vector $v$ (interpreted as $y, x$ based on usage in source) to polar coordinates, takes the angle modulo $2\pi/\text{sides}$, and converts back to Cartesian. Specifically, it folds the angle into the range $[-\pi/\text{sides}, \pi/\text{sides}]$ or similar fundamental angular sector.
*   `pReflect(p, n, d)`: Reflects point $p$ across the plane defined by normal $n$ and distance $d$ from origin. Formula: $p' = p - 2(n \cdot p - d)n$.

**Algorithm Steps:**

1.  **Define Basis Vectors:**
    Compute two normalized vectors that define the geometry of the dodecahedron's symmetry:
    $$ v_1 = \text{normalize}(0, \phi, 1) $$
    $$ v_2 = \text{normalize}(\phi, 1, 0) $$

2.  **Compute Angles:**
    Calculate the dihedral angle between the faces defined by $v_1$ and $v_2$, and the face rotation angle:
    $$ \text{dihedral} = \arccos(v_1 \cdot v_2) $$
    $$ \text{halfDdihedral} = \frac{\text{dihedral}}{2} $$
    $$ \text{faceAngle} = \frac{2\pi}{5} $$

3.  **Fold Space:**
    Apply a sequence of reflections (via absolute values) and rotations to map the query point $p$ into the fundamental domain of the dodecahedron. The sequence is strictly ordered:

    1.  Reflect across $xy$-plane: $p.z = |p.z|$
    2.  Rotate around $x$-axis (affecting $z,y$): `pR(p.zy, -halfDdihedral)`
    3.  Rotate around $z$-axis (affecting $x,y$): `pR(p.xy, faceAngle / 4)`
    4.  Reflect across $yz$-plane: $p.x = -|p.x|$
    5.  Rotate around $x$-axis: `pR(p.zy, halfDdihedral)`
    6.  Reflect across $xz$-plane: $p.y = -|p.y|$
    7.  Rotate around $x$-axis: `pR(p.zy, -halfDdihedral)`
    8.  Rotate around $z$-axis: `pR(p.xy, faceAngle)`
    9.  Rotate around $x$-axis: `pR(p.zy, halfDdihedral)`
    10. Reflect across $xz$-plane: $p.y = -|p.y|$
    11. Rotate around $x$-axis: `pR(p.zy, -halfDdihedral)`
    12. Rotate around $z$-axis: `pR(p.xy, faceAngle)`
    13. Rotate around $x$-axis: `pR(p.zy, halfDdihedral)`
    14. Reflect across $xz$-plane: $p.y = -|p.y|$
    15. Rotate around $x$-axis: `pR(p.zy, -halfDdihedral)`
    16. Rotate around $z$-axis: `pR(p.xy, faceAngle)`
    17. Rotate around $x$-axis: `pR(p.zy, halfDdihedral)`

    19. Rotate around $x$-axis: `pR(p.zy, -halfDdihedral)`

    x, y, z = p

    half_dihedral = dihedral / 2
    face_angle = 2 * math.pi / 5

    def rot_z(px, py, pz, angle):
        c = math.cos(angle)
        s = math.sin(angle)
        return (px * c - py * s, px * s + py * c, pz)
        
    # Helper: Rotate around X axis (affects y, z)

        c = math.cos(angle)
        s = math.sin(angle)
        return (px, py * c - pz * s, py * s + pz * c)

        return (-abs(px), py, pz)

## Subtopics

### Icosahedron Modulo
Computes the signed distance to a regular icosahedron. It uses a similar folding strategy but with different basis vectors and angles.
*   **Definition:** Transforms point $p$ into an icosahedron cell using reflections and rotations [S1, unofficial].
*   **Steps:**
    1.  Define $v_1 = \text{normalize}(1, 1, 1)$, $v_2 = \text{normalize}(0, 1, \phi+1)$.
    2.  Compute $\text{sides}=3$, $\text{dihedral}=\arccos(v_1 \cdot v_2)$, $\text{halfDdihedral}=\text{dihedral}/2$, $\text{faceAngle}=2\pi/3$.
    3.  Apply: $p.z=|p.z|$; `pR(p.yz, halfDdihedral)`; $p.x=-|p.x|$; `pR(p.zy, halfDdihedral)`; $p.y=-|p.y|$; `pR(p.zy, -halfDdihedral)`; `pR(p.xy, faceAngle)`; `pR(p.zy, halfDdihedral)`; $p.y=-|p.y|$; `pR(p.zy, -halfDdihedral)`; `pR(p.xy, faceAngle)`; `pR(p.zy, halfDdihedral)`; $p.y=-|p.y|$; `pR(p.zy, -halfDdihedral)`.
*   **Formula:** Fold space via successive absolute values and rotations by half-dihedral and face angles [S1, unofficial].
*   **When to choose:** Use when an icosahedron shape is required. It is the dual of the dodecahedron.

## Operating characteristics
*   **Time Complexity:** $O(1)$. The method involves a fixed number of trigonometric operations, rotations, and absolute values.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures.
*   **Performance:** Very fast, suitable for real-time ray marching. The cost is dominated by the trigonometric functions (`cos`, `sin`, `acos`, `atan2`).
*   **Strengths:** Analytical, no mesh dependencies, smooth gradients (except at symmetry boundaries where derivatives may be discontinuous).
*   **Limitations:** The source does not provide the final distance formula, requiring implementation effort to derive. The folding sequence is complex and prone to precision issues if not implemented carefully.

## Background
The method originates from procedural geometry techniques used in ray marching for signed distance fields. The specific folding sequence is documented in the `glsl-marching-cubes` repository [S1, unofficial]. It exploits the symmetry group of the dodecahedron to reduce the distance calculation to a simple query in a fundamental domain.
