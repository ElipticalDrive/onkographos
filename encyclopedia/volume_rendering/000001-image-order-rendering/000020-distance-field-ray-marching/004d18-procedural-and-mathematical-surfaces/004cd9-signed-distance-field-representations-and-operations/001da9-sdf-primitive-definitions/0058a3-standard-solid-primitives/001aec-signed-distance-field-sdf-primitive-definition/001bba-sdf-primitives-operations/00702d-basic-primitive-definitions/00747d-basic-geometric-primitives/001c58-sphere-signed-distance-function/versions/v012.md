# Sphere Signed Distance Function

Also called: SDF Primitive: Sphere, SDF Sphere, SDF Sphere Primitive, Signed Distance Field (SDF) Sphere, Signed Distance Function (SDF) Sphere, Sphere SDF, Sphere SDF Primitive

## Overview
The Sphere Signed Distance Function computes the exact Euclidean distance from a query point $p$ to the surface of a sphere defined by a center $c$ and radius $r$ [S3, S4, S5, S6, S18, unofficial]. It returns a negative value if the point is inside the sphere, a positive value if outside, and zero if on the surface [S2, S7, S11, S16, S18, unofficial]. This function serves as the fundamental building block for procedural geometry in ray marching, providing a differentiable field where the gradient $\nabla d$ yields the surface normal [S1, S18, unofficial]. It is distinguished from the [Signed Box Distance Function](1092-signed-box-distance-function.md) by its rotational symmetry and from the [Plane Signed Distance Function](1102-plane-signed-distance-function.md) by its non-linear curvature [Parent].

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $p \in \mathbb{R}^3$, sphere center $c \in \mathbb{R}^3$, sphere radius $r \in \mathbb{R}_{\ge 0}$. Optionally, a transformation matrix $M$ if the sphere is not axis-aligned or centered at the origin [S8, unofficial][S20].
*   **Output:** Scalar signed distance $d \in \mathbb{R}$.

**Data Structures:**
The sphere is typically defined by two parameters:
1.  **Center ($c$):** A 3D vector $(c_x, c_y, c_z)$. In some implementations, this is learnable or stored in a specific block (e.g., `floats[0]` for radius, with center implied or stored separately) [S4, S6, S12, unofficial].
2.  **Radius ($r$):** A scalar float. In some implementations, this is learnable [S4, S5, S6, unofficial].
3.  **Transform (Optional):** A $4 \times 4$ matrix for non-uniform scaling, rotation, or translation [S8, unofficial].

**Formula:**
The signed distance $d(p)$ is calculated as the length of the vector from the center to the point, minus the radius:
$$ d(p) = \| p - c \| - r $$
where $\| \cdot \|$ denotes the Euclidean norm (length) [S1, S2, S3, S4, S5, S6, S7, S9, S11, S12, S13, S14, S16, S18, S19, unofficial].

If a transformation matrix $M$ is applied to the point (e.g., to handle local-to-world transformations or non-uniform scaling in a generalized SDF context), the point is transformed first: $p' = M \cdot [p, 1]^T$, and the distance is computed on $p'$ [S8, unofficial]. Note that for non-uniform scaling, the Euclidean SDF is an approximation unless the inverse transpose of the linear part of the matrix is used for normal computation, but the distance value itself remains $\|p'\| - r$ in the transformed space if the sphere is defined in that space [S8, unofficial][S20].

**Parameters:**
*   $r$: Radius. Typical values depend on scene scale. Default is often 1.0 or 0.5 in examples [S11, S13, unofficial].
*   $c$: Center. Default is $(0, 0, 0)$ [S1, S7, S11, S13, unofficial].
*   $M$: Transformation matrix. Not given in the sources for standard origin-centered sphere, but required for general placement [S8, unofficial].

**Pitfalls and Edge Cases:**
1.  **Precision:** For points very close to the surface, floating-point precision errors in the square root calculation can cause jitter in normals if not handled carefully. However, the SDF itself is robust [S16, unofficial].
2.  **Zero Radius:** If $r=0$, the function returns the distance to the center point. This is valid but may cause issues in ray marching if not handled (step size becomes 0 at the center) [G].
3.  **Negative Radius:** Radii must be non-negative. A negative radius is physically invalid and should be clamped or rejected [G].
4.  **Gradient Normalization:** The gradient $\nabla d = \frac{p-c}{\|p-c\|}$ is already a unit vector (normal) everywhere except at the center $p=c$ where it is undefined [S1, S18, unofficial]. Ray marching steps should use the SDF value directly, not the gradient magnitude, for safety [Parent].

**Pseudocode:**
```python
import math

def sphere_sdf(p: list, c: list, r: float) -> float:
    """
    Computes the signed distance from point p to a sphere with center c and radius r.
    
    Args:
        p: List of 3 floats [x, y, z] representing the query point.
        c: List of 3 floats [cx, cy, cz] representing the sphere center.
        r: Float representing the sphere radius.
        
    Returns:
        Float: Signed distance. Positive outside, negative inside, zero on surface.
    """
    # Calculate vector from center to point
    dx = p[0] - c[0]
    dy = p[1] - c[1]
    dz = p[2] - c[2]
    
    # Calculate Euclidean distance from center
    dist_to_center = math.sqrt(dx*dx + dy*dy + dz*dz)
    
    # Subtract radius to get signed distance
    return dist_to_center - r

def sphere_sdf_with_transform(p: list, c: list, r: float, M: list) -> float:
    """
    Computes SDF after applying a 4x4 transformation matrix M to the point.
    Note: This assumes M transforms world coordinates to the sphere's local space
    where the sphere is centered at origin with radius r.
    
    Args:
        p: World space point.
        c: Not used directly if M includes translation, but kept for signature consistency.
        r: Radius in local space.
        M: 4x4 transformation matrix (list of lists or flat list).
        
    Returns:
        Float: Signed distance in local space.
    """
    # Transform point p using matrix M
    # Assuming M is 4x4, p is treated as [x, y, z, 1]
    # This is a simplified matrix-vector multiplication
    x, y, z = p[0], p[1], p[2]
    
    # Row 0
    tx = M[0][0]*x + M[0][1]*y + M[0][2]*z + M[0][3]
    # Row 1
    ty = M[1][0]*x + M[1][1]*y + M[1][2]*z + M[1][3]
    # Row 2
    tz = M[2][0]*x + M[2][1]*y + M[2][2]*z + M[2][3]
    # Row 3 (w component, usually 1 for points)
    # tw = M[3][0]*x + M[3][1]*y + M[3][2]*z + M[3][3]
    
    # Compute SDF in transformed space (centered at origin)
    dist_to_center = math.sqrt(tx*tx + ty*ty + tz*tz)
    return dist_to_center - r
```

## Subtopics

### [Circle Signed Distance Function](2942-circle-signed-distance-function.md)
The Circle Signed Distance Function computes the signed distance from a 2D query point to the perimeter of a circle centered at the origin. It returns a negative value inside the circle, a positive value outside, and zero on the boundary. It serves as the 2D analog of the Sphere Signed Distance Function [G].

### Distance Estimator
A Distance Estimator is a function that computes the minimum distance from a query point to any object in a scene, returning that distance along with the color of the closest object [S22, unofficial].
*   **Definition:** It aggregates SDFs of multiple primitives to find the closest surface [S22, unofficial].
*   **Step:** Initialize minimum distance to `DRAW-DISTANCE` (typically 1000) and color to `[0, 0, 0]` [S22, unofficial]. For each object, compute its SDF. If the computed distance is less than the current minimum, update the minimum distance and store the object's color [S22, unofficial]. Return the minimum distance and associated color [S22, unofficial].
*   **Parameter:** `DRAW-DISTANCE`: The initial maximum distance for the estimator, set to 1000 [S22, unofficial].
*   **Comparison:** It returns color alongside distance to avoid recomputing the color lookup for the endpoint later [S22, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query. The computation involves a few subtractions, multiplications, and a square root [S1, S7, S16, unofficial].
*   **Memory Complexity:** $O(1)$. Only the center and radius need to be stored [S3, S4, S6, unofficial].
*   **Performance:** Extremely fast, suitable for real-time ray marching on GPUs [S1, S16, unofficial]. The square root operation is the most expensive part but is well-optimized in hardware [S22, unofficial].
*   **Strengths:** Exact distance, differentiable, simple to implement, robust for ray marching steps [S1, S16, S18, unofficial].
*   **Limitations:** Only represents spherical shapes. Cannot represent complex geometry without CSG operations [S18, unofficial].
*   **When to use:** When rendering spheres or using them as primitives in CSG operations [S1, S18, unofficial].
*   **When not to use:** When the scene contains non-spherical objects without CSG, or when performance is critical and the square root is too expensive (though rare) [G].

## Background
The Sphere SDF is a fundamental primitive in Signed Distance Field (SDF) ray marching, popularized by Inigo Quilez and others in the demoscene and computer graphics community [S1, S11, S16, S17, unofficial]. It is derived from the geometric definition of a sphere as the locus of points equidistant from a center [S16, unofficial]. The function has been used in various contexts including real-time rendering, implicit surface reconstruction, and neural radiance fields (NeRFs) as a baseline or regularizer [S4, S5, S6, S15, unofficial]. The concept of using distance functions for ray marching was introduced by John C. Hart in 1994 with "Sphere Tracing" [S20].
