# 1-Lipschitz Proxy Node Construction

Also called: 1-Lipschitz Proxy, Proxy Node

## Overview
This method constructs a simplified signed distance function (SDF) proxy to replace a sub-tree in a CSG hierarchy, ensuring the resulting field is 1-Lipschitz continuous to enable safe hierarchical pruning [S1]. It differs from standard proxy nodes by explicitly interpolating between the original complex field and a simpler proxy field using a weighting function, guaranteeing the Lipschitz property required by the parent [Lipschitz Pruning](8623-lipschitz-pruning.md) algorithm [S1].

## How it works

### Inputs and Outputs
*   **Input:** A node $N$ in the CSG construction tree $T$, its original signed distance function $f$, a region of interest $\Omega$, a simpler proxy field $v$ defined over $\Omega$, and a transition parameter $\delta_r$.
*   **Output:** A new proxy node inserted into $T$ that evaluates the interpolated function $f_e$.

### Data Structures
The proxy node stores:
1.  Reference to the original child node $N$ (or its function $f$).
2.  The proxy field definition $v$ (e.g., a sphere, convex hull).
3.  The transition radius $\delta_r$.
4.  The precomputed Lipschitz constant $\lambda$.
5.  The interpolation function logic (typically based on distance to the boundary of $\Omega$).

### Steps

1.  **Determine Node Type:** Check if node $N$ is a smooth operator (e.g., smooth union, smooth intersection) or if any ancestor in the tree hierarchy above $N$ is a smooth operator.
2.  **Insert Proxy Node:**
    *   If $N$ or an ancestor is smooth, insert a **1-Lipschitz proxy node** between $N$ and its parent. This node computes $f_e$ using the full interpolation formula [S1].
    *   Otherwise, insert a standard proxy node (which may not guarantee 1-Lipschitz continuity globally, relying on other pruning mechanisms) [S1].
3.  **Compute Lipschitz Constant $\lambda$:** Calculate $\lambda$ to ensure $f_e$ is 1-Lipschitz. The formula depends on the maximum deviation between $f$ and $v$ over $\Omega$ [S1]:
    $$ \lambda = 1 + \frac{\lambda_s \sup_{\Omega} |f - v|}{\delta_r} $$
    where $\lambda_s$ is the Lipschitz constant of the interpolating function $s$ used to generate $\alpha(p)$ [S1].
4.  **Evaluate $f_e(p)$:** For any point $p$, evaluate the piecewise function defined below.

### Formulas

The interpolated function $f_e(p)$ is defined as [S1]:

$$
f_e(p) = 
\begin{cases} 
f(p)/\lambda & \text{if } p \in V \\
\frac{1}{\lambda} \left( (1 - \alpha(p)) f(p) + \alpha(p) v(p) \right) & \text{if } p \in \Omega \\
(v(p) - \delta_r) + \delta_r/\lambda & \text{otherwise}
\end{cases}
$$

**Definitions:**
*   $V$: The region where the original function $f$ is trusted and scaled. Specifically, $V$ is typically the interior region where $f(p)$ is small or negative, often defined relative to the proxy boundary. In the context of the source, $V$ is distinct from $\Omega$. The source defines the first case as $f(p)/\lambda$ for $p \in V$.
*   $\Omega$: The transition region where interpolation occurs.
*   $\alpha(p)$: A weighting function $\alpha: \mathbb{R}^3 \to [0, 1]$ that blends $f$ and $v$. It is computed as a function of the Euclidean distance to the region $s(v(p)/\delta_r)$ [S1]. The norm of its gradient $\|\nabla \alpha\|$ is equal to $\lambda_s$ [S1].
*   $\lambda$: The scaling constant ensuring the 1-Lipschitz property.
*   $\delta_r$: The transition area size parameter.

**Bounding $\lambda$:**
Since $\sup_{\Omega} |f - v|$ is often unknown, bounds are used [S1]:

1.  **Worst Case (No knowledge of $f$):**
    If the proxy is a sphere of radius $r$ and no information about $f$ is available, the bound is:
    $$ \sup_{\Omega} |f - v| \le 2r + \delta_r $$
    Leading to:
    $$ \lambda \le 1 + \frac{\lambda_s (2r + \delta_r)}{\delta_r} $$

2.  **Improved Case (Center inside object):**
    If the center $c$ of the proxy is inside the object ($f(c) < 0$), the bound tightens to:
    $$ \sup_{\Omega} |f - v| \le r + \delta_r $$
    Leading to:
    $$ \lambda \le 1 + \frac{\lambda_s (r + \delta_r)}{\delta_r} $$

### Parameters
*   **$\delta_r$**: Controls the size of the transition area $\Omega$.
    *   *Trade-off:* Smaller $\delta_r$ results in a larger Lipschitz bound $\lambda$ (potentially causing numerical instability or requiring smaller ray steps) but provides stronger resilience to side effects from distance field deformation (better visual fidelity) [S1]. Larger $\delta_r$ reduces $\lambda$ but increases deformation [S1].
*   **$\lambda_s$**: The Lipschitz constant of the interpolation function $s$. Typically $\lambda_s = 1$ if $s$ is a simple linear or smooth step function normalized by distance [S1].

### Pseudocode

```python
def evaluate_1_lipschitz_proxy(p, f, v, center_c, radius_r, delta_r, lambda_s):
    """
    Evaluates the 1-Lipschitz proxy function fe(p).
    
    Args:
        p: Point in 3D space (vector).
        f: Function evaluating the original SDF at p.
        v: Function evaluating the proxy SDF at p.
        center_c: Center of the proxy shape (vector).
        radius_r: Radius of the proxy shape (scalar).
        delta_r: Transition parameter (scalar).
        lambda_s: Lipschitz constant of the interpolation function s (scalar).
        
    Returns:
        The interpolated signed distance value.
    """
    
    # 1. Calculate the Lipschitz constant lambda
    # Determine the bound for sup|f - v|
    # Check if center is inside the object
    f_center = f(center_c)
    
    if f_center < 0:
        # Improved bound: center is inside
        sup_diff = radius_r + delta_r
    else:
        # Worst case bound: no knowledge
        sup_diff = 2 * radius_r + delta_r
        
    lambda_val = 1.0 + (lambda_s * sup_diff) / delta_r
    
    # 2. Determine region and compute alpha
    # Distance from p to the proxy surface
    dist_to_proxy = abs(v(p))
    
    # Define regions based on distance to proxy boundary
    # V: Inside the proxy core (where f is scaled directly)
    # Omega: Transition zone
    # Otherwise: Outside, using proxy shifted
    
    # Note: The exact definition of V and Omega boundaries relative to 
    # the proxy geometry depends on the specific implementation of s.
    # Typically, V is the interior of the proxy, Omega is a shell of width delta_r.
    
    # Simplified region logic based on source Figure 9 and text:
    # V is the region where we trust f, scaled by lambda.
    # Omega is the transition region.
    # "Otherwise" is the exterior.
    
    # Let's assume V is the interior of the proxy (v(p) < 0)
    # and Omega is the band [0, delta_r] around the surface.
    # This is a common interpretation, though the source implies V is 
    # defined by the proxy geometry.
    
    v_val = v(p)
    
    if v_val < 0:
        # Inside the proxy: Use scaled original function
        # Note: f(p) might be expensive, but this is the definition
        return f(p) / lambda_val
        
    elif v_val <= delta_r:
        # In the transition region Omega
        # Compute alpha(p)
        # alpha is a function of distance to the region s(v(p)/delta_r)
        # Assuming s is a smooth step, alpha goes from 0 to 1
        # as distance goes from 0 to delta_r.
        
        # Normalize distance to [0, 1]
        t = v_val / delta_r
        
        # Compute alpha using a smooth function s
        # s is typically a smoothstep or similar. 
        # The source says alpha(p) is computed as a function of distance 
        # to s(v(p)/delta_r). This implies alpha = s(t) or similar.
        # Let's assume alpha = s(t) where s is a smooth interpolation function.
        alpha = smooth_step(t)
        
        # Interpolate
        numerator = (1.0 - alpha) * f(p) + alpha * v_val
        return numerator / lambda_val
        
    else:
        # Outside the transition region
        # Use proxy shifted by delta_r, scaled
        return (v_val - delta_r) + (delta_r / lambda_val)

def smooth_step(t):
    """Standard smoothstep function for interpolation."""
    return t * t * (3.0 - 2.0 * t)
```

### Edge Cases and Pitfalls
*   **Large $\lambda$:** If $\delta_r$ is very small, $\lambda$ becomes large. This scales down the gradient significantly, which can lead to numerical instability or require very small ray-marching steps [S1].
*   **Visual Deformation:** If $\delta_r$ is too large, the interpolation region is wide, causing visible deformation of the surface geometry (side effects) [S1].
*   **Unknown $f$:** In the worst-case bound calculation, assuming no knowledge of $f$ leads to a conservative (large) $\lambda$. If $f$ is known to be well-approximated by $v$, a tighter bound can be used, but this requires additional analysis [S1].
*   **Smooth Operators:** The method must correctly identify smooth operators in the tree hierarchy. If a smooth operator is above $N$, a 1-Lipschitz proxy is mandatory to maintain continuity across the CSG tree [S1].

## Subtopics

### Standard Proxy Node
A simpler proxy that does not guarantee 1-Lipschitz continuity. Used when the tree hierarchy does not contain smooth operators above the node. It relies on other pruning mechanisms for correctness. [Link](8623-lipschitz-pruning.md)

### Lipschitz Pruning
The parent algorithm that uses the 1-Lipschitz property of the proxy node to prune inactive nodes in the CSG tree. [Link](8623-lipschitz-pruning.md)

## Operating characteristics

*   **Time Complexity:** The evaluation of $f_e(p)$ requires evaluating $f(p)$ and $v(p)$, plus a constant number of arithmetic operations. The cost is dominated by the evaluation of the original sub-tree $f$ in the transition region and the interior. However, the *benefit* is that the pruning algorithm can skip large portions of the tree, reducing the total number of $f$ evaluations.
*   **Memory Complexity:** The proxy node stores the proxy definition $v$ and parameters. This is typically small compared to the full sub-tree it replaces.
*   **Strengths:** Enables aggressive pruning of complex CSG trees by replacing sub-trees with simple, mathematically safe proxies. Maintains visual fidelity through careful tuning of $\delta_r$.
*   **Limitations:** The choice of $\delta_r$ is a critical trade-off between performance (small $\lambda$) and accuracy (small deformation). The worst-case bound for $\lambda$ can be pessimistic.
*   **When to use:** When rendering complex CSG models with smooth operators, and when the sub-tree can be well-approximated by a simple geometric primitive (e.g., sphere, convex hull).
*   **When not to use:** When the sub-tree has high-frequency details that cannot be captured by a simple proxy, or when the cost of evaluating $f$ in the transition region outweighs the pruning benefits.

## Background

The method was introduced by P. Hubert-Brierre, E. Guérin, A. Peytavie, and E. Galin in their paper "Accelerating Signed Distance Functions" [S1]. It addresses the challenge of efficiently rendering complex CSG models defined by signed distance functions. The key insight is that while CSG operations can break the 1-Lipschitz property, inserting a carefully constructed proxy node can restore it, enabling hierarchical pruning. The method builds on the concept of Lipschitz pruning, which requires the distance function to be 1-Lipschitz continuous to guarantee correct culling.
