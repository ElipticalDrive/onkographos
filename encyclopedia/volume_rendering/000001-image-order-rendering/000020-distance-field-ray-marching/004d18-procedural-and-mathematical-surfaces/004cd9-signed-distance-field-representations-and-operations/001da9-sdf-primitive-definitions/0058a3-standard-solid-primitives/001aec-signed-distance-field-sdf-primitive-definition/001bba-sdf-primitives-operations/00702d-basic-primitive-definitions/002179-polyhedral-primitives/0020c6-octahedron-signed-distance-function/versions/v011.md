# Octahedron Signed Distance Function
Also called: Octahedron SDF, sdOctahedron
## Overview
Computes the Euclidean signed distance from a query point to the surface of a regular octahedron centered at the origin with size parameter $s$ [S1, unofficial]. It exploits the octahedron's symmetry to fold the query space into a fundamental domain, reducing the 3D distance calculation to a simpler 2D or 1D case. It is distinguished from other polyhedral primitives by its specific folding logic based on the sum of coordinates relative to the size, and its use of a constant factor for the central region [S1, unofficial].
## How it works
**Inputs:** Query point $p = (p_x, p_y, p_z)$; size $s$ (distance from center to vertex along axes).
**Outputs:** Signed distance $d$. Negative inside, positive outside.

1.  **Symmetry Folding:** Compute $q = |p| = (|p_x|, |p_y|, |p_z|)$. This folds the 48 symmetric octants into the first octant [S1, unofficial].
2.  **Region Identification:** Compute $m = q_x + q_y + q_z - s$. Determine which face region the point lies in by comparing $3q_i$ to $m$:
    *   If $3q_x < m$, the closest feature is on the face normal to the x-axis. Set $q' = (q_x, q_y, q_z)$.
    *   Else if $3q_y < m$, the closest feature is on the face normal to the y-axis. Set $q' = (q_y, q_z, q_x)$ (cyclic permutation).
    *   Else if $3q_z < m$, the closest feature is on the face normal to the z-axis. Set $q' = (q_z, q_x, q_y)$ (cyclic permutation).
    *   Else, the point is in the central region (closest to the center or edges in a way that the distance is proportional to $m$) [S1, unofficial].
3.  **Central Region Handling:** If the point is in the central region (the `else` case above), return $d = m \cdot \tan(\pi/6) = m \cdot \frac{\sqrt{3}}{3} \approx m \cdot 0.57735027$ [S1, unofficial].
4.  **Face Distance Calculation:** For the identified region with transformed coordinates $q' = (q'_x, q'_y, q'_z)$:
    *   Compute $k = \text{clamp}(0.5 \cdot (q'_z - q'_y + s), 0, s)$ [S1, unofficial].
    *   Compute the vector to the closest point on the face plane: $v = (q'_x, q'_y - s + k, q'_z - k)$ [S1, unofficial].
    *   Return $d = |v|$ [S1, unofficial].

**Pseudocode:**
```python
import math

def sd_octahedron(p, s):
    """
    Computes the signed distance to an octahedron of size s.
    p: tuple or list of 3 floats (x, y, z)
    s: float, size parameter (distance from center to vertex)
    Returns: float, signed distance
    """
    # Step 1: Fold into first octant
    qx = abs(p[0])
    qy = abs(p[1])
    qz = abs(p[2])
    
    # Step 2: Identify region
    m = qx + qy + qz - s
    
    # Check conditions in order. Note: The GLSL source uses if-else if-else.
    # We must follow the exact order to match the folding logic.
    
    if 3.0 * qx < m:
        # Closest to x-face
        # q' = (qx, qy, qz)
        q_prime_x = qx
        q_prime_y = qy
        q_prime_z = qz
    elif 3.0 * qy < m:
        # Closest to y-face
        # q' = (qy, qz, qx)
        q_prime_x = qy
        q_prime_y = qz
        q_prime_z = qx
    elif 3.0 * qz < m:
        # Closest to z-face
        # q' = (qz, qx, qy)
        q_prime_x = qz
        q_prime_y = qx
        q_prime_z = qy
    else:
        # Central region
        return m * math.tan(math.pi / 6.0)
        
    # Step 3: Calculate distance to face
    # k = clamp(0.5 * (q'_z - q'_y + s), 0.0, s)
    k = 0.5 * (q_prime_z - q_prime_y + s)
    if k < 0.0:
        k = 0.0
    elif k > s:
        k = s
        
    # Vector to closest point
    # v = (q'_x, q'_y - s + k, q'_z - k)
    vx = q_prime_x
    vy = q_prime_y - s + k
    vz = q_prime_z - k
    
    # Return length of v
    return math.sqrt(vx*vx + vy*vy + vz*vz)
```

**Parameters:**
*   $s$: Size of the octahedron. Typical values depend on scene scale. [S1, unofficial]

**Edge Cases:**
*   $s=0$: The octahedron is a point. The formula may behave unexpectedly if not handled, but standard SDFs usually return distance to origin. [G]
*   Precision: The comparison $3q_i < m$ is critical for correct folding. Floating point errors near boundaries may cause slight discontinuities or incorrect region selection. [G]

**Steps:**
1.  Let $k = \sqrt{3.0}$ [S2, unofficial].
2.  Transform $p_x = |p_x| - r$, $p_y = p_y + r/k$ [S2, unofficial].

4.  Transform $p_x = p_x - \text{clamp}(p_x, -2r, 0)$ [S2, unofficial].
5.  Return $-|p| \cdot \text{sign}(p_y)$ [S2, unofficial].

## Operating characteristics
**Time Complexity:** $O(1)$ constant time.
**Memory Complexity:** $O(1)$ constant space.
**Performance:** Very fast, suitable for real-time ray marching. The branching in region identification is predictable. [S1, unofficial]
**Strengths:** Exact analytical solution, no approximation errors, efficient. [S1, unofficial]
**Limitations:** Only applies to regular octahedrons. Not suitable for deformed or irregular octahedrons. [G]
**When to use:** When rendering or ray marching regular octahedrons. [S1, unofficial]
**When not to use:** When the object is not a regular octahedron, or when higher-order primitives are needed for smoother surfaces. [G]
## Background
The Octahedron SDF is a standard primitive in the family of procedural SDFs popularized by Inigo Quilez and others in the ray marching community [S1, unofficial]. It is derived from the geometric properties of the octahedron, specifically its symmetry and the relationship between its faces and vertices. The specific folding logic is documented in various online resources and code repositories [S1, unofficial].
