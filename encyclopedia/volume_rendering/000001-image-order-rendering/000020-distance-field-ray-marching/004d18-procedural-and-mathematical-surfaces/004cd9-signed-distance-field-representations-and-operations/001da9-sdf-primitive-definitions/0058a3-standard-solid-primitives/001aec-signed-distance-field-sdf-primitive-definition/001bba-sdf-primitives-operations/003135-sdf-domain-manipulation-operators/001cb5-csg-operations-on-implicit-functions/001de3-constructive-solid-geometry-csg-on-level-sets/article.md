# Constructive Solid Geometry (CSG) on Level Sets

Also called: Level Set CSG, Point-Classification Map, Voxel CSG

## Overview
Constructive Solid Geometry (CSG) on Level Sets combines multiple implicit functions (typically Signed Distance Fields, SDFs) into a single implicit function using Boolean operations (Union, Intersection, Difference). This method solves the problem of defining complex composite shapes from simple primitives within a volumetric or ray-marched context. It differs from sibling methods like the [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md) by focusing on the mathematical composition of scalar fields or classification maps rather than a procedural stack-based evaluation, and it differs from [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md) by providing specific implementation strategies for discrete voxel buffers and classification look-up tables.

## How it works
The method operates on two primary data representations: discrete Voxel Buffers (scalar fields) and Point-Classification Maps (binary classification tables). The inputs are two level set volumes (or a CSG tree node and its children) and a Boolean operator. The output is a new level set volume or classification map.

### Data Structures

**1. Voxel Buffer**
A 3D array of floating-point values representing the signed distance (or density) at each voxel coordinate $(i, j, k)$.
*   **Fields:** `value(i, j, k)`: float.
*   **Layout:** Contiguous memory or strided array indexed by $i, j, k$.

**2. Point-Classification Map (PCM)**
A look-up table that maps a complete primitive classification result (encoded as a binary index) to the final in/out CSG classification.
*   **Fields:** `table[index]`: boolean or integer (0/1).
*   **Layout:** Array of size $2^n$, where $n$ is the number of leaf nodes (primitives) in the CSG tree.
*   **Index Encoding:** An $n$-bit binary number. A 1 at the $j$-th bit indicates the point is inside the $j$-th primitive; 0 indicates outside.

### Algorithm: Voxel Buffer Composition
This approach modifies a voxel buffer in-place or creates a new buffer by applying element-wise Boolean logic to the scalar values.

**Inputs:**
*   `A`: Source Voxel Buffer.
*   `B`: Operand Voxel Buffer (must share the same bounding box dimensions).
*   `op`: Boolean operation (`UNION`, `INTERSECTION`, `DIFFERENCE`).

**Steps:**
1.  Determine the bounding box dimensions shared by `A` and `B`.
2.  Iterate over every voxel $(i, j, k)$ in the bounding box.
3.  Apply the operation based on `op`:
    *   **Union:** $A_{new}(i,j,k) = \min(A(i,j,k), B(i,j,k))$ [S2, unofficial].
    *   **Intersection:** $A_{new}(i,j,k) = \max(A(i,j,k), B(i,j,k))$ [S2, unofficial].
    *   **Difference (A minus B):** $A_{new}(i,j,k) = \max(A(i,j,k), -B(i,j,k))$ [S2, unofficial].
4.  Store the result in `A` (or a destination buffer).

**Pseudocode:**

```python
def apply_csg_voxel(A: VoxelBuffer, B: VoxelBuffer, op: str) -> VoxelBuffer:
    dims = A.dims()
    result = VoxelBuffer(dims)
    
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                val_a = A.value(i, j, k)
                val_b = B.value(i, j, k)
                
                if op == "UNION":
                    # Union of SDFs is the minimum distance
                    result.value(i, j, k) = min(val_a, val_b)
                elif op == "INTERSECTION":
                    # Intersection of SDFs is the maximum distance
                    result.value(i, j, k) = max(val_a, val_b)
                elif op == "DIFFERENCE":
                    # Difference A - B is max(A, -B)
                    result.value(i, j, k) = max(val_a, -val_b)
                else:
                    raise ValueError("Unknown CSG operation")
                    
    return result
```

### Algorithm: PCM Construction
This approach constructs a classification map for a CSG tree node by recursively combining the maps of its children.

**Inputs:**
*   `N`: A node in the CSG tree.
*   `N.op`: The Boolean operation associated with node `N` (if `N` is not a leaf).

**Steps:**
1.  If `N` is a leaf node (primitive):
    *   Return the PCM specific to that primitive. For a primitive defined by surface boundaries, this is typically generated by ray-casting or voxelizing the primitive to determine the $n$-bit classification index for each voxel.
2.  If `N` is an internal node:
    *   Recursively compute `PCM_left` = `CSG_PCM(N.left)`.
    *   Recursively compute `PCM_right` = `CSG_PCM(N.right)`.
    *   Combine `PCM_left` and `PCM_right` using `N.op` to form `PCM_combined`.
    *   The index domain of `PCM_combined` is the Cartesian product of the index domains of the sub-PCMs.
    *   The combined classification result $c$ is calculated as $c = c_1 \text{ op } c_2$, where $c_1$ and $c_2$ are classifications from the sub-PCMs.
    *   Return `PCM_combined`.

### Parameters
*   **$n$**: The number of leaf nodes (primitives) in the CSG tree. The classification index is an $n$-bit binary number [S1].
*   **PCM Size**: A look-up table of $2^n$ entries, sufficient to describe all possible point classification cases [S1].

### Pitfalls
*   **Memory Consumption:** Recursive PCM construction can consume high memory. This is mitigated by sharing a common PCM memory space by all levels of recursive calls [S1].
*   **Precision:** When using algebraic sum/product operators for anti-aliasing or soft boundaries, the result may not satisfy $A \cup \overline{A} \neq \text{Universe}$, leading to artifacts sensitive to sampling rates [S4, book].
*   **Boundary Conditions:** For anti-aliased voxelization, the iso-surface position assumption is critical. It is assumed that the iso-surface is positioned at a density value of 0.5 in the center of the filter profile to ensure a smooth boundary for the central difference operator [S4, book].

## Subtopics

### [Lipschitz Pruning](8623-lipschitz-pruning.md)
Lipschitz Pruning is a hierarchical algorithm that reduces the number of active nodes in a smooth Constructive Solid Geometry (CSG) tree for a specific region of space, outputting a pruned tree equivalent to the full tree within that region. It relies on the 1-Lipschitz property of the distance function to determine if binary operators can be replaced by a single operand without affecting the result. Unlike naive sphere tracing or range arithmetic which evaluates bounds globally or per-node, Lipschitz pruning uses a single local evaluation to prune sub-trees, significantly reducing computational cost while preserving exact distance values near surfaces.

### [CSG Distance Field Evaluation (Batched)](21089-csg-distance-field-evaluation-batched.md)
This method computes the signed distance values and material indices for a batch of query points against a Constructive Solid Geometry (CSG) tree. It solves the problem of evaluating complex implicit surfaces defined by boolean combinations of primitives in a single pass over a point cloud, which is essential for efficient ray marching or voxelization in volume rendering. It is distinguished from sibling methods like [Lipschitz Pruning](8623-lipschitz-pruning.md) by its explicit handling of material indices alongside distance values and its non-SIMD, plain C implementation structure.

### Lazy CSG Volume Modification
Lazy CSG Volume Modification is a volume modification system where SDF operations are added to per-octant CSG queues and executed lazily when the octant is close to the viewer, allowing dynamic expansion/contraction [S3].
*   **Steps:**
    1.  **Preparation:** Translate SDF AABB into an octant key range. Identify affected octants across LOD grids.
    2.  **Queuing:** Add SDF to the CSG queue of identified octants. Do not modify data immediately.
    3.  **Execution:** When an octant is close to the viewer, execute its CSG queue. Combine SDFs using Union, Subtract, Intersect.
    4.  **Pruning:** If a modification results in an empty octant, remove it and recursively prune parent octants that become empty.
*   **Parameters:** Supports primitive SDFs including box, cylinder, cone, heightfield, noise, pill, sphere, pellet, torus, pipe, and corridor [S3].

### Constructive Volume Geometry (CVG) Boolean Operations
Constructive Volume Geometry (CVG) is a modeling paradigm extending CSG to volumetric objects, allowing combinational operations defined in the real domain on scalar fields to model complex interior structures and amorphous phenomena [S4, book].
*   **Formulas:**
    *   Intersection: $d_{A \cap B} = \min(d_A(x), d_B(x))$ [S4, book].
    *   Difference: $d_{A - B} = \min(d_A(x), 1 - d_B(x))$ [S4, book].
    *   Union: $d_{A \cup B} = \max(d_A(x), d_B(x))$ [S4, book].
    *   Alternative Intersection (Algebraic Product): $d_{A \cap B} = d_A(x)d_B(x)$ [S4, book].
*   **Parameters:** Iso-surface position assumption for anti-aliased voxelization is positioned at a density value of 0.5 in the center of the filter profile to ensure smooth boundary for central difference operator [S4, book].

## Operating characteristics
*   **Time Complexity:** Voxel buffer composition is $O(N)$ where $N$ is the number of voxels in the bounding box. PCM construction is exponential in the number of primitives ($2^n$) if not pruned, but Lipschitz pruning reduces this significantly for smooth SDFs [S1].
*   **Memory Complexity:** Voxel buffers require $O(N)$ memory. PCM requires $O(2^n)$ memory, which becomes prohibitive for large $n$ without pruning or sharing [S1].
*   **Strengths:** Exact Boolean operations; efficient for static geometry; supports complex interior structures via CVG [S4, book].
*   **Limitations:** Memory explosion for deep CSG trees with many primitives; aliasing artifacts if not handled with soft boundaries or anti-aliasing [S4, book].
*   **When to use:** When exact Boolean composition is required and the number of primitives is small to moderate, or when using hierarchical pruning techniques.
*   **When not to use:** For very deep CSG trees with many primitives without pruning, or when dynamic, continuous deformation of the CSG tree is required without re-evaluation.

## Background
The concept of Point-Classification Maps (PCM) for CSG voxelization was introduced in the paper "Fast CSG voxelization by frame buffer pixel mapping" [S1]. This method leverages hardware frame buffer pixel mapping to accelerate the determination of set membership for points in a volume space. Constructive Volume Geometry (CVG) extends these concepts to volumetric objects, allowing for the modeling of complex interior structures using real-domain scalar fields [S4, book]. Lazy CSG Volume Modification applies these principles to dynamic terrain rendering using octrees and LOD grids [S3].
