# Sweep-based SDF Generation

Also called: Approximate Distance Field computation, Marching Parabolas, SDF Generation via Sweep Passes

## Overview
Sweep-based SDF Generation is an algorithm to compute an approximate Signed Distance Field (SDF) texture efficiently without brute-force per-pixel distance calculation [S1, S2, unofficial]. It is intended for use in Sphere Tracing [S1, unofficial]. The method sets itself apart from exact analytical SDF evaluations by using a multi-pass sweep approach that propagates distance information from rendered surface primitives through the volume, trading geometric precision for computational speed and texture-based storage [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 2D or 3D texture containing initial distance values, typically resulting from an initial sweep along the X-axis or direct rasterization of surfaces [S1, S2, unofficial].
*   **Output:** A quantized Signed Distance Field texture where each texel stores an approximate distance value [S1, unofficial].

**Data Structures:**
*   **Texture Storage:** The SDF is stored in a quantized format to avoid floating-point storage requirements [S1, unofficial]. Common formats include `UNORM_R8` (range 0–255) or `SNORM_R8` (range -127 to 127) [S1, unofficial].
*   **Shared Memory:** A local memory buffer (`sharedMem`) used within a compute shader workgroup to store a segment of the row being processed [S1, unofficial].
*   **Intermediate Textures:** If the quantization factor requires high precision during intermediate calculations, intermediate result textures may require twice the bits of the input storage to prevent overflow during parabolic addition [S1, unofficial].

**Parameters:**
*   `EDF_RANGE`: The maximum quantizable distance. For `UNORM_R8`, this is 255; for `SNORM_R8`, this is 127 [S1, unofficial].
*   `QUANITZATION_FACTOR`: A rescaling factor used to convert floating-point distances to integer storage [S1, unofficial].
*   `LOCAL_WORKGROUP_SIZE_X`: The local workgroup size, typically 256 due to mobile device constraints [S1, unofficial].

**Algorithm Steps:**
1.  **Initial Rasterization (2D Context):** Render surfaces into the distance field texture [S2, unofficial]. In 2D, this is done by drawing lines a couple of pixels wide to get accurate subpixel distances for the immediate vicinity of surfaces [S2, unofficial].
2.  **X-Axis Sweep:** The input texture is assumed to have already been swept in the X direction [S1, unofficial].
3.  **Y-Axis Sweep:** Perform a sweep along the Y axis using an extension compute shader [S1, unofficial].
4.  **Synchronization:** Insert a memory barrier to ensure synchronization between passes [S1, unofficial].
5.  **Z-Axis Sweep:** Perform a sweep along the Z axis [S1, unofficial].
6.  **Completion:** The SDF generation is complete [S1, unofficial].

**Row Processing Logic (The Sweep Pass):**
The core computation occurs when processing a single row (or column) of the texture [S1, unofficial]. The algorithm processes a row by:
1.  Loading the input value for the current invocation.
2.  Quantizing the value: `_out = uint(input * QUANITZATION_FACTOR)` [S1, unofficial]. Values greater than `EDF_RANGE * EDF_RANGE` indicate "infinity" [S1, unofficial].
3.  Storing the quantized value to `sharedMem[rowInvocationID]` [S1, unofficial].
4.  Synchronizing all threads in the workgroup (`BARRIER()`) [S1, unofficial].
5.  Iterating over a range of offsets `i` from `-EDF_RANGE` to `EDF_RANGE - 1` (excluding 0 for optimization) [S1, unofficial].
6.  For each offset, calculating the wrap-around coordinate and the distance between the current invocation and the neighbor [S1, unofficial].
7.  Updating the local minimum using the parabolic distance approximation [S1, unofficial].

**Formula:**
The distance update rule for each neighbor in the sweep is:
$$ \text{newDist} = \min(\text{currentDist}, \text{sharedMem}[\text{newCoordinate}] + \text{distanceBetween}^2) $$
Where:
*   $\text{currentDist}$ is the current minimum distance found for the invocation [S1, unofficial].
*   $\text{sharedMem}[\text{newCoordinate}]$ is the quantized distance value stored in shared memory at the neighbor's position [S1, unofficial].
*   $\text{distanceBetween} = \text{rowInvocationID} - \text{newCoordinate}$ [S1, unofficial].
*   $\text{newCoordinate} = \text{coordinateWrapAround}(\text{rowInvocationID} + i)$, which is typically `x % ROW_LENGTH` [S1, unofficial].

**Post-Processing:**
After the loop, the final result is de-quantized:
$$ \text{result} = \text{float}(\text{out}) \times \text{QUANITZATION_FACTOR\_RCP} $$
Where `QUANITZATION_FACTOR_RCP` is the reciprocal of the quantization factor [S1, unofficial].

**Pseudocode:**
```python
def sweep_row(input_tex, output_tex, row_length, rowInvocationID, sharedMem, barrier_func):
    # Constants from evidence
    EDF_RANGE = 255  # For UNORM_R8
    QUANITZATION_FACTOR = 255.0
    QUANITZATION_FACTOR_RCP = 1.0 / QUANITZATION_FACTOR

    # 1. Load and Quantize
    input_val = input_tex[rowInvocationID]  # Standard texel fetch
    _out = int(input_val * QUANITZATION_FACTOR)  # uint cast

    # 2. Store to Shared Memory
    sharedMem[rowInvocationID] = _out

    # 3. Synchronize
    barrier_func()

    # 4. Sweep Loop
    # Evidence loop: for i from -EDF_RANGE to EDF_RANGE - 1
    for i in range(-EDF_RANGE, EDF_RANGE):
        # Wrap-around coordinate
        newCoordinate = (rowInvocationID + i) % row_length
        # Distance between
        distanceBetween = rowInvocationID - newCoordinate
        # Update minimum
        candidate = sharedMem[newCoordinate] + distanceBetween * distanceBetween
        if candidate < _out:
            _out = candidate

    # 5. De-quantize and Store
    result = float(_out) * QUANITZATION_FACTOR_RCP
    output_tex[rowInvocationID] = result  # Standard texel store

    # Note: If row_length > LOCAL_WORKGROUP_SIZE_X, sharedMem must be 
    # pre-loaded with LOCAL_WORKGROUP_SIZE_X + 2*EDF_RANGE samples 
    # to handle wrap-around and range access [S1, unofficial].
```

**Edge Cases and Pitfalls:**
*   **Row Length vs. Workgroup Size:** If the row length exceeds `LOCAL_WORKGROUP_SIZE_X`, `sharedMem` must be pre-loaded with `LOCAL_WORKGROUP_SIZE_X + 2*EDF_RANGE` samples to handle wrap-around and range access [S1, unofficial].
*   **Overflow:** Intermediate result textures require twice the bits of the input storage to prevent overflow during the parabolic addition ($\text{distanceBetween}^2$) [S1, unofficial].
*   **Infinity Handling:** Values exceeding `EDF_RANGE * EDF_RANGE` after quantization should be treated as infinity to avoid incorrect minimums [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The non-optimal version (without prefix-sum/scan) has a complexity proportional to $O(\text{EDF\_RANGE})$ per pixel per sweep pass [S1, unofficial].
*   **Performance:** On a 320GB/s GDDR5 desktop GPU, the performance bound is around 6ms for SDF computation [S1, unofficial]. The non-optimal algorithm is expected to take between 500-1000ms assuming 2TB/s shared memory speed and `EDF_RANGE=255` [S1, unofficial].
*   **Memory Complexity:** Requires shared memory proportional to the workgroup size plus a halo for the sweep range [S1, unofficial]. Intermediate textures may require double the bit-depth of the final output [S1, unofficial].
*   **Strengths:** Efficient generation of approximate SDFs for sphere tracing; avoids expensive per-pixel analytical distance calculations; suitable for real-time rendering on GPUs [S1, S2, unofficial].
*   **Limitations:** The result is an approximation, not an exact Euclidean distance field; accuracy depends on `EDF_RANGE` and the initial rasterization quality; performance degrades with larger `EDF_RANGE` in the non-optimized version [S1, unofficial].
*   **When to use:** When an approximate SDF is sufficient for sphere tracing, though the non-optimal version is slow (500–1000 ms) and requires optimizations like prefix-sum/scan or warp shuffles for performance-critical applications [S1, unofficial].
*   **When not to use:** When exact Euclidean distances are required for collision detection or precise ray marching [S1, unofficial].

## Background
The method is described in the context of adding an "Approximate Distance Field computation extension" to the Irrlicht engine [S1, unofficial]. It builds upon the "Marching Parabolas" technique, which is analogous to blur functions in shared memory [S1, unofficial]. The concept of rendering surfaces to get accurate subpixel distances and then sweeping to propagate them was discussed in the context of fast pixelshader 2D raytracing [S2, unofficial]. The non-optimal version can be optimized using prefix-sum/scan algorithms or warp-level primitives like `NV_shuffle` [S1, unofficial].
