# Cone Signed Distance Function

Also called: Cone SDF, sdCone, Signed Cone, Signed Capped Cone, Exact Cone SDF, Signed Distance Function (SDF) for Cone

## Overview
The Cone Signed Distance Function computes the exact Euclidean distance from a query point to the surface of a finite cone, including its lateral mantle and base cap. It solves the problem of efficiently rendering or ray-marching conical primitives in volume rendering and ray tracing without polygonization. It is distinguished from the infinite cone SDF by handling the base boundary and from the cylinder by its tapered geometry. It builds on [Basic Primitive Definitions](5346-basic-primitive-definitions.md).

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $p \in \mathbb{R}^3$ and primitive-specific parameters.
*   **Output:** Scalar signed distance $d \in \mathbb{R}$. $d < 0$ indicates the point is inside the primitive, $d > 0$ indicates it is outside, and $d = 0$ lies on the surface [S1, unofficial].

**Assumptions:**
All implementations assume the primitive is centered at the origin and axis-aligned where applicable. Transformations (rotation, translation, scaling) are applied to the query point $p$ before evaluation, or the primitive parameters are adjusted accordingly.

**Data Structures:**
No complex data structures are required. The method operates on scalar values and 2D/3D vectors.

**Parameters:**
*   $r$: Base radius of the cone.
*   $h$: Height of the cone.
*   $p$: Query point $(p_x, p_y, p_z)$.

**Geometric Configuration:**
The sources describe two primary orientations for the cone. The "Exact Cone" implementation [S4, unofficial] places the apex at the origin $(0,0,0)$ and the base center at $(0, -h, 0)$, opening downward along the negative Y-axis. The "sdCone" implementation [S3, unofficial] uses a normalized vector $c$ to define the axis and slope, often oriented along the Y-axis with the base at $y=0$ or apex at origin depending on the specific GLSL variant. The most robust and commonly cited "exact" formulation [S4, unofficial] handles the capped cone explicitly.

**Algorithm (Exact Capped Cone, Apex at Origin, Opening Downward):**
This method computes the distance to the closest point on the lateral surface (mantle) or the base cap.

1.  **Project to 2D:** Compute the radial distance from the Y-axis and form a 2D point $q$ in the $(r, y)$ plane.
    $$ q = (\sqrt{p_x^2 + p_z^2}, p_y) $$
2.  **Define Geometry in 2D:**
    *   Tip (Apex): $t = (0, 0)$
    *   Base Center: $b_{center} = (r, -h)$
    *   Vector from Tip to Base Center: $k = (r, h)$
    *   Squared length of $k$: $m_2 = r^2 + h^2$
3.  **Compute Distances:**
    *   Vector from Tip to $q$: $d_1 = q - t = q$
    *   Vector from Base Center to $q$ (for cap calculation): $d_3 = q - (\text{clamp}(q_x, 0, r), -h)$
    *   Vector representing the side slope segment (Tip to Base Edge): $ba = b_{center} - t = (r, -h)$
    *   Project $d_1$ onto $ba$ to find the closest point on the infinite line containing the slope:
        $$ u = \text{clamp}\left(\frac{d_1 \cdot ba}{m_2}, 0, 1\right) $$
    *   Distance to the side slope segment:
        $$ \text{side\_dist} = \| d_1 - ba \cdot u \| $$
    *   Distance to the base cap:
        $$ \text{cap\_dist} = \| d_3 \| $$
4.  **Unsigned Distance:**
    $$ \text{dist} = \min(\text{side\_dist}, \text{cap\_dist}) $$
5.  **Inside Test:**
    Determine if the point is inside the cone. A point is inside if it is below the apex ($q_y \le 0$), above the base ($q_y \ge -h$), and within the lateral boundary. The lateral boundary condition for a cone opening downward with apex at origin is $q_x \cdot h + q_y \cdot r \le 0$ [S4, unofficial].
    $$ \text{inside} = (q_y \le 0) \land (q_y \ge -h) \land (q_x \cdot h + q_y \cdot r \le 0) $$
6.  **Signed Distance:**
    $$ d = \begin{cases} -\text{dist} & \text{if inside} \\ \text{dist} & \text{if outside} \end{cases} $$

**Alternative Formulation (Normalized Vector $c$):**
Some implementations [S3, unofficial] use a normalized vector $c = (c_x, c_z)$ where $c_x = \sin(\theta)$ and $c_z = \cos(\theta)$ (or similar depending on axis alignment) to define the cone's slope. For a cone aligned with the Y-axis, the function `sdCone` in `sdCappedCone.glsl` [S3, unofficial] computes:
$$ q = (\|p_{xz}\|, p_y) $$
$$ d_1 = -p_y - c_z $$
$$ d_2 = \max(q \cdot c_{xy}, p_y) $$
$$ d = \| \max((d_1, d_2), 0) \| + \min(\max(d_1, d_2), 0) $$
Note: In this specific GLSL snippet, $c$ must be normalized [S3, unofficial]. The interpretation of $c$ varies; in `sdCone.glsl` [S3, unofficial], it is defined as `vec2` and used in `dot(c, vec2(q, p.z))`, implying a different orientation (Z-axis). The Y-axis version in `sdCappedCone.glsl` uses $c$ to define the slope relative to the Y-axis. Implementers must ensure the vector $c$ is normalized [S3, unofficial].

**Pseudocode (Exact Capped Cone, Y-Axis, Apex at Origin):**

```python
import math

def sd_cone(p_x, p_y, p_z, r, h):
    """
    Computes the signed distance to a capped cone.
    Cone apex at (0, 0, 0), base center at (0, -h, 0).
    Base radius r, height h.
    """
    # 1. Project to 2D (r, y) plane
    q_x = math.sqrt(p_x * p_x + p_z * p_z)
    q_y = p_y
    
    # 2. Define geometry
    # Tip at (0, 0)
    # Base center at (r, -h)
    # Vector k from Tip to Base Center: (r, h)
    k_x = r
    k_y = h
    m2 = k_x * k_x + k_y * k_y
    
    # 3. Compute distances
    # d1 is vector from Tip to q
    d1_x = q_x
    d1_y = q_y
    
    # d3 is vector from clamped base projection to q
    # Clamp q_x to [0, r] for the base cap projection
    q_x_clamped = max(0.0, min(q_x, r))
    d3_x = q_x - q_x_clamped
    d3_y = q_y - (-h)
    
    # Vector ba from Tip to Base Center (r, -h)
    ba_x = r
    ba_y = -h
    
    # Project d1 onto ba
    # u = clamp(dot(d1, ba) / m2, 0, 1)
    dot_d1_ba = d1_x * ba_x + d1_y * ba_y
    u = max(0.0, min(dot_d1_ba / m2, 1.0))
    
    # Closest point on segment
    closest_x = ba_x * u
    closest_y = ba_y * u
    
    # Distance to side slope
    side_dist_x = d1_x - closest_x
    side_dist_y = d1_y - closest_y
    side_dist = math.sqrt(side_dist_x * side_dist_x + side_dist_y * side_dist_y)
    
    # Distance to base cap
    cap_dist = math.sqrt(d3_x * d3_x + d3_y * d3_y)
    
    # Unsigned distance
    dist = min(side_dist, cap_dist)
    
    # 4. Inside test
    # Inside if: y <= 0, y >= -h, and inside lateral boundary
    # Lateral boundary: q_x * h + q_y * r <= 0
    inside = (q_y <= 0.0) and (q_y >= -h) and ((q_x * h + q_y * r) <= 0.0)
    
    # 5. Signed distance
    if inside:
        return -dist
    else:
        return dist
```

**Edge Cases and Pitfalls:**
*   **Degenerate Cone:** If $r=0$ or $h=0$, the cone degenerates to a line or disk. The formula may produce NaNs or incorrect distances if not guarded. [G] Check for $r < \epsilon$ or $h < \epsilon$ and return distance to line segment or disk accordingly.
*   **Precision:** The inside test relies on the linear inequality $q_x h + q_y r \le 0$. Floating-point errors near the surface may cause flickering. [G] Use a small epsilon for the inside test if necessary, or rely on the distance being very small.
*   **Orientation:** Ensure the query point is transformed into the cone's local space before evaluation. The formula above assumes apex at origin, opening down Y. For other orientations, rotate $p$ accordingly.
*   **Normalized Vector Variant:** If using the $c$ vector variant [S3, unofficial], ensure $c$ is normalized. Failure to normalize results in incorrect distances.

## Operating characteristics
*   **Time Complexity:** $O(1)$. The computation involves a constant number of arithmetic operations, square roots, and comparisons.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures are needed.
*   **Performance:** Extremely fast, suitable for real-time ray marching and SDF rendering. The exact formulation avoids iterative approximation.
*   **Strengths:** Exact distance, handles both lateral surface and base cap, robust for ray marching.
*   **Limitations:** Only applies to right circular cones. Does not handle truncated cones with different top/bottom radii directly (requires combination or different primitive).

## Background
The Signed Distance Function for a cone is a standard primitive in the field of Signed Distance Fields (SDFs), popularized by Inigo Quilez in his online articles on distance functions [S1, unofficial]. The exact formulation for the capped cone, particularly the one handling the base cap and lateral surface correctly, is derived from geometric projections onto the 2D cross-section plane. Variations exist in different code repositories (e.g., `glsl-sdf-primitives` [S3, unofficial], `sdf-math-rs` [S4, unofficial]), often differing in axis alignment (Y vs Z) and parameterization (radius/height vs normalized vector). The formulation in [S4, unofficial] is widely regarded as the "exact" implementation for a capped cone.
