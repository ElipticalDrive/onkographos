# Signed Distance Field (SDF) Primitive Definition

Also called: SDF Function, SDF Shapes, Signed Distance Field (SDF), Signed Distance Function (SDF), Signed Distance Function Primitives

## Overview
A Signed Distance Field (SDF) Primitive Definition is a method for representing 3D geometry using analytical scalar functions $f(\mathbf{p})$ that return the shortest Euclidean distance from a query point $\mathbf{p}$ to the nearest surface of a canonical shape [S2, S3, S8, unofficial]. The sign of the result indicates spatial containment: positive values denote points outside the object, negative values denote points inside, and zero defines the surface boundary [S2, S9, S15, unofficial]. This method replaces explicit mesh tessellation with continuous algebraic solutions, enabling efficient ray marching (sphere tracing) by providing a safe lower bound on the distance to the surface, which guarantees no tunneling occurs during step advancement [S1, S8, S15, unofficial]. Unlike [Constructive SDF Modeling](871-constructive-sdf-modeling-min-combination.md) which focuses on composition, this method defines the base primitives themselves [G].

## How it works
**Inputs:** A 3D query point $\mathbf{p} = (x, y, z)$ and primitive parameters (e.g., radius, center, extents).
**Outputs:** A scalar float $d$ representing the signed distance.

**Data Structures:**
Primitives are typically defined by simple structs or parameter tuples. Common layouts include:
*   **Sphere:** Center $\mathbf{c} \in \mathbb{R}^3$, Radius $r \in \mathbb{R}$ [S14, unofficial].
*   **Box:** Position $\mathbf{p}_{box} \in \mathbb{R}^3$, Half-extents $\mathbf{b} \in \mathbb{R}^3$ [S14, unofficial].
*   **Plane:** Normal $\mathbf{n} \in \mathbb{R}^3$ (unit length), Offset $d_{offset} \in \mathbb{R}$ [S14, unofficial].
*   **Torus:** Major radius $R_{out}$, Minor radius $R_{in}$ [S14, unofficial].

**Steps:**
1.  **Transform:** If the primitive is not at the origin or aligned with axes, map the query point $\mathbf{p}$ into the primitive's local coordinate space using the inverse transformation matrix $M^{-1}$ [S11, unofficial].
2.  **Evaluate:** Compute the distance to the nearest feature (center, edge, or face) based on the primitive's analytical formula.
3.  **Sign:** Apply the sign convention: $d > 0$ outside, $d < 0$ inside [S2, S9, unofficial].
4.  **Return:** Output $d$.

**Formulas:**
*   **Sphere:** $d(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r$ [S11, S14, unofficial].
*   **Box (Exact):** Let $\mathbf{d} = |\mathbf{p} - \mathbf{p}_{box}| - \mathbf{b}$. Then $d(\mathbf{p}) = \|\max(\mathbf{d}, \mathbf{0})\| + \min(\max(\mathbf{d}_x, \max(\mathbf{d}_y, \mathbf{d}_z)), 0)$ [S6, S14, unofficial].
*   **Box (Cheap/Overestimate):** $d(\mathbf{p}) = \max(|\mathbf{p} - \mathbf{p}_{box}| - \mathbf{b})$ [S6, unofficial]. This overestimates distance at corners but is faster.
*   **Plane:** $d(\mathbf{p}) = \mathbf{p} \cdot \mathbf{n} + d_{offset}$ [S6, S14, unofficial].
*   **Torus:** Let $\mathbf{q} = (\|\mathbf{p}_{xz} - \mathbf{c}_{xz}\| - R_{out}, p_y - c_y)$. Then $d(\mathbf{p}) = \|\mathbf{q}\| - R_{in}$ [S14, unofficial].
*   **Cylinder (Infinite):** $d(\mathbf{p}) = \|\mathbf{p}_{xz} - \mathbf{c}_{xz}\| - r$ [S14, unofficial].
*   **Cylinder (Capped):** Let $d_x = \|\mathbf{p}_{xz} - \mathbf{c}_{xz}\| - r$ and $d_y = |p_y - c_y| - h$. Then $d(\mathbf{p}) = \min(\max(d_x, d_y), 0) + \|\max(d_x, d_y, 0)\|$ [S14, unofficial].
*   **Cone:** Let $\phi = \arctan(r/h)$. $d(\mathbf{p}) = \max(\sqrt{x^2+z^2}\cos(\phi) - |y|\sin(\phi), \max(y-h, -y))$ [S14, unofficial].
*   **Capsule:** $d(\mathbf{p}) = \text{dist}(\mathbf{p}, \text{segment } \mathbf{a}, \mathbf{b}) - r$ [S13, unofficial].
*   **Smooth Min (Blend):** $smin(a, b) = \text{mix}(b, a, h) - k \cdot h \cdot (1 - h)$, where $h = \text{clamp}(0.5 + 0.5 \cdot (b - a) / k, 0, 1)$ and $k$ is a smoothing constant (e.g., 0.2) [S11, unofficial].

**Pseudocode:**
```python
def sdf_sphere(p: vec3, c: vec3, r: float) -> float:
    """Returns signed distance to a sphere."""
    return length(p - c) - r

def sdf_box(p: vec3, center: vec3, half_extents: vec3) -> float:
    """Returns exact signed distance to an axis-aligned box."""
    # Translate point to box center
    d = abs(p - center) - half_extents
    # Distance to corners vs faces
    corner_dist = length(max(d, vec3(0.0)))
    face_dist = min(max(d.x, max(d.y, d.z)), 0.0)
    return corner_dist + face_dist

def sdf_torus(p: vec3, center_xz: vec2, R_out: float, R_in: float) -> float:
    """Returns signed distance to a torus aligned with Y axis."""
    # Distance to the center ring of the torus
    q = vec2(length(p.xz - center_xz) - R_out, p.y)
    return length(q) - R_in

def sdf_plane(p: vec3, normal: vec3, offset: float) -> float:
    """Returns signed distance to a plane. Normal must be normalized."""
    return dot(p, normal) + offset

def sdf_capsule(p: vec3, a: vec3, b: vec3, r: float) -> float:
    """Returns signed distance to a capsule defined by endpoints a and b."""
    ab = b - a
    # Project p onto segment ab, clamped to [0, 1]
    t = clamp(dot(p - a, ab) / dot(ab, ab), 0.0, 1.0)
    # Closest point on segment
    closest = a + ab * t
    return length(p - closest) - r
```

**Parameters:**
*   **Gradient Step Size:** For normal approximation via finite differences, a step size of $\epsilon = 0.0001$ is typical [S11, unofficial].
*   **Smoothing Constant ($k$):** For smooth unions, $k=0.2$ is a common default [S11, unofficial].
*   **Lipschitz Bound:** The SDF must satisfy the Lipschitz condition with constant 1. This guarantees that $|f(\mathbf{p}_1) - f(\mathbf{p}_2)| \le \|\mathbf{p}_1 - \mathbf{p}_2\|$, ensuring the value is a safe lower bound for ray marching [S15, unofficial].

**Edge Cases and Pitfalls:**
*   **Non-Exact SDFs:** Not all shapes have closed-form SDFs. Arbitrary meshes require approximations (e.g., BVH traversal or baked textures) [S15, unofficial].
*   **GDF Performance:** Generalized Distance Functions (GDF) using loops for polyhedra (e.g., icosahedrons) may fail to unroll on certain drivers (e.g., Nvidia 350.12), causing slowdowns [S6, S13, unofficial].
*   **Incorrect Bounds:** Some illustrative functions (e.g., `fBlob`) do not provide correct distance bounds and should not be used for sphere tracing [S6, S13, unofficial].
*   **Discontinuities:** Taking `min` or `max` of SDFs creates sharp edges. Smooth blending requires `smin` [S11, unofficial].

## Subtopics

### [SDF Primitives & Operations](1075-sdf-primitives-operations.md)
Provides foundational analytical functions and geometric operators (union/intersection via min/max) for base primitives. Focuses on the definition of shapes like spheres, boxes, and tori, and immediate boolean composition.

### [SDF Transformation](1086-sdf-transformation.md)
Applies geometric transformations (rotation, translation, scaling) by mapping the query point into local space via inverse matrices. Preserves mathematical integrity for ray marching.

### [k-SDF](9530-k-sdf.md)
A real-time view synthesis method for fuzzy geometries using $k$ lightweight mesh shells and view-dependent transparency, bounding samples per ray to $3 \le k \le 9$.

### [SDF Representation DOP](12996-sdf-representation-dop.md)
Creates volumetric SDFs for collision detection and rigid body dynamics, focusing on topological correctness over visual appearance.

### SDF Grid Modeling
A float grid where active values describe the distance to a surface, with negative values inside and positive outside [S16, unofficial]. SDF grids allow for efficient boolean operations with smooth transitions, which are difficult to perform on explicit meshes, and support smoothing via operations like the SDF Grid Mean node [S16, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation. Total cost is $O(N \cdot M)$ where $N$ is the number of primitives and $M$ is the number of ray march steps.
*   **Memory Complexity:** $O(1)$ for analytical primitives (only parameters stored). $O(V)$ for grid-based SDFs where $V$ is voxel count [S10, S16, unofficial].
*   **Performance:** Sphere tracing converges quadratically near surfaces. Exact SDFs allow large steps far from geometry, making them significantly faster than rasterization for complex, self-occluding scenes or procedural noise [S1, S8, unofficial].
*   **Strengths:** No tessellation artifacts; infinite resolution; easy boolean composition; compact storage for simple shapes [S1, S9, unofficial].
*   **Limitations:** No closed-form SDF exists for arbitrary meshes; complex shapes may require many primitives or noise functions, increasing evaluation cost; sharp edges from min/max can cause aliasing if not smoothed [S11, S15, unofficial].
*   **When to Use:** Procedural rendering, real-time ray marching, implicit modeling, collision detection [S1, S10, unofficial].
*   **When Not to Use:** When exact mesh topology is required for non-manifold geometry, or when hardware lacks efficient floating-point performance for complex analytical functions [S15, unofficial].

## Background
The concept of Signed Distance Fields originates from level set methods in computational geometry, where an orientable manifold surface is represented as a function tracking the signed distance to the nearest point on the interface [S10, unofficial]. In computer graphics, SDFs were popularized for real-time rendering by Inigo Quilez's work on "Modeling with Distance Functions" and subsequent GLSL ray marching tutorials [S1, S7, S11, unofficial]. They are widely used in procedural generation, implicit modeling, and neural rendering (e.g., SDF-based NeRF variants) to produce noise-free geometry [S5][S13, unofficial].
