# Gradient-SDF

Also called: Gradient-SDF representation

## Overview
Gradient-SDF is a hybrid 3D geometry representation that augments a voxel-based implicit Signed Distance Field (SDF) with the SDF gradient vector field at each voxel, combining implicit topology handling with explicit surface feature access [S1]. It solves the problem of costly neighbor lookups required for gradient computation in sparse SDF storage (e.g., hash maps) by storing gradients directly, enabling efficient interpolation via first-order Taylor expansion without accessing multiple voxels [S1]. Unlike standard sparse SDFs which require accessing 8 voxels for interpolation or gradient computation, Gradient-SDF allows direct access to the gradient per voxel, facilitating direct SDF tracking from depth images and photometric bundle adjustment directly in the voxel representation [S1].

## How it works
**Inputs and Outputs:**
- **Input:** A sequence of depth images (and optionally RGB images), camera poses (initially estimated or optimized), and a voxel size $v_s$ [S1].
- **Output:** A set of voxels $v_j$, each storing an SDF value $\psi_j$, a weight $W_j$, and an accumulated gradient vector $g_j$ [S1]. Optionally, extracted surface points, normals, or meshes [S1].

**Data Structures:**
Each voxel $v_j$ stores three fields [S1]:
1. **SDF value $\psi_j$**: A scalar representing the signed distance to the closest surface point [S1].
2. **Weight $W_j$**: A scalar indicating the reliability of the SDF estimate [S1].
3. **Accumulated gradient vector $g_j$**: A 3D vector storing the weighted sum of surface normals [S1].

Voxels are stored in a hash map (one voxel per entry) rather than contiguous memory, allowing compact storage where voxels far from the surface (zero weight) are not explicitly stored [S1]. Implementation uses single precision floats for `GradSdfVoxels` [S1].

**Numbered Steps:**

1. **Voxel Indexing:** For a query point $p$, compute the voxel index $j^*$ by rounding $p/v_s$ (voxel size), leveraging the regular grid structure to avoid neighbor search [S1].
   $$ j^* = \text{round}(p / v_s) $$
   The rounding operation maps the continuous coordinate to the integer grid index of the voxel containing $p$ [S1].

2. **SDF Update:** For a new distance estimate $d(v_j)$ at voxel $v_j$ with weight $w(v_j)$, update the SDF value and total weight [S1]:
   $$ W_j \leftarrow W_j + w(v_j) $$
   $$ \psi_j \leftarrow \frac{W_j \psi_j + w(v_j) d(v_j)}{W_j + w(v_j)} $$
   If $W_j$ is initially 0, $\psi_j$ becomes $d(v_j)$ [G].

3. **Gradient Update:** Update the accumulated gradient vector $g_j$ by adding the weighted inwards-pointing surface normal $n(v_j)$ at the closest surface point [S1]:
   $$ g_j \leftarrow g_j + w(v_j) n(v_j) $$
   In most applications, normals are already computed from the incoming data (e.g., depth maps) for filtering or rendering, so the computation does not introduce overhead [S1].

4. **Gradient Normalization:** Normalize the accumulated gradient to get the actual gradient estimate $\hat{g}_j$ at $v_j$ [S1]:
   $$ \hat{g}_j = \frac{g_j}{|g_j|} $$
   If $|g_j| \approx 0$, the gradient is undefined; the voxel may be ignored or treated as non-surface [G].

5. **Distance and Gradient Approximation:** To evaluate the distance $d_S(p)$ and its gradient $\nabla d_S(p)$ for a point $p$ near voxel $v_{j^*}$, use the first-order Taylor expansion [S1]:
   $$ d^{our}_S(p) = \psi_{j^*} + (p - v_{j^*}) \cdot \hat{g}_{j^*} $$
   $$ \nabla d^{our}_S(p) = \hat{g}_{j^*} $$
   where $j^* = \arg \min_j \|p - v_j\|$. Since $v_j$ are on a regular grid, $j^*$ is computed by rounding $p/v_s$ [S1].

6. **Closest Surface Point:** Compute the closest surface point $p_s$ for a voxel $v_j$ [S1]:
   $$ p_s(v_j) = v_j - \psi_j \hat{g}_j $$

7. **Photometric Bundle Adjustment (Optional):** If optimizing poses and geometry using RGB data, minimize the energy $E(R, t)$ [S1]:
   $$ E(R, t) = \sum_k w_k d_S(R p_k + t)^2 $$
   where $p_k$ are points in the world frame, and $R, t$ are rotation and translation [G].
   - Optimize by alternating minimization of poses and distances to reduce computational cost [S1].
   - Limit pose optimization to voxels containing surface points [S1].
   - Use a Gauss-Newton solver with Cholesky decomposition for the linear system [S1].
   - Project the real surface point $v_j - \psi_j \hat{g}_j$ into RGB images $I_i$ rather than voxel centers [S1].
   - Compute voxel color $\rho^c_j$ after optimization [S1]:
     $$ \rho^c_j = \frac{1}{N_j} \sum_i \nu_{ij} I^c_{ij} $$
     where $\nu_{ij}$ is a visibility indicator and $N_j$ is the number of valid observations [S1].

8. **Surface Extraction (Oriented Point Cloud):** Extract surface points $p_s(v_j)$ and normals $-\hat{g}_j$ from voxels where $|\psi_j \hat{g}_j| \le v_s^2$ (component-wise) [S1]. This results in a homogeneously sampled, consistently oriented point cloud [S1].

9. **Geometry Upsampling:** Subdivide each voxel into four subvoxels, determine distance using Taylor expansion, and extract surfels from subvoxels where $|\psi_j \hat{g}_j| \le v_s^2/4$ [S1].

10. **Mesh Extraction (Layered Marching Cubes):**
    - Extract min/max x, y, z coordinates to get bounding box [S1].
    - Allocate two voxel layers of size $(x_{max}-x_{min}) \times (y_{max}-y_{min})$ [S1].
    - Fill with first two z-layers (weights, colors, distances) [S1].
    - Apply Marching Cubes on the layer interface [S1].
    - Shift layers: refill the first layer with the next z-values and repeat [S1].

**Parameters:**
- **Voxel size $v_s$**: Determines grid resolution [S1]. Typical values are not given in the sources.
- **Weight $w(v_j)$**: Reliability of the estimate [S1]. Typical values are not given in the sources.
- **Precision**: Single precision floats [S1].

**Edge Cases and Pitfalls:**
- **Sparse Storage Cost:** In sparse storage (hash maps), standard SDF gradient computation is costly because neighbor lookups require additional hash table accesses, especially for voxels near block boundaries (57.8% of voxels in an $8^3$ block) [S1]. Gradient-SDF avoids this by storing gradients directly [S1].
- **Zero Gradient:** If $g_j$ is zero (no surface evidence), normalization fails. Check for a zero vector before normalization [G].

## Operating characteristics
- **Time Complexity:** Distance and gradient evaluation is $O(1)$ per query due to direct voxel lookup via rounding, avoiding neighbor searches [S1]. Pose optimization uses Gauss-Newton with Cholesky decomposition, complexity depends on the number of active voxels and points [S1].
- **Memory Complexity:** Hash map storage scales with the number of non-zero weight voxels [S1]. On the 00577 sofa sequence, the hash map-based Gradient-SDF method uses more than 20x less memory than dense storage of SDF Tracker [8], despite having three more entries per voxel [S1].
- **Measured Performance:** On synthetic data, mean angular deviation for Gradient-SDF gradients within 10 voxel sizes from surface is 5.07°, compared to 9.49° for central finite differences [S1]. On the 00577 sofa sequence, it achieves comparable ATE to SDF-Fusion but is much faster [S1].
- **Strengths:** Efficient interpolation without neighbor lookups; accurate gradient estimates; compact sparse storage; enables direct photometric bundle adjustment in voxel space [S1].
- **Limitations:** Requires storing an extra 3D vector per voxel; hash map overhead may be higher than contiguous arrays for very dense grids [S1].
- **When to use:** When sparse storage is needed for large scenes, and efficient gradient-based optimization (tracking, BA) is required [S1].
- **When not to use:** When dense volumetric operations are needed, or when memory overhead of hash maps is prohibitive compared to contiguous storage [S1].

## Background
Gradient-SDF was proposed in "Gradient-SDF: A Semi-Implicit Surface Representation for 3D Reconstruction" (2022) [S1]. It builds on the idea of combining implicit voxel SDFs with explicit surfel features to overcome the limitations of pure voxel or surfel representations, particularly in sparse storage scenarios [S1]. It is used for direct SDF tracking from depth images and photometric bundle adjustment directly in voxel representation [S1].
