# Elongation

Also called: Elongation operator, elongation transform

## Overview
Elongation is a domain manipulation operator for Signed Distance Functions (SDFs) that stretches a primitive along a specific axis or vector by modifying the query position $\mathbf{p}$ before evaluation. It solves the problem of creating elongated shapes (such as capsules, rods, or stretched spheres) from standard primitives without altering the primitive's internal geometry. It sets itself apart from siblings like [SDF Rounding](1829-sdf-rounding.md) by focusing on linear stretching rather than edge smoothing, and from [Finite Repetition](2869-finite-repetition.md) by modifying a single instance rather than tiling space.

## How it works
**Inputs and Outputs:**
- Input: Query point $\mathbf{p} \in \mathbb{R}^3$, elongation vector $\mathbf{s} \in \mathbb{R}^3$, base primitive SDF $d_{base}$.
- Output: Transformed point $\mathbf{p}'$ (modified in place), resulting distance $d_{result}$.

**Data Structures:**
- $\mathbf{p}$: 3-component float vector.
- $\mathbf{s}$: 3-component float vector defining the direction and magnitude of elongation.

**Steps:**
1.  **Transform Position:** Compute the transformed point $\mathbf{p}'$ by subtracting the elongation vector $\mathbf{s}$ from the absolute value of $\mathbf{p}$, then applying a specific projection or clamping logic depending on the implementation variant. In the provided reference [S1, unofficial], the transformation involves a complex rotation and scaling matrix derived from the elongation parameter $h$.
2.  **Evaluate Base SDF:** Compute $d_{base}(\mathbf{p}')$.
3.  **Adjust Distance:** Apply a correction factor to the distance value to account for the metric distortion introduced by the elongation.

**Formulas:**
The general elongation transform can be described as:
$$ \mathbf{p}' = \text{Elongate}(\mathbf{p}, \mathbf{s}) $$
$$ d_{result} = \text{Scale}(d_{base}(\mathbf{p}'), \mathbf{s}) $$

In the specific implementation from [S1, unofficial], the elongation is achieved through a sequence of operations involving a parameter $h$ (related to the elongation factor):
1.  Decompose $\mathbf{p}$ into components $p_x, p_y, p_z$.
2.  Apply absolute values to $p_x$ and $p_z$: $p_x = |p_x|, p_z = |p_z|$.
3.  Sort components to handle symmetry: $p_x = \max(p_x, p_z), p_z = \min(p_x, p_z)$.
4.  Normalize: $p_x = p_x - 0.5, p_z = p_z - 0.5$.
5.  Construct intermediate vector $\mathbf{q}$:
    $$ q_x = p_z $$
    $$ q_y = h \cdot p_y - 0.5 \cdot p_x $$
    $$ q_z = h \cdot p_x + 0.5 \cdot p_y $$
6.  Compute elongation correction $s$:
    $$ s = \max(0, -q_x) $$
7.  Compute distance squared terms $a$ and $b$:
    $$ m = h^2 + 0.25 $$
    $$ a = m(q_x + s)^2 + q_y^2 $$
    $$ t = \text{clamp}\left(\frac{q_y - 0.5 p_z}{m + 0.25}, 0.0, 1.0\right) $$
    $$ b = m(q_x + 0.5 t)^2 + (q_y - m t)^2 $$
8.  Select minimum distance:
    $$ d_{sq} = \text{where}(\min(q_y, -q_x m - q_y 0.5) > 0, a, \min(a, b)) $$
9.  Final distance:
    $$ d = \sqrt{\frac{d_{sq} + q_z^2}{m}} \cdot \text{sign}(\max(q_z, -p_y)) $$

**Parameters:**
- $h$: Elongation factor. Typical values depend on the desired aspect ratio. Not given in the sources.

**Edge Cases:**
- **Zero Elongation:** If $\mathbf{s} = \mathbf{0}$, the operator should return the base SDF unchanged.
- **Precision:** Division by $m$ requires $m \neq 0$. If $h=0$, $m=0.25$, so division is safe.

**Pseudocode:**
```python
import math

def elongation_sdf(p, h):
    """
    Computes the SDF of an elongated primitive based on the reference implementation.
    
    Args:
        p: tuple or list of 3 floats (px, py, pz)
        h: float, elongation parameter
        
    Returns:
        float, the signed distance
    """
    px, py, pz = p
    
    # Step 1: Absolute values and sorting for symmetry
    px = abs(px)
    pz = abs(pz)
    
    # Sort to handle the specific symmetry of the primitive
    if px < pz:
        px, pz = pz, px
        
    # Normalize
    px = px - 0.5
    pz = pz - 0.5
    
    # Construct q
    qx = pz
    qy = h * py - 0.5 * px
    qz = h * px + 0.5 * py
    
    # Elongation correction
    s = max(0.0, -qx)
    
    # Precompute m
    m = h * h + 0.25
    
    # Distance squared terms
    a = m * (qx + s) ** 2 + qy ** 2
    
    # Interpolation factor t
    denom = m + 0.25
    t = (qy - 0.5 * pz) / denom
    t = max(0.0, min(1.0, t))
    
    b = m * (qx + 0.5 * t) ** 2 + (qy - m * t) ** 2
    
    # Select minimum
    cond = min(qy, -qx * m - qy * 0.5) > 0.0
    d_sq = a if cond else min(a, b)
    
    # Final distance
    dist = math.sqrt((d_sq + qz ** 2) / m)
    sign = 1.0 if max(qz, -py) >= 0 else -1.0
    
    return dist * sign
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, involving a constant number of arithmetic operations.
- **Memory Complexity:** $O(1)$, no additional data structures required.
- **Strengths:** Efficiently creates elongated shapes from simple primitives; differentiable (useful for gradient-based optimization).
- **Limitations:** The specific implementation in [S1, unofficial] is complex and may not generalize to all primitives without modification. Precision issues may arise for very large or small $h$.
- **When to use:** When creating capsules, rods, or stretched spheres from basic primitives like spheres or boxes.
- **When not to use:** When high precision is required for extreme aspect ratios, or when the primitive does not support the specific symmetry transformations used in the reference.

## Background
The specific implementation of the elongation operator described here originates from the Torch-Sphere-Tracer repository [S1, unofficial]. It is designed for differentiable rendering and ray tracing, leveraging PyTorch operations for automatic differentiation. The method is part of a broader set of domain manipulation operators used to construct complex shapes from simple primitives in implicit surface rendering.
