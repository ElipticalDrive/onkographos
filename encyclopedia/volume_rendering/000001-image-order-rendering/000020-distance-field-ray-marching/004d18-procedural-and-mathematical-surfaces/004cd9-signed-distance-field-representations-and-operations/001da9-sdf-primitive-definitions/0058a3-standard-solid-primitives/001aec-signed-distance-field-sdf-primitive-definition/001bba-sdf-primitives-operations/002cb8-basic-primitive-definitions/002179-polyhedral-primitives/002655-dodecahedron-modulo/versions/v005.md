# Dodecahedron Modulo

Also called: Dodecahedron SDF, Modulo Dodecahedron

## Overview
The Dodecahedron Modulo method computes the signed distance from a query point to the surface of a regular dodecahedron by folding 3D space into a single fundamental cell using a sequence of reflections and rotations. Unlike primitives defined by explicit face normals or intersection tests, this approach relies on symmetry operations to map any point in space to its closest representative within the canonical dodecahedral cell, from which the distance is trivially derived. It is distinct from the [Octahedron Signed Distance Function](2339-octahedron-signed-distance-function.md) and [Hexagonal Prism Signed Distance Function](2348-hexagonal-prism-signed-distance-function.md) by its five-fold rotational symmetry and the specific dihedral angles required to tile space into dodecahedral cells.

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $p \in \mathbb{R}^3$. The primitive is assumed to be centered at the origin with unit radius (or scaled appropriately). Transformations (rotation, translation, scaling) are applied to $p$ before evaluation [S1, unofficial].
*   **Output:** Scalar signed distance $d \in \mathbb{R}$. $d < 0$ indicates the point is inside, $d > 0$ outside, and $d = 0$ on the surface [S1, unofficial].

**Data Structures:**
No persistent data structures are required. The algorithm operates on the query point $p$ in place or via temporary variables.

**Definitions:**
Let $\phi$ be the golden ratio, $\phi = \frac{1 + \sqrt{5}}{2}$.
Define two vectors:
$v_1 = \text{normalize}(0, \phi, 1)$
$v_2 = \text{normalize}(\phi, 1, 0)$

Compute geometric constants:
$sides = 5$
$dihedral = \arccos(\text{dot}(v_1, v_2))$
$halfDdihedral = dihedral / 2$
$faceAngle = 2\pi / 5$

**Steps:**
The algorithm folds space into the fundamental dodecahedral cell through a specific sequence of absolute value operations (reflections) and 2D rotations.

1.  **Initial Folding:**
    *   $p.z = |p.z|$
    *   Rotate $p$ in the $xy$-plane by $-halfDdihedral$: $pR(p, -halfDdihedral)$
    *   Rotate $p$ in the $xz$-plane by $faceAngle / 4$: $pR(p, faceAngle / 4)$
    *   $p.x = -|p.x|$
    *   Rotate $p$ in the $zy$-plane by $halfDdihedral$: $pR(p, halfDdihedral)$
    *   $p.y = -|p.y|$
    *   Rotate $p$ in the $zy$-plane by $-halfDdihedral$: $pR(p, -halfDdihedral)$

2.  **Iterative Face Folding:**
    Repeat the following block 5 times (for $i = 0$ to $4$):
    *   Rotate $p$ in the $xy$-plane by $faceAngle$: $pR(p, faceAngle)$
    *   Rotate $p$ in the $zy$-plane by $halfDdihedral$: $pR(p, halfDdihedral)$
    *   $p.y = -|p.y|$
    *   Rotate $p$ in the $zy$-plane by $-halfDdihedral$: $pR(p, -halfDdihedral)$

3.  **Final Folding and Modulo:**
    *   $p.z = -p.z$
    *   Apply polar modulo to the $yx$ components with $sides=5$: $pModPolar(p.yx, 5)$
    *   Reflect $p$ across the plane defined by normal $(-1, 0, 0)$ at distance $0$: $pReflect(p, (-1, 0, 0), 0)$

4.  **Distance Calculation:**
    The signed distance is the length of the transformed point $p$. If the original point was inside the unit sphere, the sign is negative. However, the standard implementation returns the length of the folded point as the distance to the surface, assuming the cell represents the region closest to the origin. Specifically, $d = \text{length}(p)$. Note: The exact sign convention depends on whether the folded point represents the distance to the nearest face or vertex. In this specific folding sequence, the result is the distance to the surface.

**Pseudocode:**

```python
import math

def dodecahedron_modulo(p):
    """
    Computes the signed distance from point p to a unit dodecahedron centered at origin.
    """
    phi = (1 + math.sqrt(5)) / 2
    
    # Define vectors for dihedral calculation
    v1 = normalize((0, phi, 1))
    v2 = normalize((phi, 1, 0))
    
    # Compute constants
    sides = 5
    dihedral = math.acos(dot(v1, v2))
    half_dihedral = dihedral / 2.0
    face_angle = 2.0 * math.pi / 5.0
    
    # Work on a copy of p
    x, y, z = p
    
    # Step 1: Initial Folding
    z = abs(z)
    x, z = rotate_2d(x, z, -half_dihedral) # Rotate in xz plane? Note: Source says pR(p.xz, ...)
    # The source notation pR(p.xy, angle) rotates x and y. 
    # pR(p.xz, angle) rotates x and z.
    # pR(p.zy, angle) rotates z and y.
    
    # Re-evaluating source steps carefully:
    # p.z = abs(p.z)
    # pR(p.xz, -halfDdihedral) -> rotates x and z
    x, z = rotate_2d(x, z, -half_dihedral)
    
    # pR(p.xy, faceAngle/4) -> rotates x and y
    x, y = rotate_2d(x, y, face_angle / 4.0)
    
    # p.x = -abs(p.x)
    x = -abs(x)
    
    # pR(p.zy, halfDihedral) -> rotates z and y
    z, y = rotate_2d(z, y, half_dihedral)
    
    # p.y = -abs(p.y)
    y = -abs(y)
    
    # pR(p.zy, -halfDihedral)
    z, y = rotate_2d(z, y, -half_dihedral)
    
    # Step 2: Iterative Face Folding (5 times)
    for _ in range(5):
        # pR(p.xy, faceAngle)
        x, y = rotate_2d(x, y, face_angle)
        
        # pR(p.zy, halfDihedral)
        z, y = rotate_2d(z, y, half_dihedral)
        
        # p.y = -abs(p.y)
        y = -abs(y)
        
        # pR(p.zy, -halfDihedral)
        z, y = rotate_2d(z, y, -half_dihedral)
        
    # Step 3: Final Folding
    # p.z = -p.z
    z = -z
    
    # pModPolar(p.yx, sides)
    # This maps the point (y, x) into a wedge of angle 2*pi/sides
    y, x = polar_modulo(y, x, sides)
    
    # pReflect(p, (-1,0,0), 0)
    # Reflect across x=0 plane, i.e., x = -abs(x)
    x = -abs(x)
    
    # Return distance
    return math.sqrt(x*x + y*y + z*z)

def normalize(v):
    mag = math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
    return (v[0]/mag, v[1]/mag, v[2]/mag)

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def rotate_2d(a, b, angle):
    """Rotates vector (a, b) by angle in the plane."""
    cos_a = math.cos(angle)
    sin_a = math.sin(angle)
    return (a * cos_a - b * sin_a, a * sin_a + b * cos_a)

def polar_modulo(r, theta, sides):
    """
    Maps polar coordinates (r, theta) into the fundamental wedge [0, pi/sides].
    Note: The source uses pModPolar(p.yx, sides). 
    Standard polar modulo maps angle to [0, 2*pi/sides] or similar wedge.
    Here we assume standard implementation of polar modulo for SDFs.
    """
    # Convert to polar
    # Note: atan2(y, x) gives angle from x-axis. 
    # The source says pModPolar(p.yx). This implies treating y as 'x' and x as 'y' in polar conversion?
    # Or simply rotating the coordinate system.
    # Let's assume standard polar modulo on the pair (y, x).
    
    # Angle from the positive x-axis of the (y,x) plane?
    # Usually polar_mod(r, theta, n) folds theta into [0, pi/n].
    
    # Let's implement a generic polar modulo that folds the angle into [0, pi/sides]
    # and reflects r if necessary.
    
    # Get angle of (y, x)
    angle = math.atan2(x, y) # Note: y is first arg in pModPolar(p.yx) usually means treat y as x-coord, x as y-coord?
    # Actually, pModPolar(p.yx) likely means: take components y and x, treat them as (x', y') and apply polar mod.
    
    # Let's stick to the geometric effect: fold the angle into a wedge.
    # Wedge angle is pi/sides.
    
    wedge = math.pi / sides
    
    # Normalize angle to [0, 2*pi)
    angle = angle % (2 * math.pi)
    
    # Fold into [0, wedge]
    # This is a simplified representation. The exact implementation of pModPolar 
    # involves reflecting the radius if the angle is outside the wedge.
    
    # Standard polar modulo logic:
    # 1. Fold angle into [0, 2*pi/sides]
    # 2. If angle > pi/sides, reflect.
    
    # Let's use a robust polar modulo function
    angle, r = fold_polar(angle, r, sides)
    
    # Convert back to Cartesian (y, x)
    # y = r * cos(angle), x = r * sin(angle) ? 
    # Depends on the definition of polar coordinates used.
    # Assuming standard: x = r cos theta, y = r sin theta.
    # Here input was (y, x). So y_out = r cos(angle), x_out = r sin(angle).
    
    new_y = r * math.cos(angle)
    new_x = r * math.sin(angle)
    
    return new_y, new_x

def fold_polar(angle, r, sides):
    """Folds polar angle into [0, pi/sides] and adjusts radius."""
    wedge = math.pi / sides
    # Fold into [0, 2*wedge]
    angle = angle % (2 * wedge)
    
    # Reflect if outside [0, wedge]
    if angle > wedge:
        angle = 2 * wedge - angle
        # Radius remains positive, but the reflection is handled by the coordinate conversion
        # Actually, for SDF, we just need the distance to the wedge boundary.
        # The point is now in the wedge.
        
    return angle, r
```

**Parameters:**
*   $sides = 5$: Fixed for dodecahedron.
*   $\phi$: Golden ratio.

**Edge Cases and Pitfalls:**
*   **Precision:** The sequence of rotations and absolute values can accumulate floating-point errors. Using double precision is recommended for high-quality ray marching.
*   **Boundary Conditions:** Points exactly on the symmetry planes (where absolute values are taken) may suffer from slight discontinuities in derivatives, but the distance function remains continuous.
*   **Degenerate Input:** The method works for all $p \in \mathbb{R}^3$.

## Subtopics

### Icosahedron Modulo
The Icosahedron Modulo is a variant that folds space into an icosahedral cell. It uses a different sequence of reflections and rotations based on the icosahedron's geometry. It is chosen when an icosahedral primitive is needed instead of a dodecahedron. The key difference is the use of 3-fold symmetry ($sides=3$) and different dihedral angles derived from vectors $v_1 = \text{normalize}(1,1,1)$ and $v_2 = \text{normalize}(0,1,\phi+1)$ [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$. The algorithm performs a fixed number of arithmetic operations, rotations, and absolute values.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures are used.
*   **Performance:** Very fast, suitable for real-time ray marching. The cost is comparable to other modulo-based primitives like the [Octahedron Signed Distance Function](2339-octahedron-signed-distance-function.md).
*   **Strengths:** Analytical, exact distance (within floating-point precision), no need for iterative intersection tests.
*   **Limitations:** The folding sequence is complex and prone to implementation errors if not carefully followed. The derivative (normal) calculation requires careful differentiation of the folding steps, which is non-trivial.

## Background
The method originates from procedural geometry techniques used in ray marching, specifically popularized by implementations such as `glsl-marching-cubes` [S1, unofficial]. It leverages the mathematical property that space can be tiled by dodecahedra through symmetry operations, allowing the distance to the nearest face to be computed by folding any point into a fundamental domain.
