# Sphere Signed Distance Function

Also called: SDF Primitive: Sphere, SDF Sphere, SDF Sphere Primitive, Signed Distance Field (SDF) Sphere, Signed Distance Function (SDF) Sphere, Sphere SDF, Sphere SDF Primitive

## Overview
The Sphere Signed Distance Function computes the exact Euclidean distance from a query point to the surface of a sphere, returning a signed scalar where negative values indicate the interior, positive values the exterior, and zero the surface [S1, S2, S3, S4, S5, S6, S7, S8, S9, S10, S11, S12, S13, S14, S15, S16, S17, S18, S19, unofficial][S20][S21, S22, unofficial]. It serves as the fundamental 3D building block for distance-field ray marching, enabling efficient step-size estimation [S1, S11, S16, S18, unofficial]. Unlike the [Circle Signed Distance Function](2942-circle-signed-distance-function.md), which operates in 2D, this primitive defines a volumetric boundary in 3D space [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $p \in \mathbb{R}^3$ (in world or local coordinates depending on transformation context), a sphere center $c \in \mathbb{R}^3$, and a sphere radius $r \in \mathbb{R}^+$.
*   **Output:** A scalar signed distance $d \in \mathbb{R}$.

**Data Structures:**
The sphere is typically defined by its center and radius. In some implementations, these parameters are learnable (e.g., in neural implicit representations) [S4, S5, S6, unofficial].
*   **Center ($c$):** A 3D vector. Default is often $(0,0,0)$ [S10, S11, S13, unofficial].
*   **Radius ($r$):** A scalar. Default is often $1.0$ or $0.5$ [S10, S11, S13, unofficial].
*   **Transformation:** If the sphere is not centered at the origin, the query point $p$ is transformed into the sphere's local space using the inverse of the sphere's transformation matrix $M$ before evaluation, or the center $c$ is explicitly provided [S8, unofficial][S20].
*   **Memory Layout:** In some C++ implementations, a sphere struct may contain a $4 \times 4$ transformation matrix (64 bytes), a radius (4 bytes), and padding (12 bytes), totaling 80 bytes with 16-byte alignment [S8, unofficial]. In other data structures (e.g., SDF operation blocks), the radius may be stored in a specific float slot (e.g., `floats[0]`) [S12, unofficial].

**Formula:**
The signed distance $d$ is calculated as the length of the vector from the center to the point, minus the radius [S1, S2, S3, S4, S5, S6, S7, S9, S11, S12, S13, S14, S16, S18, S19, unofficial]:

$$ d(p) = \| p - c \| - r $$

Where:
*   $\| \cdot \|$ denotes the Euclidean norm (L2 norm).
*   $p$ is the query point.
*   $c$ is the sphere center.
*   $r$ is the sphere radius.

If the sphere is centered at the origin ($c = 0$), the formula simplifies to [S1, S7, S9, S11, S12, S13, S14, S16, S19, unofficial]:

$$ d(p) = \| p \| - r $$

**Gradient (Normal):**
The function is differentiable almost everywhere. The gradient $\nabla d$ provides the surface normal $n$ [S1, S13, S18, unofficial]:

$$ n = \nabla d = \frac{p - c}{\| p - c \|} $$

Note: At the center ($p=c$), the gradient is undefined [G].

**Pseudocode:**
```python
import math

def sphere_sdf(p, c, r):
    """
    Computes the signed distance from point p to a sphere with center c and radius r.
    
    Args:
        p: tuple or list of 3 floats (x, y, z) representing the query point.
        c: tuple or list of 3 floats (cx, cy, cz) representing the sphere center.
        r: float representing the sphere radius.
        
    Returns:
        float: Signed distance. Negative if inside, positive if outside, zero on surface.
    """
    # Calculate vector from center to point
    dx = p[0] - c[0]
    dy = p[1] - c[1]
    dz = p[2] - c[2]
    
    # Calculate Euclidean distance from center to point
    dist_to_center = math.sqrt(dx*dx + dy*dy + dz*dz)
    
    # Subtract radius to get signed distance
    return dist_to_center - r

def sphere_sdf_origin(p, r):
    """
    Optimized version for sphere centered at origin (0,0,0).
    """
    dist_to_center = math.sqrt(p[0]**2 + p[1]**2 + p[2]**2)
    return dist_to_center - r
```

**Parameters:**
*   **Radius ($r$):** Must be positive. Typical values range from small primitives to scene-scale objects. In some examples, $r=0.5$ or $r=1.0$ [S11, S13, unofficial].
*   **Center ($c$):** Default $(0,0,0)$ [S10, S11, S13, unofficial]. Can be learnable in optimization contexts [S4, S5, S6, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** When $p$ is very close to $c$, $\| p - c \|$ approaches zero. Subtracting $r$ is stable, but computing the gradient at $p=c$ results in division by zero [G].
*   **Transformation Order:** When using transformation matrices, ensure the point is transformed by the inverse matrix (or the center is transformed by the forward matrix) before applying the SDF [S8, unofficial][S20].
*   **Definition Order:** In some scripting languages (e.g., Fennel/Lua), the SDF function must be defined before the object constructor that uses it [S22, unofficial].

## Subtopics

### Distance Estimator
A distance estimator in this context refers to the use of the sphere SDF to determine the minimum distance to any object in a scene, often returning both the distance and the identifier/color of the closest object to avoid redundant lookups [S22, unofficial]. It initializes a minimum distance (e.g., `DRAW-DISTANCE` = 1000) and updates it if the sphere's SDF returns a smaller distance [S22, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
*   **Time:** $O(1)$ per query. The calculation involves a few subtractions, multiplications, and a square root [S1, S7, S13, unofficial].
*   **Memory:** $O(1)$. Only the center and radius need to be stored [S8, S12, unofficial].

**Measured Performance:**
The sphere SDF is one of the fastest primitives to evaluate due to its simplicity [S11, unofficial]. It is widely used in real-time ray marching shaders [S7, S13, S16, S17, S19, unofficial].

**Scaling:**
The function scales linearly with the radius. Transformations (translation, rotation, scale) are handled by transforming the query point $p$ into the local space of the sphere [S8, unofficial][S20].

**Strengths and Limitations:**
*   **Strengths:** Exact distance calculation, differentiable, simple to implement, efficient [S1, S11, S16, unofficial].
*   **Limitations:** Only represents a sphere. For complex scenes, it must be combined with other primitives using CSG operations (union, intersection, difference) [S18, unofficial].

**When to Use:**
Use when rendering spherical objects or when a sphere is a component of a more complex SDF scene [S1, S11, S16, unofficial].

**When Not to Use:**
Do not use if the object is not spherical or if an approximate distance is sufficient and a simpler function (e.g., box) is preferred for performance in specific contexts (though sphere SDF is already very fast) [G].

## Background
The Sphere Signed Distance Function is a fundamental primitive in the field of Signed Distance Fields (SDFs) and ray marching. It was popularized by Inigo Quilez in his articles on distance functions [S1, S11, S16, S17, unofficial]. The concept of sphere tracing, which uses the SDF to step along a ray, was introduced by John C. Hart in 1996 [S20]. The function is used in various applications including real-time rendering [S7, S13, S16, S17, S19, unofficial], neural implicit representations [S4, S5, S6, unofficial], and dual contouring [S21, unofficial].
