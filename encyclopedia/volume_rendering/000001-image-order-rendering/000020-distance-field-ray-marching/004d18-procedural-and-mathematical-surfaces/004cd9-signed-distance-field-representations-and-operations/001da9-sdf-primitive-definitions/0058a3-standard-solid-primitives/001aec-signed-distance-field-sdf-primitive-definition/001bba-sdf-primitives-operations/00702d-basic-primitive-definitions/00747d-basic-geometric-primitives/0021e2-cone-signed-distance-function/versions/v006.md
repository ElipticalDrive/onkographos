# Cone Signed Distance Function

Also called: Cone SDF, Exact Cone SDF, Signed Capped Cone, Signed Cone, Signed Distance Function (SDF) for Cone, sdCone

## Overview
The Cone Signed Distance Function computes the exact Euclidean distance from a query point $p$ to the surface of a capped cone, defined by its base radius $r$, height $h$, and orientation. It solves the problem of efficiently determining spatial containment and proximity for ray marching or collision detection against conical geometry. Unlike linear approximations, this method provides the true signed distance, ensuring safe step sizes in ray marching [S5, unofficial]. It is distinct from the infinite cone SDF, which lacks base and tip caps, and from the cylinder, which has parallel sides [S3, S5, unofficial].

## How it works
**Inputs:**
*   $p$: Query point in 3D space ($vec3$).
*   $r$: Base radius of the cone ($float$).
*   $h$: Height of the cone ($float$).

**Coordinate System:**
The implementation assumes the cone is aligned with the Y-axis. The apex (tip) is located at the origin $(0, 0, 0)$. The base is centered at $(0, -h, 0)$ with radius $r$. The cone opens downward along the negative Y-axis [S5, unofficial].

**Data Structures:**
No complex data structures are required. The computation relies on 2D vector projections in the radial-vertical plane.

**Algorithm:**
1.  **Radial Projection:** Project the 3D point $p$ into a 2D plane containing the cone's axis of symmetry. Let $q$ be a 2D vector where the x-component is the radial distance from the Y-axis and the y-component is the height along the Y-axis:
    $$ q = (\sqrt{p_x^2 + p_z^2}, p_y) $$
    [S2, S5, unofficial]

2.  **Define Geometry in 2D:**
    Define the tip and base points in this 2D cross-section:
    $$ \text{tip} = (0, 0) $$
    $$ \text{base} = (r, -h) $$
    [S5, unofficial]

3.  **Compute Distances:**
    Calculate the distance to the side slope (mantle) and the distance to the base cap.

    *   **Side Distance:** The shortest distance from $q$ to the line segment connecting $\text{tip}$ and $\text{base}$.
        Let $ba = \text{base} - \text{tip}$.
        Let $d_1 = q - \text{tip}$.
        Compute the projection parameter $u$ of $d_1$ onto $ba$:
        $$ u = \text{clamp}\left(\frac{d_1 \cdot ba}{ba \cdot ba}, 0.0, 1.0\right) $$
        The squared length of $ba$ is $m_2 = r^2 + h^2$.
        The closest point on the segment is $p_{seg} = \text{tip} + ba \cdot u$.
        The side distance is:
        $$ \text{side\_dist} = \| q - p_{seg} \| $$
        [S5, unofficial]

    *   **Base Cap Distance:** The distance from $q$ to the base disk. The base disk lies in the plane $y = -h$ with radius $r$.
        Clamp the radial component of $q$ to the base radius to find the closest point on the disk boundary if outside, or the projection if inside.
        Let $q_{base} = (\text{clamp}(q_x, 0.0, r), -h)$.
        $$ \text{cap\_dist} = \| q - q_{base} \| $$
        [S5, unofficial]

    *   **Unsigned Distance:**
        $$ \text{dist} = \min(\text{side\_dist}, \text{cap\_dist}) $$
        [S5, unofficial]

4.  **Sign Determination (Inside Test):**
    Determine if the point $p$ is inside the cone volume. A point is inside if its height $q_y$ is between the tip and base ($-h \le q_y \le 0$) and it lies "below" the slope line connecting the tip and base.
    The condition for being inside is:
    $$ \text{inside} = (q_y \le 0.0) \land (q_y \ge -h) \land (q_x \cdot h + q_y \cdot r \le 0.0) $$
    [S5, unofficial]
    *Note: The term $q_x \cdot h + q_y \cdot r \le 0.0$ checks if the point is on the inner side of the line segment from $(0,0)$ to $(r,-h)$. The line equation is $y = -\frac{h}{r}x \implies hx + ry = 0$. For points inside (closer to axis), the value is negative.*

5.  **Return Result:**
    $$ \text{result} = \begin{cases} -\text{dist} & \text{if inside} \\ \text{dist} & \text{if outside} \end{cases} $$
    [S5, unofficial]

**Pseudocode:**
```python
import math

def sd_cone(p: tuple, r: float, h: float) -> float:
    """
    Computes the signed distance from point p to a capped cone.
    Cone apex at (0,0,0), base center at (0,-h,0), radius r.
    Opens downward along -Y.
    """
    # 1. Radial projection
    rad = math.sqrt(p[0]**2 + p[2]**2)
    q = (rad, p[1])
    
    # 2. Define 2D geometry
    tip = (0.0, 0.0)
    base = (r, -h)
    
    # 3. Side distance calculation
    # Vector from tip to base
    ba = (base[0] - tip[0], base[1] - tip[1])
    # Vector from tip to q
    d1 = (q[0] - tip[0], q[1] - tip[1])
    
    # Squared length of ba
    m2 = ba[0]**2 + ba[1]**2
    
    # Projection parameter u
    if m2 == 0:
        u = 0.0
    else:
        u = (d1[0]*ba[0] + d1[1]*ba[1]) / m2
    
    # Clamp u to segment
    u = max(0.0, min(1.0, u))
    
    # Closest point on segment
    closest_side_x = tip[0] + ba[0] * u
    closest_side_y = tip[1] + ba[1] * u
    
    side_dist = math.sqrt((q[0] - closest_side_x)**2 + (q[1] - closest_side_y)**2)
    
    # 4. Base cap distance calculation
    # Clamp radial component to radius r
    q_base_x = max(0.0, min(r, q[0]))
    q_base_y = -h
    
    cap_dist = math.sqrt((q[0] - q_base_x)**2 + (q[1] - q_base_y)**2)
    
    # 5. Unsigned distance
    dist = min(side_dist, cap_dist)
    
    # 6. Inside test
    # q.y <= 0 (below tip) AND q.y >= -h (above base) AND inside slope
    # Slope line: y = -(h/r)x => hx + ry = 0. Inside is hx + ry <= 0
    inside = (q[1] <= 0.0) and (q[1] >= -h) and ((q[0] * h + q[1] * r) <= 0.0)
    
    if inside:
        return -dist
    else:
        return dist
```

**Edge Cases and Pitfalls:**
*   **Degenerate Cone:** If $r=0$ or $h=0$, the cone degenerates to a line segment or a disk. The formula for $m_2$ becomes 0, requiring a guard clause to avoid division by zero [S5, G, unofficial].
*   **Precision:** The inside test relies on floating-point comparisons. Points very close to the surface may flip signs due to precision errors. Using a small epsilon for the inside test boundary can help stabilize shading normals [G].
*   **Axis Alignment:** This specific implementation assumes the cone is aligned with the Y-axis. For arbitrary orientations, the point $p$ must be transformed into the cone's local coordinate system before applying the function [S5, G, unofficial].

## Subtopics

### Infinite Cone SDF
Computes distance to an unbounded cone. Simpler formula but does not account for base or tip caps. Use when the cone is part of a larger structure where caps are handled by other primitives or when the cone extends to infinity [S3, unofficial].

### Capped Cylinder SDF
A cylinder with flat caps. Use for shapes with constant radius. The cone SDF is a generalization where the radius varies linearly with height [S3, S5, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$. The computation involves a constant number of arithmetic operations, square roots, and comparisons.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures are needed.
*   **Strengths:** Provides exact distances, ensuring robust ray marching without overshooting. Differentiable almost everywhere, allowing for accurate normal computation via gradient $\nabla d$ [Parent].
*   **Limitations:** The closed-form solution is more complex than simple primitives like spheres or boxes. The inside test logic is specific to the capped geometry and must be implemented carefully to avoid sign errors [S5, unofficial].
*   **When to use:** When rendering or simulating conical objects (e.g., funnels, horns, certain architectural elements) where exact distance is required for correct marching steps or collision response.
*   **When not to use:** If the cone is infinite or if approximate distance is sufficient and performance is critical, a simpler approximation or infinite cone SDF might be preferred [S3, unofficial].

## Background
The exact signed distance function for a cone was popularized by Inigo Quilez in his article on distance functions for ray tracing [S1, S5, unofficial]. The derivation involves projecting the 3D point onto the 2D plane containing the cone's axis and computing the distance to the line segment representing the cone's profile in that plane. This method is widely used in ray marching shaders and implicit surface rendering [S2, S3, S5, unofficial].
