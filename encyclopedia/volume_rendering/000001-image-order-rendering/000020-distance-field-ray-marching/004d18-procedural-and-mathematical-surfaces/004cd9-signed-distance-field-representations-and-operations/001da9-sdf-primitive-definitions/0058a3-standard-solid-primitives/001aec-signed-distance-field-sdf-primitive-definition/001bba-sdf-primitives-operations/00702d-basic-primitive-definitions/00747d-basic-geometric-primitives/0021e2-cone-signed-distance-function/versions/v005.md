# Cone Signed Distance Function

Also called: Cone SDF, Exact Cone SDF, Signed Capped Cone, Signed Cone, Signed Distance Function (SDF) for Cone, sdCone

## Overview
The Cone Signed Distance Function computes the exact Euclidean distance from a query point to the surface of a cone, defined by a base radius and height, with a sign indicating whether the point lies inside or outside the volume [S1, S2, S4, unofficial]. The method evaluates the distance to a cone aligned with the Y-axis [S2, unofficial]. Two primary implementations exist in the literature: an exact geometric projection method that handles the base cap and side slope separately, and a simplified dot-product method often used for infinite or specific capped variants where the base cap is handled implicitly or the cone is defined by a slope vector [S2, unofficial][S3, unofficial].

## How it works
The computation operates on scalar values and 2D/3D vectors [S4, unofficial].

### Inputs and Outputs
*   **Input:** Query point $p \in \mathbb{R}^3$.
*   **Parameters:** Base radius $r$, height $h$.
*   **Output:** Signed distance $d \in \mathbb{R}$.

### Data Structures
No complex data structures are required [S4, unofficial].

### Steps (Exact Capped Cone)
This implementation, derived from Inigo Quilez's work and implemented in Rust [S4, unofficial], computes the distance to the side slope and the base cap independently, then combines them.

1.  **Canonical Projection:** Project the 3D point $p$ into a 2D cross-section $q$ in the plane containing the cone's axis (Y-axis) and the radial distance [S4, unofficial].
    $$ q = (\sqrt{p_x^2 + p_z^2}, p_y) $$
    Let $q_x = \sqrt{p_x^2 + p_z^2}$ and $q_y = p_y$ [S4, unofficial].

2.  **Define Geometry:** Define the tip and base vertices in this 2D space [S4, unofficial].
    *   Tip: $t = (0, 0)$ [S4, unofficial].
    *   Base: $b = (r, -h)$ [S4, unofficial].
    *   Vector along the side slope: $ba = b - t = (r, -h)$ [S4, unofficial].

3.  **Distance to Side Slope:** Compute the distance from $q$ to the line segment connecting the tip and the base edge [S4, unofficial].
    *   Vector from tip to query: $d_1 = q - t = q$ [S4, unofficial].
    *   Squared length of side slope: $m_2 = \|ba\|^2 = r^2 + h^2$ [S4, unofficial].
    *   Projection parameter $u$ (clamped to segment):
        $$ u = \text{clamp}\left(\frac{d_1 \cdot ba}{m_2}, 0, 1\right) $$
    *   Closest point on segment: $c_{side} = t + ba \cdot u$ [G].
    *   Side distance: $dist_{side} = \|q - c_{side}\|$ [S4, unofficial].

4.  **Distance to Base Cap:** Compute the distance from $q$ to the base disk [S4, unofficial].
    *   Clamp the radial component of $q$ to the base radius to find the closest point on the infinite plane of the base, then check if it's within the disk [S4, unofficial].
    *   Closest point on base plane within radius: $c_{cap} = (\text{clamp}(q_x, 0, r), -h)$ [S4, unofficial].
    *   Vector from $q$ to this point: $d_3 = q - c_{cap}$ [S4, unofficial].
    *   Cap distance: $dist_{cap} = \|d_3\|$ [S4, unofficial].

5.  **Combine Distances:** The unsigned distance is the minimum of the side and cap distances [S4, unofficial].
    $$ dist = \min(dist_{side}, dist_{cap}) $$

6.  **Inside Test:** Determine if the point is inside the cone [S4, unofficial]. A point is inside if it is below the apex ($q_y \le 0$), above the base ($q_y \ge -h$), and radially within the cone's slope [S4, unofficial]. The slope condition is derived from the line equation passing through $(0,0)$ and $(r, -h)$: $x \cdot h + y \cdot r = 0$ (checking sign) [S4, unofficial].
    $$ inside = (q_y \le 0) \land (q_y \ge -h) \land (q_x \cdot h + q_y \cdot r \le 0) $$

7.  **Return Signed Distance:**
    $$ d = \begin{cases} -dist & \text{if } inside \\ dist & \text{otherwise} \end{cases} $$

### Steps (Simplified/Dot-Product Variant)
Some implementations [S2, unofficial][S3, unofficial] use a normalized vector $c$ to define the cone's orientation and slope, often treating it as an infinite cone or handling caps differently [S3, unofficial].

1.  **Projection:** $q = (\|p_{xz}\|, p_y)$ [S3, unofficial].
2.  **Vector Definition:** Let $c$ be a normalized 2D vector $(c_x, c_z)$ representing the cone's axis and slope [S3, unofficial].
3.  **Distance Calculation:**
    $$ d_1 = -p_y - c_z $$
    $$ d_2 = \max(q \cdot c_{xy}, p_y) $$
    $$ d = \| \max((d_1, d_2), 0) \| + \min(\max(d_1, d_2), 0) $$

### Pseudocode (Exact Capped Cone)
```python
import math

def sd_cone(p: tuple, r: float, h: float) -> float:
    """
    Computes the signed distance to a capped cone.
    Cone apex at (0,0,0), base center at (0, -h, 0), base radius r.
    Axis aligned with Y.
    """
    # 1. Project to 2D cross-section
    qx = math.sqrt(p[0]**2 + p[2]**2)
    qy = p[1]
    
    # 2. Define 2D points
    # Tip at (0, 0), Base edge at (r, -h)
    tip_x, tip_y = 0.0, 0.0
    base_x, base_y = r, -h
    
    # 3. Distance to side slope segment
    # Vector ba from tip to base
    ba_x = base_x - tip_x
    ba_y = base_y - tip_y
    m2 = ba_x**2 + ba_y**2
    
    # Guard against division by zero for degenerate cones [G]
    if m2 == 0.0:
        return math.sqrt(qx**2 + qy**2)
    
    # Vector d1 from tip to q
    d1_x = qx - tip_x
    d1_y = qy - tip_y
    
    # Projection u
    u = (d1_x * ba_x + d1_y * ba_y) / m2
    u = max(0.0, min(1.0, u))
    
    # Closest point on segment
    closest_x = tip_x + u * ba_x
    closest_y = tip_y + u * ba_y
    
    dist_side = math.sqrt((qx - closest_x)**2 + (qy - closest_y)**2)
    
    # 4. Distance to base cap
    # Clamp qx to [0, r] to find closest point on the base disk
    clamped_qx = max(0.0, min(r, qx))
    cap_closest_x = clamped_qx
    cap_closest_y = base_y
    
    dist_cap = math.sqrt((qx - cap_closest_x)**2 + (qy - cap_closest_y)**2)
    
    # 5. Minimum unsigned distance
    dist = min(dist_side, dist_cap)
    
    # 6. Inside test
    # Inside if: below apex (qy <= 0), above base (qy >= -h),
    # and inside the slope (qx * h + qy * r <= 0)
    inside = (qy <= 0.0) and (qy >= -h) and ((qx * h + qy * r) <= 0.0)
    
    # 7. Return signed distance
    if inside:
        return -dist
    else:
        return dist
```

### Parameters
*   $r$: Base radius. Typical values depend on scene scale [S4, unofficial].
*   $h$: Height of the cone [S4, unofficial].

### Edge Cases and Pitfalls
*   **Degenerate Cone:** If $r=0$ or $h=0$, the cone degenerates to a line segment or a disk [S4, unofficial]. The formula may produce NaNs or incorrect distances if not guarded [S4, unofficial]. The implementation handles $r=0$ implicitly via the clamp, but $h=0$ results in a flat disk where the "side" distance logic might fail if not careful with division by zero in $m_2$ if $r=h=0$ [S4, unofficial].
*   **Precision:** The inside test relies on floating-point comparisons [S4, unofficial]. Points very close to the surface may oscillate between inside and outside due to precision errors [G]. It is often safer to use a small epsilon for the inside test boundary checks in ray marching to avoid z-fighting or incorrect shading [G].
*   **Axis Alignment:** The standard implementation assumes the cone is aligned with the Y-axis [S2, unofficial]. For arbitrary orientations, the point $p$ must be transformed into the cone's local space using the inverse of the cone's transformation matrix before evaluation [Parent].

## Operating characteristics
*   **Time Complexity:** $O(1)$ [S4, unofficial]. The computation involves a fixed number of arithmetic operations, square roots, and comparisons [S4, unofficial].
*   **Memory Complexity:** $O(1)$ [S4, unofficial]. No auxiliary data structures are needed [S4, unofficial].
*   **Measured performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Exact distance calculation allows for large step sizes in ray marching, improving performance [G]. Smooth gradients (except at the base edge and apex) allow for accurate normal computation [G].
*   **Limitations:** The function is not differentiable at the base edge (where the side slope meets the base cap) and at the apex [G]. This can cause artifacts in normal-based shading or physics if not handled [G].
*   **When to use:** When rendering conical objects with high precision is required, or when using the SDF for collision detection where exact boundaries matter [G].
*   **When not to use:** If the cone is part of a complex mesh where polygonal approximation is sufficient and faster, or if the cone is extremely long and thin, where precision issues might arise [G].

## Background
The exact signed distance function for a cone was popularized by Inigo Quilez in his article on distance functions [S1, S4, unofficial]. The geometric derivation relies on projecting the 3D point onto the 2D plane containing the cone's axis and computing the distance to the line segment representing the cone's profile [S4, unofficial].
