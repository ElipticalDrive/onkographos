# Signed Distance Field (SDF) Primitive Definition

Also called: SDF Function, SDF Shapes, Signed Distance Field (SDF), Signed Distance Function (SDF), Signed Distance Function Primitives

## Overview
A Signed Distance Field (SDF) Primitive Definition is a method for representing geometric surfaces as analytical scalar fields where the value at any point $\mathbf{p}$ is the signed Euclidean distance to the nearest surface [S2, S15, unofficial]. It solves the problem of defining explicit geometry for ray marching by providing a conservative lower bound on the distance to the surface, ensuring that sphere tracing steps do not overshoot or tunnel through geometry [S8, S15, unofficial]. Unlike [Distance to Natural Quadrics](1559-distance-to-natural-quadrics.md) which focuses on specific conic sections, or [Constructive SDF Modeling](871-constructive-sdf-modeling-min-combination.md) which focuses on composition logic, this method provides the foundational closed-form distance metrics for canonical shapes (spheres, boxes, planes, etc.) [S1, S6, unofficial].

## How it works

### Inputs and Outputs
*   **Input**: A query point $\mathbf{p} \in \mathbb{R}^3$ (or $\mathbb{R}^2$ for 2D primitives) and primitive-specific parameters (e.g., radius, center, normal, half-extents) [S6, S13, unofficial].
*   **Output**: A scalar float $d$ representing the signed distance.
    *   $d > 0$: Point is outside the surface.
    *   $d = 0$: Point is on the surface.
    *   $d < 0$: Point is inside the surface [S2, S15, unofficial].

### Data Structures
Primitives are typically defined by simple structs or parameter sets. Common layouts include [S14, unofficial]:
*   **Sphere**: `struct sph { float r; vec3 c; }` where `r` is radius, `c` is center.
*   **Box**: `struct box { vec3 p; vec3 size; }` where `p` is position, `size` is full extent (halved in calculation).
*   **Plane**: `struct plane { vec4 k; }` where `k.xyz` is the normal vector $\mathbf{n}$, `k.w` is the offset $d_{offset}$.
*   **Cylinder**: `struct cylinder { vec2 p; float r; }` (infinite) or `struct cylinderCapped { float r; float h; }` (capped, `h` is half-height).
*   **Torus**: `struct tor { float inR; float outR; }` where `inR` is tube radius, `outR` is major radius.

### Formulas and Steps
The general form for a primitive centered at the origin is $f(\mathbf{p})$. For primitives with a center $\mathbf{c}$, the input is transformed to $\mathbf{p}' = \mathbf{p} - \mathbf{c}$ [S2, S11, unofficial].

1.  **Sphere**:
    $$ d(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r $$
    Where $\|\cdot\|$ is the Euclidean norm (length) [S3, S11, unofficial].

2.  **Box (Exact)**:
    Let $\mathbf{b}$ be the half-extents.
    $$ \mathbf{d} = |\mathbf{p} - \mathbf{p}_{box}| - \mathbf{b} $$
    $$ d = \|\max(\mathbf{d}, \mathbf{0})\| + \min(\max(\mathbf{d}_x, \max(\mathbf{d}_y, \mathbf{d}_z)), 0) $$
    This computes the exact distance to the corners and edges [S6, S14, unofficial].
    *   *Cheap Box (Overestimate)*: $d = \max(|\mathbf{p} - \mathbf{p}_{box}| - \mathbf{b})$. This is faster but not a true SDF (Lipschitz constant may exceed 1) [S6, unofficial].

3.  **Plane**:
    $$ d(\mathbf{p}) = \mathbf{p} \cdot \mathbf{n} + d_{offset} $$
    Where $\mathbf{n}$ is the normalized normal vector [S6, S14, unofficial].

4.  **Cylinder (Infinite, along Y)**:
    $$ d(\mathbf{p}) = \|\mathbf{p}_{xz} - \mathbf{p}_{center}\| - r $$
    Where $\mathbf{p}_{xz} = (p_x, 0, p_z)$ [S14, unofficial].

5.  **Cylinder (Capped)**:
    $$ d_x = \|\mathbf{p}_{xz} - \mathbf{p}_{center}\| - r $$
    $$ d_y = |p_y| - h $$
    $$ d = \min(\max(d_x, d_y), 0) + \|\max(d_x, d_y, 0)\| $$
    Where $h$ is the half-height [S14, unofficial].

6.  **Torus**:
    Let $\mathbf{p}_{xz} = (p_x, 0, p_z)$.
    $$ \mathbf{q} = (\|\mathbf{p}_{xz}\| - R_{out}, p_y) $$
    $$ d = \|\mathbf{q}\| - R_{in} $$
    Where $R_{out}$ is the major radius and $R_{in}$ is the tube (minor) radius [S6, S14, unofficial].

7.  **Cone**:
    Let $\mathbf{q} = (\|\mathbf{p}_{xz}\|, p_y)$.
    Let $\phi = \arctan(r/h)$.
    $$ d = \max(\|\mathbf{q}\|\cos(\phi) - |p_y|\sin(\phi), \max(p_y - h, -p_y)) $$
    *Note: Exact cone SDFs require handling tip and base ring distances specifically. A robust implementation checks projection against the mantle [S13, S14, unofficial].*

8.  **Capsule**:
    Defined by endpoints $\mathbf{a}, \mathbf{b}$ and radius $r$.
    $$ d(\mathbf{p}) = \text{distance}(\mathbf{p}, \text{segment } \mathbf{a}\mathbf{b}) - r $$
    The distance to a segment is computed by projecting $\mathbf{p}$ onto the line segment and clamping the parameter $t$ to $[0, 1]$ [S13, unofficial].

9.  **Generalized Distance Function (GDF)**:
    For complex polyhedra (e.g., Icosahedron, Dodecahedron), a set of normalized vectors $\mathbf{v}_i$ is used.
    $$ d(\mathbf{p}) = \left( \sum_{i} |\mathbf{p} \cdot \mathbf{v}_i|^e \right)^{1/e} - r $$
    For sharp edges, $e \to \infty$ is approximated by $d = \max_i |\mathbf{p} \cdot \mathbf{v}_i| - r$ [S6, S13, unofficial].
    *   *GDF Vectors*: 19 pre-normalized vectors are often used, including axes and directions involving the Golden Ratio $\Phi = \frac{\sqrt{5}+1}{2}$ [S6, S13, unofficial].

### Pseudocode
```python
def sdf_sphere(p: vec3, center: vec3, radius: float) -> float:
    """Returns signed distance to a sphere."""
    return length(p - center) - radius

def sdf_box(p: vec3, center: vec3, half_extents: vec3) -> float:
    """Returns exact signed distance to an axis-aligned box."""
    d = abs(p - center) - half_extents
    # Distance to the box volume (negative inside)
    # max(d, 0) gives the part outside the box faces
    # min(d, 0) gives the part inside the box faces (clamped to 0 for the norm)
    outside = length(max(d, vec3(0)))
    inside = min(max(d.x, max(d.y, d.z)), 0)
    return outside + inside

def sdf_plane(p: vec3, normal: vec3, offset: float) -> float:
    """Returns signed distance to a plane defined by normal and offset (d in ax+by+cz+d=0)."""
    return dot(p, normal) + offset

def sdf_torus(p: vec3, major_radius: float, minor_radius: float) -> float:
    """Returns signed distance to a torus centered at origin, aligned with Y axis."""
    q = vec2(length(p.xz) - major_radius, p.y)
    return length(q) - minor_radius

def sdf_capsule(p: vec3, a: vec3, b: vec3, radius: float) -> float:
    """Returns signed distance to a capsule defined by endpoints a, b and radius."""
    ab = b - a
    t = clamp(dot(p - a, ab) / dot(ab, ab), 0.0, 1.0)
    closest = a + ab * t
    return length(p - closest) - radius

def sdf_cylinder_capped(p: vec3, center_xz: vec2, radius: float, half_height: float) -> float:
    """Returns signed distance to a capped cylinder aligned with Y axis."""
    dx = length(p.xz - center_xz) - radius
    dy = abs(p.y) - half_height
    outside = length(max(vec2(dx, dy), vec2(0)))
    inside = min(max(dx, dy), 0)
    return outside + inside
```

### Parameters and Edge Cases
*   **Lipschitz Condition**: The SDF must satisfy $|f(\mathbf{p}_1) - f(\mathbf{p}_2)| \le \|\mathbf{p}_1 - \mathbf{p}_2\|$. Exact primitives satisfy this. Approximations (like the "Cheap Box") may violate it, causing tunneling in ray marching [S2, S6, unofficial].
*   **Precision**: Near the surface ($d \approx 0$), floating-point precision errors can cause jitter. A small epsilon or bias is often added during rendering [S10, S11, unofficial].
*   **Normals**: Normals are not stored but derived via finite differences: $\mathbf{n} = \text{normalize}(\nabla f(\mathbf{p}))$. A common approximation uses a step size $\epsilon = 0.0001$:
    $$ \mathbf{n} \approx \text{normalize}( (f(\mathbf{p}+\epsilon\mathbf{x}) - f(\mathbf{p})), (f(\mathbf{p}+\epsilon\mathbf{y}) - f(\mathbf{p})), (f(\mathbf{p}+\epsilon\mathbf{z}) - f(\mathbf{p})) ) $$
    [S11, unofficial].
*   **Non-Primitive Shapes**: Not every shape has a closed-form SDF. Arbitrary meshes require approximate SDFs (e.g., baked into textures or BVH traversal) [S15, unofficial].

## Subtopics

### [SDF Primitives & Operations](1075-sdf-primitives-operations.md)
Provides the foundational analytical functions and Boolean/combinatorial logic required to define complex geometry. It distinguishes between domain manipulation (transforming $\mathbf{p}$) and value-domain operations (combining $d$).

### [SDF Transformation](1086-sdf-transformation.md)
Applies geometric transformations (rotation, translation, scaling) by mapping the query point $\mathbf{p}$ into the primitive's local space using the inverse transformation matrix $M^{-1}$ before evaluation.

### [k-SDF](9530-k-sdf.md)
A representation for real-time view synthesis of fuzzy geometries using $k$ lightweight mesh shells, bounding sampling locations per ray.

### [SDF Representation DOP](12996-sdf-representation-dop.md)
Creates a volumetric SDF for collision detection, focusing on topological correctness rather than visual appearance.

### SDF Grid Modeling
A float grid where active values describe the distance to a surface (negative inside, positive outside, zero at surface) [S16, unofficial]. It allows for efficient boolean operations with smooth transitions, which are difficult on meshes, and supports smoothing via operations like the SDF Grid Mean node [S16, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(1)$ per primitive evaluation. The cost depends on the number of primitives evaluated per ray step.
*   **Memory Complexity**: $O(1)$ for analytical primitives (only parameters stored). $O(N)$ for grid-based SDFs where $N$ is the number of voxels [S10, S16, unofficial].
*   **Performance**: Exact SDFs are computationally cheap but limited to specific shapes. Complex scenes require many primitive evaluations. GDFs with loops (e.g., Icosahedron) may suffer from driver loop unrolling issues on some hardware (e.g., Nvidia 350.12) [S6, S13, unofficial].
*   **Strengths**: No tessellation artifacts; infinite resolution; easy boolean composition; compact storage [S1, S9, unofficial].
*   **Limitations**: Limited to shapes with known analytical distances; normals require gradient estimation; sharp features in CSG unions can cause discontinuities in derivatives [S11, S15, unofficial].

## Background
The concept of Signed Distance Fields originates from the level set method, which represents an orientable manifold surface as a function tracking the signed distance to the nearest point on the interface [S10, unofficial]. In computer graphics, SDFs were popularized for ray marching and procedural rendering, allowing complex scenes to be defined by mathematical functions rather than mesh tessellation [S1, S9, unofficial]. Key developments include the use of SDFs for real-time ray marching in shaders (e.g., Inigo Quilez's work) and their application in neural rendering to learn geometry with clearer, noise-free surfaces compared to density fields [S1, unofficial][S5].
