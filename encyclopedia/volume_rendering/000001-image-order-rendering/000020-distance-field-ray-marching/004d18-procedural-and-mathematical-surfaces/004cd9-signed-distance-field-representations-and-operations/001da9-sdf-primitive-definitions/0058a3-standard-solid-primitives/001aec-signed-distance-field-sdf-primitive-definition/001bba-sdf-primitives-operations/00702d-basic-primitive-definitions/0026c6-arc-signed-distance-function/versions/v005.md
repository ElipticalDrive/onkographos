# Arc Signed Distance Function

Also called: SDF Arc, sdArc

## Overview
The Arc Signed Distance Function computes the Euclidean distance from a query point to a 3D tube of constant radius wrapping a circular arc. It solves the problem of defining smooth, analytically continuous boundaries for curved, open-ended tubular structures in ray marching and implicit modeling. It is distinguished from the [Capsule Signed Distance Function](2439-capsule-signed-distance-function.md) by its curved path rather than a straight line segment, and from the [Torus](5346-basic-primitive-definitions.md) by its limited angular aperture.

## How it works
**Inputs:**
- Query point $p = (p_x, p_y, p_z)$.
- `arc_center`: Center of the arc's circular path in 3D space.
- `orientation_angle`: Angle of the arc's starting plane relative to the global X-axis (in degrees).
- `aperture_angle`: Total angular span of the arc (in degrees).
- `ra`: Radius of the circular path defining the arc's curvature.
- `rb`: Radius of an inner circle, used for complex shapes (default 0.0).
- `arc_tube_radius`: Radius of the tube surrounding the arc path.
- `depth`: A global Z-coordinate value used to define the arc's plane if the arc is not centered at $p_z$ (implementation detail from [S1, unofficial]).

**Outputs:**
- Signed distance $d$ to the arc surface. Positive outside, negative inside.

**Data Structures:**
The implementation typically precomputes trigonometric values to avoid repeated calls during evaluation. The `Arc` struct layout is:
- `vec3 arc_center`: Center position.
- `float arc_tube_radius`: Tube radius.
- `float orientation_angle`: Orientation in degrees.
- `float aperture_angle`: Aperture in degrees.
- `float sca_cos`: $\cos(\text{orientation\_angle})$.
- `float sca_sin`: $\sin(\text{orientation\_angle})$.
- `float scb_cos`: $\cos(\text{aperture\_angle})$.
- `float scb_sin`: $\sin(\text{aperture\_angle})$.
- `float ra`: Path radius.
- `float rb`: Inner radius.

**Steps:**
1.  **Position Construction:** Construct a position vector from the query point, replacing the Z component with a global `depth` value to align the arc's plane.
    $$pos = (p_x, p_y, \text{depth})$$
2.  **Translation:** Translate the position by the arc center.
    $$pos = pos - \text{arc\_center}$$
3.  **Rotation:** Rotate the position into the arc's local coordinate system using the precomputed sine and cosine of the orientation angle.
    $$x = pos_x \cdot \text{sca\_cos} - pos_y \cdot \text{sca\_sin}$$
    $$y = pos_x \cdot \text{sca\_sin} + pos_y \cdot \text{sca\_cos}$$
    $$pos_x = x, \quad pos_y = y$$
4.  **Symmetry:** Take the absolute value of the X component to exploit symmetry across the arc's mid-plane.
    $$pos_x = |pos_x|$$
5.  **Intermediate Value Calculation:** Compute an intermediate value $k$ based on the aperture angle. This step effectively projects the point onto the arc's bounding geometry.
    $$k = \begin{cases} pos_x \cdot \text{scb\_sin} + pos_y \cdot \text{scb\_cos} & \text{if } \text{scb\_cos} \cdot pos_x > \text{scb\_sin} \cdot pos_y \\ \sqrt{pos_x^2 + pos_y^2} & \text{otherwise} \end{cases}$$
6.  **Project Distance:** Compute the distance to the circular path defined by radius $ra$ and inner radius $rb$.
    $$\text{project\_distance} = \sqrt{pos \cdot pos + ra^2 - 2 \cdot ra \cdot k} - rb$$
    *Note: The source code uses `sqrt14`, an approximation of square root [S1, unofficial].*
7.  **Final Distance:** Combine the project distance with the Z-component (depth difference) and subtract the tube radius.
    $$d = \sqrt{\text{project\_distance}^2 + p_z^2} - \text{arc\_tube\_radius}$$

**Pseudocode:**
```python
def sd_arc(p: Vec3, arc: Arc) -> float:
    # 1. Construct position vector using global depth
    # Note: 'depth' is assumed to be a global variable or passed context
    pos = Vec3(p.x, p.y, depth)
    
    # 2. Translate by arc center
    pos = pos - arc.arc_center
    
    # 3. Rotate by orientation angle
    x = pos.x * arc.sca_cos - pos.y * arc.sca_sin
    y = pos.x * arc.sca_sin + pos.y * arc.sca_cos
    pos.x = x
    pos.y = y
    
    # 4. Absolute value of x
    pos.x = abs(pos.x)
    
    # 5. Compute intermediate value k
    # Condition: scb_cos * pos.x > scb_sin * pos.y
    if arc.scb_cos * pos.x > arc.scb_sin * pos.y:
        k = pos.x * arc.scb_sin + pos.y * arc.scb_cos
    else:
        k = length(pos.x, pos.y)
        
    # 6. Compute project distance
    # Using standard sqrt for clarity; source uses FT::sqrt approximation
    project_distance = sqrt(dot(pos, pos) + arc.ra * arc.ra - 2.0 * arc.ra * k) - arc.rb
    
    # 7. Final distance
    return sqrt(project_distance * project_distance + p.z * p.z) - arc.arc_tube_radius

def length(x: float, y: float) -> float:
    return sqrt(x * x + y * y)

def dot(v: Vec3, w: Vec3) -> float:
    return v.x * w.x + v.y * w.y + v.z * w.z
```

**Parameters:**
- `ra`: Radius of the circle defining the arc path. Typical value varies by instance (e.g., 1.75f) [S1, unofficial].
- `rb`: Radius of an inner circle, used for interesting shapes. Default is 0.0f [S1, unofficial].
- `arc_tube_radius`: Radius of the tube running along the arc [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Angle Conversion:** The constructor must convert `orientation_angle` and `aperture_angle` from degrees to radians by multiplying by $\pi/180.0$ before computing sine and cosine values [S1, unofficial].
- **Precision:** The source implementation uses fast trigonometric approximations (`FT::sqrt`, `FT::atan`) which may introduce minor precision errors compared to standard library functions [S1, unofficial].
- **Depth Dependency:** The method relies on a global `depth` variable to define the Z-coordinate of the arc plane. If `depth` does not match the intended plane of the arc, the distance calculation will be incorrect [S1, unofficial].

## Subtopics

### Geodesic Arc Length Calculation
Computes the exact length of a quadratic geodesic arc defined by $z = at^2$. The integral $l(a, \rho_0) = \int \sqrt{1 + (2at)^2} dt$ is solved via substitution $u=2at$ and $x=\arctan(u)$, resulting in $l(a, \rho_0) = \frac{u\sqrt{1+u^2} + \ln(u + \sqrt{1+u^2})}{4a}$ [S2]. This is used for high-quality surface reconstruction in Gaussian Splatting, distinct from the SDF distance query [S2].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query. The calculation involves a fixed number of arithmetic operations and trigonometric lookups (precomputed).
- **Memory Complexity:** $O(1)$ for the primitive parameters.
- **Strengths:** Provides smooth, continuous distance fields for curved tubes without tessellation. Efficient for ray marching due to analytic derivatives (if computed) and simple structure.
- **Limitations:** Limited to specific geometric shapes. The approximation of square roots in the source code [S1, unofficial] may affect precision in critical applications. The reliance on a global `depth` variable [S1, unofficial] makes it less portable in generic SDF libraries unless adapted.
- **When to use:** When rendering curved, tubular structures with constant cross-sections where a torus is too complex or a capsule is too straight.

## Background
The Arc SDF is defined in the context of Signed Distance Field (SDF) primitive definitions for ray marching. It appears in the repository [AlerianEmperor/SDF-Sphere-Tracing](https://github.com/AlerianEmperor/SDF-Sphere-Tracing) [S1, unofficial], which implements various SDF primitives including spheres, boxes, and arcs. The implementation utilizes fast trigonometric approximations and SSE optimizations as noted in the source comments [S1, unofficial]. The geodesic arc length formula is derived in the context of Quadratic Gaussian Splatting for surface reconstruction [S2].
