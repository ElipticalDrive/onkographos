# Signed Distance Field (SDF) Primitive Definition

Also called: SDF Function, SDF Shapes, Signed Distance Field (SDF), Signed Distance Function (SDF), Signed Distance Function Primitives

## Overview
A Signed Distance Field (SDF) Primitive Definition is a method for representing 3D geometry using closed-form analytical functions that return the shortest Euclidean distance from any query point to the nearest surface, along with a sign indicating whether the point is inside (negative) or outside (positive) the object [S2, S3, S8, S9, S15, unofficial]. It solves the problem of defining scene geometry for ray marching by providing a conservative distance estimate that guarantees the ray step size will not overshoot the surface, enabling efficient and accurate intersection detection without explicit mesh tessellation [S1, S8, S15, unofficial]. Unlike [Constructive SDF Modeling (Min Combination)](871-constructive-sdf-modeling-min-combination.md) which combines primitives, this method focuses on the base analytical definitions of canonical shapes (spheres, boxes, tori, etc.) and their immediate geometric properties [G].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D position vector $p = (p_x, p_y, p_z)$ and primitive-specific parameters (e.g., radius $r$, center $c$, half-extents $b$).
*   **Output:** A scalar float $d = \text{SDF}(p)$, where $|d|$ is the distance to the surface, $d < 0$ indicates the point is inside, $d = 0$ is on the surface, and $d > 0$ is outside [S2, S3, S8, S9, S15, unofficial].

**Data Structures:**
Primitives are typically defined by simple structs or parameter sets. Common layouts include [S14, unofficial]:
*   **Sphere:** `struct sph { float r; vec3 c; }`
*   **Box:** `struct box { vec3 p; vec3 size; }` (where `size` is full size, halved in calculation)
*   **Cylinder:** `struct cylinder { vec2 p; float r; }` (center in XZ plane)
*   **Cylinder Capped:** `struct cylinderCapped { float r; float h; }` (half-height)
*   **Cone:** `struct cone { float r; float h; vec3 c; }`
*   **Plane:** `struct plane { vec4 k; }` (normal xyz, offset w)
*   **Torus:** `struct tor { float inR; float outR; }` (tube radius, major radius)

**Numbered Steps:**
1.  **Coordinate Transformation (Optional):** If the primitive is transformed (rotated, translated, scaled), apply the inverse transformation to the query point $p$ before evaluation [S11, unofficial]. For a transformation matrix $M$, compute $p' = M^{-1} p$. Note: Non-uniform scaling requires distance compensation (see [Uniform Scaling of SDFs](2394-uniform-scaling-of-sdfs.md)) [S2, unofficial][S9, unofficial].
2.  **Distance Calculation:** Evaluate the analytical SDF function for the specific primitive using the (possibly transformed) point $p$.
3.  **Sign Determination:** The sign is inherent in the formula (e.g., subtracting radius from distance). If $d < 0$, the point is inside; if $d > 0$, outside [S2, S3, S8, S9, S15, unofficial].
4.  **Normal Approximation (Optional):** To compute the surface normal $n$ for shading, approximate the gradient using central finite differences with step size $\epsilon$ (typically $0.0001$) [S11, S13, unofficial]:
    $$ n = \text{normalize}\left( \begin{bmatrix} \text{SDF}(p + (\epsilon, 0, 0)) - d \\ \text{SDF}(p + (0, \epsilon, 0)) - d \\ \text{SDF}(p + (0, 0, \epsilon)) - d \end{bmatrix} \right) $$

**Formulas and Implementations:**
All formulas assume $p$ is the query point. Vectors are 3D unless noted. `length(v)` is the Euclidean norm $\|v\|$. `max(a, b)` and `min(a, b)` are component-wise for vectors. `clamp(x, min, max)` clamps $x$. `mix(a, b, h)` is $a + h(b-a)$.

*   **Sphere:** Center $c$, radius $r$.
    $$ d(p) = \|p - c\| - r $$
    Implementation: `return length(p - c) - r;` [S6, S11, S13, S14, unofficial]

*   **Box (Axis-Aligned):** Center $p_{box}$, half-extents $b$. Let $d = |p - p_{box}| - b$.
    $$ d(p) = \|\max(d, 0)\| + \min(\max(d_x, \max(d_y, d_z)), 0) $$
    Implementation:
    ```python
    d = abs(p - p_box) - b
    return length(max(d, 0)) + min(max(d.x, max(d.y, d.z)), 0)
    ```
    [S6, S14, unofficial]
    *Cheap Box (overestimates corners):* `return max(abs(p - p_box) - b);` [S6, unofficial]

*   **Plane:** Normal $n$ (unit length), distance from origin $d_{offset}$.
    $$ d(p) = p \cdot n + d_{offset} $$
    Implementation: `return dot(p, n) + distance_from_origin;` [S6, S13, S14, unofficial]

*   **Cylinder (Infinite):** Center $p_{center}$ in XZ plane, radius $r$.
    $$ d(p) = \|p_{xz} - p_{center}\| - r $$
    Implementation: `return length(p.xz - p_center) - r;` [S14, unofficial]

*   **Cylinder (Capped):** Radius $r$, half-height $h$.
    Let $d_x = \|p_{xz}\| - r$ and $d_y = |p_y| - h$.
    $$ d(p) = \min(\max(d_x, d_y), 0) + \|\max(d, 0)\| $$
    where $d = (d_x, d_y)$.
    Implementation:
    ```python
    d_x = length(p.xz) - r
    d_y = abs(p.y) - h
    d = vec2(d_x, d_y)
    return min(max(d.x, d.y), 0) + length(max(d, 0))
    ```
    [S14, unofficial]

*   **Cone:** Radius $r$, height $h$, center/offset $c$.
    Let $\phi = \arctan(r/h)$.
    $$ d(p) = \max(\sqrt{x^2+z^2}\cos(\phi) - |y|\sin(\phi), \max(y-h, -y)) $$
    Implementation (handling tip and base ring explicitly) [S13, S14, unofficial]:
    ```python
    q = vec2(length(p.xz), p.y)
    tip = q - vec2(0, h)
    mantle_dir = normalize(vec2(h, r))
    mantle = dot(tip, mantle_dir)
    d = max(mantle, -q.y)
    projected = dot(tip, vec2(mantle_dir.y, -mantle_dir.x))
    
    # Distance to tip
    if (q.y > h) and (projected < 0):
        d = max(d, length(tip))
    
    # Distance to base ring
    if (q.x > r) and (projected > length(vec2(h, r))):
        d = max(d, length(q - vec2(r, 0)))
    return d
    ```

*   **Torus:** Major radius $R_{out}$, tube radius $R_{in}$.
    $$ d(p) = \|(\|p_{xz}\| - R_{out}, p_y)\| - R_{in} $$
    Implementation:
    ```python
    q = vec2(length(p.xz) - R_out, p.y)
    return length(q) - R_in
    ```
    [S6, S13, S14, unofficial]

*   **Capsule:** Endpoints $a, b$, radius $r$.
    $$ d(p) = \text{LineSegment}(p, a, b) - r $$
    Where $\text{LineSegment}(p, a, b) = \|(a + t(b-a)) - p\|$ and $t = \text{clamp}(\frac{(p-a)\cdot(b-a)}{\|b-a\|^2}, 0, 1)$.
    Implementation [S13, unofficial]:
    ```python
    ab = b - a
    t = clamp(dot(p - a, ab) / dot(ab, ab), 0, 1)
    return length((ab * t + a) - p) - r
    ```

*   **Smooth Minimum (Blending):** To blend two SDFs $a$ and $b$ smoothly with constant $k$ (e.g., 0.2) [S11, unofficial]:
    $$ h = \text{clamp}(0.5 + 0.5 \cdot \frac{b - a}{k}, 0, 1) $$
    $$ \text{smin}(a, b) = \text{mix}(b, a, h) - k \cdot h \cdot (1 - h) $$
    Implementation [S11, unofficial]:
    ```python
    k = 0.2
    h = clamp(0.5 + 0.5 * (b - a) / k, 0, 1)
    return mix(b, a, h) - k * h * (1 - h)
    ```

*   **Generalized Distance Function (GDF):** Uses a set of normalized vectors $V_i$ and exponent $e$.
    $$ d(p) = \left( \sum_{i} |p \cdot V_i|^e \right)^{1/e} - r $$
    For sharp edges, use $e \to \infty$ (max). The set `GDFVectors` contains 19 normalized directions including axes and golden-ratio based vectors ($\phi = \frac{\sqrt{5}+1}{2}$) [S6, S13, unofficial].
    Implementation [S13, unofficial]:
    ```python
    PHI = sqrt(5)*0.5 + 0.5
    GDFVectors = [ ... 19 normalized vec3s ... ] # See S13 for full list
    
    def fGDF(p, r, e, begin, end):
        d = 0
        for i in range(begin, end + 1):
            d += pow(abs(dot(p, GDFVectors[i])), e)
        return pow(d, 1/e) - r
    ```
    *Note:* The variable exponent version is slow and may not produce correct distances on all hardware; specialized implementations are recommended [S13, unofficial].

**Parameters:**
*   **Gradient Step ($\epsilon$):** $0.0001$ [S11, S13, unofficial].
*   **Torus Radii:** Example values: major $s=70$, minor $t=15$ [S4, unofficial].
*   **Round Box:** Half-size $b=(20, 20, 5)$, radius $r=10$ [S4, unofficial].
*   **Lipschitz Bound:** For exact SDFs, the ray can safely advance by $|d(p)|$ without overshooting [S15, unofficial].

**Edge Cases and Pitfalls:**
*   **Discontinuities:** Taking `min` or `max` of SDFs creates sharp corners (discontinuous normals) [S11, unofficial]. Use `smin` for smooth blending.
*   **Non-Exact SDFs:** Not all shapes have closed-form SDFs. Arbitrary meshes require approximations (e.g., BVH traversal, 3D textures) [S15, unofficial].
*   **Performance:** Loops in GDFs (e.g., `fIcosahedron`) may fail to unroll on some drivers (e.g., Nvidia 350.12), causing slowdowns [S6, S13, unofficial].
*   **Incorrect Bounds:** Some illustrative functions (e.g., `fBlob`) are not correct distance bounds [S6, S13, unofficial].
*   **Precision:** Near the surface ($d \approx 0$), floating-point precision can affect normal accuracy.

## Subtopics

### [SDF Primitives & Operations](1075-sdf-primitives-operations.md)
Provides foundational analytical functions and geometric operators (union/intersection via min/max) for defining scene geometry implicitly, replacing explicit mesh tessellation with continuous scalar fields [G]. It focuses on base primitives and immediate boolean/domain operators.

### [SDF Transformation](1086-sdf-transformation.md)
Applies geometric transformations (rotation, translation, scaling, deformation) by manipulating query point coordinates before evaluation, preserving mathematical integrity for ray marching. It relies on inverse mapping for isometries or explicit scaling factors.

### [k-SDF](9530-k-sdf.md)
Represents real-time view synthesis of fuzzy geometries using $k$ lightweight, semi-transparent mesh shells rendered via rasterization, bounding samples per ray to $3 \le k \le 9$. It models implicit geometry as $k$ SDFs combined with view-dependent transparency and color, enabling real-time rendering on low-cost smartphones.

### [SDF Representation DOP](12996-sdf-representation-dop.md)
Creates a volumetric SDF from geometry for fast inside/outside testing in collision detection, focusing on topological correctness for rigid body dynamics rather than visual appearance, using modes like Laser Scanning for non-watertight geometry.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation. Scene complexity scales with the number of primitives combined via CSG or blending.
*   **Memory Complexity:** $O(1)$ for primitive definitions. No mesh storage required.
*   **Performance:** Extremely fast for simple primitives and moderate CSG trees. Performance degrades with deep nesting or complex GDFs. Hardware loop unrolling issues can impact GDF performance [S6, S13, unofficial].
*   **Strengths:** Exact distance guarantees enable efficient ray marching (sphere tracing) without overshooting [S8, S15, unofficial]. Compact representation. Easy to implement boolean operations and transformations [S11, unofficial].
*   **Limitations:** Limited to shapes with closed-form SDFs. Sharp corners from min/max operations can cause aliasing in normals. Complex scenes may require many primitives.
*   **When to Use:** Real-time ray marching, procedural geometry, collision detection, and scenes dominated by smooth or analytically definable shapes [S1, S8, S15, unofficial].
*   **When Not to Use:** Scenes with highly detailed, arbitrary meshes where SDF approximation is inaccurate or expensive [S15, unofficial].

## Background
The concept of Signed Distance Fields originates from the level set method, which represents interfaces as functions tracking signed distance to the nearest point on the interface [S10, unofficial]. SDFs were popularized in computer graphics for ray marching and procedural modeling, notably by Inigo Quilez and others in the demoscene and real-time rendering communities [S1, S7, S11, unofficial]. They are used in ray marching renderers, collision detection systems, and neural rendering approaches (e.g., NeRF variants) to define clear, noise-free geometry [S1, unofficial][S5][S15, unofficial].
