# Cached SDF

Also called: CachedSDF, Voxel Grid SDF

## Overview
Cached SDF accelerates Signed Distance Field (SDF) queries by storing quantized distance values in a voxel grid, falling back to a ground truth SDF for points outside the cache [S2, unofficial]. It differs from standard procedural SDFs by trading memory for query speed, and from TSDFs by supporting full-range distance storage (with saturation) rather than truncating to a near-surface band [S1, S2, unofficial].

## How it works
**Inputs:**
- Ground truth SDF function $SDF_{gt}(p)$ that returns signed distance and gradient at point $p$ [S2, unofficial].
- Object bounding box (used to define grid extent) [S2, unofficial].
- Parameters: `VOXEL` (cell size), `CHUNK` (block size, optional), `SDF_SCALE`, `SDF_MAX`, `PAD` (padding voxels), `BEDROCK_SAMPLES` [S1, unofficial].

**Outputs:**
- A voxel grid storing Int8 quantized distances [S1, unofficial].
- Query result: signed distance value at a given point [S2, unofficial].

**Data Structures:**
- **Voxel Grid:** A 3D array of `int8` values. Dimensions are derived from the object's bounding box plus padding, divided by `VOXEL` [S2, unofficial].
- **Quantization:** Distances are mapped to integers in $[-128, 127]$ [S1, unofficial].

**Parameters:**
- `VOXEL`: Voxel cell size (e.g., 0.25 meters) [S1, unofficial].
- `SDF_SCALE`: Quantization scale factor (e.g., 32) [S1, unofficial].
- `SDF_MAX`: Maximum representable distance magnitude (127) [S1, unofficial].
- `PAD`: Padding in voxels around the object (e.g., 2) [S1, unofficial].
- `truncation_distance`: Optional threshold for TSDF variant; if set, grid covers only $[-truncation\_distance, truncation\_distance]$ [S2, unofficial].

**Steps:**
1. **Grid Initialization:** Determine grid dimensions from the object's bounding box extended by `PAD` voxels [S1, S2, unofficial]. Initialize all voxels to a default value (e.g., `SDF_MAX` or `SDF_MAX + 1` to indicate out-of-bounds) [S1, S2, unofficial].
2. **Sampling:** For each voxel center $v$ within the grid bounds:
   - Evaluate the ground truth SDF: $d = SDF_{gt}(v)$ [S2, unofficial].
   - Quantize: $q = \text{round}(d \times SDF\_SCALE / VOXEL)$ [S1, unofficial].
   - Clamp: $q = \text{clamp}(q, -128, 127)$ [S1, unofficial].
   - Store: $Grid[v] = q$ [S1, unofficial].
3. **Query:** Given a point $p$:
   - Convert $p$ to voxel coordinates $c$ relative to the grid origin [S2, unofficial].
   - If $c$ is within grid bounds:
     - Retrieve $q = Grid[c]$ [S2, unofficial].
     - Dequantize: $d_{cached} = q \times VOXEL / SDF\_SCALE$ [S1, unofficial].
     - Return $d_{cached}$ [S2, unofficial].
   - If $c$ is out of bounds:
     - Evaluate ground truth SDF: $d_{gt} = SDF_{gt}(p)$ [S2, unofficial].
     - Return $d_{gt}$ [S2, unofficial].

**Formula:**
The stored quantized value $q$ is calculated as:
$$ q = \text{clamp}\left(\text{round}\left(\frac{d}{VOXEL} \times SDF\_SCALE\right), -128, 127\right) $$
where $d$ is the signed distance from the ground truth SDF [S1, unofficial].

**Precision:**
Precision is approximately $1/32$ of a voxel within $\pm 4$ voxels of the surface [S1, unofficial]. Distances beyond $\pm 4$ voxels are saturated to $\pm 127$ (i.e., $\pm SDF\_MAX$), losing precision for far-field queries [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Saturation:** Far-field distances are clamped to `SDF_MAX` (127) or -128, meaning precise distance information is lost for points far from the surface [S1, unofficial].
- **Out-of-Bounds Strategy:** Points outside the cache can be handled by comparing against the object's bounding box (under-approximating the SDF) or by falling back to the ground truth SDF [S2, unofficial]. The bounding box comparison is empirically sufficient for most applications but always under-approximates [S2, unofficial].
- **TSDF Variant:** If `truncation_distance` is used, the grid is significantly smaller (e.g., ~150x smaller memory reduction), and out-of-bounds points return the truncation value [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Query time is $O(1)$ for in-bounds points (array lookup) and $O(1)$ for out-of-bounds points (ground truth evaluation, potentially slower depending on the ground truth SDF implementation) [S2, unofficial].
- **Memory Complexity:** $O(N)$ where $N$ is the number of voxels in the grid. Memory usage is reduced by Int8 quantization and optional truncation [S1, S2, unofficial].
- **Performance:** Dramatically faster than using the ground truth SDF for out-of-bounds queries if the ground truth is expensive, but primarily accelerates in-bounds queries by avoiding complex geometric calculations [S2, unofficial].
- **Strengths:** Low memory footprint (Int8), fast query speed, simple implementation [S1, S2, unofficial].
- **Limitations:** Precision loss for far-field distances due to saturation, under-approximation for out-of-bounds points if bounding box strategy is used [S1, S2, unofficial].
- **When to use:** When frequent SDF queries are needed within a known bounding volume, and memory is constrained [S2, unofficial].
- **When not to use:** When precise far-field distance information is required, or when the object's geometry is highly complex and the ground truth SDF is already very fast [S1, S2, unofficial].

## Background
Cached SDF was introduced as a method to optimize SDF queries in volumetric representations, particularly in robotics and simulation contexts where efficient collision detection and proximity queries are critical [S2, unofficial]. It leverages quantization to reduce memory usage while maintaining sufficient precision near the surface [S1, unofficial]. The approach is part of a broader trend in using voxel-based representations for implicit surfaces [S2, unofficial].
