# Plane Signed Distance Function

Also called: Plane SDF, Plane distance, Signed Distance Function (SDF) for Plane, Signed Plane, sdPlane

## Overview
The Plane Signed Distance Function (SDF) computes the shortest Euclidean distance from a query point to an infinite plane, with the sign indicating which side of the plane the point resides on. It serves as a fundamental building block for procedural geometry in ray marching, providing a differentiable surface normal for shading and a safe step size for sphere tracing. Unlike bounded primitives such as the [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md) or [Signed Box Distance Function](1092-signed-box-distance-function.md), the plane extends infinitely in all directions perpendicular to its normal, making it ideal for representing ground planes, clipping boundaries, or half-space constraints.

## How it works
**Inputs and Outputs**
*   **Input**: A query point $p \in \mathbb{R}^3$ and plane definition parameters (unit normal $n$ and offset $h$, or normal $n$ and a point $r$ on the plane).
*   **Output**: A scalar value $d(p)$ representing the signed distance.

**Data Structures**
The plane is defined by two primary components:
1.  **Normal ($n$)**: A unit vector $\mathbf{n} = (n_x, n_y, n_z)$ perpendicular to the plane surface.
2.  **Offset/Position**: Either a scalar offset $h$ representing the signed distance from the origin to the plane along the normal, or a point $\mathbf{r}$ lying on the plane.

**Formulas**
There are two common parameterizations, which are mathematically equivalent:

1.  **Normal-Offset Form**:
    $$d(p) = p \cdot n + h$$
    Where $h$ is the signed distance from the origin to the plane. If the plane passes through the origin, $h=0$. The sign of $h$ depends on the direction of $n$ relative to the origin. Specifically, if $n$ points away from the origin, $h$ is negative for planes "in front" of the origin in the direction of $n$. More precisely, $h = -r \cdot n$ where $r$ is any point on the plane.

2.  **Normal-Point Form**:
    $$d(p) = (p - r) \cdot n$$
    Where $r$ is a specific point known to lie on the plane. This is often more intuitive for construction (e.g., "plane passing through origin with normal up").

**Parameters**
*   $n$: Must be a unit vector ($\|n\| = 1$). If not normalized, the result is scaled by the length of $n$, leading to incorrect step sizes in ray marching [S2, unofficial][S6].
*   $h$: Scalar offset.
*   $r$: 3D point on the plane.

**Numbered Steps**
1.  Ensure the normal vector $n$ is normalized. If using a point $r$ and an unnormalized normal $v$, compute $n = v / \|v\|$ [S2, unofficial].
2.  Compute the dot product of the query point $p$ and the normal $n$.
3.  Add the offset $h$ (if using normal-offset form) or subtract the dot product of $r$ and $n$ (if using normal-point form, effectively $p \cdot n - r \cdot n$).
4.  Return the result.

**Pseudocode**
```python
def sd_plane(p: Vector3, n: Vector3, h: float) -> float:
    """
    Computes the signed distance from point p to a plane defined by unit normal n and offset h.
    
    Args:
        p: Query point (Vector3).
        n: Unit normal vector of the plane (Vector3). Must be normalized.
        h: Offset from the origin. The plane equation is n.x*x + n.y*y + n.z*z + h = 0.
           Alternatively, h = -dot(r, n) where r is a point on the plane.
           
    Returns:
        Signed distance. Positive if p is on the side of n, negative if on the opposite side.
    """
    # Guard: Ensure normal is normalized to guarantee correct Euclidean distance
    # [G] In production code, assert or normalize here if n is not guaranteed unit length.
    if length(n) != 1.0:
        n = normalize(n)
        
    # Formula: d = dot(p, n) + h
    # This is equivalent to dot(p - r, n) where r is a point on the plane and h = -dot(r, n)
    return dot(p, n) + h

def sd_plane_from_point(p: Vector3, n: Vector3, r: Vector3) -> float:
    """
    Computes the signed distance from point p to a plane defined by unit normal n and a point r on the plane.
    
    Args:
        p: Query point (Vector3).
        n: Unit normal vector of the plane (Vector3).
        r: A point known to lie on the plane (Vector3).
        
    Returns:
        Signed distance.
    """
    # Guard: Ensure normal is normalized
    if length(n) != 1.0:
        n = normalize(n)
        
    # Formula: d = dot(p - r, n)
    return dot(p - r, n)
```

**Edge Cases and Pitfalls**
*   **Unnormalized Normal**: If $n$ is not a unit vector, the result is not the Euclidean distance but the projection scaled by $\|n\|$. This causes ray marching to overshoot or undershoot [S2, unofficial].
*   **Sign Convention**: The sign of the distance indicates containment. $d(p) < 0$ means the point is on the side opposite to the normal direction (inside the half-space defined by $-n$), and $d(p) > 0$ means it is on the side of the normal. Consistency with the rest of the scene's SDFs is crucial for boolean operations (e.g., unions, intersections) [S5, unofficial].
*   **Infinite Extent**: The plane is infinite. It does not have edges. If a bounded plane is required, it must be combined with other primitives (e.g., using min/max operations with box SDFs) [S4, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(1)$. The calculation involves a single dot product and an addition.
*   **Memory Complexity**: $O(1)$. Requires storing the normal vector (3 floats) and the offset (1 float), or the normal and a point (6 floats).
*   **Performance**: Extremely fast, often one of the fastest SDF evaluations. Suitable for real-time ray marching and dense volume rendering.
*   **Strengths**: Analytically exact, differentiable everywhere except at the plane itself (where the gradient is discontinuous, but the normal is well-defined as $\pm n$). Provides a safe, tight bound for sphere tracing steps.
*   **Limitations**: Represents an infinite surface. Cannot model bounded planar regions without composition with other primitives.
*   **When to use**: Ground planes, infinite walls, clipping planes, or as a component in complex CSG (Constructive Solid Geometry) operations.
*   **When not to use**: When a bounded planar surface is needed (use a Box or custom mesh SDF instead).

## Background
The signed distance function for a plane is a fundamental result in computational geometry and implicit surface rendering. It is widely cited in the context of sphere tracing and ray marching for implicit surfaces. Hart (1994) provided early formalizations of SDFs for basic primitives, including the plane [S6]. The specific formulation $d(x) = x \cdot n - h$ is commonly attributed to Hart and appears in various graphics literature and educational resources on GPU ray marching [S5, unofficial]. The GLSL implementation `sdPlane` popularized by Inigo Quilez's online resources further cemented the normal-offset parameterization in the real-time graphics community [S2, unofficial].
