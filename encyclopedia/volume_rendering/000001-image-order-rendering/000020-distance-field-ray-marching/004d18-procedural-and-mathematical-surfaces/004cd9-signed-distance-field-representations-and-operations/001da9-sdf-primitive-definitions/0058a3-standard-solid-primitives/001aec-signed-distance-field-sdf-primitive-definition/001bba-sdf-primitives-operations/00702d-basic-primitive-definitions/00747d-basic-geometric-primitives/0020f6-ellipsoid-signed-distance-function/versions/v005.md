# Ellipsoid Signed Distance Function

Also called: Ellipsoid SDF, Ellipsoidal Prior SDF, Approximate Ellipsoid SDF

## Overview
The Ellipsoid Signed Distance Function (SDF) computes the shortest Euclidean distance from a query point to the surface of an ellipsoid defined by three semi-axes. It serves as a fundamental building block for procedural geometry in volume rendering and ray marching, enabling the representation of smooth, organic shapes and thin objects (via degenerate 2D disks) [S1][S2, S3, unofficial]. Unlike the Sphere SDF, which assumes uniform scaling, the Ellipsoid SDF handles anisotropic scaling, making it distinct from siblings like the Box or Capsule primitives [Parent]. It is particularly noted for its ability to handle non-watertight surfaces when one axis radius is set to zero, reducing the function to a Signed Directional Distance Function (SDDF) for 2D disks [S1].

## How it works
**Inputs:**
*   $p \in \mathbb{R}^3$: The query point in the ellipsoid's local coordinate frame.
*   $r \in \mathbb{R}^3$: The semi-axes lengths $(r_x, r_y, r_z)$, where $r_i > 0$. For a 2D disk, one component (typically $r_z$) is set to $0$ [S1][S2, S3, unofficial].

**Outputs:**
*   $d \in \mathbb{R}$: The signed distance. $d < 0$ if inside, $d = 0$ on surface, $d > 0$ if outside.

**Data Structures:**
*   Vectors $p$ and $r$ are typically stored as 3-component floating-point arrays or SIMD registers.

**Method:**
There are two primary implementations: an approximate version (fast, widely used in real-time graphics) and a more accurate iterative or analytical approximation [S2, S3, unofficial]. The sources provide specific formulas for both.

### 1. Approximate Version (V1)
This version scales the distance from the unit sphere by the minimum semi-axis. It is computationally cheap but less accurate for highly anisotropic ellipsoids [S2, unofficial].

1.  Normalize the point by the radii: $p' = p / r$ (component-wise division).
2.  Compute the length of the normalized point: $k_1 = \|p'\|$.
3.  Compute the minimum semi-axis: $r_{min} = \min(r_x, r_y, r_z)$.
4.  Calculate distance: $d = (k_1 - 1.0) \cdot r_{min}$.

### 2. Improved Approximate Version (V2)
This version provides better accuracy by correcting the step size based on the gradient magnitude at the closest point on the unit sphere [S2, S3, unofficial].

1.  Normalize the point by the radii: $p' = p / r$ (component-wise division).
2.  Compute the length of the normalized point: $k_1 = \|p'\|$.
3.  Compute the gradient magnitude factor: $k_2 = \|p' / r\|$ (Note: sources define this as length of $p$ divided by squared radii, effectively $\|p / r^2\|$ in local space, but geometrically it relates to the gradient of the implicit function $f(x) = \sum (x_i/r_i)^2 - 1$). Specifically, $k_2 = \|p / (r \cdot r)\|$ where $r \cdot r$ is component-wise squaring [S2, S3, unofficial].
4.  Calculate distance: $d = \frac{k_1 (k_1 - 1.0)}{k_2}$.

### 3. 2D Disk (Degenerate Ellipsoid)
When $r_z = 0$, the ellipsoid becomes a flat disk in the $xy$-plane. The standard SDF is ill-posed for sign in non-watertight objects, so a Signed Directional Distance Function (SDDF) is used for ray marching [S1].

**Inputs:**
*   $p'$: Ray origin in local frame.
*   $v'$: Ray direction in local frame.
*   $r_x, r_y$: Non-zero semi-axes.

**Steps:**
1.  Compute the cross product $w' = p' \times v'$.
2.  Check intersection indicator:
    $$i(p, v; E) = (r_x r_y v'_z)^2 - r_x^2 w'_z^2 - r_y^2 w'_y^2$$
3.  If $i(p, v; E) < 0$, the ray does not intersect the disk. Return $\infty$ or handle as miss [S1].
4.  If $i(p, v; E) \ge 0$, compute the signed distance:
    $$d = -\frac{p'_z}{v'_z}$$
    *   **Pitfall:** If $v'_z = 0$, the function returns $\infty$ (no intersection) [S1].
    *   **Pitfall:** If the ray points away from the disk ($v'_z > 0$ and $p'_z \le 0$, or $v'_z < 0$ and $p'_z \ge 0$), the formula yields invalid negative values. The intersection check $i \ge 0$ is required to validate the result [S1].

**Pseudocode (Improved V2 for 3D Ellipsoid):**

```python
import math

def ellipsoid_sdf(p: list, r: list) -> float:
    """
    Computes the improved approximate signed distance to an ellipsoid.
    p: [px, py, pz] query point in local space
    r: [rx, ry, rz] semi-axes lengths
    """
    # Component-wise division p / r
    px, py, pz = p
    rx, ry, rz = r
    
    # Avoid division by zero if r contains 0 (use V1 or handle separately)
    # For standard 3D ellipsoid, r_i > 0
    
    # Step 1: Normalize point
    px_r = px / rx
    py_r = py / ry
    pz_r = pz / rz
    
    # Step 2: Compute k1 = length(p / r)
    k1 = math.sqrt(px_r**2 + py_r**2 + pz_r**2)
    
    # Step 3: Compute k2 = length(p / (r * r))
    # Note: p / (r*r) means component-wise p_i / (r_i^2)
    px_rr = px / (rx * rx)
    py_rr = py / (ry * ry)
    pz_rr = pz / (rz * rz)
    
    k2 = math.sqrt(px_rr**2 + py_rr**2 + pz_rr**2)
    
    # Step 4: Return distance
    # Guard against k2 being zero (origin case)
    if k2 == 0:
        return -min(rx, ry, rz) # Inside, distance to closest surface
        
    d = (k1 * (k1 - 1.0)) / k2
    
    # Sign correction: The formula above yields positive outside, negative inside?
    # Standard SDF: positive outside, negative inside.
    # k1 > 1 implies outside. k1 < 1 implies inside.
    # If k1 > 1, k1-1 > 0, d > 0.
    # If k1 < 1, k1-1 < 0, d < 0.
    # The formula naturally handles the sign.
    
    return d
```

**Pseudocode (2D Disk SDDF):**

```python
def ellipsoid_disk_sddf(p: list, v: list, rx: float, ry: float) -> float:
    """
    Computes the signed directional distance for a 2D disk (rz=0).
    p: [px, py, pz] ray origin in local space
    v: [vx, vy, vz] ray direction in local space
    rx, ry: semi-axes of the disk
    """
    px, py, pz = p
    vx, vy, vz = v
    
    # Step 1: Compute w' = p' x v'
    wx = py * vz - pz * vy
    wy = pz * vx - px * vz
    wz = px * vy - py * vx
    
    # Step 2: Check intersection indicator
    # i = (rx * ry * vz)^2 - rx^2 * wz^2 - ry^2 * wy^2
    term1 = (rx * ry * vz) ** 2
    term2 = (rx ** 2) * (wz ** 2)
    term3 = (ry ** 2) * (wy ** 2)
    
    i = term1 - term2 - term3
    
    if i < 0:
        return float('inf') # No intersection
    
    # Step 3: Handle degenerate direction
    if vz == 0:
        return float('inf') # Parallel to disk plane, no intersection
    
    # Step 4: Compute distance
    # d = -pz / vz
    d = -pz / vz
    
    # Pitfall check: If ray points away, d might be invalid relative to geometry
    # The intersection check i >= 0 ensures we hit the disk plane within bounds,
    # but the sign of d depends on vz.
    # If vz > 0 and pz <= 0, ray starts "below" and goes "up" through disk? 
    # Actually, the formula -pz/vz gives the parameter t.
    # If t < 0, the intersection is behind the ray origin.
    # The source notes say: "If vz > 0 and pz <= 0 ... gives invalid negative values."
    # This implies we should check if the intersection is in front of the ray.
    
    if d < 0:
        return float('inf') # Intersection behind ray origin
        
    return d
```

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query. The improved version requires a few multiplications, additions, and a square root.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures.
*   **Accuracy:** The V1 approximation is fast but can have errors up to several percent for extreme aspect ratios. The V2 approximation is significantly more accurate and is the standard choice for high-quality rendering [S2, S3, unofficial].
*   **Strengths:** Handles arbitrary ellipsoids; V2 is smooth and differentiable almost everywhere, providing good normals for shading [Parent]. The 2D disk variant allows rendering of thin, non-watertight objects like walls or curtains without geometry thickness [S1].
*   **Limitations:** The V2 formula involves division by $k_2$, which can be numerically unstable if the point is very close to the center (origin) or if radii are extremely small/large. The 2D disk SDDF is not a true SDF (it is directional) and requires careful ray intersection checks to avoid artifacts [S1].

## Background
The concept of using ellipsoids as priors for scene representation has been explored in neural rendering and implicit surface modeling. The specific SDDF formulation for 2D disks using ellipsoidal priors was introduced to handle non-watertight objects in neural radiance fields and similar frameworks [S1]. The approximate SDF formulas (V1 and V2) are widely attributed to Inigo Quilez's articles on distance functions, which are standard references in the real-time graphics community [S2, S3, unofficial]. The V2 formula is a refinement over the simple scaling method (V1) to better approximate the true Euclidean distance.
