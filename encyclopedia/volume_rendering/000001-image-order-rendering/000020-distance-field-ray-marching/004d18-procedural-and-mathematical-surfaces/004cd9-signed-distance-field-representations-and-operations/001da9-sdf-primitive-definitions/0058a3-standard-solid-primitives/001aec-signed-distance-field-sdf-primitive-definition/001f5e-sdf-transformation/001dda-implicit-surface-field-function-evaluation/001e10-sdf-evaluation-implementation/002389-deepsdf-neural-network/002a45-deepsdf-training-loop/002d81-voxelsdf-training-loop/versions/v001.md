# VoxelSDF Training Loop

Also called: Training Procedure (L1 Loss + Adam + StepLR), VoxelSDF Training Procedure

## Overview
The VoxelSDF Training Loop is the optimization procedure for the VoxelSDF model, which extends the DeepSDF framework by introducing learnable grid embeddings for latent codes [S1, unofficial]. It solves the problem of shape reconstruction by jointly optimizing a neural implicit field and a discrete embedding table using L1 loss [S1, unofficial]. It differs from the standard DeepSDF Training Loop by maintaining a separate, learnable embedding matrix for shape codes, updated via a distinct learning rate [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A dataset of point-SDF pairs (e.g., ShapeNetSDF), typically batched with shuffling [S1, unofficial].
- **Output:** Updated weights for the SDF MLP (`self.model`) and the grid embeddings (`self.embeddings`) [S1, unofficial].

**Data Structures:**
- `self.model`: The neural network mapping (latent code, 3D point) to signed distance values [S1, unofficial].
- `self.embeddings`: A learnable embedding table indexed by shape ID, storing latent codes [S1, unofficial].
- `self.optimizer`: An Adam optimizer configured with separate parameter groups [S1, unofficial].
- `self.scheduler`: A StepLR scheduler for learning rate decay [S1, unofficial].

**Parameters:**
- `batch_size`: Number of samples per iteration [S1, unofficial].
- `epochs`: Total number of training epochs [S1, unofficial].
- `step_size`: Epochs between scheduler decay, default 100 [S1, unofficial].
- `lr_model`: Learning rate for the MLP, default $1 \times 10^{-4}$ [S1, unofficial].
- `lr_embedding`: Learning rate for embeddings, default $1 \times 10^{-2}$ [S1, unofficial].

**Steps:**
1. Initialize `self.embeddings` for the dataset size [S1, unofficial].
2. For each epoch $e$ from start to total epochs:
   a. Iterate through the dataloader, yielding batches of `(points, sdfs, index)` [S1, unofficial].
   b. Move `points` and `sdfs` to the device [S1, unofficial].
   c. Retrieve latent codes: `latent_codes = self.embeddings(index)` [S1, unofficial].
   d. Compute predicted SDFs: `sdf_pred = self.model(latent_codes, points)` [S1, unofficial].
   e. Reshape `sdf_pred` and `sdfs` to `(real_batch_size, -1)` [S1, unofficial].
   f. Compute L1 loss: `loss = criterion(sdf_pred, sdfs)` [S1, unofficial].
   g. Zero gradients, backward pass, and optimizer step [S1, unofficial].
   h. Accumulate epoch loss [S1, unofficial].
   i. Step the scheduler [S1, unofficial].
   j. If $e$ is a multiple of 100, save model and embedding states, and record losses [S1, unofficial].

**Pseudocode:**
```python
def train_voxelsdf(model, embeddings, dataloader, epochs, device, result_dir, start_epoch=0):
    # Initialize optimizer with separate learning rates [S1, unofficial]
    optimizer = torch.optim.Adam([
        {"params": model.parameters(), "lr": 1e-4},
        {"params": embeddings.parameters(), "lr": 1e-2}
    ])
    # StepLR scheduler with default step_size=100 [S1, unofficial]
    scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=100)
    
    criterion = torch.nn.L1Loss()
    losses = []
    
    for e in range(start_epoch, epochs + 1):
        epoch_loss = 0
        for points, sdfs, index in dataloader:
            points = points.to(device)
            sdfs = sdfs.to(device)
            real_batch_size = index.shape[0]
            
            # Forward pass [S1, unofficial]
            latent_codes = embeddings(index.to(device))
            sdf_pred = model(latent_codes, points)
            
            # Reshape for loss computation [S1, unofficial]
            sdf_pred = sdf_pred.view(real_batch_size, -1)
            sdfs = sdfs.view(real_batch_size, -1)
            
            # Compute loss [S1, unofficial]
            loss = criterion(sdf_pred, sdfs)
            
            # Optimization step [S1, unofficial]
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            
            epoch_loss += loss.item()
        
        scheduler.step()
        
        # Save model every 100 epochs [S1, unofficial]
        if e % 100 == 0:
            save_model(model, embeddings, e, result_dir)
            losses.append(epoch_loss)
            
    return losses
```

**Edge Cases and Pitfalls:**
- **Precision:** L1 loss is used, which is robust to outliers but may produce less sharp surfaces than L2 [S1, unofficial].
- **Boundaries:** The embedding table must be sized to the maximum shape index in the dataset [S1, unofficial].
- **Degenerate Input:** Empty batches or invalid indices will cause runtime errors; the dataloader should handle this [G].

## Subtopics

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of epochs and batch size [S1, unofficial].
- **Memory Complexity:** Dominated by the embedding table size, proportional to the number of shapes in the dataset [S1, unofficial].
- **Performance:** Not given in the sources.
- **Strengths:** Joint optimization of latent codes and network weights allows for shape-specific adaptation [S1, unofficial].
- **Limitations:** High memory usage for large datasets due to the embedding table [S1, unofficial].
- **When to use:** When shape-specific latent codes are beneficial and memory is sufficient [S1, unofficial].
- **When not:** For very large-scale datasets where embedding table size becomes prohibitive [S1, unofficial].
