# Signed Distance Field (SDF) Primitive Definition

Also called: SDF Function, SDF Shapes, Signed Distance Field (SDF), Signed Distance Function (SDF), Signed Distance Function Primitives

## Overview
A Signed Distance Field (SDF) Primitive Definition is a method for representing 3D geometry using closed-form analytical functions that return the Euclidean distance from any query point to the nearest surface, along with a sign indicating whether the point is inside (negative) or outside (positive) the object [S2, S3, S8, S9, S15, unofficial]. It solves the problem of defining complex scene geometry without explicit mesh tessellation, enabling efficient ray marching by providing a conservative lower bound on the distance to the surface, which guarantees that stepping along a ray by this distance will not overshoot the geometry [S8, S15, unofficial]. Unlike [Constructive SDF Modeling (Min Combination)](871-constructive-sdf-modeling-min-combination.md) which combines primitives, or [SDF Transformation](1086-sdf-transformation.md) which modifies coordinates, this method focuses on the exact analytical evaluation of canonical shapes (spheres, boxes, tori, etc.) [G].

## How it works
**Inputs:** A 3D query point $p$ (typically `vec3`), and primitive-specific parameters (e.g., radius, center, half-extents).
**Outputs:** A scalar float representing the signed distance $d$.

**Data Structures:**
Primitives are defined by their parameters. Common layouts include:
- Sphere: Center $c$ (`vec3`), Radius $r$ (`float`) [S14, unofficial].
- Box: Position $p_{box}$ (`vec3`), Half-extents $b$ (`vec3`) [S6, S14, unofficial]. Note: Some sources use full size and divide by 2 internally [S14, unofficial].
- Cylinder: Center in XZ plane $p_{xz}$ (`vec2`), Radius $r$ (`float`), Half-height $h$ (`float`) [S14, unofficial].
- Torus: Major radius $R_{out}$ (`float`), Minor radius $R_{in}$ (`float`) [S14, unofficial].
- Plane: Normal $n$ (`vec3`), Offset $d_{offset}$ (`float`) [S14, unofficial].

**Steps:**
1. Transform the query point $p$ into the primitive's local coordinate system if the primitive is not centered at the origin or aligned with the axes. For a sphere centered at $c$, compute $p' = p - c$ [S2, S11, unofficial].
2. Compute the unsigned distance from the transformed point to the primitive's geometric boundary using the specific analytical formula [S2, S15, unofficial].
3. Determine the sign:
   - If the point is outside the surface, $d > 0$.
   - If the point is on the surface, $d = 0$.
   - If the point is inside the surface, $d < 0$ [S2, S9, S15, unofficial].
4. Return $d$.

**Formulas:**
- **Sphere:** $d(p) = \|p - c\| - r$ [S11, S14, unofficial]. For a unit sphere at origin: $f(p) = \sqrt{p_x^2 + p_y^2 + p_z^2} - 1.0$ [S3, unofficial].
- **Box (Exact):** Let $d = |p| - b$. Then $d_{box} = \|\max(d, 0)\| + \min(\max(d_x, \max(d_y, d_z)), 0)$ [S6, S14, unofficial]. A cheaper approximation overestimates corner distance: $d_{cheap} = \max(|p_x|, |p_y|, |p_z|) - b_{max}$ [S6, unofficial].
- **Torus:** $d = \|(\|p_{xz}\| - R_{out}, p_y)\| - R_{in}$ [S14, unofficial].
- **Cylinder (Infinite):** $d = \|p_{xz} - p_{center}\| - r$ [S14, unofficial].
- **Cylinder (Capped):** $d_x = \|p_{xz}\| - r$, $d_y = |p_y| - h$. $d = \min(\max(d_x, d_y), 0) + \|\max(d_x, d_y, 0)\|$ [S14, unofficial].
- **Cone:** $d = \max(\sqrt{x^2+z^2}\cos(\phi) - |y|\sin(\phi), \max(y-h, -y))$, where $\phi = \arctan(r/h)$ [S14, unofficial].
- **Plane:** $d = p \cdot n + d_{offset}$ [S14, unofficial].
- **Capsule:** $d(p) = \text{dist}(p, \text{segment}(a, b)) - r$ [S13, unofficial].

**Pseudocode:**
```python
import math

def length(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def dot(v1, v2):
    return v1[0]*v2[0] + v1[1]*v2[1] + v1[2]*v2[2]

def vec3_sub(v1, v2):
    return (v1[0]-v2[0], v1[1]-v2[1], v1[2]-v2[2])

def vec3_abs(v):
    return (abs(v[0]), abs(v[1]), abs(v[2]))

def vec3_max(v1, v2):
    return (max(v1[0], v2[0]), max(v1[1], v2[1]), max(v1[2], v2[2]))

def vec3_min(v1, v2):
    return (min(v1[0], v2[0]), min(v1[1], v2[1]), min(v1[2], v2[2]))

def vec3_max_component(v):
    return max(v[0], v[1], v[2])

def vec3_min_component(v):
    return min(v[0], v[1], v[2])

def sdf_sphere(p, center, radius):
    """
    Returns signed distance from p to sphere.
    Positive outside, negative inside.
    """
    dist_to_center = length(vec3_sub(p, center))
    return dist_to_center - radius

def sdf_box(p, center, half_extents):
    """
    Returns signed distance from p to box.
    p is in local space (center at origin).
    """
    # Distance from point to box surface, ignoring sign
    d = vec3_abs(p)
    d = vec3_sub(d, half_extents)
    
    # Positive part: distance to faces
    pos_part = vec3_max(d, (0,0,0))
    dist_faces = length(pos_part)
    
    # Negative part: distance to edges/corners (inside)
    neg_part = vec3_min(d, (0,0,0))
    dist_edges = vec3_max_component(neg_part)
    
    if dist_edges[0] < 0 or dist_edges[1] < 0 or dist_edges[2] < 0:
        # Inside the box
        return -dist_edges
    else:
        # Outside the box
        return dist_faces

def sdf_torus(p, major_radius, minor_radius):
    """
    Torus centered at origin, aligned with Y axis.
    """
    # Project to XZ plane
    xz_dist = math.sqrt(p[0]**2 + p[2]**2)
    # Vector from center of tube cross-section to point
    q = (xz_dist - major_radius, p[1])
    return length(q) - minor_radius

def sdf_cylinder_capped(p, radius, half_height):
    """
    Cylinder aligned with Y axis, centered at origin.
    """
    dx = math.sqrt(p[0]**2 + p[2]**2) - radius
    dy = abs(p[1]) - half_height
    
    # Distance to side and caps
    dist_side = max(dx, 0)
    dist_cap = max(dy, 0)
    
    # Combine
    # If inside side or cap, take negative max
    inside_side = dx < 0
    inside_cap = dy < 0
    
    if inside_side or inside_cap:
        return -max(dx, dy)
    else:
        return length((dist_side, dist_cap, 0)) # Simplified 2D length for outside

def sdf_plane(p, normal, offset):
    """
    Plane defined by normal n and distance from origin offset.
    n must be normalized.
    """
    return dot(p, normal) + offset
```

**Parameters:**
- **Gradient Step Size:** For normal approximation via finite differences, a small $\epsilon$ is used, typically $0.0001$ [S11, unofficial].
- **Smoothing Constant ($k$):** When blending SDFs (e.g., `smin`), $k$ controls the transition width, e.g., $0.2$ [S11, unofficial].
- **Lipschitz Bound:** The SDF guarantees that for any point $p$ outside geometry, the ray can safely advance by $|sdf(p)|$ [S15, unofficial].

**Edge Cases and Pitfalls:**
- **Non-watertight Geometry:** Not every shape has a closed-form SDF. Arbitrary meshes require approximate SDFs (e.g., baked into 3D textures or BVH traversal) [S15, unofficial].
- **Numerical Precision:** The `fBlob` function is noted as not a correct distance bound [S6, unofficial].
- **Performance:** Generalized Distance Functions (GDF) with variable exponents can be slow and may fail to unroll loops on certain hardware (e.g., Nvidia 350.12), causing slowdowns [S13, unofficial]. Specialized implementations are recommended [S6, unofficial].
- **Discontinuities:** Taking the `min()` or `max()` of two SDFs yields a sharp discontinuity in the derivative, which can affect shading if normals are computed via finite differences [S11, unofficial].

## Subtopics

### [SDF Primitives & Operations](1075-sdf-primitives-operations.md)
Provides foundational analytical functions and geometric operators (union, intersection, difference) for defining scene geometry implicitly. It focuses on base primitives and immediate application of min/max operators, distinct from [SDF Transformation](1086-sdf-transformation.md) which modifies coordinates or [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md) which combines distinct shapes.

### [SDF Transformation](1086-sdf-transformation.md)
Applies geometric transformations (rotation, translation, scaling) by manipulating query point coordinates before evaluation. It preserves mathematical integrity for ray marching, unlike [Uniform Scaling of SDFs](2394-uniform-scaling-of-sdfs.md) which handles exact distance compensation, or [Lipschitz Transformation Bounds](1557-lipschitz-transformation-bounds.md) which derives safety bounds for non-linear deformations.

### [k-SDF](9530-k-sdf.md)
A representation for real-time view synthesis of fuzzy geometries using $k$ lightweight, semi-transparent mesh shells rendered via rasterization. It bounds sampling locations per ray ($3 \le k \le 9$) and is sorting-free, enabling real-time rendering on low-cost smartphones, unlike [3D Gaussian Splatting](52-3d-gaussian-splatting.md) or [SMERF](53-smurf.md).

### [SDF Representation DOP](12996-sdf-representation-dop.md)
Creates a volumetric SDF from geometry for fast inside/outside testing in collision detection. It focuses on topological correctness for rigid body dynamics rather than visual appearance, utilizing modes like Laser Scanning for non-watertight geometry.

### SDF Grid Modeling
A float grid where active values describe the distance to a surface (negative inside, positive outside, zero on surface). It allows for efficient boolean operations with smooth transitions, which are hard to perform on meshes, and supports smoothing via SDF Grid Mean nodes [S16, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per primitive evaluation. Scene complexity scales with the number of primitives combined via CSG operators.
- **Memory Complexity:** $O(1)$ for procedural primitives. No mesh storage required.
- **Performance:** Ray marching with SDFs is significantly faster than naive ray-triangle intersection for complex procedural scenes because the distance field allows large, safe steps along the ray [S1, S8, unofficial].
- **Strengths:** Exact distance guarantees prevent overshooting [S8, unofficial]; smooth gradients enable ambient occlusion and soft shadows [S3, unofficial]; compact representation of complex shapes [S9, unofficial].
- **Limitations:** No closed-form SDF exists for arbitrary meshes [S15, unofficial]; sharp CSG operations create non-smooth normals [S11, unofficial]; GDF loops may suffer from driver-specific performance issues [S13, unofficial].
- **When to Use:** Procedural geometry, ray marching, implicit modeling.
- **When Not to Use:** Arbitrary mesh data without preprocessing, or when exact triangle-level precision is required without approximation [S15, unofficial].

## Background
The concept of Signed Distance Functions as implicit surfaces for representing real surfaces was popularized in computer graphics for ray marching and implicit modeling [S2, S7, unofficial]. The term "Signed Distance Field" is often associated with the work of Inigo Quilez, who provided a comprehensive library of analytical SDF primitives and techniques for ray marching [S1, S7, S11, unofficial]. The method is widely used in real-time graphics, voxel-based modeling, and neural rendering (where SDFs are learned to define clear, noise-free geometry compared to density fields) [S5][S15, unofficial].
