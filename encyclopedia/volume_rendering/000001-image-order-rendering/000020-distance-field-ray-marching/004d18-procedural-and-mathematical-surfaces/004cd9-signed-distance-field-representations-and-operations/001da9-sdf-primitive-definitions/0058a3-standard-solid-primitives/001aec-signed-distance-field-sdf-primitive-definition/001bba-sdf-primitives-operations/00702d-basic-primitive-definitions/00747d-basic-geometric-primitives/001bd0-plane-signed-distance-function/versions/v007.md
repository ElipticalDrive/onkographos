# Plane Signed Distance Function

Also called: Plane SDF, Plane distance, Signed Distance Function (SDF) for Plane, Signed Plane, sdPlane

## Overview
The Plane Signed Distance Function (SDF) computes the exact Euclidean distance from a query point to an infinite plane, providing a signed scalar indicating which side of the plane the point occupies. It serves as the foundational building block for constructing complex implicit surfaces via boolean operations (union, intersection, difference) and serves as a ground plane in ray marching scenes. Unlike the [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md) or [Signed Box Distance Function](1092-signed-box-distance-function.md), the plane is unbounded and linear, making it computationally trivial but essential for defining scene boundaries and combining with other primitives.

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $p \in \mathbb{R}^3$ and plane parameters defining the plane's orientation and position.
*   **Output:** A scalar $d \in \mathbb{R}$ representing the signed distance.

**Data Structures:**
The plane is typically defined by two equivalent parameter sets. Implementers must choose one representation consistently:
1.  **Normal-Offset:** A unit normal vector $n \in \mathbb{R}^3$ and a scalar offset $h \in \mathbb{R}$. The plane equation is $n \cdot x + h = 0$.
2.  **Normal-Point:** A unit normal vector $n \in \mathbb{R}^3$ and a point $r \in \mathbb{R}^3$ lying on the plane. The offset is derived as $h = -n \cdot r$.

**Numbered Steps:**
1.  **Validate Normalization:** Ensure the normal vector $n$ is normalized ($\|n\| = 1$). If not, normalize it. Failure to do so results in incorrect distance scaling [S2, unofficial].
2.  **Compute Dot Product:** Calculate the dot product of the query point $p$ and the normal vector $n$.
3.  **Apply Offset:** Add the offset $h$ to the dot product result.
4.  **Return Result:** The result is the signed distance $d$.

**Formulas:**
The primary formula, consistent across sources [S1, unofficial], [S2, unofficial], [S3, unofficial], is:
$$ d = p \cdot n + h $$
Where:
*   $p$ is the query point.
*   $n$ is the unit normal vector.
*   $h$ is the signed distance from the origin to the plane along the normal. A positive $h$ places the plane "behind" the origin relative to the normal direction.

An alternative formulation using a point $r$ on the plane [S6] is:
$$ d = p \cdot n - r \cdot n $$
Which simplifies to the above where $h = -r \cdot n$.

Another representation using homogeneous plane coefficients $n = (n_x, n_y, n_z, n_w)$ [S2, unofficial] is:
$$ d = n_{xyz} \cdot p + n_w $$
Where $n_{xyz}$ must be normalized.

**Parameters with Typical Values:**
*   $n$: Unit vector. Typical values depend on scene orientation (e.g., $(0, 1, 0)$ for a horizontal ground plane).
*   $h$: Scalar. For a ground plane at $y=0$ with normal $(0,1,0)$, $h=0$. For a plane at $y=-5$ with normal $(0,1,0)$, $h=5$.

**Edge Cases and Pitfalls:**
*   **Unnormalized Normal:** If $n$ is not a unit vector, the result is not a Euclidean distance but a scaled projection [S2, unofficial].
*   **Sign Convention:** The sign of $d$ indicates the side. $d < 0$ is typically "inside" or "below" the plane (in the direction opposite to $n$), and $d > 0$ is "outside" or "above" (in the direction of $n$), adhering to the parent's [Shared principles](23026-basic-geometric-primitives.md).
*   **Infinite Extent:** The function assumes an infinite plane. It does not account for clipping planes or finite bounds unless combined with other primitives.

**Pseudocode:**
```python
def sd_plane(p: Vector3, n: Vector3, h: float) -> float:
    """
    Computes the signed distance from point p to a plane defined by unit normal n and offset h.
    
    Args:
        p: Query point (Vector3).
        n: Plane normal vector (Vector3). MUST be normalized.
        h: Offset from origin.
        
    Returns:
        Signed distance d.
    """
    # Guard: Ensure normal is normalized to guarantee correct Euclidean distance [S2, unofficial]
    if length(n) != 1.0:
        n = normalize(n)
        
    # Formula: d = p . n + h [S1, unofficial][S2, unofficial][S3, unofficial]
    d = dot(p, n) + h
    
    return d

def sd_plane_from_point(p: Vector3, n: Vector3, r: Vector3) -> float:
    """
    Computes the signed distance from point p to a plane defined by unit normal n and a point r on the plane.
    
    Args:
        p: Query point (Vector3).
        n: Plane normal vector (Vector3). MUST be normalized.
        r: A point lying on the plane (Vector3).
        
    Returns:
        Signed distance d.
    """
    # Guard: Ensure normal is normalized [S2, unofficial]
    if length(n) != 1.0:
        n = normalize(n)
        
    # Derive h from point r: h = - (r . n) [S6]
    h = -dot(r, n)
    
    # Compute distance using normal-offset formula
    d = dot(p, n) + h
    
    return d
```

## Operating characteristics
*   **Time Complexity:** $O(1)$. The computation involves a single dot product and one addition.
*   **Memory Complexity:** $O(1)$. Requires storing the normal vector and offset (or a point on the plane).
*   **Measured Performance:** Negligible compared to other primitives. It is often the fastest primitive to evaluate.
*   **Strengths:** Exact solution, differentiable everywhere (gradient is constant $n$), extremely cheap.
*   **Limitations:** Represents only an infinite plane. Cannot model bounded planar surfaces without combination with other primitives (e.g., intersection with a box).
*   **When to use:** As a ground plane, a clipping plane, or a component in boolean operations.
*   **When not to use:** When a finite planar surface is required without additional logic.

## Background
The plane SDF is a fundamental primitive in implicit surface rendering, originating from the work on sphere tracing and geometric modeling in the 1990s. Hart (1994) formalized the signed distance function for a plane as $f(\mathbf{x}) = \mathbf{x} \cdot \mathbf{n} - h$ [S5, unofficial]. This formulation allows for the easy combination of the plane with other objects, such as spheres, using boolean operations like minimum for union [S5, unofficial]. It is widely used in ray marching tutorials and libraries (e.g., Inigo Quilez's GLSL SDF primitives [S2, unofficial]) as the simplest example of a distance function.
