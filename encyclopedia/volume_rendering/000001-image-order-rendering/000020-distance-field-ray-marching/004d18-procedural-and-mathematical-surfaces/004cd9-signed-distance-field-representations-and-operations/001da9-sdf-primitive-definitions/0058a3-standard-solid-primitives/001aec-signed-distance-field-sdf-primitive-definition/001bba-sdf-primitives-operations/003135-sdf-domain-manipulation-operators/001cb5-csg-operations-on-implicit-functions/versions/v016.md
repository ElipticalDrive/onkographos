# CSG Operations on Implicit Functions

Also called: CSG Operations, Boolean SDF operators, SDF Boolean Operators, SDF Boolean Operations, CSG implicit surfaces, Constructive Solid Geometry with SDFs, CSG with SDFs, CSG SDF combination, CSG Operations for SDFs

## Overview
CSG Operations on Implicit Functions combine multiple Signed Distance Functions (SDFs) into a single implicit function using Boolean logic (Union, Intersection, Difference) [S1][S3, S7, unofficial]. This method solves the problem of defining complex composite shapes from simple primitives within a volumetric or ray-marched context [S7, unofficial]. It differs from [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md) by operating on scalar field values rather than transforming the input position vector $\mathbf{p}$ [S1][S3, unofficial]. It differs from [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md) by providing specific implementation strategies for discrete voxel buffers and classification look-up tables, whereas this method focuses on the direct arithmetic composition of scalar fields for ray marching [S1][S7, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two SDF functions $f(\mathbf{p})$ and $g(\mathbf{p})$ returning signed distances, and a Boolean operation type (Union, Intersection, Difference).
*   **Outputs:** A new SDF function $h(\mathbf{p})$ representing the combined geometry.

**Data Structures:**
The operations are typically implemented as nodes in a binary tree structure [S2, S4, unofficial].
*   **Node:** Contains an `operation` enum (`Union`, `Intersection`, `Difference`) and pointers to two child nodes (`left`, `right`) [S2, S4, unofficial].
*   **Leaf:** Contains a base SDF function and an optional material ID [S2, unofficial].
*   **Evaluation:** The tree is evaluated recursively or iteratively. For a query point $\mathbf{p}$, the children are evaluated, and the result is computed using the node's operation [S2, S4, unofficial].

**Formulas:**
The Boolean operations on sets translate directly to arithmetic operations on SDF values [S1][S3, unofficial][S8][S13, unofficial]:

1.  **Union ($A \cup B$):** The distance to the union is the minimum of the distances. A point is inside the union if it is inside either shape.
    $$ h(\mathbf{p}) = \min(f(\mathbf{p}), g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, unofficial]

2.  **Intersection ($A \cap B$):** The distance to the intersection is the maximum of the distances. A point is inside the intersection only if it is inside both shapes. Note that this provides a signed distance *bound*, not necessarily the exact SDF, because the closest point in the intersection may not be the closest point in either individual shape [S8][S13, unofficial].
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, unofficial]

3.  **Difference ($A \setminus B$):** This is equivalent to the intersection of $A$ with the complement of $B$. The complement of an SDF is obtained by negating its value.
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), -g(\mathbf{p})) $$
    [S1][S3, unofficial][S8][S9, S10, S12, S13, unofficial]

4.  **Negation (Complement):** Inverts the inside/outside status.
    $$ h(\mathbf{p}) = -f(\mathbf{p}) $$
    [S1, S8]

5.  **XOR:** Exclusive OR, representing points inside exactly one shape.
    $$ h(\mathbf{p}) = \max(\min(f(\mathbf{p}), g(\mathbf{p})), -\max(f(\mathbf{p}), g(\mathbf{p}))) $$
    [S10, unofficial]

**Pseudocode:**
The following Python-like pseudocode implements the recursive evaluation of a CSG tree for ray marching [S2, S3, S9, unofficial].

```python
import math

def evaluate_csg_tree(node, p):
    """
    Recursively evaluate a CSG tree node at point p.
    
    Args:
        node: A dictionary or object representing a tree node.
              If it is a Leaf, it has a 'sdf' function.
              If it is a Node, it has 'operation', 'left', and 'right'.
        p: A 3D vector (tuple or list of 3 floats) representing the query point.
        
    Returns:
        float: The signed distance to the combined surface.
    """
    # Base case: Leaf node
    if node['type'] == 'Leaf':
        return node['sdf'](p)
    
    # Recursive case: Internal node
    left_dist = evaluate_csg_tree(node['left'], p)
    right_dist = evaluate_csg_tree(node['right'], p)
    
    op = node['operation']
    
    if op == 'Union':
        # Union: min of distances
        return min(left_dist, right_dist)
    elif op == 'Intersection':
        # Intersection: max of distances
        return max(left_dist, right_dist)
    elif op == 'Difference':
        # Difference: max of left and negated right
        return max(left_dist, -right_dist)
    else:
        raise ValueError(f"Unknown operation: {op}")

def union_sdf(dist_a, dist_b):
    return min(dist_a, dist_b)

def intersection_sdf(dist_a, dist_b):
    return max(dist_a, dist_b)

def difference_sdf(dist_a, dist_b):
    return max(dist_a, -dist_b)
```

**Parameters:**
*   **k (Smoothness):** For smooth variants (see Subtopics), a blending factor $k$ controls the radius of the fillet. Typical values are $0.1$ to $1.0$ [S4, S11, unofficial].

**Edge Cases and Pitfalls:**
1.  **Scaling:** When scaling an SDF primitive, the input coordinates must be scaled by the inverse of the scale factor, and the output distance must be scaled by the scale factor to maintain correct distance values [S3, unofficial].
2.  **Subtraction Artifacts:** The formula $\max(-a, b)$ is exact only when the surface of $A$ is entirely contained within $B$. If $A$ pokes through the boundary of $B$, the resulting SDF is not Lipschitz-1, and sphere marching may skip surfaces. An EPSILON correction or tightened step size is required in those regions [S12, unofficial].
3.  **DeMorgan’s Theorem:** DeMorgan’s theorem (intersection = complement of union of complements) does not work directly with min/max operators for distance bounds because the minimum operator is not complemented properly. Using `max` for intersection ensures the bound holds [S8].
4.  **Material Changes:** When using CSG with discrete voxel buffers or polygonizers, material changes at CSG boundaries can cause drastic color changes if not treated as surface boundaries [S14, unofficial].

## Subtopics

### Smooth SDF Boolean Composition
A method using smooth approximations of Boolean operations to create rounded fillets instead of sharp edges [S15, unofficial]. It differs from standard CSG by providing continuous derivatives, which can be beneficial for rendering and optimization [S15, unofficial].
*   **Smooth Union (OR):** $f_{or} = f_1 + f_2 + \sqrt{f_1^2 + f_2^2}$ [S15, unofficial]
*   **Smooth Intersection (AND):** $f_{and} = f_1 + f_2 - \sqrt{f_1^2 + f_2^2}$ [S15, unofficial]
*   **Smooth Difference:** $f_{sub} = f_{and}(f_1, -f_2)$ [S15, unofficial]
*   **Parameters:** `inside_positive` flag to invert output if positive values represent interior [S15, unofficial].

### Patch-wise Merge Loss
A loss term used in neural implicit surface representations to ensure the zero-level set of the merged implicit function accurately reproduces target geometry via Boolean operations [S16]. It involves building a CSG tree for connected components in merge cells and assigning loss to involved patches [S16].

## Operating characteristics
*   **Time Complexity:** For ray marching, each CSG node evaluation is $O(1)$ per query point. The total time is proportional to the depth of the CSG tree and the number of marching steps. For discrete voxel generation, material index generation is $O(n^3)$ and edge generation is $O(3 \times n^3)$ [S1].
*   **Memory Complexity:** Depends on the CSG tree size. For discrete methods, arrays must be initialized to maximum potential edge size to avoid resizing [S1].
*   **Strengths:** Simple to implement, efficient for ray marching, allows complex geometry from simple primitives [S3, S7, unofficial].
*   **Limitations:** Intersection and Difference operations do not always produce exact SDFs (only bounds), which can affect marching accuracy [S8][S12, unofficial]. Sharp edges can cause aliasing or require smoothing [S15, unofficial].
*   **When to use:** Ideal for ray marching scenes with composite shapes [S7, unofficial].
*   **When not to use:** When exact SDF bounds are critical for all operations, or when sharp, non-smooth intersections are desired without post-processing [S8][S12, unofficial].

## Background
CSG on SDFs was popularized in the context of ray marching and shader programming, notably by Iñigo Quilez and Jamie Wong in the mid-2010s [S3, S12, unofficial]. The mathematical foundation relies on the properties of min and max operators on implicit surfaces, dating back to Ricci (1974) [S8]. It is widely used in real-time graphics, procedural generation, and educational demos due to its simplicity and visual appeal [S3, S7, unofficial].
