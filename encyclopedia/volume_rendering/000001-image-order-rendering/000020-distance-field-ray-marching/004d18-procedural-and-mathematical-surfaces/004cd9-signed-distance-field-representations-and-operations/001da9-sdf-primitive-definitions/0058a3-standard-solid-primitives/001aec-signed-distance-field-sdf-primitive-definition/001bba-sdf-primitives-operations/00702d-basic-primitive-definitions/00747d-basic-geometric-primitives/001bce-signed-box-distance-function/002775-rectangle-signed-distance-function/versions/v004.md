# Rectangle Signed Distance Function

Also called: 2D Rectangle SDF, sdRect

## Overview
Computes the exact Euclidean distance from a query point to the boundary of an axis-aligned rectangle centered at the origin in 2D space. It distinguishes itself from the [Signed Box Distance Function](1092-signed-box-distance-function.md) by operating in two dimensions, reducing computational overhead for planar primitives, and serving as the foundational 2D case for higher-dimensional box SDFs.

## How it works
**Inputs:**
- $p$: Query point in 2D space ($\mathbb{R}^2$).
- $hsize$: Half-extents of the rectangle ($\mathbb{R}^2$), defining the rectangle as $[-hsize_x, hsize_x] \times [-hsize_y, hsize_y]$.

**Outputs:**
- $d$: Signed distance. Positive outside, negative inside, zero on boundary.

**Data Structures:**
- Vectors $p$ and $hsize$ are 2-component floating-point vectors.

**Steps:**
1. Calculate the vector $dv$ representing the displacement from the rectangle's boundary to the query point, clamped to zero for components inside the bounds:
   $$dv = |p| - hsize$$
   where $|p|$ is the component-wise absolute value of $p$.
2. Calculate the distance to the exterior (or zero if inside):
   $$outside = \| \max(dv, 0) \|$$
   where $\max(dv, 0)$ applies the maximum operator component-wise, and $\|\cdot\|$ is the Euclidean norm.
3. Calculate the distance to the interior (or zero if outside):
   $$inside = \min(\max(dv_x, dv_y), 0)$$
   This term is non-zero only when the point is inside the rectangle's infinite extrusion but outside the rectangle itself (i.e., in the corner regions if we consider the box logic, but for a 2D rectangle, this specific formula handles the transition correctly by checking if both components are negative).
4. Return the sum:
   $$d = outside + inside$$

**Pseudocode:**
```python
def sdRect(p: Vec2, hsize: Vec2) -> float:
    # Component-wise absolute value
    abs_p = Vec2(abs(p.x), abs(p.y))
    
    # Displacement from half-extents
    dv = Vec2(abs_p.x - hsize.x, abs_p.y - hsize.y)
    
    # Clamp negative components to zero for outside distance
    dv_clamped = Vec2(max(dv.x, 0.0), max(dv.y, 0.0))
    
    # Euclidean norm of the clamped vector
    outside_dist = sqrt(dv_clamped.x**2 + dv_clamped.y**2)
    
    # Minimum of the components, clamped to zero for inside distance
    # min(max(dv.x, dv.y), 0.0)
    min_component = min(dv.x, dv.y)
    inside_dist = min(min_component, 0.0)
    
    return outside_dist + inside_dist
```

**Edge Cases:**
- If $hsize$ contains zeros, the rectangle degenerates to a line or point. The formula remains valid but may exhibit reduced precision near the degenerate geometry.
- Precision issues may arise if $p$ is very close to the boundary and floating-point errors cause sign flips.

## Subtopics

### Cube Signed Distance Function
A 3D extension of the rectangle SDF for a cube centered at the origin with side length 2.0 (half-extents of 1.0). It follows the same logic: $d = \| \max(|p| - 1, 0) \| + \min(\max(|p|_x, |p|_y, |p|_z), 0)$. It is chosen when 3D volumetric primitives are required. [S2, unofficial]

### Box Frame SDF
A primitive SDF representing a hollow box frame. It is defined by dimensions $(x, y, z)$ and a thickness parameter. In the source implementation, it is identified by `op_id 5` and stored in an `SdfOpSpecificBlock` where `vec4s[0]` holds dimensions and `floats[0]` holds thickness. It is used for creating wireframe-like structures or hollow containers. [S3, unofficial]

## Operating characteristics
- **Time Complexity:** $O(1)$ constant time. Requires a few arithmetic operations, a square root, and comparisons.
- **Memory Complexity:** $O(1)$ auxiliary space.
- **Strengths:** Exact distance calculation; no approximation errors; efficient for ray marching in 2D.
- **Limitations:** Limited to axis-aligned rectangles. For rotated rectangles, the [Oriented Box2D SDF](4370-oriented-box2d-sdf.md) is required.

## Background
The 2D rectangle SDF is a standard primitive in Signed Distance Field rendering, popularized by Inigo Quilez's online tutorials and widely adopted in shader coding communities. It is a fundamental building block for procedural geometry in real-time graphics.
