# Infinite Tiling with Modulo

Also called: Infinite Crystal Grid SDF, Infinite Tiling via Modulo, Modulo SDF, Modulo Tiling, Repeat function, Tiling SDFs, Tiling via Modulo

## Overview
Infinite Tiling with Modulo is a technique for rendering infinite, repeating patterns of a single Signed Distance Field (SDF) primitive by folding space using the modulo operator [S1, S2, unofficial]. It allows a single primitive SDF to be tiled infinitely at essentially zero extra computational cost, enabling the creation of ray-marched fractals like Mandelbulbs and Menger sponges [S3, unofficial]. Unlike explicit mesh instances, it generates infinite geometry procedurally by mapping query points into a periodic local coordinate system [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Query point $\mathbf{p} \in \mathbb{R}^3$, tile period $c \in \mathbb{R}$ (scalar or vector).
*   **Output:** Transformed point $\mathbf{q} \in \mathbb{R}^3$ mapped to the fundamental tile cell.

**Data Structures:**
No persistent data structures are required. The operation is stateless and computed per-sample.

**Steps:**
1.  **Calculate Periodic Coordinate:** Apply the modulo operation to the query point $\mathbf{p}$ using the period $c$. To center the tile at the origin (ensuring the SDF primitive is evaluated symmetrically), an offset is typically added before the modulo, and the result is shifted back.
    $$ \mathbf{q} = \text{mod}(\mathbf{p} + \mathbf{offset}, c) - \frac{c}{2} $$
    Where $\mathbf{offset}$ is often chosen to center the primitive within the tile (e.g., $\mathbf{offset} = c/2$) [S1, S2, unofficial].
2.  **Evaluate SDF:** Evaluate the base SDF primitive $f(\mathbf{q})$ using the transformed point $\mathbf{q}$ [S2, unofficial].

**Parameters:**
*   $c$: The period or size of the tile. Lower values make objects appear closer; higher values make them further apart [S2, unofficial].
*   $\mathbf{offset}$: Added before modulo to center the tile at the origin. A common value is $c/2$ [S1, unofficial].

**Pseudocode:**
```python
def repeat(p: Vector3, c: float) -> Vector3:
    """
    Maps point p into the fundamental tile cell of size c centered at origin.
    Implements: q = mod(p + c/2, c) - c/2
    """
    # Add offset to center the tile at origin before modulo
    # c/2 is the standard offset to ensure symmetry around 0
    offset = c / 2.0
    
    # Apply modulo
    # Note: Standard modulo operator behavior varies by language.
    # In GLSL/HLSL, mod(x, y) returns x - y * floor(x / y).
    # This ensures the result is in [0, y).
    q = mod(p + offset, c)
    
    # Shift back to center at origin: result in [-c/2, c/2)
    q = q - offset
    
    return q

def infinite_tile_sdf(p: Vector3, c: float, base_sdf_func) -> float:
    """
    Evaluates an SDF for an infinite tiling of a base primitive.
    """
    # Transform point to local tile coordinate
    q = repeat(p, c)
    
    # Evaluate base SDF at transformed point
    # The base_sdf_func must satisfy Lipschitz condition 1
    distance = base_sdf_func(q)
    
    return distance
```

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point precision errors in the modulo operation can cause visible seams or artifacts at tile boundaries if the SDF is not continuous or if the primitive touches the boundary [S2, unofficial].
*   **Boundary Conditions:** If the primitive SDF extends to the boundary of the tile, the distance field may become discontinuous or incorrect at the tile edges because the modulo operation folds space abruptly. The primitive should be strictly contained within the tile cell (i.e., $f(\mathbf{q}) > 0$ at the tile boundaries) to ensure correct distance values [S2, unofficial].
*   **Negative Coordinates:** Standard modulo implementations may behave differently with negative inputs. The offset strategy ($\mathbf{p} + c/2$) helps normalize the input range, but care must be taken with languages where `mod` returns negative values for negative inputs [S4, unofficial].

## Subtopics

### Finite Tiling
A variant of Infinite Tiling which produces a finite number of repetitions of a shape [S4, unofficial]. It takes an additional vector $\vec{l}$ as input, where $\vec{l}$ is the corner of the box used to limit the number of repetitions of the shape [S4, unofficial]. This is achieved by combining the modulo tiling with a box SDF subtraction or by clamping the transformed coordinates [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The modulo operation is a constant-time arithmetic operation.
*   **Memory Complexity:** $O(1)$. No additional memory is required beyond the base SDF evaluation.
*   **Performance:** Enables rendering of infinite geometry at essentially zero extra cost compared to a single primitive [S3, unofficial]. This makes it suitable for real-time ray marching of fractals and dense patterns.
*   **Strengths:** Extremely efficient for creating infinite repeating structures; no mesh generation or instance management required.
*   **Limitations:** Cannot represent non-repeating or sparse infinite structures; requires careful primitive sizing to avoid boundary artifacts; limited to periodic patterns.
*   **When to use:** When rendering infinite grids, crystals, or fractals where the pattern repeats periodically.
*   **When not to use:** When the scene requires non-periodic geometry, finite instances with varying scales/rotations (unless combined with other techniques), or when the primitive size is comparable to the tile size (leading to self-intersection artifacts).

## Background
The technique is a fundamental building block in procedural ray marching, popularized by Inigo Quilez and others in the demoscene and real-time graphics community [S2, S3, unofficial]. It leverages the mathematical property of the modulo function to create periodic space folding, allowing a single analytical surface to represent an infinite array of objects [S2, unofficial]. It is widely used in the creation of ray-marched fractals such as Mandelbulbs and Menger sponges [S3, unofficial].
