# Boolean Operations on Distance Fields

Also called: Boolean Operations on SDFs, SDF Boolean Operations, SDF Boolean Operators, SDF Boolean Union, SDF Min, Boolean Union on Distance Fields

## Overview
Boolean operations on Signed Distance Fields (SDFs) are Constructive Solid Geometry (CSG) primitives that combine two or more base SDFs to create complex shapes by performing set-theoretic unions, intersections, and differences [S2, S4, unofficial][S8]. Unlike standard geometric primitives, these operations allow the construction of arbitrary topology from simple building blocks without requiring mesh generation [S2, unofficial]. The method is distinguished by its reliance on component-wise minimum and maximum functions to preserve the distance field property, ensuring that the resulting function remains a valid distance field for ray marching [S4, S16, unofficial].

## How it works
### Inputs and Outputs
- **Inputs**: Two signed distance functions, $d_1(p)$ and $d_2(p)$, evaluated at a point $p \in \mathbb{R}^3$. Optionally, material identifiers or markers associated with each primitive [S6, S13, unofficial].
- **Outputs**: A new signed distance function $d_{result}(p)$ representing the combined shape, and optionally a material ID [S6, S13, unofficial].

### Data Structures
The core data structure is the scalar signed distance value. In implementations that track material identity, the output is a pair $(d, m)$, where $d$ is the distance and $m$ is an integer material ID [S6, S13, unofficial].
- **Scalar SDF**: A single floating-point value representing distance.
- **Vector SDF (with ID)**: A structure or vector containing:
  - `.x` (or first component): The signed distance $d$.
  - `.y` (or second component): The material ID $m$ [S6, S13, unofficial].

### Formulas
Let $d_1$ be the distance to the first object and $d_2$ be the distance to the second object at point $p$.

1.  **Union**: The union of two volumes is the set of points belonging to either volume. The distance is the minimum of the two distances [S4, unofficial][S8][S11, S16, unofficial]:
    $$ d_{union}(p) = \min(d_1(p), d_2(p)) $$
    [S3, S11, S14, unofficial]

2.  **Intersection**: The intersection is the set of points belonging to both volumes. The distance is the maximum of the two distances [S1, S4, S5, S11, S16, unofficial]:
    $$ d_{intersect}(p) = \max(d_1(p), d_2(p)) $$
    [S3, S11, S13, unofficial]

3.  **Difference (Subtraction)**: The difference $A - B$ removes volume $B$ from volume $A$. This is achieved by negating the distance of the subtracted object ($B$) and taking the maximum [S1, S4, unofficial][S8][S11, S14, unofficial]:
    $$ d_{diff}(p) = \max(d_1(p), -d_2(p)) $$
    [S3, S11, S14, unofficial]
    Note: Some sources define subtraction as $B - A$ using $\max(-d_1, d_2)$ [S3, S11, unofficial]. The standard convention in ray marching tutorials (e.g., [S8][S14, unofficial]) is $A - B = \max(d_A, -d_B)$.

4.  **Smooth Union (Optional)**: To avoid sharp discontinuities in the derivative at the boundary of the union, a smooth minimum can be used with a blending parameter $k$ [S13, S16, unofficial]:
    $$ j = \text{clamp}\left(0.5 + 0.5 \frac{d_2 - d_1}{k}, 0, 1\right) $$
    $$ d_{smooth\_union} = \text{mix}(d_2, d_1, j) - k \cdot j \cdot (1 - j) $$
    [S13, S16, unofficial]

### Pseudocode
The following Python-like pseudocode implements the standard Boolean operations. It assumes input functions `sdf1(p)` and `sdf2(p)` return a tuple `(distance, material_id)`.

```python
def op_union(a, b):
    """
    Computes the union of two SDF results.
    a, b: tuples (distance, material_id)
    Returns: (min_distance, material_id_of_min)
    """
    d1, m1 = a
    d2, m2 = b
    
    if d1 < d2:
        return (d1, m1)
    else:
        return (d2, m2)

def op_intersection(a, b):
    """
    Computes the intersection of two SDF results.
    a, b: tuples (distance, material_id)
    Returns: (max_distance, material_id_of_max)
    """
    d1, m1 = a
    d2, m2 = b
    
    if d1 > d2:
        return (d1, m1)
    else:
        return (d2, m2)

def op_subtraction(a, b):
    """
    Computes the difference A - B (subtracts B from A).
    a: tuple (distance, material_id) for A
    b: tuple (distance, material_id) for B
    Returns: (max(d_a, -d_b), material_id_of_max)
    """
    d1, m1 = a
    d2, m2 = b
    
    # Negate distance of B
    neg_d2 = -d2
    neg_m2 = m2 # Material ID usually remains associated with the surface geometry
    
    if d1 > neg_d2:
        return (d1, m1)
    else:
        return (neg_d2, neg_m2)

def smooth_union(a, b, k):
    """
    Computes a smooth union of two SDF results.
    k: blending factor (positive float)
    """
    d1, m1 = a
    d2, m2 = b
    
    # Use the scalar distance for blending logic
    j = max(0.0, min(1.0, 0.5 + 0.5 * (d2 - d1) / k))
    d_smooth = (1 - j) * d1 + j * d2 - k * j * (1 - j)
    
    # Material ID selection: typically pick the one with the smaller distance
    # or the one that dominates the blend. Here we pick the closer one.
    if d1 < d2:
        return (d_smooth, m1)
    else:
        return (d_smooth, m2)
```

### Parameters
- **$k$ (Smooth Union Parameter)**: Controls the width of the blending region. Smaller values yield sharper transitions; larger values yield smoother blends. Typical values are small positive floats (e.g., 0.1 to 0.5) [S13, S16, unofficial].
- **Material ID**: An integer identifier used to track which primitive contributes to the final distance. It is passed through the operations unchanged, selected based on which distance value (min or max) was chosen [S6, S13, unofficial].

### Edge Cases and Pitfalls
1.  **Discontinuities in Derivatives**: Standard min/max operations create sharp corners where the active primitive switches. This results in discontinuous normals, which can cause artifacts in lighting calculations or shading [S16, unofficial]. Using smooth unions mitigates this but changes the geometry slightly.
2.  **Precision**: When $d_1 \approx d_2$, floating-point precision issues may cause jitter in the normal calculation if not handled carefully. The normal is typically estimated via finite differences of the combined SDF, not by selecting the normal of the winning primitive, to ensure smoothness [S1, S7, unofficial].
3.  **Inside/Outside Logic**: The sign of the distance is critical. For subtraction, negating $d_2$ flips the inside/outside status of object B. If $d_2$ is positive (outside B), $-d_2$ is negative (inside the subtracted volume). The max operation then correctly selects the boundary of A if A is outside, or the negated boundary of B if inside A [S8].

## Operating characteristics
- **Time Complexity**: $O(1)$ per evaluation, requiring two calls to the base SDFs and a constant number of arithmetic operations (min, max, negation) [S4, unofficial][S8].
- **Memory Complexity**: $O(1)$ additional memory per operation, storing only the intermediate distance values and material IDs [S6, S13, unofficial].
- **Strengths**:
  - Enables complex, hierarchical scene construction from simple primitives [S2, unofficial].
  - Maintains the distance field property, allowing efficient sphere tracing [S16, unofficial].
  - No mesh generation or topology management required [S8].
- **Limitations**:
  - Sharp boolean edges can cause shading artifacts due to normal discontinuities [S16, unofficial].
  - Smooth unions approximate the true boolean result, potentially altering the intended geometry [S13, unofficial].
  - Performance scales linearly with the number of primitives in a CSG tree, as each node requires evaluating its children [S5, unofficial].

## Background
Boolean operations on SDFs were popularized in the context of ray marching for real-time graphics, particularly through the work of Inigo Quilez and others in the demoscene and shader programming communities [S11, S16, unofficial]. The technique leverages the mathematical properties of distance functions: the distance to the union of two sets is the minimum of their distances, and the distance to the intersection is the maximum [S4, S16, unofficial]. This allows for the construction of complex implicit surfaces without explicit mesh data, a concept rooted in Constructive Solid Geometry (CSG) but adapted for continuous distance fields [S2, unofficial][S8].
