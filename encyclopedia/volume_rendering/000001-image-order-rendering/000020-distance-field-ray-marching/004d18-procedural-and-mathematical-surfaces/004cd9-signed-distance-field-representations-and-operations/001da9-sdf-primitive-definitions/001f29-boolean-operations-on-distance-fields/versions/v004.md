# Boolean Operations on Distance Fields

Also called: Boolean Operations on SDFs, SDF Boolean Operations, SDF Boolean Operators, SDF Boolean Union, SDF Min, Boolean Union on Distance Fields

## Overview
Boolean operations on Signed Distance Fields (SDFs) allow the construction of complex 3D geometry from simple primitives by combining their scalar distance values [S2, S4, unofficial][S8]. This method solves the problem of representing Constructive Solid Geometry (CSG) in ray marching without explicit mesh topology, enabling the creation of arbitrary shapes through algebraic combination of distance functions [S2, S14, unofficial]. It is distinguished from explicit mesh CSG by operating directly on the continuous scalar field, ensuring the resulting function remains a valid distance field (satisfying the Lipschitz condition) for sphere tracing .

## How it works
The method evaluates the signed distance to two primitives at a query point $\mathbf{p}$ and combines the results using component-wise minimum or maximum operations. The parent article [SDF Primitive Definitions](1578-sdf-primitive-definitions.md) defines the individual primitive SDFs $f_1(\mathbf{p})$ and $f_2(\mathbf{p})$.

### Inputs and Outputs
*   **Inputs**: Two SDF evaluation results at point $\mathbf{p}$. In the simplest scalar case, these are distances $d_1 = f_1(\mathbf{p})$ and $d_2 = f_2(\mathbf{p})$. In implementations tracking material IDs, inputs are vectors $\mathbf{a} = (d_a, \text{id}_a)$ and $\mathbf{b} = (d_b, \text{id}_b)$ [S6, S13, unofficial].
*   **Outputs**: A combined SDF value $d_{result}$ (and optionally a material ID) representing the union, intersection, or difference of the two shapes [S4, S11, unofficial].

### Data Structures
For scalar operations, no complex data structures are required beyond the primitive functions themselves. For operations tracking material identity (e.g., in [S6, S13, unofficial]), the return type is a vector:
*   `vec2` or `struct`:
    *   `.x` (or `distance`): The combined signed distance value.
    *   `.y` (or `material_id`): An integer or float identifier for the primitive contributing the minimum distance.

### Formulas
Let $d_1$ be the signed distance to the first object and $d_2$ be the signed distance to the second object.

1.  **Union**: The volume occupied by either object. The distance is the minimum of the two, as the surface is the closest boundary [S3, S4, unofficial][S8][S11, S16, unofficial].
    $$ d_{union}(\mathbf{p}) = \min(d_1, d_2) $$

2.  **Intersection**: The volume occupied by both objects. The distance is the maximum of the two, as the surface is the furthest boundary that still satisfies both [S3, S4, S5, unofficial][S8][S11, S16, unofficial].
    $$ d_{intersect}(\mathbf{p}) = \max(d_1, d_2) $$

3.  **Subtraction (Difference)**: The volume of the first object minus the second. This is achieved by negating the distance of the subtracted object ($d_2$) and taking the maximum [S1, S3, S4, unofficial][S8][S11, S14, S16, unofficial].
    $$ d_{sub}(\mathbf{p}) = \max(d_1, -d_2) $$
    *Note: Some sources define subtraction as $A - B$ using $\max(d_A, -d_B)$ [S14, unofficial], while others describe subtracting object 1 from object 2 as $\max(-d_1, d_2)$ [S3, unofficial]. The standard CSG interpretation "A minus B" (A is the base, B is the cutter) uses $\max(d_A, -d_B)$.*

4.  **Smooth Union (Optional)**: To avoid sharp creases, a smooth minimum can be used with a blending parameter $k$ [S13, S9, unofficial]:
    $$ j = \text{clamp}\left(0.5 + 0.5 \frac{d_2 - d_1}{k}, 0, 1\right) $$
    $$ d_{smooth\_union} = \text{mix}(d_2, d_1, j) - k \cdot j \cdot (1 - j) $$

### Pseudocode
The following implementation handles scalar distances and optionally tracks material IDs. It assumes `min`, `max`, `abs`, and `mix` are standard vector/math operations.

```python
def op_union(d1, id1, d2, id2):
    """
    Computes the union of two SDFs.
    Returns the minimum distance and the ID of the closer primitive.
    """
    if d1 < d2:
        return d1, id1
    else:
        return d2, id2

def op_intersection(d1, id1, d2, id2):
    """
    Computes the intersection of two SDFs.
    Returns the maximum distance and the ID of the primitive defining the boundary.
    Note: Material ID logic for intersection is ambiguous in sources; 
    typically the ID of the primitive that is 'inside' the other or the one 
    with the larger distance (closer to surface from inside) is kept. 
    Here we keep the ID of the primitive with the larger distance.
    """
    if d1 > d2:
        return d1, id1
    else:
        return d2, id2

def op_subtraction(d1, id1, d2, id2):
    """
    Computes the difference (subtraction) of two SDFs: Object 1 minus Object 2.
    Negates the distance of Object 2 before comparison.
    """
    # Negate d2 to invert its inside/outside status
    d2_neg = -d2
    
    if d1 > d2_neg:
        return d1, id1
    else:
        return d2_neg, id2

def scene_sdf(p, primitives):
    """
    Combines multiple primitives into a single scene SDF using Union.
    primitives: List of tuples (primitive_func, material_id)
    """
    # Initialize with a large distance (background)
    current_dist = float('inf')
    current_id = 0
    
    for prim_func, prim_id in primitives:
        d = prim_func(p)
        current_dist, current_id = op_union(current_dist, current_id, d, prim_id)
        
    return current_dist, current_id
```

### Parameters
*   **$k$ (Smoothness)**: Used in smooth union/intersection. Typical values range from $0.0$ (sharp, equivalent to min/max) to $1.0$ or higher depending on scene scale [S9, S13, unofficial].
*   **Epsilon**: A small value used in gradient estimation for normals, not directly in the boolean logic, but critical for rendering the result [S7, S10, unofficial].

### Edge Cases and Pitfalls
*   **Lipschitz Condition**: The min/max operations preserve the Lipschitz constant of 1 if the input SDFs satisfy it, ensuring sphere tracing safety [Parent].
*   **Normals**: The normal of the resulting surface is the normal of the primitive contributing the minimum distance (for union) or maximum distance (for intersection/subtraction). Discontinuities in normals occur at the boundaries where the active primitive switches [S2, S10, unofficial].
*   **Precision**: When $d_1 \approx d_2$, floating-point precision errors can cause jitter in normals or artifacts in smooth blending [S10, unofficial].

## Operating characteristics
*   **Time Complexity**: $O(N)$ where $N$ is the number of primitives combined, as each primitive must be evaluated at the query point [S13, unofficial].
*   **Memory Complexity**: $O(1)$ auxiliary memory per operation, as only the current minimum/maximum distance and ID are stored [S6, S13, unofficial].
*   **Strengths**:
    *   No mesh generation or topology management required [S2, unofficial].
    *   Infinite resolution; the surface is defined analytically [S14, unofficial].
    *   Easy to animate and modify parameters in real-time [S11, unofficial].
*   **Limitations**:
    *   Sharp corners can cause aliasing in normals if not smoothed [S9, unofficial].
    *   Complex CSG trees can become computationally expensive if many primitives are evaluated per pixel [S13, unofficial].
    *   Cannot represent non-manifold geometry or holes that require topological changes beyond simple boolean logic (e.g., a handle attached to a box requires careful placement of primitives) [S8].
*   **When to use**: Ideal for procedural generation, ray marching shaders, and scenes with simple, analytically definable shapes [S2, S14, unofficial].
*   **When not to use**: For complex organic models with high-frequency detail best represented by meshes, or when precise control over mesh topology (e.g., specific UV mapping, non-manifold edges) is required [S12, unofficial].

## Background
Boolean operations on SDFs were popularized in the computer graphics community by Inigo Quilez's articles on distance functions and ray marching [S11, S13, unofficial]. The technique leverages the mathematical properties of distance fields, where the union of two sets corresponds to the minimum of their distance functions, and the intersection corresponds to the maximum [S4, unofficial][S8]. This approach allows for the creation of complex scenes like the Menger Sponge or intricate mechanical parts directly in shader code [S6, S11, unofficial]. It is widely used in real-time ray marching demos, procedural texture generation, and implicit modeling tools [S2, S14, unofficial].
