# Offset Surface Evaluation

Also called: Distance to Offset Surfaces, Global offset, Local offset, Point-to-set distance

## Overview
Offset Surface Evaluation computes the signed distance from a query point to a surface generated by offsetting a base "skeleton" geometry by a fixed distance [S1]. It solves the problem of defining smooth, thickened representations of curves, surfaces, or meshes for use in implicit modeling and ray tracing [S1]. It is distinguished from its siblings by its reliance on a global point-to-set distance search rather than local parametric expansions, which avoids the interior surface artifacts common in local offset methods [S1].

## How it works
The method evaluates the distance $d(\mathbf{p})$ to a closed skeleton geometry $S$ [S1]. The offset surface is defined implicitly by $d(\mathbf{p}) = 0$ [S1].

**Inputs and Outputs:**
*   Input: Query point $\mathbf{p}$, skeleton geometry $S$, constant offset distance $c$.
*   Output: Scalar signed distance $d(\mathbf{p})$.

**Data Structures:**
*   Skeleton $S$: Represented as a set of points, typically parameterized (e.g., a space curve $\mathbf{p}(t)$) or a mesh with defined normals [S1][S2, unofficial].
*   For parametric curves, the closest point search involves solving for parameter $t$ [S1].

**Steps:**
1.  **Global Offset (Implicit):** Compute the point-to-set distance from $\mathbf{p}$ to the skeleton $S$. This requires searching the entire set $S$ for the closest point $\mathbf{q} \in S$ [S1].
    *   If $S$ has defined surface normals, the closest point $\mathbf{q}$ lies on the surface such that the vector $\mathbf{p} - \mathbf{q}$ is aligned with the normal at $\mathbf{q}$ [S1].
    *   The distance is $d(\mathbf{p}) = \|\mathbf{p} - \mathbf{q}\| - c$ [S1, G]. (Note: The source defines the surface by $d(p)=0$ where $d$ is the point-to-set distance, implying the offset is applied to the distance value itself).
2.  **Local Offset (Parametric):** If using a local parametric definition for a generator surface $\mathbf{g}(u,v)$, the offset surface is defined as:
    $$ \mathbf{g}_{offset}(u,v) = \mathbf{g}(u,v) + c \cdot \mathbf{n}(u,v) $$
    where $\mathbf{n}(u,v)$ is the unit-length surface normal [S1].
    *   The normal is computed from partial derivatives:
        $$ \mathbf{n}(u,v) = \frac{\frac{\partial \mathbf{g}}{\partial u} \times \frac{\partial \mathbf{g}}{\partial v}}{\left\| \frac{\partial \mathbf{g}}{\partial u} \times \frac{\partial \mathbf{g}}{\partial v} \right\|} $$
        [S1]
3.  **Closest Point on Curve:** For a space curve $\mathbf{p}(t)$, the closest point satisfies the orthogonality condition:
    $$ (\mathbf{p}(t) - \mathbf{p}) \cdot \mathbf{p}'(t) = 0 $$
    [S1]
    *   For a cubic Bezier curve, this equation converts into a degree-five 1-D Bernstein polynomial [S1].
    *   Roots are found using efficient techniques for Bernstein polynomials [S1].

**Parameters:**
*   $c$: Constant offset distance applied to the skeleton [S1].

**Pitfalls:**
*   **Interior Surfaces:** Global offsets can create interior surfaces that cause problems in ray-tracing and Constructive Solid Geometry (CSG) operations [S1].
*   **Self-Intersections:** Local offsets (mesh-based) do not handle self-intersections; vertices are moved independently along their original normals [S2, unofficial].
*   **Degree Increase:** Algebraic and parametric offset surfaces are of higher degree than the generator, leading to precision loss and computational cost [S1].

def evaluate_global_offset(query_point, skeleton, offset_distance):
    """
    Computes the signed distance from query_point to the global offset surface
    of the skeleton.
    """
    # Find the closest point on the skeleton to the query point
    closest_point = find_closest_point_on_skeleton(query_point, skeleton)
    
    # Calculate Euclidean distance to the skeleton
    dist_to_skeleton = length(query_point - closest_point)
    
    # The signed distance to the offset surface is the distance to the skeleton
    # minus the offset constant. 
    # Note: Sign convention depends on whether the skeleton is inside or outside.
    # Assuming standard SDF convention where inside is negative:
    # If the skeleton is a surface, we need to know if query_point is inside or outside.
    # For a general closed skeleton, this requires a winding number or similar check.
    # However, the source [S1] defines the offset surface by d(p)=0 where d is point-to-set distance.
    # This implies d(p) = ||p - q|| - c.
    # To make it a signed distance field (SDF), we assume the skeleton defines the zero-level set.
    # If the skeleton is a surface, the sign is determined by the normal direction at q.
    
    # Get normal at closest point (if available)
    normal = get_normal_at(closest_point, skeleton)
    
    # Determine sign based on dot product of (query - closest) and normal
    # If query is outside, (query - closest) aligns with normal -> positive distance
    # If query is inside, (query - closest) opposes normal -> negative distance
    direction = query_point - closest_point
    sign = 1.0 if dot(direction, normal) > 0 else -1.0
    
    return sign * (dist_to_skeleton - offset_distance)

def find_closest_point_on_skeleton(query_point, skeleton):
    """
    Searches the entire set of the skeleton for the closest point.
    Optimization: If normals are defined, search along normals.
    """
    # This is a global search. For parametric curves, solve the orthogonality equation.
    # For meshes, iterate vertices/edges/triangles.
    # [S1] states: "If S has a surface normal defined everywhere, then the point in closest 
    # to S is one of the points on S whose normal extends directly toward P."
    
    # Simplified implementation for a mesh:
    min_dist = infinity
    closest = None
    
    for vertex in skeleton.vertices:
        dist = length(query_point - vertex)
        if dist < min_dist:
            min_dist = dist
            closest = vertex
            
    # For higher accuracy, project onto edges/faces.
    # [S1] mentions solving (p(t) - 0) . p'(t) = 0 for curves.
    # Here we assume a generic closest point search.
    return closest

def evaluate_local_offset_mesh(mesh, offset_amount):
    """
    Creates an offset surface from a mesh by moving vertices along their normals.
    [S2, unofficial]
    """
    # Ensure normals are computed
    mesh.compute_normals()
    
    nv = mesh.num_vertices()
    for i in range(nv):
        # Update vertex position by adding the scaled normal
        mesh.vertices[i] = mesh.vertices[i] + offset_amount * mesh.normals[i]
        
    # Invalidate bounding box and bounding sphere flags
    mesh.invalidate_bounding_volume()

## Subtopics

### Offset Surface Creation
Creates an offset surface from a mesh by moving vertices along their normals by a given distance [S2, unofficial]. It is a local, parametric approach [S1]. It is chosen for simple mesh thickening but fails to handle self-intersections, as vertices are moved independently along their original normals [S2, unofficial]. It is less desirable than global offsets for ray-tracing because it can produce interior surfaces and gradient discontinuities [S1][S2, unofficial].

## Operating characteristics
*   **Complexity:** Global offset evaluation requires a point-to-set distance search, which can be $O(N)$ for a mesh with $N$ vertices unless accelerated by spatial data structures (e.g., BVH, KD-tree) [S1]. Local offset evaluation is $O(N)$ for mesh processing but $O(1)$ per query if precomputed [S1].
*   **Performance:** Global offsets are computationally expensive per query due to the search [S1]. Local offsets are faster but suffer from geometric artifacts [S1].
*   **Strengths:** Global offsets provide smooth, implicit representations that avoid the high-degree algebraic issues of local offsets [S1].
*   **Limitations:** Global offsets can create interior surfaces that complicate ray-tracing and CSG [S1]. Local offsets do not handle self-intersections [S2, unofficial].
*   **When to use:** Use global offsets for smooth, implicit modeling where interior artifacts can be managed or are absent. Use local offsets for simple mesh operations where performance is critical and self-intersections are unlikely.

## Background
The concept of offset surfaces is rooted in computer-aided geometric design (CAGD) and implicit surface rendering [S1]. Hoffman (1989) and van Wijk (1984) are cited regarding the desirability of global offsets to avoid interior surface problems in ray-tracing and CSG [S1]. The mathematical formulation of point-to-set distance and its application to parametric surfaces is detailed in [S1].
