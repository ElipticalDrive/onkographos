# Curve-based Volumetric Free-Form Deformation

Also called: Lattice Construction, Lattice Construction for Deformation, Volumetric Free-Form Deformation

## Overview
Curve-based Volumetric Free-Form Deformation is a technique for manipulating the macro shape and flow of a volumetric volume (specifically procedural fire) using an open uniform B-spline curve [S1]. It solves the problem of inverse parameterization—where deforming a volume requires finding the pre-deformation texture coordinates for a deformed world-space point—by constructing a lattice of curves in world space and evaluating the deformation on the CPU [S1]. This approach allows for flexible shape manipulation while maintaining valid texture coordinates for rendering, avoiding the computational cost and robustness issues of numerical inverse parameterization [S1].

## How it works
**Inputs:**
- A set of $n$ control points $\{P_0, \dots, P_{n-1}\}$ defining a central B-spline curve [S1].
- The radius $r$ of the volume, determining the cross-section size [S1].
- The lattice resolution $c$, determining the number of samples along the curve [S1].
- The degree of the B-spline (typically 3 for cubic, though the source defines the knot vector for general degree) [S1].

**Outputs:**
- A lattice structure consisting of $c$ sections, where each section is defined by four corner points in world space [S1].
- Texture coordinates assigned to each lattice point to map the unit volume to the deformed space [S1].

**Data Structures:**
The lattice is a sequence of $c$ sections. Each section $i$ (where $i = 0 \dots c-1$) contains four 3D points corresponding to the corners of the square cross-section at that parameter value $t_i$.
- `Lattice`: Array of size $c$.
- `Lattice[i]`: Array of 4 vectors $\{C_{top-left}, C_{top-right}, C_{bottom-right}, C_{bottom-left}\}$ or similar ordering, representing the corners of the square at parameter $t_i$.

**Steps:**

1.  **Define Knot Vector:** Construct the knot vector $t_i$ for an open uniform B-spline of degree $p$ with $n$ control points [S1]. The knot values are defined as:
    $$
    t_i = \begin{cases} 
    0 & \text{if } i \leq p \\
    i - p & \text{if } p < i < n \\
    n - p & \text{if } i \geq n 
    \end{cases}
    $$
    [S1]

2.  **Sample Central Curve Properties:** For each control point index $i$ from $0$ to $n-1$, calculate the parameter $t_{sample} = \frac{i}{n-1}$ [S1]. Evaluate the central curve $C(t)$ and its derivatives at $t_{sample}$ to obtain the position, normal vector $\vec{N}_i$, and velocity vector $\vec{V}_i$ [S1]. Note: The source states sampling at $t = \frac{i}{n-1}$, which corresponds to the parameter value most affected by control point $P_i$ [S1].

3.  **Generate Corner Curves:** For each control point $P_i$, define a square in the plane defined by $P_i$ and $\vec{V}_i$, centered at $P_i$ [S1]. The edge length of this square is $2r$, where $r$ is the radius of the volume [S1]. Align the squares along the central curve normal $\vec{N}_i$ to reduce twisting [S1]. This defines four additional control points for each $i$, forming four corner curves [S1].

4.  **Sample Lattice Sections:** Sample the central curve parameter $t$ uniformly $c$ times (where $c$ is the lattice resolution) to obtain $c$ values of $t$ in the domain $[0, 1]$ [S1].

5.  **Evaluate Lattice Points:** For each of the $c$ parameter values $t$, evaluate the position on each of the four corner curves using the B-spline evaluation formula (Equation 6 below) [S1]. This yields $c$ sets of four correlated positions, defining the lattice sections [S1].

6.  **Assign Texture Coordinates:** Assign texture coordinates to each point in the lattice. For a point at lattice level $i$ (from $0$ to $c-1$) and corner index corresponding to $x, z \in \{-1, 1\}$, the texture coordinate is:
    $$
    \text{tex}_i = \left( x, \frac{i}{c-1}, z \right)
    $$
    [S1]

**Formulas:**

The B-spline basis functions are defined recursively [S1]:
$$
N_{i,0}(t) = \begin{cases} 
1 & \text{if } t_i \leq t < t_{i+1} \\
0 & \text{otherwise}
\end{cases}
$$
$$
N_{i,p}(t) = \frac{t_{i+p+1} - t}{t_{i+p} - t_i} N_{i,p-1}(t) + \frac{t - t_i}{t_{i+p+1} - t_{i+1}} N_{i+1,p-1}(t)
$$
[S1]

The curve evaluation is:
$$
C(t) = \sum_{i=0}^{n-1} N_{i, \text{degree}}(t) \cdot P_i
$$
[S1]

**Parameters:**
- $n$: Number of control points [S1].
- $t_i$: Knot values [S1].
- $N_{i,p}$: B-spline basis function of degree $p$ [S1].
- $P_i$: Control point [S1].
- $c$: Resolution of the lattice [S1].
- $r$: Radius of the fire/volume [S1].

**Pseudocode:**

```python
def compute_lattice(control_points, radius, lattice_resolution, degree):
    """
    Computes the volumetric free-form deformation lattice.
    
    Args:
        control_points: List of n 3D vectors (P_0 ... P_{n-1})
        radius: Float, radius r of the volume
        lattice_resolution: Integer c, number of sections along the curve
        degree: Integer, degree of the B-spline
        
    Returns:
        lattice: List of c sections, each section is a list of 4 3D vectors
        texture_coords: List of c sections, each section is a list of 4 texture coordinates
    """
    n = len(control_points)
    
    # Step 1: Define Knot Vector
    # Open uniform B-spline knot vector
    knots = []
    for i in range(n + degree + 1):
        if i <= degree:
            knots.append(0.0)
        elif i < n:
            knots.append(float(i - degree))
        else:
            knots.append(float(n - degree))
            
    # Helper: Evaluate B-spline basis function N_{i,p}(t)
    def basis_function(i, p, t):
        if p == 0:
            if knots[i] <= t < knots[i+1]:
                return 1.0
            else:
                return 0.0
        else:
            denom1 = knots[i+p] - knots[i]
            denom2 = knots[i+p+1] - knots[i+1]
            
            term1 = 0.0
            if denom1 != 0:
                term1 = (knots[i+p+1] - t) / denom1 * basis_function(i, p-1, t)
                
            term2 = 0.0
            if denom2 != 0:
                term2 = (t - knots[i]) / denom2 * basis_function(i+1, p-1, t)
                
            return term1 + term2

    # Helper: Evaluate Curve C(t)
    def evaluate_curve(pts, t):
        result = [0.0, 0.0, 0.0]
        for i in range(n):
            N = basis_function(i, degree, t)
            for k in range(3):
                result[k] += N * pts[i][k]
        return result

    # Step 2: Sample Central Curve Properties to define corner curves
    # We need to define 4 corner curves. Each corner curve is defined by 
    # control points derived from the central curve's geometry at each P_i.
    # The source says: "For each control point Pi... sample normal Ni and velocity Vi...
    # Generate four additional curves by placing control points on the corners of a square..."
    
    # We need to store the control points for the 4 corner curves.
    # Let's assume an ordering: Top-Left, Top-Right, Bottom-Right, Bottom-Left
    # relative to the normal and velocity vectors.
    
    corner_control_points = [[[], [], [], []] for _ in range(n)]
    
    for i in range(n):
        t_sample = i / (n - 1)
        pos = evaluate_curve(control_points, t_sample)
        
        # Calculate velocity vector (derivative)
        # Numerical derivative approximation for velocity
        dt = 1e-5
        t_plus = min(t_sample + dt, 1.0)
        t_minus = max(t_sample - dt, 0.0)
        pos_plus = evaluate_curve(control_points, t_plus)
        pos_minus = evaluate_curve(control_points, t_minus)
        velocity = [pos_plus[k] - pos_minus[k] for k in range(3)]
        
        # Calculate normal vector
        # The source says "normal vector Ni ... of the spline". 
        # In the context of a curve, this usually implies the principal normal or a constructed normal.
        # However, the source also says "plane defined by Pi and Vi".
        # And "Align all n squares along their respective Ni to reduce twisting".
        # A common approach for FFD is to use the Frenet frame or a parallel transport.
        # Given the ambiguity, we assume Ni is a vector perpendicular to Vi.
        # For implementation, we might need a reference vector to define the "up" direction.
        # The source does not specify how Ni is computed from the curve geometry explicitly,
        # other than "sample the normal vector". 
        # [G] Assuming a simple construction: Ni is perpendicular to Vi. 
        # If Vi is not aligned with a global up, we need a cross product with a reference vector (e.g., [0,1,0]).
        # Let's assume a standard Frenet-like normal or a fixed up vector is used to define the plane.
        # Since the source doesn't specify, we will note this as a gap.
        # However, looking at "plane defined by Pi and Vi", it implies the square lies in the plane containing Pi and Vi?
        # No, "centered at Pi" and "plane defined by Pi and Vi" is geometrically ambiguous if Pi is a point.
        # It likely means the plane containing the velocity vector Vi and the normal vector Ni.
        # Let's assume Ni is provided or computed via a standard method (e.g., cross product with global up).
        
        # For the sake of the algorithm description, we assume we have Ni and Vi.
        # We construct the square corners.
        # Edge length is 2r. Half edge is r.
        # Corners are at P_i +/- r*Ni +/- r*U, where U is a vector perpendicular to both Ni and Vi.
        # U = normalize(cross(Ni, Vi))
        
        # [G] Computing Normal Ni:
        # If not provided, a common heuristic is to use the cross product of the velocity and a global up vector.
        # If velocity is parallel to up, use a different reference.
        up = [0.0, 1.0, 0.0]
        cross_prod = [
            velocity[1]*up[2] - velocity[2]*up[1],
            velocity[2]*up[0] - velocity[0]*up[2],
            velocity[0]*up[1] - velocity[1]*up[0]
        ]
        norm_len = sqrt(sum(c**2 for c in cross_prod))
        if norm_len > 1e-6:
            Ni = [c/norm_len for c in cross_prod]
        else:
            Ni = [1.0, 0.0, 0.0] # Fallback
            
        Vi = velocity # Already computed
        
        # Compute U vector perpendicular to both Ni and Vi
        cross_ni_vi = [
            Ni[1]*Vi[2] - Ni[2]*Vi[1],
            Ni[2]*Vi[0] - Ni[0]*Vi[2],
            Ni[0]*Vi[1] - Ni[1]*Vi[0]
        ]
        u_len = sqrt(sum(c**2 for c in cross_ni_vi))
        if u_len > 1e-6:
            U = [c/u_len for c in cross_ni_vi]
        else:
            # Fallback if curve is straight and aligned with Ni?
            # Use a fixed vector perpendicular to Ni
            U = [1.0, 0.0, 0.0]
            if abs(dot(Ni, U)) > 0.9:
                U = [0.0, 0.0, 1.0]
            u_len = sqrt(sum(c**2 for c in U))
            U = [c/u_len for c in U]

        # Define the 4 corner control points for this section i
        # Corners: (+Ni, +U), (+Ni, -U), (-Ni, -U), (-Ni, +U)
        # Or some consistent ordering.
        # Let's use: TL, TR, BR, BL
        # TL: Ni + U
        # TR: Ni - U
        # BR: -Ni - U
        # BL: -Ni + U
        
        corners = []
        for sign_n, sign_u in [(1, 1), (1, -1), (-1, -1), (-1, 1)]:
            corner = [
                pos[0] + sign_n * radius * Ni[0] + sign_u * radius * U[0],
                pos[1] + sign_n * radius * Ni[1] + sign_u * radius * U[1],
                pos[2] + sign_n * radius * Ni[2] + sign_u * radius * U[2]
            ]
            corners.append(corner)
            
        corner_control_points[i] = corners

    # Now we have 4 sets of control points, one for each corner curve.
    # Corner 0 control points: [cp[0][0] for cp in corner_control_points], etc.
    corner_curves = []
    for k in range(4):
        curve_pts = [corner_control_points[i][k] for i in range(n)]
        corner_curves.append(curve_pts)
        
    # Step 4: Sample Lattice Sections
    lattice = []
    texture_coords = []
    
    for i in range(lattice_resolution):
        t = i / (lattice_resolution - 1)
        
        section_points = []
        section_tex = []
        
        for k in range(4):
            pt = evaluate_curve(corner_curves[k], t)
            section_points.append(pt)
            
            # Texture coordinates: (x, i/(c-1), z)
            # x and z are 1 or -1 depending on corner
            # Mapping k to (x, z):
            # k=0: (1, 1)
            # k=1: (1, -1)
            # k=2: (-1, -1)
            # k=3: (-1, 1)
            x = 1.0 if k < 2 else -1.0
            z = 1.0 if k % 2 == 0 else -1.0
            
            tex = (x, i / (lattice_resolution - 1), z)
            section_tex.append(tex)
            
        lattice.append(section_points)
        texture_coords.append(section_tex)
        
    return lattice, texture_coords

def dot(v1, v2):
    return sum(a*b for a,b in zip(v1, v2))

def sqrt(x):
    return x ** 0.5
```

**Edge Cases and Pitfalls:**
- **Inverse Parameterization:** The method avoids solving for $P$ from $P'$ analytically, which is numerically unstable [S1].
- **Twisting:** Aligning squares along the normal $\vec{N}_i$ helps reduce twisting, but the choice of normal vector is critical [S1]. If the curve has zero curvature or specific alignments, the normal may be undefined or unstable [G].
- **Coverage:** The lattice must cover the entire deformed volume to ensure pixel shader coverage is not missed [S1].

## Subtopics

### [Quadratic Bezier Tube Deformation](10138-quadratic-bezier-tube-deformation.md)
Uses quadratic Bezier curves instead of B-splines. A segment is defined by three control points. Simpler than B-splines but less flexible for complex shapes.

### [Spline Tube to Cylinder Mapping](10139-spline-tube-to-cylinder-mapping.md)
Maps the deformed spline tube to a canonical cylinder for texture mapping. This is a subsequent step often used in conjunction with deformation to handle texture coordinates.

## Operating characteristics
- **Time Complexity:** The deformation is evaluated on the CPU during lattice construction. The cost is $O(c \cdot n)$ for evaluating the B-spline basis functions for each of the $c$ lattice sections and $n$ control points per corner curve. Rendering is hardware-accelerated.
- **Memory Complexity:** $O(c)$ to store the lattice points and texture coordinates.
- **Strengths:** Real-time performance due to hardware acceleration of the final rendering step. Avoids numerical instability of inverse parameterization. Flexible macro-level control via control points.
- **Limitations:** Cannot deform the entire volume with infinite detail in real-time; only the lattice is deformed. The micro-details are handled by procedural noise, which is consistent but not physically simulated in real-time.
- **When to use:** Real-time procedural volumetric fire or similar effects requiring macro-level shape control and bi-directional interactivity.
- **When not to use:** Offline rendering requiring high physical accuracy, or scenes where the volume shape changes too rapidly for the lattice resolution to capture without artifacts.

## Background
The method was introduced by Alfred R. Fuller, Hari Krishnan, Karim Mahrous, Bernd Hamann, and Kenneth I. Joy from the University of California, Davis, in their 2007 paper "Real-time procedural volumetric fire" [S1]. It builds on earlier work in curve-based fire design and particle simulations [S1]. The technique combines curve-based volumetric free-form deformation with hardware-accelerated volumetric rendering and procedural noise (Improved Perlin Noise or M-Noise) to create vibrant, animated volumetric fire [S1].
