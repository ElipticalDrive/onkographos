# Infinite Tiling with Modulo

Also called: Infinite Crystal Grid SDF, Infinite Tiling via Modulo, Modulo SDF, Modulo Tiling, Repeat function, Tiling SDFs, Tiling via Modulo

## Overview
Infinite Tiling with Modulo is a technique for rendering infinite, repeating patterns of a single Signed Distance Field (SDF) primitive by folding space using the modulo operator [S1, S2, unofficial]. It solves the problem of representing unbounded periodic geometry (such as crystal lattices or fractal structures) without explicit mesh instances, allowing a single SDF evaluation to tile the scene infinitely at essentially zero extra computational cost [S3, unofficial]. Unlike [Constructive SDF Modeling (Min Combination)](871-constructive-sdf-modeling-min-combination.md), which requires explicit enumeration of objects, this method implicitly generates infinite instances by mapping any world-space coordinate back to a canonical local tile [S2, unofficial].

## How it works
The method transforms the sampling point $\mathbf{p}$ into a periodic coordinate system before evaluating the base SDF. This ensures that all points in space are mapped to the nearest instance of the primitive within a repeating unit cell.

**Inputs and Outputs:**
*   **Input:** $\mathbf{p} \in \mathbb{R}^3$, the world-space position of the ray sample.
*   **Input:** $c \in \mathbb{R}$, the period or tile size (must be positive) [S2, S4, unofficial].
*   **Input:** $\mathbf{o} \in \mathbb{R}^3$, an optional offset vector used to center the tile or shift the grid origin [S1, unofficial].
*   **Output:** $\mathbf{q} \in \mathbb{R}^3$, the folded local coordinate within the unit cell.

**Data Structures:**
No persistent data structures are required. The operation is stateless and computed per-sample.

**Steps:**
1.  **Shift:** Add the offset $\mathbf{o}$ to the input position $\mathbf{p}$ to adjust the grid origin.
2.  **Modulo:** Apply the modulo operator with period $c$ to each component of the shifted position.
3.  **Center:** Subtract half the period ($c/2$) from the result to center the tile at the origin (or at $\mathbf{o}$ if offset is used).

**Formula:**
$$ \mathbf{q} = \text{mod}(\mathbf{p} + \mathbf{o}, c) - \frac{c}{2} $$

Where $\text{mod}(x, c)$ is the floating-point remainder operation, typically defined as $x - c \cdot \lfloor x/c \rfloor$.

**Parameters:**
*   $c$: The size of the repeating tile. Lower values increase object density; higher values increase spacing [S2, unofficial].
*   $\mathbf{o}$: Offset. A common value is $\mathbf{o} = (1.5, 1.5, 1.5)$ when $c=3.0$ to center the tile at the origin [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Negative Coordinates:** Standard modulo implementations in some languages or hardware may return negative results for negative inputs, or the centering logic may fail if the input space is not handled correctly. The formula $\text{mod}(p, c) - c/2$ assumes the modulo result is in $[0, c)$. If the modulo implementation returns values in $(-c/2, c/2]$, the centering step changes [S2, S4, unofficial].
*   **Zero Period:** $c=0$ causes division by zero in the modulo operation.
*   **Precision:** For very large world coordinates, floating-point precision errors in the modulo operation can cause visible artifacts or "popping" as the ray marches. Bounding volume checks or local coordinate transformations are often used in production to mitigate this [S3, unofficial].

**Pseudocode:**
```python
def repeat(p: Vector3, c: float, offset: Vector3 = Vector3(0, 0, 0)) -> Vector3:
    """
    Folds space to create infinite tiling of an SDF primitive.
    
    Args:
        p: World space position.
        c: Tile period/size.
        offset: Optional offset to shift the grid origin.
        
    Returns:
        Folded local position within the unit cell.
    """
    # Step 1: Shift by offset
    shifted = p + offset
    
    # Step 2: Modulo operation
    # Note: Standard fmod(x, y) returns x - y * trunc(x/y)
    # This results in a value in (-c, c). 
    # To ensure [0, c), we adjust negative results.
    mod_val = fmod(shifted, c)
    mod_val = select(mod_val < 0.0, mod_val + c, mod_val)
    
    # Step 3: Center the tile
    # Subtracting c/2 centers the tile around the origin (or offset)
    q = mod_val - (c / 2.0)
    
    return q
```

## Subtopics

### Finite Tiling
A variant that produces a finite number of repetitions of a shape by limiting the tiling to a specific box [S4, unofficial]. It takes an additional vector $\vec{l}$ as input, representing the corner of the box used to limit the number of repetitions. The implementation typically involves checking if the folded coordinate $\mathbf{q}$ lies within the bounds defined by $\vec{l}$ and returning an infinite distance (or a large value) if it is outside, effectively clipping the infinite grid [S4, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per sample. The modulo operation is a constant-time arithmetic operation.
*   **Memory Complexity:** $O(1)$. No additional memory is required beyond the input and output vectors.
*   **Performance:** Enables rendering of fractals (e.g., Mandelbulbs, Menger sponges) and infinite scenes at real-time frame rates, as scene complexity does not grow with the number of visible instances [S3, unofficial].
*   **Strengths:** Extremely efficient for periodic structures; no need for scene graphs or instance buffers.
*   **Limitations:** Cannot represent non-periodic or sparse infinite structures without additional logic. Precision issues may arise at extreme coordinate magnitudes.

## Background
The technique is foundational in ray marching and procedural geometry, popularized by demoscene artists and researchers like Inigo Quilez, who used it to create fractals such as the Menger sponge [S2, S3, unofficial]. It leverages the mathematical property of periodicity to reuse a single distance function, a concept central to procedural texture generation and implicit modeling.
