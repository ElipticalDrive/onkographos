# Elongation

Also called: End-point Corrector

## Overview
Elongation is a domain manipulation operator for Signed Distance Functions (SDFs) that modifies the query point to create elongated or tapered geometric structures, such as skeletal branches or organic limbs [S1, unofficial]. It addresses the geometric distortion inherent in standard SDF primitives by stretching the distance field along a specific axis. Unlike [SDF Rounding](1829-sdf-rounding.md) which smooths corners, or [Finite Repetition](2869-finite-repetition.md) which tiles space, elongation warps the metric to preserve volume and shape continuity in tapered objects.

## How it works
The method transforms the input position $\mathbf{p}$ using a non-linear mapping that separates the longitudinal and transverse components relative to the elongation axis. The core logic involves an absolute-value reflection, a subtraction of an elongation vector, and a re-evaluation of the base primitive in the transformed space.

**Inputs and Outputs:**
*   Input: Query point $\mathbf{p} = (p_x, p_y, p_z)$.
*   Input: Elongation parameter $h$ (controls the taper/length ratio).
*   Output: Modified distance value $d$.
*   Note: The position $\mathbf{p}$ is typically modified in place or passed as a temporary variable $\mathbf{q}$ during the calculation steps described below.

**Data Structures:**
No persistent data structures are required. The operation is point-wise and stateless.

**Steps:**
1.  **Reflection and Subtraction:** Compute the absolute values of the lateral components (typically $x$ and $z$). Subtract the elongation vector $\mathbf{s}$ from these absolute values. In the reference implementation, this is conceptualized as mapping $\mathbf{p}$ to a local coordinate system where the elongation is normalized [S1, unofficial].
2.  **Transformation:** Apply a linear transformation to the components to decouple the longitudinal axis from the transverse plane. This often involves scaling the transverse components by $h$ [S1, unofficial].
3.  **Primitive Evaluation:** Evaluate the base primitive SDF (e.g., a cylinder or sphere) at the transformed point.
4.  **Correction:** Add the maximum of the negative part of the transformed coordinate (clamped to 0) to the result. This step ensures the distance field remains continuous and corrects for the "pinching" effect at the origin of the elongation [S1, unofficial].

**Formulas:**
Let $\mathbf{p} = (p_x, p_y, p_z)$. Let $h$ be the elongation factor.
The transformation involves intermediate variables. Based on the source code [S1, unofficial], the specific implementation for a tapered cylinder-like primitive is:

$$
\begin{aligned}
m &= h^2 + 0.25 \\
p_x' &= |p_x|, \quad p_z' = |p_z| \\
p_{max} &= \max(p_x', p_z'), \quad p_{min} = \min(p_x', p_z') \\
q_z &= p_{min} - 0.5 \\
q_y &= h p_y - 0.5 p_{max} \\
q_x &= h p_{max} + 0.5 p_{min}
\end{aligned}
$$

The distance calculation proceeds as:
$$
\begin{aligned}
s &= \max(-q_x, 0) \\
t &= \text{clamp}\left(\frac{q_y - 0.5 p_{min}}{m + 0.25}, 0.0, 1.0\right) \\
a &= m(q_x + s)^2 + q_y^2 \\
b &= m(q_x + 0.5 t)^2 + (q_y - m t)^2 \\
d_{xy} &= \begin{cases} a & \text{if } \min(q_y, -q_x m - q_y 0.5) > 0 \\ \min(a, b) & \text{otherwise} \end{cases} \\
d &= \sqrt{\frac{d_{xy} + q_z^2}{m}} \cdot \text{sign}(\max(q_z, -p_y))
\end{aligned}
$$

**Parameters:**
*   $h$: Elongation factor. Typical values depend on the desired aspect ratio. Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Precision:** The use of `clamp` and `max` functions requires careful handling of floating-point boundaries to avoid discontinuities in the gradient.
*   **Degenerate Input:** If $h=0$, the transformation may become singular. Not given in the sources.

**Pseudocode:**
```python
import math

def elongation_sdf(p, h):
    """
    Computes the SDF for an elongated primitive.
    p: tuple (px, py, pz)
    h: elongation factor
    """
    px, py, pz = p
    
    # Step 1: Absolute values and sorting
    px = abs(px)
    pz = abs(pz)
    
    # Sort to identify max and min lateral components
    if px > pz:
        p_max = px
        p_min = pz
    else:
        p_max = pz
        p_min = px
        
    # Step 2: Transformation
    m = h * h + 0.25
    
    qz = p_min - 0.5
    qy = h * py - 0.5 * p_max
    qx = h * p_max + 0.5 * p_min
    
    # Step 3: Intermediate calculations
    s = max(-qx, 0.0)
    
    # Clamp function
    denom = m + 0.25
    t_val = (qy - 0.5 * p_min) / denom
    t = max(0.0, min(1.0, t_val))
    
    a = m * (qx + s)**2 + qy**2
    b = m * (qx + 0.5 * t)**2 + (qy - m * t)**2
    
    # Condition check
    cond = min(qy, -qx * m - qy * 0.5)
    if cond > 0.0:
        d_xy = a
    else:
        d_xy = min(a, b)
        
    # Step 4: Final distance
    d_xy_plus_qz2 = d_xy + qz**2
    dist = math.sqrt(d_xy_plus_qz2 / m)
    
    sign_val = max(qz, -py)
    if sign_val < 0:
        return -dist
    else:
        return dist
```

## Subtopics

### End-point Corrector
A technique to address field variation divergence near skeleton end-points in Scale-Invariant Integral Surfaces (SCALIS) fields [S2]. It forces an additional sampling position near end-points to increase correlation between the minima of individual primitives and the global field [S2].
*   **What it is:** An additive correction segment.
*   **How it works:** Adds a segment primitive with constant radius at the end vertices of the skeleton [S2].
*   **Parameters:** The length of the end-point corrector segment is proportional to the prescribed radius at the end vertices of the skeleton and a constant depending on the kernel used [S2].
*   **When to choose:** Use when rendering skeletal structures where radius shrinkage at end-points causes visual artifacts or incorrect distance values [S2]. If absent, a heuristic presented in section 6.2 of the source can compensate [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query point. The calculation involves a fixed number of arithmetic operations.
*   **Memory Complexity:** $O(1)$. No auxiliary data structures.
*   **Strengths:** Efficiently creates complex tapered shapes without requiring mesh generation or high-resolution voxel grids.
*   **Limitations:** The specific formula provided is tailored to a particular primitive type (tapered cylinder/cone hybrid). Generalizing to arbitrary base primitives requires deriving the corresponding transformation [S1, unofficial].
*   **When to use:** Ideal for organic modeling, skeletal structures, and procedural geometry where elongation is a primary design parameter.

## Background
The concept of elongation in SDFs is rooted in the manipulation of domain space to create non-uniform scaling effects. The specific implementation detailed in [S1, unofficial] appears in the context of Torch-Sphere-Tracer, a library for differentiable sphere tracing. The End-point Corrector variant originates from research on Scale-Invariant Integral Surfaces (SCALIS) [S2], specifically addressing the mathematical limitations of integral surface representations near the boundaries of skeletal structures.
