# Signed Distance Field (SDF) Primitive Definition

Also called: SDF Function, SDF Shapes, Signed Distance Field (SDF), Signed Distance Function (SDF), Signed Distance Function Primitives

## Overview
A Signed Distance Field (SDF) Primitive Definition is a method for representing geometric surfaces as analytical functions that return the shortest Euclidean distance from a query point to the nearest surface, along with a sign indicating whether the point is inside or outside the object [S2, S5, S7, unofficial]. Unlike mesh-based representations which require explicit triangle lists and intersection tests, SDF primitives define the entire 3D world as a single mathematical function mapping any position to a distance value [S8, unofficial]. This method sets itself apart from [Constructive SDF Modeling (Min Combination)](871-constructive-sdf-modeling-min-combination.md) by providing the base geometric building blocks (spheres, boxes, etc.) rather than the Boolean operators used to combine them, and from [Distance to Natural Quadrics](1559-distance-to-natural-quadrics.md) by focusing on standard analytical primitives rather than complex quadric surfaces [S1, S3, S13, unofficial]. The primary advantage is that the returned distance serves as a conservative lower bound, enabling safe "sphere tracing" (adaptive stepping) during ray marching without overshooting surfaces [S7, S14, unofficial].

## How it works

### Inputs and Outputs
- **Input**: A query point $\mathbf{p} \in \mathbb{R}^3$ (typically in local object space) and primitive-specific parameters (e.g., radius, center, half-extents).
- **Output**: A scalar float $d = \text{SDF}(\mathbf{p})$ representing the signed distance.

### Data Structures
Primitives are typically defined by simple structs or parameter sets. Common layouts include [S13, unofficial]:
- **Sphere**: `struct sph { float r; vec3 c; }` where `r` is radius and `c` is center.
- **Box (AABB)**: `struct box { vec3 p; vec3 size; }` where `p` is position and `size` is full dimensions (half-extents are used in calculation).
- **Cylinder**: `struct cylinder { vec2 p; float r; }` where `p` is center in XZ plane and `r` is radius.
- **Capped Cylinder**: `struct cylinderCapped { float r; float h; }` where `h` is half-height.
- **Cone**: `struct cone { float r; float h; vec3 c; }` where `r` is base radius, `h` is height, `c` is center/offset.
- **Plane**: `struct plane { vec4 k; }` where `k.xyz` is the normal vector and `k.w` is the distance from origin.
- **Torus**: `struct tor { float inR; float outR; }` where `inR` is tube radius and `outR` is major radius.

### Formulas and Steps
The core property is that $d(\mathbf{p}) < 0$ implies inside, $d(\mathbf{p}) = 0$ implies on surface, and $d(\mathbf{p}) > 0$ implies outside [S2, S14, unofficial]. The Lipschitz condition with constant 1 guarantees $|d(\mathbf{p}_1) - d(\mathbf{p}_2)| \le \|\mathbf{p}_1 - \mathbf{p}_2\|$, ensuring step safety [G].

#### 1. Sphere
For a sphere with center $\mathbf{c}$ and radius $r$:
$$ d(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r $$
If centered at origin ($\mathbf{c}=\mathbf{0}$):
$$ d(\mathbf{p}) = \sqrt{p_x^2 + p_y^2 + p_z^2} - r $$
[S2, S6, S13, unofficial]

#### 2. Box (AABB)
For a box centered at origin with half-extents $\mathbf{b}$:
Let $\mathbf{d} = |\mathbf{p}| - \mathbf{b}$.
$$ d(\mathbf{p}) = \|\max(\mathbf{d}, \mathbf{0})\| + \min(\max(\mathbf{d}_x, \max(\mathbf{d}_y, \mathbf{d}_z)), 0) $$
This computes the exact distance to corners. A cheaper approximation that overestimates distance (safe for marching but less precise) is:
$$ d_{cheap}(\mathbf{p}) = \max(|p_x|, |p_y|, |p_z|) - \max(b_x, b_y, b_z) $$
Or component-wise max: `vmax(abs(p) - b)`.
[S5, S13, unofficial]

#### 3. Plane
For a plane with normal $\mathbf{n}$ (normalized) and distance from origin $d_{offset}$:
$$ d(\mathbf{p}) = \mathbf{p} \cdot \mathbf{n} + d_{offset} $$
If aligned with Y-axis: $d(\mathbf{p}) = p_y + \text{offset}$.
[S5, S13, unofficial]

#### 4. Cylinder (Infinite)
For a cylinder along the Y-axis with radius $r$ and center $\mathbf{p}_{center}$ in XZ:
$$ d(\mathbf{p}) = \|\mathbf{p}_{xz} - \mathbf{p}_{center}\| - r $$
[S13, unofficial]

#### 5. Cylinder (Capped)
For a capped cylinder with radius $r$ and half-height $h$:
Let $d_x = \|\mathbf{p}_{xz}\| - r$ and $d_y = |p_y| - h$.
$$ d(\mathbf{p}) = \min(\max(d_x, d_y), 0) + \|\max(d_x, d_y, 0)\| $$
This combines the infinite cylinder distance with the distance to the top/bottom caps.
[S13, unofficial]

#### 6. Cone
For a cone with base radius $r$, height $h$, and axis along Y:
Let $\mathbf{q} = (\|\mathbf{p}_{xz}\|, p_y)$.
Let $\phi = \arctan(r/h)$.
$$ d(\mathbf{p}) = \max(\|\mathbf{p}_{xz}\|\cos(\phi) - |p_y|\sin(\phi), \max(p_y - h, -p_y)) $$
More robust implementation handles tip and base ring distances explicitly:
1. Calculate distance to mantle: `mantle = dot(tip, mantleDir)`.
2. Calculate distance to base: `-q.y` (if below base).
3. If point is above tip and projects outside base, add distance to tip.
4. If point is below tip and projects outside base ring, add distance to base ring.
[S12, S13, unofficial]

#### 7. Torus
For a torus with major radius $R_{out}$ and minor (tube) radius $R_{in}$, centered at origin, aligned with Y:
$$ d(\mathbf{p}) = \sqrt{(\sqrt{p_x^2 + p_z^2} - R_{out})^2 + p_y^2} - R_{in} $$
Or in vectorized form:
$$ d(\mathbf{p}) = \|\vec{2}(\|\mathbf{p}_{xz}\| - R_{out}, p_y)\| - R_{in} $$
[S5, S12, S13, unofficial]

#### 8. Capsule
For a capsule defined by endpoints $\mathbf{a}, \mathbf{b}$ and radius $r$:
$$ d(\mathbf{p}) = \text{LineSegmentSDF}(\mathbf{p}, \mathbf{a}, \mathbf{b}) - r $$
Where LineSegmentSDF is the distance to the closest point on the segment $\mathbf{a} \to \mathbf{b}$.
[S5, S12, unofficial]

#### 9. Generalized Distance Function (GDF) / Polyhedra
GDFs approximate convex polyhedra by combining distances to planes defined by normal vectors.
Let $\mathbf{v}_i$ be pre-normalized vectors (e.g., 19 vectors for a dodecahedron/icosahedron approximation).
For exponent $e$ (sharp edges if $e \to \infty$, rounded if $e$ is small):
$$ d(\mathbf{p}) = \left( \sum_{i} |\mathbf{p} \cdot \mathbf{v}_i|^e \right)^{1/e} - r $$
For sharp edges ($e \to \infty$):
$$ d(\mathbf{p}) = \max_{i} |\mathbf{p} \cdot \mathbf{v}_i| - r $$
Common vectors include axes and golden-ratio based directions (PHI = $\frac{\sqrt{5}+1}{2}$).
[S5, S12, unofficial]

### Pseudocode
The following Python-like pseudocode implements the core primitive definitions. It assumes standard vector operations (`length`, `dot`, `abs`, `max`, `min`, `sqrt`).

```python
import math

def length(v):
    return math.sqrt(sum(x*x for x in v))

def dot(v1, v2):
    return sum(x*y for x, y in zip(v1, v2))

def abs_vec(v):
    return tuple(abs(x) for x in v)

def max_vec(v1, v2):
    return tuple(max(x, y) for x, y in zip(v1, v2))

def min_vec(v1, v2):
    return tuple(min(x, y) for x, y in zip(v1, v2))

def clamp(val, min_val, max_val):
    return max(min_val, min(val, max_val))

def sdf_sphere(p, center, radius):
    """Signed Distance Function for a sphere."""
    return length([p[i] - center[i] for i in range(3)]) - radius

def sdf_box(p, half_extents):
    """Exact SDF for an AABB centered at origin."""
    # d = abs(p) - b
    d = [abs(p[i]) - half_extents[i] for i in range(3)]
    # q = max(d, 0)
    q = [max(d[i], 0.0) for i in range(3)]
    # e = min(max(d), 0) -> min of components of d, clamped to 0 if positive
    # Actually: min(max(d_x, max(d_y, d_z)), 0)
    max_d = max(d)
    e = min(max_d, 0.0)
    return length(q) + e

def sdf_plane(p, normal, distance_from_origin):
    """SDF for a plane."""
    # normal must be normalized
    return dot(p, normal) + distance_from_origin

def sdf_cylinder_capped(p, radius, half_height):
    """SDF for a capped cylinder along Y axis."""
    # Distance to infinite cylinder (XZ plane)
    d_x = length([p[0], p[2]]) - radius
    # Distance to caps (Y axis)
    d_y = abs(p[1]) - half_height
    
    # Combine
    # min(max(d_x, d_y), 0)
    max_xy = max(d_x, d_y)
    e = min(max_xy, 0.0)
    
    # max(d_x, d_y, 0)
    q_x = max(d_x, 0.0)
    q_y = max(d_y, 0.0)
    q = [q_x, q_y, 0.0] # 3rd component is 0
    
    return length(q) + e

def sdf_torus(p, major_radius, minor_radius):
    """SDF for a torus aligned with Y axis."""
    # q = (length(p.xz) - R_out, p.y)
    q_x = length([p[0], p[2]]) - major_radius
    q_y = p[1]
    q = [q_x, q_y]
    
    return length(q) - minor_radius

def sdf_capsule(p, a, b, radius):
    """SDF for a capsule defined by endpoints a and b."""
    ab = [b[i] - a[i] for i in range(3)]
    ap = [p[i] - a[i] for i in range(3)]
    
    ab_len_sq = dot(ab, ab)
    if ab_len_sq == 0:
        # Degenerate case: a == b
        dist_to_point = length(ap)
        return dist_to_point - radius
    
    t = clamp(dot(ap, ab) / ab_len_sq, 0.0, 1.0)
    
    # Closest point on segment
    closest = [a[i] + t * ab[i] for i in range(3)]
    
    dist_to_segment = length([p[i] - closest[i] for i in range(3)])
    return dist_to_segment - radius

def sdf_gdf_sharp(p, vectors, radius):
    """Sharp GDF (Polyhedron approximation)."""
    max_val = -float('inf')
    for v in vectors:
        val = abs(dot(p, v))
        if val > max_val:
            max_val = val
    return max_val - radius

def sdf_gdf_rounded(p, vectors, radius, exponent):
    """Rounded GDF (Polyhedron approximation)."""
    sum_val = 0.0
    for v in vectors:
        val = abs(dot(p, v))
        sum_val += val ** exponent
    return (sum_val ** (1.0 / exponent)) - radius
```

### Parameters and Typical Values
- **Sphere Radius**: 1.0 (unit sphere) [S3, S6, unofficial].
- **Box Half-Extents**: e.g., `vec3(20, 20, 5)` [S4, unofficial].
- **Torus Radii**: Major 70, Minor 15 [S4, unofficial].
- **Gradient Step Size**: 0.0001 for normal approximation [S10, unofficial].
- **Smoothing Constant (smin)**: 0.2 [S10, unofficial].
- **GDF Vectors**: 19 normalized vectors using PHI ($\frac{\sqrt{5}+1}{2}$) for dodecahedron/icosahedron approximations [S5, S12, unofficial].

### Edge Cases and Pitfalls
- **Non-Closed-Form SDFs**: Not every shape has a closed-form SDF. Arbitrary meshes require approximate SDFs (baked into 3D textures or generated via BVH traversal) [S14, unofficial].
- **GDF Performance**: Loops in GDF implementations (e.g., `fIcosahedron`) may fail to unroll on certain hardware (e.g., Nvidia 350.12), causing slowdowns. Specialized implementations are recommended [S5, S12, unofficial].
- **Incorrect Bounds**: Some functions like `fBlob` are not correct distance bounds and should not be used for sphere tracing [S5, S12, unofficial].
- **Sharp Discontinuities**: Taking the `min()` or `max()` of two SDFs yields sharp corners. Smooth blending requires `smin` or similar operators [S10, unofficial].
- **Precision**: Near the surface ($d \approx 0$), floating-point precision can cause jitter in normals or marching steps. Using a small epsilon or higher precision may be necessary for high-quality rendering [G].

## Subtopics

### [SDF Primitives & Operations](1075-sdf-primitives-operations.md)
Provides analytical building blocks and Boolean/smoothing operators. Sets itself apart by focusing on combining primitives rather than defining base geometry. Choose when constructing complex scenes from simple shapes.

### [SDF Transformation](1086-sdf-transformation.md)
Applies geometric transformations (rotation, translation, scaling) by manipulating query points. Sets itself apart by handling general rigid body motions and deformations. Choose when animating or positioning primitives.

### [k-SDF](9530-k-sdf.md)
Represents fuzzy geometries (hair, fur) using $k$ semi-transparent mesh shells. Sets itself apart by bounding samples per ray and enabling real-time rendering on low-cost devices. Choose for volumetric/fuzzy effects.

## Operating characteristics
- **Time Complexity**: $O(1)$ per primitive evaluation. Total time is $O(N \cdot M)$ where $N$ is the number of primitives and $M$ is the number of marching steps.
- **Memory Complexity**: $O(1)$ for analytical primitives. No storage required for geometry data.
- **Measured Performance**: Sphere tracing is significantly faster than ray-triangle intersection for complex scenes because it skips empty space. However, it can be slower than rasterization for simple scenes due to the cost of distance function evaluations [S1, unofficial].
- **Strengths**: No underestimation of distance (prevents overshooting), easy to implement, supports complex shapes via CSG, infinite resolution (no aliasing from mesh tessellation).
- **Limitations**: Limited to shapes with known SDFs, normals require finite differences (expensive), sharp edges from CSG can cause artifacts if not smoothed.
- **When to Use**: Real-time ray marching, procedural geometry, soft shadows, ambient occlusion.
- **When Not to Use**: Scenes with highly detailed, arbitrary meshes without pre-computed SDFs, or when exact triangle intersection is required for specific physics.

## Background
The concept of Signed Distance Fields originates from the level set method, which represents interfaces as functions tracking the signed distance to the nearest point on the interface [S9, unofficial]. The use of SDFs for real-time ray marching was popularized by Inigo Quilez and others in the demoscene and shader programming community [S1, S6, unofficial]. The method leverages the Lipschitz property of SDFs to guarantee safe stepping during sphere tracing [S7, S14, unofficial]. It is widely used in real-time graphics for procedural rendering, soft shadows, and ambient occlusion [S3, S10, unofficial].
