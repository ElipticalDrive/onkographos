# Constructive Solid Geometry (CSG) on Level Sets

Also called: Level Set CSG, Point-Classification Map, Voxel CSG

## Overview
Constructive Solid Geometry (CSG) on Level Sets combines multiple Signed Distance Fields (SDFs) into a single implicit function using Boolean operations (Union, Intersection, Difference) [S1][S2, unofficial]. It solves the problem of representing complex composite shapes from simple primitives by evaluating the resulting distance field directly on a voxel grid or via ray marching [S2, unofficial]. Unlike [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md), which typically manages a stack of operations for procedural generation, this method explicitly constructs a unified representation (often a Point-Classification Map or a merged voxel buffer) that can be rendered as a solid object or volumetric element [S1][S2, unofficial].

## How it works
The method operates on two primary paradigms: the Point-Classification Map (PCM) for discrete boolean logic on primitive membership, and direct voxel buffer arithmetic for continuous distance field composition [S1][S2, unofficial].

### Inputs and Outputs
*   **Inputs:** A CSG tree where leaf nodes are SDF primitives (e.g., spheres, boxes) and internal nodes are Boolean operators (Union, Intersection, Difference) [S1][S2, unofficial].
*   **Outputs:** A single implicit function representing the composite shape, either as a PCM lookup table (for classification) or a merged Voxel Buffer (for distance values) [S1][S2, unofficial].

### Data Structures

#### Point-Classification Map (PCM)
The PCM is a look-up table that maps a complete primitive classification result to a final in/out CSG classification [S1].
*   **Structure:** An array of size $2^n$, where $n$ is the number of leaf nodes (primitives) in the CSG tree [S1].
*   **Indexing:** The index is an $n$-bit binary number called the **classification index** [S1].
    *   Bit $j$ is 1 if the point is inside the $j$-th primitive [S1].
    *   Bit $j$ is 0 if the point is outside the $j$-th primitive [S1].
*   **Content:** Each entry stores the final boolean classification (Inside/Outside) for that specific combination of primitive memberships [S1].

#### Voxel Buffer
A 3D grid storing signed distance values [S2, unofficial].
*   **Structure:** Array indexed by $(i, j, k)$ corresponding to voxel coordinates [S2, unofficial].
*   **Content:** Signed distance value $\phi$ at each voxel [S2, unofficial].

### Algorithm: Recursive PCM Construction
The PCM for a CSG tree is constructed recursively [S1].

1.  **Leaf Node:** If node $N$ is a leaf (primitive), return the PCM for that primitive [S1]. For a primitive defined by surface boundaries, the PCM is generated by casting rays or voxelizing the boundary to determine interior points [S1].
2.  **Internal Node:** If node $N$ is not a leaf:
    a. Recursively compute $PCM_{left}$ from $N.left$ [S1].
    b. Recursively compute $PCM_{right}$ from $N.right$ [S1].
    c. Combine them using the node's Boolean operation $N.op$ [S1].
3.  **Combination:** The combined classification $c$ is derived from sub-classifications $c_1$ and $c_2$ via the Boolean operator:
    $$ c = c_1 \text{ op } c_2 $$
    where $c_1$ and $c_2$ are the classification indices (or bits thereof) from the left and right sub-PCMs [S1].
4.  **Memory Optimization:** A common PCM memory space is shared by all levels of recursive calls to avoid excessive memory consumption [S1].

### Algorithm: Voxel Buffer Composition
For continuous SDFs, the composite distance field is computed by iterating over the bounding box dimensions shared by the operands [S2, unofficial].

**Parameters:**
*   $A, B$: Voxel Buffers (SDFs) with the same transform and dimensions [S2, unofficial].
*   $dims$: The bounding box dimensions $(min.x, max.x, min.y, max.y, min.z, max.z)$ [S2, unofficial].

**Pseudocode:**

> **Unverified code.** The code below did not pass a test run against a reference implementation, or no test fits it, so it may contain errors.

```python
def union(A, B):
    """Computes the union of two SDFs using min(A, B)."""
    dims = A.dims()
    result = VoxelBuffer(dims)
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                result[i, j, k] = min(A[i, j, k], B[i, j, k])
    return result

def intersection(A, B):
    """Computes the intersection of two SDFs using max(A, B)."""
    dims = A.dims()
    result = VoxelBuffer(dims)
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                result[i, j, k] = max(A[i, j, k], B[i, j, k])
    return result

def difference(A, B):
    """Computes the difference (A minus B) using max(A, -B)."""
    dims = A.dims()
    result = VoxelBuffer(dims)
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                result[i, j, k] = max(A[i, j, k], -B[i, j, k])
    return result
```

### Rendering Level Sets
Once the composite level set is computed, it can be rendered [S2, unofficial]:
1.  **Volumetric:** Assign constant density to voxels where $\phi \le 0$ [S2, unofficial]. To avoid aliasing, apply a roll-off band near the surface [S2, unofficial]:
    $$ \text{density} = \text{defaultDensity} \times \text{smoothstep}(-\phi, 0, \text{bandwidth}) $$
    when $\phi \le 0$ and $\phi \ge -\text{bandwidth}$ [S2, unofficial].
2.  **Surface:** Ray trace the level set directly or convert to an explicit mesh [S2, unofficial].

### Pitfalls
*   **Memory Consumption:** Recursive PCM construction can consume high memory [S1].
*   **Precision:** The classification index size grows exponentially with the number of primitives ($2^n$) [S1].
*   **Transforms:** Voxel buffer operations assume operands $A$ and $B$ share the same transform and grid alignment [S2, unofficial].

## Subtopics

### [Lipschitz Pruning](8623-lipschitz-pruning.md)
Lipschitz Pruning is a hierarchical simplification algorithm that reduces the number of active nodes in a smooth CSG tree for a specific region of space, outputting a pruned tree equivalent to the full tree within that region. It relies on the 1-Lipschitz property of the distance function to determine if a binary operator's result is unaffected by blending within a spatial region. Unlike naive sphere tracing or bounding-volume-based pruning which requires pre-computed bounding boxes that expand with blending radii, Lipschitz Pruning is space-centric, requires no bounding box computation, and guarantees distance exactness. It builds on [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md) by optimizing the evaluation of the resulting implicit functions.

### Lazy CSG Volume Modification
Lazy CSG Volume Modification is a volume modification system where SDF operations are added to per-octant CSG queues and executed lazily when the octant is close to the viewer, allowing dynamic expansion/contraction [S3]. Preparation translates the SDF AABB into an octant key range to identify affected octants across LOD grids [S3]. Queuing adds the SDF to the CSG queue of identified octants without immediately modifying data [S3]. Execution runs when an octant is close to the viewer, combining SDFs using Union, Subtract, and Intersect [S3]. Pruning removes octants that become empty after modification and recursively prunes parent octants [S3]. Supported primitives include box, cylinder, cone, heightfield, noise, pill, sphere, pellet, torus, pipe, and corridor [S3].

## Operating characteristics
*   **Time Complexity:** PCM Construction requires $O(2^n)$ time where $n$ is the number of primitives, due to the size of the lookup table [S1]. Voxel Buffer Composition requires $O(V)$ time where $V$ is the number of voxels in the bounding box, as it requires iterating over all voxels [S2, unofficial].
*   **Memory Complexity:** PCM requires $O(2^n)$ entries [S1]. Voxel Buffer requires $O(V)$ [S2, unofficial].
*   **Strengths:** PCM provides exact boolean classification for discrete primitive membership [S1]. Voxel buffer composition allows for smooth, continuous distance fields suitable for ray marching and volumetric rendering [S2, unofficial]. Lazy modification allows for dynamic scene updates without immediate global recomputation [S3].
*   **Limitations:** PCM does not scale to a large number of primitives due to exponential memory growth [S1]. Voxel buffer operations require aligned grids and transforms [S2, unofficial]. Volumetric rendering may require bandwidth tuning to avoid aliasing artifacts [S2, unofficial].
*   **When to use:** Use PCM for small numbers of primitives where exact boolean logic is required [S1]. Use Voxel Buffer composition for smooth SDF composites and ray marching [S2, unofficial]. Use Lazy Modification for dynamic terrains or large-scale scenes with frequent updates [S3].

## Background
The concept of using frame buffer pixel mapping for CSG voxelization was introduced in "Fast CSG voxelization by frame buffer pixel mapping" [S1]. This method utilizes hardware features like 3D texture mapping and logical operations to accelerate the construction of the Point-Classification Map [S1]. The voxel buffer approach for SDF composition is detailed in "Production Volume Rendering" [S2, unofficial], which outlines the mathematical formulation of Union, Intersection, and Difference operations on signed distance fields. Lazy CSG Volume Modification was proposed in "Volumetric Terrain Rendering with WebGL" [S3] to handle dynamic terrain generation efficiently.
