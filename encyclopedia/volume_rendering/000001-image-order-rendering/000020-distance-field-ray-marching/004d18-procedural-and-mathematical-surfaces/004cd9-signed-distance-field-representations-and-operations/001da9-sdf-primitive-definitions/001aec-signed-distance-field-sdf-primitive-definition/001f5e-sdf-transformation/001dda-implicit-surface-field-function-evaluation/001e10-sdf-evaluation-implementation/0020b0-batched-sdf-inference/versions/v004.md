# Batched SDF Inference

Also called: Batched SDF Evaluation

## Overview
Batched SDF Inference evaluates Signed Distance Function (SDF) values for a large set of spatial samples in batches to manage memory constraints during inference [S1, unofficial]. It differs from single-sample evaluation by processing multiple points simultaneously, and from training methods by focusing solely on forward evaluation without gradient accumulation for optimization [S1, unofficial].

## How it works
**Inputs:**
- A list of 3D query points $\mathbf{p}_i$.
- An SDF model or function capable of decoding/evaluating distance values.
- `max_batch`: Integer maximum batch size for inference, default $32^3 = 32768$ [S1, unofficial].

**Outputs:**
- An array of SDF values $d(\mathbf{p}_i)$ corresponding to each input point.

**Data Structures:**
- `samples`: A 2D array or tensor of shape $(N, 4)$, where $N$ is the total number of samples. Columns 0-2 store the coordinates $(x, y, z)$, and column 3 stores the computed SDF value.

**Steps:**
1. Disable automatic differentiation (gradients) for the inference process to save memory and computation [S1, unofficial].
2. Determine the total number of samples $N$ [S1, unofficial].
3. Initialize a head pointer $h = 0$ [S1, unofficial].
4. While $h < N$:
   a. Calculate the end of the current batch: $e = \min(h + \text{max\_batch}, N)$ [S1, unofficial].
   b. Extract the subset of samples from index $h$ to $e-1$ [S1, unofficial].
   c. Decode or evaluate the SDF for this subset [S1, unofficial].
   d. Store the resulting SDF values in column 3 of the `samples` array for indices $h$ to $e-1$ [S1, unofficial].
   e. Increment $h$ by $\text{max\_batch}$ [S1, unofficial].
5. Return the SDF values from column 3 of the `samples` array [S1, unofficial].

**Pseudocode:**
```python
def batched_sdf_inference(samples, sdf_model, max_batch=32**3):
    """
    Evaluates SDF values for a large set of samples in batches.
    
    Args:
        samples: Array of shape (N, 3) containing query points (x, y, z).
        sdf_model: Object or function with a method to evaluate SDF values.
        max_batch: Integer maximum batch size. Default 32768.
        
    Returns:
        Array of SDF values of shape (N,).
    """
    # Disable gradients for memory efficiency [S1, unofficial]
    with torch.no_grad():
        num_samples = samples.shape[0]
        head = 0
        sdf_values = np.empty(num_samples)
        
        while head < num_samples:
            # Determine batch end [S1, unofficial]
            end = min(head + max_batch, num_samples)
            
            # Extract subset [S1, unofficial]
            batch_points = samples[head:end]
            
            # Decode SDF for subset [S1, unofficial]
            # Implementation detail: sdf_model.evaluate(batch_points)
            batch_sdfs = sdf_model.evaluate(batch_points)
            
            # Store in column 3 (mapped to 1D array for return) [S1, unofficial]
            sdf_values[head:end] = batch_sdfs
            
            # Increment head [S1, unofficial]
            head += max_batch
            
    return sdf_values
```

**Parameters:**
- `max_batch`: Integer maximum batch size for inference. Default value is $32^3$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- If `max_batch` is larger than the total number of samples, the loop runs once.
- Precision issues may arise if the SDF model involves floating-point operations on very large coordinate sets; however, standard batched inference does not inherently introduce more precision errors than single-pass evaluation [G].
- Memory limits are the primary driver for batching; if `max_batch` is too large, out-of-memory errors may occur depending on the hardware [G].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of samples, with a constant factor dependent on the SDF evaluation cost per point.
- **Memory Complexity:** $O(\text{max\_batch})$ for the active batch, plus $O(N)$ to store the final results. This is significantly lower than evaluating all $N$ points in a single forward pass if $N \gg \text{max\_batch}$.
- **Strengths:** Manages memory constraints for large-scale point cloud or voxel grid evaluations.
- **Limitations:** Introduces slight overhead from loop management compared to a single vectorized operation if memory permits.
- **When to use:** When evaluating SDFs for millions of points (e.g., voxel grids, dense point clouds) where GPU memory is limited.
- **When not to use:** For small numbers of points where the overhead of batching is unnecessary.

## Background
Batched SDF Inference is a practical implementation technique used in distance-field ray marching and procedural surface rendering pipelines. It is commonly found in unofficial implementations of SDF-based renderers, such as the DIST-Renderer, where large-scale evaluation is required for training or inference [S1, unofficial].
