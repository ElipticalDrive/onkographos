# Cone Signed Distance Function

Also called: Cone SDF, sdCone, Signed Cone, Signed Capped Cone, Exact Cone SDF, Signed Distance Function (SDF) for Cone

## Overview
The Cone Signed Distance Function computes the exact Euclidean distance from a query point to the surface of a cone, including its base cap and apex, while correctly determining the sign (positive outside, negative inside). It solves the problem of efficiently rendering or ray-marching conical primitives without polygonization. Unlike the [Quadric SDF (First-Order Approximation)](2682-quadric-sdf-first-order-approximation.md), which approximates the cone as a smooth quadric surface, the Cone SDF provides the exact analytical distance, preserving sharp edges at the base and apex. It builds on [SDF Primitives & Operations](1075-sdf-primitives-operations.md) by providing a specific primitive definition.

## How it works
The method reduces the 3D distance calculation to a 2D problem by exploiting rotational symmetry around the cone's axis. The point is projected onto a 2D plane containing the axis and the radial distance, and the distance to the 2D line segment (representing the cone's side) and the base cap is computed.

### Inputs and Outputs
*   **Input**: Point $p \in \mathbb{R}^3$, base radius $r \in \mathbb{R}^+$, height $h \in \mathbb{R}^+$.
*   **Output**: Signed distance $d \in \mathbb{R}$.

### Data Structures
No complex data structures are required. The computation uses standard 2D and 3D vector operations.

### Parameters
*   $r$: Base radius of the cone.
*   $h$: Height of the cone.
*   Orientation: The implementations in [S2, S4, unofficial] align the cone along the Y-axis, with the apex at the origin $(0,0,0)$ and the base centered at $y = -h$ (opening downward). [S5] describes a cone along the Z-axis. The pseudocode below follows the Y-axis orientation common in [S2, S4, unofficial].

### Steps
1.  **2D Projection**: Project the 3D point $p$ into the 2D plane defined by the radial distance and the Y-axis.
    $$ q = (\sqrt{p_x^2 + p_z^2}, p_y) $$
2.  **Define Geometry**: Define the 2D coordinates of the apex (tip) and the base edge.
    $$ \text{tip} = (0, 0) $$
    $$ \text{base} = (r, -h) $$
3.  **Vector Definitions**:
    $$ k = (r, h) $$
    $$ m_2 = r^2 + h^2 $$
    $$ d_1 = q - \text{tip} = q $$
    $$ d_3 = q - (\text{clamp}(q_x, 0, r), -h) $$
4.  **Side Distance**: Compute the distance from $q$ to the line segment connecting the tip and the base.
    $$ \text{ba} = \text{base} - \text{tip} = (r, -h) $$
    $$ u = \text{clamp}\left(\frac{d_1 \cdot \text{ba}}{m_2}, 0, 1\right) $$
    $$ \text{side\_dist} = \| d_1 - \text{ba} \cdot u \| $$
5.  **Cap Distance**: Compute the distance from $q$ to the base cap.
    $$ \text{cap\_dist} = \| d_3 \| $$
6.  **Unsigned Distance**:
    $$ \text{dist} = \min(\text{side\_dist}, \text{cap\_dist}) $$
7.  **Inside Test**: Determine if the point is inside the cone.
    $$ \text{inside} = (q_y \le 0) \land (q_y \ge -h) \land (q_x \cdot h + q_y \cdot r \le 0) $$
8.  **Signed Distance**:
    $$ \text{result} = \begin{cases} -\text{dist} & \text{if inside} \\ \text{dist} & \text{otherwise} \end{cases} $$

### Pseudocode
```python
def sd_cone(p: Vec3, r: float, h: float) -> float:
    """
    Computes the signed distance from point p to a cone with base radius r
    and height h, aligned with the Y-axis, apex at origin, opening downward.
    """
    # 1. Project to 2D plane (radial distance, y)
    q_x = sqrt(p.x * p.x + p.z * p.z)
    q_y = p.y
    q = Vec2(q_x, q_y)
    
    # 2. Define geometry in 2D
    tip = Vec2(0.0, 0.0)
    base = Vec2(r, -h)
    
    # 3. Vectors
    k = Vec2(r, h)
    m2 = k.x * k.x + k.y * k.y
    
    d1 = q - tip  # d1 is just q
    
    # Clamp x to [0, r] for base projection
    clamped_q_x = clamp(q.x, 0.0, r)
    d3 = q - Vec2(clamped_q_x, -h)
    
    # 4. Side distance (distance to segment tip-base)
    ba = base - tip
    u = clamp(dot(d1, ba) / m2, 0.0, 1.0)
    side_dist = length(d1 - ba * u)
    
    # 5. Cap distance
    cap_dist = length(d3)
    
    # 6. Unsigned distance
    dist = min(side_dist, cap_dist)
    
    # 7. Inside test
    # Condition: y is between -h and 0, and point is "below" the slope line
    # Slope line equation in 2D (q_x, q_y): q_x * h + q_y * r <= 0
    inside = (q.y <= 0.0) and (q.y >= -h) and ((q.x * h + q.y * r) <= 0.0)
    
    # 8. Return signed distance
    if inside:
        return -dist
    else:
        return dist
```

### Edge Cases and Pitfalls
*   **Normalization**: In alternative formulations using a normalized vector $c$ for the cone slope [S3, unofficial], the vector $c$ must be normalized. Failure to normalize results in incorrect distances.
*   **Precision**: When $r$ or $h$ are very small, floating-point precision issues may arise in the dot product and clamp operations.
*   **Apex Singularity**: At the apex $(0,0,0)$, the gradient is undefined, but the distance is correctly 0.
*   **Base Ring**: The implementation above handles the base cap as a flat disk. Some variations [S2, unofficial] explicitly handle the "ring" at the base edge if the cone is not capped, but the standard "Capped Cone" SDF includes the base.

## Operating characteristics
*   **Time Complexity**: $O(1)$. The calculation involves a fixed number of arithmetic operations, square roots, and comparisons.
*   **Memory Complexity**: $O(1)$. No auxiliary data structures are needed.
*   **Strengths**: Exact distance calculation allows for precise ray marching and constructive solid geometry (CSG) operations. It is significantly faster than polygon-based distance estimation for simple cones.
*   **Limitations**: The sharp edges at the base and apex can cause aliasing in ray marching if the step size is not adaptive. The function is not differentiable at the edges and apex.
*   **When to use**: When rendering or ray-marching conical primitives with high precision is required.
*   **When not to use**: When a smooth approximation is preferred for aesthetic reasons or to avoid gradient discontinuities, consider the [Quadric SDF (First-Order Approximation)](2682-quadric-sdf-first-order-approximation.md).

## Background
The Cone SDF is based on the analytical distance functions popularized by Inigo Quilez in his article "Distance Functions" [S1, S4, unofficial]. The specific implementation for the capped cone along the Y-axis is widely used in GLSL-based ray marching engines. The formulation along the Z-axis is also described in geometric ray tracing literature [S5]. The method is a staple in the [SDF Primitives & Operations](1075-sdf-primitives-operations.md) toolkit.
