# SDF Evaluation Implementation

Also called: SDF Evaluation and Gradient, SDF Handler Implementation, SDF Query Handler, SDF Value and Gradient Evaluation

## Overview
This method implements the runtime evaluation of Signed Distance Function (SDF) values and their spatial gradients for procedural or grid-based implicit surfaces, serving as the core query interface for ray marching and differentiable rendering pipelines. It distinguishes itself from raw primitive definitions by providing a unified handler that supports both analytical derivatives (for cubic interpolation) and numerical approximations (for linear interpolation), ensuring consistent gradient flow for optimization tasks [S2, unofficial]. Unlike [Batched SDF Inference](2329-batched-sdf-inference.md) which optimizes throughput for dense grids, this implementation focuses on the correctness and differentiability of individual point queries [S1, unofficial].

## How it works
**Inputs:**
1.  **SDF Data Source:** A 3D voxel grid representing the distance field, loaded from `.sdf`, `.npy`, or `.vol` files [S2, unofficial].
2.  **Query Point:** A 3D coordinate $p = (x, y, z)$ in world space [S2, unofficial].
3.  **Interpolation Mode:** A string parameter `SDF_MODE` specifying either `'linear'` or `'cubic'` interpolation [S2, unofficial].
4.  **Finite Difference Step:** A scalar `epsilon` (default $10^{-5}$) used for gradient approximation in linear mode [S2, unofficial].

**Outputs:**
1.  **Distance Value:** A scalar $d = f(p)$ representing the signed distance from $p$ to the surface [S2, unofficial].
2.  **Gradient Vector:** A 3D vector $\nabla d = (\frac{\partial d}{\partial x}, \frac{\partial d}{\partial y}, \frac{\partial d}{\partial z})$ representing the direction of maximum increase of the distance field [S2, unofficial].

**Data Structures:**
*   **SDF Grid:** A 3D tensor of shape $(res, res, res, 1)$ storing distance values. In C++ implementations, this may be wrapped in a texture object with acceleration disabled (`use_accel=False`) to allow direct sampling [S2, unofficial].
*   **Query Handler:** An object (e.g., `SDFQueryHandler`) that encapsulates the SDF name, resolution, and interpolation mode, providing methods for value and gradient evaluation [S1, unofficial].

**Steps:**

1.  **Initialization and Validation:**
    *   Validate the SDF name using a helper function `is_valid_sdf_name(name)`. If invalid, raise an error `std::runtime_error("unknown SDF '..." + name + "')` [S1, unofficial].
    *   Load the SDF data from the specified file format. For `.sdf` or `.npy` files, parse the first element as the resolution `res` and the remaining data as the grid values. Construct the 3D tensor with shape `(res, res, res, 1)` [S2, unofficial].

2.  **Value Evaluation $d = f(p)$:**
    *   Map the query point $p$ from the input coordinate system (e.g., `Vector3`) to the internal representation (e.g., `glm::vec3`) [S1, unofficial].
    *   If `SDF_MODE` is `'linear'`:
        *   Perform trilinear interpolation on the grid at point $p$.
        *   Formula: $d = \text{grid.eval}(p)[0]$ [S2, unofficial].
    *   If `SDF_MODE` is `'cubic'`:
        *   Perform tricubic interpolation on the grid at point $p$.
        *   Formula: $d = \text{grid.eval\_cubic}(p)[0]$ [S2, unofficial].

3.  **Gradient Evaluation $\nabla d$:**
    *   If `SDF_MODE` is `'linear'`:
        *   Compute the gradient using central finite differences with step size $\epsilon = 10^{-5}$ [S2, unofficial].
        *   Let $e_x = (\epsilon, 0, 0)$, $e_y = (0, \epsilon, 0)$, $e_z = (0, 0, \epsilon)$.
        *   $\frac{\partial d}{\partial x} \approx \frac{f(p + e_x) - f(p - e_x)}{2\epsilon}$
        *   $\frac{\partial d}{\partial y} \approx \frac{f(p + e_y) - f(p - e_y)}{2\epsilon}$
        *   $\frac{\partial d}{\partial z} \approx \frac{f(p + e_z) - f(p - e_z)}{2\epsilon}$
        *   $\nabla d = (\frac{\partial d}{\partial x}, \frac{\partial d}{\partial y}, \frac{\partial d}{\partial z})$ [S2, unofficial].
    *   If `SDF_MODE` is `'cubic'`:
        *   Retrieve the analytical gradient directly from the interpolation kernel.
        *   Formula: $\nabla d = \text{grid.eval\_cubic\_grad}(p)[1][0]$ [S2, unofficial].

4.  **Normal Computation (Optional):**
    *   To compute the surface normal $n$ at point $q$:
        *   Evaluate $\nabla d$ at $q$.
        *   Normalize the gradient: $n = \frac{\nabla d}{\|\nabla d\|}$ [S1, unofficial].
    *   To compute the directional derivative in direction $d$:
        *   Normalize $\nabla d$.
        *   Compute dot product: $D = \nabla d \cdot d$ [S2, unofficial].

**Pseudocode:**

```python
import numpy as np

class SDFQueryHandler:
    def __init__(self, sdf_name, epsilon=1e-5):
        if not is_valid_sdf_name(sdf_name):
            raise RuntimeError(f"unknown SDF '{sdf_name}'")
        self.sdf_name = sdf_name
        self.epsilon = epsilon
        self.grid = load_sdf_grid(sdf_name) # Returns 3D array of shape (res, res, res)
        self.mode = 'linear' # Default, can be set to 'cubic'

    def evaluate_value(self, p):
        """
        Evaluate SDF value at point p.
        p: tuple (x, y, z)
        """
        if self.mode == 'linear':
            # Trilinear interpolation
            return self.grid.eval(p)[0]
        elif self.mode == 'cubic':
            # Tricubic interpolation
            return self.grid.eval_cubic(p)[0]
        else:
            raise ValueError(f"Unknown SDF mode: {self.mode}")

    def evaluate_gradient(self, p):
        """
        Evaluate SDF gradient at point p.
        p: tuple (x, y, z)
        Returns: tuple (dx, dy, dz)
        """
        if self.mode == 'linear':
            # Central finite differences
            dx = (self.evaluate_value((p[0] + self.epsilon, p[1], p[2])) - 
                  self.evaluate_value((p[0] - self.epsilon, p[1], p[2]))) / (2 * self.epsilon)
            dy = (self.evaluate_value((p[0], p[1] + self.epsilon, p[2])) - 
                  self.evaluate_value((p[0], p[1] - self.epsilon, p[2]))) / (2 * self.epsilon)
            dz = (self.evaluate_value((p[0], p[1], p[2] + self.epsilon)) - 
                  self.evaluate_value((p[0], p[1], p[2] - self.epsilon))) / (2 * self.epsilon)
            return (dx, dy, dz)
        elif self.mode == 'cubic':
            # Analytical gradient from cubic interpolation
            return self.grid.eval_cubic_grad(p)[1][0]
        else:
            raise ValueError(f"Unknown SDF mode: {self.mode}")

    def query_normal(self, q):
        """
        Compute the surface normal at point q.
        q: tuple (x, y, z)
        Returns: normalized gradient vector
        """
        grad = self.evaluate_gradient(q)
        norm = np.sqrt(grad[0]**2 + grad[1]**2 + grad[2]**2)
        if norm == 0:
            return (0, 0, 0) # Degenerate case
        return (grad[0]/norm, grad[1]/norm, grad[2]/norm)

    def query_directional_derivative(self, q, direction):
        """
        Compute the directional derivative of the SDF at q in the given direction.
        q: tuple (x, y, z)
        direction: tuple (dx, dy, dz)
        """
        grad = self.evaluate_gradient(q)
        # Normalize gradient
        norm = np.sqrt(grad[0]**2 + grad[1]**2 + grad[2]**2)
        if norm == 0:
            return 0.0
        grad_normalized = (grad[0]/norm, grad[1]/norm, grad[2]/norm)
        # Dot product
        return grad_normalized[0]*direction[0] + grad_normalized[1]*direction[1] + grad_normalized[2]*direction[2]
```

**Parameters:**
*   `SDF_MODE`: String, `'linear'` or `'cubic'`. `'cubic'` provides smoother geometry and theoretically more robust gradients but is significantly slower [S2, unofficial].
*   `epsilon`: Float, default $10^{-5}$. Step size for finite difference gradient calculation in linear mode [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** In linear mode, the choice of `epsilon` affects gradient accuracy. Too small leads to numerical noise; too large leads to approximation error [S2, unofficial].
*   **Boundaries:** Queries outside the grid bounds require clamping or extrapolation logic, not explicitly detailed in the sources [G].
*   **Degenerate Input:** If the gradient magnitude is zero (e.g., at a local extremum or far from the surface), normal computation may fail or return a zero vector [G].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query for value evaluation. Gradient evaluation is $O(1)$ for cubic mode (analytical) and $O(1)$ for linear mode (requires 6 additional value evaluations) [S2, unofficial].
*   **Memory Complexity:** $O(res^3)$ to store the SDF grid [S2, unofficial].
*   **Performance:** Cubic interpolation is significantly slower than linear interpolation due to the complexity of the derivative calculations [S2, unofficial].
*   **Strengths:** Provides consistent gradient information for differentiable rendering; supports both analytical and numerical gradients [S2, unofficial].
*   **Limitations:** Cubic mode is computationally expensive; linear mode gradients are approximate and sensitive to `epsilon` [S2, unofficial].
*   **When to Use:** When differentiable SDF queries are required for rendering or optimization [S2, unofficial].
*   **When Not to Use:** When performance is critical and approximate gradients are acceptable (use linear mode) or when the SDF is defined by simple primitives (use analytical primitives directly) [S2, unofficial].

## Background
The method originates from differentiable rendering frameworks that support Signed Distance Fields, such as the "Relaxed Boundary" approach for differentiable rendering of SDFs [S2, unofficial]. It was developed to provide a robust interface for evaluating SDFs and their gradients in the context of inverse rendering and optimization [S2, unofficial]. The implementation is part of a broader ecosystem of SDF-based rendering tools, including subgrid marching for mesh processing [S1, unofficial].
