# Mandelbulb SDF Evaluation

Also called: Fractal SDF, Mandelbulb, Mandelbulb Distance Estimator, Mandelbulb Fractal SDF, Mandelbulb distance function, sdMandelbulb

## Overview
The Mandelbulb SDF Evaluation computes the signed distance from a 3D point to the boundary of the Mandelbulb fractal using an iterative derivative-based estimation [S3, unofficial]. It differs from standard primitives by using polar coordinate transformations and derivative tracking to approximate the distance to a non-algebraic surface [S1, S3, unofficial]. It builds on [SDF Evaluation Implementation](1658-sdf-evaluation-implementation.md).

## How it works
The method uses the distance estimation technique for iterated function systems, where the distance is approximated by the radius of the current point scaled by the logarithm of its magnitude and divided by the accumulated derivative of the iteration function [S2, S3, unofficial].

### Inputs and Outputs
*   **Input**:
    *   `point` (`vec3`): The 3D query point in world space [S1, S3, unofficial].
    *   `center` (`vec3`): The center of the Mandelbulb [S1, S3, unofficial].
    *   `scale` (`float`): Global scaling factor applied to the input point offset and the final returned distance [S1, S3, unofficial].
    *   `power` (`float`): Exponent for the fractal mapping that controls the geometric complexity and shape of the Mandelbulb [S1, S3, unofficial].
    *   `max_iterations` (`int`): Maximum number of fractal iterations performed per point evaluation [S1, S3, unofficial].
    *   `bailout` (`float`): Maximum radius threshold to break iteration early and prevent numerical overflow [S1, S3, unofficial].
*   **Output**:
    *   `distance` (`float`): The estimated signed distance from `point` to the Mandelbulb surface [S1, S3, unofficial].

### Data Structures
No persistent data structures are required [G]. Temporary variables include:
*   `z` (`vec3`): Current position in the transformed space [S1, S3, unofficial].
*   `dr` (`float`): Accumulated derivative of the iteration function with respect to the initial position [S1, S3, unofficial].
*   `r` (`float`): Magnitude (radius) of `z` [S1, S3, unofficial].
*   `theta`, `phi` (`float`): Spherical angles [S1, S3, unofficial].

### Steps
1.  **Initialization**:
    *   Translate and scale the input point: $z = \frac{\text{point} - \text{center}}{\text{scale}}$ [S1, S3, unofficial].
    *   Initialize derivative: $dr = 1.0$ [S1, S3, unofficial].
    *   Initialize radius: $r = 0.0$ [S1, S3, unofficial].
2.  **Iteration Loop**:
    *   For $i$ from 0 to `max_iterations` - 1:
        *   Calculate current radius: $r = \|z\|$ [S1, S2, S3, unofficial].
        *   **Bailout Check**: If $r > \text{bailout}$, break the loop [S1, S2, S3, unofficial].
        *   Convert to spherical coordinates:
            *   $\theta = \arccos\left(\frac{z_z}{r}\right)$ [S1, S3, unofficial].
            *   $\phi = \operatorname{atan2}(z_y, z_x)$ [S1, S3, unofficial].
        *   Update derivative:
            *   $dr = r^{\text{power} - 1} \cdot \text{power} \cdot dr + 1.0$ [S1, S2, S3, unofficial].
        *   Calculate radial power:
            *   $z_r = r^{\text{power}}$ [S1, S3, unofficial].
        *   Scale angles:
            *   $\theta \leftarrow \theta \cdot \text{power}$ [S1, S3, unofficial].
            *   $\phi \leftarrow \phi \cdot \text{power}$ [S1, S3, unofficial].
        *   Transform back to Cartesian coordinates:
            *   $z \leftarrow z_r \cdot (\sin\theta\cos\phi, \sin\theta\sin\phi, \cos\theta) + \frac{\text{point} - \text{center}}{\text{scale}}$ [S1, S3, unofficial].
3.  **Distance Calculation**:
    *   Calculate distance: $d = \frac{0.5 \cdot \ln(r) \cdot r}{dr}$ [S1, S3, unofficial].
    *   Scale the result: $d = d \cdot \text{scale}$ [S1, S3, unofficial].
    *   Return $d$ [S1, S3, unofficial].

### Pseudocode
```python
def sdMandelbulb(point: vec3, center: vec3, scale: float, power: float, max_iterations: int, bailout: float) -> float:
    # 1. Initialize
    z = (point - center) / scale
    dr = 1.0
    r = 0.0
    
    # 2. Iterate
    for i in range(max_iterations):
        r = length(z)
        if r > bailout:
            break
            
        # Guard against division by zero in acos
        if r < 1e-6:
            break
            
        # Spherical coordinates
        theta = acos(z.z / r)
        phi = atan2(z.y, z.x)
        
        # Update derivative
        dr = pow(r, power - 1.0) * power * dr + 1.0
        
        # Radial power
        zr = pow(r, power)
        
        # Scale angles
        theta = theta * power
        phi = phi * power
        
        # Transform back to Cartesian and add constant offset
        z.x = zr * sin(theta) * cos(phi)
        z.y = zr * sin(theta) * sin(phi)
        z.z = zr * cos(theta)
        z = z + (point - center) / scale
        
    # 3. Distance Estimator
    if r < 1e-6:
        return 0.0
        
    distance = 0.5 * log(r) * r / dr
    distance = distance * scale
    
    return distance
```

### Parameters
*   `power`: 8.0 is the classic Mandelbulb exponent [S3, unofficial].
*   `max_iterations`: Defined as an integer [S1, unofficial]. One implementation fixes it at 6 [S3, unofficial]. Not given in the sources.
*   `bailout`: 2.0 is standard for escape radius [S1, S3, unofficial].
*   `scale`: Depends on the desired size of the object in the scene [S1, S3, unofficial].

### Edge Cases and Pitfalls
*   **Division by Zero**: If $r=0$ (the point is exactly at the origin of the iteration space), $\arccos(z_z/r)$ is undefined. Guard against $r < \epsilon$ [G].
*   **Precision**: Floating point precision issues can cause jitter in the distance estimate for points very close to the surface, especially with high `power` values [G].
*   **Inside the Fractal**: The distance estimator $d = \frac{0.5 \ln(r) r}{dr}$ is valid for points outside the fractal (where $r \to \infty$) [G]. For points inside, the distance is not well-defined by this formula, and ray marching may fail or require a different estimator [G].

## Operating characteristics
*   **Time Complexity**: $O(I)$, where $I$ is the number of iterations [G]. Each iteration involves trigonometric functions and vector operations [G].
*   **Memory Complexity**: $O(1)$ [G]. No auxiliary memory is required [G].
*   **Performance**: The Mandelbulb SDF is computationally expensive per evaluation due to the trigonometric functions (`sin`, `cos`, `atan2`, `acos`) and power calculations [G]. It is significantly slower than primitive SDFs but allows for infinitely detailed geometry [G].
*   **Strengths**: Generates complex, organic-looking fractal geometry with a single function [G]. No mesh storage required [G].
*   **Limitations**: High computational cost [G]. The distance estimate is an approximation and may not be perfectly tight, potentially leading to slightly larger step sizes in ray marching or visual artifacts if the derivative is inaccurate [G].
