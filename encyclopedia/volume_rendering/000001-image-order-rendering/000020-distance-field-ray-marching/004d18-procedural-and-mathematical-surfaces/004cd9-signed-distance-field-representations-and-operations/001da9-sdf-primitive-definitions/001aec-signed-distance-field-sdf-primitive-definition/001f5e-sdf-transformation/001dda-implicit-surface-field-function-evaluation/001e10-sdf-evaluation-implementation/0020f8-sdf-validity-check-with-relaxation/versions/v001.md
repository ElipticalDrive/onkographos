# SDF Validity Check with Relaxation


## Overview
This method filters Signed Distance Field (SDF) samples to distinguish between valid near-surface points and invalid far-field points using a relaxation threshold. It solves the problem of ambiguous SDF values in sparse or noisy evaluations by classifying samples into positive, negative, and valid (near-zero) categories. It differs from [SDF Training with Eikonal Loss](2553-sdf-training-with-eikonal-loss.md) by applying a static geometric threshold rather than optimizing field gradients, and from [SDF Evaluation Implementation](1658-sdf-evaluation-implementation.md) by adding a specific validity classification step.

## How it works
**Inputs and Outputs:**
- Input: A set of SDF samples, where each sample consists of a signed distance value $d$ and the associated voxel size $v$.
- Output: A classification of each sample into one of three sets: Positive, Negative, or Valid.

**Data Structures:**
- `samples`: A list or array of tuples/objects containing fields `value` (float, the SDF result) and `voxel_size` (float, the spatial resolution of the query point).

**Parameters:**
- `relaxation`: A constant factor defining the width of the "valid" band around the zero-level set. Typical value: $1.5$ [S1, unofficial].

**Steps:**
1. For each sample $i$ with SDF value $d_i$ and voxel size $v_i$:
2. Calculate the threshold $T = v_i \times \text{relaxation}$.
3. Classify the sample:
   - If $d_i > T$, mark as **Positive**.
   - If $-d_i > T$ (i.e., $d_i < -T$), mark as **Negative**.
   - If $|d_i| \le T$, mark as **Valid**.

**Formulas:**
The classification logic is defined by:
$$
\text{class}(d, v) = 
\begin{cases} 
\text{Positive} & \text{if } d > v \cdot \text{relaxation} \\
\text{Negative} & \text{if } d < -v \cdot \text{relaxation} \\
\text{Valid} & \text{otherwise}
\end{cases}
$$

**Pseudocode:**
```python
def check_valid(samples, relaxation=1.5):
    """
    Classifies SDF samples based on a relaxation threshold relative to voxel size.
    
    Args:
        samples: List of objects/tuples with attributes 'value' (float) and 'voxel_size' (float).
        relaxation: Float constant for threshold scaling (default 1.5).
        
    Returns:
        List of tuples: (original_sample, classification_string)
        classification_string is one of: 'Positive', 'Negative', 'Valid'
    """
    results = []
    for sample in samples:
        d = sample.value
        v = sample.voxel_size
        
        threshold = v * relaxation
        
        if d > threshold:
            classification = 'Positive'
        elif d < -threshold:
            classification = 'Negative'
        else:
            classification = 'Valid'
            
        results.append((sample, classification))
        
    return results
```

**Edge Cases and Pitfalls:**
- **Zero Voxel Size:** If $v_i = 0$, the threshold becomes 0, potentially misclassifying small non-zero distances. [G] Ensure voxel sizes are strictly positive.
- **Precision Errors:** Floating-point inaccuracies near the boundary $|d| \approx T$ may cause jitter between "Valid" and "Positive/Negative". [G] Consider epsilon tolerance if stability is critical.
- **Degenerate Input:** Samples with undefined or NaN SDF values should be filtered out before this check.

## Subtopics

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of samples. Each sample requires constant-time arithmetic operations.
- **Memory Complexity:** $O(N)$ to store the classification results.
- **Strengths:** Simple, fast, and robust for filtering out irrelevant far-field data in ray marching or training pipelines.
- **Limitations:** Does not correct the SDF values themselves, only classifies them. Relies on accurate voxel size estimation.
- **When to use:** When preprocessing SDF data for rendering or training to ignore points too far from the surface.
- **When not to use:** When the goal is to refine the SDF geometry itself (use [Eikonal SDF Refinement](4597-eikonal-sdf-refinement.md) instead).

## Background
This method is implemented in the DIST-Renderer project by B1ueber2y. It serves as a utility for filtering SDF samples during synthesis or evaluation phases. The relaxation factor of 1.5 is a heuristic choice to define a "valid" band around the implicit surface.
