# Signed Box Distance Function

Also called: Box SDF, Rectangular (Axis-Aligned Box) SDF, SDF Box, SDF Cube, Signed Box, sdBox

## Overview
The Signed Box Distance Function computes the exact Euclidean signed distance from a query point to the surface of an axis-aligned box centered at the origin. It returns negative values for points inside the box and positive values for points outside, distinguishing interior from exterior space [S9, S11, unofficial]. Unlike the [Unsigned Box Distance Function](3750-unsigned-box-distance-function.md), which treats the box as a solid boundary with non-negative distances, this method provides the sign necessary for correct normal calculation and boolean operations in constructive solid geometry (CSG) [S1]. It is the 3D analog of the [Rectangle Signed Distance Function](4031-rectangle-signed-distance-function.md) and builds on the symmetry principles of the [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md) by exploiting octant symmetry [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `p`, a 3D point in space (vector).
- Input: `b`, the half-extents of the box (vector), where each component represents half the side length along that axis. Alternatively, the box can be defined by center `c` and side lengths `s`, where $b = s/2$.
- Output: A scalar float representing the signed Euclidean distance.

**Data Structures:**
- `p`: `vec3` (x, y, z).
- `b`: `vec3` (bx, by, bz).
- `c`: `vec3` (cx, cy, cz) if center-based definition is used.
- `s`: `vec3` (sx, sy, sz) if side-length definition is used.

**Algorithm:**
The method exploits the symmetry of the box across the three coordinate planes. By taking the absolute value of the point coordinates, the problem is reduced to the first octant, where the box occupies the region $[0, b_x] \times [0, b_y] \times [0, b_z]$.

1.  **Shift and Scale (if center-based):** If the box is defined by center `c` and side lengths `s`, compute the half-extents $b = s / 2$. Compute the relative point $p' = p - c$. Otherwise, use $p' = p$.
2.  **Symmetry Reduction:** Compute the absolute value of the relative point coordinates: $q = |p'|$. This maps the point into the first octant relative to the box center.
3.  **Distance to Faces:** Compute the vector $d = q - b$. This vector represents the signed distance to the nearest face along each axis.
    - If $d_i < 0$, the point is inside the box along axis $i$.
    - If $d_i \ge 0$, the point is outside the box along axis $i$.
4.  **Inside Distance:** Calculate the distance to the interior surface. This is determined by the maximum of the negative components of $d$ (the "deepest" penetration into the box).
    $$ d_{inside} = \max(d_x, \max(d_y, d_z)) $$
    If the point is outside, this value is non-positive (or zero). If inside, it is negative.
5.  **Outside Distance:** Calculate the Euclidean distance to the exterior surface. This is the length of the vector formed by the positive components of $d$ (the distance to the nearest face, edge, or corner).
    $$ d_{outside} = \| \max(d, 0) \| = \sqrt{\max(d_x, 0)^2 + \max(d_y, 0)^2 + \max(d_z, 0)^2} $$
6.  **Combine:** The final signed distance is the sum of the inside distance and the outside distance.
    $$ d(p) = d_{inside} + d_{outside} $$
    $$ d(p) = \max(d_x, \max(d_y, d_z)) + \| \max(d, 0) \| $$

**Pseudocode:**
```python
def signed_box_distance(p: Vec3, b: Vec3) -> float:
    """
    Computes the signed distance from point p to an axis-aligned box
    centered at the origin with half-extents b.
    
    Args:
        p: Query point (vec3).
        b: Half-extents of the box (vec3).
        
    Returns:
        Signed distance (float). Negative inside, positive outside.
    """
    # 1. Symmetry reduction: map to first octant
    # q = abs(p)
    qx = abs(p.x)
    qy = abs(p.y)
    qz = abs(p.z)
    
    # 2. Distance to faces: d = q - b
    dx = qx - b.x
    dy = qy - b.y
    dz = qz - b.z
    
    # 3. Inside distance: max of negative components
    # max(dx, max(dy, dz))
    inside_dist = max(dx, max(dy, dz))
    
    # 4. Outside distance: length of positive components
    # max(d, 0) applied component-wise
    pos_dx = max(dx, 0.0)
    pos_dy = max(dy, 0.0)
    pos_dz = max(dz, 0.0)
    
    # Euclidean norm
    outside_dist = sqrt(pos_dx**2 + pos_dy**2 + pos_dz**2)
    
    # 5. Combine
    return inside_dist + outside_dist

def signed_box_distance_centered(p: Vec3, c: Vec3, s: Vec3) -> float:
    """
    Computes the signed distance from point p to an axis-aligned box
    defined by center c and side lengths s.
    """
    # Compute half-extents
    b_x = s.x / 2.0
    b_y = s.y / 2.0
    b_z = s.z / 2.0
    
    # Shift point to box center
    p_x = p.x - c.x
    p_y = p.y - c.y
    p_z = p.z - c.z
    
    return signed_box_distance(Vec3(p_x, p_y, p_z), Vec3(b_x, b_y, b_z))
```

**Parameters:**
- `b` (half-extents): Typical values depend on scene scale. For a unit box, $b = (0.5, 0.5, 0.5)$ [S12, unofficial].
- `c` (center): Default $(0, 0, 0)$ if not specified [S9, unofficial].
- `s` (side lengths): Must be positive.

**Edge Cases and Pitfalls:**
- **Precision:** Near the surface, floating-point precision errors can cause jitter in normals or distance values. Using double precision can mitigate this [S12, unofficial].
- **Degenerate Input:** If any component of `b` is zero, the box becomes a plane, line, or point. The formula still holds but may produce unexpected results for ray marching if not handled by the caller [S11, unofficial].
- **Underestimation vs Overestimation:** The exact formula provides the true Euclidean distance. Approximations that underestimate the distance (e.g., using only the max component for outside points) cause smaller ray steps and slower convergence, and can lead to incorrect ambient occlusion [S12, S13, unofficial]. Overestimation can cause the ray to pass through the surface [S12, unofficial].

## Subtopics

### [Unsigned Box Distance Function](3750-unsigned-box-distance-function.md)
The Unsigned Box Distance Function computes the Euclidean distance from a query point to the surface of an axis-aligned box centered at the origin, returning only non-negative values regardless of whether the point lies inside or outside the volume. Unlike its sibling, the Signed Box Distance Function, which distinguishes interior from exterior space, this method treats the box as a solid boundary where internal points are measured by their distance to the nearest face. It is useful when the interior of the object is not relevant or when using distance fields for collision detection where only the boundary matters.

### [Rectangle Signed Distance Function](4031-rectangle-signed-distance-function.md)
Computes the exact Euclidean distance from a query point to the boundary of an axis-aligned rectangle centered at the origin. It serves as a fundamental primitive for distance-field ray marching, allowing for efficient collision detection and rendering of rectangular shapes without polygonal approximation. It is the 2D analog of the [Signed Box Distance Function](1092-signed-box-distance-function.md).

#### Box with Edge Rounding SDF
Computes the signed distance to a box with rounded edges, defined by half-extents $b$ and edge radius $e$ [S15, unofficial]. The algorithm computes $p' = |p| - b$, then $q = |p' + e| - e$, and returns the minimum of three terms representing distance to face, edge, or corner with rounding [S15, unofficial]. This variant is chosen when smooth, rounded corners are desired for aesthetic or physical realism, avoiding the sharp discontinuities of the standard box SDF.

#### Oriented Box2D SDF
Computes the signed distance to a 2D box with custom orientation and thickness between points `a` and `b`, where `th` is the full thickness perpendicular to the segment $[a, b]$ [S11, unofficial]. If the segment length is negligible, it falls back to a circle SDF. Otherwise, it rotates the query point into the local frame of the segment and calls the 2D box SDF. This variant is chosen for rendering oriented rectangular objects in 2D space, such as rotated UI elements or tilted planes.

## Operating characteristics
**Time Complexity:** $O(1)$ per query. The computation involves a constant number of arithmetic operations (absolute values, subtractions, max/min, and a square root).
**Memory Complexity:** $O(1)$. No auxiliary data structures are required.
**Measured Performance:** On modern GPUs, this is one of the fastest SDF primitives to evaluate. The square root operation is the most expensive part, but it is only computed when the point is outside the box. Inside the box, only max/min operations are needed.
**Scaling:** The method scales linearly with the number of query points (e.g., in a ray marching loop). It is independent of scene complexity, as it only depends on the box parameters.
**Strengths:** Exact Euclidean distance, fast evaluation, supports CSG operations (union, intersection, difference) via min/max operations, provides correct normals via gradient.
**Limitations:** Only applies to axis-aligned boxes. For oriented boxes, a transformation matrix must be applied to the query point before evaluation, which adds computational cost. The sharp corners can cause aliasing in ambient occlusion if the ray marching steps are too large [S13, unofficial].
**When to use:** When rendering axis-aligned boxes, cubes, or rectangular prisms. Ideal for voxel-like structures, UI elements, or simple geometric primitives.
**When not to use:** When the box is rotated (use a transformed point or a different primitive). When rounded corners are required (use the Box with Edge Rounding SDF).

## Background
The Signed Box Distance Function is a fundamental primitive in the field of Signed Distance Fields (SDFs) and ray marching. It was popularized by Inigo Quilez in his online resources on distance functions [S2, unofficial]. The method exploits the symmetry of the box to reduce the computation to the first octant, a technique widely used in computer graphics for efficient geometric queries. It is used in real-time rendering, implicit modeling, and collision detection. The exact formula ensures that the distance field is a true Euclidean distance function, which is critical for correct sphere tracing and ambient occlusion calculations [S12, S13, unofficial].
