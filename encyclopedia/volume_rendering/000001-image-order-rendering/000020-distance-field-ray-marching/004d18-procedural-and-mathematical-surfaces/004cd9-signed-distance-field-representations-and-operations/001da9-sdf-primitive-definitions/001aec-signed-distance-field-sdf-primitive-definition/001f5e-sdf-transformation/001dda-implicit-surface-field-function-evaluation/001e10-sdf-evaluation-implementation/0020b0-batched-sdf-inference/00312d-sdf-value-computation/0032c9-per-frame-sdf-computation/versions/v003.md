# Per-Frame SDF Computation

## Overview
Per-Frame SDF Computation calculates the Signed Distance Function (SDF) and RGB color for a set of 3D points by projecting them into a single camera view [S1, unofficial]. It solves the problem of assigning geometric and photometric consistency to 3D points relative to a specific training view by comparing projected depths against a pre-computed depth map [S1, unofficial]. It differs from multi-view fusion methods by operating on a single viewpoint at a time, serving as the atomic unit for subsequent TSDF fusion or colorization [G].

## How it works
**Inputs:**
- `points`: Tensor of shape $(N, 3)$ containing 3D point coordinates in world space [G].
- `full_proj_transform`: Tensor of shape $(4, 4)$ representing the combined projection and view transformation matrix [G].
- `depth_map`: Tensor of shape $(H, W)$ containing the depth values for the current view [G].
- `rgb_map`: Tensor of shape $(H, W, 3)$ containing the RGB color values for the current view [G].

**Outputs:**
- `sdf`: Tensor of shape $(N, 1)$ containing the signed distance values [G].
- `rgb`: Tensor of shape $(N, 3)$ containing the sampled RGB colors [G].
- `mask`: Boolean tensor of shape $(N, 1)$ indicating valid projections [G].

**Data Structures:**
- Points, depth, and RGB maps are stored as floating-point tensors [G].

**Steps:**
1. **Homogenization**: Append a column of ones to `points` to create homogeneous coordinates of shape $(N, 4)$ [S1, unofficial].
2. **Projection**: Multiply the homogeneous points by `full_proj_transform` to obtain clip-space coordinates [S1, unofficial].
   $$ p_{clip} = P_{world} \times M_{proj} $$
   Where $P_{world}$ is the $(N, 4)$ homogeneous point matrix and $M_{proj}$ is the $(4, 4)$ transformation matrix [S1, unofficial].
3. **Perspective Division**: Extract the $z$-coordinate ($z_{clip}$) and divide the $x$ and $y$ coordinates by $z_{clip}$ to compute normalized device coordinates (NDC) [S1, unofficial].
   $$ x_{ndc} = \frac{x_{clip}}{z_{clip}}, \quad y_{ndc} = \frac{y_{clip}}{z_{clip}} $$
4. **Masking**: Create a boolean mask where $-1 \le x_{ndc} \le 1$, $-1 \le y_{ndc} \le 1$, and $z_{clip} > 0$ [S1, unofficial]. Points failing any condition are invalid [S1, unofficial].
5. **Depth Sampling**: Sample the `depth_map` at $(x_{ndc}, y_{ndc})$ using bilinear interpolation with border padding, then reshape to $(N, 1)$ [S1, unofficial].
6. **Color Sampling**: Sample the `rgb_map` at $(x_{ndc}, y_{ndc})$ using bilinear interpolation with border padding, then reshape to $(N, 3)$ [S1, unofficial].
7. **SDF Calculation**: Compute the SDF as the difference between the sampled depth and the projected $z$-coordinate [S1, unofficial].
   $$ sdf = d_{sampled} - z_{clip} $$

**Pseudocode:**
```python
def compute_sdf_perframe(points, full_proj_transform, depth_map, rgb_map):
    # points: (N, 3), full_proj_transform: (4, 4), depth_map: (H, W), rgb_map: (H, W, 3)
    N = len(points)
    H, W = len(depth_map), len(depth_map[0])
    
    # 1. Homogenize
    points_homo = [[p[0], p[1], p[2], 1.0] for p in points]
    
    # 2. Project to clip space
    points_clip = [[sum(points_homo[i][k] * full_proj_transform[k][j] for k in range(4)) for j in range(4)] for i in range(N)]
    x_clip = [p[0] for p in points_clip]
    y_clip = [p[1] for p in points_clip]
    z_clip = [p[2] for p in points_clip]
    
    # 3. Perspective division
    eps = 1e-7
    x_ndc = [x / (z + eps) for x, z in zip(x_clip, z_clip)]
    y_ndc = [y / (z + eps) for y, z in zip(y_clip, z_clip)]
    
    # 4. Create projection mask
    mask = [(x >= -1.0 and x <= 1.0 and y >= -1.0 and y <= 1.0 and z > 0) for x, y, z in zip(x_ndc, y_ndc, z_clip)]
    
    # 5 & 6. Sample depth and RGB (bilinear with border padding)
    def bilinear_sample(map_data, u, v):
        u0, u1 = max(0, min(int(u), W-2)), max(0, min(int(u)+1, W-1))
        v0, v1 = max(0, min(int(v), H-2)), max(0, min(int(v)+1, H-1))
        fu, fv = u - int(u), v - int(v)
        wa, wb, wc, wd = (1-fu)*(1-fv), (1-fu)*fv, fu*(1-fv), fu*fv
        if len(map_data[0][0]) == 3:
            return [wa*map_data[v0][u0][c] + wb*map_data[v0][u1][c] + wc*map_data[v1][u0][c] + wd*map_data[v1][u1][c] for c in range(3)]
        return wa*map_data[v0][u0] + wb*map_data[v0][u1] + wc*map_data[v1][u0] + wd*map_data[v1][u1]
        
    depth_sampled = []
    rgb_sampled = []
    for i in range(N):
        u = (x_ndc[i] + 1.0) / 2.0 * (W - 1)
        v = (y_ndc[i] + 1.0) / 2.0 * (H - 1)
        depth_sampled.append(bilinear_sample(depth_map, u, v))
        rgb_sampled.append(bilinear_sample(rgb_map, u, v))
        
    # 7. Compute SDF
    sdf = [d - z for d, z in zip(depth_sampled, z_clip)]
    
    return sdf, rgb_sampled, mask
```

**Parameters:**
- `padding_mode`: 'border' is used to handle out-of-bounds coordinates [S1, unofficial].
- `align_corners`: False is used for standard grid sampling [G].

**Edge Cases:**
- **Division by Zero**: If $z_{clip} \le 0$, the point is behind the camera or on the near plane, and these points are masked out [S1, unofficial].
- **Out of Bounds**: Points projecting outside $[-1, 1]$ in NDC space are masked out, and border padding ensures sampling does not return NaN or extreme values for slightly out-of-bounds points [S1, unofficial].

## Subtopics

### [Point Colorization via Projective SDF](10792-point-colorization-via-projective-sdf.md)
Point Colorization via Projective SDF assigns RGB colors to a set of 3D points by projecting them into training views, filtering based on alpha confidence and projective depth consistency, and sampling the closest valid color from the rendered reference frames. It differs from standard nearest-neighbor colorization by enforcing geometric consistency through a projective SDF metric, ensuring that sampled colors correspond to the visible surface rather than occluded geometry or background.

### Unbounded TSDF Fusion
Unbounded TSDF Fusion extends Per-Frame SDF Computation by fusing SDF values from multiple frames in contracted space with adaptive truncation, then uncontracting the space [S1, unofficial]. If an inverse contraction transform is provided, points outside the unit sphere ($||samples|| > 1$) are identified [S1, unofficial]. The base truncation $sdf\_trunc$ is set to $5 \times voxel\_size$ [S1, unofficial]. For points outside the unit sphere, truncation is scaled by $1/(2-||x||)$ [S1, unofficial]. If no inverse contraction is provided, $sdf\_trunc$ remains a constant $5 \times voxel\_size$ [S1, unofficial]. TSDFs are initialized to -1, RGBs to 0, and weights to 1 [S1, unofficial]. The algorithm iterates through a `viewpoint_stack`, calling `compute_sdf_perframe` for each view [S1, unofficial]. The SDF is flattened, and the mask is updated to include points where $SDF > -sdf\_trunc$ [S1, unofficial]. SDF is normalized by $sdf\_trunc$, clamped to $[-1, 1]$, and the mask is applied [S1, unofficial]. TSDF and RGB are updated using a weighted average: $new = (old \times w + val) / (w + 1)$ [S1, unofficial]. Weights are updated: $w_{new} = w_{old} + 1$ [S1, unofficial]. If inverse contraction is provided, samples are uncontracted before returning [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N)$ per frame, where $N$ is the number of points, dominated by matrix multiplication and bilinear sampling [G].
- **Memory Complexity**: $O(N)$ for storing intermediate tensors (clip coordinates, NDC, masks, sampled values) [G].
- **Strengths**: Efficiently computes geometric consistency for a single view and integrates seamlessly with multi-view fusion pipelines [G].
- **Limitations**: Only considers one view at a time and does not handle occlusions from other views within the single-frame computation (this is handled in the fusion step) [G].
- **When to use**: When initializing or updating SDF fields for a specific training view [G].
- **When not to use**: When multi-view consistency is required immediately without fusion [G].

## Background
Per-Frame SDF Computation is part of the 2D Gaussian Splatting pipeline, specifically used in the context of post-processing or refining 3D points using depth information from training views [S1, unofficial]. It originates from the work on 2D Gaussian Splatting by Inria's GRAPHDECO research group [S1, unofficial].
