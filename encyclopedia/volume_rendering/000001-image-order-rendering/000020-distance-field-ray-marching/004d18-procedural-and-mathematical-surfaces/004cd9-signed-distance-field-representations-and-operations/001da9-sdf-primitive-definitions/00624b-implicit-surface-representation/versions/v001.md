# Implicit Surface Representation

Also called: Grid-based SDF, Tricubic SDF, Zero-level set surface

## Overview
This method represents an implicit surface as a grid-based Signed Distance Function (SDF) using tricubic interpolation to ensure continuous surface normals [S2]. It defines the surface geometry as the zero-level set of a scalar field $f_{implicit}(\mathbf{p})$ [S1, unofficial]. It is distinguished from analytical primitives by its reliance on discrete grid storage and higher-order interpolation, which provides $C^1$ continuity for shading, whereas analytical methods (like [Standard Solid Primitives](16223-standard-solid-primitives.md)) are typically only $C^0$ or discontinuous at boundaries.

## How it works
**Inputs and Outputs**
*   **Input:** A 3D grid of scalar values representing the signed distance to the surface at grid vertices.
*   **Output:** A continuous scalar field $f_{implicit}(\mathbf{p})$ and its gradient $\nabla f_{implicit}(\mathbf{p})$ for any query point $\mathbf{p} \in \mathbb{R}^3$.

**Data Structures**
The core data structure is a 3D array (grid) of floating-point values. Let $G$ be a grid of size $N_x \times N_y \times N_z$. Each cell $(i, j, k)$ stores the distance value $d_{i,j,k}$ at the corresponding vertex. The grid spacing (resolution) is uniform, denoted by $\Delta$.

**Formulas**
The implicit surface $S_{implicit}$ is defined as the set of points where the function evaluates to zero [S1, unofficial]:
$$
S_{implicit} = \left\{ \begin{pmatrix} x \\ y \\ z \end{pmatrix} \in \mathbb{R}^3 \mid f_{implicit}(x, y, z) = 0 \right\}
$$

To evaluate $f_{implicit}(\mathbf{p})$ and its normal $\mathbf{n} = \nabla f_{implicit}(\mathbf{p})$ at an arbitrary point $\mathbf{p}$, tricubic interpolation is performed. Let $\mathbf{p}$ lie within a grid cell defined by vertices $\mathbf{v}_{ijk}$ for $i,j,k \in \{0,1\}$. The value is computed by applying 1D cubic Hermite interpolation along each axis.

**Parameters**
*   **Grid Resolution:** Determines the spatial frequency of the SDF. Higher resolution increases accuracy but memory cost.
*   **Interpolation Order:** Tricubic (order 3) is specified to ensure continuous normals [S2].

**Pseudocode**
```python
def evaluate_tricubic_sdf(grid, p, spacing):
    """
    Evaluates the implicit surface function and its gradient at point p
    using tricubic interpolation on a uniform grid.
    
    Args:
        grid: 3D numpy array of shape (Nx, Ny, Nz) containing distance values.
        p: 3D vector (x, y, z) of the query point.
        spacing: float, the uniform distance between grid vertices.
        
    Returns:
        value: float, the signed distance f(p).
        normal: 3D vector, the gradient df/dp (surface normal).
    """
    # 1. Map world point to grid coordinates
    # Assume grid origin is at (0,0,0) for simplicity; adjust if offset exists.
    gx = p[0] / spacing
    gy = p[1] / spacing
    gz = p[2] / spacing
    
    # 2. Find the base cell indices (floor)
    ix = int(floor(gx))
    iy = int(floor(gy))
    iz = int(floor(gz))
    
    # 3. Calculate local fractional coordinates within the cell [0, 1]
    tx = gx - ix
    ty = gy - iy
    tz = gz - iz
    
    # 4. Retrieve the 8 corner values and their gradients (if stored)
    # Note: Standard SDF grids store only values. To get continuous normals
    # via tricubic interpolation, one typically needs the gradients at vertices
    # or computes them from the values. The source [S2] cites diffsdf which
    # implies a specific implementation. Here we assume a standard tricubic
    # interpolation that requires vertex values and potentially vertex gradients.
    # If only values are stored, bicubic/tricubic interpolation of values alone
    # does not guarantee C1 continuity of the gradient unless the grid is
    # constructed specifically (e.g., via gradient descent optimization).
    # We assume the grid stores values and we compute the field value.
    
    # Retrieve 8 corner values
    # Handle boundary checks [G]
    def get_val(i, j, k):
        if 0 <= i < grid.shape[0] and 0 <= j < grid.shape[1] and 0 <= k < grid.shape[2]:
            return grid[i, j, k]
        return 0.0 # [G] Default to 0 or infinity for out-of-bounds; implementation dependent.

    v000 = get_val(ix, iy, iz)
    v100 = get_val(ix+1, iy, iz)
    v010 = get_val(ix, iy+1, iz)
    v110 = get_val(ix+1, iy+1, iz)
    v001 = get_val(ix, iy, iz+1)
    v101 = get_val(ix+1, iy, iz+1)
    v011 = get_val(ix, iy+1, iz+1)
    v111 = get_val(ix+1, iy+1, iz+1)

    # 5. Perform Tricubic Interpolation
    # First, interpolate along X for each YZ plane
    # Cubic Hermite kernel for value and derivative? 
    # Standard tricubic interpolation of values only yields C0 continuity.
    # To achieve C1 (continuous normals) as stated in [S2], the underlying
    # data usually includes vertex gradients or the grid is optimized such that
    # the interpolated field is smooth. 
    # Without explicit vertex gradients in the grid structure description,
    # we assume a standard tricubic blend of values.
    
    # Interpolate along X
    v00 = cubic_hermite(v000, v100, tx)
    v01 = cubic_hermite(v010, v110, tx)
    v10 = cubic_hermite(v001, v101, tx)
    v11 = cubic_hermite(v011, v111, tx)
    
    # Interpolate along Y
    v0 = cubic_hermite(v00, v10, ty)
    v1 = cubic_hermite(v01, v11, ty)
    
    # Interpolate along Z
    value = cubic_hermite(v0, v1, tz)
    
    # 6. Compute Normal (Gradient)
    # The normal is the gradient of the interpolated field.
    # If only values are stored, the gradient is approximated by finite differences
    # or requires storing vertex gradients. [S2] implies continuous normals,
    # suggesting the method in diffsdf handles this. 
    # A robust implementation would compute the gradient of the tricubic basis functions.
    # For brevity and based on "grid-based SDF with tricubic interpolation",
    # we note that the gradient is derived from the same interpolation weights.
    
    # [G] Specific gradient computation depends on whether vertex gradients are stored.
    # If not, finite difference of the interpolated value is a common fallback,
    # though it breaks the C1 guarantee of the interpolation itself.
    # We assume the standard approach: compute gradient of the tricubic polynomial.
    
    normal = compute_tricubic_gradient(grid, ix, iy, iz, tx, ty, tz, spacing)
    
    return value, normal

def cubic_hermite(p0, p1, t):
    """Standard cubic Hermite interpolation for values only (C0)."""
    # This is insufficient for C1 normals. 
    # True tricubic for C1 requires derivatives.
    # Given the constraint of "grid-based SDF", we assume the grid allows
    # for smooth evaluation.
    return (2*t*t*t - 3*t*t + 1)*p0 + (t*t*t - 2*t*t + t)*p1 # Placeholder for derivative info
```
*Note: The pseudocode above highlights the ambiguity. Achieving continuous normals with *only* vertex values requires the interpolation function itself to be $C^1$, which standard tricubic interpolation of values is not (it is $C^0$). The source [S2] cites `diffsdf`, which typically optimizes the grid values such that the resulting field is smooth, or stores auxiliary gradient data. A strict implementation requires vertex gradients $\mathbf{g}_{ijk}$ to be stored in the grid structure.*

**Edge Cases**
*   **Boundary Conditions:** Points outside the grid bounds require clamping or extrapolation.
*   **Precision:** Floating-point errors in interpolation can cause artifacts near the zero-level set.

## Operating characteristics
*   **Memory:** $O(N_x N_y N_z)$ for the grid storage.
*   **Time:** Evaluation is $O(1)$ per query point, involving a fixed number of arithmetic operations for interpolation.
*   **Strengths:** Continuous surface normals enable smooth shading and differentiable rendering without explicit mesh extraction [S2].
*   **Limitations:** Memory usage scales with volume rather than surface area. High resolution is needed for fine details.

## Background
This representation is used in differentiable rendering pipelines, specifically in the implementation based on the `cuda_ad_rgb` backend of Mitsuba 3 [S2]. It builds on the principles of Signed Distance Field Representations and Operations.
