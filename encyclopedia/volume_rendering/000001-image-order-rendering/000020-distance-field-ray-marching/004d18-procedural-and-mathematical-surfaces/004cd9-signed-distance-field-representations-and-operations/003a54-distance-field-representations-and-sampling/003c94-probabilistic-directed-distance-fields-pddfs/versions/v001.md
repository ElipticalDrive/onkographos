# Probabilistic Directed Distance Fields (PDDFs)
Also called: Probabilistic DDF, Directional Distance Fields (DDF)

## Overview
Probabilistic Directed Distance Fields (PDDFs) are a neural scene representation that models 3D geometry as a 5D function mapping a position and viewing direction to a directional distance and a hit probability [S1, S2]. Unlike standard Signed Distance Fields (SDFs) which require iterative sphere tracing to locate the surface, PDDFs enable differentiable rendering and shape optimization with a single forward pass per ray [S1, S2]. They are distinguished from sibling methods by their explicit modeling of ray-surface visibility ($\sigma$) and their ability to differentiably handle the discontinuities inherent in ray-based distance fields, allowing for efficient inverse rendering and generative modeling [S1, S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $\mathbf{p}$ on the unit sphere ($\mathbf{p} \in S^2$), a direction vector $\mathbf{r} \in S^2$ pointing from $\mathbf{p}$, a latent code $\mathbf{z} \in \mathbb{R}^{R_L}$ representing the specific shape, and a high-dimensional feature vector $\mathbf{f}_{pd}(\mathbf{p}, \mathbf{r}) \in \mathbb{R}^{15 \times K}$ derived from DDF grids [S1].
*   **Output:** A directional distance $d \in \mathbb{R}^+$ and a hit probability $\sigma \in [0, 1]$ [S1].

**Data Structures:**
The core data structure is a Multi-Layer Perceptron (MLP) with parameters $\Theta_d$. The MLP takes the concatenated input vector $[\mathbf{p}, \mathbf{r}, \mathbf{z}, \mathbf{f}_{pd}(\mathbf{p}, \mathbf{r})]$ (dimension $\mathbb{R}^6 + R_L + 15K$) and outputs the tuple $(d, \sigma)$ [S1]. Inputs $\mathbf{p}$ and $\mathbf{r}$ are encoded using positional encoding [S1].

**Relationship to SDF:**
The PDDF is defined on the surface of the unit sphere enclosing the object. The Signed Distance Function (SDF) at any point $\mathbf{x} \in \mathbb{R}^3$ is the minimum directional distance over all possible directions $\mathbf{r}$:
$$ \text{SDF}(\mathbf{x}) = \min_{\mathbf{r}} \text{DDF}(\mathbf{x}, \mathbf{r}) $$
where $\mathbf{r} \in S^2$ is a direction from $\mathbf{x}$ pointing towards the surface [S1].

**Key Constraint:**
The directional distance $d_{\sigma=1}$ predicted for a direction with hit probability $\sigma=1$ must correspond to a point on the surface, such that the SDF at that point is zero:
$$ \text{SDF}(\mathbf{p} + d_{\sigma=1}\mathbf{r}) = 0, \quad d_{\sigma=1} = \text{DDF}(\mathbf{p}, \mathbf{r}) \text{ when } \sigma=1 $$
[S1].

**Algorithm / Implementation Steps:**
1.  **Encode Inputs:** Apply positional encoding to the query point $\mathbf{p}$ and direction $\mathbf{r}$ [S1].
2.  **Feature Retrieval:** Retrieve the high-dimensional feature vector $\mathbf{f}_{pd}(\mathbf{p}, \mathbf{r})$ from the pre-computed DDF grids [S1].
3.  **Network Forward Pass:** Feed the encoded $(\mathbf{p}, \mathbf{r})$, latent code $\mathbf{z}$, and feature vector $\mathbf{f}_{pd}$ into the MLP $f_d$ with parameters $\Theta_d$:
    $$ (d, \sigma) = f_d((\mathbf{p}, \mathbf{r}), \mathbf{z}, \mathbf{f}_{pd}(\mathbf{p}, \mathbf{r}); \Theta_d) $$
    [S1].
4.  **Surface Intersection:** For rendering or optimization, the surface intersection along ray $\mathbf{r}$ is approximated by $\mathbf{x} = \mathbf{p} + d\mathbf{r}$. The probability $\sigma$ indicates the likelihood that this intersection is valid (i.e., the ray actually hits the object surface rather than passing through empty space or hitting a back-face) [S1, S2].
5.  **Differentiable Rendering:** Because $d$ and $\sigma$ are differentiable outputs of the MLP, gradients can be backpropagated through the ray intersection to optimize $\mathbf{z}$ or $\Theta_d$ directly from image or depth supervision [S2].

**Pseudocode:**
```python
def evaluate_pddf(p, r, z, f_pd, model_params):
    """
    Evaluates the Probabilistic Directed Distance Field.
    
    Args:
        p: Point on unit sphere, shape (3,)
        r: Direction vector, shape (3,)
        z: Latent code for the shape, shape (R_L,)
        f_pd: High-dimensional feature vector from DDF grids, shape (15*K,)
        model_params: Parameters Theta_d for the MLP
        
    Returns:
        d: Directional distance, scalar
        sigma: Hit probability, scalar in [0, 1]
    """
    # 1. Positional Encoding for p and r
    # [G] Assuming a standard NeRF-style positional encoding function
    p_enc = positional_encoding(p)
    r_enc = positional_encoding(r)
    
    # 2. Concatenate inputs
    # Input vector: [p_enc, r_enc, z, f_pd]
    # Note: The exact dimensionality depends on the encoding expansion factor
    input_vector = concatenate([p_enc, r_enc, z, f_pd])
    
    # 3. Forward pass through MLP
    # [G] model_params contains weights and biases of the MLP
    output = mlp_forward(input_vector, model_params)
    
    # 4. Extract outputs
    d = output[0]       # Directional distance
    sigma = output[1]   # Hit probability
    
    return d, sigma
```

**Edge Cases and Pitfalls:**
*   **Unit Sphere Assumption:** The method assumes the 3D shapes are contained within the unit sphere. Queries outside this domain may yield invalid results [S1].
*   **Discontinuities:** Standard DDFs have discontinuities where rays become tangent to the surface or occluded. PDDFs model these probabilistically to allow differentiable training, but care must be taken with the definition of $\sigma$ near occlusion boundaries [S2].
*   **View Consistency:** DDFs are inherently view-dependent. Theoretical analysis suggests specific constraints are needed to ensure the field represents a consistent 3D shape across different viewpoints [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per ray evaluation (single MLP forward pass), compared to $O(N)$ for sphere tracing where $N$ is the number of steps [S1]. This accelerates inverse rendering algorithms by approximately 15.5× [S1].
*   **Memory Complexity:** Requires storing the MLP parameters $\Theta_d$, the latent code $\mathbf{z}$, and the high-dimensional feature grids $\mathbf{f}_{pd}$ [S1].
*   **Strengths:** Enables differentiable rendering with a single forward pass per pixel; supports generative modeling and single-image reconstruction; handles complex topologies without restrictions on watertightness [S2].
*   **Limitations:** Requires pre-computation of feature grids; view-dependent artifacts may occur if consistency constraints are not met; limited to shapes inside the unit sphere [S1, S2].

## Background
PDDFs were introduced to address the computational cost of sphere tracing in inverse rendering and the difficulty of training neural networks on discontinuous distance fields [S1, S2]. The concept of Directional Distance Fields (DDFs) was first proposed in "FIRe: Fast Inverse Rendering Using Directional and Signed Distance Functions" [S1]. The probabilistic extension, which differentiably models discontinuities, was detailed in "Probabilistic Directed Distance Fields for Ray-Based Shape Representations" [S2]. These methods are used in single-shape fitting, generative modeling, 3D reconstruction, and path tracing [S2].
