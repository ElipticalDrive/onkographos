# Distance Field Representations and Sampling


## Overview
This family covers techniques for representing, storing, and querying distance fields (typically Signed Distance Fields, SDFs) to support ray marching and other geometric queries. It addresses the problem of efficiently accessing distance values from various data structures (textures, grids, sparse sets) while maintaining the Lipschitz continuity required for safe ray stepping [S1, S2, 1115-bounded-3d-distance-texture-ray-marching.md, 17003-sparse-point-set-haptic-rendering-via-distance-field.md]. It sets itself apart from [SDF Primitive Definitions](1578-sdf-primitive-definitions.md) by focusing on the *storage and sampling* of complex or pre-computed fields rather than analytical primitives, and from [SDF Transformations](11027-sdf-transformations.md) by focusing on the data structure itself rather than coordinate mapping.

## Shared principles
The family operates on the principle that a scene is defined by a scalar field $f(\mathbf{p})$ where the zero-level set $f(\mathbf{p}) = 0$ represents the surface. For sphere tracing to be valid, the function must satisfy the Lipschitz condition with constant 1, ensuring $|f(\mathbf{p}_1) - f(\mathbf{p}_2)| \le \|\mathbf{p}_1 - \mathbf{p}_2\|$. This guarantees that the value $f(\mathbf{p})$ is a safe lower bound on the distance to the surface, allowing the ray marcher to step forward by exactly $f(\mathbf{p})$ without tunneling [S2, S5, 9643, unofficial].

Composition is achieved through Boolean operations on the distance values:
*   **Union**: $f_{union}(\mathbf{p}) = \min(f_1(\mathbf{p}), f_2(\mathbf{p}))$ .
*   **Intersection**: $f_{intersect}(\mathbf{p}) = \max(f_1(\mathbf{p}), f_2(\mathbf{p}))$ .
*   **Subtraction**: $f_{sub}(\mathbf{p}) = \max(-f_1(\mathbf{p}), f_2(\mathbf{p}))$ .

Transformations are applied by mapping the query point $\mathbf{p}$ into the local coordinate space of the primitive using the inverse transformation matrix $M^{-1}$ before evaluation . Procedural noise (e.g., FBM) is often used to perturb these analytical surfaces, creating hypertextures where the isosurface is defined by $SDF(\mathbf{p}) + B_n(\mathbf{p}) = 0$ [S1, unofficial].

## Subtopics

### [Bounded 3D Distance Texture Ray Marching](1115-bounded-3d-distance-texture-ray-marching.md)
Bounded 3D Distance Texture Ray Marching is a technique for rendering implicit surfaces defined by a 3D distance texture, specifically addressing the problem of invalid distance values at the texture boundaries. It employs two nested bounding boxes (an inner "red" box and an outer "green" box) to distinguish between valid texture data and a boundary shell where samples may be unreliable. Unlike standard texture lookups that might return erroneous distances near edges, this method returns the distance to the outer boundary for points in the invalid shell, ensuring the ray marcher steps safely without tunneling into undefined data. It enables the inclusion of pre-computed distance textures (e.g., the Stanford Bunny) into scenes using standard SDF composition operators.

### [Sparse Point Set Haptic Rendering via Distance Field](17003-sparse-point-set-haptic-rendering-via-distance-field.md)
This method provides haptic rendering for sparse, oriented point cloud data by constructing a 3D signed distance field (SDF) on a regular grid using embedded "packing spheres". It solves the problem of generating stable collision forces from incomplete geometric data where traditional mesh-based or dense implicit function methods fail due to sparsity. Unlike sibling methods that rely on dense sampling or explicit surface reconstruction, this technique uses the local normal direction to define minimum-volume spheres that approximate the object's interior, allowing a proxy to be constrained to the zero-iso-surface via gradient descent.

### Sampler Abstraction
**Definition**: A trait-based abstraction for sampling distance fields defined in terms of specific Distance metrics. It allows samplers to abstract sampling across multiple different Distance metrics [S1, unofficial].
**Implementation**:
*   If `S` implements `ScalarSource`, `Sampler` implements `Sample<Signed>`. The sample method calls `self.source.sample_scalar(p)` [S1, unofficial].
*   If `S` implements `VectorSource`, `Sampler` implements `Sample<Directed>`. The sample method calls `self.source.sample_vector(p)` [S1, unofficial].
*   If `S` implements `HermiteSource`, `Sampler` implements `sample_normal` method which calls `self.source.sample_normal(p)` [S1, unofficial].
**Layout**: The `Sampler` struct contains a reference to the source (`&'a S`). It implements the `Sample<D>` trait for `Signed` and `Directed` distance types based on the source implementing `ScalarSource` or `VectorSource` [S1, unofficial].

### Ray Marching through Distance Fields
**Definition**: A traversal method where ray marching is performed through distance fields. Naive storage of one distance value per voxel is impractical for large grids due to memory and bandwidth costs [S2, unofficial].
**Optimization**: Memory costs are reduced by lowering field resolution to 1:4 scale (one distance value per 64 voxels), combined with occupancy masks. Masks are queried whenever sampled distance values are zero [S2, unofficial].
**Performance**: Pre-processing takes 10x more GPU time than XBrickMap. Traversal is not considerably shorter than space partitioning methods (~8% difference) [S2, unofficial].

### OctantDF
**Definition**: Space skipping traversal using tiled 256³ 8-directional distance fields at 1:4 resolution, combined with 4³ occupancy bitmasks [S2, unofficial]. A distance field implementation that creates 8 separate manhattan fields, each considering only voxels ahead of the associated ray octant direction. Distances are only propagated across rows of opposing axis directions with respect to the octant [S2, unofficial].
**Layout**: Memory cost is 8 bytes per 4³ voxel plus 1 bit per 1³ voxel [S2, unofficial].
**Performance**: Compared to traditional distance fields, it lowers the overall number of iterations by ~20-25% and increases throughput for incoherent rays by ~30-50% [S2, unofficial]. On Sponza 2k, OctantDF achieves 129.0 Mrays/s for primary rays and 84.9 Mrays/s for primary + 1 diffuse bounce [S2, unofficial].

### Distance to Value Function
**Definition**: A ray function that computes the distance along the ray until a specific scalar value $\sigma$ is encountered. Useful to emphasize depth where specific tissue is located [S3, unofficial].

### Probabilistic Directed Distance Fields (PDDFs)
**Definition**: A variant of DDFs that differentiably models the inherent discontinuities in the underlying field [S4]. PDDFs are constructed to handle the discontinuities that make standard DDFs difficult to train with differentiable neural networks [S4].

### Signed Height Indicator
**Definition**: A 2.5D indicator $\tilde{h} = [u, v, \bar{d}]$ combining UV coordinates and signed distance to resolve ambiguity for points perpendicular to the mesh surface [S5, unofficial].
**Calculation**: Calculate signed distance $\bar{d}$: project point $x$ onto mesh surface at $x_0$, obtain direction $\tilde{r} = x - x_0$, get surface normal $\tilde{n}$ at $x_0$, and compute $\bar{d} = \text{sign}(\tilde{r} \cdot \tilde{n}) \|\tilde{r}\|_2$ [S5, unofficial].
**Formula**: Define signed height: $\tilde{h} = [u, v, \bar{d}]$, where $[u, v]$ is the 2D coordinate on the UV map and $\bar{d}$ is the signed distance [S5, unofficial].

## Background
Distance fields have been widely researched for rendering implicit surfaces and collision detection. Early implementations relied on analytical primitives, but the need to render complex scanned data (like the Stanford Bunny) led to the development of bounded 3D distance textures [S1, S2, unofficial]. The use of distance fields for haptic rendering of sparse point sets was introduced to handle incomplete geometric data where mesh-based methods fail [S1, unofficial]. In the context of differentiable rendering, Probabilistic Directed Distance Fields (PDDFs) were developed to handle discontinuities in neural field training [S4]. The Signed Height Indicator was introduced in the context of unified volumetric avatars to resolve ambiguity in 3D-to-2.5D mapping [S5, unofficial].
