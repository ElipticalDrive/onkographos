# Bounded 3D Distance Texture Ray Marching

Also called: 3D Texture Distance Function with Boundary Shell, Distance function for a cube sized 3D texture

## Overview
Bounded 3D Distance Texture Ray Marching is a method for evaluating a Signed Distance Function (SDF) using a discrete 3D texture to represent an implicit surface, specifically designed to handle boundary conditions and invalid distance values at texture edges [S1, S2, unofficial]. It solves the problem of sampling artifacts that occur when a ray marches outside the valid interior of a distance texture but remains within the texture's physical volume [S1, unofficial]. Unlike standard texture sampling which may return noisy or invalid data near the edges, this method employs two bounding regions (an inner "red" box and an outer "green" box) to ensure that ray marching stops correctly at the texture boundary or uses valid interior data, preventing the "red box" artifact in ambient occlusion calculations [S1, S2, unofficial]. It builds on [Distance Field Representations and Sampling](8725-distance-field-representations-and-sampling.md).

## How it works
**Inputs and Outputs**
*   **Input:** A query point $\mathbf{x}$ in local texture space (typically normalized to $[-0.5, 0.5]^3$ or similar, centered at origin), a 3D distance texture, and two parameters: `textureBoundary` and `textureShell`.
*   **Output:** A scalar distance value $res$. If the point is within the valid interior region, this is the sampled SDF value from the texture. If the point is outside the valid region (but potentially inside the texture volume), it is the distance to the inner boundary, ensuring the ray marcher does not proceed into invalid data.

**Data Structures**
*   **3D Distance Texture:** A 3D array of floating-point values. In the reference implementation, dimensions are $192 \times 192 \times 192$ [S1, S2, unofficial].
*   **Parameters:**
    *   `textureBoundary`: A 3D vector defining the half-dimensions of the inner valid region. Value: $(0.5, 0.5, 0.5)$ [S2, unofficial].
    *   `textureShell`: A 3D vector defining the thickness of the boundary region surrounding the inner valid region. Value: $(0.05, 0.05, 0.05)$ [S2, unofficial].

**Algorithm Steps**
1.  **Calculate Distance to Inner Boundary:** Compute the distance from the query point $\mathbf{x}$ to the inner valid region box defined by `textureBoundary`. This calculation assumes the point is outside the inner region.
    *   Compute component-wise difference: $\mathbf{d_i} = |\mathbf{x}| - \text{textureBoundary} + \text{textureShell}$ [S2, unofficial].
    *   Compute the Euclidean norm: $res = \|\max(\mathbf{d_i} + \text{textureShell}, 0)\|$ [S2, unofficial]. This value represents the distance to the "red box" (the boundary of the valid region) if the point is outside it.

2.  **Check Interior Status:** Determine if the point $\mathbf{x}$ is inside the inner valid region.
    *   Compute $c = \max(d_{ix}, \max(d_{iy}, d_{iz}))$ [S2, unofficial].
    *   Here, $d_{ix}, d_{iy}, d_{iz}$ are the components of $\mathbf{d_i}$ from Step 1.

3.  **Sample Texture (If Interior):** If $c < 0$, the point is inside the inner valid region.
    *   Adjust coordinates to align with texture coordinate space: $\mathbf{x}_{adj} = \mathbf{x} + \text{textureBoundary}$ [S2, unofficial].
    *   Lookup the distance value from the 3D texture using the adjusted coordinates: $res = \text{lookupTexture}(\text{texture}, \mathbf{x}_{adj})$ [S2, unofficial].

4.  **Return Result:** Return $res$. If the point was outside the inner region, $res$ holds the distance to the boundary calculated in Step 1. If inside, it holds the texture sample [S1, S2, unofficial].

**Pseudocode**
```python
def bounded_3d_distance_texture_ray_marching(x, texture, texture_boundary, texture_shell):
    """
    Evaluates the SDF for a bounded 3D distance texture.
    
    Args:
        x: Query point in local space (vector).
        texture: 3D distance texture array.
        texture_boundary: Half-dimensions of the inner valid region (vector).
        texture_shell: Thickness of the boundary shell (vector).
        
    Returns:
        Distance value.
    """
    # Step 1: Calculate distance to the inner boundary (red box)
    # Assumes point is outside the inner region for this calculation
    di = abs(x) - texture_boundary + texture_shell
    
    # Calculate Euclidean norm of the clamped distance vector
    # max(di + texture_shell, 0) ensures we only consider positive distances
    # Note: The source formula uses k...k for norm.
    res = sqrt(max(di.x + texture_shell.x, 0)**2 + 
               max(di.y + texture_shell.y, 0)**2 + 
               max(di.z + texture_shell.z, 0)**2)
    
    # Step 2: Check if point is inside the inner valid region
    c = max(di.x, max(di.y, di.z))
    
    # Step 3: If inside, sample the texture
    if c < 0:
        # Adjust coordinates to align with texture coordinate space
        x_adj = x + texture_boundary
        
        # Lookup distance value from texture
        # lookupTexture performs trilinear interpolation or nearest neighbor
        # depending on texture configuration.
        res = lookup_texture(texture, x_adj)
        
    # Step 4: Return result
    return res
```

**Parameters and Typical Values**
*   `textureBoundary`: $(0.5, 0.5, 0.5)$ [S2, unofficial].
*   `textureShell`: $(0.05, 0.05, 0.05)$ [S2, unofficial]. This value is often deduced by trial and error and should be as small as possible to maximize the valid lookup region while preventing sampling of invalid boundary data [S1, S2, unofficial].
*   Texture Dimensions: $192 \times 192 \times 192$ with an inner valid region of $128 \times 128 \times 128$ in the reference example [S1, S2, unofficial].

**Edge Cases and Pitfalls**
*   **Invalid Boundary Data:** Texture samples outside the "green box" (inner valid region) but inside the "blue box" (total texture volume) may contain invalid distance values. The algorithm remedies this by disregarding that region for texture lookups and returning the distance to the red box instead [S1, S2, unofficial].
*   **Scale Mismatch:** The distance returned by the texture lookup must be in accordance with the scale of the scene. If not, an appropriate bound must be applied [S1, unofficial].
*   **Normal Estimation Epsilon:** When estimating normals via finite differences, the epsilon value must be adjusted to account for the voxel spacing in the texture. If the value is too small, the representation may exhibit a "grainy" look [S1, S2, unofficial].
*   **Mesh Holes:** For accurate distance field generation from meshes (e.g., Stanford Bunny), holes in the mesh must be closed before conversion to a 3D texture, otherwise the distance field will be incorrect [S2, unofficial].

## Subtopics

### [Ambient Occlusion Specific Distance Function](4320-ambient-occlusion-specific-distance-function.md)
A variant designed to mitigate ambient occlusion artifacts by returning a constant step size $\Delta t$ for points outside the texture volume, preventing the bounding shell from contributing to occlusion.

### [Standard 3D Distance Texture Sampling](8725-distance-field-representations-and-sampling.md)
The parent method which does not explicitly handle the boundary shell logic, potentially leading to artifacts when marching near texture edges.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query. The algorithm involves a constant number of vector operations and a single texture lookup.
*   **Memory Complexity:** Depends on the 3D texture size. For a $192^3$ texture, this is significant compared to analytic SDFs.
*   **Strengths:** Robust handling of discrete texture boundaries; prevents ray marchers from entering invalid data regions; allows for complex implicit surface representations stored in textures.
*   **Limitations:** Requires pre-computation of the distance texture; memory intensive for high-resolution textures; boundary artifacts (like the "red box") can still appear in shading (e.g., AO) if not handled by specific variants like the AO-specific function.
*   **When to Use:** When the implicit surface is complex and best represented by a pre-computed distance field (e.g., from a mesh), and boundary artifacts need to be controlled during ray marching.
*   **When Not to Use:** For simple analytic shapes where analytic SDFs are faster and more precise; when memory is severely constrained.

## Background
This method originates from research on GPU ray marching for ambient occlusion and distance fields, specifically detailed in works by researchers at DTU (Technical University of Denmark) [S1, S2, unofficial]. It was used to render the Stanford Bunny as a 3D distance texture, demonstrating the inclusion of such representations into scenes using union operators [S1, S2, unofficial]. The technique addresses limitations in early 3D texture distance field implementations where boundary conditions were not explicitly managed, leading to visual artifacts.
