# Scale-Invariant Integral Surface Rendering

Also called: SCALIS rendering, method using homothetic distance and quadratic polynomial interpolation

## Overview
Scale-Invariant Integral Surface Rendering (SCALIS) is a rendering algorithm for scale-invariant integral surfaces that reduces computation time by up to 70% compared to revised previous work [S1]. It addresses the excessive step counts of sphere-tracing along grazing rays by employing an initial sampling strategy based on homothetic distance to segment primitives, combined with a field mapping using quadratic polynomial interpolation [S1]. Unlike sphere-tracing, which suffers from a well-known problem of maximal number of steps along grazing rays, SCALIS provides a reduction in the maximal number of steps required [S1].

## How it works
**Inputs:**
- Skeletons (random or procedural) and associated kernel parameters [S1].
- Isosurface threshold (typically 0) [S1].

**Outputs:**
- Rendered image accumulated in an A-buffer [S1].
- Per-ray statistics (average, median, and maximal number of steps) [S1].

**Data Structures:**
- **Skeleton Support:** Each primitive is defined by a sphere-cone support [S1]. An axis-aligned bounding box (AABB) is computed for the entire model based on these supports [S1].
- **Heap:** Stores segment primitives during the ray processing loop [S1]. It must be large enough to accommodate all primitives whose supports overlap the initial intervals defined by the argument of the minimum of homothetic distance [S1].
- **A-buffer:** Used for efficient GPU implementation and accumulation [S1].

**Field Evaluation:**
The method computes both the field value and its gradient simultaneously to evaluate the directional derivative [S1]. This costs less than twice the evaluation cost of a single field value [S1]. Because both values are computed at once, segment parameters are fetched from memory only once [S1].

**Algorithm Steps:**
1. Generate skeletons (random or procedural) on the CPU at each parameter change [S1].
2. Compute the AABB for the model from the sphere-cone supports of the primitives [S1].
3. Launch sets of rays in six directions (three main axes with positive and negative orientations) to compute per-ray statistics [S1]. Sample ray origins uniformly in the associated bounding box's face such that a total of 10 million rays are launched per model [S1].
4. For each ray, determine initial intervals using the argument of the minimum of the homothetic distance to segment primitives [S1].
5. Initialize a heap with primitives whose supports overlap these initial intervals [S1].
6. Evaluate the field and gradient values at the current ray position [S1].
7. March along the ray using a quadratic polynomial interpolation heuristic for field mapping [S1].
8. Check for isosurface crossing (field value equals 0) [S1].
9. Accumulate results in the A-buffer [S1].

**Edge Cases and Pitfalls:**
- **Grazing Rays:** Less than $10^{-3}\%$ of rays miss an isosurface crossing [S1]. These are all grazing rays caused by Hermite data configurations where control polygons of the interpolant do not cross the isovalue 0 [S1]. This limits the efficiency of the rational interpolation heuristic [S1].
- **Heap Size:** The heap must be large enough to accommodate all primitives whose supports overlap the initial intervals defined by the argument of the minimum of homothetic distance [S1].
- **Finely Tessellated Curves:** Finely tessellated skeletons increase the number of arguments of the minimum of homothetic distance along the ray, which can impact performance [S1].

## Operating characteristics
- **Time Complexity:** Reduces computation time by up to 70% compared to revised previous work [S1]. Specifically reduces the maximal number of steps required along grazing rays, addressing a well-known sphere-tracing limitation [S1].
- **Memory Complexity:** Requires a heap large enough to store all primitives overlapping the initial intervals defined by the homothetic distance minimum [S1]. The A-buffer can become expensive to build for finely tessellated curves due to overlaps between primitive supports [S1].
- **Performance:** Enables interactive manipulation of a large range of skeletons and real-time exploration of kernel parameters [S1].
- **Strengths:** Significant reduction in maximal steps for grazing rays; interactive performance; no visible artifacts [S1].
- **Limitations:** Potential for missed crossings in grazing rays due to Hermite data configurations; heap size constraints; A-buffer cost for fine tessellation [S1].

## Background
Scale-Invariant Integral Surface Rendering was introduced in "Fast Ray Tracing of Scale‐Invariant Integral Surfaces" [S1]. The method is designed for interactive modeling and real-time exploration of integral surfaces defined by skeletons and kernel parameters [S1]. It builds on previous work in sphere-tracing and segment-tracing algorithms, aiming to alleviate the limitations of maximal steps along grazing rays [S1]. Future work includes investigating 2D quadric Bezier curves to mitigate the shortcoming of missed crossings in grazing rays [S1].
