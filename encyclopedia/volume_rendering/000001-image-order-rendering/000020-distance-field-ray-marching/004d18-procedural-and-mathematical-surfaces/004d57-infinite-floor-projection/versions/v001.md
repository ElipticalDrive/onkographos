# Infinite Floor Projection

Also called: testFloor

## Overview
Infinite Floor Projection is a technique for rendering an infinite, textured planar surface (typically a floor) by projecting screen coordinates into world space using perspective division, then applying player rotation and a checkerboard pattern [S1, unofficial]. It differs from standard texture mapping by calculating world-space coordinates directly per pixel using perspective division, allowing for seamless infinite tiling without UV wrapping artifacts. It builds on [Procedural and Mathematical Surfaces](13400-procedural-and-mathematical-surfaces.md) by explicitly deriving the world coordinate increments from the view frustum geometry rather than relying on pre-projected screen coordinates.

## How it works
**Inputs:**
*   Screen dimensions: `SCR_WIDTH`, `SCR_HEIGHT`.
*   Player state: `player.lookAngle` (rotation in radians), `player.x`, `player.y`, `player.z` (position).
*   Constants: `moveVertical` scaling factor (16.0), look angle multiplier (6.2, approximating $2\pi$).

**Outputs:**
*   Pixel colors (e.g., red or blue for a checkerboard pattern).

**Data Structures:**
*   No complex data structures; state is held in scalar variables and simple loops.

**Steps:**
1.  **Calculate Look Angle Offset:** Compute `lookAngle` as `-player.lookAngle * 6.2`. Clamp this value to the range `[0, SCR_HEIGHT]` [S1, unofficial].
2.  **Calculate Vertical Scale:** Compute `moveVertical` as `player.z / 16.0`. If `moveVertical` is zero, clamp it to `0.0001` to prevent division by zero [S1, unofficial].
3.  **Iterate Screen Rows:** Loop `y` from `yStart` to `yEnd` (typically the visible screen height) [S1, unofficial].
4.  **Iterate Screen Columns:** Loop `x` from `-SCR_WIDTH_HALF` to `SCR_WIDTH_HALF` [S1, unofficial].
5.  **Compute Depth Proxy:** Calculate `z = y + lookAngle`. Clamp `z` to `0.0001` if it is less than or equal to zero to prevent division by zero [S1, unofficial].
6.  **Project to World Space:** Calculate intermediate world coordinates `fx` and `fy`:
    $$ fx = \frac{x}{z} \times moveVertical $$
    $$ fy = \frac{200}{z} \times moveVertical $$
    [S1, unofficial].
7.  **Apply Player Rotation:** Rotate the world coordinates by the player's look angle:
    $$ rx = fx \times \sin(\text{angle}) - fy \times \cos(\text{angle}) + \frac{\text{player.y}}{60.0} $$
    $$ ry = fx \times \cos(\text{angle}) + fy \times \sin(\text{angle}) - \frac{\text{player.x}}{60.0} $$
    [S1, unofficial].
8.  **Mirror Coordinates:** To handle negative coordinates for tiling, mirror them:
    *   If `rx < 0`, set `rx = -rx + 1`.
    *   If `ry < 0`, set `ry = -ry + 1`.
    [S1, unofficial].
9.  **Cull Invalid Tiles:** If `rx <= 0` or `ry <= 0` or `rx >= 5` or `ry >= 5`, skip drawing (or draw background) [S1, unofficial].
10. **Determine Pattern:** Draw red if `rx % 2 == ry % 2`, else draw blue [S1, unofficial].

**Pseudocode:**
```python
def render_infinite_floor(player, scr_width, scr_height):
    # Constants
    LOOK_ANGLE_MULTIPLIER = 6.2
    MOVE_VERTICAL_SCALE = 16.0
    MIN_Z = 0.0001
    MIN_MOVE_VERTICAL = 0.0001
    FLOOR_OFFSET_X = 60.0
    FLOOR_OFFSET_Y = 60.0
    TILE_LIMIT = 5

    # 1. Calculate Look Angle Offset
    look_angle = -player.lookAngle * LOOK_ANGLE_MULTIPLIER
    look_angle = clamp(look_angle, 0, scr_height)

    # 2. Calculate Vertical Scale
    move_vertical = player.z / MOVE_VERTICAL_SCALE
    if move_vertical == 0:
        move_vertical = MIN_MOVE_VERTICAL

    # 3 & 4. Iterate Screen Pixels
    for y in range(y_start, y_end):
        for x in range(-scr_width // 2, scr_width // 2):
            # 5. Compute Depth Proxy
            z = y + look_angle
            if z <= 0:
                z = MIN_Z

            # 6. Project to World Space
            fx = (x / z) * move_vertical
            fy = (200 / z) * move_vertical

            # 7. Apply Player Rotation
            rx = fx * sin(player.lookAngle) - fy * cos(player.lookAngle) + (player.y / FLOOR_OFFSET_Y)
            ry = fx * cos(player.lookAngle) + fy * sin(player.lookAngle) - (player.x / FLOOR_OFFSET_X)

            # 8. Mirror Coordinates
            if rx < 0:
                rx = -rx + 1
            if ry < 0:
                ry = -ry + 1

            # 9. Cull Invalid Tiles
            if rx <= 0 or ry <= 0 or rx >= TILE_LIMIT or ry >= TILE_LIMIT:
                continue

            # 10. Determine Pattern
            if (rx % 2) == (ry % 2):
                draw_pixel(x + scr_width // 2, y, color=RED)
            else:
                draw_pixel(x + scr_width // 2, y, color=BLUE)
```

**Parameters:**
*   `moveVertical` scaling factor: 16.0 [S1, unofficial].
*   Look angle multiplier: 6.2 (approximates $2\pi$) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Division by Zero:** `z` and `moveVertical` are clamped to small positive values (`0.0001`) to prevent division by zero errors [S1, unofficial].
*   **Coordinate Wrapping:** The mirroring step (`rx = -rx + 1`) handles negative world coordinates to create a seamless tiling effect without explicit modulo operations on negative numbers [S1, unofficial].
*   **Tiling Limit:** The culling step (`rx >= 5`, `ry >= 5`) limits the visible tiles, likely for performance or to define a finite visible area in this specific implementation [S1, unofficial].

## Subtopics

### [Floor Rendering via Ray Casting](17901-floor-rendering-via-ray-casting.md)
Floor Rendering via Ray Casting is a technique for rendering an infinite textured floor by casting rays from the camera plane through screen pixels to the world grid, interpolating world coordinates $(x, y)$ based on the distance from the camera to the screen row. It differs from standard texture mapping by calculating world-space coordinates directly per pixel using perspective division, allowing for seamless infinite tiling without UV wrapping artifacts. It builds on [Infinite Floor Projection](13461-infinite-floor-projection.md) by explicitly deriving the world coordinate increments from the view frustum geometry rather than relying on pre-projected screen coordinates.

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of pixels rendered, as each pixel is processed in a nested loop.
*   **Memory Complexity:** $O(1)$, as no large data structures are required.
*   **Strengths:** Simple to implement; no UV mapping or texture coordinates needed; seamless infinite tiling.
*   **Limitations:** The specific implementation uses a fixed tile limit (5x5), which may not represent a truly infinite floor in all contexts; the perspective projection is approximated using screen coordinates and depth proxies rather than full 3D ray casting.
*   **When to Use:** Simple 2D/3D hybrid rendering where performance is critical and complex geometry is not required.
*   **When Not to Use:** When accurate perspective projection or complex floor interactions (e.g., slopes, holes) are needed.

## Background
The technique originates from the Voxel1993 project, a voxel engine implementation [S1, unofficial]. It is used in simple voxel-based rendering engines to provide a textured ground plane without the overhead of full 3D geometry or texture mapping.
