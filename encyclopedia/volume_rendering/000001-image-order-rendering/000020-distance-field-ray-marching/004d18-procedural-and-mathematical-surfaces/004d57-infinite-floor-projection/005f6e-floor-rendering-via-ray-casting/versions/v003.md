# Floor Rendering via Ray Casting

Also called: DDA Floor Casting, Raycast Floor Projection

## Overview
Floor Rendering via Ray Casting is a technique for rendering an infinite textured floor by casting rays from the camera plane through screen pixels to the world grid, interpolating world coordinates $(x, y)$ based on the distance from the camera to the screen row [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Screen dimensions ($SCREEN\_WIDTH$, $SCREEN\_HEIGHT$), horizon line ($HORIZON$), player position in world/grid space ($playerX$, $playerY$), player orientation vector ($dirX$, $dirY$), and camera plane vector ($planeX$, $planeY$) [S1, unofficial].
*   **Outputs:** A pixel buffer where each pixel $(x, y)$ below the horizon is colored based on the floor grid cell $(cellX, cellY)$ intersected by the ray [S1, unofficial].

**Data Structures:**
*   `normalizedLeft`: A 2D vector $(normalizedLeftX, normalizedLeftY)$ representing the normalized direction to the left edge of the view frustum at the near plane [S1, unofficial].
*   `normalizedRight`: A 2D vector $(normalizedRightX, normalizedRightY)$ representing the normalized direction to the right edge of the view frustum at the near plane [S1, unofficial].
*   `floorXStart`, `floorYStart`: Floating-point accumulators for the current world grid coordinates at the left edge of the current screen row [S1, unofficial].
*   `floorXDirInc`, `floorYDirInc`: Floating-point increments for advancing the world grid coordinates across one screen pixel horizontally [S1, unofficial].

**Steps:**

1.  **Calculate Frustum Edge Vectors:**
    Compute the unnormalized direction vectors for the left and right edges of the view frustum at the near plane [S1, unofficial].
    $$
    \begin{aligned}
    nearPlaneX1 &= dirX - planeX \\
    nearPlaneY1 &= dirY - planeY \\
    nearPlaneX2 &= dirX + planeX \\
    nearPlaneY2 &= dirY + planeY
    \end{aligned}
    $$
    Normalize these vectors to unit length [S1, unofficial]:
    $$
    \begin{aligned}
    normalizedLeftX &= \frac{nearPlaneX1}{\sqrt{nearPlaneX1^2 + nearPlaneY1^2}} \\
    normalizedLeftY &= \frac{nearPlaneY1}{\sqrt{nearPlaneX1^2 + nearPlaneY1^2}} \\
    normalizedRightX &= \frac{nearPlaneX2}{\sqrt{nearPlaneX2^2 + nearPlaneY2^2}} \\
    normalizedRightY &= \frac{nearPlaneY2}{\sqrt{nearPlaneX2^2 + nearPlaneY2^2}}
    \end{aligned}
    $$

2.  **Iterate Screen Rows:**
    Loop through screen rows $y$ from the bottom of the screen ($SCREEN\_HEIGHT$) down to the horizon ($HORIZON$) [S1, unofficial]. The floor is rendered for $y > HORIZON$.

3.  **Calculate Distance and Increments:**
    For each row $y$, calculate the perspective distance factor $yDistance$ and the horizontal world coordinate increments per pixel [S1, unofficial]:
    $$
    yDistance = \frac{HORIZON}{y - HORIZON}
    $$
    $$
    \begin{aligned}
    floorXDirInc &= yDistance \times \frac{normalizedRightX - normalizedLeftX}{SCREEN\_WIDTH} \\
    floorYDirInc &= yDistance \times \frac{normalizedRightY - normalizedLeftY}{SCREEN\_WIDTH}
    \end{aligned}
    $$
    The value $yDistance$ represents the distance from the camera to the floor plane at row $y$ [S1, unofficial]. In the source implementation, $HORIZON$ is equated to $PLAYER\_HEIGHT$ (camera height) [S1, unofficial].

4.  **Initialize Row Start Coordinates:**
    Calculate the starting world grid coordinates for the left edge of the current row [S1, unofficial]. This is the player's grid position plus the offset to the left edge of the view frustum scaled by the distance [S1, unofficial]:
    $$
    \begin{aligned}
    floorXStart &= worldToGrid(playerX) + yDistance \times normalizedLeftX \\
    floorYStart &= worldToGrid(playerY) + yDistance \times normalizedLeftY
    \end{aligned}
    $$

5.  **Iterate Screen Columns:**
    For each column $x$ from $0$ to $SCREEN\_WIDTH - 1$:
    a. Determine the grid cell indices [S1, unofficial]:
    $$
    \begin{aligned}
    cellX &= \lfloor |floorXStart| \rfloor \\
    cellY &= \lfloor |floorYStart| \rfloor
    \end{aligned}
    $$
    b. Update the start coordinates for the next pixel in the row [S1, unofficial]:
    $$
    \begin{aligned}
    floorXStart &+= floorXDirInc \\
    floorYStart &+= floorYDirInc
    \end{aligned}
    $$
    c. Render the pixel using $cellX$ and $cellY$ [S1, unofficial]. For example, a checkerboard pattern can be applied:
    $$
    \text{if } ((cellX + cellY) \pmod 2) \neq 0 \text{ then color} = (0, 0, 255, 255) \text{ else color} = (255, 255, 255, 255)
    $$

**Pseudocode:**

```python
import math

def render_floor(SCREEN_WIDTH, SCREEN_HEIGHT, HORIZON, playerX, playerY, 
                 dirX, dirY, planeX, planeY, worldToGrid):
    # 1. Calculate normalized frustum edge vectors
    nearPlaneX1 = dirX - planeX
    nearPlaneY1 = dirY - planeY
    nearPlaneX2 = dirX + planeX
    nearPlaneY2 = dirY + planeY
    
    lenLeft = math.sqrt(nearPlaneX1**2 + nearPlaneY1**2)
    lenRight = math.sqrt(nearPlaneX2**2 + nearPlaneY2**2)
    
    normalizedLeftX = nearPlaneX1 / lenLeft
    normalizedLeftY = nearPlaneY1 / lenLeft
    normalizedRightX = nearPlaneX2 / lenRight
    normalizedRightY = nearPlaneY2 / lenRight

    # Pre-calculate constant differences for increments
    diffX = normalizedRightX - normalizedLeftX
    diffY = normalizedRightY - normalizedLeftY
    
    # Player grid position
    gridPlayerX = worldToGrid(playerX)
    gridPlayerY = worldToGrid(playerY)

    # 2. Iterate screen rows from bottom to horizon
    for y in range(SCREEN_HEIGHT, HORIZON, -1):
        # 3. Calculate distance factor
        yDistance = HORIZON / (y - HORIZON)
        
        # Calculate increments per pixel
        floorXDirInc = yDistance * diffX / SCREEN_WIDTH
        floorYDirInc = yDistance * diffY / SCREEN_WIDTH
        
        # 4. Initialize start coordinates for this row
        floorXStart = gridPlayerX + yDistance * normalizedLeftX
        floorYStart = gridPlayerY + yDistance * normalizedLeftY
        
        # 5. Iterate screen columns
        for x in range(SCREEN_WIDTH):
            # Determine grid cell
            cellX = math.floor(abs(floorXStart))
            cellY = math.floor(abs(floorYStart))
            
            # Update for next pixel
            floorXStart += floorXDirInc
            floorYStart += floorYDirInc
            
            # Render pixel (Example: Checkerboard)
            if (cellX + cellY) % 2 != 0:
                color = (0, 0, 255, 255) # Blue
            else:
                color = (255, 255, 255, 255) # White
            
            # Write to buffer at index (y * SCREEN_WIDTH + x)
            # buffer[(y * SCREEN_WIDTH + x) * 4 : (y * SCREEN_WIDTH + x) * 4 + 4] = color

# worldToGrid is a helper to convert world coordinates to grid indices [G]
```

**Parameters:**
*   $PLAYER\_HEIGHT$: The vertical position of the camera. In the source implementation, this is equated to $HORIZON$ [S1, unofficial].
*   $HORIZON$: The y-coordinate on the screen corresponding to the camera height (vanishing line). Floor rendering occurs for screen $y$ values from $SCREEN\_HEIGHT$ down to $HORIZON + 1$ [S1, unofficial].
*   $SCREEN\_HEIGHT$: The total height of the canvas in pixels. The bottom pixel is at $y = SCREEN\_HEIGHT$ [S1, unofficial].
*   $SCREEN\_WIDTH$: The total width of the canvas in pixels. Used to calculate ray increment and floor step increments [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Wall/Floor Sync:** The floor rendering may appear 'out of sync' with wall rendering, where floor tiles appear to slide or change color near walls as the player moves [S1, unofficial]. This is attributed to a discrepancy between the distance used for wall height calculation (from DDA) and the distance used for floor interpolation ($yDistance$), although the author notes they are 'two different types of distances' [S1, unofficial].
*   **Horizon Division:** The formula for $yDistance$ involves division by $(y - HORIZON)$, requiring $y > HORIZON$ to avoid division by zero [S1, unofficial].

## Background
This technique is described in the context of implementing a raycaster with both wall and floor rendering [S1, unofficial]. It is presented as a method to solve the problem of rendering an infinite floor in a raycasting engine, where the floor coordinates are interpolated based on the distance from the camera [S1, unofficial]. The source notes that the basic idea uses $PLAYER\_HEIGHT$ (position of camera) and the formula $PLAYER\_HEIGHT / (y - HORIZON)$ to interpolate floor coordinates [S1, unofficial].
