# Tetrahedral Normal Estimation

Also called: 4-point normal, Quilez Normal Estimation, Tetrahedral Gradient Estimation, Tetrahedral SDF Normal Approximation, Tetrahedral gradient, Tetrahedron Gradient Normal Estimation, Tetrahedron Offset Normal Estimation

## Overview
Tetrahedral Normal Estimation approximates the surface normal of a Signed Distance Field (SDF) at a query point using only four distance function evaluations, reducing computational cost by 33% compared to the standard six-call central difference method [S1, unofficial]. It leverages the geometric symmetry of a regular tetrahedron inscribed in the unit cube to sum directional derivatives, achieving accuracy comparable to central differences with fewer samples [S2, unofficial][S3].

## How it works
**Inputs:**
- Point $p \in \mathbb{R}^3$ where the normal is estimated [S3].
- SDF function $map: \mathbb{R}^3 \to \mathbb{R}$ [S3].
- Step size $h$ (scalar) [S3].

**Outputs:**
- Normal vector $n \in \mathbb{R}^3$ [S3].

**Data Structures:**
- Offset vector $e$ constructed from two scalar components to generate four 3D offset directions via component permutation [S1, unofficial]. The source defines the base as `vec2(1.0, -1.0) * 0.0006`, which expands to 3D offsets using swizzle patterns [S1, unofficial].

**Steps:**
1. Define the base offset components $x = h$ and $y = -h$ [S1, unofficial].
2. Generate the four offset vectors by permuting components: $e^{(0)} = (x, y, y)$, $e^{(1)} = (y, y, x)$, $e^{(2)} = (y, x, y)$, $e^{(3)} = (x, x, x)$ [S1, unofficial].
3. Evaluate the SDF at the four offset points: $d_i = map(p + e^{(i)})$ for $i \in \{0, 1, 2, 3\}$ [S1, unofficial].
4. Compute the gradient approximation by multiplying each distance by its corresponding offset vector and summing: $g = \sum_{i=0}^{3} e^{(i)} \cdot d_i$ [S1, unofficial].
5. Normalize the gradient to obtain the surface normal: $n = normalize(g)$ [S1, unofficial].

**Formula:**
The general mathematical form is [S3]:
$$ normal(p) \approx normalize\left(\sum_{i=0}^{3} k_i \cdot map(p + h k_i)\right) $$
where $k_i$ are the four directional vectors of the tetrahedron vertices, $h$ is the step size, and $map$ is the distance field function [S3].

A concrete implementation from [S1, unofficial] substitutes the unit directions $k_i$ with the scaled offset vectors $e^{(i)}$ directly:
$$ n = normalize\left( e^{(0)} \cdot map(p + e^{(0)}) + e^{(1)} \cdot map(p + e^{(1)}) + e^{(2)} \cdot map(p + e^{(2)}) + e^{(3)} \cdot map(p + e^{(3)}) \right) $$
where $e^{(i)}$ are the permutations $(x, y, y)$, $(y, y, x)$, $(y, x, y)$, and $(x, x, x)$ derived from the base step [S1, unofficial].

**Parameters:**
- Step size $h$: The source implementation uses $h = 0.0006$ [S1, unofficial]. The optimal value depends on the scale of the SDF and the precision of the floating-point representation. Not given in the sources.

**Edge Cases and Pitfalls:**
- **Sharp Intersections:** The normal value is inaccurate at sharp intersections of multiple surfaces because the blended SDF distances cause the gradient sum to fail at discontinuities [S3].
- **Mitigation:** Evaluate only the SDF of the closest object by altering the map function to accept a material ID mask, ensuring only the nearest surface contributes to the distance field [S3].

**Pseudocode:**
```python
def tetrahedral_normal(p, map_func, h=0.0006):
    # Define base offset components from the source implementation
    x = h
    y = -h
    
    # Generate the four offset vectors via component permutation
    e0 = (x, y, y)
    e1 = (y, y, x)
    e2 = (y, x, y)
    e3 = (x, x, x)
    
    # Evaluate SDF at the four offset points
    d0 = map_func(p + e0)
    d1 = map_func(p + e1)
    d2 = map_func(p + e2)
    d3 = map_func(p + e3)
    
    # Compute weighted sum: multiply each distance by its corresponding offset vector
    grad_x = e0[0]*d0 + e1[0]*d1 + e2[0]*d2 + e3[0]*d3
    grad_y = e0[1]*d0 + e1[1]*d1 + e2[1]*d2 + e3[1]*d3
    grad_z = e0[2]*d0 + e1[2]*d1 + e2[2]*d2 + e3[2]*d3
    
    # Normalize to obtain the surface normal [G]
    length = (grad_x**2 + grad_y**2 + grad_z**2)**0.5
    if length == 0.0:
        return (0.0, 0.0, 1.0)
    return (grad_x/length, grad_y/length, grad_z/length)
```

## Operating characteristics
- **Time Complexity:** Requires exactly 4 SDF evaluations per query point, which is 33% faster than the 6-evaluation central difference method [S1, unofficial].
- **Memory Complexity:** Minimal, requiring storage for only 4 distance values and the resulting gradient vector [G].
- **Accuracy:** Provides accuracy comparable to central differences for smooth surfaces [S3]. Accuracy degrades at sharp intersections of multiple SDFs unless material masking is applied [S3].
- **Strengths:** Reduced computational cost and high efficiency for real-time ray marching on smooth geometry [S3].
- **Limitations:** Inaccurate at sharp intersections of multiple surfaces without additional masking logic [S3].
- **When to use:** Real-time ray marching where performance is critical and surfaces are smooth [S3].
- **When not to use:** Scenes with sharp intersections of multiple SDFs without masking, or where high precision is required at discontinuities [S3].

## Background
The method is attributed to Inigo Quilez, a graphics programmer known for real-time ray marching shader tutorials [S2, unofficial]. It is widely adopted in real-time rendering pipelines for its efficiency [S3]. Academic literature describes the technique as a method to obtain surface normals with the same accuracy as central differences using only four evaluations [S3].
