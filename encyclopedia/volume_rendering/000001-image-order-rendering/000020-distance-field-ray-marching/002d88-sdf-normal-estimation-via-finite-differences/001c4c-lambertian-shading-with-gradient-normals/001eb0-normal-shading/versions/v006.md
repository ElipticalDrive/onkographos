# Normal Shading

Also called: Absolute Normal Visualization, Clamped Normal Visualization, Normal Visualization

## Overview
Normal Shading visualizes the surface normals of a geometry by mapping the absolute values of the normal vector components to the RGB color channels. It solves the problem of verifying normal orientation and smoothness in a view-independent manner, distinct from parent [Lambertian Shading with Gradient Normals](1229-lambertian-shading-with-gradient-normals.md) which computes lighting. It sets itself apart from siblings like [Normal Integrator](4451-normal-integrator.md) by discarding sign information (via absolute value), making it suitable for debugging symmetry or magnitude rather than directional orientation.

## How it works
**Inputs and Outputs:**
- Input: Surface normal vector $\mathbf{n} = (n_x, n_y, n_z)$ at a point on the surface.
- Output: RGB color value $C \in [0, 1]^3$.

**Data Structures:**
- The normal vector $\mathbf{n}$ is a 3-component floating-point vector, typically normalized such that $|\mathbf{n}| = 1$.

**Steps:**
1. Compute the absolute value of each component of the normal vector $\mathbf{n}$.
2. Clamp the resulting components to the range $[0, 1]$.
3. Assign the clamped $x, y, z$ components to the Red, Green, and Blue channels respectively.

**Formula:**
The visualization color $N_{vis}$ is defined as:
$$ N_{vis} = \max(0, \min(1, |\mathbf{n}|)) $$
where $|\mathbf{n}|$ denotes the component-wise absolute value operation. Specifically, if $\mathbf{n} = (n_x, n_y, n_z)$, then:
$$ N_{vis} = (|n_x|, |n_y|, |n_z|) $$
Since $\mathbf{n}$ is a unit vector, each component lies in $[-1, 1]$, so the absolute value lies in $[0, 1]$, making the explicit clamp redundant but conceptually part of the mapping [S2, unofficial].

**Pseudocode:**
```python
def normal_shading(surface_normals: Vector3) -> Color3:
    """
    Visualizes surface normals using absolute component mapping.
    
    Args:
        surface_normals: A vector (nx, ny, nz) representing the surface normal.
        
    Returns:
        A color vector (r, g, b) with components in [0, 1].
    """
    # Take absolute value of each component
    abs_normal = Vector3(
        abs(surface_normals.x),
        abs(surface_normals.y),
        abs(surface_normals.z)
    )
    
    # Clamp to [0, 1] (redundant if normal is normalized, but required by spec)
    r = max(0.0, min(1.0, abs_normal.x))
    g = max(0.0, min(1.0, abs_normal.y))
    b = max(0.0, min(1.0, abs_normal.z))
    
    return Color3(r, g, b)
```

**Edge Cases and Pitfalls:**
- **Degenerate Normals:** If the normal vector is zero (e.g., at singularities or uninitialized memory), the output is black $(0,0,0)$.
- **Precision:** Floating-point errors in normal normalization might result in components slightly outside $[-1, 1]$, necessitating the clamp step [S2, unofficial].

## Subtopics

### [Laplacian Shading](1832-laplacian-shading.md)
Laplacian Shading visualizes the surface Laplacian of a Signed Distance Field (SDF) to highlight regions of high curvature or rapid change in the distance function. It sets itself apart from Normal Shading by visualizing the second-order derivative (divergence of the gradient) rather than first-order gradient components, providing insight into the local geometry's concavity and convexity. See [Laplacian Shading](1832-laplacian-shading.md).

### [Spin Shader](1959-spin-shader.md)
The Spin Shader visualizes surface geometry by mapping surface normals and camera orientation to a cyclic color field, mimicking spin-1/2 behavior where a 360-degree rotation reverses the texture orientation. It sets itself apart from Normal Shading by encoding rotational phase information rather than absolute normal direction. See [Spin Shader](1959-spin-shader.md).

### [Normal Integrator](4451-normal-integrator.md)
The Normal Integrator is a visualization technique that renders the surface normal vector of a geometry as an RGB color image. It sets itself apart from Normal Shading by preserving sign information through a linear shift-and-scale mapping ($\mathbf{n} \to (\mathbf{n}+1)/2$) rather than taking absolute values. This allows debugging of normal orientation (e.g., distinguishing front-facing from back-facing surfaces). See [Normal Integrator](4451-normal-integrator.md).

### [Normals Shader](7710-normals-shader.md)
The Normals Shader visualizes surface normals by converting vector components from the range $[-1, 1]$ to the displayable range $[0, 1]$. It serves as a debugging and visualization tool within the Normal Shading family, distinct from the Spin Shader's rotational encoding and the Normal Integrator's gradient accumulation. It outputs the normal direction as an emission color, allowing developers to verify normal orientation and smoothness. See [Normals Shader](7710-normals-shader.md).

### Tangent Space Visualization
Tangent Space Visualization projects the surface normal onto the sensor plane to visualize the tangent space components. It sets itself apart from Normal Shading by encoding the relationship between the normal and the camera view direction.
- **Steps:**
  1. Let $e_\alpha$ and $e_\beta$ be an orthonormal basis for the sensor plane, and $v_p$ be the unit vector from pixel $p$ to the focal point.
  2. Project the surface normal $N_p$ onto the sensor plane: $T_p = N_p - (N_p \cdot v_p)v_p$.
  3. Express $T_p$ in the basis $e_\alpha, e_\beta$ as $T_p = \alpha e_\alpha + \beta e_\beta$. The result is a vector $(\alpha, \beta)$ where $\alpha^2 + \beta^2 \leq 1$.
  4. Treat $(\alpha, \beta)$ as a complex number $\alpha + i\beta$ and apply domain coloring techniques to visualize the result [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel, involving only basic arithmetic operations (absolute value, clamp, assignment).
- **Memory Complexity:** $O(1)$ auxiliary memory.
- **Strengths:** Simple to implement; view-independent; effectively highlights symmetry and magnitude of normal components; useful for debugging SDF construction artifacts.
- **Limitations:** Loses sign information, making it impossible to distinguish between opposite-facing normals (e.g., inside vs. outside of a closed surface) without additional context. Not suitable for lighting calculations.
- **When to use:** Debugging normal continuity, verifying SDF smoothness, or artistic effects requiring symmetric color mapping.
- **When not to use:** When orientation matters (use [Normal Integrator](4451-normal-integrator.md) or [Normals Shader](7710-normals-shader.md)) or when lighting is required (use [Lambertian Shading with Gradient Normals](1229-lambertian-shading-with-gradient-normals.md)).

## Background
Normal Shading is a standard debugging and visualization technique in computer graphics, particularly in the context of Signed Distance Field (SDF) rendering and ray marching. It is often used to verify the correctness of normal estimation methods, such as finite differences. The method is closely related to the broader family of normal visualization techniques, including the Normal Integrator and Normals Shader. The specific "absolute" variant is noted in community implementations for its simplicity in visualizing normal magnitude symmetry [S2, unofficial].
