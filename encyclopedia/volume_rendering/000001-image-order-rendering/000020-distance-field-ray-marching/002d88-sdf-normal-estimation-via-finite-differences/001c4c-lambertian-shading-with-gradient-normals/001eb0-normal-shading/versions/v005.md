# Normal Shading

Also called: Absolute Normal Visualization, Clamped Normal Visualization, Normal Visualization

## Overview
Normal Shading is a visualization technique that renders the surface normal vector of a geometry as an RGB color image by taking the absolute value of each normal component and clamping the result to the range $[0, 1]$ [S2, unofficial]. It serves as a debugging and artistic tool to verify normal orientation and smoothness, distinct from the parent [Lambertian Shading with Gradient Normals](1229-lambertian-shading-with-gradient-normals.md) which uses these normals for lighting calculations [S2, unofficial]. Unlike the [Normal Integrator](4451-normal-integrator.md), which preserves sign information via linear shift-and-scale, Normal Shading discards sign information, making it suitable for visualizing the magnitude of normal components without directional bias [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A surface normal vector $\mathbf{n} = (n_x, n_y, n_z)$, typically derived from the gradient of a Signed Distance Field (SDF) [S2, unofficial].
- Output: A color vector $\mathbf{c} = (c_r, c_g, c_b)$ in the range $[0, 1]$.

**Data Structures:**
- The normal vector $\mathbf{n}$ is a 3D unit vector.
- The output color $\mathbf{c}$ is a 3D vector representing Red, Green, and Blue channels.

**Steps:**
1. Compute the absolute value of each component of the surface normal $\mathbf{n}$ [S2, unofficial].
2. Clamp each component to the range $[0, 1]$ [S2, unofficial].
3. Assign the clamped components to the RGB channels: $c_r = \max(0, \min(1, |n_x|))$, $c_g = \max(0, \min(1, |n_y|))$, $c_b = \max(0, \min(1, |n_z|))$ [S2, unofficial].

**Formula:**
The visualization color $\mathbf{N}_{vis}$ is defined as:
$$
\mathbf{N}_{vis} = \max(0, \min(1, |\mathbf{n}|))
$$
where $|\mathbf{n}|$ denotes the component-wise absolute value of the normal vector $\mathbf{n}$ [S2, unofficial].

**Pseudocode:**
```python
def normal_shading(surface_normals: Tensor) -> Tensor:
    """
    Visualizes surface normals by taking the absolute value of each component 
    and clamping to [0, 1].
    
    Args:
        surface_normals: A tensor of shape (..., 3) containing surface normal vectors.
        
    Returns:
        A tensor of shape (..., 3) with RGB values in [0, 1].
    """
    # Take absolute value of each component
    abs_normals = surface_normals.abs()
    
    # Clamp to [0, 1]
    clamped_normals = abs_normals.clamp(0, 1)
    
    return clamped_normals
```

**Edge Cases and Pitfalls:**
- Since the absolute value is taken, the direction of the normal (inward vs. outward) is lost. This can make it difficult to distinguish between front-facing and back-facing surfaces if the geometry is not closed or if normals are inconsistent [S2, unofficial].
- If the normal vector is not normalized, the components may exceed 1.0 before clamping, but the clamping step ensures the output remains valid for display [S2, unofficial].

## Subtopics

### [Spin Shader](1959-spin-shader.md)
The Spin Shader visualizes surface geometry by mapping surface normals and camera orientation to a cyclic color field, mimicking spin-1/2 behavior where a 360-degree rotation reverses the texture orientation. It is distinct from standard Normal Shading as it encodes rotational information rather than just component magnitudes.

### [Normal Integrator](4451-normal-integrator.md)
The Normal Integrator is a visualization technique that renders the surface normal vector of a geometry as an RGB color image by mapping the normal components from the range $[-1, 1]$ to the color channel range $[0, 1]$ or $[0, 255]$ for debugging or artistic purposes. It preserves sign information through a linear shift-and-scale mapping ($\mathbf{n} = (\mathbf{n} + 1.0) / 2.0$), unlike Normal Shading which uses absolute values.

### [Normals Shader](7710-normals-shader.md)
The Normals Shader visualizes surface normals by converting vector components from the range $[-1, 1]$ to the displayable range $[0, 1]$. It serves as a debugging and visualization tool within the Normal Shading family, distinct from the Spin Shader's rotational encoding and the Normal Integrator's gradient accumulation. It outputs the normal direction as an emission color, allowing developers to verify normal orientation and smoothness.

### Laplacian Shading
Laplacian Shading visualizes the surface Laplacian by normalizing to $[-1, 1]$, flipping the sign, mapping to $[0, 1]$, and applying gamma correction [S2, unofficial]. It is used to highlight curvature or high-frequency details in the geometry.

**Formula:**
$$
L_{vis} = \left( \frac{-\frac{\Delta}{\max(|\Delta|)} + 1}{2} \right)^{1/2.33}
$$
clamped to $[0, 1]$, where $\Delta$ is the surface Laplacian [S2, unofficial].

**Pseudocode:**
```python
def laplacian_shading(surface_laplacian: Tensor) -> Tensor:
    """
    Visualizes the surface Laplacian with normalization, sign flip, and gamma correction.
    
    Args:
        surface_laplacian: A tensor of shape (..., 1) or (..., 3) containing Laplacian values.
        
    Returns:
        A tensor of shape (..., 1) or (..., 3) with values in [0, 1].
    """
    # Normalize to [-1, 1]
    normalized = surface_laplacian.div(surface_laplacian.abs().max())
    
    # Flip sign
    flipped = normalized.mul(-1)
    
    # Map to [0, 1]
    mapped = flipped.add(1).div(2)
    
    # Clamp to [0, 1]
    clamped = mapped.clamp(0, 1)
    
    # Apply gamma correction (gamma = 2.33)
    result = clamped.pow(1 / 2.33)
    
    return result
```

### Tangent Space Visualization
Tangent Space Visualization projects the surface normal onto the sensor plane and visualizes the result using domain coloring techniques [S2, unofficial].

**Steps:**
1. Let $e_\alpha$ and $e_\beta$ be an orthonormal basis for the sensor plane, and $v_p$ be the unit vector from pixel $p$ to the focal point [S2, unofficial].
2. Project the surface normal $N_p$ onto the sensor plane: $T_p = N_p - (N_p \cdot v_p)v_p$ [S2, unofficial].
3. Express $T_p$ in the basis $e_\alpha, e_\beta$ as $T_p = \alpha e_\alpha + \beta e_\beta$. The result is a vector $(\alpha, \beta)$ where $\alpha^2 + \beta^2 \leq 1$ [S2, unofficial].
4. Treat $(\alpha, \beta)$ as a complex number $\alpha + i\beta$ and apply domain coloring techniques to visualize the result [S2, unofficial].

**Pseudocode for Domain Coloring:**
```python
def tangent_space_visualization(
    surface_normals: Tensor,
    camera_orientation_conj: Tensor,
    ray_directions: Tensor,
    cyclic_colourmap: Tensor,
    degree: int
) -> Tensor:
    """
    Visualizes tangent space normals using domain coloring.
    
    Args:
        surface_normals: Tensor of shape (..., 3) containing surface normals.
        camera_orientation_conj: Tensor of shape (..., 4) containing conjugate quaternions.
        ray_directions: Tensor of shape (..., 3) containing ray directions.
        cyclic_colourmap: Tensor of shape (N, 3) containing the cyclic color map.
        degree: int, the degree of the cyclic color map.
        
    Returns:
        A tensor of shape (..., 3) with RGB values.
    """
    # Compute the vector from pixel to focal point (ray direction)
    v_p = ray_directions
    
    # Project normal onto sensor plane
    # T_p = N_p - (N_p . v_p) * v_p
    dot_product = (surface_normals * v_p).sum(dim=-1, keepdim=True)
    T_p = surface_normals - dot_product * v_p
    
    # This step requires defining the orthonormal basis e_alpha, e_beta
    # For simplicity, we assume a standard basis or compute it from camera orientation
    # [G] The exact computation of e_alpha and e_beta from camera_orientation_conj 
    # is not detailed in the sources, but typically involves constructing a local frame.
    # We assume T_p is already in the basis (alpha, beta) for this pseudocode.
    
    # Extract alpha and beta components
    # [G] Assuming T_p is already in the (alpha, beta) basis as per the source description
    # If not, a rotation matrix would be needed.
    alpha = T_p[..., 0]
    beta = T_p[..., 1]
    
    # Treat (alpha, beta) as a complex number alpha + i*beta
    # Apply domain coloring
    # Angle coloring
    angle = torch.atan2(beta, alpha)
    cmap_index = (angle.div(math.tau).add(0.5).mul(degree)
                  .multiply(cyclic_colourmap.shape[0])
                  .floor().long().remainder(cyclic_colourmap.shape[0]))
    colours = cyclic_colourmap[cmap_index, :]
    
    # Brightness
    brightness = (alpha.pow(2) + beta.pow(2)).pow(1 / 2)
    
    return brightness.mul(colours)
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel, as it involves a constant number of arithmetic operations (absolute value, clamp, or linear mapping) [S2, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary memory per pixel, as no large data structures are required [S2, unofficial].
- **Strengths:** Simple to implement, fast, and effective for debugging normal consistency [S2, unofficial].
- **Limitations:** Loses directional information (sign), which can be misleading for non-closed surfaces or inconsistent normals [S2, unofficial].
- **When to Use:** Debugging normal orientation in SDF rendering, artistic visualization of surface curvature magnitude [S2, unofficial].
- **When Not to Use:** When directional information is critical, such as in lighting calculations or when distinguishing between front and back faces [S2, unofficial].

## Background
Normal Shading is part of a collection of geometrically motivated shaders used in ray marching algorithms operating on Signed Distance Fields (SDFs) [S2, unofficial]. The technique is implemented in differentiable rendering frameworks, such as those based on PyTorch, allowing for gradient-based optimization of scene parameters [S2, unofficial]. The broader context includes the use of quaternions for 3D rotations to track spin orientation, which enables advanced shaders like the Spin Shader [S2, unofficial].
