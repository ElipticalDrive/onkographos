# Normal Shading

Also called: Absolute Normal Visualization, Clamped Normal Visualization, Normal Visualization

## Overview
Normal Shading visualizes surface normals by taking the absolute value of each component and clamping to $[0, 1]$ [S2, unofficial]. It differs from the parent [Lambertian Shading with Gradient Normals](1229-lambertian-shading-with-gradient-normals.md) by discarding lighting calculations to provide a direct, unlit representation of normal orientation [S2, unofficial]. Unlike the [Normal Integrator](4451-normal-integrator.md), which preserves sign information via linear shift-and-scale, Normal Shading maps all components to the positive octant, making it suitable for debugging symmetry or magnitude rather than direction [S1, unofficial].

## How it works
**Inputs:** A surface normal vector $\mathbf{n} = (n_x, n_y, n_z)$, typically normalized to unit length.
**Outputs:** A visualization color vector $\mathbf{c} \in [0, 1]^3$.

**Data Structures:**
The normal vector is represented as a 3-component floating-point vector. The output is a 3-component color vector.

**Steps:**
1. Compute the absolute value of each component of the normal vector $\mathbf{n}$.
2. Clamp each component to the range $[0, 1]$.
3. Assign the resulting components to the Red, Green, and Blue channels respectively.

**Formula:**
The visualization color $\mathbf{N}_{vis}$ is defined as:
$$ \mathbf{N}_{vis} = \max(0, \min(1, |\mathbf{n}|)) $$
where $|\mathbf{n}|$ denotes the component-wise absolute value of the normal vector $\mathbf{n}$ [S2, unofficial].

**Pseudocode:**
```python
def normal_shading(surface_normals: Tensor) -> Tensor:
    """
    Visualizes surface normals by taking the absolute value of each component 
    and clamping to [0, 1].
    
    Args:
        surface_normals: Tensor of shape (..., 3) containing normal vectors.
        
    Returns:
        Tensor of shape (..., 3) with values in [0, 1].
    """
    # Take absolute value of each component
    abs_normals = surface_normals.abs()
    
    # Clamp values to [0, 1]
    clamped_normals = abs_normals.clamp(0, 1)
    
    return clamped_normals
```

**Parameters:**
- None. The method is deterministic based on the input normal.

**Edge Cases and Pitfalls:**
- **Degenerate Normals:** If the input normal is not normalized, the absolute values may exceed 1 before clamping, but the clamp operation handles this by capping at 1. However, non-unit normals distort the visualization's interpretation of direction magnitude.
- **Sign Loss:** Because absolute values are taken, normals pointing in opposite directions (e.g., $(0, 0, 1)$ and $(0, 0, -1)$) map to the same color $(0, 0, 1)$. This makes it impossible to distinguish between front-facing and back-facing surfaces or inward/outward normals [S2, unofficial].

## Subtopics

### Laplacian Shading
Visualizes the surface Laplacian by normalizing to $[-1, 1]$, flipping sign, mapping to $[0, 1]$, and applying gamma correction [S2, unofficial]. It is distinct from standard Normal Shading as it visualizes curvature (Laplacian) rather than orientation.
**Formula:**
$$ L_{vis} = \left( \frac{-\frac{\Delta}{\max(|\Delta|)} + 1}{2} \right)^{1/2.33} $$
clamped to $[0, 1]$ [S2, unofficial].
**Pseudocode:**
```python
def laplacian_shading(surface_laplacian: Tensor) -> Tensor:
    """
    Visualizes the surface Laplacian with normalization, sign flip, 
    mapping to [0, 1], and gamma correction.
    
    Args:
        surface_laplacian: Tensor of scalar Laplacian values.
        
    Returns:
        Tensor of shape (..., 3) with values in [0, 1].
    """
    # Normalize to [-1, 1]
    normalized = surface_laplacian.div(surface_laplacian.abs().max())
    
    # Flip sign
    flipped = normalized.mul(-1)
    
    # Map to [0, 1]
    mapped = flipped.add(1).div(2)
    
    # Clamp and apply gamma correction
    clamped = mapped.clamp(0, 1)
    gamma_corrected = clamped.pow(1 / 2.33)
    
    # Broadcast to 3 channels for RGB visualization
    return gamma_corrected.repeat(1, 3) if gamma_corrected.dim() == 1 else gamma_corrected
```

### Tangent Space Visualization
Projects surface normals onto the sensor plane and visualizes them using domain coloring [S2, unofficial]. It differs from Normal Shading by encoding 2D tangent space vectors into complex plane colors.
**Steps:**
1. Let $e_\alpha$ and $e_\beta$ be an orthonormal basis for the sensor plane, and $v_p$ be the unit vector from pixel $p$ to the focal point.
2. Project the surface normal $N_p$ onto the sensor plane: $T_p = N_p - (N_p \cdot v_p)v_p$.
3. Express $T_p$ in the basis $e_\alpha, e_\beta$ as $T_p = \alpha e_\alpha + \beta e_\beta$. The result is a vector $(\alpha, \beta)$ where $\alpha^2 + \beta^2 \leq 1$.
4. Treat $(\alpha, \beta)$ as a complex number $\alpha + i\beta$ and apply domain coloring techniques to visualize the result [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel, involving only basic arithmetic operations (absolute value, clamp, multiplication).
- **Memory Complexity:** $O(1)$ auxiliary memory per pixel.
- **Strengths:** Simple to implement; computationally inexpensive; effective for debugging normal continuity and symmetry.
- **Limitations:** Loses sign information, making it unsuitable for distinguishing front/back faces or inward/outward normals. Not suitable for lighting calculations.
- **When to use:** Debugging normal maps, verifying SDF gradient consistency, or artistic visualization of normal magnitude.
- **When not to use:** When sign information is critical (use [Normal Integrator](4451-normal-integrator.md) instead) or when lighting effects are desired (use [Lambertian Shading with Gradient Normals](1229-lambertian-shading-with-gradient-normals.md)).

## Background
Normal Shading is a visualization technique used in ray marching and SDF rendering to inspect surface normals. It is implemented in the `ray_marching` repository by Kyle Rosa, which provides a collection of geometrically motivated shaders for SDF rendering [S2, unofficial]. The technique is part of a broader family of normal visualization methods used in computer graphics for debugging and artistic purposes.
