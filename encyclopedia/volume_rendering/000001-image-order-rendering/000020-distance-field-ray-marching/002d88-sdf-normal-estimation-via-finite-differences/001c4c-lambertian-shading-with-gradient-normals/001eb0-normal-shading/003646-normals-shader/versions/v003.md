# Normals Shader

Also called: NormalsShader, Object Normals Shader

## Overview
The Normals Shader visualizes surface normals by linearly mapping vector components from the $[-1, 1]$ range to the displayable $[0, 1]$ range [S2, unofficial]. It outputs the normal direction as an emission color to allow developers to verify normal orientation and smoothness [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Surface normal vector $\mathbf{n} = (n_x, n_y, n_z)$ with components in $[-1, 1]$ [S2, unofficial].
- Output: Emission color $\mathbf{c} = (c_x, c_y, c_z)$ in $[0, 1]$ [S1, unofficial].

**Data Structures:**
- Parameters: `_NormalScale` (float, default $0$) and `_NormalOffset` (float, default $0$) [S1, unofficial].

**Formula:**
For each component $i \in \{x, y, z\}$, the transformation is:
$$c_i = (n_i + 1) \times 0.5 \times \text{_NormalScale} + \text{_NormalOffset}$$
[S1, unofficial]

**Steps:**
1. Retrieve the surface normal vector $\mathbf{n}$ [S2, unofficial].
2. For each component $i \in \{x, y, z\}$:
   a. Map to $[0, 1]$: $v_i = (n_i + 1) \times 0.5$ [S1, unofficial].
   b. Apply scale and offset: $c_i = v_i \times \text{_NormalScale} + \text{_NormalOffset}$ [S1, unofficial].
3. Output $\mathbf{c}$ as the emission color [S1, unofficial].

**Pseudocode:**
```python
class Vector3:
    def __init__(self, x: float, y: float, z: float):
        self.x = x
        self.y = y
        self.z = z

def normals_shader(vertex_normal: Vector3, normal_scale: float = 0.0, normal_offset: float = 0.0) -> Vector3:
    # Map [-1, 1] to [0, 1]
    v_x = (vertex_normal.x + 1.0) * 0.5
    v_y = (vertex_normal.y + 1.0) * 0.5
    v_z = (vertex_normal.z + 1.0) * 0.5
    # Apply scale and offset
    out_x = v_x * normal_scale + normal_offset
    out_y = v_y * normal_scale + normal_offset
    out_z = v_z * normal_scale + normal_offset
    return Vector3(out_x, out_y, out_z)
```

**Edge Cases and Pitfalls:**
- If `_NormalScale` is $0$, the output is constant `_NormalOffset` for all components [S1, unofficial].
- Components outside $[-1, 1]$ will map outside $[0, 1]$ after the initial transformation, potentially causing clipping if the scale is non-zero [G].
- Normals should be unit length for accurate directional visualization; non-unit normals will distort the color mapping [G].

## Background
The method is implemented in Unity-based projects, specifically noted in the context of dual contouring [S1, unofficial]. It is used to visualize vertex normals as emission colors, aiding in the verification of mesh quality and normal continuity [S1, unofficial].
