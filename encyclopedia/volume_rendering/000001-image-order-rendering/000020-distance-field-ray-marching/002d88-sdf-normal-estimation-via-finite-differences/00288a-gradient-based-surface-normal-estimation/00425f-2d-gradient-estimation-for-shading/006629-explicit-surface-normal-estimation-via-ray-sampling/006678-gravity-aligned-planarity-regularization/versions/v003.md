# Gravity-Aligned Planarity Regularization


## Overview
Gravity-Aligned Planarity Regularization is a geometric regularization technique for volume rendering that aligns depth-inferred surface normals with the gravity axis to enforce local planarity [S1]. It solves the problem of geometric artifacts and non-planar noise on flat surfaces (e.g., ground planes in satellite imagery) by coupling adjacent rays through a shared surface approximation, thereby facilitating cross-ray gradient flow [S1]. Unlike standard NeRF training which treats rays independently, this method imposes area-based geometric constraints [S1].

## How it works
**Inputs and Outputs**
*   **Inputs:** A set of rays $R$, where each ray $r$ is defined by origin $o$ and direction $d$ [S1]. The rays are associated with a camera model (e.g., RPC models with Bundle Adjustment and learned camera adjustments) [S1].
*   **Outputs:** A scalar planarity loss value $L_{planar}$ used for backpropagation [S1].

**Data Structures**
*   **Ray:** Defined by origin $o$ and direction $d$ [S1].
*   **Surface Point:** 3D coordinate $p_s(r)$ computed as $o + d(r)d$ [S1].
*   **Normal:** Unit vector $\hat{n}$ orthogonal to the local surface plane [S1].

**Parameters**
*   **Gravity Axis ($g$):** In UTM coordinate systems, the ground lies in the XY-plane, so the Z-axis approximates the inverse gravity vector [S1]. Value: $g = (0, 0, 1)^T$ [S1].
*   **Regularization Weight ($\lambda_{planar}$):** Empirically chosen weight for the planarity loss [S1]. Value: $0.1$ [S1].
*   **Activation Epoch:** The regularizer is enabled at epoch three of training, once a coarse scene representation is learned [S1].

**Steps**
1.  **Select Neighbors:** For each ray $r$, select two random adjacent rays, $r_{n1}$ and $r_{n2}$, from the four immediate neighboring pixels [S1]. To prevent unstable normal calculation, ensure one neighbor is sampled from each of the two adjacent pixels in the X- and Y-axes [S1].
2.  **Estimate Depths:** Evaluate all three rays ($r, r_{n1}, r_{n2}$) to determine their estimated depth values $d(r)$ using the volume rendering equation [S1].
3.  **Compute Surface Points:** Convert the depth values into 3D surface points by following each ray along its direction:
    $$ p_s(r) = r(d(r)) = o + d(r)d $$
    This is performed for $r$, $r_{n1}$, and $r_{n2}$ [S1].
4.  **Estimate Surface Normal:** Approximate the local surface plane normal $\hat{n}(r, r_{n1}, r_{n2})$ using the cross product of the vectors formed by the three surface points:
    $$ \hat{n}(r, r_{n1}, r_{n2}) = (p_s(r_{n1}) - p_s(r)) \times (p_s(r_{n2}) - p_s(r)) $$
    Normalize the resulting vector to ensure unit length, denoted as $n(r, r_{n1}, r_{n2})$ [S1].
5.  **Compute Loss:** Calculate the planarity loss by summing the squared L2 distance between the gravity axis $g$ and the estimated surface normals over all rays $R$:
    $$ L_{planar}(R) = \sum_{r \in R} \| g - n(r, r_{n1}, r_{n2}) \|^2 $$
    The total loss contribution is $\lambda_{planar} L_{planar}(R)$ [S1].

**Pseudocode**
```python
def cross_product(a, b):
    return (a[1]*b[2] - a[2]*b[1], a[2]*b[0] - a[0]*b[2], a[0]*b[1] - a[1]*b[0])

def dot_product(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def normalize(v):
    length = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    if length == 0:
        return (0.0, 0.0, 0.0) # [G] Guard against division by zero for degenerate planes
    return (v[0]/length, v[1]/length, v[2]/length)

def select_diverse_neighbors(neighbors):
    # [S1] Requires one neighbor from X-adjacent pixels and one from Y-adjacent pixels.
    if len(neighbors) < 2:
        return neighbors[0], neighbors[0]
    x_diff = [n for n in neighbors if n.x != neighbors[0].x]
    y_diff = [n for n in neighbors if n.y != neighbors[0].y]
    rn1 = x_diff[0] if x_diff else neighbors[1]
    rn2 = y_diff[0] if y_diff else neighbors[2]
    return rn1, rn2

def gravity_aligned_planarity_regularization(rays_with_neighbors, depth_estimator, gravity_axis=(0.0, 0.0, 1.0)):
    """
    Computes the Gravity-Aligned Planarity Regularization loss.
    
    Args:
        rays_with_neighbors: List of tuples (ray, neighbors), where neighbors is a list of adjacent Ray objects.
        depth_estimator: Function that takes a ray and returns estimated depth d(r).
        gravity_axis: 3D vector representing the gravity prior. Default is (0, 0, 1).
        
    Returns:
        scalar: The planarity loss value.
    """
    total_loss = 0.0
    
    for ray, neighbors in rays_with_neighbors:
        rn1, rn2 = select_diverse_neighbors(neighbors)
        
        d_r = depth_estimator(ray)
        d_rn1 = depth_estimator(rn1)
        d_rn2 = depth_estimator(rn2)
        
        ps_r = (ray.o[0] + d_r * ray.d[0], ray.o[1] + d_r * ray.d[1], ray.o[2] + d_r * ray.d[2])
        ps_rn1 = (rn1.o[0] + d_rn1 * rn1.d[0], rn1.o[1] + d_rn1 * rn1.d[1], rn1.o[2] + d_rn1 * rn1.d[2])
        ps_rn2 = (rn2.o[0] + d_rn2 * rn2.d[0], rn2.o[1] + d_rn2 * rn2.d[1], rn2.o[2] + d_rn2 * rn2.d[2])
        
        vec1 = (ps_rn1[0]-ps_r[0], ps_rn1[1]-ps_r[1], ps_rn1[2]-ps_r[2])
        vec2 = (ps_rn2[0]-ps_r[0], ps_rn2[1]-ps_r[1], ps_rn2[2]-ps_r[2])
        
        normal_unnormalized = cross_product(vec1, vec2)
        normal = normalize(normal_unnormalized)
        
        diff = (gravity_axis[0]-normal[0], gravity_axis[1]-normal[1], gravity_axis[2]-normal[2])
        loss_term = dot_product(diff, diff)
        
        total_loss += loss_term
        
    return total_loss
```

**Edge Cases and Pitfalls**
*   **Degenerate Planes:** If the three surface points are collinear, the cross product yields a zero vector [G].
*   **Normalization of a zero vector is undefined [G].**
*   **Camera Accuracy:** The accuracy of the surface points depends on the camera model [S1]. The method assumes Bundle Adjustment preprocessing and learned camera adjustments (XY-axis shifts per image) are applied to improve accuracy [S1].
*   **Training Timing:** Enabling this regularizer too early (before a coarse scene representation is learned) may hinder convergence [S1]. It is explicitly enabled at epoch three [S1].

## Operating characteristics
*   **Time Complexity:** Adds overhead proportional to the number of rays $|R|$ due to the evaluation of two additional rays per primary ray and the cross-product calculation [G].
*   **Memory Complexity:** Requires storing depth values for adjacent rays temporarily during the loss computation [G].
*   **Strengths:** Effectively mitigates overfitting-induced geometric artifacts on flat surfaces (e.g., ground in satellite imagery) [S1]. Couples adjacent rays to facilitate cross-ray gradient flow, unlike independent ray training [S1].
*   **Limitations:** Specific to scenes with a known gravity axis (e.g., satellite imagery in UTM coordinates) [S1].
*   **Performance:** On the DFC2019 satellite reconstruction benchmark, SatGeo-NeRF (using this regularizer) improved Mean Altitude Error by 14.0% and 11.4% relative to baselines like EO-NeRF and EO-GS [S1].

## Background
Gravity-Aligned Planarity Regularization was introduced in the SatGeo-NeRF paper [S1]. It is designed specifically for geometrically regularized NeRFs for satellite imagery [S1]. The method leverages the known alignment of scene content in the UTM coordinate system, where the ground is in the XY-plane and the Z-axis approximates the inverse gravity vector [S1]. It is one of three model-agnostic regularizers proposed in SatGeo-NeRF, alongside Granularity Regularization and Depth-Supervised Regularization [S1].
