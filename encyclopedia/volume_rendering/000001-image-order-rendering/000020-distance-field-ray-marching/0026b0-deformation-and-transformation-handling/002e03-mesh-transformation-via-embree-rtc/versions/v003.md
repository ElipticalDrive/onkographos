# Mesh Transformation via Embree RTC
Also called: xformRtcMeshOnly
## Overview
This method applies a 4x4 transformation matrix to mesh vertices within an Embree ray-tracing geometry buffer. It solves the problem of updating mesh positions for dynamic scenes or rigid body transformations while maintaining the integrity of the source mesh data. It differs from [Inverse Model Matrix Transformation for Distance Fields](1962-inverse-model-matrix-transformation-for-distance-fields.md) by modifying the actual vertex positions in the Embree buffer rather than transforming the query point in world space, and from [Motion-Compensated Block Warping](4613-motion-compensated-block-warping.md) by operating on explicit mesh geometry rather than voxel blocks.
## How it works
**Inputs:**
- `source_mesh`: The original mesh data containing initial vertex positions.
- `embree_geometry`: The Embree geometry object containing the vertex buffer to be transformed.
- `transform_matrix`: A 4x4 matrix $M$ representing the desired transformation.

**Outputs:**
- Updated `embree_geometry` vertex buffer with transformed positions.
- Updated `embree_scene` with committed geometry.

**Data Structures:**
- Vertex buffer: Array of 3D floating-point coordinates $(x, y, z)$.
- Transformation matrix: $4 \times 4$ homogeneous matrix.

**Steps:**
1. Retrieve the pointer to the vertex buffer of the Embree geometry using `rtcGetGeometryBufferData`.
2. Initialize `averagePt` as a 4D vector $(0, 0, 0, 1)$ and `maxlen` as $0$.
3. Iterate through each vertex $i$ from $0$ to $N-1$ (where $N$ is the vertex count):
   a. Reset the current vertex `vert[i]` to its original position from `source_mesh`.
   b. Compute the transformed vertex $v = M \times \text{vert}[i]$.
   c. Update `vert[i].x`, `vert[i].y`, and `vert[i].z` with $v.x$, $v.y$, and $v.z$ respectively.
   d. Accumulate the transformed position into `averagePt`: `averagePt += v`.
   e. Calculate the distance $d$ from $v$ to the running average centroid. If $i=0$, the centroid is $v$; otherwise, it is `averagePt` / $(i+1)$.
   f. If $d > \text{maxlen}$, update `maxlen = d`.
4. After the loop, compute the final centroid $cp = \text{averagePt} / N$.
5. Commit the geometry and the scene in Embree.

**Pitfalls:**
- The incremental computation of `maxlen` may be incorrect due to the use of a running average centroid that changes with each iteration, rather than a fixed global centroid [S1, unofficial].

**Pseudocode:**
```python
def transform_mesh_embree(source_mesh, embree_geometry, transform_matrix):
    # Get vertex buffer pointer
    vertex_buffer = rtcGetGeometryBufferData(embree_geometry)
    vertex_count = len(source_mesh.vertices)
    
    average_pt = [0.0, 0.0, 0.0, 1.0]
    maxlen = 0.0
    
    for i in range(vertex_count):
        # Reset to original position
        original_pos = source_mesh.vertices[i]
        vert = [original_pos.x, original_pos.y, original_pos.z, 1.0]
        
        # Transform
        v = multiply_matrix_vector(transform_matrix, vert)
        
        # Update buffer
        vertex_buffer[i].x = v[0]
        vertex_buffer[i].y = v[1]
        vertex_buffer[i].z = v[2]
        
        # Accumulate for centroid
        average_pt[0] += v[0]
        average_pt[1] += v[1]
        average_pt[2] += v[2]
        
        # Compute distance to running average
        if i == 0:
            centroid = v
        else:
            centroid = [
                average_pt[0] / (i + 1),
                average_pt[1] / (i + 1),
                average_pt[2] / (i + 1)
            ]
        
        d = distance(v, centroid)
        if d > maxlen:
            maxlen = d
            
    # Final centroid calculation (not used in the loop but part of the process)
    cp = [
        average_pt[0] / vertex_count,
        average_pt[1] / vertex_count,
        average_pt[2] / vertex_count
    ]
    
    # Commit changes
    rtcCommitGeometry(embree_geometry)
    rtcCommitScene(embree_geometry.scene)
```
## Subtopics

### [Mesh Transformation](6214-mesh-transformation.md)
Applies a 4x4 transformation matrix to all vertices and normals of a mesh, updating the source mesh data in place while preserving the original positions in the source buffer. It differs from its parent [Mesh Transformation via Embree RTC](5669-mesh-transformation-via-embree-rtc.md) by operating directly on the mesh vertex array rather than maintaining a separate Embree geometry buffer with internal transformation matrices.
