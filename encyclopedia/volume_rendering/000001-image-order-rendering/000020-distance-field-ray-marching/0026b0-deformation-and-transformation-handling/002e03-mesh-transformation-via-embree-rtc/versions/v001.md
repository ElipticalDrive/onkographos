# Mesh Transformation via Embree RTC
Also called: xformRtcMeshOnly
## Overview
This method applies a 4x4 transformation matrix to mesh vertices within an Embree ray tracing scene, updating the geometry buffer in place while preserving the original source mesh data [S1, unofficial]. It differs from its sibling [Inverse Model Matrix Transformation for Distance Fields](1962-inverse-model-matrix-transformation-for-distance-fields.md) by modifying the actual vertex positions in the Embree buffer rather than applying inverse transformations to the ray origin or direction, and from [Motion-Compensated Block Warping](4613-motion-compensated-block-warping.md) by operating on explicit mesh geometry rather than warping pre-computed blocks or fields. It is used when the scene geometry needs to be physically updated for subsequent ray tracing operations.
## How it works
**Inputs:**
- `mesh`: The original source mesh data (vertices and normals).
- `mat`: A 4x4 transformation matrix (column-major or row-major, consistent with Embree's expectation).
- `embree_geometry`: The Embree geometry object containing the vertex buffer.
- `vertex_count`: The number of vertices in the mesh.

**Outputs:**
- Updated `embree_geometry` buffer with transformed vertices.
- Updated `embree_scene` (committed).

**Data Structures:**
- `vert`: Pointer to the vertex buffer retrieved from `embree_geometry`. Layout: contiguous array of 3 floats (x, y, z) per vertex.
- `original_positions`: Array of 4-component vectors (x, y, z, 1) storing the initial mesh positions.

**Steps:**
1. Retrieve the vertex buffer pointer from the Embree geometry using `rtcGetGeometryBufferData`.
2. Initialize `averagePt` as a 4D vector $(0, 0, 0, 1)$ and `maxlen` as $0$.
3. Loop through each vertex index $i$ from $0$ to `vertex_count` - 1:
   a. Reset the current vertex `vert[i]` to its original position from the source mesh.
   b. Transform the vertex: $v = mat \times vert[i]$.
   c. Update `vert[i].x`, `vert[i].y`, `vert[i].z` with $v.x$, $v.y$, $v.z$.
   d. Accumulate the transformed position: $averagePt += v$.
   e. Compute the distance $d$ from $v$ to the running average centroid. The centroid at step $i$ is $C_i = averagePt / (i + 1)$.
      $$ d = \| v - C_i \| $$
   f. If $d > maxlen$, set $maxlen = d$.
4. After the loop, compute the final centroid $cp = averagePt / vertex\_count$.
5. Commit the geometry and the scene to apply changes.

**Pitfalls:**
- The incremental computation of `maxlen` based on the distance to the running average centroid may be incorrect or misleading for bounding volume calculations, as the running average does not represent the true geometric center until the end [S1, unofficial].

**Pseudocode:**
```python
def transform_mesh_via_embree_rtc(mesh, mat, embree_geometry, vertex_count):
    # Get vertex buffer pointer
    vert_ptr = rtcGetGeometryBufferData(embree_geometry, RTC_BUFFER_TYPE_VERTEX)
    
    # Initialize accumulators
    average_pt = [0.0, 0.0, 0.0, 1.0]
    maxlen = 0.0
    
    # Loop through vertices
    for i in range(vertex_count):
        # Reset to original position
        orig = mesh.vertices[i] # Assuming mesh.vertices stores original positions
        vert_ptr[i] = orig
        
        # Transform
        v = mat * orig # 4x4 matrix multiplication
        
        # Update buffer
        vert_ptr[i].x = v.x
        vert_ptr[i].y = v.y
        vert_ptr[i].z = v.z
        
        # Accumulate
        average_pt[0] += v.x
        average_pt[1] += v.y
        average_pt[2] += v.z
        # average_pt[3] remains 1.0 if we treat it as a counter, but note: 
        # The source says averagePt = (0,0,0,1) initially and accumulates v. 
        # If v is (x,y,z,1), then average_pt[3] will increment. 
        # However, the centroid calculation uses averagePt / vertex_count.
        # Let's assume averagePt accumulates the 4D homogeneous coordinates.
        average_pt[3] += 1.0 
        
        # Compute distance to running average
        count = i + 1
        centroid = [
            average_pt[0] / count,
            average_pt[1] / count,
            average_pt[2] / count
        ]
        
        dx = v.x - centroid[0]
        dy = v.y - centroid[1]
        dz = v.z - centroid[2]
        d = sqrt(dx*dx + dy*dy + dz*dz)
        
        if d > maxlen:
            maxlen = d
            
    # Final centroid (not strictly used in the update step but computed in source)
    cp = [
        average_pt[0] / vertex_count,
        average_pt[1] / vertex_count,
        average_pt[2] / vertex_count
    ]
    
    # Commit changes
    rtcCommitGeometry(embree_geometry)
    rtcCommitScene(embree_geometry.scene)
```
## Subtopics

### [Mesh Transformation](6214-mesh-transformation.md)
Applies a 4x4 transformation matrix to all vertices and normals of a mesh, updating the source mesh data in place while preserving the original positions in the source buffer. It differs from its parent [Mesh Transformation via Embree RTC](5669-mesh-transformation-via-embree-rtc.md) by operating directly on the mesh vertex array rather than maintaining a separate Embree geometry buffer with internal transformation matrices.

## Operating characteristics
Time complexity is $O(N)$ where $N$ is the number of vertices, as each vertex is transformed and accumulated once. Memory complexity is $O(1)$ auxiliary space beyond the vertex buffer. The method is limited by the precision of the floating-point transformation and the correctness of the incremental bounding box calculation. It is suitable for static or slowly deforming meshes where explicit vertex updates are required for ray tracing accuracy.
## Background
This method originates from the FLOD project, an unofficial implementation for rendering Gaussian splats and meshes using Embree [S1, unofficial]. It was developed to handle mesh transformations within the Embree ray tracing pipeline by directly modifying the geometry buffer.
