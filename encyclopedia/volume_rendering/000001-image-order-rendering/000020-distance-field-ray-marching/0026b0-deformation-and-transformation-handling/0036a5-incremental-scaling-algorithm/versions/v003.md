# Incremental Scaling Algorithm

Also called: Back Scaling

## Overview
The Incremental Scaling Algorithm is a method for applying uniform or non-uniform scaling transformations to voxel grids by computing destination coordinates through iterative addition rather than full matrix multiplication [S1]. It solves the computational bottleneck of per-voxel scaling in large volumes by exploiting spatial coherence, reducing the arithmetic cost of coordinate transformation to simple additions [S1]. It sets itself apart from direct matrix multiplication by avoiding multiplications for every voxel, and from [Motion-Compensated Block Warping](4613-motion-compensated-block-warping.md) by operating on the voxel grid structure itself rather than compressing temporal changes [S1].

## How it works
**Inputs and Outputs:**
- Input: Source voxel grid defined by bounds $(X_{src}, Y_{src}, Z_{src})$ to $(X_{src\_end}, Y_{src\_end}, Z_{src\_end})$.
- Input: Scaling factors $S_x, S_y, S_z$.
- Input: Destination grid bounds $(X_s, Y_s, Z_s)$ to $(X_E, Y_E, Z_E)$.
- Output: Destination voxel grid with scaled geometry.

**Data Structures:**
- The algorithm operates on integer voxel coordinates.
- Intermediate floating-point coordinates are used for the incremental stepping to maintain precision before rounding to the nearest integer voxel index [S1].

**Method:**
The standard scaling relationship maps a source coordinate to a destination coordinate:
$$ X_{dest} = X_{src} S_x $$
$$ Y_{dest} = Y_{src} S_y $$
$$ Z_{dest} = Z_{src} S_z $$

Direct computation requires a multiplication for every voxel. The incremental algorithm derives the next coordinate from the previous one:
$$ X_{dest} + S_x = (X_{src} + 1) S_x = X_{src} S_x + S_x $$
$$ Y_{dest} + S_y = (Y_{src} + 1) S_y = Y_{src} S_y + S_y $$
$$ Z_{dest} + S_z = (Z_{src} + 1) S_z = Z_{src} S_z + S_z $$

Thus, the next transformed coordinate is obtained by adding the scaling factor to the predecessor's coordinate and rounding to the nearest integer [S1].

**Pitfalls and Edge Cases:**
1.  **Holes in Forward Scaling:** If any scaling factor is greater than 1, the destination volume expands. Stepping through the source and mapping to the destination may skip destination voxels, creating holes [S1].
2.  **Back Scaling:** To avert holes, the algorithm reverses the process. It steps through the destination room and maps back to the source. The destination corners are found by transforming the source corners. The source coordinate is determined by multiplying destination coordinates by $(1/S_x, 1/S_y, 1/S_z)$ [S1].
3.  **Parallel Stepping:** A more efficient back-scaling variant steps through the source and destination rooms in parallel. The increments for the source room are $(X_{incr}/S_x, Y_{incr}/S_y, Z_{incr}/S_z)$, where $X_{incr}, Y_{incr}, Z_{incr}$ are the steps (typically 1) used in the destination room [S1].
4.  **Overwriting:** If the source and destination grids share memory, voxels may be overwritten before they are read. The starting corner of the transformation loop must be chosen based on the signs of $S_x, S_y, S_z$ to ensure safe traversal [S1].

**Pseudocode:**
The following implements back-scaling to prevent holes when $S > 1$. It assumes the destination bounds are known and the source bounds are derived or known.

```python
def incremental_scaling(source_grid, dest_bounds, scale_factors):
    """
    source_grid: 3D array of voxel values
    dest_bounds: tuple (Xs, Ys, Zs, XE, YE, ZE) defining destination voxel range
    scale_factors: tuple (Sx, Sy, Sz)
    """
    Sx, Sy, Sz = scale_factors
    
    # Initialize destination grid
    dest_grid = create_empty_grid(dest_bounds)
    
    # Determine starting point based on scale factors to avoid overwriting
    # If Sx > 1, we step forward in dest, so we need to map back to source.
    # The source coordinate is dest_coord / Sx.
    
    Xs, Ys, Zs, XE, YE, ZE = dest_bounds
    
    # Precompute inverse scales for source stepping if using parallel method
    # Or compute directly for each voxel. The source text suggests parallel stepping
    # with increments (Xincr/Sx, ...). Here we implement the direct back-mapping
    # for clarity, which is equivalent to stepping dest and rounding source.
    
    for y in range(Ys, YE + 1):
        for z in range(Zs, ZE + 1):
            for x in range(Xs, XE + 1):
                # Reverse transform: map destination integer coordinate to source
                # The source coordinate is a float position.
                src_x = x / Sx
                src_y = y / Sy
                src_z = z / Sz
                
                # Round to nearest integer voxel index in source
                src_ix = round(src_x)
                src_iy = round(src_y)
                src_iz = round(src_z)
                
                # Check bounds to avoid out-of-bounds access
                if is_within_source_bounds(src_ix, src_iy, src_iz, source_grid):
                    dest_grid[x, y, z] = source_grid[src_ix, src_iy, src_iz]
                else:
                    dest_grid[x, y, z] = EMPTY_VALUE
                    
    return dest_grid
```

## Subtopics

### [Incremental Geometric Transformation](10583-incremental-geometric-transformation.md)
Applies affine transformations (translation, scaling, rotation) by computing new positions from the immediate predecessor's position using max three additions per coordinate. It reduces arithmetic operations compared to matrix multiplication but requires processing all voxels, including empty ones, making it suitable for parallel architectures.

### [Volume Deformation via Scattered Data Interpolation](16707-volume-deformation-via-scattered-data-interpolation.md)
Deforms volumes using 2D user-guided control points and Radial Basis Functions (RBFs) to generate a 3D displacement map. It differs by relying on global smooth interpolation from sparse handles rather than local voxel-wise transformations.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels in the output grid. The cost per voxel is reduced to a few additions and a rounding operation, compared to multiplications in standard scaling [S1].
- **Memory Complexity:** $O(N)$ for the output grid. In-place modification is possible if traversal order is managed correctly to prevent overwriting [S1].
- **Strengths:** Significantly reduces computational complexity for large rooms/volumes by eliminating multiplications [S1].
- **Limitations:** Requires careful handling of scaling factors $>1$ (back scaling) to avoid holes [S1]. Requires processing all voxels in the destination volume, even if empty, unlike sparse voxel approaches [S1].
- **When to use:** When scaling voxel primitives in a voxel frame buffer processor and computational efficiency is critical [S1].

## Background
The Incremental Scaling Algorithm was introduced in the context of the VoxBLIT Engine, a voxel frame buffer processor [S1]. It was developed to handle large rooms efficiently by reducing the complexity of geometric transformations [S1].
