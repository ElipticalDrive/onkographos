# Motion-Compensated Block Warping

Also called: Inter-frame motion compensation

## Overview
Motion-Compensated Block Warping is a technique for compressing temporal sequences of Truncated Signed Distance Fields (TSDF) by predicting the current frame's geometry from the previous frame using estimated rigid body motion [S1]. It solves the problem of high residual energy in dynamic scenes where objects move between frames, allowing the encoder to transmit only the motion parameters and the small residual differences rather than the full geometry [S1]. It differs from static deformation handling by explicitly estimating and transmitting a per-block 6-DoF transform to align the previous frame's data with the current frame's target block [S1].

## How it works
The method operates on a block-based sparse TSDF representation. The scene is decomposed into voxel blocks. For each block in the target frame $t$, the algorithm estimates a rigid transform that best aligns the reconstructed TSDF from the previous frame $t-1$ to the current target block.

### Inputs and Outputs
*   **Inputs:**
    *   $s_t^{(b)}$: The TSDF values for block $b$ at frame $t$.
    *   $\hat{s}_{t-1}^{(b)}$: The reconstructed (decoded) TSDF values for block $b$ at frame $t-1$.
    *   $\Omega$: The set of sample positions (voxel centers) within block $b$.
*   **Outputs:**
    *   $\mathbf{r}, \mathbf{t}$: The optimal rotation (Euler angles) and translation (3D vector) parameters.
    *   Residual coefficients: The difference between the current block and the warped predictor, encoded in the transform domain (e.g., DCT) [S1].

### Data Structures
*   **TSDF Block:** A 3D grid of voxel values. In the source implementation, blocks are stored in a GPU-side spatial hash table (voxel hashing) for fast random access [S1].
*   **Motion Parameters:** A 6-DoF rigid transform consisting of translation $\mathbf{t} \in \mathbb{R}^3$ and rotation $\mathbf{r} \in \mathbb{R}^3$ (parameterized as Euler angles) [S1].

### Steps
1.  **Neighborhood Assembly:** Assemble a stitched $3 \times 3 \times 3$ neighborhood of blocks from the previous frame's reconstructed TSDF $\hat{s}_{t-1}$ centered on the corresponding block location. This ensures that trilinear interpolation remains valid even when warped sample positions fall into adjacent blocks or between voxel centers [S1].
2.  **Motion Estimation:** Estimate the rigid transform $(\mathbf{r}, \mathbf{t})$ that minimizes the squared difference between the warped previous frame and the current frame. This is done using a damped Gauss-Newton optimization procedure [S1].
3.  **Inverse Warping (Prediction):** For each sample position $\mathbf{p}_i \in \Omega$ in the target block $b$ at frame $t$, compute the corresponding position in the previous frame using the inverse of the estimated transform:
    $$ \mathbf{q}_i = \mathbf{T}^{-1}(\mathbf{p}_i; \mathbf{r}, \mathbf{t}) $$
    where $\mathbf{T}$ is the rigid transform mapping previous frame coordinates to current frame coordinates [S1].
4.  **Trilinear Interpolation:** Evaluate the TSDF value at the warped location $\mathbf{q}_i$ by trilinearly interpolating the values from the $3 \times 3 \times 3$ neighborhood assembled in Step 1. This forms the motion-compensated predictor $\hat{s}_{t-1}^{(b)}(\mathbf{T}(\mathbf{p}_i; \mathbf{r}, \mathbf{t}))$ [S1].
5.  **Residual Encoding:** Compute the residual between the current block $s_t^{(b)}$ and the predictor. Encode the transform-domain coefficients of this residual [S1].
6.  **Side Information Encoding:** Encode the motion parameters $\mathbf{r}$ and $\mathbf{t}$ as side information [S1].

### Formulas
The residual for sample $i$ is defined as [S1]:
$$ \epsilon_i(\mathbf{r}, \mathbf{t}) = \hat{s}_{t-1}^{(b)}(\mathbf{T}(\mathbf{p}_i; \mathbf{r}, \mathbf{t})) - s_t^{(b)}(\mathbf{p}_i) $$

The optimization objective is to minimize the sum of squared residuals [S1]:
$$ \mathbf{t}, \mathbf{r} := \arg \min_{\mathbf{t}, \mathbf{r}} \sum_{i \in \Omega} \epsilon_i(\mathbf{r}, \mathbf{t})^2 $$

The update step in the Gauss-Newton algorithm is calculated as [S1]:
$$ \Delta \mathbf{p} = -(J^\top J + \lambda I)^{-1} J^\top \boldsymbol{\varepsilon} $$
where $J$ is the Jacobian of the residuals with respect to the parameters, $\lambda$ is a damping factor for numerical stability, and $\boldsymbol{\varepsilon}$ is the vector of residuals [S1].

### Parameters
*   **Damping factor $\lambda$:** A small value for numerical stability in the Gauss-Newton solver [S1].
*   **Translation clamp:** 1 voxel per iteration [S1].
*   **Rotation clamp:** 5 degrees per iteration [S1].
*   **Termination threshold:** The optimization terminates when the decrease in the objective function falls below a specific threshold [S1].

### Edge Cases and Pitfalls
*   **Insufficient Data:** If too few reliable samples are available or the $3 \times 3 \times 3$ neighborhood is incomplete (e.g., at the boundary of the volume), the method falls back to zero-motion prediction ($\mathbf{t} = 0, \mathbf{r} = 0$) for that block [S1].
*   **Divergence:** Large motion estimates can cause the Gauss-Newton solver to diverge. Clamping the per-iteration update magnitudes prevents this [S1].
*   **Fractional Positions:** Rigid motion maps integer voxel centers to fractional positions. Trilinear interpolation is required to evaluate the TSDF at these non-integer locations [S1].

## Subtopics

### Per-Block Motion Estimation
This is the core optimization subroutine used within Motion-Compensated Block Warping. It estimates the 6-DoF rigid transform for a specific block by aligning TSDF samples using a damped Gauss-Newton procedure [S1]. It is chosen when precise local motion estimation is required to minimize residual energy. It differs from global motion estimation by operating on a per-block basis, allowing for independent motion of different parts of the scene [S1]. Key implementation details include clamping translation updates to 1 voxel and rotation updates to 5 degrees per step to prevent divergence, and falling back to zero-motion if the neighborhood is incomplete or samples are unreliable [S1].

## Operating characteristics
*   **Time Complexity:** The motion estimation step involves an iterative Gauss-Newton optimization. The cost depends on the number of samples in the block, the number of iterations, and the cost of trilinear interpolation and Jacobian computation. The source does not provide a closed-form complexity but notes the use of a damped Gauss-Newton procedure [S1].
*   **Memory Complexity:** Requires storing the current block, the previous frame's reconstructed TSDF, and the $3 \times 3 \times 3$ neighborhood for interpolation. The source uses a sparse representation with a GPU-side spatial hash table, reducing memory usage for empty space [S1].
*   **Performance:** The method is implemented in C++ with CUDA acceleration [S1]. Specific performance metrics (compression ratio, encoding time) are not provided in the source text, only the implementation details [S1].
*   **Strengths:** Effectively reduces residual energy for rigidly moving objects, leading to better compression ratios for dynamic TSDF volumes [S1].
*   **Limitations:** Relies on the assumption of rigid motion within each block. Non-rigid deformations within a block will not be well-compensated. Requires accurate motion estimation, which can be computationally expensive [S1].
*   **When to use:** Suitable for compressing dynamic scenes with significant rigid body motion, such as in 3D reconstruction from video sequences [S1].
*   **When not to use:** Not suitable for scenes with significant non-rigid deformation or where motion estimation is unreliable (e.g., textureless regions, occlusions) [S1].

## Background
The method originates from the paper "Implicit Surface Compression -- with Good Old Discrete Cosine Transform and Motion Compensation" [S1]. It is part of a codec for compressing sparse TSDF volumes, leveraging traditional image compression techniques (DCT) and video compression concepts (motion compensation) for 3D data [S1]. The implementation uses voxel hashing for sparse storage [S1].
