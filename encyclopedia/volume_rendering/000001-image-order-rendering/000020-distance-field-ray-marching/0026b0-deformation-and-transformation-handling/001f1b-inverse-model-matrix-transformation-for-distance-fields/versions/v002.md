# Inverse Model Matrix Transformation for Distance Fields

Also called: Inverse Transformation for Rotation/Translation, SDF Model Transformations, Transforming SDFs, Transforming SDFs via Inverse Matrix

## Overview
This method applies rigid body transformations (rotation and translation) to Signed Distance Field (SDF) primitives by transforming the sample point using the inverse of the object's model matrix before evaluation [S1, unofficial][S2, unofficial]. It solves the problem of animating or positioning individual SDF objects independently without modifying the underlying distance function definitions [S1, unofficial]. Unlike direct geometry transformation, it preserves the analytical nature of the SDF by operating in the object's local coordinate space [S2, unofficial]. It differs from [Motion-Compensated Block Warping](4613-motion-compensated-block-warping.md) which estimates per-block warps for temporal compression, and from [Mesh Transformation via Embree RTC](5669-mesh-transformation-via-embree-rtc.md) which transforms explicit mesh primitives rather than implicit distance fields.

## How it works
**Inputs and Outputs:**
- Input: Sample point $\mathbf{p}$ in world space, inverse model matrix $M^{-1}$.
- Output: Distance value $d$ from the base SDF primitive.

**Data Structures:**
- $M^{-1}$: A $4 \times 4$ matrix of floating-point values representing the inverse model transformation [S2, unofficial].
- $\mathbf{p}$: A 3D vector $(p_x, p_y, p_z)$ [S2, unofficial].
- Homogeneous point: A 4D vector $(p_x, p_y, p_z, 1.0)$ used for affine transformation [S2, unofficial].

**Steps:**
1. Construct the model matrix $M$ for the object in the host application using translation, rotation, and scale components [S2, unofficial].
2. Compute the inverse of the model matrix $M^{-1}$ [S2, unofficial].
3. Pass $M^{-1}$ to the rendering shader as a uniform variable [S2, unofficial].
4. Receive the world-space sample point $\mathbf{p}$ in the SDF evaluation function [S2, unofficial].
5. Transform $\mathbf{p}$ into the object's local space by multiplying the homogeneous point by $M^{-1}$:
   $$ \mathbf{q} = M^{-1} \begin{bmatrix} p_x \\ p_y \\ p_z \\ 1 \end{bmatrix} $$
   where $\mathbf{q}$ is the resulting 4D vector [S2, unofficial].
6. Extract the 3D local point $\mathbf{q}_{xyz}$ from $\mathbf{q}$ [S2, unofficial].
7. Evaluate the base SDF primitive using $\mathbf{q}_{xyz}$:
   $$ d = f_{\text{base}}(\mathbf{q}_{xyz}) $$
8. Return $d$ [S2, unofficial].

**Pseudocode:**
```python
def evaluate_transformed_sdf(p, inv_model_matrix, base_sdf):
    # p: tuple (x, y, z) in world space
    # inv_model_matrix: 4x4 list of lists, column-major layout (row i, col j)
    # base_sdf: callable taking (x, y, z) and returning distance
    x, y, z = p
    w = 1.0
    # Explicit matrix-vector multiplication: q = M^-1 * [x, y, z, 1]^T
    qx = inv_model_matrix[0][0]*x + inv_model_matrix[1][0]*y + inv_model_matrix[2][0]*z + inv_model_matrix[3][0]*w
    qy = inv_model_matrix[0][1]*x + inv_model_matrix[1][1]*y + inv_model_matrix[2][1]*z + inv_model_matrix[3][1]*w
    qz = inv_model_matrix[0][2]*x + inv_model_matrix[1][2]*y + inv_model_matrix[2][2]*z + inv_model_matrix[3][2]*w
    # qw is typically 1.0 for affine transforms; SDF evaluation uses only xyz
    q_local = (qx, qy, qz)
    return base_sdf(q_local)
```

**Parameters:**
- `inv_model_matrix`: A $4 \times 4$ uniform matrix representing the inverse of the object's model transformation [S2, unofficial].

**Edge Cases and Pitfalls:**
- **Scaling:** Uniform scaling by factor $s$ requires scaling the distance return value to preserve Euclidean properties: $f'(\mathbf{p}) = s \cdot f(\mathbf{p}/s)$ [G]. Non-uniform scaling distorts the distance field unless the metric is adjusted or the scale is baked into the inverse matrix [G].
- **Precision:** Floating-point precision errors in matrix inversion can cause slight artifacts, especially with large translation values or extreme rotations [G].
- **Non-uniform Scale:** If non-uniform scaling is used, the inverse matrix must be correctly computed; naive inversion may distort the distance field if the metric adjustment is omitted [G].

## Subtopics

### Inverse Viewing Transformations for Volumes
This variant applies the inverse transformation to the viewing geometry (eye position, light sources, pixel coordinates) rather than the object, keeping the volume data fixed [S3, unofficial]. It is chosen when the volume data is large (e.g., $>1$ million voxels) and direct per-voxel transformation is computationally prohibitive [S3, unofficial].
- **Steps:**
  1. Store X, Y, and Z ordinates in separate 1D arrays rather than per-voxel coordinates [S3, unofficial].
  2. Center the coordinate arrays by subtracting half the volume's span from each ordinate value [S3, unofficial].
  3. Apply scaling by multiplying each ordinate value by the user-specified scaling factor [S3, unofficial].
  4. For rotation/translation, transform the eye, lights, and pixels instead of the voxels [S3, unofficial].
- **Complexity:** Reduces complexity from $O(N_{\text{voxels}})$ to $O(N_{\text{pixels}} + N_{\text{lights}})$ for rotation/translation [S3, unofficial].
- **Pitfall:** Directly transforming voxel positions for rotation/translation requires $\sim 9$ multiplications and $\sim 9$ additions per voxel, which is too slow for large volumes [S3, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per sample point for the transformation step [S2, unofficial]. The overall ray marching complexity remains dominated by the number of steps per ray.
- **Strengths:** Allows independent animation of SDF parts without recomputing distance functions [S1, unofficial]. Simple to implement [S2, unofficial].
- **Limitations:** Does not naturally handle non-rigid deformations [G]. Scaling requires careful handling [G].

## Background
The technique was popularized in the context of real-time ray marching and SDF rendering, notably by Jamie Wong and Adrian Booth [S1, unofficial][S2, unofficial]. It is a standard technique in computer graphics for transforming implicit surfaces [S1, unofficial]. The inverse viewing transformation variant for volumes was described in early volumetric rendering research for aerodynamic flow field data [S3, unofficial].
