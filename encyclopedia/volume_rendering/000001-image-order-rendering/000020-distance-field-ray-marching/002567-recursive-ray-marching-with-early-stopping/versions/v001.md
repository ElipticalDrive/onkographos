# Recursive Ray Marching with Early Stopping

Also called: Dynamic Synchronized Inference

## Overview
Recursive Ray Marching with Early Stopping is a parallelization technique for sphere tracing that maintains a dynamic mask of unfinished rays to prevent wasted computation on rays that have already converged [S1][S2, unofficial]. It solves the inefficiency of synchronous batch updates where rays converge at different rates, by skipping rays that have hit the surface or exceeded bounds [S2, unofficial]. It sets itself apart from standard synchronous ray marching by dynamically updating the set of active rays at each step [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Camera rays (origin $ro$, direction $v$), SDF function $f(p)$, maximum marching steps $N_{max}$ (typically 100 [S1]), convergence threshold $\epsilon$ (e.g., $5 \times 10^{-5}$ [S2, unofficial]), and step ratio $\alpha$ (typically 1.2 to 1.8 [S1]).
- Output: Rendered depth, normal, silhouette, or color for each pixel.

**Data Structures:**
- `unfinished_mask`: A boolean tensor of shape $(H, W)$, initially all `True`. Entries are set to `False` when a ray converges or goes out of bounds [S1].
- `marching_zdepth`: A float tensor of shape $(H, W)$, initialized to zeros, tracking the accumulated distance along each ray [S2, unofficial].
- `query_locations`: A list or tensor storing the 3D points queried for each ray to enable gradient computation [S1].

**Steps:**
1. Initialize `unfinished_mask` to all `True` [S1].
2. Initialize `marching_zdepth` to zeros [S2, unofficial].
3. Loop for $i$ from 0 to $N_{max}-1$:
    a. Select active rays using `unfinished_mask` [S2, unofficial].
    b. Concatenate all unfinished rays into a single batch tensor [S1].
    c. Perform feedforward SDF query on the batch [S1].
    d. Map results back to original image resolution [S1].
    e. Check convergence criteria for each ray:
        i. If $f(p) \le \epsilon$ or ray is out of bounds (e.g., unit sphere), set `unfinished_mask` entry to `False` [S1].
    f. Update `marching_zdepth` for active rays: $d_{step} = \max(f(p), \text{small\_value}) \cdot \alpha$ [S1][S2, unofficial]. Clamp $d_{step}$ to avoid overshooting [S2, unofficial].
    g. Update ray positions: $p \leftarrow p + d_{step} \cdot v$ [S2, unofficial].
    h. Store query locations globally for backpropagation [S1].
4. Return final ray positions and SDF values for all rays [S2, unofficial].

**Formulas:**
- Convergence: $f(p) \le \epsilon$ [S1][S2, unofficial].
- Step size: $d_{step} = \max(f(p), \delta) \cdot \alpha$ [S1][S2, unofficial], where $\delta$ is a small value to prevent zero steps, and $\alpha \in [1.2, 1.8]$ [S1].

**Parameters:**
- $N_{max}$: Maximum marching steps, typically 100 [S1].
- $\epsilon$: Convergence threshold, typically $5 \times 10^{-5}$ [S2, unofficial].
- $\alpha$: Step ratio, typically 1.2 to 1.8 [S1].
- $K$: Number of queries to keep for backpropagation. $K=1$ for depth rendering, $K=3$ for shape completion, $K=1$ for multi-view reconstruction [S1].

**Edge Cases and Pitfalls:**
- Slow convergence near surface: Addressed by convergence criteria [S1].
- Memory consumption: Trivially computing minimum absolute SDF value for each ray results in unaffordable memory consumption. Solution: Save query locations globally, perform minimization over a detached tensor graph, retrieve minimum K queries, and feedforward those queries again with gradients attached [S1].

**Pseudocode:**
```python
def recursive_ray_marching(ro, v, sdf, max_steps=100, threshold=5e-5, alpha=1.5):
    H, W = ro.shape[:2]
    unfinished_mask = torch.ones(H, W, dtype=torch.bool)
    marching_zdepth = torch.zeros(H, W)
    query_locations = []
    
    for i in range(max_steps):
        if not unfinished_mask.any():
            break
            
        # Select active rays
        active_ro = ro[unfinished_mask]
        active_v = v[unfinished_mask]
        
        # Current positions
        current_p = active_ro + active_v * marching_zdepth[unfinished_mask].unsqueeze(-1)
        
        # SDF query
        sdf_vals = sdf(current_p)
        
        # Check convergence
        converged = sdf_vals.abs() <= threshold
        out_of_bounds = ... # Check against scene bounds
        
        # Update mask
        mask_indices = torch.nonzero(unfinished_mask, as_tuple=False)
        for idx, conv in zip(mask_indices, torch.cat([converged, out_of_bounds])):
            if conv:
                unfinished_mask[idx[0], idx[1]] = False
                
        # Update marching_zdepth for active rays
        step_sizes = sdf_vals.clamp(min=1e-6) * alpha
        marching_zdepth[unfinished_mask] += step_sizes.squeeze(-1)
        
        # Store query locations
        query_locations.append(current_p)
        
    # Final rendering
    final_p = ro + v * marching_zdepth.unsqueeze(-1)
    final_sdf = sdf(final_p)
    return final_p, final_sdf
```

## Subtopics

### [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md)
An adaptive ray marching algorithm that iteratively samples rays until all are occluded or a max step count is reached, using a density grid for acceleration.

## Operating characteristics
- Time Complexity: Proportional to the number of active rays times the number of steps. Early stopping reduces the average number of steps per ray [S1].
- Memory Complexity: $O(H \times W)$ for masks and depth tensors. Query locations storage depends on $K$ and max steps [S1].
- Performance: Enables high-resolution images (2048x2048) on single GPU (GTX-1080Ti) [S1].
- Strengths: Efficient parallelization, reduced wasted computation [S1].
- Limitations: Memory consumption for gradient computation if not handled carefully [S1].
