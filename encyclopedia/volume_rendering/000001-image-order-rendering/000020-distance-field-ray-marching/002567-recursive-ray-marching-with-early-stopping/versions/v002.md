# Recursive Ray Marching with Early Stopping

Also called: Dynamic Synchronized Inference

## Overview
Recursive Ray Marching with Early Stopping is a parallelization technique for sphere tracing that prevents wasted computation on rays that have already converged to a surface or exited the scene [S1]. It differs from its sibling [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md) by focusing on dynamic batch synchronization of active rays rather than fixed-size chunking for hardware throughput optimization. It builds on [Distance-field ray marching](21-distance-field-ray-marching.md) by adding a convergence mask to the standard marching loop.

## How it works
The method renders geometry by maintaining a boolean mask for all camera rays, initially set to `true` (unfinished) [S1]. Rays that hit the surface or exceed bounds are marked `false` and excluded from subsequent SDF queries [S1].

**Inputs and Outputs:**
- **Inputs:** Camera rays (origin $ro$, direction $v$), SDF function $S(p)$, maximum marching steps $N_{max}$, convergence threshold $\epsilon$.
- **Outputs:** Rendered image (depth, color, or normal) for all pixels.

**Data Structures:**
- `unfinished_mask`: A boolean array of size equal to the number of rays (pixels). `True` indicates the ray is still marching; `False` indicates convergence or termination.
- `ray_positions`: Array of current ray origins for all rays.
- `ray_depths`: Accumulated depth along rays.
- `query_history`: Optional storage of query locations for backpropagation (used in differentiable implementations) [S1].

**Parameters:**
- $N_{max}$: Maximum marching steps. Typical value: 100 [S1].
- $\epsilon$: Convergence threshold. Typical value: $5 \times 10^{-5}$ [S2, unofficial].
- $K$: Number of historical queries to retain for gradient computation. $K=1$ for depth, $K=3$ for shape completion [S1].

**Algorithm Steps:**
1. Initialize `unfinished_mask` to all `True`. Initialize `ray_positions` to ray origins $ro$. Initialize `ray_depths` to 0.
2. Loop for $i$ from 0 to $N_{max}-1$:
    a. **Select Active Rays:** Identify indices where `unfinished_mask` is `True`.
    b. **Query SDF:** Evaluate $d = S(p)$ for all active rays at their current `ray_positions`.
    c. **Check Convergence:** For each active ray, check if $|d| \le \epsilon$ or if the ray has exceeded a maximum range.
    d. **Update Mask:** Set `unfinished_mask[j] = False` for any ray $j$ that has converged or terminated.
    e. **Advance Rays:** For remaining active rays, update position: $p \leftarrow p + d \cdot v$. Update `ray_depths` by adding $d$.
    f. **Store History (Optional):** If differentiable rendering is required, store query locations for active rays. To save memory, only keep the minimum $K$ absolute SDF values per ray for backpropagation [S1].
3. **Finalize:** For rays where `unfinished_mask` is `False`, the final position and depth are recorded. For rays where `unfinished_mask` is still `True` (max steps reached), handle as miss or clamp to last position.

**Pseudocode:**
```python
def recursive_ray_marching_with_early_stopping(
    ray_origins, ray_directions, sdf_func, 
    max_steps=100, threshold=5e-5, max_range=100.0
):
    num_rays = len(ray_origins)
    unfinished_mask = np.ones(num_rays, dtype=bool)
    current_positions = ray_origins.copy()
    depths = np.zeros(num_rays)
    
    # Optional: History for gradients
    query_history = [] 
    
    for step in range(max_steps):
        # 1. Select active rays
        active_indices = np.where(unfinished_mask)[0]
        if len(active_indices) == 0:
            break
            
        active_positions = current_positions[active_indices]
        
        # 2. Query SDF
        distances = sdf_func(active_positions)
        
        # 3. Check convergence and bounds
        converged = (np.abs(distances) <= threshold) | (depths[active_indices] > max_range)
        
        # 4. Update mask
        unfinished_mask[active_indices[converged]] = False
        
        # 5. Advance rays
        # Only advance rays that are still unfinished
        still_active = active_indices[~converged]
        if len(still_active) > 0:
            current_positions[still_active] += ray_directions[still_active] * distances[~converged]
            depths[still_active] += distances[~converged]
            
        # 6. Store history (if needed for backprop)
        # In practice, this involves saving positions and distances for active rays
        # and managing the K-minimum strategy to save memory [S1]
        query_history.append((active_positions, distances))
        
    return current_positions, depths, unfinished_mask
```

**Edge Cases and Pitfalls:**
- **Precision:** When close to the surface, $d$ becomes very small, leading to slow convergence. The threshold $\epsilon$ must be chosen carefully to balance accuracy and performance [S1].
- **Memory Consumption:** Storing query history for all rays and steps can be prohibitive. The method uses a detached tensor graph for minimization to find the minimum $K$ queries per ray before attaching gradients, reducing memory usage [S1].
- **Batching:** Rays must be concatenated into a single batch for efficient SDF evaluation, then mapped back to original resolution [S1].

## Subtopics

### [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md)
Optimizes computational load by dynamically adjusting the number of sampling steps per ray based on the number of currently active rays. It differs by explicitly batching remaining active rays into fixed-size chunks to maximize hardware throughput, rather than processing rays individually or with static step counts.

## Operating characteristics
- **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of rays and $S$ is the average number of steps per ray. Early stopping reduces $S$ for rays that converge quickly.
- **Memory Complexity:** $O(N \cdot S)$ for storing ray states. With history tracking for gradients, memory usage increases by $O(N \cdot K)$, where $K$ is the number of retained queries per ray [S1].
- **Performance:** Enables high-resolution rendering (e.g., 2048x2048) on limited hardware (e.g., GTX-1080Ti) by avoiding wasted computation on converged rays [S1].
- **Strengths:** Efficient parallelization, reduced computation for converged rays, compatible with differentiable rendering.
- **Limitations:** Requires careful management of batch sizes and memory for gradient history. Convergence threshold affects accuracy.

## Background
The method was introduced as "Dynamic Synchronized Inference" in the context of differentiable sphere tracing for rendering deep implicit signed distance functions [S1]. It addresses the inefficiency of naive parallelization where all rays are updated synchronously, leading to wasted computation on rays that have already converged [S1]. The implementation details are available in the unofficial repository [S2, unofficial].
