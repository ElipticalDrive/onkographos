# Cube World Stylized Shading

Also called: Cube World Lighting, Stylized Voxel Shading

## Overview
Cube World Stylized Shading is a fragment shader technique that replicates the specific lighting and ambient occlusion (AO) aesthetic of the game *Cube World* [S1, unofficial]. It solves the problem of creating distinct, stylized shadow bands rather than smooth gradients, using a multi-band AO interpolation model [S1, unofficial]. Unlike basic multiplication shading which creates a single smooth gradient, this method creates distinct bands (exposed, mid-shadow, occluded) with specific tinting, matching the original game's aesthetic [S1, unofficial].

## How it works
The method operates on a surface point $\mathbf{p}$ with its base color $\mathbf{c}_{base}$ and a pre-computed or ray-marched raw ambient occlusion value $v_{AO} \in [0, 1]$, where 0 is fully exposed and 1 is fully occluded.

**Inputs:**
- $\mathbf{c}_{base}$: Base material color (vec3).
- $v_{AO}$: Raw ambient occlusion value (float).
- Uniforms: $u_{enable}$, $u_{mult}$, $u_{curve}$, $\mathbf{c}_{tint}$, $u_{mid\_mix}$, $u_{occ\_mix}$, $u_{mid\_dark}$, $u_{occ\_dark}$.

**Outputs:**
- $\mathbf{c}_{final}$: Final shaded color (vec3).

**Data Structures:**
No complex data structures are required. The method relies on scalar uniforms and vector arithmetic.

**Parameters:**
- $u_{enable}$: Boolean uniform (1.0 or 0.0) to toggle between stylized shading and basic multiplication fallback [S1, unofficial].
- $u_{mult}$: Float uniform, default 1.0, applied to the raw AO value before curve processing [S1, unofficial].
- $u_{curve}$: Float uniform, default 1.0, exponent applied to the clamped AO value to adjust contrast [S1, unofficial].
- $\mathbf{c}_{tint}$: vec3 uniform, default `0x2a3b5c` (converted to normalized float range), used to tint shadowed areas [S1, unofficial].
- $u_{mid\_mix}$: Float uniform, default 0.4, mixing factor for mid-shadow tinting [S1, unofficial].
- $u_{occ\_mix}$: Float uniform, default 0.8, mixing factor for occluded shadow tinting [S1, unofficial].
- $u_{mid\_dark}$: Float uniform, default 0.65, brightness multiplier for the mid-shadow band base color [S1, unofficial].
- $u_{occ\_dark}$: Float uniform, default 0.3, brightness multiplier for the occluded shadow band base color [S1, unofficial].

**Steps:**
1. **Clamp and Scale AO:** Calculate the raw AO value clamped to $[0, 1]$ and scaled by the multiplier.
   $$ v_{AO}' = \text{clamp}(v_{AO} \cdot u_{mult}, 0.0, 1.0) $$
2. **Apply Contrast Curve:** Apply the contrast curve exponent to the scaled AO.
   $$ v_{AO}'' = \text{pow}(v_{AO}', u_{curve}) $$
3. **Check Stylization Toggle:** If $u_{enable} < 0.5$, the method falls back to basic multiplication.
   $$ \mathbf{c}_{final} = \mathbf{c}_{base} \cdot v_{AO}'' $$
   Return $\mathbf{c}_{final}$.
4. **Calculate Mid-Shadow Color:** Compute the color for the mid-shadow band by mixing the darkened base color with the shadow tint.
   $$ \mathbf{c}_{mid} = \text{mix}(\mathbf{c}_{base} \cdot u_{mid\_dark}, \mathbf{c}_{base} \cdot \mathbf{c}_{tint}, u_{mid\_mix}) $$
   *Note: The source code `mix(vColor * uMidDarken, vColor * uMidMix, uMidMix)` in the notes appears to contain a typo in the second argument (`uMidMix` instead of `uShadowTint`). Based on the description "mixing factor for mid-shadow tinting" and the parallel structure with `colorOccluded`, the second argument is interpreted as the tinted color $\mathbf{c}_{base} \cdot \mathbf{c}_{tint}$.*
5. **Calculate Occluded-Shadow Color:** Compute the color for the fully occluded band.
   $$ \mathbf{c}_{occ} = \text{mix}(\mathbf{c}_{base} \cdot u_{occ\_dark}, \mathbf{c}_{base} \cdot \mathbf{c}_{tint}, u_{occ\_mix}) $$
6. **Interpolate Based on AO:**
   - If $v_{AO}'' \ge 0.5$: Interpolate between the mid-shadow color and the exposed base color.
     $$ \mathbf{c}_{final} = \text{mix}(\mathbf{c}_{mid}, \mathbf{c}_{base}, (v_{AO}'' - 0.5) \cdot 2.0) $$
   - If $v_{AO}'' < 0.5$: Interpolate between the occluded-shadow color and the mid-shadow color.
     $$ \mathbf{c}_{final} = \text{mix}(\mathbf{c}_{occ}, \mathbf{c}_{mid}, v_{AO}'' \cdot 2.0) $$

**Pseudocode:**
```python
def cube_world_stylized_shading(c_base, v_ao, u_enable, u_mult, u_curve, c_tint, u_mid_mix, u_occ_mix, u_mid_dark, u_occ_dark):
    # Step 1: Clamp and Scale AO
    v_ao_prime = clamp(v_ao * u_mult, 0.0, 1.0)
    
    # Step 2: Apply Contrast Curve
    v_ao_double_prime = pow(v_ao_prime, u_curve)
    
    # Step 3: Check Stylization Toggle
    if u_enable < 0.5:
        return c_base * v_ao_double_prime
    
    # Step 4: Calculate Mid-Shadow Color
    # c_base * u_mid_dark is the darkened base
    # c_base * c_tint is the tinted base
    c_mid = mix(c_base * u_mid_dark, c_base * c_tint, u_mid_mix)
    
    # Step 5: Calculate Occluded-Shadow Color
    c_occ = mix(c_base * u_occ_dark, c_base * c_tint, u_occ_mix)
    
    # Step 6: Interpolate Based on AO
    if v_ao_double_prime >= 0.5:
        # Interpolate between mid-shadow and exposed (base color)
        t = (v_ao_double_prime - 0.5) * 2.0
        c_final = mix(c_mid, c_base, t)
    else:
        # Interpolate between occluded-shadow and mid-shadow
        t = v_ao_double_prime * 2.0
        c_final = mix(c_occ, c_mid, t)
        
    return c_final
```

**Edge Cases and Pitfalls:**
- **Precision:** The use of `pow` and `mix` requires standard floating-point precision. No specific bit-packing is mentioned.
- **Boundaries:** The AO value is clamped to $[0, 1]$ at the start. The interpolation factors are derived from linear mappings of the $[0, 1]$ range to $[0, 1]$, ensuring valid weights.
- **Degenerate Input:** If $u_{curve} = 0$, $v_{AO}''$ becomes 1.0 (if $v_{AO}' > 0$) or 1.0 (if $0^0=1$). This results in the fully occluded color. If $u_{mult} = 0$, $v_{AO}'' = 0$, resulting in the occluded color.

## Operating characteristics
- **Time Complexity:** $O(1)$ per fragment. The computation involves a constant number of arithmetic operations, clamps, and mixings.
- **Memory Complexity:** $O(1)$ additional memory per fragment, storing only intermediate scalar and vector values.
- **Measured Performance:** Not given in the sources.
- **Scaling:** The method scales linearly with the number of fragments. It is highly efficient for real-time rendering.
- **Strengths:** Produces a distinct, stylized aesthetic with clear shadow bands. Simple to implement and fast.
- **Limitations:** Relies on pre-computed or ray-marched AO. The aesthetic is specific to the *Cube World* style and may not suit all artistic directions.
- **When to use:** When replicating the *Cube World* aesthetic is desired.
- **When not to use:** When physically accurate lighting or smooth gradients are required.

## Background
The method originates from the game *Cube World* [S1, unofficial]. It was reverse-engineered and implemented in JavaScript/Three.js by RainArcanjo in the repository `CubWrldJS` [S1, unofficial]. The technique is notable for its use of multi-band AO interpolation to achieve a specific visual style distinct from standard PBR or basic lighting models.
