# Brick Map Geometric Primitive Shading

Also called: Shaded brick map geometric primitive

## Overview
Brick Map Geometric Primitive Shading applies surface shaders to the coarse, voxel-based approximation of a surface defined by a brick map [S1]. It solves the problem of rendering complex geometry stored in brick maps with standard surface materials (e.g., plastic, matte) or procedural patterns, distinct from the raw unshaded appearance [S1]. Unlike [Custom Shading Models](3660-custom-shading-models.md) which may rely on precise analytical normals, this method operates on a discrete voxel structure where the surface is an approximation, requiring specific handling for ray-tracing biases and baked parameters [S1].

## How it works
**Inputs and Outputs:**
*   **Input:** A brick map file (`.bkm`) containing geometric primitives, and a surface shader definition (e.g., `paintedplastic`, `matte`, or custom procedural shaders) [S1].
*   **Output:** A rendered image where the brick map geometry is colored and shaded according to the applied shader [S1].

**Data Structures:**
The brick map data structure stores geometric primitives as voxels. Surface parameters required by the shader, such as surface coordinates $(s,t)$, $(u,v)$, or point references ($P_{ref}$), must be pre-computed and baked into the brick map data during its creation, similar to how position ($P$), normal ($N$), color ($C_s$), and opacity ($O_s$) are baked [S1].

**Steps:**
1.  **Shader Selection:** Define or select a surface shader compatible with the renderer (e.g., RenderMan shading language) [S1].
2.  **Geometry Application:** Associate the shader with the `brickmap` geometry primitive in the scene description (e.g., RIB file) [S1].
3.  **Parameter Baking:** Ensure any shader-dependent parameters (like texture coordinates) are baked into the brick map file if the shader does not compute them from global position $P$ [S1].
4.  **Ray Tracing Setup:** Set the ray tracing bias attribute to a high value to mitigate self-intersection artifacts caused by the coarse voxel approximation [S1].
5.  **Shading Execution:** The renderer evaluates the shader at shading points on the brick map surface [S1].

**Formulas and Logic:**
For a procedural checkerboard shader based on position $P$:
$$ x = \text{frequency} \times \text{xcomp}(P) $$
$$ x = x - \lfloor x \rfloor $$
$$ y = \text{frequency} \times \text{ycomp}(P) $$
$$ y = y - \lfloor y \rfloor $$
$$ c_x = \begin{cases} 1 & \text{if } x > 0.5 \\ 0 & \text{otherwise} \end{cases} $$
$$ c_y = \begin{cases} 1 & \text{if } y > 0.5 \\ 0 & \text{otherwise} \end{cases} $$
$$ C_i = \begin{cases} 1 & \text{if } c_x == c_y \\ \text{color}(1,0,0) & \text{otherwise} \end{cases} $$
$$ O_i = 1 $$
Where $C_i$ is the output color and $O_i$ is the output opacity [S1].

**Parameters:**
*   **Ray Tracing Bias:** Must be set high (e.g., `0.1`) to avoid "surface acne" (false self-intersections) [S1].
*   **Frequency:** Controls the density of procedural patterns (e.g., checkerboard) [S1].

**Pitfalls:**
*   **Surface Acne:** Because brick voxels are a coarse approximation of the true surface, ray tracing bias must be high to prevent false self-intersections. Finding the proper value is a general problem for this primitive [S1].
*   **Performance:** Ray-traced ambient occlusion and indirect diffuse illumination are slow because no information is shared between shading points (the `maxvariation` attribute is ignored) [S1].
*   **Overhead:** Running a constant shader on a brick map produces the same visual result as no shader but takes longer due to shader setup overhead [S1].

**Pseudocode:**
```python
# Example Checkerboard Shader Logic
def shader_checkerxy(P, frequency=1.0):
    # Extract x and y components of position P
    x = frequency * P.x
    y = frequency * P.y
    
    # Wrap to [0, 1) range
    x = x - floor(x)
    y = y - floor(y)
    
    # Determine checkerboard cell
    cx = 1 if x > 0.5 else 0
    cy = 1 if y > 0.5 else 0
    
    # Assign color
    if cx == cy:
        Ci = color(1, 1, 1) # White
    else:
        Ci = color(1, 0, 0) # Red
        
    Oi = 1.0
    return Ci, Oi
```

## Subtopics

### Brick Map Displacement Shading
Applies displacement to the brick map geometry using a displacement shader (e.g., `xydisp`) specified via the `Displacement` attribute in the RIB file [S1]. The shader transforms $P$ to object space, calculates displacement magnitude (e.g., using sine of the y-component), displaces $P$ along an axis, and recalculates the normal $N$ [S1]. **Pitfalls:** Discontinuous displacements result in "torn" geometry (holes) [S1]. Ray tracing of displaced brick maps is not implemented; displacement is ignored for ray-traced shadows/reflections, though it works for directly visible surfaces [S1].

### Brick Map Opacity/Transparency Shading
Uses a shader to define transparency patterns (e.g., checkered transparency) based on position $P$ [S1]. If the pattern condition is met, $O_i$ is set to 0 (transparent); otherwise, it is 1 (opaque) [S1]. **Pitfall:** Semitransparent voxels can appear too opaque because each surface point can be stored in up to eight voxels (data stored two voxels deep). When alpha-composited, this results in excessive opacity [S1].

## Operating characteristics
*   **Time Complexity:** Shading is slower than unshaded rendering due to shader setup overhead [S1]. Ray-traced ambient occlusion and indirect diffuse illumination are particularly slow because information is not shared between shading points [S1].
*   **Memory:** Depends on the brick map size and baked parameters [S1].
*   **Strengths:** Allows standard surface shaders to be applied to brick map geometry [S1].
*   **Limitations:** Coarse voxel approximation requires high ray tracing bias to avoid artifacts [S1]. Displacement shading does not support ray tracing [S1]. Transparency can suffer from over-accumulation due to voxel storage redundancy [S1].
*   **When to use:** When standard surface materials are needed for brick map geometry and ray-traced shadows/reflections are not critical for the displaced or transparent parts.
*   **When not to use:** When high-performance ray-traced ambient occlusion or accurate displacement-based ray tracing is required.

## Background
The brick map geometric primitive is a technique for representing complex geometry as a collection of voxels, originally described in the context of the RenderMan Shading Language and RIB file format [S1]. It allows for the compression and efficient storage of detailed surfaces, which can then be shaded using standard surface shaders [S1].
