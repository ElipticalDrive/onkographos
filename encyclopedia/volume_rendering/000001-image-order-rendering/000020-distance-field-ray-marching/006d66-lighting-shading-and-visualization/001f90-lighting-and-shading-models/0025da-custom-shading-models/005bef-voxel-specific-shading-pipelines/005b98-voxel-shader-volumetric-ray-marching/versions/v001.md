# Voxel Shader Volumetric Ray Marching

Also called: Phoenix Volumetric Rendering, V-Ray Volume Grid Shading

## Overview
The Voxel Shader Volumetric Ray Marching method is a shading technique for Fire/Smoke simulations and meshes that reads voxel grid data from a Phoenix Simulator or V-Ray Volume Grid [S1]. It solves the problem of shading volumetric data in Maya, where standard Maya materials cannot be applied because volumetrics lack explicit surfaces [S1]. It sets itself apart from its siblings by providing specific rollouts for Fire, Smoke Color, and Smoke Opacity, handling volumetric shading directly via grid data rather than converting to geometry or using generic surface shaders [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Voxel grid data (Temperature, Smoke, Speed, Fuel, Velocity, etc.), camera position, light positions, and shader parameters (Step %, Sampler Type, Surface Channel, etc.) [S1].
*   **Outputs:** Shaded pixel color, alpha, and optionally Render Elements (Normals, Velocity, Material ID, Z-Depth) [S1].

**Data Structures:**
*   **Voxel Grid:** A 3D array of cells. Each cell contains values for various channels (e.g., Temperature, Smoke, Speed) [S1].
*   **Velocity Texture:** A custom 3D texture where colors represent velocity direction per cell (Y/Z components flipped to Blue/Green channels) [S1].

**Numbered Steps:**

1.  **Ray Initialization:** For each pixel, cast a camera ray into the scene [S1].
2.  **Cutter Check (Optional):** If `rendUseGizmo` is enabled, check if the ray intersects the Render Cutter volume. If `rendInvGizmo` is enabled, shade rays not intersecting the cutter. If `geommode` is enabled, rendering is restricted to the cutter volume [S1].
3.  **Ray Marching Loop:**
    *   Determine the step size: `step_size = cell_size * (rendstep / 100.0)` [S1].
    *   If `rendstep > 100`, cells are skipped, causing artifacts [S1].
    *   If `rendstep < 90`, more samples are taken, increasing render time but capturing details smaller than a voxel [S1].
    *   For each step along the ray:
        *   Sample the voxel grid at the current position using the selected `sampler` type (Box, Linear, or Spherical) [S1].
        *   **Box:** No blending, voxels as cubes [S1].
        *   **Linear:** Linear blending between neighbor voxels, 20-30% faster than Spherical, may unveil grid structure [S1].
        *   **Spherical:** Weight-based sampling, smoothest look [S1].
        *   Apply **Border Fade:** If the sample position is within `borderFade` distance from grid boundaries, multiply the result by a transparency factor to prevent sharp edges [S1].
        *   Accumulate color and opacity based on the current shading mode (Fire, Smoke, etc.) [S1].
4.  **Lighting and Shadowing:**
    *   Cast shadow rays to light sources.
    *   Determine shadow step size: `shadow_step = cell_size * (rendshadstep / 100.0)` [S1].
    *   `rendshadstep` is typically higher than `rendstep` as shadows require less detail [S1].
    *   Sample the grid along the shadow ray to determine occlusion [S1].
5.  **Shading Computation:**
    *   **Fire Emission:** Based on `emSource` (Temperature, Smoke, Speed, Fuel, Texture, RGB, Disabled) [S1]. If `emModulate` is enabled, multiply by `emTexture` [S1].
    *   **Fire Opacity:** Based on `emIgnoreAlpha` mode:
        *   `Use Smoke Opacity`: Fire uses smoke opacity, invisible where no smoke [S1].
        *   `Fully Visible`: Full opacity, no alpha, additive blending for compositing [S1].
        *   `Use Own Opacity`: Custom opacity via diagram/texture [S1].
    *   **Smoke Color:** Based on `difSource` (Temperature, Smoke, Speed, Texture, Constant Color, RGB, Fuel, Disabled) [S1]. If `difModulate` is enabled, multiply by `difTexture` [S1].
    *   **Scattering:** Based on `difScattering` mode:
        *   `Ray-traced (GI only)`: Physically accurate, slowest, requires GI [S1].
        *   `Disabled`: No scattering, darker result [S1].
        *   `Approximate`: Approximate scattering [S1].
6.  **Motion Blur (Optional):**
    *   If `volMoblurMethod` is `Ray-traced`, use standard ray-traced motion blur [S1].
    *   If `volMoblurMethod` is `Grid-based`, use a pre-pass method requiring more memory, producing more visible streaks for fast fluids [S1].
    *   If `rendVelTexture` is set, use the velocity texture to stretch simulator contents along the direction vector, overriding the Velocity grid channel [S1].
    *   Apply `mbmult` multiplier to motion blur strength [S1].
7.  **Surface Rendering (Optional):**
    *   If `geommode` is enabled, render as procedural geometry (multiple transparent layers) [S1].
    *   Determine surface using `sarg` channel (Texture, Liquid/Temperature, Smoke, Speed, Fuel, Viscosity) [S1].
    *   Generate isosurface using `rendSurfLevel_x/t/s/v/f` threshold (default 0.5) [S1].
    *   Apply displacement using `rendDispl` and `rendDisplFine` with `rendDispltSurf` type (Gradient driven, Surface driven, Vector, Advection) [S1].
8.  **Heat Haze (Optional):**
    *   If `rendHeatHaze` > 0, trace the ray changing direction according to the gradient of the Surface channel [S1].
    *   Value 1 approximates normal heat haze; larger values needed if smoke/other channel is source [S1].
9.  **Output:** Combine accumulated color, apply alpha, and write to Render Elements if enabled (Material ID, Z-Depth) [S1].

**Parameters with Typical Values:**
*   `rendstep`: >=90% [S1].
*   `rendshadstep`: Higher than `rendstep` [S1].
*   `rendSurfLevel`: 0.5 [S1].
*   `rendHeatHaze`: 1.0 for normal heat haze [S1].
*   `mbmult`: Can be negative [S1].

**Edge Cases and Pitfalls:**
*   `rendstep > 100`: Causes artifacts due to skipped cells [S1].
*   `rendstep < 90`: Increases render time significantly [S1].
*   `geommode` with `rendUseGizmo`: Render Cutter does not work with Render as Geometry [S1].
*   `volMoblurMethod` Grid-based: Only affects Volumetric, Volumetric Geometry, and Volumetric Heat Haze Modes [S1].
*   `difScattering` Ray-traced: Requires V-Ray with Global Illumination enabled, otherwise same as Disabled [S1].
*   `rendVelTexture`: Y/Z components are flipped (Blue/Green channels) [S1].

## Subtopics

### Smoke Color Mapping
Smoke Color Mapping determines the diffuse color of the smoke volume. It requires external light to become visible if GI is enabled in V-Ray Render Settings [S1]. The color can be based on various cache channels (Temperature, Smoke, Speed, Fuel, RGB) or a texture map, remapped using a color gradient [S1]. If `difModulate` is enabled, the color is multiplied by a texture [S1]. The `difScattering` parameter controls how light rays are scattered inside the volume, with options for Ray-traced (physically accurate, slow), Disabled (no scattering), and Approximate [S1].

## Operating characteristics
*   **Time Complexity:** Depends on `rendstep` and `rendshadstep`. Lower step sizes increase render time [S1]. `difScattering` Ray-traced mode is the slowest [S1]. `geommode` slows down rendering [S1].
*   **Memory Complexity:** Grid-based motion blur requires more memory and a pre-pass [S1].
*   **Measured Performance:** Linear sampler is 20-30% faster than Spherical [S1]. Increasing `rendshadstep` speeds up rendering, especially with dome and area lights [S1].
*   **Strengths:** Handles volumetric shading directly without converting to geometry. Provides specific controls for Fire and Smoke. Supports various displacement and motion blur methods [S1].
*   **Limitations:** Standard Maya materials cannot be used for volumetrics. `geommode` is slow and V-Ray only. Grid-based motion blur is memory-intensive [S1].
*   **When to Use:** For shading Fire/Smoke simulations in Maya using Phoenix or V-Ray Volume Grids.
*   **When Not to Use:** When standard Maya materials are required, or when performance is critical and volumetric detail is low (use Box sampler or higher step sizes).

## Background
The Voxel Shader Volumetric Ray Marching method is part of the Phoenix FD plugin for Maya, developed by Chaos Group [S1]. It was introduced to provide a dedicated shading solution for volumetric simulations, as standard Maya materials could not handle volumetric data [S1]. The method supports various rendering modes and parameters to control the appearance of fire and smoke, including emission, opacity, color, and displacement [S1].
