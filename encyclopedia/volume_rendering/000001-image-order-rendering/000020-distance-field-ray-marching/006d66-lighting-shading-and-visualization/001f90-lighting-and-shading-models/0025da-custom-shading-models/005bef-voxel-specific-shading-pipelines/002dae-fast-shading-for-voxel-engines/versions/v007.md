# Fast Shading for Voxel Engines


## Overview
Fast Shading for Voxel Engines (fast_shade2) is a CPU-based lighting algorithm for voxel engines that simulates directional sunlight by modifying voxel palette indices [S1, unofficial]. It operates by checking immediate neighbors to determine shading factors, assuming vertical sun rays [S1, unofficial]. Unlike [Voxel Shading Pipeline](3898-voxel-shading-pipeline.md) which may use more complex geometric calculations, or [Voxel Shader Volumetric Ray Marching](16930-voxel-shader-volumetric-ray-marching.md) which relies on GPU ray marching, fast_shade2 is optimized for pure CPU rendering by using simple integer arithmetic and palette index clamping [S1, unofficial]. It is faster but less visually detailed than its sibling [fast_shade1](5608-fast-shade1.md), which uses fewer neighbor checks [S1, unofficial].

## How it works
**Inputs:** A 3D voxel grid of dimensions $xsize \times ysize \times zsize$, where each voxel stores a palette index.
**Outputs:** The same voxel grid with modified palette indices representing shaded lighting.

**Data Structures:**
- `voxel_grid`: A 3D array or flattened buffer of integers.
- `get_voxel_pal(x, y, z)`: Returns the palette index at coordinates $(x, y, z)$.
- `set_voxel_pal(x, y, z, val)`: Sets the palette index at coordinates $(x, y, z)$ to `val`.
- Palette indices are grouped into tone groups of 32. Indices 1-32 represent the first dark-to-light gradient, 33-64 the next, etc. Index 0 represents empty space.

**Parameters:**
- $xsize, ysize, zsize$: Integer dimensions of the voxel level.

**Algorithm Steps:**
1. Iterate through all interior voxels: $x$ from 1 to $xsize-2$, $y$ from 1 to $ysize-2$, $z$ from 1 to $zsize-2$ [S1, unofficial].
2. Retrieve the current voxel's palette index: $v = \text{get\_voxel\_pal}(x, y, z)$ [S1, unofficial].
3. If $v == 0$ (empty), skip to the next voxel [S1, unofficial].
4. Calculate the lower bound (color margin) for the current tone group:
   $$ \text{color\_margin} = \left\lfloor \frac{v - 1}{32} \right\rfloor \times 32 + 1 $$
   [S1, unofficial]
5. Initialize a shading offset $offset = 0$ [G].
6. Check neighbors and subtract from the potential new index based on occupancy:
   - If $(x, y+1, z)$ is occupied (index $\neq 0$), subtract 3 from $offset$ [S1, unofficial].
   - If $(x+1, y+1, z)$, $(x-1, y+1, z)$, $(x+1, y+1, z+1)$, or $(x+1, y+1, z-1)$ is occupied, subtract 2 from $offset$ [S1, unofficial].
   - If $(x+1, y, z+1)$, $(x-1, y, z-1)$, $(x+1, y, z-1)$, or $(x-1, y, z+1)$ is occupied, subtract 1 from $offset$ [S1, unofficial].
   *Note: The source describes "subtracting values" based on neighbors. The logic implies that occupied neighbors reduce the brightness (index). The total reduction is the sum of these subtractions.*
7. Calculate the new index: $v_{new} = v - offset$ [G].
8. Clamp the new index to the tone group lower bound:
   If $v_{new} < \text{color\_margin}$, set $v_{new} = \text{color\_margin}$ [S1, unofficial].
9. Write the result: $\text{set\_voxel\_pal}(x, y, z, v_{new})$ [S1, unofficial].

**Pseudocode:**
```python
import math

def fast_shade2(voxel_grid, xsize, ysize, zsize):
    """
    Applies fast shading to a voxel grid.
    voxel_grid: 3D list or flattened array supporting get/set via helper functions.
    """
    # Helper functions assumed to be defined elsewhere or implemented as accessors
    # get_voxel_pal(x, y, z) -> int
    # set_voxel_pal(x, y, z, val) -> None
    
    for x in range(1, xsize - 1):
        for y in range(1, ysize - 1):
            for z in range(1, zsize - 1):
                voxel = get_voxel_pal(x, y, z)
                
                # Skip empty voxels
                if voxel == 0:
                    continue
                
                # Calculate tone group lower bound
                color_margin = math.floor((voxel - 1) / 32) * 32 + 1
                
                offset = 0
                
                # Check neighbors and accumulate shading
                # Subtract 3 if (x, y+1, z) is occupied
                if get_voxel_pal(x, y + 1, z) != 0:
                    offset += 3
                
                # Subtract 2 if specific neighbors are occupied
                neighbors_2 = [
                    (x + 1, y + 1, z),
                    (x - 1, y + 1, z),
                    (x + 1, y + 1, z + 1),
                    (x + 1, y + 1, z - 1)
                ]
                for nx, ny, nz in neighbors_2:
                    if get_voxel_pal(nx, ny, nz) != 0:
                        offset += 2
                
                # Subtract 1 if specific neighbors are occupied
                neighbors_1 = [
                    (x + 1, y, z + 1),
                    (x - 1, y, z - 1),
                    (x + 1, y, z - 1),
                    (x - 1, y, z + 1)
                ]
                for nx, ny, nz in neighbors_1:
                    if get_voxel_pal(nx, ny, nz) != 0:
                        offset += 1
                
                # Apply shading
                new_voxel = voxel - offset
                
                # Clamp to tone group lower bound
                if new_voxel < color_margin:
                    new_voxel = color_margin
                
                set_voxel_pal(x, y, z, new_voxel)
```

## Subtopics

### [fast_shade1](5608-fast-shade1.md)
A variant that assumes vertical sun rays and uses fewer neighbor checks (only checking immediate vertical/horizontal adjacency for shading). It is faster but provides less visual detail than fast_shade2. Choose it when performance is critical and lighting complexity is low.

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels, as each interior voxel is visited once. The constant factor depends on the number of neighbor checks (13 checks per voxel).
- **Memory Complexity:** $O(1)$ auxiliary space, as it modifies the grid in-place.
- **Performance:** Optimized for CPU-only rendering environments [S1, unofficial]. It avoids the overhead of GPU shaders or complex ray marching.
- **Strengths:** Extremely fast, simple to implement, no floating-point arithmetic required (uses integer palette indices).
- **Limitations:** Lighting is discrete and palette-dependent, not continuous. It assumes a fixed vertical sun direction [S1, unofficial]. It does not handle shadows from distant objects or complex light sources.
- **When to use:** CPU-based voxel engines where real-time performance is critical and lighting requirements are simple (e.g., basic day/night cycles or static sun).
- **When not to use:** When dynamic lighting, shadows, or realistic illumination is required.

## Background
Fast Shading for Voxel Engines was developed as part of the DOOMMY voxel engine, a project by jabberx (jabberx@ymail.com) released in 2012 [S1, unofficial]. The engine is designed to use only the CPU for rendering and Lua for scripting [S1, unofficial]. The algorithm was created to provide efficient lighting for voxel-based games without relying on GPU acceleration.
