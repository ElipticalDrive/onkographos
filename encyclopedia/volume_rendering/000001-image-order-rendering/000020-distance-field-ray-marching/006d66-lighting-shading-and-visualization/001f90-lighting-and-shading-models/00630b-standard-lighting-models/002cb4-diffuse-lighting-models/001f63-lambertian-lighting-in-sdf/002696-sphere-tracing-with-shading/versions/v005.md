# Sphere Tracing with Shading

Also called: Sphere Tracing with Shading | ronja-tutorials/ShaderTutorials

## Overview
Sphere Tracing with Shading is a shading extension of the sphere tracing system that derives surface normals from the SDF using finite differences, calculates diffuse lighting in world space, and combines a base color with computed light [S1, unofficial]. It extends basic sphere tracing by estimating surface normals via finite differences and applying a Lambertian lighting model in world space [S1, unofficial]. Unlike [Sphere Tracing Basics](52-sphere-tracing-basics.md), which returns a flat base color, this method calculates per-pixel lighting intensity based on the angle between the surface normal and the light direction [S1, unofficial]. It builds on [Lambertian Lighting in SDF](2023-lambertian-lighting-in-sdf.md) by providing the specific implementation details for normal estimation and integration within the Unity shader pipeline [S1, unofficial].

## How it works
The method operates within a fragment shader that performs ray marching [S1, unofficial]. It differs from the basic version only in the output calculation upon a successful hit; the traversal loop remains identical [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- `localPosition`: The local-space position of the vertex on the proxy mesh [S1, unofficial].
- `viewDirection`: The view vector in local space [S1, unofficial].
- `_Color`: A `float4` representing the object's base diffuse color [S1, unofficial].
- `_LightColor0`: A `float4` representing the main directional light's color and intensity (provided by `Lighting.cginc`) [S1, unofficial].
- `_WorldSpaceLightPos0`: A `float4` where `.xyz` is the light direction for a directional light [S1, unofficial].

**Outputs:**
- `fragColor`: The final `float4` color with alpha [S1, unofficial].

### Data Structures and Constants
The shader defines three compile-time constants that control precision and performance [S1, unofficial]:

| Constant | Type | Value | Role |
|---|---|---|---|
| `MAX_STEPS` | `int` | 10 | Maximum ray marching iterations [S1, unofficial]. |
| `THICKNESS` | `float` | 0.01 | SDF distance threshold for a surface hit [S1, unofficial]. |
| `NORMAL_EPSILON` | `float` | 0.01 | Offset distance used in finite-difference normal sampling [S1, unofficial]. |

The scene is defined by the SDF function `scene(pos)`, which returns the signed distance from a point `pos` to a unit sphere of radius 0.5 centered at the origin [S1, unofficial]:
$$ \text{scene}(pos) = \|pos\| - 0.5 $$

### Algorithm Steps

1.  **Ray Initialization**:
    Construct the ray origin `pos` from the vertex's local position and the ray direction `dir` from the normalized view direction [S1, unofficial]. Initialize `progress` to 0 [S1, unofficial].

2.  **Ray Marching Loop**:
    Iterate `iter` from 0 to `MAX_STEPS` [S1, unofficial]:
    a. Calculate the sample point: `samplePoint = pos + dir * progress` [S1, unofficial].
    b. Evaluate the SDF: `distance = scene(samplePoint)` [S1, unofficial].
    c. **Hit Test**: If `distance < THICKNESS`, the ray has intersected the surface [S1, unofficial]. Proceed to **Shading**.
    d. **Advance**: Update `progress += distance` [S1, unofficial].
    e. **Miss Test**: If `iter` exceeds `MAX_STEPS`, discard the fragment (return transparent/black) [S1, unofficial].

3.  **Shading (on hit)**:
    a. **Normal Estimation**: Compute the surface normal using central finite differences in local space, then transform to world space [S1, unofficial].
    b. **Lighting Calculation**: Compute the Lambertian diffuse term using the world-space normal and world-space light direction [S1, unofficial].
    c. **Material Composition**: Multiply the base color by the lighting intensity [S1, unofficial].

### Normal Estimation
The surface normal is the normalized gradient of the SDF [S1, unofficial]. Since the SDF is analytic, the gradient is approximated using central differences with offset `NORMAL_EPSILON` ($\epsilon$) [S1, unofficial].

1.  Compute changes in local space:
    $$ \Delta_x = \text{scene}(pos + (\epsilon, 0, 0)) - \text{scene}(pos - (\epsilon, 0, 0)) $$
    $$ \Delta_y = \text{scene}(pos + (0, \epsilon, 0)) - \text{scene}(pos - (0, \epsilon, 0)) $$
    $$ \Delta_z = \text{scene}(pos + (0, 0, \epsilon)) - \text{scene}(pos - (0, 0, \epsilon)) $$
    
    Let $g_{local} = (\Delta_x, \Delta_y, \Delta_z)$ [S1, unofficial].

2.  Transform to world space. The gradient is a direction vector, so the translation component of the transformation matrix must be excluded ($w=0$) [S1, unofficial].
    $$ g_{world} = \text{normalize}\left( \text{mul}(\text{unity\_ObjectToWorld}, (g_{local}.x, g_{local}.y, g_{local}.z, 0)) \right) $$

### Lighting Calculation
The diffuse lighting intensity is computed in world space [S1, unofficial].

1.  Retrieve the light direction $L$ from `_WorldSpaceLightPos0.xyz` [S1, unofficial].
2.  Compute the dot product of the world-space normal $N = g_{world}$ and the light direction $L$:
    $$ \text{diffuseIntensity} = \max(0, N \cdot L) $$
    This is implemented as `saturate(dot(surfaceNormal, lightDirection))` [S1, unofficial].
3.  Compute the final lighting contribution:
    $$ \text{lightColor} = \text{diffuseIntensity} \times \text{_LightColor0.rgb} $$

### Material Composition
The final color is the product of the object's base color and the computed lighting [S1, unofficial]:
$$ \text{output} = \text{_Color.rgb} \times \text{lightColor} $$

### Pseudocode
```python
import math

# Standard vector operations
def add3(a, b): return (a[0]+b[0], a[1]+b[1], a[2]+b[2])
def sub3(a, b): return (a[0]-b[0], a[1]-b[1], a[2]-b[2])
def scale3(v, s): return (v[0]*s, v[1]*s, v[2]*s)
def dot3(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def length3(v): return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
def normalize3(v):
    l = length3(v)
    return (v[0]/l, v[1]/l, v[2]/l) if l > 0 else (0, 0, 0)
def transform_dir(M, v): # M is 4x4 matrix, v is vec4 (x,y,z,0)
    return (M[0][0]*v[0] + M[0][1]*v[1] + M[0][2]*v[2],
            M[1][0]*v[0] + M[1][1]*v[1] + M[1][2]*v[2],
            M[2][0]*v[0] + M[2][1]*v[1] + M[2][2]*v[2])
def saturate(x): return max(0.0, min(1.0, x))

MAX_STEPS = 10
THICKNESS = 0.01
NORMAL_EPSILON = 0.01

def scene(pos):
    return length3(pos) - 0.5

def get_normal(pos):
    eps_x = (NORMAL_EPSILON, 0, 0)
    eps_y = (0, NORMAL_EPSILON, 0)
    eps_z = (0, 0, NORMAL_EPSILON)
    dx = scene(add3(pos, eps_x)) - scene(sub3(pos, eps_x))
    dy = scene(add3(pos, eps_y)) - scene(sub3(pos, eps_y))
    dz = scene(add3(pos, eps_z)) - scene(sub3(pos, eps_z))
    grad_local = (dx, dy, dz)
    # Transform to world space (direction vector, w=0)
    grad_world = transform_dir(unity_ObjectToWorld, (grad_local[0], grad_local[1], grad_local[2], 0))
    return normalize3(grad_world)

def light_color(position):
    normal = get_normal(position)
    light_dir = _WorldSpaceLightPos0[:3]
    diffuse = saturate(dot3(normal, light_dir))
    return diffuse * _LightColor0[:3]

def frag(v2f_input):
    pos = v2f_input.localPosition
    dir = normalize3(v2f_input.viewDirection)
    progress = 0.0
    for step in range(MAX_STEPS):
        sample_point = add3(pos, scale3(dir, progress))
        distance = scene(sample_point)
        if distance < THICKNESS:
            return scale3(_Color, light_color(sample_point))
        progress += distance
    return (0.0, 0.0, 0.0, 0.0)
```

### Parameters and Edge Cases
- **`NORMAL_EPSILON`**: A value of 0.01 is used [S1, unofficial]. If too small, precision errors may cause noisy normals; if too large, the normal approximation becomes inaccurate for high-curvature areas [S1, unofficial].
- **`THICKNESS`**: A value of 0.01 defines the hit threshold [S1, unofficial]. It must be larger than the numerical precision errors of the SDF evaluation but small enough to avoid visible gaps [S1, unofficial].
- **Batching**: Static and dynamic batching must be disabled (`DisableBatching="True"`) [S1, unofficial]. The vertex shader relies on `unity_WorldToObject`, which is only valid per-object and breaks when multiple objects are batched into a single draw call [S1, unofficial].
- **Depth Buffer**: The shader must use `Queue="Transparent"` and `ZWrite Off` [S1, unofficial]. Sphere-traced geometry does not write correct hardware depth values [S1, unofficial]. Placing it in the transparent queue prevents it from incorrectly occluding rasterized geometry or being occluded by it based on the proxy mesh's depth [S1, unofficial].

## Subtopics

### Local Shading with Smooth Mirrors
A shading technique for Kernel-Reflection Sequences (KRS) that uses surface normals derived from the gradient of distance functions, with a smoothing method for discontinuities at mirror planes [S2]. It computes the shading normal using the gradient of the distance function at the sphere-traced surface point and performs lighting computation in either world space or kernel space [S2]. If computing in world space, the transformation matrix for the complete chain must be maintained throughout the iteration to transform kernel gradients to world space [S2]. Discontinuities are smoothed by interpolating between the kernel-to-world-space matrices on the two sides of a mirror when the shaded point is found near a mirror plane during iteration [S2]. The shading algorithm runs only once, after sphere tracing has found the intersection point [S2]. A key pitfall is visible discontinuity of surface normals where the plane of reflection intersects the mirrored geometry if kernel separation is not upheld [S2].

## Operating characteristics
- **Time Complexity**: $O(N)$, where $N$ is the number of ray marching steps (bounded by `MAX_STEPS`) [G]. Each step involves one SDF evaluation [G]. Normal estimation adds 6 additional SDF evaluations per hit pixel [G].
- **Memory Complexity**: $O(1)$ auxiliary memory [G]. No large textures or buffers are required beyond standard shader registers [G].
