# Phong Shading with Boundary Enhancement and Facing Subtraction

Also called: Boundary-enhanced volume shading, Gradient-based Phong shading

## Overview
This method implements per-fragment Phong lighting for volume rendering using precomputed scalar field gradients, applying boundary enhancement via absorption approximation and facing subtraction for silhouette enhancement [S1, unofficial]. It distinguishes itself from standard gradient-based Phong shading by explicitly modulating fragment alpha based on gradient magnitude and the view direction relative to the surface normal [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D texture `tex3D` containing precomputed gradient components ($g_x, g_y, g_z$) and magnitude ($||g||$), plus a 1D transfer function texture `tex1D` mapping scalar values to color and alpha [S1, unofficial].
*   **Output:** A fragment color and alpha value [S1, unofficial].

**Data Structures:**
The source defines uniform structures for lighting and rendering parameters [S1, unofficial]:
*   `light_t`: Contains coefficients `kd` (diffuse), `ks` (specular), `ka` (ambient) [S1, unofficial].
*   `rendering_t` (or `myRender`): Contains integer flags `boundary` and `facing` [S1, unofficial].
*   `Gradient_t`: Contains fields `x`, `y`, `z`, and `magnitude` of type float [S1, unofficial].
*   Varyings: `L` (light vector), `E` (eye vector) [S1, unofficial].

**Numbered Steps:**
1.  **Gradient Extraction:** Sample the 3D texture at the current fragment's position to retrieve the gradient vector components $(g_x, g_y, g_z)$ and the precomputed magnitude $||g||$ [S1, unofficial].
2.  **Normal Computation:** Normalize the gradient vector to obtain the surface normal $\mathbf{n}$:
    $$ \mathbf{n} = \frac{(g_x, g_y, g_z)}{||(g_x, g_y, g_z)||} $$
3.  **Coordinate Transformation:** Transform the normal $\mathbf{n}$ into view space using the model-view matrix [S1, unofficial]. The vertex shader computes the eye vector $\mathbf{E} = \text{normalize}(-\text{vertexPos})$ and light vector $\mathbf{L} = (0,0,-1)$ in view space and passes them as varyings [S1, unofficial].
4.  **Lighting Calculation:**
    *   Compute the diffuse term $D = \max(\mathbf{n} \cdot \mathbf{L}, 0)$ [S1, unofficial].
    *   Compute the reflection vector $\mathbf{r} = \text{reflect}(-\mathbf{L}, \mathbf{n})$ [S1, unofficial].
    *   Compute the specular term $S = \max(\mathbf{r} \cdot \mathbf{n}, 0)^{512}$ [S1, unofficial].
    *   Compute the ambient term $A = \text{TF}(t)$ by sampling the 1D transfer function at the scalar value [S1, unofficial].
    *   Combine terms to get the initial color contribution: $C = k_s S + k_d D + k_a A$ [S1, unofficial].
5.  **Boundary Enhancement:** If the `boundary` flag is enabled, modify the fragment alpha $\alpha$ using an absorption approximation based on the gradient magnitude:
    $$ \alpha' = \alpha (1 - e^{-||g||}) $$
    This step enhances the visibility of boundaries where the gradient magnitude is high [S1, unofficial].
6.  **Facing Subtraction:** If the `facing` flag is enabled, further modify the alpha by subtracting the facing component relative to the view vector $\mathbf{v}$:
    $$ \alpha'' = \alpha' (1 - |\mathbf{n} \cdot \mathbf{v}|) $$
    The source formula specifies the absolute value for silhouette symmetry, while the provided code snippet implements $\alpha' (1 - \mathbf{n} \cdot \mathbf{v})$ [S1, unofficial].

**Pseudocode:**
```python
def sample_1d_texture(tex, coord):
    return tex[coord]

def phong_shading_fragment(gradient_tex, tf_tex, scalar_value, normal, eye_vector, light_vector, kd, ks, ka, boundary, facing):
    # 1. Lighting Calculation
    diffuse = max(dot(normal, light_vector), 0.0)
    reflection = reflect(-light_vector, normal)
    specular = pow(max(dot(reflection, normal), 0.0), 512.0)
    tf_sample = sample_1d_texture(tf_tex, scalar_value)
    ambient = tf_sample
    color = ks * specular + kd * diffuse + ka * ambient
    alpha = tf_sample.a

    # 2. Boundary Enhancement
    gradient_magnitude = gradient_tex.magnitude
    if boundary > 0:
        alpha = alpha * (1.0 - exp(-gradient_magnitude))

    # 3. Facing Subtraction
    ndotv = dot(normal, eye_vector)
    if facing > 0:
        # Formula specifies |n·v| for silhouette symmetry; source code uses 1-ndotv [S1, unofficial]
        alpha = alpha * (1.0 - abs(ndotv))

    return color, alpha
```

**Parameters:**
*   `kd`, `ks`, `ka`: Diffuse, specular, and ambient lighting coefficients [S1, unofficial].
*   `boundary`: Integer flag. If `>0`, boundary enhancement is enabled [S1, unofficial].
*   `facing`: Integer flag. If `>0`, facing subtraction is enabled [S1, unofficial].
*   Specular exponent: Fixed at `512.0` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Zero Gradient:** If the gradient magnitude is zero, the normal is undefined. The source does not specify a fallback, but numerically, normalization of a zero vector results in NaN/Inf. A guard against zero-length gradients is required [G].
*   **Facing Subtraction Sign:** The source formula uses $|\mathbf{n} \cdot \mathbf{v}|$ while the code uses $\mathbf{n} \cdot \mathbf{v}$. The formula handles both front and back faces, while the code only affects front-facing fragments where $\mathbf{n} \cdot \mathbf{v} > 0$. Implementers must choose based on whether back-face silhouettes are desired [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per fragment, assuming constant-time texture lookups and arithmetic operations [S1, unofficial].
*   **Memory Complexity:** $O(1)$ additional memory per fragment, plus the storage for the 3D gradient texture and 1D transfer function texture [S1, unofficial].
*   **Strengths:** Enhances the perception of internal structures and boundaries in volume data without requiring explicit surface extraction [S1, unofficial]. The high specular exponent (512) creates sharp highlights, emphasizing surface-like qualities [S1, unofficial].
*   **Limitations:** Relies on precomputed gradients, increasing memory bandwidth and storage requirements [S1, unofficial]. The facing subtraction can make volumes appear hollow or less dense if over-applied [S1, unofficial]. The fixed specular exponent may not be suitable for all material appearances [S1, unofficial].
*   **When to use:** When visualizing complex internal structures where boundary definition is critical, and explicit surface extraction is too expensive or unnecessary [S1, unofficial].
*   **When not to use:** When real-time performance is constrained by memory bandwidth, or when a more physically accurate lighting model is required [S1, unofficial].
