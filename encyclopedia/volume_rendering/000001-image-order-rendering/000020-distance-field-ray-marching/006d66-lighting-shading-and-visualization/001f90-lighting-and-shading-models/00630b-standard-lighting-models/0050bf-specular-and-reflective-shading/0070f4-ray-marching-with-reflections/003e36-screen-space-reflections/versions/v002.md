# Screen-Space Reflections

Also called: Screen Space Ray Tracing (SSR)

## Overview
Screen-Space Reflections (SSR) is a real-time global illumination method that traces rays in screen space against the depth buffer to achieve effects like reflections and color bleeding, which direct illumination cannot produce [S2, unofficial]. It operates entirely within the 2D screen coordinate system using the existing depth buffer, distinguishing it from sibling methods that march through 3D volumes or scene graphs [G]. This approach is significantly cheaper than full ray tracing but is strictly limited to geometry currently visible on screen [S2, unofficial].

## How it works
**Inputs:**
*   Shaded point position in view space ($P_{view}$) [G].
*   View vector ($V$) from the camera to $P_{view}$ [S2, unofficial].
*   Surface normal ($N$) at $P_{view}$ [S2, unofficial].
*   Depth buffer (Z-buffer) containing depth values for all visible pixels [G].
*   Color buffer containing radiance/color values for all visible pixels [G].
*   Screen resolution ($W \times H$) [G].

**Outputs:**
*   Reflected color contribution ($C_{refl}$) for the shaded point [S2, unofficial].

**Data Structures:**
*   **Depth Buffer:** A 2D array of size $W \times H$, storing depth values ($z$) in view space [G].
*   **Color Buffer:** A 2D array of size $W \times H$, storing RGB(A) color values [G].

**Steps:**
1.  **Reflect View Vector:** Calculate the reflection direction $R$ by reflecting the view vector $V$ along the surface normal $N$ [S2, unofficial].
    $$ R = V - 2(V \cdot N)N $$
    Where $V$ and $N$ are normalized. The ray direction for tracing is $R$.
2.  **Initialize Ray:** Start a ray at $P_{view}$ with direction $R$ [G].
3.  **Iterate Ray Steps:** Advance the ray in screen space. For each step $i$:
    a.  Compute the current view position $P_i$ of the ray.
    b.  Project $P_i$ into screen space to get pixel coordinates $(u_i, v_i)$ [G].
    c.  Fetch the depth value $z_{buffer}$ from the Depth Buffer at $(u_i, v_i)$ [S2, unofficial].
    d.  Fetch the depth value $z_{ray}$ of the current ray point $P_i$ in view space [G].
    e.  **Intersection Test:**
        *   If $z_{ray} > z_{buffer}$ (assuming depth increases away from camera), the point is further away from the camera than the geometry in the depth buffer, meaning the ray is inside the geometry [S2, unofficial].
        *   If $z_{ray} < z_{buffer}$, the ray is in front of the geometry; continue to the next step [G].
        *   If the ray goes off-screen or exceeds a maximum distance, terminate [G].
4.  **Binary Search Refinement:** If an intersection is detected between step $i-1$ and step $i$, perform a binary search between these two positions to find a more precise intersection point $P_{hit}$ [S2, unofficial]. This improves accuracy because the initial intersection location is imprecise due to the unknown distance traveled between steps [S2, unofficial].
5.  **Sample Color:** Once $P_{hit}$ is determined, project it to screen space $(u_{hit}, v_{hit})$ [G]. Sample the Color Buffer at $(u_{hit}, v_{hit})$ to obtain the incident radiance value $C_{refl}$ [S2, unofficial].
6.  **Shade:** Utilize $C_{refl}$ to shade the surface [S2, unofficial].

**Pseudocode:**
```python
def screen_space_reflections(P_view, V, N, depth_buffer, color_buffer, W, H, max_steps, step_size):
    # Reflect view vector to get ray direction
    R = V - 2 * dot(V, N) * N
    
    prev_pos = P_view
    current_pos = P_view
    
    for i in range(max_steps):
        # Advance ray
        current_pos = prev_pos + R * step_size
        
        # Project current_pos to screen space
        u, v = project_to_screen(current_pos, W, H)
        
        # Check bounds
        if not (0 <= u < W and 0 <= v < H):
            return 0.0 # Off-screen
            
        # Get depth values
        z_ray = get_view_depth(current_pos)
        z_buffer = depth_buffer[v][u]
        
        # Check for intersection
        # Assuming depth buffer stores depth away from camera
        if z_ray > z_buffer:
            # Intersection occurred between prev_pos and current_pos
            # Perform binary search to refine intersection point
            hit_pos = binary_search_depth(prev_pos, current_pos, depth_buffer, W, H)
            
            # Sample color buffer at hit position
            u_hit, v_hit = project_to_screen(hit_pos, W, H)
            if 0 <= u_hit < W and 0 <= v_hit < H:
                return color_buffer[v_hit][u_hit]
            else:
                return 0.0
        else:
            prev_pos = current_pos
            
    return 0.0 # No intersection found

def project_to_screen(P_view, W, H):
    # Standard perspective projection to screen coordinates
    # Assumes camera looks down -Z, depth increases away from camera
    if P_view.z == 0:
        return 0, 0
    x_clip = P_view.x / -P_view.z
    y_clip = P_view.y / -P_view.z
    u = int((x_clip * 0.5 + 0.5) * W)
    v = int((y_clip * 0.5 + 0.5) * H)
    return u, v

def get_view_depth(P_view):
    # Return depth in view space (distance from camera)
    return -P_view.z

def binary_search_depth(start_pos, end_pos, depth_buffer, W, H):
    low = start_pos
    high = end_pos
    for _ in range(10): # Fixed iterations for stability
        mid = low + (high - low) * 0.5
        u, v = project_to_screen(mid, W, H)
        if not (0 <= u < W and 0 <= v < H):
            return mid # Fallback
            
        z_ray = get_view_depth(mid)
        z_buffer = depth_buffer[v][u]
        
        if z_ray > z_buffer:
            high = mid
        else:
            low = mid
    return low
```

**Parameters:**
*   `max_steps`: Maximum number of ray steps. Typical value: Not given in the sources.
*   `step_size`: Distance to advance the ray per step. Typical value: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Lambertian Limitation:** The approach only works on Lambertian surfaces [S2, unofficial].
*   **Screen Boundary:** It can only reflect what is currently on screen [S2, unofficial]. Geometry outside the viewport is not reflected.
*   **Precision:** Initial intersection location is imprecise due to unknown distance traveled between steps, necessitating binary search [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of ray steps and pixels processed. Each pixel requires a depth buffer lookup and potentially a binary search [G].
*   **Memory Complexity:** $O(W \times H)$ for the depth and color buffers [G].
*   **Strengths:** Real-time performance; leverages existing rasterization buffers; effective for mirror and glossy surfaces [S2, unofficial].
*   **Limitations:** Limited to visible geometry; artifacts at screen edges; requires depth buffer; limited to Lambertian surfaces according to source [S2, unofficial].
*   **When to use:** Real-time rendering of reflections and color bleeding where full ray tracing is too expensive [S2, unofficial].
*   **When not to use:** When reflections of off-screen objects are required, or for non-Lambertian surfaces if the source constraint is strict [S2, unofficial].

## Background
Screen-Space Reflections (SSR) was first presented by Sousa [S2, unofficial]. It is commonly found in real-time scenarios to render reflections [S2, unofficial]. It is considered the most general method in real-time rendering for global illumination using screen space techniques, achieving honorable global illumination effects for both mirror and glossy surfaces [S2, unofficial]. It is used in Jrender to depict global illumination for mirror and glossy surfaces [S1].
