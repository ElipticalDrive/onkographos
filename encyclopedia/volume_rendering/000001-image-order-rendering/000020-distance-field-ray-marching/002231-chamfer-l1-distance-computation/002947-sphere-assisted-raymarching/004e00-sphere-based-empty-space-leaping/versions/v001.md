# Sphere-based Empty Space Leaping
Also called: Sphere at empty voxel, Sphere-based Empty Voxel Navigation
## Overview
A technique that places a sphere at every empty voxel position, where the sphere radius indicates the distance to the closest non-empty voxel, used for navigation inside hollow volumetric objects [S1, unofficial][S2, book]. It sets itself apart from its parent [Sphere Assisted Raymarching](4497-sphere-assisted-raymarching.md) by specifically targeting the "hollow" interior case, reducing ray traversal to just a few hops until a boundary wall is reached [S1, unofficial][S2, book].
## How it works
**Inputs and Outputs:**
- Input: A volumetric dataset $V$ with voxel grid dimensions $W \times H \times D$.
- Input: A precomputed sphere radius texture $R$, where $R(x,y,z)$ stores the radius of the largest empty sphere centered at voxel $(x,y,z)$.
- Output: Ray marching steps that leap through empty space.

**Data Structures:**
- $R$: A 3D texture (or array) of floats. For any voxel $(i,j,k)$, if the voxel is empty, $R[i][j][k]$ is the Euclidean distance to the nearest non-empty voxel. If the voxel is non-empty, the value is undefined or zero.

**Steps:**
1. Initialize ray origin $O$ and direction $D$. Set current position $P = O$.
2. While $P$ is within the volume bounds:
   a. Sample the sphere radius $r = R(\text{voxel}(P))$.
   b. If $r$ is valid (empty voxel):
      i. Step size $s = r$.
      ii. Advance $P \leftarrow P + s \cdot D$.
      iii. If $P$ is still inside an empty voxel (check $R(\text{voxel}(P)) > 0$), repeat step 2b. [G]
   c. If $r$ is invalid (non-empty voxel or boundary):
      i. Perform standard volume rendering integration (e.g., ray marching with shading) from the previous valid position to $P$.
      ii. Break or continue with standard marching.

**Formulas:**
- Step size: $s = R(x,y,z)$
- New position: $P_{new} = P_{old} + s \cdot \vec{d}$

**Parameters:**

**Edge cases and pitfalls:**
- Precision: Not given in the sources.
- Boundaries: Rays missing the object are handled by the initial proximity cloud or view-sensitive extension, but this specific method focuses on navigation *inside* hollow objects [S1, unofficial][S2, book].
- Degenerate input: Not given in the sources.

**Pseudocode:**
```python
def sphere_based_leap(ray_origin, ray_direction, volume_bounds, radius_texture):
    pos = ray_origin
    while is_inside_volume(pos, volume_bounds):
        voxel_coords = world_to_voxel(pos)
        r = radius_texture[voxel_coords]
        
        # If we are in an empty voxel, leap by the radius
        if r > 0:
            step_size = r
            pos = pos + step_size * ray_direction
        else:
            # Hit a non-empty voxel or boundary
            break
    return pos
```

## Operating characteristics
- Time complexity: Not given in the sources.
- Memory complexity: Not given in the sources.
- Measured performance: Not given in the sources.
- Scaling: Not given in the sources.
- Strengths: Reduces ray traversal to just a few hops inside hollow objects [S1, unofficial][S2, book].
- Limitations: Only handles empty space leaping; does not traverse occupied space faster [S1, unofficial][S2, book].
- When to use: Navigation inside hollow volumetric objects, such as virtual colonoscopy [S1, unofficial][S2, book].
- When not: When the volume is mostly solid or when occupied space traversal speed is the primary bottleneck.
## Background
Origin: Proposed by Wan [S1, unofficial][S2, book]. It is an extension of the proximity clouds approach, addressing the shortcoming that proximity clouds are insensitive to viewing direction and slow down rays that miss the object [S1, unofficial][S2, book]. Sramek and Kaufman proposed a view-sensitive extension of proximity clouds, and Wan applied the sphere-based approach for hollow object navigation [S1, unofficial][S2, book]. Meissner later suggested an algorithm to quickly re-compute the proximity cloud when the transfer function changes [S1, unofficial][S2, book].
