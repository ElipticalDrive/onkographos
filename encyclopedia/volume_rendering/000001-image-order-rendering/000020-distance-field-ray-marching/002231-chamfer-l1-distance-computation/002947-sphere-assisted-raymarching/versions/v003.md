# Sphere Assisted Raymarching

Also called: Shape Assisted Raymarching, Shape Marching, Sphere Assisted

## Overview
Sphere Assisted Raymarching is a distance-field ray marching technique that stores the radius of the largest empty sphere centered at each voxel in a separate shape texture [S1, unofficial][S2, unofficial]. It solves the problem of excessive voxel lookups in empty space by using the stored radius as a lower bound for the step size, allowing rays to leap across large empty regions [S1, unofficial][S2, unofficial]. Unlike standard plane marching, which steps to the nearest grid boundary, this method reduces the number of texture lookups significantly, though it incurs higher upfront computational cost and memory usage due to the generation and storage of the shape data [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Input:** Ray origin $p_0$, ray direction $d$ (normalized), maximum check distance $maxDistToCheck$, voxel grid size $voxelGridSize$.
*   **Textures:**
    *   `voxels`: A 3D texture storing normalized float color values. The alpha channel indicates solidity [S1, unofficial].
    *   `shape`: A 3D texture storing integer values. The red channel stores the distance to the nearest solid voxel as a non-negative integer [S1, unofficial][S2, unofficial].
*   **Output:** A `vec4` color value. Returns the color from the `voxels` texture if a solid voxel is hit, or `vec4(0)` if the ray exits the volume or exceeds $maxDistToCheck$ [S1, unofficial].

**Data Structures**
The `shape` texture uses an integer format (e.g., 8-bit unsigned integer) to store the sphere radius. The value 255 is reserved to represent a solid voxel [S1, unofficial][S2, unofficial]. This separation allows the `voxels` texture to retain normalized float precision for color channels [S1, unofficial].

**Parameters**
*   `255`: Constant representing a solid voxel in the shape texture [S1, unofficial][S2, unofficial].
*   `epsilon`: A small positive constant added to the step size to guarantee progress and prevent infinite loops due to precision errors [S1, unofficial].
*   `maxDistToCheck`: The maximum distance the ray is allowed to travel [S1, unofficial].

**Algorithm Steps**
1.  Initialize ray distance $t = 0$.
2.  Loop while $t \le maxDistToCheck$:
    a.  Calculate current position $p = p_0 + d \cdot t$.
    b.  Sample the `shape` texture at $p / voxelGridSize$ to get `shapeValue` [S1, unofficial].
    c.  If `shapeValue` == 255, the voxel is solid. Return `textureLod(voxels, p / voxelGridSize, 0)` [S1, unofficial].
    d.  Calculate the distance to the next grid plane boundaries in each axis. For a direction component $d_i$ and position component $p_i$, the delta to the next plane is:
        $$ \delta_i = \frac{\text{step}(0, d_i) - \text{fract}(p_i)}{d_i} $$
        where $\text{step}(0, d_i)$ is 0 if $d_i < 0$ and 1 if $d_i \ge 0$, and $\text{fract}(x)$ is $x - \lfloor x \rfloor$ [S1, unofficial].
    e.  Find the minimum delta across all axes: $minDelta = \min(\delta_x, \delta_y, \delta_z)$ [S1, unofficial].
    f.  Update $t$ by adding the maximum of the minimum delta and the sampled shape radius, plus epsilon:
        $$ t \leftarrow t + \max(minDelta + shapeValue, \epsilon) $$
3.  Return `vec4(0)` [S1, unofficial].

**Pseudocode**
```python
def sphere_assisted_raymarching(p0, d, maxDistToCheck, voxelGridSize, shape_texture, voxels_texture):
    t = 0.0
    while t <= maxDistToCheck:
        p = p0 + d * t
        
        # Sample shape data
        # Note: In GLSL, textureLod is used. Here we assume a generic texture lookup
        # that returns an integer value for the radius.
        shape_value = shape_texture.sample(p / voxelGridSize, level=0).r
        
        # Check for solid voxel
        if shape_value == 255:
            return voxels_texture.sample(p / voxelGridSize, level=0)
        
        # Calculate deltas to next plane boundaries
        # step(0, d) returns 0 if d < 0 else 1
        # fract(p) returns p - floor(p)
        deltas = (step(0, d) - fract(p)) / d
        
        # Find minimum delta
        min_delta = min(deltas.x, deltas.y, deltas.z)
        
        # Update t
        epsilon = 1e-6 # Small constant to guarantee progress [S1, unofficial]
        t += max(min_delta + shape_value, epsilon)
        
    return vec4(0)
```

**Edge Cases and Pitfalls**
*   **Precision:** Floating-point errors can cause the ray to miss the exact boundary or oscillate. The `epsilon` term is critical to ensure $t$ always increases [S1, unofficial].
*   **Solid Voxel Representation:** The value 255 must be consistent between the shape generation and the raymarching shader [S1, unofficial][S2, unofficial].
*   **Upfront Cost:** Generating the shape data (distance field) has a significant computational cost, typically $O(n^2)$ or $O(n \log n)$ depending on the implementation, where $n$ is the number of voxels [S1, unofficial]. This can be a bottleneck for large voxel grids [S1, unofficial][S2, unofficial].

## Subtopics

### [Cube Assisted Raymarching](4940-cube-assisted-raymarching.md)
Cube Assisted Raymarching is a distance-field ray marching technique that stores the size of the largest empty cube centered at each voxel instead of the largest empty sphere. It solves the problem of slow shape data generation in Sphere Assisted Raymarching by trading some step optimality for significantly faster preprocessing. While Sphere Assisted Raymarching provides optimal step sizes, Cube Assisted Raymarching is an order of magnitude faster to compute the shape data, making it suitable for larger voxel grids where preprocessing time is a bottleneck.

### [Sphere-based Empty Space Leaping](13590-sphere-based-empty-space-leaping.md)
A technique that places a sphere at every empty voxel position, where the sphere radius indicates the distance to the closest non-empty voxel, used for navigation inside hollow volumetric objects. It reduces a ray's space traversal to just a few hops until a boundary wall is reached. Unlike standard sphere tracing which uses the global maximum empty sphere radius, this method is view-sensitive and specifically optimized for hollow structures like those in virtual colonoscopy.

## Operating characteristics
*   **Time Complexity:** The raymarching loop itself is efficient in empty space, reducing the number of iterations proportional to the size of empty regions. However, the preprocessing step to generate the shape data is costly. A simple implementation of shape data generation runs in $O(n^2)$ time, where $n$ is the number of voxels [S1, unofficial]. Optimized implementations using summed area tables and binary search can reduce this to $O(n \log n)$ [S1, unofficial].
*   **Memory Complexity:** Requires two 3D textures: one for color (`voxels`) and one for shape data (`shape`) [S1, unofficial]. This doubles the memory footprint compared to storing only color data, although the shape texture can use a lower precision integer format [S1, unofficial].
*   **Performance:** Reduces the number of voxel lookups in empty space compared to plane marching [S1, unofficial]. However, it is not always a performance win due to the overhead of the additional texture lookup and the preprocessing cost [S1, unofficial].
*   **Strengths:** Significantly reduces ray traversal steps in large empty volumes. Simple to implement in the shader [S1, unofficial].
*   **Limitations:** High upfront computational cost for shape generation. Higher memory usage. The shape data generation is a bottleneck for dynamic or very large voxel grids [S1, unofficial].
*   **When to use:** Suitable for static voxel scenes with large empty regions where the preprocessing cost can be amortized.
*   **When not to use:** Unsuitable for dynamic voxel data where shape data must be regenerated every frame, or for very large grids where the $O(n^2)$ or $O(n \log n)$ preprocessing is prohibitive. In such cases, Cube Assisted Raymarching may be preferred [S1, unofficial].

## Background
Sphere Assisted Raymarching was introduced by Caleb Leak in his blog post "Raymarching Voxel Rendering" [S1, unofficial][S2, unofficial]. The technique is part of a series of optimizations for voxel rendering, following plane marching and preceding cube assisted raymarching. It addresses the inefficiency of standard plane marching, which steps to the nearest grid boundary regardless of the distance to the nearest solid object [S1, unofficial][S2, unofficial]. The method leverages the concept of distance fields, storing the radius of the largest empty sphere at each voxel to guide the ray [S1, unofficial][S2, unofficial].
