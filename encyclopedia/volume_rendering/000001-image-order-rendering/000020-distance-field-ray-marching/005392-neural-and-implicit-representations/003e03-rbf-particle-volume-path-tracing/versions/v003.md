# RBF Particle Volume Path Tracing

Also called: RBF volume rendering, SPH volume rendering, Smoothed Particle Hydrodynamics (SPH) volume rendering

## Overview
RBF Particle Volume Path Tracing renders particle-based datasets (such as SPH fluid simulations) by modeling the volume as a continuous scalar field composed of additive weighted radial basis functions (RBFs), specifically Gaussians [S1, book]. This approach solves the visual clutter and pathological performance issues associated with BVH-based ray tracing of overlapping splatted particles by treating the volume as a single field rather than discrete geometry [S1, book]. It distinguishes itself from [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md) by using a BVH traversal for efficient spatial culling of contributing particles and from [Ray Marching with Neural SDF](2409-ray-marching-with-neural-sdf.md) by relying on explicit analytical kernels rather than learned implicit fields. It extends previous RBF implementations restricted to ray casting by integrating RBF reconstruction into a volume sampling kernel API that supports unbiased path tracing via delta tracking [S1, book].

## How it works
### Inputs and Outputs
**Inputs:**
*   Particle dataset: A set of $N$ particles, each defined by position $\mathbf{x}_i$, radius $r_i$, and weight $w_i$.
*   Rendering parameters: `radiusSupportFactor` (default 3), `clampMaxCumulativeValue` (optional threshold).
*   Transfer functions: Color map $C(\cdot)$ and opacity map $\alpha(\cdot)$ mapping scalar field values to emission color and extinction coefficients.
*   Ray: Origin $\mathbf{o}$ and direction $\omega$.

**Outputs:**
*   Radiance $L(0, \omega)$ accumulated along the ray.

### Data Structures
1.  **Particle Data:** Arrays for positions (`vec3f`), radii (`float`), and weights (`float`).
2.  **Bounding Volume Hierarchy (BVH):** Built around individual particles using Embree.
    *   **Leaf Nodes:** Each leaf corresponds to a single particle.
    *   **Interior Nodes:** Store the minimum and maximum scalar field values ($\Phi_{min}, \Phi_{max}$) achievable within their bounding volume.
    *   **Bounds:** Determined by the particle's base radius multiplied by `radiusSupportFactor`.
3.  **Global Statistics:** Global minimum and maximum values of the RBF field $\Phi$ over the entire dataset, used for initial $\sigma_{t,\max}$ estimation if automatic estimation is skipped.

### Algorithm Steps

1.  **Preprocessing (Optional but Recommended for Delta Tracking):**
    *   Build a BVH over the particles.
    *   Estimate local value ranges for BVH leaf nodes:
        *   For each leaf (particle), evaluate the RBF field $\Phi$ over a small grid (e.g., $10^3$ points) within the particle's support radius.
        *   Determine the local minimum and maximum from these samples.
    *   Propagate these ranges up the BVH to update interior node ranges.
    *   Store the global minimum and maximum values.
    *   *Note:* This step has worst-case time complexity $O(N)$ [S1, book]. If the user can accurately guess the cumulative maximum value, this step may be skipped, and `clampMaxCumulativeValue` set manually [S1, book].

2.  **Ray Initialization:**
    *   Initialize accumulated radiance $L = 0$.
    *   Initialize transmittance $T = 1.0$.
    *   Set current ray position $t = 0$.

3.  **Delta Tracking Loop:**
    *   Sample distance to next event $t_{next}$ using Equation 44.6:
        $$ t_{next} = -\frac{\ln(1-\xi)}{\sigma_{t,\max}} $$
        where $\xi \in [0, 1)$ is a uniform random number and $\sigma_{t,\max}$ is the maximum extinction coefficient. $\sigma_{t,\max}$ is derived from the global maximum scalar field value $\Phi_{max}$ via the opacity map $\alpha$ and a scaling factor (typically density-to-extinction conversion) [S1, book].
    *   Advance ray position: $t \leftarrow t + t_{next}$.
    *   Evaluate the scalar field $\Phi$ at the new position $\mathbf{x}(t) = \mathbf{o} + t\omega$ using `sampleRBF` (see below).
    *   Calculate actual extinction coefficient $\sigma_t$ at $\mathbf{x}(t)$ using $\Phi$ and the transfer function $\alpha$.
    *   Determine if the event is virtual:
        $$ P[\text{virtual}] = 1 - \frac{\sigma_t}{\sigma_{t,\max}} $$
    *   Generate a random number $\eta \in [0, 1)$. If $\eta < P[\text{virtual}]$, the event is virtual. Continue to the next iteration of the loop (sample a new $t_{next}$).
    *   If the event is real:
        *   Calculate emission $L^e$ using the color map $C(\Phi)$ and the incoming radiance direction.
        *   Update accumulated radiance: $L \leftarrow L + T \cdot \sigma_t \cdot L^e \cdot t_{next}$ (approximation for small steps) or integrate properly. *Note: The source cites the RTE solution for non-scattering media (Eq 44.4). In discrete delta tracking, the contribution is typically $T \cdot \sigma_e \cdot L^e \cdot \Delta t$.*
        *   Update transmittance: $T \leftarrow T \cdot \exp(-\sigma_t \cdot t_{next})$.
        *   If $T$ is below a threshold, terminate the path.

4.  **Scalar Field Evaluation (`sampleRBF`):**
    *   Traverse the BVH using `traverseBVH`.
    *   For each intersected node, check if the node's value range can contribute significantly (optional optimization based on transfer function sensitivity).
    *   For leaf nodes (particles), call `intersectAndSampleParticle`.
    *   Accumulate the result into `result`.
    *   If `clampMaxCumulativeValue` is set and `result` exceeds it, terminate the RBF evaluation early and return the clamped value [S1, book].

### Formulas

**RBF Scalar Field:**
The scalar field $\Phi$ at point $\mathbf{x}$ is the sum of Gaussian kernels for all contributing particles $i$:
$$ \Phi(\mathbf{x}) = \sum_i \phi_i(d_i(\mathbf{x})) $$
where $d_i(\mathbf{x}) = \|\mathbf{x} - \mathbf{x}_i\|$ is the distance from particle center $\mathbf{x}_i$ [S1, book].

**Gaussian Kernel:**
$$ \phi_f(\mathbf{x}) = w_f e^{-\frac{1}{2}(d_f(\mathbf{x})/r_f)^2} $$
where $w_f$ is the weight, $r_f$ is the radius, and $d_f(\mathbf{x}) = \|\mathbf{x} - \mathbf{x}_f\|$ [S1, book].
The kernel is truncated at a support radius of $\sigma r_f$ (default $\sigma = 3$) [S1, book].

**Radiative Transfer Equation (Non-scattering):**
$$ L(0, \omega) = \int_0^\infty T(0, t) \cdot \sigma_e(t) L^e(t, \omega) dt $$
where $T(0, t) = \exp(-\int_0^t \sigma_t(s) ds)$ [S1, book].

**Delta Tracking Distance Sampling:**
$$ t = -\frac{\ln(1-\xi)}{\sigma_{t,\max}} $$
where $\xi \in [0, 1)$ is a uniform random number [S1, book].

**Virtual Event Rejection Probability:**
$$ P[\text{virtual}] = 1 - \frac{\sigma_t}{\sigma_{t,\max}} $$
where $\sigma_t$ is the actual extinction coefficient at the sampled point [S1, book].

**Transfer Function Application:**
$$ L^e(t, -\omega) = L^e(C(\Phi(t)), -\omega) $$
$$ T(t, -\omega) = T(\alpha(\Phi(t)), -\omega) $$
where $C$ is a color map and $\alpha$ is an opacity map [S1, book].

            delta = samplePos - particle.position
            dist_sq = dot(delta, delta)

            support_radius_sq = support_radius * support_radius

### Parameters
*   `radiusSupportFactor`: A multiple of the base particle radius used to determine BVH bounds and kernel truncation. Default value is 3. Smaller values improve performance but may cause artifacts due to RBF truncation [S1, book].
*   `clampMaxCumulativeValue`: A threshold for the accumulated RBF field value. If the accumulated result exceeds this value, evaluation terminates early. Useful in regions of significant overlap to preserve contours at the cost of dynamic range. Default is 0 (disabled) [S1, book].

### Edge Cases and Pitfalls
*   **Overlapping Particles:** In splatting approaches, overlapping particles cause visual clutter and pathological BVH performance. RBF volume rendering solves this by treating the volume as one scalar field [S1, book].
*   **Value Estimation Cost:** Estimating $\sigma_{t,\max}$ via grid sampling has worst-case complexity $O(N)$ and can be costly. It is only necessary for small datasets with unpredictable overlap or if the user cannot guess the cumulative maximum value. For large datasets (e.g., cosmology), manual specification of `clampMaxCumulativeValue` is preferred [S1, book].
*   **Truncation Artifacts:** Using a small `radiusSupportFactor` can introduce artifacts if the RBF kernel is truncated too aggressively [S1, book].

## Operating characteristics
*   **Time Complexity:** The preprocessing step (value estimation) has a worst-case time complexity of $O(N)$, where $N$ is the number of particles [S1, book]. The rendering complexity depends on the BVH traversal and the number of delta tracking steps, which is influenced by the density of the volume and the accuracy of $\sigma_{t,\max}$.
*   **Memory Complexity:** Requires storage for particle data ($O(N)$) and the BVH ($O(N)$).
*   **Performance:** Allows for hundreds of millions of individual particles to be rendered without simplification, proxy geometry, or filtering of the original data [S1, book]. Performance is improved by the BVH culling and early termination via `clampMaxCumulativeValue` [S1, book].
*   **Strengths:** Handles overlapping particles efficiently; supports full path tracing; allows adjustable smoothing/sharpening via kernel radius and weight; supports analytical derivatives for shading [S1, book].
*   **Limitations:** Preprocessing can be costly for large datasets if automatic value estimation is used; requires careful tuning of `radiusSupportFactor` and `clampMaxCumulativeValue` for optimal quality/performance balance [S1, book].

## Background
RBF volume rendering is frequently referred to as a Smoothed Particle Hydrodynamics (SPH) approach due to its use in visualizing SPH fluid dynamics codes [S1, book]. It was implemented in Intel OSPRay and the Open Volume Kernel Library (VKL) using ISPC [S1, book]. The method builds on the Woodcock-tracking volume path tracer of Raab [S1, book] but extends it by implementing RBF reconstruction within a volume sampling kernel API, leveraging interval iterators for space skipping, and supporting path tracing within the OSPRay framework [S1, book]. It is applicable to other ray tracing architectures like NVIDIA OptiX [S1, book].
