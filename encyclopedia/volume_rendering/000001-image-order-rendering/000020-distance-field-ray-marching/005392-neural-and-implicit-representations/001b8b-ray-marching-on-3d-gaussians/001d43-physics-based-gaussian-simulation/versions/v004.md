# Physics-based Gaussian Simulation

Also called: GASP (Gaussian Splatting for Physic-Based Simulations), PhysGaussian (as a related approach), GaMeS integration

## Overview
Physics-based Gaussian Simulation integrates continuum mechanics directly into 3D Gaussian Splatting (3DGS) to enable physically accurate animation and dynamic behavior [S1][S2, S3, unofficial]. Unlike methods that rely on external meshing strategies (e.g., marching cubes) or modify the physics engine, this approach treats Gaussian components as discrete physical particles, allowing them to be simulated using standard black-box physics engines [S3, unofficial]. It distinguishes itself by using parametrized flat Gaussian distributions to map directly to triangle faces, avoiding the artifacts associated with treating points as disparate entities [S3, unofficial].

## How it works
The method operates by converting 3D Gaussian components into a geometric representation compatible with physics engines (specifically triangle meshes), simulating the deformation, and reconstructing the Gaussians from the deformed geometry.

### Inputs and Outputs
*   **Input:** A set of 3D Gaussian components defined by mean $m$, rotation matrix $R$, and scaling matrix $S$. Specifically, the method utilizes "flat" Gaussians where one scaling axis is negligible.
*   **Output:** Deformed 3D Gaussian components $(\hat{m}, \hat{R}, \hat{S})$ that reflect the physical simulation results.

### Data Structures
The core data structure is the **Flat Gaussian**, defined as $N(m, R, S)$ [S3, unofficial].
*   **Mean ($m$):** 3D vector.
*   **Rotation ($R$):** $3 \times 3$ orthogonal matrix with columns $r_1, r_2, r_3$.
*   **Scaling ($S$):** Diagonal matrix $\text{diag}(s_1, s_2, s_3)$.
*   **Constraint:** For flat Gaussians, $s_1 = \epsilon$ (a small value, effectively zero), making the Gaussian 2D-like [S3, unofficial].

The intermediate representation is a **Triangle Soup**, where each Gaussian is mapped to a triangle face $V = [v_1, v_2, v_3]$ [S3, unofficial].

### Steps
1.  **Parameterization (Gaussian to Triangle):** Convert each flat Gaussian component into a triangle face using the mapping $T(\cdot)$ [S3, unofficial].
    *   Vertex 1: $v_1 = m$
    *   Vertex 2: $v_2 = m + s_2 r_2$
    *   Vertex 3: $v_3 = m + s_3 r_3$
    *   This creates a set of triangles (triangle soup) representing the object [S3, unofficial].

2.  **Simulation:** Extract the vertices of the triangle soup and run the physics engine (e.g., Material Point Method (MPM)) on this point cloud to obtain trajectories [S3, unofficial]. The physics engine acts as a black box, requiring no modification [S3, unofficial].

3.  **Reconstruction (Triangle to Gaussian):** Recover the Gaussian parameters $(\hat{m}, \hat{R}, \hat{S})$ from the deformed triangle vertices $V = [v_1, v_2, v_3]$ using the inverse mapping $T^{-1}(\cdot)$ [S3, unofficial].

4.  **Artifact Control:** Apply additional rules to control Gaussian sizes during simulation to eliminate artifacts caused by treating points as discrete entities [S3, unofficial]. This includes rescaling when a triangle undergoes significant size changes [S3, unofficial].

5.  **Optimization (Optional):** Implement a Gaussian grouping strategy (hierarchy) to perform simulations exclusively on selected "Core Gaussians" to enhance efficiency [S3, unofficial].

### Formulas
The recovery of the Gaussian parameters from the deformed triangle vertices $V = [v_1, v_2, v_3]$ is defined as follows [S3, unofficial]:

**Mean:**
$$ \hat{m} = v_1 $$

**Rotation Matrix $\hat{R} = [\hat{r}_1, \hat{r}_2, \hat{r}_3]$:**
1.  First axis (normalized face normal):
    $$ \hat{r}_1 = \frac{(v_2 - v_1) \times (v_3 - v_1)}{\|(v_2 - v_1) \times (v_3 - v_1)\|} $$
2.  Second axis (normalized edge vector):
    $$ \hat{r}_2 = \frac{v_2 - v_1}{\|v_2 - v_1\|} $$
3.  Third axis (Gram-Schmidt orthogonalization):
    $$ \hat{r}_3 = \text{orth}(v_3 - v_1; \hat{r}_1, \hat{r}_2) $$
    Where $\text{orth}(u; a, b)$ denotes a single step of the Gram-Schmidt process to orthogonalize vector $u$ against vectors $a$ and $b$ [S3, unofficial].

**Scaling Parameters $\hat{S} = \text{diag}(\hat{s}_1, \hat{s}_2, \hat{s}_3)$:**
1.  $$ \hat{s}_1 = \epsilon $$
2.  $$ \hat{s}_2 = \|v_2 - v_1\| $$
3.  $$ \hat{s}_3 = \langle v_3 - v_1, \hat{r}_3 \rangle $$

The resulting covariance matrix is $\hat{\Sigma} = \hat{R}\hat{S}\hat{S}^T\hat{R}^T$ [S3, unofficial].

    """
    m = gaussian['m']
    r2 = gaussian['R'][:, 1] # Second column of R
    r3 = gaussian['R'][:, 2] # Third column of R
    s2 = gaussian['S'][1]
    s3 = gaussian['S'][2]
    
    v1 = m
    v2 = m + s2 * r2
    v3 = m + s3 * r3
    return [v1, v2, v3]

### Parameters and Edge Cases
*   **$\epsilon$:** A small scalar value for $s_1$. Not given in the sources.
*   **Flat Gaussian Constraint:** The method relies on $s_1 = \epsilon$. If the initial Gaussians are not flat, the mapping $T(\cdot)$ may not accurately represent the volume, leading to simulation artifacts [S3, unofficial].
*   **Discrete Point Artifacts:** Treating vertices as discrete points can cause artifacts. The use of triangles (face representation) mitigates this, but significant deformation may still require rescaling [S3, unofficial].
*   **Hierarchy:** For efficiency, a Gaussian grouping strategy can be used to simulate only "Core Gaussians" [S3, unofficial].

## Operating characteristics
*   **Performance:** The pipeline is described as "notably rapid" and does not increase rendering costs [S3, unofficial].
*   **Efficiency:** Implementing a Gaussian hierarchy (simulating only selected Gaussians) significantly accelerates the process, especially with particle-based engines like Taichi [S3, unofficial].
*   **Flexibility:** The method integrates with any black-box physics engine (e.g., Genesis, Blender, Taichi Elements) without modifying the engine or the GS model [S3, unofficial].
*   **Comparison:** GASP avoids additional meshing strategies (like marching cubes) used by GSP, Embodied Gaussians, and VR-GS, operating directly on Gaussian components [S3, unofficial]. This contrasts with PhysGaussian, which uses a first-order approximation of the deformation map and requires adjustments to the physics engine [S3, unofficial].

## Background
*   **Origin:** The GASP (Gaussian Splatting for Physic-Based Simulations) pipeline was introduced by Waczja et al. [S3, unofficial].
*   **Development:** It builds upon the GaMeS framework, which uses flat Gaussians [S3, unofficial]. The method was demonstrated using the Genesis engine, Blender software, and the Taichi Elements library [S3, unofficial].
*   **Context:** It addresses the need for physically accurate dynamics in 3DGS, which is often used for animation [S1][S2, unofficial]. Previous methods like PhysGaussian adapted Newtonian dynamics via linear transformations, while GASP uses a direct mapping to triangle faces [S3, unofficial].
