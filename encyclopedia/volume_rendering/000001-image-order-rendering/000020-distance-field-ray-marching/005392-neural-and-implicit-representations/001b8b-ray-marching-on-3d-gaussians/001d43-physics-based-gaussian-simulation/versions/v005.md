# Physics-based Gaussian Simulation

Also called: GASP (Gaussian Splatting for Physic-Based Simulations)

## Overview
Physics-based Gaussian Simulation integrates continuum mechanics directly into 3D Gaussian Splatting (3DGS) to enable physically accurate animation and dynamic behavior [S1][S2, S3, unofficial]. Unlike methods that rely on external meshing strategies (e.g., marching cubes) or modify the physics engine itself, this approach treats flat 3D Gaussians as discrete physical particles, converting them into triangle faces for simulation and reconstructing them afterward [S3, unofficial]. It distinguishes itself from [PhysGaussian](1036-ray-marching-on-3d-gaussians.md) by avoiding first-order deformation approximations and linear transformations, instead using a black-box physics engine with explicit geometric reconstruction [S3, unofficial].

## How it works
The method operates on **flat Gaussians**, where the scaling matrix $S = \text{diag}(s_1, s_2, s_3)$ has $s_1 = \epsilon$ (a small value, typically $\approx 0$), effectively reducing the Gaussian to a 2D surface [S3, unofficial].

### Inputs and Outputs
- **Input**: A set of 3D Gaussian components $N(m, R, S)$, where $m$ is the mean, $R$ is the rotation matrix, and $S$ is the scaling matrix.
- **Output**: Updated Gaussian parameters $(\hat{m}, \hat{R}, \hat{S})$ after physics simulation.

### Data Structures
Each Gaussian is represented by:
- Mean $m \in \mathbb{R}^3$
- Rotation $R \in \mathbb{R}^{3 \times 3}$ (columns $\hat{r}_1, \hat{r}_2, \hat{r}_3$)
- Scaling $S = \text{diag}(\epsilon, s_2, s_3)$
- Color $c$ and opacity $\sigma$ (unchanged during simulation)

### Steps
1. **Conversion to Triangle Soup**: Map each flat Gaussian $N(m, R, S)$ to a triangle face $V = [v_1, v_2, v_3]$ using the mapping $T(\cdot)$ [S3, unofficial].
2. **Physics Simulation**: Extract vertices from the triangle soup and run a physics engine (e.g., Material Point Method (MPM)) on the point cloud to obtain deformed vertex positions [S3, unofficial].
3. **Reconstruction**: Recover Gaussian parameters from the deformed vertices $V$ using the inverse mapping $T^{-1}(\cdot)$ [S3, unofficial].
4. **Artifact Control**: Apply rescaling rules if triangles undergo significant size changes to prevent artifacts caused by treating points as discrete entities [S3, unofficial].
5. **Optional Hierarchy**: Use a Gaussian grouping strategy to simulate only "Core Gaussians" for efficiency [S3, unofficial].

### Formulas
**Forward Mapping** $T(m, R, S) \rightarrow V$:
Given a Gaussian with mean $m$, rotation axes $\hat{r}_1, \hat{r}_2, \hat{r}_3$, and scales $s_2, s_3$ (where $s_1=\epsilon$):
$$
v_1 = m
$$
$$
v_2 = m + s_2 \hat{r}_2
$$
$$
v_3 = m + s_3 \hat{r}_3
$$

**Inverse Mapping** $T^{-1}(V) \rightarrow (\hat{m}, \hat{R}, \hat{S})$:
Given deformed vertices $V = [v_1, v_2, v_3]$:
1. Mean:
   $$ \hat{m} = v_1 $$
2. Rotation Axes:
   $$ \hat{r}_1 = \frac{(v_2 - v_1) \times (v_3 - v_1)}{\|(v_2 - v_1) \times (v_3 - v_1)\|} \quad \text{(Normalized face normal)} $$
   $$ \hat{r}_2 = \frac{v_2 - v_1}{\|v_2 - v_1\|} \quad \text{(Normalized edge vector)} $$
   $$ \hat{r}_3 = \text{orth}(v_3 - v_1; \hat{r}_1, \hat{r}_2) \quad \text{(Gram-Schmidt orthogonalization)} $$
3. Scaling:
   $$ \hat{s}_1 = \epsilon $$
   $$ \hat{s}_2 = \|v_2 - v_1\| $$
   $$ \hat{s}_3 = \langle v_3 - v_1, \hat{r}_3 \rangle $$

The resulting covariance matrix is $\hat{\Sigma} = \hat{R} \hat{S} \hat{S}^T \hat{R}^T$ [S3, unofficial].

### Pseudocode
```python
def physics_based_gaussian_simulation(gaussians, physics_engine):
    """
    Simulate physics on a list of flat Gaussians.
    
    Args:
        gaussians: List of dicts with keys 'm', 'r1', 'r2', 'r3', 's2', 's3', 'color', 'opacity'.
                   Assumes s1 = epsilon (small constant).
        physics_engine: A callable that takes a list of triangles (vertices) and returns
                        deformed vertices.
    
    Returns:
        Updated list of gaussians.
    """
    epsilon = 1e-6
    
    # Step 1: Convert Gaussians to Triangle Soup
    triangles = []
    for g in gaussians:
        v1 = g['m']
        v2 = g['m'] + g['s2'] * g['r2']
        v3 = g['m'] + g['s3'] * g['r3']
        triangles.append([v1, v2, v3])
        
    # Step 2: Run Physics Engine
    # The engine modifies vertex positions based on physical laws (e.g., MPM)
    deformed_triangles = physics_engine(triangles)
    
    # Step 3 & 4: Reconstruct Gaussians and Apply Controls
    updated_gaussians = []
    for i, tri in enumerate(deformed_triangles):
        v1, v2, v3 = tri
        
        # Recover Mean
        m_hat = v1
        
        # Recover Rotation Axes
        edge1 = v2 - v1
        edge2 = v3 - v1
        
        # r1 is the normal to the triangle face
        normal = cross(edge1, edge2)
        norm_len = length(normal)
        if norm_len < epsilon:
            # Degenerate triangle fallback [G]
            r1_hat = [0, 0, 1] 
        else:
            r1_hat = normalize(normal)
            
        # r2 is the direction of the first edge
        edge1_len = length(edge1)
        if edge1_len < epsilon:
            r2_hat = [1, 0, 0] # Fallback [G]
        else:
            r2_hat = normalize(edge1)
            
        # r3 is orthogonal to r1 and r2 (Gram-Schmidt)
        # orth(v, r1, r2) = v - proj_r1(v) - proj_r2(v)
        proj_r1 = dot(edge2, r1_hat) * r1_hat
        proj_r2 = dot(edge2, r2_hat) * r2_hat
        r3_raw = edge2 - proj_r1 - proj_r2
        r3_len = length(r3_raw)
        if r3_len < epsilon:
            r3_hat = cross(r1_hat, r2_hat) # Ensure orthogonality [G]
        else:
            r3_hat = normalize(r3_raw)
            
        # Recover Scaling
        s1_hat = epsilon
        s2_hat = edge1_len
        s3_hat = dot(edge2, r3_hat)
        
        # Artifact Control: Rescale if significant change [S3, unofficial]
        # (Implementation detail: check ratio of new vs old scales)
        # If scale change > threshold, clamp or smooth [G]
        
        # Store updated Gaussian
        updated_gaussians.append({
            'm': m_hat,
            'r1': r1_hat,
            'r2': r2_hat,
            'r3': r3_hat,
            's2': s2_hat,
            's3': s3_hat,
            'color': gaussians[i]['color'],
            'opacity': gaussians[i]['opacity']
        })
        
    return updated_gaussians
```

### Parameters
- $\epsilon$: Small constant for $s_1$ (e.g., $10^{-6}$) [S3, unofficial].
- Physics Engine: Can be any black-box engine (e.g., Genesis, Blender, Taichi Elements) [S3, unofficial].

### Edge Cases and Pitfalls
- **Degenerate Triangles**: If vertices collapse (zero area), cross products become zero. Fallback orthogonal vectors must be defined [G].
- **Discrete Artifacts**: Treating points as discrete entities causes artifacts. Using triangles and rescaling mitigates this [S3, unofficial].
- **Significant Size Changes**: Large deformations require additional rescaling rules to maintain Gaussian validity [S3, unofficial].

## Subtopics

### GASP Pipeline
The specific implementation using flat Gaussians and black-box physics engines, avoiding meshing [S3, unofficial].

### PhysGaussian
Uses first-order approximation of deformation maps and linear transformations, requiring physics engine adjustments [S3, unofficial].

### Gaussian Splashing
Uses Position-Based Fluids for fluid simulation, building on GaussianShader for material parameters [S1][S2, unofficial].

## Operating characteristics
- **Time Complexity**: Linear with respect to the number of Gaussians for conversion and reconstruction. Simulation cost depends on the physics engine (e.g., MPM complexity) [S3, unofficial].
- **Memory Complexity**: Proportional to the number of Gaussians and triangle vertices [S3, unofficial].
- **Performance**: Demonstrated superior performance on benchmark datasets for 3D object rendering [S3, unofficial].
- **Strengths**: No additional meshing strategies required; compatible with any black-box physics engine; hierarchical grouping enhances efficiency [S3, unofficial].
- **Limitations**: Artifacts from discrete point treatment if not managed; requires flat Gaussian initialization [S3, unofficial].

## Background
Originating from the GASP paper (2024), this method addresses the need for physically accurate dynamics in 3DGS [S3, unofficial]. It builds on GaMeS (flat Gaussian parameterization) [S3, unofficial] and contrasts with PhysGaussian (2023) which uses linear approximations [S3, unofficial]. It is demonstrated using the Genesis engine, Blender, and Taichi Elements [S3, unofficial].
