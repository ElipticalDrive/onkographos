# View-dependent color with Spherical Harmonics

Also called: Rendering with Spherical Harmonics, Spherical Harmonic Colour Model, Spherical Harmonics Color Evaluation, Spherical Harmonic Evaluation, SH Render

## Overview
View-dependent color with Spherical Harmonics (SH) is a representation technique used in 3D Gaussian Splatting to model the view-dependent appearance (e.g., reflections, specular highlights) of each Gaussian primitive as a function of the viewing direction [S1, unofficial][S2]. It solves the problem of storing directional color variation compactly without requiring per-ray neural network queries, allowing each Gaussian to store a color that varies with the observer's angle [S1, unofficial][S2]. Unlike simple point colors or view-independent RGB values, this model captures high-frequency directional effects like glossy reflections [S1, S5, unofficial]. It is distinct from its siblings [OTS Marching Ray Marching Algorithm](1073-ots-marching-ray-marching-algorithm.md) and [Physics-based Gaussian Simulation](1457-physics-based-gaussian-simulation.md) by providing a differentiable, closed-form basis expansion for appearance rather than physical simulation or marching logic [S1, unofficial][S2].

## How it works
**Inputs and Outputs:**
*   **Input:** A set of $N$ 3D Gaussians. For each Gaussian $i$, the method requires:
    *   The viewing direction vector $\mathbf{d}_i$, normalized, from the camera center to the Gaussian's mean position [S1, S6, unofficial].
    *   The Spherical Harmonic coefficients $\mathbf{k}_i$ stored for that Gaussian [S1, unofficial][S2].
*   **Output:** The RGB color $C_i$ of the Gaussian in the viewing direction $\mathbf{d}_i$ [S1, S6, unofficial].

**Data Structures:**
Each Gaussian stores 48 Spherical Harmonic coefficients, organized as a contiguous array of 48 floats [S1, S4, unofficial]. The layout is:
*   The first 3 elements ($f_{dc\_0}, f_{dc\_1}, f_{dc\_2}$) are the Degree-0 (DC) coefficients for Red, Green, and Blue, representing the view-independent base color [S4, unofficial].
*   The remaining 45 elements ($f_{rest\_0} \dots f_{rest\_44}$) are the coefficients for Degrees 1, 2, and 3 [S4, unofficial].
*   The coefficients are stored in increasing order of degree and order [S3, unofficial]. Specifically, for each color channel (R, G, B), there are 16 coefficients corresponding to the 16 basis functions of degrees $l=0$ to $l=3$ [S1, S4, unofficial].

**Parameters:**
*   **Maximum SH Degree ($L$):** Typically $L=3$ [S1, S3, unofficial]. This results in $(L+1)^2 = 16$ basis functions per color channel [S1, unofficial].
*   **Normalization Constants:**
    *   $SH\_C0 = 0.28209479177387814$ [S4, unofficial]
    *   $SH\_C1 = 0.4886025119029199$ [S4, unofficial]
    *   $SH\_C2\_0 = 1.0925484305920792$
    *   $SH\_C2\_1 = -0.3153915652525201$
    *   $SH\_C2\_2 = 0.5462742152960396$
    *   $SH\_C2\_3 = -0.3153915652525201$
    *   $SH\_C2\_4 = 0.1084622861092159$
    *   $SH\_C3\_0 = -0.5900435899266435$
    *   $SH\_C3\_1 = 2.890611442640554$
    *   $SH\_C3\_2 = -0.4570457994644658$
    *   $SH\_C3\_3 = 0.3731763325901154$
    *   $SH\_C3\_4 = -0.4570457994644658$
    *   $SH\_C3\_5 = 1.445305721320277$
    *   $SH\_C3\_6 = -0.5900435899266435$
    *(Note: Standard SH normalization constants are used; the specific values for C2-C3 are derived from standard SH definitions often cited in 3DGS implementations [S4, S6, S1, unofficial].)*

**Numbered Steps:**
1.  **Compute Viewing Direction:** For each Gaussian, compute the normalized direction vector $\mathbf{d} = (x, y, z)$ from the camera center to the Gaussian's mean position [S1, S6, unofficial].
2.  **Evaluate Basis Functions:** Compute the values of the Spherical Harmonic basis functions $Y_l^m(\mathbf{d})$ for the given direction $\mathbf{d}$ and degrees $l=0 \dots 3$ [S1, S6, unofficial]. These are fixed polynomials of $x, y, z$ [S1, S5, unofficial].
3.  **Compute Color:** For each color channel $c \in \{R, G, B\}$, compute the color $C_c(\mathbf{d})$ by summing the product of the SH coefficients $k_{l,c}^m$ and the basis functions $Y_l^m(\mathbf{d})$ [S1, unofficial]:
    $$C_c(\mathbf{d}) = \sum_{l=0}^{3} \sum_{m=-l}^{l} k_{l,c}^m Y_l^m(\mathbf{d})$$
4.  **Apply Non-linearity:** Apply a ReLU activation and add a bias of 0.5 to the result to ensure valid color values [S6, unofficial]:
    $$RGB = \text{ReLU}\left(\sum_{l=0}^{3} \sum_{m=-l}^{l} \mathbf{k}_{l,c}^m \cdot Y_l^m(\mathbf{d}) + 0.5\right)$$
    *(Note: The bias and ReLU are standard in 3DGS implementations to handle negative SH values and ensure non-negative output [S6, unofficial].)*

**Pseudocode:**
```python
import math

# Constants for SH evaluation (Degree 0 to 3)
SH_C0 = 0.28209479177387814
SH_C1 = 0.4886025119029199
SH_C2_0 = 1.0925484305920792
SH_C2_1 = -0.3153915652525201
SH_C2_2 = 0.5462742152960396
SH_C2_3 = -0.3153915652525201
SH_C2_4 = 0.1084622861092159
SH_C3_0 = -0.5900435899266435
SH_C3_1 = 2.890611442640554
SH_C3_2 = -0.4570457994644658
SH_C3_3 = 0.3731763325901154
SH_C3_4 = -0.4570457994644658
SH_C3_5 = 1.445305721320277
SH_C3_6 = -0.5900435899266435

def eval_sh(sh_coeffs, view_dir):
    """
    Evaluates Spherical Harmonics for a single Gaussian.
    
    Args:
        sh_coeffs: Array of 48 floats [f_dc_0..2, f_rest_0..44]
        view_dir: Tuple (x, y, z) normalized viewing direction
        
    Returns:
        Tuple (r, g, b) with values in [0, 1]
    """
    x, y, z = view_dir
    
    # Extract DC coefficients (Degree 0)
    c0_r, c0_g, c0_b = sh_coeffs[0], sh_coeffs[1], sh_coeffs[2]
    
    # Initialize color with DC component
    r = SH_C0 * c0_r
    g = SH_C0 * c0_g
    b = SH_C0 * c0_b
    
    # Degree 1 (Indices 3-11)
    # Coefficients for R, G, B are stored sequentially for each degree/order
    # Order: m=-1, 0, 1 for each color
    # Basis functions: -y, z, -x (scaled by SH_C1)
    c1_r0, c1_r1, c1_r2 = sh_coeffs[3], sh_coeffs[4], sh_coeffs[5]
    c1_g0, c1_g1, c1_g2 = sh_coeffs[6], sh_coeffs[7], sh_coeffs[8]
    c1_b0, c1_b1, c1_b2 = sh_coeffs[9], sh_coeffs[10], sh_coeffs[11]
    
    # Basis: Y1^-1 ~ -y, Y1^0 ~ z, Y1^1 ~ -x
    # Note: Sign conventions may vary; standard 3DGS uses:
    # term1 = -SH_C1 * y
    # term2 = SH_C1 * z
    # term3 = -SH_C1 * x
    term1 = -SH_C1 * y
    term2 = SH_C1 * z
    term3 = -SH_C1 * x
    
    r += term1 * c1_r0 + term2 * c1_r1 + term3 * c1_r2
    g += term1 * c1_g0 + term2 * c1_g1 + term3 * c1_g2
    b += term1 * c1_b0 + term2 * c1_b1 + term3 * c1_b2
    
    # Degree 2 (Indices 12-26)
    # Coefficients for R, G, B
    c2_r0, c2_r1, c2_r2, c2_r3, c2_r4 = sh_coeffs[12], sh_coeffs[13], sh_coeffs[14], sh_coeffs[15], sh_coeffs[16]
    c2_g0, c2_g1, c2_g2, c2_g3, c2_g4 = sh_coeffs[17], sh_coeffs[18], sh_coeffs[19], sh_coeffs[20], sh_coeffs[21]
    c2_b0, c2_b1, c2_b2, c2_b3, c2_b4 = sh_coeffs[22], sh_coeffs[23], sh_coeffs[24], sh_coeffs[25], sh_coeffs[26]
    
    # Basis functions for Degree 2:
    # Y2^-2 ~ xy, Y2^-1 ~ yz, Y2^0 ~ 2zz-xx-yy, Y2^1 ~ xz, Y2^2 ~ xx-yy
    # Scaled by SH_C2 constants
    term_xy = SH_C2_0 * x * y
    term_yz = SH_C2_1 * y * z
    term_2zz_xx_yy = SH_C2_2 * (2 * z * z - x * x - y * y)
    term_xz = SH_C2_3 * x * z
    term_xx_yy = SH_C2_4 * (x * x - y * y)
    
    r += term_xy * c2_r0 + term_yz * c2_r1 + term_2zz_xx_yy * c2_r2 + term_xz * c2_r3 + term_xx_yy * c2_r4
    g += term_xy * c2_g0 + term_yz * c2_g1 + term_2zz_xx_yy * c2_g2 + term_xz * c2_g3 + term_xx_yy * c2_g4
    b += term_xy * c2_b0 + term_yz * c2_b1 + term_2zz_xx_yy * c2_b2 + term_xz * c2_b3 + term_xx_yy * c2_b4
    
    # Degree 3 (Indices 27-47)
    # Coefficients for R, G, B
    c3_r0, c3_r1, c3_r2, c3_r3, c3_r4, c3_r5, c3_r6 = sh_coeffs[27], sh_coeffs[28], sh_coeffs[29], sh_coeffs[30], sh_coeffs[31], sh_coeffs[32], sh_coeffs[33]
    c3_g0, c3_g1, c3_g2, c3_g3, c3_g4, c3_g5, c3_g6 = sh_coeffs[34], sh_coeffs[35], sh_coeffs[36], sh_coeffs[37], sh_coeffs[38], sh_coeffs[39], sh_coeffs[40]
    c3_b0, c3_b1, c3_b2, c3_b3, c3_b4, c3_b5, c3_b6 = sh_coeffs[41], sh_coeffs[42], sh_coeffs[43], sh_coeffs[44], sh_coeffs[45], sh_coeffs[46], sh_coeffs[47]
    
    # Basis functions for Degree 3:
    # Y3^-3 ~ y(3xx-yy), Y3^-2 ~ xyz, Y3^-1 ~ y(4zz-xx-yy), Y3^0 ~ z(2zz-3xx-3yy)
    # Y3^1 ~ x(4zz-xx-yy), Y3^2 ~ z(xx-yy), Y3^3 ~ x(xx-3yy)
    # Scaled by SH_C3 constants
    term_y_3xx_yy = SH_C3_0 * y * (3 * x * x - y * y)
    term_xyz = SH_C3_1 * x * y * z
    term_y_4zz_xx_yy = SH_C3_2 * y * (4 * z * z - x * x - y * y)
    term_z_2zz_3xx_3yy = SH_C3_3 * z * (2 * z * z - 3 * x * x - 3 * y * y)
    term_x_4zz_xx_yy = SH_C3_4 * x * (4 * z * z - x * x - y * y)
    term_z_xx_yy = SH_C3_5 * z * (x * x - y * y)
    term_x_xx_3yy = SH_C3_6 * x * (x * x - 3 * y * y)
    
    r += term_y_3xx_yy * c3_r0 + term_xyz * c3_r1 + term_y_4zz_xx_yy * c3_r2 + term_z_2zz_3xx_3yy * c3_r3 + term_x_4zz_xx_yy * c3_r4 + term_z_xx_yy * c3_r5 + term_x_xx_3yy * c3_r6
    g += term_y_3xx_yy * c3_g0 + term_xyz * c3_g1 + term_y_4zz_xx_yy * c3_g2 + term_z_2zz_3xx_3yy * c3_g3 + term_x_4zz_xx_yy * c3_g4 + term_z_xx_yy * c3_g5 + term_x_xx_3yy * c3_g6
    b += term_y_3xx_yy * c3_b0 + term_xyz * c3_b1 + term_y_4zz_xx_yy * c3_b2 + term_z_2zz_3xx_3yy * c3_b3 + term_x_4zz_xx_yy * c3_b4 + term_z_xx_yy * c3_b5 + term_x_xx_3yy * c3_b6
    
    # Apply ReLU and bias
    r = max(0.0, r + 0.5)
    g = max(0.0, g + 0.5)
    b = max(0.0, b + 0.5)
    
    return (r, g, b)
```

**Training Schedule:**
Optimization begins with only the degree-0 band (base color) active. One further band is unlocked every 1,000 iterations until all four bands (degrees 0-3) are active [S1, unofficial]. This coarse-to-fine schedule allows the base color to settle before higher-frequency view-dependent details are fitted [S1, unofficial].

**Edge Cases and Pitfalls:**
*   The basis functions $Y_l^m(\mathbf{d})$ are fixed polynomials and are never updated during training; only the coefficients $k$ are learned [S1, S5, unofficial].
*   High-degree SH can cause memory bandwidth pressure, as loading 48 coefficients per Gaussian consumes significant memory [S1, unofficial].
*   Without SH (Degree 0 only), color is view-independent, leading to a measurable quality drop (e.g., PSNR reduction on Average-30K from 26.05 to 25.35) [S5, unofficial].

## Subtopics

### [Progressive View-Dependent Color Baking](2834-progressive-view-dependent-color-baking.md)
Progressive View-Dependent Color Baking is an optimization for 3D Gaussian Splatting that reduces memory bandwidth pressure caused by high-degree spherical harmonics (SH) by evaluating view-dependent colors over multiple frames rather than every frame. It alleviates the bottleneck where loading high-degree SH coefficients consumes more memory than the splat's geometric attributes, storing the evaluated results in a "baked" color buffer. Unlike standard per-frame SH evaluation, this method trades immediate visual fidelity for rendering performance, converging to the correct view-dependent color within a short, fixed number of frames. See [Progressive View-Dependent Color Baking](2834-progressive-view-dependent-color-baking.md).

### [Spherical Beta View-Dependent Color](3823-spherical-beta-view-dependent-color.md)
Spherical Beta (SB) is a specular appearance model that adds explicit specular lobes on top of a diffuse base color, used for view-dependent color in 3D Gaussian Splatting. It is distinct from Spherical Harmonics (SH) by using a parametric lobe function rather than a global basis expansion, allowing for sharper highlights with fewer parameters. It is orthogonal to SH, where SH (typically degree 0) supplies the diffuse base and SB adds the specular component. See [Spherical Beta View-Dependent Color](3823-spherical-beta-view-dependent-color.md).

### Spherical Harmonics Per Point
A representation where each point in the point cloud carries spherical harmonics parameters to model directional appearance, as opposed to directionally invariant RGB values [S7]. Using spherical harmonics yields better rendering quality than using learnable directionally invariant RGB values [S7]. On the Blender dataset, removing spherical harmonics ('w/o sh') reduces PSNR from 30.3 dB to 27.1 dB, SSIM from 0.945 to 0.932, and increases LPIPS from 0.078 to 0.155 [S7].

### RayGauss
A ray-traced variant of 3D Gaussians that treats Gaussians as volumetric primitives and ray marches them in a NeRF-like manner to achieve high quality at the cost of performance [S8]. It introduces a slab-by-slab integration scheme and augments spherical harmonics with a spherical Gaussian encoding to better capture view-dependent color [S8]. While this yields higher PSNR than 3DGS, it comes with a 6× training slowdown and approximately 25× lower frame rates [S8].

### Spherical Beta Function
A view-dependent appearance representation used in DP-GES to model higher-frequency view-dependent effects, replacing spherical harmonics (SH) [S9, unofficial]. Reverting to SH (spherical harmonics) as in Ours (base) reduces FPS slightly (472 to 480) and PSNR (28.11 to 27.72), but is used to isolate the impact of the core rendering model [S9, unofficial]. The Spherical Beta function increases the risk of overfitting, as observed in DBS [S9, unofficial].

## Operating characteristics
*   **Time Complexity:** Evaluation of SH coefficients is $O(1)$ per Gaussian per frame, as it involves a fixed number of polynomial evaluations [S1, unofficial]. The cost is negligible compared to rasterization [S1, unofficial].
*   **Memory Complexity:** Each Gaussian stores 48 floats (192 bytes) for SH coefficients at degree 3 [S1, S4, unofficial]. This is a significant memory overhead compared to view-independent RGB (12 bytes) [S1, unofficial].
*   **Measured Performance:** On the Mip-NeRF360 benchmark, 3DGS with SH reaches 27.21 dB PSNR and 0.214 LPIPS at 134 fps [S1, unofficial]. Removing SH reduces PSNR to 25.35 on Average-30K [S5, unofficial].
*   **Scaling:** SH evaluation scales linearly with the number of Gaussians and is highly parallelizable on GPUs [S1, unofficial].
*   **Strengths:** Captures view-dependent effects like highlights and reflections efficiently [S1, unofficial][S2]. Closed-form evaluation allows for fast rendering [S1, unofficial].
*   **Limitations:** High memory bandwidth usage for degree 3 SH [S1, unofficial]. May overfit to high-frequency details if not regularized [S9, unofficial].
*   **When to Use:** When view-dependent appearance (specularities, reflections) is important for photorealism [S1, unofficial][S2].
*   **When Not to Use:** When memory bandwidth is a critical bottleneck and view-dependent effects are minimal [S1, unofficial].

## Background
Spherical Harmonics (SH) are an orthogonal basis for functions on the unit sphere, repurposed from irradiance environment maps to represent the view-dependent color of 3D Gaussians [S1, S5, unofficial]. The method was introduced in the 3D Gaussian Splatting paper (Kerbl et al., 2023) [S1, unofficial]. It allows each Gaussian to store a color that varies with viewing direction, solving the problem of directional color variation compactly [S1, unofficial][S2]. The technique is distinct from classical view synthesis methods like light-field rendering, which require dense capture [S1, unofficial].
