# Ambient Occlusion Specific Distance Function

Also called: Distance function for a cube sized 3D texture (AO variant), Distance function for a cube sized 3D texture. Version for ambient occlusion

## Overview
This method is a specialized distance function for a cube-sized 3D texture designed to mitigate artifacts in ambient occlusion (AO) calculations caused by the texture's bounding shell [S1, unofficial]. While the standard distance function returns the distance to the outer boundary for points outside the texture volume, this variant returns a constant step size $\Delta t$ [S1, unofficial]. This prevents the bounding "red box" from contributing to the occlusion result, which otherwise causes visible artifacts on surfaces like the bunny's face [S1, unofficial]. It is used in conjunction with [Bounded 3D Distance Texture Ray Marching](1115-bounded-3d-distance-texture-ray-marching.md) but modifies the boundary handling logic specifically for AO shading [S1, unofficial].

## How it works
**Inputs:**
- Query point $x$ (vec3).
- 3D texture containing signed distance values.
- Constant $\Delta t$ (float), passed from the ambient occlusion algorithm to determine the sample point along the ray equation [S1, unofficial].
- Parameters: `textureBoundary` = $(0.5, 0.5, 0.5)$, `textureShell` = $(0.05, 0.05, 0.05)$ [S1, unofficial].

**Outputs:**
- Distance value `res` (float).

**Data Structures:**
- The 3D texture is assumed to be cube-sized and normalized to $[0, 1]^3$.
- `textureBoundary` defines the half-width of the valid region center.
- `textureShell` defines the thickness of the boundary region where the distance is clamped or adjusted [S1, unofficial].

**Steps:**
1. Compute the absolute value of the query point: $|x|$.
2. Calculate the distance vector $d_i$ from the inner valid region box:
   $$ d_i = |x| - \text{textureBoundary} + \text{textureShell} $$
   This results in a vector $(d_{ix}, d_{iy}, d_{iz})$ [S1, unofficial].
3. Determine if the point $x$ is inside the inner valid region (the "green box" area) by computing:
   $$ c = \max(d_{ix}, \max(d_{iy}, d_{iz})) $$
4. If $c < 0$, the point is inside the inner valid region:
   - Adjust the coordinates to map back to the texture space: $x = x + \text{textureBoundary}$.
   - Lookup the distance value from the 3D texture: `res` = `lookupTexture(texture, x)` [S1, unofficial].
5. If $c \ge 0$ (point is outside the inner valid region):
   - Return the constant $\Delta t$: `res` = $\Delta t$ [S1, unofficial].

**Pseudocode:**
```python
def distance_function_ao(x, texture, delta_t):
    # Parameters from source [S1, unofficial]
    texture_boundary = (0.5, 0.5, 0.5)
    texture_shell = (0.05, 0.05, 0.05)
    
    # Step 1 & 2: Calculate distance to inner valid region
    abs_x = (abs(x.x), abs(x.y), abs(x.z))
    di = (
        abs_x.x - texture_boundary.x + texture_shell.x,
        abs_x.y - texture_boundary.y + texture_shell.y,
        abs_x.z - texture_boundary.z + texture_shell.z
    )
    
    # Step 3: Determine if inside inner region
    c = max(di.x, max(di.y, di.z))
    
    # Step 4 & 5: Return appropriate distance
    if c < 0:
        # Inside inner valid region
        adjusted_x = (
            x.x + texture_boundary.x,
            x.y + texture_boundary.y,
            x.z + texture_boundary.z
        )
        # Lookup texture value [G] (standard 3D texture lookup)
        res = lookup_texture(texture, adjusted_x)
    else:
        # Outside inner valid region: return constant delta_t
        res = delta_t
        
    return res
```

**Edge Cases and Pitfalls:**
- Using the standard distance function (Algorithm 4.1) for ambient occlusion causes the bounding red box to contribute to the occlusion result, leading to artifacts on the bunny's face [S1, unofficial].
- The mesh must be closed (holes filled) before conversion to a 3D distance texture to ensure correct representation [S1, unofficial].

## Background
This method originates from work on GPU ray marching for ambient occlusion using the GEL (GEometry and Linear algebra) framework [S1, unofficial]. It addresses specific artifacts observed when rendering the Stanford Bunny mesh, where the standard distance function caused incorrect occlusion near the texture boundaries [S1, unofficial]. The approach modifies the distance function $f(x)$ used in the ambient occlusion algorithm (Algorithm 3.4) to use $f_{BA}(x)$ instead of $f_B(x)$, while keeping the sphere tracing algorithm unchanged [S1, unofficial].
