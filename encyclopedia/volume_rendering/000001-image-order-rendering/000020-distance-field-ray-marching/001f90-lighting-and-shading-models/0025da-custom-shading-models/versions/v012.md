# Custom Shading Models

Also called: Custom Shading Routines, Per-voxel Shading Callbacks

## Overview
Custom Shading Models provide a mechanism for users to define arbitrary lighting and material behaviors for volume rendering, bypassing standard pre-computed lookup tables or fixed-function pipelines. This family solves the problem of limited expressiveness in standard shading by allowing per-voxel or per-surface-point computation of color based on user-defined logic. It is distinguished from sibling methods like [Distance Color Blending](791-distance-color-blending.md) and [Diffuse Lighting Models](5343-diffuse-lighting-models.md) by its open-ended nature: while siblings implement specific, optimized lighting approximations, Custom Shading Models allow the implementation of any shading logic, including physically based renderers (e.g., GGX), artistic effects (e.g., YUV glow), or specialized occlusion techniques (e.g., M-DOS), often at the cost of performance [S1].

## Shared principles
All methods in this family operate on a surface point $\mathbf{p}$ and its associated geometric data, primarily the surface normal $\mathbf{n}$ [G]. The normal is typically derived from the Signed Distance Function (SDF) $f(\mathbf{x})$ using the gradient:
$$ \mathbf{n} = \frac{\nabla f(\mathbf{p})}{\|\nabla f(\mathbf{p})\|} $$
where $\nabla f(\mathbf{p})$ is estimated via finite differences, such as solving a linear system based on values at vertices of a tetrahedron, or via back-propagation [G].

The core shading computation generally follows this structure:
1. **Geometric Setup:** Determine the view direction $\mathbf{v}$ (from $\mathbf{p}$ to camera) and light direction $\mathbf{l}$ (from $\mathbf{p}$ to light source) [G].
2. **Occlusion/Ambient Occlusion:** Calculate shadow factors or ambient occlusion values to determine how much light reaches $\mathbf{p}$ from the environment or specific lights [G].
3. **Reflectance Model:** Compute the diffuse and specular components based on the angle between $\mathbf{n}$, $\mathbf{l}$, and the reflection vector $\mathbf{r}$ [G].
4. **Color Accumulation:** Combine the base material color with the lighting contributions, often modulated by depth cueing or atmospheric effects [G].

## Subtopics

### [GGX Microfacet BRDF](3715-ggx-microfacet-brdf.md)
A physically based specular model using GGX distribution, Schlick Fresnel, and Smith geometry. Chosen for high-quality rough surface reflections.

### [Light Evaluation for SDF Faces](3751-light-evaluation-for-sdf-faces.md)
Analytic lighting applied to discretized SDF faces. Chosen for simple, fast shading of extracted geometry.

### [Blinn-Phong with Metallic Reflections](4252-blinn-phong-with-metallic-reflections.md)
Blinn-Phong extended with metallic modulation and environment reflections. Chosen for stylized urban/night scenes.

### [Multidirectional Occlusion Shading](7667-multidirectional-occlusion-shading.md)
Direct volume rendering with directional light scattering via elliptical kernels. Chosen for soft shadows and depth cues in volumetric data.

### [Single-Atomic High-Quality Robust Variant (HQS1R)](10218-single-atomic-high-quality-robust-variant-hqs1r.md)
Point cloud rendering with atomic blending and overflow protection. Chosen for aliasing reduction in point-based volumes.

### [YUV Color Space Shading with Glow](11187-yuv-color-space-shading-with-glow.md)
Illumination in YUV space with independent luminance/chrominance control and glow. Chosen for artistic indirect illumination effects.

### [Tangent Space Shading](12616-tangent-space-shading.md)
Gradient-less diffuse approximation via double-pass texture offsets. Chosen for performance when explicit gradients are unavailable or costly.

### [Voxel-Specific Shading Pipelines](17027-voxel-specific-shading-pipelines.md)
Not given in the sources.

### Procedural Road Surface
A procedural surface shader for roads that differentiates between asphalt, curb/shoulder, and terrain based on lateral distance to the road centerline, including emissive lane markings [S2, unofficial].
1. Calculate $d = p.x - \text{roadX}(p.z)$ and $ad = |d|$ [S2, unofficial].
2. If $ad < \text{ROAD\_HALF\_WIDTH}$: set albedo to dark gray, metal to 0.35, emissive to 0.0. Calculate lane lines using `smoothstep` for edge lines, center line, and dashed separators. Add emissive cyan color for lines [S2, unofficial].
3. Else if $ad < \text{ROAD\_HALF\_WIDTH} + \text{SHOULDER}$: set albedo to dark gray, metal to 0.1, emissive to magenta strip at road edge [S2, unofficial].
4. Else: set albedo to very dark, metal to 0.0, emissive to 0.0 [S2, unofficial].
Parameters: Asphalt metal 0.35; Lane line color $\text{vec3}(0.15, 1.0, 1.1) \times 1.3$; Edge line offset $\text{ROAD\_HALF\_WIDTH} - 0.3$; Center line offset 0.18; Dashed line frequency $p.z \times 0.18$ [S2, unofficial].

### Triangle Subdivision Shading
Divides each triangle into four subtriangles by splitting each edge in the middle, then applies either Gouraud or Phong shading to the sub-triangles [S3]. This process can be iterated; the `smooth` argument specifies one plus the number of times to divide the triangles [S3].
Parameters: `smooth` integer (1 = no subdivision) [S3].
Pitfall: High `smooth` values cause quality deterioration due to polygon filling artifacts, exacerbated by anti-aliasing [S3].

## Background
The concept of custom shading in volume rendering originated with early libraries like VolPack, which provided mechanisms for users to define custom shading lookup tables or callback routines for per-voxel shading [S1]. The VolPack User's Guide details two primary approaches: creating custom routines to initialize shading lookup tables (allowing non-encoded normal vectors and arbitrary table sizes) or defining a callback routine via `vpSetCallback` (e.g., `VP_GRAY_SHADE_FUNC`) [S1]. These callbacks allow arbitrary color computation per voxel but are noted to cause significant performance degradation [S1]. Modern implementations extend this concept to ray-marched SDFs, allowing for complex physically based models (GGX), artistic effects (YUV glow), and specialized volume techniques (M-DOS) [S2, unofficial].
