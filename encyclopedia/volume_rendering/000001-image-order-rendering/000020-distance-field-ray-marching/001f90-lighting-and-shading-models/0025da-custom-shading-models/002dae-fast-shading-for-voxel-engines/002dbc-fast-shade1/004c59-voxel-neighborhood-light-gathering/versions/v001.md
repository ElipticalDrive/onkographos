# Voxel Neighborhood Light Gathering

Also called: 26-neighbor light gathering, chunk-boundary light sampling

## Overview
Voxel Neighborhood Light Gathering is a method for computing local lighting conditions for a specific voxel by sampling the light intensity of its 26 immediate neighbors within a voxel chunk [S1, unofficial]. It solves the problem of discontinuous lighting at chunk boundaries and provides smoothed shading for voxel engines by aggregating neighbor data [S1, unofficial]. It differs from its parent [fast_shade1](5608-fast-shade1.md) by explicitly handling inter-chunk neighbor lookups and boundary conditions, whereas fast_shade1 assumes vertical sun rays and performs fewer neighbor checks [S1, unofficial].

## How it works
**Inputs:**
- `voxel`: The target `ChunkVoxel` for which lighting is being calculated.
- `chunk`: The voxel chunk containing the target voxel, providing access to neighbor chunks and local coordinate mapping.

**Outputs:**
- `neighborhood`: An array of size `NEIGHBOR_COUNT` (26) containing the light intensity (`Option<u8>`) of each neighbor.

**Data Structures:**
- `neighborhood`: An array of length 26. Each element stores the light intensity of a neighbor. If a neighbor is inaccessible or invalid, the value is `None` (or a default max intensity as per implementation details below).
- `IVec3`: A 3D integer vector type representing voxel coordinates $(x, y, z)$.
- `IVec2`: A 2D integer vector type used for mapping coordinates across chunk boundaries.

**Parameters:**
- `NEIGHBOR_COUNT`: `usize = 26`. Calculated as $(3 \times 3 \times 3) - 1$, representing all voxels in a $3 \times 3 \times 3$ cube centered on the target voxel, excluding the center itself [S1, unofficial].
- `MAX_NATURAL_INTENSITY`: A constant representing the maximum possible natural light intensity, used as a fallback for out-of-bounds or missing neighbors [S1, unofficial].

**Steps:**
1. Initialize a mutable array `neighborhood` of size 26 with default values (e.g., `None` or `MAX_NATURAL_INTENSITY`).
2. Retrieve the base chunk's light and kind storage using helper functions `get_light` and `get_kind` [S1, unofficial].
3. Convert the input `voxel` (of type `ChunkVoxel`) to an `IVec3` base coordinate, denoted as `base_voxel` [S1, unofficial].
4. Iterate through all 26 neighbor offsets using three nested loops:
   - `y` ranges from -1 to 1.
   - `z` ranges from -1 to 1.
   - `x` ranges from -1 to 1.
5. For each iteration, construct a direction vector `dir = IVec3::new(x, y, z)` [S1, unofficial].
6. If `dir` is the zero vector $(0, 0, 0)$, skip to the next iteration (this excludes the center voxel itself) [S1, unofficial].
7. Calculate the coordinate of the neighbor voxel: `side_voxel = base_voxel + dir` [S1, unofficial].
8. Determine if `side_voxel` is within the current chunk's horizontal bounds. The source specifies checking if `y == 0` for horizontal bounds, which implies a specific coordinate system orientation where the Y-axis is vertical and X/Z are horizontal [S1, unofficial].
   - **If out of bounds horizontally:**
     - Calculate the neighbor chunk using `chunk.neighbor(dir)` [S1, unofficial].
     - Calculate the local voxel coordinate in the neighbor chunk using `chunk::overlap_voxel(voxel, IVec2::new(dir.x, dir.z))` [S1, unofficial].
     - Retrieve the light and kind data from the neighbor chunk.
     - If the neighbor chunk does not exist or the light/kind data is unavailable, set the intensity to `MAX_NATURAL_INTENSITY` [S1, unofficial].
     - Otherwise, apply the same opaque/zero check used for internal voxels to determine the final intensity [S1, unofficial].
   - **If within bounds:**
     - Retrieve the light and kind data from the current chunk's storage.
     - Apply the opaque/zero check to determine the intensity [S1, unofficial].
9. Store the calculated `intensity` (of type `Option<u8>`) into the `neighborhood` array at the current index `i` and increment `i` [S1, unofficial].
10. After iterating through all 26 neighbors, return the populated `neighborhood` array [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Chunk Boundaries:** The method must correctly handle neighbors that lie in adjacent chunks. The source specifies using `chunk.neighbor(dir)` and `chunk::overlap_voxel` for this [S1, unofficial].
- **Missing Neighbors:** If a neighbor chunk does not exist or light/kind data is unavailable, the intensity defaults to `MAX_NATURAL_INTENSITY` [S1, unofficial].
- **Coordinate System:** The source's mention of "y == 0" for horizontal bounds is ambiguous and may depend on the specific coordinate system of the engine (e.g., Y-up vs Z-up) [S1, unofficial]. Implementers should verify the axis orientation.
- **Opaque/Zero Check:** The exact logic for the "opaque/zero check" is not detailed in the source [S1, unofficial]. It is assumed to filter out non-opaque voxels or apply ambient lighting.

## Operating characteristics
- **Time Complexity:** $O(1)$ per voxel, as it always checks a fixed number of 26 neighbors.
- **Memory Complexity:** $O(1)$ per voxel, requiring storage for 26 neighbor intensities.
- **Performance:** The method is efficient for real-time voxel engines as it avoids complex ray tracing or global illumination calculations. However, it may be less visually accurate than more sophisticated shading models due to its reliance on local neighborhood data [S1, unofficial].
- **Strengths:** Simple to implement, fast, handles chunk boundaries explicitly.
- **Limitations:** Limited to local lighting effects, may not capture global lighting phenomena like shadows or reflections accurately.

## Background
Voxel Neighborhood Light Gathering is part of the "projekto" project by afonsolage [S1, unofficial]. It is designed for voxel engines that use chunk-based data structures and require efficient, local lighting calculations. The method builds on the assumptions of [fast_shade1](5608-fast-shade1.md) but extends it to handle inter-chunk lighting more robustly [S1, unofficial].
