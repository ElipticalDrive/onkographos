# Fast Shading for Voxel Engines
## Overview
Fast Shading for Voxel Engines is a CPU-based lighting algorithm for voxel engines that assumes vertical sun rays to simulate illumination by directly modifying voxel palette indices [S1, unofficial]. It solves the performance bottleneck of per-voxel lighting calculations by operating on discrete tone groups within a palette, where indices 1–32, 33–64, etc., represent dark-to-light gradients [S1, unofficial]. It differs from [GGX Microfacet BRDF](3715-ggx-microfacet-brdf.md), [Voxel Shading Pipeline](3898-voxel-shading-pipeline.md), and [Blinn-Phong with Metallic Reflections](4252-blinn-phong-with-metallic-reflections.md) by avoiding surface normal computation and physically based reflection models, instead using simple integer neighbor checks to darken voxels based on occupancy [S1, unofficial].
## How it works
**Inputs and Outputs:**
- Input: A 3D voxel grid of dimensions $xsize \times ysize \times zsize$, where each voxel stores an integer palette index [S1, unofficial].
- Output: The same voxel grid with modified palette indices to reflect shading [S1, unofficial].

**Data Structures:**
- The voxel grid is accessed via `get_voxel_pal(x, y, z)` and `set_voxel_pal(x, y, z, val)` [S1, unofficial].
- Empty voxels are represented by index 0 [S1, unofficial].
- Palette indices are grouped into tone groups of 32 (e.g., 1–32, 33–64) to maintain consistent tonal bands during shading [S1, unofficial].

**Algorithm Steps:**
1. Iterate through the voxel grid from $x=1$ to $xsize-2$, $y=1$ to $ysize-2$, and $z=1$ to $zsize-2$ [S1, unofficial].
2. Retrieve the current voxel's palette index: `voxel = get_voxel_pal(x, y, z)` [S1, unofficial].
3. Calculate the lower bound (color margin) for the current tone group:
   $$ color\_margin = \lfloor \frac{voxel - 1}{32} \rfloor \times 32 + 1 $$
   This ensures the shaded color remains within the same tonal band [S1, unofficial].
4. If `voxel != 0` (the voxel is occupied), apply shading by subtracting values based on the occupancy of neighboring voxels [S1, unofficial]:
   - Subtract 3 if the voxel directly above `(x, y+1, z)` is occupied (non-zero) [S1, unofficial].
   - Subtract 2 if any of the following are occupied: `(x+1, y+1, z)`, `(x-1, y+1, z)`, `(x+1, y+1, z+1)`, or `(x+1, y+1, z-1)` [S1, unofficial].
   - Subtract 1 if any of the following are occupied: `(x+1, y, z+1)`, `(x-1, y, z-1)`, `(x+1, y, z-1)`, or `(x-1, y, z+1)` [S1, unofficial].
5. Clamp the resulting voxel index to the lower bound: if `voxel < color_margin`, set `voxel = color_margin` [S1, unofficial].
6. Write the modified index back: `set_voxel_pal(x, y, z, voxel)` [S1, unofficial].

**Pseudocode:**
```python
def fast_shade2(xsize, ysize, zsize, get_voxel_pal, set_voxel_pal):
    for x in range(1, xsize - 1):
        for y in range(1, ysize - 1):
            for z in range(1, zsize - 1):
                voxel = get_voxel_pal(x, y, z)
                
                # Skip empty voxels
                if voxel == 0:
                    continue
                
                # Calculate tone group lower bound
                color_margin = ((voxel - 1) // 32) * 32 + 1
                
                shading = 0
                
                # Subtract 3 if directly above is occupied
                if get_voxel_pal(x, y + 1, z) != 0:
                    shading += 3
                
                # Subtract 2 if specific upper neighbors are occupied
                if (get_voxel_pal(x + 1, y + 1, z) != 0 or
                    get_voxel_pal(x - 1, y + 1, z) != 0 or
                    get_voxel_pal(x + 1, y + 1, z + 1) != 0 or
                    get_voxel_pal(x + 1, y + 1, z - 1) != 0):
                    shading += 2
                
                # Subtract 1 if specific side neighbors are occupied
                if (get_voxel_pal(x + 1, y, z + 1) != 0 or
                    get_voxel_pal(x - 1, y, z - 1) != 0 or
                    get_voxel_pal(x + 1, y, z - 1) != 0 or
                    get_voxel_pal(x - 1, y, z + 1) != 0):
                    shading += 1
                
                # Apply shading and clamp
                voxel = voxel - shading
                if voxel < color_margin:
                    voxel = color_margin
                
                set_voxel_pal(x, y, z, voxel)
```

**Parameters:**
- `xsize`, `ysize`, `zsize`: Dimensions of the current voxel level [S1, unofficial].

**Edge Cases and Pitfalls:**
- The voxel index must not drop below the lower bound of its tone group (`color_margin`) [S1, unofficial].
- Boundary voxels are excluded from processing to avoid out-of-bounds neighbor access [S1, unofficial].
- Precision is not an issue as the algorithm uses only integer arithmetic [G].

## Subtopics

### fast_shade1
A faster but less visually detailed variant of the shading algorithm, also assuming vertical sun rays [S1, unofficial]. It reduces the number of neighbor checks compared to `fast_shade2` [S1, unofficial]. The shading logic subtracts 3 if `(x, y+1, z)` is occupied, 2 if `(x+1, y+1, z)` is occupied, and 1 if `(x+1, y, z+1)` or `(x-1, y, z-1)` is occupied [S1, unofficial]. It uses the same tone group clamping logic and iteration bounds as `fast_shade2` [S1, unofficial]. Choose this variant when performance is critical and the reduced shading detail is acceptable [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of voxels processed, due to a single pass over the grid [G].
- **Memory Complexity:** $O(1)$ auxiliary space, as it modifies the grid in place [G].
- **Performance:** Optimized for CPU execution in voxel engines that rely on CPU rendering [S1, unofficial].
- **Strengths:** Extremely fast, requires no floating-point operations, simple implementation, and integrates directly with palette-based rendering pipelines [S1, unofficial].
- **Limitations:** Assumes vertical sun rays, provides limited shading detail compared to normal-based lighting, and requires specific palette structures with tone groups of 32 [S1, unofficial].
- **When to use:** Simple voxel games, CPU-only rendering pipelines, and real-time shading where performance is paramount [S1, unofficial].
- **When not to use:** Physically based rendering, scenes with complex lighting angles, or when high-fidelity shading is required [G].

## Background
Fast Shading for Voxel Engines was developed as part of the DOOMMY voxel engine, an unofficial voxel-based game engine that uses only CPU for rendering and Lua for scripting [S1, unofficial]. The engine was created by jabberx and released under the GNU General Public License [S1, unofficial]. The shading method is designed to provide basic lighting effects efficiently on CPU hardware, reflecting the constraints and goals of early voxel engine development [S1, unofficial].
