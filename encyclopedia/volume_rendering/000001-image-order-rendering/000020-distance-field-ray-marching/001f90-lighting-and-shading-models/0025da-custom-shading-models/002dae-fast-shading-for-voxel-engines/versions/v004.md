# Fast Shading for Voxel Engines

## Overview
Fast Shading for Voxel Engines is a CPU-based lighting algorithm for voxel engines that assumes vertical sun rays [S1, unofficial]. It modifies voxel palette indices to simulate lighting by darkening voxels based on the occupancy of their immediate neighbors [S1, unofficial]. It sets itself apart from general-purpose shading models by operating directly on discrete palette indices rather than computing continuous radiance, and by relying on a fixed, pre-defined neighborhood kernel instead of ray-marching for occlusion [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D voxel grid of dimensions $x_{size} \times y_{size} \times z_{size}$, where each voxel stores a palette index [S1, unofficial].
- Output: The same voxel grid with updated palette indices representing shaded colors [S1, unofficial].

**Data Structures:**
- The voxel grid is stored as a 3D array of integers (palette indices) [S1, unofficial].
- Palette indices are grouped into tone groups of 32, where indices 1-32, 33-64, etc., represent dark-to-light gradients [S1, unofficial]. Index 0 represents empty space [S1, unofficial].

**Parameters:**
- $x_{size}, y_{size}, z_{size}$: The dimensions of the current voxel level [S1, unofficial].

**Algorithm Steps:**
1. Iterate through the voxel grid excluding the outermost layer to prevent boundary checks: $x \in [1, x_{size}-2]$, $y \in [1, y_{size}-2]$, $z \in [1, z_{size}-2]$ [S1, unofficial].
2. For each voxel at $(x, y, z)$, retrieve its current palette index: $v = \text{get\_voxel\_pal}(x, y, z)$ [S1, unofficial].
3. If $v = 0$ (empty), skip to the next voxel [S1, unofficial].
4. Calculate the lower bound (color margin) of the current tone group: $\text{color\_margin} = \lfloor (v-1)/32 \rfloor \times 32 + 1$ [S1, unofficial].
5. Initialize a shading offset $d = 0$ [S1, unofficial].
6. Check neighbors and subtract from the palette index based on occupancy: subtract 3 if $(x, y+1, z)$ is occupied; subtract 2 if $(x+1, y+1, z)$, $(x-1, y+1, z)$, $(x+1, y+1, z+1)$, or $(x+1, y+1, z-1)$ is occupied; subtract 1 if $(x+1, y, z+1)$, $(x-1, y, z-1)$, $(x+1, y, z-1)$, or $(x-1, y, z+1)$ is occupied [S1, unofficial].
7. Clamp the result to the lower bound of its tone group: if $v < \text{color\_margin}$, set $v = \text{color\_margin}$ [S1, unofficial].
8. Write the modified index back: $\text{set\_voxel\_pal}(x, y, z, v)$ [S1, unofficial].

**Pseudocode:**
```python
def fast_shade2(voxel_grid, x_size, y_size, z_size):
    for x in range(1, x_size - 1):
        for y in range(1, y_size - 1):
            for z in range(1, z_size - 1):
                voxel = voxel_grid[x, y, z]
                if voxel == 0:
                    continue
                color_margin = ((voxel - 1) // 32) * 32 + 1
                shading_offset = 0
                if voxel_grid[x, y + 1, z] != 0:
                    shading_offset += 3
                if voxel_grid[x + 1, y + 1, z] != 0:
                    shading_offset += 2
                if voxel_grid[x - 1, y + 1, z] != 0:
                    shading_offset += 2
                if voxel_grid[x + 1, y + 1, z + 1] != 0:
                    shading_offset += 2
                if voxel_grid[x + 1, y + 1, z - 1] != 0:
                    shading_offset += 2
                if voxel_grid[x + 1, y, z + 1] != 0:
                    shading_offset += 1
                if voxel_grid[x - 1, y, z - 1] != 0:
                    shading_offset += 1
                if voxel_grid[x + 1, y, z - 1] != 0:
                    shading_offset += 1
                if voxel_grid[x - 1, y, z + 1] != 0:
                    shading_offset += 1
                new_voxel = voxel - shading_offset
                if new_voxel < color_margin:
                    new_voxel = color_margin
                voxel_grid[x, y, z] = new_voxel
```

## Subtopics

### fast_shade1
A faster but less visually detailed variant of fast_shade2, also assuming vertical sun rays [S1, unofficial]. It uses fewer neighbor checks: it subtracts 3 if $(x, y+1, z)$ is occupied, subtracts 2 if $(x+1, y+1, z)$ is occupied, and subtracts 1 if $(x+1, y, z+1)$ or $(x-1, y, z-1)$ is occupied [S1, unofficial]. It shares the same tone-group clamping logic and iteration bounds as fast_shade2 [S1, unofficial]. Choose this variant when performance is critical and the reduced shadow detail is acceptable [S1, unofficial].

## Operating characteristics
- Time Complexity: $O(N)$ where $N$ is the number of voxels in the grid, as each voxel is visited once [S1, unofficial]. The constant factor depends on the number of neighbor checks (10 for fast_shade2, 4 for fast_shade1) [S1, unofficial].
- Memory Complexity: $O(1)$ auxiliary space, as shading is applied in-place [S1, unofficial].
- Performance: Designed for CPU-only rendering, making it suitable for embedded systems or legacy hardware [S1, unofficial].
- Strengths: Extremely fast, simple to implement, no floating-point arithmetic required [S1, unofficial].
- Limitations: Only simulates vertical lighting; no dynamic light sources; no smooth gradients or specular highlights; limited shadow detail compared to ray-marched lighting [S1, unofficial].
- When to use: Real-time voxel engines where lighting is static or pre-computed, and CPU resources are limited [S1, unofficial].
- When not to use: Scenes requiring dynamic lighting, complex materials, or high-fidelity shadows [S1, unofficial].

## Background
Fast Shading for Voxel Engines was developed as part of the DOOMMY voxel engine, a CPU-based voxel game engine using Lua for scripting [S1, unofficial]. The engine was created by jabberx around 2012 [S1, unofficial]. The method was designed to provide basic lighting effects without the computational cost of ray marching or complex shading models, fitting the constraints of a pure CPU renderer [S1, unofficial].
