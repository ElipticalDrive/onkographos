# Multidirectional Occlusion Shading

Also called: Directional Occlusion Shading, Elliptical Kernel Convolution, M-DOS, Multidirectional OS, Multidirectional Occlusion Model

## Overview
Multidirectional Occlusion Shading (M-DOS) is a direct volume rendering technique that simulates directional light scattering to provide realistic soft-shadowing and depth cues [S1]. Unlike the original MS-DOS model which constrains light to the viewing direction, M-DOS allows arbitrary light positioning within the hemisphere defined by the view vector by using elliptical footprints instead of symmetric spherical ones [S1]. It achieves this through incremental convolution of an opacity buffer with a tilted conical phase function, requiring no precomputation [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume dataset, camera parameters (view direction $\mathbf{v}$), light source parameters (position or direction $\mathbf{l}$), aperture angle $\theta$, tilt angle $\alpha$.
*   **Outputs:** Final rendered image with shading effects.

**Data Structures:**
*   **Opacity Buffer ($O_i$):** A 2D texture storing the accumulated opacity for slice $i$. Initialized to zero.
*   **Color Buffer ($C_i$):** A 2D texture storing the accumulated color for slice $i$.
*   **Kernel Texture ($G_\epsilon$):** A $128 \times 128$ texture storing the elliptical weighting function [S1].

**Parameters:**
*   $\theta$ (theta): Aperture angle of the conical phase function.
*   $\alpha$ (alpha): Tilt angle of the conical phase function. Limited to $[0, \pi/2 - \theta)$ to prevent degeneration into hyperbolas or parabolas [S1].
*   $R$: Distance from the scattering point to the slice plane (derived from geometry).

**Geometric Setup:**
The method approximates light transport using a tilted cone-shaped phase function $\Phi_{\theta,\alpha}$ [S1]. The axis of the cone is parallel to the light direction $\mathbf{l}$. The intersection of this cone with the viewing plane (slice plane) forms an ellipse $\epsilon$ [S1].

1.  **Calculate Ellipse Axes:**
    The ellipse is defined by its major axis $A$ and minor axis $B$.
    
    First, calculate distances $a_1$ and $a_2$ from the center $O$ to the edges of the ellipse along the major axis:
    $$ a_1 = R \frac{\sin(\pi/2 - \theta)}{\sin(\pi/2 + \theta - \alpha)} $$
    $$ a_2 = R \frac{\sin(\pi/2 + \theta)}{\sin(\pi/2 - \theta - \alpha)} $$
    
    The major axis $A$ is:
    $$ A = \frac{a_1 + a_2}{2} $$
    
    The distance from the center $O$ to the ellipse center $C$ is:
    $$ kOCk = \frac{|a_2 - a_1|}{2} $$
    
    The minor axis $B$ is calculated using a modified radius $R'$ and modified distance $d'$:
    $$ B = \sqrt{R'^2 - kOCk^2 + d'^2} $$
    *(Note: $R'$ and $d'$ are derived from the geometric intersection analysis involving the circle $\kappa$ intersecting at $C$ [S1].)*

2.  **Define Weighting Function:**
    The weighting function $W_L(x,y)$ at position $(x,y)$ relative to the ellipse center is defined implicitly by $k$:
    $$ W_L(x, y) = 1 - k $$
    where $k$ is the solution to the quadratic equation:
    $$ \frac{(x - (1-k)kOCk)^2}{A^2} + \frac{y^2}{B^2} = k^2 $$
    The point $O$ represents the projection of the light vector, having the highest incident energy [S1].

3.  **Kernel Alignment:**
    The kernel $G_\epsilon$ is aligned with the light direction by rotating it so its major axis aligns with the 2D projection of the light vector $\mathbf{L'}$ on the viewing plane:
    $$ \frac{\mathbf{L'}}{k\mathbf{L'}k} = \frac{\mathbf{OC}}{kOCk} $$
    The kernel is stored in a texture. When parameters change, the kernel is recomputed, scaled to fit a unit square, and rotated [S1].

**Algorithm Steps:**
The rendering proceeds slice-by-slice in front-to-back order. For each slice $i$:

1.  **Compute Modulation Factor:**
    Calculate the visibility $\lambda_i$ for the current slice using the previous slice's opacity buffer $O_{i-1}$ and the elliptical kernel $G_\epsilon$:
    $$ \lambda_i = \frac{1}{1 + G_\epsilon * O_{i-1}} $$
    Here, $*$ denotes convolution [S1].

2.  **Update Opacity Buffer:**
    Convolve the previous opacity buffer with the kernel and add the current slice's opacity $\alpha_i$:
    $$ O_i = G_\epsilon * O_{i-1} + \alpha_i $$

3.  **Modulate Color:**
    Multiply the current slice's color contribution $c_i$ by the modulation factor $\lambda_i$:
    $$ c'_i = c_i \cdot \lambda_i $$

4.  **Composite:**
    Propagate the modified color $c'_i$ and the current opacity $\alpha_i$ to the next composite step using traditional alpha-blending with the over operator [S1].

**Pseudocode:**

```python
def multidirectional_occlusion_shading(volume_data, camera, light_dir, theta, alpha):
    # Initialize buffers
    # O_prev is the opacity buffer from the previous slice, initialized to 0 for the first slice
    # C_prev is the color buffer from the previous slice, initialized to 0 for the first slice
    O_prev = zeros_like(viewport_size)
    C_prev = zeros_like(viewport_size)
    
    # Precompute kernel parameters
    # R is derived from the distance to the current slice plane
    # Calculate a1, a2, A, B, kOCk based on theta, alpha, R
    # Construct the implicit weighting function WL(x,y)
    # Create kernel texture G_epsilon with size 128x128
    # Rotate G_epsilon to align major axis with projection of light_dir onto viewing plane
    
    for slice in volume_data.front_to_back():
        # 1. Get current slice opacity and color
        alpha_i = slice.opacity
        c_i = slice.color
        
        # 2. Calculate modulation factor lambda_i
        # Convolve O_prev with G_epsilon
        blurred_opacity = convolve_2d(O_prev, G_epsilon)
        lambda_i = 1.0 / (1.0 + blurred_opacity)
        
        # 3. Update opacity buffer for next slice
        O_next = blurred_opacity + alpha_i
        
        # 4. Modulate color
        c_modulated = c_i * lambda_i
        
        # 5. Composite with previous color
        # Traditional alpha blending: C_out = C_src * alpha_src + C_dst * (1 - alpha_src)
        # Here, the "source" is the current slice's modulated color and opacity
        # The "destination" is the accumulated color from previous slices
        alpha_blend_factor = alpha_i
        C_next = c_modulated * alpha_blend_factor + C_prev * (1.0 - alpha_blend_factor)
        
        # Update buffers for next iteration
        O_prev = O_next
        C_prev = C_next
        
    return C_prev
```

**Edge Cases and Pitfalls:**
*   **Degenerate Geometry:** The tilt angle $\alpha$ must be limited to $[0, \pi/2 - \theta)$. If $\alpha$ exceeds this range, the cone-section degenerates into hyperbolas or parabolas, breaking the elliptical kernel assumption [S1].
*   **Precision Loss:** Massive downscaling of the coordinate system to fit the kernel into the texture bounding box may lead to a loss of precision [S1].
*   **Light Direction:** The method assumes the light source is within the hemisphere defined by the view vector. Reverting the traversal order for lights in the opposite hemisphere is a potential extension but not part of the core method [S1].

## Operating characteristics
*   **Time Complexity:** The method performs an incremental convolution per slice. The convolution cost depends on the kernel size (fixed at $128 \times 128$ in the source).
*   **Memory Complexity:** Requires storage for two render targets (intermediate image and occlusion buffer) per slice and one kernel texture ($128 \times 128$) [S1].
*   **Performance:** Performs at interactive frame-rates with negligible performance penalty compared to state-of-the-art models [S1]. No precomputation is required [S1].
*   **Strengths:** Allows arbitrary light positioning within the view hemisphere; gradient-free (suitable for noisy data like ultrasound); no precomputation or additional data storage compared to shadow maps or light volumes [S1].
*   **Limitations:** Precision loss due to kernel scaling; limited to the hemisphere defined by the view vector without traversal reversal; artifacts may occur if the light direction changes rapidly without kernel updates [S1].

## Background
*   **Origin:** Developed by Veronika Šoltészová, Daniel Patel, Stefan Bruckner, and Ivan Viola [S1].
*   **Paper:** "A Multidirectional Occlusion Shading Model for Direct Volume Rendering" (2010) [S1].
*   **Development:** Extends the original MS-DOS model by Mathias Schott et al. (2009) [S1]. The original MS-DOS model constrained light to the viewing direction and used symmetric disc-shaped Gaussian kernels. M-DOS removes this constraint using elliptical footprints derived from a tilted cone [S1].
*   **Usage:** Implemented as a plugin to VolumeShop using C++ and OpenGL/GLSL [S1]. Used to visualize CT datasets (gecko, carp, human foot, human hand, human thorax) and 3D cardiac ultrasound [S1]. User studies showed high preference for directional lighting over headlamp or raycasting for depth cues [S1].
