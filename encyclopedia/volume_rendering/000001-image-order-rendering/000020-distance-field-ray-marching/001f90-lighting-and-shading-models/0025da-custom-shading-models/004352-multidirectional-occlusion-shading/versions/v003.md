# Multidirectional Occlusion Shading

Also called: Elliptical Kernel Convolution, M-DOS, Multidirectional OS, Multidirectional Occlusion Model

## Overview
Multidirectional Occlusion Shading (M-DOS) is a direct volume rendering technique that simulates directional light scattering to produce realistic soft-shadowing and depth cues [S2]. Unlike the original MS-DOS model, which constrains the light direction to the viewing direction and uses symmetric disc-shaped Gaussian kernels, M-DOS allows arbitrary light positioning within the hemisphere defined by the view vector by using elliptical footprints derived from a tilted cone [S2]. It achieves this through incremental convolution of an opacity buffer, requiring no precomputation and maintaining interactive frame rates [S2].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Volume dataset, camera parameters (view direction $\mathbf{v}$), light source parameters (position or direction $\mathbf{l}$), aperture angle $\theta$, tilt angle $\alpha$ [S2].
*   **Outputs:** Final rendered image with shading effects [S2].

**Data Structures:**
*   **Opacity Buffer ($O_i$):** A 2D texture storing the accumulated opacity for slice $i$, initialized to zero [S2].
*   **Color Buffer ($C_i$):** A 2D texture storing the accumulated color for slice $i$ [S2].
*   **Kernel Texture ($G_\epsilon$):** A $128 \times 128$ texture storing the elliptical weighting function [S2].

**Parameters:**
*   $\theta$ (theta): Aperture angle of the conical phase function [S2].
*   $\alpha$ (alpha): Tilt angle of the conical phase function, determining the light direction relative to the view [S2].
*   $R$: Distance from the scattering point to the slice plane, derived from the geometric setup [S2].

**Geometric Setup:**
The method approximates light transport using a tilted cone-shaped phase function $\Phi_{\theta,\alpha}$ [S2]. The axis of the cone is parallel to the light direction $\mathbf{l}$ [S2]. The intersection of this cone with the viewing plane (slice plane) forms an ellipse $\epsilon$ [S2]. The ellipse is defined by its major axis $A$ and minor axis $B$ [S2].

1.  **Calculate Ellipse Axes:**
    The distances $a_1$ and $a_2$ from the center $O$ to the edges of the ellipse along the major axis are:
    $$ a_1 = R \frac{\sin(\pi/2 - \theta)}{\sin(\pi/2 + \theta - \alpha)} $$
    $$ a_2 = R \frac{\sin(\pi/2 + \theta)}{\sin(\pi/2 - \theta - \alpha)} $$
    The major axis $A$ is:
    $$ A = \frac{a_1 + a_2}{2} $$
    The distance from the center $O$ to the ellipse center $C$ is:
    $$ kOCk = \frac{|a_2 - a_1|}{2} $$
    The minor axis $B$ is calculated using a modified radius $R'$ and modified distance $d'$:
    $$ B = \sqrt{R'^2 - kOCk^2 + d'^2} $$
    where $R'$ and $d'$ are derived from the geometric intersection analysis involving the circle $\kappa$ intersecting at $C$ [S2].

2.  **Define Weighting Function:**
    The weighting function $W_L(x,y)$ at position $(x,y)$ relative to the ellipse center is defined implicitly by $k$:
    $$ W_L(x, y) = 1 - k $$
    where $k$ is the solution to the quadratic equation:
    $$ \frac{(x - (1-k)kOCk)^2}{A^2} + \frac{y^2}{B^2} = k^2 $$
    The point $O$ represents the projection of the light vector and has the highest incident energy [S2].

3.  **Kernel Alignment:**
    The kernel $G_\epsilon$ is aligned with the light direction by rotating it so its major axis aligns with the 2D projection of the light vector $\mathbf{L'}$ on the viewing plane:
    $$ \frac{\mathbf{L'}}{k\mathbf{L'}k} = \frac{\mathbf{OC}}{kOCk} $$
    The kernel is stored in a texture and updated whenever lighting parameters change [S2].

**Algorithm Steps:**
The rendering proceeds slice-by-slice in front-to-back order [S2]. For each slice $i$:

1.  **Compute Modulation Factor:**
    Calculate the visibility $\lambda_i$ for the current slice using the previous slice's opacity buffer $O_{i-1}$ and the elliptical kernel $G_\epsilon$:
    $$ \lambda_i = \frac{1}{1 + G_\epsilon * O_{i-1}} $$
    where $*$ denotes convolution [S2].

2.  **Update Opacity Buffer:**
    Convolve the previous opacity buffer with the kernel and add the current slice's opacity $\alpha_i$:
    $$ O_i = G_\epsilon * O_{i-1} + \alpha_i $$
    [S2]

3.  **Modulate Color:**
    Multiply the current slice's color contribution $c_i$ by the modulation factor $\lambda_i$:
    $$ c'_i = c_i \cdot \lambda_i $$
    [S2]

4.  **Composite:**
    Propagate the modified color $c'_i$ and the current opacity $\alpha_i$ to the next composite step using traditional alpha-blending with the over operator [S2].

    # Rotate kernel to align major axis with 2D projection of light_dir
    G_epsilon = rotate_kernel(G_epsilon, light_dir)
    
    for slice in volume_slices:
        # 1. Get current slice opacity and color
        alpha_i = min(1.0, max(0.0, slice.opacity))
        c_i = slice.color
        
        # 2. Calculate modulation factor lambda_i
        blurred_opacity = convolve_2d(O_prev, G_epsilon)
        lambda_i = [1.0 / (1.0 + row_val) for row_val in blurred_opacity]
        
        # 3. Update opacity buffer for next slice
        O_next = [[blurred_opacity[r][c] + alpha_i for c in range(viewport_width)] for r in range(viewport_height)]
        
        # 4. Modulate color
        c_modulated = [[c_i[r][c] * lambda_i[r][c] for c in range(viewport_width)] for r in range(viewport_height)]
        
        # 5. Composite using over operator
        C_next = [[(c_modulated[r][c] * alpha_i) + (C_prev[r][c] * (1.0 - alpha_i)) 
                   for c in range(viewport_width)] for r in range(viewport_height)]
        
        # Update buffers for next iteration
        O_prev = O_next
        C_prev = C_next
        
    return C_prev

**Edge Cases and Pitfalls:**
*   **Degenerate Geometry:** The tilt angle $\alpha$ must be limited to $[0, \pi/2 - \theta)$ to prevent the cone-section from degenerating into hyperbolas or parabolas [S2].
*   **Precision Loss:** Massive downscaling of the coordinate system to fit the kernel into the texture bounding box may lead to a loss of precision [S2].
*   **Light Direction:** The method assumes the light source is within the hemisphere defined by the view vector; traversal reversal for opposite hemisphere lights is a potential extension but not part of the core method [S2].
*   **Kernel Updates:** The kernel $G_\epsilon$ is only recomputed when tilt, aperture, light direction, or slice distance changes, which may cause artifacts if parameters change rapidly without triggering an update [S2].

## Operating characteristics
*   **Time Complexity:** The method performs an incremental convolution per slice [S2]. The convolution cost depends on the kernel size, which is fixed at $128 \times 128$ in the source [S2].
*   **Memory Complexity:** Requires storage for two render targets (intermediate image and occlusion buffer) per slice and one kernel texture ($128 \times 128$) [S2].
*   **Performance:** Performs at interactive frame-rates with negligible performance penalty compared to state-of-the-art models [S2]. No precomputation is required [S2].
*   **Strengths:** Allows arbitrary light positioning within the view hemisphere; gradient-free (suitable for noisy data like ultrasound); no precomputation or additional data storage compared to shadow maps or light volumes [S2].
*   **Limitations:** Precision loss due to kernel scaling; limited to the hemisphere defined by the view vector without traversal reversal; artifacts may occur if the light direction changes rapidly without kernel updates [S2].

## Background
*   **Origin:** Developed by Veronika Šoltészová, Daniel Patel, Stefan Bruckner, and Ivan Viola [S2].
*   **Paper:** "A Multidirectional Occlusion Shading Model for Direct Volume Rendering" (2010) [S2].
*   **Development:** Extends the original MS-DOS model by Mathias Schott et al. (2009), which constrained light to the viewing direction and used symmetric disc-shaped Gaussian kernels [S2]. M-DOS removes this constraint using elliptical footprints derived from a tilted cone [S2].
*   **Usage:** Implemented as a plugin to VolumeShop using C++ and OpenGL/GLSL [S2]. Used to visualize CT datasets (gecko, carp, human foot, human hand, human thorax) and 3D cardiac ultrasound [S2]. User studies showed high preference for directional lighting over headlamp or raycasting for depth cues [S2].
