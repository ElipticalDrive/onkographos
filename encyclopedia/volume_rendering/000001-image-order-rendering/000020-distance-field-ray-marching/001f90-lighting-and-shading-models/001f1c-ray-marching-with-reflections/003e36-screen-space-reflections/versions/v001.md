# Screen-Space Reflections

Also called: Screen Space Ray Tracing (SSR)

## Overview
Screen-Space Reflections (SSR) is a global illumination technique that uses rays in screen space to trace against the depth buffer to achieve effects like reflections and color bleeding, which direct illumination cannot achieve [S2]. It sets itself apart from sibling methods like [Ray Marching with Reflections](1963-ray-marching-with-reflections.md) by operating entirely within the 2D screen coordinate system and utilizing the existing depth buffer, rather than marching through a 3D volume or scene graph. This makes it significantly cheaper than full ray tracing but limited to visible geometry.

## How it works
**Inputs:**
*   Shaded point position in world space ($P_{world}$).
*   View vector ($V$) from the camera to $P_{world}$.
*   Surface normal ($N$) at $P_{world}$.
*   Depth buffer (Z-buffer) containing depth values for all visible pixels.
*   Color buffer (G-Buffer or Final Color Buffer) containing radiance/color values for all visible pixels.
*   Screen resolution ($W \times H$).

**Outputs:**
*   Reflected color contribution ($C_{refl}$) for the shaded point.

**Data Structures:**
*   **Depth Buffer:** A 2D array of size $W \times H$, storing depth values ($z$) typically in clip space or view space.
*   **Color Buffer:** A 2D array of size $W \times H$, storing RGB(A) color values.

**Steps:**
1.  **Reflect View Vector:** Calculate the reflection direction $R$ by reflecting the view vector $V$ along the surface normal $N$.
    $$ R = V - 2(V \cdot N)N $$
    Where $V$ and $N$ are normalized. Note: $V$ is usually defined as the vector from the camera to the point, so the ray direction for tracing is $R$.

2.  **Initialize Ray:** Start a ray at $P_{world}$ with direction $R$.

3.  **Iterate Ray Steps:** Advance the ray in screen space. For each step $i$:
    a.  Compute the current world position $P_i$ of the ray.
    b.  Project $P_i$ into screen space to get pixel coordinates $(u_i, v_i)$.
    c.  Fetch the depth value $z_{buffer}$ from the Depth Buffer at $(u_i, v_i)$.
    d.  Fetch the depth value $z_{ray}$ of the current ray point $P_i$ in the same coordinate system as the depth buffer.
    e.  **Intersection Test:**
        *   If $z_{ray} > z_{buffer}$ (assuming depth increases away from camera), the ray has passed behind the geometry in the depth buffer. This indicates an intersection occurred between the previous step and the current step.
        *   If $z_{ray} < z_{buffer}$, the ray is in front of the geometry; continue to the next step.
        *   If the ray goes off-screen or exceeds a maximum distance, terminate.

4.  **Binary Search Refinement:** If an intersection is detected between step $i-1$ and step $i$, perform a binary search between these two positions to find a more precise intersection point $P_{hit}$. This improves accuracy because the initial step size is arbitrary [S1, unofficial].

5.  **Sample Color:** Once $P_{hit}$ is determined, project it to screen space $(u_{hit}, v_{hit})$. Sample the Color Buffer at $(u_{hit}, v_{hit})$ to obtain the incident radiance $C_{refl}$.

6.  **Shade:** Combine $C_{refl}$ with the base shading of the surface.

**Pseudocode:**
```python
def screen_space_reflections(P_world, V, N, depth_buffer, color_buffer, W, H, max_steps, step_size):
    # Reflect view vector to get ray direction
    # V is vector from camera to point, N is surface normal
    R = V - 2 * dot(V, N) * N
    
    current_pos = P_world
    prev_pos = P_world
    
    for i in range(max_steps):
        # Advance ray
        current_pos = prev_pos + R * step_size
        
        # Project current_pos to screen space
        u, v = world_to_screen(current_pos, W, H)
        
        # Check bounds
        if not (0 <= u < W and 0 <= v < H):
            return 0.0 # Off-screen
            
        # Get depth values
        z_ray = get_depth_view_space(current_pos)
        z_buffer = depth_buffer[v][u]
        
        # Check for intersection
        # Assuming depth buffer stores depth away from camera
        if z_ray > z_buffer:
            # Intersection occurred between prev_pos and current_pos
            # Perform binary search to refine intersection point
            hit_pos = binary_search_depth(prev_pos, current_pos, depth_buffer, W, H)
            
            # Sample color buffer at hit position
            u_hit, v_hit = world_to_screen(hit_pos, W, H)
            if 0 <= u_hit < W and 0 <= v_hit < H:
                return color_buffer[v_hit][u_hit]
            else:
                return 0.0
        else:
            prev_pos = current_pos
            
    return 0.0 # No intersection found

def binary_search_depth(start_pos, end_pos, depth_buffer, W, H):
    # Standard binary search to find where z_ray crosses z_buffer
    low = start_pos
    high = end_pos
    for _ in range(10): # Fixed iterations for stability
        mid = low + (high - low) / 2
        u, v = world_to_screen(mid, W, H)
        if not (0 <= u < W and 0 <= v < H):
            return mid # Fallback
            
        z_ray = get_depth_view_space(mid)
        z_buffer = depth_buffer[v][u]
        
        if z_ray > z_buffer:
            high = mid
        else:
            low = mid
    return low
```

**Parameters:**
*   `max_steps`: Maximum number of ray steps. Typical value: Not given in the sources.
*   `step_size`: Distance to advance the ray per step. Typical value: Not given in the sources.

**Edge Cases and Pitfalls:**
*   **Lambertian Limitation:** The approach only works on Lambertian surfaces [S1, unofficial].
*   **Screen Boundary:** It can only reflect what is currently on screen [S1, unofficial]. Geometry outside the viewport is not reflected.
*   **Precision:** Initial intersection location is imprecise due to unknown distance traveled between steps, necessitating binary search [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of ray steps and pixels processed. Each pixel requires a depth buffer lookup and potentially a binary search.
*   **Memory Complexity:** $O(W \times H)$ for the depth and color buffers.
*   **Strengths:** Real-time performance; leverages existing rasterization buffers; effective for mirror and glossy surfaces [S2].
*   **Limitations:** Limited to visible geometry; artifacts at screen edges; requires depth buffer; limited to Lambertian surfaces according to source [S1, unofficial].
*   **When to use:** Real-time rendering of reflections and color bleeding where full ray tracing is too expensive.
*   **When not to use:** When reflections of off-screen objects are required, or for non-Lambertian surfaces if the source constraint is strict.

## Background
Screen-Space Reflections (SSR) was first presented by Sousa [S1, unofficial]. It is commonly found in real-time scenarios to render reflections [S1, unofficial]. It is considered the most general method in real-time rendering for global illumination using screen space techniques, achieving honorable global illumination effects for both mirror and glossy surfaces [S2].
