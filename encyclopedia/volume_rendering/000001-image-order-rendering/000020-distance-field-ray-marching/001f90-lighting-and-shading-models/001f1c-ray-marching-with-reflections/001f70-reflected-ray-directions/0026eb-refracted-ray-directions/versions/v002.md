# Refracted Ray Directions

Also called: refract

## Overview
Calculates the direction of a ray after it passes through an interface between two media with different refractive indices, handling both entry and exit scenarios for spherical objects. It sets itself apart from [Reflected Ray Directions](2028-reflected-ray-directions.md) by computing the transmitted vector rather than the mirrored vector, and from [Fresnel Reflection/Refraction](9067-fresnel-reflection-refraction.md) by providing the geometric direction vector rather than the energy weighting factor.

## How it works
**Inputs:**
- `ob`: The intersected object (must support `getType()`, `getRefractive()`, and `surfaceNormal()`).
- `point`: The 3D intersection point.
- `ray`: The incoming ray direction (normalized).
- `from`: The ray origin (used to determine normal orientation).
- `ref`: The current medium's refractive index (passed by reference, updated on exit).

**Outputs:**
- `Vector3`: The normalized refracted ray direction.
- `ref`: Updated to the object's refractive index.

**Data Structures:**
- `Vector3`: A 3D vector with components `x`, `y`, `z`.
- `float`: Standard 32-bit floating point.

**Steps:**
1. Calculate the surface normal $N$ at `point` relative to `from`.
2. Set $n_1$ to the current refractive index `ref`.
3. Set $n_2$ to the object's refractive index `ob->getRefractive()`.
4. Calculate $s = \text{dot}(\text{ray}, N)$.
5. If the object is a sphere and $s > 0$ (indicating the ray is exiting the sphere), swap $n_1$ and $n_2$.
6. Calculate the ratio $n = n_1 / n_2$.
7. Calculate the refracted direction using the formula:
   $$ \text{refracted} = n \cdot (\text{ray} - s \cdot N) - N \cdot \sqrt{1 - n^2 \cdot (1 - s^2)} $$
8. Normalize the result.
9. Update `ref` to $n_2$.

**Pseudocode:**
```python
def refract(ob, point, ray, from, ref):
    # Calculate surface normal N
    N = surface_normal(ob, point, from)
    
    # Set refractive indices
    n1 = ref
    n2 = ob.get_refractive()
    
    # Calculate dot product
    s = dot(ray, N)
    
    # Handle exit from sphere
    if ob.get_type() == "sphere" and s > 0:
        n1, n2 = n2, n1
        
    # Ratio of indices
    n = n1 / n2
    
    # Calculate refracted vector
    # term1 = n * (ray - s * N)
    term1 = n * (ray - s * N)
    
    # term2 = N * sqrt(1 - n^2 * (1 - s^2))
    # Note: 1 - s^2 is equivalent to 1 - dot(ray, N)^2
    # This represents the squared magnitude of the component of ray perpendicular to N
    k = 1.0 - n * n * (1.0 - s * s)
    
    # Check for total internal reflection
    if k < 0:
        # Total internal reflection occurs; return null or handle as reflection
        # In this specific implementation context, this branch is not explicitly 
        # handled in the source snippet, but physically k < 0 implies no refraction.
        return None 
        
    term2 = N * sqrt(k)
    
    refracted = term1 - term2
    
    # Normalize
    refracted = refracted.normalize()
    
    # Update current refractive index
    ref = n2
    
    return refracted
```

**Edge Cases:**
- **Total Internal Reflection:** If $1 - n^2(1 - s^2) < 0$, refraction is impossible. The source code does not explicitly handle this return value in the snippet, but it is a physical constraint [S1, unofficial].
- **Sphere Exit Detection:** The check `s > 0` combined with `getType() == sphere` is specific to the source implementation for determining if the ray is exiting a sphere. For general surfaces, normal orientation is usually determined by the sign of the dot product with the view vector or ray origin [S1, unofficial].

## Subtopics

### [Fresnel Reflection/Refraction](9067-fresnel-reflection-refraction.md)
Calculates the Fresnel reflectance for unpolarized light at an interface between two media with different indices of refraction. It determines the ratio of reflected to refracted light energy, which is essential for physically based rendering of dielectrics and metals. It sets itself apart from sibling methods by providing the weighting factor ($k_R$) used to blend reflected and refracted ray contributions, rather than calculating the ray directions themselves.

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ per intersection, involving basic arithmetic operations and one square root.
- Memory: $O(1)$, requiring only a few scalar variables.

**Strengths and Limitations:**
- **Strengths:** Simple to implement; handles the specific case of spherical objects correctly regarding entry/exit index swapping.
- **Limitations:** The sphere-specific exit logic (`s > 0` check) is not generalizable to arbitrary convex shapes without modification. Does not handle total internal reflection explicitly in the provided snippet.

**When to use:**
- Use when rendering transparent spherical objects or when the specific implementation details of the source code are required.
- Not suitable for general-purpose path tracers without modification to handle arbitrary surface normals and total internal reflection.

## Background
Originated in the context of volumetric photon mapping implementations, specifically within the `jacklv123/Volumetric-photon-mapping` repository [S1, unofficial]. The method is part of a broader ray tracing pipeline that includes reflection and photon gathering.
