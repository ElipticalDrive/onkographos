# Ray Marching Dither


## Overview
Ray Marching Dither is a family of techniques used in distance-field ray marching to suppress banding and layering artifacts caused by low step counts or discrete sampling intervals [S1, S2, S3, unofficial]. Unlike standard fixed-step marching which produces visible intensity bands, these methods introduce controlled randomness to the sampling process—either by perturbing the ray's UV coordinates based on hit distance [S1, unofficial], offsetting the initial depth using a blue noise texture [S2, unofficial], or jittering the step size itself [S3, unofficial]. This breaks up coherent aliasing patterns while maintaining the sharpness of volumetric features like god rays [S3, unofficial].

## How it works
**Inputs and Outputs:**
- Distance-Based UV Perturbation: Inputs are fragment UV coordinates (`vUv`), hit distance (`t`), and dither strength factor (`c_fDither`). Outputs are perturbed UV coordinates (`uv`) and reconstructed ray origin (`ro`) and direction (`rd`) [S1, unofficial].
- Blue Noise Dithering: Inputs are fragment coordinates (`gl_FragCoord`), frame count (`uFrame`), blue noise texture sampler (`uBlueNoise`), and march step size (`MARCH_SIZE`). Output is a raymarched result with an offset initial depth [S2, unofficial].
- Ray Marching Jittering: Inputs are a fixed step size and a random number generator. Output is a ray position with jittered step advancement [S3, unofficial].

**Data Structures:**
- `vUv`: 2D vector of fragment coordinates [S1, unofficial].
- `t`: Scalar float representing the ray hit distance [S1, unofficial].
- `c_fDither`: Scalar float parameter [S1, unofficial].
- `uBlueNoise`: 2D sampler texture containing a blue noise pattern [S2, unofficial].
- `gl_FragCoord`: Built-in fragment coordinate vector [S2, unofficial].
- `MARCH_SIZE`: Scalar float for the fixed step size [S2, unofficial].

**Numbered Steps:**
1. **Distance-Based UV Perturbation:** Calculate the dither magnitude based on the squared hit distance and the strength factor: $d = t^2 \cdot c_{\text{fDither}}$ [S1, unofficial]. Generate two random values using a pseudo-random function seeded by the fragment UV plus fixed offsets $(0.12, 0.32)$ for X and $(0.42, 0.52)$ for Y [S1, unofficial]. Perturb the UV coordinates: $uv.x = vUv.x + \text{rand}(vUv + (0.12, 0.32)) \cdot d - \frac{d}{2.0}$ and $uv.y = vUv.y + \text{rand}(vUv + (0.42, 0.52)) \cdot d - \frac{d}{2.0}$ [S1, unofficial]. Reconstruct the ray origin and direction using the perturbed `uv` values and the camera setup [S1, unofficial].
2. **Blue Noise Dithering:** Sample the blue noise texture at normalized fragment coordinates: $\text{noise\_coord} = \frac{gl\_FragCoord.xy}{1024.0}$ and $\text{blueNoise} = \text{texture2D}(uBlueNoise, \text{noise\_coord}).r$ [S2, unofficial]. Compute the fractional offset: $\text{offset} = \text{fract}(\text{blueNoise})$ [S2, unofficial]. Add the offset scaled by the march step size to the initial depth before entering the raymarch loop: $\text{depth} = \text{MARCH\_SIZE} \cdot \text{offset}$ and $\mathbf{p} = \mathbf{rayOrigin} + \text{depth} \cdot \mathbf{rayDirection}$ [S2, unofficial]. For temporal variation, add a frame-dependent value before fracturing: $\text{offset} = \text{fract}(\text{blueNoise} + \frac{\text{float}(uFrame \% 32)}{\sqrt{0.5}})$ [S2, unofficial].
3. **Ray Marching Jittering:** During the raymarch loop, instead of advancing by a fixed step size, march the ray a random distance $\Delta t \in [0.5 \cdot \text{step\_size}, 1.5 \cdot \text{step\_size}]$ [S3, unofficial]. Apply this jittered step to both the photon gathering and lookup stages [S3, unofficial].

**Formulas with Symbols Defined:**
- $d = t^2 \cdot c_{\text{fDither}}$: $t$ is hit distance, $c_{\text{fDither}}$ is dither strength [S1, unofficial].
- $uv.x = vUv.x + \text{rand}(vUv + (0.12, 0.32)) \cdot d - \frac{d}{2.0}$: $vUv$ is fragment UV, $\text{rand}$ is pseudo-random function [S1, unofficial].
- $\text{offset} = \text{fract}(\text{blueNoise} + \frac{\text{float}(uFrame \% 32)}{\sqrt{0.5}})$: $uFrame$ is frame count [S2, unofficial].
- $\Delta t \in [0.5 \cdot \text{step\_size}, 1.5 \cdot \text{step\_size}]$: step size is the fixed march increment [S3, unofficial].

**Parameters with Typical Values:**
- `c_fDither`: Dithering strength factor. Typical value: $0.001$ [S1, unofficial].
- `MARCH_SIZE`: Fixed step size for the raymarch loop [S2, unofficial].
- `uBlueNoise`: 2D blue noise texture sampler [S2, unofficial].

**Edge Cases and Pitfalls:**
- The perturbation is distance-dependent ($t^2$), meaning artifacts further from the camera are dithered more aggressively [S1, unofficial].
- Single-frame renders may exhibit visible noise patterns [S2, unofficial]. This is mitigated by adding a temporal component based on the frame count [S2, unofficial].
- Bicubic filtering is recommended for the blue noise texture to fix remaining noise artifacts [S2, unofficial].
- Fixed step sizes introduce clearly defined bands of intensity in volume regions [S3, unofficial].

**Pseudocode:**
```python
import math

def rand(x, y):
    # [G] Standard pseudo-random hash; GLSL equivalent is fract(sin(dot(vec2(x,y), vec2(12.9898,78.233))))
    return math.sin(x * 127.1 + y * 311.7) * 43758.5453 % 1.0

def fract(x):
    return x - math.floor(x)

def ray_marching_dither(vUv, t, c_fDither, gl_FragCoord, uFrame, uBlueNoise, MARCH_SIZE, step_size, rayOrigin, rayDirection):
    # Variant 1: Distance-Based UV Perturbation
    d = t * t * c_fDither
    uv_x = vUv[0] + rand(vUv[0] + 0.12, vUv[1] + 0.32) * d - d / 2.0
    uv_y = vUv[1] + rand(vUv[0] + 0.42, vUv[1] + 0.52) * d - d / 2.0
    # [G] Reconstruct ray origin and direction from perturbed UVs using camera parameters

    # Variant 2: Blue Noise Dithering
    noise_coord = (gl_FragCoord[0] / 1024.0, gl_FragCoord[1] / 1024.0)
    # [G] Sample 2D blue noise texture at normalized coordinates
    blueNoise = uBlueNoise.sample(noise_coord).r
    offset = fract(blueNoise + (uFrame % 32) / math.sqrt(0.5))
    depth = MARCH_SIZE * offset
    p = rayOrigin + depth * rayDirection

    # Variant 3: Ray Marching Jittering
    jittered_step = step_size * (0.5 + rand(0, 0))

```

## Subtopics

### Blue Noise Dithering
A technique that uses a blue noise texture to offset the sampling start point along the ray, reducing banding and layering artifacts caused by low step counts [S2, unofficial]. It is chosen when volumetric layering is prominent and temporal coherence can be maintained via frame-dependent offsets. It differs from UV perturbation by operating in depth space rather than UV space.

### Ray Marching Jittering
A technique that adds random variation to the ray marching step sizes (specifically between 0.5x and 1.5x the fixed step size) to counteract aliasing artifacts in volumes [S3, unofficial]. It is chosen for participating media where fixed stepping causes visible intensity bands [S3, unofficial]. It differs from texture-based dithering by modifying the integration step directly rather than the initial conditions or UVs [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources [S1, S2, S3, unofficial].
- **Memory Complexity:** Not given in the sources [S1, S2, S3, unofficial].
- **Performance:** All variants allow for lower step counts while maintaining visual quality, effectively trading a small amount of randomness for reduced computational cost or improved visual fidelity [S2, S3, unofficial].
- **Strengths:** Effectively removes banding and layering artifacts [S1, S2, S3, unofficial]. Keeps volumetric features like god rays sharp [S3, unofficial].
- **Limitations:** Blue noise patterns can be noticeable in single frames without temporal variation [S2, unofficial]. UV perturbation is distance-dependent, which may cause inconsistent dithering strength across the scene [S1, unofficial].
