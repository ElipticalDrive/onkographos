# Blinn-Phong Shading in Volume Rendering

Also called: Shaded Volume Rendering (SVR)

## Overview
Blinn-Phong Shading in Volume Rendering is a technique that applies the Blinn-Phong lighting model to volume textures during ray marching to produce shaded, three-dimensional appearances [S1, unofficial]. It distinguishes itself from unshaded methods like Maximum Intensity Projection (MIP) by incorporating surface normals and light interaction, while differing from Phong shading by using the half-vector for specular highlights, which is computationally cheaper and smoother [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D volume texture (`volumeTexture`), a 1D transfer function texture (`tfTexture`), a transformation matrix (`transform`), and lighting parameters (`lightPos`, `lightColour`, `diffuse`, `specular`, `ambient`, `tfSize`) [S1, unofficial].
*   **Output:** A 2D color image with accumulated alpha [S1, unofficial].

**Data Structures:**
*   **Uniforms Struct:**
    *   `transform`: `mat4x4<f32>` (4x4 matrix) [S1, unofficial].
    *   `lightPos`: `vec3<f32>` [S1, unofficial].
    *   `lightColour`: `vec3<f32>` [S1, unofficial].
    *   `diffuse`: `f32` [S1, unofficial].
    *   `specular`: `f32` [S1, unofficial].
    *   `ambient`: `f32` [S1, unofficial].
    *   `tfSize`: `f32` [S1, unofficial].
*   **Textures:**
    *   `volumeTexture`: `texture_3d<f32>` at binding 0 [S1, unofficial].
    *   `volumeSampler`: sampler at binding 1 [S1, unofficial].
    *   `tfTexture`: `texture_1d<f32>` at binding 3 [S1, unofficial].

**Steps:**

1.  **Vertex Shader Setup:** Generate a full-screen triangle using vertex indices to produce positions `(-1, 3)`, `(-1, -1)`, and `(3, -1)` in clip space [S1, unofficial].
2.  **Ray Generation:** For each fragment with screen coordinate `coord.xy`, compute the ray origin `pos` and direction `dir` by transforming screen coordinates:
    *   `pos = transform * vec4(coord.xy, 0.0, 1.0)`
    *   `dir = transform * vec4(0.0, 0.0, 1.0, 0.0)` [S1, unofficial].
3.  **Ray-Box Intersection:** Compute entry (`near`) and exit (`far`) distances along the ray axis-aligned bounding box (AABB) of the volume (defined by `bboxMin = (0,0,0)` and `bboxMax = volume dimensions`):
    *   `inv_dir = 1.0 / dir`
    *   `bot = inv_dir * (bboxMin - pos)`
    *   `top = inv_dir * (bboxMax - pos)`
    *   `rmin = min(top, bot)`
    *   `rmax = max(top, bot)`
    *   `near = max(rmin.x, rmin.y, rmin.z)`
    *   `far = min(rmax.x, rmax.y, rmax.z)`
    *   Clamp `near` to `0` if negative [S1, unofficial].
4.  **Ray Marching Loop:** Iterate from `k = near` to `far` (in integer steps, typically slice indices):
    *   **Position Calculation:** Compute the 3D position in volume space: `transformed = transform * vec4(coord.xy, f32(k), 1.0)` [S1, unofficial].
    *   **Normalization:** Normalize coordinates to `[0, 1]`: `coords = transformed.xyz / volume_dimensions` [S1, unofficial].
    *   **Intensity Sampling:** Sample the volume texture: `sample = textureSample(volumeTexture, volumeSampler, coords)` [S1, unofficial].
    *   **Intensity Conversion:** Convert the RG8 format sample to a normalized 16-bit intensity value:
        *   `intensity = (sample.x + sample.y * 255.0) / 256.0` [S1, unofficial].
    *   **Normal Estimation:** Compute the gradient using central differences. For each axis `i` (x, y, z), sample at `pos + offset` and `pos - offset` (where `offset` is a small step in volume space, typically 1 unit or normalized):
        *   `delta[i] = sample(pos + offset_i) - sample(pos - offset_i)`
        *   `normal = normalize(delta)` [S1, unofficial].
    *   **Transfer Function Lookup:** Map intensity `val` to a 1D texture index:
        *   `tfIndex = val * tfSize`
        *   `colour = textureSample(tfTexture, tfSampler, vec2(tfIndex, 0.5))` [S1, unofficial].
    *   **Blinn-Phong Lighting:**
        *   `lightDir = normalize(lightPos - pos)`
        *   `viewDir = normalize(-pos)` (assuming camera at origin in view space, or derived from ray direction) [S1, unofficial].
        *   `halfDir = normalize(lightDir + viewDir)`
        *   `diffuse = max(0.0, dot(normal, lightDir)) * diffuse`
        *   `specular = pow(max(0.0, dot(normal, halfDir)), shininess) * specular`
        *   `litColor = lightColour * (colour.rgb * (diffuse + ambient) + specular)` [S1, unofficial].
    *   **Front-to-Back Composition:** Update accumulated color `accColour` using alpha blending:
        *   `alpha = (1.0 - accColour.a) * colour.a`
        *   `accColour.rgb += alpha * litColor.rgb`
        *   `accColour.a += alpha`
        *   Break if `accColour.a >= 0.95` [S1, unofficial].

**Parameters:**
*   `shininess`: Constant float value set to `10.0` [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** The intensity conversion from RG8 to 16-bit normalized float requires careful handling to avoid quantization artifacts [S1, unofficial].
*   **Boundaries:** Ray-box intersection must handle rays that do not intersect the volume (where `near > far`) by skipping the marching loop [S1, unofficial].
*   **Normal Estimation:** Central differences require sampling outside the volume bounds if the step size is large; clamping or mirroring may be needed [G].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of samples along the ray, which depends on the volume depth and step size. The breaking condition `accColour.a >= 0.95` can reduce average samples per ray [S1, unofficial].
*   **Memory Complexity:** Dominated by the storage of the 3D volume texture and the 1D transfer function texture [S1, unofficial].
*   **Strengths:** Provides realistic shading with specular highlights, enhancing depth perception [S1, unofficial].
*   **Limitations:** Computationally more expensive than unshaded methods due to normal calculation and lighting per sample [S1, unofficial].
*   **When to Use:** When visual realism and depth cues are prioritized over performance [S1, unofficial].
*   **When Not to Use:** For real-time applications with very large volumes or limited GPU resources where unshaded methods like MIP are sufficient [S1, unofficial].

## Background
Blinn-Phong Shading in Volume Rendering was implemented in the `ossium` project, a WebGPU-based volume rendering application for displaying DICOM files in the browser [S1, unofficial]. It is one of two techniques implemented in `ossium`, the other being Multi-Planar Reformatting (MPR) using MIP [S1, unofficial].
