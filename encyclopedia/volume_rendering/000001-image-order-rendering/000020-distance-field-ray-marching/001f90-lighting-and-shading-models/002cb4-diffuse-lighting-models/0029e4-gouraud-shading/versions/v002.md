# Gouraud Shading

Also called: intensity interpolation shading, smooth shading

## Overview
Gouraud shading is a method for rendering smooth surfaces by computing lighting colors at mesh vertices and linearly interpolating these intensities across the resulting facets [S1][S2, unofficial]. It solves the problem of faceted appearance in polygonal approximations of curved surfaces by creating continuous color gradients [S2, unofficial]. Unlike Phong shading, which interpolates normals and recomputes lighting per pixel, Gouraud shading performs the lighting calculation only at vertices, making it computationally cheaper but prone to artifacts like missing specular highlights [S1].

## How it works
**Inputs:**
- A mesh defined by vertices $\mathbf{v}_i$ and faces (triangles) connecting them.
- Per-vertex normal vectors $\mathbf{n}_i$.
- Light source direction $\mathbf{l}$ and view direction $\mathbf{v}$ (or camera position).
- Material properties (diffuse color $C_d$, ambient color $C_a$).

**Outputs:**
- A rasterized image with smooth color gradients across polygons.

**Data Structures:**
- **Vertex Buffer:** Stores position $\mathbf{p}_i$ and normal $\mathbf{n}_i$ for each vertex $i$.
- **Index Buffer:** Defines triangles by referencing vertex indices.
- **Frame Buffer:** Stores the final interpolated color for each pixel.

**Steps:**
1. **Normal Averaging:** For curved surfaces, compute the normal $\mathbf{n}_i$ for each vertex $i$ by averaging the normals of all adjacent faces $F_j$ that share the vertex:
   $$ \mathbf{n}_i = \frac{\sum_{j \in \text{adj}(i)} \mathbf{n}_{F_j}}{\|\sum_{j \in \text{adj}(i)} \mathbf{n}_{F_j}\|} $$
   If normals are not averaged, the discontinuity in slope results in a faceted or gem-like appearance [S2, unofficial]. For planar surfaces, the same normal is applied to all defining vertices [S2, unofficial].

2. **Vertex Color Computation:** For each vertex $i$, compute the color $C_i$ using a lighting model (typically Lambertian diffuse + ambient). Let $\mathbf{n}_i$ be the normalized vertex normal, $\mathbf{l}$ be the normalized light direction, and $\mathbf{v}$ be the view direction. The diffuse component is:
   $$ C_{diffuse, i} = C_d \cdot \max(0, \mathbf{n}_i \cdot \mathbf{l}) $$
   The total vertex color is:
   $$ C_i = C_{ambient} + C_{diffuse, i} $$
   [S1][S2, unofficial]. Note: Specular terms are often omitted or approximated poorly in basic Gouraud shading because the peak may fall between vertices [S1].

3. **Rasterization and Interpolation:** For each triangle defined by vertices $i, j, k$:
   - Compute the barycentric coordinates $(\alpha, \beta, \gamma)$ for each pixel inside the triangle.
   - Interpolate the color $C$ at the pixel:
     $$ C_{pixel} = \alpha C_i + \beta C_j + \gamma C_k $$
   [S1][S2, unofficial].

**Pseudocode:**
```python
def gouraud_shading(mesh, light_dir, view_dir, ambient_color, diffuse_color):
    # Step 1: Compute vertex normals
    vertex_normals = {}
    for face in mesh.faces:
        v0, v1, v2 = face.vertices
        # Compute face normal
        edge1 = v1.pos - v0.pos
        edge2 = v2.pos - v0.pos
        face_normal = normalize(cross(edge1, edge2))
        
        # Accumulate normal for each vertex
        for v in [v0, v1, v2]:
            if v.id not in vertex_normals:
                vertex_normals[v.id] = vec3(0, 0, 0)
            vertex_normals[v.id] += face_normal
    
    # Normalize averaged normals
    for v_id in vertex_normals:
        vertex_normals[v_id] = normalize(vertex_normals[v_id])

    # Step 2: Compute vertex colors
    vertex_colors = {}
    for v in mesh.vertices:
        n = vertex_normals[v.id]
        # Lambertian diffuse
        diff = max(0, dot(n, normalize(light_dir)))
        color = ambient_color + diffuse_color * diff
        vertex_colors[v.id] = color

    # Step 3: Rasterize triangles
    for face in mesh.faces:
        v0, v1, v2 = face.vertices
        c0 = vertex_colors[v0.id]
        c1 = vertex_colors[v1.id]
        c2 = vertex_colors[v2.id]
        
        # Barycentric interpolation for each pixel in triangle bounding box
        for pixel in pixels_in_triangle(v0.pos, v1.pos, v2.pos):
            alpha, beta, gamma = barycentric_coords(pixel, v0.pos, v1.pos, v2.pos)
            final_color = alpha * c0 + beta * c1 + gamma * c2
            set_pixel_color(pixel, final_color)
```

**Parameters:**
- **Shading Model:** `GL_SMOOTH` (or equivalent) enables Gouraud shading; `GL_FLAT` disables it [S2, unofficial].
- **Normal Averaging:** Essential for curved surfaces [S2, unofficial].

**Edge Cases:**
- **Faceted Appearance:** Occurs if normals are not averaged for curved surfaces [S2, unofficial].
- **Specular Artifacts:** Sharp specular highlights may be missed if they fall between vertices, as the interpolation is linear in color space, not in normal space [S1].

## Operating characteristics
- **Time Complexity:** $O(V + P)$, where $V$ is the number of vertices and $P$ is the number of pixels. Lighting is computed once per vertex, and interpolation is linear per pixel [S1][S2, unofficial].
- **Memory Complexity:** $O(V)$ to store vertex colors and normals.
- **Performance:** Significantly faster than Phong shading because it avoids per-pixel lighting calculations and normal normalization [S1].
- **Strengths:** Simple implementation, low computational cost, smooth appearance for diffuse surfaces [S2, unofficial].
- **Limitations:** Cannot accurately represent sharp specular highlights; color interpolation can cause "Mach bands" or unnatural gradients if lighting changes rapidly [S1].
- **When to Use:** Real-time rendering with limited computational resources, diffuse-dominated scenes, or when specular highlights are not critical [S2, unofficial].
- **When Not to Use:** Scenes requiring accurate specular reflections or high-fidelity lighting on curved surfaces [S1].

## Background
Gouraud shading was introduced by Henri Gouraud in 1971 [S1]. It is also known as intensity interpolation shading [S1]. The method was widely adopted in early computer graphics systems and is supported by OpenGL via `glShadeModel(GL_SMOOTH)` [S2, unofficial]. It is used in applications like Smokeview for visualizing fire dynamics simulation data, where smooth shading helps convey the three-dimensionality of blockages and iso-surfaces [S2, unofficial].
