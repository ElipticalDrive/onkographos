# Diffuse Lighting for Volume Ray Casting

Also called: Gradient Normal Lighting, Gradient-based Lighting in MRT Raycasting

## Overview
Diffuse Lighting for Volume Ray Casting illuminates a volume by calculating normals for every voxel using finite differences of the scalar field, then applying a diffuse lighting model [S1]. It provides geometric cues that allow standard diffuse lighting models to interact with the volume's internal structure [S1].

## How it works
The method operates during the ray casting loop at the shading stage for each sampled voxel [S1]. It requires access to the scalar field values of the current sample and its immediate neighbors along the three principal axes [S1].

### Inputs and Outputs
*   **Inputs**:
    *   `scalar`: The scalar value $V(x, y, z)$ at the current ray position `tr` [S1].
    *   `tr`: The current 3D texture coordinate (ray position) in the volume [S1].
    *   `voxelJump`: A uniform vector $(dx, dy, dz)$ representing the distance between adjacent voxels [S1].
    *   `lightDir`: A uniform vector representing the direction to the light source in eye space [S1].
    *   `diffColor`: A uniform vector representing the diffuse color of the light [S1].
    *   `samp`: The current sample color (RGB) derived from the transfer function [S1].
*   **Outputs**:
    *   Updated `samp` color, modulated by the diffuse lighting contribution [S1].

### Data Structures
The method operates directly on the volume texture without requiring additional data structures [S1].

### Steps
1.  Sample the current voxel's scalar value `scalar` [S1].
2.  Calculate the gradient vector (normal) by subtracting the current scalar from its neighbors in the X, Y, and Z directions using finite differences [S1].
3.  Normalize the gradient vector to get the surface normal [S1].
4.  Calculate the diffuse contribution using the dot product of the light direction and the normal, clamped to 0 [S1].
5.  Multiply the sample's color by the diffuse contribution and the light color [S1].

### Formulas
Let $V(x, y, z)$ be the scalar value at position $(x, y, z)$ [S1]. Let $dx, dy, dz$ be the voxel jumps [S1].

The gradient components are calculated as [S1]:
$$ n_x = V(x+dx, y, z) - V(x, y, z) $$
$$ n_y = V(x, y+dy, z) - V(x, y, z) $$
$$ n_z = V(x, y, z-dz) - V(x, y, z) $$

The normal vector $N$ is [S1]:
$$ N = \text{normalize}(n_x, n_y, n_z) $$

The diffuse factor $D$ is [S1]:
$$ D = \max(\text{dot}(L, N), 0.0) $$

The final output color $C_{out}$ (RGB part of the sample) is [S1]:
$$ C_{out} = C_{in} \times D \times C_{light} $$

Where $C_{in}$ is the original sample color and $C_{light}$ is `diffColor` [S1].

### Parameters
*   `lightDir`: Uniform vector for the light direction in eye space [S1].
*   `diffColor`: Uniform vector for the diffuse color of the light [S1].
*   `voxelJump`: Uniform vector representing the distance between voxels, used to offset sampling positions for finite differences [S1].

### Pseudocode
The following Python-like pseudocode implements the logic described in the source [S1]. It assumes a standard volume texture lookup function.

```python
def calculate_diffuse_lighting(samp_color, tr, scalar, light_dir, diff_color, voxel_jump):
    # 1. Calculate Gradient Components using Finite Differences
    # X-axis: forward difference
    val_right = sample_volume(tr + vec3(voxel_jump.x, 0.0, 0.0))
    n_x = val_right - scalar
    
    # Y-axis: forward difference
    val_up = sample_volume(tr + vec3(0.0, voxel_jump.y, 0.0))
    n_y = val_up - scalar
    
    # Z-axis: backward difference (as per source code)
    val_back = sample_volume(tr + vec3(0.0, 0.0, -voxel_jump.z))
    n_z = val_back - scalar
    
    # 2. Normalize the Gradient to get the Normal
    normal = normalize(vec3(n_x, n_y, n_z))
    
    # 3. Calculate Diffuse Factor
    diffuse_factor = max(dot(light_dir, normal), 0.0)
    
    # 4. Modulate Sample Color
    illuminated_color = samp_color * diffuse_factor * diff_color
    
    return illuminated_color
```

### Edge Cases and Pitfalls
*   **Transparent Transfer Functions**: The technique was tested only with opaque transfer functions. When used with transparent transfer functions, the rendering yields incoherent visual effects [S1].

## Operating characteristics
*   **Time Complexity**: The method adds three additional texture lookups and basic vector operations per shaded voxel [S1].
*   **Memory Complexity**: No additional memory is required beyond the volume texture and standard uniforms [S1].
*   **Performance**: Fetching data from neighbor voxels and performing extra calculations increases rendering cost, potentially impacting performance [S1].
*   **Strengths**: Simple to implement; works with any scalar field; provides immediate visual improvement in depth perception and shape definition [S1].
*   **Limitations**: Incoherent results with transparent transfer functions; sensitive to scalar field noise [S1].

## Background
This technique is described in the context of comparing GPU-based volume ray casting implementations across Fragment Shader, Compute Shader, OpenCL, and CUDA [S1]. It is presented as a standard method for adding illumination to volume rendering by leveraging the gradient of the scalar field as a proxy for surface normals [S1].
