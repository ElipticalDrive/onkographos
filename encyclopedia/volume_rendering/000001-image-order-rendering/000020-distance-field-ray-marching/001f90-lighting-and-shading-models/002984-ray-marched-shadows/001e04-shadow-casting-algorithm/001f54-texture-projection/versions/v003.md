# Texture Projection

Also called: Texture Projection for Volumetric Objects

## Overview
Texture projection is a texturing method that projects textures through space onto volumetrically defined objects, avoiding the difficulty of determining where defining surfaces lie [S1, unofficial][S2, unofficial]. It serves as a straightforward extension of the shadow-casting algorithm, enabling the mapping of textures onto both volumetric data and polygons embedded within it [S1, unofficial][S2, unofficial]. Unlike methods that require explicit surface parameterization, this approach handles the complex geometry of volumetric datasets by treating texture application as a spatial projection problem [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A volumetric dataset (e.g., CT scan), a geometric dataset (e.g., polygonal meshes), and a 2D texture image.
*   **Outputs:** A rendered image where textures are mapped onto the surfaces encountered by the projection rays.

**Data Structures:**
The method relies on the existing data structures of the hybrid ray tracer, specifically those used for shadow casting. No new complex data structures are defined in the sources; the texture is treated as a spatial field projected along specific directions [S1, unofficial][S2, unofficial].

**Steps:**
1.  **Extend the Shadow-Casting Algorithm:** The existing shadow-casting logic is adapted to handle texture data in addition to occlusion data [S1, unofficial][S2, unofficial].
2.  **Project Textures Through Space:** Textures are projected through the 3D space. This involves casting rays or defining projection vectors that traverse the volumetric and geometric data [S1, unofficial][S2, unofficial].
3.  **Map Textures onto Surfaces:** As the projection encounters surfaces (either from the volumetric dataset or embedded polygons), the texture is sampled and mapped onto these surfaces [S1, unofficial][S2, unofficial].

**Pitfalls and Edge Cases:**
*   **Spectral Mismatch:** Geometric, volumetric, and texture data exhibit different spectra. Care must be taken when mixing these data types to avoid visual artifacts or inconsistencies [S1, unofficial][S2, unofficial].
*   **Surface Definition Difficulty:** Wrapping textures around volumetrically defined objects is difficult because it requires knowing where their defining surfaces lie. Texture projection avoids this by projecting through space rather than wrapping [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
# Pseudocode for Texture Projection
# Based on the extension of the shadow-casting algorithm described in [S1, unofficial][S2, unofficial]

def texture_projection(volumetric_data, geometric_data, texture_image, projection_directions):
    """
    Projects textures onto volumetric and geometric surfaces.
    
    Args:
        volumetric_data: 3D array of voxel values.
        geometric_data: List of polygons.
        texture_image: 2D array of texture colors.
        projection_directions: List of 3D vectors defining projection axes.
        
    Returns:
        rendered_image: 2D array of final pixel colors.
    """
    rendered_image = initialize_empty_image()
    
    # For each pixel in the output image
    for y, x in pixels(rendered_image):
        # Cast a ray through the scene (similar to shadow casting)
        ray = cast_ray_through_pixel(x, y)
        
        # Initialize texture contribution
        texture_color = (0, 0, 0)
        texture_weight = 0.0
        
        # Traverse the ray through the volume and geometry
        while ray.has_next_step():
            point = ray.get_current_point()
            
            # Check if the point intersects with volumetric data
            if is_inside_volumetric_data(point, volumetric_data):
                # Sample the texture at this point based on projection
                # Note: Exact projection mapping formula is not specified in sources [G]
                tex_coord = project_point_to_texture(point, projection_directions)
                sample = sample_texture(texture_image, tex_coord)
                
                # Accumulate texture color
                # Note: Blending weights depend on the specific hybrid ray tracer implementation [G]
                texture_color += sample
                texture_weight += 1.0
                
            # Check if the point intersects with geometric polygons
            elif intersects_polygon(point, geometric_data):
                # Map texture onto the polygon surface
                # Note: Polygon texture mapping is described as relatively simple [S2, unofficial]
                polygon_tex_coord = get_polygon_uv(point)
                polygon_sample = sample_texture(texture_image, polygon_tex_coord)
                
                # Accumulate texture color
                texture_color += polygon_sample
                texture_weight += 1.0
                
            ray.advance_step()
            
        # Normalize and combine with base color
        if texture_weight > 0:
            final_texture = texture_color / texture_weight
        else:
            final_texture = (0, 0, 0)
            
        # Note: Spectral mismatch handling is required here [S1, unofficial][S2, unofficial]
        rendered_image[y, x] = combine_base_color_and_texture(final_texture)
        
    return rendered_image
```

## Subtopics

## Operating characteristics
*   **Complexity:** The method is described as a "straightforward extension" of the shadow-casting algorithm, implying similar computational complexity to shadow casting, which is generally linear with respect to the number of samples per ray [S1, unofficial][S2, unofficial].
*   **Strengths:** It avoids the hard problem of determining defining surfaces for volumetric objects, making it easier to apply textures to complex volumetric data [S1, unofficial][S2, unofficial].
*   **Limitations:** Care must be taken due to spectral mismatches between geometric, volumetric, and texture data [S1, unofficial][S2, unofficial].
*   **Performance:** Specific performance metrics are not given in the sources.

## Background
Texture projection was introduced in the context of interactive visualization of 3D medical data and rendering mixtures of geometric and volumetric data [S1, unofficial][S2, unofficial]. The approach is similar to methods described by Feibush, Levoy, and Cook [1980] and builds upon the hybrid ray tracer described in the technical report [Levoy 1988c] [S1, unofficial][S2, unofficial]. A good survey of texture mapping algorithms was written by Heckbert [1986] [S1, unofficial][S2, unofficial].
