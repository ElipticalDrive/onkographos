# Texture Projection

Also called: Texture Projection for Volumetric Objects

## Overview
Texture projection maps 2D textures onto geometric and volumetric data by projecting them through space onto encountered surfaces [S2, unofficial]. It solves the difficulty of wrapping textures around volumetrically defined objects, which requires knowing where their defining surfaces lie [S2, unofficial]. Implemented as a straightforward extension of the shadow-casting algorithm, it avoids explicit surface parameterization [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** A volumetric dataset, a geometric dataset (e.g., polygonal meshes), and a 2D texture image.
*   **Outputs:** A rendered image where textures are mapped onto the surfaces encountered by the projection rays.

**Data Structures:**
The method treats the texture as a spatial field projected along specific directions and does not define new complex data structures beyond those used in the base hybrid ray tracer [S1, unofficial][S2, unofficial].

**Steps:**
1.  **Extend the Shadow-Casting Algorithm:** Adapt the existing shadow-casting logic to handle texture data alongside occlusion data [S1, unofficial][S2, unofficial].
2.  **Project Textures Through Space:** Cast rays or define projection vectors that traverse the volumetric and geometric data [S1, unofficial][S2, unofficial].
3.  **Map Textures onto Surfaces:** As the projection encounters surfaces (either from the volumetric dataset or embedded polygons), sample and map the texture onto these surfaces [S1, unofficial].

**Pitfalls and Edge Cases:**
*   **Spectral Mismatch:** Geometric, volumetric, and texture data exhibit different spectra, requiring care when mixing them to avoid visual artifacts [S1, unofficial].
*   **Surface Definition Difficulty:** Wrapping textures around volumetrically defined objects is difficult because it requires knowing where their defining surfaces lie; texture projection avoids this by projecting through space rather than wrapping [S2, unofficial].

**Pseudocode:**
```python
def texture_projection(volumetric_data, geometric_data, texture_image, projection_directions, width, height):
    """Projects textures onto volumetric and geometric surfaces via spatial projection."""
    rendered_image = [[(0.0, 0.0, 0.0) for _ in range(width)] for _ in range(height)]
    for y in range(height):
        for x in range(width):
            ray_origin = (0.0, 0.0, 0.0)
            ray_dir = normalize((x - width/2, y - height/2, -1.0))
            tex_accum = (0.0, 0.0, 0.0)
            tex_weight = 0.0
            t = 0.0
            while t < max_distance:
                point = add_vectors(ray_origin, scale_vector(ray_dir, t))
                hit_vol = volumetric_data.contains(point)
                hit_poly = geometric_data.intersects(point)
                if hit_vol or hit_poly:
                    if hit_vol:
                        uv = project_point_to_texture(point, projection_directions)
                    else:
                        uv = get_polygon_uv(point, hit_poly)
                    sample = sample_texture(texture_image, uv)
                    tex_accum = add_colors(tex_accum, sample)
                    tex_weight += 1.0
                t += step_size
            if tex_weight > 0:
                final_tex = scale_color(tex_accum, 1.0 / tex_weight)
            else:
                final_tex = (0.0, 0.0, 0.0)
            rendered_image[y][x] = final_tex
    return rendered_image

# Standard helper operations
def normalize(v):
    l = (v[0]**2 + v[1]**2 + v[2]**2)**0.5
    return (v[0]/l, v[1]/l, v[2]/l)
def add_vectors(a, b): return (a[0]+b[0], a[1]+b[1], a[2]+b[2])
def scale_vector(v, s): return (v[0]*s, v[1]*s, v[2]*s)
def add_colors(c1, c2): return (c1[0]+c2[0], c1[1]+c2[1], c1[2]+c2[2])
def scale_color(c, s): return (c[0]*s, c[1]*s, c[2]*s)
def project_point_to_texture(point, directions):
    return tuple(max(0.0, min(1.0, dot(point, d))) for d in directions)
def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def volumetric_data.contains(point): return True # Standard volume lookup [G]
def geometric_data.intersects(point): return None # Standard ray-polygon intersection [G]
def sample_texture(tex, uv): return (uv[0], uv[1], 0.5) # Standard bilinear sampling [G]
def get_polygon_uv(point, polygon): return (0.0, 0.0) # Standard UV mapping [G]
```

## Subtopics

### [Triplanar Texture Projection](2303-triplanar-texture-projection.md)
Maps 2D textures onto 3D surfaces by applying planar mapping in three perpendicular planes (XY, XZ, YZ) and interpolating results based on surface normal alignment. It solves texture stretching on complex, non-planar surfaces such as spheres or organic shapes. Unlike planar projection which uses only two coordinates, triplanar mapping uses three orthogonal projections weighted by the surface normal to ensure seamless coverage regardless of orientation. Choose it when rendering organic shapes or spheres where planar projection causes distortion. See [Triplanar Texture Projection](2303-triplanar-texture-projection.md).

## Operating characteristics
*   **Complexity:** Described as a straightforward extension of the shadow-casting algorithm [S1, unofficial][S2, unofficial]. Specific time and memory complexity are not given in the sources.
*   **Strengths:** Avoids the hard problem of determining defining surfaces for volumetric objects, making it easier to apply textures to complex volumetric data [S1, unofficial][S2, unofficial].
*   **Limitations:** Requires care when mixing geometric, volumetric, and texture data due to spectral mismatch [S1, unofficial][S2, unofficial].
*   **Performance:** Specific performance metrics are not given in the sources.

## Background
Texture projection was introduced in the context of interactive visualization of 3D medical data and rendering mixtures of geometric and volumetric data [S1, unofficial][S2, unofficial]. The approach is similar to methods described by Feibush [1980] and builds upon the hybrid ray tracer detailed in the technical report [Levoy 1988c] [S1, unofficial][S2, unofficial]. A comprehensive survey of texture mapping algorithms was published by Heckbert [1986] [S1, unofficial][S2, unofficial].
