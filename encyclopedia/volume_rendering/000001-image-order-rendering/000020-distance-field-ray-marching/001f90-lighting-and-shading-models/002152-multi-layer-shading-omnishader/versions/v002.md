# Multi-Layer Shading / OmniShader

Also called: OmniShader

## Overview
Multi-Layer Shading (OmniShader) computes eight distinct visualization layers simultaneously in a single forward pass, returning them as a tuple of tensors [S1, unofficial]. It decouples geometric, photometric, and stylistic attributes into parallel outputs rather than combining them into a single RGB image, allowing for flexible post-processing or neural network ingestion [S1, unofficial].

## How it works
**Inputs and Outputs:**
The method takes ray directions, surface coordinates, surface normals, surface distances, pixel frames, camera orientation, a cyclic colormap, a degree parameter, and a decay factor as inputs [S1, unofficial]. It outputs a tuple of eight tensors: `(lambertian_layer, distance_layer, proximity_layer, vignette_layer, normal_layer, laplacian_layer, tangent_layer, spin_layer)` [S1, unofficial].

**Data Structures:**
The implementation relies on tensor operations, such as cyclic shifting [S1, unofficial]. A key internal structure is `cyclic_cmap`, a colormap tensor that is cyclically shifted by 65 positions on axis -2: `self.cyclic_cmap = self.cyclic_cmap.roll(65, -2)` [S1, unofficial].

**Parameters:**
*   `decay_factor`: A float, default `0.01`, used in the distance shading calculation [S1, unofficial].
*   `degree`: An integer parameter used in tangent and spin shading calculations [S1, unofficial].

**Steps:**
1.  **Compute Surface Normals:** Estimate the surface normal $\mathbf{n}$ at the intersection point $\mathbf{p}$ using the gradient of the Signed Distance Function (SDF) $f$. This is done by solving a linear system derived from finite differences at the vertices of a regular tetrahedron centered at 0, or via back-propagation [S1, unofficial].
2.  **Compute Surface Laplacian:** Estimate the Laplacian $\Delta f$ at $\mathbf{p}$ using the same tetrahedral samples used for the normal. The formula is:
    $$ (\Delta f)(p) \approx \frac{6}{\epsilon^2} \left( f(p) - \frac{1}{4}\sum_{i=0}^3f(p+\epsilon v_i) \right) $$
    where $\epsilon$ is a small constant and $v_i$ are the tetrahedron vertices [S1, unofficial].
3.  **Prepare Camera Orientation:** Compute the conjugate of the camera orientation quaternion: `camera_orientation_conj = camera_orientation.conjugate()[..., None, None, :]` [S1, unofficial].
4.  **Compute Lambertian Layer:** Apply the Lambertian shader to ray directions and surface normals [S1, unofficial].
5.  **Compute Distance Layer:** Apply the distance shader to pixel coordinates, surface coordinates, and the `decay_factor` [S1, unofficial].
6.  **Compute Proximity Layer:** Apply the proximity shader to surface distances [S1, unofficial].
7.  **Compute Vignette Layer:** Apply the vignette shader to ray directions and pixel frames [S1, unofficial].
8.  **Compute Normal Layer:** Apply the normal shader to surface normals. The normals $\mathbf{n}=(x,y,z)$ are typically mapped to RGB using absolute values: $(\lvert x \rvert, \lvert y \rvert, \lvert z \rvert)$ [S1, unofficial].
9.  **Compute Laplacian Layer:** Apply the Laplacian shader to the computed surface Laplacian values, normalizing them between 0 and 1 and applying gamma correction [S1, unofficial].
10. **Compute Tangent Layer:** Apply the tangent shader using `camera_orientation_conj`, ray directions, surface normals, the shifted `cyclic_cmap`, and `degree` [S1, unofficial].
11. **Compute Spin Layer:** Apply the spin shader using `camera_orientation_conj`, surface normals, the shifted `cyclic_cmap`, and `degree` [S1, unofficial].
12. **Return:** Return the tuple of all eight layers [S1, unofficial].

**Pseudocode:**
```python
def multi_layer_shading(ray_directions, surface_normals, surface_coords, 
                        surface_distances, pixel_frames, camera_orientation, 
                        cyclic_cmap, degree, decay_factor, surface_laplacian, 
                        px_coords):
    # 1. Prepare camera orientation conjugate
    camera_orientation_conj = camera_orientation.conjugate()[..., None, None, :]
    
    # 2. Shift cyclic colormap
    shifted_cmap = cyclic_cmap.roll(65, -2)
    
    # 3. Compute layers (exact shading formulas not provided in sources [G])
    lambertian_layer = ray_directions * surface_normals
    distance_layer = px_coords * surface_coords * decay_factor
    proximity_layer = surface_distances
    vignette_layer = ray_directions * pixel_frames
    normal_layer = surface_normals.abs()
    laplacian_layer = surface_laplacian.clamp(0, 1)
    tangent_layer = camera_orientation_conj * ray_directions * surface_normals * shifted_cmap[degree]
    spin_layer = camera_orientation_conj * surface_normals * shifted_cmap[degree]
    
    # 4. Return all layers as a tuple
    return (lambertian_layer, distance_layer, proximity_layer, vignette_layer, 
            normal_layer, laplacian_layer, tangent_layer, spin_layer)
```

**Edge Cases and Pitfalls:**
*   **Precision:** The Laplacian and Normal calculations rely on finite differences with a small constant $\epsilon$ [S1, unofficial].
*   **Boundary Conditions:** The distance and proximity shaders may behave unpredictably at the exact start or end of the ray march if not clamped [G].
*   **Quaternion Conjugate:** Incorrect handling of quaternion conjugation can lead to misaligned tangent and spin layers [G].

## Operating characteristics
**Time and Memory Complexity:**
The method performs a single forward pass to compute all eight layers, which is computationally efficient compared to running eight separate render passes [S1, unofficial]. However, it requires memory to store eight output tensors simultaneously [S1, unofficial].

**Strengths and Limitations:**
*   **Strengths:** High efficiency due to single-pass computation; flexible output for downstream tasks (e.g., neural networks, post-processing) [S1, unofficial].
*   **Limitations:** Requires all input data (normals, Laplacian, etc.) to be available or computed in the same pass, which may increase intermediate memory usage [G].

**When to Use:**
Use when you need multiple visualization attributes (normals, depth, curvature, etc.) for the same scene geometry without the overhead of multiple render passes [S1, unofficial].

## Background
The method originates from a ray marching visualization toolkit that implements various ray marching techniques [S1, unofficial]. It is used in contexts requiring detailed geometric and photometric analysis of ray-marched scenes, such as in neural rendering pipelines or advanced visualization tools [S1, unofficial].
