# Depth Rendering


## Overview
Depth Rendering is a visualization technique that maps the number of raymarching steps taken to reach a surface to grayscale intensity, producing a depth map where brightness corresponds to traversal depth [S1, unofficial]. It builds on its parent, Iteration-Based Coloring, but normalizes the step count against the scene's grid length to bound the output intensity to the range $[0, 255]$ [S1, unofficial].

## How it works
**Inputs:**
- Ray origin and direction for each pixel $(x, y)$, provided by `rc.getRayForPixel(x, y)` [S1, unofficial].
- An octree data structure representing the volume, with bounding box length defined by `tree->gridlength` [S1, unofficial].
- A `TreeTraverser` object initialized with the tree and the ray [S1, unofficial].

**Outputs:**
- A 4-channel texture array (`texture_array`) of size `rc.n_y * rc.n_y * 4` (assuming square resolution) [S1, unofficial].
- Channels: Red (grayscale intensity), Green (uninitialized or zeroed by caller), Blue (uninitialized or zeroed by caller), and Alpha (set to 1) [S1, unofficial].

**Data Structures:**
- `VoxelData`: Contains `morton` (uint64_t), `color` (vec3), and `normal` (vec3) [S1, unofficial].
- `TreeTraverser`: Manages the traversal state, providing `isTerminated()`, `getCurrentNode()`, `step()`, `stepcount`, and `getCurrentPosition()` [S1, unofficial].

**Algorithm:**
1. Initialize OpenMP parallelization using the number of available CPU cores [S1, unofficial].
2. Parallelize the pixel loop over $y$ and $x$ from $0$ to `rc.n_y` [S1, unofficial].
3. For each pixel $(x, y)$:
   a. Initialize `TreeTraverser t` with the tree and the ray for $(x, y)$ [S1, unofficial].
   b. Traverse the tree while `!t.isTerminated()` [S1, unofficial]:
      i. If `t.getCurrentNode()->isLeaf()` and `t.getCurrentNode()->hasData()`, break the loop [S1, unofficial].
      ii. Otherwise, call `t.step()` [S1, unofficial].
   c. Compute the normalized intensity using the traversal step count [S1, unofficial].
   d. Write the Red channel and Alpha channel to the texture array [S1, unofficial].

**Formula:**
$$ I = \frac{\text{stepcount}}{\log_2(\text{gridlength})} \times 255.0 $$
where $I$ is the intensity value, $\text{stepcount}$ is the number of traversal steps taken, and $\text{gridlength}$ is the side length of the volume bounding box [S1, unofficial].

**Parameters:**
- `tree->gridlength`: The side length of the volume bounding box, used for normalization [S1, unofficial].
- `rc.n_y`: The vertical resolution of the output image, assumed square for the horizontal resolution [S1, unofficial].

**Edge Cases:**
- If `gridlength` is less than or equal to 1, $\log_2(\text{gridlength})$ is zero or negative, causing division by zero or inverted intensity; the source does not specify a guard for this case [S1, unofficial].
- If the ray does not hit any leaf node with data, `t.isTerminated()` becomes true, and `stepcount` reflects the maximum traversal depth; the source does not specify special handling for missed rays [S1, unofficial].

    set_num_threads(num_threads)

    for y in range(rc.n_y):
        partindex = y * (rc.n_y * 4)
        for x in range(rc.n_y):
            index = partindex + x * 4
            t = TreeTraverser(tree, rc.get_ray_for_pixel(x, y))

            while not t.isTerminated():

            intensity = (t.stepcount / math.log2(tree.gridlength)) * 255.0
            r = int(intensity)

            texture_array[index] = r
            texture_array[index + 3] = 1

## Subtopics

### Logarithmic Depth Rendering
A visualization technique that renders a depth map by normalizing the logarithmic distance traveled by the ray, where brighter pixels indicate further travel distance [S2, unofficial]. It calculates the distance $d = |p_i - p_0|$ between the hit point $p_i$ and the ray origin $p_0$, computes $\log(d)$, and normalizes this value to the range $[0, 1]$ [S2, unofficial]. The implementation typically involves clamping the distance to avoid $\log(0)$, subtracting the minimum log-distance, dividing by the range, and optionally applying a power function for tonemapping [S2, unofficial].

## Operating characteristics
- Time and memory complexity: Not given in the sources.
- Strengths: Simple to implement; provides immediate visual feedback on traversal depth [S1, unofficial].
- Limitations: Sensitive to the choice of grid length for normalization; does not account for occlusion beyond the first hit [S1, unofficial].
- When to use: When a quick traversal depth visualization is needed without complex shading [S1, unofficial].
- When not to use: When accurate depth perception over large dynamic ranges is required (consider Logarithmic Depth Rendering) [S2, unofficial].

## Background
Originated in early CPU-based voxel raycasting implementations, specifically in the `cpu_voxel_raycaster` project by Forceflow [S1, unofficial]. It is used as a debugging and visualization tool for voxel-based rendering pipelines [S1, unofficial].
