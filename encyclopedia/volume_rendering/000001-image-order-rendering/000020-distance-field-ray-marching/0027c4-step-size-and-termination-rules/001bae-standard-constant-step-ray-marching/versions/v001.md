# Standard Constant Step Ray Marching

Also called: Basic Raymarching Loop, Fixed Step Ray Marching, Raymarch, SDF Ray Marching

## Overview
Standard Constant Step Ray Marching is an iterative algorithm for finding the intersection of a ray with an implicit surface or sampling a volume by advancing the ray position at fixed intervals [S4, S5, unofficial]. It mitigates the drawback of root-finding methods that may identify multiple intersection points by focusing on determining the first root (or accumulating volume data) [S4, unofficial]. Unlike Spheretracing, which uses the distance field value to determine the step size, this method uses a predefined constant step size, allowing it to work with any function that returns a boolean (inside/outside) or a scalar field, rather than requiring a strict Signed Distance Field (SDF) [S2, S4, unofficial].

## How it works
**Inputs:**
*   Ray origin $\mathbf{r}_0$ (e.g., camera position) [S3, S5, unofficial].
*   Ray direction $\mathbf{r}_d$ (normalized unit vector) [S3, S4, unofficial].
*   Fixed step size $\Delta t$ [S4, unofficial].
*   Maximum step count $k_{max}$ (or maximum distance) [S2, S4, unofficial].
*   Implicit surface function $f(\mathbf{x})$ or scalar field map [S4, S5, unofficial].
*   (Optional) Bounding box limits $t_{min}, t_{max}$ [S5, unofficial].

**Outputs:**
*   Intersection distance $t$ (if surface hit) [S4, unofficial].
*   Accumulated radiance/color (if volume rendering) [S5, unofficial].
*   Boolean indicating hit/miss [S2, S4, unofficial].

**Data Structures:**
*   Scalar variables for position, distance, and counters. No complex structures required.

**Algorithm Steps:**
1.  Initialize step counter $k = 0$ and current distance $t = 0$ [S4, S5, unofficial].
2.  (Optional) Compute bounding box intersection parameters $t_{min}$ and $t_{max}$ for the ray [S5, unofficial].
3.  Loop while $k < k_{max}$ and (if bounding box is used) $t \le t_{max}$:
    a. Calculate current sample point: $\mathbf{r}(k) = \mathbf{r}_0 + \Delta t \cdot k \cdot \mathbf{r}_d$ [S4, unofficial].
    b. Evaluate the field function at $\mathbf{r}(k)$: $d = f(\mathbf{r}(k))$ [S4, unofficial].
    c. **Surface Intersection Variant:**
        i. If $d \le 0$ (or $d < \epsilon$), the ray has hit or passed inside the surface. Return intersection distance $t = k \cdot \Delta t$ [S4, unofficial].
        ii. If $d > 0$ and a maximum distance check is used, break if $t > \text{MAX\_DIST}$ [S1, unofficial].
    d. **Volume Rendering Variant:**
        i. Sample density $\rho$ from $d$ [S5, unofficial].
        ii. Evaluate transfer function to get attenuation $\alpha$ and color contribution [S5, unofficial].
        iii. Update accumulated radiance: $L_{new} = L_{old} \cdot \exp(-\rho \cdot \Delta t \cdot \alpha)$ [S5, unofficial].
        iv. Advance $t$ by $\Delta t$ [S5, unofficial].
    e. Increment $k$ [S4, unofficial].
4.  If loop completes without hit (surface) or termination (volume), return miss/no intersection [S4, unofficial].

**Pseudocode (Surface Intersection):**
```python
def ray_march_surface(r0, rd, step_size, max_steps, surface_func):
    """
    r0: vec3, ray origin
    rd: vec3, normalized ray direction
    step_size: float, fixed delta t
    max_steps: int, maximum iterations
    surface_func: function, returns distance (negative if inside)
    """
    k = 0
    t = 0.0
    
    while k < max_steps:
        # Calculate current position
        pos = r0 + rd * (step_size * k)
        
        # Sample the implicit surface
        dist = surface_func(pos)
        
        # Check for intersection
        # Note: Some implementations use a small epsilon threshold instead of <= 0
        if dist <= 0.0:
            return t, True
            
        k += 1
        t = step_size * k
        
    return 0.0, False
```

**Pseudocode (Volume Rendering):**
```python
def ray_march_volume(r0, rd, step_size, max_steps, volume_func, transfer_func):
    """
    volume_func: returns scalar density
    transfer_func: returns (density, attenuation) tuple
    """
    t = 0.0
    L = 1.0 # Incoming radiance
    
    # Optional: Compute t_min, t_max for bounding box
    # t_min, t_max = compute_box_intersection(r0, rd, box)
    
    k = 0
    while k < max_steps:
        pos = r0 + rd * t
        
        # Sample volume
        density = volume_func(pos)
        
        # Apply transfer function
        tf_val = transfer_func(density)
        density_val = tf_val.density
        attenuation = tf_val.attenuation
        
        # Accumulate radiance
        # L *= Exp(-density * step_size * attenuation)
        L = L * exp(-density_val * step_size * attenuation)
        
        t += step_size
        k += 1
        
    return L
```

**Parameters:**
*   $\Delta t$ (Step Size): Critical parameter. Typical values range from 0.001 (high precision/volume) to 0.1 (coarse/surface) [S2, S5, unofficial].
*   $k_{max}$ (Max Steps): Typical value 10–64 depending on scene complexity and step size [S2, S3, unofficial].
*   $\epsilon$ (Epsilon): Threshold for intersection detection. Often $0.001$ or similar small value [S3, unofficial].

**Edge Cases and Pitfalls:**
*   **Tunneling:** If $\Delta t$ is too large, the ray may jump over thin geometry between samples [S2, S4, unofficial].
*   **Performance:** If $\Delta t$ is too small, excessive samples are taken in empty space, causing performance loss [S2, unofficial].
*   **Surface Definition:** The algorithm assumes $f(x) < 0$ is inside and $f(x) = 0$ is the surface boundary [S4, unofficial].
*   **Precision:** Fixed steps do not adapt to local geometry, potentially missing details that Spheretracing (adaptive step) would catch [S3, unofficial].

## Subtopics

### Iteration-Based Coloring
A rendering technique where the pixel color is determined by the number of raymarching steps taken before hitting a surface or reaching the maximum step count, visualizing computational intensity [S6, unofficial]. It serves as a debug or artistic tool rather than a physically accurate method [S6, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(k_{max})$, linear with respect to the maximum number of steps [S4, unofficial].
*   **Memory Complexity:** $O(1)$, constant space per ray [S4, unofficial].
*   **Strengths:** Simple to implement; works with any implicit function (boolean or scalar), not just SDFs [S2, unofficial].
*   **Limitations:** Prone to tunneling if step size is not carefully chosen; inefficient in empty space if step size is small; does not guarantee finding the *exact* first intersection point as accurately as adaptive methods (like Spheretracing) [S2, S4, unofficial].
*   **When to use:** Simple shapes, boolean volumes, or when SDF evaluation is expensive/impossible [S2, unofficial].
*   **When not to use:** Complex scenes with thin geometry requiring high precision, or when SDFs are available (use Spheretracing instead) [S2, S3, unofficial].

## Background
The method was indicated by [PH89] and used for rendering Hypertexture volumes [S4, unofficial]. It is similar to volumetric ray-casting techniques [S4, S5, unofficial]. The ray equation $\mathbf{r}(k) = \mathbf{r}_0 + \Delta t k \mathbf{r}_d$ is a standard formulation for fixed-step traversal [S4, unofficial].
