# Sphere Tracing Termination and Clipping

Also called: Sphere Tracing Stopping Criteria, Sphere Tracing Termination Conditions

## Overview
Sphere Tracing Termination and Clipping defines the conditions under which a ray-marching loop terminates, ensuring geometric accuracy while preventing infinite execution or rendering artifacts. It solves the problem of determining when a ray has sufficiently approximated a surface intersection or exited the scene bounds. It sets itself apart from sibling methods like [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by using distance-field-dependent step sizes and specific convergence criteria, and from [Step Size Optimization](2054-step-size-optimization.md) by focusing on the stopping logic rather than the step size calculation itself.

## How it works
The method combines three termination mechanisms: distance-based convergence, iteration limits, and spatial clipping. It may also employ oscillation detection to prevent infinite loops in non-convergent scenarios.

### Inputs and Outputs
*   **Inputs:**
    *   $d_k$: The signed distance value at the current ray position $\mathbf{p}_k$.
    *   $d_{k-1}$: The signed distance value at the previous step (for oscillation check).
    *   $\delta_b$: The stopping distance threshold.
    *   $k_{max}$: The maximum number of iterations.
    *   $D_{far}$: The far plane clipping depth.
    *   $\delta$: A small constant used in oscillation detection (typically $\delta = \delta_b$).
*   **Outputs:**
    *   Boolean `terminated`: True if the ray should stop marching.
    *   State: `Hit`, `Miss`, or `Clipped`.

### Data Structures
No complex data structures are required. The algorithm maintains scalar state variables for the current distance, previous distance, current ray length $t$, and iteration counter $k$.

### Steps
1.  **Check Iteration Limit:** If the current iteration count $k$ exceeds $k_{max}$, terminate with a "Miss" or "Clipped" state [S1].
2.  **Check Convergence:** If the absolute distance value $|d_k|$ is less than the threshold $\delta_b$, terminate with a "Hit" state [S1].
3.  **Check Oscillation:** If the step size is oscillating, terminate to prevent infinite loops. The condition is $|d_k - d_{k-1}| < 6\delta$ [S1]. Note: This check is typically applied when the step size is not decreasing monotonically or when convergence stalls.
4.  **Check Far Plane Clipping:** If the ray length $t$ exceeds the far plane depth $D_{far}$, terminate with a "Clipped" state [S1].

### Formulas
*   **Convergence Criterion:**
    $$ |d_k| < \delta_b $$
*   **Oscillation Criterion:**
    $$ |d_k - d_{k-1}| < 6\delta $$
*   **Far Plane Clip:**
    $$ t > D_{far} $$

### Parameters
*   $\delta_b$ (Stopping distance threshold): $0.0003$ [S1].
*   $k_{max}$ (Maximum iterations): $200$ [S1].
*   $D_{far}$ (Far plane clipping depth): $5.0$ [S1].
*   $\delta$ (Oscillation constant): Typically equal to $\delta_b$ [S1].

### Edge Cases and Pitfalls
*   **Oscillation:** In regions where the SDF is noisy or non-Lipschitz, the ray may oscillate between two distance values. The oscillation check $|d_k - d_{k-1}| < 6\delta$ detects this and forces termination, preventing infinite loops [S1].
*   **Precision:** The threshold $\delta_b$ must be chosen carefully. Too large, and the intersection is inaccurate; too small, and the ray may not converge within $k_{max}$ [S1].
*   **Far Plane:** The far plane depth $D_{far}$ must be set based on the scene bounds. If set too low, valid geometry may be clipped; if set too high, performance may degrade due to unnecessary marching [S1].

### Pseudocode
```python
def sphere_tracing_termination(d_k, d_k_minus_1, t, k, delta_b, k_max, far_plane_depth, delta):
    """
    Determines if sphere tracing should terminate based on convergence, iteration limit,
    oscillation, and far plane clipping.
    
    Args:
        d_k (float): Signed distance at current position.
        d_k_minus_1 (float): Signed distance at previous position.
        t (float): Current ray length (distance from origin).
        k (int): Current iteration count.
        delta_b (float): Stopping distance threshold.
        k_max (int): Maximum number of iterations.
        far_plane_depth (float): Far plane clipping depth.
        delta (float): Constant for oscillation detection.
        
    Returns:
        bool: True if termination conditions are met.
        str: Termination state ('Hit', 'Miss', 'Clipped').
    """
    # Step 1: Check iteration limit
    if k >= k_max:
        return True, "Miss"
    
    # Step 2: Check convergence
    if abs(d_k) < delta_b:
        return True, "Hit"
    
    # Step 3: Check oscillation
    # Oscillation is detected if the change in distance is very small
    # but the ray has not converged, indicating a stall.
    if abs(d_k - d_k_minus_1) < 6 * delta:
        return True, "Miss"
    
    # Step 4: Check far plane clipping
    if t > far_plane_depth:
        return True, "Clipped"
    
    return False, "Continue"
```

## Subtopics

### Cone Tracing Error Threshold
A method to determine the adaptive error threshold $\hat{\epsilon}$ based on the ray distance and pixel footprint, ensuring rays terminate when the pixel cone intersects the surface. It sets itself apart from standard fixed thresholds by adapting to the view direction and deformation, preventing the "swimming" artifact where the surface appears to move with the camera. Choose this method when rendering deformed SDFs or when high-quality anti-aliasing is required. [Cone Tracing Error Threshold](4313-cone-tracing-error-threshold.md)

### Blend Mode
A rendering mode that traverses voxels and sums their value until value accumulation results in enough content, either being opaque for early termination or containing greater than zero content for blending with a user-specified background. It sets itself apart from standard sphere tracing by operating on volumetric data rather than implicit surfaces, and by using accumulation-based termination rather than distance-based termination. Choose this method for volume rendering with hardware ray tracing. [Blend Mode](4318-blend-mode.md)

### Optimized Binary Search with Local Lipschitz Bounds
A binary search method that recursively subdivides an interval, using local Lipschitz bounds to exclude intervals earlier and shrink sub-intervals asymmetrically. It sets itself apart from standard binary search by reducing the number of field function queries and improving timing speed-ups through the use of local Lipschitz bounds $\lambda(e)$. Choose this method when high-precision intersection is needed after a coarse sphere trace. [Optimized Binary Search with Local Lipschitz Bounds](4367-optimized-binary-search-with-local-lipschitz-bounds.md)

## Operating characteristics
*   **Time Complexity:** $O(k)$, where $k$ is the number of iterations until termination. The oscillation check and far plane check are $O(1)$ per iteration [S1].
*   **Memory Complexity:** $O(1)$, as only scalar state variables are maintained [S1].
*   **Measured Performance:** With $\delta_b = 0.0003$, $k_{max} = 200$, and $D_{far} = 5$, the method provides a balance between accuracy and performance for real-time rendering [S1].
*   **Strengths:** Prevents infinite loops via oscillation detection; ensures geometric accuracy via convergence threshold; avoids rendering distant artifacts via far plane clipping [S1].
*   **Limitations:** The fixed parameters ($\delta_b$, $k_{max}$, $D_{far}$) may not be optimal for all scenes; oscillation detection may terminate rays prematurely in complex geometries [S1].
*   **When to use:** Real-time rendering of implicit surfaces where performance and stability are critical [S1].
*   **When not to use:** When high-precision intersection is required beyond the convergence threshold, or when the scene has very large bounds exceeding the far plane depth [S1].

## Background
The method originates from the Neural Geometric Level of Detail (NVIDIA) paper, which introduced these specific termination criteria for real-time rendering with implicit 3D shapes [S1]. The parameters ($\delta_b = 0.0003$, $k_{max} = 200$, $D_{far} = 5$) were empirically determined for the NVIDIA dataset [S1].
