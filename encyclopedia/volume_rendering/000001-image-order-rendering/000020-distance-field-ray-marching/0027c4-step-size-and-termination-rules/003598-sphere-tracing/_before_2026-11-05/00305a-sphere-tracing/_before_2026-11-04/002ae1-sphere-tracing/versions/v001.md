# Sphere Tracing

Also called: Classic Sphere Tracing, SDF Sphere Tracing, SDF Tracing, Signed Distance Field Ray Marching, Sphere Tracing for Ray Marching

## Overview
Sphere Tracing is an iterative ray-marching algorithm for rendering implicit surfaces defined by Signed Distance Functions (SDFs) [S1][S3, S8, unofficial]. It solves the problem of finding the intersection between a ray and a complex geometric surface represented mathematically rather than as a polygon mesh [S4, unofficial][S17]. Unlike [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md), which uses a fixed interval and risks missing thin geometry or overshooting surfaces, Sphere Tracing dynamically calculates a safe step size equal to the distance to the nearest surface [S3, S6, S10, unofficial]. This guarantees that the ray never penetrates the surface, ensuring robust convergence for pathological shapes with discontinuous derivatives [S8, S24, unofficial].

## How it works
Sphere Tracing relies on the property that an SDF $f(\mathbf{x})$ returns the Euclidean distance from a point $\mathbf{x}$ to the nearest surface $f^{-1}(0)$ [S1][S8, unofficial]. For a general Lipschitz continuous function with constant $\lambda$, the step size is bounded by $|f(\mathbf{x})|/\lambda$ [S1]. In the specific case of an SDF, $\lambda=1$, so the function value itself is the exact distance and a safe lower bound for the step [S1, S2].

### Inputs and Outputs
*   **Inputs**:
    *   Ray origin $\mathbf{o}$ (3D vector) [S24, unofficial].
    *   Ray direction $\mathbf{d}$ (normalized 3D vector) [S24, unofficial].
    *   SDF function $f(\mathbf{x})$ returning signed distance [S11, unofficial].
    *   Maximum march distance $D_{max}$ (scalar) [S26].
    *   Convergence threshold $\epsilon$ (scalar, e.g., $10^{-4}$) [S4, S24, unofficial].
    *   Maximum iteration count $N_{max}$ (integer) [S3, unofficial].
*   **Outputs**:
    *   Intersection distance $t$ (scalar) or hit point $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [S5, S11, unofficial].
    *   Hit mask (boolean) indicating if a surface was found within $D_{max}$ [S5, unofficial].

### Data Structures
The algorithm maintains a single scalar variable for the accumulated distance traveled along the ray, typically denoted as $t$ or `depth` [S11, S12, unofficial]. No complex data structures are required for the core traversal, though implementations often batch rays into tensors of shape $(N, 3)$ for origins and directions to leverage GPU parallelism [S5, unofficial].

### Algorithm Steps
1.  **Initialize**: Set the current distance traveled $t = 0.0$ [S11, unofficial][S26]. Initialize a hit flag or mask to false [S5, unofficial].
2.  **Loop**: Iterate for $i$ from $0$ to $N_{max} - 1$:
    a.  **Evaluate**: Compute the current point on the ray $\mathbf{p} = \mathbf{o} + t \cdot \mathbf{d}$ [S11, S24, unofficial]. Evaluate the SDF at this point: $d = f(\mathbf{p})$ [S13, S24, unofficial].
    b.  **Check Hit**: If $|d| < \epsilon$ (or $d < \epsilon$ for unsigned distance fields), the ray has hit the surface. Return $t$ (or $\mathbf{p}$) and mark as hit [S3, S11, S24, unofficial].
    c.  **Check Max Distance**: If $t \ge D_{max}$, the ray has traveled too far without hitting the surface. Return $D_{max}$ (or a miss indicator) [S11, unofficial][S26].
    d.  **Step**: Advance the ray by the distance $d$. Update $t \leftarrow t + d$ [S3, S11, S12, unofficial]. Note: If $d$ is negative (inside the object), the ray moves backward toward the surface boundary [S21, unofficial].
3.  **Termination**: If the loop completes without hitting the surface, return a miss indicator (e.g., $t = D_{max}$) [S11, unofficial][S26].

### Pseudocode
```python
def sphere_trace(ray_origin, ray_direction, sdf_function, max_dist, epsilon, max_steps):
    """
    Performs sphere tracing to find the intersection of a ray with an SDF surface.
    
    Args:
        ray_origin (vec3): The starting point of the ray.
        ray_direction (vec3): The normalized direction of the ray.
        sdf_function (func): A function f(p) returning the signed distance to the surface.
        max_dist (float): The maximum distance the ray will travel.
        epsilon (float): The threshold for considering a point as a hit.
        max_steps (int): The maximum number of iterations allowed.
        
    Returns:
        float: The distance to the hit point, or max_dist if no hit is found.
        bool: True if a hit was found, False otherwise.
    """
    t = 0.0
    hit = False
    
    for i in range(max_steps):
        # 1. Calculate current position
        current_pos = ray_origin + ray_direction * t
        
        # 2. Evaluate SDF
        dist = sdf_function(current_pos)
        
        # 3. Check for surface hit
        # Using absolute value for signed distance fields to handle both inside/outside
        if abs(dist) < epsilon:
            hit = True
            break
            
        # 4. Check for max distance exceeded
        if t >= max_dist:
            break
            
        # 5. Step forward
        # The SDF value is the safe lower bound for the step size
        t += dist
        
    return t, hit
```

### Parameters and Typical Values
*   **Epsilon ($\epsilon$)**: Determines the precision of the hit. Typical values range from $10^{-4}$ to $10^{-6}$ [S4, S5, S11, unofficial]. A larger epsilon may cause the ray to stop slightly before or after the true surface, while a smaller epsilon increases iteration count [S23, unofficial].
*   **Max Steps ($N_{max}$)**: Limits the computational cost. Typical values are 10–32 for simple scenes or real-time shaders, and up to 1024 for high-quality offline rendering [S4, S6, S11, S21, unofficial].
*   **Max Distance ($D_{max}$)**: The far clipping plane for the ray. Typical values depend on scene scale, e.g., 100.0 or 1000.0 [S11, S24, unofficial].

### Edge Cases and Pitfalls
*   **Overshooting**: If the function used is not a true SDF (i.e., the gradient magnitude $|\nabla f| \neq 1$), the step size may be too large, causing the ray to pass through the surface [S24, unofficial]. This is known as the "blind root-finding" problem [S26].
*   **Thin Geometry**: Rays passing near parallel surfaces or grazing angles may require many iterations because the step size is constrained by the small distance to the nearest surface [S2][S23, unofficial].
*   **Non-Convergence**: If the ray does not converge within `max_steps`, the result is invalid. Implementations often zero out the position or mark the ray as a miss [S3, unofficial].
*   **Inside the Surface**: If the ray starts inside an object ($f(\mathbf{p}) < 0$), the step size is negative, moving the ray backward toward the surface boundary [S21, unofficial].

## Subtopics

### [Cone Intersection](1553-cone-intersection.md)
Antialiasing technique representing pixels as cones to compute fractional coverage, differing from standard sphere tracing by detecting intersections with an "inner cover" surface.

### [Segment Tracing](1675-segment-tracing.md)
Uses local Lipschitz bounds on candidate segments for adaptive step sizes, reducing SDF queries compared to global bounds.

### [Quadric Tracing](1866-quadric-tracing.md)
Accelerates convergence by precomputing augmented distance fields using quadric surfaces to bound geometry.

### [Chamfer-L1 Distance Computation](2752-chamfer-l1-distance-computation.md)
Post-processing metric for evaluating geometric fidelity between predicted SDFs and ground-truth meshes.

### [Over-relaxation Sphere Tracing](3805-over-relaxation-sphere-tracing.md)
Steps further than the SDF bound allows using a relaxation parameter $\omega$ to reduce iteration counts.

### [Enhanced Sphere Tracing](3811-enhanced-sphere-tracing.md)
Steps by a multiple of the SDF value to accelerate convergence at grazing angles and allow surface penetration.

### [Non-Linear Sphere Tracing](4079-non-linear-sphere-tracing.md)
Solves ray traversal in deformed SDF spaces by integrating an ODE, correcting for invalid Euclidean metrics.

## Operating characteristics
*   **Time Complexity**: The number of iterations depends on the scene complexity and the ray's path. In the best case (perpendicular approach to flat surfaces), convergence is fast [S2]. In the worst case (grazing angles or parallel surfaces), the number of steps increases significantly [S2].
*   **Memory Complexity**: $O(1)$ auxiliary memory per ray, as only the current position and distance traveled are stored [S11, unofficial].
*   **Performance**: Highly efficient for procedural geometry and complex implicit surfaces where explicit mesh storage would be prohibitive [S16, S19, unofficial]. Performance is limited by the cost of evaluating the SDF function, which can be complex for CSG operations or noise fields [S1].
*   **Strengths**: Robust handling of pathological surfaces, no need for mesh data, compact representation of geometry, and inherent antialiasing capabilities when combined with cone tracing [S8, S16, unofficial].
*   **Limitations**: Slow convergence near grazing angles or thin features [S2][S23, unofficial]. Requires the SDF to be Lipschitz continuous with a known constant [S1]. Not suitable for non-SDF implicit functions without modification [S24, unofficial].

## Background
Sphere Tracing was introduced by John C. Hart in 1996 [S1][S8, unofficial]. It was developed as a geometric method for the antialiased ray tracing of implicit surfaces, leveraging the properties of distance functions to guarantee convergence without overshooting [S8, unofficial]. The technique has become a staple in the demoscene and real-time graphics (e.g., Shadertoy) due to its ability to render complex procedural geometry efficiently in fragment shaders [S6, S16, unofficial]. It is closely related to the broader field of Signed Distance Field (SDF) rendering and is a specific instance of distance-field ray marching [S1, S26].
