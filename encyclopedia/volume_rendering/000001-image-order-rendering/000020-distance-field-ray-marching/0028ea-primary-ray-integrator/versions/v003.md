# Primary Ray Integrator

Also called: Composite Ray Marcher, renderRay

## Overview
The Primary Ray Integrator is a single-function ray integrator that resolves a complete ray by compositing terrain, water, sky, cloud volume, and aerial perspective [S1, unofficial]. It serves as the core rendering loop for distance-field ray marching in terrain and atmospheric scenes, handling the sequential evaluation of distinct environmental layers [S1, unofficial]. It sets itself apart from sibling methods by explicitly managing the compositing order of heterogeneous scene elements (solid surfaces vs. volumetric clouds) and handling secondary ray recursion to prevent infinite loops [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:**
    *   `ctx`: A `RenderContext` object containing scratch buffers, theme parameters, and camera state [S1, unofficial].
    *   `ox, oy, oz`: The ray origin coordinates [S1, unofficial].
    *   `dx, dy, dz`: The normalized ray direction vector components [S1, unofficial].
    *   `tMax`: The maximum ray distance for traversal [S1, unofficial].
    *   `depth`: An integer recursion depth counter. Primary rays pass `0`; secondary rays (reflections/refractions) pass `1` [S1, unofficial].
*   **Outputs:**
    *   `result`: An `Rgb` color value representing the final pixel color [S1, unofficial].

**Data Structures:**
*   `RenderScratch`: A struct used for intermediate calculations, initialized to zero upon creation [S1, unofficial]. It contains:
    *   `result` (`Rgb`): Accumulated color.
    *   `secondary` (`Rgb`): Color for secondary ray contributions.
    *   `surface` (`SurfaceShade`): Surface shading data (albedo, normal, etc.) [S1, unofficial].

**Algorithm Steps:**

1.  **Secondary Ray Guard:** If `depth > 0`, disable water and cloud passes to prevent infinite recursion [S1, unofficial].
2.  **Water Plane Intersection:** If `depth == 0`, test for intersection with the water plane.
    *   Compute the water hit distance.
    *   Determine `limit`: the minimum of the water hit distance and `tMax`. If no water hit, `limit = tMax` [S1, unofficial].
3.  **Terrain/Water/Sky Trace:** Trace the ray from the origin along the direction up to `limit` using the SDF sphere tracing method [S1, unofficial].
    *   Determine the `hitKind`: `KIND_TERRAIN`, `KIND_WATER`, or `KIND_SKY` [S1, unofficial].
    *   Determine the `distance` to the hit [S1, unofficial].
4.  **Surface Shading:**
    *   **If `KIND_TERRAIN`:**
        *   Compute hit position: $\mathbf{p} = \mathbf{o} + \mathbf{d} \cdot t_{\text{terrain}}$ [S1, unofficial].
        *   Call `shadeTerrain` with the hit position and a `ditherAngle` [S1, unofficial].
        *   Copy the resulting surface color to `result` [S1, unofficial].
    *   **If `KIND_WATER`:**
        *   Compute hit position: $\mathbf{p} = \mathbf{o} + \mathbf{d} \cdot t_{\text{water}}$ [S1, unofficial].
        *   Call `shadeWater` with `ctx.waterShade` parameters [S1, unofficial].
        *   Copy the resulting surface color to `result` [S1, unofficial].
    *   **If `KIND_SKY` or no hit:**
        *   Call `skyRadiance` with the ray direction to fill `result` [S1, unofficial].
5.  **Atmospheric Compositing:**
    *   **If `KIND_SKY`:** Apply sky haze using the vertical component of the direction vector, $d_y$ [S1, unofficial].
    *   **Else (Terrain/Water hit):**
        *   Compute the hit Y coordinate: $y_{\text{hit}} = o_y + d_y \cdot \text{distance}$ [S1, unofficial].
        *   Apply aerial perspective using `distance`, $y_{\text{hit}}$, and the ray direction to composite the atmosphere over the surface color [S1, unofficial].

**Pseudocode:**

```python
def renderRay(ctx, ox, oy, oz, dx, dy, dz, tMax, depth):
    # Initialize scratch buffers
    scratch = RenderScratch()
    scratch.result = Rgb(0, 0, 0)
    scratch.secondary = Rgb(0, 0, 0)
    scratch.surface = SurfaceShade()

    # Step 1: Secondary Ray Guard
    # Disable water and cloud passes for recursive calls to prevent infinite loops
    if depth > 0:
        disable_water_pass = True
        disable_cloud_pass = True
    else:
        disable_water_pass = False
        disable_cloud_pass = False

    # Step 2: Water Plane Intersection
    limit = tMax
    if not disable_water_pass:
        water_hit_dist = intersect_water_plane(ox, oy, oz, dx, dy, dz)
        if water_hit_dist is not None and water_hit_dist < tMax:
            limit = water_hit_dist

    # Step 3: Terrain/Water/Sky Trace
    # Uses sphere tracing from the parent method [S1, unofficial]
    hit_kind, distance = trace_ray(ox, oy, oz, dx, dy, dz, limit)

    # Step 4: Surface Shading
    if hit_kind == KIND_TERRAIN:
        # Compute hit position
        px = ox + dx * distance
        py = oy + dy * distance
        pz = oz + dz * distance
        
        # Shade terrain
        shadeTerrain(px, py, pz, scratch.surface, ditherAngle)
        scratch.result = scratch.surface.color
        
    elif hit_kind == KIND_WATER:
        # Compute hit position
        px = ox + dx * distance
        py = oy + dy * distance
        pz = oz + dz * distance
        
        # Shade water
        shadeWater(px, py, pz, scratch.surface, ctx.waterShade)
        scratch.result = scratch.surface.color
        
    else:
        # Sky or no hit
        scratch.result = skyRadiance(dx, dy, dz)

    # Step 5: Atmospheric Compositing
    if hit_kind == KIND_SKY:
        # Apply sky haze using vertical component
        haze_factor = compute_haze(dy)
        scratch.result = composite_haze(scratch.result, haze_factor)
    else:
        # Compute hit Y coordinate
        y_hit = oy + dy * distance
        
        # Apply aerial perspective
        scratch.result = apply_aerial_perspective(
            scratch.result, 
            distance, 
            y_hit, 
            dx, dy, dz
        )

    return scratch.result
```

**Parameters:**
*   `ditherAngle`: Used in terrain shading to reduce banding artifacts [S1, unofficial].
*   `ctx.waterShade`: Configuration object for water rendering properties [S1, unofficial].
*   `epsilon`: Convergence threshold for sphere tracing (typically $0.001$) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Infinite Recursion:** Secondary rays (water reflections/refractions) calling back into the primary integrator can cause infinite loops. This is handled by checking `depth > 0` and disabling water/cloud passes for recursive calls [S1, unofficial].
*   **Boundary Conditions:** If `tMax` is not respected, rays may escape the scene bounds without proper termination [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of sphere tracing steps per ray. The complexity is dominated by the SDF evaluations required to find the terrain/water/sky hit [S1, unofficial].
*   **Memory Complexity:** Constant per ray, using the `RenderScratch` struct [S1, unofficial].
*   **Strengths:** Simple implementation; handles multiple scene types (terrain, water, sky, clouds) in a single pass; robust against recursion issues via depth checking [S1, unofficial].
*   **Limitations:** Limited to specific scene compositions defined in the integrator; does not handle complex volumetric scattering beyond simple aerial perspective and cloud compositing [S1, unofficial].
*   **When to use:** Ideal for terrain and atmospheric rendering where a single dominant light path is sufficient, and performance is prioritized over full global illumination [S1, unofficial].
