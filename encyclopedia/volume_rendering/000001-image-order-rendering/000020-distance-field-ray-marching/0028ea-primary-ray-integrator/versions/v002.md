# Primary Ray Integrator

Also called: Composite Ray Marcher, renderRay

## Overview
The Primary Ray Integrator is a composite ray-marching method that resolves a single primary ray by sequentially tracing and compositing terrain, water, sky, and volumetric cloud layers [S1, unofficial]. It distinguishes itself from basic sphere tracing by handling heterogeneous scene components (solid terrain, reflective water, volumetric clouds) within a single traversal loop, applying aerial perspective and sky haze based on hit depth [S1, unofficial]. It serves as the foundational renderer for complex procedural landscapes, building on the distance-field ray marching principles [21-distance-field-ray-marching.md] to manage multiple surface types and volume interactions.

## How it works
The method integrates distinct rendering passes (terrain, water, sky, clouds) into a unified ray resolution process. It uses a scratch buffer to accumulate color and shading data, preventing intermediate overwrites during the compositing phase.

### Inputs and Outputs
**Inputs:**
- `ox, oy, oz`: Ray origin coordinates [S1, unofficial].
- `dx, dy, dz`: Ray direction vector components [S1, unofficial].
- `tMax`: Maximum ray distance for traversal [S1, unofficial].
- `depth`: Recursion depth counter. `0` for primary rays; `>0` for secondary rays (reflections/refractions) [S1, unofficial].
- `ctx`: RenderContext containing scratch buffers, theme parameters, and camera state [S1, unofficial].

**Outputs:**
- `result`: The final RGB color for the pixel [S1, unofficial].

### Data Structures
The method relies on a `RenderScratch` structure to manage intermediate state. It is initialized to zero upon creation [S1, unofficial].

**Layout of `RenderScratch`:**
- `result` (Rgb): Accumulated final color.
- `secondary` (Rgb): Buffer for secondary ray contributions (e.g., reflections).
- `surface` (SurfaceShade): Struct containing surface shading data (color, normal, material properties) [S1, unofficial].

### Steps
1.  **Initialization**: Create `RenderScratch` and initialize `result`, `secondary`, and `surface` to zero [S1, unofficial].
2.  **Water Plane Check**: If `depth == 0`, test for intersection with the water plane. Compute `limit` as $\min(\text{water\_hit\_distance}, t_{max})$. If no water hit, `limit = t_{max}` [S1, unofficial].
3.  **Terrain Tracing**: Trace a terrain ray from the origin along the direction up to `limit`. Determine the hit kind (`KIND_TERRAIN`, `KIND_WATER`, `KIND_SKY`) and the distance to the hit [S1, unofficial].
4.  **Hit Processing**:
    -   **If Terrain Hit**: Compute hit position $\mathbf{p} = \mathbf{o} + \mathbf{d} \cdot t_{terrain}$. Call `shadeTerrain` with the dither angle. Copy the resulting surface color to `result` [S1, unofficial].
    -   **If Water Hit**: Compute hit position. Call `shadeWater` with `ctx.waterShade` parameters. Copy the resulting surface color to `result` [S1, unofficial].
    -   **If No Terrain or Water Hit (Sky)**: Call `skyRadiance` with the ray direction to fill `result` [S1, unofficial].
5.  **Atmospheric Effects**:
    -   **If Sky Hit**: Apply sky haze using the vertical component of the direction vector $d_y$ [S1, unofficial].
    -   **If Terrain/Water Hit**: Compute the hit Y coordinate $y = o_y + d_y \cdot \text{distance}$. Apply aerial perspective using the distance, Y coordinate, and direction [S1, unofficial].
6.  **Secondary Rays**: If `depth > 0`, disable water and cloud passes to prevent infinite recursion loops [S1, unofficial].

### Pseudocode
```python
def primary_ray_integrator(ox, oy, oz, dx, dy, dz, tMax, depth, ctx):
    # Initialize scratch buffers
    scratch = RenderScratch()
    scratch.result = (0.0, 0.0, 0.0)
    scratch.secondary = (0.0, 0.0, 0.0)
    scratch.surface = SurfaceShade()

    # Step 2: Water plane intersection check for primary rays
    limit = tMax
    if depth == 0:
        water_hit_dist = test_water_plane_intersection(ox, oy, oz, dx, dy, dz)
        if water_hit_dist is not None:
            limit = min(water_hit_dist, tMax)
        else:
            limit = tMax

    # Step 3: Trace terrain ray up to limit
    hit_kind, hit_distance = trace_terrain_ray(ox, oy, oz, dx, dy, dz, limit)

    # Step 4: Process hits
    if hit_kind == KIND_TERRAIN:
        hit_pos_x = ox + dx * hit_distance
        hit_pos_y = oy + dy * hit_distance
        hit_pos_z = oz + dz * hit_distance
        # [G] shadeTerrain computes color based on terrain SDF, lighting, and dithering
        scratch.result = shadeTerrain(hit_pos_x, hit_pos_y, hit_pos_z, ctx.theme.ditherAngle)
        
    elif hit_kind == KIND_WATER:
        hit_pos_x = ox + dx * hit_distance
        hit_pos_y = oy + dy * hit_distance
        hit_pos_z = oz + dz * hit_distance
        # [G] shadeWater computes color based on water material and lighting
        scratch.result = shadeWater(hit_pos_x, hit_pos_y, hit_pos_z, ctx.waterShade)
        
    else: # KIND_SKY or no hit
        scratch.result = skyRadiance(dx, dy, dz)

    # Step 5: Atmospheric effects
    if hit_kind == KIND_SKY:
        # Apply sky haze based on vertical direction component
        scratch.result = apply_sky_haze(scratch.result, dy)
    else:
        # Compute hit Y coordinate
        hit_y = oy + dy * hit_distance
        # Apply aerial perspective
        scratch.result = apply_aerial_perspective(scratch.result, hit_distance, hit_y, dx, dy, dz)

    # Step 6: Handle recursion depth
    # If depth > 0, water and cloud passes are disabled in shadeWater/shadeCloud
    # to prevent infinite recursion [S1, unofficial]

    return scratch.result
```

### Parameters and Edge Cases
-   **Depth Guard**: The `depth` parameter is critical. Secondary rays (reflections/refractions) call the integrator with `depth > 0`. The method must disable water and cloud passes in this case to avoid infinite recursion [S1, unofficial].
-   **Precision**: Floating-point precision errors in `trace_terrain_ray` may cause jitter or missed hits near the water surface. Using a small epsilon for hit comparisons is recommended [G].
-   **Boundary Conditions**: If `tMax` is too small, the ray may escape the scene prematurely. If `tMax` is too large, performance degrades due to unnecessary traversal [S1, unofficial].

## Operating characteristics
-   **Time Complexity**: Linear with respect to the number of steps in the ray march, which depends on the scene complexity and `tMax` [S1, unofficial].
-   **Memory Complexity**: Constant, $O(1)$, as it uses a fixed-size `RenderScratch` buffer per ray [S1, unofficial].
-   **Strengths**: Unified handling of terrain, water, sky, and clouds in a single pass; efficient compositing; supports recursive reflections/refractions with depth limiting [S1, unofficial].
-   **Limitations**: Not given in the sources.
-   **When to Use**: Ideal for procedural landscape rendering where multiple surface types and atmospheric effects are required [S1, unofficial].
-   **When Not to Use**: Not suitable for scenes requiring complex volumetric scattering within the terrain itself or non-hierarchical scene graphs [S1, unofficial].
