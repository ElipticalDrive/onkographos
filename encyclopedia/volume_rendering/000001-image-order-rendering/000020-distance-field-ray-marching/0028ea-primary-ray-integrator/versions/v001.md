# Primary Ray Integrator

Also called: Composite Ray Marcher, renderRay

## Overview
The Primary Ray Integrator is a single-function ray integrator that resolves a complete ray by compositing terrain, water, sky, cloud volumes, and aerial perspective [S1, unofficial]. It serves as the core rendering loop for complex natural scenes, handling the intersection logic for multiple surface types and the volumetric attenuation of light through the atmosphere [S1, unofficial]. It is distinguished from sibling methods by its explicit handling of secondary rays (reflections/refractions) via a recursion depth counter that disables specific passes (water, clouds) to prevent infinite recursion loops [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**:
    *   `ctx`: RenderContext containing scratch buffers, theme configuration, and camera state [S1, unofficial].
    *   `ox, oy, oz`: Ray origin coordinates [S1, unofficial].
    *   `dx, dy, dz`: Ray direction vector components [S1, unofficial].
    *   `tMax`: Maximum ray distance for traversal [S1, unofficial].
    *   `depth`: Recursion depth counter. Primary rays pass `depth=0`; secondary rays pass `depth=1` [S1, unofficial].
*   **Outputs**:
    *   `result`: The final RGB color for the pixel [S1, unofficial].

**Data Structures**
*   `RenderScratch`: A struct used for intermediate calculations, initialized to zero on creation [S1, unofficial].
    *   `result`: `Rgb` (final color) [S1, unofficial].
    *   `secondary`: `Rgb` (color for secondary rays) [S1, unofficial].
    *   `surface`: `SurfaceShade` (shading data for the hit point) [S1, unofficial].

**Algorithm Steps**
1.  **Water Plane Check**: If `depth` equals zero, test for intersection with the water plane [S1, unofficial].
    *   Compute `limit` as the minimum of the water hit distance and `tMax`. If no water hit is detected, `limit` is `tMax` [S1, unofficial].
2.  **Terrain/Water/Sky Trace**: Trace a ray from the origin along the direction up to `limit` [S1, unofficial].
    *   Determine the `hitKind` (`KIND_TERRAIN`, `KIND_WATER`, or `KIND_SKY`) and the `distance` to the hit [S1, unofficial].
3.  **Surface Shading**:
    *   If `hitKind` is `KIND_TERRAIN`:
        *   Compute hit position: $p = (ox + dx \cdot t_{terrain}, oy + dy \cdot t_{terrain}, oz + dz \cdot t_{terrain})$ [S1, unofficial].
        *   Call `shadeTerrain` with the hit position and `ditherAngle` [S1, unofficial].
        *   Copy the resulting surface color to `result` [S1, unofficial].
    *   If `hitKind` is `KIND_WATER`:
        *   Compute hit position [S1, unofficial].
        *   Call `shadeWater` with `ctx.waterShade` [S1, unofficial].
        *   Copy the resulting surface color to `result` [S1, unofficial].
4.  **Sky and Volumetrics**:
    *   If no terrain or water hit is found (i.e., `hitKind` is `KIND_SKY` or miss):
        *   Call `skyRadiance` with the ray direction to fill `result` [S1, unofficial].
        *   If the hit was a sky hit, apply sky haze using the vertical component `dy` of the direction [S1, unofficial].
    *   If a terrain or water hit occurred:
        *   Compute the hit Y coordinate: $y_{hit} = oy + dy \cdot distance$ [S1, unofficial].
        *   Apply aerial perspective using the `distance`, $y_{hit}$, and the ray direction to modulate the surface color in `result` [S1, unofficial].

**Pseudocode**
```python
def primary_ray_integrator(ctx, ox, oy, oz, dx, dy, dz, tMax, depth):
    # Initialize scratch buffers
    scratch = RenderScratch()
    scratch.result = Rgb(0, 0, 0)
    scratch.secondary = Rgb(0, 0, 0)
    scratch.surface = SurfaceShade()

    # Step 1: Water plane intersection check (only for primary rays)
    limit = tMax
    if depth == 0:
        water_hit_dist = test_water_plane_intersection(ox, oy, oz, dx, dy, dz)
        if water_hit_dist is not None:
            limit = min(water_hit_dist, tMax)

    # Step 2: Trace ray to determine hit kind and distance
    hit_kind, distance = trace_ray(ox, oy, oz, dx, dy, dz, limit)

    # Step 3: Handle surface hits
    if hit_kind == KIND_TERRAIN:
        t_terrain = distance
        hit_pos_x = ox + dx * t_terrain
        hit_pos_y = oy + dy * t_terrain
        hit_pos_z = oz + dz * t_terrain
        # [G] ditherAngle is derived from ctx or camera state, assumed available
        shade_terrain_result = shadeTerrain(hit_pos_x, hit_pos_y, hit_pos_z, ctx.ditherAngle)
        scratch.result = shade_terrain_result.color

    elif hit_kind == KIND_WATER:
        t_water = distance
        hit_pos_x = ox + dx * t_water
        hit_pos_y = oy + dy * t_water
        hit_pos_z = oz + dz * t_water
        shade_water_result = shadeWater(hit_pos_x, hit_pos_y, hit_pos_z, ctx.waterShade)
        scratch.result = shade_water_result.color

    else:
        # Step 4: Sky and Volumetrics
        sky_color = skyRadiance(dx, dy, dz)
        scratch.result = sky_color

        if hit_kind == KIND_SKY:
            # Apply sky haze using vertical component dy
            scratch.result = apply_sky_haze(scratch.result, dy)
        else:
            # Terrain or Water hit: Apply aerial perspective
            hit_y = oy + dy * distance
            scratch.result = apply_aerial_perspective(scratch.result, distance, hit_y, dx, dy, dz)

    return scratch.result
```

## Background
The Primary Ray Integrator is described in the context of the `theme1` project, an unofficial implementation of a terrain and atmospheric renderer [S1, unofficial]. It integrates concepts of sphere tracing for terrain/water surfaces with volumetric shading for sky and aerial perspective [S1, unofficial].
