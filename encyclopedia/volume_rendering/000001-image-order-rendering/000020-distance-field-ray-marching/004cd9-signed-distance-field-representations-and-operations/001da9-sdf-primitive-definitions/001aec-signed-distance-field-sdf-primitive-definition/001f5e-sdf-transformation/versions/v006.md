# SDF Transformation

Also called: SDF Transforms, Transforming SDFs, Transforming SDF Geometry, Transformed SDF, SDF Affine Transformation, SDF Spatial Transformations, SDF Model Transformations, SDF Inverse Transformation, Inverse Transform SDF, Inverse Transformation for Rotation/Translation, Rigid Body Transformation of SDFs

## Overview
SDF Transformation is a technique for applying geometric transformations (rotation, translation, scaling, deformation) to Signed Distance Field primitives by manipulating the query point coordinates before evaluating the base distance function [S1, unofficial][S3, unofficial][S8, unofficial]. It solves the problem of positioning and animating implicit surfaces in world space without modifying the underlying primitive definitions [S3, unofficial][S11, unofficial]. It differs from [Uniform Scaling of SDFs](2394-uniform-scaling-of-sdfs.md) by supporting arbitrary rigid body and non-linear domain transformations, and from [Implicit Surface Field Function Evaluation](1599-implicit-surface-field-function-evaluation.md) by explicitly applying the inverse coordinate mapping before distance query [S1, unofficial][S3, unofficial][S10, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A query point $\mathbf{x}$ in world space, and a transformation $T$ (defined by parameters such as translation vector $\mathbf{d}$, rotation matrix $R$, scale factor $s$, or deformation function) [S10, unofficial][S12, unofficial].
- Output: A signed distance value $d$ relative to the transformed surface [S13].

**Data Structures:**
- Transformation Matrix: A $4 \times 4$ homogeneous matrix $M$ representing the local-to-world transformation [S11, unofficial].
- Parameters:
  - Translation $\mathbf{d}$: 3-element vector specifying the translation [S5, unofficial].
  - Rotation angle $\theta$: Scalar [S8, unofficial].
  - Scale $s$: Scalar (uniform) or vector (non-uniform) [S8, unofficial][S10, unofficial].
  - Deformation coefficients: Scalars defining non-linear warps (e.g., twist rate) [S1, unofficial][S8, unofficial].

**Method Steps:**
1. **Compute Inverse Transformation:** Determine the inverse of the desired transformation $T^{-1}$ [S10, unofficial][S12, unofficial]. For rigid body transformations (isometries), the inverse of a rotation by $\theta$ is a rotation by $-\theta$ [S3, unofficial][S6, unofficial]. For translation by $\mathbf{d}$, the inverse is translation by $-\mathbf{d}$ [S8, unofficial]. For uniform scaling by $s$, the inverse is scaling by $1/s$ [S10, unofficial].
2. **Transform Query Point:** Apply $T^{-1}$ to the world-space query point $\mathbf{x}$ to obtain the local-space point $\mathbf{x}'$ [S3, unofficial][S10, unofficial].
   - For matrix transformations: $\mathbf{x}' = (M^{-1} \cdot [\mathbf{x}, 1]^T)_{xyz}$ [S6, unofficial][S11, unofficial].
   - For translation: $\mathbf{x}' = \mathbf{x} - \mathbf{d}$ [S8, unofficial].
   - For uniform scale: $\mathbf{x}' = \mathbf{x} / s$ [S10, unofficial].
   - For non-linear deformations (e.g., twist): Apply the inverse warp function to $\mathbf{x}$ [S1, unofficial][S8, unofficial].
3. **Evaluate Base SDF:** Query the base signed distance function $f$ with the transformed point: $d' = f(\mathbf{x}')$ [S10, unofficial][S12, unofficial].
4. **Adjust Distance (Non-Isometries):** If the transformation is not an isometry (e.g., scaling or non-linear deformation), adjust the returned distance $d'$ to preserve the metric property of the SDF [S10, unofficial][S12, unofficial].
   - For uniform scaling by $s$: $d = s \cdot d'$ [S10, unofficial][S12, unofficial].
   - For isometries (rotation, translation, reflection): No adjustment is needed; $d = d'$ [S10, unofficial][S12, unofficial][S13].
   - For non-linear deformations: The distance value may no longer be a strict signed distance; step size bounds must be adjusted using Lipschitz constants [S1, unofficial][S13].

**Formulas:**
- General Transformed Surface: $f(T^{-1}(\mathbf{x})) = 0$ [S10, unofficial][S12, unofficial].
- Isometry Distance Preservation: $d(\mathbf{x}, I \circ f^{-1}(0)) = d(I^{-1}(\mathbf{x}), f^{-1}(0))$ [S10, unofficial][S12, unofficial].
- Uniform Scale Distance: $d(\mathbf{x}, S(f^{-1}(0))) = s \cdot d(S^{-1}(\mathbf{x}), f^{-1}(0))$ where $S^{-1}(\mathbf{x}) = \mathbf{x}/s$ [S10, unofficial][S12, unofficial].
- Twist Transformation: $\mathbf{q} = \text{rotateY}(\mathbf{p}, k \cdot p_y)$, where $k$ is the twist factor [S1, unofficial][S2, unofficial].

**Pseudocode:**
```python
import math

class Vec3:
    def __init__(self, x, y, z): self.x, self.y, self.z = x, y, z
    def __sub__(self, other): return Vec3(self.x - other.x, self.y - other.y, self.z - other.z)
    def __truediv__(self, scalar): return Vec3(self.x / scalar, self.y / scalar, self.z / scalar)
    @property
    def xyz(self): return (self.x, self.y, self.z)

class Vec4:
    def __init__(self, x, y, z, w): self.x, self.y, self.z, self.w = x, y, z, w

class Mat4:
    def __init__(self, rows): self.rows = rows
    def __mul__(self, v):
        # Row-vector multiplication: v * M
        return Vec4(
            v.x * self.rows[0][0] + v.y * self.rows[1][0] + v.z * self.rows[2][0] + v.w * self.rows[3][0],
            v.x * self.rows[0][1] + v.y * self.rows[1][1] + v.z * self.rows[2][1] + v.w * self.rows[3][1],
            v.x * self.rows[0][2] + v.y * self.rows[1][2] + v.z * self.rows[2][2] + v.w * self.rows[3][2],
            v.x * self.rows[0][3] + v.y * self.rows[1][3] + v.z * self.rows[2][3] + v.w * self.rows[3][3]
        )

def transform_sdf(query_point: Vec3, transform_type: str, params: dict, base_sdf: callable) -> float:
    """
    Applies a geometric transformation to an SDF primitive.
    
    Args:
        query_point: World-space point to evaluate.
        transform_type: 'translation', 'rotation', 'scale', 'twist', 'matrix'.
        params: Dictionary containing transformation parameters.
        base_sdf: Function returning signed distance for the untransformed primitive.
        
    Returns:
        Signed distance to the transformed surface.
    """
    x = query_point
    
    # Step 1 & 2: Inverse Transform and Query Point
    if transform_type == 'translation':
        d = params['translation']
        x_local = x - d
        
    elif transform_type == 'rotation':
        theta = params['angle']
        c = math.cos(-theta)
        sin_val = math.sin(-theta)
        rot_inv = Mat4([
            [c, 0, sin_val, 0],
            [0, 1, 0, 0],
            [-sin_val, 0, c, 0],
            [0, 0, 0, 1]
        ])
        x_homogeneous = Vec4(x.x, x.y, x.z, 1.0)
        x_local = Vec3(*rot_inv * x_homogeneous).xyz
        
    elif transform_type == 'scale':
        scale_factor = params['scale_factor']
        x_local = x / scale_factor
        
    elif transform_type == 'twist':
        k = params['twist_factor']
        angle = -k * x.y
        c = math.cos(angle)
        sin_val = math.sin(angle)
        x_local = Vec3(
            x.x * c - x.z * sin_val,
            x.y,
            x.x * sin_val + x.z * c
        )
        
    elif transform_type == 'matrix':
        M_inv = params['inverse_matrix']
        x_homogeneous = Vec4(x.x, x.y, x.z, 1.0)
        x_local = Vec3(*M_inv * x_homogeneous).xyz
        
    else:
        raise ValueError("Unknown transform type")

    # Step 3: Evaluate Base SDF
    dist_local = base_sdf(x_local)
    
    # Step 4: Adjust Distance for Non-Isometries
    if transform_type == 'scale':
        scale_factor = params['scale_factor']
        dist = scale_factor * dist_local
    else:
        dist = dist_local
        
    return dist
```

**Edge Cases and Pitfalls:**
- **GLSL Matrix Inversion:** WebGL/GLSL lacks a built-in matrix inversion routine. For rotation matrices, use the transpose (negative angle) instead of `invert()` [S3, unofficial][S6, unofficial].
- **Non-Uniform Scaling:** Non-uniform spatial distortion breaks local linearity, requiring conservative step size bounds to prevent ray tunneling [S11, unofficial].
- **Deformation:** Non-linear spatial distortion (e.g., twist, bend) breaks local linearity, making normal estimation via finite differences inaccurate and requiring adjusted step sizes [S11, unofficial][S13].

## Subtopics

### [Lipschitz Transformation Bounds](1557-lipschitz-transformation-bounds.md)
Lipschitz Transformation Bounds provide a method to compute valid step sizes for ray marching through implicitly defined surfaces that have undergone spatial transformations. It solves the problem that standard Euclidean distance queries return incorrect step sizes when the underlying space is distorted, preventing ray tunneling. It differs from [Uniform Scaling of SDFs](2394-uniform-scaling-of-sdfs.md) by handling non-uniform and non-linear deformations via the Jacobian norm, and from [Spatial and nD transforms](3106-spatial-and-nd-transforms.md) by explicitly deriving the Lipschitz constant required for safety rather than just applying the inverse transform.

### [Implicit Surface Field Function Evaluation](1599-implicit-surface-field-function-evaluation.md)
Implicit Surface Field Function Evaluation computes the scalar value $d = f(x,y,z)$ for a query point in 3D space. It maps coordinates to a signed distance or density, where $d < 0$ indicates the interior, $d > 0$ the exterior, and $d = 0$ the surface contour.

### [Uniform Scaling of SDFs](2394-uniform-scaling-of-sdfs.md)
Uniform scaling of Signed Distance Fields (SDFs) is a technique to transform an implicit surface by a uniform factor while preserving the correctness of the distance value for ray marching. It solves the problem that scaling is not a rigid body transformation and distorts distances; without correction, the ray marching algorithm may overestimate the distance to the surface, causing the object to disappear. Unlike [Non-Uniform Scaling of SDFs](2423-non-uniform-scaling-of-sdfs.md), which requires conservative bounds to avoid overestimation, uniform scaling allows for an exact compensation of distance distortion.

### [Spatial and nD transforms](3106-spatial-and-nd-transforms.md)
Spatial and nD transforms apply geometric transformations to Signed Distance Field (SDF) primitives by inverse-transforming the query point rather than the geometry itself. This approach allows for the rotation, translation, scaling, and permutation of SDF models within the distance function evaluation. It sets itself apart from direct geometry manipulation by maintaining the mathematical integrity of the distance field while enabling complex hierarchical or per-node transformations, particularly in multidimensional data structures.

### Deformation SDF
A technique to create a 'blob effect' by perturbing the position $p$ with trigonometric functions before querying the SDF. This is noted as 'cheating' because it breaks the strict mathematical properties of the SDF [S14, unofficial].
- **Step:** Perturb coordinates using trigonometric functions:
  - $p_x \leftarrow p_x + 0.02 \cos(8 p_y + 3 p_z)$ [S14, unofficial].
  - $p_y \leftarrow p_y + 0.02 \sin(6 p_z + 7 p_x)$ [S14, unofficial].
  - $p_z \leftarrow p_z + 0.02 \cos(8 p_x + 9 p_x)$ [S14, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query, dominated by the cost of the base SDF evaluation and the transformation arithmetic [G].
- **Memory Complexity:** $O(1)$, requiring only storage for transformation parameters [G].
- **Strengths:** Enables complex scene composition, animation, and hierarchical modeling without modifying primitive definitions. Rigid body transformations preserve the SDF property exactly [S3, unofficial][S11, unofficial].
- **Limitations:** Non-rigid transformations (scaling, deformation) break the strict SDF property, requiring heuristic adjustments to step sizes or normal estimation [S11, unofficial][S13]. Non-linear deformations can cause artifacts in normal calculation if finite differences are used [S11, unofficial].
- **When to Use:** Ideal for rigid body animation, camera-relative effects, and simple scaling [G]. Use caution with non-linear deformations in contexts requiring precise normals or strict distance guarantees [S11, unofficial].

## Background
Originating from the foundational work on ray marching and signed distance fields in computer graphics, SDF transformations were popularized by blogs and tutorials such as those by Jamie Wong and 9bitScience [S1, unofficial][S3, unofficial]. The mathematical formalization of implicit surface transformations, including the distinction between isometries and non-isometries, is detailed in academic works on GPU ray marching [S10, unofficial][S12, unofficial]. The technique is widely used in real-time rendering, particularly in Shadertoy-style demos and WebGL implementations [S3, unofficial][S4, unofficial].
