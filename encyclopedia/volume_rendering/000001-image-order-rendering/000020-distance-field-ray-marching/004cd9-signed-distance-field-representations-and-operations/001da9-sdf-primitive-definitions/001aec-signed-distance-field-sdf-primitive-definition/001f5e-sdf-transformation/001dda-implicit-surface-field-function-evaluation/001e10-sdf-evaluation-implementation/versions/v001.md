# SDF Evaluation Implementation

Also called: SDF Handler Implementation, SDF Query Handler

## Overview
SDF Evaluation Implementation provides the concrete runtime interface for querying Signed Distance Field (SDF) values and their spatial derivatives (normals) from various implicit representations, including analytic primitives, neural networks, and learned deformable fields. It solves the problem of abstracting the underlying SDF definition (e.g., [SDF Primitive Definitions](52-name.md) or neural implicit fields) into a uniform callable interface suitable for ray marching and intersection queries. Unlike [Implicit Surface Field Function Evaluation](1599-implicit-surface-field-function-evaluation.md), which defines the mathematical concept of the field function $d = f(x,y,z)$, this implementation focuses on the software architecture, batching strategies, and numerical stability required to execute these queries efficiently in a rendering or reconstruction pipeline.

## How it works

### Inputs and Outputs
*   **Inputs**:
    *   Query point $q \in \mathbb{R}^3$.
    *   SDF identifier or configuration (e.g., name, neural weights, fractal parameters).
    *   Batch of sample points (for batched inference).
    *   Tetrahedron vertices (for mesh-based intersection queries).
*   **Outputs**:
    *   Scalar distance value $d \in \mathbb{R}$.
    *   Normal vector $n \in \mathbb{R}^3$ (computed via gradient).
    *   Intersection times and normals for ray/tetrahedron intersections.

### Data Structures
*   **SDF Query Handler**: A class or struct that encapsulates the SDF evaluation logic.
    *   Fields: `sdf_name` (string), `sdf_func` (lambda/function pointer), `min_step_size` (float).
*   **Sample Batch**: A tensor or array structure containing input coordinates and output storage.
    *   Layout: Typically a 2D array or tensor where columns represent features (e.g., column 0-2: $x,y,z$; column 3: SDF value $d$).

### Steps

#### 1. Initialization and Validation
1.  Receive SDF identifier `name`.
2.  Validate `name` using a registry function `is_valid_sdf_name(name)` [S1, unofficial].
3.  If invalid, throw `std::runtime_error("unknown SDF '" + name + "')` [S1, unofficial].
4.  Construct an evaluation lambda `sdf_func` that maps a generic `Vector3` to the specific SDF implementation (e.g., converting to `glm::vec3` and calling `sdf::evaluate(name, glm_p)`) [S1, unofficial].
5.  Store `sdf_func` and configuration parameters (e.g., `min_step_size`) in the handler instance [S1, unofficial].

#### 2. Point Query (Normal and Distance)
1.  Input query point $q$.
2.  Call `query_normal_SDF(q, sdf_func)` [S1, unofficial].
3.  Inside `query_normal_SDF`:
    *   Evaluate $d = \text{sdf\_func}(q)$.
    *   Compute gradient $\nabla d$ using finite differences or automatic differentiation.
    *   Normalize: $n = \frac{\nabla d}{\|\nabla d\|}$.
    *   Return $d$ and $n$.

#### 3. Tetrahedron Intersection Query
1.  Input: Array of tetrahedron vertices, `sdf_func`, output arrays for intersection times and normals, query count array, `min_step_size`.
2.  Call `tet_edge_intersections_SDF` [S1, unofficial].
3.  For each tetrahedron:
    *   Evaluate SDF at all 4 vertices.
    *   Identify edges where the sign of the SDF value changes (one positive, one negative).
    *   For each crossing edge, perform linear interpolation or root-finding to find the intersection point $p$ and time $t$.
    *   Compute the normal at $p$ using `query_normal_SDF(p, sdf_func)`.
    *   Store $t$ and $n$ in output arrays.
    *   Increment query count if an intersection is found.

### Pseudocode

```python
class SDFQueryHandler:
    def __init__(self, name: str, min_step_size: float = 1e-3):
        if not is_valid_sdf_name(name):
            raise RuntimeError(f"unknown SDF '{name}'")
        
        self.name = name
        self.min_step_size = min_step_size
        
        # Create evaluation lambda
        # Converts Vector3 to glm::vec3 and calls sdf::evaluate
        self.sdf_func = lambda vec: sdf_evaluate(name, to_glm_vec3(vec))

    def query_normal(self, q: Vector3):
        """Compute distance and normal at point q."""
        return query_normal_SDF(q, self.sdf_func)

    def query_intersections(self, tets: List[Tetrahedron], sdf_func=None):
        """
        Find intersections between tetrahedron edges and the SDF zero-level set.
        tets: List of tetrahedrons, each defined by 4 vertices.
        Returns: Lists of intersection times and normals.
        """
        if sdf_func is None:
            sdf_func = self.sdf_func
            
        times = []
        normals = []
        
        for tet in tets:
            # Evaluate SDF at vertices
            vals = [sdf_func(v) for v in tet.vertices]
            
            # Check edges for sign changes
            edges = get_edges(tet.vertices)
            for i, (v1, v2) in enumerate(edges):
                d1 = vals[i]
                d2 = vals[(i + 1) % 4] # Assuming edge pairing logic
                
                if d1 * d2 < 0:
                    # Linear interpolation to find intersection
                    t = d1 / (d1 - d2)
                    p = lerp(v1, v2, t)
                    
                    # Compute normal at intersection
                    n = query_normal_SDF(p, sdf_func)
                    
                    times.append(t)
                    normals.append(n)
                    
        return times, normals

def query_normal_SDF(q: Vector3, sdf_func):
    """Compute normal using central finite differences."""
    eps = 1e-4
    dx = Vector3(eps, 0, 0)
    dy = Vector3(0, eps, 0)
    dz = Vector3(0, 0, eps)
    
    d = sdf_func(q)
    d_x = sdf_func(q + dx)
    d_y = sdf_func(q + dy)
    d_z = sdf_func(q + dz)
    
    grad = Vector3(
        (d_x - d) / eps,
        (d_y - d) / eps,
        (d_z - d) / eps
    )
    
    norm = grad.length()
    if norm < 1e-8:
        return d, Vector3(0, 0, 1) # Default normal if gradient is zero
        
    return d, grad / norm
```

### Parameters
*   `min_step_size`: Minimum step size for ray marching or intersection refinement. Default: $10^{-3}$ [S1, unofficial].
*   `eps`: Finite difference step size for gradient computation. Default: $10^{-4}$ [S3, unofficial].

### Edge Cases and Pitfalls
*   **Invalid SDF Name**: Must be validated at construction time to prevent runtime errors during query [S1, unofficial].
*   **Zero Gradient**: If the gradient magnitude is near zero, the normal is undefined. A default normal or error handling is required [G].
*   **Numerical Stability**: In fractal SDFs (e.g., Mandelbulb), large radius values can cause overflow. A `bailout` threshold is used to break iteration early [S4, unofficial].
*   **Precision**: Finite difference gradients are sensitive to `eps`. Too small `eps` leads to numerical noise; too large leads to approximation error [S3, unofficial].

## Subtopics

### Batched SDF Inference
Batched SDF Inference optimizes the evaluation of SDF values for large sets of samples by processing them in chunks to manage memory usage and leverage GPU parallelism. It is chosen when evaluating millions of points (e.g., for volume rendering or training) where individual kernel launches would incur excessive overhead. Unlike single-point queries, this method disables gradients for the batch to save memory and computation if gradients are not immediately needed [S2, unofficial].
*   **Parameters**: `max_batch`: Integer maximum batch size for inference. Default: $32^3$ (32,768 samples) [S2, unofficial].
*   **Steps**:
    1.  Disable gradients for the sample batch [S2, unofficial].
    2.  Get total number of samples $N$ [S2, unofficial].
    3.  Initialize `head = 0` [S2, unofficial].
    4.  Loop while `head < N`:
        *   Extract sample subset from `head` to `min(head + max_batch, N)` [S2, unofficial].
        *   Decode/Evaluate SDF for the subset [S2, unofficial].
        *   Store results in column 3 of the samples array [S2, unofficial].
        *   Increment `head` by `max_batch` [S2, unofficial].
    5.  Return SDF values from column 3 [S2, unofficial].

### SDF Validity Check with Relaxation
SDF Validity Check with Relaxation is a method for classifying samples as "positive," "negative," or "valid" (near the surface) based on a relaxed threshold. It is used during training or post-processing to identify points close to the zero-level set for loss computation or mesh extraction. It differs from strict binary classification by allowing a margin around the surface defined by `voxel_size * relaxation` [S2, unofficial].
*   **Parameters**: `relaxation`: Constant factor for threshold definition. Value: $1.5$ [S2, unofficial].
*   **Steps**:
    1.  Identify **positive samples**: those where $d > \text{voxel\_size} \times \text{relaxation}$ [S2, unofficial].
    2.  Identify **negative samples**: those where $-d > \text{voxel\_size} \times \text{relaxation}$ [S2, unofficial].
    3.  Identify **valid samples**: those where $|d| \le \text{voxel\_size} \times \text{relaxation}$ [S2, unofficial].

### SDF Optimization via Finite Differences
SDF Optimization via Finite Differences is a method for optimizing SDF values and learnable weights (e.g., in deformable fields like FlexiCubes) by computing gradients of a mesh-extraction loss with respect to the SDF values using finite differences. It is chosen when automatic differentiation is not available or when the SDF is represented as a discrete set of values rather than a neural network. It updates only a subset of SDF values per iteration for speed [S3, unofficial].
*   **Parameters**:
    *   `eps`: Finite difference step size. Value: $10^{-4}$ [S3, unofficial].
    *   `SDF clamp range`: $[-1.0, 1.0]$ [S3, unofficial].
    *   `Gradient computation subset`: Only first 100 SDF values updated per iteration [S3, unofficial].
*   **Layout**:
    *   `beta`: Matrix<double, Dynamic, 12, RowMajor>, size num_cubes x 12 [S3, unofficial].
    *   `alpha`: Matrix<double, Dynamic, 8, RowMajor>, size num_cubes x 8 [S3, unofficial].
    *   `gamma`: VectorXd, size num_cubes [S3, unofficial].
*   **Steps**:
    1.  Initialize `beta`, `alpha`, `gamma` to zero. Add noise: `beta(i,j) += noise(rng)*0.1`, etc. [S3, unofficial].
    2.  Compute SDF gradients using finite differences with `eps=1e-4` [S3, unofficial].
    3.  Loop $i$ from 0 to $\min(100, \text{sdf.size()}) - 1$:
        *   Perturb `sdf[i] += eps`, extract mesh_plus, compute `loss_plus` [S3, unofficial].
        *   Perturb `sdf[i] -= 2*eps`, extract mesh_minus, compute `loss_minus` [S3, unofficial].
        *   Reset `sdf[i] += eps` [S3, unofficial].
        *   Compute `sdf_grad[i] = (loss_plus - loss_minus) / (2*eps)` [S3, unofficial].
    4.  Apply gradient step: `optimizer.step(sdf, sdf_grad)` [S3, unofficial].
    5.  Clamp SDF values to $[-1.0, 1.0]$ [S3, unofficial].

### Mandelbulb SDF Evaluation
Mandelbulb SDF Evaluation computes the distance to a Mandelbulb fractal, a 3D generalization of the Mandelbrot set. It is chosen for generating complex, organic-looking fractal shapes. It differs from analytic primitives by using iterative complex number mapping in 3D spherical coordinates [S4, unofficial].
*   **Parameters**:
    *   `scale`: Global scaling factor.
    *   `power`: Exponent for fractal mapping (controls complexity).
    *   `bailout`: Maximum radius threshold to break iteration.
    *   `max_iterations`: Maximum number of iterations.
*   **Formula**:
    $$ d = \frac{0.5 \cdot \log(r) \cdot r}{dr} \cdot \text{scale} $$
    where $r$ is the final radius and $dr$ is the derivative [S4, unofficial].
*   **Steps**:
    1.  Initialize $z = \frac{\text{point} - c}{\text{scale}}$, $dr = 1.0$, $r = 0.0$ [S4, unofficial].
    2.  Loop $i$ from 0 to `max_iterations - 1`:
        *   Update $r = \|z\|$ [S4, unofficial].
        *   If $r > \text{bailout}$, break [S4, unofficial].
        *   Compute spherical coordinates: $\theta = \arccos(z.z / r)$, $\phi = \operatorname{atan2}(z.y, z.x)$ [S4, unofficial].
        *   Update derivative: $dr = r^{\text{power} - 1} \cdot \text{power} \cdot dr + 1.0$ [S4, unofficial].
        *   Compute radial power $zr = r^{\text{power}}$ [S4, unofficial].
        *   Apply power to angles: $\theta = \theta \cdot \text{power}$, $\phi = \phi \cdot \text{power}$ [S4, unofficial].
        *   Update position: $z = zr \cdot (\sin\theta\cos\phi, \sin\theta\sin\phi, \cos\theta) + \frac{\text{point} - c}{\text{scale}}$ [S4, unofficial].
    3.  Return distance $d$ using the formula above [S4, unofficial].

## Operating characteristics

*   **Time Complexity**:
    *   Single point query: $O(1)$ for analytic primitives; $O(I)$ for fractals (where $I$ is max iterations) [S4, unofficial].
    *   Batched inference: $O(N/B)$ where $N$ is total samples and $B$ is batch size [S2, unofficial].
    *   Finite difference gradient: $O(3 \cdot K)$ where $K$ is the number of perturbed values (e.g., 100) [S3, unofficial].
*   **Memory Complexity**:
    *   Batched inference: $O(B)$ for the current batch [S2, unofficial].
    *   Neural SDF: Depends on network size [S1, unofficial].
*   **Measured Performance**:
    *   Not given in the sources.
*   **Strengths**:
    *   Flexibility to support various SDF types (analytic, neural, fractal) [S1, S4, unofficial].
    *   Batched inference improves throughput for large-scale queries [S2, unofficial].
    *   Relaxation allows for robust surface identification [S2, unofficial].
*   **Limitations**:
    *   Finite difference gradients are noisy and slow for large SDF arrays [S3, unofficial].
    *   Fractal evaluation is computationally expensive due to iterations [S4, unofficial].
*   **When to Use**:
    *   Use for ray marching in volume rendering where SDF values are needed per sample [S1, unofficial].
    *   Use batched inference for training or large-scale point cloud evaluation [S2, unofficial].
*   **When Not to Use**:
    *   Avoid finite difference optimization for large-scale SDFs due to $O(K)$ cost per gradient step [S3, unofficial].

## Background

*   **Origin**: The concept of SDFs dates back to early computational geometry, but their use in rendering and neural implicit surfaces has grown significantly with the advent of neural rendering and differentiable rendering.
*   **Development**:
    *   `SDFQueryHandler` and related structures are part of modern C++/Python rendering pipelines like `subgrid-marching` [S1, unofficial].
    *   Batched inference and relaxation techniques are common in neural SDF training frameworks like `DIST-Renderer` [S2, unofficial].
    *   Finite difference optimization for SDFs is used in deformable mesh extraction methods like `FlexiCubes` [S3, unofficial].
    *   Mandelbulb SDF evaluation is a classic technique in fractal rendering, implemented in various graphics libraries [S4, unofficial].
*   **Usage**: Used in ray marching, neural implicit surface reconstruction, and fractal generation.
