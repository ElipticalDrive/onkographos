# Warped-Space SDF Ray Marching
Also called: Road-space SDF, Sheared SDF

## Overview
Warped-Space SDF Ray Marching is a technique for rendering scenes with regularly spaced geometry (such as urban environments) by defining the scene in a sheared coordinate space ("road space") where buildings are axis-aligned, simplifying distance field computation [S1, unofficial]. It differs from standard Euclidean ray marching by applying a safety factor to the computed distances to compensate for the non-Euclidean metric introduced by the spatial transformation, preventing the ray from tunneling through walls [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $p_{world}$ and direction $d_{world}$ in world space.
- Scene definition: A set of buildings, each defined by a center $c$ and half-extents $h$ in road space.
- Road geometry function $roadX(z)$, which returns the lateral offset of the road center at longitudinal position $z$.
- Ground plane height $y_{ground}$.
- Safety factor $\alpha = 0.8$.

**Outputs:**
- Marched distance $d_{out}$ and material ID.

**Data Structures:**
- Buildings are stored in a grid or hash map indexed by longitudinal cell.
- Each building entry contains:
  - `center`: vec3 $(c_x, c_y, c_z)$ in road space.
  - `halfExt`: vec3 $(h_x, h_y, h_z)$ in road space.
  - `materialID`: integer.

**Steps:**
1. **Transform to Road Space:** For a given world point $p$, compute its road space coordinate $q$:
   $$ q = (p_x - roadX(p_z), p_y, p_z) $$
   This transformation shears the world such that the road runs along the $z$-axis in road space [S1, unofficial].

2. **Cell Identification:** Determine the longitudinal cell index for the current $z$-coordinate:
   $$ baseC_z = \lfloor q_z / BLOCK\_DEPTH \rfloor $$
   where $BLOCK\_DEPTH$ is the grid cell size in the $z$-direction [S1, unofficial].

3. **Neighbor Iteration:** Iterate over the current cell and its immediate neighbors in the $z$-direction. Specifically, loop over $dz \in \{-1, 0, 1\}$ and iterate through all rows and sides within those cells [S1, unofficial].

4. **Distance Computation:** For each building present in the current cell range:
   - Compute the vector from the building center to the query point in road space: $v = q - c$.
   - Compute the signed distance to the axis-aligned box using the standard formula:
     $$ d_{box} = \max(|v_x| - h_x, |v_y| - h_y, |v_z| - h_z) $$
     If $v$ is inside the box (all components less than half-extents), the distance is negative [S1, unofficial].

5. **Apply Safety Factor:** Multiply the box distance by the safety factor $\alpha$:
   $$ d_{warped} = d_{box} \times \alpha $$
   The value $\alpha = 0.8$ is chosen because the maximum compression factor of the transformation is approximately $1.13$ (derived from $|roadX'| \le 0.52$). Since $0.8 < 1/1.13$, this ensures the Lipschitz lower bound is respected [S1, unofficial].

6. **Ground Comparison:** Compute the distance to the ground plane:
   $$ d_{ground} = p_y - y_{ground} $$
   (Assuming $y$ is up and ground is at $y_{ground}$).

7. **Return Minimum:** Return the smaller of $d_{warped}$ and $d_{ground}$, along with the corresponding material ID. If no buildings are found, return $d_{ground}$ [S1, unofficial].

**Pseudocode:**
```python
def ray_march_warped(p_world, d_world, roadX_func, buildings_grid, BLOCK_DEPTH, y_ground, alpha=0.8):
    """
    Performs one step of ray marching in warped space.
    Returns (distance, material_id).
    """
    # 1. Transform world point to road space
    p_z = p_world.z
    road_offset = roadX_func(p_z)
    q = vec3(p_world.x - road_offset, p_world.y, p_z)
    
    # 2. Determine longitudinal cell index
    base_cz = floor(q.z / BLOCK_DEPTH)
    
    best_dist = infinity
    best_mat_id = -1
    
    # 3. Iterate over z-neighbors (-1, 0, 1)
    for dz in [-1, 0, 1]:
        cell_z = base_cz + dz
        # Retrieve buildings in this cell (implementation detail: grid lookup)
        cell_buildings = buildings_grid.get(cell_z, [])
        
        for b in cell_buildings:
            # 4. Compute box distance in road space
            v = q - b.center
            dx = abs(v.x) - b.halfExt.x
            dy = abs(v.y) - b.halfExt.y
            dz_box = abs(v.z) - b.halfExt.z
            
            # Standard AABB SDF
            d_box = max(dx, max(dy, dz_box))
            
            # 5. Apply safety factor
            d_warped = d_box * alpha
            
            # 6. Update best distance
            if d_warped < best_dist:
                best_dist = d_warped
                best_mat_id = b.material_id
                
    # 7. Compare with ground
    d_ground = p_world.y - y_ground
    
    if d_ground < best_dist:
        return d_ground, GROUND_MATERIAL_ID
    else:
        return best_dist, best_mat_id
```

**Parameters:**
- $\alpha = 0.8$: Safety factor. Critical for preventing tunneling [S1, unofficial].
- $BLOCK\_DEPTH$: Grid cell size in $z$. Not given in the sources.

**Edge Cases:**
- **Tunneling:** Without the safety factor, the non-Euclidean metric compresses distances by a factor of $\sqrt{1 + roadX'(z)^2}$. If the marcher steps by the raw Euclidean distance in road space, it may overshoot the actual surface in world space [S1, unofficial].
- **Degenerate Input:** If $roadX'(z)$ is large, the compression factor increases. The safety factor must be adjusted if the maximum derivative exceeds the assumed bound [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of buildings in the current and adjacent longitudinal cells. Typically small due to spatial partitioning.
- **Memory Complexity:** $O(B)$ where $B$ is the total number of buildings, stored in a grid/hash structure.
- **Strengths:** Simplifies building placement and SDF computation by aligning geometry with the coordinate axes in road space. Efficient for dense, regular urban layouts.
- **Limitations:** Only suitable for scenes with a dominant directional structure (e.g., roads). Requires careful tuning of the safety factor based on the maximum shear rate. Not suitable for arbitrary curved paths without complex $roadX(z)$ definitions.
- **When to use:** Urban environments, highways, or any scene with a strong linear or gently curving central axis.
- **When not to use:** Scenes with no dominant direction, or where high precision is required without the overhead of dynamic safety factor calculation.

## Background
The technique is described in the context of a WebGL raymarcher implementation, specifically for rendering urban environments efficiently [S1, unofficial]. It leverages the concept of Lipschitz transformation bounds to ensure valid distance queries in non-Euclidean spaces [S1, unofficial].
