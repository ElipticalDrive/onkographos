# SDF Evaluation Implementation

Also called: SDF Evaluation and Gradient, SDF Handler Implementation, SDF Query Handler, SDF Value and Gradient Evaluation

## Overview
SDF Evaluation Implementation provides the runtime mechanism to query a Signed Distance Field (SDF) for scalar values and their spatial gradients at arbitrary 3D coordinates. It solves the problem of translating discrete or implicit geometric representations into differentiable or queryable functions required by ray marching and surface extraction algorithms. It sets itself apart from [SDF Primitive Definitions](1657-sdf-primitive-definitions.md) by handling general grid-based or neural data structures rather than analytic primitives, and from [Implicit Surface Field Function Evaluation](1599-implicit-surface-field-function-evaluation.md) by providing concrete interpolation and gradient computation strategies for stored data.

## How it works
The implementation varies based on the underlying SDF representation (grid-based vs. neural vs. fractal). The core logic involves validating the source, loading the data structure, and providing a query interface that returns both the distance value $d$ and the gradient $\nabla d$.

### Inputs and Outputs
*   **Input**: A 3D query point $p = (x, y, z)$.
*   **Input**: SDF data source (e.g., voxel grid, neural network weights, fractal parameters).
*   **Output**: Scalar distance $d$.
*   **Output**: Gradient vector $\nabla d = (\frac{\partial d}{\partial x}, \frac{\partial d}{\partial y}, \frac{\partial d}{\partial z})$.

### Data Structures
1.  **Grid-Based SDF**:
    *   A 3D tensor of shape $(res, res, res, 1)$ storing float values [S2, unofficial].
    *   Wrapped in a texture object (e.g., `mi.Texture3f`) with acceleration disabled (`use_accel=False`) to allow custom interpolation logic [S2, unofficial].
2.  **Neural SDF**:
    *   Latent codes and network weights stored in tensors (e.g., PyTorch `torch.Tensor`) [S3, unofficial].
3.  **Fractal SDF**:
    *   Parameters: center $c$, scale, power, bailout, max_iterations [S5, unofficial].

### Steps for Grid-Based SDF (Linear/Cubic Interpolation)
This method is used in differentiable rendering pipelines [S2, unofficial].

1.  **Initialization**:
    *   Load SDF data from `.sdf`, `.npy`, or `.vol` files [S2, unofficial].
    *   Parse the first element as resolution `res`.
    *   Create a 3D tensor with shape `(res, res, res, 1)` [S2, unofficial].
    *   Set interpolation mode `SDF_MODE` to `'linear'` or `'cubic'` [S2, unofficial].
2.  **Value Evaluation at $p$**:
    *   If `SDF_MODE` is `'linear'`: Compute value using linear interpolation of the grid neighbors.
    *   If `SDF_MODE` is `'cubic'`: Compute value using cubic interpolation (e.g., tricubic) [S2, unofficial].
    *   Return the scalar result.
3.  **Gradient Evaluation at $p$**:
    *   If `SDF_MODE` is `'linear'`: Compute gradient using central finite differences with step size $\epsilon = 10^{-5}$ [S2, unofficial]:
        $$ \nabla d \approx \left[ \frac{d(p + \epsilon \hat{x}) - d(p - \epsilon \hat{x})}{2\epsilon}, \frac{d(p + \epsilon \hat{y}) - d(p - \epsilon \hat{y})}{2\epsilon}, \frac{d(p + \epsilon \hat{z}) - d(p - \epsilon \hat{z})}{2\epsilon} \right] $$
    *   If `SDF_MODE` is `'cubic'`: Use the analytical gradient provided by the cubic interpolation kernel (e.g., `eval_cubic_grad`) [S2, unofficial].
4.  **Query Normal**:
    *   Normalize the gradient vector: $n = \frac{\nabla d}{\|\nabla d\|}$ [S1, unofficial].

### Steps for Neural SDF (Batched Inference)
Used for optimizing neural implicit fields [S3, unofficial].

1.  **Batch Preparation**:
    *   Determine total number of samples $N$.
    *   Set batch size limit `max_batch` (default $32^3 = 32768$) [S3, unofficial].
2.  **Loop**:
    *   Initialize `head = 0`.
    *   While `head < N`:
        *   Extract subset of points from `head` to `min(head + max_batch, N)`.
        *   Disable gradients for these samples to save memory [S3, unofficial].
        *   Decode SDF values for the subset using the neural network.
        *   Store results in the output array.
        *   Increment `head` by `max_batch`.
3.  **Return**: The full array of SDF values.

### Steps for Fractal SDF (Mandelbulb)
Used for procedural geometry [S5, unofficial].

1.  **Initialization**:
    *   Set $z = \frac{point - c}{scale}$.
    *   Set derivative $dr = 1.0$.
    *   Set radius $r = 0.0$.
2.  **Iteration**:
    *   Loop $i$ from $0$ to $max\_iterations - 1$:
        *   $r = \|z\|$.
        *   If $r > bailout$, break loop.
        *   Compute spherical coordinates:
            $$ \theta = \arccos\left(\frac{z_z}{r}\right), \quad \phi = \operatorname{atan2}(z_y, z_x) $$
        *   Update derivative:
            $$ dr = r^{power - 1} \cdot power \cdot dr + 1.0 $$
        *   Compute radial power: $z_r = r^{power}$.
        *   Apply power to angles: $\theta \leftarrow \theta \cdot power$, $\phi \leftarrow \phi \cdot power$.
        *   Update position:
            $$ z = z_r \begin{bmatrix} \sin\theta \cos\phi \\ \sin\theta \sin\phi \\ \cos\theta \end{bmatrix} + \frac{point - c}{scale} $$
3.  **Final Distance**:
    $$ d = \frac{0.5 \cdot \log(r) \cdot r}{dr} \cdot scale $$

## Subtopics

### [SDF Training with Eikonal Loss](2553-sdf-training-with-eikonal-loss.md)
A method for optimizing a neural implicit SDF to match 3D point cloud data by enforcing the Eikonal equation constraint. It solves the problem of training an arbitrary scalar field to represent a valid geometric distance function, which requires the gradient magnitude to be unity everywhere. Unlike [DeepSDF Neural Network](3051-deepsdf-neural-network.md), which typically optimizes for zero-level set fitting without explicit gradient constraints, this method adds a regularization term that penalizes deviations from unit gradient norms, ensuring the output is a true signed distance field rather than just a binary segmentation or occupancy field.

### [DeepSDF Neural Network](3051-deepsdf-neural-network.md)
DeepSDF is a neural network architecture that maps 3D coordinates to signed distance field (SDF) values using a shape-specific latent code. It solves the problem of implicit surface representation by learning a continuous function that generalizes across shapes within a category, enabling compact storage and high-quality reconstruction. Unlike [Vox2SDF](4047-vox2sdf.md), which derives its latent code from a discrete voxel grid via a 3D CNN, DeepSDF relies on a global latent code independent of the input geometry structure, allowing it to capture fine geometric details without voxelization artifacts.

### [SDF and Material Optimization Pipeline](4458-sdf-and-material-optimization-pipeline.md)
This method optimizes a voxelized Signed Distance Field (SDF) and associated material properties (albedo, roughness, metallic) by minimizing the difference between rendered images and reference images. It differs from pure geometry optimization by jointly updating material volumes, and from neural SDF methods by using explicit grid-based representations with periodic upsampling. It builds on [SDF Evaluation Implementation](1658-sdf-evaluation-implementation.md) for the forward rendering pass.

### Batched SDF Inference
Evaluates SDF values for a large set of samples in batches to manage memory [S3, unofficial].
*   **Steps**: Disable gradients for samples. Get number of samples. Loop while head is less than num_samples. Extract sample subset from head to min(head + max_batch, num_samples). Decode SDF for subset and store in samples column 3. Increment head by max_batch. Return SDF values from column 3 [S3, unofficial].
*   **Parameters**: `max_batch`: Integer maximum batch size for inference, default $32^3$ [S3, unofficial].

### SDF Validity Check with Relaxation
Identifies valid samples near the zero-level set for training or filtering [S3, unofficial].
*   **Steps**: Identify positive samples: those where SDF value > voxel_size * relaxation. Identify negative samples: those where -SDF value > voxel_size * relaxation. Identify valid samples: those where absolute SDF value <= voxel_size * relaxation [S3, unofficial].
*   **Parameters**: `relaxation`: A constant factor used to define the threshold for 'valid' (near-zero) SDF values. Value: 1.5 [S3, unofficial].

### SDF Optimization via Finite Differences
Optimizes SDF values and learnable weights (beta, alpha, gamma) to minimize the difference between extracted mesh and target mesh, using finite difference gradients for the SDF [S4, unofficial].
*   **Steps**: Initialize beta, alpha, gamma to zero. Add noise: beta(i,j) += noise(rng)*0.1, alpha(i,j) += noise(rng)*0.1, gamma[i] += noise(rng)*0.1 for all i, j. Compute SDF gradients using finite differences with eps=1e-4. Loop i from 0 to min(100, sdf.size())-1. Perturb sdf[i] += eps, extract mesh_plus, compute loss_plus. Perturb sdf[i] -= 2*eps, extract mesh_minus, compute loss_minus. Reset sdf[i] += eps. Compute sdf_grad[i] = (loss_plus - loss_minus) / (2*eps). Apply gradient step: optimizer.step(sdf, sdf_grad). Clamp sdf values to [-1.0, 1.0] [S4, unofficial].
*   **Parameters**: `eps`: finite difference step size, value 1e-4. `SDF clamp range`: [-1.0, 1.0]. `Gradient computation subset`: only first 100 SDF values are updated per iteration for speed [S4, unofficial].
*   **Layout**: Learnable parameters per cube: beta (Matrix<double, Dynamic, 12, RowMajor>, size num_cubes x 12), alpha (Matrix<double, Dynamic, 8, RowMajor>, size num_cubes x 8), gamma (VectorXd, size num_cubes) [S4, unofficial].

### Mandelbulb SDF Evaluation
Evaluates the distance to a Mandelbulb fractal primitive [S5, unofficial].
*   **Steps**: Initialize position $z = (point - c) / scale$, derivative $dr = 1.0$, and radius $r = 0.0$. Loop $i$ from 0 to $max\_iterations - 1$. Update radius $r = z.length()$. If $r > bailout$, break the loop. Compute spherical coordinates: $\theta = \arccos(z_z / r)$, $\phi = \operatorname{atan2}(z_y, z_x)$. Update derivative: $dr = pow(r, power - 1.0) * power * dr + 1.0$. Compute radial power $z_r = pow(r, power)$, then apply power to angles: $\theta = \theta * power$, $\phi = \phi * power$. Update position: $z = z_r * vec3(\sin(\theta)\cos(\phi), \sin(\theta)\sin(\phi), \cos(\theta)) + (point - c) / scale$ [S5, unofficial].
*   **Formula**: Final distance: $d = \frac{0.5 \cdot \log(r) \cdot r}{dr} \cdot scale$ [S5, unofficial].
*   **Parameters**: `scale`: Global scaling factor applied to the input point offset and the final returned distance. `power`: Exponent for the fractal mapping that controls the geometric complexity and shape of the Mandelbulb. `bailout`: Maximum radius threshold to break iteration early and prevent numerical overflow. `max_iterations`: Maximum number of fractal iterations performed per point evaluation [S5, unofficial].

## Operating characteristics
*   **Time Complexity**:
    *   Grid-based: $O(1)$ per query for linear interpolation; $O(1)$ for cubic (higher constant factor). Gradient via finite differences requires $O(1)$ additional queries (3 for linear).
    *   Neural: $O(N \cdot W)$ where $N$ is batch size and $W$ is network width, dominated by matrix multiplications.
    *   Fractal: $O(I)$ where $I$ is max iterations.
*   **Memory Complexity**:
    *   Grid-based: $O(res^3)$ for the voxel grid.
    *   Neural: $O(W^2)$ for weights, plus latent code size.
*   **Measured Performance**: Cubic interpolation provides smoother geometry and is theoretically more robust for gradient-based optimization but is much slower than linear interpolation [S2, unofficial].
*   **Strengths**: Differentiable (with cubic or neural), supports arbitrary geometries (grids/neural), robust to noise with relaxation techniques.
*   **Limitations**: Grid-based methods suffer from memory explosion at high resolutions. Neural methods require training time. Fractal methods are limited to specific procedural shapes.
*   **When to use**: Use grid-based for explicit, high-fidelity geometry where memory allows. Use neural for compact, generalizable representations. Use fractal for procedural effects.

## Background
The method originates from the need to efficiently query implicit surfaces in rendering and simulation. Grid-based SDFs are standard in voxel-based rendering [S2, unofficial]. Neural SDFs were popularized by DeepSDF [S1, unofficial][S2, unofficial]. The specific implementation details regarding relaxed boundaries and differentiable rendering of SDFs were detailed in "A Simple Approach to Differentiable Rendering of SDFs" by Wang et al. (SIGGRAPH Asia 2024) [S2, unofficial].
