# Circle Signed Distance Function

Also called: 2D Circle SDF, 2D Sphere SDF, Circle SDF, sdCircle

## Overview
The Circle Signed Distance Function (SDF) computes the Euclidean distance from a query point to the perimeter of a circle centered at the origin. It serves as the fundamental 2D primitive for distance-field ray marching, providing the signed distance required to step along a ray. Unlike the Sphere SDF which operates in 3D space, this method is strictly 2D, making it suitable for planar scenes, 2D volume rendering, or as a cross-section of a 3D sphere.

## How it works
**Inputs:**
- $p$: A 2D query point, represented as a vector $(p_x, p_y)$ [S1, S2, unofficial].
- $r$: The radius of the circle, a non-negative scalar [S1, S2, unofficial].

**Outputs:**
- $d$: The signed distance from $p$ to the circle boundary [S2, unofficial].

**Data Structures:**
- No complex data structures are required. The input is a 2D vector and a scalar.

**Formula:**
The signed distance is calculated as the magnitude of the query point vector minus the radius:
$$ d = \|p\| - r $$
where $\|p\| = \sqrt{p_x^2 + p_y^2}$ [S1, S2, unofficial].

**Interpretation:**
- If $d < 0$, the point is inside the circle.
- If $d = 0$, the point is on the boundary.
- If $d > 0$, the point is outside the circle [S2, unofficial].

**Pseudocode:**
```python
def sd_circle(p: Vector2, r: float) -> float:
    """
    Computes the signed distance from point p to a circle of radius r centered at origin.
    
    Args:
        p: 2D vector (x, y) representing the query point.
        r: Float representing the radius of the circle.
        
    Returns:
        Float representing the signed distance. Negative if inside, positive if outside.
    """
    # Calculate Euclidean norm of p
    magnitude = (p.x ** 2 + p.y ** 2) ** 0.5
    return magnitude - r
```

**Edge Cases and Pitfalls:**
- **Zero Radius:** If $r=0$, the function returns the distance to the origin. This is mathematically valid but may cause degenerate behavior in ray marching if not handled (e.g., infinite steps if the ray passes exactly through the origin).
- **Precision:** For points very close to the boundary, floating-point precision errors may cause jitter in ray marching. Using a small epsilon threshold for termination is recommended [S2, unofficial].
- **Negative Radius:** The radius $r$ should be non-negative. If a negative radius is passed, the sign of the distance will be inverted relative to the geometric expectation (inside becomes positive).

## Operating characteristics
- **Time Complexity:** $O(1)$. The calculation involves a square root and a subtraction.
- **Memory Complexity:** $O(1)$. No auxiliary memory is required.
- **Strengths:** Extremely fast evaluation; no branching required; analytically exact distance.
- **Limitations:** Only applies to circles centered at the origin. For off-center circles, the query point must be translated by the circle's center vector before evaluation.
- **When to use:** Ideal for 2D ray marching, procedural texture generation, and collision detection in 2D spaces.

## Background
The Circle SDF is a standard primitive in Signed Distance Field rendering, popularized by Inigo Quilez's online articles on SDFs [S1, unofficial]. It is the 2D analog of the Sphere SDF. The implementation is trivial, relying on the definition of Euclidean distance.
