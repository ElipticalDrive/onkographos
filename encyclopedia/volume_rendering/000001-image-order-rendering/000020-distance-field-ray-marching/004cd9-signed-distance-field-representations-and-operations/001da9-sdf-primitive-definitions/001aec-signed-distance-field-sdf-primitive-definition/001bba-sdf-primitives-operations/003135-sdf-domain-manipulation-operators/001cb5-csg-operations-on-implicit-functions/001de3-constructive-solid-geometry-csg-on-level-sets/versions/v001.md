# Constructive Solid Geometry (CSG) on Level Sets

Also called: Level Set CSG, Point-Classification Map, Voxel CSG

## Overview
Constructive Solid Geometry (CSG) on Level Sets combines multiple Signed Distance Fields (SDFs) into a single implicit function using Boolean operations (Union, Intersection, Difference) to define complex volumetric shapes. Unlike tree-based CSG evaluation which computes the final distance field value on-the-fly during rendering, this method often pre-computes the logical classification of points in a volume space using a Point-Classification Map (PCM) or directly composites voxel buffers. It sets itself apart from [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md) by focusing on the spatial composition of volume data (voxels or classification maps) rather than a procedural stack of operations, and from [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md) by providing concrete implementation strategies for discrete volume representations.

## How it works
The method operates on two primary paradigms: the Point-Classification Map (PCM) for logical composition and direct Voxel Buffer compositing for distance field arithmetic.

### Inputs and Outputs
*   **Inputs:** A CSG tree structure where leaf nodes are SDF primitives (e.g., spheres, boxes) and internal nodes are Boolean operators (Union, Intersection, Difference). For PCM, the input is the CSG tree topology. For Voxel Buffer compositing, the input is two aligned voxel buffers $A$ and $B$ containing signed distance values.
*   **Outputs:** A single classification map (PCM) or a combined voxel buffer representing the final CSG object.

### Data Structures

#### Point-Classification Map (PCM)
The PCM is a look-up table that maps the complete classification result of a point with respect to all primitives to the final in/out CSG classification.
*   **Structure:** An array of size $2^n$, where $n$ is the number of leaf nodes (primitives) in the CSG tree.
*   **Indexing:** The index is an $n$-bit binary number called the **classification index**.
    *   Bit $j$ (0-indexed) corresponds to the $j$-th primitive.
    *   Bit value `1` indicates the point is inside the $j$-th primitive.
    *   Bit value `0` indicates the point is outside the $j$-th primitive.
*   **Entry Value:** The value at each index represents the final CSG classification (Inside/Outside) for that specific combination of primitive memberships.

#### Voxel Buffer
*   **Structure:** A 3D grid of voxels.
*   **Fields:** Each voxel stores a signed distance value (float).
*   **Alignment:** Buffers being combined must share the same bounding box dimensions and spatial alignment.

### Algorithm: PCM Construction
The PCM for a CSG tree is constructed recursively. To manage memory, a common PCM memory space is shared across all levels of recursive calls [S1].

1.  **Function `CSG_PCM(N)`:** Takes a CSG node $N$.
2.  **Base Case:** If $N$ is a leaf node (primitive):
    *   Return the PCM of the primitive. For a single primitive, the PCM is trivial (e.g., index 0 maps to Outside, index 1 maps to Inside).
3.  **Recursive Step:** If $N$ is an internal node:
    *   Compute `PCM_left` = `CSG_PCM(N.left)`.
    *   Compute `PCM_right` = `CSG_PCM(N.right)`.
    *   Combine them: `PCM_combined` = `combine(PCM_left, PCM_right, N.op)`.
4.  **Combine Logic:**
    *   The index domain of `PCM_combined` is the Cartesian product of the index domains of `PCM_left` and `PCM_right`.
    *   For each entry in the combined map, the classification $c$ is derived from the classifications $c_1$ (from left) and $c_2$ (from right) using the Boolean operation $op$ defined by node $N$:
        $$ c = c_1 \text{ op } c_2 $$
    *   Return `PCM_combined`.

### Algorithm: Voxel Buffer Compositing
For distance fields, the Boolean operations are implemented as element-wise arithmetic on the voxel buffers $A$ and $B$ [S2, unofficial].

1.  **Union ($A \cup B$):**
    *   The union of two volumes is the set of points inside either volume. In SDF terms, the distance to the union is the minimum of the individual distances.
    *   Formula:
        $$ A_{new}(i,j,k) = \min(A(i,j,k), B(i,j,k)) $$
    *   Implementation: Iterate over all voxels $(i,j,k)$ in the bounding box and update $A$ in place.

2.  **Intersection ($A \cap B$):**
    *   The intersection is the set of points inside both volumes. The distance to the intersection is the maximum of the individual distances (since being "further" from the surface of either implies being deeper inside the intersection).
    *   Formula:
        $$ A_{new}(i,j,k) = \max(A(i,j,k), B(i,j,k)) $$

3.  **Difference ($A \setminus B$):**
    *   The difference is the set of points inside $A$ but outside $B$. To negate $B$'s influence, its distance values are inverted (sign flipped) before comparison.
    *   Formula:
        $$ A_{new}(i,j,k) = \max(A(i,j,k), -B(i,j,k)) $$

### Pseudocode

```python
def csg_pcm(node):
    """
    Recursively constructs the Point-Classification Map for a CSG node.
    node: CSG_Node object with attributes:
        - is_leaf: bool
        - left: CSG_Node (if not leaf)
        - right: CSG_Node (if not leaf)
        - op: str ('AND', 'OR', 'XOR', etc.)
    Returns: list of bools representing the PCM
    """
    if node.is_leaf:
        # Base case: Single primitive PCM
        # Index 0 (outside) -> False (Outside CSG)
        # Index 1 (inside) -> True (Inside CSG)
        return [False, True]

    # Recursive step
    pcm_left = csg_pcm(node.left)
    pcm_right = csg_pcm(node.right)

    # Determine size of combined PCM
    # If left has 2^L entries and right has 2^R entries,
    # combined has 2^(L+R) entries.
    size_left = len(pcm_left)
    size_right = len(pcm_right)
    size_combined = size_left * size_right

    pcm_combined = [False] * size_combined

    # Combine logic
    # The index in combined PCM is formed by concatenating indices of left and right
    # i_combined = i_left * size_right + i_right
    for i_left in range(size_left):
        c1 = pcm_left[i_left]
        for i_right in range(size_right):
            c2 = pcm_right[i_right]
            i_combined = i_left * size_right + i_right
            
            # Apply Boolean operation
            if node.op == 'OR':
                c_combined = c1 or c2
            elif node.op == 'AND':
                c_combined = c1 and c2
            elif node.op == 'XOR':
                c_combined = c1 != c2
            else:
                # Handle other ops or default
                c_combined = False 
            
            pcm_combined[i_combined] = c_combined

    return pcm_combined

def voxel_union(buffer_a, buffer_b):
    """
    Computes Union of two voxel buffers in place for buffer_a.
    buffer_a, buffer_b: 3D arrays of floats (SDF values)
    Assumes same dimensions and alignment.
    """
    dims = buffer_a.dims()
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                buffer_a.set(i, j, k, min(buffer_a.get(i, j, k), buffer_b.get(i, j, k)))

def voxel_intersection(buffer_a, buffer_b):
    """
    Computes Intersection of two voxel buffers in place for buffer_a.
    """
    dims = buffer_a.dims()
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                buffer_a.set(i, j, k, max(buffer_a.get(i, j, k), buffer_b.get(i, j, k)))

def voxel_difference(buffer_a, buffer_b):
    """
    Computes Difference (A minus B) of two voxel buffers in place for buffer_a.
    """
    dims = buffer_a.dims()
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                val_a = buffer_a.get(i, j, k)
                val_b = buffer_b.get(i, j, k)
                buffer_a.set(i, j, k, max(val_a, -val_b))
```

### Parameters and Edge Cases
*   **$n$ (Number of Primitives):** The PCM size grows exponentially as $2^n$. For large $n$, the PCM becomes infeasible due to memory constraints [S1].
*   **Memory Sharing:** To mitigate memory consumption during recursive PCM construction, all levels of recursive calls should share a common PCM memory space [S1].
*   **Primitive Definition:** For primitives defined by surface boundaries, determining interior points requires ray casting or solid voxelization principles (entering sets bit to 1, exiting sets to 0) [S1].
*   **SDF Sign Convention:** SDFs yield negative values for points inside the volume and positive values for points outside. This convention is critical for the arithmetic operations in Voxel Buffer compositing [S3].

## Subtopics

### [Lipschitz Pruning](8623-lipschitz-pruning.md)
A hierarchical pruning algorithm that reduces the number of active nodes in a smooth CSG tree for a specific region of space (e.g., a grid cell), outputting a pruned tree equivalent to the full tree within that region. It relies on the 1-Lipschitz property of the distance function.

### Lazy CSG Volume Modification
A volume modification system where SDF operations are added to per-octant CSG queues and executed lazily when the octant is close to the viewer, allowing dynamic expansion/contraction.
*   **Definition:** Instead of modifying volume data immediately, SDFs are added to a CSG queue for specific octants. Execution happens on-demand [S3].
*   **Steps:**
    1.  **Preparation:** Translate the SDF's Axis-Aligned Bounding Box (AABB) into an octant key range. Identify affected octants across LOD grids.
    2.  **Queuing:** Add the SDF to the CSG queue of identified octants. Data is not modified immediately.
    3.  **Execution:** When an octant is close to the viewer, execute its CSG queue. Combine SDFs using Union, Subtract, and Intersect.
    4.  **Pruning:** If a modification results in an empty octant, remove it and recursively prune parent octants that become empty.
*   **Supported Primitives:** Box, cylinder, cone, heightfield, noise, pill, sphere, pellet, torus, pipe, corridor [S3].

## Operating characteristics
*   **Time Complexity:**
    *   **PCM Construction:** $O(2^n)$ where $n$ is the number of primitives. This is exponential and becomes prohibitive for complex scenes.
    *   **Voxel Buffer Compositing:** $O(V)$ where $V$ is the number of voxels in the bounding box. Linear with respect to volume resolution.
*   **Memory Complexity:**
    *   **PCM:** $O(2^n)$ entries. High memory consumption for large $n$ [S1].
    *   **Voxel Buffer:** $O(V)$ storage for the distance field values.
*   **Strengths:**
    *   **PCM:** Provides exact logical classification for ray marching or voxelization without per-point tree traversal overhead during rendering.
    *   **Voxel Buffer:** Simple, hardware-friendly (GPU parallelizable), and supports arbitrary SDF primitives.
*   **Limitations:**
    *   **PCM:** Exponential memory growth limits the number of primitives.
    *   **Voxel Buffer:** Resolution-dependent; aliasing artifacts may occur near surfaces without roll-off techniques (e.g., smoothstep banding) [S2, unofficial].
*   **When to Use:**
    *   Use **PCM** for scenes with a small number of primitives where exact logical composition is required and memory is sufficient.
    *   Use **Voxel Buffer** compositing for scenes with many primitives or when dynamic, resolution-dependent volume modification is needed (e.g., terrain editing) [S3].

## Background
The concept of using a Point-Classification Map (PCM) for CSG voxelization was introduced in the paper "Fast CSG voxelization by frame buffer pixel mapping" [S1]. This approach leverages hardware frame buffer pixel mapping to accelerate the determination of set membership for points in a volume space. The method of compositing voxel buffers using min/max operations for SDFs is a standard technique in production volume rendering [S2, unofficial]. Lazy CSG volume modification, utilizing per-octant queues for dynamic terrain rendering, was described in "Volumetric Terrain Rendering with WebGL" [S3].
