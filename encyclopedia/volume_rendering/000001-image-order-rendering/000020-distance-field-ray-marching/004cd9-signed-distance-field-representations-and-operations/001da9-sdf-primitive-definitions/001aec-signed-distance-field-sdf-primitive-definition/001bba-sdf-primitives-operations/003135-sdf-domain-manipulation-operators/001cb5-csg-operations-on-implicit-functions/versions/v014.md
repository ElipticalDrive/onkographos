# CSG Operations on Implicit Functions

Also called: CSG Operations, Boolean SDF operators, SDF Boolean Operators, SDF Boolean Operations, CSG implicit surfaces, Constructive Solid Geometry with SDFs, CSG with SDFs, CSG SDF combination, CSG Operations for SDFs

## Overview
CSG Operations on Implicit Functions combine multiple Signed Distance Fields (SDFs) into a single implicit function using Boolean operations: Union, Intersection, and Difference [S1][S2, S3, S7, unofficial][S8][S9, S10, S11, S13, S14, unofficial]. This method solves the problem of representing complex composite shapes from simple primitives by evaluating the resulting distance field directly, enabling rendering via ray marching or voxelization [S2, S7, S14, unofficial]. Unlike [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md), which modify the input position vector $\mathbf{p}$ to create periodic or mirrored structures, CSG operations modify the scalar distance values returned by base SDFs to define set-theoretic relationships between volumes [S1][S3, unofficial][S8].

## How it works
The method evaluates binary (or unary) operations on the scalar distance values $f(\mathbf{p})$ and $g(\mathbf{p})$ returned by two implicit functions at a query point $\mathbf{p}$ [S1][S3, unofficial][S8][S11, unofficial]. The core principle is that the sign of the SDF indicates inside ($<0$) or outside ($>0$) the volume, and the magnitude represents the distance to the surface [S3, unofficial][S8].

### Inputs and Outputs
- **Inputs**: Two scalar fields $f$ and $g$ (typically SDFs), and a query point $\mathbf{p}$.
- **Outputs**: A single scalar value $h(\mathbf{p})$ representing the combined SDF.

### Data Structures
The operations can be implemented as simple arithmetic functions or organized into a tree structure for complex scenes [S2, S4, unofficial].

**Tree Structure (Recursive)** [S2, S4, unofficial]:
```python
class Node:
    def __init__(self, op, left, right):
        self.op = op  # "Union", "Intersection", or "Difference"
        self.left = left
        self.right = right

class Leaf:
    def __init__(self, sdf_func):
        self.sdf_func = sdf_func
```
Each node holds pointers to two child `ScalarField` objects [S4, unofficial]. Evaluation is recursive: `Value(p)` calls `left.Value(p)` and `right.Value(p)` [S2, S4, unofficial].

### Formulas
The standard Boolean operations map to min/max functions as follows [S1][S3, unofficial][S8][S9, S10, S11, S12, S13, unofficial]:

1.  **Union** ($A \cup B$): The point is inside if it is inside *either* shape [S3, S14, unofficial]. The distance is the minimum of the two distances (closest surface) [S12, unofficial].
    $$ h(\mathbf{p}) = \min(f(\mathbf{p}), g(\mathbf{p})) $$
2.  **Intersection** ($A \cap B$): The point is inside only if it is inside *both* shapes [S3, S14, unofficial]. The distance is the maximum of the two distances (farthest surface) [S9, unofficial].
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), g(\mathbf{p})) $$
3.  **Difference** ($A \setminus B$): The point is inside $A$ but outside $B$ [S3, unofficial]. This is equivalent to $A \cap \bar{B}$ (intersection of $A$ and the complement of $B$) [S8]. The complement is achieved by negating the distance [S3, unofficial].
    $$ h(\mathbf{p}) = \max(f(\mathbf{p}), -g(\mathbf{p})) $$

**XOR** (Exclusive Or) [S10, unofficial]:
$$ h(\mathbf{p}) = \max(\min(f(\mathbf{p}), g(\mathbf{p})), -\max(f(\mathbf{p}), g(\mathbf{p}))) $$

### Smooth Variants
Standard min/max operations create sharp creases [S11, unofficial]. Smooth variants use a blending parameter $k$ (typically $0.1$ to $1.0$) to create rounded fillets [S4, S11, S13, unofficial].

**Smooth Union** ($smin$) [S4, S11, S12, unofficial]:
$$ h(\mathbf{p}) = smin(f(\mathbf{p}), g(\mathbf{p}), k) $$
Implementation [S12, unofficial]:
```python
def clamp(x, lo, hi):
    return max(lo, min(hi, x))

def mix(a, b, t):
    return a + t * (b - a)

def smin(a, b, k):
    h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0)
    return mix(b, a, h) - k * h * (1.0 - h)
```
**Smooth Difference** and **Smooth Intersection** are derived similarly using `smax` or negation [S11, unofficial].

### Pseudocode
The following implements the standard recursive CSG evaluation for ray marching [S2, S3, S9, unofficial]:

```python
def evaluate_csg(node, p):
    """
    Recursively evaluate a CSG tree at point p.
    node: Tree node (Leaf or Node)
    p: Query point (vec3)
    """
    if isinstance(node, Leaf):
        return node.sdf_func(p)
    
    dist_a = evaluate_csg(node.left, p)
    dist_b = evaluate_csg(node.right, p)
    
    if node.op == "Union":
        return min(dist_a, dist_b)
    elif node.op == "Intersection":
        return max(dist_a, dist_b)
    elif node.op == "Difference":
        return max(dist_a, -dist_b)
    else:
        raise ValueError("Unknown operation")
```

For non-recursive, direct composition [S5, unofficial]:
```python
# Example: Sculpture = Union(Box, Sphere) - CrossHole
d_box = sdf_box(p)
d_sphere = sdf_sphere(p)
d_cross1 = sdf_box(p)
d_cross2 = sdf_box(p)
d_cross3 = sdf_box(p)

# Intersection of cross boxes (hole)
d_cross_hole = min(d_cross1, min(d_cross2, d_cross3))

# Union of box and sphere
d_sculpture = min(d_box, d_sphere)

# Difference: Sculpture minus CrossHole
d_final = max(d_sculpture, -d_cross_hole)
```

### Parameters
- **$k$**: Smooth blending factor. Controls the radius of the fillet. Typical values $0.1 \le k \le 1.0$ [S4, S11, unofficial].
- **Epsilon**: A small constant used to prevent infinite loops in ray marching when surfaces are tangent or nearly tangent [S12, S9, unofficial].

### Edge Cases and Pitfalls
1.  **Lipschitz Property Violation**: The standard difference operation $\max(f, -g)$ is only Lipschitz-1 (guaranteeing safe sphere marching step sizes) if the surface of $B$ is entirely contained within $A$ or if $A$ and $B$ do not intersect in a way that creates sharp internal corners that violate the distance bound [S8][S12, unofficial]. If $A$ pokes through the boundary of $B$, the resulting SDF may not be Lipschitz-1, causing ray marchers to skip surfaces. A small epsilon correction or tighter step size is required in those regions [S12, unofficial].
2.  **DeMorgan’s Theorem Limitation**: DeMorgan’s theorem ($A \cap B = \overline{\overline{A} \cup \overline{B}}$) does not work directly with min/max operators for distance bounds because the minimum operator is not complemented properly in the distance metric. Using `max` for intersection ensures the bound holds [S8].
3.  **Scaling**: Scaling an SDF requires scaling the input coordinates by the inverse of the scale factor and scaling the output distance by the scale factor to maintain correct distance values [S3, unofficial].
4.  **Material/Color Changes**: Standard polygonizers do not consider materials, leading to drastic color changes at CSG boundaries. Material changes must be treated as surface boundaries to separate colors correctly [S14, unofficial].

## Subtopics

### [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md)
Combines SDFs into a single implicit function using Boolean operations, explicitly constructing a unified representation (often a Point-Classification Map or merged voxel buffer) for rendering as a solid object or volumetric element. Choose when voxelization or grid-based rendering is required instead of ray marching.

### [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md)
An interactive editor that constructs SDFs from primitives and operations using a stack-based interface (RPN), implicitly representing a tree with postorder traversal, deferring structure resolution until compilation. Choose when procedural, interactive scene assembly is preferred over direct code composition.

### Smooth SDF Boolean Composition
A symbolic representation and evaluation method for constructing complex implicit surfaces by composing primitive SDFs using smooth approximations of Boolean operations [S15, unofficial]. It replaces sharp min/max transitions with continuous polynomial blends, allowing organic blending without discrete creases [S15, unofficial]. The smooth intersection (AND) uses $f_{and} = f_1 + f_2 - \sqrt{f_1^2 + f_2^2}$, and the smooth union (OR) uses $f_{or} = f_1 + f_2 + \sqrt{f_1^2 + f_2^2}$ [S15, unofficial]. Subtraction is computed as $f_{sub} = f_{and}(f_1, -f_2)$ [S15, unofficial]. It is chosen when smooth, organic transitions between shapes are required, at the cost of slightly higher evaluation complexity compared to standard min/max [S15, unofficial].

## Operating characteristics
- **Time Complexity**: 
    - Ray Marching: $O(N)$ per ray, where $N$ is the number of steps [S2, unofficial]. Each step requires evaluating the CSG tree [S2, unofficial]. If the tree has depth $D$, the evaluation cost is $O(D)$ per step [S2, unofficial].
    - Voxelization (Grid-based): Material index generation and combination is $O(n^3)$, where $n$ is the resolution. Edge generation is $O(3 \times n^3)$. Edge combination is $O(n)$ [S1].
- **Memory Complexity**: 
    - Ray Marching: $O(D)$ for the recursion stack or $O(1)$ if iterative [S2, unofficial].
    - Voxelization: $O(n^3)$ for the material grid and edge arrays [S1].
- **Performance**: CSG operations are computationally cheap per sample (just min/max), allowing complex scenes to be rendered efficiently [S2, S4, unofficial]. However, deep CSG trees increase the number of primitive evaluations per ray step [S2, S4, unofficial].
- **Strengths**: 
    - Exact representation of Boolean combinations [S2, unofficial].
    - Smooth variants allow for organic blending [S11, unofficial].
    - Easy to implement and integrate into ray marchers [S3, unofficial].
- **Limitations**: 
    - Sharp creases in standard operations can cause artifacts in lighting or marching if not handled [S11, unofficial].
    - Difference operations can break the Lipschitz-1 property, requiring careful step size management [S12, unofficial].
    - Not suitable for direct polygonization without additional material boundary handling [S14, unofficial].

## Background
The mathematical basis relies on the properties of min and max functions preserving the signed distance property for union and intersection [S8]. Ricci (1974) established the foundation for combining implicit surfaces using these operators [S8]. The application to SDFs was later adapted for ray marching in shader programming [S3, S12, S13, unofficial].
