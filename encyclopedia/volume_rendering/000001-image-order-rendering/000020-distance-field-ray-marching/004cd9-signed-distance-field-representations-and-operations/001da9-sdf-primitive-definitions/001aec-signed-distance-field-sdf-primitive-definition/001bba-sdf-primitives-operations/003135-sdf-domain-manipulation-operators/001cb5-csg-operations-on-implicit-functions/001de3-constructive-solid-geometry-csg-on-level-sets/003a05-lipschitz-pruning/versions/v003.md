# Lipschitz Pruning

Also called: Hierarchical Simplification of Primitive-Based SDFs, Hierarchical pruning with Lipschitz criteria, Smooth CSG Tree Pruning

## Overview
Lipschitz Pruning is a hierarchical simplification algorithm that reduces the number of active nodes in a smooth Constructive Solid Geometry (CSG) tree for a specific region of space, outputting a pruned tree equivalent to the full tree within that region [S1]. It relies on the 1-Lipschitz property of the distance function to determine if a binary operator's result is unaffected by blending within a spatial region [S1]. Unlike bounding-volume approaches that require boxes extended by the blending radius, Lipschitz Pruning is space-centric, requires no bounding box computation, and guarantees distance exactness [S1]. It builds on [Constructive Solid Geometry (CSG) on Level Sets](1627-constructive-solid-geometry-csg-on-level-sets.md) by optimizing the evaluation of the resulting implicit functions [S1].

## How it works
**Inputs:**
*   A smooth CSG tree representing a Signed Distance Field (SDF) $f$ [S1]. The tree consists of leaf nodes (primitives) and internal nodes (binary operators) [S1].
*   A spatial region defined by a closed ball $B$ with center $p$ and radius $R$ [S1].
*   For hierarchical application: a parent pruned tree and a target grid resolution [S1].

**Outputs:**
*   A pruned CSG tree valid for the region $B$, containing only globally active nodes [S1].
*   The size (number of globally active nodes) of the pruned tree [S1].

**Data Structures:**
Each node in the CSG tree stores the following fields [S1]:
*   `operator_type`: Enum indicating the CSG operation (UNION, INTER, SUB) [S1].
*   `k`: Blending radius for smooth CSG operators [S1].
*   `s`: Sign ($\pm 1$) encoding the comparison direction for the pruning constraint [S1].
*   `left_child`, `right_child`: References to child nodes [S1].
*   `cFlag`: Sign ($\pm 1$) stored in the child node indicating if the operand should be complemented (flipped sign) when the operator reduces to it [S1]. Specifically, `left_child.cFlag` corresponds to $c_a$ and `right_child.cFlag` corresponds to $c_b$ [S1].

**Pruning Constraint:**
For a binary operator with operands $a$ and $b$, define complementary values $a' = c_a \cdot a$ and $b' = c_b \cdot b$ [S1]. The operator reduces to one operand if [S1]:
$$ \text{if } |a' - b'| > k, \text{ OP}(a, b) = \begin{cases} a' & \text{if } s \cdot a' \leq s \cdot b' \\ b' & \text{otherwise} \end{cases} $$
The parameters $c_a, c_b \in \{+1, -1\}$ and $s \in \{+1, -1\}$ depend on the operator type [S1]:
*   **UNION**: $c_a = +1, c_b = +1, s = +1$.
*   **INTER**: $c_a = +1, c_b = +1, s = -1$.
*   **SUB**: $c_a = +1, c_b = -1, s = -1$.

**Smooth Blending Kernel:**
The method uses quadratic blending where the blending kernel $\phi(d, k)$ vanishes as $d \to k$ [S1]:
$$ \phi(d, k) = \frac{1}{4k} \max(k - d, 0)^2 $$
The operators are defined as [S1]:
$$ \text{UNION}(a, b, k) = \min(a, b) - \phi(|a - b|, k) $$
$$ \text{INTER}(a, b, k) = \max(a, b) + \phi(|a - b|, k) $$
$$ \text{SUB}(a, b, k) = \max(a, -b) + \phi(|a + b|, k) $$

**Algorithm Steps:**

1.  **Traversal #1 (Post-order): Compute Local State** [S1]
    For each node in the tree, determine its local state: `inactive`, `skipped`, or `active` [S1].
    *   **Skip Condition**: For an operator node with children $f_1, f_2$, region center $p$, and radius $R$: [S1]
        If $|f_1(p) - f_2(p)| \geq k + 2R$, the operator is **skipped** [S1].
        *Derivation*: Since SDFs are 1-Lipschitz ($||\nabla f|| \leq 1$), for any $q \in B$:
        $$ |f_1(q) - f_2(q)| \geq |f_1(p) - f_2(p)| - |f_1(q) - f_1(p) + f_2(p) - f_2(q)| \geq (k+2R) - 2R = k $$
        Thus, the condition $|a' - b'| > k$ holds for all $q \in B$, allowing reduction to one operand [S1].
    *   **Skip Handling**: If skipped, mark the operator as `skipped` [S1]. Depending on the sign of $f_1(p) - f_2(p)$, mark one child as `inactive` (the one that is not chosen by the reduction constraint) [S1].
    *   **Inactive**: A node is `inactive` if it does not contribute to its parent's value (e.g., marked inactive by a parent skip, or a leaf with no contribution) [S1].
    *   **Active**: A node is `active` if it contributes to the parent and is not skipped [S1].

2.  **Traversal #2 (Pre-order): Compute Global State and Rewire** [S1]
    Determine the global state and construct the pruned tree [S1].
    *   Initialize root as `globally_active` [S1].
    *   For each node, if it is `globally_active` and locally `active`:
        *   Mark as `globally_active` [S1].
        *   Create a new node in the pruned tree [S1].
        *   **Parent Rewiring**: The new parent of a child node is its closest ancestor that is not `skipped` [S1].
        *   **Complementary Propagation**: If an ancestor was `skipped`, propagate its complementary flag ($c_a$ or $c_b$) to the current node's `cFlag` [S1].
    *   Count the number of `globally_active` nodes [S1].

3.  **Hierarchical Application** [S1]
    To handle dense grids and memory constraints [S1]:
    *   Start with a coarse grid covering the scene bounding box [S1].
    *   For each cell, apply the pruning procedure using the pruned tree of its parent cell as input [S1].
    *   Iteratively subdivide cells until the target resolution is reached [S1].
    *   This reduces memory footprint and computation time as trees become smaller at finer levels [S1].

**Pseudocode:**

```python
class Node:
    def __init__(self, op_type, k, s, left=None, right=None, cFlag=1):
        self.op_type = op_type
        self.k = k
        self.s = s
        self.left = left
        self.right = right
        self.cFlag = cFlag
        self.state = None  # 'inactive', 'skipped', 'active'
        self.val = 0       # Distance value at the evaluation point

def lipschitz_prune(root_node, center_p, radius_R):
    # Step 1: Post-order traversal to compute local states
    stack = [root_node]
    post_order = []
    while stack:
        node = stack.pop()
        post_order.append(node)
        if node.left: stack.append(node.left)
        if node.right: stack.append(node.right)
    
    for node in reversed(post_order):
        if node.left is None or node.right is None:
            node.state = 'active'
            continue
        
        left_val = node.left.val
        right_val = node.right.val
        
        left_val_comp = node.left.cFlag * left_val
        right_val_comp = node.right.cFlag * right_val
        
        diff = abs(left_val_comp - right_val_comp)
        
        if diff >= node.k + 2 * radius_R:
            node.state = 'skipped'
            if node.s * left_val_comp <= node.s * right_val_comp:
                node.right.state = 'inactive'
            else:
                node.left.state = 'inactive'
        else:
            node.state = 'active'

    # Step 2: Pre-order traversal to compute global states and build pruned tree
    pruned_root = None
    active_count = 0

    def build_pruned_tree(node, parent_pruned_node, inherited_cFlag):
        nonlocal active_count, pruned_root
        
        if node.state == 'inactive':
            return None
            
        if node.state == 'active':
            active_count += 1
            new_node = Node(node.op_type, node.k, node.s)
            new_node.cFlag = inherited_cFlag
            new_node.left = None
            new_node.right = None
            
            if parent_pruned_node is None:
                pruned_root = new_node
            else:
                if parent_pruned_node.left is None:
                    parent_pruned_node.left = new_node
                else:
                    parent_pruned_node.right = new_node
            
            build_pruned_tree(node.left, new_node, inherited_cFlag * node.left.cFlag)
            build_pruned_tree(node.right, new_node, inherited_cFlag * node.right.cFlag)
            
        elif node.state == 'skipped':
            build_pruned_tree(node.left, parent_pruned_node, inherited_cFlag * node.left.cFlag)
            build_pruned_tree(node.right, parent_pruned_node, inherited_cFlag * node.right.cFlag)
            
        return pruned_root

    build_pruned_tree(root_node, None, 1)
    return pruned_root, active_count
```

## Subtopics

### [Far-field Culling](8625-far-field-culling.md)
Far-field culling is an optimization for Signed Distance Field (SDF) evaluation that replaces sub-trees in cells sufficiently far from the 0-isosurface with a single constant node providing a conservative lower-bound distance. It builds on [Lipschitz Pruning](8623-lipschitz-pruning.md) by further reducing the number of active nodes during sphere tracing or contouring tasks, where exact differentiability is not required. Unlike the baseline hierarchical pruning which preserves the full tree structure within active regions, far-field culling aggressively simplifies the geometry representation in empty space, improving tracing performance by up to a factor of 2 on complex scenes.

### [GPU Implementation of Hierarchical CSG Pruning](8626-gpu-implementation-of-hierarchical-csg-pruning.md)
This method implements the hierarchical CSG pruning algorithm described in [Lipschitz Pruning](8623-lipschitz-pruning.md) on a GPU using compute shaders. It reduces the computational load of Signed Distance Field (SDF) evaluation by iteratively pruning SDF trees across a hierarchical grid, storing data in three specific arrays. It differs from CPU-based implementations by leveraging parallel thread execution per grid cell and warp-level coherence to eliminate divergence, building on the hierarchical CSG pruning framework.

## Operating characteristics
**Time and Memory Complexity:**
*   The pruning procedure is executed once for static scenes and every frame for dynamic scenes due to low runtime overhead [S1].
*   Hierarchical application reduces memory footprint and speeds up computation as trees become smaller at finer levels [S1].
*   Direct application to all cells of a dense grid without hierarchy leads to memory allocation failures for large scenes because pruned tree size is unknown in advance [S1].

**Measured Performance:**
*   Tested on an RTX 4060 laptop with 8GB VRAM [S1].
*   **Pruning Time ($T_p$):** Ranges from 0.72 ms (Gameboy, N=65) to 125.54 ms (Fluid, N=27977) [S1].
*   **Sphere Tracing Time ($T_s$):** Ranges from 1.17 ms to 78.52 ms [S1].
*   **Discretization Time ($T_d$) over a $256^3$ grid:** Ranges from 0.19 ms to 6.99 ms [S1].
*   **Speedups:** Reach two orders of magnitude over naive sphere tracing on City and Crowd scenes with one primary and one shadow ray per pixel at 1920×1080 resolution [S1].
*   Far-field culling improves tracing performance by up to a factor of 2 [S1].

**Strengths and Limitations:**
*   **Strengths:** Space-centric rather than object-centric; does not require bounding box computation; guarantees distance exactness; robust to blending radius compared to state-of-the-art methods [S1].
*   **Limitations:** Restricted to primitives and operators that are 1-Lipschitz ($||\nabla f|| \leq 1$) [S1]. Scenes with densely packed primitives (e.g., fluid particles) reduce pruning efficiency [S1]. High blending radius $k$ negatively affects runtime [S1].
*   **Comparison:** Lipschitz bounds have similar pruning capabilities to Range Arithmetic (affine/interval) but are less costly [S1].

## Background
Lipschitz Pruning was introduced in the paper "Lipschitz Pruning: Hierarchical Simplification of Primitive-Based SDFs" [S1]. It addresses the high cost of SDF evaluation in smooth CSG trees by exploiting the 1-Lipschitz property [S1]. The method complements far-field culling and is applicable to ray tracing and meshing contexts [S1]. Unlike bounding-volume approaches that require boxes extended by the blending radius, Lipschitz Pruning is space-centric and requires no bounding box computation [S1].
