# SDF Smooth Union

Also called: smooth union, Smooth Minimum, S-Union, Smooth Union SDF Operator, LogSumExp SDF Union

## Overview
SDF Smooth Union combines two or more Signed Distance Functions (SDFs) into a single smooth SDF, avoiding sharp edges at primitive intersections [S2, unofficial][S3, unofficial]. It approximates the boolean union operation using a blending parameter $k$ [S1, unofficial]. It sets itself apart from [Multi-Material Distance Fields](1943-multi-material-distance-fields.md) by focusing on geometric distance blending rather than material interpolation, though it can be extended to blend materials alongside distances [S4, unofficial].

## How it works
The method evaluates individual SDFs at a query point and blends the resulting distances to produce a unified field [S3, unofficial].

### Inputs and Outputs
*   **Inputs**: Two (or more) signed distance values $a$ and $b$ (or $S_i(p)$) at a query point, and a smoothness parameter $k$ (blend radius) [S1, unofficial][S2, unofficial].
*   **Outputs**: A single signed distance value representing the smooth union [S3, unofficial].

### Data Structures
When combining multiple primitives with associated materials, the result is wrapped in a structure [S4, unofficial]:
*   `SdResult`: A struct containing:
    *   `distance` (float): The signed distance value, accessed via `.x` [S4, unofficial].
    *   `material` (struct): Material properties (diffuse, specular, etc.) [S4, unofficial].

### Numbered Steps
1.  Apply transformations (translation, rotation, scaling) to the query point $p$ if required by the primitive definitions [S4, unofficial].
2.  Evaluate each primitive's SDF at $p$ to obtain distances $d_i$ [S4, unofficial].
3.  Combine the distances using the chosen smooth minimum formula with parameter $k$ [S3, unofficial].
4.  Return the combined distance (and associated material if using `SdResult`) [S4, unofficial].

### Formulas

#### 1. Polynomial Smooth Minimum (`sminCubic`)
This variant uses a cubic polynomial approximation [S4, unofficial].

Let $a$ and $b$ be the two SDF values. Let $k$ be the blend radius [S4, unofficial].

1.  Calculate the interpolation factor $h$:
    $$ h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right) $$
2.  Calculate the result:
    $$ \text{result} = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h) $$
    Where $\text{mix}(a, b, t) = a \cdot (1 - t) + b \cdot t$ [S1, unofficial].

#### 2. LogSumExp Smooth Minimum
This variant uses the soft-min approximation via exponentials [S2, unofficial].

For a set of SDFs $S_i(p)$:
$$ S_{union}(p) = -\frac{1}{k} \ln \left( \sum_{i} e^{-k \cdot S_i(p)} \right) $$
Or equivalently:
$$ S_{union}(p) = \frac{1}{-k} \text{logsumexp}_{i}(-k \cdot S_i(p)) $$
where $k$ is a positive float controlling smoothness [S2, unofficial].

### Parameters
*   **$k$ (blend radius / smoothness)**: Controls the width of the transition region between shapes [S1, unofficial]. Higher values result in a smoother union [S2, unofficial]. Typical values depend on the desired "blobbiness" or scale of the primitives [S4, unofficial]. In specific implementations, typical values are 0.5 for primitive blending and 0.33 for final scene blending [S4, unofficial]. A typical value of 1.0f is also noted [S3, unofficial].

### Pseudocode
```python
import math

def mix(a: float, b: float, t: float) -> float:
    """Linear interpolation: a * (1 - t) + b * t"""
    return a * (1.0 - t) + b * t

def clamp(val: float, min_val: float, max_val: float) -> float:
    """Clamp value to [min_val, max_val]"""
    return max(min_val, min(max_val, val))

def sminCubic(a: float, b: float, k: float) -> float:
    """Polynomial smooth union of two SDF values."""
    if k <= 0.0:
        return min(a, b)  # Guard against division by zero [G]
    h = 0.5 + 0.5 * (b - a) / k
    h = clamp(h, 0.0, 1.0)
    return mix(b, a, h) - k * h * (1.0 - h)

def sminLogSumExp(values: list, k: float) -> float:
    """LogSumExp smooth union for multiple SDF values."""
    if not values:
        return float('inf')
    neg_k_s = [-k * s for s in values]
    max_val = max(neg_k_s)
    sum_exp = sum(math.exp(val - max_val) for val in neg_k_s)
    log_sum_exp = math.log(sum_exp) + max_val
    return -log_sum_exp / k

class SdResult:
    """Container for distance and material data."""
    def __init__(self, distance: float, material):
        self.distance = distance
        self.material = material
        self.x = distance  # Alias for .x access [S4, unofficial]

def combine_sdfs(sdfs: list, materials: list, p, k: float) -> SdResult:
    """
    Combines multiple SDFs with materials using polynomial smin.
    Matches nested sminCubic pattern from [S4, unofficial].
    """
    distances = [sdf(p) for sdf in sdfs]
    combined_dist = distances[0]
    for i in range(1, len(distances)):
        combined_dist = sminCubic(combined_dist, distances[i], k)
    # Material blending: pick closest primitive's material [G]
    min_idx = distances.index(min(distances))
    return SdResult(combined_dist, materials[min_idx])
```

### Edge Cases and Pitfalls
*   **Precision**: When using LogSumExp, subtracting the maximum value before exponentiation is required for numerical stability [G].
*   **Boundary**: The polynomial `sminCubic` is only $C^1$ continuous if $k$ is chosen appropriately relative to the curvature of the primitives [G].
*   **Degenerate Input**: If $k \le 0$, division by zero occurs; the operation falls back to a hard `min` [G].

## Subtopics

### Polynomial Smooth Minimum
A cubic polynomial approximation for blending two SDFs [S4, unofficial][S5, unofficial]. Sets it apart by being branch-free and trigonometry-free, making it highly efficient for real-time shaders [S5, unofficial]. Choose it when performance is critical and exactly two inputs need blending. Link: [Object Combination Operators](1801-object-combination-operators.md).

### LogSumExp Smooth Minimum
A soft-min approximation using exponentials for blending multiple SDFs [S2, unofficial]. Sets it apart by naturally generalizing to $N$ inputs without nested binary calls and providing mathematically smooth gradients [S2, unofficial]. Choose it for differentiable rendering or when combining many primitives. Link: [Object Combination Operators](1801-object-combination-operators.md).

## Operating characteristics
*   **Time Complexity**: Not given in the sources.
*   **Memory Complexity**: Not given in the sources.
*   **Measured Performance**: Not given in the sources.
*   **Scaling**: Linear in the number of primitives $N$ for LogSumExp; polynomial variant requires $N-1$ nested binary calls [G].
*   **Strengths**: Produces smooth, organic transitions; avoids sharp edges [S2, unofficial][S3, unofficial].
*   **Limitations**: The resulting distance field is an approximation and not a true Euclidean distance field [G]. The smoothness parameter $k$ must be tuned per scene scale [G].
*   **When to use**: When organic, blended transitions between shapes are desired over sharp boolean edges [S3, unofficial].
*   **When not to use**: When exact Euclidean distance is required for physics or precise collision detection [G].

## Background
The concept of smooth minimum operators for SDFs has been popularized in the context of ray marching and procedural modeling [S4, unofficial]. The polynomial variant (`sminCubic`) is widely used in shader code for its simplicity [S4, unofficial]. The LogSumExp variant is derived from the soft-min function in optimization and machine learning [S2, unofficial].
