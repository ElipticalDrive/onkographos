# SDF Smooth Union

Also called: LogSumExp SDF Union, S-Union, Smooth Minimum, Smooth Minimum Blend (Cubic), Smooth Union (S-Union), Smooth Union SDF Operator, opSmoothUnion, sminCubic

## Overview
SDF Smooth Union is a method to combine two or more Signed Distance Functions (SDFs) into a single smooth SDF, avoiding sharp edges at the intersection of primitives [S2, unofficial][S3, unofficial]. It approximates the boolean union operation using a blending parameter $k$ [S1, unofficial]. It sets itself apart from its siblings, such as [Multi-Material Distance Fields](1943-multi-material-distance-fields.md), by focusing on geometric blending of distances rather than material interpolation, although it can be extended to blend materials [S4, unofficial].

## How it works
The method combines individual SDF results to produce a unified distance field [S3, unofficial]. Two primary formulations exist: the polynomial smooth minimum (often called `smin` or `sminCubic`) and the LogSumExp smooth minimum [S1, unofficial][S2, unofficial].

### Inputs and Outputs
*   **Inputs**: Two (or more) signed distance values $a$ and $b$ (or $S_i(p)$) at a query point, and a smoothness parameter $k$ (or blend factor) [S1, unofficial][S2, unofficial].
*   **Outputs**: A single signed distance value representing the smooth union [S3, unofficial].

### Data Structures
When combining multiple primitives with associated materials, the result is often wrapped in a structure [S4, unofficial]:
*   `SdResult`: A struct containing:
    *   `distance` (float): The signed distance value, accessed via `.x` [S4, unofficial].
    *   `material` (struct): Material properties (diffuse, specular, etc.) [S4, unofficial].

### Formulas

#### 1. Polynomial Smooth Minimum (`smin` / `sminCubic`)
This variant uses a cubic polynomial approximation [S4, unofficial].

Let $a$ and $b$ be the two SDF values. Let $k$ be the blend radius (smoothness parameter) [S4, unofficial].

1.  Calculate the interpolation factor $h$:
    $$ h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{b - a}{k}, 0.0, 1.0\right) $$
2.  Calculate the result:
    $$ \text{result} = \text{mix}(b, a, h) - k \cdot h \cdot (1.0 - h) $$
    Where $\text{mix}(b, a, h) = b + h(a - b)$ [S5, unofficial].

Alternatively, expressed directly using $d_1$ and $d_2$:
$$ h = \text{clamp}\left(0.5 + 0.5 \cdot \frac{d_2 - d_1}{k}, 0., 1.\right) $$
$$ \text{union}(d_1, d_2, k) = \text{mix}(d_2, d_1, h) - k \cdot h \cdot (1 - h) $$
where $\text{mix}(a, b, t) = a \cdot (1 - t) + b \cdot t$ [S1, unofficial].

#### 2. LogSumExp Smooth Minimum
This variant uses the soft-min approximation via exponentials [S2, unofficial].

For a set of SDFs $S_i(p)$:
$$ S_{union}(p) = -\frac{1}{k} \ln \left( \sum_{i} e^{-k \cdot S_i(p)} \right) $$
Or equivalently:
$$ S_{union}(p) = \frac{1}{-k} \text{logsumexp}_{i}(-k \cdot S_i(p)) $$
where $k$ is a positive float controlling smoothness [S2, unofficial].

### Parameters
*   **$k$ (blend radius / smoothness)**: Controls the width of the transition region between shapes [S1, unofficial]. Higher values result in a smoother union [S2, unofficial]. Typical values depend on the desired "blobbiness" or scale of the primitives [S4, unofficial]. In specific implementations, typical values are 0.5 for primitive blending and 0.33 for final scene blending [S4, unofficial]. A typical value of 1.0f is also noted [S3, unofficial].

### Pseudocode
```python
import math

def mix(a: float, b: float, t: float) -> float:
    """Linear interpolation: a * (1 - t) + b * t"""
    return a * (1.0 - t) + b * t

def clamp(val: float, min_val: float, max_val: float) -> float:
    """Clamp value to [min_val, max_val]"""
    return max(min_val, min(max_val, val))

def smin_polynomial(a: float, b: float, k: float) -> float:
    """Polynomial smooth union of two SDF values."""
    if k <= 0.0:
        return min(a, b)  # Guard against division by zero [G]
    h = 0.5 + 0.5 * (b - a) / k
    h = clamp(h, 0.0, 1.0)
    return mix(b, a, h) - k * h * (1.0 - h)

def smin_logsumexp(values: list, k: float) -> float:
    """LogSumExp smooth union for multiple SDF values."""
    if not values:
        return float('inf')
    neg_k_s = [-k * s for s in values]
    max_val = max(neg_k_s)
    sum_exp = sum(math.exp(val - max_val) for val in neg_k_s)
    log_sum_exp = math.log(sum_exp) + max_val
    return -log_sum_exp / k

class SdResult:
    """Container for distance and material data."""
    def __init__(self, distance: float, material):
        self.distance = distance
        self.material = material
        self.x = distance  # Alias for .x access [S4, unofficial]

def combine_sdfs(sdfs: list, materials: list, p, k: float) -> SdResult:
    """
    Combines multiple SDFs with materials using polynomial smin.
    Matches nested sminCubic pattern from [S4, unofficial].
    """
    distances = [sdf(p) for sdf in sdfs]
    combined_dist = distances[0]
    for i in range(1, len(distances)):
        combined_dist = smin_polynomial(combined_dist, distances[i], k)
    # Material blending: pick closest primitive's material [G]
    min_idx = distances.index(min(distances))
    return SdResult(combined_dist, materials[min_idx])
```

### Edge Cases and Pitfalls
*   **Precision**: When using LogSumExp, subtracting the maximum value before exponentiation is required for numerical stability [G].
*   **Boundary**: The polynomial `smin` is only $C^1$ continuous if $k$ is chosen appropriately relative to the curvature of the primitives [G].
*   **Degenerate Input**: If $k \le 0$, division by zero occurs; the operation falls back to a hard `min` [G].

## Subtopics

### Polynomial Smooth Minimum
A blending function for combining two SDF values to create organic, metaball-like merges between primitives without branching or trigonometry [S5, unofficial]. It uses a cubic polynomial approximation [S4, unofficial]. It is controlled by the blend radius parameter $k$ (or `uBlendK`) [S5, unofficial].

### LogSumExp Smooth Minimum
A method using the soft-min approximation via exponentials [S2, unofficial]. It is controlled by the positive float `blend_k` [S2, unofficial]. It generalizes easily to $N$ inputs [G].

## Background
The concept of smooth minimum operators for SDFs has been popularized in the context of ray marching and procedural modeling [S4, unofficial]. The polynomial variant (`smin`) is widely used in shader code for its simplicity [S4, unofficial]. The LogSumExp variant is derived from the soft-min function in optimization and machine learning [S2, unofficial].
