# SDF Transformations

Also called: SDF Composition, SDF Modifiers

## Overview
SDF Transformations are geometric operations applied to Signed Distance Functions to construct complex procedural scenes from simple primitives. They solve the problem of modeling intricate geometry without explicit mesh data by composing distance fields through Boolean logic and spatial manipulation. Unlike sibling methods that rely on external data structures or rasterization buffers, SDF Transformations operate directly on the distance field function, allowing for extremely low memory footprints and infinite resolution [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $\mathbf{p}$ in world space, primitive SDF functions $f_i(\mathbf{p})$, transformation parameters (e.g., spacing, twist angle, time $t$), and Boolean operators.
*   **Output:** The signed distance value $d$ at $\mathbf{p}$ for the composite scene.

**Data Structures:**
No persistent data structures are required for the transformation logic itself. The scene is defined by the composition of functions. For dynamic variants, a time parameter $t$ and object identifiers are passed to the transformation function [S2].

**Steps:**
1.  **Primitive Evaluation:** Evaluate the base SDF for the primitive at the query point. For a sphere of radius $r$ centered at $\mathbf{c}$, $f_{sphere}(\mathbf{p}) = \|\mathbf{p} - \mathbf{c}\| - r$ [S1, unofficial].
2.  **Transformation Application:** Modify the query point $\mathbf{p}$ before evaluation to apply spatial transformations. Common transformations include:
    *   **Repetition (Tiling):** Map $\mathbf{p}$ into a local cell to create periodic structures.
        $$ \mathbf{p}_{local} = \text{mod}(\mathbf{p}, \text{spacing}) - \frac{\text{spacing}}{2} $$
        Then evaluate the primitive SDF using $\mathbf{p}_{local}$ [S1, unofficial].
    *   **Deformation:** Apply a non-linear transformation function to $\mathbf{p}$, such as a twist or bend, before evaluation.
        $$ \mathbf{p}_{deformed} = \text{twist}(\mathbf{p}) $$
        Evaluate the primitive SDF using $\mathbf{p}_{deformed}$ [S1, unofficial].
    *   **Affine Transformation:** For standard rigid body motion, transform $\mathbf{p}$ to the object's local space using the inverse transformation matrix $M^{-1}$: $\mathbf{p}_{local} = M^{-1}\mathbf{p}$ [S3850, unofficial].
3.  **Boolean Composition:** Combine the distances from multiple primitives or transformed instances using set operations:
    *   **Union:** $d = \min(d_1, d_2)$
    *   **Intersection:** $d = \max(d_1, d_2)$
    *   **Subtraction:** $d = \max(-d_1, d_2)$ [S39, unofficial].
4.  **Dynamic Variation (Optional):** For dynamic objects, calculate a variation vector or transformation matrix based on time $t$ and object ID, then apply this as an additional transformation to the ray position before the Instancing operator [S2].

**Pseudocode:**
```python
def sdf_transformations(p, time, object_id):
    """
    Computes the SDF value at point p, applying transformations.
    """
    # 1. Apply Repetition (Tiling)
    spacing = 2.0
    p_local = mod(p, spacing) - spacing / 2.0
    
    # 2. Apply Deformation (Twist)
    # Example: Twist around Y axis
    angle = p_local.y * 0.5
    cos_a = cos(angle)
    sin_a = sin(angle)
    p_twisted = vec3(
        p_local.x * cos_a - p_local.z * sin_a,
        p_local.y,
        p_local.x * sin_a + p_local.z * cos_a
    )
    
    # 3. Evaluate Primitive (Sphere)
    center = vec3(0.0)
    radius = 0.5
    d = length(p_twisted - center) - radius
    
    # 4. Dynamic Transformation (if applicable)
    # Calculate dynamic variation based on time and ID
    # This modifies the position or scale dynamically
    if use_dynamic:
        variation = holistics_scene_dynamics(time, object_id)
        # Apply affine transformation derived from variation
        p_final = apply_affine(p, variation)
        d = length(p_final - center) - radius
        
    return d
```

**Parameters:**
*   `spacing`: Distance between repeated instances. Typical values depend on scene scale.
*   `time`: Simulation time for dynamic operators.
*   `object_id`: Unique identifier for per-object variation [S2].

**Edge Cases:**
*   **Precision:** Modulo operations can suffer from precision issues at large coordinates. [G] Use `fract()` or careful modulo implementation to maintain precision.
*   **Boundaries:** Deformations like twisting can cause self-intersection or invalid distances if the deformation is too severe relative to the primitive size.

## Subtopics

### Dynamic Operators
An extension to global operators that applies unique affine transformations and material animations to 3D objects using a Holistic Scene Dynamics Function (HSD). Unlike original global operators that relied on the Instancing operator's grid cell vector, Dynamic Operators calculate the grid cell vector independently and apply a transformation to the ray position before the Instancing operator to preserve the correct SDF form. This allows for effects like wind sway or flying objects [S2].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation. Total time is proportional to the number of primitives in the composition.
*   **Memory Complexity:** $O(1)$. No scene graph or mesh data is stored; only the shader code and parameters [S1, unofficial].
*   **Strengths:** Infinite resolution, extremely low memory footprint, easy to create complex procedural geometry [S1, unofficial].
*   **Limitations:** Cannot represent arbitrary topology changes easily; Boolean operations can create artifacts if not smoothed (e.g., using `smin`); deformation must preserve the Lipschitz condition for sphere tracing to remain valid [S27, unofficial].

## Background
SDF transformations are a core technique in procedural rendering, popularized by shaders in real-time graphics. The concept of composing SDFs via Boolean operations and spatial transformations allows for the creation of complex scenes from simple mathematical primitives. Dynamic operators were introduced as an extension to the Holistic UOI rendering pipeline to handle time-varying transformations and instancing [S2].
