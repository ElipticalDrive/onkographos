# SDF Depth Buffer Integration

Also called: Raymarching with Depth Buffer Output, Sphere Tracing for Depth Output, Sphere Tracing with Depth Buffer Output

## Overview
SDF Depth Buffer Integration is a technique that extends sphere tracing by explicitly writing the computed surface hit point's depth to the hardware depth buffer (`SV_Depth`) [S1, unofficial][S2, unofficial][S3, unofficial]. It solves the problem of incorrect occlusion between ray-marched SDF geometry and standard rasterized geometry, where the depth buffer would otherwise record the depth of the proxy mesh face rather than the actual ray-marched surface [S2, unofficial]. It is distinguished from standard raymarching, which typically only outputs color, by ensuring the SDF geometry participates in standard depth testing [S3, unofficial].

## How it works
The method builds on [Distance-field ray marching](21-distance-field-ray-marching.md) [S3, unofficial]. It requires a fragment shader that outputs both color and depth, and a specific render queue configuration to ensure correct occlusion ordering [S2, unofficial][S3, unofficial].

### Inputs and Outputs
**Inputs:**
- Vertex position in object space.
- Camera position in world space.
- Scene SDF function $S(\mathbf{p})$ [S3, unofficial].

**Outputs:**
- `color` (SV_TARGET): The rendered surface color [S3, unofficial].
- `depth` (SV_Depth): The normalized device coordinate (NDC) depth value of the hit point [S2, unofficial][S3, unofficial].

### Data Structures
The vertex shader output struct (`v2f`) layout is:
- `position` (SV_POSITION): Clip-space vertex position for rasterization [S2, unofficial][S3, unofficial].
- `localPosition` (TEXCOORD0): Object-space position, used as the ray origin [S2, unofficial][S3, unofficial].
- `viewDirection` (TEXCOORD1): Object-space view vector from camera to vertex, stored un-normalized to avoid interpolation precision loss [S2, unofficial][S3, unofficial].

### Parameters
- `MAX_STEPS`: Maximum ray march iterations allowed before declaring a miss. Typical value: 32 [S2, unofficial][S3, unofficial].
- `THICKNESS`: SDF value threshold below which a sample point is considered to be on or inside the surface. Typical value: 0.001 [S2, unofficial][S3, unofficial].
- `NORMAL_EPSILON`: Small offset distance used for finite difference approximation of the surface normal. Typical value: 0.01 [S2, unofficial][S3, unofficial].

### Steps
1. **Vertex Shader Setup**:
   - Compute clip-space position: `o.position = UnityObjectToClipPos(v.vertex)` [S3, unofficial].
   - Store object-space vertex position as ray origin: `o.localPosition = v.vertex` [S3, unofficial].
   - Compute camera position in object space: `objectSpaceCameraPos = mul(unity_WorldToObject, float4(_WorldSpaceCameraPos, 1))` [S3, unofficial].
   - Compute view direction: `o.viewDirection = v.vertex - objectSpaceCameraPos` [S3, unofficial].

2. **Fragment Shader Initialization**:
   - Set ray origin `pos = i.localPosition` [S3, unofficial].
   - Normalize view direction: `dir = normalize(i.viewDirection.xyz)` [S3, unofficial].
   - Initialize `progress = 0` [S3, unofficial].
   - Initialize `hitsurface = false` [S3, unofficial].

3. **Ray Marching Loop**:
   - Iterate `iter` from 0 to `MAX_STEPS - 1` [S3, unofficial].
   - Calculate sample point: `samplePoint = pos + dir * progress` [S2, unofficial].
   - Query SDF: `distance = scene(samplePoint)` [S3, unofficial].
   - If `distance < THICKNESS`:
     - Set `hitsurface = true` [S3, unofficial].
     - Break loop [S3, unofficial].
   - Advance ray: `progress = progress + distance` [S3, unofficial].

4. **Hit/Miss Handling**:
   - If `!hitsurface`: Execute `discard` to prevent writing to buffers and avoid driver differences compared to `clip(-1)` [S2, unofficial][S3, unofficial].

5. **Color Calculation**:
   - Compute surface normal using central finite differences:
     $$n_x = S(p + \epsilon e_x) - S(p - \epsilon e_x)$$
     $$n_y = S(p + \epsilon e_y) - S(p - \epsilon e_y)$$
     $$n_z = S(p + \epsilon e_z) - S(p - \epsilon e_z)$$
     where $\epsilon = \text{NORMAL\_EPSILON}$ [S3, unofficial].
   - Transform normal to world space and normalize [S3, unofficial].
   - Compute lighting and return `color` [S3, unofficial].

6. **Depth Calculation**:
   - Transform hit point to clip space: `tracedClipPos = UnityObjectToClipPos(float4(samplePoint, 1.0))` [S1, unofficial].
   - Compute NDC depth: `depth = tracedClipPos.z / tracedClipPos.w` [S2, unofficial][S3, unofficial].

### Pseudocode
```python
import math

# Constants
MAX_STEPS = 32
THICKNESS = 0.001
NORMAL_EPSILON = 0.01

# Vector/Matrix helpers
def vec3(x, y, z): return (x, y, z)
def vec4(x, y, z, w): return (x, y, z, w)
def add3(a, b): return (a[0]+b[0], a[1]+b[1], a[2]+b[2])
def sub3(a, b): return (a[0]-b[0], a[1]-b[1], a[2]-b[2])
def scale3(v, s): return (v[0]*s, v[1]*s, v[2]*s)
def dot3(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def length3(v): return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)
def normalize3(v):
    l = length3(v)
    if l == 0: return (0, 0, 0)
    return (v[0]/l, v[1]/l, v[2]/l)
def mat_mul_vec4(M, v):
    return (
        M[0][0]*v[0] + M[0][1]*v[1] + M[0][2]*v[2] + M[0][3]*v[3],
        M[1][0]*v[0] + M[1][1]*v[1] + M[1][2]*v[2] + M[1][3]*v[3],
        M[2][0]*v[0] + M[2][1]*v[1] + M[2][2]*v[2] + M[2][3]*v[3],
        M[3][0]*v[0] + M[3][1]*v[1] + M[3][2]*v[2] + M[3][3]*v[3]
    )
def UnityObjectToClipPos(pos, MVP_MATRIX):
    return mat_mul_vec4(MVP_MATRIX, vec4(pos[0], pos[1], pos[2], 1.0))

# Scene SDF (Sphere radius 0.5 at origin)
def scene(pos):
    return length3(pos) - 0.5

# Vertex Shader
def vert(v_vertex, camera_world_pos, MVP_MATRIX, inverse_model_matrix):
    o_position = UnityObjectToClipPos(v_vertex, MVP_MATRIX)
    o_localPosition = v_vertex
    objectSpaceCameraPos = mat_mul_vec4(inverse_model_matrix, vec4(camera_world_pos[0], camera_world_pos[1], camera_world_pos[2], 1.0))
    o_viewDirection = sub3(v_vertex, objectSpaceCameraPos)
    return {'position': o_position, 'localPosition': o_localPosition, 'viewDirection': o_viewDirection}

# Fragment Shader
def frag(i, MVP_MATRIX, inverse_model_matrix, unity_ObjectToWorld):
    pos = i['localPosition']
    dir = normalize3(i['viewDirection'])
    progress = 0.0
    samplePoint = vec3(0, 0, 0)
    hitsurface = False
    
    for _ in range(MAX_STEPS):
        samplePoint = add3(pos, scale3(dir, progress))
        distance = scene(samplePoint)
        if distance < THICKNESS:
            hitsurface = True
            break
        progress = progress + distance
    
    if not hitsurface:
        return None  # Simulates discard
    
    # Color Calculation
    normal = compute_normal(samplePoint, unity_ObjectToWorld)
    color = render_surface(samplePoint, normal)
    
    # Depth Calculation
    tracedClipPos = UnityObjectToClipPos(samplePoint, MVP_MATRIX)
    depth = tracedClipPos[2] / tracedClipPos[3]
    
    return color, depth

def compute_normal(pos, unity_ObjectToWorld):
    eps = NORMAL_EPSILON
    changeX = scene(add3(pos, vec3(eps, 0, 0))) - scene(sub3(pos, vec3(eps, 0, 0)))
    changeY = scene(add3(pos, vec3(0, eps, 0))) - scene(sub3(pos, vec3(0, eps, 0)))
    changeZ = scene(add3(pos, vec3(0, 0, eps))) - scene(sub3(pos, vec3(0, 0, eps)))
    surfaceNormal = vec3(changeX, changeY, changeZ)
    surfaceNormal = mat_mul_vec4(unity_ObjectToWorld, vec4(surfaceNormal[0], surfaceNormal[1], surfaceNormal[2], 0.0))
    return normalize3((surfaceNormal[0], surfaceNormal[1], surfaceNormal[2]))

def render_surface(pos, normal):
    lightDirection = normalize3(vec3(1, 1, 0))
    lightAngle = max(dot3(normal, lightDirection), 0.0)
    return lightAngle
```

### Edge Cases and Pitfalls
- **Incorrect Occlusion**: Without `SV_Depth` output, the depth buffer records the proxy mesh face depth, causing rasterized objects behind the SDF surface to appear in front, and vice versa [S2, unofficial].
- **Early-Z Disable**: Writing `SV_Depth` disables GPU early-Z optimization for affected pixels because the hardware cannot know the depth before the fragment shader runs [S2, unofficial].
- **Discard vs Clip**: Use `discard` instead of `clip(-1)` to avoid potential driver differences in depth buffering [S2, unofficial][S3, unofficial].
- **Precision Loss**: View direction is stored un-normalized in `TEXCOORD1` and normalized in the fragment shader to avoid precision loss during interpolation [S3, unofficial].
- **Batching**: `DisableBatching` must be set to `True` because batching breaks the object-to-world transform used for ray setup [S2, unofficial].

## Subtopics

### Near-Far Depth Extraction
A pixel shader technique to extract the near and far depth values of active cells for ray marching [S4, unofficial]. It uses alpha blending to simultaneously store the smallest depth in the RGB channels and the largest depth in the Alpha channel [S4, unofficial]. The view space Z component (`input.projPos.w`) is output to the Red channel for the smallest depth and to the Alpha channel for the largest depth [S4, unofficial]. This relies on the hardware's output merger behavior, which keeps the smallest value for color components (RGB) and the largest value for the alpha component when blending [S4, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is `MAX_STEPS` [S2, unofficial]. Each pixel requires up to `MAX_STEPS` SDF evaluations [S2, unofficial].
- **Memory Complexity**: $O(1)$ per pixel for the ray marching state [S2, unofficial].
- **Performance**: The explicit depth write disables early-Z, potentially reducing performance compared to standard rasterization or raymarching without depth output [S2, unofficial].
- **Strengths**: Correct occlusion between SDF and rasterized geometry [S2, unofficial].
- **Limitations**: Loss of early-Z optimization; requires specific render queue settings (`Geometry+1`) [S2, unofficial].
