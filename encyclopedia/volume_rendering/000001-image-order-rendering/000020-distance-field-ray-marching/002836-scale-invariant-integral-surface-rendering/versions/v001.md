# Scale-Invariant Integral Surface Rendering

Also called: SCALIS rendering, method using homothetic distance and quadratic polynomial interpolation

## Overview
Scale-Invariant Integral Surface Rendering (SCALIS) is a ray-marching algorithm designed to render integral surfaces defined by skeletons with varying radii, significantly reducing computation time compared to standard sphere tracing [S1]. It addresses the specific problem of excessive step counts along grazing rays—a well-known bottleneck in distance-field ray marching—by using homothetic distance for initial sampling and quadratic polynomial interpolation for field evaluation [S1]. Unlike standard sphere tracing which relies on global Lipschitz bounds, SCALIS adapts to the local geometry of segment primitives, offering up to 70% faster rendering while maintaining visual fidelity [S1].

## How it works
**Inputs:**
- A set of skeleton primitives (random or procedural) defining the geometry.
- Ray origins and directions (typically launched in six cardinal directions for statistics, or per-pixel for rendering).
- Kernel parameters defining the scale-invariant integral surface.

**Outputs:**
- Rendered image or ray statistics (average, median, maximal steps).

**Data Structures:**
- **Skeleton Primitives:** Defined by sphere-cone supports. Each primitive has an associated axis-aligned bounding box (AABB) [S1].
- **Heap:** A priority queue storing segment primitives. The heap must accommodate all primitives whose supports overlap the initial intervals defined by the argument of the minimum of homothetic distance [S1].
- **A-Buffer:** A data structure used for efficient GPU implementation to handle overlaps and accumulation [S1].

**Method Steps:**

1.  **Skeleton Generation:** Generate skeletons (random or procedural) on the CPU. This occurs at each parameter change to allow interactive manipulation [S1].
2.  **Bounding Box Computation:** Compute the axis-aligned bounding box (AABB) for each model based on the sphere-cone supports of its primitives [S1].
3.  **Ray Launching:** Launch sets of rays in six directions (positive and negative orientations of the three main axes). Ray origins are sampled uniformly on the associated bounding box's face. The source specifies a total of 10 million rays per model for statistical validation [S1].
4.  **Field and Gradient Evaluation:** For each ray, compute the field value and its gradient simultaneously. This approach costs less than twice the evaluation cost of a single field value and allows segment parameters to be fetched from memory only once [S1].
5.  **Homothetic Distance Sampling:** Use homothetic distance to segment primitives to determine the initial sampling strategy. This reduces the number of steps required, particularly for grazing rays [S1].
6.  **Quadratic Polynomial Interpolation:** Apply quadratic polynomial interpolation to the field mapping. This heuristic improves the efficiency of the ray marching process [S1].
7.  **Ray Processing Loop:**
    -   Maintain a heap of relevant primitives.
    -   Advance the ray using the interpolated field values.
    -   Check for isosurface crossings (isovalue 0).
    -   If the heap size becomes too large, a break condition based on current heap size can be added to mitigate memory limitations [S1].

**Formulas and Parameters:**
-   **Field Evaluation:** The directional derivative is evaluated using the computed gradient. The cost is $< 2 \times$ single field evaluation cost [S1].
-   **Error Rate:** Less than $10^{-3}\%$ of rays miss an isosurface crossing. These are exclusively grazing rays where the control polygons of the Hermite interpolant do not cross the isovalue 0 [S1].
-   **Performance:** The method provides a reduction in the maximal number of steps required along grazing rays compared to sphere tracing [S1].

**Pitfalls and Edge Cases:**
-   **Grazing Ray Errors:** A small fraction of rays ($< 10^{-3}\%$) may miss the isosurface due to Hermite data configurations where control polygons do not cross the isovalue 0. This limits the efficiency of the rational interpolation heuristic [S1].
-   **Heap Size:** The heap used to store segment primitives must be large enough to accommodate all primitives overlapping the initial intervals. If not, it may cause performance issues or require additional break conditions [S1].
-   **Finely Tessellated Curves:** Finely tessellated skeletons increase the number of arguments for the minimum of homothetic distance, potentially increasing computational load [S1].

## Operating characteristics
-   **Performance:** The method reduces computation time by up to 70% compared to previous work [S1]. It provides a significant reduction in the maximal number of steps required along grazing rays, which is a known limitation of sphere tracing [S1].
-   **Accuracy:** Less than $10^{-3}\%$ of rays miss an isosurface crossing, all of which are grazing rays [S1].
-   **Memory:** Requires a heap large enough to store segment primitives whose supports overlap the initial intervals. The A-buffer can become expensive for finely tessellated curves due to overlaps [S1].
-   **Hardware:** Designed for efficient GPU implementation using an A-buffer [S1].
-   **When to use:** Ideal for interactive modeling of large ranges of skeletons with varying radii, where performance on grazing rays is critical [S1].
-   **When not to use:** Not suitable for scenes with extremely finely tessellated curves where the A-buffer overhead becomes prohibitive, or when output invariance is critical without combining with occluders [S1].

## Background
Scale-Invariant Integral Surface Rendering was introduced in the paper "Fast Ray Tracing of Scale‐Invariant Integral Surfaces" [S1]. The method was developed to address the limitations of sphere tracing, particularly its inefficiency with grazing rays. It builds on the concept of integral surfaces defined by skeletons and introduces homothetic distance and quadratic polynomial interpolation to improve rendering speed. The technique allows for interactive manipulation of complex skeletal structures, making it suitable for real-time exploration of kernel parameters [S1].
