# Chunked Sphere Tracing

Also called: SphereTracingRendererChunk

## Overview
Chunked Sphere Tracing is a memory-management optimization for sphere tracing that processes rays in batches to prevent GPU out-of-memory errors during large-scale rendering. It solves the problem of excessive VRAM consumption when evaluating Signed Distance Functions (SDFs) for millions of rays simultaneously by limiting the active ray count per forward pass. It differs from its parent method by introducing a batching constraint on the ray bundle, while remaining distinct from acceleration-based siblings like [FBM Sphere Tracing with BVH Acceleration](1728-fbm-sphere-tracing-with-bvh-acceleration.md) which focus on reducing step counts rather than memory footprint.

## How it works
The method extends the standard sphere tracing loop by wrapping the evaluation of the SDF and ray advancement in a chunked iteration over the total ray population.

**Inputs and Outputs:**
*   **Input:** A ray bundle containing origins and directions for $N$ pixels, a neural implicit function or SDF evaluator, and a `chunk_size` parameter.
*   **Output:** A concatenated tensor of colors (or hit distances) for all $N$ rays.

**Data Structures:**
*   `ray_bundle`: A tensor of shape $(N, 2, 3)$ or similar, storing origins and directions.
*   `chunk_colors`: A list to store intermediate color tensors for each chunk.

**Parameters:**
*   `chunk_size`: The maximum number of rays processed in a single forward pass. [S1, unofficial]

**Algorithm Steps:**
1.  Determine the total number of rays $N$ from the input ray bundle.
2.  Initialize an empty list `chunk_colors`.
3.  Iterate through the ray bundle in steps of `chunk_size`:
    a.  Calculate `chunk_start` indices: $0, \text{chunk\_size}, 2 \times \text{chunk\_size}, \dots$
    b.  Slice the `ray_bundle` to extract the current subset of rays: `cur_ray_bundle` = `ray_bundle`[`chunk_start` : `chunk_start` + `chunk_size`].
    c.  Invoke the parent sphere tracing algorithm (or a standard SDF evaluation loop) on `cur_ray_bundle` to compute colors.
    d.  Append the resulting color tensor to `chunk_colors`.
4.  Concatenate all tensors in `chunk_colors` along the ray dimension (dimension 0) to form the final output image.

**Pseudocode:**
```python
def chunked_sphere_tracing(ray_bundle, sdf, chunk_size, max_steps, max_distance, epsilon):
    """
    Renders rays in chunks to manage memory usage.
    
    Args:
        ray_bundle: Tensor of shape (N, 2, 3) or (N, 3) for origins/directions.
        sdf: Callable Signed Distance Function.
        chunk_size: Max rays per batch.
        max_steps: Max iterations per ray.
        max_distance: Max ray length.
        epsilon: Hit threshold.
    Returns:
        colors: Tensor of shape (N, 3) with final pixel colors.
    """
    N = ray_bundle.shape[0]
    chunk_colors = []
    
    # Iterate over chunks
    for chunk_start in range(0, N, chunk_size):
        # Slice current chunk
        end_index = min(chunk_start + chunk_size, N)
        cur_ray_bundle = ray_bundle[chunk_start:end_index]
        
        # Process chunk using standard sphere tracing logic
        # Note: This calls the core logic defined in the parent article
        cur_colors = sphere_tracing(
            ray_bundle=cur_ray_bundle,
            sdf=sdf,
            max_steps=max_steps,
            max_distance=max_distance,
            epsilon=epsilon
        )
        
        chunk_colors.append(cur_colors)
        
    # Concatenate results
    colors = torch.cat(chunk_colors, dim=0)
    return colors

def sphere_tracing(ray_bundle, sdf, max_steps, max_distance, epsilon):
    """
    Standard sphere tracing for a batch of rays.
    """
    origins = ray_bundle[:, 0] # Assuming structure (N, 2, 3) or similar
    directions = ray_bundle[:, 1]
    
    # Initialize distances
    t = torch.zeros(origins.shape[0], device=origins.device)
    hit = torch.zeros(origins.shape[0], dtype=torch.bool, device=origins.device)
    colors = torch.zeros_like(origins) # Placeholder for color
    
    for _ in range(max_steps):
        if hit.all():
            break
            
        # Get current points
        points = origins + t.unsqueeze(1) * directions
        
        # Evaluate SDF
        d = sdf(points)
        
        # Update hit status
        new_hits = d < epsilon
        hit = hit | new_hits
        
        # Advance non-hit rays
        # Avoid division by zero or invalid steps for already hit rays
        step_mask = ~hit
        t[step_mask] = t[step_mask] + d[step_mask]
        
        # Check max distance
        if t.max() > max_distance:
            break
            
    return colors # In a real implementation, shading logic would populate colors
```

**Edge Cases and Pitfalls:**
*   **Memory Limits:** If `chunk_size` is too large, the GPU may still OOM. The value must be tuned based on available VRAM and the memory footprint of the SDF network. [S1, unofficial]
*   **Batch Inconsistency:** Ensure that the SDF evaluation handles batched inputs correctly and does not rely on global state that might be corrupted by partial processing.
*   **Concatenation Order:** The final concatenation must preserve the original ray order to map colors back to the correct pixel coordinates.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of rays and $S$ is the average number of steps per ray. Chunking does not change the asymptotic computational complexity but adds negligible overhead for slicing and concatenation.
*   **Memory Complexity:** $O(C \cdot S)$, where $C$ is the `chunk_size`. This is significantly lower than the naive $O(N \cdot S)$ memory requirement for storing intermediate ray states for all rays simultaneously.
*   **Performance:** Performance is limited by the chosen `chunk_size`. Smaller chunks reduce memory pressure but increase Python loop overhead and kernel launch latency. Larger chunks improve throughput but risk OOM. [S1, unofficial]
*   **Strengths:** Enables rendering of high-resolution images or large scenes on hardware with limited VRAM.
*   **Limitations:** Does not accelerate the ray marching itself; it only manages memory. Not suitable for scenarios where the SDF evaluation is the bottleneck and VRAM is sufficient.

## Background
Chunked Sphere Tracing is a practical implementation technique used in neural volume and surface rendering pipelines to handle large ray bundles. It is documented in the context of training and rendering neural implicit surfaces, specifically within the `Neural-Volume-Rendering-and-Surface-Rendering` repository. [S1, unofficial]
