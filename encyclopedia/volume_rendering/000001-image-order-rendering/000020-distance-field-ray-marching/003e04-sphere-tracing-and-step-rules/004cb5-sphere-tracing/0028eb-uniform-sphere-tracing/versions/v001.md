# Uniform Sphere Tracing

Also called: Ray Marching for Volumes, Uniform Density Volume Rendering, Volume Rendering with Ray Marching (Uniform Sphere)

## Overview
Uniform Sphere Tracing renders volumetric objects (typically spheres) by computing ray intersections to determine the path length through the medium, then applying Beer's Law to calculate transmission and blending the transmitted background with the volume's intrinsic scattered color [S1, unofficial]. Unlike general-purpose ray marching which samples discrete points within a volume grid, this method analytically solves for the entry and exit points of a ray through a closed primitive, treating the volume as a uniform slab [S1, unofficial]. It is distinct from [Sphere Tracing with SDFs](6223-sphere-tracing-with-sdfs.md) because it does not iterate via distance fields to find surfaces; instead, it uses analytic geometry to find the full chord length through the volume in a single step, assuming constant optical properties throughout the object [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $ro$ and normalized direction $v$ [S1, unofficial].
- Scene object defined by a Signed Distance Function or analytic primitive (e.g., Sphere with center $c$, radius $r$, absorption coefficient $\sigma_a$, and scatter color $C_{vol}$) [S1, unofficial].
- Background color $C_{bg}$ [S1, unofficial].

**Outputs:**
- Final pixel color $C_{final}$ [S1, unofficial].

**Data Structures:**
- `Sphere` object containing:
  - `center`: `vec3` (position) [S1, unofficial].
  - `radius`: `float` (scalar) [S1, unofficial].
  - `sigma_a`: `float` (absorption coefficient) [S1, unofficial].
  - `scatter`: `vec3` (intrinsic volume color) [S1, unofficial].
  - `intersect`: function returning intersection distances $t_0$ (entry) and $t_1$ (exit) [S1, unofficial].

**Steps:**
1. **Ray Generation:** For each pixel, compute the ray origin $ro$ and normalized direction $v$ [S1, unofficial].
2. **Intersection Test:** Query the scene object for intersection. If no intersection exists, return $C_{bg}$ [S1, unofficial].
3. **Chord Calculation:** If an intersection exists, retrieve the entry distance $t_0$ and exit distance $t_1$ [S1, unofficial].
   - Calculate the entry point $p_1 = ro + t_0 \cdot v$ [S1, unofficial].
   - Calculate the exit point $p_2 = ro + t_1 \cdot v$ [S1, unofficial].
   - Calculate the distance traveled through the volume $d$. Since $v$ is normalized, $d = t_1 - t_0$ [S1, unofficial].
4. **Transmission:** Calculate the transmission $T$ using Beer's Law [S1, unofficial]:
   $$ T = e^{-d \cdot \sigma_a} $$
   where $\sigma_a$ is the absorption coefficient [S1, unofficial].
5. **Color Blending:** Compute the final color by blending the attenuated background with the volume's scattered color [S1, unofficial]:
   $$ C_{final} = T \cdot C_{bg} + (1 - T) \cdot C_{vol} $$
   where $C_{vol}$ is the scatter color of the volume [S1, unofficial].

**Parameters:**
- $\sigma_a$ (absorption coefficient): Controls opacity. Typical value: 0.1 [S1, unofficial].
- $C_{vol}$ (scatter color): The color the volume emits/scatters. Typical value: `vec3(0.8, 0.1, 0.5)` [S1, unofficial].
- $C_{bg}$ (background color): Color behind the volume. Typical value: `vec3(0.572, 0.772, 0.921)` [S1, unofficial].

**Pitfalls:**
- The distance calculation $d$ must be accurate. If the ray direction is not normalized, $d$ cannot be simply calculated as $t_1 - t_0$; it requires vector length calculation [S1, unofficial].
- The method assumes uniform density and optical properties within the volume. It does not handle varying density or internal lighting gradients without extension [S1, unofficial].

**Pseudocode:**
```python
def uniform_sphere_trace(ray_origin, ray_direction, sphere, background_color):
    # 1. Intersection test
    # Returns t0 (entry) and t1 (exit) if intersected, else None
    t0, t1 = sphere.intersect(ray_origin, ray_direction)
    
    if t0 is None:
        return background_color

    # 2. Calculate distance through volume
    # Note: ray_direction must be normalized for t1 - t0 to be the Euclidean distance
    distance = t1 - t0
    
    # 3. Calculate transmission using Beer's Law
    # T = exp(-distance * sigma_a)
    transmission = exp(-distance * sphere.sigma_a)
    
    # 4. Blend background and volume color
    # C_final = T * C_bg + (1 - T) * C_vol
    final_color = transmission * background_color + (1.0 - transmission) * sphere.scatter
    
    return final_color
```

## Operating characteristics
- **Time Complexity:** $O(1)$ per pixel for a single sphere, as it involves a constant number of arithmetic operations and a single analytic intersection test [S1, unofficial].
- **Memory Complexity:** $O(1)$, storing only the sphere parameters and ray state [S1, unofficial].
- **Strengths:** Extremely fast for simple, closed volumetric primitives like spheres or boxes with uniform properties. No iterative sampling or grid lookups required [S1, unofficial].
- **Limitations:** Cannot handle non-uniform volumes, complex shapes without analytic intersection functions, or internal lighting effects (shadows, subsurface scattering) without significant modification [S1, unofficial]. Not suitable for general volume rendering where density varies spatially.
- **When to use:** Simple, stylized volumetric effects (e.g., fog balls, smoke puffs) where performance is critical and the volume is uniform [S1, unofficial].
- **When not to use:** Realistic medical imaging, complex atmospheric effects, or scenes with multiple interacting volumes [S1, unofficial].

## Background
The method originates from basic computer graphics tutorials on volume rendering, specifically illustrating the application of Beer's Law to simple geometric primitives [S1, unofficial]. It serves as an introductory example for understanding how light attenuation and scattering work in volumes before moving to more complex ray marching techniques [S1, unofficial]. The specific implementation details, including the `Sphere` class structure and parameter values, are derived from a tutorial hosted on BimAnt [S1, unofficial].
