# Mandelbulb Sphere Tracing

Also called: Mandelbulb Fractal Rendering, Mandelbulb Ray Marching, Mandelbulb SDF Raymarching, Mandelbulb Tracing, mandelSphereTracing

## Overview
Mandelbulb Sphere Tracing is a variation of sphere tracing that renders the Mandelbulb fractal, a 3D generalization of the Mandelbrot set, by using a specific distance estimator function (`distMandelBulb`) instead of primitive shapes [S1, unofficial][S2, unofficial]. It solves the problem of visualizing infinite-detail fractal geometry that cannot be triangulated, relying on the iterative "spherical power" operation to define the surface [S2, unofficial]. Unlike sibling methods like [Menger Sponge Raymarching](4875-menger-sponge-raymarching.md) which have finite depth, the Mandelbulb has infinite self-similar detail, requiring more iterations and suffering from greater distance estimator inaccuracy as the camera zooms in [S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Camera origin $ro$, ray direction $v$, camera parameters (zoom, up vector), fractal parameters (power exponent, typically 8), and rendering parameters (hit threshold, max march distance, max steps).
- **Outputs:** Pixel color (or background), hit status, and accumulated distance.

**Data Structures:**
- `minDistances[x][y][5]`: A 3D array storing per-pixel data. Index 0 is unused or reserved; Index 1 is status (0=light, 1=shadow); Indices 2-4 are RGB color components; Index 5 is the iteration count or mu value [S1, unofficial].
- `Vector3`: A structure containing x, y, z coordinates and potentially origin offsets, used for camera vectors [S1, unofficial].

**Parameters:**
- `power`: Spherical power exponent. Default/Typical value: 8 [S2, unofficial].
- `hit_threshold`: Distance below which a hit is registered. Default/Typical value: 0.01 [S1, unofficial].
- `max_march_distance`: Maximum distance a ray can travel before being considered a miss. Default/Typical value: 2000 [S1, unofficial].
- `iterations_per_step`: Number of Mandelbulb formula iterations run per raymarch step. Default/Typical value: ~10 [S2, unofficial].
- `max_steps`: Safety cap for raymarch iterations. Default/Typical value: 200 (from source [S1, unofficial], though parent suggests 32-128; this implementation uses 200) [S1, unofficial].

**Formulas:**
1.  **Mandelbulb Iteration (Spherical Power):**
    The core fractal generation uses the transformation:
    $$ point \rightarrow \text{spherical-power-8}(point) + c $$
    Where $c$ is a constant (often the initial point or a fixed offset depending on the specific distance estimator variant). The "spherical-power-8" operation raises the radius to the 8th power and rotates the direction by 8 times the original angle [S2, unofficial].
    
2.  **Distance Estimator (Hubbard-Douady):**
    The distance estimate $d$ is derived from the escape behavior of the iteration. Specifically, it uses the Hubbard-Douady distance estimator, which is an approximation (lower bound) of the true distance [S2, unofficial].
    $$ d \approx \frac{\|z_n\| \cdot \ln(\|z_n\|)}{\|z'_n\|} $$
    Where $z_n$ is the final point after $n$ iterations, and $z'_n$ is the derivative tracker magnitude. *Note: The exact derivative tracking formula is not explicitly provided in the sources, but it is required for the estimator [S2, unofficial].*

3.  **Ray Advancement:**
    $$ p \leftarrow p + d \cdot v $$
    Some implementations adjust the step by `cos(angle)` factors, but the standard sphere tracing step is used [S1, unofficial].

**Numbered Steps:**
1.  **Initialization:** For each pixel, initialize the ray origin $ro$ and direction $v$. Set current position $p = ro$. Initialize iteration counter $iter = 0$.
2.  **Ray Marching Loop:** While $iter < \text{MAX\_STEPS}$ and $p$ is within bounds:
    a.  Evaluate the Mandelbulb SDF at $p$ by calling `distMandelBulb(p)`. This involves running ~10 iterations of the spherical power formula and computing the Hubbard-Douady estimate [S2, unofficial].
    b.  Get the distance estimate $d$.
    c.  **Hit Test:** If $d \le \text{HIT\_THRESHOLD}$ (0.01), the ray has hit the surface. Terminate loop, record hit status and distance.
    d.  **Miss Test:** If $d > \text{MAX\_MARCH\_DISTANCE}$ (2000) or accumulated distance exceeds limit, the ray missed. Terminate loop, record miss status.
    e.  **Step Forward:** Update position $p \leftarrow p + d \cdot v$. Increment $iter$.
3.  **Post-Processing:**
    a.  If hit, estimate surface normals by sampling the SDF at four nearby points to compute the gradient [S2, unofficial].
    b.  Apply lighting: Calculate dot product with light direction, add ambient lighting, and trace soft shadows [S2, unofficial].
    c.  Store color and status in `minDistances` array [S1, unofficial].

**Pseudocode:**
```python
import math

def spherical_power_8(point, iterations=10):
    """
    Computes the Mandelbulb iteration for a given point.
    Returns the final point and the derivative tracker magnitude.
    """
    # Convert to spherical coordinates
    r = math.sqrt(point.x**2 + point.y**2 + point.z**2)
    theta = math.acos(point.z / r) if r != 0 else 0
    phi = math.atan2(point.y, point.x)
    
    # Derivative tracker initialization
    dr = 1.0
    
    for i in range(iterations):
        # Power operation: r^n, theta -> n*theta, phi -> n*phi
        r = r**8
        theta = theta * 8
        phi = phi * 8
        
        # Update derivative tracker (simplified approximation)
        # Exact formula requires chain rule on spherical conversion
        dr = dr * 8 * r**(7/8) # Placeholder for exact derivative logic [G]
        
        # Convert back to Cartesian
        point.x = r * math.sin(theta) * math.cos(phi)
        point.y = r * math.sin(theta) * math.sin(phi)
        point.z = r * math.cos(theta)
        
        # Add constant c (often point itself or fixed offset in distance estimator)
        # Note: Standard Mandelbulb set uses z -> z^8 + c. 
        # Distance estimator usually tracks |z_n| and |dz_n|
        
    return point, dr

def dist_mandelbulb(p, power=8, iterations=10):
    """
    Hubbard-Douady distance estimator for Mandelbulb.
    """
    z = p.copy()
    dr = 1.0
    
    for i in range(iterations):
        r = math.sqrt(z.x**2 + z.y**2 + z.z**2)
        if r == 0:
            break
            
        # Spherical power
        theta = math.acos(z.z / r)
        phi = math.atan2(z.y, z.x)
        
        r = r**power
        theta = theta * power
        phi = phi * power
        
        # Derivative update
        dr = dr * power * (r**(1 - 1/power)) # Simplified [G]
        
        # Convert back
        z.x = r * math.sin(theta) * math.cos(phi)
        z.y = r * math.sin(theta) * math.sin(phi)
        z.z = r * math.cos(theta)
        
        # Escape condition for distance estimator
        if r > 2.0:
            break
            
    # Distance estimate
    if r == 0:
        return 0.0
    dist = (r * math.log(r)) / dr
    return dist

def ray_march_mandelbulb(ro, v, max_steps=200, hit_threshold=0.01, max_range=2000.0):
    p = ro
    for i in range(max_steps):
        d = dist_mandelbulb(p)
        
        if d <= hit_threshold:
            return p, True, dot(p - ro, v)
        
        if dot(p - ro, v) > max_range:
            return p, False, dot(p - ro, v)
            
        p += v * d
        
    return p, False, dot(p - ro, v)

def render_pixel(ro, v):
    hit_pos, hit, dist = ray_march_mandelbulb(ro, v)
    if hit:
        # Estimate normal
        eps = 0.01
        n = normalize(
            vec3(
                dist_mandelbulb(hit_pos + vec3(eps, 0, 0)) - dist_mandelbulb(hit_pos - vec3(eps, 0, 0)),
                dist_mandelbulb(hit_pos + vec3(0, eps, 0)) - dist_mandelbulb(hit_pos - vec3(0, eps, 0)),
                dist_mandelbulb(hit_pos + vec3(0, 0, eps)) - dist_mandelbulb(hit_pos - vec3(0, 0, eps))
            )
        )
        # Lighting
        light_dir = normalize(vec3(0, 1, 0))
        diff = max(dot(n, light_dir), 0.0)
        color = vec3(diff, diff, diff) # Simple diffuse
        return color
    else:
        return vec3(0, 0, 0) # Background
```

**Edge Cases and Pitfalls:**
- **Approximate Distance:** The Hubbard-Douady estimator is a lower bound, not exact. It can be loose, leading to smaller raymarch steps and higher GPU cost [S2, unofficial].
- **Normal Noise:** Normal estimation amplifies noise because it computes differences between approximate SDF samples. Small numerical errors in distance become large errors in normals, causing bumpy shading artifacts [S2, unofficial].
- **Infinite Detail:** As the camera zooms in, more iterations are needed, the distance estimator becomes less accurate, and normal estimation gets noisier, with no Level of Detail (LOD) fallback [S2, unofficial].
- **Precision:** Using `double` precision is recommended for the fractal calculation to maintain detail at high zoom levels [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The Mandelbulb SDF call requires ~10 iterations of spherical power (involving trig functions or custom approximations) plus a derivative tracker. This is roughly 100x the work of a simple sphere SDF. The SDF is called dozens of times per pixel during raymarching, resulting in thousands of math operations per pixel per frame just for distance estimation [S2, unofficial].
- **Memory Complexity:** Minimal per-pixel storage (distance, status, color). No large textures or volumes required.
- **Measured Performance:** Runs in real-time on modern GPUs due to parallelization, but is significantly more expensive than primitive SDFs [S2, unofficial].
- **Strengths:** Renders infinite-detail fractal geometry; real-time capable; simple implementation compared to ray-tracing fractals.
- **Limitations:** Approximate distance estimator leads to visual artifacts and slower convergence; normal estimation is noisy; no LOD mechanism for zooming.
- **When to use:** When visualizing 3D fractals like the Mandelbulb is required.
- **When not to use:** When exact distance bounds are critical or when performance is severely constrained and fractal detail is not needed.

## Background
The Mandelbulb is a 3D generalization of the Mandelbrot set, first described by Daniel Shapira in 2009 [S2, unofficial]. It is defined by iterating a 'spherical power' operation and adding a constant. The technique of rendering it via sphere tracing was popularized in the demoscene and by graphics programmers like Inigo Quilez [S2, unofficial]. The specific implementation details provided here are from unofficial GitHub repositories [S1, unofficial][S2, unofficial].
