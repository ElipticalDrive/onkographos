# Kernel-Reflection Sequences


## Overview
Kernel-Reflection Sequences (KRS) are a procedural modeling technique for generating complex, fractal-like geometries using Signed Distance Functions (SDFs) and reflection transformations [S1, unofficial]. Unlike standard Iterated Function Systems (IFS) that require recursive traversal, KRS evaluates a global distance function via a fixed, non-recursive algorithm, enabling efficient real-time sphere tracing on parallel hardware [S1, unofficial]. It sets itself apart from sibling methods by providing a closed-form iterative evaluation of reflected SDFs without recursion, allowing for continuous level-of-detail and automatic minification filtering [S1, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** A world-space query point $\mathbf{x}_w \in \mathbb{R}^3$; a sequence of $n+1$ kernel SDFs $K_0, \dots, K_n$ where each $k_i(\mathbf{p})$ returns the distance to the $i$-th kernel; a sequence of $n$ reflection operators $\mathcal{R}_0, \dots, \mathcal{R}_{n-1}$, where each $\mathcal{R}_i$ is defined by a mirror plane equation $\mathbf{u}_i \cdot \mathbf{x} - w_i = 0$ with normal $\mathbf{u}_i$ and offset $w_i$.
- **Output:** The signed distance $d$ from $\mathbf{x}_w$ to the nearest surface of the KRS geometry.

**Data Structures:**
- **KRS Definition:** An ordered pair of two finite sequences: $(K_0, \dots, K_n; \mathcal{R}_0, \dots, \mathcal{R}_{n-1})$ [S1, unofficial].
- **Kernel SDFs:** Functions $k_i: \mathbb{R}^3 \to \mathbb{R}$ [S1, unofficial].
- **Reflection Plane:** Defined by normal vector $\mathbf{u}_i$ and scalar $w_i$ [S1, unofficial].

**Algorithm Steps:**
The distance evaluation proceeds iteratively from the top-level kernel down to the base level [S1, unofficial].

1. Initialize the working point $\mathbf{x} \leftarrow \mathbf{x}_w$ [S1, unofficial].
2. Initialize the distance accumulator $d \leftarrow k_n(\mathbf{x})$, representing the distance to the top-level kernel $K_n$ [S1, unofficial].
3. Loop for $i$ from $n-1$ down to $0$:
    a. Check if the current point $\mathbf{x}$ is behind the mirror plane $i$: if $\mathbf{u}_i \cdot \mathbf{x} - w_i > 0$ [S1, unofficial].
    b. If true, transform the point to the reflected space: $\mathbf{x} \leftarrow \mathcal{R}_i \mathbf{x}$ [S1, unofficial].
    c. Update the distance: $d \leftarrow \min(d, k_i(\mathbf{x}))$ [S1, unofficial].
4. Return $d$ [S1, unofficial].

**Formulas:**
The recursive definition of the geometry at expansion level $i+1$ is:
$$ L_{i+1} = K_{i+1} \cup L_i \cup \mathcal{R}_i L_i, \quad L_0 = K_0 $$
[S1, unofficial].

The distance function $l_{i+1}(\mathbf{x})$ for the KRS is computed iteratively based on the position relative to the reflection plane $\mathbf{u}_i \cdot \mathbf{x} - w_i = 0$ [S1, unofficial]:
$$ l_{i+1}(\mathbf{x}) = \begin{cases} \min(k_{i+1}(\mathbf{x}), l_i(\mathbf{x})) & \text{if } \mathbf{u}_i \cdot \mathbf{x} - w_i \leq 0, \\ \min(k_{i+1}(\mathbf{x}), l_i(\mathcal{R}_i(\mathbf{x}))) & \text{if } \mathbf{u}_i \cdot \mathbf{x} - w_i > 0. \end{cases} $$
[S1, unofficial].

The reflection transformation $\mathcal{R}_i$ reflects a point across the plane. If the plane is defined by normal $\mathbf{u}$ (unit length) and offset $w$, the reflection of point $\mathbf{x}$ is:
$$ \mathcal{R}(\mathbf{x}) = \mathbf{x} - 2(\mathbf{u} \cdot \mathbf{x} - w)\mathbf{u} $$
[G]. This is the standard Euclidean reflection formula required to implement $\mathcal{R}_i$ in the pseudocode.

**Parameters:**
- **Termination Threshold ($\epsilon$):** In sphere tracing, the loop terminates when the step size (distance value) falls below $\epsilon$. This value is inversely proportional to camera depth, set to ensure the final unbounding sphere projected onto the viewport is smaller than a pixel [S1, unofficial]. A higher threshold makes kernel geometries appear thicker [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Intersection with Mirror Plane:** If a previous level geometry $A_i$ is not entirely on the negative side of the mirror plane but intersects it, the formula still applies [S1, unofficial]. This is equivalent to discarding the part of the geometry on the positive side, providing an underestimation for the distance to the mirrored geometry, which remains suitable for sphere tracing [S1, unofficial].
- **Lipschitz Constant:** Standard KRS transformations have a Lipschitz constant of unity, ensuring exact distance evaluation [S1, unofficial]. Non-uniform scaling or non-Lipschitz distortions require modification (see Distance Distortion below) [S1, unofficial].

**Pseudocode:**
```python
def reflect_point(x, u, w):
    """Reflect point x across plane defined by normal u and offset w."""
    # u is assumed to be normalized
    dist = dot(u, x) - w
    return x - 2.0 * dist * u

def evaluate_krs(x_w, kernels, reflections):
    """
    Evaluate the distance to a Kernel-Reflection Sequence.
    
    Args:
        x_w: World space point (vec3).
        kernels: List of SDF functions [k_0, ..., k_n].
        reflections: List of reflection definitions [(u_0, w_0), ..., (u_{n-1}, w_{n-1})].
        
    Returns:
        Signed distance to the KRS geometry.
    """
    n = len(kernels) - 1
    x = x_w
    d = kernels[n](x)
    
    for i in range(n - 1, -1, -1):
        u, w = reflections[i]
        # Check if point is behind the mirror plane
        if dot(u, x) - w > 0:
            x = reflect_point(x, u, w)
        d = min(d, kernels[i](x))
        
    return d
```

## Subtopics

### Multiple KRS Union Sphere Tracing
A technique to combine multiple KRSs to produce natural disorder and hide symmetry by taking the union of their geometries [S1, unofficial]. It maintains the free distance along the ray for all KRS components, always choosing the minimal free distance among them, and advances the ray with the radius of the unbounding sphere of the respective component that provided the minimal distance [S1, unofficial]. The search terminates when the step size for the minimal component meets the error threshold [S1, unofficial]. Performance does not depend on the number of KRS components, but rather on the number of sphere tracing steps required, with a slight overhead of maintaining a small sorted index of free distances for minimum selection [S1, unofficial]. Higher threshold levels make kernel geometries appear thicker and cause distant geometries to merge into smoother formations, losing sub-pixel details [S1, unofficial].

### Distance Distortion
A method to handle any Lipschitz transformation of the KRS geometry by sacrificing some performance [S1, unofficial]. While standard KRS has a Lipschitz constant of unity, this variant allows for non-uniform scaling or twisting distortions (e.g., to avoid conspicuous symmetries in tree-like structures) by applying the transformation to the distance evaluation, though it requires careful handling to maintain the safety of the sphere tracing step size [S1, unofficial].

## Operating characteristics
- **Time Complexity:** The distance evaluation is $O(n)$ where $n$ is the number of reflection levels, independent of recursion depth [S1, unofficial]. Sphere tracing performance depends on the number of steps required to converge, which is influenced by the threshold and geometry complexity [S1, unofficial].
- **Memory Complexity:** Requires only a few registers of read-write memory, independent of the number of levels, as the algorithm is iterative and non-recursive [S1, unofficial].
- **Performance:** Enables real-time rendering on parallel hardware (GPUs) due to the fixed operation count and lack of divergent control flow associated with recursion [S1, unofficial].
- **Strengths:** Continuous level-of-detail, automatic minification filtering, no visible symmetry artifacts when combined with multiple KRSs or distortions, efficient GPU implementation [S1, unofficial].
- **Limitations:** Standard KRS is limited to reflection-multiplied instances of the same, unscaled kernel geometry; hierarchies and non-symmetric parts require additional kernels or distortions [S1, unofficial]. Higher thresholds reduce detail at a distance [S1, unofficial].

## Background
Kernel-Reflection Sequences were proposed as a procedural modeling approach inspired by iterated function systems (IFS) [S1, unofficial]. The method was introduced to allow for real-time rendering without concessions in visible detail, specifically addressing the limitations of recursive IFS on parallel hardware [S1, unofficial]. It extends sphere tracing to conformally transformed geometries and includes techniques for GPU load balancing [S1, unofficial]. The approach has been used to realize various natural phenomena in uncompromising detail and extents, such as forests and organic structures, without obvious clues of symmetry [S1, unofficial].
