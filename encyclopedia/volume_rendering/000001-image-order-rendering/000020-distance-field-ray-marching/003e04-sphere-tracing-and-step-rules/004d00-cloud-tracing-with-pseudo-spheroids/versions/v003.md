# Cloud Tracing with Pseudo-Spheroids

Also called: Apodaca’s code (variant)

## Overview
Cloud Tracing with Pseudo-Spheroids renders volumetric clouds by tracing rays through a set of implicit surfaces (pseudo-spheroids or ellipsoids) and sampling noise only when the ray traverses these volumes [S1]. It differs from standard sphere tracing by using a list of randomized bounded-surface volumes rather than a single global Signed Distance Function (SDF), optimizing performance by discarding positions outside the cloud and using a collision detection method based on quadratic discriminants [S1].

## How it works
**Inputs:**
*   Camera origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized) for each pixel [S1].
*   List of $N$ pseudo-spheroids, each defined by center $\mathbf{c}_i$, nominal radius $R_{nominal}$, distortion parameter $k$, and maximum density $\rho_{max}$ [S1].
*   3D noise function $fBm(\mathbf{p})$ (fractional Brownian motion), normalized to $[0, 1]$ [S1].
*   Density threshold $\rho_{thresh}$ for termination [S1].
*   Bounding box for spatial culling [S1].

**Outputs:**
*   Final color $R$ for each pixel, blended with the sky background [S1].

**Data Structures:**
*   `candidates`: A list of indices of pseudo-spheroids intersected by the ray [S1].
*   `sorted_candidates`: The `candidates` list sorted by intersection distance (back-to-front) [S1].

**Formulas:**
1.  **Ray-Sphere Intersection:** For a ray $r(t) = \mathbf{o} + t\mathbf{d}$ and sphere $i$ with center $\mathbf{c}_i$ and effective radius $R_i$, the intersection is determined by the discriminant $\Delta$ of the quadratic equation $|\mathbf{o} + t\mathbf{d} - \mathbf{c}_i|^2 = R_i^2$ [S1].
    $$ \Delta = (\mathbf{d} \cdot (\mathbf{o} - \mathbf{c}_i))^2 - (|\mathbf{o} - \mathbf{c}_i|^2 - R_i^2) $$
    If $\Delta \ge 0$, the ray intersects the sphere [G]. The entry and exit distances are:
    $$ t_{entry, exit} = -(\mathbf{d} \cdot (\mathbf{o} - \mathbf{c}_i)) \pm \sqrt{\Delta} $$
2.  **Effective Radius:** The nominal radius is modulated by a random component $k$ to create a pseudo-spheroid shape [S1].
    $$ R_i = R_{nominal} \pm k $$
3.  **Density Modulation:** The density $\rho$ at a point $\mathbf{p}$ inside the pseudo-spheroid is calculated as [S1].
    $$ \rho(\mathbf{p}) = \rho_{max} \cdot fBm(\mathbf{p}) \cdot \left(1 - \frac{||\mathbf{p} - \mathbf{c}_i||}{R_i}\right) $$
    The term $(1 - \frac{||\mathbf{p} - \mathbf{c}_i||}{R_i})$ ensures density drops to zero at the boundary [S1].
4.  **Level of Detail (LOD) Step Size:** The step increment $\Delta t$ is controlled by the distance from the cloud center to balance detail and performance [S1]. Longer steps are taken when close to the camera, and smaller steps when far [S1]. The exact LOD function is not provided in the sources [G].

**Algorithm Steps:**
1.  **Culling:** For each pixel, identify pseudo-spheroids within the bounding box [S1].
2.  **Collision Detection:** For each candidate sphere, compute the discriminant $\Delta$ [S1]. If $\Delta \ge 0$, add the sphere index to the `candidates` list [S1].
3.  **Sorting:** Sort the `candidates` list by intersection distance using insertion sort, ensuring back-to-front processing [S1].
4.  **Ray Marching:** For each pixel: Initialize accumulated color $C = 0$ and opacity $\alpha = 0$ [G]. For each sphere in `sorted_candidates`: Calculate intersection interval $[t_{entry}, t_{exit}]$ [G]. If the ray does not intersect the sphere, skip [G]. March from $t_{entry}$ to $t_{exit}$ with step size $\Delta t$ (LOD adjusted) [S1]. At each step point $\mathbf{p}$: Calculate density $\rho(\mathbf{p})$ using the formula above [S1]. If $\rho(\mathbf{p}) < \rho_{thresh}$, continue [S1]. Compute lighting $L(\mathbf{p})$ [S1]. Update color and opacity using volume rendering integration [G]. If $\alpha \ge 1.0$ (or sufficient opacity), break the marching loop for this sphere [G]. Blend the accumulated cloud color $R$ with the sky background [S1].

**Pseudocode:**
```python
def cloud_tracing(ray_origin, ray_direction, spheres, noise_func, rho_thresh, sky_color):
    """
    Render clouds using pseudo-spheroids.
    Args:
        ray_origin: Camera origin (vec3)
        ray_direction: Normalized ray direction (vec3)
        spheres: List of dicts with keys: 'center', 'R_nominal', 'k', 'rho_max'
        noise_func: Function fBm(p) returning normalized noise [0,1]
        rho_thresh: Density threshold for termination
        sky_color: Background color (vec3)
    Returns:
        color: Final pixel color (vec3)
    """
    candidates = []
    # 1. Culling and Collision Detection
    for i, sphere in enumerate(spheres):
        c = sphere['center']
        R = sphere['R_nominal'] + sphere['k']
        oc = ray_origin - c
        a = dot(ray_direction, ray_direction)
        b = 2.0 * dot(oc, ray_direction)
        c_quad = dot(oc, oc) - R * R
        discriminant = b * b - 4 * a * c_quad
        if discriminant >= 0:
            sqrt_disc = sqrt(discriminant)
            t1 = (-b - sqrt_disc) / (2 * a)
            t2 = (-b + sqrt_disc) / (2 * a)
            candidates.append({'index': i, 't_entry': t1, 't_exit': t2})
    # 2. Sort Candidates (Back-to-Front)
    for i in range(1, len(candidates)):
        key = candidates[i]
        j = i - 1
        while j >= 0 and candidates[j]['t_entry'] < key['t_entry']:
            candidates[j + 1] = candidates[j]
            j -= 1
        candidates[j + 1] = key
    # 3. Ray Marching and Integration
    accumulated_color = vec3(0.0)
    accumulated_alpha = 0.0
    for cand in candidates:
        t_start = max(cand['t_entry'], 0.0)
        t_end = cand['t_exit']
        if t_start >= t_end:
            continue
        # LOD Step Size: Distance from cloud center controls step size [S1]
        dist_to_center = length(ray_origin - spheres[cand['index']]['center'])
        step_size = 0.5 / (1.0 + dist_to_center)
        t = t_start
        while t < t_end:
            p = ray_origin + t * ray_direction
            sphere = spheres[cand['index']]
            c = sphere['center']
            R = sphere['R_nominal'] + sphere['k']
            dist_to_c = length(p - c)
            if dist_to_c < R:
                noise_val = noise_func(p)
                density = sphere['rho_max'] * noise_val * (1.0 - dist_to_c / R)
                if density > rho_thresh:
                    light = vec3(1.0)
                    color = light * density
                    alpha = density * step_size
                    alpha = min(alpha, 1.0 - accumulated_alpha)
                    accumulated_color += color * alpha
                    accumulated_alpha += alpha * (1.0 - accumulated_alpha)
                    if accumulated_alpha >= 0.99:
                        break
            t += step_size
        if accumulated_alpha >= 0.99:
            break
    final_color = accumulated_color + sky_color * (1.0 - accumulated_alpha)
    return final_color
```

**Edge Cases and Pitfalls:**
*   **Precision:** Discriminant calculation must handle floating-point errors near $\Delta = 0$ [G].
*   **Boundary:** Density drops to zero at the effective radius $R_i$. Points outside this radius should not be sampled [S1].
*   **LOD:** The exact LOD equation is not provided in the source. A distance-based heuristic is used [G].
*   **Sorting:** Insertion sort is efficient for small lists of candidates but may be slow for very large $N$ [S1].

## Subtopics

### Apodaca’s code
A ray-tracing algorithm over a list of $N$ randomized bounded-surface volumes (pseudo-spheroids) to render clouds, using collision detection and insertion sort for optimization [S1]. It differs from the general method by explicitly detailing the candidate selection and sorting steps. It is chosen when a simple, GPU-friendly implementation with spatial culling is required. Link: [Cloud Tracing with Pseudo-Spheroids](9643-cloud-tracing-with-pseudo-spheroids.md).

## Operating characteristics
*   **Time Complexity:** $O(N \cdot M)$, where $N$ is the number of spheres and $M$ is the number of steps per sphere. The insertion sort adds $O(K^2)$ where $K$ is the number of intersected spheres [S1].
*   **Memory Complexity:** $O(N)$ to store sphere data and $O(K)$ for candidates [S1].
*   **Performance:** The method reduces computational effort by discarding positions outside the cloud and using a short list of intersected spheres [S1].
*   **Strengths:** Efficient culling, simple geometry (spheres/ellipsoids), good for real-time GPU rendering [S1].
*   **Limitations:** Approximation of cloud shape (pseudo-spheroids), LOD step size is heuristic [S1].
*   **When to use:** Real-time cloud rendering where performance is critical and high-fidelity global noise is not required [S1].
*   **When not to use:** When complex, non-spherical cloud structures are needed [S1].

## Background
Originated in the context of real-time GPU volumetric cloud rendering [S1]. The method is an improved version of Apodaca’s code [27] and is described in [S1]. It builds on the principle of using implicit surfaces to define cloud volumes and sampling noise only within those volumes [S1].
