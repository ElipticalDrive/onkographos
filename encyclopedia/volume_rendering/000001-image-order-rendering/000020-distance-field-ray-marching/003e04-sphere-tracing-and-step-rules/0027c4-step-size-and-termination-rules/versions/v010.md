# Step Size and Termination Rules

Also called: Ray Marching Parameters and Compositing

## Overview
Step Size and Termination Rules define the iterative logic for advancing a ray through a scene and determining when to stop, solving the problem of balancing rendering performance against visual accuracy in implicit surface and volumetric rendering. This family is distinct from [Sphere Tracing](1674-sphere-tracing.md) in that it encompasses broader strategies beyond strict Lipschitz-based distance bounds, including fixed-step marching, adaptive density-based stepping, and early termination based on opacity or transmission thresholds. It differs from [Step Size Optimization](2054-step-size-optimization.md) by focusing specifically on the termination conditions and the fundamental step size calculation mechanisms (constant, SDF-derived, or adaptive) rather than just the optimization of those steps.

## Shared principles
All methods in this family operate on a ray defined by origin $\mathbf{o}$ and normalized direction $\mathbf{d}$, parameterized by accumulated distance $t$. The core loop evaluates a scene function (SDF, density field, or volume texture) at the current position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ to determine the next step size $\Delta t$ and check for termination.

**Termination Conditions:**
1.  **Surface Hit:** The ray has intersected the target geometry. For SDFs, this is typically $|f(\mathbf{p})| < \epsilon$ or $f(\mathbf{p}) \le 0$. For volumes, this may be a density threshold or opacity accumulation [S1, unofficial].
2.  **Escape/Miss:** The ray has traveled beyond a maximum distance $t_{max}$ or exceeded a maximum iteration count $N_{max}$.
3.  **Early Termination (Volumes):** Accumulated opacity $\alpha_{acc}$ exceeds a threshold (e.g., $1 - \epsilon$), or accumulated transmission falls below a minimum threshold, allowing the ray to stop early as further contributions are negligible [S1, unofficial].

**Step Size Determination:**
The step size $\Delta t$ is computed based on the local scene properties:
*   **SDF-based:** $\Delta t$ is often derived from the SDF value $f(\mathbf{p})$, potentially scaled by a relaxation factor or Lipschitz constant $\lambda$ [S2, unofficial].
*   **Volume-based:** $\Delta t$ may be fixed, adaptive based on density gradients, or constrained by minimum/maximum bounds to prevent aliasing or excessive computation [S2, unofficial].
*   **Safety:** Steps must be chosen to ensure the ray does not penetrate the surface or skip over significant volumetric features, often requiring conservative clamping.

**Pseudocode Structure:**
```python
def ray_march_loop(ray_origin, ray_direction, scene_func, max_dist, max_steps, epsilon):
    t = 0.0
    for i in range(max_steps):
        if t > max_dist:
            return False, t
        
        p = ray_origin + ray_direction * t
        val = scene_func(p)
        
        # Termination: Hit
        if is_hit(val, epsilon):
            return True, t
        
        # Termination: Early Exit (Volume specific)
        if is_early_exit(val, t):
            return False, t # Or handle partial contribution
            
        # Step Size Calculation
        step = compute_step_size(val, t, i)
        
        # Safety Clamp
        step = max(step, min_step)
        step = min(step, max_step)
        
        t += step
        
    return False, t
```

## Subtopics

### [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md)
Standard Constant Step Ray Marching is an iterative root-finding technique for determining the intersection of a ray with an implicit surface or evaluating volumetric fields by stepping along the ray at fixed intervals. It solves the problem of rendering implicit surfaces defined by Signed Distance Functions (SDFs) or scalar fields without requiring analytical intersection solutions or polygonal mesh rasterization. Unlike [Sphere Tracing](1674-sphere-tracing.md), which dynamically adjusts step size based on the local SDF value to guarantee no overshooting, this method uses a predefined constant step size $\Delta t$, simplifying implementation but requiring careful tuning to avoid aliasing or missed details. It differs from [Step Size Optimization](2054-step-size-optimization.md) by ignoring local geometry constraints for performance, and from [SDF Ray Marching with Grid Lookup](5017-sdf-ray-marching-with-grid-lookup.md) by not using interpolation for precise intersection detection.

### [Sphere Tracing](1674-sphere-tracing.md)
Sphere Tracing is an iterative ray-marching algorithm for finding the intersection of a ray with an implicit surface defined by a Signed Distance Function (SDF) or a Lipschitz continuous function. It solves the problem of rendering complex, analytic geometry without explicit polygonal meshes by stepping along the ray by a distance guaranteed not to cross the surface, ensuring convergence to the first intersection. It sets itself apart from standard constant-step ray marching by using the local distance value as an adaptive step size, which allows large jumps in empty space and fine resolution near surfaces, provided the function satisfies the Lipschitz condition.

### [Step Size Optimization](2054-step-size-optimization.md)
Step Size Optimization encompasses techniques that dynamically determine the distance $\Delta t$ to advance a ray during volume rendering or implicit surface marching, replacing fixed-step methods to balance computational cost and visual fidelity. It solves the inefficiency of uniform sampling in empty space and the aliasing/penetration artifacts of steps that are too large for local geometry. Unlike [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md), which uses a uniform $\Delta t$, this family adapts the step length based on local scene properties such as Signed Distance Field (SDF) values, density gradients, or geometric gaps. It differs from [Sphere Tracing](1674-sphere-tracing.md) in that while sphere tracing strictly uses the SDF value as a lower bound for the step (often with a relaxation factor), step size optimization includes broader strategies like error estimation, gap limiting, and integration-based adaptive stepping that may not rely solely on the geometric distance bound.

### [Sphere Tracing Termination and Clipping](2635-sphere-tracing-termination-and-clipping.md)
Sphere Tracing Termination and Clipping defines the conditions under which a ray-marching loop halts, ensuring the algorithm returns a valid intersection point or correctly identifies a miss. It solves the problem of premature termination (missing surfaces due to large steps) and infinite loops (rays escaping to infinity or oscillating). It sets itself apart from sibling methods like [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by leveraging the Lipschitz continuity of the Signed Distance Function (SDF) to guarantee safety without fixed step sizes, and from [Interval Raymarching](13020-interval-raymarching.md) by relying on point-wise distance evaluations rather than interval arithmetic bounds.

### [SDF Scaling and Early Ray Termination for Fast Sphere Tracing](3807-sdf-scaling-and-early-ray-termination-for-fast-sphere-tracin.md)
This method accelerates sphere tracing by decoupling the distance estimation from the final high-resolution rendering into a two-pass pipeline: a low-resolution pre-processing pass and a full-resolution main pass. It solves the performance bottleneck of standard sphere tracing by using a single low-resolution buffer to provide a "head start" for full-resolution rays, positioning them closer to surfaces, while applying SDF scaling to ensure small features are not missed at low resolution. Unlike Inverse Pyramid Rendering (IPR) which uses a pyramidal render target hierarchy and filtering, this method uses a single low-resolution buffer, reducing memory cost and complexity while offering similar quality.

### [Relaxed Sphere Tracing](9463-relaxed-sphere-tracing.md)
Relaxed sphere tracing is a ray marching technique that accelerates the convergence of standard sphere tracing by scaling the conservative step size by a relaxation factor, allowing the ray to traverse empty space more quickly. It solves the performance bottleneck of standard sphere tracing in large empty volumes by reducing the number of iterations required to reach a surface, while maintaining safety by reverting to the standard step size if the unbounding spheres of consecutive steps become disjoint. It is distinguished from [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by its adaptive, distance-field-driven step sizing, and from [Enhanced Sphere Tracing](1674-sphere-tracing.md) by its simpler geometric fallback logic which may result in smaller steps near complex geometry.

### [Interval Raymarching](13020-interval-raymarching.md)
Interval Raymarching is a technique for accelerating signed distance field (SDF) raymarching by evaluating the SDF over an interval of the ray using affine or interval arithmetic, rather than at a single point. It solves the problem of slow linear convergence in standard sphere tracing by enabling reliable linear interpolation (secant method) to find the surface zero, achieving superlinear (phi-degree) convergence. Unlike sphere tracing, which guarantees no-penetration via conservative step sizes, Interval Raymarching uses the bounds of the arithmetic to verify if the surface *could* exist within the interval, allowing larger steps while maintaining correctness.

### Adaptive Minimum Step Size
**Definition:** Dynamic adjustment of the minimum step size based on distance from camera and accumulated density to reduce samples in less important areas [S2, unofficial].
**Steps:**
*   Inside the cloud (distanceField <= 0), increase minStepSize by STEP_INSCREASE_OVER_DENSITY multiplied by the current sampleDensity [S2, unofficial].
*   After advancing the ray, increase minStepSize by STEP_INCREASE_OVER_DISTANCE multiplied by the stepSize used [S2, unofficial].
**Parameters:**
*   STEP_INSCREASE_OVER_DENSITY: Constant controlling how much minStepSize increases per unit of sampleDensity [S2, unofficial].
*   STEP_INCREASE_OVER_DISTANCE: Constant controlling how much minStepSize increases per unit of stepSize (distance traveled) [S2, unofficial].
**Comparison:** Increases step size further from camera (less detail needed) and behind dense areas (less light contribution), unlike fixed step sizes [S2, unofficial].

### Cone Step Mapping
**Definition:** Cone step mapping and relaxed cone step mapping are space leaping acceleration techniques used in ray marching [S3, unofficial].

### Conservative Sphere Tracing Step Sizing
**Definition:** A fix for volumetric cloud rendering where sphere tracing takes overly aggressive step sizes, skipping cloud boundaries and leaving circular/scalloped density artifacts [S4, unofficial].
**Steps:**
*   Clamp the pre-computed 2D organic cell SDF in `cloud_weather_bake.comp` to a conservative maximum of `30000.0 * uWorldScale` [S4, unofficial].
*   Reduce the sphere tracing step size multiplier from `0.8` to `0.4` in `atmosphere_lowres.comp` to make the empty space skipping strictly conservative [S4, unofficial].
*   Clamp the empty space skipping step size to a maximum of `2000.0 * worldScale` to prevent overly aggressive jumps that bypass cloud details or boundaries [S4, unofficial].
**Parameters:**
*   SDF Max Clamp: `30000.0 * uWorldScale` [S4, unofficial].
*   Step Size Multiplier: `0.4` (reduced from `0.8`) [S4, unofficial].
*   Step Size Max Clamp: `2000.0 * worldScale` [S4, unofficial].
**Pitfalls:**
*   In empty regions of the weather map, the organic cell SDF returned uncapped values (up to 1e14), causing bilinear filtering to interpolate extremely large values near cloud edges [S4, unofficial].
*   The empty-space skipping sphere tracing loop used an aggressive step multiplier of 0.8 with no upper bound, resulting in rays jumping past the actual cloud surface [S4, unofficial].

### Early Ray Marching Termination (Threshold)
**Definition:** An optimization to stop ray marching when the accumulated transmission falls below a small threshold, saving computation in dense volumes [S5, unofficial].
**Parameters:**
*   Threshold: A small value (e.g., $10^{-3}$ or 0.001) representing the minimum transmission. Below this, the contribution to the final color is considered negligible [S5, unofficial].
**Pitfalls:**
*   Simply stopping and ignoring the remaining volume contribution is statistically incorrect and introduces bias. It is acceptable for visual rendering but not for high-precision scientific simulation (e.g., thermonuclear engineering) [S5, unofficial].

## Background
The concept of ray marching with defined step sizes and termination rules originates from the need to render implicit surfaces and volumetric data without explicit polygonal meshes. Sphere tracing, introduced by John Hart and popularized by William Donnelly, established the use of SDF values as step sizes [S3, unofficial]. Early volume rendering techniques, such as those described in "Volume Rendering for Developers," introduced early termination based on transmission thresholds to optimize performance [S5, unofficial]. Cloud rendering implementations, such as those by Jack Tollenaar, further refined step sizes with adaptive minimums based on density and distance [S2, unofficial]. Recent developments in volumetric cloud systems have addressed artifacts caused by aggressive step sizes by introducing conservative clamping and multipliers [S4, unofficial].
