# Sphere Tracing

Also called: Hart's Sphere Tracing, SDF Sphere Tracing, SDF Tracing

## Overview
Sphere tracing is an iterative ray-marching algorithm for finding the intersection of a ray with an implicit surface defined by a Signed Distance Function (SDF) [S2][S3, S17, unofficial]. It solves the problem of rendering complex, analytic geometry without explicit polygonal meshes by stepping along the ray by the distance to the nearest surface, guaranteeing that the ray never overshoots or penetrates the geometry [S4, S12, S18, unofficial]. It sets itself apart from standard constant-step ray marching by using adaptive, geometry-aware step sizes that are significantly larger in empty space, and from relaxed sphere tracing by strictly adhering to the Lipschitz bound to ensure convergence without re-evaluation [S1, S12, S39, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $\mathbf{o}$, normalized ray direction $\mathbf{d}$, scene SDF function $f(\mathbf{p})$, maximum travel distance $t_{max}$, maximum iteration count $N_{max}$, and convergence threshold $\epsilon$ [S4, S11, S19, unofficial].
*   **Output:** Intersection distance $t$, intersection point $\mathbf{p}$, and a boolean hit flag [S10, S19, unofficial].

**Data Structures:**
*   **Ray:** Defined parametrically as $r(t) = \mathbf{o} + t\mathbf{d}$ [S37, unofficial][S40].
*   **SDF:** A function $f: \mathbb{R}^3 \to \mathbb{R}$ returning the signed Euclidean distance to the nearest surface. Positive values indicate outside, negative inside, and zero on the surface [S2][S33, S39, unofficial].

**Step-by-Step Method:**
1.  **Initialization:** Set accumulated distance $t = 0$ (or a small near-plane offset $t_{near}$) [S4, S19, S35, unofficial]. Initialize iteration counter $i = 0$ [S8, S11, unofficial].
2.  **Position Calculation:** Compute the current 3D position on the ray: $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [S4, S11, S19, unofficial].
3.  **SDF Evaluation:** Query the scene function to get the distance to the nearest surface: $d = f(\mathbf{p})$ [S4, S6, S19, unofficial].
4.  **Termination Check (Hit):** If $|d| < \epsilon$ (or $d < \epsilon$ for unsigned distance fields), the ray has converged to the surface. Return $t$ and $\mathbf{p}$ as a hit [S8, S11, S19, S35, unofficial].
    *   *Note:* Some implementations use a relative threshold, e.g., $d < \epsilon \cdot t$, to maintain precision at large distances [S20, unofficial].
5.  **Termination Check (Miss):** If $t > t_{max}$, the ray has exited the scene. Return $t$ and $\mathbf{p}$ as a miss [S11, S19, S35, unofficial].
6.  **Termination Check (Stagnation):** If $i \ge N_{max}$, stop to prevent infinite loops. Return current status [S8, S11, S19, unofficial].
7.  **Step Advancement:** Advance the ray by the distance value: $t \leftarrow t + d$ [S4, S8, S19, S35, unofficial].
    *   *Safety:* For a general Lipschitz function with constant $\lambda$, the step size is scaled: $\Delta t = \frac{|d|}{\lambda}$ [S2, S5]. For a true SDF, $\lambda=1$, so $\Delta t = d$ [S2][S31, unofficial].
    *   *Clamping:* In some implementations, the step size is clamped to a minimum value to prevent stagnation in noisy fields or flat regions [S38, S4, unofficial].
8.  **Increment:** Increment $i$ and repeat from Step 2 [S8, S11, S19, unofficial].

**Pseudocode:**
```python
def sphere_trace(ray_origin, ray_direction, scene_sdf, max_dist, max_iters, epsilon):
    """
    Performs sphere tracing to find the intersection of a ray with an SDF surface.
    
    Args:
        ray_origin (vec3): The starting point of the ray.
        ray_direction (vec3): The normalized direction vector of the ray.
        scene_sdf (function): A function f(p) returning the signed distance to the nearest surface.
        max_dist (float): The maximum distance the ray can travel.
        max_iters (int): The maximum number of marching steps.
        epsilon (float): The convergence threshold for surface hit detection.
        
    Returns:
        tuple: (hit: bool, distance: float, point: vec3)
    """
    t = 0.0
    point = ray_origin
    
    for i in range(max_iters):
        # 1. Calculate current position
        point = ray_origin + ray_direction * t
        
        # 2. Evaluate SDF
        dist = scene_sdf(point)
        
        # 3. Check for hit (convergence)
        # Using absolute value for signed distance, or just dist < epsilon for unsigned
        if abs(dist) < epsilon:
            return True, t, point
            
        # 4. Check for miss (max distance)
        if t > max_dist:
            return False, t, point
            
        # 5. Advance ray
        # For SDF, step size is exactly dist. 
        # For general Lipschitz function with constant lambda, step = dist / lambda
        t += dist
        
    # 6. Max iterations reached
    return False, t, point
```

**Parameters:**
*   $\epsilon$ (Convergence Threshold): Typical values range from $0.0001$ to $0.01$ [S9, S11, S17, S30, unofficial]. A smaller value increases precision but may require more iterations.
*   $t_{max}$ (Max Distance): Typical values range from $10.0$ to $1000.0$ depending on scene scale [S11, S12, S19, S35, unofficial].
*   $N_{max}$ (Max Iterations): Typical values range from $10$ to $1024$ [S1, S12, S19, S30, S35, unofficial]. Values like 128 or 255 are common in real-time applications [S1, S12, S19, unofficial].

**Edge Cases and Pitfalls:**
*   **Lipschitz Violation:** If the SDF does not satisfy the Lipschitz condition with $\lambda=1$ (i.e., the gradient magnitude exceeds 1), stepping by $d$ may overshoot the surface, causing the ray to penetrate geometry or miss intersections entirely [S2, S5]. In such cases, the step size must be scaled by $1/\lambda$ [S2].
*   **Stagnation:** If the ray grazes a surface or enters a region of high-frequency noise in the SDF, the step size $d$ may become very small, causing the loop to terminate due to $N_{max}$ without hitting the surface [S15][S38, unofficial]. Clamping the minimum step size or using enhanced tracing variants can mitigate this [S15][S38, unofficial].
*   **Precision:** At large distances, floating-point precision errors in $t$ and $\mathbf{p}$ can cause the ray to oscillate or fail to converge. Using a relative threshold ($\epsilon \cdot t$) helps maintain accuracy [S20, unofficial].

### Cube-tracing
An algorithm using the chessboard metric (or Manhattan metric) for distance computation, potentially resulting in more efficiently computed distances and ray intersection. Left as further research [S42].

### Bounding Sphere Optimization
An optimization that decreases the number of calculations in each march by enclosing several objects into one bounding sphere. Objects are bound adaptively per frame to approximate the sphere definition for increased performance. Performance gain increases with the number of enclosed objects (e.g., >3 objects), with gains up to 25% FPS at 10 enclosed objects. It can work with Orthogonal Culling by culling bounding spheres instead of single objects [S37, unofficial].

### Hybrid Ray Marching
Integrates ray marching with distance-based empty space leaping for complex scenes, using coarse SDFs to compute large skips in low-density regions before switching to fine-grained tracing near features. It balances speed and accuracy in multi-material volumes [S13].

### Acceleration Structures for SDF Evaluation
A set of optimization nodes embedded directly in hierarchical construction trees to reduce the computational cost of field function evaluation while preserving Lipschitz properties. It avoids external data structures like octrees, using proxy and continuous level-of-detail nodes. It speeds up SDF evaluation by up to three orders of magnitude and applies to both ray-surface intersection and polygonization [S43, abstract only, unofficial].

### Harnack Tracing
A method for visualizing surfaces encoded by harmonic functions (including angle-valued functions and those with singularities) by using conservative Harnack bounds on the growth of harmonic functions to determine step sizes. It avoids numerical issues common to generic root finding and can visualize surfaces directly from point clouds or polygon soup without linear solves or mesh extraction [S33, unofficial].

### Claybook SDF Construction
A method for fully real-time deformable SDF-based worlds, using a global dense SDF with mip levels for acceleration. It constructs 5 mip levels where each level encodes distance values twice as great as the previous. Sphere-tracing samples coarser mip levels to travel greater distances conservatively, ascending/descending based on sampled distance magnitude. It uses a dense volume of resolution 1024x1024x512, as compact data structures (like SVOs) are incompatible with the brush-based modification method [S44, unofficial].

## Operating characteristics
*   **Time Complexity:** The number of iterations depends on the scene complexity and the ray's path. In empty space, steps are large, leading to $O(1)$ or $O(\log N)$ behavior relative to distance. Near surfaces, steps shrink, leading to $O(1/\epsilon)$ behavior [S12, S31, unofficial].
*   **Memory Complexity:** $O(1)$ per ray, as it only requires storing the current position, distance, and iteration count. The SDF function itself may require $O(N)$ memory if it is a dense volume, or $O(1)$ if it is analytic [S1, S12, unofficial].
*   **Measured Performance:** In tested scenes, sphere tracing can achieve high frame rates for simple analytic primitives. For example, bounding sphere optimizations can increase FPS by 25% when enclosing 10 objects [S37, unofficial]. However, performance degrades near complex surfaces or with high-frequency SDFs due to small step sizes [S1, S12, unofficial].
*   **Strengths:** No preprocessing required for analytic SDFs; perfect 3D objects; robust handling of pathological surfaces; efficient in empty space [S17, S37, S41, unofficial].
*   **Limitations:** Slow convergence near surfaces or at grazing angles; sensitive to Lipschitz constant violations; requires analytic or efficiently evaluable SDFs [S1, unofficial][S5][S12, unofficial].
*   **When to Use:** Real-time rendering of analytic geometry, procedural modeling, and scenes with simple, smooth implicit surfaces [S17, S24, unofficial].
*   **When Not to Use:** Scenes with highly complex, non-analytic geometry where polygonal meshes are more efficient; scenes with high-frequency noise in the SDF that cause stagnation [S1, S12, unofficial].

## Background
Sphere tracing was introduced by John Hart in 1996 in the paper "Sphere Tracing: A Geometric Method for the Antialiased Ray Tracing of Implicit Surfaces" [S14, unofficial][S40]. It is based on the geometric property that a sphere centered on the ray with a radius equal to the distance to the nearest surface (from an SDF) is guaranteed not to contain any part of the surface. This allows the ray to safely "jump" over empty space. The method has become a cornerstone of real-time implicit surface rendering, particularly in shader-based graphics and procedural modeling [S17, S24, S41, unofficial]. It is widely used in tools like Shadertoy and various real-time rendering engines for creating complex geometry without traditional mesh data [S4, S24, unofficial].
