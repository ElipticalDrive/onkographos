# Relaxed Sphere Tracing

Also called: Keinert et al. sphere tracing

## Overview
Relaxed sphere tracing is a ray marching technique that accelerates the convergence of standard sphere tracing by scaling the conservative step size by a relaxation factor, allowing the ray to traverse empty space more quickly [S1, S2, unofficial]. It solves the performance bottleneck of standard sphere tracing in large empty volumes by reducing the number of iterations required to reach a surface, while maintaining safety by reverting to the standard step size if the unbounding spheres of consecutive steps become disjoint [S1, unofficial]. It is distinguished from [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by its adaptive, distance-field-driven step sizing, and from [Enhanced Sphere Tracing](1674-sphere-tracing.md) by its simpler geometric fallback logic which may result in smaller steps near complex geometry [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin $\mathbf{p}$, normalized ray direction $\mathbf{v}$ ($|\mathbf{v}|=1$), Signed Distance Field Estimate (SDFE) function $f$, relaxation parameter $\omega$, maximum iteration count $i_{max}$, and termination threshold $\epsilon$ (implied by "not too small").
*   **Outputs:** Total distance traveled $t$ along the ray.

**Data Structures:**
*   Scalar variables: $t$ (current distance), $r_i$ (SDF value at previous step), $r_{i+1}$ (SDF value at current step), $d_i$ (step size), $i$ (iteration counter).
*   No complex data structures; state is maintained in local scalars.

**Parameters:**
*   $\omega$: Relaxation factor. A typical value is $0.6$, resulting in a step size multiplier of $1.6$ [S2, unofficial].

**Algorithm Steps:**
1.  Initialize $t = 0$, $i = 0$, $r_i = 0$, $r_{i+1} = \infty$ (or a value $> 1$ to ensure first step is taken), and loop.
2.  Calculate the relaxed step size: $d_i = r_i + \omega \cdot r_i = r_i(1 + \omega)$.
3.  Sample the SDF at the new position: $\mathbf{p}_{new} = \mathbf{p} + (t + d_i)\mathbf{v}$. Compute $r_{i+1} = f(\mathbf{p}_{new})$.
4.  **Safety Check:** If the new SDF value $r_{i+1}$ is too small such that the unbounding spheres of the previous step (radius $r_i$) and the current step (radius $r_{i+1}$) are disjoint (i.e., $r_i + r_{i+1} < d_i$), the ray might have skipped the surface. In this case, revert to the conservative step size:
    *   Set $d_i = r_i$.
    *   Re-sample the SDF at the conservative position: $\mathbf{p}_{new} = \mathbf{p} + (t + d_i)\mathbf{v}$.
    *   Compute $r_{i+1} = f(\mathbf{p}_{new})$.
5.  Update the total distance: $t = t + d_i$.
6.  Update previous radius: $r_i = r_{i+1}$.
7.  Increment iteration counter $i$.
8.  Terminate if $i \ge i_{max}$ or if $r_{i+1}$ is "too small" (indicating surface hit or escape, typically $|r_{i+1}| < \epsilon$ or $r_{i+1} \le 0$ for SDFs) [S1, unofficial].

**Pseudocode:**
```python
def relaxed_sphere_tracing(ray_origin, ray_direction, sdf_func, max_iterations, omega, epsilon):
    """
    Implements Relaxed Sphere Tracing as described by Keinert et al.
    
    Args:
        ray_origin (vec3): Origin of the ray p.
        ray_direction (vec3): Normalized direction v.
        sdf_func (func): Signed Distance Field function f.
        max_iterations (int): Maximum number of steps i_max.
        omega (float): Relaxation factor (e.g., 0.6).
        epsilon (float): Termination threshold for "too small".
        
    Returns:
        float: Total distance traveled t.
    """
    t = 0.0
    i = 0
    
    # Initial state: r_i is the SDF at the previous point.
    # For the first step, we need a valid r_i. 
    # Standard sphere tracing starts with r_0 = f(p). 
    # The source algorithm initializes r_i = 0 and r_{i+1} = infinity (or large value)
    # to force the first step calculation, but logically the first step 
    # should be based on f(p). We adapt to standard practice for the first step 
    # while keeping the relaxation logic for subsequent steps.
    
    # Evaluate initial position
    current_pos = ray_origin
    r_prev = sdf_func(current_pos)
    
    # If already hit or escaped, return
    if abs(r_prev) < epsilon or r_prev <= 0:
        return t

    for i in range(max_iterations):
        # Step 1: Calculate relaxed step size
        # d_i = r_i * (1 + omega)
        step_size = r_prev * (1.0 + omega)
        
        # Step 2: Sample at new position
        next_pos = current_pos + ray_direction * step_size
        r_curr = sdf_func(next_pos)
        
        # Step 3: Safety Check (Disjoint Unbounding Spheres)
        # Condition: r_prev + r_curr < step_size
        # If disjoint, revert to conservative step size (standard sphere tracing step)
        if r_prev + r_curr < step_size:
            step_size = r_prev
            next_pos = current_pos + ray_direction * step_size
            r_curr = sdf_func(next_pos)
            
        # Step 4: Update distance and position
        t += step_size
        current_pos = next_pos
        r_prev = r_curr
        
        # Step 5: Termination Check
        # "not too small" implies hitting the surface or escaping
        if abs(r_prev) < epsilon or r_prev <= 0:
            break
            
    return t
```

**Edge Cases and Pitfalls:**
*   **Disjoint Spheres:** The primary pitfall is skipping the surface if $\omega$ is too large. The fallback mechanism is critical; without it, the algorithm is not robust [S1, S2, unofficial].
*   **Initial Step:** The source pseudocode initializes $r_i=0$ and $r_{i+1}=\infty$, which is a logical artifact to start the loop. In implementation, the first step must be based on the SDF value at the ray origin $f(\mathbf{p})$ to ensure correctness [S1, unofficial].
*   **Precision:** Floating-point precision errors in the disjoint check ($r_i + r_{i+1} < d_i$) may cause unnecessary fallbacks or missed safety checks. A small tolerance may be needed [G].

## Subtopics

### Enhanced Sphere Tracing
A variant that optimally approximates planar surfaces by ensuring consecutive unbounding spheres are tangential rather than just intersecting. It is decisively better in performance metrics (error-decrease velocity) than relaxed sphere tracing, especially for scenes with many planar surfaces. [Enhanced Sphere Tracing](1674-sphere-tracing.md)

### Standard Sphere Tracing
The baseline method where step size is exactly equal to the SDF value ($d_i = r_i$). Relaxed sphere tracing is a direct optimization of this method [S2, unofficial]. [Sphere Tracing](1674-sphere-tracing.md)

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of iterations. $N$ is typically significantly lower than standard sphere tracing in empty space due to larger steps, but may be similar near complex geometry due to fallbacks.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Performance:** Provides a performance increase over standard sphere tracing, particularly in scenes with large empty volumes [S2, unofficial]. However, it is outperformed by Enhanced Sphere Tracing in terms of error-decrease velocity across all iteration counts [S1, unofficial].
*   **Strengths:** Simple to implement; significant speedup in empty space; robust against skipping surfaces via fallback.
*   **Limitations:** Performance degrades near complex geometry where fallbacks are frequent; less optimal than Enhanced Sphere Tracing for planar surfaces [S1, unofficial].

## Background
Relaxed sphere tracing was introduced by Keinert et al. in 2014 [S1, S2, unofficial]. It was later used in the Claybook project to implement real-time simulation-based computer games [S2, unofficial]. The method was analyzed and compared against standard and enhanced sphere tracing by Csaba Bálint and Gábor Valasek in 2018 [S1, unofficial].
