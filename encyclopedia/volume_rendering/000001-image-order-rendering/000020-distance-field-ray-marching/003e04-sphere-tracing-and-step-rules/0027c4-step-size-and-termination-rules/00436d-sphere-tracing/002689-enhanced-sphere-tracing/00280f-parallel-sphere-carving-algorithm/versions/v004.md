# Parallel Sphere Carving Algorithm


## Overview
The Parallel Sphere Carving Algorithm is a method for automatically computing tight bounding volumes for objects defined by a conservative signed distance field (SDF). It solves the problem of accelerating implicit surface queries (such as sphere tracing or polygonization) by generating a lightweight bounding proxy function $f_e$ that avoids expensive SDF evaluations outside the object. Unlike sphere tracing, which discards empty segments along a ray to find an intersection, Sphere Carving discards empty volumes (spheres) in space to find a bounding volume of the surface. It is agnostic of the function representation, requiring only a conservative SDF query, and provides strict bounding guarantees that neural or interval-arithmetic methods may lack.

## How it works
The algorithm iteratively carves an initial large bounding volume $V_0$ using spheres defined by the SDF, extracting intersection points to compute a bounding volume. The process is parallelized into four kernels per iteration.

**Inputs and Outputs:**
*   **Input:** A conservative signed distance field function $f: \mathbb{R}^3 \to \mathbb{R}$, where $|f(p)| \le d(p, \partial \mathcal{O})$. An initial large bounding volume $V_0$ (typically an icosphere). A distance threshold $\tau$ (typical value: 0.1).
*   **Outputs:** A set of empty spheres $S$ and a point set $P$ whose convex hull bounds the object surface $\partial \mathcal{O}$.

**Data Structures:**
*   $S$: Array of spheres, where each sphere is defined by center $c$ and radius $r$.
*   $P$: Array of 3D points.
*   $P'$: Temporary array of intermediate intersection points.
*   $pairs$: Array of sphere index pairs $(a, b)$.
*   All arrays are pre-allocated with sufficient memory. Parallel updates to arrays require atomic counters.

**The Empty Sphere Criterion:**
For any point $p$, the sphere $S(p, |f(p)|)$ does not intersect the object's surface $\partial \mathcal{O}$:
$$ \forall \mathbf{p} \in \mathbb{R}^3 \ S(\mathbf{p}, |f(\mathbf{p})|) \cap \partial \mathcal{O} = \emptyset $$

**Algorithm Steps:**

1.  **Initialization:**
    *   Sample points $P$ on the surface of $V_0$.
    *   Create initial sphere set $S_0 = \{ \text{sphere}(p, |f(p)|) \mid p \in P \}$.
    *   Verify coverage: For an icosphere, ensure every triangle $\Delta(a,b,c)$ is contained in the union of spheres at its vertices: $\Delta(a,b,c) \subset S(a) \cup S(b) \cup S(c)$. If not, increase subdivision.

2.  **Iteration Loop:**
    While $\max_{p \in P} |f(p)| > \tau$:
    *   **Kernel 1 (Gather Pairs):** Identify intersecting sphere pairs.
    *   **Kernel 2 (Compute Intersections):** Calculate 3-sphere intersections (trilateration) for triplets.
    *   **Kernel 3 (Filter Points):** Discard points inside the current sphere set.
    *   **Kernel 4 (Augment Spheres):** Add new spheres based on filtered points.

**Parameters:**
*   $\tau$: Distance threshold for stopping. Typical value: 0.1.
*   $V_0$: Initial volume. Size: Usually two orders of magnitude larger than the object.

**Edge Cases and Pitfalls:**
*   **Conservative SDFs:** Underestimating distance causes slow convergence and high computational cost due to $O(n^3)$ intersection calculations and many spheres.
*   **Overestimated SDFs:** Break the bounding guarantee. The algorithm progresses, but the result is not guaranteed to bound the object.
*   **Initialization Coverage:** The initial sphere set $S_0$ must cover the entire surface of $V_0$. For an icosphere, this is checked per triangle.
*   **Precision:** Filtering points inside the sphere set volume accounts for floating-point precision by discarding a point if its distance to any sphere center is less than the sphere radius.

## Subtopics

### Icosphere Initialization
A strategy for initializing the Sphere Carving algorithm using a recursively subdivided icosahedron (icosphere) as the initial bounding volume $V_0$. It is chosen because sampling is straightforward (using vertices) and the coverage constraint can be checked per triangle $\Delta(a,b,c)$ using only the spheres at its vertices. If the triangle is not contained in the union of the spheres at its vertices, the subdivision level is increased.

## Operating characteristics
*   **Time Complexity:** The complexity of the sphere intersection routine is $O(n^3)$, where $n$ is the number of spheres, due to evaluating every possible triplet of sphere intersections.
*   **Memory Complexity:** Compact representation. The bounding volume is stored as a set of convex polyhedra or ellipsoids, which is more memory-efficient than external acceleration structures like grids or octrees.
*   **Performance:** Requires a small number of field function queries (#f), from a few thousand for complex objects to less than one hundred for an exact SDF. The algorithm typically converges in less than 20 iterations.
*   **Strengths:** Agnostic of function representation; provides strict bounding guarantees; terminates in seconds; no training time required.
*   **Limitations:** Computationally intensive for overly conservative SDFs (underestimated distances), which require more iterations and spheres. Overly conservative functions may require a larger initial volume or denser sampling.

## Background
Sphere Carving was introduced by Hugo Schott, Theo Thonat, Thibaud Lambert, Eric Guérin, and Axel Paris. It is designed to accelerate queries in sphere tracing, polygonization, and simulation by generating a bounding proxy signed distance function $f_e$. The method draws inspiration from techniques that carve space using empty spheres, similar to how sphere tracing discards empty segments. It is particularly useful for procedurally defined implicit surfaces such as exact or Lipschitz functions, BlobTrees, or neural representations.
