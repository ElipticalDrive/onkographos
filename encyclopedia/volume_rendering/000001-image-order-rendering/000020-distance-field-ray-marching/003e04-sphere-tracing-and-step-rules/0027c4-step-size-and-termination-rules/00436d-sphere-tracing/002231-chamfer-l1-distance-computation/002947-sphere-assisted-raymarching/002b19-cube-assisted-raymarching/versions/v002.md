# Cube Assisted Raymarching
Also called: Cube Assisted
## Overview
Cube Assisted Raymarching is a distance-field ray marching technique that stores the size of the largest empty cube centered at each voxel instead of the largest empty sphere [S1, unofficial][S2, unofficial]. It solves the problem of slow shape data generation in Sphere Assisted Raymarching by trading some step optimality for significantly faster preprocessing [S1, unofficial][S2, unofficial]. While Sphere Assisted Raymarching provides optimal step sizes, Cube Assisted Raymarching is an order of magnitude faster to compute the shape data, making it suitable for larger voxel grids where preprocessing time is a bottleneck [S1, unofficial][S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A 3D voxel grid indicating occupancy.
- Output: A shape texture where each voxel stores the side length of the largest empty cube centered at that voxel [S1, unofficial].

**Data Structures:**
1. **Voxel Grid:** A 3D array of occupancy values (e.g., 0 for empty, 1 for solid) [G].
2. **Summed Area Table (SAT):** A 3D array of the same dimensions as the voxel grid, storing the cumulative sum of occupancy values from the origin to each coordinate [S1, unofficial][S2, unofficial].
3. **Shape Texture:** A 3D array storing the computed cube side lengths [S1, unofficial].

**Numbered Steps:**
1. **Compute Summed Area Table:** Iterate through the voxel grid and compute the SAT [S1, unofficial][S2, unofficial].
2. **Binary Search for Cube Size:** For each empty voxel, perform a binary search to find the maximum side length `s` such that a cube of side `s` centered at that voxel contains no solid voxels [S1, unofficial][S2, unofficial].
3. **Store Result:** Store the maximum valid `s` in the shape texture for each voxel [S1, unofficial].

**Formulas:**
- **SAT Computation:** The 3D prefix sum is computed as:
  $$ SAT[x][y][z] = V[x][y][z] + SAT[x-1][y][z] + SAT[x][y-1][z] + SAT[x][y][z-1] - SAT[x-1][y-1][z] - SAT[x-1][y][z-1] - SAT[x][y-1][z-1] + SAT[x-1][y-1][z-1] $$
  where $V[x][y][z]$ is the occupancy value and out-of-bounds indices return 0 [G].
- **Cube Area Check using SAT:** The number of solid voxels in a box defined by corners $(x_1, y_1, z_1)$ and $(x_2, y_2, z_2)$ is computed in $O(1)$ time:
  $$ Count = SAT[x_2][y_2][z_2] - SAT[x_1-1][y_2][z_2] - SAT[x_2][y_1-1][z_2] - SAT[x_2][y_2][z_1-1] + SAT[x_1-1][y_1-1][z_2] + SAT[x_1-1][y_2][z_1-1] + SAT[x_2][y_1-1][z_1-1] - SAT[x_1-1][y_1-1][z_1-1] $$
  The cube is empty if $Count == 0$ [G].
- **Cube Boundaries:** For a cube of side $s$ centered at $(cx, cy, cz)$, the inclusive integer boundaries are:
  $$ x_1 = cx - \lfloor s/2 \rfloor, \quad x_2 = cx + \lfloor (s-1)/2 \rfloor $$
  $$ y_1 = cy - \lfloor s/2 \rfloor, \quad y_2 = cy + \lfloor (s-1)/2 \rfloor $$
  $$ z_1 = cz - \lfloor s/2 \rfloor, \quad z_2 = cz + \lfloor (s-1)/2 \rfloor $$
  [G]

**Pseudocode:**
```python
def compute_sat(voxel_grid, dims):
    Dx, Dy, Dz = dims
    sat = [[[0] * Dz for _ in range(Dy)] for _ in range(Dx)]
    for x in range(Dx):
        for y in range(Dy):
            for z in range(Dz):
                val = voxel_grid[x][y][z]
                sat[x][y][z] = val
                if x > 0: sat[x][y][z] += sat[x-1][y][z]
                if y > 0: sat[x][y][z] += sat[x][y-1][z]
                if z > 0: sat[x][y][z] += sat[x][y][z-1]
                if x > 0 and y > 0: sat[x][y][z] -= sat[x-1][y-1][z]
                if x > 0 and z > 0: sat[x][y][z] -= sat[x-1][y][z-1]
                if y > 0 and z > 0: sat[x][y][z] -= sat[x][y-1][z-1]
                if x > 0 and y > 0 and z > 0: sat[x][y][z] += sat[x-1][y-1][z-1]
    return sat

def get_box_solid_count(sat, x1, y1, z1, x2, y2, z2, dims):
    Dx, Dy, Dz = dims
    def get_sat(x, y, z):
        if x < 0 or y < 0 or z < 0: return 0
        if x >= Dx or y >= Dy or z >= Dz: return 0
        return sat[x][y][z]
    return (get_sat(x2, y2, z2)
            - get_sat(x1-1, y2, z2)
            - get_sat(x2, y1-1, z2)
            - get_sat(x2, y2, z1-1)
            + get_sat(x1-1, y1-1, z2)
            + get_sat(x1-1, y2, z1-1)
            + get_sat(x2, y1-1, z1-1)
            - get_sat(x1-1, y1-1, z1-1))

def compute_cube_assisted_shape(voxel_grid, dims):
    Dx, Dy, Dz = dims
    sat = compute_sat(voxel_grid, dims)
    shape = [[[0] * Dz for _ in range(Dy)] for _ in range(Dx)]
    max_dim = max(Dx, Dy, Dz)
    for x in range(Dx):
        for y in range(Dy):
            for z in range(Dz):
                if voxel_grid[x][y][z] == 1:
                    shape[x][y][z] = 0
                    continue
                low, high, best_s = 1, max_dim, 0
                while low <= high:
                    s = (low + high) // 2
                    x1, x2 = x - (s // 2), x + ((s - 1) // 2)
                    y1, y2 = y - (s // 2), y + ((s - 1) // 2)
                    z1, z2 = z - (s // 2), z + ((s - 1) // 2)
                    if x1 < 0 or x2 >= Dx or y1 < 0 or y2 >= Dy or z1 < 0 or z2 >= Dz:
                        high = s - 1
                        continue
                    if get_box_solid_count(sat, x1, y1, z1, x2, y2, z2, dims) == 0:
                        best_s = s
                        low = s + 1
                    else:
                        high = s - 1
                shape[x][y][z] = best_s
    return shape
```

**Edge Cases and Pitfalls:**
- **Boundary Conditions:** Cubes extending beyond the voxel grid boundaries are invalid and must be rejected during the binary search [G].
- **Degenerate Input:** A single solid voxel in a large empty grid is used as a test case to demonstrate algorithm behavior [S1, unofficial].
- **Precision:** The SAT uses integer sums, providing exact empty-space checks for binary voxel grids [G].

## Operating characteristics
- **Time Complexity:** Upfront shape data generation is $O(n \log n)$, where $n$ is the number of voxels [S1, unofficial][S2, unofficial]. This improves upon the $O(n^2)$ complexity of a simple sphere-assisted implementation [S1, unofficial][S2, unofficial].
- **Measured Performance:** On a 32x32x32 voxel test set, Cube Assisted Raymarching computed shape data an order of magnitude faster than Sphere Assisted Raymarching [S1, unofficial][S2, unofficial]. Render times were close on smaller sets, but Plane Marching showed a moderate lead as set size increased [S1, unofficial][S2, unofficial].
- **Strengths:** Significantly faster preprocessing than Sphere Assisted Raymarching while still providing large steps through empty space [S1, unofficial][S2, unofficial].
- **Limitations:** Slightly suboptimal step sizes compared to Sphere Assisted Raymarching [S1, unofficial][S2, unofficial].
- **When to Use:** When preprocessing time is a bottleneck and the slight loss in step optimality is acceptable [G].
- **When Not to Use:** When optimal step sizes are critical and preprocessing time is not a concern [G].

## Background
Cube Assisted Raymarching was introduced by Caleb Leak in his blog post "Raymarching Voxel Rendering" [S1, unofficial][S2, unofficial]. It was developed as an optimization to Sphere Assisted Raymarching, which suffered from high upfront computational cost [S1, unofficial][S2, unofficial]. The technique leverages Summed Area Tables, a data structure common in computer vision, to enable fast empty space queries [S1, unofficial][S2, unofficial].
