# Uniform Sphere Tracing

Also called: Ray Marching for Volumes, Uniform Density Volume Rendering, Volume Rendering with Ray Marching (Uniform Sphere)

## Overview
Uniform Sphere Tracing is a volume rendering technique that computes the optical depth and color contribution of a homogeneous medium along a camera ray by analytically integrating the Beer-Lambert law over the intersection segment [S1, unofficial]. It differs from discrete ray marching methods by treating the volume as a continuous, uniform entity defined by geometric primitives (e.g., spheres), calculating the exact path length through the volume rather than sampling it at fixed intervals [S1, unofficial]. This approach provides an exact solution for absorption and uniform scattering for simple convex shapes without discretization error [S1, unofficial].

## How it works
**Inputs and Outputs**
*   **Inputs**: Camera ray origin $\mathbf{o}$, normalized ray direction $\mathbf{d}$, volume primitive definition (e.g., sphere center $\mathbf{c}$, radius $r$, absorption coefficient $\sigma_a$, scatter color $\mathbf{C}_{vol}$), and background color $\mathbf{C}_{bg}$ [S1, unofficial].
*   **Outputs**: Final pixel color $\mathbf{C}_{final}$ [S1, unofficial].

**Data Structures**
The volume is represented by a primitive class (e.g., `Sphere`) containing:
*   `center`: `vec3` (32-bit float vector), the geometric center of the volume [S1, unofficial].
*   `radius`: `float` (32-bit float), the radius of the volume [S1, unofficial].
*   `sigma_a`: `float` (32-bit float), the absorption coefficient [S1, unofficial].
*   `scatter`: `vec3` (32-bit float vector), the color of light scattered by the volume [S1, unofficial].

**Algorithm Steps**
1.  **Ray-Primitive Intersection**: Compute the intersection of the ray $\mathbf{r}(t) = \mathbf{o} + t\mathbf{d}$ with the volume primitive. For a sphere, solve the quadratic equation derived from $\|\mathbf{o} + t\mathbf{d} - \mathbf{c}\|^2 = r^2$ [S1, unofficial].
    *   If no intersection exists ($t < 0$ or discriminant $< 0$), return $\mathbf{C}_{bg}$ [S1, unofficial].
    *   If intersection exists, identify the entry distance $t_0$ and exit distance $t_1$ (the two positive roots, sorted such that $t_0 < t_1$) [S1, unofficial].
2.  **Path Length Calculation**: Calculate the distance $d$ the ray travels through the volume. Since $\mathbf{d}$ is normalized, $d = t_1 - t_0$ [S1, G, unofficial].
3.  **Transmission Calculation**: Compute the transmission $T$ using Beer's Law:
    $$ T = e^{-d \cdot \sigma_a} $$
    where $d$ is the path length and $\sigma_a$ is the absorption coefficient [S1, unofficial].
4.  **Color Blending**: Combine the attenuated background color and the volume's scattered color:
    $$ \mathbf{C}_{final} = T \cdot \mathbf{C}_{bg} + (1 - T) \cdot \mathbf{C}_{vol} $$
    This assumes the volume scatters light uniformly with color $\mathbf{C}_{vol}$ and ignores complex lighting interactions like internal shadows or directional illumination for this basic formulation [S1, unofficial].

**Pseudocode**
```python
import math

def uniform_sphere_trace(ray_origin, ray_direction, sphere, background_color):
    """
    ray_origin: vec3
    ray_direction: vec3 (normalized)
    sphere: object with attributes center (vec3), radius (float), sigma_a (float), scatter (vec3)
    background_color: vec3
    """
    # 1. Ray-Sphere Intersection
    oc = ray_origin - sphere.center
    a = dot(ray_direction, ray_direction) # Should be 1.0 if normalized
    b = 2.0 * dot(oc, ray_direction)
    c = dot(oc, oc) - sphere.radius * sphere.radius
    discriminant = b * b - 4 * a * c

    if discriminant < 0:
        return background_color

    sqrt_disc = math.sqrt(discriminant)
    t0 = (-b - sqrt_disc) / (2 * a)
    t1 = (-b + sqrt_disc) / (2 * a)

    # Ensure we are looking at the front face or valid segment
    if t0 < 0:
        t0 = t1
    if t0 < 0:
        return background_color # Ray starts inside or behind, simplified handling

    # 2. Path Length
    # Since ray_direction is normalized, distance is simply t1 - t0
    distance = t1 - t0

    # 3. Transmission (Beer's Law)
    transmission = math.exp(-distance * sphere.sigma_a)

    # 4. Color Blending
    final_color = transmission * background_color + (1.0 - transmission) * sphere.scatter

    return final_color
```

**Parameters**
*   $\sigma_a$ (Absorption Coefficient): Controls opacity. Typical value: $0.1$ [S1, unofficial].
*   $\mathbf{C}_{vol}$ (Scatter Color): The color of the volume. Typical value: $(0.8, 0.1, 0.5)$ [S1, unofficial].
*   $\mathbf{C}_{bg}$ (Background Color): The color behind the volume. Typical value: $(0.572, 0.772, 0.921)$ [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Normalized Direction**: The simplification $d = t_1 - t_0$ is valid only if $\mathbf{d}$ is normalized. If not, $d = \|\mathbf{p}_2 - \mathbf{p}_1\|$ must be used [S1, unofficial].
*   **Ray Origin Inside**: If the ray origin is inside the volume, $t_0$ may be negative. The logic must handle this to ensure the path length is calculated correctly from the entry point to the exit point [S1, G, unofficial].
*   **Tangential Rays**: If the discriminant is zero, the ray is tangent. The path length is zero, and transmission is 1.0 [S1, G, unofficial].

## Subtopics

### [Spectral Tracking](4664-spectral-tracking.md)
Handles per-wavelength optical properties by decomposing coefficients and using a single majorant density, reducing tracker invocations compared to naive delta tracking.

### [Auto-Relaxed Sphere Tracing](9468-auto-relaxed-sphere-tracing.md)
Automatically scales step sizes based on previous iterations using a scalar hyperparameter, reducing invalid step sizes and fallbacks compared to fixed step rules.

## Operating characteristics
*   **Time Complexity**: $O(1)$ per pixel for simple primitives like spheres, as it involves a constant number of arithmetic operations and a square root [S1, unofficial].
*   **Memory Complexity**: $O(1)$, requiring only storage for the primitive parameters and temporary variables [S1, unofficial].
*   **Strengths**: Exact solution for homogeneous volumes; no discretization error; computationally efficient for simple shapes [S1, unofficial].
*   **Limitations**: Limited to simple geometric primitives or analytically intersectable volumes; does not handle complex lighting (shadows, reflections) within the volume in its basic form [S1, unofficial].
*   **When to Use**: Rendering simple, homogeneous volumes like clouds, smoke, or glass spheres where exact absorption is required and geometry is simple [S1, unofficial].
*   **When Not to Use**: Complex heterogeneous volumes, volumes with complex internal lighting, or non-convex geometries where analytical intersection is difficult [S1, unofficial].
