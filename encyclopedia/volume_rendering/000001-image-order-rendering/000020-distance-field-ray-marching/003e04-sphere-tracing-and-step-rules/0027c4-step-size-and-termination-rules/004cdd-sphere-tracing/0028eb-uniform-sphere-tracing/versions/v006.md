# Uniform Sphere Tracing

Also called: Ray Marching for Volumes, Rustgpu Sphere Tracing Implementation, Uniform Density Volume Rendering, Volume Rendering with Ray Marching (Uniform Sphere)

## Overview
Uniform Sphere Tracing is a volume rendering technique that combines distance-field ray marching with Beer-Lambert attenuation to render homogeneous media. It solves the problem of calculating the color contribution of a participating medium along a camera ray by stepping through the volume using a fixed or clamped step size derived from a Signed Distance Function (SDF) [S1, S2, unofficial]. Unlike adaptive methods, it uses a uniform step rule constrained by `min_step` and `max_step` parameters, making it distinct from its siblings [Zeno Implementation](1544-zeno-implementation.md) and [Differentiable Sphere Tracing](2316-differentiable-sphere-tracing.md) which may employ different step heuristics or gradient-based optimizations.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera origin $\mathbf{o}$, normalized ray direction $\mathbf{d}$, SDF evaluator function $f(\mathbf{p})$, maximum iterations $N_{max}$, minimum step $s_{min}$, maximum step $s_{max}$, convergence cutoff $\epsilon$, absorption coefficient $\sigma_a$, volume scatter color $C_{vol}$, and background color $C_{bg}$.
*   **Outputs:** Final pixel color $C_{final}$ and a boolean indicating if the SDF surface was hit.

**Data Structures:**
The SDF evaluator is typically a closure or function pointer taking a 3D position $\mathbf{p}$, iteration count, and prior distance, returning a scalar distance $d$ [S1, unofficial]. The volume object (e.g., a sphere) stores $\sigma_a$, $C_{vol}$, geometric center, and radius [S2, unofficial].

**Algorithm Steps:**
1.  **Initialization:** Set accumulated distance $t \leftarrow \epsilon$ (or a small near-plane value, e.g., $0.0001$) [S1, unofficial]. Set iteration counter $i \leftarrow 0$ [S1, unofficial]. Set hit flag $hit \leftarrow \text{false}$ [S1, unofficial].
2.  **Marching Loop:** While $i < N_{max}$:
    a.  **Position Update:** Compute current position $\mathbf{p} = \mathbf{o} + t \mathbf{d}$ [S1, unofficial].
    b.  **SDF Evaluation:** Evaluate $d = f(\mathbf{p})$ [S1, unofficial].
    c.  **Step Clamping:** Calculate step size $\Delta t = \text{clamp}(d, s_{min}, s_{max})$ [S1, unofficial].
    d.  **Advance:** Update $t \leftarrow t + \Delta t$ [S1, unofficial].
    e.  **Termination Check:** If $d \le \epsilon$, set $hit \leftarrow \text{true}$ and break loop [S1, unofficial].
    f.  **Iteration:** Increment $i \leftarrow i + 1$ [S1, unofficial].
3.  **Volume Integration:** If the ray intersects the volume bounds (determined by SDF hit or explicit geometric intersection), calculate the total distance $L$ traveled through the volume [S2, unofficial].
    *   If the volume is a simple primitive like a sphere, $L$ is the distance between entry point $\mathbf{p}_1$ and exit point $\mathbf{p}_2$ [S2, unofficial].
    *   Calculate transmittance $T = e^{-L \cdot \sigma_a}$ using Beer's Law [S2, unofficial].
4.  **Color Blending:** Compute final color:
    $$ C_{final} = T \cdot C_{bg} + (1 - T) \cdot C_{vol} $$
    [S2, unofficial]. If the ray did not hit the volume or SDF surface, return $C_{bg}$ [S2, unofficial].

**Pseudocode:**
```python
def uniform_sphere_tracing(ray_origin, ray_dir, sdf_func, sigma_a, vol_color, bg_color, 
                           iter_max=1000, min_step=0.0001, max_step=1.0, cutoff=0.001):
    """
    ray_origin: Vec3, camera origin
    ray_dir: Vec3, normalized direction
    sdf_func: function(p, iter, prior_d) -> float, SDF evaluator
    sigma_a: float, absorption coefficient
    vol_color: Vec3, volume scatter color
    bg_color: Vec3, background color
    """
    t = 0.0001  # Initial distance offset [S1, unofficial]
    hit_sdf = False
    
    for i in range(iter_max):
        # 1. Update position [S1, unofficial]
        current_pos = ray_origin + t * ray_dir
        
        # 2. Evaluate SDF [S1, unofficial]
        increment = sdf_func(current_pos, i, 0.0)
        
        # 3. Clamp step and advance [S1, unofficial]
        # Note: increment is clamped to [min_step, max_step]
        step = max(min_step, min(max_step, increment))
        t += step
        
        # 4. Check for surface hit [S1, unofficial]
        if increment <= cutoff:
            hit_sdf = True
            break
            
    # 5. Volume Rendering Calculation [S2, unofficial]
    # For a simple sphere, we calculate intersection to get path length L
    # If using pure SDF marching for volume density, L is approximated by t 
    # or calculated via explicit geometric bounds if available [S2, unofficial].
    # Here we assume explicit intersection for accurate L as per [S2, unofficial] logic for spheres.
    
    # Simplified: If the SDF hit indicates we are inside/on the volume,
    # we need the path length through the volume. 
    # In the provided Rust example [S1, unofficial], the SDF is used for marching, 
    # but the Beer's law application [S2, unofficial] requires the chord length.
    # Assuming the SDF defines the volume boundary:
    
    if hit_sdf:
        # Calculate distance through volume. 
        # For a sphere of radius R centered at C, intersected by ray (O, D):
        # L = 2 * sqrt(R^2 - |O - C|^2 + (dot(O-C, D))^2) 
        # Or simply t1 - t0 from quadratic intersection [S2, unofficial].
        # Since exact geometry isn't passed to sdf_func in [S1, unofficial], 
        # we assume L is derived from the marching distance or explicit bounds.
        # For the purpose of this generic method, L is the distance traveled 
        # within the medium. If the SDF represents the volume boundary,
        # the path length L can be approximated by the distance from entry to current_pos.
        
        # Using the formula from [S2, unofficial] for a sphere intersection:
        # Let's assume we have entry/exit points p1, p2.
        # distance = (p2 - p1).length()
        
        # Generic implementation using marching distance as proxy for L 
        # if explicit geometry is not separate from SDF:
        L = t 
        
        transmission = exp(-L * sigma_a)
        final_color = transmission * bg_color + (1.0 - transmission) * vol_color
        return final_color, hit_sdf
    else:
        return bg_color, False
```

**Parameters:**
*   `sigma_a`: Absorption coefficient. Typical value: $0.1$ [S2, unofficial].
*   `vol_color`: Scatter color. Typical value: $(0.8, 0.1, 0.5)$ [S2, unofficial].
*   `bg_color`: Background color. Typical value: $(0.572, 0.772, 0.921)$ [S2, unofficial].
*   `min_step`, `max_step`: Step size bounds. In the Rust example, `max_step` was capped at $0.001$ to prevent overshooting, effectively turning it into ray marching [S1, unofficial].
*   `cutoff`: Convergence threshold. Typical value: $0.001$ [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Scaling Errors:** Scaling the input position vector passed to the SDF (e.g., `*v * 10.`) without adjusting the step size or SDF output breaks the sphere tracing property, causing the ray to overshoot collisions [S1, unofficial].
*   **Step Clamping:** If `max_step` is too large relative to the SDF's local distance field accuracy, the ray may skip over thin volume boundaries or surfaces [S1, unofficial].
*   **Normalized Rays:** The distance calculation $t_1 - t_0$ is valid only if the ray direction is normalized [S2, unofficial].

## Subtopics

### [Spectral Tracking](4664-spectral-tracking.md)
Handles per-wavelength optical properties by using a single majorant density to drive sampling for all wavelengths simultaneously, reducing tracker invocations compared to naive delta tracking.

### [Auto-Relaxed Sphere Tracing](9468-auto-relaxed-sphere-tracing.md)
Automatically scales step sizes based on previous iteration data using a scalar hyperparameter, reducing invalid step sizes and minimizing fallback steps compared to uniform clamping.

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of iterations per ray, bounded by `iter_max` [S1, unofficial].
*   **Memory Complexity:** $O(1)$ per ray, as it only stores current position, distance, and counters [S1, unofficial].
*   **Performance:** The method is efficient for homogeneous volumes but can be slow if `max_step` is small to ensure precision, leading to many iterations [S1, unofficial].
*   **Strengths:** Simple to implement; robust for convex shapes defined by SDFs; provides physically plausible attenuation via Beer's Law [S2, unofficial].
*   **Limitations:** Uniform stepping is inefficient in sparse regions; sensitive to SDF scaling and step clamping parameters [S1, unofficial].

## Background
The method originates from the combination of sphere tracing techniques popularized in raymarching shaders [S1, unofficial] and volume rendering principles based on Beer-Lambert law [S2, unofficial]. The specific Rust implementation cited demonstrates the practical challenges of integrating SDF-based marching with volume attenuation, highlighting the difference between pure sphere tracing (surface hit) and volume marching (attenuation integration) [S1, S2, unofficial].
