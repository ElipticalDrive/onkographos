# Sphere Tracing

Also called: Hart's Sphere Tracing, SDF Tracing, SDF Sphere Tracing

## Overview
Sphere Tracing is an iterative ray-marching algorithm for rendering implicit surfaces defined by Signed Distance Functions (SDFs) or, more generally, Lipschitz continuous implicit functions [S1][S9, unofficial]. It solves the problem of finding the intersection between a ray and a surface without explicit polygonal geometry by stepping along the ray by a distance guaranteed not to overshoot the surface [S1][S7, unofficial]. Unlike [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md), which uses fixed intervals, Sphere Tracing adapts the step size to the local geometry, allowing it to skip empty space efficiently while maintaining robustness against pathological surfaces with discontinuous derivatives [S9, S11, unofficial].

## How it works
Sphere Tracing operates on the principle that the value of a distance function at a point provides a lower bound on the distance to the nearest surface. By stepping exactly this distance (or a scaled bound for non-SDFs), the algorithm ensures the marching sphere never penetrates the geometry [S1][S7, unofficial].

### Inputs and Outputs
*   **Inputs:**
    *   Ray origin $\mathbf{o}$ and unit direction $\mathbf{d}$ [S9, S30, unofficial].
    *   Implicit function $f: \mathbb{R}^3 \to \mathbb{R}$, which returns the distance to the nearest surface (positive outside, negative inside) [S24, S26, unofficial].
    *   Global Lipschitz constant $\lambda$ of $f$. For SDFs, $\lambda = 1$ [S1, S3].
    *   Termination parameters: convergence threshold $\epsilon$, maximum distance $t_{max}$, and maximum iterations $N_{max}$ [S4, S13, S30, unofficial].
*   **Outputs:**
    *   Intersection distance $t$ along the ray [S26, unofficial].
    *   Hit status (boolean or mask) indicating if a surface was found within $t_{max}$ [S6, S13, unofficial].

### Data Structures
The method typically operates on scalar values and 3D vectors. In batched implementations (e.g., GPU shaders), inputs are tensors of shape $(N, 3)$ for origins and directions, and outputs are tensors of shape $(N, 3)$ for points and $(N, 1)$ for masks [S6, unofficial].

### Numbered Steps
1.  **Initialization:** Set the current ray parameter $t = 0$ (or $t_{near}$) and iteration counter $i = 0$ [S13, S28, unofficial].
2.  **Position Calculation:** Compute the current 3D position $\mathbf{p}_i = \mathbf{o} + t \mathbf{d}$ [S13, S28, unofficial].
3.  **Function Evaluation:** Evaluate the implicit function at the current position: $d = f(\mathbf{p}_i)$ [S4, S13, unofficial].
    *   If $f$ is a general Lipschitz function with constant $\lambda$, the safe step size is $s = |d| / \lambda$ [S1].
    *   If $f$ is an SDF ($\lambda=1$), the step size is $s = |d|$ [S7, S30, unofficial].
4.  **Termination Check:**
    *   **Hit:** If $|d| < \epsilon$ (or $d < \epsilon$ for signed hits), the ray has converged to the surface. Return $t$ and hit status [S4, S13, S30, unofficial].
    *   **Miss/Escape:** If $t > t_{max}$, the ray has exited the scene. Return $t_{max}$ and miss status [S13, unofficial][S33].
    *   **Limit:** If $i \ge N_{max}$, stop to prevent infinite loops. Return current $t$ and miss status [S4, S13, unofficial].
5.  **Step Advance:** Update the ray parameter: $t \leftarrow t + s$ [S13, S28, unofficial].
6.  **Iteration:** Increment $i$ and repeat from Step 2 [S13, S28, unofficial].

### Formulas
*   **Ray Equation:** $\mathbf{p}(t) = \mathbf{o} + t \mathbf{d}$ [S9, S30, unofficial].
*   **Safe Step Size (SDB):** For a Lipschitz function $f$ with constant $\lambda$, the step size is $s = \frac{|f(\mathbf{p})|}{\lambda}$ [S1]. This is called a Signed Distance Bound (SDB).
*   **SDF Step Size:** For an SDF, $\lambda = 1$, so $s = |f(\mathbf{p})|$ [S1][S7, unofficial].
*   **Convergence:** The algorithm terminates when $|f(\mathbf{p}_i)| \le \epsilon$ [S30, unofficial].

### Parameters
*   **$\epsilon$ (Convergence Threshold):** Typical values range from $10^{-4}$ to $10^{-6}$ [S5, S6, S13, unofficial]. Some implementations use a relative threshold, e.g., $0.001 \times t$ [S14, unofficial].
*   **$t_{max}$ (Max Distance):** Typical values are $100.0$ or $60.0$ depending on scene scale [S7, S13, S28, unofficial].
*   **$N_{max}$ (Max Iterations):** Typical values are $128$, $255$, or $1024$ [S5, S7, S13, S28, unofficial].
*   **$\lambda$ (Lipschitz Constant):** $1$ for SDFs; must be determined for other implicit functions [S1, S3].

### Edge Cases and Pitfalls
*   **Overshooting:** If $f$ is not Lipschitz continuous or $\lambda$ is underestimated, the step size may be too large, causing the ray to jump over the surface [S1, S8].
*   **Precision:** Near the surface, floating-point errors can cause oscillation or premature termination. Using a relative epsilon or a minimum step size can mitigate this [S14, unofficial][S8].
*   **Inside Geometry:** If the ray starts inside an object ($f(\mathbf{o}) < 0$), the algorithm may march away from the surface if not handled. Some implementations check for $f(\mathbf{p}) < 0$ to handle interior rendering or volume accumulation [S24, S31, unofficial].
*   **Gradients:** For normal estimation, central differences are used: $\mathbf{N} = \text{normalize}(f(\mathbf{p} + \epsilon \mathbf{e}_x) - f(\mathbf{p} - \epsilon \mathbf{e}_x), \dots)$ [S13, unofficial].

### Pseudocode
```python
def sphere_trace(ray_origin, ray_direction, implicit_fn, max_steps=128, max_dist=100.0, epsilon=1e-4):
    """
    Performs sphere tracing for a single ray.
    
    Args:
        ray_origin (vec3): The starting point of the ray.
        ray_direction (vec3): The unit direction vector of the ray.
        implicit_fn (function): A function f(p) returning the signed distance to the surface.
        max_steps (int): Maximum number of iterations.
        max_dist (float): Maximum distance to trace.
        epsilon (float): Convergence threshold.
        
    Returns:
        tuple: (hit_distance, hit_mask)
    """
    t = 0.0
    for i in range(max_steps):
        # 1. Calculate current position
        current_pos = ray_origin + ray_direction * t
        
        # 2. Evaluate implicit function
        dist = implicit_fn(current_pos)
        
        # 3. Check for convergence (Hit)
        if abs(dist) < epsilon:
            return t, True
        
        # 4. Check for escape (Miss)
        if t > max_dist:
            return max_dist, False
        
        # 5. Advance ray
        # For SDF, step size is exactly dist (assuming dist > 0 for outside)
        # If inside, we might want to step by abs(dist) or handle differently
        step_size = abs(dist)
        t += step_size
        
    # 6. Max iterations reached
    return t, False
```

## Operating characteristics
*   **Time Complexity:** Linear in the number of steps $N$. The number of steps depends on the scene complexity and the ray's path. Best case is $O(1)$ for empty space; worst case is $O(N)$ for grazing angles or complex geometry [S3][S30, unofficial].
*   **Memory Complexity:** $O(1)$ per ray, as it only stores current position and distance. No auxiliary data structures are required unless acceleration structures (like BVH or VDB) are used [S1][S30, unofficial].
*   **Performance:** Highly efficient for procedural SDFs and simple primitives. Performance degrades with increasing scene complexity if not accelerated [S1][S30, unofficial].
*   **Strengths:** Robust handling of pathological surfaces, no need for explicit mesh storage, natural antialiasing via cone tracing [S9, unofficial][S33].
*   **Limitations:** Slow convergence near surfaces or at grazing angles. Requires Lipschitz continuity [S1, S3].
*   **When to Use:** Procedural geometry, implicit surfaces, real-time rendering where memory is constrained [S11, S18, unofficial].
*   **When Not to Use:** Explicit polygonal meshes (use ray-triangle intersection), scenes with highly non-Lipschitz functions without adaptation [S1, S3].

## Background
Sphere Tracing was introduced by John C. Hart in 1994 [S9, unofficial][S33]. It was originally developed as a geometric method for the antialiased ray tracing of implicit surfaces, particularly height fields. The technique leverages the Lipschitz property of distance functions to guarantee convergence without overshooting. It has since become a cornerstone of implicit surface rendering, widely used in the demoscene, Shadertoy, and real-time graphics for its simplicity and robustness [S7, S11, S18, unofficial].
