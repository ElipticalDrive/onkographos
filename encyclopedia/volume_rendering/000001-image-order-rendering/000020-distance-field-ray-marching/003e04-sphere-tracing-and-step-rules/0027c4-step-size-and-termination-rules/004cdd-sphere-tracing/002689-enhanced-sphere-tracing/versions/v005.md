# Enhanced Sphere Tracing

Also called: Aggressive Marching, Aggressive Ray Marching, Aggressive Sphere Tracing, Bálint and Valasek method, Over-relaxed sphere tracing, Sphere tracing with over-relaxation

## Overview
Enhanced Sphere Tracing is a family of ray-marching optimizations that accelerate convergence toward implicit surfaces defined by Signed Distance Functions (SDFs) by taking steps larger than the strict Lipschitz bound or by predicting optimal step sizes based on local surface geometry [S1][S5, S7, unofficial]. It solves the performance bottleneck of standard sphere tracing, which becomes prohibitively slow when rays graze surfaces at shallow angles or when the surface is locally planar [S1][S5, unofficial]. Unlike standard sphere tracing, which uses the queried distance value as the step size, enhanced variants either over-relax the step size by a constant factor or infer the next step size from the previous two distance queries to approximate the surface as locally flat [S5, S7, unofficial].

## How it works
The term "Enhanced Sphere Tracing" refers to two distinct but related algorithmic strategies: **Aggressive/Over-relaxed Marching** (accelerating convergence via scalar multiplication) and **Geometric Enhancement** (predicting step size via historical data) [S1][S5, S7, unofficial]. Both require a conservative SDF (one that never overstates the distance to the surface) to ensure robustness [S3, S7, unofficial].

### Inputs and Outputs
*   **Input:** Ray origin $p \in \mathbb{R}^3$, ray direction $v \in \mathbb{R}^3$ (normalized, $|v|=1$), SDF query function $f: \mathbb{R}^3 \to \mathbb{R}$, maximum iteration count $i_{max}$, convergence threshold $\epsilon$, and method-specific parameters ($\alpha$, $\omega$, or $\sigma$) [S1][S5, S7, unofficial].
*   **Output:** Distance $t \in [0, +\infty)$ traveled along the ray to the surface, or a failure state if $i_{max}$ is exceeded [S5, S7, unofficial].

### Data Structures
*   **History State:** Stores the SDF values from the previous two steps ($r_{i-1}, r_i$) and the step size taken to reach the current step ($d_i$) [S5, S7, unofficial].
*   **Accumulator:** Total distance traveled $t$ [S5, S7, unofficial].

### Algorithm 1: Over-relaxed Marching (Keinert et al.)
This variant multiplies the safe step size by a factor $\omega > 1$ to accelerate convergence, particularly for grazing rays [S3, unofficial]. It requires a safety check to prevent skipping the surface if the SDF is non-conservative or the geometry is too thin [S3, unofficial].

**Parameters:**
*   $\omega$: Over-relaxation factor. Value 1.6 [S3, unofficial].
*   $\alpha$: Aggressive multiplier. Default 1.5. Range 1.2–1.8 [S1].
*   $\sigma$: Overstepping factor in $[0, 1]$. Typical value $\approx 1.2$ [S2].
*   $\lambda$: Global Lipschitz bound of the SDF [S2].

```python
def over_relaxed_sphere_tracing(p, v, f, omega=1.6, max_steps=1024, threshold=1e-5):
    t = 0.0
    for _ in range(max_steps):
        d = f(p + t * v)
        step = omega * abs(d)
        # Safety check: retreat if step overshoots the safe radius
        if step > abs(d):
            step = abs(d)
        t += step
        if abs(d) < threshold:
            return t
    return t
```

### Algorithm 2: Geometric Enhancement (Bálint & Valasek)
This variant assumes the surface is locally flat and calculates the optimal step size using the radii of the two previous unbounding spheres [S5, S7, unofficial]. It is more expensive per step than aggressive marching but converges faster on smooth surfaces [S5, S7, unofficial].

**Parameters:**
*   $\omega$: Relaxation parameter for locally concave regions. Range $\omega \in (0, 1]$ [S5, S7, unofficial]. Typical range $(0.7, 1]$ [S5, unofficial].

```python
def geometric_enhanced_sphere_tracing(p, v, f, omega=0.8, max_steps=1024, threshold=1e-5):
    t = 0.0
    r_prev = 0.0
    r_curr = 0.0
    r_next = float('inf')
    d_i = 0.0
    for i in range(max_steps):
        if r_next <= threshold:
            break
        # Calculate step size using geometric formula
        if d_i + r_prev - r_curr == 0:
            d_i = r_curr # Fallback for first step
        else:
            d_i = r_curr + omega * r_curr * (d_i - r_prev + r_curr) / (d_i + r_prev - r_curr)
        t += d_i
        r_next = f(p + t * v)
        # Safety check: fallback if spheres are disjoint
        if d_i > r_curr + r_next:
            d_i = r_curr
            t -= d_i # Backtrack
            t += d_i
            r_next = f(p + t * v)
        r_prev = r_curr
        r_curr = r_next
    return t
```

### Edge Cases and Pitfalls
*   **Thin Geometry:** Aggressive marching ($\alpha > 1$) can cause the ray to trespass two surfaces in a single step if the geometry is super thin, leaving the ray front end outside the shape and causing infinite marching or small holes [S1].
*   **Non-Conservative SDFs:** Over-relaxation is unsound if the SDF overstates the distance (is not 1-Lipschitz or conservative) [S3, unofficial]. The backtrack mechanism ensures a surface is never skipped, provided the field is conservative [S3, S7, unofficial].
*   **Non-Smooth Surfaces:** On fractals or non-smooth surfaces (e.g., Mandelbulb), the geometric enhancement provides only marginal improvement over basic sphere tracing, as the "locally flat" assumption fails [S5, unofficial].
*   **Grazing Incidence:** Standard sphere tracing is slow when the angle $\theta$ between the ray and surface normal is small [S1]. Enhanced methods mitigate this, but aggressive marching requires careful tuning of $\alpha$ to avoid instability [S1].

## Subtopics

### [Parallel Sphere Carving Algorithm](4165-parallel-sphere-carving-algorithm.md)
The Parallel Sphere Carving Algorithm is a method for automatically computing tight bounding volumes for objects defined by a conservative signed distance field (SDF). It solves the problem of accelerating implicit surface queries (such as sphere tracing or polygonization) by generating a lightweight bounding proxy function $f_e$ that avoids expensive SDF evaluations outside the object. Unlike sphere tracing, which discards empty segments along a ray to find an intersection, Sphere Carving discards empty volumes (spheres) in space to find a bounding volume of the surface. It is agnostic of the function representation, requiring only a conservative SDF query, and provides strict bounding guarantees that neural or interval-arithmetic methods may lack.

### Overstepping
A technique where you march a small distance further outside the Minimum Distance Sphere (MDS) edge to decrease the number of times marched, increasing performance [S9, unofficial]. March to the edge of the MDS, then march a small distance further outside. Compare the original MDS with the new MDS; if they overlap, continue marching further. If the two MDSs do not overlap, step back to the edge of the first MDS and continue normally [S9, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduces the number of SDF queries significantly compared to standard sphere tracing [S8, unofficial]. For grazing angles, the minimum number of steps $k$ decreases from $k_{std}$ to $k_{enh}$ [S1].
    *   Formula for aggressive marching convergence: $k > k_{min} = \frac{\log \epsilon - \log d}{\log |1 - \alpha \sin \theta|}$ [S1].
    *   Example: For $d=1.0, \epsilon=5 \times 10^{-5}, \theta=10^\circ$, steps decrease from 52 (conventional) to 33 (aggressive $\alpha=1.5$) [S1].
*   **Memory Complexity:** Low. Requires storing only a few scalar values ($t, r_{i-1}, r_i, d_i$) per ray [S5, S7, unofficial].
*   **Performance:**
    *   Aggressive marching with $\sigma \approx 1.2$ reduces field function queries by a factor of 1.2 and speeds up computation by the same factor [S2].
    *   Geometric enhancement (Bálint & Valasek) outperforms relaxed sphere tracing by up to 1.5 times on smooth surfaces and up to 50% better than Hart and Keinert et al.'s variant in error-decrease velocity [S5, S7, unofficial].
    *   On non-smooth surfaces (Mandelbulb), it performs slightly better than basic tracing but is on par with relaxed tracing within error margins [S5, unofficial].
*   **Strengths:** Faster convergence on planar/smooth surfaces [S5, S7, unofficial]; stabilizes training in neural rendering by allowing sampling behind the surface [S1]; prevents geometry vanishing at grazing angles under non-uniform scaling [S3, unofficial].
*   **Limitations:** Risk of missing thin geometry; requires conservative SDFs; higher computational cost per step for geometric enhancement due to formula evaluation [S5, S7, unofficial].

## Background
Enhanced Sphere Tracing originated from the need to accelerate real-time rendering of implicit surfaces [S5, unofficial]. The "Relaxed Sphere Tracing" variant was introduced by Keinert et al. in 2014, proposing over-relaxation to accelerate convergence [S3, S7, unofficial]. The "Enhanced Sphere Tracing" variant, specifically the geometric approach using historical step data, was proposed by Bálint and Valasek in 2018, optimizing for locally planar surfaces [S5, S7, unofficial]. The aggressive marching strategy was also independently applied in differentiable neural rendering contexts to stabilize training and speed up forward propagation [S1].
