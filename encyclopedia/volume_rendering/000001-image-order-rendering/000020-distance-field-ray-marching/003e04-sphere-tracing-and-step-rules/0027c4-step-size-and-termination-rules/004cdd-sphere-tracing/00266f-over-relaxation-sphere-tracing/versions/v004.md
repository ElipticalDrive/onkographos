# Over-relaxation Sphere Tracing

Also called: Enhanced Sphere Tracing - Over Relaxation, Over-relaxation Sphere Tracing with Screen-Space Intersection Selection, Over-relaxation sphere tracing with screen-space selection, Over-relaxation-based sphere tracing, Over-relaxed sphere tracing, Sphere tracing with over-relaxation

## Overview
Over-relaxation Sphere Tracing accelerates the standard sphere tracing algorithm by stepping further along the ray than the conservative signed distance bound (SDF) allows, controlled by a relaxation parameter $\omega \in [1, 2)$ [S1][S3, unofficial]. It reduces the number of SDF evaluations by 20–40% in typical 3D renders [S4, unofficial]. Unlike standard sphere tracing, which guarantees no surface is skipped by stepping exactly the distance estimate, this method risks overshooting the surface; it detects such overshoots via an overlap test between consecutive unbounding spheres and falls back to standard sphere tracing ($\omega=1$) if an intersection might have been missed [S1][S3, unofficial]. It also incorporates screen-space error metrics to select the best intersection candidate when the maximum iteration count is exceeded, preventing artifacts from rays grazing object edges [S1][S3, unofficial].

## How it works
**Inputs:**
*   Ray origin $o$ and normalized direction $d$.
*   Signed Distance Function $f(p)$, where $f(p) < 0$ inside the object and $f(p) > 0$ outside [S1][S3, unofficial].
*   Parameters:
    *   $\omega$: Relaxation parameter, typically $1.2$ [S1][S3, unofficial]. Range $[1, 2)$ [S2, S3, unofficial].
    *   $t_{min}$: Minimum ray distance.
    *   $t_{max}$: Maximum ray distance.
    *   $MAX\_ITERATIONS$: Maximum number of steps, typically 80 [S1][S3, unofficial].
    *   $pixelRadius$: Radius of a pixel at $t=1$ (half pixel size), used for early termination [S1][S3, unofficial].
    *   $forceHit$: Boolean flag. If true, returns the best candidate even if error > $pixelRadius$ [S1][S3, unofficial].

**Outputs:**
*   Intersection distance $t$, or $INFINITY$ if no valid intersection is found within constraints.

**Data Structures:**
*   Floating-point variables for ray position $t$, current radius, previous radius, step length, and best candidate tracking.

**Algorithm Steps:**
1.  **Initialization:**
    *   Set $t = t_{min}$.
    *   Initialize $candidate\_t = t_{min}$ and $candidate\_error = \infty$.
    *   Initialize $previousRadius = 0$.
    *   Initialize $stepLength = 0$.
    *   Determine $functionSign$: if $f(o) < 0$, $functionSign = -1$, else $+1$. This handles rays starting inside the object [S1][S3, unofficial].

2.  **Iteration Loop:** For $i$ from $0$ to $MAX\_ITERATIONS - 1$:
    *   **Evaluate SDF:** Calculate current position $p = d \cdot t + o$. Compute $signedRadius = functionSign \cdot f(p)$ and $radius = |signedRadius|$ [S1][S3, unofficial].
    *   **Overshoot Detection (SOR Fail):** Check if the over-relaxation step would skip a surface. An overshoot is detected if:
        $$ \omega > 1 \quad \text{AND} \quad (radius + previousRadius) < stepLength $$
        This condition implies that the unbounding spheres of the previous step and the current step do not overlap, meaning the segment between them might contain a surface intersection [S1][S3, unofficial].
    *   **Handle Failure or Advance:**
        *   **If SOR Fail is true:**
            *   The algorithm has potentially skipped an intersection.
            *   Retreat to the position before the over-relaxed step. The fallback position is calculated as:
                $$ p_{fallback} = p_{prev} + d \cdot \delta_{i-1} \cdot (1 - \omega) $$
                where $\delta_{i-1}$ is the step size of the previous iteration. In terms of $t$, this effectively reduces the current step length to revert to a standard step. The implementation simplifies this by adjusting `stepLength` and disabling over-relaxation:
                ```python
                stepLength -= omega * stepLength
                omega = 1
                ```
                This sets $\omega=1$, forcing subsequent steps to use the conservative SDF value [S1][S3, unofficial].
        *   **If SOR Fail is false:**
            *   Calculate the over-relaxed step length: $stepLength = signedRadius \cdot \omega$ [S1][S3, unofficial].
            *   Update $previousRadius = radius$ [S1][S3, unofficial].
            *   **Screen-Space Error Calculation:** Compute the screen-space error metric:
                $$ error = \frac{radius}{t} $$
                This represents the unbounding sphere radius as measured in screen space [S1][S3, unofficial].
            *   **Update Best Candidate:** If the current step is valid (!sorFail) and the error is better than the best seen so far:
                ```python
                if error < candidate_error:
                    candidate_t = t
                    candidate_error = error
                ```
            *   **Early Termination:** If the error is sub-pixel ($error < pixelRadius$) or the maximum distance is reached ($t > t_{max}$), break the loop [S1][S3, unofficial].
            *   **Advance Ray:** Update $t = t + stepLength$ [S1][S3, unofficial].

3.  **Post-Loop Result:**
    *   If $forceHit$ is false, and either $t > t_{max}$ or $candidate\_error > pixelRadius$, return $INFINITY$ [S1][S3, unofficial].
    *   Otherwise, return $candidate\_t$ [S1][S3, unofficial].

**Pseudocode:**
```python
def over_relaxation_sphere_tracing(o, d, f, omega, t_min, t_max, max_iterations, pixel_radius, force_hit):
    t = t_min
    candidate_error = float('inf')
    candidate_t = t_min
    previous_radius = 0
    step_length = 0
    
    # Determine if ray starts inside or outside
    if f(o) < 0:
        function_sign = -1
    else:
        function_sign = 1
        
    for i in range(max_iterations):
        # Evaluate SDF at current position
        p = d * t + o
        signed_radius = function_sign * f(p)
        radius = abs(signed_radius)
        
        # Check for overshoot (Sphere of Influence Relaxation failure)
        # Overshoot occurs if the new sphere does not overlap the previous one
        sor_fail = (omega > 1) and ((radius + previous_radius) < step_length)
        
        if sor_fail:
            # Fallback: retreat and disable over-relaxation
            # Effectively revert to standard sphere tracing step size
            step_length -= omega * step_length
            omega = 1
        else:
            # Calculate over-relaxed step size
            step_length = signed_radius * omega
            previous_radius = radius
            
            # Calculate screen-space error
            if t > 0:
                error = radius / t
            else:
                error = float('inf')
                
            # Update best candidate
            if error < candidate_error:
                candidate_t = t
                candidate_error = error
                
            # Early termination if sub-pixel accuracy reached or max distance exceeded
            if error < pixel_radius or t > t_max:
                break
                
        # Advance ray
        t += step_length
        
    # Final check
    if not force_hit and (t > t_max or candidate_error > pixel_radius):
        return float('inf')
        
    return candidate_t
```

**Edge Cases and Pitfalls:**
*   **Overshooting:** If $\omega$ is too large, the algorithm may step over thin geometry. The overlap test $(radius + previousRadius) < stepLength$ detects this, but if the SDF is not Lipschitz continuous (e.g., user-defined DEs in fractal rendering), the test may be unreliable [S4, unofficial]. In such cases, fall back to $\omega=1$ or tune $\omega$ manually [S4, unofficial].
*   **Grazing Rays:** Rays grazing an object's edge may terminate in mid-air if the last point is used. The screen-space error metric selects the point with the smallest unbounding radius, reducing "aura" artifacts [S1][S3, unofficial].
*   **Branching Divergence:** An optimization exists where, if the fallback position's unbounding sphere overlaps with the current position's sphere, the previous over-relaxed step is guaranteed safe, and tracing can continue from the current position without retreating. However, this adds branching and state handling, which can diminish performance on GPUs due to thread divergence [S1][S3, unofficial].
*   **Self-Intersection:** For secondary rays, dynamic $\epsilon$ offsetting is recommended to prevent self-intersection, as the screen-space termination metric can result in intersection points with varying distances from the surface [S1][S3, unofficial].

## Subtopics

### [Binary Sphere Tracing](10174-binary-sphere-tracing.md)
A trial-and-error search for unbounding spheres of conformally transformed Kernel-Reflection Sequences, acting as an extreme variant of over-relaxation that uses binary search logic instead of distance functions.

### [Accelerating Sphere Tracing](13706-accelerating-sphere-tracing.md)
Predicts the next step distance by assuming the surface is locally planar, using historical SDF values to allow larger steps than standard over-relaxation while reducing overshoot corrections.

## Operating characteristics
*   **Performance:** Reduces the number of SDF evaluations (steps) by 20–40% in 3D renders compared to standard sphere tracing [S4, unofficial].
*   **Measured Performance:**
    *   City scene (1280x720, NVIDIA GTX Titan): 16.829 ms (59.421 Hz) with over-relaxation vs 20.409 ms (48.998 Hz) without [S1][S3, unofficial].
    *   Jewel scene: 2.978 ms (335.744 Hz) with over-relaxation vs 3.472 ms (288.018 Hz) without [S1][S3, unofficial].
    *   Path tracing (10 bounces, 1 sample/pixel): 101.934 ms (9.8 Hz) with $\omega=1.4$ vs 118.302 ms (8.453 Hz) without [S3, unofficial].
*   **Scaling:** Performance gains are consistent across hardware, as the primary benefit is reduced function evaluation count [S4, unofficial].
*   **Strengths:** Significant speedup for complex scenes; improved visual quality by handling grazing rays better via screen-space selection.
*   **Limitations:** Requires careful tuning of $\omega$; larger $\omega$ causes earlier fallback to standard tracing, negating benefits; non-Lipschitz SDFs can break the overshoot detection [S1][S4, unofficial].

## Background
The method was introduced by Keinert et al. in 2014 in the paper "Enhanced Sphere Tracing" [S1][S3, S4, unofficial]. It is part of a suite of enhancements to classical sphere tracing, including screen-space intersection selection and dynamic $\epsilon$ for self-intersection prevention. The technique is widely used in real-time ray marching, particularly in fractal rendering and GPU-based path tracing [S1][S3, S4, unofficial].
