# Sphere Tracing Termination and Clipping

Also called: Sphere Tracing Stopping Criteria, Sphere Tracing Termination Conditions

## Overview
Sphere Tracing Termination and Clipping defines the conditions under which a ray-marching loop over a Signed Distance Field (SDF) must halt, ensuring the algorithm returns a valid intersection point or correctly reports no hit. It solves the problem of infinite loops and precision errors by combining geometric convergence checks with hard limits on iteration count and ray depth. It distinguishes itself from [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by relying on the distance field value itself to determine step size and termination, rather than fixed geometric intersections, and from [Sphere Tracing](1674-sphere-tracing.md) by explicitly detailing the failure modes (oscillation, far-plane clipping) that require specific guards.

## How it works
The method operates on a ray defined by an origin $o$ and direction $d$, and an SDF function $f(p)$ that returns the distance to the nearest surface from point $p$.

**Inputs:**
- Ray origin $o$ and direction $d$ (normalized).
- SDF function $f(p)$.
- Maximum iteration count $k_{max}$.
- Stopping distance threshold $\delta$.
- Far plane clipping depth $d_{far}$.
- Oscillation detection factor $\alpha$ (typically 6).

**Outputs:**
- Intersection distance $t$ (if hit).
- Boolean flag `hit` (true if surface found, false if clipped or max iterations reached).

**Data Structures:**
- `current_pos`: 3D vector, initialized to $o$.
- `dist`: float, initialized to $f(o)$.
- `prev_dist`: float, initialized to $dist$.
- `iter`: integer, initialized to 0.

**Parameters:**
- $\delta = 0.0003$ [S1].
- $k_{max} = 200$ [S1].
- $d_{far} = 5.0$ [S1].
- $\alpha = 6$ [S1].

**Steps:**
1. Initialize `current_pos` = $o$, `dist` = $f(o)$, `prev_dist` = `dist`, `iter` = 0.
2. If `dist` < 0, the ray starts inside the object. Handle as a special case or clamp to 0 depending on implementation requirements [G].
3. Loop while `iter` < $k_{max}$:
    a. **Far Plane Clipping**: If `current_pos` + `dist` * $d$ exceeds the far plane distance $d_{far}$ from the origin, terminate and return `hit` = false. Specifically, if `dist` > $d_{far}$ - `ray_length_so_far`, terminate [S1].
    b. **Step**: Move along the ray: `current_pos` = `current_pos` + `dist` * $d$.
    c. **Update Ray Length**: Track the total distance traveled from origin to ensure far plane check is accurate relative to the ray start.
    d. **Evaluate SDF**: `new_dist` = $f(\text{current\_pos})$.
    e. **Oscillation Check**: If `iter` > 0, check for oscillation: if $| \text{prev\_dist} - \text{new\_dist} | < \alpha \delta$, terminate and return `hit` = false [S1]. This prevents infinite loops in regions where the SDF is noisy or non-monotonic.
    f. **Convergence Check**: If `new_dist` < $\delta$, terminate and return `hit` = true, `t` = distance from $o$ to `current_pos`.
    g. **Update State**: `prev_dist` = `new_dist`, `dist` = `new_dist`, `iter` = `iter` + 1.
4. If loop completes without hitting convergence, return `hit` = false.

**Pseudocode:**
```python
def sphere_trace_terminate_clip(o, d, f, k_max=200, delta=0.0003, d_far=5.0, alpha=6):
    current_pos = o
    dist = f(current_pos)
    prev_dist = dist
    ray_len = 0.0
    iter_count = 0
    
    # Handle starting inside object [G]
    if dist < 0:
        dist = 0.0
        
    while iter_count < k_max:
        # Far plane clipping: if the next step would go beyond d_far from origin
        # We check if the current distance to surface is greater than remaining budget
        remaining_budget = d_far - ray_len
        if dist > remaining_budget:
            return False, None
            
        # Step along the ray
        current_pos = current_pos + dist * d
        ray_len += dist
        
        # Evaluate SDF at new position
        new_dist = f(current_pos)
        
        # Oscillation check: prevents infinite loops in noisy SDFs
        if iter_count > 0:
            if abs(prev_dist - new_dist) < alpha * delta:
                return False, None
                
        # Convergence check
        if new_dist < delta:
            return True, ray_len
            
        # Update state
        prev_dist = new_dist
        dist = new_dist
        iter_count += 1
        
    return False, None
```

**Edge Cases and Pitfalls:**
- **Oscillation**: In regions with high-frequency noise or non-Lipschitz SDFs, the distance value may fluctuate around zero without converging. The oscillation check $|d_{bk} - d_{bk-1}| < 6\delta$ is critical to prevent infinite loops [S1].
- **Far Plane**: Without clipping, rays may march indefinitely in empty space. The far plane depth of 5.0 is a specific parameter from the source [S1].
- **Precision**: The threshold $\delta = 0.0003$ is specific to the source implementation [S1]. Using a too-large $\delta$ causes "swimming" artifacts where the surface appears to shift with view direction [S2].

## Subtopics

### [Affine Arithmetic Early Skip Test](4313-affine-arithmetic-early-skip-test.md)
The Affine Arithmetic Early Skip Test is a constant-time heuristic used in distance-field ray marching to detect if a ray does not collide with an object within a specific working interval, thereby avoiding expensive root-finding operations. It distinguishes itself from sibling methods like Bracketed Newton Bisection (BNB) by providing immediate non-collision detection and a conservative starting point for subsequent searches, rather than searching for monotonic intervals of derivatives.

### [Dynamic Epsilon for Self-Intersection Prevention](4318-dynamic-epsilon-for-self-intersection-prevention.md)
Dynamic epsilon is a method for preventing self-intersection artifacts in secondary rays (e.g., refraction) during sphere tracing by computing a local offset $\varepsilon_{\text{dynamic}}$ at each intersection point, rather than using a global constant. It solves the problem where global epsilon values are inappropriate for sphere tracing with screen-space termination metrics because intersection distances from the surface exhibit large variations. Unlike global epsilon, dynamic epsilon adapts to the local surface distance, making it easier and more robust to tune than a single global value.

### [Convex Object Optimization](4367-convex-object-optimization.md)
Convex Object Optimization is a technique for accelerating sphere tracing through objects represented by a signed distance bound (SDB) that are enclosed within a convex bounding volume. It solves the problem of expensive interior traversal by avoiding costly marching through the inside of the object, which typically requires many iterations and gradient computations. It sets itself apart from standard sphere tracing by using the bounding volume to determine entry and exit points, thereby reducing the number of iterations required to find a ray-surface intersection.

### [Discontinuity Reduction via Fixed-Point Iteration](4368-discontinuity-reduction-via-fixed-point-iteration.md)
Discontinuity reduction via fixed-point iteration is a post-processing step applied to intersection points retrieved by sphere tracing to smooth out discontinuities in the signed distance function (SDF) $f(p)$ and reduce artifacts in procedural texturing. It sets itself apart from its siblings by trading a slight increase in average geometric error for significantly reduced visual discontinuities across the screen-space domain, whereas [Affine Arithmetic Early Skip Test](4313-affine-arithmetic-early-skip-test.md) focuses on skipping empty space and [Dynamic Epsilon for Self-Intersection Prevention](4318-dynamic-epsilon-for-self-intersection-prevention.md) focuses on preventing self-intersection artifacts.

### [Ray Intersection with Grazing Point Detection](4463-ray-intersection-with-grazing-point-detection.md)
A ray intersection method that performs sphere tracing to find the primary intersection while simultaneously tracking the 'grazing point' (the point on the surface where the ray direction is tangent to the surface normal, indicated by a zero directional derivative). It returns the intersection time, validity, grazing point status, and the grazing point position. It sets itself apart from standard sphere tracing by explicitly identifying and refining grazing contacts, which are often missed or poorly resolved by standard termination rules.

### Cone Tracing Error Threshold
A method to determine the adaptive error threshold $\hat{\epsilon}$ based on the ray distance and pixel footprint, ensuring rays terminate when the pixel cone intersects the surface [S2]. It calculates the error threshold as $\hat{\epsilon}(\hat{x}) = \hat{x} \hat{r}_p$, where $\hat{x}$ is the distance along the ray in undeformed space and $\hat{r}_p$ is the radius of one pixel in undeformed space [S2]. The pixel radius in undeformed space is calculated as $\hat{r}_p = s r_p J_D^{-1}$, where $s$ is the distance in deformed space, $r_p$ is the pixel radius in deformed space, and $J_D^{-1}$ is the inverse Jacobian determinant [S2]. If the threshold is too high, artifacts manifest as the surface 'swimming', appearing in different places depending on view direction [S2].

### Blend Mode
A rendering mode that traverses voxels and sums their value until value accumulation results in enough content, either being opaque for early termination or containing greater than zero content for blending with a user-specified background [S3, unofficial]. It traverses voxels and sums their value, checking if value accumulation results in enough content [S3, unofficial]. The high cost of voxel access can shrink or invert performance gains of block walking and culling in this mode [S3, unofficial].

### Optimized Binary Search with Local Lipschitz Bounds
A binary search method that recursively subdivides an interval, using local Lipschitz bounds to exclude intervals earlier and shrink sub-intervals asymmetrically [S4]. It uses the local Lipschitz bound $\lambda(e)$ to exclude intervals earlier in the recursive bisection process [S4]. It shrinks the interval $e=[a,b]$ to $[e_a, e_b]$ using $e_a = a + |f(a)|/\lambda(e)$ and $e_b = b - |f(b)|/\lambda(e)$ to improve bisection efficiency [S4]. Compared to standard binary search which cuts the segment in two equal parts, this method reduces the number of field function queries similarly to Segment Tracing and provides timing speed-ups [S4].

## Operating characteristics
- **Time Complexity**: The number of iterations is bounded by $k_{max}$ (typically 200) [S1]. In practice, convergence is often much faster, depending on the Lipschitz constant of the SDF and the threshold $\delta$.
- **Memory Complexity**: $O(1)$ auxiliary memory per ray, as only current position, distance, and iteration count are stored.
- **Measured Performance**: Specific performance metrics are not provided for the base termination method alone, but related methods like Optimized Binary Search with Local Lipschitz Bounds show timing speed-ups compared to standard binary search [S4].
- **Strengths**: Robust against infinite loops via oscillation detection and far-plane clipping [S1]. Simple to implement.
- **Limitations**: The fixed iteration limit and threshold may miss very close intersections or terminate prematurely in noisy SDFs. The oscillation check parameter $\alpha=6$ is heuristic [S1].
- **When to use**: Standard sphere tracing for SDFs where the Lipschitz constant is known or bounded, and performance constraints require hard iteration limits.
- **When not to use**: When high precision is required without fixed iteration limits, or when the SDF is highly non-Lipschitz and oscillation checks are insufficient.
