# Ray Marching

Also called: Ray Marching Step, SDF-based Ray Stepping, Signed Distance Field stepping, jittered ray marching

## Overview
Ray marching is an iterative technique for finding intersections with solid geometry or evaluating volumetric fields by stepping along a ray and testing for intersections [S2, book][S10, unofficial]. It is used when the surface function is not easy to solve analytically or when rendering non-uniform volumetrics, implicit functions, fractals, and parametric surfaces where intersection is not known ahead of time [S4, unofficial][S10, unofficial]. Unlike classical ray tracing which seeks exact intersections directly, ray marching works iteratively, moving the ray through space in steps until a surface is found, a maximum distance is exceeded, or enough samples are collected for volume integration [S8, unofficial][S10, unofficial]. It sets itself apart from its parent [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by encompassing a broader family of methods, including adaptive stepping via Signed Distance Functions (SDFs) and fixed-step approaches for volume rendering, whereas the parent specifically refers to the fixed-stride mitigation of root-finding drawbacks [S12, unofficial][S13, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Ray origin $r_o$ and direction $r_d$ (normalized) [S8, unofficial][S9].
*   Scene representation: A function $scene(p)$ that returns a value at point $p$ [S12, unofficial]. This value is either a Signed Distance Function (SDF) for surface rendering or a density/opacity field for volume rendering [S5][S6, unofficial].
*   Parameters:
    *   $u_{maxDis}$: Maximum ray distance (far plane) [S11, unofficial].
    *   $u_{eps}$: Hit threshold (surface proximity) [S13, unofficial].
    *   $u_{maxSteps}$: Maximum number of iterations [S11, unofficial].
    *   $min\_step\_len$, $max\_step\_len$: Bounds for step size [S2, book].

**Outputs:**
*   For surface rendering: Hit position, surface normal, and final color [S8, unofficial][S9].
*   For volume rendering: Accumulated color and opacity [S4, unofficial][S6, unofficial].

### Data Structures
No complex data structures are required for the core algorithm itself, as it relies on procedural evaluation [S12, unofficial]. For acceleration (space leaping), preprocessed safety distances or grids may be used [S4, unofficial]. For volume rendering, the scene is often represented as a neural network or a 3D texture grid [S3, unofficial][S6, unofficial].

### Algorithm Steps
The general iterative process is as follows [S8, unofficial][S9]:

1.  **Ray Generation**: Compute ray origin $r_o$ and direction $r_d$ for the current pixel [S8, unofficial].
2.  **Initialization**: Set total distance traveled $t = 0$ and current position $p = r_o$ [S11, unofficial].
3.  **Iteration Loop**: Repeat for $i = 0$ to $u_{maxSteps}$:
    a.  **Query Scene**: Evaluate the scene function at the current position: $dist = scene(p)$ [S11, unofficial].
        *   If using SDF: $dist$ is the distance to the nearest surface [S12, unofficial].
        *   If using Volume: $dist$ is the density or transmittance contribution at $p$ [S5][S6, unofficial].
    b.  **Termination Check**:
        *   If $dist < u_{eps}$ (for SDF) or sufficient samples accumulated (for Volume), break loop [S11, unofficial][S13, unofficial].
        *   If $t + dist \ge u_{maxDis}$, break loop (missed geometry/background) [S11, unofficial].
    c.  **Advance Ray**:
        *   **Sphere Tracing (Adaptive)**: Advance by the SDF value: $t \leftarrow t + dist$ [S11, unofficial][S12, unofficial]. This is safe because no geometry exists within distance $dist$ [S1, unofficial].
        *   **Fixed Step**: Advance by a constant $\Delta t$: $t \leftarrow t + \Delta t$ [S7, unofficial].
    d.  **Update Position**: $p \leftarrow r_o + t \cdot r_d$ [S11, unofficial].
4.  **Post-Processing**:
    *   If hit ($t < u_{maxDis}$): Compute lighting (diffuse, specular, ambient) using normals derived from numerical differentiation of the SDF [S8, unofficial][S13, unofficial].
    *   If miss: Output clear/background color [S11, unofficial].
    *   For Volume: Accumulate color and opacity using the volume rendering equation [S5][S6, unofficial].

### Pseudocode
The following pseudocode implements the standard sphere tracing variant, which is the most common form of ray marching for implicit surfaces [S11, unofficial][S12, unofficial]. It uses explicit vector operations to remain valid Python.

```python
import math

def ray_march(ro, rd, scene_func, max_steps, max_dist, epsilon):
    """
    Iteratively march a ray to find intersection with implicit surface defined by scene_func.
    
    Args:
        ro: list[float], ray origin [x, y, z]
        rd: list[float], normalized ray direction [x, y, z]
        scene_func: function, returns SDF value (distance to nearest surface) for a point
        max_steps: int, maximum number of iterations
        max_dist: float, maximum distance to search
        epsilon: float, threshold for hit detection
        
    Returns:
        float: total distance traveled if hit, max_dist if missed
    """
    t = 0.0  # total distance travelled
    
    for _ in range(max_steps):
        # Calculate current position
        p = [ro[0] + t * rd[0], ro[1] + t * rd[1], ro[2] + t * rd[2]]
        
        # Query scene distance
        dist = scene_func(p)
        
        # Check for hit or max distance
        if dist < epsilon:
            return t + dist
        if t + dist > max_dist:
            return max_dist
            
        # Advance ray by the distance to the nearest surface (Sphere Tracing)
        # This is safe because no geometry exists inside the sphere of radius dist
        t += dist
        
    return max_dist

def compute_normal(scene_func, p, h=0.001):
    """
    Compute surface normal via numerical differentiation of SDF.
    """
    dx = scene_func([p[0] + h, p[1], p[2]]) - scene_func([p[0] - h, p[1], p[2]])
    dy = scene_func([p[0], p[1] + h, p[2]]) - scene_func([p[0], p[1] - h, p[2]])
    dz = scene_func([p[0], p[1], p[2] + h]) - scene_func([p[0], p[1], p[2] - h])
    
    length = math.sqrt(dx*dx + dy*dy + dz*dz)
    if length == 0.0:
        return [0.0, 0.0, 1.0]
    return [dx/length, dy/length, dz/length]
```

### Formulas
*   **Sphere Tracing Update**: $p_{n+1} = p_n + d(p_n)\hat{d}$, where $p_n$ is current position, $d(p_n)$ is SDF value, $\hat{d}$ is ray direction [S12, unofficial].
*   **Sphere SDF**: $distance = \|p\| - r$ [S13, unofficial].
*   **Cube SDF**: $distance = \max(|p.x| - s, |p.y| - s, |p.z| - s)$, where $s$ is half-size [S13, unofficial].
*   **Union SDF**: $distance = \min(distance_1, distance_2)$ [S13, unofficial].
*   **Jensen's Inequality Bias (Volume)**: Assuming constant extinction leads to bias: $\exp(\mathbb{E}[-\tau]) \le \mathbb{E}[\exp(-\tau)]$ [S17].

### Parameters
*   $u_{eps}$: Hit threshold. Typical value: $0.001$ [S13, unofficial].
*   $min\_step\_len$, $max\_step\_len$: Bounds for step size [S2, book].

### Edge Cases and Pitfalls
*   **Overestimation**: Sphere tracing requires the SDF to be conservative (never overestimate true distance). If the distance function is optimistic, the ray can step past geometry and miss it [S1, unofficial].
*   **Precision**: Insufficient precision can lead to "holes" or incorrect intersections [S13, unofficial].
*   **Volume Bias**: Fixed-step ray marching for volumes ignores true heterogeneity, leading to bias characterized by Jensen's inequality [S17].
*   **Performance at Low Samples**: Ray marching performs poorly at lower sample counts for volume rendering compared to distance sampling [S9].

## Subtopics

### [Iteration-Based Coloring](1244-iteration-based-coloring.md)
Accumulates color and opacity per step along the ray rather than stopping at the first hit. Sets itself apart by supporting translucent and participating media. Choose it when rendering fog, clouds, or neural radiance fields.

### [Step Size Selection](2331-step-size-selection.md)
Determines the increment $\Delta t$ or adaptive jump distance at each iteration. Sets itself apart by focusing on the trade-off between sampling density and computational cost. Choose it when optimizing convergence or avoiding aliasing in volumetric integration.

### [SDF Ray Marching with Grid Lookup](5017-sdf-ray-marching-with-grid-lookup.md)
Combines adaptive SDF stepping with spatial acceleration structures like 3D textures or sparse grids. Sets itself apart by replacing procedural evaluation with fast texture lookups. Choose it when rendering large, precomputed distance fields or voxel-based scenes.

## Operating characteristics
*   **Complexity**: High computational complexity due to many iterations required per pixel [S13, unofficial].
*   **Performance**: On an RTX 8000 GPU at 1024 spp, ray marching on a room scene took $11.0 \pm 0.5$ ms. On a GTX 980 Ti at 256 spp, it took $10.3 \pm 0.2$ ms [S9].
*   **Scaling**: Scalability to large explicit scenes is poor unless acceleration structures (BVH, grids) are used for distance queries [S1, unofficial].
*   **Strengths**: Natural for procedural geometry, compact scene representation, easy integration of global illumination and soft shadows [S13, unofficial].
*   **Limitations**: Inefficient for explicit triangle meshes without SDF conversion; poor convergence at low sample counts for volumes [S9][S1, unofficial].
*   **When to Use**: Rendering implicit surfaces, fractals, volumetrics, and parametric surfaces where analytical intersection is difficult [S2, book][S10, unofficial].

## Background
Ray marching was first encountered by the author in the context of per-pixel displacement mapping techniques, specifically relief mapping of non-height-field surface details [S4, unofficial]. It is a technique similar to traditional ray tracing but relies on iterative stepping rather than direct intersection solving [S4, unofficial]. It is widely used in real-time differentiable volume rendering (e.g., NeRF) and procedural graphics/shaders (e.g., ShaderToy) [S3, unofficial][S13, unofficial].
