# Uniform Ray Marching

Also called: Fixed-Step Ray Marching Setup, Normalized Step Size Calculation, Parallel Ray Sampling (Fallback), Ray-to-Sample Generation, Simple ray marching (debug view), Uniform Ray Marching for Visualization

## Overview
Uniform Ray Marching is a sampling strategy that generates 3D sample positions along rays within an Axis-Aligned Bounding Box (AABB) using a fixed spacing between consecutive samples [S2, S4, unofficial]. It serves as a debug rendering mode for direct atlas sampling without brick traversal, a PyTorch-native fallback for environments lacking custom CUDA extensions, and a dense uniform sampler for Line-of-Sight (LOS) integral visualization [S1, S3, S4, unofficial]. It sets itself apart from adaptive methods like [NeRF Ray Marching Optimizations](9999-nerf-ray-marching-optimizations.md) by using constant intervals rather than density-based acceleration, and from [Oversampled 3D Ray March](5708-oversampled-3d-ray-march.md) by not enforcing strict slab ownership at LOD boundaries [S1, S4, unofficial].

## How it works
**Inputs:**
*   `rays_o`: Tensor of shape `(N, 3)` containing ray origins [S4, unofficial].
*   `rays_d`: Tensor of shape `(N, 3)` containing ray directions [S4, unofficial].
*   `aabb_min`, `aabb_max`: Vectors defining the AABB boundaries [S4, unofficial].
*   `render_step_size`: Scalar float defining the fixed distance between sample points [S4, unofficial].
*   `r_max_rsun`: Optional float specifying an outer sphere radius in solar radii ($R_{sun}$) for clipping [S4, unofficial].
*   `atlasSize`: Scalar for volume texture normalization (used in debug/atlas mode) [S1, unofficial].
*   `numSteps`: Integer specifying the number of steps (alternative input to `render_step_size`) [S1, unofficial].

**Outputs:**
*   `sample_positions`: Tensor of 3D coordinates along the rays [S2, S4, unofficial].
*   `t_s`: Tensor of segment start times (depths) [S4, unofficial].
*   `t_e`: Tensor of segment end times (depths) [S4, unofficial].
*   `ray_idx`: Tensor mapping samples to original rays [S4, unofficial].
*   `valid`: Boolean mask indicating rays with valid intersections [S4, unofficial].

**Data Structures:**
*   Rays are typically stored as `(N, 6)` arrays where the first 3 columns are origins and the last 3 are directions [S2, unofficial].
*   Depth values are masked with `MAX_DEPTH` (constant `10000.0`) to mark invalid entries before sorting and trimming [S3, unofficial].

**Steps:**

1.  **Ray Preparation:** Extract origins and directions. Normalize directions and compute inverse directions if using slab-based intersection [S2, unofficial].
2.  **AABB Intersection:** Compute near (`t_min`) and far (`t_max`) intersection distances for each ray against the AABB [S2, S4, unofficial].
    *   Filter rays where `t_min < t_max` [S2, unofficial].
    *   Initialize a valid mask `ok = (t_max > t_min)` [S4, unofficial].
3.  **Optional Sphere Clipping:** If `r_max_rsun` is provided, clip the ray interval to an outer sphere [S4, unofficial].
    *   Calculate coefficients for the quadratic equation $|o + t d|^2 = (r_{max}/scale)^2$:
        $$ A = \sum (rays\_d^2) $$
        $$ B = 2.0 \sum (rays\_o \cdot rays\_d) $$
        $$ C = \sum (rays\_o^2) - \rho^2 $$
        where $\rho = r_{max\_rsun} / aabb\_scale$ [S4, unofficial].
    *   Solve for intersection times $t_{in}$ and $t_{out}$ using the quadratic formula. Handle numerical safety by clamping $A$ to $10^{-20}$ and the discriminant $disc = B^2 - 4AC$ to $0.0$ [S4, unofficial].
    *   Update interval bounds: $t_{min} = \max(t_{min}, t_{in})$ and $t_{max} = \min(t_{max}, t_{out})$ [S4, unofficial].
    *   Update valid mask: `ok = ok & hit` [S4, unofficial].
4.  **Step Size Calculation:** Determine the step size and number of steps [S1, S4, unofficial].
    *   If using `render_step_size`: Calculate steps per ray as $\lceil (t_{max} - t_{min}) / render\_step\_size \rceil$, clamped to a minimum of 1 [S4, unofficial].
    *   If using `numSteps`: Calculate `stepSize = rayLength / numSteps` [S1, unofficial].
5.  **Sample Generation:** Generate uniform sample points along the valid intervals [S2, S3, S4, unofficial].
    *   **Method A (Edge-based):** Create linearly spaced points $u$ in $[0, 1]$. Compute edge coordinates $edges = t_{min} + (t_{max} - t_{min}) \cdot u$. Flatten to get start times $t_s$ and end times $t_e$ [S4, unofficial].
    *   **Method B (Offset-based):** Generate delta offsets scaled by `MARCH_SIZE` (or `render_step_size`). Add deterministic noise ($0.5$) or uniform noise $[0.01, 0.99]$ if required [S3, unofficial]. Compute sampled depths and sort them [S3, unofficial].
6.  **Position Computation:** Compute 3D positions as $pos = ori + t \cdot dir$ [S2, S4, unofficial].
    *   For atlas debugging: Compute UV coordinates as $atlasUV = (pos / normalizedSize) + 0.5$ [S1, unofficial].
7.  **Post-Processing:**
    *   Identify invalid depths by comparing against `min_depth` and `max_depth` [S3, unofficial].
    *   Mask invalid depths with `MAX_DEPTH` and sort them to the end [S3, unofficial].
    *   Trim outputs to `num_max_steps` (maximum valid steps per ray) [S3, unofficial].
    *   Construct `ray_idx` mapping each sample to its source ray [S4, unofficial].

**Pseudocode:**

```python
import torch
import math

def uniform_ray_marching(rays_o, rays_d, aabb_min, aabb_max, render_step_size=None, num_steps=None, r_max_rsun=None, aabb_scale=1.0):
    """
    Generates uniform samples along rays within an AABB.
    rays_o: (N, 3)
    rays_d: (N, 3)
    aabb_min: (3,)
    aabb_max: (3,)
    """
    N = rays_o.shape[0]
    
    # 1. AABB Intersection
    # Compute inverse directions
    inv_dir = 1.0 / rays_d
    # Compute t_min and t_max for each slab
    t1 = (aabb_min - rays_o) * inv_dir
    t2 = (aabb_max - rays_o) * inv_dir
    
    # t_min is max of mins, t_max is min of maxs
    t_min = torch.maximum(t1, t2).min(dim=1).values
    t_max = torch.minimum(t1, t2).max(dim=1).values
    
    # Filter valid rays
    valid_mask = t_max > t_min
    t_min = t_min.masked_fill(~valid_mask, 0.0)
    t_max = t_max.masked_fill(~valid_mask, 0.0)
    
    # 2. Optional Sphere Clipping
    if r_max_rsun is not None:
        rho = r_max_rsun / aabb_scale
        A = (rays_d * rays_d).sum(dim=1)
        B = 2.0 * (rays_o * rays_d).sum(dim=1)
        C = (rays_o * rays_o).sum(dim=1) - rho * rho
        
        # Clamp for numerical stability
        A = torch.maximum(A, torch.tensor(1e-20))
        disc = B*B - 4.0*A*C
        disc = torch.maximum(disc, torch.tensor(0.0))
        
        sqrt_disc = torch.sqrt(disc)
        t_in = (-B - sqrt_disc) / (2.0 * A)
        t_out = (-B + sqrt_disc) / (2.0 * A)
        
        # Update bounds
        t_min = torch.maximum(t_min, t_in)
        t_max = torch.minimum(t_max, t_out)
        
        # Update valid mask (ray must hit sphere and still have t_max > t_min)
        hit_sphere = (disc >= 0) & (t_max > t_min)
        valid_mask = valid_mask & hit_sphere
        
    # 3. Step Size and Count
    if render_step_size is not None:
        # Calculate number of steps per ray
        ray_lengths = t_max - t_min
        n_steps = torch.ceil(ray_lengths / render_step_size).long()
        n_steps = torch.maximum(n_steps, torch.ones_like(n_steps))
        max_steps = n_steps.max().item()
        
        # Create index tensor for steps
        idx = torch.arange(max_steps, device=rays_o.device).unsqueeze(0) # (1, max_steps)
        n_steps_exp = n_steps.unsqueeze(1) # (N, 1)
        
        # Mask for valid steps per ray
        step_mask = idx < n_steps_exp # (N, max_steps)
        
        # Generate start times t_s
        # t_s = t_min + idx * step_size
        t_s = t_min.unsqueeze(1) + idx.float() * render_step_size
        t_s = t_s.masked_fill(~step_mask, 0.0)
        
        # Generate end times t_e
        t_e = t_s + render_step_size
        t_e = torch.minimum(t_e, t_max.unsqueeze(1))
        
        # Flatten valid samples
        t_s_flat = t_s[step_mask]
        t_e_flat = t_e[step_mask]
        
        # Create ray indices for flattened samples
        ray_indices = torch.arange(N, device=rays_o.device).repeat_interleave(n_steps)
        
    else:
        # Fallback or alternative logic if render_step_size is not provided
        # This section handles cases where num_steps might be global or derived differently
        # Based on S3/S4 notes, if not using fixed step size logic, we might use max depth logic
        # However, Uniform Ray Marching implies fixed spacing. 
        # If num_steps is provided globally:
        if num_steps is not None:
             # Simplified global step logic often used in debug modes
             # Generate uniform points between t_min and t_max
             # This requires variable length handling or padding
             pass 
        else:
            raise ValueError("Either render_step_size or num_steps must be provided")

    # 4. Compute Positions
    # Normalize directions if not already normalized
    dirs_norm = rays_d / rays_d.norm(dim=1, keepdim=True)
    
    # Positions for flattened samples
    # pos = ori + t * dir
    # We need to gather origins and directions for the flattened ray indices
    ori_flat = rays_o[ray_indices]
    dir_flat = dirs_norm[ray_indices]
    
    positions = ori_flat + t_s_flat.unsqueeze(1) * dir_flat
    
    return positions, t_s_flat, t_e_flat, ray_indices, valid_mask

```

**Parameters:**
*   `numSteps`: Typically `512` [S1, unofficial].
*   `MAX_DEPTH`: Constant `10000.0` used to mark invalid depths [S3, unofficial].
*   `EARLY_EXIT_ALPHA`: Threshold for breaking the march loop in composition [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Invalid Depths:** Depths outside the AABB or sphere are masked with `MAX_DEPTH` and sorted to the end to allow trimming to the maximum valid steps per ray [S3, unofficial].
*   **Numerical Stability:** The discriminant in sphere intersection must be clamped to $0.0$ to avoid NaNs from negative values due to precision errors [S4, unofficial].
*   **Aspect Ratio:** Builds on [Raycasting Step Size & Aspect Ratio Normalization](3734-raycasting-step-size-aspect-ratio-normalization.md) to handle arbitrary volume dimensions [Parent].

## Subtopics

### [Oversampled 3D Ray March](5708-oversampled-3d-ray-march.md)
Enforces strict slab ownership and corrected exit-face probing to resolve LOD boundary discontinuities. Choose when visual artifacts from empty-space skipping are present.

### [NeRF Ray Marching Optimizations](9999-nerf-ray-marching-optimizations.md)
Replaces fixed intervals with adaptive step sizes (exponential stepping, empty space skipping). Choose for performance optimization in NeRFs.

### [Voxel-Aware Masked Ray Sampling](11092-voxel-aware-masked-ray-sampling.md)
Samples only within intersected voxels with probabilities proportional to distance. Choose for sparse voxel fields with variable intersection counts.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of rays and $S$ is the number of steps per ray. The calculation is highly parallelizable as each ray's samples are independent [S3, S4, unofficial].
*   **Memory Complexity:** $O(N \cdot S)$ to store sample positions, depths, and indices [S4, unofficial].
*   **Performance:** Provides consistent, predictable sampling density. It is computationally inexpensive per sample but may waste samples in empty space compared to adaptive methods [S4, unofficial].
*   **Strengths:** Simple to implement, deterministic (with fixed noise), no dependency on custom CUDA extensions (PyTorch-native fallback) [S3, S4, unofficial].
*   **Limitations:** Inefficient for sparse volumes or scenes with large empty regions due to fixed step size [S4, unofficial].
*   **When to use:** Debugging, visualization, LOS integral rendering where aliasing artifacts from coarse sampling must be avoided, or as a baseline fallback [S1, S3, S4, unofficial].
*   **When not to use:** Large-scale NeRF training where performance is critical, or sparse voxel grids where traversal acceleration is preferred [S1, S4, unofficial].

## Background
Uniform Ray Marching is a fundamental technique in volume rendering, often used as a baseline or fallback implementation. It appears in various contexts: as a debug mode for direct atlas sampling in webGPU-native renderers [S1, unofficial], as a JAX-based volumetric renderer component [S2, unofficial], as a PyTorch fallback in Neural Sparse Voxel Fields (NSVF) [S3, unofficial], and in coronal NeRF rendering for solar physics [S4, unofficial]. The method relies on basic ray-AABB intersection and linear interpolation, forming the basis for more complex adaptive strategies.
