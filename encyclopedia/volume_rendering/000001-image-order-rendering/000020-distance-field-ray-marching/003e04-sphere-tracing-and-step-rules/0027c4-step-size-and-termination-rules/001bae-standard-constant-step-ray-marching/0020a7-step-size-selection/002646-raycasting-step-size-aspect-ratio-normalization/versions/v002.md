# Raycasting Step Size & Aspect Ratio Normalization

Also called: Aspect Ratio Normalized Ray Marching, Normalized Step Size Calculation

## Overview
This method computes a normalized step size and a scaling factor to map arbitrary volume dimensions and aspect ratios into a unit cube coordinate system for uniform ray marching [S1, unofficial]. It ensures that the sampling density remains consistent across axes regardless of the volume's physical aspect ratio, preventing anisotropic artifacts in the rendered output [S1, unofficial]. It differs from [Adaptive Step Size Calculation](4671-adaptive-step-size-calculation.md) by using a fixed, geometry-derived step size rather than one determined by local density gradients.

## How it works
**Inputs:**
- `dimensions`: `vec3` representing the volume's dimensions in world units or voxel counts.
- `aspectRatios`: `vec3` defining the relative scaling of volume axes.
- `stepScale`: A multiplier for the base step size, controlling the trade-off between rendering speed and quality.

**Outputs:**
- `stepSize`: The normalized distance between samples along the ray.
- `scaleFactor`: A `vec3` used to transform coordinates into the normalized unit cube space.

**Data Structures:**
- `maxSize`: A scalar float representing the maximum value among `dimensions.x`, `dimensions.y`, and `dimensions.z`.
- `scaleFactor`: A `vec3` initialized to `vec3(1) / ((vec3(1) * maxSize) / (dimensions * aspectRatios))`.

**Parameters:**
- `stepScale`: Clamped to a minimum of `0.1f` [S1, unofficial].
- `aspectRatios`: Clamped to a minimum of `vec3(0)` [S1, unofficial].

**Steps:**
1. Calculate `maxSize` as the maximum of the volume's x, y, and z dimensions:
   $$ maxSize = \max(dimensions.x, dimensions.y, dimensions.z) $$
2. Compute the `scaleFactor` to map the volume into a unit cube. This accounts for aspect ratios:
   $$ scaleFactor = \frac{1}{\frac{maxSize}{dimensions \cdot aspectRatios}} $$
   Where the division is component-wise. Specifically:
   $$ scaleFactor_i = \frac{1}{\frac{maxSize}{dimensions_i \cdot aspectRatios_i}} = \frac{dimensions_i \cdot aspectRatios_i}{maxSize} $$
3. Compute the base `stepSize` for each axis. The source describes this as:
   $$ stepSize_i = \frac{1.0f}{dimensions_i \cdot (\frac{maxSize}{dimensions_i})} $$
   Simplifying the term in the denominator:
   $$ stepSize_i = \frac{1.0f}{maxSize} $$
   Thus, the base step size is uniform across all axes and inversely proportional to the largest dimension of the volume.
4. Apply the `stepScale` multiplier to the base step size:
   $$ finalStepSize = stepSize \cdot stepScale $$
5. Clamp `stepScale` to a minimum of `0.1f` to prevent excessively small steps that could cause performance issues or precision errors [S1, unofficial].

**Pseudocode:**
```python
def compute_step_size_and_scale(dimensions, aspect_ratios, step_scale):
    # Clamp inputs as per source requirements
    aspect_ratios = max(aspect_ratios, vec3(0))
    step_scale = max(step_scale, 0.1f)
    
    # Calculate maxSize
    max_size = max(dimensions.x, dimensions.y, dimensions.z)
    
    # Compute scaleFactor
    # Formula: vec3(1) / ((vec3(1) * maxSize) / (dimensions * aspectRatios))
    # Component-wise: scaleFactor[i] = 1.0 / (max_size / (dimensions[i] * aspect_ratios[i]))
    # Which simplifies to: scaleFactor[i] = (dimensions[i] * aspect_ratios[i]) / max_size
    scale_factor = vec3(
        (dimensions.x * aspect_ratios.x) / max_size,
        (dimensions.y * aspect_ratios.y) / max_size,
        (dimensions.z * aspect_ratios.z) / max_size
    )
    
    # Compute base stepSize
    # Formula: 1.0f / (dimensions[i] * (maxSize / dimensions[i]))
    # Simplifies to: 1.0f / maxSize
    base_step_size = 1.0f / max_size
    
    # Apply stepScale
    final_step_size = base_step_size * step_scale
    
    return final_step_size, scale_factor
```

**Edge Cases and Pitfalls:**
- If `maxSize` is zero, division by zero occurs. This implies a zero-volume input, which is degenerate [G].
- If `aspectRatios` contains zeros, the corresponding `scaleFactor` component becomes zero, effectively collapsing that axis in the normalized space [S1, unofficial].
- The simplification of the step size formula assumes `dimensions[i]` is non-zero [G].

## Subtopics

### [Uniform Ray Marching](4810-uniform-ray-marching.md)
Uniform Ray Marching generates 3D sample positions along rays within an Axis-Aligned Bounding Box (AABB) using a fixed spacing between samples. It serves as a dense uniform sampler for Line-of-Sight (LOS) integral visualization, replacing coarse sampling to avoid aliasing artifacts such as concentric 'sampling rings' caused by steep gradients near inner radius cuts. It is often used as a fallback strategy in hardware or environments that do not support specialized libraries like nerfacc.

## Operating characteristics
- **Time Complexity:** $O(1)$ for the calculation of step size and scale factor per frame or volume change. The ray marching itself is $O(N)$ where $N$ is the number of samples, determined by the step size.
- **Memory Complexity:** $O(1)$ for the auxiliary variables (`maxSize`, `scaleFactor`).
- **Performance:** The method is computationally inexpensive. The primary cost is in the ray marching loop, which is influenced by `stepScale`. Smaller `stepScale` values increase accuracy but reduce performance.
- **Strengths:** Ensures consistent sampling density across different volume aspect ratios. Simple to implement.
- **Limitations:** Does not adapt to local scene complexity. May over-sample empty space or under-sample high-frequency details if `stepScale` is not tuned appropriately.
- **When to use:** When rendering volumes with non-cubic aspect ratios and uniform sampling is desired.
- **When not to use:** When the volume has highly varying density gradients that require adaptive sampling for efficiency [S2, unofficial].

## Background
This method is derived from the implementation in the `VolumeRendering` project by Jose Villegas [S1, unofficial]. It is used in the context of GPU-based volume rendering, specifically within the raycasting step, to normalize the coordinate system for uniform ray marching.
