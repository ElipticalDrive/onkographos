# Iteration-Based Coloring

Also called: Iteration count, Step count coloring [S1, unofficial]

## Overview
Iteration-Based Coloring is a rendering technique where the final pixel color is determined by the number of raymarching steps taken before the ray terminates (either by hitting a surface or reaching a maximum step count) [S1, unofficial]. It visualizes the computational intensity of the raymarch, highlighting regions where the ray traveled further or required more sampling iterations [S1, unofficial]. Unlike standard shading which relies on material properties and lighting, this method maps algorithmic performance metrics directly to visual output [S1, unofficial].

## How it works
**Inputs:**
- Ray origin and direction for each pixel [G].
- Implicit surface function or voxel data structure [G].
- Maximum step count limit ($N_{max}$) [S1, unofficial].
- Fixed step size ($\Delta t$) [G].

**Outputs:**
- Pixel color value [G].

**Data Structures:**
- Step counter: An integer tracking the number of iterations performed for the current ray [G].
- Termination flag: Boolean indicating if the ray has hit a surface or exceeded $N_{max}$ [G].

**Steps:**
1. Initialize the ray for the current pixel using the camera parameters [G].
2. Initialize step counter $k = 0$ [G].
3. While $k < N_{max}$ and ray is not terminated:
    a. Evaluate the distance to the nearest surface (or check voxel occupancy) at the current ray position [G].
    b. Advance the ray along its direction by the step size $\Delta t$ [G].
    c. Increment $k$ [G].
4. Determine the color based on the final value of $k$ [G].

**Formulas:**
The color intensity $C$ is mapped linearly to the step count $k$ [G]. A common normalization maps $k$ to the range $[0, 255]$:
$$ C = \left\lfloor \frac{k}{N_{max}} \times 255 \right\rfloor $$
Where:
- $k$ is the number of steps taken [G].
- $N_{max}$ is the maximum allowed steps [S1, unofficial].

**Parameters:**
- $N_{max}$: The maximum number of steps. A typical value cited is 64 [S1, unofficial].
- $\Delta t$: The fixed step size. Typically set to 1.0 for standard constant step marching [G].

**Edge Cases and Pitfalls:**
- **Termination:** Rays that never hit a surface (e.g., background) will always result in $N_{max}$ steps, returning the maximum intensity value [G].
- **Precision:** Floating-point accumulation errors may cause the ray to overshoot or undershoot the surface slightly, requiring a small epsilon threshold for hit detection [G].

**Pseudocode:**
```python
def iteration_based_coloring(ray_origin, ray_direction, surface_function, max_steps, step_size=1.0):
    """
    Renders a single pixel using iteration-based coloring.
    
    Args:
        ray_origin: vec3, origin of the ray.
        ray_direction: vec3, normalized direction of the ray.
        surface_function: callable, returns distance to surface at a point.
        max_steps: int, maximum number of raymarching iterations.
        step_size: float, fixed distance to advance per step.
        
    Returns:
        int: Step count taken before termination.
    """
    current_pos = ray_origin
    step_count = 0
    
    for i in range(max_steps):
        dist = surface_function(current_pos)
        
        if dist < 1e-4:
            return step_count
            
        current_pos = current_pos + ray_direction * step_size
        step_count += 1
        
    return step_count
```

## Subtopics

### [Depth Rendering](4504-depth-rendering.md)
A variant that visualizes geometric depth by mapping the z-coordinate of the first surface hit to grayscale intensity, rather than computational step count [G]. It differs from its parent by encoding spatial distance instead of algorithmic intensity [G].

## Operating characteristics
- **Time Complexity:** $O(N \times S)$, where $N$ is the number of pixels and $S$ is the average number of steps per ray [G]. The complexity is dominated by the raymarching loop [G].
- **Memory Complexity:** $O(1)$ per pixel, as only the step count and current position need to be stored [G].
- **Performance:** Visualizes computational intensity, making it useful for debugging raymarchers or creating abstract visual effects [S1, unofficial]. It does not provide physically accurate shading [G].
- **Strengths:** Simple to implement; provides immediate feedback on raymarch efficiency and surface proximity [S1, unofficial].
- **Limitations:** Does not convey material properties or lighting [G].

## Background
The technique was described in a 2013 blog post on raymarching distance fields, where it was presented as a simple way to "spice up" black and white renders by visualizing where the most intensive portions of the image are [S1, unofficial].
