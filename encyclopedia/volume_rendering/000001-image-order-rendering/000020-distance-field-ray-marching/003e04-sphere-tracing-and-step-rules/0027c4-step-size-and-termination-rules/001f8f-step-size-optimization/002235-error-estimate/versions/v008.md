# Error Estimate

Also called: Relative Error Metric

## Overview
Error Estimate calculates a relative error metric for adaptive stepping in volume rendering, determining the step size based on the local field values and a minimum threshold [S1, unofficial]. It sets itself apart from sibling methods like [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md) by focusing on a normalized relative deviation rather than a strict geometric Lipschitz constraint, allowing for dynamic adjustment in regions where the field magnitude varies significantly.

## How it works
**Inputs and Outputs:**
- Input: A scalar field value $y$ (typically a vector representing density or distance at the current ray position), a constant $k$ (representing a target error bound or scaling factor), and a `threshold` (a small positive value to prevent division by zero).
- Output: A scalar step size adjustment factor $\Delta t_{rel}$, which is the maximum component-wise relative error plus a machine epsilon.

**Data Structures:**
- $y$: A 3-component vector $\mathbf{y} = (y_x, y_y, y_z)$ or a scalar field sample. In the source implementation, it is treated as a vector where the maximum absolute component is used [S1, unofficial].
- $k$: A scalar constant. The source code implies a fixed or precomputed value, but does not specify its typical magnitude or derivation [S1, unofficial].
- `threshold`: A small float, typically near machine epsilon or a user-defined minimum to ensure numerical stability.

**Steps:**
1.  Compute the absolute value of each component of $y$: $|y_i|$ for $i \in \{x, y, z\}$.
2.  Determine the maximum absolute component: $y_{max} = \max(|y_x|, |y_y|, |y_z|)$.
3.  Apply the threshold to prevent division by zero: $y_{safe} = \max(y_{max}, \text{threshold})$.
4.  Calculate the relative error vector $r_v$:
    $$ r_v = \frac{k}{y_{safe}} $$
    Note: The source code `abs(k / max(abs(y), threshold))` suggests $k$ is treated as a scalar divisor for the entire vector, or $k$ is applied component-wise if $k$ were a vector. Given the return statement `max(r_v.x, max(r_v.y, r_v.z))`, $k$ is likely a scalar, and the division is scalar division of the vector components, or $k$ is a vector. However, `abs(k / ...)` usually implies scalar division if $k$ is scalar. Let's assume $k$ is a scalar constant representing the desired error bound. If $k$ is a vector, the operation is component-wise. The source code `abs(k / max(...))` is ambiguous if $k$ is scalar vs vector. Standard relative error is $|val - approx|/|val|$. Here, it seems to be a heuristic: $k$ acts as a numerator. Let's assume $k$ is a scalar.
    $$ r_v = \left( \frac{k}{y_{safe}}, \frac{k}{y_{safe}}, \frac{k}{y_{safe}} \right) $$
    Wait, if $k$ is scalar, $r_v$ has identical components. The max is just that value. If $k$ is a vector, it's component-wise. The source code `abs(k / max(abs(y), threshold))` in GLSL/C++ usually performs scalar division if `k` is scalar. If `k` is a `vec3`, it's component-wise. The variable name `k` often implies a constant. Let's look at the return: `max(r_v.x, max(r_v.y, r_v.z))`. This implies $r_v$ is a vector. If $k$ is scalar, $r_v$ is uniform. The max is redundant but safe.
5.  Return the maximum component of $r_v$ plus `FLOAT_MIN` (machine epsilon for float):
    $$ \Delta t_{rel} = \max(r_v) + \text{FLOAT\_MIN} $$

**Pseudocode:**
```python
def error_estimate(y: Vector3f, k: float, threshold: float) -> float:
    """
    Calculate relative error metric for adaptive stepping.
    
    Args:
        y: Field value vector at current position.
        k: Scaling constant for error bound.
        threshold: Minimum value to prevent division by zero.
        
    Returns:
        Step size adjustment factor.
    """
    # Compute absolute values of components
    abs_y_x = abs(y.x)
    abs_y_y = abs(y.y)
    abs_y_z = abs(y.z)
    
    # Find maximum absolute component
    max_abs_y = max(abs_y_x, max(abs_y_y, abs_y_z))
    
    # Apply threshold for numerical stability
    safe_max = max(max_abs_y, threshold)
    
    # Calculate relative error vector (assuming k is scalar)
    # If k were a vector, this would be component-wise division
    r_v_x = abs(k / safe_max)
    r_v_y = abs(k / safe_max)
    r_v_z = abs(k / safe_max)
    
    # Find maximum component of the error vector
    max_r_v = max(r_v_x, max(r_v_y, r_v_z))
    
    # Add machine epsilon to ensure non-zero step
    return max_r_v + FLOAT_MIN
```

**Parameters:**
- $k$: Not given in the sources. [S1, unofficial]
- `threshold`: Not given in the sources. [S1, unofficial]
- `FLOAT_MIN`: Machine epsilon for the floating-point format used (e.g., $1.19 \times 10^{-7}$ for 32-bit float). [S1, unofficial]

**Edge Cases and Pitfalls:**
- **Zero Field Value:** If $y$ is zero, the threshold prevents division by zero. If the threshold is too large, the step size may become unnecessarily large, causing overshoot. If too small, numerical noise may dominate.
- **Negative Field Values:** The use of `abs()` ensures the step size is positive regardless of the sign of the field value, which is critical for SDFs where negative values indicate inside the object.
- **Precision:** Using `FLOAT_MIN` ensures the step size is never exactly zero, preventing infinite loops in stagnation scenarios.

### Stepsize Annealing
**Definition:**
A training strategy that varies the sampling rate $s$ in a range $[s_l, s_h]$ across epochs to benefit from fast convergence at low sampling rates and refinement at high sampling rates [S2, unofficial]. It is a training acceleration method for raymarching models that starts with a high rendering step size in early epochs and decreases it over time to achieve similar performance as training with a constant small step size [S2, unofficial].

**Formula:**
The sampling rate $s(e)$ at epoch $e$ is calculated as:
$$ s(e) = s_l \left(1 - \left(\frac{e}{E}\right)^2\right) + \left(\frac{e}{E}\right)^2 s_h $$
where $s(e)$ is the sampling rate at epoch $e$, $s_l$ is the lower bound, $s_h$ is the upper bound, $e$ is the current epoch, and $E$ is the total number of epochs [S2, unofficial].

**Parameters:**
- $s_l$: Lower bound of sampling rate range. Typical value: 0.1 [S2, unofficial].
- $s_h$: Upper bound of sampling rate range. Typical value: 2.0 [S2, unofficial].

**Comparison:**
Stepsize annealing produces visual results comparable to training with a fixed sampling rate of $s=2.0$ but reduces training time by 33.4% on average compared to constant $s=2.0$ [S2, unofficial]. Compared to training with a constant small step size, stepsize annealing achieves similar performance but with accelerated training time [S2, unofficial].

## Operating characteristics
**Time and Memory Complexity:**
The calculation is $O(1)$ in time and memory, involving a few arithmetic operations and comparisons [S1, unofficial].

**Measured Performance:**
Not given in the sources. [S1, unofficial]

**Scaling:**
The method scales linearly with the number of components in the vector $y$, but since $y$ is typically 3D, it is effectively constant time.

**Strengths and Limitations:**
- **Strengths:** Simple to implement, numerically stable with thresholding, provides a relative error metric that adapts to field magnitude.
- **Limitations:** The constant $k$ and threshold are not specified, requiring empirical tuning. It does not account for higher-order derivatives or curvature, which might be necessary for complex geometries.

**When to Use:**
Use when adaptive stepping is required based on local field values and a relative error metric is preferred over absolute or geometric constraints.

**When Not to Use:**
Avoid when strict geometric safety is required (use [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md)) or when training differentiable volume rendering models where annealing is more appropriate [S2, unofficial].

## Background
The Error Estimate method is described in the context of adaptive ray marching for scalar fields [S1, unofficial]. It is part of a broader effort to optimize rendering performance by dynamically adjusting step sizes based on local data characteristics.
