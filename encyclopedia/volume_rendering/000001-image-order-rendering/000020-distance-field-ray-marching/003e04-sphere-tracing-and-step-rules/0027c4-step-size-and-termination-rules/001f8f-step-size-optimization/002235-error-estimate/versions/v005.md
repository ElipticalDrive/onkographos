# Error Estimate

Also called: Relative Error Metric for Adaptive Stepping

## Overview
Error Estimate calculates a relative error metric for adaptive ray marching in scalar volume rendering by weighting interpolation error based on the distance to a user-specified isovalue $v_{iso}$ [S1, unofficial]. It sets itself apart from uniform error metrics by refining the sampling only in regions where scalar field values are close to $v_{iso}$, significantly reducing computation time in areas far from the isosurface [S1, unofficial].

**Pseudocode:**
```python
def error_estimate(y: Vector3, k: Vector3, threshold: float) -> float:
    # y: scalar field values at current position (e.g., interpolated neighbors)
    # k: tolerance vector (or scalar broadcasted)
    # threshold: minimum value to prevent division by zero
    
    # 1. Compute absolute values of y
    abs_y = abs(y)
    
    # 2. Find max absolute value in y
    y_max = max(abs_y.x, abs_y.y, abs_y.z)
    
    # 3. Apply threshold
    denom = max(y_max, threshold)
    
    # 4. Calculate relative error vector
    # Note: If k is scalar, it is broadcast to all components.
    r_v = abs(k / denom)
    
    # 5. Return max component plus machine epsilon
    result = max(r_v.x, max(r_v.y, r_v.z))
    return result + FLOAT_MIN
```

**Parameters:**
- `threshold`: A small positive float to prevent division by zero. Typical value: Not given in the sources.
- `k`: Tolerance or scaling factor. Typical value: Not given in the sources.
- `FLOAT_MIN`: The smallest positive normalized floating-point number. Typical value: $1.17549435 \times 10^{-38}$ for IEEE 754 single precision.

**Edge Cases and Pitfalls:**
- **Zero Denominator:** If $y_{max}$ is 0 and `threshold` is not applied, division by zero occurs. The `threshold` parameter handles this [S1, unofficial].
- **Numerical Precision:** Adding `FLOAT_MIN` ensures the error metric is never exactly zero, which might be required for certain adaptive stepping logic that checks for "zero error" [S1, unofficial].

This method calculates a relative error metric for adaptive ray marching in scalar volume rendering by weighting the interpolation error based on the distance to a user-specified isovalue $v_{iso}$. Unlike uniform error metrics that treat all regions equally, this approach refines the mesh only in regions where the scalar field values are close to $v_{iso}$, significantly reducing computation time in areas far from the isosurface. It sets itself apart from its sibling [Error Estimate](2768-error-estimate.md) by introducing data-dependence on the exploration parameter ($v_{iso}$) rather than relying solely on geometric or field-range properties.

### Stepsize Annealing
A training strategy that varies the sampling rate $s$ in a range $[s_l, s_h]$ across epochs to benefit from fast convergence at low sampling rates and refinement at high sampling rates [S2, unofficial]. It is a training acceleration method for raymarching models that starts with a high rendering step size in early epochs and decreases it over time to achieve similar performance as training with a constant small step size [S2, unofficial].
**Formula:**
$$ s(e) = s_l \left(1 - \left(\frac{e}{E}\right)^2\right) + \left(\frac{e}{E}\right)^2 s_h $$
where $s(e)$ is the sampling rate at epoch $e$, $s_l$ is the lower bound, $s_h$ is the upper bound, $e$ is the current epoch, and $E$ is the total number of epochs [S2, unofficial].
**Parameters:**
- $s_l$: Lower bound of sampling rate range. Typical value: 0.1 [S2, unofficial].
- $s_h$: Upper bound of sampling rate range. Typical value: 2.0 [S2, unofficial].
**Comparison:**
Stepsize annealing produces visual results comparable to training with a fixed sampling rate of $s=2.0$ but reduces training time by 33.4% on average compared to constant $s=2.0$ [S2, unofficial]. Compared to training with a constant small step size, stepsize annealing achieves similar performance but with accelerated training time [S2, unofficial].
