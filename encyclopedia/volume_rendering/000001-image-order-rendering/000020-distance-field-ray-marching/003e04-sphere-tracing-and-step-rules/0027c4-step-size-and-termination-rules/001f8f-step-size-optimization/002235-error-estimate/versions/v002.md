# Error Estimate
Also called: Relative Error Metric for Adaptive Stepping

## Overview
This method calculates a relative error metric for adaptive ray marching in scalar volume rendering by weighting interpolation error based on the distance to a user-specified isovalue $v_{iso}$ [S1, unofficial]. It sets itself apart from its sibling [Adaptive Step Size Ray Marching](2312-adaptive-step-size-ray-marching.md) by introducing data-dependence on the exploration parameter ($v_{iso}$) rather than relying solely on geometric or field-range properties, significantly reducing computation time in areas far from the isosurface [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   Input: Scalar field values $y$ (vector), interpolation coefficient $k$, threshold value.
*   Output: Relative error metric $E$ (scalar).

**Data Structures:**
*   $y$: A vector representing the scalar field values at the current ray step or interpolation points. In the reference implementation, this is treated as a 3-component vector (e.g., `vec3`) [S1, unofficial].
*   $k$: A scalar coefficient related to the interpolation or step context.
*   threshold: A small positive constant to prevent division by zero.

**Steps:**
1.  Compute the absolute value of the scalar field vector $y$.
2.  Determine the maximum absolute value in $y$: $y_{max} = \max(|y_x|, |y_y|, |y_z|)$.
3.  Calculate the denominator for the relative error: $D = \max(y_{max}, \text{threshold})$.
4.  Compute the relative error vector components: $r_v = k / D$.
5.  Return the maximum component of $r_v$ plus a minimal float value to ensure positivity:
    $$ E = \max(r_v) + \text{FLOAT\_MIN} $$

**Pseudocode:**
```python
def compute_error_estimate(y: Vector3, k: float, threshold: float) -> float:
    """
    Calculate relative error metric for adaptive stepping.
    
    Args:
        y: Scalar field values (vector).
        k: Interpolation coefficient.
        threshold: Minimum denominator value to avoid division by zero.
        
    Returns:
        Relative error metric.
    """
    # Get absolute values
    abs_y = abs(y)
    
    # Find maximum absolute value in the vector
    y_max = max(abs_y.x, max(abs_y.y, abs_y.z))
    
    # Compute denominator with threshold guard
    denominator = max(y_max, threshold)
    
    # Compute relative error components
    # Note: In the source, k is divided by the scalar denominator
    # resulting in a vector if k is scalar? 
    # The source says: r_v = abs(k / max(abs(y), threshold))
    # This implies k is treated as a scalar or broadcast.
    # Let's assume k is scalar and r_v is a vector where each component is k/denominator?
    # Or is k a vector? The source snippet: "r_v = abs(k / max(abs(y), threshold))"
    # If k is scalar, r_v is a vector of identical values k/denominator.
    # If k is vector, it's element-wise. 
    # Given "max(r_v.x, max(r_v.y, r_v.z))", r_v is a vector.
    # Let's assume k is a scalar coefficient for the error bound.
    
    r_v = Vector3(k / denominator, k / denominator, k / denominator)
    
    # Return max component + FLOAT_MIN
    FLOAT_MIN = 1e-8  # Typical small epsilon
    return max(r_v.x, max(r_v.y, r_v.z)) + FLOAT_MIN
```

**Parameters:**
*   `threshold`: Not given in the sources. Typically a small epsilon (e.g., $10^{-8}$) [G].
*   `FLOAT_MIN`: Not given in the sources. Typically the smallest positive normalized float (e.g., $1.17549435 \times 10^{-38}$ for IEEE 754 single precision) [G].

**Edge Cases:**
*   **Zero Field Values:** If $y$ is zero, the denominator becomes the threshold, preventing division by zero.
*   **Large Field Values:** If $y$ is large, the relative error decreases, allowing larger steps.

## Subtopics

### [Data-Dependent Error Metric for Scalar Fields](6981-data-dependent-error-metric-for-scalar-fields.md)
This method calculates a relative error metric for adaptive ray marching in scalar volume rendering by weighting the interpolation error based on the distance to a user-specified isovalue $v_{iso}$. Unlike uniform error metrics that treat all regions equally, this approach refines the mesh only in regions where the scalar field values are close to $v_{iso}$, significantly reducing computation time in areas far from the isosurface. It sets itself apart from its sibling [Error Estimate](2768-error-estimate.md) by introducing data-dependence on the exploration parameter ($v_{iso}$) rather than relying solely on geometric or field-range properties.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per step, involving basic arithmetic operations.
*   **Memory Complexity:** $O(1)$ auxiliary space.
*   **Strengths:** Reduces computation time in regions far from the isosurface by allowing larger steps where the relative error is low [S1, unofficial].
*   **Limitations:** Relies on the accuracy of the scalar field values and the choice of threshold. May not account for high-frequency geometric details if the scalar field is smooth.
*   **When to Use:** Scalar volume rendering where the isosurface is the primary feature of interest.
*   **When Not to Use:** When the entire volume data is important, or when the scalar field has high-frequency noise that requires uniform sampling.

## Background
This method is described in the context of adaptive ray marching for scalar fields, specifically in the `ntsl-graphics` repository [S1, unofficial]. It is used to optimize the step size in ray marching by estimating the error introduced by the current step size relative to the scalar field values.
