# Gap-Limited Ray Marching

Also called: Distance-Proportional Step with Gap Bound, Terrain Ray Marching with Gap Limiting

## Overview
Gap-Limited Ray Marching is a heightfield intersection technique that prevents ray stalling and surface overshooting on ridgelines by combining a distance-proportional step size with a vertical gap bound [S1, unofficial]. Unlike standard sphere tracing which relies on a global distance field, this method uses the local vertical clearance to the terrain surface to cap the step, ensuring the ray never jumps over narrow peaks while maintaining efficiency on flat or gently sloping ground [S1, unofficial]. It builds on [Step Size Optimization](2054-step-size-optimization.md) and [Step Size and Termination Rules](4132-step-size-and-termination-rules.md).

## How it works
**Inputs:**
- Ray origin $(o_x, o_y, o_z)$ and direction $(d_x, d_y, d_z)$, where $d$ is normalized.
- Height field function $H(x, z)$ returning terrain height at horizontal coordinates.
- Parameters: `stepScale` (dimensionless multiplier), `minStep` (float, minimum step size), `maxSteps` (integer), `refineSteps` (integer, bisection iterations), `tMax` (float, maximum ray distance).

**Outputs:**
- Intersection distance $t$ along the ray, or $-1$ if no intersection is found within `tMax`.

**Data Structures:**
- No complex structures required. The height field is accessed via point lookup $H(x, z)$.

**Algorithm:**
1. Initialize $t = 0$.
2. Initialize $t_{prev} = 0$.
3. Loop $i$ from $0$ to `maxSteps` - 1:
   a. Calculate the distance-proportional step:
      $$d_{step} = t \times \text{stepScale}$$
   b. Calculate the current 3D position:
      $$x = o_x + d_x \times t$$
      $$z = o_z + d_z \times t$$
      $$y_{ray} = o_y + d_y \times t$$
   c. Sample the terrain height at the current horizontal position:
      $$h_{surf} = H(x, z)$$
   d. Calculate the vertical gap $h$ (distance from ray to surface):
      $$h = y_{ray} - h_{surf}$$
   e. Calculate the gap-limited step:
      $$g_{step} = h \times 0.5$$
   f. Determine the step size:
      $$step = \min(d_{step}, g_{step})$$
   g. Enforce minimum step size:
      If $step < \text{minStep}$, set $step = \text{minStep}$.
   h. Update previous distance:
      $$t_{prev} = t$$
   i. Advance the ray:
      $$t = t + step$$
   j. Termination check:
      If $t \ge \text{tMax}$, return $-1$.
   k. Surface crossing check:
      If $h \le 0$ (the ray has crossed or touched the surface):
      i. Perform binary search between $t_{prev}$ and $t$ for `refineSteps` iterations:
         - Set $lo = t_{prev}$, $hi = t$.
         - Loop $j$ from $0$ to `refineSteps` - 1:
           - $mid = (lo + hi) \times 0.5$
           - Calculate $y_{mid} = o_y + d_y \times mid$
           - Calculate $x_{mid} = o_x + d_x \times mid$
           - Calculate $z_{mid} = o_z + d_z \times mid$
           - $h_{mid} = y_{mid} - H(x_{mid}, z_{mid})$
           - If $h_{mid} \le 0$, set $hi = mid$
           - Else, set $lo = mid$
      ii. Return $hi$ as the intersection distance.

**Parameters:**
- `stepScale`: Multiplier for the distance-proportional term. Typical value not specified in sources [S1, unofficial].
- `minStep`: Prevents infinite loops on flat surfaces or precision issues [S1, unofficial].
- `maxSteps`: Maximum march iterations [S1, unofficial].
- `refineSteps`: Number of bisection iterations for precision [S1, unofficial].

**Pitfalls:**
- Without the gap limiting term ($h \times 0.5$), the ray can step through the surface on ridgelines, causing holes in the rendered terrain [S1, unofficial]. The gap step ensures the ray never steps more than half the vertical clearance, preventing overshoot [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of steps taken, plus $O(R)$ for the refinement bisection, where $R$ is `refineSteps`.
- **Memory Complexity:** $O(1)$ auxiliary memory, assuming the height field is accessible in $O(1)$ time.
- **Strengths:** Efficiently covers ground on flat or gently sloping terrain due to the distance-proportional step. Guarantees no holes on ridgelines by bounding the step by vertical clearance [S1, unofficial].
- **Limitations:** Performance degrades on highly complex, steep terrain where the gap step forces very small steps. Requires a height field (not a general distance field).
- **When to use:** Heightfield terrain rendering where ridgeline integrity is critical and a global distance field is not available or too expensive to compute [S1, unofficial].
- **When not to use:** General volume rendering or non-heightfield scenes where a true distance field is available (use Sphere Tracing instead).

## Background
This method is described in the context of a software renderer for procedural terrain generation, specifically within the `theme1` project by mingderwang [S1, unofficial]. It is used to intersect rays with a heightfield generated from noise functions and thermal erosion, where baked normals and height lookups are used for rendering [S1, unofficial]. The technique addresses the specific failure mode of standard distance-proportional stepping on sharp terrain features.
