# Gap-Limited Ray Marching

Also called: Distance-Proportional Step with Gap Bound, Terrain Ray Marching with Gap Limiting

## Overview
Gap-Limited Ray Marching is a ray marching algorithm for heightfield terrain that avoids stalling on non-distance fields by using a step size proportional to distance traveled, bounded by half the vertical gap to the surface to prevent overshooting ridgelines [S1, unofficial]. This ensures the ray never overshoots ridgelines while covering more ground per step than fixed-step methods [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $\mathbf{o} = (o_x, o_y, o_z)$ and normalized direction $\mathbf{d} = (d_x, d_y, d_z)$ [S1, unofficial].
- Heightfield function $H(x, z)$ returning surface height at world coordinates [S1, unofficial].
- Parameters: `stepScale` (multiplier for distance-proportional step), `minStep`, `maxSteps`, `refineSteps`, `tMax` [S1, unofficial].

**Outputs:**
- Intersection distance $t$ or $-1$ if no intersection is found within `tMax` [S1, unofficial].

**Data Structures:**
- No persistent data structures; state is held in local variables during the trace [G].

**Algorithm:**
1. Initialize $t = 0$ and compute initial gap $h = o_y - H(o_x, o_z)$ [S1, unofficial].
2. Loop up to `maxSteps`:
   a. Calculate distance-proportional step: $t_{\text{step}} = t \times \text{stepScale}$ [S1, unofficial].
   b. Calculate gap-limited step: $g_{\text{step}} = h \times 0.5$ [S1, unofficial].
   c. Determine step size: $\Delta t = \min(t_{\text{step}}, g_{\text{step}})$ [S1, unofficial].
   d. If $\Delta t < \text{minStep}$, set $\Delta t = \text{minStep}$ [S1, unofficial].
   e. Store previous distance: $t_{\text{prev}} = t$ [S1, unofficial].
   f. Update distance: $t = t + \Delta t$ [S1, unofficial].
   g. If $t \ge t_{\text{Max}}$, return $-1$ [S1, unofficial].
   h. Calculate new vertical gap: $h = (o_y + t \cdot d_y) - H(o_x + t \cdot d_x, o_z + t \cdot d_z)$ [S1, unofficial].
   i. If $h \le 0$, surface crossed. Perform binary search between $t_{\text{prev}}$ and $t$ for `refineSteps` iterations:
      i. $mid = (t_{\text{prev}} + t) \times 0.5$ [S1, unofficial].
      ii. Calculate $h_{\text{mid}} = (o_y + mid \cdot d_y) - H(o_x + mid \cdot d_x, o_z + mid \cdot d_z)$ [S1, unofficial].
      iii. If $h_{\text{mid}} \le 0$, set $hi = mid$ [S1, unofficial].
      iv. Else, set $lo = mid$ [S1, unofficial].
      v. Return $hi$ [S1, unofficial].
3. Return $-1$ (miss) [S1, unofficial].

**Pseudocode:**
```python
def gap_limited_ray_march(o, d, H, stepScale, minStep, maxSteps, refineSteps, tMax):
    t = 0.0
    h = o[1] + t * d[1] - H(o[0] + t * d[0], o[2] + t * d[2])
    for _ in range(maxSteps):
        distanceStep = t * stepScale
        gapStep = h * 0.5
        step = min(distanceStep, gapStep)
        if step < minStep:
            step = minStep
        previousT = t
        t += step
        if t >= tMax:
            return -1
        h = o[1] + t * d[1] - H(o[0] + t * d[0], o[2] + t * d[2])
        if h <= 0:
            lo, hi = previousT, t
            for _ in range(refineSteps):
                mid = (lo + hi) * 0.5
                hm = o[1] + mid * d[1] - H(o[0] + mid * d[0], o[2] + mid * d[2])
                if hm <= 0:
                    hi = mid
                else:
                    lo = mid
            return hi
    return -1
```

**Parameters:**
- `stepScale`: Multiplier for the distance-proportional step term. Typical value not specified [S1, unofficial].
- `minStep`: Prevents infinite loops on flat surfaces or precision issues [S1, unofficial].
- `maxSteps`: Maximum number of march iterations before giving up [S1, unofficial].
- `refineSteps`: Number of bisection iterations to find the precise surface intersection after crossing [S1, unofficial].

**Pitfalls:**
- Without the gap limiting term ($h \times 0.5$), the ray can step through the surface on ridgelines, causing holes [S1, unofficial].
- The gap step ensures the ray never steps more than half the vertical clearance, preventing overshoot [S1, unofficial].

## Background
Originating from practical implementations of terrain rendering in software ray tracers, this method addresses marching rays over heightfields [S1, unofficial]. Standard sphere tracing requires a Signed Distance Function (SDF) with a known Lipschitz constant, but heightfields are not SDFs and their local gradient varies wildly [G]. The gap-limiting technique provides a safe, adaptive step size that scales with distance but is strictly bounded by the local vertical clearance to the surface [S1, unofficial].
