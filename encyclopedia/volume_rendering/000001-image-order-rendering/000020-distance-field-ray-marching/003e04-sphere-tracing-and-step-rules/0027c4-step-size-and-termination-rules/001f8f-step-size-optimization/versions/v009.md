# Step Size Optimization
## Overview
Step Size Optimization dynamically adjusts the step length $\Delta t$ along a ray to balance rendering performance and visual fidelity [S1, S2]. It solves the problem of fixed-step methods wasting samples in empty space or skipping thin geometry and high-frequency details [S1, S2]. It sets itself apart from siblings by adapting $\Delta t$ based on local scene properties (distance field values, projected voxel size, or integration error) rather than using a constant or purely geometric bound [S1, S2].

## Subtopics

### [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md)
Safe Raymarching Step Size determines step length $\Delta t$ to prevent overshooting geometry or density features, particularly with distorted SDFs or neural implicit representations. It sets itself apart by combining clamping of the distance value, a configurable ratio multiplier, and strict boundary checks for numerical stability. Choose it when parallel or recursive marching requires strict safety bounds.

### [Compute Minimal Sample Distance Per Pixel](2684-compute-minimal-sample-distance-per-pixel.md)
This method computes the minimal sample distance per pixel by projecting each dataset cell axis onto the viewport, accounting for camera and volume transforms. It differs from [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md) by using the projected geometric footprint of volume cells rather than local field gradients or distance-field bounds [G]. Choose it for volume rendering where cell projection dictates sampling density.

### [Error Estimate](2768-error-estimate.md)
Error Estimate calculates a relative error metric to guide adaptive stepping, quantifying the deviation of the current sample relative to the local signal magnitude. It sets itself apart by focusing on the *relative* change in the field value rather than the absolute geometric distance, allowing for adaptive precision in regions of high signal variance. Choose it when relative error control is preferred over absolute distance bounds.

### [Gap-Limited Ray Marching](4412-gap-limited-ray-marching.md)
Gap-Limited Ray Marching is a step-size optimization for heightfield terrain rendering that prevents the ray from overshooting ridgelines and creating visual holes. It differs from standard sphere tracing by using a step size proportional to the distance traveled, bounded by half the vertical gap to the surface, rather than the distance field value itself. Choose it for heightfield terrain to avoid stalling on non-distance fields.

### [Adaptive Volume Rendering Integration](9817-adaptive-volume-rendering-integration.md)
Adaptive Volume Rendering Integration (VRI) is an iterative numerical method that evaluates the Volume Rendering Integral using adaptive step sizes for both the inner (transparency) and outer (color) integrals to control accuracy and efficiency. It solves the problem of mapping recursive adaptive integration to GPU architectures by avoiding recursion depth issues and excessive re-computation, allowing step sizes to be controlled in consonance. Choose it for accurate volume rendering where recursive integration is impractical.

### [Adaptive Step Size Control](9843-adaptive-step-size-control.md)
Adaptive Step Size Control is a family of ray marching techniques that dynamically adjust the step size $\Delta t_i$ based on local scene properties to optimize the trade-off between rendering performance and visual quality. It distinguishes itself from siblings like [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md) by explicitly using noise buffers or temporal accumulation to drive variation, and from [Gap-Limited Ray Marching](4412-gap-limited-ray-Marching.md) by its continuous adaptive scaling rather than discrete gap skipping [G]. Choose it when noise-driven or temporal variation guides step adaptation.

### Convexity Enhancement
Convexity Enhancement uses knowledge of convexity to increase step size along the ray; for a convex set, the line segment from the current point to the tangent plane intersection does not intersect the surface except possibly at the endpoint [S1]. This optimization hastens convergence by leveraging convexity properties, providing a faster order of convergence than standard sphere tracing [S1]. The intersection is computed as $\text{lerp}(p, p + d(p) \cdot n(p) / \|n(p)\|) = p + d(p) \cdot v$, and if $d(p) < 0$, the ray does not intersect the implicit surface of $A$ [S1]. Rays parallel to a horizon line (e.g., ground plane) would step at fixed intervals looking for an intersection that never happens; Corollary 4.1 avoids this by detecting if the ray has stepped beyond the object [S1]. In the zeno logo test, convexity enhancement reduced execution time from 26:29 to 19:23 (73% relative time), and for a single sphere, reduced execution time from 2:00 to 1:23 (69% relative time) [S1]. Convexity enhancement causes sphere tracing to converge quadratically, similar to Newton's method, confirmed by the slope on the left of the step-size histogram, whereas standard sphere tracing is linearly convergent [S1].

### FBM Performance Optimization
FBM Performance Optimization reduces octave count based on distance or time parameter $t$ using logarithmic scaling, and uses multi-level LOD with different octave counts for different resolutions (e.g., 3, 9, 16 octaves) [S2]. It uses texture sampling instead of mathematical hash functions for noise generation, manually unrolls small loops and varies lacunarity slightly, and uses adaptive step size based on distance or time [S2]. It also uses a directional derivative instead of a full gradient to reduce sample count from 3 to 1, and terminates the loop early if accumulated amplitude exceeds 0.99 [S2].

## Background
Step size optimization originated from sphere tracing for antialiased ray tracing of implicit surfaces [S1]. Convexity enhancement was introduced to accelerate convergence for convex primitives [S1]. In procedural noise rendering, optimizations such as adaptive step sizing and LOD reduction manage the high cost of Fractal Brownian Motion (FBM) evaluations [S2]. These techniques are widely used in real-time ray marching for terrain, ocean, and implicit surface rendering [S1, S2].
