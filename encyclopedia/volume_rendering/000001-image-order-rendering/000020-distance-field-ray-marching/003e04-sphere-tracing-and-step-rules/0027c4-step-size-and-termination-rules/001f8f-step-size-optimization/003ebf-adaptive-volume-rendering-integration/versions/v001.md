# Adaptive Volume Rendering Integration

Also called: Adaptive Numerical Integration for Volume Rendering, Adaptive VRI evaluation

## Overview
Adaptive Volume Rendering Integration (VRI) is a method for computing the volume rendering integral using adaptive numerical integration with step size control. It separates the computation into an inner integral (handling density/opacity) and an outer integral (handling color/transparency variations) to handle high-frequency variations in the transfer function [S1]. Unlike uniform Riemann summation, which requires prohibitive computational costs to achieve similar accuracy, this method dynamically adjusts step sizes based on local error estimates, offering better accuracy for similar or lower computational costs [S1].

## How it works
The method computes the Volume Rendering Integral (VRI) for a ray segment $[t, t_{final}]$ by iteratively adjusting the step size $h$ based on an error estimate $E(t,h)$. It employs two nested integration procedures: the Inner Integral ($RI$) and the Outer Integral ($RO$).

### Inputs and Outputs
*   **Inputs:**
    *   $t$: Current ray parameter (start of segment).
    *   $t_{final}$: End ray parameter of the segment.
    *   $h^*_0$: Initial step size.
    *   $\epsilon$: Error tolerance.
    *   $h_{min}$: Minimum step size limit.
    *   $h_{max}$: Maximum step size limit.
*   **Outputs:**
    *   $I$: Accumulated VRI vector $[R, G, B, A]$.

### Data Structures
*   **VRI Vector ($I$):** A 4-component vector storing accumulated Red, Green, Blue, and Alpha values. Initialized to $[0, 0, 0, 0]$.
*   **Step Size ($h$):** Floating-point value representing the current integration step.
*   **Error Estimate ($E$):** Floating-point value representing the estimated error of the current step.
*   **Integral Value ($D$):** Floating-point value representing the computed integral for the current step.

### Parameters
*   $h^*_0$: Initial step size. Default experimental value: $0.5$ voxel units [S1].
*   $h_{min}$: Minimum step size. Default experimental value: $0.1$ voxel units [S1].
*   $h_{max}$: Maximum step size. Default experimental value: $2.0$ voxel units [S1].
*   $\epsilon$: Error tolerance. Tested values: $0.01, 0.005, 0.001$ [S1].
*   Precision: GPU implementations typically use single precision (GLSL); CPU implementations use double precision [S1].

### Algorithm Steps

#### 1. Base Adaptive Loop (Algorithm 2)
This loop controls the step size $h$ and tolerance $\epsilon$ based on error estimation.

1.  Initialize $I = 0$, $t_{final} = t + h$, $h = \min(h^*_0, t_{final} - t)$, $lastsucceeded = true$.
2.  Loop while $t < t_{final}$:
    3.  Evaluate error $E(t,h)$.
    4.  If $E(t,h) \le \epsilon$ (Success):
        5.  Add integral $D(t,h) + E(t,h)$ to $I$. [G: Note: The source text says "Add integral D(t,h) + E(t,h) to I". In standard adaptive integration, one adds the integral estimate. The inclusion of E in the addition is likely a typo in the source or refers to adding the integral *and* tracking error, but the pseudocode explicitly writes `I = I + D(t,h) + E(t,h)`. We follow the source literally.]
        6.  Advance $t = t + h$.
        7.  If $lastsucceeded$ was true:
            8.  Double $h$ ($h = 2h$).
            9.  Double $\epsilon$ ($\epsilon = 2\epsilon$).
        10. Else:
            11. Set $lastsucceeded = true$.
        12. Cap $h$ at $t_{final} - t$ ($h = \min(h, t_{final} - t)$).
    13. If $E(t,h) > \epsilon$ (Failure):
        14. Halve $h$ ($h = h/2$).
        15. Halve $\epsilon$ ($\epsilon = \epsilon/2$).
        16. Set $lastsucceeded = false$.
    17. End If.
    18. End Loop.
    19. Return $I$.

#### 2. Inner Integral Procedure ($RI$)
This procedure evaluates the inner integral (density/opacity) to determine a valid step size.

1.  Input: $t$, $dt = t_{final} - t$, $h_{inner}$.
2.  Execute the Base Adaptive Loop (Algorithm 2) restricted to the interval $[t, t+dt]$.
3.  Ensure $h$ stays between $h_{min}$ and $h_{max}$.
4.  Terminate as soon as a valid step size is found (i.e., the first successful step in the adaptive loop).
5.  Return the last step size $h_{inner}$ and the integral value $I_{inner}$.

#### 3. Outer Integral Procedure ($RO$)
This procedure evaluates the outer integral (color/transparency) using the step size determined by the inner integral.

1.  Input: $t$, $h_{inner}$, $h_{outer}$.
2.  Execute the Base Adaptive Loop (Algorithm 2) for the outer integral.
3.  Ensure $h$ stays between $h_{min}$ and $h_{max}$.
4.  Perform integration for all color channels (R, G, B, A).
5.  Iterate until the whole ray is covered.
6.  Inside $RO$, use regular (non-adaptive) Simpson's rule to evaluate the inner integral whenever necessary, as the error is already bounded by the inner step size selection [S1].
7.  Return the last step size $h_{outer}$ and the integral value $I_{outer}$.

#### 4. Coupling Strategies
The method defines how $h_{outer}$ is initialized relative to $h_{inner}$ in the main loop (Algorithm 3).

*   **Coupled Strategy:** The inner integral dictates the initial step size for the outer integral at each evaluation ($h_{outer} = h_{inner}$). This assumes coherence between integrals and allows reuse of intermediate Simpson's values from the inner integral [S1].
*   **Decoupled Strategy:** The outer step is controlled independently. The inner step is only used to limit the integration interval. $h_{outer}$ is initialized separately (e.g., $h_{outer} = h_{inner}$ only for initialization, then controlled independently) [S1].

#### 5. Main Loop (Algorithm 3)
1.  Initialize $I = [R=0, G=0, B=0, A=0]$.
2.  Set $t_{final} = t + h$.
3.  Set $h_{inner} = \min(h^*_0, t_{final} - t)$.
4.  Set $h_{outer} = h_{inner}$ (for decoupled strategy initialization).
5.  Loop while $t < t_{final}$:
    6.  Call $RI(t, t_{final} - t, h_{inner})$ to get $I_{inner}$ and $h_{inner}$.
    7.  If $I_{inner} \neq 0$:
        8.  If Coupled Strategy: Set $h_{outer} = h_{inner}$.
        9.  Call $RO(t, h_{inner}, h_{outer})$ to get $I_{outer}$ and $h_{outer}$.
        10. Add $I_{outer}$ to $I$.
        11. Update $t$ based on outer integration progress (implied by $RO$ returning integral and step info; specifically, $t$ advances by the step taken in $RO$).
    12. End If.
    13. End Loop.
    14. Return $I$.

### Edge Cases and Pitfalls
*   **Missing High-Frequency Features:** Without $h_{max}$, the adaptive step size may become too large, skipping over high-frequency variations such as thin leaves in a Bonsai model [S1].
*   **Numerical Inaccuracies:** Error evaluation has inherent inaccuracies. Even with strict tolerance, some rays may exceed the tolerance limit due to these inaccuracies and the $h_{min}$ floor [S1].
*   **Wrongly Ignored Regions:** High-frequency regions may be wrongly ignored if the error evaluation sampling strategy fails to detect them, especially if the initial step size is too large [S1].
*   **Infinite Halving:** The $h_{min}$ limit prevents infinite halving when the error cannot be estimated precisely [S1].

## Operating characteristics
*   **Accuracy:** Offers better accuracy than Riemann summation for similar or lower computational costs [S1]. For the Bonsai model with $\epsilon=0.001$, the number of rays exceeding tolerance was ~11-15 for Adaptive VRI, compared to thousands for Riemann summation with larger step sizes [S1].
*   **Performance (CPU):** CPU architecture favors adaptive algorithms due to variable step sizes per ray [S1].
*   **Performance (GPU):** GPU SIMD architecture favors Riemann summation because adaptive approaches require different step sizes per thread, reducing parallel efficiency [S1].
*   **Strategy Trade-off:** The Coupled strategy is slightly more efficient; the Decoupled strategy is slightly more accurate, particularly for high-frequency transfer function variations [S1].
*   **Scaling:** Performance depends on the dataset. Models with large transparent regions (e.g., BluntFin) benefit from larger step sizes, while models with fine details (e.g., Bonsai) require smaller steps [S1].

## Background
The method was proposed in a paper titled "Accurate Volume Rendering based on Adaptive Numerical Integration" [S1]. It was tested on datasets from volvis.org (Bonsai, BluntFin, Teapot, Engine) using a 2.66 GHz Quad Core CPU and a GeForce GTX 560 GPU [S1]. The approach builds upon iterative integration methods and introduces the separation of inner and outer integrals to handle the specific challenges of volume rendering, such as varying density and color transfer functions [S1].
