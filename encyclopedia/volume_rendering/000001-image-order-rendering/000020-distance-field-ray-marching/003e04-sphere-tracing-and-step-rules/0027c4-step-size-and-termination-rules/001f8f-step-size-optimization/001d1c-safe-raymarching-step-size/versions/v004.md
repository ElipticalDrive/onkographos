# Safe Raymarching Step Size

Also called: Conservative stepping, Grid Step Size, Ray Marching with SDF-guided Step Size, TensorBase Step Size Calculation

## Overview
Safe Raymarching Step Size is a method for determining the step length in Signed Distance Field (SDF) ray marching that guarantees no surface penetration while mitigating artifacts caused by SDF distortion. It solves the problem where standard sphere tracing overshoots geometry in complex or distorted fields (e.g., those formed by domain repetition or boolean operations) by applying conservative clamping and ratio multipliers to the step size [S1, S2, unofficial]. Unlike standard sphere tracing which uses the raw SDF value, this method introduces explicit safety bounds and termination masks to ensure numerical stability and correct rendering logic [S2, unofficial].

## How it works
The method operates by iteratively advancing a ray along a direction $\mathbf{d}$ from an origin $\mathbf{o}$, computing a safe step size $\Delta t$ at each iteration based on the local SDF value, a clamping threshold, and a marching ratio. It supports both parallel processing of all rays and recursive processing of only unfinished rays [S2, unofficial].

### Inputs and Outputs
**Inputs:**
*   $\mathbf{o}$: Camera origin (position).
*   $\mathbf{d}$: Ray direction (normalized).
*   $f(\mathbf{p})$: SDF evaluation function (e.g., neural decoder or grid lookup).
*   $t_{init}$: Initial depth (often 0).
*   $t_{max}$: Maximum ray distance (maxbound).
*   $N_{steps}$: Maximum number of marching steps.
*   $\lambda_{ratio}$: Ray marching ratio (multiplier for step size). Typical value: $1.5$ [S2, unofficial].
*   $\epsilon_{clamp}$: Clamping threshold for SDF values. Typical value: $0.1$ [S2, unofficial].
*   $\epsilon_{hit}$: Surface hit threshold. Typical value: $5 \times 10^{-5}$ [S2, unofficial].
*   $AABB$: Axis-aligned bounding box of the scene, defined by $[\mathbf{min}, \mathbf{max}]$.
*   $R_{grid}$: Resolution of the voxel grid (if grid-based).

**Outputs:**
*   $\mathbf{p}_{hit}$: Final position of the ray.
*   $t_{hit}$: Accumulated depth.
*   $valid$: Boolean mask indicating if the ray hit the surface within bounds and did not skip it.

### Data Structures
*   **Ray State:** Tensors or arrays storing current depth $t_i$, current position $\mathbf{p}_i$, and validity masks for each ray.
*   **History Lists:** Lists to store the sequence of depths, SDF values, and positions for post-processing or differentiable rendering [S2, unofficial].
*   **Valid Mask:** A boolean array indicating which rays are still active (have not hit the surface, escaped, or exceeded $N_{steps}$).

### Step-by-Step Method

1.  **Initialization:**
    *   Initialize current depth $t_0 = t_{init}$ for all rays.
    *   Initialize valid mask $M_{valid}$ to all `True`.
    *   Initialize history lists: $L_{depth}$, $L_{sdf}$, $L_{pos}$ as empty.
    *   Compute $t_{max}$ based on the AABB diagonal length and ray direction if not provided [S3, unofficial].

2.  **Iterative Marching (for $i = 0$ to $N_{steps}-1$):**
    *   **Compute Position:** Calculate current position $\mathbf{p}_i = \mathbf{o} + t_i \mathbf{d}$.
    *   **SDF Evaluation:** Evaluate $s_i = f(\mathbf{p}_i)$. If using a neural decoder, detach gradients if necessary for non-differentiable modes [S2, unofficial].
    *   **Clamping:** Clamp the SDF value to prevent extreme steps:
        $$ s_{clamped} = \max(-\epsilon_{clamp}, \min(s_i, \epsilon_{clamp})) $$
    *   **Step Size Calculation:**
        *   If using grid-based bounds, compute unit size $u$ from AABB dimensions and grid resolution $R_{grid}$:
            $$ u = \frac{\|\mathbf{max} - \mathbf{min}\|}{R_{grid}} $$
            $$ \Delta t_{grid} = u \times \lambda_{ratio} $$
        *   If using SDF-guided stepping, compute:
            $$ \Delta t_{sdf} = s_{clamped} \times \lambda_{ratio} $$
        *   Select $\Delta t_i$. In conservative implementations, $\Delta t_i$ is often set to $s_{clamped} \times \lambda_{ratio}$ but bounded by grid constraints or a minimum step to avoid infinite loops [S2, S3, unofficial]. Note: Standard sphere tracing uses $\Delta t = s_i$, but Safe Raymarching uses $\lambda_{ratio} > 1.0$ or clamping to handle distortion [S1, S2, unofficial].
    *   **Update Depth:**
        $$ t_{i+1} = t_i + \Delta t_i $$
    *   **Record History:** Append $t_{i+1}$, $s_i$, and $\mathbf{p}_i$ to $L_{depth}$, $L_{sdf}$, $L_{pos}$.

3.  **Termination and Validation:**
    *   **Hit Detection:** Check if the minimum absolute SDF value across all steps is below the hit threshold:
        $$ M_{hit} = \min_i(|s_i|) \le \epsilon_{hit} $$
    *   **Boundary Check:** Check if the final depth exceeds the maximum bound:
        $$ M_{bound} = t_{final} \le t_{max} $$
    *   **First Query Check:** Handle the corner case where the first query is already below the threshold (immediate hit). If $s_0 \le \epsilon_{hit}$, ensure the ray is marked as valid hit to prevent filtering out immediate intersections [S2, unofficial].
        $$ M_{first} = (s_0 > \epsilon_{hit}) \lor (M_{hit}) $$
    *   **Final Validity:**
        $$ M_{valid\_final} = M_{valid} \land M_{hit} \land M_{bound} \land M_{first} $$

4.  **Output:**
    *   Return the accumulated depth, SDF values, positions, and the final validity mask.

### Edge Cases and Pitfalls
*   **SDF Distortion:** Domain repetition or boolean operations can distort the SDF, causing the estimated distance to be larger than the actual distance. This leads to overshooting. The solution is to step shorter than the SDF returns, achieved by clamping and ratio multipliers [S1, unofficial].
*   **Immediate Hit:** If the first SDF query is already below the threshold, standard logic might filter it out. A specific check (`valid_mask_first_query`) is required to handle this corner case [S2, unofficial].
*   **Boundary Escape:** Rays must not exceed the maximum bound ($t_{max}$). This is checked against the final accumulated depth [S2, unofficial].
*   **Precision:** Clamping prevents numerical instability from very large SDF values in empty space [S2, unofficial].

## Subtopics

### [Distance Accuracy vs Performance Trade-off](1546-distance-accuracy-vs-performance-trade-off.md)
Analyzes the inverse relationship between SDF evaluation accuracy and computational cost. Underestimating distance forces smaller steps, increasing iterations. An exact but slower SDF can outperform an inaccurate but fast one if the inaccuracy causes disproportionate step reduction.

### [Adaptive Lipschitz Constant (ALC)](1883-adaptive-lipschitz-constant-alc.md)
Uses a nested BVH to compute tighter, adaptive Lipschitz constants for step size, avoiding the overly conservative global constant in large scenes.

### [Gradient-based Sphere Tracing with Lipschitz Constraints](1936-gradient-based-sphere-tracing-with-lipschitz-constraints.md)
Uses local SDF gradients to compute larger, safer step sizes, particularly near silhouettes, by combining first and second Lipschitz constraints.

### [Lipschitz Step Size Ray Marching](3729-lipschitz-step-size-ray-marching.md)
Uses a pre-computed global Lipschitz constant to guarantee no surface penetration, offering simplicity and stability at the cost of efficiency in complex scenes.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot K)$, where $N$ is the number of rays and $K$ is the average number of steps. $K$ depends on the scene complexity and the accuracy of the SDF. Conservative stepping may increase $K$ compared to aggressive stepping [S1, S2, unofficial].
*   **Memory Complexity:** $O(N \cdot K)$ if history is stored for all steps (e.g., for differentiable rendering). $O(N)$ if only the final state is kept [S2, unofficial].
*   **Strengths:** Robust against SDF distortion artifacts; guarantees no surface penetration; handles complex implicit surfaces well [S1, S2, unofficial].
*   **Limitations:** Conservative stepping can lead to more iterations than necessary in smooth regions; clamping may reduce accuracy near the surface if $\epsilon_{clamp}$ is too small [S1, S2, unofficial].
*   **When to Use:** When rendering distorted SDFs (e.g., CSG operations, domain repetition) or when numerical stability is critical [S1, S2, unofficial].
*   **When Not to Use:** When performance is paramount and the SDF is known to be well-behaved (use standard sphere tracing) [S1, unofficial].

## Background
Safe Raymarching Step Size originates from the need to render complex implicit surfaces defined by Signed Distance Fields without artifacts. The concept of stepping shorter than the SDF value to mitigate distortion artifacts was highlighted in early raymarching tutorials [S1, unofficial]. The specific implementation details involving clamping, ratio multipliers, and validity masks for differentiable rendering (e.g., in neural radiance fields or deep SDF optimizers) are found in repositories like DIST-Renderer and Collaborative Neural Radiance Fields [S2, S3, unofficial].
