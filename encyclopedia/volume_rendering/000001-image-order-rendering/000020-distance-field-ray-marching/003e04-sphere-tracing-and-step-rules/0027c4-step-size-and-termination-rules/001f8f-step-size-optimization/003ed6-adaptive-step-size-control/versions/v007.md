# Adaptive Step Size Control

Also called: Adaptive Step Size Controller, Integrator Step Controller, Step Safety Factor

## Overview
Adaptive Step Size Control is a family of techniques that dynamically adjust the ray marching interval $\Delta t$ during volume rendering to balance computational cost and visual fidelity [S1, S2, unofficial]. Unlike fixed-step methods that enforce a uniform trade-off, these methods vary the sampling density based on local scene properties (such as density gradients, emptiness, or statistical variance) or user interaction state [S1, S2, unofficial]. This family is distinguished from its siblings by its focus on the *mechanism* of step size selection: [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md) relies on Lipschitz bounds for safety, [Compute Minimal Sample Distance Per Pixel](2684-compute-minimal-sample-distance-per-pixel.md) uses precomputed per-pixel metrics, [Error Estimate](2768-error-estimate.md) targets integration error, [Gap-Limited Ray Marching](4412-gap-limited-ray-marching.md) handles sparse data gaps, and [Adaptive Volume Rendering Integration](9817-adaptive-volume-rendering-integration.md) focuses on integration accuracy.

## Shared principles
The core mechanism involves evaluating a condition $C$ at or near the current ray position $t$ to determine the next step size $\Delta t_{new}$. The general loop structure is:
1.  Evaluate scene data at current position.
2.  Compute a metric (e.g., density difference, variance, emptiness).
3.  Map the metric to a step size factor or absolute step size.
4.  Clamp the step size to global bounds $[\Delta t_{min}, \Delta t_{max}]$.
5.  Advance the ray: $t_{new} = t_{old} + \Delta t_{new}$.

Common parameters include:
*   $\Delta t_{min}$: Absolute minimum step size to prevent infinite loops or excessive sampling in high-frequency regions. Typical value: $10^{-6}$ [S1, unofficial].
*   $\Delta t_{max}$: Absolute maximum step size to prevent aliasing or skipping features. Typical value: $10$ [S1, unofficial].
*   Growth/Shrink factors: Limits on how much the step size can change per iteration to prevent oscillation. $GROWTH\_MAX = 5$ and $GROWTH\_MIN = 0.2$ are typical bounds [S1, unofficial].

## Subtopics

### [Adaptive Step Size Ray Marching](2312-adaptive-step-size-ray-marching.md)
Optimizes cost by varying sampling intervals based on local density changes and transmittance. It uses fine steps in high-density regions and coarse steps in empty space, often combined with early termination. Choose this for real-time cloud or fluid rendering where density gradients are the primary visual cue.

### [Dynamic Sampling Step Adjustment](2442-dynamic-sampling-step-adjustment.md)
Increases step size exponentially when traversing empty space (zero density) and resets upon encountering geometry. It distinguishes itself by using binary density presence rather than gradient magnitude. Choose this for sparse volumes or SDFs with large empty regions.

### [Adaptive Step Size for Interaction](6615-adaptive-step-size-for-interaction.md)
Maintains high frame rates during user interaction by dynamically increasing the sampling step size, accepting lower visual fidelity. It differs from geometry-dependent methods by being time-dependent (interaction state). Choose this for interactive viewers where responsiveness is prioritized over static image quality.

### [Variance-based Step Size Adaptation](13161-variance-based-step-size-adaptation.md)
Determines step size by calculating the statistical variance of voxel data within spatial partitions ("bricks") during preprocessing. It maps brick variance to a scaling coefficient. Choose this for large, static volume datasets where preprocessing cost is acceptable and high-frequency detail preservation is critical.

### Adaptive Stepsize Rendering
*   **Definition**: A rendering method where the ray marching step size is provided per-pixel via an input tensor, allowing for variable sampling density across the image [S2, unofficial].
*   **Step**: The PyTorch wrapper `adaptiveStepsizeRendering` asserts that the input `stepsizes` tensor has shape $B \times 1 \times H \times W$ and $C=1$ [S2, unofficial]. The stepsizes tensor is moved to the CUDA device [S2, unofficial]. For each batch item, the renderer settings are sent to update the renderer state [S2, unofficial]. The viewport dimensions are extracted from settings and asserted to match the $H$ and $W$ of the stepsizes tensor [S2, unofficial]. The stepsizes tensor is padded to match the viewport requirements [S2, unofficial].
*   **Parameter**: `fd_epsilon`: A float parameter with default value $10^{-5}$, used for gradient propagation support [S2, unofficial].
*   **Layout**: Input tensor `stepsize` is a float tensor on the GPU of size $H \times W$ with only positive values [S2, unofficial]. Output tensor `output` is a float tensor on the GPU of size $B \times H \times W$ with $B=8$ channels: 0=mask, 1=normalX, 2=normalY, 3=normalZ, 4=depth, 5=ao, 6=flowX, 7=flowY [S2, unofficial].
*   **Comparison**: Unlike standard rendering which uses a uniform or pre-computed step size, this method accepts a per-pixel tensor of step sizes, enabling adaptive sampling based on importance maps [S2, unofficial].

## Background
Adaptive step size control originated as a necessity for efficient volume rendering, where fixed step sizes either waste computation in empty space or fail to capture detail in dense regions. Early implementations focused on density-based heuristics for cloud rendering [S1, S2, unofficial]. The variance-based approach was introduced to handle large medical and scientific datasets by precomputing complexity metrics [S1, unofficial]. Interactive adaptive stepping emerged with the need for real-time feedback in visualization tools [S2, unofficial]. Modern implementations often integrate these techniques with temporal accumulation and deep learning-based reconstruction [S2, unofficial].
