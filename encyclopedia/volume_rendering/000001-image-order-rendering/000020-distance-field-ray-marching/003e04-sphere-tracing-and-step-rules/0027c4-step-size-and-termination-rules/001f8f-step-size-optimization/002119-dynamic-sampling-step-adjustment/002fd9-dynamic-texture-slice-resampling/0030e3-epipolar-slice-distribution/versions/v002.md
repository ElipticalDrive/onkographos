# Epipolar Slice Distribution

Also called: Non-uniform Slice Spacing, Sinh-based Slice Placement

## Overview
Epipolar Slice Distribution is a non-uniform sampling strategy that distributes epipolar slices along the image perimeter to guarantee proper sampling density while minimizing the total number of slices [S1]. It strictly bounds the maximum sampling error to half a pixel without requiring upsampling techniques, unlike methods that relax this criterion and rely on joint bilateral upsampling [S1]. The approach achieves tighter sampling efficiency, particularly when the epipole is near screen corners [S1].

## How it works
**Inputs and Outputs:**
*   Screen resolution (width $W$, height $H$) [S1].
*   Epipole position $(e_x, e_y)$ in normalized screen coordinates [S1].
*   Pixel size $P$ in normalized screen coordinates (resolution-dependent) [S1].
*   Output: A set of slice selector coordinates $\alpha$ that define the epipolar slices [S1].

**Data Structures:**
*   List of tuples containing $(\alpha, x)$ values, where $\alpha$ is the slice selector coordinate and $x$ is the intersection location on the screen edge [S1].

**Numbered Steps:**
1.  **Coordinate Setup:** If the epipole is not at the origin, scale the screen geometry down uniformly, apply the formula, and scale the resulting coordinates back up [S1]. Assume the epipole is at the origin $(0,0)$ and one screen edge is the horizontal line $y = -1$ [S1].
2.  **Derive Intersection Function:** Let $\theta(\alpha) = \arctan(x(\alpha))$ be the angle of the ray intersecting the x-axis at $x(\alpha)$ on the line $y=-1$ [S1]. The orthogonal distance from the point $(x, -1)$ to the ray intersecting at $(x+dx, -1)$ is $\frac{dx}{\sqrt{1+x^2}}$ [S1]. Set this distance equal to the pixel size $P$ for a small increment $d\alpha$, yielding the differential equation $\frac{dx}{\sqrt{1+x(\alpha)^2}} = d\alpha$ with initial condition $x(0) = 0$ [S1]. Integrating this equation gives the intersection location function $x(\alpha) = \sinh(\alpha)$, where $x(\alpha)$ is the intersection location on the screen edge $y = -1$ and $\alpha$ is the slice selector coordinate [S1].
3.  **Generate Slices:** Step along $\alpha$ in equal increments of $d\alpha = P$ [S1]. Calculate $x(\alpha) = \sinh(\alpha)$ for each step [S1]. Continue until the entire edge is sampled [S1]. Treat other screen edges analogously [S1].

**Formulas:**
*   Differential equation: $\frac{dx}{\sqrt{1+x(\alpha)^2}} = d\alpha$, with $x(0) = 0$ [S1].
*   Intersection function: $x(\alpha) = \sinh(\alpha)$ [S1].
*   Step size: $d\alpha = P$ [S1].

**Parameters:**
*   $P$: The resolution-dependent pixel size in normalized screen coordinates, used as the uniform step increment for $\alpha$ [S1].

**Edge Cases and Pitfalls:**
*   **Epipole Position:** If the epipole is not at the origin, the geometry must be scaled uniformly, the formula applied, and then scaled back [S1]. Failure to apply this uniform scaling results in incorrect sampling density [S1].
*   **Boundary Conditions:** The method assumes the screen edges are straight lines in the normalized coordinate system [S1]. Degenerate cases where the epipole lies exactly on an edge may require special handling to avoid infinite $\alpha$ values [G].
*   **Precision:** The use of `sinh` and `asinh` requires careful handling of floating-point precision, especially for large $\alpha$ values near screen corners [G].

**Pseudocode:**
```python
import math

def generate_epipolar_slices(edge_x_min, edge_x_max, pixel_size_p):
    """
    Generates non-uniform slice distributions along a single screen edge.
    Assumes normalized coordinates where the epipole is at (0,0) and the edge is at y = -1.
    """
    slices = []
    # Compute alpha bounds from the edge x-bounds using the inverse of x(alpha) = sinh(alpha)
    alpha_min = math.asinh(edge_x_min)
    alpha_max = math.asinh(edge_x_max)

    alpha = alpha_min
    while alpha <= alpha_max:
        x = math.sinh(alpha)
        slices.append((alpha, x))
        alpha += pixel_size_p

    return slices
```

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** In a 1280x960 resolution, this method uses 15% fewer slices than uniform sampling when the epipole is in the center of the screen [S1]. When the epipole is near a corner, it uses half the number of slices [S1].
*   **Strengths:** Guarantees a strict half-pixel bound on sampling error without requiring upsampling [S1]. Reduces oversampling compared to uniform spacing [S1].
*   **Limitations:** Requires non-uniform spacing logic, which may complicate implementation compared to uniform grids [G].

## Background
Epipolar Slice Distribution was introduced in the context of hierarchical volumetric shadow algorithms for single scattering [S1]. It was developed to improve the efficiency of epipolar slice sampling by reducing the number of slices needed while maintaining strict sampling criteria, contrasting with earlier approaches like Engelhardt and Dachsbacher [2010] which relaxed the one-pixel criterion and used joint bilateral upsampling [S1].
