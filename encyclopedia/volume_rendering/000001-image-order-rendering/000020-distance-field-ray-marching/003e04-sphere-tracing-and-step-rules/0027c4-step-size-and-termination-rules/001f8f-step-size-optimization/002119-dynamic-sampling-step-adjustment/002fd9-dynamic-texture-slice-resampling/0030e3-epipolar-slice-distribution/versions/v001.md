# Epipolar Slice Distribution

Also called: Non-uniform Slice Spacing, Sinh-based Slice Placement

## Overview
Epipolar Slice Distribution is a non-uniform sampling strategy for distributing epipolar slices along the image perimeter to guarantee proper sampling density while minimizing the total number of slices [S1]. It ensures that no screen pixel is further than half a pixel from an epipolar line, strictly bounding the maximum sampling error without requiring upsampling techniques [S1]. Unlike methods that relax this criterion and rely on joint bilateral upsampling, this approach achieves tighter sampling efficiency, particularly when the epipole is near screen corners [S1].

## How it works
**Inputs:**
*   Screen resolution (width $W$, height $H$).
*   Epipole position $(e_x, e_y)$ in normalized screen coordinates.
*   Pixel size $P$ in normalized screen coordinates (resolution-dependent).

**Outputs:**
*   A set of slice selector coordinates $\alpha$ that define the epipolar slices.

**Data Structures:**
*   List of $\alpha$ values.

**Method:**
The distribution is derived by ensuring that the orthogonal distance between adjacent slice intersections on the screen edge equals the pixel size $P$ when $\alpha$ is incremented uniformly.

1.  **Coordinate System Setup:**
    *   If the epipole is not at the origin $(0,0)$, scale the screen geometry down uniformly such that the epipole is at $(0,0)$, apply the formula, and scale the resulting coordinates back up [S1].
    *   Assume the epipole is at the origin.
    *   Consider a screen edge defined by the horizontal line $y = -1$ [S1].

2.  **Derive Intersection Function:**
    *   Let $\theta(\alpha) = \arctan(x(\alpha))$ be the angle of the ray intersecting the x-axis at $x(\alpha)$ on the line $y=-1$ [S1].
    *   The orthogonal distance from the point $(x, -1)$ to the ray intersecting at $(x+dx, -1)$ is given by $\frac{dx}{\sqrt{1+x^2}}$ [S1].
    *   Set this distance equal to the pixel size $P$ for a small increment $d\alpha$. This yields the differential equation:
        $$ \frac{dx}{\sqrt{1+x(\alpha)^2}} = d\alpha $$
        with initial condition $x(0) = 0$ [S1].
    *   Integrating this equation gives the intersection location function:
        $$ x(\alpha) = \sinh(\alpha) $$
        where $x(\alpha)$ is the intersection location on the screen edge $y = -1$ and $\alpha$ is the slice selector coordinate [S1].

3.  **Generate Slices:**
    *   Step along $\alpha$ in equal increments of $d\alpha = P$ [S1].
    *   Calculate $x(\alpha) = \sinh(\alpha)$ for each step.
    *   Continue until the entire edge is sampled [S1].
    *   Treat other screen edges analogously by rotating the coordinate system or applying the same logic relative to the epipole [S1].

```python
    """
    # 1. Handle epipole not at origin by scaling
    # Scale factor to map epipole to (0,0)
    scale_x = 1.0 / epipole_x if epipole_x != 0 else 1.0

    # Note: The source implies uniform scaling. If epipole is at (ex, ey),

    # If epipole is not at (0,0), we must scale the screen dimensions.
    
    # Let's assume normalized coordinates where epipole is at (0,0)
    # and the relevant edge is y = -1.
    
    # 2. Determine pixel size P
    # P is the resolution-dependent pixel size in normalized screen coordinates.
    # Assuming normalized device coordinates range [-1, 1] or similar.
    # The source does not specify the exact normalization range, 
    # but P is derived from resolution.
    # For a 1280x960 screen, if normalized range is [-1, 1] in x and [-aspect, aspect] in y:
    # P_x = 2.0 / screen_width
    # P_y = 2.0 * (screen_height / screen_width) / screen_height = 2.0 / screen_width (if square pixels)
    # The source uses P as a scalar step in alpha.
    P = 2.0 / screen_width # Approximation for normalized x-axis pixel size
    
    slices = []
    
    # 3. Sample along one edge (y = -1)
    # x(alpha) = sinh(alpha)
    # We step alpha by P.
    # We need to determine the range of alpha to cover the edge.
    # The edge extends from x_min to x_max.
    # alpha_min = asinh(x_min)
    # alpha_max = asinh(x_max)
    
    # Assuming the edge spans from -infinity to +infinity in the local coordinate system
    # or bounded by the screen corners.
    # Let's assume the edge is bounded by the screen corners.
    # If epipole is at (0,0) and edge is y=-1, the corners are at (-W/2, -1) and (W/2, -1)
    # in a coordinate system where the epipole is centered? 
    # The source says "assume epipole is at origin... edge is y=-1".
    # This implies a local coordinate system.
    
    # Let's implement the generation for one edge.
    # We need the bounds of the edge in x.
    # If the screen is W x H, and epipole is at center, corners are at +/- W/2, +/- H/2.
    # If we map to y=-1, the x bounds depend on the aspect ratio and epipole position.
    # The source does not give explicit bounds calculation, only the distribution formula.
    # We will generate slices for a generic range [-X_max, X_max].
    
    X_max = 1.0 # Placeholder for normalized edge extent
    alpha_min = math.asinh(-X_max)
    alpha_max = math.asinh(X_max)
    
    alpha = alpha_min
    while alpha <= alpha_max:
        x = math.sinh(alpha)
        slices.append({'alpha': alpha, 'x': x})
        alpha += P
        
    return slices
```

**Parameters:**
*   $P$: The resolution-dependent pixel size in normalized screen coordinates. It serves as the step size for $\alpha$ [S1].

**Edge Cases and Pitfalls:**
*   **Epipole Position:** If the epipole is not at the origin, the geometry must be scaled uniformly, the formula applied, and then scaled back [S1]. Failure to do so results in incorrect sampling density.
*   **Precision:** The use of `sinh` and `asinh` requires careful handling of floating-point precision, especially for large $\alpha$ values near screen corners [S1].
*   **Boundary Conditions:** The method assumes the screen edges are straight lines in the normalized coordinate system. Degenerate cases where the epipole lies exactly on an edge may require special handling to avoid division by zero or infinite $\alpha$ values [G].

## Operating characteristics
*   **Time Complexity:** Generating the slice distribution is $O(N)$ where $N$ is the number of slices, determined by the perimeter length and pixel size $P$.
*   **Memory Complexity:** $O(N)$ to store the slice coordinates.
*   **Performance:** In a 1280x960 resolution, this method uses 15% fewer slices than uniform sampling when the epipole is in the center of the screen [S1]. When the epipole is near a corner, it uses half the number of slices [S1].
*   **Strengths:** Guarantees a strict half-pixel bound on sampling error without requiring upsampling [S1]. Reduces oversampling compared to uniform spacing [S1].
*   **Limitations:** Requires non-uniform spacing logic, which may complicate implementation compared to uniform grids [S1].

## Background
Epipolar Slice Distribution was introduced in the context of hierarchical volumetric shadow algorithms for single scattering [S1]. It was developed to improve the efficiency of epipolar slice sampling by reducing the number of slices needed while maintaining strict sampling criteria, contrasting with earlier approaches like Engelhardt and Dachsbacher [2010] which relaxed the one-pixel criterion and used joint bilateral upsampling [S1].
