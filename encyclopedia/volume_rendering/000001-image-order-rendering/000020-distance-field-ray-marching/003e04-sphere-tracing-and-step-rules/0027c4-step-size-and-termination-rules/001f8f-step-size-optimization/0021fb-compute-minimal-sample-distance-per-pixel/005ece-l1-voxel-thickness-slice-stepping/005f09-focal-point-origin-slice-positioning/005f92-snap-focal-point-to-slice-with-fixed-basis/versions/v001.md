# Snap Focal Point to Slice with Fixed Basis

Also called: planarSliceBasis, snapFocalPointToSlice

## Overview
This method defines a deterministic, idempotent mapping from a user-defined focal point to a discrete slice index in volume rendering. It solves the problem of non-returning round trips and inconsistent snapping that occurs when slice grids are computed relative to the current focal point or volume bounds with floating-point rounding errors. Unlike the flawed current implementation which introduces a scale factor $k \neq 1$, this method anchors all slice positions to a single, fixed basis focal point provided by the application, ensuring that $basis + m \cdot T_v$ yields exact, consistent positions [S1, unofficial].

## How it works
**Inputs:**
- `basis`: The fixed focal point (3D vector) provided by the application. This is the anchor for the slice grid.
- `m`: The integer slice index.
- `T_v`: The voxel thickness (step size) along the viewing normal.

**Outputs:**
- `position`: The 3D coordinate of the slice plane origin.

**Data Structures:**
- No complex data structures are required. The method relies on vector arithmetic. The `basis` is a single 3D vector.

**Steps:**
1. The application provides a fixed `basis` focal point. This point is not the volume minimum corner, nor is it the current dynamic focal point. It is the reference origin for the slice grid [S1, unofficial].
2. Calculate the slice position using the linear formula:
   $$ position = basis + m \cdot T_v $$
   where:
   - $basis$ is the fixed basis focal point vector.
   - $m$ is the integer slice index.
   - $T_v$ is the voxel thickness (scalar).
3. The `snapFocalPointToSlice` function must use this single basis and rule to determine the nearest slice index $m$ for a given input point.
4. The `planarSliceBasis` function must use the same basis and rule to map indices to absolute positions. This ensures both conventions agree [S1, unofficial].

**Pitfalls:**
- **Scale Factor Error:** The previous implementation computed $f = (current - min) / (max - min) \cdot steps$, where $steps = round((max - min) / spacing)$. This introduced a scale factor $k = steps \cdot spacing / (max - min)$ which is not 1. For example, in a 41x41x41 voxel volume (1mm voxels) at 30 degrees oblique, $k = 1.00656985$ [S1, unofficial].
- **Non-Idempotency:** Without a fixed basis, snapping is not idempotent. A second call to the snap moves the focal point again, and the sequence converges but does not stop at the first value [S1, unofficial].
- **Round Trip Error:** A round trip (+1 step then -1 step) does not return to the start. For an oblique 45-degree angle with 1mm voxels, the error is $8.6 \times 10^{-3}$ mm [S1, unofficial].
- **Ambiguity:** Without a fixed basis, multiple snap positions can exist for points within one slice, causing voxels near boundaries to jump between planes [S1, unofficial].

**Pseudocode:**
```python
def calculate_slice_position(basis, m, T_v):
    """
    Calculate the absolute position of a slice given a fixed basis.
    
    Args:
        basis (Vector3): The fixed focal point provided by the application.
        m (int): The slice index.
        T_v (float): The voxel thickness (step size).
        
    Returns:
        Vector3: The position of the slice plane.
    """
    # The position is strictly linear from the basis
    return basis + m * T_v

def snap_to_slice(input_point, basis, T_v, normal):
    """
    Snap an input point to the nearest slice index using the fixed basis.
    
    Args:
        input_point (Vector3): The current focal point to snap.
        basis (Vector3): The fixed basis focal point.
        T_v (float): The voxel thickness.
        normal (Vector3): The viewing normal (unit vector).
        
    Returns:
        int: The snapped slice index m.
    """
    # Project the vector from basis to input_point onto the normal
    # This gives the signed distance from the basis along the normal
    diff = input_point - basis
    distance = dot(diff, normal)
    
    # Calculate the slice index
    # Note: The sources do not specify the rounding mode (floor, round, ceil).
    # Standard practice is rounding to nearest integer for snapping.
    m = round(distance / T_v)
    
    return m
```

## Operating characteristics
- **Time Complexity:** $O(1)$ for both position calculation and snapping.
- **Memory Complexity:** $O(1)$.
- **Accuracy:** Eliminates the scale factor error ($k \neq 1$) and round-trip errors. For a 41x41x41 volume at 30 degrees, the previous error was $7.4 \times 10^{-3}$ mm; this method ensures exact returns [S1, unofficial].
- **Strengths:** Idempotent snapping, consistent round trips, single snap position per slice.
- **Limitations:** Requires the application to provide and maintain a fixed `basis` focal point. If the basis changes, the entire grid shifts.

## Background
This method addresses implementation requirements identified in the cornerstone3D project. The previous implementation of `snapFocalPointToSlice` and `planarSliceBasis` used inconsistent conventions, leading to visual artifacts and navigation issues in oblique volume rendering. The fix was proposed to ensure that slice positions are anchored to a user-defined basis, resolving issues with non-idempotent snaps and round-trip errors [S1, unofficial].
