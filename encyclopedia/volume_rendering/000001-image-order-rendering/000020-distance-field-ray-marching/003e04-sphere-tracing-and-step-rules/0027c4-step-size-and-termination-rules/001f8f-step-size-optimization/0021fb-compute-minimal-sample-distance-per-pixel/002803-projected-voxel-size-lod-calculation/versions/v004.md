# Projected Voxel Size / LOD Calculation

Also called: ComputeVoxelSize

## Overview
Projected Voxel Size / LOD Calculation computes a scalar metric representing the projected size of a voxel relative to the camera, primarily used for Level-of-Detail (LOD) decisions and step size adaptation in volume rendering [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Camera position ($\mathbf{C}$), voxel center ($\mathbf{V}$), and voxel half-size vector ($\mathbf{h}$) [S1, unofficial].
- Output: A scalar projected size metric $S$ [S1, unofficial].

**Data Structures:**
- Voxel geometry is defined by its center $\mathbf{V}$ and half-extents $\mathbf{h} = (h_x, h_y, h_z)$ [S1, unofficial].
- Camera geometry is defined by origin $\mathbf{C}$ [S1, unofficial].

**Steps:**
1. Compute the lower-left (LL) and upper-right (UR) corners of the voxel half-size box: $\mathbf{P}_{LL} = \mathbf{V} - \mathbf{h}$ and $\mathbf{P}_{UR} = \mathbf{V} + \mathbf{h}$ [S1, unofficial].
2. Compute vectors from the camera position to these corners: $\mathbf{v}_{LL} = \mathbf{P}_{LL} - \mathbf{C}$ and $\mathbf{v}_{UR} = \mathbf{P}_{UR} - \mathbf{C}$ [S1, unofficial].
3. Normalize these vectors to obtain $\mathbf{u}_{LL}$ and $\mathbf{u}_{UR}$ [S1, unofficial]. Guard against zero-length vectors to prevent division by zero [G].
4. Calculate the dot product of the normalized vectors [S1, unofficial].
5. Return $S = 1.0 - \mathbf{u}_{LL} \cdot \mathbf{u}_{UR}$ [S1, unofficial].

**Formula:**
$$ S = 1 - \mathbf{u}_{LL} \cdot \mathbf{u}_{UR} $$
Where:
- $S$ is the projected size metric [S1, unofficial].
- $\mathbf{u}_{LL}$ is the normalized vector from the camera to the lower-left corner of the voxel [S1, unofficial].
- $\mathbf{u}_{UR}$ is the normalized vector from the camera to the upper-right corner of the voxel [S1, unofficial].

**Parameters:**
- Not given in the sources.

**Edge Cases and Pitfalls:**
- **Camera at Voxel Center:** If the camera is located exactly at the voxel center, the vectors are identical, leading to $\mathbf{u}_{LL} \cdot \mathbf{u}_{UR} = 1$ and $S = 0$ [S1, unofficial].
- **Near-Plane Degeneracy:** The metric lacks explicit clamping or fallback for degenerate near-plane cases where the voxel intersects the camera plane [S1, unofficial]. Division by zero during normalization must be guarded [G].

**Pseudocode:**
```python
import math

def compute_projected_voxel_size(camera_pos, voxel_center, voxel_half_size):
    """
    Computes the projected size metric for a voxel.
    
    Args:
        camera_pos: (x, y, z) camera position.
        voxel_center: (x, y, z) voxel center.
        voxel_half_size: (x, y, z) half-extents of the voxel.
        
    Returns:
        S: Scalar projected size metric.
    """
    # 1. Compute corners of the voxel half-size box
    p_ll = (voxel_center[0] - voxel_half_size[0],
            voxel_center[1] - voxel_half_size[1],
            voxel_center[2] - voxel_half_size[2])
    p_ur = (voxel_center[0] + voxel_half_size[0],
            voxel_center[1] + voxel_half_size[1],
            voxel_center[2] + voxel_half_size[2])
    
    # 2. Compute vectors from camera to corners
    v_ll = (p_ll[0] - camera_pos[0],
            p_ll[1] - camera_pos[1],
            p_ll[2] - camera_pos[2])
    v_ur = (p_ur[0] - camera_pos[0],
            p_ur[1] - camera_pos[1],
            p_ur[2] - camera_pos[2])
    
    # 3. Normalize vectors (guard against zero length)
    len_ll = math.sqrt(v_ll[0]**2 + v_ll[1]**2 + v_ll[2]**2)
    len_ur = math.sqrt(v_ur[0]**2 + v_ur[1]**2 + v_ur[2]**2)
    
    if len_ll == 0.0 or len_ur == 0.0:
        return 0.0 # Degenerate case fallback [G]
        
    u_ll = (v_ll[0]/len_ll, v_ll[1]/len_ll, v_ll[2]/len_ll)
    u_ur = (v_ur[0]/len_ur, v_ur[1]/len_ur, v_ur[2]/len_ur)
    
    # 4 & 5. Compute dot product and return metric
    dot = u_ll[0]*u_ur[0] + u_ll[1]*u_ur[1] + u_ll[2]*u_ur[2]
    return 1.0 - dot
```

## Subtopics

### [MIP Scale Computation](7029-mip-scale-computation.md)
Computes a per-Gaussian scale factor based on the Euclidean distance from the camera center and the camera's focal length, primarily used for anti-aliasing or level-of-detail (LOD) adjustments in Gaussian splatting. It differs from standard projected voxel size calculations by operating on parametric Gaussian primitives rather than volumetric voxels, scaling the representation size inversely to the focal length to maintain consistent screen-space coverage.

### Depth-Dependent Spatial Resolution (Voxel Sizing)
Determines the minimum reproducible voxel size in a light field display based on distance from the screen and beam angular divergence, dictating volume sampling rates [S2]. It differs from standard projected voxel size calculations by incorporating the physical properties of the light field display, specifically the angular size of light beams, to define a distance-dependent resolution limit [S2]. It is chosen when rendering for light field displays where spatial resolution degrades with depth [S2]. The formula is $s(z) = s_0 + 2|z| \tan(\Phi/2)$, where $s(z)$ is the minimum voxel size at distance $z$ from the screen, $s_0$ is the pixel size on the screen surface, and $\Phi$ is the finite angular size of light beams leaving the screen [S2].

### Max Sample Rate Calculation
Calculates the maximum sampling rate across all cameras for each voxel, based on voxel length and sample interval derived from depth [S3, unofficial]. It differs by aggregating sampling requirements from multiple camera views to determine a global maximum rate for a voxel [S3, unofficial]. It is chosen in multi-view reconstruction or training scenarios where voxel density must be consistent across all viewpoints [S3, unofficial]. The method initializes a `max_samp_rate` tensor of size `len(octree_paths)` with zeros on CUDA, calculates the z-distance from voxel centers to camera positions along the lookat vector, identifies visible voxels where `n_duplicates > 0` and `zdist > near_plane`, calculates the sample interval as `zdist * cam.pix_size`, computes the sample rate as `vox_lengths / samp_interval`, and updates `max_samp_rate` with the maximum of the current value and the new rate [S3, unofficial]. The `near_plane` parameter defaults to 0.02 to filter voxels too close to the camera [S3, unofficial].

- Strengths: Provides a geometrically intuitive measure of voxel importance relative to the viewer [S1, unofficial].
- Limitations: The basic metric lacks robustness for near-plane cases and requires careful corner selection [S1, unofficial].
- When to use: Use for LOD management in volume rendering where angular coverage is a key factor [S1, unofficial]. Use max sample rate for multi-view consistent voxelization [S3, unofficial].

## Background
The concept of projected voxel size for LOD is discussed in the context of voxel visualization and ray marching [S1, unofficial]. The depth-dependent spatial resolution is derived from research on GPU-accelerated direct volume rendering on interactive light field displays [S2].
