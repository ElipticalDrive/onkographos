# Incremental Minimum Step Relaxed Sphere Tracing

Also called: faster raymarch, relaxed sphere trace with faster raymarch, sphere trace + faster raymarch

## Overview
Incremental Minimum Step Relaxed Sphere Tracing is a ray marching algorithm that accelerates traversal through empty space by combining the step-scaling logic of [Relaxed Sphere Tracing](9463-relaxed-sphere-tracing.md) with an incrementally increasing minimum step size. It solves the performance bottleneck of standard sphere tracing in large empty volumes by allowing the step size to grow as the ray travels further from the origin, while retaining the safety checks of relaxed sphere tracing to prevent skipping intersections. It is distinguished from basic sphere tracing by its adaptive step growth and from standard relaxed sphere tracing by the explicit addition of a growing minimum step component.

## How it works
The method advances a ray along a parameter $t$ using a Signed Distance Function (SDF) to determine step sizes. It maintains a minimum step size $msp$ that increases linearly with each iteration, ensuring that steps do not shrink below a growing threshold. It also implements a backward correction mechanism to handle cases where the distance estimate drops significantly, which can occur with glassy artifacts or rapid changes in geometry.

### Inputs and Outputs
**Inputs:**
- $r$: Ray origin and direction (normalized).
- $sdf(p)$: Signed Distance Function returning distance to surface.
- $stepcount$: Maximum number of iterations.
- $stepsize$: Initial step size scalar.
- $TRACE\_STEPINCR$: Constant increment for the minimum step size.
- $TRACE\_OR$: Overstep ratio (typically $> 1$).

**Outputs:**
- A `vec2` (or pair) containing the hit position $t_{hit}$ and the end position $t_{end}$ of the traversal. If no intersection is found within $stepcount$, it returns the last valid interval.

### Data Structures
No complex data structures are required. The algorithm uses scalar variables for ray parameter $t$, previous distance $pft$, current distance $ft$, minimum step $msp$, and overstep ratio components.

### Pseudocode
```python
def incremental_min_step_relaxed_sphere_trace(ray, sdf, stepcount, stepsize, TRACE_STEPINCR, TRACE_OR):
    """
    ray: object with .origin and .direction (normalized)
    sdf: function taking a point and returning float distance
    stepcount: int, max iterations
    stepsize: float, initial step size
    TRACE_STEPINCR: float, increment for minimum step
    TRACE_OR: float, overstep ratio (> 1)
    """
    t = 0.0
    msp = stepsize
    pft = 0.0  # Previous distance
    orm1 = TRACE_OR - 1.0
    
    for i in range(stepcount):
        # Evaluate SDF at current position
        ft = sdf(ray.origin + ray.direction * t)
        
        # Backward correction if distance drops significantly
        # Note: pft is 0 on first iteration, so ft < 0 check handles inside-object start
        if ft < pft * orm1:
            # Step back by the overstep amount of the previous distance
            t = t - orm1 * pft
            # Re-evaluate SDF at corrected position
            ft = sdf(ray.origin + ray.direction * t)
        
        # Increment minimum step size
        msp = msp + TRACE_STEPINCR
        
        # Check for intersection
        if ft <= 0:
            return (t - msp, t)
        
        # Advance ray
        # Step size is overstep * distance + minimum step
        t = t + TRACE_OR * ft + msp
        
        # Update previous distance for next iteration
        pft = ft
        
    # Loop finished without intersection
    return (t - msp, t)
```

### Parameters
- $TRACE\_STEPINCR$: The amount added to $msp$ per step. Not given in the sources.
- $TRACE\_OR$: Overstep ratio. Not given in the sources, but implied to be $>1$.
- $stepsize$: Initial minimum step. Not given in the sources.
- $stepcount$: Max iterations. Not given in the sources.

### Edge Cases and Pitfalls
- **Initial $pft=0$**: On the first iteration, $pft$ is 0. The condition $ft < 0 \times (TRACE\_OR - 1)$ becomes $ft < 0$. This correctly triggers if the ray starts inside an object, but does not trigger false positives for empty space.
- **Precision**: Floating point errors in $t$ updates can accumulate. The backward correction helps mitigate overshooting but relies on accurate SDF evaluation.
- **Glassy Artifacts**: The method is specifically noted to handle glassy artifacts at low step counts by adjusting step size based on previous distance.

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of steps taken, up to $stepcount$. The incremental step size reduces the number of steps required for long empty traversals compared to constant step size methods.
- **Memory Complexity**: $O(1)$ auxiliary space.
- **Performance**: Accelerates traversal in empty space compared to basic sphere tracing. The "faster raymarch" alias suggests it is optimized for speed.
- **Strengths**: Handles large empty volumes efficiently; reduces glassy artifacts; simple implementation.
- **Limitations**: Requires tuning of $TRACE\_STEPINCR$ and $TRACE\_OR$; backward correction adds computational overhead per step; may overshoot if parameters are not set correctly.

## Background
The method is derived from the Interactive-SDF-Renderer project by Csabix. It is an unofficial implementation combining relaxed sphere tracing with an incrementing minimum step size. It appears in shader code labeled `02_Shaders` and is associated with aliases like `Raytracer_02` and `faster raymarch`.
