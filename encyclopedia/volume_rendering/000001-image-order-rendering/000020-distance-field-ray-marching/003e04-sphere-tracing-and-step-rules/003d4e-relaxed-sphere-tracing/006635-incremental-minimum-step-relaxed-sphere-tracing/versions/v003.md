# Incremental Minimum Step Relaxed Sphere Tracing

Also called: faster raymarch, relaxed sphere trace with faster raymarch, sphere trace + faster raymarch [S1, unofficial]

## Overview
Incremental Minimum Step Relaxed Sphere Tracing is a ray marching algorithm that accelerates traversal by combining the step-scaling logic of [Relaxed Sphere Tracing](9463-relaxed-sphere-tracing.md) with an incrementally increasing minimum step size [S1, unofficial]. It adjusts the step size based on the previous distance estimate to handle glassy artifacts at low step counts [S1, unofficial].

## How it works
The method advances a ray along a parameter $t$ using a Signed Distance Function (SDF) to determine step sizes [S1, unofficial]. It maintains a minimum step size $msp$ that increases linearly with each iteration, ensuring that steps do not shrink below a growing threshold [S1, unofficial]. It also implements a backward correction mechanism to handle cases where the distance estimate drops significantly, which can occur with glassy artifacts or rapid changes in geometry [S1, unofficial].

### Inputs and Outputs
**Inputs:**
- $r$: Ray origin and direction (normalized) [S1, unofficial].
- $sdf(p)$: Signed Distance Function returning distance to surface [S1, unofficial].
- $stepcount$: Maximum number of iterations [S1, unofficial].
- $stepsize$: Initial step size scalar [S1, unofficial].
- $TRACE\_STEPINCR$: Constant increment for the minimum step size [S1, unofficial].
- $TRACE\_OR$: Overstep ratio (typically $> 1$) [S1, unofficial].

**Outputs:**
- A `vec2` (or pair) containing the hit position $t_{hit}$ and the end position $t_{end}$ of the traversal [S1, unofficial]. If no intersection is found within $stepcount$, it returns the last valid interval [S1, unofficial].

### Data Structures
No complex data structures are required [S1, unofficial]. The algorithm uses scalar variables for ray parameter $t$, previous distance $pft$, current distance $ft$, minimum step $msp$, and overstep ratio components [S1, unofficial].

### Algorithm Steps
The implementation varies slightly depending on whether backward correction is enabled [S1, unofficial]. The core logic involves initializing variables, looping, evaluating the SDF, checking for intersections, applying backward correction if necessary, incrementing the minimum step, and advancing the ray [S1, unofficial].

1. **Initialization**:
   - Set $t = 0$ [S1, unofficial].
   - Set $msp = stepsize$ [S1, unofficial].
   - If backward correction is used:
     - Set $pft = 0$ [S1, unofficial].
     - Set $orm1 = TRACE\_OR - 1$ [S1, unofficial].
2. **Iteration Loop** (for $i$ from $0$ to $stepcount - 1$):
   - **Evaluate SDF**:
     - $ft = sdf(RAY(r, t))$ [S1, unofficial].
   - **Backward Correction** (if enabled):
     - If $ft < pft \times orm1$:
       - $t = t - orm1 \times pft$ [S1, unofficial].
       - $ft = sdf(RAY(r, t))$ [S1, unofficial].
   - **Increment Minimum Step**:
     - $msp = msp + TRACE\_STEPINCR$ [S1, unofficial].
   - **Intersection Test**:
     - If $ft \le 0$:
       - Return $vec2(t - msp, t)$ [S1, unofficial].
   - **Advance Ray**:
     - $t = t + TRACE\_OR \times ft + msp$ [S1, unofficial].
   - [G] Update $pft = ft$ at the end of the loop to serve as the previous distance for the next iteration, as the source notes do not explicitly show this assignment.
3. **Termination**:
   - If the loop completes without returning:
     - Return $vec2(t - msp, t)$ [S1, unofficial].

### Pseudocode
```python
def incremental_min_step_relaxed_sphere_trace(ray, sdf, stepcount, stepsize, TRACE_STEPINCR, TRACE_OR):
    t = 0.0
    msp = stepsize
    pft = 0.0
    orm1 = TRACE_OR - 1.0
    
    for i in range(stepcount):
        ft = sdf(ray.origin + ray.direction * t)
        
        if ft < pft * orm1:
            t = t - orm1 * pft
            ft = sdf(ray.origin + ray.direction * t)
        
        msp = msp + TRACE_STEPINCR
        
        if ft <= 0:
            return (t - msp, t)
        
        t = t + TRACE_OR * ft + msp
        
        # [G] Update previous distance for next iteration
        pft = ft
        
    return (t - msp, t)
```

### Parameters
- $TRACE\_STEPINCR$: The amount added to $msp$ per step. Not given in the sources.
- $TRACE\_OR$: Overstep ratio. Not given in the sources.
- $stepsize$: Initial minimum step. Not given in the sources.
- $stepcount$: Max iterations. Not given in the sources.

### Edge Cases and Pitfalls
- **Initial $pft=0$**: On the first iteration, $pft$ is 0. The condition $ft < 0 \times (TRACE\_OR - 1)$ becomes $ft < 0$. This correctly triggers if the ray starts inside an object, but does not trigger false positives for empty space [S1, unofficial].
- **Precision**: Floating point errors in $t$ updates can accumulate. The backward correction helps mitigate overshooting but relies on accurate SDF evaluation [S1, unofficial].
- **Glassy Artifacts**: The method is specifically noted to handle glassy artifacts at low step counts by adjusting step size based on previous distance [S1, unofficial].

## Operating characteristics
- **Time Complexity**: $O(N)$ where $N$ is the number of steps taken, up to $stepcount$ [S1, unofficial]. The incremental step size reduces the number of steps required for long empty traversals compared to constant step size methods [S1, unofficial].
- **Memory Complexity**: $O(1)$ auxiliary space [S1, unofficial].
- **Performance**: Accelerates traversal in empty space compared to basic sphere tracing. The "faster raymarch" alias suggests it is optimized for speed [S1, unofficial].
- **Strengths**: Handles large empty volumes efficiently; reduces glassy artifacts; simple implementation [S1, unofficial].
- **Limitations**: Requires tuning of $TRACE\_STEPINCR$ and $TRACE\_OR$; backward correction adds computational overhead per step; may overshoot if parameters are not set correctly [S1, unofficial].

## Background
The method is derived from the Interactive-SDF-Renderer project by Csabix. It is an unofficial implementation combining relaxed sphere tracing with an incrementing minimum step size. It appears in shader code labeled `02_Shaders` and is associated with aliases like `Raytracer_02` and `faster raymarch` [S1, unofficial].
