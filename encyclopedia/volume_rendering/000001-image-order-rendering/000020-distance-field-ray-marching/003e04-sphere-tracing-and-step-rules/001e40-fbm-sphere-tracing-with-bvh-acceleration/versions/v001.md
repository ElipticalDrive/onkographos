# FBM Sphere Tracing with BVH Acceleration

Also called: High-level view algorithm of how step size is computed during the FBM loop, Procedural FBM Sphere Tracing

## Overview
This method accelerates the sphere tracing of isosurfaces defined by Fractal Brownian Motion (FBM) noise by computing valid Sphere Distance Bounds (SDB) using a dynamic Bounding Volume Hierarchy (BVH) derived from the FBM structure itself [S1]. It enables early termination of octave summation and adaptive step sizing, reducing the average evaluation cost in empty space from $O(N)$ to $O(k)$, where $k \ll N$ is the number of octaves required to prove emptiness [S1]. Unlike naive sphere tracing which evaluates the full FBM at every step, this approach builds on [Distance-field ray marching](21-distance-field-ray-marching.md) by integrating the BVH logic directly into the FBM summation loop, avoiding the memory overhead of explicit spatial trees or dynamic re-ordering [S1].

## How it works
The algorithm computes a step size and the final FBM value $F$ by iterating through the $n$ octaves of the noise function. It maintains the current accumulated value $F$, the derivative along the ray $dF$, and the total step size `step`. The method uses global Lipschitz constants $\lambda$ and $\gamma$ initially, which can be replaced by local values for adaptive stepping [S1].

**Inputs:**
- $p$: Current 3D position.
- $n$: Number of octaves in the FBM sum.
- $v$: Threshold function (hypertexture), approximated by its 1st order (affine) Taylor polynomial [S1].
- $u$: Ray direction vector.
- $k$: Early stop threshold parameter.

**Outputs:**
- $F$: Final FBM value.
- `step`: Computed step size for the ray march.

**Parameters:**
- $\lambda_{noise}, \gamma_{noise}$: Lipschitz constants for the noise function. Default values used for Perlin noise [Per85] [S1].
- $\lambda_{Fn}, \gamma_{Fn}$: Global Lipschitz constants for the full FBM.
- Typical $n$: 20 (as used in Sponge scene tests) [S1].
- Typical $k$: 0, 1, 2, 3 [S1].

**Data Structures:**
- `inclFuncParams`: Tuple $(BVH, \lambda, dF, \gamma)$ passed to the intersection function [S1].

**Algorithm Steps:**
1. Initialize $F \leftarrow 0$, $dF \leftarrow 0$, `step` $\leftarrow 0$.
2. Set global Lipschitz constants: $\lambda \leftarrow \lambda_{Fn}$, $\gamma \leftarrow \gamma_{Fn}$ [S1].
3. Loop for $i$ from 1 to $n$ (each octave):
    a. Add current octave value to $F$: $F \leftarrow F + o_i(p)$ [S1].
    b. Add derivative along ray to $dF$: $dF \leftarrow dF + (u \cdot o'_i(p))$ [S1].
    c. Compute Bounding Volume H (BVH) for remaining octaves: $BVH \leftarrow F + s(i+1, n)$ [S1]. Here $s(i+1, n)$ represents the bound of the remaining octaves.
    d. Determine if step size computation is required (`compStep`):
       - `compStep` is true if $i == n$ (last octave) OR if the ray is outside the bounding volume ($BVH - v(0) < 0$) [S1].
    e. If `compStep` is true:
       i. Update Lipschitz constants to local values: $\lambda \leftarrow \lambda_{Fi}$, $\gamma \leftarrow \gamma_{Fi}$ (Adaptive Lipschitz) [S1].
       ii. Prepare inclusion function parameters: `inclFuncParams` $\leftarrow (BVH, \lambda, dF, \gamma)$ [S1].
       iii. Compute current step size: `curr_step` $\leftarrow$ `intersect`(`inclFuncParams`, $v$) [S1].
       iv. Update total step size: `step` $\leftarrow$ `step` + `curr_step` [S1].
       v. Enforce minimum step size: `step` $\leftarrow \max(\text{step}, \text{curr\_step})$ (optional if Sub-stepping is on) [S1].
    f. Perform Sub-stepping:
       i. Move ray position: $p \leftarrow p + u \cdot \text{curr\_step}$ [S1].
       ii. Update $F$ using threshold at current step: $F \leftarrow v(\text{curr\_step})$ [S1].
       iii. Update threshold $v$ at current step [S1].
       iv. Update derivative: $dF \leftarrow dF + \gamma \cdot \text{curr\_step}$ [S1].
       v. Clamp $dF$: $dF \leftarrow \max(dF, \lambda)$ [S1].
    g. Apply Early Stop+k:
       i. Decrement $k$: $k \leftarrow k - 1$ [S1].
       ii. If $k < 0$, break the loop [S1].
4. Return final $F$ and `step` [S1].

**Pseudocode:**
```python
def fbm_sphere_trace(p, n, v_func, u, k, lambda_noise, gamma_noise, lambda_Fn, gamma_Fn):
    """
    Computes FBM value and step size using BVH acceleration.
    
    Args:
        p: Current position (vec3)
        n: Number of octaves (int)
        v_func: Threshold function (callable, approximated by 1st order Taylor)
        u: Ray direction (vec3)
        k: Early stop threshold (int)
        lambda_noise: Lipschitz constant for noise
        gamma_noise: Gamma constant for noise
        lambda_Fn: Global Lipschitz constant for FBM
        gamma_Fn: Global Gamma constant for FBM
        
    Returns:
        F: Final FBM value (float)
        step: Computed step size (float)
    """
    F = 0.0
    dF = 0.0
    step = 0.0
    lam = lambda_Fn
    gam = gamma_Fn
    
    for i in range(1, n + 1):
        # Evaluate current octave and its derivative
        o_i = octave_noise(p, i)
        o_i_prime = octave_derivative(p, i)
        
        F += o_i
        dF += dot(u, o_i_prime)
        
        # Compute BVH for remaining octaves
        # s(i+1, n) is the bound of remaining octaves
        s_rem = remaining_octave_bound(i + 1, n)
        BVH = F + s_rem
        
        # Determine if step size computation is needed
        comp_step = (i == n) or (BVH - v_func(0) < 0)
        
        if comp_step:
            # Adaptive Lipschitz: replace global with local
            lam = local_lipschitz(i)
            gam = local_gamma(i)
            
            # Compute step size using inclusion function
            incl_params = (BVH, lam, dF, gam)
            curr_step = intersect_inclusion(incl_params, v_func)
            
            # Update total step
            step += curr_step
            # Optional: enforce minimum step if Sub-stepping is on
            # step = max(step, curr_step)
            
            # Sub-stepping
            p = p + u * curr_step
            F = v_func(curr_step)
            # Update threshold v at current step (handled by v_func(curr_step) above if v_func returns value)
            # Note: The source says "Update threshold v at current step", 
            # assuming v_func handles the threshold logic or returns the updated threshold value.
            dF += gam * curr_step
            dF = max(dF, lam)
            
            # Early Stop+k
            k -= 1
            if k < 0:
                break
                
    return F, step
```

**Edge Cases and Pitfalls:**
- **Thread Divergence:** The FBM sum loop may exit earlier for some threads than others due to Early Stop. However, rays from the same warp are spatially coherent, so divergence is typically limited to a single octave [S1].
- **GPU Memory Usage:** The method avoids $O(n)$ per-thread data storage required by dynamic re-ordering methods [WH96], making it more suitable for fast GPU implementation [S1].
- **Threshold Approximation:** The threshold function $v(p)$ is approximated by its 1st order (affine) Taylor polynomial. Higher order functions were not implemented as the approximation showed no noticeable error in tested scenes [S1].
- **Noise Parameters:** The algorithm requires $\lambda_{noise}$ and $\gamma_{noise}$ for arbitrary noise functions. Default values are used for Perlin noise [Per85] [S1].

## Subtopics

### [FBM Sphere Tracing with Implicit BVH](1901-fbm-sphere-tracing-with-implicit-bvh.md)
This method accelerates the sphere tracing of isosurfaces defined by Fractal Brownian Motion (FBM) noise by treating the cascaded sum of octaves as a dynamic, implicit Bounding Volume Hierarchy (BVH). It progressively evaluates octaves while bounding the remaining potential contribution to determine if the total function value can exceed the isosurface threshold, allowing for early termination and empty space skipping. Unlike naive sphere tracing which evaluates the full FBM at every step, this approach reduces the average evaluation cost in empty space from $O(N)$ to $O(k)$, where $k \ll N$ is the number of octaves required to prove emptiness. It builds on [FBM Sphere Tracing with BVH Acceleration](1728-fbm-sphere-tracing-with-bvh-acceleration.md) by replacing the explicit spatial tree with a procedural hierarchy derived from the FBM structure itself.

## Operating characteristics
- **Time Complexity:** The average number of octaves computed per step is reduced from $O(N)$ to $O(k)$ in empty space, where $k \ll N$ [S1].
- **Memory Complexity:** $O(1)$ per thread, avoiding the $O(n)$ storage required by dynamic re-ordering methods [S1].
- **Performance:** Tested on an Nvidia RTX 4080 Ti at 1024×1024 resolution on a 20-octave FBM Sponge scene [S1]:
    - **Early Stop (ES):** Reduced avg octaves from 49596.3 to 24252.6 (close view) and 56577.8 to 10347.0 (far view). Time reduced from 770.0ms to 399.8ms (1.9x speedup) and 843.0ms to 178.4ms (4.7x speedup) [S1].
    - **Adaptive Lipschitz:** Reduced avg steps from 428.1 to 331.7 (close view) and 223.7 to 154.5 (far view). Time reduced from 110.2ms to 87.1ms (1.3x speedup) and 42.4ms to 28.3ms (1.5x speedup) [S1].
    - **Sub-stepping (SS):** With Adaptive Lipschitz, reduced avg steps from 331.7 to 265.2 (close view) and 154.5 to 273.0 (far view, steps increased but octaves decreased). Time reduced from 87.1ms to 72.5ms (1.2x speedup) and 28.3ms to 22.0ms (1.3x speedup) [S1].
    - **Early Stop+k (ES+k=1):** With SS, reduced avg octaves from 4314.0 to 3815.0 (close view) and 1123.6 to 749.6 (far view). Time reduced from 72.5ms to 65.0ms (1.1x speedup) and 22.7ms to 16.7ms (1.4x speedup) [S1].
- **Strengths:** Significant performance gains in scenes with large empty spaces or intricate structures where FBM evaluation cost dominates. Low memory overhead suitable for GPU implementation.
- **Limitations:** Slightly smaller step sizes compared to dynamic re-ordering [WH96], but with much lower overhead. Thread divergence due to Early Stop, though limited by spatial coherence [S1].

## Background
The method was introduced in the paper "Fast sphere tracing of procedural volumetric noise for very large and detailed scenes" [S1]. It was implemented in GLSL fragment shaders and tested on scenes with 20-octave FBM of Perlin noise. The approach was developed to address the high computational cost of evaluating large FBM sums in sphere tracing, particularly for very large and detailed scenes [S1].
