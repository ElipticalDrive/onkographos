# Volumetric Light Shafts (Cone Raymarching)

Also called: Per-light ray marching, Post-process Volumetric Lighting, Ray Marching for Volumetric Lighting, Volumetric ray marching, WebGPU Volumetrics

## Overview
Volumetric Light Shafts (Cone Raymarching) is a real-time post-processing technique that renders volumetric light shafts by raymarching through a cone-shaped volume originating from a light source, using Signed Distance Fields (SDFs) to define the volume shape and noise for density variation [S1, unofficial]. It solves the problem of rendering visible light beams in fog or haze by accumulating scattered light along the view ray only within the light's defined geometry [S2, unofficial]. Unlike standard cone raymarching which may use fixed geometric bounds, this method decouples the light's physical geometry from the ray's direction via SDFs, allowing for complex, non-conical volumes like cylinders or toruses in post-processing [S1, unofficial]. It differs from its parent [Volumetric Raymarching with SDF Density](4484-volumetric-raymarching-with-sdf-density.md) by focusing specifically on light shafts in a post-process context, using the SDF primarily for volume boundary definition and shadow occlusion rather than just surface distance [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Screen UV coordinates, depth texture (scene depth), shadow map (light space), blue noise texture, and uniform constants (camera/light positions, transforms, time, frame index).
*   **Outputs:** Final color buffer with volumetric light shafts composited over the scene.

**Data Structures:**
*   **Constants Uniform Buffer:**
    *   `projectionInverse`: `mat4x4<f32>`
    *   `viewMatrixInverse`: `mat4x4<f32>`
    *   `lightTransform`: `mat4x4<f32>`
    *   `cameraPosition`: `vec3f`
    *   `time`: `f32`
    *   `lightPosition`: `vec3f`
    *   `frameIndex`: `u32`
    *   `lightDirection`: `vec3f`
*   **Textures:**
    *   Binding 0: `constants` (uniform)
    *   Binding 1: `sceneTexture` (`texture_2d<f32>`)
    *   Binding 2: `depthTexture` (`texture_depth_2d`)
    *   Binding 3: `shadowTexture` (`texture_depth_2d`)
    *   Binding 4: `blueNoiseTexture` (`texture_2d<f32>`)
    *   Binding 5: `blueNoiseSampler` (`sampler`)

**Pseudocode:**
```python
# Constants
cone_angle_half = radians(30.0)
step_size = 0.5
step_count = 16
fog_density = 0.03
light_color = vec3(1.0, 0.85, 0.85)
light_intensity = 1.0
grain_intensity = 1.0 / 8.0
absorption = 1.0
g = 0.375
gg = g * g

def pcg_hash_u32(x):
    state = x * 747796405 + 2891336453
    word = ((state >> ((state >> 28) + 4)) ^ state) * 277803737
    return (word >> 22) ^ word

def pcg_random(state):
    h = pcg_hash_u32(state)
    return (h >> 8) * (1.0 / 16777216.0)

def hash2i(p):
    ux = u32(p.x)
    uy = u32(p.y)
    return pcg_random((ux * 0x27d4eb2d) ^ (uy * 0x165667b1))

def hash3i(p):
    ux = u32(p.x)
    uy = u32(p.y)
    uz = u32(p.z)
    return pcg_random((ux * 0x27d4eb2d + 29) ^ (uy * 0x165667b1 - 1) ^ (uz * 0x9e3779b1 + 9))

def noise3D(st):
    s = st + vec3(1234.0)
    i0 = floor(s)
    f = fract(s)
    n0 = hash3i(i0)
    n1 = hash3i(i0 + vec3(1,0,0))
    n2 = hash3i(i0 + vec3(0,1,0))
    n3 = hash3i(i0 + vec3(1,1,0))
    n4 = hash3i(i0 + vec3(0,0,1))
    n5 = hash3i(i0 + vec3(1,0,1))
    n6 = hash3i(i0 + vec3(0,1,1))
    n7 = hash3i(i0 + vec3(1,1,1))
    x00 = mix(n0, n1, f.x)
    x10 = mix(n2, n3, f.x)
    x01 = mix(n4, n5, f.x)
    x11 = mix(n6, n7, f.x)
    y0 = mix(x00, x10, f.y)
    y1 = mix(x01, x11, f.y)
    return mix(y0, y1, f.z)

def fbm3D(p):
    value = 0.0
    amplitude = 0.5
    st = p + vec3(time * 0.25, time * 0.125, 0.0)
    for i in range(4):
        value += amplitude * noise3D(st)
        st *= 2.0
        amplitude *= 0.5
    return value

def sdCone(p, axis_origin, axis_dir, angle_rad):
    p_to_origin = p - axis_origin
    h = dot(p_to_origin, axis_dir)
    r = length(p_to_origin - axis_dir * h)
    c = cos(angle_rad)
    s = sin(angle_rad)
    dist_to_surface_line = r * c - h * s
    dist_to_apex_plane = -h
    if h < 0.0 and dist_to_surface_line > 0.0:
        return length(p_to_origin)
    boundary_dists = vec2(dist_to_surface_line, dist_to_apex_plane)
    return length(max(boundary_dists, vec2(0.0))) + min(max(boundary_dists.x, boundary_dists.y), 0.0)

def calculate_shadow(world_pos):
    clip = light_transform * vec4(world_pos, 1.0)
    ndc = clip.xyz / clip.w
    coord = ndc.xy * 0.5 + 0.5
    if any(coord > 1.0) or any(coord < 0.0):
        return 1.0
    pixel_loc = vec2(coord.x, 1.0 - coord.y) * vec2(texture_dimensions(shadow_texture)) * (1023.0 / 1024.0)
    shadow_map_depth = texture_load(shadow_texture, vec2i(pixel_loc), 0)
    return step(ndc.z, shadow_map_depth)

def hg_phase(mu):
    denom = max(1.0 + gg - 2.0 * g * mu, 0.001)
    return (1.0 - gg) / pow(denom, 1.5)

def get_world_position(uv, depth):
    clip_z = depth * 2.0 - 1.0
    ndc = uv * 2.0 - 1.0
    clip = vec4(ndc, clip_z, 1.0)
    world = view_matrix_inverse * projection_inverse * clip
    return world.xyz / world.w

# Main Fragment Shader Logic
def fs_main(frag, uv):
    depth = texture_load(depth_texture, vec2i(frag.xy), 0)
    world_position = get_world_position(uv, depth)
    ray_origin = camera_position
    ray_direction = normalize(world_position - ray_origin)
    
    cone_angle_half = radians(30.0)
    blue_noise_uv = (frag.xy / 64.0) + f32(frame_index & 0xFFFF) * 0.61803399
    blue_noise_offset = texture_sample(blue_noise_texture, blue_noise_sampler, blue_noise_uv).r
    
    # Initial t calculation based on source [S1, unofficial]
    # Note: Source calculates distance to cone at 0.125 offset but uses stepSize + noise for t
    distance_to_cone = sdCone(ray_origin + ray_direction * 0.125, light_position, light_direction, cone_angle_half)
    t = step_size + blue_noise_offset
    
    accumulated_light = vec3(0.0)
    transmittance = 5.0
    scene_depth = length(world_position - camera_position)
    
    for i in range(step_count):
        sample_position = ray_origin + ray_direction * t
        
        if t > scene_depth or t > 16.0:
            break
            
        shadow = calculate_shadow(sample_position)
        if shadow == 0.0:
            t += step_size
            continue
            
        sdf_value = sdCone(sample_position, light_position, light_direction, cone_angle_half)
        shape_factor = -sdf_value + (fbm3D(sample_position) * 2.0)
        
        if shape_factor == 0.0:
            t += step_size
            continue
            
        distance_to_light = length(sample_position - light_position)
        sample_light_direction = normalize(sample_position - light_position)
        
        attenuation = exp(-0.24 * distance_to_light)
        scatter_phase = hg_phase(dot(ray_direction, -sample_light_direction))
        
        luminance = light_color * light_intensity * attenuation * scatter_phase
        step_density = max(fog_density * shape_factor, 0.0)
        
        step_transmittance = exp(-step_density * step_size * absorption)
        transmittance *= step_transmittance
        
        accumulated_light += luminance * transmittance * step_density * step_size
        t += step_size
        
    scene_color = texture_load(scene_texture, vec2i(frag.xy), 0).rgb
    film_grain = hash2i(vec2i(vec2u(frag.xy) * vec2u(frame_index) * vec2u(49218, 9123))) * grain_intensity - (grain_intensity / 2.0)
    final_color = black_and_white(scene_color + accumulated_light) + film_grain
    return vec4(final_color, 1.0)
```

**Parameters:**
*   `coneAngle`: Half-angle of the light cone in radians. Default: `radians(30.0)` [S1, unofficial].
*   `stepSize`: Distance between raymarch steps. Default: `0.5` [S1, unofficial].
*   `stepCount`: Maximum number of raymarch steps. Default: `16` [S1, unofficial].
*   `fogDensity`: Base density multiplier. Default: `0.03` [S1, unofficial].
*   `lightColor`: Color of the light. Default: `vec3(1.0, 0.85, 0.85)` [S1, unofficial].
*   `grainIntensity`: Intensity of film grain. Default: `1.0 / 8.0` [S1, unofficial].
*   `Min Step Size`: Minimum step length for ray marching. Range: `0.1` (Good) to `8` (Light Speed) [S2, unofficial].
*   `Raymarch Quality`: Divisor for the logarithmic step calculation. Range: `1` (Light Speed) to `8` (Good) [S2, unofficial].
*   `Max Steps`: Caps the maximum number of steps per ray to prevent excessive cost [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Shadow Map Boundaries:** If UV coordinates calculated from light space are outside `[0,1]`, the point is considered fully lit (`shadow = 1.0`) to avoid artifacts at the edges of the shadow map [S1, unofficial].
*   **SDF Zero Check:** If `shapeFactor` is exactly `0.0`, the step is skipped (`continue`) to avoid division by zero or invalid density calculations [S1, unofficial].
*   **Ray Termination:** The raymarch loop breaks if the step distance `t` exceeds the scene depth (distance to the screen pixel) or exceeds a hard limit of `16.0` units, preventing infinite loops or rendering behind the camera [S1, unofficial].
*   **Banding Artifacts:** Occur with few steps. Jittering offsets the start of each ray per pixel to turn banding into fine grain [S2, unofficial]. Blue Noise can replace the default hash for better quality at the cost of one extra texture fetch [S2, unofficial].

## Subtopics

### [SDF Light Shaping](17725-sdf-light-shaping.md)
SDF Light Shaping is a technique for defining the geometry of volumetric light shafts using Signed Distance Functions (SDFs) during raymarching. It solves the problem of arbitrary light volume boundaries by allowing the renderer to accumulate light only when a sample point lies within a mathematically defined shape (e.g., cylinder, cone, sphere). It differs from standard cone raymarching by decoupling the light's physical geometry from the ray's direction, enabling complex, non-conical volumes like cylinders or toruses to be rendered in post-processing.

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of steps per ray and the number of lights. Each light marches only inside its own volume (cone, sphere, or box) instead of across the whole screen [S2, unofficial].
*   **Memory Complexity:** Low, primarily requiring storage for the shadow map, depth texture, and blue noise texture.
*   **Measured Performance:** Performance scales with the number of pixels covered, the number of steps per ray, and the number of lights [S2, unofficial].
*   **Scaling:** Step length is not fixed; it uses `Min Step Size + log(Path Length / Raymarch Quality)`. Long rays through big volumes take longer steps, so their cost stays under control, and Max Steps caps the number of steps per ray [S2, unofficial].
*   **Strengths:** Real-time capability; decoupled geometry allows for complex light shapes; jittering and blue noise reduce banding artifacts [S2, unofficial].
*   **Limitations:** Cost grows with the number of lights; requires shadow maps for occlusion; banding can occur with few steps [S2, unofficial].
*   **When to Use:** Real-time rendering of volumetric light shafts in fog or haze, especially for spot lights or directional lights with defined volumes [S2, unofficial].
*   **When Not to Use:** When high-fidelity, physically accurate light scattering is required over real-time constraints, or when the scene has an extremely high number of volumetric lights [S2, unofficial].

## Background
Volumetric Light Shafts (Cone Raymarching) is a post-processing technique that renders volumetric light shafts by raymarching through a cone-shaped volume originating from a light source, using Signed Distance Fields (SDFs) to define the volume shape and noise for density variation [S1, unofficial]. It is a real-time technique where the shader walks along the view ray in small steps inside a light's volume (cone, sphere, or box) to evaluate light and medium density, adding up scattered light toward the camera [S2, unofficial]. The method uses a cone SDF to define the volume shape rather than a box or sphere, allowing for directional light shafts that taper from the light source [S1, unofficial].
