# Adaptive Step Size and Termination

Also called: Adaptive Ray Marching, Adaptive Step Rules

## Overview
This family defines the control flow logic for ray-marching loops, determining how far a ray advances per iteration ($\Delta t$) and when the loop halts. It solves the trade-off between computational efficiency (skipping empty space) and visual fidelity (avoiding missed geometry or aliasing). It sets itself apart from specific implementations like [Sphere Tracing](1674-sphere-tracing.md) or [Standard Constant Step Ray Marching](1080-standard-constant-step-ray-marching.md) by providing the general framework for adaptive stepping, early termination, and safety constraints applicable to both Signed Distance Fields (SDFs) and volumetric density fields.

## Shared principles
All methods in this family operate on a ray defined by origin $\mathbf{o}$ and normalized direction $\mathbf{d}$, parameterized by accumulated distance $t$. The core loop evaluates a scene function (SDF, density field, or volume texture) at the current position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ to determine the next step size $\Delta t$ and check for termination.

**Termination Conditions:**
1.  **Surface Hit:** The ray has intersected the target geometry. For SDFs, this is typically $|f(\mathbf{p})| < \epsilon$ or $f(\mathbf{p}) \le 0$. For volumes, this may be a density threshold or opacity accumulation [S1].
2.  **Escape/Miss:** The ray has traveled beyond a maximum distance $t_{max}$ or exceeded a maximum iteration count $N_{max}$.
3.  **Early Termination (Volumes):** Accumulated opacity $\alpha_{acc}$ exceeds a threshold (e.g., $1 - \epsilon$), or accumulated transmission falls below a minimum threshold, allowing the ray to stop early as further contributions are negligible [S1].

**Step Size Determination:**
The step size $\Delta t$ is computed based on the local scene properties:
*   **SDF-based:** $\Delta t$ is often derived from the SDF value $f(\mathbf{p})$, potentially scaled by a relaxation factor or Lipschitz constant $\lambda$ .
*   **Volume-based:** $\Delta t$ may be fixed, adaptive based on density gradients, or constrained by minimum/maximum bounds to prevent aliasing or excessive computation .
*   **Safety:** Steps must be chosen to ensure the ray does not penetrate the surface or skip over significant volumetric features, often requiring conservative clamping.

**Pseudocode Structure:**
```python
def ray_march_loop(ray_origin, ray_direction, scene_func, max_dist, max_steps, epsilon):
    """
    Generic ray marching loop with adaptive step size and termination.
    
    Args:
        ray_origin (vec3): The starting point of the ray.
        ray_direction (vec3): The normalized direction of the ray.
        scene_func (function): A function evaluating the scene (SDF or density) at point p.
        max_dist (float): The maximum distance the ray can travel.
        max_steps (int): The maximum number of iterations allowed.
        epsilon (float): The convergence threshold for hit detection.
        
    Returns:
        tuple: (hit: bool, distance: float)
    """
    t = 0.0
    
    for i in range(max_steps):
        # Check for escape
        if t > max_dist:
            return False, t
        
        # Calculate current position
        p = ray_origin + ray_direction * t
        
        # Evaluate scene function
        val = scene_func(p)
        
        # Termination: Hit
        if is_hit(val, epsilon):
            return True, t
        
        # Termination: Early Exit (Volume specific)
        if is_early_exit(val, t):
            return False, t # Or handle partial contribution
            
        # Step Size Calculation
        step = compute_step_size(val, t, i)
        
        # Safety Clamp
        step = max(step, min_step)
        step = min(step, max_step)
        
        t += step
        
    # Max steps reached
    return False, t
```

### [Adaptive Step Size Adjustment](20769-adaptive-step-size-adjustment.md)
[Adaptive Step Size Adjustment](20769-adaptive-step-size-adjustment.md) refers to a family of techniques in distance-field ray marching that dynamically modify the step length during traversal to optimize the trade-off between rendering performance and visual fidelity. Unlike fixed-step methods, these algorithms adjust the step size based on local geometry (via Signed Distance Functions) or screen-space error metrics, often incorporating mechanisms to handle the risks of non-conservative stepping such as overshooting. This family is distinct from [Step Size and Termination Rules](4132-step-size-and-termination-rules.md) by its focus on dynamic adjustment logic rather than static thresholds, and from [Step Size and Tracing Geometry](20976-step-size-and-tracing-geometry.md) by its reliance on SDF properties rather than purely geometric bounding volumes.

### [Step Size and Tracing Geometry](20976-step-size-and-tracing-geometry.md)
[Step Size and Tracing Geometry](20976-step-size-and-tracing-geometry.md) defines how a ray advances through a volume or implicit field, determining the distance to the next sampling point and the conditions for termination. It solves the problem of balancing rendering accuracy (avoiding missed surfaces or artifacts) with computational performance (minimizing expensive volume or SDF evaluations). It sets apart from its siblings by focusing on the geometric interpretation of the step: [Non-Linear Sphere Tracing](4079-non-linear-sphere-tracing.md) handles deformed spaces via ODE integration, [Cone Tracing](5679-cone-tracing.md) uses expanding apertures for lighting approximation, and [Occlusion-Aware Raycasting](21748-occlusion-aware-raycasting-with-clip-frustum.md) clips rays against foreground geometry to reduce overdraw.

## Background
The concept of adaptive stepping in ray marching evolved from the need to optimize the computational cost of evaluating implicit surfaces and volumetric data. While standard sphere tracing uses a fixed conservative step based on the SDF value, adaptive methods allow for larger steps in empty space or smoother regions, and smaller steps near complex geometry. The specific "Edge-based Speed Function" described in the minor variants originates from medical imaging applications, specifically for tagged volume rendering of the heart, where accurate contour propagation is critical [S1].
