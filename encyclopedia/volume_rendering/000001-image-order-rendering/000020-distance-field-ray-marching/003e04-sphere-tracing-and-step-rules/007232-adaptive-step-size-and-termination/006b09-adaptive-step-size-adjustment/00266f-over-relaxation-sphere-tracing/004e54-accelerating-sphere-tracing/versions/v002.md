# Accelerating Sphere Tracing

Also called: Planar Assumption Sphere Tracing, Predictive Sphere Tracing

## Overview
Accelerating Sphere Tracing is a ray marching step rule that predicts the next step distance by assuming the object surface is locally planar near the current ray position [S1, unofficial]. This allows for larger, more aggressive steps than standard Over-relaxation Sphere Tracing while reducing the frequency of overshoot corrections [S1, unofficial]. It builds on [Over-relaxation Sphere Tracing](3805-over-relaxation-sphere-tracing.md) by incorporating historical SDF values to refine step prediction [S1, unofficial].

## How it works
**Inputs:** Ray origin $p_0$, ray direction $\mathbf{d}$ (normalized), SDF function $f(\cdot)$, safety factor $\omega \in (0, 1)$, termination threshold $\epsilon$ [S1, unofficial].
**Outputs:** Intersection point $p_{hit}$, number of steps [G].

**Data Structures:**
- Current position $p_n \in \mathbb{R}^3$ [G].
- Previous position $p_{n-1} \in \mathbb{R}^3$ [G].
- Current SDF value $r_n = f(p_n) \in \mathbb{R}$ [G].
- Previous SDF value $r_{n-1} = f(p_{n-1}) \in \mathbb{R}$ [G].
- Previous step distance $d_n = \|p_n - p_{n-1}\| \in \mathbb{R}$ [G].

**Steps:**
1. Initialize ray parameters and set $p_0$ as the ray origin [S1, unofficial].
2. For each step $n$ starting from $0$: evaluate $r_n = f(p_n)$ [S1, unofficial].
3. If $r_n$ is below the threshold $\epsilon$, terminate as the intersection is found [S1, unofficial].
4. If $n = 0$, calculate the initial step distance $d_1 = r_0$ using standard sphere tracing to establish history [G]. For $n > 0$, retrieve the previous SDF value $r_{n-1}$ and previous step distance $d_n$ [S1, unofficial].
5. Calculate the predicted radius $r_{n+1}$ using the planar assumption formula:
   $$r_{n+1} = \frac{d_n - r_{n-1} + r_n}{d_n + r_{n-1} + r_n}$$
   [S1, unofficial].
6. Calculate the next step distance $d_{n+1} = r_n + \omega r_{n+1}$ [S1, unofficial].
7. Move the ray to $p_{n+1} = p_n + d_{n+1} \cdot \mathbf{d}$ [S1, unofficial].
8. Check for overshoot by evaluating $r_{n+1}' = f(p_{n+1})$ [S1, unofficial]. If $r_{n+1}' + r_n < d_{n+1}$, the ray has jumped over the object [S1, unofficial].
9. If overshoot is detected, retreat by $\omega r_{n+1}$: $p_{n+1} \leftarrow p_{n+1} - \omega r_{n+1} \cdot \mathbf{d}$ [S1, unofficial]. Then proceed with standard sphere tracing logic for the remaining distance, meaning the next step distance will be set to $f(p_{n+1})$ [S1, unofficial].
10. Update history: $p_{n-1} \leftarrow p_n$, $p_n \leftarrow p_{n+1}$, $r_{n-1} \leftarrow r_n$, $r_n \leftarrow f(p_{n+1})$, $d_n \leftarrow d_{n+1}$ [S1, unofficial].

**Pseudocode:**
```python
def accelerating_sphere_tracing(ray_origin, ray_direction, sdf, omega, epsilon):
    p_curr = ray_origin
    r_curr = sdf(p_curr)
    
    # Handle first step to initialize history
    d_prev = r_curr
    p_prev = p_curr
    r_prev = r_curr
    
    p_next = p_curr + d_prev * ray_direction
    r_next = sdf(p_next)
    
    # Update history after first standard step
    p_prev = p_curr
    r_prev = r_curr
    d_prev = d_prev
    p_curr = p_next
    r_curr = r_next
    
    while r_curr >= epsilon:
        # Calculate predicted radius based on planar assumption
        numerator = d_prev - r_prev + r_curr
        denominator = d_prev + r_prev + r_curr
        
        if denominator == 0:
            r_pred = 0.0
        else:
            r_pred = numerator / denominator
            
        # Calculate next step distance
        d_next = r_curr + omega * r_pred
        
        # Move ray
        p_next = p_curr + d_next * ray_direction
        r_next = sdf(p_next)
        
        # Check for overshoot
        if r_next + r_curr < d_next:
            # Overshoot detected: retreat by omega * r_pred
            p_next = p_next - omega * r_pred * ray_direction
            r_next = sdf(p_next)
            # Proceed with standard sphere tracing logic for next step
            d_next = r_next
            
        # Update history
        p_prev = p_curr
        r_prev = r_curr
        d_prev = d_next
        
        p_curr = p_next
        r_curr = r_next
        
    return p_curr
```

**Parameters:**
- $\omega$: Safety factor multiplier applied to the predicted additional distance to prevent overshooting into concave geometry [S1, unofficial]. Value range: $(0, 1)$ [S1, unofficial].

**Pitfalls:**
- **Concave Geometry:** The planar assumption may cause the predicted step to land inside the object if the surface is concave [S1, unofficial]. The safety factor $\omega \in (0, 1)$ is applied to $r_{n+1}$ to reduce the step size and maintain a margin, preventing deep penetration [S1, unofficial].
- **Overshoot Correction:** If overshoot is detected, the ray retreats by $\omega r_{n+1}$ and proceeds with standard sphere tracing logic [S1, unofficial].
- **Initial Steps:** The formula requires $r_{n-1}$ and $d_n$, so the first step cannot use this formula directly [S1, unofficial]. A standard sphere tracing step is typically used to initialize history [G].

## Operating characteristics
- **Performance:** Rendering time is approximately 0.8 times that of conventional Relaxation Sphere Tracing [S1, unofficial].
- **Strengths:** Allows more aggressive stepping than standard over-relaxation, reducing the number of steps and overshoot corrections [S1, unofficial].
- **Limitations:** Relies on the planar assumption, which may be inaccurate for highly curved or concave surfaces, requiring the safety factor $\omega$ [S1, unofficial].

## Background
- **Origin:** The method was proposed in 2018 as an improvement over Enhanced Sphere Tracing and Relaxation Sphere Tracing [S1, unofficial].
- **Development:** It aims to make ray marching steps bolder by using historical SDF values to predict the next step size based on a planar surface assumption [S1, unofficial].
