# Over-relaxation Sphere Tracing

Also called: Enhanced Sphere Tracing - Over Relaxation, Over-Relaxation Raymarching, Over-relaxation Sphere Tracing with Screen-Space Intersection Selection, Over-relaxation sphere tracing with screen-space selection, Over-relaxation-based sphere tracing, Over-relaxed sphere tracing, Sphere tracing with over-relaxation

## Overview
Over-relaxation Sphere Tracing accelerates the standard sphere tracing algorithm by stepping further than the conservative signed distance bound allows, controlled by a relaxation parameter $\omega \in [1, 2)$ [S1][S2, S3, unofficial]. It reduces the number of Signed Distance Function (SDF) evaluations by 20–40% in typical 3D renders [S4, unofficial][S5, abstract only, unofficial]. Unlike standard sphere tracing, which guarantees no surface penetration per step, this method risks overshooting the surface; it detects this via an overlap test between consecutive unbounding spheres and falls back to standard sphere tracing if an intersection is missed [S1][S6, unofficial]. It also incorporates screen-space error metrics to select the best shading point when the ray grazes an object or exceeds the maximum iteration count, reducing artifacts compared to simply using the last evaluated point [S1][S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Ray origin $\mathbf{o}$, normalized ray direction $\mathbf{d}$, SDF function $f(\mathbf{p})$, relaxation parameter $\omega$ (typically 1.2), maximum iterations $N_{max}$ (e.g., 80), maximum distance $t_{max}$, minimum distance $t_{min}$, pixel radius $r_{pixel}$ (radius of a pixel at $t=1$), convergence threshold $\epsilon$ (e.g., $0.001$), and a boolean `forceHit` [S1][S3, unofficial].
*   **Outputs:** The distance $t$ to the surface, or a sentinel value (e.g., $\infty$) if no valid intersection is found within constraints [S1][S3, unofficial].

**Data Structures:**
The algorithm maintains scalar state variables for the current ray distance $t$, the best candidate distance `candidate_t`, the best candidate screen-space error `candidate_error`, the previous step's radius `previousRadius`, and the current step length `stepLength` [S1][S3, unofficial].

**Algorithm Steps:**
1.  **Initialization:**
    *   Set $t = t_{min}$.
    *   Set `candidate_t` = $t_{min}$ and `candidate_error` = $\infty$ [S1][S3, unofficial].
    *   Set `previousRadius` = 0 [S1][S3, unofficial].
    *   Determine the sign of the starting position relative to the surface: `functionSign` = $+1$ if $f(\mathbf{o}) \ge 0$, else $-1$ [S1][S3, unofficial]. [G] This handles rays starting inside the object.

2.  **Marching Loop:** Iterate $i$ from 0 to $N_{max} - 1$:
    *   **Evaluate SDF:** Compute position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ and evaluate $d = f(\mathbf{p})$ [G].
    *   **Hit Detection:** If $|d| < \epsilon$, the ray has converged to the surface; return $t$ [G].
    *   **Calculate Radius:** Compute `signedRadius` = `functionSign` $\cdot d$ and `radius` = $|d|$ [S1][S3, unofficial].
    *   **Overshoot Detection (SOR Fail):** Check if the current over-relaxed step would skip over the surface. This occurs if $\omega > 1$ AND the sum of the current radius and the previous radius is less than the previous step length:
        $$ \text{sorFail} = (\omega > 1) \land (\text{radius} + \text{previousRadius} < \text{stepLength}) $$
        [S1][S3, unofficial]. This condition ensures that the unbounding spheres of the current and previous steps do not overlap, implying the ray segment between them might contain a surface [S1][S6, unofficial].
    *   **Handle Failure or Advance:**
        *   **If `sorFail` is true:**
            *   Retreat the ray to the position before the over-relaxed step. The fallback position is calculated as:
                $$ \mathbf{p}_{fallback} = \mathbf{p}_{prev} + \mathbf{d} \cdot \delta_{i-1} \cdot (1 - \omega) $$
                where $\delta_{i-1}$ is the step size of the previous iteration [S2, S3, unofficial]. In terms of distance $t$, this effectively resets the step size to the standard SDF value by making the next step negative, backing the ray up to a safe point [S2, S3, unofficial]. The implementation achieves this by updating `stepLength` as `stepLength *= (1 - omega)` and setting $\omega = 1$ [S1][S3, unofficial].
            *   Do not update `candidate_t` or `candidate_error` for this failed step [S1][S3, unofficial].
        *   **If `sorFail` is false:**
            *   Calculate the new step length: `stepLength` = `signedRadius` $\cdot \omega$ [S1][S3, unofficial].
            *   Update `previousRadius` = `radius` [S1][S3, unofficial].
            *   Calculate screen-space error: `error` = `radius` / $t$ [S1][S3, unofficial]. [G] Division by zero is avoided if $t_{min} > 0$.
            *   **Update Best Candidate:** If `error` < `candidate_error`, update `candidate_t` = $t$ and `candidate_error` = `error` [S1][S3, unofficial].
            *   **Early Termination:** If `error` < $r_{pixel}$ (sub-pixel accuracy) or $t > t_{max}$, break the loop [S1][S3, unofficial].
            *   **Advance Ray:** $t \leftarrow t + \text{stepLength}$ [S1][S3, unofficial].

3.  **Result Selection:**
    *   After the loop, if `forceHit` is false AND ($t > t_{max}$ OR `candidate_error` > $r_{pixel}$), return $\infty$ (no hit) [S1][S3, unofficial].
    *   Otherwise, return `candidate_t` [S1][S3, unofficial].

**Pseudocode:**
```python
def over_relaxation_sphere_tracing(ray_origin, ray_direction, sdf, max_iterations, t_min, t_max, pixel_radius, omega=1.2, force_hit=False, epsilon=1e-3):
    """
    Over-relaxation Sphere Tracing with screen-space intersection selection.
    
    Args:
        ray_origin: Camera origin (vec3)
        ray_direction: Normalized ray direction (vec3)
        sdf: Signed Distance Function callable sdf(p)
        max_iterations: Maximum number of iterations (e.g., 80)
        t_min: Minimum ray distance
        t_max: Maximum ray distance
        pixel_radius: Radius of a pixel at t=1 (sub-pixel threshold)
        omega: Relaxation parameter in [1, 2). Default 1.2.
        force_hit: If True, return candidate_t even if error > pixel_radius.
        epsilon: Convergence threshold for surface hit.
        
    Returns:
        hit_distance: Distance along ray to surface, or float('inf') if no hit.
    """
    t = t_min
    candidate_error = float('inf')
    candidate_t = t_min
    previous_radius = 0.0
    step_length = 0.0
    
    # Determine sign based on starting position
    f_o = sdf(ray_origin)
    function_sign = -1.0 if f_o < 0 else 1.0
    
    for _ in range(max_iterations):
        # Evaluate SDF at current position
        p = ray_origin + t * ray_direction
        signed_radius = function_sign * sdf(p)
        radius = abs(signed_radius)
        
        # Hit detection
        if radius < epsilon:
            return t
            
        # Check for over-relaxation failure (overshoot)
        # Condition: omega > 1 AND spheres do not overlap
        sor_fail = (omega > 1) and ((radius + previous_radius) < step_length)
        
        if sor_fail:
            # Fallback to standard sphere tracing
            # Retreat and disable over-relaxation
            step_length *= (1.0 - omega)
            omega = 1.0
        else:
            # Calculate step length using over-relaxation
            step_length = signed_radius * omega
            previous_radius = radius
            
            # Calculate screen-space error
            error = radius / t if t > 0 else float('inf')
            
            # Update best candidate
            if error < candidate_error:
                candidate_t = t
                candidate_error = error
            
            # Early termination if sub-pixel accuracy reached or max distance exceeded
            if error < pixel_radius or t > t_max:
                break
            
            # Advance ray
            t += step_length
    
    # Final result selection
    if not force_hit and (t > t_max or candidate_error > pixel_radius):
        return float('inf')
        
    return candidate_t
```

**Parameters:**
*   $\omega$: Relaxation parameter. Range $[1, 2)$ [S1][S2, S3, unofficial]. Typical value is 1.2 for a balance of performance and quality [S1][S3, unofficial]. Values up to 1.6 are used in some implementations [S4, unofficial]. A value of 1.0 is standard sphere tracing [S4, unofficial].
*   $N_{max}$: Maximum iterations. Typical value 80 [S1][S3, unofficial].
*   $r_{pixel}$: Pixel radius at $t=1$. Used for early termination and candidate selection [S1][S3, unofficial].
*   $\epsilon$: Convergence threshold. Standard value $\approx 0.001$ [G].

**Edge Cases and Pitfalls:**
*   **Overshooting:** If $\omega$ is too large, the ray may skip over surfaces. The overlap test detects this, but frequent failures degrade performance [S1][S3, unofficial].
*   **Non-Lipschitz SDFs:** Numeric or user-defined distance estimators (e.g., User Bulb) may not satisfy the Lipschitz condition, making the overlap test unreliable. In such cases, fall back to $\omega=1$ or tune $\omega$ carefully [S4, unofficial].
*   **Grazing Rays:** Rays grazing an object's edge may terminate in mid-air. The screen-space error metric selects the point with the smallest unbounding sphere radius, as measured in screen-space, reducing "aura" artifacts [S1][S3, unofficial].
*   **Self-Intersection:** Secondary rays may self-intersect. A dynamic $\epsilon$ offset (e.g., $2 \cdot |f(p)|$) is recommended for secondary rays [S1][S3, unofficial].
*   **Branch Divergence:** Checking if the fallback sphere overlaps the current sphere to avoid re-tracing adds branching, which can reduce GPU performance [S1][S3, unofficial].

## Subtopics

### [Binary Sphere Tracing](10174-binary-sphere-tracing.md)
A variant for conformally transformed Kernel-Reflection Sequences (KRSs) that uses binary search on unbounding spheres instead of distance values. It is an extreme form of over-relaxation tailored for geometries where the world-space sphere center differs from the query point [10174-binary-sphere-tracing.md].

### [Accelerating Sphere Tracing](13706-accelerating-sphere-tracing.md)
Predicts step size by assuming local planarity, using historical SDF values to allow larger steps than standard over-relaxation while reducing overshoot corrections [13706-accelerating-sphere-tracing.md].

## Operating characteristics
*   **Performance:** Reduces the number of SDF evaluations (steps) by 20–40% in 3D renders compared to standard sphere tracing [S4, unofficial][S5, abstract only, unofficial].
*   **Measured Performance:** In a city scene (1280x720, NVIDIA GTX Titan), rendering time dropped from 20.409 ms (48.998 Hz) to 16.829 ms (59.421 Hz) [S1]. In a jewel scene, it dropped from 3.472 ms (288.018 Hz) to 2.978 ms (335.744 Hz) [S1]. Path tracing integration also showed improvements (101.934 ms vs 118.302 ms for one sample) [S1].
*   **Scaling:** Performance gains are consistent across hardware [S4, unofficial].
*   **Strengths:** Faster convergence, fewer iterations, better handling of grazing rays via screen-space selection [S1][S3, unofficial].
*   **Limitations:** Requires careful tuning of $\omega$; larger $\omega$ causes earlier fallback to standard tracing [S1][S3, unofficial]. Non-Lipschitz SDFs may require disabling over-relaxation [S4, unofficial].

## Background
The method was introduced by Keinert et al. in 2014 in the paper "Enhanced Sphere Tracing" [S1][S4, unofficial][S5, abstract only, unofficial]. It builds on the principle of over-relaxation from numerical analysis to accelerate the convergence of sphere tracing [S1]. It is widely used in real-time ray marching, including in tools like User Bulb and KIFS [S4, unofficial].
