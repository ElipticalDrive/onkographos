# Depth Rendering


## Overview
Depth Rendering is a visualization technique that maps ray traversal metrics to grayscale intensity, providing a direct representation of distance or computational depth [S1, unofficial]. The source implementation computes intensity from the number of traversal steps, while the accompanying documentation describes an alternative mapping using the hit position's z-coordinate [S1, unofficial].

## How it works
**Inputs:**
- `tree`: Voxel data structure containing spatial bounds `tree->min[2]` and `tree->max[2]` along the depth axis, and side length `tree->gridlength` [S1, unofficial].
- `rc`: Render context providing pixel dimension `rc.n_y` (assumed square) and ray generation `rc.getRayForPixel(x, y)` returning origin `o` and direction `d` [S1, unofficial].
- `texture_array`: Output buffer of size `n_y * n_y * 4` (RGBA), where each pixel occupies 4 unsigned chars [S1, unofficial].

**Data Structures:**
- Ray: Defined by origin `o` (vec3) and direction `d` (vec3, typically normalized) [S1, unofficial].
- Voxel Grid: Uniform grid spanning `[0, gridlength)` in each axis [S1, unofficial].

**Parameters:**
- `gridlength`: Side length of the voxel grid, used for normalization [S1, unofficial].
- `factor`: Normalized intensity value in range [0, 1] [S1, unofficial].

**Algorithm:**
1. Initialize OpenMP threads equal to the number of CPU processors [S1, unofficial].
2. Parallelize the outer pixel loop over `y` [S1, unofficial].
3. For each pixel `(x, y)`:
   a. Compute `index = y * (n_y * 4) + x * 4`.
   b. Initialize ray traverser with `tree`, `o`, and `d` [S1, unofficial].
   c. Traverse the tree:
      i. While not terminated:
         - If leaf node has data, break loop [S1, unofficial].
         - Else, call `t.step()` [S1, unofficial].
   d. Get hit position `pos = t.getCurrentPosition()` [S1, unofficial].
   e. Compute intensity from step count:
      $$ factor = \frac{stepcount}{\log_2(gridlength)} $$
      [S1, unofficial]
      (Note: The source notes describe an alternative position-based factor $factor = \frac{|pos[2]|}{|tree->max[2]| - |tree->min[2]|}$, but the executable code uses step count [S1, unofficial].)
   f. Compute grayscale color:
      $$ val = 255 \times (1 - factor) $$
      [S1, unofficial]
   g. Write to `texture_array`:
      - `texture_array[index] = val`
      - `texture_array[index+1] = val`
      - `texture_array[index+2] = val`
      - `texture_array[index+3] = 1` (Alpha) [S1, unofficial]

**Pseudocode:**
```python
import math

def render_depth(tree, rc, texture_array):
    n_y = rc.n_y
    gridlength = tree.gridlength
    log2_size = math.log2(gridlength) if gridlength > 0 else 1.0
    
    for y in range(n_y):
        partindex = y * (n_y * 4)
        for x in range(n_y):
            index = partindex + x * 4
            ray = rc.getRayForPixel(x, y)
            o, d = ray.origin, ray.direction
            
            stepcount = 0
            hit = False
            
            # DDA initialization for uniform grid [G]
            if d[0] == 0: t_max_x = float('inf')
            else: t_max_x = ((0 if d[0] > 0 else gridlength) - o[0]) / d[0]
            if d[1] == 0: t_max_y = float('inf')
            else: t_max_y = ((0 if d[1] > 0 else gridlength) - o[1]) / d[1]
            if d[2] == 0: t_max_z = float('inf')
            else: t_max_z = ((0 if d[2] > 0 else gridlength) - o[2]) / d[2]
            
            step_x = 1 if d[0] > 0 else -1
            step_y = 1 if d[1] > 0 else -1
            step_z = 1 if d[2] > 0 else -1
            
            t_delta_x = abs(1.0 / d[0]) if d[0] != 0 else float('inf')
            t_delta_y = abs(1.0 / d[1]) if d[1] != 0 else float('inf')
            t_delta_z = abs(1.0 / d[2]) if d[2] != 0 else float('inf')
            
            cur_x = int(o[0]) if 0 <= o[0] < gridlength else -1
            cur_y = int(o[1]) if 0 <= o[1] < gridlength else -1
            cur_z = int(o[2]) if 0 <= o[2] < gridlength else -1
            
            # Traverse until bounds exceeded or hit found
            while stepcount < gridlength * 3 + 100:
                if 0 <= cur_x < gridlength and 0 <= cur_y < gridlength and 0 <= cur_z < gridlength:
                    hit = True
                    break
                if t_max_x < t_max_y:
                    if t_max_x < t_max_z:
                        cur_x += step_x
                        t_max_x += t_delta_x
                    else:
                        cur_z += step_z
                        t_max_z += t_delta_z
                else:
                    if t_max_y < t_max_z:
                        cur_y += step_y
                        t_max_y += t_delta_y
                    else:
                        cur_z += step_z
                        t_max_z += t_delta_z
                stepcount += 1
            
            # Compute intensity from step count [S1, unofficial]
            factor = stepcount / log2_size
            factor = max(0.0, min(1.0, factor))
            val = int(255 * (1.0 - factor))
            
            texture_array[index] = val
            texture_array[index+1] = val
            texture_array[index+2] = val
            texture_array[index+3] = 1
```

**Edge Cases and Pitfalls:**
- **Division by Zero:** If `gridlength == 0`, `log2_size` is clamped to 1.0 to prevent NaN/Inf [G].
- **Termination:** If the ray escapes the tree without hitting a surface, the loop terminates when bounds are exceeded. The code sets alpha to 1 regardless of hit status [S1, unofficial].
- **Coordinate System:** The notes' formula uses `abs(pos[2])`, implying depth is the Z-axis. Standard graphics APIs often use Y or -Z for depth [G].

## Subtopics

### Logarithmic Depth Rendering
A variant that normalizes the logarithmic distance traveled by the ray to the range [0, 1], where brighter pixels indicate further travel distance [S2, unofficial]. It calculates distance $d = |p_i - p_0|$, computes $\log(d)$, and normalizes it. This helps visualize depth over large ranges where linear mapping would compress distant details [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of steps per ray [S1, unofficial]. Parallelized with OpenMP [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the output texture array [S1, unofficial].
- **Strengths:** Simple to implement; provides immediate visual feedback on object proximity [S1, unofficial].
- **Limitations:** Does not account for surface orientation or lighting; linear mapping may not be perceptually uniform [S1, unofficial].

## Background
Originated in early voxel rendering implementations for CPU-based raycasting, specifically in the `cpu_voxel_raycaster` project by Forceflow [S1, unofficial].
