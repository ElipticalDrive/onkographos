# Depth Rendering

Also called: Depth Visualization, Z-Buffer Visualization

## Overview
Depth Rendering is a visualization technique that maps the depth coordinate (z-coordinate) of the first surface hit by a ray to grayscale intensity, allowing the viewer to perceive the spatial structure of a volume or scene based on proximity [S1, unofficial]. It differs from standard shading methods by ignoring surface normals and lighting, relying solely on the distance from the camera to the closest voxel to determine pixel brightness [S2, unofficial].

## How it works
**Inputs:**
- A voxel tree (e.g., Octree) containing spatial data [S1, unofficial].
- A ray generation function `rc.getRayForPixel(x, y)` that returns a ray for each pixel coordinate $(x, y)$ [S1, unofficial].
- The tree's bounding box depth limits: `tree->min[2]` and `tree->max[2]` [S1, unofficial].
- Output buffer: `texture_array` of size $N \times 4$ (RGBA), where $N$ is the number of pixels [S1, unofficial].

**Data Structures:**
- `VoxelData`: Contains `morton` (uint64_t), `color` (vec3), and `normal` (vec3) [S1, unofficial].
- `TreeTraverser`: Manages the traversal state, including `stepcount` and current position [S1, unofficial].

**Algorithm:**
1.  **Initialization:** Set the number of OpenMP threads to the number of available CPU cores [S1, unofficial].
2.  **Parallel Loop:** Iterate over each pixel $(x, y)$ in parallel [S1, unofficial].
3.  **Ray Traversal:**
    - Initialize `TreeTraverser t` with the tree and the ray for pixel $(x, y)$ [S1, unofficial].
    - Traverse the tree while `!t.isTerminated()` [S1, unofficial]:
        - If the current node is a leaf and has data, break the loop [S1, unofficial].
        - Otherwise, call `t.step()` to advance to the next node [S1, unofficial].
4.  **Hit Position:** Retrieve the position of the hit point using `t.getCurrentPosition()` [S1, unofficial]. Let this be $p = (p_x, p_y, p_z)$ [S1, unofficial].
5.  **Depth Factor Calculation:**
    - Compute the normalized depth factor $f$ using the z-coordinate of the hit point and the tree's depth bounds [S1, unofficial]:
      $$ f = \frac{|p_z|}{|tree\_max_z| - |tree\_min_z|} $$
      where $tree\_max_z = tree->max[2]$ and $tree\_min_z = tree->min[2]$ [S1, unofficial].
6.  **Grayscale Conversion:**
    - Calculate the grayscale intensity $I$ for R, G, and B channels [S1, unofficial]:
      $$ I = 255 - (255 \times f) $$
    - Clamp $I$ to the range $[0, 255]$ and cast to `unsigned char` [S1, unofficial].
7.  **Output:**
    - Write $I$ to `texture_array[index]`, `texture_array[index+1]`, and `texture_array[index+2]` [S1, unofficial].
    - Set alpha to 1: `texture_array[index+3] = 1` [S1, unofficial].

**Pseudocode:**
```python
import math

def render_depth(tree, rc, texture_array):
    # Initialize OpenMP threads [S1, unofficial]
    num_threads = get_num_procs()
    set_num_threads(num_threads)

    # Parallel pixel loop [S1, unofficial]
    for y in range(rc.n_y):
        for x in range(rc.n_y):
            index = y * (rc.n_y * 4) + x * 4
            
            # Initialize ray traverser [S1, unofficial]
            ray = rc.get_ray_for_pixel(x, y)
            t = TreeTraverser(tree, ray)
            
            # Traverse tree [S1, unofficial]
            while not t.is_terminated():
                current_node = t.get_current_node()
                if current_node.is_leaf() and current_node.has_data():
                    break
                t.step()
            
            # Get hit position [S1, unofficial]
            pos = t.get_current_position()
            pos_z = pos[2]
            
            # Compute depth factor [S1, unofficial]
            max_z = abs(tree.max[2])
            min_z = abs(tree.min[2])
            denominator = max_z - min_z
            
            if denominator == 0:
                factor = 0.0
            else:
                factor = abs(pos_z) / denominator
            
            # Compute grayscale color [S1, unofficial]
            intensity = 255 - (255 * factor)
            # Clamp to [0, 255] and cast to int
            intensity = max(0, min(255, int(intensity)))
            
            # Write color [S1, unofficial]
            texture_array[index] = intensity
            texture_array[index + 1] = intensity
            texture_array[index + 2] = intensity
            texture_array[index + 3] = 1
```

**Parameters:**
- `tree->min[2]` and `tree->max[2]`: Define the depth bounds for normalization [S1, unofficial].

**Edge Cases:**
- If the ray does not hit any leaf node with data, the behavior depends on the traverser's termination condition. The provided code assumes a hit is always found or the loop terminates naturally [S1, unofficial].
- Division by zero if `tree->max[2] == tree->min[2]` [G].

## Subtopics

### Logarithmic Depth Rendering
A variant that normalizes the logarithmic distance traveled by the ray to the range $[0, 1]$, where brighter pixels indicate further travel distance [S2, unofficial]. It calculates the distance $d = |p_i - p_0|$ between the hit point $p_i$ and the origin $p_0$, computes $\log(d)$, and normalizes it [S2, unofficial]. This method is useful for visualizing large depth ranges where linear mapping would compress distant details [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of steps per ray [S1, unofficial]. Parallelized with OpenMP [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the output texture array [S1, unofficial].
- **Strengths:** Simple to implement; provides immediate visual feedback on depth structure without lighting calculations [S1, unofficial].
- **Limitations:** Ignores surface orientation, which can lead to ambiguous depth perception for flat surfaces facing the camera [S2, unofficial]. Linear mapping may not utilize the full dynamic range for scenes with large depth variations [S2, unofficial].

## Background
Depth Rendering is implemented in CPU-based voxel raycasters, such as the `cpu_voxel_raycaster` project, to visualize the spatial distribution of voxel data [S1, unofficial]. It serves as a debugging and visualization tool for volume rendering pipelines, allowing developers to inspect the depth of the first hit without the complexity of shading [S1, unofficial].
