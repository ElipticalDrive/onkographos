# Depth Rendering

Also called: Depth Map Rendering, Z-Buffer Visualization

## Overview
Depth Rendering is a visualization technique that maps the z-coordinate (depth) of the first surface hit by a ray to grayscale intensity, producing a depth map [S1, unofficial]. It differs from [Iteration-Based Coloring](1244-iteration-based-coloring.md) by using the geometric position of the hit point rather than the computational step count to determine pixel brightness.

## How it works
**Inputs:**
- A voxel tree (e.g., Octree) containing spatial data.
- A render context defining image dimensions ($n_x, n_y$) and ray generation logic.
- Tree bounds: $min$ and $max$ vectors defining the axis-aligned bounding box of the voxel data.

**Outputs:**
- A texture array (RGBA) where each pixel is a grayscale value with alpha=1.

**Data Structures:**
- `TreeTraverser`: Manages ray traversal through the tree.
- `DataPoint`: Represents voxel content (not strictly used for color in this method, but checked for existence).

**Steps:**
1. Initialize parallel execution threads equal to the number of CPU processors [S1, unofficial].
2. Iterate over each pixel $(x, y)$ in parallel.
3. For each pixel, create a `TreeTraverser` instance initialized with the tree and the ray for $(x, y)$ [S1, unofficial].
4. Traverse the tree:
   - While the traverser is not terminated:
     - If the current node is a leaf and contains data, break the loop [S1, unofficial].
     - Otherwise, step to the next node [S1, unofficial].
5. Retrieve the hit position $pos$ from the traverser [S1, unofficial].
6. Compute the depth factor $f$ by normalizing the absolute z-coordinate of the hit position against the tree's z-bounds:
   $$ f = \frac{|pos_z|}{|max_z| - |min_z|} $$
   [S1, unofficial]
7. Compute grayscale intensity $I$:
   $$ I = 255 - (255 \times f) $$
   [S1, unofficial]
8. Set pixel color to $(I, I, I)$ and alpha to 1 [S1, unofficial].

**Pseudocode:**
```python
def render_depth(tree, rc, texture_array):
    # Initialize OpenMP threads [S1, unofficial]
    num_threads = omp_get_num_procs()
    omp_set_num_threads(num_threads)

    # Parallel pixel loop [S1, unofficial]
    for y in range(rc.n_y):
        for x in range(rc.n_x):
            # Initialize ray traverser [S1, unofficial]
            t = TreeTraverser(tree, rc.get_ray_for_pixel(x, y))
            
            # Traverse tree [S1, unofficial]
            while not t.is_terminated():
                current_node = t.get_current_node()
                if current_node.is_leaf() and current_node.has_data():
                    break
                t.step()
            
            # Get hit position [S1, unofficial]
            pos = t.get_current_position()
            
            # Compute depth factor [S1, unofficial]
            # Note: Source uses abs() on bounds. If min_z is negative, 
            # |min_z| is positive. This effectively maps [min_z, max_z] 
            # to [0, 1] based on distance from origin or specific normalization.
            z_min = abs(tree.max[2])
            z_max = abs(tree.min[2])
            denominator = z_min - z_max # Source: abs(tree->max[2])-abs(tree->min[2])
            
            # Guard against division by zero [G]
            if denominator == 0:
                denominator = 1.0
                
            factor = abs(pos[2]) / denominator
            
            # Compute grayscale [S1, unofficial]
            intensity = 255 - (255 * factor)
            
            # Write color [S1, unofficial]
            index = (y * rc.n_x + x) * 4
            texture_array[index] = int(intensity)
            texture_array[index + 1] = int(intensity)
            texture_array[index + 2] = int(intensity)
            texture_array[index + 3] = 1
```

**Parameters:**
- Tree bounds $min$ and $max$: Used for normalization [S1, unofficial].

**Edge Cases:**
- If the ray terminates without hitting a leaf with data, the hit position is undefined. The source code breaks only on hit; if terminated without hit, `pos` may be invalid. [G] Implementation should check `is_terminated()` after the loop and handle miss cases (e.g., black or background color).
- Division by zero if $|max_z| = |min_z|$.

## Subtopics

### Logarithmic Depth Rendering
A visualization technique that renders a depth map by normalizing the logarithmic distance traveled by the ray [S2, unofficial]. It differs from linear depth rendering by compressing large depth ranges, making distant features more visible [S2, unofficial]. To implement: calculate the Euclidean distance $d = \|p_i - p_0\|$ from the ray origin $p_0$ to the hit point $p_i$ [S2, unofficial]. Compute $\log(d)$ [S2, unofficial]. Normalize this value to the range $[0, 1]$ using min-max scaling: $f = \frac{\log(d) - \min(\log)}{\max(\log) - \min(\log)}$ [S2, unofficial]. Brighter pixels indicate further travel distance [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of steps per ray. Parallelized across CPU cores [S1, unofficial].
- **Memory Complexity:** $O(N)$ for the output texture array.
- **Strengths:** Simple to implement; provides immediate visual feedback on surface proximity [S1, unofficial].
- **Limitations:** Sensitive to the choice of normalization bounds; does not account for surface orientation or lighting [S1, unofficial].
- **When to use:** Debugging voxel structures, visualizing depth distribution.
- **When not to use:** When surface normals or lighting effects are required.

## Background
Originated in early voxel rendering implementations for CPU-based raycasting [S1, unofficial]. Used in educational contexts and simple visualization tools to debug voxel tree structures [S1, unofficial].
