# Dynamic SDF Ray Marching with Adaptive Step Skipping

Also called: Ray Advancing Kernel, SDF Marching

## Overview
A GPU-based ray marching technique for Signed Distance Fields (SDFs) that advances ray origins by predicted distances, skips empty space using an octree, handles floor reflections, and tracks shadow visibility metrics for soft shadows [S1, unofficial]. Unlike standard SDF marching which uses `fminf(distance, max_step)`, this method uses a predicted distance from previous steps (`prev_distances`) to determine step size and visibility, allowing for adaptive skipping of empty space via the octree [S1, unofficial].

## How it works
**Inputs and Outputs:**
The kernel operates on device buffers [S1, unofficial].
*   `positions`: `Vector3f*` array of current ray origins [S1, unofficial].
*   `distances`: `float*` array of raw distance field values retrieved at the current position [S1, unofficial].
*   `payloads`: `SdfPayload*` array containing ray state (`alive`, `dir`, `n_steps`, `idx`) [S1, unofficial].
*   `prev_distances`: `float*` array storing the distance estimate from the previous step for each ray [S1, unofficial].
*   `total_distances`: `float*` array accumulating total distance traveled (used for visibility metrics) [S1, unofficial].
*   `min_visibility`: `float*` array tracking minimum visibility values [S1, unofficial].
*   `octree_nodes`: Optional reference to a `TriangleOctree` structure for spatial acceleration [S1, unofficial].
*   `floor_y`: Float constant defining the floor plane height [S1, unofficial].
*   `distance_scale`: Float multiplier for distance scaling [S1, unofficial].
*   `zero_offset`: Float offset subtracted from raw distance [S1, unofficial].
*   `maximum_distance`: Float threshold for ray termination [S1, unofficial].
*   `k`: Constant factor for visibility calculation (value not given in the sources) [S1, unofficial].
*   `aabb`: Axis-aligned bounding box for ray containment [S1, unofficial].
*   `n_elements`: Total number of rays processed [S1, unofficial].

**Data Structures:**
*   `SdfPayload`:
    *   `alive`: `bool` indicating if the ray is active [S1, unofficial].
    *   `dir`: `Vector3f` ray direction [S1, unofficial].
    *   `n_steps`: `uint32_t` or `int` step counter [S1, unofficial].
    *   `idx`: `uint32_t` thread/element index [S1, unofficial].

**Algorithm Steps:**
1.  Calculate thread index `i` and check bounds `i >= n_elements` [S1, unofficial].
2.  Check payload alive status; if not alive, return [S1, unofficial].
3.  Retrieve `distance` from `distances[i]`, subtract `zero_offset`, and multiply by `distance_scale` [S1, unofficial].
4.  Advance position: `pos += distance * payload.dir` [S1, unofficial].
5.  If `octree_nodes` exists and `pos` is not contained in the octree (`!TriangleOctree::contains`), calculate intersection distance `octree_distance` using `TriangleOctree::ray_intersect`, add `1e-6f` epsilon, update `distance += octree_distance`, and `pos += octree_distance * payload.dir` [S1, unofficial].
6.  If `pos.y() < floor_y` and `payload.dir.y() < 0.f`, calculate floor intersection `floor_dist = -(pos.y()-floor_y)/payload.dir.y()`, update `distance += floor_dist`, `pos += floor_dist * payload.dir`, and set `payload.alive = false` [S1, unofficial].
7.  Update `positions[i] = pos` [S1, unofficial].
8.  If `total_distances` is not null and `distance > 0.0f`: calculate `y = distance*distance / (2.0f * prev_distances[i])`, `d = sqrtf(distance*distance - y*y)`, update `min_visibility[i] = fminf(min_visibility[i], k * d / fmaxf(0.0f, total_distance - y))` where `total_distance = total_distances[i]`, update `prev_distances[i] = distance`, and `total_distances[i] += distance` [S1, unofficial].
9.  Check survival: `stay_alive = distance > maximum_distance && fabsf(distance / 2) > 3*maximum_distance` [S1, unofficial]. If not alive, set `payload.alive = false` and return [S1, unofficial].
10. Check AABB containment; if `!aabb.contains(pos)`, set `payload.alive = false` and return [S1, unofficial].
11. Increment `payload.n_steps++` [S1, unofficial].

**Pseudocode:**
```python
import math

def get_thread_index():
    return 0  # Runtime intrinsic placeholder

def advance_pos_kernel_sdf(positions, distances, payloads, prev_distances, 
                           total_distances, min_visibility, octree_nodes, 
                           floor_y, distance_scale, zero_offset, maximum_distance, 
                           k, aabb, n_elements):
    i = get_thread_index()
    if i >= n_elements:
        return

    payload = payloads[i]
    if not payload.alive:
        return

    # Step 3: Retrieve and scale distance
    raw_dist = distances[i]
    distance = (raw_dist - zero_offset) * distance_scale
    
    # Step 4: Advance position
    pos = positions[i] + distance * payload.dir
    
    # Step 5: Octree skip
    if octree_nodes is not None and not octree_nodes.contains(pos):
        octree_distance = octree_nodes.ray_intersect(pos, payload.dir)
        octree_distance += 1e-6  # Epsilon to prevent self-intersection
        distance += octree_distance
        pos += octree_distance * payload.dir
        
    # Step 6: Floor reflection
    if pos.y < floor_y and payload.dir.y < 0.0:
        floor_dist = -(pos.y - floor_y) / payload.dir.y
        distance += floor_dist
        pos += floor_dist * payload.dir
        payload.alive = False
        
    # Step 7: Update position
    positions[i] = pos
    
    # Step 8: Visibility metrics
    if total_distances is not None and distance > 0.0:
        prev_d = prev_distances[i]
        if prev_d > 0.0:  # Guard against division by zero [G]
            y = (distance * distance) / (2.0 * prev_d)
            d_val = math.sqrt(max(0.0, distance * distance - y * y))
            total_dist = total_distances[i]
            denom = max(0.0, total_dist - y)
            if denom > 0.0:
                visibility_val = (k * d_val) / denom
                min_visibility[i] = min(min_visibility[i], visibility_val)
        prev_distances[i] = distance
        total_distances[i] += distance
        
    # Step 9: Survival check
    stay_alive = (distance > maximum_distance) and (abs(distance / 2.0) > 3.0 * maximum_distance)
    if not stay_alive:
        payload.alive = False
        return
        
    # Step 10: AABB containment
    if not aabb.contains(pos):
        payload.alive = False
        return
        
    # Step 11: Increment steps
    payload.n_steps += 1
```

**Parameters:**
*   `MARCH_ITER`: Constant set to 10000, likely the maximum number of march steps or iterations allowed in the testbed context [S1, unofficial].
*   `zero_offset`: A float offset subtracted from the raw distance value before scaling [S1, unofficial].
*   `distance_scale`: A float multiplier applied to the distance after zero offset subtraction [S1, unofficial].
*   `maximum_distance`: A float threshold; if the current step distance is less than or equal to this, or if half the distance is not greater than 3 times this value, the ray is killed [S1, unofficial].
*   `k`: Constant factor for visibility calculation (value not given in the sources) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Self-intersection:** When skipping octree nodes, a small epsilon `1e-6f` is added to the intersection distance to handle precision issues [S1, unofficial].
*   **Floor Termination:** If the ray hits the floor (`pos.y() < floor_y` and moving downwards), the ray is marked as dead immediately after calculating the intersection [S1, unofficial].
*   **Division by Zero:** In the visibility formula, `prev_distances[i]` and `total_distance - y` are used as denominators; the source code uses `fmaxf(0.0f, ...)` for the latter, but explicit checks for zero `prev_distances` are recommended to prevent NaN propagation [G].

## Operating characteristics
*   **Time Complexity:** Linear with respect to the number of rays and steps, but adaptive skipping via octree reduces the number of SDF evaluations in empty space [S1, unofficial].
*   **Memory Complexity:** Requires storage for `prev_distances`, `total_distances`, and `min_visibility` buffers in addition to standard ray buffers [S1, unofficial].
*   **Strengths:** Adaptive step size based on previous estimates allows for larger steps in empty space. Octree integration enables efficient skipping of large empty volumes. Visibility metrics support soft shadow calculation [S1, unofficial].
*   **Limitations:** Requires maintaining history buffers (`prev_distances`). Floor reflection logic is hardcoded and may not generalize to all scenes [S1, unofficial].
*   **When to use:** Scenes with large empty spaces where octree acceleration is effective, and soft shadow visibility metrics are required [S1, unofficial].
*   **When not to use:** Scenes without a defined floor plane, or where high-precision surface proximity requires smaller, more frequent steps than the adaptive predictor allows [G].

## Background
Originating from the Dynamic-NGPs project, this method is part of a pipeline for training and rendering dynamic neural graphics primitives [S1, unofficial]. It is used in the rendering phase to generate frames from trained models, incorporating spatial acceleration and shadow visibility tracking [S1, unofficial].
