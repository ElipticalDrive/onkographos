# Analytical and Differentiable Methods
## Overview
Analytical and Differentiable Methods evaluate Signed Distance Functions (SDFs) analytically at render time instead of discretizing them into grids, enabling either gradient-based optimization for inverse graphics or optimized real-time shader evaluation [S1, unofficial][S2, unofficial]. This sets them apart from grid-based or uniform sampling approaches by preserving continuous differentiability or minimizing SDF evaluations per ray through offline compilation [S1, unofficial][S2, unofficial].

## Shared principles
All variants in this family bypass precomputed distance grids, computing SDF values directly from analytical expressions or neural networks during ray marching [S1, unofficial][S2, unofficial]. They rely on the Lipschitz continuity of the underlying functions to guarantee safe step sizes and convergence [S2, unofficial]. Differentiable variants additionally ensure the entire forward and backward rendering pipeline is compatible with automatic differentiation frameworks [S1, unofficial].

## Subtopics

### [Differentiable Sphere Tracing](2316-differentiable-sphere-tracing.md)
Differentiable Sphere Tracing (DIST) is a rendering algorithm for implicit SDFs represented by neural networks, enabling efficient forward and backward passes for inverse graphics optimization. It solves the problem of non-differentiable or computationally prohibitive ray marching in neural implicit representations by optimizing the rendering pipeline for GPU efficiency. It sets itself apart from naive sphere tracing by using a coarse-to-fine approach and aggressive ray marching to save computation, and from standard differentiable renderers by providing a specific gradient approximation that reduces memory consumption while maintaining training performance. Choose this for inverse graphics with neural SDFs.

```python
import torch
import torch.nn as nn

def differentiable_sphere_tracing(sdf_network, camera_intrinsics, camera_extrinsics, image_height, image_width, 
                                  num_iterations=2000, convergence_threshold=1e-3, bounding_radius=None):
    # 1. Initialize Camera Rays
    y, x = torch.meshgrid(torch.arange(image_height), torch.arange(image_width), indexing='ij')
    homo_grid = torch.stack([x, y, torch.ones_like(x)], dim=0).float()
    K_inv = torch.inverse(camera_intrinsics)
    homo_calib = torch.matmul(K_inv, homo_grid.view(3, -1))
    R = camera_extrinsics[:3, :3]
    rays = torch.matmul(R.t(), homo_calib)
    rays = rays / torch.norm(rays, dim=0, keepdim=True)
    rays = rays.view(3, image_height, image_width).permute(1, 2, 0)
    cam_pos = -torch.matmul(R.t(), camera_extrinsics[:3, 3:4]).squeeze()
    ray_positions = cam_pos.unsqueeze(0).unsqueeze(0).repeat(image_height, image_width, 1)
    ray_directions = rays
    foreground_masks = torch.ones((image_height, image_width, 1), dtype=torch.bool, device=ray_positions.device)

    # Handle Bounding Radius
    if bounding_radius is not None:
        a = torch.sum(ray_directions * ray_directions, dim=-1, keepdim=True)
        b = 2 * torch.sum(ray_directions * ray_positions, dim=-1, keepdim=True)
        c = torch.sum(ray_positions * ray_positions, dim=-1, keepdim=True) - bounding_radius ** 2
        d = b ** 2 - 4 * a * c
        d = torch.clamp(d, min=0.0)
        t = (-b - torch.sqrt(d)) / (2 * a)
        t = torch.clamp(t, min=0.0)
        bounded = d >= 0
        ray_positions = torch.where(bounded, ray_positions + ray_directions * t, ray_positions)
        foreground_masks = foreground_masks & bounded.unsqueeze(-1)

    # 2. Ray Marching Loop
    for i in range(num_iterations):
        pos_flat = ray_positions.view(-1, 3)
        sdf_values = sdf_network(pos_flat).view(image_height, image_width, 1)
        converged = torch.abs(sdf_values) < convergence_threshold
        march_mask = foreground_masks.squeeze(-1) & ~converged.squeeze(-1)
        update_mask = foreground_masks.squeeze(-1) if i == 0 else march_mask
        step_size = torch.where(update_mask, torch.abs(sdf_values), torch.zeros_like(sdf_values))
        ray_positions = torch.where(update_mask.unsqueeze(-1), ray_positions + ray_directions * step_size, ray_positions)
        if bounding_radius is not None:
            dist_from_origin = torch.norm(ray_positions, dim=-1, keepdim=True)
            bounded = dist_from_origin < bounding_radius
            foreground_masks = foreground_masks & bounded
        if torch.all(~foreground_masks.squeeze(-1) | converged.squeeze(-1)):
            break

    # 3. Backward Pass (Gradient Computation)
    ray_positions_detached = ray_positions.detach()
    ray_positions_detached.requires_grad_(True)
    pos_flat_detached = ray_positions_detached.view(-1, 3)
    sdf_values_detached = sdf_network(pos_flat_detached).view(image_height, image_width, 1)
    grad_outputs = torch.ones_like(sdf_values_detached)
    grad_positions, = torch.autograd.grad(
        outputs=sdf_values_detached, 
        inputs=ray_positions_detached, 
        grad_outputs=grad_outputs, 
        retain_graph=True, 
        create_graph=True
    )
    grad_outputs_dot_directions = torch.sum(grad_outputs * ray_directions, dim=-1, keepdim=True)
    grad_positions_dot_directions = torch.sum(grad_positions * ray_directions, dim=-1, keepdim=True)
    grad_positions_dot_directions = torch.where(
        grad_positions_dot_directions > 0, 
        torch.clamp(grad_positions_dot_directions, min=1e-6), 
        torch.clamp(grad_positions_dot_directions, max=-1e-6)
    )
    grad_outputs = -grad_outputs_dot_directions / grad_positions_dot_directions
    grad_outputs = torch.where(converged, grad_outputs, torch.zeros_like(grad_outputs))
    depth = torch.norm(ray_positions - cam_pos.unsqueeze(0).unsqueeze(0), dim=-1)
    normals = grad_positions / (torch.norm(grad_positions, dim=-1, keepdim=True) + 1e-12)
    return ray_positions, sdf_values, normals, depth, grad_outputs
```

### Aeva Analytical SDF Rendering
An approach that avoids discretization by sphere-tracing analytical SDFs at render time, using offline compilation of CSG trees into optimized shaders [S1, unofficial]. It sets itself apart by analyzing CSG trees offline to compile a large set of shaders, each correctly rendering a portion of the scene with the minimum number of SDF evaluations per ray [S1, unofficial]. Choose this for real-time rendering of complex CSG geometries where offline compilation is acceptable [S1, unofficial]. Pitfall: Not suited for real-time modification because continuously recompiling shaders at runtime is not feasible or effective for GPU hardware [S1, unofficial]. Presented by Aeva (2022) [S1, unofficial].

### Analytical Derivatives for Normals and Slopes
A technique using analytical derivatives of noise to compute fast normals and slopes, which helps speed up the raymarching process by adjusting step size based on slope [S2, unofficial]. It sets itself apart by leveraging the Lipschitz constant of noise functions to dynamically adjust step size, taking smaller steps for steeper slopes [S2, unofficial]. Choose this for raymarching noise-based terrains or fractals where normal computation is a bottleneck [S2, unofficial]. Used in the 'Rainforest' Shadertoy example (2016) for raymarching a signed distance field of a tree-populated terrain [S2, unofficial].

## Background
Differentiable Sphere Tracing addresses the computational bottlenecks of neural implicit representations by enabling end-to-end gradient flow for inverse graphics [S1, unofficial]. Analytical SDF rendering was introduced by Aeva (2022) to enable real-time CSG evaluation without grid discretization, though it requires offline shader compilation [S1, unofficial]. Analytical derivatives for normals and slopes were demonstrated in 2016 Shadertoy examples to optimize raymarching performance for noise-based SDFs [S2, unofficial].
