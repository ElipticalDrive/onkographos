# Adaptive Step Size Ray Marching

Also called: Adaptive Step Size Volume Rendering, CSRayMarch, DDVR, DDVR Raymarching Shader, Ray Marching with Adaptive Step Size, Ray Marching with Adaptive Step Size and Temporal Accumulation, Volume Rendering via Ray Marching

## Overview
Adaptive Step Size Ray Marching is a volume rendering technique that optimizes computational cost by dynamically varying the sampling interval along a ray based on local density changes and transmittance [S1][S2, S3, unofficial]. Unlike fixed-step methods that force a trade-off between quality and efficiency, this method uses fine steps in high-density regions and coarse steps in empty space, often combined with early termination [S4, unofficial]. It distinguishes itself from siblings like [Dynamic Sampling Step Adjustment](2442-dynamic-sampling-step-adjustment.md) by explicitly linking step size to density gradients and transmittance thresholds to manage accumulation and noise in real-time rendering [S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera parameters (origin $\mathbf{o}$, direction $\mathbf{d}$), volume bounding box ($\mathbf{bb}_{min}, \mathbf{bb}_{max}$), 3D/4D volume texture(s), transfer function/color map, configuration parameters (base step size, thresholds).
*   **Outputs:** Final pixel color (RGB) and alpha (A), optional motion vectors, depth buffer.

**Data Structures:**
*   **Volume Texture:** 3D or 4D texture storing density/scalar values. For 4D, two textures are used: `volumeTexture` (current frame) and `volumeTexture4DNextFrame` (next frame) [S3, unofficial].
*   **Noise Image:** 2D image (`rg32f`) storing per-pixel noise. Component `.r` stores the current adaptive step size (or 0 for default). Component `.g` stores the ray offset/jitter [S3, unofficial].
*   **Position Depth Buffer:** 2D image (`rgba32f`) storing the world position of the first hit (`.xyz`) and depth $t$ (`.w`) [S3, unofficial].
*   **Motion Vector Image:** 2D image (`rgba8`) storing motion vectors in UV space (`.xy`) [S3, unofficial].
*   **Output Image:** 2D image (`rgba8`) storing the final rendered color and alpha [S3, unofficial].

**Parameters:**
*   `stepSize`: Base step size for ray marching [S3, unofficial].
*   `ZERO_THRESHOLD`: Threshold for density and transmittance to skip empty space or terminate [S2, unofficial].
*   `EARLY_STOP_THRESHOLD`: Transmittance value below which the ray terminates early (e.g., 0.05) [S4, unofficial].
*   `STEPSIZE_FINE`: Maximum size of a fine step [S4, unofficial].
*   `COARSE_STEPSIZE_MULTIPLIER`: Multiplier to determine coarse step size from fine step size [S4, unofficial].
*   `MAX_NUM_MISSED_STEPS`: Threshold for switching from fine to coarse steps after missing cloud density [S4, unofficial].
*   `g_numSamples`: Maximum number of ray steps per iteration [S2, unofficial].
*   `ABSORPTION`: Absorption coefficient [S2, unofficial].
*   `accumulation`: Boolean flag enabling temporal accumulation [S3, unofficial].
*   `bVolume4D`: Boolean flag indicating time-varying volume [S3, unofficial].
*   `pingpong4D`: Boolean flag for swapping 4D volume textures [S3, unofficial].
*   `interpolationFactor`: Float for mixing 4D volume frames [S3, unofficial].
*   `scalarMinMax`: Vec2 for density normalization [S3, unofficial].
*   `illuminationScale`: Scalar multiplier for final color [S3, unofficial].

**Algorithm Steps:**

1.  **Ray Initialization:**
    *   Construct ray $r(t) = \mathbf{o} + t\mathbf{d}$ from camera position and UV coordinates [S3, unofficial].
    *   Perform ray-box intersection against the volume bounding box to find entry distance $t_{entry}$ and exit distance $t_{exit}$ [S1][S3, unofficial].
    *   If no intersection, output black color and zero depth, then return [S3, unofficial].
    *   Initialize transmittance $T = 1.0$, accumulated color $C_{acc} = \mathbf{0}$, and light energy $L = 0.0$ [S4, unofficial].
    *   Initialize step size $dt$ and offset. Load noise offset from `noiseImage` [S3, unofficial].

2.  **Step Size Determination:**
    *   The step size is adapted based on local density and transmittance [S2, unofficial].
    *   If using a noise-based approach, the step size $m\_stepSize$ is loaded from `noiseImage.r`. If 0, use the base `stepSize` [S3, unofficial].
    *   Calculate the step offset for jittering: $offset += (1 / m\_stepSize \times 10) \times 0.00001$ [S3, unofficial].
    *   In cloud rendering variants, use fine steps inside density and coarse steps outside, switching after `MAX_NUM_MISSED_STEPS` [S4, unofficial].

3.  **Ray Marching Loop:**
    *   Iterate $t$ from $t_{entry} + offset$ to $t_{exit}$ with step $dt$ [S3, unofficial].
    *   **Termination Conditions:**
        *   If $t > t_{exit}$, break [S3, unofficial].
        *   If transmittance $T < ZERO\_THRESHOLD$ (or $1.0 - T > 0.95$), break (Early Ray Termination) [S3, S4, unofficial].
        *   If maximum iterations $N_{max}$ is reached, break [Parent].
    *   **Sampling:**
        *   Calculate world position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [S2, unofficial].
        *   Convert $\mathbf{p}$ to texture coordinates [S3, unofficial].
        *   If 4D volume (`bVolume4D == 1`), sample density from `volumeTexture` and `volumeTexture4DNextFrame`, then interpolate using `interpolationFactor` and `pingpong4D` [S3, unofficial].
        *   If 3D volume, sample density directly [S3, unofficial].
    *   **Density Check:**
        *   If density $\le 0$ (or threshold), decrement a "missed steps" counter (in cloud variants) or continue [S4, unofficial].
        *   If density $> 0.01$ (threshold), proceed with compositing [S3, unofficial].
    *   **Compositing:**
        *   Map density to color/opacity using the transfer function/color map [S3, unofficial].
        *   Calculate alpha: $\alpha = 1.0 - \exp(-\text{extinction} \times dt)$ [S3, unofficial].
        *   Calculate contribution: $C_{contrib} = T \times \text{srgb} \times \alpha$ [S3, unofficial].
        *   Update accumulated color: $C_{acc} += C_{contrib}$ [S3, unofficial].
        *   Update transmittance: $T *= (1.0 - \alpha)$ [S3, unofficial].
        *   Store first hit position and depth in `positionDepthBufferImage` if not already set [S3, unofficial].
    *   **Adaptive Step Update:**
        *   Calculate density difference $dDensity = \text{currentDensity} - \text{prevDensity}$ [S2, unofficial].
        *   Compute new step size: $newStep = GetStep(dDensity, T, \text{currentDensity}, stepScale)$ [S2, unofficial].
        *   Update step: $dt = (dt + newStep) \times 0.5$ [S2, unofficial].
        *   Update previous density: $prevDensity = \text{currentDensity}$ [S2, unofficial].
    *   **Advance Position:**
        *   $\mathbf{p} += \mathbf{d} \times dt$ [S3, unofficial].

4.  **Post-Processing and Output:**
    *   Apply gamma correction: $C_{acc}.rgb = \text{pow}(C_{acc}.rgb, 1.0/2.2)$ [S3, unofficial].
    *   Calculate final alpha: $\alpha_{final} = 1.0 - T$ [S3, unofficial].
    *   Apply illumination scale: $C_{final} = C_{acc} \times illuminationScale$ [S3, unofficial].
    *   **Temporal Accumulation:** If `accumulation` is enabled and camera has not moved, blend $C_{final}$ with the previous frame's color from `outputImage` using $\alpha_{final}$ as weight [S3, unofficial].
    *   **Motion Vectors:** If enabled, calculate motion vector by reprojecting the first hit position from the previous frame's camera state [S3, unofficial].
    *   Store final color and motion vectors in output images [S3, unofficial].

**Pseudocode:**

```python
def adaptive_step_ray_march(ray_origin, ray_dir, t_entry, t_exit, volume_texture, noise_image, config):
    # Initialize state
    t = t_entry + noise_image.r # Use noise offset for jittering
    dt = noise_image.r if noise_image.r > 0 else config.stepSize
    transmittance = 1.0
    accumulated_color = vec3(0.0)
    first_hit = False
    prev_density = 0.0
    
    # Loop until exit or termination
    while t < t_exit:
        # Calculate position
        pos = ray_origin + ray_dir * t
        
        # Sample volume
        uvw = world_to_tex_coords(pos)
        density = sample_volume(uvw, volume_texture)
        
        # Termination checks
        if density <= 0.0:
            # Handle empty space (e.g., increment missed steps in cloud variants)
            pass
        else:
            # Compositing
            # Map density to color/opacity
            color_map_coord = clamp((density - config.scalar_min) / (config.scalar_max - config.scalar_min), 0.0, 1.0)
            s = sample_color_map(color_map_coord) # Returns vec4 (rgb, extinction)
            
            alpha = 1.0 - exp(-s.a * dt)
            contribution = transmittance * s.rgb * alpha
            accumulated_color += contribution
            transmittance *= (1.0 - alpha)
            
            # Store first hit
            if not first_hit and alpha > 0.0:
                first_hit = True
                store_first_hit(pos, t)
            
            # Early ray termination
            if 1.0 - transmittance > 0.95:
                break
        
        # Adaptive step size update
        d_density = density - prev_density
        new_step = get_adaptive_step(d_density, transmittance, density, config.step_scale)
        dt = (dt + new_step) * 0.5
        
        prev_density = density
        
        # Advance
        t += dt
        
        # Max iterations check (G)
        if t > t_exit + 1000.0: # Guard against infinite loop if dt stagnates
            break
            
    # Finalize
    accumulated_color = pow(accumulated_color, vec3(1.0 / 2.2)) # Gamma correction
    final_alpha = 1.0 - transmittance
    final_color = accumulated_color * config.illumination_scale
    
    return final_color, final_alpha
```

## Subtopics

### [Screen-Space Ray Casting with Adaptive Step Size](16661-screen-space-ray-casting-with-adaptive-step-size.md)
A pixel shader technique that renders volumetric scattering by casting rays from the camera through each pixel into a 3D texture, accumulating in-scattered radiance using an adaptive step size based on density changes and transmittance. It distinguishes itself by operating entirely in screen space without requiring explicit geometry intersection beyond depth buffer occlusion.

## Operating characteristics
*   **Time Complexity:** Reduces the number of sampling points compared to linear sampling, improving efficiency in empty regions [S1]. The complexity depends on the density distribution; high-density regions require more steps [S4, unofficial].
*   **Memory Complexity:** Requires additional buffers for noise (`noiseImage`), depth/position (`positionDepthBufferImage`), and motion vectors (`motionVectorImage`) if temporal accumulation and motion vectors are enabled [S3, unofficial].
*   **Performance:** Achieves high efficiency with SSIM values of 0.95 compared to source images [S1]. Real-time performance is supported on GPUs [S3, unofficial].
*   **Strengths:** Balances quality and performance by adapting to local scene properties. Supports 4D volumes and temporal accumulation for noise reduction [S3, unofficial].
*   **Limitations:** Requires careful tuning of thresholds (`ZERO_THRESHOLD`, `EARLY_STOP_THRESHOLD`) and step size parameters. Camera movement requires resetting accumulation buffers to prevent artifacts [S3, unofficial].
*   **When to Use:** Real-time volume rendering where performance is critical, especially for sparse or varying density volumes [S1][S3, unofficial].
*   **When Not to Use:** Offline rendering where maximum quality is required regardless of cost, or when hardware does not support the required texture formats/binding points [S3, unofficial].

## Background
Adaptive step size ray marching originated as a solution to the excessive computational cost of GPU-based 3-D volume rendering [S1]. It was proposed to tackle the dilemma of fixed-step sampling, where a small step ensures quality but reduces efficiency, and a large step ensures efficiency but reduces quality [S1]. The method simulates photography, where far objects are vague and close objects are clear, by using a non-linear sampling function [S1]. It has been implemented in various real-time rendering engines and research projects, including DDVR (Direct Volume Renderer) which supports 4D volumes and temporal accumulation [S3, unofficial].
