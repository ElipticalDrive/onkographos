# Focal Point Origin Slice Positioning

Also called: Focal point based slice grid, Offset slice indexing

## Overview
Focal Point Origin Slice Positioning is a method for determining the spatial coordinates of oblique slice planes in volume rendering by anchoring the slice grid's origin to the user-defined focal point rather than the volume's geometric minimum corner [S1, unofficial]. It solves the problem of misaligned slice indexing, where standard implementations that derive slice positions from the volume corner shift the rendered plane away from the application's requested focal point, causing visual artifacts such as split voxels and horizontal lines [S1, unofficial]. It sets itself apart from sibling methods by decoupling the slice grid topology from the volume's bounding box, ensuring that the slice index $m$ corresponds directly to a displacement from the focal point, thereby preserving the exact plane requested by the application [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** The application-defined focal point $\mathbf{F}$ (a 3D vector), the slice index $m$ (integer), and the L1 voxel thickness $T_v$ along the view normal (computed by the parent method [L1 Voxel Thickness Slice Stepping](17718-l1-voxel-thickness-slice-stepping.md)) [S1, unofficial].
*   **Output:** The 3D position $\mathbf{P}_m$ of the slice plane corresponding to index $m$ [S1, unofficial].

**Data Structures:**
The method requires no additional data structures beyond the input vectors and scalars [S1, unofficial].

**Steps:**
1.  **Retrieve Focal Point:** Obtain the exact focal point $\mathbf{F}$ provided by the application without modifying or snapping it to a grid derived from the volume corner [S1, unofficial].
2.  **Retrieve Step Size:** Obtain the L1 voxel thickness $T_v$ along the view normal [S1, unofficial].
3.  **Calculate Offset:** Compute the scalar displacement from the focal point for slice index $m$ using the formula $\text{offset} = m \times T_v$ [S1, unofficial].
4.  **Compute Position:** Calculate the slice position $\mathbf{P}_m$ by scaling the view normal $\mathbf{n}$ (unit vector) by the offset and adding it to the focal point: $\mathbf{P}_m = \mathbf{F} + (m \times T_v) \times \mathbf{n}$ [S1, unofficial].

**Parameters:**
*   $m$: The slice index. Can be negative, zero, or positive [S1, unofficial].
*   $T_v$: The L1 voxel thickness along the normal [S1, unofficial].
*   $\mathbf{F}$: The focal point. Must be precise [S1, unofficial].
*   $\mathbf{n}$: The view normal direction [G].

**Pitfalls and Edge Cases:**
*   **Misaligned Grid Origin:** If the slice grid origin is fixed at the volume's minimum corner ($\mathbf{min}$), the slice positions are calculated as $\mathbf{min} + m \times T_v$, which shifts the application's requested plane and causes horizontal line artifacts where voxels appear split across neighboring slices [S1, unofficial].
*   **Unsnapped Focal Point:** If the focal point is not aligned with the slice grid, the plane may fall between slice positions. While a snapping function (`snapFocalPointToSlice`) can remove visual artifacts, it violates the requirement to preserve the exact application focal point and should not be used to reset the focal point in production [S1, unofficial].
*   **Oblique Normals:** The method must hold for oblique normals as well as acquisition orientations [S1, unofficial].

**Pseudocode:**
```python
def calculate_slice_position(focal_point, slice_index, voxel_thickness_l1, normal_vector):
    """
    Calculates the 3D position of a slice plane anchored at the focal point.
    
    Args:
        focal_point: list or tuple of 3 floats representing the application's focal point.
        slice_index: int, the slice index m.
        voxel_thickness_l1: float, T_v, the L1 voxel thickness along the normal.
        normal_vector: list or tuple of 3 floats representing the unit view normal n.
        
    Returns:
        list of 3 floats representing the slice plane position P_m.
    """
    # Step 3: Calculate scalar offset from the focal point
    offset_scalar = slice_index * voxel_thickness_l1
    
    # Step 4: Compute displacement vector along the normal
    displacement = [offset_scalar * n for n in normal_vector]
    
    # Step 4: Compute final slice position by adding displacement to focal point
    slice_position = [f + d for f, d in zip(focal_point, displacement)]
    
    return slice_position
```

## Subtopics

### [Snap Focal Point to Slice with Fixed Basis](17922-snap-focal-point-to-slice-with-fixed-basis.md)
A mechanism that defines a deterministic, idempotent mapping from a user-defined focal point to a discrete slice index. It sets itself apart from sibling methods by anchoring all slice positions to a single, fixed basis focal point provided by the application, ensuring that $basis + m \cdot T_v$ yields exact, consistent positions without introducing a scale factor $k \neq 1$. Choose it when the application requires stable, round-trip consistent snapping without shifting the requested plane.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per slice position calculation [S1, unofficial].
*   **Memory Complexity:** $O(1)$, requiring no additional data structures beyond the focal point and step size [S1, unofficial].
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Not given in the sources.
*   **Strengths:** Preserves the exact plane requested by the application, eliminating shifts caused by volume corner alignment, and prevents horizontal line artifacts caused by split voxels [S1, unofficial].
*   **Limitations:** Requires the application to provide a precise focal point; if the focal point is not aligned with the slice grid, visual artifacts may occur unless snapping is applied, which trades accuracy for visual correctness [S1, unofficial].
*   **When to Use:** Use when the application requires precise control over the slice plane location relative to a specific anatomical or data point (focal point) [S1, unofficial].
*   **When Not to Use:** Avoid if the application does not provide a stable focal point or if the rendering pipeline relies on a fixed grid origin for other optimizations [S1, unofficial].

## Background
This method was identified to correct defects in existing volume rendering implementations, where using the L2 spacing or anchoring the grid to the volume corner caused voxels to appear on multiple slices and introduced horizontal line artifacts [S1, unofficial]. The requirement to keep the exact application focal point as the grid origin ensures that each slice index shows exactly one plane of voxels without overlap or gaps [S1, unofficial].
