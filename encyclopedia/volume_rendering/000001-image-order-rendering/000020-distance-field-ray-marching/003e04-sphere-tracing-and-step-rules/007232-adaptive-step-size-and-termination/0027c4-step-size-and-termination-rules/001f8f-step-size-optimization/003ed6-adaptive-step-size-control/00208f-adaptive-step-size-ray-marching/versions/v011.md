# Adaptive Step Size Ray Marching

Also called: Adaptive Step Size Volume Rendering, CSRayMarch, DDVR, DDVR Raymarching Shader, Ray Marching with Adaptive Step Size, Ray Marching with Adaptive Step Size and Temporal Accumulation, Volume Rendering via Ray Marching

## Overview
Adaptive Step Size Ray Marching is a volume rendering technique that optimizes computational cost by varying the sampling interval along the ray based on local density changes and transmittance [S1][S2, S3, S4, unofficial]. It distinguishes itself from fixed-step ray marching by dynamically adjusting the step size to maintain visual fidelity in high-density regions while skipping empty space, and it often incorporates temporal accumulation and denoising to manage noise inherent in sparse sampling [S1][S3, unofficial]. It builds on [Adaptive Step Size Control](9843-adaptive-step-size-control.md).

## How it works
**Inputs and Outputs:**
*   **Inputs:** Camera parameters (position, projection, view matrices), 3D or 4D volume texture(s), transfer function/color mapping texture, noise image (for step size jittering and temporal accumulation), and optional motion vector buffers.
*   **Outputs:** Final color image (RGBA), optional motion vectors, optional depth/position buffer.

**Data Structures:**
*   **Noise Image:** 2D image buffer (`rg32f`). Component `.r` stores the current step size (or 0 to use default). Component `.g` stores the ray offset for jittering. Components `.b`, `.a` are unused (0.0) [S3, unofficial].
*   **Position Depth Buffer:** 2D image buffer (`rgba32f`). Components `.xyz` store the world position of the first hit. Component `.w` stores the depth $t$ along the ray [S3, unofficial].
*   **Motion Vector Image:** 2D image buffer (`rgba8`). Components `.xy` store the motion vector in UV space. Component `.z` is unused (0.0). Component `.w` is unused (1.0) [S3, unofficial].
*   **Volume Data:** 3D texture (`sampler3D`). For 4D volumes, a second texture (`volumeTexture4DNextFrame`) is used [S3, unofficial].
*   **Color Mapping:** 1D texture (`sampler1D`) for density-to-color/opacity transfer [S3, unofficial].

**Parameters:**
*   $\Delta t_{min}$: Absolute minimum step size. Typical value: $10^{-6}$ [S1].
*   $\Delta t_{max}$: Absolute maximum step size. Typical value: $10$ [S1].
*   $GROWTH\_MAX$: Maximum growth factor. Typical value: $5$ [S1].
*   $GROWTH\_MIN$: Minimum shrink factor. Typical value: $0.2$ [S1].
*   $ZERO\_THRESHOLD$: Threshold for density and transmittance to skip empty space or terminate ray. Value not given in the sources.
*   $STEPSIZE\_FINE$: Maximum size of a fine step. Value not given in the sources.
*   $COARSE\_STEPSIZE\_MULTIPLIER$: Multiplier to determine coarse step size from fine step size. Value not given in the sources.
*   $MAX\_NUM\_MISSED\_STEPS$: Threshold for switching from fine to coarse steps after missing cloud density. Value not given in the sources.
*   $EARLY\_STOP\_THRESHOLD$: Transmittance value below which the ray march terminates early. Value not given in the sources.
*   $ABSORPTION$: Absorption coefficient used in radiance accumulation. Value not given in the sources.
*   $stepSize$: Base step size for ray marching, loaded from config. Value not given in the sources.
*   $accumulation$: Boolean flag enabling temporal accumulation. Value not given in the sources.
*   $bVolume4D$: Boolean flag indicating if the volume is time-varying. Value not given in the sources.
*   $pingpong4D$: Boolean flag used to swap between two 4D volume textures. Value not given in the sources.
*   $interpolationFactor$: Float value used to mix between two 4D volume frames. Value not given in the sources.
*   $scalarMinMax$: Vec2 containing min/max scalar values for density normalization. Value not given in the sources.
*   $illuminationScale$: Scalar multiplier applied to final color. Value not given in the sources.
*   $rotationAngles$: Vec2 containing rotation angles for the volume bounding box. Value not given in the sources.

**Algorithm Steps:**

1.  **Ray Initialization:**
    *   Construct rays from the eye position.
    *   Perform ray-box intersection against the volume bounding box ($bbmin, bbmax$) to find entry ($t_{entry}$) and exit ($t_{exit}$) distances [S1][S3, S4, unofficial].
    *   If no intersection, output black color $(0,0,0,1)$ and zero depth, then return [S3, unofficial].
    *   Initialize transmittance $T = 1.0$, accumulated color $C_{acc} = (0,0,0)$, and light energy $L = 0.0$ [S4, unofficial].
    *   Initialize step size $dt$ and offset. Load noise offset from `noiseImage`. If `noiseOffset.r` is 0, use base `stepSize`; otherwise, use `noiseOffset.r` as $dt$ [S3, unofficial].
    *   If camera has moved, reset `positionDepthBufferImage` to zero and `noiseImage.g` to 0 to prevent accumulation artifacts [S3, unofficial].

2.  **Ray Marching Loop:**
    *   Iterate $t$ from $t_{entry} + rayOffset$ to $t_{exit}$ with step $dt$ [S3, unofficial].
    *   **Position Calculation:** Calculate current position $pos = rayOrigin + rayDir \times t$ [S2, S3, unofficial].
    *   **Coordinate Transformation:** Convert world position to texture coordinates. Apply rotation if necessary (using $rotationAngles$) [S3, unofficial].
    *   **Volume Sampling:**
        *   If 3D volume ($bVolume4D == 0$), sample density $d$ from `volumeTexture` [S3, unofficial].
        *   If 4D volume ($bVolume4D == 1$), sample density $d_1$ from `volumeTexture` and $d_2$ from `volumeTexture4DNextFrame`. Mix them using $interpolationFactor$ and $pingpong4D$ flag [S3, unofficial].
    *   **Density Threshold Check:** If density $d \le 0.01$ (or $ZERO\_THRESHOLD$), skip color mapping and compositing, but still advance step [S3, S4, unofficial].
    *   **Color Mapping:**
        *   Calculate normalized density: $normD = clamp((d - scalarMinMax.x) / (scalarMinMax.y - scalarMinMax.x), 0.0, 1.0)$ [S3, unofficial].
        *   Sample `colorMapping` texture at $normD$ to get color $s$ (vec4) [S3, unofficial].
        *   Extract extinction $\epsilon = s.a$ [S3, unofficial].
    *   **Compositing:**
        *   Calculate alpha: $\alpha = 1.0 - \exp(-\epsilon \times dt)$ [S3, unofficial].
        *   Calculate contribution: $contrib = T \times s.rgb \times \alpha$ [S3, unofficial].
        *   Update accumulated color: $C_{acc} += contrib$ [S3, unofficial].
        *   Update transmittance: $T *= (1.0 - \alpha)$ [S3, unofficial].
    *   **Lighting (Optional/Advanced):**
        *   If density is above threshold, calculate light contribution using light direction and spherical harmonics or similar approximation [S2, S4, unofficial].
        *   Update light energy: $L *= phaseVal$ [S4, unofficial].
        *   Final cloud color: $cloudColor = L \times sunColor$ [S4, unofficial].
    *   **Adaptive Step Size Control:**
        *   Compute metric: density difference $dDensity = d - prevDensity$ and transmittance $T$ [S2, unofficial].
        *   Compute new step size: $newStep = GetStep(dDensity, T, d, stepScale)$ [S2, unofficial].
        *   Update step: $dt = (dt + newStep) \times 0.5$ [S2, unofficial].
        *   Clamp $dt$ to $[\Delta t_{min}, \Delta t_{max}]$ and growth limits $[GROWTH\_MIN, GROWTH\_MAX]$ [S1].
        *   Update previous density: $prevDensity = d$ [S2, unofficial].
    *   **Early Termination:**
        *   If $1.0 - T > 0.95$ (or $T < EARLY\_STOP\_THRESHOLD$), break loop [S3, S4, unofficial].
        *   If $t > t_{exit}$, break loop [S3, unofficial].
    *   **First Hit Storage:**
        *   If first hit not recorded and $\alpha > 0.0$, set $firstHit = true$ and store $pos$ and $t$ in `positionDepthBufferImage` [S3, unofficial].
    *   **Advance Position:**
        *   $pos += rayDir \times dt$ [S3, unofficial].
    *   **Noise Offset Update:**
        *   Update noise offset in `noiseImage`. If $accumulation == 1$, increment offset by $(1 / dt \times 10) \times 0.00001$ [S3, unofficial].

3.  **Temporal Accumulation (Optional):**
    *   If $accumulation == 1$ and camera has not moved:
        *   Load previous frame color $C_{prev}$ from `outputImage` [S3, unofficial].
        *   Blend: $C_{final}.rgb = C_{prev}.rgb \times (1.0 - \alpha) + C_{acc}.rgb \times \alpha$ [S3, unofficial].
        *   Blend alpha: $C_{final}.a = C_{prev}.a \times (1.0 - \alpha) + C_{acc}.a \times \alpha$ [S3, unofficial].
    *   Else, $C_{final} = C_{acc}$ [S3, unofficial].

4.  **Post-Processing:**
    *   Apply gamma correction: $C_{final}.rgb = pow(C_{final}.rgb, 1.0/2.2)$ [S3, unofficial].
    *   Apply illumination scale: $C_{final}.rgb *= illuminationScale$ [S3, unofficial].
    *   Store $C_{final}$ to `outputImage` [S3, unofficial].

5.  **Motion Vector Calculation (Optional):**
    *   If $motionVectorCalc == 1$:
        *   Load position from `positionDepthBufferImage`. If zero, store zero motion vector and return [S3, unofficial].
        *   Get depth $t$. Calculate previous ray origin and direction from `previousCam` [S3, unofficial].
        *   Reproject position to previous frame coordinates [S3, unofficial].
        *   Calculate motion vector difference in UV space, map to $[0, 1]$, and store in `motionVectorImage` [S3, unofficial].

**Pseudocode:**

```python
def adaptive_step_size_ray_marching(ray_origin, ray_dir, t_entry, t_exit, volume_texture, color_mapping, noise_image, config):
    """
    ray_origin: vec3
    ray_dir: vec3
    t_entry: float
    t_exit: float
    volume_texture: sampler3D
    color_mapping: sampler1D
    noise_image: image2D (rg32f)
    config: struct containing stepSize, accumulation, bVolume4D, pingpong4D, interpolationFactor, scalarMinMax, illuminationScale, rotationAngles, etc.
    """
    
    # Initialization
    T = 1.0
    C_acc = vec3(0.0)
    L = 0.0
    prev_density = 0.0
    first_hit = False
    
    # Load noise offset
    noise_offset = image_load(noise_image, pixel_coord)
    dt = noise_offset.r if noise_offset.r > 0.0 else config.stepSize
    ray_offset = noise_offset.g
    
    # Handle camera movement
    if config.camera_moved:
        reset_position_depth_buffer(pixel_coord)
        reset_noise_offset_g(pixel_coord)
        
    # Ray-box intersection already done, t_entry and t_exit are known
    
    # Loop
    t = t_entry + ray_offset
    while t < t_exit:
        # Position
        pos = ray_origin + ray_dir * t
        
        # Coordinate transformation
        uvw = local_to_tex_3d_space(pos, config.rotationAngles)
        
        # Volume sampling
        if config.bVolume4D:
            d1 = sample_3d(volume_texture, uvw)
            d2 = sample_3d(volume_texture_4d_next_frame, uvw)
            d = mix(d1, d2, config.interpolationFactor)
        else:
            d = sample_3d(volume_texture, uvw)
            
        # Density threshold
        if d <= 0.01:
            prev_density = d
            t += dt
            continue
            
        # Color mapping
        norm_d = clamp((d - config.scalarMinMax.x) / (config.scalarMinMax.y - config.scalarMinMax.x), 0.0, 1.0)
        s = sample_1d(color_mapping, norm_d)
        extinction = s.a
        
        # Compositing
        alpha = 1.0 - exp(-extinction * dt)
        contrib = T * s.rgb * alpha
        C_acc += contrib
        T *= (1.0 - alpha)
        
        # First hit storage
        if not first_hit and alpha > 0.0:
            first_hit = True
            store_position_depth(pixel_coord, pos, t)
            
        # Early termination
        if 1.0 - T > 0.95:
            break
            
        # Adaptive step size
        d_density = d - prev_density
        new_step = get_step(d_density, T, d, config.stepScale)
        dt = (dt + new_step) * 0.5
        dt = clamp(dt, config.dt_min, config.dt_max)
        dt = clamp(dt, prev_dt * config.growth_min, prev_dt * config.growth_max) # GROWTH_MIN/MAX
        prev_dt = dt
        prev_density = d
        
        # Advance
        t += dt
        
        # Noise offset update
        if config.accumulation:
            update_noise_offset_g(pixel_coord, 1.0 / dt * 10 * 0.00001)
            
    # Temporal accumulation
    if config.accumulation and not config.camera_moved:
        C_prev = image_load(output_image, pixel_coord)
        C_acc = C_prev.rgb * (1.0 - alpha) + C_acc * alpha
        final_alpha = C_prev.a * (1.0 - alpha) + alpha
    else:
        final_alpha = 1.0 - T
        
    # Post-processing
    C_acc = pow(C_acc, vec3(1.0 / 2.2))
    C_acc *= config.illuminationScale
    
    # Store output
    image_store(output_image, pixel_coord, vec4(C_acc, final_alpha))
    
    # Motion vector calculation
    if config.motion_vector_calc:
        pos_depth = image_load(position_depth_buffer, pixel_coord)
        if pos_depth.xyz == vec3(0.0):
            image_store(motion_vector_image, pixel_coord, vec4(0.0, 0.0, 0.0, 1.0))
        else:
            prev_pos = reproject_position(pos_depth.xyz, pos_depth.w, config.previous_cam)
            mv = uv_diff(prev_pos, pos_depth.xyz)
            image_store(motion_vector_image, pixel_coord, vec4(mv, 0.0, 1.0))
```

## Subtopics

### [Screen-Space Ray Casting with Adaptive Step Size](16661-screen-space-ray-casting-with-adaptive-step-size.md)
A screen-space variant that renders volumetric scattering by casting rays from the camera through each pixel into a 3D texture, accumulating in-scattered radiance using an adaptive step size based on density changes and transmittance. It distinguishes itself by operating entirely in screen space without requiring explicit geometry intersection beyond depth buffer occlusion.

## Operating characteristics
*   **Time Complexity:** $O(N \cdot S)$, where $N$ is the number of pixels and $S$ is the average number of samples per ray. Adaptive step size reduces $S$ in empty regions, improving performance compared to fixed-step methods [S1].
*   **Memory Complexity:** $O(N)$ for per-pixel buffers (noise, depth, motion vectors) plus volume texture storage [S3, unofficial].
*   **Measured Performance:** The method generates a result image with a Structural Similarity Index (SSIM) value of 0.95 compared to the source image, indicating high quality [S1].
*   **Strengths:** Reduces computational cost by skipping empty space and using finer steps in dense regions. Supports temporal accumulation for noise reduction. Supports 4D volumes [S1][S3, unofficial].
*   **Limitations:** Requires additional buffers for noise, depth, and motion vectors. Camera movement resets accumulation, potentially causing flicker if not handled carefully. Uniform density fields can cause undefined light direction in light probe approximations [S2, S3, S4, unofficial].
*   **When to use:** Real-time volume rendering where performance is critical and visual quality can be maintained with adaptive sampling. Suitable for GPU-based implementations [S1][S3, unofficial].
*   **When not to use:** When exact analytical integration is required, or when the volume has uniform density where adaptive step size provides no benefit [S2, S4, unofficial].

## Background
Adaptive Step Size Ray Marching was proposed to tackle the excessive computational cost in GPU-based 3-D volume rendering [S1]. It was introduced in a paper by [S1] (2019) which demonstrated an adaptive sampling method using a non-linear sampling function to reduce the number of sampling points while maintaining high image quality (SSIM 0.95) [S1]. The method has been implemented in various projects, including DDVR (Direct Volume Renderer) which supports 3D and 4D volumes with temporal accumulation and denoising [S3, unofficial], and FluidX12 which uses a similar approach for fluid simulation visualization [S2, unofficial]. The technique is inspired by the principle that objects farther away appear less clear, allowing for coarser sampling at greater distances [S1].
