# Error Estimate

Also called: Relative Error Metric, Adaptive Step Error Check

## Overview
Error Estimate calculates a relative error metric to determine whether a ray marching step is acceptable, enabling adaptive step sizing in distance-field ray marching. It differs from [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md), which computes a geometric upper bound on the step length, by evaluating the numerical consistency of the current integration step against the field values, allowing for smaller steps in regions of high variation or numerical instability [S1, unofficial].

## How it works
**Inputs:**
- `k`: A scalar constant representing the error tolerance or step size scaling factor.
- `y`: A vector representing the current field value or solution state (typically 3D for volume rendering).
- `threshold`: A small positive value to prevent division by zero.

**Outputs:**
- `error`: A scalar float representing the normalized error magnitude.

**Data Structures:**
- `y`: `vec3` (or equivalent 3-component vector).
- `k`: `float`.
- `threshold`: `float`.

**Steps:**
1. Compute the absolute value of each component of `y`.
2. Find the maximum absolute component value: $y_{max} = \max(|y_x|, |y_y|, |y_z|)$.
3. Compute the denominator scale: $scale = \max(y_{max}, threshold)$.
4. Compute the relative error vector components: $r_v = k / scale$.
5. Compute the final error metric as the maximum component of $r_v$, ensuring a minimum positive value to avoid zero-division artifacts in subsequent logic.

**Formula:**
$$ r_v = \frac{k}{\max(\max(|y_x|, |y_y|, |y_z|), \text{threshold})} $$
$$ \text{error} = \max(r_v.x, r_v.y, r_v.z) + \text{FLOAT\_MIN} $$

**Parameters:**
- `k`: Not given in the sources.
- `threshold`: Not given in the sources.
- `FLOAT_MIN`: The smallest positive normalized floating-point number (implementation-dependent, e.g., $1.17549435 \times 10^{-38}$ for IEEE 754 single precision).

**Pseudocode:**
```python
def error_estimate(k: float, y: Vec3, threshold: float) -> float:
    # Compute absolute values of components
    abs_y_x = abs(y.x)
    abs_y_y = abs(y.y)
    abs_y_z = abs(y.z)
    
    # Find maximum absolute component
    max_abs_y = max(abs_y_x, abs_y_y, abs_y_z)
    
    # Compute scale with threshold to prevent division by zero
    scale = max(max_abs_y, threshold)
    
    # Compute relative error vector
    r_v_x = k / scale
    r_v_y = k / scale
    r_v_z = k / scale
    
    # Find maximum component of relative error
    max_r_v = max(r_v_x, r_v_y, r_v_z)
    
    # Add floating point minimum to ensure non-zero result
    FLOAT_MIN = 1.17549435e-38  # IEEE 754 single precision min positive normalized
    return max_r_v + FLOAT_MIN
```

**Edge Cases and Pitfalls:**
- If `y` is zero and `threshold` is zero, division by zero occurs. The `threshold` parameter must be non-zero.
- If `k` is zero, the error is `FLOAT_MIN`, which may be interpreted as "acceptable" depending on the caller's logic.
- Precision issues may arise if `max_abs_y` is very small but non-zero, leading to large `r_v` values.

## Subtopics

### Embedded Error Norm Calculation
Embedded Error Norm Calculation computes a norm of the error vector relative to the solution vector, supporting both single and multi-component fields. It is used when a more robust error metric is needed than the simple component-wise maximum. It sets itself apart from the basic Error Estimate by using an RMS-like norm for multi-component vectors, providing a smoother error signal [S2, unofficial].

**Steps:**
1. For a single component, compute $|err| / scale$.
2. For multi-component, compute the RMS-like norm: $\sqrt{\frac{1}{N} \sum_{i=1}^{N} \left(\frac{err_i}{scale_i}\right)^2}$.
3. The scale is derived from `rtol * |y| + atol`.

**Parameters:**
- `rtol`: Relative tolerance. Typical: $10^{-6}$ [S2, unofficial].
- `atol`: Absolute tolerance. Typical: $0$ [S2, unofficial].

**Example:**
Given `err=[1e-6, 2e-6]`, `y=[1, 2]`, `rtol=1e-6`, `atol=0`:
- Scale for component 0: $1e-6 * 1 + 0 = 1e-6$.
- Scale for component 1: $1e-6 * 2 + 0 = 2e-6$.
- Normalized error 0: $1e-6 / 1e-6 = 1$.
- Normalized error 1: $2e-6 / 2e-6 = 1$.
- RMS norm: $\sqrt{\frac{1^2 + 1^2}{2}} = 1$.
(Note: The source cites a norm of ~1.581139, which suggests a different normalization or example values not fully detailed. The formula provided is the standard relative error norm.)

## Operating characteristics
**Time and Memory Complexity:**
- Time: $O(1)$ per step.
- Memory: $O(1)$.

**Measured Performance:**
Not given in the sources.

**Scaling:**
Scales linearly with the number of components in the field.

**Strengths and Limitations:**
- Strengths: Simple to implement, computationally inexpensive, effective for scalar fields.
- Limitations: May be sensitive to the choice of `k` and `threshold`. Does not account for higher-order derivatives or field curvature directly.

**When to Use:**
Use when a simple, fast error metric is sufficient for adaptive stepping in scalar volume rendering.

**When Not to Use:**
Use [Embedded Error Norm Calculation](6981-data-dependent-error-metric-for-scalar-fields.md) when multi-component fields or smoother error signals are required.

## Background
Originated in the context of adaptive ray marching for volume rendering, specifically within the NTSL graphics framework [S1, unofficial]. It is used to control step size based on local field variations.
