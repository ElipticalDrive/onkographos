# Compute Minimal Sample Distance Per Pixel


## Overview
This method computes the minimal sample distance required per pixel for volume rendering by projecting the dataset's cell axes onto the viewport. It accounts for camera and volume transformations to determine the appropriate sampling density [S1, unofficial]. It differs from standard distance-field ray marching step rules by explicitly evaluating the angular span of a voxel's extent from the camera center, rather than relying solely on Euclidean distance or fixed grid spacing [S1, unofficial].

## How it works
**Inputs:**
*   `renderer`: A pointer to the rendering context providing camera position, orientation, and viewport dimensions [S1, unofficial].
*   `volume`: A pointer to the volume object providing the dataset geometry (cell dimensions) and transformation matrix [S1, unofficial].

**Outputs:**
*   `min_sample_distance`: The computed minimal sample distance per pixel [S1, unofficial].
*   `IgnoreSampleDistancePerPixel`: A boolean flag indicating whether the computed distance is invalid due to degenerate geometry [S1, unofficial].

**Data Structures:**
The method operates on the volume's cell dimensions (axis-aligned bounding box extents or voxel sizes) and the camera's projection matrix. No complex intermediate structures are defined in the source; the calculation is performed directly from these parameters [S1, unofficial].

**Steps:**
1.  **Retrieve Geometry:** Extract the dimensions of the dataset cells (voxel sizes) along the X, Y, and Z axes from the `volume` object [S1, unofficial].
2.  **Retrieve Camera State:** Obtain the camera's view direction, up vector, and projection parameters (field of view, aspect ratio) from the `renderer` [S1, unofficial].
3.  **Project Axes:** For each of the three dataset cell axes, project the axis vector onto the viewport plane. This involves transforming the axis vector by the camera's view and projection matrices to determine its angular span relative to the pixel size [S1, unofficial].
4.  **Compute Minimal Distance:** Determine the minimal sample distance based on the projected sizes. The distance is derived such that the voxel's projected size on the screen does not undersample the pixel. The exact formula is not provided in the source, but it relies on the relationship between the voxel's physical size, the camera distance, and the projection geometry [S1, unofficial].
5.  **Check for Degeneracy:** If any dataset axis is degenerate (e.g., aligned with the view direction, resulting in zero projected width or infinite aspect ratio), set `IgnoreSampleDistancePerPixel` to `true` and return a default or invalid distance [S1, unofficial].
6.  **Return Result:** Return the computed `min_sample_distance` and the `IgnoreSampleDistancePerPixel` flag [S1, unofficial].

## Operating characteristics
*   **Complexity:** The method performs a constant number of vector and matrix operations per pixel (or per volume, depending on implementation granularity). It is $O(1)$ with respect to the number of voxels, as it only considers the dataset's global cell dimensions and camera state.
*   **Performance:** Very fast, as it avoids per-voxel or per-ray calculations. It is typically computed once per frame or when camera/volume transforms change.
*   **Strengths:** Provides a geometrically accurate sampling distance based on the actual projected size of voxels, preventing aliasing and ensuring consistent visual quality across different camera positions and orientations.
*   **Limitations:** Relies on the accuracy of the camera and volume transformation matrices. If the volume is non-axis-aligned or has complex transformations, the projection logic must be robust. The source does not specify how non-axis-aligned volumes are handled beyond the general projection step.
