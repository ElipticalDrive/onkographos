# Safe Raymarching Step Size

Also called: Conservative stepping, Distance-Aided Ray Marching, Grid Step Size, Ray Marching with SDF-guided Step Size, TensorBase Step Size Calculation

## Overview
Safe Raymarching Step Size is a technique for traversing a Signed Distance Field (SDF) where the step length at each iteration is determined by the local distance to the nearest surface, ensuring the ray never overshoots geometry [S3, unofficial]. It solves the problem of missing thin structures or artifacts caused by fixed-step ray marching by adapting the step size to the local geometry [S1, unofficial]. It differs from its siblings by explicitly using the SDF value as a lower bound on the distance to any surface, whereas [Compute Minimal Sample Distance Per Pixel](2684-compute-minimal-sample-distance-per-pixel.md) focuses on pixel-level sampling density, and [Gap-Limited Ray Marching](4412-gap-limited-ray-marching.md) handles specific occlusion gaps.

## How it works
**Inputs:**
*   Ray origin $\mathbf{o}$ and direction $\mathbf{d}$ (normalized).
*   SDF function $f(\mathbf{p})$ returning signed distance to the closest surface.
*   Termination threshold $\tau$ (e.g., $5 \times 10^{-5}$) [S2, unofficial].
*   Maximum step count $N_{max}$ or maximum distance $d_{max}$ [S2, unofficial].
*   Safety ratio $\alpha \in (0, 1]$ (often $1.0$ for strict safety, or slightly less to mitigate distortion artifacts) [S1, unofficial].

**Outputs:**
*   List of sampled points $\{\mathbf{p}_0, \mathbf{p}_1, \dots, \mathbf{p}_k\}$.
*   List of SDF values $\{s_0, s_1, \dots, s_k\}$.
*   Accumulated depth $z_{depth}$.
*   Validity mask indicating if a surface was hit within bounds.

**Data Structures:**
*   `points_list`: Array of shape $(N_{max}, 3)$ storing 3D coordinates.
*   `sdf_list`: Array of shape $(N_{max})$ storing SDF values.
*   `marching_zdepth_list`: Array of shape $(N_{max})$ storing accumulated distance along ray.
*   `valid_mask`: Boolean flag or array indicating successful convergence.

**Parameters:**
*   $\tau$: Threshold for surface intersection. Typical value: $5 \times 10^{-5}$ [S2, unofficial].
*   $\alpha$: Ray marching ratio. Typical value: $1.0$ (or slightly less, e.g., $0.9$, to handle distorted fields) [S1, unofficial][S2, unofficial].
*   $clamp\_dist$: Clamping range for SDF values to prevent instability. Typical value: $0.1$ [S2, unofficial].

**Algorithm:**
1.  Initialize current position $\mathbf{p} = \mathbf{o}$.
2.  Initialize accumulated depth $z = 0$.
3.  Initialize iteration counter $i = 0$.
4.  Loop while $i < N_{max}$ and $z < d_{max}$:
    a.  Evaluate distance: $s = f(\mathbf{p})$.
    b.  Clamp $s$: $s_{clamped} = \max(-clamp\_dist, \min(s, clamp\_dist))$ [S2, unofficial].
    c.  Calculate step size: $\Delta z = \alpha \cdot s_{clamped}$.
    d.  **Pitfall:** If $s_{clamped} \le 0$, the ray is inside or on the surface. Set $\Delta z$ to a small positive epsilon or terminate immediately depending on implementation requirements [G]. Standard sphere tracing assumes $s > 0$ for stepping.
    e.  Update position: $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{d} \cdot \Delta z$.
    f.  Update depth: $z \leftarrow z + \Delta z$.
    g.  Store $\mathbf{p}, s, z$ in lists.
    h.  Check termination: If $s \le \tau$, mark as hit and break.
    i.  Increment $i$.

**Pseudocode:**
```python
def safe_raymarch(o, d, sdf_func, threshold=5e-5, max_steps=100, max_dist=100.0, alpha=1.0, clamp_dist=0.1):
    """
    Performs safe raymarching using SDF-guided step sizes.
    
    Args:
        o: Ray origin (vec3)
        d: Ray direction (vec3, normalized)
        sdf_func: Function returning signed distance for a point (vec3 -> float)
        threshold: SDF value below which a surface is considered hit
        max_steps: Maximum number of iterations
        max_dist: Maximum distance along the ray
        alpha: Safety ratio (1.0 is strictly safe, <1.0 mitigates distortion artifacts)
        clamp_dist: Max absolute value for SDF clamping
        
    Returns:
        points: List of sampled points
        sdfs: List of sampled SDF values
        depths: List of accumulated depths
        hit: Boolean indicating if surface was hit
    """
    points = []
    sdfs = []
    depths = []
    p = o
    z = 0.0
    hit = False
    
    for i in range(max_steps):
        if z >= max_dist:
            break
            
        # Evaluate SDF
        s = sdf_func(p)
        
        # Clamp SDF to prevent extreme steps
        s_clamped = max(-clamp_dist, min(s, clamp_dist))
        
        # Calculate step size
        # Note: If s_clamped <= 0, we are inside the object. 
        # Standard sphere tracing steps away or stops. 
        # Here we assume we step by the clamped distance.
        step = alpha * s_clamped
        
        # Guard against zero or negative steps if inside geometry
        if step <= 0:
            step = 1e-6 # [G] Small epsilon to prevent infinite loop if inside
            
        # Update position and depth
        p = p + d * step
        z += step
        
        # Store samples
        points.append(p)
        sdfs.append(s)
        depths.append(z)
        
        # Check for intersection
        if s <= threshold:
            hit = True
            break
            
    return points, sdfs, depths, hit
```

**Edge Cases and Pitfalls:**
*   **Distortion Artifacts:** Domain repetition or boolean operations can distort the SDF, making the estimated distance larger than the actual distance to the surface. This causes the ray to skip over geometry [S1, unofficial]. Mitigation: Use $\alpha < 1.0$ (step shorter than the distance field returns) [S1, unofficial].
*   **Immediate Hit:** If the first SDF query is already below the threshold, the ray starts inside or on the surface. The algorithm must handle this to prevent incorrect rendering logic (e.g., by checking `valid_mask_first_query`) [S2, unofficial].
*   **Boundary Exceedance:** Rays must not exceed the maximum bound ($maxbound\_zdepth$). This is checked against the final accumulated depth [S2, unofficial].
*   **Precision:** Floating-point errors in SDF evaluation can lead to jittering near surfaces. Using a small epsilon for termination or clamping helps [G].

## Subtopics

### [Distance Accuracy vs Performance Trade-off](1546-distance-accuracy-vs-performance-trade-off.md)
Analyzes the inverse relationship between SDF evaluation accuracy and computational cost. Underestimating distance forces smaller steps, increasing iterations. An exact SDF may outperform a fast, inaccurate bound if the inaccuracy causes disproportionate step count increases.

### [Adaptive Lipschitz Constant (ALC)](1883-adaptive-lipschitz-constant-alc.md)
Uses a nested BVH to compute tighter, adaptive Lipschitz constants for step size calculation, solving the problem of overly conservative steps in large scenes with high global Lipschitz constants.

### [Gradient-based Sphere Tracing with Lipschitz Constraints](1936-gradient-based-sphere-tracing-with-lipschitz-constraints.md)
Uses local SDF gradients to compute larger, safer step sizes, particularly near silhouettes. Combines first and second Lipschitz constraints to account for curvature, leveraging gradient magnitude rather than just BVHs.

### [Lipschitz Step Size Ray Marching](3729-lipschitz-step-size-ray-marching.md)
A robust algorithm using a pre-computed global Lipschitz constant $\lambda$ to guarantee no overshooting. Simple and stable but potentially less efficient for complex scenes with varying feature scales compared to adaptive methods.

## Operating characteristics
*   **Time Complexity:** $O(N)$, where $N$ is the number of iterations until termination. $N$ depends on the scene complexity and the accuracy of the SDF. Inaccurate SDFs or distorted fields can significantly increase $N$ due to smaller effective steps [S1, unofficial].
*   **Memory Complexity:** $O(N)$ to store sampled points and SDF values if history is needed for rendering (e.g., volume integration). For simple intersection tests, $O(1)$ auxiliary memory is sufficient.
*   **Performance:** Generally efficient for smooth, well-behaved SDFs. Performance degrades with high-frequency details or distorted fields unless mitigated by $\alpha < 1.0$ or adaptive methods [S1, unofficial]. Parallel implementations (e.g., processing all rays in a pixel grid simultaneously) can improve throughput on GPUs [S2, unofficial].
*   **Strengths:** Guarantees no overshooting (with $\alpha \le 1.0$), simple to implement, works with any SDF.
*   **Limitations:** Can be slow for complex scenes with small features if the SDF is not tight. Distorted SDFs require tuning of $\alpha$.
*   **When to use:** When rendering implicit surfaces defined by SDFs, especially when avoiding missed geometry is critical.
*   **When not to use:** When performance is paramount and the scene has very small features that require many steps, consider adaptive methods or hierarchical structures.

## Background
Safe Raymarching Step Size, also known as Distance-Aided Ray Marching or Sphere Tracing, originated in the demoscene and computer graphics research for rendering implicit surfaces [S3, unofficial]. The core insight is that the SDF value provides a safe lower bound on the distance to the nearest surface, allowing for variable step sizes that accelerate convergence compared to fixed-step marching [S3, unofficial]. It has been widely adopted in real-time rendering, neural rendering (e.g., NeRF variants), and 3D reconstruction [S2, unofficial][S4, unofficial].
