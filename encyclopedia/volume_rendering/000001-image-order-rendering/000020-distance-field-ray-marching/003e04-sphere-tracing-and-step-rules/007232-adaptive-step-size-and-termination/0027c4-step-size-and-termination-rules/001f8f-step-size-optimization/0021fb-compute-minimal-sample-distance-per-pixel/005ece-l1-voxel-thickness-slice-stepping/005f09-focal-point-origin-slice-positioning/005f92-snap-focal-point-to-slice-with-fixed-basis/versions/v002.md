# Snap Focal Point to Slice with Fixed Basis

Also called: planarSliceBasis, snapFocalPointToSlice

## Overview
This method snaps a user-defined focal point to a discrete slice grid in volume rendering by anchoring all slice positions to a single, fixed basis focal point provided by the application [S1, unofficial]. It solves the problem of non-idempotent snaps, non-returning round trips, and multiple snap positions for points within one slice that occur when slice grids are computed relative to the current focal point or volume bounds with floating-point rounding errors [S1, unofficial]. Unlike the previous implementation which computed a scale factor $k \neq 1$ via normalized coordinates, this method ensures exact consistency by using the linear rule $basis + m \cdot T_v$ for both snapping and index mapping [S1, unofficial].

## How it works
**Inputs:**
- `basis`: The fixed focal point (3D vector) provided by the application [S1, unofficial].
- `m`: The integer slice index [S1, unofficial].
- `T_v`: The voxel thickness (step size) along the viewing normal [S1, unofficial].

**Outputs:**
- `position`: The 3D coordinate of the slice plane origin [S1, unofficial].

**Data Structures:**
- Not given in the sources.

**Steps:**
1. The application provides a fixed `basis` focal point, which serves as the single reference origin for the slice grid and is neither the volume minimum corner nor the current dynamic focal point [S1, unofficial].
2. Calculate the slice position using the linear formula:
   $$ position = basis + m \cdot T_v $$
   where:
   - $basis$ is the fixed basis focal point vector [S1, unofficial].
   - $m$ is the integer slice index [S1, unofficial].
   - $T_v$ is the voxel thickness (scalar) [S1, unofficial].
3. The `snapFocalPointToSlice` function must use this single basis and rule to determine the nearest slice index $m$ for a given input point [S1, unofficial].
4. The `planarSliceBasis` function must use the same basis and rule to map indices to absolute positions, ensuring both conventions agree [S1, unofficial].

**Pitfalls:**
- **Scale Factor Error:** The previous implementation computed $f = (current - min) / (max - min) \cdot steps$, where $steps = round((max - min) / spacing)$, introducing a scale factor $k = steps \cdot spacing / (max - min) \neq 1$ [S1, unofficial].
- **Non-Idempotency:** Without a fixed basis, snapping is not idempotent; a second call moves the focal point again, and the sequence converges without stopping at the first value [S1, unofficial].
- **Round Trip Error:** A round trip (+1 step then -1 step) does not return to the start [S1, unofficial].
- **Ambiguity:** Without a fixed basis, multiple snap positions can exist for points within one slice [S1, unofficial].

**Pseudocode:**
```python
def calculate_slice_position(basis, m, T_v):
    """
    Calculate the absolute position of a slice given a fixed basis.
    
    Args:
        basis (Vector3): The fixed focal point provided by the application.
        m (int): The slice index.
        T_v (float): The voxel thickness (step size).
        
    Returns:
        Vector3: The position of the slice plane.
    """
    return basis + m * T_v

def snap_to_slice(input_point, basis, T_v, normal):
    """
    Snap an input point to the nearest slice index using the fixed basis.
    
    Args:
        input_point (Vector3): The current focal point to snap.
        basis (Vector3): The fixed basis focal point.
        T_v (float): The voxel thickness.
        normal (Vector3): The viewing normal (unit vector).
        
    Returns:
        int: The snapped slice index m.
    """
    # Project the vector from basis to input_point onto the normal
    diff = input_point - basis
    distance = dot(diff, normal)
    
    # Calculate the slice index
    # Rounding mode not specified in sources; standard nearest-integer rounding used [G].
    m = round(distance / T_v)
    
    return m
```

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Accuracy:** Eliminates the scale factor error ($k \neq 1$) and round-trip errors [S1, unofficial]. For a 41x41x41 voxel volume (1mm voxels) at 30 degrees oblique, the previous scale factor was $k = 1.00656985$ with a round-trip error of $7.4 \times 10^{-3}$ mm [S1, unofficial]. At 45 degrees oblique, $k = 1.00762715$ and the round-trip error was $8.6 \times 10^{-3}$ mm [S1, unofficial]. Two starts 0.4 mm apart snap to positions differing by $3.1 \times 10^{-3}$ mm [S1, unofficial].
- **Strengths:** Idempotent snapping, exact round trips, and a single snap position per slice [S1, unofficial].
- **Limitations:** Requires the application to provide and maintain a fixed `basis` focal point [S1, unofficial].

## Background
This method addresses implementation requirements identified in the cornerstone3D project [S1, unofficial]. The previous implementation of `snapFocalPointToSlice` and `planarSliceBasis` used inconsistent conventions, with the former building a grid relative to the current focal point and the latter mapping indices to an absolute grid anchored at the volume corner ($min + index \cdot spacing$) [S1, unofficial]. These inconsistencies led to visual artifacts and navigation issues in oblique volume rendering [S1, unofficial]. The fix anchors slice positions to a user-defined basis to resolve non-idempotent snaps and round-trip errors [S1, unofficial].
