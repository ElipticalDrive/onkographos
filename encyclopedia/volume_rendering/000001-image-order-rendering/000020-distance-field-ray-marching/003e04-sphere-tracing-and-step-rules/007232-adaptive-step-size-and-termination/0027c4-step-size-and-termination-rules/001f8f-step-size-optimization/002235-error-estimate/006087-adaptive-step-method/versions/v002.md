# Adaptive Step Method

Also called: Adaptive RK2

## Overview
The Adaptive Step Method is a numerical integration technique for volume rendering that dynamically adjusts the ray marching step size to maintain a specified error tolerance [S1]. It solves the problem of balancing rendering speed and accuracy by estimating the local truncation error at each step and modifying the step length accordingly [S1]. Unlike fixed-step methods, it uses a user-defined tolerance parameter rather than a fixed step count, making it more user-friendly [S1]. It distinguishes itself from its sibling [Data-Dependent Error Metric for Scalar Fields](6981-data-dependent-error-metric-for-scalar-fields.md) by using order-difference estimation (Euler vs. RK2) rather than field-specific gradients, and from [Stepsize Annealing](7542-stepsize-annealing.md) by its explicit error-based feedback loop [S1].

## How it works
**Inputs:**
*   Current position $P_n$ and direction $D$ [S1].
*   Radiance transfer function parameters (scattering coefficient $\sigma_s$, emission $L_e$, extinction $\sigma_t$) [S1].
*   Target relative error tolerance $E$ [S1].
*   Current step size $dt$ [S1].

**Outputs:**
*   Next position $P_{n+1}$ [S1].
*   Accumulated radiance contribution [S1].
*   Updated step size $dt_{new}$ [S1].

**Data Structures:**
*   Position $P$: 3D vector $(x, y, z)$ [G].
*   Step size $dt$: Scalar float [G].
*   Error tolerance $E$: Scalar float [S1].

**Method Steps:**
1.  **Euler Estimate:** Compute the next position using Euler’s method (first-order) with the current step size $dt$ [S1].
    $$ P_{Euler} = P_n + dt \cdot V(P_n) $$
    Where $V(P)$ is the derivative of the state (e.g., radiance or position in phase space) at $P$ [S1]. In standard volume rendering, this often refers to the radiance integration step [S1].
2.  **RK2 Estimate:** Compute the next position using a second-order Runge-Kutta method (midpoint) with the same step size $dt$ [S1].
    $$ k_1 = V(P_n) $$
    $$ k_2 = V(P_n + \frac{dt}{2} k_1) $$
    $$ P_{RK2} = P_n + dt \cdot k_2 $$
3.  **Error Estimation:** Calculate the relative error between the two estimates [S1].
    $$ error = \frac{|P_{RK2} - P_{Euler}|}{|P_{RK2}| + \epsilon} $$
    Where $\epsilon$ is a small constant to prevent division by zero [G].
4.  **Step Size Adjustment:** Compare the estimated error against the tolerance $E$ and adjust $dt$ [S1].
    *   If $error > E$: Reduce step size.
        $$ dt_{new} = dt \cdot \left( \frac{E}{error} \right)^{1/2} $$
    *   If $error \le E$: Increase step size.
        $$ dt_{new} = dt \cdot \left( \frac{error}{E} \right)^{1/3} $$
    The exponents $1/2$ and $1/3$ are standard stability factors for order-difference adaptation [G].
5.  **Integration:** Advance the ray using the RK2 estimate $P_{RK2}$ as $P_{n+1}$ and accumulate radiance [G].

**Pseudocode:**
```python
def adaptive_step(P_n, dt, tolerance, velocity_func):
    # 1. Euler step (1st order)
    V_n = velocity_func(P_n)
    P_euler = P_n + dt * V_n

    # 2. RK2 step (2nd order) - Midpoint method
    V_mid = velocity_func(P_n + 0.5 * dt * V_n)
    P_rk2 = P_n + dt * V_mid

    # 3. Error estimation
    # Use relative error to handle scale
    denom = max(norm(P_rk2), 1e-8)
    error = norm(P_rk2 - P_euler) / denom

    # 4. Adjust step size
    if error > tolerance:
        dt = dt * (tolerance / error) ** 0.5
    else:
        dt = dt * (error / tolerance) ** (1.0/3.0)

    # 5. Finalize step using the more accurate method (RK2)
    P_next = P_rk2
    return P_next, dt
```

**Edge Cases and Pitfalls:**
*   **High-Frequency Illumination:** In scenes with sharp light beams or high-frequency illumination, the method may increase the step size in dark, low-error regions, causing the ray to skip over the high-frequency light beams entirely [S1].
*   **Maximum Step Size:** To mitigate the skipping of high-frequency features, a maximum step size constraint is required [S1].
*   **Precision:** Floating-point precision errors in the error estimation can lead to oscillating step sizes [G].

## Subtopics

### [Adaptive Time Integration (Steady/Particle)](21524-adaptive-time-integration-steady-particle.md)
A variant used for particle tracing or steady flow integration that keeps integration error constant by adjusting the time step $dt$. It is described in the context of unsteady flow volumes and references Press et al. [12] for its derivation. It uses 11 function evaluations per step and applies a conservative factor of 0.9 for $dt$ changes. It uses specific exponents for shrinking and growing $dt$: SHRINK is $1/2$ for second-order RK and $1/4$ for fourth-order RK; GROW is $1/3$ for second-order RK and $1/5$ for fourth-order RK. The algorithm evaluates velocity at the current position, performs a half-step RK, a full-step RK, evaluates velocity at the half-step position, and then performs a final correction step to estimate error.

## Operating characteristics
*   **Time Complexity:** Variable per step due to multiple function evaluations (Euler + RK2 = 2-3 evaluations per step vs. 1 for Euler) [S1].
*   **Memory Complexity:** Not given in the sources.
*   **Performance:** Provides better accuracy than Euler for the same render time at low tolerances [S1]. For lower tolerances, the effect of step size is ignored, as the method adapts its step size to the desired overall error [S1].
*   **Strengths:** User-friendly via tolerance parameter; adapts to scene complexity [S1].
*   **Limitations:** Can fail on high-frequency illumination without a maximum step size constraint; artifacts may persist even with restrictive tolerances if the scene has sharp discontinuities (e.g., shadows) [S1].
*   **Hardware:** Tested on Intel Core i5 at 2.4GHz with 4GB RAM, parallelized using threads [S1].
*   **Scaling:** Not given in the sources.

## Background
The method was tested and described in the context of differential ray marching for participating media [S1]. It was evaluated against fixed-step methods (Euler, RK2) in scenes including green fog and car headlights with sharp shadows [S1].
