# Gap-Limited Ray Marching

Also called: Distance-Proportional Step with Gap Bound, Terrain Ray Marching with Gap Limiting

## Overview
Gap-Limited Ray Marching is a step-size optimization technique for heightfield terrain rendering that prevents ray stalling and surface overshooting on non-distance fields [S1, unofficial]. Unlike standard sphere tracing which relies on a global Lipschitz constant, this method bounds the step size by half the vertical gap to the surface, ensuring the ray never penetrates ridgelines while allowing larger steps in open space [S1, unofficial]. It builds on [Step Size Optimization](2054-step-size-optimization.md) by combining distance-proportional growth with a local geometric constraint [S1, unofficial].

## How it works
**Inputs:** Ray origin $\mathbf{o} = (o_x, o_y, o_z)$, normalized ray direction $\mathbf{d} = (d_x, d_y, d_z)$, heightfield lookup function `heightAtExtended(field, x, z)`, maximum distance $t_{max}$, maximum iterations $N_{max}$, step scale factor $s$, minimum step size $\delta_{min}$, and refinement iterations $N_{refine}$ [S1, unofficial].

**Outputs:** Intersection distance $t_{hit}$ or miss indicator [S1, unofficial].

**Data Structures:**
*   `heightAtExtended(field, x, z)`: Returns the height $H(x, z)$ at the given world coordinates. For bilinear interpolation, this involves sampling the four surrounding grid points and interpolating [S1, unofficial].

**Pseudocode:**
```python
def gap_limited_ray_march(ox, oy, oz, dx, dy, dz, field, heightAtExtended, t_max, max_steps, step_scale, min_step, refine_steps):
    t = 0.0
    t_prev = 0.0
    for i in range(max_steps):
        if t >= t_max:
            return -1  # miss
        # Calculate current position and vertical gap
        x = ox + dx * t
        z = oz + dz * t
        y_ray = oy + dy * t
        h = y_ray - heightAtExtended(field, x, z)
        # Surface hit check
        if h <= 0:
            lo, hi = t_prev, t
            for _ in range(refine_steps):
                mid = (lo + hi) * 0.5
                x_mid = ox + dx * mid
                z_mid = oz + dz * mid
                y_mid = oy + dy * mid
                h_mid = y_mid - heightAtExtended(field, x_mid, z_mid)
                if h_mid <= 0:
                    hi = mid
                else:
                    lo = mid
            return hi  # intersection distance
        # Step size calculation
        distance_step = t * step_scale
        gap_step = h * 0.5
        step = min(distance_step, gap_step)
        if step < min_step:
            step = min_step
        # Advance ray
        t_prev = t
        t += step
    return -1  # miss
```

**Parameters:**
*   $s$ (stepScale): Multiplier for the distance-proportional step term. Determines how fast the distance-proportional term grows. No typical value specified in sources [S1, unofficial].
*   $\delta_{min}$ (minStep): Minimum step size to prevent infinite loops on flat surfaces or precision issues [S1, unofficial].
*   $N_{max}$ (maxSteps): Maximum number of march iterations [S1, unofficial].
*   $N_{refine}$ (refineSteps): Number of bisection iterations to find the precise surface intersection after crossing [S1, unofficial].

**Pitfalls:**
*   Without the gap limiting term ($h \cdot 0.5$), the ray can step through the surface on ridgelines, causing holes [S1, unofficial].
*   The gap step ensures the ray never steps more than half the vertical clearance, preventing overshoot [S1, unofficial].
*   Precision issues on flat surfaces may require $\delta_{min}$ to avoid stalling [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** Not given in the sources.
*   **Memory Complexity:** Not given in the sources.
*   **Strengths:** Prevents surface penetration on complex terrain (ridgelines); efficient for large open areas due to distance-proportional steps; simple to implement [S1, unofficial].
*   **Limitations:** Specific to heightfields; requires a height function [S1, unofficial].
*   **When to use:** Terrain rendering where heightfields are available and ridgeline accuracy is critical [S1, unofficial].
*   **When not to use:** Not given in the sources.

## Background
Originating from the `theme1` renderer by mingderwang, this method was developed to efficiently render heightfield-based terrain without relying on distance fields [S1, unofficial]. It addresses the specific challenge of ray marching over terrain where the surface is not a distance field, preventing the common issue of rays stepping over ridgelines [S1, unofficial].
