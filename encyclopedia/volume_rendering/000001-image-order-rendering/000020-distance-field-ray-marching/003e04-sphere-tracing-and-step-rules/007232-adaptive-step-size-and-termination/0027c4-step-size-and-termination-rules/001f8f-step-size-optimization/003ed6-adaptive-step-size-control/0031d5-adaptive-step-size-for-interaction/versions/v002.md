# Adaptive Step Size for Interaction

Also called: Interactive Step Size Increase, Variable Step Size, Volume Step Rate Adjustment, Volume shadow step rate

## Overview
Adaptive Step Size for Interaction is a performance optimization technique that temporarily increases the ray marching step size during user interaction (e.g., viewpoint changes) to maintain frame rate, followed by a high-quality render with standard parameters [S1, unofficial]. It differs from static step size reduction by being context-aware, triggering only during active manipulation, and from variance-based adaptation by relying on interaction state rather than local data density [S1, S3, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Current ray position $t$, interaction state flag $I$ (boolean, true during manipulation), base step size $\Delta t_{base}$, interaction step size multiplier $M_{int} > 1$.
*   **Output:** Next ray position $t_{new}$, updated step size $\Delta t_{new}$.

**Data Structures:**
No specific complex data structures are required beyond the standard ray marching state. The method relies on a simple boolean flag and scalar multipliers.

**Steps:**
1.  **Check Interaction State:** Determine if the user is currently interacting with the viewport (e.g., rotating, panning, zooming). Let this be $I$.
2.  **Select Step Size:**
    *   If $I$ is true, set $\Delta t_{new} = \Delta t_{base} \times M_{int}$.
    *   If $I$ is false, set $\Delta t_{new} = \Delta t_{base}$.
3.  **Clamp:** Ensure $\Delta t_{new}$ is within global bounds $[\Delta t_{min}, \Delta t_{max}]$ [S1, unofficial].
4.  **Advance Ray:** $t_{new} = t_{old} + \Delta t_{new}$.
5.  **Final Render:** Upon completion of interaction, reset $M_{int}$ to 1 (or a value close to 1) for the final high-quality image generation [S1, unofficial].

**Parameters:**
*   $\Delta t_{base}$: The standard step size used for final rendering. Typical value: Not given in the sources.
*   $M_{int}$: The multiplier applied during interaction. Typical value: Not given in the sources, but must be $>1$.
*   $\Delta t_{min}, \Delta t_{max}$: Global bounds. Typical values: $10^{-6}, 10$ [S1, unofficial].

**Pitfalls:**
*   **Feature Skipping:** If the step size becomes too large, significant features (e.g., "big mountains" in heightmap contexts) may be completely skipped, leading to visual artifacts [S3, unofficial].
*   **Transparency/Shadow Loss:** While increasing step size speeds up rendering, it can cause volumes to appear more transparent and lose shadow detail if not managed correctly, especially when compared to increasing pixel samples [S2].
*   **Accuracy Trade-off:** Reducing the step rate (increasing step size) speeds up rendering but reproduces volumes less accurately [S2].

**Pseudocode:**
```python
def ray_march_with_interaction(ray_origin, ray_direction, volume_data, is_interacting, base_step_size, interaction_multiplier):
    """
    Performs ray marching with adaptive step size based on interaction state.
    
    Args:
        ray_origin: vec3
        ray_direction: vec3
        volume_data: Volume structure providing sample() method
        is_interacting: bool, True if user is currently manipulating the view
        base_step_size: float, standard step size for final render
        interaction_multiplier: float, factor > 1 to increase step size during interaction
        
    Returns:
        color: vec3, the accumulated color
    """
    t = 0.0
    accumulated_color = vec3(0.0)
    accumulated_opacity = 0.0
    
    # Global bounds for step size
    dt_min = 1e-6
    dt_max = 10.0
    
    # Determine current step size based on interaction state
    if is_interacting:
        dt = base_step_size * interaction_multiplier
    else:
        dt = base_step_size
        
    # Clamp step size
    dt = max(dt_min, min(dt_max, dt))
    
    while t < 1.0 and accumulated_opacity < 0.99: # 1.0 is max distance, 0.99 is opacity threshold
        # Sample volume at current position
        density = volume_data.sample(ray_origin + ray_direction * t)
        
        # Standard front-to-back compositing
        color = volume_data.get_color(density)
        alpha = volume_data.get_alpha(density)
        
        # Contribution
        contribution = alpha * (1.0 - accumulated_opacity)
        accumulated_color += color * contribution
        accumulated_opacity += contribution
        
        # Advance ray
        t += dt
        
    return accumulated_color
```

## Subtopics

### Adaptive Step Size Ray Marching
Uses local data metrics (like density gradients) to adjust step size continuously, rather than relying on interaction state. Choose when fine detail preservation is needed regardless of user input. [Link](2312-adaptive-step-size-ray-marching.md)

### Dynamic Sampling Step Adjustment
Adjusts step size based on dynamic scene changes or temporal coherence. Choose for animated scenes where interaction state is not the primary driver of performance needs. [Link](2442-dynamic-sampling-step-adjustment.md)

### Variance-based Step Size Adaptation
Uses statistical variance of the volume data to determine step size. Choose when the volume has high-frequency noise or complex structures that require denser sampling in specific regions. [Link](13161-variance-based-step-size-adaptation.md)

## Operating characteristics
*   **Time Complexity:** Reduces the number of samples per ray by a factor of $M_{int}$ during interaction, leading to a proportional decrease in rendering time.
*   **Memory Complexity:** No additional memory overhead compared to standard ray marching.
*   **Measured Performance:** Not given in the sources.
*   **Scaling:** Scales linearly with the interaction multiplier. Higher multipliers yield faster interaction but lower quality.
*   **Strengths:** Provides fluent interaction without requiring complex data structures or pre-computation. Simple to implement.
*   **Limitations:** Can introduce artifacts (skipped features, transparency loss) if the multiplier is too high. Not suitable for final quality rendering.
*   **When to Use:** During real-time viewport manipulation (rotation, zoom, pan).
*   **When Not to Use:** For final image generation or when high fidelity is required during interaction.

## Background
The method was described by Hadwiger and Rezk Salama in 2004 [S1, unofficial]. It is a common trick in volume rendering to balance interactivity and quality, where increasing step size or reducing slices reduces computational effort at the cost of potential artifacts [S1, unofficial]. It is often used in conjunction with early ray termination and empty space skipping to further optimize performance [S1, unofficial].
