# Adaptive Step Size for Interaction

Also called: Interactive Step Size Increase, Variable Step Size, Volume Step Rate Adjustment, Volume shadow step rate

## Overview
Adaptive Step Size for Interaction is a performance optimization technique that dynamically increases the ray marching step size during user interaction (e.g., viewpoint changes) to maintain frame rate, then restores smaller step sizes for high-quality final image generation [S1, unofficial]. It differs from continuous adaptive methods like [Adaptive Step Size Ray Marching](2312-adaptive-step-size-ray-marching.md) by switching step size based on a global interaction state rather than continuously adapting to local geometric features [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $\mathbf{o}$, normalized direction $\mathbf{d}$, scene function $f(\mathbf{p})$ (SDF or volume texture), maximum distance $t_{max}$, maximum iterations $N_{max}$, interaction flag $\phi \in \{0, 1\}$, base step size $\Delta t_{base}$, interaction step size $\Delta t_{int}$, minimum step size $\Delta t_{min}$, maximum step size $\Delta t_{max}$ [G].
*   **Output:** Intersection status, final distance $t$, accumulated color/opacity [G].

**Data Structures:**
*   `scene_func(p)`: Evaluates the density or SDF at position $\mathbf{p}$, returning `(density, color)` [G].
*   `is_hit(val, epsilon)`: Returns true if surface is intersected [G].
*   `is_early_exit(val, t)`: Returns true if accumulated opacity is sufficient [G].

**Parameters:**
*   $\Delta t_{base}$: Standard step size for high-quality rendering. Typical value depends on volume resolution (e.g., 1-2 voxels) [G].
*   $\Delta t_{int}$: Step size during interaction. [G]
*   $\phi$: Boolean flag. True during mouse drag/view rotation; False during idle/render [G].

**Numbered Steps:**
1.  Initialize $t = 0.0$, accumulated opacity $\alpha_{acc} = 0.0$, and color $C_{acc} = (0,0,0,0)$ [G].
2.  Loop for $i$ from $0$ to $N_{max}-1$:
    a. Check termination: If $t > t_{max}$, return miss [G].
    b. Compute position: $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [G].
    c. Evaluate scene: $val = f(\mathbf{p})$ [G].
    d. Check hit: If `is_hit(val, epsilon)`, return hit at $t$ [G].
    e. Check early exit: If `is_early_exit(val, t)`, return accumulated color [G].
    f. Compute step size $\Delta t$:
       i. If $\phi$ is true (interaction mode), set $\Delta t = \Delta t_{int}$ [G].
       ii. If $\phi$ is false (render mode), set $\Delta t = \Delta t_{base}$ [G].
    g. Clamp step size: $\Delta t = \max(\Delta t, \Delta t_{min})$ [G].
    h. Advance ray: $t \leftarrow t + \Delta t$ [G].
    i. Accumulate contribution (if volume rendering): Update $\alpha_{acc}$ and $C_{acc}$ using front-to-back compositing with the sample at $\mathbf{p}$ and step $\Delta t$ [G].
3.  Return miss [G].

**Pseudocode:**
```python
import math

def adaptive_interaction_march(ray_origin, ray_direction, scene_func, 
                               max_dist, max_steps, epsilon, 
                               is_interacting, base_step, interact_step, 
                               min_step, max_step):
    t = 0.0
    alpha_acc = 0.0
    color_acc = (0.0, 0.0, 0.0, 0.0)
    
    # Determine step size based on interaction state
    step_size = interact_step if is_interacting else base_step
    step_size = max(min_step, min(step_size, max_step))

    for i in range(max_steps):
        if t >= max_dist:
            return False, t, color_acc
        
        p = ray_origin + ray_direction * t
        density, color = scene_func(p)
        
        # Termination: Hit (SDF)
        if abs(density) < epsilon:
            return True, t, color_acc
        
        # Termination: Early Exit (Volume)
        if alpha_acc >= 1.0 - epsilon:
            return False, t, color_acc
            
        # Volume Accumulation
        alpha = 1.0 - math.exp(-density * step_size)
        color_acc = tuple(c + col * alpha * (1.0 - alpha_acc) for c, col in zip(color_acc, color))
        alpha_acc += alpha * (1.0 - alpha_acc)
        
        # Advance
        t += step_size
        
    return False, t, color_acc
```

**Edge Cases and Pitfalls:**
*   **Skipping Features:** If $\Delta t_{int}$ is too large, significant geometric features (e.g., "big mountains" in heightmaps) may be completely skipped, leading to holes or artifacts [S3, unofficial].
*   **Shadow Detail Loss:** Increasing pixel samples can cause loss of shadow detail and make volumes appear more transparent, whereas smaller volume step sizes improve accuracy [S2].
*   **State Synchronization:** The transition between interaction and render modes must be handled carefully to avoid visual popping. The renderer should switch back to $\Delta t_{base}$ immediately after interaction ends [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ where $N$ is the number of steps. During interaction, $N$ is reduced by a factor of $\frac{\Delta t_{base}}{\Delta t_{int}}$ [G].
*   **Memory Complexity:** $O(1)$ auxiliary memory (excluding the volume texture/SDF storage) [G].
*   **Performance:** Significantly improves frame rate during viewport navigation by reducing sample count per ray [S1, unofficial].
*   **Strengths:** Simple to implement; requires no additional data structures; effective for maintaining interactivity in real-time applications [S1, unofficial].
*   **Limitations:** Visual quality degrades during interaction; large steps can cause aliasing or missed geometry [S3, unofficial]; not suitable for final image production [S1, unofficial].
*   **When to use:** Real-time volume rendering where user interaction (rotation, zoom) is frequent [S1, unofficial].
*   **When not to use:** Final offline rendering or when high geometric accuracy is required at all times [S1, unofficial].

## Background
The technique was described by Hadwiger and Rezk Salama in 2004 [S1, unofficial]. It is a common trick in direct volume rendering to balance the trade-off between computational effort and visual artifacts during interactive exploration [S1, unofficial]. The concept of discarding information as distance increases or taking bigger steps to reduce computation is also discussed in the context of realtime voxel landscape engines [S3, unofficial].
