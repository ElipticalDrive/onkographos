# Compute Minimal Sample Distance Per Pixel
## Overview
This method computes the minimal sample distance per pixel by projecting each dataset cell axis onto the viewport, accounting for camera and volume transforms [S1, unofficial]. It determines the smallest valid step size for ray marching based on data resolution limits rather than surface Lipschitz constraints [S1, unofficial]. It differs from [Safe Raymarching Step Size](1462-safe-raymarching-step-size.md) by focusing on grid resolution, and from [Projected Voxel Size / LOD Calculation](4189-projected-voxel-size-lod-calculation.md) by providing a direct scalar metric for step sizing rather than a general LOD metric [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** `renderer`: a `vtkRenderer` pointer providing camera and viewport state [S1, unofficial]. `volume`: a `vtkVolume` pointer providing dataset geometry and transformation [S1, unofficial].
*   **Output:** A scalar value representing the minimal sample distance per pixel, or a flag indicating that the distance should be ignored due to degenerate alignment [S1, unofficial].

**Data Structures:**
The method operates on the volume's internal data representation. Key fields accessed include the dataset extent, voxel spacing, and transformation matrices [S1, unofficial].

**Steps:**
1.  **Retrieve Camera and Volume State:** Obtain the view matrix and projection parameters from the `renderer`, and the dataset geometry and transformation matrix from the `volume` [S1, unofficial].
2.  **Compute Axis Vectors:** Determine the world-space direction vectors corresponding to the dataset's x, y, and z axes. These are derived from the columns of the volume's transformation matrix, scaled by the respective voxel spacings [S1, unofficial].
3.  **Project to View Space:** Transform the axis vectors into the camera's view space using the view matrix [S1, unofficial].
4.  **Check for Degeneracy:** For each axis vector, check if it is aligned with the view direction. The view direction is typically the negative z-axis in view space, $\mathbf{d}_{\text{view}} = (0, 0, -1)$ [G]. Calculate the dot product $dot_i = \mathbf{v}_i \cdot \mathbf{d}_{\text{view}}$ [G]. If $|dot_i|$ is close to 1.0, the projection is degenerate [G].
5.  **Handle Degeneracy:** If any axis is degenerate, set `IgnoreSampleDistancePerPixel` to true and terminate [S1, unofficial]. This prevents division by zero or invalid step sizes when the volume is viewed edge-on along a grid axis [G].
6.  **Compute Projected Sizes:** For non-degenerate axes, compute the projected length of each axis vector onto the image plane by projecting onto the x and y axes of the view space and scaling by the viewport dimensions [G].
7.  **Determine Minimal Distance:** The minimal sample distance is derived from the smallest projected axis size, ensuring the step size is small enough to capture the finest detail in any direction [S1, unofficial]. If `IgnoreSampleDistancePerPixel` is true, the method returns a default large step size or signals the caller to use a different strategy [G].

**Pseudocode:**
```python
def compute_minimal_sample_distance_per_pixel(renderer, volume):
    # 1. Retrieve camera and volume state
    # renderer provides camera and viewport state [S1, unofficial]
    # volume provides dataset geometry and transformation [S1, unofficial]
    camera = renderer.get_camera()
    viewport = renderer.get_viewport()
    geometry = volume.get_geometry()
    transform = volume.get_transform()

    # 2. Project dataset cell axes onto the viewport
    # Axes are derived from dataset geometry and transformed by volume matrix [S1, unofficial]
    axes = [geometry.x_axis, geometry.y_axis, geometry.z_axis]
    transformed_axes = [transform.apply(axis) for axis in axes]
    projected_axes = [camera.project_to_viewport(axis, viewport) for axis in transformed_axes]

    # 3. Check for degenerate axes
    # If any axis is aligned with the view direction, the projection is degenerate [S1, unofficial]
    view_direction = camera.get_direction()
    for axis in projected_axes:
        # Standard dot product and magnitude check [G]
        dot_product = axis.x * view_direction.x + axis.y * view_direction.y + axis.z * view_direction.z
        if abs(dot_product) > 0.99:
            return {"ignore": True, "distance": 0.0}

    # 4. Compute minimal sample distance
    # The distance is derived from the projected axes sizes [S1, unofficial]
    min_distance = float('inf')
    for axis in projected_axes:
        mag = (axis.x**2 + axis.y**2 + axis.z**2)**0.5
        if mag < min_distance:
            min_distance = mag
    return {"ignore": False, "distance": min_distance}
```

**Parameters:**
*   `IgnoreSampleDistancePerPixel`: A boolean flag set to true if any dataset axis is degenerate (aligned with the view direction) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Degenerate Alignment:** Occurs when a dataset axis is parallel to the view ray, making the projected size zero and requiring the `IgnoreSampleDistancePerPixel` flag [S1, unofficial].
*   **Precision:** Floating-point errors in matrix multiplication and dot products can cause incorrect degeneracy detection, requiring a small epsilon threshold [G].
*   **Non-Uniform Scaling:** The method accounts for non-uniform voxel spacing by scaling the basis vectors by the spacing values [S1, unofficial].

## Subtopics

### [Projected Voxel Size / LOD Calculation](4189-projected-voxel-size-lod-calculation.md)
Computes a scalar metric for the projected size of a voxel relative to the camera, primarily used for Level of Detail (LOD) decisions. It evaluates the angular spread of the voxel to provide a normalized measure of voxel appearance in viewing space. Choose this when LOD management is the primary goal rather than direct step size control.

## Operating characteristics
*   **Time Complexity:** $O(1)$ relative to the number of samples, as it involves a fixed number of matrix-vector multiplications and comparisons [G]. It is computed once per volume or per frame depending on implementation [S1, unofficial].
*   **Memory Complexity:** $O(1)$, requiring only temporary storage for vectors and scalars [G].
*   **Strengths:** Provides a geometrically accurate estimate of the required sampling density based on the volume's orientation and resolution [S1, unofficial]. It is robust to volume transformations [G].
*   **Limitations:** Does not account for the actual content of the volume (e.g., smooth vs. high-frequency regions) [G]. It may overestimate the required step size in smooth areas or underestimate it in complex regions if the geometry is not aligned with the axes [G]. It is not suitable for dynamic scenes where the volume changes rapidly, as it requires recomputation [G].
*   **When to Use:** Use when the volume's resolution is the limiting factor for visual quality and the volume is static or changes slowly [G]. It is particularly useful in distance-field ray marching where the step size must be constrained by the data resolution [S1, unofficial].

## Background
The method originates from the VTK (Visualization Toolkit) ecosystem, specifically in the context of multi-volume ray casting [S1, unofficial]. It is implemented in classes that process `vtkRenderer` and `vtkVolume` pointers to optimize rendering by ensuring the sampling rate is appropriate for each volume's geometry and orientation [S1, unofficial]. The approach is part of a broader effort to improve the performance and quality of volume rendering by adapting the sampling strategy to the specific characteristics of the data [S1, unofficial].
