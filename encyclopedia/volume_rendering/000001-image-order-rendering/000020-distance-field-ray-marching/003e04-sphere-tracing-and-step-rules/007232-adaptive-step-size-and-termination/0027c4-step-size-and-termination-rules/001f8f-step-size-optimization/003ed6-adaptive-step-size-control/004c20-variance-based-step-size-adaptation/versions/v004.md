# Variance-based Step Size Adaptation

Also called: Choosing dt through Variance Bricking, Variance Bricking

## Overview
Variance-based Step Size Adaptation is a preprocessing technique that determines the adaptive ray traversal step size ($\Delta t$) for volume rendering by calculating the statistical variance of voxel data within spatial bricks [S1, unofficial]. It solves the problem of selecting an appropriate step size for sparse or local traversal without the computational cost of calculating iso-surface normals at runtime [S1, unofficial]. Unlike fixed-step methods, it adjusts $\Delta t$ based on local data complexity: high variance (frequent normal changes) yields smaller steps, while low variance allows larger steps [S1, unofficial].

## How it works
**Inputs:**
*   Volume dataset $V$ stored in bricks.
*   Voxel dimensions $dx, dy, dz$.
*   Precomputed variance map $v_{ijk}$ for each brick $(i,j,k)$ [S1, unofficial].
*   Constants $\kappa_{min}, \kappa_{max}$ [S1, unofficial].

**Outputs:**
*   Adaptive step size $\Delta t_{ijk}$ for each brick [S1, unofficial].

**Data Structures:**
*   **Brick:** A sub-volume of the dataset. The source tests thread block dimensions such as $4\times4$, $4\times8$, $4\times16$, $4\times32$, $8\times8$, $8\times16$, $8\times32$, and $16\times16$ [S1, unofficial].
*   **Variance Map:** A 3D array where each element corresponds to a brick, storing the precomputed variance $v$ [S1, unofficial].

**Steps:**

1.  **Preprocessing (CPU):** For each brick in the volume, calculate the variance $v$ of the voxel values contained within it [S1, unofficial].
    $$ v = \frac{1}{n} \sum_{i=1}^{n} (x_i - \bar{x})^2 $$
    where $n$ is the number of voxels in the brick, $x_i$ is the value of the $i$-th voxel, and $\bar{x}$ is the mean of the voxel values in the brick [S1, unofficial].

2.  **Mapping Variance to Coefficient:** Map the variance $v$ of a brick to a coefficient $\kappa$ using a linear function that takes the brick's variance $v$, the global minimum variance $v_{min}$, and the global maximum variance $v_{max}$ across all bricks [S1, unofficial]:
    $$ \kappa = \kappa_{min} + \frac{(\kappa_{max} - \kappa_{min})(v - v_{min})}{v_{max} - v_{min}} $$
    Areas with larger variance require a larger value of $\kappa$ [S1, unofficial].

3.  **Calculate Step Size:** Compute the step size $\Delta t$ for the brick using the coefficient $\kappa$ and the voxel dimensions [S1, unofficial]:
    $$ \Delta t_{ijk} = \frac{\min(dx, dy, dz)}{\kappa_{ijk}} $$
    where $dx, dy, dz$ are the physical lengths of a single voxel in the x, y, and z directions [S1, unofficial].

**Parameters:**
*   $\kappa_{max}$: Maximum kappa value. Typical value: 0.3 [S1, unofficial].
*   $\kappa_{min}$: Minimum kappa value. Typical value: 0.1 [S1, unofficial].
*   Thread Block Dimensions: Experimentally determined for GPU execution. The source reports performance tests for block sizes like $4\times4$, $8\times8$, and $16\times16$ [S1, unofficial].

**Pseudocode:**

```python
def compute_variance_map(volume_data, brick_size):
    """
    Preprocess volume data to calculate variance for each brick.
    volume_data: 3D list/array of voxel values.
    brick_size: tuple (bx, by, bz) defining the brick dimensions.
    Returns: 3D list of variances, one per brick.
    """
    vol_shape = (len(volume_data), len(volume_data[0]), len(volume_data[0][0]))
    num_bricks = (
        (vol_shape[0] + brick_size[0] - 1) // brick_size[0],
        (vol_shape[1] + brick_size[1] - 1) // brick_size[1],
        (vol_shape[2] + brick_size[2] - 1) // brick_size[2]
    )
    
    variance_map = [[0.0] * num_bricks[2] for _ in range(num_bricks[1])]
    for _ in range(num_bricks[0]):
        variance_map = [[0.0] * num_bricks[2] for _ in range(num_bricks[1])]
        
    for i in range(num_bricks[0]):
        for j in range(num_bricks[1]):
            for k in range(num_bricks[2]):
                x_start, y_start, z_start = i * brick_size[0], j * brick_size[1], k * brick_size[2]
                x_end = min(x_start + brick_size[0], vol_shape[0])
                y_end = min(y_start + brick_size[1], vol_shape[1])
                z_end = min(z_start + brick_size[2], vol_shape[2])
                
                brick_data = [volume_data[x][y][z] for x in range(x_start, x_end) 
                              for y in range(y_start, y_end) for z in range(z_start, z_end)]
                
                n = len(brick_data)
                if n == 0:
                    variance_map[j][k] = 0.0
                    continue
                    
                mean_val = sum(brick_data) / n
                variance = sum((val - mean_val) ** 2 for val in brick_data) / n
                variance_map[j][k] = variance
                
    return variance_map

def compute_step_sizes(variance_map, voxel_dims, kappa_min, kappa_max):
    """
    Compute adaptive step sizes based on variance map.
    variance_map: 3D list of variances.
    voxel_dims: tuple (dx, dy, dz).
    kappa_min, kappa_max: constants.
    Returns: 3D list of step sizes.
    """
    v_min = min(min(row) for row in variance_map)
    v_max = max(max(row) for row in variance_map)
    
    if v_max == v_min:
        avg_kappa = (kappa_min + kappa_max) / 2.0
        min_dim = min(voxel_dims)
        return [[min_dim / avg_kappa for _ in range(len(variance_map[0]))] for _ in range(len(variance_map))]
        
    v_range = v_max - v_min
    min_dim = min(voxel_dims)
    step_sizes = []
    
    for row in variance_map:
        step_row = []
        for v in row:
            kappa = kappa_min + ((kappa_max - kappa_min) * (v - v_min)) / v_range
            step_row.append(min_dim / kappa)
        step_sizes.append(step_row)
        
    return step_sizes

def ray_march_variance(ray_origin, ray_direction, step_sizes_map, brick_dims_world, max_dist):
    """
    Ray marching loop using precomputed variance-based step sizes.
    Assumes ray origin aligns with grid and uses sparse traversal logic.
    """
    t = 0.0
    max_steps = 10000
    brick_size_x, brick_size_y, brick_size_z = brick_dims_world
    
    for _ in range(max_steps):
        if t >= max_dist:
            return False, t
            
        p_x, p_y, p_z = ray_origin[0] + ray_direction[0] * t, ray_origin[1] + ray_direction[1] * t, ray_origin[2] + ray_direction[2] * t
        
        bx = int(p_x / brick_size_x)
        by = int(p_y / brick_size_y)
        bz = int(p_z / brick_size_z)
        
        if not (0 <= bx < len(step_sizes_map[0]) and 0 <= by < len(step_sizes_map) and 0 <= bz < len(step_sizes_map[0][0])):
            break
            
        dt = step_sizes_map[by][bz]
        t += dt
        
    return False, t
```

**Edge Cases and Pitfalls:**
*   **Uniform Data:** If $v_{max} = v_{min}$, the denominator in the mapping function becomes zero. The implementation must handle this by clamping the denominator or using the average $\kappa$ [G].
*   **Brick Boundaries:** The step size is constant within a brick. If a ray crosses a brick boundary, the step size changes abruptly. The traversal logic accounts for this explicitly using sparse traversal, which checks for surface intersection between samples rather than clamping the step size [S1, unofficial].
*   **Precision:** The variance calculation involves squaring differences, which can lead to precision issues for large datasets with large value ranges. Using double precision for variance accumulation is recommended [G].

## Operating characteristics
*   **Time Complexity:** Preprocessing is $O(N)$ where $N$ is the number of voxels, performed once on the CPU. Ray traversal is $O(M)$ where $M$ is the number of steps, but the number of steps is reduced in high-variance regions compared to fixed-step methods that must use the smallest step size required by the most complex region [S1, unofficial].
*   **Memory Complexity:** Requires storing the variance map, which is $O(N_{bricks})$ where $N_{bricks}$ is the number of bricks. This is significantly smaller than the volume data itself [S1, unofficial].
*   **Measured Performance:** The source reports performance improvements on NVIDIA CUDA hardware. For example, on the "Bucky" dataset, a $4\times4$ thread block size achieved 31 FPS, while $8\times8$ achieved 61 FPS. On the "Engine" dataset, $8\times8$ achieved 31 FPS. On the "Porsche" dataset, $8\times8$ achieved 21 FPS [S1, unofficial].
*   **Strengths:** Eliminates the need for expensive runtime normal calculations. Enhances interactivity for rotating datasets. Effectively utilizes the CUDA memory hierarchy [S1, unofficial].
*   **Limitations:** Introduces a slight decrease in image correctness during rotation, though described as negligible. Requires CPU preprocessing. The choice of thread block dimensions affects performance and quality [S1, unofficial].
*   **When to Use:** Interactive volume rendering of large datasets where iso-surface normals change frequently, and precomputation is acceptable [S1, unofficial].
*   **When Not to Use:** Real-time applications where preprocessing time is prohibitive, or datasets with very low variance where fixed-step methods are sufficient [S1, unofficial].

## Background
The method was developed to enhance the performance of sparse and local traversal techniques for isosurface volume rendering on GPUs [S1, unofficial]. The authors noted that future work would focus on refining the mapping function from variance to step size [S1, unofficial].
