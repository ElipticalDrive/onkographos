# Dynamic Sampling Step Adjustment

Also called: Adaptive Step Doubling, Empty Space Step Doubling

## Overview
Dynamic Sampling Step Adjustment is a ray marching optimization technique that accelerates traversal through empty or low-density regions of a volume by exponentially increasing the step size. It solves the problem of wasted samples in large voids, which is a common bottleneck in distance-field ray marching and density-based volume rendering. It sets itself apart from [Adaptive Step Size Ray Marching](2312-adaptive-step-size-ray-marching.md) and [Variance-based Step Size Adaptation](13161-variance-based-step-size-adaptation.md) by using a simple binary emptiness check (density threshold) rather than gradient magnitude or statistical variance to drive step growth, making it computationally cheaper but potentially prone to aliasing artifacts if the step becomes too large [S1, unofficial].

## How it works
**Inputs:**
*   Current ray position $t$.
*   Current step size $\Delta t$.
*   Current Mipmap level offset `mipOffset` (used to sample lower-resolution textures for emptiness checks) [S1, unofficial].
*   Density threshold $\epsilon$ (typically $>0$) to define "empty" [S1, inferred, unofficial].
*   Bounds $[\Delta t_{min}, \Delta t_{max}]$ [S1, unofficial].

**Outputs:**
*   Next ray position $t_{new}$.
*   Updated step size $\Delta t_{new}$.
*   Updated `mipOffset`.

**Data Structures:**
*   `density`: Scalar value returned by texture lookup at current position.
*   `is_empty`: Boolean, true if `density < epsilon`.

**Steps:**
1.  Sample the volume density at the current ray position $t$ using the current `mipOffset`. Let this value be $d$.
2.  Check if the sample is empty: $d < \epsilon$.
3.  If empty:
    *   Double the step size: $\Delta t_{new} = \Delta t \times 2$.
    *   Increment the Mipmap offset: `mipOffset` = `mipOffset` + 1. This reduces texture resolution for subsequent samples, accelerating the emptiness check [S1, unofficial].
    *   Clamp $\Delta t_{new}$ to $[\Delta t_{min}, \Delta t_{max}]$.
    *   Advance the ray: $t_{new} = t + \Delta t_{new}$.

**Pseudocode:**
```python
def dynamic_sampling_step_adjustment(t, delta_t, mip_offset, density_threshold, delta_t_min, delta_t_max, delta_t_original, mip_offset_original):
    """
    t: current ray position
    delta_t: current step size
    mip_offset: current mipmap level
    density_threshold: scalar density below which volume is considered empty
    delta_t_min: minimum allowed step size
    delta_t_max: maximum allowed step size
    delta_t_original: the base step size (used for restoration)
    mip_offset_original: the base mipmap level (used for restoration)
    """
    
    # 1. Sample density
    density = sample_volume(t, mip_offset)
    
    # 2. Check emptiness
    if density < density_threshold:
        # Empty region: accelerate
        new_delta_t = delta_t * 2
        
        # Clamp step size
        if new_delta_t > delta_t_max:
            new_delta_t = delta_t_max
        if new_delta_t < delta_t_min:
            new_delta_t = delta_t_min
            
        # Increase mip offset for coarser sampling
        new_mip_offset = mip_offset + 1
        
        # Advance ray
        t_new = t + new_delta_t
        
        return t_new, new_delta_t, new_mip_offset
    else:
        # Non-empty region: retreat and reset
        # "Step back one step"
        t_retracted = t - delta_t
        
        # "Restore step size and mipOffset to original values"
        new_delta_t = delta_t_original
        new_mip_offset = mip_offset_original
        
        # Advance with original step to re-evaluate boundary
        t_new = t_retracted + new_delta_t
        
        return t_new, new_delta_t, new_mip_offset
```

**Parameters:**
*   $\epsilon$: Density threshold. Not given in the sources. [G] Typical values range from $10^{-5}$ to $0.01$ depending on normalization.
*   $\Delta t_{original}$: The initial step size. Not given in the sources. [G] Typically derived from $\Delta t_{max}$ or a fixed resolution-based step.

**Edge Cases and Pitfalls:**
*   **Artifacts:** The optimization provides small performance gains and may cause artifacts in some cases, particularly if the step size doubles too quickly over thin features [S1, unofficial].
*   **Oscillation:** Stepping back and resetting can cause the ray to oscillate at the boundary of a volume if the density fluctuates near the threshold.
*   **Mipmap Clamping:** `mipOffset` must be clamped to the maximum available mipmap level to prevent out-of-bounds texture access.

## Subtopics

### [Gradient-driven Sampling](5281-gradient-driven-sampling.md)
Gradient-driven sampling is a ray marching technique that dynamically adjusts step sizes based on the magnitude of the scalar field gradient, refining traversal in regions with high feature sharpness while coarsening it in smooth interiors. It distinguishes itself from uniform sampling by adapting to local geometry to preserve boundary details without aliasing, and from hierarchical sampling by using gradient magnitude rather than variance or error tolerance to drive step selection.

### [Dynamic Texture Slice Resampling](6101-dynamic-texture-slice-resampling.md)
Dynamic Texture Slice Resampling is a technique for volume rendering that dynamically updates slicing steps according to viewing directions to maintain a constant step size during the Direct Volume Rendering (DVR) process. It solves the problem of striping artifacts caused by non-uniform sampling steps. The method adapts the sampling density to the viewing geometry to maintain high rendering performance.

### Dynamic Adaptive Sampling Ray-Casting
An improved volume rendering algorithm designed to address slow rendering speed and low sampling efficiency in 3D reconstruction of medical images by dynamically adjusting sampling intervals and using a new rendering operator [S2]. It uses the central difference gradient method to obtain the corresponding sampling interval dynamically according to the different sampling points [S2]. It applies a new rendering operator based on the color value and opacity changes before and after the ray enters the volume element, and the resistance luminosity [S2]. On the ISBI2018 dataset, the ray-casting DAS algorithm reduces and avoids artifact phenomena in CT image rendering and improves image visibility compared to Francisco Sans' algorithm, Roba Binyahibs' algorithm, Feiniu Yuan's algorithm, Leonardo's algorithm, and Yan Zhang's algorithm [S2]. Compared with other algorithms, this method achieves faster rendering speed while ensuring the quality of the generated image [S2].

### Geometry Sampling Adjustment
A method to adjust the maximum number of geometry samples per streamline based on a geometry sampling factor [S3, unofficial]. It sets `m_maxGeometrySamples` to `m_maxSamples / m_geometrySampling + 1` [S3, unofficial]. `m_maxSamples` is the base maximum number of samples per streamline, and `m_geometrySampling` is a factor used to reduce the number of geometry samples [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per step for the decision logic. The benefit comes from skipping steps in empty space, reducing the total number of samples $N$ for a ray.
*   **Memory Complexity:** $O(1)$ additional state (current step, mip offset).
*   **Performance:** Provides small performance gains [S1, unofficial]. The gain is most significant in scenes with large empty volumes (e.g., atmospheric rendering, large medical scans with air).
*   **Strengths:** Simple to implement; very low computational overhead per step; effective for large voids.
*   **Limitations:** May cause artifacts if the step size grows too large relative to feature size [S1, unofficial]; does not account for high-frequency details within non-empty regions; oscillation at boundaries.
*   **When to use:** Scenes with large empty regions where the cost of sampling is high (e.g., cloud rendering, large-scale atmospheric effects).
*   **When not to use:** Scenes with thin, high-frequency features where aliasing is a concern, or where gradient-based adaptation is preferred for quality.
