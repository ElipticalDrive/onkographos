# Dynamic Epsilon for Self-Intersection Prevention

Also called: Dynamic epsilon, Dynamic offset, Dynamic ε for self-intersection prevention

## Overview
Dynamic epsilon is a method for preventing self-intersection artifacts in secondary rays (such as refraction or reflection) within sphere tracing by computing a local offset dynamically at each intersection point, rather than using a global constant [S1][S3, unofficial]. It solves the problem where global epsilon values are inappropriate for sphere tracing because intersection distances from the surface exhibit large variations, particularly when screen-space termination metrics are used [S1][S3, unofficial]. Unlike siblings that may use fixed offsets or affine arithmetic, this method adapts the offset magnitude to the local signed distance bound, ensuring robustness against precision issues near the surface while maintaining performance [S1][S3, unofficial].

## How it works
**Inputs and Outputs:**
- **Input:** The intersection point $p$ obtained from sphere tracing, the signed distance function value $f(p)$ at that point, and a global minimal offset constant $\epsilon_{min}$ [S1].
- **Output:** A dynamic offset value $\epsilon_{dynamic}$ and the new ray origin for the secondary ray [S1].

**Data Structures:**
No specific complex data structures are required beyond standard floating-point variables for the point $p$, the scalar distance $f(p)$, and the constants [G].

**Parameters:**
- $\epsilon_{min}$: A global minimal offset value. It must be chosen carefully; if too small, it causes numerical problems (when $f(p) \approx 0$) and poor performance (slow acceleration away from the surface) [S1][S3, unofficial]. The sources do not provide a specific numerical value, but note that manually choosing $\epsilon_{min}$ is easier and more robust than choosing a global epsilon that works for all distances [S1][S3, unofficial].

**Formulas:**
The dynamic epsilon is calculated as:
$$ \epsilon_{dynamic} = 2 \cdot \max(\epsilon_{min}, |f(p)|) $$
This ensures that $\epsilon_{dynamic} \ge 2 \cdot \epsilon_{min}$, which obviates numerical problems associated with $f(p) \approx 0$ [S1][S3, unofficial].

**Steps:**
1. At each intersection point $p$ obtained from sphere tracing, compute the signed distance bound $f(p)$ [S1].
2. Calculate $\epsilon_{dynamic}$ using the formula $\epsilon_{dynamic} = 2 \cdot \max(\epsilon_{min}, |f(p)|)$ [S1][S3, unofficial].
   - If $|f(p)| \ge \epsilon_{min}$, then $\epsilon_{dynamic} = 2 \cdot |f(p)|$ [S1][S3, unofficial].
   - If $|f(p)| \le \epsilon_{min}$, then $\epsilon_{dynamic} = 2 \cdot \epsilon_{min}$ [S1][S3, unofficial].
3. Offset the new ray origin for the secondary ray by $\epsilon_{dynamic}$ along the surface normal at $p$ [S1].

**Pseudocode:**
```python
def compute_dynamic_epsilon_offset(p, f_p, epsilon_min, normal):
    """
    Computes the new ray origin for a secondary ray to prevent self-intersection.
    
    Args:
        p: The intersection point from sphere tracing.
        f_p: The signed distance function value at p.
        epsilon_min: The global minimal offset constant.
        normal: The surface normal at p.
        
    Returns:
        new_origin: The offset ray origin for the secondary ray.
    """
    # Calculate dynamic epsilon based on the absolute signed distance
    # Formula: epsilon_dynamic = 2 * max(epsilon_min, abs(f_p))
    abs_f_p = abs(f_p)
    epsilon_dynamic = 2.0 * max(epsilon_min, abs_f_p)
    
    # Offset the ray origin along the normal
    new_origin = p + epsilon_dynamic * normal
    
    return new_origin
```

**Edge Cases and Pitfalls:**
- **Precision Issues:** If $f(p)$ is very close to zero, a global epsilon might be too small, causing self-intersection [S1]. The dynamic method ensures $\epsilon_{dynamic} \ge 2 \cdot \epsilon_{min}$, avoiding this [S3, unofficial].
- **Performance Degradation:** If $\epsilon_{min}$ is too small, the sphere tracing for the secondary ray must spend many iterations accelerating away from the surface, degrading performance [S3, unofficial].
- **Screen-Space Termination:** Standard origin offsetting is insufficient for sphere tracing because the intersection point can be far from the surface, especially when using epsilon-based termination [S2, unofficial]. Dynamic epsilon accommodates these large variations [S1][S3, unofficial].

### [Affine Arithmetic Early Skip Test](4313-affine-arithmetic-early-skip-test.md)
Uses affine arithmetic to skip steps where the ray cannot intersect the object [G]. It sets itself apart by avoiding distance function evaluations entirely for safe regions [G]. Choose it when performance is critical and the scene has simple primitives [G].

### [Convex Object Optimization](4367-convex-object-optimization.md)

### [Ray Intersection with Grazing Point Detection](4463-ray-intersection-with-grazing-point-detection.md)

### [Gradient Magnitude Windowing](8299-gradient-magnitude-windowing.md)
Uses gradient magnitude to adjust step sizes [G]. It sets itself apart by modulating step length based on local function smoothness rather than distance bounds [G]. Choose it when the signed distance function has varying smoothness [G].

## Background
Dynamic epsilon was introduced in the paper "Enhanced Sphere Tracing" [S1][S3, unofficial]. The paper presents several performance and quality enhancements to classical sphere tracing, including this method for dynamically preventing self-intersections upon converting signed distance bounds [S1][S3, unofficial].
