# Termination Criteria


## Overview
Termination criteria define the conditions under which a ray-marching loop halts, ensuring the algorithm returns a valid intersection point or correctly identifies a miss without infinite iteration [G]. It solves the problem of premature termination (missing thin geometry), self-intersection artifacts (due to insufficient epsilon), and excessive computation (tracing through empty space or deep into volumes). It sets itself apart from sibling methods like [Sphere Tracing](1674-sphere-tracing.md) by focusing on the general control flow logic applicable to both Signed Distance Fields (SDFs) and volumetric density fields, rather than the specific geometric step-size constraints of sphere tracing or the fixed-step simplicity of constant marching.

```python
def ray_march_loop(ray_origin, ray_direction, scene_func, max_dist, max_steps, epsilon, min_step=1e-6, max_step=1.0):
    """
    Generic ray marching loop with adaptive step size and termination.
    """
    t = 0.0
    for i in range(max_steps):
        if t > max_dist:
            return False, t
        
        p = ray_origin + ray_direction * t
        val = scene_func(p)
        
        # Termination: Surface Hit (SDF)
        if abs(val) < epsilon:
            return True, t
        
        # Step Size Calculation (SDF-based)
        step = val
        # Clamp step to prevent backward movement or excessive steps
        step = max(min_step, min(max_step, step))
        
        t += step
        
    return False, t
```

### [Sphere Tracing Termination and Clipping](2635-sphere-tracing-termination-and-clipping.md)

It solves the problem of premature termination (missing thin geometry), self-intersection artifacts (due to insufficient epsilon), and excessive computation (tracing through empty space or deep into volumes). It sets itself apart from sibling methods like [Ray Marching with Early Termination](17724-ray-marching-with-early-termination.md) by focusing specifically on the geometric constraints of Signed Distance Fields (SDFs) and the numerical stability of the step-size logic, rather than volumetric opacity accumulation. See [Sphere Tracing Termination and Clipping](2635-sphere-tracing-termination-and-clipping.md).

### [Ray Marching with Early Termination](17724-ray-marching-with-early-termination.md)
Ray marching with early termination is a control flow strategy applied to the iterative ray marching loop to halt computation once the ray has interacted with the target scene or exceeded computational limits. It solves the problem of unnecessary processing by breaking the loop when a surface intersection is detected or when the ray has traveled beyond a defined maximum distance. Unlike methods that strictly iterate a fixed number of steps regardless of scene content, this approach dynamically adapts the loop duration based on geometric or volumetric feedback, significantly improving performance for sparse or bounded scenes. See [Ray Marching with Early Termination](17724-ray-marching-with-early-termination.md).

### [Early Ray Marching Termination (Threshold)](13009-early-ray-marching-termination-threshold.md)
Early Ray Marching Termination (Threshold) is an optimization that halts the ray marching loop when the accumulated transmission falls below a user-defined small value, thereby skipping the computation of negligible volume contributions. It trades statistical accuracy for performance by discarding the "long tail" of the volume's contribution. Unlike standard constant step marching, which samples until exit or hit, this method stops early when further contributions are deemed insignificant. See [Early Ray Marching Termination (Threshold)](13009-early-ray-marching-termination-threshold.md).

## Background
The concept of early termination in ray marching emerged alongside the practical implementation of volume rendering and SDF-based rendering in real-time graphics [G]. As ray marching became a standard technique for rendering implicit surfaces and volumetric data, the computational cost of iterating through empty space or fully opaque regions became a bottleneck [G]. The specific threshold-based early exit for volumes was discussed in community-driven educational resources, highlighting the trade-off between rendering speed and physical accuracy [G]. The geometric termination criteria for sphere tracing, including oscillation detection and grazing resolution, were developed to address numerical instability and visual artifacts like "auras" and self-intersections in SDF rendering [G].
