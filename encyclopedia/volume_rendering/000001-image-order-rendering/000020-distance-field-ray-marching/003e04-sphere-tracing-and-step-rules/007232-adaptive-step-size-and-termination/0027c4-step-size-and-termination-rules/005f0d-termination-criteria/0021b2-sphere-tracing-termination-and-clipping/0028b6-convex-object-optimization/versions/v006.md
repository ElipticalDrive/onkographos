# Convex Object Optimization

Also called: Convex Shape Optimization for Internal Origins, Convex bounding volume optimization, Internal Ray Optimization, Inverse ray tracing for convex objects

## Overview
Convex Object Optimization accelerates sphere tracing through convex objects represented by a signed distance field (SDF) enclosed by a convex bounding volume [S3, unofficial]. It solves the problem of inefficient ray marching when the ray origin lies inside the object, where standard sphere tracing requires many small steps to traverse the interior [S3, unofficial]. It sets itself apart from standard sphere tracing by avoiding internal steps entirely for internal origins, and from gradient-based optimizations by relying only on the bounding volume geometry rather than per-step gradient computations [S1][S3, unofficial]. It builds on [Sphere Tracing Termination and Clipping](2635-sphere-tracing-termination-and-clipping.md).

## How it works
The method assumes the object is enclosed by a convex bounding volume for which ray intersection and point containment can be computed efficiently [S1][S3, unofficial]. It categorizes the ray origin $o$ relative to the bounding volume and the object surface into three cases [S1].

### Inputs and Outputs
- **Inputs**: Ray origin $o$, normalized ray direction $d$, object SDF function $f(p)$, convex bounding volume $B$ [S1][S3, unofficial].
- **Outputs**: Intersection distance $t$ along the ray, or `None` if no intersection [S1].

### Data Structures
- **Bounding Volume $B$**: A convex shape supporting analytic ray intersection and point containment tests [G].
- **SDF $f(p)$**: A function returning the signed distance to the object surface. $f(p) < 0$ indicates inside, $f(p) > 0$ outside [G].

### Steps

1. **Detect Case**: Determine the position of the ray origin $o$ relative to the bounding volume $B$ and the object $f$ [S1].
   - Compute $t_b = \text{intersect\_ray\_convex}(o, d, B)$ [G]. If `None`, the ray does not intersect the bounding volume; return `None` [S1].
   - Check if $o$ is inside the object: $inside\_obj = (f(o) < 0)$ [S2, unofficial].
   - Check if $o$ is inside the bounding volume: $inside\_bound = \text{point\_in\_convex}(o, B)$ [G].
   - The three cases are:
     - **Case 1**: Origin outside bounding volume ($o \notin B$) [S1].
     - **Case 2**: Origin inside bounding volume but outside object ($o \in B$ and $f(o) \ge 0$) [S1].
     - **Case 3**: Origin inside bounding volume and inside object ($o \in B$ and $f(o) < 0$) [S1].

2. **Handle Case 1 (Origin outside bounding volume)**:
   - The ray enters the bounding volume at $t_b$ [S1].
   - Set new origin $o' = o + t_b \cdot d$ [G].
   - Perform standard sphere tracing starting from $o'$ using $f(p)$ [S1][S3, unofficial].
   - Return the result.

3. **Handle Case 2 (Origin inside bounding volume, outside object)**:
   - The ray is already inside the bounding volume but outside the object [S1].
   - Perform standard sphere tracing starting from $o$ using $f(p)$ [S1][S3, unofficial].
   - Return the result.

4. **Handle Case 3 (Origin inside bounding volume and inside object)**:
   - This is the optimization case. Tracing forward through the interior is costly [S1][S3, unofficial].
   - Find the intersection of the ray with the bounding volume in the forward direction. Let this distance be $t_b$ [S1].
   - Compute the point on the bounding volume boundary: $p_{bound} = o + t_b \cdot d$ [G].
   - Perform sphere tracing in the **inverse** ray direction starting from $p_{bound}$ [S1][S3, unofficial].
     - Inverse ray: origin $p_{bound}$, direction $-d$ [G].
     - Trace using $f(p)$ until an intersection is found. Let the distance along the inverse ray be $t_{inv}$ [G].
   - The intersection point in world space is $p_{hit} = p_{bound} - t_{inv} \cdot d$ [G].
   - The intersection distance for the original ray is $t = t_b - t_{inv}$ [G].
   - If $t < 0$, the intersection lies behind the origin; return `None` [G].
   - Return $t$.

### Pseudocode

```python
def convex_optimized_sphere_trace(o, d, f, B):
    # Step 1: Intersect ray with bounding volume
    t_b = intersect_ray_convex(o, d, B)
    if t_b is None:
        return None

    inside_obj = f(o) < 0
    inside_bound = point_in_convex(o, B)

    # Case 1: Origin outside bounding volume
    if not inside_bound:
        o_prime = o + t_b * d
        return sphere_trace(o_prime, d, f)

    # Case 2: Origin inside bounding volume, outside object
    if not inside_obj:
        return sphere_trace(o, d, f)

    # Case 3: Origin inside bounding volume and inside object
    p_bound = o + t_b * d
    t_inv = sphere_trace(p_bound, -d, f)

    if t_inv is None:
        return None
    if t_inv > t_b:
        return None # Intersection is behind the origin

    return t_b - t_inv

def sphere_trace(o, d, f):
    """Standard sphere tracing loop."""
    max_steps = 1000
    max_dist = 100.0
    t = 0.0
    for _ in range(max_steps):
        p = o + t * d
        dist = f(p)
        if dist < 1e-4:
            return t
        if t > max_dist:
            return None
        t += dist
    return None

def intersect_ray_convex(o, d, B):
    """Returns smallest positive t where o + t*d intersects convex volume B, or None.
    Implemented here as a standard ray-sphere intersection for a spherical bounding volume [G]."""
    oc = [o[i] - B['center'][i] for i in range(3)]
    b = sum(oc[i] * d[i] for i in range(3))
    c = sum(oc[i] * oc[i] for i in range(3)) - B['radius']**2
    disc = b*b - c
    if disc < 0:
        return None
    disc = disc**0.5
    t = -b - disc
    if t < 0:
        t = -b + disc
        if t < 0:
            return None
    return t

def point_in_convex(p, B):
    """Returns True if point p is inside convex volume B, False otherwise.
    Implemented here as a standard point-in-sphere test [G]."""
    return sum((p[i] - B['center'][i])**2 for i in range(3)) <= B['radius']**2
```

### Parameters
- **Hit Threshold**: Not given in the sources. [G] A value of $10^{-4}$ is standard for sphere tracing.
- **Max Steps**: Not given in the sources. [G] A value of 1000 is standard for sphere tracing.
- **Max Distance**: Not given in the sources. [G] Scene-dependent.

### Edge Cases and Pitfalls
- **Precision**: When $t_{inv} \approx t_b$, the result $t$ may suffer from cancellation errors. However, since $t_{inv}$ is the distance from the boundary to the surface, and the origin is inside, $t_{inv}$ is generally small compared to $t_b$ unless the origin is very close to the boundary [G].
- **Degenerate Bounding Volume**: If the bounding volume is not strictly convex, the intersection test may fail or return incorrect results [G].
- **Origin on Boundary**: If $f(o) \approx 0$, the case classification may be unstable. [G] Treat as outside object (Case 2) if $f(o) \ge 0$.

## Subtopics

## Operating characteristics
- **Time Complexity**: Reduces the number of iterations for internal origins from $O(D)$ where $D$ is the diameter of the object, to $O(1)$ for the bounding volume intersection plus $O(d_{exit})$ where $d_{exit}$ is the distance from the boundary to the surface [G]. This is significantly faster for large objects [S1].
- **Memory Complexity**: $O(1)$ additional memory for the bounding volume intersection [G].
- **Measured Performance**: In a test scene with 3 spheres, a ground plane, and a dodecahedron with a bounding sphere, using two reflection bounces and eight refraction bounces, the convex optimization provided a speedup of around 10% (2.73 ms with optimization vs. 3.03 ms without) [S1].
- **Strengths**: Avoids costly marching through the interior of the object. Avoids the often costly computation of the gradient per iteration step, which is not feasible in real-time applications [S1][S3, unofficial].
- **Limitations**: Requires a convex bounding volume that supports efficient ray intersection. Not applicable to non-convex objects without decomposition [G].

## Background
The optimization was proposed by Hart et al. [Har96] for sphere tracing convex objects. However, many of the original optimizations involved the often costly computation of the gradient per iteration step, which is not feasible in real-time applications [S1][S3, unofficial]. The specific implementation described here, which uses inverse ray tracing from a bounding volume, is presented in the context of Enhanced Sphere Tracing [S1][S3, unofficial].
