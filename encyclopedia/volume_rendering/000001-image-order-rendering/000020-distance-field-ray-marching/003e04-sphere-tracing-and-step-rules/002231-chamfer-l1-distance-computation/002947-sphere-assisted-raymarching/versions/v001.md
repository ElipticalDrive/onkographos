# Sphere Assisted Raymarching

Also called: Shape Assisted Raymarching, Shape Marching, Sphere Assisted

## Overview
Sphere Assisted Raymarching is a technique for accelerating ray traversal in voxel grids by storing the radius of the largest empty sphere centered at each voxel in a separate shape texture [S1, S2, unofficial]. This allows rays to take large steps through empty space, significantly reducing the number of voxel lookups compared to plane marching [S1, S2, unofficial]. It sets itself apart from its parent method, Chamfer-L1 Distance Computation, by using the exact Euclidean distance (sphere radius) rather than the L1 distance (Manhattan distance) to determine step sizes, providing tighter bounds on empty space [S1, S2, unofficial].

## How it works
Sphere Assisted Raymarching decouples shape information from color information. Instead of storing solid/not-solid flags or L1 distances, it stores the Euclidean distance to the nearest solid voxel for every empty voxel [S1, S2, unofficial].

**Inputs and Outputs**
*   **Input:** Ray origin $p_0$, ray direction $d$ (normalized), maximum check distance $maxDistToCheck$, voxel grid size $voxelGridSize$.
*   **Output:** Color of the first solid voxel hit, or transparent if no voxel is hit within $maxDistToCheck$.

**Data Structures**
Two 3D textures are required:
1.  **`voxels`**: A 3D texture storing normalized float color values. The alpha channel indicates solidity (or is used in conjunction with the shape texture) [S1, unofficial].
2.  **`shape`**: A separate 3D texture storing non-negative integers. The red channel stores the radius of the largest empty sphere centered at that voxel [S1, S2, unofficial].
    *   **Solid Voxel Marker**: The value `255` represents a solid voxel [S1, S2, unofficial].
    *   **Empty Voxel Value**: The value represents the distance to the nearest solid voxel [S2, unofficial].

**Algorithm Steps**
1.  Initialize ray parameter $t = 0$.
2.  Loop while $t \le maxDistToCheck$:
    a.  Calculate current position $p = p_0 + d \cdot t$.
    b.  Sample the shape texture at grid coordinates $p / voxelGridSize$ to get `shapeValue` [S1, S2, unofficial].
    c.  If `shapeValue` == 255, the ray has hit a solid voxel. Return the color from the `voxels` texture at $p / voxelGridSize$ [S1, S2, unofficial].
    d.  Calculate the distance to the next plane boundaries along the ray direction $d$. Let $\delta_{plane}$ be the minimum distance to any axis-aligned plane boundary [S1, unofficial].
    e.  Update $t$ by adding the maximum of the plane boundary distance and the sphere radius: $t \leftarrow t + \max(\delta_{plane} + \text{shapeValue}, \epsilon)$ [S1, unofficial].
        *   Note: The sources provide a specific implementation for $\delta_{plane}$ using `step` and `fract` functions [S1, unofficial].
3.  If the loop terminates without hitting a solid voxel, return transparent color [S1, unofficial].

**Pseudocode**
The following pseudocode implements the method as described in [S1, unofficial]. It assumes standard GLSL-like vector operations (`step`, `fract`, `mincomp` for component-wise minimum).

```python
def sphere_assisted_raymarch(p0, d, maxDistToCheck, voxelGridSize, shape_texture, voxels_texture):
    t = 0.0
    epsilon = 1e-6  # Small constant to guarantee progress [S1, unofficial]
    
    while t <= maxDistToCheck:
        # Calculate current position
        p = p0 + d * t
        
        # Sample shape data
        # Note: p / voxelGridSize converts world position to voxel grid coordinates
        shape_value = shape_texture.sample_level(p / voxelGridSize, 0).r
        
        # Check for solid voxel
        if shape_value == 255:
            return voxels_texture.sample_level(p / voxelGridSize, 0)
        
        # Calculate deltas to next plane boundaries
        # step(0, d) returns 1.0 where d > 0, else 0.0
        # fract(p) returns the fractional part of p
        # This computes the distance to the next integer grid plane along d
        deltas = (step(0.0, d) - fract(p)) / d
        
        # Find the minimum delta to the nearest plane boundary
        min_delta = min(deltas.x, min(deltas.y, deltas.z))
        
        # Step forward by the maximum of the plane distance and the sphere radius
        # This ensures we don't overshoot the sphere boundary or the plane boundary
        t += max(min_delta + shape_value, epsilon)
        
    return vec4(0.0)
```

**Parameters**
*   `255`: Constant representing a solid voxel in the shape texture [S1, S2, unofficial].
*   `epsilon`: Small constant added to the step size to guarantee progress and avoid infinite loops due to floating-point precision issues [S1, unofficial].
*   `maxDistToCheck`: Maximum distance the ray will travel [S1, unofficial].

**Edge Cases and Pitfalls**
*   **Upfront Cost**: Generating the shape data (distance field) has a significant upfront computational cost [S2, unofficial].
*   **Memory Usage**: Requires two textures (color and shape), increasing memory usage compared to single-texture methods [S1, unofficial].
*   **Precision**: The shape data uses integer formats to store distances, which may limit precision for very large voxel grids or fine details [S1, unofficial].

## Subtopics

### Cube Assisted Raymarching
A variant that stores the size of the largest possible cube around each empty cell instead of a sphere [S2, unofficial]. It is faster to compute (order of magnitude faster) but slightly suboptimal for step size compared to sphere-assisted [S2, unofficial]. It uses a summed area table (SAT) to compute the area of arbitrary boxes in $O(1)$ time, allowing binary search for the maximum cube size in $O(\log n)$ per voxel, reducing upfront complexity from $O(n^2)$ to $O(n \log n)$ [S2, unofficial].

## Operating characteristics
*   **Time Complexity**: The raymarching step itself is efficient, reducing voxel lookups in empty space [S1, unofficial]. However, the upfront cost to generate the shape data is $O(n^2)$ for sphere-assisted, where $n$ is the number of voxels [S2, unofficial].
*   **Memory Complexity**: Requires two 3D textures (color and shape), doubling memory usage compared to methods using a single texture [S1, unofficial].
*   **Performance**: Reduces the number of voxel lookups, which can improve performance in sparse scenes [S1, unofficial]. However, it is not always a performance win due to the overhead of texture sampling and the upfront generation cost [S1, S2, unofficial].
*   **Strengths**: Large steps through empty space; reduces ray traversal steps [S1, S2, unofficial].
*   **Limitations**: High upfront computational cost for shape generation; higher memory usage; integer precision limits [S1, S2, unofficial].
*   **When to Use**: When the scene is sparse and the cost of ray traversal is high relative to the upfront shape generation cost [S1, unofficial].
*   **When Not to Use**: When memory is constrained, or when the scene is dense and the upfront cost outweighs the traversal savings [S1, S2, unofficial].

## Background
Sphere Assisted Raymarching was introduced by Caleb Leak in his blog posts on raymarching voxel rendering [S1, S2, unofficial]. It was developed as an optimization over plane marching and Chamfer-L1 distance computation to handle large empty spaces more efficiently [S1, S2, unofficial]. The technique was tested on a GTX 980 Ti with a 1920x1080 resolution [S2, unofficial].
