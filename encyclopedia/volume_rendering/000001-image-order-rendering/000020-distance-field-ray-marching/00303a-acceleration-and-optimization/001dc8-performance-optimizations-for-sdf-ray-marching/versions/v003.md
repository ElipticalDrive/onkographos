# Performance Optimizations for SDF Ray Marching

Also called: Optimisations, SDF Ray Marching Optimizations

## Overview
Performance Optimizations for SDF Ray Marching encompasses techniques to reduce the computational cost of rendering Signed Distance Field scenes while maintaining visual fidelity [S1, unofficial][S2, unofficial]. It addresses the primary bottleneck of ray marching: the high number of SDF evaluations required per pixel [S2, unofficial]. What sets these optimizations apart from sibling methods like [Beam Optimization](932-beam-optimization.md) is their focus on reducing the number of march steps or the cost per step through geometric culling, resolution scaling, and parameter tuning, rather than altering the traversal structure or parallelism model [S1, unofficial][S2, unofficial].

## How it works
The method applies several independent optimization strategies during the ray marching loop or the rendering pipeline setup [S1, unofficial][S2, unofficial].

### Inputs and Outputs
*   **Inputs:** Scene SDF functions, camera parameters, ray origin/direction, maximum step count (`MAX_STEPS`), epsilon threshold (`EPSILON`), and resolution settings [S1, unofficial][S2, unofficial].
*   **Outputs:** Rendered image with reduced computational cost [S1, unofficial][S2, unofficial].

### Data Structures
No new data structures are strictly required for the core optimizations, though baked shadow/AO techniques utilize 3D volume textures [S3, unofficial].

### Steps and Formulas

1.  **Early-Out Bounding Volumes**
    Surround expensive sub-scenes with a fast sphere SDF check [S1, unofficial]. Skip the detail if the bounding SDF value is greater than the marching step [S1, unofficial].
    *   Let $d_{bound}$ be the distance from the current ray point $P$ to the bounding volume [S1, unofficial].
    *   Let $d_{step}$ be the current step size [S1, unofficial].
    *   Condition: If $d_{bound} > d_{step}$, skip the complex SDF evaluation [S1, unofficial].

2.  **Level of Detail (LOD) Adjustment**
    Reduce the maximum number of steps and increase the epsilon threshold for distant geometry, as the visual difference is imperceptible beyond 10 scene units [S1, unofficial][S2, unofficial].
    *   Let $dist$ be the distance from the camera to the current ray point [S1, unofficial].
    *   If $dist > 10$, apply a reduced maximum step count and a larger epsilon threshold [S1, unofficial][S2, unofficial].

3.  **Resolution Scaling**
    Render at half resolution before upscaling to keep frame rates real-time [S2, unofficial]. This is cited as the most effective single optimization for real-time SDF rendering at larger resolutions [S1, unofficial].
    *   Let $W, H$ be the target resolution [S1, unofficial][S2, unofficial].
    *   Render to a buffer of size $\lfloor W/2 \rfloor \times \lfloor H/2 \rfloor$, then upscale to the target resolution [S1, unofficial][S2, unofficial].

4.  **Over-Relaxation**
    Multiply the step size $d$ by a constant factor $k$ where $1.1 \le k \le 1.6$ [S1, unofficial].
    *   Update rule: $t_{new} = t_{old} + d \times k$ [S1, unofficial].
    *   This allows the ray to advance faster through open scenes [S1, unofficial].
    *   **Pitfall:** This risks artefacts near concave edges [S1, unofficial].

5.  **Pre-marched Shadow and Ambient Occlusion Baking**
    For static volumes, pre-calculate shadow and ambient occlusion data into the volume texture [S3, unofficial].
    *   **Baking Shadow:** Pre-march a shadow ray through the volume (e.g., 4 shadow samples per cloud sample), allowing dynamic time-of-day changes [S3, unofficial].
    *   **Baking Ambient Occlusion:** Pre-march ambient occlusion into the volume texture to add shading without runtime cost [S3, unofficial].
    *   **Runtime Lookup:** Use the baked texture to retrieve values with a single 3D texture lookup, matching the cloud geometry perfectly [S3, unofficial].

### Pseudocode

```python
def optimize_sdf_raymarch(ray_origin, ray_direction, scene_sdf, bounds_sdf,
                          max_steps_near, max_steps_far, epsilon_near, epsilon_far,
                          use_over_relaxation, over_relaxation_factor,
                          baked_shadow_tex, baked_ao_tex, max_distance):
    """
    Performs ray marching with performance optimizations.
    """
    t = 0.0
    steps = 0
    current_step = 1.0  # Initial safe step size for bounding volume check [G]
    
    while steps < max_steps_near:
        p = ray_origin + ray_direction * t
        dist_to_camera = length(p - ray_origin)  # Standard vector length [G]

        # Level of Detail
        if dist_to_camera > 10.0:
            current_max_steps = max_steps_far
            current_epsilon = epsilon_far
        else:
            current_max_steps = max_steps_near
            current_epsilon = epsilon_near

        if steps >= current_max_steps:
            break

        # Early-Out Bounding Volumes
        d_bound = bounds_sdf(p)
        if d_bound > current_step:
            t += d_bound
            current_step = d_bound
            steps += 1
            continue

        # Evaluate Main SDF
        d = scene_sdf(p)
        current_step = d

        # Over-Relaxation
        if use_over_relaxation:
            current_step = d * over_relaxation_factor

        # Safety clamp to prevent infinite loops or negative steps
        if current_step < 0.0001:
            current_step = 0.0001

        t += current_step
        steps += 1

        # Check for hit
        if d < current_epsilon:
            shadow = 1.0
            ao = 1.0
            if baked_shadow_tex is not None:
                shadow = texture_3d(baked_shadow_tex, p)  # Standard 3D texture lookup [G]
            if baked_ao_tex is not None:
                ao = texture_3d(baked_ao_tex, p)
            return {"hit": True, "position": p, "shadow": shadow, "ao": ao}

        # Check for miss
        if t > max_distance:
            break

    return {"hit": False, "position": p}
```

## Subtopics

### [Subsurface Scattering Approximation via Local Thickness](1946-subsurface-scattering-approximation-via-local-thickness.md)
Approximates subsurface scattering by computing the local thickness of a surface along random inward hemispherical directions, then using the thickness to modulate a simplified SSS lighting term. It is chosen when full SSS simulation is too expensive but some translucency is desired. See [Subsurface Scattering Approximation via Local Thickness](1946-subsurface-scattering-approximation-via-local-thickness.md).

### [Aggressive Ray Marching with SDF](2326-aggressive-ray-marching-with-sdf.md)
Uses SDF values to dynamically determine step sizes, allowing large skips in empty space and fine-grained sampling near surfaces. It is distinguished by its use of a configurable `ray_marching_ratio` to scale the SDF-derived step size and its integration with neural implicit representations and explicit termination masks. See [Aggressive Ray Marching with SDF](2326-aggressive-ray-marching-with-sdf.md).

### [Coverage Search](2534-coverage-search.md)
A SDF raymarching algorithm designed to solve ray hit/miss in fewer iterations than sphere tracing by using a stack to manage coverage spans along the ray. It is chosen when exact hit/miss determination is prioritized over iterative approximation. See [Coverage Search](2534-coverage-search.md).

### [SDF-Accelerated Volumetric Ray Marching](3681-sdf-accelerated-volumetric-ray-marching.md)
Accelerates volumetric ray marching by using an SDF to skip large empty spaces. The SDF stores the distance to the nearest surface of the volume, allowing the ray to advance by that distance in empty space. See [SDF-Accelerated Volumetric Ray Marching](3681-sdf-accelerated-volumetric-ray-marching.md).

### [Adaptive SDF Ray Marching with Cell Acceleration](3714-adaptive-sdf-ray-marching-with-cell-acceleration.md)
Marches a ray through an SDF scene using an acceleration structure to skip empty space, adaptive step sizing, and sign-change detection for surface refinement. See [Adaptive SDF Ray Marching with Cell Acceleration](3714-adaptive-sdf-ray-marching-with-cell-acceleration.md).

### [SDF Ray Marching with Eikonal Correction](4598-sdf-ray-marching-with-eikonal-correction.md)
Marches a ray through an SDF field while applying a correction factor to counteract distance elongation along non-cardinal directions caused by the Eikonal equation. See [SDF Ray Marching with Eikonal Correction](4598-sdf-ray-marching-with-eikonal-correction.md).

### [Ray Marching with SDFs and Soft Accumulation](5001-ray-marching-with-sdfs-and-soft-accumulation.md)
Renders hair-thin strands (e.g., jellyfish tentacles) using SDFs combined with soft accumulation to anti-alias across frames. See [Ray Marching with SDFs and Soft Accumulation](5001-ray-marching-with-sdfs-and-soft-accumulation.md).

### Pre-marched Shadow and Ambient Occlusion Baking
A technique to improve visual fidelity and performance by pre-calculating shadow and ambient occlusion data into the volume texture, leveraging the static nature of the cloud volume [S3, unofficial]. It involves pre-marching a shadow ray through the volume (e.g., 4 shadow samples per cloud sample) and pre-marching ambient occlusion into the volume texture [S3, unofficial]. This allows dynamic time-of-day changes and runtime shadow lookup with a single 3D texture lookup, matching the cloud geometry perfectly [S3, unofficial].

## Operating characteristics
*   **Time Complexity:** Reduced by a factor proportional to the number of skipped steps (via early-outs and over-relaxation) and the reduction in pixel count (via resolution scaling) [S1, unofficial][S2, unofficial].
*   **Memory Complexity:** Minimal overhead, limited to the 3D volume texture for baked data [S3, unofficial].
*   **Measured Performance:** Rendering at half resolution is cited as the "most effective single optimisation for real-time SDF rendering at larger resolutions" [S1, unofficial][S2, unofficial].
*   **Strengths:** Simple to implement; significant FPS gains in real-time applications; effective for static scenes (baking) [S1, unofficial][S2, unofficial][S3, unofficial].
*   **Limitations:** Over-relaxation can cause artefacts near concave edges [S1, unofficial]. Baking is limited to static volumes [S3, unofficial]. LOD adjustments may reduce visual quality for distant objects if not tuned correctly [S1, unofficial][S2, unofficial].
*   **When to use:** Real-time rendering where frame rate is critical; static volumetric scenes; scenes with large empty spaces [S1, unofficial][S2, unofficial][S3, unofficial].
*   **When not to use:** Dynamic scenes requiring high-fidelity shadows without pre-computation; scenes with very thin geometry where over-relaxation causes overshooting [S1, unofficial].

## Background
The techniques described are derived from practical implementations of ray marching in real-time graphics, particularly in the context of SDF rendering and volumetric clouds [S1, unofficial][S2, unofficial][S3, unofficial]. The concepts of early-out bounding volumes, LOD, and resolution scaling are common in production graphics [S1, unofficial][S2, unofficial]. The specific application of pre-marching shadow and AO into volume textures for static clouds was detailed in a blog post by UHawkVR [S3, unofficial]. The term "sphere tracing" was introduced by John C. Hart in 1996 [S2, unofficial].
