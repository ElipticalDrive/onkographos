# SDF Ray Marching with Eikonal Correction

Also called: Eikonal-corrected ray marching, distance field ray marching with step correction

## Overview
This method marches a ray through a Signed Distance Field (SDF) to find surface intersections while applying a correction factor to counteract distance elongation along non-cardinal directions caused by the Eikonal equation [S1, unofficial]. It sets itself apart from standard SDF ray marching by explicitly scaling step sizes based on ray direction to prevent overshooting and jitter [S1, unofficial].

## How it works
**Inputs:**
- Ray origin $O$ and direction $D$ (normalized) [S1, unofficial].
- SDF field $SDF(x, y, z)$ [S1, unofficial].
- Maximum ray march steps $N_{max}$ (typical value: 128, range 8–512) [S1, unofficial].
- Hit threshold distance $\epsilon$ (implicit in `hitThreshold()`) [S1, unofficial].
- Progress multiplier $k$ (16.0 for ray origin march, 32.0 for shadow march) [S1, unofficial].
- Eikonal correction factor $C_{eikonal}$, computed from ray direction $D$ [S1, unofficial].

**Outputs:**
- Hit distance $t$ [G].
- Hit status flag [S1, unofficial].

**Data Structures:**
- The SDF is stored as a 3D texture or voxel grid, accessed via world-space coordinates mapped to texture coordinates [S1, unofficial].
- No additional complex data structures are required beyond standard ray parameters and SDF lookup [S1, unofficial].

**Algorithm Steps:**
1. Initialize current ray distance $t = 0.0$ and progress accumulator $res = 1.0$.
2. Loop up to $N_{max}$ iterations:
   a. Calculate current world position: $P = O + D \cdot t$.
   b. Check bounds: If $P$ is out of the SDF volume, return $0.0$ [S1, unofficial].
   c. Sample SDF: $d = SDF(P)$.
   d. Check hit: If $d \le \epsilon$, set hit position to $P$, set $res = 0.0$, and return $1.0$ [S1, unofficial].
   e. Apply Eikonal correction: Clamp $d$ to a minimum positive value ($0.0001$), then multiply by the correction factor: $d_{corrected} = \max(d, 0.0001) \cdot C_{eikonal}$ [S1, unofficial].
   f. Update progress: $res = \min(res, k \cdot d_{corrected} / t)$ [S1, unofficial].
   g. Advance ray: $t = t + d_{corrected}$ [S1, unofficial].
3. Return $1.0$ if the loop finishes without hitting [S1, unofficial].

**Formula:**
The core step advancement formula is:
$$ t_{new} = t_{old} + \max(d, 0.0001) \cdot C_{eikonal} $$
where $d$ is the raw SDF value at the current position, and $C_{eikonal}$ is the correction factor derived from the ray direction [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Distance Elongation:** The Eikonal equation causes distance values to be larger than the true Euclidean distance along non-cardinal directions, leading to larger step sizes than necessary [S1, unofficial]. The `eikonal_fix` factor corrects this [S1, unofficial].
- **Zero Distance:** If `dist` is 0 or negative, it is clamped to 0.0001 to prevent zero-step stalls [S1, unofficial].
- **Out of Bounds:** Rays leaving the SDF volume must be handled explicitly to avoid sampling errors [S1, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$, where $N$ is the number of ray march steps (up to `max_steps`) [G].
- **Memory Complexity:** $O(1)$ auxiliary memory, plus the SDF texture storage [G].
- **Performance:** The correction factor calculation adds minimal overhead; the main cost is SDF sampling [S1, unofficial]. The correction improves accuracy for non-cardinal rays but may increase step counts if the correction factor is large [S1, unofficial].
- **Strengths:** Improves accuracy of ray marching in SDFs, especially for rays not aligned with grid axes [S1, unofficial].
- **Limitations:** Requires a method to calculate the Eikonal correction factor, which is not detailed in the source [S1, unofficial].
- **When to use:** When high accuracy is required in SDF ray marching, particularly for non-axis-aligned rays [S1, unofficial].
- **When not to use:** If performance is critical and approximate results are acceptable, or if rays are always aligned with cardinal directions [G].

## Background
This method is part of the implementation of signed distance fields in Unity, as described in an unofficial GitHub repository by samuelbigos [S1, unofficial]. It addresses a known issue in SDF rendering where the Eikonal equation introduces directional bias in the distance values, which is corrected during ray marching to ensure accurate surface intersection detection [S1, unofficial].
