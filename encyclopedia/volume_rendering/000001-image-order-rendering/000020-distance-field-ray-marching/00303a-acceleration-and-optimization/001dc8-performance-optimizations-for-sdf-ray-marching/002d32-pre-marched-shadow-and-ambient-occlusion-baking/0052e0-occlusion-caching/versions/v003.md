# Occlusion Caching

Also called: Baking Occlusion

## Overview
Occlusion Caching is a performance optimization for volumetric lighting that pre-calculates shadow and ambient occlusion data into static volume textures, avoiding expensive per-frame camera renders for static lights and occluders [S2, unofficial]. It differs from real-time ray-marched shadows by trading visual accuracy for significant runtime cost reduction, storing occlusion information in spherical harmonics (SH) coefficients within dedicated "occlusion volumes" [S1].

## How it works
The method consists of two phases: a baking stage where occlusion data is captured and compressed, and a runtime decomposition stage where ambient occlusion is reconstructed for surface points.

### Inputs and Outputs
*   **Inputs:** Static light positions, static occluder geometry, camera parameters (for capture), and surface point position $\mathbf{x}$ with normal $\mathbf{n}$ (for runtime).
*   **Outputs:** Occlusion cubemaps $\{\hat{O}_p^i\}$ and SH coefficients $f_o^i$ stored in occlusion volumes $V_{occl}$ [S1].

### Data Structures
1.  **Occlusion Volumes ($V_{occl}$):** A set of spatial volumes $\{v_i^{occl}\}$ distributed in the scene. Each volume $v_i^{occl}$ contains:
    *   Position vector $\mathbf{p}_i$.
    *   Spherical Harmonics coefficients $f_o^i$ representing the principal components of occlusion [S1].
2.  **Occlusion Cubemaps ($\hat{O}_p^i$):** For each volume $v_i^{occl}$, six cubemap faces $\{\hat{O}_p^i\}_{p=1}^6$ are generated [S1].

### Steps

#### 1. Baking Stage
1.  **Initialize Capture Cameras:** For each occlusion volume $v_i^{occl}$, set up six cameras with a 90-degree Field of View (FoV). These cameras must be non-overlapping and oriented to cover the full sphere [S1].
2.  **Render Depth:** Perform six render passes to obtain depth cubemaps $\{\hat{D}_p^i\}_{p=1}^6$ from the perspective of the six cameras [S1].
3.  **Convert to Occlusion:** Convert the depth cubemaps $\{\hat{D}_p^i\}_{p=1}^6$ into occlusion cubemaps $\{\hat{O}_p^i\}_{p=1}^6$ [S1].
4.  **Compute SH Coefficients:** Store the principal components of the occlusion data from the cubemaps into SH coefficients $f_o^i$ associated with volume $v_i^{occl}$ [S1].

#### 2. Runtime Decomposition
To recover ambient occlusion (AO) for a surface point $\mathbf{x}$ with normal $\mathbf{n}$:

1.  **Find Neighbors:** Identify the eight nearest occlusion volumes $\{v_k\}_{k=1}^8$ to point $\mathbf{x}$. Let $\mathbf{p}_k$ be the position vector of volume $v_k$ and $f_k^o$ be its SH coefficients [S1].
2.  **Calculate Masked Weights:** Compute masked trilinear interpolation weights $\tilde{w}_k$ for each neighbor. Let $w_k$ be the standard trilinear interpolation weight [S1]:
    $$
    \tilde{w}_k = 
    \begin{cases} 
    0 & \text{if } (\mathbf{p}_k - \mathbf{x}) \cdot \mathbf{n} \le 0 \\
    w_k & \text{if } (\mathbf{p}_k - \mathbf{x}) \cdot \mathbf{n} > 0 
    \end{cases}
    $$
    This mask ensures that only occlusion from the upper hemisphere relative to the surface normal contributes to the AO calculation [S1].
3.  **Normalize Weights:** Compute the sum of masked weights:
    $$
    \hat{w}_k = \frac{\tilde{w}_k}{\sum_{j=1}^8 \tilde{w}_j}
    $$
    *(Note: The source defines $\hat{w}_k$ in Eq. 20 context, implying normalization is required for valid interpolation)* [S1].
4.  **Interpolate Coefficients:** Calculate the final SH coefficients $f_x^o$ for point $\mathbf{x}$:
    $$
    f_x^o = \sum_{k=1}^8 \hat{w}_k f_k^o
    $$
    *(Note: Source Eq. 21 shows $f_x^o = \sum \hat{w}_k f_k^o$)* [S1].
5.  **Reconstruct Occlusion:** Use the interpolated SH coefficients $f_x^o$ to reconstruct the occlusion value $O(\omega)$ for a direction $\omega$ [S1].

### Parameters
*   **Bake Interval:** Controls caching behavior.
    *   `On Start`: Captures once at start; re-captures if light moves or rotates (unless Ignore Rotation is enabled) [S2, unofficial].
    *   `Every Frame`: Continuous capture [S2, unofficial].
*   **Shadow Resolution:** Resolution of the capture cubemaps (e.g., 512x512) [S2, unofficial].
*   **Check Time Interval:** Frequency of Auto Toggle distance checks. Default: 1 second [S2, unofficial].
*   **Ignore Rotation:** Boolean. If enabled with `On Start`, rotating the light does not trigger re-capture; the map is reprojected [S2, unofficial].

### Edge Cases and Pitfalls
*   **Rotation Handling:** If `Ignore Rotation` is disabled, any rotation of the light triggers a full re-capture, increasing cost [S2, unofficial].
*   **Visibility:** Capture is suspended when the light volume is not visible to any camera [S2, unofficial].
*   **Distance Culling:** Auto Toggle disables occlusion for lights beyond a specified distance from the target camera to save performance [S2, unofficial].
*   **Masking Degeneracy:** If all eight neighbors have $(\mathbf{p}_k - \mathbf{x}) \cdot \mathbf{n} \le 0$, the sum of weights is zero, leading to division by zero in normalization. Implementation must handle this case (e.g., fallback to zero AO or nearest neighbor) [G].

### Pseudocode

```python
def bake_occlusion_volume(volume_pos, occluders, num_faces=6):
    """
    Bakes occlusion data for a single volume.
    Returns SH coefficients f_o.
    """
    # 1. Set up six cameras with 90-degree FoV, non-overlapping
    cameras = create_cubemap_cameras(fov=90.0)
    
    # 2. Render depth cubemaps
    depth_cubemaps = []
    for cam in cameras:
        # Render scene with occluders from cam's perspective
        depth_map = render_depth(cam, occluders)
        depth_cubemaps.append(depth_map)
        
    # 3. Convert depth to occlusion cubemaps
    occlusion_cubemaps = [convert_depth_to_occlusion(d) for d in depth_cubemaps]
    
    # 4. Compute SH coefficients from occlusion cubemaps
    # This step compresses the cubemap data into SH coefficients
    f_o = compute_sh_coefficients(occlusion_cubemaps)
    
    return f_o

def decompose_occlusion(point_x, normal_n, occlusion_volumes):
    """
    Recovers ambient occlusion for a surface point.
    Returns reconstructed occlusion value.
    """
    # 1. Find 8 nearest occlusion volumes
    neighbors = find_k_nearest(point_x, occlusion_volumes, k=8)
    
    # 2. Calculate masked trilinear weights
    masked_weights = []
    for vol in neighbors:
        p_k = vol.position
        f_k = vol.sh_coefficients
        
        # Standard trilinear weight w_k (implementation depends on spatial layout)
        w_k = compute_trilinear_weight(point_x, p_k, neighbors)
        
        # Masking: only consider upper hemisphere relative to normal
        if dot(p_k - point_x, normal_n) <= 0:
            w_tilde = 0
        else:
            w_tilde = w_k
            
        masked_weights.append((w_tilde, f_k))
        
    # 3. Normalize weights
    sum_weights = sum(w for w, _ in masked_weights)
    
    # Handle degenerate case where sum_weights is 0
    if sum_weights == 0:
        return 0.0 # Or fallback logic
        
    # 4. Interpolate SH coefficients
    f_x = [0.0] * len(masked_weights[0][1]) # Assuming SH degree is fixed
    for w_tilde, f_k in masked_weights:
        w_hat = w_tilde / sum_weights
        for i in range(len(f_x)):
            f_x[i] += w_hat * f_k[i]
            
    # 5. Reconstruct occlusion from SH coefficients
    # This step evaluates the SH function for specific directions
    occlusion_value = evaluate_sh_occlusion(f_x)
    
    return occlusion_value
```

## Subtopics

### Masked-Trilinear Interpolation for AO
A variant of the decomposition step that modifies standard trilinear interpolation to respect surface orientation. It sets the interpolation weight $\tilde{w}_k$ to zero if the vector from the sample point $\mathbf{x}$ to the volume center $\mathbf{p}_k$ forms an angle greater than or equal to 90 degrees with the surface normal $\mathbf{n}$ (i.e., $(\mathbf{p}_k - \mathbf{x}) \cdot \mathbf{n} \le 0$) [S1]. This ensures that ambient occlusion is only calculated from the upper hemisphere, preventing occlusion from "below" the surface from affecting the result [S1].

## Operating characteristics
*   **Time Complexity:** Baking is $O(N \cdot F)$ where $N$ is the number of occlusion volumes and $F$ is the number of faces (6) [S1]. Runtime decomposition is $O(1)$ per point, involving a fixed number of neighbors (8) and SH evaluations [S1].
*   **Memory Complexity:** $O(N \cdot D)$ where $D$ is the dimension of the SH basis [S1].
*   **Performance:** Significantly reduces runtime cost for static scenes by eliminating per-frame shadow renders for static lights [S2, unofficial].
*   **Strengths:** Ideal for static lights and occluders (e.g., windows, street lamps) [S2, unofficial]. Supports event-driven updates for dynamic occluders (e.g., doors) [S2, unofficial].
*   **Limitations:** Less accurate than real-time ray-marched shadows. Requires baking time. Rotation handling can be costly if not ignored [S2, unofficial].
*   **When to Use:** Static volumetric lights with static or infrequently changing occluders [S2, unofficial].
*   **When Not to Use:** Highly dynamic scenes with constantly moving occluders (e.g., fans, characters) where `Every Frame` baking is required, or where high-fidelity dynamic shadows are critical [S2, unofficial].

## Background
Occlusion caching in volumetric lighting was introduced to address the performance bottleneck of per-frame shadow rendering for volumetric lights [S2, unofficial]. The technique of storing occlusion in occlusion volumes and using SH coefficients for decomposition was proposed in the context of 3D Gaussian Splatting for Inverse Rendering (GS-IR) [S1]. Unity's Volumetric Lighting package in URP implements a practical version of this caching strategy, providing settings like `Bake Interval` and `Ignore Rotation` to manage the trade-off between accuracy and performance [S2, unofficial].
