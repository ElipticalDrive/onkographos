# Occlusion Caching

Also called: Baking Occlusion

## Overview
Occlusion Caching is a performance optimization for volumetric lighting that pre-calculates shadow and ambient occlusion data into static volume textures, avoiding expensive per-frame camera renders for static lights and occluders [S2, unofficial][S1]. It sets itself apart from real-time ray-marched shadows by trading immediate dynamic accuracy for significant runtime cost reduction, storing occlusion data in spherical harmonics (SH) coefficients within dedicated volumes [S1].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Static or semi-static light source (position, orientation, type), scene geometry (occluders), and camera configuration.
*   **Outputs:** Occlusion volumes ($V_{occl}$) containing SH coefficients ($f_o$) representing ambient occlusion, and potentially translucency maps if enabled [S1][S2, unofficial].

**Data Structures:**
*   **Occlusion Volume ($v_i^{occl}$):** A spatial partition in the scene. Each volume stores principal components of occlusion as SH coefficients ($f_o^i$) [S1].
*   **Depth Cubemap ($\hat{D}_p^i$):** For each volume $v_i^{occl}$, six depth cubemaps are generated, one for each face $p \in \{1, ..., 6\}$ [S1].
*   **Occlusion Cubemap ($\hat{O}_p^i$):** Derived from depth cubemaps, representing the occlusion state for each face [S1].

**Steps:**

1.  **Baking Stage Initialization:**
    *   Create occlusion volumes $V_{occl}$ for the light source [S1].
    *   Determine the `Bake Interval` setting: `On Start` or `Every Frame` [S2, unofficial].
    *   If `On Start`: Render the capture for a few frames, then turn off the capture camera and keep the result. If the light moves or rotates, trigger a re-capture [S2, unofficial].
    *   If `Every Frame`: Continuously capture [S2, unofficial].

2.  **Capture Process (per volume $v_i^{occl}$):**
    *   Set up six cameras with a 90-degree Field of View (FoV), non-overlapping, oriented to cover the full sphere [S1].
    *   Perform six render passes to obtain depth cubemaps $\{\hat{D}_p^i\}_{p=1}^6$ [S1].
    *   Convert depth cubemaps $\{\hat{D}_p^i\}$ into occlusion cubemaps $\{\hat{O}_p^i\}$ [S1].
    *   Store the principal components of occlusion into SH coefficients $f_o^i$ [S1].
    *   *Optimization:* If `Cubemap One Face Per Frame` is enabled, spread the six cubemap faces over six frames [S2, unofficial].
    *   *Optimization:* If `Point Light Half Sphere To Camera` is enabled, re-capture only when the camera direction changes by more than 45 degrees [S2, unofficial].
    *   *Optimization:* Suspend capture if the light volume is not visible to any camera [S2, unofficial].
    *   *Optimization:* If `Ignore Rotation` is enabled (On Start only), rotating the light does not trigger re-capture; the map is reprojected [S2, unofficial].

3.  **Runtime Decomposition (for a point $x$ with normal $n$):**
    *   Find the eight nearest occlusion volumes $\{v_k\}_{k=1}^8$ to point $x$ [S1].
    *   Let $p_k$ be the position vector of volume $v_k$ and $f_k^o$ be its SH coefficients [S1].
    *   Calculate masked trilinear interpolation weights $\tilde{w}_k$:
        $$
        \tilde{w}_k = \begin{cases} 
        0, & (p_k - x) \cdot n \le 0 \\
        w_k, & (p_k - x) \cdot n > 0 
        \end{cases}
        $$
        where $w_k$ are the standard trilinear interpolation weights [S1].
    *   Normalize weights: $\hat{w}_k = \frac{\tilde{w}_k}{\sum_{j=1}^8 \tilde{w}_j}$ [S1].
    *   Interpolate SH coefficients:
        $$
        f_x^o = \sum_{k=1}^8 \hat{w}_k f_k^o
        $$
        [S1]

4.  **Update Triggers:**
    *   **Event-Driven:** Call `ScheduleShadowCapture()` to refresh a cached map when external changes occur (e.g., a door opens) [S2, unofficial].
    *   **Auto Toggle:** Disable occlusion for lights beyond a specified `Distance` from the target camera. The distance is measured to the camera in the `Target Camera` field, or to the main camera if empty. This check occurs every `Check Time Interval` (default 1 second) [S2, unofficial].

**Pseudocode:**
```python
# Setup
vl.enable_shadows = True
vl.shadow_bake_interval = ShadowBakeInterval.ON_START
vl.shadow_resolution = ShadowResolution._512
vl.update_material_properties()

# Runtime: Event-driven update (e.g., door opens)
def on_door_opened():
    vl.schedule_shadow_capture()

# Runtime: Decomposition for point x with normal n
def get_occlusion_coefficients(x, n, occlusion_volumes):
    # Find 8 nearest volumes
    nearest_volumes = find_8_nearest(x, occlusion_volumes)
    
    total_weight = 0.0
    interpolated_coeffs = [0.0] * 10 # Assuming 10 SH coefficients
    
    for v in nearest_volumes:
        p_k = v.position
        f_k = v.sh_coefficients
        
        # Calculate standard trilinear weight w_k
        w_k = calculate_trilinear_weight(x, p_k, v.bounds)
        
        # Masked weight
        dot_product = dot(p_k - x, n)
        if dot_product <= 0:
            w_tilde = 0.0
        else:
            w_tilde = w_k
            
        total_weight += w_tilde
        
        # Accumulate weighted coefficients
        for i in range(len(f_k)):
            interpolated_coeffs[i] += w_tilde * f_k[i]
            
    # Normalize
    if total_weight > 0:
        for i in range(len(interpolated_coeffs)):
            interpolated_coeffs[i] /= total_weight
            
    return interpolated_coeffs
```

**Parameters:**
*   `Bake Interval`: `On Start` or `Every Frame` [S2, unofficial].
*   `Check Time Interval`: Frequency of Auto Toggle distance checks. Default: 1 second [S2, unofficial].
*   `Shadow Resolution`: Resolution of the capture cubemaps. Example: `_512` [S2, unofficial].
*   `Distance`: Threshold for Auto Toggle [S2, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** SH approximation may lose high-frequency occlusion details [S1].
*   **Boundaries:** Masked interpolation ensures occlusion is only calculated for the upper hemisphere relative to the surface normal [S1].
*   **Degenerate Input:** If no occlusion volumes are found near $x$, the result is undefined or zero [G].

## Subtopics

### Masked-Trilinear Interpolation for AO
A variant of the decomposition step where trilinear interpolation weights are masked based on the surface normal. For a point $x$ with normal $n$, and eight nearest occlusion volumes $\{v_k\}$ with positions $\{p_k\}$, the weight $\tilde{w}_k$ is zero if $(p_k - x) \cdot n \le 0$, otherwise it is the standard trilinear weight $w_k$ [S1]. This ensures that occlusion is only integrated from the hemisphere visible to the surface normal [S1].

## Operating characteristics
*   **Time Complexity:** Baking is $O(N)$ where $N$ is the number of occlusion volumes and faces. Runtime decomposition is $O(1)$ per point, requiring only 8 nearest neighbor lookups and interpolation [S1][S2, unofficial].
*   **Memory Complexity:** $O(V \cdot C)$ where $V$ is the number of occlusion volumes and $C$ is the number of SH coefficients per volume [S1].
*   **Measured Performance:** For static lights and occluders, runtime cost drops to near zero after the initial capture [S2, unofficial]. For moving occluders, cost is one capture per frame while visible [S2, unofficial].
*   **Strengths:** Significant performance improvement for static scenes; supports event-driven updates for dynamic elements [S2, unofficial].
*   **Limitations:** Less accurate for highly dynamic scenes; SH approximation may blur sharp shadows [S1][S2, unofficial].
*   **When to Use:** Static lights, static occluders, or lights with infrequent movement [S2, unofficial].
*   **When Not to Use:** Highly dynamic scenes with constantly moving occluders where real-time accuracy is critical [S2, unofficial].

## Background
Occlusion caching in volumetric lighting was introduced in the GS-IR paper (2024) as part of a 3D Gaussian Splatting for Inverse Rendering framework, using SH architectures to cache occlusion into volumes [S1]. Unity's Volumetric Lighting in URP also implements similar baking techniques, allowing developers to optimize shadow rendering for static lights [S2, S2, unofficial].
