# SDF Texture Baking for Ray Marching

Also called: 3D SDF Baking for Cloud Sphere Tracing, Cloud SDF texture baking, Conservative SDF proxy for raymarching

## Overview
This method optimizes cloud raymarching by baking a low-resolution 3D Signed Distance Field (SDF) texture that acts as a conservative proxy for the analytical cloud SDF [S1, unofficial]. It allows the marching loop to skip empty space conservatively before falling back to analytical evaluations inside active cells [S1, unofficial]. Unlike sibling methods that modify the ray step size or accumulation logic directly, this approach offloads the distance estimation to a pre-computed texture lookup, reducing the computational cost of the analytical SDF evaluation during the main rendering pass [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** Dynamic cloud parameters (e.g., position, scale, density fields) and the analytical cloud SDF function.
*   **Output:** A 3D texture (`_cloudSdf3DTexture`) containing the baked SDF values.

**Data Structures:**
*   `_cloudSdf3DTexture`: A 3D texture allocated in `AtmosphereManager`.
    *   **Resolution:** $128 \times 32 \times 128$ (width $\times$ height $\times$ depth) [S1, unofficial].
    *   **Format:** `GL_R32F` (single-channel 32-bit floating point) [S1, unofficial].
    *   **Binding:** Texture Unit 45 [S1, unofficial].
    *   **Wrapping:** `GL_REPEAT` horizontally (S and T axes), `GL_CLAMP_TO_EDGE` vertically (R axis) [S1, unofficial].
    *   **Layered Flag:** `GL_TRUE` [S1, unofficial].

**Numbered Steps:**

1.  **Bake SDF Texture:**
    *   A compute shader (`cloud_3d_sdf_bake.comp`) is dispatched to analytically bake the lofted cloud SDF into the 3D texture [S1, unofficial].
    *   The baking uses **unadvected coordinates** to ensure the SDF represents the cloud geometry in its local space before transformation [S1, unofficial].
    *   This dispatch occurs every frame in `AtmosphereManager::Update` to maintain synchrony with dynamic cloud parameters and resolve initialization frame order issues [S1, unofficial].

2.  **Optimize Ray Marching Loop:**
    *   In the rendering compute shader (`atmosphere_lowres.comp`), the raymarching loop is modified [S1, unofficial].
    *   **Conservative Skip:** The loop first samples the `_cloudSdf3DTexture` at the current ray position. If the sampled SDF value indicates empty space (distance to surface > current step size or threshold), the ray is advanced conservatively by that distance [S1, unofficial].
    *   **Analytical Fallback:** Full analytical SDF evaluations are performed **only** inside active cells where the texture indicates the presence of cloud matter (i.e., when the ray is close to the surface or inside the cloud) [S1, unofficial].

**Pseudocode:**

```python
# cloud_3d_sdf_bake.comp (Compute Shader)
# Dispatched every frame in AtmosphereManager::Update
# Invocations cover the 128x32x128 volume

void main() {
    ivec3 texelCoord = ivec3(gl_GlobalInvocationID);
    
    // Convert texel coordinate to unadvected world/local space position
    // Assuming texture bounds map to the cloud's bounding box
    vec3 pos = texelCoordToPosition(texelCoord); 
    
    // Evaluate the analytical lofted cloud SDF at this position
    // 'cloudParams' are passed as uniforms
    float sdfValue = evaluateAnalyticalCloudSDF(pos, cloudParams);
    
    // Write to the 3D texture (GL_R32F)
    // The texture is bound to a storage image or uniform buffer depending on implementation
    cloudSdfTexture[texelCoord] = sdfValue;
}

# atmosphere_lowres.comp (Rendering Compute Shader)
// Raymarching loop optimization

void main() {
    vec3 rayOrigin = ...; // Camera ray origin
    vec3 rayDir = ...;    // Camera ray direction
    float t = 0.0;
    float maxDist = ...;
    
    while (t < maxDist) {
        vec3 currentPos = rayOrigin + rayDir * t;
        
        // 1. Sample the baked 3D SDF texture
        // Texture coordinates must be mapped from currentPos to [0,1] range
        vec3 texCoords = positionToTexCoords(currentPos);
        
        // Clamp to handle boundary conditions if necessary
        // Note: Horizontal wrapping is GL_REPEAT, Vertical is GL_CLAMP_TO_EDGE
        float bakedSdf = texture(cloudSdfTexture, texCoords).r;
        
        // 2. Conservative Skip
        // If the baked SDF indicates we are far from the cloud, skip ahead
        // 'bakedSdf' is the distance to the nearest cloud surface
        if (bakedSdf > t) {
            // This condition implies the ray is outside the cloud volume
            // and the distance to the surface is greater than the current t.
            // However, standard sphere tracing uses the SDF value as the step size.
            // To skip empty space conservatively, we advance by the SDF value.
            // If bakedSdf is large, we jump far.
            t += bakedSdf;
            continue;
        }
        
        // 3. Analytical Fallback
        // If we are close to the surface (bakedSdf <= t) or inside,
        // perform the full analytical evaluation for accuracy.
        float analyticalSdf = evaluateAnalyticalCloudSDF(currentPos, cloudParams);
        
        // Use the analytical SDF for the step size to ensure precision
        // near the surface and for density sampling
        t += analyticalSdf;
        
        // Check for intersection or density threshold
        if (analyticalSdf <= 0.0 || density(currentPos) > threshold) {
            break;
        }
    }
}
```

**Parameters:**
*   **Texture Resolution:** $128 \times 32 \times 128$ [S1, unofficial].
*   **Texture Format:** `GL_R32F` [S1, unofficial].
*   **Texture Unit:** 45 [S1, unofficial].
*   **Update Frequency:** Every frame [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision Loss:** The low resolution ($128 \times 32 \times 128$) may lead to inaccurate distance estimates for thin cloud features, potentially causing the ray to skip over small details or intersect the surface prematurely [S1, unofficial].
*   **Boundary Conditions:** The vertical wrapping mode is `GL_CLAMP_TO_EDGE`, which must be handled correctly in texture coordinate mapping to avoid artifacts at the top and bottom of the cloud volume [S1, unofficial].
*   **Synchronization:** The bake shader must be dispatched before the rendering shader samples the texture. This is managed by dispatching in `AtmosphereManager::Update` to solve initialization frame order issues [S1, unofficial].
*   **Unadvected Coordinates:** The baking uses unadvected coordinates, meaning the texture represents the cloud in its local space. The raymarching loop must correctly transform the ray position to this local space before sampling [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** The baking step is $O(N)$ where $N$ is the number of texels ($128 \times 32 \times 128 = 524,288$) [S1, unofficial]. This is performed every frame. The raymarching loop is accelerated by skipping empty space, reducing the number of analytical SDF evaluations [S1, unofficial].
*   **Memory Complexity:** The texture requires $128 \times 32 \times 128 \times 4$ bytes $\approx 2$ MB of VRAM [S1, unofficial].
*   **Performance:** The method was validated with unit tests and shader validations passing 100% [S1, unofficial]. It optimizes cloud sphere tracing by reducing the computational load of the analytical SDF evaluation during the main rendering pass [S1, unofficial].
*   **Strengths:** Reduces the number of expensive analytical SDF evaluations per ray. Simple to implement as a texture lookup.
*   **Limitations:** Introduces a fixed memory overhead. The low resolution may not capture fine cloud details accurately. Requires frequent rebaking for dynamic clouds.
