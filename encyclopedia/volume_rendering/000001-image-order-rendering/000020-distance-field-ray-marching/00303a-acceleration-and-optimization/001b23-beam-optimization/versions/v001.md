# Beam Optimization

Also called: Beam Optimization for Primary Rays, Ray Batching, Ray Grouping Optimization

## Overview
Beam Optimization is an acceleration technique for primary rays in distance-field ray marching that groups adjacent rays into beams to reduce redundant intersection tests [S1][S2, unofficial]. By marching a group of rays together along a central path, the method exploits spatial coherence: if the distance to the nearest geometry is large relative to the group's spatial extent, all rays in the group can advance simultaneously without individual checks [S2, unofficial]. This reduces the number of scene queries for rays far from geometry, at the cost of potential over-stepping or splitting when rays diverge near surfaces [S2, unofficial].

## How it works
**Inputs:** A rectangular grid of primary rays (pixels), a Signed Distance Function (SDF) evaluator, and a beam size parameter (typically $8 \times 8$ pixels) [S1][S2, unofficial].
**Outputs:** Hit distances or visibility flags for each pixel.

**Data Structures:**
*   **Beam:** A 2D block of pixels defined by top-left coordinate $(x, y)$ and dimensions $(w, h)$.
*   **Ray State:** For each pixel, stores current position $\mathbf{p}$, direction $\mathbf{d}$, and accumulated distance $t$.

**Algorithm:**
1.  **Initialization:** Divide the image into non-overlapping beams of size $W \times H$ (default $8 \times 8$) [S1]. Initialize all rays with $t=0$ and $\mathbf{p} = \text{origin} + t \cdot \mathbf{d}$ [G].
2.  **Marching Loop:** While there are active beams:
    a.  **Central March:** For each active beam, compute the SDF value $d_{center}$ at the center pixel's current position [S2, unofficial].
    b.  **Step Size:** Advance the center ray by $t_{step} = d_{center}$ [S2, unofficial]. Update the center ray's position $\mathbf{p}_{center} \leftarrow \mathbf{p}_{center} + t_{step} \cdot \mathbf{d}_{center}$.
    c.  **Collision Check:** Calculate the maximum possible deviation of any ray in the beam from the center ray after the step. Let $R_{beam}$ be the radius of the beam's spatial extent (approx. $\max(w, h) \cdot \text{pixel\_pitch}$) [S2, unofficial]. If $d_{center} > R_{beam}$, the beam is safe to advance without splitting because no ray in the group can have hit geometry yet [S2, unofficial].
    d.  **Splitting:** If $d_{center} \le R_{beam}$, the beam might contain rays intersecting geometry. Split the beam into four sub-beams (quadrants) [S2, unofficial].
    e.  **Discard:** If a beam has stepped far enough into the scene such that its minimum possible distance to geometry exceeds the maximum ray length, discard it [S2, unofficial].
    f.  **Termination:** If a sub-beam contains only one ray and that ray has hit an object (SDF value $\le \epsilon$), mark the pixel as hit and remove the beam from the active list [S2, unofficial].
3.  **Repeat:** Process the new set of sub-beams.

**Pseudocode:**
```python
def beam_optimization(rays, beam_size=8, max_steps=100):
    # rays: list of Ray objects, each with position, direction, t, hit
    # Initialize beams
    beams = create_beams(rays, beam_size)
    
    while beams:
        next_beams = []
        for beam in beams:
            # Get center ray of the beam
            center_ray = beam.get_center_ray()
            
            # March center ray
            dist = sdf(center_ray.position)
            if dist <= 0:
                # Hit detected for center, likely need split or individual trace
                # For simplicity, split if not already single
                if len(beam.rays) > 1:
                    next_beams.extend(split_beam(beam))
                else:
                    center_ray.hit = True
                    center_ray.t += dist
                continue
            
            # Calculate beam spatial radius
            # Assuming uniform pixel pitch and direction spread
            beam_radius = calculate_beam_radius(beam)
            
            if dist > beam_radius:
                # Safe to advance all rays in beam by dist
                for ray in beam.rays:
                    ray.position += ray.direction * dist
                    ray.t += dist
                # Beam remains intact, no split needed
                # Note: In a strict implementation, we might keep it in 'beams' 
                # for next iteration if not finished, or mark as 'advanced'
                # Here we assume we re-evaluate in next loop or keep in queue
                # To avoid infinite loop, we process and remove if done
                if is_beam_done(beam):
                    pass # Discard
                else:
                    next_beams.append(beam)
            else:
                # Potential collision, split
                if len(beam.rays) == 1:
                    # Single ray, handle individually
                    ray = beam.rays[0]
                    ray.position += ray.direction * dist
                    ray.t += dist
                    if ray.hit:
                        pass # Done
                    else:
                        next_beams.append(beam)
                else:
                    next_beams.extend(split_beam(beam))
        
        beams = next_beams
    return rays

def split_beam(beam):
    # Split 2D beam into 4 quadrants
    w, h = beam.width, beam.height
    mid_x, mid_y = beam.x + w // 2, beam.y + h // 2
    sub_beams = []
    sub_beams.append(create_beam(beam.x, beam.y, w // 2, h // 2))
    sub_beams.append(create_beam(beam.x + w // 2, beam.y, w - w // 2, h // 2))
    sub_beams.append(create_beam(beam.x, beam.y + h // 2, w // 2, h - h // 2))
    sub_beams.append(create_beam(beam.x + w // 2, beam.y + h // 2, w - w // 2, h - h // 2))
    return sub_beams
```

**Parameters:**
*   **Beam Size:** $8 \times 8$ pixels is a common default [S1]. Larger beams reduce overhead but increase split frequency near geometry.

**Edge Cases:**
*   **Precision:** Floating-point errors in SDF evaluation can cause rays to oscillate or miss intersections near the threshold [G].
*   **Boundaries:** Rays near the edge of the image must be handled to avoid out-of-bounds beam creation [G].

## Subtopics

### Beam Optimization for Soft Shadows
An extension of beam optimization applied to shadow ray tracing [S1]. Instead of primary rays, beams are shot from the view-sample position to the area light [S1].
*   **Method:** Shoot a beam of four rays per pixel from the view-sample to the light [S1]. Find the conservative furthest distance along these rays where no geometry is intersected [S1]. Shorten all shadow rays for that pixel by this distance [S1]. Trace the same beam rays in reverse (from light to view) to find a conservative interval where geometry *may* be intersected [S1].
*   **Benefit:** Improves traversal speed of shadow rays and allows discarding pixels whose entire beams have no intersection with geometry, requiring no additional shadow rays [S1].

## Operating characteristics
*   **Time Complexity:** Reduces the number of SDF evaluations for rays far from geometry. Complexity is roughly $O(N \cdot \frac{1}{k})$ where $k$ is the beam size factor, but degrades to $O(N)$ near complex geometry due to frequent splitting [S2, unofficial].
*   **Memory Complexity:** Low overhead, only requiring storage for beam metadata [S1].
*   **Strengths:** Significant speedup for primary rays in scenes with large empty spaces [S1][S2, unofficial].
*   **Limitations:** Inefficient for scenes with high-frequency geometry or where rays are frequently occluded, as splitting overhead dominates [S2, unofficial].
*   **When to Use:** Best for primary rays in large, sparse scenes [S1]. Less effective for secondary rays (shadows, reflections) unless adapted as in the soft shadow variant [S1].

## Background
Beam optimization was introduced by Laine and Karras in 2010 for high-resolution sparse voxel DAGs [S1]. It builds on the concept of ray grouping to leverage the coherence of primary rays in rasterization-based rendering pipelines [S1]. The technique is particularly relevant in the context of distance-field ray marching, where sphere tracing is the standard traversal method [S2, unofficial].
