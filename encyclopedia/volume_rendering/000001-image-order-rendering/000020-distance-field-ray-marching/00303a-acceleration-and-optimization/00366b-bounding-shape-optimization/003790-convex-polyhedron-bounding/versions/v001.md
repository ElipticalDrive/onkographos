# Convex Polyhedron Bounding
Also called: PARC (Polygon assisted ray casting)
## Overview
Convex Polyhedron Bounding is a bounding shape optimization technique that constructs a convex polyhedron around volumetric objects to enable efficient space-leaping during ray traversal [S1, unofficial]. Unlike standard bounding boxes which provide loose axis-aligned approximations, this method creates a tighter geometric enclosure, reducing the number of density evaluations in empty space for scenes with few distinct objects [S1, unofficial]. It serves as a specialized variant of Bounding Shape Optimization tailored for complex object geometries where axis-aligned bounds are insufficient.
## How it works
**Inputs and Outputs:**
- Input: A set of voxels defining one or more volumetric objects.
- Output: A convex polyhedron (defined by its vertices and faces) enclosing the object(s), used to accelerate ray traversal.

**Data Structures:**
- **Convex Polyhedron:** Defined by a set of vertices $V$ and a set of planar faces $F$. Each face $f \in F$ is defined by a normal vector $\mathbf{n}_f$ and a distance $d_f$ from the origin, such that for any point $\mathbf{p}$ on the face, $\mathbf{n}_f \cdot \mathbf{p} = d_f$. The interior is defined by $\mathbf{n}_f \cdot \mathbf{p} \le d_f$ for all $f$.
- **Ray:** Defined by origin $\mathbf{o}$ and direction $\mathbf{d}$.

**Steps:**
1. **Object Identification:** Identify the voxels belonging to the target object(s) within the volume dataset [S1, unofficial].
2. **Convex Hull Construction:** Compute the convex hull of the identified object voxels. This involves determining the minimal convex polyhedron that encloses all occupied voxels [S1, unofficial].
   - [G] Standard convex hull algorithms (e.g., QuickHull, Gift Wrapping) are used to determine the vertices and faces.
3. **Polyhedron Representation:** Store the resulting polyhedron as a list of faces with their associated plane equations [S1, unofficial].
4. **Ray Traversal with Bounding:**
   - For each ray, first test intersection with the convex polyhedron.
   - If the ray does not intersect the polyhedron, skip all density evaluations for that ray (space-leaping) [S1, unofficial].
   - If the ray intersects, perform standard ray marching within the polyhedron bounds, potentially using the polyhedron faces to cull further empty space if the marching algorithm supports it.

**Formulas:**
- Ray-Plane Intersection: For a face with normal $\mathbf{n}$ and distance $d$, the intersection parameter $t$ is:
  $$ t = \frac{d - \mathbf{n} \cdot \mathbf{o}}{\mathbf{n} \cdot \mathbf{d}} $$
  The ray intersects the half-space if $t \ge 0$ and $\mathbf{n} \cdot (\mathbf{o} + t\mathbf{d}) \le d$. The ray intersects the polyhedron if it intersects all half-spaces defined by the faces.

**Parameters:**
- Not given in the sources.

**Edge Cases and Pitfalls:**
- **Precision:** Numerical precision issues may arise when computing the convex hull or ray-plane intersections, especially for thin or flat objects.
- **Complexity:** Computing the convex hull can be computationally expensive for large numbers of voxels.
- **Degenerate Input:** Objects with no volume or single-voxel objects may result in degenerate polyhedra.

**Pseudocode:**
```python
def compute_convex_polyhedron(voxels):
    """
    Compute the convex hull of a set of voxel centers.
    voxels: List of 3D coordinates (x, y, z) of occupied voxel centers.
    Returns: List of faces, where each face is a tuple (normal, distance).
    """
    # [G] Use a standard convex hull algorithm (e.g., QuickHull)
    # to compute the convex hull of the input points.
    hull = compute_hull(voxels)
    faces = []
    for face in hull.faces:
        # Compute plane equation from face vertices
        v0, v1, v2 = face.vertices
        normal = cross(v1 - v0, v2 - v0)
        normal = normalize(normal)
        distance = dot(normal, v0)
        faces.append((normal, distance))
    return faces

def ray_intersects_polyhedron(ray_origin, ray_direction, polyhedron_faces):
    """
    Test if a ray intersects a convex polyhedron.
    ray_origin: 3D coordinate (x, y, z)
    ray_direction: 3D vector (x, y, z)
    polyhedron_faces: List of (normal, distance) tuples
    Returns: Boolean
    """
    t_min = -infinity
    t_max = infinity
    for normal, distance in polyhedron_faces:
        denom = dot(normal, ray_direction)
        if abs(denom) < epsilon:
            # Ray is parallel to the plane
            if dot(normal, ray_origin) > distance:
                return False
        else:
            t = (distance - dot(normal, ray_origin)) / denom
            if denom > 0:
                t_min = max(t_min, t)
            else:
                t_max = min(t_max, t)
            if t_min > t_max:
                return False
    return t_max >= 0
```
## Subtopics
## Operating characteristics
- **Time Complexity:** Computing the convex hull is $O(N \log N)$ for $N$ voxels in 3D. Ray-polyhedron intersection is $O(F)$ where $F$ is the number of faces.
- **Memory Complexity:** $O(V + F)$ to store the polyhedron vertices and faces.
- **Performance:** Provides tighter bounds than axis-aligned bounding boxes, potentially reducing the number of ray marching steps. However, the overhead of computing the convex hull and performing ray-polyhedron intersection may outweigh benefits for simple scenes or large numbers of objects.
- **Strengths:** Tighter bounds for complex shapes, effective for space-leaping in scenes with few objects.
- **Limitations:** High computational cost for hull construction, less effective for scenes with many small objects or highly complex geometries where the hull becomes large.
- **When to Use:** Scenes with a small number of distinct, complex volumetric objects where tight bounding is crucial for performance.
- **When Not to Use:** Scenes with many small objects, or where axis-aligned bounding boxes provide sufficient culling with lower overhead.

## Background
The PARC (Polygon assisted ray casting) method was introduced as a technique for direct volume rendering to improve performance by using convex polyhedra for space-leaping [S1, unofficial]. It is part of a broader set of optimization techniques for volume rendering, including adaptive ray traversal and proximity clouds [S1, unofficial]. The method is particularly relevant for volumes with few objects, where the overhead of constructing and using the polyhedron is justified by the reduction in density evaluations.
