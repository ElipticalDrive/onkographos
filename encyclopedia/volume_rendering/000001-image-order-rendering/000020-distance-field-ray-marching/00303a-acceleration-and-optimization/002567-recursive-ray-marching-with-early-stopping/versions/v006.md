# Recursive Ray Marching with Early Stopping

Also called: Dynamic Synchronized Inference

## Overview
Recursive Ray Marching with Early Stopping is a parallelization technique for sphere tracing that maintains a dynamic mask of unfinished rays to prevent wasted computation on rays that have already converged or exited the scene [S1][S2, unofficial]. It differs from naive synchronous batching by selectively processing only active rays at each step, and from [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md) by focusing on the binary active/inactive state of rays rather than adjusting step counts based on global ray density [S1].

## How it works
**Inputs:**
*   Camera rays (origin $O$, direction $D$).
*   Signed Distance Function (SDF) network or evaluator.
*   Marching parameters: `max_steps`, `ratio` (step multiplier), `threshold` (convergence stop).

**Outputs:**
*   Rendered depth, normal, or color per pixel.

**Data Structures:**
*   `marching_zdepth`: Tensor of shape $(H, W)$, storing the current distance traveled along each ray. Initialized to 0.
*   `unfinished_mask`: Boolean tensor of shape $(H, W)$. Initially all `True` (or valid within bounds).
*   `query_points`: List or tensor storing the 3D coordinates of SDF queries for backpropagation.

**Steps:**
1.  **Initialization:**
    *   Set `marching_zdepth` to zeros.
    *   Set `unfinished_mask` to `True` for all rays within the valid viewing volume (e.g., within the unit sphere or bounding box) [S2, unofficial].
    *   Initialize `query_points` storage [S1].

2.  **Iteration Loop:**
    *   For `step` in range(`max_steps`):
        *   **Selection:** Identify active rays where `unfinished_mask` is `True` [S1][S2, unofficial].
        *   **Point Generation:** For active rays, compute the current 3D position $P = O + \text{marching\_zdepth} \cdot D$ [S2, unofficial].
        *   **SDF Query:** Evaluate $d = \text{SDF}(P)$ for active rays [S1][S2, unofficial].
        *   **Storage:** Save $P$ to `query_points` for gradient computation [S1].
        *   **Update:** Update `marching_zdepth` for active rays:
            $$ \text{marching\_zdepth} \leftarrow \text{marching\_zdepth} + \text{clamp}(d, \text{min\_val}) \cdot \text{ratio} $$
            Where `ratio` is typically between 1.2 and 1.8 [S1]. The `clamp` ensures the step does not overshoot the surface significantly [S2, unofficial].
        *   **Convergence Check:** For each active ray, check if converged or out of bounds:
            *   Converged if $|d| < \text{threshold}$ (default $5 \times 10^{-5}$) [S2, unofficial].
            *   Out of bounds if distance exceeds scene bounds (e.g., unit sphere radius) [S1].
        *   **Mask Update:** Set `unfinished_mask` entries to `False` for rays that converged or went out of bounds [S1][S2, unofficial].
        *   **Early Exit:** If all entries in `unfinished_mask` are `False`, break the loop [S1][S2, unofficial].

3.  **Backpropagation Optimization (Implementation Detail):**
    *   To avoid unaffordable memory consumption from storing all query locations in the computational graph:
        *   Perform minimization of absolute SDF values over a detached tensor graph (no gradients) [S1].
        *   Retrieve the minimum $K$ queries for each ray [S1].
        *   Re-evaluate (feedforward) only these $K$ queries with gradients attached [S1].
        *   Typical $K$ values: 1 for depth rendering, 3 for shape completion, 1 for multi-view reconstruction [S1].

**Pseudocode:**

```python
def recursive_ray_marching_with_early_stopping(
    origins, directions, sdf_network, 
    max_steps=100, ratio=1.5, threshold=5e-5, 
    scene_bounds=1.0, k_queries=1
):
    """
    Recursive ray marching with early stopping for sphere tracing.
    
    Args:
        origins: Tensor (H, W, 3), camera ray origins.
        directions: Tensor (H, W, 3), camera ray directions.
        sdf_network: Callable, returns SDF value given 3D points.
        max_steps: Maximum number of marching steps.
        ratio: Step size multiplier (1.2-1.8 typical).
        threshold: Convergence threshold for |SDF|.
        scene_bounds: Radius of the bounding sphere/box.
        k_queries: Number of queries to keep for backprop.
        
    Returns:
        depth: Tensor (H, W), rendered depth.
        sdf_values: Tensor (H, W), final SDF values.
    """
    H, W, _ = origins.shape
    marching_zdepth = torch.zeros((H, W), device=origins.device)
    unfinished_mask = torch.ones((H, W), dtype=torch.bool, device=origins.device)
    
    # Store query points for backpropagation optimization
    # In practice, this might be a list of tensors or a large buffer
    query_points_history = [] 
    
    for step in range(max_steps):
        # 1. Select active rays
        active_indices = torch.nonzero(unfinished_mask, as_tuple=False)
        
        if active_indices.numel() == 0:
            break
            
        # 2. Generate points for active rays
        # Gather origins and directions for active rays
        active_origins = origins[unfinished_mask]
        active_directions = directions[unfinished_mask]
        
        # Current 3D positions
        # P = O + z * D
        active_points = active_origins + marching_zdepth[unfinished_mask].unsqueeze(-1) * active_directions
        
        # 3. Evaluate SDF
        # Note: In a real framework, this would be a batched network forward pass
        active_sdfs = sdf_network(active_points)
        
        # 4. Store points for backprop (optimized)
        # We store all points, but optimization happens later
        query_points_history.append(active_points)
        
        # 5. Update marching distance
        # Clamp SDF to prevent negative steps or overshooting too much
        # Typical logic: step = clamp(sdf, min_step) * ratio
        # Here we assume a simple clamp to 0 or a small epsilon if needed, 
        # but standard sphere tracing uses sdf directly if positive, 
        # or handles negative carefully. The source implies standard sphere tracing logic.
        step_sizes = torch.clamp(active_sdfs, min=0.0) * ratio
        
        # Update zdepth for active rays
        marching_zdepth[unfinished_mask] += step_sizes
        
        # 6. Check convergence and bounds
        converged = torch.abs(active_sdfs) < threshold
        out_of_bounds = torch.norm(active_points, dim=-1) > scene_bounds
        
        # Update mask: rays are finished if converged OR out of bounds
        finished = converged | out_of_bounds
        unfinished_mask[unfinished_mask] = ~finished
        
    # 7. Final Depth Calculation
    # Depth is the accumulated zdepth for rays that are still active or finished
    # For rays that finished early, marching_zdepth holds the correct depth
    # For rays that hit max steps, it holds the last position
    depth = marching_zdepth
    
    return depth, active_sdfs # Return SDFs for further processing if needed
```

**Parameters:**
*   `max_steps`: Integer, typically 100 [S1].
*   `ratio`: Float, step multiplier. Typical range 1.2 to 1.8. Small $\alpha$ (ratio) causes slow convergence; large $\alpha$ causes holes in thin areas [S1].
*   `threshold`: Float, convergence stop. Default $5 \times 10^{-5}$ [S2, unofficial].
*   `K`: Integer, number of queries to retain for backpropagation. 1 for depth, 3 for shape completion, 1 for multi-view [S1].

**Edge Cases and Pitfalls:**
*   **Precision:** When close to the surface, SDF values are near zero, causing slow convergence. The `threshold` prevents infinite loops [S1].
*   **Memory:** Storing all query points for backpropagation is memory-intensive. The detached tensor minimization trick is required for high resolutions (e.g., 2048x2048) [S1].
*   **Thin Structures:** Large `ratio` values can overshoot thin geometry, creating holes. Careful tuning of `ratio` is needed [S1].

## Subtopics

### [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md)
Adjusts step counts based on active ray density rather than binary convergence masks. Choose when global ray distribution varies significantly.

## Operating characteristics
*   **Time Complexity:** Proportional to the sum of steps taken by all rays. Early stopping reduces total steps compared to synchronous batching, especially for complex shapes where rays converge at different rates [S1].
*   **Memory Complexity:** $O(H \cdot W \cdot K)$ for the backpropagation optimization, where $K$ is the number of retained queries per ray. Without this optimization, it would be $O(H \cdot W \cdot \text{max\_steps})$ [S1].
*   **Performance:** Enables high-resolution rendering (2048x2048) on single GPUs (e.g., GTX-1080Ti) by reducing redundant SDF evaluations [S1].
*   **Strengths:** Significant speedup for rays that converge early; differentiable; simple to implement with tensor operations.
*   **Limitations:** Requires careful tuning of `ratio` and `threshold`; memory overhead for backpropagation if not optimized.

## Background
The method was introduced as "Dynamic Synchronized Inference" in the DIST (Differentiable Implicit Signed Distance) paper [S1]. It addresses the inefficiency of naive parallel sphere tracing where rays are updated synchronously, wasting computation on converged rays [S1]. The implementation details and aliases are documented in the unofficial DIST-Renderer repository [S2, unofficial].
