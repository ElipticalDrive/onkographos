# Recursive Ray Marching with Early Stopping

Also called: Dynamic Synchronized Inference

## Overview
Recursive Ray Marching with Early Stopping is a parallelization technique for differentiable sphere tracing that maintains a dynamic mask of unfinished rays to prevent wasted computation on rays that have already converged or exited the scene [S1][S2, unofficial]. It differs from its siblings, such as [Beam Optimization](932-beam-optimization.md) which prunes low-probability paths, and [Performance Optimizations for SDF Ray Marching](1629-performance-optimizations-for-sdf-ray-marching.md) which may use static acceleration structures, by explicitly managing the active set of rays at every iteration to handle heterogeneous convergence rates across the image plane [S1][S2, unofficial].

## How it works
**Inputs:**
- Camera rays: origin $\mathbf{o}_i$ and direction $\mathbf{d}_i$ for each pixel $i \in [0, H \times W - 1]$ [S1].
- SDF function $f(\mathbf{p})$: returns signed distance value for a query point [S1].

**Outputs:**
- Rendered depth, normal, color, or silhouette for each pixel [S1].
- Gradients for optimization (if differentiable) [S1].

**Data Structures:**
- `marching_zdepth`: Array of size $N$, storing accumulated distance along each ray. Initialized to $0$.
- `unfinished_mask`: Boolean array of size $N$, initially `True` for all rays within the valid viewing frustum or unit sphere bounds [S2, unofficial].
- `ray_positions`: Array of size $N \times 3$, storing current 3D position of each ray. Initialized to $\mathbf{o}_i$ [S1].
- `query_history`: List of arrays storing query positions for backpropagation [S1].

**Numbered Steps:**
1. **Initialization:** Set `marching_zdepth` to zeros. Set `ray_positions` to ray origins $\mathbf{o}_i$. Set `unfinished_mask` to `True` for all rays within the valid viewing frustum or unit sphere bounds [S2, unofficial].
2. **Iteration Loop:** For step $k$ from 1 to `max_steps`:
   a. **Select Active Rays:** Identify indices where `unfinished_mask` is `True`. Concatenate these rays into a single batch tensor [S1].
   b. **Query SDF:** Evaluate $d_j = f(\mathbf{p}_j)$ for each active ray $j$ in the batch [S1][S2, unofficial].
   c. **Update Positions:** Compute step size using the SDF value and a multiplier. Update position and accumulated depth [S2, unofficial].
   d. **Check Convergence:** If the ray meets convergence criteria, set its mask entry to `False` [S1].
   e. **Gradient Handling:** Save query locations globally. Perform minimization of absolute SDF over a detached tensor graph to find the minimum $K$ queries per ray. Re-evaluate these specific queries with gradients attached [S1].
3. **Final Compositing:** Map results back to original image resolution [S1].

**Formulas:**
- Step size: $\text{step\_size}_j = \min(d_j, \text{max\_step}) \times \alpha$
- Position update: $\mathbf{p}_j \leftarrow \mathbf{p}_j + \mathbf{d}_j \times \text{step\_size}_j$
- Depth update: $\text{marching\_zdepth}_j \leftarrow \text{marching\_zdepth}_j + \text{step\_size}_j$
- Convergence: $|d_j| < \text{threshold}$ or ray exits bounding volume [S1][S2, unofficial].
- Symbols: $d_j$ is signed distance at $\mathbf{p}_j$, $\alpha$ is step multiplier, $\text{max\_step}$ is a clamp limit, $\text{threshold}$ is convergence tolerance, $\mathbf{d}_j$ is ray direction, $\mathbf{p}_j$ is current position.

**Parameters:**
- `max_steps`: Maximum marching iterations. Default is 100 [S1].
- `alpha` ($\alpha$): Step multiplier scaling the SDF value. Typical range is 1.2–1.8 [S1].
- `threshold`: Convergence stop threshold. Default is $5 \times 10^{-5}$ [S2, unofficial].
- `K`: Number of queries to keep for backpropagation. $K=1$ for depth rendering, $K=3$ for shape completion, $K=1$ for multi-view reconstruction [S1].

**Edge Cases and Pitfalls:**
- **Precision:** When close to the surface, SDF values are small, leading to slow convergence. The `threshold` must be chosen relative to the rendering resolution and object scale [S1].
- **Thin Structures:** Large `alpha` values can cause rays to overshoot thin surfaces, creating holes. Empirical values range from 1.2 to 1.8 [S1].
- **Memory:** Storing all query positions for backpropagation is memory-intensive. The detached tensor minimization trick is essential for high-resolution rendering (e.g., 2048x2048) [S1].

**Pseudocode:**
```python
def recursive_ray_marching_with_early_stopping(rays, sdf_func, max_steps=100, alpha=1.5, threshold=5e-5, K=1):
    """
    rays: list of (origin, direction) tuples, each 3D vector
    sdf_func: callable returning distance (float)
    """
    N = len(rays)
    positions = [ray[0] for ray in rays]
    directions = [ray[1] for ray in rays]
    z_depth = [0.0] * N
    unfinished_mask = [True] * N
    query_history = []

    for step in range(max_steps):
        active_indices = [i for i in range(N) if unfinished_mask[i]]
        if not active_indices:
            break

        active_positions = [positions[i] for i in active_indices]
        distances = [sdf_func(p) for p in active_positions]

        query_history.append(active_positions)

        for idx, i in enumerate(active_indices):
            d = distances[idx]
            step_size = min(d, 1.0) * alpha
            positions[i] = [positions[i][j] + directions[i][j] * step_size for j in range(3)]
            z_depth[i] += step_size

            if abs(d) < threshold:
                unfinished_mask[i] = False

    # Gradient computation: find min |SDF| per ray from query_history, 
    # re-evaluate with gradients attached. Requires framework-specific autograd hooks [G].
    return z_depth, positions
```

## Subtopics

### [Adaptive Ray Marching with Dynamic Step Count](3888-adaptive-ray-marching-with-dynamic-step-count.md)
Dynamically adjusts the number of steps per ray based on the count of currently active rays, differing from this method which uses a fixed step count per iteration but variable active set size.

### [Adaptive Ray Marching (Test)](15779-adaptive-ray-marching-test.md)
Processes rays in explicit batches with a fixed step count per batch, differing from this method which updates a single active set with variable steps per iteration.

## Operating characteristics
- **Time Complexity:** $O(N \cdot S_{active})$, where $N$ is the number of rays and $S_{active}$ is the average number of steps per active ray. Early stopping reduces $S_{active}$ for converged rays, improving performance over fixed-step marching [S1].
- **Memory Complexity:** $O(N \cdot K)$ for storing query history for backpropagation, where $K$ is the number of queries kept per ray [S1].
- **Performance:** Enables high-resolution rendering (2048x2048) on single GPUs (e.g., GTX-1080Ti) by avoiding wasted computation on converged rays [S1].
- **Strengths:** Efficient for scenes with varying depth complexity; reduces compute for background and converged foreground pixels [S1].
- **Limitations:** Requires tuning of the step multiplier $\alpha$ (typically 1.2–1.8) to balance convergence speed and hole formation in thin areas [S1].

## Background
The method was introduced as "Dynamic Synchronized Inference" in the DIST framework [S1]. It addresses the inefficiency of naive parallel sphere tracing where all rays are updated synchronously, leading to wasted computation when some rays converge earlier than others [S1]. The implementation details were further explored in unofficial repositories such as B1ueber2y/DIST-Renderer [S2, unofficial].
