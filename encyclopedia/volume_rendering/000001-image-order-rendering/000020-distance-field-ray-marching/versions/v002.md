# Distance-field ray marching

Also called: Sphere tracing

## Overview
Distance-field ray marching (commonly known as sphere tracing) is a rendering method that finds surfaces by moving along a ray in repeated steps, using a signed distance field (SDF) to choose each step size adaptively, avoiding the tradeoff of fixed-step marching [S1, unofficial]. Unlike naive fixed-step marching which uses a constant increment, sphere tracing uses the SDF value as the step size, ensuring the step is as large as possible without risk of overshooting [S3, unofficial]. Unlike traditional rasterization, the visible shape is defined mathematically by a scene function, not by a triangle mesh [S2, unofficial].

## Shared principles
The method renders geometry by shooting a ray through each pixel and repeatedly querying a Signed Distance Function (SDF) [S2, unofficial]. An SDF is a formula that, given any point $p$ in space, returns the distance from $p$ to the nearest surface [S3, unofficial]. The sign indicates position: negative inside, positive outside, zero exactly on the surface [S3, unofficial].

The core loop initializes a ray with an origin point $ro$ and a normalized direction vector $v$ [S3, unofficial]. It maintains a current position $p$ (initially $ro$) and an accumulated distance $t$ (initially 0) [S4, unofficial]. In each iteration:
1. The SDF is evaluated at the current position $p$ to get the distance $d$ to the nearest surface [S4, unofficial].
2. If $d < 0$, the ray is inside an obstacle; the algorithm stops immediately to avoid oscillating or marching further into the interior [S3, unofficial].
3. If $d \le \text{HIT\_THRESHOLD}$ (a small value such as 0.001 or 1.5 pixels), the ray has hit the surface [S1, unofficial][S3, unofficial]. The loop terminates, and the point $p$ is considered on the surface [S4, unofficial].
4. Otherwise, the position is advanced along the ray direction by the distance $d$: $p = p + d * v$ [S4, unofficial]. This step size is guaranteed not to overshoot the surface because $d$ is the distance to the nearest surface [S2, unofficial].
5. The accumulated distance $t$ is increased by $d$ [S1, unofficial].
6. The loop continues while $d > \text{HIT\_THRESHOLD}$ and the step count is less than $\text{MAX\_STEPS}$ [S4, unofficial].

If the loop terminates with $d < \text{epsilon}$, the surface normal $n(p)$ can be calculated using the gradient approximation: $n(p) = \text{normalized}(iso(p + \text{small}) - iso(p - \text{small}))$ [S4, unofficial].

The scene is defined by combining primitive SDFs. For a sphere of radius $r$ centered at $c$, the distance function is $d(p) = |p - c| - r$ [S4, unofficial]. Union of two objects with distance fields $d1$ and $d2$ is $iso(p) = \min(d1(p), d2(p))$ [S4, unofficial]. Intersection is $iso(p) = \max(d1(p), d2(p))$ [S4, unofficial]. Subtraction of object $d2$ from $d1$ is $iso(p) = \max(d1(p), -d2(p))$ [S4, unofficial].

Parameters include $\text{MAX\_STEPS}$ (a safety cap, typically 40) and $\text{HIT\_THRESHOLD}$ (epsilon) [S3, unofficial][S4, unofficial]. A maximum range or accumulated travel distance limit can also bound rays that miss [S1, unofficial].

```python
def ray_march(ro, v, scene, max_steps=40, hit_threshold=0.001, max_range=100.0):
    p = ro
    t = 0.0
    for i in range(max_steps):
        d = scene(p)
        if d < 0:
            break
        if d <= hit_threshold:
            return p, True, t
        t += d
        if t > max_range:
            break
        p = p + d * v
    return p, False, t
```

## Subtopics

### Sphere Tracing with Shading
Computes surface properties like normals and colors after a hit, enabling lighting and shading calculations instead of returning a flat color [S2, unofficial]. Choose it when visual fidelity and material response are required. [Link](21-sphere-tracing-shading.md)

### Sphere Tracing with Depth Buffer Output
Writes the hit distance to a depth buffer so sphere-traced objects correctly occlude standard rasterized geometry, solving Z-write conflicts [S2, unofficial]. Choose it when integrating implicit surfaces into a traditional raster pipeline. [Link](22-sphere-tracing-depth.md)

## Background
The technique was introduced as 'Sphere Tracing' by John C. Hart in 1996 in 'Sphere tracing: a geometric method for the antialiased ray tracing of implicit surfaces' [S4, unofficial]. It was also referenced in Hart's 1989 work 'Ray Tracing Deterministic 3-D Fractals' and NVIDIA Gems2 (2004) [S4, unofficial].

It became widely used in 4k intros released in 2009, specifically in productions like 'Frequency' by xt95 and 'Potatro' [S4, unofficial]. It is widely used in real-time shader art (e.g., Shadertoy) for rendering scenes with no mesh data, and for volumetrics (fog, clouds) by treating density as an SDF [S3, unofficial].
