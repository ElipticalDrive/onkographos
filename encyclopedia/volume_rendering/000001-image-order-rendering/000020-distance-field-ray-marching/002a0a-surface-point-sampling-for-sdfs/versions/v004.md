# Surface Point Sampling for SDFs

Also called: Forplane Rendering Procedure, Sphere Tracing Surface Sampling

## Overview
Surface Point Sampling for SDFs refers to a family of techniques that generate point clouds or render images by sampling points near or on the zero-level set of a Signed Distance Function (SDF). Unlike standard volume rendering which integrates density along a ray, these methods focus on extracting geometric representations (point clouds) or computing surface-based shading by identifying the intersection $t$ where $f(\mathbf{o} + t\mathbf{d}) \approx 0$. It is distinguished from its sibling [Distance-field ray marching](21-distance-field-ray-marching.md) by its specific focus on the *sampling strategy* for surface extraction or feature aggregation rather than just the marching loop itself, and from [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md) by its reliance on implicit distance fields rather than explicit Gaussian primitives.

## How it works
The method encompasses several distinct approaches depending on the goal: extracting a point cloud for training/representation, or rendering a view using surface-adjacent samples.

### Inputs and Outputs
*   **Inputs**:
    *   SDF function $f(\mathbf{p})$ or a learned implicit representation (e.g., MLP $\theta$, grid fields $G$).
    *   Ray definition $r(t) = \mathbf{o} + t\mathbf{d}$, where $\mathbf{o}$ is the camera origin and $\mathbf{d}$ is the normalized direction vector [G].
    *   Bounding volume $B$ (typically $[-1, 1]^3$) [S1, S6].
    *   Optional: Indicator grid $G_o$ [S2], static/dynamic field levels $\{V^s_{3d}, V^d_{3d}\}_4$ [S2].
*   **Outputs**:
    *   Point cloud $P$ on or near the surface $S$ [S1, S6].
    *   Rendered color $\hat{C}$ and depth $\hat{D}$ [S2].
    *   Surface interaction properties (normal, frame) [S4, unofficial].

### Data Structures
1.  **Point Set**: A list of points $P = \{\mathbf{p}_i\}$, where each $\mathbf{p}_i \in \mathbb{R}^3$. For temporal data, points may include time $\tau$ [S2].
2.  **Feature Vector**: For rendering, a feature vector $v(\mathbf{p}, \tau)$ initialized to 1, updated via interpolation [S2].
3.  **Surface Interaction**: A structure `SurfaceInteraction3f` containing:
    *   `si.t`: Intersection distance.
    *   `si.p`: Intersection position.
    *   `si.sh_frame.n`: Normalized gradient.
    *   `si.sh_frame.s`, `si.sh_frame.t`: Tangent vectors.
    *   `si.wi`: Incoming direction in local frame.
    *   `si.dp_du`, `si.dp_dv`: Partial derivatives for texture mapping [S4, unofficial].

### Algorithms

#### 1. Uniform Sphere Tracing for Point Cloud Extraction
This method generates a uniform distribution of surface points by casting rays from random origins and directions [S1].

1.  **Initialization**: Define bounding box $B = [-1, 1]^3$ [S1].
2.  **Ray Casting Loop**:
    *   Sample a point $\mathbf{o}$ uniformly from $B$: $\mathbf{o} \sim U[B]$ [S1, S6].
    *   Sample a direction $\mathbf{d}$ uniformly from the unit sphere $S^2$ [S1, S6].
    *   Define ray $r(t) = \mathbf{o} + t\mathbf{d}$ [G].
3.  **Sphere Tracing**:
    *   Initialize $t = 0$ [S1, S3].
    *   While $t < t_{max}$ and $|f(r(t))| > \epsilon$:
        *   Evaluate $d = f(r(t))$ [S1, S3].
        *   Advance $t \leftarrow t + d$ [S1, S3].
    *   If $|f(r(t))| \le \epsilon$, add $\mathbf{p} = r(t)$ to the point cloud $P$ [S1].
4.  **Termination**: Repeat until sufficient points are collected [S1].

#### 2. Explicit Sampling for Point Cloud Extraction (PDDF)
This method projects random points onto the surface using multiple directions to handle visibility and depth accuracy [S6].

1.  **Input**: Probabilistic Directed Distance Field (PDDF) $d(\mathbf{p}, \mathbf{v})$ and visibility $\xi(\mathbf{p}, \mathbf{v})$ [S6].
2.  **Parameters**: $n_v = 128$ (directions per point), $N_H = 3$ (iterations) [S6].
3.  **Sampling Loop**:
    *   Sample $\mathbf{p} \sim U[B]$ [S6].
    *   For $h = 1$ to $N_H$:
        *   Sample $n_v$ directions $V(\mathbf{p}) = \{\mathbf{v}_i\}_{i=1}^{n_v}$ uniformly from $S^2$ [S6].
        *   Estimate best direction $\mathbf{v}^*_b(\mathbf{p})$ that maximizes visibility $\xi(\mathbf{p}, \mathbf{v}) = 1$ [S6].
        *   Compute surface point $\mathbf{q} = \mathbf{p} + d(\mathbf{p}, \mathbf{v}^*_b(\mathbf{p})) \mathbf{v}^*_b(\mathbf{p})$ [S6].
        *   Update $\mathbf{p} \leftarrow \mathbf{q}$ [S6].
    *   Add $\mathbf{p}$ to point cloud [S6].

#### 3. Near-Surface Perturbation
This method generates points near the surface by perturbing existing mesh samples [S1].

1.  **Input**: Mesh surface samples $P_{mesh}$ [S1].
2.  **Perturbation**: For each $\mathbf{p} \in P_{mesh}$, sample $\mathbf{n} \sim \mathcal{N}(0, \sigma^2 I)$ where $\sigma = 0.01$ [S1].
3.  **Output**: $\mathbf{p}' = \mathbf{p} + \mathbf{n}$ [S1].

### Parameters
*   $\epsilon$: Convergence threshold for sphere tracing. Typical value: $0.001$ [S1, S39, unofficial].
*   $t_{max}$: Maximum ray distance. Not given in the sources.
*   $\sigma$: Noise standard deviation for near-surface perturbation. Value: $0.01$ [S1].
*   $n_v$: Number of directions sampled per point in explicit sampling. Value: $128$ [S6].
*   $N_H$: Number of iterations for explicit sampling refinement. Value: $3$ [S6].
*   Learning rate: $0.001$ for training MLPs [S1].

### Edge Cases and Pitfalls
*   **Precision**: Floating-point errors in sphere tracing can cause jitter or missed intersections. Use a small $\epsilon$ [S1, S39, unofficial].
*   **Visibility**: In explicit sampling, rays may intersect other geometry. The visibility term $\xi(\mathbf{p}, \mathbf{v})$ must be checked to ensure the sampled point is on the visible surface [S6].
*   **Uniformity**: Explicit sampling does not guarantee uniform sampling over the surface $S$ [S6].
*   **Complex Topology**: Baseline methods using only sampling points may exhibit topological defects and missing features in regions with high curvature or thin structures [S3].

## Subtopics

### [Near-Surface Point Sampling](2910-near-surface-point-sampling.md)
Near-Surface Point Sampling generates point clouds for implicit surface representation by perturbing existing mesh surface samples with Gaussian noise ($\sigma=0.01$). It solves the problem of insufficient training data density near the surface boundary. It is distinguished from its sibling [Surfel Parameterization from Mesh Sampling](4501-surfel-parameterization-from-mesh-sampling.md) by its reliance on random perturbation rather than geometric parameterization, and from [Bidirectional Projective Sampling](8824-bidirectional-projective-sampling.md) by its simplicity and lack of view-dependent optimization.

### [Surfel Parameterization from Mesh Sampling](4501-surfel-parameterization-from-mesh-sampling.md)
This method estimates the full parameter set (position, normal, tangent vectors, and scales) for a surfel representation starting from a triangle mesh. It solves the problem of defining local tangent frames and anisotropic kernel shapes for point clouds sampled from meshes. It differs from sibling methods by deriving tangent scales from the local point cloud neighborhood structure rather than mesh connectivity or fixed heuristics, offering two variants: isotropic scaling for performance and anisotropic scaling for quality.

### [Bidirectional Projective Sampling](8824-bidirectional-projective-sampling.md)
Bidirectional Projective Sampling is a boundary sampling method for physics-based differentiable rendering that generates seed rays from both sensors and emitters to initialize a guiding structure, addressing inefficiencies when scenes contain small-area lights at a distance. It improves upon Zhang et al.'s projective sampling by incorporating rays emitted directly from small-area emitters into the seed ray set during the projection operation, ensuring all successfully projected rays contribute to the guiding structure regardless of emitter size. Unlike previous methods that rely solely on sensor-spawned rays, which have a near-zero probability of intersecting small-area emitters, this method guarantees intersection by explicitly sampling from the emitter, thereby maximizing contribution to the boundary integral.

### [Multi-view Feature Consistency via Linear Interpolation](10227-multi-view-feature-consistency-via-linear-interpolation.md)
A method to derive a differentiable surface point from volume rendering samples using linear interpolation of SDF zero-crossings, used to enforce multi-view feature consistency.

### Projection Point Integration
**Definition**: The incorporation of projection points derived from gradient information into the power diagram computation to accurately capture the underlying surface, particularly in regions with complex topology or fine details [S3].
**Steps**: Projection points are especially valuable for reconstructing thin structures, sharp edges, and regions with high curvature variation that might otherwise be inadequately captured by discrete SDF sampling points alone [S3].
**Comparison**: The baseline method using only sampling points without projections exhibits substantial topological defects and missing features, whereas the projection-enhanced approach preserves topological integrity [S3].

### Surface Interaction Construction
**Definition**: Constructs a `SurfaceInteraction3f` structure from a ray and intersection time, computing normal, frame, and other interaction properties without SDF autodiff support [S4, unofficial].
**Steps**: Set `si.t = t`, `si.p = ray(t)`, `si.sh_frame.n = normalize(gradient(si.p))`, initialize sh frame, set `si.n = si.sh_frame.n`, `si.wi = to_local(-ray.d)`, `si.wavelengths = ray.wavelengths`, `si.dp_du = sh_frame.s`, `si.dp_dv = sh_frame.t` [S4, unofficial].

### SDF-guided Sampling
**Definition**: A method using an SDF field to guide surface sampling by estimating ray-surface intersections and performing fine-grained sampling around the intersection point [S5].

### Explicit Sampling for Point Cloud Extraction
**Definition**: A method to extract a point cloud (PC) from a Probabilistic Directed Distance Field (PDDF) by projecting random points onto the shape surface $S$. It does not guarantee uniform sampling over $S$ [S6].
**Steps**: Sample a point $p$ uniformly from the bounding box $B$. For each $p$, sample $n_v$ directions $v_i$ uniformly from the unit sphere $S^2$. Compose these directions to estimate the best direction $v_b^*(p)$ to avoid visibility $\xi(p, v) = 0$. Compute the surface point $q(p, v_b^*(p))$ using the PDDF depth and direction. Repeat the process $N_H$ times, starting from the newly found point $q$ (i.e., $p \leftarrow q$), to improve accuracy for depths far from $S$ [S6].
**Parameters**: $n_v$: Number of directions sampled per point. Typical value: 128 [S6].

## Operating characteristics
*   **Time Complexity**: Depends on the number of samples and the cost of SDF evaluation. Sphere tracing is $O(N)$ where $N$ is the number of steps per ray [S1, S3]. Explicit sampling is $O(N \cdot n_v \cdot N_H)$ [S6].
*   **Memory Complexity**: $O(P)$ for storing the point cloud, where $P$ is the number of points [S1, S6]. For rendering methods like Forplane, additional memory is required for grid fields and MLP weights [S2].
*   **Measured Performance**: Not given in the sources.
*   **Scaling**: Scales with the resolution of the SDF or the complexity of the MLP. Adaptive methods (like Power Diagram enhancement) scale with the number of refinement iterations [S3].
*   **Strengths**: Provides explicit geometric representations (point clouds) suitable for downstream tasks like mesh extraction or training [S1, S6]. Can capture fine details with sufficient sampling [S3].
*   **Limitations**: Uniform sampling may be inefficient for complex scenes. Explicit sampling does not guarantee uniformity [S6]. Requires careful tuning of parameters like $\epsilon$, $n_v$, and $N_H$ [S6].
*   **When to use**: When an explicit point cloud representation is needed for training or processing [S1, S6]. When rendering dynamic scenes with orthogonal planes [S2].
*   **When not to use**: When uniform surface sampling is strictly required without post-processing [S6]. When computational resources are extremely limited and simple sphere tracing is insufficient [S3].

## Background
*   **Origin**: The concept of using SDFs for surface sampling and rendering has been developed in various forms. Neural Geometric Level of Detail (NGLOD) introduced sphere tracing for point cloud extraction [S1]. Efficient Deformable Tissue Reconstruction via Orthogonal Neural Planes (Forplane) introduced the rendering procedure using orthogonal planes [S2]. Power Diagram Enhanced Adaptive Isosurface Extraction introduced projection points for topological accuracy [S3]. Probabilistic Directed Distance Fields (PDDF) introduced explicit sampling for point cloud extraction [S6].
*   **History**: Early methods relied on uniform sampling and sphere tracing [S1]. Later methods incorporated adaptive strategies and projection points to handle complex topology [S3]. Recent advances integrate learned features and orthogonal planes for dynamic rendering [S2].
*   **Usage**: Used in neural rendering, implicit surface reconstruction, and differentiable rendering pipelines [S1, S2, S6].
