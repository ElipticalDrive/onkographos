# Surface Interaction Construction

Also called: SurfaceInteraction3f Construction

## Overview
Constructs a `SurfaceInteraction3f` structure from a ray and intersection time, computing the surface normal, local frame, and other interaction properties for ray-surface intersection in volume rendering pipelines [S1, unofficial]. It differs from sibling methods by explicitly handling the sign determination of the Signed Distance Function (SDF) via normal-based majority voting, which allows it to handle meshes with holes better than depth-based approaches, though it introduces specific geometric artifacts [S2, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A ray (origin, direction, wavelengths), an intersection time $t$, and the SDF gradient function $\nabla \phi$.
- Output: A `SurfaceInteraction3f` structure `si` containing position, normal, local frame, and direction vectors.

**Data Structures:**
The `SurfaceInteraction3f` structure contains the following fields:
- `si.t`: float, intersection distance along the ray.
- `si.p`: `Vector3f`, intersection point in world space.
- `si.sh_frame`: `Frame` object, the shading frame.
  - `si.sh_frame.n`: `Vector3f`, surface normal.
  - `si.sh_frame.s`: `Vector3f`, tangent vector (u-direction).
  - `si.sh_frame.t`: `Vector3f`, bitangent vector (v-direction).
- `si.n`: `Vector3f`, the geometric normal (alias for `sh_frame.n`).
- `si.wi`: `Vector3f`, incoming direction in local space.
- `si.wavelengths`: array, wavelengths of the incident light.
- `si.dp_du`: `Vector3f`, partial derivative of position with respect to u (`sh_frame.s`).
- `si.dp_dv`: `Vector3f`, partial derivative of position with respect to v (`sh_frame.t`).

**Steps:**
1. Set the intersection time: `si.t = t`.
2. Compute the intersection point: `si.p = ray.origin + t * ray.direction`.
3. Compute the surface normal by normalizing the SDF gradient at the intersection point:
   $$ \mathbf{n}_{raw} = \nabla \phi(\text{si.p}) $$
   $$ \text{si.sh\_frame.n} = \frac{\mathbf{n}_{raw}}{\|\mathbf{n}_{raw}\|} $$
4. Initialize the shading frame. The tangent `si.sh_frame.s` and bitangent `si.sh_frame.t` are derived from the normal to form an orthonormal basis [S1, unofficial].
5. Set the geometric normal: `si.n = si.sh_frame.n`.
6. Compute the incoming direction in local space:
   $$ \text{si.wi} = \text{to\_local}(-\text{ray.direction}) $$
   where `to_local` transforms the vector from world space to the local frame defined by `si.sh_frame`.
7. Assign the ray's wavelengths: `si.wavelengths = ray.wavelengths`.
8. Set the position derivatives:
   $$ \text{si.dp\_du} = \text{si.sh\_frame.s} $$
   $$ \text{si.dp\_dv} = \text{si.sh\_frame.t} $$
9. Determine the sign of the SDF. If using the `normal` sign method, perform a majority vote on nearby surface points to determine if the point is inside or outside the mesh [S2, unofficial].

**Parameters:**
- `normal_sample_count`: Integer, number of nearby surface points to check when determining the SDF sign using `sign_method='normal'`. Default value is 11 [S2, unofficial].

**Pseudocode:**
```python
def construct_surface_interaction(ray, t, sdf_gradient_func, sign_method='normal', normal_sample_count=11):
    # 1. Set time and position
    si_t = t
    si_p = ray.origin + t * ray.direction
    
    # 2. Compute normal from SDF gradient
    grad = sdf_gradient_func(si_p)
    si_sh_frame_n = grad / length(grad)
    
    # 3. Initialize shading frame (s and t are orthogonal to n)
    # [G] Implementation of orthonormal basis construction from normal not specified in sources.
    # Assuming a standard Gram-Schmidt or cross-product with an arbitrary up vector.
    si_sh_frame_s = compute_tangent(si_sh_frame_n)
    si_sh_frame_t = cross(si_sh_frame_n, si_sh_frame_s)
    
    # 4. Set structure fields
    si = SurfaceInteraction3f()
    si.t = si_t
    si.p = si_p
    si.sh_frame.n = si_sh_frame_n
    si.sh_frame.s = si_sh_frame_s
    si.sh_frame.t = si_sh_frame_t
    si.n = si_sh_frame_n
    
    # 5. Compute local incoming direction
    # [G] to_local is assumed to be a standard frame transformation
    si.wi = to_local(-ray.direction, si.sh_frame)
    
    # 6. Set wavelengths
    si.wavelengths = ray.wavelengths
    
    # 7. Set derivatives
    si.dp_du = si_sh_frame_s
    si.dp_dv = si_sh_frame_t
    
    # 8. Determine SDF sign
    if sign_method == 'normal':
        # [S2, unofficial] Determine sign using majority vote of nearby points
        # This step is critical for handling holes but may produce artifacts
        si.sign = determine_sign_by_voting(si_p, normal_sample_count)
    else:
        # [S2, unofficial] Depth method fallback
        si.sign = determine_sign_by_depth(si_p)
        
    return si
```

**Edge Cases and Pitfalls:**
- **Cone-shaped artifacts:** The `normal` sign method produces cone-shaped artifacts in the SDF volume, particularly when the mesh contains tiny triangles facing differently than surrounding areas [S2, unofficial].
- **Ineffectiveness of sampling increase:** Increasing `normal_sample_count` does not mitigate the cone artifacts [S2, unofficial].
- **Mesh holes:** The `normal` method works better for meshes with holes compared to the `depth` method. However, the `depth` method suffers from ray-shaped artifacts when holes allow the camera to see "inside" the mesh [S2, unofficial].
- **Bad Meshes:** If checks fail (e.g., SDF difference smaller than distance difference between points), a `BadMeshException` is thrown [S2, unofficial].

## Operating characteristics
- **Time Complexity:** Not given in the sources.
- **Memory Complexity:** Not given in the sources.
- **Performance:** The underlying mesh-to-SDF conversion process can process about 60% of meshes in the ShapeNet dataset [S2, unofficial].
- **Strengths:** Handles meshes with holes effectively when using the normal-based sign determination [S2, unofficial].
- **Limitations:** Prone to cone-shaped artifacts in the SDF volume due to small, differently oriented triangles [S2, unofficial].

## Background
This method is part of the `mesh_to_sdf` pipeline for generating Signed Distance Functions from triangle meshes [S2, unofficial]. It is used in rendering systems that require SDF-based ray marching, such as the `relaxed-boundary` project [S1, unofficial]. The approach was developed to address limitations in depth-based sign determination for complex mesh topologies [S2, unofficial].
