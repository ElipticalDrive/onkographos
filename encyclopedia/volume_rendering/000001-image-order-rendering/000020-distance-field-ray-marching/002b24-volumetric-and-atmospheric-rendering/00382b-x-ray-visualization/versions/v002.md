# X-Ray Visualization

Also called: Average Density Projection, X-Ray Rendering, n-D X-ray projection

## Overview
X-Ray Visualization is a volume rendering technique that projects a 3D dataset into a 2D image by computing the average density along each ray, producing a grey-scale image similar to medical X-rays [S2]. Unlike standard ray marching which accumulates color and opacity based on depth ordering, this method treats ordering as irrelevant to simplify the user interface and reveal topological information in high-dimensional or complex data [S1, unofficial]. It is distinct from [Ray Marching with Single Scattering](2057-ray-marching-with-single-scattering.md) and [SDF Cloud Rendering](2064-sdf-cloud-rendering.md) because it discards depth cues and inscattering, focusing solely on the mean density value encountered along the ray path.

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric dataset defined by density values $\rho(\mathbf{p})$ at discrete grid positions; a viewing direction defined by camera origin $\mathbf{o}$ and normalized direction vector $\mathbf{d}$; and rotation parameters for the view axes.
*   **Output:** A 2D grey-scale image where pixel intensity corresponds to the average density along the corresponding ray.

**Data Structures:**
*   **Volume Grid:** A 3D array of density values. The specific bit-packing or data type (e.g., 12-bit unsigned integer as noted in threshold ranges 0-4095) is implementation-dependent but must support linear interpolation [S2].
*   **Ray Parameters:** Origin $\mathbf{o}$, direction $\mathbf{d}$, and step size $\Delta t$.

**Steps:**
1.  **View Transformation:** The user defines the viewing orientation by rotating the system of axis vectors. The view can be rotated in any of the 3 directions (X, Y, Z axes) in degrees within the range $[-360, 360]$ [S2].
2.  **Ray Casting:** For each pixel in the output image, cast a ray $r(t) = \mathbf{o} + t\mathbf{d}$ through the volume bounds [S2].
3.  **Density Sampling:** March along the ray, sampling the density $\rho$ at each step.
4.  **Average Density Calculation:** Compute the arithmetic mean of the sampled density values along the ray segment contained within the volume. Let $N$ be the number of samples and $\rho_i$ be the density at the $i$-th sample. The average density $\bar{\rho}$ is:
    $$ \bar{\rho} = \frac{1}{N} \sum_{i=1}^{N} \rho_i $$
    [S2]
5.  **Image Formation:** Map the calculated $\bar{\rho}$ to a grey-scale intensity value for the corresponding pixel [S2].

**Pseudocode:**
```python
def render_xray(volume, camera_origin, camera_direction, image_width, image_height, num_samples):
    """
    Renders an X-ray projection of a volume.
    
    Args:
        volume: 3D array of density values.
        camera_origin: 3D vector (x, y, z).
        camera_direction: Normalized 3D vector (x, y, z).
        image_width: Integer width of output image.
        image_height: Integer height of output image.
        num_samples: Integer number of samples per ray.
        
    Returns:
        2D array of grey-scale values.
    """
    image = zeros((image_height, image_width))
    
    # Determine ray bounds or fixed length based on volume extent
    # Note: Exact volume bounds and step calculation are not specified in sources [G]
    ray_length = compute_ray_length(volume.bounds, camera_origin, camera_direction)
    step_size = ray_length / num_samples
    
    for y in range(image_height):
        for x in range(image_width):
            # Generate ray for pixel (x, y)
            # Note: Exact pixel-to-ray mapping (projection matrix) is not specified [G]
            ray_o = compute_pixel_origin(x, y, camera_origin, camera_direction, image_width, image_height)
            ray_d = camera_direction
            
            density_sum = 0.0
            count = 0
            
            # March along the ray
            for t in range(num_samples):
                current_pos = ray_o + t * step_size * ray_d
                
                # Check if position is within volume bounds
                if is_inside_volume(current_pos, volume.bounds):
                    # Sample density at current_pos
                    # Note: Interpolation method (trilinear, etc.) is not specified [G]
                    density = sample_volume(volume, current_pos)
                    density_sum += density
                    count += 1
            
            # Compute average density
            if count > 0:
                avg_density = density_sum / count
                # Map to grey scale
                # Note: Exact mapping function (e.g., normalization) is not specified [G]
                image[y, x] = map_to_greyscale(avg_density)
            else:
                image[y, x] = 0 # Background
                
    return image
```

**Parameters:**
*   **View Rotation:** Rotation angles for X, Y, and Z axes in degrees, typically ranging from -360 to 360 [S2].
*   **Num Samples:** Number of integration steps per ray. Not given in the sources.

**Edge Cases:**
*   **Empty Rays:** If a ray does not intersect the volume, the average density is undefined or zero.
*   **High-Dimensional Data:** The method is designed for n-D volume rendering (n>3) where ordering is irrelevant, but implementation requires projection into 3D or 2D viewing spaces [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(W \cdot H \cdot N)$, where $W$ and $H$ are image dimensions and $N$ is the number of samples per ray.
*   **Memory Complexity:** $O(V)$ for the volume data, where $V$ is the number of voxels.
*   **Strengths:** Simplifies user interface by eliminating occlusion exploration; reveals topological information in n-D spaces; computationally simpler than full radiative transfer integration [S1, unofficial].
*   **Limitations:** Lacks depth cues; ordering of structures is irrelevant, which may obscure spatial relationships; limited to density visualization [S1, unofficial][S2].
*   **When to use:** When exploring topological features of high-dimensional or complex datasets where depth ordering is less important than average density distribution.
*   **When not to use:** When realistic lighting, shadows, or depth perception is required.

## Background
The method was introduced by Bajaj et al. for n-D volume rendering (n>3) to simplify the user interface by treating ordering as irrelevant, thereby eliminating the need for occlusion exploration [S1, unofficial]. It allows users to change viewpoints in n-D space by stretching and rotating axis vectors [S1, unofficial]. The technique is also implemented in educational visualization tools, such as the one described by Thomas Lidy, where it computes average density values along rays and visualizes them as grey-scale images, similar to medical X-rays [S2].
