# Ray Marching with Single Scattering

Also called: Real-time Volumetric Rendering, Volumetric Cloud Rendering, Volumetric Cloud Rendering with Ray Marching

## Overview
Ray marching with single scattering is a real-time technique for rendering volumetric clouds using OpenGL/WebGL ray marching, procedural noise or 3D textures for density, and physically-based single scattering illumination [S1, S2, unofficial]. It solves the problem of rendering translucent, animated volumetric media efficiently by approximating light transport with a single scattering event per sample, balancing visual fidelity against computational cost [S1, S2, unofficial]. It differs from [SDF Cloud Rendering](2064-sdf-cloud-rendering.md) by generating density via procedural noise or texture lookups rather than signed distance fields, and from [Atmospheric Ray Marching](4874-atmospheric-ray-marching.md) by targeting localized cloud volumes with explicit bounding or spherical boundaries and wind animation rather than global atmospheric scattering [S1, S2, unofficial].

## How it works
**Inputs and Outputs:**
- **Inputs:** Eye position ($e$), screen position ($s$), camera rotation matrix ($camRot$), bounding box ($bMin, bMax$), sun position ($uUserSunPos$), sun color ($uUserSunColor$), time ($uTime$), resolution ($uResolution$), and uniform parameters for step sizes, coefficients, and noise settings [S1, S2, unofficial].
- **Output:** Fragment color ($fColor$) [S1, unofficial].

**Data Structures:**
- **Bounding Box:** Defined by $bMin$ and $bMax$ [S2, unofficial]. The effective bounds are adjusted by $uUserSize$: $bMin.x -= uUserSize.x$, $bMax.x += uUserSize.x$, etc. [S2, unofficial].
- **Noise Texture (Optional):** If using texture-based density, a `FloatingPointTexture` uses a `Float32Array` buffer of size $textureWidth \times textureHeight \times 4$ [S2, unofficial]. Pixels are stored in RGBA order, with index $(x + y \times textureWidth) \times 4$ for R, $+1$ for G, $+2$ for B, $+3$ for A [S2, unofficial]. The texture is 2D, RGBA format, FLOAT type, NEAREST filtering, CLAMP_TO_EDGE wrapping [S2, unofficial].
- **Procedural Noise:** Uses Perlin or Simplex noise (`cnoise` or `snoise`) combined with Fractal Brownian Motion (fBm) [S1, unofficial].

**Parameters:**
- $MAX\_STEPS = 50$ [S1, unofficial].
- $STEP\_SIZE = 0.08$ [S1, unofficial].
- $MAX\_STEPS\_LIGHT = 5$ [S1, unofficial].
- $STEP\_SIZE\_LIGHT = 0.6$ [S1, unofficial].
- $scatteringCoeff$: 1.5 (sunset), 1.2 (day) [S1, unofficial].
- $absorptionCoeff$: 0.4 (sunset), 0.2 (day) [S1, unofficial].
- $extinctionCoeff = scatteringCoeff + absorptionCoeff$ [S1, unofficial].
- $WIND = vec3(0.7, 0.2, -0.5)$ [S1, unofficial].
- $SUN = normalize(vec3(1.5, 1.0, 1.0))$ [S1, unofficial].
- $CAMERA = vec3(0.0, 0.0, -3.0)$ [S1, unofficial].
- $SUN\_COLOUR\_SUNSET = vec3(1.8, 1.1, 0.6)$ [S1, unofficial].
- $SUN\_COLOUR\_DAY = vec3(1.5, 1.3, 0.9)$ [S1, unofficial].
- $uUserSize, uUserSpeed, uUserSunPos, uUserSunColor, uUserDensity, uUserScale, uUserZoom, uUserControl, uRandomVector$ are user-defined uniforms [S2, unofficial].

**Formulas:**
- **Sky Color:** $screenRange = clamp(rayDir.y \times 0.5 + 0.5, 0.0, 1.0)$; $sky = mix(skyBottom, skyTop, screenRange)$ [S1, unofficial].
- **Sphere SDF:** $sdfSphere(p, r) = -length(p) + r$ [S1, unofficial].
- **Henyey-Greenstein Phase Function:**
  $$
  henyeyGreenstien(cos\Theta) = mix(forward, backward, 0.4) \times 0.4
  $$
  where
  $$
  forward = \frac{1 - g_1^2}{(1 + g_1^2 - 2g_1 cos\Theta)^{1.5}}, \quad g_1 = 0.7
  $$
  $$
  backward = \frac{1 - g_2^2}{(1 + g_2^2 - 2g_2 cos\Theta)^{1.5}}, \quad g_2 = -0.2
  $$
  [S1, unofficial].
- **Beer-Lambert Law:** $transmittance *= exp(-density \times extinctionCoeff \times STEP\_SIZE \times 1.5)$ [S1, unofficial]. The source implementation applies an additional multiplier of 1.5 to the exponent [S1, unofficial].
- **Single Scattering Approximation:** $scattering = (1. - localTransmittance) \times currentLightRayT$ [S2, unofficial].

**Pseudocode:**

```python
def ray_march_single_scattering(e, s, uTime, sunset):
    # Constants from sources [S1, unofficial]
    MAX_STEPS = 50
    STEP_SIZE = 0.08
    MAX_STEPS_LIGHT = 5
    STEP_SIZE_LIGHT = 0.6
    WIND = (0.7, 0.2, -0.5)
    SUN = normalize((1.5, 1.0, 1.0))
    SUN_COLOUR_SUNSET = (1.8, 1.1, 0.6)
    SUN_COLOUR_DAY = (1.5, 1.3, 0.9)
    scatteringCoeff = 1.5 if sunset else 1.2
    absorptionCoeff = 0.4 if sunset else 0.2
    extinctionCoeff = scatteringCoeff + absorptionCoeff
    maxOctaves = 4  # Standard fBm iteration count [G]

    rayDir = normalize(vec_sub(s, e))
    sky = calculate_sky_color(rayDir, sunset)
    sunColour = SUN_COLOUR_SUNSET if sunset else SUN_COLOUR_DAY

    transmittance = 1.0
    t = 0.0
    colour = (0.0, 0.0, 0.0)

    for i in range(MAX_STEPS):
        p = vec_add(e, vec_scale(rayDir, t))

        # S1 uses sphere SDF for soft boundary [S1, unofficial]
        dist = -length(p) + 2.0
        if dist <= 0.0:
            t += STEP_SIZE
            continue

        density = clamp(octaves(vec_add(p, vec_scale(WIND, uTime)), maxOctaves), 0.0, 1.0)
        density *= smoothstep(0.0, 1.0, dist)

        if density < 0.01:
            t += STEP_SIZE
            continue

        # Light march [S1, unofficial]
        transmittanceLight = 1.0
        tLight = 0.0
        for j in range(MAX_STEPS_LIGHT):
            pLight = vec_add(p, vec_scale(SUN, tLight))
            densityLight = clamp(octaves(vec_add(pLight, vec_scale(WIND, uTime)), maxOctaves), 0.0, 1.0)

            if transmittanceLight < 0.05:
                break

            transmittanceLight *= exp(-densityLight * extinctionCoeff * STEP_SIZE_LIGHT * 1.5)
            tLight += STEP_SIZE_LIGHT

        cosTheta = dot(rayDir, SUN)
        phase = henyey_greenstein(cosTheta)
        ambient = vec_scale(sky, 0.7)
        scattered = vec_scale(vec_add(vec_scale(sunColour, transmittanceLight * phase * 6.0), ambient), scatteringCoeff)

        localTransmittance = exp(-density * extinctionCoeff * STEP_SIZE * 1.5)
        colour = vec_add(colour, vec_scale(scattered, transmittance * density * STEP_SIZE))

        transmittance *= localTransmittance
        if transmittance < 0.01:
            break
        t += STEP_SIZE
        
        if t > 20.0:
            break

    colour = vec_add(colour, vec_scale(sky, transmittance))
    return (colour[0], colour[1], colour[2], 1.0)

def calculate_sky_color(rayDir, sunset):
    screenRange = clamp(rayDir.y * 0.5 + 0.5, 0.0, 1.0)
    if sunset:
        skyTop = (0.15, 0.30, 0.60)
        skyBottom = (0.85, 0.45, 0.30)
    else:
        skyTop = (0.2, 0.4, 0.8)
        skyBottom = (0.7, 0.85, 1.0)
    return vec_mix(skyBottom, skyTop, screenRange)

def henyey_greenstein(cosTheta):
    g1 = 0.7
    denom1 = 1.0 + g1 * g1 - 2.0 * g1 * cosTheta
    forward = (1.0 - g1 * g1) / pow(denom1, 1.5)
    
    g2 = -0.2
    denom2 = 1.0 + g2 * g2 - 2.0 * g2 * cosTheta
    backward = (1.0 - g2 * g2) / pow(denom2, 1.5)
    
    return vec_mix(forward, backward, 0.4) * 0.4

def octaves(p, maxOctaves):
    f = 0.0
    amp = 0.5
    freq = 2.0
    for _ in range(maxOctaves):
        noise_val = cnoise(p)  # or snoise(p)
        f += amp * noise_val
        p = vec_scale(p, freq)
        freq += 0.20
        amp *= 0.5
    return f

# Vector helpers for self-contained Python
def vec_add(a, b): return (a[0]+b[0], a[1]+b[1], a[2]+b[2])
def vec_sub(a, b): return (a[0]-b[0], a[1]-b[1], a[2]-b[2])
def vec_scale(v, s): return (v[0]*s, v[1]*s, v[2]*s)
def vec_mix(a, b, t): return (a[0]+(b[0]-a[0])*t, a[1]+(b[1]-a[1])*t, a[2]+(b[2]-a[2])*t)
def dot(a, b): return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]
def length(v): return (v[0]**2 + v[1]**2 + v[2]**2)**0.5
def normalize(v): l = length(v); return (v[0]/l, v[1]/l, v[2]/l)
def clamp(x, mn, mx): return max(mn, min(mx, x))
def smoothstep(edge0, edge1, x): t = max(0.0, min(1.0, (x-edge0)/(edge1-edge0))); return t*t*(3.0-2.0*t)
def exp(x): import math; return math.exp(x)
def pow(base, exp): import math; return math.pow(base, exp)
def cnoise(p): return 0.0  # Placeholder for procedural noise implementation [G]
def snoise(p): return 0.0  # Placeholder for procedural noise implementation [G]
```

**Edge Cases and Pitfalls:**
- **Low Density Optimization:** If density < 0.01, the step is skipped to save computation, but $t$ is still incremented [S1, unofficial].
- **Early Exit for Light:** If light transmittance drops below 0.05, the light march stops [S1, unofficial].
- **Early Exit for Main Ray:** If main transmittance drops below 0.01, the main march stops [S1, unofficial].
- **Max Distance Limit:** The main march stops if $t$ exceeds 20.0 [S1, unofficial].
- **WebGL 1 Limitation:** Dynamic loop bounds are not supported, so $STEP\_SIZE$ and $STEP\_SIZE\_LIGHT$ must be hardcoded constants [S2, unofficial].
- **Precision:** The Beer-Lambert law uses an additional multiplier of 1.5 in the exponent in the source implementation [S1, unofficial], which may deviate from standard physical definitions [G].

## Operating characteristics
- **Time Complexity:** $O(MAX\_STEPS \times MAX\_STEPS\_LIGHT)$ per fragment [G]. With $MAX\_STEPS=50$ and $MAX\_STEPS\_LIGHT=5$, this is 250 noise evaluations and transmittance calculations per pixel [S1, unofficial].
- **Memory Complexity:** $O(1)$ for procedural noise [G]. If using texture-based density, $O(textureWidth \times textureHeight \times 4)$ for the texture buffer [S2, unofficial].
- **Measured Performance:** Not given in the sources [S1, S2, unofficial].
- **Scaling:** Quality can be increased by decreasing $STEP\_SIZE$ and $STEP\_SIZE\_LIGHT$, but this increases computational cost linearly [S2, unofficial].
- **Strengths:** Real-time performance on WebGL 1/2 hardware; physically-based single scattering approximation; procedural noise allows infinite resolution and easy animation [S1, S2, unofficial].
- **Limitations:** Single scattering approximation is less physically accurate than multiple scattering [S2, unofficial]; procedural noise may lack the detailed structure of texture-based volumes; WebGL 1 requires hardcoded step sizes [S2, unofficial].
- **When to use:** Real-time cloud rendering in games or interactive applications where performance is critical [S1, unofficial].
- **When not to use:** Offline rendering requiring high physical accuracy or complex multiple scattering effects [S2, unofficial].

## Background
This technique originates from real-time OpenGL/WebGL implementations of volumetric cloud rendering [S1, S2, unofficial]. It was popularized by demos and open-source projects such as `gmanishaa/volumetric-rendering` and `M4trixStrike/WebGL-Volumetric-clouds` [S1, S2, unofficial]. The method combines classic ray marching with single scattering approximation, using procedural noise for density and Henyey-Greenstein phase function for light scattering [S1, unofficial]. It is used in real-time graphics engines and web-based visualizations [S1, S2, unofficial].
