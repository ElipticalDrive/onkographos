# Shadow Occlusion via Occlusion Camera

Also called: Light-space shadow maps, Volumetric shadow maps

## Overview
Shadow Occlusion via Occlusion Camera is a technique that uses a child camera (OcclusionCam) to capture a depth map from the light's point of view, allowing geometry to block the volumetric beam [S1, unofficial]. Unlike standard URP shadows, this occlusion map does not depend on the light's Shadow Type or URP shadow settings; it works independently, enabling volumetric shadows even when the light casts no regular shadows [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Inputs:** Light position, direction, and type (Spot, Rect, Disc, Point); Volume entry/exit points; Occlusion map texture (depth); Shadow map resolution; Culling mask.
*   **Outputs:** Shadow density value per ray step.

**Data Structures:**
*   **Occlusion Map:** A depth texture generated by the OcclusionCam. Resolution is configurable (32–4096, default 256) [S1, unofficial].
*   **Shadow Coordinates:** 2D texture coordinates derived from the light's view space, interpolated along the ray [S1, unofficial].

**Steps:**
1.  **Capture:** Render a lightweight depth-only pass from the OcclusionCam to generate the occlusion map [S1, unofficial].
    *   For Point lights, use specific capture modes: Half Sphere (160 degrees, fastest), Cubemap One Face Per Frame, or Cubemap All 6 Faces Per Frame (slowest) [S1, unofficial].
2.  **Compute Entry/Exit:** In the ray marching shader, compute shadow coordinates at the ray's entry point and exit point from the volume [S1, unofficial].
3.  **Interpolate:** Interpolate shadow coordinates between entry and exit along the ray for each step [S1, unofficial].
4.  **Sample:** Sample the occlusion map texture for each step to determine shadow density [S1, unofficial].

**Parameters:**
*   **Resolution:** 32 to 4096. Default 256. Higher values needed for fine patterns like window bars [S1, unofficial].
*   **Intensity and Color:** Shadow color blending. The shadowed part of the beam blends toward this color instead of black [S1, unofficial].
*   **Culling Mask:** Layers that occlude the beam. TransparentFX layer is excluded unless Include Transparent is on [S1, unofficial].
*   **Include Transparent:** If on, transparent geometry and 2D sprites block light if they write depth via a DepthOnly pass [S1, unofficial].
*   **Near Clip Distance:** Near plane of the OcclusionCam. Used when the light is inside a model (e.g., a lamp) [S1, unofficial].

**Pitfalls:**
*   Point lights require specific capture modes which have significant performance implications [S1, unofficial].
*   Transparent geometry only occludes if it writes depth [S1, unofficial].

## Operating characteristics
*   **Performance:** Depends on shadow map resolution and point light capture mode. Half Sphere is fastest; Cubemap All 6 Faces Per Frame is slowest [S1, unofficial].
*   **Quality:** Beams are soft, so 256 resolution is often sufficient. Higher resolutions improve sharpness for thin occluders [S1, unofficial].
*   **Independence:** Does not rely on URP shadow settings [S1, unofficial].

## Background
This method is part of the Volumetric Lighting system in Unity URP, utilizing a dedicated child camera for depth capture [S1, unofficial].
