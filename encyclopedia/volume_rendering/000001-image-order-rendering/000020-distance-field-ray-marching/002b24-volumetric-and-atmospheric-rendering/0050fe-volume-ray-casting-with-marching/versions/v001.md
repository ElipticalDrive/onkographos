# Volume Ray Casting with Marching

Also called: Front-to-Back Ray Casting, Marching along the point of view, Ray Casting with Adaptive Step Size and Early Ray Termination, Volume Rendering via Ray Casting

## Overview
Volume Ray Casting with Marching is an image-order rendering technique that casts rays from the camera through a scalar volume, sampling the field at discrete intervals to accumulate color and opacity using front-to-back compositing [S2, unofficial]. It distinguishes itself from sibling methods by explicitly combining a fixed-step traversal with jittered sampling to mitigate aliasing, early ray termination (ERT) for performance, and opacity correction to maintain physical accuracy despite discrete stepping [S2, unofficial]. Unlike [SDF Cloud Rendering](2064-sdf-cloud-rendering.md) which uses signed distance fields for surface extraction, this method directly integrates volumetric properties [S2, unofficial].

## How it works
**Inputs:**
*   Volume texture (scalar field), typically 8-bit, 16-bit, or float [S2, unofficial].
*   Colormap texture (2D, mapping scalar value to RGBA) [S2, unofficial].
*   Volume bounding box defined by `box_min` and `box_max` [S2, unofficial].
*   Camera parameters: origin $\mathbf{o}$, direction $\mathbf{d}$, and volume dimensions `volume_dims` [S2, unofficial].
*   Step size scaling factor `dt_scale` [S2, unofficial].

**Outputs:**
*   Accumulated color $C$ and opacity $\alpha$ for each pixel [S2, unofficial].

**Data Structures:**
*   **Volume Texture:** 3D texture. Access via normalized coordinates. For 16-bit data, values are read as integers and divided by 65536.0; for 8-bit/float, read directly [S2, unofficial].
*   **Colormap Texture:** 2D texture. The x-coordinate represents the normalized scalar value, and the y-coordinate is fixed at 0.5 [S2, unofficial].

**Algorithm Steps:**

1.  **Ray Setup:**
    *   Calculate the ray direction $\mathbf{d} = \text{normalize}(\mathbf{v}_{ray})$ [S2, unofficial].
    *   Intersect the ray with the volume bounding box to find entry distance $t_0$ and exit distance $t_1$ [S2, unofficial].
    *   If $t_0 > t_1$, discard the ray [S2, unofficial].
    *   Clamp entry distance: $t_{hit} = \max(t_0, 0.0)$ [S2, unofficial].

2.  **Step Size Calculation:**
    *   Compute the base step size $dt$ based on volume dimensions and ray direction [S2, unofficial]:
        $$ dt = dt_{scale} \times \min \left( \frac{1}{|d_x| \cdot D_x}, \frac{1}{|d_y| \cdot D_y}, \frac{1}{|d_z| \cdot D_z} \right) $$
        where $D_x, D_y, D_z$ are the volume dimensions [S2, unofficial].

3.  **Jittering:**
    *   Generate a random offset to jitter the starting position within the first voxel to reduce aliasing artifacts (e.g., 'wood grain') [S2, unofficial].
    *   Calculate offset using a hash function (e.g., `wang_hash`) on fragment coordinates [S2, unofficial]:
        $$ \text{offset} = \text{wang\_hash}(\text{int}(gl\_FragCoord.x + 640.0 \cdot gl\_FragCoord.y)) $$
    *   [G] The hash output is typically normalized to $[0, 1)$ or $[-0.5, 0.5)$. The source implies it scales with $dt$.

4.  **Initialization:**
    *   Initialize sample position $\mathbf{p}$:
        $$ \mathbf{p} = \mathbf{o} + (t_{hit} + \text{offset} \cdot dt) \cdot \mathbf{d} $$
    *   Initialize accumulated color $C = (0, 0, 0)$ and opacity $\alpha = 0$ [S2, unofficial].

5.  **Marching Loop:**
    *   Loop from current distance $t = t_{hit}$ to $t_1$ with step $dt$ [S2, unofficial].
    *   **Sample:** Read scalar value $v$ from volume texture at $\mathbf{p}$ [S2, unofficial].
        *   If 16-bit: $v = \text{texture}(\text{volume}, \mathbf{p}).r / 65536.0$ [S2, unofficial].
        *   Else: $v = \text{texture}(\text{volume}, \mathbf{p}).r$ [S2, unofficial].
    *   **Map:** Retrieve RGBA from colormap: $\mathbf{c}_{map} = \text{texture}(\text{colormap}, (v, 0.5))$ [S2, unofficial].
    *   **Combine:** Form segment color $\mathbf{c}_{seg}$ and opacity $\alpha_{seg}$:
        $$ \mathbf{c}_{seg} = \mathbf{c}_{map}.rgb $$
        $$ \alpha_{seg} = v \cdot \mathbf{c}_{map}.a $$
    *   **Opacity Correction:** Adjust opacity for the step size to approximate integral absorption [S2, unofficial]:
        $$ \alpha_{corrected} = 1 - (1 - \alpha_{seg})^{dt_{scale}} $$
    *   **Accumulate (Front-to-Back):**
        $$ C \leftarrow C + (1 - \alpha) \cdot \alpha_{corrected} \cdot \mathbf{c}_{seg} $$
        $$ \alpha \leftarrow \alpha + (1 - \alpha) \cdot \alpha_{corrected} $$
    *   **Early Ray Termination (ERT):** If $\alpha \ge 0.95$, break loop [S2, unofficial].
    *   **Advance:** $\mathbf{p} \leftarrow \mathbf{p} + \mathbf{d} \cdot dt$ [S2, unofficial].

6.  **Finalization:**
    *   Draw frame around volume and generate color maps if not pre-computed [S1, unofficial].
    *   Update controller and view matrix based on previous state, applying rescaling if necessary [S1, unofficial].

**Pseudocode:**

```python
def volume_ray_casting(ray_origin, ray_dir, volume_tex, colormap_tex, volume_dims, dt_scale):
    # 1. Ray-Bbox Intersection
    # Simplified AABB intersection logic
    inv_dir = 1.0 / ray_dir
    t0 = (volume_dims.min - ray_origin) * inv_dir
    t1 = (volume_dims.max - ray_origin) * inv_dir
    t_enter = max(min(t0), min(t1))
    t_exit = min(max(t0), max(t1))
    
    if t_enter > t_exit:
        return vec3(0.0) # Ray misses volume

    t_hit = max(t_enter, 0.0)
    
    # 2. Step Size Calculation
    # dt_vec = 1.0 / (volume_dims * abs(ray_dir))
    dt_vec = 1.0 / (volume_dims * abs(ray_dir))
    dt = dt_scale * min(dt_vec.x, dt_vec.y, dt_vec.z)
    
    # 3. Jittering
    # Assuming fragment coordinates are available as global or passed
    # offset = wang_hash(int(gl_FragCoord.x + 640.0 * gl_FragCoord.y))
    # Note: wang_hash returns integer, needs normalization. 
    # Source implies offset * dt is added. Let's assume hash returns [0, 2^32) or similar.
    # For implementation, we assume a normalized random float [0, 1) derived from hash.
    hash_val = wang_hash(int(gl_FragCoord.x + 640.0 * gl_FragCoord.y))
    jitter = normalize_hash(hash_val) # [0, 1)
    p = ray_origin + (t_hit + jitter * dt) * ray_dir
    
    # 4. Initialization
    acc_color = vec3(0.0)
    acc_alpha = 0.0
    
    # 5. Marching Loop
    current_t = t_hit
    while current_t < t_exit:
        # Sample Volume
        # val = texture(volume, p).r
        # If 16-bit data: val /= 65536.0
        val = texture(volume_tex, p).r
        
        # Map to Color
        trans_sample = texture(colormap_tex, vec2(val, 0.5))
        seg_color = trans_sample.rgb
        seg_alpha_raw = val * trans_sample.a
        
        # Opacity Correction
        seg_alpha = 1.0 - pow(1.0 - seg_alpha_raw, dt_scale)
        
        # Accumulate
        # color.rgb += (1.0 - color.a) * val_color.a * val_color.rgb
        # color.a += (1.0 - color.a) * val_color.a
        weight = (1.0 - acc_alpha) * seg_alpha
        acc_color += weight * seg_color
        acc_alpha += weight
        
        # Early Ray Termination
        if acc_alpha >= 0.95:
            break
            
        # Advance
        p += ray_dir * dt
        current_t += dt
        
    return acc_color
```

**Edge Cases and Pitfalls:**
*   **Aliasing:** Lack of jittering causes 'wood grain' artifacts [S2, unofficial].
*   **Flat Surfaces:** Jittering can cause artifacts on flat surfaces ('with offset is bad for flat surfaces') [S2, unofficial].
*   **16-bit Data:** Requires division by 65536.0 to normalize [S2, unofficial].
*   **Performance:** ERT threshold of 0.95 is used to terminate rays early [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N)$ per pixel, where $N$ is the number of steps along the ray. $N$ depends on volume depth and step size $dt$.
*   **Memory Complexity:** $O(V)$ for volume texture storage, $O(C)$ for colormap.
*   **Performance:** Early Ray Termination (ERT) significantly reduces average computation time for opaque volumes [S2, unofficial].
*   **Strengths:** Simple to implement; jittering reduces aliasing; ERT improves performance [S2, unofficial].
*   **Limitations:** Fixed step size may lead to inaccuracies or aliasing if not jittered; jittering can artifact flat surfaces [S2, unofficial].
*   **When to use:** Real-time visualization of scalar volumes where aliasing is a concern and simple compositing is sufficient [S2, unofficial].
*   **When not to use:** When high-fidelity lighting (multiple scattering) is required, or when the volume has very thin structures that might be missed by large steps [S2, unofficial].

## Background
This method is described in the context of WebGL-based numerical PDE visualization and the VisWeb library [S1, S2, unofficial]. It is presented as a standard technique for volume rendering in web environments, leveraging GPU shaders for parallel ray casting [S1, S2, unofficial]. The specific implementation details, including jittering and opacity correction, are derived from the VisWeb project [S2, unofficial].
