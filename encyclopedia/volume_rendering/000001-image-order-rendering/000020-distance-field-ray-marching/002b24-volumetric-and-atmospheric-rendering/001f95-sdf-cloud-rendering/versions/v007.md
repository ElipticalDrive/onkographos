# SDF Cloud Rendering

Also called: Warped Sphere SDF Clouds

## Overview
SDF Cloud Rendering is a technique for rendering volumetric cloud-like structures using Signed Distance Fields (SDFs) via ray marching in a fragment shader, utilizing warped sphere primitives and smooth unions to create complex shapes [S1, unofficial]. It differs from standard volumetric rendering by representing the cloud density implicitly through a single continuous distance function rather than a sampled density volume, allowing for sharp, organic shapes with minimal memory overhead [S1, unofficial]. It builds on [Volumetric and Atmospheric Rendering](4968-volumetric-and-atmospheric-rendering.md) by replacing the density integration step with a surface intersection check on a deformed implicit geometry.

## How it works
The method constructs a scene SDF by warping space with a procedural noise function and combining primitive spheres using smooth boolean operations. Ray marching is performed to find the intersection with this implicit surface, followed by a shadowing pass to determine lighting.

### Inputs and Outputs
*   **Inputs**: Fragment coordinates (`gl_FragCoord`), screen size, camera field of view, a random seed for noise variation.
*   **Outputs**: Final color value for the pixel.

### Data Structures
No external data structures are used. All geometry is defined implicitly via functions. The only state maintained during execution is the ray depth and accumulated shadow factor.

### Parameters
*   `MAX_MARCHING_STEPS`: Integer constant, value `100` [S1, unofficial].
*   `MIN_DIST`: Float constant, value `0.0` [S1, unofficial].
*   `MAX_DIST`: Float constant, value `100.0` [S1, unofficial].
*   `EPSILON`: Float constant, value `0.0001` [S1, unofficial].
*   `STEP_SCALE`: Float constant, value `0.67` [S1, unofficial].
*   `EXPOSURE`: Float constant, value `1.0` [S1, unofficial].
*   `WHITE`: Float constant, value `200.0` [S1, unofficial].
*   `LIGHT`: Constant vector, value `vec3(-10.0, 10.0, 3.0)` [S1, unofficial].
*   `DARK`: Constant vector, value `vec3(5.0, 8.0, 20.0)` [S1, unofficial].
*   `LIGHT_COLOR`: Constant vector, value `vec3(100.0, 100.0, 100.0)` [S1, unofficial].

### Formulas
1.  **Jitter Noise**:
    $$ \text{jitter}(m, o) = 0.09 \sum_{p=0}^{2} \frac{\sin((o + \text{seed} + m \cdot 1234.0) \cdot 2^p)}{2^p} $$
    Where $m$ is the mix amount (coordinate component), $o$ is the offset, and seed is a global random value [S1, unofficial].

2.  **Space Warping**:
    $$ \text{warp}(\mathbf{v}, s) = \mathbf{v} + s \cdot \begin{bmatrix} \text{jitter}(v_x, 0.0) \\ \text{jitter}(v_y, 0.2) \\ \text{jitter}(v_z, 0.5) \end{bmatrix} $$
    Where $\mathbf{v}$ is the input vector and $s$ is the warp scale (typically `1.5`) [S1, unofficial].

3.  **Smooth Union**:
    $$ \text{smoothUnion}(d_1, d_2, k) = \text{mix}(d_2, d_1, h) - k \cdot h \cdot (1.0 - h) $$
    Where $h = \text{clamp}(0.5 + 0.5 \cdot \frac{d_2 - d_1}{k}, 0.0, 1.0)$ and $k$ is the blending factor (typically `0.4`) [S1, unofficial].

4.  **Sphere SDF**:
    $$ \text{sphereSDF}(\mathbf{p}, \mathbf{c}, r) = \|\mathbf{p} - \mathbf{c}\| - r $$
    Where $\mathbf{p}$ is the sample point, $\mathbf{c}$ is the center, and $r$ is the radius [S1, unofficial].

5.  **Scene SDF**:
    $$ \text{sceneSDF}(\mathbf{p}) = \min(\text{smoothUnion}(\text{sphereSDF}(\mathbf{w}, \mathbf{c}_1, r_1), \text{sphereSDF}(\mathbf{w}, \mathbf{c}_2, r_2), 0.4), \text{sphereSDF}(\mathbf{w}, \mathbf{c}_3, r_3)) $$
    Where $\mathbf{w} = \text{warp}(\mathbf{p}, 1.5)$, $\mathbf{c}_1=(0.5, 0.0, 0.0), r_1=1.0$, $\mathbf{c}_2=(-0.5, -0.4, 0.2), r_2=0.5$, $\mathbf{c}_3=(-0.8, 0.55, 0.2), r_3=0.3$ [S1, unofficial].

6.  **Shadow Estimation**:
    $$ \text{shadow}(\mathbf{o}, \mathbf{d}) = \min_{i} \left( 1.0, \min_{j} \left( \frac{k \cdot h_j}{t_j} \right) \right) $$
    Where $k=2.0$, $t$ starts at $100.0 \cdot \text{EPSILON}$, $h_j = \text{sceneSDF}(\mathbf{o} + t_j \cdot \mathbf{d})$, and $t_{j+1} = t_j + h_j \cdot \text{STEP\_SCALE}$ [S1, unofficial].

7.  **Hable Tone Mapping**:
    $$ \text{toneMap}(x) = \frac{x(Ax + CB) + DE}{x(Ax + B) + DF} - \frac{E}{F} $$
    With $A=0.15, B=0.50, C=0.10, D=0.20, E=0.02, F=0.30$ [S1, unofficial].

### Pseudocode

```python
def jitter(mix_amount, offset, seed):
    amount = 0.0
    scale = 1.0
    offset += seed
    for power in range(3):
        amount += sin((offset * 1234.0 + mix_amount) * scale) / scale
        scale *= 2.0
    return amount * 0.09

def warp(v, scale, seed):
    return v + scale * vec3(
        jitter(v.x, 0.0, seed),
        jitter(v.y, 0.2, seed),
        jitter(v.z, 0.5, seed)
    )

def smooth_union(d1, d2, k):
    h = clamp(0.5 + 0.5 * (d2 - d1) / k, 0.0, 1.0)
    return mix(d2, d1, h) - k * h * (1.0 - h)

def sphere_sdf(sample_point, origin, radius):
    return length(sample_point - origin) - radius

def scene_sdf(sample_point, seed):
    warped = warp(sample_point, 1.5, seed)
    d1 = sphere_sdf(warped, vec3(0.5, 0.0, 0.0), 1.0)
    d2 = sphere_sdf(warped, vec3(-0.5, -0.4, 0.2), 0.5)
    smoothed = smooth_union(d1, d2, 0.4)
    d3 = sphere_sdf(warped, vec3(-0.8, 0.55, 0.2), 0.3)
    return min(smoothed, d3)

def ray_direction(field_of_view, size, frag_coord):
    xy = frag_coord - size / 2.0
    z = size.y / tan(radians(field_of_view) / 2.0)
    return normalize(vec3(xy, -z))

def ray_march(eye, marching_direction, start, end, seed):
    depth = start
    for i in range(100):
        dist = scene_sdf(eye + depth * marching_direction, seed)
        if dist < 0.0001:
            return depth
        depth += dist * 0.67
        if depth >= end:
            return end
    return end

def shadow_calc(origin, dir, seed):
    k = 2.0
    t = 100.0 * 0.0001
    res = 1.0
    for i in range(100):
        h = scene_sdf(origin + t * dir, seed)
        if h < 0.0001:
            return 0.0
        t += h * 0.67
        res = min(res, k * h / t)
    return res

def tone_map(x):
    A = 0.15
    B = 0.50
    C = 0.10
    D = 0.20
    E = 0.02
    F = 0.30
    return (x * (A * x + C * B) + D * E) / (x * (A * x + B) + D * F) - E / F

def render(frag_coord, screen_size, seed):
    dir = ray_direction(45.0, screen_size, frag_coord)
    eye = vec3(0.0, 0.0, 8.0)
    dist = ray_march(eye, dir, 0.0, 100.0, seed)

    if dist > 100.0 - 0.0001:
        d = dot(dir, normalize(vec3(0.0, -1.0, 0.0)))
        d = d * 6.0
        d = d / 2.0 + 0.5
        d = max(0.0, min(1.0, d))
        return mix(vec3(4.0, 40.0, 100.0), vec3(20.0, 100.0, 100.0), d)

    intersection = eye + dist * dir
    to_light = normalize(vec3(-10.0, 10.0, 3.0) - intersection)
    shadow_val = shadow_calc(intersection, to_light, seed)
    
    dark = vec3(5.0, 8.0, 20.0)
    light_color = vec3(100.0, 100.0, 100.0)
    color = mix(dark, light_color, shadow_val)
    
    return color

def main(frag_coord, screen_size, seed):
    color = render(frag_coord, screen_size, seed)
    exposure = 1.0
    white = 200.0
    w_scale = 1.0 / tone_map(exposure * white)
    final_color = tone_map_vec(exposure * color) * w_scale
    return final_color
```

### Edge Cases and Pitfalls
*   **Precision**: The use of `float` precision in fragment shaders may cause jittering or artifacts if `EPSILON` is too small relative to the scene scale. The source uses `0.0001` [S1, unofficial].
*   **Overshooting**: The `STEP_SCALE` of `0.67` is used to prevent the ray from overshooting the surface due to the non-linear nature of the warped SDF. Using a scale of `1.0` may cause the ray to pass through the surface without detection [S1, unofficial].
*   **Shadow Artifacts**: The shadow calculation uses a heuristic (`k*h/t`) rather than a binary occlusion test. This can result in soft, slightly inaccurate shadows if the step size is too large or the number of steps is insufficient [S1, unofficial].

## Subtopics

### Warped SDFs
A variation where space is deformed by noise before SDF evaluation, creating organic, non-Euclidean shapes. Chosen when organic, cloud-like, or fluid shapes are desired over rigid primitives. [Link to Warped SDFs](52-warping-sdfs.md).

### Smooth Boolean Operations
Techniques like `smoothUnion` that blend SDFs continuously. Chosen when sharp edges are undesirable and a more natural, blended appearance is needed. [Link to Smooth Booleans](53-smooth-boolean-operations.md).

## Operating characteristics
*   **Time Complexity**: $O(N \cdot M)$ where $N$ is the number of pixels and $M$ is the maximum marching steps (100 in the source). Each step involves a warp and multiple SDF evaluations [S1, unofficial].
*   **Memory Complexity**: $O(1)$. No textures or volumes are stored; all geometry is procedural [S1, unofficial].
*   **Performance**: Fast on modern GPUs due to lack of memory bandwidth constraints, but limited by the complexity of the SDF function and the number of marching steps. The specific implementation uses 100 steps per ray, which can be expensive for high-resolution renders [S1, unofficial].
*   **Strengths**: Extremely low memory footprint, sharp details, easy to animate by changing the seed or warp parameters.
*   **Limitations**: Cannot represent true volumetric effects like subsurface scattering or internal density variations easily. The "cloud" appearance is purely based on surface lighting and shadowing, not volume integration.
*   **When to use**: Real-time rendering of stylized clouds, smoke, or organic shapes where memory is constrained and true volumetric lighting is not required.
*   **When not to use**: When physically accurate volumetric scattering, fog, or internal light transport is needed.

## Background
The method was created by Dave Pagurek as a small experiment in rendering with signed distance fields, presented at Graphics Interface 2019 [S1, unofficial]. It demonstrates the potential of SDFs for creating complex, organic shapes without the need for traditional mesh or volume data. The technique relies on the mathematical properties of SDFs, specifically the Lipschitz condition, which guarantees that the distance value is a lower bound on the distance to the surface, allowing for safe ray marching [S2, S5, 9643].
