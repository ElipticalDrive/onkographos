# Terrain Raymarching

Also called: Heightmap Raymarching

## Overview
Terrain Raymarching renders 2D heightmap terrains by casting rays through each pixel and stepping along the ray until the ray's height drops below the terrain surface defined by the heightmap value at the ray's xz position [S1, unofficial]. It distinguishes itself from standard raycasting by its simplicity in handling high-level detail via procedural or texture-based heightmaps, and from voxel rendering by operating on a 2D height function rather than a 3D occupancy grid [S1, unofficial]. Unlike [Heightfield Rendering](1634-heightfield-rendering.md), which fills vertical screen segments from the calculated terrain height down to the horizon for each column, Terrain Raymarching typically marches a single ray per pixel to find the first hit [S1, unofficial].

## How it works
**Inputs:**
- Camera position and projection matrix.
- Heightmap data (texture sampler or procedural function) $H(x, z)$, returning the terrain height at world coordinates $x, z$.
- Step size $\Delta s$ for ray marching.
- Maximum number of steps or maximum distance.

**Outputs:**
- Color buffer with terrain shading.

**Data Structures:**
- Heightmap: 2D array or texture mapping $(x, z) \rightarrow h$.

**Steps:**
1. For each pixel $(u, v)$ in the image, construct a ray origin $\mathbf{o}$ and direction $\mathbf{d}$ from the camera.
2. Initialize ray position $\mathbf{p} = \mathbf{o}$.
3. Loop for $i = 0$ to $N_{max}$:
   a. Sample the terrain height at the ray's current xz coordinates: $h_{terrain} = H(p_x, p_z)$.
   b. Get the ray's current height: $h_{ray} = p_y$.
   c. If $h_{ray} \le h_{terrain}$, the ray has hit the terrain. Break loop.
   d. Advance the ray: $\mathbf{p} = \mathbf{p} + \mathbf{d} \cdot \Delta s$.
4. If a hit was found, determine the color based on the height $h_{terrain}$ (e.g., white for snow at high altitudes, green for grass at lower altitudes) [S1, unofficial].
5. Shade the hit point by raymarching towards a light source to compute lighting [S1, unofficial].

**Parameters:**
- Step size $\Delta s$: Not given in the sources.
- Maximum steps $N_{max}$: Not given in the sources.

**Edge Cases and Pitfalls:**
- If the step size is too large, the ray may skip over the terrain surface, resulting in no hit or incorrect depth.
- Precision issues may occur if the terrain height and ray height are very close but the step size causes overshooting.
- Procedural heightmaps must be consistent with the coordinate system used for ray sampling.

**Pseudocode:**
```python
def terrain_raymarching(camera, heightmap, step_size, max_steps):
    for each pixel (u, v):
        ray_origin = camera.get_origin(u, v)
        ray_direction = camera.get_direction(u, v)
        
        p = ray_origin
        hit = False
        
        for i in range(max_steps):
            # Get terrain height at current ray xz position
            terrain_h = heightmap.sample(p.x, p.z)
            
            # Check if ray is below terrain
            if p.y <= terrain_h:
                hit = True
                break
            
            # Step along the ray
            p = p + ray_direction * step_size
        
        if hit:
            # Determine color based on height
            if terrain_h > threshold_snow:
                color = WHITE
            else:
                color = GREEN
            
            # Shade the point by raymarching towards a light source
            color = shade_point(p, color, light_source)
            
            set_pixel_color(u, v, color)
```

## Subtopics

### Horizon Mapping
Horizon Mapping is a technique to describe the self-occlusion of a heightfield by calculating visibility [S2, unofficial]. Visibility is calculated by determining the altitude or horizon angle for a set of azimuth directions for every point in the surface [S2, unofficial]. This data is stored into a horizon map [S2, unofficial]. It is used to approximate shadows and ambient occlusion in terrain rendering without full ray tracing.

## Operating characteristics
Terrain Raymarching is computationally intensive per pixel due to the iterative stepping process, but it fits perfectly on the GPU as each pixel can be calculated independently [S1, unofficial]. The performance depends heavily on the step size and the complexity of the heightmap. Larger step sizes reduce the number of iterations but may lead to inaccuracies. The method allows for high-level detail rendering, which is a major advantage [S1, unofficial]. However, it may suffer from aliasing if the step size is not adaptive.

## Background
Terrain Raymarching is a general application of raymarching techniques, which have been used to render a variety of complex scenes [S1, unofficial]. The specific application to terrain rendering using heightmaps is discussed in the context of distance field raymarching [S1, unofficial]. The technique leverages the GPU's parallel processing capabilities to achieve real-time rendering speeds [S1, unofficial].
