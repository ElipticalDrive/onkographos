# Zeno Implementation

Also called: Zeno, Zeno Implementation for Implicit Surfaces

## Overview
The Zeno Implementation is a specific software architecture for sphere tracing that minimizes the interface required to define new implicit surfaces. It solves the problem of rapid prototyping for mathematical visualization by allowing users to define geometry solely through a signed distance bound, automatically deriving shading normals via numerical differentiation. It differs from general-purpose renderers by treating the distance bound as the primary geometric primitive and using a fixed six-sample gradient approximation to avoid explicit normal function definitions [S1, S2].

## How it works
The method extends the standard sphere tracing loop by integrating a specific shading strategy and a simplified primitive definition interface.

### Inputs and Outputs
- **Inputs**: Ray origin $ro$, ray direction $v$ (normalized), a distance bound function $d(p)$, and rendering parameters ($\text{MAX\_STEPS}$, $\text{HIT\_THRESHOLD}$, $\text{MAX\_RANGE}$).
- **Outputs**: Intersection point $p$, hit status (boolean), and surface normal $n$ (computed numerically).

### Data Structures
No complex scene graphs are required. The scene is defined by the composition of distance bound functions.
- **Distance Bound Function**: A function $d: \mathbb{R}^3 \rightarrow \mathbb{R}$ that returns the distance to the nearest surface.
- **Gradient Approximation**: Requires access to the function $d(p)$ at 6 specific offsets.

### Steps
1. **Initialize Ray**: Set current position $p = ro$.
2. **Sphere Trace Loop**:
   a. Evaluate distance bound: $dist = d(p)$.
   b. **Hit Check**: If $dist \le \text{HIT\_THRESHOLD}$, terminate loop and proceed to shading.
   c. **Penetration Check**: If $dist < 0$, the ray has penetrated the surface. Terminate loop and proceed to shading [S1, S2].
   d. **Advance**: $p \leftarrow p + dist \cdot v$.
   e. **Range Check**: If $\|p - ro\| > \text{MAX\_RANGE}$, terminate loop (miss).
   f. **Step Count**: If iteration count $> \text{MAX\_STEPS}$, terminate loop (miss).
3. **Shading (Normal Computation)**:
   If a hit is detected (steps 2b or 2c), compute the surface normal $n$ using a six-sample numerical gradient approximation of the distance bound gradient. The sources specify a "general six-sample" method [S1, S2]. The gradient $\nabla d(p)$ is approximated by evaluating $d(p)$ at $p \pm \epsilon \hat{x}$, $p \pm \epsilon \hat{y}$, and $p \pm \epsilon \hat{z}$, where $\hat{x}, \hat{y}, \hat{z}$ are the basis vectors and $\epsilon$ is a small step size. The normal is the normalized gradient:
   $$ n = \frac{\nabla d(p)}{\|\nabla d(p)\|} $$
   This approach avoids the need for an explicit analytic normal function [S1, S2].

### Pseudocode
```python
def zeno_sphere_trace(ro, v, distance_bound, max_steps=40, hit_threshold=0.001, max_range=100.0, grad_epsilon=0.001):
    p = ro
    for i in range(max_steps):
        dist = distance_bound(p)
        
        # Hit or penetration check
        if dist <= hit_threshold:
            normal = compute_numerical_normal(distance_bound, p, grad_epsilon)
            return p, True, normal
            
        # Advance
        p = p + v * dist
        
        # Range check
        if length(p - ro) > max_range:
            return p, False, None
            
    return p, False, None

def compute_numerical_normal(distance_bound, p, epsilon):
    # Six-sample gradient approximation
    # Gradient components
    dx = (distance_bound(p + vec3(epsilon, 0, 0)) - distance_bound(p - vec3(epsilon, 0, 0))) / (2 * epsilon)
    dy = (distance_bound(p + vec3(0, epsilon, 0)) - distance_bound(p - vec3(0, epsilon, 0))) / (2 * epsilon)
    dz = (distance_bound(p + vec3(0, 0, epsilon)) - distance_bound(p - vec3(0, 0, epsilon))) / (2 * epsilon)
    
    grad = vec3(dx, dy, dz)
    return normalize(grad)
```

### Parameters
- **$\text{HIT\_THRESHOLD}$**: Small epsilon for surface detection. Typical value: 0.001 [S1, S2].
- **$\text{MAX\_STEPS}$**: Safety cap for iteration count. Typical value: 40 [S1, S2].
- **$\text{MAX\_RANGE}$**: Maximum distance from ray origin. Typical value: 100.0 [S1, S2].
- **$\text{GRAD\_EPSILON}$**: Step size for numerical gradient. Not given in the sources.

### Edge Cases and Pitfalls
- **Penetration**: The implementation explicitly handles cases where $dist < 0$, which occurs if the ray starts inside the surface or overshoots due to precision issues. The negative part of the distance bound is only necessary for CSG and blending operations, not for simple visualization of zero-valued functions [S1, S2].
- **Performance**: The numerical gradient approximation is computationally inefficient compared to analytic normals. However, the sources state that since most time is spent on ray intersection, the impact on overall rendering performance is negligible [S1, S2].

## Operating characteristics
- **Time Complexity**: $O(N \cdot M)$, where $N$ is the number of pixels and $M$ is the average number of sphere tracing steps. The shading step adds a constant overhead of 6 distance evaluations per hit.
- **Memory Complexity**: $O(1)$ auxiliary memory per ray, as no scene graph or acceleration structures are required.
- **Strengths**: Extremely simple to implement for new implicit surfaces; only a distance bound function is required. Ideal for mathematical visualization and prototyping [S1, S2].
- **Limitations**: Numerical gradient approximation is less accurate than analytic normals and slightly slower per hit. Not suitable for scenes requiring high-performance shading or complex material definitions that require explicit normals [S1, S2].

## Background
The Zeno Implementation was developed as part of the Zeno rendering system, described in the paper "Sphere Tracing: A Geometric Method for the Antialiased Ray Tracing of Implicit Surfaces" by John Hart, et al. [S1, S2]. It was used for the animated short "Air on the Dirac Strings" (Sandin et al., 1993), which visualized a homotopy removing a 720° twist from a ribbon using interpolated quaternion rotations [S1, S2]. The system was designed to facilitate the investigation of new implicit surfaces and mathematical tasks by simplifying the inclusion of new primitives [S1, S2].
