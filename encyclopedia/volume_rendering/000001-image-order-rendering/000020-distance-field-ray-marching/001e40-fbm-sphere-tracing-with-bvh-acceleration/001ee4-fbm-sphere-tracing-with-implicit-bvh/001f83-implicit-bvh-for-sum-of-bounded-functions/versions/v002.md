# Implicit BVH for Sum of Bounded Functions

Also called: Procedural Bounding Volume Hierarchy

## Overview
This method accelerates ray marching for implicit surfaces defined by a sum of bounded functions $F_n(\mathbf{p}) = \sum_{i=1}^n f_i(\mathbf{p})$ by exploiting known value ranges of individual terms [S1]. It constructs an implicit hierarchy where partial sums act as bounding volumes for the final sum, enabling early termination when the potential range of the total function excludes the isosurface threshold [S1]. It differs from explicit spatial BVH approaches by computing bounds on-the-fly from pre-sorted function ranges rather than traversing a tree structure [S1].

## How it works
**Inputs:**
- A set of $n$ scalar functions $f_i: \mathbb{R}^d \to \mathbb{R}$, each bounded within $[-\Delta_{f_i}, \Delta_{f_i}]$ [S1].
- A target threshold value $v$ (typically $0$ for isosurfaces) [S1].
- A ray origin $\mathbf{o}$ and direction $\mathbf{d}$ for marching [G].

**Outputs:**
- The intersection distance $t$ along the ray, or a failure indicator if no intersection exists within the marching bounds [G].

**Data Structures:**
- **Precomputed Range Sum Array:** An array $S$ of size $n+1$ where $S[k] = s(k+1, n) = \sum_{m=k+1}^{n} \Delta_{f_m}$ for $k \in [0, n]$, with $S[n] = 0$ [S1].
- **Sorted Functions:** The functions $f_i$ must be sorted such that $\Delta_{f_1} \geq \Delta_{f_2} \geq \dots \geq \Delta_{f_n}$ [S1].

**Steps:**
1. **Preprocessing:** Compute $\Delta_{f_i}$ for all $i$ [S1]. Sort $f_i$ in descending order of $\Delta_{f_i}$ [S1]. Compute the suffix sums $s(i+1, n)$ for all $i \in [1, n]$ [S1].
2. **Ray Marching Initialization:** Start at $t=0$ [G].
3. **Iteration:** For each marching step:
   a. Evaluate the current position $\mathbf{p} = \mathbf{o} + t\mathbf{d}$ [G].
   b. Initialize partial sum $F_{current} = 0$ and current index $i=1$ [G].
   c. **Early Termination Check Loop:** While $i \leq n$:
      i. Evaluate $f_i(\mathbf{p})$ and update $F_{current} \leftarrow F_{current} + f_i(\mathbf{p})$ [S1].
      ii. Compute the inclusion interval for the final sum $F_n$ based on the current partial sum: $[F_n](\mathbf{p}) = F_{current} \pm s(i+1, n)$ [S1].
      iii. Check if the threshold $v$ lies outside this interval. If $v < F_{current} - s(i+1, n)$ or $v > F_{current} + s(i+1, n)$, then no root exists for $F_n$ at this $\mathbf{p}$ in the current direction. Terminate the ray march (return failure) [S1].
      iv. Increment $i \leftarrow i + 1$ [G].
   d. If the loop completes, $F_n(\mathbf{p}) = F_{current}$ is the exact function value [G].
   e. Check if $|F_n(\mathbf{p}) - v| < \epsilon$ (convergence). If yes, return $t$ [G].
   f. Compute step size $h$ (e.g., using Lipschitz constants if available, or a fixed step) and advance $t \leftarrow t + h$ [G].

**Formulas:**
- **Inclusion Function for Intermediate Sum:**
  $$[F_{i+1}](\mathbf{p}) = F_i(\mathbf{p}) \pm \Delta_{f_{i+1}} \quad (4)$$
  where $\Delta_f$ is the bound such that $f \in [-\Delta_f, \Delta_f]$ [S1].
- **Sum of Ranges:**
  $$s(i, j) = \sum_{m=i}^{j} \Delta_{f_m} \quad \text{for } j \geq i$$
  [S1].
- **Inclusion Function for Final Sum from Partial Sum:**
  $$[F_n](\mathbf{p}) = F_i(\mathbf{p}) \pm s(i+1, n) \quad (6)$$
  [S1].

**Parameters:**
- $\epsilon$: Convergence tolerance for ray marching. Not given in the sources.
- Step size strategy: Not given in the sources (depends on Lipschitz continuity assumptions in later sections) [S1].

**Edge Cases and Pitfalls:**
- **Unsorted Functions:** If functions are not sorted by descending $\Delta_{f_i}$, the early termination guarantee is weakened or invalid, potentially leading to incorrect skips or missed intersections [S1].
- **Invalid Bounds:** If $\Delta_{f_i}$ is not a tight bound, the inclusion interval becomes loose, reducing the effectiveness of early termination but maintaining correctness [S1].
- **Lipschitz Continuity:** This method assumes only boundedness for the inclusion logic. If the derivative is not Lipschitz continuous, standard sphere tracing step sizes may be invalid, requiring alternative marching strategies [S1].

**Pseudocode:**
```python
def ray_march_sum_of_bounded_functions(ray_origin, ray_direction, functions, deltas, threshold, max_steps, step_size):
    """
    functions: list of callable f_i(p)
    deltas: list of float Delta_f_i, sorted descending
    threshold: float v
    step_size: float h (fixed step or computed via Lipschitz bounds)
    """
    n = len(functions)
    # Precompute suffix sums s(i+1, n) for 0-indexed i
    # suffix_sums[k] stores sum of deltas from index k to n-1
    suffix_sums = [0.0] * (n + 1)
    current_sum = 0.0
    for i in range(n - 1, -1, -1):
        current_sum += deltas[i]
        suffix_sums[i] = current_sum
    
    t = 0.0
    for _ in range(max_steps):
        p = ray_origin + t * ray_direction
        
        partial_sum = 0.0
        early_stop = False
        
        for i in range(n):
            partial_sum += functions[i](p)
            
            # Inclusion interval for final sum F_n based on partial sum F_{i+1}
            # [F_n](p) = partial_sum +/- s(i+2, n) in 1-indexed math
            # In 0-indexed: remaining sum is suffix_sums[i+1]
            lower_bound = partial_sum - suffix_sums[i+1]
            upper_bound = partial_sum + suffix_sums[i+1]
            
            if threshold < lower_bound or threshold > upper_bound:
                early_stop = True
                break
        
        if early_stop:
            return None  # No intersection
        
        # If loop completes, partial_sum is the exact F_n(p)
        if abs(partial_sum - threshold) < 1e-6:
            return t
        
        # Advance ray
        t += step_size
        
    return None  # Max steps reached
```

## Subtopics

### Lipschitz Sphere Tracing
Uses derivative bounds to compute safe step sizes. Chosen when functions are differentiable and Lipschitz constants are known. Link: [Lipschitz Sphere Tracing](1902-lipschitz-sphere-tracing.md).

### Octree-Based BVH
Uses explicit spatial subdivision. Chosen for sparse scenes or when functions have complex spatial locality not captured by range bounds. Link: [Octree BVH](1903-octree-bvh.md).

## Operating characteristics
- **Time Complexity:** $O(n)$ per ray marching step in the worst case (evaluating all functions). Best case is $O(1)$ if early termination occurs at the first function [S1].
- **Memory Complexity:** $O(n)$ to store precomputed range sums and function references [S1].
- **Strengths:** No spatial data structure construction overhead; efficient for functions with rapidly decaying ranges (e.g., FBM octaves) [S1].
- **Limitations:** Requires prior knowledge of tight bounds $\Delta_{f_i}$; sorting overhead; less effective if bounds are loose or functions have similar ranges [S1].
- **When to Use:** When the implicit function is a sum of many bounded terms with known, decreasing ranges (e.g., procedural noise) [S1].
- **When Not to Use:** When functions are not bounded or bounds are unknown; when spatial coherence is high and explicit BVH is more efficient [S1].

## Background
Originated in the context of fast sphere tracing for procedural volumetric noise [S1]. The method was introduced to exploit the hierarchical nature of FBM (Fractional Brownian Motion) noise, where higher-frequency octaves have smaller amplitudes, allowing them to be treated as bounding volumes for lower-frequency sums [S1]. It is used in real-time rendering of procedural landscapes and materials [S1].
