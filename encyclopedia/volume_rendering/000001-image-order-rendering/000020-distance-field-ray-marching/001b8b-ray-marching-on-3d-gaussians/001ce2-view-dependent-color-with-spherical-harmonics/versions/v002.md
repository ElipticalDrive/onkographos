# View-dependent color with Spherical Harmonics

Also called: Spherical Harmonics (SH) for View-Dependent Color, Spherical Harmonics Color Evaluation, Spherical Harmonics Rendering, SH Render, Rendering with Spherical Harmonics, Spherical Harmonic Colour Model

## Overview
This method represents the view-dependent color of a 3D Gaussian primitive as a function of the viewing direction using spherical harmonics (SH) coefficients [S1]. It solves the problem of storing directional color variation (such as specular highlights and reflections) compactly without requiring per-ray neural network queries [S1]. Unlike simple point colors or view-independent diffuse shading, this model captures glossy effects by evaluating a fixed set of orthogonal basis functions on the unit sphere, allowing each Gaussian to exhibit different colors from different angles [S1]. It builds on [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md) by providing the color value $C_c(\mathbf{d})$ used during the compositing step.

## How it works
**Inputs and Outputs**
*   **Input:** A set of $N$ Gaussians. For each Gaussian $i$, the method requires:
    *   The viewing direction vector $\mathbf{d}_i$, normalized, pointing from the camera center to the Gaussian's mean position [S1].
    *   The SH coefficients stored for that Gaussian [S1].
*   **Output:** An RGB color vector $\mathbf{C}_i = [R_i, G_i, B_i]^T$ for each Gaussian [S1].

**Data Structures**
Each Gaussian stores 48 SH coefficients, organized as 16 coefficients per color channel (Red, Green, Blue) [S1]. The coefficients are stored contiguously in memory [S3]. The layout is:
*   Indices 0–2: Degree-0 (DC) coefficients for R, G, B respectively.
*   Indices 3–47: Higher-order coefficients for R, G, B interleaved or grouped depending on implementation, but logically corresponding to degrees 1, 2, and 3 [S3].
    *   Specifically, the first 3 elements are the DC color ($f_{dc}$), and the next 45 elements are the remaining coefficients ($f_{rest}$) [S3].
    *   The coefficients are scalars $k_{\ell, c}^m$ corresponding to basis functions $Y_{\ell}^m$ [S1].

**Spherical Harmonic Basis Constants**
The evaluation uses fixed normalization constants for each degree [S3]:
*   $SH\_C0 = 0.28209479177387814$
*   $SH\_C1 = 0.4886025119029199$
*   Degree 2 constants ($SH\_C2_0$ to $SH\_C2_4$) are defined in the source but exact values are not provided in the text excerpts [S3].

**Numbered Steps**
1.  **Compute Viewing Direction:** For each Gaussian, compute the normalized direction vector $\mathbf{d} = [x, y, z]^T$ from the camera center to the Gaussian's mean position [S1].
2.  **Initialize Color:** Initialize the output color vector $\mathbf{C}$ with the DC component (degree 0) scaled by $SH\_C0$ [S3].
    $$ \mathbf{C} = SH\_C0 \cdot [k_{0,R}^0, k_{0,G}^0, k_{0,B}^0]^T $$
3.  **Evaluate Degree 1 (if active):** If the SH degree is $\ge 1$, add contributions from the first-order coefficients using the direction components $x, y, z$ scaled by $SH\_C1$ [S3]. The specific linear combination depends on the SH convention, but generally involves terms like $y, z, x$ [S3].
    *   Note: Source [S3] code snippet shows: `color = color - SH_C1 * y * c1 + SH_C1 * z * c2 - SH_C1 * x * c3`. This implies a specific ordering of coefficients $c1, c2, c3$ corresponding to specific $m$ values.
4.  **Evaluate Degree 2 (if active):** If the SH degree is $\ge 2$, add contributions from second-order coefficients using quadratic direction terms ($xy, yz, 2zz-xx-yy, xz, xx-yy$) scaled by $SH\_C2$ constants [S3].
5.  **Evaluate Degree 3 (if active):** If the SH degree is $\ge 3$, add contributions from third-order coefficients using cubic direction terms [S3].
6.  **Apply Bias and Clamping:** Apply a bias of $+0.5$ and a ReLU activation to the resulting RGB values to ensure non-negative color values [S4].
    $$ \mathbf{C}_{final} = \text{ReLU}(\mathbf{C} + 0.5) $$

**Pseudocode**
```python
import math

# Constants from [S3]
SH_C0 = 0.28209479177387814
SH_C1 = 0.4886025119029199
# SH_C2_0 to SH_C2_4 are not provided in the text excerpts [S3]
# SH_C3 constants are not provided in the text excerpts [S3]

def eval_sh_degree_0(coeffs_dc):
    """
    coeffs_dc: array of 3 floats [k_R, k_G, k_B] for degree 0
    Returns: array of 3 floats [R, G, B]
    """
    return [SH_C0 * c for c in coeffs_dc]

def eval_sh_degree_1(coeffs_d1, x, y, z):
    """
    coeffs_d1: array of 9 floats [k_R1, k_R2, k_R3, k_G1, k_G2, k_G3, k_B1, k_B2, k_B3]
    Corresponding to m=-1, 0, 1 for each channel.
    Based on [S3] snippet: color = color - SH_C1 * y * c1 + SH_C1 * z * c2 - SH_C1 * x * c3
    This implies c1->m=-1 (y), c2->m=0 (z), c3->m=1 (-x) or similar mapping.
    Standard SH1 basis functions are proportional to y, z, -x (or x, y, z depending on convention).
    We follow the [S3] logic structure.
    """
    # Extract coefficients for R, G, B
    # c1, c2, c3 correspond to the three coefficients for one channel
    r_c1, r_c2, r_c3 = coeffs_d1[0], coeffs_d1[1], coeffs_d1[2]
    g_c1, g_c2, g_c3 = coeffs_d1[3], coeffs_d1[4], coeffs_d1[5]
    b_c1, b_c2, b_c3 = coeffs_d1[6], coeffs_d1[7], coeffs_d1[8]
    
    # Apply formula from [S3]
    r = -SH_C1 * y * r_c1 + SH_C1 * z * r_c2 - SH_C1 * x * r_c3
    g = -SH_C1 * y * g_c1 + SH_C1 * z * g_c2 - SH_C1 * x * g_c3
    b = -SH_C1 * y * b_c1 + SH_C1 * z * b_c2 - SH_C1 * x * b_c3
    
    return [r, g, b]

def eval_sh_degree_2(coeffs_d2, x, y, z):
    """
    coeffs_d2: array of 15 floats for degree 2.
    Basis functions involve xy, yz, 2z^2-x^2-y^2, xz, x^2-y^2.

    coeffs_d3: array of 21 floats for degree 3.

def compute_view_dependent_color(sh_coeffs, x, y, z, max_degree=3):
    """
    sh_coeffs: array of 48 floats [DC(3), D1(9), D2(15), D3(21)]
    x, y, z: components of the normalized viewing direction vector
    max_degree: integer, maximum SH degree active (0-3)
    Returns: array of 3 floats [R, G, B]
    """
    # Extract DC
    dc = sh_coeffs[0:3]
    color = eval_sh_degree_0(dc)
    
    if max_degree >= 1:
        d1 = sh_coeffs[3:12]
        d1_contrib = eval_sh_degree_1(d1, x, y, z)
        color = [color[i] + d1_contrib[i] for i in range(3)]
        
    if max_degree >= 2:
        d2 = sh_coeffs[12:27]
        d2_contrib = eval_sh_degree_2(d2, x, y, z)
        color = [color[i] + d2_contrib[i] for i in range(3)]
        
    if max_degree >= 3:
        d3 = sh_coeffs[27:48]
        d3_contrib = eval_sh_degree_3(d3, x, y, z)
        color = [color[i] + d3_contrib[i] for i in range(3)]
        
    # Apply bias and ReLU [S4]
    color = [max(0.0, c + 0.5) for c in color]
    
    return color
```

**Parameters**
*   **Maximum SH Degree ($L$):** Typically 3 [S1]. This results in $(L+1)^2 = 16$ basis functions per color channel, totaling 48 coefficients per Gaussian [S1].
*   **Training Schedule:** Optimization begins with only the degree-0 band active. One further band is unlocked every 1,000 iterations until all four bands (degrees 0-3) are active [S1].

**Edge Cases and Pitfalls**
*   **Basis Functions are Fixed:** The basis functions $Y_{\ell}^m(\mathbf{d})$ are fixed polynomials of the direction components and are never updated during training. Only the coefficients $k$ are learned via gradient descent [S1].
*   **Precision:** The evaluation involves summing many terms. Using single-precision floats is standard, but care should be taken with the bias and ReLU to avoid negative colors [S4].
*   **Direction Normalization:** The direction vector $\mathbf{d}$ must be normalized before evaluation [S1].

## Subtopics

### [Progressive View-Dependent Color Baking](2834-progressive-view-dependent-color-baking.md)
An optimization that reduces memory bandwidth pressure by evaluating view-dependent colors over multiple frames rather than every frame, trading immediate visual fidelity for rendering performance.

## Operating characteristics
*   **Time Complexity:** The evaluation of SH coefficients is $O(1)$ per Gaussian per frame, involving a fixed number of multiplications and additions (48 coefficients, but many are zero if lower degrees are used) [S1]. It is significantly faster than querying a neural network [S1].
*   **Memory Complexity:** Each Gaussian stores 48 additional float values (48 $\times$ 4 bytes = 192 bytes) for the SH coefficients [S1]. This is a constant overhead per primitive.
*   **Measured Performance:** The method contributes to the overall rendering speed of 3DGS, which reaches 134 fps on the Mip-NeRF360 benchmark [S1]. The SH evaluation itself is described as costing "almost nothing at display time" [S1].
*   **Strengths:** Captures view-dependent effects like highlights and reflections, which simple point colors cannot [S1]. It is differentiable and can be optimized via gradient descent [S1].
*   **Limitations:** High-degree SH (degree 3) increases memory usage significantly (48 coefficients vs 3 for DC) [S1]. It may struggle with very sharp, high-frequency specularities compared to other representations, though degree 3 is generally sufficient for many scenes [S1].
*   **When to Use:** When view-dependent appearance (specularities, reflections) is important for photorealism [S1].
*   **When Not to Use:** When memory bandwidth is extremely constrained and view-dependent effects are not critical (use DC only) [S1].

## Background
*   **Origin:** The method was introduced in the 3D Gaussian Splatting paper (Kerbl et al., 2023) [S1]. It repurposes spherical harmonics from irradiance environment maps to represent the color leaving a Gaussian [S1].
*   **History:** Spherical harmonics are a well-known orthogonal basis for functions on the unit sphere, analogous to Fourier series [S1]. The specific application to 3DGS involves truncating the series at degree 3 and learning the coefficients via gradient descent [S1].
*   **Usage:** It is a core component of the 3D Gaussian Splatting rendering pipeline, enabling photorealistic novel view synthesis [S1].
