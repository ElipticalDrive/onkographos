# View-dependent color with Spherical Harmonics

Also called: Rendering with Spherical Harmonics, SH Render, Spherical Harmonic Colour Model, Spherical Harmonic Evaluation, Spherical Harmonics (SH) for View-Dependent Color, Spherical Harmonics Color Evaluation, Spherical Harmonics Rendering

## Overview
View-dependent color with Spherical Harmonics (SH) is a technique used in 3D Gaussian Splatting to model the view-dependent appearance (e.g., reflections, highlights) of each Gaussian primitive by representing its color as a function of the viewing direction [S1, unofficial][S2]. Unlike static color models that store a single RGB value per Gaussian, this method stores a set of coefficients that, when evaluated against the camera-to-Gaussian direction, produce a directionally varying color [S2][S5, unofficial]. This approach solves the problem of capturing specular details and reflections in point-based rendering without requiring per-ray neural network queries, keeping the rendering path closed-form and computationally cheap [S1, unofficial]. It builds on [Ray-marching on 3D Gaussians](1036-ray-marching-on-3d-gaussians.md) by providing the appearance model for the primitives being marched [G].

## How it works
**Inputs:**
- Gaussian SH coefficients [S4, unofficial].
- Camera center position [G].
- Maximum SH degree $L$ (typically 3) [S1, S4, unofficial].

**Outputs:**
- RGB color value for each Gaussian at the current viewing direction [S4, unofficial].

**Data Structures:**
Each Gaussian stores 48 floating-point values for SH coefficients [S1, S4, unofficial].
- Layout: Contiguous array of 48 floats [S4, unofficial].
- Structure:
  - Indices 0-2: Degree 0 (DC) coefficients for Red, Green, Blue ($k_{0,c}^0$) [S4, unofficial].
  - Indices 3-47: Higher-order coefficients for degrees 1, 2, and 3 [S4, unofficial].
  - Organization: The coefficients are stored in increasing order of degree and order $m$, with 16 coefficients per color channel [S1, S3, unofficial].

**Formulas:**
The color $C_c(\mathbf{d})$ for channel $c$ in viewing direction $\mathbf{d}$ is computed as [S1, unofficial]:
$$ C_c(\mathbf{d}) = \sum_{\ell=0}^L \sum_{m=-\ell}^{\ell} k_{\ell,c}^m Y_{\ell}^m(\mathbf{d}) $$
Where:
- $\mathbf{d}$ is the normalized direction vector from the camera center to the Gaussian's mean [S1, unofficial].
- $k_{\ell,c}^m$ are the learned SH coefficients for degree $\ell$, order $m$, and channel $c$ [S1, unofficial].
- $Y_{\ell}^m(\mathbf{d})$ are the fixed spherical harmonic basis functions evaluated at $\mathbf{d}$ [S1, unofficial].

For implementation with $L=3$, the evaluation expands into polynomial terms of the direction components $x, y, z$ (where $\mathbf{d} = [x, y, z]$) [S3, S4, unofficial]. The normalization constants used are [S4, unofficial]:
- $SH\_C0 = 0.28209479177387814$
- $SH\_C1 = 0.4886025119029199$
- $SH\_C2_0$ to $SH\_C2_4$: Not given in the sources.
- $SH\_C3_0$ to $SH\_C3_6$: Not given in the sources.

**Parameters:**
- Maximum Degree $L=3$: Results in 16 basis functions per channel, 48 total coefficients per Gaussian [S1, S4, unofficial].
- Training Schedule: Optimization starts with only Degree 0 (DC) active. One additional band (degree) is unlocked every 1,000 iterations until all bands (0-3) are active [S1, unofficial]. This coarse-to-fine schedule allows the base color to settle before fitting higher-frequency view-dependent details [S1, unofficial].

**Steps:**
1. **Compute View Direction:** For each Gaussian, calculate the vector $\mathbf{v}$ from the camera center to the Gaussian's mean position. Normalize it to get $\mathbf{d} = \mathbf{v} / \|\mathbf{v}\|$ [S1, unofficial].
2. **Evaluate Basis Functions:** Compute the values of the spherical harmonic basis functions $Y_{\ell}^m(\mathbf{d})$ for $\ell \in \{0, \dots, L\}$ and $m \in \{-\ell, \dots, \ell\}$ using the components of $\mathbf{d}$ [S1, S5, unofficial]. These are fixed polynomials [S1, unofficial].
3. **Dot Product with Coefficients:** For each color channel $c \in \{R, G, B\}$, compute the dot product of the evaluated basis functions and the stored SH coefficients for that channel [S1, S5, unofficial].
   $$ C_c(\mathbf{d}) = \sum_{\ell=0}^L \sum_{m=-\ell}^{\ell} k_{\ell,c}^m Y_{\ell}^m(\mathbf{d}) $$
4. **Apply Non-Linearity:** Some implementations apply a bias of $+0.5$ before ReLU (`max(0, sum + 0.5)`) [S5, unofficial], while others scale the sum by $0.5$ (`max(0, 0.5 * sum)`) [S3, unofficial]. Both ensure non-negative output and adjust dynamic range [S5, unofficial].
5. **Output:** Return the RGB vector $[C_R(\mathbf{d}), C_G(\mathbf{d}), C_B(\mathbf{d})]$ [S1, unofficial].

**Pseudocode:**
```python
import math

# SH constants for degree 3
SH_C0 = 0.28209479177387814
SH_C1 = 0.4886025119029199
# SH_C2_0 to SH_C2_4: Not given in the sources.
# SH_C3_0 to SH_C3_6: Not given in the sources.

def eval_sh_bases(l_max, dirs):
    """
    Evaluates spherical harmonic basis functions up to degree l_max for directions dirs.
    dirs: list of tuples (x, y, z) with normalized direction vectors.
    Returns: list of lists, shape (len(dirs), (l_max+1)^2) for one channel.
    """
    bases = []
    for x, y, z in dirs:
        # Degree 0
        y0 = [SH_C0]
        
        # Degree 1
        y1 = [-SH_C1 * y, SH_C1 * z, -SH_C1 * x]
        
        # Degree 2
        y2 = [
            SH_C2_0 * x * y,
            SH_C2_1 * y * z,
            SH_C2_2 * (2 * z * z - x * x - y * y),
            SH_C2_3 * x * z,
            SH_C2_4 * (x * x - y * y)
        ]
        
        # Degree 3
        y3 = [
            SH_C3_0 * y * (3 * x * x - y * y),
            SH_C3_1 * x * y * z,
            SH_C3_2 * y * (4 * z * z - x * x - y * y),
            SH_C3_3 * z * (2 * z * z - 3 * x * x - 3 * y * y),
            SH_C3_4 * x * (4 * z * z - x * x - y * y),
            SH_C3_5 * z * (x * x - y * y),
            SH_C3_6 * x * (x * x - 3 * y * y)
        ]
        
        bases.append(y0 + y1 + y2 + y3)
    return bases

def get_color(sh_coeffs, dirs):
    """
    sh_coeffs: list of lists, shape (N, 48) or (N, 3, 16)
    dirs: list of tuples (x, y, z)
    Returns: list of tuples (R, G, B)
    """
    # Flatten to (N, 3, 16) if stored as (N, 48)
    if isinstance(sh_coeffs[0], (list, tuple)) and len(sh_coeffs[0]) == 48:
        sh_coeffs = [[sh_coeffs[i][c*16:(c+1)*16] for c in range(3)] for i in range(len(sh_coeffs))]
        
    bases = eval_sh_bases(3, dirs)
    colors = []
    for i, base in enumerate(bases):
        rgb = []
        for c in range(3):
            # Dot product of coefficients and bases for channel c
            val = sum(sh_coeffs[i][c][j] * base[j] for j in range(16))
            # Apply bias/offset; sources differ between +0.5 [S5, unofficial] and 0.5*sum [S3, unofficial]
            val = max(0.0, val + 0.5)
            rgb.append(val)
        colors.append(tuple(rgb))
    return colors
```

**Edge Cases and Pitfalls:**
- **Precision:** The basis functions are fixed polynomials. Ensure direction vectors are normalized before evaluation to maintain orthogonality properties [S1, unofficial].
- **Degenerate Input:** If the Gaussian is at the camera center, the direction vector is undefined. Handle this by clamping or using a default direction [G].
- **Coefficient Ordering:** The mapping between stored coefficients and the SH terms ($m$ values) must be consistent between training and rendering. The sources imply a standard ordering (increasing degree and order) [S1, S3, unofficial].
- **Negative Colors:** SH coefficients can lead to negative color values. The ReLU and bias in [S5, unofficial] mitigate this, but training stability depends on the schedule [S1, unofficial].

## Subtopics

### [Progressive View-Dependent Color Baking](2834-progressive-view-dependent-color-baking.md)
Progressive View-Dependent Color Baking is an optimization for 3D Gaussian Splatting that reduces memory bandwidth pressure caused by high-degree spherical harmonics (SH) by evaluating view-dependent colors over multiple frames rather than every frame. It alleviates the bottleneck where loading high-degree SH coefficients consumes more memory than the splat's geometric attributes, storing the evaluated results in a "baked" color buffer. Unlike standard per-frame SH evaluation, this method trades immediate visual fidelity for rendering performance, converging to the correct view-dependent color within a short, fixed number of frames.

### [Spherical Beta View-Dependent Color](3823-spherical-beta-view-dependent-color.md)
Spherical Beta (SB) is a specular model that adds explicit specular lobes on top of the base or Spherical Harmonic (SH) color to model view-dependent appearance in 3D Gaussian Splatting. It is derived from Deformable Beta Splatting (Liu et al., SIGGRAPH 2025). Unlike SH, which represents the full view-dependent function, SB uses a small number of explicit lobes, offering higher PSNR and significantly smaller file sizes than SH degree 3.

## Operating characteristics
- **Time Complexity:** $O(1)$ per Gaussian per frame for color evaluation, as it involves a fixed number of arithmetic operations (polynomial evaluation) [S1, unofficial]. The cost is negligible compared to rasterization and compositing [S1, unofficial].
- **Memory Complexity:** $O(N)$ where $N$ is the number of Gaussians. Each Gaussian stores 48 floats (192 bytes) for SH coefficients [S1, S4, unofficial]. This is a significant memory overhead compared to static color (12 bytes), but necessary for view-dependent effects [S1, unofficial].
- **Measured Performance:** On the Mip-NeRF360 benchmark, the method reaches 27.21 dB PSNR and 0.214 LPIPS at 134 fps [S1, unofficial].
- **Scaling:** The method scales linearly with the number of Gaussians. Higher degrees increase memory and computation linearly but provide diminishing returns in visual quality beyond degree 3 [S1, unofficial].
- **Strengths:** Captures complex view-dependent effects like reflections and highlights [S1, unofficial]. Closed-form evaluation is fast [S1, unofficial]. Compatible with standard gradient descent training [S1, unofficial].
- **Limitations:** High memory usage due to 48 coefficients per Gaussian [S1, unofficial]. Can suffer from ringing artifacts if the SH degree is insufficient for the scene's complexity [G]. Training requires a coarse-to-fine schedule to stabilize [S1, unofficial].
- **When to Use:** When view-dependent appearance (specularities, reflections) is critical for photorealism [S1, unofficial].

## Background
The method was introduced in the 3D Gaussian Splatting paper by Kerbl et al. (2023) [S1, unofficial]. It repurposes spherical harmonics from their traditional use in irradiance environment maps to represent the view-dependent color of Gaussian primitives [S1, unofficial]. The choice of SH was driven by the need for a compact, differentiable, and efficient representation of directional color variation [S1, unofficial]. The method has become a standard component of 3D Gaussian Splatting pipelines [S1, unofficial].
