# OTS Marching Ray Marching Algorithm

Also called: Adaptive Binning Ray Marching, OTS Marcher, OTS Marching, Ray Marching (OTS scheme)

## Overview
The OTS Marching Ray Marching Algorithm is a volumetric rendering method for 3D Gaussians that evaluates the full Gaussian mixture to accurately handle primitive overlap and compute the volumetric integral using an extinction-based model [S1]. It distinguishes itself from splatting-based approaches by performing adaptive binning and analytical integration along rays, ensuring that overlapping Gaussians are resolved with precision governed by sample count rather than relying on rasterization approximations [S1]. Unlike raytracing solutions for Gaussians, this method explicitly accounts for primitive overlap in the integration process [S1].

## How it works
The algorithm performs adaptive sampling along each viewing ray to resolve Gaussian overlap. It iterates over the Gaussian mixture twice: first to establish bin borders adapted to the Gaussian data, and second to perform analytical integration into bins of variable extent [S1]. The bins are then blended together following the volume integral equation [S1].

### Inputs and Outputs
*   **Inputs:** A set of 3D Gaussians defined by position, scale, rotation, and color; a viewing ray defined by origin $\mathbf{o}$ and direction $\mathbf{d}$; a maximum ray depth or opacity threshold.
*   **Outputs:** The final pixel color $I(\mathbf{x})$ and accumulated transmittance.

### Data Structures
*   **Density Section Buffer:** A fixed-size buffer storing sections. Each section is defined by:
    *   `start`: The start parameter $t$ along the ray.
    *   `end`: The end parameter $t$ along the ray.
    *   `density`: The sampling density for this section.
*   **Bin:** A segment of the ray defined by start and end $t$ values, storing integrated color and extinction.

### Steps

1.  **Adaptive Binning Initialization:**
    Create a fixed-size density section buffer. Iterate over all Gaussians to fill the buffer. For each Gaussian, compute its intersection interval with the ray. Define the start and end of the sampling section using the Gaussian's position $\pm 3$ standard deviations along the ray direction [S1]. Compute the density such that a pre-defined number of bins fit within the space defined by start and end [S1].

2.  **Section Merging:**
    Add the new section to the density section buffer. Combine existing and new sections to ensure they are ordered and non-overlapping. If sections overlap, the section with the higher sampling density takes precedence in the overlap area. Combining two sections can result in up to three new sections. Sections that fall outside the buffer capacity are deferred to the next batch [S1].

3.  **Bin Creation:**
    Traverse the merged sections to create bins. The size of each bin is inversely proportional to the density of the section it belongs to [S1].

4.  **Blending Integral Computation (Batching):**
    Divide the work into batches of bins (e.g., 128 bins per batch) [S1].
    *   Initialize the first batch at $t=0$. Subsequent batches start at the end-border of the last bin of the previous batch [S1].
    *   Iterate over the Gaussian mixture again to compute integrals for each bin in the current batch.
    *   For each bin, compute 4 values: Red, Green, Blue, and integrated extinction (opacity) [S1].
    *   Colors are multiplied by the per-Gaussian integrated extinction [S1].
    *   Stop when all Gaussians are processed or accumulated opacity reaches a high threshold [S1].

5.  **Blending:**
    Blend the bin evaluations together using the following equation [S1]:

    $$
    I(\mathbf{x}) = \sum_{i=0}^{\infty} \gamma_i \prod_{j=0}^{i-1} e^{-\rho_j} + c_b \prod_{j=0}^{\infty} e^{-\rho_j}
    $$

    Where:
    *   $\gamma_i$ is the color contribution of bin $i$.
    *   $\rho_j$ is the integrated extinction (opacity) of bin $j$.
    *   The term $\prod_{j=0}^{i-1} e^{-\rho_j}$ is the transmittance factor, cached between iterations to avoid redundant computation [S1].
    *   $c_b$ is the background color.

6.  **Gradient Computation:**
    Compute gradients manually using a front-to-back strategy [S1]. Two variants exist:
    *   **Attached:** Considers the numerical integration procedure and border positions in the gradient calculation.
    *   **Detached:** Assumes the numerical method can be ignored, keeping sampling and border positions constant with respect to differentiation. The detached variant performs significantly better [S1].

def ots_marching_ray_march(ray_origin, ray_direction, gaussians, max_bins_buffer_size, bins_per_batch=128, opacity_threshold=0.99):
    """
    Renders a single ray using the OTS Marching Algorithm.
    """
    # 1. Adaptive Binning Initialization & Section Merging
    sections = []
    for g in gaussians:
        # Compute intersection interval [t_start, t_end] along ray
        # Use position +/- 3 standard deviations
        t_start, t_end = g.intersect_interval(ray_origin, ray_direction)
        if t_start > t_end:
            t_start, t_end = t_end, t_start
        
        # Compute density such that pre-defined number of bins fit in space
        # Let N_bins_per_gaussian be a constant or derived from scene complexity
        density = compute_density(t_end - t_start) 
        
        new_section = Section(start=t_start, end=t_end, density=density)
        sections = merge_sections(sections, new_section, max_bins_buffer_size)
        
    # 2. Bin Creation
    bins = create_bins(sections)
    
    # 3. Blending Integral Computation (Batching)
    total_color = [0.0, 0.0, 0.0]
    transmittance = 1.0
    current_t = 0.0
    
    # Process bins in batches
    for batch_start_idx in range(0, len(bins), bins_per_batch):
        batch_end_idx = min(batch_start_idx + bins_per_batch, len(bins))
        current_batch_bins = bins[batch_start_idx:batch_end_idx]
        
        # Reset transmittance for the batch if not accumulating from previous? 
        # Note: The paper says "cached between iteration", implying accumulation.
        # However, batching splits the ray. Transmittance must carry over.
        
        for bin in current_batch_bins:
            # Iterate over Gaussians to compute integrals for this bin
            bin_color = [0.0, 0.0, 0.0]
            bin_extinction = 0.0
            
            for g in gaussians:
                # Check if Gaussian overlaps with bin [bin.start, bin.end]
                if g.overlaps_ray_segment(ray_origin, ray_direction, bin.start, bin.end):
                    # Compute analytical integral of Gaussian over bin
                    integral_color, integral_extinction = g.integrate_over_bin(
                        ray_origin, ray_direction, bin.start, bin.end
                    )
                    bin_color += integral_color
                    bin_extinction += integral_extinction
            
            # Apply transmittance from previous bins
            alpha = 1.0 - exp(-bin_extinction)
            total_color += bin_color * transmittance
            transmittance *= exp(-bin_extinction)
            
            # Check threshold
            if 1.0 - transmittance > opacity_threshold:
                break
        
        current_t = current_batch_bins[-1].end if current_batch_bins else current_t
        
        if transmittance < (1.0 - opacity_threshold):
            break
            
    # Add background
    total_color += background_color * transmittance
    
    return total_color

### Parameters
*   **Batch Size:** Typically 128 bins per batch [S1].
*   **Activation Function:** Softplus with $\beta = 2$ is used instead of sigmoid to allow Gaussians to become fully opaque [S1].
*   **Standard Deviation Factor:** 3 standard deviations are used to define the start and end of sampling sections [S1].

### Edge Cases and Pitfalls
*   **Buffer Overflow:** Sections that fall out of the fixed-size density section buffer are deferred to the next batch [S1].
*   **Opacity Convergence:** Using a constant opacity initialization can prevent convergence for large Gaussian counts. A power function fitting opacity to the number of Gaussians is recommended for initialization [S1].
*   **Gradient Choice:** The attached gradient variant is computationally more expensive and performs worse than the detached variant [S1].

## Operating characteristics
*   **Performance:** The algorithm is considerably slower than splatting, typically between one and two orders of magnitude slower, depending on the scene [S1].
*   **Accuracy:** It provides accurate resolution of Gaussian overlap and precise perspective projection, serving as a testbed to examine the importance of these factors in 3DGS [S1].
*   **Complexity:** The algorithm requires iterating over the Gaussian mixture twice per batch (once for binning, once for integration), leading to higher computational cost compared to single-pass splatting [S1].
*   **Strengths:** Accurate volumetric rendering, handles overlap correctly, accounts for primitive overlap in integration unlike some raytracing solutions [S1].
*   **Limitations:** Low performance compared to splatting; implementation complexity is higher [S1].

## Background
The OTS Marching Ray Marching Algorithm was introduced in the paper "Does 3D Gaussian Splatting Need Accurate Volumetric Rendering?" [S1]. It was developed as part of an implementation to study the impact of approximations like spatial overlap and sorting in 3D Gaussian Splatting. The implementation builds on the original 3DGS code base to enable meaningful comparisons [S1].
