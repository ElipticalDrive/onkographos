# Mandelbulb Sphere Tracing

Also called: Mandelbulb Fractal Rendering, Mandelbulb Ray Marching, Mandelbulb SDF Raymarching, Mandelbulb Tracing, mandelSphereTracing

## Overview
Mandelbulb Sphere Tracing is a volume rendering technique that renders the Mandelbulb fractal by raymarching through 3D space using a specific Signed Distance Function (SDF) based on iterative spherical power operations [S1, unofficial][S2, unofficial]. It differs from standard primitive sphere tracing by replacing simple geometric distance calculations with a computationally expensive iterative formula that approximates the fractal's boundary [S1, unofficial]. Unlike recursive polyhedral fractals (e.g., Menger sponge) which have finite depth, the Mandelbulb possesses infinite self-similar detail, requiring adaptive iteration counts and suffering from increasing distance estimator inaccuracy and normal noise as the camera zooms in [S2, unofficial].

## How it works
**Inputs:**
*   Camera position $(O_x, O_y, O_z)$ and direction vectors (right, up, forward) [S1, unofficial].
*   Screen resolution $(W, H)$ and pixel coordinates $(x, y)$ [S1, unofficial].
*   Fractal parameters: `power` (exponent, typically 8) [S2, unofficial], `max_march_dist` (2000) [S1, unofficial], `hit_threshold` (0.01) [S1, unofficial].
*   Iteration count per raymarch step: approximately 10 [S2, unofficial].

**Outputs:**
*   Pixel color (RGB) based on surface hit, lighting, and shadows [S1, unofficial][S2, unofficial].
*   Background color if no hit [S2, unofficial].

**Data Structures:**
*   `minDistances[x][y][5]`: A 3D array storing per-pixel data. Indices: `[0]` distance, `[1]` hit flag (0=light, 1=shadow), `[2]` R, `[3]` G, `[4]` B, `[5]` auxiliary value (e.g., for mu calculation) [S1, unofficial].
*   `Vector3`: Represents 3D coordinates $(x, y, z)$ and camera offsets [S1, unofficial].

**Algorithm Steps:**

1.  **Initialization:** For each pixel $(x, y)$, construct the ray origin $P$ at the camera position and direction $D$ based on screen coordinates, zoom, and view range [S1, unofficial][S2, unofficial]. Initialize `minDist` to a large value [S1, unofficial].
2.  **Raymarching Loop:** While `minDist` > `hit_threshold` (0.01) AND `minDist` < `max_march_dist` (2000):
    a.  Evaluate the Mandelbulb SDF at the current ray position $P$ using `distMandelBulb(P)` [S1, unofficial].
    b.  If `minDist` <= `hit_threshold`, the ray has hit the surface [S1, unofficial]. Break loop.
    c.  Advance the ray position: $P \leftarrow P + D \times \text{minDist}$ [S1, unofficial][S2, unofficial].
    d.  Increment iteration counter [S1, unofficial].
3.  **Hit Processing:** If `minDist` <= `hit_threshold`:
    a.  Estimate surface normal $N$ by sampling the SDF at four nearby points around $P$ and computing the gradient [S2, unofficial].
    b.  Apply lighting: Calculate diffuse component (dot product of $N$ and light direction), ambient lighting, and soft shadows [S2, unofficial].
    c.  Store color in `minDistances[x][y]` [S1, unofficial].
4.  **Miss Processing:** If `minDist` > `max_march_dist` or loop exits without hit:
    a.  Store distance as 10000 and iteration count [S1, unofficial].
    b.  Paint background color [S2, unofficial].

**Formulas:**

*   **Mandelbulb Iteration:**
    The core SDF calculation iterates the transformation:
    $$ z_{n+1} = z_n^{\text{power}} + c $$
    Where $z$ is a 3D vector represented in spherical coordinates $(r, \theta, \phi)$ [G]. The "spherical power" operation raises the radius $r$ to the `power` exponent and multiplies the angles $\theta$ and $\phi$ by the `power` [S2, unofficial]. Specifically, for a point $(x, y, z)$:
    1.  Convert to spherical coordinates: $r = \sqrt{x^2+y^2+z^2}$, $\theta = \arctan2(y, x)$, $\phi = \arccos(z/r)$ [G].
    2.  Apply power: $r' = r^{\text{power}}$, $\theta' = \theta \times \text{power}$, $\phi' = \phi \times \text{power}$ [S2, unofficial].
    3.  Convert back to Cartesian: $x' = r' \sin(\phi') \cos(\theta')$, $y' = r' \sin(\phi') \sin(\theta')$, $z' = r' \cos(\phi')$ [G].
    4.  Add constant $c$ (usually the original pixel coordinate or a fixed offset) [S2, unofficial].
    5.  Repeat for `num_iterations` (approx. 10) [S2, unofficial].

*   **Distance Estimator (Hubbard-Douady):**
    The distance estimate $d$ is derived from the iteration's escape behavior using the Hubbard-Douady distance estimator [S2, unofficial]. It is an approximate lower bound [S2, unofficial].
    $$ d \approx \frac{r_n \ln r_n}{|\frac{\partial z_n}{\partial z_0}|} $$
    Where $r_n$ is the magnitude of the final iterate and the denominator is the derivative of the iteration function with respect to the initial point, tracked during iteration [G]. *Note: Exact formula not provided in sources, described as "Hubbard-Douady distance estimator" using "escape behavior" [S2, unofficial].*

*   **Normal Estimation:**
    $$ N = \frac{\partial SDF}{\partial P} \approx \frac{SDF(P + \epsilon) - SDF(P - \epsilon)}{2\epsilon} $$
    Sampled at four nearby points to compute the gradient [S2, unofficial].

**Pseudocode:**

```python
import math

class Vector3:
    def __init__(self, x, y, z):
        self.x, self.y, self.z = x, y, z
    def __add__(self, o):
        return Vector3(self.x + o.x, self.y + o.y, self.z + o.z)
    def __mul__(self, s):
        return Vector3(self.x * s, self.y * s, self.z * s)
    def __sub__(self, o):
        return Vector3(self.x - o.x, self.y - o.y, self.z - o.z)

def normalize(v):
    m = math.sqrt(v.x**2 + v.y**2 + v.z**2)
    return Vector3(v.x / m, v.y / m, v.z / m) if m > 0 else Vector3(0, 0, 0)

def dot(a, b):
    return a.x * b.x + a.y * b.y + a.z * b.z

background_color = (0, 0, 0)

def dist_mandelbulb(x, y, z, power=8, iterations=10):
    """Computes the approximate distance to the Mandelbulb fractal surface."""
    r = math.sqrt(x*x + y*y + z*z)
    if r == 0:
        return 0.0
    theta = math.atan2(y, x)
    phi = math.acos(z / r)
    dr = 1.0
    for _ in range(iterations):
        r = pow(r, power)
        theta *= power
        phi *= power
        dr *= power * r
        x = r * math.sin(phi) * math.cos(theta)
        y = r * math.sin(phi) * math.sin(theta)
        z = r * math.cos(phi)
    if dr == 0:
        return 2000.0
    return (r * math.log(r)) / dr

def render_pixel(px, py, cam_pos, cam_dir, power=8, max_march=2000, hit_thresh=0.01):
    """Renders a single pixel of the Mandelbulb."""
    ray_pos = cam_pos
    ray_dir = cam_dir
    min_dist = 0.0
    hit = False
    for _ in range(1000):
        dist = dist_mandelbulb(ray_pos.x, ray_pos.y, ray_pos.z, power)
        if dist < hit_thresh:
            hit = True
            min_dist = dist
            break
        if dist > max_march:
            min_dist = 10000.0
            break
        ray_pos = ray_pos + ray_dir * dist
    if hit:
        eps = 0.01
        dx = dist_mandelbulb(ray_pos.x + eps, ray_pos.y, ray_pos.z, power) - dist_mandelbulb(ray_pos.x - eps, ray_pos.y, ray_pos.z, power)
        dy = dist_mandelbulb(ray_pos.x, ray_pos.y + eps, ray_pos.z, power) - dist_mandelbulb(ray_pos.x, ray_pos.y - eps, ray_pos.z, power)
        dz = dist_mandelbulb(ray_pos.x, ray_pos.y, ray_pos.z + eps, power) - dist_mandelbulb(ray_pos.x, ray_pos.y, ray_pos.z - eps, power)
        normal = normalize(Vector3(dx, dy, dz))
        light_dir = normalize(Vector3(0, 1, 0))
        diff = max(dot(normal, light_dir), 0.0)
        ambient = 0.2
        return (int((diff + ambient) * 255), int((diff + ambient) * 255), int((diff + ambient) * 255))
    else:
        return background_color

def render_chunk(start_y, end_y, cam_pos, cam_dir, power=8):
    """Processes a horizontal strip of pixels."""
    results = []
    for y in range(start_y, end_y):
        for x in range(600): # Assuming fixed width for example
            color = render_pixel(x, y, cam_pos, cam_dir, power)
            results.append((x, y, color))
    return results
```

## Subtopics

### Menger Sponge Raymarching
Renders a recursive cube-based fractal. Unlike the Mandelbulb, it has finite depth at reasonable zoom levels, making distance estimation more stable and normals less noisy [S2, unofficial].

### Primitive SDF Raymarching
Renders basic shapes (spheres, boxes) using exact distance formulas [S2, unofficial]. Significantly faster than Mandelbulb as it avoids iterative calculations [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** The Mandelbulb SDF call requires approximately 10 iterations of spherical power (involving trigonometric functions) plus derivative tracking per raymarch step [S2, unofficial]. This is roughly 100x the work of a simple sphere SDF [S2, unofficial]. Since the SDF is called dozens of times per pixel during raymarching, the total cost is thousands of math operations per pixel per frame [S2, unofficial].
*   **Memory Complexity:** Low. Requires storage for the image buffer and camera state [G].
*   **Measured Performance:** Real-time rendering is possible on modern GPUs due to parallel pixel processing, but high-resolution or high-iteration renders are computationally expensive [S2, unofficial].
*   **Strengths:** Can render complex, organic, infinitely detailed fractal structures that are impossible to model with polygons [S2, unofficial].
*   **Limitations:**
    *   **Approximate Distance:** The Hubbard-Douady estimator is a lower bound, not exact [S2, unofficial]. It can be loose, leading to smaller raymarch steps and higher GPU cost [S2, unofficial].
    *   **Noise:** Normal estimation amplifies noise because it computes differences between approximate SDF samples. Small numerical errors in distance become large errors in normals, causing bumpy shading artifacts [S2, unofficial].
    *   **Zoom Limitations:** As the camera zooms in, more iterations are needed, the distance estimator becomes less accurate, and normal estimation gets noisier, with no Level of Detail (LOD) fallback [S2, unofficial].
*   **When to Use:** When rendering 3D fractals or implicit surfaces with infinite detail [S2, unofficial].
*   **When Not to Use:** When high precision is required at close zoom levels, or when performance is critical and the geometry is simple [S2, unofficial].

## Background
The Mandelbulb is a 3D generalization of the 2D Mandelbrot set, defined by iterating a "spherical power" operation [S2, unofficial]. It was popularized in the demoscene and by graphics engineers like Inigo Quilez [S2, unofficial]. The technique of rendering it via sphere tracing was implemented in projects such as `haydenparker3/3D-Sphere-Tracing` and `AJKKinney/Mandelbulb` [S1, unofficial][S2, unofficial]. The method relies on the Hubbard-Douady distance estimator, which is an approximation suitable for fractals where exact distance calculation is intractable [S2, unofficial].
