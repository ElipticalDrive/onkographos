# Linear SDF Blend

Also called: Shape Blending

## Overview
Linear SDF Blend interpolates between two signed distance functions (SDFs) using a linear blend factor to create smooth transitions or morphing between shapes [S1, unofficial]. It produces a linear interpolation of the distance values themselves, rather than a rounded boolean union or intersection [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input 1: $d_1$, the signed distance from the query point to the first primitive [S1, unofficial].
- Input 2: $d_2$, the signed distance from the query point to the second primitive [S1, unofficial].
- Input 3: $a$, the blend factor, a scalar in the range $[0, 1]$ [S1, unofficial].
- Output: $d_{blend}$, the interpolated signed distance [S1, unofficial].

**Data Structures:**
The operation is element-wise on scalar distances [S1, unofficial]. When material identification is required, the function can return a tuple or vector containing the blended distance and a primitive identifier [S2, unofficial].

**Formula:**
$$d_{blend} = a \cdot d_1 + (1 - a) \cdot d_2$$
Where $d_1$ and $d_2$ are the distances of the two shapes, and $a \in [0, 1]$ is the blend factor [S1, unofficial].

**Parameters:**
- $a$: The blend factor. Typical usage involves a constant value for static blending or a time-varying value (e.g., derived from $\sin(\text{time})$) for animation [S1, unofficial].

**Pseudocode:**
```python
def linear_sdf_blend(d1: float, d2: float, a: float) -> float:
    """Linearly interpolate between two SDF values."""
    return a * d1 + (1.0 - a) * d2
```

**Edge Cases and Pitfalls:**
- The blend factor $a$ can be constant or vary over time or space [S1, unofficial].
- If the blend factor varies rapidly in space, the resulting distance field may not represent a true metric distance, which can affect ray marching step sizes [G].

## Subtopics

### Smoothstep SDF Blend
A variant where the blend factor $s$ is determined by the spatial position of the query point, specifically its distance from the origin, creating a spatially varying blend region [S2, unofficial].
- **Definition:** Blends two SDFs using a smoothstep interpolation factor based on the length of the query point $p$ [S2, unofficial].
- **Formula:**
  $$s = \text{smoothstep}(0.0, 1.0, \|p\|)$$
  $$d = (1 - s) \cdot d_1 + s \cdot d_2$$
  [S2, unofficial]
- **Parameters:** The smoothstep range is fixed between 0.0 and 1.0, defining the spherical shell region where the blend occurs [S2, unofficial].
- **Data Layout:** The function returns a `vec2` where the x-component is the distance and the y-component is a primitive identifier (e.g., 1) [S2, unofficial].
- **Pseudocode:**
  ```python
  def smoothstep(edge0: float, edge1: float, x: float) -> float:
      """Standard cubic Hermite smoothstep interpolation [G]."""
      t = max(0.0, min(1.0, (x - edge0) / (edge1 - edge0)))
      return t * t * (3.0 - 2.0 * t)

  def smoothstep_sdf_blend(p: tuple, d1: float, d2: float) -> tuple:
      """Blend two SDFs based on the distance of the query point from the origin."""
      dist_from_origin = (p[0]**2 + p[1]**2 + p[2]**2)**0.5
      s = smoothstep(0.0, 1.0, dist_from_origin)
      blended_d = (1.0 - s) * d1 + s * d2
      return (blended_d, 1.0)
  ```
- **When to choose:** Use when the transition between shapes should depend on the object's position relative to a center, creating a fading effect between geometries [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query point, involving two multiplications and one addition [G].
- **Memory Complexity:** $O(1)$, requiring no additional data structures beyond the input distances and blend factor [G].
- **Strengths:** Simple to implement; allows for smooth morphing animations; works with any pair of SDFs [S1, unofficial].
- **Limitations:** Does not preserve the Lipschitz continuity property (gradient magnitude $\le 1$), meaning it is not a true distance field in the mathematical sense after blending [G].
- **When to use:** For visual effects, morphing animations, or when the exact distance metric is less critical than the visual smoothness of the transition [S1, unofficial].

## Background
The technique was demonstrated by Alan Zucconi as a method for morphing between shapes like spheres and cubes using a time-varying blend factor [S1, unofficial]. Geeks3D extended the concept to spatially varying blends using smoothstep functions to transition between primitives like rounded boxes and tori based on their distance from the origin [S2, unofficial].
