# Multi-Material Distance Fields

Also called: Color-Coded SDFs, SDF with Material Data

## Overview
Multi-Material Distance Fields extend standard Signed Distance Field (SDF) ray marching by associating material properties (such as color or ID) with geometric primitives. While standard SDFs return a single scalar distance, this method returns a vector containing both the distance and material data, allowing the raymarcher to identify the surface material upon intersection. It differs from [SDF Smooth Union](1817-sdf-smooth-union.md) by focusing on material identification rather than geometric blending, and builds on [Object Combination Operators](1801-object-combination-operators.md) to combine these multi-component values.

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $ro$, ray direction $rd$, maximum steps, and a color ramp texture.
*   **Output:** A final pixel color determined by the material ID of the closest hit surface.

**Data Structures:**
*   **Map Output:** A `float2` vector.
    *   `x` component: The signed distance value.
    *   `y` component: The material identifier (typically normalized to $[0, 1]$).

**Algorithm Steps:**
1.  **Define Primitive Maps:** Each primitive's distance function must be wrapped to return a `float2`. The distance is calculated normally, and a constant material ID is assigned to the `y` component.
2.  **Combine Objects:** Use a modified Union operator that compares only the distance components (`x`) of the input vectors and returns the entire vector of the closer object.
3.  **Raymarch:** Iterate along the ray. At each step, sample the combined map function.
4.  **Hit Detection:** Check if the distance component (`x`) is below a threshold.
5.  **Material Lookup:** If a hit occurs, use the material ID component (`y`) to sample a color ramp texture to determine the final color.

**Formulas:**
The modified Union operator $opU$ for two multi-material distances $d_1$ and $d_2$ is:
$$
opU(d_1, d_2) = \begin{cases} 
d_1 & \text{if } d_1.x < d_2.x \\
d_2 & \text{otherwise}
\end{cases}
$$

**Parameters:**
*   **ColorRamp:** A `sampler2D` texture mapping material IDs (0.0 to 1.0) to RGB colors [S1].
*   **Threshold:** A small epsilon (e.g., 0.001) for hit detection [S1].

**Pseudocode:**
```python
# Union operator for multi-material SDFs
def opU(d1, d2):
    """
    Returns the vector (distance, material_id) of the closer object.
    Comparison is strictly on the distance component (x).
    """
    if d1.x < d2.x:
        return d1
    else:
        return d2

# Map function returning distance and material ID
def map(p):
    """
    Returns float2: (distance, material_id_normalized)
    """
    # Example primitives with hardcoded material IDs
    # Torus: ID 0.5
    dist_torus = sd_torus(p, float2(1.0, 0.2))
    d_torus = float2(dist_torus, 0.5)
    
    # Box: ID 0.25
    dist_box = sd_box(p - float3(-3, 0, 0), float3(0.75, 0.5, 0.5))
    d_box = float2(dist_box, 0.25)
    
    # Sphere: ID 0.75
    dist_sphere = sd_sphere(p - float3(3, 0, 0), 1.0)
    d_sphere = float2(dist_sphere, 0.75)
    
    # Combine using modified union
    ret = opU(d_torus, d_box)
    ret = opU(ret, d_sphere)
    
    return ret

# Raymarching loop snippet
def raymarch(ro, rd):
    t = 0.0
    max_steps = 64
    hit_material_id = -1.0
    
    for i in range(max_steps):
        p = ro + rd * t
        d = map(p)
        
        # d.x is distance, d.y is material ID
        if d.x < 0.001:
            hit_material_id = d.y
            break
        
        t += d.x
        
    if hit_material_id >= 0:
        # Sample color ramp based on material ID
        color = sample_color_ramp(hit_material_id)
        return color
    else:
        return background_color
```

## Subtopics

### [Material Object Format](1981-material-object-format.md)
A data structure holding surface shading info, separating geometric displacement from shading calculations.

## Operating characteristics
*   **Complexity:** Time complexity is identical to standard SDF ray marching $O(N)$ where $N$ is the number of steps, as the vector operations are constant-time. Memory overhead is negligible, limited to the color ramp texture.
*   **Strengths:** Enables complex multi-material scenes with minimal code changes to the raymarching loop.
*   **Limitations:** The material ID is discrete; smooth transitions between materials require additional blending logic not inherent to the basic method. Precision issues may arise if material IDs are not normalized consistently.

## Background
This technique was popularized in the context of real-time raymarching shaders, specifically within the Unity engine ecosystem. It allows artists to define materials directly within the SDF code rather than relying on external mesh materials.
