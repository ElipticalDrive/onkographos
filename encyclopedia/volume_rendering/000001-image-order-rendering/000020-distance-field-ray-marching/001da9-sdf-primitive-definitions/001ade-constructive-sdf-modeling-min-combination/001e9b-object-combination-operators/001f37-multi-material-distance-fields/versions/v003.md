# Multi-Material Distance Fields

Also called: Color-Coded SDFs, SDF with Material Data

## Overview
Multi-Material Distance Fields associate material properties with geometric primitives by returning a vector containing both the distance value and the material ID or color from the `map()` function [S1, unofficial]. While standard SDFs return a single scalar distance, this method returns a two-component vector, allowing the raymarcher to identify the surface material upon intersection [S1, unofficial]. It differs from [SDF Smooth Union](1817-sdf-smooth-union.md) by focusing on material identification rather than geometric blending, and builds on [Object Combination Operators](1801-object-combination-operators.md) to combine these multi-component values [G].

## How it works
**Inputs and Outputs:**
*   **Input:** Ray origin $ro$, ray direction $rd$, maximum steps, and a color ramp texture [S1, unofficial].
*   **Output:** A final pixel color determined by the material ID of the closest hit surface [S1, unofficial].

**Data Structures:**
*   **Map Output:** A two-component vector [S1, unofficial].
    *   `x` component: The signed distance value [S1, unofficial].
    *   `y` component: The material identifier, typically normalized to $[0, 1]$ [S1, unofficial].

**Algorithm Steps:**
1.  **Define Primitive Maps:** Each primitive's distance function must be wrapped to return a two-component vector. The distance is calculated normally, and a constant material ID is assigned to the `y` component [S1, unofficial].
2.  **Combine Objects:** Use a modified Union operator that compares only the distance components (`x`) of the input vectors and returns the entire vector of the closer object [S1, unofficial].
3.  **Raymarch:** Iterate along the ray. At each step, sample the combined map function [S1, unofficial].
4.  **Hit Detection:** Check if the distance component (`x`) is below a threshold [S1, unofficial].
5.  **Material Lookup:** If a hit occurs, use the material ID component (`y`) to sample a color ramp texture to determine the final color [S1, unofficial].

**Formulas:**
The modified Union operator $opU$ for two multi-material distances $d_1$ and $d_2$ is:
$$opU(d_1, d_2) = d_1 \text{ if } d_1.x < d_2.x \text{ else } d_2$$ [S1, unofficial].

**Parameters:**
*   **ColorRamp:** A `sampler2D` texture mapping material IDs to colors [S1, unofficial].
*   **Threshold:** A small epsilon (e.g., 0.001) for hit detection [S1, unofficial].

**Edge Cases and Pitfalls:**
*   Precision issues may arise if material IDs are not normalized consistently across primitives [G].
*   Degenerate input (e.g., zero-length rays) requires explicit guards before the loop [G].

**Pseudocode:**
```python
import math

def opU(d1, d2):
    """Returns the vector (distance, material_id) of the closer object."""
    return d1 if d1[0] < d2[0] else d2

def sd_box(p, half_size):
    """Standard SDF for an axis-aligned box [G]."""
    q = (abs(p[0]) - half_size[0], abs(p[1]) - half_size[1], abs(p[2]) - half_size[2])
    return max(max(q[0], q[1]), q[2])

def sd_sphere(p, radius):
    """Standard SDF for a sphere [G]."""
    return math.sqrt(p[0]**2 + p[1]**2 + p[2]**2) - radius

def sd_torus(p, radius, tube):
    """Standard SDF for a torus [G]."""
    q = (abs(p[0]) - radius, abs(p[1]) - tube)
    return math.sqrt(max(q[0], 0)**2 + max(q[1], 0)**2) + min(max(q[0], q[1]), 0)

def map(p):
    """Returns tuple: (distance, material_id_normalized)."""
    d_torus = sd_torus(p, 1.0, 0.2)
    d_box = sd_box((p[0] + 3, p[1], p[2]), (0.75, 0.5, 0.5))
    d_sphere = sd_sphere((p[0] - 3, p[1], p[2]), 1.0)
    ret = opU((d_torus, 0.5), (d_box, 0.25))
    ret = opU(ret, (d_sphere, 0.75))
    return ret

def raymarch(ro, rd, color_ramp):
    t = 0.0
    max_steps = 64
    hit_id = -1.0
    for _ in range(max_steps):
        p = (ro[0] + rd[0]*t, ro[1] + rd[1]*t, ro[2] + rd[2]*t)
        d = map(p)
        if d[0] < 0.001:
            hit_id = d[1]
            break
        t += d[0]
    if hit_id >= 0:
        color = color_ramp[int(hit_id * len(color_ramp))]
        return color
    return (0.0, 0.0, 0.0)
```

## Subtopics

### [Material Object Format](1981-material-object-format.md)
A data structure holding surface shading info, separating geometric displacement from shading calculations.

## Operating characteristics
*   **Complexity:** Time complexity is identical to standard SDF ray marching $O(N)$ where $N$ is the number of steps, as the vector operations are constant-time [G]. Memory overhead is negligible, limited to the color ramp texture [S1, unofficial].
*   **Strengths:** Enables complex multi-material scenes with minimal code changes to the raymarching loop [G].
*   **Limitations:** The material ID is discrete; smooth transitions between materials require additional blending logic not inherent to the basic method [G]. Precision issues may arise if material IDs are not normalized consistently [G].

## Background
This technique was popularized in the context of real-time raymarching shaders, specifically within the Unity engine ecosystem [S1, unofficial]. It allows artists to define materials directly within the SDF code rather than relying on external mesh materials [S1, unofficial].
