# Smooth SDF Composition

Also called: Signed Distance Function (SDF) Scene Composition, Smooth Min SDF, Smooth Union of SDFs

## Overview
Smooth SDF Composition blends multiple primitive Signed Distance Functions (SDFs) into a single continuous field using a smooth minimum operator, avoiding the sharp creases produced by standard constructive SDF modeling [S1, unofficial]. Unlike the nearest-surface control of [Constructive SDF Modeling (Min Combination)](871-constructive-sdf-modeling-min-combination.md), this method creates a transitional volume between objects, enabling organic merging effects in ray marching [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: Two or more scalar SDF values ($d_1, d_2, \dots$) evaluated at a point $p$, and a blending factor $k \ge 0$.
- Output: A single blended distance value $d_{smooth}$.

**Data Structures:**
No specific data structures are required beyond the scalar values returned by individual primitive SDF evaluators (e.g., `sdfTorus`, `sdfBox` as defined in [S1, unofficial]).

**Steps:**
1. Evaluate the individual SDF for each primitive at the query point $p$. For example, calculate $d_{torus}$ and $d_{box}$ [S1, unofficial].
2. Select a blending factor $k$. A typical value is $0.5$ for moderate blending [S1, unofficial].
3. Compute the smooth minimum of the distances using the formula:
   $$ d_{smooth} = -\frac{1}{k} \ln(e^{-k d_1} + e^{-k d_2}) $$
   This formula approximates the minimum while maintaining $C^1$ continuity [S1, unofficial].
4. Return $d_{smooth}$ as the distance to the nearest object in the blended scene [S1, unofficial].

**Parameters:**
- $k$: Blending factor. Controls the width of the transition zone. Larger $k$ approaches the hard minimum; smaller $k$ creates a smoother, wider blend. Typical value: $0.5$ [S1, unofficial].

**Edge Cases and Pitfalls:**
- If $k=0$, the formula involves division by zero. In practice, if $k$ is very small, the result approaches the arithmetic mean or requires a fallback to the standard minimum [G].
- Precision issues may arise if $d_1$ and $d_2$ differ significantly in magnitude, causing one exponential term to dominate and underflow/overflow [G].

**Pseudocode:**
```python
import math

def smooth_min(d1: float, d2: float, k: float) -> float:
    """
    Computes the smooth minimum of two distances.
    :param d1: Distance to first primitive
    :param d2: Distance to second primitive
    :param k: Blending factor (>= 0)
    :return: Blended distance
    """
    if k == 0.0:
        # Fallback to standard minimum if no blending is requested
        return min(d1, d2)
    
    # Calculate exponential terms
    # Note: In production, clamp inputs to avoid overflow in exp()
    exp1 = math.exp(-k * d1)
    exp2 = math.exp(-k * d2)
    
    # Sum of exponentials
    sum_exp = exp1 + exp2
    
    # Log-sum-exp trick for stability: -1/k * ln(sum_exp)
    # If sum_exp is 0 (extremely large negative distances), handle gracefully
    if sum_exp == 0.0:
        return min(d1, d2)
        
    return -1.0 / k * math.log(sum_exp)

def evaluate_scene_sdf(p: Vector3, primitives: list, k: float) -> float:
    """
    Evaluates the scene SDF by composing primitives with smooth min.
    :param p: Query point
    :param primitives: List of primitive SDF evaluators
    :param k: Global blending factor
    :return: Smoothed scene distance
    """
    if not primitives:
        return float('inf')
        
    # Initialize with the first primitive
    current_dist = primitives[0].evaluate(p)
    
    # Blend with subsequent primitives
    for i in range(1, len(primitives)):
        next_dist = primitives[i].evaluate(p)
        current_dist = smooth_min(current_dist, next_dist, k)
        
    return current_dist
```

## Subtopics

### Scene SDF Evaluation
Computes the minimum signed distance from a point to any primitive in the scene, effectively performing a union operation [S2, unofficial]. It initializes a minimum distance variable (e.g., `MAX_SIGNED_DISTANCE` or 10000.0) and iterates through all scene primitives (spheres, cuboids, etc.), updating the minimum distance with the result of each primitive's SDF evaluation [S2, unofficial]. This is the standard hard-min approach, distinct from smooth composition as it does not blend distances but selects the absolute nearest [S2, unofficial].

## Operating characteristics
- **Time Complexity:** $O(N)$ where $N$ is the number of primitives, as each primitive must be evaluated to determine the minimum [S2, unofficial].
- **Memory Complexity:** $O(1)$ auxiliary space, storing only the current minimum distance [S2, unofficial].
- **Strengths:** Enables organic, fluid merging of shapes without sharp edges, useful for organic modeling or material blending [S1, unofficial].
- **Limitations:** The smooth transition zone can obscure the true boundary of objects, potentially causing ray marching artifacts if the step size is not adjusted for the gradient changes in the blend region [G]. It is computationally slightly more expensive than hard min due to transcendental functions (exp, log) [S1, unofficial].

## Background
Smooth SDF composition is a technique used in ray marching and implicit surface rendering to create visually pleasing transitions between geometric primitives [S1, unofficial]. It was popularized in the context of procedural geometry and shader programming, notably by artists and developers sharing code on platforms like GitHub [S1, S2, unofficial]. The technique relies on the mathematical property of the smooth minimum function to approximate the lower envelope of distance fields while maintaining differentiability [S1, unofficial].
