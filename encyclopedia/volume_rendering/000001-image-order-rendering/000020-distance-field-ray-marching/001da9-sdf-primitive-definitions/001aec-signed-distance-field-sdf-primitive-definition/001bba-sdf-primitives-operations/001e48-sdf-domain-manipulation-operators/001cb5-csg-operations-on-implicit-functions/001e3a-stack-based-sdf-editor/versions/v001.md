# Stack-Based SDF Editor

Also called: Post-order SDF construction, RPN-style SDF editor

## Overview
An interactive editor that constructs Signed Distance Fields (SDFs) from primitives and operations using a stack-based interface similar to Reverse Polish Notation (RPN), implicitly representing a tree with postorder traversal [S1, unofficial]. It differs from explicit tree editors by deferring structure resolution until compilation, allowing users to build complex scenes by pushing operations onto a linear stack where only the top item is visible until combined [S1, unofficial].

## How it works
**Inputs and Outputs:**
- Input: A sequence of operations pushed onto a stack. Operations are categorized as Shapes, Transformations, or CSG Operations [S1, unofficial].
- Output: A compiled GLSL shader string containing the SDF evaluation function [S1, unofficial].

**Data Structures:**
- **Operation Stack:** A list of operation objects. Each object contains:
  - `type`: Enum indicating 'Shape', 'Transformation', or 'Operation' [S1, unofficial].
  - `params`: Arguments specific to the operation (e.g., radius, offset, rotation angle) [S1, unofficial].
  - `children`: Implicitly defined by stack position during tree reconstruction [S1, unofficial].
- **AST Tree:** A recursive structure built from the stack. Nodes are either:
  - **Leaf:** A primitive shape function with an associated list of domain-modifying transformations [S1, unofficial].
  - **Internal:** A CSG operation (e.g., `min` for union) acting on range values [S1, unofficial].

**Steps:**
1. **Push Operation:** When a user adds an operation, it is pushed onto the stack. The UI updates to show parameters for this operation. If the operation is a CSG operation (arity 2), it consumes the top two items from the conceptual stack to form a new composite item [S1, unofficial].
2. **Invalidate Cache:** Modifying any parameter calls `#invalidate`, which clears the cached GLSL shader program [S1, unofficial].
3. **Build SDF (Tree Reconstruction):**
   - Iterate through the operation stack from bottom to top (or top to bottom, depending on implementation, but logically processing post-order) [S1, unofficial].
   - For each operation, pop the required number of operands from a temporary buffer based on the operation's arity [S1, unofficial].
   - Construct the AST node.
     - If the operation is a **Shape**, create a leaf node.
     - If the operation is a **Transformation**, attach it to the domain of the top shape node. Transformations modify the input position $p$ before evaluation [S1, unofficial].
     - If the operation is a **CSG Operation** (e.g., Union, Intersection), create an internal node that applies the range operation (e.g., $min$) to its children [S1, unofficial].
4. **Generate GLSL:**
   - Recursively traverse the AST [S1, unofficial].
   - For **Leaf Nodes**: Compose the domain transformations. If transformations $T_1, T_2, \dots$ were applied to the object in that order, the input position $p$ is transformed as $T_n(\dots T_2(T_1(p)) \dots)$ [S1, unofficial]. The GLSL code calls the primitive function with this transformed position: `sdPrimitive(opTx(opRot(p), offset), params)` [S1, unofficial].
   - For **Internal Nodes**: Generate the range operation. For Union, generate `min(left, right)` [S1, unofficial].
5. **Compile:** Assemble the generated GLSL string into a template and compile the shader program [S1, unofficial].

**Formulas:**
- **Union:** $S_{union}(p) = \min(S_A(p), S_B(p))$ [S1, unofficial].
- **Domain Transformation:** If a shape is translated by $t$ and rotated by $R$, the SDF is evaluated at $R^{-1}(p - t)$ [S1, unofficial]. Note: The source describes composing functions in the opposite order of application for domain modifications [S1, unofficial].

**Parameters:**
- **Stack Size:** Not given in the sources.
- **Primitive Types:** Box, Sphere (radius 1.0 example) [S1, unofficial].
- **Transformations:** Translate (vec3), Rotate (float angle, axis implied) [S1, unofficial].

**Edge Cases and Pitfalls:**
- **Visibility:** Until a union or similar operation is pushed, subsequent stack items are not visible in the viewport because the editor only considers the first item on the stack by default [S1, unofficial].
- **Performance:** Without the `#invalidate` caching mechanism, the shader would be reassembled and compiled on every frame, which is inefficient [S1, unofficial].
- **Tree Structure:** The generated AST tree is not identical to the conceptual operation tree because domain modifications (transformations) are handled differently from range modifications (CSG operations) [S1, unofficial].

**Pseudocode:**
```python
class Operation:
    def __init__(self, type, params):
        self.type = type  # 'Shape', 'Transform', 'CSG'
        self.params = params

class StackBasedSDFEditor:
    def __init__(self):
        self.stack = []
        self.cached_shader = None

    def push_operation(self, op_type, params):
        self.stack.append(Operation(op_type, params))
        self.invalidate()

    def invalidate(self):
        self.cached_shader = None

    def build_sdf(self):
        if self.cached_shader is not None:
            return self.cached_shader
        
        # Reconstruct AST from stack
        # Note: The source implies iterating the stack to pop operations
        # based on arity. We assume a post-order processing logic.
        ast_stack = []
        
        for op in self.stack:
            if op.type == 'Shape':
                # Create leaf node with empty transform list
                node = {'type': 'Leaf', 'shape': op.params['shape'], 'transforms': []}
                ast_stack.append(node)
            elif op.type == 'Transform':
                # Attach transform to the top shape node
                if not ast_stack:
                    raise ValueError("Transform without shape")
                top = ast_stack[-1]
                top['transforms'].append(op.params)
            elif op.type == 'CSG':
                # Pop two operands for binary CSG operations
                if len(ast_stack) < 2:
                    raise ValueError("CSG operation requires two operands")
                right = ast_stack.pop()
                left = ast_stack.pop()
                node = {'type': 'CSG', 'op': op.params['op'], 'left': left, 'right': right}
                ast_stack.append(node)
        
        if not ast_stack:
            return ""
            
        root = ast_stack[0]
        glsl_code = self.generate_glsl(root)
        self.cached_shader = glsl_code
        return glsl_code

    def generate_glsl(self, node):
        if node['type'] == 'Leaf':
            # Compose transforms in reverse order of application for domain
            # Source says: "compose them in the opposite order in which they were applied"
            # Assuming transforms list is [T1, T2] applied as T2(T1(p))
            # GLSL composition: T1(T2(p)) ? 
            # Source example: opTx(opRotX(p, 1.48), vec3(3, 0, 0))
            # This implies the last transform in the list is applied first to p?
            # Let's follow the source example structure.
            current_p = "p"
            for t in reversed(node['transforms']):
                if t['type'] == 'Translate':
                    current_p = f"vec3({current_p}.x - {t['offset'][0]}, {current_p}.y - {t['offset'][1]}, {current_p}.z - {t['offset'][2]})"
                elif t['type'] == 'Rotate':
                    # Simplified rotation placeholder
                    current_p = f"opRotX({current_p}, {t['angle']})"
            
            return f"sd{node['shape'].upper()}({current_p}, {node['params'].get('radius', '1.0')})"
        
        elif node['type'] == 'CSG':
            left_code = self.generate_glsl(node['left'])
            right_code = self.generate_glsl(node['right'])
            if node['op'] == 'Union':
                return f"min({left_code}, {right_code})"
            elif node['op'] == 'Intersection':
                return f"max({left_code}, {right_code})"
            # Other CSG ops not detailed in source
            return f"min({left_code}, {right_code})" # Default to union if unspecified
        
        return ""
```

## Subtopics

### SDF Primitive Definitions
The base primitives (Box, Sphere) used as leaves in the editor's stack [S1, unofficial].

## Operating characteristics
- **Time Complexity:** Shader compilation is $O(N)$ where $N$ is the number of operations in the stack, as it requires a single pass to build the AST and a recursive pass to generate GLSL [S1, unofficial].
- **Memory Complexity:** $O(N)$ to store the stack and the AST tree [S1, unofficial].
- **Performance:** Caching prevents recompilation on every frame, making runtime evaluation efficient. The bottleneck is the initial compilation [S1, unofficial].
- **Strengths:** Intuitive interface for building complex scenes; lazy evaluation ensures efficiency [S1, unofficial].
- **Limitations:** Limited to the primitives and operations explicitly implemented in the editor; debugging generated GLSL can be difficult due to the implicit stack-to-tree conversion [S1, unofficial].

## Background
The Stack-Based SDF Editor was developed as part of a final project for COS 426, focusing on raymarching with Signed Distance Fields [S1, unofficial]. It was designed to demonstrate how SDFs can be built up from primitives and operations using a stack-based interface similar to RPN notation [S1, unofficial].
