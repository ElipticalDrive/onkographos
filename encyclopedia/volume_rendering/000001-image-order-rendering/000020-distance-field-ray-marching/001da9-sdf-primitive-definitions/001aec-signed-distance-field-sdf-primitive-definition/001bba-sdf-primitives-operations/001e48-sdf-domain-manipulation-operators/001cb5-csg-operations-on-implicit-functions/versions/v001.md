# CSG Operations on Implicit Functions

Also called: CSG implicit surfaces, Constructive Solid Geometry, Constructive Solid Geometry (CSG) on Implicit Surfaces, Constructive Solid Geometry (CSG) with SDFs, Constructive Solid Geometry (CSG) with Signed Distance Bounds, Range Operations, SDF Boolean Operations, Set Operations, Union/Intersection via min/max

## Overview
Constructive Solid Geometry (CSG) on implicit functions composites multiple primitive shapes into a single implicit surface by applying Boolean logic to their distance fields [S1, S5]. This method allows the rendering of complex geometries composed of multiple primitives using a single field evaluation, which is essential for ray marching and bisection tracers [S1, S8]. Unlike explicit mesh operations, CSG on implicit functions reduces geometric composition to arithmetic operations on scalar values, enabling "free" normals and shadows derived from the resulting field's gradient [S4]. It is distinguished from sibling primitives by its role as a compositing layer that combines the outputs of [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md), [Signed Box Distance Function](1092-signed-box-distance-function.md), and other primitives into a unified scene representation.

## How it works
**Inputs and Outputs:**
*   **Inputs:** Two or more signed distance functions (SDFs), denoted $f_1(\mathbf{p})$ and $f_2(\mathbf{p})$, evaluated at a point $\mathbf{p}$ in 3D space. Each $f_i$ returns a scalar representing the signed distance to the surface of the $i$-th primitive.
*   **Outputs:** A new signed distance function $f_{result}(\mathbf{p})$ that represents the Boolean combination of the input shapes.

**Data Structures:**
The method operates on scalar values. In voxel-based implementations, it operates on 3D grids of floating-point values. In ray-marching implementations, it operates on single scalar values per ray step.

**Core Formulas:**
The fundamental CSG operations on SDFs are defined as follows [S2, S3, S4, S5, S6]:

1.  **Union:** The distance to the union is the minimum of the individual distances. A point is inside the union if it is inside at least one component.
    $$f_{union}(\mathbf{p}) = \min(f_1(\mathbf{p}), f_2(\mathbf{p}))$$
2.  **Intersection:** The distance to the intersection is bounded by the maximum of the individual distances. A point is inside the intersection only if it is inside all components.
    $$f_{intersection}(\mathbf{p}) = \max(f_1(\mathbf{p}), f_2(\mathbf{p}))$$
3.  **Difference (Subtraction):** Subtracting shape $B$ from shape $A$ is equivalent to intersecting $A$ with the complement of $B$. The complement of an SDF is its negation.
    $$f_{diff}(\mathbf{p}) = \max(f_1(\mathbf{p}), -f_2(\mathbf{p}))$$

**Proof of Correctness for Intersection (Signed Distance Bounds):**
While Union preserves the exact signed distance property, Intersection and Difference yield *signed distance bounds* rather than exact distances [S2]. This is because DeMorgan’s theorem does not hold directly with min/max operators for distance bounds (the minimum operator is not complemented properly) [S2]. The correctness of the intersection bound $\max(d_A, d_B)$ is verified by four cases [S2]:
*   **Case I ($d_A < 0, d_B < 0$):** Both points are inside. The distance to the intersection edge is the larger (less negative) of the two distances.
*   **Case II ($d_A < 0, d_B > 0$):** Point is inside $A$ but outside $B$. The closest point on $A$ to $\mathbf{p}$ may not be in the intersection, but no point in the intersection can be closer than $d_B$. Thus, the bound is $d_B$ (which is $> d_A$).
*   **Case III ($d_A > 0, d_B < 0$):** Symmetric to Case II.
*   **Case IV ($d_A > 0, d_B > 0$):** Both points are outside. The closest point in the intersection is no closer than the farther of the two distances.

**Pseudocode (Ray Marching Context):**
The following Python-like pseudocode demonstrates the evaluation of CSG operations within a standard sphere-tracing loop. It assumes `scene(p)` returns the composite SDF value.

```python
def evaluate_union(p, sdf_a, sdf_b):
    """Returns the signed distance to the union of two shapes."""
    return min(sdf_a(p), sdf_b(p))

def evaluate_intersection(p, sdf_a, sdf_b):
    """Returns the signed distance bound to the intersection of two shapes."""
    return max(sdf_a(p), sdf_b(p))

def evaluate_difference(p, sdf_a, sdf_b):
    """Returns the signed distance bound to A minus B."""
    return max(sdf_a(p), -sdf_b(p))

def ray_march_csg(scene_func, ray_origin, ray_direction, max_steps=64, max_dist=100.0, epsilon=0.001):
    """
    Standard sphere tracing loop using a composite CSG scene function.
    scene_func(p) must internally call the appropriate min/max operations.
    """
    t = 0.0
    for _ in range(max_steps):
        pos = ray_origin + t * ray_direction
        dist = scene_func(pos)
        
        # Hit detection
        if dist < epsilon:
            return t, pos
        
        # Miss detection
        if t > max_dist:
            return None, None
            
        # Advance along ray
        t += dist
        
    return None, None
```

**Pseudocode (Voxel Grid Context):**
For voxel-based level set operations, the operations are applied element-wise across the grid [S6].

```python
def voxel_union(buffer_a, buffer_b):
    """In-place union of two voxel buffers."""
    dims = buffer_a.dims()
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                buffer_a.value(i, j, k) = min(buffer_a.value(i, j, k), buffer_b.value(i, j, k))

def voxel_difference(buffer_a, buffer_b):
    """In-place difference (A minus B) of two voxel buffers."""
    dims = buffer_a.dims()
    for k in range(dims.min.z, dims.max.z + 1):
        for j in range(dims.min.y, dims.max.y + 1):
            for i in range(dims.min.x, dims.max.x + 1):
                buffer_a.value(i, j, k) = max(buffer_a.value(i, j, k), -buffer_b.value(i, j, k))
```

**Edge Cases and Pitfalls:**
*   **Normals at CSG Boundaries:** The gradient of the resulting SDF provides surface normals. However, at the boundaries where CSG operations switch (e.g., where $\min(f_1, f_2)$ switches from $f_1$ to $f_2$), the gradient may be discontinuous or incorrect if not handled carefully. Standard finite difference methods for normals may produce artifacts at these seams [S4].
*   **Material/Color Changes:** Polygonizers generating meshes from CSG level sets do not inherently consider material properties. This can lead to drastic color changes between vertices at CSG boundaries if materials are not treated as surface boundaries (inside/outside changes) [S5].
*   **Signed Distance Bound Accuracy:** Intersection and Difference operations do not preserve the exact signed distance property. The resulting field is a bound, which may cause sphere tracing to overshoot or undershoot slightly compared to an exact SDF, though it remains valid for rendering [S2].

## Subtopics

### Smooth Union
An alternative to the standard Union operation that creates a smooth transition (rounded fillets) between the edges of two shapes rather than a sharp crease. It takes an additional float parameter $k$ (typically 0 to 2) determining the degree of smoothness. It uses a polynomial function `smin(a, b, k)` instead of `min(a, b)` [S3, S4].

### Smooth Intersection
Similar to Smooth Union, this operation creates a smooth transition for the intersection of two shapes. It retains the common part but blends the boundary smoothly using the `smin` function with a smoothness parameter $k$ [S3].

### Smooth Subtract
Similar to Smooth Union, this operation subtracts the second shape from the first with a smooth transition at the boundary. It uses the `smin` function combined with negation logic [S3].

### Union Stairs
A binary operation that takes the union of two shapes and creates a set of steps between the edges where they connect. It takes two additional float parameters: $r$ (step width) and $n$ (number of steps) [S3].

### Difference Stairs
Behaves like Union Stairs but performs subtraction (A minus B) instead of union, creating stepped boundaries for the difference operation [S3].

### Intersection Stairs
Behaves like Union Stairs but performs intersection, creating stepped boundaries for the intersection operation [S3].

### Noise
A unary operation that adds Perlin noise to the signed distance of a shape. It takes a float parameter `noiseProp` (0 to 0.5) determining the intensity of the noise. It uses a GLSL `mix` function to blend the noise into the distance value: `mix(f, f + noise, noiseProp)` [S3].

### Onion
A unary operation that creates a hole inside a shape, resulting in a hollow object. It takes a float parameter `thickness` (smaller values result in larger holes). The implementation typically involves modifying the distance function to create a negative distance region inside the original shape [S3].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation. The cost of CSG operations is negligible compared to the cost of evaluating the underlying primitive SDFs (e.g., sphere or box distance). The total cost is proportional to the number of primitives in the CSG tree.
*   **Memory Complexity:** $O(1)$ for ray marching (scalar values). $O(N)$ for voxel grids, where $N$ is the number of voxels, as intermediate buffers may be required for multi-step CSG trees.
*   **Strengths:**
    *   **Simplicity:** Complex geometry is defined by simple arithmetic expressions.
    *   **Normals and Shadows:** Surface normals are derived analytically from the gradient of the composite SDF, and soft shadows can be computed using the same field, requiring no additional data structures [S4].
    *   **Exact Bounds:** Union preserves the exact signed distance property, allowing for optimal sphere tracing step sizes.
*   **Limitations:**
    *   **Intersection Bounds:** Intersection and Difference operations yield signed distance *bounds*, not exact distances. This can lead to slightly suboptimal step sizes in sphere tracing (overshooting or undershooting) [S2].
    *   **Discontinuities:** Sharp CSG boundaries can cause gradient discontinuities, leading to visual artifacts in normals if not smoothed [S4].
    *   **Material Handling:** Standard CSG does not handle material changes at boundaries automatically; explicit handling is required for correct shading across different materials [S5].
*   **When to Use:** Ideal for rendering complex, hard-surface geometry composed of basic primitives (spheres, boxes, cylinders) where exact mesh topology is not required, and where the simplicity of the field definition outweighs the need for exact intersection distances.
*   **When Not to Use:** When exact signed distance properties are critical for all operations (e.g., precise collision detection requiring exact penetration depth), or when complex material transitions are needed without additional logic.

## Background
CSG on implicit surfaces was formalized following Ricci's work in 1974, which established that minimum and maximum operations on functions result in union and intersection operations on their implicit surfaces [S2]. The method became widely popularized in real-time graphics through the "sphere tracing" technique described by John C. Hart in 1996, which demonstrated how SDFs could be used for antialiased ray tracing of implicit surfaces [S2]. The specific arithmetic formulations for SDFs (min for union, max for intersection) were further detailed in subsequent literature on geometric methods for ray tracing [S2]. The technique is a cornerstone of ray-marched rendering, enabling the creation of complex fractals and composite objects with minimal code overhead [S4].
