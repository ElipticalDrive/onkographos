# CSG Operations on Implicit Functions

Also called: CSG Operations, SDF Boolean Operations, SDF Boolean Operators, Boolean SDF operators, CSG with SDFs, CSG SDF combination, CSG implicit surfaces, CSG Operations for SDFs, Constructive Solid Geometry with SDFs

## Overview
CSG Operations on Implicit Functions is a technique for creating complex geometric shapes from simple Signed Distance Function (SDF) primitives via boolean operations: union, intersection, and difference [S2, unofficial][S5, unofficial][S4, unofficial]. It maps set-theoretic boolean logic directly to arithmetic operators on scalar distance values, allowing the construction of complex implicit surfaces from simple components [S3, unofficial]. Unlike explicit mesh-based CSG which requires complex topological handling, this method reduces scene composition to simple arithmetic, enabling the rendering of near-tangent intersections and complex composites with minimal code overhead [S6, unofficial]. It builds on [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md) which handle spatial transformations, while this article handles the combination of the resulting distance fields.

## How it works

### Inputs and Outputs
*   **Inputs**: Two (or more) SDF values, $d_A$ and $d_B$, evaluated at the same query point $\mathbf{p}$. These values represent the signed distances to the surfaces of object A and object B, respectively.
*   **Outputs**: A single combined SDF value $d_{combined}$ representing the distance to the resulting boolean surface.

### Data Structures
The scene is typically represented as a binary tree (or expression tree) where leaves are primitive SDF functions and internal nodes are CSG operators [S1, unofficial][S3, unofficial].

**Tree Layout:**
```python
class CSGNode:
    def __init__(self, operation, left, right):
        self.operation = operation  # Union, Intersection, Difference
        self.left = left            # CSGNode or PrimitiveSDF
        self.right = right          # CSGNode or PrimitiveSDF

class PrimitiveSDF:
    def __init__(self, sdf_func, material_id):
        self.sdf_func = sdf_func  # Function returning float
        self.material_id = material_id
```

### Formulas
The core mechanism relies on the properties of signed distances:
*   $d < 0$: Point is inside the surface.
*   $d > 0$: Point is outside the surface.
*   $d = 0$: Point is on the surface.

**1. Union ($A \cup B$)**
The union contains points inside A OR inside B. The distance to the closest surface is the minimum of the two distances [S2, unofficial][S8, unofficial][S9, unofficial][S11, unofficial][S12, unofficial].
$$ d_{union} = \min(d_A, d_B) $$

**2. Intersection ($A \cap B$)**
The intersection contains points inside A AND inside B. The distance to the boundary is bounded by the farthest surface, ensuring the point remains inside both [S2, unofficial][S7][S8, unofficial][S9, unofficial][S11, unofficial][S12, unofficial].
$$ d_{intersection} = \max(d_A, d_B) $$

**3. Difference ($A - B$)**
Subtracting B from A is equivalent to intersecting A with the complement (inverse) of B. The complement of an SDF is obtained by negating its value [S2, unofficial][S7][S8, unofficial][S9, unofficial][S11, unofficial][S12, unofficial][S13, unofficial].
$$ d_{difference} = \max(d_A, -d_B) $$

**4. XOR**
Points inside exactly one of the shapes.
$$ d_{xor} = \max(\min(d_A, d_B), -\max(d_A, d_B)) $$
[S9, unofficial]

### Smooth Variants
Standard boolean operations result in sharp creases. Smooth variants blend the transition using a parameter $k$ (typically $0.1$ to $1.0$) [S3, unofficial].

**Smooth Union (smin):**
Creates a rounded fillet of radius approximately $k$.
$$ h = \text{clamp}\left(0.5 + 0.5 \frac{d_B - d_A}{k}, 0.0, 1.0\right) $$
$$ d_{smooth\_union} = \text{mix}(d_B, d_A, h) - k \cdot h \cdot (1.0 - h) $$
[S11, unofficial][S12, unofficial]

**Smooth Intersection (smax):**
$$ d_{smooth\_intersection} = -\text{smin}(-d_A, -d_B, k) $$
[S4, unofficial]

**Smooth Difference:**
$$ d_{smooth\_difference} = \text{smax}(d_A, -d_B, k) $$
[S10, unofficial]

### Pseudocode
The following implementation demonstrates recursive evaluation of a CSG tree and the core arithmetic operations.

```python
import math

def min(a, b):
    return a if a < b else b

def max(a, b):
    return a if a > b else b

def clamp(val, min_val, max_val):
    if val < min_val: return min_val
    if val > max_val: return max_val
    return val

def mix(a, b, t):
    return a + t * (b - a)

def smin(a, b, k):
    """Smooth minimum for union blending."""
    h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0)
    return mix(b, a, h) - k * h * (1.0 - h)

def smax(a, b, k):
    """Smooth maximum for intersection blending."""
    return -smin(-a, -b, k)

def union_sdf(d_a, d_b):
    """Standard Union: min(d_a, d_b)."""
    return min(d_a, d_b)

def intersection_sdf(d_a, d_b):
    """Standard Intersection: max(d_a, d_b)."""
    return max(d_a, d_b)

def difference_sdf(d_a, d_b):
    """Standard Difference: max(d_a, -d_b)."""
    return max(d_a, -d_b)

def smooth_union_sdf(d_a, d_b, k):
    """Smooth Union with blend factor k."""
    return smin(d_a, d_b, k)

def smooth_difference_sdf(d_a, d_b, k):
    """Smooth Difference with blend factor k."""
    return smax(d_a, -d_b, k)

class CSGNode:
    def __init__(self, op, left, right, k=0.0):
        self.op = op
        self.left = left
        self.right = right
        self.k = k

    def evaluate(self, p):
        d_left = self.left.evaluate(p)
        d_right = self.right.evaluate(p)
        
        if self.op == "union":
            if self.k > 0:
                return smooth_union_sdf(d_left, d_right, self.k)
            return union_sdf(d_left, d_right)
        elif self.op == "intersection":
            if self.k > 0:
                return -smin(-d_left, -d_right, self.k)
            return intersection_sdf(d_left, d_right)
        elif self.op == "difference":
            if self.k > 0:
                return smooth_difference_sdf(d_left, d_right, self.k)
            return difference_sdf(d_left, d_right)
        else:
            raise ValueError(f"Unknown operation: {self.op}")

class PrimitiveSDF:
    def __init__(self, func):
        self.func = func

    def evaluate(self, p):
        return self.func(p)

# Example: Sphere minus Box
def sphere(p, center, radius):
    return math.sqrt(sum((p[i] - center[i])**2 for i in range(3))) - radius

def box(p, center, half_size):
    # Axis-aligned box SDF
    dist = 0.0
    for i in range(3):
        diff = max(abs(p[i] - center[i]) - half_size[i], 0.0)
        dist += diff**2
    return math.sqrt(dist)

# Build tree: Union(Sphere, Box) -> Intersection with Inverted Sphere (Difference)
# Actually, let's do Sphere - Box
sphere_node = PrimitiveSDF(lambda p: sphere(p, [0,0,0], 1.0))
box_node = PrimitiveSDF(lambda p: box(p, [0,0,0], [0.5, 0.5, 0.5]))
diff_node = CSGNode("difference", sphere_node, box_node)

# Evaluate at point
point = [0.0, 0.0, 0.0]
distance = diff_node.evaluate(point)
```

### Edge Cases and Pitfalls
1.  **Lipschitz Continuity in Difference**: The standard difference formula $\max(d_A, -d_B)$ is exact only when the surface of A is entirely contained within B, or when B does not "poke through" the boundary of A in a way that creates non-Lipschitz-1 regions [S11, unofficial]. If A pokes through B, the resulting SDF may not be a true distance field, causing sphere marching to skip surfaces. Mitigation: Add a small EPSILON correction or tighten the step size in those regions [S11, unofficial].
2.  **DeMorgan’s Theorem Limitations**: While set theory defines intersection as the complement of the union of complements, applying this to min/max operators for distance bounds does not work directly because the minimum operator is not complemented properly in the distance domain. Using $\max$ for intersection ensures the bound holds [S7].
3.  **Material Boundaries**: Standard CSG operations combine distance values but do not inherently track material IDs across the boolean boundary. Polygonizers may produce drastic color changes at CSG boundaries because they treat material changes as surface boundaries [S13, unofficial]. To separate colors, material changes must be explicitly treated as surface boundaries.
4.  **Scaling**: Scaling an SDF requires scaling the input coordinates by the inverse of the scale factor and scaling the output distance by the scale factor to maintain correct distance values [S2, unofficial].

## Subtopics

### [Stack-Based SDF Editor](1696-stack-based-sdf-editor.md)
An interactive editor that constructs SDFs from primitives and operations using a stack-based interface similar to Reverse Polish Notation (RPN). It differs from explicit tree editors by deferring structure resolution until compilation, allowing users to build complex scenes by pushing operations onto a linear stack where only the top item is visible until combined.

### Constructive Solid Geometry (CSG) on Level Sets
A voxel-based variant of CSG operations applied to discrete volumetric data rather than continuous implicit functions [S14, unofficial].
*   **Union**: $A_{new}(i,j,k) = \min(A(i,j,k), B(i,j,k))$
*   **Intersection**: $A_{new}(i,j,k) = \max(A(i,j,k), B(i,j,k))$
*   **Difference**: $A_{new}(i,j,k) = \max(A(i,j,k), -B(i,j,k))$
This approach operates on voxel grids, making it suitable for volume rendering pipelines that process discrete data rather than ray-marched continuous fields [S14, unofficial].

## Operating characteristics

*   **Time Complexity**: $O(N)$ per ray, where $N$ is the depth of the CSG tree. Each ray march step requires evaluating all nodes in the tree down to the leaves.
*   **Memory Complexity**: $O(D)$ where $D$ is the depth of the CSG tree (recursion stack) or $O(T)$ if the tree is stored explicitly.
*   **Strengths**:
    *   **Simplicity**: Complex geometry is defined with very little code [S12, unofficial].
    *   **Free Normals**: Surface normals are derived from the gradient of the combined SDF, which is consistent with the boolean logic [S12, unofficial].
    *   **No Topology Errors**: Avoids meshing artifacts like holes or self-intersections common in polygonal CSG [S11, unofficial].
*   **Limitations**:
    *   **Sharp Edges**: Standard boolean operations produce sharp, non-smooth edges. Smooth variants introduce approximation errors and require tuning the blend factor $k$ [S11, unofficial].
    *   **Distance Accuracy**: The resulting SDF is a bound, not necessarily the exact Euclidean distance, especially for concave shapes or complex differences [S7].
    *   **Performance**: Deep CSG trees increase the number of primitive evaluations per ray step, potentially slowing down rendering [S7].

## Background

CSG was introduced by Ian Buckland and others in the early 1980s for solid modeling [S2, unofficial]. The application of CSG to Signed Distance Functions was popularized in the context of ray marching and shader programming by artists and researchers such as Inigo Quilez and Jamie Wong in the 2010s [S2, unofficial][S11, unofficial][S12, unofficial]. The mathematical foundation relies on the properties of min and max operators on implicit surfaces, as described by Ricci in 1974 [S7]. The technique is widely used in real-time graphics, particularly in Shadertoy-style demos and procedural generation, due to its conciseness and visual appeal [S2, unofficial][S12, unofficial].
