# SDF Primitives

Also called: Basic SDFs, Basic Signed Distance Functions, SDF Primitive Functions, Signed Distance Field (SDF) Primitives, Signed Distance Primitives

## Overview
SDF Primitives are analytical Signed Distance Functions that compute the exact Euclidean distance from a query point in 3D space to the surface of a basic geometric shape, returning a negative value if the point is inside and a positive value if it is outside [S1, S3, S5, S7, S8]. They serve as the foundational building blocks for distance-field ray marching, enabling efficient step-size estimation by guaranteeing that the returned distance is never an underestimation, which prevents ray overshooting [S1, S7]. Unlike [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md) which transform space, or [SDF Rounding](1829-sdf-rounding.md) which modifies surfaces, primitives define the base geometry itself [S7].

## How it works
**Inputs:** A query point $p \in \mathbb{R}^3$ and primitive-specific parameters (e.g., radius, half-extents, normal).
**Outputs:** A scalar signed distance $d \in \mathbb{R}$.

**Data Structures:**
*   `vec3`: 3D vector $(x, y, z)$.
*   `vec2`: 2D vector $(x, y)$.
*   `float`: Scalar real number.

**General Transformations:**
All primitives are defined centered at the origin. To place a primitive at a different location or orientation:
1.  **Translate:** Replace $p$ with $p - c$, where $c$ is the center [S7].
2.  **Rotate:** Multiply $p$ by an inverse rotation matrix $R^{-1}$ before passing to the SDF: $p' = R^{-1} p$ [S7].
3.  **Scale:** Uniformly scale by $s$ using $d(p/s) \cdot s$ [S7].

**Formulas and Steps:**

1.  **Sphere**
    *   Parameters: Radius $r$.
    *   Formula: $d(p) = \|p\| - r$ [S1, S3, S5, S6, S7].
    *   Implementation: `return length(p) - r;` [S7].

2.  **Axis-Aligned Box (AABB)**
    *   Parameters: Half-extents $b = (b_x, b_y, b_z)$.
    *   Steps:
        1.  Compute $q = |p| - b$ (component-wise absolute value and subtraction) [S1, S3, S6, S7].
        2.  Compute $d_{out} = \| \max(q, 0.0) \|$ [S1, S3, S6, S7].
        3.  Compute $d_{in} = \min(\max(q_x, \max(q_y, q_z)), 0.0)$ [S1, S3, S6, S7].
        4.  Result: $d = d_{out} + d_{in}$ [S1, S3, S6, S7].
    *   Note: This handles faces, edges, and corners correctly without underestimation [S7].

3.  **Torus**
    *   Parameters: Major radius $R$, tube radius $r$.
    *   Steps:
        1.  Compute $q = (\|p_{xz}\| - R, p_y)$ where $p_{xz} = (p_x, p_z)$ [S1, S5, S6, S7].
        2.  Result: $d = \|q\| - r$ [S1, S5, S6, S7].

4.  **Infinite Plane**
    *   Parameters: Unit normal $n$, offset $d$ (distance from origin along normal).
    *   Formula: $d(p) = p \cdot n + d$ [S2, S7].
    *   Note: $n$ must be normalized [S2].

5.  **Cylinder (Infinite along Y)**
    *   Parameters: Radius $r$, half-height $h$.
    *   Steps:
        1.  Compute $d_{vec} = (\|p_{xz}\|, p_y)$ [S4, S7].
        2.  Compute $dist = |d_{vec}| - (r, h)$ [S4, S7].
        3.  Result: $d = \min(\max(dist_x, dist_y), 0.0) + \| \max(dist, 0.0) \|$ [S4, S7].
    *   Note: This defines a cylinder capped at $y = \pm h$ [S4, S7].

6.  **Capsule**
    *   Parameters: Endpoints $a, b$, radius $r$.
    *   Steps:
        1.  Compute vector $ab = b - a$ and $ap = p - a$ [S7].
        2.  Compute projection parameter $t = \text{clamp}(\frac{ap \cdot ab}{ab \cdot ab}, 0.0, 1.0)$ [S7].
        3.  Compute closest point on segment $c = a + ab \cdot t$ [S7].
        4.  Result: $d = \|p - c\| - r$ [S7].

7.  **Rhombic Triacontahedron**
    *   Parameters: None (fixed shape).
    *   Steps:
        1.  Initialize magic numbers: $c = \cos(\pi/5)$, $s = \sqrt{0.75 - c^2}$ [S8].
        2.  Define direction $n = (-0.5, -c, s)$ [S8].
        3.  Fold 1: $p = |p|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
        4.  Fold 2: $p_{xy} = |p_{xy}|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
        5.  Fold 3: $p_{xy} = |p_{xy}|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
        6.  Result: $d = p_z - 1.0$ [S8].

**Pseudocode:**
```python
import math

def vec3_length(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def vec3_dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def vec3_abs(v):
    return (abs(v[0]), abs(v[1]), abs(v[2]))

def vec3_sub(a, b):
    return (a[0]-b[0], a[1]-b[1], a[2]-b[2])

def vec3_add(a, b):
    return (a[0]+b[0], a[1]+b[1], a[2]+b[2])

def vec3_scale(v, s):
    return (v[0]*s, v[1]*s, v[2]*s)

def vec3_max_comp(v):
    return max(v[0], v[1], v[2])

def vec3_min_comp(v):
    return min(v[0], v[1], v[2])

def vec3_component_max(v, threshold):
    """Returns max(v.x, max(v.y, v.z)) if any component > threshold, else threshold."""
    # Based on S7: min(max(q.x, max(q.y, q.z)), 0.0)
    # We need the max component, clamped to 0.0 if negative? 
    # S7 formula: min(max(q.x, max(q.y, q.z)), 0.0)
    # This calculates the max component, then clamps it to 0.0 from above.
    m = max(v[0], max(v[1], v[2]))
    return min(m, 0.0)

def vec3_component_min(v, threshold):
    """Returns min(v.x, min(v.y, v.z)) if any component < threshold, else threshold."""
    # Not directly used in standard primitives listed, but for completeness.
    return min(v[0], min(v[1], v[2]))

def vec3_max_scalar(v, s):
    """Component-wise max of vector v and scalar s."""
    return (max(v[0], s), max(v[1], s), max(v[2], s))

def vec3_min_scalar(v, s):
    """Component-wise min of vector v and scalar s."""
    return (min(v[0], s), min(v[1], s), min(v[2], s))

def sd_sphere(p, r):
    return vec3_length(p) - r

def sd_box(p, b):
    q = vec3_sub(vec3_abs(p), b)
    d_out = vec3_length(vec3_max_scalar(q, 0.0))
    d_in = vec3_component_max(q, 0.0) # min(max(q.x, max(q.y, q.z)), 0.0)
    return d_out + d_in

def sd_torus(p, R, r):
    # p.xz length
    pxz_len = math.sqrt(p[0]**2 + p[2]**2)
    q = (pxz_len - R, p[1])
    return math.sqrt(q[0]**2 + q[1]**2) - r

def sd_plane(p, n, d):
    # n must be normalized
    return vec3_dot(p, n) + d

def sd_cylinder(p, r, h):
    # Cylinder along Y axis, capped at +/- h
    pxz_len = math.sqrt(p[0]**2 + p[2]**2)
    d_vec = (pxz_len, p[1])
    dist = vec3_sub(vec3_abs(d_vec), (r, h))
    # min(max(d.x, d.y), 0.0)
    min_max_val = min(max(dist[0], dist[1]), 0.0)
    # length(max(d, 0.0))
    d_out = vec3_length(vec3_max_scalar(dist, 0.0))
    return min_max_val + d_out

def sd_capsule(p, a, b, r):
    ab = vec3_sub(b, a)
    ap = vec3_sub(p, a)
    ab_dot_ab = vec3_dot(ab, ab)
    if ab_dot_ab == 0:
        return vec3_length(ap) - r
    t = vec3_dot(ap, ab) / ab_dot_ab
    t = max(0.0, min(1.0, t))
    closest = vec3_add(a, vec3_scale(ab, t))
    return vec3_length(vec3_sub(p, closest)) - r

def sd_rhombic_triacontahedron(p):
    c = math.cos(math.pi / 5.0)
    s = math.sqrt(0.75 - c*c)
    n = (-0.5, -c, s)
    
    # Fold 1
    p = vec3_abs(p)
    dot_pn = vec3_dot(p, n)
    p = vec3_sub(p, vec3_scale(n, 2.0 * min(0.0, dot_pn)))
    
    # Fold 2
    p_xy = (abs(p[0]), abs(p[1]), p[2])
    p = p_xy
    dot_pn = vec3_dot(p, n)
    p = vec3_sub(p, vec3_scale(n, 2.0 * min(0.0, dot_pn)))
    
    # Fold 3
    p_xy = (abs(p[0]), abs(p[1]), p[2])
    p = p_xy
    dot_pn = vec3_dot(p, n)
    p = vec3_sub(p, vec3_scale(n, 2.0 * min(0.0, dot_pn)))
    
    return p[2] - 1.0
```

## Subtopics

### [Signed Box Distance Function](1092-signed-box-distance-function.md)
Computes exact Euclidean distance to an axis-aligned box using component-wise absolute values and max/min operations. Chosen when axis-aligned bounding volumes are needed; distinguishes itself from spheres by handling distinct geometric regions (faces, edges, corners).

### [Plane Signed Distance Function](1102-plane-signed-distance-function.md)
Computes distance to an infinite plane defined by a unit normal and height. Chosen for infinite surfaces or clipping planes.

### [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md)
Computes exact Euclidean distance to a sphere surface. Chosen as the simplest primitive; analytically closed-form and computationally minimal compared to ellipsoids.

### [Ellipsoid Signed Distance Function](2397-ellipsoid-signed-distance-function.md)
Computes signed distance for an ellipsoid with radii $r$. Chosen when non-uniform scaling is required; requires solving higher-degree polynomials compared to the sphere.

### [Capsule Signed Distance Function](2439-capsule-signed-distance-function.md)
Computes signed distance for a capsule (cylinder with hemispherical caps) aligned with an axis or defined by endpoints. Chosen for organic shapes or limbs.

### Rhombic Triacontahedron SDF
A crystal shape constructed by folding 3D space using magic numbers and directions. Chosen for crystalline or iridescent effects [S8].

### Rhombic Triacontahedron SDF
A Signed Distance Function for a Rhombic Triacontahedron crystal shape, constructed by folding 3D space using specific magic numbers and directions multiple times [S8]. It distinguishes itself from standard convex primitives by using iterative space folding to create complex symmetry [S8]. Chosen for artistic or crystalline visual effects [S8].

**Definition:**
The shape is defined by folding space along a specific direction $n$ and axes, using magic numbers derived from $\pi/5$ [S8].

**Steps:**
1.  Initialize magic numbers: $c = \cos(\pi/5)$, $s = \sqrt{0.75 - c^2}$ [S8].
2.  Define direction $n = (-0.5, -c, s)$ [S8].
3.  Fold 1: $p = |p|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
4.  Fold 2: $p_{xy} = |p_{xy}|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
5.  Fold 3: $p_{xy} = |p_{xy}|$; $p = p - 2 \cdot \min(0.0, p \cdot n) \cdot n$ [S8].
6.  Result: $d = p_z - 1.0$ [S8].

**Formula:**
$c = \cos(\pi/5)$, $s = \sqrt{0.75 - c^2}$, $n = (-0.5, -c, s)$ [S8].

**Code:**
See `sd_rhombic_triacontahedron` in the main pseudocode section [S8].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per primitive evaluation. Most primitives involve a constant number of arithmetic operations and square roots [S1, S3, S5, S7].
*   **Memory Complexity:** $O(1)$, requiring only the query point and primitive parameters [S7].
*   **Performance:** Exact and efficient, free of numerical noise for standard primitives [S7]. The Rhombic Triacontahedron is more expensive due to multiple folds and trigonometric constants, but still $O(1)$ [S8].
*   **Strengths:** Exact distance guarantees prevent ray overshooting in sphere tracing [S1, S7]. Simple to implement and highly parallelizable on GPUs [S7].
*   **Limitations:** Only supports specific geometric shapes. Complex scenes require combining primitives via CSG operations, which can increase evaluation cost and introduce artifacts for concave geometry [S7].
*   **When to use:** Real-time ray marching, procedural geometry, and scenes composed of basic shapes [S1, S7].
*   **When not to use:** Scenes with highly complex, non-analytic geometry where mesh-based rendering or voxel-based methods are more appropriate [S8].

## Background
SDF primitives were popularized by Inigo Quilez in his articles on distance functions [S5, S7]. The concept of sphere tracing using SDFs was introduced earlier by John C. Hart in 1994 [S6]. The Rhombic Triacontahedron SDF was demonstrated by Varun A. in a tutorial on iridescent crystals [S8]. These primitives are widely used in creative coding, real-time rendering, and procedural generation [S5, S8].
