# Signed Box Distance Function

Also called: Box SDF, SDF Box, Rectangular (Axis-Aligned Box) SDF, SDF Cube, SDF Half-space Intersection

## Overview
The Signed Box Distance Function computes the exact Euclidean distance from a query point to the surface of an axis-aligned box, returning a negative value if the point is inside and a positive value if it is outside [S3, S5, S7]. It distinguishes itself from sibling primitives like the Sphere SDF by handling the distinct geometric regions of a box (faces, edges, and corners) using component-wise absolute values and max/min operations, ensuring the distance estimate is never an underestimation [S1, S7]. This property is critical for sphere tracing, as underestimating the distance can cause the ray to overshoot the surface or produce incorrect ambient occlusion [S1, S7].

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $p \in \mathbb{R}^3$ and box parameters: center $c \in \mathbb{R}^3$ and side lengths $s \in \mathbb{R}^3$ (where $s_i > 0$) [S4, S5, S6]. Alternatively, the box can be defined by half-extents $e = s/2$ [S2, S4].
*   **Output:** A scalar signed distance $d \in \mathbb{R}$. $d < 0$ indicates the point is inside the box; $d > 0$ indicates the point is outside; $d = 0$ indicates the point is on the surface [S4, S5, S7].

**Data Structures:**
*   The box is defined by two vectors: `center` (3 floats) and `side_lengths` (3 floats). In some implementations, these are learnable parameters [S4, S5, S6].

**Algorithm:**
The standard robust implementation (Algorithm 3.6 in [S7, S8]) proceeds as follows:

1.  **Translate and Scale:** Compute the vector from the box center to the point, then subtract the half-extents.
    $$ q = |p - c| - \frac{s}{2} $$
    Here, $| \cdot |$ is the component-wise absolute value. Let $q = (q_x, q_y, q_z)$ [S4, S5, S7, S8].

2.  **Determine Inside/Outside:** Calculate the maximum component of $q$.
    $$ m = \max(q_x, \max(q_y, q_z)) $$
    This value represents the distance to the closest face if the point is inside [S7, S8].

3.  **Compute Distance:**
    *   The outside distance is the Euclidean norm of the positive components of $q$ (clamping negative components to zero):
        $$ d_{\text{out}} = \| \max(q, 0) \|_2 = \sqrt{\max(q_x, 0)^2 + \max(q_y, 0)^2 + \max(q_z, 0)^2} $$
    *   The inside distance is the minimum of $m$ and zero:
        $$ d_{\text{in}} = \min(m, 0) $$
    *   The final signed distance is the sum:
        $$ d = d_{\text{out}} + d_{\text{in}} $$
    This branchless formulation is mathematically equivalent to the conditional version but avoids branching in shader execution [S4, S5, S7].

**Pseudocode:**
```python
def signed_box_distance(p, center, side_lengths):
    """
    Computes the exact signed distance from point p to an axis-aligned box.
    
    Args:
        p: vec3, query point coordinates.
        center: vec3, center of the box.
        side_lengths: vec3, lengths of the box sides (x, y, z).
        
    Returns:
        float: Signed distance. Negative if inside, positive if outside.
    """
    # Step 1: Translate point to box-local space and subtract half-extents
    # q = |p - center| - side_lengths / 2
    q_x = abs(p.x - center.x) - side_lengths.x / 2.0
    q_y = abs(p.y - center.y) - side_lengths.y / 2.0
    q_z = abs(p.z - center.z) - side_lengths.z / 2.0
    
    # Step 2: Determine inside/outside boundary via max component
    # m = max(q_x, max(q_y, q_z))
    m = q_x
    if q_y > m: m = q_y
    if q_z > m: m = q_z
    
    # Step 3: Compute outside distance (L2 norm of positive components)
    qx_pos = q_x if q_x > 0.0 else 0.0
    qy_pos = q_y if q_y > 0.0 else 0.0
    qz_pos = q_z if q_z > 0.0 else 0.0
    d_out = sqrt(qx_pos * qx_pos + qy_pos * qy_pos + qz_pos * qz_pos)
    
    # Step 4: Compute inside distance (min of max component and 0)
    d_in = m if m < 0.0 else 0.0
    
    # Step 5: Return combined signed distance
    return d_out + d_in
```

**Parameters:**
*   `center`: The 3D coordinates of the box center. Default: $(0, 0, 0)$ [S1, S7].
*   `side_lengths`: The width, height, and depth of the box. Must be positive. Half-extents $e = (0.5, 0.5, 0.5)$ yield a $1 \times 1 \times 1$ box [S7].

**Edge Cases and Pitfalls:**
*   **Underestimation:** An incorrect implementation (e.g., Algorithm 3.5 in [S7, S8]) may underestimate the distance in corner regions. This leads to smaller ray steps, slower convergence, and incorrect ambient occlusion (artifacts like black dots or banding) [S7, S8].
*   **Overestimation:** Overestimating the distance can cause the ray to pass through the surface or inaccurately estimate the surface position, also negatively impacting ambient occlusion [S7].
*   **Precision:** The use of absolute values and max/min operations is numerically stable. However, floating-point precision issues near the surface ($d \approx 0$) are common to all SDFs and may require epsilon clamping in downstream shading logic [G].

## Subtopics

### [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md)
Computes distance to a sphere. Simpler than the box, as it relies solely on radial distance. Choose when rotational symmetry is sufficient.

### [Ellipsoid Signed Distance Function](2397-ellipsoid-signed-distance-function.md)
Generalizes the sphere to non-uniform scaling. More complex than the box, requiring iterative or approximate methods for exact distance. Choose when anisotropic scaling is needed.

### [Capsule Signed Distance Function](2439-capsule-signed-distance-function.md)
Computes distance to a line segment with rounded caps. More complex than the box, involving projection onto a line. Choose for organic or limb-like shapes.

### [Plane Signed Distance Function](1102-plane-signed-distance-function.md)
Computes distance to an infinite plane. The simplest primitive. Choose for ground planes or infinite boundaries.

## Operating characteristics
*   **Time Complexity:** $O(1)$. The computation involves a fixed number of arithmetic operations (subtractions, absolute values, max/min, and one square root) [S8].
*   **Memory Complexity:** $O(1)$. No auxiliary data structures are required [G].
*   **Strengths:** Exact distance calculation; robust for sphere tracing; efficient; handles all octants uniformly via symmetry [S1, S7].
*   **Limitations:** Only applies to axis-aligned boxes. For rotated boxes, the point must be transformed into the box's local coordinate system first [G].
*   **When to use:** When rendering axis-aligned rectangular volumes or bounding boxes in ray marching [S1].
*   **When not to use:** For rotated boxes (use transformation) or when approximate distance is acceptable and simpler primitives suffice (though box SDF is already very simple) [G].

## Background
The Signed Box Distance Function is a fundamental primitive in Signed Distance Field (SDF) rendering, popularized by Inigo Quilez in his online resources on distance functions [S1]. It is used in ray marching for rendering implicit surfaces [S1] and in neural rendering pipelines where it serves as a learnable primitive [S4, S5, S6]. The correct formulation (Algorithm 3.6) was highlighted in academic work on GPU ray marching to avoid artifacts in ambient occlusion computation [S7, S8].
