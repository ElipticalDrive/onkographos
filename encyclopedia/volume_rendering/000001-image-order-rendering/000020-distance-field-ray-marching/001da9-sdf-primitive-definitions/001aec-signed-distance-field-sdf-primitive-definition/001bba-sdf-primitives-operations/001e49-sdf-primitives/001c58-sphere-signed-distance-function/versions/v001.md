# Sphere Signed Distance Function

Also called: Sphere SDF, SDF Sphere, Signed Distance Function Sphere, Signed Distance Function (SDF) for Sphere, Sphere Implicit Function, Sphere Distance Estimator, sdSphere, Sphere distance, implicit sphere

## Overview
The Sphere Signed Distance Function (SDF) computes the exact Euclidean distance from a query point in 3D space to the surface of a sphere, providing a signed value that indicates whether the point lies inside (negative), outside (positive), or on (zero) the surface [S1, S8, S10, S13]. It serves as a fundamental implicit primitive in distance-field ray marching, enabling efficient step-size estimation and surface normal calculation without explicit mesh intersection tests [S1, S10]. Unlike the [Ellipsoid Signed Distance Function](2397-ellipsoid-signed-distance-function.md), which requires solving higher-degree polynomials, the sphere SDF is analytically closed-form and computationally minimal [S12].

## How it works
### Inputs and Outputs
*   **Inputs**:
    *   `p`: The query point in 3D space, represented as a vector $(x, y, z)$ or `vec3` [S1, S3, S13].
    *   `c`: The center of the sphere, represented as a 3D vector $(c_x, c_y, c_z)$ [S3, S4, S5, S6]. Default is the origin $(0, 0, 0)$ [S1, S8, S11].
    *   `r`: The radius of the sphere, a scalar value $r > 0$ [S1, S3, S4, S5, S6, S8].
*   **Output**:
    *   `d`: A scalar representing the signed distance. $d = 0$ on the surface, $d < 0$ inside, $d > 0$ outside [S1, S8, S10, S13].

### Data Structures
No complex data structures are required. The function operates on standard vector and scalar types. In neural implicit representations, `c` and `r` may be stored as learnable parameters (tensors) [S4, S5, S6].

### Formula
The signed distance $d(p)$ from a point $p$ to a sphere with center $c$ and radius $r$ is defined as:

$$
d(p) = \| p - c \| - r
$$

Where:
*   $\| \cdot \|$ denotes the Euclidean norm (L2 norm).
*   $\| p - c \| = \sqrt{(p_x - c_x)^2 + (p_y - c_y)^2 + (p_z - c_z)^2}$ [S3, S4, S5, S6, S10, S13].

If the sphere is centered at the origin ($c = 0$), the formula simplifies to:

$$
d(p) = \| p \| - r
$$

[S1, S8, S9, S11]

### Parameters
*   **Radius (`r`)**: The physical radius of the sphere. In some implementations, this is a hardcoded constant (e.g., 0.5 or 1.0) [S8, S11], while in others (particularly neural implicit fields), it is a learnable parameter initialized from configuration [S4, S5, S6].
*   **Center (`c`)**: The 3D coordinates of the sphere's center. Like the radius, this can be fixed or learnable [S4, S5, S6]. Default is $(0, 0, 0)$ [S1, S7, S8].

### Pseudocode
The following Python-like pseudocode implements the general case (arbitrary center). For performance, the square root operation is the most expensive component; however, for exact SDF evaluation, it is necessary.

```python
import math

def sphere_sdf(p, c, r):
    """
    Computes the signed distance from point p to a sphere with center c and radius r.
    
    Args:
        p (tuple or list of 3 floats): Query point (x, y, z).
        c (tuple or list of 3 floats): Sphere center (cx, cy, cz).
        r (float): Sphere radius.
        
    Returns:
        float: Signed distance. Negative if inside, positive if outside.
    """
    # Calculate the vector from the center to the point
    dx = p[0] - c[0]
    dy = p[1] - c[1]
    dz = p[2] - c[2]
    
    # Calculate Euclidean distance from center to point
    dist_to_center = math.sqrt(dx*dx + dy*dy + dz*dz)
    
    # Subtract radius to get signed distance
    return dist_to_center - r
```

### Edge Cases and Pitfalls
1.  **Radius Zero**: If $r=0$, the function returns the distance to the center point. This is valid but represents a degenerate sphere (a point) [S12].
2.  **Negative Radius**: The radius must be non-negative. A negative radius is physically undefined for a standard sphere SDF [S12].
3.  **Precision**: For points very close to the surface, floating-point precision errors in the square root calculation may cause jitter in normal estimation if the gradient is computed numerically. Analytical gradients are preferred [S1].
4.  **Definition Order**: In some scripting environments (e.g., Fennel/Lua), the SDF function must be defined before any object constructor or scene graph that references it, due to top-down evaluation order [S13].

## Subtopics

### Circle Signed Distance Function
The 2D analog of the sphere SDF. It computes the signed distance from a 2D point $p$ to a circle of radius $r$ centered at the origin.
*   **Formula**: $d(p) = \|p\| - r$, where $\|p\| = \sqrt{x^2 + y^2}$ [S9].
*   **Usage**: Used in 2D ray marching or as a cross-section primitive.
*   **Code**: `pub fn circle(p: Vec2, r: f32) -> f32 { p.length() - r }` [S9].

## Operating characteristics
*   **Time Complexity**: $O(1)$. The computation involves a fixed number of arithmetic operations (subtractions, multiplications, one addition, one square root) [S1, S8, S13].
*   **Memory Complexity**: $O(1)$. No auxiliary memory is required beyond the input and output scalars/vectors [S1, S8].
*   **Strengths**:
    *   **Exactness**: Provides the exact Euclidean distance, unlike voxel-based approximations [S3, S12].
    *   **Efficiency**: Extremely fast to evaluate, making it suitable for real-time ray marching where millions of samples are taken per frame [S1, S8].
    *   **Smoothness**: The function is differentiable everywhere except at the center $c$ (where the gradient is undefined), which is typically not sampled in ray marching [S1, S12].
*   **Limitations**:
    *   **Center Singularity**: The gradient $\nabla d(p) = \frac{p-c}{\|p-c\|}$ is undefined at $p=c$. Ray marchers should avoid stepping exactly to the center, though this is rare in practice [S1, S12].
    *   **Shape Limitation**: Only represents perfect spheres. Cannot represent complex organic shapes without composition (e.g., blending with other SDFs) [S10].
*   **When to use**: Ideal for simple geometric primitives, collision detection, and as building blocks for complex scenes via Boolean operations (union, intersection) [S10].
*   **When not to use**: When the object is not spherical or when high-frequency geometric detail is required without composition [S10].

## Background
The Sphere SDF is one of the most basic implicit surface representations, originating from the field of constructive solid geometry (CSG) and ray marching. It was popularized in the context of real-time graphics by Inigo Quilez, who compiled a list of distance functions for common shapes [S1]. The mathematical foundation relies on the definition of a sphere as the locus of points equidistant from a center [S12]. The use of signed distances for ray marching (spheretracing) was formalized by John C. Hart in 1994, who demonstrated that the sphere SDF allows for efficient antialiased ray tracing of implicit surfaces [S12]. The simplicity of the sphere SDF makes it a standard example in tutorials on distance field rendering [S8, S10, S11].
