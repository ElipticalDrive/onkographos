# SDF Primitives & Operations

Also called: Basic Shapes, Boolean operations on implicit surfaces, CSG Intersection, Implicit Function CSG, SDF Operations, Subtraction, Union

## Overview
SDF Primitives & Operations define the fundamental geometric building blocks and Boolean compositing rules for Signed Distance Fields (SDFs) [S3, S4, unofficial]. This method solves the problem of representing complex 3D geometry as a single continuous scalar field by combining simple analytic shapes (primitives) using arithmetic operators [S4, unofficial]. It is distinguished from mesh-based rendering by replacing explicit topology with implicit distance evaluations, allowing complex scenes to be constructed via simple arithmetic on scalar values [S4, unofficial]. Unlike sibling [SDF Transformation](1086-sdf-transformation.md) which modifies the input coordinate space, this method operates on the output distance values to define the final surface [G].

## How it works

### Inputs and Outputs
**Inputs:**
- Point $\mathbf{p}$ in 3D space [S3, unofficial].
- Primitive parameters (e.g., radius $r$, box half-extents $\mathbf{b}$, plane normal $\mathbf{n}$) [S3, unofficial].
- For composite operations: two or more SDF functions $f_A, f_B$ and their respective parameters [S4, unofficial].

**Outputs:**
- A scalar float representing the signed distance from $\mathbf{p}$ to the nearest surface [S3, unofficial].
- Positive values indicate outside, zero on the surface, negative inside [S3, unofficial].

### Data Structures
No complex data structures are required for basic primitives [G]. The state is defined by the function parameters [G]. For CSG operations, the scene graph is typically a tree of function pointers or lambda expressions evaluating child SDFs [G].

### Numbered Steps
1. Evaluate the primitive SDF $f(\mathbf{p})$ for the current raymarch point $\mathbf{p}$ using the appropriate analytic formula [S3, unofficial].
2. If compositing, evaluate child SDFs $f_A(\mathbf{p})$ and $f_B(\mathbf{p})$ [S4, unofficial].
3. Apply the Boolean operator (min for union, max for intersection, max with negation for subtraction) to combine the scalar outputs [S1, unofficial].
4. Return the resulting scalar distance value [S3, unofficial].
5. Compute the surface normal via central finite differences if lighting is required [S1, unofficial].

### Formulas
All vectors are 3D. $|\cdot|$ denotes component-wise absolute value, $\|\cdot\|$ denotes Euclidean length, and $\max/\min$ denote component-wise or scalar maximum/minimum as context dictates.

1. **Sphere**: Centered at origin, radius $r$ [S3, unofficial].
   $$f_{sphere}(\mathbf{p}) = \|\mathbf{p}\| - r$$
2. **Box**: Axis-aligned, centered at origin, half-extents $\mathbf{b} = (b_x, b_y, b_z)$ where $b_i > 0$ [S3, unofficial].
   $$q = |\mathbf{p}| - \mathbf{b}$$
   $$q_{max} = \max(q, 0)$$
   $$f_{box}(\mathbf{p}) = \|q_{max}\| + \min(\max(q_x, \max(q_y, q_z)), 0)$$
3. **Round Box**: Box with rounded edges of radius $r_{round}$ [S3, unofficial].
   $$f_{roundbox}(\mathbf{p}) = f_{box}(\mathbf{p}) - r_{round}$$
4. **Cylinder**: Axis-aligned along Y, height $h$, radius $r$ [S3, unofficial].
   $$d = \sqrt{p_x^2 + p_z^2} - r$$
   $$h_{half} = h / 2$$
   $$f_{cyl}(\mathbf{p}) = \max(\max(d, |p_y| - h_{half}), 0)$$
5. **Round Cylinder**: Cylinder with rounded edges [S3, unofficial].
   $$f_{roundcyl}(\mathbf{p}) = f_{cyl}(\mathbf{p}) - r_{round}$$
6. **Plane**: Defined by unit normal $\mathbf{n}$ and distance $h$ from origin along $\mathbf{n}$ [S4, unofficial].
   $$f_{plane}(\mathbf{p}) = \mathbf{p} \cdot \mathbf{n} - h$$
7. **Torus**: Centered at origin, major radius $R$, minor radius $r$ [S3, unofficial].
   $$q = \sqrt{p_x^2 + p_z^2} - R$$
   $$f_{torus}(\mathbf{p}) = \sqrt{q^2 + p_y^2} - r$$
8. **Ellipsoid**: Axis-aligned, radii $\mathbf{r} = (r_x, r_y, r_z)$ [S3, unofficial].
   $$\mathbf{p}' = \mathbf{p} / \mathbf{r}$$
   $$f_{ellipsoid}(\mathbf{p}) = \|\mathbf{p}'\| - 1$$
9. **Cone**: Parametrized by position $\mathbf{p}$, surface normal $\mathbf{c}$, and height $h$ [S3, unofficial]. Exact formula not provided in sources [G].
10. **Pyramid**: Parametrized by position $\mathbf{p}$ and height $h$ [S3, unofficial]. Exact formula not provided in sources [G].
11. **Link**: Produces one half of a chain-link structure [S3, unofficial]. Parametrized by position $\mathbf{p}$, major/minor radii, and link length. Exact formula not provided in sources [G].
12. **Elongated Torus**: Variant of Torus extended in x, y, z directions [S3, unofficial]. Exact formula not provided in sources [G].

**CSG Operations** combine SDFs $f_A$ and $f_B$ to create new surfaces [S1, S4, unofficial]:
1. **Union (A $\cup$ B)**: The surface is the boundary of the combined volume [S4, unofficial].
   $$f_{union}(\mathbf{p}) = \min(f_A(\mathbf{p}), f_B(\mathbf{p}))$$
2. **Intersection (A $\cap$ B)**: The surface is the boundary of the overlapping volume [S4, unofficial].
   $$f_{intersect}(\mathbf{p}) = \max(f_A(\mathbf{p}), f_B(\mathbf{p}))$$
3. **Subtraction (A \ B)**: The surface is A minus B [S4, unofficial].
   $$f_{sub}(\mathbf{p}) = \max(f_A(\mathbf{p}), -f_B(\mathbf{p}))$$

### Parameters
- **Epsilon**: For normal calculation, a small value [S1, unofficial].
- **Radius/Size**: Primitive-specific [S3, unofficial].
- **Amplitude (A)**: Maximal amplitude of the fractal function for solid noise primitives [S6, unofficial].

### Edge Cases and Pitfalls
- **Precision**: Near the surface ($f(\mathbf{p}) \approx 0$), floating-point errors can cause jitter in ray marching steps [G].
- **Subtraction Artifacts**: Subtracting a large object from a small one can result in inverted normals if not handled correctly by the CSG logic [G].
- **Smooth Union**: Not covered in basic operations, but standard min/max creates sharp edges [S3, unofficial].
- **Fractal Density Bounds**: Due to the fractal function, density may be positive outside the sphere's radius [S6, unofficial]. The function has non-negative values at most $A$ units away from the radius, requiring bounds padding [S6, unofficial].

### Pseudocode
```python
import math

def length(v):
    return math.sqrt(v[0]**2 + v[1]**2 + v[2]**2)

def abs_vec(v):
    return [abs(v[0]), abs(v[1]), abs(v[2])]

def max_vec(a, b):
    return [max(a[0], b[0]), max(a[1], b[1]), max(a[2], b[2])]

def sphere(p, r):
    return length(p) - r

def box(p, b):
    q = abs_vec(p) - b
    q_max = max_vec(q, [0, 0, 0])
    return length(q_max) + min(max(q[0], max(q[1], q[2])), 0)

def plane(p, n, h):
    return sum(p[i] * n[i] for i in range(3)) - h

def union(a_func, a_params, b_func, b_params, p):
    return min(a_func(p, a_params), b_func(p, b_params))

def intersection(a_func, a_params, b_func, b_params, p):
    return max(a_func(p, a_params), b_func(p, b_params))

def subtraction(a_func, a_params, b_func, b_params, p):
    return max(a_func(p, a_params), -b_func(p, b_params))

def normal_at(func, params, p, eps=1e-4):
    dx = func([p[0]+eps, p[1], p[2]], params) - func([p[0]-eps, p[1], p[2]], params)
    dy = func([p[0], p[1]+eps, p[2]], params) - func([p[0], p[1]-eps, p[2]], params)
    dz = func([p[0], p[1], p[2]+eps], params) - func([p[0], p[1], p[2]-eps], params)
    vec = [dx, dy, dz]
    l = length(vec)
    if l == 0: return [0, 1, 0]
    return [vec[0]/l, vec[1]/l, vec[2]/l]
```

## Subtopics

### [Signed Box Distance Function](1092-signed-box-distance-function.md)
Computes the distance to an axis-aligned box using component-wise absolute value and max/min operators. It is computationally efficient due to the absence of square roots in intermediate steps, making it ideal for tight bounding volume hierarchies [1092-signed-box-distance-function.md].

### [Sphere Signed Distance Function](1237-sphere-signed-distance-function.md)
Returns the distance from a point to a sphere surface centered at the origin. It is the simplest analytic primitive and serves as a foundational building block for ellipsoids and windowed noise primitives [1237-sphere-signed-distance-function.md].

### [CSG Operations on Implicit Functions](1329-csg-operations-on-implicit-functions.md)
Composites multiple primitive shapes into a single implicit surface by applying Boolean logic to their distance fields. It reduces geometric composition to arithmetic operations on scalar values, enabling normals and shadows derived from the resulting field's gradient. It is chosen when complex, multi-part geometry is required without explicit mesh topology [1329-csg-operations-on-implicit-functions.md].

### [SDF Domain Manipulation Operators](1730-sdf-domain-manipulation-operators.md)
Modifies the input position vector to create periodic, mirrored, or reflected spatial structures. They partition space into cells and are chosen when infinite repeating patterns (grids, tiles) are needed without increasing geometric complexity [1730-sdf-domain-manipulation-operators.md].

### [SDF Primitives](1731-sdf-primitives.md)
Provides atomic Signed Distance Functions for common geometric shapes like Sphere, Box, and Torus. These are chosen as the base layer for all procedural SDF scene construction [1731-sdf-primitives.md].

### [SDF Rounding](1829-sdf-rounding.md)
Rounds an SDF by subtracting a constant distance value from the result. It is chosen to uniformly thicken or thin surfaces, create rounded edges on boxes, or adjust collision boundaries [1829-sdf-rounding.md].

### [Plane Signed Distance Function](1102-plane-signed-distance-function.md)
Defines a plane using a unit normal and height parameter. It is chosen for infinite planar surfaces, ground planes, or clipping boundaries in ray marching [1102-plane-signed-distance-function.md].

### Boolean Subtraction with Domain Repetition
Creates complex geometry by subtracting domain-repeated smaller objects from a non-repeated larger object. It is chosen to generate perforated or lattice-like structures efficiently [S5, unofficial].

### Solid Noise Primitive
Windows a fractal noise function within a sphere's radius to create volumetric density. It is chosen for procedural organic or gaseous volumes, requiring bounds padding due to fractal amplitude [S6, unofficial].

## Operating characteristics

**Time Complexity**: $O(1)$ per primitive evaluation [G]. CSG operations add a constant factor proportional to the number of children in the scene graph [G].
**Memory Complexity**: $O(1)$ for primitives [G]. Scene graph size depends on the number of primitives [G].
**Measured Performance**: Highly efficient on GPUs due to lack of branching and simple arithmetic [G]. Performance scales linearly with the depth of the CSG tree [G].
**Strengths**:
- Infinite resolution (analytic) [G].
- Easy to implement and debug [G].
- Compact memory footprint [G].
- Natural support for smooth blending and morphing [S3, unofficial].
**Limitations**:
- Cannot represent arbitrary topology (e.g., self-intersections in complex ways without CSG) [G].
- Normals are approximate if computed via finite differences [G].
**When to use**: Ideal for real-time rendering of stylized, geometric, or procedural scenes [G].
**When not to use**: When photorealistic detail from scanned meshes is required, or when the geometry is too complex for efficient CSG evaluation [G].

## Background
The concept of Signed Distance Fields for rendering was popularized by Inigo Quilez in his blog posts and books on ray marching [S1, S3, unofficial]. The mathematical foundations of CSG with distance fields were established by Hart [S4, unofficial]. The technique has become a staple in real-time graphics for creating procedural geometry, VFX, and stylized rendering [G].
