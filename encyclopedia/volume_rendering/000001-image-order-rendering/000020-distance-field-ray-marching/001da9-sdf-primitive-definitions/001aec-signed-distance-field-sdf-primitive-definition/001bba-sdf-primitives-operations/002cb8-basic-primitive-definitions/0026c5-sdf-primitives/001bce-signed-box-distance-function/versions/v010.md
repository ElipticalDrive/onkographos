# Signed Box Distance Function

Also called: Box SDF, Box SDF v2, Rectangular (Axis-Aligned Box) SDF, SDF Box, SDF Cube, Signed Box, sdBox

## Overview
The Signed Box Distance Function computes the exact Euclidean signed distance from a query point to the surface of an axis-aligned box [S5, S9, S11, unofficial]. It distinguishes interior from exterior space by returning negative values inside the box and positive values outside [S9, unofficial]. Unlike the naive intersection of six half-spaces, which only returns the distance to the nearest face or edge, this method provides the true Euclidean distance to corners and edges, ensuring correct step sizes in sphere tracing and accurate ambient occlusion [S14, S12, S13, unofficial].

## How it works
**Inputs and Outputs:**
- Input: `p`, a 3D point in space (vector).
- Input: `b`, the half-extents of the box (vector), defining the box as centered at the origin with dimensions $2b_x \times 2b_y \times 2b_z$ [S12, S11, unofficial]. If the box is not centered at the origin, `p` is transformed to local coordinates: $p_{local} = p - c$, where $c$ is the center [S6, S7, S8, unofficial].
- Output: A scalar float representing the signed distance.

**Data Structures:**
- `p`: `vec3` (x, y, z).
- `b`: `vec3` (x, y, z).
- `c`: `vec3` (x, y, z), optional center offset.

**Algorithm:**
The method exploits symmetry by taking the absolute value of the point coordinates, effectively folding the space into the first octant [S2, S9, unofficial]. It then calculates the distance to the box boundaries in this folded space [S9, S11, unofficial].

1. **Local Coordinate Transformation:** If the box has a center $c$, compute $p' = p - c$. Otherwise, $p' = p$ [S6, S7, unofficial].
2. **Symmetry Folding:** Compute $q = |p'| - b$. This vector $q$ represents the difference between the absolute point coordinates and the half-extents [S9, S11, S12, unofficial].
3. **Inside Distance:** Compute the maximum component of $q$: $c_{in} = \max(q_x, \max(q_y, q_z))$. This value is negative if the point is strictly inside the box [S9, S11, S12, unofficial].
4. **Outside Distance:** Compute the Euclidean length of the positive components of $q$: $d_{out} = \| \max(q, 0) \|$ [S10, S11, unofficial]. This handles points outside the box, correctly calculating distance to faces, edges, or corners [S9, S11, S12, unofficial].
5. **Combine:** The final signed distance is $d = \min(c_{in}, 0) + d_{out}$ [S9, S11, unofficial].

**Pseudocode:**
```python
def signed_box_distance(p: Vec3, b: Vec3, c: Vec3 = None) -> float:
    # 1. Transform to local coordinates if center is provided
    if c is not None:
        p_local = Vec3(p.x - c.x, p.y - c.y, p.z - c.z)
    else:
        p_local = p
        
    # 2. Symmetry folding: absolute value minus half-extents
    q = Vec3(abs(p_local.x) - b.x, abs(p_local.y) - b.y, abs(p_local.z) - b.z)
    
    # 3. Calculate inside distance (max component, clamped to 0 from above)
    inside_dist = min(max(q.x, max(q.y, q.z)), 0.0)
    
    # 4. Calculate outside distance (L2 norm of positive components)
    outside_dist = sqrt(max(q.x, 0.0)**2 + max(q.y, 0.0)**2 + max(q.z, 0.0)**2)
    
    # 5. Combine
    return inside_dist + outside_dist
```

**Parameters:**
- `b` (half-extents): Typical values depend on scene scale. For a unit box centered at origin, $b = (0.5, 0.5, 0.5)$ [S11, S12, unofficial].
- `c` (center): Not given in the sources as having a default, but typically $(0, 0, 0)$ when omitted [G].

**Edge Cases and Pitfalls:**
- **Underestimation (Version 1):** An earlier approximation used $d = \min(c_{in}, \| \max(q, 0) \|)$ [S12, S13, unofficial]. This underestimates the distance in corner regions, leading to smaller ray steps, slower convergence, and incorrect ambient occlusion (aliasing/black dots) [S12, S13, unofficial]. The correct formula uses the sum of the clamped inside distance and the outside distance [S9, S11, unofficial].
- **Overestimation:** Overestimating distance can cause the ray to pass through the surface or inaccurately estimate the surface point, negatively impacting ambient occlusion [S12, unofficial].
- **Cheap Approximation:** A cheaper, less precise approximation uses $d = \max(|p-c| - s)$ where $s$ is the full side length [S14, unofficial]. This is not a true Euclidean distance for points outside corners and should only be used if performance is critical and visual artifacts are acceptable [S14, unofficial].

## Subtopics

### [Unsigned Box Distance Function](3750-unsigned-box-distance-function.md)
The Unsigned Box Distance Function computes the Euclidean distance from a query point to the surface of an axis-aligned box centered at the origin, returning only non-negative values regardless of whether the point lies inside or outside the volume. Unlike its sibling, the Signed Box Distance Function, which distinguishes interior from exterior space, this method treats the box as a solid boundary where internal points are measured by their distance to the nearest face.

### [Box with Edge Rounding SDF](4004-box-with-edge-rounding-sdf.md)
Computes the signed distance to an axis-aligned box with rounded edges and corners, defined by half-extents $b$ and edge radius $e$. It extends the basic box distance by replacing sharp corners with spherical fillets, allowing for smooth geometric transitions in ray marching. It differs from the [Unsigned Box Distance Function](3750-unsigned-box-distance-function.md) by providing signed interior/exterior information and from the [Rectangle Signed Distance Function](4031-rectangle-signed-distance-function.md) by supporting 3D volumes with uniform edge rounding rather than planar rectangles [G].

### [Rectangle Signed Distance Function](4031-rectangle-signed-distance-function.md)
Computes the exact Euclidean distance from a query point to the boundary of an axis-aligned rectangle centered at the origin. It is the 2D analog of the [Signed Box Distance Function](1092-signed-box-distance-function.md).

### Oriented Box2D SDF
Computes the signed distance to a 2D box with custom orientation and thickness between points `a` and `b`, where `th` is the full thickness perpendicular to segment `[a, b]` [S11, unofficial]. If segment length `l <= 1e-6`, it returns the distance to a circle of radius `th * 0.5` centered at `a` [S11, unofficial]. Otherwise, it calculates direction `d = (b - a) / l`, center `q = p - (a + b) * 0.5`, rotates `q` into the local frame aligned with `d`, defines half-extents `h = (l * 0.5, th * 0.5)`, and returns `box2d(local, h)` [S11, unofficial].

## Operating characteristics
- **Time Complexity:** $O(1)$ per query. Involves a few vector subtractions, absolute values, max/min operations, and one square root (for the L2 norm) [S10, unofficial].
- **Memory Complexity:** $O(1)$. No auxiliary data structures required.
- **Performance:** Extremely fast, suitable for real-time ray marching. The square root is the most expensive operation, but it is only computed for the outside distance [S10, unofficial].
- **Strengths:** Exact Euclidean distance ensures correct sphere tracing steps and accurate ambient occlusion. Simple implementation.
- **Limitations:** Only applies to axis-aligned boxes. For oriented boxes, a transformation is required [S11, unofficial].
- **When to use:** When exact distance is required for sphere tracing, especially for ambient occlusion or collision detection [S12, S13, unofficial].
- **When not to use:** When performance is critical and approximate distance is acceptable (use the cheap approximation [S14, unofficial]). When the box is rotated (use oriented box variants or transform coordinates) [S11, unofficial].

## Background
The Signed Box Distance Function is a fundamental primitive in Signed Distance Field (SDF) rendering [S8, unofficial]. The exact formulation using the sum of inside and outside distances is widely attributed to Inigo Quilez [S9, S12, S13, unofficial]. Earlier approximations (Version 1) were found to cause artifacts in ambient occlusion [S12, S13, unofficial]. The function is a standard component in ray marching engines and implicit surface rendering [S2, S14, unofficial].
