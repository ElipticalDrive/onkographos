# Segment Signed Distance Function

Also called: Segment SDF, sdSegment, Distance to line segment

## Overview
The Segment Signed Distance Function computes the distance from a query point $p$ to the closest point on a line segment defined by endpoints $a$ and $b$ [S1, S3, S5, unofficial]. Source [S1, unofficial] returns the squared Euclidean distance, while sources [S3, S5, unofficial] return the standard Euclidean distance [S1, S3, S5, unofficial]. The method projects the query point onto the infinite line containing the segment and clamps the projection parameter to the segment bounds [S1, S3, unofficial].

## How it works
**Inputs:**
- $p$: The query point [S2, unofficial][S6]. Source [S2, unofficial] specifies `vec2` (2D space), while source [S6] specifies `Vec3T` (3D space).
- $a$: The first endpoint of the segment [S1, S3, unofficial].
- $b$: The second endpoint of the segment [S1, S3, unofficial].

**Outputs:**
- $d$: The distance value [S1, S3, unofficial]. Source [S1, unofficial] returns the squared distance $\|p - \text{closest}\|^2$, while sources [S3, S5, unofficial] return the Euclidean distance $\|p - \text{closest}\|$ [S1, S3, S5, unofficial].

**Data Structures:**
- Vectors $a, b, p$ are stored as standard floating-point arrays with 2 or 3 components [S2, unofficial][S6].
- Intermediate scalars $t$ (or $h, u$) store the normalized projection parameter [S1, S3, S4, unofficial].

**Steps:**
1. Compute the segment vector: $ab = b - a$ [S1, S3, unofficial].
2. Compute the vector from the start point to the query point: $ap = p - a$ [S1, S3, unofficial].
3. Compute the squared length of the segment: $len\_sq = ab \cdot ab$ [S1, S3, unofficial]. Source [S3, unofficial] denotes this as `ba.length_squared()`.
4. Handle degenerate segments (zero length):
   - If $len\_sq < \epsilon$ (where $\epsilon$ is $10^{-12}$ [S3, unofficial] or $10^{-8}$ [S4, unofficial]), the segment is a point. Return $\|p - a\|$ [S3, S4, unofficial].
5. Compute the projection parameter $t$:
   - Calculate the dot product: $dot = ap \cdot ab$ [S1, S3, unofficial].
   - Normalize by squared length: $t = dot / len\_sq$ [S1, S3, unofficial].
   - Clamp $t$ to the range $[0, 1]$ to restrict the closest point to the segment: $t = \text{clamp}(t, 0.0, 1.0)$ [S1, S3, unofficial].
6. Compute the closest point on the segment: $closest = a + ab \cdot t$ [S1, S3, unofficial].
7. Return the distance: $d = \|p - closest\|$ [S3, S5, unofficial]. Source [S1, unofficial] returns $(p - closest) \cdot (p - closest)$ instead [S1, unofficial].

**Pseudocode:**
```python
def sdSegment(p, a, b):
    """
    Computes the Euclidean distance from point p to the segment [a, b].
    p, a, b are vectors of the same dimension (2D or 3D).
    """
    # 1. Vector from a to b
    ab = b - a
    
    # 2. Vector from a to p
    ap = p - a
    
    # 3. Squared length of the segment
    len_sq = dot(ab, ab)
    
    # 4. Handle degenerate segment (point)
    epsilon = 1e-12
    if len_sq < epsilon:
        return length(ap)
    
    # 5. Project p onto the line, clamped to [0, 1]
    t = dot(ap, ab) / len_sq
    t = clamp(t, 0.0, 1.0)
    
    # 6. Find the closest point on the segment
    closest = a + ab * t
    
    # 7. Return the Euclidean distance
    return length(p - closest)
```
Note: Source [S1, unofficial] returns the squared distance by replacing the final `length(p - closest)` with `dot(p - closest, p - closest)`.

**Parameters:**
- $\epsilon$: Epsilon for degenerate check. Common values are $10^{-12}$ [S3, unofficial] or $10^{-8}$ [S4, unofficial].
- $p, a, b$: Coordinates in the same space (2D or 3D) [S2, unofficial][S6].

**Edge Cases and Pitfalls:**
- **Degenerate Segments:** If $a = b$, the denominator $len\_sq$ becomes zero [S3, S4, unofficial]. Explicitly checking $len\_sq < \epsilon$ prevents division by zero [S3, S4, unofficial].
- **Precision:** When $p$ is very close to the segment, floating-point errors in the dot product and division can cause slight inaccuracies [G]. Using `clamp` ensures the result remains physically valid (distance $\ge 0$) [S1, S3, unofficial].
- **Dimensionality:** The algorithm works for any dimension $N$ as long as vector arithmetic is supported [S6].

## Subtopics

### Line Segment Distance
Computes the Euclidean distance from a point $p$ to a line segment defined by endpoints $l_0$ and $l_1$ [S5, unofficial]. This variant explicitly details the branch logic for determining which endpoint is closer when the projection falls outside the segment, rather than relying on a generic clamp function [S5, unofficial]. It computes $v = l_1 - l_0$ and $w = p - l_0$, then checks if $c_1 = \text{dot}(v, w) \le 0.0$ to return $\|p - l_0\|$, or if $c_2 = \text{dot}(v, v) \le c_1$ to return $\|p - l_1\|$, otherwise computing $b = c_1 / c_2$ and returning $\|p - (l_0 + b \cdot v)\|$ [S5, unofficial]. Choose this when you need explicit control over the "closer to start" vs "closer to end" conditions [S5, unofficial].

### Point on Segment Check
Checks if a point $Q$ lies on the line segment between $P_i$ and $P_j$ using distance comparison with an epsilon tolerance [S4, unofficial]. It calculates distances $dis1$ ($P_i$ to $Q$), $dis2$ ($P_j$ to $Q$), and $dis3$ ($P_i$ to $P_j$) [S4, unofficial]. If $dis3 + \epsilon < dis1 + dis2$, it returns false; otherwise true [S4, unofficial]. This is a geometric predicate rather than a distance function, used for validation or collision detection [S4, unofficial]. Choose this when you need to verify collinearity and bounds rather than compute a distance value [S4, unofficial].

### Point-to-Segment Distance
Computes the closest point on a line segment $[v_0, v_1]$ to a query point $p$ [S6]. The result is guaranteed to lie on the closed segment by clamping the parameter $t$ to $[0, 1]$ [S6]. This is a helper function often used in conjunction with the SDF to retrieve the geometric closest point for shading or normal calculation [S6]. Choose this when the closest point location is needed, not just the distance [S6].

## Operating characteristics
- **Time Complexity:** $O(1)$ constant time [G]. It involves a fixed number of vector subtractions, dot products, and a square root.
- **Memory Complexity:** $O(1)$ auxiliary space [G]. No large data structures are required.
- **Performance:** Extremely fast, suitable for real-time ray marching in fragment shaders or CPU-based path tracing [S2, S4, unofficial].
- **Strengths:** Simple implementation, numerically stable with proper epsilon handling, works in any dimension [S3, unofficial][S6].
- **Limitations:** Does not handle infinite lines or thick segments [S5, unofficial].
- **When to use:** For rendering thin wires, edges, or skeletal structures in SDF scenes [S2, unofficial].
- **When not to use:** For infinite lines or when the segment thickness is significant [S5, unofficial].

## Background
The Segment SDF is a standard primitive in the field of Signed Distance Fields [S3, unofficial]. It is widely used in ray marching techniques for rendering complex geometries composed of simple primitives [S2, unofficial]. The mathematical formulation relies on projecting a point onto a line segment and clamping the parameter to the segment's bounds [S1, S3, unofficial].
