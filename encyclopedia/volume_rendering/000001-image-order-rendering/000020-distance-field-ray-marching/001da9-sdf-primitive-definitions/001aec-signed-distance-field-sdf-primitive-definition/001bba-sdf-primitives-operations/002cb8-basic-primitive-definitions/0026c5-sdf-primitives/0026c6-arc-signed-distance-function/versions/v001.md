# Arc Signed Distance Function

Also called: SDF Arc, sdArc

## Overview
The Arc Signed Distance Function computes the exact Euclidean distance from a query point to a 3D arc shape, defined as a tube of constant radius running along a circular path. It solves the problem of ray marching against curved, non-closed tubular primitives that cannot be represented by simple spheres or boxes. It is distinguished from the [Capsule Signed Distance Function](2439-capsule-signed-distance-function.md) by its curved, circular trajectory rather than a linear segment, and from the [Torus](1731-sdf-primitives.md) by its limited angular aperture.

## How it works
**Inputs:**
*   `p`: Query point in 3D space (`vec3`).
*   `depth`: A global Z-coordinate value used to define the plane of the arc [S1, unofficial].
*   `arc_center`: Center of the arc's circular path (`vec3`) [S1, unofficial].
*   `orientation_angle`: Angle of the arc's starting position in degrees [S1, unofficial].
*   `apature_angle`: Total angular width of the arc in degrees [S1, unofficial].
*   `ra`: Radius of the circular path defining the arc [S1, unofficial].
*   `rb`: Radius of an inner circle, used for complex shapes (e.g., toroidal cuts) [S1, unofficial].
*   `arc_tube_radius`: Radius of the tube surrounding the arc path [S1, unofficial].

**Data Structures:**
The implementation typically precomputes trigonometric values to avoid runtime calls. The `Arc` struct layout is:
*   `vec3 arc_center`
*   `float arc_tube_radius`
*   `float orientation_angle`
*   `float apature_angle`
*   `float sca_cos` (cosine of orientation angle)
*   `float sca_sin` (sine of orientation angle)
*   `float scb_cos` (cosine of half aperture angle)
*   `float scb_sin` (sine of half aperture angle)
*   `float ra`
*   `float rb`

**Steps:**
1.  **Construct Position:** Create a 3D position vector from the query point `p`, replacing its Z-component with the global `depth`.
    $$ \text{pos} = (p.x, p.y, \text{depth}) $$
2.  **Translate:** Shift the position relative to the arc center.
    $$ \text{pos} = \text{pos} - \text{arc\_center} $$
3.  **Rotate:** Rotate the position into the arc's local coordinate system using the precomputed sine and cosine of the orientation angle.
    $$ x = \text{pos}.x \cdot \text{sca\_cos} - \text{pos}.y \cdot \text{sca\_sin} $$
    $$ y = \text{pos}.x \cdot \text{sca\_sin} + \text{pos}.y \cdot \text{sca\_cos} $$
    $$ \text{pos}.x = x, \quad \text{pos}.y = y $$
4.  **Symmetry:** Take the absolute value of the X component to exploit symmetry across the arc's central axis.
    $$ \text{pos}.x = |\text{pos}.x| $$
5.  **Project Distance:** Compute the distance to the infinite circular ring defined by radii `ra` and `rb`. This involves comparing the rotated coordinates against the half-aperture bounds.
    $$ k = \begin{cases} \text{pos}.x \cdot \text{scb\_sin} + \text{pos}.y \cdot \text{scb\_cos} & \text{if } \text{scb\_cos} \cdot \text{pos}.x > \text{scb\_sin} \cdot \text{pos}.y \\ \sqrt{\text{pos}.x^2 + \text{pos}.y^2} & \text{otherwise} \end{cases} $$
    $$ \text{project\_distance} = \sqrt{\text{pos} \cdot \text{pos} + ra^2 - 2 \cdot ra \cdot k} - rb $$
    *Note: The source uses `sqrt14` which is an approximation of square root [S1, unofficial].*
6.  **Final Distance:** Combine the project distance with the Z-axis deviation (from `depth`) and subtract the tube radius.
    $$ \text{distance} = \sqrt{\text{project\_distance}^2 + p.z^2} - \text{arc\_tube\_radius} $$

**Pseudocode:**
```python
def sd_arc(p: Vec3, depth: float, arc: Arc) -> float:
    # 1. Construct position vector using global depth
    pos = Vec3(p.x, p.y, depth)
    
    # 2. Translate by arc center
    pos = pos - arc.arc_center
    
    # 3. Rotate by orientation angle
    x = pos.x * arc.sca_cos - pos.y * arc.sca_sin
    y = pos.x * arc.sca_sin + pos.y * arc.sca_cos
    pos.x = x
    pos.y = y
    
    # 4. Take absolute value of x
    pos.x = abs(pos.x)
    
    # 5. Compute intermediate value k
    # Check if point is within the angular aperture bounds
    if arc.scb_cos * pos.x > arc.scb_sin * pos.y:
        k = pos.x * arc.scb_sin + pos.y * arc.scb_cos
    else:
        k = length(pos.x, pos.y)
        
    # 6. Compute project distance to the ring
    # Using standard sqrt for clarity; source uses FT::sqrt approximation
    project_distance = sqrt(dot(pos, pos) + arc.ra * arc.ra - 2.0 * arc.ra * k) - arc.rb
    
    # 7. Compute final distance including Z deviation
    return sqrt(project_distance * project_distance + p.z * p.z) - arc.arc_tube_radius
```

**Parameters:**
*   `ra`: Radius of the circle defining the arc path. Typical value varies by instance (e.g., 1.75) [S1, unofficial].
*   `rb`: Radius of an inner circle. Default is 0.0 [S1, unofficial].
*   `arc_tube_radius`: Radius of the tube running along the arc [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Angle Conversion:** The constructor must convert `orientation_angle` and `apature_angle` from degrees to radians by multiplying by $\pi/180.0$ [S1, unofficial].
*   **Precision:** The source code utilizes a fast square root approximation (`FT::sqrt`) which may introduce minor precision errors compared to standard `sqrt` [S1, unofficial].
*   **Aperture Logic:** The conditional check for `k` determines if the point lies within the angular span of the arc. If outside, the distance is calculated to the nearest endpoint of the arc segment.

## Operating characteristics
*   **Time Complexity:** $O(1)$ per query. It involves a fixed number of arithmetic operations and one square root.
*   **Memory Complexity:** $O(1)$ for the primitive parameters.
*   **Strengths:** Provides exact distance for curved tubular shapes, enabling efficient ray marching without voxelization.
*   **Limitations:** Limited to a single circular arc segment. Does not support arbitrary 3D curves.
*   **When to use:** When rendering curved pipes, handles, or decorative arcs where a torus is too complex or a capsule is too linear.

## Background
The Arc SDF is derived from implementations found in real-time ray marching demos and GitHub repositories focusing on SDF primitives [S1, unofficial]. It extends the basic SDF primitives (Sphere, Box) to include curved linear features. The specific implementation details, including the fast trigonometric approximations and SSE optimizations referenced in the source comments, originate from fast C++ math libraries often used in graphics programming [S1, unofficial].
