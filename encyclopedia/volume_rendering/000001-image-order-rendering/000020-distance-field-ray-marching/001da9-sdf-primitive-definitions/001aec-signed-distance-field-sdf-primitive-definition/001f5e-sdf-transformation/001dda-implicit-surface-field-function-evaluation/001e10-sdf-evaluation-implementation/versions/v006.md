# SDF Evaluation Implementation

Also called: SDF Evaluation and Gradient, SDF Handler Implementation, SDF Query Handler, SDF Value and Gradient Evaluation

## Overview
This method implements the runtime evaluation of a Signed Distance Field (SDF) defined on a 3D voxel grid, providing both the scalar distance value and its spatial gradient (normal) at arbitrary query points [S2, unofficial]. It solves the problem of efficiently querying implicit geometry for ray marching or differentiable rendering pipelines by supporting configurable interpolation orders [S1, unofficial][S2, unofficial]. It differs from [Batched SDF Inference](2329-batched-sdf-inference.md) by operating on single arbitrary points rather than fixed batches, and from [DeepSDF Neural Network](3051-deepsdf-neural-network.md) by using explicit grid-based storage rather than neural network inference [S2, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A 3D voxel grid representing the SDF, typically stored in `.sdf`, `.npy`, or `.vol` formats [S2, unofficial]. The grid is defined by a resolution $R \times R \times R$ and contains scalar distance values [S2, unofficial]. A query point $p = (x, y, z)$ in 3D space [G].
*   **Output:** The signed distance value $d = f(p)$ and the gradient vector $\nabla f(p) = (\frac{\partial d}{\partial x}, \frac{\partial d}{\partial y}, \frac{\partial d}{\partial z})$ [S2, unofficial].

**Data Structures:**
*   **SDF Grid:** A 3D array of floating-point values. In implementation [S2, unofficial], this is wrapped in a texture object (e.g., `mi.Texture3f`) with acceleration disabled (`use_accel=False`) to allow direct coordinate-based sampling. The shape is $(R, R, R, 1)$ [S2, unofficial].
*   **Configuration:** A string parameter `SDF_MODE` determining the interpolation method: `'linear'` or `'cubic'` [S2, unofficial].
*   **Parameters:**
    *   `epsilon` ($\epsilon$): The step size for finite difference gradient computation when in linear mode. Default value: $10^{-5}$ [S2, unofficial].

**Steps:**

1.  **Initialization and Validation:**
    *   Validate the SDF identifier/name using `is_valid_sdf_name(name)` [S1, unofficial]. If invalid, raise `std::runtime_error("unknown SDF '...'")` [S1, unofficial].
    *   Load raw grid data from `.sdf`, `.npy`, or `.vol` files [S2, unofficial].
    *   Parse the first element as resolution $R$ [S2, unofficial].
    *   Construct `mi.TensorXf` with shape $(R, R, R, 1)$ and wrap in `mi.Texture3f` with `use_accel=False` [S2, unofficial].

2.  **Value Evaluation $f(p)$:**
    *   Given query point $p$, determine interpolation mode via `SDF_MODE` [S2, unofficial].
    *   **If `'linear'`:** Evaluate using `self.grid.eval(p)[0]` [S2, unofficial].
    *   **If `'cubic'`:** Evaluate using `self.grid.eval_cubic(p)[0]` [S2, unofficial].

3.  **Gradient Evaluation $\nabla f(p)$:**
    *   **If `'linear'`:** Compute gradient using central finite differences with $\epsilon = 10^{-5}$ for dx, dy, dz components [S2, unofficial].
    *   **If `'cubic'`:** Use `self.grid.eval_cubic_grad(p)[1][0]` [S2, unofficial].

4.  **Normal and Directional Derivative:**
    *   To compute surface normal $n$ at point $q$, normalize the gradient [S2, unofficial].
    *   To compute directional derivative along direction $d$, calculate the dot product $\nabla f(q) \cdot d$ [S2, unofficial].

**Pseudocode:**

```python
import numpy as np

class SDFEvaluator:
    def __init__(self, grid_data, resolution, mode='linear', epsilon=1e-5):
        """
        Initialize SDF evaluator.
        
        Args:
            grid_data: 1D array of SDF values.
            resolution: Integer R, grid size is R x R x R.
            mode: 'linear' or 'cubic'.
            epsilon: Step size for finite differences.
        """
        self.resolution = resolution
        self.mode = mode
        self.epsilon = epsilon
        # Source [S2, unofficial] stores data as (res, res, res, 1) in texture,
        # but logical access is 3D. We reshape to (R, R, R).
        self.grid = grid_data.reshape(resolution, resolution, resolution)

    def _linear_interp(self, p):
        """
        Evaluate SDF value at point p using linear interpolation.
        p is assumed to be in grid coordinates [0, R-1].
        """
        x, y, z = p
        # Clamp to grid bounds [0, resolution-1]
        x = np.clip(x, 0, self.resolution - 1)
        y = np.clip(y, 0, self.resolution - 1)
        z = np.clip(z, 0, self.resolution - 1)

        ix, iy, iz = np.floor([x, y, z]).astype(int)
        fx, fy, fz = x - ix, y - iy, z - iz

        ix_next = np.clip(ix + 1, 0, self.resolution - 1)
        iy_next = np.clip(iy + 1, 0, self.resolution - 1)
        iz_next = np.clip(iz + 1, 0, self.resolution - 1)

        # Fetch 8 corners
        v000 = self.grid[ix, iy, iz]
        v100 = self.grid[ix_next, iy, iz]
        v010 = self.grid[ix, iy_next, iz]
        v110 = self.grid[ix_next, iy_next, iz]
        v001 = self.grid[ix, iy, iz_next]
        v101 = self.grid[ix_next, iy, iz_next]
        v011 = self.grid[ix, iy_next, iz_next]
        v111 = self.grid[ix_next, iy_next, iz_next]

        # Trilinear interpolation
        v00 = v000 * (1 - fx) + v100 * fx
        v01 = v010 * (1 - fx) + v110 * fx
        v10 = v001 * (1 - fx) + v101 * fx
        v11 = v011 * (1 - fx) + v111 * fx

        v0 = v00 * (1 - fy) + v01 * fy
        v1 = v10 * (1 - fy) + v11 * fy

        return v0 * (1 - fz) + v1 * fz

    def evaluate(self, p):
        """
        Evaluate SDF value and gradient at point p.
        
        Args:
            p: numpy array [x, y, z] in grid coordinates.
            
        Returns:
            d: float, signed distance.
            grad: numpy array [dx, dy, dz], gradient.
        """
        if self.mode == 'linear':
            d = self._linear_interp(p)
            # Central finite differences for gradient [S2, unofficial]
            p_xp = p + np.array([self.epsilon, 0, 0])
            p_xm = p - np.array([self.epsilon, 0, 0])
            p_yp = p + np.array([0, self.epsilon, 0])
            p_ym = p - np.array([0, self.epsilon, 0])
            p_zp = p + np.array([0, 0, self.epsilon])
            p_zm = p - np.array([0, 0, self.epsilon])

            dx = (self._linear_interp(p_xp) - self._linear_interp(p_xm)) / (2 * self.epsilon)
            dy = (self._linear_interp(p_yp) - self._linear_interp(p_ym)) / (2 * self.epsilon)
            dz = (self._linear_interp(p_zp) - self._linear_interp(p_zm)) / (2 * self.epsilon)
            grad = np.array([dx, dy, dz])
        elif self.mode == 'cubic':
            # Source [S2, unofficial] uses self.grid.eval_cubic(p)[0] and self.grid.eval_cubic_grad(p)[1][0].
            # Library bindings required for cubic kernel evaluation.
            d = self._linear_interp(p) # Fallback for standalone execution
            grad = np.zeros(3) # Fallback for standalone execution
        else:
            raise ValueError(f"Unknown SDF mode: {self.mode}")
        return d, grad

    def query_normal(self, q):
        """
        Compute the normalized normal vector at point q.
        """
        _, grad = self.evaluate(q)
        norm = np.linalg.norm(grad)
        if norm < 1e-8:
            return np.array([0.0, 0.0, 0.0])
        return grad / norm
```

**Edge Cases and Pitfalls:**
*   **Boundary Conditions:** Points outside grid bounds are clamped to `[0, R-1]` [G].
*   **Precision:** Finite differences in linear mode use $\epsilon = 10^{-5}$ [S2, unofficial].
*   **Cubic Performance:** Cubic interpolation provides smoother geometry and is theoretically more robust, but is significantly slower than linear interpolation [S2, unofficial].

## Operating characteristics
*   **Time Complexity:** Linear interpolation is $O(1)$ per query with a constant factor proportional to 8 neighbors and 6 finite difference evaluations [G]. Cubic interpolation is $O(1)$ per query with a higher constant factor due to the cubic kernel [G].
*   **Memory Complexity:** $O(R^3)$ for storing the SDF grid [G].
*   **Performance:** Linear interpolation is significantly faster than cubic interpolation [S2, unofficial]. Cubic interpolation provides smoother geometry and is theoretically more robust for gradient-based optimization [S2, unofficial].
*   **Strengths:** Supports arbitrary query points; provides analytical or high-accuracy numerical gradients; flexible interpolation modes [G].
*   **Limitations:** Memory usage scales cubically with resolution; cubic interpolation is slow; linear interpolation gradients are noisy due to finite differences [G].
*   **When to Use:** When explicit grid-based SDFs are required for differentiable rendering or ray marching, and the scene geometry fits within memory constraints [S1, unofficial][S2, unofficial].
*   **When Not to Use:** For very high-resolution scenes where memory is a bottleneck (consider [DeepSDF Neural Network](3051-deepsdf-neural-network.md) or [Augmented SDF](4725-augmented-sdf.md)); when real-time performance is critical and linear interpolation is insufficient (consider [Batched SDF Inference](2329-batched-sdf-inference.md) for throughput) [G].

## Background
The method originates from implementations of differentiable rendering with Signed Distance Fields, specifically as described in "A Simple Approach to Differentiable Rendering of SDFs" by Wang et al. (SIGGRAPH Asia 2024) [S2, unofficial]. It is also used in subgrid ray marching pipelines for efficient intersection queries [S1, unofficial]. The approach leverages standard voxel grid interpolation techniques adapted for gradient computation, enabling the use of SDFs in optimization-based rendering pipelines [S2, unofficial].
