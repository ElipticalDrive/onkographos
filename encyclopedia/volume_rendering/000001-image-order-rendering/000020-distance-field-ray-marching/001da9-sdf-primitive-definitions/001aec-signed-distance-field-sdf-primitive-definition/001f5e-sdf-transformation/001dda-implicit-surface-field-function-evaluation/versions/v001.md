# Implicit Surface Field Function Evaluation

Also called: Field Function Evaluation, Implicit Function Evaluation

## Overview
Implicit Surface Field Function Evaluation is the core computational step in ray marching and contouring algorithms that determines the spatial relationship of a query point to a volume defined by a scalar field $d = f(x,y,z)$ [S1, unofficial]. It solves the problem of mapping 3D coordinates to a signed distance (or density) value, where $d < 0$ indicates the interior, $d > 0$ the exterior, and $d = 0$ the surface contour [S1, unofficial]. It differs from [SDF Transformation](1086-sdf-transformation.md) in that it performs the actual arithmetic evaluation of the primitive's geometry, whereas the parent article describes the coordinate system adjustment required before this evaluation can occur.

## How it works
**Inputs and Outputs:**
*   **Input:** A query point $(x_0, y_0, z_0)$ in world space.
*   **Input:** A transformation matrix $T$ applied to the implicit surface.
*   **Input:** Primitive parameters (e.g., radius $R$ for a sphere).
*   **Output:** A scalar value $d$ representing the signed distance/density.

**Data Structures:**
*   **Transformation Matrix:** A $4 \times 4$ matrix (or $3 \times 3$ if translation is handled separately) representing the object's pose. The implementation must store the inverse transformation $T^{-1}$ or compute it at runtime [S1, unofficial].
*   **Primitive State:** Stored fields such as `_radius` for spheres [S1, unofficial].

**Steps:**
1.  **Inverse Transformation:** Transform the query point $(x_0, y_0, z_0)$ from world space into the implicit surface's local object space using the inverse of the surface's transformation matrix $T^{-1}$. Let the resulting local coordinates be $(x_t, y_t, z_t)$ [S1, unofficial].
    *   If no transformation is applied, $T$ is the identity matrix, so $(x_t, y_t, z_t) = (x_0, y_0, z_0)$ [S1, unofficial].
    *   Example: If a sphere is translated by $(-5, 0, 0)$, $T^{-1}$ translates the query point by $(+5, 0, 0)$ [S1, unofficial].
2.  **Distance Calculation:** Evaluate the analytic distance function $f$ using the local coordinates $(x_t, y_t, z_t)$ and primitive parameters [S1, unofficial].
3.  **Return Value:** Return the computed scalar $d$ [S1, unofficial].

**Formulas:**
For a sphere of radius $R$ centered at the origin in local space:
$$ f(x_t, y_t, z_t) = x_t^2 + y_t^2 + z_t^2 - R^2 $$
where:
*   $x_t, y_t, z_t$ are the transformed query coordinates [S1, unofficial].
*   $R$ is the radius of the sphere [S1, unofficial].
*   $d = 0$ if the point is on the contour (distance $R$ from center) [S1, unofficial].
*   $d > 0$ if the point is outside (distance $> R$) [S1, unofficial].
*   $d < 0$ if the point is inside (distance $< R$) [S1, unofficial].

**Pseudocode:**
The following Python-like pseudocode implements batch evaluation along the +z axis, as described in the source [S1, unofficial]. It assumes a `transform_inverse` function that applies $T^{-1}$ to a point.

```python
def evaluate_field(x0, y0, z0, dz, num_points, radius, transform_inverse):
    """
    Evaluates the implicit field function for a batch of points.
    
    Args:
        x0, y0, z0: Starting coordinates of the batch.
        dz: Step size along the +z axis for subsequent points.
        num_points: Number of points to evaluate.
        radius: Radius of the sphere primitive.
        transform_inverse: Function that transforms (x, y, z) by T^-1.
        
    Returns:
        A list of density values d.
    """
    densities = []
    current_z = z0
    
    for i in range(num_points):
        # Step 1: Transform query point to local object space
        xt, yt, zt = transform_inverse(x0, y0, current_z)
        
        # Step 2: Evaluate sphere field function
        # f(x,y,z) = x^2 + y^2 + z^2 - R^2
        sqr_dist = xt * xt + yt * yt + zt * zt
        sqr_rad = radius * radius
        d = sqr_dist - sqr_rad
        
        densities.append(d)
        
        # Advance to next point along +z axis
        current_z += dz
        
    return densities
```

**Parameters:**
*   `dz`: The delta step size along the +z axis for batch evaluation [S1, unofficial].
*   `num_points`: The number of points to evaluate in the batch [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Precision:** Floating-point errors may cause points exactly on the contour to return non-zero values. This is acceptable for ray marching but may affect marching cube grid generation [S1, unofficial].
*   **Bounding Box:** Determining the bounding box for the implicit surface is non-trivial and must be computed separately (e.g., in the constructor) to optimize culling [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(1)$ per point for analytic primitives (e.g., spheres, boxes). Batch evaluation reduces overhead per point.
*   **Memory Complexity:** $O(1)$ for analytic primitives, as no grid or texture storage is required.
*   **Strengths:** Compact representation; precise contours; no discretization artifacts inherent to voxel grids [S1, unofficial].
*   **Limitations:** Bounding box computation can be difficult for complex implicit functions [S1, unofficial].

## Background
The concept of implicit surfaces defined by field functions $d = f(x,y,z)$ is foundational in computer graphics for representing volumes. The specific implementation details and examples (such as the sphere function and batch evaluation interface) are derived from early tutorials on contouring algorithms like Marching Cubes and Dual Contouring [S1, unofficial].
