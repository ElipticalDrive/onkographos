# Spherical Harmonics Approximation

Also called: SH Approximation, Spherical Harmonics Basis Approximation

## Overview
Spherical Harmonics (SH) Approximation is a technique to represent a spherical function $f(\omega)$ as a linear combination of SH basis functions, enabling efficient and differentiable computation for inverse problems in volume rendering [S1]. It solves the problem of expensive, high-dimensional integration during ray casting by replacing Monte Carlo integration with algebraic operations on coefficient vectors [S1]. Unlike direct Monte Carlo integration, which is noisy and slow, SH approximation allows the integral of a product of functions to be computed as a dot product of their coefficients, leveraging the orthonormality of the basis [S1]. It sets itself apart from general SH Approximation by focusing specifically on the projection mechanics and the subsequent efficient integration of these projected coefficients in the context of direct volume ray casting [S1].

## How it works
**Inputs:** A spherical function $f(\omega)$ defined over the domain $\Omega$ (the unit sphere), and a maximum bandwidth $n$ (number of coefficients).
**Outputs:** A vector of SH coefficients $\mathbf{f} \in \mathbb{R}^n$.

**Data Structures:**
The coefficients are stored in a 1D vector $\mathbf{f}$ of size $n$. The index $i$ maps the degree $l$ and order $m$ to a linear index using the formula $i = l^2 + l + m$, where $l \in \{0, \dots, L\}$ and $m \in \{-l, \dots, l\}$. The total number of coefficients is $n = (L+1)^2$ [S1, Parent].

**Steps:**

1.  **Projection:** Compute the SH coefficients $\mathbf{f}$ by projecting the function $f(\omega)$ onto the basis functions $y_i(\omega)$ [S1]:
    $$
    f_i = \int_{\Omega} f(\omega) y_i(\omega) d\omega
    $$
    In the context of inverse problems, this integral is typically precomputed or solved numerically at initialization to ensure differentiability with respect to other parameters (like environment map coefficients) [S1].

2.  **Reconstruction:** Approximate the function $\tilde{f}(\omega)$ at any direction $\omega$ by summing the basis functions weighted by the coefficients [S1]:
    $$
    \tilde{f}(\omega) = \sum_{i=1}^{n} f_i y_i(\omega)
    $$
    The accuracy increases with the number of bands $n$ [S1].

3.  **Product Convolution:** To compute the SH projection of the product of two functions $\tilde{a}(\omega)$ and $\tilde{b}(\omega)$, use the precomputed transfer matrix $C_{ijk}$ [S1]:
    $$
    (a * b)_i = \sum_{j=1}^{n} \sum_{k=1}^{n} C_{ijk} a_j b_k
    $$
    where $C_{ijk} = \int_{\Omega} y_i(\omega) y_j(\omega) y_k(\omega) d\omega$ [S1].

4.  **Integral of Product:** The integral of the product of two approximated functions is computed as the dot product of their coefficient vectors [S1]:
    $$
    \int_{\Omega} \tilde{a}(\omega)\tilde{b}(\omega)d\omega = \mathbf{a} \cdot \mathbf{b}
    $$

**Parameters:**
*   **Bandwidth ($n$):** The number of coefficients. A bandwidth of $n=8$ is chosen in the source for good low-frequency approximations [S1]. Note that $n$ corresponds to $(L+1)^2$, so $n=8$ implies $L \approx 1.8$, which is non-integer; the source likely refers to a specific truncation or a typo for $n=9$ ($L=2$) or $n=16$ ($L=3$). However, the text explicitly states "bandwidth of n = 8" [S1].

**Pseudocode:**

```python
import numpy as np

def compute_sh_coefficients(f_func, basis_functions, n):
    """
    Projects a spherical function f(omega) onto SH basis functions.
    
    Args:
        f_func: Callable f(omega) returning the function value at direction omega.
        basis_functions: Array of shape (n, num_samples, 3) containing basis values y_i(omega) for n coefficients.
        n: Number of SH coefficients.
        
    Returns:
        f_coeffs: Array of shape (n,) containing the SH coefficients.
    """
    # In practice, this integral is often precomputed or solved via numerical integration
    # at initialization for inverse problems [S1].
    # Here we assume a discrete approximation via Monte Carlo or quadrature.
    
    # Example: Simple Monte Carlo integration
    num_samples = 10000
    omegas = sample_sphere_uniform(num_samples) # Returns (num_samples, 3)
    
    # Evaluate function at sample points
    f_values = np.array([f_func(omega) for omega in omegas]) # Shape (num_samples,)
    
    # Evaluate basis functions at sample points
    # basis_values shape: (num_samples, n)
    basis_values = np.array([basis_functions[i](omega) for i in range(n) for omega in omegas]).reshape(num_samples, n)
    
    # Compute coefficients: f_i = integral(f(omega) * y_i(omega))
    # Approximated as mean(f * y_i) * 4*pi
    f_coeffs = np.mean(f_values[:, np.newaxis] * basis_values, axis=0) * 4 * np.pi
    
    return f_coeffs

def reconstruct_sh_signal(f_coeffs, basis_functions, omega):
    """
    Reconstructs the signal at a specific direction omega using SH coefficients.
    
    Args:
        f_coeffs: Array of shape (n,) containing SH coefficients.
        basis_functions: List of callable basis functions y_i(omega).
        omega: Direction vector (3,) to evaluate at.
        
    Returns:
        f_tilde: Approximated signal value at omega.
    """
    # Evaluate basis functions at omega
    y_values = np.array([basis_functions[i](omega) for i in range(len(f_coeffs))])
    
    # Reconstruct: f_tilde(omega) = sum(f_i * y_i(omega))
    f_tilde = np.dot(f_coeffs, y_values)
    
    return f_tilde

def sh_product_convolution(a_coeffs, b_coeffs, transfer_matrix):
    """
    Computes the SH coefficients of the product of two functions a and b.
    
    Args:
        a_coeffs: Array of shape (n,) for function a.
        b_coeffs: Array of shape (n,) for function b.
        transfer_matrix: 3D array of shape (n, n, n) containing C_ijk.
        
    Returns:
        ab_coeffs: Array of shape (n,) for the product a * b.
    """
    n = len(a_coeffs)
    ab_coeffs = np.zeros(n)
    
    for i in range(n):
        for j in range(n):
            for k in range(n):
                ab_coeffs[i] += transfer_matrix[i, j, k] * a_coeffs[j] * b_coeffs[k]
                
    return ab_coeffs

def integral_of_product(a_coeffs, b_coeffs):
    """
    Computes the integral of the product of two SH approximated functions.
    
    Args:
        a_coeffs: Array of shape (n,) for function a.
        b_coeffs: Array of shape (n,) for function b.
        
    Returns:
        integral: Scalar value of the integral.
    """
    return np.dot(a_coeffs, b_coeffs)

def sample_sphere_uniform(num_samples):
    """
    Samples points uniformly on the unit sphere.
    
    Args:
        num_samples: Number of points to sample.
        
    Returns:
        omegas: Array of shape (num_samples, 3) with unit vectors.
    """
    # Using spherical coordinates with uniform distribution
    phi = np.random.uniform(0, 2 * np.pi, num_samples)
    cos_theta = np.random.uniform(-1, 1, num_samples)
    theta = np.arccos(cos_theta)
    
    x = np.sin(theta) * np.cos(phi)
    y = np.sin(theta) * np.sin(phi)
    z = cos_theta
    
    return np.column_stack((x, y, z))
```

**Edge Cases and Pitfalls:**
*   **Smoothness:** The method assumes input functions are sufficiently smooth. Discontinuities (e.g., hard shadows) cause slow convergence and ringing artifacts (Gibbs phenomenon) due to truncation [Parent].
*   **Bandwidth Selection:** The choice of bandwidth $n$ affects accuracy. The source uses $n=8$ for low-frequency approximations [S1]. Switching between common bandwidths (e.g., SH-16 for $L=3$ and SH-25 for $L=4$) yields negligible differences in visual quality for many applications [S1].

## Subtopics

### Hemisphere Projection in SH Space
Hemisphere Projection in SH Space is a technique to compute the SH coefficients of the hemisphere visibility function $H(x)$ efficiently and differentially [S1]. It solves the problem of computing the integral $\int_{\Omega} \max((n(x) \cdot \omega), 0)y(\omega)d\omega$ by reformulating it using a linear rotation function $\phi_{SH}$ [S1]. Unlike direct integration, this approach makes the equation differentiable with respect to the normal $n(x)$ [S1]. The formula is:
$$
H(x) = \phi_{SH}(n(x)) \int_{\Omega} \max(i_z \cdot \omega, 0)y(\omega)d\omega
$$
where $\phi_{SH}(x)(\cdot)$ is a linear function defining the rotation of SH functions, and $i_z = (0, 0, 1)^T$ [S1]. The integral is solved using numerical integration at initialization and does not need to be differentiable as only SH coefficients of the environment map are updated [S1].

## Operating characteristics
*   **Time Complexity:** Projection requires solving an integral, which is expensive if done via Monte Carlo [S1]. However, once projected, operations like reconstruction and product convolution are algebraic. The product convolution involves $O(n^3)$ operations due to the transfer matrix [S1].
*   **Memory Complexity:** Storing the transfer matrix $C_{ijk}$ requires $O(n^3)$ memory [S1].
*   **Performance:** SH approximation is significantly faster than Monte Carlo integration for inverse problems, as it avoids sampling noise and allows for differentiable computation [S1].
*   **Strengths:** Efficient, differentiable, and suitable for low-frequency approximations [S1].
*   **Limitations:** Poor convergence for high-frequency details or discontinuities (Gibbs phenomenon) [Parent]. The fixed basis cannot adapt to the signal [S1].
*   **When to Use:** When efficient, differentiable computation of light transport is required, and the signal is relatively smooth [S1].
*   **When Not to Use:** When high-frequency details or sharp discontinuities are present, as SHs will exhibit ringing artifacts [Parent].

## Background
Spherical Harmonics Approximation was introduced in the context of efficient and differentiable shadow computation for inverse problems [S1]. The method leverages the mathematical properties of Spherical Harmonics, which form a complete basis of functions mapping the unit sphere $S^2$ to the complex numbers $\mathbb{C}$ [S1]. In graphics, real-valued bases are used to represent directional functions like radiance, visibility, or BRDFs [S2, unofficial]. The specific application to volume rendering and inverse problems highlights the trade-off between computational efficiency and approximation accuracy [S1].
