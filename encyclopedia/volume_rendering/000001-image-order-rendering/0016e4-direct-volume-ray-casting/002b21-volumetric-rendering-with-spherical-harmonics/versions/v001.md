# Volumetric Rendering with Spherical Harmonics


## Overview
A CUDA-based volume rendering method that traces rays through a sparse grid represented by spherical harmonics (SH) coefficients to compute color output and optionally log-transmittance for background compositing [S1, unofficial]. Unlike standard direct volume rendering which maps scalar density to color via a transfer function, this method encodes directional radiance information directly into the voxel grid using SH basis functions, allowing for view-dependent appearance without per-ray lighting calculations [S1, unofficial]. It sets itself apart from [Spherical Harmonic Volume Shading](5946-spherical-harmonic-volume-shading.md) by operating on the ray-casting level to accumulate gradients and colors directly from SH coefficients stored in the volume, rather than computing diffuse illumination via Fourier transforms [S1, unofficial].

## How it works
**Inputs:**
- Ray origins and directions for all pixels.
- A sparse voxel grid storing SH coefficients and opacity (density) values.
- Configuration flags for background rendering.
- Parameters: `nb_samples` (default 512 or 100), `cuda_n_threads` (macro `TRACE_RAY_CUDA_THREADS`), `TRACE_RAY_BG_CUDA_THREADS` [S1, S2, unofficial].

**Outputs:**
- Final accumulated color per ray.
- Optional log-transmittance tensor for background compositing [S1, unofficial].

**Data Structures:**
- **Voxel Grid:** Stores interpolated opacity (`interp_opacities`) and SH coefficients (`interp_sh_coeffs`) at sample points. The SH coefficients are typically stored as a vector of size $N_{SH}$ (e.g., 12 for degree 1, 27 for degree 2) per voxel [S2, unofficial].
- **Sample Points:** 1D array of positions along the ray [S2, unofficial].
- **Log Transmittance:** 1D tensor of size equal to the number of rays, used if background rendering is enabled [S1, unofficial].

**Steps:**
1.  **Background Check:** Verify if `grid.background_links` is defined and has size > 0. If true, allocate a 1D tensor `log_transmit` with size equal to the number of rays (origins.size(0)) [S1, unofficial].
2.  **Sample Point Generation:** Compute sample points in world space:
    $$ \text{sample\_points\_in} = \text{ray\_start} + \text{dir} \times \text{samples}[:, \text{None}] $$
    where `samples` are parameterized by `tics` in range $[0.05, 0.95]$ or $[0, 1]$ [S2, unofficial].
3.  **Interpolation:** Interpolate density (opacity) and SH coefficients from the voxel grid at the sample points using trilinear interpolation [S2, unofficial].
    - Extract opacities: `interp_opacities = interp[:, :1]`
    - Extract SH coefficients: `interp_sh_coeffs = interp[:, 1:]` [S2, unofficial].
4.  **SH Basis Evaluation:** Compute the SH basis evaluation for the ray direction:
    $$ \text{my\_sh\_in} = \text{SH\_basis}(\text{ray\_direction}) $$ [S2, unofficial].
5.  **SH Harmonics Computation:** Compute the SH harmonics by multiplying the interpolated coefficients with the basis evaluation:
    $$ \text{interp\_harmonics} = \text{interp\_sh\_coeffs} \times \text{my\_sh\_in} $$ [S2, unofficial].
6.  **Sample Color Computation:** Compute sample colors by summing the SH harmonics across the SH dimension:
    $$ \text{samples\_colors} = \sum \text{interp\_harmonics}, \text{axis}=3 $$ [S2, unofficial].
7.  **Optical Depth and Transmittance:**
    - Compute optical depth deltas:
      $$ \text{deltas} = \text{samples}[1:] - \text{samples}[:-1] $$ [S2, unofficial].
    - Compute weighted deltas for transmittance:
      $$ \text{deltas\_times\_sigmas} = -\text{deltas} \times \text{interp\_opacities}[:-1] $$ [S2, unofficial].
    - Compute cumulative transmittance:
      $$ \text{cum\_weighted\_deltas} = \text{cumsum}(\text{deltas\_times\_sigmas}) $$
      Prepend with 0 [S2, unofficial].
    - Compute per-sample transmittance $T$ and opacity $1-T$:
      $$ \text{tmp1} = \exp(\text{cum\_weighted\_deltas}) $$
      $$ \text{tmp2} = 1 - \exp(\text{deltas\_times\_sigmas}) $$ [S2, unofficial].
8.  **Final Color Compositing:** Composite the final color:
    $$ \text{rays\_color} = \sum T \times (1-T) \times \text{samples\_colors} $$ [S2, unofficial].
9.  **Background Rendering (Optional):** If background is enabled, launch `render_background_kernel` with block count `CUDA_N_BLOCKS_NEEDED(Q, TRACE_RAY_BG_CUDA_THREADS)`, passing `log_transmit` and results tensors [S1, unofficial].
10. **Ray Kernel Launch:** Launch `render_ray_kernel` with block count `CUDA_N_BLOCKS_NEEDED(Q * WARP_SIZE, cuda_n_threads)`, where $Q$ is the number of rays [S1, unofficial].

**Pseudocode:**

```python
import math
import numpy as np

def sh_basis_eval(direction, degree=1):
    """
    Evaluates Spherical Harmonics basis functions for a given direction.
    For degree 1, returns 4 coefficients (L0, L1x, L1y, L1z).
    """
    x, y, z = direction
    norm = math.sqrt(x*x + y*y + z*z)
    if norm == 0:
        return [1.0, 0.0, 0.0, 0.0]
    nx, ny, nz = x/norm, y/norm, z/norm
    
    # Degree 0
    c0 = 1.0 / math.sqrt(4.0 * math.pi)
    
    # Degree 1
    c1 = math.sqrt(3.0 / (4.0 * math.pi))
    
    return [c0, c1*nx, c1*ny, c1*nz]

def volumetric_render_sh(rays_origin, rays_direction, grid, grid_dims, nb_samples=512, background_enabled=False):
    """
    Renders volume using Spherical Harmonics coefficients.
    """
    num_rays = len(rays_origin)
    final_colors = np.zeros((num_rays, 3))
    log_transmit = None
    
    if background_enabled:
        log_transmit = np.zeros(num_rays)
        
    # Sample positions along ray [S2, unofficial]
    tics = np.linspace(0.05, 0.95, nb_samples)
    
    for i in range(num_rays):
        origin = rays_origin[i]
        direction = rays_direction[i]
        
        # Compute sample points [S2, unofficial]
        sample_points = origin + direction * tics[:, None]
        
        # Interpolate opacity and SH coefficients [S2, unofficial]
        # Assume trilinear interpolation returns (opacity, sh_coeffs)
        # sh_coeffs shape: (nb_samples, n_sh_coeffs)
        opacities, sh_coeffs = trilinear_interpolate_grid(grid, sample_points, grid_dims)
        
        # Compute SH basis for ray direction [S2, unofficial]
        sh_in = sh_basis_eval(direction)
        
        # Compute SH harmonics [S2, unofficial]
        # interp_harmonics = sh_coeffs * sh_in (broadcasted)
        interp_harmonics = sh_coeffs * np.array(sh_in)
        
        # Compute sample colors [S2, unofficial]
        samples_colors = np.sum(interp_harmonics, axis=1)
        
        # Compute optical depth deltas [S2, unofficial]
        deltas = np.diff(tics)
        
        # Compute weighted deltas for transmittance [S2, unofficial]
        deltas_times_sigmas = -deltas * opacities[:-1]
        
        # Compute cumulative transmittance [S2, unofficial]
        cum_weighted_deltas = np.cumsum(deltas_times_sigmas)
        cum_weighted_deltas = np.insert(cum_weighted_deltas, 0, 0)
        
        # Compute per-sample transmittance T and opacity 1-T [S2, unofficial]
        tmp1 = np.exp(cum_weighted_deltas)
        tmp2 = 1 - np.exp(deltas_times_sigmas)
        
        # Composite final color [S2, unofficial]
        # rays_color = sum(T * (1-T) * samples_colors)
        # Note: T corresponds to transmittance *before* the sample, 
        # so we use tmp1[:-1] for T and tmp2 for opacity contribution
        T = tmp1[:-1]
        opacity_contrib = tmp2
        final_colors[i] = np.sum(T * opacity_contrib * samples_colors, axis=0)
        
        if background_enabled:
            # Update log_transmit with final transmittance
            log_transmit[i] = cum_weighted_deltas[-1]
            
    return final_colors, log_transmit
```

## Subtopics

### [Spherical Harmonics](5603-spherical-harmonics.md)
Spherical Harmonics (SH) provide a complete basis of functions mapping the unit sphere $S^2$ to the complex numbers $\mathbb{C}$, used to represent directional functions like radiance in volumetric rendering. Unlike Spherical Gaussians (SGs), SHs constitute a fixed, non-learnable basis, which simplifies implementation by removing the need for optimization of basis parameters.

### [Spherical Harmonic Volume Shading](5946-spherical-harmonic-volume-shading.md)
Spherical Harmonic Volume Shading is a method for computing diffuse illumination in Fourier Volume Rendering (FVR) that handles the nonlinearity of the shading function (specifically the $\max(\mathbf{N} \cdot \mathbf{L}, 0)$ term) without requiring repeated 3D Fourier transforms for every light direction change. It approximates the illumination and shading functions using spherical harmonics, allowing the shading equation to be expressed as a linear convolution in spherical coordinates. Unlike linear or cubic illumination models which require slicing only two volumes but perform complex calculations in the inner loop, this method slices multiple volumes (typically 10) to assemble one image, offering a trade-off between memory usage and the ability to interactively change lighting.

### [Ray Tracing Backward Pass](5966-ray-tracing-backward-pass.md)
The Ray Tracing Backward Pass computes the gradients for spherical harmonic (SH) coefficients, ray origins, and ray directions required for optimizing Volumetric Rendering with Spherical Harmonics. It serves as the differentiable counterpart to the forward ray casting kernel, enabling end-to-end training of 3D Gaussian or voxel-based scene representations. It is distinguished from its sibling [Spherical Harmonic Volume Shading](5946-spherical-harmonic-volume-shading.md) by operating on the ray-tracing level to accumulate gradients across the entire ray path, including background contributions and regularization losses, rather than shading individual primitives.

### Volumetric Spherical Harmonics Precomputed Radiance Transfer
Stores the scene's response to light with a distribution defined by a spherical harmonic basis function, modeling the response for a number of spherical harmonic bands to render any arbitrary lighting setup [S3, unofficial]. Calculates precomputed transfer volumetrically, allowing querying at any location in 3D space and providing consistent lighting between static and dynamic geometry [S3, unofficial]. Exhibits ringing artifacts; prefiltering can mitigate this but leads to undesirable smoothening of the lighting [S3, unofficial]. Presents relatively high memory and bandwidth costs [S3, unofficial]. Suffers from high runtime cost [S3, unofficial].

## Operating characteristics
- **Time Complexity:** Linear with respect to the number of rays and samples per ray. The SH evaluation and compositing steps are constant time per sample relative to the number of SH bands.
- **Memory Complexity:** Linear with respect to the number of voxels and the size of the SH basis. High memory and bandwidth costs are noted for precomputed transfer approaches [S3, unofficial].
- **Performance:** Measured performance depends on the sparsity of the grid and the number of SH bands. CUDA-based implementations utilize block counts calculated as `CUDA_N_BLOCKS_NEEDED(Q * WARP_SIZE, cuda_n_threads)` [S1, unofficial].
- **Strengths:** View-dependent appearance without per-ray lighting calculations; differentiable for optimization [S1, unofficial].
- **Limitations:** Ringing artifacts may occur; high memory and bandwidth costs; high runtime cost for precomputed transfer [S3, unofficial].
- **When to use:** When view-dependent effects are required in volumetric rendering and differentiability is needed for optimization [S1, unofficial].
- **When not to use:** When memory bandwidth is a critical bottleneck and simple scalar transfer functions suffice [S3, unofficial].

## Background
Originated from CUDA-based volume rendering methods that trace rays through sparse grids represented by spherical harmonics coefficients [S1, unofficial]. The use of SH for precomputed radiance transfer in volumetric rendering was described by Lehtinen et al. [S3, unofficial], allowing for querying at any location in 3D space and providing consistent lighting between static and dynamic geometry. The method is used in neural volume representations and differentiable rendering pipelines [S1, unofficial].
