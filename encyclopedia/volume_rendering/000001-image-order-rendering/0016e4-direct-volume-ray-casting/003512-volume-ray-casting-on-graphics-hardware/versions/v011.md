# Volume Ray-Casting on Graphics Hardware

Also called: Stream model for volumetric ray-casting

## Overview
This method implements direct volume ray casting on programmable graphics hardware (specifically DirectX 9-level architectures like the ATI 9700) using a multi-pass stream model [S1, unofficial]. It solves the problem of integrating acceleration techniques, such as early ray termination and empty-space skipping, into 3D texture-based volume rendering by exploiting intrinsic parallelism and efficient communication between rendering passes [S1, unofficial]. It sets itself apart from single-pass fragment shader approaches by using a sequence of rendering passes where the output of one pass (accumulated color and opacity) is stored in a 2D texture and read by the next, allowing the hardware's early z-test to discard fragments that have already reached an opacity threshold or hit an iso-surface [S1, unofficial].

## How it works
**Inputs and Outputs:**
*   **Input:** A volumetric scalar field stored in 3D texture memory; camera parameters; an opacity threshold $\alpha_{thresh}$ (typically 0.95 or 1.0); and an optional iso-surface value $v_{iso}$ [S1, unofficial].
*   **Output:** A 2D color buffer representing the final rendered image [S1, unofficial].

**Data Structures:**
1.  **Volume Texture:** 3D texture containing scalar voxel values $V(x,y,z)$ [S1, unofficial].
2.  **Ray Direction Textures:** Two 2D textures storing the pre-computed ray direction vectors in local texture coordinates for each pixel [S1, unofficial].
3.  **Accumulation Textures:** Two 2D textures (one for color $C$, one for opacity $\alpha$) used to store the state of ray marching between passes. These are rendered to and sampled from in consecutive passes [S1, unofficial].
4.  **Depth Buffer:** Used for early z-testing [S1, unofficial].

**Numbered Steps:**

1.  **Pre-computation:** For each pixel, compute the direction of the ray of sight through the volume in local texture coordinates. Store these directions in two 2D textures [S1, unofficial].
2.  **Initialization:** Render the accumulation textures (color and opacity) to zero. Set the depth buffer to a state that allows all fragments to pass [S1, unofficial].
3.  **Main Ray Marching Passes:** Perform a fixed number of rendering passes. In each pass:
    a.  Bind the accumulation textures from the previous pass as input.
    b.  Bind the ray direction textures.
    c.  Execute a fragment shader that:
        i.  Samples the accumulated color $C_{prev}$ and opacity $\alpha_{prev}$ from the previous pass's textures.
        ii. Advances the ray position along the pre-computed direction by a fixed step size.
        iii. Samples the volume texture $V$ at the new position using trilinear interpolation.
        iv. Applies the transfer function to compute the sample color $C_{sample}$ and opacity $\alpha_{sample}$ [S1, unofficial].
        v.  Performs front-to-back compositing:
            $$ C_{new} = C_{prev} + (1 - \alpha_{prev}) \alpha_{sample} C_{sample} $$
            $$ \alpha_{new} = \alpha_{prev} + (1 - \alpha_{prev}) \alpha_{sample} $$
        vi. Writes $C_{new}$ and $\alpha_{new}$ to the output accumulation textures [S1, unofficial].
4.  **Termination Check Pass:** Between main passes, execute an additional pass to test for termination:
    a.  Sample the accumulated opacity $\alpha$ from the accumulation texture.
    b.  If $\alpha \ge \alpha_{thresh}$ or an iso-surface is hit (if applicable), set the fragment's depth value $z$ to the maximum possible value (e.g., 1.0).
    c.  Otherwise, set $z$ to 0 [S1, unofficial].
5.  **Early Z-Test Configuration:** Set the depth test function to GREATER. This ensures that if a fragment's depth was set to the maximum in the termination check pass, all subsequent main passes will discard this fragment due to the early z-test, effectively terminating the ray [S1, unofficial].
6.  **Final Output:** After all main passes, the final accumulated color and opacity are in the accumulation textures. Render these to the frame buffer [S1, unofficial].

**Parameters:**
*   **Number of Main Passes:** Fixed number, determined by the desired ray length and step size [S1, unofficial].
*   **Opacity Threshold:** Typically 0.95 or 1.0 [S1, unofficial].
*   **Hardware:** ATI 9700 graphics card [S1, unofficial].
*   **API:** Pixel Shader 2.0 API (DirectX9-level) [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Dependent Texture Fetches:** The ATI 9700 has a limited number of dependent texture fetches. The algorithm must minimize the number of texture reads per fragment to avoid performance degradation [S1, unofficial].
*   **Floating Point Textures:** Accumulation textures must support floating point values to handle negative values if required, though standard volume rendering typically uses non-negative values [S1, unofficial].
*   **Early Z-Test Timing:** The early z-test is applied before the shader program is executed. This requires careful synchronization between the termination check pass and the main passes to ensure the depth buffer correctly reflects the termination state [S1, unofficial].

**Pseudocode:**

```python
# Pre-computation
ray_directions = compute_ray_directions(camera_params, volume_bounds)

# Initialization
accum_color = Texture2D(width, height, format=FLOAT32)
accum_opacity = Texture2D(width, height, format=FLOAT32)
accum_color.clear(0.0)
accum_opacity.clear(0.0)
depth_buffer.clear(0.0)

# Main Ray Marching Passes
for i in range(num_main_passes):
    # Bind previous accumulation textures as inputs
    bind_texture(accum_color, unit=0)
    bind_texture(accum_opacity, unit=1)
    bind_texture(ray_directions, unit=2)
    bind_texture(volume_texture, unit=3)

    # Execute fragment shader for ray marching
    # Shader code:
    #   prev_color = sample_texture(accum_color, tex_coord)
    #   prev_opacity = sample_texture(accum_opacity, tex_coord)
    #   ray_dir = sample_texture(ray_directions, tex_coord)
    #   new_pos = current_pos + ray_dir * step_size
    #   sample_value = sample_volume(volume_texture, new_pos)
    #   sample_color, sample_opacity = apply_transfer_function(sample_value)
    #   new_color = prev_color + (1.0 - prev_opacity) * sample_opacity * sample_color
    #   new_opacity = prev_opacity + (1.0 - prev_opacity) * sample_opacity
    #   output_color = new_color
    #   output_opacity = new_opacity
    render_to_textures(accum_color, accum_opacity)

    # Termination Check Pass
    bind_texture(accum_opacity, unit=0)
    render_to_depth_buffer()
    # Shader code for termination check:
    #   opacity = sample_texture(accum_opacity, tex_coord)
    #   if opacity >= threshold or iso_surface_hit:
    #       depth = 1.0
    #   else:
    #       depth = 0.0
    #   output_depth = depth

    # Set depth test to GREATER for subsequent passes
    set_depth_test(GREATER)

# Final Output
bind_texture(accum_color, unit=0)
render_to_framebuffer()
```

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the number of main passes. The early z-test reduces the effective number of passes for opaque regions [S1, unofficial].
*   **Memory Complexity:** $O(W \cdot H)$ for the accumulation textures, where $W$ and $H$ are the viewport dimensions [S1, unofficial].
*   **Measured Performance:** Performance gains up to a factor of 3 for typical renditions of volumetric data sets on the ATI 9700 graphics card [S1, unofficial].
*   **Strengths:** Exploits intrinsic parallelism of fragment processors; efficient communication between passes via texture render targets; effective early ray termination via early z-test [S1, unofficial].
*   **Limitations:** Limited by the number of dependent texture fetches on the hardware; fixed number of passes may lead to unnecessary computations for empty space if not combined with empty-space skipping [S1, unofficial].
*   **When to Use:** When targeting DirectX 9-level hardware with programmable pixel shaders and the need for early ray termination [S1, unofficial].
*   **When Not to Use:** When targeting hardware with limited dependent texture fetches or when more advanced acceleration techniques like empty-space skipping are required [S1, unofficial].

## Background
This method was proposed in 2003 by researchers at the Technical University of Munich (TUM) [S1, unofficial]. It was designed to integrate acceleration techniques into 3D texture-based volume rendering on programmable graphics hardware, specifically targeting the capabilities of DirectX 9-level hardware like the ATI 9700 [S1, unofficial]. The method builds on the observation that CPU-based volume rendering is insufficient for real-time interaction with large data sets, and leverages the parallelism of GPU fragment processors [S1, unofficial].
