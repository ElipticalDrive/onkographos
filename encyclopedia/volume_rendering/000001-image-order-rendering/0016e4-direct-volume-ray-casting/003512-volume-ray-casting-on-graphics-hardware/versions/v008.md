# Volume Ray-Casting on Graphics Hardware

Also called: Stream model for volumetric ray-casting

## Overview
This method implements direct volume ray casting on programmable graphics hardware (specifically DirectX 9-level architectures like the ATI 9700) using a multi-pass stream model [S1, unofficial]. It solves the challenge of integrating early ray termination and empty-space skipping into 3D texture-based rendering by exploiting the intrinsic parallelism of fragment processors and efficient inter-pass communication via texture render targets [S1, unofficial]. Unlike single-pass software ray casting, it leverages the GPU's early z-test to discard fragments that have reached an opacity threshold or hit an iso-surface, avoiding unnecessary shader execution for subsequent samples [S1, unofficial].

## How it works
The method uses a multi-pass rendering pipeline where the output of each pass is stored in a 2D texture (texture render target) rather than the frame buffer, allowing consecutive passes to access accumulated color and opacity values [S1, unofficial].

**Inputs and Outputs:**
*   **Input:** Volumetric scalar data stored in a 3D texture; camera parameters; transfer function; opacity threshold $\alpha_{thresh}$; iso-surface value $v_{iso}$ (optional).
*   **Output:** Final 2D image stored in a texture render target.

**Data Structures:**
1.  **Ray Direction Textures:** Two 2D textures storing the ray direction vectors in local texture coordinates for each pixel. Computed prior to ray traversal.
2.  **Accumulation Textures:** 2D textures storing the accumulated color $C'$ and opacity $\alpha'$ for each fragment. These are updated in each main pass.
3.  **Depth Buffer:** Used for early z-testing.

**Numbered Steps:**

1.  **Pre-computation:** For each pixel, compute the ray direction in local texture coordinates. Store these directions in two 2D textures [S1, unofficial].
2.  **Main Ray Marching Passes:** Perform a fixed number of rendering passes. In each pass:
    a.  Bind the accumulation textures from the previous pass as inputs.
    b.  Bind the ray direction textures.
    c.  Execute the fragment shader to advance the ray by one step, sample the volume, classify the value, and update $C'$ and $\alpha'$ using the front-to-back compositing equations defined in [Hardware-Accelerated Volume Rendering](5616-hardware-accelerated-volume-rendering.md).
    d.  Write the updated $C'$ and $\alpha'$ to the accumulation texture render target [S1, unofficial].
3.  **Termination Check Pass:** Between main passes, execute an additional pass to test for early termination:
    a.  Read the accumulated opacity $\alpha'$ from the accumulation texture.
    b.  Check if $\alpha' \ge \alpha_{thresh}$ or if an iso-surface is hit (if applicable).
    c.  If the condition is true, set the fragment's depth value $z$ to the maximum possible depth (e.g., 1.0 in normalized device coordinates).
    d.  If the condition is false, set $z$ to 0 [S1, unofficial].
4.  **Early Z-Test Configuration:** Set the depth test function to `GREATER`. This ensures that in subsequent main passes, any fragment with $z=1.0$ (terminated) will fail the depth test and be discarded before the shader executes, while fragments with $z=0$ (active) will pass and be processed [S1, unofficial].
5.  **Final Pass (Optional):** If an iso-surface was hit, a final pass may use the intersection coordinates to perform gradient-based shading [S1, unofficial].

**Pseudocode:**

```python
# Pre-computation
ray_directions = compute_ray_directions(camera, volume_bounds)

# Initialize accumulation textures with zero color and opacity
accum_color = zeros(width, height, 3)
accum_opacity = zeros(width, height, 1)

# Main ray marching loop
for step in range(num_steps):
    # Main Pass: Advance ray and accumulate
    render_pass(
        textures=[accum_color, accum_opacity, ray_directions, volume_texture],
        shader=ray_march_shader,
        render_target=[accum_color, accum_opacity]
    )
    
    # Termination Check Pass
    render_pass(
        textures=[accum_opacity],
        shader=termination_check_shader,
        render_target=None, # Only writes to depth buffer
        depth_write=True,
        depth_func='GREATER'
    )
    
    # Check if all fragments are terminated (optional optimization)
    if all_terminated(accum_opacity):
        break

# Final image is in accum_color
```

**Termination Check Shader Logic:**
```python
def termination_check_shader(accum_opacity):
    alpha = accum_opacity
    if alpha >= alpha_threshold or iso_surface_hit:
        return depth_max # Discard in next pass
    else:
        return 0.0 # Process in next pass
```

**Parameters:**
*   **Opacity Threshold ($\alpha_{thresh}$):** Typically 0.95 or 1.0 [S1, unofficial].
*   **Hardware:** ATI 9700 graphics card [S1, unofficial].
*   **API:** Pixel Shader 2.0 (DirectX 9) [S1, unofficial].
*   **Features:** Per-fragment texture fetches (up to 8 textures), texture render targets, depth replace, per-fragment arithmetic [S1, unofficial].

**Edge Cases and Pitfalls:**
*   **Dependent Texture Fetches:** On ATI hardware, the number of dependent texture fetches is limited. Care must be taken to minimize dependencies in the shader [S1, unofficial].
*   **Floating Point Textures:** Accumulation textures must support floating-point formats to handle negative values and high dynamic range if required [S1, unofficial].
*   **Early Z-Test Dependency:** The early z-test only works if all other per-fragment tests (like stencil) are disabled or pass [S1, unofficial].

## Operating characteristics
*   **Time Complexity:** $O(N \cdot P)$, where $N$ is the number of pixels and $P$ is the average number of active samples per ray. Early termination reduces $P$ significantly for sparse volumes.
*   **Memory Complexity:** $O(W \cdot H)$ for accumulation textures, where $W, H$ are viewport dimensions.
*   **Performance:** Demonstrated performance gains up to a factor of 3 for typical volumetric data sets on the ATI 9700 [S1, unofficial].
*   **Strengths:** Efficient early ray termination and empty-space skipping via hardware early z-test; leverages GPU parallelism.
*   **Limitations:** Requires multiple rendering passes; limited by dependent texture fetch counts on older hardware; not suitable for real-time on very large datasets without further optimization [S1, unofficial].

## Background
This method was proposed in 2003 by the authors of [S1, unofficial] as a novel approach to integrate acceleration techniques into 3D texture-based volume rendering. It was designed for DirectX 9-level programmable graphics hardware, specifically targeting the ATI 9700. The work highlights the importance of texture render targets and early z-tests for achieving interactive frame rates in volume rendering.
