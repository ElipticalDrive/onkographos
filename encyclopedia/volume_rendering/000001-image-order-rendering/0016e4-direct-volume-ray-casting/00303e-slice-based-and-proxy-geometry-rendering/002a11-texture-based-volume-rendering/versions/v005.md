# Texture-Based Volume Rendering

Also called: Proxy Geometry Rendering, TBVR, Texture Based Ray Casting, Slice-Based Volume Rendering (SBVR)

## Overview
Texture-Based Volume Rendering (TBVR) is a direct volume ray casting technique that accelerates rendering by mapping volumetric data to GPU textures and sampling it via rasterized proxy geometry (polygonal slices) [S1, unofficial][S2, book][S7]. It solves the problem of efficient interactive visualization by leveraging the graphics pipeline's hardware texture sampling and alpha blending capabilities, avoiding the need for explicit ray-marching loops in shaders [S3, unofficial][S5, unofficial]. It is distinguished from pure ray-marching methods by its reliance on geometric primitives and hardware compositing, and from object-aligned slice methods by its ability to use view-aligned slices for consistent sampling [S1, unofficial][S2, book].

## How it works
### Inputs and Outputs
**Inputs:**
*   Volumetric scalar data (regular grid) [S1, unofficial][S5, unofficial].
*   Camera position and orientation [S2, book].
*   Transfer function (mapping scalar values to color and opacity) [S1, unofficial][S2, book].

**Outputs:**
*   2D image composited into the frame buffer [S1, unofficial][S7].

### Data Structures
1.  **Volume Texture:**
    *   **3D Texture:** Stores the entire volume in GPU memory. Dimensions match the data grid $(W, H, D)$ [S1, unofficial][S2, book].
    *   **2D Texture Stack:** Stores slices as a stack of 2D textures. Requires replication in three principal directions (x, y, z) for object-aligned rendering, tripling memory usage [S1, unofficial][S2, book][S4, unofficial].
2.  **Transfer Function Texture:**
    *   1D texture mapping scalar values $v \in [0, 1]$ to RGBA color and opacity [S1, unofficial][S2, book].
3.  **Proxy Geometry:**
    *   Set of polygons (quads or triangle fans) intersecting the volume bounding box [S1, unofficial][S4, unofficial].
    *   Vertices store 3D texture coordinates $(u, v, w)$ mapping volume space $[0,1]^3$ to the polygon surface [S1, unofficial][S2, book].

### Algorithm Steps
The implementation follows three stages: Initialize, Update, and Draw [S2, book][S7].

1.  **Initialize:**
    1.  Load volumetric data into CPU memory [S2, book].
    2.  Process data if necessary (e.g., compute gradients, down-sample) [S2, book][S7].
    3.  Create transfer function lookup tables (1D textures) [S2, book].
    4.  Upload volume data to GPU memory as a 3D texture or stack of 2D textures [S1, unofficial][S2, book][S5, unofficial].
    5.  Compile fragment shaders [S2, book].

2.  **Update (on view or parameter change):**
    1.  Compute proxy geometry:
        *   Intersect slicing planes with the volume bounding box [S1, unofficial][S4, unofficial].
        *   Sort resulting vertices in clockwise or counter-clockwise order around their center [S2, book][S4, unofficial].
        *   Construct polygon primitives (e.g., triangle fans from centroid) [S4, unofficial].
        *   Assign 3D texture coordinates to each vertex [S1, unofficial][S2, book].
    2.  Refresh textures if rendering mode or transfer function parameters change [S2, book][S7].
    3.  Perform opacity correction of transfer function textures if the sampling rate has changed [S7].
    4.  Sort proxy polygons in depth order relative to the camera (back-to-front for Over operator, front-to-back for Under operator) [S1, unofficial][S2, book].

3.  **Draw:**
    1.  Set up rendering state:
        *   Disable lighting and culling [S2, book][S7].
        *   Enable alpha blending. For the Over operator: Source = `GL_ONE`, Destination = `GL_ONE_MINUS_SRC_ALPHA` [S1, unofficial][S2, book]. For the Under operator: Source = `GL_ONE_MINUS_DST_ALPHA`, Destination = `GL_ONE` [S1, unofficial].
        *   Enable depth testing but disable depth buffer writing if blending with opaque geometry [S7].
        *   Bind volume texture (unit 0) and transfer function texture (unit 1) [S2, book].
    2.  Draw slice polygons in sorted order [S1, unofficial][S2, book].
    3.  Restore rendering state [S2, book][S7].

### Fragment Shader Execution
For each fragment generated by the proxy geometry:
1.  Interpolate texture coordinates $(u, v, w)$ from vertex attributes [S2, book][S7].
2.  Perform data texture lookup: $v = \text{tex3D}(u, v, w, \text{dataTex})$ [S1, unofficial][S2, book].
3.  Perform dependent lookup into the transfer function texture: $\text{color} = \text{tex1D}(v, \text{tfTex})$ [S1, unofficial][S2, book].
4.  (Optional) Apply illumination (e.g., Blinn-Phong using gradients) [S1, unofficial][S2, book].
5.  Send color and opacity to the compositing stage [S2, book].

### Pseudocode

```python
# Initialization
def initialize(volume_data, transfer_function):
    # Upload volume to GPU as 3D texture
    data_tex = upload_to_gpu(volume_data, format='3D')
    
    # Upload transfer function to GPU as 1D texture
    tf_tex = upload_to_gpu(transfer_function, format='1D')
    
    # Compile fragment shader
    fragment_shader = compile_shader("""
        uniform sampler3D dataTex;
        uniform sampler1D tfTex;
        varying vec3 texCoord;
        
        void main() {
            float v = texture3D(dataTex, texCoord).r;
            vec4 color = texture1D(tfTex, v);
            gl_FragColor = color;
        }
    """)

# Update Stage
def update_proxy_geometry(camera, volume_bounds, slice_spacing):
    # 1. Define slicing planes perpendicular to view direction
    # 2. Intersect planes with volume bounding box
    vertices = intersect_planes_with_box(camera, volume_bounds)
    
    # 3. Sort vertices in counter-clockwise order around centroid
    centroid = compute_centroid(vertices)
    sorted_vertices = sort_ccw(vertices, centroid)
    
    # 4. Construct triangle fan from centroid
    proxy_polygons = []
    for i in range(len(sorted_vertices) - 1):
        poly = [centroid, sorted_vertices[i], sorted_vertices[i+1]]
        proxy_polygons.append(poly)
        
    # 5. Assign 3D texture coordinates to vertices
    for vertex in proxy_polygons:
        vertex.tex_coord = world_to_texture_coords(vertex.pos, volume_bounds)
        
    # 6. Sort polygons by depth relative to camera
    sorted_polygons = sort_by_depth(proxy_polygons, camera)
    return sorted_polygons

# Draw Stage
def render(sorted_polygons, data_tex, tf_tex):
    # Set up blending for Over operator
    set_blend_func(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)
    
    # Disable depth writing to allow alpha blending
    set_depth_mask(False)
    
    bind_texture(data_tex, unit=0)
    bind_texture(tf_tex, unit=1)
    
    for polygon in sorted_polygons:
        draw_triangle_fan(polygon)
        
    # Restore state
    set_depth_mask(True)
```

### Subtopics
*   **Object-Aligned Slices:** Uses three stacks of 2D textures aligned with principal axes (x, y, z). Fast to render but requires 3x memory due to data replication and suffers from intensity variations and popping artifacts when the camera moves [S1, unofficial][S2, book][S4, unofficial].
*   **View-Aligned Slices:** Generates proxy geometry orthogonal to the viewing direction. More memory efficient (no replication) and provides consistent sampling distance, but requires dynamic geometry generation per frame [S1, unofficial][S2, book].

## Operating characteristics
*   **Time Complexity:** Rendering time is proportional to the number of proxy polygons (slices) and the resolution of the texture lookup. View-aligned slices require $O(N)$ geometry generation per frame, where $N$ is the number of slices [S1, unofficial][S2, book].
*   **Memory Complexity:**
    *   3D Texture: $O(V)$, where $V$ is the volume size [S2, book].
    *   2D Texture Stack (Object-Aligned): $3 \times O(V)$ due to replication along three axes [S1, unofficial][S2, book][S4, unofficial].
*   **Measured Performance:** Hardware-accelerated texture sampling and blending allow for interactive frame rates on consumer hardware [S1, unofficial][S3, unofficial]. 3D textures provide trilinear interpolation but may have slower access speeds compared to 2D textures [S6, unofficial].
*   **Strengths:** Leverages mature GPU hardware for sampling and compositing; simple implementation; supports interactive rotation [S1, unofficial][S5, unofficial].
*   **Limitations:**
    *   **Artifacts:** "Pop-up" artifacts occur when switching between texture stacks in object-aligned rendering due to changes in sampling points [S1, unofficial][S2, book][S6, unofficial].
    *   **Intensity Variation:** Sampling distance changes with viewpoint in object-aligned slices, causing intensity variations [S1, unofficial][S2, book].
    *   **Memory:** Object-aligned slices triple memory usage [S1, unofficial][S4, unofficial].
    *   **Sampling Rate:** Accuracy depends on the sampling rate $s$ (inverse of sample distance $l$); insufficient sampling causes artifacts [S2, book][S5, unofficial].

## Background
Texture-Based Volume Rendering was developed in the early 2000s to exploit the emerging 3D texture capabilities of consumer graphics hardware [S1, unofficial][S2, book]. Key early implementations include the work by Krüger and Westermann (2003) and the NVIDIA GPU Gems Chapter 39 [S1, unofficial][S2, book]. It represents a shift from CPU-based ray casting to GPU-accelerated rasterization techniques [S3, unofficial].
