# Texture-Based Volume Rendering

Also called: Geometry-based volume visualization, Proxy Geometry Rendering, Slice-based rendering, TBVR, Texture Based Ray Casting

## Overview
Texture-Based Volume Rendering (TBVR) is a direct volume ray casting technique that accelerates rendering by mapping volumetric data onto 2D or 3D textures and using proxy geometry (polygonal slices) to sample the volume [S1, S2, S7, unofficial]. Unlike standard ray marching which computes samples per pixel, TBVR rasterizes a set of polygons spanning the volume, leveraging the graphics pipeline's texture sampling and hardware alpha blending to perform compositing [S2, unofficial][S9]. It is distinguished from [2D Visualization from 3D Grid (Slow)](1507-2d-visualization-from-3d-grid-slow.md) by its use of GPU-accelerated texture memory and fragment shaders for interactive frame rates, and from [Raymarching with 3D Volume Texture](10839-raymarching-with-3d-volume-texture.md) by its object-order rasterization of proxy slices rather than image-order ray traversal [S2, S7, unofficial].

## How it works
### Inputs and Outputs
**Inputs:**
*   Scalar volume data $V$ (regular grid).
*   Transfer function $T(V) \rightarrow (\mathbf{c}, \alpha)$ [S2, unofficial][S3, book].
*   Camera parameters (view and projection matrices) [S5, unofficial].
*   Slicing parameters (number of slices, spacing) [S5, unofficial].

**Outputs:**
*   Final composited image $\mathbf{C}_{out}$ in the frame buffer [S2, unofficial].

### Data Structures
**Volume Texture:**
*   **3D Texture:** Preferred for modern hardware. Stores the entire volume in GPU memory. Format: `RedFormat` (single channel scalar), Type: `UnsignedByteType` (or `FloatType` for higher precision), Filter: `LinearFilter` (trilinear interpolation) [S5, unofficial].
*   **2D Texture Stack:** Legacy approach. Stores volume as a stack of 2D textures. To support arbitrary viewing angles, data is often replicated along three principal axes (x, y, z), tripling memory usage [S2, unofficial][S3, book][S7, unofficial].

**Proxy Geometry:**
*   **Object-Aligned Slices:** Parallel planes aligned with the volume axes (e.g., XY, YZ, XZ planes). Requires three stacks of 2D textures if arbitrary rotation is needed [S2, S6, unofficial].
*   **View-Aligned Slices:** Parallel planes orthogonal to the viewing direction. Requires dynamic generation of polygon vertices based on the intersection of slicing planes with the volume bounding box [S2, S6, unofficial].

**Transfer Function Texture:**
*   1D texture mapping scalar values to RGBA color and opacity [S3, book].

### Algorithm Steps
1.  **Initialize:**
    *   Load volume data into CPU memory [S3, book].
    *   Process data if necessary (e.g., compute gradients for shading, downsample) [S3, book][S5, unofficial].
    *   Create transfer function lookup table (1D texture) [S3, book].
    *   Upload volume data to GPU as a 3D texture or 2D texture stack [S2, S5, unofficial].
    *   Create fragment shaders for data sampling, transfer function lookup, and optional shading [S3, book][S5, unofficial].

2.  **Update (Per Frame):**
    *   **Compute Proxy Geometry:**
        *   *View-Aligned:* Intersect $N$ slicing planes with the volume bounding box. Sort resulting vertices in counter-clockwise order. Construct polygon primitives (e.g., triangle fans from centroid) [S2, S6, unofficial].
        *   *Object-Aligned:* Select the texture stack closest to the current viewpoint to minimize sampling artifacts [S2, unofficial].
    *   **Set Rendering State:**
        *   Disable lighting and culling [S3, book][S9].
        *   Enable alpha blending. For the Over operator (back-to-front), set source factor to 1 and destination factor to $1 - \text{Source Alpha}$ [S2, unofficial].
        *   Disable depth testing or disable depth buffer writing if blending with opaque geometry [S9].
        *   Bind volume texture (unit 0) and transfer function texture (unit 1) [S3, book][S9].
        *   Pass uniform parameters: texture dimensions (`u_slices`), threshold (`u_thresh`), alpha scale (`u_alphaScale`), and clipping planes if used [S5, unofficial].

3.  **Draw:**
    *   Render proxy geometry polygons in sorted order (back-to-front for Over compositing) [S2, unofficial][S9].
    *   **Vertex Shader:**
        *   Compute world-space position and texture coordinates for each vertex. For view-aligned slices, texture coordinates map the polygon vertices to the volume bounds (e.g., -1 to 1 or 0 to 1) [S3, book][S5, unofficial].
    *   **Fragment Shader:**
        *   Interpolate texture coordinates across the polygon [S3, book].
        *   **Data Lookup:** Sample the 3D volume texture using interpolated coordinates to get scalar value $v$ [S2, unofficial][S3, book].
        *   **Transfer Function:** Use $v$ as a texture coordinate to sample the 1D transfer function texture, obtaining color $\mathbf{c}$ and opacity $\alpha$ [S3, book].
        *   **Shading (Optional):** Compute normal $\mathbf{n}$ via finite differences of neighboring voxels. Apply Phong shading model with ambient, diffuse, and specular components [S5, unofficial].
        *   **Clipping (Optional):** Discard fragment if position is outside defined clip planes/cube [S5, unofficial].
        *   **Compositing:** Output color and alpha. The hardware blending unit accumulates the result into the frame buffer using the configured blend factors [S2, unofficial][S9].

### Pseudocode

```python
# Vertex Shader
def vertex_shader(position, model_matrix, view_matrix, projection_matrix):
    # Compute world position
    world_pos = model_matrix * vec4(position, 1.0)
    
    # Compute texture coordinates based on world position
    # Assuming volume bounds are known and normalized to [-1, 1] or [0, 1]
    # Example: mapping world pos to texture space
    tex_coord = (world_pos.xyz - volume_min) / (volume_max - volume_min)
    
    # Pass to fragment shader
    gl_Position = projection_matrix * view_matrix * world_pos
    return tex_coord

# Fragment Shader
def fragment_shader(tex_coord, volume_texture, tf_texture, alpha_scale, threshold):
    # 1. Sample Volume Data
    v = texture(volume_texture, tex_coord).r
    
    # 2. Discard if below threshold (optimization)
    if v < threshold:
        discard()
        
    # 3. Transfer Function Lookup
    # Map scalar v to [0, 1] if necessary, then sample 1D texture
    tf_color = texture(tf_texture, v)
    color = tf_color.rgb
    alpha = tf_color.a * alpha_scale
    
    # 4. Optional Shading (Phong)
    # Compute gradient for normal
    delta = 1.0 / 256.0 # Example step size
    v_x_minus = texture(volume_texture, tex_coord - vec3(delta, 0, 0)).r
    v_x_plus = texture(volume_texture, tex_coord + vec3(delta, 0, 0)).r
    # ... similar for y and z
    normal = normalize(vec3(v_x_minus - v_x_plus, ...))
    
    # Compute lighting (simplified)
    # ... Phong calculation ...
    color = apply_phong_shading(color, normal, light_positions, view_vector)
    
    # 5. Output
    gl_FragColor = vec4(color, alpha)
```

### Parameters
*   **PLANE_INC:** Increment value for plane slicing (e.g., 1.0) [S5, unofficial].
*   **u_slices:** Uniform `vec3` containing texture dimensions for coordinate normalization [S5, unofficial].
*   **u_thresh:** Uniform `float` threshold for fragment discard [S5, unofficial].
*   **u_alphaScale:** Uniform `float` multiplier for fragment alpha [S5, unofficial].
*   **Shading Constants:** $K_a=(0.1,0.1,0.1)$, $K_d=(0.6,0.6,0.6)$, $K_s=(0.2,0.2,0.2)$, shininess=100.0 [S5, unofficial].

### Edge Cases and Pitfalls
*   **Object-Aligned Artifacts:** Using 2D texture stacks aligned with axes causes "popping" artifacts when the viewpoint crosses the diagonal (45 degrees) and requires swapping texture stacks, leading to lag and intensity variations due to changing sampling distances [S2, S6, S8, unofficial].
*   **Memory Usage:** Object-aligned slices require replicating data along three axes, increasing memory consumption by 3x [S2, unofficial][S3, book][S7, unofficial].
*   **Sampling Artifacts:** 2D textures use bilinear interpolation, causing artifacts at slice edges. 3D textures use trilinear interpolation, providing better quality but potentially slower access [S1, S8, unofficial].
*   **View-Aligned Performance:** View-aligned slices require dynamic geometry generation and trilinear filtering, which is slower than object-aligned bilinear filtering but provides consistent sampling distance and no popping artifacts [S2, S7, unofficial].

## Operating characteristics
*   **Time Complexity:** Rendering time is proportional to the number of proxy slices and the resolution of the texture lookup. View-aligned slices require more CPU overhead for geometry generation but consistent GPU performance. Object-aligned slices are faster to render but suffer from cache misses and stack swaps [S2, S7, unofficial].
*   **Memory Complexity:** 3D textures use $O(N)$ memory where $N$ is the volume size. 2D texture stacks use $O(3N)$ memory if replicated for all axes [S2, unofficial][S3, book].
*   **Strengths:** Leverages mature GPU hardware (texture units, blending). Interactive frame rates achievable. Simple implementation using standard graphics pipeline [S1, S2, unofficial].
*   **Limitations:** Fixed sampling rate determined by slice spacing. Cannot easily adapt sampling density to view distance (unlike adaptive ray marching). 2D textures suffer from interpolation artifacts. 3D textures may have slower access speeds on older hardware [S1, S8, unofficial].
*   **When to use:** Interactive visualization on modern GPUs where simplicity and speed are prioritized over perfect sampling accuracy.
*   **When not to use:** When high-quality anti-aliasing is required without supersampling, or when memory is extremely constrained and 3D textures are not supported.

## Background
Texture-Based Volume Rendering emerged with the advent of programmable graphics hardware and 3D texture support in GPUs [S1, S7, unofficial]. Early implementations used 2D texture stacks (Object-Aligned Slices) due to limited 3D texture support, leading to artifacts [S1, S8, unofficial]. The technique was formalized in the mid-2000s as a standard method for GPU-accelerated volume rendering, described in detail in *GPU Gems* Chapter 39 [S3, book]. It remains a foundational technique for real-time volume visualization, often serving as a baseline for more advanced methods like [Pre-integrated Volume Rendering](5327-pre-integrated-volume-rendering.md) which enhances the texture lookup step [S7, unofficial].
